# Texture-Based Volume Rendering

Also called: Geometry-based volume visualization, Proxy Geometry Rendering, Slice-based rendering, TBVR, Texture Based Ray Casting

## Overview
Texture-Based Volume Rendering (TBVR) is a forward-projection technique that renders volumetric data by sampling it from GPU texture memory onto a set of 2D geometric primitives (proxy geometry) [S1, S2, S7, unofficial]. It solves the problem of interactive volume visualization on graphics hardware by leveraging the GPU's texture sampling and hardware alpha blending capabilities to perform the volume rendering integral [S1, unofficial][S3, book]. Unlike [View-Aligned Slicing](6530-view-aligned-slicing.md), which dynamically computes slice positions to maintain constant sampling density, TBVR typically uses fixed proxy geometry (often axis-aligned or view-aligned planes) and relies on texture interpolation [S2, unofficial][S3, book].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric scalar field data (regular grid), transfer function (mapping scalar values to color/opacity), and camera parameters (view and projection matrices).
*   **Output:** A 2D image composited in the frame buffer.

**Data Structures:**
1.  **Volume Texture:** The scalar data is stored in GPU texture memory.
    *   **3D Texture:** A single `sampler3D` object. Dimensions match the volume $(W, H, D)$. Format is typically single-channel (e.g., `GL_RED`, `UnsignedByte` or `Float`) [S2, S5, S7, unofficial].
    *   **2D Texture Stack (Legacy/Alternative):** A set of 2D textures. For object-aligned slicing, data is replicated along three principal axes (X, Y, Z), requiring three stacks [S2, unofficial][S3, book].
2.  **Transfer Function Texture:** A 1D texture (`sampler1D`) mapping scalar values to RGBA color/opacity [S3, book][S5, unofficial].
3.  **Proxy Geometry:** A set of polygons (quads or triangle fans) representing slices through the volume.
    *   **Vertices:** Defined by the intersection of slicing planes with the volume bounding box.
    *   **Texture Coordinates:** Assigned to vertices to map the polygon surface to the volume texture space. For 3D textures, coordinates range from $(0,0,0)$ to $(1,1,1)$ [S3, book][S5, unofficial].

**Algorithm Steps:**

1.  **Initialize:**
    *   Load volume data into CPU memory.
    *   Process data if necessary (e.g., compute gradients, downsample) [S3, book][S9].
    *   Create transfer function lookup tables (textures) [S3, book][S9].
    *   Download volume data to GPU as a 3D texture or 2D texture stack [S2, S7, unofficial][S9].
    *   Set up rendering state: Disable lighting, disable depth testing (or disable depth writing if blending with opaque geometry), enable alpha blending [S3, book][S9].

2.  **Update (Per Frame/View Change):**
    *   Compute proxy geometry: Determine the position and orientation of slicing planes based on the camera view [S3, book][S9].
        *   *View-Aligned:* Planes are orthogonal to the viewing direction [S7, unofficial].
        *   *Object-Aligned:* Planes are axis-aligned (X, Y, or Z) [S2, unofficial].
    *   Intersect slicing planes with the volume bounding box to generate polygon vertices [S6, unofficial].
    *   Sort vertices in counter-clockwise order and construct polygon primitives (e.g., triangle fan from centroid) [S6, unofficial].
    *   Assign texture coordinates to each vertex. For a 3D texture, if a vertex is at position $P=(x,y,z)$ in normalized space, the texture coordinate is $P$ [S3, book][S5, unofficial].
    *   Refresh textures if rendering mode or transfer function parameters change [S3, book][S9].
    *   Perform opacity correction of transfer function textures if the sampling rate changes [S9].

3.  **Draw:**
    *   Bind volume texture and transfer function texture [S3, book][S9].
    *   Draw slice polygons in sorted order.
        *   **Back-to-Front:** For the Over operator [S2, unofficial][S3, book].
        *   **Front-to-Back:** For the Under operator [S2, unofficial][S3, book].
    *   **Fragment Shader Execution (Per Pixel):**
        1.  Interpolate texture coordinates from vertex attributes [S3, book][S9].
        2.  Perform data texture lookup: $v = \text{tex3D}(texCoord, \text{dataTex})$ [S2, unofficial][S3, book].
        3.  **Optional: Illumination:** Compute surface normal via finite differences of neighboring voxels and apply shading (e.g., Blinn-Phong) [S2, S5, unofficial].
        4.  **Transfer Function Lookup:** Use interpolated data value $v$ as texture coordinate for dependent lookup: $color = \text{tex1D}(v, \text{tfTex})$ [S3, book][S9].
        5.  **Compositing:** The hardware alpha blender accumulates the fragment color and alpha into the frame buffer using the specified blending equation [S2, unofficial][S3, book].

**Formulas:**

*   **Volume Rendering Integral (Discrete):**
    The color $C$ and opacity $A$ are accumulated along the ray. For each sample $i$ with opacity $A_i$ and color $C_i$:
    $$ C = \sum_{i} C_i A_i \prod_{j < i} (1 - A_j) $$
    $$ A = 1 - \prod_{i} (1 - A_i) $$
    [S3, book]

*   **Hardware Blending Equations:**
    *   **Over Operator (Back-to-Front):**
        $$ Source = 1 $$
        $$ Destination = 1 - Source\ Alpha $$
        [S2, unofficial]
    *   **Under Operator (Front-to-Back):**
        $$ Source = 1 - Destination\ Alpha $$
        $$ Destination = 1 $$
        [S2, unofficial]

*   **Normal Estimation (for Illumination):**
    Using central differences with step $\delta$ (e.g., $1/256.0$):
    $$ N_x = \text{tex3D}(P + (\delta, 0, 0)) - \text{tex3D}(P - (\delta, 0, 0)) $$
    $$ N_y = \text{tex3D}(P + (0, \delta, 0)) - \text{tex3D}(P - (0, \delta, 0)) $$
    $$ N_z = \text{tex3D}(P + (0, 0, \delta)) - \text{tex3D}(P - (0, 0, \delta)) $$
    $$ N = \text{normalize}(N_x, N_y, N_z) $$
    [S5, unofficial]

*   **Blinn-Phong Shading:**
    $$ H = \text{normalize}(L + V) $$
    $$ Ambient = K_a \cdot L_{ambient} $$
    $$ Diffuse = K_d \cdot L_{color} \cdot \max(0, L \cdot N) $$
    $$ Specular = K_s \cdot L_{color} \cdot \max(0, H \cdot N)^{shininess} $$
    $$ Result = Ambient + Diffuse + Specular $$
    [S2, S5, unofficial]

**Parameters:**
*   **Slice Increment (PLANE_INC):** Controls the distance between proxy planes. Initialized to 1.0 in some implementations [S5, unofficial].
*   **Threshold (u_thresh):** Scalar value below which fragments are discarded [S5, unofficial].
*   **Alpha Scale (u_alphaScale):** Multiplier for fragment alpha in transparent mode [S5, unofficial].
*   **Shading Constants:** $K_a=(0.1,0.1,0.1)$, $K_d=(0.6,0.6,0.6)$, $K_s=(0.2,0.2,0.2)$, shininess=100.0 [S5, unofficial].

**Pseudocode:**

```python
# Vertex Shader
varying vec3 vTexCoords;
varying vec3 vWorldPos;

void main() {
    // position is the vertex position in world/object space
    // u_slices is vec3(1.0/width, 1.0/height, 1.0/depth)
    // Assuming texture coordinates are passed or computed from position
    vTexCoords = position * u_slices + 0.5; 
    vWorldPos = position;
    gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}

# Fragment Shader
uniform sampler3D u_data;
uniform sampler1D u_tf;
uniform float u_thresh;
uniform float u_alphaScale;
uniform vec3 u_lightPos;
uniform vec3 u_camPos;

void main() {
    // 1. Sample Volume Data
    float val = texture(u_data, vTexCoords).r;
    
    // 2. Discard if below threshold
    if (val < u_thresh) {
        discard;
    }
    
    // 3. Transfer Function Lookup
    vec4 tfColor = texture(u_tf, val);
    vec3 color = tfColor.rgb;
    float alpha = tfColor.a * u_alphaScale;
    
    // 4. Optional Illumination (Blinn-Phong)
    // Compute normal via finite differences
    float delta = 1.0 / 256.0;
    vec3 N = normalize(vec3(
        texture(u_data, vTexCoords + vec3(delta, 0, 0)).r - texture(u_data, vTexCoords - vec3(delta, 0, 0)).r,
        texture(u_data, vTexCoords + vec3(0, delta, 0)).r - texture(u_data, vTexCoords - vec3(0, delta, 0)).r,
        texture(u_data, vTexCoords + vec3(0, 0, delta)).r - texture(u_data, vTexCoords - vec3(0, 0, delta)).r
    ));
    
    vec3 L = normalize(u_lightPos - vWorldPos);
    vec3 V = normalize(u_camPos - vWorldPos);
    vec3 H = normalize(L + V);
    
    vec3 Ka = vec3(0.1);
    vec3 Kd = vec3(0.6);
    vec3 Ks = vec3(0.2);
    float shininess = 100.0;
    vec3 ambientLight = vec3(0.3);
    vec3 lightColor = vec3(1.0);
    
    vec3 ambient = Ka * ambientLight;
    float diff = max(dot(L, N), 0.0);
    vec3 diffuse = Kd * lightColor * diff;
    float spec = pow(max(dot(H, N), 0.0), shininess);
    if (diff <= 0.0) spec = 0.0;
    vec3 specular = Ks * lightColor * spec;
    
    color = color * (ambient + diffuse + specular);
    
    // 5. Output for Hardware Blending
    gl_FragColor = vec4(color, alpha);
}
```

## Subtopics

### 2D Slice Replication Approach
Stores data as a set of 2D texture slices. Proxy polygons are rectangles aligned with the slices. Requires data replication along three principal directions (X, Y, Z), increasing memory usage by 3x. Fast rendering but suffers from sampling artifacts when the viewing angle approaches 45 degrees relative to the slices, as the viewer sees between slice gaps. Intensity variations occur as the camera moves because sampling distance changes. Image popping artifacts occur when switching texture stacks [S2, unofficial][S3, book][S7, unofficial][S9].

### 3D Texture Approach
Stores the volume as a single 3D texture. Proxy geometry can be view-aligned (orthogonal to the viewing direction), eliminating 45-degree artifacts and providing consistent sampling distance. Requires trilinear interpolation, which is slightly slower than 2D bilinear interpolation but provides excellent image quality. Uses less memory than 2D replication [S1, S2, unofficial][S3, book][S7, unofficial].

### View-Aligned Slicing
A variant where proxy geometry planes are always orthogonal to the camera view. This ensures consistent sampling distance and eliminates intensity variations. Slower to compute proxy geometry than object-aligned slices but more memory efficient than 2D replication. Vertices are computed by intersecting planes with the bounding box and sorted into a triangle fan [S2, S6, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering time is proportional to the number of slices and the resolution of the image. Fragment shader cost is constant per pixel (texture lookups).
*   **Memory Complexity:**
    *   3D Texture: $O(N)$ where $N$ is the number of voxels [S3, book].
    *   2D Replication: $O(3N)$ due to data duplication along axes [S2, unofficial][S3, book][S9].
*   **Performance:** Achieves interactive frame rates on modern GPUs by offloading sampling and compositing to hardware [S1, unofficial]. 2D textures are faster for interpolation but suffer from artifacts; 3D textures are slower but higher quality [S1, S8, unofficial].
*   **Strengths:** Simple implementation leveraging standard graphics pipeline; interactive performance; good image quality with 3D textures [S1, unofficial][S3, book].
*   **Limitations:** 2D approach suffers from artifacts (popping, intensity variation, 45-degree gaps); 3D approach may have slower access speeds on older hardware; sampling rate dependency on volume resolution [S2, unofficial][S3, book][S7, S8, unofficial].
*   **When to Use:** Interactive visualization where frame rate is critical and artifacts are acceptable (2D) or high quality is required (3D). Not suitable for non-regular grids without resampling.

## Background
Originated with the advent of GPU texture hardware. Early implementations used 2D texture stacks due to limited 3D texture support, leading to the 2D slice replication approach [S1, S7, unofficial]. The technique was formalized in the GPU Gems Chapter 39 (NVIDIA, 2004) and popularized by Krüger and Westermann (2003) for interactive visualization on consumer hardware [S2, unofficial][S3, book]. It remains a standard method for real-time volume rendering in medical and scientific visualization [S5, S7, unofficial].
