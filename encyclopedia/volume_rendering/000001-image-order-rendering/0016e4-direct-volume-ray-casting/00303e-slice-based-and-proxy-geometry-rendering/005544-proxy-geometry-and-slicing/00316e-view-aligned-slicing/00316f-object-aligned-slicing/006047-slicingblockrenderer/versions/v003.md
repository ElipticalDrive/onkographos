# SlicingBlockRenderer

Also called: Slice-based direct volume renderer with subvolume blocking

## Overview
SlicingBlockRenderer is a slice-based direct volume rendering method that organizes volume data into subvolumes (blocks) and renders them as textured quads (slices) sorted by distance from the camera to handle transparency correctly [S1, unofficial]. It builds on [Object-Aligned Slicing](6531-object-aligned-slicing.md) [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Volume data partitioned into blocks, camera position and view direction, transfer function parameters [S1, unofficial].
- Output: Rendered image with correct alpha blending [S1, unofficial].

**Data Structures:**
- **Block:** Represents a subvolume. Contains a status flag `GPU_RES` indicating if texture data is uploaded to the GPU [S1, unofficial].
- **Vertex Buffer:** A single buffer containing geometry for all possible slice orientations [S1, unofficial].
  - Layout: 6 sets of quads corresponding to 3 axes (YZ, XZ, XY) and 2 viewing directions (positive/negative) per axis [S1, unofficial].
  - Each set contains `numSlices` slices [S1, unofficial].
  - Each slice is a quad (4 vertices) [S1, unofficial].
  - Total vertices = $6 \times \text{numSlices} \times 4$ [S1, unofficial].
  - Indices are structured to draw these quads sequentially [S1, unofficial].
- **Sampler:** Configured with linear min/mag filtering and clamp-to-border wrapping for S, T, and R axes [S1, unofficial]. Bound to `BLOCK_TEXTURE_UNIT` [S1, unofficial].

**Parameters:**
- `m_tfuncScaleValue`: Scale factor for the transfer function. Default: $1.0$ [S1, unofficial]. Passed to shader uniform `VOLUME_TRANSF_SCALER_UNIFORM_STR` [S1, unofficial].
- `m_shouldUseLighting`: Boolean flag to toggle lighting. Default: `false` [S1, unofficial].
- `m_drawNonEmptySlices`: Boolean flag to toggle slice rendering. Default: `true` [S1, unofficial].
- `m_drawNonEmptyBoundingBoxes`: Boolean flag to toggle bounding box rendering. Default: `false` [S1, unofficial].

**Numbered Steps:**
1. **Sampler Setup:** Create a sampler object with linear min/mag filtering and clamp-to-border wrapping for S, T, and R axes. Bind it to `BLOCK_TEXTURE_UNIT` [S1, unofficial].
2. **Block Sorting:** In the draw loop, identify non-empty blocks. Sort these blocks by distance from the camera eye using the block's origin in descending order (furthest first) to satisfy the painters algorithm for transparency [S1, unofficial].
3. **View Axis Determination:** Compute the base vertex and element offset for the vertex buffer based on the view direction [S1, unofficial].
   - Determine the axis with the largest absolute component in the view vector to select the slice set (YZ, XZ, or XY) [S1, unofficial].
   - Determine if viewing in the positive or negative direction to select the correct vertex range within that set [S1, unofficial].
4. **Rendering Loop:** For each non-empty block in the sorted list:
   - Check if the block's status includes `GPU_RES`. If not, skip the block [S1, unofficial].
   - Set the world matrix for the block.
   - Bind the block's texture to `BLOCK_TEXTURE_UNIT` [S1, unofficial].
   - Set the MVP matrix uniform.
   - Draw the slices using `glDrawElementsBaseVertex` with the computed base vertex and element offset [S1, unofficial].

**Formulas:**
Let $N$ be the number of slices along the viewing axis (`numSlicesPerBlock`) [S1, unofficial]. Let $V_{quad} = 4$ be the vertices per quad [S1, unofficial]. The base vertex index for the vertex buffer is calculated as follows:

- **View along X (YZ slices):**
  - Positive X: $BaseVertex = 0$
  - Negative X: $BaseVertex = 1 \times V_{quad} \times N$

- **View along Y (XZ slices):**
  - Positive Y: $BaseVertex = 2 \times V_{quad} \times N$
  - Negative Y: $BaseVertex = 3 \times V_{quad} \times N$

- **View along Z (XY slices):**
  - Positive Z: $BaseVertex = 4 \times V_{quad} \times N$
  - Negative Z: $BaseVertex = 5 \times V_{quad} \times N$

Where $N$ is `numSlicesPerBlock.x` for X-view, `.y` for Y-view, and `.z` for Z-view [S1, unofficial].

**Pseudocode:**
```python
def render_slicing_block_renderer(blocks, camera_eye, view_vector, num_slices_per_block, index_buffer):
    GPU_RES = 1
    BLOCK_TEXTURE_UNIT = 0
    V_QUAD = 4
    m_tfuncScaleValue = 1.0

    # 1. Sort blocks by distance from camera eye, descending (furthest first)
    sorted_blocks = sorted(blocks, key=lambda b: ((b.origin.x - camera_eye.x)**2 + (b.origin.y - camera_eye.y)**2 + (b.origin.z - camera_eye.z)**2)**0.5, reverse=True)

    # 2. Determine view axis and base vertex
    abs_x, abs_y, abs_z = abs(view_vector.x), abs(view_vector.y), abs(view_vector.z)
    if abs_x >= abs_y and abs_x >= abs_z:
        axis = 'X'
        is_pos = view_vector.x > 0
    elif abs_y >= abs_x and abs_y >= abs_z:
        axis = 'Y'
        is_pos = view_vector.y > 0
    else:
        axis = 'Z'
        is_pos = view_vector.z > 0

    N = num_slices_per_block[axis]
    if axis == 'X':
        base_vertex = 0 if is_pos else 1 * V_QUAD * N
    elif axis == 'Y':
        base_vertex = 2 * V_QUAD * N if is_pos else 3 * V_QUAD * N
    else:
        base_vertex = 4 * V_QUAD * N if is_pos else 5 * V_QUAD * N

    # 3. Render loop
    for block in sorted_blocks:
        if not (block.status & GPU_RES):
            continue

        # Set world matrix, bind texture, set MVP uniform
        # (Standard graphics API calls to set shader uniforms and bind resources)
        set_world_matrix(block.world_matrix)
        bind_texture(block.texture, BLOCK_TEXTURE_UNIT)
        set_mvp_uniform(camera.mvp_matrix * block.world_matrix)
        set_transfer_function_scaler(m_tfuncScaleValue)

        # Draw slices using glDrawElementsBaseVertex with computed base vertex
        # index_buffer contains sequential indices for quads
        # count = N * 6 (6 indices per quad)
        draw_elements_base_vertex(index_buffer, count=N * 6, type=UNSIGNED_INT, base_vertex=base_vertex)
```

**Edge Cases and Pitfalls:**
- **Transparency Sorting:** Blocks must be sorted from furthest to nearest relative to the camera to ensure correct blending order [S1, unofficial].
- **Resource Availability:** Slices are only drawn if the block's status includes `GPU_RES` [S1, unofficial].

## Background
The SlicingBlockRenderer is an implementation of slice-based direct volume rendering with subvolume blocking. It is associated with the work of Jim Pelton [S1, unofficial]. The method is part of a broader family of volume rendering techniques that use proxy geometry (slices) to approximate the volume [S1, unofficial].
