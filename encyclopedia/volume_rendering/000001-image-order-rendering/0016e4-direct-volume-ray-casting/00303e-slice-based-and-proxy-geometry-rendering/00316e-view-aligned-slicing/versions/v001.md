# View-Aligned Slicing


## Overview
View-aligned slicing is a proxy geometry technique that divides a 3D volume into planar slices and rotates them to align with the view plane, minimizing sampling artifacts and maintaining consistent slice thickness relative to the camera [S2, S1, unofficial]. It is chosen when consistent sampling distance is required across viewpoints, offering a trade-off of slower performance but higher memory efficiency compared to fixed-step ray casting [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D volume data, volume bounding box, number of slices $n$ (sampling rate), camera view matrix, projection matrix.
*   **Output:** 2D image with accumulated color and opacity.

**Data Structures:**
*   **3D Texture:** Stores the volume data. Clamping mode must be set to `GL_CLAMP_TO_BORDER` to avoid artifacts from texture coordinate transformation [S2, unofficial].
*   **Proxy Geometry:** A unit quad (or triangle fan) representing a single slice. The geometry is stationary in screen space (or view space aligned with the view plane), while texture coordinates are transformed [S2, unofficial].
*   **Shader Uniforms (per slice):**
    *   `sliceNumber` (float): Index of the current slice.
    *   `totalSlices` (float): Total number of slices $n$.
    *   `MVPMatrix` (Matrix4f): Model-View-Projection matrix.
    *   `ModelMatrix` (Matrix4f): Model matrix.
    *   `ViewMatrix` (Matrix4f): View matrix.
    *   `TextureMatrix` (Matrix4f): Rotation matrix transforming texture coordinates to align with the view [S2, unofficial].

**Steps:**
1.  **Load Volume:** Load 3D volume data into a 3D texture [S2, unofficial].
2.  **Scale Geometry:** Scale a unit cube (or quad) with the volume's dimensions [S2, unofficial].
3.  **Divide Volume:** Divide the volume into $n$ slices along the z-direction, where $n$ is the sampling rate [S2, unofficial].
4.  **Intersect Bounding Box:** Intersect the slicing planes with the volume bounding box to determine the extent of each slice [S1, unofficial].
5.  **Sort Vertices:** Sort the resulting vertices in counter-clockwise order [S1, unofficial].
6.  **Construct Primitive:** Construct a polygon primitive (e.g., triangle fan) from the centroid [S1, unofficial].
7.  **Align Slices:** Align slices to the view plane (X-Y plane) by stacking them in the negative z-direction [S2, unofficial]. This is achieved by using a rotation matrix that transforms texture coordinates, keeping the slice geometry stationary while changing the texture content [S2, unofficial].
8.  **Render Loop:** For each slice $i$ from 1 to $n$:
    a. Calculate the slice position and pass `sliceNumber`, `totalSlices`, and transformation matrices to the shader [S2, unofficial].
    b. Transform texture coordinates in the vertex shader using the `TextureMatrix` [S2, unofficial].
    c. Render the slice primitive.
    d. **Compositing:** Perform front-to-back compositing using hardware alpha blending. The "Over" operator is used:
       $$ C_{out} = C_{src} + (1 - \alpha_{src}) C_{dst} $$
       $$ \alpha_{out} = \alpha_{src} + (1 - \alpha_{src}) \alpha_{dst} $$
       Where Source is the current slice and Destination is the accumulated result [S1, unofficial].
9.  **Transfer Function:** In the fragment shader, sample the 3D texture using the transformed texture coordinates. Apply a 1D transfer function (e.g., cubic spline fit to manual points) to map the scalar value to color and opacity [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Slower than fixed-step ray casting due to the overhead of rendering multiple primitives and managing texture coordinate transformations [S1, unofficial].
*   **Memory Complexity:** More memory efficient than ray casting as it does not require storing large intermediate buffers for ray marching, relying instead on hardware alpha blending [S1, unofficial].
*   **Strengths:** Maintains consistent sampling distance relative to the camera, reducing intensity variations as the camera moves [S1, unofficial].
*   **Limitations:** Slower performance; requires careful handling of texture coordinate transformations and clamping modes [S2, unofficial].
*   **When to Use:** When consistent sampling distance is critical and memory efficiency is preferred over raw speed [S1, unofficial].
