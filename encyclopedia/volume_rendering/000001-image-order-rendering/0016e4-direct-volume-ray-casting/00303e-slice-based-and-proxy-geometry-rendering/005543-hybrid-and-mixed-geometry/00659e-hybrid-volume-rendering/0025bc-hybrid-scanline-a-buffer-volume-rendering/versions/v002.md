# Hybrid Scanline A-Buffer Volume Rendering

Also called: Scanline A-Buffer with Volume Fragments

## Overview
Hybrid Scanline A-Buffer Volume Rendering is a method that integrates explicit surface geometry and implicit volumetric data (such as procedural gases) into a single image by combining a scanline-based A-buffer for surfaces with direct volume rendering for the volume data [S1, unofficial]. It solves the problem of correctly resolving visibility between opaque/semi-transparent polygons and volumetric elements by using a fragment list per pixel, allowing volume rendering to cease early once full coverage is achieved [S1, unofficial]. Unlike pure ray casting, it leverages the efficiency of scanline processing for solid objects while maintaining the flexibility of volume rendering for procedural media [S1, unofficial].

## How it works
The method operates on a per-scanline basis, maintaining an A-buffer that stores fragments for each pixel.

**Inputs and Outputs:**
*   **Inputs:** Polygonal geometry (surface-defined objects), volumetric data (procedural gases), viewing parameters, and a depth buffer.
*   **Outputs:** A final color image where polygons and volumes are correctly composited based on depth.

**Data Structures:**
*   **A-Buffer:** For each scanline, an A-buffer is created. It contains a list for each pixel in the scanline. Each list stores fragments that partially or fully cover the pixel.
*   **Fragment:** A fragment represents a portion of a surface or volume section covering a pixel. It includes color, opacity, and depth information.

**Steps:**
1.  **Initialize A-Buffer:** For the current scanline, create an A-buffer containing an empty list for each pixel.
2.  **Render Surfaces:** Render surface-defined objects into the A-buffer. This populates the fragment lists with polygon fragments, sorted or managed according to the A-buffer's coverage rules [S1, unofficial].
3.  **Volume Rendering Loop:** For each volume that intersects the current scanline:
    a.  Perform volume rendering for the intersecting sections of the volume.
    b.  Generate A-buffer fragments for these volume sections.
    c.  **Early Termination Check:** Cease volume rendering for a specific pixel once full coverage (opacity = 1.0 or sufficient depth occlusion) by either volume or surface-defined elements is achieved [S1, unofficial].
4.  **Sort Fragments:** Sort the volume A-buffer fragments into the existing A-buffer fragment list for each pixel based on their average Z-depth values [S1, unofficial].
5.  **Composite:** Render the A-buffer fragment list for each pixel to produce the final color, compositing the sorted fragments from front to back (or according to the A-buffer's specific compositing rule) [S1, unofficial].

**Parameters and Models:**
*   **Illumination:** Uses a physically-based low-albedo illumination model for gases [S1, unofficial].
*   **Attenuation:** Uses an atmospheric attenuation model for gases [S1, unofficial].
*   **Shadows:** Volumetric shadows are combined using three-dimensional shadow tables [S1, unofficial].

## Subtopics

### Scanline A-buffer rendering
A rendering algorithm for surface-defined objects in hybrid scenes. An A-buffer is created for a scanline, containing a list for each pixel of all fragments that partially or fully cover the pixel [S2, unofficial]. It serves as the foundation for handling explicit geometry in the hybrid system [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of fragments per pixel and the complexity of volume rendering. Early termination of volume rendering can significantly reduce computation time for fully occluded pixels [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of fragments stored in the A-buffer. High fragment counts can lead to significant memory usage [S1, unofficial].
*   **Strengths:** Efficiently handles hybrid scenes with both surfaces and volumes. Early termination optimizes volume rendering. Physically-based lighting and shadows enhance realism [S1, unofficial].
*   **Limitations:** A-buffer management can be complex and memory-intensive. Performance may degrade with high fragment density [S1, unofficial].
*   **When to Use:** Suitable for visualizing procedural gases or fluids alongside explicit polygonal geometry where correct depth ordering is critical [S1, unofficial].

## Background
The method was developed by David Ebert as part of a system for procedural modeling, animation, and rendering of gases, fluids, and textures [S1, unofficial]. It builds upon earlier work in solid texturing and volume rendering [S1, unofficial]. The use of 3D shadow tables for volumetric shadows was introduced in earlier work by Ebert et al.
