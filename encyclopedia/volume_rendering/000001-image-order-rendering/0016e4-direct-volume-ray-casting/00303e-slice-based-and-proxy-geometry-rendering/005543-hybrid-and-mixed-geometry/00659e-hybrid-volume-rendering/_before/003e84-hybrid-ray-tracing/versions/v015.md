# Hybrid Ray Tracing

Also called: Hybrid Ray Tracer, Hybrid Ray Tracing for Geometric/Volumetric Mixing, Mixing Polygons and Volumes

## Overview
Hybrid Ray Tracing is a method for mixing geometric and volumetric data by casting rays through the ensemble of both, drawing samples of each, and compositing them in depth-sorted order [S1, S2, unofficial]. It solves the problem of rendering scenes containing both polygonal models (e.g., surgical instruments, surface meshes) and volumetric data (e.g., CT/MR scans) in a single pass with correct visibility and attenuation [S2, S3, unofficial]. Unlike pure volume rendering which rasterizes slices, or pure ray tracing which handles only geometry, this method simultaneously traces rays through volumetric sample arrays and polygonal databases, resampling both at equally spaced intervals to handle mixtures of geometric and volumetric data [S2, unofficial]. It is distinguished from [Hybrid Volume Rendering](15456-hybrid-volume-rendering.md) by its explicit ray-casting approach to mixing rather than slice-based or proxy-geometry rasterization.

## How it works
The method consists of two primary variants: the **Hybrid Ray Tracer** (direct ray casting through mixed data) and **3D Scan-Conversion** (converting geometry to volume). The Hybrid Ray Tracer is the core method described below.

### Inputs and Outputs
*   **Inputs**:
    *   A 3D voxel array of scalar values (volume data) [S2, unofficial].
    *   A set of embedded polygons (geometric data) [S2, unofficial].
    *   Camera position and viewing direction [S2, unofficial].
    *   Transfer functions mapping scalar values to color $c_v$ and opacity $o_v$ for voxels [S2, unofficial].
    *   Shading parameters for polygons (color $c_p$, opacity $o_p$) [S2, unofficial].
    *   Supersampling threshold $\theta$ [S2, unofficial].
*   **Outputs**:
    *   A 2D image where each pixel contains the final composited color [S2, unofficial].

### Data Structures
*   **Volumetric Data**: Stored as a 3D texture or array. Each voxel has an associated color and opacity derived from classification [S2, unofficial].
*   **Geometric Data**: A list of polygons (triangles/quads) with surface normals for shading [S2, unofficial].
*   **Ray State**: For each pixel, a viewing ray is defined by origin and direction [S2, unofficial].

### Algorithm: Hybrid Ray Tracer
The Hybrid Ray Tracer casts rays through both data types and composites them.

1.  **Preprocessing**: Shade and classify volumetric data to yield color $c_v$ and opacity $o_v$ for each voxel [S2, unofficial]. Independently, shade polygons to yield color $c_p$ and opacity $o_p$ [S2, unofficial].
2.  **Ray Casting**: For each pixel, trace a parallel viewing ray from the observer position into the data [S2, unofficial].
3.  **Volumetric Sampling**: Compute a vector of colors $c_v$ and opacities $o_v$ by resampling the volumetric data at equally spaced positions along the ray. Use tri-linear interpolation from the colors and opacities in the eight voxels surrounding each sample location [S2, unofficial].
    *   The spacing between samples along the ray equals the slab thickness [S2, unofficial].
    *   The spacing between adjacent rays equals the slab width [S2, unofficial].
4.  **Geometric Intersection**: Independently compute all intersections between the ray and polygons in the environment [S2, unofficial].
5.  **Slab Handling**: The volume is conceptually divided into slabs of thickness equal to the sample spacing [S2, unofficial]. When a ray intersects a polygon within a slab:
    *   Treat the polygon locally as a plane perpendicular to the ray at the intersection point [S2, unofficial].
    *   Calculate the opacity of the volumetric sliver immediately in front of the plane ($o_f$) and immediately behind the plane ($o_b$) using exponential attenuation formulas [S2, unofficial].
6.  **Compositing**: Composite the contributions in depth-sorted order (front-to-back) [S2, unofficial].
    *   If a ray intersects more than one polygon within a slab, compute and composite the contribution of each polygon and each sliver of volumetric gel separately [S2, unofficial].
    *   Order: Composite front volumetric sliver ($c_v, o_f$), then the polygon ($c_p, o_p$), then the back volumetric sliver ($c_v, o_b$) [S2, unofficial].
7.  **Adaptive Supersampling**: To avoid aliasing at polygonal edges, intersections, and highlights, increase the number of rays per pixel in specific regions [S2, unofficial].
    *   Compute two auxiliary colors during ray tracing:
        *   $C_x$: Contributions only from polygons (set $o_v=0$ for all volumetric samples) [S2, unofficial].
        *   $C_q$: Contributions only from polygons, attenuated by passage through volumetric data (set $o_v=0$ for all volumetric samples) [S2, unofficial].
    *   Determine if supersampling is needed based on the range of these colors within a sample region:
        *   If range($C_x$) > $\theta$ and range($C_q$) $\le \theta$: Color difference is due to volumetric data. Do not supersample [S2, unofficial].
        *   If range($C_q$) > $\theta$ and range($C_x$) $\le \theta$: Geometric event is hidden by opaque volumetric data. Do not supersample [S2, unofficial].
        *   If range($C_x$) > $\theta$ and range($C_q$) > $\theta$: Region contains a visible geometric event. Cast more rays (supersample) [S2, unofficial].

### Algorithm: 3D Scan-Conversion Variant
This variant converts geometry to volume to avoid ray-polygon intersection complexity [S1, unofficial].

1.  **Shading**: Shade the polygons [S1, unofficial].
2.  **Bandlimiting**: Bandlimit the object to the Nyquist frequency in all three dimensions to avoid aliasing artifacts [S1, unofficial].
3.  **Scan-Conversion**: Use efficient 3D scan-conversion algorithms (e.g., Kaufman 1987b) to create a binary voxel representation of the geometry [S1, unofficial].
4.  **Sampling**: Sample the object to limit quantization losses [S1, unofficial].
5.  **Filtering**: Filter the sampled geometry [S1, unofficial].
6.  **Combining**: Combine the filtered geometry with the volumetric data [S1, unofficial].
7.  **Rendering**: Render the composite dataset using standard volume rendering techniques [S1, unofficial].

### Formulas
*   **Slab Opacity**: The opacity $o_v$ of a slab is related to density $d_v$ and thickness $t_v$ by [S2, unofficial]:
    $$ o_v = 1 - e^{-d_v t_v} $$
    where $0 < o_v < 1$ and $o_v = 1$ signifies complete attenuation.
*   **Front Sliver Opacity**: The opacity $o_f$ of the portion of a slab lying immediately in front of an embedded plane perpendicular to the viewing ray is [S2, unofficial]:
    $$ o_f = 1 - (1 - o_v)^{t_f/t_v} $$
    where $t_f$ is the thickness of the front portion and $t_v$ is the total slab thickness.
*   **Back Sliver Opacity**: The opacity $o_b$ of the portion of a slab lying immediately behind an embedded plane perpendicular to the viewing ray is [S2, unofficial]:
    $$ o_b = 1 - (1 - o_v)^{t_b/t_v} $$
    where $t_b$ is the thickness of the back portion.

### Parameters
*   **Slab Thickness**: Equal to the spacing between samples along a viewing ray [S2, unofficial].
*   **Slab Width**: Equal to the spacing between adjacent rays [S2, unofficial].
*   **Threshold $\theta$**: Used in adaptive supersampling to determine if geometric events are visible [S2, unofficial]. Value not given in the sources.

### Edge Cases and Pitfalls
*   **Visibility Errors**: Volumetric samples lying immediately in front of and behind polygons require special treatment to avoid errors in visibility [S1, S2, unofficial]. The slab splitting method addresses this [S2, unofficial].
*   **Aliasing**: Binary voxel representations in scan-conversion result in aliasing. This is handled by bandlimiting the object to the Nyquist frequency before sampling [S1, unofficial].
*   **Supersampling Ambiguity**: Distinguishing whether color difference is due to volumetric data or geometric data is difficult. The use of $C_x$ and $C_q$ resolves this [S2, unofficial].

## Subtopics

### Hybrid Ray Tracing with Volume Data
A rendering method that combines shaded polygons with volumetric data by treating surfaces as infinitesimally thin solids, using a binary voxel representation for the geometry, and rendering the composite dataset using volume rendering techniques to avoid aliasing artifacts [S1, unofficial]. Unlike the direct ray-tracing variant, this approach does not require supersampling if polygons are sufficiently bandlimited prior to sampling [S1, unofficial]. It is chosen when hardware acceleration for volume rendering is available and polygonal aliasing can be mitigated by pre-filtering [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: The hybrid ray tracer is computationally expensive due to ray-polygon intersection tests and adaptive supersampling [S2, unofficial]. The 3D scan-conversion method requires 3D scan-conversion and filtering of polygons, which can be costly for complex meshes [S1, unofficial].
*   **Memory Complexity**: Requires storage for both the volumetric data and the polygonal database [S2, unofficial]. The scan-conversion method requires additional memory for the binary voxel representation of the geometry [S1, unofficial].
*   **Performance**: The hybrid ray tracer provides high-quality images with correct visibility but is slow due to supersampling [S2, unofficial]. The scan-conversion method is faster if efficient 3D scan-conversion algorithms are used, but may suffer from aliasing if bandlimiting is insufficient [S1, unofficial].
*   **Strengths**: Handles mixtures of geometry and volume correctly; avoids errors in visibility with proper slab handling [S2, unofficial]. Scan-conversion avoids ray-polygon intersection complexity [S1, unofficial].
*   **Limitations**: Supersampling increases rendering time significantly [S2, unofficial]. Scan-conversion may lose geometric detail if not bandlimited properly [S1, unofficial].
*   **When to use**: Use when high-quality mixing of geometry and volume is required and performance is not the primary constraint [S2, unofficial]. Use scan-conversion when hardware acceleration for volume rendering is available and geometry is simple enough to be bandlimited effectively [S1, unofficial].

## Background
The concept of a hybrid ray tracer handling both scalar fields and polygons was proposed by multiple researchers including Kajiya (1984), Levoy (1988a), DeRose (1988), and Upson (1988) [S1, unofficial]. However, no implementation was reported until Kaufman et al. published their methods [S1, S2, unofficial]. The hybrid ray tracer was described in detail by Kaufman et al. in 1990 [S2, S3, unofficial]. The 3D scan-conversion method was also developed by Kaufman et al. as an alternative to avoid aliasing and supersampling costs [S1, unofficial]. These methods are foundational for applications such as virtual endoscopy, where synthetic objects (probes, catheters) must be mixed with anatomical volume data (CT/MR) [S3, unofficial].
