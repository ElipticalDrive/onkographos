# Hybrid Ray Tracing

Also called: Hybrid Ray Tracer, Hybrid Ray Tracing for Geometric/Volumetric Mixing, Mixing Polygons and Volumes

## Overview
Hybrid Ray Tracing is a method for mixing geometric and volumetric data by casting rays through the ensemble of both, drawing samples of each, and compositing them in depth-sorted order [S1, S2, unofficial]. It solves the problem of rendering scenes containing both explicit polygonal primitives and implicit scalar fields (volumes) while maintaining correct visibility and anti-aliasing [S2, unofficial]. Unlike sibling methods that convert geometry to volume (3D scan-conversion) or use hardware depth buffers for clipping, this method simultaneously traces rays through volumetric sample arrays and polygonal databases, resampling both at equally spaced intervals to handle mixtures directly in the ray space [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An $N \times N \times N$ voxel array of scalar values (volumetric data) and a set of embedded polygonal primitives [S2, unofficial].
*   **Output:** A final image color for each pixel, computed by compositing volumetric and geometric contributions [S2, unofficial].

**Data Structures:**
*   **Volumetric Data:** A 3D grid where each voxel stores a scalar value. This is pre-processed to yield a color $c_v$ and opacity $o_v$ for each voxel using a transfer function [S2, unofficial].
*   **Geometric Data:** A list of polygons (e.g., triangles) with associated shading attributes (color $c_p$, opacity $o_p$) [S2, unofficial].

**Algorithm Steps:**
The method proceeds per pixel/ray as follows:

1.  **Ray Casting:** Parallel viewing rays are traced from the observer position into the data [S2, unofficial].
2.  **Volumetric Sampling:** For each ray, a vector of colors $c_v$ and opacities $o_v$ is computed by resampling the volumetric data at equally spaced positions along the ray. The color and opacity at each sample location are obtained by tri-linearly interpolating from the colors and opacities in the eight surrounding voxels [S2, unofficial]. The spacing between samples equals the spacing between voxels to minimize aliasing [S2, unofficial].
3.  **Geometric Intersection:** Independently, all intersections between the ray and polygons in the environment are computed. Each intersection is shaded to yield a color $c_p$ and opacity $o_p$ [S2, unofficial].
4.  **Slab Decomposition:** The space along the ray is conceptually divided into slabs, where the thickness of each slab equals the spacing between samples along the viewing ray [S2, unofficial].
5.  **Handling Embedded Polygons:** When a polygon intersects a slab, it is treated locally as a plane perpendicular to the ray at the intersection point [S2, unofficial]. The slab is split into a front portion (thickness $t_f$) and a back portion (thickness $t_b$) relative to this plane. The opacities for these portions are calculated using exponential attenuation formulas [S2, unofficial]:
    $$ o_v = 1 - e^{-d_v t_v} $$
    $$ o_f = 1 - (1 - o_v)^{t_f/t_v} $$
    $$ o_b = 1 - (1 - o_v)^{t_b/t_v} $$
    where $d_v$ is the density, $t_v$ is the total slab thickness, $o_v$ is the total slab opacity, $o_f$ is the front portion opacity, and $o_b$ is the back portion opacity [S2, unofficial].
6.  **Depth-Sorted Compositing:** Samples from both sources are composited in depth-sorted order (front-to-back) [S2, unofficial].
    *   If a ray intersects more than one polygon within a slab, the contribution of each polygon and each sliver of volumetric gel is computed and composited separately [S2, unofficial].
    *   The compositing order for a single polygon intersection within a slab is:
        1.  Composite the front volumetric sliver ($c_v, o_f$).
        2.  Composite the polygon ($c_p, o_p$).
        3.  Composite the back volumetric sliver ($c_v, o_b$) [S2, unofficial].
7.  **Adaptive Supersampling:** To avoid aliasing at polygonal edges, intersections, and highlights, adaptive supersampling is employed [S2, unofficial].
    *   Two auxiliary colors are computed during the initial ray trace:
        *   $C_x$: Contributions only from polygons (volumetric opacity $o_v$ set to 0).
        *   $C_q$: Contributions only from polygons, attenuated by volumetric data (volumetric opacity $o_v$ set to 0, but volumetric color $c_v$ is used for attenuation) [S2, unofficial].
    *   Let $\theta$ be a threshold.
        *   If range($C_x$) > $\theta$ and range($C_q$) $\le \theta$: The difference is due to volumetric data; do not supersample [S2, unofficial].
        *   If range($C_q$) > $\theta$ and range($C_x$) $\le \theta$: The geometric event is hidden by opaque volume; do not supersample [S2, unofficial].
        *   If range($C_x$) > $\theta$ and range($C_q$) > $\theta$: A visible geometric event exists; cast more rays (supersample) [S2, unofficial].

**Pseudocode:**

```python
def hybrid_ray_trace(ray, volume_data, polygons, threshold_theta):
    # 1. Sample Volume
    vol_samples = []
    t = 0.0
    while t < ray.length:
        pos = ray.origin + ray.direction * t
        c_v, o_v = trilinear_interpolate(volume_data, pos)
        vol_samples.append({'t': t, 'c': c_v, 'o': o_v})
        t += sample_spacing # Equal to voxel spacing
    
    # 2. Intersect Polygons
    poly_intersections = []
    for poly in polygons:
        hit = ray_intersect_ray_poly(ray, poly)
        if hit:
            c_p, o_p = shade_poly(poly, hit.normal)
            poly_intersections.append({'t': hit.distance, 'c': c_p, 'o': o_p})
    
    # 3. Sort all events by depth t
    events = vol_samples + poly_intersections
    events.sort(key=lambda x: x['t'])
    
    # 4. Composite
    final_color = (0, 0, 0)
    accumulated_opacity = 0.0
    
    for event in events:
        # If event is a polygon, handle slab splitting
        if event in poly_intersections:
            # Find the slab containing this intersection
            # Simplified: assume event.t falls within a specific slab index
            # Calculate front and back opacities for that slab
            slab_idx = get_slab_index(event['t'])
            slab = vol_samples[slab_idx]
            slab_thickness = sample_spacing
            
            # Calculate distances from slab start to intersection
            t_f = event['t'] - (slab_idx * sample_spacing)
            t_b = slab_thickness - t_f
            
            # Calculate partial opacities
            # o_v is the total opacity of the slab
            o_v = slab['o']
            o_f = 1.0 - (1.0 - o_v) ** (t_f / slab_thickness)
            o_b = 1.0 - (1.0 - o_v) ** (t_b / slab_thickness)
            
            # Composite Front Sliver
            alpha = o_f * (1.0 - accumulated_opacity)
            final_color += slab['c'] * alpha
            accumulated_opacity += alpha
            
            # Composite Polygon
            alpha = event['o'] * (1.0 - accumulated_opacity)
            final_color += event['c'] * alpha
            accumulated_opacity += alpha
            
            # Composite Back Sliver
            alpha = o_b * (1.0 - accumulated_opacity)
            final_color += slab['c'] * alpha
            accumulated_opacity += alpha
            
        else:
            # Standard Volume Sample
            alpha = event['o'] * (1.0 - accumulated_opacity)
            final_color += event['c'] * alpha
            accumulated_opacity += alpha
            
        if accumulated_opacity >= 1.0:
            break
            
    return final_color

def adaptive_supersample_check(ray, volume_data, polygons, threshold_theta):
    # Compute Cx: Polygons only, no volume opacity
    Cx = composite_polygons_only(ray, volume_data, set_vol_opacity_to_zero=True)
    
    # Compute Cq: Polygons only, but attenuated by volume color (no volume opacity)
    Cq = composite_polygons_only(ray, volume_data, set_vol_opacity_to_zero=True, use_vol_color_for_attenuation=True)
    
    range_Cx = max(Cx) - min(Cx)
    range_Cq = max(Cq) - min(Cq)
    
    if range_Cx > threshold_theta and range_Cq <= threshold_theta:
        return False # Volumetric variation, no supersample
    if range_Cq > threshold_theta and range_Cx <= threshold_theta:
        return False # Hidden geometry, no supersample
    if range_Cx > threshold_theta and range_Cq > threshold_theta:
        return True # Visible geometry, supersample
    return False
```

## Subtopics

### Hybrid Ray Tracing with Volume Data
A variant that combines shaded polygons with volumetric data by treating surfaces as infinitesimally thin solids, using a binary voxel representation for the geometry, and rendering the composite dataset using volume rendering techniques [S1, unofficial]. Unlike the primary hybrid ray tracer which casts rays through both simultaneously, this method converts polygons into a sampled volume via 3D scan-conversion [S1, unofficial]. It requires bandlimiting the object to the Nyquist frequency in all three dimensions prior to sampling to avoid aliasing artifacts, after which no supersampling is required [S1, unofficial]. This approach avoids the complexity of depth-sorted compositing between distinct ray traces but incurs the cost of 3D scan-conversion and filtering [S1, unofficial].

## Operating characteristics
*   **Complexity:** The method requires intersecting rays with all polygons and sampling the volume along the ray. The complexity is $O(R \cdot (N + P))$ where $R$ is the number of rays, $N$ is the number of volume samples per ray, and $P$ is the number of polygons [S2, unofficial]. Adaptive supersampling increases $R$ locally at edges [S2, unofficial].
*   **Performance:** The method is computationally expensive due to the simultaneous processing of two data structures and the overhead of adaptive supersampling [S2, unofficial]. It is slower than pure volume rendering or pure rasterization but provides higher quality for mixed scenes [S2, unofficial].
*   **Strengths:** Correctly handles visibility between geometry and volume without depth-buffer artifacts; provides anti-aliasing through adaptive supersampling; allows for complex interactions like shadows and textures if extended [S1, S2, unofficial].
*   **Limitations:** Requires significant memory for both data structures; the approximation of treating polygons as planes perpendicular to the ray within slabs can introduce errors if the polygon curvature is high or the slab thickness is large [S2, unofficial].
*   **When to use:** When high-quality rendering of mixed geometric and volumetric data is required, and performance is secondary to correctness [S2, unofficial].

## Background
The concept of a hybrid ray tracer handling both scalar fields and polygons was proposed by researchers such as Kajiya (1984), Levoy (1988a), and Upson (1988) [S1, unofficial]. However, no implementation was reported until Levoy (1990b) presented two methods: the hybrid ray tracer and 3D scan-conversion [S1, S2, unofficial]. The hybrid ray tracer method was detailed in the technical report "Rendering Mixtures of Geometric and Volumetric Data" [S2, unofficial]. It builds on the volume rendering algorithm described by Levoy (1988a) [S2, unofficial]. The method is particularly relevant in medical applications such as virtual endoscopy, where CT/MR volumes are combined with synthetic objects like surgical instruments [S3, unofficial].
