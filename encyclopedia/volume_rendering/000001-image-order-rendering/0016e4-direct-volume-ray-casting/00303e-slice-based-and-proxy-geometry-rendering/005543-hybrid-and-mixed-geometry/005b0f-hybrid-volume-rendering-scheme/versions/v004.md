# Hybrid Volume Rendering Scheme

Also called: Scalable Hybrid Scheme, Hybrid between classical object order and image order

## Overview
The Hybrid Volume Rendering Scheme is a parallel volume rendering algorithm for unstructured grids that combines object-order and image-order techniques to handle complex block boundaries, dramatic cell size variations, and camera-induced load imbalances [S1]. Unlike pure image-order methods, which suffer from replicated cell loading and unequal cell distribution, or pure object-order methods, where image compositing becomes a bottleneck, this approach bounds the computation of each processing phase to adapt dynamically to the workload [S1].

## How it works
The algorithm operates on unstructured grids (and structured ones) by dividing work over resources such that each phase of processing is bounded in the amount of computation it can perform [S1]. The method addresses the memory footprint issues of the original 2006 Childs et al. technique by introducing the concept of partial composites [S1].

**Inputs and Outputs:**
*   **Input:** Unstructured volume data (mesh), camera parameters, transfer function, and image resolution [S1, G].
*   **Output:** Final composited image [S1, G].

**Data Structures:**
*   **Unstructured Grid:** Defined by cells and vertices, with sizes and shapes that may vary dramatically [S1, G].
*   **Partial Composites:** Intermediate image tiles stored to reduce memory footprint compared to storing full intermediate results [S1].
*   **Processor Partitioning:** Work is distributed across $P$ processors [S1].

**Steps:**
1.  **Phase 1: Object-Order Ray Casting (Bounded):** Processors perform ray casting on their local portion of the unstructured grid [S1]. To prevent load imbalance caused by large cells or camera focus, the processing of large cells is deferred [S1]. Each processor bounds the amount of computation it performs in this phase to ensure balanced workload distribution [S1]. Rays are cast through the cells owned by the processor [G]. For each ray, the scalar values are sampled along the ray path within the cell [G]. The sampled values are mapped to color and opacity using the transfer function [G]. Instead of compositing into a single final image immediately, processors generate partial composites for their assigned tiles [S1].
2.  **Phase 2: Image Compositing (Bounded):** The partial composites from all processors are collected and composited to produce the final image [S1]. This phase handles the depth ordering and blending of the partial results [G]. The amount of computation in this phase is also bounded to maintain balance [S1].
3.  **Handling Load Imbalance:** If a processor owns larger cells or the camera view focuses on a region owned by one processor, the workload would normally be unequal [S1]. The hybrid approach solves this by deferring the processing of large cells in Phase 1 and distributing the workload among processors in Phase 2 [S1].

**Formulas:** Not given in the sources.

**Parameters:**
*   **Number of Processors ($P$):** Scaled up to 8,192 processors [S1].
*   **Data Size:** Operated on data sets with more than one billion cells [S1].
*   **Partial Composite Size:** Not given in the sources [S1].

**Edge Cases and Pitfalls:**
*   **Memory Footprint:** The original 2006 technique required unnecessarily large amounts of memory to store intermediate results, affecting timing and causing crashes [S1]. The scalable hybrid scheme introduces partial composites to mitigate this [S1].
*   **Load Imbalance:** Caused by varying cell sizes or camera positions focusing on specific regions [S1]. The hybrid approach manages this by bounding computation per phase [S1].
*   **Many-Core Architectures:** The algorithm was adapted to support many-core architectures, accounting for the changed balance of computing and communication inherent in these environments [S1].

## Operating characteristics
*   **Time Complexity:** The algorithm adapts its computation based on workload, performing well in all cases tested (varying camera position, data set size, transfer function, image size, and processor count) [S1].
*   **Memory Complexity:** Reduced memory footprint compared to the original 2006 technique due to the use of partial composites [S1].
*   **Scalability:** Scaled up to 8,192 processors and operated on data sets with more than one billion cells [S1].
*   **Strengths:** Handles complex block boundaries, dramatic cell size variations, and camera-induced load imbalances effectively [S1]. It can operate like either an object-order or image-order technique depending on the scenario [S1].
*   **Limitations:** The original technique had high memory requirements (addressed in the scalable version) [S1].
*   **When to Use:** When dealing with unstructured grids with varying cell sizes or when camera position causes load imbalance in traditional methods [S1].
*   **When Not to Use:** Not specified in the sources [S1].

## Background
The approach is based on a 2006 method by Childs et al. [S1], which was a hybrid between object-order and image-order techniques for unstructured meshes [S1]. The original work was lacking in three major respects: insufficient evaluation, high memory requirements for intermediate results, and no consideration for many-core architectures [S1]. The scalable hybrid scheme addresses these shortcomings by providing a comprehensive evaluation, introducing partial composites to reduce memory footprint, and adding support for many-core architectures [S1].
