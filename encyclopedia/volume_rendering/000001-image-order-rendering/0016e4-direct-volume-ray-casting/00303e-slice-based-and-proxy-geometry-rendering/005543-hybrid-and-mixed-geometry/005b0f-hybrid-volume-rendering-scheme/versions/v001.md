# Hybrid Volume Rendering Scheme

Also called: Scalable Hybrid Scheme, Hybrid between classical object order and image order

## Overview
The Hybrid Volume Rendering Scheme is a parallel volume rendering algorithm for unstructured grids that hybridizes object-order and image-order techniques to handle complex block boundaries, dramatic cell size variations, and camera-induced load imbalances [S1]. It solves the problem of performance degradation in pure object-order or image-order methods when cell sizes vary significantly or when the camera focuses on specific regions, causing uneven workload distribution [S1]. Unlike pure image-order, which suffers from replicated cell loading and unequal cell distribution, and pure object-order, where image compositing becomes a bottleneck, this method adapts its computation based on workload by bounding the amount of computation per phase [S1].

## How it works
The algorithm divides work over resources such that each phase of its processing is bounded in the amount of computation it can perform, allowing it to adapt to the workload [S1]. It addresses the memory footprint issues of the base method by introducing the concept of partial composites [S1]. The implementation supports many-core architectures, adapting to the changed balance of computing and communication inherent in many-core environments [S1].

**Inputs:** Unstructured volume data (scalar field mapped to color/opacity), camera parameters, transfer function, image resolution, processor count.
**Outputs:** Final rendered image.

**Data Structures:**
*   **Unstructured Grid:** Collection of cells (e.g., tetrahedra, hexahedra) with associated scalar values.
*   **Partial Composite:** An intermediate image tile or sub-image generated by a subset of processors or a subset of cells, used to reduce memory footprint [S1].
*   **Depth Buffer:** Hardware depth buffer used to resolve visibility between geometry and volume if hybridized with explicit geometry (as per parent principles) [S1].

**Steps:**
1.  **Initialization:** Distribute the unstructured grid data among processors. Initialize the image buffer and depth buffer [S1].
2.  **Phase 1: Object-Order Processing:** Process cells locally on each processor. For each cell, determine its projection onto the image plane. If the cell is small or fully contained within a single tile, render it directly to the local image buffer using ray casting or texture mapping [S1].
3.  **Phase 2: Deferral of Large Cells:** Identify cells that are large, span multiple tiles, or cause load imbalance. Defer the processing of these cells to a later phase [S1].
4.  **Phase 3: Image-Order Processing (Load Balancing):** Distribute the deferred large cells among processors to balance the workload. This phase ensures that no single processor is overwhelmed by a few large cells or a concentrated camera view [S1].
5.  **Partial Composite Generation:** Generate partial composites for the processed cells. These are intermediate image tiles that represent the contribution of a subset of cells to the final image [S1].
6.  **Image Compositing:** Collect and composite the partial composites from all processors. This step resolves depth ordering and blends the contributions to produce the final image [S1].
7.  **Final Image Output:** The final image is produced by combining the geometric contribution (if any) and the volumetric contribution [S1].

**Edge Cases and Pitfalls:**
*   **Memory Footprint:** The original 2006 Childs et al. technique required unnecessarily large amounts of memory to store intermediate results, affecting timing and causing crashes [S1]. The scalable hybrid scheme addresses this with partial composites [S1].
*   **Load Imbalance:** Pure image-order suffers from replicated cell loading and unequal cell distribution. Pure object-order suffers from image compositing bottlenecks and load imbalance if the camera zooms into a region [S1]. The hybrid scheme mitigates these by deferring large cells and distributing workload [S1].

## Background
The approach is based on a 2006 method by Childs et al. [1], which was a hybrid between object-order and image-order techniques for unstructured meshes [S1]. The original technique was lacking in three major respects: insufficient evaluation, large memory footprint for intermediate results, and no consideration for many-core architectures [S1]. The scalable hybrid scheme addresses these shortcomings by providing a more comprehensive evaluation, introducing partial composites to reduce memory footprint, and adding support for many-core architectures [S1].
