# Slice-based and Proxy Geometry Rendering

Also called: Texture-Based Volume Rendering, Proxy Geometry Rendering, View-Aligned Slicing, Object-Aligned Slicing

## Overview
Slice-based and Proxy Geometry Rendering is an image-order direct volume ray casting technique that performs sampling and compositing by rasterizing a set of 2D geometric primitives (proxy geometry) inside the volume [S2, unofficial][S6]. It solves the problem of rendering volumetric data on graphics hardware by leveraging the standard graphics pipeline's rasterization and blending stages [S1][S4, unofficial]. Unlike pure ray marching which computes samples per pixel, this method projects slices through the volume, sorting them back-to-front to accumulate optical properties via alpha blending [S1][S3, unofficial]. It is distinguished from sibling methods by its reliance on explicit polygon primitives for sampling rather than implicit ray traversal or slow CPU-based grid visualization [S1][S2, unofficial].

## Shared principles
The method implements the emission-absorption optical model, computing the light intensity reaching the eye by integrating radiative energy along a ray through the scalar volume [S1, S5, S9, unofficial]. The process follows a strict pipeline for each pixel: ray generation, sampling, classification (transfer function application), shading, and compositing [S4, S34, unofficial].

### Ray Generation and Discretization
For each pixel, a ray $r(t) = \mathbf{o} + t\mathbf{d}$ is defined, where $\mathbf{o}$ is the camera origin and $\mathbf{d}$ is the direction [S1, S2, S3, S4, S5, S6, S7, S8, S9, S10, S11, S12, S13, S14, S15, S16, S17, S18, S19, S20, S21, S22, S23, S24, S25, S26, S27, S28, S29, S30, S31, S32, S33, S34, S35, S36, S37, S38, S39, S40, S41, S42, S43, S44, S45, S46, S47, S48, S49, S50, S51, S52, S53, S54, S55, S56, S57, S58, S59, S60, S61, S62, S63, S64, S65, S66, S67, S68, S69, S70, S71, S72, S73, S74, S75, S76, S77, S78, S79, S80, S81, S82, S83, S84, S85, S86, S87, S88, S89, S90, S91, S92, S93, S94, S95, S96, S97, S98, S99, S100]. The ray is intersected with the volume domain (typically an axis-aligned bounding box) to determine the entry parameter $t_{start}$ and exit parameter $t_{end}$ [S1, S7, S15, S22, S33, S55, unofficial]. The segment $[t_{start}, t_{end}]$ is discretized into $N$ samples at equidistant intervals $\Delta t$ [S4, S8, S9, S16, S33, S40, unofficial]. The step size $\Delta t$ is often chosen to ensure at least one sample per voxel along the fastest axis to minimize aliasing, though adaptive stepping is also used [S36, unofficial][S46, abstract only, unofficial].

### Sampling and Interpolation
At each sample point $\mathbf{p}_i = r(t_i)$, the scalar volume value $V(\mathbf{p}_i)$ is reconstructed from the discrete voxel grid [S6, S7, S33, unofficial][S44, book]. Trilinear interpolation is the standard reconstruction filter for high-quality rendering, combining the eight surrounding voxels [S6, S7, S33, S40, unofficial]. Nearest-neighbor interpolation is used for performance or specific artifact styles [S43, unofficial][S44, book]. The interpolated value represents the local density or material property [S9, S18, unofficial].

### Classification (Transfer Function)
The scalar value $d_i = V(\mathbf{p}_i)$ is mapped to optical properties: color $C_i$ and opacity $\alpha_i$ [S2, S5, S11, S12, S25, S29, S31, S34, unofficial]. This mapping is defined by a transfer function $T(d_i)$ [S2, S5, S2789]. Pre-classification maps scalar values to RGBA before interpolation, while post-classification interpolates scalars first and then applies the transfer function [S4, unofficial][S44, book]. The opacity $\alpha_i$ determines the fraction of light absorbed or scattered at the sample [S18, S23, S51, unofficial].

### Compositing (Front-to-Back Integration)
The final pixel color $C_{final}$ is computed by integrating contributions from all samples along the ray from front to back ($t_{start}$ to $t_{end}$) [S1, S12, S16, S23, S24, S43, S50, S51, unofficial]. The standard compositing equation (over operator) updates the accumulated color $C'$ and accumulated opacity $\alpha'$ for each sample $i$:

$$
C'_{i} = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i
$$
$$
\alpha'_{i} = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i
$$

where $C'_0 = 0$ and $\alpha'_0 = 0$ [S12, S43, S50, unofficial]. The term $(1 - \alpha'_{i-1})$ represents the transmittance (light reaching the current sample) [S1, S51, unofficial]. If $\alpha'$ reaches 1 (or a threshold close to it), the ray can be terminated early, as subsequent samples are fully occluded [S9, S12, S27, unofficial].

### Shading
Shading models are applied to enhance depth perception. Common techniques include Phong or Blinn-Phong shading, which use the gradient of the volume data $\nabla V$ to compute surface normals for lighting calculations [S14, S15, S30, unofficial][S54]. The gradient is typically estimated using central differences or Sobel operators on the interpolated scalar field [S14, S30, unofficial][S54].

## Subtopics

### [2D Visualization from 3D Grid (Slow)](1507-2d-visualization-from-3d-grid-slow.md)
This method generates a 2D projection of a 3D scalar volume by processing the data as a series of 2D slices, applying a transfer function to each slice, and compositing them into a 2D image using the over operator. It solves the problem of visualizing medical, scientific, or natural volumetric data (such as fluids, smoke, or fire) without extracting explicit surface geometry. Unlike its sibling [Hybrid Ray Tracer](2308-hybrid-ray-tracer.md) which may use geometry acceleration, or [Texture-Based Volume Rendering](4707-texture-based-volume-rendering.md) which leverages hardware texture units, this approach explicitly iterates through slices or rays in a software-defined or less-optimized manner, often referred to as "slow" due to the lack of hardware-accelerated ray marching or pre-integration. It builds on the parent [Slice-based and Proxy Geometry Rendering](6225-slice-based-and-proxy-geometry-rendering.md) by relying on the volume rendering integral discretized into a summation over sample points along a ray.

### [Hybrid Ray Tracer](2308-hybrid-ray-tracer.md)
The Hybrid Ray Tracer is a rendering method that simultaneously traces rays through volumetric sample arrays and polygonal databases, resampling both at equally spaced intervals, and compositing the resulting colors and opacities in depth-sorted order to handle mixtures of geometric and volumetric data. It sets itself apart from pure volume ray casting by explicitly handling polygon intersections within the volumetric slabs, treating polygons locally as planes perpendicular to the ray to compute attenuated volumetric "slivers" before and after the intersection. Unlike 3D scan-conversion methods, it performs compositing in image space (ray space) rather than object space, avoiding the need to filter and sample polygons into the voxel grid.

### [Mixed Geometry Rendering](3442-mixed-geometry-rendering.md)
Mixed Geometry Rendering combines direct volume rendering of scalar fields with standard Z-buffer rendering of explicit geometric primitives (such as wireframes or surfaces) to provide structural context for volumetric data. It solves the problem of ambiguous spatial relationships in pure volume rendering by overlaying precise geometric boundaries, allowing viewers to distinguish between the interior density distribution and the external shell or grid structure. Unlike pure volume methods, it introduces a hard occlusion boundary where the geometry completely blocks the view of volume data behind it, while volume data in front of the geometry correctly transmits the geometry's color.

### [Texture-Based Volume Rendering](4707-texture-based-volume-rendering.md)
Texture-Based Volume Rendering (also known as Proxy Geometry Rendering) is an image-order direct volume ray casting technique that performs sampling and compositing by rasterizing a set of 2D geometric primitives (proxy geometry) inside the volume. It solves the problem of rendering volumetric data on graphics hardware by leveraging the standard graphics pipeline's rasterization and blending stages. Unlike pure ray marching which computes samples per pixel, this method projects slices through the volume, sorting them back-to-front to accumulate optical properties via alpha blending. It is distinguished from sibling methods by its reliance on explicit polygon primitives for sampling rather than implicit ray traversal or slow CPU-based grid visualization.

### [View-Aligned Slicing](6530-view-aligned-slicing.md)
View-aligned slicing is a proxy geometry technique that divides a 3D volume into planar slices and rotates them to align with the view plane, minimizing sampling artifacts and maintaining consistent slice thickness relative to the camera. It is chosen when consistent sampling distance is required across viewpoints, offering a trade-off of slower performance but higher memory efficiency compared to fixed-step ray casting.

### [Image-based rendering integration](6969-image-based-rendering-integration.md)
This method integrates volume rendering into a polygonal virtual environment by treating rendered volume images as image-based primitives (impostors) within the scene. It decouples the computationally expensive volume rendering process from the interactive client, distributing it to a separate server and transmitting the resulting images over a network. Unlike direct ray casting or texture-based methods that render the volume locally, this approach uses 2D quads textured with pre-rendered volume slices to represent 3D data, enabling seamless mixing of volume and polygonal rendering.

### [Vector Icon Volume Rendering](7693-vector-icon-volume-rendering.md)
Vector Icon Volume Rendering is a 3D raster resampling technique that integrates vector field visualization into volume rendering by embedding small billboard images containing vector icons within splat footprints. It solves the problem of visualizing flow direction and magnitude within a scalar volume (such as density clouds) by creating an illusion of coherent flow through stochastic placement. It sets itself apart from standard volume ray casting by modifying the volume integral to include discrete geometric primitives (cylinders/icons) within the splat footprint, rather than relying solely on scalar transfer functions.

### 2D Slice Replication Approach
- **Definition**: When data is stored as a set of 2D texture slices, proxy polygons are simply rectangles aligned with the slices [S1].
- **Steps**: Reconstruct slices on the fly to avoid data replication, with some performance overhead [S1]. Add intermediate slices and perform trilinear interpolation with a fragment shader to solve sampling rate dependency [S1].
- **Pitfalls**: Requires three times more memory because data slices need to be replicated along each principal direction [S1]. Sampling rate depends on the resolution of the volume [S1]. Sampling distance changes with the viewpoint, resulting in intensity variations as the camera moves and image-popping artifacts when switching from one set of slices to another [S1].

### Two-Pass Volume Rendering with Shadows
- **Definition**: A two-pass algorithm to render volumetric shadows on the GPU by modifying proxy geometry slicing to render from both the eye and the light's point of view [S2, unofficial].
- **Steps**: Set the slice axis half-way between the view direction and the light direction [S2, unofficial]. First Pass: Render from the eye. In the fragment shader, look up light color from a light buffer bound as a texture and multiply material color by light color [S2, unofficial]. Second Pass: Render from the light. In the fragment shader, only blend alpha values to compute light transmissivity [S2, unofficial].
- **Parameters**: Render order for light: front-to-back [S2, unofficial]. Render order for eye: front-to-back or back-to-front [S2, unofficial].

### Object-Aligned Slicing
- **Steps**: Create three stacks of 2D textures corresponding to the x, y, and z principal directions [S2, unofficial]. Swap the texture stack based on the viewpoint's closest principal direction [S2, unofficial].

## Background
The method was introduced in the early 2000s as a means to leverage the fixed-function pipeline of graphics hardware for volume rendering. Key developments include the use of 3D textures and proxy geometry for view-aligned slicing [S2, unofficial][S6]. The approach was further refined to handle shadows and translucency using two-pass techniques [S2, unofficial]. It is widely used in medical imaging and scientific visualization where interactive frame rates are required on standard graphics hardware.
