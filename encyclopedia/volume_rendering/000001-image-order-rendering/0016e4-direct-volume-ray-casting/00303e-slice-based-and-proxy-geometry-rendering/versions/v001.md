# Slice-based and Proxy Geometry Rendering

Also called: Texture-Based Volume Rendering, Proxy Geometry Rendering

## Overview
Slice-based and Proxy Geometry Rendering is an image-order direct volume ray casting technique that performs sampling and compositing by rasterizing a set of 2D geometric primitives (proxy geometry) inside the volume [S1][S3]. It solves the problem of rendering volumetric data on hardware that lacks native 3D texture sampling or ray marching capabilities by leveraging the standard graphics pipeline's rasterization and blending stages [S2, unofficial]. Unlike pure ray marching which computes samples per pixel, this method projects slices through the volume, sorting them back-to-front to accumulate optical properties via alpha blending [S1][S3]. It is distinguished from sibling methods by its reliance on explicit polygon primitives for sampling rather than implicit ray traversal or slow CPU-based grid visualization [S1][S2, unofficial].

## Shared principles
The method relies on the volume rendering integral, discretized into a summation over sample points along a ray [S3, S5, unofficial]. The ray $r$ is parameterized by $r(t) = O + tD$, entering the volume at $t_{start}$ and exiting at $t_{end}$ [Volume Raycasting Discretization](831-volume-raycasting-discretization.md). The data model is sampled using $s(t)$ [Volume Raycasting Discretization](831-volume-raycasting-discretization.md).

The compositing is performed front-to-back [S2, S3, S8, S9, S11, S14, S16, S20, S23, S26, unofficial]. Let $C'_i$ be the accumulated color and $\alpha'_i$ be the accumulated opacity after sample $i$, with initial conditions $C'_0 = 0$ and $\alpha'_0 = 0$ [S9, unofficial]. For each sample $i$ along the ray:
1.  Sample the volume at the current ray position to get a scalar value $d_i$ [S2, S5, unofficial].
2.  Apply a transfer function to map the scalar value to color $C_i$ and opacity $\alpha_i$ [S2, S5, unofficial].
3.  Update accumulated color:
    $$ C'_i = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i $$
4.  Update accumulated opacity:
    $$ \alpha'_i = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i $$
5.  If $\alpha' \ge 1$ or a threshold (typically 0.99) [S2, S18, unofficial], terminate the ray (early ray termination) [S2, S3, S4, unofficial].

Rays are cast from the eyepoint, one for each pixel [S1][S4, unofficial]. The volume is typically represented as a 3D texture [S4, S3, unofficial]. Gradients for shading are calculated using a central difference operator [S6, unofficial]. To avoid normal discontinuities that cause visible rings on smooth surfaces, the gradient is computed using a two-voxel offset rather than a one-voxel offset [S18, unofficial]. Sampling is performed using trilinear interpolation [S1][S5, unofficial]. A fixed random offset is applied to each ray's start position to prevent sample layers from appearing as bands [S18, unofficial]. The final accumulated color is typically corrected with gamma 2.2 [S9, unofficial].

```python
import random
import math

def vec3(x, y, z):
    return [x, y, z]

def pow_vec3(v, exponent):
    return [v[0]**exponent, v[1]**exponent, v[2]**exponent]

def compute_ray_exit(origin, direction, bounds):
    # Slab intersection for axis-aligned box [G]
    t0 = max((bounds[0][i] - origin[i]) / direction[i] if direction[i] != 0 else float('inf') for i in range(3))
    t1 = min((bounds[1][i] - origin[i]) / direction[i] if direction[i] != 0 else float('inf') for i in range(3))
    return max(t0, t1)

def trilinear_interpolate(volume, pos, dims):
    # Standard trilinear interpolation [G]
    vx = pos[0] * (dims[0] - 1)
    vy = pos[1] * (dims[1] - 1)
    vz = pos[2] * (dims[2] - 1)
    x0, y0, z0 = int(math.floor(vx)), int(math.floor(vy)), int(math.floor(vz))
    x1, y1, z1 = x0 + 1, y0 + 1, z0 + 1
    x0 = max(0, min(x0, dims[0]-1))
    x1 = max(0, min(x1, dims[0]-1))
    y0 = max(0, min(y0, dims[1]-1))
    y1 = max(0, min(y1, dims[1]-1))
    z0 = max(0, min(z0, dims[2]-1))
    z1 = max(0, min(z1, dims[2]-1))
    wx = vx - x0
    wy = vy - y0
    wz = vz - z0
    c00 = volume[x0][y0][z0] * (1-wx) + volume[x1][y0][z0] * wx
    c01 = volume[x0][y0][z1] * (1-wx) + volume[x1][y0][z1] * wx
    c10 = volume[x0][y1][z0] * (1-wx) + volume[x1][y1][z0] * wx
    c11 = volume[x0][y1][z1] * (1-wx) + volume[x1][y1][z1] * wx
    r0 = c00 * (1-wy) + c10 * wy
    r1 = c01 * (1-wy) + c11 * wy
    return r0 * (1-wz) + r1 * wz

def direct_volume_raycast(volume_data, camera, transfer_function, volume_bounds, volume_dims, step_size=0.001, threshold=0.99):
    """
    Renders a volume using fixed-step raycasting with front-to-back compositing.
    """
    h, w = camera.screen_height, camera.screen_width
    image = [[vec3(0.0, 0.0, 0.0) for _ in range(w)] for _ in range(h)]
    
    for y in range(h):
        for x in range(w):
            ray_origin, ray_direction = camera.cast_ray(x, y)
            accumulated_color = vec3(0.0, 0.0, 0.0)
            accumulated_opacity = 0.0
            
            # Ray initialization: fixed random offset to prevent banding [S18, unofficial]
            t = random.uniform(0.0, step_size)
            
            # Compute ray exit distance from volume bounds [G]
            t_end = compute_ray_exit(ray_origin, ray_direction, volume_bounds)
            
            while accumulated_opacity < threshold and t < t_end:
                # Compute current position in texture space [0,1]
                pos = [(ray_origin[i] + t * ray_direction[i]) for i in range(3)]
                # Sample volume at current position using trilinear interpolation [S1][S5, unofficial]
                scalar_value = trilinear_interpolate(volume_data, pos, volume_dims)
                
                # Apply transfer function to get color and opacity [S2, S5, unofficial]
                color, opacity = transfer_function(scalar_value)
                
                # Front-to-back compositing [S2, S5, unofficial]
                accumulated_color[0] += (1.0 - accumulated_opacity) * opacity * color[0]
                accumulated_color[1] += (1.0 - accumulated_opacity) * opacity * color[1]
                accumulated_color[2] += (1.0 - accumulated_opacity) * opacity * color[2]
                accumulated_opacity += (1.0 - accumulated_opacity) * opacity
                
                t += step_size
                
            # Gamma correction [S9, unofficial]
            image[y][x] = pow_vec3(accumulated_color, 1.0/2.2)
            
    return image
```

## Subtopics

### [2D Visualization from 3D Grid (Slow)](1507-2d-visualization-from-3d-grid-slow.md)
This method generates a 2D projection of a 3D scalar grid by processing the volume data as a series of 2D slices, applying a transfer function to each slice, and compositing them into a 2D image using the over operator. It solves the problem of visualizing medical/scientific data and natural effects like fluids, smoke, and fire without extracting any surface geometry. It differs from its sibling [Texture-Based Volume Rendering](4707-texture-based-volume-rendering.md) by performing explicit per-slice compositing in software (or CPU-side) rather than leveraging hardware-accelerated texture sampling and fragment shaders for ray casting.

### [Hybrid Ray Tracer](2308-hybrid-ray-tracer.md)
A rendering method that simultaneously traces rays through volumetric sample arrays and polygonal databases, resampling both at equally spaced intervals, and compositing the resulting colors and opacities in depth-sorted order to handle mixtures of geometric and volumetric data. It sets itself apart from pure volume rendering by explicitly handling polygonal intersections within volumetric slabs using exponential attenuation approximations, and from pure ray tracing by treating the volume as a resampled slab-based medium rather than a continuous density field.

### [Mixed Geometry Rendering](3442-mixed-geometry-rendering.md)
Mixed Geometry Rendering combines direct volume ray casting with standard Z-buffer surface rendering to visualize scalar fields alongside explicit geometric structures, such as finite element meshes or computational fluid dynamics grids. It solves the problem of contextualizing volumetric data by allowing users to see the underlying structural boundaries (wireframes or surfaces) while retaining the internal density information of the volume. Unlike pure volume rendering, it introduces a hybrid occlusion model where explicit geometry can occlude the volume, but the volume correctly transmits light from geometry behind it, distinguishing it from [2D Visualization from 3D Grid (Slow)](1507-2d-visualization-from-3d-grid-slow.md) which lacks this explicit geometric overlay, and [Texture-Based Volume Rendering](4707-texture-based-volume-rendering.md) which relies on texture mapping rather than explicit mesh integration.

### [Texture-Based Volume Rendering](4707-texture-based-volume-rendering.md)
Texture-Based Volume Rendering (also known as Proxy Geometry Rendering) is an image-order direct volume ray casting technique that performs sampling and compositing by rasterizing a set of 2D geometric primitives (proxy geometry) inside the volume. It solves the problem of rendering volumetric data on hardware that lacks native 3D texture sampling or ray marching capabilities by leveraging the standard graphics pipeline's rasterization and blending stages. Unlike pure ray marching which computes samples per pixel, this method projects slices through the volume, sorting them back-to-front to accumulate optical properties via alpha blending. It is distinguished from sibling methods by its reliance on explicit polygon primitives for sampling rather than implicit ray traversal or slow CPU-based grid visualization.

#### 2D Slice Replication Approach
- **Definition**: When data is stored as a set of 2D texture slices, proxy polygons are simply rectangles aligned with the slices [S1].
- **Steps**: Reconstruct slices on the fly to avoid data replication, with some performance overhead [S1]. Add intermediate slices and perform trilinear interpolation with a fragment shader to solve sampling rate dependency [S1].
- **Pitfalls**: Requires three times more memory because data slices need to be replicated along each principal direction [S1]. Sampling rate depends on the resolution of the volume [S1]. Sampling distance changes with the viewpoint, resulting in intensity variations as the camera moves and image-popping artifacts when switching from one set of slices to another [S1].

## Background
The technique was popularized in the early 2000s as graphics hardware gained support for 3D textures and fragment shaders. Key references include Lefohn et al. (2004) for on-the-fly slice reconstruction, Rezk-Salama et al. (2000) for trilinear interpolation in fragment shaders, and Kniss et al. (2002b) for addressing intensity variations and image-popping artifacts [S1]. It is widely used in medical imaging and scientific visualization where real-time interaction is required on older or constrained hardware [S1].
