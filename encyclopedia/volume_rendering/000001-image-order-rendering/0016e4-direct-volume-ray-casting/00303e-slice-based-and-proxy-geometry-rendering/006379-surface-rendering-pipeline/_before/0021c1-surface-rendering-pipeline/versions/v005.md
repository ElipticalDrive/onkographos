# Surface Rendering Pipeline

Also called: Surface Rendering (R_so, Surface Rendering from Volume

## Overview
Surface rendering is a volume rendering mode that stops at the first voxel inside a threshold and shades it with a normal taken from the value gradient [S1, unofficial]. It generates no mesh or triangles, avoiding invented shapes between voxels [S1, unofficial]. Unlike volume rendering which integrates over slice spacing, surface rendering exposes the slice spacing as terracing artifacts [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field (volume data), a threshold value, a camera configuration (position, orientation, image size $W \times H$), and a light direction [S2, unofficial][S1, unofficial].
*   **Output:** A 2D color image of size $H \times W \times 3$ [S2, unofficial].

**Data Structures:**
*   **RayBundle:** Contains origins, directions, and sample points for each pixel [S2, unofficial].
*   **SurfaceModel:** Contains `implicit_fn`, `sampler`, and `renderer` modules initialized from configuration dictionaries [S2, unofficial].
*   **Volume Data:** Stored as a scalar field accessible via the implicit function or sampler [S2, unofficial].

**Method Steps:**
1.  **Initialization:** Initialize the `SurfaceModel` with an implicit function, a sampler, and a renderer from configuration dictionaries [S2, unofficial].
2.  **Coordinate Generation:** For each camera, generate normalized image plane coordinates $xy\_grid$ based on the image dimensions [S2, unofficial].
    $$ x = \text{linspace}(-1, 1, W) $$
    $$ y = \text{linspace}(-1, 1, H) $$
    $$ xy\_grid = \text{meshgrid}(y, x) $$
3.  **Ray Generation:** Generate a ray bundle from the pixel coordinates using the camera's inverse projection matrix to obtain ray origins and directions [S2, unofficial].
4.  **Ray Marching:** March each ray until the first voxel value exceeds the specified threshold [S1, unofficial].
5.  **Normal Estimation:** Compute the surface normal at the hit point using the gradient of the scalar field [S1, unofficial]. The method is classified as scene space, object space, or view space depending on the normal estimation technique [S3].
6.  **Rendering:** Pass the ray bundle and light direction through the model to compute the final color [S2, unofficial]. Reshape the output tensor to $H \times W \times 3$ and convert to a standard image array [S2, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def get_normalized_image_plane_coordinates(image_size):
    W, H = image_size
    x = torch.linspace(-1, 1, steps=W)
    y = torch.linspace(-1, 1, steps=H)
    grid_y, grid_x = torch.meshgrid(y, x)
    xy_grid = torch.stack((grid_x, grid_y), dim=-1).view(W * H, 2)
    return -xy_grid

def get_rays_from_pixels(xy_grid, camera):
    N = xy_grid.shape[0]
    xy_grid_copy = xy_grid.clone().to(camera.device)
    ndc_pts_ip = torch.cat([xy_grid_copy, torch.ones([N, 1], device=camera.device)], dim=-1)
    # Standard inverse projection: world = inv_proj @ ndc
    unprojected = camera.inverse_projection @ ndc_pts_ip.T
    origins = unprojected[:3, :]
    directions = unprojected[3:, :]
    directions = directions / torch.norm(directions, dim=0, keepdim=True)
    return origins.T, directions.T

def march_to_surface(origins, directions, implicit_fn, threshold, max_steps=1000, step_size=0.01):
    # Advance along ray until implicit_fn value > threshold
    t = torch.arange(max_steps, device=origins.device).unsqueeze(1) * step_size
    sample_points = origins.unsqueeze(1) + directions.unsqueeze(1) * t.unsqueeze(2)
    values = implicit_fn(sample_points)
    hit_mask = values > threshold
    hit_indices = hit_mask.argmax(dim=1)
    hit_points = sample_points[torch.arange(len(origins)), hit_indices]
    return hit_points

def compute_gradient_at_point(point, implicit_fn):
    # Central finite differences for normal estimation
    eps = 1e-4
    dx = (implicit_fn(point + torch.tensor([eps, 0, 0])) - implicit_fn(point + torch.tensor([-eps, 0, 0]))) / (2 * eps)
    dy = (implicit_fn(point + torch.tensor([0, eps, 0])) - implicit_fn(point + torch.tensor([0, -eps, 0]))) / (2 * eps)
    dz = (implicit_fn(point + torch.tensor([0, 0, eps])) - implicit_fn(point + torch.tensor([0, 0, -eps]))) / (2 * eps)
    return torch.stack([dx, dy, dz])

def surface_render_pipeline(volume_data, threshold, camera, image_size, light_dir):
    # 1. Generate rays
    xy_grid = get_normalized_image_plane_coordinates(image_size)
    origins, directions = get_rays_from_pixels(xy_grid, camera)

    # 2. March to first surface hit
    hit_points = march_to_surface(origins, directions, volume_data, threshold)

    # 3. Compute normals via gradient
    normals = compute_gradient_at_point(hit_points, volume_data)
    normals = normals / torch.norm(normals, dim=1, keepdim=True)

    # 4. Shade and composite
    diffuse = torch.clamp(torch.sum(normals * light_dir, dim=1), 0, 1)
    colors = volume_data(hit_points) * diffuse.unsqueeze(1)

    # 5. Reshape to image
    image = colors.view(image_size[1], image_size[0], 3)
    return image
```

**Parameters:**
*   **Threshold:** The scalar value separating background from surface voxels [S1, unofficial].
*   **Slice Spacing:** The physical distance between voxels along the depth axis, which directly determines the magnitude of terracing artifacts [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Terracing:** Discrete voxel sampling exposes slice spacing as visible stair-step artifacts, particularly when spacing is large (e.g., 3 mm) [S1, unofficial].
*   **Gradient Noise:** Computing normals via finite differences on unsmoothed scalar fields produces jagged normals and shading artifacts [S1, unofficial].
*   **Threshold Sensitivity:** Incorrect threshold selection either fragments the surface or includes background noise [S1, unofficial].

## Subtopics

### [Real Time Cutting Operations](3494-real-time-cutting-operations.md)
Real Time Cutting Operations clips volume surfaces using cutting planes by maintaining near and far depth buffers per pixel, avoiding full re-rendering when planes change. It differs from static cutting methods by dynamically filtering voxels per frame via halfspace checks, whereas static methods pre-filter and discard cut voxels.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Measured at 390×844 on a synthetic 700 HU sphere: surface rendering exposed 9.8% of the canvas at peak intensity 255, compared to volume rendering's 9.3% at 238 [S1, unofficial].
*   **Strengths:** No mesh generation overhead; avoids shape invention between voxels [S1, unofficial].
*   **Limitations:** Terracing artifacts due to discrete sampling; sensitive to threshold selection; does not reveal internal structure [S1, unofficial].

## Background
Surface rendering is classified as a scene space, object space, or view space operation depending on the normal estimation technique used [S3]. It is discussed within the framework of imaging transforms for visualizing surfaces and volumes, where it operates on explicit hard sets of volume or surface elements [S3].
