# Vector Icon Volume Rendering

Also called: Billboard vector icons, Vector Icon Splatting with Billboard Textures, Vector icons embedded in splat footprint, Volume Rendering with Embedded Vector Icons

## Overview
Vector Icon Volume Rendering is a 3D raster resampling technique that integrates vector field visualization into volume rendering by embedding small billboard images containing vector icons within splat footprints [S1, unofficial]. It solves the problem of visualizing flow direction and magnitude within a scalar volume (such as density clouds) by creating an illusion of coherent flow through stochastic placement [S1, unofficial]. It sets itself apart from standard volume ray casting by modifying the volume integral to include discrete geometric primitives (cylinders/icons) within the splat footprint, rather than relying solely on scalar transfer functions [S1, unofficial].

## How it works
The method builds upon the slice-based rendering principles of its parent [Slice-based and Proxy Geometry Rendering](6225-slice-based-and-proxy-geometry-rendering.md). It renders the volume in sheets oriented parallel to the image plane, compositing these sheets in a back-to-front order [S1, unofficial].

### Inputs and Outputs
- **Input:** A 3D scalar field (e.g., density) and a 3D vector field (e.g., wind velocity).
- **Input:** A set of billboard textures containing vector icons.
- **Output:** A 2D image where scalar volume is rendered and vector flow is indicated by colored icons.

### Data Structures
- **Billboard Textures:** A discrete set of textures. Each texture contains a vector icon. The icons vary in size to indicate direction relative to the viewer: largest when flow is parallel to the screen, reduced to a small dot when parallel to the line of sight [S1, unofficial].
- **Splat Footprint:** The area covered by the image reconstruction operator (splat) at each grid point [S1, unofficial].

### Steps
1.  **Sheet Generation:** Divide the volume into sheets oriented parallel to the image plane [S1, unofficial].
2.  **Sheet Compositing:** Process sheets in back-to-front order [S1, unofficial].
3.  **Grid Sampling:** For the current sheet, take a regular grid sampling of the data points [S1, unofficial].
4.  **Splat Placement:** Place an image reconstruction operator (splat) over each grid point [S1, unofficial].
5.  **Stochastic Decision:** Use a stochastic heuristic to determine whether the splat should include a vector icon (cylinder) [S1, unofficial].
6.  **Icon Placement:**
    - If the heuristic selects an icon, randomly offset the cylinder from the center of the splat [S1, unofficial].
    - Orient the billboard image such that it lies perpendicular to the viewing ray and parallel to the projected vector direction at the splat's center point [S1, unofficial].
    - Select the appropriate icon size based on the flow direction relative to the viewer [S1, unofficial].
7.  **Volume Integral Update:** Add the volume integral for each pixel under both the splat and the cylinder to the accumulated result [S1, unofficial].
8.  **Color Mapping:** Color the vector icons according to a scalar attribute, such as altitude [S1, unofficial].
9.  **Animation (Optional):** To alleviate sparse representation and create motion, cycle through a set of textures where icons move across the texture, fading in and out, at rendering time [S1, unofficial].

### Pseudocode
The following pseudocode illustrates the core stochastic splatting logic for a single sheet. It assumes the parent's compositing loop is active.

```python
import random

def render_vector_icon_sheet(scalar_field, vector_field, sheet_index, camera, billboard_textures):
    """
    Renders a single sheet of the volume with embedded vector icons.
    """
    # Get grid points for the current sheet [S1, unofficial]
    grid_points = get_grid_points_for_sheet(scalar_field, sheet_index)
    
    for point in grid_points:
        # Sample vector at grid point [S1, unofficial]
        v = vector_field.sample(point)
        
        # Stochastic heuristic to decide if icon is included [S1, unofficial]
        if random.random() < inclusion_probability:
            # Determine orientation: perpendicular to view, parallel to projected vector [S1, unofficial]
            billboard_orientation = compute_billboard_orientation(v, camera)
            
            # Select icon size based on flow direction [S1, unofficial]
            # Largest if parallel to screen, dot if parallel to view
            icon_size = compute_icon_size(v, camera)
            icon_texture = select_billboard_texture(billboard_textures, icon_size)
            
            # Random offset from center [S1, unofficial]
            offset = vec2(random.uniform(-0.5, 0.5), random.uniform(-0.5, 0.5))
            
            # Render the billboard with the icon at the offset position [S1, unofficial]
            render_billboard(icon_texture, billboard_orientation, point.position + offset)
            
            # Color the icon by altitude [S1, unofficial]
            altitude = scalar_field.sample_altitude(point)
            set_icon_color(altitude)
        
        # Render the base splat for the scalar field [S1, unofficial]
        render_splat(point)
```

### Parameters and Edge Cases
- **Inclusion Probability:** Not given in the sources. [G]
- **Icon Size Mapping:** Not given in the sources. [G]
- **Sparse Representation:** The discrete and sparse nature of the icons can make flow difficult to understand. This is mitigated by using cycling textures with fade-in/fade-out effects [S1, unofficial].
- **Time-Varying Fields:** For animated data, a new rendering is produced for each time step and animated in a movie loop [S1, unofficial].

## Operating characteristics
- **Strengths:** Merges scalar field rendering (e.g., density clouds) with vector field rendering (wind velocity) [S1, unofficial]. The stochastic placement creates an illusion of coherent flow rather than individual icons rotating [S1, unofficial].
- **Limitations:** The flow can be difficult to understand due to the sparse and discrete representation of the vector icons [S1, unofficial].

## Background
The technique was developed by R. Crawfis, H. Shen, and N. Max [S1, unofficial]. It is described in the context of flow visualization techniques for Computational Data Fields (CDF) using volume rendering [S1, unofficial]. The work was presented at the 9th International Symposium on Flow Visualization, Heriot-Watt University, Edinburgh, 2000 [S1, unofficial].
