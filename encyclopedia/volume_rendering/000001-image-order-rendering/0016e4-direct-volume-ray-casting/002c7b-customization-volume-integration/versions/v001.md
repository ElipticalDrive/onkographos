# Customization Volume Integration

Also called: Customization Volume Integration in Ray Casting, Position-dependent Parameter Modification

## Overview
Customization Volume Integration is a method that integrates a pre-computed "customization volume" into the volume rendering pipeline (typically ray casting) to apply position-dependent modifications to visualization parameters, such as gamma correction of intensity values [S1]. It differs from standard volume rendering by decoupling the data intensity modification from the transfer function, allowing spatially varying parameter adjustments (e.g., local gamma, contrast) without redefining the global transfer function [S1].

## How it works
**Inputs and Outputs:**
- **InputVolume**: The primary scalar volume data to be visualized.
- **CustomizationVolume**: A pre-computed volume storing position-dependent visualization parameters (e.g., gamma values).
- **TransferFunction**: Maps scalar intensity to color and opacity.
- **Output**: The final rendered image with position-dependent parameter modifications applied.

**Data Structures:**
- **InputVolume**: 3D grid of scalar values.
- **CustomizationVolume**: 3D grid of scalar values (parameters). The resolution can vary (e.g., $32^3$ to $128^3$) [S1].
- **Sampling Position**: 3D coordinates $(x, y, z)$ along the ray, typically in texture space $[0, 1]$ or voxel indices.

**Numbered Steps:**
1.  Pass both `InputVolume` and `CustomizationVolume` to the rendering shader (e.g., ray-casting kernel) [S1].
2.  For each sample point along the ray:
    a. Fetch the intensity value $I$ from `InputVolume` at the current sampling position using linear filtering [S1].
    b. Fetch the visualization parameter $P$ (e.g., gamma) from `CustomizationVolume` at the same sampling position using linear filtering [S1].
    c. Apply the parameter $P$ to the intensity $I$. Example: $I_{modified} = \text{pow}(I, P)$ [S1].
    d. Apply the `TransferFunction` to $I_{modified}$ to obtain color $C$ and opacity $\alpha$ [S1].
    e. Composite $C$ and $\alpha$ using front-to-back compositing [Parent].

**Formulas:**
- **Intensity Modification**:
  $$ I_{modified} = f(I, P) $$
  Where $I$ is the input intensity, $P$ is the parameter from the customization volume, and $f$ is the specific modification function (e.g., $I_{modified} = I^P$ for gamma correction) [S1].
- **Note on Intensity Range**: The example assumes input intensities are in the range $[0, 1]$ to justify the gamma correction [S1].

**Parameters:**
- **CustomizationVolume Resolution**: Typically between $32^3$ and $128^3$ [S1].
- **Filtering**: Linear filtering is used for fetching values from both volumes [S1].

**Edge Cases and Pitfalls:**
- **Performance Impact**: Additional lookups and computations (e.g., power function) reduce rendering performance. The impact depends on the number of samples and the complexity of the customization computation [S1].
- **Memory Bottleneck**: For large out-of-core volume datasets, the bottleneck is memory transfer to the GPU, making the performance impact of the customization step negligible [S1].
- **Resolution Trade-off**: Higher resolution in the customization volume increases computational complexity for interpolation, potentially diminishing interactivity when adjusting seed points. Mitigation: Use lower resolution for interactive customization and higher resolution for final rendering [S1].

**Pseudocode:**
```python
def customization_volume_raycast(InputVolume, CustomizationVolume, TransferFunction, Ray):
    """
    Renders a volume using ray casting with position-dependent customization.
    """
    accumulated_color = vec3(0.0, 0.0, 0.0)
    accumulated_opacity = 0.0
    threshold = 0.99
    
    # Ray initialization (from Parent)
    t = random.uniform(0.0, step_size)
    t_end = compute_ray_exit(Ray.origin, Ray.direction, VolumeBounds)
    
    while accumulated_opacity < threshold and t < t_end:
        # Compute current position in texture space [0,1]
        pos = [(Ray.origin[i] + t * Ray.direction[i]) for i in range(3)]
        
        # Step 2a: Fetch intensity from InputVolume
        intensity = trilinear_interpolate(InputVolume, pos, InputVolumeDims)
        
        # Step 2b: Fetch parameter from CustomizationVolume
        # Using linear filtering as per [S1]
        parameter = trilinear_interpolate(CustomizationVolume, pos, CustomizationVolumeDims)
        
        # Step 2c: Apply parameter to intensity
        # Example: Gamma correction
        modified_intensity = intensity ** parameter
        
        # Step 2d: Apply TransferFunction
        color, opacity = TransferFunction(modified_intensity)
        
        # Step 2e: Front-to-back compositing (from Parent)
        accumulated_color[0] += (1.0 - accumulated_opacity) * opacity * color[0]
        accumulated_color[1] += (1.0 - accumulated_opacity) * opacity * color[1]
        accumulated_color[2] += (1.0 - accumulated_opacity) * opacity * color[2]
        accumulated_opacity += (1.0 - accumulated_opacity) * opacity
        
        t += step_size
        
    # Gamma correction for display (from Parent)
    return pow_vec3(accumulated_color, 1.0/2.2)
```

## Subtopics

### Voronoi-based Customization Volume Generation
A method to pre-compute the customization volume by assigning visualization parameters from seed points to voxels based on distance (Euclidean or Manhattan) in a Voronoi diagram. This allows interactive adjustment of seed points to define regions of influence [S1].

### Interactive Customization
Adjusting seed points in real-time to modify the customization volume. Lower resolution is recommended for interactivity to maintain performance [S1].

## Operating characteristics
- **Time Complexity**: $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the number of samples per ray. The customization step adds a constant overhead per sample (lookup + function application) [S1].
- **Memory Complexity**: $O(V_{input} + V_{custom})$, where $V$ is the volume of the respective 3D grids [S1].
- **Performance**: The additional computational cost (power function, extra texture lookup) reduces overall rendering performance. However, for large out-of-core datasets, the GPU memory transfer bottleneck dominates, making the customization overhead negligible [S1].
- **Strengths**: Allows spatially varying visualization parameters without global transfer function changes. Simple integration into existing pipelines [S1].
- **Limitations**: Requires pre-computation of the customization volume. Performance impact depends on customization complexity and resolution [S1].

## Background
- **Origin**: Introduced in "Interactive Position-dependent Customization of Transfer Function Classification Parameters in Volume Rendering" (2015) [S1].
- **Development**: The method was developed to address the need for local, position-dependent adjustments to visualization parameters (e.g., gamma, contrast) in volume rendering, which are difficult to achieve with global transfer functions. It uses a pre-computed customization volume to store these parameters, which are then applied during the ray-casting loop [S1].
- **Usage**: Used in interactive volume visualization systems where users need to adjust visualization parameters in specific regions of the volume without affecting the entire dataset [S1].
