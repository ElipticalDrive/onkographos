# Customization Volume Integration

Also called: Customization Volume Integration in Ray Casting, Position-dependent Parameter Modification

## Overview
Customization Volume Integration is a method that integrates a pre-computed customization volume into the volume rendering pipeline to apply position-dependent modifications to visualization parameters, such as gamma correction of intensity values [S1]. It enables localized control over rendering appearance without altering the underlying scalar field [S1]. Unlike global transfer function adjustments, this approach decouples the modification logic from the core compositing loop, allowing spatially coherent parameter fields to drive the visualization [S1].

## How it works
**Inputs and Outputs:**
*   **InputVolume**: The primary scalar volume dataset to be visualized [S1].
*   **CustomizationVolume**: A pre-computed 3D grid containing position-dependent visualization parameters (e.g., gamma values) [S1].
*   **Output**: The final composited image with position-dependent parameter modifications applied [S1].

**Data Structures:**
*   **InputVolume**: A 3D grid of scalar values representing the target dataset [S1].
*   **CustomizationVolume**: A 3D grid of scalar values representing the parameter field, typically with a resolution between $32^3$ and $128^3$ [S1].
*   **Linear Filtering Helper**: A function that retrieves a value from a volume at a continuous 3D position using linear interpolation [S1].

**Numbered Steps:**
1.  **Pass Volumes**: The `CustomizationVolume` is passed to the rendering shader alongside the `InputVolume` [S1].
2.  **Ray Sampling**: For each sample position along the ray segment, fetch the intensity value from the `InputVolume` [S1].
3.  **Parameter Fetch**: Fetch the visualization parameter from the `CustomizationVolume` at the identical sampling position using linear filtering [S1].
4.  **Apply Modification**: Apply the fetched parameter to the intensity value [S1]. For gamma correction, compute $intensity_{modified} = \text{pow}(intensity, \gamma)$ [S1]. The intensity values are assumed to be normalized to the range $[0, 1]$ to justify this operation [S1].
5.  **Classification**: Apply the transfer function to the modified intensity to obtain the color vector and opacity scalar [S1].
6.  **Compositing**: Accumulate the color and opacity using the standard front-to-back volume rendering equation [S1].

**Pseudocode:**
```python
def ray_casting_with_customization(InputVolume, CustomizationVolume, ray_origin, ray_direction, ray_begin, ray_end, num_samples, transfer_function):
    """
    Performs volume rendering with position-dependent customization.
    Args:
        InputVolume: Primary scalar volume.
        CustomizationVolume: Pre-computed parameter volume.
        ray_origin: Camera origin point.
        ray_direction: Normalized viewing direction vector.
        ray_begin: Entry t parameter of the ray segment.
        ray_end: Exit t parameter of the ray segment.
        num_samples: Discretization count for the ray segment.
        transfer_function: Maps intensity to (color, opacity).
    Returns:
        Final composited color and accumulated opacity.
    """
    acc_color = vec3(0.0, 0.0, 0.0)
    acc_opacity = 0.0
    delta_t = (ray_end - ray_begin) / num_samples

    for i in range(num_samples):
        t = ray_begin + i * delta_t
        position = ray_origin + t * ray_direction

        # 1. Fetch intensity from input volume
        intensity = linear_filter_sample(InputVolume, position)

        # 2. Fetch customization parameter (e.g., gamma) from customization volume
        gamma = linear_filter_sample(CustomizationVolume, position)

        # 3. Apply modification (e.g., gamma correction)
        # Note: intensity is assumed to be in [0, 1]
        intensity = pow(intensity, gamma)

        # 4. Apply transfer function
        color, opacity = transfer_function(intensity)

        # 5. Front-to-back compositing
        alpha_term = opacity * (1.0 - acc_opacity)
        acc_color += alpha_term * color
        acc_opacity += alpha_term

        # Early ray termination optimization
        if acc_opacity >= 1.0:
            break

    return acc_color, acc_opacity
```

**Parameters:**
*   **CustomizationVolume Resolution**: Typically ranges from $32^3$ to $128^3$ [S1].
*   **Intensity Range**: Input intensity values must be normalized to $[0, 1]$ for operations like gamma correction [S1].

**Edge Cases and Pitfalls:**
*   **Performance Impact**: Additional lookups and computations (e.g., the power function) reduce overall rendering performance [S1]. The impact scales with the number of samples and the complexity of the customization computation [S1].
*   **Resolution Trade-off**: Changing the customization volume resolution between $32^3$ and $128^3$ has no significant impact on rendering performance, but higher resolution increases interpolation complexity, diminishing interactivity when adjusting seed points [S1]. Mitigation: Use lower resolution for interactive customization and higher resolution for final rendering [S1].
*   **Memory Bottleneck**: For large out-of-core volume datasets, memory transfer to the GPU is the primary bottleneck, making the performance impact of the customization step negligible [S1].

## Operating characteristics
*   **Time Complexity**: Adds $O(1)$ overhead per sample for the additional lookup and parameter application [S1]. The total rendering time increases proportionally to the number of samples and the computational cost of the customization function [S1].
*   **Memory Complexity**: Requires storing an additional volume of size $R^3$, where $R$ is the resolution of the customization volume [S1].
*   **Performance**: The performance impact is generally small, especially for large datasets where memory bandwidth limits throughput [S1]. Complex customization functions or high-resolution parameter fields can degrade interactivity [S1].
*   **Strengths**: Enables spatially varying, position-dependent control over visualization parameters without significantly altering the core ray-casting algorithm [S1]. Integrates easily into existing rendering pipelines [S1].
*   **Limitations**: Requires pre-computation of the customization volume (e.g., via Voronoi tessellation) [S1]. Performance degrades with high customization volume resolution or complex per-sample functions [S1].
*   **When to Use**: When spatially varying adjustments to visualization parameters (gamma, opacity scaling, color mapping) are required, and the parameter field can be pre-computed or interactively adjusted at lower resolution [S1].
*   **When Not to Use**: When real-time, per-sample dynamic parameter generation without pre-computation is required, or when the customization function is extremely complex and strict performance constraints exist [S1].

## Background
*   **Origin**: The method was introduced in the paper "Interactive Position-dependent Customization of Transfer Function Classification Parameters in Volume Rendering" [S1].
*   **History**: The technique was developed to address the need for localized control over volume rendering parameters, allowing users to adjust visualization aspects in specific regions without affecting the entire dataset [S1].
*   **Usage**: It is employed in interactive volume rendering systems where users require fine-tuned control over the appearance of specific structures or regions within a volume dataset [S1].
