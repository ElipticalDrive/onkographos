# Hardware-based Direct Volume Ray Casting

Also called: VIRIM DSP shading, VIRIM Ray-Casting Unit

## Overview
Hardware-based Direct Volume Ray Casting is a specialized architecture that offloads the computationally intensive tasks of ray-casting, shading, and compositing from the CPU to dedicated programmable Digital Signal Processors (DSPs) [S1]. It solves the bottleneck of real-time volume visualization by decoupling the high-speed data generation of the geometry unit from the slower, complex arithmetic of the shading unit [S1]. Unlike general-purpose GPU ray casting, this method uses a fixed-function geometry pipeline to generate sample/gradient data and a DSP array to perform the final image synthesis, offering maximum flexibility for shading models while maintaining hardware-accelerated throughput [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Sample density and gradient values (16-bit precision) generated by the preceding Geometry Unit [S1].
*   **Output:** Final pixel colors (scanlines) transferred to the host system [S1].

**Data Structures:**
*   **FIFO Buffer:** Asynchronous buffer connecting the Geometry Unit to the DSPs. It decouples the fast geometry unit from the slower DSPs [S1].
*   **Local DSP Memory:** Stores the calculated scanlines for a specific DSP [S1].
*   **Data Precision:** All calculations for density and gradient values are performed with 16-bit precision [S1].

**Numbered Steps:**
1.  **Data Transmission:** The Geometry Unit transmits sample density and gradient values to the Ray-Casting Units over a dedicated bus. The bus operates at a peak transfer rate of 240 MBytes/sec at 40 MHz [S1].
2.  **Buffering:** Each DSP receives its assigned stream of values from an asynchronous FIFO buffer [S1].
3.  **Shading Computation:** The DSPs compute the interaction of light and material for each volume element. This computation must complete within 15 clock cycles per volume element [S1]. The shading model is implemented in software on the DSPs, allowing any model where data remains in one sample plane [S1].
4.  **Scanline Storage:** One or more scanlines of the resulting projection are calculated per DSP and stored in the DSP's local memory [S1].
5.  **Result Collection:** A local master CPU on the board collects all scanlines from the DSP memories and transfers the final image results to the host system [S1]. No inter-DSP communication is required for the current visualization model [S1].

**Parameters:**
*   **Bus Speed:** 240 MBytes/sec (40 MHz) [S1].
*   **Computation Latency:** 15 clock cycles per volume element [S1].
*   **Data Precision:** 16 bits for density and gradient values [S1].
*   **Memory Access:** All memories and Look-Up Tables (LUTs) are accessible by the host system for real-time reloading [S1].

```python
# Hardware-based Direct Volume Ray Casting (VIRIM DSP Shading)
# Note: This pseudocode represents the logical flow of data and control.
# Actual implementation is hardware-bound (DSPs, FIFO, Bus).

def hardware_ray_casting_pipeline(geometry_unit_output, local_master_cpu):
    """
    Simulates the data flow of the VIRIM ray-casting unit.
    """
    # 1. Data Transmission from Geometry Unit
    # Bus transfer rate: 240 MB/s at 40 MHz
    # Data: 16-bit density and gradient values
    data_stream = geometry_unit_output.transmit_over_bus()
    
    # 2. Asynchronous Buffering
    # FIFO decouples fast geometry unit from slower DSPs
    fifo_buffer = FIFO()
    for data_packet in data_stream:
        fifo_buffer.enqueue(data_packet)
        
    # 3. DSP Processing
    # Each DSP handles a subset of the data
    dsp_results = []
    for dsp in available_dsp_units:
        # DSP reads from FIFO asynchronously
        volume_elements = fifo_buffer.dequeue_for(dsp)
        
        # Compute light/material interaction
        # Constraint: Must complete within 15 clock cycles per element
        # Shading model is programmable on DSP
        scanline = []
        for element in volume_elements:
            # element contains 16-bit density and gradient
            shaded_pixel = dsp.compute_shading(element)
            scanline.append(shaded_pixel)
            
        # Store result in local DSP memory
        dsp.local_memory.store(scanline)
        dsp_results.append(scanline)
        
    # 4. Result Collection
    # Local master CPU collects scanlines
    final_image = []
    for scanline in dsp_results:
        final_image.extend(scanline)
        
    # Transfer to host system
    local_master_cpu.transfer_to_host(final_image)
    
    return final_image
```

## Subtopics

### Ray Projection Tree
A hardware mechanism structured as a hierarchical binary tree of $n-1$ Voxel Combination Units (VCUs) that accepts $n$ voxels along a viewing ray at the leaves and produces the final pixel color at the root [S2]. Each VCU combines two input voxels into an output voxel value in 7 time units [S2]. The tree is fed in a pipelined fashion: after an initialization time of $7 \log n$ time units, the tree processes $\log n$ rays simultaneously, producing a new pixel color every 7 time units [S2]. Unlike the original beam projection mechanism, the RPT supports various projection schemes including first/last opaque, max/min voxel value, weighted summation, and compositing [S2].

## Operating characteristics
**Time and Memory Complexity:**
*   **Computation:** The DSP-based shading unit requires 15 clock cycles per volume element [S1].
*   **Pipeline Latency (RPT):** Initialization time is $7 \log n$ time units; steady-state throughput is one pixel every 7 time units [S2].

**Measured Performance:**
*   **Hardware:** VIRIM module consisting of four boards (36x39 cm² each), with four modules per crate [S1].
*   **Performance:** For a 256x256x128 dataset, the system achieves a frame rate of 2.5 Hz [S1].
*   **Throughput:** The bus transfers data at 240 MBytes/sec [S1]. The geometry unit is approximately 16 times faster than the DSP [S1].

**Strengths and Limitations:**
*   **Strengths:** Maximum flexibility for shading models via programmable DSPs; decoupled architecture allows independent optimization of geometry and shading; real-time reloadable LUTs and memories [S1].
*   **Limitations:** Requires specific hardware (VIRIM); inter-DSP communication is not supported in the current model, limiting certain global shading effects [S1].

**When to Use:**
*   When real-time volume rendering with complex, programmable shading models is required on dedicated hardware.
*   When the scene data can be efficiently generated by a preceding geometry unit.

**When Not to Use:**
*   When general-purpose flexibility or software-based shading is preferred.
*   When inter-DSP communication is necessary for the shading model.

## Background
The architecture was described in the mid-1990s as part of the VIRIM (Volume Rendering Image Machine) project [S1, S2]. It was developed to address the performance limitations of software-based volume rendering by leveraging custom hardware units, specifically programmable DSPs for the ray-casting phase [S1]. The Ray Projection Tree variant was introduced to optimize the compositing stage using a hierarchical hardware pipeline [S2].
