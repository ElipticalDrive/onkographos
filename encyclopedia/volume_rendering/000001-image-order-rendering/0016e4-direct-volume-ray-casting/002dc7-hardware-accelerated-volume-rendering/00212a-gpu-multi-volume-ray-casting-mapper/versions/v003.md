# GPU Multi-Volume Ray Casting Mapper

Also called: Base GPU Volume Ray Caster, GPU Multi Volume Ray Cast Mapper, Multi-Volume Composite Ray Casting, Multi-Volume Ray Casting in VTK, Multi-Volume Ray Casting with Coordinate Transformation, Multi-volume ray casting, vtkGPUMultiVolumeRayCastMapper

## Overview
The GPU Multi-Volume Ray Casting Mapper is a volume rendering technique that renders multiple 3D scalar fields simultaneously by compositing them along a single ray using GPU shaders [S1, S2, unofficial]. It extends the single-volume `vtkGPUVolumeRayCastMapper` to accept multiple `vtkImageData` datasets and `vtkVolumeProperty` objects, using coordinate transformation matrices to align samples from different volumes to a common ray space [S1, unofficial]. It differs from its siblings, such as [CUDA Volume Ray Casting](2048-cuda-volume-ray-casting.md) which may use general-purpose compute kernels, by relying on GLSL fragment shaders for faster execution and broader hardware support [S1, unofficial]. It builds on [Hardware and Platform Specific](2517-hardware-and-platform-specific.md) by implementing the shared principles of texture upload, thread-per-pixel mapping, and front-to-back compositing, but adds the complexity of managing multiple coordinate spaces and transformation matrices [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** One or more `vtkImageData` datasets (scalar fields) and corresponding `vtkVolumeProperty` objects (transfer functions). The primary input is at port 0; additional inputs are at ports 1 to $N$. A mask input (`vtkImageData`) is optional for region confinement [S1, S2, unofficial].
*   **Outputs:** A final color and opacity value written to the frame buffer for each pixel [S1, S2, unofficial].

**Data Structures:**
*   **Textures:** Each volume dataset is uploaded as a 3D texture (`sampler3D`). Transfer functions are uploaded as 1D textures (`sampler1D`) for opacity and color [S1, S2, unofficial].
*   **Transformations:** An array `P1toPN` of $N-1$ matrices stores the transformation from the first volume's texture coordinates to the $N$-th volume's texture coordinates [S1, unofficial].
*   **Bounds:** Arrays `lowBounds` and `highBounds` store the bounding box information for each volume, modified by cropping [S1, S2, unofficial].
*   **Clipping/Cropping:** `ClippedCroppingRegionPlanes` stores up to 6 clipping/cropping planes (min/max for x, y, z) in world coordinates, converted to texture coordinates for the shader [S1, S2, unofficial].
*   **State:** `LastInput` and `LastInput2` track input modification times to trigger updates [S2, unofficial]. `TransformedInput` and `TransformedInput2` hold shallow copies of inputs with adjusted extents [S2, unofficial].

**Parameters:**
*   `MAX_NUMBER_OF_ADDITIONAL_VOLUMES`: 3 on Apple platforms, 4 otherwise [S1, S2, unofficial].
*   `ImageSampleDistance`: Base sample distance in image space. Default 1.0. Clamped [0.1, 100.0] [S2, unofficial].
*   `MinimumImageSampleDistance`: Lower bound for adaptive sampling. Default 1.0 [S2, unofficial].
*   `MaximumImageSampleDistance`: Upper bound for adaptive sampling. Default 10.0 [S2, unofficial].
*   `AutoAdjustSampleDistances`: Boolean (0/1). Enables automatic adjustment of `ImageSampleDistance` based on render time. Default 1 (true) [S1, S2, unofficial].
*   `MaxMemoryInBytes`: Maximum GPU memory for volume data. Probed from GPU info; defaults to 128 MB if unavailable [S1, S2, unofficial].
*   `MaxMemoryFraction`: Fraction of `MaxMemoryInBytes` used. Default 0.75. Clamped [0.1, 1.0] [S1, S2, unofficial].
*   `ReportProgress`: Boolean. If true, uses `glFinish()` to report progress. Default true [S1, S2, unofficial].
*   `MaskBlendFactor`: Blending weight for mask color transfer function. Default 1.0. Clamped [0.0, 1.0] [S1, S2, unofficial].
*   `MaskType`: Enum for mask type (`BinaryMaskType` or `LabelMapMaskType`). Default `LabelMapMaskType` [S1, S2, unofficial].

**Steps:**

1.  **Initialization:** Probe GPU memory to set `MaxMemoryInBytes`. If dedicated video memory is 0, use dedicated system memory. If both are 0, set to 128 MB. Ignore shared system memory [S2, unofficial].
2.  **Input Validation:** Check for null renderer or volume. Check that inputs are valid `vtkImageData`. If `Cropping` is enabled, verify that cropping planes define a valid volume (min < max for all axes); if not, fail silently (`goodSoFar = 0`) [S1, S2, unofficial].
3.  **Transform Setup:** For each additional volume $N$, compute the transformation matrix $P1toPN$ combining the world-to-texture-$N$ transform, the inverse world-to-texture-1 transform, and any user-defined transform [S1, unofficial].
4.  **Extent Adjustment (Workaround):** If the input extents do not start at zero, adjust the origin and shift extents to start from zero for GPU compatibility. Specifically, for each axis $cc$: `origin += extents[2*cc] * spacing`, `extents[2*cc] -= extents[2*cc]`, `extents[2*cc+1] -= extents[2*cc]` [S2, unofficial].
5.  **Clipping/Cropping Conversion:** Convert clipping and cropping planes from world coordinates to texture coordinates just before rendering and pass them to shaders via uniform variables [S1, S2, unofficial].
6.  **Ray Traversal (Shader):**
    *   Initialize `pos` (entry position for volume 0), `rayDir` (incremental vector in texture space), `tMax` (max ray length), and `destColor` (initial color) [S1, unofficial].
    *   Set `remainOpacity = 1.0 - destColor.a` [S1, unofficial].
    *   Loop while `inside` is true: `inside` is true if `t < tMax`, `remainOpacity >= 0.0039` (1/255), and `pos` is within `lowBounds[0]` and `highBounds[0]` [S1, unofficial].
    *   For each additional volume $iii$ from 0 to $N-2$, compute transformed position: `posX[iii] = vec3(P1toPN[iii] * vec4(pos, 1))` [S1, unofficial].
    *   For volume 0: if `pos` is within bounds and not clipped, sample `value[0] = texture3D(dataSetTexture[0], pos)`, compute `scalar[0] = scalarFromValue(value[0])`, sample `opacity[0] = texture1D(opacityTexture[0], scalar[0])` [S1, unofficial].
    *   For volumes 1 to $N-1$: if `posX[xx-1]` is within bounds and not clipped, sample `value[xx] = texture3D(dataSetTexture[xx], posX[xx-1])`, compute `scalar[xx] = scalarFromValue(value[xx])`, sample `opacity[xx] = texture1D(opacityTexture[xx], scalar[xx])` [S1, unofficial].
    *   Composite: if `opacity[vol].a > 0.0`, compute `color[vol] = shade(vol, value[vol]) * opacity[vol].a`, update `destColor = destColor + color[vol] * remainOpacity`, and update `remainOpacity = remainOpacity * (1.0 - opacity[vol].a)` [S1, unofficial].
    *   Advance ray: `pos = pos + rayDir`, `t += 1.0` [S1, unofficial].
7.  **Final Output:** Write `gl_FragColor = destColor` and `gl_FragColor.a = 1.0 - remainOpacity` [S1, unofficial].

**Pseudocode:**

```python
# Shader: vtkGPUVolumeRayCastMapper_CompositeFS

# Uniforms
uniform sampler3D dataSetTexture[MAX_NUMBER_OF_VOLUMES];
uniform sampler1D opacityTexture[MAX_NUMBER_OF_VOLUMES];
uniform mat4 P1toPN[MAX_NUMBER_OF_VOLUMES - 1];
uniform vec3 lowBounds[MAX_NUMBER_OF_VOLUMES];
uniform vec3 highBounds[MAX_NUMBER_OF_VOLUMES];
uniform int Number_Of_Volumes;
uniform vec3 ClippingplanesNormal[MAX_NUMBER_OF_VOLUMES];
uniform vec3 ClippingplanesOrigins[MAX_NUMBER_OF_VOLUMES];
uniform int clipped[MAX_NUMBER_OF_VOLUMES];

# Inputs
uniform vec3 pos; # Initial position for volume 0
uniform vec3 rayDir; # Ray direction in texture space
uniform float tMax; # Max ray length

# Local variables
vec3 posX[MAX_NUMBER_OF_VOLUMES - 1];
float remainOpacity = 1.0;
vec3 destColor = vec3(0.0, 0.0, 0.0);

# Compute initial transformed positions for additional volumes
for (int iii = 0; iii < Number_Of_Volumes - 1; iii++) {
    posX[iii] = (P1toPN[iii] * vec4(pos, 1.0)).xyz;
}

# Ray traversal loop
float t = 0.0;
while (t < tMax && remainOpacity >= 0.0039) {
    bool inside = true;
    
    # Check if ray is inside volume 0 bounds
    if (pos.x < lowBounds[0].x || pos.x > highBounds[0].x ||
        pos.y < lowBounds[0].y || pos.y > highBounds[0].y ||
        pos.z < lowBounds[0].z || pos.z > highBounds[0].z) {
        inside = false;
    }
    
    if (inside) {
        # Sample volume 0
        float value0 = texture3D(dataSetTexture[0], pos).r;
        float scalar0 = scalarFromValue(value0); # Implementation depends on data type
        float opacity0 = texture1D(opacityTexture[0], scalar0).a;
        
        if (opacity0 > 0.0) {
            vec3 color0 = shade(0, value0) * opacity0;
            destColor += color0 * remainOpacity;
            remainOpacity *= (1.0 - opacity0);
        }
        
        # Sample additional volumes
        for (int xx = 1; xx < Number_Of_Volumes; xx++) {
            bool insideXX = true;
            # Check bounds for volume xx using transformed position
            if (posX[xx-1].x < lowBounds[xx].x || posX[xx-1].x > highBounds[xx].x ||
                posX[xx-1].y < lowBounds[xx].y || posX[xx-1].y > highBounds[xx].y ||
                posX[xx-1].z < lowBounds[xx].z || posX[xx-1].z > highBounds[xx].z) {
                insideXX = false;
            }
            
            # Check clipping for volume xx
            if (clipped[xx] == 1 && insideXX) {
                # Simple clipping check: ensure position is greater than clipMin
                # Implementation detail: clipMin[i] computed from ClippingplanesNormal/Origins
                # For brevity, assuming a helper function isClipped(pos, normal, origin)
                if (isClipped(posX[xx-1], ClippingplanesNormal[xx], ClippingplanesOrigins[xx])) {
                    insideXX = false;
                }
            }
            
            if (insideXX) {
                float valueXX = texture3D(dataSetTexture[xx], posX[xx-1]).r;
                float scalarXX = scalarFromValue(valueXX);
                float opacityXX = texture1D(opacityTexture[xx], scalarXX).a;
                
                if (opacityXX > 0.0) {
                    vec3 colorXX = shade(xx, valueXX) * opacityXX;
                    destColor += colorXX * remainOpacity;
                    remainOpacity *= (1.0 - opacityXX);
                }
            }
        }
    }
    
    # Advance ray
    pos = pos + rayDir;
    for (int iii = 0; iii < Number_Of_Volumes - 1; iii++) {
        posX[iii] = posX[iii] + rayDir; # Note: P1toPN is applied once at start, 
                                        # but rayDir must be transformed for subsequent volumes?
                                        # Source says: "pos and posX[] is updated according to the ray direction (rayDir)"
                                        # This implies posX update might need transformation of rayDir or just adding rayDir if space is aligned.
                                        # Source code comment: "pos and posX[] is updated according to the ray direction (rayDir)"
                                        # Given P1toPN is a matrix, posX[iii] = P1toPN[iii] * pos.
                                        # So posX[iii]_new = P1toPN[iii] * (pos + rayDir) = posX[iii] + P1toPN[iii] * rayDir.
                                        # The source notes say "posX[] is updated according to the ray direction (rayDir)".
                                        # This is ambiguous. However, mathematically, if pos updates by rayDir,
                                        # posX must update by P1toPN * rayDir.
                                        # Let's assume the source implies the logical update step.
                                        # To be safe and implementable, we transform rayDir.
    }
    # Corrected update for posX based on linear transformation
    for (int iii = 0; iii < Number_Of_Volumes - 1; iii++) {
        vec3 transformedRayDir = (P1toPN[iii] * vec4(rayDir, 0.0)).xyz;
        posX[iii] = posX[iii] + transformedRayDir;
    }
    t += 1.0;
}

# Final output
gl_FragColor = vec4(destColor, 1.0 - remainOpacity);
```

*Note: The pseudocode above simplifies `shade()` and `scalarFromValue()` which are implementation-specific. The update of `posX` in the loop is corrected to apply the transformation to the ray direction increment, as `posX` is a linear transformation of `pos`.*

## Subtopics

### [OpenGL GPU Multi Volume Ray Cast Mapper](2919-opengl-gpu-multi-volume-ray-cast-mapper.md)
The OpenGL GPU Multi Volume Ray Cast Mapper is an OpenGL-specific subclass of the GPU Multi-Volume Ray Casting Mapper that handles hardware extension checks, OpenGL object lifecycle management, and clipping/cropping plane setup for GPU-accelerated volume rendering. It serves as the concrete implementation responsible for drawing the volume ray cast image to the screen by managing the fragment shader programs, framebuffer objects, and texture uploads required for rendering multiple volumes simultaneously. It builds on [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) by providing the specific OpenGL API bindings and state management necessary for hardware-accelerated ray casting.

### [GPU Volume Ray Casting (VTK Composite Blend)](6912-gpu-volume-ray-casting-vtk-composite-blend.md)
A hardware-accelerated volume rendering technique using VTK's `vtkGPUVolumeRayCastMapper` with composite blending mode to render 3D medical datasets (CT/MRI) by accumulating color and opacity along rays. It differs from its sibling [OpenGL GPU Multi Volume Ray Cast Mapper](2919-opengl-gpu-multi-volume-ray-cast-mapper.md) by explicitly enforcing the composite blending logic within the VTK rendering pipeline, focusing on the specific configuration of transfer functions and lighting models required for medical visualization.

### Mask Type Configuration
Methods to set the mask type for volume rendering, either Binary or LabelMap [S2, unofficial]. To set binary mask: assign `this->MaskType = vtkGPUMultiVolumeRayCastMapper::BinaryMaskType`. To set label map mask: assign `this->MaskType = vtkGPUMultiVolumeRayCastMapper::LabelMapMaskType` [S2, unofficial].

### Label Map Masking for Volume Rendering
A masking technique that confines volume rendering to specific regions using either a binary mask or a label map. Supports blending between standard and mask-specific color transfer functions [S1, unofficial]. Binary mask processing assumes UCHAR datatype with values 255 (inside) and 0 (outside); rendering is confined strictly to regions where mask value is 255 [S1, unofficial]. Label map processing assumes UCHAR datatype with exactly 3 labels (0, 1, 2). Label 0 uses component 0's CT. Label 1 uses component 1's CT blended with component 0's CT using `MaskBlendFactor`. Label 2 uses component 2's CT blended with component 0's CT using `MaskBlendFactor` [S1, unofficial]. Parameters include `MaskInput` (vtkImageData*) and `MaskBlendFactor` (float, clamped [0.0, 1.0], default 1.0) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray and the number of volumes. Adaptive sampling (`AutoAdjustSampleDistances`) can reduce the number of samples based on render time constraints [S1, S2, unofficial].
*   **Memory Complexity:** Proportional to the total size of the volume textures and transfer functions uploaded to GPU memory. Limited by `MaxMemoryInBytes` [S1, S2, unofficial].
*   **Measured Performance:** Performance depends on GPU hardware and resolution. Adaptive sampling helps maintain frame rates for large datasets [S2, unofficial].
*   **Scaling:** Scales with the number of pixels (threads) and volumes. Limited by `MAX_NUMBER_OF_ADDITIONAL_VOLUMES` (3-5) [S1, S2, unofficial].
*   **Strengths:** Hardware acceleration via GLSL shaders, support for multiple volumes, adaptive sampling, and masking [S1, S2, unofficial].
*   **Limitations:** Limited number of additional volumes, potential slowdown from `ReportProgress` (glFinish) on small datasets, and non-zero extent workaround requirements [S1, S2, unofficial].
*   **When to use:** When rendering multiple aligned or transformable volume datasets on the GPU with VTK [S1, S2, unofficial].
*   **When not to use:** When more than `MAX_NUMBER_OF_ADDITIONAL_VOLUMES` volumes are needed, or when non-GPU rendering is required [S1, S2, unofficial].

## Background
The GPU Multi-Volume Ray Casting Mapper was developed as an extension to the Visualization Toolkit (VTK) to support multi-volume rendering on the GPU. It was modified by Carlos Falcón and Karl Krissian from CTIM [S1, unofficial]. The project uses GLSL shaders instead of OpenCL for general GPU programming because shaders are faster and supported by more devices [S1, unofficial]. It builds on the single-volume `vtkGPUVolumeRayCastMapper` by adding support for multiple inputs, coordinate transformations, and compositing [S1, S2, unofficial].
