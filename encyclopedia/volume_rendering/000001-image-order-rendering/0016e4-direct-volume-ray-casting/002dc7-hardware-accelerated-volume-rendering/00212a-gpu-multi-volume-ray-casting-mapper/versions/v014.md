# GPU Multi-Volume Ray Casting Mapper

Also called: vtkGPUMultiVolumeRayCastMapper, GPU Multi Volume Ray Cast Mapper, Multi-volume ray casting

## Overview
The GPU Multi-Volume Ray Casting Mapper is a hardware-accelerated direct volume rendering technique that renders multiple 3D scalar fields simultaneously along a single ray [S1, S2, unofficial]. It extends the single-volume [Hardware-Accelerated Volume Rendering](5616-hardware-accelerated-volume-rendering.md) pipeline by introducing coordinate transformation matrices to align samples from different volumes into a common ray space [S1, unofficial]. Unlike its sibling [Hardware-Accelerated Volume Rendering via 3D Texturing](2799-hardware-accelerated-volume-rendering-via-3d-texturing.md), which handles a single dataset, this method supports composite blending of up to five volumes (one primary, four additional) using GLSL fragment shaders [S1, S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** Two or more `vtkImageData` datasets (scalar volumes) and corresponding `vtkVolumeProperty` objects (transfer functions). A mask input (`vtkImageData`) is optional.
*   **Outputs:** A 2D color buffer with accumulated color and opacity per pixel.

**Data Structures**
The mapper maintains the following key state variables and shader uniforms:
*   `TransformedInput`, `TransformedInput2`: Pointers to `vtkImageData` holding the primary and secondary volume data, adjusted for GPU constraints (see Pitfalls).
*   `Property[N]`: Array of `vtkVolumeProperty*` for additional volumes.
*   `P1toPN[N]`: Array of `mat4` transformation matrices. $P1toPN[i]$ maps texture coordinates from the first volume to the $(i+1)$-th volume. Computed as $T_{world \to tex_N} \cdot T_{world \to tex_1}^{-1} \cdot T_{user}$ [S1, unofficial].
*   `lowBounds[N]`, `highBounds[N]`: `vec3` arrays storing the bounding box limits for each volume in texture space.
*   `ClippedCroppingRegionPlanes[6]`: Array of doubles defining the active cropping region (X min/max, Y min/max, Z min/max) [S1, S2, unofficial].
*   Shader Uniforms:
    *   `sampler3D dataSetTexture[MAX_NUMBER_OF_VOLUMES]`
    *   `sampler1D opacityTexture[MAX_NUMBER_OF_VOLUMES]`
    *   `mat4 P1toPN[MAX_NUMBER_OF_VOLUMES-1]`
    *   `vec3 lowBounds[MAX_NUMBER_OF_VOLUMES]`, `vec3 highBounds[MAX_NUMBER_OF_VOLUMES]`
    *   `int Number_Of_Volumes`
    *   `vec3 ClippingplanesNormal[MAX_NUMBER_OF_VOLUMES]`, `vec3 ClippingplanesOrigins[MAX_NUMBER_OF_VOLUMES]`
    *   `int clipped[MAX_NUMBER_OF_VOLUMES]` [S1, unofficial]

**Parameters**
*   `MAX_NUMBER_OF_VOLUMES`: 4 on Apple platforms, 5 otherwise [S1, unofficial].
*   `ImageSampleDistance`: Base sample distance in image space. Default 1.0. Clamped to [0.1, 100.0] [S2, unofficial].
*   `MinimumImageSampleDistance`: Lower bound for adaptive sampling. Default 1.0 [S2, unofficial].
*   `MaximumImageSampleDistance`: Upper bound for adaptive sampling. Default 10.0 [S2, unofficial].
*   `AutoAdjustSampleDistances`: Boolean (0/1). Enables dynamic adjustment of `ImageSampleDistance` based on render time [S2, unofficial].
*   `MaxMemoryInBytes`: Maximum GPU memory for textures. Defaults to dedicated video memory, or 128 MB if unavailable [S2, unofficial].
*   `MaxMemoryFraction`: Fraction of `MaxMemoryInBytes` used. Default 0.75. Range [0.1, 1.0] [S2, unofficial].
*   `MaskBlendFactor`: Blending weight for label map masks. Default 1.0. Range [0.0, 1.0] [S2, unofficial].
*   `ReportProgress`: Boolean. If true, calls `glFinish()` to report progress. Should be false for small datasets to avoid stalls [S2, unofficial].

**Algorithm Steps**

1.  **Initialization and Validation**:
    *   Probe GPU memory. If dedicated/shared memory is 0, set `MaxMemoryInBytes` to 128 MB [S2, unofficial].
    *   Validate inputs: Check for null renderer, volume, or inputs. Ensure color channels are 3 (optional check in some versions) [S2, unofficial].
    *   Validate cropping: If `Cropping` is true, check if `Planes[0] >= Planes[1]` or `Planes[2] >= Planes[3]` or `Planes[4] >= Planes[5]`. If so, set `goodSoFar = 0` and fail silently [S2, unofficial].
    *   Compute `ClippedCroppingRegionPlanes` by intersecting user-defined cropping planes with volume bounds [S1, unofficial].

2.  **Data Preparation**:
    *   Check if `LastInput` or `LastInput2` differ from current inputs or if modification times have changed. If so, update `TransformedInput` and `TransformedInput2` [S2, unofficial].
    *   **Extent Adjustment Workaround**: GPU ray casting requires extents starting from zero. For each input:
        *   Get `extents`, `origin`, `spacing`.
        *   Adjust origin: `new_origin[cc] = origin[cc] + extents[2*cc] * spacing[cc]` [S2, unofficial].
        *   Shift extents: `extents[2*cc] -= extents[2*cc]`, `extents[2*cc+1] -= extents[2*cc]` [S2, unofficial].
        *   Update input data with new origin and extent [S2, unofficial].

3.  **Ray Generation**:
    *   Render a proxy geometry (bounding box) to activate the fragment shader [S1, unofficial].
    *   Compute ray origin, direction, and entry/exit points ($t_{min}, t_{max}$) for the combined volume bounds [S1, S4].

4.  **Ray Marching Loop (Shader `trace()`)**:
    *   Initialize `pos` (position in volume 1 texture space), `posX[]` (positions in additional volumes), `t` (current distance), `destColor` (accumulated color), and `remainOpacity` ($1.0 - destColor.a$) [S1, unofficial].
    *   Loop while `inside` is true:
        *   `inside` is true if $t < t_{max}$, `remainOpacity` $\ge 0.0039$ (1/255), and `pos` is within `lowBounds[0]` and `highBounds[0]` [S1, unofficial].
        *   **Transform Positions**: For each additional volume $iii$ (from 0 to $Number\_Of\_Volumes-2$), compute `posX[iii] = P1toPN[iii] * vec4(pos, 1.0)` [S1, unofficial].
        *   **Sample Volume 0**:
            *   If `pos` is within bounds and not clipped:
                *   `value[0] = texture3D(dataSetTexture[0], pos)`
                *   `scalar[0] = scalarFromValue(value[0])`
                *   `opacity[0] = texture1D(opacityTexture[0], scalar[0])`
                *   `color[0] = shade(0, value[0]) * opacity[0].a`
                *   `destColor += color[0] * remainOpacity`
                *   `remainOpacity *= (1.0 - opacity[0].a)`
        *   **Sample Additional Volumes ($1$ to $N-1$)**:
            *   For each volume $xx$ (1 to $Number\_Of\_Volumes-1$):
                *   If `posX[xx-1]` is within bounds and not clipped:
                    *   `value[xx] = texture3D(dataSetTexture[xx], posX[xx-1])`
                    *   `scalar[xx] = scalarFromValue(value[xx])`
                    *   `opacity[xx] = texture1D(opacityTexture[xx], scalar[xx])`
                    *   `color[xx] = shade(xx, value[xx]) * opacity[xx].a`
                    *   `destColor += color[xx] * remainOpacity`
                    *   `remainOpacity *= (1.0 - opacity[xx].a)`
        *   **Advance Ray**: `pos += rayDir`, `t += 1.0` [S1, unofficial].

5.  **Final Output**:
    *   Set `gl_FragColor = destColor` and `gl_FragColor.a = 1.0 - remainOpacity` [S1, unofficial].

**Pseudocode**

```python
def render_multi_volume(renderer, volume_list, properties, mask_input=None):
    """
    Simulates the GPU Multi-Volume Ray Casting Mapper pipeline.
    volume_list: List of vtkImageData (at least 2).
    properties: List of vtkVolumeProperty.
    """
    # 1. Initialization
    max_volumes = 5 if not is_apple else 4
    if len(volume_list) > max_volumes:
        raise ValueError("Exceeds MAX_NUMBER_OF_VOLUMES")

    # 2. Data Preparation (Extent Adjustment)
    transformed_inputs = []
    for vol in volume_list:
        extents = vol.get_extents()
        origin = vol.get_origin()
        spacing = vol.get_spacing()
        
        # Adjust origin to start from 0
        new_origin = [origin[i] + extents[2*i] * spacing[i] for i in range(3)]
        
        # Shift extents to start from 0
        new_extents = [extents[2*i+1] - extents[2*i] for i in range(3)]
        
        transformed_vol = vol.clone()
        transformed_vol.set_origin(new_origin)
        transformed_vol.set_extents([0, new_extents[0], 0, new_extents[1], 0, new_extents[2]])
        transformed_inputs.append(transformed_vol)

    # 3. Compute Transforms
    # P1toPN[i] maps texture coords from volume 0 to volume i+1
    p1to_pn = []
    for i in range(1, len(transformed_inputs)):
        # T_world_to_tex_N * inv(T_world_to_tex_1) * T_user
        # Assuming identity user transform for simplicity
        t_world_to_tex_0 = compute_world_to_texture_transform(transformed_inputs[0])
        t_world_to_tex_n = compute_world_to_texture_transform(transformed_inputs[i])
        p1to_pn.append(t_world_to_tex_n * t_world_to_tex_0.inverse())

    # 4. Ray Generation (Proxy Geometry)
    # Render bounding box to generate fragments
    # For each fragment (pixel), compute ray origin and direction
    # Compute t_max based on combined bounds
    
    # 5. Shader Execution (Simplified CPU Simulation for Logic)
    # In reality, this runs in GLSL fragment shader
    
    for pixel in pixels:
        ray_origin = compute_ray_origin(pixel)
        ray_direction = compute_ray_direction(pixel)
        
        # Transform ray to texture space of volume 0
        # pos is in texture coordinates of volume 0
        pos = ray_origin # Simplified; needs scaling by spacing/origin
        
        # posX[i] is in texture coordinates of volume i+1
        pos_x = [p1to_pn[i] * vec4(pos, 1.0) for i in range(len(p1to_pn))]
        
        t = 0.0
        t_max = compute_max_t(ray_origin, ray_direction, combined_bounds)
        dest_color = vec4(0.0, 0.0, 0.0, 0.0)
        remain_opacity = 1.0
        
        step_size = compute_step_size(pixel, properties)
        
        while t < t_max and remain_opacity > 0.0039:
            inside = True
            
            # Check bounds for volume 0
            if not is_inside(pos, transformed_inputs[0].bounds):
                inside = False
            
            # Check bounds for additional volumes
            for i, p in enumerate(pos_x):
                if not is_inside(p, transformed_inputs[i+1].bounds):
                    inside = False
            
            if inside:
                # Sample Volume 0
                val_0 = sample_texture(transformed_inputs[0], pos)
                op_0 = sample_transfer_function(properties[0], val_0)
                col_0 = shade(properties[0], val_0) * op_0.a
                
                dest_color += col_0 * remain_opacity
                remain_opacity *= (1.0 - op_0.a)
                
                # Sample Additional Volumes
                for i in range(len(pos_x)):
                    val_i = sample_texture(transformed_inputs[i+1], pos_x[i])
                    op_i = sample_transfer_function(properties[i+1], val_i)
                    col_i = shade(properties[i+1], val_i) * op_i.a
                    
                    dest_color += col_i * remain_opacity
                    remain_opacity *= (1.0 - op_i.a)
            
            # Advance
            pos += ray_direction * step_size
            for i in range(len(pos_x)):
                pos_x[i] += ray_direction * step_size # Note: P1toPN is applied once at start in shader, 
                                                      # but rayDir must also be transformed or pos_x updated via transform
            # Correction: In shader, posX is recomputed or rayDir is transformed.
            # Source says: "pos and posX[] is updated according to the ray direction (rayDir)"
            # This implies rayDir is pre-transformed or posX is recomputed.
            # Source code comment: "posX[iii] = vec3(P1toPN[iii]*vec4(pos,1))" is done inside loop?
            # Actually, source says: "calculate initial position... posX[]... while loop: update pos and posX[] using rayDir"
            # This suggests rayDir is transformed once or pos is updated and posX recomputed.
            # Given P1toPN is constant, recomputing posX from updated pos is safer.
            
            t += step_size

        gl_frag_color = dest_color
        gl_frag_color.a = 1.0 - remain_opacity
```

## Subtopics

### [OpenGL GPU Multi Volume Ray Cast Mapper](2919-opengl-gpu-multi-volume-ray-cast-mapper.md)
An OpenGL-specific subclass that handles hardware extension checks, OpenGL object lifecycle management, and clipping/cropping plane setup for GPU-accelerated volume rendering [2919-opengl-gpu-multi-volume-ray-cast-mapper.md]. It serves as the concrete implementation responsible for drawing the volume ray cast image to the screen by managing fragment shader programs, framebuffer objects, and texture uploads required for rendering multiple volumes simultaneously. It builds on [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) by providing the specific OpenGL API bindings and state management necessary for hardware-accelerated ray casting.

### [GPU Volume Ray Casting (VTK Composite Blend)](6912-gpu-volume-ray-casting-vtk-composite-blend.md)
A hardware-accelerated direct volume rendering technique implemented in VTK via `vtkGPUVolumeRayCastMapper` that performs ray casting on the GPU to visualize 3D scalar fields. It transforms raw volumetric data into a 3D environment by accumulating color and opacity along rays using composite blending. It sets itself apart from its siblings by explicitly utilizing the **Composite** blend mode for standard alpha blending during the ray casting process, distinguishing it from the OpenGL-specific multi-volume mapper [2919-opengl-gpu-multi-volume-ray-cast-mapper.md] and the Slicer-specific mapper [7450-vtkslicergpuraycastvolumemapper.md].

### [vtkSlicerGPURayCastVolumeMapper](7450-vtkslicergpuraycastvolumemapper.md)
Renders a volume using ray casting on a 3D texture. It builds on [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) to provide a specific implementation for the 3D Slicer environment, supporting adaptive sampling, masking, and AMR modes via the parent's pipeline hooks. It is distinguished from its siblings by its specific integration with CTK transfer functions and its handling of specific OpenGL uniform layouts for ray casting parameters.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M \cdot R)$, where $N$ is the number of volumes, $M$ is the number of samples per ray, and $R$ is the number of rays (pixels). Adaptive sampling reduces $M$ dynamically [S2, unofficial].
*   **Memory Complexity:** $O(\sum V_i)$, where $V_i$ is the size of each volume texture in GPU memory. Limited by `MaxMemoryInBytes` [S2, unofficial].
*   **Performance:** Hardware-accelerated via fragment shaders. Performance is limited by memory bandwidth due to 3D texture sampling [S1, unofficial].
*   **Strengths:** Supports simultaneous rendering of multiple volumes with different transfer functions; efficient early ray termination; adaptive sampling for interactive performance [S1, S2, unofficial].
*   **Limitations:** Limited to a small number of additional volumes (max 4 extra); requires GPU with OpenGL support; non-zero volume extents require software-side adjustment [S2, unofficial].
*   **When to Use:** Interactive visualization of multi-modal medical data (e.g., CT and MRI fused) or multi-material scientific data [S1, unofficial].
*   **When Not to Use:** When rendering more than 5 volumes simultaneously; when hardware lacks required OpenGL extensions; when input data has non-standard component counts (e.g., >3 color channels) [S3, unofficial].

## Background
The GPU Multi-Volume Ray Casting Mapper was developed as an extension to the Visualization Toolkit (VTK) to support multi-volume rendering on GPUs. It was modified by Carlos Falcón and Karl Krissian from the original single-volume `vtkGPUVolumeRayCastMapper` [S1, unofficial]. The implementation uses GLSL shaders instead of OpenCL for broader device support and higher performance [S1, unofficial]. It is part of the VTK volume rendering pipeline, specifically designed for hardware-accelerated direct volume rendering [S2, unofficial].
