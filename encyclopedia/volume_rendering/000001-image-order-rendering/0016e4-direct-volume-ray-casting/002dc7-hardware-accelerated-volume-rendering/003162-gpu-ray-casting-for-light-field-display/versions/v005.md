# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
This method implements GPU-accelerated direct volume rendering specifically for interactive light field displays using Multi-Camera Optical Projection (MCOP) [S1]. It solves the problem of incorrect per-pixel ray parameter values that arise from standard vertex attribute interpolation in light field projections, where long straight lines appear curved and linear interpolation fails to produce correct ray origins and directions [S1]. It sets itself apart from standard ray casting by computing rays from projector positions through screen pixels into the volume using a proxy geometry and MCOP projection, and by employing depth-dependent mipmap level selection to match sampling rates to the display's spatial resolution [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   Volume data stored in a single 4-component texture: RGB channels contain unscaled precomputed gradients, Alpha channel contains voxel values [S1].
    *   A 1D RGBA lookup table for transfer functions [S1].
    *   Uniform parameters: Projector position $E_w$ (float3), Virtual observer distance $V_d$ (float), Virtual observer height $V_h$ (float), $\log_2$ of voxel size $\log_2 V$ (float), Step size $DL$ (float), Screen pixel size $S_0$ (float), Angular spread factor $\tan \Phi$ (float) [S1].
    *   Model-view inverse matrix $M_{vw}^{-1}$ and Model-view matrix $M_{vw}$ [S1].
*   **Outputs:**
    *   Fragment color and opacity (float4) [S1].

**Data Structures:**
*   `ray_t`: Struct containing `org` (float3), `dir` (float3), `len` (float) [S1].
*   `fragment_out`: Struct containing `color` (float4) [S1].

**Steps:**

1.  **Proxy Geometry Setup:** Use a coarsely tessellated proxy geometry (8x8 quads) of a slightly enlarged bounding volume [S1]. Stream vertices through a vertex shader that performs MCOP projection [S1].
2.  **Ray Origin and Direction Computation:** In the fragment shader, receive the unnormalized projected position $S$ (screen pixel position in display reference frame) [S1]. Compute the ray direction $d$ using MCOP projection parameterized by emitter $E$ and virtual viewer parameters $V$ [S1]:
    $$
    d = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right]
    $$
    [S1]
3.  **Coordinate Transformation:** Transform the infinite ray defined by $S$ and $d$ into local volume coordinates (coincident with texture coordinates) by applying the world-to-texture homogeneous transform matrix ($M_{vw}^{-1}$) [S1].
4.  **Ray Clipping and Validation:** Clip the line against the unit box to compute ray entry point and integration lengths. If the length is null (or less than epsilon), discard the fragment as invalid [S1].
5.  **Mipmap Level Selection:** At each sampling step, compute the depth $z$ of the current sample by transforming its position in texture space to world (screen-aligned) space using a single dot product for the z-coordinate [S1]. Compute the mipmap level $l$ using the equation:
    $$
    l = \text{median}(0, L_{max}, \lfloor \log_2 \frac{s(z)}{v_0} \rfloor)
    $$
    where $s(z)$ is the variable step-size, $L_{max}$ is the maximum available mipmap level, and $v_0$ is the voxel size at the finest mipmap level [S1]. The implementation uses:
    $$
    l = \log_2(S_0 + 2 \tan \Phi z) - \log_2 V
    $$
    [S1]
6.  **Volume Resampling and Compositing:** Step through the ray in a loop, performing volume resampling using `tex3Dlod` with the computed mipmap level and front-to-back compositing until the volume is exited or full opacity is reached [S1]. Match resampling and integration kernels with the actual representable voxel size based on depth-dependent spatial resolution [S1].
7.  **Shading and Classification:** Apply transfer function and shading to get color $C_i$ and opacity $\alpha_i$ [S1].

def ray_at_xy(x: float, y: float, mv_inv: float4x4) -> ray_t:
    # Compute ray passing through pixel in world coords
    ray_o = float4(x, y, 0, 0)
    # Direction calculation based on MCOP projection
    # d = [-(Ew.x-x)/Ew.z, (Vh-y)/Vd, -1, 0]
    ray_d = float4(-(Ew.x - x) / Ew.z, (Vh - y) / Vd, -1, 0)
    
    # Transform from world to texture coordinates
    tex_o = mul(mv_inv, ray_o).xyz
    tex_e = mul(mv_inv, ray_o + ray_d).xyz
    
    # Clip ray to volume box
    dir_norm = normalize(tex_e - tex_o)
    tmin_tmax = clip_to_unit_box(tex_o, dir_norm)
    
    result = ray_t()
    result.org = tex_o + dir_norm * tmin_tmax.x
    result.len = tmin_tmax.y - tmin_tmax.x
    result.dir = dir_norm
    return result

def fragment_shader(Qw: float2) -> float4:
    # Compute ray in tex coords
    ray = ray_at_xy(Qw.x, Qw.y, mv_inv)
    
    if ray.len < 1e-6: # Epsilon check [S1]
        discard_fragment()
        return float4(0, 0, 0, 0)
    
    # Ray composition initialization
    delta_dir = ray.dir * DL
    N = int(ray.len / DL)
    uvw = ray.org
    I = float3(0, 0, 0)
    a = 0.0
    a_max = 0.99 # Threshold for early termination [G]
    
    for i in range(N):
        if a >= a_max:
            break
            
        # Find distance from screen
        # z = abs(dot(modelview[0][2], float4(uvw.xyz, 1.0)))
        z = abs(dot(mv[0][2], float4(uvw.xyz, 1.0)))
        
        # Compute mipmap level
        # l = log2(S0 + 2*tanPhi*z) - log2V
        mipmap_l = log2(S0 + 2 * tanPhi * z) - log2V
        
        # Sample texture
        gggv = mipmap_value(uvw, mipmap_l)
        
        # Apply transfer function and shading
        C_i, a_i = apply_transfer_and_shading(gggv)
        
        # Accumulate color and opacity (Front-to-Back)
        # I = I + (1.0 - a) * C_i
        # a = a + (1.0 - a) * a_i
        transmittance = 1.0 - a
        I = I + transmittance * C_i
        a = a + transmittance * a_i
        
        # Step along ray
        uvw += delta_dir
        
    return float4(I, a)

**Parameters:**
*   Proxy Tessellation: 8x8 quads [S1].
*   Volume Texture Format: Single 4-component texture (RGB: precomputed gradient, A: voxel value) [S1].
*   Lookup Table: 1D RGBA texture [S1].
*   Typical Performance Optimization: Lower sampling rate during interaction by reducing pixel count (2.5mm precision on screen) and doubling integration step-size [S1].

**Edge Cases and Pitfalls:**
*   **Vertex Attribute Interpolation Error:** Standard fixed-function pipeline interpolation does not produce correct per-pixel ray parameter values for MCOP [S1]. Solved by using proxy geometry and computing projections in the vertex shader [S1].
*   **Tile Misalignment Artifacts:** When objects are moved with a slow refresh rate, misalignment between tiles becomes visible because the 96 display projectors are updated in batches of 16 [S1].
*   **Ray Length Validation:** If ray length is less than epsilon, the fragment is out of bounds and must be discarded [S1].

## Operating characteristics
*   **Time Complexity:** The method requires propagating millions of rays for hundreds of steps through the volume at full resolution (1 ray/pixel, 1 sample/voxel) [S1]. Interactive frame rates are improved by lowering the sampling rate (reducing pixel count and doubling step size) [S1].
*   **Memory Complexity:** Volume stored in a single 4-component texture plus a 1D lookup table [S1].
*   **Strengths:** Provides a fully continuous perceived image, unlike other multiview technologies that force users into fixed positions due to abrupt view-image changes when crossing discrete viewing zones [S1]. Good registration between displayed object space and physical space, demonstrating multi-user capability [S1].
*   **Limitations:** Performance is limited by single GPU volume renderer capacity at full resolution [S1]. Tile misalignment can occur with slow refresh rates [S1].
*   **When to use:** Interactive light field displays requiring continuous parallax and multi-user viewing [S1].
*   **When not to use:** Traditional single-viewpoint rendering where MCOP complexity is unnecessary [S1].

## Background
*   **Origin:** The method was introduced by Agus et al. in 2008 [S1].
*   **History:** It addresses the limitations of contemporary multiview technologies that rely on discrete viewing zones [S1]. It builds on GPU ray casting techniques and MCOP projection principles [S1].
*   **Usage:** Used for rendering datasets like Chameleon, Visible Human head, and rotational angiography on interactive light field displays [S1].
