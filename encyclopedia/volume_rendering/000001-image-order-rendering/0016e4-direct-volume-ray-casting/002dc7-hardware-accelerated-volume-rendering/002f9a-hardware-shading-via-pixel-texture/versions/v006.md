# Hardware Shading via Pixel Texture

Also called: Quantized Normal Shading

## Overview
Hardware Shading via Pixel Texture is a technique for adding Phong or Blinn-Phong shading to texture-memory based volume rendering [S1]. It solves the problem of poor depth perception in standard hardware-accelerated volume rendering by encoding surface normals into a 2D pixel texture, allowing the graphics hardware to perform lighting calculations efficiently [S1]. It sets itself apart from standard 3D texturing approaches by avoiding hardware interpolation redundancy and truncation errors associated with normal vectors, using nearest-neighbor interpolation for the texture lookup instead [S1, S2].

## How it works
The method extends the standard volume rendering pipeline by introducing a shading volume and a pixel texture lookup stage. It operates on the principle that normals can be quantized and stored in a 2D texture, which is then used to modulate the color of the volume slices during compositing [S1, S2].

**Inputs and Outputs**
*   **Inputs:**
    *   Scalar volume data $V$ (and optionally gradient magnitude $G$ and hue $H$ for multi-dimensional transfer functions) [S1, S2].
    *   Camera view parameters (position, orientation) [S1, S2].
    *   Lighting parameters (light position, view direction, material properties) [S1].
*   **Outputs:**
    *   Final composited image with shaded volume structures [S1, S2].

**Data Structures**
1.  **Shading Pixel Texture:** A 2D texture where each texel stores a quantized surface normal.
    *   **Layout:** 16-bit encoding per normal.
    *   **Channel Mapping:** The first 8 bits of the quantized normal are stored in the Red channel, and the second 8 bits are stored in the Green channel [S1, S2]. The Blue and Alpha channels are unused or reserved [S2].
    *   **Interpolation Mode:** Nearest-neighbor interpolation is strictly required to avoid redundancy and truncation artifacts inherent in hardware linear interpolation of quantized normal data [S1, S2].
2.  **Scratch/Auxiliary Buffer:** A temporary frame buffer used to render individual slices before compositing them into the final image [S2].

**Numbered Steps**
1.  **Normal Quantization:** Compute the surface normal $\mathbf{n}$ at each voxel using the gradient of the scalar volume $\nabla V$. Quantize the normal vector components into a 16-bit integer representation [S1, S2].
2.  **Texture Generation:** Generate the shading pixel texture on a per-view basis in software [S1, S2].
    *   Encode the quantized normals into the Red and Green channels of the 2D texture as described above [S1, S2].
    *   *Alternative Hardware Method:* Render the quantized normals as points with hardware lighting to a frame buffer, then copy the result to the pixel texture. Note: This alternative is not supported by all hardware implementations [S2].
3.  **Slice Rendering (Shading Volume):** Render the slice of the shading volume (containing the quantized normals) to the scratch/auxiliary buffer [S2].
4.  **Pixel Texture Operation:** Use a `glCopyPixels()` operation (or equivalent) to pixel texture the rendered slice from the scratch buffer. This step effectively applies the lighting model defined by the pixel texture to the slice geometry [S2].
    *   The lighting calculation is performed as a 2D pixel texture lookup, which is equivalent to a 16-bit 1D nearest-neighbor lookup [S1].
5.  **Modulation:** Multiply the shaded slice (from the scratch buffer) with the corresponding slice from the raw data volume (VGH) [S2]. This combines the shading information with the volume classification data.
6.  **Compositing:** Copy the shaded slice from the scratch buffer and blend it with the previously rendered slices in the main frame buffer using the standard front-to-back compositing equation [S2].
    *   If the transfer function is being manipulated while the view is static, only the portion of the volume changing requires re-rendering and pixel texture updates [S2].

**Formulas**
The compositing step uses the standard over operator, but the color $C_i$ at each sample is modulated by the shading result $S_i$ derived from the pixel texture lookup:

$$
C'_{i} = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i (C_i \cdot S_i)
$$
$$
\alpha'_{i} = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i
$$

Where $S_i$ is the shading value obtained from the 2D pixel texture lookup using the quantized normal at sample $i$ [S1, S2].

**Parameters**
*   **Quantization Scheme:** 16-bit encoding for normals [S1, S2].
*   **Interpolation:** Nearest-neighbor [S1, S2].

**Edge Cases and Pitfalls**
*   **Hardware Flexibility:** Some hardware implementations (e.g., SGI Octane2 with V-series cards) do not support rendering quantized normals as points with hardware lighting and copying to a pixel texture directly during rasterization. In such cases, the software-based per-view texture generation and `glCopyPixels()` workaround is required [S2].
*   **Performance Cost:** Generating the shading pixel texture on a per-view basis in software has minimal performance cost, but it must be done whenever the view point changes [S1, S2].
*   **Redundancy/Truncation:** Using standard hardware interpolation (linear) on quantized normals leads to redundancy and truncation errors. Nearest-neighbor is mandatory [S1, S2].

## Subtopics

### Quantized Normal Shading via Pixel Texture
A specific implementation variant that emphasizes the encoding of surface normals into a 2D pixel texture to avoid hardware interpolation redundancy and truncation [S2]. It differs from general hardware shading by strictly using nearest-neighbor interpolation for the pixel texture lookup and encoding the first 8 bits of the quantized normal into the Red channel and the second 8 bits into the Green channel [S2]. It is chosen when high-quality shading is needed in texture-memory based volume rendering without the cost of full per-fragment normal interpolation [S1, S2].

### Line Bundles
A technique that relies on graphics hardware to create texture by rendering and compositing many semitransparent line segments to produce an anisotropic volume rendering result [S3, unofficial]. It differs from pixel texture shading by using pre-computed sets of rendered line segments for each data point (splatting analogy) and perturbing their colors to provide a colored pattern [S3, unofficial]. It is chosen for flow field visualization where directionality must be clearly evident alongside velocity magnitude, which standard volume rendering may lack [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The shading texture generation is done in software on a per-view basis. The cost is minimal [S1]. The rendering cost per frame is dominated by the slice rendering and compositing, which is standard for hardware-accelerated volume rendering [S1].
*   **Memory Complexity:** Requires additional memory for the shading pixel texture (2D texture storing quantized normals) and a scratch/auxiliary buffer for intermediate slice rendering [S2].
*   **Measured Performance:** On SGI Octane 2 with V-series graphics cards and nVidia GeForce3, the method adds negligible cost to the rendering pipeline [S1, S2].
*   **Strengths:** Dramatically increases the quality of renderings by providing depth cues through shading, with negligible increase in rendering cost [S1].
*   **Limitations:** Dependent on hardware support for pixel texture operations (e.g., `glCopyPixels()`). Some hardware does not support the alternative hardware lighting method for texture generation [S2].
*   **When to use:** When texture-memory based volume rendering is used and shading is desired to improve shape perception [S1].
*   **When not to use:** When hardware does not support the required pixel texture operations or when the view point changes too frequently for the software texture generation to be efficient (though the cost is noted as minimal) [S1, S2].

## Background
The method was developed as part of the Interactive Volume Rendering Using Multi-Dimensional Transfer Functions project [S1, S2]. It was implemented on SGI Octane 2 with V-series graphics cards and nVidia GeForce3 series graphics adaptors [S2]. The approach addresses the lack of shading in previous texture-memory based volume rendering work, which often resulted in poor depth perception [S1]. The technique leverages the fact that pixel texture operations can be used to apply lighting models efficiently, treating the quantized normal as a 2D texture lookup [S1, S2].
