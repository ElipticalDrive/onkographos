# Hardware Shading via Pixel Texture

Also called: Quantized Normal Shading

## Overview
Hardware Shading via Pixel Texture is a technique for applying surface shading to volume rendering results by encoding surface normals into a 2D pixel texture, which is then used to modulate the rendered volume slices [S1, S2]. It solves the problem of adding shading to texture-memory based volume rendering, which previously often lacked shading capabilities [S1]. It sets itself apart from standard hardware-accelerated volume rendering by avoiding hardware interpolation of normals, which causes redundancy and truncation errors, by instead using nearest-neighbor interpolation on quantized normal data [S1, S2].

## How it works
The method integrates shading into the volume rendering pipeline by generating a separate "shading volume" or pixel texture that encodes lighting information, which is then composited with the primary volume data [S1, S2].

**Inputs and Outputs**
*   **Input:** Scalar volume data $V$, gradient data $\nabla V$ (or pre-computed normals), camera view parameters, and transfer function parameters [S1, S2].
*   **Output:** A shaded volume image composited into the frame buffer [S1, S2].

**Data Structures**
*   **Shading Pixel Texture:** A 2D texture where each texel encodes a quantized surface normal [S1, S2].
    *   **Layout:** The normal is quantized to 16 bits [S1, S2].
    *   **Encoding:** The first 8 bits of the quantized normal are stored in the Red channel, and the second 8 bits are stored in the Green channel [S1, S2]. The Blue and Alpha channels are unused or set to 0 [S1, S2].
    *   **Interpolation:** Nearest-neighbor interpolation is used for texture lookups to avoid redundancy and truncation errors associated with hardware linear interpolation of quantized values [S1, S2].

**Steps**
1.  **Normal Quantization:** Compute the surface normal $\mathbf{n}$ at each sample point or voxel boundary. Quantize $\mathbf{n}$ into a 16-bit integer representation [S1, S2].
2.  **Texture Encoding:** Encode the 16-bit quantized normal into a 2D pixel texture. Map the upper 8 bits to the Red channel and the lower 8 bits to the Green channel [S1, S2].
3.  **Texture Generation:** Generate the shading pixel texture on a per-view basis in software [S1, S2].
    *   *Alternative Hardware Method:* Render the quantized normals as points with hardware lighting, then copy the result from the frame buffer to the pixel texture using `glCopyPixels()` [S2]. Note: This alternative is not supported by all hardware implementations [S2].
4.  **Volume Rendering (Slice-based):**
    *   Render the current slice of the scalar volume data to a scratch/auxiliary buffer [S2].
    *   If shading is enabled, render the corresponding slice from the shading volume (or use the pixel texture) to modulate the current slice [S2]. The modulation is typically a multiplication operation [S2].
    *   Copy the slice from the scratch buffer to the frame buffer, blending it with previously rendered slices [S2].
5.  **Compositing:** The shaded slice is composited with the accumulated frame buffer content using the standard front-to-back over operator [S2, S4].

**Formulas**
The shading modulation is applied as a multiplication of the volume color $C_{vol}$ and the shading factor $S$ derived from the pixel texture:
$$
C_{shaded} = C_{vol} \times S
$$
Where $S$ is derived from the lighting model applied to the quantized normal retrieved from the pixel texture [S1, S2].

**Parameters**
*   **Quantization:** 16-bit encoding for normals [S1, S2].
*   **Interpolation:** Nearest-neighbor [S1, S2].

**Edge Cases and Pitfalls**
*   **Hardware Flexibility:** Some hardware implementations do not support rendering quantized normals as points with hardware lighting and copying them to a pixel texture [S2].
*   **Performance Cost:** Generating the shading pixel texture in software has minimal performance cost [S1].
*   **View Dependency:** The shading pixel texture must be regenerated when the view point changes [S1, S2].

## Subtopics

### Quantized Normal Shading via Pixel Texture
A specific implementation of hardware shading via pixel texture that explicitly details the encoding of normals into a 2D pixel texture to avoid hardware interpolation redundancy [S2]. It is chosen when high-quality shading is required for volume rendering on hardware that supports 3D pixel textures or `glCopyPixels` operations, such as the SGI Octane2 or nVidia GeForce3 [S2]. It differs from standard shading by using a 16-bit quantized normal encoding scheme [S2].

### Line Bundles
A technique that relies on graphics hardware to create texture by rendering and compositing many semitransparent line segments to produce an anisotropic volume rendering result [S3, unofficial]. It is used for flow field visualization where directionality is critical [S3, unofficial]. It differs from pixel texture shading by using pre-computed sets of rendered line segments with slightly perturbed colors to create a colored pattern, composited in back-to-front order [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The shading pixel texture generation is performed on a per-view basis in software, but the cost is described as minimal [S1]. The rendering itself follows the standard volume rendering pipeline complexity [S1, S2].
*   **Memory Complexity:** Requires additional memory for the shading pixel texture and a scratch/auxiliary buffer for slice rendering [S2].
*   **Performance:** Adds negligible cost to the rendering pipeline [S1].
*   **Strengths:** Dramatically increases rendering quality by adding shading with minimal performance impact [S1]. Avoids interpolation artifacts in normal encoding [S1, S2].
*   **Limitations:** Requires per-view regeneration of the shading texture [S1]. Dependent on hardware support for pixel texture operations (e.g., `glCopyPixels`) [S2].

## Background
The method was developed as part of interactive volume rendering using multi-dimensional transfer functions [S1, S2]. It was implemented on SGI Octane2 with V series graphics cards and nVidia GeForce3 series graphics adaptors [S2]. The technique addresses the lack of shading in previous texture-memory based volume rendering work [S1].
