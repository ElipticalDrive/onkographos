# Hardware Shading via Pixel Texture

Also called: Quantized Normal Shading

## Overview
Hardware Shading via Pixel Texture is a method for adding surface shading to texture-memory based volume rendering to improve the perception of shape and structure [S1]. It solves the problem of hardware interpolation redundancy and truncation that occurs when encoding continuous surface normals into standard 8-bit per-channel textures [S1, S2]. By quantizing normals and using nearest-neighbor interpolation on a 2D pixel texture, it achieves high-quality shading with negligible performance cost [S1]. It differs from [3D Pixel Texture Classification](6055-3d-pixel-textification.md) by focusing specifically on the lighting model rather than classification, and from [Hardware-Accelerated Volume Rendering via 3D Texturing](2799-hardware-accelerated-volume-rendering-via-3d-texturing.md) by decoupling the shading computation from the primary volume texture lookup [S1].

## How it works
**Inputs:**
*   Volume data (scalar values).
*   Surface normals derived from the volume data (typically via gradient estimation).
*   View direction.
*   Light direction(s).

**Outputs:**
*   Shaded volume image composited into the frame buffer.

**Data Structures:**
*   **Shading Pixel Texture:** A 2D texture where each texel stores a quantized normal.
    *   **Layout:** 16-bit quantized normal encoded into two 8-bit channels.
    *   **Red Channel:** First 8 bits of the quantized normal.
    *   **Green Channel:** Second 8 bits of the quantized normal.
    *   **Interpolation Mode:** Nearest-neighbor (to avoid redundancy/truncation).

**Steps:**
1.  **Normal Quantization:** Compute surface normals for the volume. Encode each normal using a 16-bit quantization scheme [S1, S2].
2.  **Texture Encoding:** Map the 16-bit quantized normal to the 2D pixel texture. Assign the first 8 bits to the Red channel and the second 8 bits to the Green channel [S1, S2].
3.  **Shading Texture Generation:** Generate the shading pixel texture on a per-view basis in software [S1, S2].
    *   *Alternative Hardware Method:* Render quantized normals as points with hardware lighting, then copy the result from the frame buffer to the pixel texture [S2]. Note: This alternative is not supported by all hardware implementations [S2].
4.  **Lighting Lookup:** During rendering, use the view direction and light direction to index into the 2D shading pixel texture. This is equivalent to a 16-bit 1D nearest-neighbor lookup [S1, S2].
5.  **Volume Rendering:** Render the volume slices.
    *   On platforms like SGI Octane 2, render the slice to a scratch/auxiliary buffer first [S2].
    *   Use `glCopyPixels()` to pixel texture the slice from the scratch buffer [S2].
    *   Modulate the slice with the shading texture (multiply) [S2].
    *   Blend the shaded slice with previously rendered slices in the frame buffer [S2].

**Formulas:**
*   **Normal Encoding:**
    Let $N$ be the normalized surface normal vector $(n_x, n_y, n_z)$.
    The 16-bit quantized value $Q$ is derived from $N$.
    $R = \text{first 8 bits of } Q$
    $G = \text{second 8 bits of } Q$
    Texel $T = (R, G, 0, 255)$ [S1, S2].

*   **Lighting:**
    The shading value $S$ is retrieved from the 2D pixel texture using coordinates derived from the view and light directions.
    $S = \text{TextureLookup}(\text{ShadingTexture}, \text{ViewLightCoords})$ [S1, S2].

**Parameters:**
*   **Quantization Scheme:** 16-bit [S1, S2].
*   **Interpolation:** Nearest-neighbor [S1, S2].

**Edge Cases and Pitfalls:**
*   **Hardware Flexibility:** Some hardware implementations do not support rendering quantized normals as points with hardware lighting and copying to a pixel texture [S2].
*   **Interpolation Artifacts:** Using linear interpolation instead of nearest-neighbor introduces redundancy and truncation errors in the normal encoding [S1, S2].
*   **Performance:** Generating the shading pixel texture in software has minimal cost, but doing it per-view can be costly if the view changes frequently [S1].

## Subtopics

### Quantized Normal Shading via Pixel Texture
A specific implementation of the method that emphasizes the 16-bit quantization and 2D pixel texture encoding [S2]. It is chosen when high-fidelity normal shading is required without the overhead of complex lighting calculations per fragment [S2]. It differs from standard shading by avoiding hardware interpolation redundancy [S2].

### Line Bundles
A technique for anisotropic volume rendering, particularly for flow fields, that uses graphics hardware to create texture by rendering and compositing many semitransparent line segments [S3, unofficial]. It relies on a splatting analogy where each data point is rendered with pre-computed sets of line segments [S3, unofficial]. The colors of these segments are slightly perturbed to provide a colored pattern [S3, unofficial]. When composited back-to-front, it results in an anisotropic volume rendering that clearly evidences directionality while viewing velocity magnitude [S3, unofficial]. It is chosen when directionality in vector fields is critical [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Minimal additional cost for shading generation if done in software per view [S1]. The lighting lookup is $O(1)$ per fragment using nearest-neighbor texture lookup [S1, S2].
*   **Memory Complexity:** Requires an additional 2D pixel texture for shading, sized based on the view/light space quantization [S1, S2]. Requires a scratch/auxiliary buffer for intermediate slice rendering on some hardware [S2].
*   **Performance:** Negligible increase in rendering cost compared to unshaded volume rendering [S1].
*   **Strengths:** Dramatically increases visual quality by expressing shape information [S1]. Avoids hardware interpolation artifacts [S1, S2].
*   **Limitations:** Requires per-view texture generation if done in software [S1]. Hardware-dependent implementation details (e.g., `glCopyPixels` support) [S2].

## Background
The method was developed as part of the Interactive Volume Rendering Using Multi-Dimensional Transfer Functions project [S1, S2]. It addresses the lack of shading in previous texture-memory based volume rendering work [S1]. The implementation was tested on SGI Octane 2 with V series graphics cards and nVidia GeForce3 series graphics adaptors [S2]. The Line Bundles variant was developed by Crawfis, Shen, and Max for flow visualization [S3, unofficial].
