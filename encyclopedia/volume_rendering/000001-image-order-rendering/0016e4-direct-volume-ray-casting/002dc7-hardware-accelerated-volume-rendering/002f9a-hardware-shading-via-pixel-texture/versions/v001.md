# Hardware Shading via Pixel Texture

Also called: Quantized Normal Shading

## Overview
Hardware Shading via Pixel Texture is a method for adding surface shading to texture-memory based volume rendering to improve the perception of shape and structure [S1, S2]. It solves the problem of hardware interpolation redundancy and truncation that occurs when encoding surface normals for lighting calculations [S2]. By encoding quantized normals into a 2D pixel texture and using nearest-neighbor interpolation, it achieves high-quality shading with negligible performance cost, distinguishing it from siblings that may lack shading or use less efficient encoding schemes [S1, S2].

## How it works
**Inputs:**
- 3D volume data (scalar values).
- Surface normals computed from the volume data (typically via gradient estimation).
- A 2D pixel texture containing the lighting model (shading lookup table).

**Outputs:**
- Shaded volume rendering image.

**Data Structures:**
- **Quantized Normal Texture:** A 2D texture where each texel stores a quantized surface normal.
  - **Layout:** 16-bit quantization scheme.
  - **Channel Packing:** The first 8 bits of the quantized normal value are stored in the Red channel. The second 8 bits are stored in the Green channel. Blue and Alpha channels are unused or set to zero.
- **Shading Texture:** A 2D pixel texture representing the lighting model. It acts as a 16-bit 1D nearest-neighbor lookup table, equivalent to an 8-bit per-axis 2D nearest-neighbor texture [S2].

**Steps:**
1. **Compute Normals:** Calculate surface normals for the volume data.
2. **Quantize Normals:** Encode the normals using a 16-bit quantization scheme [S1, S2].
3. **Encode into Texture:** Map the quantized normals to a 2D pixel texture:
   - Extract the upper 8 bits of the quantized normal and write to the Red channel.
   - Extract the lower 8 bits of the quantized normal and write to the Green channel [S2].
4. **Generate Shading Texture:** Create the 2D shading pixel texture. This can be done:
   - **In Software:** Generate the texture on a per-view basis in software [S1, S2].
   - **In Hardware (Alternative):** Render quantized normals as points with hardware lighting, then copy the result from the frame buffer to the pixel texture [S2].
5. **Render Slice:** Render a slice of the volume data to a scratch/auxiliary buffer [S2].
6. **Apply Shading:** Use a `glCopyPixels()` operation (or equivalent) to pixel texture the slice from the scratch buffer. This applies the shading texture using nearest-neighbor interpolation to the quantized normal data [S2].
7. **Composite:** Copy the shaded slice from the scratch buffer and blend it with previously rendered slices in the frame buffer using front-to-back compositing [S2].

## Subtopics

### Quantized Normal Shading via Pixel Texture
A specific implementation of Hardware Shading via Pixel Texture that emphasizes the 16-bit quantization and 2D pixel texture encoding [S2]. It is chosen when high-quality shading is needed with minimal performance impact, particularly on hardware that supports pixel texture operations via `glCopyPixels()` [S2]. It differs from general hardware shading by its specific encoding of normals into RGB channels and the use of nearest-neighbor interpolation to avoid truncation [S2].

## Operating characteristics
- **Time Complexity:** Minimal additional cost for generating the shading texture on a per-view basis [S2]. The pixel texture operation itself is hardware-accelerated.
- **Memory Complexity:** Requires additional memory for the normal texture and shading texture. A scratch/auxiliary buffer is also needed for intermediate slice rendering [S2].
- **Measured Performance:** The performance cost of generating the shading pixel texture is minimal [S2]. Shading dramatically increases rendering quality with negligible increase in rendering cost [S1].
- **Strengths:** Improves shape perception; avoids hardware interpolation redundancy and truncation; negligible performance cost.
- **Limitations:** Dependent on hardware support for pixel texture operations; some hardware may not support direct point rendering with lighting and framebuffer copy [S2].
- **When to Use:** When shading is desired for volume rendering and hardware supports pixel texture operations.
- **When Not to Use:** When hardware does not support the required pixel texture operations or when performance is critical and the minimal cost is still too high.

## Background
The method was developed for interactive volume rendering using multi-dimensional transfer functions [S1, S2]. It was implemented on SGI Octane 2 with V series graphics cards and nVidia GeForce3 series graphics adaptors [S2]. The approach addresses the lack of shading in previous texture-memory based volume rendering work [S1].
