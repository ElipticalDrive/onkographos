# Back-face rasterized volume rendering

Also called: Back-Face Entry Point Method, Backface Rendering for Ray Casting, Backface Culling for Ray Casting Entry Points

## Overview
Back-face rasterized volume rendering is a GPU-accelerated technique that determines ray entry and exit points for volume raycasting by rasterizing the bounding box geometry rather than computing intersections analytically in the fragment shader [S1, S2, S3, S4, unofficial]. It solves the problem of efficiently restricting fragment shader execution to pixels intersecting the volume while correctly handling camera zooming, which can cause front-face clipping [S2, S4, unofficial]. It differs from [Bounding Box Raymarching](2071-bounding-box-raymarching.md) by explicitly utilizing a two-pass approach where the first pass captures back-face coordinates into a texture, and the second pass uses these coordinates to define ray endpoints for front-to-back compositing [S1, S2, S3, unofficial]. Unlike [Volume Ray Casting with RayData Texture](3077-volume-ray-casting-with-raydata-texture.md), which stores ray data in a dedicated texture, this method often computes ray directions from geometry attributes or camera matrices directly in the fragment shader [S5, unofficial].

## How it works
The method uses a two-pass rendering pipeline. The first pass renders the back faces of the volume's axis-aligned bounding box (AABB) to a framebuffer object (FBO) to store the ray exit points (or entry points, depending on culling convention) in a 2D texture. The second pass renders the front faces, sampling the texture from the first pass to retrieve the opposite boundary, and performs the raymarching integration [S1, S2, S3, S4, unofficial].

### Inputs and Outputs
**Inputs:**
*   Volume data: Stored as a 3D texture (`sampler3D`) or a 2D texture array (`sampler2DArray`) representing the scalar field $V(\mathbf{p})$ [S1, S4, unofficial].
*   Transfer function: Maps scalar values to RGBA, typically stored as a 1D texture (`sampler1D`) or 2D texture (`sampler2D`) [S1, S2, S4, unofficial].
*   Camera parameters: Projection matrix, view matrix, and eye position [S2, S4, unofficial].
*   Bounding box geometry: A unit cube $[0,1]^3$ or scaled cube representing the volume domain [S2, S4, unofficial].

**Outputs:**
*   Final image: Rendered to the default framebuffer [S1, S4, unofficial].

### Data Structures
1.  **Bounding Box Geometry:**
    *   Vertices: 8 vertices in object coordinates, typically $\{0,0,0\}$ to $\{1,1,1\}$ [S4, unofficial].
    *   Indices: 36 indices defining 12 triangles (2 per face) [S4, unofficial].
2.  **Back-face Texture (`g_bfTexObj` / `u_ExitPoints`):**
    *   Type: 2D texture (`sampler2D`) [S1, S4, unofficial].
    *   Dimensions: Matches viewport resolution ($W \times H$) [S4, unofficial].
    *   Internal Format: `GL_RGBA16F` (half-precision float) to store 3D coordinates [S4, unofficial].
    *   Content: RGB components store the 3D position of the back-face intersection point in object/texture space [S1, S4, unofficial].
3.  **Framebuffer Object (FBO):**
    *   Attachments: `GL_COLOR_ATTACHMENT0` bound to `g_bfTexObj`; `GL_DEPTH_ATTACHMENT` bound to a depth renderbuffer [S3, S4, unofficial].

### Steps

1.  **Initialization:**
    *   Create the FBO and attach the 2D texture `g_bfTexObj` [S4, unofficial].
    *   Define the bounding box geometry (unit cube) [S4, unofficial].

2.  **Pass 1: Capture Back-Face Coordinates:**
    *   Bind the FBO [S1, S4, unofficial].
    *   Set viewport to $(0, 0, W, H)$ [S1, S4, unofficial].
    *   Enable face culling and set `glCullFace` to `GL_FRONT` (culling front faces, rendering only back faces) [S1, S4, unofficial].
    *   Execute the back-face vertex/fragment shaders:
        *   **Vertex Shader:** Transforms vertex position to clip space. Outputs the vertex position in object/texture space (e.g., `fragPos`) [S1, S4, unofficial].
        *   **Fragment Shader:** Writes the interpolated vertex position as the fragment color to the FBO [S1, S4, unofficial].
            $$ \text{Color}_{out} = \text{vec4}(\text{fragPos}, 1.0) $$
    *   Unbind the FBO [S1, S4, unofficial].

3.  **Pass 2: Raycasting and Compositing:**
    *   Bind the default framebuffer [S1, S4, unofficial].
    *   Set viewport to $(0, 0, W, H)$ [S1, S4, unofficial].
    *   Enable face culling and set `glCullFace` to `GL_BACK` (culling back faces, rendering only front faces) [S1, S4, unofficial].
    *   Bind `g_bfTexObj` as a uniform sampler (e.g., `uBackCoord`) [S1, S4, unofficial].
    *   Execute the raycasting vertex/fragment shaders:
        *   **Vertex Shader:** Outputs the current vertex position in object/texture space as `EntryPoint` (front face) [S1, S4, unofficial].
        *   **Fragment Shader:**
            1.  **Retrieve Exit Point:** Sample the back-face texture using normalized fragment coordinates to get the exit point $\mathbf{p}_{exit}$ [S1, S4, unofficial].
                $$ \mathbf{p}_{exit} = \text{texture}(uBackCoord, \frac{\text{gl\_FragCoord}.st}{\text{Resolution}}).xyz $$
            2.  **Compute Ray Direction:** Calculate the ray direction vector $\mathbf{d}$ from the front point $\mathbf{p}_{entry}$ (interpolated vertex position) to the exit point [S1, S4, unofficial].
                $$ \mathbf{d} = \mathbf{p}_{exit} - \mathbf{p}_{entry} $$
            3.  **Check Validity:** If $\mathbf{p}_{entry} == \mathbf{p}_{exit}$ (ray length is zero, e.g., tangent ray or miss), discard the fragment [S4, unofficial].
            4.  **Compute Step Size:** Determine the step vector $\Delta \mathbf{p}$ based on the desired number of steps $N$ or voxel size [S1, S4, unofficial].
                $$ \text{len} = \|\mathbf{d}\| $$
                $$ \Delta \mathbf{p} = \frac{\mathbf{d}}{N} \quad \text{or} \quad \Delta \mathbf{p} = \frac{\mathbf{d}}{\|\mathbf{d}\|} \cdot \Delta t $$
            5.  **Raymarching Loop:** Iterate $i$ from $0$ to $N-1$:
                *   Sample volume value $v = V(\mathbf{p}_{entry})$ [S1, S4, unofficial].
                *   Apply transfer function $T(v) \rightarrow (C_i, \alpha_i)$ [S1, S4, unofficial].
                *   Composite using front-to-back over operator:
                    $$ C'_{i} = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i $$
                    $$ \alpha'_{i} = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i $$
                *   Advance position: $\mathbf{p}_{entry} \leftarrow \mathbf{p}_{entry} + \Delta \mathbf{p}$ [S1, S4, unofficial].
                *   **Termination Conditions:**
                    *   If $\alpha' \ge 1.0$ (or threshold), break (early ray termination) [S1, S4, unofficial].
                    *   If position exceeds volume bounds $[0,1]$, break [S1, unofficial].
                    *   If loop counter reaches $N$, break [S1, unofficial].
            6.  **Final Output:** Write accumulated color $C'$ to the framebuffer [S1, S4, unofficial].

### Pseudocode

```python
# Pass 1: Back-face capture
def pass1_capture_backface():
    bind_framebuffer(fbo, texture=g_bfTexObj)
    set_viewport(0, 0, width, height)
    enable_cull_face(GL_FRONT) # Render only back faces
    
    # Vertex Shader Logic (simplified)
    # fragPos = vertex_position_in_object_space
    # gl_Position = MVP * vec4(vertex_position, 1.0)
    
    # Fragment Shader Logic
    # out_color = vec4(fragPos, 1.0)
    
    draw_box_geometry()
    unbind_framebuffer()

# Pass 2: Raycasting
def pass2_raycast():
    bind_framebuffer(default)
    set_viewport(0, 0, width, height)
    enable_cull_face(GL_BACK) # Render only front faces
    bind_texture(g_bfTexObj, unit=0) # uBackCoord
    
    # Vertex Shader Logic
    # EntryPoint = vertex_position_in_object_space
    # gl_Position = MVP * vec4(vertex_position, 1.0)
    
    # Fragment Shader Logic
    # 1. Get Exit Point
    uv = gl_FragCoord.xy / resolution
    exit_point = texture(uBackCoord, uv).xyz
    
    entry_point = EntryPoint # Interpolated from vertex
    
    # 2. Compute Ray
    dir = exit_point - entry_point
    length = length(dir)
    
    if length < epsilon:
        discard()
        
    # 3. Setup Marching
    step_vector = dir / num_steps
    pos = entry_point
    accum_color = vec4(0.0)
    accum_alpha = 0.0
    
    # 4. Loop
    for i in range(num_steps):
        # Sample Volume
        val = texture(uVolumeTex, pos).r
        
        # Transfer Function
        tf_sample = texture(uTransferFunc, val)
        color_sample = tf_sample.rgb
        alpha_sample = tf_sample.a
        
        # Composite
        if alpha_sample > 0.0:
            # Adjust alpha for step size if necessary (e.g., power approximation)
            # alpha_sample = 1.0 - pow(1.0 - alpha_sample, step_size_factor)
            
            transmittance = 1.0 - accum_alpha
            accum_color.rgb += transmittance * alpha_sample * color_sample
            accum_alpha += transmittance * alpha_sample
            
        # Advance
        pos += step_vector
        
        # Termination
        if accum_alpha >= 1.0:
            break
        if not is_inside_volume(pos):
            break
            
    # 5. Output
    out_color = vec4(accum_color, 1.0)
    
    draw_box_geometry()
```

### Parameters
*   `uSteps` / `num_steps`: Number of sampling steps along the ray. Typical value: 256 [S1, unofficial].
*   `uOpacityVal`: Opacity scaling factor. Typical value: 4.0 [S1, unofficial].
*   `uMinGrayVal` / `uMaxGrayVal`: Volume value thresholds for visibility. Typical values: 0.001, 1.0 [S1, unofficial].
*   `uAbsorptionModeIndex`: Rendering mode switch. 0: Simple accumulation, 1: Standard alpha blending, 2: Max projection [S1, unofficial].
*   `volume_scale`: Scaling factor for the unit cube to match non-uniform volume dimensions [S2, unofficial].

### Edge Cases and Pitfalls
*   **Zooming:** Rendering only front faces causes clipping when the camera zooms inside the volume, leaving pixels unrendered. Rendering back faces (or both, carefully ordered) avoids this [S2, unofficial].
*   **Tangent/Miss Rays:** If the entry and exit points are identical, the ray length is zero. The shader must discard the fragment to avoid division by zero or infinite loops [S4, unofficial].
*   **GLSL Loop Limits:** Some GLSL implementations require explicit loop bounds or break conditions. Using a large constant (e.g., 4095) with an explicit `break` when `i == uSteps` is a common workaround [S1, unofficial].
*   **Precision:** Using `GL_RGBA16F` for the back-face texture provides sufficient precision for most volume rendering tasks, but extreme aspect ratios or large volumes may require higher precision [S4, unofficial].
*   **Coordinate Systems:** Ensure consistent coordinate spaces (object, texture, eye) between the vertex shaders of both passes and the volume texture sampling [S2, S4, unofficial].

## Subtopics

### [Bounding Box Raymarching](2071-bounding-box-raymarching.md)
A GPU-accelerated technique that renders a 3D voxel grid by casting rays through the volume's bounding box geometry. It differs by explicitly utilizing a two-pass approach where the first pass captures back-face coordinates into a texture, and the second pass uses these coordinates to define ray endpoints for front-to-back compositing.

### [Volume Ray Casting with RayData Texture](3077-volume-ray-casting-with-raydata-texture.md)
Stores ray data in a dedicated texture, often computing ray directions from geometry attributes or camera matrices directly in the fragment shader, differing from the back-face rasterization method which derives endpoints from geometry colors.

## Operating characteristics
*   **Time Complexity:** $O(W \cdot H \cdot N)$, where $W, H$ are viewport dimensions and $N$ is the number of steps per ray. The two-pass approach adds a constant overhead for the back-face rasterization [S1, S2, unofficial].
*   **Memory Complexity:** $O(W \cdot H)$ for the back-face texture storage [S4, unofficial].
*   **Performance:** Efficiently restricts fragment processing to pixels intersecting the volume, avoiding unnecessary work for empty screen regions [S2, unofficial]. Early ray termination further reduces average step count [S2, unofficial].
*   **Strengths:** Correctly handles zooming into the volume; avoids complex ray-box intersection math in the fragment shader for boundary determination; leverages hardware rasterization for culling [S2, S4, unofficial].
*   **Limitations:** Requires two render passes; depends on the bounding box being a simple convex shape (typically an AABB); precision of the back-face texture can limit accuracy for very large or high-resolution volumes [S4, unofficial].
*   **When to Use:** Ideal for interactive volume rendering on GPUs where simplicity of boundary determination and correct zoom behavior are prioritized over single-pass efficiency.
*   **When Not to Use:** When single-pass rendering is strictly required, or when the volume has a complex, non-convex bounding shape that cannot be easily represented by a simple rasterized box [S3, S4, unofficial].

## Background
The method originated as a practical solution for GPU-based volume rendering, leveraging the graphics pipeline's built-in face culling and rasterization to determine ray bounds. It was popularized in WebGL and OpenGL tutorials for volume rendering, addressing common pitfalls like front-face clipping during zooming [S2, S4, unofficial]. Implementations can be found in various open-source projects and educational resources [S1, S3, S4, unofficial].
