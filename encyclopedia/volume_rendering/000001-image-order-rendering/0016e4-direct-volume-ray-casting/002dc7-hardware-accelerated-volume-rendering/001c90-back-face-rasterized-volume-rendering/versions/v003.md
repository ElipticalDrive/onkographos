# Back-face rasterized volume rendering

Also called: Back-Face Entry Point Method, Backface Rendering for Ray Casting, Backface Culling for Ray Casting Entry Points

## Overview
Back-face rasterized volume rendering is a hardware-accelerated technique that determines ray entry and exit points for volume ray casting by rasterizing the bounding box geometry of the volume, rather than computing intersections analytically in the fragment shader [S1, S2, S3, S4, unofficial]. It solves the problem of efficiently restricting fragment shader execution to pixels intersecting the volume while correctly handling camera zooming, which can cause front-face clipping if standard culling is used [S2, unofficial]. It differs from [Hardware-Accelerated Volume Rendering via 3D Texturing](2799-hardware-accelerated-volume-rendering-via-3d-texturing.md) by using geometry rasterization to drive the ray bounds instead of 3D texture sampling for traversal, and from [Bounding Box Raymarching](2071-bounding-box-raymarching.md) by explicitly storing the back-face coordinates in a 2D texture to be sampled during the front-face pass, rather than computing endpoints directly in the fragment shader [S2, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume texture ($V$), a transfer function texture ($TF$), a camera model (position $\mathbf{o}$, projection matrix $P$, view matrix $V_{iew}$), and a bounding box geometry (typically a unit cube $[0,1]^3$ scaled to volume dimensions).
*   **Output:** A 2D image where each pixel contains the accumulated color and opacity of the ray passing through the volume.

**Data Structures:**
1.  **Bounding Box Geometry:** Defined by 8 vertices in object coordinates $\{0,0,0\}$ to $\{1,1,1\}$ and 36 indices forming 12 triangles [S4, unofficial].
2.  **Back-Face Texture ($T_{back}$):** A 2D texture (e.g., `GL_RGBA16F`) with resolution equal to the viewport ($W \times H$) [S4, unofficial]. It stores the 3D entry point (back-face intersection) as RGB color values [S1, S4, unofficial].
3.  **Frame Buffer Object (FBO):** Attached to $T_{back}$ for the first pass [S3, S4, unofficial].

**Steps:**

1.  **Pass 1: Render Back Face to Texture**
    *   Bind the FBO attached to $T_{back}$.
    *   Enable face culling with `GL_FRONT` (cull front faces, render back faces) [S1, S4, unofficial].
    *   Render the bounding box geometry using a vertex shader that outputs the vertex position in object/local space as a varying color, and a fragment shader that writes this position to the framebuffer [S1, S4, unofficial].
    *   The fragment shader output for a fragment at screen coordinate $(u,v)$ is the 3D entry point $\mathbf{p}_{entry}$ of the ray through the back face of the bounding box [S4, unofficial].
    *   Unbind the FBO.

2.  **Pass 2: Ray Casting from Front Face**
    *   Bind the default framebuffer.
    *   Enable face culling with `GL_BACK` (cull back faces, render front faces) [S1, S4, unofficial].
    *   Render the bounding box geometry using the ray-casting shaders.
    *   **Vertex Shader:** Outputs the vertex position in object/local space as the front-face position $\mathbf{p}_{front}$ (exit point) [S1, S4, unofficial].
    *   **Fragment Shader:**
        *   Sample $T_{back}$ using the interpolated screen coordinates (normalized by viewport resolution) to retrieve $\mathbf{p}_{entry}$ [S1, S4, unofficial].
        *   Compute ray direction: $\mathbf{d} = \mathbf{p}_{front} - \mathbf{p}_{entry}$ [S1, unofficial].
        *   Compute ray length: $L = \|\mathbf{d}\|$ [S4, unofficial].
        *   If $L \approx 0$ (entry equals exit, e.g., tangent ray), discard the fragment [S4, unofficial].
        *   Compute step vector: $\mathbf{s} = \mathbf{d} / N_{steps}$ or $\mathbf{s} = \mathbf{d} \cdot \Delta t$ where $\Delta t$ is a fixed step size [S1, S2, unofficial].
        *   Initialize accumulation variables: $C_{acc} = (0,0,0,0)$, $\alpha_{acc} = 0$ [S1, S4, unofficial].
        *   Set current position $\mathbf{p} = \mathbf{p}_{entry}$ [S1, unofficial].
        *   **Ray Marching Loop:** For $i = 0$ to $N_{steps}$:
            1.  Sample volume: $val = V(\mathbf{p})$ [S4, unofficial].
            2.  Apply transfer function: $c_{sample} = TF(val)$ [S4, unofficial].
            3.  If $\alpha_{sample} > 0$:
                *   Adjust alpha for step size (optional, depends on implementation): $\alpha'_{sample} = 1 - (1 - \alpha_{sample})^{\Delta}$ [S4, unofficial].
                *   Composite: $C_{acc}.rgb += (1 - \alpha_{acc}) \cdot \alpha'_{sample} \cdot c_{sample}.rgb$ [S4, unofficial].
                *   Update alpha: $\alpha_{acc} += (1 - \alpha_{acc}) \cdot \alpha'_{sample}$ [S4, unofficial].
            4.  Advance position: $\mathbf{p} += \mathbf{s}$ [S1, unofficial].
            5.  **Termination Conditions:**
                *   If $\alpha_{acc} \ge 1.0$ (or a threshold like 0.95), break [S1, S3, S4, unofficial].
                *   If $\mathbf{p}$ is outside the volume bounds $[0,1]^3$, break [S1, unofficial].
                *   If $i == N_{steps}$, break [S1, unofficial].
            6.  If loop completes without early exit, composite background: $C_{final}.rgb = C_{acc}.rgb + (1 - \alpha_{acc}) \cdot C_{bg}.rgb$ [S4, unofficial].
        *   Output $C_{final}$ [S4, unofficial].

**Pseudocode:**

```python
# Pass 1: Back-face rasterization
def render_back_face_to_texture(viewport_width, viewport_height, fbo, texture_back):
    bind_framebuffer(fbo)
    bind_texture(texture_back, unit=0)
    enable_cull_face(GL_FRONT) # Cull front, render back
    draw_bounding_box_geometry()
    unbind_framebuffer()

# Pass 2: Ray casting
def render_front_face(viewport_width, viewport_height, texture_back, volume_tex, transfer_func):
    bind_default_framebuffer()
    enable_cull_face(GL_BACK) # Cull back, render front
    draw_bounding_box_geometry()

# Fragment Shader Logic (Pass 2)
def fragment_shader(screen_uv, viewport_res):
    # Retrieve entry point from back-face texture
    # screen_uv is interpolated from vertex positions
    uv_normalized = screen_uv / viewport_res
    entry_point = texture_2d(texture_back, uv_normalized).xyz
    
    # Exit point is the current vertex position (passed as varying)
    exit_point = current_vertex_position
    
    # Compute ray
    ray_dir = exit_point - entry_point
    ray_len = length(ray_dir)
    
    if ray_len < 1e-6:
        discard()
        
    # Determine step size
    # Option A: Fixed number of steps
    num_steps = 256
    step_vec = ray_dir / num_steps
    
    # Option B: Fixed step size (delta)
    # step_vec = normalize(ray_dir) * delta
    
    # Initialize accumulation
    acc_color = vec4(0.0, 0.0, 0.0, 0.0)
    acc_alpha = 0.0
    pos = entry_point
    
    # Background color
    bg_color = vec4(1.0, 1.0, 1.0, 1.0)
    
    for i in range(1600): # Max iterations
        # Sample volume
        val = texture_3d(volume_tex, pos).r
        
        # Transfer function
        sample = texture_2d(transfer_func, vec2(val, 0.5))
        color_sample = sample.rgb
        alpha_sample = sample.a
        
        if alpha_sample > 0.0:
            # Adjust alpha for step size (approximation)
            # Using a power law to simulate continuous integration over step
            alpha_sample = 1.0 - pow(1.0 - alpha_sample, 0.1) # 0.1 is arbitrary step factor
            
            # Over operator
            acc_color.rgb += (1.0 - acc_alpha) * alpha_sample * color_sample
            acc_alpha += (1.0 - acc_alpha) * alpha_sample
            
        # Advance
        pos += step_vec
        
        # Termination checks
        if acc_alpha >= 1.0:
            break
        if not (0.0 <= pos.x <= 1.0 and 0.0 <= pos.y <= 1.0 and 0.0 <= pos.z <= 1.0):
            break
        if i >= 1600: # Safety break
            break
            
    # Final composite with background
    final_color = acc_color.rgb + (1.0 - acc_alpha) * bg_color.rgb
    return final_color
```

**Parameters:**
*   `uSteps` / `num_steps`: Number of sampling steps. Typical value: 256 [S1, unofficial].
*   `uOpacityVal`: Opacity scaling factor. Typical value: 4.0 [S1, unofficial].
*   `uMinGrayVal` / `uMaxGrayVal`: Volume value thresholds. Typical: 0.001 to 1.0 [S1, unofficial].
*   `DELTA`: Constant step size. Value: 0.005 [S3, unofficial].
*   `volume_scale`: Scaling factor for the unit cube to match volume dimensions [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Zooming:** Rendering front faces causes clipping when the camera zooms inside the volume, as front faces project behind the camera. Rendering only back faces in Pass 1 and front faces in Pass 2 avoids this [S2, unofficial].
*   **Tangent Rays:** If the entry point equals the exit point, the ray length is zero. The shader must discard the fragment to avoid division by zero [S4, unofficial].
*   **Loop Limits:** GLSL compilers may have limits on loop unrolling or iteration counts. Using a large constant (e.g., 4095) with an explicit break condition is often safer than a variable loop bound [S1, unofficial].
*   **Precision:** Using `GL_RGBA16F` for the back-face texture provides sufficient precision for coordinate storage [S4, unofficial].

Computes ray endpoints directly in the fragment shader using slab intersection, avoiding the texture lookup overhead of the two-pass method. Choose when memory bandwidth is a bottleneck and explicit intersection math is acceptable.

## Operating characteristics
*   **Time Complexity:** $O(W \cdot H \cdot N_{steps})$ per frame, where $W, H$ are viewport dimensions and $N_{steps}$ is the number of samples. The two-pass approach adds a constant overhead of one full-screen render pass.
*   **Memory Complexity:** $O(W \cdot H)$ for the back-face texture (typically 8 bytes per pixel for `RGBA16F`) [S4, unofficial].
*   **Performance:** Efficiently culls pixels outside the volume, reducing fragment shader invocations [S2, unofficial]. The extra render pass adds overhead but simplifies the ray-box intersection logic in the main pass [S4, unofficial].
*   **Strengths:** Handles zooming correctly; avoids complex ray-box intersection code in the fragment shader; leverages hardware rasterization for culling [S2, S4, unofficial].
*   **Limitations:** Requires two render passes; extra memory for the intermediate texture; potential precision loss if texture format is low-bit [S4, unofficial].
*   **When to use:** Interactive volume rendering where camera movement is frequent and zooming is required.
*   **When not to use:** When memory bandwidth is extremely constrained and a single-pass solution is preferred, or when the volume is static and pre-computation is viable.

## Background
The method was developed as part of GPU-based volume rendering implementations to leverage hardware rasterization for culling and ray bound determination. It is featured in various open-source WebGL and OpenGL volume rendering tutorials and prototypes, such as those by Will Usher [S2, unofficial], levl-dev [S1, unofficial], and thePZH [S4, unofficial]. The approach addresses the limitations of early hardware ray casting by using the graphics pipeline's built-in face culling to determine which pixels require ray marching.
