# Volume Ray-Casting on Graphics Hardware
Also called: Stream model for volumetric ray-casting

## Overview
This method implements direct volume ray casting on programmable graphics hardware (specifically DirectX 9-level architectures like the ATI 9700) using a multi-pass stream model [S1, unofficial]. It solves the performance bottleneck of CPU-based ray casting by exploiting the intrinsic parallelism of fragment processors and efficient inter-pass communication via texture render targets [S1, unofficial]. Unlike single-pass hardware approaches, it separates ray traversal into discrete steps, using early z-testing to skip empty space and terminate rays early, achieving performance gains up to a factor of 3 on typical data sets [S1, unofficial].

## How it works
The method uses a multi-pass rendering pipeline where the output of each pass is stored in a 2D texture, allowing consecutive passes to access accumulated state (color, opacity, and ray direction) [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** Volumetric scalar data, transfer function, camera parameters, and an iso-surface threshold (optional).
*   **Output:** Final 2D image (frame buffer).

**Data Structures:**
1.  **Volume Texture:** 3D texture storing scalar voxel values [S1, unofficial].
2.  **Ray Direction Textures:** Two 2D textures storing the $(u, v)$ components of the ray direction in local texture space for each pixel [S1, unofficial].
3.  **Accumulation Textures:** Two 2D textures (one for color, one for opacity) storing the accumulated result from the previous pass [S1, unofficial].
4.  **Z-Buffer:** Used for early z-testing [S1, unofficial].

**Numbered Steps:**

1.  **Pre-computation:** For each pixel, compute the ray direction in local texture coordinates. Store these components in two separate 2D textures [S1, unofficial].
2.  **Initialization:** Render the initial ray direction textures to the accumulation textures (or initialize them to zero if starting accumulation) [S1, unofficial].
3.  **Main Ray Traversal Passes:** Perform a fixed number of rendering passes. In each pass:
    a.  Bind the accumulation textures from the previous pass as input textures.
    b.  Bind the ray direction textures.
    c.  Execute a pixel shader that:
        i.  Reads the accumulated color $C_{acc}$ and opacity $\alpha_{acc}$ from the previous pass textures.
        ii. Reads the ray direction $(d_u, d_v)$ for the current fragment.
        iii. Advances the ray position by one step $\Delta t$ along the direction.
        iv. Samples the volume texture at the new position to get scalar value $V$.
        v.  Applies the transfer function to get color $C$ and opacity $\alpha$ [S1, unofficial].
        vi. Updates accumulation using the front-to-back over operator:
            $$ C_{new} = C_{acc} + (1 - \alpha_{acc}) \alpha C $$
            $$ \alpha_{new} = \alpha_{acc} + (1 - \alpha_{acc}) \alpha $$
        vii. Writes $C_{new}$ and $\alpha_{new}$ to the output accumulation textures [S1, unofficial].
4.  **Termination Check Pass:** Between main traversal passes, execute an additional pass:
    a.  Read the accumulated opacity $\alpha_{acc}$ from the accumulation texture.
    b.  Test if $\alpha_{acc}$ exceeds a specified threshold or if an iso-surface is hit (if applicable) [S1, unofficial].
    c.  If the test succeeds, set the fragment's depth value $z$ to the maximum possible value (using depth replace).
    d.  If the test fails, set $z$ to zero [S1, unofficial].
    e.  Set the depth test function to GREATER. This ensures that in subsequent main passes, fragments that have already terminated (with $z=$ max) are discarded by the early z-test before the shader executes, while active fragments (with $z=0$) pass the test [S1, unofficial].
5.  **Final Shading Pass (Optional):** If an iso-surface was hit, use the stored intersection coordinates to perform gradient-based shading [S1, unofficial].

**Pseudocode:**

```python
# Pseudocode for the Main Ray Traversal Pixel Shader
# Inputs: 
#   tex_accum_color: 2D texture from previous pass (accumulated color)
#   tex_accum_opacity: 2D texture from previous pass (accumulated opacity)
#   tex_ray_dir: 2D texture containing ray direction (u, v)
#   tex_volume: 3D texture containing scalar volume data
#   step_size: float, distance to advance ray per pass
#   tf_color: function mapping scalar value to color
#   tf_opacity: function mapping scalar value to opacity

# Output:
#   out_color: vec4
#   out_opacity: float

def main_pass_shader(pixel_coord):
    # 1. Retrieve accumulated state from previous pass
    prev_color = sample_2d(tex_accum_color, pixel_coord)
    prev_opacity = sample_2d(tex_accum_opacity, pixel_coord)
    
    # 2. Retrieve ray direction
    ray_dir = sample_2d(tex_ray_dir, pixel_coord)
    
    # 3. Advance ray position
    # Note: In a real implementation, the ray position must be tracked.
    # This stream model typically requires storing the current ray position
    # in a texture as well, or computing it from the step count and direction.
    # Assuming a texture 'tex_ray_pos' stores the current 3D position:
    current_pos = sample_3d(tex_ray_pos, pixel_coord) # Simplified: assuming 3D coord storage
    new_pos = current_pos + ray_dir * step_size
    
    # 4. Sample volume and classify
    scalar_val = sample_3d(tex_volume, new_pos)
    sample_color = tf_color(scalar_val)
    sample_opacity = tf_opacity(scalar_val)
    
    # 5. Composite
    # Front-to-back over operator
    transmittance = 1.0 - prev_opacity
    new_color = prev_color + transmittance * sample_opacity * sample_color
    new_opacity = prev_opacity + transmittance * sample_opacity
    
    # 6. Update ray position texture for next pass (G: Implementation detail)
    # The shader must write new_pos to a texture bound for the next pass.
    write_to_texture(tex_ray_pos, pixel_coord, new_pos)
    
    return new_color, new_opacity

# Pseudocode for the Termination Check Shader
def termination_check_shader(pixel_coord):
    accumulated_opacity = sample_2d(tex_accum_opacity, pixel_coord)
    
    # Check threshold or iso-surface hit
    threshold_exceeded = accumulated_opacity > 0.95 # Example threshold
    iso_hit = check_iso_surface_hit(pixel_coord) # Implementation specific
    
    if threshold_exceeded or iso_hit:
        # Mark as terminated by setting depth to max
        return depth_replace(MAX_DEPTH)
    else:
        # Mark as active by setting depth to min (or 0)
        return depth_replace(0.0)
```

**Parameters:**
*   **Step Size $\Delta t$:** Not explicitly defined in sources, but implied to be fixed per pass [S1, unofficial].
*   **Opacity Threshold:** Typically 0.95 or similar, used to terminate rays [S1, unofficial].
*   **Number of Passes:** Fixed number of main traversal passes [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Dependent Texture Fetches:** Hardware limitations (e.g., ATI 9700) restrict the number of dependent texture fetches, requiring careful management of texture bindings [S1, unofficial].
*   **Precision:** Floating-point textures are required to store negative values and high-precision accumulation [S1, unofficial].
*   **Early Z-Test:** The early z-test must be enabled and configured correctly (GREATER) to discard terminated fragments efficiently [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the fixed number of ray steps per pass [S1, unofficial].
*   **Memory Complexity:** Requires multiple 2D textures for accumulation, ray direction, and ray position, plus the 3D volume texture [S1, unofficial].
*   **Measured Performance:** Up to a factor of 3 speedup on ATI 9700 graphics card for typical volumetric data sets compared to CPU-based methods [S1, unofficial].
*   **Strengths:** Exploits hardware parallelism; efficient empty space skipping and early ray termination via early z-test; flexible multi-pass architecture [S1, unofficial].
*   **Limitations:** Limited by hardware features available at the time (DirectX 9 level); dependent texture fetch limits; requires multiple passes for a single frame [S1, unofficial].
*   **When to use:** Real-time volume rendering on older programmable GPUs where 3D texture hardware acceleration is not available or insufficient [S1, unofficial].
*   **When not to use:** Modern GPUs with advanced 3D texture support and compute shaders, which can perform ray casting in fewer passes or single-pass [S1, unofficial].

## Background
The method was proposed in 2003 by researchers at the Technical University of Munich (TUM) [S1, unofficial]. It was designed for DirectX 9-level hardware, specifically the ATI 9700 graphics card, which supported Pixel Shader 2.0, texture render targets, and depth replace [S1, unofficial]. The work addressed the challenge of real-time volume rendering for large scalar fields by leveraging the parallelism of fragment processors and efficient communication between rendering passes [S1, unofficial].
