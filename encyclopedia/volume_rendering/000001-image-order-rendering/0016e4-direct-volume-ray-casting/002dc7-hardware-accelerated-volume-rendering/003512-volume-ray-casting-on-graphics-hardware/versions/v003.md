# Volume Ray-Casting on Graphics Hardware

Also called: Stream model for volumetric ray-casting

## Overview
This method implements direct volume ray casting on programmable graphics hardware (specifically DirectX 9-level architectures like the ATI 9700) using a multi-pass stream model [S1, unofficial]. It solves the performance bottleneck of CPU-based ray casting by exploiting the intrinsic parallelism of fragment processors and efficient inter-pass communication via texture render targets [S1, unofficial]. It is distinguished from sibling methods by its reliance on the **early z-test** and **depth replace** capabilities to implement early ray termination and empty-space skipping, rather than relying solely on 3D texture sampling or geometry-based resampling [S1, unofficial].

## How it works
**Inputs:**
*   Volumetric scalar data (accessed via 2D texture slices or 3D textures).
*   Ray direction vectors for each pixel, pre-computed and stored in 2D textures.
*   Accumulated color and opacity buffers, stored in 2D texture render targets.
*   Threshold values for early termination.

**Outputs:**
*   Final 2D image (color and opacity) stored in a texture render target or frame buffer.

**Data Structures:**
1.  **Ray Direction Textures (2):** Two 2D textures storing the $(u, v)$ components of the ray direction in local texture space for every pixel.
2.  **Accumulation Textures (2):** Two 2D textures (floating-point format supported) storing the accumulated color $C'$ and accumulated opacity $\alpha'$ for each pixel. These serve as the render target for each pass.
3.  **Iso-surface Intersection Texture (Optional):** A 2D texture storing local texture coordinates of iso-surface intersections, used in a final pass to restrict shading computations.

**Parameters:**
*   **Opacity Threshold:** A scalar value determining when ray casting terminates. Not given in the sources.
*   **Number of Passes:** Fixed number of rendering passes per ray. Not given in the sources.
*   **Hardware:** ATI 9700 graphics card with Pixel Shader 2.0 API [S1, unofficial].

**Algorithm Steps:**

1.  **Pre-computation:** For each pixel, compute the direction of the ray of sight through the volume in local texture coordinates. Store these directions in two dedicated 2D textures [S1, unofficial].

2.  **Multi-Pass Ray Casting Loop:**
    For each of the fixed number of main passes:
    a.  **Fragment Shader Execution:** For each fragment (pixel), retrieve the ray direction from the direction textures. Perform a single step of ray traversal:
        *   Sample the volume data at the current ray position.
        *   Apply the transfer function to obtain density $\rho$ and color $C$.
        *   Update accumulated color and opacity using the standard over operator:
            $$
            C'_{new} = C'_{old} + (1 - \alpha'_{old}) \cdot \alpha \cdot C
            $$
            $$
            \alpha'_{new} = \alpha'_{old} + (1 - \alpha'_{old}) \cdot \alpha
            $$
            where $\alpha$ is derived from $\rho$ [S1, S12, S43, S50, unofficial].
        *   Write the new $C'_{new}$ and $\alpha'_{new}$ to the accumulation texture render target.

    b.  **Termination Test Pass:** Between main passes, execute an additional pass to test for termination conditions:
        *   Read the accumulated opacity $\alpha'$ from the accumulation texture.
        *   Check if $\alpha'$ exceeds the specified threshold OR if an iso-surface intersection has been detected (if applicable).
        *   **Depth Replace Logic:**
            *   If the test succeeds (termination condition met), set the fragment's depth value ($z$) to the maximum possible depth value.
            *   If the test fails, set the fragment's depth value ($z$) to zero.
        *   **Early Z-Test Configuration:** Set the depth test function to `GREATER`.
            *   Because fragments with termination conditions have $z = \text{max}$, they will pass the `GREATER` test against the current depth buffer (assuming standard depth initialization).
            *   Fragments without termination conditions have $z = 0$. If the depth buffer contains values $> 0$ (from previous steps or other geometry), these fragments will fail the `GREATER` test and be discarded.
            *   *Correction/Clarification based on source logic:* The source states: "if the z-test is set to GREATER, all consecutive main passes will be discarded due to the early z-test." This implies that once a fragment terminates, it is marked with max depth. In subsequent passes, the early z-test (which happens before shader execution) checks if the fragment's depth is greater than the depth buffer. If the fragment was marked with max depth, it passes. If it was marked with 0, it likely fails if the depth buffer is non-zero, or the logic relies on the fact that terminated fragments are effectively "done" and their depth state prevents re-processing or allows skipping. The key mechanism is that the **early z-test** is enabled and used to skip shader execution for fragments that have already terminated or are in empty space, based on the depth value written in the previous test pass [S1, unofficial].

3.  **Iso-surface Refinement (Optional):** If an iso-surface is hit, the coordinates of the intersection are written to a 2D texture. A final pass uses this texture to perform gradient-based shading only at these specific points, reducing computation [S1, unofficial].

**Pseudocode:**

```python
# Pre-computation
ray_direction_u = compute_ray_directions(volume_bounds, camera)
ray_direction_v = compute_ray_directions(volume_bounds, camera)

# Initialize accumulation textures with 0
accum_color = Texture2D(width, height, format=FLOAT)
accum_opacity = Texture2D(width, height, format=FLOAT)
accum_color.clear(0.0)
accum_opacity.clear(0.0)

# Main Ray Casting Loop
for pass_index in range(num_passes):
    # 1. Main Ray Casting Pass
    render_target = accum_color, accum_opacity
    set_depth_test(NEVER) # Disable depth test during accumulation to allow overwriting
    for each fragment (x, y):
        u = ray_direction_u[x, y]
        v = ray_direction_v[x, y]
        current_pos = get_current_ray_position(pass_index, u, v)
        
        # Sample volume
        density = sample_volume(current_pos)
        alpha, color = apply_transfer_function(density)
        
        # Composite
        old_c = accum_color[x, y]
        old_a = accum_opacity[x, y]
        new_c = old_c + (1.0 - old_a) * alpha * color
        new_a = old_a + (1.0 - old_a) * alpha
        
        # Write to render target
        accum_color[x, y] = new_c
        accum_opacity[x, y] = new_a

    # 2. Termination Test Pass
    # This pass determines if the ray should continue in the next main pass
    set_depth_test(GREATER) # Critical for early z-test skipping
    for each fragment (x, y):
        current_alpha = accum_opacity[x, y]
        
        # Check termination conditions
        terminated = (current_alpha > opacity_threshold) or iso_surface_hit(x, y)
        
        if terminated:
            # Mark as terminated by setting depth to max
            # This fragment will pass the GREATER test in subsequent passes if depth buffer is lower,
            # or the logic relies on the early z-test skipping shader execution for non-terminated fragments.
            # Source says: "If the test succeeds, the z-value is set to the maximum value"
            set_depth_value(MAX_DEPTH)
        else:
            # Mark as active/continue by setting depth to 0
            set_depth_value(0.0)
            
        # Note: The early z-test happens BEFORE the shader. 
        # The source implies that the depth value written here affects the NEXT pass's early z-test.
        # If a fragment is terminated (z=max), it might be processed or skipped depending on depth buffer state.
        # The key is that the early z-test avoids executing the expensive ray casting shader for fragments 
        # that have already terminated or are in empty space, based on the depth state set in this pass.
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point textures are required to store negative values and high dynamic range accumulation. Not given in the sources.
*   **Dependent Texture Fetches:** Limited number of dependent texture fetches on ATI hardware restricts the complexity of ray traversal logic within a single pass [S1, unofficial].
*   **Early Z-Test Dependency:** The method relies heavily on the early z-test being enabled and functioning correctly with the depth replace feature. If the hardware does not support early z-test with depth replace, the optimization fails [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the fixed number of passes. Early ray termination reduces the effective number of samples per ray for opaque regions.
*   **Memory Complexity:** Requires storage for ray direction textures, accumulation textures, and potentially iso-surface intersection textures. Memory usage is proportional to screen resolution.
*   **Measured Performance:** Performance gains up to a factor of 3 for typical renditions of volumetric data sets on the ATI 9700 graphics card [S1, unofficial].
*   **Strengths:** Efficient use of fragment parallelism; effective early ray termination and empty-space skipping via hardware early z-test; simple implementation on DirectX 9-level hardware.
*   **Limitations:** Limited by the number of texture fetches and dependent texture fetches; fixed number of passes may lead to over-sampling in empty space or under-sampling in dense regions if not adaptive; hardware-specific (ATI 9700, Pixel Shader 2.0) [S1, unofficial].
*   **When to use:** Real-time volume rendering on older programmable graphics hardware (DirectX 9 era) where 3D texture sampling is inefficient or unavailable.
*   **When not to use:** Modern GPUs with advanced ray tracing hardware or more flexible texture fetch capabilities; scenes requiring adaptive step sizes or complex shading per sample.

## Background
The method was proposed in 2003 by researchers at the Technical University of Munich (TUM) as part of their work on acceleration techniques for GPU-based volume rendering [S1, unofficial]. It was designed to leverage the emerging programmable graphics hardware (specifically the ATI 9700 and Pixel Shader 2.0 API) to achieve real-time performance for large volumetric data sets, which was previously challenging for CPUs [S1, unofficial]. The approach builds on the observation that modern graphics chips offer intrinsic parallelism and efficient communication mechanisms (like texture render targets) that can be exploited for volume ray casting [S1, unofficial].
