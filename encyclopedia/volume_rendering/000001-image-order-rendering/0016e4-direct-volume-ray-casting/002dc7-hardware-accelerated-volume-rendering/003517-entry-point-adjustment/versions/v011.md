# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated technique for direct volume ray casting that enables the camera to move inside the volume's bounding box without the view disappearing or clipping artifacts [S1, unofficial]. It solves the problem of maintaining continuous visibility when the ray origin exceeds the volume's back face by dynamically shifting the ray's entry point forward along the ray direction based on a scale coefficient [S1, unofficial]. Unlike standard ray casting which assumes the camera is outside the volume, this method allows for a "flowing through" experience [S1, unofficial].

## How it works
The method operates in a two-pass rendering pipeline using framebuffer objects (FBOs) and fragment shaders [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** A 3D volume texture (`VolumeTex`), a 1D transfer function texture (`TransferFunc`), the volume's front and back face geometry, and uniform parameters (`StepSize`, `AlphaReduce`, `scaleCoeff`, `ScreenSize`) [S1, unofficial].
*   **Output:** A 2D color buffer containing the final rendered image [S1, unofficial].

**Data Structures:**
1.  **ExitPoints Texture:** A 2D texture storing the 3D world coordinates of the exit points for rays passing through the back face of the volume. Each pixel in this texture corresponds to a screen coordinate and stores the `xyz` position of the exit point [S1, unofficial].
2.  **VolumeTex:** A 3D texture storing the scalar field data [S1, unofficial].
3.  **TransferFunc:** A 1D texture mapping scalar values to RGBA color and opacity [S1, unofficial].

**Numbered Steps:**

1.  **Render Back Face (Exit Point Calculation):**
    *   Bind an FBO with the `ExitPoints` 2D texture as the color attachment.
    *   Render the back face of the volume's axis-aligned bounding box (AABB).
    *   In the vertex shader, pass the world-space position of the back face vertices to the fragment shader.
    *   In the fragment shader, output the vertex position as the color. This stores the exit coordinates for every pixel where a ray intersects the back face [S1, unofficial].

2.  **Render Front Face (Ray Marching):**
    *   Unbind the FBO and bind the default framebuffer.
    *   Render the front face of the volume's AABB.
    *   In the vertex shader, pass the world-space position of the front face vertices as `EntryPoint` and the screen coordinates (normalized by `ScreenSize`) to the fragment shader [S1, unofficial].

3.  **Fragment Shader Execution:**
    *   **Retrieve Exit Point:** Sample the `ExitPoints` texture using the normalized screen coordinates to get the `exitPoint` [S1, unofficial].
    *   **Discard Check:** If `EntryPoint` equals `exitPoint` (indicating the ray does not pass through the volume or the camera is positioned such that no back-face intersection exists for this pixel), discard the fragment [S1, unofficial].
    *   **Calculate Ray Direction:** Compute `rayDirection = normalize(exitPoint - EntryPoint)` [S1, unofficial].
    *   **Adjust Entry Point (Flowing Through):**
        *   If `scaleCoeff >= 2.7`, calculate a temporary shift factor:
            $$ tmp = \min((scaleCoeff - 2.7) \times 0.1, 1.0) $$
        *   Shift the entry point forward:
            $$ adjustedEntryPoint = EntryPoint + tmp \times (exitPoint - EntryPoint) $$
        *   If `scaleCoeff < 2.7`, use the original `EntryPoint` [S1, unofficial].
    *   **Initialize Variables:**
        *   Set `currentPosition` to `adjustedEntryPoint`.
        *   Initialize `colorSum` (accumulated color) to $(0, 0, 0, 0)$.
        *   Calculate `Step = rayDirection * StepSize`.
        *   Calculate `stepLength = length(Step)`.
        *   Calculate total ray length `Length = length(exitPoint - adjustedEntryPoint)` [S1, unofficial].
    *   **Ray Marching Loop:**
        *   Iterate up to 16,000 times (or until termination conditions are met) [S1, unofficial]:
            1.  Sample the volume: `value = texture(VolumeTex, currentPosition.xyz)`.
            2.  Apply Transfer Function: `color = texture(TransferFunc, value.a)`.
            3.  Adjust Opacity: `color.a *= AlphaReduce`.
            4.  Front-to-Back Blending:
                $$ colorSum = (1.0 - colorSum.a) \times color + colorSum $$
                *(Note: `color.rgb` is multiplied by `color.a` before addition in the source code)* [S1, unofficial].
            5.  Accumulate Length: `LengthSum += stepLength`.
            6.  **Termination Conditions:**
                *   If `colorSum.a >= 0.95`, break loop.
                *   If `LengthSum >= Length`, break loop.
            7.  Advance Position: `currentPosition.xyz += Step` [S1, unofficial].
    *   **Output:** Write `colorSum` to the framebuffer [S1, unofficial].

**Pseudocode:**

```python
def fragment_shader(entry_point, exit_point_coord, screen_size, scale_coeff, step_size, alpha_reduce):
    # 1. Retrieve Exit Point from 2D texture
    # Note: In implementation, ExitPoints is a sampler2D. 
    # Here we assume the function returns the sampled vec3.
    exit_point = sample_exit_points_texture(exit_point_coord / screen_size)
    
    # 2. Discard if no valid ray through volume
    if entry_point == exit_point:
        discard_fragment()
        
    # 3. Calculate Ray Direction
    ray_direction = normalize(exit_point - entry_point)
    
    # 4. Adjust Entry Point for "Flowing Through" effect
    if scale_coeff >= 2.7:
        tmp = min((scale_coeff - 2.7) * 0.1, 1.0)
        current_entry = entry_point + tmp * (exit_point - entry_point)
    else:
        current_entry = entry_point
        
    # 5. Initialize Variables
    current_position = current_entry
    color_sum = vec4(0.0, 0.0, 0.0, 0.0)
    
    step_vector = ray_direction * step_size
    step_length = length(step_vector)
    total_length = length(exit_point - current_entry)
    accumulated_length = 0.0
    
    # 6. Ray Marching Loop
    for i in range(16000):
        # Sample Volume
        value = sample_volume_texture(current_position)
        
        # Apply Transfer Function
        color = sample_transfer_function(value.a)
        
        # Reduce Alpha
        color.a *= alpha_reduce
        
        # Front-to-Back Blending
        # Source code: color.rgb *= color.a; colorSum = (1.0 - colorSum.a) * color + colorSum;
        color.rgb *= color.a
        color_sum = (1.0 - color_sum.a) * color + color_sum
        
        # Accumulate Length
        accumulated_length += step_length
        
        # Termination Checks
        if color_sum.a >= 0.95:
            break
        if accumulated_length >= total_length:
            break
            
        # Advance Position
        current_position += step_vector
        
    return color_sum
```

**Parameters:**
*   `StepSize`: Uniform float controlling the distance between samples along the ray [S1, unofficial].
*   `AlphaReduce`: Uniform float multiplier applied to alpha to increase transparency [S1, unofficial].
*   `scaleCoeff`: Custom uniform representing the scaling factor of the volume, used to determine if the camera is inside [S1, unofficial].
*   `ScreenSize`: Uniform vec2 representing the resolution of the viewport [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The comparison `EntryPoint == exitPoint` relies on exact equality. In floating-point arithmetic, this may fail due to precision errors if the camera is exactly on the boundary. [G] A small epsilon threshold should be used in practice (e.g., `distance(EntryPoint, exitPoint) < epsilon`).
*   **Termination:** The loop breaks at `colorSum.a >= 0.95`. This is a heuristic threshold. If the volume is very transparent, the loop may run the full 16,000 iterations, impacting performance.
*   **Boundary:** The method assumes the volume is enclosed in a simple AABB. Complex bounding volumes require different exit point calculations.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray ($N$) and the number of pixels ($P$). $O(P \times N)$. The maximum iterations are capped at 16,000 [S1, unofficial].
*   **Memory Complexity:** Requires storage for the `ExitPoints` 2D texture, which is $O(W \times H)$ where $W, H$ are screen dimensions, plus the standard 3D volume texture [S1, unofficial].
*   **Performance:** The two-pass approach adds overhead due to FBO rendering and texture sampling. However, it avoids the need for complex ray-volume intersection logic in the main ray-marching shader for the entry point, simplifying the fragment shader [S1, unofficial].
*   **Strengths:** Enables seamless camera movement inside the volume ("flowing through") without clipping artifacts [S1, unofficial]. Simple to implement on standard GPU hardware using FBOs [S1, unofficial].
*   **Limitations:** The "flowing through" effect is controlled by a heuristic (`scaleCoeff >= 2.7`) which may not produce physically accurate results for all camera positions [S1, unofficial]. The fixed iteration limit (16,000) may be excessive for simple volumes or insufficient for very large, detailed volumes if the step size is small [S1, unofficial].
*   **When to use:** When the application requires the user to navigate inside the volume data (e.g., medical visualization, virtual reality exploration) and hardware acceleration is available [S1, unofficial].
*   **When not to use:** When the camera is strictly outside the volume, standard ray casting is more efficient. When precise physical accuracy of the entry point is required over the heuristic "flowing" effect [S1, unofficial].
