# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated volume rendering technique that enables the camera to move inside the volume's bounding box without the view disappearing or clipping artifacts. It solves the problem of standard ray casting failing when the ray origin exceeds the back face of the volume by dynamically shifting the ray entry point forward along the ray direction based on a scale coefficient [S1, unofficial]. Unlike methods that rely on plane clipping to handle visibility, this approach maintains continuous rendering by adjusting the start of the ray march [S1, unofficial].

## How it works
The method operates in two rendering passes: a back-face rasterization pass to determine exit points, and a front-face rasterization pass to perform ray marching with adjusted entry points.

### Inputs and Outputs
*   **Inputs**:
    *   `VolumeTex`: 3D texture containing scalar volume data.
    *   `TransferFunc`: 1D texture mapping scalar values to color and opacity.
    *   `ExitPoints`: 2D texture storing exit coordinates of rays passing through the back face.
    *   `ScreenSize`: Uniform vector $(W, H)$ representing the resolution of the viewport.
    *   `StepSize`: Uniform float controlling the distance between samples along the ray.
    *   `AlphaReduce`: Uniform float multiplier applied to alpha to increase transparency.
    *   `scaleCoeff`: Uniform float representing the scaling factor of the volume, used to determine if the camera is inside.
*   **Outputs**:
    *   `FragColor`: The final accumulated color and opacity for each pixel.

### Data Structures
1.  **ExitPoints Texture**: A 2D texture where each texel stores the 3D world coordinates $(x, y, z)$ of the ray's exit point from the volume's back face. The coordinates are stored as RGB components of a `vec3` or `vec4` (with $w=0$).
2.  **Volume Texture**: A 3D texture (`sampler3D`) containing the scalar field $V(\mathbf{p})$.
3.  **Transfer Function**: A 1D texture (`sampler1D`) mapping the alpha channel of the sampled scalar value to a `vec4` color.

### Steps
1.  **Back-Face Pass**: Render the back face of the volume's bounding box into a framebuffer object bound to the `ExitPoints` 2D texture. The color of each vertex is set to its world position, effectively storing the exit coordinates for rays passing through that pixel.
2.  **Front-Face Pass**: Render the front face of the volume's bounding box to the screen. Pass the entry point (camera position or front-face vertex position) to the fragment shader.
3.  **Retrieve Exit Point**: In the fragment shader, retrieve the exit point for the current pixel from the `ExitPoints` texture using normalized screen coordinates:
    $$ \mathbf{p}_{exit} = \text{texture}(\text{ExitPoints}, \frac{\mathbf{c}_{screen}}{\mathbf{S}_{size}}).xyz $$
    where $\mathbf{c}_{screen}$ is `gl_FragCoord` and $\mathbf{S}_{size}$ is `ScreenSize`.
4.  **Discard Invalid Rays**: If the entry point equals the exit point, the ray does not pass through the volume (or the camera is outside in a way that yields no intersection). Discard the fragment.
5.  **Calculate Ray Direction**: Compute the normalized ray direction:
    $$ \mathbf{d} = \frac{\mathbf{p}_{exit} - \mathbf{p}_{entry}}{\|\mathbf{p}_{exit} - \mathbf{p}_{entry}\|} $$
6.  **Adjust Entry Point**: To handle the "flowing through" effect when the camera is inside the volume:
    *   If `scaleCoeff` $\ge 2.7$:
        $$ \tau = \min((\text{scaleCoeff} - 2.7) \times 0.1, 1.0) $$
        $$ \mathbf{p}_{entry}' = \mathbf{p}_{entry} + \tau (\mathbf{p}_{exit} - \mathbf{p}_{entry}) $$
    *   Else:
        $$ \mathbf{p}_{entry}' = \mathbf{p}_{entry} $$
7.  **Initialize Ray Marching**:
    *   Set current position $\mathbf{p}_{curr} = \mathbf{p}_{entry}'$.
    *   Initialize accumulated color `colorSum` = $(0, 0, 0, 0)$.
    *   Calculate step vector $\mathbf{s} = \mathbf{d} \times \text{StepSize}$.
    *   Calculate total ray length $L = \|\mathbf{p}_{exit} - \mathbf{p}_{entry}\|$.
    *   Initialize accumulated length $L_{sum} = 0$.
8.  **Ray March Loop**: Iterate up to 16,000 times (or until termination conditions are met):
    *   Sample volume: $v = \text{texture}(\text{VolumeTex}, \mathbf{p}_{curr})$.
    *   Sample transfer function: $c = \text{texture}(\text{TransferFunc}, v.a)$.
    *   Reduce alpha: $c.a = c.a \times \text{AlphaReduce}$.
    *   Front-to-back compositing:
        $$ \mathbf{C}_{rgb} = c.rgb \times c.a $$
        $$ \text{colorSum} = (1.0 - \text{colorSum}.a) \times ( \mathbf{C}_{rgb}, c.a ) + \text{colorSum} $$
    *   Update length: $L_{sum} += \|\mathbf{s}\|$.
    *   Advance position: $\mathbf{p}_{curr} += \mathbf{s}$.
    *   **Early Ray Termination**: If $\text{colorSum}.a \ge 0.95$, break.
    *   **Boundary Check**: If $L_{sum} \ge L$, break.
9.  **Output**: Write `colorSum` to the framebuffer.

### Pseudocode
```python
# Fragment Shader Logic
def fragment_shader(entry_point: vec3, exit_point_coord: vec4, 
                    exit_points_tex: sampler2D, volume_tex: sampler3D, 
                    transfer_func: sampler1D, screen_size: vec2, 
                    step_size: float, alpha_reduce: float, scale_coeff: float) -> vec4:
    
    # 1. Retrieve exit point from texture
    normalized_coord = exit_point_coord.xy / screen_size
    exit_point = texture(exit_points_tex, normalized_coord).xyz
    
    # 2. Discard if no intersection
    if entry_point == exit_point:
        discard()
        
    # 3. Calculate ray direction
    ray_direction = normalize(exit_point - entry_point)
    
    # 4. Adjust entry point for inside-volume rendering
    if scale_coeff >= 2.7:
        tmp = min((scale_coeff - 2.7) * 0.1, 1.0)
        adjusted_entry = entry_point + tmp * (exit_point - entry_point)
    else:
        adjusted_entry = entry_point
        
    # 5. Initialize variables
    current_pos = adjusted_entry
    color_sum = vec4(0.0, 0.0, 0.0, 0.0)
    step_vector = ray_direction * step_size
    step_length = length(step_vector)
    total_length = length(exit_point - entry_point)
    accumulated_length = 0.0
    
    # 6. Ray marching loop
    for i in range(16000):
        # Sample volume and transfer function
        value = texture(volume_tex, current_pos)
        color = texture(transfer_func, value.a)
        
        # Reduce alpha
        color.a *= alpha_reduce
        
        # Front-to-back blending
        color.rgb *= color.a
        color_sum = (1.0 - color_sum.a) * color + color_sum
        
        # Update length
        accumulated_length += step_length
        
        # Early ray termination
        if color_sum.a >= 0.95:
            break
            
        # Advance position
        current_pos += step_vector
        
        # Boundary check
        if accumulated_length >= total_length:
            break
            
    return color_sum
```

### Parameters
*   `StepSize`: Controls sample density. Smaller values increase quality but reduce performance.
*   `AlphaReduce`: Scales opacity to prevent premature occlusion when inside the volume.
*   `scaleCoeff`: Threshold for entering "inside-volume" mode. Values $\ge 2.7$ trigger entry point adjustment.

### Edge Cases and Pitfalls
*   **Precision**: Comparing `entry_point == exit_point` may fail due to floating-point inaccuracies. A tolerance check is recommended in production [G].
*   **Degenerate Input**: If the camera is exactly on the boundary, the ray length may be zero, causing division by zero in normalization. The discard step handles this if equality holds exactly.
*   **Performance**: The loop limit of 16,000 is arbitrary and may be excessive for simple volumes. Early ray termination is crucial for performance [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N)$ per pixel, where $N$ is the number of samples along the ray, bounded by the loop limit and early termination.
*   **Memory Complexity**: $O(W \times H)$ for the `ExitPoints` texture, where $W, H$ are screen dimensions.
*   **Strengths**: Allows seamless camera movement through the volume without clipping artifacts. Simple to implement on standard GPU pipelines.
*   **Limitations**: The "flowing through" effect is heuristic and may not perfectly simulate being surrounded by the volume. Performance depends heavily on `StepSize` and volume density.
*   **When to Use**: When the application requires the user to fly through or inside volumetric data (e.g., medical visualization, scientific exploration).
*   **When Not to Use**: When strict physical accuracy of ray origins is required, or when the volume is sparse and other acceleration structures (like [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md)) are more efficient.

## Background
This technique was discussed in the context of OpenGL/GLSL volume rendering implementations, specifically addressing the problem of "flowing through the volume" where the camera moves inside the bounding box [S1, unofficial]. It was presented as a solution to the disappearance of the view when the camera position exceeds the back face of the volume, contrasting with plane clipping methods [S1, unofficial].
