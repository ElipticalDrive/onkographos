# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated volume rendering technique that enables the camera to move inside the volume's bounding box without the view disappearing or clipping artifacts. It solves the problem of ray termination when the camera position exceeds the front face of the volume by dynamically shifting the ray's entry point forward along the ray direction based on a scale coefficient [S1, unofficial]. Unlike standard ray casting where the entry point is fixed at the front face, this method allows for a "flowing through" effect, distinguishing it from sibling methods like Back-face rasterized volume rendering which rely on static front-face rasterization [S1, unofficial].

## How it works
The method operates in two rendering passes, leveraging the shared principles of Hardware-Accelerated Volume Rendering.

**Inputs and Outputs:**
*   **Inputs:** 3D volume texture (`VolumeTex`), 1D transfer function texture (`TransferFunc`), screen resolution (`ScreenSize`), step size (`StepSize`), alpha reduction factor (`AlphaReduce`), and a scaling coefficient (`scaleCoeff`).
*   **Outputs:** Final color buffer (`FragColor`).

**Data Structures:**
1.  **ExitPoints Texture:** A 2D texture (`sampler2D`) storing the 3D exit coordinates of rays passing through the back face of the volume bounding box. Each pixel stores a `vec3` (XYZ) representing the exit point in world/object space.
2.  **VolumeTex:** A 3D texture (`sampler3D`) storing the scalar field $V(\mathbf{x})$.
3.  **TransferFunc:** A 1D texture (`sampler1D`) mapping scalar values to color and opacity.

**Numbered Steps:**

1.  **Back-Face Pass:** Render the back face of the volume's bounding box into a framebuffer object (FBO) attached to the `ExitPoints` 2D texture. The fragment shader outputs the world-space coordinates of the intersection point. This stores the exit point for every pixel that will later be rendered from the front face.
2.  **Front-Face Pass:** Render the front face of the volume's bounding box to the screen. The vertex shader passes the entry point (`EntryPoint`) and the screen coordinates to the fragment shader.
3.  **Retrieve Exit Point:** In the fragment shader, retrieve the exit point from the `ExitPoints` texture using the normalized screen coordinates:
    $$ \mathbf{p}_{exit} = \text{texture}(\text{ExitPoints}, \frac{\mathbf{gl\_FragCoord.st}}{\text{ScreenSize}}).xyz $$
4.  **Discard Invalid Rays:** If the entry point equals the exit point ($\mathbf{p}_{entry} == \mathbf{p}_{exit}$), the ray does not pass through the volume (or the camera is outside in a way that yields no intersection). Discard the fragment. [S1, unofficial]
5.  **Calculate Ray Direction:** Compute the normalized ray direction vector:
    $$ \mathbf{d} = \text{normalize}(\mathbf{p}_{exit} - \mathbf{p}_{entry}) $$
6.  **Adjust Entry Point (Flowing Through):** To handle the case where the camera is inside the volume, adjust the entry point based on `scaleCoeff`.
    *   If `scaleCoeff` $\ge 2.7$:
        $$ \tau = \min((\text{scaleCoeff} - 2.7) \times 0.1, 1.0) $$
        $$ \mathbf{p}_{adjusted} = \mathbf{p}_{entry} + \tau (\mathbf{p}_{exit} - \mathbf{p}_{entry}) $$
    *   If `scaleCoeff` $< 2.7$:
        $$ \mathbf{p}_{adjusted} = \mathbf{p}_{entry} $$
    *   Use $\mathbf{p}_{adjusted}$ as the starting position for ray marching. [S1, unofficial]
7.  **Initialize Variables:**
    *   Current position: $\mathbf{p}_{curr} = \mathbf{p}_{adjusted}$
    *   Accumulated color: $C_{sum} = (0, 0, 0, 0)$
    *   Step vector: $\mathbf{s} = \mathbf{d} \times \text{StepSize}$
    *   Total ray length: $L = \|\mathbf{p}_{exit} - \mathbf{p}_{entry}\|$
    *   Accumulated length: $L_{acc} = 0$
8.  **Ray Marching Loop:** Iterate up to 16,000 times (or until termination conditions are met):
    a.  Sample the volume: $v = \text{texture}(\text{VolumeTex}, \mathbf{p}_{curr})$
    b.  Sample transfer function: $c = \text{texture}(\text{TransferFunc}, v.a)$
    c.  Apply alpha reduction: $c.a = c.a \times \text{AlphaReduce}$
    d.  Front-to-back compositing:
        $$ C_{sum} = C_{sum} + (1 - C_{sum}.a) \times (c.rgb \times c.a, c.a) $$
        *(Note: The source code implements this as `colorSum = (1.0f - colorSum.a) * color + colorSum` where `color.rgb *= color.a` is done prior. This is equivalent to standard over-operator if `color` holds the pre-multiplied color.)*
    e.  Update length: $L_{acc} += \|\mathbf{s}\|$
    f.  Advance position: $\mathbf{p}_{curr} += \mathbf{s}$
    g.  **Early Ray Termination:** If $C_{sum}.a \ge 0.95$, break loop.
    h.  **Boundary Check:** If $L_{acc} \ge L$, break loop.
9.  **Output:** Write $C_{sum}$ to `FragColor`.

**Pseudocode:**

```python
# Fragment Shader Logic
def fragment_shader(entry_point: vec3, exit_point_coord: vec4, 
                    exit_points_tex: sampler2D, volume_tex: sampler3D, 
                    transfer_func: sampler1D, screen_size: vec2,
                    step_size: float, alpha_reduce: float, scale_coeff: float) -> vec4:
    
    # 1. Retrieve exit point from texture
    uv = exit_point_coord.xy / screen_size
    exit_point = texture(exit_points_tex, uv).xyz
    
    # 2. Check for valid intersection
    if entry_point == exit_point:
        discard_fragment()
        
    # 3. Calculate ray direction
    ray_dir = normalize(exit_point - entry_point)
    
    # 4. Adjust entry point for "flowing through" effect
    if scale_coeff >= 2.7:
        tmp = min((scale_coeff - 2.7) * 0.1, 1.0)
        current_pos = entry_point + tmp * (exit_point - entry_point)
    else:
        current_pos = entry_point
        
    # 5. Initialize compositing variables
    color_sum = vec4(0.0, 0.0, 0.0, 0.0)
    step_vec = ray_dir * step_size
    step_length = length(step_vec)
    total_length = length(exit_point - entry_point)
    accumulated_length = 0.0
    
    # 6. Ray marching loop
    for i in range(16000):
        # Sample volume and transfer function
        value = texture(volume_tex, current_pos)
        color = texture(transfer_func, value.a)
        
        # Apply alpha reduction
        color.a *= alpha_reduce
        
        # Pre-multiply color RGB by alpha
        color.rgb *= color.a
        
        # Front-to-back blending
        # C' = C' + (1 - alpha') * C_sample
        color_sum = color_sum + (1.0 - color_sum.a) * color
        
        # Update length
        accumulated_length += step_length
        
        # Early Ray Termination
        if color_sum.a >= 0.95:
            break
            
        # Advance position
        current_pos += step_vec
        
        # Boundary check
        if accumulated_length >= total_length:
            break
            
    return color_sum
```

**Parameters:**
*   `StepSize`: Uniform float controlling the distance between samples. Typical values depend on volume resolution and desired quality.
*   `AlphaReduce`: Uniform float multiplier for opacity to increase transparency.
*   `scaleCoeff`: Custom uniform representing the scaling factor of the volume, used to determine camera proximity/inside status. Threshold for adjustment is 2.7 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision in texture lookups for `ExitPoints` may cause slight misalignments if the back-face and front-face renderings use different projection matrices or if the FBO resolution differs from the screen resolution.
*   **Degenerate Input:** If the ray is tangent to the volume or the camera is positioned such that the entry and exit points are identical, the ray is discarded. This prevents rendering background pixels as black or undefined.
*   **Clipping Alternative:** The source notes that Plane Clipping is an alternative method to handle visibility through the volume, suggesting Entry Point Adjustment is one specific heuristic among others [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray ($N$) and the number of pixels ($P$). $O(P \times N)$. The loop limit is fixed at 16,000, but Early Ray Termination (ERT) often reduces the average $N$.
*   **Memory Complexity:** Requires storage for the `ExitPoints` 2D texture ($W \times H \times 3$ floats) and the standard volume/transfer function textures.
*   **Performance:** Performance is comparable to standard ray casting but incurs the overhead of an additional render pass (back-face rendering) and texture lookup for the exit point. The "flowing through" logic adds minimal arithmetic cost.
*   **Strengths:** Enables seamless camera movement inside the volume without complex ray-volume intersection math in the fragment shader. Simple to implement on existing hardware-accelerated pipelines.
*   **Limitations:** The adjustment logic (`scaleCoeff` threshold) is heuristic and may not produce a physically accurate "inside" view for all volume shapes or camera positions. It relies on the bounding box approximation.
*   **When to use:** When the application requires the user to fly through or inside the volume data, and a simple bounding-box-based heuristic is sufficient.
*   **When not to use:** When precise ray-volume intersection is required for complex, non-convex, or non-bounding-box volumes, or when the "flowing" effect artifacts are unacceptable.

## Background
This technique originates from community implementations of GLSL-based volume rendering, specifically addressing the limitation of standard ray casting where the camera cannot penetrate the front face of the volume. It was popularized in online forums and code repositories (e.g., GitHub, Stack Overflow) as a solution for "flowing through" volumes [S1, unofficial]. It is not derived from a single peer-reviewed academic paper but is a practical engineering solution developed by graphics programmers to extend hardware-accelerated ray casting capabilities.
