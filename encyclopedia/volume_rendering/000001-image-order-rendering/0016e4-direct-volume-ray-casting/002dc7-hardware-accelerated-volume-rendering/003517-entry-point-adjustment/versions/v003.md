# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated technique for direct volume ray casting that enables the camera to move inside the volume's bounding box without the view disappearing or clipping artifacts [S1, unofficial]. It solves the problem of ray termination when the camera position exceeds the front face of the volume by dynamically shifting the ray's starting position forward along the ray direction based on a scale coefficient [S1, unofficial]. Unlike standard ray casting which assumes the camera is always outside the volume, this method allows for a "flowing through" effect [S1, unofficial].

## How it works
The method operates in two rendering passes, leveraging the hardware's rasterization capabilities to determine ray boundaries before performing the ray march in the fragment shader.

### Inputs and Outputs
*   **Inputs:**
    *   Volume data: A 3D texture (`VolumeTex`) containing scalar values [S1, unofficial].
    *   Transfer function: A 1D texture (`TransferFunc`) mapping scalar values to color and alpha [S1, unofficial].
    *   Geometry: The front and back faces of the volume's bounding box [S1, unofficial].
    *   Uniforms: `StepSize` (float), `AlphaReduce` (float), `ScreenSize` (vec2), and `scaleCoeff` (float) [S1, unofficial].
*   **Outputs:**
    *   Final pixel color (`FragColor`) [S1, unofficial].

### Data Structures
1.  **ExitPoints Texture:** A 2D texture (`sampler2D`) storing the 3D exit coordinates of rays passing through the back face of the volume. Each texel stores a `vec3` (xyz) representing the world-space exit position [S1, unofficial].
2.  **VolumeTex:** A 3D texture (`sampler3D`) storing the scalar field data [S1, unofficial].
3.  **TransferFunc:** A 1D texture (`sampler1D`) storing the color/alpha mapping [S1, unofficial].

### Steps
1.  **Back-Face Rasterization (Pass 1):** Render the back face of the volume's bounding box into a framebuffer object (FBO) attached to the `ExitPoints` 2D texture. The vertex color or position is used to store the exit coordinates of the rays [S1, unofficial].
2.  **Front-Face Rasterization (Pass 2):** Render the front face of the volume's bounding box to the screen. The vertex shader passes the entry point (`EntryPoint`) to the fragment shader [S1, unofficial].
3.  **Fragment Shader Execution:**
    *   Retrieve the exit point for the current pixel from the `ExitPoints` texture using normalized screen coordinates: `gl_FragCoord.st / ScreenSize` [S1, unofficial].
    *   **Discard Check:** If the `EntryPoint` equals the `exitPoint`, the ray does not pass through the volume (or the camera is outside/misses), so discard the fragment [S1, unofficial].
    *   **Ray Direction:** Calculate the ray direction by normalizing the vector from the entry point to the exit point: $\mathbf{d} = \text{normalize}(\mathbf{p}_{exit} - \mathbf{p}_{entry})$ [S1, unofficial].
    *   **Entry Point Adjustment:** To handle the "flowing through" effect when the camera is inside the volume:
        *   If `scaleCoeff` $\ge 2.7$, calculate a temporary shift factor: $tmp = \min((scaleCoeff - 2.7) \times 0.1, 1.0)$ [S1, unofficial].
        *   Shift the entry point forward: $\mathbf{p}_{start} = \mathbf{p}_{entry} + tmp \times (\mathbf{p}_{exit} - \mathbf{p}_{entry})$ [S1, unofficial].
        *   If `scaleCoeff` $< 2.7$, use the original entry point: $\mathbf{p}_{start} = \mathbf{p}_{entry}$ [S1, unofficial].
    *   **Initialization:**
        *   Set current position $\mathbf{p}_{curr} = \mathbf{p}_{start}$ [S1, unofficial].
        *   Initialize accumulated color `colorSum` = $(0,0,0,0)$ [S1, unofficial].
        *   Calculate step vector: $\mathbf{Step} = \mathbf{d} \times \text{StepSize}$ [S1, unofficial].
        *   Calculate total ray length: $L = \|\mathbf{p}_{exit} - \mathbf{p}_{entry}\|$ [S1, unofficial].
        *   Calculate step length: $l_{step} = \|\mathbf{Step}\|$ [S1, unofficial].
    *   **Ray Marching Loop:** Iterate up to 16,000 times (or until termination conditions are met) [S1, unofficial]:
        1.  Sample the volume: $v = \text{texture}(\text{VolumeTex}, \mathbf{p}_{curr})$ [S1, unofficial].
        2.  Sample the transfer function: $c = \text{texture}(\text{TransferFunc}, v.a)$ [S1, unofficial].
        3.  Apply alpha reduction: $c.a = c.a \times \text{AlphaReduce}$ [S1, unofficial].
        4.  Front-to-back compositing:
            $$
            \mathbf{c}_{rgb} = c.rgb \times c.a
            $$
            $$
            \text{colorSum} = (1.0 - \text{colorSum}.a) \times \mathbf{c}_{rgb} + \text{colorSum}
            $$
            (Note: The source code applies the alpha to RGB before adding to the sum, effectively implementing the standard over operator where the new color is weighted by its alpha and the previous transmittance) [S1, unofficial].
        5.  Update accumulated length: $L_{sum} += l_{step}$ [S1, unofficial].
        6.  **Termination Conditions:**
            *   If `colorSum.a` $\ge 0.95$, break loop [S1, unofficial].
            *   If $L_{sum} \ge L$, break loop [S1, unofficial].
        7.  Advance position: $\mathbf{p}_{curr} += \mathbf{Step}$ [S1, unofficial].
    *   Output `colorSum` as `FragColor` [S1, unofficial].

### Pseudocode
```python
# Fragment Shader Logic
# Inputs: EntryPoint (vec3), ExitPointCoord (vec4, used to index ExitPoints texture)
# Uniforms: ExitPoints (sampler2D), VolumeTex (sampler3D), TransferFunc (sampler1D)
#           StepSize (float), AlphaReduce (float), ScreenSize (vec2), scaleCoeff (float)

def fragment_shader(EntryPoint, ExitPointCoord):
    # 1. Retrieve exit point from 2D texture
    # Normalize screen coordinates by screen size
    uv = ExitPointCoord.xy / ScreenSize
    exitPoint = texture(ExitPoints, uv).xyz

    # 2. Discard if ray does not pass through volume
    if EntryPoint == exitPoint:
        discard_fragment()

    # 3. Calculate ray direction
    rayDirection = normalize(exitPoint - EntryPoint)

    # 4. Entry Point Adjustment
    if scaleCoeff >= 2.7:
        tmp = min((scaleCoeff - 2.7) * 0.1, 1.0)
        start_point = EntryPoint + tmp * (exitPoint - EntryPoint)
    else:
        start_point = EntryPoint

    # 5. Initialization
    current_pos = start_point
    color_sum = vec4(0.0, 0.0, 0.0, 0.0)
    step = rayDirection * StepSize
    step_length = length(step)
    total_length = length(exitPoint - EntryPoint)
    accumulated_length = 0.0

    # 6. Ray Marching Loop
    for i in range(16000):
        # Sample volume and transfer function
        value = texture(VolumeTex, current_pos).a
        color = texture(TransferFunc, value)

        # Reduce alpha
        color.a *= AlphaReduce

        # Front-to-back blending
        # Note: Source code does: color.rgb *= color.a; colorSum = (1.0 - colorSum.a) * color + colorSum
        # This implies color.rgb is the emitted color, and it is weighted by its own alpha
        # and the transmittance of previous layers.
        emitted_color = color.rgb * color.a
        color_sum = (1.0 - color_sum.a) * emitted_color + color_sum

        # Update length
        accumulated_length += step_length

        # Termination checks
        if color_sum.a >= 0.95:
            break
        if accumulated_length >= total_length:
            break

        # Advance position
        current_pos += step

    return color_sum
```

### Parameters
*   **StepSize:** Uniform float controlling the distance between samples along the ray [S1, unofficial].
*   **AlphaReduce:** Uniform float multiplier applied to alpha to increase transparency [S1, unofficial].
*   **scaleCoeff:** Custom uniform/variable representing the scaling factor of the volume, used to determine if the camera is inside the volume [S1, unofficial].
*   **Termination Alpha:** 0.95 (hardcoded in source) [S1, unofficial].
*   **Max Iterations:** 16,000 (hardcoded in source) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision:** The comparison `EntryPoint == exitPoint` for discarding fragments may suffer from floating-point precision issues. [G] In practice, a small epsilon tolerance should be used for this comparison to avoid discarding valid rays due to minor rasterization discrepancies.
*   **Boundary Conditions:** The method relies on the bounding box geometry. If the volume is not axis-aligned or the bounding box is not correctly defined, the exit point retrieval will be incorrect.
*   **Inside-Volume Effect:** The adjustment formula `tmp = min((scaleCoeff - 2.7) * 0.1, 1.0)` is a heuristic. It may not perfectly simulate being "surrounded" by the volume, as noted by the author [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray, bounded by the max iterations (16,000) and the ray length [S1, unofficial].
*   **Memory Complexity:** Requires storage for the `ExitPoints` 2D texture (resolution dependent on screen size) and the 3D volume texture [S1, unofficial].
*   **Strengths:** Allows camera movement inside the volume without complex geometry clipping or ray origin recalculation logic in the CPU [S1, unofficial].
*   **Limitations:** The "flowing through" effect is approximate and relies on a heuristic scale coefficient [S1, unofficial]. The hardcoded loop limit and termination threshold may not be optimal for all volumes [S1, unofficial].
*   **When to use:** When implementing a simple "fly-through" visualization where the camera enters the volume, and high performance is required on older hardware that supports FBOs and 3D textures [S1, unofficial].

## Background

It is presented as a solution to the problem of ray casting when the camera moves inside the volume bounding box, offering an alternative to plane clipping [S1, unofficial].
