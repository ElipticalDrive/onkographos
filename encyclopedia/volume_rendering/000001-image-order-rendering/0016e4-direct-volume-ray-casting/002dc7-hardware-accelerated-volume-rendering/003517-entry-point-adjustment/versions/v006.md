# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated technique for direct volume ray casting that enables the camera to move inside the volume's bounding box without the view disappearing or clipping artifacts. It solves the problem of standard ray generation failing when the camera origin exceeds the back face of the volume by dynamically shifting the ray's entry point forward along the ray direction based on a scale coefficient [S1, unofficial]. Unlike standard methods that assume the camera is always outside the volume, this approach maintains visual continuity as the viewer "flows through" the volume [S1, unofficial].

## How it works
The method operates in a two-pass rendering pipeline using framebuffer objects (FBOs) and fragment shaders. It relies on the Shared principles of the parent family [5616-hardware-accelerated-volume-rendering.md], specifically ray generation, sampling, classification, and compositing.

### Inputs and Outputs
**Inputs:**
*   `VolumeTex`: A 3D texture containing the scalar volume data [S1, unofficial].
*   `TransferFunc`: A 1D texture mapping scalar values to RGBA color and opacity [S1, unofficial].
*   `ExitPoints`: A 2D texture storing the exit coordinates of rays passing through the back face of the volume [S1, unofficial].
*   `ScreenSize`: A uniform vector $(W, H)$ representing the resolution of the viewport [S1, unofficial].
*   `StepSize`: A uniform float controlling the distance between samples along the ray [S1, unofficial].
*   `AlphaReduce`: A uniform float multiplier applied to alpha to increase transparency [S1, unofficial].
*   `scaleCoeff`: A uniform float representing the scaling factor of the volume, used to determine if the camera is inside [S1, unofficial].

**Outputs:**
*   `FragColor`: The final accumulated color for each pixel [S1, unofficial].

### Data Structures
*   **ExitPoints Texture**: A 2D texture where each texel at normalized screen coordinates $(u, v)$ stores the 3D world-space exit point $(x, y, z)$ of the ray passing through that pixel's back-face intersection [S1, unofficial].
*   **Volume Texture**: A 3D texture storing scalar values. Sampling returns a `vec4` where the alpha channel typically holds the scalar value for transfer function lookup [S1, unofficial].

### Steps
1.  **Back-Face Rendering (Pre-pass)**: Render the back face of the volume's axis-aligned bounding box into an FBO bound to the `ExitPoints` texture. The fragment shader outputs the world-space coordinates of the intersection point. This captures where rays exit the volume [S1, unofficial].
2.  **Front-Face Rendering (Main Pass)**: Render the front face of the volume's bounding box to the screen. Pass the entry point (camera origin or front-face intersection) as a varying `EntryPoint` to the fragment shader [S1, unofficial].
3.  **Ray Direction Calculation**: In the fragment shader, retrieve the exit point from `ExitPoints` using normalized screen coordinates:
    $$ \mathbf{p}_{exit} = \text{texture}(\text{ExitPoints}, \frac{\mathbf{gl\_FragCoord.st}}{\text{ScreenSize}}).xyz $$
    If the entry point equals the exit point, the ray does not pass through the volume (or the camera is outside in a way that misses the volume), and the fragment is discarded [S1, unofficial].
    Calculate the ray direction:
    $$ \mathbf{d} = \text{normalize}(\mathbf{p}_{exit} - \mathbf{p}_{entry}) $$
4.  **Entry Point Adjustment**: Determine the effective entry point $\mathbf{p}_{eff}$ based on `scaleCoeff`. If `scaleCoeff` $\ge 2.7$, shift the entry point forward to simulate being inside the volume:
    $$ \tau = \min((\text{scaleCoeff} - 2.7) \times 0.1, 1.0) $$
    $$ \mathbf{p}_{eff} = \mathbf{p}_{entry} + \tau (\mathbf{p}_{exit} - \mathbf{p}_{entry}) $$
    Otherwise, $\mathbf{p}_{eff} = \mathbf{p}_{entry}$ [S1, unofficial].
5.  **Ray Marching Initialization**:
    *   Set current position $\mathbf{p}_{curr} = \mathbf{p}_{eff}$ [S1, unofficial].
    *   Initialize accumulated color $C_{sum} = (0, 0, 0, 0)$ and opacity $\alpha_{sum} = 0$ [S1, unofficial].
    *   Calculate step vector $\mathbf{s} = \mathbf{d} \times \text{StepSize}$ [S1, unofficial].
    *   Calculate total ray length $L = \|\mathbf{p}_{exit} - \mathbf{p}_{entry}\|$ [S1, unofficial].
    *   Initialize accumulated length $L_{acc} = 0$ [S1, unofficial].
6.  **Loop**: Iterate up to a maximum number of steps (e.g., 16,000) [S1, unofficial]:
    *   Sample volume: $v = \text{texture}(\text{VolumeTex}, \mathbf{p}_{curr})$ [S1, unofficial].
    *   Classify: $c = \text{texture}(\text{TransferFunc}, v.a)$ [S1, unofficial].
    *   Adjust opacity: $c.a = c.a \times \text{AlphaReduce}$ [S1, unofficial].
    *   Composite (Front-to-Back):
        $$ C_{sum} = (1 - C_{sum}.a) \times (c.rgb \times c.a) + C_{sum} $$
        $$ \alpha_{sum} = C_{sum}.a $$
    *   Update position: $\mathbf{p}_{curr} += \mathbf{s}$ [S1, unofficial].
    *   Update length: $L_{acc} += \|\mathbf{s}\|$ [S1, unofficial].
    *   Termination: Break if $\alpha_{sum} \ge 0.95$ or $L_{acc} \ge L$ [S1, unofficial].
7.  **Output**: Write $C_{sum}$ to `FragColor` [S1, unofficial].

### Pseudocode
```python
# Fragment Shader Logic
def fragment_shader(entry_point: vec3, screen_coord: vec2, screen_size: vec2, 
                    exit_points_tex: sampler2D, volume_tex: sampler3d, 
                    transfer_func: sampler1d, step_size: float, 
                    alpha_reduce: float, scale_coeff: float) -> vec4:
    
    # 1. Retrieve exit point
    uv = screen_coord / screen_size
    exit_point = texture(exit_points_tex, uv).xyz
    
    # 2. Check if ray passes through volume
    if entry_point == exit_point:
        discard()
        
    # 3. Calculate ray direction
    ray_direction = normalize(exit_point - entry_point)
    
    # 4. Adjust entry point if inside volume
    if scale_coeff >= 2.7:
        tmp = min((scale_coeff - 2.7) * 0.1, 1.0)
        effective_entry = entry_point + tmp * (exit_point - entry_point)
    else:
        effective_entry = entry_point
        
    # 5. Initialize variables
    current_pos = effective_entry
    color_sum = vec4(0.0, 0.0, 0.0, 0.0)
    step_vector = ray_direction * step_size
    step_length = length(step_vector)
    total_length = length(exit_point - entry_point)
    accumulated_length = 0.0
    
    # 6. Ray marching loop
    for i in range(16000):
        # Sample volume and classify
        value = texture(volume_tex, current_pos)
        color = texture(transfer_func, value.a)
        
        # Reduce alpha for transparency
        color.a *= alpha_reduce
        
        # Front-to-back compositing
        # Note: color.rgb is multiplied by alpha before adding to sum
        contribution = color.rgb * color.a
        color_sum = (1.0 - color_sum.a) * contribution + color_sum
        
        # Advance
        current_pos += step_vector
        accumulated_length += step_length
        
        # Termination conditions
        if color_sum.a >= 0.95:
            break
        if accumulated_length >= total_length:
            break
            
    return color_sum
```

### Parameters
*   `scaleCoeff`: Threshold for entering the volume. Values $\ge 2.7$ trigger adjustment [S1, unofficial].
*   `StepSize`: Controls sampling density. Not given in the sources.
*   `AlphaReduce`: Transparency multiplier. Not given in the sources.

### Edge Cases and Pitfalls
*   **Precision**: Comparing `EntryPoint == exitPoint` for discarding fragments may suffer from floating-point precision issues. [G] A small epsilon tolerance should be used in practice.
*   **Boundary Conditions**: The method assumes the volume is enclosed by a bounding box. If the volume is not axis-aligned or the bounding box is loose, the exit point texture may contain invalid data for rays that miss the volume.
*   **Scale Coefficient**: The formula `(scaleCoeff - 2.7) * 0.1` is empirical. Values significantly above 2.7 may shift the entry point too far, causing the ray to start inside the volume and potentially miss front-face details or create visual artifacts if the shift exceeds the volume bounds.

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of samples per ray ($N$) and the number of pixels ($P$). $O(P \times N)$. The loop runs up to 16,000 times, but early termination reduces average cost [S1, unofficial].
*   **Memory Complexity**: Requires storage for the `ExitPoints` texture ($W \times H \times 4$ bytes) and the `VolumeTex` ($D_x \times D_y \times D_z \times 4$ bytes) [S1, unofficial].
*   **Performance**: Dependent on GPU fragment shader execution speed. The two-pass approach adds overhead but allows for efficient ray marching in the second pass [S1, unofficial].
*   **Strengths**: Enables immersive "inside-the-volume" viewing without complex ray-triangle intersection calculations for every sample. Simple to implement on standard graphics hardware [S1, unofficial].
*   **Limitations**: The entry point adjustment is heuristic and may not perfectly represent the physical camera position inside the volume. It is specific to convex, box-like volumes [S1, unofficial].
