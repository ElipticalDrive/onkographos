# 3D Pixel Texture Classification

Also called: VGH Lookup

## Overview
3D Pixel Texture Classification is a hardware-accelerated volume rendering technique that maps multi-dimensional voxel attributes to color and opacity via a 3D texture lookup [S1]. It solves the problem of high-dimensional transfer function evaluation by encoding classification rules into a volumetric texture, allowing the graphics hardware to perform the classification during ray casting [S1]. It differs from standard 1D transfer functions by supporting multi-dimensional inputs (e.g., value, gradient, curvature) and from general GPU ray casting by offloading the classification logic to the texture unit [S1].

## How it works
**Inputs:** Scalar volume data $V$, transfer function parameters defining color $C$ and opacity $\alpha$ for multi-dimensional inputs.
**Outputs:** Final image with accumulated color and opacity.

**Data Structures:**
The core data structure is a 3D pixel texture (lookup table) with dimensions $D_v \times D_g \times D_s$.
- Axis 1 (Data Value): 8-bit resolution (256 entries) [S1].
- Axis 2 (Gradient Magnitude): 8-bit resolution (256 entries) [S1].
- Axis 3 (Second Derivative): Limited resolution, represented as "sheets" [S1].
- Texture Format: RGBA, storing color and opacity values [S1].

**Steps:**
1. **Ray Casting Setup:** For each pixel, generate a ray $r(t) = \mathbf{o} + t\mathbf{d}$ and discretize into samples [S1, S4].
2. **Sample Extraction:** At each sample point $\mathbf{p}_i$, extract the scalar value $d_i = V(\mathbf{p}_i)$, compute the gradient magnitude $g_i = \|\nabla V(\mathbf{p}_i)\|$, and compute the second derivative $s_i$ (e.g., Laplacian or directional second derivative) [S1].
3. **Second Derivative Preprocessing:** The second derivative $s_i$ is signed. To maintain sign information for interpolation, apply a scale and bias to map negative, zero, and positive values to distinct regions in the texture coordinate space [S1].
4. **Texture Lookup:** Use the triplet $(d_i, g_i, s'_i)$ as 3D texture coordinates to sample the pixel texture. The hardware returns the pre-computed color $C_i$ and opacity $\alpha_i$ [S1].
5. **Compositing:** Perform front-to-back compositing using the standard emission-absorption model [S4].

**Formulas:**
The second derivative axis is mapped to three control points: negative, zero, and positive [S1].
Let $O_{center}$ be the opacity at the zero-crossing sheet.
Let $O_{outer}$ be the opacity at the positive/negative sheets.
The opacity for a given second derivative value is determined by linear interpolation between these sheets, scaled by a "boundary emphasis" parameter $E$ [S1]:
$$
\alpha_{lookup} = \text{Interpolate}(O_{center}, O_{outer}, \text{sign}(s_i)) \times \text{Weight}(s_i, E)
$$
Specifically, the opacity on the outer sheets is scaled from the center sheet opacity according to the boundary emphasis slider [S1].

**Parameters:**
- Data Value Resolution: 256 entries [S1].
- Gradient Magnitude Resolution: 256 entries [S1].
- Second Derivative Control Points: 3 (negative, zero, positive) [S1].
- Boundary Emphasis Slider: Controls the relative opacity of outer sheets vs. center sheet [S1].

**Edge Cases:**
- Precision: Full 8-bit resolution is used for data value and gradient to capture fine variations [S1].
- Sign Handling: The second derivative must be scaled and biased to preserve sign for correct interpolation [S1].
- Degenerate Input: If the second derivative is exactly zero, the center sheet opacity is used directly [S1].

## Subtopics

### Adaptive Pre-integrated Voxel Classification
A technique included in a real-time raycaster built by Roettger et al. to exploit the intrinsically parallel nature of GPUs, along with volume clipping [S2]. It addresses the inefficiency of multi-pass rendering pipelines by using a single-pass framework [S2].

## Operating characteristics
**Time Complexity:** $O(N)$ per pixel, where $N$ is the number of samples along the ray. The classification lookup is $O(1)$ via hardware texture sampling [S1, S2].
**Memory Complexity:** $O(D_v \times D_g \times D_s \times 4)$ bytes for the 3D pixel texture. With 256x256x3 entries, this is approximately 480 KB [S1].
**Performance:** Enables real-time rendering on GPUs by leveraging hardware texture units [S2].
**Strengths:** Efficient multi-dimensional classification; hardware-accelerated [S1, S2].
**Limitations:** Texture size is limited by hardware; second derivative axis resolution is limited [S1].

## Background
Originated in the context of interactive volume rendering using multi-dimensional transfer functions [S1]. The method was developed to allow efficient classification of voxel data using hardware-accelerated 3D texturing [S1]. It was later extended in real-time raycasting frameworks to include adaptive pre-integrated voxel classification [S2].
