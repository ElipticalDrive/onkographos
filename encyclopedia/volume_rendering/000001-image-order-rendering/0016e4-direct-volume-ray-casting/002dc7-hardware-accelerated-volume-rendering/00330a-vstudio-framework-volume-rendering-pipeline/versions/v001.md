# VStudio Framework Volume Rendering Pipeline

Also called: Single Pass GPU Ray Casting, VStudio Ray Casting

## Overview
The VStudio Framework is a single-pass GPU ray casting implementation designed for interactive volume visualization and shader customization [S1]. It distinguishes itself by exposing the entire rendering pipeline through a modular, multi-file fragment shader architecture, allowing users to edit and link components (classification, gradient, lighting, shadow) in real-time [S1]. Unlike black-box renderers, it provides explicit control over the ray casting loop, transfer function application, and shading models within a single draw call per pixel [S1].

## How it works
The method implements the emission-absorption optical model using a single-pass GPU ray casting approach [S1]. The pipeline is driven by a specific shader pair configuration (version 1.2) and requires explicit attachment of vertex and fragment shader components to function [S1].

### Inputs and Outputs
**Inputs:**
- Volumetric data in `.dat`, `.vol8`, `.vol12`, or `.vol16` format [S1].
- Camera parameters (origin $\mathbf{o}$, direction $\mathbf{d}$) derived from the view matrix [S1, S4].
- Transfer function parameters (density and gradient magnitude histograms) [S1].
- Lighting parameters (Blinn-Phong model with point and directional lights) [S1].

**Outputs:**
- Final pixel color $C_{final}$ [S1].

### Data Structures and File Formats
The framework expects volumetric data in specific binary formats with little-endian byte ordering [S1].

**`.dat` Format:**
- Header: 6 bytes.
  - Bytes 0-1: X dimension (voxels).
  - Bytes 2-3: Y dimension (voxels).
  - Bytes 4-5: Z dimension (voxels).
- Data: 16-bit scalar values.

**`.vol8`, `.vol12`, `.vol16` Formats:**
- Header: 12 bytes.
  - Bytes 0-1: X dimension (voxels).
  - Bytes 2-3: Y dimension (voxels).
  - Bytes 4-5: Z dimension (voxels).
  - Bytes 6-7: X voxel scale.
  - Bytes 8-9: Y voxel scale.
  - Bytes 10-11: Z voxel scale.
- Data: Scalar values matching the bit depth (8, 12, or 16 bits).
- Constraint: All header values must be in the range 1-4096 [S1].

**Shader Structure:**
The rendering logic is split into multiple files linked together [S1]:
1. `DVR_VERTEX_BACK_FRONT_v1.2.vs`: Vertex shader handling ray generation.
2. `DVR_FRAGMENT_BACK_FRONT_v1.2.fs`: Main fragment entry point.
3. `classify.fs`: Transfer function and classification logic.
4. `grad.fs`: Gradient estimation.
5. `light.fs`: Lighting calculations.
6. `shadow.fs`: Shadow ray traversal.

Linking succeeds only when all specified shader files are attached [S1].

### Algorithm Steps

1. **Data Import and Histogram Calculation:**
   - Load volumetric data using `File/Import/Volume` [S1].
   - The system automatically initiates an "advanced ACC histogram calculation" for density and gradient magnitude [S1].
   - If aborted, only the traditional density histogram is calculated [S1].
   - VStudio expands the data value range during import, regardless of the original bit depth distribution [S1].

2. **Shader Attachment:**
   - Attach the vertex shader `DVR_VERTEX_BACK_FRONT_v1.2.vs` [S1].
   - Attach the fragment shader components: `DVR_FRAGMENT_BACK_FRONT_v1.2.fs`, `classify.fs`, `grad.fs`, `light.fs`, and `shadow.fs` [S1].
   - Link the shader program [S1].

3. **Ray Generation:**
   - For each pixel, compute the ray $r(t) = \mathbf{o} + t\mathbf{d}$ [S1, S4].
   - Intersect the ray with the volume's axis-aligned bounding box to find $t_{start}$ and $t_{end}$ [S1, S4].

4. **Ray Marching and Compositing:**
   - Discretize the segment $[t_{start}, t_{end}]$ into samples [S1, S4].
   - Iterate from front to back:
     - Sample the volume at $\mathbf{p}_i = r(t_i)$ [S1, S4].
     - **Classification:** Map the scalar value $V(\mathbf{p}_i)$ to color $C_i$ and opacity $\alpha_i$ using the transfer function defined in `classify.fs` [S1].
     - **Shading:** Compute lighting using the Blinn-Phong model in `light.fs`, utilizing gradients estimated in `grad.fs` [S1].
     - **Shadows:** Perform brute-force shadow-ray traversal in `shadow.fs` if enabled [S1].
     - **Compositing:** Apply the front-to-back over operator [S1, S4]:
       $$
       C'_{i} = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i
       $$
       $$
       \alpha'_{i} = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i
       $$
     - **Early Ray Termination:** If $\alpha'$ reaches 1 (or a threshold), terminate the ray [S1].

5. **Rendering Features:**
   - **Progressive Refinement:** Iteratively improve image quality [S1].
   - **Stochastic Ray Shifting:** Reduce aliasing by jittering ray origins [S1].
   - **Slicing:** Render cross-sections in view or object space [S1].
   - **MIP:** Use Maximum Intensity Projection mode if shaders are not attached [S1].

### Pseudocode

```python
# VStudio Single-Pass GPU Ray Casting Implementation
# Based on DVR_FRAGMENT_BACK_FRONT_v1.2.fs and associated modules

def vstudio_ray_casting(pixel_uv, camera_origin, camera_direction, volume_data, volume_dims, transfer_function):
    """
    Main entry point for VStudio volume rendering.
    """
    # 1. Ray Generation
    # Compute ray direction from UV coordinates and camera parameters
    ray_direction = compute_ray_direction(pixel_uv, camera_origin, camera_direction)
    
    # Intersect ray with volume AABB to get t_start and t_end
    t_start, t_end = intersect_aabb(camera_origin, ray_direction, volume_dims)
    
    # Initialize compositing variables
    accumulated_color = vec3(0.0)
    accumulated_opacity = 0.0
    
    # 2. Ray Marching Loop
    # Step size is determined by the discretization strategy (equidistant or adaptive)
    step_size = compute_step_size(t_start, t_end, volume_dims)
    t = t_start
    
    while t < t_end:
        # Sample point in world space
        point = camera_origin + t * ray_direction
        
        # Check if point is within volume bounds
        if not is_inside_volume(point, volume_dims):
            break
            
        # 3. Sampling and Interpolation
        # Trilinear interpolation of scalar value V
        scalar_value = trilinear_sample(volume_data, point, volume_dims)
        
        # 4. Classification (from classify.fs)
        # Map scalar value to color and opacity using transfer function
        color, opacity = apply_transfer_function(scalar_value, transfer_function)
        
        # 5. Shading (from light.fs and grad.fs)
        # Estimate gradient for normal calculation
        gradient = estimate_gradient(volume_data, point, volume_dims)
        normal = normalize(gradient)
        
        # Compute lighting (Blinn-Phong)
        # Includes point and directional light sources
        lighting_color = compute_blinn_phong(point, normal, camera_origin, ray_direction)
        
        # 6. Shadows (from shadow.fs)
        # Brute-force shadow ray traversal
        shadow_factor = compute_shadow(point, normal, volume_data, volume_dims)
        
        # Apply lighting and shadow to the classified color
        final_sample_color = color * lighting_color * shadow_factor
        
        # 7. Compositing (Front-to-Back)
        # Over operator
        transmittance = 1.0 - accumulated_opacity
        accumulated_color += transmittance * opacity * final_sample_color
        accumulated_opacity += transmittance * opacity
        
        # 8. Early Ray Termination
        if accumulated_opacity >= 1.0:
            break
            
        t += step_size
        
    return accumulated_color
```

### Parameters and Edge Cases
- **Histogram Calculation:** The "advanced ACC histogram" is critical for accurate transfer function specification. Aborting this results in a fallback to traditional density-only histograms [S1].
- **Data Range Expansion:** VStudio expands the input data range during import, which may affect transfer function mapping if the original data range is assumed [S1].
- **Shader Linking:** The pipeline fails if any of the required fragment shader files (`classify.fs`, `grad.fs`, `light.fs`, `shadow.fs`) are not attached [S1].
- **MIP/Slicing:** These modes do not require shader attachment, providing a fallback for basic visualization [S1].

## Operating characteristics
- **Performance:** Single-pass GPU ray casting offers interactive performance for moderate-resolution volumes [S1].
- **Complexity:** The complexity is linear with respect to the number of samples per ray and the number of rays (pixels) [S1, S4].
- **Strengths:** Interactive shader editing allows for rapid experimentation with classification and shading models [S1].
- **Limitations:** Brute-force shadow ray traversal can be computationally expensive [S1]. Stochastic ray shifting and progressive refinement add overhead but improve quality [S1].
- **Hardware:** Requires a GPU capable of fragment shader execution and texture sampling [S1].

## Background
The VStudio Framework was developed by Robert Hausmair, a student at the Technical University of Vienna, Austria [S1]. It was created as part of the "Visualisierung" course at the Institute of Computer Graphics and Algorithms [S1]. The framework is designed to demonstrate and facilitate interactive volume visualization techniques, particularly single-pass GPU ray casting with customizable shaders [S1].
