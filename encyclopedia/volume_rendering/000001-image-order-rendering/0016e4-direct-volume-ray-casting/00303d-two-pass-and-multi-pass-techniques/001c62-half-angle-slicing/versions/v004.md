# Half-angle slicing

Also called: Halfway vector slicing, Half angle slice axis

## Overview
Half-angle slicing is a two-pass per-slice rendering technique for volumetric shadows that orients slice planes perpendicular to the half-angle vector between the eye and light directions [S1, unofficial][S5, book]. This orientation allows a single slice to be rendered from both the observer's and the light's points of view, decoupling light transport computation from data volume resolution [S2][S5, book]. It achieves high-resolution shadow map effects without pre-computation or storage, avoiding the attenuation leakage artifacts common in standard 2D shadow buffers [S2][S5, book].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D volume texture, camera position and projection matrix, light direction (and position/projection if point light), bounding box of the volume.
*   **Outputs:** Final composited image in the eye buffer (framebuffer).

**Data Structures:**
*   **Light Buffer:** An off-screen 2D texture (render target) storing light transmissivity/attenuation. Initialized to $1 - \text{light intensity}$ [S5, book]. Resolution should be 30%–50% higher than the frame buffer to mitigate shadow boundary artifacts [S5, book]. Format: 16-bit floating point per channel (e.g., `R16G16B16A16Sfloat`) to preserve HDR values [S1, unofficial].
*   **Eye Buffer:** An off-screen 2D texture (or directly the framebuffer) storing the composited color. Format: 16-bit floating point per channel [S1, unofficial].
*   **Push Constants:**
    *   **Light Pass:** `glm::mat4 lightMVP` (64 bytes), `float opacityCorrection` (4 bytes), `float densityMin` (4 bytes), `float densityMax` (4 bytes). Total: 76 bytes [S1, unofficial].
    *   **Eye Pass:** `glm::mat4 eyeMVP` (64 bytes), `glm::mat4 lightMVP` (64 bytes), `float opacityCorrection` (4 bytes), `float ambient` (4 bytes), `float densityMin` (4 bytes), `float densityMax` (4 bytes). Total: 144 bytes [S1, unofficial]. Note: Vulkan guarantees only 128 bytes; drivers supporting 256 bytes are required [S1, unofficial].

**Algorithm Steps:**

1.  **Coordinate Transformation:** Transform the camera position and light direction into the object's local (inverted) space using the inverse model matrix $M^{-1}$ [S4, unofficial].
    *   `invCamPosition = M.inverse * cameraPosition`
    *   `invLightVector = normalize(M.inverse * lightDirection)`
    *   `invCamVector = normalize(invCamPosition - cameraPosition)` (Note: Source [S4, unofficial] defines `invCamVector` as pointing from camera to object, but standard view vector is camera to object. The code snippet uses `mainCamera.transform.position - ...` which is object to camera? No, `gameObject.transform.position - mainCamera.transform.position` is camera to object. Let's stick to the vector logic: `invCamVector` is the normalized vector from camera to object in local space [S4, unofficial]).

2.  **Half-Vector Calculation:** Determine the slicing axis based on the dot product of the inverted light and view vectors [S4, unofficial][S5, book].
    *   Compute $D = \text{dot}(\text{normalize}(\text{invLightVector}), \text{normalize}(\text{invCamVector}))$.
    *   If $D \ge 0$: `halfVector = normalize(invCamVector + invLightVector)`.
    *   If $D < 0$: `halfVector = normalize(-invCamVector + invLightVector)`.
    *   This ensures the half-vector lies between the light and the *effective* view direction [S4, unofficial][S5, book].

3.  **Slice Bounds and Spacing:**
    *   Project the 8 bounding box vertices onto the `halfVector` to find `min_dist` and `max_dist` [S4, unofficial].
    *   Calculate the total length along the half-vector: `halfVectorLength = |halfVector * (max_dist - min_dist)|` [S4, unofficial].
    *   Determine the number of slices $N$ (e.g., 256) [S1, unofficial].
    *   Calculate step size: `stepSize = halfVectorLength / N` [S4, unofficial].
    *   *Note on Spacing:* The slice spacing along the half-vector axis $d_s$ relates to the desired view-space slice spacing $d_v$ and the angle $\theta$ between view and light by $d_s = \frac{d_v}{\cos(\theta/2)}$ [S5, book].

4.  **Per-Slice Loop:** For each slice $s$ from $0$ to $N-1$:
    *   **Calculate Slice Plane:**
        *   `newpos = halfVector * min_dist`
        *   `C = newpos + (halfVector.normalized * s * stepSize) + (halfVector.normalized * stepSize / 2)` [S4, unofficial].
    *   **Generate Proxy Geometry:**
        *   Intersect the plane defined by center $C$ and normal `halfVector` with the bounding box edges [S4, unofficial].
        *   Sort intersection vertices counter-clockwise around $C$ using the cross-product test: `if (dot(halfVector, cross(A-C, B-C)) <= 0) return 1; else return -1;` [S4, unofficial].
        *   Construct a fan mesh: Add a central vertex (centroid of intersections) and connect to sorted boundary vertices. Handle winding order based on `bViewInverted` (derived from $D \ge 0$) [S4, unofficial].
    *   **Pass 1: Light Pass (Accumulate Attenuation):**
        *   Render the slice from the **light's** point of view.
        *   Render order: Front-to-back with respect to the light [S3, unofficial][S5, book].
        *   Fragment Shader: Compute opacity from volume density. Accumulate alpha using the "over" operator into the Light Buffer. This buffer represents the light intensity arriving at the current slice depth [S3, unofficial][S5, book].
        *   *Note:* The Light Buffer is updated incrementally. The amount of light arriving at a slice is $1 - \text{accumulated opacity}$ [S5, book].
    *   **Pass 2: Eye Pass (Composite Color):**
        *   Render the **same** slice from the **eye's** point of view.
        *   Render order: Front-to-back if $D \ge 0$, Back-to-front if $D < 0$ (with respect to the observer) [S5, book].
        *   Fragment Shader:
            1.  Sample the Light Buffer to get the available light intensity at the current slice's depth [S3, unofficial].
            2.  Sample the volume texture to get color and opacity.
            3.  Modulate the volume color by the sampled light intensity.
            4.  Composite the result into the Eye Buffer using the "over" operator [S1, unofficial][S5, book].

5.  **Final Composition:** Copy the Eye Buffer to the screen [S1, unofficial].

**Pseudocode:**

```python
def half_angle_slicing(volume, camera, light, bounding_box, num_slices=256):
    # 1. Transform to local space
    inv_model = inverse(camera.model_matrix) # Assuming model matrix transforms local to world
    inv_cam_pos = inv_model * camera.position
    inv_light_dir = normalize(inv_model * light.direction)
    inv_cam_dir = normalize(inv_cam_pos - camera.position) # Vector from camera to object in local space? 
    # Correction: inv_cam_dir should be vector FROM camera TO object. 
    # If inv_cam_pos is camera pos in local space, and object is at origin, 
    # vector is -inv_cam_pos. 
    # Source [S4, unofficial] uses: cameraVector = (gameObject.transform.position - mainCamera.transform.position).normalized
    # In local space, gameObject is at 0. So vector is -mainCamera.transform.position.
    inv_cam_dir = normalize(-inv_cam_pos)

    # 2. Compute Half Vector
    dot_product = dot(inv_light_dir, inv_cam_dir)
    b_view_inverted = dot_product >= 0
    
    if b_view_inverted:
        half_vector = normalize(inv_cam_dir + inv_light_dir)
    else:
        half_vector = normalize(-inv_cam_dir + inv_light_dir)

    # 3. Compute Bounds
    box_vertices = [(-0.5,-0.5,0.5), (-0.5,0.5,0.5), (0.5,0.5,0.5), (0.5,-0.5,0.5),
                    (-0.5,-0.5,-0.5), (-0.5,0.5,-0.5), (0.5,0.5,-0.5), (0.5,-0.5,-0.5)]
    projections = [dot(half_vector, v) for v in box_vertices]
    min_dist = min(projections)
    max_dist = max(projections)
    
    half_vector_length = abs(max_dist - min_dist)
    step_size = half_vector_length / num_slices
    newpos = half_vector * min_dist

    # Initialize Light Buffer (Texture)
    # Initialized to 1 - light_intensity. 
    # If light is directional with intensity I, init to 1-I. 
    # If ambient only, init to 1.
    light_buffer = create_texture(width=frame_width*1.5, height=frame_height*1.5, format=RGBA16F)
    light_buffer.clear(1.0 - light.intensity) 

    eye_buffer = create_texture(width=frame_width, height=frame_height, format=RGBA16F)

    for s in range(num_slices):
        # 4. Slice Geometry
        center = newpos + (half_vector * s * step_size) + (half_vector * step_size / 2)
        
        # Intersect plane with box edges
        intersections = intersect_plane_with_box(center, half_vector, box_vertices)
        
        # Sort intersections CCW around center
        intersections.sort(key=lambda p: cross_product_angle(half_vector, p - center))
        
        # Create fan mesh
        centroid = sum(intersections) / len(intersections)
        vertices = [centroid] + intersections
        indices = []
        for i in range(len(intersections)):
            p1 = (i + 1) % len(intersections) + 1 # +1 for centroid at 0
            p2 = (i + 2) % len(intersections) + 1
            if b_view_inverted:
                indices.extend([p2, p1])
            else:
                indices.extend([p1, p2])
        
        mesh = Mesh(vertices, indices)

        # 5. Light Pass
        # Render mesh from Light POV
        # Shader: Sample volume, compute opacity, accumulate to light_buffer
        render_to_texture(mesh, light.camera_matrix, light_buffer, 
                          push_constants={
                              'lightMVP': light.camera_matrix,
                              'opacityCorrection': 1.0,
                              'densityMin': 0.0,
                              'densityMax': 1.0
                          },
                          blend_mode='OVER', # Accumulate opacity
                          vertex_shader='light_vs',
                          fragment_shader='light_fs')

        # 6. Eye Pass
        # Render mesh from Eye POV
        # Shader: Sample volume, sample light_buffer, modulate color, composite to eye_buffer
        render_to_texture(mesh, camera.camera_matrix, eye_buffer,
                          push_constants={
                              'eyeMVP': camera.camera_matrix,
                              'lightMVP': light.camera_matrix,
                              'opacityCorrection': 1.0,
                              'ambient': light.ambient,
                              'densityMin': 0.0,
                              'densityMax': 1.0
                          },
                          blend_mode='OVER',
                          vertex_shader='eye_vs',
                          fragment_shader='eye_fs')

    # 7. Final Output
    copy_to_screen(eye_buffer)
```

**Edge Cases and Pitfalls:**
*   **Push Constants Size:** The Eye Pass push constants total 144 bytes. Vulkan only guarantees 128 bytes. This requires a driver supporting 256 bytes (standard on desktop GPUs) [S1, unofficial].
*   **Attenuation Leakage:** If view and light are perpendicular, the half-vector is at 45 degrees. While this method avoids the worst-case leakage of 2D shadow maps, artifacts can still appear at shadow boundaries if opacity jumps sharply. Using a higher resolution light buffer (30-50% larger) mitigates this [S5, book].
*   **Slice Order:** The half-vector always lies between eye and light, fixing the light traversal order to front-to-back. No toggle is needed [S1, unofficial].
*   **Perpendicular View/Light:** When view and light are perpendicular, the slice spacing $d_s$ becomes $\sqrt{2} d_v$. The method handles this gracefully by rotating the slices, unlike methods that require separate 3D shadow maps [S5, book].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of slices and $S$ is the number of samples per slice (determined by ray length and step size). Two passes per slice.
*   **Memory Complexity:** $O(W \cdot H)$ for the light and eye buffers, where $W, H$ are buffer dimensions. Significantly less than 3D shadow maps [S5, book].
*   **Performance:** High performance on modern GPUs due to "render to texture" extensions avoiding copy operations [S5, book]. The decoupling allows efficient use of hardware blending [S1, unofficial].
*   **Strengths:** No pre-computation; high-resolution shadows; memory efficient compared to volumetric shadow maps; avoids attenuation leakage artifacts associated with coarse 2D buffers [S2][S5, book].
*   **Limitations:** Artifacts at sharp shadow boundaries if resolution is insufficient; requires GPU driver support for large push constants (144 bytes) [S1, unofficial]; complex geometry generation for proxy slices [S4, unofficial].
*   **When to use:** Interactive volume rendering with dynamic lighting where shadow quality is important and memory is constrained [S2][S5, book].
*   **When not to use:** When the view and light directions are such that the half-vector causes excessive slice count for the desired view spacing (though the formula adapts $d_s$) [S5, book].
