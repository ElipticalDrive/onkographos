# Effective Depth Peeling

Also called: DP with PVHVs, DP+PVHV, EDP (Extended Depth Peeling with PVHV), PVHV-based culling, Sampling-based backward-search algorithm

## Overview
Effective Depth Peeling (EDP) is a visibility culling technique for multi-layer volume ray casting that integrates Potentially Visible Hidden-Volume (PVHV) analysis into the depth peeling process [S1]. It solves the problem of processing redundant, completely hidden fragments in subsequent peeling layers by implicitly identifying and culling fragments that are occluded by large-area occluders, thereby reducing the number of effective layers required for high-quality multi-view warping [S1]. Unlike standard Depth Peeling (DP) which peels one layer per pass linearly, or Umbra culling-based DP (UDP) which uses tiny pixel occluders, EDP captures important edge fragments early using wider area occluders, significantly reducing warping costs and total layer count [S1].

## How it works
EDP operates by testing whether a fragment in a hidden layer lies within a PVHV defined by the occluders in the previous layer [S1]. If a fragment is inside a PVHV, it is considered fully hidden and culled; otherwise, it is retained for warping [S1]. The method uses a sampling-based backward search to approximate PVHVs without explicit edge analysis [S1].

### Inputs and Outputs
*   **Inputs:**
    *   $Z$: Known-view depth texture from the previous layer (or foreground image for $h=1$) [S1].
    *   $E$: Novel-view bound radius (screen-space LCOC radius) [S1].
    *   $\Delta$: Depth-difference threshold for surface connectivity (default: 0.002 in normalized linear scale) [S1].
    *   $|\Omega|$: Number of backward-search samples (default: 14) [S1].
    *   `fragments`: List of candidate fragments for layer $h$ [S1].
*   **Outputs:**
    *   Culled fragments for layer $h$: Only fragments not determined to be in a PVHV are passed to the next stage [S1].

### Data Structures
*   **Item Buffer:** Stores object IDs for fragments [S1]. Used to immediately reject samples belonging to different objects during edge existence tests [S1].
*   **Fragment Encoding:** RGBA32F format, storing color, depth ($z$), and item index [S1].
*   **Depth Texture ($Z$):** Stores depth values for the occluder layer [S1].

### Algorithm Steps

1.  **Initialization:** For each fragment $p$ in the current hidden layer $h$, identify its projection $q$ onto the occluder layer $h-1$ (or foreground $h=0$) [S1]. The depth of $q$ is $q_z = Z(p_x, p_y)$ [S1].
2.  **LCOC Calculation:** Compute the Local Cone of Confusion (LCOC) radius $R$ in screen space based on the depth difference between $p$ and $q$, and the novel-view bound $E$ [S1]. The formula is:
    $$ R = \text{ProjectToScreen}\left( \left| \frac{p_z - q_z}{q_z} \right| E \right) $$
    where $\text{ProjectToScreen}$ converts the physical bound to screen-space pixels [S1].
3.  **Sample Generation:** Generate a set of uniform random samples $\Omega$ within a circle of radius $R$ centered at $q$ [S1]. The size $|\Omega|$ is typically 14 [S1].
4.  **Edge Existence Test:** For each sample $w \in \Omega$:
    a.  Sample the depth at the offset location: $w_z = Z(p_x + w_x, p_y + w_y)$ [S1].
    b.  Test if an edge exists between $w$ and $q$ using `EdgeExists(w, q)` [S1].
5.  **PVHV Inclusion Check:**
    *   If `EdgeExists(w, q)` returns true, the fragment $p$ is in a PVHV [S1]. Return true (fragment is hidden/culled) [S1].
    *   If the depth difference is small ($w_z \ge q_z - \Delta$), the sample $w$ is on the connected surface [S1]. Bypass $w$ (do not process as a new occluder) and continue to the next sample [S1].
    *   If the depth difference is significant ($w_z < q_z - \Delta$), the sample may find a secondary inner occluder [S1].
        *   **Recursive Extension (CPU/Conceptual):** Recursively extend the bound at $w$ to find secondary inner occluders by calling `InPVHV` again [S1].
        *   **GPU Implementation:** Since GPU implementations do not support recursion for secondary inner occluders, a Halton sequence is used for quasi-random samples so that subsequent samples naturally handle bound extensions [S1]. Alternatively, a conservative approximation can be used by considering such samples as potentially in PVHVs (return true) to avoid excessive sampling [S1].
6.  **Final Decision:** If no samples indicate an edge or PVHV inclusion after checking all $w \in \Omega$, return false (fragment is fully visible/retained) [S1].

### Pseudocode

```python
import math
import random

def effective_depth_peeling(Z, E, Delta, Omega_size, ItemBuffer, fragments):
    def ProjectToScreen(value):
        return int(round(value))

    def GetRandomSamples(radius, count):
        samples = []
        for _ in range(count):
            angle = random.uniform(0, 2 * math.pi)
            r = math.sqrt(random.uniform(0, 1)) * radius
            samples.append((r * math.cos(angle), r * math.sin(angle)))
        return samples

    def LCOC(pz, qz):
        return ProjectToScreen(abs((pz - qz) / qz) * E)

    def EdgeExists(w, q):
        if ItemBuffer[w] != ItemBuffer[q]:
            return True
        wz = Z[w]
        qz = Z[q]
        if wz > qz + Delta:
            return True
        return False

    def InPVHV(p, pz, conservative=False):
        q = p
        qz = Z[q]
        R = LCOC(pz, qz)
        Omega = GetRandomSamples(R, Omega_size)
        for w in Omega:
            w_coord = (p[0] + w[0], p[1] + w[1])
            wz = Z[w_coord]
            if EdgeExists(w_coord, q):
                return True
            if wz >= qz - Delta:
                continue
            if conservative:
                return True
            if InPVHV(w_coord, wz, conservative):
                return True
        return False

    for p in fragments:
        pz = p.depth
        if not InPVHV(p, pz):
            retain_fragment(p)
```

### Parameters
*   $\Delta$: Depth-difference threshold [S1]. Default: 0.002 (normalized linear scale) [S1]. Trades errors for peeling efficiency [S1].
*   $E$: Novel-view bound radius [S1]. Input parameter for LCOC calculation [S1].
*   $|\Omega|$: Number of backward-search samples [S1]. Default: 14 [S1]. More samples (e.g., 16) lower the chance of missing edges in complex scenes [S1].

### Edge Cases and Pitfalls
*   **GPU Recursion:** GPU implementations do not support recursion for secondary inner occluders [S1]. A Halton sequence is used for quasi-random samples to handle bound extensions in subsequent iterations [S1].
*   **Approximate Tests:** The edge existence test is approximate [S1]. Small numbers of missing fragments may occur, but experiments show negligible error rates (e.g., 0.000014 average fraction of erroneous pixels in RU scene) [S1].
*   **Disjoint Surfaces:** Few adjacent disjoint surfaces may be incorrectly considered connected [S1]. Insufficient samples may miss existing edges [S1].

## Subtopics

### [Packed Effective Depth Peeling](17011-packed-effective-depth-peeling.md)
A memory-optimized variant that uses a linked list structure to pack sparse valid fragments, reducing memory consumption compared to fixed-size buffers.

## Operating characteristics
*   **Time Complexity:** Per-layer cost is costlier than regular DP due to the PVHV culling overhead, but fewer layers are needed for similar quality [S1].
*   **Memory Complexity:** Standard EDP requires two working textures (ping-pong) for input and output layers [S1]. Packed EDP (PEDP) reduces memory by tightly packing sparse valid fragments using a linked list structure, and requires a head texture of screen resolution holding 4-byte indexes to the first nodes per pixel [S1].
*   **Performance:**
    *   In the Satellites (ST) scene with $E=1000$mm, EDP achieves a 38.5x reduction in hidden fragments compared to Baseline DP (BDP) [S1].
    *   Speedup factors for combined DP and warping costs range from 2.3–3.4x vs BDP and 1.6–2.9x vs UDP [S1].
    *   EDP requires only two hidden layers for high-quality DOF rendering in complex scenes, reducing effective layers by up to 2/2/3 (RU/SF/ST) for BDP and 3/2/2 for UDP [S1].
*   **Strengths:** Captures important fragments early, reduces warping cost, handles large-area occluders better than UDP [S1].
*   **Limitations:** Approximate edge tests may miss small fragments; GPU recursion limitation requires Halton sequence handling [S1].
*   **Usage:** Best for Depth-of-Field (DOF) rendering in multi-view warping applications [S1].

## Background
Effective Depth Peeling was introduced by Janghun Kim and Sungkil Lee in 2023 in the paper "Potentially Visible Hidden-Volume Rendering for Multi-View Warping" [S1]. It builds on the concept of Potentially Visible Hidden-Volumes (PVHVs) and extends Depth Peeling by integrating on-the-fly fragment culling [S1]. The method is designed to improve efficiency in multi-fragment rendering and remote rendering scenarios [S1].
