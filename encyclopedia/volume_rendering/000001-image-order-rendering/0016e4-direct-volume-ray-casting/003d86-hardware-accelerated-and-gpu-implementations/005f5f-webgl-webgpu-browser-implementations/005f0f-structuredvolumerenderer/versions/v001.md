# StructuredVolumeRenderer

Also called: Luma.gl StructuredVolumeRenderer, WebGPU Structured Volume Renderer

## Overview
StructuredVolumeRenderer is a reusable, graph-native GPU renderer for scalar, vector, and hybrid volume data implemented via the WebGPU API [S1, unofficial]. It solves the problem of rendering structured grid data (regular 2D/3D samples with explicit spacing) by exposing a consistent facade for forward, deferred, ray-traced, and ray-marched rendering pipelines [S1, unofficial]. It distinguishes itself from general-purpose hardware-accelerated ray casting by enforcing a strict "structured" data model where dimensions, backing types, and channel formats are construction-time invariants, and by providing manual eight-corner trilinear interpolation for both storage buffer and 3D texture backends [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input Data**: Float32 scalar buffers, WGSL-aligned float32x4 vector buffers, or matching float 3D textures [S1, unofficial].
*   **Transforms**: Model-to-volume matrix (`worldToVolumeMatrix`), camera parameters, and local bounds [S1, unofficial].
*   **Output**: Composed color and opacity per pixel, optionally with 3D arrow glyphs [S1, unofficial].

**Data Structures**
The renderer does not define a custom volume data structure but consumes standard WebGPU resources. Key constraints include:
*   **Storage Buffers**: Must be aligned to `device.limits.minStorageBufferOffsetAlignment` (commonly 256 bytes) [S1, unofficial].
*   **Textures**: 32-bit float textures (`r32float`, `rgba32float`) must be bound with `sampleType: 'unfilterable-float'` if the adapter lacks the `float32-filterable` feature [S1, unofficial].

**Numbered Steps**

1.  **Initialization**: Construct the renderer with fixed dimensions, backing type (buffer or texture), and channel format. These are invariants; compatible sources can be rebound later [S1, unofficial].
2.  **Ray Generation**:
    *   Compute `nearWorld` and `farWorld` by unprojecting the camera UV coordinates at depth 0.0 and 1.0 respectively [S1, unofficial].
    *   Transform `nearWorld` using `worldToVolumeMatrix` to get `rayOrigin` [S1, unofficial].
    *   Transform `farWorld` using `worldToVolumeMatrix` to get `rayTarget` [S1, unofficial].
    *   Calculate `rayDirection = normalize(rayTarget - rayOrigin)` [S1, unofficial].
    *   *Note*: Using a single camera position for all ray origins causes convergence in orthographic projections and ignores near-plane clipping in perspective cases [S1, unofficial].
3.  **Ray Marching**:
    *   Perform fixed-step jittered ray marching through the volume [S1, unofficial].
    *   At each step, sample the volume value.
4.  **Interpolation**:
    *   Perform manual eight-corner trilinear interpolation of the surrounding voxels [S1, unofficial]. This is done manually in the shader for both buffer and texture backends, rather than relying on hardware texture filtering [S1, unofficial].
5.  **Classification and Compositing**:
    *   Apply sequential or signed scalar transfer functions for scalar data, or direction/constant vector colors for vector data [S1, unofficial].
    *   Perform premultiplied front-to-back compositing [S1, unofficial].
    *   Apply Early Ray Termination (ERT) based on accumulated opacity [S1, unofficial].
6.  **Rendering**:
    *   Call `prepare(commandEncoder, options)` to set up bindings. This does not submit the command buffer [S1, unofficial].
    *   Call `draw(renderPass)` to execute the draw call [S1, unofficial].

**Pseudocode**

# Initialization
class StructuredVolumeRenderer:
    def __init__(self, device, scalar_source, vector_source=None):
        # scalar_source is either a StorageBuffer or a Texture
        # Dimensions and format are invariants
        self.device = device
        self.scalar_source = scalar_source
        self.vector_source = vector_source
        self.world_to_volume_matrix = None
        self.camera_matrix = None
        
    def bind_resources(self, command_encoder):
        # Handle storage buffer offset alignment
        if self.scalar_source.type == 'buffer':
            offset = self.scalar_source.offset
            # WebGPU requires offset to be multiple of minStorageBufferOffsetAlignment
            if offset % self.device.limits.minStorageBufferOffsetAlignment != 0:
                raise Error("Storage buffer offset not aligned")
            
            # Create binding
            binding = {
                'buffer': self.scalar_source.buffer,
                'offset': offset,
                'size': self.scalar_source.size
            }
        else:
            # Handle texture binding
            # Must specify unfilterable-float for 32-bit floats if float32-filterable is not supported
            sample_type = 'unfilterable-float'
            binding = {
                'texture': self.scalar_source.texture,
                'sample_type': sample_type,
                'view_dimension': '3d'
            }
        
        # Update bind group in command_encoder
        command_encoder.set_bind_group(0, self.bind_group, [binding])

    def compute_ray_parameters(self, camera_uv, camera_matrix, world_to_volume_matrix):
        # Unproject near and far planes
        near_world = unproject(camera_uv, 0.0)
        far_world = unproject(camera_uv, 1.0)
        
        # Transform to volume space
        ray_origin = transform_point(world_to_volume_matrix, near_world)
        ray_target = transform_point(world_to_volume_matrix, far_world)
        
        # Calculate direction
        ray_direction = normalize(ray_target - ray_origin)
        return ray_origin, ray_direction

    def trilinear_interpolate(self, volume_data, x, y, z):
        # Manual eight-corner trilinear interpolation
        # x, y, z are fractional coordinates within the voxel
        ix = floor(x)
        iy = floor(y)
        iz = floor(z)
        
        fx = x - ix
        fy = y - iy
        fz = z - iz
        
        # Get 8 corners
        c000 = volume_data[ix, iy, iz]
        c100 = volume_data[ix+1, iy, iz]
        c010 = volume_data[ix, iy+1, iz]
        c110 = volume_data[ix+1, iy+1, iz]
        c001 = volume_data[ix, iy, iz+1]
        c101 = volume_data[ix+1, iy, iz+1]
        c011 = volume_data[ix, iy+1, iz+1]
        c111 = volume_data[ix+1, iy+1, iz+1]
        
        # Interpolate along x
        d00 = lerp(c000, c100, fx)
        d10 = lerp(c010, c110, fx)
        d01 = lerp(c001, c101, fx)
        d11 = lerp(c011, c111, fx)
        
        # Interpolate along y
        d0 = lerp(d00, d10, fy)
        d1 = lerp(d01, d11, fy)
        
        # Interpolate along z
        return lerp(d0, d1, fz)

    def render(self, command_encoder, render_pass, camera_matrix, world_to_volume_matrix, viewport):
        self.bind_resources(command_encoder)

**Parameters**
*   **Ray Steps**: Fixed-step jittered marching [S1, unofficial].
*   **Termination**: Early opacity termination [S1, unofficial].
*   **Transfer Functions**: Sequential or signed scalar transfer functions; direction or constant vector colors [S1, unofficial].
*   **Viewport**: Viewport and scissor control [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Texture Binding Failure**: On adapters without the `float32-filterable` feature, binding `r32float` or `rgba32float` textures without explicitly setting `sampleType: 'unfilterable-float'` causes pipeline creation failure [S1, unofficial].
*   **Buffer Offset Alignment**: Storage buffer offsets must be multiples of `device.limits.minStorageBufferOffsetAlignment` (typically 256 bytes). Non-aligned offsets cause bind-group creation failure [S1, unofficial].
*   **Ray Origin Calculation**: Using a single camera position for ray origins in orthographic projections causes rays to converge incorrectly. Rays must start from the unprojected near plane [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of ray samples per pixel. The use of fixed-step marching implies a constant number of samples per ray, determined by the step size and volume depth.
*   **Memory Complexity**: Linear with respect to the volume data size. The renderer consumes the input buffers/textures directly.
*   **Performance**: Demonstrated on a 40³ volume with 72 ray samples per view, achieving 30 Hz updates for field and derivative calculations without volume readback [S1, unofficial].
*   **Strengths**: Reusable, graph-native integration with WebGPU; supports both buffer and texture backends; manual interpolation allows for consistent behavior across backends.
*   **Limitations**: Requires WebGPU support; construction-time invariants limit dynamic reconfiguration of data structure; manual interpolation may be slower than hardware filtering if the hardware supports it.

## Background
StructuredVolumeRenderer was introduced as part of the luma.gl library, specifically in PR #3104, to provide a reusable GPU primitive for volume rendering within a graph-native execution model [S1, unofficial]. It was developed to support the "Vector Field Lab" showcase, which includes animated Taylor–Green fields and sparse 3D glyphs [S1, unofficial]. The implementation emphasizes numerical verification and parity between buffer and texture backends [S1, unofficial].
