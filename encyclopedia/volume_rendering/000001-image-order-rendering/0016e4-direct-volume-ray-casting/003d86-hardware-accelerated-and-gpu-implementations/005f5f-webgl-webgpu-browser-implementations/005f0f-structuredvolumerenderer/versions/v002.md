# StructuredVolumeRenderer

Also called: luma.gl StructuredVolumeRenderer, Luma.gl Volume Renderer

## Overview
StructuredVolumeRenderer is a reusable, graph-native WebGPU renderer for scalar, vector, and hybrid volume data, exposing facades at `@luma.gl/scene/forward`, `/deferred`, `/raytrace`, and `/raymarch` [S1, unofficial]. It solves the problem of rendering structured grid data (buffers or 3D textures) in the browser by providing a fixed-step jittered ray marching implementation with front-to-back compositing [S1, unofficial]. It sets itself apart from sibling WebGL implementations by leveraging the WebGPU compute/render pipeline for direct GPU execution without CPU submission, and by supporting both storage buffer and 3D texture backing with manual trilinear interpolation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input Data:** `float32` scalar buffers, `WGSL`-aligned `float32x4` vector buffers, or matching `float` 3D textures [S1, unofficial].
*   **Input Transforms:** Model-to-world matrix (`worldToVolumeMatrix`), camera position, and view/projection matrices [S1, unofficial].
*   **Input Parameters:** Local bounds, viewport/scissor rectangles, transfer functions (sequential/signed scalar, direction/constant vector), and optional 3D glyph configurations [S1, unofficial].
*   **Output:** Rendered image with premultiplied front-to-back transparency [S1, unofficial].

**Data Structures:**
*   **Scalar Source:** Defined by `sources.scalar.type` ('buffer' or 'texture') and `sources.scalar.format` [S1, unofficial].
    *   If buffer: `read-only-storage` binding with `location: 0` [S1, unofficial].
    *   If texture: `texture_3d` binding with `viewDimension: '3d'` [S1, unofficial].
*   **Vector Source:** `WGSL`-aligned `float32x4` storage buffer [S1, unofficial].
*   **Binding Layout:** Texture bindings for 32-bit formats (`r32float`, `rgba32float`) must specify `sampleType: 'unfilterable-float'` to avoid pipeline creation failure on adapters lacking `float32-filterable` [S1, unofficial].

**Numbered Steps:**
1.  **Initialization:** Construct the renderer with fixed dimensions, backing type, and channel format. These are construction-time invariants [S1, unofficial].
2.  **Binding Setup:**
    *   For scalar buffers, validate offset alignment. The offset must be an integer, non-negative, and a multiple of `bytesPerElement` [S1, unofficial].
    *   Enforce WebGPU `device.limits.minStorageBufferOffsetAlignment` (commonly 256 bytes) for storage buffer offsets. If the source offset is not aligned, bind from an aligned base and apply a shader-side element offset [S1, unofficial].
    *   For scalar textures, set `sampleType: 'unfilterable-float'` for 32-bit formats [S1, unofficial].
3.  **Ray Generation:**
    *   Compute `nearWorld` and `farWorld` by unprojecting the camera UV coordinates at depth 0.0 and 1.0 respectively [S1, unofficial].
    *   Transform `nearWorld` using `worldToVolumeMatrix` to get `rayOrigin` [S1, unofficial].
    *   Transform `farWorld` using `worldToVolumeMatrix` to get `rayTarget` [S1, unofficial].
    *   Compute `rayDirection = normalize(rayTarget - rayOrigin)` [S1, unofficial].
    *   *Note:* Do not use a single camera position as the origin for all rays, as this causes convergence in orthographic projections and ignores near-plane clipping in perspective projections [S1, unofficial].
4.  **Ray Marching:**
    *   Perform fixed-step jittered ray marching [S1, unofficial].
    *   Sample the volume data using manual eight-corner trilinear interpolation for both buffer and texture backings [S1, unofficial].
    *   Apply transfer functions: sequential/signed scalar values or direction/constant vector colors [S1, unofficial].
    *   Composite using premultiplied front-to-back transparency [S1, unofficial].
    *   Terminate early if opacity threshold is reached [S1, unofficial].
5.  **Rendering:**
    *   Call `prepare(commandEncoder, options)` to set up the render pass [S1, unofficial].
    *   Call `draw(renderPass)` to execute the draw call [S1, unofficial].
    *   *Note:* These functions do not submit the command buffer internally; submission is handled by the caller [S1, unofficial].

        self.sources = sources

        self.dimensions = options.dimensions
        self.backing_type = options.backing_type
        self.channel_format = options.channel_format
        
        # Setup bindings
        self.bindings = self._setup_bindings(sources)

    def _setup_bindings(self, sources):
        bindings = {}
        # Scalar source binding
        if sources.scalar.type == 'buffer':
            offset = sources.scalar.offset if hasattr(sources.scalar, 'offset') else 0
            bytes_per_element = 4 # float32
            if not isinstance(offset, int) or offset < 0 or offset % bytes_per_element != 0:
                raise Error('Structured volume buffer offset is not aligned to its element format.')
            
            # Enforce device alignment
            min_alignment = self.device.limits.minStorageBufferOffsetAlignment
            if offset % min_alignment != 0:
                # Bind from aligned base and add shader-side offset
                aligned_offset = (offset // min_alignment) * min_alignment
                shader_offset = offset - aligned_offset
                bindings['scalar'] = {
                    'type': 'read-only-storage',
                    'group': 0,
                    'location': 0,
                    'buffer': sources.scalar.buffer,
                    'offset': aligned_offset,

**Parameters:**
*   **Ray Samples:** 72 ray samples per selected view in the showcase [S1, unofficial].
*   **Update Rate:** 30 Hz field/derivative updates without volume readback [S1, unofficial].
*   **Boundary Handling:** Selectable second-order one-sided or periodic boundary handling for finite difference calculations [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Float32 Texture Binding:** On adapters without `float32-filterable`, `r32float` and `rgba32float` sources fail if `sampleType` is omitted. Must be set to `unfilterable-float` [S1, unofficial].
*   **Storage Buffer Offset Alignment:** WebGPU requires offsets to be multiples of `minStorageBufferOffsetAlignment` (commonly 256). Non-aligned offsets cause bind-group creation failure [S1, unofficial].
*   **Ray Origin Calculation:** Using a single camera position as the origin for all rays causes convergence in orthographic projections and ignores near-plane clipping. Rays must start from the unprojected near plane [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of ray samples and volume depth. Fixed-step marching implies constant steps per ray.
*   **Memory Complexity:** Linear with respect to the volume data size (buffer or texture).
*   **Measured Performance:** 40³ showcase volume with 72 ray samples per view, 6³ glyph lattice, and 30 Hz field/derivative updates without volume readback [S1, unofficial].
*   **Strengths:** Reusable, graph-native, supports both buffers and textures, manual trilinear interpolation, early opacity termination.
*   **Limitations:** Fixed-step marching may be less efficient than adaptive methods. Requires WebGPU support.
*   **When to Use:** Browser-based volume rendering of structured grid data (scalar, vector, hybrid) where GPU performance is critical.
*   **When Not to Use:** When adaptive ray marching is required, or when running on hardware without WebGPU support.

## Background
StructuredVolumeRenderer was introduced as part of the luma.gl library to provide a reusable, graph-native GPU primitive for volume rendering [S1, unofficial]. It was developed to support the Vector Field Lab showcase, which includes animated Taylor–Green fields, divergence views, and curl glyphs [S1, unofficial]. The renderer is designed to be integrated into the luma.gl scene graph, exposing facades for forward, deferred, ray-tracing, and ray-marching rendering modes [S1, unofficial]. It is part of the ongoing development of WebGPU-based visualization tools in the visgl ecosystem.
