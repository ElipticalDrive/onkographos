# StructuredVolumeRenderer

Also called: luma.gl StructuredVolumeRenderer

## Overview
StructuredVolumeRenderer is a reusable, graph-native GPU renderer for scalar, vector, and hybrid volume data in WebGPU environments [S1, unofficial]. It consumes storage buffers or 3D textures and exposes scene renderer facades for forward, deferred, raytrace, and raymarch passes [S1, unofficial]. It distinguishes itself from sibling WebGL implementations by leveraging WebGPU's storage buffer and texture binding models, manual trilinear interpolation, and fixed-step jittered ray marching with early opacity termination [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**: Float32 scalar buffers, WGSL-aligned float32x4 vector buffers, or matching float 3D textures [S1, unofficial].
*   **Outputs**: Rendered image with premultiplied front-to-back transparency [S1, unofficial].

**Data Structures**
*   **Scalar Source**: Defined by `sources.scalar.type` ('buffer' or 'texture') [S1, unofficial].
    *   If 'buffer': Binding layout is `read-only-storage`, group 0, location 0 [S1, unofficial].
    *   If 'texture': Binding layout includes `viewDimension: '3d'` [S1, unofficial].
*   **Vector Source**: WGSL-aligned float32x4 buffers [S1, unofficial].
*   **Transforms**: `worldToVolumeMatrix` for coordinate transformation [S1, unofficial].
*   **Camera**: `cameraAndSamples.xyz` for ray origin derivation [S1, unofficial].

**Numbered Steps**
1.  **Source Binding Setup**: Determine binding type based on `sources.scalar.type`. If texture, set `viewDimension` to '3d' [S1, unofficial].
2.  **Offset Validation**: Check if buffer offset is an integer, non-negative, and aligned to `bytesPerElement` [S1, unofficial].
3.  **Ray Generation**:
    *   Compute `nearWorld` by unprojecting camera UV at depth 0.0 [S1, unofficial].
    *   Compute `farWorld` by unprojecting camera UV at depth 1.0 [S1, unofficial].
    *   Transform `nearWorld` using `worldToVolumeMatrix` to get `rayOrigin` [S1, unofficial].
    *   Transform `farWorld` using `worldToVolumeMatrix` to get `rayTarget` [S1, unofficial].
    *   Compute `rayDirection` as `normalize(rayTarget - rayOrigin)` [S1, unofficial].
4.  **Ray Marching**: Execute fixed-step jittered ray marching [S1, unofficial].
5.  **Interpolation**: Perform manual eight-corner trilinear interpolation for volume values [S1, unofficial].
6.  **Compositing**: Apply premultiplied front-to-back transparency [S1, unofficial].
7.  **Early Termination**: Terminate ray if accumulated opacity exceeds threshold [S1, unofficial].
8.  **Transfer Function**: Apply sequential/signed scalar transfer functions or direction/constant vector colors [S1, unofficial].

**Formulas**
*   Ray Origin: $O = M_{w2v} \cdot \text{unproject}(UV, 0.0)$
*   Ray Direction: $D = \text{normalize}(M_{w2v} \cdot \text{unproject}(UV, 1.0) - O)$
*   Compositing: Standard front-to-back alpha blending [S1, unofficial].

**Parameters**
*   **Ray Samples**: 72 samples per view in showcase [S1, unofficial].
*   **Boundary Handling**: Second-order centered differences in interior; selectable second-order one-sided or periodic boundary handling [S1, unofficial].
*   **Glyphs**: Optional 3D arrows (solid shaft-plus-cone SDFs) [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Texture Binding**: On adapters without `float32-filterable`, r32float/rgba32float textures must be bound with `unfilterable-float` sample type to avoid pipeline creation failure [S1, unofficial].
*   **Buffer Offset Alignment**: WebGPU requires storage buffer offsets to be multiples of `device.limits.minStorageBufferOffsetAlignment` (commonly 256) [S1, unofficial].
*   **Ray Origin**: Using a single camera position for orthographic projections causes rays to converge; using near plane unprojection ensures parallel rays and correct near-plane clipping [S1, unofficial].

**Pseudocode**
```python
def setup_binding(sources):
    if sources.scalar.type == 'buffer':
        return {
            'type': 'read-only-storage',
            'group': 0,
            'location': 0
        }
    else:
        return {
            'type': 'texture',
            'group': 0,
            'location': 0,
            'viewDimension': '3d'
        }

def validate_offset(binding, bytes_per_element):
    offset = binding.offset if 'offset' in binding else 0
    if not isinstance(offset, int) or offset < 0 or offset % bytes_per_element != 0:
        raise Error('Structured volume buffer offset is not aligned to its element format.')

def generate_ray(camera_uv, world_to_volume_matrix):
    near_world = unproject(camera_uv, 0.0)
    far_world = unproject(camera_uv, 1.0)
    ray_origin = transform_point(world_to_volume_matrix, near_world)
    ray_target = transform_point(world_to_volume_matrix, far_world)
    ray_direction = normalize(ray_target - ray_origin)
    return ray_origin, ray_direction

def render(command_encoder, render_pass, structured_volume):
    # Prepare and draw do not submit internally
    prepare(command_encoder, structured_volume.options)
    draw(render_pass, structured_volume)
```

## Subtopics

### WebGL Multi-pass Ray-casting with 3D Geometry Intersection
Uses multi-pass approach with 3D geometry intersection for ray-box intersection [6575-webgl-multi-pass-ray-casting-with-3d-geometry-intersection.md]. Choose when WebGL is required or when geometry-based intersection is preferred.

### WebGL Path Tracing Volume Rendering
Uses path tracing for more accurate lighting and scattering [8592-webgl-path-tracing-volume-rendering.md]. Choose when physically accurate lighting is needed and performance allows.

## Operating characteristics
*   **Time Complexity**: Fixed-step ray marching with 72 samples per view in showcase [S1, unofficial].
*   **Memory Complexity**: Depends on volume resolution; 40³ showcase volume used [S1, unofficial].
*   **Performance**: 30 Hz field/derivative updates without volume readback in showcase [S1, unofficial].
*   **Strengths**: Reusable, graph-native, supports scalar/vector/hybrid data, manual interpolation for control [S1, unofficial].
*   **Limitations**: Requires WebGPU, manual interpolation may be slower than hardware trilinear, alignment constraints [S1, unofficial].
*   **When to Use**: WebGPU environments, need for reusable renderer, scalar/vector/hybrid data [S1, unofficial].
*   **When Not to Use**: WebGL-only environments, need for hardware trilinear interpolation [S1, unofficial].

## Background
StructuredVolumeRenderer was introduced in luma.gl PR #3104 as part of the Vector Field Lab showcase [S1, unofficial]. It supports scalar, vector, and hybrid volume rendering, exposing facades for various rendering passes [S1, unofficial]. The renderer is designed to be reusable and graph-native, integrating with WebGPU's command encoding and rendering pass models [S1, unofficial].
