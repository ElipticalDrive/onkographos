# Volume Ray-Casting on Graphics Hardware

Also called: Stream model for volumetric ray-casting

## Overview
This method implements direct volume ray casting on programmable graphics hardware (specifically DirectX 9-level architectures like the ATI 9700) using a multi-pass stream model [S1, unofficial]. It solves the performance bottleneck of CPU-based ray casting by exploiting the intrinsic parallelism of fragment processors and efficient inter-pass communication via texture render targets [S1, unofficial]. Unlike single-pass hardware approaches, it separates ray traversal into discrete steps, using an early z-test mechanism to terminate ray processing once an opacity threshold is exceeded or an iso-surface is hit, thereby skipping empty space and reducing redundant computations [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset, camera parameters (position, view direction, projection), a transfer function mapping scalar values to color and opacity, and a termination threshold (opacity or iso-value).
*   **Output:** A 2D rendered image (color and opacity) stored in a texture or frame buffer.

**Data Structures:**
1.  **Volume Texture:** 3D texture storing scalar values.
2.  **Ray Direction Textures:** Two 2D textures storing the pre-computed ray direction vectors in local texture coordinates for each pixel.
3.  **Accumulation Textures:** Two 2D textures (one for color, one for opacity) used to store the accumulated result between passes. These serve as the render targets.
4.  **Iso-surface Texture:** A 2D texture storing the local texture coordinates of iso-surface intersection points (used in the final shading pass).
5.  **Z-Buffer:** Used for early z-testing to discard fragments.

**Numbered Steps:**

1.  **Pre-computation:** For each pixel in the viewport, compute the direction of the ray of sight through the volume in local texture coordinates. Store these directions in two 2D textures [S1, unofficial].
2.  **Multi-pass Ray Traversal:** Perform a fixed number of rendering passes. In each pass:
    a.  Bind the accumulation textures (from the previous pass) as input textures.
    b.  Bind the ray direction textures.
    c.  Bind the volume texture.
    d.  Execute a fragment shader that:
        i.  Retrieves the accumulated color ($C_{acc}$) and opacity ($\alpha_{acc}$) from the input textures.
        ii. Computes the current sample position along the ray using the ray direction and the current pass index.
        iii. Samples the volume texture at the current position to get the scalar value ($s$).
        iv. Applies the transfer function to get color ($c$) and opacity ($\alpha$).
        v.  Performs front-to-back compositing:
            $$ C_{new} = C_{acc} + c \cdot \alpha \cdot (1 - \alpha_{acc}) $$
            $$ \alpha_{new} = \alpha_{acc} + \alpha \cdot (1 - \alpha_{acc}) $$
        vi. Outputs $C_{new}$ and $\alpha_{new}$ to the accumulation textures (render targets) [S1, unofficial].
3.  **Termination Check Pass:** Between main traversal passes, execute an additional pass:
    a.  Read the accumulated opacity ($\alpha_{acc}$) from the accumulation texture.
    b.  Check if $\alpha_{acc}$ exceeds a specified threshold ($\alpha_{thresh}$) or if an iso-surface condition is met.
    c.  If the condition is true, set the fragment's depth value ($z$) to the maximum possible value (e.g., 1.0 in normalized device coordinates).
    d.  If the condition is false, set $z$ to 0.
    e.  Set the depth test function to `GREATER`. This ensures that if $z$ was set to the maximum, subsequent passes will fail the early z-test and be discarded [S1, unofficial].
4.  **Iso-surface Handling (Optional):** If an iso-surface is hit during traversal, store the intersection coordinates in a dedicated 2D texture.
5.  **Final Shading Pass:** If iso-surface coordinates are stored, perform a final pass that uses these coordinates to compute lighting (e.g., gradient-based shading) and restricts expensive gradient texture accesses to these specific points [S1, unofficial].

**Formulas:**
*   **Compositing:**
    $$ C_{out} = C_{in} + c \cdot \alpha \cdot (1 - \alpha_{in}) $$
    $$ \alpha_{out} = \alpha_{in} + \alpha \cdot (1 - \alpha_{in}) $$
    Where $C_{in}, \alpha_{in}$ are accumulated values, and $c, \alpha$ are the current sample's color and opacity [S1, unofficial].
*   **Depth Replacement:**
    $$ z_{out} = \begin{cases} 1.0 & \text{if } \alpha_{out} \ge \alpha_{thresh} \text{ or iso-surface hit} \\ 0.0 & \text{otherwise} \end{cases} $$
    With depth test `GREATER`, fragments with $z_{out}=1.0$ are discarded in subsequent passes [S1, unofficial].

**Parameters:**
*   **Opacity Threshold:** Not given in the sources.
*   **Number of Passes:** Fixed number, determined by the desired sampling density and volume extent. Not given in the sources.
*   **Iso-value:** User-defined scalar value for surface extraction. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point textures are required to store negative values and high-precision accumulated results. Standard 8-bit textures may cause precision loss [S1, unofficial].
*   **Dependent Texture Fetches:** Hardware limits the number of dependent texture fetches per fragment (e.g., on ATI 9700). This limits the complexity of the ray traversal logic within a single pass [S1, unofficial].
*   **Early Z-Test Dependency:** The early z-test optimization relies on the depth buffer being enabled and the depth test function being set correctly. If the depth buffer is not available or the test is disabled, the optimization fails [S1, unofficial].

**Pseudocode:**

```python
# Pre-computation
ray_directions = compute_ray_directions(viewport_width, viewport_height, camera_params)

# Pass 1 to N-1: Ray Traversal and Accumulation
for pass_index in range(1, num_passes):
    # Bind textures
    bind_texture(accumulated_color_texture, unit=0)
    bind_texture(accumulated_opacity_texture, unit=1)
    bind_texture(ray_direction_texture, unit=2)
    bind_texture(volume_texture, unit=3)
    
    # Set render targets
    set_render_target(accumulated_color_texture, unit=0)
    set_render_target(accumulated_opacity_texture, unit=1)
    
    # Execute fragment shader
    for each fragment (x, y):
        # Retrieve accumulated values
        C_acc = texture2D(accumulated_color_texture, uv)
        alpha_acc = texture2D(accumulated_opacity_texture, uv)
        
        # Get ray direction
        dir = texture2D(ray_direction_texture, uv)
        
        # Compute current sample position
        # Note: The exact formula for position depends on the ray origin and step size
        # which are typically passed as uniforms or derived from pass_index
        sample_pos = ray_origin + dir * (pass_index * step_size)
        
        # Sample volume
        s = texture3D(volume_texture, sample_pos)
        
        # Apply transfer function
        c, alpha = transfer_function(s)
        
        # Composite
        C_new = C_acc + c * alpha * (1.0 - alpha_acc)
        alpha_new = alpha_acc + alpha * (1.0 - alpha_acc)
        
        # Output
        color = C_new
        opacity = alpha_new

    # Termination Check Pass
    bind_texture(accumulated_opacity_texture, unit=0)
    set_render_target(z_buffer, unit=0) # Implicitly handled by depth buffer
    
    # Set depth test to GREATER
    set_depth_test_function(GREATER)
    
    for each fragment (x, y):
        alpha_acc = texture2D(accumulated_opacity_texture, uv)
        
        # Check termination condition
        if alpha_acc >= opacity_threshold or iso_surface_hit:
            depth = 1.0
        else:
            depth = 0.0
            
        # Write depth
        write_depth(depth)
        
        # If terminated, skip further processing
        if depth == 1.0:
            discard_fragment()

# Final Pass (if iso-surface)
if iso_surface_hit_detected:
    bind_texture(iso_surface_coords_texture, unit=0)
    bind_texture(volume_texture, unit=1)
    set_render_target(final_color_texture, unit=0)
    
    for each fragment (x, y):
        if iso_surface_coords_valid:
            coords = texture2D(iso_surface_coords_texture, uv)
            # Compute gradient and lighting
            gradient = compute_gradient(volume_texture, coords)
            color = shade(coords, gradient, light_params)
        else:
            color = texture2D(accumulated_color_texture, uv)
            
        write_color(color)
```

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the number of passes (sampling steps). $O(W \cdot H \cdot N)$, where $W, H$ are viewport dimensions and $N$ is the number of passes [S1, unofficial].
*   **Memory Complexity:** Proportional to the size of the volume texture and the accumulation textures. $O(V + W \cdot H)$, where $V$ is the volume data size [S1, unofficial].
*   **Measured Performance:** Performance gains up to a factor of 3 for typical renditions of volumetric data sets on the ATI 9700 graphics card [S1, unofficial].
*   **Scaling:** Scales with the number of fragment processors. Performance is limited by texture bandwidth and the number of dependent texture fetches [S1, unofficial].
*   **Strengths:** Effective early ray termination and empty-space skipping. Exploits hardware parallelism. Efficient communication between passes via texture render targets.
*   **Limitations:** Requires multiple passes, increasing overhead. Limited by dependent texture fetch counts. Precision issues with non-floating-point textures.
*   **When to Use:** When real-time or interactive rendering of large volumetric datasets is required on hardware supporting Pixel Shader 2.0 and texture render targets. [S1, unofficial]
*   **When Not to Use:** When hardware lacks floating-point texture support or dependent texture fetch limits are too restrictive for the desired accuracy. [S1, unofficial]

## Background
The method was proposed in 2003 by researchers associated with the Technical University of Munich (TUM) [S1, unofficial]. It was developed to address the challenge of real-time volume rendering of large scalar fields, which was not feasible on general-purpose CPUs at the time. The work leveraged the emerging programmable graphics hardware (DirectX 9 level) and the Pixel Shader 2.0 API [S1, unofficial]. It is used in applications requiring interactive visualization of volumetric data, such as medical imaging and scientific visualization [S1, unofficial].
