# Hardware-Accelerated AMR Volume Rendering via Homogenization

Also called: AMR Partition Tree Rendering, Tiling AMR domain with grid patches

## Overview
This method renders Adaptive Mesh Refinement (AMR) data by preprocessing the hierarchy into a set of non-overlapping Cartesian grid patches, allowing standard Direct Volume Ray Casting (DVR) algorithms to be used without resampling [S1, S2, unofficial]. It differs from methods that resample AMR data to a uniform grid or render individual grids with complex boundary handling by explicitly tiling the domain with homogeneous resolution regions [S1, S2, unofficial].

## How it works
**Inputs:** An AMR dataset satisfying the Berger–Colella constraints: integer refinement ratios (typically 2 or 4) between adjacent levels, no partial refinement of cells, and no overlapping grids within the same hierarchy level [S1, unofficial].
**Outputs:** A view-dependent back-to-front ordered list of grid patches, each rendered as an RGB image with an alpha channel, composited into the final image [S1, unofficial].

**Data Structures:**
1. **AMR Partition Tree:** A generalized kD-tree where each leaf represents a single grid patch [S2, unofficial].
2. **Grid Patch:** Defined as a rectangular subgrid of a single AMR grid, containing cells of identical size and data stored in a single contiguous memory region [S1, unofficial].

**Algorithm Steps:**
1. **Initialize Tree:** Create a kD-tree with a single root leaf representing the entire AMR domain [S1, unofficial].
2. **Insert Grids:** Iterate through AMR grids in order of increasing resolution (finest last) [S1, unofficial]. For each grid, traverse the kD-tree downwards [S1, unofficial]. Existing interior kD-tree nodes implicitly split the incoming grid into candidate patches [S1, unofficial]. If an interior node is completely contained inside one of the candidate patches created by the incoming grid, replace that node and its entire subtree with a single leaf representing that new higher-resolution patch [S1, unofficial]. If an existing kD-tree leaf is partially overlaid by the incoming grid patch, recursively split that leaf into a set of non-overlapped patches (retaining the coarse resolution) and a single overlaid patch [S1, unofficial]. Replace the overlaid patch with the new higher-resolution grid patch [S1, unofficial].
3. **Enumerate Order:** Perform a directed depth-first traversal of the resulting kD-tree to determine rendering order [S1, unofficial]. At each internal node, compare the camera viewpoint with the node's dividing plane [S1, unofficial]. Traverse the subtree corresponding to the region "behind" the dividing plane (from the viewpoint's perspective) first [S1, unofficial]. Traverse the other region second [S1, unofficial]. This ensures that no patch rendered in the first traversal can occlude any patch rendered in the second, guaranteeing correct front-to-back compositing even if the viewpoint is inside the domain [S1, unofficial].
4. **Render:** For each patch in the enumerated order, upload the patch data to 3D texture memory and execute standard hardware-accelerated DVR (ray generation, sampling, compositing) [S1, S2, unofficial]. Patches are composited into the frame buffer, typically using hardware alpha blending [S1, unofficial].

**Compositing Formulas:**
The standard front-to-back emission-absorption model updates accumulated color $C'$ and opacity $\alpha'$ at each step $i$:
$$
C'_{i} = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i
$$
$$
\alpha'_{i} = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i
$$
where $\alpha_i$ and $C_i$ are the sampled opacity and color at the current step, and $\alpha'$ is clamped to $1.0$ to prevent floating-point accumulation errors and enable early ray termination [G].

**Pseudocode:**
```python
class KDTreeNode:
    def __init__(self, min_c, max_c, is_leaf=True, patch=None, children=None, plane=None):
        self.min_c = min_c
        self.max_c = max_c
        self.is_leaf = is_leaf
        self.patch = patch
        self.children = children if children else []
        self.plane = plane  # (axis, coord)

class Patch:
    def __init__(self, grid_id, min_c, max_c, res):
        self.grid_id = grid_id
        self.min_c = min_c
        self.max_c = max_c
        self.res = res

def build_partition_tree(amr_grids, domain_min, domain_max):
    root = KDTreeNode(domain_min, domain_max, is_leaf=True, patch=None)
    sorted_grids = sorted(amr_grids, key=lambda g: g.resolution)
    for grid in sorted_grids:
        insert_grid(root, grid)
    return root

def insert_grid(node, grid):
    if node.is_leaf:
        if grid.min_c <= node.min_c and grid.max_c >= node.max_c:
            node.is_leaf = False
            node.patch = Patch(grid.id, node.min_c, node.max_c, grid.resolution)
            node.children = []
        else:
            split_leaf(node, grid)
    else:

            if box_intersects(child.min_c, child.max_c, grid.min_c, grid.max_c):
                insert_grid(child, grid)

def traverse_for_order(node, viewpoint, order_list):
    if node.is_leaf:
        if node.patch:
            order_list.append(node.patch)
        return
    behind_child, front_child = node.children[0], node.children[1]
    if point_behind_plane(viewpoint, node.plane):
        traverse_for_order(behind_child, viewpoint, order_list)
        traverse_for_order(front_child, viewpoint, order_list)
    else:
        traverse_for_order(front_child, viewpoint, order_list)
        traverse_for_order(behind_child, viewpoint, order_list)

def render_patches(patches, camera, transfer_function):
    for patch in patches:
        for pixel in patch.screen_bounds:
            ray_o = camera.get_ray_origin(pixel)
            ray_d = camera.get_ray_direction(pixel)
            t_min, t_max = compute_intersection(ray_o, ray_d, patch.min_c, patch.max_c)
            if t_max < t_min: continue
            acc_color = [0.0, 0.0, 0.0]
            acc_alpha = 0.0
            t = t_min
            dt = patch.res
            while t < t_max and acc_alpha < 1.0:
                sample_pos = ray_o + ray_d * t
                val = sample_volume(patch.grid_id, sample_pos)
                alpha_i, color_i = transfer_function(val)
                weight = (1.0 - acc_alpha) * alpha_i
                acc_color = [c + weight * color_i for c in acc_color]
                acc_alpha += weight
                acc_alpha = min(acc_alpha, 1.0)
                t += dt
            write_pixel(pixel, acc_color, acc_alpha)
```

**Parameters:**
*   **Refinement Ratios:** Integers, typically 2 or 4 [S1, unofficial].
*   **Transfer Function Scaling:** Opacity and saturation scaling may be applied to handle varying resolution levels [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Viewpoint Inside Domain:** The kD-tree traversal order handles this correctly by using the viewpoint to determine "behind" vs "front" relative to dividing planes [S1, unofficial].
*   **Partial Refinement:** The method assumes no partial refinement; if present, the algorithm is undefined [S1, unofficial].
*   **Precision:** Using hardware-accelerated DVR avoids varying sample distances associated with texture slicing, offering higher precision [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Preprocessing (homogenization) is computationally efficient, relying on kD-tree insertions [S2, unofficial]. Rendering time scales with the number of grid patches and the complexity of the transfer function [S2, unofficial].
*   **Memory Complexity:** Requires storing the kD-tree structure and the AMR data [S2, unofficial]. Grid patches are stored in contiguous memory regions [S1, unofficial].
*   **Performance:** Homogenization is cited as the most efficient way to render AMR hierarchies because it is computationally efficient and allows the use of standard, optimized hardware-accelerated methods [S2, unofficial].
*   **Strengths:** No resampling required; leverages standard DVR hardware; correct compositing order guaranteed by kD-tree traversal [S1, S2, unofficial].
*   **Limitations:** Requires AMR data to satisfy specific constraints (integer refinement ratios, no partial refinement) [S1, unofficial]. The number of patches can increase significantly with complex AMR structures, potentially increasing draw calls [S1, unofficial].

## Background
The method was developed to address the challenges of rendering AMR data, which does not fit standard Cartesian grid rendering algorithms [S1, unofficial]. It was presented in the context of interactive direct volume rendering for AMR data, specifically tested on a star cluster formation simulation (Root level 32x32x32, data from Greg Bryan, Theoretical Astronomy Group, MIT) [S2, unofficial]. The approach builds on earlier work by Kähler & Hege (2001/2002) regarding texture-based AMR volume rendering and was further refined for GPU-assisted raycasting [S2, unofficial].
