# GPU Based Single-Pass Raycasting

Also called: Single-pass raycaster, Volume Rendering Component

## Overview
GPU Based Single-Pass Raycasting is a volume rendering technique where the volume is traversed along a single ray per pixel, implemented within the Volume Rendering Component framework [S1, unofficial]. It solves the limitations of polygonal-based methods (which are limited in expressive power) and slicing techniques (which can lead to artifacts) by providing high-quality visual results [S1, unofficial]. It is distinguished from its siblings by its implementation as a single-pass fragment shader execution on modern graphics hardware [S1, unofficial]. It builds on [Hardware-Accelerated and GPU Implementations](9525-hardware-accelerated-and-gpu-implementations.md) and implements the emission-absorption optical model defined in [Direct volume ray casting](19-direct-volume-ray-casting.md).

## How it works
The method operates within the Volume Rendering Component, separating scene graph responsibilities into data representation (`VolumeData`) and rendering styles (`VolumeRenderStyle`) [S1, unofficial]. The core algorithm executes a ray marching loop in the fragment shader for each pixel [S1, unofficial].

### Inputs and Outputs
*   **Input**: A 3D texture volume (`voxels`), camera parameters, ray generation settings (`stepSize`, `type`), acceleration settings (`boundingVolumeType`, `traversalFunction`), normal calculation settings (`algorithm`), and transfer functions (`OpacityMap`) [S1, unofficial].
*   **Output**: A 2D image with accumulated color and opacity per pixel.

### Data Structures
The primary data structure is the `VolumeData` node, which holds the volume data in its `voxels` field (an `MFNode` holding a 3D texture) [S1, unofficial]. Additional fields include:
*   `sliceThickness` (`SFVec3f`): Default `(1,1,1)`. Used to handle non-equidistant grids [S1, unofficial].
*   `dimensions` (`SFVec3f`): Currently unused [S1, unofficial].
*   `swapped` (`SFBool`): Helper for 16-bit volume byte swapping [S1, unofficial].

Rendering settings are encapsulated in:
*   `AccelerationVolumeSettings`: Contains `boundingVolumeType` (`"boxGeometry"` or `"boundaryGeometry"`) for outer space skipping and `traversalFunction` (`"simple"` or `"blockSkipping"`) for inner space skipping [S1, unofficial].
*   `NormalVolumeSettings`: Contains `algorithm` (`"precomputedCentralDifferences"`, `"onlineCentralDifferences"`, or `"onlineSobel"`) [S1, unofficial].
*   `RayGenerationVolumeSettings`: Contains `type` (`"simple"` or `"interleaved"`) and `stepSize` (e.g., `0.0039`) [S1, unofficial].
*   `OpacityMapVolumeStyle`: Contains `transferFunction` (an `ImageTexture`) and `type` (`"simple"` or `"preintegrated"`) [S1, unofficial].

### Steps
1.  **Volume Loading**: Load the volume data into a 3D texture [S1, unofficial]. Handle byte swapping if necessary using the `swapped` field [S1, unofficial]. Adjust sampling coordinates based on `sliceThickness` if the grid is non-equidistant [S1, unofficial].
2.  **Ray Generation**: For each pixel, generate a ray [S1, unofficial]. The `type` parameter determines the generation strategy:
    *   `"simple"`: Standard per-pixel ray generation.
    *   `"interleaved"`: Interleaved ray generation to mitigate wood artifacts [S1, unofficial].
3.  **Acceleration (Outer Space Skipping)**: Determine the entry and exit points of the ray through the volume bounding box [S1, unofficial]. The `boundingVolumeType` in `AccelerationVolumeSettings` selects between `"boxGeometry"` or `"boundaryGeometry"` [S1, unofficial].
4.  **Acceleration (Inner Space Skipping)**: Traverse the volume from entry to exit [S1, unofficial]. The `traversalFunction` in `AccelerationVolumeSettings` selects between `"simple"` or `"blockSkipping"` [S1, unofficial].
5.  **Sampling and Classification**: At each step along the ray, sample the 3D texture using hardware-accelerated trilinear interpolation [S1, unofficial]. Apply the transfer function (defined in `OpacityMapVolumeStyle`) to determine color $C_i$ and opacity $\alpha_i$ [S1, unofficial]. The `type` in `OpacityMapVolumeStyle` selects between `"simple"` or `"preintegrated"` [S1, unofficial].
6.  **Normal Calculation**: If lighting is enabled (`ShadedVolumeStyle.lighting = TRUE`), calculate surface normals [S1, unofficial]. The `algorithm` in `NormalVolumeSettings` determines the method:
    *   `"precomputedCentralDifferences"`: Fastest [S1, unofficial].
    *   `"onlineCentralDifferences"`: Usually most appropriate [S1, unofficial].
    *   `"onlineSobel"`: Nicest [S1, unofficial].
7.  **Compositing**: Perform front-to-back compositing using the standard emission-absorption model:
    $$
    C'_{i} = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i
    $$
    $$
    \alpha'_{i} = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i
    $$

### Pseudocode
```python
def raycast(volume, origin, direction, step_size, bounds_min, bounds_max, transfer_function, lighting_enabled=False):
    # Normalize direction
    dir_len = (direction[0]**2 + direction[1]**2 + direction[2]**2)**0.5
    if dir_len == 0:
        return [0.0, 0.0, 0.0, 0.0]
    d = [direction[i] / dir_len for i in range(3)]
    
    # Compute entry and exit t values for AABB
    t_min = 0.0
    t_max = float('inf')
    for i in range(3):
        if d[i] == 0:
            if origin[i] < bounds_min[i] or origin[i] > bounds_max[i]:
                return [0.0, 0.0, 0.0, 0.0]
        else:
            t1 = (bounds_min[i] - origin[i]) / d[i]
            t2 = (bounds_max[i] - origin[i]) / d[i]
            t_enter = min(t1, t2)
            t_exit = max(t1, t2)
            t_min = max(t_min, t_enter)
            t_max = min(t_max, t_exit)
            
    if t_min >= t_max:
        return [0.0, 0.0, 0.0, 0.0]
        
    accumulated_color = [0.0, 0.0, 0.0]
    accumulated_opacity = 0.0
    
    t = t_min
    while t < t_max and accumulated_opacity < 0.95:
        # Sample position
        pos = [origin[i] + t * d[i] for i in range(3)]
        
        # Sample volume (assume trilinear interpolation handled by volume access)
        value = volume.sample(pos)
        
        # Apply transfer function
        alpha, color = transfer_function(value, step_size)
        
        # Lighting (if enabled)
        if lighting_enabled:
            normal = volume.compute_normal(pos)
            # Lighting model applied here
            
        # Compositing
        if accumulated_opacity >= 1.0:
            break
            
        accumulated_color[0] += (1.0 - accumulated_opacity) * alpha * color[0]
        accumulated_color[1] += (1.0 - accumulated_opacity) * alpha * color[1]
        accumulated_color[2] += (1.0 - accumulated_opacity) * alpha * color[2]
        accumulated_opacity += (1.0 - accumulated_opacity) * alpha
        
        t += step_size
        
    return accumulated_color + [accumulated_opacity]
```

### Parameters and Typical Values
*   `stepSize`: Controls the distance between samples. A smaller value increases quality but reduces performance. Example value: `0.0039` [S1, unofficial].
*   `type` (RayGeneration): `"simple"` or `"interleaved"`. `"interleaved"` reduces wood artifacts [S1, unofficial].
*   `boundingVolumeType`: `"boxGeometry"` or `"boundaryGeometry"`. Used for outer space skipping [S1, unofficial].
*   `traversalFunction`: `"simple"` or `"blockSkipping"`. Used for inner space skipping to improve performance [S1, unofficial].
*   `type` (OpacityMap): `"simple"` or `"preintegrated"`. `"preintegrated"` often leads to a much better look [S1, unofficial].
*   `algorithm` (NormalVolumeSettings): `"precomputedCentralDifferences"` (fastest), `"onlineCentralDifferences"` (usually most appropriate), `"onlineSobel"` (nicest) [S1, unofficial].
*   `lighting`: Boolean. If `TRUE`, lighting effects are calculated [S1, unofficial].

### Edge Cases and Pitfalls
*   **Wood Artifacts**: Can occur in raycasting. Mitigated by using the `"interleaved"` ray generation type [S1, unofficial].
*   **Non-equidistant Grids**: Handled by the `sliceThickness` field in `VolumeData`, defaulting to `(1,1,1)` [S1, unofficial].
*   **16-bit Volume Byte Swapping**: Handled by the `swapped` field in `VolumeData` [S1, unofficial].
*   **Hardware Requirements**: Requires modern graphics hardware [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of steps along the ray, which depends on the volume size, `stepSize`, and ray length. Acceleration techniques (`blockSkipping`) can reduce the effective number of steps.
*   **Memory Complexity**: Dominated by the storage of the 3D volume texture. The `VolumeData` node holds the volume in `voxels`.
*   **Measured Performance**: Performance is heavily dependent on GPU capabilities and the complexity of the transfer function and lighting calculations. Preintegrated opacity and block skipping can improve performance.
*   **Strengths**: High visual quality, handles complex transfer functions and lighting, avoids artifacts associated with slicing.
*   **Limitations**: Requires modern graphics hardware, can be computationally expensive for large volumes or small step sizes. Limited to one volume per scene in the current implementation [S1, unofficial].
*   **When to Use**: When high-quality volume visualization is required and modern graphics hardware is available.
*   **When Not to Use**: When hardware does not support 3D textures or fragment shaders, or when real-time performance on low-end hardware is critical.

## Background
The GPU Based Single-Pass Raycasting method is implemented within the Volume Rendering Component, an X3D extension proposal. It was developed to alleviate the drawbacks of polygonal-based methods and slicing techniques. The component separates scene graph responsibilities into data representation and rendering styles, allowing for flexible configuration of rendering parameters. The implementation relies on GPU-based single-pass raycasting, traversing the volume along a single ray per pixel [S1, unofficial].
