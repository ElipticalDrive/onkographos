# Hardware-assisted Volume Deformation

Also called: Deformed Volume Rendering via Inverse Deformation in Fragment Shaders, Shader-based volume warping

## Overview
Hardware-assisted volume deformation renders non-linearly deformed volumes by integrating the deformation process directly into the fragment shader, avoiding the computational expense of pre-computing a resampled deformed volume [S1]. Unlike methods that pre-compute the deformed volume, this approach allows for dynamic deformations at interactive rates by evaluating the inverse deformation function per-pixel [S1]. It builds on [Hardware-Accelerated and GPU Implementations](9525-hardware-accelerated-and-gpu-implementations.md) by modifying the texture coordinate generation and sampling logic to account for spatial transformations [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Undeformed volume data $v$ stored in a 3D texture; inverse deformation function $u = d^{-1}$, where $d$ maps undeformed object space to deformed object space [S1].
*   **Output:** Rendered image with accumulated color and opacity [S1].

**Data Structures:**
*   **3D Texture:** Stores the scalar field of the undeformed volume $v$. Coordinates in this texture correspond to undeformed object space (texture space) [S1].
*   **Proxy Geometry:** A series of polygons (view-aligned planes) aligned with the image plane. These polygons define the sampling planes in view space [S1].
*   **Texture Coordinates:** Assigned to each polygon fragment representing the deformed object-space coordinates [S1].
*   **Inverse Deformation Function ($u$):** The mapping from deformed object space to undeformed object space [S1].

**Numbered Steps:**
1.  **Setup:** Store the undeformed volume data $v$ in a 3D texture [S1].
2.  **Geometry:** Draw a series of polygons aligned with the image plane (view-aligned planes) in back-to-front order [S1].
3.  **Texture Coordinates:** Assign texture coordinates to each polygon fragment representing the deformed object-space coordinates [S1].
4.  **Fragment Shader Execution:** For each fragment:
    a.  Retrieve the deformed object-space coordinates ($\mathbf{x}_{deformed}$) from the interpolated texture coordinates [S1].
    b.  Apply the inverse deformation function $u$ to these coordinates to obtain undeformed object-space coordinates ($\mathbf{x}_{undeformed}$):
        $$ \mathbf{x}_{undeformed} = u(\mathbf{x}_{deformed}) $$ [S1].
    c.  Sample the 3D texture using $\mathbf{x}_{undeformed}$ to retrieve the scalar value $d$:
        $$ d = \text{texture3D}(texD, \mathbf{x}_{undeformed}) $$ [S1].
    d.  Apply the transfer function to $d$ to compute the color $C$ and opacity $\alpha$ [S1].
    e.  Accumulate the color and opacity into the framebuffer using back-to-front compositing [S1].

**Formulas:**
The deformed volume $v'$ is defined as the composition of the undeformed volume $v$ and the inverse deformation function $u$:
$$ v'(x, y, z) = (v \circ u)(x, y, z) $$
where $u = d^{-1}$ and $d$ is the deformation mapping from undeformed to deformed object space [S1].

**Parameters:**
*   **Inverse Deformation Function ($u$):** The mapping from deformed object space to undeformed object space. If only the forward deformation $d$ is provided, $u$ must be computed using scattered data interpolation [S1].

**Edge Cases and Pitfalls:**
*   **Aliasing:** Point sampling in the volume texture can lead to aliasing. To correctly filter the warp, the kernel radius must be determined for the spacing of the sampling in texture space, not object space [S1].
*   **Resource Limits:** Fragment programs have limited resources, making some complex deformation functions impractical to implement directly in the shader [S1].
*   **Non-Uniform Sampling:** If the spacing of samples in view space is non-uniform, errors may occur. These can be addressed through non-planar proxy geometry or applying a per-pixel correction factor [S1].

**Pseudocode:**
```python
def render_deformed_fragment(textCoord, volume_texture, inverse_deform, transfer_fn, acc_color, acc_opacity):
    # 1. Get deformed object-space coordinates from texture coordinates
    deformed_coords = textCoord

    # 2. Apply inverse deformation to get undeformed (texture space) coordinates
    undeformed_coords = inverse_deform(deformed_coords)

    # 3. Sample the undeformed volume texture [G] standard GPU texture sampling
    scalar_value = texture3D(volume_texture, undeformed_coords)

    # 4. Apply transfer function to get color and opacity
    color, opacity = transfer_fn(scalar_value)

    # 5. Back-to-front compositing update
    acc_color = acc_color + (1.0 - acc_opacity) * opacity * color
    acc_opacity = acc_opacity + (1.0 - acc_opacity) * opacity

    return acc_color, acc_opacity
```

## Operating characteristics
*   **Time Complexity:** The deformation function $u$ is evaluated per fragment [S1].
*   **Memory Complexity:** Requires storing the undeformed volume in a 3D texture [S1].
*   **Strengths:** Allows for dynamic, interactive deformations without pre-computation. Leverages GPU hardware for parallel texture sampling and compositing [S1].
*   **Limitations:** Limited by fragment program resources for complex deformation functions. Aliasing issues if not properly filtered [S1].
*   **When to use:** Interactive visualization of deforming volumes, such as in non-linear registration or real-time animation [S1].
*   **When not to use:** When the deformation is static and can be pre-computed, or when the deformation function is too complex for the fragment shader [S1].

## Background
This method was introduced in "Integrating Dynamic Deformations into Interactive Volume Visualization" [S1]. It addresses the limitation of traditional volume rendering where deformations require expensive 3D resampling, precluding dynamic deformations [S1]. By integrating the deformation into the rendering pipeline, it enables interactive rates for applications like non-linear registration and real-time volume animation [S1].
