# VIRIM Architecture

Also called: Virtual Reality in Medicine, VIRIM

## Overview
VIRIM is an object-order volume rendering engine developed at the University of Mannheim and commercially distributed by Volume Graphics GmbH [S1]. It implements projection plane raycasting, where rays belonging to a particular scanline reside on the same projection plane and are resampled in top-to-bottom order [S1]. The architecture is characterized by its flexibility, utilizing a farm of programmable Digital Signal Processors (DSPs) for the ray-casting portion of the algorithm, allowing users to implement different visualization models and balance image quality versus rendering speed [S2]. Unlike VOGUE, which partitions the dataset, VIRIM replicates the entire volume memory in each parallel geometry unit to circumvent data dependency problems [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume data stored in 8-way interleaved memory; density lookup table; gradient estimation parameters [S1].
*   **Output:** Final image pixels generated by DSPs [S1].

**Data Structures:**
*   **Volume Memory:** 8-way interleaved memory system. Maximum dataset size is $256^3$ for 16-bit voxels [S1].
*   **Geometry Bus:** Transmits sample density and X/Y-gradient components to the ray-casting unit. Width: 48 bits; Clock: 40 MHz; Peak transfer rate: 240 MB/s [S1].
*   **Density Lookup Table:** Maps voxel values to density values [S1].
*   **DSPs:** 16 programmable digital signal processors [S1].

**Steps:**
1.  **Memory Organization:** Store volume data in an 8-way interleaved memory system [S1].
2.  **Density Mapping:** Map voxel values to density values using a density lookup table [S1].
3.  **Gradient Estimation:** Estimate the X- and Y-components of the gradient using a 2D gradient operator [S1].
4.  **Transmission:** Transmit sample density and X/Y-gradient components to the ray-casting unit over the geometry bus (48 bits @ 40 MHz) [S1].
5.  **Ray Casting and Shading:** Use the 16 programmable DSPs to generate the final image using high-quality illumination models, such as the Heidelberg ray-tracing algorithm which includes shadowing [S1].
6.  **Image Assembly:** A local master processor on the ray-casting board collects all scan lines of the final image from the DSP memories and transfers the results to the host system [S1].

**Pseudocode:**
```python
def virim_render(volume_data, density_lut, gradient_operator):
    # 1. Memory Access: Read volume data from 8-way interleaved memory [S1].
    #    Max dataset size: 256^3 voxels (16-bit) [S1]. Max read-out rate: 640 MB/s [S1].
    #    For parallel geometry units, replicate the entire volume memory in each unit [S2].
    samples = [volume_data[i] for i in range(len(volume_data))] # Not given in the sources.

    # 2. Density Mapping: Map voxel values to density values using a density lookup table [S1].
    densities = [density_lut[v] for v in samples]

    # 3. Gradient Estimation: Estimate X- and Y-component of the gradient using a 2D gradient operator [S1].
    x_grad = [gradient_operator.compute_x(v) for v in densities] # Not given in the sources.
    y_grad = [gradient_operator.compute_y(v) for v in densities] # Not given in the sources.

    # 4. Transmission: Send sample density and X/Y-gradient components to the ray-casting unit over the geometry bus (48 bits @ 40 MHz, 240 MB/s) [S1].
    bus_payload = []
    for d, x, y in zip(densities, x_grad, y_grad):
        bus_payload.append((d, x, y)) # Not given in the sources.
    # send_to_ray_casting_unit(bus_payload) # Not given in the sources.

    # 5. Ray Casting & Shading: Process samples using a farm of 16 programmable DSPs [S1].
    #    Implement high-quality illumination models (e.g., Heidelberg ray-tracing with shadowing) [S1].
    #    Assign fixed functions (e.g., reconstruction of arbitrarily oriented slices) to dedicated hardware units [S2].
    scanlines = []
    for i in range(16):
        scanline = []
        for sample in bus_payload:
            scanline.append(sample) # Not given in the sources.
        scanlines.append(scanline)

    # 6. Image Assembly: Local master processor collects all scan lines from DSP memories and transfers to host [S1].
    image = []
    for scanline in scanlines:
        image.extend(scanline) # Not given in the sources.
    return image
```

**Parameters:**
*   **Geometry Bus:** 48 bits width, 40 MHz clock, 240 MB/s peak transfer rate [S1].
*   **Volume Memory:** 8-way interleaved [S1].
*   **DSPs:** 16 programmable processors [S1].
*   **Max Dataset Size:** $256^3$ voxels (16-bit) [S1].
*   **Max Read-out Rate:** 640 MB/s [S1].

**Edge Cases and Pitfalls:**
*   **Polygon Intermixing:** VIRIM does not allow arbitrary intermixing of volumes and polygons [S1].
*   **Data Dependency:** To circumvent data dependency problems in parallel operation, the entire volume memory is replicated in each parallel geometry unit [S2].
*   **Precision:** Not given in the sources.

## Operating characteristics
*   **Time Complexity:** Not explicitly defined in terms of Big-O; performance is measured in frames per second [S1].
*   **Memory Complexity:** Maximum dataset size is $256^3$ for 16-bit voxels [S1]. Memory is replicated across parallel geometry units to circumvent data dependency problems [S2].
*   **Measured Performance:** Geometry unit generates a maximum of 36 million tri-linear samples per second [S1]. Achieves up to 2.5 frames per second for $256 \times 256 \times 128$ datasets [S1].
*   **Scaling:** Higher rendering performance is achieved by duplicating the dataset across multiple VIRIM engines [S1].
*   **Strengths:** Flexibility and versatility for a large variety of application areas [S2]. Programmable DSPs allow users to implement different visualization models and balance image quality versus rendering speed [S2]. Dedicated hardware units provide maximum speed for fixed functions like reconstruction of arbitrarily oriented slices [S2].
*   **Limitations:** Does not allow arbitrary intermixing of volumes and polygons [S1]. Replicating volume memory in each parallel geometry unit increases memory requirements compared to partitioning approaches [S2].
*   **When to use:** When flexibility and high-quality illumination models (e.g., shadowing) are required, and the dataset size fits within the $256^3$ limit [S1, S2].
*   **When not to use:** When arbitrary intermixing of volumes and polygons is needed, or when memory efficiency is critical and partitioning is preferred [S1, S2].

## Background
*   **Origin:** VIRIM is an object-order volume rendering engine developed and built at the University of Mannheim and commercially distributed by the Volume Graphics GmbH, Heidelberg, Germany [S1].
*   **History:** The architecture was presented in comparative studies with VOGUE and Cube-3 in 1995 [S2]. It represents a solution characterized by flexibility, using object order ray-casting [S2].
*   **Usage:** Used for real-time volume rendering [S1].
