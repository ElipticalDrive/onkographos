# VIRIM Architecture

Also called: Virtual Reality in Medicine, VIRIM

## Overview
VIRIM is an object-order volume rendering engine developed at the University of Mannheim and commercially distributed by Volume Graphics GmbH [S1, S2]. It implements projection plane raycasting, where rays belonging to a particular scanline reside on the same projection plane and are resampled in top-to-bottom order [S1]. The architecture is characterized by its flexibility, utilizing a farm of programmable Digital Signal Processors (DSPs) for the ray-casting portion of the algorithm, allowing users to implement different visualization models and balance image quality versus rendering speed [S2]. Unlike VOGUE, which partitions the dataset, VIRIM replicates the entire volume memory in each parallel geometry unit to circumvent data dependency problems [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume data stored in 8-way interleaved memory; density lookup table; gradient estimation parameters.
*   **Output:** Final image pixels generated by DSPs.

**Data Structures:**
*   **Volume Memory:** 8-way interleaved memory system. Maximum dataset size is $256^3$ for 16-bit voxels [S1].
*   **Geometry Bus:** Transmits sample density and X/Y-gradient components to the ray-casting unit. Width: 48 bits; Clock: 40 MHz; Peak transfer rate: 240 MB/s [S1].
*   **Density Lookup Table:** Maps voxel values to density values [S1].
*   **DSPs:** 16 programmable digital signal processors [S1].

**Steps:**
1.  **Memory Organization:** Store volume data in an 8-way interleaved memory system [S1].
2.  **Density Mapping:** Map voxel values to density values using a density lookup table [S1].
3.  **Gradient Estimation:** Estimate the X- and Y-components of the gradient using a 2D gradient operator [S1].
4.  **Transmission:** Transmit sample density and X/Y-gradient components to the ray-casting unit over the geometry bus (48 bits @ 40 MHz) [S1].
5.  **Ray Casting and Shading:** Use the 16 programmable DSPs to generate the final image using high-quality illumination models, such as the Heidelberg ray-tracing algorithm which includes shadowing [S1].
6.  **Image Assembly:** A local master processor on the ray-casting board collects all scan lines of the final image from the DSP memories and transfers the results to the host system [S1].

## Operating characteristics
*   **Time Complexity:** Not explicitly defined in terms of Big-O, but performance is measured in frames per second. VIRIM achieves up to 2.5 frames per second for $256 \times 256 \times 128$ datasets [S1].
*   **Memory Complexity:** Maximum dataset size is $256^3$ for 16-bit voxels [S1]. Memory is replicated across parallel geometry units [S2].
*   **Measured Performance:**
    *   Geometry unit generates a maximum of 36 million tri-linear samples per second [S1].
    *   Up to 2.5 frames per second for $256 \times 256 \times 128$ datasets [S1].
    *   Higher performance may be achieved by duplicating the dataset across multiple VIRIM engines [S1].
*   **Scaling:** Higher rendering performance can be achieved by distributing subvolumes of the dataset among several basic units interconnected by a high-speed network? No, that is VOGUE. VIRIM scales by duplicating the dataset across multiple VIRIM engines [S1].
*   **Strengths:** Flexibility and versatility for a large variety of application areas [S2]. Programmable DSPs allow users to implement different visualization models and balance image quality versus rendering speed [S2]. Dedicated hardware units provide maximum speed for fixed functions like reconstruction of arbitrarily oriented slices [S2].
*   **Limitations:** Does not allow arbitrary intermixing of volumes and polygons [S1]. Replicating volume memory in each parallel geometry unit increases memory requirements compared to partitioning approaches like VOGUE [S2].
*   **When to use:** When flexibility and high-quality illumination models (e.g., shadowing) are required, and the dataset size fits within the $256^3$ limit.
*   **When not to use:** When arbitrary intermixing of volumes and polygons is needed, or when memory efficiency is critical and partitioning is preferred.

## Background
*   **Origin:** VIRIM is an object-order volume rendering engine developed and built at the University of Mannheim [GPR+ 94] and commercially distributed by the Volume Graphics GmbH, Heidelberg, Germany [S1].
*   **History:** The architecture was presented in comparative studies with VOGUE and Cube-3 in 1995 [S2]. It represents a solution characterized by flexibility, using object order ray-casting [S2].
*   **Usage:** Used for real-time volume rendering, particularly in medical imaging applications (implied by "Virtual Reality in Medicine") [S1].
