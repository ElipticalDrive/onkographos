# Hardware-based Direct Volume Ray Casting

Also called: VIRIM DSP shading, VIRIM Ray-Casting Unit

## Overview
Hardware-based Direct Volume Ray Casting offloads the computationally intensive tasks of ray casting, shading, and compositing to dedicated programmable Digital Signal Processors (DSPs), decoupling these operations from general-purpose processors and geometry units. Unlike software implementations that rely on general-purpose CPU or GPU shaders, this method uses specialized DSPs to compute light-material interactions for volume elements with high throughput, as seen in the VIRIM architecture [S1]. It is distinct from tree-based hardware methods like the Ray Projection Tree by using sequential scanline processing per DSP rather than parallel hierarchical combination [S1, S2].

## How it works
The method processes volume data in a pipeline where a geometry unit generates sample data, which is then consumed by DSPs for ray casting.

**Inputs and Outputs:**
*   **Input:** Sample density and gradient values (16-bit precision) generated by the geometry unit [S1].
*   **Output:** Final image scanlines stored in local DSP memory, later collected by a master CPU [S1].

**Data Structures:**
*   **Sample Data:** 16-bit density and gradient values [S1].
*   **FIFO Buffer:** Asynchronous buffer receiving data from the geometry unit bus [S1].
*   **Local Memory:** Stores calculated scanlines within each DSP [S1].
*   **LUTs:** Lookup tables accessible by the host system for real-time reloading [S1].

**Steps:**
1.  **Data Transmission:** The geometry unit transmits sample density and gradient values to the ray-casting units over a dedicated bus. The peak transfer rate is 240 MBytes/sec at 40 MHz [S1].
2.  **Buffering:** DSPs receive these values from an asynchronous FIFO buffer. This mechanism decouples the fast geometry unit from the slower DSPs; for the Heidelberg Raytracing algorithm, the geometry unit is approximately 16 times faster than a DSP [S1].
3.  **DSP Processing:** Each DSP computes the interaction of light and material for each volume element. This computation, which may involve up to 20 Sobel filters for gradient calculation, completes within 15 clock cycles per volume element [S1].
4.  **Scanline Generation:** One or more scanlines of the resulting projection are calculated per DSP and stored in the DSP's local memory [S1].
5.  **Result Collection:** A local master CPU collects all scanlines from the DSP memories and transfers the final image results to the host system. No inter-DSP communication is necessary for the current visualization model [S1].

**Parameters:**
*   **Data Precision:** 16 bits for density and gradient values [S1].
*   **Bus Speed:** 240 MBytes/sec at 40 MHz [S1].
*   **DSP Latency:** 15 clock cycles per volume element [S1].
*   **Geometry Speed Ratio:** Geometry unit is ~16x faster than DSP [S1].

## Subtopics

### Ray Projection Tree
A hardware mechanism structured as a hierarchical binary tree of Voxel Combination Units (VCUs) that accepts $n$ voxels along a viewing ray at the leaves and produces the final pixel color at the root [S2]. It differs from the DSP-based approach by processing rays in parallel through a tree structure rather than sequential scanlines per DSP [S2]. It supports various projection schemes including first/last opaque, max/min voxel value, weighted summation, and compositing [S2].

## Operating characteristics
*   **Throughput:** The geometry unit is approximately 16 times faster than the DSPs, creating a bottleneck at the DSP stage [S1].
*   **Performance:** A VIRIM module consists of four boards (36x39 cm²), with four modules fitting into one crate. For a 256x256x128 dataset, the frame rate is 2.5 Hz [S1].
*   **Memory:** All memories and LUTs are accessible by the host system for real-time reloading [S1].
*   **Communication:** No inter-DSP communication is required; all intra-DSP communication is handled via the local master CPU if needed [S1].
*   **Precision:** 16-bit data resolution for density and gradient values [S1].

## Background
The method was developed as part of the VIRIM (Volume Image Rendering on Massively Parallel Systems) project. It utilizes programmable DSPs to allow maximum flexibility in shading models, provided all data remains in one sample plane [S1]. The architecture was designed to handle the Heidelberg Raytracing algorithm efficiently [S1].
