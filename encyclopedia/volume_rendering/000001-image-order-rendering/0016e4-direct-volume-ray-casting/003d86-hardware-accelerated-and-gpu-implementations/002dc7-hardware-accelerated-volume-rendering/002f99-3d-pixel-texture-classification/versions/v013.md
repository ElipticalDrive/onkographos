# 3D Pixel Texture Classification

Also called: VGH Lookup

## Overview
3D Pixel Texture Classification is a hardware-accelerated method that maps multi-dimensional scalar attributes to optical properties using a 3D texture lookup, enabling real-time volume rendering by offloading classification to the GPU texture unit [S1]. It differs from standard 1D or 2D transfer functions by incorporating gradient magnitude and second derivative information directly into the texture coordinate generation, allowing for boundary-aware classification without explicit shader computation for every sample [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset $V$, a camera ray $r(t)$, and classification parameters defining the transfer function.
*   **Output:** Final pixel color $C_{final}$ and opacity $\alpha_{final}$ via front-to-back compositing.

**Data Structures:**
The core data structure is a 3D pixel texture $T_{3D}$ with dimensions $D \times G \times S$, where:
*   $D$: Resolution of the Data Value axis (typically 256 entries, 8-bit) [S1].
*   $G$: Resolution of the Gradient Magnitude axis (typically 256 entries, 8-bit) [S1].
*   $S$: Resolution of the Second Derivative axis (limited, e.g., 3-8 entries) [S1].
*   **Texture Content:** Each texel stores the resulting RGBA color and opacity values [S1].

**Numbered Steps:**
1.  **Ray Sampling:** For each pixel, generate a ray and sample the scalar volume at discrete intervals $t_i$ [S1, S4].
2.  **Attribute Extraction:** At each sample point $\mathbf{p}_i$, compute:
    *   Scalar value $d_i = V(\mathbf{p}_i)$ [S1].
    *   Gradient magnitude $g_i = \|\nabla V(\mathbf{p}_i)\|$ [S1].
    *   Second derivative $s_i = \nabla^2 V(\mathbf{p}_i)$ (or a signed approximation) [S1].
3.  **Coordinate Transformation:** Map attributes to texture coordinates $(u, v, w)$:
    *   $u = d_i / D_{max}$ (normalized data value) [S1].
    *   $v = g_i / G_{max}$ (normalized gradient magnitude) [S1].
    *   $w = \text{bias}(s_i)$ (biased second derivative) [S1].
    *   *Note:* The sign of the second derivative must be preserved via scale and bias to allow proper interpolation across zero crossings [S1].
4.  **Texture Lookup:** Perform a 3D texture lookup $T_{lookup} = T_{3D}(u, v, w)$ [S1]. The hardware interpolates between texels, providing smooth transitions even with limited $S$ resolution [S1].
5.  **Classification Sheets:** The second derivative axis is structured as "sheets" with control points for negative, zero, and positive values [S1].
    *   Opacity at zero second derivative ($s_i \approx 0$) is directly controlled by classification widgets [S1].
    *   Opacity at non-zero second derivatives is scaled from the center sheet opacity based on a "boundary emphasis" slider [S1].
6.  **Compositing:** Use the retrieved color $C_i$ and opacity $\alpha_i$ from $T_{lookup}$ in the standard front-to-back compositing equation [S1, S4].

**Formulas:**
The second derivative axis mapping uses a bias $b$ and scale $k$ to maintain sign:
$$ w = \frac{k \cdot s_i + b}{S_{max}} $$
where $s_i$ is the signed second derivative [S1].

**Parameters:**
*   $D, G$: 256 (8-bit resolution) [S1].
*   $S$: Small integer (e.g., 3 for negative/zero/positive sheets) [S1].
*   Boundary Emphasis: A scalar parameter scaling the opacity of outer sheets relative to the center sheet [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** Limited resolution on the second derivative axis requires careful placement of control points to avoid aliasing in boundary detection [S1].
*   **Sign Preservation:** Failure to bias the second derivative correctly will cause interpolation to average positive and negative values, losing boundary information [S1].
*   **Memory:** A full 8-bit resolution on all three axes ($256^3$) is prohibitively large; limiting $S$ is essential [S1].

## Subtopics

### Adaptive Pre-integrated Voxel Classification
A technique included in a real-time raycaster built by Roettger et al. to exploit the intrinsically parallel nature of GPUs, along with volume clipping [S2]. It adapts the classification and integration steps to reduce redundant computations in transparent regions, improving performance over standard single-pass methods [S2].

## Operating characteristics
*   **Time Complexity:** $O(N)$ per pixel, where $N$ is the number of samples, but with a very low constant factor due to hardware texture lookup [S1, S2].
*   **Memory Complexity:** $O(D \times G \times S)$ for the classification texture [S1].
*   **Performance:** Enables real-time rendering on hardware that supports 3D texturing, avoiding the overhead of multi-pass software-based classification [S1, S2].
*   **Strengths:** High performance, smooth classification boundaries via hardware interpolation, support for multi-dimensional transfer functions [S1].
*   **Limitations:** Limited resolution on higher-dimensional axes (like second derivative) due to texture memory constraints; less flexible than shader-based methods for complex, non-lookup-based classification logic [S1].

## Background
Originated in the early 2000s as a method to leverage emerging GPU 3D texturing capabilities for volume rendering [S1]. It was developed to address the computational cost of multi-dimensional transfer functions in software, allowing for real-time interaction with complex volume datasets [S1]. The approach was further refined with adaptive techniques to improve efficiency on parallel GPU architectures [S2].
