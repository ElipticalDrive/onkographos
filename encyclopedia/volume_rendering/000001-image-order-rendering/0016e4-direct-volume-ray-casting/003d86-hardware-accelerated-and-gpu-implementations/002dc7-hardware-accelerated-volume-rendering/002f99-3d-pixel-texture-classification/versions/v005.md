# 3D Pixel Texture Classification

Also called: VGH Lookup

## Overview
3D Pixel Texture Classification is a hardware-accelerated method that maps multi-dimensional voxel attributes to optical properties (color and opacity) using a 3D texture lookup, enabling real-time direct volume ray casting [S1, S2]. It distinguishes itself from sibling methods by offloading the classification step entirely to the graphics hardware's texture unit via a pre-computed 3D texture, rather than computing transfer functions in shader code or using 1D/2D lookups [S1]. This approach supports complex, multi-dimensional transfer functions (e.g., Data Value, Gradient Magnitude, and Second Derivative) within a single hardware texture access [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset where each voxel contains three values: Data Value ($D$), Gradient Magnitude ($G$), and Second Derivative ($S$) [S1].
*   **Output:** A 3D pixel texture (lookup table) mapping $(D, G, S)$ to RGBA color and opacity [S1].
*   **Ray Casting:** Standard direct volume ray casting pipeline using the compositing equation from [Hardware-Accelerated Volume Rendering](5616-hardware-accelerated-volume-rendering.md) [S1, S2].

**Data Structures:**
The core data structure is a 3D texture (the "VGH Lookup") with dimensions $N_D \times N_G \times N_S$ [S1].
*   **Axis 1 (Data Value):** 8-bit resolution (256 entries) [S1].
*   **Axis 2 (Gradient Magnitude):** 8-bit resolution (256 entries) [S1].
*   **Axis 3 (Second Derivative):** Limited resolution (not 8-bit) [S1].
*   **Texture Format:** RGBA, storing the final color and opacity for the given attribute combination [S1].

**Steps:**
1.  **Pre-compute Voxel Attributes:** For each voxel in the volume, compute the Data Value ($D$), Gradient Magnitude ($G = \|\nabla V\|$), and Second Derivative ($S = \nabla^2 V$) [S1].
2.  **Define Second Derivative Control Points:** The Second Derivative axis is represented by three "sheets" corresponding to negative, zero, and positive values [S1].
    *   Let $S_{neg}$, $S_{zero}$, and $S_{pos}$ be the indices or representative values for these sheets [S1].
    *   The sign of $S$ is maintained via scale and bias to ensure correct interpolation [S1].
3.  **Define Opacity Control:**
    *   The opacity at the center sheet ($S_{zero}$) is directly controlled by classification widgets [S1]. Let this be $\alpha_{zero}$ [S1].
    *   The opacity at the outer sheets ($S_{neg}$ and $S_{pos}$) is scaled from $\alpha_{zero}$ based on a "boundary emphasis" slider parameter $k$ [S1].
    *   $\alpha_{neg} = k \cdot \alpha_{zero}$
    *   $\alpha_{pos} = k \cdot \alpha_{zero}$
    *   [G] If $k > 1$, boundaries are emphasized; if $k < 1$, they are suppressed.
4.  **Populate the 3D Texture:**
    *   For each voxel $(i, j, k)$ with attributes $(D, G, S)$:
        *   Map $D$ to index $idx_D \in [0, 255]$.
        *   Map $G$ to index $idx_G \in [0, 255]$.
        *   Map $S$ to index $idx_S$ based on its sign and magnitude relative to the three sheets [S1].
        *   Interpolate the color and opacity from the three sheets in the $S$ dimension [S1].
        *   Store the result in the 3D texture at $(idx_D, idx_G, idx_S)$ [S1].
5.  **Ray Casting:**
    *   For each pixel, cast a ray through the volume [S1].
    *   At each sample point along the ray, compute $D, G, S$ [S1].
    *   Perform a 3D texture lookup using $(D, G, S)$ to retrieve color $C$ and opacity $\alpha$ [S1].
    *   Composite the result using the standard over operator [S1, S2].

**Parameters:**
*   **Boundary Emphasis ($k$):** Controls the relative opacity of non-zero second derivative values compared to zero [S1]. Typical value: Not given in the sources.
*   **Resolution:** 256x256x$N_S$ for the texture [S1]. $N_S$ is small (e.g., 3-10) [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The Second Derivative axis has limited resolution, which may cause quantization artifacts [S1].
*   **Sign Handling:** The sign of the Second Derivative must be preserved via scale and bias to ensure correct interpolation across the zero-crossing [S1].
*   **Texture Size:** A full 8-bit resolution for all three axes would be prohibitively large ($256^3$ entries) [S1]. Limiting the Second Derivative axis is critical for memory efficiency [S1].

## Subtopics

### Adaptive Pre-integrated Voxel Classification
A technique included in a real-time raycaster built by Roettger et al. to exploit the intrinsically parallel nature of GPUs, along with volume clipping [S2]. It extends the basic 3D Pixel Texture Classification by adapting the classification resolution or pre-integration based on the view or data density, improving performance on modern GPU architectures [S2]. It is chosen when real-time performance is critical and the hardware supports adaptive rendering techniques [S2].

## Operating characteristics
*   **Time Complexity:** Classification is $O(1)$ per sample due to hardware texture lookup [S1].
*   **Memory Complexity:** The 3D texture size is $N_D \times N_G \times N_S \times 4$ bytes [S1]. With $N_D=256, N_G=256$, and small $N_S$, this is feasible for modern GPUs [S1].
*   **Performance:** Enables real-time ray casting by offloading classification to hardware [S1, S2].
*   **Strengths:** Supports multi-dimensional transfer functions; fast hardware lookup; simple pipeline [S1].
*   **Limitations:** Limited resolution for Second Derivative; texture size constraints; less flexible than shader-based methods for complex functions [S1].
*   **When to Use:** Real-time visualization with multi-dimensional transfer functions [S1, S2].
*   **When Not to Use:** When high-resolution Second Derivative classification is required or when the transfer function is too complex for a 3D texture [S1].

## Background
Originated in the early 2000s as a method to leverage 3D texture hardware for volume rendering [S1]. It was developed to address the limitations of 1D and 2D transfer functions by allowing the use of gradient and second derivative information in the classification step [S1]. The method was later extended with adaptive techniques for real-time performance on GPUs [S2].
