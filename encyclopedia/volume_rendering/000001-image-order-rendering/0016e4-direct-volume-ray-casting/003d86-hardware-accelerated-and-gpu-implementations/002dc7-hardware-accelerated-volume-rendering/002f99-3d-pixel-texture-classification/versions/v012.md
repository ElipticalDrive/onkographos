# 3D Pixel Texture Classification

Also called: VGH Lookup

## Overview
3D Pixel Texture Classification is a hardware-accelerated volume rendering technique that maps voxel attributes to color and opacity using a 3D texture lookup, enabling real-time interactive classification via multi-dimensional transfer functions. It distinguishes itself from standard direct volume ray casting by offloading the classification logic to the GPU's texture hardware, allowing for complex attribute combinations (Data Value, Gradient Magnitude, Second Derivative) to be resolved in a single texture fetch per sample, rather than through complex shader arithmetic [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset; a classification specification defining mappings for Data Value ($D$), Gradient Magnitude ($G$), and Second Derivative ($S$).
*   **Output:** A 2D image with color and opacity values for each pixel.

**Data Structures:**
The core data structure is a 3D pixel texture (lookup table) with dimensions $N_D \times N_G \times N_S$.
*   **Axis 0 (Data Value):** 8-bit resolution (256 entries).
*   **Axis 1 (Gradient Magnitude):** 8-bit resolution (256 entries).
*   **Axis 2 (Second Derivative):** Limited resolution (not 256 entries).
*   **Texture Format:** Each texel stores RGBA values representing the final color and opacity contribution for the corresponding attribute combination.

**Steps:**
1.  **Volume Traversal:** For each pixel, compute the ray origin and direction. Sample the volume at regular intervals along the ray.
2.  **Attribute Extraction:** For each sample point, extract the scalar value $v$ and compute the gradient magnitude $g$. Compute the second derivative $s$ (typically via finite differences).
3.  **Second Derivative Normalization:** The second derivative $s$ is a signed quantity. To maintain the sign for proper interpolation, apply a scale and bias transformation to map negative, zero, and positive values into the valid texture coordinate range $[0, 1]$ of the third axis [S1].
4.  **Texture Lookup:** Perform a trilinear texture lookup in the 3D pixel texture using coordinates $(u_D, u_G, u_S)$ derived from $v$, $g$, and the transformed $s$.
    *   $u_D$ is mapped linearly from $v$ to $[0, 1]$.
    *   $u_G$ is mapped linearly from $g$ to $[0, 1]$.
    *   $u_S$ is mapped based on the "sheet" structure described below.
5.  **Compositing:** Use the returned color and opacity from the texture lookup in the front-to-back compositing loop.

**Second Derivative "Sheet" Representation:**
To handle the second derivative axis efficiently with limited resolution, the texture uses a "sheet" representation with three control points: negative, zero, and positive [S1].
*   **Control Points:** Three distinct slices or regions in the third axis correspond to negative $s$, $s=0$, and positive $s$.
*   **Linear Control:** Opacity for second derivative values is controlled linearly between these sheets.
*   **Center Sheet:** The opacity at the center sheet ($s=0$) is directly controlled by classification widgets.
*   **Outer Sheets:** The opacity at the outer sheets (positive and negative $s$) is scaled from the center sheet opacity based on a "boundary emphasis" slider. This allows users to emphasize or de-emphasize boundaries (edges) in the volume [S1].

**Parameters:**
*   **Data Value Resolution:** 256 entries (8-bit) [S1].
*   **Gradient Magnitude Resolution:** 256 entries (8-bit) [S1].
*   **Second Derivative Resolution:** Limited (exact number not specified, but significantly less than 256) [S1].
*   **Boundary Emphasis Slider:** A user-controllable parameter scaling the opacity of the outer second derivative sheets relative to the center sheet [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The limited resolution of the second derivative axis may lead to quantization artifacts if the boundary emphasis slider is set to extreme values, as the linear interpolation between sheets may not capture subtle variations in the second derivative [S1].
*   **Sign Maintenance:** Failure to correctly apply scale and bias to the second derivative will result in incorrect interpolation across the zero-crossing, leading to visual artifacts at boundaries [S1].
*   **Texture Size:** While the first two axes are 8-bit, the total texture size must be managed to fit in GPU memory. The limited resolution of the third axis is a direct consequence of this constraint [S1].

## Subtopics

### Adaptive Pre-integrated Voxel Classification
A technique included in a real-time raycaster built by Roettger et al. to exploit the intrinsically parallel nature of GPUs, along with volume clipping. It extends the basic 3D pixel texture approach by incorporating pre-integration to reduce aliasing and adaptive sampling to improve performance in complex regions [S2].

## Operating characteristics
*   **Time Complexity:** $O(N)$ per pixel, where $N$ is the number of samples along the ray. The classification lookup is $O(1)$ due to hardware texture interpolation.
*   **Memory Complexity:** $O(N_D \times N_G \times N_S)$ for the 3D pixel texture. With 8-bit axes for $D$ and $G$, and limited $S$, the texture size is manageable but can still be large if $N_S$ is not sufficiently limited.
*   **Performance:** Enables real-time interaction due to the offloading of classification to the GPU texture hardware. Performance is highly dependent on the resolution of the lookup table and the complexity of the volume traversal [S1, S2].
*   **Strengths:** High performance for interactive classification; supports multi-dimensional transfer functions; leverages existing GPU hardware.
*   **Limitations:** Limited resolution for the second derivative axis; requires careful tuning of the scale and bias for signed quantities; texture size can become a bottleneck if higher resolutions are needed [S1].

## Background
The method was introduced in the context of interactive volume rendering using multi-dimensional transfer functions. It addresses the need for efficient, hardware-accelerated classification of volume data based on multiple attributes, which is computationally expensive if performed in the shader [S1]. The approach builds on the principles of hardware-accelerated volume rendering, specifically leveraging 3D texturing capabilities [S1].
