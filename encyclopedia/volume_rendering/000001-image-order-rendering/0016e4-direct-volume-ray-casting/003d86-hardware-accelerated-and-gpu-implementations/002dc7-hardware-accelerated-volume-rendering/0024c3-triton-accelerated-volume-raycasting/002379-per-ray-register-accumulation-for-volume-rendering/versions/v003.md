# Per-ray register accumulation for volume rendering

Also called: Residual Accumulation, Residual Accumulator Optimization, Stage 1 optimization, register accumulation

## Overview
Per-ray register accumulation is a forward-pass optimization for direct volume ray casting that eliminates per-sample global-memory read-modify-write operations by accumulating RGB, depth, and opacity values in per-thread stack-allocated registers [S2, unofficial]. It differs from the baseline by writing each per-ray output exactly once to global memory after the ray marching loop completes, thereby significantly reducing global memory traffic [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ray origin, ray direction, volume density/opacity samples, transfer function parameters, bounding box, and step size [G].
*   **Outputs:** `outRGB` (accumulated color), `outDepth` (accumulated depth), `outOpacity` (accumulated opacity) [S2, unofficial].

**Data Structures:**
The method uses per-thread local storage to hold intermediate state [S2, unofficial].
*   `accRgb[MAX_VOLUME_RENDER_CHANNELS]`: A stack-allocated array for RGB accumulation, typically unrolled via `#pragma unroll` [S2, unofficial].
*   `depth`: A scalar variable for depth accumulation [S2, unofficial].
*   `opacity`: A scalar variable for accumulated alpha/opacity [S2, unofficial].

**Algorithm Steps:**
1.  **Initialization:** For each ray processed by a thread, initialize `accRgb` to zero, `depth` to 0, and `opacity` to 0 [S2, unofficial].
2.  **Ray Marching Loop:** Iterate through the volume samples along the ray [S2, unofficial].
    *   Sample the volume density and color at the current step [G].
    *   Compute the step opacity `alpha = 1.0 - exp(-density * step_size)` and transmittance `T = exp(-opacity)` [G].
    *   Compute the contribution weight `w = alpha * T` and update the registers: `accRgb[c] += w * color[c]`, `depth += w * (t - t_min)`, `opacity += alpha` [G].
3.  **Final Write:** After the loop completes, write the final accumulated values from the per-thread registers to the global output tensors `outRGB`, `outDepth`, and `outOpacity` exactly once per ray [S2, unofficial].

**Pseudocode:**
```python
# Pseudocode for a single thread processing one ray
MAX_VOLUME_RENDER_CHANNELS = 3  # Compile-time constant [S2, unofficial]

def per_ray_register_accumulation(ray_origin, ray_direction, t_min, t_max, step_size, volume_sampler):
    # 1. Initialize per-thread registers
    acc_rgb = [0.0] * MAX_VOLUME_RENDER_CHANNELS
    depth = 0.0
    opacity = 0.0
    transmittance = 1.0
    
    # 2. Accumulate in registers
    num_steps = max(1, int(round((t_max - t_min) / step_size)))
    for i in range(num_steps):
        t = t_min + (i + 0.5) * step_size  # Mid-point sampling [G]
        pos = ray_origin + t * ray_direction
        
        density, color = volume_sampler.sample(pos)
        
        # Standard direct volume rendering compositing [G]
        alpha = 1.0 - exp(-density * step_size)
        weight = alpha * transmittance
        
        for c in range(MAX_VOLUME_RENDER_CHANNELS):
            acc_rgb[c] += weight * color[c]
        depth += weight * (t - t_min)  # Relative depth accumulation [G]
        opacity += alpha
        transmittance *= (1.0 - alpha)
        
        # Early termination guard [G]
        if transmittance < 1e-4:
            break

    # 3. Write final results to global memory exactly once
    out_rgb = acc_rgb
    out_depth = depth
    out_opacity = opacity
    
    return out_rgb, out_depth, out_opacity
```

**Parameters:**
*   `MAX_VOLUME_RENDER_CHANNELS`: Compile-time constant defining the maximum number of RGB channels supported in the accumulation register array [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Accumulating in registers changes the order of floating-point operations compared to global memory accumulation, which may yield minor precision differences [G].
*   **Early Termination:** If early termination is triggered, the final write must still occur, outputting the partial accumulation state [G].
*   **Backward Pass:** This optimization applies strictly to the forward pass; the backward pass is handled separately via a Python `torch.autograd.Function` wrapper to avoid storing per-sample weights [S2, unofficial].

## Operating characteristics
*   **Performance:** In a fire renderer at 256 spp, this optimization reduced the `volume_render` stage time from 8772.5 ms to 6171.4 ms (-29.7%) and reduced end-to-end walltime by 17.8% (saving 2.57 s) [S2, unofficial].
*   **Memory Traffic:** Significantly reduces global memory read-modify-write operations on `outRGB`, `outDepth`, and `outOpacity` [S2, unofficial].
*   **Scalability:** Performance gains are most significant when global memory bandwidth is the primary bottleneck [G].
*   **Strengths:** Reduced global memory traffic, lower latency per ray, and simpler memory access patterns for output tensors [S2, unofficial].
*   **Limitations:** Performance is bounded by hardware register limits; excessive channels or auxiliary variables may cause register spilling to local memory, negating bandwidth benefits [G].

## Background
This optimization was introduced alongside the migration of the autograd layer to Python in the `fvdb-core` pull request "Optimizations for `volume_render` and move its autograd layer to Python" [S2, unofficial]. It was designed to address the performance bottleneck of the `volume_render` stage, which previously accounted for 60.7% of the total runtime [S2, unofficial]. The technique builds on standard GPU programming principles that use per-thread registers to minimize global memory accesses [G].
