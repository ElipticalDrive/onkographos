# VStudio Framework Volume Rendering Pipeline

Also called: Single Pass GPU Ray Casting, VStudio Ray Casting

## Overview
The VStudio Framework is an interactive volume visualization environment that implements single-pass GPU ray casting, allowing for real-time shader editing and pipeline customization [S1]. It distinguishes itself from standard ray casting implementations by exposing the entire rendering pipeline (vertex and fragment shaders) for interactive modification, supporting features such as early ray termination, stochastic ray shifting, and brute-force shadow ray traversal within a single pass [S1]. Unlike methods that require complex multi-pass setups or external libraries, VStudio operates as a self-contained application with a specific file-based scene management system and a modular shader architecture [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   Volumetric data files in specific binary formats (`.dat`, `.vol8`, `.vol12`, `.vol16`) [S1].
*   Shader source files: One vertex shader and multiple fragment shader components [S1].
*   Scene configuration (camera, light sources, transfer functions) stored in `.vst` text files [S1].

**Outputs:**
*   Rendered image on the screen.
*   Scene state saved to `.vst` files [S1].

### Data Structures and Layouts
The framework expects volumetric data in specific binary formats with little-endian byte ordering implied by the structure descriptions [S1].

**1. `.dat` Format:**
*   **Header:** 6 bytes.
    *   Bytes 0-1: Number of voxels in X ($N_x$).
    *   Bytes 2-3: Number of voxels in Y ($N_y$).
    *   Bytes 4-5: Number of voxels in Z ($N_z$).
*   **Data:** 16-bit scalar values ($N_x \times N_y \times N_z$) [S1].

**2. `.vol8`, `.vol12`, `.vol16` Formats:**
*   **Header:** 12 bytes.
    *   Bytes 0-1: Number of voxels in X ($N_x$).
    *   Bytes 2-3: Number of voxels in Y ($N_y$).
    *   Bytes 4-5: Number of voxels in Z ($N_z$).
    *   Bytes 6-7: Voxel scale in X ($S_x$).
    *   Bytes 8-9: Voxel scale in Y ($S_y$).
    *   Bytes 10-11: Voxel scale in Z ($S_z$).
*   **Constraints:** All header values must be in the range 1-4096 [S1].
*   **Data:** Scalar values matching the bit depth indicated by the extension (8, 12, or 16 bits) [S1].

**3. Shader Files (Version 1.2):**
*   Vertex Shader: `DVR_VERTEX_BACK_FRONT_v1.2.vs` [S1].
*   Fragment Shaders (linked together):
    *   `DVR_FRAGMENT_BACK_FRONT_v1.2.fs` (Main entry point) [S1].
    *   `classify.fs` (Classification logic) [S1].
    *   `grad.fs` (Gradient calculation) [S1].
    *   `light.fs` (Lighting model) [S1].
    *   `shadow.fs` (Shadow ray traversal) [S1] [G].

### Pipeline Steps

1.  **Data Import and Histogram Calculation:**
    *   Load volumetric data using `File/Import/Volume`.
    *   The system automatically initiates an "advanced ACC histogram calculation" for density and gradient magnitude [S1].
    *   *Pitfall:* If this calculation is aborted, only the traditional density histogram is computed, potentially affecting transfer function accuracy [S1].
    *   VStudio expands the data value range during import, even if the original data fits the bit depth [S1].

2.  **Shader Attachment:**
    *   Load and attach the vertex shader (`DVR_VERTEX_BACK_FRONT_v1.2.vs`) via `Shader/Apply Vertex Shader` [S1].
    *   Load and attach the fragment shader components (`DVR_FRAGMENT_BACK_FRONT_v1.2.fs`, `classify.fs`, `grad.fs`, `light.fs`, `shadow.fs`) via `Shader/Apply Fragment Shader` [S1].
    *   Linking succeeds only when all specified shader files are attached [S1].

3.  **Feature Configuration:**
    *   Enable/disable features via the UI:
        *   Blinn Lighting Model (Point and Directional lights) [S1].
        *   Early Ray Termination (ORT) [S1].
        *   Progressive Refinement [S1].
        *   Stochastic Ray Shifting [S1].
        *   Brute Force Shadow-Ray Traversal [S1].
        *   Maximum Intensity Projection (MIP) [S1].
        *   Slicing (View and Object Space) [S1].
    *   *Note:* MIP and Slicing modes can be used immediately without importing shaders [S1].

4.  **Rendering Loop (Single Pass GPU Ray Casting):**
    *   The vertex shader prepares geometry (likely a full-screen quad or volume bounding box) [S1].
    *   The fragment shader executes the ray casting pipeline for each pixel:
        *   **Ray Generation:** Compute ray origin and direction based on camera parameters [S1].
        *   **Sampling:** Sample the volume texture.
        *   **Classification:** Apply transfer function to map scalar values to color and opacity [S1].
        *   **Shading:** Calculate lighting using the Blinn-Phong model, utilizing gradients computed in `grad.fs` [S1].
        *   **Shadows:** If enabled, perform brute-force shadow ray traversal [S1].
        *   **Compositing:** Perform front-to-back compositing with early ray termination if opacity threshold is reached [S1].

### Pseudocode

The following pseudocode represents the logical flow of the VStudio pipeline, derived from the shader structure and feature descriptions [S1].

```python
# VStudio Rendering Pipeline Logic

def vstudio_render_pipeline(volume_data, camera, lights, features):
    """
    Main rendering function for VStudio Framework.
    """
    
    # 1. Data Preparation
    # VStudio expands data range during import [S1]
    # Histograms for density and gradient magnitude are pre-calculated [S1]
    density_histogram = volume_data.compute_advanced_histogram()
    gradient_histogram = volume_data.compute_gradient_histogram()
    
    # 2. Shader Compilation and Linking
    # Requires specific files: DVR_VERTEX_BACK_FRONT_v1.2.vs and fragment components [S1]
    vertex_shader = compile_shader("DVR_VERTEX_BACK_FRONT_v1.2.vs")
    fragment_shaders = [
        compile_shader("classify.fs"),
        compile_shader("grad.fs"),
        compile_shader("light.fs"),
        compile_shader("shadow.fs"),
        compile_shader("DVR_FRAGMENT_BACK_FRONT_v1.2.fs")
    ]
    
    # Linking succeeds only if all files are attached [S1]
    program = link_program(vertex_shader, fragment_shaders)
    
    # 3. Feature Setup
    use_early_ray_termination = features.get("Early Ray Termination", False)
    use_shadows = features.get("Brute Force Shadow-Ray Traversal", False)
    use_stochastic_shifting = features.get("Stochastic Ray Shifting", False)
    use_blinn_lighting = features.get("Blinn Lighting Model", False)
    
    # 4. Rendering Loop (Per Pixel)
    for pixel in screen_pixels:
        # Ray Generation
        ray_origin, ray_direction = camera.generate_ray(pixel)
        
        # Stochastic Ray Shifting (if enabled) [S1]
        if use_stochastic_shifting:
            ray_origin += random_offset()
            ray_direction += random_offset()
            
        # Ray-Volume Intersection
        t_start, t_end = intersect_aabb(ray_origin, ray_direction, volume_data.bbox)
        
        accumulated_color = vec3(0.0)
        accumulated_opacity = 0.0
        
        # Ray Casting Loop
        t = t_start
        while t < t_end:
            sample_point = ray_origin + t * ray_direction
            
            # Sampling and Interpolation
            scalar_value = volume_data.sample_trilinear(sample_point)
            
            # Classification (from classify.fs) [S1]
            color, opacity = classify(scalar_value, density_histogram)
            
            # Early Ray Termination [S1]
            if accumulated_opacity >= 0.99: # Threshold [G]
                break
                
            # Shading (from light.fs and grad.fs) [S1]
            if use_blinn_lighting:
                gradient = compute_gradient(sample_point, volume_data) # From grad.fs
                normal = normalize(gradient)
                lighting = calculate_blinn_phong(sample_point, normal, lights)
                color *= lighting
            
            # Shadows (from shadow.fs) [S1]
            if use_shadows:
                shadow_factor = brute_force_shadow_trace(sample_point, lights, volume_data)
                color *= shadow_factor
            
            # Front-to-Back Compositing
            transmittance = 1.0 - accumulated_opacity
            accumulated_color += transmittance * opacity * color
            accumulated_opacity += transmittance * opacity
            
            # Step forward
            t += step_size
            
        # Final Color
        pixel.color = accumulated_color

def brute_force_shadow_trace(point, lights, volume_data):
    """
    Implements Brute Force Shadow-Ray Traversal [S1].
    Traces rays from sample point to each light source.
    """
    total_shadow = 1.0
    for light in lights:
        shadow_ray_dir = normalize(light.position - point)
        shadow_t_start = 0.001
        shadow_t_end = distance(point, light.position)
        
        is_shadowed = False
        t = shadow_t_start
        while t < shadow_t_end:
            sample = point + t * shadow_ray_dir
            if volume_data.sample_trilinear(sample) > threshold:
                is_shadowed = True
                break
            t += shadow_step_size
            
        if is_shadowed:
            total_shadow = 0.0
            break
    return total_shadow
```

### Parameters and Edge Cases
*   **Header Constraints:** In `.vol` formats, voxel counts and scales must be between 1 and 4096 [S1].
*   **Histogram Abortion:** Aborting the advanced ACC histogram calculation results in only the traditional density histogram being calculated, which may degrade transfer function quality [S1].
*   **Shader Linking:** The pipeline fails if any of the required fragment shader files (`classify.fs`, `grad.fs`, `light.fs`, `shadow.fs`, `DVR_FRAGMENT_BACK_FRONT_v1.2.fs`) are missing during attachment [S1].
*   **Data Range Expansion:** VStudio expands the data value range during import, which may alter the effective transfer function mapping compared to the raw data distribution [S1].

## Operating characteristics

*   **Performance:** The method uses single-pass GPU ray casting, which is generally faster than multi-pass techniques but can be computationally intensive per pixel due to the brute-force shadow ray traversal and stochastic shifting features [S1].
*   **Interactivity:** Designed for interactive shader editing, allowing users to modify the rendering pipeline in real-time [S1].
*   **Memory:** Requires storing the volume data and pre-calculated histograms (density and gradient magnitude) [S1]. Scene state is saved in text-based `.vst` files, which reference shader filenames rather than embedding shader code [S1].
*   **Strengths:** High flexibility through interactive shader editing; supports advanced features like shadows and stochastic shifting in a single pass; simple file format for data import [S1].
*   **Limitations:** Performance may degrade with brute-force shadow tracing; dependent on specific shader file structure; limited to the features exposed in the version 1.2 implementation [S1].

## Background

The VStudio Framework was created by Robert Hausmair, a student at the Technical University of Vienna (TU Wien), Austria [S1]. It was developed as part of the "Visualisierung" (Visualization) course at TU Wien [S1]. The framework is designed to demonstrate and facilitate interactive volume visualization techniques, specifically focusing on GPU-based ray casting [S1]. It provides a complete environment for loading data, configuring transfer functions, and modifying shaders to achieve different rendering effects [S1].
