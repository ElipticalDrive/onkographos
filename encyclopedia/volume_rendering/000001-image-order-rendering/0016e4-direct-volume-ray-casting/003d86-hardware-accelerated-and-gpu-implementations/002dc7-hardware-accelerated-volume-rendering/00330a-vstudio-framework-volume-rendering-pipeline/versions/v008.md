# VStudio Framework Volume Rendering Pipeline

Also called: Single Pass GPU Ray Casting, VStudio Ray Casting

## Overview
The VStudio Framework is an interactive volume visualization tool that implements single-pass GPU ray casting, allowing for real-time shader editing and customization of the rendering pipeline [S1]. It distinguishes itself from other hardware-accelerated methods by exposing the fragment shader logic to the user, enabling immediate modification of classification, lighting, and shadowing functions without recompiling the core application [S1]. Unlike methods that rely on fixed-function pipelines or pre-baked textures, VStudio computes gradients and lighting dynamically within the shader program during the ray casting process [S1].

## How it works
The framework performs volume rendering by loading volumetric data, computing histograms for transfer function specification, and executing a ray casting loop via a linked vertex and fragment shader pair [S1].

### Inputs and Outputs
*   **Input:** Volumetric scalar data in `.dat`, `.vol8`, `.vol12`, or `.vol16` format [S1].
*   **Input:** Shader source files (`.vs` for vertex, `.fs` for fragment components) [S1].
*   **Input:** User-defined transfer functions for density and gradient magnitude [S1].
*   **Output:** Rendered 2D image on the screen [S1].

### Data Structures
The framework expects specific file layouts for volumetric data [S1]:

**`.dat` Format:**
*   **Header:** 6 bytes.
    *   Bytes 0-1: Number of voxels in X (2 bytes).
    *   Bytes 2-3: Number of voxels in Y (2 bytes).
    *   Bytes 4-5: Number of voxels in Z (2 bytes).
*   **Data:** 16-bit scalar values following the header.

**`.vol8`, `.vol12`, `.vol16` Formats:**
*   **Header:** 12 bytes.
    *   Bytes 0-1: Number of voxels in X (2 bytes).
    *   Bytes 2-3: Number of voxels in Y (2 bytes).
    *   Bytes 4-5: Number of voxels in Z (2 bytes).
    *   Bytes 6-7: Voxel scale in X (2 bytes).
    *   Bytes 8-9: Voxel scale in Y (2 bytes).
    *   Bytes 10-11: Voxel scale in Z (2 bytes).
*   **Constraint:** All header values must be in the range 1-4096 [S1].
*   **Data:** Scalar values matching the bit depth indicated by the extension (8, 12, or 16 bits) following the header.

### Rendering Pipeline Steps
1.  **Import Data:** Load a volumetric file using `File/Import/Volume` [S1].
    *   The system automatically initiates an "advanced ACC histogram calculation" for density and gradient magnitude [S1].
    *   **Pitfall:** If this calculation is aborted, only the traditional histogram for density is calculated, potentially limiting interactive transfer function specification [S1].
    *   VStudio expands the data value range during import, even if the original data distribution matches the bit depth [S1].
2.  **Attach Vertex Shader:** Load and attach the vertex shader, typically `DVR_VERTEX_BACK_FRONT_v1.2.vs` [S1].
3.  **Attach Fragment Shaders:** Load and attach the required fragment shader components [S1]. The implementation requires the following files to be attached for successful linking:
    *   `DVR_FRAGMENT_BACK_FRONT_v1.2.fs` (Main entry point)
    *   `classify.fs`
    *   `grad.fs`
    *   `light.fs`
    *   `shadow.fs`
    *   **Linking:** The shader pair links successfully only when all specified vertex and fragment files are attached [S1].
4.  **Configure Features:** Enable optional rendering features via the UI, such as Blinn Lighting, Early Ray Termination, Progressive Refinement, Stochastic Ray Shifting, Brute Force Shadow-Ray Traversal, Maximum Intensity Projection (MIP), and Slicing [S1].
5.  **Render:** The GPU executes the ray casting loop. The vertex shader prepares geometry (likely a screen-aligned quad or volume bounding box), and the fragment shader performs the ray traversal, sampling, classification, shading, and compositing [S1].

### Pseudocode
The following pseudocode represents the logical flow of the VStudio framework's initialization and rendering setup, based on the documented workflow [S1]. Note that the internal ray casting loop is contained within the attached GLSL shaders, which are not fully detailed in the source text, but the structure of the shader composition is defined.

```python
class VStudioPipeline:
    def __init__(self):
        self.volume_data = None
        self.vertex_shader = None
        self.fragment_shaders = []
        self.program_linked = False
        self.features = {
            "blinn_lighting": False,
            "early_ray_termination": False,
            "progressive_refinement": False,
            "stochastic_ray_shifting": False,
            "brute_force_shadow": False,
            "mip": False,
            "slicing": False
        }

    def import_volume(self, filepath):
        """
        Loads volume data and computes histograms.
        """
        # Parse header based on extension (.dat, .vol8, etc.)
        # Extract dimensions and scales
        # Load scalar data
        self.volume_data = load_data(filepath)
        
        # Initiate advanced ACC histogram calculation for density and gradient magnitude
        # If aborted, falls back to traditional density histogram only
        self.histograms = compute_advanced_histograms(self.volume_data)
        
        # Expand data value range during import
        self.volume_data = expand_range(self.volume_data)

    def apply_vertex_shader(self, filepath):
        """
        Loads and attaches the vertex shader.
        """
        self.vertex_shader = load_shader(filepath, type='VERTEX')

    def apply_fragment_shader(self, filepath):
        """
        Loads and attaches a fragment shader component.
        """
        self.fragment_shaders.append(load_shader(filepath, type='FRAGMENT'))

    def link_shaders(self):
        """
        Links the shader program.
        Succeeds only if vertex shader and all required fragment components are attached.
        Required fragments: DVR_FRAGMENT_BACK_FRONT_v1.2.fs, classify.fs, grad.fs, light.fs, shadow.fs
        """
        required_fragments = [
            "DVR_FRAGMENT_BACK_FRONT_v1.2.fs",
            "classify.fs",
            "grad.fs",
            "light.fs",
            "shadow.fs"
        ]
        
        # Check if all required fragment files are present in self.fragment_shaders
        # and if vertex shader is present
        if self.vertex_shader and all(f in self.fragment_shaders for f in required_fragments):
            self.program = compile_program(self.vertex_shader, self.fragment_shaders)
            self.program_linked = True
        else:
            self.program_linked = False

    def set_feature(self, feature_name, enabled):
        """
        Enables or disables a rendering feature.
        """
        if feature_name in self.features:
            self.features[feature_name] = enabled

    def render(self):
        """
        Executes the rendering pipeline.
        """
        if not self.program_linked:
            raise Exception("Shaders not linked")
        
        if self.volume_data is None:
            raise Exception("No volume data loaded")

        # Bind volume data to GPU texture
        bind_volume_texture(self.volume_data)
        
        # Set transfer functions based on histograms
        set_transfer_function(self.histograms)
        
        # Configure shader uniforms based on enabled features
        configure_shader_uniforms(self.features)
        
        # Execute draw call (e.g., draw a quad or volume mesh)
        # The fragment shader performs the single-pass GPU ray casting
        execute_draw_call(self.program)
```

### Parameters and Edge Cases
*   **Data Range Expansion:** VStudio expands the data value range during import [S1]. Implementers must account for this scaling when defining transfer functions, as the input values to the shader may differ from the raw file values.
*   **Histogram Abortion:** Aborting the advanced ACC histogram calculation results in a fallback to a traditional density-only histogram [S1]. This may degrade the quality of interactive transfer function specification, particularly for gradient-based classification.
*   **Header Constraints:** For `.vol*` formats, voxel counts and scales must be between 1 and 4096 [S1]. Values outside this range will likely cause import errors or undefined behavior.
*   **Shader Dependency:** The framework relies on a specific set of fragment shader files (`classify.fs`, `grad.fs`, `light.fs`, `shadow.fs`) being attached alongside the main fragment shader [S1]. Missing any of these will prevent linking.

## Operating characteristics
*   **Performance:** The method uses single-pass GPU ray casting, which is generally efficient for interactive visualization [S1].
*   **Interactivity:** The framework supports interactive shader editing, allowing users to modify classification, lighting, and shadowing logic in real-time [S1].
*   **Features:** Supports Blinn Lighting, Early Ray Termination, Progressive Refinement, Stochastic Ray Shifting, Brute Force Shadow-Ray Traversal, MIP, and Slicing [S1].
*   **Limitations:** The reliance on specific shader file structures and the need for manual shader attachment may increase complexity for users compared to fully automated pipelines. The "advanced ACC histogram" calculation can be time-consuming and, if aborted, reduces functionality [S1].
*   **Scene Management:** Scenes are saved as text-based `.vst` files, referencing shader filenames rather than embedding shader code [S1].

## Background
The VStudio Framework was created by Robert Hausmair, a student at the Technical University of Vienna, Austria [S1]. It was developed as part of the "Visualisierung" (Visualization) course at the university [S1]. The framework is designed to demonstrate and facilitate interactive volume visualization techniques, particularly focusing on the customization of the rendering pipeline through shader editing [S1]. Datasets for testing are provided via the LU Visualisierung webpage [S1].
