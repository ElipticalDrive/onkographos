# Back-face rasterized volume rendering

Also called: Back-Face Entry Point Method, Backface Rendering for Ray Casting, Backface Culling for Ray Casting Entry Points

## Overview
Back-face rasterized volume rendering is a GPU-accelerated technique that determines ray entry and exit points for volume traversal by rasterizing the volume's bounding box geometry [S1, S4, unofficial]. It solves the problem of efficiently activating fragment shaders only for pixels intersecting the volume while avoiding expensive per-pixel ray-box intersection calculations in the final rendering pass [S2, S3, unofficial]. It differs from [Bounding Box Raymarching](2071-bounding-box-raymarching.md) by explicitly utilizing a two-pass approach where the first pass captures back-face coordinates into a texture, and the second pass uses these coordinates to define ray endpoints for front-to-back compositing [S1, S2, S3, unofficial]. Unlike [Volume Ray Casting with RayData Texture](3077-volume-ray-casting-with-raydata-texture.md), which stores ray data in a dedicated texture, this method often computes ray directions from geometry attributes or camera matrices directly in the fragment shader [S5, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D volume texture ($V$), transfer function texture ($TF$), camera projection and view matrices ($M_{proj}, M_{view}$), camera position ($\boldsymbol{o}$), viewport resolution ($W, H$), number of sampling steps ($N$ or step size $\Delta$).
*   **Outputs:** Final 2D color buffer with composited volume image.

**Data Structures:**
1.  **Bounding Box Geometry:** A unit cube defined in object coordinates $[0,1]^3$.
    *   Vertices: 8 vertices at corners $(x,y,z) \in \{0,1\}^3$.
    *   Indices: 36 indices defining 12 triangles covering the cube surface [S4, unofficial].
2.  **Back-Face Texture ($T_{back}$):** A 2D texture of size $W \times H$.
    *   Format: `GL_RGBA16F` (or equivalent high-precision float format) [S4, unofficial].
    *   Content: Stores the 3D world/object coordinates of the back-face intersection points as RGB color values [S1, S4, unofficial].
3.  **Frame Buffer Object (FBO):** Attached to $T_{back}$ for the first pass [S4, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    *   Create FBO and attach 2D texture $T_{back}$ as color attachment [S4, unofficial].
    *   Define bounding box geometry (unit cube) [S4, unofficial].
    *   Set up 3D volume texture and transfer function texture [S1, S4, unofficial].

2.  **Pass 1: Capture Back-Face Entry Points:**
    *   Bind FBO with $T_{back}$ [S4, unofficial].
    *   Set viewport to $(0, 0, W, H)$ [S1, unofficial].
    *   Enable face culling: `glCullFace(GL_FRONT)` to render only back faces [S1, S4, unofficial].
    *   Render the bounding box using the **Back-Face Shader**:
        *   Vertex Shader: Transforms vertex positions to clip space. Outputs the original vertex position (in object/world space) as a varying color `fragPos` [S4, unofficial].
        *   Fragment Shader: Writes `fragPos` (as `vec4(fragPos, 1.0)`) to the output color buffer [S4, unofficial]. This stores the 3D entry point of the ray into the volume for each pixel [S1, S4, unofficial].
    *   Unbind FBO [S1, unofficial].

3.  **Pass 2: Ray Marching and Compositing:**
    *   Bind default framebuffer [S1, unofficial].
    *   Enable face culling: `glCullFace(GL_BACK)` to render only front faces [S1, S4, unofficial].
    *   Render the bounding box using the **Raycast Shader**:
        *   Vertex Shader: Outputs the current vertex position (front face) as `EntryPoint` [S4, unofficial].
        *   Fragment Shader:
            1.  Sample $T_{back}$ using interpolated fragment coordinates (normalized by resolution) to retrieve the back-face position (`ExitPoint`) [S4, unofficial].
            2.  Compute ray direction: $\boldsymbol{d} = \text{ExitPoint} - \text{EntryPoint}$ [S4, unofficial].
            3.  Compute ray length: $L = \|\boldsymbol{d}\|$ [S4, unofficial].
            4.  **Edge Case:** If $L \approx 0$ (entry equals exit, e.g., tangent ray), discard fragment to avoid division by zero [S4, unofficial].
            5.  Compute step vector: $\boldsymbol{s} = \frac{\boldsymbol{d}}{N}$ (or using fixed step size $\Delta$) [S1, S4, unofficial].
            6.  Initialize accumulation: $\boldsymbol{C}_{acc} = (0,0,0,0)$, $\alpha_{acc} = 0$ [S4, unofficial].
            7.  Set current position $\boldsymbol{p} = \text{EntryPoint}$ [S4, unofficial].
            8.  **Ray Marching Loop:** For $i = 0$ to $N-1$:
                *   Sample volume: $v = \text{texture}(V, \boldsymbol{p})$ [S4, unofficial].
                *   Map to color/opacity: $(\boldsymbol{c}, \alpha) = \text{texture}(TF, v)$ [S4, unofficial].
                *   Apply transfer function adjustments if necessary (e.g., step-size dependent opacity scaling) [S4, unofficial].
                *   Composite:
                    $$ \boldsymbol{C}_{acc}.\text{rgb} \leftarrow \boldsymbol{C}_{acc}.\text{rgb} + (1 - \alpha_{acc}) \cdot \boldsymbol{c} \cdot \alpha $$
                    $$ \alpha_{acc} \leftarrow \alpha_{acc} + (1 - \alpha_{acc}) \cdot \alpha $$
                *   Advance position: $\boldsymbol{p} \leftarrow \boldsymbol{p} + \boldsymbol{s}$ [S4, unofficial].
                *   **Early Termination:** If $\alpha_{acc} \ge 1.0$ (or threshold like 0.95), break loop [S1, S4, unofficial].
                *   **Boundary Check:** If $\boldsymbol{p}$ goes outside $[0,1]^3$, break loop [S1, unofficial].
            9.  Final color: $\boldsymbol{C}_{final} = \boldsymbol{C}_{acc}.\text{rgb} + (1 - \alpha_{acc}) \cdot \boldsymbol{C}_{bg}$, where $\boldsymbol{C}_{bg}$ is background color (e.g., white) [S4, unofficial].
            10. Output $\boldsymbol{C}_{final}$ [S4, unofficial].

**Pseudocode (Fragment Shader for Pass 2):**

```python
# Inputs:
# EntryPoint: vec3 (interpolated from vertex shader, front face position)
# u_ExitPoints: sampler2D (texture from Pass 1)
# u_VolumeTex: sampler3D
# u_TransferFunc: sampler1D or sampler2D
# u_Resolution: vec2 (viewport width, height)
# u_StepSize: float (fixed step size or 1.0/N)
# u_Steps: int (total steps, if using fixed step size logic)

vec4 main() {
    // 1. Retrieve exit point from back-face texture
    // gl_FragCoord.st are screen coordinates; normalize by resolution
    vec2 uv = gl_FragCoord.xy / u_Resolution;
    vec3 exitPoint = texture(u_ExitPoints, uv).xyz;
    
    // 2. Check for degenerate ray (entry == exit)
    if (length(exitPoint - EntryPoint) < 1e-6) {
        discard;
    }
    
    // 3. Compute ray direction and length
    vec3 dir = exitPoint - EntryPoint;
    float len = length(dir);
    
    // 4. Compute step vector
    // Option A: Fixed number of steps
    // float stepLen = len / u_Steps;
    // vec3 stepVec = dir / u_Steps;
    
    // Option B: Fixed step size (delta)
    vec3 stepVec = normalize(dir) * u_StepSize;
    float stepLen = u_StepSize;
    
    // 5. Initialize accumulation
    vec4 colorAccum = vec4(0.0);
    float alphaAccum = 0.0;
    vec3 bgColor = vec4(1.0, 1.0, 1.0, 1.0).rgb; // White background
    vec3 pos = EntryPoint;
    
    // 6. Ray Marching Loop
    // Using a large constant loop bound for GLSL compatibility, break early
    for (int i = 0; i < 1600; i++) {
        // Sample volume
        float intensity = texture(u_VolumeTex, pos).r;
        
        // Map to color and opacity
        vec4 colorSample = texture(u_TransferFunc, intensity);
        
        // Apply opacity scaling if needed (e.g., for fixed step size)
        // colorSample.a = 1.0 - pow(1.0 - colorSample.a, u_StepSize * scale);
        
        if (colorSample.a > 0.0) {
            // Front-to-back compositing
            colorAccum.rgb += (1.0 - colorAccum.a) * colorSample.rgb * colorSample.a;
            colorAccum.a += (1.0 - colorAccum.a) * colorSample.a;
        }
        
        // Advance position
        pos += stepVec;
        
        // Early termination: fully opaque
        if (colorAccum.a >= 1.0) {
            break;
        }
        
        // Boundary check: if pos is outside [0,1] (assuming unit cube)
        if (any(greaterThan(pos, vec3(1.0))) || any(lessThan(pos, vec3(0.0)))) {
            break;
        }
    }
    
    // 7. Composite with background
    vec3 finalColor = colorAccum.rgb + (1.0 - colorAccum.a) * bgColor;
    return vec4(finalColor, 1.0);
}
```

**Parameters with Typical Values:**
*   `uSteps` (Number of sampling steps): 256 [S1, unofficial].
*   `uStepSize` (Fixed step size): 0.005 [S3, unofficial].
*   `uOpacityVal` (Opacity scaling): 4.0 [S1, unofficial].
*   `uMinGrayVal` / `uMaxGrayVal` (Volume value thresholds): 0.001 / 1.0 [S1, unofficial].
*   `DELTA` (Gradient/Step constant): 0.005 [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Zooming Issues:** Rendering only front faces causes clipping when the camera zooms in, as front faces project behind the camera. Rendering back faces avoids this [S2, unofficial].
*   **Tangent/Missing Rays:** If the ray is tangent to the box or misses it, entry and exit points may be identical or invalid. Discard such fragments [S4, unofficial].
*   **Loop Termination:** GLSL may require fixed loop bounds. Use a large constant (e.g., 1600 or 4095) and break explicitly based on conditions [S1, S4, unofficial].
*   **Precision:** Use `GL_RGBA16F` for the back-face texture to ensure accurate 3D coordinate storage [S4, unofficial].
*   **Compositing Modes:** Some implementations support MIP or MIDA modes, but "mida" may have bugs [S3, unofficial].

## Subtopics

### [Bounding Box Raymarching](2071-bounding-box-raymarching.md)
A variant that explicitly uses a two-pass approach to derive ray bounds from geometry colors, avoiding manual ray-box intersection math in the fragment shader. It differs by storing exit points in a texture in the first pass and using them in the second. Choose when you want to offload intersection math to the rasterizer.

### [Entry Point Adjustment](7406-entry-point-adjustment.md)
A technique to refine the entry points determined by back-face rasterization, often used to correct for aliasing or improve accuracy at the volume boundaries. Choose when high-quality boundary rendering is critical.

## Operating characteristics
*   **Time Complexity:** $O(W \cdot H \cdot N)$, where $W, H$ are viewport dimensions and $N$ is the number of samples per ray. The two-pass approach adds constant overhead.
*   **Memory Complexity:** $O(W \cdot H)$ for the back-face texture storage [S4, unofficial].
*   **Performance:** Efficient because fragment shader execution is restricted to pixels intersecting the volume [S2, unofficial]. Early ray termination further reduces average sample count [S1, S4, unofficial].
*   **Strengths:** Simple implementation, leverages hardware rasterization for culling, handles zooming correctly by using back faces [S2, unofficial].
*   **Limitations:** Requires two render passes and an extra texture bind/sampling [S4, unofficial]. Precision of entry/exit points depends on texture format and rasterization accuracy [S4, unofficial].
*   **When to Use:** Standard direct volume rendering on GPU where simplicity and compatibility are priorities.
*   **When Not to Use:** When single-pass performance is critical (consider [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) or [Triton-accelerated Volume Raycasting](3379-triton-accelerated-volume-raycasting.md)).

## Background
The method originates from early GPU-accelerated volume rendering techniques that sought to replace CPU-driven ray casting with fragment shader execution [S2, unofficial]. It was popularized in WebGL and OpenGL tutorials as a straightforward way to implement volume rendering without complex ray-triangle intersection code [S2, S4, unofficial]. The core idea of using back-face culling to determine entry points was documented in various open-source implementations and blog posts around 2017-2019 [S1, S2, S3, S4, unofficial].
