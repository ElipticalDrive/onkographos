# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated volume rendering technique that enables the camera to move inside the volume's bounding box without the view disappearing or clipping artifacts. It solves the problem of standard ray casting failing when the camera origin exceeds the back face of the volume by dynamically shifting the ray's entry point forward along the ray direction based on a scale coefficient [S1, unofficial]. Unlike standard direct volume ray casting where the ray always starts at the camera position, this method decouples the visual entry point from the physical camera position to maintain continuous visibility [S1, unofficial].

## How it works
The method operates in a two-pass pipeline. First, the exit points of rays passing through the volume are pre-computed. Second, the front face is rendered, and for each pixel, the pre-computed exit point is used to define the ray segment, which is then marched through the volume texture.

### Inputs and Outputs
*   **Inputs**:
    *   `VolumeTex`: A 3D texture containing the scalar volume data [S1, unofficial].
    *   `TransferFunc`: A 1D texture mapping scalar values to RGBA color and opacity [S1, unofficial].
    *   `ExitPoints`: A 2D texture storing the 3D exit coordinates for each pixel, generated in the first pass [S1, unofficial].
    *   `ScreenSize`: A uniform vector $(W, H)$ representing the resolution of the viewport [S1, unofficial].
    *   `StepSize`: A uniform float controlling the distance between samples along the ray [S1, unofficial].
    *   `AlphaReduce`: A uniform float multiplier applied to the sampled alpha to increase transparency [S1, unofficial].
    *   `scaleCoeff`: A uniform float representing the scaling factor of the volume, used to determine if the camera is inside [S1, unofficial].
*   **Outputs**:
    *   `FragColor`: The final accumulated RGBA color for the pixel [S1, unofficial].

### Data Structures
*   **ExitPoints Texture**: A 2D texture where each texel stores a `vec3` (xyz) representing the 3D world coordinates of the ray's exit point from the volume's back face. The texture coordinates are normalized screen coordinates [S1, unofficial].
*   **Volume Texture**: A 3D texture (`VolumeTex`) storing the scalar field. Sampling returns a `vec4` where the alpha channel typically holds the scalar value or is used to index the transfer function [S1, unofficial].

### Numbered Steps

1.  **Pre-computation (Back Face Pass)**: Render the back face of the volume's axis-aligned bounding box (AABB) into a framebuffer object bound to a 2D texture named `ExitPoints`. The color of each vertex in the back face corresponds to its 3D location. This stores the exit coordinates for rays passing through the back face [S1, unofficial].
2.  **Front Face Rendering**: Render the front face of the volume's AABB to the screen. The vertex shader passes the entry point (`EntryPoint`) to the fragment shader [S1, unofficial].
3.  **Retrieve Exit Point**: In the fragment shader, retrieve the exit point for the current pixel from the `ExitPoints` texture using the screen coordinates normalized by `ScreenSize`:
    $$ \mathbf{p}_{exit} = \text{texture}(\text{ExitPoints}, \frac{\mathbf{gl\_FragCoord.st}}{\text{ScreenSize}}).xyz $$
    [S1, unofficial]
4.  **Discard Invalid Rays**: If the entry point equals the exit point ($\mathbf{p}_{entry} == \mathbf{p}_{exit}$), the ray does not pass through the volume or the camera is outside in a way that yields no intersection. Discard the fragment [S1, unofficial].
5.  **Calculate Ray Direction**: Compute the ray direction by normalizing the vector from the entry point to the exit point:
    $$ \mathbf{d} = \text{normalize}(\mathbf{p}_{exit} - \mathbf{p}_{entry}) $$
    [S1, unofficial]
6.  **Adjust Entry Point (Flowing Through)**: To handle the case where the camera is inside the volume, adjust the entry point based on `scaleCoeff`. If `scaleCoeff` $\ge 2.7$, calculate a temporary shift factor:
    $$ \tau = \min((\text{scaleCoeff} - 2.7) \times 0.1, 1.0) $$
    Shift the entry point forward:
    $$ \mathbf{p}_{entry}' = \mathbf{p}_{entry} + \tau (\mathbf{p}_{exit} - \mathbf{p}_{entry}) $$
    If `scaleCoeff` $< 2.7$, use the original entry point ($\mathbf{p}_{entry}' = \mathbf{p}_{entry}$) [S1, unofficial].
7.  **Initialize Variables**:
    *   Current position: $\mathbf{p}_{curr} = \mathbf{p}_{entry}'$
    *   Accumulated color: $C_{sum} = (0, 0, 0, 0)$
    *   Step vector: $\mathbf{s} = \mathbf{d} \times \text{StepSize}$
    *   Total ray length: $L = \|\mathbf{p}_{exit} - \mathbf{p}_{entry}'\|$
    *   Accumulated length: $L_{curr} = 0$
    [S1, unofficial]
8.  **Ray Marching Loop**: Iterate up to a maximum number of steps (e.g., 16,000):
    a.  **Sample Volume**: Sample the scalar value from `VolumeTex` at $\mathbf{p}_{curr}$. Let the result be $V$.
    b.  **Classification**: Sample the `TransferFunc` using the alpha channel of $V$ (or $V$ itself, depending on implementation) to get color $C$ and opacity $\alpha$.
    c.  **Adjust Opacity**: Multiply the alpha by `AlphaReduce`: $\alpha' = \alpha \times \text{AlphaReduce}$ [S1, unofficial].
    d.  **Compositing**: Perform front-to-back blending:
        $$ C_{sum} = (1 - C_{sum}.a) \times (C \times \alpha') + C_{sum} $$
        Note: The source code multiplies $C.rgb$ by $\alpha'$ before adding. The standard over operator is implied by the weighting $(1 - C_{sum}.a)$ [S1, unofficial].
    e.  **Termination Check 1**: If $C_{sum}.a \ge 0.95$, break the loop [S1, unofficial].
    f.  **Advance Position**: $\mathbf{p}_{curr} = \mathbf{p}_{curr} + \mathbf{s}$
    g.  **Accumulate Length**: $L_{curr} = L_{curr} + \|\mathbf{s}\|$
    h.  **Termination Check 2**: If $L_{curr} \ge L$, break the loop [S1, unofficial].
9.  **Output**: Write $C_{sum}$ to `FragColor` [S1, unofficial].

### Pseudocode

```python
# Fragment Shader Logic
# Inputs: EntryPoint (vec3), gl_FragCoord (vec2), ScreenSize (vec2)
# Uniforms: ExitPoints (sampler2D), VolumeTex (sampler3D), TransferFunc (sampler1D)
#           StepSize (float), AlphaReduce (float), scaleCoeff (float)

def fragment_shader(EntryPoint, gl_FragCoord, ScreenSize, ExitPoints, VolumeTex, TransferFunc, StepSize, AlphaReduce, scaleCoeff):
    # 1. Retrieve Exit Point
    normalized_coord = gl_FragCoord / ScreenSize
    exit_point = texture(ExitPoints, normalized_coord)
    
    # 2. Discard if no intersection
    if EntryPoint == exit_point:
        discard()
        
    # 3. Calculate Ray Direction
    ray_direction = normalize(exit_point - EntryPoint)
    
    # 4. Adjust Entry Point for Inside-Volume Rendering
    if scaleCoeff >= 2.7:
        tmp = min((scaleCoeff - 2.7) * 0.1, 1.0)
        entry_point = EntryPoint + tmp * (exit_point - EntryPoint)
    else:
        entry_point = EntryPoint
        
    # 5. Initialize
    current_position = entry_point
    color_sum = vec4(0.0, 0.0, 0.0, 0.0)
    step_vector = ray_direction * StepSize
    step_length = length(step_vector)
    total_length = length(exit_point - entry_point)
    accumulated_length = 0.0
    
    # 6. Ray Marching
    for i in range(16000):
        # Sample Volume
        value = texture(VolumeTex, current_position)
        
        # Classification
        color = texture(TransferFunc, value.a)
        
        # Reduce Alpha
        color.a *= AlphaReduce
        
        # Front-to-Back Blending
        # Note: Source code: colorSum = (1.0 - colorSum.a) * color + colorSum
        # This implies color.rgb is already multiplied by alpha in the source logic or 
        # the formula assumes color includes the alpha weighting. 
        # Based on source: color.rgb *= color.a; then colorSum = ...
        color.rgb *= color.a
        color_sum = (1.0 - color_sum.a) * color + color_sum
        
        # Termination Check 1
        if color_sum.a >= 0.95:
            break
            
        # Advance
        accumulated_length += step_length
        current_position += step_vector
        
        # Termination Check 2
        if accumulated_length >= total_length:
            break
            
    return color_sum
```

### Parameters and Typical Values
*   `StepSize`: Controls sampling density. Not given in the sources.
*   `AlphaReduce`: Multiplier for transparency. Not given in the sources.
*   `scaleCoeff`: Threshold for entering "flowing" mode is 2.7. The shift rate is 0.1 per unit above 2.7. [S1, unofficial]

### Edge Cases and Pitfalls
*   **Precision**: The method relies on exact equality `EntryPoint == exitPoint` to discard fragments. Floating-point precision issues might cause valid rays to be discarded or invalid rays to be processed. [S1, unofficial]
*   **Clipping**: The method shifts the entry point but does not clip the ray against the volume boundaries during marching, relying on the loop termination condition `accumulated_length >= total_length`. [S1, unofficial]
*   **Alternative**: Plane Clipping is suggested as an alternative method to handle visibility through the volume, implying Entry Point Adjustment is one specific heuristic among others. [S1, unofficial]

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of samples per ray. The loop runs up to 16,000 times, but typically terminates early when opacity reaches 0.95 or the ray exits the bounding box. [S1, unofficial]
*   **Memory Complexity**: Requires storage for the `ExitPoints` 2D texture, which is proportional to the screen resolution. [S1, unofficial]
*   **Strengths**: Allows the camera to move inside the volume, creating a "flowing through" effect without the view disappearing. It leverages standard hardware rasterization for the back-face pass and ray marching for the front face. [S1, unofficial]
*   **Limitations**: The entry point adjustment is heuristic-based (threshold 2.7) and may not perfectly simulate being "surrounded" by the volume. It assumes a simple AABB bounding box. [S1, unofficial]
*   **When to use**: When the application requires the user to fly through or inside the volume data. [S1, unofficial]
*   **When not to use**: When precise geometric clipping is required or when the volume has complex bounding shapes that cannot be approximated by an AABB. [S1, unofficial]
