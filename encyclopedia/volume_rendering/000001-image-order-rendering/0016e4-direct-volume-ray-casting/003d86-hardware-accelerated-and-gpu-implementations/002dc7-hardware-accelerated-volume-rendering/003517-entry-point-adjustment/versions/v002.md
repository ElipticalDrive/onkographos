# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated technique for direct volume ray casting that enables the camera to move inside the volume's bounding box without the view disappearing or clipping artifacts [S1, unofficial]. It solves the problem of ray origin placement when the viewer penetrates the front face of the volume by dynamically shifting the ray entry point forward along the ray direction based on a scale coefficient [S1, unofficial]. Unlike standard hardware-accelerated methods that assume the camera remains outside the volume, this method allows for a "flowing through" experience by adjusting the start of the ray march [S1, unofficial].

## How it works
The method uses a two-pass rendering approach to determine ray boundaries and a fragment shader to perform the volume integration with dynamic entry point adjustment.

**Inputs and Outputs:**
*   **Inputs:** 3D volume texture (`VolumeTex`), 1D transfer function texture (`TransferFunc`), screen coordinates, camera position, volume scale coefficient (`scaleCoeff`), step size (`StepSize`), alpha reduction factor (`AlphaReduce`), and screen resolution (`ScreenSize`).
*   **Outputs:** Final color buffer (`FragColor`).

**Data Structures:**
1.  **ExitPoints Texture:** A 2D texture (`sampler2D`) storing the 3D exit coordinates of rays passing through the back face of the volume bounding box. Each pixel stores an `xyz` vector.
2.  **VolumeTex:** A 3D texture (`sampler3D`) storing the scalar field data.
3.  **TransferFunc:** A 1D texture (`sampler1D`) mapping scalar values (alpha channel) to RGBA color values.

**Numbered Steps:**

1.  **Back Face Rendering (Pre-pass):** Render the back face of the volume's bounding box into a framebuffer object (FBO) attached to the `ExitPoints` 2D texture. The color of each vertex in the back face corresponds to its 3D world position, effectively storing the exit point for every ray passing through that face [S1, unofficial].
2.  **Front Face Rendering (Main Pass):** Render the front face of the volume bounding box to the screen. Pass the original entry point (camera intersection with front face) as a vertex attribute (`EntryPoint`) to the fragment shader [S1, unofficial].
3.  **Retrieve Exit Point:** In the fragment shader, sample the `ExitPoints` texture using normalized screen coordinates (`gl_FragCoord.st / ScreenSize`) to retrieve the `exitPoint` for the current pixel [S1, unofficial].
4.  **Discard Invalid Rays:** If the `EntryPoint` equals the `exitPoint`, the ray does not pass through the volume (or the camera is positioned such that no volume is visible). Discard the fragment [S1, unofficial].
5.  **Calculate Ray Direction:** Compute the ray direction vector by normalizing the difference between the exit and entry points:
    $$ \vec{d} = \text{normalize}(\text{exitPoint} - \text{EntryPoint}) $$
6.  **Adjust Entry Point (Flowing Through):** Determine the effective entry point based on the `scaleCoeff` parameter [S1, unofficial]:
    *   If `scaleCoeff >= 2.7`:
        Calculate a temporary shift factor:
        $$ tmp = \min((\text{scaleCoeff} - 2.7) \times 0.1, 1.0) $$
        Shift the entry point forward:
        $$ \text{effectiveEntryPoint} = \text{EntryPoint} + tmp \times (\text{exitPoint} - \text{EntryPoint}) $$
    *   If `scaleCoeff < 2.7`:
        $$ \text{effectiveEntryPoint} = \text{EntryPoint} $$
    *   *Note:* This adjustment prevents the view from disappearing when the camera moves deep into the volume [S1, unofficial].
7.  **Initialize Variables:**
    *   Set current position `P` to `effectiveEntryPoint`.
    *   Initialize accumulated color `colorSum` to `(0, 0, 0, 0)`.
    *   Calculate step vector: $\vec{Step} = \vec{d} \times \text{StepSize}$.
    *   Calculate total ray length: $L = \|\text{exitPoint} - \text{EntryPoint}\|$.
    *   Initialize accumulated length `LengthSum` to 0.
8.  **Ray Marching Loop:** Iterate up to a maximum number of steps (e.g., 16,000) [S1, unofficial]:
    a.  **Sample Volume:** Sample `VolumeTex` at `P` to get scalar value `v`.
    b.  **Transfer Function:** Sample `TransferFunc` using `v.a` to get color `C` [S1, unofficial].
    c.  **Alpha Reduction:** Multiply alpha by `AlphaReduce`: $C.a = C.a \times \text{AlphaReduce}$ [S1, unofficial].
    d.  **Front-to-Back Blending:**
        $$ C.rgb = C.rgb \times C.a $$
        $$ \text{colorSum} = (1.0 - \text{colorSum}.a) \times C + \text{colorSum} $$
    e.  **Update Length:** `LengthSum += length(Step)` [S1, unofficial].
    f.  **Termination Conditions:**
        *   If `colorSum.a >= 0.95`, break loop [S1, unofficial].
        *   If `LengthSum >= L`, break loop [S1, unofficial].
    g.  **Advance Position:** `P += Step` [S1, unofficial].
9.  **Output:** Write `colorSum` to the framebuffer [S1, unofficial].

**Pseudocode:**

```python
# Fragment Shader Logic
# Inputs: EntryPoint (vec3), ExitPointCoord (vec4, unused in logic but passed),
#         ExitPoints (sampler2D), VolumeTex (sampler3D), TransferFunc (sampler1D),
#         StepSize (float), AlphaReduce (float), ScreenSize (vec2), scaleCoeff (float)

def fragment_shader(EntryPoint, ExitPointCoord, ExitPoints, VolumeTex, TransferFunc,
                    StepSize, AlphaReduce, ScreenSize, scaleCoeff):
    # 1. Retrieve exit point from texture
    normalized_coord = gl_FragCoord.st / ScreenSize
    exitPoint = texture(ExitPoints, normalized_coord).xyz

    # 2. Check if ray passes through volume
    if EntryPoint == exitPoint:
        discard_fragment()

    # 3. Calculate ray direction
    rayDirection = normalize(exitPoint - EntryPoint)

    # 4. Adjust entry point for "flowing through" effect
    if scaleCoeff >= 2.7:
        tmp = min((scaleCoeff - 2.7) * 0.1, 1.0)
        effectiveEntryPoint = EntryPoint + tmp * (exitPoint - EntryPoint)
    else:
        effectiveEntryPoint = EntryPoint

    # 5. Initialize variables
    currentPosition = effectiveEntryPoint
    colorSum = vec4(0.0, 0.0, 0.0, 0.0)
    
    stepVector = rayDirection * StepSize
    stepLength = length(stepVector)
    totalLength = length(exitPoint - EntryPoint)
    accumulatedLength = 0.0

    # 6. Ray marching loop
    for i in range(16000):
        # Sample volume
        value = texture(VolumeTex, currentPosition)
        
        # Apply transfer function
        color = texture(TransferFunc, value.a)
        
        # Reduce alpha
        color.a *= AlphaReduce
        
        # Front-to-back blending
        color.rgb *= color.a
        colorSum = (1.0 - colorSum.a) * color + colorSum
        
        # Update length
        accumulatedLength += stepLength
        
        # Termination checks
        if colorSum.a >= 0.95:
            break
        if accumulatedLength >= totalLength:
            break
            
        # Advance position
        currentPosition += stepVector

    return colorSum
```

**Parameters:**
*   `StepSize`: Uniform float controlling the distance between samples along the ray [S1, unofficial].
*   `AlphaReduce`: Uniform float multiplier applied to alpha to increase transparency [S1, unofficial].
*   `scaleCoeff`: Custom uniform representing the scaling factor of the volume, used to determine if the camera is inside the volume [S1, unofficial].
*   `ScreenSize`: Uniform vec2 representing the resolution of the screen [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Comparing `EntryPoint == exitPoint` for discarding fragments may suffer from floating-point precision issues. A tolerance-based comparison might be more robust in practice [G].
*   **Boundary Conditions:** The method relies on the back face being rendered correctly. If the volume bounding box is not convex or the camera is positioned such that the back face is not visible, the exit point retrieval may fail [G].
*   **Performance:** The loop limit of 16,000 steps is arbitrary and may lead to unnecessary computation if the volume is thin or the step size is large. Early termination based on opacity is crucial [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray, which depends on the volume thickness and `StepSize`. The maximum iterations are capped at 16,000 [S1, unofficial].
*   **Memory Complexity:** Requires storage for the `ExitPoints` 2D texture (resolution of the screen) and the `VolumeTex` 3D texture [S1, unofficial].
*   **Strengths:** Enables seamless navigation inside the volume without clipping artifacts. Simple to implement on modern graphics hardware using standard fragment shaders [S1, unofficial].
*   **Limitations:** The "flowing through" effect is approximated by shifting the entry point, which may not perfectly simulate being surrounded by the volume. The method assumes a convex bounding box [S1, unofficial].
*   **When to use:** When the application requires the user to move inside the volume (e.g., medical visualization, virtual reality).
*   **When not to use:** When the camera is strictly outside the volume, standard ray casting is more efficient.
