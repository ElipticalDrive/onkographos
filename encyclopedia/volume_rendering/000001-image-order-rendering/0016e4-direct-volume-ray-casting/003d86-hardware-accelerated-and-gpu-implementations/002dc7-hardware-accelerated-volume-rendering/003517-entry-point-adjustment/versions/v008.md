# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated technique for direct volume ray casting that enables the camera to move inside the volume's bounding box without the view disappearing or clipping artifacts [S1, unofficial]. It solves the problem of ray origin placement when the viewer penetrates the volume by dynamically shifting the ray entry point forward along the ray direction based on a scale coefficient [S1, unofficial]. Unlike standard ray casting where the entry point is fixed at the front face of the bounding box, this method adjusts the start of the ray march to maintain visibility through the volume as the camera moves deeper [S1, unofficial].

## How it works
The method uses a two-pass rendering approach to determine ray boundaries and a fragment shader to perform the ray marching with dynamic entry adjustment.

### Inputs and Outputs
*   **Inputs**:
    *   `VolumeTex`: A 3D texture containing the scalar volume data.
    *   `TransferFunc`: A 1D texture mapping scalar values (alpha channel) to RGBA color.
    *   `ExitPoints`: A 2D texture storing the exit coordinates of rays passing through the back face of the volume bounding box.
    *   `EntryPoint`: The screen-space coordinates of the front face of the volume bounding box, passed from the vertex shader.
    *   `ScreenSize`: The resolution of the viewport.
    *   `StepSize`: Uniform float controlling the distance between samples along the ray.
    *   `AlphaReduce`: Uniform float multiplier applied to alpha to increase transparency.
    *   `scaleCoeff`: Uniform float representing the scaling factor of the volume, used to determine if the camera is inside the volume.
*   **Outputs**:
    *   `FragColor`: The final accumulated color for the pixel.

### Data Structures
*   **ExitPoints Texture**: A 2D texture where each texel stores the 3D world-space exit point of the ray corresponding to that pixel. The coordinates are normalized by `ScreenSize` to index the texture.
*   **Volume Texture**: A 3D texture sampled at `currentPosition.xyz`.
*   **Transfer Function**: A 1D texture sampled using the alpha channel of the volume value.

### Steps
1.  **Back-Face Rendering**: Render the back face of the volume bounding box into a framebuffer object bound to a 2D texture (`ExitPoints`). The color of each vertex represents its 3D location, effectively storing the exit point for rays passing through that pixel.
2.  **Front-Face Rendering**: Render the front face of the volume bounding box to the screen. Pass the vertex location as `EntryPoint` to the fragment shader.
3.  **Retrieve Exit Point**: In the fragment shader, retrieve the exit point for the current pixel from the `ExitPoints` texture using `gl_FragCoord.st / ScreenSize`.
4.  **Discard Invalid Rays**: If `EntryPoint` equals `exitPoint`, the ray does not pass through the volume (or the camera is outside in a way that yields no intersection). Discard the fragment.
5.  **Calculate Ray Direction**: Compute the ray direction as the normalized vector from `EntryPoint` to `exitPoint`:
    $$ \mathbf{d} = \frac{\text{exitPoint} - \text{EntryPoint}}{\| \text{exitPoint} - \text{EntryPoint} \|} $$
6.  **Adjust Entry Point**: To handle "flowing through" the volume, adjust the entry point if `scaleCoeff` indicates the camera is inside.
    *   If `scaleCoeff >= 2.7`:
        $$ \text{tmp} = \min((\text{scaleCoeff} - 2.7) \times 0.1, 1.0) $$
        $$ \text{adjustedEntryPoint} = \text{EntryPoint} + \text{tmp} \times (\text{exitPoint} - \text{EntryPoint}) $$
    *   Else:
        $$ \text{adjustedEntryPoint} = \text{EntryPoint} $$
    *   Use `adjustedEntryPoint` as the start of the ray march.
7.  **Initialize Ray Marching**:
    *   Set `currentPosition` to `adjustedEntryPoint`.
    *   Initialize `colorSum` (accumulated color) to $(0, 0, 0, 0)$.
    *   Calculate `Step` vector: $\mathbf{s} = \mathbf{d} \times \text{StepSize}$.
    *   Calculate `stepLength` (magnitude of `Step`).
    *   Calculate `Length` (total distance from `adjustedEntryPoint` to `exitPoint`).
    *   Initialize `LengthSum` to 0.
8.  **Ray March Loop**: Iterate up to 16,000 times (or until termination conditions are met):
    *   Sample the volume: $v = \text{texture}(\text{VolumeTex}, \text{currentPosition})$.
    *   Sample the transfer function: $c = \text{texture}(\text{TransferFunc}, v.a)$.
    *   Reduce alpha: $c.a = c.a \times \text{AlphaReduce}$.
    *   Front-to-back compositing:
        $$ \text{colorSum}.rgb = \text{colorSum}.rgb + (1.0 - \text{colorSum}.a) \times (c.rgb \times c.a) $$
        $$ \text{colorSum}.a = \text{colorSum}.a + (1.0 - \text{colorSum}.a) \times c.a $$
    *   Accumulate length: $\text{LengthSum} += \text{stepLength}$.
    *   **Early Termination**: If $\text{colorSum}.a \ge 0.95$, break the loop.
    *   **Boundary Check**: If $\text{LengthSum} \ge \text{Length}$, break the loop.
    *   Advance position: $\text{currentPosition}.xyz += \mathbf{s}$.
9.  **Output**: Write `colorSum` to the framebuffer.

### Pseudocode
```python
# Fragment Shader Logic
def fragment_shader(entry_point: vec3, exit_point_coord: vec4, 
                    exit_points_tex: sampler2D, volume_tex: sampler3D, 
                    transfer_func: sampler1D, screen_size: vec2,
                    step_size: float, alpha_reduce: float, scale_coeff: float) -> vec4:
    
    # 1. Retrieve exit point from texture
    uv = exit_point_coord.xy / screen_size
    exit_point = texture(exit_points_tex, uv).xyz
    
    # 2. Check if ray passes through volume
    if entry_point == exit_point:
        discard_fragment()
        
    # 3. Calculate ray direction
    ray_direction = normalize(exit_point - entry_point)
    
    # 4. Adjust entry point for inside-volume rendering
    if scale_coeff >= 2.7:
        tmp = min((scale_coeff - 2.7) * 0.1, 1.0)
        adjusted_entry_point = entry_point + tmp * (exit_point - entry_point)
    else:
        adjusted_entry_point = entry_point
        
    # 5. Initialize variables
    current_position = vec3(adjusted_entry_point, 0.0)
    color_sum = vec4(0.0, 0.0, 0.0, 0.0)
    
    step_vector = ray_direction * step_size
    step_length = length(step_vector)
    total_length = length(exit_point - adjusted_entry_point)
    length_sum = 0.0
    
    # 6. Ray marching loop
    for i in range(16000):
        # Sample volume and transfer function
        value = texture(volume_tex, current_position).a
        color = texture(transfer_func, value)
        
        # Reduce alpha
        color.a *= alpha_reduce
        
        # Front-to-back blending
        color.rgb *= color.a
        color_sum.rgb = color_sum.rgb + (1.0 - color_sum.a) * color.rgb
        color_sum.a = color_sum.a + (1.0 - color_sum.a) * color.a
        
        # Accumulate length
        length_sum += step_length
        
        # Early termination
        if color_sum.a >= 0.95:
            break
            
        # Boundary check
        if length_sum >= total_length:
            break
            
        # Advance position
        current_position += step_vector
        
    return color_sum
```

### Parameters
*   `StepSize`: Controls sample density. Not given in the sources.
*   `AlphaReduce`: Transparency multiplier. Not given in the sources.
*   `scaleCoeff`: Threshold for entry point adjustment. The source uses a hardcoded threshold of 2.7 [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision**: Comparing `EntryPoint == exitPoint` for discarding fragments may suffer from floating-point precision issues. [G] It is recommended to use a small epsilon tolerance for this comparison.
*   **Hardcoded Thresholds**: The method relies on specific hardcoded values (`2.7`, `0.1`, `16000` iterations) which may not generalize to all volume sizes or camera speeds [S1, unofficial].
*   **Back-Face Rendering**: Requires rendering the back face first into a separate texture. If the volume bounding box is not axis-aligned or is complex, calculating the correct back-face exit points may require additional geometry processing.

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of samples per ray ($N$) and the number of pixels ($P$). $O(P \times N)$. The loop limit is fixed at 16,000 iterations in the source, but early termination reduces average cost [S1, unofficial].
*   **Memory Complexity**: Requires storage for the `ExitPoints` 2D texture, which is $O(P)$ where $P$ is the screen resolution. The volume texture is $O(V)$ where $V$ is the volume data size.
*   **Strengths**: Allows seamless camera movement inside the volume ("flowing through") without the view disappearing. Simple to implement on hardware with 3D texture support.
*   **Limitations**: The entry point adjustment is heuristic-based and may not perfectly simulate "being surrounded" by the volume. The hardcoded parameters limit flexibility.
*   **When to use**: When the application requires the camera to move inside the volume and a simple, hardware-accelerated solution is needed.
*   **When not to use**: When high precision is required for inside-volume rendering, or when the volume geometry is complex and back-face rasterization is difficult.
