# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated volume rendering technique that enables the camera to move inside the volume's bounding box without the view disappearing or clipping artifacts. It solves the problem of ray origin placement when the viewer penetrates the front face of the volume by dynamically shifting the ray entry point forward along the ray direction based on a scale coefficient [S1, unofficial]. Unlike standard direct volume ray casting where the ray always starts at the front face, this method allows for a "flowing through" experience by adjusting the start of the ray-marching loop [S1, unofficial].

## How it works
The method extends the standard hardware-accelerated pipeline by decoupling the ray origin from the fixed front face of the bounding box when the camera is inside the volume. It requires a two-pass rendering approach to determine ray bounds and a modified fragment shader to handle dynamic entry points.

### Inputs and Outputs
*   **Inputs:**
    *   `VolumeTex`: A 3D texture (`sampler3D`) containing the scalar volume data [S1, unofficial].
    *   `TransferFunc`: A 1D texture (`sampler1D`) mapping scalar values to color and opacity [S1, unofficial].
    *   `ExitPoints`: A 2D texture (`sampler2D`) storing the exit coordinates of rays passing through the back face of the volume [S1, unofficial].
    *   `EntryPoint`: The geometric intersection of the ray with the front face of the volume bounding box, passed from the vertex shader [S1, unofficial].
    *   `ScreenSize`: The resolution of the viewport [S1, unofficial].
*   **Outputs:**
    *   `FragColor`: The final composited color and accumulated opacity for the pixel [S1, unofficial].

### Data Structures
*   **ExitPoints Texture:** A 2D texture where each texel stores a `vec3` (RGB) representing the 3D world coordinates of the ray's exit point from the back face of the volume. The texture is generated by rendering the back face of the volume's bounding box into a framebuffer object (FBO) [S1, unofficial].
*   **Uniforms:**
    *   `StepSize` (`float`): The distance between samples along the ray [S1, unofficial].
    *   `AlphaReduce` (`float`): A multiplier applied to the sampled alpha to increase transparency [S1, unofficial].
    *   `scaleCoeff` (`float`): A scaling factor representing the camera's position relative to the volume, used to determine if the camera is inside [S1, unofficial].

### Algorithm Steps
1.  **Generate Exit Points:** Render the back face of the volume's bounding box into a framebuffer object bound to a 2D texture named `ExitPoints`. The color buffer of this FBO stores the 3D coordinates of the exit points [S1, unofficial].
2.  **Render Front Face:** Render the front face of the volume's bounding box to the screen. Pass the front face intersection coordinates as `EntryPoint` to the fragment shader [S1, unofficial].
3.  **Retrieve Exit Point:** In the fragment shader, sample the `ExitPoints` texture using the normalized screen coordinates (`gl_FragCoord.st / ScreenSize`) to retrieve the `exitPoint` [S1, unofficial].
4.  **Discard Invalid Rays:** If `EntryPoint` equals `exitPoint`, the ray does not pass through the volume (or the camera is positioned such that no intersection occurs). Discard the fragment [S1, unofficial].
5.  **Calculate Ray Direction:** Compute the ray direction vector by normalizing the difference between the exit and entry points:
    $$ \mathbf{d} = \text{normalize}(\text{exitPoint} - \text{EntryPoint}) $$
6.  **Adjust Entry Point:** Determine the actual starting position for ray marching based on `scaleCoeff`:
    *   If `scaleCoeff >= 2.7`: Calculate a temporary shift factor `tmp = min((scaleCoeff - 2.7) * 0.1, 1.0)`. Shift the entry point forward:
        $$ \text{adjustedEntryPoint} = \text{EntryPoint} + tmp \times (\text{exitPoint} - \text{EntryPoint}) $$
    *   If `scaleCoeff < 2.7`: Use the original `EntryPoint` [S1, unofficial].
7.  **Initialize Ray Marching:**
    *   Set `currentPosition` to `adjustedEntryPoint`.
    *   Initialize `colorSum` (accumulated color) and `color` (current sample) to zero [S1, unofficial].
    *   Calculate `Step = d * StepSize`.
    *   Calculate `Length = length(exitPoint - EntryPoint)` [S1, unofficial].
8.  **Ray Marching Loop:** Iterate up to a maximum number of steps (e.g., 16,000):
    *   Sample the volume: `value = texture(VolumeTex, currentPosition.xyz)` [S1, unofficial].
    *   Map to color: `color = texture(TransferFunc, value.a)` [S1, unofficial].
    *   Reduce alpha: `color.a *= AlphaReduce` [S1, unofficial].
    *   Front-to-back compositing:
        $$ \text{colorSum} = (1.0 - \text{colorSum.a}) \times \text{color} + \text{colorSum} $$
    *   Check for early termination: If `colorSum.a >= 0.95`, break the loop [S1, unofficial].
    *   Advance position: `currentPosition.xyz += Step` [S1, unofficial].
    *   Check bounds: If accumulated length exceeds `Length`, break the loop [S1, unofficial].
9.  **Output:** Write `colorSum` to the framebuffer [S1, unofficial].

### Pseudocode
```python
# Fragment Shader Logic
# Inputs: EntryPoint (vec3), ExitPoints (sampler2D), VolumeTex (sampler3D), TransferFunc (sampler1D)
# Uniforms: StepSize (float), AlphaReduce (float), ScreenSize (vec2), scaleCoeff (float)

def fragment_shader(EntryPoint, gl_FragCoord, ScreenSize, ExitPoints, VolumeTex, TransferFunc, StepSize, AlphaReduce, scaleCoeff):
    # 1. Retrieve exit point from pre-rendered texture
    normalized_coord = gl_FragCoord.xy / ScreenSize
    exitPoint = texture(ExitPoints, normalized_coord)

    # 2. Discard if ray does not pass through volume
    if EntryPoint == exitPoint:
        return discard

    # 3. Calculate ray direction
    rayDirection = normalize(exitPoint - EntryPoint)

    # 4. Adjust entry point based on scale coefficient
    if scaleCoeff >= 2.7:
        tmp = min((scaleCoeff - 2.7) * 0.1, 1.0)
        adjustedEntryPoint = EntryPoint + tmp * (exitPoint - EntryPoint)
    else:
        adjustedEntryPoint = EntryPoint

    # 5. Initialize variables
    currentPosition = adjustedEntryPoint
    colorSum = vec4(0.0, 0.0, 0.0, 0.0)
    color = vec4(0.0, 0.0, 0.0, 0.0)
    
    Step = rayDirection * StepSize
    stepLength = length(Step)
    Length = length(exitPoint - EntryPoint)
    LengthSum = 0.0

    # 6. Ray marching loop
    for i in range(16000):
        # Sample volume and transfer function
        value = texture(VolumeTex, currentPosition)
        color = texture(TransferFunc, value.a)
        
        # Reduce alpha for transparency
        color.a *= AlphaReduce
        
        # Front-to-back blending
        color.rgb *= color.a
        colorSum = (1.0 - colorSum.a) * color + colorSum
        
        # Accumulate length
        LengthSum += stepLength
        
        # Early termination
        if colorSum.a >= 0.95:
            break
            
        # Advance position
        currentPosition += Step
        
        # Boundary check
        if LengthSum >= Length:
            break

    return colorSum
```

### Parameters and Typical Values
*   `StepSize`: Controls sample density. Not given in the sources.
*   `AlphaReduce`: Multiplier for alpha. Not given in the sources.
*   `scaleCoeff`: Threshold for entering the volume. The transition begins at 2.7 [S1, unofficial].
*   Maximum iterations: 16,000 [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision:** Comparing `EntryPoint == exitPoint` for discarding fragments may suffer from floating-point precision issues. [G] In practice, a small epsilon tolerance should be used for equality checks.
*   **Clipping Artifacts:** The method shifts the entry point linearly. If `scaleCoeff` is very large, the entry point may shift too far, potentially causing the ray to start inside the volume without proper visualization of the surrounding structure. [S1, unofficial] suggests this is a limitation compared to "being surrounded" effects.
*   **Plane Clipping Alternative:** The source notes that Plane Clipping is an alternative method for handling visibility through the volume, implying Entry Point Adjustment is one of several strategies for inside-volume navigation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray ($N$) and the number of pixels ($P$). $O(P \times N)$. The maximum loop count is fixed at 16,000, but early termination often reduces this [S1, unofficial].
*   **Memory Complexity:** Requires additional memory for the `ExitPoints` 2D texture, which is $O(W \times H)$ where $W, H$ are screen dimensions [S1, unofficial].
*   **Strengths:** Enables smooth camera movement inside the volume without visual discontinuities at the front face. Simple to implement as a shader modification [S1, unofficial].
*   **Limitations:** Does not fully simulate being "surrounded" by the volume; the view may still feel constrained compared to more advanced inside-volume techniques. The linear shift based on `scaleCoeff` is a heuristic [S1, unofficial].
*   **When to use:** When the application requires the user to fly through or inside the volume data, and a simple, hardware-friendly solution is preferred over complex geometry clipping or multiple rendering passes.

## Background
The method originates from community-driven implementations of volume rendering using GLSL and OpenGL, specifically addressing the limitation of standard ray casting where the camera cannot penetrate the volume's front face. It was discussed in the context of OpenTK and C# implementations on Stack Overflow [S1, unofficial]. The technique is often contrasted with Plane Clipping as an alternative approach for handling inside-volume visibility [S1, unofficial].
