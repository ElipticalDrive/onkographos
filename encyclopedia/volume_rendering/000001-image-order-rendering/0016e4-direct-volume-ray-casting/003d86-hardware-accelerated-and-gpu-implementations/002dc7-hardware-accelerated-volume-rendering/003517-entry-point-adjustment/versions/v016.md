# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated volume rendering technique where the camera or volume is scaled so the viewer enters the bounding box, and the ray entry point is dynamically shifted forward along the ray direction based on a scale coefficient to prevent the view from disappearing when the camera position exceeds the back face [S1, unofficial].

## How it works
The method extends the standard two-pass hardware-accelerated approach by adding a render pass to capture exit points and modifying the fragment shader to handle dynamic entry point adjustment [S1, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   `VolumeTex`: 3D texture containing scalar volume data [S1, unofficial].
    *   `TransferFunc`: 1D texture mapping scalar values to RGBA color/opacity [S1, unofficial].
    *   `ExitPoints`: 2D texture storing the 3D exit coordinates of rays passing through the back face of the volume bounding box [S1, unofficial].
    *   `ScreenSize`: Uniform `vec2` representing the viewport resolution [S1, unofficial].
    *   `StepSize`: Uniform `float` controlling the distance between samples along the ray [S1, unofficial].
    *   `AlphaReduce`: Uniform `float` multiplier applied to alpha to increase transparency [S1, unofficial].
    *   `scaleCoeff`: Uniform `float` representing the scaling factor of the volume/camera, used to determine if the camera is inside [S1, unofficial].
    *   `EntryPoint`: Varying `vec3` passed from the vertex shader, representing the geometric entry point (front face intersection) [S1, unofficial].
    *   `screenCoord`: `vec2` representing the current fragment's screen coordinates [G].
*   **Outputs:**
    *   `FragColor`: `vec4` containing the accumulated color and opacity for the pixel [S1, unofficial].

### Data Structures
*   **ExitPoints Texture:** A 2D texture (`sampler2D`) where each texel at normalized screen coordinates $(u, v)$ stores the 3D world position $(x, y, z)$ of the ray's exit point from the volume's back face [S1, unofficial].

### Steps
1.  **Back-Face Rendering:** Render the back face of the volume's bounding box geometry into a framebuffer object (FBO) attached to a 2D texture named `ExitPoints` [S1, unofficial]. The vertex shader outputs the world position of the back-face vertices [S1, unofficial].
2.  **Front-Face Rendering:** Render the front face of the volume's bounding box to the screen [S1, unofficial]. The vertex shader outputs the geometric entry point (`EntryPoint`) [S1, unofficial].
3.  **Fragment Shader Execution:** For each pixel:
    a. Retrieve the exit point from `ExitPoints` using the normalized screen coordinates (`screenCoord / ScreenSize`) [S1, unofficial].
    b. Check if the ray intersects the volume. If `EntryPoint == exitPoint`, discard the fragment [S1, unofficial].
    c. Calculate the ray direction: $\mathbf{d} = \text{normalize}(\text{exitPoint} - \text{EntryPoint})$ [S1, unofficial].
    d. **Entry Point Adjustment:** If `scaleCoeff >= 2.7`, calculate a temporary shift factor: $\text{tmp} = \min((\text{scaleCoeff} - 2.7) \times 0.1, 1.0)$ [S1, unofficial]. Adjust the entry point: $\text{adjustedEntryPoint} = \text{EntryPoint} + \text{tmp} \times (\text{exitPoint} - \text{EntryPoint})$ [S1, unofficial]. Otherwise, use the original `EntryPoint` [S1, unofficial].
    e. Initialize the current position at `adjustedEntryPoint` [S1, unofficial]. Initialize accumulation variables: `colorSum = (0,0,0,0)`, `color = (0,0,0,0)`, `value = (0,0,0,0)` [S1, unofficial].
    f. Calculate the step vector: $\mathbf{s} = \mathbf{d} \times \text{StepSize}$ [S1, unofficial]. Calculate the total ray length: $L = \|\text{exitPoint} - \text{EntryPoint}\|$ [S1, unofficial].
    g. **Ray Marching Loop:** Iterate up to 16,000 times (or until termination conditions are met) [S1, unofficial]:
       i. Sample the volume: $V = \text{texture}(\text{VolumeTex}, \text{currentPosition.xyz})$ [S1, unofficial].
       ii. Sample the transfer function: $C = \text{texture}(\text{TransferFunc}, V.a)$ [S1, unofficial].
       iii. Reduce alpha: $C.a = C.a \times \text{AlphaReduce}$ [S1, unofficial].
       iv. Front-to-back compositing: $C_{\text{rgb}} = C.rgb \times C.a$ [S1, unofficial]. Update accumulated color: $\text{colorSum} = (1.0 - \text{colorSum.a}) \times C + \text{colorSum}$ [S1, unofficial].
       v. Accumulate length: $L_{\text{sum}} += \|\mathbf{s}\|$ [S1, unofficial].
       vi. **Early Ray Termination:** If $\text{colorSum.a} \ge 0.95$, break [S1, unofficial].
       vii. Advance position: $\text{currentPosition.xyz} += \mathbf{s}$ [S1, unofficial].
       viii. **Boundary Check:** If $L_{\text{sum}} \ge L$, break [S1, unofficial].
    h. Output `colorSum` as `FragColor` [S1, unofficial].

### Pseudocode
```python
def fragment_shader(EntryPoint: vec3, ExitPointsTex: sampler2D, VolumeTex: sampler3D,
                    TransferFunc: sampler1D, StepSize: float, AlphaReduce: float,
                    ScreenSize: vec2, scaleCoeff: float, screenCoord: vec2) -> vec4:
    # 1. Retrieve exit point from texture
    exitPoint = texture(ExitPointsTex, screenCoord / ScreenSize).xyz

    # 2. Check for intersection
    if EntryPoint == exitPoint:
        return vec4(0.0) # Discard fragment

    # 3. Calculate ray direction
    rayDirection = normalize(exitPoint - EntryPoint)

    # 4. Entry point adjustment
    if scaleCoeff >= 2.7:
        tmp = min((scaleCoeff - 2.7) * 0.1, 1.0)
        adjustedEntryPoint = EntryPoint + tmp * (exitPoint - EntryPoint)
    else:
        adjustedEntryPoint = EntryPoint

    # 5. Initialize variables
    currentPosition = adjustedEntryPoint
    colorSum = vec4(0.0, 0.0, 0.0, 0.0)
    Step = rayDirection * StepSize
    stepLength = length(Step)
    Length = length(exitPoint - EntryPoint)
    LengthSum = 0.0

    # 6. Ray marching loop
    for i in range(16000):
        # Sample volume and transfer function
        value = texture(VolumeTex, currentPosition).a
        color = texture(TransferFunc, value)
        
        # Reduce alpha
        color.a *= AlphaReduce
        color.rgb *= color.a
        
        # Front-to-back blending
        colorSum = (1.0 - colorSum.a) * color + colorSum
        
        # Accumulate length
        LengthSum += stepLength
        
        # Early Ray Termination
        if colorSum.a >= 0.95:
            break
            
        # Advance position
        currentPosition += Step
        
        # Boundary check
        if LengthSum >= Length:
            break
            
    return colorSum
```

### Parameters
*   `StepSize`: Uniform `float` controlling the distance between samples along the ray [S1, unofficial].
*   `AlphaReduce`: Uniform `float` multiplier applied to alpha to make the volume more transparent [S1, unofficial].
*   `scaleCoeff`: Uniform `float` representing the scaling factor of the volume/camera, used to determine if the camera is inside [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision:** Floating-point equality `EntryPoint == exitPoint` may fail incorrectly at exact boundaries; an epsilon comparison is recommended [G].
*   **Heuristic Threshold:** The entry point shift is strictly heuristic and only activates when `scaleCoeff >= 2.7` [S1, unofficial].
*   **Plane Clipping Alternative:** Plane clipping is suggested as an alternative method to handle visibility through the volume [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ per ray, bounded by the loop limit of 16,000 iterations or early termination when accumulated opacity reaches 0.95 [S1, unofficial].
*   **Memory Complexity:** $O(W \times H)$ for the `ExitPoints` texture, where $W$ and $H$ are the screen dimensions [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths:** Enables seamless navigation inside the volume without the view disappearing [S1, unofficial].
*   **Limitations:** The adjustment is heuristic-based and may not produce physically accurate results for all camera positions [S1, unofficial].
*   **When to use:** When visualizing internal structures by "flying through" the volume is required on standard GPU hardware [S1, unofficial].
*   **When not to use:** When high accuracy of internal ray origins is critical or when complex internal occlusion requires spatial acceleration structures [S1, unofficial].

## Background
This technique originates from practical implementations of hardware-accelerated volume rendering where users needed to navigate inside the volume [S1, unofficial]. It was discussed in online forums as a solution to the "disappearing view" problem when the camera moves past the front face of the bounding box [S1, unofficial]. It is often contrasted with Plane Clipping, which is another suggested method for handling visibility through the volume [S1, unofficial].
