# Entry Point Adjustment

Also called: Flowing through volume, Inside-volume rendering, Raycasting Volume Rendering with Entry Point Adjustment

## Overview
Entry Point Adjustment is a hardware-accelerated technique for direct volume ray casting that enables the camera to move inside the volume's bounding box without the view disappearing or clipping artifacts. It solves the problem of ray origin placement when the viewer penetrates the front face of the volume by dynamically shifting the ray entry point forward along the ray direction based on a scale coefficient, allowing the user to "flow through" the volume [S1, unofficial]. Unlike standard ray casting which assumes the camera is always outside the front face, this method maintains visual continuity by adjusting the start of the ray march to remain within the volume bounds defined by the exit point [S1, unofficial].

## How it works
The method operates in a two-pass rendering pipeline using framebuffer objects (FBOs) and fragment shaders. It relies on the geometric relationship between the front and back faces of the volume's bounding box.

### Inputs and Outputs
*   **Inputs:**
    *   `VolumeTex`: A 3D texture containing the scalar field data.
    *   `TransferFunc`: A 1D texture mapping scalar values to RGBA colors.
    *   `ExitPoints`: A 2D texture storing the 3D exit coordinates of rays passing through the back face of the volume.
    *   `ScreenSize`: A uniform `vec2` representing the resolution of the screen/FBO.
    *   `StepSize`: A uniform `float` controlling the distance between samples along the ray.
    *   `AlphaReduce`: A uniform `float` multiplier applied to alpha to increase transparency.
    *   `scaleCoeff`: A uniform `float` representing the scaling factor of the volume, used to determine the camera's penetration depth.
*   **Outputs:**
    *   `FragColor`: The final composited RGBA color for each pixel.

### Data Structures
1.  **ExitPoints Texture**: A 2D texture where each texel at normalized screen coordinates $(u, v)$ stores the 3D world-space coordinates $(x, y, z)$ of the ray's exit point from the volume's back face.
2.  **VolumeTex**: A 3D texture sampled at normalized coordinates $(s, t, r)$ corresponding to the ray's current position.
3.  **TransferFunc**: A 1D texture sampled using the alpha channel of the volume scalar value to retrieve the final color.

### Algorithm Steps
1.  **Back-Face Rendering (Pre-pass):** Render the back face of the volume's bounding box into an FBO bound to the `ExitPoints` texture. The vertex color or position is used to store the 3D exit coordinates for each fragment.
2.  **Front-Face Rendering (Main Pass):** Render the front face of the volume's bounding box to the screen. Pass the original entry point (front face vertex position) to the fragment shader.
3.  **Exit Point Retrieval:** In the fragment shader, retrieve the exit point from the `ExitPoints` texture using the current fragment's screen coordinates normalized by `ScreenSize`.
4.  **Visibility Check:** If the retrieved exit point is identical to the entry point, discard the fragment. This indicates the ray does not pass through the volume or the camera is positioned such that no volume is visible [S1, unofficial].
5.  **Ray Direction Calculation:** Compute the ray direction by normalizing the vector from the entry point to the exit point.
6.  **Entry Point Adjustment:**
    *   If `scaleCoeff` $\ge 2.7$, calculate a temporary shift factor:
        $$ tmp = \min((scaleCoeff - 2.7) \times 0.1, 1.0) $$
    *   Shift the entry point forward:
        $$ \text{AdjustedEntryPoint} = \text{EntryPoint} + tmp \times (\text{ExitPoint} - \text{EntryPoint}) $$
    *   If `scaleCoeff` $< 2.7$, use the original `EntryPoint` [S1, unofficial].
7.  **Ray Marching Initialization:**
    *   Set `currentPosition` to the adjusted entry point.
    *   Initialize `colorSum` (accumulated color) and `color` (current sample) to zero.
    *   Calculate `Step` vector: $\text{Step} = \text{rayDirection} \times \text{StepSize}$.
    *   Calculate `stepLength`: $|\text{Step}|$.
    *   Calculate `Length`: $|\text{ExitPoint} - \text{EntryPoint}|$.
    *   Initialize `LengthSum` to 0.
8.  **Ray Marching Loop:** Iterate up to 16,000 times (or until termination conditions are met):
    *   Sample `VolumeTex` at `currentPosition.xyz` to get `value`.
    *   Sample `TransferFunc` using `value.a` to get `color`.
    *   Apply transparency reduction: `color.a *= AlphaReduce`.
    *   Perform front-to-back blending:
        $$ \text{colorSum} = (1.0 - \text{colorSum.a}) \times \text{color} + \text{colorSum} $$
        *(Note: `color.rgb` is multiplied by `color.a` before addition in the source code)*.
    *   Accumulate length: `LengthSum += stepLength`.
    *   Terminate if `colorSum.a >= 0.95` or `LengthSum >= Length`.
    *   Advance position: `currentPosition.xyz += Step`.
9.  **Output:** Write `colorSum` to `FragColor` [S1, unofficial].

### Pseudocode
The following pseudocode represents the fragment shader logic described in the source. It assumes standard vector and matrix operations are available.

```python
# Inputs
EntryPoint: vec3          # From vertex shader (front face position)
ExitPointCoord: vec4      # Not directly used, screen coords used instead
ExitPoints: sampler2D     # Texture storing exit points
VolumeTex: sampler3D      # 3D volume data
TransferFunc: sampler1D   # 1D transfer function
StepSize: float           # Uniform
AlphaReduce: float        # Uniform
ScreenSize: vec2          # Uniform (width, height)

# Output
FragColor: vec4

def main():
    # 1. Retrieve exit point from texture
    # Normalize screen coordinates to [0, 1]
    uv = gl_FragCoord.xy / ScreenSize
    exitPoint = texture(ExitPoints, uv).xyz

    # 2. Visibility check
    # If entry equals exit, the ray does not pass through the volume
    if EntryPoint == exitPoint:
        discard()

    # 3. Calculate ray direction
    rayDirection = normalize(exitPoint - EntryPoint)

    # 4. Entry Point Adjustment
    # Determine if we need to shift the entry point based on scaleCoeff
    # Note: scaleCoeff is assumed to be a uniform passed to the shader
    if scaleCoeff >= 2.7:
        tmp = min((scaleCoeff - 2.7) * 0.1, 1.0)
        adjustedEntryPoint = EntryPoint + tmp * (exitPoint - EntryPoint)
    else:
        adjustedEntryPoint = EntryPoint

    # 5. Initialize variables
    currentPosition = adjustedEntryPoint
    colorSum = vec4(0.0, 0.0, 0.0, 0.0)
    color = vec4(0.0, 0.0, 0.0, 0.0)
    
    Step = rayDirection * StepSize
    stepLength = length(Step)
    Length = length(exitPoint - EntryPoint)
    LengthSum = 0.0

    # 6. Ray Marching Loop
    for i in range(16000):
        # Sample volume
        value = texture(VolumeTex, currentPosition)
        
        # Sample transfer function
        color = texture(TransferFunc, value.a)
        
        # Reduce alpha for transparency
        color.a *= AlphaReduce
        
        # Front-to-back blending
        # Source code: color.rgb *= color.a; colorSum = (1.0 - colorSum.a) * color + colorSum;
        color.rgb *= color.a
        colorSum = (1.0 - colorSum.a) * color + colorSum
        
        # Accumulate length
        LengthSum += stepLength
        
        # Termination conditions
        if colorSum.a >= 0.95:
            break
        if LengthSum >= Length:
            break
            
        # Advance position
        currentPosition += Step

    FragColor = colorSum
```

### Parameters and Typical Values
*   **StepSize**: Controls sampling density. Not given in the sources.
*   **AlphaReduce**: Multiplier for alpha. Not given in the sources.
*   **scaleCoeff**: Threshold for entry point shift. The source uses a hardcoded threshold of `2.7` [S1, unofficial].
*   **Max Iterations**: 16,000 [S1, unofficial].
*   **Termination Alpha**: 0.95 [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision**: Comparing `EntryPoint == exitPoint` for discarding fragments may suffer from floating-point precision issues. [G] In practice, a small epsilon tolerance should be used for this comparison.
*   **Boundary Conditions**: The method assumes the volume is a convex bounding box. If the volume has complex geometry, the simple front/back face rasterization may not accurately represent the true entry/exit points, leading to artifacts.
*   **Scale Coefficient**: The shift logic is linear and hardcoded. If `scaleCoeff` is very large, the entry point shift is capped at 1.0, which may cause the ray to start too close to the exit point, resulting in insufficient sampling.

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of samples per ray ($O(N)$), where $N$ is the number of steps in the ray march. The pre-pass is $O(F)$ where $F$ is the number of fragments in the back face.
*   **Memory Complexity**: $O(V)$ for the 3D volume texture and $O(R \times H)$ for the 2D exit points texture, where $R, H$ are resolution dimensions.
*   **Strengths**: Allows seamless navigation inside the volume without clipping. Simple to implement on standard graphics hardware using FBOs.
*   **Limitations**: The "flowing through" effect is an approximation and may not perfectly simulate being "surrounded" by the volume. The hardcoded thresholds (2.7, 0.1) are arbitrary and may not work for all volume scales. [S1, unofficial]
*   **When to use**: When interactive navigation inside the volume is required and the volume can be approximated by a bounding box.
*   **When not to use**: When high accuracy of entry/exit points is required for non-convex volumes, or when the "surrounded" effect is critical.

## Background
The method was discussed in a Stack Overflow post by user "imo" in April 2016, as a solution to a problem with OpenGL ray casting where the view disappeared when the camera moved inside the volume [S1, unofficial]. The code was based on a GitHub repository "toolchainX/Volume_Rendering_Using_GLSL". It is presented as an alternative to plane clipping for handling visibility when the camera penetrates the volume [S1, unofficial].
