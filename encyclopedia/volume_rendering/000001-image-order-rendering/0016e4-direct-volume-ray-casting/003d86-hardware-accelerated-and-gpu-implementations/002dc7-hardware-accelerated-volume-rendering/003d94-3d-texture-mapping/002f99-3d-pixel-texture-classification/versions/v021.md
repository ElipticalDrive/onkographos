# 3D Pixel Texture Classification

Also called: VGH Lookup

## Overview
3D Pixel Texture Classification is a hardware-accelerated method for evaluating multi-dimensional transfer functions during direct volume ray casting. It solves the problem of efficiently mapping voxel attributes (Data Value, Gradient Magnitude, and Second Derivative) to color and opacity by storing the classification function in a 3D texture [S1]. It differs from standard 1D or 2D lookup tables by explicitly incorporating curvature information (second derivative) to enhance boundary detection, using a specialized "sheet" representation for the signed second derivative axis [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume. For each sample point along a ray, the method computes three attributes: Data Value ($D$), Gradient Magnitude ($G$), and Second Derivative ($S$).
*   **Output:** Color ($C$) and Opacity ($\alpha$) for the sample.

**Data Structures:**
A 3D pixel texture (volume texture) is used to store the transfer function.
*   **Axis 1 (Data Value):** 8-bit resolution (256 entries).
*   **Axis 2 (Gradient Magnitude):** 8-bit resolution (256 entries).
*   **Axis 3 (Second Derivative):** Limited resolution. The axis represents "sheets" corresponding to specific second derivative values.

**Steps:**
1.  **Attribute Computation:** For a voxel at position $\mathbf{p}$, compute the scalar value $D = V(\mathbf{p})$. Compute the gradient magnitude $G = \|\nabla V(\mathbf{p})\|$. Compute the second derivative $S$. The second derivative is typically the Laplacian or a directional second derivative along the gradient.
2.  **Sign Maintenance:** Since $S$ is a signed quantity, apply a scale and bias transformation to map the signed range to the texture coordinate range, preserving the sign information for interpolation [S1].
3.  **Texture Lookup:** Use $(D, G, S')$ as coordinates to sample the 3D pixel texture.
    *   $D$ and $G$ use full 8-bit indexing.
    *   $S'$ is the transformed second derivative coordinate.
4.  **Sheet Representation:** The second derivative axis is structured as three distinct "sheets" or control planes within the texture:
    *   Sheet 1: Negative second derivative values.
    *   Sheet 2: Zero second derivative values (center sheet).
    *   Sheet 3: Positive second derivative values.
5.  **Opacity Interpolation:** The opacity value retrieved from the texture is modulated by a "boundary emphasis" parameter.
    *   Let $\alpha_{center}$ be the opacity value at the center sheet (zero second derivative).
    *   Let $\alpha_{outer}$ be the opacity value at the outer sheets (positive/negative second derivative).
    *   The opacity on the outer sheets is scaled from the center sheet opacity based on the boundary emphasis slider [S1].

**Parameters:**
*   **Resolution:** 256x256x$N$ for the texture, where $N$ is the number of second derivative control points (typically small, e.g., 3 sheets) [S1].
*   **Boundary Emphasis:** A scalar parameter controlling the relative opacity of the outer sheets compared to the center sheet [S1].

**Pseudocode:**
```python
def classify_voxel(data_value, gradient_magnitude, second_derivative, texture, boundary_emphasis):
    # 1. Map second derivative to texture coordinate
    # Scale and bias to maintain sign and fit within texture bounds
    # Assuming texture depth covers negative, zero, and positive regions
    s_coord = scale_and_bias(second_derivative)
    
    # 2. Sample the 3D texture
    # D and G use full 8-bit resolution (0-255)
    # S uses limited resolution (sheet index or normalized coordinate)
    color, alpha_raw = texture.sample(data_value, gradient_magnitude, s_coord)
    
    # 3. Apply boundary emphasis scaling
    # The opacity on outer sheets is scaled from the center sheet opacity
    # This logic is implicitly handled by the texture layout and the emphasis slider
    # If the texture stores raw values, explicit scaling might be:
    # alpha = alpha_raw * boundary_emphasis_factor
    
    return color, alpha
```
*Note: The exact scaling formula for boundary emphasis is not provided in the sources, only that outer sheet opacity is scaled from the center sheet opacity [S1].*

## Subtopics

### Adaptive Pre-integrated Voxel Classification
A technique included in a real-time raycaster built by Roettger et al. to exploit the intrinsically parallel nature of GPUs, along with volume clipping [S2]. It addresses the inefficiency of multi-pass rendering pipelines by using a single-pass framework [S2].

## Operating characteristics
*   **Memory:** The 3D texture size is $256 \times 256 \times N$. With $N$ being small (e.g., 3 sheets), the memory footprint is manageable, but full 8-bit resolution on all three axes would be prohibitively large ($256^3$ entries) [S1].
*   **Performance:** Hardware-accelerated texture lookups are efficient on GPUs. The method avoids complex shader computations for transfer function evaluation by offloading it to the texture unit [S1].
*   **Limitations:** The resolution of the second derivative axis is limited, which may reduce the fidelity of curvature-based classification compared to higher-resolution methods [S1].

## Background
The method was described in the context of interactive volume rendering using multi-dimensional transfer functions [S1]. It leverages the capabilities of 3D pixel textures available in graphics hardware at the time of publication [S1].
