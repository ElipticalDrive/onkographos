# 3D Pixel Texture Classification

Also called: VGH Lookup

## Overview
3D Pixel Texture Classification is a hardware-accelerated method for evaluating multi-dimensional transfer functions during direct volume ray casting. It maps voxel attributes (Data Value, Gradient Magnitude, and Second Derivative) to color and opacity by sampling a 3D texture [S1]. It differs from its sibling [Hardware-Accelerated Volume Rendering via 3D Texturing](2799-hardware-accelerated-volume-rendering-via-3d-texturing.md) by specifically addressing the interpolation challenges of signed second derivatives through a "sheet-based" representation, and from [Hardware Shading via Pixel Texture](6056-hardware-shading-via-pixel-texture.md) by focusing on volumetric classification rather than surface shading [S1].

## How it works
**Inputs:**
1.  Volume dataset where each voxel contains three scalar values: Data Value ($D$), Gradient Magnitude ($G$), and Second Derivative ($S$) [S1].
2.  Classification parameters defining the transfer function [S1].

**Outputs:**
1.  Color ($C$) and Opacity ($\alpha$) for the current ray sample [S1].

**Data Structures:**
A 3D pixel texture (volume texture) with dimensions $(N_D, N_G, N_S)$ [S1].
*   **Axis 1 (Data Value):** 8-bit resolution ($N_D = 256$) [S1].
*   **Axis 2 (Gradient Magnitude):** 8-bit resolution ($N_G = 256$) [S1].
*   **Axis 3 (Second Derivative):** Limited resolution ($N_S < 256$) [S1].
*   **Texture Format:** RGBA, storing color and opacity values [S1].

**Preprocessing (Second Derivative Axis):**
Since $S$ is signed, it must be mapped to the texture's unsigned coordinate space to preserve sign information for interpolation [S1].
1.  Define three control points for the second derivative axis: Negative ($S_{neg}$), Zero ($S_{zero}$), and Positive ($S_{pos}$) [S1].
2.  Map these control points to specific indices in the $N_S$ dimension [S1].
3.  Apply a scale and bias transformation to the input $S$ value to align it with the texture coordinates [S1].

**Classification Steps:**
1.  **Sample Extraction:** For a given voxel, extract $D$, $G$, and $S$ [S1].
2.  **Coordinate Mapping:**
    *   Map $D$ to texture coordinate $u \in [0, 1]$ based on the 8-bit range [S1].
    *   Map $G$ to texture coordinate $v \in [0, 1]$ based on the 8-bit range [S1].
    *   Map $S$ to texture coordinate $w \in [0, 1]$ using the scale/bias derived from the control points [S1].
3.  **Texture Lookup:** Perform trilinear interpolation on the 3D pixel texture using $(u, v, w)$ to retrieve base color $C_{base}$ and base opacity $\alpha_{base}$ [S1].
4.  **Second Derivative Opacity Adjustment:**
    *   Let $\alpha_{center}$ be the opacity value associated with the zero-crossing sheet ($S_{zero}$) [S1].
    *   Let $\beta$ be the "boundary emphasis" slider parameter [S1].
    *   The final opacity $\alpha$ is calculated by scaling the opacity of the outer sheets (positive/negative $S$) relative to the center sheet [S1].
    *   Specifically, the opacity contribution from the second derivative axis is linearly controlled such that the center sheet's opacity is directly set by classification widgets, while outer sheets are scaled by $\beta$ [S1].
    *   *Note:* The exact formula for combining the base lookup with the boundary emphasis scaling is not explicitly provided in the sources, but the mechanism is described as linear scaling of outer sheet opacity from the center sheet opacity [S1].

**Parameters:**
*   **Boundary Emphasis Slider ($\beta$):** Controls the relative opacity of positive/negative second derivatives compared to zero [S1].
*   **Resolution:** 256x256 for $D$ and $G$; limited for $S$ [S1].

**Edge Cases and Pitfalls:**
*   **Sign Preservation:** Failure to apply scale and bias to the second derivative will result in incorrect interpolation across the zero-crossing, losing boundary information [S1].
*   **Memory Usage:** Full 8-bit resolution on all three axes would be prohibitively expensive; limiting the second derivative axis is critical for feasibility [S1].

## Subtopics

### Adaptive Pre-integrated Voxel Classification
A technique included in a real-time raycaster built by Roettger et al. to exploit the intrinsically parallel nature of GPUs, along with volume clipping [S2]. It was designed to address the inefficiency of multi-pass rendering pipelines by enabling single-pass frameworks [S2].

## Operating characteristics
*   **Memory Complexity:** The 3D texture size is $256 \times 256 \times N_S \times 4$ bytes. With limited $N_S$, this fits in GPU memory, whereas full 8-bit resolution on all axes would be "prohibitively large" [S1].
*   **Performance:** Hardware-accelerated via 3D texture sampling, leveraging GPU parallelism [S1, S2].
*   **Strengths:** Efficient evaluation of multi-dimensional transfer functions; supports real-time interaction via classification widgets [S1].
*   **Limitations:** Requires careful tuning of the second derivative axis resolution and mapping to maintain sign integrity [S1].

## Background
The method was described in the context of interactive volume rendering using multi-dimensional transfer functions [S1]. It addresses the computational cost of evaluating complex transfer functions by offloading the lookup to hardware 3D texture units [S1]. The approach is part of the evolution of GPU-based raycasting, which moved from multi-pass framebuffer accumulation to single-pass frameworks to improve efficiency on modern graphics hardware [S2].
