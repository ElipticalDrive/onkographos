# 3D Pixel Texture Classification

Also called: VGH Lookup

## Overview
3D Pixel Texture Classification is a hardware-accelerated method that maps multi-dimensional volume attributes to optical properties using a 3D texture lookup, enabling real-time interactive volume rendering [S1]. It distinguishes itself from standard single-axis transfer functions by simultaneously utilizing Data Value, Gradient Magnitude, and Second Derivative to define material opacity and color, leveraging GPU texture hardware for efficient classification [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset $V$. For each sample point $\mathbf{p}$ along a ray, the method computes three attributes:
    1.  Data Value $d = V(\mathbf{p})$ [S1].
    2.  Gradient Magnitude $g = \|\nabla V(\mathbf{p})\|$ [S1].
    3.  Second Derivative $s = \nabla^2 V(\mathbf{p})$ [S1].
*   **Output:** A 4-tuple $(R, G, B, \alpha)$ representing the color and opacity for the sample [S1].

**Data Structures:**
The core data structure is a 3D pixel texture (volume texture) $T_{lookup}$ with dimensions $D \times G \times S$.
*   **Axis 1 (Data Value):** 8-bit resolution (256 entries) [S1].
*   **Axis 2 (Gradient Magnitude):** 8-bit resolution (256 entries) [S1].
*   **Axis 3 (Second Derivative):** Limited resolution (not 8-bit) [S1].
*   **Texture Format:** RGBA, where RGB defines color and $\alpha$ defines opacity [S1].

**Steps:**
1.  **Attribute Computation:** For each sample point $\mathbf{p}_i$ along the ray, compute the scalar value $d_i$, the gradient magnitude $g_i$, and the second derivative $s_i$ [S1].
2.  **Second Derivative Encoding:** The second derivative $s_i$ is signed. To maintain the sign for proper interpolation, it is transformed using a scale and bias operation to map it into the positive texture coordinate space of the third axis [S1].
3.  **Lookup:** Perform a 3D texture lookup using coordinates $(d_i, g_i, s'_i)$, where $s'_i$ is the encoded second derivative. The hardware interpolates the RGBA values from the texture [S1].
4.  **Second Derivative Sheet Control:** The third axis is structured as "sheets" corresponding to specific control points. Three control points are used: negative, zero, and positive second derivative values [S1].
5.  **Opacity Scaling:** The opacity $\alpha$ retrieved from the texture is modulated based on a "boundary emphasis" parameter [S1].
    *   The opacity at the center sheet (zero second derivative) is directly controlled by classification widgets [S1].
    *   The opacity at the outer sheets (positive/negative second derivatives) is scaled from the center sheet opacity according to the boundary emphasis slider [S1].

**Pseudocode:**
```python
# Assume volume V, gradient magnitude function grad_mag, second derivative func second_deriv
# Assume lookup texture T_lookup with dimensions [256, 256, S]
# Assume boundary_emphasis is a scalar parameter in [0, 1]
# Assume center_opacity is a scalar parameter

def classify(d, g, s):
    # 1. Encode second derivative to maintain sign for texture lookup
    # Scale and bias s to fit within [0, S-1]
    s_encoded = scale_and_bias(s, S)
    
    # 2. Perform 3D texture lookup
    # Coordinates are normalized to [0, 1] for texture sampling
    coord_d = d / 255.0
    coord_g = g / 255.0
    coord_s = s_encoded / (S - 1)
    
    rgba = texture_3d_sample(T_lookup, coord_d, coord_g, coord_s)
    
    # 3. Determine which "sheet" we are in to apply boundary emphasis
    # Determine if s is negative, zero, or positive
    if s < 0:
        sheet_type = NEGATIVE
    elif s == 0:
        sheet_type = ZERO
    else:
        sheet_type = POSITIVE
        
    # 4. Apply opacity scaling based on sheet type
    if sheet_type == ZERO:
        alpha = center_opacity
    else:
        # Outer sheets opacity is scaled from center sheet opacity
        alpha = center_opacity * boundary_emphasis
        
    return (rgba.r, rgba.g, rgba.b, alpha)
```

**Parameters:**
*   **Data Value Resolution:** 8-bit (256 entries) [S1].
*   **Gradient Magnitude Resolution:** 8-bit (256 entries) [S1].
*   **Second Derivative Resolution:** Limited (Not given in the sources).
*   **Boundary Emphasis:** A slider controlling the opacity scaling for non-zero second derivatives [S1].
*   **Center Opacity:** Directly controlled by classification widgets [S1].

**Edge Cases and Pitfalls:**
*   **Second Derivative Sign:** The second derivative is signed. Failure to maintain the sign via scale and bias before texture lookup will result in incorrect interpolation and classification [S1].
*   **Texture Size:** Using full 8-bit resolution for all three axes would be prohibitively expensive in memory. The method relies on limiting the second derivative axis resolution to mitigate this [S1].

## Subtopics

### Adaptive Pre-integrated Voxel Classification
A technique included in a real-time raycaster built by Roettger et al. to exploit the intrinsically parallel nature of GPUs, along with volume clipping [S2]. It addresses the inefficiency of multi-pass rendering pipelines by enabling single-pass frameworks [S2].

## Operating characteristics
*   **Performance:** Enables real-time interactive rendering by leveraging hardware texture lookup units [S1, S2].
*   **Memory:** Requires a 3D texture for classification. Memory usage is reduced by limiting the resolution of the second derivative axis compared to a full 8-bit 3D texture [S1].
*   **Strengths:** Allows complex, multi-dimensional transfer functions (Data, Gradient, Second Derivative) to be evaluated efficiently in hardware [S1].
*   **Limitations:** The resolution of the second derivative axis is limited, which may reduce precision in boundary detection compared to higher-resolution methods [S1].

## Background
The method was introduced in the context of interactive volume rendering using multi-dimensional transfer functions [S1]. It was designed to overcome the memory constraints of full 8-bit 3D lookup tables while providing rich classification capabilities [S1].
