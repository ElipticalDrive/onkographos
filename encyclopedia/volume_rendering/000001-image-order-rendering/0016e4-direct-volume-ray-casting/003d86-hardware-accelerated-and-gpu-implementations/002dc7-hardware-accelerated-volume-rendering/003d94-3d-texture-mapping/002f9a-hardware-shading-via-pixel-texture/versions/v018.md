# Hardware Shading via Pixel Texture

Also called: Quantized Normal Shading, Volume Ray Tracing via 2D Texture Packing

## Overview
Hardware Shading via Pixel Texture is a technique that adds shading to texture-memory based volume rendering to increase visual quality with negligible performance cost [S2]. It distinguishes itself from standard hardware interpolation by encoding surface normals into a 2D pixel texture and using nearest-neighbor interpolation to avoid redundancy and truncation errors [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset, a 3D texture containing density/radiance values, and a 2D pixel texture containing quantized surface normals.
*   **Output:** A shaded 2D image.

**Data Structures:**
*   **3D Texture:** Stores scalar volume values (density/radiance).
*   **2D Pixel Texture:** Stores quantized surface normals. The first 8 bits of the quantized normal are encoded in the Red channel, and the second 8 bits are encoded in the Green channel [S2].

**Steps:**
1.  **Normal Quantization:** Compute surface normals for the volume. Encode these normals using a 16-bit quantization scheme [S2].
2.  **Texture Packing:** Pack the quantized normals into a 2D pixel texture. The first 8 bits of the quantized normal are stored in the Red channel, and the second 8 bits in the Green channel [S2].
3.  **Shading Texture Generation:** Generate the shading pixel texture on a per-view basis in software [S2]. The performance cost of this operation is minimal [S2].
4.  **Ray Tracing Setup:** Draw a quad of the same size as the output image to trigger the pixel shader [S1].
5.  **Volume Ray Tracing:** Perform volume ray tracing for all sample points in a single call [S1].
    *   Pack all sample points into a 2D texture [S1].
    *   Intersect Ray Basis Functions (RBFs) of the density representation with slices of thickness $\Delta x$ perpendicular to the view direction [S1].
    *   Render slices from far to near with alpha blending set to `GL ONE` and `GL SRC ALPHA` [S1].
    *   For each pixel, retrieve density $D(x)$ and radiance $L_x$ from 3D textures [S1].
    *   Set the RGB channels of the output to $D(x)L_x$ and the alpha channel to the differential transmittance [S1].
    *   Terminate the tracing of a ray if it exits the volume [S1].
6.  **Shading Application:** Use nearest-neighbor interpolation for the pixel texture lookup to retrieve quantized normals [S2]. Light the quantized normals using the 2D pixel texture [S2]. There is essentially no difference between a 16-bit 1D nearest neighbor pixel texture and an eight-bit per-axis 2D nearest neighbor pixel texture [S2].

**Pseudocode:**
```python
# Step 1-3: Pre-computation (Software)
def generate_shading_texture(volume_data, view_direction):
    # Compute normals for the volume
    normals = compute_normals(volume_data)
    
    # Quantize normals to 16-bit
    quantized_normals = quantize_16bit(normals)
    
    # Pack into 2D texture: Red = first 8 bits, Green = second 8 bits
    shading_texture = create_2d_texture()
    for x, y in shading_texture.dimensions:
        normal = quantized_normals[x, y]
        shading_texture.set_pixel(x, y, 
                                  r=normal.first_8_bits, 
                                  g=normal.second_8_bits, 
                                  b=0, 
                                  a=1.0)
    return shading_texture

# Step 4-6: Rendering (Hardware/Shader)
def fragment_shader(pixel_coord, shading_texture, volume_3d_texture):
    # Ray generation and marching (simplified)
    ray = generate_ray(pixel_coord)
    accumulated_color = (0, 0, 0)
    accumulated_alpha = 0.0
    
    while ray.inside_volume():
        # Sample 3D texture
        density = volume_3d_texture.sample_trilinear(ray.position)
        
        # Retrieve quantized normal from 2D pixel texture using nearest-neighbor
        # Note: The normal texture is generated per-view, so coordinates must match
        normal_tex_coord = project_to_shading_texture(ray.position)
        quantized_normal = shading_texture.sample_nearest(normal_tex_coord)
        
        # Decode normal from 16-bit quantization
        # R channel = first 8 bits, G channel = second 8 bits
        r = quantized_normal.r / 255.0
        g = quantized_normal.g / 255.0
        # B channel is 0, so normal is in XY plane of local space? 
        # Or R/G represent two components of a 3D normal?
        # Source [S2] says "first eight bits... Red... second eight bits... Green"
        # and "16-bit 1D nearest neighbor". 
        # Assuming R and G encode two components, and the third is derived or fixed.
        # For implementation, we assume the shading texture provides the necessary lighting info.
        
        # Lighting calculation using the quantized normal
        # Source [S2] implies the lighting is done via the 2D pixel texture lookup
        # effectively acting as a pre-computed lighting map for the normals.
        shaded_color = apply_lighting(density, quantized_normal)
        
        # Compositing
        alpha = compute_alpha(density)
        accumulated_color += (1.0 - accumulated_alpha) * alpha * shaded_color
        accumulated_alpha += (1.0 - accumulated_alpha) * alpha
        
        # Early Ray Termination
        if accumulated_alpha > 0.95:
            break
            
        ray.step()
        
    return accumulated_color
```

**Edge Cases and Pitfalls:**
*   **Interpolation Artifacts:** Using linear interpolation on the quantized normal texture would introduce redundancy and truncation errors. Nearest-neighbor interpolation is required [S1, S2].
*   **Per-View Generation:** The shading pixel texture must be generated on a per-view basis in software, which adds a small overhead but is negligible [S2].

## Subtopics

### [Quantized Normal Shading via Pixel Texture](6549-quantized-normal-shading-via-pixel-texture.md)
Quantized Normal Shading via Pixel Texture is a hardware-accelerated volume rendering technique that encodes surface normals into a 2D pixel texture to provide shading while avoiding the redundancy and truncation errors associated with standard hardware interpolation. It distinguishes itself from nearest-neighbor volume texture sampling by using a dedicated 2D texture lookup for lighting calculations, ensuring that the quantized normal data is retrieved without interpolation artifacts.

## Operating characteristics
*   **Performance:** The performance cost of generating the shading pixel texture is minimal [S2]. Shading is added to texture-memory based volume rendering to increase quality with negligible cost [S2].
*   **Strengths:** Dramatically increases the quality of renderings with a negligible increase in rendering cost [S2]. Avoids redundancy and truncation errors in normal encoding [S2].
*   **Limitations:** Requires per-view generation of the shading texture in software [S2]. Previous work often lacked shading, so this method fills a gap in quality [S2].

## Background
*   **Origin:** The method is described in the context of PDF Interactive Volume Rendering Using Multi-Dimensional Transfer Functions [S2].
*   **History:** It was developed to address the lack of shading in previous texture-memory based volume rendering work [S2].
*   **Usage:** Used in volume rendering pipelines to enhance visual quality by adding shading information [S2].
