# Hardware Shading via Pixel Texture

Also called: Quantized Normal Shading

## Overview
Hardware Shading via Pixel Texture is a method for adding surface shading to texture-memory based volume rendering to increase visual quality with negligible computational cost [S1]. It addresses the limitation that previous texture-memory based volume rendering techniques often lacked shading, which is fundamental for expressing the shape of structures in the volume [S1]. It sets itself apart from standard hardware acceleration methods by encoding surface normals into a 2D pixel texture and using nearest-neighbor interpolation to avoid the redundancy and truncation errors associated with hardware interpolation of normals [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Scalar volume data $V$, gradient data $G$ (for normal calculation), and a view direction.
*   **Output:** A shaded volume rendering image.

**Data Structures:**
*   **Shading Pixel Texture:** A 2D texture where surface normals are encoded.
    *   **Layout:** The texture stores quantized normals.
    *   **Encoding:** A 16-bit quantization scheme is used for each normal vector. The first 8 bits of the quantized normal are stored in the Red channel, and the second 8 bits are stored in the Green channel [S1, S2].
    *   **Interpolation:** Nearest-neighbor interpolation is used for pixel texture lookups to avoid redundancy and truncation errors inherent in hardware linear interpolation of quantized data [S1, S2].

**Steps:**
1.  **Normal Calculation:** Compute surface normals for the volume data. The sources indicate that normals are quantized using a 16-bit scheme [S1, S2].
2.  **Shading Texture Generation:** Generate a shading pixel texture on a per-view basis [S1, S2].
    *   *Software Generation:* The shading pixel texture is generated in software [S1].
    *   *Hardware Alternative:* Alternatively, quantized normals can be represented as points, rendered to the frame buffer using hardware lighting, and then copied to the pixel texture [S2].
3.  **Slice Rendering:** Render a slice of the volume data to a scratch or auxiliary buffer [S2].
4.  **Shading Modulation:** If shading is enabled, render the corresponding slice from the shading volume (containing the quantized normals) and modulate (multiply) it with the current slice rendered in the scratch buffer [S2].
    *   *Note:* When the transfer function is manipulated, the raw data values are used for the volume texture, and a pre-computed RGBA shade volume is used [S2].
5.  **Pixel Texture Copy:** Copy the slice from the scratch buffer to the pixel texture using a `glCopyPixels()` operation [S2]. This step is necessary because, on some hardware (e.g., SGI Octane2), pixel texture does not occur directly on a per-fragment basis during rasterization [S2].
6.  **Compositing:** Blend the shaded slice from the scratch buffer with previously rendered slices in the frame buffer [S2].

```python
def generate_shading_texture_software(shading_data, view_direction):
    """
    Generates the 2D pixel texture for shading in software [S1].
    """
    # Quantize normals using 16-bit scheme [S1, S2]
    quantized_normals = quantize_normals(shading_data.normals, bits=16)
    
    # Encode first 8 bits to Red, second 8 bits to Green [S1, S2]
    texture = create_2d_texture()
    for x, y in texture.dimensions:
        normal = quantized_normals[x, y]
        r_channel = normal & 0xFF          # First 8 bits
        g_channel = (normal >> 8) & 0xFF   # Second 8 bits
        texture.set_pixel(x, y, r=r_channel, g=g_channel)
        
    return texture
```

**Parameters:**
*   **Quantization Scheme:** 16-bit encoding for normals [S2].
*   **Interpolation Mode:** Nearest-neighbor [S1, S2].

**Edge Cases and Pitfalls:**
*   **Hardware Flexibility:** Some hardware implementations are not flexible enough to support the operation of rendering quantized normals as points with hardware lighting and copying them to a pixel texture [S2].
*   **Interpolation Errors:** Using hardware linear interpolation for normals causes redundancy and truncation; nearest-neighbor is required [S1, S2].
*   **Performance Cost:** The performance cost of generating the shading pixel texture is minimal [S1].

## Subtopics

### Quantized Normal Shading via Pixel Texture
A shading method for volume rendering that encodes surface normals into a 2D pixel texture to avoid hardware interpolation redundancy and truncation, using nearest-neighbor interpolation [S2]. It sets itself apart by explicitly handling the quantization and encoding of normals into texture channels (R/G) to preserve precision during lookup [S2]. Choose this when using hardware that does not support efficient per-fragment normal interpolation or when using older APIs like OpenGL 1.x pixel textures [S2]. It is implemented by encoding the first eight bits of the quantized normal into the red channel and the second eight into the green channel [S2]. The shading pixel texture is generated on a per-view basis in software, or by rendering quantized normals as points with hardware lighting and copying from the frame buffer [S2]. On hardware like the SGI Octane2, the slice is rendered to a scratch buffer, then `glCopyPixels()` is used to pixel texture it, as pixel texture does not occur directly on a per-fragment basis during rasterization [S2]. The slice is then copied from the scratch buffer and blended with previously rendered slices in the frame buffer [S2]. A key parameter is the 16-bit quantization scheme for normals [S2]. A pitfall is that some hardware implementations are not flexible enough to support rendering quantized normals as points with hardware lighting and copying to a pixel texture [S2].

### Line Bundles
A technique relying on graphics hardware to create texture by rendering and compositing many semitransparent line segments to produce an anisotropic volume rendering result [S3, unofficial]. It sets itself apart by visualizing directionality (e.g., flow fields) through anisotropic patterns, unlike standard volume rendering which may lack clear directionality [S3, unofficial]. Choose this for flow visualization where velocity magnitude and direction are both important [S3, unofficial]. It is implemented by rendering pre-computed sets of line segments for each data point (splatting analogy), slightly perturbing their colors to provide a colored pattern, and compositing them in back-to-front order [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The performance cost of generating the shading pixel texture is described as minimal [S1]. However, generating the texture on a per-view basis in software adds a CPU-side overhead proportional to the texture size [S1].
*   **Memory Complexity:** Requires additional memory for the shading pixel texture and a scratch/auxiliary buffer for slice rendering [S2].
*   **Measured Performance:** Implemented on SGI Octane 2 with V series graphics cards and nVidia GeForce3 series [S2]. The method increases quality with negligible cost [S1].
*   **Strengths:** Adds fundamental shading information (shape of structures) to volume rendering with minimal performance impact [S1]. Avoids interpolation artifacts of normals [S1, S2].
*   **Limitations:** Dependent on hardware support for pixel textures (e.g., `glCopyPixels` requirement on SGI Octane2) [S2]. Some hardware cannot support the alternative hardware lighting approach [S2].
*   **When to use:** When using texture-memory based volume rendering and shading is desired for better shape perception [S1].
*   **When not to use:** When hardware does not support pixel textures or the required copy operations [S2].

## Background
The method was developed as part of work on Interactive Volume Rendering Using Multi-Dimensional Transfer Functions [S1, S2]. It was implemented on SGI Octane 2 with V series graphics cards and nVidia GeForce3 series graphics adaptors [S2]. The approach was motivated by the observation that much previous work with texture-memory based volume rendering lacked shading, which is a natural and efficient way to express information about the shape of structures in the volume [S1].
