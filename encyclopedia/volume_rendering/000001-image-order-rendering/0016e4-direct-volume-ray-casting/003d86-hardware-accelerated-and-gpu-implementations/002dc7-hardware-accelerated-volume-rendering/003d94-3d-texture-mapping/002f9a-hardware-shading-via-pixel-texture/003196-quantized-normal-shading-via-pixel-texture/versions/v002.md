# Quantized Normal Shading via Pixel Texture

Also called: Quantized Normal Shading

## Overview
Quantized Normal Shading via Pixel Texture is a hardware-accelerated volume rendering technique that encodes surface normals into a 2D pixel texture to provide shading while avoiding the redundancy and truncation errors associated with standard hardware interpolation [S1]. It distinguishes itself from standard volume texture sampling by using a dedicated 2D texture lookup for lighting calculations, ensuring that the quantized normal data is retrieved without interpolation artifacts [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset containing multi-dimensional components (e.g., $V, G, H$) and a current view vector [S1].
*   **Output:** A shaded 2D image composited into the frame buffer [S1].

**Data Structures:**
*   **Shading Pixel Texture:** A 2D texture where the red channel stores the first 8 bits of the quantized normal, and the green channel stores the second 8 bits [S1].
*   **Scratch/Auxiliary Buffer:** A temporary buffer used to render individual slices before they are composited into the final frame buffer [S1].

**Quantization Scheme:**
Normals are quantized using a 16-bit scheme [S1]. The normal vector $\mathbf{n}$ is mapped to a 16-bit integer index, which is then split into two 8-bit values [S1]:
1.  First 8 bits $\rightarrow$ Red channel ($R$)
2.  Second 8 bits $\rightarrow$ Green channel ($G$) [S1]

**Algorithm Steps:**
1.  **Generate Shading Texture:** For the current view direction, compute the quantized normals for all relevant data points and encode them into the 2D pixel texture [S1]. This is typically performed in software on a per-view basis [S1]. Alternatively, quantized normals can be rendered as points with hardware lighting and copied from the frame buffer to the pixel texture, though some hardware implementations lack the flexibility for this operation [S1].
2.  **Render Slice to Scratch Buffer:** Render the current slice of the volume data (using the appropriate transfer function components) into the scratch/auxiliary buffer [S1].
3.  **Apply Shading via Pixel Texture:** Use a `glCopyPixels()` operation to render the slice from the scratch buffer while applying the shading pixel texture [S1]. On hardware like the SGI Octane 2 with V-series cards, pixel texture lookup does not occur directly on a per-fragment basis during standard rasterization, necessitating this two-step buffer approach [S1]. Nearest-neighbor interpolation must be used for the pixel texture lookup to preserve the quantized normal values [S1].
4.  **Composite:** Blend the shaded slice from the scratch buffer into the main frame buffer, combining it with previously rendered slices [S1].

**Pseudocode:**
```python
def generate_shading_texture(volume_data, view_vector):
    """
    Encodes quantized normals into a 2D texture for the current view.
    """
    texture = [[None for _ in range(volume_data.width)] for _ in range(volume_data.height)]
    for y in range(volume_data.height):
        for x in range(volume_data.width):
            normal = compute_surface_normal(volume_data, x, y, view_vector)
            quantized_index = int(normal.x * 32767 + 32768) & 0xFFFF
            red_channel = quantized_index & 0xFF
            green_channel = (quantized_index >> 8) & 0xFF
            texture[y][x] = (red_channel, green_channel, 0, 0)
    return texture

def render_slice_with_shading(volume_data, view_vector, frame_buffer, scratch_buffer, shading_texture):
    """
    Renders a single slice with quantized normal shading and composites it.
    """
    current_shading_texture = generate_shading_texture(volume_data, view_vector)
    render_slice_to_buffer(volume_data, scratch_buffer)
    for y in range(scratch_buffer.height):
        for x in range(scratch_buffer.width):
            shade = shading_texture[y][x]
            apply_shading_to_pixel(scratch_buffer, x, y, shade)
    composite_slices(scratch_buffer, frame_buffer)

def compute_surface_normal(volume_data, x, y, view_vector):
    """Computes the surface normal at a data point using gradient estimation."""
    dx = volume_data[x+1, y] - volume_data[x-1, y]
    dy = volume_data[x, y+1] - volume_data[x, y-1]
    dz = 0.0
    length = (dx*dx + dy*dy + dz*dz)**0.5
    return (dx/length, dy/length, dz/length)

def render_slice_to_buffer(volume_data, buffer):
    """Samples volume data and applies transfer function to fill buffer."""
    for y in range(volume_data.height):
        for x in range(volume_data.width):
            value = volume_data[x, y]
            buffer[y][x] = apply_transfer_function(value)

def apply_shading_to_pixel(buffer, x, y, shade):
    """Modulates pixel color using nearest-neighbor pixel texture lookup."""
    r, g, b, a = buffer[y][x]
    shade_r, shade_g, _, _ = shade
    buffer[y][x] = (r * shade_r / 255.0, g * shade_g / 255.0, b, a)

def composite_slices(scratch_buffer, frame_buffer):
    """Blends scratch buffer contents into the frame buffer."""
    for y in range(scratch_buffer.height):
        for x in range(scratch_buffer.width):
            s = scratch_buffer[y][x]
            f = frame_buffer[y][x]
            frame_buffer[y][x] = (
                f[0] + s[0] * s[3] / 255.0,
                f[1] + s[1] * s[3] / 255.0,
                f[2] + s[2] * s[3] / 255.0,
                f[3] + s[3] * (1.0 - f[3] / 255.0)
            )
```

**Parameters:**
*   **Quantization Bits:** 16 bits total (8 bits per channel for R and G) [S1].
*   **Interpolation Mode:** Nearest-neighbor [S1].

**Edge Cases and Pitfalls:**
*   **Hardware Flexibility:** Some hardware implementations are not flexible enough to support rendering quantized normals as points with hardware lighting and copying them to a pixel texture [S1]. The authors currently generate the shading pixel texture on a per-view basis in software, noting it could easily be performed in hardware as well [S1].
*   **Rasterization Limitations:** On certain architectures (e.g., SGI Octane 2), pixel texture lookup is not available during standard per-fragment rasterization, necessitating the use of an auxiliary buffer and `glCopyPixels()` [S1].
*   **Performance Cost:** Generating the shading pixel texture on a per-view basis in software has a minimal performance cost [S1].

## Subtopics

### RGB Normal Shading via Pixel Texture
A lighting method using texture-shader features (e.g., Nvidia GeForce 3) where the normal vector at each point is encoded in the three color values of an RGB texture [S2]. The GeForce 3 interpolates these values for each pixel, computes the dot product with the current view vector, and uses the result as a lookup into a texture that encodes a reflection map [S2]. This method provides better precision than the normal index method but costs more memory [S2].

### Hardware Lighting via Normal Index Textures
A hardware lighting method encoding normal information in a separate set of textures [S2]. It encodes the normal at each data point as an 8-bit index indicating one of 256 direction vectors uniformly distributed in 3-space [S2]. These textures are drawn in a separate pass using a palette to map each normal index to a specular light value for the current view vector [S2]. This method has lower precision than the RGB texture method but uses less memory [S2].

## Operating characteristics
*   **Time Complexity:** The generation of the shading pixel texture is performed on a per-view basis, with a minimal performance cost when done in software [S1].
*   **Memory Complexity:** The method requires a scratch/auxiliary buffer for each slice [S1]. The shading texture size depends on the quantization scheme (16-bit per normal) [S1].
*   **Performance:** The method is implemented on SGI Octane 2 with V-series graphics cards and nVidia GeForce3 series [S1]. The performance cost of generating the shading texture is minimal [S1].
*   **Strengths:** Avoids hardware interpolation redundancy and truncation errors associated with standard normal interpolation [S1].
*   **Limitations:** Requires an auxiliary buffer on some hardware due to rasterization limitations [S1]. Some hardware does not support the alternative hardware lighting path [S1].
*   **When to Use:** When high-quality shading is required in volume rendering and the hardware supports pixel texture operations (or can be emulated via copy operations) [S1].
*   **When Not to Use:** When hardware flexibility is limited and the software-based texture generation becomes a bottleneck, or when memory constraints are severe (compared to normal index methods) [S1, S2].

## Background
The method was developed for interactive volume rendering using multi-dimensional transfer functions [S1]. It was implemented on the SGI Octane 2 with V-series graphics cards and the nVidia GeForce3 series graphics adaptor [S1]. The approach leverages the texture-shader features of hardware like the GeForce 3 to perform lighting calculations in hardware, enhancing the geometry and structure of the rendered data [S2]. The key observation in the implementation is that pixel texture operations only need to be applied to the portion of the volume currently changing (e.g., when the transfer function is manipulated) [S1].
