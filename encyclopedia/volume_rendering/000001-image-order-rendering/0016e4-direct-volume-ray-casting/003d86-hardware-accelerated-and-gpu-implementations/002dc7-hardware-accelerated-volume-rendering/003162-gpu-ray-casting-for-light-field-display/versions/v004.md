# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
This method accelerates direct volume rendering on an interactive light field display by computing rays from projector positions through screen pixels into the volume using Multi-Camera Optical Projection (MCOP) [S1]. It avoids the incorrect per-pixel ray parameter values caused by standard vertex attribute interpolation in non-homogeneous projections by using a coarsely tessellated proxy geometry [S1]. Unlike traditional multiview technologies that force users into fixed positions due to abrupt view changes, this approach provides a fully continuous perceived image with parallax effects [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   Screen pixel coordinates $(x, y)$ [S1].
    *   Uniform parameters: Projector position $\mathbf{E}_w$ (float3), Virtual observer distance $V_d$ (float), Virtual observer height $V_h$ (float), $\log_2$ of voxel size $\log_2 V$ (float), Step size $DL$ (float), Screen pixel size $S_0$ (float), Angular spread factor $\tan \Phi$ (float) [S1].
    *   Inverse model-view matrix $\mathbf{M}_{v}^{-1}$ (float4x4) [S1].
    *   Volume texture: A single 4-component texture where RGB channels contain unscaled precomputed gradients and the A channel contains the voxel value [S1].
    *   Lookup table: A 1D RGBA texture for transfer functions [S1].
*   **Outputs:**
    *   Fragment color and opacity (float4) [S1].

**Data Structures:**
*   `ray_t`: Struct containing `org` (float3), `dir` (float3), and `len` (float) [S1].
*   `fragment_out`: Struct containing `color` (float4) [S1].

**Steps:**

1.  **Proxy Geometry Setup:** Use a coarsely tessellated version (8x8 quads) of a slightly enlarged bounding volume as a proxy [S1]. Stream its vertices through a vertex shader that performs MCOP projection using equations 1 and 2 from the source, passing normalized and unnormalized projected coordinates to the fragment stage [S1].
2.  **Ray Origin Computation:** In the fragment shader, receive the unnormalized projected position $\mathbf{S}$ from the vertex stage. $\mathbf{S}$ represents the screen pixel’s position expressed in the display reference frame [S1].
3.  **Ray Direction Calculation:** Compute the ray direction $\mathbf{d}$ passing through point $\mathbf{S}$ using MCOP projection parameterized by emitter $\mathbf{E}$ and virtual viewer parameters $\mathbf{V}$ [S1]:
    $$
    \mathbf{d} = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right]
    $$
    [S1]
4.  **Coordinate Transformation:** Transform the infinite ray defined by $\mathbf{S}$ and $\mathbf{d}$ into local volume coordinates (assumed coincident with texture coordinates) by applying a world-to-texture homogeneous transform matrix stored in the OpenGL model-view register [S1].
5.  **Ray Clipping and Validation:** Clip the line against the unit box to compute ray entry point and integration lengths. If the length is null (or less than epsilon), discard the fragment as invalid [S1].
6.  **Ray Marching Loop:** Step through the ray in a loop, performing volume resampling and compositing until the volume is exited or full opacity is reached. Match resampling and integration kernels with actual representable voxel size based on depth-dependent spatial resolution [S1].
7.  **Mipmap Level Selection:** Store the volume texture in a Mipmap pyramid. Access it using the `tex3Dlod` intrinsic. At each sampling step, compute the depth of the current sample by transforming its position in texture space to world (screen aligned) space using a single dot product for the z coordinate. Choose the coarsest mipmap level $l$ with a sufficiently small voxel size using the equation:
    $$
    l = \text{median}(0, L_{max}, \lfloor \log_2 \frac{s(z)}{v_0} \rfloor)
    $$
    where $s(z)$ is the variable step-size, $L_{max}$ is the maximum available Mipmap level, and $v_0$ is the voxel size at the finest Mipmap level [S1].

ray_t ray_at_xy(float x, float y, float4x4 mv_inv):
    # Compute ray passing through pixel in world coords
    ray_o = float4(x, y, 0, 0)
    ray_d = float4(-(Ew.x - x) / Ew.z, (Vh - y) / Vd, -1, 0)
    
    # Transform from world to texture coordinates
    tex_o = mul(mv_inv, ray_o).xyz
    tex_e = mul(mv_inv, ray_o + ray_d).xyz
    
    # Clip ray to volume box
    dir = normalize(tex_e - tex_o)
    tmin_tmax = clip_to_unit_box(tex_o, dir)
    
    result = ray_t()
    result.org = tex_o + dir * tmin_tmax.x
    result.len = tmin_tmax.y - tmin_tmax.x
    result.dir = dir
    return result

fragment_out fragment_shader(vertex_out IN):
    # Compute ray in tex coords
    ray = ray_at_xy(IN.Qw.x, IN.Qw.y, glstate.matrix.inverse.modelview[0])
    
    if ray.len < Epsilon:
        discard
    
    # Ray composition
    delta_dir = ray.dir * DL
    N = int(ray.len / DL)
    uvw = ray.org
    I = float3(0, 0, 0)
    a = 0.0
    
    for i in range(N):
        if a >= a_max:
            break
            
        # Find distance from screen
        z = abs(dot(glstate.matrix.modelview[0][2], float4(uvw.xyz, 1.0)))
        
        # Compute mipmap level and sample texture
        mipmap_l = log2(S0 + 2 * tanPhi * z) - log2V
        gggv = mipmap_value(uvw.xyz, mipmap_l)
        
        # Apply transfer function and shading
        C_i, a_i = apply_transfer_and_shading(gggv.rgb, gggv.a)
        
        # Accumulation and stepping
        I = I + (1.0 - a) * C_i
        a = a + (1.0 - a) * a_i
        uvw += delta_dir
        
    OUT = fragment_out()
    OUT.color = float4(I, a)
    return OUT

**Edge Cases and Pitfalls:**
*   **Vertex Attribute Interpolation Error:** Standard vertex attribute interpolation does not produce correct per-pixel ray parameter values for MCOP. This is handled by using a proxy geometry and computing projections in the vertex shader [S1].
*   **Tile Misalignment Artifacts:** When objects are moved with a too slow refresh rate, misalignment between tiles can become visible because the 96 display projectors are updated in batches of 16 [S1].
*   **Out of Bounds:** If ray length is less than epsilon, discard fragment as it is out of bounds [S1].

## Operating characteristics
*   **Time Complexity:** The method requires propagating millions of rays for hundreds of steps through the volume at full resolution (1 ray/pixel and 1 sample/voxel) [S1]. To improve interactive frame rates, the sampling rate is lowered during interaction by reducing pixel count (2.5mm precision on screen) and doubling the integration step-size [S1].
*   **Memory Complexity:** The volume is stored in a single 4-component texture with a Mipmap pyramid [S1]. An additional 1D RGBA texture is used for the lookup table [S1].
*   **Strengths:** Provides a fully continuous perceived image, unlike other contemporary multiview technologies that force users into fixed positions due to abrupt view-image changes when crossing discrete viewing zones [S1]. Users can exploit accommodation, stereo, and motion parallax to gain understanding of complex shapes [S1].
*   **Limitations:** Performance is limited by single GPU volume renderer performance at full resolution [S1]. Tile misalignment artifacts can occur with slow refresh rates [S1].
*   **When to use:** Interactive light field displays requiring continuous viewing zones and multi-user capability [S1].
*   **When not to use:** When high-resolution static rendering without interaction is required, or when the display hardware does not support the specific MCOP projection model [S1].

## Background
*   **Origin:** The method was introduced by Agus et al. in 2008 [S1].
*   **History:** It was developed to address the limitations of traditional multiview technologies on light field displays, specifically the issue of discrete viewing zones [S1].
*   **Usage:** Used for rendering datasets like Chameleon, Visible Human head, and rotational angiography on interactive light field displays [S1].
