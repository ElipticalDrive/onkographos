# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
This method performs direct volume rendering on an interactive light field display by computing rays from projector positions through screen pixels into the volume using Multi-Camera Optical Projection (MCOP) [S1]. It avoids the incorrect per-pixel ray parameter values caused by standard vertex attribute interpolation by using a coarsely tessellated proxy geometry [S1]. Unlike traditional multiview technologies that restrict users to fixed positions due to discrete viewing zones, this approach provides a fully continuous perceived image [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:**
    *   Volume data stored in a single 4-component texture: RGB channels contain the unscaled precomputed gradient, and the A channel contains the voxel value [S1].
    *   A 1D RGBA lookup table for the transfer function [S1].
    *   Uniform parameters: Projector position $E_w$ (float3), Virtual observer distance $V_d$ (float), Virtual observer height $V_h$ (float), $\log_2$ of voxel size $\log_2 V$ (float), Step size $DL$ (float), Screen pixel size $S_0$ (float), Angular spread factor $\tan \Phi$ (float) [S1].
    *   Model-view inverse matrix $M_{inv}$ and Model-view matrix $M_{mv}$ [S1].
*   **Outputs:**
    *   Final color and accumulated opacity for each fragment [S1].

**Data Structures**
The method uses two structures defined in the source code [S1]:
```c
struct ray_t {
    float3 org; // Ray origin in texture coordinates
    float3 dir; // Ray direction (normalized)
    float len;  // Integration length within the volume
};

struct fragment_out {
    float4 color: COLOR0; // Output color and accumulated opacity
};
```

**Numbered Steps**

1.  **Proxy Geometry Setup:** A coarsely tessellated version (8x8 quads) of a slightly enlarged bounding volume is used as a proxy [S1]. Its vertices are streamed through a vertex shader that performs MCOP projection, passing normalized and unnormalized projected coordinates to the fragment stage [S1].
2.  **Ray Origin and Direction Computation:** In the fragment shader, the unnormalized projected position $S$ is received [S1]. The ray direction $d$ is computed using MCOP projection parameterized by emitter $E$ and virtual viewer parameters $V$ [S1]:
    $$
    d = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right]
    $$
    [S1]
3.  **Coordinate Transformation:** The infinite ray defined by $S$ and $d$ is transformed into local volume coordinates (coincident with texture coordinates) by applying the world-to-texture homogeneous transform matrix $M_{inv}$ [S1].
4.  **Ray Clipping and Validation:** The line is clipped against the unit box to compute the ray entry point and integration lengths. If the length is null (or less than epsilon), the fragment is discarded as invalid [S1].
5.  **Mipmap Level Selection:** The volume texture is stored in a Mipmap pyramid. At each sampling step, the depth $z$ of the current sample is computed by transforming its position in texture space to world (screen-aligned) space using a single dot product [S1]:
    $$
    z = | \mathbf{m}_{mv}[2] \cdot \mathbf{uvw}_{hom} |
    $$
    where $\mathbf{m}_{mv}[2]$ is the third row of the model-view matrix and $\mathbf{uvw}_{hom}$ is the homogeneous sample position [S1]. The mipmap level $l$ is chosen as the coarsest level with a sufficiently small voxel size [S1]:
    $$
    l = \text{median}(0, L_{max}, \lfloor \log_2 \frac{s(z)}{v_0} \rfloor)
    $$
    where $s(z)$ is the variable step-size, $L_{max}$ is the maximum mipmap level, and $v_0$ is the voxel size at the finest level [S1]. In the implementation, this is calculated as:
    $$
    l = \log_2(S_0 + 2 \tan \Phi \cdot z) - \log_2 V
    $$
    [S1]
6.  **Ray Marching Loop:** The ray is stepped through in a loop. Volume resampling is performed using `tex3Dlod` with the computed mipmap level [S1].
7.  **Compositing:** Front-to-back compositing updates the accumulated color $I$ and opacity $a$ [S1].
8.  **Classification and Shading:** The transfer function and shading model are applied to the sampled value to obtain color $C_i$ and opacity $\alpha_i$ [S1].

**Pseudocode**
The following pseudocode implements the fragment shader logic described in [S1]. Helper functions for basic geometric operations (like `clip_to_unit_box`) are assumed defined.

```python
# Uniforms
Ew: float3          # Projector position
Vd: float           # Virtual observer distance
Vh: float           # Virtual observer height
log2V: float        # log2 of voxel size
DL: float           # Step size
S0: float           # Screen pixel size
tanPhi: float       # Angular spread factor
mv_inv: float4x4    # Inverse model-view matrix
mv: float4x4        # Model-view matrix

# Structures
struct Ray:
    org: float3
    dir: float3
    len: float

def compute_ray(x: float, y: float) -> Ray:
    # Compute ray passing through pixel in world coords
    ray_o = float4(x, y, 0, 0)
    ray_d = float4(-(Ew.x - x) / Ew.z, (Vh - y) / Vd, -1, 0)
    
    # Transform from world to texture coordinates
    tex_o = mul(mv_inv, ray_o).xyz
    tex_e = mul(mv_inv, ray_o + ray_d).xyz
    
    # Clip ray to volume box (unit box)
    dir = normalize(tex_e - tex_o)
    tmin_tmax = clip_to_unit_box(tex_o, dir)
    
    # If length is null, discard
    if tmin_tmax.y - tmin_tmax.x < epsilon:
        return None
        
    org = tex_o + dir * tmin_tmax.x
    length = tmin_tmax.y - tmin_tmax.x
    return Ray(org, dir, length)

def fragment_shader(screen_coords: float2) -> float4:
    ray = compute_ray(screen_coords.x, screen_coords.y)
    if ray is None:
        discard()
        
    delta_dir = ray.dir * DL
    N = int(ray.len / DL)
    uvw = ray.org
    I = float3(0, 0, 0)
    a = 0.0
    
    for i in range(N):
        if a >= 1.0:
            break
            
        # Find distance from screen (z coordinate in world space)
        uvw_hom = float4(uvw.xyz, 1.0)
        z = abs(dot(mv[2], uvw_hom)) # mv[2] is the 3rd row
        
        # Compute mipmap level
        mipmap_l = log2(S0 + 2 * tanPhi * z) - log2V
        
        # Sample texture
        # Note: gggv contains gradient (RGB) and voxel value (A)
        gggv = tex3Dlod(volume_texture, float4(uvw.xyz, mipmap_l))
        
        # Apply transfer function and shading to get C_i and a_i
        # Implementation details omitted in source, assumed helper function
        C_i, alpha_i = apply_transfer_and_shading(gggv)
        
        # Accumulate color and opacity using front-to-back compositing
        I = I + (1.0 - a) * C_i
        a = a + (1.0 - a) * alpha_i
        
        # Step along ray
        uvw += delta_dir
        
    return float4(I, a)
```

**Parameters**
*   $E_w$: Projector position [S1].
*   $V_d$: Virtual observer distance [S1].
*   $V_h$: Virtual observer height [S1].
*   $\log_2 V$: Log2 of voxel size [S1].
*   $DL$: Step size [S1].
*   $S_0$: Screen pixel size [S1].
*   $\tan \Phi$: Angular spread factor [S1].
*   Proxy Tessellation: 8x8 quads [S1].

**Edge Cases and Pitfalls**
*   **Vertex Attribute Interpolation Error:** Standard vertex attribute interpolation does not produce correct per-pixel ray parameter values for MCOP. This is handled by using a proxy geometry and computing projections in the vertex shader [S1].
*   **Ray Length Validation:** If the ray length is less than epsilon, the fragment is discarded as it is out of bounds [S1].
*   **Tile Misalignment Artifacts:** When objects are moved with a too slow refresh rate, misalignment between tiles can become visible because the 96 display projectors are updated in batches of 16 [S1].

## Operating characteristics
*   **Performance:** The main limiting factor is the single GPU volume renderer performance. At full resolution (1 ray/pixel and 1 sample/voxel), many millions of rays need to be propagated for hundreds of steps [S1].
*   **Optimization:** To improve interactive frame rates, the sampling rate is lowered during interaction by reducing the pixel count (2.5mm precision on screen) and doubling the integration step-size [S1].
*   **Strengths:** Provides a fully continuous perceived image, unlike other contemporary multiview technologies that force users into fixed positions due to abrupt view-image changes when crossing discrete viewing zones [S1]. Users can exploit accommodation, stereo, and motion parallax [S1].
*   **Limitations:** Performance is constrained by the GPU; misalignment artifacts can occur if the refresh rate is too slow relative to object movement [S1].

## Background
This method was developed for the MCOP (Multi-Camera Optical Projection) viewing approach, presented in a paper by Agus et al. [S1]. It is designed for an interactive light field display consisting of 96 projectors [S1]. The approach allows users to perceive objects floating in the display space, manipulable via a six-degree-of-freedom tracker, and supports multi-user capability with good registration between displayed object space and physical space [S1].
