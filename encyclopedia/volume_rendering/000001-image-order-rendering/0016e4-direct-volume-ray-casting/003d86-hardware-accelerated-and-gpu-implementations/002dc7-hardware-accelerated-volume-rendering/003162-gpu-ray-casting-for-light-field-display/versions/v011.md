# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
GPU Ray Casting for Light Field Display is a direct volume rendering technique designed for interactive light field displays, such as the MCOP (Multi-Camera Optical Projection) system. It solves the problem of generating correct per-pixel ray parameters for multi-viewer 3D displays where standard rasterization interpolation fails due to the non-linear nature of the projection. It sets itself apart from standard GPU ray casting by computing rays from projector positions through screen pixels into the volume using a custom MCOP projection model, and by employing depth-dependent mipmap level selection to maintain spatial resolution consistency across the display space [S1].

## How it works
The method renders volume data by projecting rays from virtual emitter positions through screen pixels into a 3D texture volume. It uses a proxy geometry to bypass vertex attribute interpolation errors and computes ray parameters in the vertex/fragment shaders.

### Inputs and Outputs
**Inputs:**
*   **Volume Data:** Stored in a single 4-component 3D texture. The RGB channels contain the unscaled precomputed gradient, and the A channel contains the voxel value [S1].
*   **Lookup Table:** A 1D RGBA texture for interactively modifiable transfer functions [S1].
*   **Uniforms:**
    *   `Ew` (float3): Projector position (emitter) [S1].
    *   `Vd` (float): Virtual observer distance [S1].
    *   `Vh` (float): Virtual observer height [S1].
    *   `log2V` (float): Log2 of the voxel size at the finest mipmap level [S1].
    *   `DL` (float): Integration step size [S1].
    *   `S0` (float): Screen pixel size [S1].
    *   `tanPhi` (float): Angular spread factor [S1].
    *   `mv_inv` (float4x4): Inverse model-view matrix (world-to-texture transform) [S1].
    *   `glstate.matrix.modelview` (float4x4): Current model-view matrix for depth calculation [S1].
*   **Proxy Geometry:** A coarsely tessellated (8x8 quads) slightly enlarged bounding volume of the dataset [S1].

**Outputs:**
*   **Fragment Color:** A `float4` containing the accumulated color (RGB) and opacity (A) [S1].

### Data Structures
The implementation uses the following structures:

```cpp
struct ray_t {

struct fragment_out {
    float4 color; // Accumulated color and opacity
};
```

### Algorithm Steps

1.  **Proxy Geometry Setup:** Render a coarse proxy geometry (8x8 quads) representing the volume bounds. This geometry is used solely to activate the fragment shader for pixels intersecting the volume [S1].
2.  **Vertex Shader MCOP Projection:** For each vertex of the proxy, compute the projected screen position $S$ using the MCOP projection equations. Pass the unnormalized projected position $S$ to the fragment shader [S1].
3.  **Ray Origin and Direction Computation:** In the fragment shader, receive $S$ (the screen pixel position in the display reference frame). Compute the ray direction $d$ using the MCOP projection parameterized by emitter $E$ and virtual viewer parameters $V$ [S1]:
    $$ d = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right] $$
    *Note: In the provided pseudocode, $S$ is represented by screen coordinates $(x,y)$, $E$ by `Ew`, and $V$ by `Vd` and `Vh`. The formula in the code adapts this to: `ray_d = float4(-(Ew.x-x)/Ew.z, (Vh-y)/Vd, -1, 0)` [S1].*
4.  **Coordinate Transformation:** Transform the infinite ray defined by origin $S$ and direction $d$ from world coordinates to local volume (texture) coordinates using the inverse model-view matrix `mv_inv` [S1].
5.  **Ray Clipping and Validation:** Clip the line segment against the unit box (volume bounds) to compute the entry point and integration length. If the length is null (or less than epsilon), discard the fragment as it is out of bounds [S1].
6.  **Ray Marching Loop:** Step through the ray in a loop. At each step:
    *   Compute the depth $z$ of the current sample in world space.
    *   Calculate the appropriate mipmap level based on depth.
    *   Sample the volume texture.
    *   Apply transfer function and shading to get color $C_i$ and opacity $a_i$.
    *   Accumulate using front-to-back compositing.
    *   Step along the ray direction.
    *   Terminate if full opacity is reached or the volume is exited [S1].

### Pseudocode

The following pseudocode implements the fragment shader logic described in the source [S1]. It assumes helper functions `clip_to_unit_box` and `mipmap_value` are available.

```python
# Uniforms
uniform float3 Ew;          # Projector position
uniform float Vd;           # Virtual observer distance
uniform float Vh;           # Virtual observer height
uniform float log2V;        # log2 voxel size
uniform float DL;           # stepsize
uniform float S0;           # screen pixel size
uniform float tanPhi;       # angular spread factor
uniform float4x4 mv_inv;    # Inverse model-view matrix
uniform float4x4 modelview; # Current model-view matrix

# Structures
struct ray_t {
    float3 org;
    float3 dir;
    float len;
};

struct fragment_out {
    float4 color;
};

# Helper: Clip ray to unit box [0,1]^3
# Returns float2 {tmin, tmax}
# Note: Implementation details of clip_to_unit_box are assumed standard
# function clip_to_unit_box(float3 org, float3 dir) -> float2;

# Helper: Sample texture with specific mipmap level
# function mipmap_value(float3 uvw, float level) -> float4;

# Helper: Apply transfer function and shading
# function apply_transfer_and_shading(float4 tex_val) -> (float3 C, float a);

ray_t compute_ray(float x, float y) {
    ray_t result;
    
    # Compute ray passing through pixel in world coords
    # Ray origin at z=0 plane (screen plane approximation for ray generation)
    float4 ray_o = float4(x, y, 0, 0);
    
    # Compute ray direction using MCOP projection
    # d = [ -(Ex-x)/Ez, (Vy-y)/Vd, -1 ]
    # Note: Source uses Vh for Vy in code snippet: (Vh-y)/Vd
    float4 ray_d = float4(-(Ew.x - x) / Ew.z, (Vh - y) / Vd, -1, 0);
    
    # Transform from world to texture coordinates
    float3 tex_o = mul(mv_inv, ray_o).xyz;
    float3 tex_e = mul(mv_inv, ray_o + ray_d).xyz;
    
    # Clip ray to volume box (unit box in texture space)
    result.dir = normalize(tex_e - tex_o);
    float2 tmin_tmax = clip_to_unit_box(tex_o, result.dir);
    
    result.org = tex_o + result.dir * tmin_tmax.x;
    result.len = tmin_tmax.y - tmin_tmax.x;
    
    return result;
}

fragment_out fragment_shader(float2 screen_coords) {
    fragment_out OUT;
    
    # Compute ray in texture coordinates
    ray_t ray = compute_ray(screen_coords.x, screen_coords.y);
    
    # If ray length is less than epsilon, discard fragment
    if (ray.len < 1e-6) {
        OUT.color = float4(0, 0, 0, 0);
        return OUT;
    }
    
    # Initialize compositing variables
    float3 delta_dir = ray.dir * DL;
    int N = int(ray.len / DL);
    float3 uvw = ray.org;
    float3 I = float3(0, 0, 0);
    float a = 0.0;
    float a_max = 0.95; # Threshold for early termination
    
    # Ray marching loop
    for (int i = 0; (a < a_max) && (i < N); ++i) {
        # Find distance from screen (z coordinate in world space)
        # Transform texture coordinate to world space to get depth
        float z = abs(dot(modelview[2], float4(uvw.xyz, 1.0)));
        
        # Compute mipmap level
        # l = log2(S0 + 2*tanPhi*z) - log2V
        float mipmap_l = log2(S0 + 2 * tanPhi * z) - log2V;
        
        # Sample texture at current position with computed mipmap level
        float4 gggv = mipmap_value(uvw.xyz, mipmap_l);
        
        # Apply transfer function and shading to get C_i and a_i
        # Implementation details omitted in source, assumed to use gggv
        float3 C_i;
        float a_i;
        apply_transfer_and_shading(gggv, C_i, a_i);
        
        # Accumulate color and opacity using front-to-back compositing
        I = I + (1.0 - a) * C_i;
        a = a + (1.0 - a) * a_i;
        
        # Step along ray
        uvw += delta_dir;
    }
    
    OUT.color = float4(I, a);
    return OUT;
}
```

### Parameters and Typical Values
*   **Proxy Tessellation:** 8x8 quads [S1].
*   **Step Size (DL):** Reduced during interaction to improve frame rates (e.g., doubling the integration step-size compared to full resolution) [S1].
*   **Precision:** 2.5mm precision on screen is mentioned as a trade-off for interactive performance [S1].
*   **Mipmap Level Selection:** The level $l$ is chosen as the coarsest level with a sufficiently small voxel size:
    $$ l = \text{median}(0, L_{max}, \lfloor \log_2 \frac{s(z)}{v_0} \rfloor) $$
    where $s(z)$ is the variable step-size, $L_{max}$ is the maximum mipmap level, and $v_0$ is the voxel size at the finest level [S1]. In the pseudocode, this is approximated by `log2(S0 + 2*tanPhi*z) - log2V`.

### Edge Cases and Pitfalls
*   **Vertex Attribute Interpolation Error:** Standard fixed-function pipeline interpolation does not produce correct per-pixel ray parameters for MCOP projection. This is mitigated by using the proxy geometry and computing projections in the vertex shader [S1].
*   **Tile Misalignment Artifacts:** If objects are moved with a slow refresh rate, misalignment between tiles becomes visible because the 96 display projectors are updated in batches of 16 [S1].
*   **Out of Bounds:** If the clipped ray length is null or less than epsilon, the fragment is discarded [S1].
*   **Performance:** At full resolution (1 ray/pixel, 1 sample/voxel), millions of rays require hundreds of steps, limiting interactive frame rates. Lowering sampling rate (reducing pixel count, increasing step size) is necessary for interaction [S1].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of pixels intersecting the volume and $S$ is the number of samples per ray. Performance is limited by the high number of rays and steps required for full resolution [S1].
*   **Memory Complexity:** Dominated by the 3D volume texture and the mipmap pyramid. The volume is stored in a single 4-component texture [S1].
*   **Measured Performance:** The method was demonstrated on a light field display with 96 projectors. Interactive frame rates were achieved by reducing sampling rate (2.5mm screen precision, doubled step size) [S1].
*   **Strengths:** Provides a fully continuous perceived image for multiple viewers, unlike discrete multiview technologies. Correctly handles parallax and accommodation cues.
*   **Limitations:** Single GPU performance bottleneck at full resolution. Tile misalignment artifacts can occur with slow refresh rates [S1].
*   **When to Use:** Interactive light field displays requiring continuous multi-viewer experience.
*   **When Not to Use:** When discrete viewing zones are acceptable and higher resolution/performance is needed without the complexity of MCOP projection.

## Background
The method was introduced by Agus et al. in 2008 in the paper "GPU Accelerated Direct Volume Rendering on an Interactive Light Field Display" [S1]. It was developed for the MCOP (Multi-Camera Optical Projection) display system, which uses a cluster of projectors to create a large, interactive 3D display. The approach builds on the principles of direct volume ray casting but adapts them for the specific optical geometry of the light field display, addressing the limitations of standard rasterization for non-linear projections [S1].
