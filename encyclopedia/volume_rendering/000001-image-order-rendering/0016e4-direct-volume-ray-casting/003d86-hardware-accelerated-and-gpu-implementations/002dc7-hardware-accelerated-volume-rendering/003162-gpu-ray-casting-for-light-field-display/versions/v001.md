# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
This method performs GPU-accelerated direct volume rendering specifically for interactive light field displays, addressing the challenge of generating correct per-pixel ray parameters for multi-viewer 3D visualization [S1]. Unlike traditional multiview technologies that restrict users to fixed positions due to discrete viewing zones, this approach provides a fully continuous perceived image by projecting rays from specific emitter (projector) positions through screen pixels into the volume [S1]. It distinguishes itself from standard ray casting by using Multi-Camera Optical Projection (MCOP) to compute ray origins and directions, avoiding interpolation errors inherent in standard vertex attribute interpolation, and employing depth-dependent mipmap level selection to match spatial resolution [S1].

## How it works
The method renders a volume by casting rays from projector positions through display pixels, computing ray parameters via MCOP projection, and performing front-to-back compositing with adaptive sampling resolution [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Volume data stored in a single 4-component 3D texture: RGB channels contain unscaled precomputed gradients, and the Alpha channel contains the voxel value [S1].
    *   A 1D RGBA lookup table (LUT) for interactively modifiable transfer functions [S1].
    *   Uniform parameters: Projector position $E_w$ (float3), Virtual observer distance $V_d$ (float), Virtual observer height $V_h$ (float), $\log_2$ of voxel size $\log_2 V$ (float), Step size $DL$ (float), Screen pixel size $S_0$ (float), and Angular spread factor $\tan \Phi$ (float) [S1].
    *   Inverse model-view matrix $M_{inv}$ for world-to-texture coordinate transformation [S1].
*   **Outputs:**
    *   A fragment color (float4) containing the accumulated color and opacity [S1].

### Data Structures
The method uses the following structures for ray representation and output:

```c
struct ray_t {
    float3 org; // Ray origin in texture coordinates
    float3 dir; // Ray direction (normalized)
    float len;  // Integration length within the volume
};

struct fragment_out {
    float4 color; // Accumulated color and opacity
};
```

### Algorithm Steps

1.  **Proxy Geometry Setup:** Use a coarsely tessellated proxy geometry (8x8 quads) of a slightly enlarged bounding volume [S1]. Stream vertices through a vertex shader that performs MCOP projection to compute normalized and unnormalized projected coordinates, passing them to the fragment stage [S1]. This avoids incorrect per-pixel ray parameter values caused by standard vertex attribute interpolation [S1].

2.  **Ray Origin and Direction Computation:** In the fragment shader, receive the unnormalized projected position $S$ representing the screen pixel's position in the display reference frame [S1]. Compute the ray direction $d$ using MCOP projection parameterized by emitter $E$ and virtual viewer parameters $V$:
    $$ d = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right] $$
    where $E = (E_x, E_y, E_z)$ is the projector position and $V = (V_x, V_y, V_z)$ defines the virtual viewer geometry [S1]. Note: In the implementation code, $V_y$ is substituted by $V_h$ and $V_z$ by $V_d$ [S1].

3.  **Coordinate Transformation:** Transform the infinite ray defined by $S$ and $d$ into local volume coordinates (assumed coincident with texture coordinates) by applying the world-to-texture homogeneous transform matrix $M_{inv}$ [S1].
    $$ \text{tex}_o = M_{inv} \cdot \text{ray}_o $$
    $$ \text{tex}_e = M_{inv} \cdot (\text{ray}_o + \text{ray}_d) $$
    where $\text{ray}_o$ is the ray origin in world coordinates and $\text{ray}_d$ is the ray direction [S1].

4.  **Ray Clipping and Validation:** Clip the line segment against the unit box (volume bounds in texture space) to compute the ray entry point and integration length [S1].
    $$ \text{result.dir} = \text{normalize}(\text{tex}_e - \text{tex}_o) $$
    $$ [t_{min}, t_{max}] = \text{clip\_to\_unit\_box}(\text{tex}_o, \text{result.dir}) $$
    $$ \text{result.org} = \text{tex}_o + \text{result.dir} \cdot t_{min} $$
    $$ \text{result.len} = t_{max} - t_{min} $$
    If the length is null (or less than a small epsilon), discard the fragment as invalid [S1].

5.  **Ray Marching Loop:** Initialize compositing variables: accumulated color $I = (0,0,0)$, accumulated opacity $a = 0.0$, current position $uvw = \text{result.org}$, and step vector $\delta_{dir} = \text{result.dir} \cdot DL$ [S1]. Iterate for $N = \lfloor \text{result.len} / DL \rfloor$ steps, or until full opacity is reached [S1].

6.  **Mipmap Level Selection:** At each sampling step, compute the depth $z$ of the current sample by transforming its position in texture space to world (screen-aligned) space using a single dot product with the model-view matrix [S1]:
    $$ z = | \text{dot}(M_{modelview}[0][2], \text{float4}(uvw.xyz, 1.0)) | $$
    Compute the mipmap level $l$ using the variable step-size $s(z)$ (derived from spatial resolution requirements) and the finest voxel size $v_0$:
    $$ l = \text{median}\left(0, L_{max}, \left\lfloor \log_2 \frac{s(z)}{v_0} \right\rfloor \right) $$
    In the implementation, this is approximated as:
    $$ l = \log_2(S_0 + 2 \tan \Phi \cdot z) - \log_2 V $$
    where $L_{max}$ is the maximum available mipmap level and $\log_2 V$ is the uniform parameter [S1].

7.  **Volume Sampling:** Sample the texture at the current position $uvw$ using the computed mipmap level $l$ via the `tex3Dlod` intrinsic (or equivalent hardware function) [S1]. The sample returns the precomputed gradient (RGB) and voxel value (A) [S1].

8.  **Transfer Function and Shading:** Apply the transfer function and shading model to the sampled data to obtain color $C_i$ and opacity $\alpha_i$ [S1]. The specific shading implementation (e.g., Phong illumination) is not detailed in the core algorithm but relies on the precomputed gradient [S1].

9.  **Front-to-Back Compositing:** Update accumulated color and opacity:
    $$ I = I + (1.0 - a) \cdot C_i $$
    $$ a = a + (1.0 - a) \cdot \alpha_i $$
    If $a \ge a_{max}$ (typically 1.0 or a threshold like 0.99), terminate the ray [S1].

10. **Step Advancement:** Advance the sample position:
    $$ uvw = uvw + \delta_{dir} $$

        # If we treat the matrix as row-major for dot product, we need the 3rd element of the 1st row?
        # Actually, dot(v, M[i]) usually means v dot the i-th row.
        # Let's assume mv_modelview is stored such that mv_modelview[2] is the 3rd row.
        
        # Compute mipmap level
        # l = log2(S0 + 2*tanPhi*z) - log2V
        mipmap_l = math.log2(S0 + 2 * tanPhi * z) - log2V
        
        # Clamp mipmap level
        # Lmax is not passed, assume 0 is min, and we clamp to reasonable max
        # In source: median(0, Lmax, ...)
        # We'll clamp to 0 for simplicity if not provided, or assume Lmax is large enough
        mipmap_l = max(0.0, mipmap_l)
        
        # 6. Volume Sampling
        gggv = mipmap_value(volume, uvw, mipmap_l)

        C_i, alpha_i = apply_transfer_function(gggv[:3], gggv[3])

        # I = I + (1.0 - a) * C_i
        # a = a + (1.0 - a) * alpha_i
        factor = 1.0 - a
        I = [I[j] + factor * C_i[j] for j in range(3)]
        a = a + factor * alpha_i
        
        # 9. Step Advancement
        uvw = [uvw[j] + delta_dir[j] for j in range(3)]
        
    return I

### Edge Cases and Pitfalls
*   **Vertex Attribute Interpolation Error:** Standard fixed-function pipeline interpolation does not produce correct per-pixel ray parameter values for MCOP projection. This is mitigated by using the proxy geometry and computing projections in the vertex shader [S1].
*   **Tile Misalignment Artifacts:** If objects are moved with a slow refresh rate, misalignment between tiles can become visible because the 96 display projectors are updated in batches of 16 [S1].
*   **Ray Length Validation:** If the computed ray length is less than epsilon, the fragment is discarded as it is out of bounds [S1].
*   **Precision:** The method relies on accurate transformation matrices and mipmap level calculations. Errors in $z$-depth calculation can lead to incorrect LOD selection and visual artifacts [S1].

## Operating characteristics
*   **Time Complexity:** The complexity is proportional to the number of pixels multiplied by the average number of samples per ray. The number of samples is determined by the ray length divided by the step size $DL$ [S1].
*   **Memory Complexity:** The volume is stored in a 3D texture with a mipmap pyramid. The memory usage is proportional to the volume size plus the overhead of the mipmap levels [S1].
*   **Performance:** The main limiting factor is the single GPU volume renderer performance, as many millions of rays need to be propagated for hundreds of steps at full resolution (1 ray/pixel, 1 sample/voxel) [S1]. Interactive frame rates are improved by lowering the sampling rate (reducing pixel count and doubling step size) during interaction [S1].
*   **Strengths:** Provides a fully continuous perceived image for multiple viewers, unlike discrete multiview technologies. Supports interactive manipulation of the volume (translation, rotation, scaling, transfer function modification) [S1].
*   **Limitations:** Performance is constrained by GPU capabilities at full resolution. Tile misalignment artifacts can occur with slow refresh rates [S1].

## Background
The method was introduced by Agus et al. in 2008 in the paper "GPU Accelerated Direct Volume Rendering on an Interactive Light Field Display" [S1]. It was developed to enable interactive direct volume rendering on a large-scale interactive light field display consisting of 96 projectors. The work builds on previous research in multiview 3D displays and GPU-accelerated volume rendering, addressing the specific challenges of ray parameter computation and spatial resolution adaptation for light field displays [S1].
