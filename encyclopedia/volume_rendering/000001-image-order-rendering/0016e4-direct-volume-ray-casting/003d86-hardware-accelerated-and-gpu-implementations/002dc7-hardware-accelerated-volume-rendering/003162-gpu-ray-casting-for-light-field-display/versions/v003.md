# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
This method accelerates direct volume rendering on an interactive light field display by computing rays from projector positions through screen pixels into the volume using Multi-Camera Optical Projection (MCOP) [S1]. It solves the problem of incorrect per-pixel ray parameters caused by standard vertex attribute interpolation in non-linear projections, ensuring a fully continuous perceived image for multiple viewers [S1]. Unlike traditional multiview technologies that restrict users to fixed positions due to discrete viewing zones, this approach provides continuous parallax and accommodation cues [S1].

## How it works
The method implements a GPU-based ray casting pipeline where ray parameters are computed via MCOP projection in the vertex shader, and volume integration occurs in the fragment shader with depth-dependent mipmap selection [S1].

### Inputs and Outputs
**Inputs:**
*   **Volume Data:** Stored in a single 4-component 3D texture. The RGB channels contain the unscaled precomputed gradient, and the A channel contains the voxel value [S1].
*   **Lookup Table:** A 1D RGBA texture containing an interactively modifiable transfer function [S1].
*   **Uniforms:**
    *   `Ew`: Projector position (float3) [S1].
    *   `Vd`: Virtual observer distance (float) [S1].
    *   `Vh`: Virtual observer height (float) [S1].
    *   `log2V`: Log2 of the finest voxel size (float) [S1].
    *   `DL`: Integration step size (float) [S1].
    *   `S0`: Screen pixel size (float) [S1].
    *   `tanPhi`: Angular spread factor (float) [S1].
    *   `mv_inv`: Inverse model-view matrix (float4x4) [S1].
    *   `a_max`: Maximum opacity threshold for early termination (float) [S1].

**Outputs:**
*   **Fragment Color:** A `float4` containing the accumulated color (RGB) and opacity (A) [S1].

### Data Structures
The method defines two primary structures for ray state and output:

```cpp
struct ray_t {
    float3 org; // Ray origin in texture coordinates
    float3 dir; // Normalized ray direction in texture coordinates
    float len;  // Integration length within the volume
};

struct fragment_out {
    float4 color; // Accumulated color and opacity
};
```

### Algorithm Steps

1.  **Proxy Geometry Setup:** A coarsely tessellated proxy geometry (8x8 quads) of a slightly enlarged bounding volume is used [S1]. This avoids the curvature artifacts and interpolation errors inherent in standard fixed-function pipelines when projecting MCOP rays [S1].
2.  **Vertex Shader (MCOP Projection):** For each vertex, the MCOP projection is computed. The vertex shader calculates the unnormalized projected position $S$ in the display reference frame and passes normalized and unnormalized coordinates to the fragment stage [S1].
3.  **Fragment Shader (Ray Initialization):**
    *   Receive the unnormalized projected position $S$ from the vertex stage [S1].
    *   Compute the ray direction $d$ in world coordinates using the MCOP projection formula parameterized by emitter $E$ and virtual viewer $V$:
        $$ d = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right] $$
        where $S$ is the screen pixel position, $E$ is the projector position, and $V$ represents virtual viewer parameters ($V_y, V_z$) [S1].
    *   Transform the ray from world coordinates to local volume (texture) coordinates using the inverse model-view matrix [S1].
    *   Clip the ray against the unit box to determine the entry point and integration length. If the length is null (or less than epsilon), discard the fragment [S1].
4.  **Ray Marching Loop:**
    *   Initialize compositing variables: accumulated color $I = (0,0,0)$, accumulated opacity $a = 0.0$, and current texture coordinate $uvw = \text{ray.org}$ [S1].
    *   Calculate the number of steps $N = \lfloor \text{ray.len} / DL \rfloor$ [S1].
    *   Iterate $i$ from 0 to $N$ while $a < a_{max}$:
        *   **Mipmap Level Selection:** Compute the depth $z$ of the current sample in world space using a dot product with the model-view matrix row [S1]. Calculate the mipmap level $l$ using:
            $$ l = \text{median}\left(0, L_{max}, \left\lfloor \log_2 \frac{s(z)}{v_0} \right\rfloor \right) $$
            where $s(z)$ is the variable step size, $v_0$ is the finest voxel size, and $L_{max}$ is the maximum mipmap level [S1]. In the implementation, this is approximated as:
            $$ l = \log_2(S_0 + 2 \cdot \tan\Phi \cdot z) - \log_2 V $$
            [S1].
        *   **Sampling:** Sample the volume texture at $uvw$ using the computed mipmap level $l$ via `tex3Dlod` (or equivalent) [S1]. Retrieve voxel value and gradient [S1].
        *   **Shading and Transfer Function:** Apply the transfer function and shading model (e.g., Phong illumination) to compute the sample color $C_i$ and opacity $a_i$ [S1].
        *   **Compositing:** Update accumulated color and opacity using front-to-back compositing:
            $$ I = I + (1.0 - a) \cdot C_i $$
            $$ a = a + (1.0 - a) \cdot a_i $$
            [S1].
        *   **Step:** Advance the texture coordinate: $uvw = uvw + \text{ray.dir} \cdot DL$ [S1].

        # Accumulate
        I = I + (1.0 - a) * C_i
        a = a + (1.0 - a) * a_i
        
        # Step
        uvw += delta_dir
        
    OUT.color = float4(I, a)
    return OUT

### Edge Cases and Pitfalls
*   **Interpolation Error:** Standard vertex attribute interpolation fails for MCOP because the projection cannot be recast into a traditional homogeneous matrix, and long straight lines appear curved [S1]. The proxy geometry and vertex-shader projection solve this [S1].
*   **Tile Misalignment:** If the object moves too slowly relative to the display refresh rate, misalignment between tiles becomes visible because the 96 display projectors are updated in batches of 16 [S1].
*   **Ray Length:** If the clipped ray length is less than epsilon, the fragment is discarded as it lies outside the volume bounds [S1].

## Operating characteristics
*   **Performance:** The method requires millions of rays to be propagated for hundreds of steps at full resolution, which is the main limiting factor for interactive frame rates [S1].
*   **Optimization:** To improve performance, the sampling rate is lowered during interaction by reducing pixel count (e.g., 2.5mm precision on screen) and doubling the integration step size [S1].
*   **Memory:** The volume is stored in a single 4-component texture, and a 1D LUT is used for the transfer function [S1].
*   **Strengths:** Provides a fully continuous perceived image with correct parallax and accommodation cues, unlike discrete multiview systems [S1].
*   **Limitations:** Performance is constrained by single GPU volume rendering capabilities; heavy optimization (lowering resolution/step size) is required for interactivity [S1].

## Background
This method was introduced by Agus et al. in 2008 [S1]. It was developed for an interactive light field display system, aiming to provide multi-user 3D volume rendering with continuous viewing zones. The work builds upon GPU-accelerated volume rendering techniques and addresses the specific geometric challenges of projecting volume data onto a multi-projector light field display.
