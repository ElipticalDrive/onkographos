# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
This method performs interactive direct volume rendering on a multi-projector light field display by computing rays from projector positions through screen pixels into a volume, using Multi-Camera Optical Projection (MCOP) to avoid interpolation artifacts [S1]. It distinguishes itself from standard GPU ray casting by explicitly modeling the discrete projector geometry and using depth-dependent mipmap selection to match sampling rates to the display's spatial resolution, providing a continuous perceived image unlike discrete multiview technologies [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume stored in a 4-component texture (RGB: precomputed gradient, A: voxel value) [S1]. A 1D RGBA lookup table for transfer functions [S1]. Uniforms for projector position $E_w$, virtual observer distance $V_d$, virtual observer height $V_h$, log2 voxel size $\log_2 V$, step size $DL$, screen pixel size $S_0$, and angular spread factor $\tan \Phi$ [S1].
*   **Output:** A fragment color and opacity representing the accumulated volume rendering for the specific projector view [S1].

**Data Structures:**
*   `ray_t`: Struct containing `org` (float3), `dir` (float3), and `len` (float) [S1].
*   `fragment_out`: Struct containing `color` (float4) [S1].

**Steps:**
1.  **Proxy Geometry Setup:** Use a coarsely tessellated proxy (8x8 quads) of a slightly enlarged bounding volume [S1].
2.  **Vertex Shader (MCOP Projection):** Stream proxy vertices through a vertex shader that performs MCOP projection. This computes the unnormalized projected position $S$ for each fragment, representing the screen pixel's position in the display reference frame [S1]. Standard vertex attribute interpolation is avoided because linear interpolation does not produce correct per-pixel ray parameters for the non-homogeneous MCOP projection [S1].
3.  **Ray Origin and Direction:** In the fragment shader, receive $S$. Compute the ray direction $d$ using the MCOP projection parameterized by emitter $E$ and virtual viewer parameters $V$ [S1]:
    $$
    \mathbf{d} = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right]
    $$
    where $E = (E_x, E_y, E_z)$ is the projector position and $V = (V_x, V_y, V_z)$ defines the virtual viewer [S1]. Note: The source code uses specific uniform names $E_w, V_d, V_h$ which map to these geometric parameters [S1].
4.  **Coordinate Transformation:** Transform the infinite ray defined by $S$ and $d$ into local volume coordinates (texture coordinates) by applying the inverse model-view matrix [S1].
5.  **Ray Clipping:** Clip the line against the unit box to compute the ray entry point and integration length. If the length is null (or less than epsilon), discard the fragment [S1].
6.  **Ray Marching Loop:** Step through the ray. At each step:
    *   Compute the depth $z$ of the current sample in world space using a dot product with the model-view matrix [S1].
    *   Compute the mipmap level $l$ based on $z$ to ensure the voxel size matches the spatial resolution at that depth [S1].
    *   Sample the volume texture at the current position using the computed mipmap level [S1].
    *   Apply the transfer function and shading to obtain color $C_i$ and opacity $\alpha_i$ [S1].
    *   Accumulate using front-to-back compositing [S1].
    *   Step along the ray direction [S1].
7.  **Termination:** Stop when full opacity is reached or the volume is exited [S1].

    ray.len = tmin_tmax.y - tmin_tmax.x

    for i in range(N):
        if a >= a_max:

        # Transform uvw to world space to get z

        z = abs(world_pos.z)
        
        # Compute mipmap level

        mipmap_l = log2(S0 + 2.0 * tanPhi * z) - log2V

**Pitfalls:**
*   **Interpolation Error:** Standard vertex attribute interpolation fails for MCOP projection because it cannot be recast into a traditional homogeneous matrix, causing long straight lines to appear curved and incorrect per-pixel ray parameters [S1].
*   **Tile Misalignment:** If the refresh rate is too slow, misalignment between tiles becomes visible because the 96 display projectors are updated in batches of 16 [S1].
*   **Precision:** If ray length is less than epsilon, the fragment is discarded [S1].

## Operating characteristics
*   **Performance:** The main limiting factor is the single GPU volume renderer performance, as millions of rays need to be propagated for hundreds of steps at full resolution (1 ray/pixel, 1 sample/voxel) [S1].
*   **Optimization:** Interactive frame rates are improved by lowering the sampling rate: reducing pixel count (2.5mm precision on screen) and doubling the integration step-size [S1].
*   **Scaling:** The method uses mipmap-based sampling with level calculated based on distance from screen ($z$) and angular spread ($\tan \Phi$), adapting to depth-dependent spatial resolution [S1].
*   **Strengths:** Provides a fully continuous perceived image, unlike contemporary multiview technologies that force users into fixed positions due to abrupt view-image changes [S1]. Supports parallax, accommodation, and stereo cues [S1].
*   **Limitations:** Performance is constrained by GPU throughput; requires lowering resolution/step size for interactivity [S1].

## Background
*   **Origin:** The method was introduced by Agus et al. in 2008 [S1].
*   **Context:** It addresses the challenges of rendering volumetric data on interactive light field displays, which consist of multiple projectors. It builds on direct volume ray casting principles but adapts them for the specific geometry of a multi-projector setup [S1].
*   **Usage:** Demonstrated with datasets like Chameleon, Visible Human head, and rotational angiography [S1].
