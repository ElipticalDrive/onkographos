# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
This method performs interactive direct volume rendering on an interactive light field display by computing rays from projector positions through screen pixels into the volume using Multi-Camera Optical Projection (MCOP) [S1]. It differs from standard GPU ray casting by using a coarsely tessellated proxy geometry to compute correct per-pixel ray parameters, avoiding interpolation errors inherent in the fixed-function pipeline, and employs depth-dependent mipmap level selection to match sampling rates to spatial resolution [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   Volume data stored in a single 4-component texture: RGB channels contain the unscaled precomputed gradient, and the A channel contains the voxel value [S1].
    *   A 1D RGBA lookup table for the transfer function [S1].
    *   Uniform parameters: Projector position $E_w$ (float3), Virtual observer distance $V_d$ (float), Virtual observer height $V_h$ (float), $\log_2$ of voxel size $\log_2 V$ (float), Step size $DL$ (float), Screen pixel size $S_0$ (float), Angular spread factor $\tan \Phi$ (float) [S1].
    *   World-to-texture inverse model-view matrix $M_{inv}$ [S1].
*   **Outputs:**
    *   Final color and accumulated opacity for each fragment [S1].

**Data Structures:**
*   `ray_t`: Struct containing `org` (float3), `dir` (float3), and `len` (float) [S1].
*   `fragment_out`: Struct containing `color` (float4) [S1].

**Steps:**

1.  **Proxy Geometry Setup:** Use a coarsely tessellated version (8x8 quads) of a slightly enlarged bounding volume as a proxy [S1]. Stream its vertices through a vertex shader that performs MCOP projection [S1].
2.  **Ray Origin and Direction Computation:** In the fragment shader, receive the unnormalized projected position $S$ from the vertex stage, representing the screen pixel’s position in the display reference frame [S1]. Compute the ray direction $d$ using MCOP projection parameterized by emitter $E$ and virtual viewer parameters $V$:
    $$
    d = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right]
    $$
    [S1]
3.  **Coordinate Transformation:** Transform the infinite ray defined by $S$ and $d$ into local volume coordinates (coincident with texture coordinates) by applying the world-to-texture homogeneous transform matrix $M_{inv}$ [S1].
4.  **Ray Clipping and Validation:** Clip the line against the unit box to compute ray entry point and integration lengths. If the length is null (or less than epsilon), discard the fragment as invalid [S1].
5.  **Ray Marching Loop:** Step through the ray in a loop, performing volume resampling and compositing until the volume is exited or full opacity is reached [S1].
6.  **Mipmap Level Selection:** At each sampling step, compute the depth $z$ of the current sample by transforming its position in texture space to world (screen aligned) space using a single dot product for the z coordinate [S1]. Compute the mipmap level $l$ using:
    $$
    l = \text{median}(0, L_{max}, \lfloor \log_2 \frac{s(z)}{v_0} \rfloor)
    $$
    where $s(z)$ is the variable step-size, $L_{max}$ is the maximum available mipmap level, and $v_0$ is the voxel size at the finest mipmap level [S1]. Access the texture using `tex3Dlod` with the computed level [S1].
7.  **Compositing:** Accumulate color and opacity using front-to-back compositing [S1].
8.  **Classification and Shading:** Apply the transfer function and shading to get color $C_i$ and opacity $\alpha_i$ [S1].

**Edge Cases and Pitfalls:**
*   **Vertex Attribute Interpolation Error:** Standard vertex attribute interpolation does not produce correct per-pixel ray parameter values due to the non-homogeneous nature of MCOP projection. This is handled by using a proxy geometry and computing projections in the vertex shader [S1].
*   **Tile Misalignment Artifacts:** When objects are moved with a too slow refresh rate, misalignment between tiles can become visible because the 96 display projectors are updated in batches of 16 [S1].
*   **Out of Bounds:** If ray length is less than epsilon, discard fragment as it is out of bounds [S1].

## Operating characteristics
*   **Time Complexity:** The method requires propagating millions of rays for hundreds of steps through the volume at full resolution (1 ray/pixel, 1 sample/voxel) [S1]. To improve interactive frame rates, the sampling rate is lowered by reducing pixel count (2.5mm precision on screen) and doubling the integration step-size [S1].
*   **Memory Complexity:** The volume is stored in a single 4-component texture (RGB for gradient, A for value) and a 1D RGBA lookup table [S1].
*   **Strengths:** Provides a fully continuous perceived image, unlike other contemporary multiview technologies that force users into fixed positions due to abrupt view-image changes when crossing discrete viewing zones [S1]. Users can exploit accommodation, stereo, and motion parallax [S1].
*   **Limitations:** Performance is limited by single GPU volume renderer capability at full resolution [S1]. Tile misalignment artifacts can occur with slow refresh rates [S1].

## Background
This method was introduced by Agus et al. in 2008 [S1]. It was developed for an interactive light field display consisting of 96 projectors [S1]. The approach allows users to manipulate objects with a six-degree-of-freedom tracker and modify the transfer function interactively [S1].
