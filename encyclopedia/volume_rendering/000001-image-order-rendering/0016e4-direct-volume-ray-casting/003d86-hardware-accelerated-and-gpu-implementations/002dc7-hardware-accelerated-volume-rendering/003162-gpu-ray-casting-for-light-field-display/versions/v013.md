# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
This method performs direct volume rendering on an interactive light field display by computing rays from projector positions through screen pixels into the volume, utilizing Multi-Camera Optical Projection (MCOP) to avoid interpolation artifacts [S1]. It distinguishes itself from standard GPU ray casting by explicitly modeling the light field geometry via MCOP projection in the vertex shader and employing depth-dependent mipmap level selection to match spatial resolution with the display's angular spread [S1].

## How it works
### Inputs and Outputs
**Inputs:**
*   Volumetric data $V$ stored in a 4-component 3D texture (`sampler3D`). The RGB channels contain unscaled precomputed gradients, and the Alpha channel contains the voxel value [S1].
*   A 1D RGBA lookup table texture for the transfer function [S1].
*   Uniform parameters:
    *   `Ew`: Projector position (float3) [S1].
    *   `Vd`: Virtual observer distance (float) [S1].
    *   `Vh`: Virtual observer height (float) [S1].
    *   `log2V`: Log2 of the finest voxel size (float) [S1].
    *   `DL`: Integration step size (float) [S1].
    *   `S0`: Screen pixel size (float) [S1].
    *   `tanPhi`: Angular spread factor (float) [S1].
    *   `mv_inv`: Inverse model-view matrix (float4x4) [S1].
*   Proxy geometry: A coarsely tessellated mesh (8x8 quads) of a slightly enlarged bounding volume [S1].

**Outputs:**
*   Fragment color and opacity (`fragment_out`), written to the frame buffer for each projector tile [S1].

### Data Structures
The method uses two primary structures passed between shader stages or used internally:

```c
struct ray_t {
    float3 org; // Ray origin in texture coordinates
    float3 dir; // Normalized ray direction in texture coordinates
    float len;  // Integration length within the volume
};

struct fragment_out {
    float4 color: COLOR0; // Final accumulated color and opacity
};
```

### Algorithm Steps

1.  **Proxy Geometry Setup**: Render a coarse proxy mesh (8x8 quads) representing the volume bounds. This geometry is used to generate per-pixel ray parameters [S1].
2.  **MCOP Projection (Vertex Shader)**:
    *   For each vertex, compute the projected position $S$ in the display reference frame using MCOP equations [S1].
    *   Pass normalized and unnormalized projected coordinates to the fragment shader [S1].
3.  **Ray Parameter Computation (Fragment Shader)**:
    *   Receive the unnormalized projected position $S$ from the vertex stage [S1].
    *   Compute the ray direction $\mathbf{d}$ in world coordinates using the MCOP projection parameterized by emitter $E$ and virtual viewer parameters $V$:
        $$
        \mathbf{d} = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right]
        $$
        where $E = (E_x, E_y, E_z)$ is the projector position and $V = (V_x, V_y, V_z)$ represents the virtual viewer parameters (specifically height $V_h$ and distance $V_d$) [S1].
    *   Transform the ray from world coordinates to local volume (texture) coordinates using the inverse model-view matrix `mv_inv` [S1].
    *   Clip the ray against the unit box (volume bounds in texture space) to determine the entry point and integration length [S1].
    *   If the ray length is less than a small epsilon, discard the fragment as invalid [S1].
4.  **Ray Marching Loop**:
    *   Initialize compositing variables: accumulated color $I = (0,0,0)$, accumulated opacity $a = 0.0$, current texture coordinate $uvw = \text{ray.org}$, and step vector $\Delta \mathbf{r} = \text{ray.dir} \times DL$ [S1].
    *   Calculate the total number of steps $N = \lfloor \text{ray.len} / DL \rfloor$ [S1].
    *   Iterate $i$ from $0$ to $N-1$ while $a < a_{max}$ (typically 1.0) [S1].
5.  **Adaptive Mipmap Selection**:
    *   At each step, compute the depth $z$ of the current sample $uvw$ from the screen (world-aligned) using a dot product with the model-view matrix:
        $$
        z = \left| \mathbf{m}_{2} \cdot (uvw, 1) \right|
        $$
        where $\mathbf{m}_{2}$ is the third row (z-axis) of the model-view matrix [S1].
    *   Compute the mipmap level $l$ to ensure the voxel size matches the spatial resolution at depth $z$:
        $$
        l = \text{median}\left(0, L_{max}, \left\lfloor \log_2 \left( \frac{s(z)}{v_0} \right) \right\rfloor \right)
        $$
        where $s(z)$ is the variable step size, $v_0$ is the finest voxel size, and $L_{max}$ is the maximum mipmap level [S1]. In the implementation, this is approximated as:
        $$
        l = \log_2(S_0 + 2 \cdot \tan\Phi \cdot z) - \log_2 V
        $$
        [S1].
6.  **Sampling and Compositing**:
    *   Sample the volume texture at $uvw$ using the computed mipmap level $l$ via `tex3Dlod` (or equivalent) [S1].
    *   Apply the transfer function and shading model to derive color $C_i$ and opacity $\alpha_i$ from the sampled gradient and value [S1].
    *   Update accumulated color and opacity using front-to-back compositing:
        $$
        I = I + (1.0 - a) C_i
        $$
        $$
        a = a + (1.0 - a) \alpha_i
        $$
    *   Advance the sample position: $uvw = uvw + \Delta \mathbf{r}$ [S1].
7.  **Output**: Write the final accumulated color and opacity to the output buffer [S1].

### Pseudocode

```python
# Vertex Shader
# Input: Vertex position in proxy geometry
# Output: Varying coordinates for fragment shader

vertex_out vertex_shader(vertex_in IN):
    # Compute MCOP projection for the vertex
    # S is the projected position in display reference frame
    S = compute_mcop_projection(IN.position, Ew, Vd, Vh)
    
    # Pass normalized and unnormalized coordinates
    OUT.Qw = S 
    return OUT

# Fragment Shader
# Input: Varying coordinates from vertex shader
# Uniforms: Ew, Vd, Vh, log2V, DL, S0, tanPhi, mv_inv, volume_tex, lut_tex

fragment_out fragment_shader(vertex_out IN):
    # 1. Compute Ray in Texture Coordinates
    # Extract screen pixel coordinates from projected position
    x = IN.Qw.x
    y = IN.Qw.y
    
    # Compute ray origin and direction in world coordinates
    # Note: The source code uses float4(x, y, 0, 0) for origin, 
    # implying the ray starts at the screen plane z=0 in a specific local frame.
    ray_o = float4(x, y, 0, 0)
    ray_d = float4(-(Ew.x - x) / Ew.z, (Vh - y) / Vd, -1, 0)
    
    # Transform to texture coordinates
    tex_o = mul(mv_inv, ray_o).xyz
    tex_e = mul(mv_inv, ray_o + ray_d).xyz
    
    # Clip to unit box
    dir = normalize(tex_e - tex_o)
    tmin_tmax = clip_to_unit_box(tex_o, dir)
    
    ray_org = tex_o + dir * tmin_tmax.x
    ray_len = tmin_tmax.y - tmin_tmax.x
    
    # 2. Validate Ray
    if ray_len < epsilon:
        discard # Fragment is out of bounds
    
    # 3. Initialize Compositing
    delta_dir = dir * DL
    N = int(ray_len / DL)
    uvw = ray_org
    I = float3(0, 0, 0)
    a = 0.0
    
    # 4. Ray Marching Loop
    for i from 0 to N-1:
        if a >= a_max:
            break
            
        # Compute depth z for mipmap selection
        # Using the third row of the model-view matrix
        z = abs(dot(glstate.matrix.modelview[0][2], float4(uvw, 1.0)))
        
        # Compute mipmap level
        # l = median(0, Lmax, floor(log2(s(z)/v0)))
        # Implementation approximation:
        mipmap_l = log2(S0 + 2 * tanPhi * z) - log2V
        
        # Clamp mipmap level to valid range [0, Lmax]
        mipmap_l = clamp(mipmap_l, 0.0, float(Lmax))
        
        # Sample volume texture
        # gggv contains gradient (RGB) and value (A)
        gggv = sample_3d_texture_lod(volume_tex, uvw, mipmap_l)
        
        # Apply Transfer Function and Shading
        # C_i and a_i are derived from gggv and the LUT
        C_i, a_i = apply_transfer_and_shading(gggv, lut_tex)
        
        # Front-to-back compositing
        I = I + (1.0 - a) * C_i
        a = a + (1.0 - a) * a_i
        
        # Step along ray
        uvw = uvw + delta_dir
        
    OUT.color = float4(I, a)
    return OUT
```

### Edge Cases and Pitfalls
*   **Vertex Attribute Interpolation Error**: Standard fixed-function pipeline interpolation of vertex attributes does not produce correct per-pixel ray parameters for MCOP because the projection cannot be recast into a traditional homogeneous matrix and long lines appear curved. This is mitigated by using the coarse proxy geometry and computing projections in the vertex shader [S1].
*   **Tile Misalignment Artifacts**: The display projectors are updated in batches of 16. If objects are moved with a refresh rate that is too slow, misalignment between tiles becomes visible [S1].
*   **Ray Out of Bounds**: If the clipped ray length is null or less than epsilon, the fragment is discarded [S1].
*   **Performance Limitations**: At full resolution (1 ray/pixel, 1 sample/voxel), millions of rays require hundreds of steps, limiting interactive frame rates. The method often lowers sampling rate during interaction by reducing pixel count and doubling step size [S1].

## Operating characteristics
*   **Time Complexity**: $O(N \cdot P)$, where $N$ is the number of samples per ray and $P$ is the number of pixels (projector tiles). The adaptive mipmap selection adds a logarithmic cost for level calculation but reduces memory bandwidth by sampling coarser levels at depth.
*   **Memory Complexity**: $O(V)$ for the volume texture, where $V$ is the number of voxels, plus $O(L)$ for the mipmap pyramid. The proxy geometry is minimal ($8 \times 8$ quads) [S1].
*   **Performance**: The method achieves interactive frame rates by reducing sampling density during interaction (e.g., 2.5mm precision on screen, doubled step size) [S1].
*   **Strengths**: Provides a fully continuous perceived image for multi-viewers, avoiding the abrupt view-image changes of discrete multiview technologies. Correctly handles parallax and accommodation cues [S1].
*   **Limitations**: Performance is limited by single GPU throughput for high-resolution, high-sample-count rendering. Tile misalignment artifacts can occur with slow refresh rates [S1].

## Background
The method was introduced by Agus et al. in 2008 for the "Chameleon" light field display, a system using 96 projectors to create an interactive 3D volume rendering environment [S1]. It builds upon the principles of GPU-accelerated volume rendering and adapts them to the specific geometry of a multi-projector light field display using MCOP projection [S1].
