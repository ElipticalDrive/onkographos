# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
This method implements GPU-accelerated direct volume rendering specifically for interactive light field displays using Multi-Camera Optical Projection (MCOP) [S1]. It solves the problem of generating correct per-pixel ray parameters for a multi-projector display where standard fixed-function pipeline interpolation fails, producing curved lines and incorrect ray origins [S1]. Unlike traditional multiview technologies that restrict users to discrete viewing zones, this approach provides a fully continuous perceived image by computing rays from projector positions through screen pixels into the volume [S1]. It distinguishes itself by using a coarsely tessellated proxy geometry to compute MCOP projections in the vertex shader and employing depth-dependent mipmap level selection to match spatial resolution to the display's angular spread [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   **Volume Data:** Stored in a single 4-component 3D texture. The RGB channels contain the unscaled precomputed gradient, and the Alpha channel contains the voxel value [S1].
*   **Lookup Table:** A 1D RGBA texture containing an interactively modifiable transfer function [S1].
*   **Uniforms:**
    *   `Ew` (float3): Projector position (emitter coordinates) [S1].
    *   `Vd` (float): Virtual observer distance [S1].
    *   `Vh` (float): Virtual observer height [S1].
    *   `log2V` (float): Log2 of the finest voxel size [S1].
    *   `DL` (float): Integration step size [S1].
    *   `S0` (float): Screen pixel size [S1].
    *   `tanPhi` (float): Angular spread factor [S1].
    *   `mv_inv` (float4x4): Inverse model-view matrix (world-to-texture transform) [S1].
    *   `a_max` (float): Opacity threshold for early ray termination [S1].
*   **Proxy Geometry:** A coarsely tessellated mesh (8x8 quads) of a slightly enlarged bounding volume [S1].

**Outputs:**
*   **Fragment Color:** A `float4` containing the accumulated color in RGB and accumulated opacity in Alpha [S1].

### Data Structures
The method defines two primary structures for passing data between shader stages and managing ray state [S1]:

```cpp
struct ray_t {
    float3 org; // Ray origin in texture coordinates
    float3 dir; // Ray direction in texture coordinates
    float len;  // Integration length within the volume
};

struct fragment_out {
    float4 color: COLOR0; // Accumulated color and opacity
};
```

### Algorithm Steps

1.  **Proxy Geometry Setup:** Render a coarse proxy mesh (8x8 quads) covering the display area. This geometry is used solely to drive the fragment shader with correct per-pixel screen coordinates, avoiding interpolation errors inherent in standard vertex attribute interpolation for MCOP projections [S1].

2.  **Ray Generation (Vertex/Fragment Shader Boundary):**
    The fragment shader receives the unnormalized projected position $S$ (screen pixel position in the display reference frame) from the vertex stage [S1]. The ray direction $\mathbf{d}$ is computed using the MCOP projection formula, parameterized by the emitter position $\mathbf{E}$ and virtual viewer parameters $\mathbf{V}$ [S1]:
    $$
    \mathbf{d} = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right]
    $$
    Note: In the implementation, $V_y$ corresponds to `Vh` and $V_z$ corresponds to `Vd` [S1].

3.  **Coordinate Transformation:**
    Transform the infinite ray defined by origin $S$ and direction $\mathbf{d}$ into local volume coordinates (assumed coincident with texture coordinates) by applying the inverse model-view matrix `mv_inv` [S1].

4.  **Ray Clipping and Validation:**
    Clip the transformed ray against the unit box (the volume domain in texture space) to compute the entry parameter $t_{min}$ and exit parameter $t_{max}$ [S1].
    *   Calculate the ray length $L = t_{max} - t_{min}$.
    *   If $L < \epsilon$ (or is null), discard the fragment as it is out of bounds [S1].
    *   Compute the final ray origin in texture space: $\mathbf{o}_{tex} = \mathbf{o}_{tex} + \mathbf{d}_{tex} \cdot t_{min}$ [S1].

5.  **Initialization:**
    Initialize the compositing variables:
    *   Accumulated color $\mathbf{I} = (0, 0, 0)$ [S1].
    *   Accumulated opacity $a = 0.0$ [S1].
    *   Step vector $\Delta \mathbf{dir} = \mathbf{d}_{tex} \cdot DL$ [S1].
    *   Number of steps $N = \lfloor L / DL \rfloor$ [S1].
    *   Current position $\mathbf{uvw} = \mathbf{o}_{tex}$ [S1].

6.  **Ray Marching Loop:**
    Iterate $i$ from $0$ to $N-1$ while $a < a_{max}$ [S1]:
    
    a. **Depth Computation:** Compute the distance $z$ of the current sample from the screen (in world space) to determine the appropriate spatial resolution. This is done by transforming the current texture coordinate $\mathbf{uvw}$ to world space and extracting the Z component using a single dot product with the model-view matrix [S1]:
    $$
    z = | \mathbf{m}_{2} \cdot [\mathbf{uvw}, 1]^T |
    $$
    where $\mathbf{m}_{2}$ is the third row (index 2) of the model-view matrix `glstate.matrix.modelview[0]` [S1].

    b. **Mipmap Level Selection:** Calculate the mipmap level $l$ based on the depth $z$, screen pixel size $S_0$, angular spread $\tan \Phi$, and finest voxel size $v_0$ [S1]:
    $$
    l = \text{median}(0, L_{max}, \lfloor \log_2 \left( \frac{S_0 + 2 \tan \Phi \cdot z}{v_0} \right) \rfloor)
    $$
    where $L_{max}$ is the maximum available mipmap level [S1]. This selects the coarsest level with a sufficiently small voxel size for the current depth [S1].

    c. **Volume Sampling:** Sample the 3D texture at $\mathbf{uvw}$ using the computed mipmap level $l$ via the `tex3Dlod` intrinsic (or equivalent hardware function) [S1]. Let the result be $\mathbf{g}_{gggv}$ [S1].
    *   The gradient is extracted from the RGB channels.
    *   The scalar value is extracted from the Alpha channel [S1].

    d. **Classification and Shading:** Apply the transfer function (using the 1D LUT) and shading model (e.g., Phong using the precomputed gradient) to the sampled data to obtain the color $\mathbf{C}_i$ and opacity $\alpha_i$ for the current step [S1]. *Note: The specific implementation of this step is omitted in the source code but is required for the compositing equation* [S1].

    e. **Compositing:** Update the accumulated color and opacity using the front-to-back over operator [S1]:
    $$
    \mathbf{I} = \mathbf{I} + (1.0 - a) \mathbf{C}_i
    $$
    $$
    a = a + (1.0 - a) \alpha_i
    $$

    f. **Stepping:** Advance the position along the ray:
    $$
    \mathbf{uvw} = \mathbf{uvw} + \Delta \mathbf{dir}
    $$

7.  **Output:** Return the accumulated color and opacity as the fragment output [S1].

### Pseudocode
The following pseudocode implements the core ray casting loop described in the source [S1]. It assumes helper functions `clip_to_unit_box`, `mipmap_value`, and transfer function application are available.

```python
# Uniforms
Ew: float3          # Projector position
Vd: float           # Virtual observer distance
Vh: float           # Virtual observer height
log2V: float        # log2(voxel_size)
DL: float           # Step size
S0: float           # Screen pixel size
tanPhi: float       # Angular spread factor
mv_inv: float4x4    # Inverse model-view matrix
a_max: float        # Opacity threshold

# Structures
struct Ray:
    org: float3
    dir: float3
    len: float

def compute_ray(x: float, y: float) -> Ray:
    # 1. Compute ray origin and direction in world coordinates
    # Note: Source uses float4 with w=0 for direction to ignore translation
    ray_o_world = float4(x, y, 0, 0)
    ray_d_world = float4(-(Ew.x - x) / Ew.z, (Vh - y) / Vd, -1, 0)
    
    # 2. Transform to texture coordinates
    tex_o = mul(mv_inv, ray_o_world).xyz
    tex_e = mul(mv_inv, ray_o_world + ray_d_world).xyz
    
    # 3. Normalize direction and clip to unit box
    dir_norm = normalize(tex_e - tex_o)
    t_min, t_max = clip_to_unit_box(tex_o, dir_norm)
    
    ray_len = t_max - t_min
    if ray_len < epsilon:
        return None # Discard fragment
        
    ray_org = tex_o + dir_norm * t_min
    return Ray(org=ray_org, dir=dir_norm, len=ray_len)

def fragment_shader(screen_x: float, screen_y: float) -> float4:
    ray = compute_ray(screen_x, screen_y)
    if ray is None:
        discard()
        
    # 4. Initialize compositing
    delta_dir = ray.dir * DL
    N = int(ray.len / DL)
    uvw = ray.org
    I = float3(0, 0, 0)
    a = 0.0
    
    # 5. Ray Marching Loop
    for i in range(N):
        if a >= a_max:
            break
            
        # Compute depth z for mipmap selection
        # Using the third row of the model-view matrix
        z = abs(dot(mv_inv[2], float4(uvw, 1.0)))
        
        # Compute mipmap level
        # median(0, Lmax, floor(log2((S0 + 2*tanPhi*z)/v0)))
        # v0 = 2^log2V
        voxel_ratio = (S0 + 2 * tanPhi * z) / (2 ** log2V)
        l = median(0, L_max, floor(log2(voxel_ratio)))
        
        # Sample volume
        # gggv contains gradient (RGB) and scalar (A)
        gggv = mipmap_value(uvw, l)
        
        # Apply Transfer Function and Shading
        # C_i and a_i are derived from gggv and the 1D LUT
        C_i, a_i = apply_transfer_and_shading(gggv)
        
        # Front-to-Back Compositing
        I = I + (1.0 - a) * C_i
        a = a + (1.0 - a) * a_i
        
        # Step
        uvw = uvw + delta_dir
        
    return float4(I, a)
```

### Parameters and Typical Values
*   **Proxy Tessellation:** 8x8 quads [S1].
*   **Step Size (DL):** Adjusted for performance; typically doubled during interaction to lower sampling rate [S1].
*   **Screen Pixel Size (S0):** Determined by display resolution [S1].
*   **Angular Spread (tanPhi):** Determined by the light field display's optical properties [S1].
*   **Voxel Size (v0):** Determined by the volume dataset resolution [S1].

### Edge Cases and Pitfalls
*   **Vertex Attribute Interpolation Error:** Standard fixed-function pipeline interpolation does not produce correct per-pixel ray parameter values for MCOP projections because the projection cannot be recast into a traditional homogeneous matrix [S1]. This is mitigated by using the coarse proxy geometry and computing projections in the vertex shader [S1].
*   **Tile Misalignment:** If the object is moved with a refresh rate slower than the projector batch update rate (16 projectors per batch), misalignment artifacts between tiles become visible [S1].
*   **Out of Bounds:** If the clipped ray length is less than epsilon, the fragment is discarded [S1].
*   **Performance:** The method requires millions of rays to be propagated for hundreds of steps. Interactive frame rates are maintained by reducing pixel count (e.g., 2.5mm precision) and doubling the integration step size [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Time Complexity:** $O(P \cdot N)$, where $P$ is the number of pixels (projectors) and $N$ is the number of samples per ray. The number of samples $N$ is determined by the volume depth and step size $DL$ [S1].
*   **Memory Complexity:** $O(V)$ for the volume texture, where $V$ is the number of voxels, plus $O(L)$ for the mipmap pyramid and 1D LUT [S1].

### Measured Performance
*   The method was tested on a light field display with 96 projectors [S1].
*   At full resolution (1 ray/pixel, 1 sample/voxel), performance is limited by the single GPU's ability to handle millions of rays [S1].
*   Interactive frame rates are achieved by lowering the sampling rate (reducing pixel count and increasing step size) [S1].

### Strengths and Limitations
*   **Strengths:**
    *   Provides a fully continuous perceived image, unlike discrete multiview technologies [S1].
    *   Correctly handles parallax and registration between object space and physical space [S1].
    *   GPU-accelerated using standard graphics pipeline components (with custom shaders) [S1].
*   **Limitations:**
    *   Performance is constrained by the number of projectors and rays [S1].
    *   Tile misalignment artifacts can occur during slow object movement [S1].
    *   Requires precomputed gradients in the volume texture [S1].

## Background

### Origin and History
The method was introduced by Agus et al. in 2008 in the paper "GPU Accelerated Direct Volume Rendering on an Interactive Light Field Display" [S1]. It was developed to address the limitations of existing multiview 3D displays, which forced users into fixed positions due to abrupt view changes [S1]. The work builds on the MCOP (Multi-Camera Optical Projection) framework [S1].

### Usage
The method is used for interactive direct volume rendering on light field displays, allowing multiple users to view 3D volumetric data (e.g., medical scans, simulations) with natural motion parallax and accommodation cues [S1]. It has been demonstrated with datasets such as the Chameleon, Visible Human head, and rotational angiography data [S1].
