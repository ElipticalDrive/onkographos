# GPU Ray Casting for Light Field Display

Also called: Direct Volume Rendering on Light Field Display, Interactive Light Field Volume Rendering, MCOP Ray Casting with Adaptive Mipmap Level Selection, MCOP projection, Multi-viewer 3D Volume Rendering

## Overview
This method accelerates direct volume rendering for interactive light field displays by computing per-pixel ray parameters via Multi-Camera Optical Projection (MCOP) in the vertex shader, avoiding interpolation errors inherent in standard fixed-function pipelines [S1]. It differs from sibling methods by targeting the specific geometry of projector-based light field displays, using a proxy geometry to correctly map screen pixels to volumetric rays and employing depth-dependent mipmap selection to maintain spatial resolution [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `Ew`: Projector position (uniform `float3`) [S1].
    *   `Vd`: Virtual observer distance (uniform `float`) [S1].
    *   `Vh`: Virtual observer height (uniform `float`) [S1].
    *   `log2V`: Log2 of the finest voxel size (uniform `float`) [S1].
    *   `DL`: Integration step size (uniform `float`) [S1].
    *   `S0`: Screen pixel size (uniform `float`) [S1].
    *   `tanPhi`: Angular spread factor (uniform `float`) [S1].
    *   `mv_inv`: Inverse model-view matrix (uniform `float4x4`) [S1].
    *   `Lmax`: Maximum available mipmap level [S1].
    *   `a_max`: Maximum opacity threshold for early termination (implementation detail, typically 1.0) [G].
    *   `Epsilon`: Minimum valid ray length [G].
    *   Volume texture: Single 4-component texture (`RGBA`). RGB channels store unscaled precomputed gradients; A channel stores voxel values [S1].
    *   Lookup table: 1D RGBA texture for transfer functions [S1].
*   **Outputs:**
    *   `fragment_out`: Struct containing `color` (`float4`) [S1].

**Data Structures:**
```c
struct ray_t {
    float3 org; // Ray origin in texture coordinates
    float3 dir; // Ray direction (normalized)
    float len;  // Integration length within the volume
};

struct fragment_out {
    float4 color; // Accumulated color and opacity

```

**Steps:**

1.  **Proxy Geometry Setup:** Use a coarsely tessellated proxy geometry (8x8 quads) representing a slightly enlarged bounding volume [S1]. Stream vertices through a vertex shader that performs MCOP projection [S1].
2.  **Ray Origin and Direction Computation:** In the fragment shader, receive the unnormalized projected screen position $S$ from the vertex stage [S1]. Compute the ray direction $d$ using MCOP projection parameterized by emitter $E$ and virtual viewer $V$ [S1]:
    $$ d = \left[ \frac{S_x - E_x}{E_z}, \frac{S_y - V_y}{V_z}, -1 \right] $$
    where $S$ is the screen pixel position in the display reference frame [S1].
3.  **Coordinate Transformation:** Transform the infinite ray defined by $S$ and $d$ into local volume coordinates (coincident with texture coordinates) by applying the world-to-texture homogeneous transform matrix (`mv_inv`) [S1].
4.  **Ray Clipping and Validation:** Clip the line against the unit box to compute the ray entry point and integration length. If the length is null (or less than epsilon), discard the fragment [S1].
5.  **Ray Marching Loop:** Step through the ray in a loop, performing volume resampling and compositing until the volume is exited or full opacity is reached [S1].
6.  **Mipmap Level Selection:** At each sampling step, compute the depth $z$ of the current sample in world space. Calculate the mipmap level $l$ to ensure the voxel size matches the spatial resolution at depth $z$ [S1].
7.  **Sampling and Compositing:** Sample the volume texture using the computed mipmap level. Apply transfer function and shading to obtain color $C_i$ and opacity $a_i$. Accumulate using front-to-back compositing [S1].

**Edge Cases and Pitfalls:**
*   **Vertex Attribute Interpolation Error:** Standard linear interpolation of vertex attributes does not produce correct per-pixel ray parameter values for MCOP projection. This is mitigated by computing projections in the vertex shader using the proxy geometry [S1].
*   **Tile Misalignment Artifacts:** On displays with 96 projectors updated in batches of 16, moving objects with a slow refresh rate can cause visible misalignment between tiles [S1].
*   **Ray Length Validation:** If the clipped ray length is less than epsilon, the fragment is discarded as it lies outside the volume bounds [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray ($N$) and the number of pixels. $N$ is determined by ray length divided by step size $DL$ [S1].
*   **Memory Complexity:** Dominated by the volume texture storage (4-component texture) and the mipmap pyramid [S1].
*   **Performance:** At full resolution (1 ray/pixel, 1 sample/voxel), millions of rays require hundreds of steps, limiting interactive frame rates [S1]. Performance is improved by lowering sampling rate (reducing pixel count to 2.5mm precision and doubling step size) during interaction [S1].
*   **Strengths:** Provides a fully continuous perceived image for multiple viewers, unlike discrete multiview technologies [S1]. Correctly handles parallax and registration between object space and physical space [S1].
*   **Limitations:** Single GPU performance bottleneck at high resolutions [S1]. Artifact-prone if refresh rate is too low relative to object motion [S1].

## Background
The method was introduced by Agus et al. in 2008 [S1]. It addresses the limitations of traditional multiview technologies that force users into fixed positions due to abrupt view-image changes when crossing discrete viewing zones [S1]. The approach leverages the MCOP (Multi-Camera Optical Projection) model to project rays from projector positions through screen pixels into the volume [S1].
