# CUDA GPU Implementation

Also called: CUDA Raycast Backend, cvc::volren CUDA backend

## Overview
The CUDA GPU Implementation is a direct volume ray casting method that offloads the per-ray sampling, classification, and compositing loop to the NVIDIA CUDA architecture, mirroring the semantic behavior of a reference CPU marcher while leveraging hardware acceleration for real-time performance [S1, unofficial]. It sets itself apart from CPU-based ray casting by utilizing the GPU's parallel thread architecture to significantly reduce computational complexity for intersection calculation, resampling, and compositing [S1, unofficial][S2, unofficial], and differs from generic hardware-accelerated approaches by explicitly decoupling ray traversal logic from the volume data structure to allow for adaptive algorithms and custom spatial indices [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric data (scalar field or SDF), transfer function (LUT), camera parameters, and rendering options (isosurface threshold, lighting model, cut planes).
*   **Output:** Final 2D image (color and depth) and optional accumulated opacity.

**Data Structures:**
*   **Volume Data:** Stored in device memory (texture or linear buffer). For SDF volumes, gradient computation uses de Boor splines [S1, unofficial].
*   **Transfer Function:** Baked Lookup Table (LUT) stored in device memory [S1, unofficial].
*   **Spatial Index:** A dynamic redundant octree (Guennebaud et al.) used for efficient neighbor sampling and adaptive traversal [S2, unofficial].
*   **Marching Cubes Tables:** `__constant__` memory storage for isosurface geometry, tracked per-device to avoid cross-GPU aliasing issues [S1, unofficial].
*   **Ray Stack:** A small stack stored in local memory to manage recursion for adaptive ray traversal [S2, unofficial].

**Parameters:**
*   **Block Size:** 16x16 threads per block [S1, unofficial].
*   **Ray Cap:** 32 hits per ray (historically documented as unreachable due to opacity cutoff, but implemented as a hard limit for DDA collection) [S1, unofficial].
*   **Isosurface Limit:** Up to 8 isosurfaces/lights/cut planes per scene [S1, unofficial].
*   **Volume Limit:** Exactly one volume per render in version 1 [S1, unofficial].
*   **Backend Selection:** `backend::cpu` (default), `backend::cuda` (demands GPU), `backend::automatic` (uses GPU if available, falls back silently) [S1, unofficial].
*   **Math Precision:** Compiled with `--use_fast_math` [S1, unofficial].

**Steps:**
1.  **Initialization:** Upload volume data and LUT from host to device (H2D) for each render pass [S1, unofficial]. Ensure CUDA error state is cleared before launch to prevent spurious fallbacks from previous unrelated errors [S1, unofficial].
2.  **Kernel Launch:** Launch one CUDA thread per pixel in 16x16 blocks [S1, unofficial].
3.  **Ray Generation:** Each thread computes ray parameters from camera matrices and determines entry/exit points via slab intersection [S1, unofficial].
4.  **Ray Traversal:**
    *   **Isosurface Path:** Use Amanatides-Woo DDA to traverse cells, enumerating every crossed cell to avoid silhouette holes [S1, unofficial].
    *   **General Path:** Implement either constant step size or adaptive algorithm. Adaptive recursion is managed via a local memory stack [S2, unofficial].
    *   **Neighbor Access:** Use the dynamic redundant octree to find neighbor samples efficiently [S2, unofficial].
5.  **Sampling:**
    *   Sample volume data using trilinear interpolation [S1, unofficial].
    *   Compute gradients using de Boor splines for SDF volumes [S1, unofficial].
6.  **Classification:**
    *   Apply transfer functions using the baked LUT [S1, unofficial].
    *   Apply gradient ramp, density window, and cut planes [S1, unofficial].
    *   Handle NaN corners correctly by using `std::min`/`std::max` semantics (keeping NaN accumulator) rather than `fminf`/`fmaxf` (which discard NaN) for corner min/max folds [S1, unofficial].
7.  **Compositing:**
    *   Perform front-to-back compositing on a per-cell basis [S1, unofficial].
    *   Update accumulated color $C'$ and opacity $\alpha'$:
        $$
        C'_{i} = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i
        $$
        $$
        \alpha'_{i} = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i
        $$
    *   Apply Blinn-Phong lighting model if enabled [S1, unofficial].
8.  **Depth Latch:** Store depth information for the final pixel [S1, unofficial].

**Pseudocode:**
```python
# CUDA Kernel: raycast_kernel
# Inputs: volume_data, lut, camera_params, isovalue, cut_planes
# Outputs: out_color, out_depth

__global__ void raycast_kernel(float* volume_data, float* lut, CameraParams cam, float isovalue, CutPlane* cut_planes, float4* out_color, float* out_depth) {
    // 1. Thread Indexing
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    
    // Check bounds
    if (x >= width || y >= height) return;

    // 2. Ray Generation
    Ray ray = generate_ray(cam, x, y);
    
    // 3. Slab Intersection
    float t_entry, t_exit;
    if (!intersect_slab(ray, volume_bounds, t_entry, t_exit)) {
        out_color[y * width + x] = make_float4(0, 0, 0, 0);
        return;
    }

    // 4. Ray Traversal & Compositing
    float acc_color_r = 0.0f, acc_color_g = 0.0f, acc_color_b = 0.0f, acc_alpha = 0.0f;
    float t = t_entry;
    float step_size = get_step_size(ray, t_entry, t_exit); // Constant or adaptive
    
    // Stack for adaptive traversal (local memory)
    // Stack is managed implicitly by recursion or explicit local array
    
    while (t < t_exit) {
        // 5. Sampling
        float3 pos = ray.origin + t * ray.direction;
        float density = sample_volume_trilinear(volume_data, pos);
        
        // Gradient computation for SDF
        float3 grad;
        if (is_sdf) {
            grad = compute_gradient_deboor(volume_data, pos);
        } else {
            grad = compute_gradient_trilinear(volume_data, pos);
        }

        // 6. Classification
        float alpha, color_r, color_g, color_b;
        
        // Isosurface check
        if (is_isosurface_mode) {
            // Amanatides-Woo DDA ensures all crossed cells are visited
            // Check if cell contains isosurface using correct NaN handling
            if (contains_isosurface(pos, isovalue)) {
                // Get color from LUT
                float4 tf = lookup_lut(lut, density);
                alpha = tf.a;
                color_r = tf.r;
                color_g = tf.g;
                color_b = tf.b;
                
                // Apply lighting (Blinn-Phong)
                float3 light_dir = normalize(light_position - pos);
                float3 view_dir = normalize(-ray.direction);
                float3 half_dir = normalize(light_dir + view_dir);
                float NdotH = max(0.0f, dot(normalize(grad), half_dir));
                float specular = pow(NdotH, shininess);
                
                color_r = color_r * diffuse + specular * specular_factor;
                color_g = color_g * diffuse + specular * specular_factor;
                color_b = color_b * diffuse + specular * specular_factor;
            } else {
                t += step_size;
                continue;
            }
        } else {
            // Standard DVF
            float4 tf = lookup_lut(lut, density);
            alpha = tf.a;
            color_r = tf.r;
            color_g = tf.g;
            color_b = tf.b;
            
            // Apply gradient ramp, density window, cut planes
            if (apply_cut_planes(pos, cut_planes)) {
                t += step_size;
                continue;
            }
        }

        // 7. Compositing (Front-to-Back)
        float weight = alpha * (1.0f - acc_alpha);
        acc_color_r += weight * color_r;
        acc_color_g += weight * color_g;
        acc_color_b += weight * color_b;
        acc_alpha += weight;

        // 8. Early Ray Termination
        if (acc_alpha > 0.95f) break;

        // Advance
        t += step_size;
    }

    // 9. Output
    out_color[y * width + x] = make_float4(acc_color_r, acc_color_g, acc_color_b, acc_alpha);
    out_depth[y * width + x] = t_exit; // Or depth latch value
}
```

## Subtopics

### [Slab-based Raycasting](11383-slab-based-raycasting.md)
Slab-based raycasting is a CUDA GPU optimization for direct volume rendering that caches sampled voxels in shared memory as "slabs" to improve performance when volume data is accessed multiple times, such as for gradient calculation in Phong lighting. It sets itself apart from basic raycasting by trading increased shared memory overhead and reduced early ray termination granularity for cache hits on repeated voxel access. Unlike hardware texture caches, which benefit from large viewports where adjacent rays hit the same voxels, the slab cache is most efficient when the data set resolution is high compared to the viewport size.

### [GPU-accelerated ray casting](12256-gpu-accelerated-ray-casting.md)
GPU-accelerated ray casting is a direct volume rendering method that offloads the per-ray sampling and integration loop to the graphics processor, enabling real-time interaction with volumetric datasets. It differs from CPU-based ray casting by leveraging the GPU's parallel architecture to significantly reduce computational complexity for intersection calculation, resampling, and compositing. As a standard image-order approach, it is embarrassingly parallel and supports numerous performance and quality enhancements.

### [Jittor Volume Render Cuvol Wrapper](15370-jittor-volume-render-cuvol-wrapper.md)
The Jittor Volume Render Cuvol Wrapper is a custom Jittor function that fuses the forward and backward passes of volume rendering into a single CUDA kernel launch sequence, managing memory aliases and gradient propagation for a sparse grid representation. It differs from standard CPU-based ray marchers by executing the core ray casting logic on the GPU via CUDA, while maintaining compatibility with Jittor's automatic differentiation engine. It builds on the [CUDA GPU Implementation](13016-cuda-gpu-implementation.md) by providing a high-level API that handles the integration of sparse grid data structures (offsets, scaling, links) into the CUDA kernels.

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** Linear with respect to the number of rays (pixels) and the number of samples per ray. The GPU implementation provides significant speedups over CPU counterparts due to massive parallelism [S1, unofficial].
*   **Memory:** Requires storage for the volume data, LUT, and spatial index (octree) in device memory. The octree allows for dynamic updates and control of memory footprint versus performance [S2, unofficial].

**Measured Performance:**
*   **Hardware:** NVIDIA GTX 1650 [S1, unofficial].
*   **Resolution:** 512x512 [S1, unofficial].
*   **Results:**
    *   Isosurface rendering: 160 ms (CPU) vs 65 ms (CUDA) [S1, unofficial].
    *   Shaded Transfer Function + Gradient Ramp + Cut Plane: 270 ms (CPU) vs 113 ms (CUDA) [S1, unofficial].
    *   Image Parity: 100% of pixels within 1 LSB with identical depth compared to CPU reference [S1, unofficial].
*   **Throughput:** 16.5 Mray/s at 640x360 resolution for a single bunny model [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** High performance for single-volume scenes; image-level parity with CPU reference; flexible traversal strategies (constant/adaptive); efficient neighbor access via octree [S1, unofficial][S2, unofficial].
*   **Limitations:** Version 1 is limited to a single volume; limited to 8 isosurfaces/lights/cut planes; requires GPU memory for H2D uploads per render; `__constant__` memory management requires per-device tracking [S1, unofficial].

**When to Use:**
*   Real-time interactive volume rendering on NVIDIA hardware.
*   Single-volume scenes with complex lighting or isosurface extraction.
*   When image-level parity with a CPU reference is required.

**When Not to Use:**
*   Multi-volume scenes (v1 limitation) [S1, unofficial].
*   Non-NVIDIA hardware.
*   Scenes requiring more than 8 isosurfaces/lights/cut planes [S1, unofficial].

## Background
The CUDA GPU Implementation was developed as part of the `libcvc` library, specifically within the `cvc::volren` module, to provide a high-performance alternative to CPU-based volume rendering [S1, unofficial]. It was introduced in pull request #323, which added the `cvcGL VolRenNode` and the `volren_bunny` demo [S1, unofficial]. The implementation mirrors the semantic behavior of the existing CPU marcher, ensuring visual consistency while leveraging CUDA for speed [S1, unofficial]. It builds on the principles of hardware-accelerated volume rendering, specifically utilizing the fragment shader-like parallelism of CUDA threads [S1, unofficial][S2, unofficial].
