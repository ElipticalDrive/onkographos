# GPU Ray Casting Pipeline

Also called: Basic GPU Ray Casting Pipeline, Front-to-Back GPU Ray Casting

## Overview
The GPU Ray Casting Pipeline is the foundational hardware-accelerated method for direct volume rendering, solving the problem of efficiently integrating volumetric data into a 2D image by offloading ray traversal and compositing to the graphics processing unit [S1, unofficial]. It differs from CPU-based approaches by leveraging massive parallelism to achieve real-time frame rates, which is mandatory for high-refresh-rate displays like the HTC Vive (90 Hz) . It builds on [GPU-accelerated ray casting](12256-gpu-accelerated-ray-casting.md) by explicitly defining the data flow between CPU-side texture preparation and GPU-side ray execution.

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric data sets (typically from CT and MRI images) [S1, unofficial].
*   **Output:** A final 2D image generated by the GPU [S1, unofficial].

**Data Structures:**
1.  **Volume Model:** The volumetric data is stored in a 3D texture on the GPU [S1, unofficial]. The CPU reads the original data set and builds this model [S1, unofficial].
2.  **Ray Definition:** Implicitly defined by the camera position and viewport geometry for each pixel.

**Optical and Illumination Models:**
*   **Optical Model:** The emission-absorption model is used to estimate the volume-rendering integral [S1, unofficial].
*   **Illumination Model:** The Blinn-Phong illumination model is used to approximate the scattering of light [S1, unofficial].

**Algorithm Steps:**
1.  **Data Preparation (CPU):** Read the original volumetric data set [S1, unofficial].
2.  **Texture Upload (CPU):** Build a volume model from the data and store it in a 3D texture [S1, unofficial].
3.  **Transfer:** Pass the 3D texture to the GPU [S1, unofficial].
4.  **Ray Casting (GPU):** Perform ray casting on the 3D texture to generate the final image [S1, unofficial]. This involves casting rays from the camera through the volume and accumulating color and opacity along each ray path using front-to-back compositing .

**Formulas:**
The rendering integral is estimated using the emission-absorption model [S1, unofficial]. The color $C$ and opacity $\alpha$ for a ray segment are accumulated. The illumination $L$ at a sample point is calculated using the Blinn-Phong model [S1, unofficial].

```python
# CPU Side
def prepare_volume(data_source):
    """
    Reads volumetric data (e.g., CT/MRI) and creates a 3D texture.
    """
    volume_model = build_3d_texture(data_source)
    return volume_model

def upload_to_gpu(volume_model):
    """
    Passes the 3D texture to the GPU memory.
    """
    gpu_texture = transfer_to_gpu(volume_model)
    return gpu_texture

# GPU Side (Fragment Shader Logic)
def gpu_ray_casting(gpu_texture, camera_params):
    """
    Performs ray casting on the 3D texture to generate the final image.
    Uses front-to-back compositing and Blinn-Phong illumination.
    """
    # For each pixel in the output buffer
    for pixel in output_buffer:
        ray = create_ray(camera_params, pixel)
        color = vec3(0.0)
        alpha = 0.0
        
        # Traverse the volume along the ray
        while ray_inside_volume(ray):
            sample_pos = ray_position(ray)
            density = sample_3d_texture(gpu_texture, sample_pos)
            
            # Calculate illumination using Blinn-Phong model
            # [S1, unofficial]
            light_color = blinn_phong_lighting(sample_pos, density)
            
            # Front-to-back compositing (Emission-Absorption Model)
            # [S1, unofficial]
            contribution = light_color * (1.0 - alpha)
            color += contribution
            alpha += (1.0 - alpha) * opacity_factor(density)
            
            ray_advance(ray)
            
        set_pixel_color(pixel, color)
```

## Subtopics

### [GPU-based Raycasting Rendering](14516-gpu-based-raycasting-rendering.md)
GPU-based raycasting renders volumetric datasets by casting rays from the camera through the volume on the GPU, accumulating color and opacity along each ray path. It differs from CPU-based raycasting by leveraging massive parallelism to achieve real-time frame rates, which is mandatory for high-refresh-rate displays like the HTC Vive (90 Hz). It builds on the [GPU Ray Casting Pipeline](14281-gpu-ray-casting-pipeline.md) by offloading the ray traversal and compositing steps to the graphics hardware.

### [GPU Raycasting for Stack-Based Terrains](15741-gpu-raycasting-for-stack-based-terrains.md)
GPU Raycasting for Stack-Based Terrains (SBRT) is a direct volume rendering technique adapted for geoscientific terrain data, implemented on the GPU to enable real-time visualization. It solves the problem of efficiently rendering complex, layered subsurface structures by casting rays from a virtual camera through each output buffer pixel and composing sampled colors along the ray path. What sets it apart from standard raycasting is its specific adaptation to the SBRT data structure, which uses a stack-based representation of geological intervals, and its hybrid deferred strategy for normal calculation to avoid the performance bottlenecks associated with 3D convolution on sparse stack data.
