# GPU-based Raycasting Rendering

Also called: GPU-accelerated volume ray casting, Hardware-accelerated direct volume rendering

## Overview
GPU-based raycasting renders volumetric datasets by casting rays from the camera through the volume on the GPU, accumulating color and opacity along each ray path [S2]. It differs from CPU-based raycasting by leveraging massive parallelism to achieve real-time frame rates, which is mandatory for high-refresh-rate displays like the HTC Vive (90 Hz) [S2]. It builds on the [GPU Ray Casting Pipeline](14281-gpu-ray-casting-pipeline.md) by offloading the ray traversal and compositing steps to the graphics hardware.

## How it works
**Inputs:**
*   Volumetric dataset (scalar field).
*   Transfer functions (mapping scalar values to color and opacity).
*   Camera parameters (position, orientation, projection).
*   Pre-computed gradient data (optional, see optimization).

**Outputs:**
*   Final image (color and alpha per pixel).

**Data Structures:**
*   **Volume Texture:** 3D texture storing scalar values.
*   **Gradient Texture:** 3D RGBA texture storing pre-computed gradients. Each voxel stores gradient direction and magnitude [S2].
*   **Transfer Function Texture:** 1D or 2D texture mapping scalar values to RGBA [S1, unofficial].

**Steps:**
1.  **Ray Generation:** For each pixel in the viewport, generate a ray originating from the camera position and passing through the pixel center in world space [S2].
2.  **Ray-Volume Intersection:** Determine the entry and exit points of the ray with the volume bounding box.
3.  **Step Size Calculation:** Determine the step size along the ray. This may be fixed or adaptive based on resolution and desired accuracy.
4.  **Sampling Loop:**
    a.  Sample the volume texture at the current ray position to get the scalar value $v$.
    b.  Sample the transfer function using $v$ to get color $c$ and opacity $\alpha$.
    c.  If pre-computed gradients are used, sample the gradient texture at the current position to get $\nabla v$. Otherwise, compute gradients on-the-fly using finite differences (requires 6 extra texture fetches) [S2].
    d.  **Compositing:** Update the accumulated color $C_{acc}$ and opacity $A_{acc}$ using front-to-back compositing:
        $$ C_{acc} = C_{acc} + c \cdot \alpha \cdot (1 - A_{acc}) $$
        $$ A_{acc} = A_{acc} + \alpha \cdot (1 - A_{acc}) $$
    e.  Advance the ray position by the step size.
    f.  If $A_{acc} \geq 1$ or the ray has exited the volume, terminate the loop.
5.  **Post-Processing:** Apply any final image processing (e.g., tone mapping, anti-aliasing).

**Parameters:**
*   **Step Size:** Determines sampling density. Smaller steps increase accuracy but reduce performance.
*   **Gradient Pre-computation:** Trade-off between memory usage and computational cost. Pre-computing gradients saves texture fetches but increases memory bandwidth requirements [S2].

**Edge Cases and Pitfalls:**
*   **Overlapping Material Ranges:** When transfer functions for different materials have overlapping scalar ranges, the color contribution should be set as the average of the non-transparent materials for the sample, rather than a sum [S1, unofficial].
*   **Precision:** Floating-point precision errors can accumulate during ray traversal, especially for long rays.
*   **Boundary Conditions:** Ensure correct handling of rays that do not intersect the volume or intersect only at the boundary.

**Pseudocode:**
```python
def gpu_ray_casting(volume_tex, gradient_tex, tf_tex, camera, viewport):
    # Initialize output image
    image = zeros(viewport.width, viewport.height, 4)
    
    for y in range(viewport.height):
        for x in range(viewport.width):
            # Generate ray
            ray_origin, ray_direction = camera.generate_ray(x, y, viewport)
            
            # Intersect with volume bounding box
            t_min, t_max = intersect_bbox(ray_origin, ray_direction, volume_bbox)
            
            if t_min > t_max:
                image[y, x] = background_color
                continue
                
            # Initialize accumulation
            acc_color = vec3(0.0)
            acc_alpha = 0.0
            
            # Step along ray
            t = t_min
            while t < t_max and acc_alpha < 1.0:
                # Sample volume
                v = volume_tex.sample(ray_origin + t * ray_direction)
                
                # Sample transfer function
                c, alpha = tf_tex.sample(v)
                
                # Sample gradient (if pre-computed)
                if use_precomputed_gradients:
                    grad = gradient_tex.sample(ray_origin + t * ray_direction)
                else:
                    # Compute gradient on-the-fly (6 texture fetches)
                    grad = compute_gradient_on_fly(volume_tex, ray_origin + t * ray_direction)
                
                # Compositing
                weight = alpha * (1.0 - acc_alpha)
                acc_color += c * weight
                acc_alpha += weight
                
                # Advance ray
                t += step_size
                
            image[y, x] = vec4(acc_color, acc_alpha)
            
    return image
```

## Subtopics

### Reduced Viewport Rendering
Renders the volume at a lower resolution viewport and scales the result up to the target display resolution using interpolation to reduce computational cost [S2]. It differs from full-resolution raycasting by trading spatial resolution for performance; effective because raycasting is a screen-space algorithm [S2]. Used in Unity 3D VR systems for HTC Vive to achieve real-time rendering at 90 fps, allowing comfortable movement without motion sickness [S2].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is the average number of samples per ray.
*   **Memory Complexity:** $O(V)$, where $V$ is the volume of the dataset, plus additional memory for pre-computed gradients if used [S2].
*   **Performance:** Achieves real-time frame rates (e.g., 90 fps) on modern GPUs, which is essential for VR applications [S2].
*   **Strengths:** High parallelism, real-time capability, flexible transfer functions.
*   **Limitations:** High memory bandwidth usage, especially with on-the-fly gradient computation or pre-computed gradients [S2]. Performance degrades with large step sizes or complex transfer functions.
*   **When to Use:** Real-time visualization of volumetric data, especially in VR/AR environments [S2].
*   **When Not to Use:** When high spatial resolution is critical and performance is not a constraint, or when memory bandwidth is severely limited.

## Background
GPU-based raycasting has become the standard for real-time volume visualization due to the parallel architecture of GPUs [S2]. It was originally developed to overcome the performance limitations of CPU-based raycasting. The technique has been widely adopted in medical imaging, scientific visualization, and VR/AR applications [S1, unofficial][S2].
