# GPU Ray Casting Pipeline

Also called: CUDA-based Ray-casting

## Overview
The GPU Ray Casting Pipeline is a hardware-accelerated direct volume rendering method that offloads ray traversal and front-to-back compositing to the graphics processing unit to generate a 2D image from volumetric data [S2, unofficial]. It differs from CPU-based implementations by leveraging massive parallelism to achieve real-time frame rates [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric data sets (typically from CT and MRI images) [S2, unofficial].
*   **Output:** A final 2D image generated by the GPU [S2, unofficial].

**Data Structures:**
1.  **Volume Model:** The volumetric data is stored in a 3D texture on the GPU [S2, unofficial]. The CPU reads the original data set and builds a volume model stored in a 3D texture [S2, unofficial].
2.  **Ray Definition:** Implicitly defined by the camera position and viewport geometry for each pixel [G].

**Optical and Illumination Models:**
*   **Optical Model:** The emission-absorption model is used to estimate the volume-rendering integral [S2, unofficial].
*   **Illumination Model:** The Blinn-Phong illumination model is used to approximate the scattering of light [S2, unofficial].

**Algorithm Steps:**
1.  **Data Preparation (CPU):** Read the original volumetric data set [S2, unofficial].
2.  **Texture Upload (CPU):** Build a volume model from the data and store it in a 3D texture [S2, unofficial].
3.  **Transfer:** Pass the 3D texture to the GPU [S2, unofficial].
4.  **Ray Casting (GPU):** Perform ray casting on the 3D texture to generate the final image [S2, unofficial]. This involves casting rays from the camera through the volume and accumulating color and opacity along each ray path using front-to-back compositing [S2, unofficial].

**Formulas:**
The rendering integral is estimated using the emission-absorption model [S2, unofficial]:
$$C = \int_{t_0}^{t_1} c(t) e^{-\int_{t_0}^t \alpha(\tau) d\tau} dt$$
where $c(t)$ is the emitted color and $\alpha(t)$ is the absorption coefficient at position $t$ [S2, unofficial]. Discretized with step size $\Delta t$, the front-to-back compositing updates are:
$$C_{out} = C_{in} + c_i (1 - \alpha_{in})$$
$$\alpha_{out} = \alpha_{in} + \alpha_i (1 - \alpha_{in})$$
where $\alpha_i = 1 - e^{-\alpha(t_i) \Delta t}$ is the segment opacity [G]. The illumination $L$ at a sample point is calculated using the Blinn-Phong model [S2, unofficial]:
$$L = k_a I_a + \sum k_d I_d \max(0, \mathbf{n} \cdot \mathbf{l}) + k_s I_s (\mathbf{r} \cdot \mathbf{v})^p$$
where $\mathbf{n}$ is the surface normal, $\mathbf{l}$ is the light direction, $\mathbf{v}$ is the view direction, and $\mathbf{r}$ is the reflection vector [G].

**Pseudocode:**
```python
def gpu_ray_casting_pipeline(volume_data, camera_origin, ray_directions, res_x, res_y, step_size):
    # volume_data: 3D array of shape (Dx, Dy, Dz) with values in [0, 1]
    # camera_origin: (ox, oy, oz)
    # ray_directions: 2D list of (dx, dy, dz) for each pixel
    # res_x, res_y: integer dimensions
    # step_size: float distance between samples
    output_color = [[vec3(0.0) for _ in range(res_x)] for _ in range(res_y)]
    output_alpha = [[0.0 for _ in range(res_x)] for _ in range(res_y)]

    for y in range(res_y):
        for x in range(res_x):
            ray_o = camera_origin
            ray_d = normalize(ray_directions[y][x])
            color = vec3(0.0)
            alpha = 0.0
            t = 0.0

            while t < 1000.0:
                # Ray position in world space
                pos = (ray_o[0] + t * ray_d[0], ray_o[1] + t * ray_d[1], ray_o[2] + t * ray_d[2])

                # Boundary check (assuming volume occupies [0, 1]^3)
                if not (0.0 <= pos[0] < 1.0 and 0.0 <= pos[1] < 1.0 and 0.0 <= pos[2] < 1.0):
                    break

                # Tri-linear interpolation to get density
                density = tri_linear_sample(volume_data, pos)

                # Segment opacity via Beer-Lambert law
                alpha_seg = 1.0 - exp(-density * step_size)

                # Gradient for normal estimation
                grad = compute_gradient(volume_data, pos)
                normal = normalize(grad)
                view_dir = normalize((-ray_d[0], -ray_d[1], -ray_d[2]))
                light_dir = normalize((0.5, 1.0, 0.3))
                half_vec = normalize((light_dir[0] + view_dir[0], light_dir[1] + view_dir[1], light_dir[2] + view_dir[2]))
                diff = max(dot(normal, light_dir), 0.0)
                spec = pow(max(dot(normal, half_vec), 0.0), 32.0)
                color_seg = vec3(0.8, 0.8, 0.8) * (0.2 + 0.6 * diff + 0.2 * spec)

                # Front-to-back compositing
                weight = alpha_seg * (1.0 - alpha)
                color = color + color_seg * weight
                alpha = alpha + weight

                if alpha >= 0.99:
                    break

                t += step_size

            output_color[y][x] = color
            output_alpha[y][x] = alpha
    return output_color, output_alpha

def tri_linear_sample(data, p):
    ix, iy, iz = p[0] * (data.shape[0]-1), p[1] * (data.shape[1]-1), p[2] * (data.shape[2]-1)
    x0, y0, z0 = floor(ix), floor(iy), floor(iz)
    x1, y1, z1 = x0+1, y0+1, z0+1
    dx, dy, dz = ix-x0, iy-y0, iz-z0
    def v(x, y, z): return data[min(x, data.shape[0]-1)][min(y, data.shape[1]-1)][min(z, data.shape[2]-1)]
    c00 = v(x0, y0, z0) * (1-dx) + v(x1, y0, z0) * dx
    c10 = v(x0, y1, z0) * (1-dx) + v(x1, y1, z0) * dx
    c01 = v(x0, y0, z1) * (1-dx) + v(x1, y0, z1) * dx
    c11 = v(x0, y1, z1) * (1-dx) + v(x1, y1, z1) * dx
    return c00 * (1-dy) * (1-dz) + c10 * dx * (1-dy) * (1-dz) + c01 * (1-dy) * dz + c11 * dx * (1-dy) * dz

def compute_gradient(data, p):
    eps = 0.001
    def v(x, y, z): return data[min(max(floor(x*(data.shape[0]-1)),0), data.shape[0]-1)][min(max(floor(y*(data.shape[1]-1)),0), data.shape[1]-1)][min(max(floor(z*(data.shape[2]-1)),0), data.shape[2]-1)]
    gx = v(p[0]+eps, p[1], p[2]) - v(p[0]-eps, p[1], p[2])
    gy = v(p[0], p[1]+eps, p[2]) - v(p[0], p[1]-eps, p[2])
    gz = v(p[0], p[1], p[2]+eps) - v(p[0], p[1], p[2]-eps)
    return (gx, gy, gz)

def normalize(v):
    l = sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    return (v[0]/l, v[1]/l, v[2]/l) if l > 0 else (0,0,0)

def dot(a, b): return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]
def vec3(r, g, b): return (r, g, b)
def floor(x): return int(x) if x >= 0 else int(x) - 1
def exp(x): return math.exp(x)
def sqrt(x): return math.sqrt(x)
def pow(x, n): return x**n
def max(a, b): return a if a > b else b
import math
```

## Subtopics

### [GPU-based Raycasting Rendering](14516-gpu-based-raycasting-rendering.md)
GPU-based raycasting renders volumetric datasets by casting rays from the camera through the volume on the GPU, accumulating color and opacity along each ray path. It differs from CPU-based raycasting by leveraging massive parallelism to achieve real-time frame rates, which is mandatory for high-refresh-rate displays like the HTC Vive (90 Hz). It builds on the [GPU Ray Casting Pipeline](14281-gpu-ray-casting-pipeline.md) [G].

### [GPU Raycasting for Stack-Based Terrains](15741-gpu-raycasting-for-stack-based-terrains.md)
GPU Raycasting for Stack-Based Terrains (SBRT) is a direct volume rendering technique adapted for geoscientific terrain data, implemented on the GPU to enable real-time visualization. It solves the problem of efficiently rendering complex, layered subsurface structures by casting rays from a virtual camera through each output buffer pixel and composing sampled colors along the ray path. What sets it apart from standard raycasting is its specific adaptation to the SBRT data structure, which uses a stack-based representation of geological intervals, and its hybrid deferred strategy for normal calculation to avoid the performance bottlenecks associated with 3D convolution on sparse stack data.
