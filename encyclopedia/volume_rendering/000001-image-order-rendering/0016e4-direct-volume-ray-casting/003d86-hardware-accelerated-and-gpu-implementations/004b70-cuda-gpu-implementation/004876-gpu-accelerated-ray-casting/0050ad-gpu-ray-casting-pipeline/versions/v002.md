# GPU Ray Casting Pipeline
Also called: Basic GPU Ray Casting Pipeline, Front-to-Back GPU Ray Casting

## Overview
The GPU Ray Casting Pipeline is the fundamental hardware-accelerated method for direct volume rendering, mapping volumetric data to a 2D image by casting rays from a virtual camera through a 3D texture [S1, unofficial]. It solves the problem of efficiently evaluating the volume rendering integral on the GPU by leveraging texture hardware for trilinear interpolation and fragment shaders for front-to-back compositing [S1, unofficial]. It sets itself apart from CPU-based ray casting by utilizing parallel fragment processing and from ray marching by relying on fixed-function 3D texture sampling rather than explicit step-size control in shader loops [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volumetric data set (e.g., from CT or MRI images) [S1, unofficial].
*   **Output:** A final 2D image (color buffer) [S1, unofficial].

**Data Structures:**
*   **Volume Model:** The input data is converted into a 3D texture stored in GPU memory [S1, unofficial].
*   **Ray Definition:** Defined by camera position and direction for each pixel.

**Algorithm Steps:**
1.  **CPU Preprocessing:** The CPU reads the original volumetric data set and constructs a volume model [S1, unofficial].
2.  **Texture Upload:** The volume model is stored in a 3D texture and passed to the GPU [S1, unofficial].
3.  **Ray Casting (GPU):** The GPU performs ray casting on the 3D texture to generate the final image [S1, unofficial]. This involves:
    *   For each pixel, casting a ray through the volume.
    *   Sampling the 3D texture along the ray path.
    *   Compositing the samples using the front-to-back compositing scheme [S1, unofficial].
    *   Estimating the volume-rendering integral using the emission-absorption model [S1, unofficial].
    *   Approximating light scattering using the Blinn-Phong illumination model [S1, unofficial].

**Formulas:**
*   **Emission-Absorption Model:** The color $C$ and opacity $\alpha$ are accumulated along the ray. For a sample $i$ with color $c_i$, opacity $\alpha_i$, and transmittance $T_i$:
    $$ C = \sum_{i} c_i \cdot \alpha_i \cdot T_i $$
    $$ T_{i+1} = T_i \cdot (1 - \alpha_i) $$
    $$ T_0 = 1 $$
    (Derived from [S1, unofficial] description of emission-absorption model and front-to-back compositing).
*   **Blinn-Phong Illumination:** Used to approximate scattering of light for the color $c_i$ [S1, unofficial]. Standard Blinn-Phong formula applies:
    $$ c_i = k_a I_a + k_d I_d (\mathbf{n} \cdot \mathbf{l}) + k_s I_s (\mathbf{r} \cdot \mathbf{v})^n $$
    Where $\mathbf{n}$ is the normal, $\mathbf{l}$ is the light direction, $\mathbf{v}$ is the view direction, and $\mathbf{r}$ is the reflection vector [S1, unofficial].

**Parameters:**
*   **Data Source:** CT and MRI images [S1, unofficial].
*   **Optical Model:** Emission-absorption [S1, unofficial].
*   **Illumination Model:** Blinn-Phong [S1, unofficial].

**Pitfalls:**
*   **Overlapping Material Ranges:** When materials have overlapping ranges, the color should be set as the average of the non-transparent materials for the sample, rather than a sum [S2, unofficial].

## Subtopics

### GPU-based Raycasting Rendering
A variant focusing on the general implementation of raycasting on GPU architectures, emphasizing the use of fragment shaders for parallel processing of rays [S1, unofficial]. It differs from CPU-based approaches by offloading the heavy computation of ray traversal and compositing to the GPU's parallel cores [S1, unofficial]. It is chosen when real-time performance is required for large volumetric datasets [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the number of samples per ray ($O(P \cdot S)$), where $P$ is the number of pixels and $S$ is the number of samples along the ray [S1, unofficial].
*   **Memory Complexity:** Linear with respect to the volume of the 3D texture ($O(V)$) [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** High parallelism on GPU; efficient texture sampling; real-time potential [S1, unofficial].
*   **Limitations:** Memory bandwidth bound for large volumes; fixed step size may lead to aliasing or inefficiency [S1, unofficial].
*   **When to use:** Real-time visualization of CT/MRI data [S1, unofficial].
*   **When not to use:** When adaptive step sizes or complex ray marching logic is required beyond simple texture sampling [S1, unofficial].

## Background
The method originates from the basic rendering pipeline for visualizing volume models using a GPU version of the ray casting process [S1, unofficial]. It was proposed in the context of a thesis on enhanced perception in volume visualization, aiming to familiarize readers with different topics in visualization [S1, unofficial]. The approach uses the front-to-back compositing scheme and is based on volumetric data sets from CT and MRI images [S1, unofficial]. It is used in medical visualization and scientific visualization [S1, unofficial].
