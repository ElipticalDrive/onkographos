# Mask Type Configuration

Also called: Mask Type Selection, SetMaskTypeToBinary, SetMaskTypeToLabelMap

## Overview
Configures the masking strategy for the [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) by assigning an internal integer field to either a binary or label map mode [S1, unofficial][S2, unofficial]. It determines how the mapper interprets the mask volume during ray casting [S1, unofficial][S2, unofficial]. This configuration is a direct property of the mapper's internal state, distinct from post-processing or composite blend operations [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: An integer constant representing the target mask type (`BinaryMaskType` or `LabelMapMaskType`).
- Output: The `MaskType` member variable of the mapper instance is updated.

**Data Structures:**
The mapper stores the configuration in an integer field named `MaskType` [S1, unofficial][S2, unofficial]. The valid constants are `BinaryMaskType` and `LabelMapMaskType` [S1, unofficial][S2, unofficial].

**Steps:**
1. Obtain a reference to the `vtkGPUMultiVolumeRayCastMapper` instance [S1, unofficial][S2, unofficial].
2. Assign the target mask type constant to the instance's `MaskType` field [S1, unofficial][S2, unofficial].

**Pseudocode:**
```python
# Constants representing the mask types as defined in the mapper
BinaryMaskType = 0
LabelMapMaskType = 1

def configure_mask_type(mapper_mask_type_field, mask_type_value):
    mapper_mask_type_field = mask_type_value
    return mapper_mask_type_field
```

**Parameters:**
- `MaskType`: Integer field storing the active mask interpretation mode [S1, unofficial][S2, unofficial].
- `BinaryMaskType`: Enum constant for binary masking [S1, unofficial][S2, unofficial].
- `LabelMapMaskType`: Enum constant for label map masking [S1, unofficial][S2, unofficial].

**Edge Cases and Pitfalls:**
- The mask volume data must be supplied via `SetTransformedInput` or `SetTransformedInput2` prior to rendering [S1, unofficial][S2, unofficial].
- Changing `MaskType` after rendering begins may require internal state invalidation, though the exact invalidation mechanism is not specified in the sources [S1, unofficial][S2, unofficial].
- Assigning an integer value outside the defined enumeration constants is not validated by the sources [S1, unofficial][S2, unofficial].

## Subtopics

### [8-bit Packed Volumetric Masking](16604-8-bit-packed-volumetric-masking.md)
Stores voxel-level visibility masks as 8-bit packed boolean arrays to avoid duplicating scalar volume data. Maps XYZ coordinates directly to boolean visibility, allowing independent transformation of the mask relative to the volume. Choose this when memory overhead of traditional masking is a constraint.

## Operating characteristics
- Time Complexity: Not given in the sources.
- Memory Complexity: Not given in the sources.
- Strengths: Provides a direct configuration switch for masking semantics without modifying the core ray casting pipeline [S1, unofficial][S2, unofficial].
- Limitations: Lacks documented performance metrics or memory overhead comparisons between binary and label map modes [S1, unofficial][S2, unofficial].
- When to use: When the rendering pipeline requires a quick toggle between binary and label map masking interpretations [S1, unofficial][S2, unofficial].
- When not to use: When detailed performance profiling or custom mask blending logic is required [S1, unofficial][S2, unofficial].

## Background
This configuration method originates from the VTK (Visualization Toolkit) `vtkGPUMultiVolumeRayCastMapper` class, which implements GPU-accelerated volume ray casting for multiple volumes [S1, unofficial][S2, unofficial]. It provides a programmatic interface to switch between binary and label map masking strategies during the rendering pipeline setup [S1, unofficial][S2, unofficial].
