# Raymarching with 3D Volume Texture

Also called: 3D Texture Raycasting, 3D texture raymarching, Ray tracing through 3D mesh, RayMarchedAtlasVolume, Wolfenstein-style 3D raycasting

## Overview
This method renders volumetric data by storing the voxel space in a GPU 3D texture (`sampler3D`) and performing raycasting directly in the fragment shader [S1, S2, unofficial]. It replaces 2D texture atlases with a single 3D volume texture, enabling larger XYZ volumes and sharing the in-memory representation with path-tracing and isosurface modes [S2, unofficial]. Unlike meshing methods that require building and uploading geometry, it avoids the overhead of many draw calls by rendering a single screen-covering quad [S1, unofficial].

## How it works
### Inputs and Outputs
*   **Input:** A 3D volume texture containing voxel intensities (up to 4 channels), a 2D lookup table (LUT) texture for color/alpha reconstruction, camera parameters (near/far planes, eye direction), and volume scaling parameters.
*   **Output:** A 2D image where each pixel represents the accumulated color and alpha of the ray passing through the volume.

### Data Structures
**3D Volume Texture (`volumeTexture`)**
*   **Type:** `Data3DTexture` (WebGL2 required) [S2, unofficial].
*   **Precision:** 8-bit [S2, unofficial].
*   **Layout:** The CPU-side data buffer is laid out as `data[i + ix * 4 + iy * 4 * sx + iz * 4 * sx * sy]`, where `i` is the channel index (0-3), `ix, iy, iz` are coordinates, and `sx, sy` are width and height [S2, unofficial].

**Lookup Table Texture (`gLutTexture`)**
*   **Type:** `DataTexture` (2D) [S2, unofficial].
*   **Dimensions:** 256x4 [S2, unofficial].
*   **Purpose:** Combined LUT for up to 4 active channels, used to reconstruct color and alpha from sampled intensity [S2, unofficial].

**Uniforms**
*   `volumeTexture`: `sampler3D` [S2, unofficial].
*   `gLutTexture`: `sampler2D` [S2, unofficial].
*   `gNChannels`: `int`, number of active channels (up to 4) [S2, unofficial].
*   `BREAK_STEPS`: `float/int`, base number of steps [S2, unofficial].
*   `volumeScale`: `vec3`, scaling factor for volume dimensions [S2, unofficial].
*   `SLICES`: `float`, number of slices (depth) in the volume [S2, unofficial].
*   `maskAlpha`: `float`, mask transparency (currently unused in shader but set in CPU code) [S2, unofficial].
*   `CLIP_NEAR`, `CLIP_FAR`: `float`, near and far clipping planes [S2, unofficial].
*   `eye_d`: `vec3`, eye direction vector [S2, unofficial].

### Algorithm Steps
1.  **Setup:** Render a single quad covering the screen using one `glDraw` call [S1, unofficial].
2.  **Ray Initialization (Vertex/Fragment Shader):**
    *   Calculate the ray direction `eye_d` based on camera projection [S2, unofficial].
    *   Compute the scaled step count:
        $$ \text{scaledSteps} = \text{BREAK\_STEPS} \times \left\| \frac{\text{eye\_d.xyz}}{\text{volumeScale}} \right\| $$
    *   Clamp the steps to the valid range:
        $$ \text{csteps} = \text{clamp}(\text{scaledSteps}, 1.0, \text{maxSteps}) $$
    *   Calculate the inverse step size:
        $$ \text{invstep} = \frac{\text{tfar} - \text{tnear}}{\text{csteps}} $$
        where `tfar` and `tnear` are the far and near clipping distances [S2, unofficial].
3.  **Ray Marching Loop:**
    *   Initialize ray position `pos` at `tnear` [S2, unofficial].
    *   Compute ray dither to reduce banding:
        $$ r = \text{rand}(\text{eye\_d.xy}) $$
        *Note: The original implementation disabled dithering for single-slice volumes (`SLICES == 1.0`) to avoid Moiré patterns, but the 3D texture implementation removes this check, potentially reintroducing artifacts [S2, unofficial].*
    *   Loop `csteps` times:
        *   Sample the volume texture at the current position:
            $$ \text{sample} = \text{sampler3D}(\text{volumeTexture}, \text{pos}) $$
        *   Reconstruct color and alpha using the sampled intensity and `gLutTexture` [S2, unofficial].
        *   Accumulate color and alpha using front-to-back blending (standard volume rendering equation) [G].
        *   Advance position:
            $$ \text{pos} += \text{eye\_d} \times \text{invstep} $$
        *   If accumulated alpha exceeds a threshold (e.g., 1.0), break early [G].

### Pseudocode
```python
# Vertex Shader / Setup
# Renders a full-screen quad. Passes eye_d, CLIP_NEAR, CLIP_FAR to fragment shader.

# Fragment Shader
uniform sampler3D volumeTexture;
uniform sampler2D gLutTexture;
uniform int gNChannels;
uniform float BREAK_STEPS;
uniform vec3 volumeScale;
uniform float SLICES;
uniform float CLIP_NEAR;
uniform float CLIP_FAR;
uniform vec3 eye_d;

void main() {
    // 1. Calculate steps
    float scaledSteps = BREAK_STEPS * length(eye_d.xyz / volumeScale);
    float csteps = clamp(scaledSteps, 1.0, float(maxSteps)); // maxSteps is implementation-specific
    
    // 2. Calculate step size
    float invstep = (CLIP_FAR - CLIP_NEAR) / csteps;
    
    // 3. Initialize ray
    vec3 pos = vec3(0.0); // Assuming origin at near plane, adjusted by eye_d
    // Note: Exact ray origin calculation depends on camera projection matrix passed as uniform
    pos = eye_origin + eye_d * CLIP_NEAR; 
    
    // 4. Dither
    // Original code had: float r = (SLICES == 1.0) ? 0.0 : rand(eye_d.xy);
    // New code removes special case:
    float r = rand(eye_d.xy); 
    
    // 5. Marching loop
    vec3 accumulatedColor = vec3(0.0);
    float accumulatedAlpha = 0.0;
    
    for (int i = 0; i < int(csteps); i++) {
        // Sample volume
        // pos needs to be in texture coordinates [0,1] if volumeTexture is normalized
        // Assuming volumeTexture is in world/voxel space, coordinates must be scaled
        vec3 texPos = pos * volumeTextureSize; // Implementation detail: scaling to texel space
        
        vec4 sample = texture(volumeTexture, texPos);
        
        // Reconstruct color/alpha using LUT
        // gLutTexture is 256x4. Index depends on sample intensity and gNChannels
        float intensity = sample.r; // Assuming R channel holds intensity for simplicity
        vec4 lutResult = texture(gLutTexture, vec2(intensity * 255.0, float(gNChannels)));
        
        vec3 color = lutResult.rgb;
        float alpha = lutResult.a;
        
        // Front-to-back blending
        float weight = alpha * (1.0 - accumulatedAlpha);
        accumulatedColor += color * weight;
        accumulatedAlpha += weight;
        
        if (accumulatedAlpha > 0.99) break; // Early exit
        
        // Advance
        pos += eye_d * invstep;
    }
    
    gl_FragColor = vec4(accumulatedColor, accumulatedAlpha);
}
```

### Edge Cases and Pitfalls
*   **WebGL1 Compatibility:** The method requires `Data3DTexture` and `sampler3D`, which are WebGL2 features. It will fail on WebGL1 fallback paths [S2, unofficial].
*   **Single-Slice Moiré:** Random ray dithering causes Moiré patterns in single-slice volumes. The original atlas-based code disabled dithering for `SLICES==1.0`, but the 3D texture implementation removed this check, potentially reintroducing the artifact [S2, unofficial].
*   **Masking Semantics:** Masking is applied by scaling per-voxel intensity before LUT lookup, affecting alpha and color, not just RGB. It is applied up to 4 times (once per channel) [S2, unofficial].
*   **Performance:** When masking is enabled, the CPU-side `VolumeDataUpdater` traverses the full 3D volume twice per active channel (once for intensity, once for mask), which is a significant cost for large volumes [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of steps (`csteps`) and volume depth. `csteps` is scaled by ray length and volume dimensions [S2, unofficial].
*   **Memory Complexity:** Proportional to the volume size ($W \times H \times D \times 4$ bytes for 8-bit 4-channel data) plus the LUT size (256x4) [S2, unofficial].
*   **Measured Performance:** Rendered 128x128x128 or 256x256x256 voxels in 12.4ms [S1, unofficial].
*   **Strengths:**
    *   Avoids overhead of many draw calls and VBO management [S1, unofficial].
    *   Allows larger XYZ volumes compared to texture atlases [S2, unofficial].
    *   Simpler edge handling than texture atlases [S2, unofficial].
    *   Shares memory representation with path-tracing and isosurface modes [S2, unofficial].
*   **Limitations:**
    *   Requires WebGL2 [S2, unofficial].
    *   Limited to 4 channels [S2, unofficial].
    *   Cannot "pre-fuse" channels on the GPU, requiring CPU-side packing [S2, unofficial].
    *   Masking performance degrades with multiple channels due to double traversal [S2, unofficial].
*   **When to Use:** When WebGL2 is available, large volumes are needed, and memory sharing with other rendering modes (path-tracing) is beneficial.
*   **When Not to Use:** On WebGL1-only hardware, or when single-slice Moiré artifacts are unacceptable without restoring the dithering check.

## Background
This method was introduced by toloudis in Pull Request #370 for AllenCell/vole-core, dated Jan 30, 2026 [S2, unofficial]. It evolved from earlier techniques that represented voxel space in 3D textures for raycasting, similar to Wolfenstein 3D raycasting but in 3D [S1, unofficial]. The shift from texture atlases to 3D textures was motivated by the desire to simplify representation, enable larger volumes, and unify the in-memory data format across different rendering modes (path-tracing, isosurface, raymarching) [S2, unofficial].
