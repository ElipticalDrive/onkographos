# Fixed-Point Volume Ray Casting

Also called: vtkFixedPointVolumeRayCastMapper

## Overview
Fixed-Point Volume Ray Casting is a direct volume rendering technique implemented in the Visualization Toolkit (VTK) as `vtkFixedPointVolumeRayCastMapper` [S1][S2, unofficial]. It builds on [Direct volume ray casting](19-direct-volume-ray-casting.md) by using fixed-point arithmetic for interpolation and accumulation to improve computational efficiency, particularly for 3D voxel volumes like medical images [S1][S2, unofficial]. It distinguishes itself from [Volume Ray-Casting on Graphics Hardware](7443-volume-ray-casting-on-graphics-hardware.md) by utilizing VTK's fixed-point arithmetic pipeline for interpolation and accumulation [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A `vtkImageData` object containing the scalar volume data, including dimensions, spacing, and origin [S2, unofficial]. The data is typically derived from DICOM slices, where dimensions are $(z, y, x)$ and spacing is derived from pixel spacing and slice thickness [S2, unofficial].
*   **Output:** A rendered 2D image [S1][S2, unofficial].

**Data Structures:**
The core data structure is `vtkImageData`, which stores:
1.  **Dimensions:** A tuple $(D_x, D_y, D_z)$ representing the number of voxels in each axis [S2, unofficial].
2.  **Spacing:** A tuple $(S_x, S_y, S_z)$ representing the physical distance between voxel centers [S2, unofficial].
3.  **Origin:** A tuple $(O_x, O_y, O_z)$ representing the physical coordinates of the first voxel (typically $[0,0,0]$) [S2, unofficial].
4.  **Scalars:** A 1-component array of the original pixel data type [S2, unofficial].

**Parameters:**
*   **Interpolation:** Set to Linear (`SetInterpolationTypeToLinear`) for trilinear interpolation of scalar values during sampling [S2, unofficial].
*   **Shading:** Enabled via `ShadeOn()` to calculate diffuse and specular lighting based on gradients [S1][S2, unofficial].
    *   Ambient Coefficient: 0.2 [S1].
    *   Diffuse Coefficient: 0.9 [S1].
    *   Specular Coefficient: 0.2 [S1].
    *   Specular Power: 10 [S1].
*   **Transfer Functions:**
    *   **Opacity:** Piecewise function mapping scalar values to opacity $\alpha$. Example points: $(120, 0.0), (250, 1.0), (520, 1.0), (650, 0.0)$ [S1].
    *   **Color:** Piecewise function mapping scalar values to RGB. Example points: $(120, 0.999, 0.384, 0.384), (250, 1.0, 1.0, 0.705), (520, 1.0, 1.0, 1.0), (650, 1.0, 1.0, 1.0)$ [S1].
    *   **Gradient:** Maps gradient magnitude to opacity/weight. Example points: $(120, 2.0), (250, 2.0), (520, 0.1), (650, 0.1)$ [S1].

**Algorithm Steps:**
1.  **Initialization:** Instantiate `vtkFixedPointVolumeRayCastMapper` and set the input `vtkImageData` [S2, unofficial].
2.  **Property Configuration:** Create a `vtkVolumeProperty` object. Configure the color and opacity transfer functions using `vtkPiecewiseFunction` and `vtkColorTransferFunction` [S2, unofficial]. Enable shading and set lighting coefficients [S1].
3.  **Ray Casting:** For each pixel, cast a ray through the volume. The mapper uses fixed-point arithmetic to accumulate color and opacity along the ray segment defined by the entry and exit points of the volume bounding box [S1][S2, unofficial].
4.  **Compositing:** Apply the front-to-back compositing equation using fixed-point precision. The opacity $\alpha_i$ at each sample is derived from the transfer function and potentially corrected for step size [S2, unofficial].
5.  **Shading:** If enabled, compute the gradient $\nabla V$ at each sample point to determine surface normals and apply the Phong shading model using the configured coefficients [S1][S2, unofficial].
6.  **Early Termination & Optimization:** When accumulated opacity $\alpha$ approaches 1, the ray casting loop skips remaining voxels to terminate early and eliminate invalid computation [S1]. The mapper also generates a `MinMaxVolume` during preprocessing to skip empty voxels [S1].

**Pseudocode:**
```python
def fixed_point_volume_rendering(volume_data, dimensions, spacing, origin, transfer_functions, shading_params):
    # Initialize framebuffer for accumulated color
    framebuffer = np.zeros((dimensions[0], dimensions[1], 3))
    # Preprocess volume to generate MinMaxVolume for empty voxel skipping [S1]
    min_max_volume = compute_min_max_volume(volume_data)
    # Compute ray directions and bounding box intersections for each pixel [G]
    rays = compute_rays(dimensions, spacing, origin)
    for pixel in pixels:
        ray = rays[pixel]
        t_near, t_far = intersect_bounding_box(ray, volume_bounds)
        # Fixed-point accumulation variables [S1]
        acc_color = [0.0, 0.0, 0.0]
        acc_opacity = 0.0
        # Discretize ray segment into samples [G]
        num_samples = compute_num_samples(t_far - t_near, spacing)
        for i in range(num_samples):
            t = t_near + i * (t_far - t_near) / num_samples
            sample_pos = ray.origin + t * ray.direction
            # Check if sample is within volume bounds [G]
            if not is_inside_volume(sample_pos, dimensions, spacing, origin):
                continue
            # Skip empty voxels using MinMaxVolume [S1]
            if not is_voxel_active(sample_pos, min_max_volume):
                continue
            # Sample scalar value using trilinear interpolation [S1]
            scalar_val = trilinear_interpolate(volume_data, sample_pos)
            # Map to optical properties via transfer functions [S1]
            color, opacity = transfer_functions.map(scalar_val)
            # Apply shading if enabled [S1]
            if shading_params.enabled:
                normal = compute_gradient(volume_data, sample_pos)
                color = apply_phong_shading(color, normal, shading_params)
            # Correct opacity for step size (Beer-Lambert approximation) [G]
            step_size = (t_far - t_near) / num_samples
            opacity = 1.0 - exp(-extinction_coefficient(scalar_val) * step_size)
            # Fixed-point front-to-back compositing [S1]
            # Convert to fixed-point integers for accumulation
            acc_color = fixed_point_add(acc_color, color * opacity * (1.0 - acc_opacity))
            acc_opacity = fixed_point_add(acc_opacity, opacity * (1.0 - acc_opacity))
            # Early termination: if accumulated opacity is close to 1, skip remaining samples [S1]
            if acc_opacity >= 0.99:
                break
        framebuffer[pixel] = acc_color
    return framebuffer
```

**Edge Cases and Pitfalls:**
*   **Z-Spacing Calculation:** If DICOM slices are not contiguous or ordered, calculating Z-spacing as `abs(dicomSlice[0].SliceLocation - dicomSlice[1].SliceLocation)` yields incorrect depth, distorting the volume [S2, unofficial].
*   **Data Type Mismatch:** Ensure the VTK array type matches the input data type (e.g., `vtkUnsignedShortArray` for 16-bit DICOM) to prevent overflow or precision loss [S2, unofficial].
*   **Fixed-Point Precision:** While faster, fixed-point arithmetic may suffer from quantization errors in compositing compared to floating-point methods, potentially affecting subtle transparency effects [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Offers a balance between performance and accuracy for 3D voxel volumes, particularly suitable for medical images [S2, unofficial].
*   **Strengths:** Efficient for CPU-based rendering pipelines; avoids GPU memory transfer overheads in some VTK configurations; suitable for real-time or near-real-time visualization of large medical datasets [S2, unofficial].
*   **Limitations:** Less flexible than programmable shaders for complex transfer functions or shading models; fixed-point precision may limit dynamic range in compositing [S2, unofficial].
*   **When to Use:** When rendering large 3D voxel volumes (e.g., seismic or medical data) where computational efficiency is prioritized over floating-point precision [S1][S2, unofficial].
*   **When Not to Use:** When high-precision floating-point compositing is required, or when GPU-specific acceleration features are necessary [S2, unofficial].

## Background
Fixed-Point Volume Ray Casting is implemented as `vtkFixedPointVolumeRayCastMapper` in the Visualization Toolkit (VTK) [S1][S2, unofficial]. It is particularly used in medical imaging and seismic data visualization applications where DICOM or SEG-Y data is processed [S1][S2, unofficial]. The technique was developed to improve computational efficiency by replacing time-consuming floating-point arithmetic with fixed-point operations during interpolation and accumulation [S1].
