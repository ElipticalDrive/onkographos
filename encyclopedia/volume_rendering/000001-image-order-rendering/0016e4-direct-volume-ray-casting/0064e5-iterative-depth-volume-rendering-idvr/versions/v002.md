# Iterative Depth Volume Rendering (IDVR)

Also called: IDVR with Skip-Step Optimization, IDVR design

## Overview
Iterative Depth Volume Rendering (IDVR) is an interactive volume rendering technique that removes the brain tissue in front of a clipping surface to expose deeper internal structures while retaining anatomical context [S1]. Unlike standard direct volume ray casting which composites all samples along a ray, IDVR iteratively searches for the closest valid voxel (V) or depth voxel (Vd) along view rays to determine depth and opacity, enabling observation of subcortical regions and white matter that surface-based visualizations miss [S1]. It distinguishes itself by using a skip-step optimization to manage the performance cost of searching for these closest valid voxels without early termination [S1].

## How it works
IDVR operates by removing the brain volume in front of a clipping surface while rendering anatomical maps and volume change data completely [S1]. The core mechanism involves an iterative search for the Point of View/Projection (PV), defined as the closest valid voxel (V) or depth voxel (Vd) with the highest lighting/alpha value ($l_a$) along the view ray [S1].

**Inputs and Outputs:**
*   **Input:** Volume data texture $T_V$, clipping surface definition, view ray parameters, skip-step parameter $i$ [S1].
*   **Output:** Final pixel color and depth, with the front-most brain tissue removed to reveal internal structures [S1].

**Data Structures:**
*   **Texture $T_V$:** The volume data texture [S1]. Its resolution is assumed to be sufficiently large for the skip-step optimization to be effective [S1].
*   **Skip-step parameter $i$:** An integer controlling the accuracy and performance of the iteration [S1].

**Algorithm Steps:**
1.  **Ray Initialization:** For each pixel, define the view ray and intersect it with the volume bounding box to determine the entry parameter $t_{near}$ and exit parameter $t_{far}$ [G].
2.  **Iterative Search:** March along the ray segment $[t_{near}, t_{far}]$ to seek the PV [S1].
3.  **Skip-Step Optimization:** Skip every $i$-th texel so it is not tested as a candidate for V or Vd [S1].
    *   If $i=1$ (High Accuracy): Test every texel [S1].
    *   If $i=2$ (Balanced): Skip every 2nd texel [S1].
    *   If $i=3$ (Low Accuracy): Skip every 3rd texel [S1].
4.  **Validity Check:** For each tested texel, determine if it is a valid voxel (V) or depth voxel (Vd) relative to the clipping surface, and compute its lighting/alpha value ($l_a$) [S1].
5.  **Best Candidate Tracking:** The iteration cannot be early-terminated because there is always a possibility of finding a closer V or Vd with a higher $l_a$ value further along the ray [S1]. Track the candidate with the smallest depth $t$ and highest $l_a$.
6.  **Compositing:** Render the anatomical regions in front of the clipping surface and the surface texture to provide localization, blending their colors with the volume change data [S1].

**Pseudocode:**
```python
def idvr_render(ray_origin, ray_direction, t_near, t_far, volume_texture, clipping_surface, skip_step_i):
    """
    Renders a single ray using Iterative Depth Volume Rendering.
    
    Args:
        ray_origin: 3D vector (x, y, z)
        ray_direction: Normalized 3D vector (x, y, z)
        t_near: Entry parameter into volume bounding box
        t_far: Exit parameter from volume bounding box
        volume_texture: 3D array with .sample_trilinear(pos) method
        clipping_surface: Object with .is_behind(pos) method
        skip_step_i: Integer skip-step parameter (1, 2, or 3)
        
    Returns:
        color: Final pixel color (r, g, b)
        alpha: Final pixel opacity
        depth: Depth of the closest valid voxel found
    """
    # Step size derived from texture resolution [G]
    step_size = 1.0 / max(volume_texture.resolution)
    t = t_near
    texel_index = 0

    best_depth = float('inf')
    best_la = -1.0
    best_color = (0.0, 0.0, 0.0)
    best_alpha = 0.0

    while t <= t_far:
        # Skip-step optimization: skip every i-th texel [S1]
        if skip_step_i > 1 and texel_index % skip_step_i != 0:
            t += step_size
            texel_index += 1
            continue

        # Sample volume at current position [G]
        pos = ray_origin + ray_direction * t
        v_val = volume_texture.sample_trilinear(pos)

        # Check if voxel is behind clipping surface (valid V or Vd) [G]
        is_valid = clipping_surface.is_behind(pos)

        if is_valid:
            # Standard transfer function mapping to extinction and color [G]
            sigma = max(0.0, v_val)
            alpha = 1.0 - math.exp(-sigma * step_size)
            color = (v_val, v_val, v_val)
            la = alpha  # l_a represents visibility/opacity contribution [S1]

            # Update best candidate: closer to camera (smaller t) and higher la [S1]
            if t < best_depth and la > best_la:
                best_depth = t
                best_la = la
                best_color = color
                best_alpha = alpha

        t += step_size
        texel_index += 1

    # Composite with anatomical context to provide localization [S1]
    if best_alpha > 0:
        anatomical_color = (0.8, 0.8, 0.8)  # Context texture color [G]
        final_color = best_color * best_alpha + anatomical_color * (1.0 - best_alpha)
        final_alpha = best_alpha
    else:
        final_color = (0.0, 0.0, 0.0)
        final_alpha = 0.0

    return final_color, final_alpha, best_depth
```

**Parameters:**
*   **$i$ (Skip-step parameter):** Controls the trade-off between accuracy and performance [S1].
    *   $i=1$: High Accuracy. Tests every texel [S1].
    *   $i=2$: Balanced. Skips every 2nd texel. Nearly no visual artifacts [S1].
    *   $i=3$: Low Accuracy. Skips every 3rd texel. Noticeable artifacts (loose wrong depth values) but reasonable performance [S1].

**Edge Cases and Pitfalls:**
*   **Visual Artifacts:** When $i=3$, loose wrong depth values may appear due to skipped texels potentially being the true closest valid voxel [S1]. However, these artifacts do not disturb overall depth perception in the cutout [S1].
*   **Performance Limitation:** The iteration cannot be early-terminated because a closer valid voxel with higher $l_a$ might exist further along the ray [S1]. This makes the method computationally expensive compared to standard ray casting with early termination [S1].

## Operating characteristics
*   **Time Complexity:** The method requires iterating over all neighboring texels along the ray without early termination, making it $O(N/i)$ where $N$ is the number of samples along the ray [S1].
*   **Memory Complexity:** Depends on the volume texture size and the storage for the best candidate per ray [G].
*   **Measured Performance:**
    *   **Nvidia GeForce GTX 480 (Mono view, 1400x1050):**
        *   $i=1$: 55 fps
        *   $i=2$: 11 fps
        *   $i=3$: 18 fps [S1]
    *   **Nvidia Quadro 6000 (Stereo view, 1400x1050):**
        *   $i=1$: 4 fps
        *   $i=2$: 3 fps
        *   $i=3$: 10 fps [S1]
*   **Strengths:** Allows observation of data inside the brain, including subcortical regions and white matter, which surface-based visualization misses [S1]. Provides good spatial perception and anatomical localization through blending of colors [S1].
*   **Limitations:** Performance is limited by the iteration over all neighboring texels, which cannot be early-terminated [S1]. Frame rates are lower than common volume rendering, especially in stereo mode [S1].
*   **When to use:** When interactive visualization of internal brain structures (e.g., in neurodegenerative disease studies) is required, and the user needs to see past a clipping surface while retaining anatomical context [S1].
*   **When not to use:** When high performance is critical and visual artifacts from skipping texels are unacceptable, or when the volume data does not require internal structure visualization behind a clipping plane [S1].

## Background
IDVR was developed for the interactive 3D visualization of structural changes in the brain of a person with corticobasal syndrome (CBS) [S1]. It was introduced to allow scientists to observe data not only on the surface but also inside the brain, providing a better impression of the spatial extent of regional volume loss in the context of individual brain anatomy [S1]. The work was funded by the Helmholtz Portfolio Theme “Supercomputing and Modeling for the Human Brain” and partially by the “Human Brain Project” [S1].
