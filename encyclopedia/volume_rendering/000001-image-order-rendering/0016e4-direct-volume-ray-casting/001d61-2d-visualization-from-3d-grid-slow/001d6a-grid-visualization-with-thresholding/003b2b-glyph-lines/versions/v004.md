# Glyph Lines

Also called: Active Vector Field Arrow Rendering, ActiveVectorValuesOp, Vector Glyphs as Lines, Vector rendering

## Overview
Glyph Lines visualizes a 3D vector field by sampling it on a 2D grid at a fixed coordinate and rendering each vector as a line segment centered at the sample point, scaled by magnitude and colored by magnitude [S2, unofficial]. It builds on [Grid Visualization with Thresholding](1515-grid-visualization-with-thresholding.md) by replacing the 3D scatter plot of grid cells with directed line glyphs that explicitly encode vector direction and magnitude, rather than just scalar presence [S2, unofficial]. Unlike [Density Range Windowing](1571-density-range-windowing.md) which focuses on scalar opacity, this method is specialized for vector field topology and flow visualization [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D vector field grid (stored as a CUDA texture or OpenVDB volume), a fixed scalar coordinate $x$ defining the 2D slice plane, and rendering parameters (`glyphLength`, `magnitudeCtfNormalizeMult`) [S2, unofficial].
*   **Output:** A set of line primitives (start and end vertices with associated colors) representing the vector field on the slice [S2, unofficial].

**Data Structures:**
*   **Mask Tree:** A boolean topology tree derived from the grid to identify active voxels [S1, unofficial].
*   **Vertex Buffer:** Stores pairs of 3D coordinates (start and end points) for each glyph. Size: $2 \times \text{voxelCount}$ vertices [S1, unofficial].
*   **Color Buffer:** Stores RGB colors for each vertex. Size: $2 \times \text{voxelCount}$ colors [S1, unofficial].
*   **Index Buffer:** Indices for `GL_LINES` primitive type. Size: $2 \times \text{voxelCount}$ indices [S1, unofficial].

**Numbered Steps:**
1.  **Topology Preparation (CPU/OpenVDB variant):** Create a boolean mask tree from the grid's topology using `mask->topologyUnion(tree)` and voxelize active tiles using `mask->voxelizeActiveTiles()` [S1, unofficial].
2.  **Global Maximum Calculation (CPU/OpenVDB variant):** Calculate the maximum vector length in the tree using `openvdb::tools::minMax(tree).max().length()` and store it in `length` [S1, unofficial].
3.  **Thread Execution (GPU Kernel variant):** Calculate global thread ID `id`. Calculate total count `totalCount = glyphsCount.x * glyphsCount.y`. If `id >= totalCount`, return. Calculate grid coordinates: `col = id % glyphsCount.x`, `row = id / glyphsCount.x`. Calculate position: `position = make_float3(x, col * (worldSize.x / glyphsCount.x), row * (worldSize.y / glyphsCount.y))`. Sample vector field: `vector = tex3D(vectorFieldTex, position.x * volumeCoordSpaceMult.x, position.y * volumeCoordSpaceMult.y, position.z * volumeCoordSpaceMult.z)`. Set start vertex: `outputPts[id] = position`. Set end vertex: `outputPts[id + 1] = position + normalize(make_float3(vector.x, vector.y, vector.z)) * glyphLength * vector.w * magnitudeCtfNormalizeMult * 0.5`. Sample color: `color = tex1D(vectorMagnitudeCtfTex, vector.w * magnitudeCtfNormalizeMult)`. Set colors: `outVertexColors[id]` and `outVertexColors[id + 1]` to `make_float3(color.x, color.y, color.z)` [S2, unofficial].
4.  **CPU/Alternative Iteration (OpenVDB specific):** Allocate buffers for `pointCount * 2` points (start and end of each arrow), colors, and indices. `pointCount` is `voxelCount * 2`. Iterate over all active voxels in the mask's leaf nodes. For each voxel at coordinate `ijk`: Get the world position `pos` via `grid->indexToWorld(ijk)`. Store `pos` as the start point. Get the vector value `vec` from the grid. Calculate weight $w = \text{vec.length()} / \text{length}$. Normalize `vec`. Calculate end position `pos += grid->voxelSize()[0] * 0.9 * vec`. Store end position. Calculate color using interpolation. Multiply final RGB values by 0.3 for the start point and 1.0 for the end point [S1, unofficial].
5.  **Buffer Generation:** Generate GPU buffers for vertices, colors, and indices using `mVectorBuffer->genVertexBuffer`, `genColorBuffer`, and `genIndexBuffer(indices, GL_LINES)` [S1, unofficial].

**Formulas:**
*   Color interpolation (OpenVDB variant): $color = w \times (0.9, 0.3, 0.3) + (1.0 - w) \times (0.3, 0.3, 0.9)$, where $w$ is the normalized vector length [S1, unofficial].
*   End vertex position (GPU variant): $P_{end} = P_{start} + \frac{\vec{v}}{\|\vec{v}\|} \times \text{glyphLength} \times v_w \times \text{magnitudeCtfNormalizeMult} \times 0.5$, where $\vec{v}$ is the sampled vector and $v_w$ is its magnitude component [S2, unofficial].

**Parameters:**
*   $x$: The fixed x-coordinate for the 2D grid of glyphs [S2, unofficial].
*   `glyphLength`: Scaling factor for the length of the glyph line [S2, unofficial].
*   `magnitudeCtfNormalizeMult`: Normalization factor calculated as $\text{vectorMagnitudeCtfLength} / \text{maxMagnitude}$ [S2, unofficial].
*   `worldSize`: The physical dimensions of the volume [S2, unofficial].
*   `glyphsCount`: The number of samples in the x and y dimensions of the 2D grid [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Magnitude:** If the vector magnitude is zero, the direction is undefined. The sources do not explicitly define a guard for zero vectors, but a standard implementation should check for zero length before normalizing to avoid NaN or arbitrary directions [G].
*   **Precision:** The use of `float3` and texture sampling may introduce precision errors in position calculation, especially for large volumes [S2, unofficial].
*   **Boundary Conditions:** The fixed x-coordinate must be within the volume bounds. If it is outside, the texture sampling may return zero or undefined values [G].

**Pseudocode:**
```python
def render_glyph_lines(vector_field_tex, world_size, glyphs_count, glyph_length, magnitude_ctf_normalize_mult, fixed_x):
    """
    Renders vector field glyphs on a 2D slice at a fixed x-coordinate using a GPU kernel approach.
    """
    total_count = glyphs_count.x * glyphs_count.y
    output_pts = [None] * (total_count * 2)
    out_vertex_colors = [None] * (total_count * 2)
    
    # Precompute scaling factors for texture coordinates [0,1] [G]
    volume_coord_space_mult = (1.0 / world_size.x, 1.0 / world_size.y, 1.0 / world_size.z)

    for id in range(total_count):
        col = id % glyphs_count.x
        row = id // glyphs_count.x
        
        # Calculate position on the 2D slice
        position = (fixed_x, col * (world_size.x / glyphs_count.x), row * (world_size.y / glyphs_count.y))
        
        # Sample vector field: trilinear interpolation of 3D texture [G]
        tex_coords = (position[0] * volume_coord_space_mult[0], 
                      position[1] * volume_coord_space_mult[1], 
                      position[2] * volume_coord_space_mult[2])
        # vector = (x, y, z, magnitude) fetched from texture [G]
        vector = (0.0, 0.0, 0.0, 0.0) 
        
        # Set start vertex
        output_pts[id] = position
        
        # Normalize vector direction, handle zero magnitude [G]
        vec_len = (vector[0]**2 + vector[1]**2 + vector[2]**2)**0.5
        if vec_len > 1e-6:
            vec_norm = (vector[0]/vec_len, vector[1]/vec_len, vector[2]/vec_len)
        else:
            vec_norm = (0.0, 0.0, 0.0)
            
        # Calculate end vertex
        # vector[3] holds the magnitude in this implementation
        scale = glyph_length * vector[3] * magnitude_ctf_normalize_mult * 0.5
        output_pts[id + 1] = (
            position[0] + vec_norm[0] * scale,
            position[1] + vec_norm[1] * scale,
            position[2] + vec_norm[2] * scale
        )
        
        # Sample color based on magnitude
        color_t = vector[3] * magnitude_ctf_normalize_mult
        # color_sample = (r, g, b) fetched from 1D color transfer function texture [G]
        color_sample = (0.5, 0.5, 0.5)
        
        # Set colors for both start and end vertices
        out_vertex_colors[id] = (color_sample[0], color_sample[1], color_sample[2])
        out_vertex_colors[id + 1] = (color_sample[0], color_sample[1], color_sample[2])
        
    return output_pts, out_vertex_colors
```

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of active voxels or grid samples. The GPU kernel runs in parallel for each glyph [G].
*   **Memory Complexity:** $O(N)$ for vertex, color, and index buffers [S1, unofficial].
*   **Performance:** Performance depends on the number of active voxels and the efficiency of the texture sampling and GPU kernel execution [S2, unofficial].
*   **Strengths:** Simple and efficient for visualizing vector fields on 2D slices. Provides clear direction and magnitude information [S2, unofficial].
*   **Limitations:** Limited to 2D slices. Performance may degrade with very high resolution grids [S2, unofficial].
*   **When to use:** When visualizing vector fields on specific planes or slices is required [S2, unofficial].

## Background
Glyph Lines is a technique for visualizing vector fields, often implemented using GPU shaders and texture sampling [S2, unofficial]. The implementation described here is based on CUDA and OpenVDB [S1, S2, unofficial].
