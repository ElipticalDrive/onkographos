# Volume Raycasting with Front/Back Face Depth Textures

Also called: Dual-Texture Enter/Exit Vector Method, Enter/Exit 3D vectors method, Entry/Exit Depth Ray Casting, Front/Back face texture method, Ray Casting with Pre-computed Entry/Exit Textures, Volume Ray Casting with Pre-computed Entry/Exit Textures

## Overview
A volume rendering technique that visualizes 3D scalar fields by projecting a 2D screen onto a 3D volume's bounding box using pre-computed coordinate textures to map screen pixels to 3D entry and exit points, then marching along rays between these faces to accumulate color and alpha [S3, unofficial]. It differs from standard ray casting by avoiding per-ray intersection tests with the volume geometry; instead, it relies on two 2D textures storing the 3D coordinates of the front and back faces of the volume's bounding box for each screen pixel [S1, S2, unofficial]. This method is a specific implementation of the two-pass depth ray casting approach, where the depth information is encoded as full 3D coordinates rather than just depth values [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field (volume data), a 3D bounding box defining the volume extent, a camera view matrix, and a projection matrix [S2, unofficial].
*   **Output:** A 2D image where each pixel contains the accumulated color and alpha of the ray passing through the volume [S3, unofficial].

**Data Structures:**
1.  **3D Texture:** Stores the scalar field values. The layout is a matrix of Z slices with dimensions $M \times N$ divisions in X and Y, and subdivisions in Z. Z increases from top to bottom ($Z=0$ at top) [S3, unofficial].
2.  **Front Face Coordinate Texture:** A 2D texture with resolution matching the screen (or target framebuffer). Each pixel's RGB value represents the 3D world coordinates $(x, y, z)$ of the point on the front face of the bounding box corresponding to that screen pixel [S2, unofficial].
3.  **Back Face Coordinate Texture:** A 2D texture with resolution matching the screen. Each pixel's RGB value represents the 3D world coordinates $(x, y, z)$ of the point on the back face of the bounding box corresponding to that screen pixel [S2, unofficial].

**Parameters:**
*   **Threshold:** A scalar value below which field data is disregarded. Example value: $0.5$ for a level set [S3, unofficial].
*   **Alpha Correction:** A multiplier for the local alpha contribution, typically a number smaller than 1. Example value: $0.1$ [S3, unofficial].
*   **Step Size:** The distance between samples along the ray. Not given in the sources.

**Algorithm Steps:**
1.  **Generate Coordinate Textures:**
    *   Render the back face of the volume's bounding box to a texture. The fragment shader outputs the 3D world coordinates of the fragment. This creates the Back Face Coordinate Texture [S2, unofficial].
    *   Render the front face of the volume's bounding box to a separate texture. The fragment shader outputs the 3D world coordinates of the fragment. This creates the Front Face Coordinate Texture [S2, unofficial].
    *   *Note:* This step effectively pre-computes the ray origins and destinations for every screen pixel [S2, unofficial].

2.  **Ray Casting Pass:**
    For each pixel in the output image:
    1.  Retrieve the 3D front point $P_{front}$ from the Front Face Coordinate Texture [S2, unofficial].
    2.  Retrieve the 3D back point $P_{back}$ from the Back Face Coordinate Texture [S2, unofficial].
    3.  Construct the ray vector $\vec{R} = P_{back} - P_{front}$ [S2, unofficial].
    4.  Initialize accumulated color $C_{acc} = (0, 0, 0)$ and accumulated alpha $A_{acc} = 0$ [S2, unofficial].
    5.  Iterate along the ray from $P_{front}$ towards $P_{back}$ with a small step size $\Delta s$. Let the current position be $P_{curr}$ [S2, unofficial].
        a.  Sample the 3D field value $v$ at $P_{curr}$ using trilinear interpolation from the 3D Texture [S3, unofficial].
        b.  If $v$ is above the Threshold:
            i.  Calculate local color $c$ and local alpha $\alpha$ based on $v$ (using a transfer function) [S3, unofficial].
            ii. Update accumulated color: $C_{acc} = C_{acc} + c \times \alpha_{correction}$ [S3, unofficial].
            iii. Update accumulated alpha: $A_{acc} = A_{acc} + \alpha$ [S3, unofficial].
        c.  If $A_{acc} \ge 1$ or $P_{curr}$ has reached or passed $P_{back}$, break the loop [S3, unofficial].
    6.  The final color for the pixel is $C_{acc}$ [S3, unofficial].

```python
def volume_ray_casting(front_coord_texture, back_coord_texture, volume_texture, transfer_function, threshold, alpha_correction):
    """
    Main raycasting pass.
    """
    output_image = empty_2d_texture()
    
    for u, v in output_image.dimensions():
        # 1. Retrieve entry and exit points
        P_front = front_coord_texture.sample(u, v)
        P_back = back_coord_texture.sample(u, v)
        
        # 2. Construct ray
        ray_vector = P_back - P_front
        ray_length = length(ray_vector)
        ray_direction = normalize(ray_vector)
        
        # 3. Initialize accumulators
        C_acc = (0.0, 0.0, 0.0)
        A_acc = 0.0
        
        # Step size is not given in the sources. [G]
        step_size = 0.01 
        
        t = 0.0
        while t < ray_length:
            P_curr = P_front + ray_direction * t
            v = volume_texture.sample_trilinear(P_curr)
            
            # Check threshold
            if v > threshold:
                # Calculate local color and alpha based on v
                c, alpha = transfer_function(v)
                
                # Update accumulators
                C_acc = tuple(C_acc[i] + c[i] * alpha_correction for i in range(3))
                A_acc = A_acc + alpha
                
                # Check for termination
                if A_acc >= 1.0:
                    break
            
            t += step_size
            
        # 5. Store result
        output_image.set_pixel(u, v, C_acc)
        
    return output_image
```

**Edge Cases and Pitfalls:**
*   **Premature Termination:** The loop must break if accumulated alpha reaches 1 (full opacity) to avoid unnecessary computation, or if the back face is reached [S3, unofficial].
*   **Degenerate Input:** If the camera is inside the volume, the front and back face coordinates might be swapped or invalid. Not given in the sources.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M \cdot S)$, where $N$ and $M$ are the screen dimensions, and $S$ is the number of steps along the ray. The number of steps depends on the ray length and step size.
*   **Memory Complexity:** $O(V + N \cdot M)$, where $V$ is the size of the 3D volume texture, and $N \cdot M$ is the size of the two coordinate textures.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Performance scales linearly with screen resolution and ray length. The use of pre-computed coordinates avoids expensive ray-box intersection tests per pixel, but requires two additional render passes for coordinate generation.
*   **Strengths:** Simple implementation, avoids complex ray-triangle intersection logic for the volume boundary.
*   **Limitations:** Requires two additional render passes. Precision of the coordinate textures can affect accuracy. Not suitable for dynamic volumes where the bounding box changes frequently, as the coordinate textures must be regenerated.
*   **When to use:** Static volumes with simple bounding boxes.
*   **When not to use:** Dynamic volumes, complex geometries, or when high precision is required without high-resolution coordinate textures.
