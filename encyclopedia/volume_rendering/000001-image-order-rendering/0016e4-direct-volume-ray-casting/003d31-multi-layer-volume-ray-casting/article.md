# Multi-layer Volume Ray Casting

Also called: raycast1Layer, segment-by-segment ray casting

## Overview
Multi-layer volume ray casting is a GPU-based rendering method that unifies volume rendering, geometric clipping, and object embedding by treating all visual elements as Volume-of-Interests (VOIs) with assigned priorities [S1]. It solves the problem of handling complex spatial overlaps, empty-space skipping, and multiple material types in a single pass by encoding non-overlapping ray segments into a pre-computed ray-layer buffer [S1]. Unlike single-layer ray casters that cannot skip empty spaces between visible samples or handle embedded objects producing multiple layers, this method explicitly stores segment boundaries and material IDs, allowing the ray caster to iterate through layers efficiently [S1].

## How it works
The method operates in two distinct phases: the generation of a ray-layer buffer via depth peeling, and the segment-by-segment ray casting using that buffer [S1].

### Inputs and Outputs
**Inputs:**
*   A set of Volume-of-Interests (VOIs), each defined by a boundary (volume data, clipping geometry, embedded objects, MPRs, or non-empty-space boundaries) and a priority number [S1].
*   A transfer function stack, where each material ID maps to a specific transfer function [S1].
*   A `renderMpr` flag indicating whether Multi-Planar Reformation (MPR) layers should be rendered [S1].
*   The volume dataset, partitioned into bricks for bricking support [S1].

**Outputs:**
*   A final image where each pixel is composed of contributions from all valid ray segments along the view ray [S1].

### Data Structures

**Ray-layer Buffer**
The core data structure is a per-pixel array of ray segments [S1].
*   **Layout:** Each entry in the array represents one non-overlapping ray segment.
*   **Fields:**
    *   `rayStart`: The starting Z-coordinate (depth) of the segment. This is not a full 3D texture coordinate, but the Z-value relative to the view direction [S1].
    *   `rayEnd`: The ending Z-coordinate of the segment [S1].
    *   `materialID`: An integer identifying the material properties (transfer function, shading parameters) for this segment [S1].
*   **Generation:** The buffer is generated by performing depth peeling on all VOI boundaries, followed by layer simplification [S1]. The peeling process resolves overlaps based on VOI priority numbers [S1].

**Transfer Function Stack**
To support multiple transfer functions in a single pass, they are stacked into a single 2D texture [S1].
*   **Access:** To sample the transfer function for a specific `materialID`, the texture coordinates are offset by `materialID * D`, where `D` is the size (width or height, depending on layout) of a single transfer function in the stack [S1].

### Algorithm Steps

#### Phase 1: Ray-layer Buffer Generation
1.  **VOI Definition:** Define all visual elements as VOIs. Assign each VOI a priority number (integer). Higher priority overwrites lower priority in overlapping regions. Multiple VOIs may share identical priorities, in which case their contributions are blended [S1].
2.  **Default VOI:** Assign the implicit bounding box of the volume dataset as the default VOI with the lowest priority. Voxels excluded by all other VOIs are rendered according to this default [S1].
3.  **Depth Peeling:** Perform depth peeling on the boundaries of all VOIs [S1]. This extracts the front-most, second-front-most, etc., surfaces for each pixel [S1].
4.  **Layer Simplification & Encoding:** Organize the peeled fragments into layers. For each pixel, encode a set of non-overlapping ray segments. Record the starting Z-coordinate (`rayStart`) and the `materialID` for each segment [S1].
5.  **Buffer Creation:** Store these segments in the ray-layer buffer. A single shared buffer is used for the whole volume (across all bricks) rather than per-brick buffers, ensuring aligned sampling locations and easier debugging [S1].

#### Phase 2: Multi-layer Ray Casting
For each pixel, the ray caster iterates through the segments in the ray-layer buffer [S1].

1.  **Fetch Segment:** Retrieve the current segment's `rayStart`, `rayEnd`, and `materialID` from the ray-layer buffer [S1].
2.  **Validity Check:** If the segment is invalid (e.g., empty), skip to the next segment [S1].
3.  **Brick Boundary Check:** Check if `rayStart` is behind the far end of the current brick. If so, return `false` to terminate the ray for the current brick [S1].
4.  **MPR Rendering (Optional):** If the `renderMpr` flag is set, render the MPR layer in the intersection of `[rayStart, rayEnd]` with the current brick before standard volume ray casting [S1].
5.  **Single-Layer Ray Casting (`raycast1Layer`):**
    *   Initialize accumulated color $C' = 0$ and accumulated opacity $\alpha' = 0$ [S1, S12].
    *   Sample the volume along the segment from `rayStart` to `rayEnd` [S1].
    *   For each sample point $\mathbf{p}_i$:
        *   Sample the scalar value $V(\mathbf{p}_i)$ [S1, S6].
        *   Apply the transfer function associated with `materialID` to get color $C_i$ and opacity $\alpha_i$ [S1, S2].
        *   Composite using the front-to-back over operator:
            $$
            C'_{i} = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i
            $$
            $$
            \alpha'_{i} = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i
            $$
        *   Check accumulated opacity $\alpha'$. If $\alpha'$ reaches 1 (or a threshold), terminate the ray for this segment [S1, S9].
    *   Estimate gradients on layer surfaces using the ray-layer buffer to improve shading effects (e.g., Phong shading) [S1, S14].
6.  **Termination Check:**
    *   Check if `rayEnd` is behind the far end of the brick.
    *   If yes, return `false` (termination of the ray for the current brick) [S1].
    *   Otherwise, return `true` to continue to the next ray segment in the buffer [S1].
7.  **Loop:** Repeat steps 1-6 for all segments in the ray-layer buffer until `false` is returned or all segments are processed [S1].

def multi_layer_volume_ray_casting(pixels, ray_layer_buffer, bricks, transfer_function_stack, render_mpr_flag):
    """
    Renders the image using the multi-layer volume ray casting method.
    
    Args:
        pixels: List of pixel objects, each with a color accumulator (C_acc) and opacity accumulator (alpha_acc).
        ray_layer_buffer: 2D array where each pixel contains a list of segments.
                          Each segment is a tuple: (ray_start_z, ray_end_z, material_id).
        bricks: List of brick objects, each with a far_end_z (relative to camera).
        transfer_function_stack: 2D texture containing stacked transfer functions.
        render_mpr_flag: Boolean flag for MPR rendering.
    """
    for pixel in pixels:
        # Initialize accumulators for the pixel
        pixel.C_acc = 0.0
        pixel.alpha_acc = 0.0
        
        # Get the list of segments for this pixel
        segments = ray_layer_buffer[pixel.x][pixel.y]
        
        # Iterate through all non-empty ray segments
        for segment in segments:
            ray_start_z, ray_end_z, material_id = segment
            
            # Check if segment is valid
            if not is_valid_segment(ray_start_z, ray_end_z):
                continue
            
            # Check brick boundary
            # Assuming we are processing a specific brick context or the buffer is brick-relative
            # If rayStart is behind the far end of the current brick, terminate
            if ray_start_z > current_brick.far_end_z:
                break # Terminate ray for this brick
            
            # Optional: Render MPR layer
            if render_mpr_flag:
                mpr_intersection_start = max(ray_start_z, current_brick.near_end_z)
                mpr_intersection_end = min(ray_end_z, current_brick.far_end_z)
                if mpr_intersection_start < mpr_intersection_end:
                    render_mpr_layer(pixel, mpr_intersection_start, mpr_intersection_end, material_id)
            
            # Perform single-layer ray casting for the segment
            terminated = raycast1_layer(pixel, ray_start_z, ray_end_z, material_id, current_brick, transfer_function_stack)
            
            if terminated:
                break # Terminate ray for this brick
            
            # Check if rayEnd is behind the far end of the brick
            if ray_end_z > current_brick.far_end_z:
                break # Terminate ray for this brick

def raycast1_layer(pixel, ray_start_z, ray_end_z, material_id, brick, transfer_function_stack):
    """
    Casts a ray for a single segment.
    Returns True if the ray should be terminated, False otherwise.
    """
    # Initialize segment accumulators
    seg_C_acc = 0.0
    seg_alpha_acc = 0.0
    
    # Determine step size and number of samples
    # Not given in sources, typically based on voxel size or fixed step
    step_size = get_step_size() 
    num_samples = int((ray_end_z - ray_start_z) / step_size)
    
    for i in range(num_samples):
        # Calculate sample position
        t = ray_start_z + i * step_size
        
        # Check if sample is within brick bounds
        if t > brick.far_end_z:
            return True # Terminate
        
        # Sample volume
        # Interpolate scalar value V at position corresponding to t
        # Note: t is Z, need to convert to 3D coordinates (x, y, z) based on ray direction
        pos_3d = get_3d_position_from_z(t, pixel)
        scalar_value = sample_volume(pos_3d)
        
        # Apply transfer function
        # Offset texture coordinates by material_id * D
        color, opacity = sample_transfer_function(transfer_function_stack, material_id, scalar_value)
        
        # Composite
        # C' = C' + (1 - alpha') * alpha * C
        # alpha' = alpha' + (1 - alpha') * alpha
        seg_C_acc = seg_C_acc + (1.0 - seg_alpha_acc) * opacity * color
        seg_alpha_acc = seg_alpha_acc + (1.0 - seg_alpha_acc) * opacity
        
        # Check for early termination
        if seg_alpha_acc >= 1.0:
            break
            
    # Update pixel accumulators
    # Note: The pixel accumulators are updated after each segment or at the end?
    # The paper implies the ray caster updates the pixel buffer.
    # Standard front-to-back compositing across segments:
    pixel.C_acc = pixel.C_acc + (1.0 - pixel.alpha_acc) * seg_C_acc
    pixel.alpha_acc = pixel.alpha_acc + (1.0 - pixel.alpha_acc) * seg_alpha_acc
    
    # Check if pixel is fully opaque
    if pixel.alpha_acc >= 1.0:
        return True # Terminate ray
        
    return False

def sample_transfer_function(stack, material_id, scalar_value):

    Samples the transfer function stack for a given material ID.
    """
    # D is the size of a single transfer function in the stack
    D = get_transfer_function_size()
    offset = material_id * D
    
    # Sample the 2D texture at (scalar_value, offset)
    # This returns color and opacity
    return texture_lookup(stack, scalar_value, offset)

### Parameters
*   **VOI Priority Number:** Integer assigned to each VOI. Higher priority overwrites lower priority. Multiple VOIs may share identical priorities, in which case their contributions are blended [S1].
*   **renderMpr:** Boolean flag. If true, MPR layers are rendered before volume ray casting for the current segment [S1].
*   **Default VOI:** Implicit bounding box of the volume dataset, assigned the lowest priority. Voxels excluded by all other VOIs are rendered according to this default [S1].

### Edge Cases and Pitfalls
*   **Empty Space Skipping:** Single-layer ray casting cannot skip empty spaces between the first and last visible samples. The multi-layer encoding explicitly stores non-overlapping segments, solving this [S1].
*   **Embedded Objects:** Single-layer representation cannot cope with embedded objects that produce multiple layers. The multi-layer buffer handles this by storing multiple segments per pixel [S1].
*   **Bricking Compatibility:** Storing only the Z value of the starting position (instead of full 3D texture coordinates) ensures that sampling locations align across bricks, which is required for bricking compatibility [S1].
*   **Memory Usage:** Storing only the Z value reduces memory usage compared to storing full 3D texture coordinates in auxiliary ray textures [S1].
*   **Performance:** The multi-pass depth peeling cost is nearly ignorable compared to the ray casting cost. The algorithm shifts computational workload to layer sorting to keep the ray-casting loop simple and GPU-efficient [S1].

## Operating characteristics
*   **Time Complexity:** The complexity is dominated by the ray casting pass, which is linear with respect to the number of samples across all segments. The depth peeling cost is considered nearly ignorable [S1].
*   **Memory Complexity:** The ray-layer buffer size is proportional to the number of pixels and the average number of layers per pixel. Storing only Z coordinates and material IDs minimizes memory usage [S1].
*   **Strengths:**
    *   Unified framework for volume rendering, clipping, embedding, and CSG operations [S1].
    *   Supports interactive editing and cutaway views [S1].
    *   Efficient GPU implementation due to simple ray-casting loop and single-pass ray casting [S1].
    *   Handles complex spatial overlaps with priority-based resolution [S1].
*   **Limitations:**
    *   Requires pre-computation of the ray-layer buffer via depth peeling [S1].
    *   Relies on the assumption that depth peeling cost is negligible, which may vary with scene complexity [S1].
*   **When to Use:** Medical imaging and scientific visualization software requiring interactive volume editing, cutaway views, and prioritized overlay of geometric masks, MPRs, and embedded objects [S1].

## Background
Multi-layer volume ray casting was introduced by Wei Li from Siemens Corporate Research [S1]. The method was presented in the paper "Multi-layer Volume Ray Casting on GPU" at the International Conference on Visualization, Imaging, and Image Processing (VG10) in 2010 [S1]. It addresses the limitations of previous GPU-based volume rendering techniques, such as the inability to handle multiple material types, complex CSG operations, and embedded objects in a single pass [S1]. The method builds on the principles of polygon-assisted ray casting and depth peeling but adapts them for volume data by using a ray-layer buffer with Z-coordinate encoding [S1].
