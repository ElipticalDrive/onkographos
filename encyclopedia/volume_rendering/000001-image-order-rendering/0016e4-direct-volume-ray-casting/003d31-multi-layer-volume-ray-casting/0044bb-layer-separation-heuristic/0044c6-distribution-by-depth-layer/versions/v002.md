# Distribution by Depth Layer

Also called: Adaptive Layer Distribution, Quality/Performance Tradeoff via Layer Count

## Overview
Distribution by Depth Layer is a workload distribution method that assigns high-quality raycasting to the first $n$ depth layers (representing close structures) and multi-frame rate image warping to the remaining layers [S1]. It exploits the observation that close structures contribute more to the final image than distant ones [S1]. It sets itself apart from sibling methods by using depth proximity as the primary heuristic for quality allocation, whereas [Layered Image Warping](11344-layered-image-warping.md) focuses on the warping mechanism itself [S1].

## How it works
**Inputs:**
*   Volume dataset [S1].
*   Camera position and orientation [S1].
*   Target minimum frame rate ($FPS_{min}$) [S1].
*   Hardware configuration: a fast GPU and a slow GPU [S1].

**Outputs:**
*   Final rendered image [S1].
*   Dynamic number of raycasted layers ($n$) [S1].

**Data Structures:**
*   Depth layers extracted from the volume dataset, ordered by distance from the camera [S1].

**Parameters:**
*   $n$: The number of front layers to raycast [S1].
*   $FPS_{min}$: The desired minimum frame rate [S1].

**Steps:**
1.  **Initial Setup:** Determine the total number of layers $N$ in the volume dataset. Initialize $n$ to a starting value [G].
2.  **Layer Assignment:** Assign layers $0$ to $n-1$ (the closest $n$ layers) to be rendered via raycasting on the fast GPU [S1]. Assign layers $n$ to $N-1$ (the remaining back layers) to be rendered via multi-frame rate image warping on the slow GPU [S1].
3.  **Rendering:** Perform raycasting for the front $n$ layers [S1]. Perform image warping for the back $N-n$ layers [S1]. Composite the results into the final image [S1].
4.  **Performance Monitoring:** Measure the current frame rate $FPS_{curr}$ [S1].
5.  **Adaptive Adjustment:** If $FPS_{curr} < FPS_{min}$, immediately decrease $n$ by 1 [S1]. Periodically attempt to render with $n+1$ layers to check if improved quality is possible [S1].
6.  **Repeat:** Return to Step 2 for the next frame or update cycle [S1].

**Pseudocode:**
```python
def distribution_by_depth_layer(volume, camera, fps_min):
    # Extract depth layers and sort by distance from camera (closest first)
    layers = sorted(volume.get_depth_layers(), key=lambda layer: layer.distance_from(camera))
    total_layers = len(layers)
    
    # Initial guess for n (number of raycasted layers)
    n = max(1, total_layers // 2)  # [G] Standard initialization
    
    frame_count = 0
    while True:
        # 1. Assign layers
        raycast_layers = layers[:n]
        warp_layers = layers[n:]
        
        # 2. Render
        # Raycast close layers
        front_image = raycast(raycast_layers, camera)
        
        # Warp back layers
        back_image = image_warp(warp_layers, camera, front_image)
        
        # Composite
        final_image = composite(front_image, back_image)
        
        # 3. Monitor Frame Rate
        current_fps = 1.0 / get_frame_time()
        
        # 4. Adaptive Adjustment
        if current_fps < fps_min:
            # Decrease n immediately to improve performance
            if n > 0:
                n -= 1
        else:
            # Periodically check if higher quality is possible
            # [G] Using a simple frame counter for periodicity
            if frame_count % 30 == 0 and n + 1 <= total_layers:
                # Try rendering with n+1 layers
                test_front = raycast(layers[:n+1], camera)
                test_back = image_warp(layers[n+1:], camera, test_front)
                test_fps = 1.0 / get_frame_time()
                
                if test_fps >= fps_min:
                    n += 1
                # Else: keep n as is
        
        yield final_image
        frame_count += 1
```

**Edge Cases and Pitfalls:**
*   **Degenerate Input:** If $n=0$, all layers are warped, potentially losing all high-frequency detail from close structures. If $n=N$, all layers are raycasted, potentially missing the performance benefit of warping [G].
*   **Precision:** The transition between raycasting and warping at layer $n$ may introduce visible seams if the warping accuracy is insufficient for the depth discontinuity [G].
*   **Boundary:** The number of raycasted layers cannot exceed the total number of layers $N$ [G].

### [Advanced Workload Distribution Schemes](11581-advanced-workload-distribution-schemes.md)
Extends this concept by distributing workload between GPUs to replace some image warping with raycasting for higher quality beyond strict node assignment.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of raycasted layers $n$ [S1]. Performance (FPS) degrades linearly as $n$ increases [S1].
*   **Memory Complexity:** Depends on the storage of the volume dataset and intermediate buffers for raycasting and warping. Not given in the sources.
*   **Measured Performance:** Evaluation on a scene rotated 90 degrees showed that reconstruction error converges to the reference image as more layers are raycasted [S1]. Performance (FPS) degrades linearly as more layers are raycasted [S1]. The benefit of warping more than 6 layers vanishes [S1].
*   **Strengths:** Automatically adjusts quality/performance tradeoff based on current frame rate [S1]. Exploits the perceptual importance of close structures [S1].
*   **Limitations:** Requires two GPUs (fast and slow) for optimal implementation as described [S1]. The "vanishing benefit" after 6 layers suggests diminishing returns for high layer counts [S1].

## Background
Originated in the paper "Multi-Frame Rate Volume Rendering" by S. Hauswiesner, D. Kalkofen, and D. Schmalstieg (2010) [S1]. The method is part of a broader framework for multi-frame rate rendering, aiming to provide the best quality for a given maximum latency by dynamically adjusting the rendering workload [S1].
