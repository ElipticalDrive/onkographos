# Ray-Layer Buffer Generation via Depth Peeling

Also called: VOI layer generation, peeling VOI definitions

## Overview
This method generates the ray-layer buffer for multi-layer volume ray casting by depth-peeling Volume of Interest (VOI) definitions and grouping the resulting fragments into ordered layers based on VOI priority and material ID [S1]. It differs from standard GPU-based Constructive Solid Geometry (CSG) by performing stencil-like tests inside a GPU program rather than using hardware stencil buffers, thereby preserving critical priority and ID information required for correct layer placement and optimization [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A set of VOI definitions (each with a material ID and priority), clipping meshes, Multi-Planar Reformation (MPR) meshes, and depth-peeled fragments [S1].
*   **Output:** A ray-layer buffer containing ordered entries representing visible geometry along each ray, including material IDs and depth information [S1].

**Data Structures**
*   **InsideFlag Array:** An array indexed by material ID that stores the net count of front-facing minus back-facing fragments for each ID [S1]. This count is maintained even for discarded fragments that do not contribute to the layer buffer [S1].
*   **Ray-Layer Buffer Entry:** A record containing depth and material ID fields [S1].

**Algorithm Steps**
1.  **Initialize InsideFlags:** For each pixel/ray, initialize the `insideFlag` array for all material IDs to zero [S1].
2.  **Process Peeling Passes:** Iterate through the depth-peeling passes [S1]. For each fragment:
    *   Update the `insideFlag` for the fragment's material ID: increment by one for front-facing, decrement by one for back-facing [S1].
    *   **Handle Clipping Meshes:** If front-facing, clear all previous layers in the ray-layer buffer for the current ray [S1]. If back-facing, mark layer generation as finished for the current ray [S1].
    *   **Handle MPR Meshes:** Write the MPR fragment directly to the buffer [S1]. If the MPR is inside a non-empty layer, append an entry with the same depth as the MPR but using the previous material ID to continue the intersected layer [S1].
    *   **Determine Current Material ID (`currentId`):** Scan the `insideFlag` array to find the material ID of the enclosing VOI with the highest priority [S1]. A back-facing fragment indicates the exit of a contributing VOI, so `currentId` will differ from the ID of the VOI being exited [S1].
    *   **Write to Buffer:** If `currentId` differs from the material ID of the previous layer, write the current fragment to the buffer with `currentId` [S1].
3.  **Optimization (Empty Space Merging):** Identify empty segments between adjacent `mtIdVolume` layers [S1]. If the length of an empty segment is shorter than a given threshold, merge the adjacent layers into one [S1].

```python
BACK = -1

MPR = "mpr"

def create_entry(depth, mat_id):
    return {"depth": depth, "material_id": mat_id}

def generate_ray_layer_buffer(peeled_fragments, voi_priorities):
    inside_flags = {}
    ray_layer_buffers = {}
    ray_finished = set()

    for frag in peeled_fragments:
        rid = frag.ray_id
        if rid in ray_finished:
            continue

        if rid not in inside_flags:
            inside_flags[rid] = {mid: 0 for mid in voi_priorities}

        mat_id = frag.material_id
        facing = frag.facing
        depth = frag.depth
        mesh_type = frag.mesh_type

        inside_flags[rid][mat_id] += 1 if facing == FRONT else -1

        if mesh_type == CLIPPING:
            if facing == FRONT:
                ray_layer_buffers[rid] = []
            else:
                ray_finished.add(rid)
            continue

        if mesh_type == MPR:
            entry = create_entry(depth, mat_id)
            ray_layer_buffers[rid].append(entry)
            if ray_layer_buffers[rid] and ray_layer_buffers[rid][-1]["material_id"] != EMPTY:
                ray_layer_buffers[rid].append(create_entry(depth, ray_layer_buffers[rid][-1]["material_id"]))
            continue

        current_id = None
        best_priority = -1
        for mid, count in inside_flags[rid].items():
            if count > 0 and voi_priorities[mid] > best_priority:
                best_priority = voi_priorities[mid]
                current_id = mid

        if rid not in ray_layer_buffers or not ray_layer_buffers[rid]:
            ray_layer_buffers[rid].append(create_entry(depth, current_id))
        else:
            prev_id = ray_layer_buffers[rid][-1]["material_id"]
            if prev_id != current_id:
                ray_layer_buffers[rid].append(create_entry(depth, current_id))

    for rid in ray_layer_buffers:
        buffer = ray_layer_buffers[rid]
        i = 0
        while i < len(buffer) - 1:
            curr = buffer[i]
            next_ = buffer[i+1]
            if curr["material_id"] != EMPTY and next_["material_id"] == EMPTY:
                j = i + 1
                while j < len(buffer) and buffer[j]["material_id"] == EMPTY:
                    j += 1
                if j < len(buffer) and buffer[j]["material_id"] != EMPTY:
                    seg_len = buffer[j]["depth"] - curr["depth"]
                    if seg_len < threshold:
                        del buffer[i+1:j]
                        continue
            i += 1

    return ray_layer_buffers
```

**Parameters**
*   **Empty Space Merge Threshold:** A length threshold below which empty segments between volume layers are merged [S1]. Not given in the sources.

**Edge Cases and Pitfalls**
*   **Identical Depth Fragments:** Standard peeling outputs only one fragment for identical depths, causing incorrect `insideFlags` [S1]. This occurs when common points of two surfaces project exactly to pixel centers, or when a back-facing surface touches a front-facing surface of the same VOI at corners/edges of non-empty-space bounding boxes [S1].
*   **Hardware Depth Test Limitations:** Modifying depth in a fragment program may disable hardware depth testing on some GPUs [S1]. In such cases, the encoded depth must be written to a color channel and compared using MIN/MAX frame buffer operations [S1].

## Subtopics

### Identical Depth Fragment Handling
A method to resolve ambiguity when two fragments at the same pixel have identical depths, which causes standard peeling to output only one and produce incorrect `insideFlags` [S1]. It encodes depth, facing, and mesh ID into a new number (similar to ray-layer buffer entry encoding) and sets it as the modified depth in the peeling fragment program [S1]. If hardware does not support depth testing with modified depth, the encoded value is written to a color channel and compared using MIN or MAX operations [S1].

### Dual Depth Peeling
An improvement to Depth Peeling that reduces the number of passes by $N/2$ for $N$ layers by performing simultaneous peeling in both directions: from camera to background and background to camera [S2]. It may still store elements at different depths within the same layer if no intermediate geometry occludes them, which reduces depth-sorting precision [S2].

## Operating characteristics
*   **Time Complexity:** Depends on the number of depth peeling passes [S2]. Dual Depth Peeling reduces this by half compared to standard peeling [S2].
*   **Memory Complexity:** Requires storage for the `insideFlag` array per ray and the ray-layer buffer [S1]. The buffer size depends on the number of layers per ray [S1].
*   **Strengths:** Preserves VOI priority and ID information which is critical for layer placement, unlike standard GPU stencil buffers [S1]. Allows for view-dependent simplification of bounding boxes to reduce layer complexity [S1].
*   **Limitations:** Complex implementation due to custom stencil-like tests in GPU programs [S1]. Identical depth handling requires additional encoding or color buffer tricks [S1].
*   **When to Use:** When rendering complex scenes with multiple overlapping VOIs requiring precise material ID and priority-based layering [S1].
*   **When Not to Use:** When hardware limitations prevent modified depth testing and color buffer alternatives are insufficient [S1].

## Background
The method originates from the work on Multi-layer Volume Ray Casting on GPU, which introduced the concept of generating ray-layer buffers via depth-peeling VOI definitions to handle complex volume interactions [S1]. It was developed to address the limitations of standard GPU-based CSG stencil buffers in preserving VOI-specific metadata [S1]. Dual Depth Peeling was later proposed as an optimization to reduce the number of rendering passes [S2].
