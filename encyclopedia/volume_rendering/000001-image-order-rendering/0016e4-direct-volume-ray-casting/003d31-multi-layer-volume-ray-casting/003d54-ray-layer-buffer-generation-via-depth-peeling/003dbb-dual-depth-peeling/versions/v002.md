# Dual Depth Peeling

Also called: Bidirectional Depth Peeling, Depth Peeling Rendering Pipeline, Depth peeling loop, On-the-fly front-to-back peeling

## Overview
Dual Depth Peeling is an order-independent transparency (OIT) technique that decomposes a scene into depth layers by rendering primitives multiple times, discarding fragments closer than the previously peeled layer, and blending the resulting layers to assemble the final image [S1]. It improves upon standard Depth Peeling by performing simultaneous peeling in both directions—front-to-back and back-to-front—thereby reducing the total number of rendering passes required for $N$ layers by approximately half ($N/2$) [S2]. Unlike standard depth sorting, which fails on self-intersecting surfaces, Dual Depth Peeling resolves depth ordering per pixel, making it suitable for complex integral surfaces [S1].

## How it works
The method executes a peeling loop for each frame, where each iteration consists of a **peel stage** and a **blend stage** [S1]. The loop adaptively terminates when no pixels are rendered in the peel stage, determined via an occlusion query [S1]. The total number of iterations equals one greater than the number of surface layers for the current viewpoint [S1].

### Inputs and Outputs
*   **Inputs:** Discrete representation of the integral surface (triangles or quadrilaterals) with associated texture coordinates; lighting model parameters; silhouette color; transparency parameters [S1].
*   **Outputs:** Final blended RGBA image in a floating-point color buffer [S1].

### Data Structures
1.  **Color Buffer:** Floating-point RGBA buffer for improved blending accuracy to avoid banding artifacts with many layers [S1].
2.  **Normal Buffer:** Secondary floating-point RGBA buffer storing surface normals required for the blend stage [S1].
3.  **Mask Buffer:** Stored in the secondary A-component of the Normal Buffer; indicates whether a pixel belongs to the integral surface or the context [S1].
4.  **Depth Texture:** Stores the depth information of the current surface layer, required for the depth peeling algorithm [S1].

### Pseudocode
The following pseudocode describes the adaptive peeling loop. It assumes standard OpenGL/GLSL context where `glBeginQuery`/`glEndQuery` and `glGetQueryObjectiv` are available for occlusion queries.

```python
def dual_depth_peeling_loop(scene_primitives, max_layers):
    # Initialize buffers
    color_buffer = create_floating_point_rgba_buffer()
    normal_buffer = create_floating_point_rgba_buffer() # A-component used as mask
    depth_texture = create_depth_texture()
    
    # Set up stencil or depth test to discard fragments closer than previous layer
    # Initial state: discard nothing (or use a very large depth value)
    previous_depth_limit = INFINITY 
    
    layer_count = 0
    total_passes = 0
    
    while layer_count < max_layers:
        # 1. Peel Stage
        # Check if any pixels will be rendered to adaptively terminate
        start_occlusion_query()
        
        render_scene_with_depth_test(scene_primitives, previous_depth_limit)
        
        end_occlusion_query()
        
        # Check if any fragments were rendered
        if not occlusion_query_result_is_positive():
            break
            
        # Compute shading and transparency
        # Alpha final calculation depends on modulation type
        # Multiplicative: alpha_final = alpha_view * alpha_tex + alpha_specular
        # Additive: alpha_final = alpha_view + alpha_tex + alpha_specular
        # Color final: c_final = c_diffuse * c_tex + c_specular
        write_to_color_buffer_and_normal_buffer()
        
        # Update depth limit for next pass
        # The depth texture now holds the depth of the peeled layer
        previous_depth_limit = get_max_depth_from_depth_texture()
        
        layer_count += 1
        total_passes += 1
        
        # 2. Blend Stage
        # Determine silhouette strength using Sobel filter on normal and depth buffers
        silhouette_strength = compute_sobel_edge_detection(normal_buffer, depth_texture, mask_buffer)
        
        # Fade surface color into silhouette color based on strength
        blended_color = apply_silhouette_fading(color_buffer, silhouette_strength)
        
        # Blend into final output
        # Note: Standard depth peeling blends front-to-back or back-to-front.
        # Dual depth peeling performs this blending logic for the peeled layer.
        # The specific blending equation for the final image assembly is not detailed 
        # beyond the layer composition in the sources, but typically involves over-blending.
        update_color_buffer(blended_color)
        
    return color_buffer
```

### Formulas
The final RGBA output $(c, \alpha)_{peel}$ of the peel pass is computed as follows [S1]:

**Multiplicative Modulation:**
$$ \alpha_{final} = \alpha_{view} \cdot \alpha_{tex} + \alpha_{specular} $$
$$ c_{final} = c_{diffuse} \cdot c_{tex} + c_{specular} $$

**Additive Modulation:**
$$ \alpha_{final} = \alpha_{view} + \alpha_{tex} + \alpha_{specular} $$

Where:
*   $\alpha_{view}$: View-dependent transparency term computed from the normal vector. For normal-variation transparency, partial derivatives are evaluated using `dFdx` and `dFdy` [S1].
*   $\alpha_{tex}$: Texture opacity obtained via procedural evaluation or texture lookup [S1].
*   $\alpha_{specular}$: Specular highlight alpha term [S1].
*   $c_{diffuse}$: Diffuse surface color evaluated via Phong or Gooch lighting model [S1].
*   $c_{tex}$: Texture color [S1].
*   $c_{specular}$: Specular highlight color [S1].

### Parameters
*   **Lighting Model:** Phong or Gooch [S1].
*   **Silhouette Color:** User-specified color for fading [S1].
*   **Edge Detection Filter:** Sharp and symmetric Sobel filter [S1].

### Edge Cases and Pitfalls
1.  **Silhouette Width:** Silhouettes are extracted twice (once per pair of successive depth layers), potentially resulting in inner silhouettes of increased width. This is mitigated by using a sharp and symmetric edge detection filter [S1].
2.  **Banding Artifacts:** Slight banding artifacts can appear if blending directly to the output framebuffer with many surface layers. A floating-point color buffer is required for improved accuracy [S1].
3.  **Depth Sorting Precision:** Elements at different depths may still be stored within the same layer if no intermediate geometry occludes them, reducing depth-sorting precision [S2].
4.  **Self-Intersection:** Unlike depth sorting, this method handles self-intersecting surfaces correctly because depth ordering is resolved per pixel [S1].

## Operating characteristics
*   **Complexity:** Rendering speed is largely a function of surface geometry size. The total rendering time is dominated by the requirement to submit the surface for rendering multiple times during the depth peeling loop [S1].
*   **Performance:** On moderately current graphics hardware (NVIDIA GTX280), interactive frame rates exceeding 15fps are achieved for small to medium meshes (below ≈500K triangles) with medium depth complexity (10 layers or less) [S1].
*   **Scalability:** Larger meshes with many layers result in correspondingly smaller frame rates due to the increased number of peeling passes [S1].
*   **Strengths:** Resolves depth ordering per pixel, handling self-intersecting surfaces; reduces pass count by half compared to standard depth peeling [S1, S2].
*   **Limitations:** Performance degrades with high depth complexity and large mesh sizes; potential for increased silhouette width; precision loss if intermediate occluders are absent [S1, S2].

## Background
Dual Depth Peeling was proposed as an improvement to the standard Depth Peeling algorithm to reduce the number of rendering passes required for order-independent transparency [S2]. It allows simultaneous peeling in both directions: from the camera to the background and from the background to the camera [S2]. The technique is implemented in OpenGL using GLSL shader programs, though the concepts are portable to DirectX [S1]. It is particularly useful in illustrative rendering for integral surfaces, such as streamlines on stream surfaces, where path surfaces often self-intersect [S1].
