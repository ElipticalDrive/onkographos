# Irradiance Caching
## Overview
Irradiance caching is a technique to compute an expensive quantity, the fluence rate $G$, exactly at a sparse set of points and interpolate the value everywhere else, reducing the number of exact evaluations required [S1, unofficial]. It sets itself apart from its siblings by caching the scalar value of the quantity rather than directional radiance, relying on the assumption that the quantity is smooth over local regions [S1, unofficial]. Unlike [Radiance Caching (Jarosz et al.)](8493-radiance-caching-jarosz-et-al.md) which caches directional information, or the [Light Cache Rendering Pipeline](9159-light-cache-rendering-pipeline.md) which uses a different sampling strategy, irradiance caching focuses on spatial interpolation of a scalar field [S1, unofficial].

## How it works
**Inputs:** A set of receiver points (e.g., cell centers in a mesh) where the quantity $G$ is needed; a method to compute $G$ exactly at a point (e.g., a gather operation) [S1, unofficial].
**Outputs:** An interpolated value of $G$ for every receiver point [S1, unofficial].

**Data Structures:**
*   **Cache Record:** Stores the exact value of $G$, the position of the receiver, and a validity radius $r$. For the gradient variant, it also stores the spatial gradient $\nabla G$. Exact field layouts and bit packing are Not given in the sources.
*   **Visibility Mask:** A structure representing the visibility from the receiver to light sources, used to prevent interpolation across shadow edges [S1, unofficial].

**Steps:**
1.  **Exact Evaluation:** For a subset of receivers (typically cell centers), compute the quantity $G$ exactly using the gather method [S1, unofficial].
2.  **Gradient Computation (Optional):** If using irradiance gradients, compute the spatial gradient $\nabla G$ at the receiver position via forward-mode differentiation with respect to the receiver position during the gather itself, at a small multiple of the value's cost [S1, unofficial].
3.  **Validity Radius Calculation:** Determine the validity radius $r$ for the cached record. This radius is set by an error estimate, specifically the harmonic mean distance to the surfaces seen by the receiver [S1, unofficial]. The radius must be derived from a bound or measured local variation, not a fixed spacing [S1, unofficial].
4.  **Caching:** Store the value $G$, position, radius $r$, and visibility mask in the cache. If using gradients, store $\nabla G$ as well [S1, unofficial].
5.  **Interpolation:** For remaining receivers, search the cache for a record whose validity radius covers the receiver's position and whose visibility mask matches the receiver's [S1, unofficial].
    *   If a match is found, interpolate the value. For basic caching, use zero-order (constant) interpolation: $G_{interp} = G_{cached}$ [S1, unofficial].
    *   For irradiance gradients, use first-order interpolation: $G_{interp} = G_{cached} + \nabla G_{cached} \cdot (P_{receiver} - P_{cached})$ [S1, unofficial].
    *   If no match is found, compute $G$ exactly and add a new record to the cache [S1, unofficial].

**Parameters:**
*   **Validity Radius:** Determined by the harmonic mean distance to visible surfaces [S1, unofficial].
*   **Error Threshold:** Implicitly handled by the radius calculation; records are invalid if the local variation exceeds the bound implied by the radius [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Shadow Edges:** Interpolating across a shadow edge smears the shadow. Records must not be shared across a change in the visibility mask. The validity test must use the visibility mask (e.g., via conservative shaft certificates) so a record serves only points in tiles with the same certificate [S1, unofficial].
*   **Fixed Spacing:** Using a fixed spacing for the cache grid is incorrect. The error estimate determining the record's radius must come from a bound or measured local variation [S1, unofficial].

## Subtopics

### Irradiance Gradients
An extension of irradiance caching that caches the spatial gradient of the quantity in addition to the value, allowing first-order interpolation [S1, unofficial]. It is chosen when higher accuracy is needed over larger distances, as caching the gradient widens each record's valid radius because first-order interpolation is more accurate than zero-order (constant) interpolation [S1, unofficial]. The cost of computing the gradient adds a small multiple of the value's cost to the exact evaluation [S1, unofficial]. It was introduced by Ward & Heckbert in 1992 [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Reduces the number of exact evaluations from $O(N)$ to $O(N/k)$ where $k$ is the average number of receivers served by one cache record. The interpolation cost is $O(1)$ per receiver [G].
*   **Memory Complexity:** $O(M)$ where $M$ is the number of cache records [G].
*   **Strengths:** Significantly reduces computation for smooth quantities. Composes well with emitter clustering methods [S1, unofficial].
*   **Limitations:** Fails to capture sharp discontinuities (shadow edges) without careful visibility handling. Gradient computation adds a small multiple of the value's cost via forward-mode differentiation during the gather [S1, unofficial].
*   **When to Use:** When the quantity being computed is smooth over local regions and exact evaluation is expensive [S1, unofficial].
*   **When Not to Use:** When the quantity has sharp discontinuities that cannot be handled by visibility masks, or when memory is extremely constrained [G].

## Background
Irradiance caching was introduced by Ward, Rubinstein & Clear in SIGGRAPH 1988 [S1, unofficial]. It is based on the assumption that volume material scatters light isotropically, allowing the lighting distribution inside the volume to be pre-computed and stored in an illumination cache [Parent]. The technique is particularly useful in radiation transport problems where the fluence rate is smooth almost everywhere, varying sharply only near light sources or across shadow edges [S1, unofficial].
