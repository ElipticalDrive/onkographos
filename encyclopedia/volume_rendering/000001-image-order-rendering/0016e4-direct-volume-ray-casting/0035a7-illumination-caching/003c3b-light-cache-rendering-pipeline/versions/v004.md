# Light Cache Rendering Pipeline

Also called: GPU Volume Ray-Caster with Light Cache, Illumination Cache Volume Rendering, TBRayMarcher, TBRayMarcher Plugin

## Overview
The Light Cache Rendering Pipeline is a GPU volume ray-casting technique that pre-computes lighting distributions inside a volume and stores them in an illumination cache, drastically improving rendering performance [S1, S2, unofficial]. Unlike standard ray-marching which recalculates illumination per frame, this method exploits the assumption of isotropic light scattering to separate volume density evaluation from lighting computation, allowing for fast updates when only light positions change [S1, S2, unofficial]. It sets itself apart from siblings like Radiance Caching by using aggregate queries on a 3D Summed Area Table (SAT) for speed, yielding results similar in quality to dense sampling but much faster [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume dataset $V$, Transfer Function $TF$, Light sources $L$, Camera parameters.
*   **Output:** Rendered image pixels.
*   **Intermediate Data Structures:**
    *   **Volume Texture $V$:** 3D texture storing volume data, normalized to 8-bit precision to fit within texture constraints [S1, unofficial].
    *   **Light Cache Texture $T$:** 3D texture containing summation terms for Ambient Occlusion (AO)/color bleeding and directional shadows in different channels [S2, unofficial].
    *   **SAT Texture $S$:** 3D Summed Area Table texture constructed from the transfer-function-applied volume texture [S2, unofficial].

**Data Structures and Layout:**
*   **Volume Texture $V$:** Stores the scalar field values. For large datasets, chunked into sub-volumes (e.g., max 2048 voxels per dimension in DX11/DX12) [S1, unofficial].
*   **Light Cache Texture $T$:** Stores pre-computed attenuation factors. One channel (or set of channels) for AO/color bleeding, others for directional shadows per light source [S2, unofficial].
*   **SAT Texture $S$:** Stores cumulative sums of extinction coefficients to enable $O(1)$ neighborhood queries [S2, unofficial].

**Algorithm Steps:**

1.  **Check for Changes:** Determine if the Transfer Function ($TF$) or light positions ($L$) have changed relative to the volume dataset [S2, unofficial].
2.  **Update Light Cache (if $TF$ changed):**
    a.  Apply $TF$ to volume $V$ and store result to texture $T$ [S2, unofficial].
    b.  Compute SAT from texture $T$ using recursive doubling with ping-pong textures $S$ and $T$. Store SAT to $S$ [S2, unofficial].
    c.  **Compute AO/Color Bleeding:** For each voxel in $S$, sample shells from $S$, sum weighted shells, and store the sum to texture $T$ [S2, unofficial]. This computes the aggregate extinction over a neighborhood $\Omega$ [S2, unofficial].
3.  **Update Directional Shadows (if $L$ or $TF$ changed):**
    a.  For each light source $L$:
    b.  For each voxel in $S$, query cuboids towards light source $L$, sum weighted cuboids, and store sum to texture $T$ [S2, unofficial].
4.  **Ray-Casting Pass:**
    a.  For each pixel on screen:
    b.  Compute entry and exit points for volume $V$ [S2, unofficial].
    c.  Compute ray $R$ from entry and exit points [S2, unofficial].
    d.  For each sample position $P$ along ray $R$:
        i.  Lookup volume $V$ and apply $TF$ [S2, unofficial].
        ii. Lookup texture $T$ (Light Cache) [S2, unofficial].
        iii. Evaluate illumination model using the cached terms [S2, unofficial].
        iv. Add contribution to pixel [S2, unofficial].

**Formulas:**
The attenuation factor $\tau_L$ for a light source $L$ is computed as $e^{-\int \tau(t) dt}$, where $\tau(t)$ is the extinction coefficient [S2, unofficial]. In the discretized setup, this involves the sum of extinction coefficients $\sum_{\Omega} \Delta t \tau_j$ over a voxel neighborhood $\Omega$ [S2, unofficial]. The SAT allows efficient computation of these sums via aggregate queries [S2, unofficial].

**Parameters:**
*   **Rendering Backend:** DirectX 11 is required for best performance; DirectX 12 has unresolved issues, and Vulkan does not work [S1, unofficial].
*   **Data Precision:** Voxel data is normalized to 8-bit precision [S1, unofficial].
*   **Max Texture Extent:** 2048 voxels per dimension in DX11/DX12 [S1, unofficial].

**Pitfalls and Edge Cases:**
*   **Chunking Artifacts:** Large datasets must be chunked due to texture size limits [S1, unofficial]. This causes incorrect lighting at chunk borders because each chunk is illuminated independently, making borders incorrectly bright [S1, unofficial].
*   **VRAM Limits:** Crashes can occur well below the 2048 voxel limit due to VRAM fragmentation and available memory [S1, unofficial].
*   **TF Changes:** If the Transfer Function changes, the entire light cache (SAT and shadow factors) must be recomputed [S2, unofficial].
*   **Light Position Changes:** If only light positions change, only directional shadow factors need recomputation [S2, unofficial].

**Pseudocode:**

```python
def light_cache_rendering_pipeline(volume_V, transfer_function, light_sources, camera):
    """
    Main rendering pipeline for Light Cache Volume Rendering.
    """
    # Check if TF or lights changed (implementation-specific check)
    tf_changed = True  # [G] Standard change detection logic
    lights_changed = True  # [G] Standard change detection logic

    if tf_changed:
        # Apply TF to volume V and store result to texture T
        texture_T = apply_transfer_function_to_volume(volume_V, transfer_function)
        
        # Compute SAT from texture T using recursive doubling with ping-pong textures S, T
        texture_S = compute_sat_recursive_doubling(texture_T)
        
        # Compute Ambient Occlusion / Color Bleeding factors
        for voxel in texture_S:
            # Sample shells from S
            shells = sample_shells_from_sat(texture_S, voxel)
            # Sum up weighted shells
            ao_factor = sum_weighted_values(shells)
            # Store sum to texture T (AO channel)
            texture_T.set_ao(voxel, ao_factor)

    if lights_changed or tf_changed:
        # Compute Directional Shadow factors
        for light in light_sources:
            for voxel in texture_S:
                # Query cuboids towards light source L
                cuboids = query_cuboids_towards_light(texture_S, voxel, light)
                # Sum up weighted cuboids
                shadow_factor = sum_weighted_values(cuboids)
                # Store sum to texture T (Shadow channel for light)
                texture_T.set_shadow(voxel, light, shadow_factor)

    # Ray Casting Pass
    image = create_empty_image()
    for pixel in image:
        # Compute entry and exit point for volume V
        entry, exit = compute_ray_bounds_volume(pixel, camera, volume_V)
        # Compute ray R
        ray = create_ray_from_points(entry, exit)
        
        accumulated_color = 0
        for sample_pos in ray.samples():
            # Lookup volume V and apply transfer function
            density = lookup_volume_data(volume_V, sample_pos)
            tf_value = apply_transfer_function_value(density, transfer_function)
            
            # Lookup texture T (Light Cache)
            ao_factor = lookup_light_cache_ao(texture_T, sample_pos)
            shadow_factors = lookup_light_cache_shadows(texture_T, sample_pos, light_sources)
            
            # Evaluate illumination model using the cached terms
            illumination = evaluate_illumination_model(tf_value, ao_factor, shadow_factors, light_sources)
            
            # Add contribution to pixel
            accumulated_color += illumination
            
        image[pixel] = accumulated_color

    return image

# Helper functions (standard operations)
def apply_transfer_function_to_volume(volume_V, transfer_function):
    """Applies transfer function to volume data and returns texture T."""
    return [transfer_function(v) for v in volume_V]

def compute_sat_recursive_doubling(texture_T):
    """Computes 3D SAT from texture T using recursive doubling with ping-pong textures."""
    # Standard SAT computation via recursive doubling
    return compute_3d_sat(texture_T)

def sample_shells_from_sat(texture_S, voxel):
    """Samples spherical shells around a voxel in the SAT."""
    return [texture_S.query_shell(voxel, radius) for radius in shell_radii]

def sum_weighted_values(values):
    """Sums weighted values."""
    return sum(v * w for v, w in zip(values, weights))

def query_cuboids_towards_light(texture_S, voxel, light):
    """Queries cuboids towards a light source in the SAT."""
    return [texture_S.query_cuboid(voxel, light.direction) for cuboid in cuboids]

def create_empty_image():
    """Creates an empty image buffer."""
    return {}

def compute_ray_bounds_volume(pixel, camera, volume_V):
    """Computes entry and exit points for a ray through volume V."""
    return camera.ray_intersect_volume(pixel, volume_V)

def create_ray_from_points(entry, exit):
    """Creates a ray from entry and exit points."""
    return Ray(entry, exit - entry)

def lookup_volume_data(volume_V, sample_pos):
    """Looks up volume data at a sample position."""
    return volume_V.sample(sample_pos)

def apply_transfer_function_value(density, transfer_function):
    """Applies transfer function to a single density value."""
    return transfer_function(density)

def lookup_light_cache_ao(texture_T, sample_pos):
    """Looks up AO factor from light cache texture T."""
    return texture_T.sample_ao(sample_pos)

def lookup_light_cache_shadows(texture_T, sample_pos, light_sources):
    """Looks up shadow factors from light cache texture T."""
    return [texture_T.sample_shadow(sample_pos, light) for light in light_sources]

def evaluate_illumination_model(tf_value, ao_factor, shadow_factors, light_sources):
    """Evaluates illumination model using cached terms."""
    # Standard volumetric shading using cached terms [G]
    return tf_value * ao_factor * sum(shadow_factors)
```

## Subtopics

### [Photon Map Caching for Volumes](14012-photon-map-caching-for-volumes.md)
Photon Map Caching for Volumes is a global illumination (GI) acceleration technique designed for slow-moving or evolving volumetric scenes, such as cumulus clouds. It addresses the high computational cost of calculating light bounces inside participating media by pre-computing and caching photon maps. Unlike standard ray-marching which recalculates illumination per frame, this method caches indirect lighting data, significantly speeding up rendering when the scene geometry and lighting remain static.

## Operating characteristics
*   **Time Complexity:** The pre-computation of the SAT is $O(N)$ where $N$ is the number of voxels. The AO/shadow factor computation is also efficient due to aggregate queries. The ray-casting pass is $O(P \cdot S)$ where $P$ is pixels and $S$ is samples per ray, but lighting evaluation is $O(1)$ due to cache lookup [S2, unofficial].
*   **Memory Complexity:** Requires storing Volume Texture $V$, Light Cache Texture $T$, and SAT Texture $S$. Memory usage scales with volume resolution and number of light sources [S1, S2, unofficial].
*   **Measured Performance:** Aggregate sampling is over 45 times faster than individual neighborhood sampling (0.22s vs 10s) with virtually no difference in image quality [S2, unofficial].
*   **Strengths:** Drastic performance improvement for static or slowly changing lighting scenarios; efficient updates for light position changes [S1, S2, unofficial].
*   **Limitations:** Requires isotropic scattering assumption; chunking artifacts at borders; VRAM limitations; backend dependency (DX11 best) [S1, unofficial].
*   **When to Use:** Static or slowly evolving volumetric scenes with isotropic scattering, where lighting changes are limited to light position or TF updates [S1, S2, unofficial].

## Background
The method is based on an implementation by Sundén and Ropinski [S1, unofficial]. It is implemented in the TBRayMarcher Plugin for Unreal Engine [S1, unofficial]. The technique relies on the assumption that volume material scatters light isotropically, allowing the lighting distribution inside the volume to be pre-computed and stored in an illumination cache [S1, unofficial]. This approach was developed to address the high computational cost of calculating light bounces inside participating media [S1, unofficial].
