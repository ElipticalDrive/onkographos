# Radiance Caching (Jarosz et al.)
Also called: Jarosz Radiance Caching, Jarosz et al. Radiance Caching, Log-space extrapolation caching, Original radiance caching

## Overview
Radiance caching pre-computes and stores directional radiance distributions at sparse points within a volume using spherical harmonics (SH) and gradient information [S1]. It reduces per-pixel lighting costs in participating media by interpolating illumination from these cached samples rather than computing it from scratch [S1].

## How it works
**Inputs:** Sparse set of cache points $\{x_k\}$ within the volume, each storing SH coefficients $\lambda_l^m$ for the incoming radiance distribution and a translational gradient $\nabla L_k$ [S1, S2].
**Outputs:** Interpolated radiance $L(x', \omega_o)$ at an arbitrary query point $x'$ [S2].

**Data Structures:**
*   **Cache Point:** Spatial location $x_k$ with associated SH coefficients $\lambda_l^m$ and gradient $\nabla L_k$ [S1, S2].
*   **SH Coefficients:** Vector $\lambda_l^m$ representing the angular radiance distribution $L_i(\theta, \phi)$ at $x_k$ [S3, unofficial].
*   **Gradient:** Translational derivative $\nabla L_k$ used for log-space extrapolation [S2].
*   **Weighting Function:** $w(x_k, x')$ that diminishes to zero as the query point approaches the cache point's valid radius [S2].
*   **Valid Radius:** Scalar $R$ defining the interpolation support region for each cache point [S2].

**Steps:**
1.  **Pre-computation:** Ray-march through the volume to sample incoming radiance $L_i$ at sparse points [S3, unofficial]. Project $L_i$ onto SH basis functions using Monte Carlo quadrature [S3, unofficial].
2.  **Gradient Computation:** Compute translational gradients $\nabla L_k$ for each cache point [S2]. For single scattering, Monte Carlo sample the first derivative in surface-area form by tracing rays in a sphere around $x_k$ to fixed hit points $y_s$, tracking transmittance and geometry changes as $x_k$ translates [S2]. For multiple scattering, Monte Carlo sample the first derivative assuming sampled paths move rigidly, accounting for translational derivatives at each scattering vertex [S2].
3.  **Query & Interpolation:** For a query point $x'$, find the set of nearby cache points $C$ whose valid radii contain $x'$ [S2]. Compute the log-space translational gradient $\nabla \ln L_k = \nabla L_k / L_k$ [S2]. Interpolate radiance using log-space extrapolation [S2].
4.  **Adaptive Sampling:** If no nearby cache points are found, compute radiance via Monte Carlo sampling, insert the value and gradient into the cache, and update the valid radius using the error metric [S2].

**Formulas:**
The radiance distribution $L_i(\theta, \phi)$ at a cache point is represented as:
$$ L_i(\theta, \phi) = \sum_{l=0}^{n-1} \sum_{m=-l}^{l} \lambda_l^m Y_{lm}(\theta, \phi) $$
where $n$ is the order of the SH representation, $Y_{lm}$ are the spherical harmonic basis functions, and $\lambda_l^m$ are the coefficients [S3, unofficial].

The coefficients are computed via Monte Carlo quadrature with uniform sampling [S3, unofficial]:
$$ \lambda_l^m = \frac{4\pi}{N} \sum_{j=1}^{N} L_i(\theta_j, \phi_j) Y_{lm}(\theta_j, \phi_j) $$
where $N$ is the total number of samples, and $(\theta_j, \phi_j)$ are the sampled directions [S3, unofficial].

The radiance at a query point $x'$ is interpolated using log-space extrapolation [S2]:
$$ L(x', \omega_o) \approx \exp\left( \frac{\sum_{k \in C} (\ln L_k + \nabla \ln L_k \cdot \Delta x') w(x_k, x')}{\sum_{k \in C} w(x_k, x')} \right) $$
where $\Delta x' = x' - x_k$, $\nabla \ln L_k = \nabla L_k / L_k$, and $w(x_k, x')$ is the weighting function [S2].

The valid radius $R$ is calculated using an error metric [S2]:
$$ R = \epsilon \frac{\sum L_j}{\sum \|\nabla L_j\|} $$
where $\epsilon$ is a global error tolerance parameter, and $L_j$ and $\nabla L_j$ are individual Monte Carlo samples of radiance and translational gradient respectively [S2].

**Parameters:**
*   **SH Order ($n$):** 2nd order is used to map the four coefficients to standard four-component graphics hardware buffers [S3, unofficial].
*   **Sample Count ($N$):** Number of random directions for Monte Carlo integration; computed via stratified sampling [S3, unofficial].
*   **Error Tolerance ($\epsilon$):** Global parameter controlling the valid radius calculation [S2].

**Edge Cases and Pitfalls:**
*   **Occlusion Mismatch:** Sparse cache points may experience different occlusion than query points, causing illumination errors since visibility is not considered during interpolation [S1].
*   **Ad-hoc Error Metric:** The radius metric $R$ is an approximation of log-scale interpolation error, which can lead to difficulty predicting sample distribution error and suboptimal cache placement [S2].

**Pseudocode:**
```python
def interpolate_radiance(query_point, cache_points, epsilon):
    nearby = []
    for point in cache_points:
        # Calculate valid radius R from Monte Carlo samples [S2]
        sum_L = sum(sample.L for sample in point.mc_samples)
        sum_grad_norm = sum(norm(sample.grad_L) for sample in point.mc_samples)
        R = epsilon * (sum_L / sum_grad_norm)
        
        # Check if query point falls within valid radius
        if distance(query_point, point.position) <= R:
            nearby.append(point)
            
    if not nearby:
        # No cache points found; trigger Monte Carlo sampling and cache insertion [S2]
        return None
        
    numerator = 0.0
    denominator = 0.0
    for point in nearby:
        delta_x = query_point - point.position
        log_L = log(point.L)
        log_grad = point.grad_L / point.L
        weight = weighting_function(point.position, query_point, R)
        
        numerator += (log_L + dot(log_grad, delta_x)) * weight
        denominator += weight
        
    interpolated_L = exp(numerator / denominator)
    return interpolated_L
```

## Subtopics

### [Second-Order Occlusion-Aware Volumetric Radiance Caching](19428-second-order-occlusion-aware-volumetric-radiance-caching.md)
Second-Order Occlusion-Aware Volumetric Radiance Caching is a radiance caching algorithm for participating media that uses second-order gradient analysis (Hessian) of light transport to adaptively sample and interpolate radiance from sparse cache points, accounting for occlusion changes. It solves the problem of suboptimal cache distribution in scenes with complex shadows by deriving a Hessian-based error metric that predicts extrapolation error more accurately than first-order gradient methods. Unlike its parent [Radiance Caching (Jarosz et al.)](8493-radiance-caching-jarosz-et-al.md), which relies on spherical harmonics and first-order gradients, this method uses a proxy triangulation-based representation to compute occlusion-aware derivatives, preventing the concentration of cache points near reflecting geometry and enabling efficient capture of high-frequency shadow boundaries.

### Volume Sampling and Radiance Caching
This variant explicitly computes the incoming radiance distribution for each voxel by ray-marching through the volume and storing the result as spherical harmonic coefficients [S3, unofficial]. It differs from the general Jarosz method by defining a voxel-based grid for caching rather than arbitrary sparse points [S3, unofficial]. It is chosen when a structured voxel representation is already available or when integrating with deferred rendering pipelines that update voxels based on visible surface reprojection [S3, unofficial]. The implementation uses 2nd-order SH (4 coefficients) to fit into standard 4-component framebuffers [S3, unofficial]. Coefficients are computed using Monte Carlo quadrature with stratified sampling of $N$ random directions per voxel [S3, unofficial].

## Operating characteristics
**Time Complexity:** Pre-computation is expensive due to ray-marching and gradient computation per cache point [S2][S3, unofficial]. Query time is fast, dominated by interpolation and SH evaluation [S1, S2].
**Memory Complexity:** Scales linearly with the number of cache points times the number of SH coefficients per point [S3, unofficial].
**Measured Performance:** Related implementations show ray-marching times for GI per bounce around 4.3–4.6 ms on a NVIDIA GTX460 for scenes with 10k–260k triangles, while AO is faster due to limited ray distance [S3, unofficial].
**Strengths:** Reduces per-pixel lighting cost and provides smoother results than unfiltered sampling [S1].
**Limitations:** Sparse sampling causes visibility errors if occlusion is not considered during interpolation [S1]. The ad-hoc error metric can lead to suboptimal cache distribution [S2].
**When to use:** Suitable for scenes with smooth lighting variations where pre-computation cost is acceptable [S1].
**When not to use:** Scenes with complex, dynamic occlusion or high-frequency lighting details where the sparse cache cannot accurately represent the radiance field [S1, S2].

## Background
Radiance caching was introduced by Jarosz et al. [S1]. It is part of the broader field of illumination caching for volume rendering [S1]. The method was later improved by Marco et al. [S1], who introduced a second-order Hessian error metric to determine interpolation acceptability and consider visibility, resulting in higher quality than the original Jarosz method [S1].
