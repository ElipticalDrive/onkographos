# Image-Order Volumetric Compositing

Also called: Image-Order Compositing, Levoy's Image-Order Compositing, Levoy's Image-Order Volume Rendering

## Overview
Image-Order Volumetric Compositing is a volume rendering framework proposed by Marc Levoy, originally implemented on the PIXEL-PLANES 5 hardware [S1, unofficial]. It solves the problem of real-time volume visualization by precomputing color and opacity arrays from the raw scalar data, allowing the rendering loop to operate directly in image space rather than object space [S2, unofficial]. It sets itself apart from object-order methods by decoupling the shading and classification steps from the ray-casting loop, enabling efficient use of hardware acceleration for compositing [S1, unofficial].

## How it works
The method consists of a preprocessing phase to generate compositing arrays and a rendering phase to composite these arrays into an image [S2, unofficial].

### Inputs and Outputs
**Inputs:**
*   $S$: A 3D array of scalar data samples [S2, unofficial].
*   Camera parameters (view direction, projection) [G].
*   Iso-surface value $v$ and target opacity $v_{ought}$ (for classification) [S2, unofficial].
*   Gradient magnitude threshold or transition width parameter (for smoothing) [S2, unofficial].

**Outputs:**
*   $S_c$: A 3D array of color values (RGB) at each grid location [S2, unofficial].
*   $S_\alpha$: Precomputed opacity field [S2, unofficial].
*   Final 2D image.

### Data Structures
1.  **$S$**: Input scalar field. Layout: $S[x][y][z]$ where $x, y, z$ are grid indices [S2, unofficial].
2.  **$S_c$**: Precomputed color field. Layout: $S_c[x][y][z]$ storing RGB tuples [S2, unofficial].
3.  **$S_\alpha$**: Precomputed opacity field. Layout: $S_\alpha[x][y][z]$ storing scalar opacity [S2, unofficial].
4.  **Interpolation Functions**:
    *   $f(x,y,z)$: Trilinear interpolation function for sample values [S2, unofficial].
    *   $f_c(x,y,z)$: Trilinear interpolation function for color values [S2, unofficial].
    *   $f_\alpha(x,y,z)$: Trilinear interpolation function for opacity values [S2, unofficial].

### Steps

#### 1. Preprocessing: Generate $S_c$ and $S_\alpha$
This step transforms the raw scalar data $S$ into compositing-ready arrays [S2, unofficial].

1.  **Compute Gradients**: For each sample in $S$, compute the gradient vector $\nabla f$ [S2, unofficial]. The components are obtained by partially differentiating the interpolation function $f$ with respect to $x, y,$ and $z$ [S2, unofficial].
    *   *Note*: To avoid aliasing artifacts from discontinuous normal vectors, the interpolation function must be first derivative continuous [S2, unofficial]. A central differencing method is recommended for smoother gradient vectors [S2, unofficial].
2.  **Generate $S_c$ (Color)**: Perform a shading operation at each data sample [S2, unofficial].
    *   Use the unit gradient vector $\hat{n} = \frac{\nabla f}{\|\nabla f\|}$ as the surface normal [S2, unofficial].
    *   Apply a lighting model (e.g., Phong illumination) using $\hat{n}$ to compute the color [S2, unofficial].
3.  **Generate $S_\alpha$ (Opacity)**: Perform surface classification on $S$ to determine opacity [S2, unofficial].
    *   **Basic Classification**: For an iso-surface at constant value $v$ with desired opacity $v_{ought}$:
        $$ S_\alpha(x,y,z) = \begin{cases} v_{ought} & \text{if } f(x,y,z) = v \\ 0 & \text{otherwise} \end{cases} $$ [S2, unofficial].
    *   **Smoothed Classification**: To reduce aliasing, assign $S_\alpha(x,y,z)$ close to $v_{ought}$ if $f(x,y,z)$ is close to $v$ [S2, unofficial].
    *   **Transition Width**: To maintain a constant thickness of the transition region, the opacity should fall off at a rate inversely proportional to the magnitude of the local gradient vector $\|\nabla f\|$ [S2, unofficial].
    *   **Multiple Surfaces**: For multiple iso-surfaces, apply separate classification mappings and combine the resulting opacities [S2, unofficial].

#### 2. Rendering: Image-Order Compositing
Cast rays from the image plane through the precomputed arrays [S2, unofficial].

1.  **Ray Casting**: For each pixel, cast a ray through the volume [G].
2.  **Sampling**: Sample the arrays $S_c$ and $S_\alpha$ at evenly spaced locations along the ray [S2, unofficial].
    *   Use trilinear interpolation functions $f_c$ and $f_\alpha$ to determine the color $C_{sample}$ and opacity $\alpha_{sample}$ at each location [S2, unofficial].
3.  **Compositing**: Composite the samples in back-to-front order [S2, unofficial].
    *   Initialize accumulated color $C_{acc} = 0$ and accumulated opacity $\alpha_{acc} = 0$ [G].
    *   Add a fully opaque background (e.g., $C_{bg} = (1,1,1)$ or scene background) to ensure the ray has a final color if it exits the volume transparently [S2, unofficial].
    *   For each sample $i$ from back to front:
        $$ C_{acc} = C_{acc} + C_{sample,i} \cdot \alpha_{sample,i} \cdot (1 - \alpha_{acc}) $$
        $$ \alpha_{acc} = \alpha_{acc} + \alpha_{sample,i} \cdot (1 - \alpha_{acc}) $$ [G].
    *   Produce a single color that is placed in the pixel [S2, unofficial].

### Pseudocode

```python
def preprocess_volume(S, iso_value, target_opacity):
    """
    Preprocesses scalar volume S into color array Sc and opacity array S_alpha.
    """
    Dx, Dy, Dz = len(S), len(S[0]), len(S[0][0])
    Sc = [[[0.0, 0.0, 0.0] for _ in range(Dz)] for _ in range(Dy)]
    S_alpha = [[[0.0] for _ in range(Dz)] for _ in range(Dy)]

    for z in range(Dz):
        for y in range(Dy):
            for x in range(Dx):
                # Compute gradient by central differencing [S2, unofficial]
                gx = (S[x+1][y][z] - S[x-1][y][z]) / 2.0 if 0 < x < Dx-1 else 0.0
                gy = (S[x][y+1][z] - S[x][y-1][z]) / 2.0 if 0 < y < Dy-1 else 0.0
                gz = (S[x][y][z+1] - S[x][y][z-1]) / 2.0 if 0 < z < Dz-1 else 0.0
                grad_norm = (gx**2 + gy**2 + gz**2)**0.5

                # Generate Sc: Phong shading using unit gradient as normal [S2, unofficial]
                if grad_norm > 1e-6:
                    nx, ny, nz = gx/grad_norm, gy/grad_norm, gz/grad_norm
                    # Simplified Phong model [G]
                    diffuse = max(0.0, nx*0.5 + ny*0.5 + nz*0.8)
                    intensity = 0.2 + 0.8 * diffuse
                    Sc[x][y][z] = [intensity, intensity, intensity]
                else:
                    Sc[x][y][z] = [0.0, 0.0, 0.0]

                # Generate S_alpha: Classification [S2, unofficial]
                val = S[x][y][z]
                dist = abs(val - iso_value)
                # Smoothed classification: opacity falls off inversely proportional to grad_norm [S2, unofficial]
                if grad_norm > 1e-6:
                    S_alpha[x][y][z] = [target_opacity * max(0.0, 1.0 - dist / grad_norm)]
                else:
                    S_alpha[x][y][z] = [0.0]
    return Sc, S_alpha

def image_order_compositing(Sc, S_alpha, ray_origin, ray_direction, t_near, t_far, num_samples):
    """
    Renders the volume by casting rays and compositing precomputed arrays.
    """
    # Ray casting and back-to-front compositing [S2, unofficial]
    dt = (t_far - t_near) / num_samples
    samples = []
    for i in range(num_samples):
        t = t_near + i * dt
        # Trilinear interpolation [S2, unofficial]
        pos = (ray_origin[0] + t * ray_direction[0], 
               ray_origin[1] + t * ray_direction[1], 
               ray_origin[2] + t * ray_direction[2])
        c_sample = trilinear_interpolate(Sc, pos)
        a_sample = trilinear_interpolate(S_alpha, pos)
        samples.append((c_sample, a_sample))

    # Back-to-front compositing with opaque background [S2, unofficial]
    acc_color = (1.0, 1.0, 1.0)
    acc_alpha = 0.0
    for c_sample, a_sample in reversed(samples):
        weight = a_sample[0] * (1.0 - acc_alpha)
        acc_color = (
            acc_color[0] + c_sample[0] * weight,
            acc_color[1] + c_sample[1] * weight,
            acc_color[2] + c_sample[2] * weight
        )
        acc_alpha = acc_alpha + a_sample[0] * (1.0 - acc_alpha)
        if acc_alpha >= 1.0:
            break
    return acc_color

def trilinear_interpolate(grid, point):
    """Standard trilinear interpolation for 3D grid [G]."""
    x, y, z = point
    ix, iy, iz = int(x), int(y), int(z)
    fx, fy, fz = x - ix, y - iy, z - iz
    def v(x, y, z):
        x = max(0, min(x, len(grid)-1))
        y = max(0, min(y, len(grid[0])-1))
        z = max(0, min(z, len(grid[0][0])-1))
        return grid[x][y][z]
    c00 = [v(ix, iy, iz)*(1-fx) + v(ix+1, iy, iz)*fx for _ in range(3)]
    c01 = [v(ix, iy, iz+1)*(1-fx) + v(ix+1, iy, iz+1)*fx for _ in range(3)]
    c10 = [v(ix, iy+1, iz)*(1-fx) + v(ix+1, iy+1, iz)*fx for _ in range(3)]
    c11 = [v(ix, iy+1, iz+1)*(1-fx) + v(ix+1, iy+1, iz+1)*fx for _ in range(3)]
    top = [c00[i]*(1-fy) + c10[i]*fy for i in range(3)]
    bot = [c01[i]*(1-fy) + c11[i]*fy for i in range(3)]
    return [top[i]*(1-fz) + bot[i]*fz for i in range(3)]
```

### Parameters
*   **$v$**: Iso-surface value [S2, unofficial].
*   **$v_{ought}$**: Target opacity for the iso-surface [S2, unofficial].
*   **Interpolation**: Trilinear interpolation is specified for $f_c$ and $f_\alpha$ [S2, unofficial].

### Pitfalls
*   **Aliasing**: If the interpolation function is not first derivative continuous, aliasing artifacts occur due to discontinuous normal vectors during shading [S2, unofficial].
*   **Transition Region**: Failing to adjust opacity fall-off based on gradient magnitude can result in variable thickness of the rendered surface, leading to visual inconsistencies [S2, unofficial].

## Operating characteristics
*   **Performance**: The system achieved real-time or near real-time performance on the PIXEL-PLANES 5 hardware [S1, unofficial].
*   **Complexity**: The preprocessing step is $O(N)$ where $N$ is the number of voxels. The rendering step is $O(P \cdot R)$ where $P$ is the number of pixels and $R$ is the number of samples per ray [G].
*   **Strengths**: Decouples shading from rendering, allowing for efficient hardware compositing. Enables real-time performance on specialized hardware [S1, unofficial].
*   **Limitations**: Requires significant memory for precomputed $S_c$ and $S_\alpha$ arrays. Less flexible for dynamic transfer functions compared to object-order methods [G].

## Background
*   **Origin**: Proposed by Marc Levoy [S1, unofficial].
*   **Implementation**: Implemented on the PIXEL-PLANES 5 hardware, which consisted of 32 independently programmable 20-MFLOPS graphics processors, 16 independently programmable renderers with 1/4 million pixel processors, a 512x512 pixel color frame buffer, and a 640 Mb/sec ring network [S1, unofficial].
*   **History**: The method is described in Levoy's work on image-order volumetric compositing [S2, unofficial]. It was one of the early frameworks to achieve real-time volume rendering by leveraging parallel hardware and precomputed data structures [S1, unofficial].
