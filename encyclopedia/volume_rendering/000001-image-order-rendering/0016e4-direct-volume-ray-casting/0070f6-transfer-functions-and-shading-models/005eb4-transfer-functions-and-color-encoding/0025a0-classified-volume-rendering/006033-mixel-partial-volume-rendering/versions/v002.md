# Mixel Partial-Volume Rendering

Also called: voxel model v2 phase C

## Overview
Mixel Partial-Volume Rendering replaces synthetic, blur-derived partial-volume estimates with real, stored mixel fractions at tissue boundaries to blend rendered signals [S1, unofficial]. Unlike sibling methods that rely on geometric approximations or gradient-based shading, this method preserves the voxel's own texture detail ($S_a$) while blending in the second tissue's slice-mean signal ($S_b$) based on the specific mixel fraction [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel's rendered signal value ($S_a$), the second tissue's slice-mean signal ($S_b$), the mixel fraction ($f$), and a control parameter $pv\_sigma$ [S1, unofficial].
*   **Output:** The blended partial-volume signal value [S1, unofficial].

**Data Structures:**
The method relies on "sidecar" data structures containing pre-computed mixel fractions, stored as `.npy` files (e.g., `<Region>_mixel.npy`) associated with specific anatomical regions [S1, unofficial]. These sidecars must be aligned with the exact atlas transforms (straightening, flipping) applied to the volume [S1, unofficial].

**Parameters:**
*   $pv\_sigma$: Controls whether partial volume rendering is active; if $pv\_sigma = 0$, partial volume rendering is disabled [S1, unofficial].

**Steps:**
1. Check if $pv\_sigma = 0$. If true, disable partial volume rendering [S1, unofficial].
2. Determine if the current voxel is a mixed voxel (located at a tissue boundary where a second tissue exists) [S1, unofficial].
3. If the second tissue is absent, the voxel is pure; return $S_a$ unchanged without applying blending [S1, unofficial].
4. If the voxel is mixed, retrieve the real stored mixel fraction $f$ from the sidecar data [S1, unofficial].
5. Calculate the output signal using the linear blend formula:
   $$Output = f \cdot S_a + (1 - f) \cdot S_b$$
   Where $f$ is the mixel fraction, $S_a$ is the voxel's own rendered value, and $S_b$ is the second tissue's slice-mean signal [S1, unofficial].
6. Return the calculated $Output$ [S1, unofficial].

**Pseudocode:**
```python
def partial_volume_mixel(S_a, S_a, S_b, f, pv_sigma):
    """
    Blends voxel signal S_a with second tissue signal S_b using mixel fraction f.
    
    Args:
        S_a (float): The voxel's own rendered value.
        S_b (float): The second tissue's slice-mean signal.
        f (float): The real stored mixel fraction.
        pv_sigma (float): Control parameter. If 0, PV is disabled.
        
    Returns:
        float: The blended signal value.
    """
    # Step 1: Disable PV if parameter is zero [S1, unofficial]
    if pv_sigma == 0:
        return S_a
        
    # Step 3: Pure voxels (second tissue absent) skip blending [S1, unofficial]
    if f is None or f == 0:
        return S_a
        
    # Steps 4-5: Apply the partial-volume formula [S1, unofficial]
    output = f * S_a + (1 - f) * S_b
    
    return output
```

**Edge Cases and Pitfalls:**
*   **Atlas Transform Mismatch:** If atlas transforms (flip/straighten) are mismatched between the volume and the mixel sidecar, mixel fractions scatter off the 3x3x3 label boundaries, causing rendering errors [S1, unofficial].
*   **Guard Condition:** An objective test is required: >90% of mixed voxels must sit on the transformed atlas's 3x3x3 label boundaries [S1, unofficial].
*   **Sidecar-less Regions:** Regions without a mixel sidecar (e.g., Brain, synthetic fallbacks) keep the synthetic path unchanged [S1, unofficial].

## Operating characteristics
*   **Time and Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Relies on pre-computed sidecars, suggesting low runtime overhead compared to on-the-fly blur calculations [S1, unofficial].
*   **Scaling:** Performance scales with the number of mixed voxels and sidecar I/O; no explicit scaling metrics provided [S1, unofficial].
*   **Strengths and Limitations:** Preserves texture detail in $S_a$ better than synthetic blur methods because it uses real stored mixel fractions rather than approximations [S1, unofficial]. Highly dependent on correct atlas transforms and valid mixel sidecars, failing hard if the >90% boundary guard is not met [S1, unofficial].
*   **When to Use:** Suitable for MRI physics simulation platforms requiring accurate boundary blending for signal equations, k-space, EPI, Dixon, FSE/EPG, SENSE, diffusion, fMRI, and 3D slab acquisition [S1, unofficial].

## Background
This method was introduced as "voxel model v2, phase C" in the `mrisim` project by ea1188 [S1, unofficial]. It represents the final phase of the voxel-model-v2 specification, shifting from synthetic blur-derived mixel fractions to real stored ones [S1, unofficial]. It is wired at both partial-volume call sites: the image path and the quantitative-map PVE (Partial Volume Estimation) [S1, unofficial].
