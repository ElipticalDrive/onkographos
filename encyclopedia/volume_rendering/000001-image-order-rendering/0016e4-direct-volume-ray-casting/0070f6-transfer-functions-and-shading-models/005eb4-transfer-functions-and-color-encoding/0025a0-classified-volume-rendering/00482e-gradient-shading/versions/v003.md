# Gradient Shading
Also called: CT Viewer Volume Render, Phong Illumination with Gradient Lighting, Ray Casting with Gradient Shading, Volume Rendering with Gradient Shading, vzTMGradientShader

## Overview
Gradient Shading enhances surface perception in direct volume ray casting by computing per-voxel lighting from local intensity gradients using the Phong illumination model [S2]. It extends [Classified Volume Rendering](3590-classified-volume-rendering.md) by integrating gradient-based shading into the ray casting pipeline [S2]. The method supports maximum intensity projection (MIP) as an alternative rendering mode that selects the maximum intensity along the ray, ignoring opacity and color mapping [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume data texture, optional pre-computed gradient texture, transfer function lookup table, lighting parameters, and control flags [S1, unofficial][S2].
*   **Output:** Rendered image with shaded colors [S2].

**Data Structures:**
*   **Volume Texture ($V$):** Standard 3D texture storing voxel intensities [S2].
*   **Gradient Texture ($G$):** 3D texture storing gradient vectors [S2]. Each voxel stores RGB values representing the $(a, b, c)$ coefficients of the gradient at that position [S2].
    *   Format: If pre-computed, stored as `vzParameterVolumeTexture` [S2].
    *   Internal format for non-GPU fallback: `VZ_INTENSITYn` where $n \in \{8, 12, 16\}$ [S2].

**Steps:**
1.  **Gradient Preparation:** The application must compute the gradient texture and attach it to the shape's appearance [S2]. On GPU systems supporting `ARB_fragment_program`, if the gradient parameter is omitted, the shader computes gradients internally using central differencing [S2]. Using a separate gradient texture increases texture memory usage by a factor of two to four compared to the original volume texture [S2].
2.  **Ray Casting:** For each pixel, a ray is cast through the volume [S1, unofficial]. The volume texture is sampled at the current ray position to obtain the voxel intensity [S1, unofficial]. The transfer function maps the intensity to color $(R, G, B)$ and opacity $\alpha$ [S2].
3.  **Lighting Calculation:** The gradient vector $\vec{g}$ is retrieved from the gradient texture at the current position [S2]. The vector is normalized to form the surface normal $\vec{n}$ [S2]. The light direction vector $\vec{l}$ points from the surface point to the light source [S2]. The Phong shading components are computed as diffuse $k_d (\vec{n} \cdot \vec{l})$ and specular $k_s (\vec{r} \cdot \vec{v})^{\text{shininess}}$, where $\vec{r}$ is the reflection vector, $\vec{v}$ is the view vector, and $k_a, k_d, k_s$ are ambient, diffuse, and specular coefficients [S2]. These are combined with ambient light [S2].
4.  **Compositing:** Color and opacity are accumulated using front-to-back blending [S1, unofficial]. When `isGradient` is enabled, the calculated lighting modulates the color contribution [S1, unofficial].

**Parameters:**
*   `isGradient`: Boolean flag enabling/disabling gradient shading [S1, unofficial].
*   `isGradientInterpolation`: Boolean flag enabling/disabling gradient interpolation [S1, unofficial].
*   `lightSourceX`: Integer position of the light source along the X axis [S1, unofficial].
*   `gradient`: The gradient values, type `vzParameterVolumeTexture`. RGB values provide $(a, b, c)$ coefficients [S2].
*   `lightdir`: Light direction, type `vzParameterVec3f` [S2].
*   `lookup_table`: Transfer function lookup table, type `vzParameterLookupTable` [S2].
*   `ambient`: Ambient color, type `vzParameterVec3f` (optional) [S2].
*   `diffuse`: Diffuse color, type `vzParameterVec3f` (optional) [S2].
*   `specular`: Specular color, type `vzParameterVec3f` (optional) [S2].
*   `shininess`: Shininess exponent, type `vzParameterVec3f` (optional) [S2].

**Pseudocode:**
```python
def render_gradient_shading(volume_texture, gradient_texture, light_dir, ambient, diffuse, specular, shininess, is_gradient_enabled):
    image = [[0.0, 0.0, 0.0] for _ in range(height)]
    for y in range(height):
        for x in range(width):
            ray_origin = [0.0, 0.0, 0.0]  # Not given in the sources.
            ray_direction = [0.0, 0.0, 1.0]  # Not given in the sources.
            alpha_accum = 0.0
            color_accum = [0.0, 0.0, 0.0]
            t = 0.0
            while t < max_depth:
                pos = [ray_origin[i] + t * ray_direction[i] for i in range(3)]
                voxel_intensity = volume_texture.sample(pos)  # Not given in the sources.
                color, alpha = volume_texture.apply_transfer_function(voxel_intensity)  # Not given in the sources.
                if is_gradient_enabled:
                    if gradient_texture is not None:
                        gradient_vec = gradient_texture.sample(pos)
                    else:
                        # GPU fallback: compute central difference internally
                        gradient_vec = volume_texture.compute_central_difference(pos)  # Not given in the sources.
                    normal = normalize(gradient_vec)
                    light_dir_norm = normalize(light_dir)
                    view_dir = normalize([-ray_direction[i] for i in range(3)])
                    diff = max(dot(normal, light_dir_norm), 0.0)
                    reflect_dir = reflect(-light_dir_norm, normal)
                    spec = pow(max(dot(reflect_dir, view_dir), 0.0), shininess)
                    lighting = ambient + diffuse * diff + specular * spec
                else:
                    lighting = 1.0
                alpha_contrib = alpha * (1.0 - alpha_accum)
                color_accum = [color_accum[i] + color[i] * lighting * alpha_contrib for i in range(3)]
                alpha_accum += alpha_contrib
                if alpha_accum >= 1.0:
                    break
                t += step_size  # Not given in the sources.
            image[y][x] = color_accum
    return image
```

**Edge Cases and Pitfalls:**
*   **Non-GPU Systems:** On systems without `ARB_fragment_program` support, `specular` and `shininess` parameters have no effect [S2].
*   **Legacy Shading:** On systems without `ARB_fragment_program` or `ATI_fragment_shader`, shading uses destination alpha to compute gradient lighting [S2]. This requires `ARB_imaging` extensions and the gradient texture internal format `VZ_INTENSITYn` ($n=8, 12, 16$) [S2].
*   **Memory Usage:** Using a separate gradient texture increases texture memory usage by a factor of two to four compared to the original volume texture [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S2].
*   **Memory Complexity:** $O(V + G)$, where $V$ is the volume texture size and $G$ is the gradient texture size. $G$ is two to four times the size of $V$ [S2].
*   **Strengths:** Provides more accurate lighting effects than tangent-space shading and avoids bricking artifacts associated with shape bricking [S2]. Enhances surface perception in volume rendering [S2].
*   **Limitations:** Increased memory usage [S2]. Dependent on hardware support for advanced OpenGL extensions for full feature set (specular/shininess) [S2].
*   **When to use:** Not given in the sources [S2].
*   **When not to use:** Not given in the sources [S2].

## Background
Gradient Shading in volume rendering is implemented via shaders such as `vzTMGradientShader` in SGI OpenGL Volumizer [S2]. The method leverages the Phong illumination model to compute diffuse and specular contributions based on per-voxel gradient information [S2]. It is used in medical imaging applications, such as CT viewer volume rendering, to enhance the visualization of anatomical structures [S1, unofficial].
