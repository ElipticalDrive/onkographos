# Multi-Variable Color Encoding

Also called: Four data channel rendering, Multi-channel Volume Rendering, RGB Channel Mapping

## Overview
Multi-Variable Color Encoding is a visualization technique that displays up to four independent scalar variables in a single image by mapping each variable to a specific color channel (Red, Green, Blue, and a separate fourth channel) [S1, unofficial][S2, unofficial]. It solves the problem of visualizing multi-modal or multi-component volumetric data by keeping variables spectrally distinct and allowing independent visibility control via intensity adjustments [S1, unofficial][S2, unofficial]. Unlike [Classified Volume Rendering](3590-classified-volume-rendering.md) which assigns discrete material classes to colors, this method preserves continuous scalar values per channel [S1, unofficial][S2, unofficial]. The sources disagree on the maximum channel count: [S1, unofficial] states up to four variables can be shown in a single image, while [S2, unofficial] specifies up to three variables mapped directly to RGB [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A multi-channel volume dataset containing up to four independent scalar variables per voxel [S1, unofficial][S2, unofficial]. The data must be pre-merged into a single file structure where each channel is stored separately but accessible as a distinct component [S1, unofficial][S2, unofficial].
*   **Output:** A single RGB image where the Red channel encodes Variable 1, Green encodes Variable 2, Blue encodes Variable 3, and the fourth variable is handled separately [S1, unofficial][S2, unofficial].

**Data Structures:**
The source data is a merged volume file created by a dedicated command-line tool [S1, unofficial][S2, unofficial]. The rendering system treats the merged channels as distinct components accessible by index [S1, unofficial][S2, unofficial].

**Steps:**
1.  **Data Preparation:** Merge independent variable datasets into a single multi-channel data file using a dedicated tool (e.g., `VConv`) [S1, unofficial][S2, unofficial].
2.  **Channel Mapping:** Assign the first scalar variable to the Red color channel, the second to the Green channel, and the third to the Blue channel [S1, unofficial][S2, unofficial].
3.  **Fourth Variable Handling:** If a fourth variable is present, its color is set separately using three dials on the user interface, distinct from the RGB gamma controls [S1, unofficial].
4.  **Intensity Adjustment:** Apply interactive gamma correction to each color channel independently using gamma dials on the icon wall [S1, unofficial][S2, unofficial].
5.  **Reconstruction Mode Selection:** Toggle between Alpha Blending and Maximum Intensity Projection (MIP) using a checkbox on the icon wall [S1, unofficial][S2, unofficial].

**Formulas:**
The sources describe a direct assignment mapping without explicit mathematical formulas [S1, unofficial][S2, unofficial]:
$$ C_{red} = V_1 $$
$$ C_{green} = V_2 $$
$$ C_{blue} = V_3 $$
Where $V_i$ is the value of the $i$-th variable [S1, unofficial][S2, unofficial]. The intensity adjustment is described as gamma correction applied via dials [S1, unofficial][S2, unofficial]. The exact gamma function is not specified in the sources [S1, unofficial][S2, unofficial].

**Parameters:**
*   **Number of variables:** Up to three variables are mapped directly to RGB channels [S2, unofficial]. A fourth variable can be rendered, but its color is set separately [S1, unofficial].
*   **Gamma Dials:** Interactive controls for adjusting the intensity of each color component [S1, unofficial][S2, unofficial].
*   **Reconstruction Mode:** Binary toggle between Alpha Blending and MIP [S1, unofficial][S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Overlap:** If values from different modalities overlap significantly in the same voxels, it becomes difficult to distinguish which intensity corresponds to which variable [S1, unofficial][S2, unofficial]. This requires the user to have considerable experience with combined colors [S1, unofficial][S2, unofficial].
*   **Data Merging:** The data must be pre-merged; the method does not describe on-the-fly merging of disparate datasets [S1, unofficial][S2, unofficial].

**Pseudocode:**
```python
def render_multi_variable_volume(volume_data, gamma_r, gamma_g, gamma_b, use_mip):
    """
    Renders a multi-channel volume using direct RGB channel mapping and gamma correction.
    
    Args:
        volume_data: 4D array (depth, height, width, channels) containing merged variables.
                     volume_data[z, y, x, 0] -> Variable 1 (Red)
                     volume_data[z, y, x, 1] -> Variable 2 (Green)
                     volume_data[z, y, x, 2] -> Variable 3 (Blue)
                     volume_data[z, y, x, 3] -> Variable 4 (Fourth Channel)
        gamma_r: Gamma value for Red channel intensity.
        gamma_g: Gamma value for Green channel intensity.
        gamma_b: Gamma value for Blue channel intensity.
        use_mip: Boolean flag for reconstruction mode (True for MIP, False for Alpha Blending).
        
    Returns:
        rendered_image: 2D array (height, width, 3) with RGB values.
    """
    depth, height, width, channels = volume_data.shape
    rendered_image = [[0.0, 0.0, 0.0] for _ in range(height * width)]
    
    for z in range(depth):
        for y in range(height):
            for x in range(width):
                idx = y * width + x
                var1 = volume_data[z, y, x, 0]
                var2 = volume_data[z, y, x, 1]
                var3 = volume_data[z, y, x, 2]
                
                # Apply gamma correction [G]
                red_channel = var1 ** (1.0 / gamma_r)
                green_channel = var2 ** (1.0 / gamma_g)
                blue_channel = var3 ** (1.0 / gamma_b)
                
                # Clamp to valid range [0.0, 1.0]
                red_channel = max(0.0, min(1.0, red_channel))
                green_channel = max(0.0, min(1.0, green_channel))
                blue_channel = max(0.0, min(1.0, blue_channel))
                
                if use_mip:
                    # MIP takes the maximum intensity across the ray [G]
                    # Since this is a single-slice/voxel mapping, we store the max encountered
                    # In a full raycaster, this would accumulate across z.
                    pass
                else:
                    # Alpha Blending is handled by the renderer's reconstruction mode [S1, unofficial][S2, unofficial]
                    pass
                
                rendered_image[idx][0] = red_channel
                rendered_image[idx][1] = green_channel
                rendered_image[idx][2] = blue_channel
                
    return rendered_image
```

## Subtopics

### Data Fusion
The prerequisite process of merging multiple datasets into a single file using tools like `VConv` [S1, unofficial][S2, unofficial]. It sets apart from on-the-fly fusion by requiring offline preparation, and is chosen when pre-processing overhead is acceptable for real-time rendering [S1, unofficial][S2, unofficial]. See [Data Fusion](link).

### Interactive Gamma Control
The use of dials to adjust the intensity of individual color channels, allowing variables to be faded in and out [S1, unofficial][S2, unofficial]. It sets apart from static transfer functions by enabling real-time per-channel visibility control, and is chosen when independent variable inspection is required [S1, unofficial][S2, unofficial]. See [Interactive Controls](link).

### Reconstruction Modes
The toggle between Alpha Blending and Maximum Intensity Projection (MIP) to view the encoded data [S1, unofficial][S2, unofficial]. It sets apart from single-mode rendering by offering a fast overview (MIP) versus a realistic translucent representation (Alpha Blending), and is chosen based on whether feature visibility or material appearance is prioritized [S1, unofficial][S2, unofficial]. See [Reconstruction Modes](link).

## Operating characteristics
*   **Time Complexity:** Real-time interaction is supported via pixel shaders [S1, unofficial][S2, unofficial]. The sources do not provide specific frame rates or complexity formulas [S1, unofficial][S2, unofficial].
*   **Memory Complexity:** The method does not address out-of-core rendering or parallelization for large datasets [S1, unofficial]. It relies on the data fitting in memory, as demonstrated with a 128x128x100 voxel dataset per time step [S1, unofficial].
*   **Strengths:** Allows independent control of up to three variables via gamma dials; real-time interaction; simple conceptual mapping [S1, unofficial][S2, unofficial].
*   **Limitations:** Difficult to interpret when modalities overlap significantly; requires user experience to distinguish combined colors; limited to four variables [S1, unofficial][S2, unofficial].
*   **When to use:** When variables are distinct and do not heavily overlap, and independent visibility control is needed [S1, unofficial][S2, unofficial].
*   **When not to use:** When variables overlap significantly, or when precise quantitative comparison of intensities across variables is required [S1, unofficial][S2, unofficial].

## Background
This technique was developed for the IEEE Visualization 2004 Contest, specifically for exploring hurricane data sets in a CAVE-like immersive virtual environment at Brown University [S1, unofficial][S2, unofficial]. It was part of a system designed for user-friendly volume data set exploration, leveraging pixel shaders for real-time interaction [S1, unofficial][S2, unofficial]. The data sets used included ICEf48, RAINf48, and SNOWf48 [S1, unofficial][S2, unofficial].
