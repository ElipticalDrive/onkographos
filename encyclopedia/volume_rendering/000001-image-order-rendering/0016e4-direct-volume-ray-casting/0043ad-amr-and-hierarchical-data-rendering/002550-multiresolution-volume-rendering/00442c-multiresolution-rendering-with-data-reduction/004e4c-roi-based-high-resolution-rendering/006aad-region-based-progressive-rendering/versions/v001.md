# Region-Based Progressive Rendering

Also called: region-based scheme

## Overview
Region-based progressive rendering is a transmission and rendering strategy for foveated volume data that prioritizes a user-defined Region of Interest (ROI) by reconstructing and displaying it at high resolution first, then iteratively adding peripheral layers at decreasing resolutions [S1, unofficial]. It differs from coarse-to-fine schemes by avoiding the interference of low-resolution coefficients on the high-resolution ROI, resulting in a clearer initial view of the area of interest at the cost of a longer initial wait time [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A multiresolution volume dataset (typically Haar wavelet coefficients), a ROI mask defined by center coordinates $(x, y, z)$ and dimensions $(s, s, s)$, and a viewing direction [S1, unofficial].
*   **Output:** A sequence of rendered images, starting with the high-resolution ROI and progressively expanding to the full volume [S1, unofficial].

**Data Structures**
The method relies on a hierarchical data structure, typically an octree or wavelet decomposition, where data is organized into layers or blocks. Each layer $i$ contains detail coefficients representing a specific resolution scale [S1, unofficial]. The ROI is defined by a binary mask or coordinate bounds [S1, unofficial].

**Parameters**
*   **Mask Center:** The center coordinates of the ROI. Typical value: $(128, 128, 128)$ for a $256^3$ volume [S1, unofficial].
*   **Mask Size:** The dimensions of the ROI. Typical value: $(50, 50, 50)$ [S1, unofficial].
*   **Resolution Scale:** In iteration $i$, sub-volumes are reconstructed at a resolution scale of $2^{i-1}$ relative to the inner layer [S1, unofficial].

**Algorithm Steps**
1.  **Initialization:** Define the ROI mask. Identify the "fovea" (the innermost ROI) [S1, unofficial].
2.  **First Iteration ($i=1$):**
    *   Reconstruct the center fovea using partial volume reconstruction from the available high-resolution data [S1, unofficial].
    *   Render the fovea using a standard volume rendering algorithm (e.g., ray casting) [S1, unofficial].
    *   Display the result. This is the first rendering result [S1, unofficial].
3.  **Subsequent Iterations ($i > 1$):**
    *   Identify the immediate outer layer surrounding the previously rendered region.
    *   Divide this outer layer into 6 sub-volumes: Top, Bottom, Left, Right, Front, and Back [S1, unofficial].
    *   Reconstruct each of the 6 sub-volumes at a resolution scale of $2^{i-1}$ [S1, unofficial].
    *   Render each sub-volume separately using the standard rendering algorithm [S1, unofficial].
4.  **Image Composition:**
    *   Combine the newly rendered images with the previous image.
    *   For Top, Bottom, Left, and Right sub-volumes: Add the rendered images to the previous image at their correct spatial positions [S1, unofficial].
    *   For Front and Back sub-volumes: Perform alpha compositing using the 'over' operator along the viewing ray [S1, unofficial].
5.  **Repeat:** Continue iterations until the full volume is rendered or the user stops the process [S1, unofficial].

**Pseudocode**
```python
def region_based_progressive_rendering(volume_data, roi_mask, view_direction):
    """
    Renders volume data progressively focusing on an ROI.
    
    Args:
        volume_data: Multiresolution volume data (e.g., wavelet coefficients).
        roi_mask: Dictionary with 'center' (x,y,z) and 'size' (s,s,s).
        view_direction: Vector defining the camera view.
        
    Returns:
        Sequence of rendered images.
    """
    # Initialize
    current_image = None
    roi_center = roi_mask['center']
    roi_size = roi_mask['size']
    
    # Iteration 1: Render the inner fovea
    # Reconstruct center fovea using partial volume reconstruction
    fovea_data = reconstruct_partial_volume(volume_data, roi_center, roi_size, resolution_scale=1)
    
    # Render fovea
    fovea_image = render_volume(fovea_data, view_direction)
    
    # Store result
    results = [fovea_image]
    current_image = fovea_image
    
    # Subsequent iterations
    iteration = 2
    while not full_volume_rendered(current_image, volume_data):
        # Define outer layer boundaries based on previous ROI
        outer_layer_bounds = get_outer_layer_bounds(roi_center, roi_size, iteration)
        
        # Divide into 6 sub-volumes
        sub_volumes = {
            'top': get_sub_volume(outer_layer_bounds, 'top'),
            'bottom': get_sub_volume(outer_layer_bounds, 'bottom'),
            'left': get_sub_volume(outer_layer_bounds, 'left'),
            'right': get_sub_volume(outer_layer_bounds, 'right'),
            'front': get_sub_volume(outer_layer_bounds, 'front'),
            'back': get_sub_volume(outer_layer_bounds, 'back')
        }
        
        new_images = {}
        
        # Reconstruct and render each sub-volume at resolution scale 2^(i-1)
        for name, sub_vol in sub_volumes.items():
            res_scale = 2 ** (iteration - 1)
            reconstructed_data = reconstruct_volume(volume_data, sub_vol, res_scale)
            new_images[name] = render_volume(reconstructed_data, view_direction)
            
        # Compose images
        # Top, Bottom, Left, Right are added spatially
        for name in ['top', 'bottom', 'left', 'right']:
            current_image = add_image_spatially(current_image, new_images[name], name)
            
        # Front and Back are composited using 'over' operator
        # Order: Front over Inner over Back
        # Note: 'Inner' here refers to the current_image which contains the previous layers
        # The 'over' operator is applied pixel-by-pixel
        
        # First, composite Front over current image
        current_image = composite_over(new_images['front'], current_image)
        
        # Then, composite Back over the result
        current_image = composite_over(current_image, new_images['back'])
        
        results.append(current_image)
        iteration += 1
        
    return results

def composite_over(pixel_a, pixel_b):
    """
    Performs the 'over' compositing operation on two pixels.
    Given pixel A(d_a, alpha_a) and B(d_b, alpha_b).
    Result C(d_c, alpha_c) where d_c = d_a + (1 - alpha_a) * d_b.
    """
    d_a, alpha_a = pixel_a
    d_b, alpha_b = pixel_b
    
    d_c = d_a + (1 - alpha_a) * d_b
    alpha_c = alpha_a + (1 - alpha_a) * alpha_b
    
    return (d_c, alpha_c)
```

**Edge Cases and Pitfalls**
*   **Non-Orthogonal Viewing:** When viewing from a non-orthogonal direction, slices must be transformed to a sheared object space to allow efficient projection, then warped to the image plane [S1, unofficial].
*   **Precision:** The 'over' operator is performed pixel-by-pixel. Floating-point precision issues may arise during compositing, especially with many layers [S1, unofficial].
*   **Boundary Conditions:** The definition of "outer layer" must be precise to avoid gaps or overlaps between iterations [S1, unofficial].

## Subtopics

### Coarse-to-Fine Progressive Volume Rendering
A variant where rendering starts with a rough average image of the entire volume and iteratively refines the fovea area [S1, unofficial]. It divides each layer (excluding the innermost) into 7 parts: Top, Bottom, Left, Right, Front, Back, and Center. The Center part is saved for the next iteration, and the Front/Back results are combined with the next iteration's result using a specific refinement equation [S1, unofficial]. It is chosen when a very fast initial preview is prioritized over ROI clarity, as it has a shorter initial wait time (0.1468s vs 0.381s) but suffers from low-resolution interference in the ROI [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not explicitly given, but involves iterative reconstruction and rendering of expanding layers.
*   **Memory Complexity:** Depends on the multiresolution data structure (e.g., octree/wavelet) and the current rendered image buffer.
*   **Measured Performance:**
    *   **Initial Wait Time:** 0.381 seconds for the innermost ROI to arrive and be displayed [S1, unofficial].
    *   **Comparison:** Coarse-to-fine has a shorter initial wait time of 0.1468 seconds [S1, unofficial].
    *   **Total Time:** The region-based scheme takes 0.381 seconds for the first result, while coarse-to-fine takes 0.1468 seconds. The second algorithm (coarse-to-fine) takes 0.5118 seconds for the innermost ROI to arrive, which is more than twice the time of the region-based scheme's initial display [S1, unofficial].
*   **Strengths:** Provides a clearer result for the ROI because it avoids interference from low-resolution coefficients that arrive early in coarse-to-fine schemes [S1, unofficial].
*   **Limitations:** Longer initial wait time compared to coarse-to-fine schemes [S1, unofficial].
*   **When to Use:** When the user's primary interest is the clarity of a specific region of interest and they are willing to wait longer for the initial high-quality view [S1, unofficial].
*   **When Not to Use:** When a very fast initial preview of the entire volume is required, even if it is low resolution [S1, unofficial].

## Background
Originated in the context of progressive transmission and rendering of foveated volume data, likely from research by Bhaniramka and Demange (2002) or related works on OpenGL VoluMizer and wavelet-based volume rendering [S1, unofficial]. The method is part of a broader effort to handle large-scale volume data stored on server repositories and progressively rendered on client sites [S1, unofficial].
