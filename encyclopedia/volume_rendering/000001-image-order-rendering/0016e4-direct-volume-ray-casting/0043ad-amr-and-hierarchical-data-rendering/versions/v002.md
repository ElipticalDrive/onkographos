# AMR and Hierarchical Data Rendering

Also called: Adaptive Mesh Refinement Volume Rendering, Hierarchical Volume Rendering

## Overview
AMR and Hierarchical Data Rendering is a family of direct volume ray casting methods designed to visualize large-scale datasets with non-uniform spatial resolution, such as those generated by adaptive mesh refinement simulations [S1, unofficial]. It solves the problem of high memory bandwidth and computational cost associated with uniformly sampling high-resolution regions by leveraging hierarchical data structures to adaptively select sampling rates and data sources along rays [S1, unofficial]. It is distinguished from its siblings by its explicit reliance on spatial hierarchy (AMR grids, clusters, or multiresolution decompositions) to drive the rendering pipeline, rather than relying solely on fixed-resolution textures or neural networks.

## Shared principles
The method operates on the fundamental loop structure of [Direct volume ray casting](19-direct-volume-ray-casting.md): for each pixel, a ray $r(t) = \mathbf{o} + t\mathbf{d}$ is defined, intersected with the volume domain, and sampled/composited along its path [G]. The traversal order is determined by the pixel's position in the image plane [G].

The core computational engine consists of four sequential stages applied to each ray [S5, S10, S37, unofficial]:

1.  **Ray Generation and Discretization**: The ray segment $[t_{start}, t_{end}]$ intersecting the volume is determined, typically by intersecting the ray with the volume's bounding box [S1, unofficial][S8, S16, unofficial]. The segment is discretized into $N$ samples at equidistant intervals $\Delta t = (t_{end} - t_{start}) / N$ [S5, S10, S17, unofficial].
2.  **Sampling and Interpolation**: At each sample point $\mathbf{p}_i = r(t_i)$, the scalar value $V(\mathbf{p}_i)$ is retrieved from the volume data. This is typically performed by trilinear interpolation of the eight surrounding voxels [S9, S11, S47, unofficial].
3.  **Classification (Transfer Function)**: The scalar value $V(\mathbf{p}_i)$ is mapped to optical properties: color $C_i$ and opacity $\alpha_i$ [S2, S2789]. The opacity is often corrected for the step size $\Delta t$ to ensure physical consistency, using the Beer-Lambert law approximation:
    $$ \alpha_i = 1 - e^{-\sigma_i \Delta t} $$
    where $\sigma_i$ is the extinction coefficient derived from the scalar value [S24, S30, unofficial].
4.  **Compositing**: The samples are accumulated from front to back (closest to the eye to furthest) using the front-to-back alpha compositing equation [S1, unofficial][S2, S13, unofficial][S61]:
    $$ C_{out} = C_{in} + (1 - \alpha_{in}) \cdot C_{sample} \cdot \alpha_{sample} $$
    $$ \alpha_{out} = \alpha_{in} + (1 - \alpha_{in}) \cdot \alpha_{sample} $$
    where $C_{in}$ and $\alpha_{in}$ are the accumulated color and opacity from previous samples, and $C_{sample}$ and $\alpha_{sample}$ are the color and opacity of the current sample [S52, S60, unofficial]. The process initializes with $C_{in} = 0$ and $\alpha_{in} = 0$ [S15, S46, unofficial].

## Subtopics

### [Multiresolution Volume Rendering](3541-multiresolution-volume-rendering.md)
Multiresolution Volume Rendering utilizes hierarchical data decompositions (such as wavelets or Laplacian pyramids) to perform adaptive integration and early termination along rays. It solves the problem of high computational cost in large volume datasets by allowing the renderer to sample at lower resolutions where accuracy requirements are relaxed or occlusion is high, thereby reducing the number of samples needed. It is distinguished from its siblings by its explicit use of mathematical multiresolution transforms to drive the sampling step size and data retrieval, rather than spatial partitioning structures like clusters or AMR grids.

### [Cluster Hierarchy-based Volume Rendering](10972-cluster-hierarchy-based-volume-rendering.md)
Cluster Hierarchy-based Volume Rendering is a method for the interactive visual exploration of multi-variate volume data by mapping hierarchical clusters of data points to transfer function parameters (color, opacity, size) for direct volume rendering. It solves the problem of exploring high-dimensional feature spaces in volumetric datasets by allowing users to interactively define, modify, and filter clusters via a cluster tree widget and parallel coordinates widget, which are then immediately reflected in the 3D visualization. It sets itself apart from standard direct volume rendering by decoupling the classification logic from the rendering loop, performing it on the CPU based on user interaction with a hierarchical structure, while retaining the core ray-casting pipeline for rendering.

### [In-Core Volume Rendering](11164-in-core-volume-rendering.md)
In-core volume rendering, specifically as implemented in the **Srend** system, is a method for visualizing Computational Fluid Dynamics (CFD) simulations using Cartesian grids by embedding the rendering code directly within the simulation application. It solves the problem of high data I/O overhead and latency in large-scale parallel simulations by performing rendering in-core during the simulation run, eliminating the need for external visualization tools or post-processing steps. Unlike general-purpose in-situ renderers that often employ complex load-balancing or supervisory mechanisms, Srend relies on a simple time-partitioning strategy where every simulation process renders its local data, followed by space-partitioned compositing via a user-defined "rendering tree". This approach exploits the embarrassingly parallel nature of ray casting and the associativity of pre-multiplied alpha compositing to achieve scalable, low-overhead visualization.

### Texture-Based AMR Volume Rendering
**Definition**: A texture/slicing-based volume rendering technique for AMR data that resamples to node-centered data, subdivides into homogeneous resolution regions using a kD-tree, and optimizes texture packing [S1, unofficial].
**Steps**:
1. Resample AMR data to node-centered format [S1, unofficial].
2. Subdivide data into homogeneous resolution regions using a kD-tree, minimizing the number of blocks using AMR grid placement algorithm information [S1, unofficial].
3. Perform texture/slicing-based volume rendering with optimized texture packing [S1, unofficial].
4. Adapt slice spacing and correct opacity to handle varying resolution levels [S1, unofficial].
**Usage**: Used in Virtual Director and CAVE for rendering 'The First Star of the Universe' astrophysical data set [S1, unofficial].

## Background
The visualization of Adaptive Mesh Refinement (AMR) data has been a significant challenge due to the irregular and hierarchical nature of the grids. Early work by Kähler and Hege (2001/2002) introduced texture-based AMR volume rendering, which resampled data to node-centered formats and used kD-trees for subdivision [S1, unofficial]. Park et al. (2002) proposed splatting-based rendering using kD-tree and octree domain subdivision [S1, unofficial]. Kreylos et al. (2002) developed direct volume rendering of AMR data using homogenization via kD-trees and distributed rendering with texture-based slicing [S1, unofficial]. These methods were applied to large-scale astrophysical simulations, such as "The First Star of the Universe," which was aired on the Discovery Channel [S1, unofficial]. The field continues to evolve with in-core rendering solutions like Srend for CFD simulations [S1, unofficial].
