# Cluster Hierarchy-based Volume Rendering

Also called: Cluster Tree Widget Rendering, Interactive Visual Exploration of Multi-variate Volume Data

## Overview
This method renders multi-variate volume data by mapping hierarchical clusters of feature vectors to transfer function parameters (color, opacity, size) for direct volume rendering, enabling interactive exploration via cluster tree and parallel coordinates widgets [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A multi-variate volume dataset (scalar fields or derived properties) and a hierarchical clustering of the data's feature space, or a single root cluster if pre-clustering is absent [S1, unofficial].
- **Output:** A rendered image with clusters visualized according to user-defined transfer functions [S1, unofficial].

**Data Structures:**
1. **Cluster Hierarchy:** A tree structure where nodes represent clusters. Each node stores default color and opacity assigned by the automatic clustering algorithm, and a density slider value used to filter voxels based on density thresholds [S1, unofficial].
2. **Mask Volume:** A volume data structure with the same spatial dimensions as the input data. Voxels with a mask value of `1` belong to a selected cluster and meet the density/brushing criteria; voxels with `0` are hidden (fully transparent) [S1, unofficial].

**Steps:**
1. **Clustering Initialization:** If pre-clustering exists, use the automatic clustering algorithm's output to assign default color and opacity to each cluster. If no pre-clustering exists, place all data points into a single root cluster [S1, unofficial].
2. **User Interaction (CPU/GPU split):** Adjust density sliders in the cluster tree widget to modify cluster sizes by defining density thresholds. Brush intervals in the parallel coordinates widget to mark data points within selected intervals as `1` and others as `0`. Reclustering operations (splitting/merging nodes) are performed on the CPU and take less than half a second on modern hardware. Assigning material properties to clusters and changing their sizes via density sliders is instantaneous and executed on the GPU [S1, unofficial].
3. **Mask Generation:** For each voxel, determine if it belongs to a selected cluster and satisfies the current density and brushing criteria. Set the corresponding value in the Mask Volume to `1` if true, `0` if false [S1, unofficial].
4. **Rendering (GPU):** Perform direct volume ray casting using a 3D texture-based renderer. Voxels with a mask value of `0` are rendered fully transparent. Combine the mask with the transfer function, which maps cluster properties (e.g., physical properties like ionization state) to color and opacity. Use precomputed surface normals for illumination [S1, unofficial].

**Pseudocode:**
```python
def render_cluster_hierarchy(data, cluster_tree, mask_volume, screen_width, screen_height):
    # Initialize mask volume with zeros
    mask_volume[:] = 0
    
    # Mask Generation (CPU)
    # Note: Exact clustering lookup and parallel coordinates brushing logic are not specified in the sources [G]
    for z in range(data.shape[0]):
        for y in range(data.shape[1]):
            for x in range(data.shape[2]):
                voxel = data[z, y, x]
                cluster = cluster_tree.find_cluster(voxel.features)
                
                is_selected = cluster.is_selected
                meets_density = voxel.features.density >= cluster.density_threshold
                meets_brush = check_parallel_coordinates_brush(voxel.features)
                
                if is_selected and meets_density and meets_brush:
                    mask_volume[z, y, x] = 1
                else:
                    mask_volume[z, y, x] = 0
                    
    # Rendering (GPU)
    for screen_y in range(screen_height):
        for screen_x in range(screen_width):
            ray = generate_ray(screen_x, screen_y)
            accumulated_color = [0.0, 0.0, 0.0]
            accumulated_opacity = 0.0
            
            for t in range(ray.length):
                sample_point = ray.origin + t * ray.direction
                if mask_volume[sample_point] == 0:
                    continue  # Fully transparent
                    
                cluster = cluster_tree.find_cluster(sample_point.features)
                color = cluster.color
                opacity = cluster.opacity
                
                # Standard front-to-back compositing
                alpha = opacity
                accumulated_color = [
                    accumulated_color[i] + color[i] * alpha * (1.0 - accumulated_opacity)
                    for i in range(3)
                ]
                accumulated_opacity += alpha * (1.0 - accumulated_opacity)
                
            set_pixel(screen_x, screen_y, accumulated_color)
```

**Parameters:**
- **Rendering Hardware:** nVIDIA GTX260 [S1, unofficial].
- **Screen Resolution:** 1680x1050 pixels [S1, unofficial].
- **Performance Target:** 20-30 frames per second [S1, unofficial].
- **Reclustering Time:** < 0.5 seconds on modern hardware [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Aliasing:** Post-classification with nearest-neighbor interpolation causes aliasing artifacts at cluster boundaries [S1, unofficial].
- **Performance:** Pre-classification (computing colors/opacities for all voxels on CPU and transmitting to GPU) inhibits interactive frame rates with marginal quality gain [S1, unofficial].
- **Normals:** On-the-fly surface normal computation significantly slows down rendering; normals must be precomputed [S1, unofficial].
- **Illumination:** If no density values are available, illumination cannot be applied [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Rendering time depends on dataset resolution, zoom level, and sampling rate [S1, unofficial]. Reclustering operations (splitting/merging) take < 0.5 seconds on modern hardware [S1, unofficial].
- **Memory Complexity:** Requires storing the multi-variate data, the cluster hierarchy, and the mask volume [S1, unofficial].
- **Measured Performance:** Achieved 20-30 fps at 1680x1050 resolution on an nVIDIA GTX260 [S1, unofficial].
- **Strengths:** Interactive exploration of multi-variate data; intuitive UI with cluster tree and parallel coordinates; fast reclustering [S1, unofficial].
- **Limitations:** Aliasing artifacts at cluster boundaries; requires precomputed normals; no illumination if density is unavailable [S1, unofficial].
- **When to Use:** Interactive exploration of multi-variate volume data where user-driven clustering and filtering are needed [S1, unofficial].
- **When Not to Use:** When pre-computed classification is required for maximum quality (due to performance costs) or when density-based illumination is critical but density data is absent [S1, unofficial].

## Background
- **Origin:** Presented by Dobrev et al. in 2011 [S1, unofficial].
- **History:** Applied to various datasets including Bonsai tree, ionization front instability, medical MRI, tornado flow field, and white dwarf/black hole simulations [S1, unofficial].
