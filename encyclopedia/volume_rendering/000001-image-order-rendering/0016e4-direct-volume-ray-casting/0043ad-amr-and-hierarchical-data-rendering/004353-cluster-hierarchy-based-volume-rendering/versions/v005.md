# Cluster Hierarchy-based Volume Rendering

Also called: Cluster Tree Widget Rendering, Interactive Visual Exploration of Multi-variate Volume Data

## Overview
This method renders multi-variate volume data by mapping hierarchical clusters of feature vectors to transfer function parameters (color, opacity, size) for direct volume rendering, enabling interactive exploration via cluster tree and parallel coordinates widgets [S1, unofficial]. It distinguishes itself from sibling methods by decoupling the classification/clustering logic (CPU) from the rendering loop (GPU), using a mask-based post-classification approach to maintain interactive frame rates, whereas [Multiresolution Volume Rendering](3541-multiresolution-volume-rendering.md) focuses on spatial LOD and [In-Core Volume Rendering](11164-in-core-volume-rendering.md) focuses on memory management for large datasets.

## How it works
**Inputs and Outputs:**
- **Input:** A multi-variate volume dataset (scalar fields or derived properties) and a hierarchical clustering of the data's feature space.
- **Output:** A rendered image with clusters visualized according to user-defined transfer functions.

**Data Structures:**
1.  **Cluster Hierarchy:** A tree structure where nodes represent clusters. Each node contains:
    -   A set of data points (voxels) belonging to the cluster.
    -   Default color and opacity assigned by the automatic clustering algorithm [S1, unofficial].
    -   A density slider value used to filter voxels within the cluster based on density thresholds [S1, unofficial].
2.  **Mask Volume:** A volume data structure with the same spatial dimensions as the input data.
    -   Value `1`: The voxel belongs to a selected cluster and meets the density criteria.
    -   Value `0`: The voxel is hidden (fully transparent) [S1, unofficial].

**Steps:**
1.  **Clustering Initialization:**
    -   If pre-clustering exists, use the automatic clustering algorithm's output to assign default color and opacity to each cluster [S1, unofficial].
    -   If no pre-clustering exists, place all data points into a single root cluster [S1, unofficial].
2.  **User Interaction (CPU):**
    -   **Cluster Tree Widget:** Users adjust density sliders for specific clusters. This modifies the effective size of the cluster by defining density thresholds [S1, unofficial].
    -   **Parallel Coordinates Widget:** Users brush intervals in the multi-variate feature space. Data points falling within selected intervals are marked; others are marked with zero [S1, unofficial].
    -   **Reclustering:** Users can split or merge nodes in the cluster hierarchy. This operation is performed on the CPU [S1, unofficial].
3.  **Mask Generation (CPU):**
    -   For each voxel, determine if it belongs to a selected cluster and satisfies the current density/brushing criteria.
    -   Set the corresponding value in the Mask Volume to `1` if true, `0` if false [S1, unofficial].
4.  **Rendering (GPU):**
    -   Perform direct volume ray casting using a 3D texture-based renderer [S1, unofficial].
    -   **Masking:** Voxels with a mask value of `0` are rendered fully transparent (hidden) [S1, unofficial].
    -   **Compositing:** Combine the mask with the transfer function. The transfer function maps the cluster's properties (e.g., physical properties like ionization state) to color and opacity [S1, unofficial].
    -   **Illumination:** Use precomputed surface normals for lighting [S1, unofficial].

**Parameters:**
-   **Rendering Hardware:** nVIDIA GTX260 [S1, unofficial].
-   **Screen Resolution:** 1680x1050 pixels [S1, unofficial].
-   **Performance Target:** 20-30 frames per second [S1, unofficial].
-   **Reclustering Time:** < 0.5 seconds on modern hardware [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Aliasing:** Post-classification with nearest-neighbor interpolation causes aliasing artifacts at cluster boundaries [S1, unofficial].
-   **Performance:** Pre-classification (computing colors/opacities for all voxels on CPU and transmitting to GPU) inhibits interactive frame rates with marginal quality gain [S1, unofficial].
-   **Normals:** On-the-fly surface normal computation significantly slows down rendering; normals must be precomputed [S1, unofficial].
-   **Illumination:** If no density values are available, illumination cannot be applied [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** Rendering time depends on dataset resolution, zoom level, and sampling rate [S1, unofficial]. Reclustering operations (splitting/merging) take < 0.5 seconds on modern hardware [S1, unofficial].
-   **Memory Complexity:** Requires storing the multi-variate data, the cluster hierarchy, and the mask volume [S1, unofficial].
-   **Measured Performance:** Achieved 20-30 fps at 1680x1050 resolution on an nVIDIA GTX260 [S1, unofficial].
-   **Strengths:** Interactive exploration of multi-variate data; intuitive UI with cluster tree and parallel coordinates; fast reclustering [S1, unofficial].
-   **Limitations:** Aliasing artifacts at cluster boundaries; requires precomputed normals; no illumination if density is unavailable [S1, unofficial].
-   **When to Use:** Interactive exploration of multi-variate volume data where user-driven clustering and filtering are needed [S1, unofficial].
-   **When Not to Use:** When pre-computed classification is required for maximum quality (due to performance costs) or when density-based illumination is critical but density data is absent [S1, unofficial].

## Background
-   **Origin:** Presented by Dobrev et al. in 2011 [S1, unofficial].
-   **History:** Applied to various datasets including Bonsai tree, ionization front instability, medical MRI, tornado flow field, and white dwarf/black hole simulations [S1, unofficial].
-   **Usage:** Implemented in C++ using QT, OpenGL, and GLSL [S1, unofficial].
