# Image-order volume rendering

Also called: Levoy's Image-order Volume Rendering

## Overview
Image-order volume rendering is a direct volume ray casting technique that precomputes optical properties for every voxel before rendering [S1, unofficial][S2]. Unlike on-the-fly methods, it shifts shading and classification to a preprocessing phase, allowing the rendering pass to sample and composite pre-calculated arrays [S1, unofficial]. It is distinguished by this explicit separation of property generation from integration, enabling higher-order interpolation on the precomputed data [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset $V$ on a 3D grid, a transfer function $T$ mapping scalar values to optical properties, and a shading model for computing color from gradients [S1, unofficial].
*   **Output:** Two precomputed 3D arrays: a color array $\mathbf{C}_{pre}$ and an opacity array $\alpha_{pre}$, aligned with the voxel grid [S1, unofficial]. The final image is generated by ray casting through these arrays [S2].

**Data Structures:**
1.  **Volume Grid:** $V[x, y, z]$ stores scalar values.
2.  **Precomputed Color Array:** $\mathbf{C}_{pre}[x, y, z]$ stores RGB vectors.
3.  **Precomputed Opacity Array:** $\alpha_{pre}[x, y, z]$ stores scalar opacity values.

**Steps:**
1.  **Preprocessing:** For each voxel $(x, y, z)$, generate the color and opacity arrays using preprocessing techniques [S1, unofficial]. This involves performing a shading operation to compute the color array and applying transfer functions to define the opacity array [S1, unofficial].
2.  **Ray Casting:** For each pixel, traverse a viewing ray from the eye point into the volume [S2]. Evaluate the volume rendering integral using equidistant sampling along the ray [S2]. Composite samples front-to-back from the eye into the volume [S2].

**Formulas:**
The front-to-back compositing for samples $i=1 \dots N$ with color $\mathbf{c}_i$ and opacity $\alpha_i$ is:
$$ \mathbf{C}_{out} = \sum_{i=1}^{N} \mathbf{c}_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
$$ \alpha_{out} = 1 - \prod_{i=1}^{N} (1 - \alpha_i) $$
Iteratively, initialized to $(\mathbf{C}_{acc}, \alpha_{acc}) = (\mathbf{0}, 0)$:
$$ \mathbf{C}_{acc} \leftarrow \mathbf{C}_{acc} + (1 - \alpha_{acc}) \cdot \mathbf{c}_i \cdot \alpha_i $$
$$ \alpha_{acc} \leftarrow \alpha_{acc} + (1 - \alpha_{acc}) \cdot \alpha_i $$

```python
def intersect_box(origin, direction, bounds):
    t_min, t_max = 0.0, float('inf')
    for i in range(3):
        if direction[i] == 0.0:
            if origin[i] < bounds[2*i] or origin[i] > bounds[2*i+1]:
                return None, None
        else:
            t1 = (bounds[2*i] - origin[i]) / direction[i]
            t2 = (bounds[2*i+1] - origin[i]) / direction[i]
            if t1 > t2: t1, t2 = t2, t1
            if t1 > t_min: t_min = t1
            if t2 < t_max: t_max = t2
            if t_min > t_max: return None, None
    return t_min, t_max

def trilinear_interpolate(grid, x, y, z):
    ix, iy, iz = int(x), int(y), int(z)
    fx, fy, fz = x - ix, y - iy, z - iz
    def v(dx, dy, dz):
        return grid[min(max(ix+dx, 0), grid.shape[0]-1)][min(max(iy+dy, 0), grid.shape[1]-1)][min(max(iz+dz, 0), grid.shape[2]-1)]
    c00 = v(0,0,0)*(1-fx) + v(1,0,0)*fx
    c10 = v(0,1,0)*(1-fx) + v(1,1,0)*fx
    c01 = v(0,0,1)*(1-fx) + v(1,0,1)*fx
    c11 = v(0,1,1)*(1-fx) + v(1,1,1)*fx
    c0 = c00*(1-fy) + c10*fy
    c1 = c01*(1-fy) + c11*fy
    return c0*(1-fz) + c1*fz

def compute_gradient(volume_data, x, y, z):
    dx = volume_data[min(x+1, volume_data.shape[0]-1), y, z] - volume_data[max(x-1, 0), y, z]
    dy = volume_data[x, min(y+1, volume_data.shape[1]-1), z] - volume_data[x, max(y-1, 0), z]
    dz = volume_data[x, y, min(z+1, volume_data.shape[2]-1)] - volume_data[x, y, max(z-1, 0)]
    return np.array([dx, dy, dz])

def preprocess_volume(volume_data, transfer_function, shading_model):
    X, Y, Z = volume_data.shape
    precomputed_color = np.zeros((X, Y, Z, 3))
    precomputed_opacity = np.zeros((X, Y, Z))
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                v = volume_data[x, y, z]
                grad = compute_gradient(volume_data, x, y, z)
                base_color = shading_model(grad)
                alpha_intrinsic, color_mod = transfer_function(v)
                precomputed_color[x, y, z] = base_color * color_mod
                precomputed_opacity[x, y, z] = alpha_intrinsic
    return precomputed_color, precomputed_opacity

def render_image_order(precomputed_color, precomputed_opacity, camera, volume_bounds, step_size):
    width, height = camera.image_size
    image = np.zeros((height, width, 3))
    for u in range(width):
        for v in range(height):
            ray_origin, ray_direction = camera.get_ray(u, v)
            t_near, t_far = intersect_box(ray_origin, ray_direction, volume_bounds)
            if t_far is None or t_far < t_near:
                continue
            num_samples = int(round((t_far - t_near) / step_size))
            acc_color = np.array([0.0, 0.0, 0.0])
            acc_opacity = 0.0
            for i in range(num_samples):
                t = t_near + i * step_size
                pos = ray_origin + t * ray_direction
                c_sample = trilinear_interpolate(precomputed_color, pos[0], pos[1], pos[2])
                alpha_sample = trilinear_interpolate(precomputed_opacity, pos[0], pos[1], pos[2])
                weight = alpha_sample * (1.0 - acc_opacity)
                acc_color += weight * c_sample
                acc_opacity += weight
            image[v, u] = acc_color
    return image
```

**Parameters:**
*   **Interpolation Order:** Higher-order interpolation (e.g., cubic) is applied to the precomputed arrays to define sample values, color, and opacity at arbitrary locations [S1, unofficial].
*   **Step Size:** Equidistant sampling is used along the viewing rays [S2].

**Edge Cases and Pitfalls:**
*   **Memory:** Requires storing the original volume plus two additional arrays of identical dimensions [S1, unofficial].
*   **Data Updates:** If the volume data or transfer function changes, the preprocessing phase must be repeated [G].

## Subtopics

### V-Buffer Image Order Ray Casting
Uses a V-Buffer to manage depth and occlusion while retaining the image-order precomputation strategy [S1, unofficial].

### V-Buffer Cell-by-Cell Processing
Processes volume cells individually during ray traversal, combining image-order precomputation with cell-based optimization [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Preprocessing scales as $O(V)$ where $V$ is the voxel count, covering shading and classification for every voxel. Rendering scales as $O(P \cdot N)$ where $P$ is pixel count and $N$ is samples per ray [G].
*   **Memory Complexity:** Requires $3 \times$ the base memory footprint of the scalar volume (original data, color array, opacity array) [S1, unofficial].
*   **Strengths:** Reduces per-pixel runtime computation by moving shading and classification to a single preprocessing pass. Enables higher-order interpolation on precomputed data [S1, unofficial].
*   **Limitations:** High memory consumption. Requires full preprocessing regeneration for dynamic data or transfer function changes [G].
*   **When to Use:** Static volumes where high-quality rendering with higher-order interpolation is prioritized and memory is sufficient [G].
*   **When Not to Use:** Dynamic volumes, interactive transfer function adjustment, or memory-constrained environments [G].
