# Slab-based Ray Sampling

Also called: Image-order caching, Slab Definition and Sampling, Slab Sampling, Slab-based approach

## Overview
Slab-based ray sampling is an image-order caching mechanism for direct volume ray casting that groups rays into rectangular screen regions to form stacked slabs, storing voxel samples in shared memory to optimize neighborhood access for lighting and compositing [S1, unofficial]. Unlike object-order bricking, which struggles with GPU hardware mapping due to per-brick lists, this method leverages the regular structure of rays within a slab to reduce memory bandwidth and latency when calculating gradients or performing ambient occlusion [S1, unofficial]. It is distinct from sibling methods like [Uniform Ray Sampling](1261-uniform-ray-sampling.md) by explicitly managing spatial locality in shared memory across multiple rays, and from [Stochastic Jittering](924-stochastic-jittering.md) by prioritizing deterministic cache coherence over variance reduction [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   3D volume texture (scalar field) [S1, unofficial].
*   Camera parameters (view matrix, projection type: orthogonal or perspective) [S1, unofficial].
*   Screen resolution and subdivision grid (rectangular regions) [S1, unofficial].
*   Slab depth parameter $s_d$ (number of samples written to cache per ray at once) [S1, unofficial].
*   Step length $d$ (distance between samples) [S2].

**Outputs:**
*   Final pixel color and opacity via front-to-back compositing [S2].

### Data Structures
*   **Slab Cache:** A three-dimensional array stored in GPU shared memory [S1, unofficial].
    *   Dimensions: $[N_{slices}, N_{rays}, N_{samples\_per\_slice}]$ [S1, unofficial].
    *   $N_{rays}$: Number of rays in the slab (threads in the block) [S1, unofficial].
    *   $N_{slices}$: Determined by slab depth $s_d$ and ray length [S1, unofficial].
    *   $N_{samples\_per\_slice}$: Determined by ray length and step size [S1, unofficial].
    *   Layout: Rays with the same distance to the camera lie on the same slice in the slab [S1, unofficial].
*   **Slab Definition:** A slab of thickness $2d$ is defined by three successive samples $(s_f, s_m, s_b)$ [S2]. The next slab is indexed by $(s_f, s_m, s_b)$ with the correlation $s_f = s_b$ (front sample of the next slab equals the back sample of the current slab) [S2].

### Parameters
*   $d$: Step length between samples [S2].
*   $s_d$: Slab depth, controlling the number of samples written into the cache per ray simultaneously [S1, unofficial].
*   Typical values: Not given in the sources [S1, unofficial].

### Algorithm Steps

1.  **Screen Subdivision and Slab Creation:**
    The screen is subdivided into rectangular regions [S1, unofficial]. For each region, a slab is created [S1, unofficial]. For orthogonal projection, the slab is a cuboid; for perspective projection, it is a frustum [S1, unofficial].

2.  **Start Point Preprocessing:**
    To ensure voxels adjacent in texture space lie close together in the cache, all ray start points in a slab are modified to have the same distance to the camera as the closest ray [S1, unofficial].
    *   Use shared memory and thread synchronization to find the minimum camera distance among all rays in the block [S1, unofficial].
    *   Move each ray's start point to this minimum distance [S1, unofficial].
    *   **Pitfall:** If the view plane is not parallel to one side of the proxy geometry cube, ray start positions have different distances, causing adjacent voxels to lie on different slices in the cache, resulting in incorrect gradients [S1, unofficial]. Modifying start points resolves this [S1, unofficial]. Texture coordinates will lie outside $[0,1]^3$; checks must be performed before each 3D texture fetch [S1, unofficial].

3.  **Main Loop Part 1 (Cache Filling):**
    *   Traverse the ray from the modified start point [S1, unofficial].
    *   Retrieve scalar values for the current sample position from the 3D volume texture [S2].
    *   Write the sample result into the shared memory slab cache [S1, unofficial].
    *   The slab depth $s_d$ controls how many samples are written per ray at a time [S1, unofficial].
    *   **Border Handling:** For rays adjacent to the slab boundary, execute only Part 1 to write samples into the cache [S1, unofficial]. This ensures inner rays have access to neighbor voxels for gradient calculation, avoiding discontinuities (grid patterns) [S1, unofficial].

4.  **Thread Synchronization:**
    Perform a barrier synchronization after Part 1 to ensure all samples are written to shared memory before reading [S1, unofficial].

5.  **Main Loop Part 2 (Lighting and Compositing):**
    *   Restart ray traversal from the beginning of the slab [S1, unofficial].
    *   Read samples directly from the shared memory cache instead of the texture [S1, unofficial].
    *   **Gradient Calculation:** Calculate gradients in eye space using adjacent samples on the same slice from top, left, bottom, and right rays (as seen from the viewpoint), and the next/previous samples on the current ray [S1, unofficial]. Transform gradients to object space for lighting [S1, unofficial].
    *   **Compositing:** Apply lighting and front-to-back compositing [S1, unofficial]. For pre-integration methods, fetch color/opacity from a 3D pre-integration table using the retrieved scalar values [S2].

6.  **Early Ray Termination (ERT):**
    *   ERT cannot stop a single ray independently because data sampled by one ray is used for gradient calculation in adjacent rays [S1, unofficial].
    *   Determine if *all* rays in the slab have reached the required alpha threshold [S1, unofficial].
    *   Use a flag in shared memory for synchronization to terminate further traversal for the entire slab if the condition is met [S1, unofficial].

### Pseudocode

```python
import math

def sync_threads():
    """Thread block synchronization barrier [G]."""
    pass

def texture_fetch(tex, coord):
    """3D texture lookup with boundary check [G]."""
    if 0.0 <= coord[0] <= 1.0 and 0.0 <= coord[1] <= 1.0 and 0.0 <= coord[2] <= 1.0:
        return tex.sample(coord)
    return 0.0

def normalize(v):
    l = math.sqrt(sum(c*c for c in v))
    return [c/l for c in v] if l > 0 else v

def length(v):
    return math.sqrt(sum(c*c for c in v))

def slab_based_ray_casting(rays, volume_texture, view_to_obj_matrix, transfer_func, sd, d):
    # rays: list of (origin, direction, is_border_ray)
    # sd: slab depth, number of samples written to cache per ray at once [S1, unofficial]
    # d: step length between samples [S2]
    num_rays = len(rays)
    # Shared memory cache layout: [slice_index][ray_index][sample_index]
    # slice_index groups rays by distance to camera [S1, unofficial]
    # Exact cache dimensions depend on ray length and d; not given in sources [G]
    cache = [[[0.0] * sd for _ in range(num_rays)] for _ in range(2)]

    # 1. Start Point Preprocessing
    min_dist = float('inf')
    for i in range(num_rays):
        dist = length(rays[i][0])
        if dist < min_dist:
            min_dist = dist
    sync_threads()

    for i in range(num_rays):
        current_dist = length(rays[i][0])
        if current_dist > min_dist:
            dir_norm = normalize(rays[i][1])
            rays[i] = (
                [rays[i][0][j] + (min_dist - current_dist) * dir_norm[j] for j in range(3)],
                rays[i][1],
                rays[i][2]
            )
    sync_threads()

    # 2. Main Loop Part 1: Cache Filling
    for ray_idx in range(num_rays):
        origin, direction, is_border = rays[ray_idx]
        step_vec = [direction[j] * d for j in range(3)]
        current_pos = origin

        for sample_idx in range(sd):
            val = texture_fetch(volume_texture, current_pos)
            dist = length(current_pos)
            slice_idx = int(dist / d) % 2
            cache[slice_idx][ray_idx][sample_idx] = val
            current_pos = [current_pos[j] + step_vec[j] for j in range(3)]

    sync_threads()

    # 3. Main Loop Part 2: Lighting and Compositing
    for ray_idx in range(num_rays):
        origin, direction, is_border = rays[ray_idx]
        step_vec = [direction[j] * d for j in range(3)]
        current_pos = origin
        color = [0.0, 0.0, 0.0]
        opacity = 0.0
        ray_alive = True

        for sample_idx in range(sd):
            if not ray_alive:
                break

            dist = length(current_pos)
            slice_idx = int(dist / d) % 2
            val = cache[slice_idx][ray_idx][sample_idx]

            if not is_border:
                # Gradient Calculation in eye space [S1, unofficial]
                # Adjacent samples on same slice from top, left, bottom, right rays
                # and next/previous samples on current ray [S1, unofficial]
                # Exact neighbor indexing depends on block layout [G]
                grad_eye = [0.0, 0.0, 0.0]
                # Left/Right rays (same slice, different ray_idx) [G]
                if ray_idx > 0: grad_eye[0] += cache[slice_idx][ray_idx-1][sample_idx] - val
                if ray_idx < num_rays-1: grad_eye[0] += cache[slice_idx][ray_idx+1][sample_idx] - val
                # Top/Bottom rays (different slice_idx, same ray_idx) [G]
                if slice_idx > 0: grad_eye[1] += cache[slice_idx-1][ray_idx][sample_idx] - val
                if slice_idx < 1: grad_eye[1] += cache[slice_idx+1][ray_idx][sample_idx] - val
                # Next/Previous samples on current ray [G]
                if sample_idx > 0: grad_eye[2] += cache[slice_idx][ray_idx][sample_idx-1] - val
                if sample_idx < sd-1: grad_eye[2] += cache[slice_idx][ray_idx][sample_idx+1] - val

                # Transform gradient to object space for lighting [S1, unofficial]
                grad_obj = [
                    view_to_obj_matrix[0][0]*grad_eye[0] + view_to_obj_matrix[0][1]*grad_eye[1] + view_to_obj_matrix[0][2]*grad_eye[2],
                    view_to_obj_matrix[1][0]*grad_eye[0] + view_to_obj_matrix[1][1]*grad_eye[1] + view_to_obj_matrix[1][2]*grad_eye[2],
                    view_to_obj_matrix[2][0]*grad_eye[0] + view_to_obj_matrix[2][1]*grad_eye[1] + view_to_obj_matrix[2][2]*grad_eye[2]
                ]

                # Apply lighting and front-to-back compositing [S1, unofficial]
                # Standard volume rendering step using transfer_func and grad_obj [G]
                alpha = transfer_func(val, grad_obj)
                color = [color[j] + (1.0 - opacity) * alpha * color[j] for j in range(3)]
                opacity = opacity + (1.0 - opacity) * alpha

                # Early Ray Termination check [S1, unofficial]
                if opacity >= 0.99:
                    ray_alive = False

            current_pos = [current_pos[j] + step_vec[j] for j in range(3)]

        # Early Ray Termination: determine if all rays reached required alpha threshold [S1, unofficial]
        # Synchronization performed using a flag in shared memory [S1, unofficial]
        # if all_rays_terminated(): break
        pass

    return color, opacity
```

### Edge Cases and Pitfalls
*   **Incorrect Gradients:** If the view plane is not parallel to one side of the proxy geometry cube, ray start positions have different distances to the camera [S1, unofficial]. This causes voxels adjacent in the volume to lie on different slices in the slab cache, leading to incorrect gradients [S1, unofficial]. **Solution:** Modify all ray start points in a slab to have the same distance to the camera as the closest one [S1, unofficial].
*   **Discontinuities (Grid Pattern):** Ignoring voxels not accessible through the cache for gradient calculation leads to discontinuities, visible as a grid pattern [S1, unofficial]. **Solution:** Include surrounding voxels by adding all rays adjacent to the slab to the cache [S1, unofficial]. For these border rays, only Part 1 of the main loop is executed [S1, unofficial].
*   **Texture Coordinates:** Moving start points may result in texture coordinates outside $[0,1]^3$ [S1, unofficial]. Checks must be performed before each 3D texture fetch [S1, unofficial].
*   **Perspective Projection:** Rays are not parallel, so the distance between sample points differs, making the relation between adjacent samples in the cache irregular [S1, unofficial]. An approximation of the neighborhood is often sufficient [S1, unofficial].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** Uses shared memory for the slab cache [S1, unofficial]. The size depends on the number of rays in a block, slab depth $s_d$, and samples per slice [S1, unofficial]. It avoids large global memory allocations for bricking lists [S1, unofficial].
*   **Time:** Two passes per slab (fill cache, then read/composite) [S1, unofficial]. This doubles the traversal cost for the cached portion but saves memory bandwidth for gradient calculations [S1, unofficial].

### Measured Performance
*   Implemented in the Voreen volume rendering framework (Meyer-Spradow et al., 2009) for CUDA version 2.1 [S1, unofficial].
*   Specific performance numbers are not provided in the sources, but it is noted to be better adapted to CUDA architecture features than bricking [S1, unofficial].

### Scaling
*   Performance advantage is realized when lighting techniques (ambient occlusion, gradient calculation) access the same sample position multiple times [S1, unofficial]. Caching provides no advantage if samples are accessed only once [S1, unofficial].

### Strengths and Limitations
*   **Strengths:** Efficient use of shared memory for image-order processing; reduces memory bandwidth for neighborhood-dependent lighting; avoids object-order bricking inefficiencies on GPUs [S1, unofficial].
*   **Limitations:** Requires synchronization; ERT is slab-wide, not per-ray; irregular cache layout in perspective projection; increased complexity in border handling [S1, unofficial].

### When to Use
*   Use when gradient-based lighting or ambient occlusion is required and memory bandwidth is a bottleneck [S1, unofficial].
*   Use when targeting GPU architectures with efficient shared memory access [S1, unofficial].
*   Do not use if samples are accessed only once (no caching benefit) or if per-ray early termination is critical without slab-wide synchronization overhead [S1, unofficial].
