# Adaptive Supersampling

Also called: Adaptive Ray Supersampling

## Overview
Adaptive supersampling is a technique for direct volume ray casting that maintains a user-specified 3D sampling rate by recursively splitting rays when the projected pixel area exceeds the square of the linear sampling rate, thereby avoiding the wasted computation of uniform oversampling near the eye [S1]. Unlike uniform supersampling, which wastes computation on near-eye voxels by applying a constant high sampling rate regardless of distance, adaptive supersampling ensures no computation is wasted by oversampling regions close to the eyepoint while increasing density only where necessary [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A volume dataset, camera parameters (eye position, view direction, field of view), a user-specified minimum linear sampling rate $s$, and a screen resolution.
*   **Output:** A final pixel value for each screen pixel, computed by compositing ray fragments.

**Data Structures**
*   **Ray Structure:** Each ray object contains:
    *   Origin point $\mathbf{o}$ and direction vector $\mathbf{d}$.
    *   Current position along the ray $t$.
    *   Accumulated opacity $\alpha_{acc}$ (initialized to 0).
    *   A child pointer to manage split rays [S1].
    *   A queue or list of active rays (slab queue) for processing [S1].

**Numbered Steps**
1.  **Initialization:** Compute the solid angle subtended by each screen pixel during initialization. Queue all rays for processing [S1].
2.  **Ray Casting Loop:** For each active ray, determine its current position along the ray axis.
3.  **Projected Area Calculation:** Calculate the projected area $A_{proj}$ of the screen pixel at the current position along the ray. This area grows with distance from the eyepoint [S1].
4.  **Split Condition Check:** Compare $A_{proj}$ to the square of the linear sampling rate $s^2$.
    *   If $A_{proj} > s^2$, the ray is split.
    *   If $A_{proj} \le s^2$, the ray continues without splitting [S1].
5.  **Ray Splitting:** If the condition is met, split the current ray into four divergent child rays at the current split point. The specific geometric arrangement of the four divergent rays is not detailed in the sources, but they are generated to cover the pixel area more finely [S1].
6.  **Recursion:** Recursively apply the split condition to the child rays. This process continues until the ray exits the volume boundary [S1].
7.  **Sampling:** Maintain the sampling rate along the ray axis by taking samples at regular intervals along the ray direction. The sampling rate in the remaining two dimensions (transverse to the ray) is maintained by the adaptive splitting based on projected area [S1].
8.  **Opacity Check:** If the accumulated opacity $\alpha_{acc}$ of a ray approaches unity, halt the processing of its child rays by removing them from the slab queue to save computation [S1].
9.  **Compositing:** Composite the resulting ray fragments to yield the final pixel value. In the described implementation, all ray fragments are averaged uniformly during composition. Any filter function could be used in its place [S1].

**Formulas**
*   **Split Condition:**
    $$ A_{proj}(t) > s^2 $$
    Where:
    *   $A_{proj}(t)$ is the projected area of the screen pixel at distance $t$ along the ray from the eye.
    *   $s$ is the user-specified linear sampling rate (samples per unit length in the transverse plane).
    *   $s^2$ is the square of the linear sampling rate, representing the maximum allowed projected pixel area before splitting is required [S1].

**Parameters**
*   **Linear Sampling Rate ($s$):** User-specified threshold. The minimum volumetric sampling rate required before triggering a ray split [S1].
*   **Uniform Averaging Weight:** In the current implementation, fragments are averaged uniformly. The weight for each fragment is $1/N$ where $N$ is the number of fragments contributing to the pixel [S1].

**Edge Cases and Pitfalls**
*   **Opacity Cutoff:** If accumulated opacity approaches unity, child rays may be halted. Implementers must define a threshold for "approaches unity" (e.g., $\alpha_{acc} > 0.99$) to prevent unnecessary computation [S1].
*   **Filter Function:** While uniform averaging is used in the source implementation, other filter functions can be used. The choice of filter affects the final image quality and must be consistent with the sampling strategy [S1].
*   **Depth of Field:** If depth of field is simulated by jittering ray origins over a finite aperture, the slice processing order must be modified to account for the shifting ray origins, necessitating two passes through the slabs within the minimum and maximum z extents of the lens [S1].

**Pseudocode**
```python
def adaptive_supersampling(volume, camera, s):
    """
    volume: 3D array of density/opacity values
    camera: object with eye_pos, view_dir, fov, screen_width, screen_height
    s: linear sampling rate threshold
    """
    # Initialize rays for each screen pixel
    rays = []
    for y in range(camera.screen_height):
        for x in range(camera.screen_width):
            ray = create_ray_from_pixel(camera, x, y)
            ray.accumulated_opacity = 0.0
            ray.children = []
            rays.append(ray)
    
    # Process rays through volume slabs
    # Note: The source mentions a slab processing order optimized to load each slice once.
    # We assume a simplified loop over slabs for clarity.
    for slab in volume.get_slabs_in_order():
        active_rays = []
        for ray in rays:
            if ray.is_inside_volume(slab):
                # Calculate projected area at current ray position
                projected_area = calculate_projected_area(ray, camera)
                
                # Check split condition
                if projected_area > s**2:
                    # Split ray into four divergent children
                    children = split_ray(ray)
                    ray.children = children
                    # Add children to active list for next slab
                    active_rays.extend(children)
                    # Mark original ray as split, no longer process directly
                    ray.processed = True
                else:
                    # Continue with current ray
                    active_rays.append(ray)
            
            # Sample along ray axis at regular intervals
            sample_value = sample_volume(ray, slab)
            ray.accumulated_opacity = composite_opacity(ray.accumulated_opacity, sample_value)
            
            # Check opacity cutoff
            if ray.accumulated_opacity >= 0.99:
                # Halt processing of child rays
                ray.children = []
                ray.processed = True
        
        rays = active_rays

    # Composite final pixel values
    pixels = {}
    for ray in rays:
        pixel_value = average_ray_fragments(ray)
        pixels[ray.pixel_coords] = pixel_value
    return pixels

def calculate_projected_area(ray, camera):
    """
    Calculate the projected area of the screen pixel at the ray's current position.
    This area grows with distance from the eyepoint.
    """
    # Distance from eye to current ray position
    dist = ray.distance_from_eye()
    # Projected area is proportional to dist^2
    # Assuming a pinhole camera model
    pixel_size = camera.screen_width / camera.fov
    area = (pixel_size * dist)**2
    return area

def split_ray(ray):
    """
    Split a ray into four divergent child rays at the current position.
    The exact geometric distribution is not specified in the source.
    """
    children = []
    # Placeholder for specific divergence strategy
    # Typically, this might involve jittering or grid-based subdivision
    for i in range(4):
        child = Ray(
            origin=ray.current_position,
            direction=ray.direction + get_divergence_vector(i),
            accumulated_opacity=0.0,
            children=[]
        )
        children.append(child)
    return children

def average_ray_fragments(ray):
    """
    Average the contributions of all ray fragments (children) uniformly.
    """
    if not ray.children:
        return ray.sample_value # Or final accumulated color
    total = 0
    count = len(ray.children)
    for child in ray.children:
        total += average_ray_fragments(child)
    return total / count
```

## Operating characteristics
*   **Time Complexity:** The number of samples is adaptive. In a test case on a 256x256 rendering of a 119x112x73 CT study, adaptive supersampling took about 6 million samples, compared to 12 million samples for uniform supersampling ensuring at least two samples per voxel [S1]. This represents a 50% reduction in sample count for the same minimum sampling rate guarantee [S1].
*   **Memory Complexity:** Requires storing ray structures with child pointers and a slab queue. The source notes that rays are queued during initialization and the slice processing order is optimized so that each slice of memory is loaded only once [S1].
*   **Strengths:** Automatically computes the number of child rays necessary to maintain a given sampling rate independent of screen resolution. No computation effort is wasted by oversampling the region close to the eyepoint [S1].
*   **Limitations:** Adds complexity to the ray tracer, which must pass through several sets of slabs and vary the sampling rate along the ray direction [S1]. The recursive splitting and management of child rays can increase implementation complexity compared to uniform supersampling [S1].
*   **When to Use:** When a guaranteed minimum sampling rate is necessary for precision, but uniform supersampling would result in excessive computation due to near-eye oversampling [S1].
*   **When Not to Use:** When computational resources are extremely limited and a lower, non-adaptive sampling rate is acceptable, or when the volume data does not require high-frequency detail that would benefit from adaptive refinement [S1].

## Background
Adaptive supersampling was introduced in the paper "An efficient method for volume rendering using perspective projection" [S1]. The method builds on the concept of supersampling to combat aliasing but adapts the sampling density based on the geometric projection of the pixel onto the volume. It is used in direct volume ray casting to ensure that voxels are taken into account when precision is absolutely necessary, providing a guarantee that all voxels are sampled adequately without the waste of uniform oversampling [S1]. The technique is implemented as an option to any ray tracer, allowing for easy integration [S1].
