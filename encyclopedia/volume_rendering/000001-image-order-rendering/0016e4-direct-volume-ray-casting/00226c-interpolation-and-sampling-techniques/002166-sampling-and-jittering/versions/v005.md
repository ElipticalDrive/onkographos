# Sampling and Jittering
Also called: Jittered Ray Casting, Jittered Sampling Volume Rendering, Volume Ray Casting with Jittered Sampling and Front-to-Back Blending

## Overview
Sampling and Jittering is a direct volume ray casting technique that casts rays from the camera through the volume, samples voxel data with jittered step offsets to reduce banding, and composites the result using front-to-back alpha blending [S1, unofficial]. It differs from [Uniform Ray Sampling](1261-uniform-ray-sampling.md) by perturbing sample locations with random offsets, transforming structured aliasing into less visually noticeable noise [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera position ($\mathbf{o}$), ray direction ($\mathbf{d}$), volume texture ($V$), jitter texture ($J$), volume bounding box ($[\mathbf{VolExtentMin}, \mathbf{VolExtentMax}]$), lighting parameters ($\mathbf{k}_{Ambient}, \mathbf{k}_{Diffuse}, \mathbf{k}_{Specular}, k_{Shininess}$), and control flags ($ComputeLighting$) [S1, unofficial].
*   **Outputs:** Final fragment color ($\mathbf{dst}$) [S1, unofficial].

**Data Structures:**
*   **Voxel Sampler:** A 3D texture storing scalar or RGBA volume data [S1, unofficial].
*   **Jitter Texture:** A 2D texture storing pre-computed random offsets [S1, unofficial]. The width and height are defined by $JitterTexSize$ [S1, unofficial]. The red channel is used for the jitter value [S1, unofficial].
*   **Ray State:** Current position $\mathbf{p}$, direction $\mathbf{d}$, step size $s$ [S1, unofficial].

**Parameters:**
*   $NumSamples$: Maximum iterations per ray [S1, unofficial].
*   $RayStepSize$: Distance between consecutive samples ($s$) [S1, unofficial].
*   $JitterTexSize$: Dimension of the jitter texture [S1, unofficial].
*   $ComputeLighting$: Boolean flag for shading [S1, unofficial].
*   $\mathbf{k}_{Ambient} = (0.05, 0.05, 0.05)$ [S1, unofficial].
*   $\mathbf{k}_{Diffuse} = (1.0, 1.0, 1.0)$ [S1, unofficial].
*   $\mathbf{k}_{Specular} = (1.0, 1.0, 1.0)$ [S1, unofficial].
*   $k_{Shininess} = 100.0$ [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Set destination color $\mathbf{dst} = (0.0, 0.0, 0.0, 0.0)$ [S1, unofficial]. Calculate ray direction $\mathbf{d} = \text{normalize}(\mathbf{p}_{frag} - \mathbf{o})$ [S1, unofficial]. Calculate step vector $\mathbf{s} = \mathbf{d} \times RayStepSize$ [S1, unofficial].
2.  **Jitter Application:** Determine texture coordinate from fragment coordinates modulo $JitterTexSize$ [S1, unofficial]. Fetch jitter value $j$ from the red channel of $J$ [S1, unofficial]. Update ray position: $\mathbf{p} \leftarrow \mathbf{p} + \mathbf{s} \times j$ [S1, unofficial].
3.  **Boundary Check:** Check if $\mathbf{p}$ is inside the volume bounds [S1, unofficial]. Using the bounding box defined by $\mathbf{VolExtentMin}$ and $\mathbf{VolExtentMax}$, compute test vectors [S1, unofficial]. If $\text{dot}(\mathbf{test1}, \mathbf{test2}) \ge 3.0$, the point is inside [S1, unofficial].
4.  **Sampling:** Sample the volume at $\mathbf{p}$ to get source color/alpha $\mathbf{src}$ [S1, unofficial].
5.  **Lighting (Optional):** If $ComputeLighting$ is true:
    *   Estimate gradient normal using central differences on the alpha channel ($a$) of $\mathbf{src}$ [S1, unofficial]. Use offsets `ivec4(1, 0, 0, -1)` and permutations (yxz, yzx, wyz, ywz, yzw) to sample neighbors [S1, unofficial].
    *   Calculate $\mathbf{n} = \text{normalize}(\mathbf{sample2} - \mathbf{sample1})$ [S1, unofficial]. If $\mathbf{n}$ is NaN, skip shading [S1, unofficial].
    *   Apply Phong shading to $\mathbf{src}.rgb$ using ambient, diffuse, and specular components [S1, unofficial].
6.  **Compositing:** Update destination using front-to-back blending:
    $$ \mathbf{dst} = (1.0 - \mathbf{dst}.a) \times \mathbf{src} + \mathbf{dst} $$
7.  **Termination:** If $\mathbf{dst}.a > 0.95$, break the loop (early ray termination) [S1, unofficial].
8.  **Advance:** Update $\mathbf{p} \leftarrow \mathbf{p} + \mathbf{s}$ [S1, unofficial]. Re-evaluate boundary check [S1, unofficial]. Repeat until $NumSamples$ is reached or ray exits [S1, unofficial].
9.  **Output:** Return $\mathbf{dst}$ [S1, unofficial].

**Pseudocode:**
```python
def render_jittered_volume(ray_position, camera_position, ray_step_size, num_samples, 
                           jitter_tex, jitter_tex_size, voxel_tex, vol_extent_min, vol_extent_max,
                           compute_lighting, light_position, frag_coord):
    # 1. Initialize
    dst = vec4(0.0, 0.0, 0.0, 0.0)
    ray_dir = normalize(ray_position - camera_position)
    ray_step = ray_dir * ray_step_size
    
    # 2. Jitter offset application
    jitter_uv = vec2(frag_coord.x % jitter_tex_size, frag_coord.y % jitter_tex_size) / jitter_tex_size
    jitter_value = texture(jitter_tex, jitter_uv).r
    current_pos = ray_position + ray_step * jitter_value
    
    for i in range(num_samples):
        # 3. Boundary Check
        test1 = vec3(sign(current_pos - vol_extent_min))
        test2 = vec3(sign(vol_extent_max - current_pos))
        if dot(test1, test2) < 3.0:
            current_pos += ray_step
            continue
            
        # 4. Sample Voxel Data
        src = texture(voxel_tex, current_pos)
        
        # 5. Lighting (Optional)
        if compute_lighting:
            # Estimate gradient normal using central differences on the alpha channel
            # Offsets and permutations from source: ivec4(1, 0, 0, -1) and permutations (yxz, yzx, wyz, ywz, yzw)
            alpha_center = texture(voxel_tex, current_pos).a
            alpha_xp = texture(voxel_tex, current_pos + vec3(1.0, 0.0, 0.0)).a
            alpha_xm = texture(voxel_tex, current_pos + vec3(-1.0, 0.0, 0.0)).a
            alpha_yp = texture(voxel_tex, current_pos + vec3(0.0, 1.0, 0.0)).a
            alpha_ym = texture(voxel_tex, current_pos + vec3(0.0, -1.0, 0.0)).a
            alpha_zp = texture(voxel_tex, current_pos + vec3(0.0, 0.0, 1.0)).a
            alpha_zm = texture(voxel_tex, current_pos + vec3(0.0, 0.0, -1.0)).a
            normal = normalize(vec3(alpha_xp - alpha_xm, alpha_yp - alpha_ym, alpha_zp - alpha_zm))
            
            if not isnan(normal):
                to_camera = normalize(camera_position - current_pos)
                to_light = normalize(light_position - current_pos)
                src.rgb = shading(src.rgb, normal, to_camera, to_light)
        
        # 6. Front-to-Back Blending
        dst = (1.0 - dst.a) * src + dst
        
        # 7. Early Ray Termination
        if dst.a > 0.95:
            break
            
        # 8. Advance Ray
        current_pos += ray_step
        
    return dst

def shading(rgb, normal, to_camera, to_light):
    halfway = normalize(to_light + to_camera)
    diffuse_light = max(dot(to_light, normal), 0.0)
    diffuse = vec3(0.0, 0.0, 0.0)
    specular = vec3(0.0, 0.0, 0.0)
    
    if diffuse_light > 0.0:
        diffuse = vec3(1.0, 1.0, 1.0) * rgb * diffuse_light
        specular_light = pow(max(dot(halfway, normal), 0.0), 100.0)
        specular = vec3(1.0, 1.0, 1.0) * rgb * specular_light
        
    ambient = vec3(0.05, 0.05, 0.05) * rgb
    return ambient + diffuse + specular
```

**Edge Cases and Pitfalls:**
*   **NaN Normals:** Gradient calculation may result in NaN if `sample1` equals `sample2` or if values are identical. This is handled by checking `isnan(normal)` and skipping shading [S1, unofficial].
*   **Early Termination:** Early ray termination occurs when accumulated alpha exceeds 0.95, potentially missing faint structures behind dense ones [S1, unofficial].

## Subtopics

### [Stochastic Jittering](924-stochastic-jittering.md)
Stochastic jittering is a sampling technique used in direct volume ray casting to mitigate banding and quantization artifacts caused by regular, uniformly spaced sample positions. It differs from [Uniform Ray Sampling](1261-uniform-ray-sampling.md) by perturbing sample locations with random offsets, transforming structured aliasing into less visually noticeable noise. It is particularly effective when using low sample counts or nearest-neighbor interpolation, where regular grid patterns are most visible.

### [Hierarchical Sampling (Inverse CDF Sampling)](973-hierarchical-sampling-inverse-cdf-sampling.md)
Hierarchical sampling (Inverse CDF Sampling) is a method for generating importance samples along a ray in volume rendering by inverting the cumulative distribution function (CDF) of the rendering contribution. It solves the problem of efficiently placing sample points in regions of high density without redundant radiance queries. Unlike standard hierarchical sampling which samples from a piecewise constant probability density defined by coarse weights, this method uses inverse transform sampling on a piecewise approximated density field (constant or linear), allowing gradients to back-propagate through the sampling process to the density parameters. It builds on [Sampling and Jittering](2516-sampling-and-jittering.md) by providing a deterministic or stratified mechanism to concentrate fine samples where the coarse pass indicated high opacity [G].

### [Uniform Ray Sampling](1261-uniform-ray-sampling.md)
Uniform Ray Sampling is a ray traversal approach where samples are taken at equal distances along the ray as it passes through volume data stored on a regular grid. It serves as the baseline sampling method in NeRF, assuming every point along the ray contributes equally to the final rendering when no transmittance estimator is available. It sets itself apart from [Stochastic Jittering](924-stochastic-jittering.md) by using fixed intervals rather than random offsets, and from [Slab-based Ray Sampling](2853-slab-based-ray-sampling.md) by ignoring voxel boundaries and maintaining a constant step size regardless of scene geometry.

### [Slab-based Ray Sampling](2853-slab-based-ray-sampling.md)
Slab-based ray sampling is an image-order caching mechanism for direct volume ray casting that groups rays into rectangular screen regions to form stacked slabs, storing voxel samples in shared memory to optimize neighborhood access for lighting and compositing. Unlike object-order bricking, which struggles with GPU hardware mapping due to per-brick lists, this method leverages the regular structure of rays within a slab to reduce memory bandwidth and latency when calculating gradients or performing ambient occlusion. It is distinct from sibling methods like [Uniform Ray Sampling](1261-uniform-ray-sampling.md) by explicitly managing spatial locality in shared memory across multiple rays, and from [Stochastic Jittering](924-stochastic-jittering.md) by prioritizing deterministic cache coherence over variance reduction.

### [Supersampling](3493-supersampling.md)
Supersampling is a technique to minimize aliasing artifacts by casting multiple rays per pixel and averaging the results. It handles high-frequency components in transfer functions by performing dense quadrature of the volume render integral, assuming linearity of the scalar field between sample points but not linearity of the integral itself. Unlike pre-integration, which requires equidistant sample points and fails for nonlinear integrals, supersampling accounts for the nonlinearity of the volume render integral while avoiding oversampling of the scalar field. It differs from [Stochastic Jittering](924-stochastic-jittering.md) by using deterministic, fixed offsets for low sample counts (1x–4x) rather than random or stratified patterns, and from [Monte Carlo Volume Rendering](2060-monte-carlo-volume-rendering.md) by relying on simple arithmetic averaging rather than importance-weighted integration.

### [Importance Sampling for SPH Rendering](3624-importance-sampling-for-sph-rendering.md)
Importance Sampling for SPH Rendering is a technique to increase rendering performance by reducing the number of particles used during rendering, using a non-uniform sampling strategy based on data importance and view-dependent criteria. It solves the problem of high computational cost when rendering large, unstructured Smoothed Particle Hydrodynamics (SPH) datasets by ensuring that particles in complex regions (e.g., phase interfaces, vortices) are sampled more densely than those in homogeneous areas. It differs from [Uniform Ray Sampling](1261-uniform-ray-sampling.md) by avoiding equal-time high-error trade-offs.

### [Epipolar Sampling](3899-epipolar-sampling.md)
Epipolar sampling is a technique that places sample points along epipolar lines (rays emanating radially from a light source's projection on the screen or feature correspondences between views) to exploit the smooth variation of inscattered light or cross-view features along these lines. This reduces the number of expensive ray-marching or feature-interpolation steps required compared to uniform sampling. In volume rendering, it optimizes light shaft computation by leveraging the observation that light intensity varies smoothly orthogonally to epipolar rays. In multi-view reconstruction, it enables cross-view feature aggregation without full 3D volume rendering by correlating features along epipolar lines.

### [Warp-based Sampling](4298-warp-based-sampling.md)
Warp-based Sampling is a GPU optimization strategy for direct volume ray casting that improves texture cache performance by reorganizing thread warps to align sampling directions with the volume's memory strides. Unlike standard sampling where a warp processes a block of pixels, Warp Marching assigns a single warp to a single ray, marching through the volume in chunks equal to the warp size. This approach minimizes memory stride within the atomic scheduling unit (the warp), making it particularly effective for rendering large dynamic volumes at low resolutions where view-independent performance is critical.

### [Hierarchical Sampling](4865-hierarchical-sampling.md)
Hierarchical sampling is a two-stage strategy for volume rendering that improves image quality by concentrating samples in regions of high geometric or color complexity, addressing the bottleneck of point sampling in neural radiance fields. It sets itself apart from uniform sampling by using a coarse network to estimate density and guide importance sampling for a fine network.

### Resampling Techniques
Resampling techniques align geometry and color between scenes along corresponding rays [S2]. Uniform sampling points evenly along the ray but can lead to misalignment [S2]. A strategy exists where points are valid only if density exceeds a threshold in both scenes, without resampling [S2]. Density-based resampling identifies density peaks along each ray and adjusts sampling to align key points in both scenes, ensuring improved color-geometry consistency [S2].

### Consistent Ray Sampling
Consistent Ray Sampling ensures that ray sample intervals are consistent across all subvolumes to allow correct reconstruction of the original volume and prevent feature loss or enhancement [S3]. The starting sample location for each subvolume is calculated such that the distance between the first sample of the new subvolume and the last sample of the previous subvolume equals the predetermined interval [S3]. Incorrect calculation of sample locations causes small features in the data to be lost or enhanced erroneously [S3].

### [Ray Direction Jitter](14475-ray-direction-jitter.md)
Ray Direction Jitter improves the generalizability of learned rendering models by applying sub-pixel noise to ray directions. It prevents the color network from overfitting to specific training viewing directions, which otherwise leads to artifacts in novel view synthesis and texture reproduction. Unlike [Uniform Ray Sampling](1261-uniform-ray-sampling.md) which distributes samples across a pixel area, this method perturbs the ray vector itself while ensuring the ray remains confined within the pixel's geometric boundaries.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray ($NumSamples$) and the number of pixels.
*   **Memory Complexity:** Depends on the volume texture size and the jitter texture size ($JitterTexSize^2$).
*   **Strengths:** Reduces banding artifacts significantly compared to uniform sampling, especially at low sample counts. Simple to implement in shaders.
*   **Limitations:** Early ray termination may miss faint structures. Gradient estimation can be noisy or produce NaNs.
*   **When to use:** When visual quality (reduction of banding) is prioritized over strict physical accuracy or when using low sample counts.
*   **When not to use:** When high precision is required for faint structures behind dense ones, or when deterministic sampling is strictly required for reproducibility without random seeds.

## Background
The method originates from direct volume ray casting techniques that utilize jittered sampling to mitigate aliasing. The specific implementation details, including the jitter texture lookup and Phong shading integration, are documented in the VoxViz thesis [S1, unofficial].
