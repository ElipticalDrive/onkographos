# Ray Direction Jitter

Also called: Direction Jitter, Ray Direction Noise

## Overview
Ray Direction Jitter is a technique that improves the generalizability of learned rendering models by applying sub-pixel noise to ray directions [S1, S2]. It prevents the color network from overfitting to specific training viewing directions, which otherwise leads to artifacts in novel view synthesis and texture reproduction [S2]. Unlike [Uniform Ray Sampling](1261-uniform-ray-sampling.md) which distributes samples across a pixel area, this method perturbs the ray vector itself while ensuring the ray remains confined within the pixel's geometric boundaries [S1, G].

## How it works
**Inputs and Outputs:**
*   Input: Ray origin $\mathbf{o}$, nominal ray direction $\mathbf{d}$, and pixel boundary constraints [S1, S2].
*   Output: Jittered ray direction $\mathbf{d}' = \mathbf{d} + \psi$ and the resulting ray equation [S1, S2].

**Data Structures:**
*   $\mathbf{o}$: 3D vector $(o_x, o_y, o_z)$ representing the camera origin [S1, S2].
*   $\mathbf{d}$: 3D vector $(d_x, d_y, d_z)$ representing the nominal ray direction pointing through the pixel center [S1, S2].
*   $\psi$: 3D vector representing the sub-pixel jitter noise [S1, S2].

**Steps:**
1.  Sample a jitter vector $\psi$ uniformly [S1].
2.  The sampling distribution must ensure that the perturbed ray $\mathbf{o} + t(\mathbf{d} + \psi)$ remains within the pixel boundaries for all $t > 0$ [S1].
3.  Compute the jittered direction: $\mathbf{d}' = \mathbf{d} + \psi$ [S1, S2].
4.  Construct the ray equation: $\mathbf{x}_i = \mathbf{o} + t_i (\mathbf{d} + \psi)$ [S1, S2].

**Formula:**
$$ \mathbf{x}_i = \mathbf{o} + t_i (\mathbf{d} + \psi) $$
Where:
*   $\mathbf{x}_i$ is the point on the ray at distance $t_i$ [S1, S2].
*   $\mathbf{o}$ is the camera origin [S1, S2].
*   $\mathbf{d}$ is the nominal ray direction (pointing through the pixel center) [S1, S2].
*   $\psi$ is the sub-pixel jitter noise [S1, S2].
*   $t_i$ is the distance along the ray [S1, S2].

**Parameters:**
*   The magnitude of $\psi$ is determined by the pixel size and camera intrinsics to ensure boundary confinement [G]. Specific numerical bounds for $\psi$ are not given in the sources [S1, S2].

**Pitfalls:**
*   Without jitter, the color network tends to overfit training viewing directions, leading to visible artifacts in rendering and textures [S2].
*   The jitter must be sampled such that the ray does not exit the pixel boundaries; otherwise, the sample no longer corresponds to the intended pixel [S1].

**Pseudocode:**
```python
import random

def jitter_ray_direction(origin, nominal_direction, pixel_size, focal_length):
    """
    Generates a jittered ray direction confined to pixel boundaries.
    
    Args:
        origin: 3D vector (o_x, o_y, o_z)
        nominal_direction: 3D vector (d_x, d_y, d_z)
        pixel_size: float, physical pixel width/height
        focal_length: float, camera focal length
        
    Returns:
        jittered_direction: 3D vector (d_x + psi_x, d_y + psi_y, d_z + psi_z)
    """
    # [G] Sources do not specify the exact sampling distribution for ψ.
    # Standard implementation samples a 2D offset in the image plane
    # and transforms it to 3D direction space relative to the origin.
    u = random.uniform(-0.5, 0.5)
    v = random.uniform(-0.5, 0.5)
    psi_x = u * pixel_size / focal_length
    psi_y = v * pixel_size / focal_length
    psi = [psi_x, psi_y, 0.0]
    
    jittered_direction = [nominal_direction[i] + psi[i] for i in range(3)]
    return jittered_direction
```

## Subtopics

### Stochastic Jittering
Adds random noise to break aliasing patterns; broader category including this method [G]. Choose when general banding reduction is needed across multiple rendering passes [G]. [Link](924-stochastic-jittering.md)

### Hierarchical Sampling (Inverse CDF Sampling)
Samples based on probability density functions for importance; different goal than generalizability [G]. Choose when variance reduction via importance sampling is required for complex integrands [G]. [Link](973-hierarchical-sampling-inverse-cdf-sampling.md)

### Uniform Ray Sampling
Distributes samples evenly across the pixel area without directional perturbation [G]. Choose when isotropic pixel coverage is preferred over view-dependent generalization [G]. [Link](1261-uniform-ray-sampling.md)

## Operating characteristics
*   **Time Complexity**: Adds negligible overhead as it involves only vector addition and a single random sample per ray [G].
*   **Memory Complexity**: No additional memory required beyond storing the jittered direction [G].
*   **Performance**: The source [S2] notes that without this noise, the model achieves a Novel PSNR of 28.56, View SSIM of 0.962, and Synthesis LPIPS of 0.058 [S2]. The jitter improves these metrics by preventing overfitting, though exact improved values are not provided in the notes [S2].
*   **Strengths**: Improves generalizability of learned color networks [S1, S2]. Prevents overfitting to training viewing directions [S2].
*   **Limitations**: Requires careful implementation to ensure rays remain within pixel boundaries [S1]. Exact numerical bounds for the jitter magnitude are not specified in the sources [S1, S2].

## Background
Ray Direction Jitter was introduced in the context of NeRF for Outdoor Scene Relighting [S1] and UV Volumes for Real-time Rendering of Editable Free-view Human Performance [S2]. It addresses the issue of learned rendering models overfitting to the specific viewing directions present in the training dataset [S1, S2].
