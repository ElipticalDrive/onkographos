# Ray Direction Jitter

Also called: Direction Jitter, Ray Direction Noise

## Overview
Ray Direction Jitter is a technique that improves the generalizability of learned rendering models by applying sub-pixel noise to ray directions [S1, S2]. It prevents the color network from overfitting to specific training viewing directions, which otherwise leads to artifacts in novel view synthesis and texture reproduction [S2]. Unlike [Uniform Ray Sampling](1261-uniform-ray-sampling.md) which distributes samples across a pixel area, this method perturbs the ray vector itself while ensuring the ray remains confined within the pixel's geometric boundaries [S1].

## How it works
**Inputs and Outputs:**
*   Input: Ray origin $\mathbf{o}$, nominal ray direction $\mathbf{d}$, and pixel boundary constraints.
*   Output: Jittered ray direction $\mathbf{d}' = \mathbf{d} + \psi$ and the resulting ray equation.

**Data Structures:**
*   $\mathbf{o}$: 3D vector $(o_x, o_y, o_z)$.
*   $\mathbf{d}$: 3D vector $(d_x, d_y, d_z)$, typically normalized.
*   $\psi$: 3D vector representing the jitter offset.

**Steps:**
1.  Sample a jitter vector $\psi$ uniformly. The sampling distribution must ensure that the perturbed ray $\mathbf{o} + t(\mathbf{d} + \psi)$ remains within the pixel boundaries for all $t > 0$ [S1].
2.  Compute the jittered direction: $\mathbf{d}' = \mathbf{d} + \psi$.
3.  Construct the ray equation: $\mathbf{x}_i = \mathbf{o} + t_i (\mathbf{d} + \psi)$ [S1, S2].

**Formula:**
$$ \mathbf{x}_i = \mathbf{o} + t_i (\mathbf{d} + \psi) $$
Where:
*   $\mathbf{x}_i$ is the point on the ray at distance $t_i$.
*   $\mathbf{o}$ is the camera origin.
*   $\mathbf{d}$ is the nominal ray direction (pointing through the pixel center).
*   $\psi$ is the sub-pixel jitter noise [S1, S2].
*   $t_i$ is the distance along the ray.

**Parameters:**
*   The magnitude of $\psi$ is determined by the pixel size and camera intrinsics to ensure boundary confinement. Specific numerical bounds for $\psi$ are not given in the sources [S1, S2].

**Pitfalls:**
*   Without jitter, the color network tends to overfit training viewing directions, leading to visible artifacts in rendering and textures [S2].
*   The jitter must be sampled such that the ray does not exit the pixel boundaries; otherwise, the sample no longer corresponds to the intended pixel [S1].

**Pseudocode:**
```python
def jitter_ray_direction(origin, nominal_direction, pixel_bounds):
    """
    Generates a jittered ray direction confined to pixel boundaries.
    
    Args:
        origin: 3D vector (o_x, o_y, o_z)
        nominal_direction: 3D vector (d_x, d_y, d_z)
        pixel_bounds: Object or tuple defining the min/max x and y offsets 
                      relative to the pixel center at a reference depth.
                      Implementation detail: [G] The exact sampling distribution 
                      for psi depends on the camera projection matrix and pixel 
                      dimensions to ensure the ray stays within the pixel frustum.
    
    Returns:
        jittered_direction: 3D vector (d_x + psi_x, d_y + psi_y, d_z + psi_z)
    """
    # Sample psi uniformly such that the ray confines to the pixel boundaries [S1]
    # [G] In practice, this involves sampling a 2D offset in the image plane 
    # and transforming it back to 3D direction space relative to the origin.
    psi = sample_uniform_within_pixel_bounds(origin, nominal_direction, pixel_bounds)
    
    jittered_direction = nominal_direction + psi
    return jittered_direction
```

## Subtopics

### Stochastic Jittering
Uses random noise to break aliasing patterns; broader category including this method. [Link](924-stochastic-jittering.md)

### Hierarchical Sampling (Inverse CDF Sampling)
Samples based on probability density functions for importance; different goal than generalizability. [Link](973-hierarchical-sampling-inverse-cdf-sampling.md)

### Uniform Ray Sampling
Distributes samples evenly across the pixel area without directional perturbation. [Link](1261-uniform-ray-sampling.md)

## Operating characteristics
*   **Time Complexity**: Adds negligible overhead as it involves only vector addition and a single random sample per ray [S1, S2].
*   **Memory Complexity**: No additional memory required beyond storing the jittered direction [S1, S2].
*   **Performance**: The source [S2] notes that without this noise, the model achieves a Novel PSNR of 28.56, View SSIM of 0.962, and Synthesis LPIPS of 0.058. The jitter improves these metrics by preventing overfitting, though exact improved values are not provided in the notes [S2].
*   **Strengths**: Improves generalizability of learned color networks; reduces artifacts in novel views [S1, S2].
*   **Limitations**: Requires careful implementation to ensure rays remain within pixel boundaries [S1].

## Background
Ray Direction Jitter was introduced in the context of NeRF for Outdoor Scene Relighting [S1] and UV Volumes for Real-time Rendering of Editable Free-view Human Performance [S2]. It addresses the issue of learned rendering models overfitting to the specific viewing directions present in the training dataset [S1, S2].
