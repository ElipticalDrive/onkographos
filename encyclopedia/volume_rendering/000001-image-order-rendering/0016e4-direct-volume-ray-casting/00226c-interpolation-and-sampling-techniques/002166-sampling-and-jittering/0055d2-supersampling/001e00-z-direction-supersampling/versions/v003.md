# Z-direction Supersampling

Also called: Supersampling in z, VolumePro Supersampling

## Overview
Z-direction supersampling is a hardware-accelerated technique that reduces aliasing artifacts by increasing the number of sample slices per volume in the z-direction, interpolating additional sample slices between existing voxel slices [S1, S2, unofficial]. It is distinct from its sibling [Multi-Sample Anti-Aliasing via Ray Distribution](1219-multi-sample-anti-aliasing-via-ray-distribution.md) because it operates by interpolating additional sample slices between existing voxel slices along the volume's z-axis, rather than distributing multiple rays per pixel in the image plane [S1, S2, unofficial].

## How it works
**Inputs:** Volume dataset stored in voxel memory; viewing parameters (viewing angle, sample spacing) [S1, unofficial].
**Outputs:** Rendered image with reduced aliasing artifacts [G].
**Data Structures:** The volume data is stored in voxel memory [S1, unofficial]. The hardware pipeline includes an Interpolation unit that processes slices in order [S1, unofficial].

**Steps:**
1.  **Interpolation:** The hardware interpolates additional sample slices between existing voxel slices in the z-direction [S2, unofficial]. This is done by performing several interpolations from the same pair of adjacent voxel slices before moving to the next slice pair [S1, unofficial]. Samples pass from the Interpolation unit in slice-by-slice order [S1, unofficial].
2.  **Opacity Correction:** The software automatically corrects opacity according to the viewing angle and the new sample spacing by reloading the opacity table [S2, unofficial].
3.  **Rendering:** The interpolated slices are composited along the ray [G]. If the supersampling factor is $k$, the total number of sample slices exceeds the number of voxel slices by a factor of $k$ [S1, unofficial].

**Parameters:**
*   **Supersampling Factor ($k$):** The maximum supersampling factor in z is eight [S1, S2, unofficial]. Typical values include 2x [S1, unofficial] and 3x [S2, unofficial].

**Pitfalls:**
*   **Pipeline Stall:** The voxel memory stages of the pipeline must stall and wait for the additional, supersampled slices to clear, which reduces the rendering rate [S1, unofficial].
*   **Performance:** For a $256^3$ data set, supersampling reduces the rendering rate to 30 frames per second [S1, unofficial].

**Pseudocode:**
```python
def z_direction_supersampling(volume, ray_origin, ray_direction, step_size, supersampling_factor):
    """
    volume: 3D list [Z][Y][X] of (R, G, B, alpha) tuples.
    ray_origin: (ox, oy, oz)
    ray_direction: (dx, dy, dz)
    step_size: float (original voxel spacing)
    supersampling_factor: int k (max 8)
    Returns: (R, G, B, alpha)
    """
    # Opacity correction handled by reloading the opacity table based on viewing angle and spacing [S2, unofficial]
    def apply_opacity_correction(alpha, viewing_angle, sample_spacing, k):
        # Standard correction scales opacity by the ratio of original to supersampled spacing
        return alpha * (sample_spacing / (sample_spacing / k))

    # Linear interpolation between two adjacent voxel slices [S1, unofficial]
    def interpolate_slices(slice_a, slice_b, fraction):
        return (
            slice_a[0] * (1.0 - fraction) + slice_b[0] * fraction,
            slice_a[1] * (1.0 - fraction) + slice_b[1] * fraction,
            slice_a[2] * (1.0 - fraction) + slice_b[2] * fraction,
            slice_a[3] * (1.0 - fraction) + slice_b[3] * fraction
        )

    # Initialize compositing state
    alpha_out = 0.0
    color_out = [0.0, 0.0, 0.0]

    # Volume dimensions
    vol_z = len(volume)
    vol_y = len(volume[0])
    vol_x = len(volume[0][0])

    # Ray parameters
    ox, oy, oz = ray_origin
    dx, dy, dz = ray_direction

    # Effective step size in z accounts for supersampling factor k [S1, unofficial]
    step_z = step_size / supersampling_factor

    t = 0.0
    while True:
        x = ox + dx * t
        y = oy + dy * t
        z = oz + dz * t

        # Check bounds
        if not (0 <= x < vol_x and 0 <= y < vol_y and 0 <= z < vol_z):
            break

        # Get voxel indices
        ix, iy, iz = int(x), int(y), int(z)
        # Clamp indices to valid interpolation range
        if ix < 0: ix = 0
        if iy < 0: iy = 0
        if iz < 0: iz = 0
        if ix >= vol_x - 1: ix = vol_x - 2
        if iy >= vol_y - 1: iy = vol_y - 2
        if iz >= vol_z - 1: iz = vol_z - 2

        # Z-supersampling interpolation between adjacent slices [S1, unofficial]
        fz = z - iz
        c1 = volume[iz][iy][ix]
        c2 = volume[iz + 1][iy][ix]
        sample = interpolate_slices(c1, c2, fz)

        # Apply opacity correction for supersampling [S2, unofficial]
        a = apply_opacity_correction(sample[3], 0.0, step_size, supersampling_factor)

        # Front-to-back compositing
        alpha_out += a * (1.0 - alpha_out)
        color_out[0] += sample[0] * a * (1.0 - alpha_out)
        color_out[1] += sample[1] * a * (1.0 - alpha_out)
        color_out[2] += sample[2] * a * (1.0 - alpha_out)

        if alpha_out >= 1.0:
            break

        t += step_z

    return color_out[0], color_out[1], color_out[2], alpha_out
```

## Operating characteristics
*   **Time Complexity:** Rendering time increases with the supersampling factor $k$ due to the increased number of slices to process and the pipeline stall [S1, unofficial].
*   **Memory Complexity:** Requires storing additional interpolated slices in the pipeline buffer, causing stalls [S1, unofficial].
*   **Performance:** For a $256^3$ dataset, rendering rate drops to 30 fps with supersampling [S1, unofficial]. For a $152 \times 261 \times 200$ CT scan, 3x supersampling reduces artifacts caused by insufficient sampling rate of high frequencies on the foot surface [S2, unofficial].
*   **Strengths:** Hardware-accelerated, effective at reducing aliasing artifacts caused by insufficient sampling rate of high frequencies [S2, unofficial].
*   **Limitations:** Limited to z-direction in hardware [S1, S2, unofficial]. Supersampling in x and y requires software-based multi-pass rendering and blending [S1, unofficial]. Pipeline stalls reduce throughput [S1, unofficial].
*   **When to use:** When aliasing artifacts are visible due to coarse z-sampling, especially for high-frequency surfaces [S2, unofficial].
*   **When not to use:** When performance is critical and artifacts are acceptable, or when supersampling in x/y is required (requires software workaround) [S1, unofficial].

## Background
Z-direction supersampling was introduced in the VolumePro real-time ray-casting system [S1, S2, unofficial]. VolumePro is a hardware-accelerated volume rendering system [S1, unofficial]. The technique was designed to address aliasing artifacts in real-time volume rendering by increasing the sampling density along the volume's z-axis [S1, S2, unofficial]. It is part of the VolumePro hardware's support for high-quality volume visualization [S1, S2, unofficial].
