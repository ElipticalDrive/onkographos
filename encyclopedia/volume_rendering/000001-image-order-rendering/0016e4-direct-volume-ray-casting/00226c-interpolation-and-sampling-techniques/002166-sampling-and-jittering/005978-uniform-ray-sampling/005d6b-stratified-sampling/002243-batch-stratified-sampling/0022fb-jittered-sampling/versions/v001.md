# Jittered Sampling

Also called: Grid-based Jittered Sampling

## Overview
Jittered Sampling generates a regular grid of samples per pixel with independent uniform random offsets within each grid cell to reduce aliasing while maintaining stratification [S1, unofficial]. It enhances supersampling by introducing random offsets to ray origins within the pixel grid, distributing samples more evenly and reducing patterned artifacts compared to uniform grids [S2]. Unlike standard uniform ray sampling, it breaks the rigid alignment of sample positions, which prevents coherent aliasing patterns in volume rendering.

## How it works
**Inputs:**
- `Adepth`: The number of samples along each axis per pixel (integer, typically $\ge 1$).
- `sample->getX()`, `sample->getY()`: The base coordinates of the pixel or voxel center in the image/texture space.
- `randf()`: A function returning a uniform random float in $[0, 1)$.

**Outputs:**
- A set of 2D sample coordinates for the pixel.

**Data Structures:**
- No complex structures required. The method operates on scalar coordinates.

**Steps:**
1. Iterate through the grid of samples defined by `Adepth`.
2. For each grid cell defined by indices `ax` and `ay` (where $0 \le ax < Adepth$ and $0 \le ay < Adepth$):
   a. Compute the normalized grid position:
      $$xOffset = \frac{ax}{Adepth}$$
      $$yOffset = \frac{ay}{Adepth}$$
   b. Generate independent random offsets within the cell boundaries:
      $$xOffsetRandom = randf() \times xOffset$$
      $$yOffsetRandom = randf() \times yOffset$$
   c. Compute the final sample position:
      $$x_{final} = sample \rightarrow getX() + xOffset + xOffsetRandom$$
      $$y_{final} = sample \rightarrow getY() + yOffset + yOffsetRandom$$
   d. Use $(x_{final}, y_{final})$ as the sampling coordinate.

**Pseudocode:**
```python
def jittered_sample(Adepth, base_x, base_y, randf):
    samples = []
    for ax in range(Adepth):
        for ay in range(Adepth):
            # Compute normalized grid offset
            x_offset = ax / Adepth
            y_offset = ay / Adepth
            
            # Generate random jitter within the cell [0, offset]
            # Note: The source defines the jitter range as [0, offset], 
            # not [0, 1/Adepth]. This implies the cell size is normalized 
            # by the grid index, which is a specific implementation detail 
            # from the source [S1, unofficial]. Standard stratified sampling usually 
            # uses cell size 1/Adepth. We follow the source exactly.
            x_jitter = randf() * x_offset
            y_jitter = randf() * y_offset
            
            # Final coordinate
            final_x = base_x + x_offset + x_jitter
            final_y = base_y + y_offset + y_jitter
            
            samples.append((final_x, final_y))
    return samples
```

**Parameters:**
- `Adepth`: Controls the density of samples. Higher values increase quality but also cost. Typical values depend on the desired anti-aliasing strength.

**Edge Cases and Pitfalls:**
- **Precision:** Ensure `randf()` is uniform and independent for each sample to maintain the statistical benefits of jittering.
- **Boundary Conditions:** The source formula adds the jitter to the base offset. If `Adepth` is 1, `x_offset` is 0, resulting in no jitter. This is consistent with the definition of jittered sampling as an enhancement to supersampling.
- **Source Discrepancy:** The source [S1, unofficial] defines the jitter magnitude as proportional to the grid index (`ax/Adepth`). This is non-standard for typical "stratified sampling" where jitter is proportional to the cell width ($1/Adepth$). The implementation must follow the source formula exactly if adhering strictly to [S1, unofficial], but note that this results in non-uniform cell sizes in the normalized space if interpreted strictly. However, given the context of "Grid-based Jittered Sampling", it is likely intended to distribute samples within the pixel. The standard interpretation of jittered sampling is uniform jitter within each sub-pixel. The source code snippet suggests `xOffset` is the grid step. If `randf()` is in $[0,1)$, then `xOffsetRandom` is in $[0, xOffset)$. This means the jitter range grows with the grid index, which is unusual. It is possible `xOffset` in the source refers to the cell width ($1/Adepth$) and the variable name is misleading, or the source implements a specific variant. Given the instruction to follow the source, the pseudocode above reflects the literal formula. *Correction*: Re-reading [S1, unofficial], `xOffset = ax / Adepth`. If `ax` goes from 0 to `Adepth-1`, then `xOffset` goes from 0 to $(Adepth-1)/Adepth$. This creates a non-uniform distribution. However, standard jittered sampling uses uniform jitter within each stratum. The source [S1, unofficial] might be a specific implementation detail or a typo in the variable naming (perhaps `xOffset` was meant to be `1/Adepth`). Given the constraint to implement from the source, we use the formula provided. *Note*: In standard graphics literature, jittered sampling uses uniform jitter within each cell of size $1/N$. The source [S1, unofficial] formula is idiosyncratic. We present it as is, marked by the source.

## Operating characteristics
- **Time Complexity:** $O(N^2)$ per pixel, where $N = Adepth$.
- **Memory Complexity:** $O(1)$ auxiliary space per sample.
- **Strengths:** Reduces aliasing artifacts compared to uniform sampling by breaking up coherent patterns. Simple to implement.
- **Limitations:** The specific jitter formula in [S1, unofficial] may not provide optimal stratification compared to standard uniform jitter within cells. Performance scales quadratically with `Adepth`.
- **When to use:** When supersampling is needed to reduce aliasing in volume rendering, and a simple, low-overhead method is preferred.
- **When not to use:** When high-quality stratification is critical and the non-standard jitter distribution of [S1, unofficial] is unacceptable. Consider standard stratified sampling or adaptive methods.

## Background
Jittered sampling is an enhancement to supersampling introduced to reduce patterned artifacts in ray casting [S2]. It is used in volume rendering to improve the visual quality of ray-cast images by distributing samples more evenly within pixels [S1, unofficial][S2]. The method is part of the family of sampling and jittering techniques in direct volume ray casting.
