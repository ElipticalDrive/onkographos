# Supersampling

Also called: Hardware Supersampling, Multi-sampling, Oversampling

## Overview
Supersampling is a technique to minimize aliasing artifacts by casting multiple rays per pixel and averaging the results, effectively sampling the scene at a higher spatial frequency than the displayed resolution [S2, S3, S4, unofficial]. It addresses the coarse granularity of per-pixel sampling, which causes visible artifacts such as jagged edges (staircase artifacts) and moiré patterns, particularly along object silhouettes where intensity changes abruptly [S1, S4, unofficial]. Unlike standard single-sampling, supersampling provides a more accurate color representation for each pixel by integrating the signal over the pixel area [S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume dataset $V$, a camera projection matrix, and a supersampling factor $k$ (or distribution pattern).
*   **Output:** A rendered image where each pixel color $C_{pixel}$ is the average of $N$ sub-sample colors.

**Data Structures:**
*   **Pixel Buffer:** Stores the accumulated color values. For $N$ samples per pixel, an accumulator buffer of size $N \times W \times H$ (where $W, H$ are image dimensions) is typically used to store partial sums before division.
*   **Sample Pattern:** A set of 2D offsets $(\delta x_i, \delta y_i)$ for $i \in [0, N-1]$ relative to the pixel center.

**Numbered Steps:**
1.  **Initialize Accumulator:** For each pixel $(u, v)$ in the output image, initialize an accumulator $A_{u,v} = 0$ and a counter $C_{u,v} = 0$.
2.  **Generate Sample Points:** For each pixel $(u, v)$, generate $N$ sample positions in screen space. The position $s_i$ for the $i$-th sample is calculated as:
    $$ s_i = (u + 0.5 + \delta x_i, v + 0.5 + \delta y_i) $$
    where $(\delta x_i, \delta y_i)$ are the offsets defined by the chosen distribution pattern [S4, unofficial].
3.  **Ray Casting:** For each sample point $s_i$, construct a ray originating from the camera center and passing through $s_i$ [S2, unofficial].
4.  **Volume Integration:** Perform volume ray casting along the ray. Sample the volume data $V$ at the ray's intersection points using the parent method's interpolation scheme [Parent]. Compute the accumulated color $c_i$ and opacity $\alpha_i$ for the sample [S4, unofficial].
5.  **Accumulate:** Add the sample color $c_i$ to the pixel accumulator:
    $$ A_{u,v} \leftarrow A_{u,v} + c_i $$
    $$ C_{u,v} \leftarrow C_{u,v} + 1 $$
6.  **Finalize:** After all samples for all pixels are processed, compute the final pixel color by dividing the accumulator by the number of samples $N$ (or $C_{u,v}$ if adaptive):
    $$ C_{pixel}(u,v) = \frac{A_{u,v}}{N} $$

**Parameters:**
*   **Sampling Rate ($N$):** The number of samples per pixel. A common value is 5 samples per pixel (e.g., 4 corners + 1 center) [S2, unofficial].
*   **Supersampling Factor ($k$):** In hardware implementations (e.g., VolumePro), this refers to the number of interpolated slices in the z-direction. The maximum factor is typically 8 [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Aliasing from Regular Grids:** Using regular spacing for sample points in the x- and y-directions can still result in aliasing artifacts due to periodicity [S4, unofficial]. Uniform or jittered distributions are preferred [S4, unofficial].
*   **Performance Cost:** Supersampling increases the number of rays linearly with $N$, reducing rendering frame rates. For example, in the VolumePro hardware, supersampling by a factor of $k$ reduces the rendering rate of a $256^3$ dataset to 30 frames per second due to pipeline stalls [S3, unofficial].
*   **Hardware Limitations:** Hardware supersampling is often restricted to specific dimensions. In VolumePro, hardware support exists only for the z-direction (interpolating slices); x- and y-direction supersampling must be implemented via software re-rendering [S3, unofficial].

**Pseudocode:**
```python
def supersample_render(volume, camera, width, height, samples_per_pixel, sample_offsets):
    """
    Renders a volume using supersampling.
    
    Args:
        volume: 3D array of voxel values.
        camera: Camera object with project_ray(screen_x, screen_y) method.
        width: Image width in pixels.
        height: Image height in pixels.
        samples_per_pixel: Integer N, number of samples per pixel.
        sample_offsets: List of (dx, dy) tuples for the N samples.
        
    Returns:
        image: 2D array of final pixel colors.
    """
    # Initialize accumulator buffers
    # Using float accumulation to prevent precision loss during summation
    acc_color = [[(0.0, 0.0, 0.0) for _ in range(width)] for _ in range(height)]
    
    for y in range(height):
        for x in range(width):
            pixel_sum = (0.0, 0.0, 0.0)
            
            # Iterate over all sub-samples for this pixel
            for dx, dy in sample_offsets:
                # Calculate screen coordinates for the sub-sample
                # Pixel center is at (x + 0.5, y + 0.5)
                sample_x = x + 0.5 + dx
                sample_y = y + 0.5 + dy
                
                # Cast ray for this sub-sample
                ray = camera.project_ray(sample_x, sample_y)
                
                # Perform volume integration (calls parent method logic)
                # Returns accumulated color (r, g, b) for this specific ray
                sample_color = volume_ray_cast(ray, volume)
                
                # Accumulate
                pixel_sum = (
                    pixel_sum[0] + sample_color[0],
                    pixel_sum[1] + sample_color[1],
                    pixel_sum[2] + sample_color[2]
                )
            
            # Average the samples
            if samples_per_pixel > 0:
                final_color = (
                    pixel_sum[0] / samples_per_pixel,
                    pixel_sum[1] / samples_per_pixel,
                    pixel_sum[2] / samples_per_pixel
                )
            else:
                final_color = (0.0, 0.0, 0.0)
                
            acc_color[y][x] = final_color
            
    return acc_color
```

## Subtopics

### Differential Super-Sampling
A technique to mitigate interpolation artifacts in sliced-based volume rendering by adjusting the supersampling level per slab based on its distance to the viewpoint. Slabs closer to the viewpoint are assigned a higher supersampling level, while farther slabs use a lower level [S5, unofficial]. This balances image quality and rendering speed, unlike uniform supersampling which causes performance degradation across all slabs [S5, unofficial].

### Z-direction Supersampling
A hardware-accelerated technique to reduce aliasing by increasing the number of sample slices per volume in the z-direction. It interpolates additional sample slices between existing voxel slices, with a maximum supersampling factor of eight [S3, unofficial]. The pipeline stalls to wait for these additional slices, reducing rendering rates (e.g., to 30 fps for a $256^3$ dataset with factor $k$) [S3, unofficial].

### XY-direction Supersampling
A software-based technique to achieve supersampling in the x and y directions. It involves rendering the volume multiple times with slightly different sub-pixel accurate initial offsets of the base plane in the x and y dimensions, then blending the resulting images in software [S3, unofficial].

### Supersampling with Reconstruction Filters
A technique that improves image quality by supersampling a 3D dataset using a high-quality reconstruction filter in a pre-processing step, then rendering the higher-resolution dataset using standard trilinear interpolation. This yields noticeable quality improvements without necessarily increasing rendering time, addressing the low quality of standard trilinear interpolation [S6].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot R \cdot S)$, where $N$ is the number of samples per pixel, $R$ is the number of rays (pixels), and $S$ is the number of samples per ray. Supersampling increases computational cost linearly with $N$ [S1, S4, unofficial].
*   **Memory Complexity:** $O(N \cdot W \cdot H)$ for the accumulator buffer if not rendered directly to frame buffer, or $O(1)$ extra if using floating-point frame buffers with accumulation [S4, unofficial].
*   **Performance:** Significant performance hit. In hardware implementations like VolumePro, supersampling by factor $k$ reduces frame rates substantially due to pipeline stalls [S3, unofficial]. Software-based XY supersampling requires $N$ full render passes, multiplying the cost by $N$ [S3, unofficial].
*   **Strengths:** Effectively reduces aliasing and jagged edges; improves visual quality of silhouettes and high-frequency details [S2, S4, unofficial].
*   **Limitations:** High computational cost; regular sampling patterns can still alias; hardware support is often limited to specific dimensions (z-axis) [S3, S4, unofficial].
*   **When to use:** When visual quality is critical and performance budget allows; for static scenes or offline rendering.
*   **When not to use:** When real-time performance is required and aliasing can be tolerated or handled by other means (e.g., MSAA in rasterization, though this is volume rendering); when hardware only supports limited supersampling dimensions [S3, unofficial].

## Background
Supersampling originated as a general anti-aliasing technique in computer graphics, applied to volume rendering to combat artifacts caused by coarse sampling [S4, unofficial]. The VolumePro real-time ray-casting system implemented hardware-accelerated supersampling in the z-direction, demonstrating its feasibility for real-time applications but highlighting performance trade-offs [S3, unofficial]. Adaptive approaches using convolution to target high-contrast areas were also explored to optimize the cost [S4, unofficial]. Differential supersampling was later introduced in shear-warp factorization systems to optimize performance based on depth [S5, unofficial]. Pre-processing with reconstruction filters was proposed to leverage hardware trilinear interpolation for higher quality [S6].
