# Multi-Sample Anti-Aliasing via Ray Distribution

Also called: Multi-ray AA, Multi-sample AA, Ray Distribution AA, MSAA via Ray Distribution

## Overview
Multi-Sample Anti-Aliasing via Ray Distribution reduces jagged edges in volume rendering by casting multiple rays per pixel, distributed within the pixel area, and averaging the results [S1, S2, S3, unofficial]. It samples the scene at a higher effective resolution to combat aliasing artifacts caused by abrupt changes in intensity along silhouette edges [S3, unofficial]. The method uses deterministic offset patterns derived from fragment coordinates to select sample positions [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Integer pixel coordinates (e.g., `gl_FragCoord`), an integer uniform `AA` selecting the sampling mode (1, 2, 3, or 4), and a rendering function `render(uv)` that performs volume integration for a given normalized UV offset within the pixel [S1, S2, unofficial].
*   **Output:** A single averaged color value for the pixel [S1, unofficial].

**Data Structures:**
The method operates on scalar values and fixed offset vectors without requiring complex data structures [G].

**Parameters:**
*   `AA`: Integer uniform selector. Values: 1, 2, 3, 4. The default mode is 4 if the uniform is not explicitly set to 1, 2, or 3 [S2, unofficial].

**Steps:**
1.  **Select Mode:** Determine the number of samples $N$ based on the `AA` uniform value [S2, unofficial].
2.  **Generate Offsets:** Calculate 2D UV offsets $(\delta u, \delta v)$ for each of the $N$ rays relative to the pixel center [S1, unofficial]. The offsets are additive to the pixel's base UV coordinate [S2, unofficial].
3.  **Cast Rays:** For each sample $i \in [0, N-1]$, compute the ray origin/direction using the calculated offset and call `render` to obtain color $C_i$ [S1, S2, unofficial].
4.  **Average:** Sum the color results of all rays and divide by $N$ to calculate the average color [S1, unofficial].

**Formulas and Offsets:**
Let $bxy = (x + y) \pmod 2$, where $x$ and $y$ are the integer pixel coordinates (e.g., from `gl_FragCoord`) [S2, unofficial]. Let $nbxy = 1 - bxy$ [S2, unofficial].

*   **AAx1 ($N=1$):**
    *   Offset: $(0, 0)$.
    *   Formula: $C = \text{render}(\text{getUV}(0, 0))$ [S2, unofficial].

*   **AAx2 ($N=2$):**
    *   Offsets: $(0.33 \cdot nbxy, 0)$ and $(0.33 \cdot bxy, 0.66)$ [S2, unofficial].
    *   Formula: $C = \frac{1}{2} \left( \text{render}(\text{getUV}(0.33 \cdot nbxy, 0)) + \text{render}(\text{getUV}(0.33 \cdot bxy, 0.66)) \right)$ [S2, unofficial].

*   **AAx3 ($N=3$):**
    *   Offsets: $(0.66 \cdot nbxy, 0)$, $(0.66 \cdot bxy, 0.66)$, and $(0.33, 0.33)$ [S2, unofficial].
    *   Formula: $C = \frac{1}{3} \left( \text{render}(\text{getUV}(0.66 \cdot nbxy, 0)) + \text{render}(\text{getUV}(0.66 \cdot bxy, 0.66)) + \text{render}(\text{getUV}(0.33, 0.33)) \right)$ [S2, unofficial].

*   **AAx4 ($N=4$):**
    *   Define vector $e = (0.125, -0.125, 0.375, -0.375)$ [S2, unofficial].
    *   Offsets: $(e_x, e_z)$, $(e_y, e_w)$, $(e_w, e_x)$, $(e_z, e_y)$ [S2, unofficial].
    *   Explicit Offsets: $(0.125, 0.375)$, $(-0.125, -0.375)$, $(-0.375, 0.125)$, $(0.375, -0.125)$ [S2, unofficial].
    *   Formula: $C = \frac{1}{4} \left( \text{render}(\text{getUV}(0.125, 0.375)) + \text{render}(\text{getUV}(-0.125, -0.375)) + \text{render}(\text{getUV}(-0.375, 0.125)) + \text{render}(\text{getUV}(0.375, -0.125)) \right)$ [S2, unofficial].

**Pseudocode:**
```python
class vec3:
    def __init__(self, r, g, b):
        self.r, self.g, self.b = r, g, b
    def __add__(self, other):
        return vec3(self.r + other.r, self.g + other.g, self.b + other.b)
    def __truediv__(self, scalar):
        return vec3(self.r / scalar, self.g / scalar, self.b / scalar)

def render_aa(AA_mode, pixel_x, pixel_y, get_uv, render):
    """
    Renders a pixel using Multi-Sample Anti-Aliasing via Ray Distribution.
    
    Args:
        AA_mode (int): 1, 2, 3, or 4.
        pixel_x (int): X coordinate of the fragment/pixel.
        pixel_y (int): Y coordinate of the fragment/pixel.
        get_uv (function): Returns the base UV coordinate for the pixel center.
        render (function): Takes a UV offset (tuple) and returns a color (vec3).
        
    Returns:
        vec3: The averaged color for the pixel.
    """
    if AA_mode == 1:
        return render(get_uv((0.0, 0.0)))
    elif AA_mode == 2:
        bxy = (pixel_x + pixel_y) & 1
        nbxy = 1.0 - bxy
        uv1 = get_uv((0.33 * nbxy, 0.0))
        uv2 = get_uv((0.33 * bxy, 0.66))
        return (render(uv1) + render(uv2)) / 2.0
    elif AA_mode == 3:
        bxy = (pixel_x + pixel_y) & 1
        nbxy = 1.0 - bxy
        uv1 = get_uv((0.66 * nbxy, 0.0))
        uv2 = get_uv((0.66 * bxy, 0.66))
        uv3 = get_uv((0.33, 0.33))
        return (render(uv1) + render(uv2) + render(uv3)) / 3.0
    elif AA_mode == 4:
        e_x, e_y, e_z, e_w = 0.125, -0.125, 0.375, -0.375
        uv1 = get_uv((e_x, e_z))
        uv2 = get_uv((e_y, e_w))
        uv3 = get_uv((e_w, e_x))
        uv4 = get_uv((e_z, e_y))
        return (render(uv1) + render(uv2) + render(uv3) + render(uv4)) / 4.0
    else:
        return render_aa(4, pixel_x, pixel_y, get_uv, render)
```

**Edge Cases and Pitfalls:**
*   **Performance:** This technique significantly reduces framerate due to the increased ray count [S1, unofficial].
*   **Optimization:** An optimization is to only perform AA if the iteration count is above average, as this likely indicates an object edge where aliasing is most visible [S1, unofficial].
*   **Coordinate System:** The offsets provided in the sources are additive to a base UV coordinate [S2, unofficial]. If `getUV` expects normalized coordinates in $[0,1]$ relative to the pixel, the offsets must be interpreted accordingly [G].

## Subtopics

### Supersampling
The general concept of sampling at a higher resolution than the displayed resolution to combat artifacts [S3, unofficial]. MSAA via Ray Distribution implements this concept using fixed, deterministic offset patterns [S2, unofficial]. [Link](3493-supersampling.md)

### Sampling and Jittering
MSAA uses deterministic offsets based on pixel coordinates, whereas jittering uses random offsets to break up regular aliasing patterns [G]. [Link](2516-sampling-and-jittering.md)

### Epipolar Sampling
Epipolar sampling exploits geometric constraints along epipolar lines to reduce sampling, whereas MSAA uses fixed pixel-local offsets independent of scene geometry [G]. [Link](3899-epipolar-sampling.md)

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of samples (1, 2, 3, or 4) [S1, S2, unofficial].
*   **Memory Complexity:** $O(1)$ additional memory per pixel, as only the accumulated color sum is needed [G].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Effectively removes jagged edges and aliasing artifacts, particularly along silhouette edges where intensity changes abruptly [S1, S3, unofficial].
*   **Limitations:** High computational cost proportional to the sample count [S1, unofficial]. Fixed patterns do not adapt to scene complexity, potentially wasting samples in empty space or under-sampling complex regions [G].
*   **When to Use:** When visual quality is prioritized over performance and aliasing is a noticeable issue [G].
*   **When Not to Use:** When performance is critical or the scene is simple enough that single-ray casting is sufficient [G].

## Background
The technique is described in the context of raymarching distance fields and volume rendering as a straightforward method to improve image quality by distributing rays within a pixel [S1, unofficial]. The specific offset patterns for AAx2, AAx3, and AAx4 are derived from GLSL shader code examples in a GitHub repository [S2, unofficial]. The theoretical basis for supersampling to combat aliasing artifacts caused by coarse sampling granularity is discussed in academic literature on volume ray casting [S3, unofficial].
