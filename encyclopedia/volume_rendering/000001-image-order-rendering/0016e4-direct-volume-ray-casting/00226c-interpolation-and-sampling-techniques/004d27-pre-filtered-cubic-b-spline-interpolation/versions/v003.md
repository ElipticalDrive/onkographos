# Pre-filtered Cubic B-spline Interpolation
Also called: Pre-filtered B-spline Interpolation
## Overview
Pre-filtered Cubic B-spline Interpolation is an on-the-fly interpolation technique that improves sampling accuracy in direct volume ray casting by applying a pre-processing step to the voxel data [S1, unofficial]. It addresses the artifacts associated with standard tri-linear interpolation, such as jerky edges and aliasing, without increasing the memory footprint of the volume dataset [S1, unofficial]. Unlike methods that store larger intermediate data structures, this approach modifies the existing voxel values in-place or via a lightweight pre-filter, relying on local lookups during ray evaluation to achieve higher-order continuity [S1, unofficial].

## How it works
**Inputs and Outputs**
- Input: A 3D volume dataset $V$ of size $N_x \times N_y \times N_z$ containing scalar voxel values.
- Output: A modified volume dataset $V'$ where each voxel value has been convolved with the inverse of the cubic B-spline kernel, or an on-the-fly computation that applies this pre-filtering effect during the ray casting loop.

**Data Structures**
- The volume data is stored as a 3D array of floating-point values. No additional auxiliary structures (like octrees or sparse grids) are required for the interpolation itself, preserving the original memory layout [S1, unofficial].

**Steps**
1. **Pre-filtering (Offline/Pre-processing)**:
   The source voxel values are processed to compensate for the smoothing effect of the cubic B-spline kernel. Let $K(u)$ be the cubic B-spline basis function. The pre-filtering step computes a modified value $V'_{ijk}$ for each voxel $(i,j,k)$ such that when the standard cubic B-spline interpolation is applied to $V'$, the result approximates the original signal more accurately.
   
   The cubic B-spline kernel $B_3(x)$ is defined as:
   $$
   B_3(x) = \frac{1}{6} \begin{cases} 
   (2 - |x|)^3 - 4(1 - |x|)^3 & \text{if } 1 \le |x| < 2 \\
   2 - 6|x|^2 + 3|x|^3 & \text{if } |x| < 1 \\
   0 & \text{otherwise}
   \end{cases}
   $$
   
   The pre-filtering operation is effectively a deconvolution. In practice, this is often implemented as a separable 1D filter applied along each axis. For a 1D signal $v$, the pre-filtered value $v'$ at index $i$ is computed using a weighted sum of neighbors. A common approximation for the inverse cubic B-spline filter coefficients $c_k$ involves solving the system defined by the kernel's frequency response. The coefficients for the 1D pre-filter are typically:
   $$
   c = [\dots, -0.055, 0.416, 1.278, 0.416, -0.055, \dots]
   $$
   (Note: Exact coefficients may vary based on the specific implementation of the inverse filter [G].)
   
   The 3D pre-filtered value $V'_{ijk}$ is computed by applying this 1D filter separably along x, y, and z axes.

2. **Ray Casting and Interpolation**:
   During ray casting, for a ray $r(t) = \mathbf{o} + t\mathbf{d}$, sample points $\mathbf{p}$ are determined.
   - Map $\mathbf{p}$ to grid coordinates $(u, v, w)$.
   - Identify the 8 neighboring voxels in the pre-filtered volume $V'$.
   - Compute the cubic B-spline weights $w_{lmn}$ based on the fractional parts of $(u, v, w)$.
   - The interpolated value $V(\mathbf{p})$ is:
     $$
     V(\mathbf{p}) = \sum_{l=-1}^{0} \sum_{m=-1}^{0} \sum_{n=-1}^{0} w_{lmn} V'_{i+l, j+m, k+n}
     $$
     where $i, j, k$ are the integer grid indices.

**Parameters**
- Kernel order: Cubic (3rd degree).
- Pre-filter coefficients: As derived from the inverse of the B-spline kernel [G].

**Edge Cases and Pitfalls**
- **Boundary Conditions**: The pre-filtering step requires handling boundaries carefully. Standard approaches include clamping, mirroring, or assuming zero values outside the volume. Incorrect boundary handling can introduce artifacts at the edges of the volume [G].
- **Precision**: The pre-filtering coefficients can be negative, which may lead to values outside the original range of the data. This requires sufficient bit-depth (e.g., 32-bit float) to prevent clipping or precision loss [G].
- **Performance**: The pre-filtering step adds an offline cost, and the interpolation itself is more computationally expensive than tri-linear interpolation due to the 27-tap (8 neighbors $\times$ 3D kernel) nature of cubic B-splines [S1, unofficial].

    Interpolates value at continuous position p using pre-filtered volume.
    p is a 3D vector (x, y, z).
    """

        ax = abs(x)
        if ax < 1.0:
            return (2.0 - 6.0 * ax * ax + 3.0 * ax * ax * ax) / 6.0
        elif ax < 2.0:
            return (2.0 - ax) ** 3 / 6.0
        else:
            return 0.0
            
    weights = []
    for l in [-1, 0]:
        for m in [-1, 0]:
            for n in [-1, 0]:
                w = b3(du - l) * b3(dv - m) * b3(dw - n)
                weights.append((l, m, n, w))
                
    value = 0.0
    for l, m, n, w in weights:
        # Handle boundary checks
        if 0 <= i+l < Nx and 0 <= j+m < Ny and 0 <= k+n < Nz:
            value += w * V_prefiltered[i+l, j+m, k+n]

## Subtopics

### [Isogeometric Volume Rendering](14205-isogeometric-volume-rendering.md)
Isogeometric Volume Rendering is a method for the interactive visualization of isogeometric analysis (IGA) results, ensuring correct, pixel-accurate geometry of the volume including its bounding surfaces. It extends classic volume rendering to isogeometric volumes where both geometry and scalar field are given in terms of splines (NURBS, B-splines). Unlike voxelized methods which suffer from block-like structures and high memory demands, this method provides pixel-accurate outer surfaces and avoids the loss of geometrically exact representation.

## Operating characteristics
- **Time Complexity**: The pre-filtering step is $O(N)$ where $N$ is the number of voxels, performed once. During rendering, the interpolation is more expensive than tri-linear interpolation due to the larger kernel support (27 taps vs 8). The ray casting loop must compute 27 weighted lookups per sample point.
- **Memory Complexity**: $O(N)$, same as the original volume data. No additional storage is required for the interpolation structure [S1, unofficial].
- **Performance**: Offers higher visual quality with reduced aliasing and smoother gradients compared to tri-linear interpolation. However, it incurs a performance penalty due to the increased computational cost of the cubic B-spline evaluation and the pre-filtering step [S1, unofficial].
- **Strengths**: No increased memory footprint; improved accuracy and smoothness; reduces artifacts like jerky edges.
- **Limitations**: Higher computational cost; potential for ringing artifacts if the pre-filter is not well-conditioned; boundary effects.

## Background
Pre-filtered Cubic B-spline Interpolation is an advancement in volume rendering sampling techniques, aiming to bridge the gap between the speed of linear interpolation and the accuracy of higher-order methods. It is discussed in the context of common artifacts in volume rendering, such as jerky edges and aliasing, which are prevalent when using simple interpolation schemes like tri-linear interpolation [S1, unofficial]. The method leverages the properties of B-splines to provide a smooth, continuous approximation of the volume data while maintaining a manageable memory footprint.
