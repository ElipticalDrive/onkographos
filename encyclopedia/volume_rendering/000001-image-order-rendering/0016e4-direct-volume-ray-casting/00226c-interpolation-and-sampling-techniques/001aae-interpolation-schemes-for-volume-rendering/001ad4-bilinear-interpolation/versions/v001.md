# Bilinear Interpolation

Also called: 2D Bilinear Sampling, Bilinear Image Sampling, Bilinear Image Sampling at XY Grid, F.grid_sample with bilinear mode, Grid Sample Bilinear, Grid with Bilinear Interpolation, Tri-linear Interpolation on GPU

## Overview
Bilinear interpolation is a reconstruction scheme that estimates values at arbitrary 2D coordinates by performing linear interpolation first in one direction and then in the other, using the four nearest grid points. In volume rendering, it is primarily used to sample 2D image data (such as color or opacity textures) associated with volume slices or to approximate 3D trilinear sampling by treating the third dimension as a sequence of 2D planes. It sets itself apart from nearest neighbor interpolation by providing continuous, artifact-free gradients, though it introduces low-pass filtering effects compared to higher-order schemes like [Tri-cubic interpolation](848-fast-tri-cubic-interpolation.md) or [Sinc Resampling](826-frequency-domain-volume-rendering-with-sinc-resampling.md).

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D grid of values (e.g., an image or texture) with dimensions $H \times W$ and $C$ channels, and a set of query coordinates $(x, y)$ in the continuous domain.
*   **Output:** The interpolated value $V(x,y)$ at the query coordinates, preserving the channel count $C$.

**Data Structures:**
The source data is typically stored in a 1D contiguous array or a 2D tensor.
*   **Layout:** For a grid of size $resX \times resY$, the element at integer coordinates $(x, y)$ is stored at index $x \cdot resY + y$ in a 1D array [S3, unofficial].
*   **Tensor Format:** In deep learning frameworks, inputs are often shaped as $[batch\_size, H, W, C]$ [S2, unofficial].

**Formulas:**
Let the query coordinate be $(x, y)$.
1.  Compute integer bounds:
    $$x_1 = \lfloor x \rfloor, \quad y_1 = \lfloor y \rfloor$$
    *Note: For negative coordinates, special handling is required to ensure $x_1$ is the floor (e.g., if $x = -0.5$, $x_1 = -1$) [S3, unofficial].*
2.  Compute fractional offsets:
    $$d_x = x - x_1, \quad d_y = y - y_1$$
    where $d_x, d_y \in [0, 1)$.
3.  Identify the four surrounding grid points:
    *   $V_{00} = Grid(x_1, y_1)$
    *   $V_{10} = Grid(x_1 + 1, y_1)$
    *   $V_{01} = Grid(x_1, y_1 + 1)$
    *   $V_{11} = Grid(x_1 + 1, y_1 + 1)$
4.  Calculate the interpolated value:
    $$V(x,y) = V_{00}(1-d_x)(1-d_y) + V_{10}d_x(1-d_y) + V_{01}(1-d_x)d_y + V_{11}d_x d_y$$
    [S3, unofficial]

**Parameters:**
*   **Alignment:** When using hardware or library implementations (e.g., `align_corners=True`), the coordinate system maps the pixel centers to the boundaries of the grid, affecting the scaling of coordinates [S2, unofficial].
*   **Buffer Size:** In out-of-core implementations, a `BufferSize` parameter controls memory paging (default 64 elements), trading I/O frequency for memory usage [S3, unofficial].

**Steps:**
1.  **Coordinate Normalization:** Convert pixel coordinates to the expected range of the interpolation function (e.g., $[-1, 1]$ or $[0, 1]$). In PyTorch's `grid_sample`, coordinates are often negated and reshaped to $[N, H_{out}, W_{out}, 2]$ [S2, unofficial].
2.  **Boundary Handling:** Determine if the query coordinates fall within the valid grid range. If using wrapping (toroidal boundary conditions), apply modulo arithmetic:
    $$x_{wrapped} = x \pmod{resX}$$
    $$y_{wrapped} = y \pmod{resY}$$
    *Pitfall:* Incorrect modulo operations on negative numbers can cause artifacts. Specifically, using `resY` instead of `resX` for x-axis wrapping is a known bug in some implementations [S3, unofficial].
3.  **Nearest Neighbor Fetch:** Retrieve the four values $V_{00}, V_{10}, V_{01}, V_{11}$ from the grid.
4.  **Interpolation:** Apply the bilinear formula to compute the final value.
5.  **Output Formatting:** Reshape and flatten the output tensor to match the expected batch and channel layout [S2, unofficial].

**Pseudocode:**
```python
def bilinear_interpolate(grid, x, y, resX, resY, wrap=False):
    """
    Performs bilinear interpolation on a 2D grid.
    grid: 1D array of size resX * resY, row-major (x * resY + y)
    x, y: float coordinates
    resX, resY: integer dimensions
    wrap: boolean, if True, wrap coordinates around boundaries
    """
    # 1. Handle negative coordinates for floor
    if x < 0:
        x1 = -int(-x) - 1
    else:
        x1 = int(x)
        
    if y < 0:
        y1 = -int(-y) - 1
    else:
        y1 = int(y)

    # 2. Boundary wrapping
    if wrap:
        # Correct wrapping: use respective dimension for each axis
        if x1 < 0 or x1 >= resX:
            x1 = x1 % resX
            if x1 < 0: x1 += resX
        if y1 < 0 or y1 >= resY:
            y1 = y1 % resY
            if y1 < 0: y1 += resY
            
    # 3. Compute fractional parts
    dx = x - x1
    dy = y - y1

    # 4. Fetch neighbors (handle edge cases where x1+1 or y1+1 exceed bounds if not wrapped)
    # Assuming valid input or wrapping ensures indices are within [0, resX-1] and [0, resY-1]
    
    # Helper to get value from 1D grid
    def get_val(ix, iy):
        idx = ix * resY + iy
        return grid[idx]

    v00 = get_val(x1, y1)
    v10 = get_val(x1 + 1, y1)
    v01 = get_val(x1, y1 + 1)
    v11 = get_val(x1 + 1, y1 + 1)

    # 5. Bilinear formula
    # V = V00 * (1-dx)*(1-dy) + V10 * dx*(1-dy) + V01 * (1-dx)*dy + V11 * dx*dy
    res = v00 * (1 - dx) * (1 - dy) + \
          v10 * dx * (1 - dy) + \
          v01 * (1 - dx) * dy + \
          v11 * dx * dy
          
    return res

def torch_style_grid_sample(images, xy_grid):
    """
    Simulates PyTorch's grid_sample with bilinear mode and align_corners=True.
    images: tensor [batch_size, H, W, C]
    xy_grid: tensor [batch_size, H_out, W_out, 2] with coordinates in [-1, 1]
    """
    batch_size, H, W, C = images.shape
    _, H_out, W_out, _ = xy_grid.shape
    
    # Reshape xy_grid to [batch_size, -1, 1, 2]
    xy_grid_flat = xy_grid.view(batch_size, -1, 1, 2)
    
    # Negate coordinates as per specific implementation note [S2, unofficial]
    xy_grid_neg = -xy_grid_flat
    
    # Permute images to [batch_size, C, H, W] for NCHW format
    images_nchw = images.permute(0, 3, 1, 2)
    
    # Apply interpolation (conceptual, as actual grid_sample is hardware/library dependent)
    # In a real implementation, this calls the underlying bilinear sampler
    sampled_nchw = apply_bilinear_sampler(images_nchw, xy_grid_neg, align_corners=True)
    
    # Permute back to [batch_size, H_out, W_out, C] and flatten spatial dims
    sampled_hwc = sampled_nchw.permute(0, 2, 3, 1)
    result = sampled_hwc.view(batch_size, -1, C)
    
    return result
```

## Subtopics

### Optimized Trilinear Reconstruction
Trilinear interpolation is the 3D extension of bilinear interpolation. Optimized variants use SIMD extensions (MMX, SSE, 3DNow!) to accelerate memory copying and interpolation speed, often operating on 16-bit unsigned integers for color and opacity [S5]. On MMX-only processors, certain line equation tests cannot be performed, leading to minor visual artifacts [S5].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample, as it involves a fixed number of arithmetic operations and memory accesses (4 reads).
*   **Memory Complexity:** $O(1)$ auxiliary memory per sample.
*   **Performance:** Extremely fast and widely supported by hardware texture units. It is the standard for real-time rendering where performance is critical.
*   **Strengths:** Smooth gradients, low computational cost, hardware acceleration.
*   **Limitations:** Introduces blurring (low-pass filtering) due to its triangular frequency response. Not suitable for high-fidelity scientific visualization where sharp features or high-frequency details must be preserved.
*   **When to use:** Real-time volume rendering, texture sampling, and when computational resources are limited.
*   **When not to use:** When high-frequency detail preservation is required (use [Sinc Resampling](826-frequency-domain-volume-rendering-with-sinc-resampling.md)) or when higher-order continuity is needed (use [Tri-cubic](848-fast-tri-cubic-interpolation.md)).

## Background
Bilinear interpolation is a fundamental technique in computer graphics and image processing. In the context of volume rendering, it is often used as a building block for trilinear interpolation in 3D grids. The method is implemented in various graphics APIs and deep learning frameworks (e.g., PyTorch's `grid_sample`) [S2, unofficial]. It is also utilized in frequency domain volume rendering, where blending factors are derived from texture coordinates to approximate interpolation in the frequency domain [S4, unofficial].
