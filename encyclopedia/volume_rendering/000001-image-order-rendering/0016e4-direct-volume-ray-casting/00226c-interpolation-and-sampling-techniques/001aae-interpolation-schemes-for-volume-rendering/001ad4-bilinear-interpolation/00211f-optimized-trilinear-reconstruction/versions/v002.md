# Optimized Trilinear Reconstruction

Also called: Trilinear interpolation optimized using SIMD

## Overview
Optimized Trilinear Reconstruction accelerates the trilinear interpolation of color and opacity values during direct volume ray casting by utilizing SIMD processor extensions such as MMX, SSE, or 3DNow! [S1]. It improves memory copying and interpolation speed compared to scalar implementations [S1].

## How it works
**Inputs and Outputs:**
*   Input: A 3D volume dataset, camera rays, and rendering parameters.
*   Output: Rendered image with color and opacity values.

**Data Structures:**
*   Color and opacity values are stored and processed as 16-bit unsigned integers [S1].
*   To reduce cache misses, the volume is decomposed into small blocks containing $32^3$ samples [S1].
*   Memory addresses for these blocks are generated using bit-interleaved coordinates. For coordinates $(X, Y, Z)$, the bits are interleaved as follows:
    $$ (X_{n \dots 0}, Y_{n \dots 0}, Z_{n \dots 0}) \implies Z_{n \dots 5} Y_{n \dots 5} X_{n \dots 5} Z_4 Y_4 X_4 \dots Z_0 Y_0 X_0 $$
    A 32-entry table and binary operators are used to interleave the five lower bits to generate the new memory address [S1].

**Steps:**
1.  Decompose the volume into $32^3$ blocks and compute bit-interleaved memory addresses for each block [S1].
2.  For each pixel, cast a ray through the volume and determine the current sample position [S1].
3.  Retrieve the 8 neighboring voxels surrounding the sample position using the bit-interleaved addressing scheme [S1].
4.  Perform trilinear interpolation on the 8 voxels using SIMD instructions (MMX, SSE, or 3DNow!) to compute color and opacity values in 16-bit unsigned integer arithmetic [S1].
5.  Composite the interpolated color and opacity along the ray using standard volume rendering integration [S1].
6.  Write the final pixel color to the frame buffer [S1].

**Pseudocode:**
```python
def optimized_trilinear_reconstruction(volume_data, rays, options):
    # Precompute bit-interleave table for the five lower bits (32 entries)
    interleave_table = [0] * 32
    for i in range(32):
        # Interleave bits: Z4 Y4 X4 Z3 Y3 X3 Z2 Y2 X2 Z1 Y1 X1 Z0 Y0 X0
        interleave_table[i] = ((i & 16) << 10) | ((i & 8) << 8) | ((i & 4) << 6) | \
                              ((i & 2) << 4) | ((i & 1) << 2) | \
                              ((i & 16) << 4) | ((i & 8) << 2) | ((i & 4) << 0) | \
                              ((i & 2) << 1) | ((i & 1) << 0)

    for ray in rays:
        color_acc = 0
        opacity_acc = 0.0
        t = ray.origin

        while t < ray.end:
            x, y, z = t
            ix, iy, iz = int(x), int(y), int(z)
            dx, dy, dz = x - ix, y - iy, z - iz

            # Generate memory address using bit-interleaved coordinates
            block_addr = compute_block_address(ix, iy, iz, interleave_table)

            # Load 8 neighboring voxels
            v000 = volume_data[block_addr, 0, 0, 0]
            v100 = volume_data[block_addr, 1, 0, 0]
            v010 = volume_data[block_addr, 0, 1, 0]
            v110 = volume_data[block_addr, 1, 1, 0]
            v001 = volume_data[block_addr, 0, 0, 1]
            v101 = volume_data[block_addr, 1, 0, 1]
            v011 = volume_data[block_addr, 0, 1, 1]
            v111 = volume_data[block_addr, 1, 1, 1]

            # Trilinear interpolation using 16-bit unsigned integer arithmetic
            c00 = v000 + dx * (v100 - v000)
            c01 = v001 + dx * (v101 - v001)
            c10 = v010 + dx * (v110 - v010)
            c11 = v011 + dx * (v111 - v011)
            c0 = c00 + dy * (c10 - c00)
            c1 = c01 + dy * (c11 - c01)
            color_sample = c0 + dz * (c1 - c0)

            o00 = v000 + dx * (v100 - v000)
            o01 = v001 + dx * (v101 - v001)
            o10 = v010 + dx * (v110 - v010)
            o11 = v011 + dx * (v111 - v011)
            o0 = o00 + dy * (o10 - o00)
            o1 = o01 + dy * (o11 - o01)
            opacity_sample = o0 + dz * (o1 - o0)

            # Standard volume rendering compositing
            alpha = opacity_sample / 65535.0
            color_acc = color_acc + color_sample * alpha * (1.0 - opacity_acc)
            opacity_acc += alpha * (1.0 - opacity_acc)

            t += ray.step_size

        write_pixel(ray.pixel_id, color_acc, opacity_acc)

def compute_block_address(ix, iy, iz, table):
    # Interleave lower 5 bits of coordinates
    x_bits = ix & 31
    y_bits = iy & 31
    z_bits = iz & 31
    lower = table[x_bits] | table[y_bits] | table[z_bits]
    # Upper bits (n..5) remain in original axis order: Z, then Y, then X
    upper = ((iz & ~31) << 10) | ((iy & ~31) << 5) | (ix & ~31)
    return upper | lower
```

**Parameters:**
*   Data type: 16-bit unsigned integers for color and opacity values [S1].

**Edge Cases and Pitfalls:**
*   On MMX-only processors, line equation tests cannot be performed, leading to minor artifacts in the image [S1].

## Subtopics

### NV Rendering Formula (Trilerp)
Implements an 'NV' rendering formula using trilinear interpolation (trilerp) [S2, unofficial]. Includes forward, backward, and fused variants [S2, unofficial]. The forward variant computes the output tensor directly. The backward variant computes gradients for the grid output. The fused variant combines the forward pass with additional parameters and computes gradients [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Improved over standard trilinear interpolation due to SIMD parallelism [S1].
*   **Memory Complexity:** Reduced cache misses due to bit-interleaved block decomposition ($32^3$ samples) [S1].
*   **Strengths:** Faster interpolation and memory copying on supported hardware [S1].
*   **Limitations:** Artifacts on MMX-only processors [S1].
*   **When to use:** When rendering performance is critical and the target hardware supports MMX, SSE, or 3DNow! [S1].
*   **When not to use:** On MMX-only processors if artifacts are unacceptable [S1].

## Background
The method was introduced in "A new object-order ray-casting algorithm" [S1]. It leverages existing SIMD processor extensions to optimize volume rendering performance. The bit-interleaved addressing scheme is also described in this work [S1].
