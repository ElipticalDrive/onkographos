# NDC Points to Distance

Also called: NDC to Distance, ndc2dist, ndc_pts to dists

## Overview
Computes the Euclidean segment distances between consecutive points sampled in Normalized Device Coordinates (NDC) space along a ray. It solves the problem of converting discrete NDC depth samples into physical distances required for volume rendering integration, specifically handling the perspective projection geometry where uniform NDC steps do not correspond to uniform physical distances. It differs from linear depth-to-distance conversion by accounting for the non-linear nature of NDC space, which is compressed near the near plane and expanded near the far plane.

## How it works
**Inputs and Outputs:**
- Input: `ndc_pts`, a tensor of shape $(N, 3)$ containing $N$ 3D points in NDC space, ordered along the ray from near to far.
- Input: `cos_angle`, a scalar or tensor representing the cosine of the angle between the ray direction and the view direction (used for perspective correction).
- Output: `dists`, a tensor of shape $(N)$ containing the Euclidean distances between consecutive points, with the last element being a large placeholder value.

**Data Structures:**
- `ndc_pts`: Float tensor. Coordinates are in $[-1, 1]$ range for NDC space.
- `dists`: Float tensor.

**Steps:**
1. Compute the difference vector between consecutive points: $\Delta \mathbf{p}_i = \mathbf{p}_{i+1} - \mathbf{p}_i$ for $i = 0 \dots N-2$.
2. Compute the Euclidean norm of these difference vectors to get the segment lengths: $d_i = \|\Delta \mathbf{p}_i\|_2$.
3. Append a large value to the end of the distance array to serve as a sentinel for the final segment or to handle boundary conditions in integration. This value is scaled by the cosine of the viewing angle.

**Formulas:**
Let $\mathbf{p}_i$ be the $i$-th point in `ndc_pts`.
$$ d_i = \sqrt{(x_{i+1}-x_i)^2 + (y_{i+1}-y_i)^2 + (z_{i+1}-z_i)^2} \quad \text{for } i = 0, \dots, N-2 $$
The final distance $d_{N-1}$ is set to:
$$ d_{N-1} = 10^{10} \cdot \cos(\theta) $$
where $\theta$ is the angle between the ray and the view direction.

**Pseudocode:**
```python
import torch
import math

def ndc_pts_to_dists(ndc_pts, cos_angle):
    """
    Compute distances between NDC points along the ray.
    
    Args:
        ndc_pts: Tensor of shape (N, 3) containing NDC coordinates of points along the ray.
        cos_angle: Scalar or tensor representing cos(angle) between ray and view direction.
        
    Returns:
        dists: Tensor of shape (N) containing segment distances.
    """
    # Step 1 & 2: Compute Euclidean distance between consecutive points
    # ndc_pts[:, 1:] are points 1 to N-1
    # ndc_pts[:, :-1] are points 0 to N-2
    diffs = ndc_pts[:, 1:] - ndc_pts[:, :-1]
    dists = torch.norm(diffs, dim=-1)
    
    # Step 3: Append a large value scaled by cos_angle
    # The large value acts as a sentinel for the last segment
    large_value = 1e10 * cos_angle.unsqueeze(-1) if cos_angle.dim() > 0 else 1e10 * cos_angle
    
    # Concatenate the computed distances with the sentinel value
    dists = torch.cat([dists, large_value], dim=-1)
    
    return dists
```

**Parameters:**
- `1e10`: A sufficiently large constant to ensure the last segment does not contribute significantly to the volume rendering integral if the ray extends beyond the defined NDC bounds. [S1, S2, unofficial]

**Edge Cases and Pitfalls:**
- **Precision:** NDC space compression near the near plane can lead to small differences. Standard float32 precision is generally sufficient, but float64 may be needed for extreme aspect ratios or very large scenes.
- **Boundary Conditions:** The last distance is a sentinel. In volume rendering, this large value ensures that the alpha accumulation saturates or that the ray is considered "closed" at the far plane.
- **Cosine Angle:** If `cos_angle` is zero (ray perpendicular to view direction, rare in standard camera setups), the sentinel becomes zero. This might cause issues if the integration logic expects a non-zero sentinel. [G] Ensure `cos_angle` is clamped to a small positive value if necessary, though standard forward-facing cameras have `cos_angle > 0`.

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of sampled points per ray. The operation involves a single pass over the points to compute differences and norms.
- **Memory Complexity:** $O(N)$ for storing the output distance tensor.
- **Performance:** Very fast, dominated by vectorized tensor operations. On a single 2080 Ti, training with this method takes ~4-8 hours for standard NeRF scenes, indicating the sampling and distance computation are not the bottleneck. [S1, S2, unofficial]
- **Strengths:** Accurately models the non-linear spacing of points in NDC space, which is crucial for forward-facing scenes where NDC sampling is common.
- **Limitations:** Requires points to be in NDC space. Not applicable to linear depth or world-space sampling without conversion.
- **When to use:** When using NDC space for ray sampling, particularly in forward-facing scene reconstruction (e.g., NeRF, TensoRF).
- **When not to use:** When using linear depth sampling or world-space sampling.

## Background
Originated in the context of Neural Radiance Fields (NeRF) and its tensor-based variants like TensoRF. The use of NDC space for forward-facing scenes was introduced to handle the infinite depth range more effectively by compressing the scene into a unit cube. The conversion from NDC points to distances is a necessary step in the volume rendering pipeline to compute the correct weights for alpha compositing. [S1, S2, unofficial]
