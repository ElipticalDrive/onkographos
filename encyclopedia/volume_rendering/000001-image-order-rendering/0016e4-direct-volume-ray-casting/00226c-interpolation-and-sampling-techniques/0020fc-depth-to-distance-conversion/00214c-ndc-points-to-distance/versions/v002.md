# NDC Points to Distance

Also called: NDC to Distance, NDC to Distance Conversion, ndc2dist, ndc_pts to dists

## Overview
Converts sampled Normalized Device Coordinates (NDC) points to segment distances between consecutive samples along a ray, accounting for the cosine of the viewing angle [S1, S2, S3, unofficial]. It operates directly in NDC space, where uniform sampling steps do not correspond to uniform physical distances, unlike linear depth-to-distance methods [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
- Input: `ndc_pts`, a tensor of shape `[N_ray, N_sample, 3]` containing 3D points in NDC space, ordered along the ray [S1, unofficial].
- Input: `cos_angle`, a tensor of shape `[N_ray]` representing the cosine of the angle between the ray direction and the view direction [S1, S2, unofficial].
- Output: `dists`, a tensor of shape `[N_rays, N_samples]` containing the segment distances [S1, unofficial].

**Data Structures:**
- `ndc_pts`: Float tensor. Coordinates are in NDC space [S1, unofficial].
- `dists`: Float tensor.

**Steps:**
1. Compute the Euclidean distance between consecutive NDC points along the ray: `dists = torch.norm(ndc_pts[:, 1:] - ndc_pts[:, :-1], dim=-1)` [S1, S2, S3, unofficial].
2. Append a large value scaled by `cos_angle` to the end of the distance array: `dists = torch.cat([dists, 1e10 * cos_angle.unsqueeze(-1)], -1)` [S1, S2, S3, unofficial].

**Formulas:**
Let $\mathbf{p}_i$ be the $i$-th point in `ndc_pts` for a given ray. The segment distance for $i = 0, \dots, N-2$ is:
$$ d_i = \|\mathbf{p}_{i+1} - \mathbf{p}_i\|_2 $$
The final distance is:
$$ d_{N-1} = 10^{10} \cdot \cos(\theta) $$
where $\theta$ is the angle between the ray and the view direction [S1, S2, unofficial].

**Pseudocode:**
```python
import torch

def ndc_pts_to_dists(ndc_pts, cos_angle):
    # ndc_pts: [N_ray, N_sample, 3]
    # cos_angle: [N_ray]
    # Step 1: Compute Euclidean distances between consecutive points
    diffs = ndc_pts[:, 1:] - ndc_pts[:, :-1]
    dists = torch.norm(diffs, dim=-1)  # Shape: [N_ray, N_sample - 1]
    
    # Step 2: Append large value scaled by cos_angle
    # cos_angle.unsqueeze(-1) makes it [N_ray, 1] for broadcasting
    sentinel = 1e10 * cos_angle.unsqueeze(-1)
    dists = torch.cat([dists, sentinel], dim=-1)  # Shape: [N_ray, N_sample]
    
    return dists
```

**Parameters:**
- `1e10`: A large constant appended to the distance array [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
- **Cosine Angle:** If `cos_angle` is zero, the sentinel becomes zero, which may affect integration logic [G]. Standard forward-facing camera setups typically yield `cos_angle > 0` [G].
- **Batch Dimensions:** The pseudocode assumes batched inputs `[N_ray, ...]`. For a single ray, unsqueeze dimensions appropriately before calling, or adjust slicing [G].

## Operating characteristics
- **Time and Memory Complexity:** $O(N)$ time and memory per ray, where $N$ is the number of samples, dominated by vectorized tensor operations [G].
- **Strengths and Limitations:** Accurately computes physical distances from NDC samples for forward-facing scenes [S1, S3, unofficial]. Requires points to be in NDC space and does not apply to linear depth or world-space sampling without prior conversion [G].

## Background
Originated in Neural Radiance Fields (NeRF) and tensor-based variants for forward-facing scene reconstruction, where NDC space compresses the infinite depth range into a unit cube [S1, S2, S3, unofficial]. The conversion is a standard step in the volume rendering pipeline to compute correct weights for alpha compositing [S1, S2, S3, unofficial].
