# Trilinear Interpolation

Also called: 3D Linear Interpolation, Interpolação trilinear, Linear Interpolation (Trilinear), Trilinear Interpolant, Trilinear Sampling, Voxel Trilinear Interpolation

## Overview
Trilinear interpolation estimates the scalar value at an arbitrary point within a voxel grid by computing a weighted average of the values of the 8 surrounding voxels, based on their distances to the sample point [S1, S8, S11, unofficial]. It solves the problem of discretization artifacts (blockiness) inherent in nearest-neighbor sampling by providing a continuous, first-order approximation of the underlying scalar field [S1, S17, unofficial]. It produces softer, higher-quality images than nearest-neighbor interpolation but requires approximately 5 times more computation time [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field defined on a regular grid with dimensions $D_x \times D_y \times D_z$, and a query position $\mathbf{p} = (x, y, z)$ in voxel space [S11, S14, unofficial].
*   **Output:** A single scalar value $V(\mathbf{p})$.

**Data Structures:**
The volume data is stored in a 3D array (or flattened 1D array with row-major indexing) [S12, S19, unofficial]. For a query point, the algorithm accesses the 8 corner values of the containing voxel:
$$
\begin{aligned}
v_{000} &= \text{Grid}(i_0, j_0, k_0) \\
v_{100} &= \text{Grid}(i_1, j_0, k_0) \\
v_{010} &= \text{Grid}(i_0, j_1, k_0) \\
v_{110} &= \text{Grid}(i_1, j_1, k_0) \\
v_{001} &= \text{Grid}(i_0, j_0, k_1) \\
v_{101} &= \text{Grid}(i_1, j_0, k_1) \\
v_{011} &= \text{Grid}(i_0, j_1, k_1) \\
v_{111} &= \text{Grid}(i_1, j_1, k_1)
\end{aligned}
$$
where $i_1 = i_0 + 1$, $j_1 = j_0 + 1$, $k_1 = k_0 + 1$ [S14, unofficial].

**Algorithm Steps:**

1.  **Coordinate System Alignment:** Depending on the grid's coordinate convention, an offset (e.g., $-0.5$) may be applied to align voxel centers with integer coordinates [S1, unofficial]. Standard implementations assume voxel corners at integer indices and skip this step [S12, S14, unofficial].
    $$ \mathbf{p}_{\text{aligned}} = \mathbf{p} - \mathbf{c} \quad (\text{where } \mathbf{c} \text{ is typically } (0,0,0) \text{ or } (0.5,0.5,0.5)) $$

2.  **Index Calculation:** Compute the integer indices of the lower-left corner of the containing voxel using the floor function [S1, S14, unofficial].
    $$ i_0 = \lfloor p_{\text{aligned}, x} \rfloor, \quad j_0 = \lfloor p_{\text{aligned}, y} \rfloor, \quad k_0 = \lfloor p_{\text{aligned}, z} \rfloor $$

3.  **Boundary Clamping:** Clamp the lower indices to prevent out-of-bounds access if the query point lies on the grid boundary. If $i_0 = D_x - 1$, set $i_0 = D_x - 2$ (and similarly for $y, z$) [S12, S19, unofficial].

4.  **Fractional Weights:** Calculate the fractional offset (weights) within the voxel [S1, S14, unofficial].
    $$ w_x = p_{\text{aligned}, x} - i_0, \quad w_y = p_{\text{aligned}, y} - j_0, \quad w_z = p_{\text{aligned}, z} - k_0 $$
    These weights lie in the range $[0, 1]$.

5.  **Interpolation:** Perform linear interpolation sequentially along the x, y, and z axes [S2, S7, unofficial].
    *   **X-axis:** Interpolate pairs along the x-dimension for the bottom ($k_0$) and top ($k_1$) faces [S12, unofficial].
        $$
        \begin{aligned}
        c_{00} &= v_{000}(1 - w_x) + v_{100}w_x \\
        c_{10} &= v_{010}(1 - w_x) + v_{110}w_x \\
        c_{01} &= v_{001}(1 - w_x) + v_{101}w_x \\
        c_{11} &= v_{011}(1 - w_x) + v_{111}w_x
        \end{aligned}
        $$
    *   **Y-axis:** Interpolate the results from the X-step along the y-dimension [S7, unofficial].
        $$
        \begin{aligned}
        c_0 &= c_{00}(1 - w_y) + c_{10}w_y \\
        c_1 &= c_{01}(1 - w_y) + c_{11}w_y
        \end{aligned}
        $$
    *   **Z-axis:** Interpolate the results from the Y-step along the z-dimension to get the final value [S7, unofficial].
        $$ V(\mathbf{p}) = c_0(1 - w_z) + c_1 w_z $$

**Expanded Formula:**
The result can also be expressed as a weighted sum of the 8 corners:
$$
\begin{aligned}
V(\mathbf{p}) = & \ v_{000}(1-w_x)(1-w_y)(1-w_z) + v_{100}w_x(1-w_y)(1-w_z) + \\
& \ v_{010}(1-w_x)w_y(1-w_z) + v_{110}w_x w_y (1-w_z) + \\
& \ v_{001}(1-w_x)(1-w_y)w_z + v_{101}w_x(1-w_y)w_z + \\
& \ v_{011}(1-w_x)w_y w_z + v_{111}w_x w_y w_z
\end{aligned}
$$
[S1, S11, unofficial]

**Pseudocode:**
```python
def trilinear_interpolation(grid, p, dims):
    """
    grid: 3D array of shape (Dz, Dy, Dx)
    p: tuple (x, y, z) in voxel space
    dims: tuple (Dx, Dy, Dz)
    """
    x, y, z = p
    
    # 1. Compute lower indices
    i0 = int(x // 1) if x >= 0 else int(x // 1) - (1 if x != int(x) else 0)
    j0 = int(y // 1) if y >= 0 else int(y // 1) - (1 if y != int(y) else 0)
    k0 = int(z // 1) if z >= 0 else int(z // 1) - (1 if z != int(z) else 0)
    
    # 2. Handle boundaries: clamp lower index to valid range [0, dim-2]
    i0 = max(0, min(i0, dims[0] - 2))
    j0 = max(0, min(j0, dims[1] - 2))
    k0 = max(0, min(k0, dims[2] - 2))
    
    i1 = i0 + 1
    j1 = j0 + 1
    k1 = k0 + 1
    
    # 3. Compute fractional weights
    wx = x - i0
    wy = y - j0
    wz = z - k0
    
    # 4. Fetch 8 corner values (assuming grid is indexed as [z, y, x])
    v000 = grid[k0, j0, i0]
    v100 = grid[k0, j0, i1]
    v010 = grid[k0, j1, i0]
    v110 = grid[k0, j1, i1]
    v001 = grid[k1, j0, i0]
    v101 = grid[k1, j0, i1]
    v011 = grid[k1, j1, i0]
    v111 = grid[k1, j1, i1]
    
    # 5. Interpolate along X
    c00 = v000 * (1 - wx) + v100 * wx
    c10 = v010 * (1 - wx) + v110 * wx
    c01 = v001 * (1 - wx) + v101 * wx
    c11 = v011 * (1 - wx) + v111 * wx
    
    # 6. Interpolate along Y
    c0 = c00 * (1 - wy) + c10 * wy
    c1 = c01 * (1 - wy) + c11 * wy
    
    # 7. Interpolate along Z
    result = c0 * (1 - wz) + c1 * wz
    
    return result
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** If the query point lies exactly on the upper boundary of the grid, the upper neighbor index would exceed the array bounds. Clamping the lower index to `dim - 2` ensures valid access [S12, S19, unofficial].
*   **Zero-Width Voxels:** If the grid has degenerate voxels (width 0), division by zero may occur if using explicit division for weights. The fractional weight calculation $w = p - i_0$ avoids this, but boundary clamping is still necessary [S14, unofficial].
*   **Coordinate System Mismatch:** Applying a $-0.5$ offset when the grid uses corner-aligned coordinates (or vice versa) shifts the sampling grid, causing incorrect interpolation weights and visual artifacts [S1, S12, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample, requiring exactly 8 memory fetches and 7 linear interpolations (14 multiplications, 7 additions) [S2, S15, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space [G].
*   **Performance:** Produces significantly higher quality images than nearest-neighbor interpolation but takes approximately 5 times longer to compute [S1, S6, unofficial]. It is faster than higher-order methods like tri-cubic interpolation [S8, unofficial].
*   **Strengths:** Simple to implement, hardware-supported (via 3D texture sampling units in GPUs), and provides smoother results than nearest-neighbor [S1, S13, S19, unofficial].
*   **Limitations:** Introduces blurring and high-frequency artifacts (false edges or "star patterns") due to the infinite extent of the triangular pulse kernel's Fourier transform [S7, unofficial]. It is not suitable for applications requiring sharp feature preservation or exact geometric reconstruction [S7, S14, unofficial].
*   **When to use:** General-purpose volume rendering where visual smoothness is prioritized over sharpness, and computational resources are limited compared to higher-order methods [S19, unofficial].
*   **When not to use:** When exact geometric intersection is required, as it approximates values rather than computing precise voxel boundaries [S14, unofficial].

## Background
Trilinear interpolation is the direct 3D extension of bilinear interpolation, defined as the linear interpolation of two bilinear interpolations [S15, unofficial]. It was widely adopted in early volume rendering techniques to improve upon the blocky artifacts of nearest-neighbor sampling [S7, S15, unofficial]. The method is fundamental to many volume rendering pipelines, including those implemented in OpenVDB and standard GPU texture sampling hardware [S1, S13, unofficial]. It is also used in related fields such as fluid simulation [S19, unofficial].
