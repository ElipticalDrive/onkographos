# Bilinear Interpolation

Also called: Bilinear Lerp, 2D Linear Interpolation, Linear Bi-interpolation, Bi-interpolation linéaire

## Overview
Bilinear interpolation estimates the value of a function at an arbitrary point within a two-dimensional rectangular grid by using the known values at the four surrounding corner points [S5]. It extends linear interpolation from one dimension to two by applying the process sequentially along each axis, resulting in a surface that is linear along any line parallel to the coordinate axes [S5]. Unlike nearest neighbor interpolation, which exhibits noticeable artifacts, bilinear interpolation provides $C^0$ continuity, ensuring smooth transitions between grid cells [S5]. It is widely used in volume rendering for sampling texture maps, computing face values in ray casting, and as a component in higher-dimensional schemes [S6, unofficial][S16].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D grid of scalar or vector values $V$ defined at integer lattice points $(x, y)$; a query point $(x, y)$ with real-valued coordinates.
*   **Output:** The interpolated value $f(x, y)$ at the query point.

**Data Structures:**
The grid is typically stored as a 1D contiguous array of size $W \times H$ (width $\times$ height), where the element at grid coordinates $(x, y)$ is accessed at index $x \cdot H + y$ [S8, unofficial].

**Steps:**
1.  **Identify Grid Cell:** Determine the integer coordinates of the bottom-left corner of the cell containing the query point $(x, y)$. Let $x_0 = \lfloor x \rfloor$ and $y_0 = \lfloor y \rfloor$. The four surrounding corners are $(x_0, y_0)$, $(x_0+1, y_0)$, $(x_0, y_0+1)$, and $(x_0+1, y_0+1)$ [S5].
2.  **Compute Fractional Parts:** Calculate the fractional distances from the bottom-left corner:
    $$ t = x - x_0 $$
    $$ u = y - y_0 $$
    Here, $t$ and $u$ are in the range $[0, 1)$ [S5].
3.  **Interpolate along X:** Perform linear interpolation along the bottom edge ($y_0$) and top edge ($y_0+1$) of the cell.
    $$ \text{val}_0 = (1 - t) V_{00} + t V_{10} $$
    $$ \text{val}_1 = (1 - t) V_{01} + t V_{11} $$
    where $V_{00} = V(x_0, y_0)$, $V_{10} = V(x_0+1, y_0)$, $V_{01} = V(x_0, y_0+1)$, and $V_{11} = V(x_0+1, y_0+1)$ [S5].
4.  **Interpolate along Y:** Perform linear interpolation between $\text{val}_0$ and $\text{val}_1$ using $u$:
    $$ f(x, y) = (1 - u) \text{val}_0 + u \text{val}_1 $$
    Substituting the previous steps yields the direct tensor product formula:
    $$ f(x, y) = (1-t)(1-u)V_{00} + t(1-u)V_{10} + (1-t)u V_{01} + t u V_{11} $$
    [S5].

**Parameters:**
*   **Boundary Handling:** Standard bilinear interpolation assumes the query point lies within the grid bounds. If coordinates fall outside, behavior depends on implementation (e.g., clamping, wrapping, or zero-padding) [S10, unofficial].
*   **Coordinate Alignment:** In frameworks like PyTorch, `align_corners=True` maps the extreme values of the input tensor to the extreme values of the output tensor, affecting the exact scaling of $t$ and $u$ [S4, S10, unofficial].

**Pseudocode:**
```python
def bilinear_interpolate(grid, x, y, width, height):
    """
    grid: 1D array of size width * height
    x, y: query coordinates (float)
    width, height: dimensions of the grid
    """
    # 1. Identify grid cell
    x0 = floor(x)
    y0 = floor(y)
    
    # Handle boundary conditions (clamp to valid range)
    x0 = max(0, min(x0, width - 2))
    y0 = max(0, min(y0, height - 2))
    
    # 2. Compute fractional parts
    t = x - x0
    u = y - y0
    
    # 3. Fetch corner values
    # Index calculation: index = x_coord * height + y_coord
    idx_00 = x0 * height + y0
    idx_10 = (x0 + 1) * height + y0
    idx_01 = x0 * height + (y0 + 1)
    idx_11 = (x0 + 1) * height + (y0 + 1)
    
    v00 = grid[idx_00]
    v10 = grid[idx_10]
    v01 = grid[idx_01]
    v11 = grid[idx_11]
    
    # 4. Interpolate
    val0 = (1 - t) * v00 + t * v10
    val1 = (1 - t) * v01 + t * v11
    
    result = (1 - u) * val0 + u * val1
    
    return result
```

**Edge Cases and Pitfalls:**
*   **Discontinuity:** Bilinear interpolation provides $C^0$ continuity, but first derivatives (gradients) are discontinuous at the boundaries of grid cells [S5][S12, unofficial].
*   **Negative Indices:** Implementations must handle negative coordinates. A common bug in naive wrapping implementations is using the wrong dimension for modulo operations (e.g., using `resY` instead of `resX` for x-axis wrapping) [S8, unofficial].
*   **Precision:** In differentiable rendering, half-precision arithmetic may be used for performance, but requires careful handling of gradient accumulation [S7, unofficial].

## Subtopics

### [Optimized Trilinear Reconstruction](2437-optimized-trilinear-reconstruction.md)
Optimized Trilinear Reconstruction accelerates the trilinear interpolation of volume data during direct volume ray casting by leveraging SIMD (Single Instruction, Multiple Data) processor extensions such as MMX, SSE, or 3DNow!. It improves memory copying and interpolation speed compared to scalar implementations.

### [Multi-Dimensional Interpolation Extension](2784-multi-dimensional-interpolation-extension.md)
This method extends one-dimensional reconstruction kernels to three dimensions for volume rendering. It constructs a 3D filter from a 1D base kernel $h'$ to correctly reconstruct signals on a regular 3D mesh, setting itself apart from radial extension methods by avoiding sample frequency ripple artifacts that occur with rotationally-symmetric kernels on regular grids.

### [POCS Interpolation Hardware Implementation](6377-pocs-interpolation-hardware-implementation.md)
A hardware architecture for implementing POCS interpolation filters in volume rendering, designed to overcome the quality limitations of standard tri-linear interpolation while remaining feasible within VLSI constraints. It distinguishes itself from Bilinear Interpolation by supporting larger kernel sizes ($3 \times 3 \times 3$ and $5 \times 5 \times 5$) using lookup tables and specialized memory banking to handle the high data throughput required for multi-voxel sampling.

### [View Adapted Stepping Distances](13215-view-adapted-stepping-distances.md)
View Adapted Stepping Distances is a volume rendering acceleration technique that aligns sample points with voxel cube faces to enable bilinear interpolation instead of trilinear interpolation, while using adaptive termination to skip empty space. It differs from its parent Bilinear Interpolation by dynamically calculating the stepping distance based on the view direction to enforce this alignment, and from Optimized Trilinear Reconstruction by reducing the number of neighbor lookups from 8 to 4.

### Linear Interpolation on Polyhedra
Uses linear interpolation to scan-convert the front and back faces of each polyhedron. Used for unstructured meshes [S12, unofficial]. Exhibits $C^1$ discontinuities common to linear interpolation [S12, unofficial]. Linear interpolation is used because reconstruction for non-uniform sampling on unstructured meshes is not well understood and is significantly more complex than uniform sampling [S12, unofficial].

### Temporal Interpolation
Linear interpolation between two sampled flow vectors of different time steps to handle dynamic vector fields [S13, unofficial]. Formula: $M_R(v, t) = (1 - t)S_i(v) + tS_j(v)$ where $S_i(v), S_j(v)$ are vector field slices [S13, unofficial]. If $k$ is not in $[i, j]$, the equation yields extrapolation instead of interpolation [S13, unofficial].

### Hat-shaped Basis Functions
A method using hat-shaped basis functions to define the interpolant, involving actual leaf cells only on the boundary to remove ghost artifacts [S14, unofficial]. It is unclear how to perform ray-isosurface intersections with this interpolant [S14, unofficial].

### SVGS Bilinear Interpolation
A spatially varying function that divides each Gaussian surfel into four quadrants using bilinear interpolation, assigning a learnable color and opacity value to each quadrant [S15]. Formula: $F_c(p) = (1-u')(1-v')c_0 + (1-u')v'c_1 + u'(1-v')c_2 + u'v'c_3$, where $c_{0..3}$ are learnable colors and $u', v'$ are normalized coordinates [S15]. Parameter $\lambda_s = 5.0$ controls the sigmoid changing rate [S15]. Each Gaussian primitive stores 4 learnable colors and 4 learnable opacities [S15]. This design may cause gradient vanishing issues [S15].

### Bilinear Interpolation with Sigmoid Scaling
A spatial color variation function that uses bilinear interpolation to model intra-primitive color changes, scaled by a sigmoid function to handle coordinates outside the standard (0,1) range [S15]. Coordinates $(u, v)$ are passed through a sigmoid function before bilinear sampling: $u' = \sigma(u), v' = \sigma(v)$ [S15]. Sigmoid scaling causes pixel gradients to approach zero near the center of a quadrant, leading to gradient vanishing during sharp color transitions and preventing perfect scene fitting [S15]. Bilinear interpolation is only effective when the spatial color pattern conforms to a four-quadrant distribution [S15]. It captures abrupt color transitions more effectively than tiny neural networks or movable kernels, but suffers from vanishing gradients in other regions, reducing overall expressiveness when multiple Gaussians are superimposed [S15].

### Ray-Texture UV Mapping and Interpolation
Computes UV coordinates for ray-Gaussian intersections to sample spatially varying colors from texture maps using bilinear interpolation [S16]. Steps: Cast a ray from the camera origin to find intersection point $p_i$ with the $i$-th Gaussian; Compute UV coordinates $u_i$ and $v_i$ using the tangent/bitangent vectors, intersection point, texel size, and texture dimensions; Sample the texture map $T_i$ at $(u_i, v_i)$ using bilinear interpolation to obtain color $c_{tex}$ [S16]. Formula: $u_i(p_i) = ((t_u)_i \cdot p_i) / T_{size} + (U_i - 1)/2$, where $(t_u)_i$ is the tangent vector, $p_i$ is the intersection point, $T_{size}$ is the texel size, and $U_i$ is the texture width [S16].

### Pixel Level Data Dependent Interpolation
Scans the low-resolution source image $X$ to initialize a 2D array $x_{mn}$ recording edge directions; scans the high-resolution target image $Y$ to initialize $y_{ij}$; uses $x_{mn}$ to identify the triangle in which the inversely mapped point falls in $X$; calculates $y_{ij}$ using barycentric interpolation; detects outliers by comparing differences of four pixel values [S17, unofficial]. In experiments with stamens (75x75 to 2048x2048), it preserved details better than bilinear interpolation [S17, unofficial]. Compared to bilinear interpolation, it keeps edges sharp and smooth areas smooth, whereas bilinear interpolation may blur edges [S17, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
Bilinear interpolation requires a constant number of arithmetic operations (8 multiplications, 4 additions/subtractions) and memory accesses (4 samples) per query, regardless of grid size [S5]. The memory complexity is $O(W \cdot H)$ for storing the grid [S8, unofficial].

**Measured Performance:**
Performance is highly dependent on hardware support. Modern GPUs provide dedicated bilinear filtering instructions (e.g., `LRP` in some architectures, or texture sampling units) which execute in a single cycle per fragment when accessed via texture caches [S9, unofficial]. In software implementations, SIMD optimizations can significantly accelerate the process [S1].

**Scaling:**
The method scales linearly with the number of query points. It is independent of the total grid size, making it suitable for large volumes where only local samples are needed [S5].

**Strengths and Limitations:**
*   **Strengths:** Computationally efficient; provides smoother results than nearest neighbor; easy to implement; supports differentiable rendering (gradients are well-defined) [S7, S10, unofficial].
*   **Limitations:** $C^0$ continuity only; prone to blurring high-frequency details; suffers from aliasing if the sampling rate is insufficient (Nyquist criterion not met) [S5].

**When to Use:**
Use bilinear interpolation for general-purpose volume rendering where performance is critical and high-frequency detail preservation is not the primary goal. It is ideal for texture mapping, face value computation in ray casting, and as a base for more complex filters [S6, unofficial][S16].

**When Not to Use:**
Avoid when $C^1$ continuity is required (use cubic or spline interpolation) or when preserving sharp edges is critical without post-processing (use edge-aware methods) [S17, unofficial].

## Background
Bilinear interpolation is a fundamental technique in computer graphics and image processing. It was widely adopted in early volume rendering systems for its simplicity and efficiency [S5]. The method is often used in conjunction with ray casting to sample density and color values from volume textures [S6, unofficial]. In the context of Fourier space reconstruction, bilinear interpolation is used to retrieve values from polar grids to Cartesian grids [S11, unofficial]. It is also a core component in differentiable rendering pipelines, such as those used in 3D Gaussian Splatting variants (e.g., SVGS) to model spatially varying colors [S15].
