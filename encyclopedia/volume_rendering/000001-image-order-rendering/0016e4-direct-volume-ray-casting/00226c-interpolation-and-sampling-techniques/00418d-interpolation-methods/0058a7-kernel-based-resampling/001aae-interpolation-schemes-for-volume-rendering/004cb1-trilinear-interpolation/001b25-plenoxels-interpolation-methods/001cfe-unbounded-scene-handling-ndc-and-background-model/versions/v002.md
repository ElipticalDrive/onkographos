# Unbounded Scene Handling (NDC and Background Model)
Also called: Background Spheres, NDC and Background Model

## Overview
This method extends Plenoxels to real, unbounded scenes, both forward-facing and 360° [S1][S2, unofficial]. For forward-facing scenes, it uses normalized device coordinates (NDC) for the sparse voxel grid structure [S1][S2, unofficial]. For 360° scenes, it augments the sparse voxel grid foreground with a multisphere image (MSI) background model to represent distant geometry [S1][S2, unofficial].

## How it works
The method adapts the discrete voxel representation based on the scene type.

### Inputs and Outputs
*   **Inputs:** Camera poses, image observations, and scene classification (forward-facing or 360°) [S1][S2, unofficial].
*   **Outputs:** Radiance and density fields represented by a sparse voxel grid (foreground) and, for 360° scenes, multisphere layers (background) [S1][S2, unofficial].

### Data Structures
1.  **Foreground Voxel Grid:** A sparse 3D grid storing learned voxel colors and opacities [S1] or densities [S2, unofficial].
    *   **Forward-facing:** Coordinates are mapped to NDC space [S1][S2, unofficial].
    *   **360°:** Coordinates remain in standard Euclidean space, with the background handled separately [S1][S2, unofficial].
2.  **Multisphere Image (MSI) Layers (360° only):**
    *   Consists of 64 concentric spheres [S1][S2, unofficial].
    *   Each sphere stores a 2D voxel grid indexed by spherical angles $\theta$ and $\phi$ via equirectangular projection [S1][S2, unofficial].
    *   **Storage:** Only RGB channels (zero-order SH) are stored to conserve memory [S1][S2, unofficial].
    *   **Sparsity:** Layers are stored sparsely using opacity thresholding [S1] or density thresholding [S2, unofficial].

### Steps
1.  **Scene Classification:** Determine if the scene is forward-facing or 360° [S1][S2, unofficial].
2.  **Coordinate Transformation:**
    *   **If Forward-Facing:** Use normalized device coordinates (NDC) for the sparse voxel grid structure, as defined in the original NeRF paper [S1][S2, unofficial].
    *   **If 360°:** Keep coordinates in standard Euclidean space for the foreground [S1][S2, unofficial].
3.  **Background Model Construction (360° only):**
    *   Pre-scale the inner scene so it is approximately contained within the unit sphere [S1][S2, unofficial].
    *   Place 64 spheres linearly in inverse radius from $r=1$ to $r=\infty$ [S1][S2, unofficial].
    *   For each sphere, voxels are indexed by spherical angles $\theta$ and $\phi$ using an equirectangular projection [S1][S2, unofficial].
    *   Learn voxel colors (RGB) and opacities for each sphere layer using trilinear interpolation within and between spheres [S1][S2, unofficial].
4.  **Rendering:**
    *   For each pixel, cast a ray [G].
    *   If the ray intersects the foreground voxel grid, sample radiance and density using trilinear interpolation [S1][S2, unofficial].
    *   If the ray extends beyond the foreground (or for 360° scenes), intersect the MSI layers [S1][S2, unofficial].
    *   Sample the appropriate sphere based on distance, using equirectangular coordinates to index the 2D voxel grid [S1][S2, unofficial].

### Parameters
*   **Number of Background Spheres:** 64 [S1][S2, unofficial].
*   **Radius Distribution:** Linear in inverse radius from 1 to $\infty$ [S1][S2, unofficial].
*   **Color Representation:** RGB only (zero-order SH) [S1][S2, unofficial].
*   **Sparsity Threshold:** Opacity thresholding [S1] or density thresholding [S2, unofficial] is used to prune empty background layers.

### Edge Cases and Pitfalls
*   **Precision:** The pre-scaling of the inner scene to the unit sphere is critical for correct sphere placement and smooth foreground-background transitions [S1][S2, unofficial].
*   **Memory:** Storing 64 full-resolution spheres is memory-intensive, requiring sparsity pruning and zero-order SH storage to remain feasible [S1][S2, unofficial].
*   **Forward-Facing Assumption:** NDC is only valid for forward-facing scenes where the camera does not orbit 360° around the center [S1][S2, unofficial].

## Subtopics

### Plenoxel Unbounded Scene Handling
This variant refers to the implementation details in the Plenoxels paper for handling unbounded scenes [S1][S2, unofficial]. It distinguishes two modes: forward-facing scenes using NDC coordinates [S1][S2, unofficial], and 360° scenes using a Multisphere Image (MSI) background model [S1][S2, unofficial]. The MSI model uses 64 spheres linearly spaced in inverse radius from 1 to $\infty$, with voxels warped into spheres via equirectangular projection [S1][S2, unofficial]. Colors are stored as RGB (zero-order SH) and layers are stored sparsely using opacity thresholding [S1] or density thresholding [S2, unofficial].

## Operating characteristics
*   **Memory:** Memory consumption is mitigated by storing only RGB channels (zero-order SH) and pruning layers via opacity thresholding [S1] or density thresholding [S2, unofficial].
*   **Strengths:** Enables training on real, unbounded scenes, both forward-facing and 360°, without requiring manual bounding box estimation [S1][S2, unofficial].
*   **Limitations:** The NDC approach is restricted to forward-facing camera trajectories [S1][S2, unofficial].

## Background
This method was introduced in the Plenoxels paper (Fridovich-Keil et al., 2022) to extend radiance field representation without neural networks to real, unbounded scenes [S1][S2, unofficial]. It builds on the NDC coordinate system from the original NeRF paper [S1][S2, unofficial] and the multisphere background model from NeRF++ [S1].
