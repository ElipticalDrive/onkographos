# Bilinear Interpolation

Also called: Bilinear Lerp, 2D Linear Interpolation, Linear Bi-interpolation, Bi-interpolation linéaire

## Overview
Bilinear interpolation estimates the value of a function at an arbitrary point within a two-dimensional rectangular grid by using the known values at the four surrounding corner points [S5]. It extends linear interpolation from one dimension to two by applying the process sequentially along each axis, resulting in a surface that is linear along any line parallel to the coordinate axes [S5]. In the context of volume rendering, it is primarily used to sample scalar or color values on the faces of voxels (2D slices) or to handle 2D texture coordinates for spatially varying attributes [S6, unofficial][S16]. Unlike its sibling [Trilinear Interpolation](1531-trilinear-interpolation.md), which samples the interior of a 3D voxel using 8 neighbors, bilinear interpolation operates on a 2D plane using 4 neighbors, offering lower computational cost at the expense of reduced spatial continuity in the third dimension [S5].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D grid of values $V$ (e.g., a texture map, a voxel face, or a frequency domain slice), a query position $(x, y)$ in the grid's coordinate system, and the grid dimensions $(W, H)$.
*   **Output:** The interpolated scalar or vector value $f(x, y)$.

**Data Structures:**
The grid is typically stored as a 1D contiguous array of size $W \times H$ (or $H \times W$ depending on layout convention), where the element at grid coordinates $(u, v)$ is accessed at index $u \times H + v$ (assuming row-major storage with width $W$ and height $H$, or $x \times resY + y$ as per [S8, unofficial]).

**Steps:**
1.  **Coordinate Normalization:** If the query coordinates $(x, y)$ are in a normalized range (e.g., $[0, 1]$ or $[-1, 1]$), map them to the grid's pixel space. For a grid of width $W$ and height $H$, the pixel coordinates are $x_{pix} = x \cdot W$ and $y_{pix} = y \cdot H$ [S9, unofficial].
2.  **Cell Identification:** Determine the integer coordinates of the bottom-left corner of the grid cell containing $(x, y)$:
    $$ u_0 = \lfloor x_{pix} \rfloor, \quad v_0 = \lfloor y_{pix} \rfloor $$
    The four surrounding corners are $(u_0, v_0)$, $(u_0+1, v_0)$, $(u_0, v_0+1)$, and $(u_0+1, v_0+1)$ [S5][S7, unofficial].
3.  **Fractional Parts:** Calculate the fractional offsets within the cell:
    $$ w_u = x_{pix} - u_0, \quad w_v = y_{pix} - v_0 $$
    where $w_u, w_v \in [0, 1)$ [S7, unofficial].
4.  **Boundary Handling:** Handle indices that fall outside the grid boundaries. Common strategies include clamping to the nearest edge, wrapping (modulo arithmetic), or returning a default value (e.g., 0) [S8, S10, unofficial]. Note that naive wrapping using modulo on negative indices can be buggy if not handled carefully (e.g., using the correct dimension for modulo) [S8, unofficial].
5.  **Interpolation:**
    *   **Sequential Method:**
        1.  Interpolate along the x-axis for the bottom row ($v_0$):
            $$ val_0 = (1 - w_u) V(u_0, v_0) + w_u V(u_0+1, v_0) $$
        2.  Interpolate along the x-axis for the top row ($v_0+1$):
            $$ val_1 = (1 - w_u) V(u_0, v_0+1) + w_u V(u_0+1, v_0+1) $$
        3.  Interpolate along the y-axis between $val_0$ and $val_1$:
            $$ f(x, y) = (1 - w_v) val_0 + w_v val_1 $$
    *   **Direct Tensor Product Formula:**
        $$ f(x, y) = (1-w_u)(1-w_v)V_{00} + w_u(1-w_v)V_{10} + (1-w_u)w_v V_{01} + w_u w_v V_{11} $$
        where $V_{00} = V(u_0, v_0)$, $V_{10} = V(u_0+1, v_0)$, $V_{01} = V(u_0, v_0+1)$, and $V_{11} = V(u_0+1, v_0+1)$ [S5][S8, unofficial].

**Pseudocode:**
```python
def bilinear_interpolate(grid, x, y, width, height, padding_mode="zeros"):
    """
    grid: 1D array of size width * height
    x, y: query coordinates in pixel space (float)
    width, height: dimensions of the grid
    padding_mode: "zeros", "clamp", or "wrap"
    """
    # 1. Identify cell corners
    u0 = int(x)
    v0 = int(y)
    
    # 2. Calculate fractional parts
    w_u = x - u0
    w_v = y - v0
    
    # 3. Handle boundaries and fetch values
    def get_value(u, v):
        if padding_mode == "zeros":
            if u < 0 or u >= width or v < 0 or v >= height:
                return 0.0
        elif padding_mode == "clamp":
            u = max(0, min(width - 1, u))
            v = max(0, min(height - 1, v))
        elif padding_mode == "wrap":
            u = u % width
            v = v % height
        else:
            # Default to clamp if mode unknown
            u = max(0, min(width - 1, u))
            v = max(0, min(height - 1, v))
            
        return grid[u * height + v]

    # 4. Fetch the four corner values
    v00 = get_value(u0, v0)
    v10 = get_value(u0 + 1, v0)
    v01 = get_value(u0, v0 + 1)
    v11 = get_value(u0 + 1, v0 + 1)
    
    # 5. Perform interpolation
    # Sequential: x then y
    val_bottom = (1 - w_u) * v00 + w_u * v10
    val_top = (1 - w_u) * v01 + w_u * v11
    result = (1 - w_v) * val_bottom + w_v * val_top
    
    return result
```

**Parameters:**
*   `padding_mode`: Determines behavior at boundaries. "zeros" returns 0 for out-of-bounds access (common in deep learning frameworks like PyTorch) [S10, unofficial]. "clamp" clamps to the edge pixels. "wrap" uses modulo arithmetic [S8, unofficial].
*   `align_corners`: In some frameworks, this boolean flag changes how the coordinate range is mapped to pixel centers. If `True`, the corners of the first and last pixels align with the boundaries of the sampling grid [S10, unofficial].

**Edge Cases and Pitfalls:**
*   **Discontinuity:** Bilinear interpolation provides $C^0$ continuity (function values are continuous) but the first derivatives (gradients) are discontinuous at the grid cell boundaries [S5][S12, unofficial]. This can cause visible artifacts in high-frequency details or when used for gradient-based optimization [S15].
*   **Negative Indices:** When implementing wrapping for negative coordinates, care must be taken to use the correct dimension for the modulo operation. A common bug is using `resY` instead of `resX` for x-axis wrapping [S8, unofficial].
*   **Gradient Vanishing:** When bilinear interpolation is combined with sigmoid scaling to handle coordinates outside the $[0, 1]$ range (e.g., in spatially varying Gaussian splatting), gradients can vanish near the center of quadrants, hindering learning [S15].

## Subtopics

### [Optimized Trilinear Reconstruction](2437-optimized-trilinear-reconstruction.md)
Optimized Trilinear Reconstruction accelerates the trilinear interpolation of volume data during direct volume ray casting by leveraging SIMD (Single Instruction, Multiple Data) processor extensions such as MMX, SSE, or 3DNow!. It improves memory copying and interpolation speed compared to scalar implementations. While bilinear interpolation is the 2D analog, this variant focuses on optimizing the 3D case using hardware-specific instructions.

### [Multi-Dimensional Interpolation Extension](2784-multi-dimensional-interpolation-extension.md)
This method extends one-dimensional reconstruction kernels to three dimensions for volume rendering. It constructs a 3D filter from a 1D base kernel $h'$ to correctly reconstruct signals on a regular 3D mesh, setting itself apart from radial extension methods by avoiding sample frequency ripple artifacts that occur with rotationally-symmetric kernels on regular grids.

### [POCS Interpolation Hardware Implementation](6377-pocs-interpolation-hardware-implementation.md)
A hardware architecture for implementing POCS interpolation filters in volume rendering, designed to overcome the quality limitations of standard tri-linear interpolation while remaining feasible within VLSI constraints. It distinguishes itself from Bilinear Interpolation by supporting larger kernel sizes ($3 \times 3 \times 3$ and $5 \times 5 \times 5$) using lookup tables and specialized memory banking to handle the high data throughput required for multi-voxel sampling.

### [View Adapted Stepping Distances](13215-view-adapted-stepping-distances.md)
View Adapted Stepping Distances is a volume rendering acceleration technique that aligns sample points with voxel cube faces to enable bilinear interpolation instead of trilinear interpolation, while using adaptive termination to skip empty space. It differs from its parent Bilinear Interpolation by dynamically calculating the stepping distance based on the view direction to enforce this alignment, and from Optimized Trilinear Reconstruction by reducing the number of neighbor lookups from 8 to 4.

### Linear Interpolation on Polyhedra
Uses linear interpolation to scan-convert the front and back faces of each polyhedron. Used for unstructured meshes [S12, unofficial]. Exhibits $C^1$ discontinuities common to linear interpolation [S12, unofficial]. Linear interpolation is used because reconstruction for non-uniform sampling on unstructured meshes is not well understood and is significantly more complex than uniform sampling [S12, unofficial].

### Temporal Interpolation
Linear interpolation between two sampled flow vectors of different time steps to handle dynamic vector fields [S13, unofficial]. Formula: $M_R(v, t) = (1 - t)S_i(v) + tS_j(v)$ where $S_i(v), S_j(v)$ are vector field slices [S13, unofficial]. If $k$ is not in $[i, j]$, the equation yields extrapolation instead of interpolation [S13, unofficial].

### Hat-shaped Basis Functions
A method using hat-shaped basis functions to define the interpolant, involving actual leaf cells only on the boundary to remove ghost artifacts [S14, unofficial]. It is unclear how to perform ray-isosurface intersections with this interpolant [S14, unofficial].

### SVGS Bilinear Interpolation
A spatially varying function that divides each Gaussian surfel into four quadrants using bilinear interpolation, assigning a learnable color and opacity value to each quadrant [S15]. Formula: $F_c(p) = (1-u')(1-v')c_0 + (1-u')v'c_1 + u'(1-v')c_2 + u'v'c_3$, where $c_0..c_3$ are learnable colors for the four quadrants, and $u', v'$ are normalized coordinates [S15]. $u' = 1 / (1 + e^{-\lambda_s u})$, $v' = 1 / (1 + e^{-\lambda_s v})$, where $\lambda_s = 5.0$ controls the sigmoid changing rate [S15]. Each Gaussian primitive stores 4 learnable colors and 4 learnable opacities for the four quadrants [S15]. This design may cause gradient vanishing issues [S15].

### Bilinear Interpolation with Sigmoid Scaling
A spatial color variation function that uses bilinear interpolation to model intra-primitive color changes, scaled by a sigmoid function to handle coordinates outside the standard $(0,1)$ range [S15]. Coordinates $(u, v)$ are passed through a sigmoid function before bilinear sampling: $u' = \sigma(u)$, $v' = \sigma(v)$. This maps arbitrary coordinates to $(0,1)$ but compresses gradients near quadrant centers [S15]. Sigmoid scaling causes pixel gradients to approach zero near the center of a quadrant, leading to gradient vanishing during sharp color transitions and preventing perfect scene fitting [S15]. Bilinear interpolation is only effective when the spatial color pattern conforms to a four-quadrant distribution [S15]. Captures abrupt color transitions more effectively than tiny neural networks or movable kernels, but suffers from vanishing gradients in other regions, reducing overall expressiveness when multiple Gaussians are superimposed [S15].

### Ray-Texture UV Mapping and Interpolation
Computes UV coordinates for ray-Gaussian intersections to sample spatially varying colors from texture maps using bilinear interpolation [S16]. Cast a ray from the camera origin to find intersection point $p_i$ with the $i$-th Gaussian [S16]. Compute UV coordinates $u_i$ and $v_i$ using the tangent/bitangent vectors, intersection point, texel size, and texture dimensions [S16]. Sample the texture map $T_i$ at $(u_i, v_i)$ using bilinear interpolation to obtain color $c_{tex}$ [S16]. Formula: $u_i(p_i) = ((t_u)_i \cdot p_i) / T_{size} + (U_i - 1)/2$, where $(t_u)_i$ is the tangent vector of the $i$-th Gaussian, $p_i$ is the intersection point, $T_{size}$ is the texel size, and $U_i$ is the texture width [S16]. $v_i(p_i) = ((t_v)_i \cdot p_i) / T_{size} + (V_i - 1)/2$, where $(t_v)_i$ is the bitangent vector of the $i$-th Gaussian and $V_i$ is the texture height [S16].

### Pixel Level Data Dependent Interpolation
Scans the low-resolution source image $X$ to initialize a 2D array $x_{mn}$, which records the edge direction of all four-pixel squares [S17, unofficial]. Scans the high-resolution target image $Y$ to initialize a 2D array $y_{ij}$ [S17, unofficial]. Each $y_{ij}$ is inversely mapped to the sample image $X$ [S17, unofficial]. Uses the array $x_{mn}$ to identify the triangle in which the inversely mapped point falls in the source image $X$ [S17, unofficial]. Calculates the value of $y_{ij}$ using barycentric interpolation [S17, unofficial]. Detects outliers by comparing the difference $|a - c|$ and $|b - d|$ of four pixel values (represented as heights) [S17, unofficial]. The pair with the smaller difference is treated as an edge [S17, unofficial]. In experiments with stamens (original photo 75x75 pixels, morphed texture 2048x2048 pixels), pixel level data dependent interpolation preserved details better than bilinear interpolation [S17, unofficial]. Compared to bilinear interpolation, pixel level data dependent interpolation keeps edges sharp and smooth areas smooth, whereas bilinear interpolation may blur edges [S17, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
Bilinear interpolation requires a constant number of arithmetic operations (4 multiplications, 4 additions/subtractions, and 2 floor operations) and 4 memory accesses per query, regardless of the grid size. The time complexity is $O(1)$ per sample [S5]. Memory complexity is proportional to the size of the grid $W \times H$ [S8, unofficial].

**Measured Performance:**
Performance depends heavily on hardware support. Modern GPUs have dedicated hardware units for bilinear texture sampling, making it extremely fast [S9, unofficial]. In software implementations, SIMD optimizations can significantly accelerate the process [S1].

**Scaling:**
The method scales linearly with the number of samples (pixels/voxels) but is independent of the grid resolution in terms of per-sample cost. However, higher resolution grids may lead to increased cache misses if the access pattern is not coherent [S1].

**Strengths and Limitations:**
*   **Strengths:** Simple to implement, computationally efficient, provides smoother results than nearest-neighbor interpolation [S5].
*   **Limitations:** $C^0$ continuity only, leading to discontinuous gradients at cell boundaries [S5]. Can introduce blurring artifacts, especially when downscaling [S5]. Not suitable for high-frequency details or sharp edges without additional techniques (e.g., anisotropic filtering) [S17, unofficial].

**When to Use:**
Use bilinear interpolation when sampling 2D textures, voxel faces, or when computational efficiency is critical and high-frequency detail preservation is not the primary concern [S5, S16].

**When Not to Use:**
Avoid when $C^1$ continuity is required (use cubic or spline interpolation) or when sampling 3D volumes where trilinear or higher-order methods are more appropriate [S5][S12, unofficial].

## Background
Bilinear interpolation is a fundamental technique in computer graphics and image processing, extending the concept of linear interpolation to two dimensions [S5]. It has been widely used for tasks such as image resizing, texture mapping, and volume rendering [S5]. The method is often implemented in hardware via texture sampling units in GPUs [S9, unofficial]. In the context of volume rendering, it is used to sample values on voxel faces or to handle 2D attributes associated with 3D primitives [S6, unofficial][S16].
