# Bilinear Interpolation

Also called: Bilinear Lerp, 2D Linear Interpolation, Linear Bi-interpolation, Bi-interpolation linéaire

## Overview
Bilinear interpolation estimates the value of a function at an arbitrary point within a two-dimensional rectangular grid by using the known values at the four surrounding corner points [S5]. It extends linear interpolation from one dimension to two by applying the process sequentially along each axis, resulting in a surface that is linear along any line parallel to the coordinate axes [S5]. In the context of volume rendering, it is primarily used for sampling 2D texture maps associated with volume data or for interpolating values on the faces of 3D voxels [S6, unofficial][S16]. It sets itself apart from [Trilinear Interpolation](1531-trilinear-interpolation.md) by operating in two dimensions rather than three, and from [Nearest neighbor interpolation](817-interpolation-schemes-for-volume-rendering.md) by providing C⁰ continuity and smoother transitions, though it introduces blurring compared to higher-order methods [S5].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D grid of values $V$ with dimensions $W \times H$ (or $resX \times resY$), and a query coordinate $(x, y)$ in the continuous domain of the grid.
*   **Output:** The interpolated scalar value $f(x, y)$ at the query point.

**Data Structures:**
The grid is typically stored as a 1D contiguous array of size $resX \times resY$ [S8, unofficial]. The element at integer coordinates $(x, y)$ is stored at index $x \cdot resY + y$ [S8, unofficial].

**Steps:**
1.  **Coordinate Normalization/Mapping:** If the query coordinates are in a different space (e.g., normalized device coordinates or texture coordinates), map them to the grid's coordinate system. For standard bilinear interpolation, the coordinates $(x, y)$ should fall within the range $[0, resX-1] \times [0, resY-1]$ or $[0, 1] \times [0, 1]$ depending on implementation [S9, S10, unofficial].
2.  **Identify Surrounding Grid Points:** Determine the integer coordinates of the four corners of the grid cell containing $(x, y)$. Let $x_0 = \lfloor x \rfloor$ and $y_0 = \lfloor y \rfloor$ be the floor coordinates. The four corners are $(x_0, y_0)$, $(x_0+1, y_0)$, $(x_0, y_1)$, and $(x_0+1, y_1)$, where $y_1 = y_0 + 1$ [S5][S7, unofficial].
3.  **Compute Fractional Parts:** Calculate the fractional offsets $t$ and $u$ (or $d_x, d_y$) representing the position of $(x, y)$ within the cell:
    $$ t = x - x_0 $$
    $$ u = y - y_0 $$
    These values lie in the range $[0, 1)$ [S5][S8, unofficial].
4.  **Retrieve Corner Values:** Fetch the values from the grid at the four corners:
    *   $f_{00} = V(x_0, y_0)$
    *   $f_{10} = V(x_0+1, y_0)$
    *   $f_{01} = V(x_0, y_0+1)$
    *   $f_{11} = V(x_0+1, y_0+1)$
    [S5][S8, unofficial].
5.  **Interpolate along X:** Perform linear interpolation along the x-axis for the bottom and top edges of the cell:
    $$ val_0 = (1 - t) f_{00} + t f_{10} $$
    $$ val_1 = (1 - t) f_{01} + t f_{11} $$
    [S5].
6.  **Interpolate along Y:** Perform linear interpolation along the y-axis between the two intermediate values:
    $$ f(x, y) = (1 - u) val_0 + u val_1 $$
    [S5].

**Formula:**
The direct tensor product formula combines the above steps:
$$ f(x,y) = (1-t)(1-u)f_{00} + t(1-u)f_{10} + (1-t)uf_{01} + tuf_{11} $$
[S5][S8, unofficial].

Alternatively, using vector notation where $\mathbf{w}$ is the weight vector and $\mathbf{p}$ is the vector of neighbor values:
$$ \mathbf{w} = \begin {bmatrix} (1-w_u)(1-w_v) \\ w_u(1-w_v) \\ (1-w_u)w_v \\ w_u w_v \end {bmatrix}, \quad \mathbf{p} = \begin {bmatrix} P_i[v_0, u_0] \\ P_i[v_0, u_0+1] \\ P_i[v_0+1, u_0] \\ P_i[v_0+1, u_0+1] \end {bmatrix} $$
$$ M_i(x,y) = \mathbf{w}^T \mathbf{p} = \sum _{j=0}^{3} w_j p_j $$
[S7, unofficial].

**Parameters:**
*   `align_corners`: In some implementations (e.g., PyTorch), this boolean parameter determines if the corner pixels of input and output tensors align. If `True`, the corners are aligned [S4, S10, unofficial].
*   `padding_mode`: Determines how to handle queries outside the grid boundaries. Common values are "zeros" or "reflection" [S10, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Queries outside the grid bounds require boundary handling. "Zeros" padding is common [S10, unofficial].
*   **Negative Indices:** Implementations must handle negative coordinates. A naive modulo operation on negative numbers can yield incorrect results. Correct wrapping requires adjusting the index before modulo: `if(x<0){x = resX - ((-x) % resX);}` [S8, unofficial]. Note that a bug exists in some code where `resY` is used instead of `resX` for x-axis wrapping [S8, unofficial].
*   **Continuity:** Bilinear interpolation provides C⁰ continuity (continuous function values) but the first derivatives (gradients) are discontinuous at the grid cell boundaries [S5][S12, unofficial].

**Pseudocode:**
```python
def bilinear_interpolate(grid, x, y, resX, resY, padding_mode='zeros'):
    """
    Performs bilinear interpolation on a 2D grid.
    
    Args:
        grid: 1D array of size resX * resY.
        x, y: Query coordinates.
        resX, resY: Dimensions of the grid.
        padding_mode: 'zeros' for out-of-bounds.
        
    Returns:
        Interpolated value.
    """
    # 1. Handle boundaries
    if padding_mode == 'zeros':
        if x < 0 or x >= resX - 1 or y < 0 or y >= resY - 1:
            return 0.0
    
    # 2. Identify grid cell
    x0 = int(x)
    y0 = int(y)
    
    # Handle negative indices correctly for wrapping if needed, 
    # but for standard interpolation within bounds, floor is sufficient.
    # If wrapping is required (e.g., texture coordinates):
    # if x0 < 0: x0 = resX - ((-x0) % resX)
    # if y0 < 0: y0 = resY - ((-y0) % resY)
    
    # 3. Fractional parts
    t = x - x0
    u = y - y0
    
    # 4. Retrieve corner values
    # Index calculation: index = x * resY + y
    idx_00 = x0 * resY + y0
    idx_10 = (x0 + 1) * resY + y0
    idx_01 = x0 * resY + (y0 + 1)
    idx_11 = (x0 + 1) * resY + (y0 + 1)
    
    f_00 = grid[idx_00]
    f_10 = grid[idx_10]
    f_01 = grid[idx_01]
    f_11 = grid[idx_11]
    
    # 5. Interpolate
    val_0 = (1 - t) * f_00 + t * f_10
    val_1 = (1 - t) * f_01 + t * f_11
    result = (1 - u) * val_0 + u * val_1
    
    return result
```

## Subtopics

### [Optimized Trilinear Reconstruction](2437-optimized-trilinear-reconstruction.md)
Optimized Trilinear Reconstruction accelerates the trilinear interpolation of volume data during direct volume ray casting by leveraging SIMD (Single Instruction, Multiple Data) processor extensions such as MMX, SSE, or 3DNow!. It improves memory copying and interpolation speed compared to scalar implementations.

### [Multi-Dimensional Interpolation Extension](2784-multi-dimensional-interpolation-extension.md)
This method extends one-dimensional reconstruction kernels to three dimensions for volume rendering. It constructs a 3D filter from a 1D base kernel $h'$ to correctly reconstruct signals on a regular 3D mesh, setting itself apart from radial extension methods by avoiding sample frequency ripple artifacts that occur with rotationally-symmetric kernels on regular grids.

### [POCS Interpolation Hardware Implementation](6377-pocs-interpolation-hardware-implementation.md)
A hardware architecture for implementing POCS interpolation filters in volume rendering, designed to overcome the quality limitations of standard tri-linear interpolation while remaining feasible within VLSI constraints. It distinguishes itself from Bilinear Interpolation by supporting larger kernel sizes ($3 \times 3 \times 3$ and $5 \times 5 \times 5$) using lookup tables and specialized memory banking to handle the high data throughput required for multi-voxel sampling.

### [View Adapted Stepping Distances](13215-view-adapted-stepping-distances.md)
View Adapted Stepping Distances is a volume rendering acceleration technique that aligns sample points with voxel cube faces to enable bilinear interpolation instead of trilinear interpolation, while using adaptive termination to skip empty space. It differs from its parent Bilinear Interpolation by dynamically calculating the stepping distance based on the view direction to enforce this alignment, and from Optimized Trilinear Reconstruction by reducing the number of neighbor lookups from 8 to 4.

### [Seamless Interpolation](17470-seamless-interpolation.md)
Seamless Interpolation is a method for rendering smooth surfaces stored in hierarchical tile-based structures (TileTrees) that eliminates pixelated appearance and interpolation seams at tile boundaries. It solves the problem of discontinuous color transitions when sampling from partially covered faces or n-leaves by computing a weighted sum of contributions from up to three adjacent face tiles ($T_x, T_y, T_z$) based on the surface normal. It differs from standard bilinear interpolation by explicitly handling multi-face visibility via binary alpha flags and normal-based dampening to ensure continuity across adaptive resolution boundaries and partial coverage areas.

### Linear Interpolation on Polyhedra
Uses linear interpolation to scan-convert the front and back faces of each polyhedron. Used for unstructured meshes [S12, unofficial]. Exhibits C1 discontinuities common to linear interpolation [S12, unofficial]. Linear interpolation is used because reconstruction for non-uniform sampling on unstructured meshes is not well understood and is significantly more complex than uniform sampling [S12, unofficial].

### Temporal Interpolation
Linear interpolation between two sampled flow vectors of different time steps to handle dynamic vector fields [S13, unofficial]. Formula: $M_R(v, t) = (1 - t)S_i(v) + tS_j(v)$ where $S_i(v), S_j(v)$ are vector field slices [S13, unofficial]. If $k$ is not in $[i, j]$, the equation yields extrapolation instead of interpolation [S13, unofficial].

### Hat-shaped Basis Functions
A method using hat-shaped basis functions to define the interpolant, involving actual leaf cells only on the boundary to remove ghost artifacts [S14, unofficial]. It is unclear how to perform ray-isosurface intersections with this interpolant [S14, unofficial].

### SVGS Bilinear Interpolation
A spatially varying function that divides each Gaussian surfel into four quadrants using bilinear interpolation, assigning a learnable color and opacity value to each quadrant [S15]. Formula: $F_c(p) = (1-u')(1-v')c_0 + (1-u')v'c_1 + u'(1-v')c_2 + u'v'c_3$, where $c_0..c_3$ are learnable colors for the four quadrants, and $u', v'$ are normalized coordinates [S15]. $u' = 1 / (1 + e^{-\lambda_s u})$, $v' = 1 / (1 + e^{-\lambda_s v})$, where $\lambda_s = 5.0$ controls the sigmoid changing rate [S15]. Each Gaussian primitive stores 4 learnable colors ($c_0-c_3$) and 4 learnable opacities ($\alpha_0-\alpha_3$) for the four quadrants [S15]. This design may cause gradient vanishing issues [S15].

### Bilinear Interpolation with Sigmoid Scaling
A spatial color variation function that uses bilinear interpolation to model intra-primitive color changes, scaled by a sigmoid function to handle coordinates outside the standard (0,1) range [S15]. Coordinates $(u, v)$ are passed through a sigmoid function before bilinear sampling: $u' = \sigma(u)$, $v' = \sigma(v)$. This maps arbitrary coordinates to (0,1) but compresses gradients near quadrant centers [S15]. Sigmoid scaling causes pixel gradients to approach zero near the center of a quadrant, leading to gradient vanishing during sharp color transitions and preventing perfect scene fitting [S15]. Bilinear interpolation is only effective when the spatial color pattern conforms to a four-quadrant distribution [S15]. Captures abrupt color transitions more effectively than tiny neural networks or movable kernels, but suffers from vanishing gradients in other regions, reducing overall expressiveness when multiple Gaussians are superimposed [S15].

### Ray-Texture UV Mapping and Interpolation
Computes UV coordinates for ray-Gaussian intersections to sample spatially varying colors from texture maps using bilinear interpolation [S16]. Cast a ray from the camera origin to find intersection point $p_i$ with the $i$-th Gaussian [S16]. Compute UV coordinates $u_i$ and $v_i$ using the tangent/bitangent vectors, intersection point, texel size, and texture dimensions [S16]. Sample the texture map $T_i$ at $(u_i, v_i)$ using bilinear interpolation to obtain color $c_{tex}$ [S16]. Formula: $u_i(p_i) = ((t_u)_i \cdot p_i) / T_{size} + (U_i - 1)/2$, where $(t_u)_i$ is the tangent vector of the $i$-th Gaussian, $p_i$ is the intersection point, $T_{size}$ is the texel size, and $U_i$ is the texture width [S16]. $v_i(p_i) = ((t_v)_i \cdot p_i) / T_{size} + (V_i - 1)/2$, where $(t_v)_i$ is the bitangent vector of the $i$-th Gaussian and $V_i$ is the texture height [S16].

### Pixel Level Data Dependent Interpolation
Scans the low-resolution source image X to initialize a 2D array $x_{mn}$, which records the edge direction of all four-pixel squares [S17, unofficial]. Scans the high-resolution target image Y to initialize a 2D array $y_{ij}$ [S17, unofficial]. Each $y_{ij}$ is inversely mapped to the sample image X [S17, unofficial]. Uses the array $x_{mn}$ to identify the triangle in which the inversely mapped point falls in the source image X [S17, unofficial]. Calculates the value of $y_{ij}$ using barycentric interpolation [S17, unofficial]. Detects outliers by comparing the difference $|a - c|$ and $|b - d|$ of four pixel values (represented as heights) [S17, unofficial]. The pair with the smaller difference is treated as an edge [S17, unofficial]. In experiments with stamens (original photo 75x75 pixels, morphed texture 2048x2048 pixels), pixel level data dependent interpolation preserved details better than bilinear interpolation [S17, unofficial]. Compared to bilinear interpolation, pixel level data dependent interpolation keeps edges sharp and smooth areas smooth, whereas bilinear interpolation may blur edges [S17, unofficial].

## Operating characteristics
*   **Time Complexity:** O(1) per query, as it involves a fixed number of arithmetic operations and memory accesses (4 samples) [S5].
*   **Memory Complexity:** O(1) auxiliary memory per query, assuming the grid is accessible [S5].
*   **Performance:** Fast and efficient, making it suitable for real-time applications [S5]. Hardware acceleration is often available via texture sampling units in GPUs [S9, unofficial].
*   **Strengths:** Simple to implement, computationally inexpensive, provides smoother results than nearest-neighbor interpolation [S5].
*   **Limitations:** Introduces blurring (low-pass filtering effect) due to its linear nature [S5]. Discontinuous gradients at cell boundaries can cause artifacts in high-frequency details [S5][S12, unofficial]. Not suitable for reconstructing signals with high curvature or sharp edges without additional processing [S5].
*   **When to use:** When computational efficiency is critical and high-frequency detail preservation is not the primary goal, such as in initial volume rendering passes or texture sampling [S5].
*   **When not to use:** When high-fidelity reconstruction of sharp edges or high-frequency details is required, or when C1 continuity is necessary [S5][S12, unofficial].

## Background
Bilinear interpolation is a fundamental technique in computer graphics and image processing, extending linear interpolation to two dimensions [S5]. It has been widely used for tasks such as image resizing, texture mapping, and sampling in volume rendering [S5]. The method is based on the tensor product of linear interpolation kernels [S5]. It is commonly implemented in hardware via texture units in GPUs [S9, unofficial].
