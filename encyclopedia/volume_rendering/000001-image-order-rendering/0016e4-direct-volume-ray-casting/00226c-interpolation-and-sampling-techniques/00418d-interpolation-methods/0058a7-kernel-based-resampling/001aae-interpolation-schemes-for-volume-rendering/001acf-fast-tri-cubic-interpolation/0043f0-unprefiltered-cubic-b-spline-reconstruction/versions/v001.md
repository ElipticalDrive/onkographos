# Unprefiltered Cubic B-Spline Reconstruction

Also called: Approximating Cububic B-Spline Reconstruction, Cubic B-spline reconstruction, Quasi-interpolating Cubic B-Spline, Standard Cubic B-Spline Filter, cubic Bspline, fourth order B-spline

## Overview
Unprefiltered Cubic B-Spline Reconstruction is an approximating reconstruction filter used to sample a continuous volume function from discrete voxel samples without prior deconvolution [S1, unofficial][S2]. It is classified as a 2-EF (Error Function of order 2) reconstruction, meaning it is quasi-interpolating of order 2 [S2]. Unlike interpolating methods such as [Cubic Interpolation (Mitchell-Netravali)](2073-cubic-interpolation-mitchell-netravali.md) or [Prefiltered Reconstruction](11114-prefiltered-reconstruction.md), this method does not pass through the original sample values; at a sample location, only 2/3 of the sample value contributes to the reconstructed result [S1, unofficial]. It is primarily chosen for its strong oversmoothing effect, which makes it suitable for reconstructing data corrupted by noise, rather than for high-fidelity detail reconstruction [S2].

## How it works
**Inputs and Outputs**
- Input: A 3D volume texture $V$ with discrete samples $f_k$ at integer grid positions.
- Output: A continuous approximation $\tilde{f}(t)$ evaluated at arbitrary texture coordinates $t$.

**Data Structures**
- The volume is stored as a 3D array of floating-point values.
- No auxiliary prefiltering data structures are used, distinguishing this from [Prefiltered Reconstruction](11114-prefiltered-reconstruction.md) which requires a deconvolved coefficient array [S2].

**The Filter Kernel**
The reconstruction relies on the 1D cubic B-spline basis function $\beta_3(t)$, defined piecewise by $|t|$ [S2]:

$$
\beta_3(t) = 
\begin{cases} 
\frac{1}{2}|t|^3 - |t|^2 + \frac{2}{3} & \text{if } |t| \le 1 \\
-\frac{1}{6}|t|^3 + \frac{1}{2}|t|^2 - |t| + \frac{2}{3} & \text{if } 1 < |t| \le 2 \\
0 & \text{otherwise}
\end{cases}
$$

Note: The source [S1, unofficial] provides an equivalent formulation for $x \ge 0$:
- For $0 \le x < 1$: $\frac{1}{4}(2x^3 - x^2 + 3)$
- For $1 \le x < 2$: $-\frac{1}{6}(x^3 - 3x^2 + 2x + 2)$
These are mathematically identical to the [S2] definition [S1, unofficial][S2].

**Reconstruction Formula**
The continuous function is reconstructed by convolving the samples with the tensor product of the 1D basis functions [S2]:

$$
\tilde{f}(t) = \sum_{k=-\infty}^{\infty} f_k \cdot \beta_3\left(\frac{t - k}{T}\right)
$$

Where:
- $t$ is the query position.
- $T$ is the sampling interval (typically 1 for normalized coordinates).
- $f_k$ is the voxel value at integer index $k$.

In 3D, this extends to a tri-cubic convolution over the $4 \times 4 \times 4$ neighborhood of the query point.

**Algorithm Steps**
1. Determine the integer grid coordinates $(i, j, k)$ surrounding the query point $(x, y, z)$.
2. Compute the fractional offsets $(\delta_x, \delta_y, \delta_z)$ where $\delta = x - i$.
3. For each dimension, identify the 4 relevant sample indices (e.g., $i-1, i, i+1, i+2$).
4. Evaluate the 1D basis function $\beta_3$ for each offset relative to the sample centers.
5. Compute the 64 weights as the tensor product of the 1D weights: $w_{u,v,w} = \beta_3(\delta_x + u) \cdot \beta_3(\delta_y + v) \cdot \beta_3(\delta_z + w)$.
6. Sum the products of the 64 neighboring voxel values and their corresponding weights.

**Pseudocode**
```python
def cubic_b_spline_1d(t):
    """
    Evaluates the 1D cubic B-spline basis function beta_3(t).
    t is the distance from the sample center.
    """
    abs_t = abs(t)
    if abs_t <= 1.0:
        return 0.5 * abs_t**3 - abs_t**2 + 2.0/3.0
    elif abs_t <= 2.0:
        return -1.0/6.0 * abs_t**3 + 0.5 * abs_t**2 - abs_t + 2.0/3.0
    else:
        return 0.0

def reconstruct_unprefiltered_cubic_bspline(volume, x, y, z):
    """
    Reconstructs the volume value at (x, y, z) using unprefiltered cubic B-splines.
    volume: 3D array of voxel values.
    x, y, z: float coordinates in the same scale as the volume grid.
    """
    # Determine integer base coordinates
    ix = int(floor(x))
    iy = int(floor(y))
    iz = int(floor(z))
    
    # Fractional offsets
    dx = x - ix
    dy = y - iy
    dz = z - iz
    
    result = 0.0
    
    # Iterate over the 4x4x4 neighborhood
    # The support of the cubic B-spline is [-2, 2], so we need indices 
    # from base-1 to base+2.
    for i in range(-1, 3):
        for j in range(-1, 3):
            for k in range(-1, 3):
                # Calculate distance from the sample center (ix+i, iy+j, iz+k)
                dist_x = dx - i
                dist_y = dy - j
                dist_z = dz - k
                
                # Get weight for this dimension
                w_x = cubic_b_spline_1d(dist_x)
                w_y = cubic_b_spline_1d(dist_y)
                w_z = cubic_b_spline_1d(dist_z)
                
                weight = w_x * w_y * w_z
                
                # Fetch voxel value (handle boundaries with clamp or zero)
                # [G] Boundary handling is implementation-specific; 
                # assuming volume access handles out-of-bounds gracefully.
                voxel_val = volume[ix + i, iy + j, iz + k]
                
                result += voxel_val * weight
                
    return result
```

**Parameters**
- No adjustable parameters. The filter is fixed as the standard cubic B-spline ($B=1, C=0$ in the general cubic-spline family) [S1, unofficial].

**Edge Cases and Pitfalls**
- **Non-Interpolating**: The filter value at $x=0$ is $2/3$, not $1$. The reconstructed value at a sample location is a weighted average of neighbors, not the sample value itself [S1, unofficial].
- **Oversmoothing**: Due to strong low-pass characteristics, high-frequency details are attenuated. It is not suitable for high-fidelity reconstruction where sharp features must be preserved [S2].
- **Computational Cost**: A naive implementation requires 64 texture fetches per sample. While acceleration techniques (e.g., Sigg and Hadwiger) can reduce this to 8 trilinear fetches using GPU linear filtering, the unprefiltered nature means the coefficients are not pre-computed into the texture [S2].
- **Derivative Continuity**: The filter has a continuous second-order derivative, allowing it to reconstruct straight lines accurately, a property shared with Catmull-Rom but not all cubic splines [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(1)$ per sample, but with a high constant factor (64 multiplications/additions) if implemented naively. Can be reduced to $O(1)$ with 8 fetches using hardware acceleration [S2].
- **Memory Complexity**: $O(1)$ auxiliary memory. No prefiltering coefficients are stored [S2].
- **Strengths**: Excellent noise reduction; continuous second derivative; reconstructs linear functions exactly [S1, unofficial][S2].
- **Limitations**: Significant blurring/oversmoothing; not interpolating; high attenuation of high frequencies makes it unsuitable for sharp detail [S1, unofficial][S2].
- **When to use**: When the input data is noisy and smoothness is preferred over sharpness [S2].
- **When not to use**: For high-fidelity visualization requiring sharp edges or accurate representation of sample values [S2].

## Background
The cubic B-spline is a member of the cubic-spline family defined by parameters $B=1$ and $C=0$ [S1, unofficial]. It is distinct from the Catmull-Rom spline, which is the only interpolating cubic-spline function that reconstructs straight lines ($B=0, C=1/2$) [S1, unofficial]. The unprefiltered version is classified as a 2-EF reconstruction, meaning it approximates the original signal with an error function of order 2 [S2]. Historically, higher-order B-splines are generally avoided in 3D volume rendering due to excessive high-frequency attenuation and computational cost [S1, unofficial].
