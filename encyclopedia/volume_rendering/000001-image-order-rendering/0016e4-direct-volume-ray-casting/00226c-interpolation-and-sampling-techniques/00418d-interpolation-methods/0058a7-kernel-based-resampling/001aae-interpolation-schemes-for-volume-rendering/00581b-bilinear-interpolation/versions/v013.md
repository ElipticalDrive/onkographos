# Bilinear Interpolation

Also called: Bilinear Lerp, 2D Linear Interpolation, Linear Bi-interpolation, Bi-interpolation linéaire

## Overview
Bilinear interpolation is a method for estimating the value of a function at a point within a two-dimensional rectangular grid by using the known values at the four surrounding corner points [S5]. It extends linear interpolation from one dimension to two by applying the process sequentially along each axis, resulting in a surface that is linear along any line parallel to the coordinate axes [S5]. In the context of volume rendering, it serves as a first-order reconstruction scheme (triangular filter) that provides $C^0$ continuity, distinguishing it from nearest-neighbor interpolation which exhibits noticeable artifacts [S2, unofficial][S3]. It is primarily used for sampling 2D textures, projecting 3D data onto 2D planes, or as a component in higher-dimensional schemes [S5][S7, unofficial][S16].

## How it works
**Inputs and Outputs:**
*   **Input:** A discrete 2D grid of values $V$ defined on integer coordinates $(x, y)$, and a query point $\mathbf{p} = (x, y)$ with real-valued coordinates.
*   **Output:** A scalar (or vector) value $f(x, y)$ estimated at $\mathbf{p}$.

**Data Structures:**
The input volume is typically stored as a 1D contiguous array of size $W \times H$ (width $\times$ height), where the element at grid coordinates $(x, y)$ is accessed at index $x \cdot H + y$ [S8, unofficial].

**Steps:**
1.  **Neighborhood Selection:** Identify the grid cell containing the query point $(x, y)$. The cell is bounded by integer corners $(x_0, y_0)$, $(x_1, y_0)$, $(x_0, y_1)$, and $(x_1, y_1)$, where $x_0 = \lfloor x \rfloor$, $x_1 = x_0 + 1$, $y_0 = \lfloor y \rfloor$, and $y_1 = y_0 + 1$ [S5][S7, unofficial].
2.  **Fractional Coordinate Calculation:** Compute the fractional distances from the lower-left corner:
    $$ t = x - x_0 $$
    $$ u = y - y_0 $$
    Here, $t$ and $u$ represent the relative position within the cell, ranging from 0 to 1 [S5][S8, unofficial].
3.  **Weight Calculation:** The weights for the four corners are determined by the tensor product of the 1D linear weights:
    *   $w_{00} = (1 - t)(1 - u)$
    *   $w_{10} = t(1 - u)$
    *   $w_{01} = (1 - t)u$
    *   $w_{11} = tu$
    These weights correspond to the corners $(x_0, y_0)$, $(x_1, y_0)$, $(x_0, y_1)$, and $(x_1, y_1)$ respectively [S5][S7, S8, unofficial].
4.  **Aggregation:** Compute the interpolated value using the weighted sum:
    $$ f(x, y) = w_{00} V_{00} + w_{10} V_{10} + w_{01} V_{01} + w_{11} V_{11} $$
    where $V_{ij} = V(x_i, y_j)$ [S5][S8, unofficial].

**Pseudocode:**
```python
def bilinear_interpolate(grid, width, height, x, y):
    # 1. Identify grid cell
    x0 = floor(x)
    y0 = floor(y)
    x1 = x0 + 1
    y1 = y0 + 1

    # 2. Handle boundary conditions (clamp or wrap)
    # Note: Standard bilinear interpolation assumes valid grid bounds.
    # If x or y are outside [0, width-1] or [0, height-1], 
    # behavior depends on implementation (e.g., clamping to edge values).
    if x0 < 0 or x1 >= width or y0 < 0 or y1 >= height:
        return 0.0 # Or handle boundary logic as per specific application [G]

    # 3. Calculate fractional parts
    t = x - x0
    u = y - y0

    # 4. Fetch neighbor values
    # Accessing 1D array: index = x * height + y
    v00 = grid[x0 * height + y0]
    v10 = grid[x1 * height + y0]
    v01 = grid[x0 * height + y1]
    v11 = grid[x1 * height + y1]

    # 5. Interpolate along x for fixed y0 and y1
    val0 = (1 - t) * v00 + t * v10
    val1 = (1 - t) * v01 + t * v11

    # 6. Interpolate along y between the two intermediate values
    result = (1 - u) * val0 + u * val1

    return result
```

**Parameters:**
*   **Grid Resolution:** $W \times H$.
*   **Coordinate System:** The fractional parts $t$ and $u$ are in the range $[0, 1)$. If coordinates are normalized to $[-1, 1]$ (as in some deep learning frameworks like PyTorch's `grid_sample`), they must be mapped to grid indices first [S4, S10, unofficial].
*   **Boundary Handling:** Not defined in the core method. Common implementations clamp to the nearest edge value or wrap around [S10, S8, unofficial].

**Edge Cases and Pitfalls:**
*   **Discontinuities:** Bilinear interpolation provides $C^0$ continuity, but the first derivatives (gradients) are discontinuous at the grid cell boundaries [S5][S12, unofficial].
*   **Negative Indices:** Implementations must handle negative coordinates. A common bug in naive wrapping implementations is using the wrong dimension for modulo operations (e.g., using height instead of width for x-wrapping) [S8, unofficial].
*   **Precision:** In differentiable rendering, half-precision arithmetic may require specific handling for gradient accumulation [S7, unofficial].

## Subtopics

### [Optimized Trilinear Reconstruction](2437-optimized-trilinear-reconstruction.md)
Optimized Trilinear Reconstruction accelerates the trilinear interpolation of volume data during direct volume ray casting by leveraging SIMD (Single Instruction, Multiple Data) processor extensions such as MMX, SSE, or 3DNow!. It improves memory copying and interpolation speed compared to scalar implementations.

### [Multi-Dimensional Interpolation Extension](2784-multi-dimensional-interpolation-extension.md)
This method extends one-dimensional reconstruction kernels to three dimensions for volume rendering. It constructs a 3D filter from a 1D base kernel $h'$ to correctly reconstruct signals on a regular 3D mesh, setting itself apart from radial extension methods by avoiding sample frequency ripple artifacts that occur with rotationally-symmetric kernels on regular grids.

### [POCS Interpolation Hardware Implementation](6377-pocs-interpolation-hardware-implementation.md)
A hardware architecture for implementing POCS interpolation filters in volume rendering, designed to overcome the quality limitations of standard tri-linear interpolation while remaining feasible within VLSI constraints. It distinguishes itself from Bilinear Interpolation by supporting larger kernel sizes ($3 \times 3 \times 3$ and $5 \times 5 \times 5$) using lookup tables and specialized memory banking to handle the high data throughput required for multi-voxel sampling.

### [View Adapted Stepping Distances](13215-view-adapted-stepping-distances.md)
View Adapted Stepping Distances is a volume rendering acceleration technique that aligns sample points with voxel cube faces to enable bilinear interpolation instead of trilinear interpolation, while using adaptive termination to skip empty space. It differs from its parent Bilinear Interpolation by dynamically calculating the stepping distance based on the view direction to enforce this alignment, and from Optimized Trilinear Reconstruction by reducing the number of neighbor lookups from 8 to 4.

### Linear Interpolation on Polyhedra
Uses linear interpolation to scan-convert the front and back faces of each polyhedron. Used for unstructured meshes [S12, unofficial]. Exhibits $C^1$ discontinuities common to linear interpolation [S12, unofficial]. Linear interpolation is used because reconstruction for non-uniform sampling on unstructured meshes is not well understood and is significantly more complex than uniform sampling [S12, unofficial].

### Temporal Interpolation
Linear interpolation between two sampled flow vectors of different time steps to handle dynamic vector fields [S13, unofficial]. Formula: $M_R(v, t) = (1 - t)S_i(v) + tS_j(v)$ where $S_i(v), S_j(v)$ are vector field slices [S13, unofficial]. If $k$ is not in $[i, j]$, the equation yields extrapolation instead of interpolation [S13, unofficial].

### Hat-shaped Basis Functions
A method using hat-shaped basis functions to define the interpolant, involving actual leaf cells only on the boundary to remove ghost artifacts [S14, unofficial]. It is unclear how to perform ray-isosurface intersections with this interpolant [S14, unofficial].

### SVGS Bilinear Interpolation
A spatially varying function that divides each Gaussian surfel into four quadrants using bilinear interpolation, assigning a learnable color and opacity value to each quadrant [S15]. Formula: $F_c(p) = (1-u')(1-v')c_0 + (1-u')v'c_1 + u'(1-v')c_2 + u'v'c_3$, where $c_{0..3}$ are learnable colors and $u', v'$ are normalized coordinates [S15]. Coordinates are rescaled via sigmoid: $u' = 1 / (1 + e^{-\lambda_s u})$, with $\lambda_s = 5.0$ [S15]. Each Gaussian stores 4 learnable colors and 4 learnable opacities [S15]. This design may cause gradient vanishing issues [S15].

### Bilinear Interpolation with Sigmoid Scaling
A spatial color variation function that uses bilinear interpolation to model intra-primitive color changes, scaled by a sigmoid function to handle coordinates outside the standard $(0,1)$ range [S15]. Coordinates $(u, v)$ are passed through a sigmoid function before bilinear sampling: $u' = \sigma(u), v' = \sigma(v)$. Sigmoid scaling causes pixel gradients to approach zero near the center of a quadrant, leading to gradient vanishing during sharp color transitions and preventing perfect scene fitting [S15]. Bilinear interpolation is only effective when the spatial color pattern conforms to a four-quadrant distribution [S15]. It captures abrupt color transitions more effectively than tiny neural networks or movable kernels, but suffers from vanishing gradients in other regions, reducing overall expressiveness when multiple Gaussians are superimposed [S15].

### Ray-Texture UV Mapping and Interpolation
Computes UV coordinates for ray-Gaussian intersections to sample spatially varying colors from texture maps using bilinear interpolation [S16]. Cast a ray from the camera origin to find intersection point $p_i$ with the $i$-th Gaussian [S16]. Compute UV coordinates $u_i$ and $v_i$ using the tangent/bitangent vectors, intersection point, texel size, and texture dimensions [S16]. Sample the texture map $T_i$ at $(u_i, v_i)$ using bilinear interpolation to obtain color $c_{tex}$ [S16]. Formula: $u_i(p_i) = ((t_u)_i \cdot p_i) / T_{size} + (U_i - 1)/2$, $v_i(p_i) = ((t_v)_i \cdot p_i) / T_{size} + (V_i - 1)/2$ [S16].

### Pixel Level Data Dependent Interpolation
Scans the low-resolution source image to initialize a 2D array recording edge directions, then uses barycentric interpolation on the high-resolution target image [S17, unofficial]. Detects outliers by comparing pixel value differences to treat pairs with smaller differences as edges [S17, unofficial]. Compared to bilinear interpolation, it keeps edges sharp and smooth areas smooth, whereas bilinear interpolation may blur edges [S17, unofficial]. In experiments with stamens (75x75 to 2048x2048), it preserved details better than bilinear interpolation [S17, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
The method requires constant time $O(1)$ per query point and constant memory $O(1)$ for the four neighbor values [S5].

**Measured Performance:**
Performance depends on hardware support for linear interpolation instructions (e.g., GPU texture units often implement bilinear filtering in hardware) [S9, unofficial]. In software, SIMD optimizations can significantly accelerate the process [S1].

**Scaling:**
Bilinear interpolation scales linearly with the number of query points. It is suitable for real-time rendering when hardware acceleration is available [S9, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Smooth transitions compared to nearest-neighbor; computationally inexpensive; $C^0$ continuous [S5].
*   **Limitations:** Discontinuous gradients at cell boundaries ($C^1$ discontinuity) [S5][S12, unofficial]; blurs high-frequency details more than higher-order methods [S17, unofficial]; not suitable for unstructured meshes without significant complexity [S12, unofficial].

**When to Use:**
Use when smooth visual appearance is required and computational resources are limited, or when implementing higher-order schemes that rely on 2D sub-steps [S5]. Avoid when gradient continuity is critical or when dealing with unstructured data [S12, unofficial].

## Background
Bilinear interpolation is a fundamental technique in computer graphics and image processing, extending 1D linear interpolation to 2D grids [S5]. It is widely used in direct volume ray casting for sampling texture coordinates and in differentiable rendering pipelines [S7, unofficial][S16]. The method is often implemented in hardware via texture sampling units [S9, unofficial].
