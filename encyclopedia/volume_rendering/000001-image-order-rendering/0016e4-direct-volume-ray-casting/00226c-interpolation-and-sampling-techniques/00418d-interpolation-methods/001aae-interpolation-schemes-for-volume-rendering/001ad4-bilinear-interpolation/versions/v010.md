# Bilinear Interpolation

Also called: Bi-interpolation linéaire, Bi-linear Interpolation for Triangle Coloring, Bilinear Interpolation for Primitive Sampling, Bilinear Sampling, F RBiLin, Linear Bi-interpolation

## Overview
Bilinear interpolation is a reconstruction scheme that estimates values at arbitrary 2D coordinates by performing linear interpolation in both spatial dimensions. It solves the problem of sampling discrete grid data (such as textures, scalar fields, or feature maps) at non-integer positions, providing a smoother result than nearest-neighbor interpolation while remaining computationally inexpensive. It sets itself apart from [Trilinear Interpolation](1531-trilinear-interpolation.md) by operating on 2D planes rather than 3D volumes, and from [Frequency Domain Volume Rendering with Sinc Resampling](826-frequency-domain-volume-rendering-with-sinc-resampling.md) by using a local linear kernel rather than a global sinc function, trading frequency accuracy for speed.

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D grid of values $V$ of size $H \times W$ (or $C \times H \times W$ for multi-channel data), and a query coordinate $\mathbf{p} = (u, v)$ in the continuous domain.
*   **Output:** The interpolated scalar or vector value $V(\mathbf{p})$.

**Data Structures:**
The grid is typically stored as a contiguous 1D array or a 2D array. For a grid of width $W$ and height $H$, the element at integer coordinates $(x, y)$ where $0 \le x < W$ and $0 \le y < H$ is accessed at index $x \cdot H + y$ (row-major) or $y \cdot W + x$ (column-major), depending on the implementation [S7, unofficial].

**Steps:**
1.  **Coordinate Normalization:** If the input grid uses a specific coordinate system (e.g., $[-1, 1]$ or $[0, 1]$), map the query coordinate $\mathbf{p}$ to the grid's index space. If using `align_corners=True` (common in deep learning frameworks), the corners of the grid correspond to the query bounds [S4, unofficial][S9, unofficial].
2.  **Integer and Fractional Decomposition:**
    *   Compute the integer coordinates of the top-left neighbor: $x_0 = \lfloor u \rfloor$, $y_0 = \lfloor v \rfloor$.
    *   Compute the fractional offsets: $d_x = u - x_0$, $d_y = v - y_0$.
    *   Note: $d_x, d_y \in [0, 1)$.
3.  **Boundary Handling:** Clamp $x_0, y_0$ to the valid range $[0, W-1]$ and $[0, H-1]$. If the query point lies outside the grid, use a padding mode (e.g., zeros, border replication) [S9, unofficial].
4.  **Neighbor Fetching:** Retrieve the four nearest grid values:
    *   $V_{00} = V(x_0, y_0)$
    *   $V_{10} = V(x_0 + 1, y_0)$
    *   $V_{01} = V(x_0, y_0 + 1)$
    *   $V_{11} = V(x_0 + 1, y_0 + 1)$
5.  **Interpolation:** Compute the weighted sum.

**Formula:**
The interpolated value is calculated as:
$$
V(u, v) = V_{00}(1 - d_x)(1 - d_y) + V_{10}d_x(1 - d_y) + V_{01}(1 - d_x)d_y + V_{11}d_x d_y
$$
where $V_{00}=Grid(x_0,y_0)$, $V_{10}=Grid(x_0+1,y_0)$, $V_{01}=Grid(x_0,y_0+1)$, $V_{11}=Grid(x_0+1,y_0+1)$, $d_x=u-x_0$, $d_y=v-y_0$ [S7, unofficial].

Alternatively, using vector notation for the weights $\mathbf{w}$ and values $\mathbf{p}$:
$$
\mathbf{w} = \begin{bmatrix} (1-d_x)(1-d_y) \\ d_x(1-d_y) \\ (1-d_x)d_y \\ d_x d_y \end{bmatrix}, \quad \mathbf{p} = \begin{bmatrix} V_{00} \\ V_{10} \\ V_{01} \\ V_{11} \end{bmatrix}
$$
$$
V(u, v) = \mathbf{w}^T \mathbf{p} = \sum_{j=0}^{3} w_j p_j
$$
[S6, unofficial].

**Parameters:**
*   `align_corners`: Boolean. If true, the grid corners are aligned with the query bounds $[-1, 1]$ or $[0, 1]$. If false, the grid centers are aligned [S4, unofficial][S9, unofficial].
*   `padding_mode`: String. "zeros", "border", or "reflection" [S9, unofficial].

**Pseudocode:**
```python
def bilinear_interpolate(grid, u, v, align_corners=True, padding_mode="zeros"):
    """
    grid: 2D array of shape (H, W) or (C, H, W).
    u, v: float coordinates.
    Returns interpolated value(s).
    """
    H, W = grid.shape[-2], grid.shape[-1]
    
    # 1. Coordinate Transformation
    if align_corners:
        # Map [0, 1] query space to [0, H-1] / [0, W-1] index space
        # Assuming u, v are in [0, 1]
        idx_u = u * (W - 1)
        idx_v = v * (H - 1)
    else:
        # Map [0, 1] query space to [-0.5, H-0.5] / [-0.5, W-0.5] index space
        idx_u = u * W - 0.5
        idx_v = v * H - 0.5
        
    # 2. Integer and Fractional Decomposition
    x0 = int(idx_u)
    y0 = int(idx_v)
    dx = idx_u - x0
    dy = idx_v - y0
    
    # 3. Boundary Handling
    # Clamp coordinates to valid range [0, W-1] and [0, H-1]
    if padding_mode == "zeros":
        if x0 < 0 or x0 >= W - 1 or y0 < 0 or y0 >= H - 1:
            return 0.0 # Or appropriate padding value
    
    x0 = max(0, min(x0, W - 2))
    y0 = max(0, min(y0, H - 2))
    
    # 4. Neighbor Fetching
    # Assuming grid is (H, W) for simplicity; handle channels if needed
    v00 = grid[y0, x0]
    v10 = grid[y0, x0 + 1]
    v01 = grid[y0 + 1, x0]
    v11 = grid[y0 + 1, x0 + 1]
    
    # 5. Interpolation
    # Weights
    w00 = (1 - dx) * (1 - dy)
    w10 = dx * (1 - dy)
    w01 = (1 - dx) * dy
    w11 = dx * dy
    
    result = w00 * v00 + w10 * v10 + w01 * v01 + w11 * v11
    
    return result
```

## Subtopics

### [Optimized Trilinear Reconstruction](2437-optimized-trilinear-reconstruction.md)
Optimized Trilinear Reconstruction is a method for accelerating the trilinear interpolation of volume data during direct volume ray casting by leveraging SIMD (Single Instruction, Multiple Data) processor extensions such as MMX, SSE, or 3DNow!. It improves memory copying and interpolation speed compared to scalar implementations.

### [Multi-Dimensional Interpolation Extension](2784-multi-dimensional-interpolation-extension.md)
This method extends one-dimensional reconstruction kernels to three dimensions for volume rendering. It constructs a 3D filter from a 1D base kernel $h'$ to correctly reconstruct signals on a regular 3D mesh, setting itself apart from radial extension methods by avoiding sample frequency ripple artifacts that occur with rotationally-symmetric kernels on regular grids.

### [POCS Interpolation Hardware Implementation](6377-pocs-interpolation-hardware-implementation.md)
A hardware architecture for implementing POCS interpolation filters in volume rendering, designed to overcome the quality limitations of standard tri-linear interpolation while remaining feasible within VLSI constraints. It distinguishes itself from [Bilinear Interpolation](858-bilinear-interpolation.md) by supporting larger kernel sizes ($3 \times 3 \times 3$ and $5 \times 5 \times 5$) using lookup tables and specialized memory banking to handle the high data throughput required for multi-voxel sampling.

### [View Adapted Stepping Distances](13215-view-adapted-stepping-distances.md)
View Adapted Stepping Distances is a volume rendering acceleration technique that aligns sample points with voxel cube faces to enable bilinear interpolation instead of trilinear interpolation, while using adaptive termination to skip empty space. It differs from its parent [Bilinear Interpolation](858-bilinear-interpolation.md) by dynamically calculating the stepping distance based on the view direction to enforce this alignment, and from [Optimized Trilinear Reconstruction](2437-optimized-trilinear-reconstruction.md) by reducing the number of neighbor lookups from 8 to 4.

### Linear Interpolation on Polyhedra
Uses linear interpolation to scan-convert the front and back faces of each polyhedron. Used for unstructured meshes [S11, unofficial]. Exhibits C1 discontinuities common to linear interpolation [S11, unofficial]. Linear interpolation is used because reconstruction for non-uniform sampling on unstructured meshes is not well understood and is significantly more complex than uniform sampling [S11, unofficial].

### Temporal Interpolation
Linear interpolation between two sampled flow vectors of different time steps to handle dynamic vector fields [S12, unofficial]. The interpolated vector is $M_R(v, t) = (1 - t)S_i(v) + tS_j(v)$ where $S_i(v), S_j(v)$ are vector field slices [S12, unofficial]. If $k$ is not in $[i, j]$, the equation yields extrapolation instead of interpolation [S12, unofficial].

### Hat-shaped Basis Functions
A method using hat-shaped basis functions to define the interpolant, involving actual leaf cells only on the boundary to remove ghost artifacts [S13, unofficial]. It is unclear how to perform ray-isosurface intersections with this interpolant [S13, unofficial].

### SVGS Bilinear Interpolation
A spatially varying function that divides each Gaussian surfel into four quadrants using bilinear interpolation, assigning a learnable color and opacity value to each quadrant [S14]. The color function is $F_c(p) = (1-u')(1-v')c_0 + (1-u')v'c_1 + u'(1-v')c_2 + u'v'c_3$, and opacity is $F_\alpha(p) = (1-u')(1-v')\alpha_0 + (1-u')v'\alpha_1 + u'(1-v')\alpha_2 + u'v'\alpha_3$, where $c_i, \alpha_i$ are learnable parameters and $u', v'$ are normalized coordinates [S14]. Coordinates are rescaled via sigmoid $u' = \frac{1}{1 + e^{-\lambda_s u}}$ with $\lambda_s = 5.0$ [S14]. This design may cause gradient vanishing issues [S14].

### Bilinear Interpolation with Sigmoid Scaling
A spatial color variation function that uses bilinear interpolation to model intra-primitive color changes, scaled by a sigmoid function to handle coordinates outside the standard (0,1) range [S14]. Coordinates $(u, v)$ are passed through a sigmoid function before bilinear sampling: $u' = \sigma(u), v' = \sigma(v)$. Sigmoid scaling causes pixel gradients to approach zero near the center of a quadrant, leading to gradient vanishing during sharp color transitions and preventing perfect scene fitting [S14]. Bilinear interpolation is only effective when the spatial color pattern conforms to a four-quadrant distribution [S14]. It captures abrupt color transitions more effectively than tiny neural networks or movable kernels, but suffers from vanishing gradients in other regions, reducing overall expressiveness when multiple Gaussians are superimposed [S14].

### Ray-Texture UV Mapping and Interpolation
Computes UV coordinates for ray-Gaussian intersections to sample spatially varying colors from texture maps using bilinear interpolation [S15]. Cast a ray from the camera origin to find intersection point $p_i$ with the $i$-th Gaussian. Compute UV coordinates $u_i$ and $v_i$ using the tangent/bitangent vectors, intersection point, texel size, and texture dimensions. Sample the texture map $T_i$ at $(u_i, v_i)$ using bilinear interpolation to obtain color $c_{tex}$ [S15]. The UV coordinates are computed as $u_i(p_i) = \frac{(t_u)_i \cdot p_i}{T_{size}} + \frac{U_i - 1}{2}$ and $v_i(p_i) = \frac{(t_v)_i \cdot p_i}{T_{size}} + \frac{V_i - 1}{2}$, where $(t_u)_i$ is the tangent vector, $(t_v)_i$ is the bitangent vector, $T_{size}$ is the texel size, and $U_i, V_i$ are texture dimensions [S15].

### Pixel Level Data Dependent Interpolation
Scans the low-resolution source image X to initialize a 2D array $x_{mn}$ recording edge directions. Scans the high-resolution target image Y to initialize $y_{ij}$, inversely mapping to X. Uses $x_{mn}$ to identify the triangle in which the inversely mapped point falls in X. Calculates $y_{ij}$ using barycentric interpolation. Detects outliers by comparing differences of four pixel values. Compared to bilinear interpolation, pixel level data dependent interpolation keeps edges sharp and smooth areas smooth, whereas bilinear interpolation may blur edges [S16, unofficial]. In experiments with stamens (75x75 to 2048x2048), it preserved details better than bilinear interpolation [S16, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample, as it requires exactly four memory accesses and four multiplications/additions.
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Performance:** Extremely fast, often hardware-accelerated in GPUs via texture sampling units (e.g., `texture2D` with linear filtering) [S8, unofficial].
*   **Strengths:** Low computational cost, smooth results compared to nearest-neighbor, differentiable (useful for gradient-based optimization in neural rendering) [S6, unofficial][S9, unofficial].
*   **Limitations:** Introduces blurring (low-pass filtering), which can alias high-frequency details. Not suitable for reconstructing signals with frequencies above the Nyquist limit without pre-filtering. C1 discontinuities can occur at grid boundaries in some implementations [S11, unofficial].
*   **When to use:** When performance is critical and the signal is band-limited or the resolution is high enough that blurring is acceptable. Common in texture mapping, feature extraction in CNNs, and basic volume rendering.
*   **When not to use:** When sharp edges must be preserved (use nearest-neighbor or edge-aware methods) or when high-fidelity reconstruction of high-frequency content is required (use cubic or sinc interpolation).

## Background
Bilinear interpolation is a fundamental technique in computer graphics and image processing. It was widely used in early volume rendering systems for sampling scalar fields on regular grids [S5, unofficial]. In the context of differentiable rendering, it has become a standard operation for back-propagating gradients through sampling layers [S6, unofficial][S9, unofficial]. It is also used in Fourier space reconstruction for tomography, where it retrieves values from polar grids to Cartesian grids [S10, unofficial].
