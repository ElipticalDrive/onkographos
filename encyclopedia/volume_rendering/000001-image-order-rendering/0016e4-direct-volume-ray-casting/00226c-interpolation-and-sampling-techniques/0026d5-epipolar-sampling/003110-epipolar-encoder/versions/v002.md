# Epipolar Encoder


## Overview
The Epipolar Encoder is a two-view (or multi-view) neural module that resolves scale ambiguity in 3D reconstruction by aggregating cross-view features along epipolar lines [S1]. It solves the problem where camera poses are scaled by an arbitrary factor $s_i$, preventing the inference of metric depth from a single view [S1]. Unlike standard volume rendering which samples along a ray, this method samples features from a reference pixel and correlates them with features sampled along the corresponding epipolar line in a second view, augmented with positionally encoded depths [S1]. This allows the encoder to memorize the correct depth consistent with the scene's arbitrary scale, which is then used for subsequent Gaussian parameter prediction [S1].

## How it works
The method operates on a pair of reference views, denoted as $I$ (reference) and $\tilde{I}$ (secondary), though it extends to $N$ views [S1]. The core mechanism is epipolar cross-attention, which aligns features from $I$ with potential correspondences in $\tilde{I}$ using geometric depth constraints [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Reference image $I$ and secondary image $\tilde{I}$ [S1].
    *   Camera poses for $I$ and $\tilde{I}$ (extrinsics $E, \tilde{E}$ and intrinsics $K, \tilde{K}$) [S1].
    *   Feature volumes $\mathbf{F}$ and $\tilde{\mathbf{F}}$ of shape $(H, W, C)$, where $H, W$ are image dimensions and $C$ is the feature dimension [S1]. These are produced by a per-image feature encoder applied to $I$ and $\tilde{I}$ separately [S1].
*   **Outputs:**
    *   Updated feature volume $\mathbf{F}'$ of shape $(H, W, C)$, where each pixel $\mathbf{F}'[\mathbf{u}]$ contains aggregated cross-view information and encoded depth consistent with the scene scale [S1].

### Data Structures
*   **Feature Volumes:** $\mathbf{F}, \tilde{\mathbf{F}} \in \mathbb{R}^{H \times W \times C}$ [S1].
*   **Embedding Matrices:** $\mathbf{Q}, \mathbf{K}, \mathbf{V} \in \mathbb{R}^{C \times C_{head}}$ [S1]. These are learnable linear projection matrices [G].
*   **Positional Encoding:** $\gamma: \mathbb{R} \to \mathbb{R}^{C_{enc}}$ [S1]. A standard positional encoding function (e.g., sine/cosine or learned) mapping a scalar depth to a vector [G].
*   **Per-Image Embeddings:** $\mathbf{e}_i \in \mathbb{R}^{C_{emb}}$ for each view $i$ (used in multi-view variant) [S1].

### Numbered Steps
1.  **Per-Image Encoding:** Encode each input view into a feature volume [S1].
    $$ \mathbf{F} = \text{Encoder}(I), \quad \tilde{\mathbf{F}} = \text{Encoder}(\tilde{I}) $$
2.  **Epipolar Line Computation:** For each pixel $\mathbf{u} = (u_x, u_y)$ in $I$, compute the epipolar line $\ell$ in $\tilde{I}$ induced by $\mathbf{u}$'s camera ray [S1].
3.  **Epipolar Sampling:** Sample pixel coordinates $\{\tilde{\mathbf{u}}_l\}$ along the epipolar line $\ell$ in $\tilde{I}$ [S1].
4.  **Depth Triangulation:** For each sample $\tilde{\mathbf{u}}_l$, compute the distance $\tilde{d}_{\tilde{\mathbf{u}}_l}$ from the sample to $I$'s camera origin by triangulating $\mathbf{u}$ and $\tilde{\mathbf{u}}_l$ [S1].
5.  **Feature Augmentation:** For each sample $\tilde{\mathbf{u}}_l$, create an augmented feature vector $\mathbf{s}$ [S1]:
    $$ \mathbf{s} = \tilde{\mathbf{F}}[\tilde{\mathbf{u}}_l] \oplus \gamma(\tilde{d}_{\tilde{\mathbf{u}}_l}) $$
    where $\oplus$ denotes concatenation [S1].
6.  **Attention Projection:** Compute query, key, and value vectors for the epipolar attention [S1]:
    $$ \mathbf{q} = \mathbf{Q} \cdot \mathbf{F}[\mathbf{u}], \quad \mathbf{k}_l = \mathbf{K} \cdot \mathbf{s}, \quad \mathbf{v}_l = \mathbf{V} \cdot \mathbf{s} $$
7.  **Epipolar Cross-Attention:** Update the feature $\mathbf{F}[\mathbf{u}]$ using softmax attention over the epipolar samples [S1]:
    $$ \mathbf{F}[\mathbf{u}] \leftarrow \mathbf{F}[\mathbf{u}] + \text{Att}(\mathbf{q}, \{\mathbf{k}_l\}, \{\mathbf{v}_l\}) $$
    where $\text{Att}$ denotes softmax attention and $+$ denotes a skip connection [S1].
8.  **Per-Image Self-Attention:** Apply a self-attention layer to the entire feature volume $\mathbf{F}$ [S1]:
    $$ \mathbf{F} \leftarrow \mathbf{F} + \text{SelfAttention}(\mathbf{F}) $$

### Pseudocode
```python
import torch
import torch.nn as nn
import torch.nn.functional as F
import math

class PositionalEncoding(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.dim = dim
    def forward(self, d):
        # d: (B, N, L) scalar depths
        div_term = torch.exp(torch.arange(0, self.dim, 2, dtype=torch.float).log() * -(math.log(10000.0) / self.dim))
        pe = torch.zeros_like(d).unsqueeze(-1)
        pe[..., 0::2] = torch.sin(d.unsqueeze(-1) * div_term)
        pe[..., 1::2] = torch.cos(d.unsqueeze(-1) * div_term)
        return pe

def get_pixel_coordinates(H, W, device):
    y, x = torch.meshgrid(torch.arange(H, device=device), torch.arange(W, device=device), indexing='ij')
    return torch.stack([x.float(), y.float()], dim=-1)

def compute_epipolar_lines(u_coords, pose_I, pose_tilde, K, K_tilde):
    # u_coords: (B, N, 2)
    u_hom = torch.cat([u_coords, torch.ones_like(u_coords[..., :1])], dim=-1) # (B, N, 3)
    R_I, t_I = pose_I[:, :, :3, :3], pose_I[:, :, :3, 3]
    R_t, t_t = pose_tilde[:, :, :3, :3], pose_tilde[:, :, :3, 3]
    # Essential matrix E = [t_t]_x * R_t * R_I^T
    def skew(v):
        x, y, z = v.unbind(dim=-1)
        return torch.stack([torch.zeros_like(x), -z, y, z, torch.zeros_like(x), -x, -y, x, torch.zeros_like(x)], dim=-1).view(v.shape[0], 3, 3)
    E = torch.bmm(skew(t_t), torch.bmm(R_t, R_I.transpose(1, 2)))
    # Fundamental matrix F = K_tilde^-T * E * K^-1
    F_mat = torch.bmm(torch.inverse(K_tilde).transpose(1, 2), torch.bmm(E, torch.inverse(K)))
    # Epipolar lines l_tilde = F * u_hom
    l_tilde = torch.bmm(F_mat, u_hom.transpose(1, 2)).transpose(1, 2) # (B, N, 3)
    return l_tilde

def sample_line_points(l, H, W, L):
    # l: (B, N, 3) line coefficients (a, b, c)
    ys = torch.linspace(0, H, L, device=l.device).unsqueeze(0).unsqueeze(0).expand(l.shape[0], l.shape[1], -1)
    xs = (-l[:, :, 1:2] * ys - l[:, :, 2:3]) / (l[:, :, 0:1] + 1e-8)
    xs = torch.clamp(xs, 0, W - 1)
    ys = torch.clamp(ys, 0, H - 1)
    return torch.stack([xs, ys], dim=-1) # (B, N, L, 2)

def triangulate_depths(u_coords, u_tilde_samples, pose_I, pose_tilde, K, K_tilde):
    # u_coords: (B, N, 2), u_tilde_samples: (B, N, L, 2)
    # Unproject to rays in camera frames
    def unproject(u, K):
        u_hom = torch.cat([u, torch.ones_like(u[..., :1])], dim=-1)
        rays = torch.bmm(u_hom.unsqueeze(1), torch.inverse(K).unsqueeze(0)).squeeze(1)
        return F.normalize(rays, dim=-1)
    r_I = unproject(u_coords, K) # (B, N, 3)
    r_t = unproject(u_tilde_samples, K_tilde) # (B, N, L, 3)
    
    # Transform to world frame
    R_I, t_I = pose_I[:, :, :3, :3], pose_I[:, :, :3, 3]
    R_t, t_t = pose_tilde[:, :, :3, :3], pose_tilde[:, :, :3, 3]
    O_I = -torch.bmm(R_I.transpose(1, 2), t_I.unsqueeze(2)).squeeze(2).unsqueeze(1).expand(-1, r_I.shape[1], -1)
    D_I = torch.bmm(R_I.transpose(1, 2), r_I.transpose(1, 2)).transpose(1, 2)
    O_t = -torch.bmm(R_t.transpose(1, 2), t_t.unsqueeze(2)).squeeze(2).unsqueeze(1).unsqueeze(2).expand(-1, r_t.shape[1], r_t.shape[2], -1)
    D_t = torch.bmm(R_t.transpose(1, 2), r_t.transpose(2, 3)).transpose(2, 3)
    
    # Triangulation: solve for depth d_I along D_I
    diff = O_t - O_I.unsqueeze(2) # (B, N, L, 3)
    cross_prod = torch.cross(D_I.unsqueeze(2), D_t, dim=3) # (B, N, L, 3)
    cross_prod_sq = torch.sum(cross_prod ** 2, dim=3, keepdim=True) + 1e-8
    numerator = torch.sum(diff * cross_prod, dim=3, keepdim=True)
    depths = numerator.squeeze(3) / cross_prod_sq.squeeze(3) # (B, N, L)
    return depths

def sample_features_at_coords(F, coords, H, W):
    # F: (B, H, W, C), coords: (B, N, L, 2) in [0, W]x[0, H]
    F_perm = F.permute(0, 3, 1, 2) # (B, C, H, W)
    x = coords[..., 0] / (W - 1) * 2 - 1
    y = coords[..., 1] / (H - 1) * 2 - 1
    grid = torch.stack([x, y], dim=-1) # (B, N, L, 2)
    B, N, L, _ = coords.shape
    sampled = F.grid_sample(F_perm.view(B*N, F_perm.shape[1], H, W), grid.view(B*N, L, 1, 2), align_corners=True) # (B*N, C, L, 1)
    return sampled.view(B, N, L, F.shape[-1])

class EpipolarEncoder(nn.Module):
    def __init__(self, feature_dim, head_dim=64, num_heads=8, num_samples=64):
        super().__init__()
        self.num_samples = num_samples
        self.num_heads = num_heads
        self.head_dim = head_dim
        self.q_proj = nn.Linear(feature_dim, num_heads * head_dim)
        self.k_proj = nn.Linear(feature_dim + 64, num_heads * head_dim)
        self.v_proj = nn.Linear(feature_dim + 64, num_heads * head_dim)
        self.self_attn = nn.MultiheadAttention(feature_dim, num_heads, batch_first=True)
        self.pos_enc = PositionalEncoding(64)

    def forward(self, F, F_tilde, pose_I, pose_tilde, K, K_tilde, H, W):
        B, H, W, C = F.shape
        u_coords = get_pixel_coordinates(H, W, F.device)
        u_coords_flat = u_coords.view(1, 1, H*W, 2).expand(B, -1, -1, -1)
        
        l_tilde = compute_epipolar_lines(u_coords_flat, pose_I, pose_tilde, K, K_tilde)
        u_tilde_samples = sample_line_points(l_tilde, H, W, self.num_samples)
        depths = triangulate_depths(u_coords_flat, u_tilde_samples, pose_I, pose_tilde, K, K_tilde)
        
        F_tilde_samples = sample_features_at_coords(F_tilde, u_tilde_samples, H, W)
        depth_enc = self.pos_enc(depths)
        s = torch.cat([F_tilde_samples, depth_enc], dim=-1)
        
        q = self.q_proj(F.view(B, -1, C))
        k = self.k_proj(s)
        v = self.v_proj(s)
        
        q = q.view(B, H*W, self.num_heads, self.head_dim).transpose(1, 2)
        k = k.view(B, H*W, self.num_samples, self.num_heads, self.head_dim).transpose(1, 3).transpose(2, 3)
        v = v.view(B, H*W, self.num_samples, self.num_heads, self.head_dim).transpose(1, 3).transpose(2, 3)
        
        attn_weights = F.softmax(torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(self.head_dim), dim=-1)
        attn_output = torch.matmul(attn_weights, v)
        
        attn_output = attn_output.transpose(1, 2).view(B, H*W, self.num_heads * self.head_dim)
        F_flat = F.view(B, -1, C)
        F_updated_flat = F_flat + attn_output
        F_updated = F_updated_flat.view(B, H, W, C)
        
        F_self_input = F_updated.view(B, H*W, C)
        F_self_out, _ = self.self_attn(F_self_input, F_self_input, F_self_input)
        F_final = F_updated + F_self_out
        F_final = F_final.view(B, H, W, C)
        
        return F_final
```

### Parameters
*   **Number of samples ($L$):** Typically 64 [S1].
*   **Feature dimension ($C$):** Depends on the backbone (e.g., 256, 512) [G].
*   **Head dimension ($C_{head}$):** Typically 64 [G].
*   **Positional Encoding:** Standard sine/cosine or learned [S1].

### Edge Cases and Pitfalls
*   **Missing Correspondences:** Pixels in $I$ that have no match in $\tilde{I}$ (occlusions, boundaries) will have no valid epipolar samples [S1]. The per-image self-attention layer propagates depth estimates from neighboring pixels to these regions [S1].
*   **Triangulation Instability:** If the rays from $I$ and $\tilde{I}$ are nearly parallel, the triangulation depth $\tilde{d}_{\tilde{\mathbf{u}}_l}$ becomes noisy [G]. This is mitigated by the attention mechanism, which learns to down-weight unreliable samples [G].
*   **Scale Ambiguity:** Without the positional encoding of depth, the encoder cannot resolve the arbitrary scale factor $s_i$ [S1]. The depth augmentation is critical [S1].

## Subtopics

### Epipolar Transformer (for Scale Ambiguity)
A multi-view encoder component that resolves scale ambiguity by finding cross-view pixel correspondences and associating them with positionally encoded depth values, allowing the inference of the per-scene scale factor $s_i$ [S1]. It compares features belonging to a ray's corresponding pixel on one view with features sampled along the epipolar line on the other view [S1]. Epipolar samples are augmented with their positionally-encoded depths along the ray [S1]. Recorded depths are later used for depth prediction [S1].

### Multi-View Epipolar Encoder
Extends the epipolar encoder from pairs to an arbitrary number of reference views by taking epipolar samples from any number of images and using their union [S1]. For a given pixel coordinate, epipolar samples are taken from any number of images [S1]. The union of these samples is used in place of a single epipolar line's samples [S1]. A learnable per-image embedding is added to each sampled feature to allow the epipolar transformer to distinguish between samples taken from different views [S1].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot L \cdot C^2)$ per pixel for the cross-attention, where $N$ is the number of pixels, $L$ is the number of epipolar samples, and $C$ is the feature dimension [G]. The self-attention layer adds $O(N^2 \cdot C)$ if applied globally, but is typically applied per-image with linear complexity or reduced heads [G].
*   **Memory Complexity:** $O(N \cdot L \cdot C)$ to store the epipolar samples and intermediate features [G].
*   **Performance:** In 3-view settings, PSNR improves from 26.09 to 28.31 on the Real Estate 10k dataset, with SSIM improving from 0.863 to 0.908 [S1].
*   **Strengths:** Resolves scale ambiguity without explicit depth supervision; leverages geometric constraints for robust feature aggregation [S1].
*   **Limitations:** Requires accurate camera poses; performance degrades if epipolar geometry is incorrect; self-attention may blur details in textureless regions [G].

## Background
The Epipolar Encoder was introduced in "PixelSplat: 3D Gaussian Splats from Image Pairs for Scalable Generalizable 3D Reconstruction" (CVPR 2024) [S1]. It addresses the limitation of diffusion models that rescale 3D scenes according to heuristics on depth statistics [S1]. By using an epipolar transformer, the method infers the scene scale directly from cross-view correspondences [S1]. It builds on the concept of epipolar attention [16] and is used in conjunction with 3D Gaussian Splatting [19] for novel view synthesis [S1].
