# Weighted Lookup Table Computation

Also called: Back-weighted lookup tables, Front-weighted lookup tables

## Overview
Weighted Lookup Table Computation is a method for generating pre-integrated lookup tables that incorporate lighting effects (diffuse and specular) by applying spatially varying scaling functions (ramps) to transfer function colors during integration [S1]. It solves the problem that standard pre-integration assumes uniform lighting across a voxel interval, whereas weighted tables allow the lighting contribution to vary linearly from the front to the back of the interval [S1]. Unlike standard pre-integration, where the lookup table entry depends only on the opacity values at the endpoints, weighted tables depend on the integration range $(i, j)$ [S1]. This dependency is resolved by computing three intermediate tables and combining them, allowing the method to run in $O(n^2)$ time, matching the complexity of standard pre-integration [S1].

## How it works
**Inputs:**
- Transfer function size $n_t$ (number of bins).
- Pre-integration table size $n \times n$, where $n = n_t / n_r$ and $n_r$ is the number of samples per bin [S1].
- Opacity values $\alpha_k$ and color values $C_k$ for each transfer function sample $k \in [0, n_t-1]$ [S1].

**Outputs:**
- Three intermediate lookup tables:
  1. $C^1$: Standard pre-integrated lookup table (unweighted).
  2. $C^G_{front}$: Table computed with a global ramp weighting function increasing from front to back (index $k$).
  3. $C^G_{back}$: Table computed with a global ramp weighting function decreasing from front to back (index $n_t - 1 - k$) [S1].
- Final weighted lookup tables $C^W$ derived from the intermediates [S1].

**Data Structures:**
- The lookup tables are 2D arrays of size $n \times n$. Each entry $(i, j)$ stores a 3D color vector $(r, g, b)$ [S1].
- Intermediate tables store the same format but represent integrals with modified color weights [S1].

**Steps:**
1. **Compute Standard Table ($C^1$):**
   Run the standard incremental subrange integration algorithm [Parent] on the original transfer function colors $C_k$ to populate $C^1$. This represents the unweighted pre-integrated color [S1].

2. **Compute Globally Ramped Tables ($C^G$):**
   - Create a modified transfer function where each color $C_k$ is multiplied by its index $k$ (for front-weighted) or $n_t - 1 - k$ (for back-weighted). Note that opacity $\alpha_k$ remains unchanged [S1].
   - Run the standard incremental subrange integration algorithm on these modified colors to populate $C^G_{front}$ and $C^G_{back}$ respectively [S1].

3. **Compute Final Weighted Tables ($C^W$):**
   For each entry $(i, j)$ in the lookup table where $i < j$:
   - Calculate the weighted color using the formula:
     $$C_{i \rightarrow j}^W = \frac{C_{i \rightarrow j}^G - i C_{i \rightarrow j}^1}{j - i}$$
     where $C_{i \rightarrow j}^G$ is the value from the appropriate globally ramped table ($C^G_{front}$ or $C^G_{back}$ depending on the desired weighting direction), $C_{i \rightarrow j}^1$ is the value from the standard table, $i$ is the front sample index, and $j$ is the back sample index [S1].

**Formulas:**
The opacity factor $A_x$ for term $x$ in the integration sum is defined as [S1]:
$$A_x = (1 - \alpha_i)(1 - \alpha_{i+1})\dots(1 - \alpha_{x-1}) \alpha_x$$

The derivation relies on the fact that the desired weighted integral $C_{i \rightarrow j}^W$ with a local ramp $W(x) = \frac{x-i}{j-i}$ can be expressed as [S1]:
$$C_{i \rightarrow j}^W = \frac{1}{j-i} \sum_{x=i}^{j} (x-i) A_x C_x$$
This is equivalent to [S1]:
$$C_{i \rightarrow j}^W = \frac{1}{j-i} \left( \sum_{x=i}^{j} x A_x C_x - i \sum_{x=i}^{j} A_x C_x \right)$$
The first sum is $C_{i \rightarrow j}^G$ and the second is $C_{i \rightarrow j}^1$ [S1].

**Parameters:**
- $n_t$: Number of transfer function bins. Typical values depend on the transfer function complexity [S1].
- $n_r$: Number of samples per bin. Determines the resolution of the lookup table $n = n_t / n_r$ [S1].

**Edge Cases and Pitfalls:**
- Division by zero: If $i = j$, the denominator $j-i$ is zero. This case corresponds to a single-sample interval and should be handled separately or avoided by ensuring $i < j$ for weighted entries [S1].
- Precision: The subtraction $C^G - i C^1$ may suffer from catastrophic cancellation if $i$ is large and $C^G \approx i C^1$. Use high-precision arithmetic if necessary [G].
- Lighting direction: Front-weighted tables are used when lighting varies from front to back; back-weighted when it varies from back to front [S1].

**Pseudocode:**
```python
def compute_weighted_lookup_tables(transfer_function, n_r):
    """
    transfer_function: list of tuples (alpha, r, g, b) for each bin.
    n_r: number of samples per bin.
    Returns: weighted_lookup_table (n x n array of (r, g, b))
    """
    n_t = len(transfer_function)
    n = n_t // n_r
    
    # Step 1: Compute standard pre-integrated table C^1
    # This uses the standard incremental subrange integration algorithm [Parent]
    C1 = compute_standard_preintegration(transfer_function, n_r)
    
    # Step 2: Compute globally ramped tables C^G_front and C^G_back
    # Create modified transfer functions
    tf_front = []
    tf_back = []
    for k, (alpha, r, g, b) in enumerate(transfer_function):
        # Multiply color by index k for front-weighted
        tf_front.append((alpha, r * k, g * k, b * k))
        # Multiply color by (n_t - 1 - k) for back-weighted
        tf_back.append((alpha, r * (n_t - 1 - k), g * (n_t - 1 - k), b * (n_t - 1 - k)))
    
    C_G_front = compute_standard_preintegration(tf_front, n_r)
    C_G_back = compute_standard_preintegration(tf_back, n_r)
    
    # Step 3: Compute final weighted tables
    weighted_table = [[(0, 0, 0) for _ in range(n)] for _ in range(n)]
    
    for i in range(n):
        for j in range(i + 1, n):
            # Get values from intermediate tables
            c1 = C1[i][j]
            c_g_f = C_G_front[i][j]
            c_g_b = C_G_back[i][j]
            
            # Compute front-weighted entry
            # Formula: (C^G - i * C^1) / (j - i)
            denom = j - i
            r_f = (c_g_f[0] - i * c1[0]) / denom
            g_f = (c_g_f[1] - i * c1[1]) / denom
            b_f = (c_g_f[2] - i * c1[2]) / denom
            weighted_table[i][j] = (r_f, g_f, b_f)
            
            # Compute back-weighted entry
            r_b = (c_g_b[0] - i * c1[0]) / denom
            g_b = (c_g_b[1] - i * c1[1]) / denom
            b_b = (c_g_b[2] - i * c1[2]) / denom
            # Note: The back-weighted table might be stored separately or combined
            # depending on implementation. Here we assume a single table for front-weighted
            # as per the primary formula derivation [S1].
            
    return weighted_table
```

## Operating characteristics
- **Time Complexity:** $O(n^2)$, where $n$ is the number of bins in the lookup table. This is because there are $2n$ diagonals in the $n \times n$ table, and each requires a single range-integral table computation of $O(n_t)$ operations, leading to $O(n \cdot n_t) = O(n^2)$ total time [S1].
- **Memory Complexity:** $O(n^2)$ to store the three intermediate tables and the final weighted table [S1].
- **Performance:** The method allows interactive generation of lit pre-integration tables, similar to standard pre-integration [S1].
- **Strengths:** Incorporates lighting effects (diffuse and specular) into pre-integration, providing higher visual quality than unweighted pre-integration [S1]. Efficient $O(n^2)$ computation makes it feasible for real-time applications [S1].
- **Limitations:** More complex to implement than standard pre-integration due to the need for three intermediate tables and the combination step [S1]. The weighting function depends on the integration range, requiring the specific derivation to avoid $O(n^4)$ complexity [S1].

## Background
The method was introduced in the paper "High-Quality Lighting and Efficient Pre-Integration for Volume Rendering" by Ma et al. (2004) [S1]. It extends the concept of pre-integration to include lighting by applying scaling functions to transfer function colors during integration [S1]. The key insight is that the dependency of the weighting function on the integration range can be resolved using globally ramped intermediate tables, allowing efficient computation [S1].
