# Pre-integrated Volume Rendering

Also called: PIVR, Pre-integration (Pré-integração), Precomputed volume rendering integral, Preintegration Volume Rendering, Pré-integração

## Overview
Pre-integrated Volume Rendering (PIVR) is a technique that accelerates direct volume rendering by pre-computing the volume rendering integral for all possible segment configurations and storing the results in a lookup table [S1, S4, S8, unofficial]. It solves the problem of aliasing artifacts caused by high-frequency non-linear transfer functions when using standard point-sampling classification [S1, unofficial][S5]. Unlike standard methods that apply the transfer function to individual samples, PIVR decouples the integration of the transfer function contribution from the sampling process, allowing the sampling to focus solely on volume reconstruction [S8, unofficial]. It sets itself apart from siblings like [Pre-integration of Transfer Function Contribution](12225-pre-integration-of-transfer-function-contribution.md) by explicitly pre-computing the integral over a segment defined by endpoint scalar values and length, rather than just integrating the transfer function parameters independently [S5][S8, unofficial].

## How it works
**Inputs:**
*   Scalar volume data $V$.
*   Transfer functions: extinction density $\tau(s)$ and color density $\tilde{c}(s)$, where $s$ is the scalar value.
*   Ray segment length $d$ (assumed constant for the frame in CPU implementations [S4, unofficial]).

**Outputs:**
*   Accumulated color $\mathbf{C}_{out}$ and opacity $\alpha_{out}$ for each pixel.

**Data Structures:**
*   **1D Integral Table:** A lookup table storing pre-computed integrals.
    *   **Size:** 256 entries (assuming 8-bit scalar quantization) [S4, unofficial].
    *   **Layout:** Each entry contains four 32-bit floating-point numbers: accumulated color components $(\tilde{R}_A, \tilde{G}_A, \tilde{B}_A)$ and accumulated opacity $T_A$ [S4, unofficial]. Total size: 4 Kbytes [S4, unofficial].
    *   **Content:** The table stores $T(s)$ and $K(s)$ for $s \in [0, 255]$.
        *   $T(s) = \int_0^s \tau(\sigma) d\sigma$
        *   $K(s) = \int_0^s \tilde{c}(\sigma) d\sigma$
    *   **Refresh:** The table must be recomputed whenever the user modifies the transfer function [S1, S4, unofficial].

**Numbered Steps:**

1.  **Pre-computation:** Compute the integral functions $T(s)$ and $K(s)$ from the user-supplied transfer functions $\tau(s)$ and $\tilde{c}(s)$ for all discrete scalar values $s$. Store these in the 1D table [S4, unofficial].
2.  **Sampling:** Sample the scalar field along the viewing ray. For each segment, obtain the scalar values at the beginning ($s_f$) and end ($s_b$) of the segment [S1, S2, unofficial].
3.  **Ordering:** Determine $s_{max} = \max(s_f, s_b)$ and $s_{min} = \min(s_f, s_b)$ [S4, unofficial].
4.  **Table Lookup:** Retrieve $T(s_{max}), K(s_{max})$ and $T(s_{min}), K(s_{min})$ from the pre-computed table [S4, unofficial].
5.  **Compute Intermediate Values:**
    *   Calculate the difference in scalar values: $diff = s_{max} - s_{min}$ [S4, unofficial].
    *   Compute the reciprocal: $invDiff = 1 / diff$ [S4, unofficial].
    *   Compute the color numerator: $\Delta K = K(s_{max}) - K(s_{min})$ [S4, unofficial].
    *   Compute the opacity numerator: $\Delta T = T(s_{max}) - T(s_{min})$ [S4, unofficial].
6.  **Compute Segment Properties:**
    *   **Color:** $\tilde{C} = d \cdot invDiff \cdot \Delta K$ [S4, unofficial].
    *   **Opacity Parameter:** $x = invDiff \cdot \Delta T$ [S4, unofficial]. Note that $x \ge 0$ [S4, unofficial].
7.  **Approximate Opacity:** Compute the actual opacity $\alpha$ from $x$ using the approximation $\alpha = 1 - \exp(-x)$ [S4, unofficial].
    *   *Implementation Note:* This exponential can be approximated using four linear segments $y_i = m_i \cdot x + b_i$ for $i \in \{0,1,2,3\}$, where the final opacity is $\min(y_0, y_1, y_2, y_3)$ [S4, unofficial]. The parameters $m_i, b_i$ are pre-computed to minimize error for $x \ge 0$ [S4, unofficial].
8.  **Compositing:** Composite the segment contributions $(\tilde{C}, \alpha)$ using front-to-back blending:
    $$ \mathbf{C}_{out} = \sum_{i} \tilde{C}_i \prod_{j < i} (1 - \alpha_j) $$
    $$ \alpha_{out} = 1 - \prod_{i} (1 - \alpha_i) $$
    [S1, S8, unofficial]

**Pseudocode:**

```python
# Pre-computation phase (run once or when TF changes)
def precompute_transfer_functions(tau_func, c_func, num_bins=256):
    """
    Computes the 1D integral table for pre-integration.
    tau_func: function mapping scalar s -> extinction density tau(s)
    c_func: function mapping scalar s -> color density c(s) (returns RGB vector)
    """
    table_size = num_bins
    # Table stores [R_A, G_A, B_A, T_A] for each scalar value
    table = [[0.0, 0.0, 0.0, 0.0] for _ in range(table_size)]
    
    accumulated_color = [0.0, 0.0, 0.0]
    accumulated_opacity = 0.0
    
    for s in range(table_size):
        # Integrate from s-1 to s (assuming unit step in scalar space for table indexing)
        # In practice, this is a Riemann sum or trapezoidal rule over the scalar domain
        tau_val = tau_func(s)
        c_val = c_func(s)
        
        accumulated_opacity += tau_val
        accumulated_color[0] += c_val[0]
        accumulated_color[1] += c_val[1]
        accumulated_color[2] += c_val[2]
        
        table[s] = [accumulated_color[0], accumulated_color[1], accumulated_color[2], accumulated_opacity]
        
    return table

# Rendering phase
def render_segment(s_f, s_b, d, table):
    """
    Computes color and opacity for a single ray segment using pre-integration.
    s_f: scalar value at front of segment
    s_b: scalar value at back of segment
    d: length of the segment
    table: pre-computed 1D integral table
    """
    # 1. Order values
    s_max = max(s_f, s_b)
    s_min = min(s_f, s_b)
    
    # 2. Handle degenerate case where s_max == s_min
    if s_max == s_min:
        return 0.0, [0.0, 0.0, 0.0]
        
    # 3. Table Lookup
    # Assuming table indices correspond directly to quantized scalar values
    # In a real implementation, s_f and s_b might be interpolated floats, 
    # requiring interpolation of the table entries or clamping to 0-255.
    # Here we assume s_f, s_b are already quantized indices for simplicity of the core logic.
    entry_max = table[s_max]
    entry_min = table[s_min]
    
    # 4. Compute differences
    delta_k = [
        entry_max[0] - entry_min[0],
        entry_max[1] - entry_min[1],
        entry_max[2] - entry_min[2]
    ]
    delta_t = entry_max[3] - entry_min[3]
    
    # 5. Compute intermediate values
    diff = s_max - s_min
    inv_diff = 1.0 / diff
    
    # 6. Compute segment color
    # C_tilde = d * (1/diff) * (K(s_max) - K(s_min))
    color = [d * inv_diff * dk for dk in delta_k]
    
    # 7. Compute opacity parameter x
    x = inv_diff * delta_t
    
    # 8. Approximate opacity alpha = 1 - exp(-x)
    # Using a simple approximation or standard math function
    alpha = 1.0 - math.exp(-x)
    
    return alpha, color

def composite_ray(rays_segments, initial_color=[0.0, 0.0, 0.0], initial_alpha=0.0):
    """
    Front-to-back compositing of ray segments.
    rays_segments: list of (alpha, color) tuples, ordered from near to far.
    """
    accumulated_color = initial_color
    accumulated_alpha = initial_alpha
    
    for alpha, color in rays_segments:
        # Contribution of this segment
        contribution = [c * (1.0 - accumulated_alpha) for c in color]
        
        # Update accumulators
        accumulated_color = [ac + c for ac, c in zip(accumulated_color, contribution)]
        accumulated_alpha = 1.0 - (1.0 - accumulated_alpha) * (1.0 - alpha)
        
        # Early termination if fully opaque (optional optimization)
        if accumulated_alpha >= 0.99:
            break
            
    return accumulated_color, accumulated_alpha
```

**Edge Cases and Pitfalls:**
*   **Thresholding:** Raypoints below a threshold should not be simply discarded if the previous point was above the threshold, as the linear interpolation might exceed the threshold within the interval [S4, unofficial]. However, if $s_{max}$ is below the threshold, the entire interval is below the threshold (assuming clamped transfer functions) and can be safely skipped [S4, unofficial].
*   **Simplified Alpha Loss:** Using a simplified opacity formula (e.g., linear approximation without the exponential) results in a visible loss in contrast [S4, unofficial].
*   **Discretization Artifacts:** The method assumes a linear progression of scalar values between samples, which can introduce artifacts if the scalar field varies non-linearly within a segment [S6, unofficial].
*   **High-Dimensional Transfer Functions:** Pre-integration is not directly applicable to transfer functions with dimension greater than one (e.g., 2D TFs) without restrictions, due to the large memory and processing time required for multi-dimensional lookup tables (at least 4 dimensions) [S8, unofficial].

## Subtopics

### [Adaptive Pre-integration](8075-adaptive-pre-integration.md)
Adaptive Pre-integration is a technique applied to texture slicing that pre-computes optimal step sizes for each ray based on pre-integrated emission, opacity, and second-order gradients to guarantee error bounds on ray integration. It is an adaptive approach that overcomes pre-integration artifacts by using an adaptive sampling rate based on the actual information stored in the volume and the transfer function used. It builds on [Pre-integrated Volume Rendering](5327-pre-integrated-volume-rendering.md) by dynamically adjusting the discretization of the pre-integration integral rather than using a fixed slab thickness.

### [Direct Volume Rendering with Pre-integration](8968-direct-volume-rendering-with-pre-integration.md)
Direct Volume Rendering with Pre-integration renders adapted tetrahedral meshes using direct volume ray casting, accelerated by pre-integration computed in shaders. It extends pre-integrated volume rendering, which allows for faster evaluation by pre-computing all possible results from the integral and storing them in a table for lookup [Parent], to unstructured volumetric data (tetrahedral meshes). Unlike methods limited to regular grids, this approach handles the geometric complexity of unstructured grids by storing the mesh data structure in textures and using barycentric interpolation for value estimation.

## Operating characteristics
*   **Time Complexity:** The per-segment computation is dominated by SIMD arithmetic operations (multiplication, addition, subtraction, minimum) with latencies of 4-6 cycles [S4, unofficial]. The pre-computation step is time-consuming but done once per transfer function change [S5].
*   **Memory Complexity:** The 1D table approach uses 4 Kbytes (256 entries × 16 bytes), which fits in the L1 cache of typical CPUs, resulting in a high hit ratio and avoiding the cache misses associated with larger 2D tables (512 Kbytes) [S4, unofficial].
*   **Measured Performance:** On a Pentium-4 2GHz, pre-integrated rendering (d=0.45) achieved 0.158s per frame (6.33 fps) compared to 0.295s for standard classification with empty-space skipping [S4, unofficial]. A 200 MHz CPU with an nVidia GeForce3 achieved 4 fps for a 256x256 viewport [S1, unofficial].
*   **Strengths:** Reduces aliasing artifacts caused by high frequencies in non-linear transfer functions [S4, unofficial][S5]. Allows for larger ray step sizes (coarser sampling) while maintaining image quality, effectively increasing the Nyquist frequency for the scalar field reconstruction independent of the transfer function [S1, unofficial][S5].
*   **Limitations:** Assumes linear scalar variation between samples, which can cause artifacts in regions of high curvature [S6, unofficial]. Not directly applicable to high-dimensional transfer functions without significant memory overhead [S8, unofficial].
*   **When to use:** Suitable for interactive volume rendering of regular grid data with non-linear transfer functions, especially on hardware with limited memory bandwidth or cache [S4, S7, unofficial].
*   **When not to use:** When the scalar field varies highly non-linearly within segments and adaptive sampling is not used [S6, unofficial], or when using high-dimensional transfer functions [S8, unofficial].

## Background
Pre-integrated Volume Rendering was introduced by Engel et al. in 2001 [Engel01] as an improvement over basic texture mapping to overcome high Nyquist frequencies from non-linear transfer functions [S1, unofficial]. It was later combined with volumetric clipping and advanced lighting effects by Röttger et al. in 2003 [Röttger03]. The method separates the DVR integral into two parts: one for the continuous scalar value and one for the transfer function parameters (colors and extinction coefficient) [S5]. It is implemented in software systems like UltraVis [S4, unofficial] and has been adapted for GPU-based raycasting [S5].
