# Pre-integration of Transfer Function Contribution

Also called: Pre-integrated Transfer Function Tables

## Overview
Pre-integration of transfer function contribution is a technique that replaces on-the-fly interpolation and integration with pre-computed lookup tables to perform fully-shaded semi-transparent and iso-surface volume rendering [S1, unofficial]. It addresses the dichotomy between image quality and performance by pre-integrating the transfer function's contribution along ray segments, thereby smoothing image imperfections caused by low sampling frequencies [S3, unofficial]. It sets itself apart from standard ray casting by mapping pairs of scalar density values directly to pre-integrated color and opacity, decoupling the integration of the transfer function from the sampling process [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset $V$, a color transfer function $C(v)$, an extinction coefficient transfer function $\lambda(v)$, and a gradient volume for shading [G].
*   **Output:** A rendered image with reduced aliasing artifacts [S3, unofficial].

**Data Structures:**
*   **Pre-integrated Transfer Function Table:** A 2D lookup table indexed by two scalar density values (e.g., $v_i$ and $v_{i+1}$) [G]. The stored values are the pre-integrated color and opacity contributions for the segment between these two densities [G].
*   **Gradient Volume:** Loaded into texture memory to compute gradients for shading [G]. Note that interpolating a gradient volume without subsequent normalization is generally incorrect, though artifacts may not always be visible [S1, unofficial].

**Method Steps:**
1.  **Pre-computation:** Compute the analytical integration of the transfer function over the segment between two adjacent sample values. For a segment from $l_i$ to $l_o$, the resulting color $C_{res}$ and opacity $\alpha$ are derived from the integrals [S3, unofficial]:
    $$
    C_{res} = \int_{l_i}^{l_o} C(V(R(l))) \times \exp \left( - \int_{l_i}^l \lambda(V(R(j))) \times dj \right) \times dl
    $$
    $$
    \alpha = 1 - \exp \left( - \int_{l_i}^{l_o} \lambda(V(R(l))) \times dl \right)
    $$
    The integrals are evaluated for relevant density pairs and stored in the table [G].
2.  **Ray Casting:** Decompose view rays into segments of homogeneous or very similar length [S3, unofficial].
3.  **Lookup:** For each segment, determine the scalar density values at the endpoints. Use these values to index into the pre-integrated transfer function table to retrieve the pre-computed color and opacity contribution for that segment [G].
4.  **Composition:** Composite the retrieved color and opacity contributions along the ray [G]. Note that in these approximations, color and extinction coefficient values often become absolute values rather than ratios per unit length due to the decomposition of rays into segments [S3, unofficial].
5.  **Shading:** Load the gradient volume and compute shading [G]. To eliminate artifacts from incorrect gradient interpolation, use a shading cube texture instead of standard texture mapping [S1, unofficial].

**Parameters:**
*   **Table Resolution:** Determined by the number of discrete density values stored. Not given in the sources.
*   **Segment Length:** Should be homogeneous or very similar to ensure the validity of the pre-integrated values [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Gradient Interpolation:** Interpolating a gradient volume without normalization yields incorrect results [S1, unofficial].
*   **Value Interpretation:** The pre-integrated values are absolute contributions for the segment, not per-unit-length ratios [S3, unofficial].

## Subtopics

## Operating characteristics
*   **Time and Memory Complexity:** Not given in the sources.
*   **Measured Performance:** The implementation can perform fully-shaded semi-transparent and iso-surface volume rendering at 1-4 frames per second for $256^3$ volumes, using an NVidia GeForce3 [S1, unofficial].
*   **Scaling:** Not given in the sources.
*   **Strengths and Limitations:** Overcomes undersampling problems associated with large inter-slice distances at off-angles [S1, unofficial]. Smooths image imperfections caused by low sampling frequencies [S3, unofficial]. Performance is inversely dependent on sampling frequency, and the sampled field behavior, when modulated by the transfer function, cannot be satisfactorily reconstructed using too low sampling frequencies [S3, unofficial].
*   **When to Use:** Use when image quality must be maintained at low sampling frequencies without increasing computational cost per frame [S3, unofficial]. When not: Avoid when hardware lacks efficient 2D texture lookup or when exact per-unit-length ratios are required [S1, unofficial].

## Background
The technique was proposed by Engel et al. to smooth image imperfections caused by low sampling frequencies [S3, unofficial]. It replaced earlier techniques that overcame undersampling problems by interpolating intermediate slices on-the-fly using register combiners in the fragment shader compartment [S1, unofficial].
