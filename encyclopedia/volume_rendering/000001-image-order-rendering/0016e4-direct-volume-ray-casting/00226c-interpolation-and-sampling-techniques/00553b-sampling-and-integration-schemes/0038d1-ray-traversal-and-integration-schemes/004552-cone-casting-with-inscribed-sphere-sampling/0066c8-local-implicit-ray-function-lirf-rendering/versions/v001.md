# Local Implicit Ray Function (LIRF) Rendering

Also called: cone-based ray sampling

## Overview
Local Implicit Ray Function (LIRF) is a rendering technique that represents the feature aggregation of samples within a ray conical frustum in a continuous manner, enabling arbitrary supersampling of rays for novel view synthesis at multiple scales [S1]. Unlike standard ray casting which treats a pixel as an infinitesimal line, LIRF constructs each target ray by aggregating information from a cone (represented by vertices), allowing for better handling of thin structures and multi-scale synthesis [S1]. It sets itself apart from its sibling [Cone Casting with Inscribed Sphere Sampling](11501-cone-casting-with-inscribed-sphere-sampling.md) by explicitly defining a continuous implicit function over the frustum's volume to interpolate features, rather than relying solely on geometric sampling strategies [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   A 3D coordinate $\mathbf{p}$ of a sampled position within a conical frustum [S1].
    *   Features of the $M$ vertices defining the conical frustum [S1].
    *   Image feature maps extracted from $V$ nearby source views [S1].
*   **Outputs:**
    *   Aggregated feature for the sample at $\mathbf{p}$ in a continuous manner [S1].
    *   Predicted density and color for the sample [S1].
    *   Final rendered color via volume rendering [S1].

**Data Structures:**
*   **Conical Frustum:** Represented by $M=8$ vertices [S1]. The vertices are defined based on neighbor rays through neighbor pixels [S1].
*   **Feature Maps:** Extracted image feature maps with $C=32$ channels, sized same as the original image [S1].
*   **Visibility Patches:** Feature patches of size $7 \times 7$ used to predict visibility weights [S1].

**Parameters:**
*   $V = 8$: Number of nearby source views selected for training and testing [S1].
*   $M = 8$: Number of vertices used to represent a conical frustum [S1].
*   $r_m$: Cone radius, set to the pixel width of the target image with the minimum resolution [S1].
*   $N = 128$: Number of points directly sampled on a ray [S1].
*   Patch size: $7 \times 7$ [S1].

**Algorithm Steps:**

1.  **Select Source Views:** For a target view, select $V=8$ nearby source views [S1].
2.  **Extract Features:** Extract image feature maps with 32 channels from the source views, maintaining the original image dimensions [S1].
3.  **Define Conical Frustum:** Construct a conical frustum for the target pixel. The frustum is defined by $M=8$ vertices. The radius $r_m$ is determined by the pixel width of the target image at minimum resolution [S1].
4.  **Sample Points:** Directly sample $N=128$ points along the target ray [S1].
5.  **Compute Visibility Weights:** For each sample, match local multi-view feature patches of size $7 \times 7$ from the source views to estimate visibility weights, mitigating occlusion artifacts [S1].
6.  **Evaluate LIRF:** For each sampled 3D position $\mathbf{p}$ within the frustum:
    *   Input $\mathbf{p}$ and the features of the $M=8$ frustum vertices into the Local Implicit Ray Function [S1].
    *   The function outputs the aggregated feature continuously [S1].
    *   *Note: The specific mathematical formulation of the LIRF function (e.g., Eq. 5 and 6 in the source) involves scale $s$ and relative position $\Delta x$ [S1].*
7.  **Predict Radiance:** Use the aggregated features to predict the density and color of the sample [S1].
8.  **Volume Rendering:** Render the final color of the target ray using the predicted densities and colors via standard volume rendering integration [S1].

**Edge Cases and Pitfalls:**
*   **Occlusion:** Rendering regions occluded in all input views is impossible [S1].
*   **View Consistency:** View consistency is weaker than NeRF because selected input views vary with the novel view position [S1].
*   **Computational Cost:** Rendering a pixel requires casting four rays to approximate a cone, increasing computational cost [S1].
*   **Scale Sensitivity:** Performance degrades significantly if the scale parameter or relative position components of the LIRF are removed, especially at extreme scales ($\times 0.5$ and $\times 4$) [S1].

## Operating characteristics
*   **Time Complexity:** Increases due to the requirement of casting four rays to approximate a cone for each pixel [S1]. Training takes approximately two days on eight V100 GPUs for 250k iterations with a batch size of 512 rays [S1].
*   **Memory Complexity:** Requires storing feature maps for $V=8$ source views and processing $N=128$ samples per ray [S1].
*   **Performance:** The full LIRF model performs better than the "single ray" variant on all scales, especially at $\times 0.5$ and $\times 4$ [S1]. It outperforms IBRNet, NeuRay, and GeoNeRF in quantitative metrics (PSNR, SSIM, LPIPS) on real forward-facing scenes [S1]. Using the method's own feature extraction yields significantly better performance than using U-Net features from IBRNet [S1].
*   **Strengths:** Enables arbitrary supersampling for novel view synthesis at multiple levels of detail (anti-blurring and anti-aliasing) [S1]. Better handling of thin structures compared to single-ray methods [S1].
*   **Limitations:** Cannot render fully occluded regions; weaker view consistency compared to NeRF; higher computational cost due to cone approximation [S1].

## Background
Local Implicit Ray Function (LIRF) was proposed as a novel method for generalizable radiance field representation and novel view synthesis of unseen scenes [S1]. It addresses the limitations of single-ray representations by introducing a continuous aggregation of features within a conical frustum [S1]. The method was supported by NSFC under Grant 62031023 [S1].
