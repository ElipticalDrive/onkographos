# Ray Marching with Depth Testing

Also called: GPU Ray Marching, Manual Depth Testing, Ray Marching for Volume Rendering, Sequential Ray Marching

## Overview
Ray marching with depth testing visualizes volumes by casting rays from the camera and sampling at discrete steps along each ray's path, traversing a voxel grid and applying transfer functions to map raw values to color and opacity [S1]. It solves the problem of correct occlusion between volumetric effects and solid geometry by integrating manual depth buffer comparisons into the ray marching loop [S1]. This method sets itself apart from sibling techniques like [Fixed Step Ray Marching](3136-fixed-step-ray-marching.md) by explicitly discarding samples that lie behind opaque objects, thereby preventing visual artifacts where volume appears in front of or behind solid geometry incorrectly [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera matrices (view/projection), ray origin $o$, normalized ray direction $d$, volume textures (density, temperature), depth buffer from the geometry pass, step count $N$, and opacity factor $o$ [S1].
*   **Outputs:** Final accumulated color $C_{acc}$ and opacity $\alpha_{acc}$ for the pixel [S1].

**Data Structures:**
*   **Ray:** Defined by origin $o$ and direction $d$.
*   **Volume Texture:** 3D texture storing density and temperature values [S1].
*   **Depth Buffer:** Stores depth values $z_b$ for each pixel from the preceding geometry pass [S1].

**Numbered Steps:**

1.  **Ray Initialization:** Derive the ray origin $o$ and direction $d$ from camera matrices. Calculate the intersection of the ray with the volume's bounding box to determine the entry point $t_{min}$ and exit point $t_{max}$ [S1].
2.  **Step Size Calculation:** Compute the step size $\Delta t$ using the formula:
    $$ \Delta t = \frac{t_{max} - t_{min}}{N} $$
    where $N$ is the configurable step count [S1].
3.  **Marching Loop:** Iterate $i$ from $0$ to $N-1$. For each step:
    a.  **Position Update:** Calculate the current world position $p(t)$:
        $$ p(t) = o + t d $$
        where $p(t)$ is the current position, $o$ is the ray origin, and $d$ is the normalized direction [S1].
    b.  **Depth Testing:** Transform the sample's world position $p(t)$ to clip space to obtain screen depth $z$. Compare $z$ against the stored depth buffer value $z_b$ with a small bias $\epsilon$ to determine the depth weight $d_w$:
        $$ d_w := \begin{cases} 1, & \text{if } z < f(z_b + \epsilon) \\ 0, & \text{otherwise} \end{cases} $$
        where $f$ is the depth mapping function, $z$ is the screen depth, $z_b$ is the stored depth buffer value, and $\epsilon$ is a small bias (e.g., 0.004) to handle precision issues [S1].
    c.  **Sample and Weight:** If $d_w = 0$, discard the sample. If $d_w = 1$, sample the density texture $\tilde{d}$ and temperature at $p(t)$. Apply the depth weight to the density:
        $$ w := \tilde{d} \cdot d_w $$
        where $w$ is the weighted density and $\tilde{d}$ is the density value of the volume sample [S1].
    d.  **Interpolation:** Use quasi-cubic sampling to enhance interpolation quality [S1].
    e.  **Accumulation:** Update the accumulated color and opacity using alpha blending adapted from Max [13]:
        $$ \alpha_{acc} := 1 - (1 - \alpha_{acc}) \cdot (1 - \alpha_{current}) $$
        $$ C_{acc} := C_{acc} + (1 - \alpha_{acc}) \cdot C_{current} \cdot \alpha_{current} $$
        where $\alpha_{current}$ and $C_{current}$ are the opacity and color of the current voxel, derived from the weighted density $w$ and temperature via transfer functions [S1].
    f.  **Termination:** Continue marching until the ray exits the volume ($t > t_{max}$) or the accumulated opacity $\alpha_{acc}$ reaches a threshold (e.g., 1.0) [S1].

**Pseudocode:**
```python
class Vec3:
    def __init__(self, x, y, z): self.x, self.y, self.z = x, y, z
    def __add__(self, other): return Vec3(self.x + other.x, self.y + other.y, self.z + other.z)
    def __mul__(self, s): return Vec3(self.x * s, self.y * s, self.z * s)
    def __getitem__(self, i): return (self.x, self.y, self.z)[i]

class Vec4:
    def __init__(self, x, y, z, w): self.x, self.y, self.z, self.w = x, y, z, w
    def __getitem__(self, i): return (self.x, self.y, self.z, self.w)[i]

def ray_march_with_depth_testing(ray_origin, ray_direction, volume_texture, depth_buffer, step_count, opacity_factor):
    # 1. Calculate bounding box intersections (standard slab method) [G]
    t_min, t_max = 0.0, 1.0
    for axis in range(3):
        if abs(ray_direction[axis]) > 1e-6:
            t1 = (0.0 - ray_origin[axis]) / ray_direction[axis]
            t2 = (1.0 - ray_origin[axis]) / ray_direction[axis]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
        else:
            if ray_origin[axis] < 0.0 or ray_origin[axis] > 1.0:
                return Vec3(0.0, 0.0, 0.0), 0.0
    if t_min > t_max:
        return Vec3(0.0, 0.0, 0.0), 0.0

    # 2. Calculate step size
    step_size = (t_max - t_min) / step_count
    
    # Initialize accumulation
    acc_color = Vec3(0.0, 0.0, 0.0)
    acc_alpha = 0.0
    
    # 3. Marching loop
    for i in range(step_count):
        t = t_min + i * step_size
        position = ray_origin + t * ray_direction
        
        # Transform to clip space to get screen depth [G]
        clip_pos = world_to_clip_space(position)
        z = clip_pos.z / clip_pos.w
        
        # Get stored depth buffer value for this pixel
        z_b = depth_buffer.get_value_at_pixel(clip_pos.x, clip_pos.y)
        
        # Bias to avoid precision issues
        epsilon = 0.004
        depth_weight = 1.0 if z < z_b + epsilon else 0.0
        
        # Discard if behind opaque geometry
        if depth_weight == 0.0:
            continue
            
        # Sample volume using quasi-cubic sampling
        density = quasi_cubic_sample(volume_texture, position)
        temperature = quasi_cubic_sample(volume_texture, position, channel='temperature')
        
        # Apply depth weight to density
        weighted_density = density * depth_weight
        
        # Map to color and opacity via transfer functions
        current_alpha = weighted_density * opacity_factor
        current_color = transfer_function_temperature_to_color(temperature)
        
        # Alpha blending (Max's formula)
        acc_alpha = 1.0 - (1.0 - acc_alpha) * (1.0 - current_alpha)
        acc_color = acc_color + (1.0 - acc_alpha) * current_color * current_alpha
        
        # Early exit if fully opaque
        if acc_alpha >= 1.0:
            break
            
    return acc_color, acc_alpha

def quasi_cubic_sample(texture, uv, channel='density'):
    # Implementation from Listing 1 in [S1]
    R = texture.dimensions()
    U = uv * R + Vec3(0.5, 0.5, 0.5)
    F = Vec3(U.x % 1.0, U.y % 1.0, U.z % 1.0)
    U = Vec3(
        (U.x - F.x) + F.x * F.x * (3.0 - 2.0 * F.x),
        (U.y - F.y) + F.y * F.y * (3.0 - 2.0 * F.y),
        (U.z - F.z) + F.z * F.z * (3.0 - 2.0 * F.z)
    )
    C = Vec3((U.x - 0.5) / R, (U.y - 0.5) / R, (U.z - 0.5) / R)
    return texture.lookup(C, channel)

def world_to_clip_space(position):
    # Standard view-projection transform [G]
    view_pos = apply_view_matrix(position)
    clip_pos = apply_projection_matrix(view_pos)
    return clip_pos

def transfer_function_temperature_to_color(temperature):
    # Standard 1D texture lookup or palette mapping [G]
    return Vec3(temperature, temperature, temperature)
```

**Parameters:**
*   **Step Count ($N$):** Configurable value with options 16, 32, 64, 128, or 256. 128-256 steps provide a balance between performance and visual quality [S1].
*   **Bias ($\epsilon$):** A small value (e.g., 0.004) added to the depth buffer value to prevent precision issues in depth comparison [S1].
*   **Opacity Factor ($o$):** User-adjustable factor controlling the contribution of each sample to the accumulated opacity [S1].

**Edge Cases and Pitfalls:**
*   **Precision Issues:** Without a bias $\epsilon$, depth comparison can fail due to floating-point precision errors, causing the volume to appear incorrectly behind or in front of opaque objects [S1].
*   **Occlusion:** If depth testing is omitted, volumetric effects may render incorrectly relative to solid geometry [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of steps $N$ and the number of pixels [S1]. Each pixel requires $N$ samples in the worst case [S1].
*   **Memory Complexity:** Depends on the size of the volume texture and the depth buffer [S1]. The depth buffer is required from the previous pass [S1].
*   **Performance:** 128-256 steps are recommended for a balance between performance and visual quality [S1].
*   **Strengths:** Correctly handles occlusion between volumes and solid geometry, reducing artifacts [S1]. Quasi-cubic sampling improves interpolation quality over linear sampling [S1].
*   **Limitations:** Requires a pre-pass to generate the depth buffer. Precision issues can occur without proper biasing [S1].

## Background
This method is described in the context of real-time volumetric explosion special effects for games, implemented using WebGPU and WGSL shaders [S1]. The accumulation formula adapts classical alpha blending principles described by Max [13] [S1]. The specific implementation details, including manual depth testing and quasi-cubic sampling, are presented in the WSCG 2025 Proceedings [S1].
