# Mr-Voxel Volume Rendering

Also called: VolumeIntegrator::Li

## Overview
Mr-Voxel Volume Rendering is a direct volume ray casting technique implemented in the `VolumeIntegrator::Li` function that performs ray marching through a single volume region, accumulating emitted light and computing transmittance and scattering contributions from a single light source [S1, unofficial]. It is distinguished from its siblings by its specific implementation within the Mr-Voxel library, which combines an accelerated voxel data structure with a volume rendering library, and its reliance on a simplified single-volume, single-light model for its core integration loop [S1, unofficial]. Unlike [DVGO Density and Color Rendering](12839-dvgo-density-and-color-rendering.md) which uses sparse voxel octrees for neural radiance fields, or [Procedural Volumetric Cloud Rendering](3480-procedural-volumetric-cloud-rendering.md) which often employs procedural noise, Mr-Voxel operates on explicit voxel grids accessed via the `mScene` interface [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A camera ray `ray`, a scene object `mScene` containing volumes and lights, and a step size parameter `mStepSize`.
*   **Output:** A `Spectrum` representing the accumulated radiance `Lv` and an updated transmittance `*T`.

**Data Structures:**
The implementation assumes access to the following scene components via `mScene`:
*   `mScene->getVolumeCount()`: Returns the number of active volumes.
*   `mScene->getVolumes()`: Returns an array of volume objects. The implementation currently assumes a single volume at index 0 (`volumes[0]`) [S1, unofficial].
*   `mScene->getLightSources()`: Returns an array of light sources. The implementation currently assumes a single light at index 0 (`lights[0]`) [S1, unofficial].
*   `mScene->intersect(shadRay, &surface)`: A standard ray-surface intersection test for shadow rays [S1, unofficial].

Each volume object `v` provides the following methods:
*   `v.tau(ray, length, param)`: Computes the optical depth (tau) along a ray segment.
*   `v.Lve(p)`: Returns the emitted radiance at point `p`.
*   `v.sigma_s(p)`: Returns the scattering coefficient at point `p`.

**Numbered Steps:**
1.  **Calculate Sample Count:** Determine the number of samples `numSamples` based on the ray segment length `(t1 - t0)` and the integrator's `mStepSize`. If `numSamples` is 0, set it to 1 [S1, unofficial].
    $$ \text{numSamples} = \max\left(1, \left\lfloor \frac{t_1 - t_0}{\text{mStepSize}} \right\rfloor \right) $$
2.  **Calculate Step Length:** Compute the actual step length `step` to ensure the ray covers the exact distance `(t1 - t0)` [S1, unofficial].
    $$ \text{step} = \frac{t_1 - t_0}{\text{numSamples}} $$
3.  **Random Offset:** Apply a random offset to the starting position `t0` along the ray to reduce banding artifacts. The offset is a random float between 0 and `step` [S1, unofficial].
    $$ t_0 \leftarrow t_0 + \text{rand}() \times \text{step} $$
    where `rand()` returns a value in $[0, 1]$.
4.  **Initialize Accumulators:** Set accumulated radiance $L_v = 0$ and transmittance $T_r = 1$ [S1, unofficial].
5.  **Ray Marching Loop:** Iterate `i` from 0 to `numSamples`:
    a.  **Update Positions:** Let $p_{prev}$ be the current position. Update $p$ to `ray(t0)`. Create a short ray segment `tRay` from $p_{prev}$ to $p$ with length `step` [S1, unofficial].
    b.  **Compute Optical Depth:** Calculate the optical depth `stepTau` for the segment using the volume's `tau` method. The implementation passes `0.5 * step` as the length parameter and `0` as a parameter (likely a phase function or sampling parameter) [S1, unofficial].
        $$ \text{stepTau} = \text{volumes}[0].\text{tau}(tRay, 0.5 \times \text{step}, 0) $$
    c.  **Update Transmittance:** Update the ray transmittance $T_r$ by multiplying it with the exponential of the negative optical depth [S1, unofficial].
        $$ T_r \leftarrow T_r \times e^{-\text{stepTau}} $$
    d.  **Accumulate Emission:** Add the volume's emitted radiance at the current point $p$ to $L_v$ [S1, unofficial].
        $$ L_v \leftarrow L_v + \text{volumes}[0].L_e(p) $$
    e.  **Check Scattering:** Get the scattering coefficient $\sigma_s = \text{volumes}[0].\sigma_s(p)$. If $\sigma_s$ is effectively zero (black), skip lighting calculations for this step [S1, unofficial].
    f.  **Lighting Contribution:**
        i.  Compute the normalized light direction $\omega_L$ from $p$ to the light source position [S1, unofficial].
        ii. Create a shadow ray `shadRay` from $p$ in direction $\omega_L$. Check if the ray intersects a surface closer than the light distance. The condition for being unshadowed is:
            $$ \neg (\text{mScene}.\text{intersect}(shadRay, \&surface)) \lor (surface.t > \|p - \omega_L\|) $$
            where $\|p - \omega_L\|$ is the distance to the light [S1, unofficial].
        iii. If unshadowed, compute the light transmittance $lTr$ through the volume. The implementation uses `mStepSize * 2` as the length parameter and `0.0` as the parameter [S1, unofficial].
            $$ lTr = e^{-\text{volumes}[0].\text{tau}(shadRay, \text{mStepSize} \times 2, 0.0)} $$
        iv. Compute the direct lighting contribution $L_d$ as the product of light transmittance, light color, scattering coefficient, and ray transmittance. Add to $L_v$ [S1, unofficial].
            $$ L_d = lTr \times \text{lights}[0].\text{color} $$
            $$ L_v \leftarrow L_v + L_d \times \sigma_s \times T_r $$
6.  **Russian Roulette:** If $T_r < 10^{-3}$, perform Russian Roulette. With probability 0.5, break the loop. Otherwise, continue by scaling $T_r$ by $1/0.5$ (i.e., $T_r = T_r / 0.5$) [S1, unofficial].
7.  **Return:** Return $L_v$ and update `*T` with the final $T_r$ [S1, unofficial].

**Pseudocode:**
```python
def VolumeIntegrator_Li(ray, mScene, mStepSize):
    # 1. Calculate number of samples
    t0 = ray.start
    t1 = ray.end
    numSamples = int((t1 - t0) / mStepSize)
    if numSamples == 0:
        numSamples = 1
    
    # 2. Calculate actual step length
    step = (t1 - t0) / numSamples
    
    # 3. Apply random offset
    t0 = t0 + (rand_float() * step)
    
    # 4. Initialize accumulators
    Lv = Spectrum(0, 0, 0)
    Tr = 1.0
    
    # Get volumes and lights (assuming single volume/light as per implementation)
    volumes = mScene.getVolumes()
    lights = mScene.getLightSources()
    volume = volumes[0]
    light = lights[0]
    
    p_prev = ray(t0)
    
    # 5. Ray marching loop
    for i in range(numSamples):
        p = ray(t0 + (i + 1) * step) # Note: t0 was offset, so we march from offset start
        
        # Create short ray segment
        tRay = Ray(p_prev, p - p_prev)
        
        # Compute optical depth
        stepTau = volume.tau(tRay, 0.5 * step, 0)
        
        # Update transmittance
        Tr = Tr * exp(-stepTau)
        
        # Accumulate emitted light
        Lv = Lv + volume.L_e(p)
        
        # Get scattering coefficient
        ss = volume.sigma_s(p)
        
        # Check if scattering is non-zero
        if ss != Spectrum(0, 0, 0):
            # Compute light direction
            wL = normalize(light.position - p)
            
            # Create shadow ray
            shadRay = Ray(p, wL)
            
            # Check shadow
            surface = Surface()
            intersects = mScene.intersect(shadRay, surface)
            dist_to_light = length(light.position - p)
            
            if not intersects or surface.t > dist_to_light:
                # Compute light transmittance
                lTr = exp(-volume.tau(shadRay, mStepSize * 2, 0.0))
                
                # Compute direct lighting
                Ld = lTr * light.color
                Lv = Lv + Ld * ss * Tr
        
        p_prev = p
        
        # 6. Russian Roulette
        if Tr < 1e-3:
            if rand_float() < 0.5:
                break
            else:
                Tr = Tr / 0.5
                
    # 7. Return result
    return Lv, Tr
```

**Parameters:**
*   `mStepSize`: The step size used for ray marching through the volume. Typical values are not given in the sources, but it determines the resolution of the integration [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Single Volume/Light Assumption:** The implementation assumes a single volume (`volumes[0]`) and a single light source (`lights[0]`). A TODO comment notes that multiple volumes will need aggregators [S1, unofficial].
*   **Precision:** Transmittance can drop below 1e-3, requiring Russian Roulette to prevent infinite loops or underflow [S1, unofficial].
*   **Boundary Conditions:** The ray marching loop assumes the ray segment `(t0, t1)` is fully contained within the volume or that the volume's `tau` and `sigma_s` methods handle out-of-bounds queries gracefully [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** $O(N)$ where $N$ is the number of samples per ray, determined by the volume thickness and `mStepSize`. Each sample involves a constant number of volume queries and potentially one shadow ray intersection [S1, unofficial].
*   **Memory:** $O(1)$ per ray, excluding the storage for the voxel data structure itself [S1, unofficial].

**Measured Performance:**
Not given in the sources.

**Scaling:**
Performance scales linearly with the number of samples and the complexity of the volume queries. The single-volume assumption simplifies the loop but limits scalability to complex scenes with multiple media [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Simple implementation, easy to integrate with existing ray tracers, uses Russian Roulette for efficiency [S1, unofficial].
*   **Limitations:** Limited to single volume and single light scenarios in the current implementation, potentially inefficient for large volumes due to fixed step size [S1, unofficial].

**When to Use:**
Use for simple volume rendering tasks where a single medium and light source are sufficient, or as a baseline implementation for educational purposes [S1, unofficial].

**When Not to Use:**
Avoid for complex scenes with multiple scattering media, multiple light sources, or when high performance is required for large volumes without acceleration structures [S1, unofficial].

## Background
Mr-Voxel is a combination of an accelerated voxel data-structure and volume rendering library, developed by C. Gibson as part of his graphics graduate thesis [S1, unofficial]. The lighting equations specific to the volume rendering process are derived or loosely based off the volume rendering sections of "Physically Based Rendering, 2nd edition" by Matt Pharr [S1, unofficial]. The project aims to include importance-sampled light caches for all polygonal, implicit and volume objects in a scene [S1, unofficial].
