# Discrete Ray Tracing

Also called: 3D DDA Voxel Traversal, Naive Voxel-Raycasting

## Overview
Discrete Ray Tracing (DRT) approximates continuous viewing rays with discrete, voxel-connected paths (voxelization) to traverse a 3D scalar field [S7, unofficial]. Unlike methods that rely on geometric primitives or acceleration structures, DRT directly samples the voxel grid using a 3D Digital Differential Analyzer (DDA) or Bresenham-like algorithm, guaranteeing that voxels are visited in the exact order of intersection [S1, unofficial]. This approach limits intersection tests to Pythagorean complexity rather than cubic, ensuring the first opaque voxel found is the closest [S1, unofficial]. It is distinguished from [Fixed Step Ray Marching](3136-fixed-step-ray-marching.md) by its adaptive step size (always moving to the next voxel boundary) and from [Exponential Approximation Method](2079-exponential-approximation-method.md) by its explicit traversal of every voxel along the ray path without skipping [S1, S7, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel grid (scalar field) $V$ of dimensions $W \times H \times D$; camera parameters (position, view vectors, near/far planes); transfer function $T(v) \rightarrow (r, g, b, \alpha)$; projection type (surface, maximum, sum, or composite) [S1, S4, S7, unofficial].
*   **Output:** A 2D image where each pixel $(x, y)$ holds the accumulated color and opacity [S4, unofficial].

**Data Structures:**
*   **Voxel Grid:** A 3D array $V[i, j, k]$ where indices are integers [S1, unofficial]. A voxel is defined as an index in an axis-aligned grid, not a geometric cube with independent position [S1, unofficial].
*   **Ray:** Defined by origin $\mathbf{o}$ and direction $\mathbf{d}$. In DRT, the ray is represented as a sequence of integer voxel coordinates $(i, j, k)$ [S7, unofficial].
*   **Pixel Accumulator:** A 4-tuple $(R, G, B, A)$ initialized to $(0, 0, 0, 0)$ [S4, unofficial].

**Algorithm Steps:**

1.  **Ray Setup:**
    For each pixel $(x, y)$ in the image plane:
    *   Calculate the ray direction $\mathbf{d}$ using bilinear interpolation of the four viewport corner normals [S1, unofficial].
    *   Set ray origin $\mathbf{o}$ to the camera position (for perspective) or a point on the near plane (for orthographic) [S1, S4, unofficial].
    *   *Note:* For orthographic projection along the Z-axis, $\mathbf{d} = (0, 0, 1)$ and $\mathbf{o} = (x/W, y/H, \text{near\_plane})$ [S4, unofficial].

2.  **Voxelization (Ray Traversal):**
    Generate a discrete path of voxels intersected by the ray using a 3D DDA algorithm [S7, unofficial].
    *   Initialize current voxel coordinates $(i, j, k)$ to the voxel containing $\mathbf{o}$:
        $$ i = \lfloor \mathbf{o}_x \cdot W - 0.5 \rfloor, \quad j = \lfloor \mathbf{o}_y \cdot H - 0.5 \rfloor, \quad k = \lfloor \mathbf{o}_z \cdot D - 0.5 \rfloor $$
        The $-0.5$ offset centers the sampling within the voxel [S4, unofficial].
    *   Determine the step direction $(\Delta i, \Delta j, \Delta k) \in \{-1, 0, 1\}$ based on the sign of $\mathbf{d}$ [G].
    *   Calculate the distance to the next voxel boundary in each axis:
        $$ t_{i} = \frac{\text{boundary}_i - \mathbf{o}_x}{\mathbf{d}_x} \quad \text{(if } \mathbf{d}_x \neq 0 \text{)} $$
        (Similar formulas for $t_j, t_k$) [G].
    *   While the ray is within the volume bounds:
        1.  Sample the scalar value $v = V[i, j, k]$ [S4, unofficial].
        2.  Apply the transfer function to get color $\mathbf{c} = (r, g, b)$ and opacity $\alpha$ [S4, unofficial].
        3.  Composite the sample into the pixel accumulator using the front-to-back over operator [S4, unofficial]:
            $$ \mathbf{C}_{out} = \mathbf{C}_{in} + (1 - A_{in}) \cdot \mathbf{c} \cdot \alpha $$
            $$ A_{out} = A_{in} + (1 - A_{in}) \cdot \alpha $$
        4.  If using surface projection, stop at the first non-transparent voxel [S7, unofficial].
        5.  Advance to the next voxel:
            *   Find the axis with the smallest positive $t$ (distance to next boundary) [G].
            *   Increment/decrement the coordinate on that axis by 1 [G].
            *   Update the boundary distance for that axis [G].

3.  **Projection Variants:**
    *   **Composite:** Accumulate all samples along the ray using the over operator [S4, unofficial].
    *   **Maximum:** Store the maximum scalar value encountered [S7, unofficial].
    *   **Sum/Average:** Accumulate scalar values (X-ray simulation) [S7, unofficial].

**Pseudocode:**

```python
import math

def discrete_ray_tracing(volume, width, height, depth, camera_pos, view_vectors):
    """
    volume: 3D list of lists of lists (W, H, D)
    camera_pos: (ox, oy, oz)
    view_vectors: dict with 'upperLeft', 'upperRight', 'lowerLeft', 'lowerRight' (tuples)
    """
    image = [[0.0, 0.0, 0.0, 0.0] for _ in range(height * width)]
    
    inv_h = 1.0 / height
    inv_w = 1.0 / width
    
    ul_n = normalize(view_vectors['upperLeft'])
    ur_n = normalize(view_vectors['upperRight'])
    ll_n = normalize(view_vectors['lowerLeft'])
    lr_n = normalize(view_vectors['lowerRight'])
    
    left_y_delta = tuple(ll_n[i] - ul_n[i] for i in range(3)) * inv_h
    right_y_delta = tuple(lr_n[i] - ur_n[i] for i in range(3)) * inv_h
    
    left_normal = ul_n
    right_normal = ur_n
    
    for y in range(height):
        x_delta = tuple(right_normal[i] - left_normal[i] for i in range(3)) * inv_w
        ray_dir = left_normal
        
        for x in range(width):
            acc_r, acc_g, acc_b, acc_a = 0.0, 0.0, 0.0, 0.0
            
            # Map ray to voxel space for traversal
            # In practice, origin is mapped from world to voxel coordinates.
            ray_origin = (0.0, 0.0, 0.0)
            
            for i, j, k in get_voxel_path(ray_origin, ray_dir, width, height, depth):
                val = volume[i][j][k]
                
                # Transfer function (Gaussian Mixtures from S4)
                r = math.exp(-((val - 9.0)**2) / 1.0) + 0.1 * math.exp(-((val - 3.0)**2) / 0.1) + 0.1 * math.exp(-((val + 3.0)**2) / 0.5)
                g = math.exp(-((val - 9.0)**2) / 1.0) + math.exp(-((val - 3.0)**2) / 0.1) + 0.1 * math.exp(-((val + 3.0)**2) / 0.5)
                b = 0.1 * math.exp(-((val - 9.0)**2) / 1.0) + 0.1 * math.exp(-((val - 3.0)**2) / 0.1) + math.exp(-((val + 3.0)**2) / 0.5)
                a = 0.6 * math.exp(-((val - 9.0)**2) / 1.0) + 0.1 * math.exp(-((val - 3.0)**2) / 0.1) + 0.01 * math.exp(-((val + 3.0)**2) / 0.5)
                
                acc_r += (1.0 - acc_a) * r * a
                acc_g += (1.0 - acc_a) * g * a
                acc_b += (1.0 - acc_a) * b * a
                acc_a += (1.0 - acc_a) * a
                
                if acc_a >= 1.0:
                    break
            
            image[y * width + x] = [acc_r, acc_g, acc_b, acc_a]
            ray_dir = tuple(ray_dir[i] + x_delta[i] for i in range(3))
            
        left_normal = tuple(left_normal[i] + left_y_delta[i] for i in range(3))
        right_normal = tuple(right_normal[i] + right_y_delta[i] for i in range(3))
        
    return image

def normalize(v):
    mag = math.sqrt(sum(c*c for c in v))
    return tuple(c/mag for c in v)

def get_voxel_path(origin, direction, w, h, d):
    """
    Yields voxel indices (i, j, k) along the ray defined by direction.
    Uses 3D DDA [G].
    """
    ix = math.floor(origin[0])
    iy = math.floor(origin[1])
    iz = math.floor(origin[2])
    
    step_x = 1 if direction[0] > 0 else -1
    step_y = 1 if direction[1] > 0 else -1
    step_z = 1 if direction[2] > 0 else -1
    
    t_max_x = ( (ix + (1 if step_x > 0 else 0)) - origin[0] ) / direction[0] if direction[0] != 0 else float('inf')
    t_max_y = ( (iy + (1 if step_y > 0 else 0)) - origin[1] ) / direction[1] if direction[1] != 0 else float('inf')
    t_max_z = ( (iz + (1 if step_z > 0 else 0)) - origin[2] ) / direction[2] if direction[2] != 0 else float('inf')
    
    t_delta_x = abs(1.0 / direction[0]) if direction[0] != 0 else float('inf')
    t_delta_y = abs(1.0 / direction[1]) if direction[1] != 0 else float('inf')
    t_delta_z = abs(1.0 / direction[2]) if direction[2] != 0 else float('inf')
    
    while 0 <= ix < w and 0 <= iy < h and 0 <= iz < d:
        yield ix, iy, iz
        
        if t_max_x < t_max_y:
            if t_max_x < t_max_z:
                ix += step_x
                t_max_x += t_delta_x
            else:
                iz += step_z
                t_max_z += t_delta_z
        else:
            if t_max_y < t_max_z:
                iy += step_y
                t_max_y += t_delta_y
            else:
                iz += step_z
                t_max_z += t_delta_z
```

**Edge Cases and Pitfalls:**
*   **Aliasing:** Using nearest-neighbor sampling (flooring coordinates) can result in blocky artifacts at low resolutions [S4, unofficial].
*   **Connectivity:** The choice of 6-, 18-, or 26-connected paths affects accuracy and performance. 6-connected paths contain almost twice as many voxels as 26-connected paths. 26-connected paths are faster but may miss intersections detected by 6-connected paths [S7, unofficial].
*   **Performance:** High number of texture accesses and multiplications per ray leads to low frame rates for large or sparse volumes [S2, unofficial].
*   **Voxel Definition:** Voxels are indices, not geometric cubes. They do not move [S1, unofficial].

## Subtopics

### [Cube-3 Hybrid Ray-Casting](3143-cube-3-hybrid-ray-casting.md)
A hardware-oriented hybrid algorithm for real-time visualization of high-resolution volumes ($512^3$). It ensures each voxel is read at most once per projection using a Cubic Frame Buffer and global communication network, exploiting spatial coherency. Choose when memory bandwidth is the bottleneck and hardware support for skewed memory organization exists.

## Operating characteristics
*   **Time Complexity:** $O(n)$, where $n$ is the number of voxels traversed along the ray [S2, unofficial]. In the worst case, $n$ is proportional to the volume dimension in the view direction [G].
*   **Memory Complexity:** $O(1)$ auxiliary space per ray (excluding the volume storage) [G].
*   **Performance:** Suitable for small, dense voxel entities (e.g., $50^3$ or $100^3$) where modifications are frequent and acceleration structures cannot be updated efficiently [S2, unofficial]. Performance degrades significantly for large, sparse volumes due to the lack of acceleration structures [S2, unofficial].
*   **Strengths:** Simple implementation; no need for acceleration structures; guarantees closest intersection; insensitive to scene complexity (only one primitive type: voxel) [S7, unofficial].
*   **Limitations:** Low frame rates for large or sparse volumes due to high texture accesses and multiplications [S2, unofficial].

## Background
Discrete Ray Tracing was proposed by Yagel, Cohen, and Kaufman as a method for fast parallel implementation of volume rendering [S3, S7, unofficial]. It allows rendering 3D sampled datasets like MRI or fluid dynamics simulations directly, avoiding the approximation of sampled data with geometric primitives [S5, unofficial]. The method leverages the 3D DDA algorithm, originally used in computer graphics for line rasterization, to traverse voxel grids efficiently [S1, unofficial].
