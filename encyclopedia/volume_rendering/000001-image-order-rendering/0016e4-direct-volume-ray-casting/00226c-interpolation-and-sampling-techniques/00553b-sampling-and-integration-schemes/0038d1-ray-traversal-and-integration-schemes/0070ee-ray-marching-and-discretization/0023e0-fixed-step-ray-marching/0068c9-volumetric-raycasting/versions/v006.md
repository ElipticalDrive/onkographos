# Volumetric Raycasting

Also called: Direct Ray Casting, Direct Volume Rendering Ray Casting, Direct Volume Rendering via Ray Casting, Ray Casting (Volume Rendering), Ray Marching Volume Rendering, 光线投射算法

## Overview
Volumetric Raycasting is a direct volume rendering technique that visualizes 3D scalar or vector fields by casting rays from the camera through the volume for each pixel, sampling density and color along the path, and compositing the results front-to-back using alpha blending [S1, S2, S3, unofficial][S4, book][S5, S10, S24, S30, unofficial]. It solves the problem of rendering translucent, heterogeneous volumes (such as smoke, clouds, or medical CT data) where internal structures must be visible simultaneously, without converting the volume into a polygonal mesh [S9][S17, unofficial][S23][S31, unofficial]. Unlike image-space techniques that reconstruct rays from screen-space depth, Volumetric Raycasting explicitly computes ray-volume intersections in world or object space, allowing for precise control over sampling density and integration accuracy [S1, unofficial][S22]. It differs from its sibling [Ray Marching Volume Rendering with Henyey-Greenstein Scattering](2545-ray-marching-volume-rendering-with-henyey-greenstein-scatter.md) by typically focusing on absorption/emission compositing rather than complex scattering phase functions, and from [Ray Evaluation Stepping DVR](3461-ray-evaluation-stepping-dvr.md) by using a fixed or adaptive step size along the ray rather than evaluating specific discrete points [S2, S10, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A 3D volume texture (scalar field for density, optionally vector field for color/emission), camera parameters (position $\mathbf{o}$, direction $\mathbf{d}$, projection matrices), volume bounding box (AABB), and rendering parameters (step size $\Delta t$ or number of steps $N$, transfer function, light sources) [S2, unofficial][S4, book][S5, S10, S24, S30, unofficial].
*   **Outputs:** A 2D image where each pixel contains the accumulated color and opacity of the volume along the corresponding ray [S1, unofficial][S4, book][S10, S24, unofficial].

**Data Structures:**
*   **Volume Texture:** Typically a 3D texture (or 2D texture array/sliced 2D texture for older APIs) storing density values. In some implementations, color is stored in a separate 3D texture or computed on-the-fly [S4, book][S6, S10, S13, S30, unofficial].
*   **Bounding Box:** An Axis-Aligned Bounding Box (AABB) defined by minimum and maximum coordinates (e.g., $[-0.5, 0.5]^3$ or $[0, 1]^3$) used for ray intersection tests [S5, S7, S10, S14, unofficial].
*   **Transfer Function:** A 1D or 2D texture mapping density values to RGBA color and opacity [S11, S13, S24, unofficial].

**Numbered Steps:**

1.  **Ray Generation:** For each pixel $(u, v)$ in the image, compute the ray origin $\mathbf{o}$ (camera position) and direction $\mathbf{d}$ in world or object space. This is done by unprojecting the pixel's normalized device coordinates (NDC) through the inverse projection and model-view matrices [S2, S5, S7, S10, S29, unofficial].
    *   $\mathbf{d} = \text{normalize}(\mathbf{P}^{-1} \mathbf{p} - \mathbf{o})$, where $\mathbf{p}$ is the pixel coordinate and $\mathbf{P}^{-1}$ is the camera-to-world matrix [S29, unofficial].
    *   Alternatively, in clip space: $\mathbf{rayClip} = (u, v, -1, 1)$, then transform to eye space and normalize [S2, unofficial].

2.  **Ray-Box Intersection:** Compute the intersection of the ray with the volume's bounding box to determine the entry ($t_{near}$) and exit ($t_{far}$) distances.
    *   Using the slab method: $t_{min/max} = (box_{min/max} - o) / d$.
    *   $t_{near} = \max(t_{min})$, $t_{far} = \min(t_{max})$ [S10, S14, unofficial].
    *   If $t_{near} > t_{far}$ or $t_{far} < 0$, the ray misses the volume; discard the pixel [S10, S14, unofficial].
    *   Adjust $t_{near}$ slightly inward (e.g., $t_{near} += \epsilon$) to avoid boundary precision errors [S10, unofficial].

3.  **Initialization:** Initialize accumulation variables:
    *   Transmittance $T = 1.0$ (or accumulated opacity $\alpha_{acc} = 0$) [S3, S10, S30, unofficial].
    *   Accumulated Color $C_{acc} = (0, 0, 0)$ [S3, S10, S30, unofficial].
    *   Current position $\mathbf{pos} = \mathbf{o} + t_{near} \mathbf{d}$ [S10, S30, unofficial].

4.  **Ray Marching Loop:** Iterate for a fixed number of steps $N$ or until the ray exits the volume ($t > t_{far}$) or transmittance drops below a threshold [S2, S10, S30, unofficial].
    *   **Step Size Calculation:** Determine the distance to advance per step.
        *   Fixed step size: $\Delta t = (t_{far} - t_{near}) / N$ [S3, S10, unofficial].
        *   Pixel-based step size: $\Delta t = \text{pixel\_size} \times \text{factor}$, where pixel size depends on volume resolution [S6, unofficial].
        *   Diagonal normalization: $\Delta t = \sqrt{3} / N$ for a unit cube to ensure consistent sampling density regardless of view angle [S10, S16, unofficial].
    *   **Sampling:** Sample the volume density $\rho$ at the current position $\mathbf{pos}$ using trilinear interpolation [S1, S10, unofficial][S23][S30, unofficial].
        *   If color is stored in the volume, sample color $c$ as well [S30, unofficial].
        *   If color is computed, apply a transfer function to map $\rho$ to $c$ and opacity $\alpha_{sample}$ [S24, unofficial].
    *   **Opacity/Alpha Calculation:** Compute the opacity contribution of the current step.
        *   Linear approximation: $\alpha_{sample} = \rho \cdot \Delta t$ [S2, S11, S30, unofficial].
        *   Exponential (Beer-Lambert): $\alpha_i = 1 - e^{-\sigma_i \Delta t}$, where $\sigma_i$ is the extinction coefficient (often equal to density) [S3, S29, unofficial].
    *   **Compositing (Front-to-Back):** Update the accumulated color and transmittance.
        *   Weight: $w_i = T \cdot \alpha_{sample}$ [S3, S27, unofficial].
        *   Update Color: $C_{acc}^{new} = C_{acc}^{old} + w_i \cdot c$ [S3, S27, S30, unofficial].
            *   Note: Some implementations use $C_{acc} += (1 - \alpha_{acc}) \cdot c \cdot \alpha_{sample}$ [S30, unofficial].
        *   Update Transmittance: $T^{new} = T^{old} \cdot (1 - \alpha_{sample})$ [S3, S10, S27, S30, unofficial].
            *   Or update accumulated opacity: $\alpha_{acc}^{new} = \alpha_{acc}^{old} + (1 - \alpha_{acc}^{old}) \cdot \alpha_{sample}$ [S2, S30, unofficial].
    *   **Advance:** $\mathbf{pos} = \mathbf{pos} + \mathbf{d} \cdot \Delta t$ [S10, S30, unofficial].

5.  **Final Composition:** Combine the accumulated volume color with the background color $C_{bg}$ (e.g., sky color or clear color).
    *   $C_{out} = C_{acc} + T \cdot C_{bg}$ [S3, S10, unofficial].
    *   Or $C_{out} = C_{acc} / (1 - T)$ if $C_{acc}$ was weighted differently [S30, unofficial].
    *   Output the final color and opacity $1 - T$ [S10, S30, unofficial].

**Formulas:**
*   **Ray Equation:** $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ [S27, unofficial].
*   **Step Size (Unit Cube):** $\Delta t = \frac{\sqrt{3}}{N}$ [S10, unofficial].
*   **Opacity per Step:** $\alpha_{sample} = \rho \cdot \Delta t$ [S2, S11, S30, unofficial].
*   **Transmittance:** $T = e^{-\tau}$, where $\tau = \sum \rho_i \Delta t_i$ [S26, unofficial].
*   **Accumulated Color:** $C = \sum_{i=1}^{M} T_i \alpha_i c_i$, where $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ [S27, unofficial].

**Parameters:**
*   **Number of Steps ($N$ or `maxSteps`):** Controls sampling density. Typical values: 32–128 for real-time, higher for offline [S3, S5, S7, S10, S11, S14, S20, S29, S30, unofficial].
*   **Step Size ($\Delta t$):** Distance between samples. Smaller values increase quality but reduce performance [S4, book][S6, S15, S30, unofficial].
*   **Density Multiplier (`densityMult` or `DENSITY_MULTIPLIER`):** Scales sampled density to adjust visibility. Typical value: 1.0–50.0 [S2, S5, S7, S14, unofficial].
*   **Background Color (`background_color`):** Color behind the volume. Typical value: Sky blue or black [S3, S10, S30, unofficial].

**Edge Cases and Pitfalls:**
*   **Aliasing/Moiré:** If the step size is too large relative to the volume features or transfer function gradients, aliasing artifacts appear. Adaptive step sizing or supersampling can mitigate this [S23].
*   **Boundary Errors:** Rays starting exactly on the volume boundary may sample incorrectly. Adjusting $t_{near}$ by a small epsilon ($\epsilon$) prevents this [S10, unofficial].
*   **Overshooting:** Fixed step sizes may skip thin structures. Refinement techniques like binary search can help but add cost [S32, unofficial].
*   **Performance:** The number of samples is proportional to the image resolution and the number of steps. High-resolution volumes require careful optimization (e.g., frustum culling, early ray termination) [S4, book][S6, S20, unofficial].

**Pseudocode:**
```python
def volumetric_ray_casting(ray_origin, ray_direction, volume_texture, bbox_min, bbox_max, num_steps, transfer_function, background_color):
    # 1. Ray-Box Intersection (Slab Method)
    inv_dir = 1.0 / ray_direction
    t_min = (bbox_min - ray_origin) * inv_dir
    t_max = (bbox_max - ray_origin) * inv_dir
    t_near = max(min(t_min), min(t_max))
    t_far = min(max(t_min), max(t_max))
    
    # Adjust for boundary errors
    t_near += 1e-6
    
    # If no intersection, return background
    if t_near > t_far or t_far < 0:
        return background_color, 1.0

    # 2. Initialization
    step_size = (t_far - t_near) / num_steps
    pos = ray_origin + ray_direction * t_near
    accumulated_color = vec3(0.0, 0.0, 0.0)
    transmittance = 1.0
    
    # 3. Ray Marching Loop
    for i in range(num_steps):
        # Check if we have exited the volume
        if pos.x < bbox_min.x or pos.x > bbox_max.x or \
           pos.y < bbox_min.y or pos.y > bbox_max.y or \
           pos.z < bbox_min.z or pos.z > bbox_max.z:
            break
            
        # Early ray termination (optional optimization)
        if transmittance < 0.01:
            break

        # Sample density
        density = volume_texture.sample_trilinear(pos)
        
        # Compute opacity for this step
        alpha_sample = density * step_size
        
        # Apply transfer function to get color
        color_sample = transfer_function(density)
        
        # Compositing
        weight = transmittance * alpha_sample
        accumulated_color += weight * color_sample
        transmittance *= (1.0 - alpha_sample)
        
        # Advance position
        pos += ray_direction * step_size

    # 4. Final Composition
    final_color = accumulated_color + transmittance * background_color
    return final_color, 1.0 - transmittance
```

## Subtopics

### [Ray Marching Volume Rendering with Geometry Occlusion](2066-ray-marching-volume-rendering-with-geometry-occlusion.md)
A front-to-back ray marching technique that renders a 3D volume texture by stepping along rays from the camera, compositing color and opacity, and using pre-rendered opaque geometry to occlude the volume and adjust sampling rates. It solves the problem of self-occlusion in volume rendering by decoupling the occlusion estimation from the ray step, using spatial averaging of a pre-rendered occlusion texture to modulate the current slice's contribution. Unlike standard front-to-back ray casting which integrates opacity along the ray, this method stops the volume march at opaque geometry surfaces, preventing the volume from rendering "through" solid objects. It differs from its sibling [Volumetric Raycasting](3462-volumetric-raycasting.md) by explicitly handling geometry occlusion via depth buffer checks, and from [Image-space Volume Ray Marching](20131-image-space-volume-ray-marching.md) by relying on explicit bounding box intersection rather than screen-space ray reconstruction.

### [Volumetric Ray Marching for Fire](2578-volumetric-ray-marching-for-fire.md)
Volumetric Ray Marching for Fire is a GPU-based technique for rendering fire and smoke simulations by ray marching through 3D volume textures. It decouples the simulation from the rendering pipeline, allowing multiple fire instances to share a fixed pool of simulation resources while rendering them via fragment shaders that sample temperature and smoke density fields. It composites emissive fire and absorptive smoke using front-to-back alpha blending while using a scene depth buffer for occlusion culling. The final pixel color is calculated as the average of the samples weighted by the length of the ray inside the target volume. It builds on [Ray Marching Volume Rendering](1735-ray-marching-volume-rendering.md) by adding specific fire physics (temperature-based emission) and a shared simulation slot architecture.

### [Raycasting with Transfer Function and Shading](3773-raycasting-with-transfer-function-and-shading.md)
This method performs direct volume ray casting by sampling a 3D texture storing pre-computed integer isovalue and gradient magnitude data, allowing the fragment shader to sample surface properties directly without numerical differentiation. It distinguishes itself from standard raycasting by weighting the transfer function opacity with the gradient magnitude to enhance edges and surfaces, and by using a lookup-based approach for lighting and visibility selection. It builds on [Volumetric Raycasting](3462-volumetric-raycasting.md) by replacing on-the-fly gradient computation with pre-sampled gradient magnitudes and adding isovalue-based selection logic.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot R)$, where $N$ is the number of pixels (resolution) and $R$ is the number of samples per ray. Performance is linear with respect to both resolution and sample count [S4, book][S20, unofficial].
*   **Memory Complexity:** $O(V)$, where $V$ is the size of the 3D volume texture. Additional memory is required for intermediate buffers if multi-pass techniques are used [S4, book][S12, unofficial].
*   **Measured Performance:** Real-time performance (30+ FPS) is achievable on modern GPUs for volumes up to $256^3$ with 32–128 steps per ray [S6, S7, S10, S14, unofficial]. Higher resolutions or step counts require optimization techniques like frustum culling, early ray termination, or adaptive stepping [S6, S20, unofficial].
*   **Scaling:** Scales well with GPU parallelism as each pixel's ray is independent. However, memory bandwidth becomes a bottleneck for large volumes [S4, book][S6, unofficial].
*   **Strengths:** High visual quality, handles complex internal structures, supports arbitrary transfer functions, and integrates naturally with lighting and shadowing [S9][S17, unofficial][S23].
*   **Limitations:** Computationally expensive for high-resolution volumes, prone to aliasing if step size is not tuned, and difficult to accelerate with traditional triangle-based spatial structures (requires voxel-based acceleration like 3D grids or octrees) [S4, book][S23].
*   **When to Use:** Ideal for scientific visualization (CT/MRI scans), atmospheric effects (smoke, clouds), and real-time volumetric effects in games where visual fidelity is prioritized over extreme performance [S4, book][S6, unofficial][S9, S23].
*   **When Not to Use:** When rendering extremely large volumes (e.g., global climate models) where performance is critical, or when the volume is sparse and sparse voxel octrees (SVO) or ray marching with depth testing are more appropriate [S1, S18412-ray-marching-with-depth-testing.md, unofficial].

## Background
Volumetric Raycasting originated in the early 1990s as a method for visualizing 3D scalar fields without surface extraction. Key early works include the "Projected Tetrahedra" method by Shirley and Tuchman (1990) and the development of direct volume rendering techniques that integrated opacity and color along rays [S1, unofficial]. The technique became widely adopted with the advent of GPU hardware acceleration, allowing real-time ray marching through 3D textures in fragment shaders [S4, book][S6, S10, unofficial]. It is now a standard technique in medical imaging, scientific visualization, and real-time graphics engines [S9][S17, unofficial][S23].
