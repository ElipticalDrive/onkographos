# Ray Marching and Discretization

Also called: Front-to-Back Accumulation, Ray Marching (Core Algorithm), Ray Marching for Volume Rendering, Volume Ray Marching (Basic)

## Overview
Ray Marching and Discretization is the fundamental iterative algorithm for solving the volume rendering equation in image-order rendering by sampling volumetric data at discrete intervals along camera rays [S1][S6, unofficial]. It solves the problem of integrating light transport through participating media by approximating the continuous integral with a finite sum of sampled contributions, enabling real-time performance on GPUs [S1][S2, unofficial]. It differs from [Ray Traversal Schemes](6890-ray-traversal-schemes.md) by using fixed or adaptive step sizes guided by distance estimators rather than voxel connectivity traversal, and from [Monte Carlo Path Tracing for Volume Rendering](4980-monte-carlo-path-tracing-for-volume-rendering.md) by using deterministic quadrature instead of stochastic sampling [S3, S4].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera position $\mathbf{o}$, ray direction $\mathbf{d}$, volume domain bounds (min/max coordinates), volume texture (3D texture or procedural function), transfer function (colormap), and step parameters (number of steps $N$ or step size $\Delta s$) [S2, S5, unofficial][S9].
*   **Outputs:** Final pixel color $C_{out}$ and accumulated opacity $\alpha_{out}$ [S2, S5, unofficial].

**Data Structures:**
*   **Volume Texture:** A 3D texture storing scalar density values. Layout is typically $W \times H \times D$ voxels, accessed via normalized coordinates $[0, 1]^3$ [S2, unofficial][S9].
*   **Colormap:** A 1D or 2D texture mapping scalar values to RGBA color and opacity [S9].
*   **Accumulators:** Two vectors (or `vec4` in GLSL) for current accumulated color $C_{in}$ and opacity $\alpha_{in}$, initialized to $(0, 0, 0, 0)$ [S2, S5, unofficial][S9].

**Steps:**

1.  **Ray Generation and Intersection:**
    Define the ray $r(t) = \mathbf{o} + t\mathbf{d}$. Intersect the ray with the volume's bounding box to find the entry parameter $t_{near}$ and exit parameter $t_{far}$ [S5, unofficial]. If no intersection occurs, discard the pixel [S5, unofficial].
    $$ t_{near} = \max(\max(\frac{boxMin - o}{d}), 0) $$
    $$ t_{far} = \min(\min(\frac{boxMax - o}{d})) $$
    If $t_{near} > t_{far}$, the ray misses the volume [S5, unofficial].

2.  **Discretization:**
    Calculate the total path length $L = t_{far} - t_{near}$. Determine the step size $\Delta s$. This can be fixed based on a user-defined number of steps $N$:
    $$ \Delta s = \frac{L}{N} $$
    Or derived from a fixed step length parameter [S5, unofficial][S9].

3.  **Marching Loop:**
    Iterate $i$ from $0$ to $N-1$ (or while transmittance is significant):
    a. **Sample Position:** Calculate the current position $\mathbf{p}_i$ along the ray.
    $$ \mathbf{p}_i = \mathbf{o} + (t_{near} + i \cdot \Delta s) \mathbf{d} $$
    b. **Query Volume:** Retrieve the scalar density value $V(\mathbf{p}_i)$ from the volume texture using trilinear interpolation [S2, S5, unofficial].
    c. **Classification:** Map $V(\mathbf{p}_i)$ to color $C_i$ and opacity $\alpha_i$.
       *   **Color:** $C_i = \text{Colormap}(V(\mathbf{p}_i))$ [S9].
       *   **Opacity:** Calculate $\alpha_i$ using the Beer-Lambert law approximation for the step size $\Delta s$:
       $$ \alpha_i = 1 - e^{-\sigma_i \Delta s} $$
       where $\sigma_i$ is the extinction coefficient, often derived from $V(\mathbf{p}_i)$ (e.g., $\sigma_i = V(\mathbf{p}_i) \cdot \text{extinctionMultiplier}$) [S5, unofficial]. Alternatively, for low albedo or simplified models, $\alpha_i$ may be directly proportional to $V(\mathbf{p}_i)$ and a base alpha step [S9].
    d. **Compositing:** Update accumulated color and opacity using front-to-back blending:
    $$ C_{out} = C_{in} + (1 - \alpha_{in}) \cdot C_i \cdot \alpha_i $$
    $$ \alpha_{out} = \alpha_{in} + (1 - \alpha_{in}) \cdot \alpha_i $$
    e. **Early Termination:** If $\alpha_{out}$ exceeds a threshold (e.g., 0.95 or 0.99), break the loop [S2, S5, unofficial][S9].

**Pseudocode:**

```python
def ray_march(volume_texture, colormap, camera_pos, ray_dir, box_min, box_max, num_steps):
    # 1. Ray-Box Intersection
    # Calculate intersection parameters t_near and t_far
    t_min = (box_min - camera_pos) / ray_dir
    t_max = (box_max - camera_pos) / ray_dir
    
    t_enter = max(max(t_min.x, t_min.y), t_min.z)
    t_exit = min(min(t_max.x, t_max.y), t_max.z)
    
    # If ray misses or starts inside and exits behind, handle appropriately
    if t_enter > t_exit:
        return (0.0, 0.0, 0.0, 0.0)
    
    # Ensure we start inside the box if the ray origin is outside
    t_start = max(t_enter, 0.0)
    
    # 2. Discretization
    step_length = (t_exit - t_start) / num_steps
    
    # 3. Initialization
    acc_color = (0.0, 0.0, 0.0)
    acc_alpha = 0.0
    
    # 4. Marching Loop
    for i in range(num_steps):
        # Current distance along ray
        t = t_start + i * step_length
        
        # Current position
        pos = camera_pos + t * ray_dir
        
        # Normalize position to [0, 1] for texture lookup (assuming box maps to [0,1])
        # This depends on specific coordinate system; here we assume normalized space
        norm_pos = (pos - box_min) / (box_max - box_min)
        
        # Check bounds to avoid out-of-bounds sampling
        if not (0.0 <= norm_pos.x <= 1.0 and 0.0 <= norm_pos.y <= 1.0 and 0.0 <= norm_pos.z <= 1.0):
            continue
            
        # Sample volume density
        density = volume_texture.sample_trilinear(norm_pos)
        
        # Skip empty or out-of-range density
        if density <= 0.0:
            continue
            
        # Classification: Map density to color and opacity
        # Example: Simple linear mapping for opacity, colormap for color
        # Extinction coefficient sigma
        sigma = density 
        
        # Opacity for this step (Beer-Lambert)
        alpha_step = 1.0 - exp(-sigma * step_length)
        
        # Color from colormap
        color_step = colormap.sample_1d(density)
        
        # Front-to-Back Compositing
        # Transmittance from previous steps
        transmittance = 1.0 - acc_alpha
        
        # Contribution of current step
        contribution = transmittance * color_step * alpha_step
        
        acc_color = acc_color + contribution
        acc_alpha = acc_alpha + transmittance * alpha_step
        
        # Early Ray Termination
        if acc_alpha >= 0.99:
            break
            
    return (acc_color, acc_alpha)
```

**Parameters:**
*   `num_steps` (or `RAY_STEPS`): Integer, typically 64-300. Higher values increase quality but reduce performance [S2, S5, unofficial].
*   `stepLength`: Real, controls step size. Can be fixed or adaptive [S9].
*   `extinctionMultiplier`: Real, scales density to extinction coefficient [S5, unofficial].
*   `minCutoffValue` / `maxCutoffValue`: Real, defines the transfer function range where alpha is non-zero [S5, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point errors in ray-box intersection can cause rays to miss the volume or sample outside bounds. Use epsilon checks [S5, unofficial].
*   **Aliasing:** Fixed step sizes can cause aliasing artifacts. Randomizing the start position (`useRandomStart`) can help soften edges [S5, unofficial].
*   **Early Termination:** While it saves performance, it can lead to inaccurate transparency in thin, highly transparent regions if the threshold is too high [S9].
*   **Boundary Conditions:** Sampling outside the volume texture bounds must be handled (e.g., clamp to edge or return 0 density) [S2, unofficial].

### Low Albedo Discrete VRE (Alpha Blending Form)
A discrete VRE form derived by approximating transmittance using the first two terms of its Taylor series expansion and assuming low albedo ($\sigma_t \approx \sigma_a, \sigma_s \approx 0$) [S11]. The opacity is approximated as $\alpha_i \approx \sigma_a(\mathbf{p}_i, \omega) \Delta s$ [S11]. The final color is computed as $C = \sum_{i=0}^{N-1} C_i \alpha_i \prod_{j=i+1}^{N-1} (1 - \alpha_j)$, where $C_i$ refers to emission $L_e$ [S11]. This differs from standard discrete VRE by applying low albedo and Taylor series approximations, interpreting the result as alpha blending [S11].

### Beam Pre-pass
A coarse pre-pass that computes first-hit distances at low resolution (e.g., 1/8 resolution, one ray per 8x8 block) to fast-forward the main raymarch pass [S12, unofficial]. Each ray walks the world at tile granularity and writes the first-hit distance to an `r32float` texture. The main pass then fast-forwards each ray to that depth minus a 16-voxel safety margin [S12, unofficial].

### ROVER Volume Rendering Pipeline
A distributed ray casting method that initializes rays with a fixed direction $(1.0, 1.0, 1.0)$ and computes a uniform sample distance from domain bounds [S13, unofficial]. The sample distance is calculated as $\text{sample\_distance} = \text{magnitude}(\text{domain\_extent}) / \text{num\_samples}$, where $\text{domain\_extent} = (X_{max}-X_{min}, Y_{max}-Y_{min}, Z_{max}-Z_{min})$ [S13, unofficial]. It delegates the marching loop to a VTK-m proxy tracer [S13, unofficial]. Pitfalls include runtime errors if called without a valid dataset or primary field [S13, unofficial].

### Parallel Analytic Marching
A parallelization strategy where multiple initial points are solved simultaneously to march towards all unsolved analytic cells in the active set [S14]. It initializes multiple points $\mathbf{x}$ in $\mathbb{Z}$ in parallel by solving Eq 17, instead of a single point [S14]. This achieves an efficiency improvement of order 10 on Nvidia GPUs compared to sequential execution [S14].

### Interpolated Shading
A technique that uses linear interpolation to shade entire patches of up to 10x10 pixels, allowing for fewer than one sample per pixel [S15, unofficial]. It queries ahead of the current position, checks if all four corners of the current quad are inside the object and if normals are aligned, then interpolates shading [S15, unofficial]. This is an approximation that likely only makes sense for flat-shaded objects [S15, unofficial]. On a MacBook Air M1, it renders a simple SDF object at up to 100 FPS [S15, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of samples per ray and $P$ is the number of pixels [S5, unofficial]. Performance scales linearly with the number of steps [S5, unofficial].
*   **Memory Complexity:** $O(V)$ for the volume texture, where $V$ is the number of voxels [S2, unofficial][S9].
*   **Performance:** Real-time performance is achievable on GPUs, especially with early ray termination and fixed step counts [S1][S2, unofficial]. Performance is highly dependent on the number of steps and the density of the volume [S5, unofficial].
*   **Strengths:** Simple to implement, efficient on GPUs, supports real-time interaction [S1][S2, unofficial].
*   **Limitations:** Fixed step sizes can lead to aliasing or inefficiency in sparse volumes [S3]. Early termination can cause inaccuracies in transparent regions [S9]. Biased estimates if transmittance is not handled correctly [S4].
*   **When to Use:** Real-time volume rendering, interactive visualization, when performance is prioritized over exact physical accuracy [S1][S2, unofficial].
*   **When Not to Use:** When exact physical accuracy is required (use Monte Carlo methods), or when the volume is extremely sparse and adaptive traversal is more efficient [S3, S4].

## Background
Ray marching for volume rendering was introduced as an efficient method to solve the volume rendering equation with real-time performance [S1]. It has been widely implemented in GPU-based rendering pipelines, such as OpenGL fragment shaders [S2, unofficial] and WebGL libraries like Three.js [S5, unofficial]. It is also used in scientific visualization frameworks like Qt Quick 3D [S9] and Jrender [S1]. The method is foundational for rendering Neural Radiance Fields (NeRF) and Signed Distance Functions (SDFs) [S6, unofficial].
