# Volumetric Sun Shafts (God Rays)

Also called: Haze volumetrics, In-scattered light shafts

## Overview
A post-processing technique that renders volumetric light shafts (sun shafts) by marching a view ray through a sun shadow map, accumulating in-scattered light where the ray is lit and no light where it is shadowed, modulated by ground-hugging haze density [S1, unofficial]. It differs from screen-space alternatives like [Screen-Space God Rays](3981-screen-space-god-rays.md) by relying on a dedicated shadow map for occlusion rather than screen-space depth, allowing accurate volumetric occlusion from geometry outside the current view frustum, while trading off higher memory bandwidth for the shadow map [S1, unofficial]. It builds on [Volumetric Light Shafts (URP Raymarching)](3873-volumetric-light-shafts-urp-raymarching.md) and contrasts with [Image-Based Light Shaft (Dobashi)](22496-image-based-light-shaft-dobashi.md) by using explicit ray marching instead of screen-space blurring [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Depth buffer, inverse projection matrix, inverse view matrix, sun shadow map, sun color, sun direction, ground plane height, global intensity multiplier, and camera position [S1, unofficial].
*   **Outputs:** A post-processing texture containing the accumulated sun shafts, composited over the scene [S1, unofficial].

**Data Structures:**
*   **VolumetricPass Target:** A render target with `HalfFloatType` precision, no depth buffer, sized at half the screen resolution [S1, unofficial].
*   **Shadow Map:** A texture storing depth or binary lit/shadowed status for the sun light source [S1, unofficial].

**Parameters:**
*   `STEPS`: Number of march steps, set to 16 [S1, unofficial].
*   `uIntensity`: Global intensity multiplier, calculated as $0.07 \times \text{strength}$ [S1, unofficial].
*   `uGround`: Height of the ground plane for density calculation [S1, unofficial].
*   `MARCH_LENGTH`: The last 32 units of the ray are used for marching, or 0 if the ray is shorter than 32 units [S1, unofficial].

**Algorithm Steps:**
1.  **Resolution Reduction:** Render the effect at half resolution to quarter the per-pixel shadow-map sampling cost, relying on the soft nature of the haze effect to hide aliasing [S1, unofficial].
2.  **Jittering:** To hide banding artifacts in the volumetric march, jitter the start position of the ray march using interleaved gradient noise [S1, unofficial].
3.  **Ray Reconstruction:** For each pixel, reconstruct the world position from the depth buffer using the inverse projection and view matrices [S1, unofficial].
4.  **Ray Definition:** Compute the view ray direction $\mathbf{rd}$ from the camera position to the reconstructed world position and its length $L$ [S1, unofficial].
5.  **March Setup:** Determine the march start distance as the last 32 units of the ray (or 0 if $L < 32$) [S1, unofficial]. Calculate the step length $\Delta s$ based on 16 steps over the march length:
    $$ \Delta s = \frac{\text{MARCH\_LENGTH}}{\text{STEPS}} $$
6.  **Integration Loop:** Loop `STEPS` (16) times:
    a.  Compute sample position $\mathbf{p}$ along the ray [S1, unofficial].
    b.  Transform $\mathbf{p}$ to shadow map space [S1, unofficial].
    c.  Determine if the sample is lit by checking shadow map bounds and depth [S1, unofficial]. Let $S \in \{0, 1\}$ be the shadow factor (1 if lit, 0 if shadowed) [S1, unofficial].
    d.  Calculate ground-hugging density $\rho$ using exponential falloff based on sample height $y$ relative to ground level $uGround$:
        $$ \rho = e^{-k(y - uGround)} $$
        (Note: The exact decay constant $k$ is not specified in the sources [G].)
    e.  Apply forward scattering phase function $P(\theta)$, which is brighter when looking toward the sun [S1, unofficial].
    f.  Scale the contribution by distance attenuation and density [S1, unofficial].
    g.  Accumulate the result: $Accum += S \cdot \rho \cdot P(\theta) \cdot \text{attenuation}$ [S1, unofficial].
7.  **Output:** Output final color as sun color multiplied by the accumulated amount, phase, and intensity `uIntensity` [S1, unofficial].

**Pseudocode:**
```python
import math

def render_volumetric_sun_shafts(depth_buffer, inv_proj, inv_view, shadow_map, shadow_matrix, sun_color, sun_dir, u_ground, strength, camera_pos):
    STEPS = 16
    MARCH_LENGTH = 32.0
    u_intensity = 0.07 * strength
    out_w = depth_buffer.width // 2
    out_h = depth_buffer.height // 2
    output = [[(0.0, 0.0, 0.0) for _ in range(out_w)] for _ in range(out_h)]

    for y in range(out_h):
        for x in range(out_w):
            depth_val = depth_buffer.get(x, y)
            # Reconstruct world position from depth buffer using inverse projection and view matrices [S1, unofficial]
            clip_x = 2.0 * (x + 0.5) / out_w - 1.0
            clip_y = 2.0 * (y + 0.5) / out_h - 1.0
            clip_z = depth_val * 2.0 - 1.0
            clip_pos = (clip_x, clip_y, clip_z, 1.0)
            view_pos = inv_proj @ clip_pos
            view_pos = (view_pos[0]/view_pos[3], view_pos[1]/view_pos[3], view_pos[2]/view_pos[3])
            world_pos = inv_view @ (view_pos[0], view_pos[1], view_pos[2], 1.0)
            ray_dir = normalize(world_pos[:3] - camera_pos)
            ray_len = length(world_pos[:3] - camera_pos)

            # March start distance as the last 32 units of the ray (or 0 if L < 32) [S1, unofficial]
            start_dist = max(0.0, ray_len - MARCH_LENGTH)
            step_len = MARCH_LENGTH / STEPS
            if step_len <= 0.0:
                continue

            # Jitter start position using interleaved gradient noise to hide banding artifacts [S1, unofficial]
            jitter = ((x * 12.9898 + y * 78.233) % 1.0) * 2.0 - 1.0
            t = start_dist + jitter * step_len * 0.5

            accumulated = [0.0, 0.0, 0.0]
            for i in range(STEPS):
                sample_pos = camera_pos + ray_dir * t
                # Transform to shadow map space [S1, unofficial]
                shadow_clip = shadow_matrix @ (sample_pos[0], sample_pos[1], sample_pos[2], 1.0)
                shadow_uv = (shadow_clip[0] / shadow_clip[3], shadow_clip[1] / shadow_clip[3])
                # Determine if the sample is lit by checking shadow map bounds and depth [S1, unofficial]
                if 0.0 <= shadow_uv[0] <= 1.0 and 0.0 <= shadow_uv[1] <= 1.0:
                    stored_depth = shadow_map.get(shadow_uv)
                    S = 1.0 if sample_pos[2] < stored_depth else 0.0
                else:
                    S = 0.0

                # Calculate ground-hugging density using exponential falloff based on sample height relative to ground level [S1, unofficial]
                height_diff = sample_pos[1] - u_ground
                density = math.exp(-max(0.0, height_diff)) # Decay constant not given [G]

                # Apply forward scattering phase function (brighter when looking toward sun) [S1, unofficial]
                phase = max(0.0, dot(ray_dir, sun_dir))

                # Scale by distance attenuation [S1, unofficial]
                attenuation = 1.0 / (t + 1.0) # [G]

                contrib = S * density * phase * attenuation * step_len
                accumulated[0] += contrib * sun_color[0]
                accumulated[1] += contrib * sun_color[1]
                accumulated[2] += contrib * sun_color[2]

            output[y][x] = (accumulated[0] * u_intensity, accumulated[1] * u_intensity, accumulated[2] * u_intensity)
    return output

def normalize(v):
    l = math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    return (v[0]/l, v[1]/l, v[2]/l) if l > 0 else (0,0,0)
def length(v): return math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
def dot(v1, v2): return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]
```

**Edge Cases and Pitfalls:**
*   **Banding:** Banding artifacts in the volumetric march are hidden by jittering the start position using interleaved gradient noise [S1, unofficial].
*   **Short Rays:** If the ray length is less than 32 units, the march length is 0, and no light is accumulated [S1, unofficial].
*   **Resolution:** Running at half resolution is critical for performance; running at full resolution would significantly increase cost without proportional visual benefit due to the soft nature of the effect [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(W \cdot H \cdot \text{STEPS})$, where $W$ and $H$ are the output resolution (half screen) and STEPS is 16 [S1, unofficial]. The cost is dominated by shadow map lookups [S1, unofficial].
*   **Memory Complexity:** $O(W \cdot H)$ for the output texture (half float, 3 channels) plus the shadow map size [S1, unofficial].
*   **Performance:** Runs at half resolution to reduce cost, relying on the soft nature of the haze effect [S1, unofficial].
*   **Strengths:** Accurate volumetric occlusion from shadow maps, allowing shafts to be cast by geometry outside the view frustum [S1, unofficial].
*   **Limitations:** Requires a dedicated shadow map and post-processing pass. Performance scales with resolution and step count [S1, unofficial].

## Background
This technique is part of the volumetric rendering pipeline in a custom WebAssembly-based voxel engine, specifically implemented in `src/volumetric.ts` [S1, unofficial]. It is designed to render atmospheric lighting effects in a browser environment [S1, unofficial].
