# Runge-Kutta 4 (RK4) Integration

Also called: Runge-Kutta 4 (RK4), RK4 method, RK4 integration, RK4 Integrator, Runge-Kutta 4 Integrator, 4th order Runge-Kutta, Runge-Kutta 4th order, Fourth Order Runge-Kutta, Order Four Runge-Kutta

## Overview
Runge-Kutta 4 (RK4) is a fourth-order numerical integration method used to compute particle trajectories in vector fields for volume rendering [S4, unofficial]. It improves upon first-order methods like [Euler Integration](3836-euler-integration.md) by sampling the vector field at four distinct positions within a step to compute a weighted average slope, significantly reducing integration error [S4, unofficial]. While it requires four times the computational cost of Euler integration, it achieves an order-of-magnitude reduction in error, allowing for larger step sizes without sacrificing accuracy [S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Current position $x_n$ (or $x_i$), step size $\delta$ (or $dt$), and optionally a time parameter $t_{\text{func}}$ for unsteady fields [S4, unofficial][S5, unofficial].
*   **Output:** Next position $x_{n+1}$ (or $x_{i+1}$) [S4, unofficial][S5, unofficial].

**Data Structures:**
*   Position: 3D vector (e.g., `float3` or `double3`) [S4, unofficial].
*   Vector Field Sample: 3D vector representing the field value $v(x)$ at a given position [S4, unofficial].

**Parameters:**
*   $\delta$ (or $dt$): The integration step size. In real-time applications, this is often dynamic to maintain frame rate [S5, unofficial].
*   $t_{\text{func}}$: The current time for unsteady vector fields. For steady fields, this is ignored or fixed to a constant value [S5, unofficial].

**Steps:**
1.  Compute the half-step scalar: $dt_{half} = dt \times 0.5$ [S4, unofficial].
2.  Sample the vector field at the current position to get the first slope $k_1$: $k_1 = dt \cdot v(x_n, t_{\text{func}})$ [S4, unofficial].
3.  Sample the vector field at the midpoint using $k_1$ to estimate the position: $k_2 = dt \cdot v(x_n + k_1/2, t_{\text{func}})$ [S4, unofficial].
4.  Sample the vector field at the midpoint using $k_2$: $k_3 = dt \cdot v(x_n + k_2/2, t_{\text{func}})$ [S4, unofficial].
5.  Sample the vector field at the end of the step using $k_3$: $k_4 = dt \cdot v(x_n + k_3, t_{\text{func}})$ [S4, unofficial].
6.  Compute the weighted sum of the slopes to determine the displacement: $x_{n+1} = x_n + \frac{1}{6}(k_1 + 2k_2 + 2k_3 + k_4)$ [S4, unofficial].
*Note: Some sources define the intermediate samples $v_i$ as raw field values and apply the step size $\delta$ in the final sum as $x_{i+1} = x_i + \frac{1}{6} \delta (v_0 + 2v_1 + 2v_2 + v_3)$ [S5, unofficial]. Both formulations are mathematically equivalent [G].*

**Pseudocode:**
```python
def rk4_integrate(pos: Vector3, dt: float, vector_field_func, t_func: float = 0.0) -> Vector3:
    """Performs one step of Runge-Kutta 4 integration."""
    k1 = dt * vector_field_func(pos, t_func)
    k2 = dt * vector_field_func(pos + k1 * 0.5, t_func)
    k3 = dt * vector_field_func(pos + k2 * 0.5, t_func)
    k4 = dt * vector_field_func(pos + k3, t_func)
    return pos + (k1 + 2.0 * k2 + 2.0 * k3 + k4) * (1.0 / 6.0)
```

**Edge Cases and Pitfalls:**
*   **Steady vs. Unsteady Fields:** For steady vector fields, the time argument $t_{\text{func}}$ must be ignored or set to a constant value [S5, unofficial]. For unsteady fields, integration requires sampling the field at intermediate time steps, which may increase texture reads [S3].
*   **Precision and Step Size:** The method is sensitive to the step size $\delta$ [S4, unofficial][S5, unofficial]. While RK4 is more robust than Euler, extremely large step sizes can still lead to instability or divergence from the true trajectory, particularly in complex flow structures like vortices [S4, unofficial].
*   **Vortex Behavior:** RK4 tends to stay within vortices better than Euler integration, which may escape them [S4, unofficial]. However, RK4 can sometimes converge to the center of vortices instead of following the streamline correctly [S4, unofficial].

## Subtopics

### [Euler Integration](3836-euler-integration.md)
First-order method using a single sample per step. Choose it when computational efficiency is prioritized over accuracy, as it serves as the baseline explicit integrator for streamline visualization.

### [Runge-Kutta 2/3 ODE Solver](3839-runge-kutta-2-3-ode-solver.md)
Lower-order RK variant requiring fewer function evaluations per step. Choose it when a balance between accuracy and performance is needed, offering a middle ground between Euler and RK4.

### [Tensorline Integration](9613-tensorline-integration.md)
Integrates streamlines through tensor fields using RK4 for geometric accuracy, combined with discrete compositing for image synthesis. Choose it when visualizing directional information in volumetric tensor data.

### [Dormand-Prince 5(4) Step](13933-dormand-prince-5-4-step.md)
Fifth-order method with embedded error estimation for adaptive step control. Choose it when varying field complexity requires dynamic step sizing, whereas RK4 uses a fixed step size [G].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per step, requiring four vector field evaluations [S2].
*   **Memory Complexity:** $O(1)$ auxiliary memory per step to store the four intermediate slope vectors $k_1, k_2, k_3, k_4$ [G].
*   **Accuracy:** The method achieves an order-of-magnitude reduction in error compared to Euler integration, with a local truncation error of $O(dt^5)$ [S4, unofficial]. This allows RK4 to maintain lower error than Euler even with significantly larger time steps [S4, unofficial].
*   **Strengths:** High accuracy for smooth vector fields; better stability in vortices compared to Euler integration [S4, unofficial].
*   **Limitations:** Higher computational cost; potential for converging to vortex centers incorrectly in some complex flows [S4, unofficial].
*   **When to use:** When higher accuracy is required than Euler can provide, and computational resources allow for the increased per-step cost [S2].
*   **When not to use:** When extreme performance is critical and lower accuracy is acceptable (use Euler); when adaptive step size is needed for varying field complexity (use Dormand-Prince 5(4) Step) [S2][G].

## Background
RK4 was developed as part of the Runge-Kutta family of methods for solving ordinary differential equations [G]. In volume rendering and vector field visualization, it has been adopted to improve the accuracy of streamline and pathline integration compared to simpler methods like Euler integration [S4, unofficial][S5, unofficial]. It is used in real-time visualization systems where step size can be adjusted dynamically to maintain performance [S5, unofficial].
