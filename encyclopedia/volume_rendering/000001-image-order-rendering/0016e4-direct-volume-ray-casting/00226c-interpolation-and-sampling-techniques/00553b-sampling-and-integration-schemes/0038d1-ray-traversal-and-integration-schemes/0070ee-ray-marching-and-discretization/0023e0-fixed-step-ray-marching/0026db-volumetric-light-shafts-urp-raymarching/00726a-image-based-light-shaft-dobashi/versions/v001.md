# Image-Based Light Shaft (Dobashi)
Also called: Dobashi Light Shafts, Parallel Slice Light Shafts
## Overview
A method that displays light shafts with a shadow map using texture-mapping hardware by placing parallel slices in front of the screen to compute light scattering induced by atmospheric particles [S1, unofficial]. It uses the color buffer of light received by visible objects to calculate the light frustum from a shadow map and the average extinction of participating media [S1, unofficial]. It sets itself apart from siblings like [Screen-Space God Rays](3981-screen-space-god-rays.md) by explicitly modeling the volumetric light transport equation via parallel slices rather than post-processing screen-space artifacts, and from [Volumetric Sun Shafts (God Rays)](15833-volumetric-sun-shafts-god-rays.md) by relying on hardware-accelerated shadow mapping for occlusion rather than simple radial blurring.
## How it works
**Inputs and Outputs:**
*   **Inputs:** View ray, light source position, shadow map, color buffer of visible objects, particle density distribution, light frustum parameters.
*   **Outputs:** Final image with light shafts.

**Data Structures:**
*   **Parallel Slices:** A series of planes positioned in front of the screen. The number of slices is proportional to the desired quality and inversely proportional to the sampling error [S1, unofficial].
*   **Shadow Map:** Standard depth buffer storing depth of opaque objects from the light's perspective [S1, unofficial].
*   **Color Buffer:** Stores the color of light received by visible objects [S1, unofficial].

**Steps:**
1.  **Render Shadow Map:** Generate a shadow map from the light source's perspective, storing depths of opaque objects [S1, unofficial].
2.  **Calculate Light Frustum:** Determine the light frustum using the shadow map and the average extinction of participating media [S1, unofficial].
3.  **Intersect Eye Ray:** Calculate the intersection of the eye ray with the light frustum to determine the length of the light path through the frustum [S1, unofficial].
4.  **Render Parallel Slices:** Place parallel slices in front of the screen. For each slice:
    a.  Sample the shadow map to determine if the slice is in shadow [S1, unofficial].
    b.  Compute light scattering induced by atmospheric particles using the rendering light transport equation [S1, unofficial].
    c.  Integrate in-scattering along the view ray [S1, unofficial].
    d.  Compute light attenuation reaching the viewpoint based on particle density [S1, unofficial].
5.  **Composite:** Combine the results from all slices to form the final image [S1, unofficial].

**Formulas:**
*   **Light Transport Equation:** The method integrates the in-scattering along the view ray and light attenuation reaching the viewpoint. The extra intensity is computed from information that represents light scattering, where leads to appear columns of scattered radiance visible with space is partly in shadow [S1, unofficial].
*   **Light Path Length:** $L = \text{Intersection}(EyeRay, LightFrustum)$ [S1, unofficial].

**Parameters:**
*   **Number of Virtual Planes:** Proportional to the number of passes required [S1, unofficial].
*   **Particle Density:** Determines the density of particles in the atmosphere [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Sampling Error:** Requires multiple passes proportional to the number of virtual planes, which leads to error sampling [S1, unofficial].
*   **Aliasing:** The method tries to avoid aliasing problems, but the multiple passes can introduce sampling artifacts [S1, unofficial].
*   **Performance:** Adding sub-planes to overcome sampling error requires more computation, making it time-consuming [S1, unofficial].

**Pseudocode:**
```python
def render_light_shafts_dobashi(view_ray, light_source, shadow_map, color_buffer, particle_density, num_slices):
    # Step 1: Render Shadow Map (Assumed pre-computed)
    shadow_map = render_shadow_map(light_source)
    
    # Step 2: Calculate Light Frustum
    light_frustum = calculate_light_frustum(shadow_map, particle_density)
    
    # Step 3 & 4: Render Parallel Slices
    final_image = zeros_like(color_buffer)
    
    for i in range(num_slices):
        # Place slice in front of screen
        slice_plane = get_slice_plane(i, num_slices)
        
        # Intersect eye ray with light frustum
        light_path_length = intersect_eye_ray_with_frustum(view_ray, light_frustum)
        
        # Sample shadow map for this slice
        is_in_shadow = sample_shadow_map(shadow_map, slice_plane.position)
        
        # Compute light scattering
        if not is_in_shadow:
            scattering = compute_scattering(slice_plane, particle_density, light_source)
            attenuation = compute_attenuation(particle_density, light_path_length)
            final_image += scattering * attenuation
        else:
            # Slice is in shadow, no scattering
            pass
            
    # Step 5: Composite
    return final_image
```
## Subtopics

### Image-Based Light Shaft (Morgan)
A method based on stochastic transparency that casts shadows between any aggregation of colored transmissive, opaque, and partial coverage surfaces, consistent with hardware shadow mapping [S1, unofficial]. It applies an infinite number of surfaces on GPUs and consoles, using the depth buffer to store the depth of opaque surfaces and blending RGB channels to emulate a depth test for translucent surfaces [S1, unofficial]. It extends Dobashi's method by allowing translucent objects to cast shadows, which Dobashi's original method could not do [S1, unofficial].

### Image-Based Light Shaft (Bruneton)
A method to render sunlight and illumination effects induced by attenuated light reaching the viewpoint at different altitudes [S1, unofficial]. It computes lit segments from the view ray and ignores dark parts through a shadow test to reduce the cost of the integral equation of light [S1, unofficial]. It differs from Dobashi by focusing on altitude-based attenuation and optimizing the integral calculation by skipping dark segments [S1, unofficial].

### Geometrically-Based Light Shaft (Wyman)
A method that restores intensity points in space as a texture put in an array, using shadow sampling to calculate intensity for interactive rate images [S1, unofficial]. It lacks calculation of multiple scattering [S1, unofficial]. It differs from Dobashi by using a geometric approach with intensity points in an array rather than parallel slices, and is optimized for interactive rates but sacrifices physical accuracy in multiple scattering [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of virtual planes (slices) [S1, unofficial]. Adding sub-planes increases computation time, making it time-consuming [S1, unofficial].
*   **Memory Complexity:** Depends on the number of slices and the resolution of the shadow map and color buffer [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Performance degrades linearly with the number of slices [S1, unofficial].
*   **Strengths:** Uses hardware-accelerated shadow mapping; physically based on light transport equation [S1, unofficial].
*   **Limitations:** Multiple passes lead to sampling errors and aliasing; time-consuming if sub-planes are added [S1, unofficial].
*   **When to use:** When physically accurate light shafts are needed and hardware shadow mapping is available [S1, unofficial].
*   **When not to use:** When performance is critical and sampling errors can be tolerated or mitigated by other means [S1, unofficial].
## Background
Dobashi proposed the method to display light shafts with a shadow map using texture-mapping hardware [S1, unofficial]. The method includes rendering light shafts by placing parallel slices in front of the screen to compute light scattering induced by atmospheric particles [S1, unofficial]. The principle fundamental of participating media to interact with light is based on rendering the light transport equation for generating effects of atmospheric phenomena such as light shaft [S1, unofficial]. Therefore, when light travels from the light source through space in variety directions hits particles of atmosphere, based on physical properties of particles yield effects such as scattering and absorption of light [S1, unofficial]. The integration of the in-scattering along the view ray and light attenuation that reaches to viewpoint will appear light volume according to the density of particles in atmosphere [S1, unofficial]. Moreover, the presence of objects inside the light volume leads to generate shadow with light shaft [S1, unofficial]. This method has been exploited graphics hardware rendering light shaft and shadow map [S1, unofficial]. However, this method tried avoiding aliasing problem, but it needs multiple passes for number virtual planes that must proportional to the number of passes which lead to error sampling [S1, unofficial]. Dobashi later modified the method by adding sub-planes to overcome the sampling error, but this method requires more computation which time-consuming [S1, unofficial]. Mitchell presented a method which based on work by Dobashi for simulating light shafts [S1, unofficial]. This method renders a traditional shadow map from opaque objects merely and then fills the scene with hundreds of translucent fog planes that receive the shadowing [S1, unofficial]. This provides convincing light shafts, which can have color if the light has a projective texture or fog planes have colored texture [S1, unofficial]. But this method, translucent objects cannot cast shadows [S1, unofficial]. Then Morgan proposed a method based on develop technique presented by stochastic transparency, for shadow cast between any aggregation of colored transmissive, opaque, and partial coverage surfaces which it consistent with hardware shadow mapping techniques [S1, unofficial]. This method used number infinity of surfaces that apply on GPUs and consoles [S1, unofficial]. However it use depth buffer to store a depth of opaque surfaces and use to blending RGB channels to emulate a depth test for translucent surfaces [S1, unofficial]. Gautron presented technique to use color buffer to light received by visible objects to calculate light frustum form shadow map and average extinction of participating media [S1, unofficial]. The intersection of an eye ray is calculated in order to determine length of the light path through frustum [S1, unofficial]. Bruneton proposed method to render sunlight and illumination effects induced of attenuated light until reach to viewpoint and at different altitude from level ground for atmosphere [S1, unofficial]. However, it based on compute the lit segments from view ray and ignore the dark parts through shadow test that reduce cost of integral equation of light [S1, unofficial].
