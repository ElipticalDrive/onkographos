# Ray-marched Volumetric Fog

Also called: Fog Filter, Forward ray-marching fog, Full-screen volumetric fog, Volumetric Fog (CRYENGINE 3), Voxel-based Volumetric Fog

## Overview
Ray-marched volumetric fog simulates light absorption, scattering, soft shadows, and light shafts (god rays) by treating fog as a 3D volume of participating media traced via forward ray-marching from the camera to the scene [S2, unofficial]. It solves the problem of rendering aerial perspective and dynamic volumetric lighting in real-time applications [S1][S2, unofficial]. Unlike backward ray-marching, this method marches from the camera to the scene intersection, allowing for early-out optimizations when transmittance drops below a threshold [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera position, view direction, depth buffer (for scene intersection), light position and intensity, fog density, scattering coefficient, phase function parameters, step size $\Delta l$, and maximum ray distance $z_{far}$ [S2, unofficial].
*   **Outputs:** Final pixel radiance $L$ [S2, unofficial].

**Data Structures:**
*   **Ray:** Defined by origin $o$ (camera position) and direction $d$ (normalized vector from camera to pixel).
*   **Depth Buffer:** 2D texture storing depth values $z$ for each pixel UV coordinate [S2, unofficial].
*   **Light Data:** Position $L_{pos}$, intensity $\Phi$, and optionally shadow map data for visibility $v(x)$ [S2, unofficial].

**Numbered Steps:**
1.  **Ray Initialization:** For each pixel, construct a ray $r(t) = o + td$ originating from the camera [S2, unofficial].
2.  **Scene Intersection:** Sample the depth buffer at the current pixel's UV coordinate to reconstruct the 3D position of the scene intersection point. Calculate the total ray length $l_{max}$ to this point [S2, unofficial].
3.  **Clamping:** Clamp $l_{max}$ to a predefined $z_{far}$ value to prevent infinite marching if the ray misses the scene geometry [S2, unofficial].
4.  **Jittering (Optional):** Add a pseudo-random delta step to the ray's starting position to fix slice artifacts caused by aligned samples [S2, unofficial].
5.  **Marching Loop:** Iterate from $t = 0$ to $t = l_{max}$ with step size $\Delta l$.
    *   Calculate current sample position $x(t) = o + td$.
    *   Calculate transmittance from camera to sample: $T(t) = e^{-\tau t}$, where $\tau$ is the fog density [S2, unofficial].
    *   Calculate in-scattering term $L_i(x(t), \omega)$ for the current sample [S2, unofficial].
    *   Accumulate radiance: $L \leftarrow L + L_i(x(t), \omega) \cdot T(t) \cdot \Delta l$ [S2, unofficial].
    *   **Early-out:** If $T(t)$ drops below a threshold (e.g., $10^{-3}$), terminate the loop [S2, unofficial].
6.  **Final Output:** Return accumulated $L$ as the pixel color [S2, unofficial].

**Formulas:**
The final radiance $L$ is approximated using a Riemann sum [S2, unofficial]:
$$ L = \sum_{n=0}^{N} L_i(x(l_n), \omega) e^{-\tau l_n} \Delta l $$
Where:
*   $L_i(x(l_n), \omega)$ is the in-scattering term at step $n$.
*   $e^{-\tau l_n}$ is the transmittance from the camera to distance $l_n$.
*   $\Delta l$ is the step size [S2, unofficial].

The in-scattering term $L_i$ for a point light is calculated as [S2, unofficial]:
$$ L_i(x, \omega) = \frac{a \Phi}{4\pi d^2} v(x) e^{-\tau d} P(\omega, \omega') $$
Where:
*   $\tau$ is the fog density (constant for uniform fog) [S2, unofficial].
*   $a$ is the scattering coefficient [S2, unofficial].
*   $\Phi$ is the point light intensity [S2, unofficial].
*   $d$ is the distance from the sample point $x$ to the light source [S2, unofficial].
*   $v(x)$ is the visibility of the sample point from the light source (set to 1 if no shadow mapping is used) [S2, unofficial].
*   $e^{-\tau d}$ is the transmittance from the sample point to the light [S2, unofficial].
*   $P(\omega, \omega')$ is the phase function, approximated using the Schlick approximation of the Henyey-Greenstein function for real-time performance [S2, unofficial].

**Parameters:**
*   **Density ($\tau$):** Constant for uniform fog. Can be procedurally generated, sampled from a texture, or from OpenVDB for non-uniform fog [S2, unofficial].
*   **Visibility ($v(x)$):** Set to 1 in basic implementations. Can be sampled from a light's cube shadow map if available [S2, unofficial].
*   **Phase Function ($P$):** Schlick approximation of Henyey-Greenstein [S2, unofficial].
*   **Step Size ($\Delta l$):** Controls accuracy vs. performance. Larger steps cause slice artifacts [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Slice Artifacts:** Occur when rays march with the same step size starting at the same point, causing samples to align on the same "slices" [S2, unofficial]. Fixed by jittering the starting position or every sample [S2, unofficial].
*   **Noise:** Jittering can make the result look noisier on larger step sizes [S2, unofficial].
*   **Infinite Marching:** Rays missing the scene geometry must be clamped by $z_{far}$ [S2, unofficial].

**Pseudocode:**
```python
def ray_marched_volumetric_fog(camera_pos, camera_dir, depth_buffer, light_pos, light_intensity, fog_density, scattering_coeff, step_size, z_far):
    # Initialize radiance
    radiance = 0.0
    
    # Reconstruct scene intersection
    # Note: Implementation of depth buffer sampling and unprojection is assumed
    scene_dist = reconstruct_depth(depth_buffer, current_uv)
    
    # Clamp ray distance
    ray_length = min(scene_dist, z_far)
    
    # Jitter starting position to fix slice artifacts [S2, unofficial]
    jitter = random_float(0.0, step_size)
    current_dist = jitter
    
    # Pre-calculate constants
    # Schlick phase function approximation of Henyey-Greenstein [S2, unofficial]
    # g is asymmetry parameter, typically 0.8 for fog
    g = 0.8
    g2 = g * g
    one_minus_g2 = 1.0 - g2
    k = (1.0 - g2) / (1.0 + g2)
    
    while current_dist < ray_length:
        # Calculate sample position
        sample_pos = camera_pos + camera_dir * current_dist
        
        # Calculate transmittance from camera to sample
        # T = exp(-tau * distance)
        transmittance = exp(-fog_density * current_dist)
        
        # Early-out optimization [S2, unofficial]
        if transmittance < 0.001:
            break
            
        # Calculate in-scattering term
        # Vector from sample to light
        to_light = light_pos - sample_pos
        dist_to_light = length(to_light)
        
        # Visibility v(x) [S2, unofficial]
        # Set to 1 if no shadow mapping is available
        visibility = 1.0
        
        # Transmittance from sample to light
        light_transmittance = exp(-fog_density * dist_to_light)
        
        # Phase function P(omega, omega') [S2, unofficial]
        # Approximation of Henyey-Greenstein using Schlick
        # cos_theta is dot product of view direction and light direction
        cos_theta = dot(normalize(camera_dir), normalize(to_light))
        phase = k / (4.0 * 3.14159 * (1.0 - g * cos_theta) * (1.0 - g * cos_theta) + 1.0) # Simplified Schlick approx
        
        # In-scattering Li [S2, unofficial]
        # Li = (a * Phi) / (4 * pi * d^2) * v(x) * e^(-tau * d) * P
        in_scattering = (scattering_coeff * light_intensity * visibility * light_transmittance * phase) / (4.0 * 3.14159 * dist_to_light * dist_to_light)
        
        # Accumulate radiance [S2, unofficial]
        radiance += in_scattering * transmittance * step_size
        
        # Advance step
        current_dist += step_size
        
    return radiance
```

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of pixels and $P$ is the number of steps per ray. Performance is heavily dependent on step size and early-out efficiency [S2, unofficial].
*   **Memory Complexity:** $O(1)$ per pixel for the marching loop, plus storage for depth buffer and light data [S2, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Simple to implement, allows for early-out optimization, works well with standard depth buffers, and can simulate dynamic lighting interactions (soft shadows, god rays) [S2, unofficial].
*   **Limitations:** Slice artifacts if not jittered, noise with large step sizes, and performance degradation with high step counts or large volumes [S2, unofficial].
*   **When to use:** Real-time applications requiring simple, uniform fog or simple participating media effects where performance is critical and high-fidelity non-uniform volumes are not required [S2, unofficial].
*   **When not to use:** When complex, non-uniform volumes with detailed internal structure are needed, or when backward ray-marching is required for specific lighting effects [S2, unofficial].

## Background
Ray-marched volumetric fog is a technique used in real-time graphics to simulate participating media. It is based on the principles of volume rendering, where the integral of radiance along a ray is approximated via discretization [S2, unofficial]. The specific implementation described here follows the approach of Toth and Umenhofer (TU09) for forward ray-marching, adapted for real-time full-screen shaders [S2, unofficial]. It is used in games like Horizon Zero Dawn, Death Stranding, and Returnal to simulate dynamic fog and light shafts [S2, unofficial]. The term "Fog Filter" is also used in older volume rendering software like DF3 Viewer [S1].
