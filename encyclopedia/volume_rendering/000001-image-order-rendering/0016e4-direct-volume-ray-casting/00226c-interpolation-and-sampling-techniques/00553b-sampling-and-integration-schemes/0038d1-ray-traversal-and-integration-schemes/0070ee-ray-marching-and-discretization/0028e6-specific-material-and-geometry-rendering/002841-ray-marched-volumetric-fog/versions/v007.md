# Ray-marched Volumetric Fog

Also called: Fog Filter, Forward ray-marching fog, Full-screen volumetric fog

## Overview
Ray-marched volumetric fog simulates light absorption, scattering, and soft shadows by treating fog as a 3D volume of participating media traced via forward ray-marching from the camera to the scene [S2, unofficial]. It solves the problem of rendering aerial perspective and light shafts (god rays) in real-time applications by approximating the volume rendering integral using a Riemann sum [S2, unofficial]. Unlike backward ray-marching, this forward approach allows for early-out optimizations when transmittance becomes negligible [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera position, view direction per pixel, depth buffer (for scene intersection), light position and intensity, fog density ($\tau$), scattering coefficient ($a$), and phase function parameters.
*   **Outputs:** Final pixel color (radiance $L$).

**Data Structures:**
*   **Ray:** Defined by origin $o$ (camera) and direction $d$ (pixel UV mapped to world space).
*   **Depth Buffer:** 2D texture storing depth values $z$ for scene geometry.
*   **Fog Parameters:** Uniform scalar $\tau$ (density) and $a$ (scattering coefficient) for uniform fog [S2, unofficial].

**Numbered Steps:**
1.  **Ray Generation:** For each pixel, generate a ray $r(t) = o + td$ originating from the camera [S2, unofficial].
2.  **Scene Intersection:** Sample the depth buffer at the current pixel's UV coordinate to reconstruct the 3D position of the scene intersection point. Calculate the total ray length $L_{max}$ to this point [S2, unofficial].
3.  **Clamping:** Clamp $L_{max}$ to a maximum value `zfar` to prevent infinite marching if the ray misses the scene geometry [S2, unofficial].
4.  **Jittering (Optional):** Add a pseudo-random delta step to the ray's starting position to fix slice artifacts caused by aligned sampling grids [S2, unofficial].
5.  **Marching Loop:** Iterate from $t=0$ to $t=L_{max}$ with a fixed step size $\Delta l$.
6.  **Accumulation:** At each step, calculate the in-scattering term and transmittance, then accumulate the result into the final radiance $L$ [S2, unofficial].

**Formulas:**
The final radiance $L$ is approximated by the Riemann sum [S2, unofficial]:
$$ L = \sum_{n=0}^{N} L_i(x(l_n), \omega) e^{-\tau l_n} \Delta l $$
Where:
*   $L_i(x(l_n), \omega)$ is the in-scattering term at step $n$.
*   $e^{-\tau l_n}$ is the transmittance for the distance $l_n$ travelled from the camera to the current sample point.
*   $\Delta l$ is the ray-march step size.
*   $\tau$ is the fog density [S2, unofficial].

The in-scattering term $L_i$ for a point light source is calculated as [S2, unofficial]:
$$ L_i(x, \omega) = \frac{a \Phi}{4\pi d^2} v(x) e^{-\tau d} P(\omega, \omega') $$
Where:
*   $a$ is the scattering coefficient.
*   $\Phi$ is the point light intensity.
*   $d$ is the distance from the sample point to the light source.
*   $v(x)$ is the visibility of the sample point from the light source (set to 1 if shadow mapping is not available) [S2, unofficial].
*   $e^{-\tau d}$ is the transmittance from the light to the sample point.
*   $P(\omega, \omega')$ is the phase function describing the angular distribution of scattered light.

**Parameters:**
*   **Density ($\tau$):** Constant for uniform fog [S2, unofficial].
*   **Visibility ($v(x)$):** Set to 1 in the basic implementation; can be sampled from a light's cube shadow map for shadows [S2, unofficial].
*   **Phase Function ($P$):** Uses the Schlick phase function approximation of Henyey-Greenstein (HG) for real-time performance [S2, unofficial].

**Pseudocode:**
```python
def ray_marched_volumetric_fog(camera_pos, pixel_uv, depth_buffer, light_pos, light_intensity, fog_density, scattering_coeff, step_size, zfar):
    # 1. Generate Ray
    ray_origin = camera_pos
    ray_direction = reconstruct_direction_from_uv(pixel_uv, camera_pos)
    
    # 2. Scene Intersection
    depth_value = depth_buffer.sample(pixel_uv)
    scene_point = reconstruct_world_position(pixel_uv, depth_value, camera_pos)
    ray_to_scene = scene_point - ray_origin
    max_dist = length(ray_to_scene)
    
    # 3. Clamping
    if max_dist > zfar:
        max_dist = zfar
        
    # 4. Jittering (to fix slice artifacts)
    jitter = random_float(0.0, step_size)
    
    # 5. Marching Loop
    accumulated_radiance = vec3(0.0)
    current_dist = jitter
    transmittance = 1.0
    
    while current_dist < max_dist:
        # Current sample point
        sample_point = ray_origin + ray_direction * current_dist
        
        # Calculate In-Scattering
        # Distance from sample to light
        dist_to_light = length(light_pos - sample_point)
        
        # Visibility (1 if no shadow map)
        visibility = 1.0 
        
        # Phase Function (Schlick approximation of Henyey-Greenstein)
        # Simplified placeholder for P(omega, omega_prime)
        phase = schlick_phase_function(fog_density, ray_direction, light_pos - sample_point)
        
        # In-scattering term Li
        # Formula: (a * Phi) / (4 * pi * d^2) * v(x) * e^(-tau * d) * P
        light_attenuation = light_intensity / (4.0 * 3.14159 * dist_to_light * dist_to_light)
        light_transmittance = exp(-fog_density * dist_to_light)
        in_scattering = scattering_coeff * light_attenuation * visibility * light_transmittance * phase
        
        # Transmittance from camera to sample
        camera_transmittance = exp(-fog_density * current_dist)
        
        # Accumulate
        # L += Li * e^(-tau * l_n) * delta_l
        accumulated_radiance += in_scattering * camera_transmittance * step_size
        
        # Update distance
        current_dist += step_size
        
    return accumulated_radiance
```

**Edge Cases and Pitfalls:**
*   **Slice Artifacts:** Marching rays with the same step size starting at the same point causes samples to align on the same "slices," creating visible banding [S2, unofficial].
*   **Noise:** Jittering reduces slice artifacts but can introduce noise, especially with larger step sizes [S2, unofficial].
*   **Infinite Marching:** Rays missing the scene must be clamped by `zfar` to prevent infinite loops [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of pixels and $P$ is the number of steps per ray.
*   **Memory Complexity:** $O(1)$ per pixel (excluding depth buffer and light shadow maps).
*   **Strengths:** Simple to implement; allows early-out optimization when transmittance is low; works well for uniform fog [S2, unofficial].
*   **Limitations:** Slice artifacts require jittering; noise increases with larger step sizes; uniform fog assumption limits complexity unless procedural noise or textures are added [S2, unofficial].
*   **When to use:** Real-time applications requiring simple aerial perspective or light shafts with uniform fog density.
*   **When not to use:** Scenes requiring complex, non-uniform fog volumes (use [Mr-Voxel Volume Rendering](3874-mr-voxel-volume-rendering.md) or [DVGO Density and Color Rendering](12839-dvgo-density-and-color-rendering.md)) or high-fidelity multiple scattering.

## Background
Ray-marched volumetric fog is a technique used in real-time graphics to simulate participating media. It is based on the principles of volume rendering, specifically the integration of in-scattering and transmittance along a ray [S2, unofficial]. The specific forward ray-marching implementation described here deviates from the backward ray-marching approach used in the Real-time Volumetric Lighting in Participating Media paper by Toth and Umenhofer [TU09], favoring forward marching for early-out optimization [S2, unofficial]. The technique is used in games such as Horizon Zero Dawn, Death Stranding, and Returnal [S2, unofficial].
