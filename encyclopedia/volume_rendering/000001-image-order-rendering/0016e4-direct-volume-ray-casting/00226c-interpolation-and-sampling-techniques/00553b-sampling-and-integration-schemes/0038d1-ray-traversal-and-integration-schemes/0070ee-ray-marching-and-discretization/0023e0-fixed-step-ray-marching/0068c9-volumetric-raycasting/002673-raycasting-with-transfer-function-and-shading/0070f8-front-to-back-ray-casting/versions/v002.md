# Front-to-Back Ray Casting
Also called: RayCastSimple
## Overview
Front-to-Back Ray Casting is a direct volume rendering technique that accumulates color and opacity along a ray traversing a 3D texture space, starting from the viewer and moving toward the back of the volume [S1, unofficial]. It solves the problem of compositing semi-transparent volumetric data into a 2D image by applying the standard front-to-back alpha blending equation at each sample step [S1, unofficial]. It is distinguished from its siblings by its explicit use of a fixed iteration count combined with boundary checks, and its specific normalization of raw volume values to a fixed [0, 1] range before blending, rather than relying solely on the transfer function's alpha channel for opacity weighting [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume texture (`Volume`), a front-face position texture (`Front`), a back-face position texture (`Back`), and a fragment shader input containing projective texture coordinates [S1, unofficial].
*   **Output:** A `float4` color value representing the accumulated ray color and opacity [S1, unofficial].

**Data Structures:**
*   `Front` / `Back`: 2D textures storing the 3D world coordinates of the entry and exit points of the ray through the volume bounding box [S1, unofficial].
*   `Volume`: 3D texture storing scalar density values [S1, unofficial].
*   `dst`: Accumulator buffer, initialized to `(0, 0, 0, 0)` [S1, unofficial].
*   `src`: Temporary sample buffer, initialized to `(0, 0, 0, 0)` [S1, unofficial].
*   `pos`: Current ray position, initialized to `float4(front, 0)` [S1, unofficial].
*   `dir`: Ray direction vector [S1, unofficial].
*   `Step`: Step vector calculated as `dir * StepSize` [S1, unofficial].

**Parameters:**
*   `Iterations`: Fixed number of steps (e.g., 1500) [S1, unofficial].
*   `StepSize`: Distance between samples [S1, unofficial].
*   `ThresholdMin`: Lower bound for value clamping (40) [S1, unofficial].
*   `ThresholdMax`: Upper bound for value clamping (60) [S1, unofficial].
*   `AlphaScale`: Divisor for alpha normalization (`Iterations / 50.0`) [S1, unofficial].
*   `EarlyTerminationThreshold`: Alpha threshold to stop rendering (0.95) [S1, unofficial].

**Steps:**
1.  **Compute Ray Geometry:**
    *   Calculate projective texture coordinates from the vertex shader output:
        $$ texC.x = 0.5 \times \left(\frac{input.pos.xy.x}{input.pos.w}\right) + 0.5 $$
        $$ texC.y = -0.5 \times \left(\frac{input.pos.xy.y}{input.pos.w}\right) + 0.5 $$
    *   Sample the front and back positions:
        $$ front = Front.Sample(texC).rgb $$
        $$ back = Back.Sample(texC).rgb $$
    *   Compute direction and initialize position:
        $$ dir = normalize(back - front) $$
        $$ pos = float4(front, 0) $$
    *   Compute step vector:
        $$ Step = dir \times StepSize $$
2.  **Ray Marching Loop:**
    Iterate $i$ from 0 to $Iterations - 1$:
    *   **Sample Volume:**
        $$ value = TrilinearSample(pos.xyz) $$
        [G] `TrilinearSample` performs standard trilinear interpolation on the 3D volume texture at `pos.xyz`.
    *   **Clamp and Normalize:**
        *   Clamp value to $[40, 60]$:
            $$ value = \max(40, \min(60, value)) $$
        *   Normalize to $[0, 1]$:
            $$ value = \frac{value - 40.0}{20.0} $$
    *   **Prepare Source Color/Alpha:**
        *   Set source components to the normalized value:
            $$ src = (value, value, value, value) $$
        *   Calculate source alpha:
            $$ src.a = \frac{src.a}{Iterations / 50.0} $$
    *   **Front-to-Back Blending:**
        *   Modulate color by alpha:
            $$ src.rgb = src.rgb \times src.a $$
        *   Update destination:
            $$ dst = (1.0 - dst.a) \times src + dst $$
    *   **Early Termination:**
        *   If $dst.a \ge 0.95$, break loop.
    *   **Advance Ray:**
        $$ pos.xyz = pos.xyz + Step $$
    *   **Boundary Check:**
        *   If any component of $pos.xyz$ is outside $[0.0, 1.0]$, break loop.
3.  **Return Result:**
    *   Return `dst`.

**Pseudocode:**
```python
def RayCastSimple(input_pos, front_tex, back_tex, volume_tex, iterations=1500, step_size=0.01):
    # 1. Compute Ray Geometry
    tex_c_x = 0.5 * (input_pos.xy.x / input_pos.w) + 0.5
    tex_c_y = -0.5 * (input_pos.xy.y / input_pos.w) + 0.5
    
    front = front_tex.sample(tex_c_x, tex_c_y)
    back = back_tex.sample(tex_c_x, tex_c_y)
    
    dir = normalize(back - front)
    pos = vec4(front, 0.0)
    
    dst = vec4(0.0, 0.0, 0.0, 0.0)
    src = vec4(0.0, 0.0, 0.0, 0.0)
    
    step = dir * step_size
    
    # 2. Ray Marching Loop
    for i in range(iterations):
        value = volume_tex.trilinear_sample(pos.xyz)
        
        value = max(40.0, min(60.0, value))
        value = (value - 40.0) / 20.0
        
        src = vec4(value, value, value, value)
        src.a /= (iterations / 50.0)
        
        src.rgb *= src.a
        dst = (1.0 - dst.a) * src + dst
        
        if dst.a >= 0.95:
            break
            
        pos.xyz += step
        
        if pos.x < 0.0 or pos.x > 1.0 or pos.y < 0.0 or pos.y > 1.0 or pos.z < 0.0 or pos.z > 1.0:
            break
            
    return dst
```

**Edge Cases and Pitfalls:**
*   **Precision:** The normalization relies on fixed thresholds (40, 60) [S1, unofficial]. If the volume data does not contain values in this range, the output will be uniformly black or white [S1, unofficial].
*   **Boundary Exit:** The boundary check `pos.x > 1.0f || ...` assumes the volume texture coordinates are normalized to $[0, 1]$ [S1, unofficial]. If the volume is larger or smaller, this check may terminate rays prematurely or allow them to sample outside the texture bounds [S1, unofficial].
*   **Alpha Saturation:** The early termination threshold of 0.95 may cause visible artifacts (banding) in transparent regions if the step size is too large, as the ray stops before fully integrating the back of the volume [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of iterations (steps) per pixel [S1, unofficial]. The complexity is linear with respect to the number of samples taken along the ray [S1, unofficial].
*   **Memory Complexity:** $O(1)$ per pixel, as only the current position, direction, and accumulation buffers are stored [S1, unofficial]. The volume texture is accessed via streaming [S1, unofficial].
*   **Measured Performance:** Performance depends heavily on the `Iterations` parameter and early termination [S1, unofficial]. With `Iterations = 1500` and early termination at `dst.a >= 0.95`, average steps per pixel may be significantly lower than 1500 in opaque regions, but full 1500 steps in transparent regions [S1, unofficial].
*   **Strengths:** Simple to implement; efficient early termination; fixed iteration count ensures consistent performance across frames [S1, unofficial].
*   **Limitations:** Fixed step size may lead to aliasing or missing thin structures; normalization thresholds are hardcoded and not adaptive; boundary checks are simplistic [S1, unofficial].
*   **When to Use:** Real-time rendering of volumetric data with known density ranges; when computational resources are limited and a simple, fast approximation is acceptable [S1, unofficial].
*   **When Not to Use:** High-fidelity scientific visualization requiring adaptive step sizes; volumes with density ranges outside the hardcoded [40, 60] range; scenes requiring accurate transparency blending across large distances [S1, unofficial].

## Background
The method originates from a specific implementation discussed in a GameDev Stack Exchange post [S1, unofficial] titled "3D Texture Only interpolates on Y-Axis". The code snippet provided in the source demonstrates a fragment shader (`RayCastSimplePS`) that performs front-to-back raycasting using a fixed number of iterations and specific normalization thresholds [S1, unofficial]. It is part of a broader family of direct volume rendering techniques that map 3D texture coordinates to screen space and accumulate color along rays [S1, unofficial]. The technique is often used in real-time applications where performance is critical, and the volume data has a known, limited range of values [S1, unofficial].
