# Procedural Volumetric Cloud Rendering

Also called: Nubis³, Nubis Cubed, Nubis Evolved, Volumetric Cloud Renderer, Volumetric Cloud Rendering, Real-time Volumetric Cloud Rendering

## Overview
Procedural Volumetric Cloud Rendering is a real-time technique that renders planetary-scale cloud layers using adaptive ray marching through noise-based density fields, lit by multi-scattering approximations and shadowed by depth maps. It differs from local volumetrics or ground fog by treating clouds as a spherical shell surrounding a planet, allowing the camera to be inside, below, or above the layer, and supports multiple planets [S1, S2, S3, unofficial]. It combines the density shaping of Nubis Evolved/Cubed with the light transport of Frostbite [S2, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera position ($o$), ray direction ($d$), sun direction ($L_{dir}$), sun color ($L_{sun}$), cloud layer inner/outer radii ($R_{in}, R_{out}$), noise textures (Shape $128^3$, Detail $32^3$, Weather $512^2$), and parameters (density, wind, anisotropy).
*   **Outputs:** In-scattered radiance ($L_{in}$), transmittance ($T$), and transmittance-weighted mean depth ($D_{mean}$).

**Data Structures:**
*   **Shape Texture:** $128^3$ 3D texture, tileable, generated via compute shader. Contains Perlin fBm dilated by Worley noise plus three Worley octaves.
*   **Detail Texture:** $32^3$ 3D texture, tileable, Worley noise. Erodes base shape edges.
*   **Weather Map:** $512^2$ 2D texture. Stores coverage (0-1) and cloud type (stratus, cumulus, cumulonimbus) per region.
*   **Framebuffers:**
    *   Cloud FBO: Two attachments. `GL_RGBA16F` for radiance/transmittance, `GL_R32F` for depth.
    *   Resolve FBO: Two ping-pong `GL_RGBA16F` textures for temporal history.

**Step 1: Ray-Shell Intersection**
Calculate the intersection of the view ray with the spherical cloud shell.
Let $C$ be the planet center (typically $(0, -R_{planet}, 0)$ in local space).
Let $oc = o - C$.
Let $r_{cam} = |oc|$.
Let $b = \text{dot}(oc, d)$.
Let $c = \text{dot}(oc, oc)$.

Calculate outer intersection:
$h_{outer} = b^2 - (c - R_{out}^2)$.
If $h_{outer} < 0$, no intersection.
$s_{outer} = \sqrt{h_{outer}}$.
$t_{outer\_near} = -b - s_{outer}$.
$t_{outer\_far} = -b + s_{outer}$.

Calculate inner intersection:
$h_{inner} = b^2 - (c - R_{in}^2)$.
If $h_{inner} > 0$, $s_{inner} = \sqrt{h_{inner}}$, else $s_{inner} = 0$.
If $h_{inner} > 0$, $t_{inner\_near} = -b - s_{inner}$, $t_{inner\_far} = -b + s_{inner}$.

The valid marching interval is $[t_{start}, t_{end}]$.
If the ray starts inside the shell ($t_{inner\_near} < 0$), $t_{start} = 0$.
Otherwise, $t_{start} = t_{inner\_far}$ (if positive) or $t_{outer\_near}$.
$t_{end} = t_{outer\_far}$.
If $t_{start} \ge t_{end}$, return empty.

**Step 2: Adaptive Ray Marching**
Initialize $T = 1.0$, $L_{in} = (0,0,0)$, $depth\_sum = 0$.
Calculate step size $\Delta l$. Sources vary:
*   [S3, unofficial]: Derived from ray span, jittered per pixel with interleaved gradient noise.
*   [S2, unofficial]: Adaptive coarse/fine steps. Coarse step size multiplier 4x fine. Min fine steps 16.
*   [S4, unofficial]: Fixed step size based on quality preset (e.g., 1.0 to 3.0 units).

Loop while $t < t_{end}$ and $T > 0.005$ (0.5% threshold) [S3, unofficial]:
1.  **Sample Position:** $p = o + t \cdot d$.
2.  **Density Calculation:**
    *   Transform $p$ to noise space. Apply wind offset: $p_{wind} = p + \text{wind} \cdot \text{time}$.
    *   Sample Shape Texture $S$ at $p_{wind}$.
    *   Sample Detail Texture $D$ at $p_{wind}$.
    *   Sample Weather Map $W$ at horizontal projection of $p$. Get coverage $C_{cov}$ and type $T_{type}$.
    *   Apply vertical profile based on $T_{type}$ (stratus/cumulus/cumulonimbus) and height above base.
    *   Combine: $\rho = \text{Shape}(S) \cdot \text{Detail}(D) \cdot C_{cov}$.
    *   Apply falloffs (Y-axis and XZ-axis) if using box-based volumes [S2, unofficial].
    *   $\rho = \max(\rho \cdot \text{density\_mult}, 0)$.
3.  **Transmittance Update:**
    *   $\sigma_t = \rho \cdot \text{extinction}$.
    *   $T_{new} = T \cdot e^{-\sigma_t \Delta l}$.
    *   $T = T_{new}$.
4.  **Lighting (In-Scattering):**
    *   **Optical Depth to Sun:** Sample density along 6 steps toward sun direction $L_{dir}$ from $p$. Sum $\rho \cdot \Delta l_{sun}$. Calculate transmittance $T_{sun} = e^{-\sigma_t \cdot \text{optical\_depth}}$.
    *   **Phase Function:** Calculate $\cos \theta = \text{dot}(d, L_{dir})$.
        *   Use Mie phase [S1, unofficial] or two-lobe Henyey-Greenstein [S3, unofficial]:
        $$ P(\theta) = \frac{1-g^2}{4\pi (1+g^2-2g\cos\theta)^{1.5}} $$
        where $g$ is anisotropy.
    *   **Multiple Scattering:** Evaluate 4-octave approximation (attenuated extinction, contribution, phase eccentricity) [S3, unofficial].
    *   **Ambient/Powder:** Add ambient term (blue top, grey bottom) and powder term (darkens back-lit edges) [S3, unofficial].
    *   **Accumulate Radiance:**
        $$ L_{in} += T_{sun} \cdot P(\theta) \cdot \text{sun\_color} \cdot \sigma_s \cdot \Delta l \cdot T $$
        (Note: [S3, unofficial] states in-scattering is integrated analytically over each step so result is step-size independent).
5.  **Depth Accumulation:**
    *   $depth\_sum += T \cdot t \cdot \Delta l$.
6.  **Advance:**
    *   $t += \Delta l$.

**Step 3: Output**
*   $L_{out} = L_{in}$.
*   $T_{out} = T$.
*   $D_{mean} = depth\_sum / (1 - T)$ (if $T < 1$).

**Parameters:**
*   `shape_noise_scale`: 6.4 km (default). Controls cloud size.
*   `coverage`: Scales cloud fraction.
*   `density`: Global density multiplier.
*   `wind`: 2D vector for scrolling noise.
*   `anisotropy`: $g$ parameter for phase function.
*   `extinction`: Extinction coefficient.
*   `sun_intensity`: Sun brightness.
*   `max_steps`: 128 (default).

**Edge Cases:**
*   **Camera Inside Shell:** Ray intersection logic handles $t_{start}=0$.
*   **Thin Clouds Over Thick:** Reprojection uses mean depth; history clamp handles disocclusion [S3, unofficial].
*   **Shadow Map Basis:** Shadow map is traced along view's first directional light. Other lights must march cloud layer toward their own direction for correct shadows [S1, unofficial].

## Subtopics

### [Volumetric Clouds from Base Shape (Nubis/Frostbite Hybrid)](9609-volumetric-clouds-from-base-shape-nubis-frostbite-hybrid.md)
Renders clouds as a spherical shell using 3D noise density, combining Nubis shaping with Frostbite light transport. Choose for planetary-scale scenes with camera movement through the layer.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$ where $N$ is number of pixels and $M$ is number of steps per ray. Adaptive stepping reduces $M$ in empty space.
*   **Memory Complexity:** $O(R^3)$ for 3D noise textures ($128^3$ shape, $32^3$ detail) and $O(R^2)$ for weather map. Framebuffer storage for temporal reprojection.
*   **Performance:** On Mesa llvmpipe at 640x360, full-res 128 steps takes 927 ms. Half-res with temporal reprojection takes 266 ms (29% of full-res) [S3, unofficial].
*   **Strengths:** Real-time performance, supports arbitrary camera positions, physically-based lighting approximation, temporal stability.
*   **Limitations:** Approximate multiple scattering (flatter lit side than path tracing), sky is analytic gradient (not full atmosphere model), single cloud layer [S3, unofficial].
*   **When to Use:** Real-time games, planetary simulators, VR.
*   **When Not to Use:** Offline rendering requiring exact light transport, scenes with multiple distinct cloud layers at different altitudes (requires extensions).

## Background
Originating from Andrew Schneider's work on *Horizon: Zero Dawn* (Nubis) [S2, S3, unofficial] and refined in *Nubis Evolved* (SIGGRAPH 2022) and *Nubis³* [S1, unofficial], this technique integrates Hillaire's Frostbite sky/atmosphere model (SIGGRAPH 2016) [S1, S2, S3, unofficial]. It has been implemented in various open-source projects for engines like Bevy, Unity, and custom OpenGL frameworks [S1, S2, S3, S4, unofficial].
