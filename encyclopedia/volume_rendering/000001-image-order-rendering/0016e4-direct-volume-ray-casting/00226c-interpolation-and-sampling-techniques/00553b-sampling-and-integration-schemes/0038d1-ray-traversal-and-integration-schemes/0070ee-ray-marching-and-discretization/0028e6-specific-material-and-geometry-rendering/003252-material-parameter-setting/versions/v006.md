# Material Parameter Setting

Also called: Material Format, Material object fields, Standard Volume Material, vpSetMaterial

## Overview
Material Parameter Setting defines the optical and geometric properties of volumetric media by mapping raw data grids to physical attributes such as density, color, and emission. It solves the problem of converting abstract simulation data (e.g., density, temperature) into renderable radiance contributions within the volume rendering integral. It differs from sibling methods by focusing on the *definition* of these properties via explicit channel bindings and parameter sliders (Standard Volume Material) or low-level API calls (VolPack), rather than the traversal or shading algorithms themselves.

## How it works
The method operates in two primary paradigms: a high-level "Standard Volume Material" interface for direct grid binding, and a low-level "Material Format" structure for procedural or texture-driven shading. Both paradigms feed into the volume rendering integral by defining $\sigma_t$ (extinction/density) and $c$ (color/emission).

### Inputs and Outputs
*   **Inputs:** Raw scalar/vector grids (e.g., density, temperature, labels), user-defined parameters (density multipliers, anisotropy), and optional texture descriptors.
*   **Outputs:** A material state object or context configuration that defines how sample points along a ray are shaded.

### Data Structures

#### 1. Standard Volume Material (High-Level)
This structure binds named VDB grids to specific physical properties. It does not have a single C++ struct definition in the sources but is defined by its channel fields:
*   `Volume Channel`: String (case-sensitive name of the VDB grid, typically 'density').
*   `Density`: Float multiplier for the volume channel.
*   `Scatter Color`: RGB vector.
*   `Scatter Scale`: Float multiplier for scatter intensity.
*   `Anisotropy Mode`: Enum (Henyey-Greenstein or Jendersie-d’Eon).
*   `Transparency Color`: RGB vector (per-wavelength attenuation).
*   `Transparency Depth`: Float (cm, per-wavelength travel distance).
*   `Emission Channel`: String (name of temperature grid).
*   `Emission Mode`: Enum (Blackbody or Color).

#### 2. Material Object Fields (Low-Level/Procedural)
Defined in [S1], this struct holds shading parameters for surface-like volumetric boundaries or procedural volumes.

```cpp
struct Material {
    // Core PBR-like properties
    float albedo[3];       // Linear float RGB
    float metalness;       // Float [0..1]
    float roughness;       // Float [0..1]
    float F0[3];           // Linear float RGB, base reflectivity
    
    // Projection and Normal
    bool triplar;          // True for XZ planar, False for triplanar
    float normalStrength;  // Linear float
    
    // Texture Descriptors (-1 if unused)
    int albedoTex;         // Texture descriptor
    int normalTex;         // Texture descriptor
    int roughnessTex;      // Texture descriptor
    int metalnessTex;      // Texture descriptor
    int heightmapTex;      // Texture descriptor (geometric displacement)
    int ambietTex;         // Texture descriptor (ambient occlusion)
};
```

#### 3. VolPack Material State (API)
Defined in [S2], this is not a persistent struct but a state set via `vpSetMaterial`. The relevant constants are:
*   `material_num`: `VP_MATERIAL0` to `VP_MATERIAL5`.
*   `property`: `VP_AMBIENT`, `VP_DIFFUSE`, `VP_SPECULAR`, `VP_SHINYNESS`.
*   `surface_side`: `VP_EXTERIOR`, `VP_INTERIOR`, `VP_BOTH_SIDES`.

#### 4. VRDF SDK Material Configuration (GPU Shader Uniforms)
Defined in [S4, unofficial], this configuration binds textures and metadata to a shader material.

```cpp
struct VRDFMaterialConfig {
    int _IsLabelMap;       // 1 if labelmap, 0 otherwise
    float _P1;             // Lower bound of intensity range
    float _P99;            // Upper bound of intensity range
    vec4 _Dim;             // (dimX, dimY, dimZ, 1.0f)
    mat4 _Affine;          // 4x4 affine transform
    mat4 _InvAffine;       // Inverse affine transform
    texture3D _TFTex;      // Transfer function texture
    texture3D _VolumeTexLabels; // Label texture (fallback: BlackTex3D)
    texture3D _VolumeTexWeights; // Weight texture (fallback: BlackTex3D or null)
    int _HasWeights;       // 1 if weights exist, 0 otherwise
};
```

### Numbered Steps

#### Standard Volume Material Setup
1.  **Bind Volume Channel:** Assign the name of the density grid to the `Volume Channel` field. [S3]
2.  **Set Density:** Multiply the grid values by the `Density` parameter to control overall thickness. [S3]
3.  **Configure Scatter:** Set `Scatter Color` and `Scatter Scale` to define reflection properties. [S3]
4.  **Select Phase Function:** Choose `Anisotropy Mode`. Use Henyey-Greenstein (-1 to +1) for isotropic smoke or Jendersie-d’Eon for cloud droplets. [S3]
5.  **Configure Transparency:** Set `Transparency Color` (darker = thicker) and `Transparency Depth` (in cm) to model wavelength-dependent attenuation. [S3]
6.  **Configure Emission (Optional):** If rendering fire, bind the temperature grid to `Emission Channel`. Set `Emission Mode` to Blackbody for physical accuracy (3,000K–12,000K) or Color for artistic control. [S3]

#### VolPack API Setup
1.  **Initialize Context:** Create a `vpContext` object. [S2]
2.  **Set Material Properties:** Call `vpSetMaterial(vpc, material_num, property, surface_side, r, g, b)`. [S2]
    *   For `VP_SHINYNESS`, set `g` and `b` to 0. [S2]
3.  **Define Surface Side:** Use `VP_EXTERIOR` (gradient towards viewer), `VP_INTERIOR` (gradient away), or `VP_BOTH_SIDES`. [S2]
4.  **Reverse Sides (Optional):** Call `vpEnable(vpc, VP_REVERSE_SURFACE_SIDES)` to invert exterior/interior definitions. [S2]

#### VRDF SDK Setup
1.  **Extract Dimensions:** Get `dimX, dimY, dimZ` from `d.meta.dim`. [S4, unofficial]
2.  **Determine Intensity Range:**
    *   Initialize `p1 = 0.0f`, `p99 = 1.0f`.
    *   If `d.tf.type == "continuous"` and `d.meta.intensity_range` exists with length 2, set `p1 = d.meta.intensity_range[0]`, `p99 = d.meta.intensity_range[1]`. [S4, unofficial]
3.  **Compute Affine Matrices:** Construct `affine` from `d.meta.affine` (4x4). Compute `invAffine = affine.inverse()`. [S4, unofficial]
4.  **Select Textures:**
    *   `texLbl = volumeTexLabels ?? d.labelTexture ?? BlackTex3D`. [S4, unofficial]
    *   `texW = volumeTexWeights ?? d.weightTexture ?? null`. [S4, unofficial]
    *   Bind `_VolumeTexWeights` to `texW` or `BlackTex3D`. Set `_HasWeights = 1` if `texW != null`, else `0`. [S4, unofficial]
5.  **Bind Transfer Function:** Bind `_TFTex` to `tfTexCurrent`. Set `_IsLabelMap = 1` if `d.tf.type == "labelmap"`, else `0`. [S4, unofficial]
6.  **Set Uniforms:** Set `_P1`, `_P99`, `_Dim`, `_Affine`, `_InvAffine`. Assign `volumeMaterial` to `MeshRenderer.sharedMaterial`. [S4, unofficial]

#### Material Object Construction (Procedural)
1.  **Constructor 1 (Full):** Initialize `albedo`, `metalness`, `roughness`, `F0`. Set all texture descriptors (`albedoTex`, etc.) to `-1`. Set `triplar` to planar (False) and `normalStrength` to `1.0`. [S1]
2.  **Constructor 2 (Default F0):** Initialize `albedo`, `roughness`, `metalness`. Call Constructor 1 with `F0 = [0.04, 0.04, 0.04]`. [S1]

### Formulas

**Volume Rendering Integral (Context):**
$$
C(r) = \int_{t_n}^{t_f} T(t) \sigma_t(t) c(t) dt
$$
Where $\sigma_t$ is derived from the `Volume Channel` multiplied by `Density` and modified by `Transparency Color/Depth`. [S3]

**Blackbody Emission (Standard Volume):**
Temperature $T$ (Kelvin) maps to color $C$.
*   $T \approx 3,000$ K $\rightarrow$ Deep Red.
*   $T > 9,000$ K $\rightarrow$ White/Blue-White. [S3]

**Base Reflectivity (Material Format):**
For non-metal dielectrics, $F_0 = [0.04, 0.04, 0.04]$. [S1]

### Parameters and Typical Values
*   **F0:** `[0.04, 0.04, 0.04]` for dielectrics. [S1]
*   **Anisotropy (Henyey-Greenstein):** Slider range $[-1, 1]$. [S3]
*   **Transparency Depth:** Measured in centimeters; should match real-world volume size. [S3]
*   **Material IDs:** `VP_MATERIAL0` through `VP_MATERIAL5`. [S2]

### Edge Cases and Pitfalls
*   **Case Sensitivity:** Volume channel names are case-sensitive. [S3]
*   **Surface Side Ambiguity:** `VP_EXTERIOR` and `VP_INTERIOR` depend on gradient direction. Use `VP_REVERSE_SURFACE_SIDES` if the gradient is inverted relative to the viewer. [S2]
*   **Textureless Default:** Material objects default to textureless (descriptors = -1) unless explicitly bound. [S1]
*   **Labelmap Handling:** In VRDF, `_IsLabelMap` must be set correctly to switch between continuous and discrete transfer function evaluation. [S4, unofficial]

## Subtopics

### Volume Material Setup
A specific implementation within the VRDF SDK that handles the binding of transfer functions, label maps, and weight textures to the GPU shader. It distinguishes itself by supporting label-based rendering (discrete classes) and weighted sampling. Choose this when using the VRDF SDK for scientific visualization requiring label maps or importance weighting. [S4, unofficial]

## Operating characteristics
*   **Time Complexity:** O(1) for setting up the material state; O(N) for shading N samples along rays (dependent on the traversal method, not the material setting itself).
*   **Memory Complexity:** O(1) for the material struct; O(V) for the underlying VDB grids and textures.
*   **Strengths:** Standard Volume Material offers a fast path for common use cases (clouds, smoke, fire) with physically based presets. VolPack provides simple, low-level control for binary or simple scalar volumes. VRDF SDK offers flexible GPU-side transfer function handling.
*   **Limitations:** Standard Volume Material's "fast path" limits procedural complexity compared to the node-based approach. VolPack is legacy and lacks modern PBR features. VRDF SDK requires manual affine matrix management.
*   **When to Use:** Use Standard Volume Material for general-purpose VDB rendering. Use VolPack for legacy C-style API integration. Use VRDF SDK for custom GPU-based volume rendering pipelines with label maps.

## Background
*   **Standard Volume Material:** Originated with Maxon's Cinema 4D and Redshift renderer, designed to simplify VDB volume rendering for artists. [S3]
*   **Material Format:** Described in "Raymarching Distance Fields with CUDA" (2021), providing a CUDA-friendly material structure for raymarched SDFs and volumes. [S1]
*   **VolPack:** Developed at Stanford University in the 1990s, providing a C library for volume rendering. [S2]
*   **VRDF SDK:** An unofficial SDK by Guillaume Schneider for rendering volumetric data in Unity/Unreal, supporting label maps and transfer functions. [S4, unofficial]
