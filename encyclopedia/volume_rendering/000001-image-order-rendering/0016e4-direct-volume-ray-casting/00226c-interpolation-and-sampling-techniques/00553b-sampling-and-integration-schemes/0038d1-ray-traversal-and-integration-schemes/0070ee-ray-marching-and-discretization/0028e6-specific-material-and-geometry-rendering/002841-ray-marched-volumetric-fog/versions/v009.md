# Ray-marched Volumetric Fog

Also called: Fog Filter, Forward ray-marching fog, Full-screen volumetric fog, Volumetric Fog (CRYENGINE 3), Voxel-based Volumetric Fog

## Overview
Ray-marched volumetric fog simulates light absorption, scattering, and soft shadows by treating fog as a 3D volume of participating media traced via forward ray-marching from the camera to the scene [S2, unofficial]. It solves the problem of rendering aerial perspective and dynamic light shafts (god rays) in real-time applications [S1][S2, unofficial]. Unlike backward ray-marching, this method marches from the camera outward, enabling early-out optimizations when transmittance drops below a threshold [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera position, view direction, depth buffer (for scene intersection), light position/intensity, fog density ($\tau$), scattering coefficient ($a$), phase function parameters, and step size ($\Delta l$).
*   **Outputs:** Final pixel radiance $L$.

**Data Structures:**
*   **Ray:** Defined by origin $o$ (camera position) and direction $d$ (view vector).
*   **Depth Buffer:** 2D texture mapping UV coordinates to depth values $z$.
*   **Light Data:** Position $L_{pos}$, intensity $\Phi$.

**Numbered Steps:**
1.  **Ray Initialization:** For each pixel with UV coordinate $u$, construct a ray $r(t) = o + t \cdot d$.
2.  **Scene Intersection:** Sample the depth buffer at $u$ to obtain the depth $z_{scene}$. Reconstruct the 3D world position $x_{scene}$ of the scene intersection. If no intersection is found, clamp the ray length to a maximum distance $z_{far}$ [S2, unofficial].
3.  **Jittering:** To prevent slice artifacts, add a pseudo-random offset $\delta$ to the ray's starting position or step count. This ensures adjacent rays sample different "slices" of the volume [S2, unofficial].
4.  **Ray Marching Loop:** Iterate from $t = 0$ to $t = t_{max}$ (where $t_{max}$ is the distance to $x_{scene}$ or $z_{far}$) with step size $\Delta l$.
    *   Calculate current sample position $x(l_n) = o + l_n \cdot d$, where $l_n$ is the accumulated distance.
    *   Calculate transmittance from camera to sample: $T_{cam} = e^{-\tau l_n}$.
    *   Calculate in-scattering radiance $L_i$ at $x(l_n)$:
        $$ L_i(x(l_n), \omega) = \frac{a \Phi}{4\pi d_{light}^2} v(x) e^{-\tau d_{light}} P(\omega, \omega_{light}) $$
        where $d_{light}$ is the distance from $x(l_n)$ to the light source, $v(x)$ is visibility (1 if unoccluded, or sampled from shadow map), and $P$ is the phase function [S2, unofficial].
    *   Accumulate radiance: $L \leftarrow L + L_i \cdot T_{cam} \cdot \Delta l$.
    *   **Early-Out:** If $T_{cam}$ drops below a threshold (e.g., $10^{-3}$), terminate the loop [S2, unofficial].
5.  **Final Compositing:** Add the accumulated fog radiance $L$ to the background color (scene color at $x_{scene}$) weighted by the total transmittance $T_{total} = e^{-\tau t_{max}}$.

**Pseudocode:**
```python
def ray_marched_volumetric_fog(camera_pos, view_dir, depth_buffer, light_pos, light_intensity, fog_density, scattering_coeff, phase_func, step_size, z_far):
    # 1. Initialize
    ray_origin = camera_pos
    ray_dir = view_dir
    max_dist = z_far
    
    # 2. Scene Intersection
    # Reconstruct scene position from depth buffer at current UV
    scene_depth = depth_buffer.sample(current_uv)
    scene_pos = reconstruct_world_position(current_uv, scene_depth)
    
    # Calculate distance to scene
    dist_to_scene = length(scene_pos - ray_origin)
    max_dist = min(max_dist, dist_to_scene)
    
    # 3. Jittering
    # Add pseudo-random offset to start position or step index to break slice alignment
    jitter = random_float(0.0, step_size)
    
    accumulated_radiance = vec3(0.0)
    current_dist = 0.0
    current_pos = ray_origin + ray_dir * jitter
    
    # 4. Ray Marching Loop
    while current_dist < max_dist:
        # Calculate transmittance from camera to current sample
        # T = exp(-density * distance)
        transmittance = exp(-fog_density * current_dist)
        
        # Early-out optimization
        if transmittance < 0.001:
            break
            
        # Calculate in-scattering term
        # Distance from sample point to light
        dist_to_light = length(light_pos - current_pos)
        
        # Visibility: 1.0 if no shadow mapping, else sample shadow map
        visibility = 1.0 
        
        # Transmittance from light to sample point
        light_transmittance = exp(-fog_density * dist_to_light)
        
        # Phase function approximation (Schlick-Henyey-Greenstein)
        # P depends on scattering angle between view_dir and light_dir
        phase = schlick_henyey_greenstein(view_dir, light_pos - current_pos)
        
        # In-scattering formula: Li = (a * Phi / (4 * pi * d^2)) * v * e^(-tau*d) * P
        in_scattering = (scattering_coeff * light_intensity / (4.0 * 3.14159 * dist_to_light * dist_to_light)) * visibility * light_transmittance * phase
        
        # Accumulate: L += Li * T_cam * delta_l
        accumulated_radiance += in_scattering * transmittance * step_size
        
        # Advance ray
        current_dist += step_size
        current_pos = ray_origin + ray_dir * current_dist
        
    # 5. Final Compositing
    # Total transmittance to scene
    total_transmittance = exp(-fog_density * current_dist)
    
    # Get background color from scene
    background_color = scene_color_at(scene_pos)
    
    # Final pixel color
    final_color = background_color * total_transmittance + accumulated_radiance
    
    return final_color
```

**Parameters:**
*   **Density ($\tau$):** Controls fog thickness. Constant for uniform fog [S2, unofficial].
*   **Scattering Coefficient ($a$):** Probability of photon scattering [S2, unofficial].
*   **Step Size ($\Delta l$):** Distance between samples. Smaller values reduce artifacts but increase cost [S2, unofficial].
*   **Phase Function ($P$):** Schlick approximation of Henyey-Greenstein is used for real-time performance [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Slice Artifacts:** Regular sampling grids cause visible banding ("slices") because rays sample aligned points. Fixed by jittering [S2, unofficial].
*   **Noise:** Jittering introduces noise, especially with large step sizes [S2, unofficial].
*   **Infinite Marching:** Rays missing the scene must be clamped to $z_{far}$ [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is the number of steps per ray.
*   **Memory Complexity:** $O(1)$ per pixel (excluding depth buffer and shadow maps).
*   **Strengths:** Simple implementation; allows early-out optimization; works well for uniform or simple procedural fog [S2, unofficial].
*   **Limitations:** High computational cost for large volumes or small step sizes; prone to noise without temporal or spatial filtering; slice artifacts require jittering [S2, unofficial].
*   **When to Use:** Real-time applications requiring simple aerial perspective or light shafts with limited budget [S2, unofficial].
*   **When Not to Use:** Complex, non-uniform volumes requiring high accuracy; scenes with many dynamic light sources requiring shadow maps for every sample [S2, unofficial].

## Background
Volumetric fog is a medium that emits or absorbs light, used for aerial perspective [S1]. The technique of ray-marching fog in games, such as in *Horizon Zero Dawn*, *Death Stranding*, and *Returnal*, treats fog as participating media traced via ray-marching [S2, unofficial]. The specific forward ray-marching implementation described here follows the approach of Toth and Umenhofer (Real-time Volumetric Lighting in Participating Media) but adapts it for forward marching to enable early-out optimizations [S2, unofficial].
