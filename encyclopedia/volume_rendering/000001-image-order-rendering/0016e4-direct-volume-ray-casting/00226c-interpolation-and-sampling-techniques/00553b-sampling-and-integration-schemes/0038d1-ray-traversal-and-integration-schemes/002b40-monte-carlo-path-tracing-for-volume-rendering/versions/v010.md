# Monte Carlo Path Tracing for Volume Rendering

Also called: Exposure Render DVR Framework, MCSRender, Monte Carlo Scattering Rendering, Progressive Stochastic Volume Rendering, Stochastic Raycasting DVR

## Overview
Monte Carlo Path Tracing for Volume Rendering is a unified, brute-force, progressive stochastic rendering framework designed to produce photo-realistic direct volume rendering (DVR) without relying on pre-computed quantities or auxiliary volumes [S1]. It solves the problem of physically accurate light transport in participating media by treating the volume as a continuous medium, supporting complex lighting (directional, point, environment) and hybrid surface/volumetric scattering [S1]. Unlike slice-based or isosurface-based methods, it integrates depth-of-field and scattering in a unified stochastic manner, making it distinct from siblings like [Ray Marching and Discretization](2788-ray-marching-and-discretization.md) which use fixed step sizes, and [Front-to-Back Volume Ray Casting with HSV Shading and SOS/Attenuation/Reflection Filtering](4324-front-to-back-volume-ray-casting-with-hsv-shading-and-sos-at.md) which often rely on approximations for lighting [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Volumetric data (typically 16-bit unsigned short [S1]), camera parameters (position, lens aperture, film plane), lighting configuration (environment map, point/area lights), transfer function (opacity $\alpha$, color), and maximum extinction coefficient $\sigma_{max}$ [S1][S2, unofficial].
*   **Outputs:** A Low Dynamic Range (LDR) image, accumulated progressively over frames [S1].

**Data Structures:**
*   **Accumulator Buffer:** Stores the cumulative Monte Carlo estimate (HDR) for each pixel. Initialized to zero [S1][S2, unofficial].
*   **Frame Buffer:** Stores the current frame's HDR estimate [S2, unofficial].
*   **Camera Parameters:** Stored in constant memory for fast access [S1].
*   **Light Data:** Stored in constant memory [S1].

**Parameters:**
*   $\sigma_{max}$: Maximum extinction coefficient used for Woodcock tracking [S2, unofficial].
*   $g$: Gradient factor $[0, 1]$ controlling the blend between surface and volumetric scattering [S1].
*   $\alpha_x$: Opacity at sample position $x$ from the transfer function [S1].
*   Gaussian Kernel: Standard deviation $\sigma=1.5$, window $5 \times 5$ pixels [S1].
*   $uOffset$: Offset for random seed generation [S2, unofficial].
*   $uInvFrameNumber$: Inverse of the current frame number $1/N$ for accumulation [S2, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Clear the Accumulator Buffer to $(0,0,0,1)$ if the transfer function, lighting, or camera position has changed [S1][S2, unofficial].
    *   Initialize frame counter $N=1$ [S2, unofficial].

2.  **Ray Generation:**
    *   Unproject screen position to get ray origin $v_{RayFrom}$ and ray end $v_{RayTo}$ using the inverse Model-View-Projection matrix [S2, unofficial].
    *   Construct a camera ray using a thin lens model: sample a point on the lens and a perturbed point on the film plane using stratified sampling [S1].
    *   Intersect the ray with the volume’s bounding box to obtain parametric range $[t_{min}, t_{max}]$. If no intersection, discard [S1].
    *   Calculate ray segment within the cube: $from = v_{RayFrom} + t_{min} \cdot direction$, $to = v_{RayFrom} + t_{max} \cdot direction$. Compute $maxDistance = ||to - from||$ [S2, unofficial].

3.  **Scattering Point Selection (Woodcock Tracking):**
    *   Initialize seed: $seed = v_{Position} + rand(vec2(uOffset, uOffset))$ [S2, unofficial].
    *   Call `sampleDistance(from, to, seed)` to find the first scattering distance $dist$:
        ```python
        def sample_distance(from_point, to_point, max_distance, sigma_max, seed):
            inv_sigma_max = 1.0 / sigma_max
            inv_max_distance = 1.0 / max_distance
            dist = 0.0
            while True:
                # Generate random number for path length
                r = rand(seed) # Assuming rand generates uniform [0,1)
                dist -= log(1.0 - r.x) * inv_sigma_max
                if dist > max_distance:
                    return max_distance # Ray exits volume
                # Sample position
                sampling_position = mix(from_point, to_point, dist * inv_max_distance)
                # Sample alpha from transfer function
                alpha_sample = sample_volume_color_alpha(sampling_position) * uAlphaCorrection
                # Acceptance test
                r2 = rand(seed + 1) # Use next random number
                if r2.y < alpha_sample * inv_sigma_max:
                    return dist
                # Update seed for next iteration
                seed = seed + 1
        ```
    *   If $dist > maxDistance$, sample the environment map and output as color [S2, unofficial].
    *   Update $from = mix(from, to, dist / maxDistance)$ [S2, unofficial].

4.  **Lighting and Transmittance Calculation:**
    *   Sample diffuse color at $from$: $diffuseColor = sampleVolumeColor(from)$ [S2, unofficial].
    *   Sample light color from environment in scattering direction $uScatteringDirection$: $lightColor = sampleEnvironmentMap(uScatteringDirection)$ [S2, unofficial].
    *   Calculate transmittance from $from$ to $to$ using `sampleTransmittance`:
        ```python
        def sample_transmittance(from_point, to_point, max_distance, sigma_max, seed):
            inv_sigma_max = 1.0 / sigma_max
            inv_max_distance = 1.0 / max_distance
            transmittance = 1.0
            dist = 0.0
            while True:
                r = rand(seed)
                dist -= log(1.0 - r.x) * inv_sigma_max
                if dist > max_distance:
                    break
                sampling_position = mix(from_point, to_point, dist * inv_max_distance)
                alpha_sample = sample_volume_color_alpha(sampling_position) * uAlphaCorrection
                transmittance *= (1.0 - alpha_sample * inv_sigma_max)
                seed = seed + 1
            return transmittance
        ```
    *   Final color contribution: $oColor = diffuseColor \times lightColor \times transmittance$ [S2, unofficial].

5.  **Hybrid Scattering (Surface vs. Volume):**
    *   Calculate BRDF probability $P_{brdf}$:
        $$P_{brdf} = \alpha_x \cdot (1 - \exp(-25 \cdot g \cdot ||\nabla t_n(x)||))$$
        where $\alpha_x$ is opacity, $||\nabla t_n(x)||$ is normalized gradient magnitude, and $g$ is the gradient factor [S1].
    *   Draw random $j \sim U[0,1]$.
    *   If $j < P_{brdf}$: Treat as surface scattering. Use Fresnel blend shading model (diffuse + glossy) [S1].
    *   Else: Treat as volumetric scattering. Use isotropic phase function (or Schlick’s) [S1].
    *   *Note:* The sources describe calculating direct lighting contribution via Woodcock tracking for shadowing and combining contributions using Multiple Importance Sampling (MIS) with the power heuristic [S1]. The simplified shader code in [S2, unofficial] focuses on single-scattering environment lighting.

6.  **Progressive Accumulation:**
    *   Compute current frame estimate $frame$ [S2, unofficial].
    *   Filter $frame$ with a separable Gaussian kernel ($\sigma=1.5$, $5 \times 5$ window) to reduce anti-aliasing [S1].
    *   Accumulate using cumulative moving average:
        ```python
        acc = texture(uAccumulator, vPosition)
        frame = texture(uFrame, vPosition)
        oColor = acc + (frame - acc) * uInvFrameNumber
        ```
    *   Increment frame counter $N$. Update $uInvFrameNumber = 1/N$ [S2, unofficial].

7.  **Post-Processing:**
    *   Tone map the HDR estimate to compress dynamic range [S1].
    *   Gamma correct [S1].
    *   Apply anisotropic filtering to the LDR image to reduce noise [S1].

**Edge Cases and Pitfalls:**
*   **Ray Marching Performance:** Standard ray marching is prohibitively slow for shadow calculations at every sample. Woodcock tracking is used to yield fewer shadow computations and remains unbiased [S1].
*   **Startup Noise:** Noise is objectionable at the start. A noise reduction filter is applied during initial iterations, reducing its influence based on the error in the running estimate [S1].
*   **Reset Condition:** Any change in transfer function, lighting, or camera position requires clearing the accumulator and restarting [S1].

## Operating characteristics
*   **Time Complexity:** Unbiased Monte Carlo integration converges at $O(1/\sqrt{N})$ where $N$ is the number of samples (frames). Performance is measured in frame estimates per second.
*   **Memory Complexity:** Memory footprint is insensitive to lighting, material, camera, and transfer function configurations [S1]. Requires storage for the accumulator buffer and frame buffer [S2, unofficial].
*   **Measured Performance:** Rendered at 800x600 pixels with environment and area lights [S1]:
    *   Mecanix (512x743x512): 35.2 (Front), 34.1 (Left), 36.3 (Top) fps [S1].
    *   Manix (512x460x512): 32.7 (Front), 39.7 (Left), 42.4 (Top) fps [S1].
    *   Engine (256x256x128): 65.5 (Front), 53.7 (Left), 65.7 (Top) fps [S1].
    *   Bonsai (256x256x257): 57.7 (Front), 66.6 (Left), 68.1 (Top) fps [S1].
    *   Artifix (512x347x512): 47.3 (Front), 40.3 (Left), 50.8 (Top) fps [S1].
*   **Strengths:** Physically accurate, supports complex lighting (directional, point, environment), unified depth-of-field, unbiased [S1].
*   **Limitations:** Slow convergence (requires progressive refinement), noisy at startup, computationally expensive compared to deterministic ray marching [S1].
*   **When to use:** Photo-realistic visualization where physical accuracy is paramount.
*   **When not to use:** Real-time applications requiring immediate feedback without progressive refinement, or scenes with extremely high dynamic range requiring many samples for convergence.

## Background
The method was introduced by Csébfalvi et al. in 2012 as part of the Exposure Render framework [S1]. It was the first to demonstrate interactive, brute-force, progressive stochastic rendering for photo-realism in DVR [S1]. It builds on Monte Carlo Ray Tracing (MCRT) principles [S1]. It is used in the Exposure Render framework and demonstrated on datasets like Mecanix, Manix, Engine, Bonsai, Artifix, and bat CT scans [S1].
