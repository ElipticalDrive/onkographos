# Ray Casting with Ray Subdividing

Also called: Adaptive Ray Subdivision, Ray Splitting for Perspective Rendering, Ray Subdividing

## Overview
Ray Casting with Ray Subdividing maintains adequate spatial sampling rates in volume rendering under perspective projection, where rays diverge as they travel deeper into the scene [S2, book][S3, unofficial]. It addresses undersampling in distant volume slices by dynamically splitting rays when local ray density falls below a threshold, ensuring sample footprints remain consistent with the target resolution [S1, unofficial][S2, book]. Unlike fixed-step ray marching, this method adapts integration granularity based on geometric divergence rather than local data features [S3, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Perspective camera rays $r(t) = \mathbf{o} + t\mathbf{d}$, a volume dataset $V$, and a target maximum screen-space footprint size $\delta_{max}$ [S2, book][S3, unofficial].
- Output: Color and opacity values for each pixel, computed via front-to-back compositing [G].

**Data Structures:**
- Active Ray List: A queue of ray segments, each storing origin $\mathbf{o}$, direction $\mathbf{d}$, current depth $t$, original screen-space position, accumulated color $C$, accumulated opacity $\alpha$, and pixel identifier [G].

**Steps:**
1. **Initialization**: Generate one ray per pixel from the camera center through the pixel center [G].
2. **Divergence Check**: For each ray, compute the screen-space distance to its original pixel center or nearest sibling at the current depth $t$ [S2, book][S3, unofficial].
3. **Splitting**: If the distance exceeds $\delta_{max}$, split the ray into two or more sub-rays [S3, unofficial]. The new origins are offset in screen space, and directions are adjusted to maintain perspective consistency. The original ray is removed and replaced by the sub-rays in the list [G].
4. **Integration**: For each ray segment, sample the volume, interpolate values, and composite along the segment until the next split point or volume exit [G].
5. **Merging**: When rays converge or density exceeds requirements, adjacent segments can be merged to reduce computation, tracking ancestry for correct compositing [S1, unofficial].
6. **Final Compositing**: Combine results from all leaf rays contributing to each pixel [G].

**Formulas:**
- Ray Divergence Metric: Let $d_{screen}(r_i, r_j)$ be the Euclidean distance between the screen-space projections of rays $r_i$ and $r_j$ at depth $t$. Split if:
  $$ d_{screen}(r_i, r_j) > \delta_{max} $$
  where $\delta_{max}$ is the maximum allowed screen-space footprint size [S2, book][S3, unofficial].

**Parameters:**
- $\delta_{max}$: Typically set to the pixel pitch or a fraction thereof, depending on desired anti-aliasing quality [G].

**Edge Cases and Pitfalls:**
- **Infinite Splitting**: If $\delta_{max}$ is too small, rays may split indefinitely. Enforce a maximum recursion depth or minimum ray segment length [G].
- **Merging Complexity**: Merging requires careful handling of compositing order to avoid artifacts. Efficient spatial partitioning may be needed to find nearest neighbors quickly [S1, unofficial].

**Pseudocode:**
```python
import math

def ray_casting_with_subdivision(camera_rays, volume, delta_max, max_depth):
    # Active ray queue: (origin, direction, depth, pixel_id, orig_screen_pos, acc_c, acc_a)
    active_rays = []
    for r in camera_rays:
        active_rays.append((r.origin, r.direction, 0.0, r.pixel_id, [r.origin[0], r.origin[1]], [0.0, 0.0, 0.0], 0.0))
    pixel_results = {}

    while active_rays:
        next_rays = []
        for origin, direction, depth, pixel_id, orig_screen, acc_c, acc_a in active_rays:
            # 1. Compute screen-space position at current depth
            pos = [origin[i] + direction[i] * depth for i in range(3)]
            screen_pos = [pos[0], pos[1]]

            # 2. Check divergence against original pixel center
            dist = math.sqrt((screen_pos[0] - orig_screen[0])**2 + (screen_pos[1] - orig_screen[1])**2)

            if dist > delta_max and depth < max_depth:
                # 3. Split ray into two sub-rays with offset origins
                offset = delta_max * 0.5
                r1_origin = [origin[0] + offset, origin[1] + offset, origin[2]]
                r2_origin = [origin[0] - offset, origin[1] - offset, origin[2]]
                next_rays.append((r1_origin, direction, depth, pixel_id, orig_screen, acc_c, acc_a))
                next_rays.append((r2_origin, direction, depth, pixel_id, orig_screen, acc_c, acc_a))
            else:
                # 4. Integrate ray segment through volume
                step_size = 0.1
                t = depth
                seg_c = [0.0, 0.0, 0.0]
                seg_a = 0.0
                while t < depth + 1.0:
                    sample_pt = [origin[i] + direction[i] * t for i in range(3)]
                    val = volume.query(sample_pt) # Standard volume query [G]
                    c, a = val.color, val.opacity
                    seg_c = [seg_c[i] + c[i] * a * (1.0 - seg_a) for i in range(3)]
                    seg_a = seg_a + a * (1.0 - seg_a)
                    t += step_size

                # 5. Composite segment result into pixel accumulator
                nc = [acc_c[i] + seg_c[i] * seg_a * (1.0 - acc_a) for i in range(3)]
                na = acc_a + seg_a * (1.0 - acc_a)
                pixel_results[pixel_id] = (nc, na)
        active_rays = next_rays
    return pixel_results
```

## Operating characteristics
- **Time Complexity**: $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the average number of splits per ray. Splits increase $S$ in distant regions [G].
- **Memory Complexity**: $O(N \cdot D)$, where $D$ is the maximum depth of ray splitting. The ray queue grows with the number of active sub-rays [G].
- **Performance**: Improves image quality in distant regions compared to fixed-step ray marching. However, it is more complex to implement and may have higher overhead due to queue management [G].
- **Strengths**: Maintains consistent sampling density across the entire volume, reducing aliasing in perspective views [S2, book][S3, unofficial].
- **Limitations**: Complex implementation; potential for high memory usage if many rays split; merging is non-trivial [G].
- **When to Use**: Perspective volume rendering where distant details are important and fixed-step sampling leads to aliasing [S3, unofficial].
- **When Not to Use**: Parallel projection (where rays do not diverge) or when performance is critical and some aliasing is acceptable [S3, unofficial].

## Background
The concept of ray subdividing was introduced as a solution to the undersampling problem in perspective volume rendering [S3, unofficial]. It is considered an equivalent approach to Elliptical Weighted Average (EWA) splatting for raycasting, which handles screen-space footprint mapping [S1, unofficial][S2, book]. Kreeger et al. proposed improvements involving optimal splitting and merging of rays [S1, unofficial]. The method operates on the principle that continuous volume functions must be approximated from discrete samples, adapting the sampling grid to camera geometry rather than data density [S1, unofficial][S2, book].
