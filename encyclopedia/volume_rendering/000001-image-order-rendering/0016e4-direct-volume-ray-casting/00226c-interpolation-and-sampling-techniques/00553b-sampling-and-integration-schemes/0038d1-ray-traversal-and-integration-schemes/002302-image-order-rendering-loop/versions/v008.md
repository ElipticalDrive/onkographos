# Image-order Rendering Loop

Also called: Image order approach, Image-Order Volume Ray Casting, Image-ordered ray casting, Main Rendering Loop, Octree Rendering Loop

## Overview
The Image-order Rendering Loop is the primary control structure for volume ray casting, iterating over each pixel of the output image to generate a ray and shade the scene along that ray [S2, unofficial][S3]. It solves the problem of mapping 3D volumetric data to a 2D screen by decoupling pixel generation from data traversal, allowing for correct perspective projection and flexible shading models in a single pass [S1, unofficial]. Unlike object-order (rasterization) methods, it is described as more "CPU-like" but offers superior flexibility for adaptive sampling and full 32-bit compositing precision without intermediate buffers [S1, unofficial].

## How it works
The method operates by iterating through the screen space, generating camera rays, and invoking a raymarcher to sample the volume. The core logic follows a nested loop structure: an outer loop over pixels and an inner loop over ray samples (or traversal steps).

**Inputs and Outputs:**
*   **Inputs:** Image dimensions ($vwidth, vheight$), camera parameters (position, direction, projection mode), volume dataset, shading mode enum.
*   **Outputs:** A 2D image buffer where each pixel contains the final color and/or depth value.

**Data Structures:**
*   **Pixel Coordinates:** Integer indices $(x, y)$ ranging from $0$ to $vwidth-1$ and $0$ to $vheight-1$.
*   **Ray Parameters:** `rayOrigin` (vec3), `rayDirection` (vec3).
*   **Shading Mode:** Enum values including `TRACE`, `DEPTH`, `DEPTH_HIT`, `DIFFUSE`, `NORMAL`, `INDEX` [S2, unofficial].
*   **Projection Mode:** Enum values `PERSPECTIVE`, `ORTHOGRAPHIC` [S2, unofficial].

**Numbered Steps:**
1.  **Initialization:** Set `CompletedSamples = 0`. Calculate light bounds $p_0, p_1$ if required for lighting checks [S2, unofficial].
2.  **Camera Transformation:** Apply rotation to the camera position and direction vectors [S2, unofficial].
3.  **Pixel Loop:** Iterate $y$ from $0$ to $vheight-1$ and $x$ from $0$ to $vwidth-1$.
4.  **Ray Generation:**
    *   Calculate normalized position $pos$ from pixel coordinates $(x, y)$ [S2, unofficial].
    *   If `ProjectionMode == PERSPECTIVE`:
        *   `rayOrigin` = `cameraPos`
        *   `rayDirection` = `cameraDir` + `pos`
    *   If `ProjectionMode == ORTHOGRAPHIC`:
        *   `rayOrigin` = `cameraPos` + `pos`
        *   `rayDirection` = `cameraDir`
5.  **Ray Marching/Shading:**
    *   If `ShadingMode == TRACE`:
        *   Call `ShadePathTrace` (or equivalent raymarcher) to accumulate color.
        *   Average the result with previous samples if `CompletedSamples > 0` [S2, unofficial].
    *   Else:
        *   Call `Raymarch` to find intersection or sample data.
        *   If a hit is detected, shade based on the active `ShadingMode` (e.g., DEPTH, DIFFUSE, NORMAL) [S2, unofficial].
        *   If no hit but the ray intersects the light AABB, write the light color [S2, unofficial].
        *   Otherwise, write a dark color (e.g., 25, 25, 25) [S2, unofficial].
6.  **Output:** Write the computed color/depth to the pixel buffer at index $x + y \times vwidth$ [S2, unofficial].

**Formulas:**
*   **Ray Origin (Perspective):** $\mathbf{o} = \mathbf{C}$
*   **Ray Direction (Perspective):** $\mathbf{d} = \mathbf{D} + \mathbf{P}$
*   **Ray Origin (Orthographic):** $\mathbf{o} = \mathbf{C} + \mathbf{P}$
*   **Ray Direction (Orthographic):** $\mathbf{d} = \mathbf{D}$
    *   Where $\mathbf{C}$ is camera position, $\mathbf{D}$ is camera direction, and $\mathbf{P}$ is the normalized pixel offset [S2, unofficial].

**Parameters:**
*   **ShadingMode:** Determines the visual output. Common values: `TRACE` (path tracing), `DEPTH` (depth visualization), `DIFFUSE` (diffuse lighting), `NORMAL` (normal visualization), `INDEX` (scalar index) [S2, unofficial].
*   **ProjectionMode:** `PERSPECTIVE` or `ORTHOGRAPHIC` [S2, unofficial].
*   **Compositing Methods:** MIP (Maximum Intensity Projection), averaging, nearest-point, and alpha compositing are commonly used within the compositing module [S3].

**Edge Cases and Pitfalls:**
*   **Shader Model Requirements:** Requires Shader Model 3.0 or higher to enable conditional loops and early loop exit in fragment shaders, which replaces multiple rendering passes and early-z testing [S1, unofficial].
*   **Precision:** The method supports full 32-bit compositing precision, avoiding the need for a separate compositing buffer [S1, unofficial].
*   **Lighting Bounds:** Failure to correctly calculate light bounds ($p_0, p_1$) may result in incorrect lighting for rays that do not hit the volume but pass through light sources [S2, unofficial].

**Pseudocode:**
```python
def image_order_rendering_loop(vwidth, vheight, camera_pos, camera_dir, projection_mode, shading_mode, volume_data):
    """
    Renders a volume using the image-order approach.
    
    Args:
        vwidth (int): Width of the output image.
        vheight (int): Height of the output image.
        camera_pos (Vec3): Camera position.
        camera_dir (Vec3): Camera direction vector.
        projection_mode (str): 'PERSPECTIVE' or 'ORTHOGRAPHIC'.
        shading_mode (str): 'TRACE', 'DEPTH', 'DEPTH_HIT', 'DIFFUSE', 'NORMAL', 'INDEX'.
        volume_data (Volume): The volumetric dataset.
        
    Returns:
        Image: The rendered 2D image buffer.
    """
    image = Image(vwidth, vheight)
    completed_samples = 0
    
    # Pre-calculate light bounds if necessary for lighting checks
    # light_bounds = calculate_light_bounds(volume_data) 
    
    for y in range(vheight):
        for x in range(vwidth):
            # Calculate normalized pixel position
            # Implementation detail: 'pos' depends on specific camera setup
            # Assuming a simple linear mapping for demonstration
            pos = calculate_pixel_offset(x, y, vwidth, vheight)
            
            # Transform camera parameters (rotation applied here)
            # transformed_pos = rotate(pos)
            # transformed_dir = rotate(camera_dir)
            # transformed_cam_pos = rotate(camera_pos)
            
            # Generate Ray
            if projection_mode == 'PERSPECTIVE':
                ray_origin = camera_pos
                ray_direction = camera_dir + pos
            elif projection_mode == 'ORTHOGRAPHIC':
                ray_origin = camera_pos + pos
                ray_direction = camera_dir
            else:
                raise ValueError("Unknown projection mode")
            
            # Normalize direction if necessary
            ray_direction = normalize(ray_direction)
            
            # Ray Marching and Shading
            if shading_mode == 'TRACE':
                # Path tracing accumulation
                color = shade_path_trace(ray_origin, ray_direction, volume_data)
                if completed_samples > 0:
                    # Average with previous samples
                    color = (color + image.get_pixel(x, y)) / 2.0
                image.set_pixel(x, y, color)
                completed_samples += 1
            else:
                # Standard raymarching
                hit, hit_point, normal = raymarch(ray_origin, ray_direction, volume_data)
                
                if hit:
                    if shading_mode == 'DEPTH':
                        depth = distance(camera_pos, hit_point)
                        # Example depth shading: green channel scales with depth
                        color = volume_data.get_color(hit_point)
                        color.g *= depth / 2.0
                    elif shading_mode == 'DEPTH_HIT':
                        depth = distance(camera_pos, hit_point)
                        color = volume_data.get_color(hit_point)
                        color.g *= depth / 2.0
                    elif shading_mode == 'DIFFUSE':
                        # Diffuse shading logic
                        color = compute_diffuse_shading(hit_point, normal, volume_data)
                    elif shading_mode == 'NORMAL':
                        # Normal visualization
                        color = map_normal_to_color(normal)
                    elif shading_mode == 'INDEX':
                        color = volume_data.get_scalar_index(hit_point)
                    else:
                        color = volume_data.get_color(hit_point)
                else:
                    # Check if ray intersects light AABB
                    if intersects_light_aabb(ray_origin, ray_direction):
                        color = get_light_color()
                    else:
                        color = Vec3(25, 25, 25) # Dark color
                
                image.set_pixel(x, y, color)
                
    return image

def calculate_pixel_offset(x, y, vwidth, vheight):
    """
    Calculates the normalized position vector from pixel coordinates.
    Note: Exact formula depends on camera frustum setup.
    """
    # Placeholder for specific camera projection math
    # Typically involves mapping [0, width] to [-1, 1] or similar
    nx = (2.0 * x / vwidth) - 1.0
    ny = 1.0 - (2.0 * y / vheight)
    return Vec3(nx, ny, 0.0)

def map_normal_to_color(normal):
    """
    Maps a normal vector to a color for visualization.
    """
    r = 1.0 if normal.x != 0 else 0.0
    g = 1.0 if normal.y != 0 else 0.0
    b = 1.0 if normal.z != 0 else 0.0
    return Vec3(r, g, b)
```

## Subtopics

### [Terminal Rendering Pipeline](3434-terminal-rendering-pipeline.md)
The Terminal Rendering Pipeline renders a 3D scene to a text-based terminal buffer by iterating over pixels, mapping them to Normalized Device Coordinates (NDC), casting rays via a raymarcher, and applying ASCII/ANSI styling based on depth and lighting. It differs from standard terminal rendering by explicitly accounting for character aspect ratio when converting pixel indices to NDC and using ANSI escape codes to modulate brightness based on depth percentage, effectively acting as a low-resolution, text-based raymarcher.

### [Diffuse Octree Rendering](4989-diffuse-octree-rendering.md)
Diffuse Octree Rendering is an image-order raycasting technique that traverses an octree to locate the first leaf node containing data for each pixel, then computes surface lighting using a diffuse and Phong specular model with distance attenuation. It differs from sibling methods by relying on a coarse-to-fine octree traversal to skip empty space entirely, rather than marching through a dense voxel grid.

### [Ray Casting Loop with Supersampling](12786-ray-casting-loop-with-supersampling.md)
Renders an image by casting rays per pixel through a scene, with optional multi-sample anti-aliasing using uniform sub-pixel jittering. It extends the basic [Image-order Rendering Loop](2938-image-order-rendering-loop.md) by introducing a sampling loop that averages multiple jittered ray samples per pixel to reduce aliasing artifacts.

### Renderer configuration
A top-level rendering controller managing ray depth, sampling rate, and background color [S4, unofficial].
*   **Parameters:**
    *   `maxDepth`: Maximum recursion depth for ray tracing. Default: 100 [S4, unofficial].
    *   `samplesPerPixel`: Number of samples per pixel for anti-aliasing/noise reduction. Default: 500 [S4, unofficial].
*   **Layout:**
    *   Class `Renderer`.
    *   Fields: `int maxDepth = 100`, `int samplesPerPixel = 500`, `RGB background{0, 0, 0}` [S4, unofficial].
    *   Methods: `RGB rayColor(const Ray &ray, const Scene &scene, int depth) const`, `void render(const Scene &scene, const Camera &camera, Image &image) const` [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(P \times S)$, where $P$ is the number of pixels and $S$ is the number of samples per ray.
*   **Memory Complexity:** $O(P)$ for the output image buffer. The method does not require a compositing buffer, allowing full 32-bit precision [S1, unofficial].
*   **Performance:** The approach is flexible and supports adaptive sampling [S1, unofficial]. It is suitable for wide field of view, fly-throughs, virtual endoscopy, and integration into perspective scenes like games [S1, unofficial].
*   **Strengths:** Correct perspective projection, single-pass ray casting, full 32-bit compositing precision, and flexibility for advanced illumination techniques [S1, unofficial].
*   **Limitations:** Can be computationally expensive due to the per-pixel ray casting nature. Requires Shader Model 3.0+ for efficient conditional loops on GPU [S1, unofficial].
*   **When to use:** When correct perspective, flexible shading, or high-precision compositing is required, and hardware supports modern shader models.
*   **When not to use:** When hardware lacks support for conditional loops in shaders, or when object-order rasterization is sufficient for the scene complexity.

## Background
The image-order approach is a fundamental technique in volume rendering, often contrasted with object-order (rasterization) methods. It has been widely adopted in GPU-based volume ray casting for its flexibility and ability to handle advanced illumination techniques [S1, unofficial]. Key implementations and optimizations have been published by researchers such as Krüger and Westermann (2003), Röttger et al. (2003), Green (2004), Stegmaier et al. (2005), and others [S1, unofficial]. The method is also utilized in FPGA-based volume rendering systems for applications like endomicroscopic image visualization [S3].
