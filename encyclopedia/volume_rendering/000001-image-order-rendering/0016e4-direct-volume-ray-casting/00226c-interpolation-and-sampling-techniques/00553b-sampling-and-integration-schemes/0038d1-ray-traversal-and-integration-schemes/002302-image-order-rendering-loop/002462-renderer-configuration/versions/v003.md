# Renderer configuration

Also called: RenderingParams

## Overview
Renderer configuration is a top-level controller that manages global rendering parameters such as ray depth, sampling rates, and background color [S1, unofficial]. It serves as the static interface for adjusting image-order rendering behavior, including exposure, gamma correction, and post-processing flags like FXAA, diffuse shading, shadows, and Screen Space Ambient Occlusion (SSAO) [S2, unofficial].

## How it works
**Inputs and Outputs:** The configuration maintains global state without direct execution inputs [S2, unofficial]. It outputs parameter values accessed by the rendering pipeline to control ray depth, sampling rates, background color, exposure, gamma, and post-processing flags [S1, unofficial][S2, unofficial].

**Data Structures:** Two distinct layouts are observed in the sources:
1. Instance-based Layout [S1, unofficial]: Class `Renderer` contains fields `int maxDepth = 100`, `int samplesPerPixel = 500`, `RGB background{0, 0, 0}`. It provides methods `RGB rayColor(const Ray &ray, const Scene &scene, int depth) const` and `void render(const Scene &scene, const Camera &camera, Image &image) const` [S1, unofficial].
2. Static Class Layout [S2, unofficial]: Private static members include `gammaValue` (float), `exposureValue` (float), `fxaa` (bool), `diffuseShading` (bool), `shadows` (bool), `ssao` (bool), `ssaoBias` (float), `ssaoRadius` (float), `ssaoPower` (float) [S2, unofficial].

**Steps:** Not given in the sources [S1, unofficial][S2, unofficial].

**Formulas:** Not given in the sources [S1, unofficial][S2, unofficial].

**Parameters and Typical Values:**
* `maxDepth`: Maximum recursion depth for ray tracing. Default: 100 [S1, unofficial].
* `samplesPerPixel`: Number of samples per pixel for anti-aliasing/noise reduction. Default: 500 [S1, unofficial].
* `Exposure`: Controls brightness scaling [S2, unofficial].
* `Gamma`: Controls gamma correction [S2, unofficial].
* `FXAA`: Boolean flag for Fast Approximate Anti-Aliasing [S2, unofficial].
* `DiffuseShading`: Boolean flag for diffuse lighting [S2, unofficial].
* `Shadows`: Boolean flag for shadow rendering [S2, unofficial].
* `SSAO`: Boolean flag for Screen Space Ambient Occlusion [S2, unofficial].
* `SSAO Bias`: Float parameter for SSAO bias [S2, unofficial].
* `SSAO Radius`: Float parameter for SSAO radius [S2, unofficial].
* `SSAO Power`: Float parameter for SSAO power [S2, unofficial].

**Edge Cases and Pitfalls:** Not given in the sources [S1, unofficial][S2, unofficial].

## Operating characteristics
* **Time Complexity:** O(1) for configuration access [G]. The actual rendering time depends on the raymarcher and scene complexity [G].
* **Memory Complexity:** O(1) for static parameters [G].
* **Performance:** High sampling rates (`samplesPerPixel`) significantly increase render time but reduce noise [S1, unofficial]. Enabling features like SSAO, shadows, and diffuse shading adds computational overhead [S2, unofficial]. Hardware, resolution, and scene-specific measured performance are not given in the sources.

## Background
The concept of renderer configuration as a top-level controller managing ray depth, sampling rate, and background color originates from volumetric path tracing implementations [S1, unofficial]. The static class approach for managing global parameters like exposure, gamma, and post-processing flags is documented in style transfer function codebases [S2, unofficial].
