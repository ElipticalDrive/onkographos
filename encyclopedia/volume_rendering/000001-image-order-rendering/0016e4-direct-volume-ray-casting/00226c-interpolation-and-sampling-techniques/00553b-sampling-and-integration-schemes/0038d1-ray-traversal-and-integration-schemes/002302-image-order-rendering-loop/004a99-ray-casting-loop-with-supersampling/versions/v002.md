# Ray Casting Loop with Supersampling

Also called: Image-order Rendering Loop with Supersampling

## Overview
Renders an image by casting rays per pixel through a scene, with optional multi-sample anti-aliasing using uniform sub-pixel jittering [S1, unofficial]. It extends the basic [Image-order Rendering Loop](2938-image-order-rendering-loop.md) by introducing a sampling loop that averages multiple jittered ray samples per pixel to reduce aliasing artifacts [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Camera object (providing `getWidth()`, `getHeight()`, `drawPixel()`), boolean flag `SAMPLING`, integer `SN`, and a `trace(x, y)` function returning a `Color` [S1, unofficial].
- Output: Image drawn via `camera->drawPixel()` [S1, unofficial].

**Data Structures:**
- `Color`: A vector-like structure supporting initialization to zero, addition, scalar division, and clamping [S1, unofficial].
- `Vector3D`: A 3D vector structure supporting arithmetic operations (addition, subtraction, multiplication, division) [S1, unofficial].
- `Ray`: Contains origin, direction, and hit information, handled internally by `trace` [S1, unofficial].

**Parameters:**
- `SN`: Number of samples per axis for supersampling. Typical value: 5 [S1, unofficial].
- `SAMPLING`: Boolean flag enabling/disabling supersampling. Typical value: false [S1, unofficial].

**Steps:**
1. Initialize pixel index `i = 0`.
2. Loop while `renderLoop()` returns false.
3. Inside `renderLoop()`, parallelize over the vertical pixel coordinate `j` from 0 to `camera->getHeight() - 1`.
4. If `SAMPLING` is false: call `trace(i, j)`, clamp the color, and draw the pixel at `(i, j)`.
5. If `SAMPLING` is true: initialize `color` to zero, loop `p` from 0 to `SN - 1`, loop `q` from 0 to `SN - 1`, generate random `e` via `randGen(1)`, compute sub-pixel coordinates `x = i + (p + e) / SN` and `y = j + (q + e) / SN`, call `trace(x, y)`, clamp the sample color, and accumulate it into `color`. After the inner loops, draw the pixel at `(i, j)` with `color / (SN * SN)`.
6. Increment `i`. If `i == camera->getWidth()`, reset `i = 0` and return true to terminate the loop.

**Pseudocode:**
```python
import random

class Color:
    def __init__(self, r=0.0, g=0.0, b=0.0):
        self.r, self.g, self.b = r, g, b
    def __iadd__(self, other):
        self.r += other.r; self.g += other.g; self.b += other.b
        return self
    def __truediv__(self, scalar):
        return Color(self.r/scalar, self.g/scalar, self.b/scalar)
    def clamp(self):
        self.r = max(0.0, min(1.0, self.r))
        self.g = max(0.0, min(1.0, self.g))
        self.b = max(0.0, min(1.0, self.b))
        return self

def render_loop(camera, trace, sampling=False, sn=5):
    width = camera.getWidth()
    height = camera.getHeight()
    i = 0
    while True:
        # Parallelize over j as per source [S1, unofficial]
        for j in range(height):
            if not sampling:
                color = trace(i, j)
                color.clamp()
                camera.drawPixel(i, j, color)
            else:
                color = Color(0.0, 0.0, 0.0)
                for p in range(sn):
                    for q in range(sn):
                        e = random.random() # Maps to randGen(1) [S1, unofficial]
                        x = i + (p + e) / sn
                        y = j + (q + e) / sn
                        c = trace(x, y)
                        c.clamp()
                        color += c
                camera.drawPixel(i, j, color / (sn * sn))
        i += 1
        if i == width:
            i = 0
            return True # renderLoop() returns true to terminate
```

**Edge Cases and Pitfalls:**
- Precision: The sub-pixel coordinates `x` and `y` are floating-point values; `trace` must handle sub-pixel sampling correctly.
- Boundaries: The loop assumes `i` and `j` remain within valid camera dimensions; the reset logic `if i == width` ensures `i` wraps around.
- Randomness: `randGen(1)` is assumed to return a value in `[0, 1)` [G].
