# MPIRE Raycasting on Tera MTA

Also called: MPIRE, Tera MTA Raycasting

## Overview
MPIRE is a massively parallel direct volume raycasting implementation designed for the Tera MTA architecture, leveraging a flat global memory model and hardware multithreading to hide memory latency [S1, unofficial]. It distinguishes itself from distributed-memory alternatives like the Cray T3E by eliminating the need for a pixel composition step and avoiding the overhead of message passing and local memory partitioning [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** Image raster dimensions (`xsize`, `ysize`), a shaded volume data structure (`v`), and a ray structure (`R`) containing camera parameters.
*   **Output:** An image buffer (`image`) containing the final color and opacity for each pixel.

**Data Structures**
*   `image`: A linear array indexed by `index`. The size is `xsize * ysize`.
*   `R`: A structure of type `ray` passed to the sampling function.
*   `v`: The volume data structure containing the scalar field and transfer functions.

**Numbered Steps**
1.  Initialize a double loop iterating over the image raster dimensions.
2.  Calculate the linear index for the current pixel in the image buffer using the formula:
    $$index = i + j \times xsize$$
3.  Invoke the `SampleRay` function with the ray `R` and volume `v` to compute the final color and opacity.
4.  Store the result in the image buffer at the calculated index:
    $$image[index] = SampleRay(R, v)$$
5.  Attach the pragma `#pragma tera assert parallel` to both the outer and inner loops to explicitly instruct the Tera compiler to multithread the execution.

**Pseudocode**
```python
# Initialize image buffer of size xsize * ysize
image = [0.0] * (xsize * ysize)

# Outer loop over x-dimension
#pragma tera assert parallel
for i in range(xsize):
    # Inner loop over y-dimension
    # Note: The source code places the pragma on the inner loop as well.
    # In a standard Python context, this pragma is ignored, but it represents
    # the instruction for the Tera compiler.
    # #pragma tera assert parallel
    for j in range(ysize):
        # Calculate linear index
        index = i + j * xsize
        
        # Create ray R based on camera parameters and pixel coordinates (i, j)
        # This step is implicit in the source's abstraction of SampleRay
        R = create_ray(i, j, camera_params)
        
        # Sample the volume and composite color/opacity
        # SampleRay steps through the volume v compositing color and opacity
        color, opacity = SampleRay(R, v)
        
        # Store result
        image[index] = color
```

**Parameters**
*   **Image Resolution:** Typically 400 x 400 pixels, resulting in 160,000 rays (threads) [S1, unofficial].
*   **Hardware Thread Capacity:** 128 threads per processor [S1, unofficial].
*   **Memory Size:** 4 gigabytes of globally addressable, physically distributed memory with no local memory [S1, unofficial].
*   **Processor-Memory Bandwidth:** 8 bytes per cycle [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Compiler Parallelization Uncertainty:** The Tera compiler may refuse to automatically parallelize the loop if it cannot verify the absence of side effects in called functions like `SampleRay`. Explicit pragmas are required to force multithreading [S1, unofficial].
*   **Thread Granularity:** Since there are 128 threads per processor, it is only efficient to use more than one processor if there are more than 128 calls to `SampleRay` (i.e., more than 128 pixels) [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity**
*   **Time Complexity:** The algorithm scales linearly with the number of pixels ($N = xsize \times ysize$) and the number of processors ($P$), assuming sufficient parallelism.
*   **Memory Complexity:** $O(N)$ for the image buffer and $O(V)$ for the volume data, where $V$ is the volume size. The flat memory model requires all data to be globally addressable.

**Measured Performance**
*   **MTA Performance:** On a $256^3$ sample data volume and 400x400 pixel image:
    *   1 processor: 3.67s
    *   2 processors: 1.89s (97% efficiency)
    *   3 processors: 1.32s (93% efficiency)
    *   4 processors: 0.97s (95% efficiency) [S1, unofficial]
*   **T3E Performance (Comparison):** On the same problem:
    *   1 processor: 16.31s
    *   2 processors: 8.56s (95% efficiency)
    *   3 processors: 6.82s (80% efficiency)
    *   4 processors: 5.45s (75% efficiency)
    *   8 processors: 3.19s (64% efficiency)
    *   16 processors: 2.08s (49% efficiency) [S1, unofficial]

**Scaling and Trade-offs**
*   **Scalability:** The MTA scales well with problem size due to fine-grained parallelism (one thread per ray) [S1, unofficial].
*   **Strengths:** The MTA outperforms the T3E by more than 4:1 on single processors due to higher memory bandwidth (8 bytes/cycle vs. 2 bytes/cycle on cache miss) and hardware multithreading that hides latency [S1, unofficial]. It avoids the pixel composition step required by distributed-memory machines [S1, unofficial].
*   **Limitations:** The MTA configuration described has only 4 gigabytes of main memory, compared to the T3E's aggregate total of more than 36 gigabytes. This makes the T3E the machine of choice for truly large renders that exceed the MTA's memory capacity [S1, unofficial].
*   **When to use:** Small to medium-sized problems where memory bandwidth and low-latency parallelism are critical, and the volume fits within 4GB.
*   **When not to use:** Very large renders that exceed the MTA's 4GB memory limit, or problems where the overhead of message passing on the T3E is amortized by a sufficiently large problem size.

## Background
MPIRE was developed for the Tera MTA architecture, a massively parallel machine designed to handle memory-intensive problems like raycasting [S1, unofficial]. The implementation highlights the advantages of a flat global memory model over distributed-memory architectures like the Cray T3E, which require complex decomposition and message passing [S1, unofficial]. The work was presented in the context of comparing data-intensive volume visualization on the Tera MTA and Cray T3E [S1, unofficial].
