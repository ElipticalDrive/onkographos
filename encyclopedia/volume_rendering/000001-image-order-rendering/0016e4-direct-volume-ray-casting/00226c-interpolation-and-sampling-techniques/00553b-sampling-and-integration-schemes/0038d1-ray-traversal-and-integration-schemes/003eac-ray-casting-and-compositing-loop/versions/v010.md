# Ray Casting and Compositing Loop

Also called: Basic Ray Casting, Ray Casting Volume Rendering, Single pass GPU Ray casting, Standard Ray Casting Loop

## Overview
Ray Casting and Compositing Loop is the fundamental image-order rendering technique for direct volume rendering, where scalar volume data is sampled along rays and composited directly to the screen without intermediate surface extraction [S1, unofficial]. It differs from iso-surface methods by mapping scalar values directly to color and opacity via a transfer function, and from advanced traversal schemes by typically using a fixed-step or simple adaptive integration loop [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D texture volume (`u_Volume3DSampler`), camera position (`u_cameraPosition`), step size (`u_stepSize`), and interpolated 3D texture coordinates for the pixel (`oTexCoords`) [S1, unofficial].
*   **Output:** A `vec4` fragment color (`FragColor`) containing the accumulated RGB color and opacity [S1, unofficial].

**Data Structures:**
*   `oTexCoords`: `vec3`, smooth interpolated texture coordinates representing the ray origin in texture space [S1, unofficial].
*   `u_Volume3DSampler`: `sampler3D`, the volume data texture [S1, unofficial].
*   `u_cameraPosition`: `vec3`, the camera's position in world/texture space [S1, unofficial].
*   `u_stepSize`: `vec3`, the uniform step vector for ray marching [S1, unofficial].
*   `FragColor`: `vec4`, the output buffer storing accumulated color (RGB) and opacity (A) [S1, unofficial].

**Parameters:**
*   `MAX_SAMPLES`: Integer constant defining the maximum number of ray march steps. Value: 300 [S1, unofficial].
*   Early Ray Termination (ERT) Threshold: Float value for opacity. Value: 0.99 [S2, unofficial].

**Algorithm Steps:**
1.  **Ray Initialization:** Calculate the ray direction by subtracting 0.5 from `oTexCoords`, subtracting `u_cameraPosition`, and normalizing the result [S1, unofficial]. Initialize the current position `dataPosition` to `oTexCoords` [S1, unofficial].
2.  **Loop:** Iterate `i` from 0 to `MAX_SAMPLES` [S1, unofficial].
3.  **Boundary Check:** Before sampling, check if `dataPosition` has exited the volume boundary. A common implementation checks if the dot product of the signs of the distance to min/max bounds is less than 3.0: `if dot(sign(dataPosition - texMin), sign(texMax - dataPosition)) < 3.0, break` [S1, unofficial].
4.  **Sampling:** Sample the volume at `dataPosition` to get the scalar value `fSample` [S1, unofficial].
5.  **Classification:** Map `fSample` to color and opacity. In the basic single-pass GPU implementation described, the scalar value is often used directly as the color contribution if no explicit transfer function is applied in the shader, or mapped via a texture lookup [S1, unofficial]. The opacity contribution is calculated as `prev_alpha = fSample * (1 - FragColor.a)` [S1, unofficial]. *Note: Source [S1, unofficial] code snippet shows `prev_alpha = fSample - (fSample * FragColor.a)`, which simplifies to `fSample * (1 - FragColor.a)`.*
6.  **Compositing:** Update the accumulated color and opacity using front-to-back compositing [S1, unofficial]:
    *   `FragColor.rgb = prev_alpha * vec3(fSample) + FragColor.rgb` [S1, unofficial].
    *   `FragColor.a += prev_alpha` [S1, unofficial].
7.  **Termination Check:** If `FragColor.a > 0.99`, break the loop [S1, unofficial].
8.  **Advancement:** Advance `dataPosition` by `directionStep` (calculated as `geomatryDirection * u_stepSize`) [S1, unofficial].

**Pseudocode:**
```python
def ray_casting_loop(oTexCoords, u_cameraPosition, u_Volume3DSampler, u_stepSize, texMin, texMax):
    # 1. Initialize Ray
    # Calculate geometry direction
    raw_dir = oTexCoords - 0.5
    geometry_direction = normalize(raw_dir - u_cameraPosition)
    
    # Calculate step vector
    direction_step = geometry_direction * u_stepSize
    
    # Initialize position
    data_position = oTexCoords
    
    # Initialize output
    frag_color = vec4(0.0, 0.0, 0.0, 0.0)
    
    # 2. Loop
    for i in range(300): # MAX_SAMPLES
        # 3. Boundary Check
        # Check if inside volume bounds
        dist_min = data_position - texMin
        dist_max = texMax - data_position
        
        # If any component is negative, we are outside
        # Using the dot product of signs method from source
        sign_min = sign(dist_min)
        sign_max = sign(dist_max)
        
        if dot(sign_min, sign_max) < 3.0:
            break
            
        # 4. Sampling
        f_sample = texture(u_Volume3DSampler, data_position).r # Assuming scalar volume
        
        # 5. Classification & Compositing
        # Calculate contribution based on current accumulated opacity
        prev_alpha = f_sample * (1.0 - frag_color.a)
        
        # Update RGB
        frag_color.rgb = prev_alpha * vec3(f_sample) + frag_color.rgb
        
        # Update Alpha
        frag_color.a += prev_alpha
        
        # 6. Termination Check
        if frag_color.a > 0.99:
            break
            
        # 7. Advancement
        data_position += direction_step
        
    return frag_color
```

**Edge Cases and Pitfalls:**
*   **Boundary Intersection:** The method relies on simple bounding box checks. For non-convex volumes, this may include empty space or exclude valid data if the bounding box is not tight [S2, unofficial].
*   **Precision:** Floating-point precision in texture coordinate calculations can lead to sampling artifacts if not handled carefully [G].
*   **Step Size:** A fixed `u_stepSize` may lead to aliasing if too large or excessive computation if too small [S1, unofficial].

## Subtopics

### [Wavelet-Assisted Volume Ray Casting](10893-wavelet-assisted-volume-ray-casting.md)
Uses wavelet coefficients to determine adaptive sampling distances, solving the cost of standard ray casting by skipping samples via an index volume.

### [Accumulative Rendering](14504-accumulative-rendering.md)
Combines previous rendering output with new slices for incremental data, solving latency in live imaging.

### [Template-based Ray-Casting](14511-template-based-ray-casting.md)
Hardware-accelerated technique processing voxels in planar slices, eliminating view-dependent artifacts.

### [Resampling Point Shading](14923-resampling-point-shading.md)
Improves shading accuracy by applying lighting at resampling points, avoiding Mach band artifacts.

### Multi-Cast / Super-Sampling Ray Casting
Instead of sampling one ray per pixel, this variant samples 4 rays per pixel to improve image quality by reducing aliasing [S3, unofficial]. It produces better image quality but takes four times longer to render [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray and the number of pixels. $O(N \cdot P)$ where $N$ is samples per ray and $P$ is pixel count [S1, unofficial].
*   **Memory Complexity:** Low, primarily storing the volume texture and frame buffer [S1, unofficial].
*   **Performance:** The basic loop is efficient on GPUs due to its simplicity and parallelizability [S1, unofficial]. However, fixed step sizes can lead to over-sampling in transparent regions or under-sampling in dense regions [S1, unofficial].
*   **Strengths:** Simple to implement, hardware-friendly, supports direct scalar-to-color mapping [S1, unofficial].
*   **Limitations:** Fixed step sizes may not adapt to data density; boundary checks are simplistic [S1, S2, unofficial].
*   **When to Use:** Real-time visualization of scalar volumes where performance is critical and data density is relatively uniform [S1, unofficial].
*   **When Not to Use:** When high accuracy in complex, non-convex boundaries is required, or when significant performance optimization via adaptive sampling is needed [S2, unofficial].

## Background
The method originates from early direct volume rendering techniques, popularized by GPU implementations in the mid-2000s [S1, unofficial]. It is a foundational technique in computer graphics, often taught as the basic approach to volume rendering before introducing more complex traversal or shading methods [S3, unofficial].
