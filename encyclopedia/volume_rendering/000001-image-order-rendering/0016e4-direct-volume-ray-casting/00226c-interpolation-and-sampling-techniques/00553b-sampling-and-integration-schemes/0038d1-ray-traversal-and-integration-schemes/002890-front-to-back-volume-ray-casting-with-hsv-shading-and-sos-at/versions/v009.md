# Front-to-Back Volume Ray Casting with HSV Shading and SOS/Attenuation/Reflection Filtering

Also called: Front-to-Back Volume Ray Casting

## Overview
This method is a direct volume rendering technique that casts rays from the camera through each pixel into a 3D volume, samples voxel values along the ray, and composites them front-to-back to produce the final pixel color [S1, unofficial]. It distinguishes itself by filtering samples based on three specific physical properties—Scalar Output Scalar (SOS), Attenuation, and Reflection—and mapping the valid data to color via the HSV color space before compositing [S1, unofficial]. It builds on [Ray Traversal and Integration Schemes](8341-ray-traversal-and-integration-schemes.md) using the accumulation reduction scheme.

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `frontColor`: Entry point coordinates and background color, passed as a `vec4` varying from the vertex shader. The RGB components represent the 3D entry position in normalized device coordinates (NDC) or texture space [S1, unofficial].
    *   `uBackCoord`: A 2D texture (`sampler2D`) storing the exit point coordinates for each pixel [S1, unofficial].
    *   `uSliceMaps`: An array of 2D textures (`sampler2D[]`) representing the 3D volume data sliced along the Z-axis [S1, unofficial].
    *   `uStepsI`: Integer constant defining the number of steps per ray (typically 144) [S1, unofficial].
    *   `uOpacityVal`: Float uniform controlling the global opacity scaling factor [S1, unofficial].
    *   `uSlicesOverX`, `uSlicesOverY`: Float uniforms defining the grid layout of the volume slices in the texture atlas [S1, unofficial].
    *   `uNumberOfSlices`: Float uniform defining the total number of Z-slices in the volume [S1, unofficial].
    *   `minSos`, `maxSos`, `minAtten`, `maxAtten`, `minRefl`, `maxRefl`: Float uniforms defining the valid ranges for the three volume components [S1, unofficial].
*   **Outputs:**
    *   `gl_FragColor`: The final composited color and alpha for the pixel [S1, unofficial].

**Data Structures:**
*   **Volume Representation:** The 3D volume is stored as a stack of 2D textures (`uSliceMaps`). Each texture contains a subset of Z-slices arranged in a 2D grid of size `uSlicesOverX` by `uSlicesOverY` [S1, unofficial].
*   **Ray State:**
    *   `vpos`: `vec3` current position along the ray [S1, unofficial].
    *   `accum`: `vec4` accumulated color and alpha [S1, unofficial].
    *   `sample`: `vec4` temporary storage for the current sample's color and alpha [S1, unofficial].
    *   `colorValue`: `vec4` intermediate storage for the mapped RGB and alpha values before compositing [S1, unofficial].

**Numbered Steps:**
1.  **Coordinate Transformation:** Calculate normalized texture coordinates `texC` from the fragment position `pos` (which is `MVP * vertex_position`) [S1, unofficial]:
    $$ \text{texC} = \frac{(\text{pos}.xy / \text{pos}.w) + 1.0}{2.0} $$
2.  **Exit Point Retrieval:** Sample the exit point from the back coordinate texture:
    $$ \text{backColor} = \text{texture2D}(uBackCoord, \text{texC}) $$
3.  **Ray Direction:** Compute the ray direction vector by subtracting the entry point from the exit point:
    $$ \text{dir} = \text{backColor}.rgb - \text{frontColor}.rgb $$
4.  **Initialization:**
    *   Set current position `vpos` to the entry point: `vpos = frontColor` [S1, unofficial].
    *   Calculate the step vector: `Step = dir / uStepsI` [S1, unofficial].
    *   Initialize accumulation buffer: `accum = vec4(0, 0, 0, 0)` [S1, unofficial].
    *   Initialize sample buffer: `sample = vec4(0, 0, 0, 0)` [S1, unofficial].
5.  **Ray Loop:** Iterate `i` from 0 to `uStepsI - 1`:
    a.  **Volume Sampling:** Retrieve the volume value at `vpos.xyz` using `getVolumeValue(vpos.xyz)`. This function maps the 3D coordinate to the appropriate 2D slice texture and performs bilinear interpolation within the slice [S1, unofficial]. Let the result be `gray_val` (a `vec3` representing SOS, Attenuation, and Reflection) [S1, unofficial].
    b.  **Filtering:** Check if `gray_val` components fall outside their respective thresholds:
        *   If `gray_val.z < 0.05` OR `gray_val.x < minSos` OR `gray_val.x > maxSos` OR `gray_val.y < minAtten` OR `gray_val.y > maxAtten` OR `gray_val.z < minRefl` OR `gray_val.z > maxRefl`:
            *   Set `colorValue = vec4(0.0)` and skip to step 5f [S1, unofficial].
    c.  **HSV Mapping:** If the sample passes filtering, compute `colorValue`:
        *   $H = \text{gray\_val}.x$ (SOS)
        *   $S = 1.0 - \frac{\text{gray\_val}.y}{0.6}$ (Attenuation mapped to Saturation) [S1, unofficial]
        *   $V = \text{gray\_val}.z$ (Reflection)
        *   $A_{raw} = 0.1$ (Base Alpha)
        *   `colorValue = vec4(H, S, V, A_raw)` [S1, unofficial]
    d.  **Alpha Adjustment:** Compute the sample alpha `sample.a` based on the raw alpha, opacity factor, and step count:
        $$ \text{sample}.a = \text{colorValue}.a \times \text{uOpacityVal} \times \left(\frac{1.0}{\text{uStepsI}}\right) $$
        *Note: Some implementations use a power function for alpha adjustment: `sample.a = 1.0 - pow(1.0 - colorSample.a, StepSize * 200.0)` [S1, unofficial]. The linear version is used in the primary loop description.*
    e.  **Color Conversion:** Convert the HSV color to RGB:
        $$ \text{sample}.rgb = (1.0 - \text{accum}.a) \times \text{hsv2rgb}(\text{colorValue}.rgb) \times \text{sample}.a $$
    f.  **Accumulation:** Add the sample to the accumulator:
        $$ \text{accum}.rgb += \text{sample}.rgb $$
        $$ \text{accum}.a += \text{sample}.a \times (1.0 - \text{accum}.a) $$
        *Note: The source code snippet shows `accum += sample` for RGB, but the standard front-to-back blending for alpha is `accum.a += (1.0 - accum.a) * sample.a` [S1, unofficial]. The RGB accumulation in the source `colorAcum.rgb += (1.0 - colorAcum.a) * colorSample.rgb * colorSample.a` implies the standard blending equation.*
    g.  **Termination Check:** If `accum.a >= 1.0`, break the loop [S1, unofficial].
    h.  **Position Advance:** Update position: `vpos.xyz += Step` [S1, unofficial].
    i.  **Boundary Check:** If `vpos.x`, `vpos.y`, or `vpos.z` is outside the range $[0.0, 1.0]$, break the loop [S1, unofficial].
6.  **Output:** Write `accum` to `gl_FragColor` [S1, unofficial].

**HSV to RGB Conversion:**
The `hsv2rgb` function converts HSV values to RGB. Standard implementation:
```python
def hsv2rgb(h, s, v):
    # h, s, v in [0, 1]
    c = v * s
    x = c * (1.0 - abs((h / 60.0) % 2 - 1.0))
    m = v - c
    if h < 60:
        r, g, b = c, x, 0
    elif h < 120:
        r, g, b = x, c, 0
    elif h < 180:
        r, g, b = 0, c, x
    elif h < 240:
        r, g, b = 0, x, c
    elif h < 300:
        r, g, b = x, 0, c
    else:
        r, g, b = c, 0, x
    return (r + m, g + m, b + m)
```

**Parameters:**
*   `uStepsI`: 144 [S1, unofficial].
*   `uOpacityVal`: 40.0 (typical value from source) [S1, unofficial].
*   `minSos`, `maxSos`, `minAtten`, `maxAtten`, `minRefl`, `maxRefl`: Configurable thresholds [S1, unofficial].
*   `StepSize`: Adjustable via UI, range 0 to 1024.0 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Opaque Rays:** The loop breaks when `accum.a >= 1.0` to prevent unnecessary computation [S1, unofficial].
*   **Out-of-Bounds Access:** The loop breaks if `vpos` exceeds $[0.0, 1.0]$ to prevent memory errors [S1, unofficial].
*   **Alpha Clamping:** Accumulated alpha can exceed 1.0 due to floating-point precision; it should be clamped to 1.0 [S1, unofficial].
*   **Ray Length:** Termination must account for the exact ray length to avoid sampling outside the volume [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of pixels and $P$ is the number of steps per ray (fixed at 144 in the reference implementation) [S1, unofficial].
*   **Memory Complexity:** $O(V)$ for the volume data, where $V$ is the number of voxels, stored in 2D texture atlases [S1, unofficial].
*   **Performance:** The fixed step count provides predictable performance but lacks the adaptivity of gradient-based methods [S1, unofficial].
*   **Strengths:** Simple implementation, efficient early termination, clear mapping of physical properties to visual attributes via HSV [S1, unofficial].
*   **Limitations:** Fixed step size may lead to aliasing or slow convergence in sparse regions; HSV mapping is a heuristic and may not represent physical light transport accurately [S1, unofficial].
*   **When to Use:** Real-time visualization of volumetric data where specific physical properties (SOS, Attenuation, Reflection) need to be highlighted [S1, unofficial].
*   **When Not to Use:** High-fidelity scientific visualization requiring accurate light transport or adaptive sampling for complex density variations [S1, unofficial].

## Background
This method is derived from a specific implementation of front-to-back volume ray casting using OpenGL shaders [S1, unofficial]. It utilizes a texture-based volume representation and HSV color mapping to visualize three distinct volume components [S1, unofficial].
