# Ray Traversal and Integration Schemes

Also called: Ray Casting and Compositing, Volume Ray Casting, DVR Integration

## Overview
Ray Traversal and Integration Schemes define the aggregation logic applied to the optical properties sampled along a ray to produce the final pixel value [S1, unofficial]. They solve the problem of reducing a 1D sequence of volumetric samples to a single pixel color and auxiliary data . They are distinguished from sibling schemes by their focus on the compositing and reduction rules rather than the sampling geometry or image-order loop structure [G].

## Shared principles
The family operates on the discretized ray samples $(C_i, \alpha_i)$ generated by the parent's sampling stage [G]. The core mechanism is a reduction function $R$ that maps the sample sequence to a pixel output . The reduction types are:
1.  **Accumulation**: Front-to-back compositing using the standard alpha blending equation .
2.  **Extremum**: Selecting the maximum or minimum scalar value along the ray .
3.  **Averaging**: Computing the arithmetic mean of scalar values .
4.  **First Hit**: Identifying the first sample that meets a classification threshold [S1, unofficial].
5.  **Depth**: Recording the ray parameter $t$ where the primary event occurs [S1, unofficial].

All schemes operate on the discretized ray samples generated by the parent's sampling stage [G]. The reduction logic can be implemented as follows:

```python
def reduce_samples(samples, scheme):
    accumulated_color = (0.0, 0.0, 0.0)
    accumulated_alpha = 0.0
    first_intensity = None
    first_depth = None
    max_intensity = None
    sum_intensity = 0.0
    count = 0
    for i, (c, a, t) in enumerate(samples):
        if scheme == "accumulate":
            accumulated_color = c * a * (1.0 - accumulated_alpha) + accumulated_color * (1.0 - a)
            accumulated_alpha = a + accumulated_alpha * (1.0 - a)
        elif scheme == "max":
            if max_intensity is None or c > max_intensity:
                max_intensity = c
        elif scheme == "average":
            sum_intensity += c
            count += 1
        elif scheme == "first":
            if first_intensity is None:
                first_intensity = c
                first_depth = t
        if scheme == "accumulate" and accumulated_alpha >= 1.0:
            break
    if scheme == "max": return max_intensity
    if scheme == "average": return sum_intensity / count if count > 0 else 0.0
    if scheme == "first": return first_intensity, first_depth
    return accumulated_color, accumulated_alpha
```

## Subtopics

### [Ray Marching and Discretization](2788-ray-marching-and-discretization.md)
Ray Marching and Discretization is the fundamental iterative algorithm for solving the volume rendering equation in image-order rendering by sampling volumetric data at discrete intervals along camera rays. It solves the problem of integrating light transport through participating media by approximating the continuous integral with a finite sum of sampled contributions, enabling real-time performance on GPUs. It differs from [Ray Traversal Schemes](6890-ray-traversal-schemes.md) by using fixed or adaptive step sizes guided by distance estimators rather than voxel connectivity traversal, and from [Monte Carlo Path Tracing for Volume Rendering](4980-monte-carlo-path-tracing-for-volume-rendering.md) by using deterministic quadrature instead of stochastic sampling.

### [Image-order Rendering Loop](2938-image-order-rendering-loop.md)
The Image-order Rendering Loop is the fundamental computational engine of direct volume ray casting, operating on the principle of iterating over each pixel in the image plane to generate a corresponding ray, which is then marched through the volume data to compute the final color. It solves the problem of mapping 3D volumetric data to a 2D image by performing per-pixel ray generation, discretization, sampling, classification, and compositing in a single pass. Unlike object-order methods (such as rasterization), this approach is described as more "CPU-like" in its logic but offers correct perspective projection, adaptive sampling capabilities, and full 32-bit compositing precision without the need for multiple passes or early-z testing. It builds on the [Image-order rendering](16-image-order-rendering.md) paradigm and serves as the core loop for [Ray Traversal and Integration Schemes](8341-ray-traversal-and-integration-schemes.md).

### [Front-to-Back Volume Ray Casting with HSV Shading and SOS/Attenuation/Reflection Filtering](4324-front-to-back-volume-ray-casting-with-hsv-shading-and-sos-at.md)
This method performs direct volume rendering by casting rays from the camera through each pixel into a 3D volume, sampling voxel values along the ray path, and compositing them front-to-back to produce the final pixel color. It distinguishes itself from standard ray casting by utilizing a multi-component volume value (Scalar Output Scalar, Attenuation, Reflection) to drive filtering and shading, converting these values to RGB via HSV color space, and applying specific attenuation-based opacity scaling. Unlike adaptive step methods, it typically employs a fixed number of steps with early termination based on opacity saturation or volume boundaries.

### [LOS-integration for visualization](4807-los-integration-for-visualization.md)
LOS-integration for visualization computes physical scalar quantities (electron column density, integrated emissivity, or emission-weighted temperature) along camera rays by integrating interpolated field values. It differs from standard direct volume rendering by outputting integrated physical metrics rather than a composited RGB image, reusing the ray sampling and field query infrastructure of the forward pass.

### [Monte Carlo Path Tracing for Volume Rendering](4980-monte-carlo-path-tracing-for-volume-rendering.md)
Monte Carlo Path Tracing for Volume Rendering is a unified, brute-force, progressive stochastic rendering framework that computes photo-realistic direct volume rendering (DVR) without relying on pre-computed quantities or auxiliary data structures. It solves the problem of integrating complex lighting, shadows, and hybrid surface/volumetric scattering in participating media by treating the volume as a continuous medium where light transport is estimated via random sampling. Unlike slice-based or layer-based methods that treat isosurfaces distinctly, this approach renders the volume uniformly, supporting directional, point, and environment lights while maintaining a memory footprint insensitive to lighting or material complexity.

### [Ray Traversal Schemes](6890-ray-traversal-schemes.md)
Ray traversal schemes define the aggregation logic applied to the optical properties sampled along a ray to produce the final pixel value. They solve the problem of reducing a 1D sequence of volumetric samples to a single pixel color and auxiliary data. They are distinguished from sibling schemes by their focus on the compositing and reduction rules rather than the sampling geometry or image-order loop structure [G].

### [Ray Casting and Compositing Loop](9826-ray-casting-and-compositing-loop.md)
Ray Casting and Compositing Loop is the fundamental image-order rendering technique for direct volume rendering, where scalar volume data is sampled along rays and composited directly to the screen without intermediate surface extraction. It differs from iso-surface methods by mapping scalar values directly to color and opacity via a transfer function, and from advanced traversal schemes by typically using a fixed-step or simple adaptive integration loop.

### [Ray Casting with Ray Subdividing](11392-ray-casting-with-ray-subdividing.md)
Ray Casting with Ray Subdividing is a technique for direct volume ray casting that addresses the issue of insufficient sampling density in perspective projections. Unlike fixed-step methods, it dynamically adjusts the sampling rate along the ray to maintain consistent spatial resolution relative to the screen pixels, preventing aliasing and artifacts caused by ray divergence. It sets itself apart from [Ray Marching and Discretization](2788-ray-marching-and-discretization.md) by varying the step size $\Delta t$ adaptively rather than keeping it constant.

### [Cone Casting with Inscribed Sphere Sampling](11501-cone-casting-with-inscribed-sphere-sampling.md)
Cone casting with inscribed sphere sampling is a volume rendering technique that formulates a pixel as a disc on the image plane and emits a cone from the camera's projection center to sample the volume, thereby avoiding the aliasing artifacts inherent in distance-agnostic ray casting. Unlike MipNeRF, which samples the cone with anisotropic multivariate Gaussians, this method uses spheres inscribed within the cone to provide isotropic pre-filtering, making it particularly effective when paired with Tri-Mip encoding.

#### Adaptive Segment Length

### definition
- [S1, unofficial] A strategy to optimize speed while reducing artifacts by varying segment length based on contribution to ray color.

### step
- [S1, unofficial] Use smaller segments when the contribution to the ray color is large.
- [S1, unofficial] Use longer segments when the contribution to the ray color is low.

## Background
Origin: The foundational principles of ray casting and front-to-back compositing were established in the early 1980s by Williams et al. and Levoy, forming the basis of Direct Volume Rendering (DVR) [S1, unofficial]. The specific adaptive segment length strategy cited in [S1, unofficial] references Quatrin Campagnolo et al. [9] for optimizing speed by varying segment length based on color contribution.
