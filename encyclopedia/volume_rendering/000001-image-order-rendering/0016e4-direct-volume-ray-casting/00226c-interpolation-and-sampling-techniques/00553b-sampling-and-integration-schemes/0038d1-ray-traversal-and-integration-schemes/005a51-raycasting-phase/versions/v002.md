# Raycasting Phase

Also called: Data sampling, Two-Pass Raycasting with Back-Face Depth Buffering

## Overview
The Raycasting Phase samples volumetric data along camera rays and applies shading to compute optical properties [S1]. It is implemented using a two-pass rasterization strategy to determine ray entry and exit points via back-face depth buffering [S2]. In parallel implementations, its performance is highly sensitive to the interaction between decomposition geometry and camera direction [S1].

## How it works
**Inputs:**
*   Volumetric data grid $V$ [S1].
*   Camera parameters (origin $\mathbf{o}$, direction $\mathbf{d}$, field of view) [S1].
*   Decomposition geometry (block structure for parallel processing) [S1].
*   Predefined step length parameter $d$ [S2].

**Outputs:**
*   Final pixel color $C_{\text{pixel}}$ [S1].
*   Intermediate fragment buffers (back-face and front-face coordinates) [S2].

**Data Structures:**
1.  **Auxiliary Buffers:** Two texture buffers bound to distinct texture units; one stores back-face depth/coordinates, the other stores front-face coordinates [S2].
2.  **Fragment Buffer:** Temporary storage for image fragments; size constraints may require scaling down data volume if the buffer overflows (e.g., at image size $23040^3$) [S1].

**Algorithm Steps:**

1.  **Pass 1: Back-Face Depth Buffering**
    *   Render the volume bounding box or decomposition blocks [S2].
    *   Bind auxiliary buffers for multiple render targets using `GL_ARB_draw_buffers` [S2].
    *   For each fragment generated by a back-facing polygon, store its texture coordinates in the back-face buffer [S2].

2.  **Pass 2: Ray Initialization and Integration Setup**
    *   Bind the two auxiliary buffers to distinct texture units [S2].
    *   Project a viewport-filling quadrilateral [S2].
    *   For each pixel:
        *   Fetch back-face texture coordinates from the first buffer [S2].
        *   If invalid (no back-face hit), discard the fragment [S2].
        *   Otherwise, retrieve the corresponding front-face texture coordinates from the second buffer [S2].
        *   Compute the step vector $\Delta \mathbf{p}$ along the ray based on the predefined step length $d$ and the distance between front and back faces [S2].
        *   Calculate the total number of iterations $N$ required to traverse the ray segment [S2].

3.  **Integration Loop**
    *   Initialize ray position $\mathbf{p}$ at the front-face entry point [S2].
    *   For $i = 0$ to $N-1$:
        *   Sample the volume data $V(\mathbf{p})$ using trilinear interpolation [S1].
        *   Apply a Phong-style shader to compute optical properties (color, opacity) [S1].
        *   Integrate the contribution into the accumulated color and opacity [G].
        *   Advance $\mathbf{p}$ by the step vector $\Delta \mathbf{p}$ [S2].
    *   The integration is structured in slabs: each slab of thickness $2d$ is defined by three successive samples $(s_f, s_m, s_b)$, with the next slab indexed by shifting these samples [S2].

**Pseudocode:**

```python
def raycasting_phase(volume_data, camera, step_length_d, decomposition):
    # Pass 1: Determine entry and exit points via back-face buffering
    back_face_coords = render_back_faces(volume_data, camera, decomposition)

    # Pass 2: Initialize rays and integrate
    final_colors = [None] * camera.resolution

    for pixel in camera.viewport:
        bf_coord = back_face_coords[pixel]

        if bf_coord is None:
            continue  # Discard fragment if no back-face hit

        ff_coord = get_front_face_coord(pixel)

        ray_origin = ff_coord
        ray_direction = normalize(camera.direction)
        step_vector = compute_step_vector(ray_direction, step_length_d, ff_coord, bf_coord)
        num_steps = compute_num_steps(ray_origin, bf_coord, step_vector)

        accumulated_color = [0.0, 0.0, 0.0]
        accumulated_opacity = 0.0
        current_pos = ray_origin

        for i in range(num_steps):
            # Sample volume data using trilinear interpolation [S1]
            sample_value = trilinear_interpolate(volume_data, current_pos)

            # Apply Phong-style shading [S1]
            color, opacity = apply_phong_shading(sample_value, current_pos, camera)

            # Integrate contribution into accumulated color and opacity [G]
            weight = (1.0 - accumulated_opacity) * opacity
            accumulated_color = [accumulated_color[j] + weight * color[j] for j in range(3)]
            accumulated_opacity += weight

            # Advance position by step vector
            current_pos = [current_pos[j] + step_vector[j] for j in range(3)]

        final_colors[pixel] = accumulated_color

    return final_colors

def render_back_faces(volume_data, camera, decomposition):
    # Rasterize decomposition blocks; store back-face texture coordinates in auxiliary buffer
    return [[None for _ in range(camera.resolution[1])] for _ in range(camera.resolution[0])]

def get_front_face_coord(pixel):
    # Retrieve front-face coordinates from second auxiliary buffer
    return [0.0, 0.0, 0.0]

def compute_step_vector(ray_direction, step_length_d, ff_coord, bf_coord):
    # Compute step vector along the ray based on predefined step length d and geometry
    return [step_length_d * ray_direction[j] for j in range(3)]

def compute_num_steps(ray_origin, bf_coord, step_vector):
    # Calculate total iterations to traverse the ray segment
    dist = ((bf_coord[0]-ray_origin[0])**2 + (bf_coord[1]-ray_origin[1])**2 + (bf_coord[2]-ray_origin[2])**2)**0.5
    step_mag = ((step_vector[0]**2 + step_vector[1]**2 + step_vector[2]**2)**0.5)
    return int(dist / step_mag) if step_mag > 0 else 0

def trilinear_interpolate(volume_data, pos):

def apply_phong_shading(sample_value, pos, camera):

def normalize(v):
    mag = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    return [v[0]/mag, v[1]/mag, v[2]/mag]
```

**Parameters:**
*   $d$: Predefined step length; slabs are defined with thickness $2d$ [S2].
*   Interpolation: Trilinear interpolation is used for data sampling along the ray [S1].
*   Shading: Phong-style shading is applied during the integration process [S1].

**Edge Cases and Pitfalls:**
*   **Thread Divergence:** The final raycasting time is determined by the runtime of the thread that takes the most integration steps, which depends on the view and decomposition geometry interaction [S1].
*   **Weak Scaling Degradation:** Perspective projection causes variation in the number of samples each thread must calculate; this variation increases at scale as each core operates on a smaller portion of the view frustum, accounting for a 20% performance degradation [S1].
*   **Memory Overflow:** Increasing image size to $23040^3$ causes temporary buffers for image fragments to overflow; to accommodate the fragment buffer, data size had to be scaled down to $19200^3$ (7.1 trillion cells) instead of $23040^3$ (12.2 trillion cells) [S1].
*   **Hybrid Memory Performance:** At higher concurrencies, the interaction between decomposition geometry and camera direction causes the hybrid-memory implementation to underperform distributed memory by 10% due to irregular block sizes in GPU clusters [S1].

## Operating characteristics
*   **Time Complexity:** Performance is bounded by the maximum integration steps among all threads [S1].
*   **Memory Complexity:** Fragment buffer size constraints force data downsampling to avoid overflow [S1].
*   **Scalability:** Distributed memory achieves linear scaling up to 216,000-way concurrency for the raycasting phase [S1]. Hybrid-memory implementations maintain ~80% scalability in weak scaling up to 216,000 cores but exhibit sublinear scaling in strong scaling due to irregular decomposition geometry [S1].
*   **Performance:** At 448-way concurrency with a $4608^3$ dataset, the hybrid/CUDA implementation averaged 1.18s for raycasting [S1].
*   **Strengths:** No message passing is involved in the raycasting phase itself, allowing for efficient scaling in distributed memory systems [S1].
*   **Limitations:** Performance is highly sensitive to view direction relative to decomposition geometry, and perspective projection exacerbates load imbalance in weak scaling [S1].

## Background
The method originated in the context of large-scale parallel volume rendering on multi- and many-core systems [S1]. It was developed to address the challenges of scaling raycasting across distributed and hybrid memory architectures [S1]. The two-pass approach with back-face depth buffering was introduced to efficiently determine ray entry and exit points without complex ray-volume intersection algorithms, leveraging GPU rasterization capabilities [S2].
