# Ray Marching and Discretization

Also called: Front-to-Back Accumulation, Ray Marching (Core Algorithm), Ray Marching for Volume Rendering, Volume Ray Marching (Basic), Volumetric Ray Marching

## Overview
Ray marching is an iterative numerical algorithm that solves the volume rendering equation by casting rays from the camera, advancing them through the volume in discrete steps, and accumulating optical contributions via front-to-back alpha compositing [S1][S6, unofficial]. It differs from fixed-step traversal by allowing variable step sizes guided by distance estimators or density thresholds, which enables efficient handling of sparse, implicit, or procedural data without uniform sampling across the entire domain [S3]. Unlike [Ray Tracing (Binary Objects)](3002-ray-tracing-binary-objects.md) which stops at the first surface hit, ray marching processes the entire volume along the ray to render translucent participating media [S3][S11, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ (in world or model space); 3D volume texture $V$ (scalar field); transfer function or colormap $C_{map}$; step size $\Delta s$ (or number of steps $N$); clipping bounds.
*   **Outputs:** Final pixel color $C_{out}$ and alpha $A_{out}$.

**Data Structures:**
*   **Volume Texture:** A 3D texture array or atlas storing scalar values (density/extinction coefficient). Layout is typically $[0, 1]^3$ normalized coordinates [S9].
*   **Accumulators:** Two floating-point variables, $C_{acc}$ (color, RGB) and $A_{acc}$ (alpha, scalar), initialized to $(0,0,0)$ and $0$ respectively [S9].

**Parameters:**
*   $\Delta s$: Step length. Typical values range from $0.00391$ ($\approx 1/256$) to fixed counts like $64$ steps per ray [S5, unofficial][S9].
*   $t_{max}$: Maximum ray distance or termination threshold for alpha (e.g., $0.95$ or $1.0$) [S9].
*   $\sigma_e$: Extinction coefficient (may be derived from sampled density) [S5, unofficial].

**Numbered Steps:**
1.  **Ray Initialization:** Determine the ray origin $\mathbf{o}$ and direction $\mathbf{d}$ in the volume's local coordinate system. Intersect the ray with the volume bounding box to find entry $t_{near}$ and exit $t_{far}$ distances [S5, unofficial][S9]. If no intersection, discard the pixel [S5, unofficial].
2.  **Step Calculation:** Compute the step vector $\mathbf{s} = \mathbf{d} \cdot \Delta s$ or calculate uniform step length if $N$ is fixed: $\Delta s = \frac{\|\mathbf{p}_{far} - \mathbf{p}_{near}\|}{N}$ [S5, unofficial][S9].
3.  **Iteration Loop:** While $t < t_{far}$ and $A_{acc} < t_{max}$:
    a. **Query:** Sample the volume at current position $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ to get scalar value $v = V(\mathbf{p})$ [S9].
    b. **Transfer Function:** Map $v$ to color $c$ and opacity $\alpha$. Commonly, $\alpha = 1 - e^{-\sigma_e \Delta s}$ where $\sigma_e$ is derived from $v$ (e.g., $\sigma_e = v \cdot \text{multiplier}$) [S5, unofficial]. Alternatively, for low albedo, $\alpha \approx \sigma_a \Delta s$ [S12].
    c. **Compositing:** Update accumulators using front-to-back blending:
       $$ C_{acc} \leftarrow C_{acc} + c \cdot \alpha \cdot (1 - A_{acc}) $$
       $$ A_{acc} \leftarrow A_{acc} + \alpha \cdot (1 - A_{acc}) $$
    d. **Advance:** Increment $t \leftarrow t + \Delta s$ [S9].
4.  **Early Termination:** If $A_{acc}$ exceeds a threshold (e.g., $0.95$), break the loop. This optimization does not significantly affect final appearance for opaque regions [S1, S9].
5.  **Output:** Write $C_{acc}$ and $A_{acc}$ to the framebuffer.

**Pseudocode:**
```python
def ray_march(ray_origin, ray_direction, volume_texture, colormap, step_length, alpha_threshold=0.95):
    # 1. Intersect with bounding box [S5, unofficial][S9]
    # Assume box_min and box_max are defined in the same coordinate space as ray_origin
    t_min = max((box_min.x - ray_origin.x) / ray_direction.x,
                (box_min.y - ray_origin.y) / ray_direction.y,
                (box_min.z - ray_origin.z) / ray_direction.z)
    t_max = min((box_max.x - ray_origin.x) / ray_direction.x,
                (box_max.y - ray_origin.y) / ray_direction.y,
                (box_max.z - ray_origin.z) / ray_direction.z)
    
    if t_min > t_max or t_max < 0:
        return vec4(0.0) # No intersection

    t = t_min
    acc_color = vec3(0.0)
    acc_alpha = 0.0
    
    # 2. Iterate [S9]
    while t < t_max and acc_alpha < alpha_threshold:
        # Current position
        pos = ray_origin + ray_direction * t
        
        # 3. Query Volume [S9]
        # Sample scalar value (e.g., density)
        val = texture(volume_texture, pos).r
        
        # 4. Transfer Function & Alpha Calculation [S5, unofficial][S9]
        # Example: Linear alpha mapping or exponential extinction
        # Using exponential extinction: alpha = 1 - exp(-sigma_e * delta_s)
        # Here sigma_e is approximated by val * multiplier
        sigma_e = val * 1.0 # multiplier depends on data range
        alpha = 1.0 - exp(-sigma_e * step_length)
        
        # Map value to color
        color = texture(colormap, vec2(val, 0.5)).rgb
        
        # 5. Front-to-Back Compositing [S5, S8, unofficial]
        # C_out = C_in + c * alpha * (1 - A_in)
        # A_out = A_in + alpha * (1 - A_in)
        weight = alpha * (1.0 - acc_alpha)
        acc_color += color * weight
        acc_alpha += weight
        
        # 6. Advance [S9]
        t += step_length
        
    return vec4(acc_color, acc_alpha)
```

## Subtopics

### [Exponential Approximation Method](2079-exponential-approximation-method.md)
The Exponential Approximation Method (EAM) approximates the continuous light attenuation integral using discrete steps and an exponential transmittance model. It differs from standard linear alpha compositing by scaling sampled alpha values by a step-size-dependent correction factor, allowing larger steps while approximating exponential decay. It is typically chosen when performance is prioritized over exact physical accuracy, or when the volume data is sparse enough that early ray termination provides significant speedup.

### [Ray Marching Volume Rendering with Henyey-Greenstein Scattering](2545-ray-marching-volume-rendering-with-henyey-greenstein-scatter.md)
This method renders a 3D volume defined by a density texture by accumulating scattered light along a ray, utilizing the Henyey-Greenstein phase function to model anisotropic scattering and shadow rays for self-shadowing. It distinguishes itself from standard front-to-back volume rendering by explicitly incorporating directional light transport through the Henyey-Greenstein phase function, allowing for the visualization of forward or backward scattering effects in participating media.

### [Ray Tracing (Binary Objects)](3002-ray-tracing-binary-objects.md)
Ray Tracing (Binary Objects) is an image-order rendering technique for visualizing surfaces contained within binary volumetric data by determining only the first intersection points with a surface. It solves the problem of displaying opaque surfaces in binary volumes without requiring explicit boundary detection or hidden-surface removal algorithms. Unlike methods that composite translucent data or require gradient estimation from multi-valued volumes, this method treats the volume as a set of opaque objects where light stops at the first surface hit. It is distinguished from its siblings, such as [Discrete Ray Tracing](3020-discrete-ray-tracing.md) which uses voxel connectivity, and [Fixed Step Ray Marching](3136-fixed-step-ray-marching.md) which integrates density, by its exclusive focus on the binary "first-hit" condition using zero-order interpolation.

### [Discrete Ray Tracing](3020-discrete-ray-tracing.md)
Discrete Ray Tracing (DRT) is a volume rendering technique that approximates continuous viewing rays with discrete, voxel-connected paths (voxelization) to traverse a 3D scalar field. Unlike methods that rely on geometric primitives or acceleration structures, DRT directly samples the voxel grid using a 3D Digital Differential Analyzer (DDA) or Bresenham-like algorithm, guaranteeing that voxels are visited in the exact order of intersection. This approach limits intersection tests to Pythagorean complexity rather than cubic, ensuring the first opaque voxel found is the closest. It is distinguished from [Fixed Step Ray Marching](3136-fixed-step-ray-marching.md) by its adaptive step size (always moving to the next voxel boundary) and from [Exponential Approximation Method](2079-exponential-approximation-method.md) by its explicit traversal of every voxel along the ray path without skipping.

### [Fixed Step Ray Marching](3136-fixed-step-ray-marching.md)
Fixed Step Ray Marching is a direct volume rendering technique that integrates the volume rendering equation along camera rays using a constant step size, applying exponential absorption and gradient-based shading to fog-like participating media. It uniformly samples the ray, which simplifies implementation but requires tuning of `step_size` to balance visual quality and performance. Unlike [Exponential Approximation Method](2079-exponential-approximation-method.md), which may use analytical approximations for transmittance, this method explicitly computes transmittance per step using the Beer-Lambert law.

### [Per-primitive Ray Sampling](3560-per-primitive-ray-sampling.md)
Per-primitive ray sampling is a rendering strategy where each geometric primitive (specifically ellipsoids) independently updates only the ray segments it intersects, avoiding redundant parameter loads and enabling accurate Transfer Function (TF) mapping by accumulating contributions in 3D space. It sets itself apart from sibling methods like [Fixed Step Ray Marching](3136-fixed-step-ray-marching.md) and [Volume Ray Casting](3161-volume-ray-casting.md) by organizing computation around primitives rather than rays, which eliminates the need for explicit per-tile sorting required in 2D rasterization because contributions accumulate in depth order as each ray segment corresponds to a discrete depth interval.

### [Directional Derivative Diffuse Lighting](4113-directional-derivative-diffuse-lighting.md)
Directional Derivative Diffuse Lighting is an approximation for diffuse lighting in volumetric raymarching that estimates light scattering by comparing density at the current point and an offset point in the light direction, avoiding the need for normal calculation. It sets itself apart from standard surface raymarching normals by requiring only two density samples instead of multiple gradient estimates, making it significantly cheaper for the resource-intensive volumetric loop.

### [Specific Material and Geometry Rendering](4395-specific-material-and-geometry-rendering.md)
Specific Material and Geometry Rendering encompasses techniques for defining optical properties, handling complex geometric boundaries (such as planetary shells or binary objects), and implementing specific material compositing strategies within direct volume ray casting. It solves the problem of mapping raw spatial data (grids, textures, or procedural functions) to physically or artistically plausible light interaction, while providing specialized traversal logic for non-uniform domains like cloud layers or fog volumes. It differs from generic ray marching by explicitly handling material blending, post-activation density grids, and geometric constraints (shells, cutters) that dictate the integration domain and optical behavior.

### [DOSRender](5119-dosrender.md)
DOSRender is a depth-ordered, slice-based volume rendering technique that accumulates color and occlusion along a ray while simultaneously tracking semantic instance and group IDs for segmentation. It distinguishes itself from standard front-to-back ray casting by integrating precomputed occlusion samples and hierarchical group membership buffers directly into the accumulation pass, allowing for efficient occlusion-aware rendering and semantic data extraction in a single pass.

### [Light Transmittance Marching](5400-light-transmittance-marching.md)
Light Transmittance Marching is a technique to compute physically accurate lighting in a volume by casting a secondary raymarch from each sample point on the primary view ray towards the light source to calculate absorbed light (transmittance). It solves the problem of volumetric occlusion, where light passing through the volume before reaching a sample point is attenuated by the medium itself. Unlike [Front-to-Back Volume Rendering](2350-front-to-back-volume-rendering.md), which typically assumes uniform or pre-computed lighting, this method dynamically computes the light energy arriving at each sample point by accounting for the density along the path to the light.

### [Ray Casting with Slice-Based Sampling and Gradient Shading](12619-ray-casting-with-slice-based-sampling-and-gradient-shading.md)
This method performs direct volume ray casting by sampling a 3D volume stored in a 2D texture atlas, computing surface normals via finite differences of sampled densities, and applying diffuse shading. It stops sampling when a high-density threshold is reached or the ray exits the bounding box. It is distinguished from standard ray marching by its specific use of a 2D texture atlas for 3D data storage and the explicit calculation of gradients for lighting, rather than relying solely on transmittance accumulation or pre-computed normals.

### [Sphere-Guided Volume Rendering](15265-sphere-guided-volume-rendering.md)
Sphere-Guided Volume Rendering is a sampling strategy for neural implicit surface reconstruction that uses a trainable cloud of spheres to filter ray-marching samples. It solves the problem of inefficient sample distribution in standard volume rendering, where samples are often wasted in empty space or fail to capture thin geometry. Unlike fixed-step ray marching or methods relying on greedy optimization, this approach guides sampling by intersecting rays with a coarse surface approximation, ensuring samples are concentrated near the estimated surface. This improves sample efficiency and helps the implicit function converge to a better optimum.

### Low Albedo Discrete VRE (Alpha Blending Form)
A discrete VRE form derived by approximating transmittance using the first two terms of its Taylor series expansion and assuming low albedo ($\sigma_t \approx \sigma_a, \sigma_s \approx 0$) [S12]. The opacity is approximated as $\alpha_i \approx \sigma_a(\mathbf{p}_i, \omega)\Delta s$ [S12]. The final color is computed as $C = \sum_{i=0}^{N-1} [ C_i \alpha_i \prod_{j=0}^{i-1} t_j ]$, where $C_i$ refers to emission $L_e(\mathbf{p}_i, \omega)$ [S12]. This differs from standard discrete VRE where $C_i$ refers to the source term $L_i \Delta s$ [S12].

### Beam Pre-pass
A coarse pre-pass that computes first-hit distances at low resolution to fast-forward the main raymarch pass [S13, unofficial]. It runs at 1/8 resolution, launching one ray per 8×8 pixel block. Each ray walks the world at tile granularity and writes the first-hit distance to an `r32float` texture. The main pass fast-forwards each ray to that depth minus a 16-voxel safety margin [S13, unofficial].

### Parallel Analytic Marching
A parallelization strategy where multiple initial points are solved simultaneously to march towards all unsolved analytic cells in the active set [S14]. It initializes multiple points $\mathbf{x}$ in $Z$ in parallel by solving Eq 17, instead of a single point, and simultaneously marches towards all analytic cells in the active set $S$ that are unsolved to compute their respective analytic faces [S14]. This provides an efficiency improvement of order 10 on Nvidia GPUs compared to sequential execution [S14].

### Interpolated Shading
A technique that uses linear interpolation to shade entire patches of up to 10x10 pixels, allowing for fewer than one sample per pixel [S15, unofficial]. When hitting an object, it queries ahead of the current position, checks if all four corners of the current quad are inside the object, and compares normals at every corner to ensure they are relatively aligned [S15, unofficial]. It then uses linear interpolation to shade the patch [S15, unofficial]. This is an approximation that likely only makes sense for flat-shaded objects [S15, unofficial]. On a single CPU core of a MacBook Air M1, it renders a simple SDF object at up to 100 FPS [S15, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of pixels and $P$ is the number of steps per ray. Performance scales linearly with step count [S5, unofficial].
*   **Memory Complexity:** $O(V)$ for the volume texture, where $V$ is the number of voxels. Accumulators use constant memory per pixel [S9].
*   **Performance:** Fixed step counts provide predictable performance [S5, unofficial]. Early ray termination significantly speeds up rendering of opaque or dense volumes [S1, S9].
*   **Strengths:** Simple to implement; handles sparse and implicit data well via variable steps [S3]; real-time capable on GPUs [S1][S5, unofficial].
*   **Limitations:** Biased estimates if standard quadrature is used without delta tracking [S4]; low resolution causes blockiness [S10, unofficial]; early termination may miss subtle transparent details [S9].
*   **When to Use:** Real-time volume rendering, NeRF, SDF rendering [S6, unofficial].
*   **When Not to Use:** When physically accurate light transport (scattering) is required without approximation [S4]; when exact surface boundaries in binary data are needed without compositing .

## Background
Ray marching was introduced as an efficient method to solve the volume rendering equation with real-time performance, notably used in systems like Jrender [S1]. It is a core component of GPU-based volume rendering techniques that perform ray marching in fragment shaders [S2, unofficial]. The technique is widely used in rendering Neural Radiance Fields (NeRF) and Signed Distance Functions (SDFs) [S6, unofficial]. Variants like sphere tracing were introduced for antialiased rendering of height fields and extended to general implicit volumes [S3].
