# Material Parameter Setting

Also called: Material Format, Material object fields, Standard Volume Material, vpSetMaterial

## Overview
Material Parameter Setting defines the binding between spatial data (grids, textures, or procedural functions) and optical properties (absorption, scattering, emission) in volume rendering. It solves the problem of how to map raw voxel data to physically or artistically plausible light interaction. It is distinguished by two primary paradigms: a **Structured Object-Based** approach where a material object holds typed fields and texture descriptors, switching between a fast path (grid names) and a programmable path (nodes) [S1][S3], and a **Procedural API-Based** approach using context handles and integer constants to define material slots and surface side logic [S2].

## How it works
The method operates through two distinct implementation styles found in the literature: the Object-Based Material Format (common in modern GPU ray marchers) and the API-Based Material State (common in legacy C-based volume renderers).

### Inputs and Outputs
*   **Inputs:** Spatial data (VDB grids, 3D textures, or label maps), optical parameters (albedo, density, phase function coefficients), and metadata (affine transforms, intensity ranges).
*   **Outputs:** A configured material state object or context handle that the ray marching kernel queries during integration to determine color, opacity, and emission at each sample point.

### Data Structures

#### 1. Material Object (Object-Based)
Defined in [S1], this structure holds shading parameters. Texture descriptors are integers; `-1` indicates the texture is unused.

```cpp
struct Material {
    // Basic shading properties
    float3 albedo;          // Linear float RGB
    float metalness;        // Float [0..1]
    float roughness;        // Float [0..1]
    float3 F0;              // Linear float RGB, base reflectivity
    
    // Projection and Normal settings
    bool triplar;           // Boolean: XZ planar (false) vs triplanar (true)
    float normalStrength;   // Linear float
    
    // Texture Descriptors (integers, -1 if unused)
    int albedoTex;          // Texture descriptor for albedo
    int normalTex;          // Texture descriptor for normals
    int roughnessTex;       // Texture descriptor for roughness
    int metalnessTex;       // Texture descriptor for metalness
    int heightmapTex;       // Texture descriptor for geometric displacement
    int ambietTex;          // Texture descriptor for ambient occlusion
};
```

#### 2. Volume Material Setup State (SDK-Based)
Defined in [S4, unofficial], this represents the state passed to a shader material for rendering a volume with transfer functions.

```cpp
struct VolumeMaterialSetup {
    int _IsLabelMap;        // int flag (0 or 1)
    float _P1;              // Continuous TF intensity range lower bound
    float _P99;             // Continuous TF intensity range upper bound
    float4 _Dim;            // Vector4(dimX, dimY, dimZ, 1f)
    float4x4 _Affine;       // Affine matrix from metadata
    float4x4 _InvAffine;    // Inverse affine matrix
    Texture3D* texLbl;      // Label texture
    Texture3D* texW;        // Weight texture (null if not present)
    Texture3D* tfTexCurrent;// Transfer function texture
};
```

#### 3. API Material Properties (Procedural API)
Defined in [S2], properties are set via integer constants.

*   `material_num`: `VP_MATERIAL0` through `VP_MATERIAL5`.
*   `property`: `VP_AMBIENT`, `VP_DIFFUSE`, `VP_SPECULAR`, `VP_SHINYNESS`.
*   `surface_side`: `VP_EXTERIOR`, `VP_INTERIOR`, `VP_BOTH_SIDES`.

### Numbered Steps

#### Path A: Object-Based Material Construction
1.  **Initialize Material:** Create a `Material` instance.
2.  **Set Core Properties:** Assign `albedo`, `metalness`, `roughness`.
3.  **Set F0:**
    *   If using Constructor 1: Assign `F0` directly.
    *   If using Constructor 2: Assign `F0` to `[0.04, 0.04, 0.04]` (standard base reflectance for non-metal dielectrics) [S1].
4.  **Reset Textures:** Set all texture descriptors (`albedoTex`, `normalTex`, etc.) to `-1` [S1].
5.  **Set Defaults:** Set `triplar` to false (XZ planar), `normalStrength` to `1.0` [S1].
6.  **Attach Procedural Inputs (Optional):** If nodes are attached, override the fast-path grid names with procedural outputs for density, color, and temperature [S3].

#### Path B: API-Based Material Configuration
1.  **Select Context:** Obtain `vpContext *vpc`.
2.  **Select Material Slot:** Choose `material_num` (e.g., `VP_MATERIAL0`).
3.  **Set Surface Side:** Choose `surface_side` (`VP_EXTERIOR`, `VP_INTERIOR`, or `VP_BOTH_SIDES`). Note: `VP_EXTERIOR` affects voxels where the gradient points towards the viewer; `VP_INTERIOR` where it points away. Use `VP_REVERSE_SURFACE_SIDES` to invert this logic [S2].
4.  **Set Properties:** Call `vpSetMaterial(vpc, material_num, property, surface_side, r, g, b)`.
    *   For `VP_SHINYNESS`, `g` and `b` are unused.
    *   For `VP_AMBIENT`, `VP_DIFFUSE`, `VP_SPECULAR`, set RGB coefficients [S2].

#### Path C: Volume SDK Setup (VRDF)
1.  **Extract Dimensions:** Get `dimX, dimY, dimZ` from `d.meta.dim` [S4, unofficial].
2.  **Initialize Ranges:** Set `p1 = 0.0f`, `p99 = 1.0f`.
3.  **Check Intensity Range:** If `d.tf.type == "continuous"` and `d.meta.intensity_range` exists with length 2, set `p1 = d.meta.intensity_range[0]` and `p99 = d.meta.intensity_range[1]` [S4, unofficial].
4.  **Compute Affine:** Construct `affine` from `d.meta.affine` (4x4). Compute `invAffine = affine.inverse()` [S4, unofficial].
5.  **Select Textures:**
    *   `texLbl = volumeTexLabels ?? d.labelTexture ?? BlackTex3D` [S4, unofficial].
    *   `texW = volumeTexWeights ?? d.weightTexture ?? null`. Bind `_VolumeTexWeights` to `texW` or `BlackTex3D`. Set `_HasWeights = 1` if `texW != null`, else `0` [S4, unofficial].
6.  **Bind Transfer Function:** Bind `_TFTex` to `tfTexCurrent`. Set `_IsLabelMap = 1` if `d.tf.type == "labelmap"`, else `0` [S4, unofficial].
7.  **Set Uniforms:** Set `_P1`, `_P99`, `_Dim` (Vector4), `_Affine`, `_InvAffine`. Assign `volumeMaterial` to `MeshRenderer.sharedMaterial` [S4, unofficial].

### Formulas and Parameters

#### Optical Parameters
*   **Density ($\sigma$):** Multiplied by the volume channel grid to set the overall thick or thin character of the medium [S3].
*   **Scatter Color:** Sets the RGB reflectance of the volume [S3].
*   **Scatter Scale:** Sets the brightness of the reflection [S3].
*   **Anisotropy Mode:**
    *   **Henyey-Greenstein:** Slider range $[-1, +1]$. All-rounder for isotropic smoke [S3].
    *   **Jendersie-d’Eon:** Cloud specialist for light passing through water droplets [S3].
*   **Transparency Color:** Implements per-wavelength travel distances. Darker means thicker, brighter means thinner. Tints the volume with its opposite color at depth [S3].
*   **Transparency Depth:** Measured in centimeters. Should be set in relation to the real-world size of the volume. Tints the volume with its opposite color at depth, including shadows [S3].
*   **Emission Mode:**
    *   **Blackbody:** Converts temperature (Kelvin) to physically correct colors. Deep red $\approx 3,000$ K to white/blue-white $> 9,000$ K [S3].
    *   **Color:** Art-directed black-to-red-to-yellow gradient [S3].

#### Pseudocode: Object-Based Material Initialization
```python
def create_material(albedo, metalness, roughness, F0=None):
    """
    Creates a Material object.
    If F0 is None, uses default dielectric reflectance.
    """
    mat = Material()
    
    mat.albedo = albedo
    mat.metalness = metalness
    mat.roughness = roughness
    
    if F0 is not None:
        mat.F0 = F0
    else:
        # Default F0 for non-metal dielectrics
        mat.F0 = float3(0.04, 0.04, 0.04)
        
    # Reset textures to unused
    mat.albedoTex = -1
    mat.normalTex = -1
    mat.roughnessTex = -1
    mat.metalnessTex = -1
    mat.heightmapTex = -1
    mat.ambietTex = -1
    
    # Set defaults
    mat.tripar = False
    mat.normalStrength = 1.0
    
    return mat
```

### Edge Cases and Pitfalls
*   **Case Sensitivity:** Volume channel names (grid names) are case-sensitive [S3].
*   **Surface Side Logic:** `VP_EXTERIOR` and `VP_INTERIOR` depend on gradient direction. If the gradient is ambiguous or zero, behavior may be undefined or default to the specified side. Use `VP_REVERSE_SURFACE_SIDES` if the gradient direction is inverted relative to the viewer [S2].
*   **Transparency Depth Scaling:** `Transparency Depth` is in centimeters. Setting it incorrectly relative to the scene scale will result in incorrect attenuation and tinting [S3].
*   **Texture Descriptors:** Using `-1` explicitly disables texture lookup. Using an uninitialized or invalid integer may cause GPU crashes or undefined behavior [S1].

## Subtopics

### Volume Material Setup
A specific implementation variant for SDK-based rendering (e.g., VRDF) that handles transfer function binding and affine transformations. It differs from the generic object-based material by explicitly managing label maps, weight textures, and intensity range clamping (`_P1`, `_P99`) for continuous transfer functions. It is chosen when using a structured SDK pipeline that requires automatic handling of metadata and transfer function types (labelmap vs. continuous) [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** O(1) for material setup/configuration. O(1) per sample during ray marching (texture lookup and parameter evaluation).
*   **Memory Complexity:** O(1) for the material object itself. O(N) for associated textures/grids if attached.
*   **Performance:** The "fast path" (typed grid names) is optimized for speed, avoiding procedural node evaluation overhead [S3]. The "fully programmable path" incurs higher CPU/GPU overhead for node evaluation but offers greater flexibility [S3].
*   **Strengths:** Clear separation of concerns (data vs. shading). Support for both physical (Blackbody) and artistic (Color gradient) emission. Fine control over surface side selection.
*   **Limitations:** API-based approach (`vpSetMaterial`) is rigid and requires recompilation or complex state management for dynamic changes. Object-based approach requires careful management of texture descriptors.
*   **When to Use:** Use Object-Based for modern, flexible volume rendering with procedural details. Use API-Based for legacy systems or simple, static volume shading. Use Volume Material Setup when working with structured SDKs that provide metadata and transfer functions.

## Background
*   **Material Format:** Originated in GPU-based ray marching frameworks, specifically detailed in "Raymarching Distance Fields with CUDA" [S1]. It reflects the shift towards PBR (Physically Based Rendering) principles in volumetric shading.
*   **vpSetMaterial:** Part of the VolPack library, a classic C-based volume rendering toolkit from Stanford [S2]. It represents an earlier, state-machine approach to volume shading.
*   **Standard Volume Material:** Popularized by modern 3D software (e.g., Maxon Cinema 4D Redshift) as a user-friendly interface for VDB volumes, combining fast paths with procedural node support [S3].
*   **Volume Material Setup:** Derived from open-source SDKs like VRDF, focusing on automated setup from metadata [S4, unofficial].
