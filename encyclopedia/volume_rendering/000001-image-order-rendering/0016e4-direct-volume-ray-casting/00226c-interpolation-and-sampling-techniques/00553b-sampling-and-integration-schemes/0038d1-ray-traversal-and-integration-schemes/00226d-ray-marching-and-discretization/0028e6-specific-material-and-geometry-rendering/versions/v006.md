# Specific Material and Geometry Rendering

Also called: Material Parameter Setting, DVGO Density and Color Rendering, Procedural Volumetric Cloud Rendering, Mr-Voxel Volume Rendering, Ray-marched Volumetric Fog, Surface and DRR Rendering Modes, Material Percentage Volume Rendering, Volumetric Heat Haze, Volumetric Geometry Rendering

## Overview
Specific Material and Geometry Rendering encompasses the techniques for defining optical properties (density, scattering, emission) and geometric boundaries for participating media during ray marching. It solves the problem of mapping raw spatial data (voxels, procedural noise, or neural features) to physically plausible light interaction and determining how rays traverse these media. It is distinguished from generic integration schemes by its focus on the **material definition** (how $\sigma_a, \sigma_s, \sigma_e$ are derived) and **geometric constraints** (spherical shells, voxel grids, or procedural boundaries) that dictate the sampling domain.

## Shared principles
All methods in this family operate within the direct volume ray casting framework, accumulating radiance along a ray segment $[t_{near}, t_{far}]$. The core rendering equation solved is:
$$ L_o(x, \omega_o) = L_e(x, \omega_o) + \int_{0}^{\infty} \sigma_s(x) p(x, \omega_i, \omega_o) L_i(x, \omega_i) e^{-\int_{0}^{s} \sigma_t(x') ds'} ds $$
where $\sigma_t = \sigma_a + \sigma_s$. The specific variations lie in:
1.  **Density/Opacity Source:** Whether $\sigma_t$ is derived from explicit voxel grids ([Mr-Voxel](3874-mr-voxel-volume-rendering.md), [DVGO](12839-dvgo-density-and-color-rendering.md)), procedural noise fields ([Procedural Clouds](3480-procedural-volumetric-cloud-rendering.md)), or uniform constants ([Fog](4248-ray-marched-volumetric-fog.md)).
2.  **Geometric Boundary:** How the integration interval is determined. This may be a spherical shell intersection ([Procedural Clouds](3480-procedural-volumetric-cloud-rendering.md)), a depth-buffer-clamped ray segment ([Fog](4248-ray-marched-volumetric-fog.md)), or a scene-defined volume object ([Mr-Voxel](3874-mr-voxel-volume-rendering.md)).
3.  **Material Parameterization:** How optical coefficients are bound to spatial coordinates. This ranges from simple scalar fields ([Material Parameter Setting](5335-material-parameter-setting.md)) to neural feature vectors interpolated from grids ([DVGO](12839-dvgo-density-and-color-rendering.md)).

## Subtopics

### [Procedural Volumetric Cloud Rendering](3480-procedural-volumetric-cloud-rendering.md)
A real-time technique that ray-marches a spherical cloud layer built from tileable 3D noise fields. It is distinguished by its camera-centred direction grid for sky integration and explicit lifting of the cloud layer above terrain to avoid depth-compositing artifacts. It uses a spherical shell geometry defined by inner/outer radii relative to Earth's radius.

### [Mr-Voxel Volume Rendering](3874-mr-voxel-volume-rendering.md)
A direct volume ray casting technique implemented within the Mr-Voxel library. It is distinguished by its reliance on a simplified single-volume, single-light model and explicit voxel grid access via the `mScene` interface. It uses Russian Roulette for transmittance termination and computes optical depth via a specific `tau` method.

### [Ray-marched Volumetric Fog](4248-ray-marched-volumetric-fog.md)
Simulates light absorption, scattering, and soft shadows by treating fog as a 3D volume traced from the camera. It is distinguished by its use of a depth buffer to clamp ray length and its forward ray-marching approach which enables early-out optimizations when transmittance drops. It typically uses uniform density and Schlick-Henyey Greenstein phase functions.

### [Material Parameter Setting](5335-material-parameter-setting.md)
Defines the binding between spatial data and optical properties. It is distinguished by two paradigms: **Structured Object-Based** (using typed fields and texture descriptors in a `Material` struct) and **Procedural API-Based** (using context handles and integer constants like `VP_AMBIENT`). It handles the mapping of raw voxel data to physically or artistically plausible light interaction.

### [DVGO Density and Color Rendering](12839-dvgo-density-and-color-rendering.md)
Synthesizes novel views by combining a 3D voxel grid with a shallow neural network. It is distinguished by storing density and color features in a structured grid, allowing for fast trilinear interpolation, while using an MLP to handle view-dependent appearance. It uses shifted softplus activation for density to ensure non-negativity and sharpness.

### Surface and DRR Rendering Modes
*   **Definition:** Variants of volume rendering modes defined by how color $C(s)$ is computed. Surface rendering uses the Phong equation with volume gradients. Digitally Reconstructed Radiographs (DRRs) set $C(s)=(0,0,0)$, attenuating only backlight. Maximum Intensity Projections (MIPs) output the opacity $\alpha$ of the maximum-opacity interval [S1, unofficial].
*   **Parameter:** A uniform variable tells the fragment shader which mode to use [S1, unofficial].

### Material Percentage Volume Rendering
*   **Definition:** A technique for rendering volumes with mixtures of materials (e.g., bone, muscle) by creating material percentage volumes and compositing them [S2, unofficial].
*   **Steps:** Assumes scalar field sampled above Nyquist or low-pass filtered. Differentiates materials by scalar value or composition info. Creates scalar fields for each material percentage. Associates color/opacity with each material and linearly combines them. Uses a matte volume (0-1 scalar field) for slicing or spatial set operations. Transforms volume so one axis is perpendicular to image plane, projecting plane-by-plane back-to-front [S2, unofficial].

### Volumetric Heat Haze
*   **Definition:** Produces the same result as Volumetric Geometry but adds heat haze refraction. Requires V-Ray. Uses Surface channel gradient to change ray direction [S3].
*   **Parameter:** `Heat Haze (hhfactor)` multiplies refraction based on Surface channel gradient. 1 approximates normal air heat haze. 0 produces no effect. Larger values needed for smoke/other sources. Only available in Volumetric Heat Haze mode [S3].
*   **Pitfall:** Heat Haze only affects camera view, not shadows. If intersecting with VRayMtl refraction, Max depth of VRayMtl may need increase [S3].

### Volumetric Geometry Rendering
*   **Definition:** Produces the same visual result as Volumetric mode but uses procedural geometry made of multiple transparent layers. Requires V-Ray. Used for exporting deep images and render elements (normals, velocity, multi matte) not available in standard Volumetric mode [S3].
*   **Pitfall:** Approximate and Approximate+Shadows options for Scattering are not supported. Cutter Geom does not work when Mode is set to Volumetric Geometry [S3].

## Background
The concept of specific material rendering in volumes evolved from early object-order techniques like Drebin, Carpenter, and Hanrahan's material percentage volumes, which allowed compositing of multiple materials (bone, muscle) via scalar fields [S2, unofficial]. Image-order techniques, such as binary ray casting, shifted the focus to per-pixel integration [S2, unofficial]. Modern real-time implementations, such as those in Phoenix for 3ds Max, introduced specific modes like Volumetric Geometry and Heat Haze to leverage GPU ray marching for complex atmospheric effects and render element extraction [S3]. More recently, neural approaches like DVGO have reintroduced explicit voxel grids combined with neural networks to balance rendering speed and view-dependent accuracy [S1, unofficial].
