# Ray Marching and Discretization

Also called: Front-to-Back Accumulation, Ray Marching (Core Algorithm), Ray Marching for Volume Rendering, Volume Ray Marching (Basic)

## Overview
Ray marching and discretization is the core iterative algorithm for solving the volume rendering equation in image-order rendering by sampling volumetric data at discrete intervals along camera rays [S1][S6, unofficial]. It solves the problem of integrating light transport through participating media or implicit fields by replacing the continuous integral with a finite sum of sampled contributions [S6, unofficial]. Unlike [Ray Traversal and Integration Schemes](8341-ray-traversal-and-integration-schemes.md) which may use adaptive traversal or acceleration structures, this method typically employs fixed or uniformly distributed steps, making it simple to implement on GPUs but potentially inefficient in sparse volumes [S3][S5, unofficial]. It is distinguished from [Monte Carlo Path Tracing for Volume Rendering](4980-monte-carlo-path-tracing-for-volume-rendering.md) by its deterministic, low-variance accumulation and from [Cone Casting with Inscribed Sphere Sampling](11501-cone-casting-with-inscribed-sphere-sampling.md) by its point-sampling nature [S5, S6, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A 3D volume texture (scalar field, density, or SDF) [S2, unofficial][S9], a camera position and direction for each pixel [S5, unofficial], and rendering parameters (step size, max samples, transfer function) [S5, unofficial][S9].
*   **Outputs:** A final pixel color and alpha value [S5, unofficial][S9].

**Data Structures:**
*   **Volume Texture:** A 3D texture array or atlas storing scalar values. Layout is typically `width x height x depth` voxels [S9]. Access is via normalized coordinates $[0, 1]^3$ or world-space coordinates scaled by voxel size [S5, unofficial].
*   **Ray State:** For each pixel, maintain current position $\mathbf{p}$, accumulated color $C_{out}$, and accumulated alpha $A_{out}$ [S5, unofficial][S9].
*   **Accumulators:** $C_{out} = (0,0,0)$, $A_{out} = 0$ [S9].

**Numbered Steps:**

1.  **Ray Initialization:**
    Calculate the ray origin $\mathbf{o}$ and direction $\mathbf{d}$ in the volume's local space.
    *   $\mathbf{o}$ is the camera position transformed to model space [S9].
    *   $\mathbf{d}$ is normalized vector from $\mathbf{o}$ through the pixel's world position [S5, unofficial].
    *   Determine the entry ($t_{near}$) and exit ($t_{far}$) points of the ray with the volume bounding box [S5, unofficial]. If no intersection, discard [S5, unofficial].

2.  **Step Calculation:**
    Compute the step length $\Delta s$.
    *   Fixed step: $\Delta s = \frac{\text{intersection length}}{\text{RAY\_STEPS}}$ [S5, unofficial].
    *   Adaptive step: $\Delta s = \max(\Delta s_{min}, f(\mathbf{p}))$ where $f$ estimates distance to next feature [S3].
    *   Initialize current distance $t = t_{near}$ [S5, unofficial].

3.  **Marching Loop:**
    Iterate while $t < t_{far}$ and $A_{out} < \alpha_{threshold}$ (e.g., 0.95 or 0.99) [S5, unofficial][S9].
    *   **Sample:** Query the volume at $\mathbf{p} = \mathbf{o} + t \cdot \mathbf{d}$. Get scalar value $v$ [S9].
    *   **Transfer Function:** Map $v$ to color $c$ and opacity $\alpha_{step}$ using a transfer function or colormap [S5, unofficial][S9].
        *   Example: $\alpha_{step} = 1 - e^{-\sigma_e \Delta s}$ where $\sigma_e$ is extinction coefficient derived from $v$ [S5, unofficial].
        *   Example: $\alpha_{step} = v \cdot \text{stepAlpha}$ for low albedo approximation [S9].
    *   **Shading (Optional):** Estimate normal $\mathbf{n}$ via finite differences if lighting is enabled [S5, unofficial]. Compute diffuse/specular terms.
    *   **Composite:** Update accumulators using front-to-back blending [S5, unofficial][S9]:
        $$ C_{out} = C_{out} + c \cdot \alpha_{step} \cdot (1 - A_{out}) $$
        $$ A_{out} = A_{out} + \alpha_{step} \cdot (1 - A_{out}) $$
    *   **Advance:** $t = t + \Delta s$ [S5, unofficial].

4.  **Early Termination:**
    If $A_{out} \ge \alpha_{threshold}$, break the loop [S5, unofficial][S9]. This optimization assumes that further samples contribute negligibly to the final color [S1].

5.  **Output:**
    Return $C_{out}$ and $A_{out}$ as the pixel color and alpha [S5, unofficial].

**Pseudocode:**
```python
def ray_march(volume_texture, camera_origin, camera_direction, params):
    """
    volume_texture: function or object providing sample(x, y, z) -> scalar
    camera_origin: vec3
    camera_direction: vec3 (normalized)
    params: dict with keys:
        - step_size: float
        - max_steps: int
        - alpha_threshold: float (default 0.95)
        - transfer_function: function(scalar) -> (color, alpha)
    """
    # 1. Ray-Box Intersection (Simplified AABB)
    box_min = params.get('box_min', vec3(-1))
    box_max = params.get('box_max', vec3(1))
    
    # Calculate intersection t values
    inv_dir = 1.0 / camera_direction
    t1 = (box_min - camera_origin) * inv_dir
    t2 = (box_max - camera_origin) * inv_dir
    t_near = max(max(t1.x, t1.y), t1.z)
    t_far = min(min(t2.x, t2.y), t2.z)
    
    # If ray misses or starts inside behind the box
    if t_near > t_far or t_far < 0:
        return (0.0, 0.0, 0.0), 0.0
        
    # Adjust origin if ray starts inside
    if t_near < 0:
        t_current = 0.0
    else:
        t_current = t_near
        
    # 2. Initialize Accumulators
    acc_color = vec3(0.0)
    acc_alpha = 0.0
    
    # 3. Marching Loop
    for i in range(params['max_steps']):
        # Check early termination
        if acc_alpha >= params['alpha_threshold']:
            break
            
        # Current position
        pos = camera_origin + camera_direction * t_current
        
        # 4. Sample Volume
        # Note: pos should be normalized to [0,1] if texture expects it
        scalar_val = volume_texture.sample(pos)
        
        # 5. Transfer Function
        color, step_alpha = params['transfer_function'](scalar_val)
        
        # 6. Composite (Front-to-Back)
        # Contribution of current step
        contribution = color * step_alpha * (1.0 - acc_alpha)
        acc_color = acc_color + contribution
        acc_alpha = acc_alpha + step_alpha * (1.0 - acc_alpha)
        
        # 7. Advance
        t_current += params['step_size']
        
    return acc_color, acc_alpha
```

**Parameters:**
*   `step_size` or `RAY_STEPS`: Controls resolution. Fixed step count is common for performance predictability [S5, unofficial]. Typical values: 64-300 steps [S2, S5, unofficial].
*   `alpha_threshold`: Early termination threshold. 0.95-0.99 is standard [S5, unofficial][S9].
*   `transfer_function`: Maps scalar density to RGBA. Can be linear, exponential, or lookup-table based [S5, unofficial][S9].

**Edge Cases and Pitfalls:**
*   **Aliasing:** Fixed step sizes can cause aliasing artifacts if the step size is too large relative to volume features [S5, unofficial].
*   **Precision:** Floating-point precision errors in ray position accumulation can cause gaps or overlaps in dense volumes [S3].
*   **Empty Space:** Marching through empty space wastes computation. Early termination helps, but sparse volumes benefit from acceleration structures (see [Ray Traversal Schemes](6890-ray-traversal-schemes.md)) [S3].
*   **Boundary Conditions:** Ray-box intersection logic must handle rays starting inside the volume correctly [S5, unofficial].

## Subtopics

### [Exponential Approximation Method](2079-exponential-approximation-method.md)
Approximates transmittance using exponential decay, allowing larger steps. Chosen for performance in sparse volumes.

### [Ray Marching Volume Rendering with Henyey-Greenstein Scattering](2545-ray-marching-volume-rendering-with-henyey-greenstein-scatter.md)
Adds anisotropic scattering via Henyey-Greenstein phase function. Chosen for realistic participating media like fog or clouds.

### [Ray Tracing (Binary Objects)](3002-ray-tracing-binary-objects.md)
Focuses on first-hit detection in binary volumes. Chosen for opaque surface visualization without compositing.

### [Discrete Ray Tracing](3020-discrete-ray-tracing.md)
Uses 3D DDA for exact voxel traversal. Chosen for efficient sampling in regular grids without geometric intersection tests.

### [Fixed Step Ray Marching](3136-fixed-step-ray-marching.md)
Uses constant step size with Beer-Lambert transmittance. Chosen for simplicity and uniform sampling.

### [Per-primitive Ray Sampling](3560-per-primitive-ray-sampling.md)
Organizes computation around primitives (e.g., ellipsoids). Chosen for accurate TF mapping in primitive-based volumes.

### [Directional Derivative Diffuse Lighting](4113-directional-derivative-diffuse-lighting.md)
Approximates diffuse lighting with two density samples. Chosen for cheap volumetric shading.

### [Specific Material and Geometry Rendering](4395-specific-material-and-geometry-rendering.md)
Defines data structures and shading logic. Chosen for decoupling traversal from material response.

### [DOSRender](5119-dosrender.md)
Depth-ordered, slice-based rendering with semantic IDs. Chosen for segmentation and occlusion-aware rendering.

### [Light Transmittance Marching](5400-light-transmittance-marching.md)
Casts secondary rays for light transmittance. Chosen for physically accurate volumetric occlusion.

### [Ray Casting with Slice-Based Sampling and Gradient Shading](12619-ray-casting-with-slice-based-sampling-and-gradient-shading.md)
Uses 2D texture atlas and gradient shading. Chosen for slice-based visualization with lighting.

### [Sphere-Guided Volume Rendering](15265-sphere-guided-volume-rendering.md)
Uses trainable spheres to guide sampling. Chosen for efficient neural implicit surface reconstruction.

### Low Albedo Discrete VRE (Alpha Blending Form)
A discrete VRE form derived by approximating transmittance using the first two terms of its Taylor series expansion and assuming low albedo ($\sigma_t \approx \sigma_a, \sigma_s \approx 0$) [S11]. The opacity is approximated as $\alpha_i \approx \sigma_a(\mathbf{p}_i, \omega)\Delta s$ [S11]. The final color is computed as $C = \sum_{i=0}^{N-1} [ C_i \alpha_i \prod_{j=i+1}^{N-1} (1 - \alpha_j) ]$, where $C_i$ is the emission $L_e(\mathbf{p}_i, \omega)$ [S11]. This differs from standard discrete VRE by applying low albedo and Taylor series approximations, interpreting the result as alpha blending [S11].

### Beam Pre-pass
A coarse pre-pass that computes first-hit distances at low resolution to fast-forward the main raymarch pass [S12, unofficial]. It runs at 1/8 resolution, launching one ray per 8×8 pixel block. Each ray walks the world at tile granularity and writes the first-hit distance to an `r32float` texture. The main pass fast-forwards each ray to that depth minus a 16-voxel safety margin [S12, unofficial].

### ROVER Volume Rendering Pipeline
A distributed ray casting volume rendering method that initializes rays with a fixed direction, computes a uniform sample distance from domain bounds, and delegates the marching loop to a VTK-m proxy tracer [S13, unofficial]. Ray direction components are initialized to $(1.0, 1.0, 1.0)$ and weight/alpha to 0.0 [S13, unofficial]. The sample distance is calculated as $\text{sample\_distance} = \frac{\|\text{domain\_extent}\|}{\text{num\_samples}}$ [S13, unofficial]. Pitfalls include runtime errors if called without a valid dataset or primary field [S13, unofficial].

### Parallel Analytic Marching
A parallelization strategy where multiple initial points are solved simultaneously to march towards all unsolved analytic cells in the active set [S14]. It initializes multiple points $\mathbf{x}$ in $\mathbb{Z}$ in parallel and marches towards all analytic cells in the active set $S$ that are unsolved [S14]. This achieves an efficiency improvement of order 10 on Nvidia GPUs compared to sequential execution [S14].

### Interpolated Shading
A technique that uses linear interpolation to shade entire patches of up to 10x10 pixels, allowing for fewer than one sample per pixel [S15, unofficial]. When hitting an object, it queries ahead, checks if all four corners of the current quad are inside the object, and compares normals to ensure alignment [S15, unofficial]. This is an approximation that likely only makes sense for flat-shaded objects [S15, unofficial]. On a MacBook Air M1, it renders a simple SDF object at up to 100 FPS [S15, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of pixels and $P$ is the number of samples per ray [S5, unofficial]. Performance scales linearly with step count [S5, unofficial].
*   **Memory Complexity:** $O(V)$ for the volume texture, where $V$ is the number of voxels [S5, unofficial].
*   **Measured Performance:** On a GPU, fixed-step ray marching is highly parallelizable. 64 steps is a reasonable compromise for quality and performance [S5, unofficial]. Early termination can significantly speed up sparse volumes [S1].
*   **Strengths:** Simple to implement, deterministic, works well with GPU fragment shaders [S2, S5, unofficial].
*   **Limitations:** Inefficient in sparse volumes due to uniform sampling [S3]. Prone to aliasing if step size is not tuned [S5, unofficial].
*   **When to Use:** Real-time rendering of dense volumes, procedural volumes, or when simplicity is prioritized [S1][S5, unofficial].
*   **When Not to Use:** Sparse volumes where acceleration structures are better [S3], or when high-fidelity light transport (scattering) is required without additional passes .

## Background
Ray marching for volume rendering originated as a practical method for real-time visualization of 3D scalar fields [S1][S2, unofficial]. It was popularized in the context of GPU-based rendering, where fragment shaders could efficiently march rays through 3D textures [S2, S5, unofficial]. The technique is foundational for rendering Neural Radiance Fields (NeRF) and Signed Distance Functions (SDFs) [S6, unofficial]. Variants like sphere tracing extend the concept to implicit surfaces [S3].
