# Ray-marched Volumetric Fog

Also called: Fog Filter, Forward ray-marching fog, Full-screen volumetric fog, Volumetric Fog (CRYENGINE 3), Voxel-based Volumetric Fog

## Overview
Ray-marched volumetric fog simulates light absorption, scattering, soft shadows, and light shafts (god rays) by treating fog as a 3D volume of participating media traced via ray-marching from the camera to the scene [S2, unofficial]. It is used for aerial perspective and to visualize volumes that absorb light [S1]. Unlike backward ray-marching, this forward approach allows for early-out optimizations when transmittance becomes sufficiently low [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera position, view direction per pixel, depth buffer (for scene intersection), light position and intensity, fog density, scattering coefficient, and phase function parameters.
*   **Outputs:** Final radiance $L$ per pixel.

**Data Structures:**
*   **Ray:** Defined by origin (camera position) and direction (view vector).
*   **Step Size ($\Delta l$):** A scalar float determining the distance between samples.
*   **Density ($\tau$):** A scalar float. For uniform fog, this is constant; for non-uniform fog, it is sampled from textures or OpenVDB [S2, unofficial].

**Numbered Steps:**
1.  **Ray Initialization:** For each pixel, construct a ray originating at the camera.
2.  **Scene Intersection:** Sample the depth buffer using the pixel's UV coordinate to reconstruct the 3D position of the scene intersection point [S2, unofficial].
3.  **Ray Clamping:** Clamp the ray's maximum distance to a `zfar` value to prevent infinite marching if the ray misses the scene [S2, unofficial].
4.  **Jittering (Optional but Recommended):** Add a pseudo-random delta step to the ray's starting position to fix slice artifacts caused by aligned samples [S2, unofficial].
5.  **Ray Marching Loop:** Iterate from the camera (start) to the scene intersection (finish) at regular intervals $\Delta l$.
6.  **Accumulation:** For each step $n$, calculate the in-scattering term and transmittance, then accumulate the result using a Riemann sum approximation [S2, unofficial].
7.  **Early Out:** If transmittance drops below a threshold, terminate the loop early [S2, unofficial].

**Formulas:**
The final radiance $L$ is calculated as:
$$
L = \sum_{n=0}^{N} L_i(x(l_n), \omega) e^{-\tau l_n} \Delta l
$$
Where:
*   $L_i(x(l_n), \omega)$ is the in-scattering term at step $n$.
*   $e^{-\tau l_n}$ is the transmittance for the distance $l_n$ travelled from the camera to the sample point.
*   $\Delta l$ is the ray-march step size.

The in-scattering term $L_i$ for a point light is:
$$
L_i(x, \omega) = \frac{a \Phi}{4\pi d^2} v(x) e^{-\tau d} P(\omega, \omega')
$$
Where:
*   $\tau$ is the fog density.
*   $a$ is the scattering coefficient.
*   $\Phi$ is the point light intensity.
*   $d$ is the distance from the sample point to the light source.
*   $v(x)$ is the visibility of the sample point from the light source (set to 1 if shadow mapping is not available) [S2, unofficial].
*   $e^{-\tau d}$ is the transmittance between the sample point and the light.
*   $P(\omega, \omega')$ is the phase function.

**Parameters:**
*   **Density ($\tau$):** Constant for uniform fog [S2, unofficial].
*   **Visibility ($v(x)$):** Typically 1 in basic implementations; can be sampled from a light's cube shadow map if available [S2, unofficial].
*   **Phase Function ($P$):** Uses the Schlick phase function approximation of Henyey-Greenstein (HG) for real-time performance [S2, unofficial].

**Pitfalls:**
*   **Slice Artifacts:** Occur when marching rays with the same step size starting at the same point, causing samples to align on the same "slices" [S2, unofficial].
*   **Noise:** Jittering reduces slice artifacts but can make the result look noisier on larger step sizes [S2, unofficial].

**Pseudocode:**
```python
def ray_marched_volumetric_fog(camera_pos, ray_dir, depth_buffer, light_pos, light_intensity, fog_density, scattering_coeff, step_size, zfar):
    # 1. Reconstruct scene intersection
    uv = get_pixel_uv()
    depth = depth_buffer.sample(uv)
    scene_pos = reconstruct_3d_position(uv, depth)
    
    # 2. Calculate ray length
    ray_length = length(scene_pos - camera_pos)
    
    # 3. Clamp to zfar
    ray_length = min(ray_length, zfar)
    
    # 4. Jitter start position to fix slice artifacts
    jitter = pseudo_random_float() * step_size
    current_dist = jitter
    
    # 5. Initialize accumulation
    total_radiance = vec3(0.0)
    current_transmittance = 1.0
    
    # 6. March loop
    while current_dist < ray_length:
        # Calculate sample position
        sample_pos = camera_pos + normalize(ray_dir) * current_dist
        
        # Calculate distance to light
        dist_to_light = length(sample_pos - light_pos)
        
        # Calculate transmittance from camera to sample
        camera_transmittance = exp(-fog_density * current_dist)
        
        # Calculate visibility (shadow) from sample to light
        # Note: v(x) is 1 if no shadow mapping is implemented [S2, unofficial]
        visibility = 1.0 
        
        # Calculate transmittance from sample to light
        light_transmittance = exp(-fog_density * dist_to_light)
        
        # Calculate phase function (Schlick approximation of HG)
        phase = schlick_henyey_greenstein(0.0) # Assuming g=0 for isotropic for simplicity
        
        # Calculate in-scattering
        in_scattering = (scattering_coeff * light_intensity / (4.0 * pi * dist_to_light * dist_to_light)) * visibility * light_transmittance * phase
        
        # Accumulate
        contribution = in_scattering * camera_transmittance * step_size
        total_radiance += contribution
        
        # Early out optimization if transmittance is too low
        if camera_transmittance < 0.01:
            break
            
        current_dist += step_size
        
    return total_radiance
```

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples $N$ along the ray.
*   **Memory Complexity:** Constant, requiring only per-pixel accumulators.
*   **Strengths:** Simple to implement in a full-screen shader; allows for early-out optimization; simulates dynamic lighting interactions (soft shadows, light shafts) [S2, unofficial].
*   **Limitations:** Slice artifacts require jittering; jittering can introduce noise; performance degrades with large step sizes or high resolution; assumes uniform fog unless additional data structures (textures/OpenVDB) are used [S2, unofficial].
*   **When to use:** Real-time applications requiring atmospheric effects and dynamic lighting interaction where backward ray-marching is not feasible or where early-out optimization is beneficial [S2, unofficial].

## Background
Ray-marched volumetric fog is a technique used in real-time graphics to simulate participating media. It is based on the volume rendering integral and approximates it using Riemann sums [S2, unofficial]. The specific implementation described follows the forward ray-marching approach, deviating from the backward ray-marching used in the Real-time Volumetric Lighting in Participating Media paper by Toth and Umenhofer [S2, unofficial]. This technique is used in games like Horizon Zero Dawn, Death Stranding, and Returnal [S2, unofficial].
