# Specific Material and Geometry Rendering

Also called: Material Parameter Setting, DVGO Density and Color Rendering, Procedural Volumetric Cloud Rendering, Mr-Voxel Volume Rendering, Ray-marched Volumetric Fog, Surface and DRR Rendering Modes, Material Percentage Volume Rendering, Volumetric Heat Haze, Volumetric Geometry Rendering

## Overview
Specific Material and Geometry Rendering encompasses the techniques for defining optical properties (density, scattering, emission) and geometric boundaries for participating media, and the specific integration strategies used to render them. It solves the problem of mapping raw spatial data (voxels, procedural noise, or neural features) to physically plausible light interaction and efficiently integrating the radiative transfer equation along camera rays. It is distinguished from general ray marching by its focus on the **material definition layer** (how data maps to $\sigma_a, \sigma_s, \sigma_e$) and **specialized geometry constraints** (spherical shells, binary objects, or neural grids) that dictate the sampling domain and integration limits.

## Shared principles
All methods in this family operate on the volume rendering integral, computing the radiance $L$ arriving at the camera by integrating along a ray $r(t) = o + td$:

$$ L = \int_{t_n}^{t_f} \sigma_e(r(t)) e^{-\int_{t_n}^{t} \sigma_t(r(\tau)) d\tau} dt + \int_{t_n}^{t_f} \sigma_s(r(t)) L_i(r(t)) e^{-\int_{t_n}^{t} \sigma_t(r(\tau)) d\tau} dt $$

where $\sigma_t = \sigma_a + \sigma_s$ is the extinction coefficient, $\sigma_e$ is emission, and $L_i$ is in-scattered radiance.

1.  **Discretization**: The integral is approximated via Riemann sums or numerical integration schemes (e.g., fixed step, adaptive step, or sphere-guided).
2.  **Material Binding**: Spatial data (grids, textures, noise) must be bound to optical parameters. This involves:
    *   **Interpolation**: Trilinear (voxels), procedural evaluation (noise), or neural network lookup (DVGO).
    *   **Activation**: Mapping raw data to physical coefficients (e.g., softplus for density, Schlick-HG for phase functions).
3.  **Geometric Clipping**: Rays are constrained to valid volume regions. Common constraints include:
    *   **Spherical Shells**: Defined by inner/outer radii (e.g., clouds).
    *   **Binary/Explicit Bounds**: Ray-surface intersections or voxel grid boundaries.
    *   **Procedural Masks**: Noise thresholds or weather maps defining presence.
4.  **Lighting Approximation**: In-scattering $L_i$ is often approximated due to computational cost:
    *   **Single Scattering**: Direct light transmittance $e^{-\sigma_t d}$.
    *   **Multiple Scattering**: Analytical approximations (e.g., 4-octave attenuation) or pre-computed lookups.
    *   **Phase Functions**: Henyey-Greenstein or Schlick approximations for angular distribution.

## Subtopics

### [Procedural Volumetric Cloud Rendering](3480-procedural-volumetric-cloud-rendering.md)
A real-time technique for rendering spherical cloud layers using procedural noise. It distinguishes itself by using a camera-centred direction grid for sky integration and explicitly lifting the cloud layer above terrain to avoid depth-compositing artifacts. It combines Schneider’s Nubis density model with Hillaire 2016 light transport, utilizing multiple scattering approximations and temporal reprojection.

### [Mr-Voxel Volume Rendering](3874-mr-voxel-volume-rendering.md)
A direct volume ray casting technique implemented within the Mr-Voxel library. It distinguishes itself by operating on explicit voxel grids accessed via a specific scene interface (`mScene`), assuming a single volume and single light source model. It uses a simplified integration loop with Russian Roulette for transmittance management.

### [Ray-marched Volumetric Fog](4248-ray-marched-volumetric-fog.md)
Simulates light absorption, scattering, and soft shadows by treating fog as a 3D volume traced via forward ray-marching from the camera. It differs from backward ray-marching by enabling early-out optimizations when transmittance becomes sufficiently low. It typically uses Schlick-Henyey Greenstein phase functions and inverse-square light attenuation.

### [Material Parameter Setting](5335-material-parameter-setting.md)
Defines the binding between spatial data and optical properties. It distinguishes itself through two paradigms: **Structured Object-Based** (using typed fields and texture descriptors in GPU shaders) and **Procedural API-Based** (using context handles and integer constants in legacy C-based renderers). It handles the mapping of raw voxel/noise data to $\sigma_a, \sigma_s, \sigma_e$.

### [DVGO Density and Color Rendering](12839-dvgo-density-and-color-rendering.md)
Direct Volume Grid Optimization synthesizes novel views by combining a 3D voxel grid with a shallow neural network. It distinguishes itself by storing density and color features in a structured grid for fast trilinear interpolation, while using an MLP to handle view-dependent appearance. It uses shifted softplus activation for density to ensure non-negativity and sharpness.

### Surface and DRR Rendering Modes
*   **Definition**: Variants of volume rendering modes often found in software like V-Ray. Surface rendering computes color via Phong shading using volume gradients. Digitally Reconstructed Radiographs (DRRs) set surface color to $(0,0,0)$, attenuating only the backlight. Maximum Intensity Projections (MIPs) output the maximum opacity $\alpha$ along the ray [S1, unofficial].
*   **Parameter**: A uniform variable controls the active mode in the fragment shader [S1, unofficial].

### Material Percentage Volume Rendering
*   **Definition**: A technique for rendering mixtures of materials (e.g., bone, muscle) by creating separate scalar fields for each material's percentage [S2, unofficial].
*   **Steps**: Assumes scalar fields are sampled above Nyquist or low-pass filtered. Creates material percentage volumes, associates color/opacity with each, and composites them linearly. A matte volume can be used for spatial slicing. Rendering is performed plane-by-plane in back-to-front order after transforming the volume axis [S2, unofficial].

### Volumetric Heat Haze
*   **Definition**: Produces the same visual result as Volumetric Geometry but adds a refraction effect based on the Surface channel gradient [S3].
*   **Parameter**: `Heat Haze (hhfactor)` multiplies the refraction. 1 approximates normal air heat haze; 0 produces no effect. Larger values are needed if using smoke channels. It only affects camera view, not shadows [S3].
*   **Pitfall**: May require increasing the Max depth of intersecting refractive materials (e.g., VRayMtl) [S3].

### Volumetric Geometry Rendering
*   **Definition**: Uses procedural geometry made of multiple transparent layers to produce the same result as standard Volumetric mode. Used for exporting deep images and render elements (normals, velocity) not available in standard mode [S3].
*   **Pitfall**: Approximate scattering options are not supported. Cutter Geom does not work in this mode [S3].

## Background
Volume rendering has evolved from object-order techniques (Drebin, Carpenter, and Hanrahan [S2, unofficial]) to image-order ray casting. The specific material and geometry rendering family addresses the practical implementation challenges of real-time and offline rendering:
1.  **Material Binding**: Early work focused on transfer functions for scalar fields [S2, unofficial]. Modern approaches use GPU-friendly object-based structures [S1, unofficial] and neural features (DVGO) [S1, unofficial].
2.  **Geometry Constraints**: Cloud rendering introduced spherical shell intersections and procedural noise (Nubis) [S3]. Fog rendering standardized forward ray-marching with early-outs [S1, unofficial].
3.  **Software Integration**: Renderers like V-Ray introduced specific modes (DRR, MIP, Heat Haze) to handle specialized visualization needs and export requirements [S1, unofficial][S3].
