# Runge-Kutta 4 (RK4) Integration

Also called: Fourth-order Runge-Kutta, RK4 Integrator, Runge-Kutta 4 Integrator, Runge-Kutta 4th order

## Overview
Runge-Kutta 4 (RK4) is a higher-order numerical integration scheme used to solve the initial value problem for particle trajectories in vector fields during volume rendering [S1, unofficial][S2, unofficial]. It improves upon the [Zero Order Integration (Rectangle Rule)](2082-zero-order-integration-rectangle-rule.md) by querying the vector field at four distinct positions within a step to compute a weighted average slope, significantly reducing integration error [S1, unofficial]. Unlike its sibling [Gaussian Integration for Volume Rendering](5546-gaussian-integration-for-volume-rendering.md), which may use probabilistic or smoothed sampling, RK4 is a deterministic, high-accuracy method that maintains particles within flow structures (such as vortices) where lower-order methods like Euler integration tend to escape [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Current position $x_i$ (3D vector), step size $\delta$ (scalar), and optionally a function time $t_{\text{func}}$ (scalar) for unsteady fields.
*   **Output:** Next position $x_{i+1}$ (3D vector).

**Data Structures:**
*   **Vector Field:** A function or texture lookup $v(x, t)$ returning a 3D vector at position $x$ and time $t$.
*   **Position:** A 3D vector $(x, y, z)$.

**Numbered Steps:**
1.  Calculate half-step size: $dt_{half} = \delta / 2$.
2.  Sample the vector field at the current position to get the first slope estimate $v_0$:
    $$v_0 = v(x_i, t_{\text{func}})$$
3.  Sample the vector field at the position advanced by half a step using $v_0$ to get the second slope estimate $v_1$:
    $$v_1 = v(x_i + \frac{1}{2} \delta v_0, t_{\text{func}})$$
4.  Sample the vector field at the position advanced by half a step using $v_1$ to get the third slope estimate $v_2$:
    $$v_2 = v(x_i + \frac{1}{2} \delta v_1, t_{\text{func}})$$
5.  Sample the vector field at the position advanced by a full step using $v_2$ to get the fourth slope estimate $v_3$:
    $$v_3 = v(x_i + \delta v_2, t_{\text{func}})$$
6.  Compute the next position $x_{i+1}$ using the weighted sum of the slopes:
    $$x_{i+1} = x_i + \frac{\delta}{6} (v_0 + 2v_1 + 2v_2 + v_3)$$

**Formulas:**
The core integration step is defined as [S2, unofficial]:
$$x_{i+1} = x_i + \frac{1}{6} \delta (v_0 + 2v_1 + 2v_2 + v_3)$$
Where:
*   $x_i$ is the current position.
*   $x_{i+1}$ is the next position.
*   $\delta$ is the step size.
*   $v_0, v_1, v_2, v_3$ are the vector field samples defined above.

Alternatively, using intermediate $k$ values as described in [S1, unofficial]:
$$k_1 = \delta \cdot v(x_n)$$
$$k_2 = \delta \cdot v(x_n + k_1/2)$$
$$k_3 = \delta \cdot v(x_n + k_2/2)$$
$$k_4 = \delta \cdot v(x_n + k_3)$$
$$x_{n+1} = x_n + \frac{k_1}{6} + \frac{k_2}{3} + \frac{k_3}{3} + \frac{k_4}{6} + O(\delta^5)$$
Where $O(\delta^5)$ represents the local truncation error [S1, unofficial].

**Parameters:**
*   **Step size ($\delta$ or $dt$):** In real-time applications, this is often dynamic, adjusted to maintain frame rate performance [S2, unofficial]. For steady fields, it is a fixed constant.

**Edge Cases and Pitfalls:**
*   **Unsteady Fields:** For unsteady vector fields, the function time $t_{\text{func}}$ must be synchronized with the integration step size to maintain real-time behavior and consistency [S2, unofficial].
*   **Steady Fields:** For steady fields, the time argument $t_{\text{func}}$ should be ignored or set to a fixed value (e.g., 0) [S2, unofficial].
*   **Vortex Convergence:** RK4 may converge to the center of vortices rather than escaping them, which differs from Euler integration that tends to escape vortices even at small step sizes [S1, unofficial].

**Pseudocode:**
```python
def rk4_integrate(pos, dt, vector_field_func, t_func=0.0):
    """
    Performs one step of Runge-Kutta 4 integration.
    
    Args:
        pos: Current position (tuple or list of 3 floats: x, y, z).
        dt: Step size (float).
        vector_field_func: Function that takes (x, y, z, t) and returns (vx, vy, vz).
        t_func: Current time for unsteady fields (float).
        
    Returns:
        Next position (tuple or list of 3 floats: x, y, z).
    """
    dt_half = dt * 0.5
    
    # Sample k1 at current position
    k1 = vector_field_func(pos[0], pos[1], pos[2], t_func)
    
    # Sample k2 at pos + dt_half * k1
    x2 = pos[0] + dt_half * k1[0]
    y2 = pos[1] + dt_half * k1[1]
    z2 = pos[2] + dt_half * k1[2]
    k2 = vector_field_func(x2, y2, z2, t_func)
    
    # Sample k3 at pos + dt_half * k2
    x3 = pos[0] + dt_half * k2[0]
    y3 = pos[1] + dt_half * k2[1]
    z3 = pos[2] + dt_half * k2[2]
    k3 = vector_field_func(x3, y3, z3, t_func)
    
    # Sample k4 at pos + dt * k3
    x4 = pos[0] + dt * k3[0]
    y4 = pos[1] + dt * k3[1]
    z4 = pos[2] + dt * k3[2]
    k4 = vector_field_func(x4, y4, z4, t_func)
    
    # Weighted sum: dt/6 * (k1 + 2*k2 + 2*k3 + k4)
    dt_sixth = dt / 6.0
    
    new_x = pos[0] + dt_sixth * (k1[0] + 2.0 * k2[0] + 2.0 * k3[0] + k4[0])
    new_y = pos[1] + dt_sixth * (k1[1] + 2.0 * k2[1] + 2.0 * k3[1] + k4[1])
    new_z = pos[2] + dt_sixth * (k1[2] + 2.0 * k2[2] + 2.0 * k3[2] + k4[2])
    
    return (new_x, new_y, new_z)
```

## Subtopics

### [Euler Integration](3836-euler-integration.md)
A first-order method with lower accuracy ($O(dt)$ global error) but significantly lower computational cost per step compared to RK4. Choose when performance is critical and high accuracy is not required.

### [Runge-Kutta 2/3 ODE Solver](3839-runge-kutta-2-3-ode-solver.md)
A lower-order formulation requiring fewer function evaluations per step than RK4, offering a balance of accuracy and performance. Choose when RK4 is too slow but Euler is too inaccurate.

### [Tensorline Integration](9613-tensorline-integration.md)
Targets tensor fields and utilizes RK4 for higher accuracy in complex flow structures, combined with discrete compositing for image synthesis. Choose when visualizing directional information in tensor volumes.

### [Dormand-Prince 5(4) Step](13933-dormand-prince-5-4-step.md)
An explicit Run-Kutta method with 5th-order accuracy and embedded error estimation for adaptive step control. Choose when adaptive step sizing is needed to handle varying field complexity, unlike RK4's fixed step.

## Operating characteristics
*   **Time Complexity:** RK4 requires four vector field evaluations per step, making it approximately 4 times slower than Euler integration [S1, unofficial].
*   **Memory Complexity:** Minimal additional memory beyond storing the current position and temporary slope vectors.
*   **Accuracy:** The local truncation error is $O(\delta^5)$, providing significantly smaller error than Euler integration ($O(\delta^2)$) for the same step size [S1, unofficial]. For example, RK4 with $dt=1$ has less error than Euler with $dt=0.5$ [S1, unofficial].
*   **Strengths:** High accuracy, stability in complex flow structures (e.g., vortices), and deterministic behavior.
*   **Limitations:** Higher computational cost per step compared to lower-order methods. Fixed step size (unless combined with an adaptive controller) can lead to inefficiency in regions of low complexity.
*   **When to Use:** When high accuracy is required for particle trajectories or streamline visualization, and computational resources allow for 4x the cost of Euler integration.
*   **When Not to Use:** When real-time performance is strictly constrained and lower accuracy is acceptable (use Euler), or when adaptive step sizing is preferred (use Dormand-Prince).

## Background
RK4 was developed as part of the broader Runge-Kutta family of methods for solving ordinary differential equations. In the context of volume rendering and vector field visualization, it was adopted to overcome the inaccuracies of Euler integration, particularly in maintaining particles within vortices and reducing integration error [S1, unofficial]. It is widely used in real-time visualization systems where a balance between accuracy and performance is needed, often implemented on GPUs using CUDA or similar parallel computing frameworks [S1, unofficial][S2, unofficial].
