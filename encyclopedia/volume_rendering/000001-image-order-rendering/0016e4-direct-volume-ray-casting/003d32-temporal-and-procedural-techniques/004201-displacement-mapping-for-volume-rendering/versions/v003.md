# Displacement Mapping for Volume Rendering

Also called: Discontinuous Displacement Mapping, Generalized Displacement Mapping, Inverse Displacement Mapping

## Overview
Displacement Mapping for Volume Rendering is a technique for modeling interactive deformations, such as cutting, peeling, and deforming, on volumetric objects by applying unconventional, unorthogonal, and discontinuous displacements without requiring mesh re-tessellation [S1, unofficial]. It solves the problem of applying complex geometric transformations to implicit or texture-based volumes where explicit surface models are unavailable. Unlike surface subdivision methods that require costly re-meshing for discontinuities, this method uses GPU-based volumetric rendering with inverse displacement maps [S1, unofficial]. It sets itself apart from sibling procedural techniques by explicitly mapping sample points from a displaced proxy space back to the original object space using a vector-valued displacement function, allowing for non-smooth and topological changes [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset $O_j$ (stored as a 3D texture in GPU memory) representing the original object; a displacement function $D$ (stored as a texture of 8-bit or 16-bit point numbers, normalized) [S1, unofficial]; a proxy scene geometry (a bounding box) defining the bounded spatial domain of the displaced object [S1, unofficial].
*   **Output:** A rendered image of the displaced volumetric object.

**Data Structures:**
*   **Volume Texture:** 3D texture containing scalar density/opacity values for the original object $O$.
*   **Displacement Texture:** 3D texture containing 3D vector values for the displacement field $D$. The values are normalized point numbers (8-bit or 16-bit) [S1, unofficial].
*   **Proxy Geometry:** A simple bounding box (or similar primitive) that encloses the expected extent of the displaced volume.

**Steps:**
1.  **Define Reference Space:** Establish a common reference coordinate system $\Lambda$. For this method, $\Lambda$ is set to 3D Euclidean space ($E^3$) to allow displacement in any direction and magnitude [S1, unofficial].
2.  **Setup Proxy Geometry:** Define a proxy scene geometry (e.g., a bounding box) that represents the bounded spatial domain of the displaced object $O_0$ [S1, unofficial].
3.  **Render Slices:** Perform texture-based volume rendering using view-aligned slices. Render the proxy scene geometry with slices parallel to the view plane [S1, unofficial].
4.  **Inverse Mapping:** For each pixel in a slice, obtain the sample point $p_0$ in the displaced space (from the proxy geometry intersection). Map this point back to the original object space $p$ using the inverse displacement function:
    $$ p = p_0 + D(p_0) $$
    where $D$ is the displacement vector function evaluated at $p_0$ [S1, unofficial].
5.  **Sample Volume:** Use the mapped point $p$ to sample the original volume texture $O_j$ to retrieve the density and opacity values for compositing [S1, unofficial].
6.  **Compositing:** Perform standard direct volume ray casting compositing (alpha blending) along the ray using the sampled values [S5, S10, S37].

**Pseudocode:**
```python
# Assume standard direct volume ray casting loop structure
# Ray: origin o, direction d
# Volume: vol_texture (original object O)
# Displacement: disp_texture (function D)
# Proxy: bounding_box (defines domain of displaced space)

def render_displaced_volume(ray_o, ray_d, vol_texture, disp_texture, proxy_bbox):
    # 1. Intersect ray with proxy geometry to find range in displaced space
    t_min, t_max = proxy_bbox.intersect(ray_o, ray_d)
    
    # 2. Initialize compositing variables
    alpha = 0.0
    color = (0.0, 0.0, 0.0)
    
    # 3. Ray march through the displaced space
    # Step size can be adaptive or fixed
    step_size = 0.01 
    t = t_min
    
    while t < t_max and alpha < 1.0:
        # Current point in displaced space (p0)
        p0 = ray_o + t * ray_d
        
        # 4. Sample displacement vector D(p0) from displacement texture
        # D is stored as a 3D vector texture
        disp_vec = disp_texture.sample(p0)
        
        # 5. Map to original object space (p)
        # Formula: p = p0 + D(p0)
        p = p0 + disp_vec
        
        # 6. Sample original volume at p
        density, opacity = vol_texture.sample(p)
        
        # 7. Composite
        # Standard front-to-back compositing
        contribution = opacity * (1.0 - alpha)
        color += contribution * density # Simplified color/density mix
        alpha += contribution
        
        t += step_size
        
    return color
```

**Parameters:**
*   **Reference Space $\Lambda$:** $E^3$ [S1, unofficial].
*   **Displacement Texture Precision:** 8-bit or 16-bit normalized point numbers [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Normal Estimation:** Conventional normal estimation causes lighting artifacts at breaking points in discontinuous displacement maps. Correct calculation of surface normals is required if lighting is applied [S1, unofficial].
*   **Discontinuities:** The method supports discontinuous displacements (e.g., cuts), but standard interpolation in the displacement texture may blur sharp edges if not handled carefully [S1, unofficial].
*   **Proxy Bounds:** The proxy geometry must fully enclose the displaced object to avoid clipping artifacts [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray, similar to standard volume rendering. The additional cost is the texture lookup for the displacement vector and the vector addition for coordinate mapping [S1, unofficial].
*   **Memory Complexity:** Requires storage for the original volume texture and the displacement vector texture. The displacement texture size depends on the resolution of the displacement field [S1, unofficial].
*   **Strengths:** Allows for interactive, discontinuous deformations (cutting, peeling) without mesh re-tessellation; works with implicit or texture-based volumes; leverages GPU texture hardware [S1, unofficial].
*   **Limitations:** Requires careful handling of normals for lighting; discontinuities may require special texture filtering or sampling strategies; the proxy geometry must be chosen to encompass all possible displacements [S1, unofficial].
*   **When to use:** When rendering volumetric objects that undergo complex, potentially discontinuous deformations interactively, and when explicit mesh representations are not available or desirable [S1, unofficial].
*   **When not to use:** When high-fidelity surface lighting is critical and normal calculation is complex; when the displacement field is extremely large and cannot be efficiently stored in texture memory [S1, unofficial].

## Background
Displacement mapping is traditionally used for adding surface details to polygonal objects, often involving micro-polygons and costly re-meshing for discontinuities [S1, unofficial]. This approach was extended to volume graphics by introducing a generalized notion of displacement mapping that allows for unorthogonal and discontinuous displacements [S1, unofficial]. The method was proposed by [S1, unofficial] to address the technical difficulties associated with applying such displacements to volumetric objects, where the interior is represented rather than just the surface. It utilizes inverse displacement maps in 3D vector space and adapts slicing-based rendering strategies for view-oriented sampling [S1, unofficial].
