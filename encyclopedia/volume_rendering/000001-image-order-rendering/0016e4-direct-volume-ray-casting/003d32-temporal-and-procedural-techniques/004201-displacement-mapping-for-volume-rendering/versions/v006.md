# Displacement Mapping for Volume Rendering

Also called: Discontinuous Displacement Mapping, Generalized Displacement Mapping, Inverse Displacement Mapping

## Overview
Displacement Mapping for Volume Rendering is a technique for modeling interactive deformations (cuts, peeling, deforming) on volumetric objects by applying unconventional, unorthogonal, and discontinuous displacements, avoiding mesh re-tessellation [S1, unofficial]. It solves the limitation of static volumetric representations by allowing complex geometric changes without explicit surface models, building on the principles of [Direct volume ray casting](19-direct-volume-ray-casting.md). Unlike standard scalar displacement which often produces symmetrical deformations, this method supports vector-based and surface-normal-based shifts, enabling complex, asymmetric geometries such as waves with convex backs and concave fronts [S1, unofficial]. It differs from [GPU-accelerated ray casting with volumetric lenses](6767-gpu-accelerated-ray-casting-with-volumetric-lenses.md) by focusing on topological changes (discontinuities) rather than optical refraction, and from [Procedural Volumetric Cloud Rendering (GPU Shader)](8240-procedural-volumetric-cloud-rendering-gpu-shader.md) by explicitly separating the proxy geometry sampling from the original object evaluation via an inverse map.

## How it works
**Inputs and Outputs:**
*   **Input:** A proxy scene geometry (bounding box) defining the spatial domain of the displaced object $O_0$; a displacement function $D$ (stored as a texture $D_k$); an original object representation $O$ (e.g., scalar volume texture $O_j$); view parameters.
*   **Output:** A rendered image of the displaced volumetric object.

**Data Structures:**
*   **Proxy Geometry:** A 3D bounding box object. If it contains volume data, it is sampled via slicing.
*   **Displacement Texture ($D_k$):** A 3D texture storing the displacement vector field. Values are 8-bit or 16-bit point numbers, normalized in $[0, 1]$ or $[-1, 1]$ depending on implementation, representing vectors in $E^3$ [S1, unofficial].
*   **Original Volume Texture ($O_j$):** A 3D texture storing the scalar density or color values of the undeformed object [S1, unofficial].

**Reference Coordinate System:**
Let $\Lambda$ be a common reference coordinate system shared by the object position function $P$ and the displacement function $D_B$. In this method, $\Lambda = E^3$ (3D Euclidean space) [S1, unofficial].
*   $P(\lambda)$: Maps a reference point $\lambda$ to a point in $E^3$.
*   $D_B(\lambda)$: The forward displacement vector function.

**Numbered Steps:**
1.  **Define Proxy Domain:** Establish a bounding box object that defines the bounded spatial domain of the displaced object $O_0$. This proxy serves as the sampling volume for the rendering process [S1, unofficial].
2.  **Render via Slicing:** Perform texture-based volume rendering using view-aligned slices. Render the proxy scene geometry by sampling it with slices parallel to the view plane [S1, unofficial].
3.  **Inverse Mapping:** For each pixel in a slice, obtain the sample point $p_0$ in the displaced space (proxy space). Map this point back to the original object space $p$ using the inverse displacement map [S1, unofficial].
4.  **Evaluate Original Object:** Evaluate the original object function $O(p)$ at the mapped point $p$ to retrieve luminance/density attributes [S1, unofficial].
5.  **Normal Calculation:** Compute surface normals for lighting. Conventional normal estimation causes artifacts at breaking points in discontinuous maps; specific techniques for displaced surface normals are required [S1, unofficial].

**Formulas:**
The forward displacement mapping is defined as [S1, unofficial]:
$$ P_0(\lambda) = P(\lambda) + D_B(\lambda) $$
where $\lambda \in \Lambda$, $P$ maps reference to point in $E^3$, and $D_B$ is the displacement vector function.

The rendering uses the inverse displacement mapping. Since $\Lambda = E^3$, we can simplify $P(\lambda) = p$ and $P_0(\lambda) = p_0$. The relationship is rewritten as [S1, unofficial]:
$$ p = p_0 + D(p_0) $$
where:
*   $p$ is the point in the original object space.
*   $p_0$ is the point in the displaced space (sampled from the proxy).
*   $D$ is the inverse displacement function (often denoted $D_C$ in literature, where $D_C$ is the inverse of $D_B$).

**Parameters:**
*   **Reference Space $\Lambda$:** Set to $E^3$ to allow displacement in any direction and magnitude [S1, unofficial].
*   **Displacement Texture Precision:** 8-bit or 16-bit point numbers [S1, unofficial].

**Pseudocode:**

```python
    """
    Renders a displaced volumetric object using inverse displacement mapping.
    
    Args:
        proxy_volume: 3D texture representing the bounding box/proxy geometry.
        displacement_texture: 3D texture storing the inverse displacement field D(p0).
        original_volume: 3D texture storing the original object density/color O(p).
        view_matrix: Camera view parameters for slicing.
        
    Returns:
        Image buffer.
    """
    image = create_empty_image_buffer()
    
    # 1. Define proxy scene geometry (bounding box) implicitly via proxy_volume bounds
    # 2. Render using texture-based volume rendering with view-aligned slices
    for each slice in view_aligned_slices(view_matrix):
        for each pixel in slice:
            # Sample the proxy scene geometry to get point p0 in displaced space
            p0 = sample_3d_texture(proxy_volume, pixel_ray_origin, pixel_ray_direction)
            
            # 3. Map back to original object space using inverse displacement map
            # Formula: p = p0 + D(p0)
            # D is stored in displacement_texture
            displacement_vector = sample_3d_texture(displacement_texture, p0)
            p = p0 + displacement_vector
            
            # 4. Evaluate original object at mapped point p
            # O(p) returns density/color
            density = sample_3d_texture(original_volume, p)
            
            # 5. Compute normal for lighting
            # Note: Conventional normal estimation causes artifacts at discontinuities.
            # A specific displaced normal calculation is required here [S1, unofficial].
            # Placeholder for specific normal computation logic not detailed in source.
            normal = compute_displaced_normal(p0, displacement_texture)
            
            # Shade pixel
            color = shade(density, normal, light_source)
            image[pixel] = color
            
    return image
```

**Edge Cases and Pitfalls:**
*   **Discontinuities:** Conventional normal estimation leads to noticeable lighting artifacts on surfaces displaced in varying directions and at breaking points in a discontinuous displacement map [S1, unofficial]. Correct normal calculation is required.
*   **Precision:** Displacement values must be handled carefully to avoid precision loss when mapping between spaces, especially with large displacements [S1, unofficial].

It solves the limitation of static volumetric representations by allowing interactive deformation without mesh re-tessellation, building on the principles of [Displacement Mapping for Volume Rendering](10659-displacement-mapping-for-volume-rendering.md). ## Operating characteristics
*   **Time Complexity:** Depends on the volume rendering algorithm (e.g., ray marching) and the cost of texture lookups for both the proxy and displacement maps. The inverse mapping adds one extra 3D texture lookup per sample.
*   **Memory Complexity:** Requires storage for the proxy volume, the original volume, and the displacement texture. Displacement textures are typically 8-bit or 16-bit [S1, unofficial].
*   **Strengths:** Allows interactive deformation (cuts, peeling) without mesh re-tessellation; supports unorthogonal and discontinuous displacements; works with implicit surfaces, level sets, and volume textures [S1, unofficial].
*   **Limitations:** Requires correct normal calculation to avoid artifacts at discontinuities; proxy geometry must bound the displaced object accurately; not suitable for methods requiring explicit surface meshes [S1, unofficial].
*   **When to use:** When simulating dynamic, discontinuous volumetric effects like cutting or peeling on GPU hardware without explicit mesh structures [S1, unofficial].
*   **When not to use:** When high-fidelity surface continuity is required without complex normal computation, or when the displacement is purely cosmetic on a static surface (standard displacement mapping may be simpler).

## Background
Displacement mapping is commonly used for adding surface details to an object. This method outlines a generalized notion of displacement mapping, allowing for unconventional features such as unorthogonal and discontinuous displacement [S1, unofficial]. By lifting the restriction on the geometric properties of the displacement, it generates special effects including peeling, cutting, and deforming objects, which are useful for volumetric objects where the interior is represented [S1, unofficial]. To address technical difficulties, it employs inverse displacement maps in 3D vector space and devises techniques including sampling displaced objects through proxy geometry and computing displaced surface normals [S1, unofficial]. The approach was demonstrated on current GPU hardware, adapting slicing-based rendering strategies [S1, unofficial].
