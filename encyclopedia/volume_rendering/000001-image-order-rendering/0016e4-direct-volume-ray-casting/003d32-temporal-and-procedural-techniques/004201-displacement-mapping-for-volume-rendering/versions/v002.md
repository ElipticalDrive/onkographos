# Displacement Mapping for Volume Rendering

Also called: Discontinuous Displacement Mapping, Generalized Displacement Mapping, Inverse Displacement Mapping

## Overview
Displacement Mapping for Volume Rendering is a technique for modeling interactive deformations (cuts, peeling, deforming) on volumetric objects by applying unconventional, unorthogonal, and discontinuous displacements, avoiding mesh re-tessellation [S1, unofficial]. It solves the problem of rendering deformed volumes where the interior is represented, by lifting restrictions on geometric properties of the displacement to allow complex special effects [S1, unofficial]. Unlike surface subdivision which requires costly re-meshing for discontinuities, this method uses GPU-based volumetric rendering without mesh structures [S1, unofficial]. It sets itself apart from siblings like [Volumetric Smoke Rendering with Worley Noise and Light Maps](2447-volumetric-smoke-rendering-with-worley-noise-and-light-maps.md) by focusing on explicit geometric deformation of a proxy volume rather than procedural density generation.

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset $O_j$ (original object) stored as a 3D texture in GPU memory; a displacement function $D_k$ (discretized from procedural specification) stored as a texture of 8-bit or 16-bit point numbers, normalized in $[0, 1]$; a proxy scene geometry (bounding box) defining the spatial domain of the displaced object $O_0$.
*   **Output:** A rendered image of the displaced volumetric object $O_0$.

**Data Structures:**
*   **Volume Texture $O_j$:** 3D texture containing scalar density/color values for the original object $O$.
*   **Displacement Texture $D_k$:** 3D texture storing vector displacements. Components are normalized 8-bit or 16-bit integers.
*   **Proxy Geometry:** A bounding box object that encloses the displaced volume $O_0$.

**Reference Coordinate System:**
A common reference coordinate system $\Lambda$ is shared by the object position function $P$ and the displacement function $D_B$. In this method, $\Lambda = E^3$ (3D Euclidean space) to allow displacement in any direction and magnitude [S1, unofficial].

**Formulas:**
The forward displacement mapping is defined as:
$$ P_0(\lambda) = P(\lambda) + D_B(\lambda) $$
where $\lambda \in \Lambda$, $P$ maps reference to point in $E^3$, and $D_B$ is the displacement vector function [S1, unofficial].

The rendering uses the inverse displacement mapping. Since $\Lambda = E^3$, we can make $P(\lambda) = p$ and $P_0(\lambda) = p_0$ where $p, p_0 \in E^3$. The equation is rewritten as:
$$ p = p_0 + D(p_0) $$
where $p$ is the point in original space, $p_0$ is the point in displaced space, and $D$ is the inverse displacement function [S1, unofficial].

**Steps:**
1.  Define the proxy scene geometry (bounding box) to define the bounded spatial domain of the displaced object $O_0$ [S1, unofficial].
2.  Render using texture-based volume rendering with view-aligned slices, sampling the proxy scene geometry with slices parallel to the view plane [S1, unofficial].
3.  For each pixel in a slice, obtain the sample point $p_0$ in the displaced space.
4.  Map the sampled point back to the original object space using the inverse displacement map: $p = p_0 + D(p_0)$ [S1, unofficial].
5.  Sample the original volume dataset $O_j$ at position $p$ to retrieve luminance attributes [S1, unofficial].
6.  Compute surface normals correctly to avoid lighting artifacts at breaking points in discontinuous displacement maps [S1, unofficial].

**Pseudocode:**
```python
def render_displaced_volume(proxy_bbox, volume_texture, displacement_texture, view_matrix):
    """
    Renders a displaced volume using inverse displacement mapping.
    proxy_bbox: Bounding box defining the domain of the displaced object O0.
    volume_texture: 3D texture of the original object O.
    displacement_texture: 3D texture of the displacement function D.
    view_matrix: Camera view matrix for generating view-aligned slices.
    """
    # Initialize output image
    image = create_empty_image()
    
    # Generate view-aligned slices within the proxy bounding box
    slices = generate_view_aligned_slices(proxy_bbox, view_matrix)
    
    for slice in slices:
        for pixel in slice.pixels:
            # 1. Sample point p0 in the displaced space (from the slice/proxy geometry)
            p0 = pixel.world_position
            
            # 2. Retrieve displacement vector D(p0) from the displacement texture
            # Note: Displacement texture stores normalized 8/16-bit values, 
            # must be converted to vector space coordinates.
            d_vec = displacement_texture.sample(p0)
            
            # 3. Map back to original object space using inverse displacement formula: p = p0 + D(p0)
            p = p0 + d_vec
            
            # 4. Sample the original volume dataset O at position p
            # O(p) returns luminance/density attributes
            color = volume_texture.sample(p)
            
            # 5. Compute correct normal for lighting
            # Conventional normal estimation causes artifacts at discontinuities.
            # Normal must be calculated based on the displacement field gradient 
            # or the transformed geometry of the proxy surface.
            normal = compute_displaced_normal(p0, displacement_texture)
            
            # 6. Apply lighting model (e.g., Phong or volume shading)
            lit_color = apply_lighting(color, normal, view_matrix)
            
            image.set_pixel(pixel.u, pixel.v, lit_color)
            
    return image
```

**Parameters:**
*   **Reference Space $\Lambda$:** Set to $E^3$ [S1, unofficial].
*   **Displacement Texture Precision:** 8-bit or 16-bit point numbers [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Lighting Artifacts:** Conventional normal estimation causes noticeable lighting artifacts on surfaces displaced in varying directions, and at breaking points in a discontinuous displacement map [S1, unofficial]. Correct normal calculation is required.
*   **Discontinuity Handling:** The method supports discontinuous displacements (cuts, peeling), but standard interpolation in the displacement texture may blur sharp edges if not handled carefully.

## Operating characteristics
*   **Time Complexity:** Depends on the number of slices and pixels per slice. Each pixel requires a texture lookup in the displacement map and a texture lookup in the volume map.
*   **Memory Complexity:** Requires storing the original volume texture and the displacement texture in GPU memory.
*   **Strengths:** Allows interactive deformations (cuts, peeling) without mesh re-tessellation; supports unorthogonal and discontinuous displacements; leverages GPU hardware for texture-based rendering [S1, unofficial].
*   **Limitations:** Requires a proxy geometry; correct normal calculation is non-trivial for discontinuous maps; limited by the resolution of the displacement texture [S1, unofficial].
*   **When to use:** When interactive deformation of volumetric objects is needed, especially for effects like cutting or peeling where mesh-based approaches are cumbersome.
*   **When not to use:** When high-fidelity continuous surface deformation is required without discontinuities, or when the volume data is too large to fit in GPU memory along with the displacement map.

## Background
Displacement mapping is commonly used for adding surface details to an object. This technique generalizes the notion to allow unconventional features such as unorthogonal and discontinuous displacement [S1, unofficial]. It was introduced to address technical difficulties associated with generalizing displacement mapping to volume graphics, where no surface model is available [S1, unofficial]. The method employs inverse displacement maps in 3D vector space and adapts slicing-based rendering strategies [S1, unofficial]. It demonstrates generality, interactivity, and usability for volumetric effects [S1, unofficial].
