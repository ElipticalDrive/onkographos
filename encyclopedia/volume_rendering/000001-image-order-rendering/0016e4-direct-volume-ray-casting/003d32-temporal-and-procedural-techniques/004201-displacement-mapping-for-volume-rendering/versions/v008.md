# Displacement Mapping for Volume Rendering

Also called: Discontinuous Displacement Mapping, Generalized Displacement Mapping, Inverse Displacement Mapping

## Overview
Displacement Mapping for Volume Rendering is a technique for modeling interactive deformations (cuts, peeling, deforming) on volumetric objects by applying unconventional, unorthogonal, and discontinuous displacements, avoiding mesh re-tessellation [S1, unofficial]. It solves the limitation of static volumetric representations by allowing complex geometric changes without explicit surface models, building on the principles of [Direct volume ray casting](19-direct-volume-ray-casting.md) [S1, unofficial]. Unlike surface subdivision which requires costly re-meshing for discontinuities, this method uses GPU-based volumetric rendering without mesh structures [S1, unofficial]. It differs from [GPU-accelerated ray casting with volumetric lenses](6767-gpu-accelerated-ray-casting-with-volumetric-lenses.md) by focusing on topological changes rather than optical refraction, and from [Procedural Volumetric Cloud Rendering (GPU Shader)](8240-procedural-volumetric-cloud-rendering-gpu-shader.md) by explicitly separating the proxy geometry sampling from the original object evaluation via an inverse map [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A proxy scene geometry (bounding box) defining the spatial domain of the displaced object $O_0$; a displacement function $D$ (stored as a texture $D_k$); an original object representation $O$ (e.g., scalar volume texture $O_j$); view parameters [S1, unofficial].
*   **Output:** A rendered image of the displaced volumetric object [S1, unofficial].

**Data Structures:**
*   **Proxy Geometry:** A 3D bounding box object that defines the bounded spatial domain of the displaced object $O_0$ [S1, unofficial]. If it contains volume data, it is sampled via slicing [S1, unofficial].
*   **Displacement Texture ($D_k$):** A 3D texture storing the displacement vector field, discretized from a procedural specification, stored as 8-bit or 16-bit point numbers normalized in $[0, 1]$ or $[-1, 1]$ [S1, unofficial].
*   **Original Volume Texture ($O_j$):** A 3D texture storing the scalar density or color values of the undeformed object, representing $O(p)$ [S1, unofficial].

**Reference Coordinate System:**
Let $\Lambda$ be a common reference coordinate system shared by the object position function $P$ and the displacement function $D_B$, set to $E^3$ (3D Euclidean space) [S1, unofficial]. $P(\lambda)$ maps a reference point $\lambda$ to a point in $E^3$, and $D_B(\lambda)$ is the forward displacement vector function [S1, unofficial].

**Numbered Steps:**
1.  Define a common reference coordinate system $\Lambda = E^3$ shared by $P$ and $D_B$ [S1, unofficial].
2.  Define a proxy scene geometry (a bounding box object) to define the bounded spatial domain of the displaced object $O_0$ [S1, unofficial].
3.  Render using texture-based volume rendering with view-aligned slices, sampling the proxy scene geometry with slices parallel to the view plane [S1, unofficial].
4.  For each pixel in a slice, map the sampled point back to the original object space using the inverse displacement map [S1, unofficial].
5.  Evaluate the original object function $O(p)$ at the mapped point to retrieve luminance attributes [S1, unofficial].
6.  Compute surface normals for lighting, using specific techniques for displaced surfaces to avoid artifacts at breaking points in discontinuous maps [S1, unofficial].

**Formulas:**
The forward displacement mapping is defined as [S1, unofficial]:
$$ P_0(\lambda) = P(\lambda) + D_B(\lambda) $$
where $\lambda \in \Lambda$, $P$ maps reference to point in $E^3$, and $D_B$ is the displacement vector function [S1, unofficial].

The rendering uses the inverse displacement mapping [S1, unofficial]. Since $\Lambda = E^3$, we can simplify $P(\lambda) = p$ and $P_0(\lambda) = p_0$ [S1, unofficial]. The relationship is rewritten as [S1, unofficial]:
$$ p = p_0 + D(p_0) $$
where:
*   $p$ is the point in the original object space [S1, unofficial].
*   $p_0$ is the point in the displaced space (sampled from the proxy) [S1, unofficial].
*   $D$ is the inverse displacement function (often denoted $D_C$ in literature, where $D_C$ is the inverse of $D_B$) [S1, unofficial].

**Parameters:**
*   **Reference Space $\Lambda$:** Set to $E^3$ to allow displacement in any direction and magnitude [S1, unofficial].
*   **Displacement Texture Precision:** 8-bit or 16-bit point numbers [S1, unofficial].

**Pseudocode:**
```python
def render_displaced_volume(proxy_volume, displacement_texture, original_volume, view_matrix, resolution):
    image = []
    # Generate slice planes parallel to the view plane [G]
    slices = generate_view_aligned_slices(view_matrix, resolution)
    for slice_plane in slices:
        for u in range(slice_plane.width):
            for v in range(slice_plane.height):
                # Sample point p0 on the proxy geometry/slice [G]
                p0 = sample_slice_point(slice_plane, u, v)
                # Sample inverse displacement vector D(p0)
                d = sample_3d_texture(displacement_texture, p0)
                # Map to original object space: p = p0 + D(p0)
                p = [p0[i] + d[i] for i in range(3)]
                # Evaluate original object O(p)
                density = sample_3d_texture(original_volume, p)
                # Compute normal for displaced surface [G]
                normal = compute_displaced_normal(p0, displacement_texture)
                # Shade and accumulate
                color = shade(density, normal, light_source)
                image.append((u, v, color))
    return image

def generate_view_aligned_slices(view_matrix, resolution):
    # Returns list of slice planes parallel to the view plane [G]
    return []

def sample_slice_point(slice_plane, u, v):
    # Returns 3D point p0 on the slice/proxy geometry [G]
    return [0.0, 0.0, 0.0]

def sample_3d_texture(tex, point):
    # Trilinear interpolation of 3D texture at point
    return [0.0, 0.0, 0.0]

def compute_displaced_normal(p0, displacement_texture):
    # Finite difference approximation of normal from displacement field [G]
    eps = 1e-3
    dx = sample_3d_texture(displacement_texture, [p0[0]+eps, p0[1], p0[2]]) - sample_3d_texture(displacement_texture, [p0[0]-eps, p0[1], p0[2]])
    dy = sample_3d_texture(displacement_texture, [p0[0], p0[1]+eps, p0[2]]) - sample_3d_texture(displacement_texture, [p0[0], p0[1]-eps, p0[2]])
    dz = sample_3d_texture(displacement_texture, [p0[0], p0[1], p0[2]+eps]) - sample_3d_texture(displacement_texture, [p0[0], p0[1], p0[2]-eps])
    tangent_x = [1, 0, 0] + dx
    tangent_y = [0, 1, 0] + dy
    tangent_z = [0, 0, 1] + dz
    normal = cross(tangent_x, tangent_y)
    return normalize(normal)

def cross(a, b):
    return [a[1]*b[2]-a[2]*b[1], a[2]*b[0]-a[0]*b[2], a[0]*b[1]-a[1]*b[0]]

def normalize(v):
    mag = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    return [v[0]/mag, v[1]/mag, v[2]/mag] if mag > 0 else [0, 0, 1]

def shade(density, normal, light_source):
    # Standard volume shading [G]
    return [density, density, density]
```

**Edge Cases and Pitfalls:**
*   **Discontinuities:** Conventional normal estimation leads to noticeable lighting artifacts on surfaces displaced in varying directions and at breaking points in a discontinuous displacement map [S1, unofficial]. Correct normal calculation is required.
*   **Precision:** Displacement values must be handled carefully to avoid precision loss when mapping between spaces, especially with large displacements [S1, unofficial].

## Subtopics

### [Displacement General Setup](11527-displacement-general-setup.md)
A rendering-time technique for adding geometric detail to volumetric simulations by shifting fluid points or surface vertices based on sampled texture maps. It solves the limitation of static volumetric meshes by allowing complex, high-frequency surface deformations without re-tessellating the underlying geometry. It distinguishes itself from standard mesh displacement by operating on volumetric data structures and supporting specialized modes like Surface-driven and Vector displacement, which handle directional consistency differently than scalar or gradient-based methods.

## Operating characteristics
*   **Time Complexity:** Depends on the volume rendering algorithm and the cost of texture lookups for both the proxy and displacement maps [S1, unofficial]. The inverse mapping adds one extra 3D texture lookup per sample [S1, unofficial].
*   **Memory Complexity:** Requires storage for the proxy volume, the original volume, and the displacement texture [S1, unofficial].
*   **Strengths:** Allows interactive deformation without mesh re-tessellation; supports unorthogonal and discontinuous displacements; works with implicit surfaces, level sets, and volume textures [S1, unofficial].
*   **Limitations:** Requires correct normal calculation to avoid artifacts at discontinuities; proxy geometry must bound the displaced object accurately; not suitable for methods requiring explicit surface meshes [S1, unofficial].
*   **When to use:** When simulating dynamic, discontinuous volumetric effects like cutting or peeling on GPU hardware without explicit mesh structures [S1, unofficial].
*   **When not to use:** When high-fidelity surface continuity is required without complex normal computation, or when the displacement is purely cosmetic on a static surface [S1, unofficial].

## Background
Displacement mapping is commonly used for adding surface details to an object [S1, unofficial]. This method outlines a generalized notion of displacement mapping, allowing for unconventional features such as unorthogonal and discontinuous displacement [S1, unofficial]. By lifting the restriction on the geometric properties of the displacement, it generates special effects including peeling, cutting, and deforming objects, which are useful for volumetric objects where the interior is represented [S1, unofficial]. To address technical difficulties, it employs inverse displacement maps in 3D vector space and devises techniques including sampling displaced objects through proxy geometry and computing displaced surface normals [S1, unofficial]. The approach was demonstrated on current GPU hardware, adapting slicing-based rendering strategies [S1, unofficial].
