# Displacement Mapping for Volume Rendering

Also called: Discontinuous Displacement Mapping, Generalized Displacement Mapping, Inverse Displacement Mapping

## Overview
Displacement Mapping for Volume Rendering is a technique for modeling interactive deformations (cuts, peeling, deforming) on volumetric objects by applying unconventional, unorthogonal, and discontinuous displacements, avoiding mesh re-tessellation [S1, unofficial]. It solves the limitation of static volumetric representations by allowing complex geometric changes without explicit surface models. Unlike standard scalar displacement which often produces symmetrical deformations, this method supports vector-based and surface-normal-based shifts, enabling complex, asymmetric geometries such as waves with convex backs and concave fronts [S1, unofficial]. It builds on the principles of [Direct volume ray casting](19-direct-volume-ray-casting.md) but modifies the sampling stage to account for displaced coordinates.

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset $O_j$ (original object) stored as a 3D texture; a displacement function $D_k$ (discretized, e.g., procedural or texture-based) stored as a 3D texture of 8-bit or 16-bit point numbers, normalized in $[0, 1]$ [S1, unofficial].
*   **Output:** A rendered image of the displaced volumetric object $O_0$.

**Data Structures:**
*   **Reference Space $\Lambda$:** Set to 3D Euclidean space ($E^3$) to allow displacement in any direction and magnitude [S1, unofficial].
*   **Proxy Geometry:** A bounding box object defining the bounded spatial domain of the displaced object $O_0$ [S1, unofficial].
*   **Volume Texture:** 3D texture containing the original scalar field $O_j$ [S1, unofficial].
*   **Displacement Texture:** 3D texture containing the vector field $D_k$ [S1, unofficial].

**Method Steps:**
1.  **Define Reference System:** Establish a common reference coordinate system $\Lambda = E^3$ shared by the object position function $P$ and the displacement function $D_B$ [S1, unofficial].
2.  **Setup Proxy Geometry:** Define a proxy scene geometry (a bounding box) that encloses the expected spatial domain of the displaced object $O_0$ [S1, unofficial].
3.  **Render via Slicing:** Use texture-based volume rendering with view-aligned slices. Sample the proxy scene geometry with slices parallel to the view plane [S1, unofficial].
4.  **Inverse Mapping:** For each sample point $p_0$ in the displaced space (obtained from the slice intersection with the proxy), map it back to the original object space $p$ using the inverse displacement map [S1, unofficial].
5.  **Evaluate Density:** Evaluate the original object function $O(p)$ at the mapped coordinate $p$ to retrieve the density/color attribute [S1, unofficial].
6.  **Composite:** Accumulate color and opacity along the ray using standard volume rendering integration [S1, unofficial].

**Formulas:**
The forward displacement mapping is defined as:
$$ P_0(\lambda) = P(\lambda) + D_B(\lambda) $$
where $\lambda \in \Lambda$, $P$ maps reference to point in $E^3$, and $D_B$ is the displacement vector function [S1, unofficial].

The rendering uses the inverse displacement mapping:
$$ p = p_0 + D(p_0) $$
where $p$ is the point in original space, $p_0$ is the point in displaced space, and $D$ is the inverse displacement function (where $D = -D_B$ in vector terms, or specifically the function $D$ such that $P(\lambda) = P_0(\lambda) + D(\lambda)$) [S1, unofficial].

**Parameters:**
*   **Reference Space $\Lambda$:** $E^3$ [S1, unofficial].
*   **Displacement Texture Precision:** 8-bit or 16-bit point numbers, normalized [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Normal Estimation:** Conventional normal estimation causes lighting artifacts at breaking points in discontinuous displacement maps. Correct normal calculation is required, likely involving analytical derivatives of the displacement function or finite differences in the original space [S1, unofficial].
*   **Discontinuities:** The method handles discontinuous maps (e.g., cuts) where traditional mesh-based approaches would require costly re-meshing [S1, unofficial].

**Pseudocode:**
```python
# Assume standard volume rendering ray casting loop
# Ray: origin r_o, direction r_d
# Volume: vol_texture (original density O_j)
# Displacement: disp_texture (vector field D_k)
# Proxy: bounding_box (defines domain of displaced space)

def render_displaced_volume(ray_origin, ray_direction):
    # 1. Intersect ray with proxy bounding box to get range in displaced space
    t_min, t_max = intersect_bounding_box(ray_origin, ray_direction)
    
    # 2. Sample along the ray in the displaced space (p_0)
    # Standard volume rendering integration loop
    accumulated_color = (0, 0, 0, 0)
    accumulated_opacity = 0.0
    
    t = t_min
    while t < t_max:
        # Point in displaced space
        p_0 = ray_origin + t * ray_direction
        
        # 3. Map back to original object space (p)
        # Retrieve displacement vector D(p_0) from texture
        # Note: D is the inverse displacement function such that p = p_0 + D(p_0)
        disp_vec = sample_3d_texture(disp_texture, p_0)
        p = p_0 + disp_vec
        
        # 4. Evaluate original object density at p
        density = sample_3d_texture(vol_texture, p)
        
        # 5. Standard volume rendering step (e.g., front-to-back compositing)
        # alpha = 1.0 - exp(-density * step_size)
        # color_contribution = density * alpha
        # accumulated_color += color_contribution * (1.0 - accumulated_opacity)
        # accumulated_opacity += alpha * (1.0 - accumulated_opacity)
        
        t += step_size
        
    return accumulated_color
```

## Subtopics

### [Displacement General Setup](11527-displacement-general-setup.md)
Displacement General Setup is a rendering technique that adds geometric detail to volumetric simulations by sampling a texture map and shifting fluid or surface points in a direction determined by that texture. It solves the limitation of static volumetric representations by allowing interactive deformation without mesh re-tessellation, building on the principles of [Displacement Mapping for Volume Rendering](10659-displacement-mapping-for-volume-rendering.md). Unlike standard scalar displacement which often produces symmetrical deformations, this setup supports vector-based and surface-normal-based shifts, enabling complex, asymmetric geometries such as waves with convex backs and concave fronts.

## Operating characteristics
*   **Time Complexity:** Depends on the cost of 3D texture lookups for both the volume and displacement fields, plus the arithmetic for coordinate transformation. No mesh traversal or re-tessellation is required.
*   **Memory Complexity:** Requires storage for the original volume texture and the displacement vector texture [S1, unofficial].
*   **Strengths:** Handles discontinuous and unorthogonal displacements (cuts, peeling) without mesh re-tessellation; supports interactive deformation; works with implicit surfaces or scalar volumes [S1, unofficial].
*   **Limitations:** Requires correct normal calculation to avoid lighting artifacts at discontinuities [S1, unofficial]. Performance depends on the resolution of the displacement texture.
*   **When to use:** When rendering volumetric objects that undergo complex, discontinuous deformations (e.g., cutting, peeling) and explicit surface meshes are not available or desirable [S1, unofficial].

## Background
Displacement mapping is commonly used for adding surface details to an object. This paper outlines a generalized notion of displacement mapping, which allows for unconventional features such as unorthogonal and discontinuous displacement [S1, unofficial]. By lifting the restriction on the geometric properties of the displacement, many different special effects including peeling, cutting and deforming an object can be generated [S1, unofficial]. These types of operations are useful for volumetric objects, where the interior of objects is represented [S1, unofficial]. To address the technical difficulties associated with this generalization, inverse displacement maps in 3D vector space were employed, and a collection of techniques including sampling displaced objects through a proxy geometry and computing displaced surface normals was devised [S1, unofficial].
