# Smooth Domain Warp for Volumetric Clouds


## Overview
Smooth Domain Warp eliminates repetitive tiling artifacts in volumetric cloud fields by applying a smooth, periodic domain warp to every noise read, ensuring the cloud field does not repeat at the original noise periods [S1, unofficial]. It sets itself apart from sibling techniques by using a fixed, large-period sine-based warp carried by wind, rather than procedural noise-driven warping, which can introduce unwanted shear [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** 3D voxel coordinates $(x, y, z)$, wind velocity vector $\vec{w}$, warp period in voxels $P_{vox}$, warp amplitude $A_{amp}$, and noise sampling functions for shape, weather, and detail layers.
*   **Output:** Warped 3D coordinates $(x', y', z')$ used for subsequent noise evaluation.

**Data Structures**
*   `warp_period_vox`: Integer, typically $2^{23}$ (8,388,608) [S1, unofficial].
*   `WARP_AMPLITUDE`: Float, typically 0.015 (periods) [S1, unofficial].
*   `wind_offset`: 3D vector, updated per frame or per tile, wrapping at `warp_period_vox` [S1, unofficial].

**Parameters**
*   $P_{vox} = 2^{23}$ voxels [S1, unofficial]. At 5 cm voxel size, this equals 419 km [S1, unofficial].
*   $A_{amp} = 0.015$ periods [S1, unofficial]. This results in a maximum stretch of 0.42 (typical ~0.2) [S1, unofficial].
*   Period Hierarchy: Weather period $\le P_{vox} / 4$, Shape period $\le$ Weather period, Detail period $\le$ Shape period [S1, unofficial].

**Steps**
1.  **Initialize Warp Offset:** Calculate the wind displacement for the current frame. Let $\vec{w}_{frame}$ be the wind vector scaled by time step. Update `wind_offset` by adding $\vec{w}_{frame}$ and wrapping each component modulo $P_{vox}$ [S1, unofficial].
2.  **Calculate Base Position:** Let $\vec{p}_{base} = \vec{p}_{input} + \vec{w}_{offset}$ [S1, unofficial].
3.  **Compute Warp Vector:** For each axis $i \in \{x, y, z\}$, compute two sine waves:
    $$
    w_i = A_{amp} \cdot P_{vox} \cdot \left( \sin\left(2\pi \frac{p_{base, i}}{P_{vox}} \cdot N_1\right) + \sin\left(2\pi \frac{p_{base, i}}{P_{vox}} \cdot N_2\right) \right)
    $$
    Where $N_1$ and $N_2$ are integers ensuring whole cycles per period (e.g., 1 and 2, or other distinct integers). The sources specify "two sine waves per axis" with "whole cycles per a $2^{23}$-voxel period" [S1, unofficial]. The exact integers $N_1, N_2$ are not specified beyond "whole cycles" [G: Assuming $N_1=1, N_2=2$ for fundamental and first harmonic, or similar low-frequency integers to ensure smoothness].
4.  **Apply Warp:** The final warped coordinate is:
    $$
    \vec{p}_{warped} = \vec{p}_{base} + \vec{w}
    $$
    Where $\vec{w} = (w_x, w_y, w_z)$ [S1, unofficial].
5.  **Noise Sampling:** Use $\vec{p}_{warped}$ to sample shape, weather, and detail noise fields [S1, unofficial].
6.  **Layer Skipping:** For light march and shadow pass points outside the cloud layer, skip the weather noise and its associated warp calculation [S1, unofficial].
7.  **Reuse:** The light march reuses the start point's warp value for subsequent steps, similar to how it reuses the weather noise [S1, unofficial].

**Pitfalls**
*   **Shearing:** Using a warp read from the shape noise itself at a long period breaks repetition but shears clouds into streaks due to fine octaves (gradients ~1.5) [S1, unofficial].
*   **Clamping:** If the period hierarchy is violated (e.g., weather period > warp/4), at tiny voxel sizes, the frame's longest period would clamp all periods to the same value [S1, unofficial].
*   **Residual Repetition:** The field still repeats every warp period ($2^{23}$ voxels / 419 km at 5 cm) [S1, unofficial]. This is not fixed in this method [S1, unofficial].

**Pseudocode**
```python
import math

def compute_smooth_domain_warp(p_input, wind_offset, warp_period_vox, warp_amplitude):
    """
    Computes the smooth domain warp for volumetric clouds.
    
    Args:
        p_input (tuple): Input 3D voxel coordinates (x, y, z).
        wind_offset (tuple): Current wind offset vector (x, y, z), wrapped at warp_period_vox.
        warp_period_vox (int): Period of the warp in voxels (e.g., 2**23).
        warp_amplitude (float): Amplitude of the warp waves in periods (e.g., 0.015).
        
    Returns:
        tuple: Warped 3D coordinates (x', y', z').
    """
    # Step 1: Base position with wind offset
    p_base_x = p_input[0] + wind_offset[0]
    p_base_y = p_input[1] + wind_offset[1]
    p_base_z = p_input[2] + wind_offset[2]
    
    # Step 2: Compute warp vector
    # Two sine waves per axis. N1 and N2 are integers for whole cycles.
    # Using N1=1, N2=2 as a common implementation for "two sine waves" with whole cycles.
    N1 = 1
    N2 = 2
    
    # Calculate warp for each axis
    def get_warp_component(p_base, period, amplitude):
        # Amplitude is in periods, so multiply by period to get voxel units
        amp_voxels = amplitude * period
        term1 = math.sin(2 * math.pi * p_base / period * N1)
        term2 = math.sin(2 * math.pi * p_base / period * N2)
        return amp_voxels * (term1 + term2)
    
    w_x = get_warp_component(p_base_x, warp_period_vox, warp_amplitude)
    w_y = get_warp_component(p_base_y, warp_period_vox, warp_amplitude)
    w_z = get_warp_component(p_base_z, warp_period_vox, warp_amplitude)
    
    # Step 3: Apply warp
    p_warped_x = p_base_x + w_x
    p_warped_y = p_base_y + w_y
    p_warped_z = p_base_z + w_z
    
    return (p_warped_x, p_warped_y, p_warped_z)
```

## Operating characteristics
*   **Time Complexity:** The warp calculation involves a constant number of trigonometric operations per voxel, so it is $O(1)$ per sample.
*   **Memory Complexity:** $O(1)$ additional memory per sample for the warp vector.
*   **Measured Performance:** At 1280x720 resolution, the steady phase GPU cost increases by +0.17 ms (p50) for atmosphere + clouds above the layer and on the ground [S1, unofficial]. This cost was measured before passes skipped weather outside the layer, so the final cost is at most this [S1, unofficial].
*   **Full Amplitude Cost:** At full amplitude, the cost increase is +0.6 to +1.0 ms due to increased cloud cover (21% to 29–42%) caused by the warp landing on different parts of the weather noise [S1, unofficial].
*   **Strengths:** Effectively breaks repetition at shape and weather scales (42.1% pixel difference at shape period shift, 34.3% at weather period shift, targeting ~42% for unrelated fields) [S1, unofficial].
*   **Limitations:** Residual repetition at the warp period (419 km at 5 cm) [S1, unofficial]. Increased GPU cost at full amplitude due to higher cloud cover [S1, unofficial].

## Background
*   **Origin:** Introduced in the `opti-voxel` project by aobayama-gaming, specifically in pull request #148 [S1, unofficial].
*   **History:** The technique was developed to address the issue where volumetric clouds repeated exactly every weather period (26.2 km) and shapes every shape period (6.55 km) on a flat world at 5 cm voxel size [S1, unofficial].
*   **Usage:** Used in the `opti-voxel` renderer for procedural volumetric cloud rendering [S1, unofficial].
