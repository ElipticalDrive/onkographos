# Block-based Volume Rendering

Also called: Independent block rendering, Resource-independent volume rendering

## Overview
Block-based volume rendering is a strategy for rendering large volumetric scenes by dividing the space into independent blocks, rendering each block separately, and then blending the results. It solves the problem of resource isolation in distributed or web-based rendering environments where multiple shaders cannot communicate or share intermediate state [S1]. Unlike methods that integrate all samples globally before deferred processing (e.g., MERF), this method uses segmented integration followed by inter-block blending, ensuring seamless boundaries and correct occlusion without requiring global synchronization [S1].

## How it works
The method decomposes a ray traversal into two phases: intra-block rendering and inter-block compositing. It assumes a hierarchical representation of the scene with $L$ Levels of Detail (LODs), where blocks are merged between consecutive LODs [S1].

**Inputs:**
*   Ray $r(t)$ defined by origin $\mathbf{o}$ and direction $\mathbf{d}$.
*   Scene representation: A set of $M$ blocks intersected by the ray. Each block $k$ contains $N_k$ sample points.
*   Per-sample data for block $k$: diffuse color $\boldsymbol{c}_i^k$, specular feature $\boldsymbol{f}_i^k$, and opacity $\alpha_i^k$ for $i=1 \dots N_k$. These are typically retrieved from baked sparse voxel or triplane textures via an attribute query function $f^{k,l}$ [S1].
*   Optional: A tiny deferred MLP $\Phi^{k,l}$ for view-dependent effects and a proposal MLP $\psi^{k,l}$ for sampling [S1].

**Outputs:**
*   Final ray color $\boldsymbol{C}(r)$, composed of diffuse color $\boldsymbol{C}_d(r)$ and specular feature $\boldsymbol{F}(r)$.

**Data Structures:**
*   **Block:** A spatial partition of the volume. In hierarchical LODs, block size increases with LOD level $l$ (e.g., $2\times2$ blocks merged into one at higher LODs) [S1].
*   **Sample Point:** Contains scalar opacity $\alpha$ and vector attributes (color/feature).

**Algorithm Steps:**

1.  **Intra-block Rendering:** For each block $k$ intersected by the ray, perform standard front-to-back volume rendering over its $N_k$ samples to compute the block's aggregate properties.
    *   Calculate block diffuse color $\boldsymbol{C}_d^k$:
        $$ \boldsymbol{C}_d^k = \sum_{i=1}^{N_k} \left( \prod_{j=1}^{i-1} (1 - \alpha_j^k) \right) \alpha_i^k \boldsymbol{c}_i^k $$
    *   Calculate block specular feature $\boldsymbol{F}^k$:
        $$ \boldsymbol{F}^k = \sum_{i=1}^{N_k} \left( \prod_{j=1}^{i-1} (1 - \alpha_j^k) \right) \alpha_i^k \boldsymbol{f}_i^k $$
    *   Calculate block opacity $\alpha^k$:
        $$ \alpha^k = \sum_{i=1}^{N_k} \left( \prod_{j=1}^{i-1} (1 - \alpha_j^k) \right) \alpha_i^k $$
    *   Note: The block opacity is equivalent to the product of individual transmittances:
        $$ 1 - \alpha^k = \prod_{i=1}^{N_k} (1 - \alpha_i^k) $$
        [S1]

2.  **Inter-block Compositing:** Depth-sort the $M$ blocks along the ray from near to far. Blend the results of the blocks using the standard volume rendering equation, treating each block's aggregate opacity $\alpha^k$ as a single "super-sample".
    *   Calculate final diffuse color:
        $$ \boldsymbol{C}_d(r) = \sum_{k=1}^{M} \left( \prod_{j=1}^{k-1} (1 - \alpha^j) \right) \boldsymbol{C}_d^k $$
    *   Calculate final specular feature:
        $$ \boldsymbol{F}(r) = \sum_{k=1}^{M} \left( \prod_{j=1}^{k-1} (1 - \alpha^j) \right) \boldsymbol{F}^k $$
    *   The final color $\boldsymbol{C}(r)$ combines these components, potentially applying the deferred MLP $\Phi$ if view-dependent effects are required [S1].

**Pseudocode:**

```python
def block_based_volume_rendering(ray, blocks):
    """
    ray: object with origin, direction, and intersection range [t_near, t_far]
    blocks: list of Block objects intersected by the ray, sorted by distance from camera
    """
    # Initialize accumulators for the final ray
    acc_diffuse = [0.0, 0.0, 0.0]
    acc_specular = [0.0, 0.0, 0.0]
    acc_opacity = 0.0
    
    # Transmittance from previous blocks (initially 1.0, meaning no occlusion yet)
    transmittance = 1.0
    
    for block in blocks:
        # Step 1: Intra-block rendering
        block_diffuse = [0.0, 0.0, 0.0]
        block_specular = [0.0, 0.0, 0.0]
        block_opacity = 0.0
        block_transmittance = 1.0
        
        # Iterate through samples within this block
        for sample in block.samples:
            alpha = sample.opacity
            c_diffuse = sample.diffuse_color
            f_specular = sample.specular_feature
            
            # Contribution of this sample to the block's aggregates
            contribution = block_transmittance * alpha
            
            block_diffuse += contribution * c_diffuse
            block_specular += contribution * f_specular
            block_opacity += contribution
            
            # Update block transmittance for next sample
            block_transmittance *= (1.0 - alpha)
            
        # Step 2: Inter-block blending
        # The block's result is blended into the ray using the ray's current transmittance
        ray_contribution = transmittance * block_opacity
        
        acc_diffuse += ray_contribution * block_diffuse
        acc_specular += ray_contribution * block_specular
        acc_opacity += ray_contribution
        
        # Update ray transmittance for next block
        transmittance *= (1.0 - block_opacity)
        
    # Combine diffuse and specular components for final color
    # (Assuming simple addition or weighted sum based on specific shading model)
    final_color = acc_diffuse + acc_specular
    
    return final_color, acc_opacity
```

**Edge Cases and Pitfalls:**
*   **Ordering:** Blocks must be strictly depth-sorted along the ray. Incorrect sorting leads to incorrect occlusion and visual artifacts [S1].
*   **Lambertian Assumption:** The equivalence to traditional volume rendering (where segmented integration equals global integration) holds strictly under Lambertian surface conditions where specular color is zero. If view-dependent specular effects are present, the deferred MLP $\Phi$ is required to maintain correctness [S1].
*   **Training/Rendering Consistency:** To avoid discrepancies between training and inference, the same block-based pipeline must be used during training as during rendering [S1].

## Subtopics

### Block-based Volume Rendering with Inter-block Alpha Blending
A specific implementation variant that emphasizes the blending mechanism across block boundaries. It ensures seamless boundaries and correct occlusion at inter-block edges, avoiding seams caused by simple averaging or incorrect depth sorting. It differs from MERF, which integrates all sample points together followed by deferred rendering, by using segmented integration (block-by-block) followed by inter-block blending. Without deferred rendering, this variant is entirely equivalent to traditional volume rendering [S1]. It supports hierarchical LODs where $L$ is the total number of levels, and blocks are merged between consecutive LODs [S1].

## Operating characteristics
*   **Resource Independence:** The primary advantage is that each block can be rendered independently by separate shaders or processes that cannot communicate, making it suitable for web-based or distributed rendering environments [S1].
*   **Complexity:** The computational complexity is linear with respect to the total number of samples $N$ across all blocks, similar to standard volume rendering. The overhead of block aggregation and blending is minimal [S1].
*   **Memory:** Requires storing per-block aggregate data or re-sampling per-block data. In hierarchical LODs, memory usage scales with the number of blocks and the resolution of baked textures (sparse voxel/triplane) [S1].
*   **Accuracy:** Maintains 3D consistency and correct occlusion. Under Lambertian conditions, it is mathematically equivalent to global volume rendering [S1].

## Background
The method was introduced in the context of "City-on-Web," a system for real-time neural rendering of large-scale scenes on the web [S1]. It addresses the limitations of previous neural rendering methods (like MERF) that required global integration and deferred rendering, which are difficult to implement in resource-constrained or isolated shader environments. The approach proves that segmented integration followed by alpha blending is equivalent to traditional volume rendering under Lambertian conditions, allowing for efficient, parallelizable rendering pipelines [S1].
