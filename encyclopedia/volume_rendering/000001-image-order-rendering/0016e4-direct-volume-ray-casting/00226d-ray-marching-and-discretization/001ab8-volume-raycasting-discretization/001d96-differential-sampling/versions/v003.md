# Differential Sampling

Also called: Differential construction of T

## Overview
Differential sampling is a ray discretization strategy for volume raycasting that adapts the sampling density along a ray based on the view-dependent frequency of the image plane, ensuring the sampling rate respects the Nyquist limit [S1]. Unlike uniform sampling methods, it uses a quadratic sampling function $T(x)$ derived from ray differentials, allowing variable step sizes that are finer near the viewpoint and coarser further away, which prevents aliasing for features close to the camera [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera origin $\vec{o}$, central view direction $\vec{w}$, right vector $\vec{u}$, up vector $\vec{v}$, image plane resolution $(\Delta x, \Delta y)$, scaling factor $sk$, macrocell entry distance $T_{\text{enter}}$, and exit distance $D_{\text{exit}}$ [S1].
*   **Outputs:** A sequence of sample positions $\vec{P}_i$ along the ray and their corresponding transfer function evaluations [S1].

**Data Structures:**
The method maintains the following state variables per ray during iteration:
*   $\vec{P}$: Current 3D sample position.
*   $\vec{D}$: Unitized ray direction vector.
*   $x$: Current image-space coordinate index (integer).
*   $\Delta t$: Current step size (derivative of $T$ with respect to $x$).
*   $T$: Cumulative distance along the ray corresponding to image coordinate $x$.
*   `max_t_sampled`: Greatest $t$ value already sampled [G].
Exact memory layouts and bit packing are not given in the sources. [S1]

**Numbered Steps:**
1.  Generate the ray direction vector $\vec{d}$ for pixel coordinates $(x, y)$ using the pinhole camera model [S1].
2.  Unitize the ray direction to obtain $\vec{D}$ [S1].
3.  Compute the partial derivative of $\vec{D}$ with respect to the image-space coordinate $x$ [S1].
4.  Calculate the scalar coefficients $k$, $a$, and $b$ based on the pixel footprint and differential magnitude [S1].
5.  Initialize the sampling state at $x=0$ [S1].
6.  Iterate along the ray: sample the volume, handle macrocell entry boundaries, and increment the position and step size [S1].

**Formulas:**
*   Ray generation: $\vec{d}(x, y) = \vec{w} + x\vec{u} + y\vec{v}$ [S1].
*   Ray unitization: $\vec{D}(x, y) = \vec{d} / \sqrt{\vec{d} \cdot \vec{d}}$ [S1].
*   Ray differential vector: $\frac{\partial \vec{D}}{\partial x} = \frac{(\vec{d} \cdot \vec{d})\vec{u} - (\vec{d} \cdot \vec{u})\vec{d}}{(\vec{d} \cdot \vec{d})^{3/2}}$ [S1].
*   Step size multiplier: $k = sk |\vec{u}\Delta x + \vec{v}\Delta y|$ [S1].
*   Quadratic coefficients: $a = k \left| \frac{\partial \vec{D}}{\partial x} \right|$, $b = k$ [S1].
*   Sampling function: $T(x) = \frac{a}{2}x^2 + bx$ [S1].
*   Step size derivative: $\frac{\partial T}{\partial x} = ax + b$ [S1].
*   Position update: $\vec{P}_{n+1} = \vec{P}_n + \Delta t_n \vec{D}$ [S1].
*   Step size update: $\Delta t_{n+1} = \Delta t_n + a$ [S1].
*   Macrocell entry coordinate: $x_{\text{enter}} = \frac{-b + \sqrt{b^2 + 2aT_{\text{enter}}}}{a}$ [S1].

**Parameters:**
*   $sk$: Scaling factor for $k$. Typical value: $4$ [S1]. Theoretical Nyquist limit requires $sk < 0.5$, but this is excessive in practice [S1].
*   $k_0$: Constant combining $k$ and geometric factors. If $k$ is arbitrarily chosen, $k_0 = k$ [S1].

**Pseudocode:**
```python
# Precomputation per ray
d = w + x*u + y*v
D = d / sqrt(dot(d, d))
D_dx = ((dot(d, d) * u) - (dot(d, u) * d)) / (dot(d, d) ** 1.5)
mag_D_dx = sqrt(dot(D_dx, D_dx))
k = sk * sqrt(dot(u*dx + v*dy, u*dx + v*dy))
a = k * mag_D_dx
b = k

# Initialization
x = 0
dt = b
P = o
T = 0.0
max_t_sampled = 0.0  # [G] Guard for macrocell entry duplicates

while P is inside volume and T < D_exit:
    # Sample volume data at P [G]
    
    # Handle macrocell entry boundaries
    if T_enter > max_t_sampled:
        x_enter = (-b + sqrt(b**2 + 2*a*T_enter)) / a
        x_new = floor(x_enter)
        dt = b + a * x_new
        T = 0.5 * a * x_new**2 + b * x_new
        P = o + T * D
        max_t_sampled = max(max_t_sampled, T)

    # Increment per source equations
    P = P + dt * D
    dt = dt + a
    x = x + 1
    T = 0.5 * a * x**2 + b * x
```

**Edge Cases and Pitfalls:**
*   **Duplicate Samples at Macrocell Boundaries:** When entering a new macrocell, the sampling sequence might overlap with previously visited space. To avoid duplicate samples, store the greatest $t$ already sampled and use the maximum of that value and $T_{\text{enter}}$ [S1].
*   **Nyquist Limit:** Using $sk < 0.5$ satisfies the Nyquist limit theoretically but is computationally expensive. $sk=4$ is a practical default [S1].

## Operating characteristics
*   **Implementation Cost:** Incrementing the position from one sample to the next consists only of an extra vector multiplication and addition, on top of the vector addition for uniform sampling [S1].
*   **Strengths:** Respects the Nyquist frequency of the image plane, reducing aliasing artifacts for structures close to the viewpoint [S1]. Avoids adaptive branching, maintaining thread coherence on GPUs [S1].
*   **Limitations:** Requires computation of ray differentials ($\partial \vec{D} / \partial x$) per pixel. Purely adaptive methods based on local gradients perform poorly on GPUs due to poor thread coherence, though per-macrocell adaptation is supported [S1].
*   **When to Use:** High-quality volume rendering where aliasing is a concern, particularly for large volumes viewed from varying distances [S1].
*   **When Not to Use:** Real-time applications with strict performance constraints where uniform sampling is sufficient, or when the volume lacks high-frequency features near the camera [S1].

## Background
Differential sampling was introduced in the context of volume ray casting with peak finding, building on the concept of ray differentials originally formulated by Igehy [S1]. The method addresses the issue that regular sampling in world-space undersamples features close to the viewpoint relative to those further away, due to the convolution of the volume rendering integral during the transformation from world-space to image-space [S1]. It was implemented in a GLSL fragment shader framework for OpenGL [S1].
