# Hybrid Volume and Isosurface Rendering with Partial Pre-Integration

Also called: PT with partial preintegration, PTINT

## Overview
Hybrid Volume and Isosurface Rendering with Partial Pre-Integration (PTINT) is a GPU-accelerated cell projection method that combines direct volume rendering with multiple isosurfaces to achieve interactive frame rates [S1]. It builds on [Partial Pre-Integration](1148-partial-pre-integration.md) by eliminating bus transfer overhead and allowing the simultaneous rendering of opaque or semi-transparent isosurfaces within the same fragment shader passes [S1]. Unlike pure ray casting, PTINT uses a tetrahedral discretization that requires no cell connectivity, offering significantly lower memory usage than hardware-accelerated ray casting (HARC) variants [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field defined on a set of $n$ vertices and $m$ tetrahedra.
*   **Output:** A 2D image with combined volume shading and isosurface geometry.

**Data Structures and Memory Layout:**
The method requires no explicit cell connectivity, storing data in textures to optimize GPU access [S1].
*   **Texture Element Size:** 16 bytes per element [S1].
*   **Total Storage:** $16(2n + m)$ bytes for $n$ vertices and $m$ tetrahedra [S1].
*   **Storage per Tetrahedron:** Assuming an average of 4 tetrahedra per vertex, the storage is 24 bytes per tetrahedron [S1].
*   **Memory Usage:** Approximately 24 MB for one million cells (20 MB without illumination data) [S1].

**Operational Variants:**
The algorithm supports three operational variants [S1]:
1.  **Basic Average Scalar Method:** Standard volume rendering without pre-integration [S1].
2.  **Partial Pre-Integration Technique:** Uses the $\psi$ table for improved integration accuracy [S1].
3.  **Partial Pre-Integration with Isosurface Rendering:** A hybrid mode combining direct volume rendering with multiple isosurfaces to achieve interactive frame rates by eliminating bus transfer overhead [S1].

**Algorithm Steps:**
The rendering is performed in two main passes, with all isosurface computation handled in the second fragment shader to avoid additional rendering passes [S1].

1.  **First Pass (Volume/Pre-integration):**
    *   Render the tetrahedra to intermediate framebuffers 2 and 3 [S1].
    *   Compute gradient vectors $g_f$ and $g_b$ if lighting or isosurfaces are enabled [S1].
    *   If isosurfaces/lighting are *not* desired, skip gradient computations and skip rendering to framebuffers 2 and 3 [S1].

2.  **Intermediate CPU Pass:**
    *   Update gradient arrays if they were computed in the first pass [S1].
    *   If gradients were skipped, this step is omitted [S1].

3.  **Second Pass (Hybrid Rendering):**
    *   Interpolate gradients and compute normals [S1].
    *   If gradients were skipped, skip interpolation and normal computation [S1].
    *   Perform isosurface detection and shading in the second fragment shader [S1].
    *   Apply Phong shading model with controllable diffuse, specular, and ambient coefficients for isosurfaces [S1].
    *   Render isosurfaces as fully opaque or semi-transparent fragments [S1].

**Optimizations and Pitfalls:**
*   **Early Tetrahedral Discard:** An early discard test is applied to improve performance by skipping tetrahedra that do not contribute to the final image [S1].
*   **Small Pixel Area Degradation:** On datasets like "Liquid Oxygen Post," PTINT may lose performance compared to ray casting at viewpoints where the model occupies a small pixel area, as cell projection approaches are unaffected by pixel area size [S1].

**Pseudocode:**
```python
def render_ptint(vertices, tetrahedra, isosurface_thresholds, enable_lighting, enable_isosurfaces):
    # 1. First Pass: Volume and Gradient Computation
    if enable_lighting or enable_isosurfaces:
        # Compute forward and backward gradients g_f and g_b
        # [G] Standard gradient estimation per tetrahedron
        gradients = estimate_gradients(vertices, tetrahedra)
        # Render volume data to intermediate framebuffers 2 and 3
        rasterize_volume(vertices, tetrahedra, gradients)
    else:
        # Skip gradient computation and framebuffer 2/3 rendering
        rasterize_volume(vertices, tetrahedra, None)

    # 2. Intermediate CPU Pass
    if enable_lighting or enable_isosurfaces:
        # Update gradient arrays on CPU
        # [G] Synchronize gradient data between GPU passes
        sync_gradients(gradients)
    else:
        # Skip updating gradient arrays
        pass

    # 3. Second Pass: Hybrid Isosurface and Volume Shading
    if enable_lighting or enable_isosurfaces:
        # Interpolate gradients and compute normals
        # [G] Barycentric interpolation of gradients to fragment positions
        normals = interpolate_gradients(vertices, tetrahedra, gradients)
    else:
        # Skip interpolation and normal computation
        normals = None

    # Apply early tetrahedral discard test
    # [G] Cull tetrahedra outside view frustum or with zero screen projection
    visible_tets = cull_tetrahedra(tetrahedra)

    # Render final image
    for tet in visible_tets:
        if enable_isosurfaces:
            for threshold in isosurface_thresholds:
                # [G] Find intersection of scalar field with threshold inside tetrahedron
                if find_isosurface_intersection(tet, threshold):
                    # Phong shading for isosurface with controllable coefficients
                    # [G] Standard Phong model: ambient + diffuse + specular
                    color = apply_phong_shading(tet, normals, diffuse=0.8, specular=0.5, ambient=0.2)
                    output_fragment(color, opaque=True) # Or semi-transparent

        # Render volume contribution
        # [G] Accumulate color and opacity using partial pre-integration
        volume_color = accumulate_volume_shading(tet, normals)
        output_fragment(volume_color, alpha=0.5) # Blending with isosurface
```

## Operating characteristics
*   **Time Complexity:** Not explicitly defined in sources, but achieves interactive frame rates on tested hardware [S1].
*   **Memory Complexity:** $O(n + m)$ with a constant factor of 16 bytes per vertex/tet element. Total memory is $16(2n + m)$ bytes [S1].
*   **Measured Performance:**
    *   **Hardware:** Intel Pentium IV 3.6 GHz, 2 GB RAM, nVidia GeForce 6800 256 MB, PCI Express 16x [S1].
    *   **Viewport:** $512 \times 512$ pixels, constantly rotating model [S1].
    *   **Blunt Fin Dataset:** PTINT outperforms all compared algorithms (GATOR, VICP, VICP Balanced, HARC, HARC INT, HAVIS, HAVS) [S1].
    *   **Oxygen Post Dataset:** PTINT loses to ray casting algorithms at certain viewpoints where the model has a small pixel area [S1].
*   **Strengths:**
    *   Low memory footprint (24 bytes/tet vs. 96-144 bytes/tet for HARC variants) [S1].
    *   No cell connectivity required, freeing GPU memory [S1].
    *   Interactive frame rates via elimination of bus transfer overhead [S1].
    *   Hybrid visualization allows underlying volumes to be hidden by opaque isosurfaces or enhanced by semi-transparent layers [S1].
*   **Limitations:**
    *   Performance degradation on small pixel area views compared to ray casting [S1].
    *   Considerable performance loss if Phong shading is used for isosurfaces due to gradient computation overhead [S1].
*   **When to Use:** When interactive frame rates are required for large tetrahedral datasets and hybrid volume/isosurface visualization is desired, particularly on hardware with limited GPU memory [S1].
*   **When Not to Use:** When rendering datasets with small pixel area coverage where ray casting might be more efficient [S1].

## Background
*   **Origin:** Proposed by R. Marroquim et al. in the paper "Volume and Isosurface Rendering with GPU-Accelerated Cell Projection" (CGF 2008) [S1].
*   **Development:** The method extends previous cell projection techniques (GATOR, VICP) and hardware-accelerated ray casting (HARC) by integrating partial pre-integration and isosurface rendering into a unified GPU pipeline [S1].
*   **Usage:** Tested on datasets including Blunt Fin, Combustion Chamber, Liquid Oxygen Post, Super Phoenix, Fuel Injection, and Electron Distribution Probability [S1]. Implemented in C++ with OpenGL 2.0 and GLSL under Linux [S1].
