# Volume Raycasting Discretization

Also called: CPU Ray Casting (Front-to-Back), Discrete Volume Rendering Integral, Fixed-step Raycasting, Front-to-back Ray Casting, Ray Casting Volume Rendering, Standard Ray Casting, Volume ray marching

## Overview
Volume Raycasting Discretization is a direct volume rendering technique that approximates the volume rendering integral by sampling a 3D scalar field at fixed intervals along rays cast from the camera [S2, S3]. It solves the problem of mapping volumetric data to a 2D image plane by performing front-to-back alpha compositing of sampled color and opacity values [S1, S2]. It is distinguished from its siblings by its explicit discretization of the continuous rendering integral into a fixed-step summation, typically implemented on the CPU for simplicity or as a baseline [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume texture (scalar field), camera parameters (origin, direction, screen dimensions), a transfer function mapping scalar values to color and opacity, a fixed step size $\Delta x$, and an early termination threshold $\alpha_{thresh}$ (typically 0.95 to 0.99) [S1, S2, S3].
*   **Output:** A 2D image where each pixel contains the accumulated color and opacity [S1, S2].

**Data Structures:**
*   **Volume Data:** A 1D array of unsigned shorts (or similar scalar type) representing the 3D grid. The layout is row-major: for dimensions $dim.x \times dim.y \times dim.z$, the index for a voxel at $(x, y, z)$ is $x \cdot (dim.y \cdot dim.z) + y \cdot dim.z + z$ [S1].
*   **Ray Structure:** Defined by an origin point $\bar{O}$ and a direction vector $\bar{D}$ [S2].
*   **Accumulators:** Per-pixel variables for accumulated color $C'$ (vector) and accumulated opacity $\alpha'$ (scalar) [S2].

**Numbered Steps:**
1.  **Initialization:** Initialize the output image with a black background (color $\{0,0,0\}$, opacity 0) [S1, S2].
2.  **Ray Casting Loop:** Iterate over each pixel $(i, j)$ on the image plane [S1].
3.  **Ray Generation:** Compute the ray origin and direction for the current pixel [S1, S2].
4.  **Ray Initialization:** Compute the ray's entry and exit parameters ($t_{start}$, $t_{end}$) relative to the volume bounding box. Set accumulated color $C' = \{0,0,0\}$ and accumulated opacity $\alpha' = 0$ [G].
5.  **Sampling Loop:** While $\alpha' < \alpha_{thresh}$ and $t \le t_{end}$:
    a.  **Sample Volume:** Evaluate the scalar value $d$ at the current ray position $\bar{P} = \bar{O} + t \cdot \bar{D}$ using trilinear interpolation [S1, S3].
    b.  **Transfer Function:** Map the scalar value $d$ to a color $C_{sample}$ and opacity $\alpha_{sample}$ using the transfer function [S1, S2].
    c.  **Compositing:** Update the accumulated color and opacity using the front-to-back alpha compositing equations [S2, S3]:
        $$ C'_{new} = C'_{old} + (1 - \alpha'_{old}) \cdot \alpha_{sample} \cdot C_{sample} $$
        $$ \alpha'_{new} = \alpha'_{old} + (1 - \alpha'_{old}) \cdot \alpha_{sample} $$
    d.  **Advance Ray:** Increment $t$ by the step size $\Delta x$ [S2].
6.  **Final Compositing:** If the ray exits the volume before reaching the threshold, the final color is the accumulated color $C'$ [S2].
7.  **Gamma Correction:** Apply gamma correction (typically $\gamma = 2.2$) to the final color values [S2].
    $$ C_{final} = (C')^{1/2.2} $$

**Pseudocode:**
```python
def volume_raycasting_discretization(volume_data, volume_dims, camera, transfer_function, step_size=0.001, threshold=0.99):
    """
    Renders a volume using fixed-step raycasting with front-to-back compositing.
    """
    h, w = camera.screen_height, camera.screen_width
    image = [[vec3(0.0) for _ in range(w)] for _ in range(h)]
    dim_x, dim_y, dim_z = volume_dims
    stride_y = dim_z
    stride_x = dim_y * dim_z

    # Standard trilinear interpolation [G]
    def trilinear_interpolation(data, dims, x, y, z):
        x = max(0.0, min(float(dims[0] - 1), x))
        y = max(0.0, min(float(dims[1] - 1), y))
        z = max(0.0, min(float(dims[2] - 1), z))
        x0, y0, z0 = int(x), int(y), int(z)
        x1, y1, z1 = min(x0 + 1, dims[0] - 1), min(y0 + 1, dims[1] - 1), min(z0 + 1, dims[2] - 1)
        fx, fy, fz = x - x0, y - y0, z - z0
        def get_val(ix, iy, iz): return float(data[ix * stride_x + iy * stride_y + iz])
        c00 = get_val(x0, y0, z0) * (1-fx) + get_val(x1, y0, z0) * fx
        c10 = get_val(x0, y1, z0) * (1-fx) + get_val(x1, y1, z0) * fx
        c01 = get_val(x0, y0, z1) * (1-fx) + get_val(x1, y0, z1) * fx
        c11 = get_val(x0, y1, z1) * (1-fx) + get_val(x1, y1, z1) * fx
        c0 = c00 * (1-fy) + c10 * fy
        c1 = c01 * (1-fy) + c11 * fy
        return c0 * (1-fz) + c1 * fz

    # Standard ray-AABB intersection [G]
    def ray_box_intersection(ray_o, ray_d, dims):
        t_min, t_max = 0.0, float('inf')
        for i in range(3):
            if ray_d[i] == 0.0:
                if ray_o[i] < 0.0 or ray_o[i] >= dims[i]: return None, None
            else:
                t1 = (0.0 - ray_o[i]) / ray_d[i]
                t2 = (dims[i] - 1.0 - ray_o[i]) / ray_d[i]
                if t1 > t2: t1, t2 = t2, t1
                t_min = max(t_min, t1)
                t_max = min(t_max, t2)
        if t_min > t_max: return None, None
        return t_min, t_max

    for y in range(h):
        for x in range(w):
            ray_o, ray_d = camera.cast_ray((x, y))
            t_start, t_end = ray_box_intersection(ray_o, ray_d, volume_dims)
            if t_start is None: continue

            acc_color = vec3(0.0)
            acc_opacity = 0.0
            t = t_start + random_float(0.0, step_size)  # Fixed random offset to prevent banding [G]

            while acc_opacity < threshold and t <= t_end:
                pos = ray_o + t * ray_d
                scalar = trilinear_interpolation(volume_data, volume_dims, pos.x, pos.y, pos.z)
                color_s, opacity_s = transfer_function(scalar)

                weight = (1.0 - acc_opacity) * opacity_s
                acc_color += weight * color_s
                acc_opacity += weight

                t += step_size

            image[y][x] = pow(acc_color, vec3(1.0/2.2))

    return image
```

**Parameters:**
*   **Step Size ($\Delta x$):** The distance between consecutive samples. Too large causes undersampling (aliasing, missed features); too small causes oversampling (performance loss) [S2, S3]. Default is 0.001 [S2].
*   **Threshold ($\alpha_{thresh}$):** The opacity value at which the ray terminates. Commonly 0.95 or 0.99 [S1, S2].
*   **Transfer Function:** Maps scalar values to color and opacity. A simple example provided in [S1] uses normalized data range to compute RGB and alpha: $r = (v - DATA_{MIN}) / (DATA_{MAX} - DATA_{MIN})$, $\alpha = 0.9$ if $|r - 0.8| < 0.1$ else $0.01$, R: $(DATA_{MAX} - v) / (DATA_{MAX} - DATA_{MIN})$, G: $1 - |(DATA_{MAX} + DATA_{MIN})/2 - v| \times 2 / (DATA_{MAX} - DATA_{MIN})$, B: $(v - DATA_{MIN}) / (DATA_{MAX} - DATA_{MIN})$ [S1].

**Edge Cases and Pitfalls:**
*   **Boundary Artifacts:** Incorrect handling of the first and last sample points (entry/exit) can cause stepping artifacts or gaps at the volume boundaries [S4]. Strategies must accurately sample corner voxels to avoid missing corner samples, which causes intensities to drop to zero prematurely when the ray length is shorter than the step size [S4].
*   **Undersampling/Oversampling:** Choosing an inappropriate step size leads to visual artifacts or poor performance [S2].
*   **Gradient Calculation:** Gradients for shading are calculated using a central difference operator with a two-voxel offset rather than a one-voxel offset to avoid normal discontinuities that cause visible rings on smooth surfaces [S1, S3].

## Subtopics

### [Eye Align](849-eye-align.md)
A sample placement strategy where the first sample point is calculated from the eye's perspective, creating concentric sampling lines across pixels. Chosen to align sampling with the view direction, potentially reducing aliasing in specific geometries.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M \cdot L)$, where $N$ is the number of pixels, $M$ is the average number of samples per ray (dependent on volume depth and step size), and $L$ is the cost of sampling/compositing per sample [S2, S3].
*   **Memory Complexity:** $O(V)$ for the volume data, where $V$ is the number of voxels. $O(1)$ auxiliary memory per pixel for accumulators [S1, S2].
*   **Performance:** Performance is highly dependent on the step size and volume density. High-resolution volumes with small step sizes are computationally expensive [S2].
*   **Strengths:** Suitable for CPU implementation [S1].
*   **Limitations:** Fixed step size does not adapt to density variations, risking aliasing or inefficiency [S2, S3].
*   **When to Use:** Educational purposes, simple volumes, CPU-based rendering, or as a baseline for more complex methods [S1, S2].
*   **When Not to Use:** High-performance real-time rendering of large, complex volumes where adaptive sampling or GPU acceleration is required [S2].

## Background
The method is based on the volume rendering integral, discretized into a summation [S3]. The specific analysis of sampling strategies and boundary artifacts was conducted in the Inviwo visualization framework, supported by ELLIIT, SeRC, and VINNOVA grants [S4]. The technique is a fundamental approach in direct volume rendering, often contrasted with indirect methods like ray marching with acceleration structures or ray tracing [S2].
