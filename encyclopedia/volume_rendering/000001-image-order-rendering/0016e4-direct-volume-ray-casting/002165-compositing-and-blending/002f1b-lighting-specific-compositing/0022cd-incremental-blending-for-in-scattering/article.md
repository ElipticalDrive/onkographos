# Incremental Blending for In-scattering

Also called: Incremental In-scattering Blending

## Overview
Incremental Blending for In-scattering is a method for approximating volumetric light scattering (in-scattering) in direct volume rendering by accumulating scattered light intensity from multiple discrete directions. It solves the problem of computing the integral of light scattered into the eye ray by discretizing the scattering sphere into $J$ directions and blending the results incrementally. It differs from standard compositing by maintaining a separate accumulator for in-scattered intensity that is updated using a weighted average, and from [Intermixing](5139-intermixing.md) by using a specific harmonic-mean-like blending function derived from the number of samples processed so far.

## How it works
**Inputs and Outputs:**
*   **Input:** A volume dataset with opacity $\alpha$ and color $c$ transfer functions; a light source direction; a discretization of the scattering sphere into $J$ directions.
*   **Output:** The final eye color $I_{eye}$ for each pixel.

**Data Structures:**
*   $I_{stored}$: A volume buffer (or per-pixel accumulator) storing the blended in-scattered intensity. Size matches the volume resolution or screen resolution.
*   $I_{final}$: A temporary buffer or variable holding the computed in-scattered intensity for the current direction $j$.

**Steps:**
1.  **Initialization:** Initialize $I_{stored}$ to zero (or a bias value, see parameters).
2.  **Direction Sampling:** Compute $J$ directions for the scattering sphere. These are typically generated by subdividing a regular polyhedron (tetrahedron, icosahedron, or octahedron) to a level that provides the desired number of rays [S1]. The light source direction is computed first to ensure shadows are correctly approximated [S1].
3.  **Iterative Blending:** For each incremental update step $j$ from 1 to $J$:
    a.  Compute the in-scattered intensity $I_{final}$ for the current direction $j$. This involves evaluating the scattering term for the current view ray and the current light direction.
    b.  Blend $I_{final}$ with the previously stored intensity $I_{stored}$ using the incremental blending formula.
    c.  Store the result as the new $I_{stored}$.

**Formulas:**
The final eye color is computed as a Riemann sum discretizing the ray casting integral [S1]:

$$I_{eye} = \sum_{k=0}^n g_k \prod_{p=0}^{k-1} (1 - \alpha(s_p)) \quad (12)$$

where $g_k$ is the emitted color at sample $k$, $\alpha(s_p)$ is the opacity at sample $p$, and $n$ is the total number of samples along the ray.

The term $g_k$ is defined as [S1]:

$$g_k = I_{final} \cdot c(s_k) \cdot \alpha(s_k)$$

where $I_{final}$ is the in-scattered intensity component:

$$I_{final} = I_{bias} + (1 - I_{bias}) \cdot I_s(s_k)$$

Here, $c(s_k)$ is the color from the transfer function at point $s_k$, and $I_s(s_k)$ is the scattered intensity.

The incremental blending of the in-scattered intensity is performed using [S1]:

$$I_{blended} = \frac{1}{j} \cdot I_{final} + \left(1 - \frac{1}{j}\right) \cdot I_{stored} \quad (13)$$

where:
*   $I_{blended}$ is the new stored intensity.
*   $I_{final}$ is the result from the current direction $j$.
*   $I_{stored}$ is the previously accumulated intensity.
*   $j$ is the current ray index (from 1 to $J$).

**Parameters:**
*   **Bias ($I_{bias}$):** A parameter in the range $[0, 1]$ that adjusts the minimum light level. It ensures that even in shadowed areas, there is a base level of illumination. The default behavior assumes a white light source, but the equations can be extended for colored light [S1].

**Pitfalls:**
*   **Memory Usage:** The method requires storing intermediate results ($\alpha \cdot l_p$, $\alpha \cdot g$, and $I_{final}$) for each voxel. For a volume of $512^3$, this requires three additional $512^3$ volumes, which is computationally expensive in terms of memory [S1]. Reducing the resolution of the scattering volume (SVR) is a common mitigation strategy [S1].
*   **Precision:** The incremental blending formula relies on the counter $j$. If $j$ is not tracked correctly or if the number of directions $J$ is small, the approximation of the scattering integral may be inaccurate.

## Subtopics

### [Incremental Lighting for In-Scattering](3401-incremental-lighting-for-in-scattering.md)
Incremental Lighting for In-Scattering is a screen-space technique that approximates volumetric light scattering by propagating and blurring indirect lighting components across volume slices. It extends the base Incremental Blending for In-scattering method by introducing per-channel indirect attenuation parameters and a blur operation, allowing light to change color as it penetrates deeper into the volume, similar to the effect of holding a flashlight under a hand.

### [Hardware Blending Recurrence Evaluation](5317-hardware-blending-recurrence-evaluation.md)
Hardware Blending Recurrence Evaluation is a technique for evaluating the multiple forward scattering recurrence $I_k = g_{k-1} + T_{k-1} I_{k-1}$ by mapping the mathematical operation to GPU hardware blending and pixel read-back operations. It solves the problem of efficiently computing the incident light on a particle in a participating medium by leveraging the frame buffer as an accumulator. It differs from [Incremental Lighting for In-Scattering](3401-incremental-lighting-for-in-scattering.md) by using explicit pixel read-back to resolve the recurrence dependency, whereas its sibling uses a different accumulation strategy.

## Operating characteristics
*   **Time Complexity:** The complexity is proportional to the number of scattering directions $J$ and the number of samples per ray. Each direction requires a full pass or significant computation to determine $I_{final}$, followed by a blending step.
*   **Memory Complexity:** Requires storage for intermediate volumes ($\alpha \cdot l_p$, $\alpha \cdot g$, $I_{final}$). As noted, this can be substantial (e.g., three $512^3$ volumes) [S1].
*   **Strengths:** Provides a reasonable approximation of in-scattering with relatively simple incremental updates. The blending formula is computationally inexpensive per step.
*   **Limitations:** High memory footprint for large volumes. The accuracy depends heavily on the number of scattering directions $J$. The bias parameter $I_{bias}$ is a simplification that may not accurately represent complex lighting scenarios.
*   **When to use:** Suitable for interactive volume rendering where approximate in-scattering is desired and memory is not the primary constraint.
*   **When not to use:** When high-fidelity global illumination is required, or when memory bandwidth is a bottleneck.

## Background
The method was introduced in the context of interactive global light propagation in direct volume rendering using local piecewise integration [S1]. It addresses the need for efficient in-scattering approximation in real-time or near-real-time volume rendering applications. The approach builds on the principle of incremental updates to avoid recomputing the entire scattering integral for each frame or view change.
