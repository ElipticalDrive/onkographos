# Multi-pass Blending

Also called: Hardware Polygon Blending with Quadratic Approximation, Multi-pass Quadratic Blending, Quadratic Alpha Blending, Quadratic Fit to Exponential

## Overview
Multi-pass blending is a hardware-accelerated technique for direct volume ray casting that approximates the correct intensity and opacity of semi-transparent cells using standard polygon rasterization [S1, unofficial]. It solves the problem where linear interpolation (Gouraud shading) produces incorrect estimates of intensity and opacity across projected polygons, even when vertex values are accurate [S1, unofficial]. By decomposing the rendering of a single cell into three passes, it uses quadratic functions to approximate the exponential decay of background opacity and the nonlinear contribution of cell color, allowing for correct compositing without software-based ray casting [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A visibility-ordered cell (e.g., from a curvilinear or tetrahedral grid) with vertex attributes: color $\mathbf{C}$ and opacity $\alpha$ [S1, unofficial].
*   **Output:** The composited color and alpha in the framebuffer, correctly accounting for the exponential transmission of light through the cell's depth [S1, unofficial].

**Data Structures:**
The method relies on standard hardware polygon attributes [S1, unofficial]. For each vertex $v$ of the projected cell, the following values are computed and passed to the rasterizer:
*   **Color Vector ($\mathbf{c}$):** The interpolated color contribution [S1, unofficial].
*   **Alpha Scalar ($\alpha$):** The interpolated opacity weight [S1, unofficial].
*   **Depth ($z$):** The physical depth of the vertex within the cell, ranging from $0$ (nearest) to $A$ (thickest point of the cell projection) [S1, unofficial].

**Formulas:**
The physical model assumes that for a semi-transparent light-emitting medium with planar faces, the depth $z$ varies linearly along any line, but the effective transmission of color varies exponentially [S1, unofficial]. The accumulated light contribution $f(z)$ at depth $z$ is:
$$ f(z) = 1 - e^{-a z} $$
where $a$ is the absorption coefficient and $z$ is the depth [S1, unofficial].

This exponential function is approximated by a quadratic function $g(z)$ over the interval $[0, A]$, where $A$ is the depth of the thickest vertex:
$$ g(z) = (c_0 + c_1 z)(a_0 + a_1 z) $$
The approximation is constrained such that $g(0) = f(0)$ and $g(A) = f(A)$ [S1, unofficial].
1.  $f(0) = 0$, so $g(0) = c_0 a_0 = 0$. The source sets $a_0 = 0$ [S1, unofficial].
2.  To maintain generality and scale, $a_1$ is set to $1/A$ [S1, unofficial]. The alpha term is computed as $(a_0 + a_1 z) = (0 + (1/A)z)$ [S1, unofficial].
3.  The quadratic function $g(z)$ as a whole is chosen to minimize the squared error between $g(z)$ and $f(z)$ on $[0, A]$, subject to the constraint $g(A) = f(A)$ [S1, unofficial]. The exact closed-form solution for the color coefficients $c_0$ and $c_1$ is detailed in Appendix A of the source [S1, unofficial].

The hardware blend function used is `one minus source alpha` for attenuation passes, and `source color x source alpha` (or equivalent additive blend with alpha weighting) for the final color addition [S1, unofficial].

**Numbered Steps:**
The rendering of a single cell requires three distinct passes over the same polygon geometry:

1.  **Pass 1 (First Opacity Attenuation):**
    *   **Vertex Attributes:**
        *   Color: $\mathbf{c}_1 = \mathbf{C}_{vertex}$ (arbitrary, as it will be multiplied by the blend factor).
        *   Alpha: $\alpha_1(z) = a_0 + a_1 z = (1/A)z$ (Linear interpolation of depth normalized by max depth) [S1, unofficial].
    *   **Blend Function:** `one minus source alpha` [S1, unofficial].
    *   **Effect:** Multiplies the current framebuffer background by $(1 - \frac{z}{A})$. This is the first linear factor of the quadratic approximation [S1, unofficial].

2.  **Pass 2 (Second Opacity Attenuation):**
    *   **Vertex Attributes:**
        *   Color: $\mathbf{c}_2 = \mathbf{C}_{vertex}$ (arbitrary).
        *   Alpha: $\alpha_2(z) = (1/A)z$ (Same linear interpolation) [S1, unofficial].
    *   **Blend Function:** `one minus source alpha` [S1, unofficial].
    *   **Effect:** Multiplies the result of Pass 1 by $(1 - \frac{z}{A})$ again. The combined attenuation is $(1 - \frac{z}{A})^2$, which serves as a quadratic approximation to the exponential decay of the background [S1, unofficial]. The source states that using a linear function twice with this blend function yields a quadratic approximation to the desired exponential decay [S1, unofficial].

3.  **Pass 3 (Color Addition):**
    *   **Vertex Attributes:**
        *   Color: $\mathbf{c}_3(z) = \mathbf{C}_{vertex} \cdot (c_0 + c_1 z)$ (Color modulated by the linear color term of the quadratic approximation) [S1, unofficial].
        *   Alpha: $\alpha_3(z) = (1/A)z$ (Used to weight the color addition) [S1, unofficial].
    *   **Blend Function:** `source color x source alpha` (or equivalent additive blend with alpha weighting) [S1, unofficial].
    *   **Effect:** Adds the cell's color contribution to the attenuated background [S1, unofficial].

**Pseudocode:**
```python
import math

def render_cell_multi_pass(vertex_colors, vertex_depths, A, absorption_coeff, fb):
    """
    Renders a single cell using multi-pass blending.
    vertex_colors: List of (R, G, B) tuples for each vertex.
    vertex_depths: List of z-depths for each vertex (0 to A).
    A: Max depth of the cell (thickest vertex).
    absorption_coeff: The 'a' in the exponential model.
    fb: 2D array of shape (H, W, 3) representing the framebuffer.
    """
    # Precompute quadratic coefficients c0, c1 for the color term.
    # g(z) = (c0 + c1*z) * (z/A)
    # Constraint g(A) = f(A) => c0 + c1*A = 1 - exp(-a*A)
    target_val = 1.0 - math.exp(-absorption_coeff * A)
    
    best_c1 = 0.0
    min_error = float('inf')
    # Numerical minimization of squared error over [0, A] as described in the source
    for c1 in range(-1000, 1000):
        c1_f = c1 / 100.0
        c0_f = target_val - c1_f * A
        error = 0.0
        for z in [i * A / 100.0 for i in range(101)]:
            f_z = 1.0 - math.exp(-absorption_coeff * z)
            g_z = (c0_f + c1_f * z) * (z / A)
            error += (f_z - g_z) ** 2
        if error < min_error:
            min_error = error
            best_c1 = c1_f
    best_c0 = target_val - best_c1 * A

    # Pass 1: First opacity attenuation
    apply_pass(vertex_colors, [z / A for z in vertex_depths], 'ONE_MINUS_SRC_ALPHA', fb, A)

    # Pass 2: Second opacity attenuation
    apply_pass(vertex_colors, [z / A for z in vertex_depths], 'ONE_MINUS_SRC_ALPHA', fb, A)

    # Pass 3: Color addition
    modulated_colors = []
    for i, z in enumerate(vertex_depths):
        color_term = best_c0 + best_c1 * z
        modulated_colors.append(tuple(c * color_term for c in vertex_colors[i]))
    apply_pass(modulated_colors, [z / A for z in vertex_depths], 'SRC_ALPHA', fb, A)

def apply_pass(colors, alphas, blend_func, fb, A):
    """
    Simulates a hardware rendering pass with explicit blend math.
    Assumes a global framebuffer `fb` of shape (H, W, 3) initialized to background.
    """
    # Rasterization interpolates vertex attributes across the polygon.
    # We simulate this by iterating over sample points (z) within the cell's depth range.
    for z in [i * A / 100.0 for i in range(101)]:
        src_alpha = z / A
        src_color = interpolate_color(z, colors, [0.0, A])
        if blend_func == 'ONE_MINUS_SRC_ALPHA':
            # Hardware blend: dst = dst * (1 - src_alpha)
            fb[:] = fb[:] * (1.0 - src_alpha)
        elif blend_func == 'SRC_ALPHA':
            # Hardware blend: dst = dst + src_color * src_alpha
            fb[:] = fb[:] + src_color * src_alpha

def interpolate_color(z, colors, depths):
    """Linear interpolation of vertex colors based on depth z."""
    # In practice, this is handled by the GPU rasterizer
    if depths[1] == depths[0]:
        return colors[0]
    t = (z - depths[0]) / (depths[1] - depths[0])
    return tuple(c0 * (1 - t) + c1 * t for c0, c1 in zip(colors[0], colors[1]))
```

**Edge Cases and Pitfalls:**
*   **Precision:** The method relies on the hardware's ability to accurately interpolate linear attributes and perform the blend operations [G]. Precision errors in the quadratic approximation can lead to visible artifacts, especially with high absorption coefficients where the exponential decay is steep [G].
*   **Visibility Ordering:** Correctness depends on a valid visibility ordering where no earlier cell occludes a later cell in screen space [S1, unofficial].
*   **Thick Cells:** The approximation is valid on the interval $[0, A]$ [S1, unofficial]. If the cell projection is not convex or the depth variation is complex, the linear interpolation of $z$ may not accurately represent the path length, leading to errors [S1, unofficial].

## Subtopics

### Visibility Ordering
The prerequisite for correct compositing. Ensures that cells are processed in an order such that earlier cells do not occlude later ones in screen space [S1, unofficial]. [Link](5751-visibility-ordering.md)

### Gouraud Shading
The underlying hardware rasterization technique used for linear interpolation of vertex attributes, which multi-pass blending extends via multiple passes [S1, unofficial]. [Link](5752-gouraud-shading.md)

## Operating characteristics
*   **Time Complexity:** Three passes per cell, making it significantly slower than single-pass linear blending. The source notes "The extra time in computation and rendering are substantial" [S1, unofficial].
*   **Memory Complexity:** Low, as it uses standard framebuffer operations and does not require storing intermediate volume data per pixel [G].
*   **Strengths:** Allows the use of standard hardware polygon renderers for volume rendering, avoiding the need for software ray casting. Provides a much better approximation of opacity and intensity than linear interpolation [S1, unofficial].
*   **Limitations:** Computationally expensive due to multiple passes. Approximation errors exist, particularly for cells with high absorption or complex geometry. Requires careful visibility ordering [S1, unofficial].
*   **When to Use:** When hardware acceleration is required and the visual quality of linear blending is insufficient, and software ray casting is too slow [G].
*   **When Not to Use:** For real-time applications with very high frame rate requirements, or when exact physical accuracy is required [G].

## Background
Multi-pass blending was introduced in the context of rapid exploration of curvilinear grids using direct volume rendering [S1, unofficial]. It addresses the limitations of earlier methods that used linear interpolation (Gouraud shading) for color and opacity, which produced incorrect intensity and opacity estimates [S1, unofficial]. The method was developed to leverage existing hardware polygon renderers while achieving higher fidelity in volume visualization [S1, unofficial].
