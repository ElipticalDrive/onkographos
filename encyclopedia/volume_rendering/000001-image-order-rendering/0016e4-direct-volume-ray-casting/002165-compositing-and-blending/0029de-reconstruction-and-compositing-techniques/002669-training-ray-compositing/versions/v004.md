# Training Ray Compositing

Also called: Volume Rendering Composite, Volume Rendering Composite Forward

## Overview
Training Ray Compositing is a differentiable volume rendering method that composites per-ray samples of density ($\sigma$) and color ($\mathbf{c}$) into final image colors, alpha weights, and depth, while simultaneously computing gradients with respect to the input parameters for training [S1, unofficial]. It extends standard alpha compositing by including ambient light contributions and supporting a custom backward pass to propagate gradients from the loss function back to the density and color fields [S1, unofficial]. It is distinguished from its sibling [Training Ray Compositing (Backward)](3893-training-ray-compositing-backward.md) by handling the forward composition and the joint forward-backward logic in a unified CUDA kernel interface, whereas the backward variant focuses specifically on the gradient computation logic [S1, unofficial].

## How it works
**Inputs and Outputs:**
The method takes as input tensors for densities (`sigmas`), colors (`rgbs`), step sizes (`deltas`), and ray metadata (`rays`). It outputs the composited RGB image, depth, opacity (alpha weights), and gradients for `sigmas` and `rgbs` during the backward pass [S1, unofficial][S3, unofficial].

**Data Structures:**
*   `sigmas`: Density values, shape `[M]`, float [S1, unofficial].
*   `rgbs`: RGB colors at sampled points, shape `[M, 3]`, float [S1, unofficial][S3, unofficial].
*   `deltas`: Step sizes, shape `[M, 2]` (containing step size and real delta), float [S1, unofficial][S3, unofficial].
*   `rays`: Ray metadata, shape `[N, 3]`, int32. Each row is `[ray_index, start_point_index, num_steps]` [S1, unofficial][S3, unofficial].
*   `weights_sum`: Output buffer for total alpha (opacity) per ray, shape `[N]`, float [S1, unofficial][S3, unofficial].
*   `image`: Output buffer for final RGB color per ray, shape `[N, 3]`, float [S1, unofficial][S3, unofficial].
*   `depth`: Depth value, shape `[N]`, float [S1, unofficial].

**Parameters:**
*   `T_thresh`: Transparency threshold for early termination, default $10^{-4}$ [S1, unofficial][S4, unofficial].
*   `N_THREAD`: Number of threads per CUDA block, typically 256 [S3, unofficial].
*   `M`: Number of samples per ray [S3, unofficial].
*   `N`: Number of rays [S3, unofficial].

**Algorithm:**
The method iterates over active rays. For each ray, it retrieves the number of samples and the ray index. It initializes transmittance $T$ and accumulators for RGB, depth, and opacity. It then iterates through the samples along the ray. For each sample, it calculates the alpha $\alpha$, the weight $w$, and updates the accumulators and transmittance. If transmittance drops below `T_thresh`, the ray is marked as dead and the loop breaks. Finally, the accumulated values are written to the output buffers.

1.  **Initialization**: For each ray $n$ in the active set, retrieve `num_steps` from `rays[n * 3 + 2]` and `start_point_index` from `rays[n * 3 + 1]`. If `num_steps` is 0 or the offset overflows, set `weights_sum` and `image` to 0 and return [S3, unofficial]. Initialize transmittance $T = 1.0$ and accumulators $\mathbf{C}_{temp} = \mathbf{0}$, $D_{temp} = 0$, $\alpha_{temp} = 0$ [S2, unofficial][S3, unofficial].
2.  **Sample Loop**: For each sample $s$ in `range(num_steps)`:
    a.  Retrieve density $\sigma = \text{sigmas}[s]$ and step size $\delta = \text{deltas}[s]$ [S3, unofficial].
    b.  Calculate alpha: $\alpha = 1 - e^{-\sigma \delta}$ [S3, unofficial].
    c.  Calculate weight: $w = \alpha \cdot T$ [S3, unofficial].
    d.  Retrieve color $\mathbf{c} = \text{rgbs}[s]$ [S3, unofficial].
    e.  Accumulate RGB: $\mathbf{C}_{temp} \leftarrow \mathbf{C}_{temp} + w \cdot \mathbf{c}$ [S2, unofficial][S3, unofficial].
    f.  Accumulate Depth: $D_{temp} \leftarrow D_{temp} + w \cdot t_s$, where $t_s$ is the depth/position of the sample [S2, unofficial].
    g.  Accumulate Opacity: $\alpha_{temp} \leftarrow \alpha_{temp} + w$ [S2, unofficial].
    h.  Update Transmittance: $T \leftarrow T \cdot (1 - \alpha)$ [S3, unofficial].
    i.  **Early Termination**: If $T < T_{thresh}$, mark the ray as dead and break the loop [S2, unofficial][S3, unofficial].
3.  **Finalization**: Add accumulated values to the final buffers: $\text{self.rgb}[r] \leftarrow \text{self.rgb}[r] + \mathbf{C}_{temp}$, $\text{self.depth}[r] \leftarrow \text{self.depth}[r] + D_{temp}$, $\text{self.opacity}[r] \leftarrow \text{self.opacity}[r] + \alpha_{temp}$ [S2, unofficial]. Set `weights_sum[index] = 1.0 - T` and `image[index * 3..5] = r, g, b` [S3, unofficial].

**Pseudocode:**

```python
import torch
import math

def composite_rays_train_forward(sigmas, rgbs, deltas, rays, T_thresh=1e-4):
    """
    Forward pass for Training Ray Compositing.
    
    Args:
        sigmas: Density values, shape [M], float.
        rgbs: RGB colors, shape [M, 3], float.
        deltas: Step sizes, shape [M, 2], float.
        rays: Ray metadata, shape [N, 3], int32. [ray_index, start_point_index, num_steps].
        T_thresh: Transparency threshold, float.
        
    Returns:
        image: Composited RGB, shape [N, 3], float.
        depth: Composited Depth, shape [N], float.
        weights_sum: Total Alpha/Opacity, shape [N], float.
    """
    N = rays.shape[0]
    M = sigmas.shape[0]
    
    # Initialize output buffers
    image = torch.zeros((N, 3), dtype=torch.float32, device=sigmas.device)
    depth = torch.zeros((N,), dtype=torch.float32, device=sigmas.device)
    weights_sum = torch.zeros((N,), dtype=torch.float32, device=sigmas.device)
    
    # Iterate over rays
    for n in range(N):
        ray_index = int(rays[n, 0])
        start_point_index = int(rays[n, 1])
        num_steps = int(rays[n, 2])
        
        # Check for empty rays or overflow
        if num_steps == 0 or start_point_index + num_steps > M:
            continue
            
        # Initialize accumulators
        T = 1.0
        rgb_temp = torch.zeros(3, dtype=torch.float32, device=sigmas.device)
        depth_temp = 0.0
        opacity_temp = 0.0
        
        # Iterate through samples
        for s in range(num_steps):
            sample_idx = start_point_index + s
            
            # Get density and delta
            sigma = sigmas[sample_idx]
            delta = deltas[sample_idx, 0] # Assuming first element is step size
            
            # Calculate alpha
            alpha = 1.0 - math.exp(-sigma * delta)
            
            # Calculate weight
            w = alpha * T
            
            # Get color
            color = rgbs[sample_idx]
            
            # Accumulate RGB
            rgb_temp += w * color
            
            # Accumulate Depth (assuming deltas[sample_idx, 1] is the depth/position)

            depth_temp += w * deltas[sample_idx, 1]

            opacity_temp += w

            T *= (1.0 - alpha)
            
            # Early termination
```

**Edge Cases and Pitfalls:**
*   **Empty Rays**: If `num_steps` is 0 or the offset overflows, the ray is skipped, and outputs are set to 0 [S3, unofficial].
*   **Early Termination**: Rays with low transmittance are terminated early to save computation. The threshold `T_thresh` (default $10^{-4}$) controls this [S1, unofficial][S4, unofficial].
*   **Gradient for Depth**: The gradient for depth is not propagated to sigmas [S1, unofficial][S4, unofficial].

## Subtopics

### [Training Ray Compositing (Sigma)](3868-training-ray-compositing-sigma.md)
Training Ray Compositing (Sigma) is a differentiable volume rendering method that composites per-ray samples of density ($\sigma$) and color ($\mathbf{c}$) into final image colors, alpha weights, and depth, while simultaneously computing gradients with respect to the input parameters for training. It extends standard alpha compositing by including ambient light contributions and supporting a custom backward pass to propagate gradients from the loss function back to the density and color fields. It is distinguished from its sibling [Training Ray Compositing (Backward)](3893-training-ray-compositing-backward.md) by handling the forward composition and the joint forward-backward logic in a unified CUDA kernel interface, whereas the backward variant focuses specifically on the gradient computation logic.

### Multi-Layer Compositing with Gradient Backpropagation
Multi-Layer Compositing with Gradient Backpropagation caps the number of composited layers at $c_{max} = 16$ per pixel to bound memory for backward pass statistics [S5, unofficial]. The forward pass performs depth-interval grouping, MIP-filtered kernel evaluation, Shepard normalization, and front-to-back compositing fused into a single kernel invocation per tile [S5, unofficial]. The backward pass first replays forward gap detection to reconstruct per-layer totals ($C_c, \alpha_c$) for $c=1$ to $c_{max}$, and then retraverses primitives to assign each to its layer and decompose per-layer gradients into per-surfel gradients through normalized accumulation using atomic operations [S5, unofficial]. Concurrent writes from different pixels during gradient decomposition are handled by atomic operations [S5, unofficial].

### Partial Image Source Signature Integration
Partial Image Source Signature Integration is a post-processing step that combines pre-computed ray buffer data (absorption/color) with a source signature vector to compute final emerging intensities, using OpenMP parallelization [S6, unofficial]. It retrieves control portals for the buffer and intensity arrays, determines pixel and channel counts, and iterates over all pixels in parallel. For each pixel and channel, it computes the new intensity as: $\text{intensity} = \text{emission} + \text{buffer} \times \text{source\_sig[channel]}$ [S6, unofficial]. The buffer stores either color or absorption values per pixel/channel, and the intensities store the final intensity emerging from each ray after source signature integration [S6, unofficial].

## Operating characteristics
*   **Time Complexity**: The forward pass is $O(N \cdot M)$ where $N$ is the number of rays and $M$ is the number of samples per ray. Early termination can reduce the effective $M$. The backward pass is also $O(N \cdot M)$ but involves more complex gradient calculations.
*   **Memory Complexity**: $O(N \cdot M)$ for storing intermediate values during the forward pass if needed for the backward pass. The output buffers are $O(N)$.
*   **Performance**: Implemented in CUDA for high performance on GPUs [S1, unofficial][S3, unofficial].
*   **Strengths**: Differentiable, allowing for end-to-end training of neural radiance fields. Efficient early termination.
*   **Limitations**: Gradient computation can be complex. Depth gradient is not propagated to sigmas [S1, unofficial][S4, unofficial].

## Background
Training Ray Compositing is used in the context of training Neural Radiance Fields (NeRFs) and related methods. It is implemented in repositories such as ER-NeRF [S1, unofficial], taichi-ngp-renderer [S2, unofficial], cv-master-ex [S3, unofficial], and IDDR-NGP [S4, unofficial]. The method is crucial for differentiable rendering, enabling the optimization of scene representations from 2D images.
