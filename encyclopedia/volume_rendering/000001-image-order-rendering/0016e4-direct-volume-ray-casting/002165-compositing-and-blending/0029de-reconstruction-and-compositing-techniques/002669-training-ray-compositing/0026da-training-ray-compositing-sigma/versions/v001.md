# Training Ray Compositing (Sigma)

Also called: Ray Compositing for Training (Sigma + Ambient)

## Overview
Training Ray Compositing (Sigma) is a differentiable volume rendering method that composites per-ray samples of density ($\sigma$) and color ($\mathbf{c}$) into final image colors, alpha weights, and depth, while simultaneously computing gradients with respect to the input parameters for training [S1, unofficial]. It extends standard alpha compositing by including ambient light contributions and supporting a custom backward pass to propagate gradients from the loss function back to the density and color fields [S1, unofficial]. It is distinguished from its sibling [Training Ray Compositing (Backward)](3893-training-ray-compositing-backward.md) by handling the forward composition and the joint forward-backward logic in a unified CUDA kernel interface, whereas the backward variant focuses specifically on the gradient computation logic [S1, unofficial].

## How it works
The method implements differentiable volume rendering along rays. It assumes that the scene is represented by a set of samples along each ray, characterized by density, color, and step size. The forward pass computes the accumulated color, alpha, and depth, while the backward pass computes the gradients of the loss with respect to the input densities and colors.

### Inputs and Outputs
**Inputs:**
*   `sigmas`: Float tensor of shape $[M]$, representing volume density for $M$ samples [S1, unofficial].
*   `rgbs`: Float tensor of shape $[M, 3]$, representing view-dependent color for $M$ samples [S1, unofficial].
*   `ambient`: Float tensor of shape $[M]$, representing ambient light contribution for $M$ samples [S1, unofficial].
*   `deltas`: Float tensor of shape $[M, 2]$, representing step sizes (typically $t_{i+1}-t_i$ and other geometric info) for $M$ samples [S1, unofficial].
*   `rays`: Integer tensor of shape $[N, 3]$, containing ray indices or identifiers for $N$ rays [S1, unofficial].
*   `T_thresh`: Float, transparency threshold. Default value is $10^{-4}$ [S1, unofficial].

**Outputs:**
*   `image`: Float tensor of shape $[N, 3]$, the final composited RGB color for each of the $N$ rays [S1, unofficial].
*   `weights_sum`: Float tensor of shape $[N]$, the output alpha channel (accumulated opacity) for each ray [S1, unofficial].
*   `depth`: Float tensor of shape $[N]$, the output depth for each ray [S1, unofficial].
*   `ambient_sum`: Float tensor of shape $[N]$, the accumulated ambient contribution for each ray [S1, unofficial].

### Data Structures and Layout
The implementation relies on contiguous CUDA tensors. The input data is structured as follows:
*   `sigmas`: $[M]$ float32.
*   `rgbs`: $[M, 3]$ float32.
*   `ambient`: $[M]$ float32.
*   `deltas`: $[M, 2]$ float32.
*   `rays`: $[N, 3]$ int32.

The output tensors are allocated with shapes:
*   `weights_sum`: $[N]$ float32.
*   `ambient_sum`: $[N]$ float32.
*   `depth`: $[N]$ float32.
*   `image`: $[N, 3]$ float32.

### Algorithm Steps

#### Forward Pass
1.  **Validation**: Ensure `sigmas`, `rgbs`, `ambient`, `deltas`, and `rays` are contiguous in memory [S1, unofficial].
2.  **Dimensions**: Let $M$ be the number of samples (`sigmas.shape[0]`) and $N$ be the number of rays (`rays.shape[0]`) [S1, unofficial].
3.  **Allocation**: Allocate output tensors `weights_sum` $[N]$, `ambient_sum` $[N]$, `depth` $[N]$, and `image` $[N, 3]$ initialized to zero [S1, unofficial].
4.  **Kernel Execution**: Call the forward CUDA kernel `_backend.composite_rays_train_sigma_forward` with inputs `sigmas`, `rgbs`, `ambient`, `deltas`, `rays`, and `T_thresh`, writing results to the output tensors [S1, unofficial].
5.  **Save for Backward**: Save the input tensors (`sigmas`, `rgbs`, `ambient`, `deltas`, `rays`) and the output tensors (`weights_sum`, `ambient_sum`, `depth`, `image`) for use in the backward pass [S1, unofficial].
6.  **Save Parameters**: Save the dimensions $M$, $N$, and the threshold $T_{thresh}$ [S1, unofficial].

#### Backward Pass
1.  **Gradient Validation**: Ensure `grad_weights_sum`, `grad_ambient_sum`, and `grad_image` (gradients from the loss) are contiguous [S1, unofficial].
2.  **Retrieve**: Load the saved tensors and dimensions from the forward pass [S1, unofficial].
3.  **Initialize**: Initialize gradient tensors `grad_sigmas` $[M]$, `grad_rgbs` $[M, 3]$, and `grad_ambient` $[M]$ with zeros [S1, unofficial].
4.  **Kernel Execution**: Call the backward CUDA kernel `_backend.composite_rays_train_sigma_backward` with the saved tensors, gradients, and parameters to compute `grad_sigmas`, `grad_rgbs`, and `grad_ambient` [S1, unofficial].
5.  **Ambient Gradient**: Call the CUDA backend kernel `_backend.composite_rays_ambient_sigma` to handle specific ambient light gradient computations if required by the implementation [S1, unofficial].

### Pseudocode
The following Python-like pseudocode illustrates the PyTorch `autograd.Function` structure used in the implementation [S1, unofficial].

```python
import torch
import _backend # Hypothetical CUDA extension module

class TrainingRayCompositingSigma(torch.autograd.Function):
    @staticmethod
    def forward(ctx, sigmas, rgbs, ambient, deltas, rays, T_thresh=1e-4):
        # 1. Ensure contiguous
        sigmas = sigmas.contiguous()
        rgbs = rgbs.contiguous()
        ambient = ambient.contiguous()
        deltas = deltas.contiguous()
        rays = rays.contiguous()
        
        # 2. Get dimensions
        M = sigmas.shape[0]
        N = rays.shape[0]
        
        # 3. Allocate outputs
        weights_sum = torch.zeros(N, device=sigmas.device, dtype=sigmas.dtype)
        ambient_sum = torch.zeros(N, device=sigmas.device, dtype=sigmas.dtype)
        depth = torch.zeros(N, device=sigmas.device, dtype=sigmas.dtype)
        image = torch.zeros(N, 3, device=sigmas.device, dtype=sigmas.dtype)
        
        # 4. Call forward kernel
        _backend.composite_rays_train_sigma_forward(
            sigmas, rgbs, ambient, deltas, rays, 
            weights_sum, ambient_sum, depth, image, T_thresh
        )
        
        # 5. Save for backward
        ctx.save_for_backward(sigmas, rgbs, ambient, deltas, rays, 
                              weights_sum, ambient_sum, depth, image)
        ctx.M = M
        ctx.N = N
        ctx.T_thresh = T_thresh
        
        return image, weights_sum, ambient_sum, depth

    @staticmethod
    def backward(ctx, grad_image, grad_weights_sum, grad_ambient_sum, grad_depth):
        # Note: grad_depth is typically not used or propagated to sigmas [S1, unofficial]
        
        # 1. Retrieve saved tensors
        sigmas, rgbs, ambient, deltas, rays, weights_sum, ambient_sum, depth, image = ctx.saved_tensors
        M = ctx.M
        N = ctx.N
        T_thresh = ctx.T_thresh
        
        # 2. Ensure gradients are contiguous
        grad_image = grad_image.contiguous()
        grad_weights_sum = grad_weights_sum.contiguous()
        grad_ambient_sum = grad_ambient_sum.contiguous()
        
        # 3. Initialize gradient tensors
        grad_sigmas = torch.zeros_like(sigmas)
        grad_rgbs = torch.zeros_like(rgbs)
        grad_ambient = torch.zeros_like(ambient)
        
        # 4. Call backward kernel
        _backend.composite_rays_train_sigma_backward(
            sigmas, rgbs, ambient, deltas, rays,
            weights_sum, ambient_sum, depth, image,
            grad_image, grad_weights_sum, grad_ambient_sum,
            grad_sigmas, grad_rgbs, grad_ambient, T_thresh
        )
        
        # 5. Call ambient-specific kernel if needed
        _backend.composite_rays_ambient_sigma(
            sigmas, rgbs, ambient, deltas, rays,
            weights_sum, ambient_sum, depth, image,
            grad_image, grad_weights_sum, grad_ambient_sum,
            grad_sigmas, grad_rgbs, grad_ambient, T_thresh
        )
        
        # Return gradients in order of inputs
        return grad_sigmas, grad_rgbs, grad_ambient, None, None, None
```

### Parameters
*   `T_thresh`: Float. The transparency threshold. Rays with accumulated transparency below this value are considered fully opaque and can be skipped or terminated for efficiency [S1, unofficial]. Default: $10^{-4}$.

### Edge Cases and Pitfalls
*   **Depth Gradient**: The gradient for depth is not propagated back to the density (`sigmas`) parameters [S1, unofficial]. This is a known limitation or design choice in this specific implementation.
*   **Contiguity**: The method requires all input tensors to be contiguous in memory. Non-contiguous tensors must be cloned or moved before passing to the kernel [S1, unofficial].
*   **Precision**: Standard float32 precision is used for all tensors. Precision issues may arise in very deep scenes or with very small step sizes, though the threshold `T_thresh` helps mitigate unnecessary computation for transparent regions [S1, unofficial].

## Subtopics

### Ray Compositing for Training (Uncertainty)
This variant composites rays for training including uncertainty estimation, computing gradients for sigmas, RGBs, ambient, and uncertainty [S1, unofficial]. It extends the base method by adding an `uncertainty` input tensor and an `uncertainty_sum` output tensor [S1, unofficial]. The forward pass calls `_backend.composite_rays_train_uncertainty_forward` and the backward pass calls `_backend.composite_rays_train_uncertainty_backward` [S1, unofficial]. It is chosen when the model needs to predict and train on uncertainty metrics alongside color and density [S1, unofficial].

### Ray Compositing for Training (Triplane/Aud/Eye)
This variant composites rays for training with triplane-based ambient lighting, specifically handling auditory (`amb_aud`) and eye-specific (`amb_eye`) ambient components, as well as uncertainty [S1, unofficial]. It computes gradients for sigmas, RGBs, and the various ambient components [S1, unofficial]. The forward pass calls `_backend.composite_rays_train_triplane_forward` and handles inputs `amb_aud`, `amb_eye`, and `uncertainty` [S1, unofficial]. It is chosen for models that incorporate multi-modal inputs like audio and eye tracking into the volume rendering process [S1, unofficial]. Like the base method, the gradient for depth is not propagated to sigmas [S1, unofficial].

### CUDA Ray Compositing
A GPU-accelerated kernel that performs alpha compositing of pre-sampled RGB and sigma values along rays to produce final image and depth [S2, unofficial]. It iterates through samples for each alive ray, accumulating transparency and computing weighted RGB and depth contributions [S2, unofficial]. It uses inputs `sigmas` $[n_{alive} \times n_{step}]$, `rgbs` $[n_{alive} \times n_{step}, 3]$, and `deltas` $[n_{alive} \times n_{step}, 2]$, with in-place outputs `weights_sum` $[N]$, `depth` $[N]$, and `image` $[N, 3]$ [S2, unofficial]. It is chosen for high-performance rendering where the ray structure is flattened into alive-step pairs [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: The forward and backward passes are $O(N \cdot M)$, where $N$ is the number of rays and $M$ is the number of samples per ray, assuming uniform sampling. The use of `T_thresh` allows for early termination, reducing the effective $M$ for transparent rays [S1, unofficial][S2, unofficial].
*   **Memory Complexity**: The method requires storing the input tensors and the output tensors. The backward pass requires saving the forward pass inputs and outputs, leading to memory usage proportional to $O(N \cdot M)$ for the saved tensors [S1, unofficial].
*   **Performance**: As a CUDA kernel-based implementation, it is highly optimized for GPU execution [S1, unofficial][S2, unofficial]. Performance scales with the number of alive rays and the number of samples [S2, unofficial].
*   **Strengths**: Differentiable, supports ambient lighting and uncertainty, efficient early termination [S1, unofficial][S2, unofficial].
*   **Limitations**: Gradient for depth is not propagated to sigmas [S1, unofficial]. Requires contiguous tensors [S1, unofficial].

## Background
Training Ray Compositing (Sigma) is part of the differentiable volume rendering pipeline used in neural radiance fields (NeRF) and related methods, specifically those involving training with ambient lighting and uncertainty [S1, unofficial]. It is implemented in the ER-NeRF repository, which focuses on efficient neural rendering with audio and eye-driven animations [S1, unofficial]. The method builds on the principles of differentiable alpha compositing, adapting them for training scenarios where gradients must be computed for density and color parameters [S1, unofficial].
