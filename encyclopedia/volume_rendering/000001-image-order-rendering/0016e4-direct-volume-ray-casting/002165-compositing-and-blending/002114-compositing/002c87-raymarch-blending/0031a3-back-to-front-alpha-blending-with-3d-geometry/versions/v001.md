# Back-to-Front Alpha Blending with 3D Geometry

Also called: WebGL blending for volume-geometry intersection

## Overview
This method composites a ray-marched volume over pre-rendered opaque 3D polygonal geometry by leveraging standard graphics pipeline alpha blending. It solves the occlusion problem where volumetric data must correctly interact with solid meshes, ensuring that the volume is blended against the background color already present in the framebuffer from previous rendering passes [S1]. Unlike standard ray casting which only evaluates volume density, this approach ensures correct occlusion of the volume by solid geometry, solving the problem of rendering transparent volumes over opaque meshes in a single pass or specific pipeline configuration [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   Volume texture (3D scalar field).
    *   Depth textures (RGBA packed) from previous passes rendering the 3D geometry [S1].
    *   Color buffer containing the rendered 3D geometry from previous passes [S1].
    *   Ray origin and direction (derived from camera and screen coordinates).
*   **Outputs:**
    *   Final color and alpha for each pixel, composited into the screen buffer [S1].

**Data Structures:**
*   **Depth Texture:** Since WebGL 1.0 lacks native float depth texture support on all devices, depth information from passes 1 and 3 is packed into RGBA textures [S1]. The fragment shader must unpack this depth value to determine if a ray intersects a 3D object at a specific step [S1].
*   **Frame Buffer Objects (FBO):** Used to store the intermediate depth and color data from the geometry passes [S1].

**Parameters:**
*   **Blend Function:** `gl.SRC_ALPHA` for source and `gl.ONE_MINUS_SRC_ALPHA` for destination [S1].
*   **Early Ray Termination Threshold:** Accumulated alpha equal to 1.0 (opaque) [S1].

**Steps:**
1.  **Geometry Passes (Passes 1 and 3):** Render the opaque 3D polygonal objects. Store the depth information in RGBA textures [S1].
2.  **Volume Ray Casting (Pass 5):** Execute the ray-casting fragment shader.
3.  **Depth Unpacking:** In the ray-casting shader, unpack the depth value from the RGBA texture sampled at the current pixel coordinate [S1].
4.  **Ray Traversal:** Traverse the volume along the ray. At each step, check if the ray intersects a 3D object using the unpacked depth data [S1].
5.  **Accumulation:** Accumulate volume color and alpha along the ray.
6.  **Early Ray Termination:** If the accumulated alpha reaches 1.0, terminate the ray traversal early [S1].
7.  **Blending:** Output the accumulated volume color and alpha. The graphics pipeline applies the blend function to composite this result with the existing color in the framebuffer (which contains the 3D geometry color) [S1].

**Pseudocode:**
```python
# Fragment Shader Logic for Pass 5
# Assumes uniforms: volumeTexture, depthTexture, rayOrigin, rayDirection, stepSize

def ray_cast_fragment_shader():
    # 1. Unpack depth from previous geometry passes
    # depth_rgba is sampled from depthTexture at current screen coordinates
    depth_rgba = texture(depthTexture, gl_FragCoord.xy / resolution)
    # Unpack depth value (implementation depends on packing scheme, e.g., RGB to float)
    depth_value = unpack_depth(depth_rgba)
    
    # 2. Initialize accumulation
    acc_color = vec3(0.0)
    acc_alpha = 0.0
    
    # 3. Ray traversal
    t = 0.0
    while t < volume_max_distance:
        # Sample volume at current ray position
        sample_pos = rayOrigin + rayDirection * t
        density = sample_volume(volumeTexture, sample_pos)
        
        # Convert density to alpha (e.g., using Beer-Lambert law or simple mapping)
        # [G] Assuming a simple linear mapping for demonstration; actual mapping depends on transfer function
        step_alpha = density * stepSize
        
        # 4. Early Ray Termination
        if acc_alpha >= 1.0:
            break
            
        # 5. Accumulate color and alpha (Front-to-Back)
        # [G] Standard front-to-back compositing formula
        weight = step_alpha * (1.0 - acc_alpha)
        acc_color += weight * sample_color
        acc_alpha += weight
        
        t += stepSize
        
    # 6. Output for blending
    # The pipeline will apply: gl.blendFunc(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA)
    # Final Color = acc_color * acc_alpha + existing_buffer_color * (1.0 - acc_alpha)
    return vec4(acc_color, acc_alpha)
```

**Edge Cases and Pitfalls:**
*   **Transparent Geometry:** The base implementation assumes opaque 3D objects. Transparent 3D polygonal objects are not supported [S1].
*   **Depth Precision:** Packing depth into RGBA may introduce precision loss compared to native float depth textures [S1].
*   **WebGL Compatibility:** Native depth texture support is not universal in WebGL 1.0, necessitating the RGBA packing fallback [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of steps in the ray traversal, subject to early ray termination [S1].
*   **Memory Complexity:** Requires storage for the volume texture and the depth textures from previous passes [S1].
*   **Strengths:** Correctly handles occlusion of volume by opaque geometry; leverages standard hardware blending [S1].
*   **Limitations:** Does not support transparent 3D geometry in the base implementation; dependent on WebGL version and extensions for depth texture support [S1].
*   **When to use:** When rendering volumetric data over opaque 3D meshes in a WebGL environment where standard blending is desired [S1].
*   **When not to use:** When transparent 3D geometry is present in the scene [S1].
