# Piecewise Linear Opacity Mapping with Gradient Scaling

Also called: Gradient-scaled opacity mapping, Gradient-scaled piecewise linear opacity, Surface-enhanced volume rendering

## Overview
This method maps voxel scalar values to opacity using piecewise linear functions defined by tissue types, then scales the resulting opacity by the magnitude of the local gradient vector to suppress tissue interiors and enhance bounding surfaces [S1, unofficial][S2, unofficial]. Unlike binary classification which creates holes for thin structures, this method renders thin regions as faint wisps because all voxels are typically mapped to non-zero opacity [S1, unofficial][S2, unofficial]. It builds on [Transfer Function and Opacity Mapping](2789-transfer-function-and-opacity-mapping.md) by introducing a gradient-based scaling factor that emphasizes boundaries.

## How it works
**Inputs:**
- Scalar volume data $f(x_i)$ for voxels at positions $x_i$.
- A list of $N$ tissue types, where $N \ge 1$.
- For each tissue type $n \in \{1, \dots, N\}$:
  - A known CT number (scalar value) $f_{vn}$.
  - A target opacity $\alpha_{vn} \in [0, 1]$.
- The tissue types must be ordered such that $f_{v1} < f_{v2} < \dots < f_{vN}$ [S1, unofficial][S2, unofficial].
- Pre-computed gradient magnitude $|\nabla f(x_i)|$ for each voxel [S1, unofficial][S2, unofficial].

**Outputs:**
- Opacity $\alpha(x_i)$ for each voxel, used in the front-to-back compositing equations from [Transfer Function and Opacity Mapping](2789-transfer-function-and-opacity-mapping.md).

**Data Structures:**
- **Tissue Definition:** An array of $N$ structs, each containing `fv` (float) and `alpha` (float).
- **Gradient Field:** A 3D array of floats storing $|\nabla f(x_i)|$ for every voxel. If not pre-stored, it must be computed per-voxel.

**Assumptions (Adjacency Criteria):**
The method assumes that if tissue types are ordered by CT number, each type touches only types adjacent to it in the ordering. Formally, no tissue of CT number $f_{vn_1}$ touches any tissue of CT number $f_{vn_2}$ where $|n_1 - n_2| > 1$ [S1, unofficial][S2, unofficial]. Violation of this criteria leads to voxels that cannot be unambiguously classified [S1, unofficial][S2, unofficial].

**Numbered Steps:**
1. **Gradient Calculation:** Compute the local gradient vector $\nabla f(x_i)$ for each voxel and its magnitude $|\nabla f(x_i)|$. The gradient vector is approximated using a standard finite difference operator [S1, unofficial][S2, unofficial].
2. **Interval Determination:** For a voxel with value $f(x_i)$, determine which tissue interval $[f_{vn}, f_{vn+1}]$ it falls into.
3. **Base Opacity Interpolation:** Calculate the linear interpolation weight $w$ based on the position of $f(x_i)$ within $[f_{vn}, f_{vn+1}]$:
   $$ w = \frac{f(x_i) - f_{vn}}{f_{vn+1} - f_{vn}} $$
   Compute the base opacity $\alpha_{base}$ by interpolating between $\alpha_{vn}$ and $\alpha_{vn+1}$:
   $$ \alpha_{base} = (1 - w) \alpha_{vn} + w \alpha_{vn+1} $$
4. **Gradient Scaling:** Multiply the base opacity by the gradient magnitude:
   $$ \alpha(x_i) = |\nabla f(x_i)| \cdot \alpha_{base} $$
5. **Out-of-Range Handling:** If $f(x_i)$ is outside all defined intervals (i.e., $f(x_i) < f_{v1}$ or $f(x_i) > f_{vN}$), set opacity to 0 [S2, unofficial].

**Pseudocode:**
```python
def compute_opacity(f_voxel, gradient_magnitude, tissue_types):
    """
    Compute opacity for a single voxel using piecewise linear mapping and gradient scaling.
    
    Args:
        f_voxel (float): Scalar value of the voxel.
        gradient_magnitude (float): Magnitude of the local gradient |grad f(x_i)|.
        tissue_types (list of dict): List of tissue definitions sorted by 'fv'.
            Each dict has keys 'fv' (float) and 'alpha' (float).
            
    Returns:
        float: The computed opacity alpha(x_i).
    """
    n = len(tissue_types)
    
    # Check if voxel value is within the range of defined tissue types
    if f_voxel < tissue_types[0]['fv'] or f_voxel > tissue_types[-1]['fv']:
        return 0.0
    
    # Find the interval [fv_n, fv_n+1] containing f_voxel
    # Since tissue_types is sorted by 'fv', we can iterate or use binary search
    for i in range(n - 1):
        fv_n = tissue_types[i]['fv']
        fv_n1 = tissue_types[i+1]['fv']
        
        if fv_n <= f_voxel <= fv_n1:
            # Calculate linear interpolation weight
            # w = (f(x_i) - fv_n) / (fv_n+1 - fv_n)
            if fv_n1 == fv_n:
                # Avoid division by zero if adjacent tissue types have same CT number
                # This violates the strict ordering assumption f_vn < f_vn+1
                # In practice, clamp or handle as error. 
                # Based on source, strict inequality is assumed.
                weight = 0.0 
            else:
                weight = (f_voxel - fv_n) / (fv_n1 - fv_n)
            
            # Interpolate base opacity
            alpha_n = tissue_types[i]['alpha']
            alpha_n1 = tissue_types[i+1]['alpha']
            alpha_base = (1.0 - weight) * alpha_n + weight * alpha_n1
            
            # Scale by gradient magnitude
            alpha = gradient_magnitude * alpha_base
            
            return alpha
            
    # Fallback if not found (should be covered by range check)
    return 0.0

def compute_gradient_magnitude(volume_data, x, y, z):
    """
    Approximate gradient magnitude using central differences.
    Assumes volume_data is a 3D array.
    Handles boundaries by clamping or using one-sided differences.
    """
    # Central differences for interior points
    # dx = f(x+1,y,z) - f(x-1,y,z)
    # dy = f(x,y+1,z) - f(x,y-1,z)
    # dz = f(x,y,z+1) - f(x,y,z-1)
    
    # Note: Source [S1, unofficial] mentions "operator given in section 3"
    # Standard central difference is implied for gradient approximation.
    
    # Boundary handling [G]: Clamp indices to valid range
    def get_val(x, y, z):
        # Clamp coordinates to volume bounds
        x = max(0, min(x, volume_data.shape[0]-1))
        y = max(0, min(y, volume_data.shape[1]-1))
        z = max(0, min(z, volume_data.shape[2]-1))
        return volume_data[x, y, z]

    dx = get_val(x+1, y, z) - get_val(x-1, y, z)
    dy = get_val(x, y+1, z) - get_val(x, y-1, z)
    dz = get_val(x, y, z+1) - get_val(x, y, z-1)
    
    return (dx*dx + dy*dy + dz*dz)**0.5
```

**Parameters:**
- $f_{vn}$: Known CT number for tissue type $n$. Ordered $f_{v1} < f_{v2} < \dots < f_{vN}$ [S1, unofficial][S2, unofficial].
- $\alpha_{vn}$: Target opacity for tissue type $n$ at $f_{vn}$ [S1, unofficial][S2, unofficial].
- $K$: Number of sample locations along each ray [S1, unofficial][S2, unofficial].

**Edge Cases and Pitfalls:**
- **Adjacency Violation:** If non-adjacent tissue types touch, voxels at boundaries cannot be unambiguously classified, leading to incorrect rendering [S1, unofficial][S2, unofficial]. Solution: Interactive clipping to isolate subsets meeting criteria [S1, unofficial][S2, unofficial].
- **Thin Features:** Binary thresholds may miss thin features of tissue type B if their voxel values are less than $f_{vB}$. This method avoids that by mapping all voxels to non-zero opacity, rendering them as faint wisps [S1, unofficial][S2, unofficial].
- **Gradient Constancy:** The thickness of the transition region around isosurface contours remains constant only if the local gradient magnitude is constant within a radius of $r$ voxels around each point on the surface [S1, unofficial][S2, unofficial].
- **Striping Artifacts:** CT scanners have anisotropic spatial sensitivity, causing striping. Patient motion also causes striping because shading depends on gradient orientation, and misalignments between adjacent slices disrupt this [S1, unofficial][S2, unofficial].
- **Rotation Shading:** Fixing colors and opacities while rotating causes light sources to appear to travel with the data, creating incorrect highlights [S1, unofficial][S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- **Opacity Computation:** One lookup table reference per voxel if gradient magnitudes are pre-stored. New lookup table generation is required if classification parameters change [S1, unofficial][S2, unofficial].
- **Ray Tracing/Compositing:** For a square image of $n$ pixels with orthographic projection and $K$ samples per ray, the cost is $3Kn^2$ additions, $2Kn^2$ tri-linear interpolations, and $Kn^2$ linear interpolations [S1, unofficial][S2, unofficial].

**Measured Performance:**
- **Molecular Graphics (Cytochrome B5, $113^3$ voxels):** Classification/shading took 5 minutes on a SUN 4/280 with 32MB RAM. Ray tracing/compositing took 40 minutes [S1, unofficial][S2, unofficial].
- **Medical Imaging (CT Cadaver, 113 slices of $256 \times 256$):** Each set of colors/opacities took 20 minutes. Each view took an additional 20 minutes [S1, unofficial][S2, unofficial].

**Strengths and Limitations:**
- **Strengths:** Renders thin, wispy surfaces instead of holes for regions not meeting strict adjacency or threshold criteria [S1, unofficial][S2, unofficial]. Suppresses tissue interiors while enhancing bounding surfaces [S1, unofficial][S2, unofficial].
- **Limitations:** Sensitive to acquisition artifacts like striping from anisotropic sensitivity or patient motion [S1, unofficial][S2, unofficial]. Requires pre-computation of gradient magnitudes or lookup tables. Blurring opacities softens silhouettes but may reduce crispness if over-applied [S1, unofficial][S2, unofficial]. Super-sampling improves accuracy but substantially increases computational expense [S1, unofficial][S2, unofficial].

**When to Use:**
- Suitable for molecular graphics and medical imaging (CT) where surface enhancement is desired [S1, unofficial][S2, unofficial].
- Use when tissue types can be ordered and adjacency criteria are met or can be enforced via clipping [S1, unofficial][S2, unofficial].

**When Not to Use:**
- When datasets contain internal soft tissue organs that violate adjacency criteria and cannot be easily clipped [S1, unofficial][S2, unofficial].
- When high-fidelity geometric merging with other visualizations is required without true 3-D merge capabilities [S1, unofficial][S2, unofficial].

## Background
**Origin:**
The method was introduced by Levoy in 1988 in the paper "Display of Surfaces from Volume Data" [S1, unofficial][S2, unofficial].

**History and Development:**
It was applied to molecular graphics (Cytochrome B5 electron density map) and medical imaging (CT cadaver study) [S1, unofficial][S2, unofficial]. The method relies on the assumption that scenes contain tissue types with CT numbers falling within small neighborhoods of known values, and that tissues touch only adjacent types in the ordered CT number list [S1, unofficial][S2, unofficial].

**Usage:**
Used in molecular graphics study on Cytochrome B5 electron density map ($113 \times 113 \times 113$ voxels) [S1, unofficial][S2, unofficial]. Used in medical imaging study on CT data of a cadaver (113 slices of $256 \times 256$ samples) [S1, unofficial][S2, unofficial].
