# Linear Opacity Interpolation

Also called: pokrytie

## Overview
Linear Opacity Interpolation maps scalar volume data values to opacity using linear interpolation between two threshold values [S1, unofficial]. It serves as the fundamental opacity mapping primitive in piecewise linear transfer functions, providing a simple, computationally efficient way to define transparency ranges [S1, unofficial]. Unlike its sibling [Piecewise Linear Opacity Mapping with Gradient Scaling](1335-piecewise-linear-opacity-mapping-with-gradient-scaling.md), which adjusts opacity based on local gradient magnitude to enhance edges, this method relies solely on the scalar value itself, making it suitable for homogeneous regions or when gradient computation is prohibitive.

## How it works
**Inputs and Outputs:**
- Input: A scalar volume data value $i$ (typically unsigned integer, e.g., `UINT16`).
- Parameters: Lower threshold $oa$ (`UINT16`), upper threshold $ob$ (`UINT16`), opacity at lower threshold $foa$ (`float`), opacity at upper threshold $fob$ (`float`).
- Output: Opacity scalar $\alpha$ (`float`).

**Data Structures:**
No complex data structures are required. The method operates on scalar values and four parameter constants.

**Steps:**
1. Check if the input value $i$ lies outside the defined range $[oa, ob]$.
2. If $i < oa$ or $i > ob$, the opacity is zero.
3. If $oa \le i \le ob$, compute the opacity using linear interpolation between $(oa, foa)$ and $(ob, fob)$.

**Formula:**
The opacity $\alpha$ is defined as:
$$
\alpha = \begin{cases} 
0.0 & i < oa \lor i > ob \\
foa + (fob - foa) \frac{i - oa}{ob - oa} & \text{otherwise}
\end{cases}
$$

**Parameters:**
- $oa, ob$: Lower and upper thresholds defining the active range. Type: `UINT16` [S1, unofficial].
- $foa, fob$: Opacity values at the thresholds. Type: `float`, typically in $[0.0, 1.0]$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Division by Zero:** If $oa = ob$, the denominator becomes zero. The source code implies a check or assumes $oa < ob$ [S1, unofficial]. In implementation, guard against $oa == ob$ to avoid NaN or infinity.
- **Clamping:** The input $i$ should be clamped or checked against the valid range of the data type to prevent out-of-bounds access if used as an index elsewhere, though here it is purely arithmetic [S1, unofficial].
- **Precision:** Using floating-point for the result ensures smooth transitions, but input thresholds are integer-based [S1, unofficial].

**Pseudocode:**
```python
def linear_opacity_interpolation(i: int, oa: int, ob: int, foa: float, fob: float) -> float:
    """
    Compute opacity for scalar value i using linear interpolation between thresholds oa and ob.
    
    Args:
        i: Scalar volume data value (int).
        oa: Lower threshold (int).
        ob: Upper threshold (int).
        foa: Opacity at oa (float).
        fob: Opacity at ob (float).
        
    Returns:
        Opacity alpha (float).
    """
    # Guard against division by zero if oa == ob
    if oa == ob:
        # If thresholds are equal, opacity is undefined by linear interpolation.
        # Return foa if i equals oa, else 0.0. This is a logical inference [G].
        if i == oa:
            return foa
        else:
            return 0.0

    # Step 1: Check bounds
    if i < oa or i > ob:
        return 0.0

    # Step 2: Linear interpolation
    # alpha = foa + (fob - foa) * (i - oa) / (ob - oa)
    alpha = foa + (fob - foa) * (i - oa) / (ob - oa)
    
    return alpha
```

## Subtopics

### Piecewise Function Scalar Opacity Transfer
A method to define scalar-to-opacity mapping using a piecewise function, allowing specific intensity ranges to be made transparent or opaque [S2, unofficial]. It extends the basic linear interpolation by allowing multiple segments. A key parameter is the **stretch factor**, a constant $0.05$ used to scale raw DICOM pixel values before mapping to the transfer function, likely to adjust for bit-depth or specific data range [S2, unofficial]. This scaling ensures that the full dynamic range of the 16-bit DICOM data is utilized within the transfer function's defined points.

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample. The operation involves a few comparisons and a single arithmetic division.
- **Memory Complexity:** $O(1)$. No additional memory is required beyond the four parameter values.
- **Strengths:** Extremely fast, simple to implement, and easy to tune for specific data ranges.
- **Limitations:** Cannot capture complex opacity transitions (e.g., smooth curves, multiple peaks) without many segments. Does not account for local geometry (gradients), which may result in less visually distinct boundaries compared to gradient-based methods.
- **When to use:** When performance is critical, or when the volume data has clear, distinct scalar ranges that need to be isolated.
- **When not to use:** When smooth, non-linear opacity transitions are required, or when edge enhancement is needed (use [Piecewise Linear Opacity Mapping with Gradient Scaling](1335-piecewise-linear-opacity-mapping-with-gradient-scaling.md) instead).

## Background
The method is implemented in the `besnik/parallel-volume-rendering` repository, where it is used as a core component of the transfer function evaluation [S1, unofficial]. The term "pokrytie" (Czech for "coverage" or "opacity") is used as an alias in this context [S1, unofficial]. It is a standard technique in direct volume rendering, often part of a larger piecewise linear transfer function framework.
