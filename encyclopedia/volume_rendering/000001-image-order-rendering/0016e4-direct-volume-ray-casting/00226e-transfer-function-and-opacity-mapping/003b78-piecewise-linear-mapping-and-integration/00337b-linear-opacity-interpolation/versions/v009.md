# Linear Opacity Interpolation

Also called: pokrytie

## Overview
Linear Opacity Interpolation maps scalar volume data values to opacity using linear interpolation between two threshold values [S1, unofficial]. It sets itself apart from its sibling [Piecewise Linear Opacity Mapping with Gradient Scaling](1335-piecewise-linear-opacity-mapping-with-gradient-scaling.md) by using a fixed linear segment without gradient modulation, and from [Piecewise Function Scalar Opacity Transfer](12435-piecewise-function-scalar-opacity-transfer.md) by restricting the mapping to a single linear range rather than arbitrary piecewise definitions [S2, S12435, unofficial].

## How it works
**Inputs and Outputs**:
- Input: Scalar value $i$ (typically UINT16) retrieved from the volume.
- Parameters: Lower threshold $oa$ (UINT16), upper threshold $ob$ (UINT16), opacity at lower threshold $foa$ (float), opacity at upper threshold $fob$ (float).
- Output: Opacity $\alpha$ (float).

**Data Structures**:
No complex data structures are required. The method relies on four scalar parameters defining the linear segment.

**Steps**:
1. Check if the input value $i$ lies within the range $[oa, ob]$.
2. If $i < oa$ or $i > ob$, the opacity is zero.
3. If $oa \le i \le ob$, compute the opacity using linear interpolation between $(oa, foa)$ and $(ob, fob)$.

**Formula**:
The opacity $\alpha$ is defined as:
$$
\alpha = \begin{cases} 
0.0 & i < oa \lor i > ob \\
foa + (fob - foa) \frac{i - oa}{ob - oa} & \text{otherwise}
\end{cases}
$$

**Parameters**:
- $oa, ob$: Lower and upper thresholds. Typically UINT16 values representing the data range [S1, unofficial].
- $foa, fob$: Opacity values at the thresholds. Typically floats in the range $[0.0, 1.0]$ [S1, unofficial].

**Edge Cases and Pitfalls**:
- If $oa = ob$, the denominator in the interpolation formula becomes zero. The source code implies a check `if (i<oa) || (i>ob)` which handles equality implicitly if the range is valid, but division by zero must be guarded against in implementation if $oa$ and $ob$ can be equal [S1, unofficial].
- Input values outside the $[oa, ob]$ range result in zero opacity, effectively masking data outside the selected feature range.

**Pseudocode**:
```python
def linear_opacity_interpolation(i: int, oa: int, ob: int, foa: float, fob: float) -> float:
    """
    Computes opacity for a scalar value i using linear interpolation between thresholds oa and ob.
    
    Args:
        i: Scalar input value (UINT16).
        oa: Lower threshold (UINT16).
        ob: Upper threshold (UINT16).
        foa: Opacity at oa (float).
        fob: Opacity at ob (float).
        
    Returns:
        Opacity alpha (float).
    """
    if i < oa or i > ob:
        return 0.0
    
    # Guard against division by zero if oa == ob
    if oa == ob:
        return foa # Or 0.0, depending on desired behavior for degenerate range
        
    # Linear interpolation
    alpha = foa + (fob - foa) * (i - oa) / (ob - oa)
    return alpha
```

## Subtopics

### [Bézier Curve Opacity Mapping](8485-b-zier-curve-opacity-mapping.md)
Uses smooth polynomial curves instead of linear segments for non-linear opacity control. Choose when smooth transitions are required.

### [Piecewise Function Scalar Opacity Transfer](12435-piecewise-function-scalar-opacity-transfer.md)
Supports arbitrary piecewise definitions and non-linear combinations. Choose when complex data distributions require multiple linear or non-linear segments.

## Operating characteristics
- **Time Complexity**: $O(1)$ per sample. The operation involves a few comparisons and basic arithmetic.
- **Memory Complexity**: $O(1)$. Only four parameters are stored.
- **Strengths**: Simple to implement and understand. Efficient for isolating specific data ranges.
- **Limitations**: Cannot model complex opacity distributions with a single segment. Discontinuous derivatives at thresholds may cause visual artifacts if not handled carefully.
- **When to use**: When a specific feature range needs to be highlighted with a constant or linearly varying opacity.
- **When not to use**: When the data requires non-linear opacity mapping or multiple distinct features with different opacity behaviors.
