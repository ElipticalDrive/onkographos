# MPF Volume Rendering
Also called: Volume Rendering with MPFs
## Overview
MPF Volume Rendering is a neural volume rendering technique that replaces the Signed Distance Field (SDF) backbone with Metric-Phase Fields (MPFs) to handle sign-ambiguous geometry and thin structures [S1, unofficial]. It derives opacity from a signed composite field $\phi$ using a NeuS-style occupancy mapping, while color is predicted by a separate radiance network, isolating the geometry representation change from the rendering pipeline [S1, unofficial].
## How it works
**Inputs:**
*   Camera ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, where $\mathbf{o}$ is the origin and $\mathbf{d}$ is the direction [S1, unofficial].
*   MPF network predicting the signed composite field $\phi(\mathbf{x})$ [S1, unofficial].
*   Radiance network predicting color $\mathbf{c}(\mathbf{x}, \mathbf{d})$ [S1, unofficial].

**Outputs:**
*   Rendered color $\widehat{C}(\mathbf{r})$ for the ray [S1, unofficial].

**Data Structures:**
*   Sample points: A set of depths $t_1 < t_2 < \dots < t_n$ along the ray [S1, unofficial].
*   Field values: $\phi_i = \phi(\mathbf{r}(t_i))$ and color $\mathbf{c}_i = \mathbf{c}(\mathbf{r}(t_i), \mathbf{d})$ for each sample $i$ [S1, unofficial].

**Parameters:**
*   $s > 0$: Learned sharpness parameter controlling the transition band width of the occupancy CDF [S1, unofficial].
*   $\varepsilon$: Small constant for numerical stability in opacity calculation [S1, unofficial].

**Steps:**
1.  **Sampling:** For each pixel, generate sample depths $t_1 < t_2 < \dots < t_n$ along the ray $\mathbf{r}(t)$ [S1, unofficial].
2.  **Evaluation:** Evaluate the signed composite field $\phi_i = \phi(\mathbf{r}(t_i))$ and the color $\mathbf{c}_i = \mathbf{c}(\mathbf{r}(t_i), \mathbf{d})$ at each sample point [S1, unofficial].
3.  **Occupancy Mapping:** Compute the occupancy function $\Phi_i$ using a monotone cumulative distribution function (CDF) applied to the scaled field value:
    $$ \Phi_i = \text{CDF}\left(\frac{\phi_i}{s}\right) $$
    The source specifies a monotone CDF without prescribing a specific function [S1, unofficial].
4.  **Opacity Estimation:** Calculate the per-interval opacity $\alpha_i$ based on the change in occupancy between adjacent samples:
    $$ \alpha_i = \text{clip}_{[0,1]}\left( \frac{\Phi_i - \Phi_{i+1}}{\Phi_i + \varepsilon} \right) $$
    This formulation leverages the signed nature of $\phi$ to produce well-conditioned zero crossings [S1, unofficial].
5.  **Weight Computation:** Compute rendering weights $w_i$. The source text contains a garbled formula `wi = αi Q jαj )`, which is interpreted here as the standard volumetric transmission product implied by the context:
    $$ w_i = \alpha_i \prod_{j < i} (1 - \alpha_j) $$
    This represents the probability of the ray terminating in the $i$-th interval, accounting for transmission through previous intervals [S1, unofficial].
6.  **Color Accumulation:** Compute the final rendered color by summing the weighted colors:
    $$ \widehat{C}(\mathbf{r}) = \sum_{i=1}^{n} w_i \mathbf{c}_i $$
    This matches the standard volume integration equation [S1, unofficial].

**Pseudocode:**
```python
import math

def mpf_volume_render(ray_o, ray_d, mpf_net, radiance_net, t_vals, s, eps):
    """
    ray_o: (3,) ray origin
    ray_d: (3,) ray direction
    t_vals: (n,) sorted sample depths
    mpf_net: function returning phi(x)
    radiance_net: function returning color(x, d)
    s: sharpness parameter
    eps: numerical stability constant
    """
    n = len(t_vals)
    positions = [(ray_o[0] + t * ray_d[0], ray_o[1] + t * ray_d[1], ray_o[2] + t * ray_d[2]) for t in t_vals]
    
    # Evaluate fields
    phi_vals = [mpf_net(p) for p in positions]
    colors = [radiance_net(p, ray_d) for p in positions]
    
    # Occupancy mapping: Phi_i = CDF(phi_i / s)
    # Source specifies a monotone CDF; sigmoid is standard for NeuS-style mappings [G]
    occupancy = [1.0 / (1.0 + math.exp(-phi / s)) for phi in phi_vals]
    
    # Opacity estimation: alpha_i = clip((Phi_i - Phi_{i+1}) / (Phi_i + eps))
    # Phi_{n} is 0.0 for the last sample (outside volume)
    alphas = []
    for i in range(n):
        phi_next = occupancy[i + 1] if i + 1 < n else 0.0
        num = occupancy[i] - phi_next
        den = occupancy[i] + eps
        alpha = num / den
        alpha = max(0.0, min(1.0, alpha))
        alphas.append(alpha)
        
    # Weight computation: w_i = alpha_i * product_{j<i} (1 - alpha_j)
    weights = []
    transmittance = 1.0
    for i in range(n):
        weights.append(transmittance * alphas[i])
        transmittance *= (1.0 - alphas[i])
        
    # Color accumulation: C = sum(w_i * c_i)
    rendered_color = [0.0, 0.0, 0.0]
    for i in range(n):
        for c in range(3):
            rendered_color[c] += weights[i] * colors[i][c]
    return rendered_color
```

**Edge Cases and Pitfalls:**
*   **Numerical Stability:** The denominator $\Phi_i + \varepsilon$ prevents division by zero when $\Phi_i$ is near zero, requiring $\varepsilon$ to be small but non-zero [S1, unofficial].
*   **Sign Ambiguity:** MPFs retain flexibility in sign-ambiguous regions through metric/phase decomposition, which helps in thin structures where SDFs might fail [S1, unofficial].
*   **Garbled Formula:** The source text's rendering weight formula `wi = αi Q jαj )` is ambiguous; the implementation assumes the standard volumetric rendering weight definition implied by the context [S1, unofficial].
## Operating characteristics
*   **Complexity:** Time complexity is linear with respect to the number of samples $n$ per ray [S1, unofficial]. Memory complexity is dominated by the storage of the MPF and radiance networks [S1, unofficial].
*   **Strengths:** Handles sign-ambiguous geometry and thin structures better than standard SDF-based methods by using MPFs [S1, unofficial]. Produces well-conditioned zero crossings and occlusion-aware weights [S1, unofficial].
*   **Limitations:** Requires learning the sharpness parameter $s$ and potentially more complex geometry representation (MPF) compared to simple SDFs [S1, unofficial].
*   **When to use:** Suitable for scenes with thin structures or sign-ambiguous geometry where standard SDFs struggle [S1, unofficial].
*   **When not to use:** For simple, watertight, sign-definite geometry, standard SDF-based methods may be simpler and sufficient [S1, unofficial].
## Background
MPF Volume Rendering builds on the NeuS pipeline, which uses a signed-field-to-opacity mapping via a monotone CDF [S1, unofficial]. It specifically addresses limitations of SDFs in handling sign-ambiguous geometry and thin structures by introducing Metric-Phase Fields (MPFs) as the geometry backbone [S1, unofficial]. The method was introduced in the paper "Volume Rendering with Metric--Phase Fields for Thin Structures and Sign-Ambiguous Geometry" [S1, unofficial].
