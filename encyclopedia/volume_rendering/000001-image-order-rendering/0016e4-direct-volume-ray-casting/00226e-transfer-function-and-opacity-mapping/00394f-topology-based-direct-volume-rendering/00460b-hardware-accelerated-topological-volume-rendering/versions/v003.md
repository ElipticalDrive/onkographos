# Hardware-Accelerated Topological Volume Rendering

Also called: Topological Zone Look-up Rendering, Topology-Controlled Volume Rendering

## Overview
Hardware-Accelerated Topological Volume Rendering applies topological segmentation to scalar fields to guide direct volume rendering attributes, rather than relying solely on indirect mesh visualization [S1, unofficial]. It solves the problem of visualizing simplified topological structures (such as contour tree branches) in real-time by dynamically rendering "tubes" between saddles and extrema within the fragment shader, avoiding the need to modify the scalar field data beforehand [S1, unofficial]. It sets itself apart from its siblings by performing gradient reversal and tube blending directly on the GPU using texture lookups, enabling interactive manipulation of topological simplifications like branch pruning [S1, unofficial].

## How it works
The method operates by storing topological data in textures accessible by the fragment shader, allowing for dynamic modification of function values based on proximity to topological features (tubes) and topological constraints (scaling) [S1, unofficial].

### Inputs and Outputs
*   **Input:** A 3D scalar field (volume data), a precomputed contour tree branch decomposition, and user-defined transfer functions [S1, unofficial].
*   **Output:** A 2D image with modified opacity and color based on topological zone membership and tube proximity [S1, unofficial].

### Data Structures and Layout
The method relies on several texture-based data structures:

1.  **Image Data:** Stored as a 3D texture with trilinear interpolation [S1, unofficial].
2.  **Vertex-to-Branch Map:** Stored as a 3D texture with nearest-neighbor interpolation. The output of this texture lookup is a reference (texture coordinate) to an array of branches [S1, unofficial].
3.  **Branch Records:** Logically a 1D array, but physically wrapped as a 2D texture due to 3D texture dimension limits. Each branch record contains:
    *   Reference to its parent branch [S1, unofficial].
    *   Value at its saddle point [S1, unofficial].
    *   Depth in the rooted branch decomposition [S1, unofficial].
    *   Reference to its transfer function [S1, unofficial].
4.  **Transfer Functions:** Stored in a logically 1D, physically 2D array. References are texture coordinates; a function value is added to offset the coordinate to select the proper color [S1, unofficial].
5.  **Tube Lookup Table:** Stores position $p_t(v)$, tube radius $r_t(v)$, and replacement function value $f_t(v)$ for each function value $v$. Accessed via texture lookup indexed by function value [S1, unofficial].
6.  **Closest Tube Reference:** Stored in a 3D texture. For each voxel, the closest tube in its topological zone is stored. This is determined in preprocessing by checking the parent and child tubes of that zone [S1, unofficial].
7.  **Scale-and-Bias Pair:** Stored in branch textures. Parameters for a uniform 1D scaling transformation about the saddle value, composed for zones with multiple parents [S1, unofficial].

### Numbered Steps
1.  **Sample Input Value:** For each fragment, sample the original function value $v_{in}$ from the image data 3D texture using trilinear interpolation [S1, unofficial].
2.  **Identify Topological Zone:** Look up the branch reference for the current voxel from the vertex-to-branch map 3D texture using nearest-neighbor interpolation [S1, unofficial].
3.  **Apply Scaling Transformation:** Retrieve the scale-and-bias pair for the identified branch. If the branch has been pruned or simplified, apply the scaling transformation to $v_{in}$ about the saddle value. This ensures monotonic paths when parent/child extrema constraints are violated. If a branch is pruned, the scaling transformation $s$ is applied to all children by multiplying each child's scale-bias pair by $s$; if pruning is reversed, the inverse $s^{-1}$ is applied [S1, unofficial].
4.  **Look Up Tube Data:** Using the (potentially scaled) function value, look up the tube position $p_t(v)$, tube radius $r_t(v)$, and replacement function value $f_t(v)$ from the tube lookup table [S1, unofficial].
5.  **Compute Blending Function:** Calculate the blending function $b$ based on the distance from the tube axis. The parameter $k$ controls the width of the tube [S1, unofficial].
6.  **Compute Output Value:** Compute the final function value $v_{out}$ using linear interpolation between the original value $v_{in}$ and the replacement value $f_t(v_{in})$, weighted by the blending function $b$ [S1, unofficial].
7.  **Render:** Use $v_{out}$ to index into the transfer function texture to determine the final color and opacity [S1, unofficial].

### Formulas
**Blending Function:**
The blending function $b$ controls the transition between the original field and the tube's modified field. It is defined as:

$$
b = \frac{r_t(v) - k \| s - p_t(v) \|}{r_t(v)}
$$

Where:
*   $r_t(v)$ is the tube radius at function value $v$ [S1, unofficial].
*   $k$ is a width control parameter [S1, unofficial].
*   $s$ is the current sample position (fragment position) [S1, unofficial].
*   $p_t(v)$ is the position on the tube axis corresponding to function value $v$ [S1, unofficial].
*   $\| \cdot \|$ denotes the Euclidean distance [S1, unofficial].

The value of $b$ is restricted to the interval $[0, 1]$ [S1, unofficial].

**Output Function Value:**
The final function value $v_{out}$ is computed as:

$$
v_{out} = \text{clamp}(1 - b)v_{in} + \text{clamp}(b)f_t(v_{in})
$$

Where:
*   $v_{in}$ is the original (and scaled) function value [S1, unofficial].
*   $f_t(v_{in})$ is the replacement function value from the tube lookup table [S1, unofficial].
*   $\text{clamp}(x)$ is defined as:
    $$
    \text{clamp}(x) = \begin{cases} 
    0 & \text{if } x \le 0 \\
    x & \text{if } 0 < x < 1 \\
    1 & \text{if } x \ge 1 
    \end{cases}
    $$

**Scaling Transformation:**
The scaling transformation is a uniform 1D scaling about the saddle value $S$ [S1, unofficial]. If the scale-and-bias pair is $(\sigma, \beta)$, the transformed value $v'$ is:
$$
v' = \sigma \cdot (v - S) + S + \beta
$$
(Note: The exact composition of scale-and-bias for multiple parents is handled by storing the composed pair in the branch texture [S1, unofficial].)

### Parameters
*   **$k$ (Width Control):** Defines the width of the tube by controlling how quickly $b$ falls off from the axis. It must be larger than one (e.g., $k=2$) to ensure the interior volume with $b=1$ is visible. If $k \le 1$, $b$ attains its maximum value only along the axis, making the tube interior invisible [S1, unofficial].

### Edge Cases and Pitfalls
*   **Tube Width Visibility:** As noted, if $k \le 1$, the tube interior is invisible. A value of $k=2$ is recommended [S1, unofficial].
*   **Texture Dimension Limits:** 3D texture dimensions are limited, requiring branch arrays (logically 1D) to be wrapped as 2D textures. Implementers must handle the coordinate mapping correctly [S1, unofficial].
*   **Pruning Propagation:** When a branch is pruned, the scaling transformation must be correctly propagated to all children. When pruning is reversed, the inverse transformation must be applied. Failure to compose these transformations correctly for zones with multiple parents will result in incorrect monotonic paths [S1, unofficial].
*   **Closest Tube Selection:** The closest tube reference is determined in preprocessing by checking the parent and child tubes of that zone [S1, unofficial].

### Pseudocode
```python
def raycast_topological_volume(volume_tex, branch_map_tex, branch_tex, tube_table_tex, tf_tex, closest_tube_tex, k, origin, direction, step_size, max_steps):
    # Standard front-to-back compositing initialization [G]
    color = [0.0, 0.0, 0.0, 0.0]
    alpha_accum = 0.0

    for i in range(max_steps):
        pos = origin + direction * (i * step_size)
        
        # Step 1: Sample input value
        vin = volume_tex.sample_trilinear(pos)
        
        # Step 2: Identify Topological Zone
        branch_ref = branch_map_tex.sample_nearest(pos)
        branch = branch_tex.sample(branch_ref)
        
        # Step 3: Apply Scaling Transformation
        scale, bias, saddle = branch.scale, branch.bias, branch.saddle
        vin_scaled = scale * (vin - saddle) + saddle + bias
        
        # Step 4: Look Up Tube Data
        # Closest tube reference texture stores the tube ID for this voxel's zone [S1, unofficial]
        tube_id = closest_tube_tex.sample_nearest(pos)
        # Tube table is indexed by function value [S1, unofficial]
        tube = tube_table_tex.sample(tube_id, vin_scaled)
        pt, rt, ft = tube.position, tube.radius, tube.replacement_value
        
        # Step 5: Compute Blending Function
        dist = length(pos - pt)
        b_raw = (rt - k * dist) / rt
        b = clamp(b_raw)
        
        # Step 6: Compute Output Value
        vout = clamp(1 - b) * vin_scaled + clamp(b) * ft
        
        # Step 7: Render (Transfer Function Lookup & Compositing)
        tf_ref = branch.tf_ref
        tf_val = clamp(vout, 0.0, 1.0)
        color_sample = tf_tex.sample(tf_ref, tf_val)
        alpha = color_sample[3]
        
        # Front-to-back compositing [G]
        weight = (1.0 - alpha_accum) * alpha
        color[0] += weight * color_sample[0]
        color[1] += weight * color_sample[1]
        color[2] += weight * color_sample[2]
        alpha_accum += weight
        
        if alpha_accum >= 1.0:
            break
            
    return color
```

## Subtopics

### Topology-Based Direct Volume Rendering
The parent method that applies topological segmentation to scalar fields to guide direct volume rendering attributes [S1, unofficial]. Hardware-Accelerated Topological Volume Rendering is a specific implementation of this concept using GPU textures and shaders [S1, unofficial]. [Link](8480-topology-based-direct-volume-rendering.md)

### Contour Tree Simplification
A preprocessing step often used in conjunction with this method to reduce the number of branches [S1, unofficial]. Simplification methods like hypervolume or manual pruning determine which branches are retained and which are scaled or pruned [S1, unofficial]. [Link](8480-topology-based-direct-volume-rendering.md)

## Operating characteristics
*   **Time Complexity:** The rendering step executes a fixed sequence of texture lookups and arithmetic operations per fragment [S1, unofficial]. The preprocessing step (contour tree construction, simplification, tube generation) is more complex but done offline [S1, unofficial].
*   **Memory Complexity:** Memory usage is dominated by the textures [S1, unofficial]. For the Chest CT dataset (384x384x240), 32 bits per voxel are used for the voxel-to-branch map, and 8 bits per voxel for the data itself [S1, unofficial].
*   **Measured Performance:** On an NVIDIA 7800 GPU, rendering the Chest CT dataset (384x384x240 voxels, simplified to 28 branches) at 512x512 resolution with approximately 1 sample per voxel per ray achieved interactive frame rates [S1, unofficial]. The Fuel dataset (64x64x64) and Nucleon dataset (41x41x41) were also rendered successfully [S1, unofficial].
*   **Strengths:** Enables real-time interaction with topological simplifications (pruning, scaling) [S1, unofficial]. Leverages GPU hardware for efficient texture lookups and blending [S1, unofficial].
*   **Limitations:** Requires significant preprocessing [S1, unofficial]. Limited by 3D texture dimensions, requiring workarounds for large branch arrays [S1, unofficial]. Tube width visibility depends on careful parameter tuning ($k > 1$) [S1, unofficial].
*   **When to Use:** When interactive exploration of topological features in large scalar fields is required, and the hardware supports 3D textures with sufficient resolution [S1, unofficial].
*   **When Not to Use:** When the scalar field is too large to fit in texture memory, or when the preprocessing time is prohibitive [S1, unofficial].

## Background
The method was introduced by J. Weber, P. Peine, M. Rost, and M. E. Papka in their paper "Topology-Controlled Volume Rendering" [S1, unofficial]. It builds upon earlier work in topological simplification and contour tree analysis [S1, unofficial]. The method was demonstrated on datasets such as Fuel, Nucleon, and Chest CT, showing its applicability to various scientific visualization domains [S1, unofficial].
