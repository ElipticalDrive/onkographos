# Gradient Shading
Also called: CT Viewer Volume Render, Phong Illumination with Gradient Lighting, Ray Casting with Gradient Shading, Volume Rendering with Gradient Shading, vzTMGradientShader

## Overview
Gradient Shading is a technique for Direct Volume Ray Casting that enhances surface perception by computing per-voxel lighting based on local intensity gradients, typically using the Phong illumination model [S2]. It builds on [Classified Volume Rendering](3590-classified-volume-rendering.md) by replacing simple opacity accumulation with physically-based shading, distinguishing itself from siblings like [Image-Centric Volume Rendering with SN-SVM Classification](7509-image-centric-volume-rendering-with-sn-svm-classification.md) by relying on explicit gradient vectors rather than learned classification boundaries [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume data texture ($V$), optional pre-computed gradient texture ($G$), transfer function (lookup table), light position, and Phong parameters (ambient, diffuse, specular, shininess) [S2].
*   **Output:** Rendered image with shaded colors [S2].

**Data Structures:**
*   **Volume Texture ($V$):** Standard 3D texture storing voxel intensities [S2].
*   **Gradient Texture ($G$):** 3D texture storing gradient vectors. Each voxel stores RGB values representing the $(a, b, c)$ coefficients of the gradient at that position [S2].
    *   Format: If pre-computed, stored as `vzParameterVolumeTexture` [S2].
    *   Internal format for non-GPU fallback: `VZ_INTENSITYn` where $n \in \{8, 12, 16\}$ [S2].

**Steps:**
1.  **Gradient Computation (Optional/Pre-computed):**
    *   If the application provides a gradient texture, it must compute the gradient for each voxel and add it to the shape's appearance [S2].
    *   If the gradient parameter is not specified on GPU systems supporting `ARB_fragment_program`, the shader computes gradients internally using central differencing [S2].
    *   *Note:* Using a separate gradient texture increases texture memory usage by a factor of 2 to 4 compared to the original volume texture [S2].

2.  **Ray Casting Loop:**
    *   For each pixel, cast a ray through the volume [S1, unofficial].
    *   Sample the volume texture $V$ at the current ray position to get voxel intensity $I$ [S1, unofficial].
    *   Apply the transfer function (lookup table) to map $I$ to color $(R, G, B)$ and opacity $\alpha$ [S2].

3.  **Lighting Calculation:**
    *   Retrieve the gradient vector $\vec{g}$ from the gradient texture $G$ at the current position [S2].
    *   Normalize $\vec{g}$ to obtain the surface normal $\vec{n}$ [S1, unofficial][S2].
    *   Calculate the light direction vector $\vec{l}$ from the surface point to the light source [S2].
    *   Compute the Phong shading components:
        *   Diffuse: $k_d (\vec{n} \cdot \vec{l})$
        *   Specular: $k_s (\vec{r} \cdot \vec{v})^{\text{shininess}}$, where $\vec{r}$ is the reflection vector and $\vec{v}$ is the view vector [S2].
    *   Combine with ambient light $k_a$ [S2].

4.  **Compositing:**
    *   Accumulate color and opacity using front-to-back or back-to-front blending [S1, unofficial].
    *   If `isGradient` is enabled and specific conditions are met (e.g., bone detection in CT data), apply the calculated lighting $L$ to modulate the color contribution [S1, unofficial].

**Parameters:**
*   `isGradient`: Boolean flag enabling/disabling gradient shading [S1, unofficial].
*   `isGradientInterpolation`: Boolean flag enabling/disabling gradient interpolation [S1, unofficial].
*   `lightSourceX`: Integer position of the light source along the X axis [S1, unofficial].
*   `gradient`: The gradient values, type `vzParameterVolumeTexture`. RGB values provide $(a, b, c)$ coefficients [S2].
*   `lightdir`: Light direction, type `vzParameterVec3f` [S2].
*   `ambient`: Ambient color, type `vzParameterVec3f` (optional) [S2].
*   `diffuse`: Diffuse color, type `vzParameterVec3f` (optional) [S2].
*   `specular`: Specular color, type `vzParameterVec3f` (optional) [S2].
*   `shininess`: Shininess exponent, type `vzParameterVec3f` (optional) [S2].
*   `lookup_table`: Transfer function lookup table, type `vzParameterLookupTable` [S2].

**Pseudocode:**
```python
def render_gradient_shading(volume_texture, gradient_texture, light_pos, ambient, diffuse, specular, shininess, is_gradient_enabled):
    # Initialize output image
    image = create_empty_image()
    
    for each pixel (x, y) in image:
        ray_origin, ray_direction = generate_ray(x, y)
        alpha_accum = 0.0
        color_accum = [0.0, 0.0, 0.0]
        
        # Ray marching through volume
        t = 0.0
        while t < max_depth:
            pos = ray_origin + t * ray_direction
            voxel_intensity = sample_volume(volume_texture, pos)
            
            # Get gradient for normal calculation
            if is_gradient_enabled:
                if gradient_texture is not None:
                    gradient_vec = sample_volume(gradient_texture, pos)
                else:
                    # GPU fallback: compute central difference internally
                    gradient_vec = compute_central_difference(volume_texture, pos)
                
                # Normalize gradient to get surface normal
                normal = normalize(gradient_vec)
                
                # Calculate lighting
                light_dir = normalize(light_pos - pos)
                view_dir = normalize(-ray_direction)
                
                # Phong model
                diff = max(dot(normal, light_dir), 0.0)
                reflect_dir = reflect(-light_dir, normal)
                spec = pow(max(dot(reflect_dir, view_dir), 0.0), shininess)
                
                lighting = ambient + diffuse * diff + specular * spec
            else:
                lighting = 1.0 # No shading
            
            # Apply transfer function
            color, alpha = apply_transfer_function(voxel_intensity)
            
            # Composite
            # Front-to-back blending
            alpha_contrib = alpha * (1.0 - alpha_accum)
            color_accum += color * lighting * alpha_contrib
            alpha_accum += alpha_contrib
            
            if alpha_accum >= 1.0:
                break
                
            t += step_size
            
        image.set_pixel(x, y, color_accum)
        
    return image
```

**Edge Cases and Pitfalls:**
*   **Non-GPU Systems:** On systems without `ARB_fragment_program` support, `specular` and `shininess` parameters have no effect [S2].
*   **Legacy Shading:** On systems without `ARB_fragment_program` or `ATI_fragment_shader`, shading uses destination alpha to compute gradient lighting. This requires `ARB_imaging` extensions and the gradient texture internal format `VZ_INTENSITYn` ($n=8, 12, 16$) [S2].
*   **Memory Usage:** Using a separate gradient texture increases texture memory usage by a factor of 2 to 4 compared to the original volume texture [S2].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot R)$, where $N$ is the number of pixels and $R$ is the number of samples per ray. Gradient computation adds overhead if done per-voxel during rendering or requires pre-computation.
*   **Memory Complexity:** $O(V + G)$, where $V$ is the volume texture size and $G$ is the gradient texture size. $G$ can be 2-4 times the size of $V$ [S2].
*   **Strengths:** Provides more accurate lighting effects than tangent-space shading and avoids bricking artifacts associated with shape bricking [S2]. Enhances surface perception in volume rendering [S2].
*   **Limitations:** Increased memory usage [S2]. Dependent on hardware support for advanced OpenGL extensions for full feature set (specular/shininess) [S2].
*   **When to use:** When surface detail and depth perception are critical, and sufficient memory is available.
*   **When not to use:** When memory is constrained or hardware does not support required OpenGL extensions and specular lighting is desired.

## Background
Gradient Shading in volume rendering is implemented via shaders such as `vzTMGradientShader` in SGI OpenGL Volumizer [S2]. It was introduced in versions prior to OpenGL Volumizer 2.1 for related tagging shaders, indicating its integration into the Volumizer framework [S2]. The method leverages the Phong illumination model to compute diffuse and specular contributions based on per-voxel gradient information [S2]. It is used in medical imaging applications, such as CT viewer volume rendering, to enhance the visualization of anatomical structures [S1, unofficial].
