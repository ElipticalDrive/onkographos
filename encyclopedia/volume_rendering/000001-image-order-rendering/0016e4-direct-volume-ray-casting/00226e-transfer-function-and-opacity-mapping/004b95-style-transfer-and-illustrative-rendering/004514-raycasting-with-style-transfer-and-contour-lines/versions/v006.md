# Raycasting with Style Transfer and Contour Lines

Also called: FGC_T3 Raycasting, Style-based Volume Raycasting

## Overview
This method performs direct volume ray casting augmented with artistic style transfer and contour line rendering to produce illustrative visualizations. It differs from standard ray casting by mapping surface normals and material indices to a 2D array texture of artistic styles, and by selectively applying matcap-based contour lines based on local curvature and view angle [S1, unofficial]. It builds on [Style Transfer and Illustrative Rendering](13031-style-transfer-and-illustrative-rendering.md).

## How it works
**Inputs and Outputs**
*   **Inputs**:
    *   Volume data: 3D texture `VolumeTex` (sampler3D) containing scalar density values.
    *   Geometry: `EntryPoint` (vec3) and `ExitPoints` (sampler2D) defining ray start and end positions per fragment.
    *   Transfer Functions: `transferFunctionTexture` (sampler1D) mapping density to opacity (green channel) and material index (red channel); `indexFunctionTexture` (sampler1D) mapping material index to style index.
    *   Style Data: `styleTransferTexture` (sampler2DArray) containing pre-rendered artistic styles indexed by normal and material.
    *   Parameters: `StepSize` (float, default 0.01), `Threshold` (float, default 0.15), `AVAILABLE_STYLE_COUNT` (int, value 34), `NormalMatrix` (mat4), `ScreenSize` (vec2).
*   **Outputs**:
    *   `FragColor` (vec4): The final composited color and opacity.

**Data Structures**
*   `EntryPoint`: A `vec3` attribute or uniform representing the camera-space entry point of the ray into the volume.
*   `ExitPoints`: A 2D texture where each texel stores the `vec3` exit point for the corresponding screen coordinate.
*   `transferFunctionTexture`: A 1D texture. Each texel stores `(index, opacity, 0, 0)`. The red channel (`r`) is the material index, and the green channel (`g`) is the raw opacity.
*   `indexFunctionTexture`: A 1D texture mapping material indices to style indices.
*   `styleTransferTexture`: A 2D array texture. The first two dimensions represent the normalized normal vector (litsphere projection), and the third dimension (array layer) represents the style index.

**Algorithm Steps**
1.  **Ray Initialization**:
    *   Retrieve the exit point from the `ExitPoints` texture using normalized fragment coordinates: $\mathbf{p}_{exit} = \text{texture}(\text{ExitPoints}, \frac{\mathbf{gl\_FragCoord.st}}{\text{ScreenSize}}).xyz$.
    *   If $\mathbf{p}_{entry} == \mathbf{p}_{exit}$, discard the fragment (background).
    *   Compute ray direction $\mathbf{d} = \mathbf{p}_{exit} - \mathbf{p}_{entry}$ and length $L = \|\mathbf{d}\|$.
    *   Compute step vector $\mathbf{s} = \text{StepSize} \cdot \frac{\mathbf{d}}{L}$.
    *   Initialize ray position $\mathbf{p} = \mathbf{p}_{entry}$. If noise jittering is enabled, add jitter: $\mathbf{p} \leftarrow \mathbf{p} + \mathbf{s} \cdot \text{snoise}(\frac{\mathbf{gl\_FragCoord.xy}}{2.5})$.
    *   Initialize accumulators: destination color/opacity $\mathbf{c}_{dst} = (0,0,0,0)$, current normal $\mathbf{n} = (1,0,0)$, base style color $\mathbf{c}_{base} = (0,0,0,0)$.

2.  **Ray Marching Loop**:
    While $\mathbf{c}_{dst}.a < 1.0$ and $L > 0$:
    *   Sample volume density $v = \text{texture}(\text{VolumeTex}, \mathbf{p}).x$.
    *   If `USE_THRESHOLD` is defined and $v \le \text{Threshold}$, skip to next step.
    *   Sample transfer function: raw opacity $\alpha_{raw} = \text{texture}(\text{transferFunctionTexture}, v).g$ and material index $idx = \text{texture}(\text{transferFunctionTexture}, v).r$.
    *   Determine style index: $styleIdx = \lfloor \text{texture}(\text{indexFunctionTexture}, idx).x \cdot \text{AVAILABLE\_STYLE\_COUNT} \rfloor$.
    *   Compute gradient $\nabla v$ at $\mathbf{p}$ using central differences with step size $h = \text{StepSize}$:
        $$ \nabla v = \begin{bmatrix} v(x+h, y, z) - v(x-h, y, z) \\ v(x, y+h, z) - v(x, y-h, z) \\ v(x, y, z+h) - v(x, y, z-h) \end{bmatrix} $$
        [G] Note: The source code uses forward differences relative to a lookup value, but standard gradient estimation for normals typically uses central differences or symmetric differences. The provided code snippet `computeGradient` uses `texture(P + vec3(L,0,0)) - lookUp`, which implies a specific implementation detail. We follow the source's logic: $\nabla v_x = V(\mathbf{p} + (h,0,0)) - V(\mathbf{p})$, etc., where $V(\mathbf{p})$ is the current density.
    *   Transform normal: $\mathbf{n}_{new} = \text{NormalMatrix} \cdot \begin{bmatrix} \nabla v_x \\ \nabla v_y \\ \nabla v_z \\ 0 \end{bmatrix}$.
    *   Map normal to 2D litsphere coordinates: $\mathbf{u} = \begin{bmatrix} n_x \\ -n_y \end{bmatrix} \cdot 0.5 + 0.5$.
    *   Sample style color: $\mathbf{c}_{base} = \text{texture}(\text{styleTransferTexture}, \begin{bmatrix} \mathbf{u} \\ styleIdx \end{bmatrix})$.

3.  **Contour Line Application**:
    *   If `USE_CONTOUR` is defined:
        *   Calculate curvature approximation using the angle between the current normal $\mathbf{n}_{new}$ and the previous normal $\mathbf{n}_{old}$:
            $$ \kappa = \arccos\left(\frac{\mathbf{n}_{new} \cdot \mathbf{n}_{old}}{\|\mathbf{n}_{new}\| \|\mathbf{n}_{old}\|}\right) \cdot \text{StepSize} $$
        *   Calculate contour condition threshold: $T_{kv} = \text{thickness} \cdot \kappa$ (where `thickness` is 1.0).
        *   Calculate contour mask: $C = \sqrt{T_{kv} (2 - T_{kv})}$.
        *   Calculate view dot product: $n \cdot V = |\mathbf{n}_{new} \cdot \frac{-\mathbf{p}}{\|\mathbf{p}\|}|$.
        *   If $n \cdot V \le C$:
            *   Calculate lighting delta: $\Delta L = 1 - \min(1, \frac{C - n \cdot V}{C})$.
            *   Adjust length: $L_{adj} = \min(1, \frac{\|\mathbf{n}_{new}\|}{\Delta L})$.
            *   Sample matcap style: $\mathbf{c}_{base} = \text{texture}(\text{styleTransferTexture}, \begin{bmatrix} \text{matcap}(\mathbf{p}, \mathbf{n}_{new}).xy \\ styleIdx \end{bmatrix})$.

4.  **Compositing**:
    *   Set source color: $\mathbf{c}_{src} = (\mathbf{c}_{base}.rgb, \alpha_{raw})$.
    *   Pre-multiply alpha: $\mathbf{c}_{src}.rgb \leftarrow \mathbf{c}_{src}.rgb \cdot \mathbf{c}_{src}.a$.
    *   Composite: $\mathbf{c}_{dst} = (1 - \mathbf{c}_{dst}.a) \mathbf{c}_{src} + \mathbf{c}_{dst}$.
    *   Advance ray: $\mathbf{p} \leftarrow \mathbf{p} + \mathbf{s}$, $L \leftarrow L - \text{StepSize}$.

5.  **Output**:
    *   Set `FragColor` = $\mathbf{c}_{dst}$.

**Pseudocode**
```python
def raycast_with_style_transfer_and_contour_lines(
    volume_tex, exit_points_tex, transfer_func_tex, index_func_tex, style_tex,
    entry_point, normal_matrix, step_size, threshold, available_style_count,
    use_threshold, use_contour, thickness=1.0
):
    # 1. Ray Initialization
    # Get exit point from texture based on fragment coordinates
    exit_point = exit_points_tex.sample_normalized()
    
    if entry_point == exit_point:
        return vec4(0, 0, 0, 0) # Discard background

    ray_direction = exit_point - entry_point
    ray_length = length(ray_direction)
    step_vector = step_size * normalize(ray_direction)
    
    # Initialize noise jitter if needed
    ray_start = entry_point
    if USE_NOISE_JITTER:
        ray_start += step_vector * snoise(gl_FragCoord.xy / 2.5)
        
    pos = ray_start
    dst = vec4(0.0)
    normal = vec3(1.0, 0.0, 0.0)
    
    # 2. Ray Marching
    while dst.a < 1.0 and ray_length > 0.0:
        density = volume_tex.sample(pos).x
        
        if use_threshold and density <= threshold:
            pos += step_vector
            ray_length -= step_size
            continue
            
        # Sample transfer function
        tf_sample = transfer_func_tex.sample(density)
        opacity = tf_sample.g
        index = tf_sample.r
        
        # Determine style index
        idx_sample = index_func_tex.sample(index)
        style_index = int(idx_sample.x * available_style_count)
        
        # Compute gradient
        # Using forward differences as per source implementation details
        look_up = density
        grad_x = volume_tex.sample(pos + vec3(step_size, 0, 0)).x - look_up
        grad_y = volume_tex.sample(pos + vec3(0, step_size, 0)).x - look_up
        grad_z = volume_tex.sample(pos + vec3(0, 0, step_size)).x - look_up
        gradient = vec3(grad_x, grad_y, grad_z)
        
        # Transform normal
        prev_normal = normal
        normal = (normal_matrix * vec4(gradient, 0.0)).xyz
        
        # Map normal to litsphere
        litsphere_coords = vec2(normal.x, -normal.y) * 0.5 + 0.5
        
        # Sample base style
        base_color = style_tex.sample(vec3(litsphere_coords, float(style_index)))
        
        # Contour Lines
        if use_contour:
            magnitudes = length(normal) * length(prev_normal)
            if magnitudes > 0:
                curvature = acos(dot(normal, prev_normal) / magnitudes) * step_size
            else:
                curvature = 0.0
                
            t_kv = thickness * curvature
            cond = sqrt(t_kv * (2.0 - t_kv))
            
            view_dir = normalize(-pos)
            n_dot_v = abs(dot(normal, view_dir))
            
            if n_dot_v <= cond:
                lit_delta = 1.0 - min(1.0, (cond - n_dot_v) / cond)
                # matcap function returns 2D coords from position and normal
                matcap_coords = matcap(pos, normal).xy
                base_color = style_tex.sample(vec3(matcap_coords, float(style_index)))
                
        # Composite
        src = vec4(base_color.rgb, opacity)
        src.rgb *= src.a
        dst = (1.0 - dst.a) * src + dst
        
        pos += step_vector
        ray_length -= step_size
        
    return dst
```

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of samples per ray, which depends on the volume extent and `StepSize`. The style lookup is constant time $O(1)$ per sample.
*   **Memory Complexity**: Dominated by the `styleTransferTexture` (2D array). With 34 styles and typical resolution (e.g., 256x256 per style), this requires significant VRAM. The volume data and transfer functions are standard.
*   **Performance**: The method is GPU-intensive due to multiple texture lookups per sample (volume, transfer function, index function, style array). Contour calculations add minor arithmetic overhead.
*   **Strengths**: Produces high-quality artistic illustrations with consistent style application across surfaces. Contour lines enhance structural perception.
*   **Limitations**: Requires pre-computed style textures. The curvature approximation for contours is sensitive to `StepSize` and may produce artifacts if sampling is too coarse. The use of forward differences for gradients may reduce normal accuracy compared to central differences.

## Background
This method originates from the FGC_T3 project, an implementation of illustrative volume rendering techniques. It was developed by Jose Villegas and made available on GitHub [S1, unofficial]. The technique combines direct volume ray casting with style transfer mechanisms inspired by image-based rendering and material appearance modeling.
