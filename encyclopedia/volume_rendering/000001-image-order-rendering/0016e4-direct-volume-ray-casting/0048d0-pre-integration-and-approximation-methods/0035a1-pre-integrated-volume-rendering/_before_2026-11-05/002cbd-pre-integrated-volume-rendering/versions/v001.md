# Pre-integrated Volume Rendering

Also called: Hardware-Accelerated Pixel Shading for Volume Rendering, PIVR, Pre-integrated Classification

## Overview
Pre-integrated Volume Rendering (PIVR) is a technique that accelerates direct volume ray casting by pre-computing the results of the volume rendering integral for a ray segment and storing them in a lookup table for runtime retrieval [S1, unofficial][S2][S3, unofficial]. It solves the problem of high-frequency artifacts and performance bottlenecks caused by non-linear transfer functions in standard discrete ray casting [S1, S3, unofficial]. Unlike standard methods that sample point-by-point, PIVR renders the volume segment-by-segment, separating the integration of the continuous scalar field from the transfer function parameters [S2][S3, unofficial]. This approach achieves the image quality of post-shading techniques with far fewer slices and avoids the need for additional interpolated slices [S3, unofficial].

## How it works
**Inputs:**
*   Volume data (scalar field).
*   Transfer function (mapping scalar values to color $C$ and opacity $\alpha$).
*   Camera parameters (ray origin, direction).
*   Ray segment length (assumed constant for performance [S1, unofficial]).

**Outputs:**
*   Final image color per pixel.

**Data Structures:**
*   **Lookup Table (LUT):** A 2D texture or array storing pre-computed color and opacity values. The indices correspond to the scalar values at the start and end of a ray segment, and potentially the segment length [S1, unofficial].
*   **Scalar Field Samples:** Discrete values $s_i$ sampled along the ray [S1, unofficial].

**Method Steps:**

1.  **Pre-computation (Offline/Update):**
    *   The volume rendering integral is split into two parts: one for the continuous scalar field and one for the transfer function parameters (colors and extinction coefficient $\tau(\lambda)$) [S2].
    *   For a given ray segment of length $L$, assume a piecewise linear scalar field between the start scalar value $s_{start}$ and end scalar value $s_{end}$ [S1, unofficial].
    *   Numerically integrate the volume rendering equation over this segment for all possible combinations of $s_{start}$, $s_{end}$, and $L$ [S1, unofficial].
    *   Store the resulting accumulated color and opacity in the Lookup Table [S1, unofficial].
    *   *Note:* The LUT must be refreshed whenever the transfer function is modified by the user [S1, unofficial].

2.  **Rendering (Runtime):**
    *   Sample the scalar field along the viewing ray [S1, unofficial]. This sampling has its own Nyquist frequency, independent of the transfer function [S1, unofficial].
    *   For each ray segment, identify the scalar values at the start ($s_{front}$ or $s_f$) and end ($s_{back}$ or $s_b$) of the segment [S3, unofficial].
    *   Perform a lookup in the pre-computed table using $s_{front}$, $s_{back}$, and the segment length to retrieve the pre-integrated color and opacity for that segment [S1, unofficial].
    *   Composite the segment results using front-to-back compositing [S2][S3, unofficial].

**Formulas:**
The standard front-to-back compositing equations are used for the final accumulation [S2][S3, unofficial]:
$$ C'_i = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i $$
$$ \alpha'_i = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i $$
Where $(C_i, \alpha_i)$ are the color and opacity retrieved from the LUT for segment $i$, rather than computed from a single sample.

**Parameters:**
*   **Ray Segment Length:** Assumed constant to improve performance [S1, unofficial].
*   **Transfer Function:** Must be non-linear to benefit from pre-integration; the method reduces under-sampling artifacts caused by TF non-linearity [S2].

**Edge Cases and Pitfalls:**
*   **LUT Construction Time:** Constructing the color lookup table is time-consuming [S2].
*   **Hardware Interpolation Mapping:** In hardware implementations using Register Combiners, interpolation values are stored in the range of 0.5 to 1.0, requiring proper input and output mappings to obtain correct interpolation [S3, unofficial].
*   **Off-center Pixels:** Path length differences for off-center pixels must be handled, as the assumption of constant segment length may vary slightly [S1, unofficial].

**Pseudocode:**

```python
import math

def precompute_lut(transfer_function, segment_length, scalar_range_min, scalar_range_max, resolution):
    """
    Pre-computes the lookup table for a given segment length and transfer function.
    Returns a 2D array LUT where LUT[i][j] contains (color, opacity) for scalar values
    corresponding to indices i and j.
    """
    # Define scalar values for the start and end of the segment
    scalars = [scalar_range_min + (scalar_range_max - scalar_range_min) * (i / (resolution - 1)) for i in range(resolution)]
    
    lut = [[None for _ in range(resolution)] for _ in range(resolution)]
    
    for i, s_start in enumerate(scalars):
        for j, s_end in enumerate(scalars):
            # Integrate the volume rendering equation for the segment from s_start to s_end
            # with length = segment_length
            # This involves numerical integration of the piecewise linear scalar field
            # and the transfer function over the segment [S1, unofficial][S2]
            color, opacity = integrate_segment(s_start, s_end, segment_length, transfer_function)
            lut[i][j] = (color, opacity)
            
    return lut

def integrate_segment(s_start, s_end, length, transfer_function):
    """
    Numerically integrates the volume rendering equation for a segment.
    Assumes a piecewise linear scalar field between s_start and s_end [S1, unofficial].
    """
    # Discretize the segment into small steps for integration
    num_steps = 100
    step_size = length / num_steps
    
    accumulated_color = [0.0, 0.0, 0.0]
    accumulated_opacity = 0.0
    
    for k in range(num_steps):
        t = k * step_size
        # Interpolate scalar value along the segment
        # Linear interpolation between s_start and s_end
        t_norm = t / length
        s_current = s_start * (1 - t_norm) + s_end * t_norm
        
        # Get color and opacity from transfer function
        color, opacity = transfer_function(s_current)
        
        # Front-to-back compositing for the small step
        # Note: This is the internal integration step, not the final ray compositing
        weight = (1.0 - accumulated_opacity) * opacity
        accumulated_color[0] += weight * color[0]
        accumulated_color[1] += weight * color[1]
        accumulated_color[2] += weight * color[2]
        accumulated_opacity += weight
        
    return accumulated_color, accumulated_opacity

def render_volume_piv(volume_data, camera, transfer_function, lut, segment_length, scalar_range_min, scalar_range_max, resolution):

    """
    h, w = camera.screen_height, camera.screen_width
    image = [[None for _ in range(w)] for _ in range(h)]
    
    # Helper to map scalar value to LUT index
    def scalar_to_index(s):
        # Clamp s to range
        s = max(scalar_range_min, min(scalar_range_max, s))
        idx = int((s - scalar_range_min) / (scalar_range_max - scalar_range_min) * (resolution - 1))
        return max(0, min(resolution - 1, idx))
```

## Subtopics

### Hardware-Accelerated PIVR
Uses GPU texture units and register combiners to perform the lookup and interpolation in hardware, reducing the CPU overhead of LUT construction and runtime evaluation [S3, unofficial].

### Adaptive Pre-Integration
Variants that adjust segment lengths or LUT resolution based on local volume properties to balance quality and performance [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Pre-computation is $O(N^2)$ where $N$ is the resolution of the LUT, which is time-consuming [S2]. Runtime rendering is $O(1)$ per segment for the lookup, plus compositing overhead.
*   **Memory Complexity:** Requires storage for the LUT, which can be large depending on the resolution and number of segment lengths supported [S1, unofficial].
*   **Performance:** Achieved 4 fps for a 256x256 viewport using a 200 MHz CPU and an nVidia GeForce3 [S1, unofficial].
*   **Strengths:** Improves image quality by decreasing under-sampling artifacts compared to pre- and post-classification [S2]. Provides high image quality for low-resolution volume data and non-linear transfer functions with high frequencies without the performance overhead of rendering additional interpolated slices [S3, unofficial].
*   **Limitations:** Constructing the color lookup table is time-consuming [S2]. Requires constant ray segment lengths for optimal performance [S1, unofficial].

## Background
Pre-integrated volume rendering was introduced by Klaus Engel et al. in 2001 [S1, S3, unofficial]. It builds on ideas from Röttger et al. [Röttger00] and was later extended for regular grids [S1, unofficial]. The method was designed to overcome the problem of high Nyquist frequencies resulting from non-linear transfer functions in standard texture-mapping-based volume rendering [S1, unofficial]. It was later combined with volumetric clipping and advanced lighting effects by Röttger et al. [Röttger03] [S1, unofficial].
