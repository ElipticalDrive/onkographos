# Direct volume ray casting

Also called: Direct Volume Rendering (DVR), Ray Casting, Ray Marching

## Overview
Direct volume ray casting is an image-order rendering technique that casts a ray through a 3D volume for every pixel, sampling scalar values, mapping them to RGBA via a transfer function, and compositing samples front-to-back using alpha blending to produce the final image [S2, S3, unofficial]. It differs from [Isosurface and first-hit ray casting](20-isosurface-and-first-hit-ray-casting.md) by allowing all voxels to contribute to the final image rather than stopping at the first opaque surface [S1, unofficial], and from [Distance-field ray marching](21-distance-field-ray-marching.md) by using uniform step sizes rather than distance-field-guided steps [G]. It replaces slice-stack methods by providing a solid volume appearance from any angle without edge-on gaps [S3, unofficial].

## Shared principles
The method relies on the volume rendering integral, discretized into a summation over sample points along a ray [S5, unofficial]. The ray $r$ is parameterized by $\rho_r(\bar{\rho}) : \bar{R} \rightarrow \bar{R}^2$, entering the volume at $\bar{\rho} = 0$ and exiting at $\bar{\rho} = D$ [Volume Raycasting Discretization](831-volume-raycasting-discretization.md). The data model is sampled using $s(\bar{\rho})$ [Volume Raycasting Discretization](831-volume-raycasting-discretization.md).

The compositing is performed front-to-back [S2, S3, S5, unofficial]. Let $C'_i$ be the accumulated color and $\alpha'_i$ be the accumulated opacity after sample $i$, with initial conditions $C'_0 = 0$ and $\alpha'_0 = 0$ [S2, S5, unofficial]. For each sample $i$ along the ray:
1.  Sample the volume at the current ray position to get a scalar value $d_i$ [S2, S5, unofficial].
2.  Apply a transfer function to map the scalar value to color $C_i$ and opacity $\alpha_i$ [S2, S5, unofficial].
3.  Update accumulated color:
    $$ C'_i = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i $$
4.  Update accumulated opacity:
    $$ \alpha'_i = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i $$
5.  If $\alpha' \ge 1$ (or a specific threshold, typically 99%) [S2, S3, unofficial], terminate the ray (early ray termination) [S2, S3, S4, unofficial].

Rays are cast from the eyepoint, one for each pixel [S1, S4, unofficial]. The volume is typically represented as a 3D texture [S4, S3, unofficial]. Gradients for shading are calculated using a central difference operator [S1, S4, unofficial]. To avoid normal discontinuities that cause visible rings on smooth surfaces, the gradient is computed using a two-voxel offset rather than a one-voxel offset [S1, S3, unofficial]. Sampling is performed using trilinear interpolation [S1, S5, unofficial]. A fixed random offset is applied to each ray's start position to prevent sample layers from appearing as bands [S3, unofficial]. The final accumulated color is typically corrected with gamma 2.2 [S2, unofficial].

```python
def direct_volume_raycast(volume_texture, camera, transfer_function, step_size=0.001, threshold=0.99):
    # Initialize output image
    image = zeros_like(camera.screen)
    
    for pixel in camera.screen:
        ray_origin, ray_direction = camera.cast_ray(pixel)
        accumulated_color = vec3(0.0)
        accumulated_opacity = 0.0
        
        # Ray initialization: fixed random offset to prevent banding [S3, unofficial]
        t = random_float(0.0, step_size)
        
        while accumulated_opacity < threshold and t < ray_length:
            # Sample volume at current position using trilinear interpolation [S1, S5, unofficial]
            scalar_value = volume_texture.sample_trilinear(ray_origin + t * ray_direction)
            
            # Apply transfer function to get color and opacity [S2, S5, unofficial]
            color, opacity = transfer_function(scalar_value)
            
            # Front-to-back compositing [S2, S5, unofficial]
            accumulated_color += (1.0 - accumulated_opacity) * opacity * color
            accumulated_opacity += (1.0 - accumulated_opacity) * opacity
            
            t += step_size
            
        # Gamma correction [S2, unofficial]
        image[pixel] = pow(accumulated_color, vec3(1.0/2.2))
        
    return image
```

### Distance Color Blending
A technique to enhance depth perception by dimming colors and shifting them towards a background color (often blue for aerial perspective) as they recede from the viewer [S6, unofficial]. It uses an exponential function for non-linear progression [S6, unofficial].
1.  Determine fraction of distance through volume $d_v$ for the sample [S6, unofficial].
2.  Calculate blending factor $B = k_{ds} d_v^{k_{de}}$ [S6, unofficial].
3.  Compute final color $c_d = (1 - B) c_v + B c_b$ [S6, unofficial].
4.  Use $c_d$ as the final color [S6, unofficial].

Formula:
$$ c_d = (1 - k_{ds} d_v^{k_{de}}) c_v + k_{ds} d_v^{k_{de}} c_b $$
where $c_d$ is the depth-cued color, $c_v$ is the original voxel color, $c_b$ is the background color, $d_v$ is the fraction of distance through the volume, $k_{ds}$ controls the size/magnitude of the blending effect, and $k_{de}$ controls the rate of application (exponent) [S6, unofficial].
Parameters: $c_b$ is the background color. If grey $(a,a,a)$, only intensity dimming occurs. If blue $(a,b,c)$ with $c>a,b$, a cool shift is introduced [S6, unofficial].

## Background
The term "direct volume rendering" was coined by Marc Levoy in his 1988 paper "Display of Surfaces from Volume Data" [S1, S4, unofficial]. Levoy defined the volume rendering pipeline, which remains an influential framework [S1, unofficial]. The technique was originally designed to display weak or fuzzy surfaces with smooth silhouettes and few aliasing artifacts [S1, unofficial].

Historically, it evolved from slice-stack methods, which showed gaps when viewed edge-on [S3, unofficial]. GPU-based implementations, such as ray marching, were developed to perform the traversal efficiently within fragment shaders, outperforming CPU-based Shear-Warp methods in both speed and image quality [S4, unofficial]. For example, GPU ray marching achieved 48 fps for a Skull model with 400 steps, compared to 10 fps for Shear-Warp [S4, unofficial]. It is used in medical imaging visualization, such as in the quick_dicom project [S3, unofficial].
