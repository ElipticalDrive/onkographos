# Splatting for Anti-aliasing Small Cells

Also called: Anti-Aliased Ellipsoidal Splats, Anti-Aliasing for Small Cells via Splatting, Anti-aliased Splatting for Small Cells, Gaussian Splatting for Small Cells, Gaussian ellipsoid splatting, Small cell anti-aliasing, Splatting Anti-Aliasing

## Overview
This method prevents the loss of geometric detail in adaptive meshes by rendering small cells as anti-aliased ellipsoidal splats instead of polygons [S1, S2][S3, unofficial]. It solves the problem where small cells are missed between slice planes or by pixel samples during scan conversion, which would otherwise result in missing important high-gradient features [S1, S2][S3, unofficial]. Unlike sibling methods that rely on post-processing filters or motion blur, this approach integrates anti-aliasing directly into the object-order rendering pipeline by convolving the splat footprint with a Gaussian presampling filter [S1, S2][S3, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   A set of polyhedral cells from an adaptive mesh [S1, S2][S3, unofficial].
*   A volume threshold $V_{th}$ [S1, S2][S3, unofficial].
*   A transfer function mapping cell properties to RGBA color and opacity [S1, S2][S3, unofficial].
*   A slicing direction and a set of parallel slice planes [S1, S2][S3, unofficial].
*   A camera view and image resolution [S1, S2][S3, unofficial].

**Outputs:**
*   A composited image where small cells are rendered as smooth, anti-aliased splats and large cells as polygons [S1, S2][S3, unofficial].

### Data Structures
*   **Cell:** Contains vertex coordinates, volume $V$, and center of gravity (centroid) $C$ [S1, S2][S3, unofficial].
*   **Splat:** Defined by its centroid $C$, a Gaussian ellipsoid shape approximating the cell, and an enlarged 2D footprint [S1, S2][S3, unofficial].
*   **Texture Map:** A 2D texture object containing a sequence of textured rectangles from consecutive slices, created per slicing direction [S1, S2][S3, unofficial].
*   **Stencil Buffer:** A buffer recording the presence of large cell polygons to prevent splat overlap [S1, S2][S3, unofficial].

### Parameters
*   **Volume Threshold ($V_{th}$):** Cells with volume $V < V_{th}$ are splatted; others are sliced [S1, S2][S3, unofficial]. The exact value is not specified in the sources [G].
*   **Gaussian Presampling Filter:** A Gaussian filter applied in the image plane to enlarge the splat footprint for anti-aliasing [S1, S2][S3, unofficial]. The standard deviation is not specified [G].

### Steps

1.  **Classification:** For each cell, compare its volume $V$ to the threshold $V_{th}$ [S1, S2][S3, unofficial].
    *   If $V \ge V_{th}$, mark as **Large**.
    *   If $V < V_{th}$, mark as **Small** [S1, S2][S3, unofficial].

2.  **Assignment:** For each Small cell, assign it to the closest slice plane [S1, S2][S3, unofficial].

3.  **Splat Fitting:** Fit each Small cell with a Gaussian ellipsoid that approximates its shape [S1, S2][S3, unofficial].
    *   *Note:* In a curvilinear grid with a slowly varying Jacobian derivative matrix, these splats sum to near unity at any point, smoothly interpolating the scalar field [S1, S2][S3, unofficial].

4.  **Footprint Enlargement:** Convolve the "footprint" projection of each splat with a Gaussian presampling filter in the image plane to create an enlarged 2D splat [S1, S2][S3, unofficial].

5.  **Preprocessing (Texture Map Creation):**
    a.  Sort Small cells closest to each slice by the depth of their centers of gravity [S1, S2][S3, unofficial].
    b.  Splat them into an image in back-to-front order [S1, S2][S3, unofficial].
    c.  Read back the image and determine a rectangle enclosing its non-zero values [S1, S2][S3, unofficial].
    d.  Create texture maps per slicing direction, containing as many textured rectangles from consecutive slices as would fit [S1, S2][S3, unofficial].
    e.  Load these texture maps into texture objects [S1, S2][S3, unofficial].

6.  **Interactive Rendering:**
    a.  Bind the texture map for the current slicing direction [S1, S2][S3, unofficial].
    b.  Render polygons for Large cells in the current slice, recording their presence in a stencil buffer [S1, S2][S3, unofficial].
    c.  Position the rectangle representing the Small cell splats on the slice plane [S1, S2][S3, unofficial].
    d.  Composite the splats using texture mapping, applying a stencil test restricted to regions where polygons are absent [S1, S2][S3, unofficial].
    e.  The splat color is determined by multiplying a 2D circular Gaussian texture by an RGBA color derived from the transfer function, cell volume, and enlarged footprint size [S1, S2][S3, unofficial].

### Pseudocode

```python
def render_small_cells(cells, slice_planes, transfer_function, threshold, image_size):
    """
    Renders small cells as anti-aliased splats.
    """
    small_cells = []
    large_cells = []
    
    # Step 1: Classification
    for cell in cells:
        if cell.volume < threshold:
            small_cells.append(cell)
        else:
            large_cells.append(cell)
            
    # Step 2 & 3: Assignment and Fitting
    # Assign small cells to closest slice plane and fit with Gaussian ellipsoid
    splats = []
    for cell in small_cells:
        closest_plane = find_closest_slice_plane(cell.centroid, slice_planes)
        # Fit Gaussian ellipsoid approximating cell shape
        ellipsoid = fit_gaussian_ellipsoid(cell)
        splats.append({
            'cell': cell,
            'plane': closest_plane,
            'ellipsoid': ellipsoid,
            'centroid': cell.centroid
        })
        
    # Step 4: Footprint Enlargement
    # Convolve footprint with Gaussian presampling filter
    for splat in splats:
        splat.footprint = convolve_gaussian(splat.ellipsoid.projection, gaussian_filter)
        
    # Step 5: Preprocessing
    # Sort by depth of centroid
    splats.sort(key=lambda s: s.centroid.depth)
    
    # Splat into image to find bounding rectangles
    # Note: This step implies a software render or simulation to find bounds
    texture_maps = []
    for plane in slice_planes:
        plane_splats = [s for s in splats if s.plane == plane]
        # Determine rectangle enclosing non-zero values of splats on this plane
        rect = find_bounding_rectangle(plane_splats)
        # Create texture map entry
        texture_maps.append({
            'plane': plane,
            'rect': rect,
            'splats': plane_splats
        })
        
    # Create texture objects
    texture_objects = create_texture_objects(texture_maps)
    
    # Step 6: Interactive Rendering
    for plane in slice_planes:
        # Bind texture map for current plane
        bind_texture(texture_objects[plane])
        
        # Render large cells and record in stencil buffer
        render_large_cells(large_cells, plane, stencil_buffer=ON)
        
        # Render small cell splats
        for splat in plane_splats:
            # Calculate RGBA color from transfer function, volume, footprint
            color = transfer_function(splat.cell.volume, splat.footprint.size)
            
            # Render rectangle with Gaussian texture and stencil test
            render_rectangle(
                rect=splat.rect,
                texture=GaussianTexture,
                color=color,
                stencil_test=STENCIL_TEST_ARENA_POLYGONS_ABSENT
            )
```

### Edge Cases and Pitfalls
*   **Precision:** The method relies on accurate calculation of cell volume and centroid depth [S1, S2][S3, unofficial].
*   **Boundaries:** The stencil test ensures splats do not overlap fully opaque polygon regions, preventing double-counting of opacity [S1, S2][S3, unofficial].
*   **Curvilinear Grids:** The assumption that splats sum to near unity holds only if the Jacobian derivative matrix varies slowly [S1, S2][S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Preprocessing involves sorting and texture map creation, which is $O(N \log N)$ for $N$ small cells [S1, S2][S3, unofficial]. Interactive rendering is efficient as it uses texture mapping and stencil tests [S1, S2][S3, unofficial].
*   **Memory Complexity:** Requires storing texture maps for all slicing directions and stencil buffers [S1, S2][S3, unofficial].
*   **Performance:** Reduces the number of polygons rendered, saving bandwidth and processing time [S1, S2][S3, unofficial].
*   **Strengths:** Prevents loss of small details in adaptive meshes; integrates anti-aliasing naturally [S1, S2][S3, unofficial].
*   **Limitations:** Requires preprocessing; relies on accurate cell volume and centroid calculations [S1, S2][S3, unofficial].
*   **When to Use:** When rendering adaptive meshes with small cells that might be missed by slicing [S1, S2][S3, unofficial].
*   **When Not to Use:** When cells are uniformly large or when preprocessing time is prohibitive [S1, S2][S3, unofficial].

## Background
This method was developed for volume rendering of curvilinear and unstructured grids [S1, S2][S3, unofficial]. It builds on the work of Williams et al. [8] and Zwicker et al. [5] [S1, S2][S3, unofficial]. The technique is used in scientific visualization to handle adaptive meshes where small cells contain important high-gradient features [S1, S2][S3, unofficial].
