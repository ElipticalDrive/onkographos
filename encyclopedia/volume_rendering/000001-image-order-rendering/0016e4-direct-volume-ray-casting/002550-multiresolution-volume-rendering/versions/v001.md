# Multiresolution Volume Rendering

Also called: Direct rendering of multiresolution decomposed volume data, Multiresolution Volume Rendering with Adaptive Integration, Wavelet/Laplacian Pyramid Volume Rendering

## Overview
Multiresolution Volume Rendering is a direct volume ray casting technique that decomposes volume data into a hierarchy of resolutions (e.g., via wavelets or Laplacian pyramids) to enable adaptive integration and early termination [S1, unofficial]. It reduces computational cost by using lower-resolution data for parts of the ray where accuracy requirements are lower or occlusion is high, while maintaining image quality by selectively using higher-resolution data for critical regions [S1, unofficial]. It differs from fixed-resolution ray casting by dynamically selecting the resolution level for shading and occlusion calculations based on the ray's progress and the data's hierarchical structure [S1, unofficial].

## How it works
**Inputs:**
- Multiresolution volume data: A hierarchy of $k+1$ levels ($m = 0, \dots, k$), where level 0 is the highest resolution and level $k$ is the lowest [S1, unofficial]. Each level contains coefficients for reconstruction (wavelet coefficients or pyramid levels) [S1, unofficial].
- Camera parameters: Viewpoint, projection matrix, screen dimensions [S1, unofficial].
- Transfer function: Maps scalar values to color $C(t)$ and opacity $\alpha(t)$ [S1, unofficial].
- Integration parameters: Step size for each resolution level (larger steps for lower levels) [S1, unofficial], early termination threshold $\epsilon$ [S1, unofficial].

**Outputs:**
- Rendered image: Pixel colors $I_{m,j}$ computed from combinations of shading $C_m(t)$ and occlusion $W_j(t)$ from different resolution levels [S1, unofficial].

**Data Structures:**
- Multiresolution Hierarchy: Stored as a list of arrays, one per level. For wavelets, each level $m$ contains coefficients $c_{u,w}(l)$ [S1, unofficial]. For Laplacian pyramids, each level $k$ contains detail coefficients $w(n-2k)$ and the coarse approximation $c_i^{k+1}$ [S1, unofficial].
- Ray State: Current position $t$, accumulated opacity $W(t)$, accumulated color $C'(t)$ [S1, unofficial].

**Steps:**
1. **Ray Casting:** For each pixel, cast a ray $r(t) = O + tD$ from the viewpoint [S1, unofficial]. Compute intersection points $t_1$ and $t_2$ with the volume boundary [S1, unofficial].
2. **Initialization:** Set accumulated opacity $W(t) = 1.0$ and accumulated color $C'(t) = 0$ [S1, unofficial]. Initialize $t = t_1$ [S1, unofficial].
3. **Adaptive Integration Loop:** While $t < t_2$ and $W(t) > \epsilon$:
    a. **Resolution Selection:** Choose resolution levels $m$ (for shading) and $j$ (for occlusion) based on $t$ and $W(t)$ [S1, unofficial]. Lower levels (coarser) may be used when $W(t)$ is small or when high-frequency details are less critical [S1, unofficial].
    b. **Sampling:** Sample the volume at $t$ using the selected resolution levels.
        - For wavelets, reconstruct the scalar value $v(i)$ using kernel size $q$:
          $$ v(i) = \sum_{l=0}^{q-1} c_{u,w}(l) \phi(i-l) $$
          Extended to 3D by summing over kernel dimensions [S1, unofficial].
        - For Laplacian pyramids, reconstruct using:
          $$ c_i^k = c_{i}^{k+1} + \sum_{n} w(n - 2k) c_{i}^{k+1} $$
          where $k$ is the level [S1, unofficial].
    c. **Shading and Occlusion:** Compute shading color $C_m(t)$ and opacity sample $\alpha(t)$ from the scalar value using the transfer function [S1, unofficial]. Compute occlusion $W_j(t)$ from accumulated opacity using level $j$ [S1, unofficial].
    d. **Compositing:** Update accumulated color and opacity using front-to-back compositing [S1, unofficial]:
        $$ C'(t) = C'(t-\Delta t) + (1 - W(t-\Delta t)) \alpha(t) C_m(t) $$
        $$ W(t) = W(t-\Delta t) (1 - \alpha(t)) $$
    e. **Step Advancement:** Advance $t$ by $\Delta t$, where $\Delta t$ is larger for lower resolution levels [S1, unofficial].
4. **Early Termination:** If $W(t) < \epsilon$, terminate the ray [S1, unofficial]. This avoids computing negligible contributions from distant parts of the volume [S1, unofficial].
5. **Final Color:** The pixel color is $C'(t_2)$ [S1, unofficial].

**Parameters:**
- $\epsilon$: Early termination threshold, typically a small positive value (e.g., $10^{-3}$) [S1, unofficial].
- Step sizes: Larger for lower resolution levels to reduce computation [S1, unofficial].
- Resolution levels: Number of levels $k$ in the decomposition (e.g., 5 levels in experiments) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Mixing Levels:** Combining shading from high resolution and occlusion from low resolution (or vice versa) can introduce errors. Table 4.2 in [S1, unofficial] shows errors such as $-0.027605$ for $C_2/W_2$ and $0.011057$ for $C_0/W_0$ [S1, unofficial]. Using high-resolution shading with low-resolution occlusion generally yields better quality [S1, unofficial].
- **Occlusion Decay:** As $t$ increases, $W(t)$ approaches zero, making distant contributions negligible. Failure to implement early termination wastes computation [S1, unofficial].
- **Reconstruction Artifacts:** Wavelet and Laplacian pyramid reconstructions may introduce artifacts if the kernel size or decomposition is not appropriate for the data [S1, unofficial].

```python
import math

def vec3(x, y, z):
    return [x, y, z]

def trilinear_interpolate(volume, pos, dims):
    # Standard trilinear interpolation [G]
    vx = pos[0] * (dims[0] - 1)
    vy = pos[1] * (dims[1] - 1)
    vz = pos[2] * (dims[2] - 1)
    x0, y0, z0 = int(math.floor(vx)), int(math.floor(vy)), int(math.floor(vz))
    x1, y1, z1 = x0 + 1, y0 + 1, z0 + 1
    x0 = max(0, min(x0, dims[0]-1))
    x1 = max(0, min(x1, dims[0]-1))
    y0 = max(0, min(y0, dims[1]-1))
    y1 = max(0, min(y1, dims[1]-1))
    z0 = max(0, min(z0, dims[2]-1))
    z1 = max(0, min(z1, dims[2]-1))
    wx = vx - x0
    wy = vy - y0
    wz = vz - z0
    c00 = volume[x0][y0][z0] * (1-wx) + volume[x1][y0][z0] * wx
    c01 = volume[x0][y0][z1] * (1-wx) + volume[x1][y0][z1] * wx
    c10 = volume[x0][y1][z0] * (1-wx) + volume[x1][y1][z0] * wx
    c11 = volume[x0][y1][z1] * (1-wx) + volume[x1][y1][z1] * wx
    r0 = c00 * (1-wy) + c10 * wy
    r1 = c01 * (1-wy) + c11 * wy
    return r0 * (1-wz) + r1 * wz

def compute_ray_exit(origin, direction, bounds):
    # Slab intersection for axis-aligned box [G]
    t0 = max((bounds[0][i] - origin[i]) / direction[i] if direction[i] != 0 else float('inf') for i in range(3))
    t1 = min((bounds[1][i] - origin[i]) / direction[i] if direction[i] != 0 else float('inf') for i in range(3))
    return max(t0, t1)

def multiresolution_volume_raycast(multires_data, camera, transfer_function, volume_bounds, volume_dims, epsilon=1e-3):
    """
    Renders a volume using multiresolution decomposition with adaptive integration.
    multires_data: List of arrays, one per level (0=highest, k=lowest)
    """
    h, w = camera.screen_height, camera.screen_width
    image = [[vec3(0.0, 0.0, 0.0) for _ in range(w)] for _ in range(h)]
    
    for y in range(h):
        for x in range(w):
            ray_origin, ray_direction = camera.cast_ray(x, y)
            accumulated_color = vec3(0.0, 0.0, 0.0)
            accumulated_opacity = 0.0 # W(t) = 1 - accumulated_opacity
            
            t_end = compute_ray_exit(ray_origin, ray_direction, volume_bounds)
            t = volume_bounds[0][0] # Simplified start, assume ray starts at volume entry [G]
            
            # Determine step sizes for each level [S1, unofficial]
            step_sizes = [0.001 * (2**i) for i in range(len(multires_data))] # Larger steps for lower levels
            
            while t < t_end and (1.0 - accumulated_opacity) > epsilon:
                # Select resolution levels m (shading) and j (occlusion) [S1, unofficial]
                # Heuristic: Use lower levels when opacity is low or t is large
                m = 0 # Default to highest resolution for shading
                j = 0 # Default to highest resolution for occlusion
                
                # Adaptive selection logic [G]
                if (1.0 - accumulated_opacity) < 0.5:
                    m = min(m + 1, len(multires_data) - 1)
                    j = min(j + 1, len(multires_data) - 1)
                
                # Compute current position in texture space [0,1]
                pos = [(ray_origin[i] + t * ray_direction[i]) for i in range(3)]
                
                # Sample volume at current position using selected resolution levels
                if multires_data[m].is_wavelet:
                    scalar_value = wavelet_reconstruct(multires_data[m].coeffs, pos, kernel_size=3, dims=volume_dims)
                else:
                    scalar_value = laplacian_reconstruct(multires_data[m].coeffs, pos, level=m, dims=volume_dims)
                
                # Apply transfer function to get color and opacity
                color, opacity = transfer_function(scalar_value)
                
                # Front-to-back compositing
                accumulated_color[0] += (1.0 - accumulated_opacity) * opacity * color[0]
                accumulated_color[1] += (1.0 - accumulated_opacity) * opacity * color[1]
                accumulated_color[2] += (1.0 - accumulated_opacity) * opacity * color[2]
                accumulated_opacity += (1.0 - accumulated_opacity) * opacity
                
                # Advance t using step size for level j
                t += step_sizes[j]
                
            image[y][x] = accumulated_color
            
    return image
```

## Subtopics

### Wavelet Decomposition
Uses wavelet transforms to create a multiresolution hierarchy. Suitable for data with smooth variations and sharp edges. [Link](wavelet-decomposition.md)

### Laplacian Pyramid Decomposition
Uses a pyramid structure of detail coefficients. Simpler to implement than wavelets but may have less compact representation. [Link](laplacian-pyramid.md)

### Adaptive Integration
The core technique of selecting resolution levels based on ray progress. Balances speed and accuracy. [Link](adaptive-integration.md)

## Operating characteristics
- **Time Complexity:** Reduced compared to fixed-resolution ray casting due to adaptive step sizes and early termination. Complexity depends on the number of levels and the adaptive selection strategy [S1, unofficial].
- **Memory Complexity:** Higher than fixed-resolution due to storage of multiple resolution levels. The total memory is roughly proportional to the sum of the sizes of all levels [S1, unofficial].
- **Measured Performance:** Experiments with a CT data set decomposed into 5 levels showed reduced processing time, with errors ranging from $-0.027605$ to $0.031589$ depending on the combination of levels used [S1, unofficial].
- **Strengths:** Significant speedup for large volumes, especially when occlusion allows early termination. Maintains high quality in critical regions. [S1, unofficial]
- **Limitations:** Increased memory usage. Potential for artifacts if resolution levels are not selected carefully. Reconstruction overhead for wavelets/pyramids. [S1, unofficial]
- **When to Use:** Large volumes where performance is critical, and the data has a natural multiresolution structure. [S1, unofficial]
- **When Not to Use:** Small volumes where fixed-resolution ray casting is fast enough, or when memory is constrained. [S1, unofficial]

## Background
Multiresolution Volume Rendering was introduced in the context of direct volume ray casting to address the computational cost of rendering large volumes [S1, unofficial]. It builds on the principles of wavelet and Laplacian pyramid decompositions, which provide hierarchical representations of data [S1, unofficial]. The method was explored in experiments with CT data sets, demonstrating its potential for reducing processing time while maintaining image quality [S1, unofficial].
