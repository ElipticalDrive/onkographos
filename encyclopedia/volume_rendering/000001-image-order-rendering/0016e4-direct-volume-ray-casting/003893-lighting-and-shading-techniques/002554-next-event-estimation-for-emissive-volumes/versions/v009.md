# Next Event Estimation for Emissive Volumes

Also called: Emissive Media Rendering, Emissive Volume Rendering with Next Event Estimation (NEE), NEE for Emissive Volumes

## Overview
Next Event Estimation (NEE) for Emissive Volumes is a direct lighting estimation technique used in path tracing within participating media [S2, unofficial]. It solves the problem of noisy or incorrect direct illumination from emissive volumes by explicitly sampling light sources and evaluating the emission along the ray segment between the sample point and the light source [S1, unofficial]. Unlike standard volume shading methods that may rely on ambient terms or approximate scattering, this method ensures energy consistency by correctly handling the probability density functions (PDFs) associated with sampling directions in 3D space [S1, unofficial]. It sets itself apart from siblings like [Direct Volume Rendering with Phong Illumination](3686-direct-volume-rendering-with-phong-shading.md) by explicitly accounting for the geometric attenuation and PDF conversion required when the light source is a volume rather than a surface, avoiding the pitfalls of naive solid-angle-to-volume PDF conversions [S1, unofficial].

## How it works
The method integrates NEE into the direct volume ray casting loop defined in [Direct volume ray casting](19-direct-volume-ray-casting.md) [G]. When a ray hits a surface or enters a volume, NEE estimates the direct lighting contribution from emissive volumes [G].

### Inputs and Outputs
*   **Input**: The current sample point $\mathbf{p}$ (hit point or volume sample), the view direction $\vec{\omega}_o$, the scene geometry including emissive volumes, and the light sources [G].
*   **Output**: The direct lighting term $L_{\text{direct}}(\mathbf{p})$ to be combined with the base color and other lighting terms [G].

### Data Structures
*   **Ray Segment**: Defined by entry point $\mathbf{p}_{\text{entry}}$ and exit point $\mathbf{p}_{\text{exit}}$ within the bounding volume of the emissive source [S1, unofficial].
*   **PDF Storage**: Requires tracking the solid angle PDF $p(\vec{\omega})$ and the derived volume PDF $p(\mathbf{x})$ [S1, unofficial].

### Steps
1.  **Light Sampling**: For each light source (specifically emissive volumes), sample a point $\mathbf{x}_L$ on the light [S2, unofficial]. Calculate the vector $\vec{L} = \mathbf{x}_L - \mathbf{p}$ and distance $r = \|\vec{L}\|$ [S2, unofficial].
2.  **Shadow Ray**: Cast a shadow ray from $\mathbf{p}$ to $\mathbf{x}_L$ with near clip $0.001$ and far clip $r - 0.001$ [S2, unofficial]. Check for occlusion by intersecting with scene objects [S2, unofficial]. If occluded, the direct lighting contribution from this light is zero [S2, unofficial].
3.  **PDF Conversion**: If not occluded, compute the MIS weight [S1, unofficial]. The standard volume PDF $p(\mathbf{x})$ must be compared against the solid angle PDF $p(\vec{\omega})$ converted to volume space [S1, unofficial]. The conversion factor involves $r^{-2}$ [S1, unofficial].
    *   The MIS weight is computed as $\mathrm{MIS}(r^{-2}p(\vec{\omega}), p(\mathbf{x}))$ [S1, unofficial].
    *   Note: $r^{-2}p(\vec{\omega})$ is a non-normalisable PDF because $\int_V r^{-2} p(\vec{\omega}) \mathrm{dV}$ does not converge to 1 in the standard manner [S1, unofficial].
4.  **Emission Evaluation**: Evaluate the emission along the entire ray segment between $\mathbf{p}$ and $\mathbf{x}_L$ to ensure consistency with the direction sampling used in the MIS calculation [S1, unofficial]. This involves integrating the emission coefficient over the path, accounting for transmittance [S1, unofficial].
5.  **Lighting Term Calculation**: Compute the direct lighting term using the evaluated emission, the geometric cosine factor, and the PDF weights [S2, unofficial].
    $$
    L_{\text{direct}} = \frac{f_r(\mathbf{p}, \vec{\omega}_o, \vec{\omega}_i) L_e(\mathbf{x}_L) \cos \theta}{p(\mathbf{x})} \cdot \text{MIS weight}
    $$
    Where $L_e$ is the emitted radiance, $\theta$ is the angle between the surface normal and light direction, and $f_r$ is the BSDF [S2, unofficial].
6.  **Accumulation**: Add $L_{\text{direct}}$ to the total lighting term $L(\mathbf{p})$ for the sample point [G].

### Pseudocode
```python
import math

def vector_norm(v):
    return math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)

def vector_normalize(v):
    n = vector_norm(v)
    if n == 0: return [0.0, 0.0, 0.0]
    return [v[0]/n, v[1]/n, v[2]/n]

def dot(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def vector_sub(a, b):
    return [a[0]-b[0], a[1]-b[1], a[2]-b[2]]

def vector_add(a, b):
    return [a[0]+b[0], a[1]+b[1], a[2]+b[2]]

def vector_mul(v, s):
    return [v[0]*s, v[1]*s, v[2]*s]

def compute_normal(p):
    # Standard gradient normalization for volume shading [G]
    return [0.0, 1.0, 0.0]

def balance_heuristic_mis(p1, p2):
    p1_sq = p1 * p1
    p2_sq = p2 * p2
    return p1_sq / (p1_sq + p2_sq)

def intersects_scene(origin, direction, t_min, t_max):
    # Standard ray-scene intersection test [G]
    # Returns True if ray intersects any geometry within [t_min, t_max]
    return False

def evaluate_emission_segment(p_start, p_end, scene):
    # Integrates emission along the segment to ensure consistency with direction sampling [S1, unofficial]
    direction = vector_normalize(vector_sub(p_end, p_start))
    distance = vector_norm(vector_sub(p_end, p_start))
    num_samples = 10
    total_emission = [0.0, 0.0, 0.0]
    for i in range(num_samples):
        t = (i + 0.5) / num_samples
        sample_point = vector_add(p_start, vector_mul(direction, t * distance))
        emission_coeff = scene.get_emission_coefficient(sample_point)
        transmittance = scene.get_transmittance(sample_point, p_end)
        total_emission = vector_add(total_emission, vector_mul(emission_coeff, transmittance * (distance / num_samples)))
    return total_emission

def next_event_estimation(p, wo, scene, depth):
    # Base case for path tracing recursion [S2, unofficial]
    if depth <= 0:
        return [0.0, 0.0, 0.0]

    direct_light = [0.0, 0.0, 0.0]
    if not scene.lights:
        return direct_light

    for light in scene.lights:
        # Sample point on light source [S2, unofficial]
        to_light = light.random_sample(p)
        distance_to_light = vector_norm(to_light)
        if distance_to_light < 0.001:
            continue

        light_dir = vector_normalize(to_light)
        point_on_light = vector_add(p, to_light)

        # Shadow ray with tight intervals to avoid self-intersection [S2, unofficial]
        shadow_near = 0.001
        shadow_far = distance_to_light - 0.001
        # Check occlusion by intersecting with scene objects [S2, unofficial]
        if intersects_scene(p, light_dir, shadow_near, shadow_far):
            continue

        # PDF values for MIS [S1, unofficial]
        p_omega = light.pdf(p)
        r = distance_to_light
        # Volume PDF derived from solid angle PDF [S1, unofficial]
        p_vol = (1.0 / (r * r)) * p_omega
        p_x = scene.get_volume_pdf(p) # Standard volume PDF [S1, unofficial]

        # MIS weight [S1, unofficial]
        mis_weight = balance_heuristic_mis(p_vol, p_x)

        # Evaluate emission along the entire ray segment for MIS consistency [S1, unofficial]
        emission_integral = evaluate_emission_segment(p, point_on_light, scene)

        # Compute direct lighting term [S2, unofficial]
        normal = compute_normal(p)
        cosine = max(0.0, dot(normal, light_dir))
        light_color = light.emitted(point_on_light)
        attenuation = 1.0
        # Formula from [S2, unofficial], adjusted for emission integral [S1, unofficial]
        term = (attenuation / 255.0) * light_color * cosine * emission_integral / (math.pi * p_x)
        direct_light = vector_add(direct_light, vector_mul(term, mis_weight))

    return direct_light
```

### Parameters and Edge Cases
*   **Ray Intervals**: Shadow rays must use tight intervals (e.g., $0.001$ to $r-0.001$) to avoid self-intersection artifacts [S2, unofficial].
*   **PDF Normalization**: The term $r^{-2}p(\vec{\omega})$ is non-normalisable [S1, unofficial]. Naive conversion using $r^{-2}\frac{\mathrm{dV}}{\mathrm{d\Omega}}$ yields incorrect results and is inconsistent with previous results without NEE [S1, unofficial].
*   **Performance**: Integrating the volume PDF over the ray length is significantly slower (20x-40x) due to required ray casts and raises OptiX warnings in CUDA modes [S1, unofficial].
*   **Mode Discrepancies**: In `llvm_*` modes, the implementation using NEE is approximately 5x slower than not using NEE [S1, unofficial]. In `cuda_*` modes, it is approximately 1.5x slower [S1, unofficial].
*   **Intersection Backend**: Differences in ray intersection handling between Embree (llvm) and OptiX (cuda) can lead to different results for ray entry/exit points, potentially causing incorrect results in `llvm_*` modes if not carefully handled [S1, unofficial].

## Subtopics

### Path Tracing with Next Event Estimation
A general path tracing algorithm that includes direct lighting estimation via NEE [S2, unofficial]. It recursively traces rays to compute pixel color [S2, unofficial]. The base case returns black if depth is 0 [S2, unofficial]. It handles transmission materials by returning emitted light plus the recursive ray color scaled by transmittance [S2, unofficial]. For opaque materials, it computes direct lighting by sampling a point on the light, checking for shadow, and calculating the contribution using the cosine term, light color, and PDF [S2, unofficial]. Indirect lighting is computed recursively [S2, unofficial]. This variant is a standard implementation of NEE in path tracers [S2, unofficial].

### Volume Light Emission
A technique using the Volume Light shelf tool to set up a geometry light based on a selected volume [S3]. Using an actual light is more straightforward, less noisy, and faster than simply assigning an emissive material, and provides convenient controls like rolloff [S3]. The emissive (Ce) value only contributes to the diffuse component and does not affect the reflective component of the volume [S3].

## Operating characteristics
*   **Time Complexity**: The method adds overhead due to shadow ray casting and emission integration along the segment [S1, unofficial][S2, unofficial]. In `llvm_*` modes, it is ~5x slower than without NEE [S1, unofficial]. In `cuda_*` modes, it is ~1.5x slower [S1, unofficial].
*   **Memory Complexity**: Requires storing ray intersection data and PDF values [S1, unofficial][G]. No significant additional memory compared to standard path tracing [G].
*   **Performance**: Reduces noise for the same sample count by providing accurate direct lighting estimates [S1, unofficial].
*   **Strengths**: Ensures energy consistency and reduces noise in scenes with emissive volumes [S1, unofficial].
*   **Limitations**: Slower performance, especially in CPU-based renderers. Potential inconsistencies between CPU and GPU backends due to intersection differences [S1, unofficial].
*   **When to Use**: When accurate direct lighting from emissive volumes is required and noise reduction is a priority [S1, unofficial].
*   **When Not to Use**: In real-time applications where performance is critical and approximate lighting is acceptable [G].

## Background
The method was developed as part of the Mitsuba 3 renderer project, specifically in the context of implementing emissive volume rendering [S1, unofficial]. It addresses the challenges of correctly sampling and integrating emission from volumes in a path tracing framework, ensuring consistency with Multiple Importance Sampling (MIS) [S1, unofficial]. The implementation details and discussions were documented in the Mitsuba 3 repository pull request [S1, unofficial].
