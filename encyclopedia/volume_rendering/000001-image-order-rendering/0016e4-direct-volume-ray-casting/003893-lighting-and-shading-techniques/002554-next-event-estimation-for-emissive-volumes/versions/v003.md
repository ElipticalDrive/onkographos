# Next Event Estimation for Emissive Volumes

Also called: Emissive Media Rendering, Emissive Volume Rendering with Next Event Estimation (NEE), NEE for Emissive Volumes

## Overview
Next Event Estimation (NEE) for emissive volumes reduces noise in participating media by explicitly sampling light sources (or emissive geometry) rather than relying solely on path tracing through the medium. It differs from standard volume rendering by decoupling the emission sampling from the ray's natural progression, requiring careful handling of probability density functions (PDFs) to maintain unbiased results. It builds on [Lighting and Shading Techniques](8281-lighting-and-shading-techniques.md).

## How it works
**Inputs and Outputs:**
*   **Input:** Ray segment $[t_{min}, t_{max}]$ intersecting an emissive volume or shape; solid angle PDF $p(\vec{\omega})$ of the sampled light direction; volume density/scattering properties.
*   **Output:** Emissive contribution estimate; MIS weight.

**Data Structures:**
*   Ray entry point $\vec{x}_{in}$ and exit point $\vec{x}_{out}$ within the bounding shape.
*   Distance $r$ from the shading point to the sampled light position.

**Method:**
1.  **Sample Light Direction:** Sample a point $\vec{x}_L$ on the emissive geometry using a solid angle PDF $p(\vec{\omega})$ centered at the current shading point $\vec{x}$.
2.  **Calculate Distance:** Compute the distance $r = \|\vec{x}_L - \vec{x}\|$.
3.  **Determine Ray Bounds:** Calculate the exact entry and exit points of the ray segment passing through the emissive shape containing $\vec{x}_L$. Let these be $t_{entry}$ and $t_{exit}$ relative to $\vec{x}$.
4.  **Convert PDF:** Convert the solid angle PDF $p(\vec{\omega})$ to a volume PDF $p_v(\vec{x}')$ for any point $\vec{x}'$ along the ray segment. The conversion is given by:
    $$ p_v(\vec{x}') = \frac{p(\vec{\omega})}{r^2} $$
    where $r$ is the distance from $\vec{x}$ to $\vec{x}'$. Note that this PDF is non-normalizable over the entire volume $V$ because $\int_V r^{-2} p(\vec{\omega}) \mathrm{dV}$ does not converge to 1 in the standard manner [S1, unofficial].
5.  **Evaluate Emission:** Evaluate the emission along the entire ray segment from $t_{entry}$ to $t_{exit}$. This evaluation must be consistent with the direction sampling used in the MIS calculation [S1, unofficial].
6.  **Compute MIS Weight:** Use Multiple Importance Sampling (MIS) to combine the NEE estimate with the standard volume sampling estimate. The weight is computed as:
    $$ \mathrm{MIS}(w) = \frac{w_{NEE}}{w_{NEE} + w_{vol}} $$
    where $w_{NEE}$ is derived from the volume PDF $p_v(\vec{x}') = r^{-2}p(\vec{\omega})$ and $w_{vol}$ is derived from the standard volume PDF $p(\vec{x})$ [S1, unofficial].

**Pseudocode:**
```python
def next_event_estimation_emissive_volume(shading_point, ray_direction, light_sampler, volume):
    # 1. Sample light direction
    light_pos, p_omega = light_sampler.sample(shading_point)
    
    # 2. Calculate distance
    r = distance(shading_point, light_pos)
    
    # 3. Determine ray bounds within the emissive shape
    # This requires intersecting the ray with the bounding shape of the emissive volume
    t_entry, t_exit = intersect_ray_shape(shading_point, ray_direction, volume.shape)
    
    # 4. Convert solid angle PDF to volume PDF
    # p_v = p_omega / r^2
    # Note: This PDF is non-normalizable over the whole volume, but valid for the segment
    p_v = p_omega / (r * r)
    
    # 5. Evaluate emission along the ray segment
    # Integrate emission from t_entry to t_exit
    # This step must be consistent with the direction sampling
    emission_contribution = integrate_emission(shading_point, ray_direction, t_entry, t_exit, volume)
    
    # 6. Compute MIS weight
    # w_nee is based on p_v, w_vol is based on standard volume PDF p(x)
    w_nee = p_v
    w_vol = volume.pdf(shading_point) # Standard volume PDF
    
    mis_weight = w_nee / (w_nee + w_vol)
    
    return emission_contribution * mis_weight
```

**Parameters:**
*   Light sampler: Must support solid angle sampling.
*   Volume shape: Must support ray intersection queries.

**Edge Cases and Pitfalls:**
*   **Incorrect PDF Conversion:** Simply converting the solid angle PDF to a volume PDF using the differential element $r^{-2}\frac{\mathrm{dV}}{\mathrm{d\Omega}}$ yields incorrect results and is inconsistent with previous results obtained without NEE [S1, unofficial].
*   **Integration Cost:** Integrating the volume PDF over the ray length is significantly slower (20x-40x) due to required ray casts and raises OptiX warnings in CUDA modes [S1, unofficial].
*   **Implementation Discrepancies:** In `llvm_*` modes, the implementation using NEE is approximately 5x slower than not using NEE. In `cuda_*` modes, it is approximately 1.5x slower [S1, unofficial].
*   **Ray Intersection Handling:** Differences in ray intersection handling between Embree (llvm) and OptiX (cuda) can lead to different results for ray entry and exit points, potentially causing incorrect results in `llvm_*` modes if not carefully handled [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Slower than standard volume rendering without NEE. In `llvm_*` modes, ~5x slower; in `cuda_*` modes, ~1.5x slower [S1, unofficial].
*   **Memory Complexity:** Not specified.
*   **Strengths:** Noticeable reduction in noise for the same sample count [S1, unofficial].
*   **Limitations:** Significant performance overhead, especially in `llvm_*` modes. Potential for incorrect results due to ray intersection discrepancies between backends [S1, unofficial].
*   **When to use:** When noise reduction is critical and performance overhead is acceptable.
*   **When not to use:** When performance is critical or when using `llvm_*` modes with strict correctness requirements regarding ray intersections.

## Background
This method was developed as part of the Mitsuba 3 renderer, specifically in the context of emissive media rendering. It addresses the challenge of efficiently sampling emission from participating media by leveraging next event estimation techniques. The implementation and associated discussions are documented in the Mitsuba 3 GitHub repository [S1, unofficial].
