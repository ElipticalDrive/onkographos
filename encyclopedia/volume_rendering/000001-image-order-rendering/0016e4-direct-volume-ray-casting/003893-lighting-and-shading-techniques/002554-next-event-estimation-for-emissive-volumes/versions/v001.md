# Next Event Estimation for Emissive Volumes

Also called: Emissive Media Rendering, Emissive Volume Rendering with Next Event Estimation (NEE), NEE for Emissive Volumes

## Overview
Next Event Estimation (NEE) for Emissive Volumes is a technique used in path tracing to directly sample light sources within participating media, reducing noise in scenes with volumetric emission [S1, unofficial]. It differs from standard direct volume ray casting [19-direct-volume-ray-casting.md] by explicitly estimating the contribution of emissive media at specific points along a ray, rather than relying solely on the accumulated emission from the volume rendering integral discretization. This method is particularly useful for reducing variance in scenes where emissive volumes are sparse or highly anisotropic.

## How it works
The method integrates NEE into the path tracing loop for volumes. It requires tracking the ray's entry and exit points within the volume to calculate the exact directional probability density function (PDF) for sampling points on the ray segment [S1, unofficial].

### Inputs and Outputs
*   **Inputs**: Current path vertex position (inside or near the volume), volume geometry (bounding shape), volume density/emission data, current path throughput.
*   **Outputs**: Estimated direct lighting contribution from the emissive volume segment, updated path throughput.

### Data Structures
*   **Ray Segment**: Defined by entry point $t_{start}$ and exit point $t_{end}$ along the ray direction $D$ [S1, unofficial].
*   **Directional PDF**: A function $p(\vec{\omega})$ representing the probability density of sampling a direction $\vec{\omega}$ towards the emissive segment [S1, unofficial].

### Steps
1.  **Ray-Volume Intersection**: Determine the entry point $t_{start}$ and exit point $t_{end}$ of the ray segment intersecting the emissive volume [S1, unofficial].
2.  **Sample Direction**: Sample a direction $\vec{\omega}$ towards the emissive segment. This is often done by sampling a point uniformly on the segment or using a solid angle distribution [S1, unofficial].
3.  **Calculate Volume PDF**: Compute the PDF for the sampled point on the ray. The key insight is that the standard conversion from solid angle PDF $p(\vec{\omega})$ to volume PDF $p(\vec{x})$ involves a factor of $r^{-2}$, where $r$ is the distance from the sampling point to the volume segment [S1, unofficial].
    $$ p(\vec{x}) \propto r^{-2} p(\vec{\omega}) $$
    However, this PDF is non-normalizable over the entire volume because $\int_V r^{-2} p(\vec{\omega}) \mathrm{dV}$ does not converge to 1 [S1, unofficial].
4.  **Evaluate Emission**: Evaluate the emission $L_e$ along the entire ray segment from $t_{start}$ to $t_{end}$ to ensure consistency with the direction sampling used in the Multiple Importance Sampling (MIS) calculation [S1, unofficial].
5.  **MIS Weighting**: Compute the MIS weight to balance between the volume PDF and the directional PDF. The weight is computed as:
    $$ \mathrm{MIS}(r^{-2}p(\vec\omega), p(\vec x)) $$
    where $r^{-2}p(\vec\omega)$ represents the volume PDF derived from the solid angle PDF, and $p(\vec x)$ is the standard volume PDF [S1, unofficial].
6.  **Accumulate Contribution**: Add the weighted emission contribution to the path throughput.

### Pseudocode
```python
def next_event_estimation_emissive_volume(ray_origin, ray_direction, volume_bounds, volume_emission_function, mis_weight_func):
    """
    Estimates direct lighting from an emissive volume using NEE.
    """
    # 1. Ray-Volume Intersection [S1, unofficial]
    t_start, t_end = compute_ray_segment_intersection(ray_origin, ray_direction, volume_bounds)
    
    if t_start >= t_end:
        return 0.0, 0.0 # No intersection
    
    # 2. Sample Direction/Point on Segment [S1, unofficial]
    # Sample a point uniformly on the segment [t_start, t_end]
    t_sample = random.uniform(t_start, t_end)
    sample_point = ray_origin + t_sample * ray_direction
    r = t_sample # Distance from origin to sample point along the ray
    
    # 3. Calculate PDFs [S1, unofficial]
    # Solid angle PDF p(omega) for sampling the segment
    p_omega = compute_solid_angle_pdf(ray_origin, sample_point, volume_bounds)
    
    # Volume PDF derived from solid angle PDF
    # Note: r^-2 * p(omega) is non-normalizable over the whole volume [S1, unofficial]
    p_volume_directional = (1.0 / (r * r)) * p_omega
    
    # Standard volume PDF p(x) for the sampled point
    p_volume_standard = compute_volume_pdf(sample_point, volume_bounds)
    
    # 4. Evaluate Emission along the segment [S1, unofficial]
    # Integrate emission from t_start to t_end
    emission_contribution = integrate_emission_along_segment(ray_origin, ray_direction, t_start, t_end, volume_emission_function)
    
    # 5. MIS Weighting [S1, unofficial]
    # Compute MIS weight between the two PDFs
    weight = mis_weight_func(p_volume_directional, p_volume_standard)
    
    # 6. Accumulate Contribution
    # The contribution is the emission evaluated at the sample point, weighted by MIS
    # Note: The source suggests evaluating emission along the *entire* segment for consistency [S1, unofficial]
    # However, typically NEE evaluates the light at the sampled point. 
    # Based on the source, the emission evaluation must be consistent with the direction sampling.
    # We assume the emission_contribution above is the relevant term, scaled by the PDF and weight.
    
    # Simplified contribution calculation based on source description
    # Contribution = (Emission * Weight) / PDF
    # Since p_volume_directional is used for the direction sampling, we divide by it.
    
    if p_volume_directional > 0:
        contribution = (emission_contribution * weight) / p_volume_directional
    else:
        contribution = 0.0
        
    return contribution, weight
```

### Parameters
*   **MIS Weight Function**: Typically the balance heuristic or power heuristic [S1, unofficial].
*   **Sampling Strategy**: Uniform sampling along the ray segment is a simple method [S1, unofficial].

### Edge Cases and Pitfalls
*   **Non-normalizable PDF**: Simply converting the solid angle PDF to a volume PDF using $r^{-2}$ yields incorrect results if not handled correctly with MIS, as the resulting PDF is non-normalizable over the entire volume [S1, unofficial].
*   **Performance**: Integrating the volume PDF over the ray length is significantly slower (20x-40x) due to required ray casts and can raise warnings in CUDA modes (e.g., OptiX) [S1, unofficial].
*   **Implementation Discrepancies**: In some implementations (e.g., llvm_* modes), using ray entry/exit points can lead to different results compared to other modes (e.g., cuda_* modes), likely due to differences in ray intersection handling (Embree vs. OptiX) [S1, unofficial].
*   **Speed**: The NEE implementation is slower than not using NEE (approx. 5x slower in llvm_* modes, 1.5x slower in cuda_* modes) but reduces noise [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Slower than standard volume rendering without NEE. In llvm_* modes, it is approximately 5x slower; in cuda_* modes, it is approximately 1.5x slower [S1, unofficial].
*   **Memory Complexity**: Requires storing ray segment intersection data and potentially additional buffers for emission integration [S1, unofficial].
*   **Strengths**: Significantly reduces noise for the same sample count in scenes with emissive volumes [S1, unofficial].
*   **Limitations**: Higher computational cost per sample; potential implementation inconsistencies across different ray tracing backends [S1, unofficial].
*   **When to Use**: When rendering scenes with emissive volumes where noise reduction is critical and performance budget allows for the overhead [S1, unofficial].
*   **When Not to Use**: When performance is the primary constraint and noise levels are acceptable without NEE [S1, unofficial].

## Background
This method was developed as part of the Mitsuba 3 renderer, specifically in the context of adding emissive volume rendering support [S1, unofficial]. The implementation was contributed by Microno95 and reviewed by dvicini in June 2023 [S1, unofficial]. It addresses the challenge of correctly sampling and weighting emissive media in path tracing, ensuring consistency with Multiple Importance Sampling (MIS) [S1, unofficial].
