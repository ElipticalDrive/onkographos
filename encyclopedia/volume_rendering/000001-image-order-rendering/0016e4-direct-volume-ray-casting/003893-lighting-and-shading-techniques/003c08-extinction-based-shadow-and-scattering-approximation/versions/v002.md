# Extinction-based Shadow and Scattering Approximation

Also called: Cone approximation via SAT, Extinction SAT queries

## Overview
This method approximates directional shadows and light scattering in volume rendering by computing the extinction of light intensity for voxels using a 3D Summed Area Table (SAT) [S1, unofficial]. It solves the problem of efficiently calculating soft shadows and ambient occlusion without propagating illumination from outside the volume, allowing for multiple light sources including those inside or on the border of the dataset [S1, unofficial]. It differs from half-angle slicing by handling any light type and from propagation methods by computing voxel-wise extinction rather than external illumination propagation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Scalar volume field $V$, transfer function $TF$, light source positions and types, cone angle $\Psi$, sampling frequency, growth rate, and weighting function $h$.
*   **Output:** Light cache texture containing shadow and ambient occlusion (AO)/color bleeding terms.

**Data Structures:**
*   **3D Summed Area Table (SAT):** Stores cumulative extinction coefficients. Constructed once per transfer function change or light source movement relative to the dataset [S1, unofficial].
*   **Light Cache Texture:** Stores precomputed shadow and AO terms to avoid duplicate queries during raycasting [S1, unofficial].

**Steps:**
1.  **Primary Axis Selection:** For a given light source and sample point, define the primary axis for sampling as the coordinate axis with the smallest angle to the vector pointing to the light source [S1, unofficial]. This ensures the best coverage of the cone with axis-aligned cuboids, which is required because SAT lookups are inherently axis-aligned [S1, unofficial].
2.  **Cuboid Query Derivation:**
    *   Define sampling points on the primary axis using a user-defined sampling frequency and a growth rate (change of frequency over distance) [S1, unofficial]. The growth rate adjusts sampling density, allowing lower frequency further away [S1, unofficial].
    *   Derive cuboid queries from these primary axis sampling points and the projection of the query cone onto the primary-secondary axis planes [S1, unofficial].
3.  **SAT Lookup:** Perform SAT lookups to sum extinction coefficients for the derived cuboids that cover the cone [S1, unofficial].
4.  **Weighting:** Apply a weighting function $h$ to weight cuboids differently, allowing control over the strength of the shadow effect [S1, unofficial].
5.  **Storage:** Store the computed shadow and AO/color bleeding terms in the light cache texture [S1, unofficial].
6.  **Raycasting Application:** During the raycasting pass, apply illumination terms using one additional texture lookup per sample [S1, unofficial].

**Parameters:**
*   **Cone Angle ($\Psi$):** Defines the angular spread of the shadow cone. Typical values range from 1.0 to 5.0 degrees, with larger angles producing smoother shadows [S1, unofficial].
*   **Sampling Frequency:** Defines the number of cuboids for approximation. A few dozen lookups per cone and voxel are typically sufficient [S1, unofficial].
*   **Growth Rate:** Controls the growth of cuboids (change of frequency over distance) [S1, unofficial].
*   **Weighting Function ($h$):** Used to weight cuboids differently [S1, unofficial].

**Pitfalls:**
*   Using very few cone samples (e.g., 12) results in clearly visible cuboid artifacts [S1, unofficial].
*   The SAT and AO terms must be recomputed every time the transfer function changes or the light source moves relative to the dataset [S1, unofficial].

def compute_extinction_sat(volume_field, transfer_function):
    """
    Constructs the 3D Summed Area Table (SAT) for extinction coefficients.
    Recomputed when TF or light source position changes.
    """
    # Calculate extinction coefficient for each voxel based on TF
    extinction = [transfer_function(v) for v in volume_field]
    
    # Build 3D SAT
    # SAT[x, y, z] = sum(extinction[i, j, k] for i<=x, j<=y, k<=z)
    sat = build_3d_cumulative_sum(extinction)
    return sat

def get_shadow_term(sat, voxel_pos, light_dir, cone_angle, sampling_freq, growth_rate, weighting_func):
    """
    Computes shadow term for a voxel using SAT cuboid queries.
    """
    # 1. Determine primary axis (axis with smallest angle to light_dir)
    primary_axis = argmin_angle(light_dir)
    
    # 2. Define sampling points on primary axis
    # Points are spaced by sampling_freq, adjusted by growth_rate over distance
    sampling_points = generate_sampling_points(voxel_pos, primary_axis, sampling_freq, growth_rate)
    
    # 3. Derive cuboid queries
    # Project cone onto primary-secondary axis planes
    cuboids = derive_cuboids(sampling_points, primary_axis, cone_angle)
    
    # 4. Sum extinction using SAT lookups
    total_extinction = 0.0
    for cuboid in cuboids:
        # Axis-aligned lookup in SAT
        ext = sum_extinction_in_cuboid(sat, cuboid)
        # Apply weighting function
        total_extinction += weighting_func(cuboid) * ext
        
    return total_extinction

        color = (0, 0, 0)
        for each sample along ray:

            base_color = transfer_function(volume_field[sample_pos])
            
            # Apply lighting model (e.g., Phong)
            # Note: This method provides shadow/AO terms via light_cache

            # using the cached terms for attenuation
            
            # Retrieve precomputed shadow/AO term
            shadow_term = light_cache[sample_pos]
            
            # Modulate color by shadow term
            shaded_color = base_color * shadow_term
            
            # Front-to-back compositing

## Operating characteristics
*   **Time Complexity:** SAT construction time scales with volume size. For a $256^3$ volume, SAT construction takes 0.311s; for $64^3$, it takes 0.029s [S1, unofficial]. AO/color bleeding computation for a $256^3$ texture with 3 shells takes 0.0307s, compared to 3.0818s for explicit sampling of radius 7 [S1, unofficial]. Shadow computation for a $64^3$ texture with 50 samples takes 0.0079s/frame [S1, unofficial].
*   **Memory Complexity:** Requires storage for the 3D SAT and the light cache texture [S1, unofficial].
*   **Performance:** The method is fast and flexible, allowing for soft, realistic-looking directional shadows at very low costs [S1, unofficial]. It achieves interactive performance even with dynamic transfer functions and light sources [S1, unofficial].
*   **Strengths:** Handles any type and multiple light sources, including those inside or on the border of the dataset [S1, unofficial]. Requires only one additional texture lookup per sample during raycasting [S1, unofficial].
*   **Limitations:** Requires recomputation of SAT and AO terms when the transfer function changes or light sources move [S1, unofficial]. Low number of cone samples can lead to visible artifacts [S1, unofficial].

## Background
This method was described in the context of GPU volume ray-casting for interactive rendering [S1, unofficial]. It was developed to provide realistic depth and occlusion effects with improved performance compared to classical shadow rays or other illumination models [S1, unofficial].
