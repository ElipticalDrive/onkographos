# Light Cache Rendering Pipeline

Also called: GPU Volume Ray-Caster with Light Cache, Illumination Cache Volume Rendering, TBRayMarcher, TBRayMarcher Plugin

## Overview
The Light Cache Rendering Pipeline is a direct volume ray-casting technique that pre-computes illumination attenuation factors (ambient occlusion and directional shadows) into a 3D texture, allowing for real-time rendering of complex lighting in volumetric data [S2, unofficial]. It distinguishes itself from standard ray-casting by replacing per-sample shadow ray traversal with single-texture lookups of pre-aggregated extinction coefficients, achieving speedups of over 45 times while maintaining visual quality comparable to dense sampling [S2, unofficial].

## How it works
The method relies on the assumption that volume material scatters light isotropically, allowing the lighting distribution inside the volume to be pre-computed and stored in an illumination cache [S2, unofficial]. The pipeline consists of three phases: SAT construction, Light Cache computation, and Ray-casting [S2, unofficial].

### Inputs and Outputs
*   **Input Volume ($V$):** 3D texture containing density or extinction values [S2, unofficial].
*   **Transfer Function ($TF$):** Maps scalar values in $V$ to color and opacity [S2, unofficial].
*   **Light Sources ($L$):** Positions and intensities of light sources [S2, unofficial].
*   **Output:** Rendered image [S2, unofficial].
*   **Intermediate Data:**
    *   **Light Cache Texture ($T$):** 3D texture storing summation terms for ambient occlusion (AO)/color bleeding and directional shadows in different channels [S2, unofficial].
    *   **SAT Texture ($S$):** 3D Summed Area Table texture constructed from the transfer-function-applied volume texture [S2, unofficial].

### Data Structures
*   **Light Cache Texture ($T$):** A 3D texture where each voxel stores pre-computed attenuation factors for AO/color bleeding and directional shadows in separate channels [S2, unofficial]. The exact channel layout is not specified in the sources [S2, unofficial].
*   **SAT Texture ($S$):** A 3D texture representing the Summed Area Table of the volume data after applying the transfer function [S2, unofficial]. It supports $O(1)$ aggregate queries over rectangular cuboids [S2, unofficial].

### Algorithm Steps
1.  **Initialization and Change Detection:** Determine if the Transfer Function ($TF$) or light positions have changed since the last frame [S2, unofficial]. If $TF$ has changed, recompute the entire light cache [S2, unofficial]. If only light positions changed, recompute only directional shadows [S2, unofficial].
2.  **Transfer Function Application:** Apply $TF$ to volume $V$ to produce a texture containing extinction coefficients and color information [S2, unofficial].
3.  **SAT Construction:** Compute the 3D Summed Area Table ($S$) from the TF-applied texture using recursive doubling with ping-pong textures [S2, unofficial]. The SAT allows efficient computation of the sum of extinction coefficients over any voxel neighborhood $\Omega$: $\sum_{\Omega} \Delta t \cdot \tau_j$, where $\tau_j$ is the extinction coefficient and $\Delta t$ is the step size [S2, unofficial].
4.  **Ambient Occlusion / Color Bleeding Computation:** For each voxel in $S$, sample shells (spherical neighborhoods) from $S$ using aggregate queries [S2, unofficial]. Sum the weighted extinction coefficients from these shells [S2, unofficial]. Store the result in the AO channel of $T$ [S2, unofficial].
5.  **Directional Shadow Computation (if lights changed):** For each light source $L$, for each voxel in $S$, query cuboids towards light source $L$ using the SAT [S2, unofficial]. Sum the weighted extinction coefficients along the path [S2, unofficial]. Store the result in the shadow channel of $T$ corresponding to $L$ [S2, unofficial].
6.  **Ray-Casting Pass:** For each pixel on the screen, compute entry and exit points for volume $V$ [S2, unofficial]. Compute ray $R$ from entry and exit points [S2, unofficial]. For each sample position $P$ along $R$, lookup volume $V$ and apply $TF$ to get color and opacity [S2, unofficial]. Lookup texture $T$ at $P$ to retrieve pre-computed AO and shadow factors [S2, unofficial]. Evaluate illumination model using the retrieved factors [S2, unofficial]. Add contribution to the pixel [S2, unofficial].

    lights_changed = True
    T = None

        if tf_changed or lights_changed:
            if tf_changed:

                T_temp = apply_transfer_function(volume_V, transfer_function)
                # Compute SAT from T_temp using recursive doubling with ping-pong textures
                S = compute_sat_recursive_doubling(T_temp)
                # Initialize T with zeros

                # Ambient Occlusion / Color Bleeding
                for voxel_pos in S.indices():
                    shells = sample_spherical_shells(S, voxel_pos)
                    ao_factor = sum_weighted_extinction(shells)
                    T[voxel_pos].ao = ao_factor
                tf_changed = False

            if lights_changed:
                for light in light_sources:
                    for voxel_pos in S.indices():
                        shadow_factor = query_cuboid_shadow(S, voxel_pos, light.position)
                        T[voxel_pos].shadow[light.id] = shadow_factor
                lights_changed = False

        # Ray-Casting Pass
        image = create_image(screen_resolution)
        for pixel in screen_resolution:
            entry, exit = compute_ray_bounds(volume_V, pixel)
            ray_origin = entry
            ray_direction = normalize(exit - entry)
            accumulated_color = vec3(0.0)
            accumulated_opacity = 0.0
            for sample_pos in sample_ray(ray_origin, ray_direction, entry, exit):
                vol_value = lookup_volume(volume_V, sample_pos)
                color, opacity = apply_transfer_function_sample(vol_value, transfer_function)
                ao_factor = lookup_light_cache(T, sample_pos, "ao")
                shadow_factors = lookup_light_cache(T, sample_pos, "shadow")

                final_color = color * light_intensity * ao_factor
                accumulated_color += final_color * opacity * (1.0 - accumulated_opacity)
                accumulated_opacity += opacity * (1.0 - accumulated_opacity)
                if accumulated_opacity > 0.99:
                    break
            image[pixel] = accumulated_color
        return image

### Parameters and Edge Cases
*   **Transfer Function Change:** If the TF changes, the entire light cache must be recomputed, including SAT and AO [S2, unofficial].
*   **Light Position Change:** If only light positions change, only the directional shadow factors need recomputation [S2, unofficial].
*   **Precision:** Voxel data is normalized to 8-bit precision to fit within texture constraints [S1, unofficial].
*   **Maximum Extents:** Maximum volume texture extents are limited to 2048 voxels per dimension in both DX11 and DX12, requiring chunking for larger datasets [S1, unofficial].
*   **Chunking Artifacts:** Chunking causes incorrect lighting at chunk borders because each chunk is illuminated independently as if other chunks do not exist, making borders incorrectly bright [S1, unofficial].
*   **VRAM Limits:** VRAM fragmentation and available memory can cause crashes well below the 2048 voxel limit per dimension [S1, unofficial].
*   **Rendering Backend:** DirectX 11 is required for best performance; DirectX 12 has unresolved issues, and Vulkan does not work [S1, unofficial].
*   **Homogeneous Media:** The method is particularly effective for highly homogeneous media such as smoke or translucent materials [S2, unofficial].
*   **Isotropic Scattering:** The method assumes volume material scatters light isotropically [S2, unofficial].

## Operating characteristics
*   **Performance:** The method yields results similar in quality to dense sampling but is much faster [S2, unofficial]. Specifically, aggregate sampling is over 45 times faster than individually sampled neighborhoods (0.22s vs 10s for ambient occlusion) [S2, unofficial].
*   **Memory:** Requires storage for the Light Cache Texture ($T$) and SAT Texture ($S$), in addition to the volume data [S2, unofficial]. The SAT construction uses ping-pong textures, requiring temporary memory [S2, unofficial].
*   **Strengths:** Real-time rendering of complex lighting effects (AO, soft shadows) in volumes [S2, unofficial]. High speed due to aggregate queries [S2, unofficial].
*   **Limitations:** Requires isotropic scattering assumption [S2, unofficial]. Recomputation cost if TF changes [S2, unofficial]. Quality depends on the accuracy of the SAT and shell/cuboid approximations [S2, unofficial].
*   **When to use:** Real-time volume rendering where lighting effects are important and the volume data is static or changes infrequently [S2, unofficial]. Suitable for homogeneous media [S2, unofficial].
*   **When not to use:** Highly anisotropic scattering [S2, unofficial]. Frequent TF changes [S2, unofficial].

## Background
The method is based on the work of Sundén and Ropinski [S2, unofficial]. It builds on the concept of illumination caching [Illumination Caching](7548-illumination-caching.md) and uses 3D Summed Area Tables for efficient aggregate queries [S2, unofficial]. The implementation is built using OpenGL and GLSL shaders [S2, unofficial]. The TBRayMarcher plugin for Unreal Engine is based on this implementation [S1, unofficial].
