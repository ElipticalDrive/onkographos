# Neural Radiance Caching

Also called: NRC, Neural Surface Cache

## Overview
Neural Radiance Caching (NRC) is a neural rendering technique that uses a Multi-Layer Perceptron (MLP) to predict photorealistic pixel colors from per-pixel feature buffers containing world-space positions and auxiliary features [S2, unofficial]. It enables real-time rendering by continuously overfitting to the current lighting and geometry using sparse light paths spawned from the camera view, operating within a strict training budget [S2, unofficial]. Unlike sibling methods that may require scene-specific retraining or lack dynamic support, NRC processes each pixel independently, allowing feature buffers to be treated as per-pixel feature vectors [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Per-pixel feature buffers containing the world-space position $\mathbf{x}$ and additional auxiliary encoded dimensions (e.g., view direction) [S2, unofficial].
*   **Output:** Predicted photorealistic pixel color (RGB) [S2, unofficial].

**Data Structures:**
*   **Feature Buffer:** A per-pixel array storing the concatenated encoded position and auxiliary features [S2, unofficial].
*   **Multi-resolution Hash Encoding:** A data structure mapping input coordinates to feature vectors across multiple grid resolutions [S2, unofficial][S1]. The encoding uses the same representational capacity as Neural Irradiance Volume (NIV) [S1].
*   **MLP:** A non-convolutional network processing each pixel independently [S2, unofficial].

**Parameters:**
*   **MLP Architecture:** 2 hidden layers with 64 neurons each [S2, unofficial].
*   **Training Budget:** 1 millisecond per frame to support animated content [S2, unofficial].
*   **Encoding:** Multi-resolution hash encoding [MESK22] [S1][S2, unofficial].

**Steps:**
1.  **Feature Buffer Construction:** For each pixel, retrieve the world-space position $\mathbf{x}$ and any additional auxiliary features (e.g., view direction) [S2, unofficial].
2.  **Position Encoding:** Encode the world-space position $\mathbf{x}$ using multi-resolution hash encoding [S2, unofficial].
3.  **Feature Concatenation:** Encode the auxiliary features using the same encoding scheme and concatenate them with the encoded position [S2, unofficial].
4.  **MLP Inference:** Feed the concatenated vector into the MLP to predict the pixel color [S2, unofficial].
5.  **Online Training:** Continuously update the MLP using sparse light paths spawned from the camera view, adhering to the 1 ms per frame training budget [S2, unofficial].

**Pseudocode:**
```python
def concatenate(vectors):
    """Concatenate a list of 1D vectors into a single 1D vector."""
    result = []
    for v in vectors:
        result.extend(v)
    return result

def neural_radiance_caching_pixel(x_world, aux_features, mlp, hash_encoder):
    """
    Predicts color for a single pixel using Neural Radiance Caching.
    
    Args:
        x_world: World-space 3D position vector.
        aux_features: List of auxiliary feature vectors (e.g., view direction).
        mlp: The trained MLP model.
        hash_encoder: Multi-resolution hash encoder instance.
        
    Returns:
        Predicted RGB color.
    """
    # Step 2: Encode position
    encoded_pos = hash_encoder.encode(x_world)
    
    # Step 3: Encode auxiliary features and concatenate
    encoded_aux = [hash_encoder.encode(feat) for feat in aux_features]
    input_vector = concatenate([encoded_pos] + encoded_aux)
    
    # Step 4: MLP Inference
    color = mlp.forward(input_vector)
    
    return color

# Step 5 is handled externally by the renderer's online training loop,
# which backpropagates the pixel loss against the MLP and hash encoder
# within the 1 ms per frame budget [S2, unofficial].
```

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Hash collisions cause microstructure artifacts at the finest grid resolution, which do not disappear with longer training times [S2, unofficial].
*   **Model Capacity:** Increasing the MLP capacity reduces bias but does not significantly improve quality because variance is the dominant error source in related deferred variants [S1].
*   **Training Budget:** The 1 ms per frame constraint requires efficient encoding and small network sizes to maintain real-time performance [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Runtime overhead is approximately 0.7 ms at 1920x1080 resolution, including both training and inference costs [S2, unofficial].
*   **Memory Complexity:** Uses 2 or 4 grid levels, consuming 0.16 to 1.20 MB of memory [S1].
*   **Measured Performance:** Achieves 133 FPS with multi-resolution hash encoding versus 147 FPS with triangle wave encoding at 1920x1080 resolution [S2, unofficial].
*   **Strengths:** Real-time performance, online adaptability to dynamic scenes, and high quality for static scenes [S1][S2, unofficial].
*   **Limitations:** Hash collisions produce persistent microstructure artifacts, and the method requires careful budget management to stay within the 1 ms training limit [S2, unofficial].
*   **When to Use:** Suitable for real-time rendering of scenes with static geometry and dynamic objects where online adaptation is needed [S1][S2, unofficial].
*   **When Not to Use:** Not suitable for scenes where hash collision artifacts are unacceptable or where hardware acceleration for the specific encoding is unavailable [S2, unofficial].

## Background
Neural Radiance Caching was introduced by Müller et al. in 2021 [S2, unofficial]. It builds on the concept of neural surface caches but adapts it for real-time rendering with online learning [S1][S2, unofficial]. The method was later augmented with multi-resolution hash encoding [MESK22] to improve quality and performance [S1][S2, unofficial]. It is used in real-time rendering applications, particularly within the instant neural graphics primitives framework [S2, unofficial].
