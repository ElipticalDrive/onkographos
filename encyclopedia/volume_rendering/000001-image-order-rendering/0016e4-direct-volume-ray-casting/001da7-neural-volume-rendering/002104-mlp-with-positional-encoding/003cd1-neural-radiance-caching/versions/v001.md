# Neural Radiance Caching

Also called: NRC, Neural Surface Cache

## Overview
Neural Radiance Caching (NRC) is a neural rendering technique that uses a Multi-Layer Perceptron (MLP) to predict photorealistic pixel colors from per-pixel feature buffers containing world-space positions and auxiliary features [S2, unofficial]. It solves the problem of real-time indirect illumination by deferring shading computations to a trained neural model, allowing for online adaptation to dynamic scenes [S1][S2, unofficial]. Unlike sibling methods that may require scene-specific retraining or lack dynamic support, NRC continuously overfits to the current lighting and geometry using sparse light paths spawned from the camera view, enabling real-time performance with a strict training budget [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Per-pixel feature buffers containing the world-space position $\mathbf{x}$ and additional auxiliary encoded dimensions (e.g., view direction, surface normals) [S2, unofficial].
*   **Output:** Predicted photorealistic pixel color (RGB) [S2, unofficial].

**Data Structures:**
*   **Feature Buffer:** A per-pixel array storing the concatenated encoded position and auxiliary features [S2, unofficial].
*   **Multi-resolution Hash Encoding:** A data structure mapping input coordinates to feature vectors across multiple grid resolutions [S2, unofficial][S1]. The encoding uses the same representational capacity as Neural Irradiance Volume (NIV) [S1].
*   **MLP:** A non-convolutional network processing each pixel independently [S2, unofficial].

**Parameters:**
*   **MLP Architecture:** 2 hidden layers with 64 neurons each [S2, unofficial].
*   **Training Budget:** 1 millisecond per frame to support animated content [S2, unofficial].
*   **Encoding:** Multi-resolution hash encoding [MESK22] [S1][S2, unofficial].

**Steps:**
1.  **Feature Buffer Construction:** For each pixel, retrieve the world-space position $\mathbf{x}$ and any additional auxiliary features (e.g., view direction) [S2, unofficial].
2.  **Position Encoding:** Encode the world-space position $\mathbf{x}$ using multi-resolution hash encoding [S2, unofficial].
3.  **Feature Concatenation:** Concatenate the encoded position with the encoded auxiliary dimensions using the same encoding scheme as Müller et al. [2021] [S2, unofficial].
4.  **MLP Inference:** Feed the concatenated vector into the MLP to predict the pixel color [S2, unofficial].
5.  **Online Training:** Continuously update the MLP using sparse light paths spawned from the camera view, adhering to a 1 ms per frame training budget [S2, unofficial].
6.  **Dynamic Object Handling (Deferred Shading):** If a ray hits a dynamic object not part of the static training domain, defer the cache query by one or more bounces until it hits a static surface where the neural cache is valid [S1].
7.  **Denoising:** Apply a denoiser to remove variance resulting from the deferred path depth [S1].

**Pseudocode:**
```python
def neural_radiance_caching_pixel(x_world, aux_features, mlp, hash_encoder):
    """
    Predicts color for a single pixel using Neural Radiance Caching.
    
    Args:
        x_world: World-space 3D position vector.
        aux_features: List of auxiliary feature vectors (e.g., view direction).
        mlp: The trained MLP model.
        hash_encoder: Multi-resolution hash encoder instance.
        
    Returns:
        Predicted RGB color.
    """
    # Step 2: Encode position
    encoded_pos = hash_encoder.encode(x_world)
    
    # Step 3: Encode auxiliary features and concatenate
    # Note: Auxiliary features are encoded using the same scheme as position
    encoded_aux = []
    for feat in aux_features:
        encoded_aux.append(hash_encoder.encode(feat))
        
    # Concatenate encoded position and encoded auxiliary features
    input_vector = concatenate(encoded_pos, encoded_aux)
    
    # Step 4: MLP Inference
    color = mlp.forward(input_vector)
    
    return color

def handle_dynamic_object_ray(ray, cache, denoiser):
    """
    Handles rays hitting dynamic objects by deferring shading.
    
    Args:
        ray: The current ray segment.
        cache: The neural radiance cache (MLP + Hash Encoder).
        denoiser: The denoising filter.
        
    Returns:
        Shaded color.
    """
    # Check if ray hits a dynamic object not in training domain
    if is_dynamic_object(ray.hit):
        # Step 6: Defer cache query
        # Trace ray further until it hits a static surface
        deferred_ray = trace_ray_until_static(ray, cache.static_meshes)
        
        if deferred_ray.hit:
            # Query cache for the deferred hit point
            color = neural_radiance_caching_pixel(
                deferred_ray.hit_point, 
                deferred_ray.aux_features, 
                cache.mlp, 
                cache.hash_encoder
            )
            # Step 7: Denoise to remove variance from deferral
            color = denoiser.filter(color)
            return color
        else:
            # Fallback if no static surface hit
            return background_color
    else:
        # Direct cache query for static objects
        return neural_radiance_caching_pixel(
            ray.hit_point, 
            ray.aux_features, 
            cache.mlp, 
            cache.hash_encoder
        )
```

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Hash collisions cause microstructure artifacts at the finest grid resolution. These artifacts do not disappear with longer training times [S2, unofficial].
*   **Dynamic Object Shading:** Objects not part of the training domain (dynamic objects) cannot be directly shaded. Ray tracing is required to defer shading, which increases variance proportional to the deferred path depth [S1].
*   **Variance:** Increasing model capacity reduces bias but does not significantly improve quality because variance from deferring is the major source of error [S1].

## Operating characteristics
*   **Time Complexity:** Runtime overhead is approximately 0.7 ms at 1920x1080 resolution, including training and runtime costs [S2, unofficial]. However, when handling dynamic objects, ray tracing and denoising add 5-10 ms per frame overhead [S1].
*   **Memory Complexity:** Uses 2 or 4 grid levels, consuming 0.16 to 1.20 MB of memory [S1].
*   **Performance:** Achieves 133 FPS with multi-resolution hash encoding vs. 147 FPS with triangle wave encoding at 1920x1080 resolution [S2, unofficial].
*   **Strengths:** Real-time performance, online adaptability to dynamic scenes, high quality for static scenes [S1][S2, unofficial].
*   **Limitations:** Requires ray tracing and denoising for dynamic objects, leading to higher variance and runtime overhead compared to methods like NIV [S1]. Hash collisions cause persistent artifacts [S2, unofficial].
*   **When to Use:** Suitable for real-time rendering of scenes with static geometry and dynamic objects where online adaptation is needed [S1][S2, unofficial].
*   **When Not to Use:** Not suitable for scenes with many dynamic objects where low variance is critical, or when hardware ray tracing is unavailable [S1].

## Background
Neural Radiance Caching was introduced by Müller et al. in 2021 [S2, unofficial]. It builds on the concept of neural surface caches [RWG∗ 13, HCZ21, CDD∗ 24] but adapts it for real-time rendering with online learning [S1][S2, unofficial]. The method was later augmented with multi-resolution hash encoding [MESK22] to improve quality and performance [S1][S2, unofficial]. It is used in real-time rendering applications, particularly in the context of instant neural graphics primitives [S2, unofficial].
