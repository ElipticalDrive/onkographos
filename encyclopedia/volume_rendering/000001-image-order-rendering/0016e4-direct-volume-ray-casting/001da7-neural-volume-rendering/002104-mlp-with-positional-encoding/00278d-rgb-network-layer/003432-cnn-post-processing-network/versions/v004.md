# CNN Post-Processing Network

Also called: Reflectance Padding CNN, Shallow Refinement CNN

## Overview
The CNN Post-Processing Network is a shallow convolutional neural network applied after the initial volumetric rendering step to enhance texture detail and convert feature representations into final RGB colors [S1]. It solves the problem of blurry or low-fidelity outputs from standard neural volume rendering by leveraging spatial context from neighboring pixels, ensuring that the rendering process for each pixel depends on its local neighborhood rather than just the individual ray [S1]. It sets itself apart from its siblings, the [RGB Network Layer](4051-rgb-network-layer.md) and [Sigma Network Layer](6256-sigma-network-layer.md), by operating in image space (2D) rather than feature space along the ray, and by explicitly using padding strategies to prevent upsampling artifacts [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D feature map (or rendered patch) $R$ of size $H \times W \times C_{in}$, where $C_{in}$ is the number of input channels (features).
*   **Output:** An RGB image of size $H \times W \times 3$.

**Data Structures:**
The network consists of a sequence of convolutional layers followed by a fully connected (perceptron) layer.
*   **Convolutional Layers:** Use $3 \times 3$ kernels.
*   **Padding:** "Reflectance" padding is applied to the inputs of each convolution.
*   **Activation:** ReLU is used after each convolutional layer.
*   **Final Layer:** A feed-forward perceptron (fully connected layer) maps the final feature space to RGB space.

**Steps:**
1.  **Padding:** Apply reflectance padding to the input feature map $R$. This involves mirroring the boundary pixels to create a padded tensor $R_{pad}$.
2.  **Convolution 1:** Apply a $3 \times 3$ convolution to $R_{pad}$.
3.  **Crop:** Remove the padding values from the output of Convolution 1 to restore the original spatial dimensions $H \times W$. This prevents checkerboard artifacts [S1].
4.  **Activation:** Apply ReLU activation to the cropped output.
5.  **Convolution 2:** Apply a $3 \times 3$ convolution to the activated output.
6.  **Crop:** Remove padding values from the output of Convolution 2.
7.  **Activation:** Apply ReLU activation.
8.  **Convolution 3:** Apply a $3 \times 3$ convolution to the activated output.
9.  **Crop:** Remove padding values from the output of Convolution 3.
10. **Perceptron:** Apply a feed-forward perceptron layer to the final feature map to convert it from feature space to RGB space.

**Formulas:**
Let $f$ be the convolution operation with reflectance padding. Let $c$ be the cropping operation that removes the border of width $p$ (where $p$ is the padding size). Let $\sigma$ be the ReLU activation function. Let $P$ be the perceptron layer.
$$ F_1 = \sigma(c(f(R, k=3, p=1))) $$
$$ F_2 = \sigma(c(f(F_1, k=3, p=1))) $$
$$ F_3 = c(f(F_2, k=3, p=1)) $$
$$ I_{RGB} = P(F_3) $$

**Parameters:**
*   Kernel size: $3 \times 3$ [S1].
*   Number of convolutional layers: 3 [S1].
*   Activation: ReLU [S1].
*   Padding type: Reflectance [S1].

**Edge Cases and Pitfalls:**
*   **Checkerboard Artifacts:** Standard upsampling or improper padding can cause checkerboard artifacts. This is prevented by using reflectance padding and explicitly removing the padding values in the outputs [S1].
*   **Multiview Inconsistency:** Because the CNN is very shallow and performs no upsampling, multiview inconsistency is avoided [S1].

**Pseudocode:**
```python
def cnn_post_processing(feature_map):
    """
    Applies a 3-layer shallow CNN with reflectance padding and cropping
    to convert feature maps to RGB.
    
    Args:
        feature_map: Tensor of shape (H, W, C_in)
        
    Returns:
        Tensor of shape (H, W, 3)
    """
    # Step 1: Reflectance Padding
    # Reflectance padding mirrors the boundary. For kernel size 3, padding is 1.
    padded = reflectance_pad(feature_map, pad_size=1)
    
    # Step 2: Convolution 1
    conv1 = conv2d(padded, kernel_size=3, channels_out=feature_map.shape[2]) # Assuming same channels or defined by model
    # Step 3: Crop
    cropped1 = crop(padded_output=conv1, crop_size=1)
    # Step 4: Activation
    act1 = relu(cropped1)
    
    # Step 5: Convolution 2
    conv2 = conv2d(act1, kernel_size=3, channels_out=feature_map.shape[2])
    # Step 6: Crop
    cropped2 = crop(conv2, crop_size=1)
    # Step 7: Activation
    act2 = relu(cropped2)
    
    # Step 8: Convolution 3
    conv3 = conv2d(act2, kernel_size=3, channels_out=feature_map.shape[2])
    # Step 9: Crop
    cropped3 = crop(conv3, crop_size=1)
    
    # Step 10: Perceptron to RGB
    # Flatten spatial dimensions, apply linear layer, reshape
    flat = flatten_spatial(cropped3)
    rgb_flat = perceptron(flat) # Maps to 3 channels
    rgb_image = reshape_to_image(rgb_flat, H, W, 3)
    
    return rgb_image
```

## Subtopics

### 2D Refinement Layers
An optional shallow 2D CNN used to refine the rendered image, specifically designed to prevent texture sticking under viewpoint changes [S2]. It sets itself apart from the standard post-processing CNN by using alias-free layers with critical sampling [S2]. It is chosen when high-fidelity synthesis is required and texture consistency across views is critical [S2].
*   **Definition:** A shallow 2D CNN applied to refine the rendered image [S2].
*   **Step:** Apply a shallow 2D CNN with 2 hidden layers of dimension 16 and kernel size 3 [S2]. Use alias-free layers with critical sampling [S2].
*   **Parameter:** Hidden layers: 2 [S2]. Hidden layer dimension: 16 [S2]. Kernel size: 3 [S2].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and channels, as it is a shallow CNN with fixed kernel size [S1].
*   **Memory Complexity:** Low, as the network is shallow and does not store large intermediate feature maps beyond the input and output [S1].
*   **Strengths:** Improves texture detail without causing multiview inconsistency [S1]. Prevents checkerboard artifacts [S1].
*   **Limitations:** Does not perform upsampling, so it cannot increase resolution [S1].
*   **When to use:** When the initial neural volume rendering produces blurry outputs and multiview consistency is required [S1].
*   **When not to use:** When resolution increase is needed (use super-resolution variants instead) [S1].

## Background
The CNN Post-Processing Network was introduced in the context of high-fidelity neural radiance fields, specifically in the AligNeRF paper [S1]. It builds on the idea that rendering each pixel should depend on neighboring regions to produce better texture detail [S1]. The 2D Refinement Layer variant was introduced in VoxGRAF to address texture sticking under viewpoint changes [S2].
