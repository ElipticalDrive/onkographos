# Real-Time Rendering Pipeline


## Overview
This pipeline renders Neural Duplex Radiance Fields in real-time by replacing iterative neural volume ray casting with hardware rasterization of pre-computed mesh features followed by a lightweight convolutional neural network (CNN) [S1]. It solves the performance bottleneck of neural volume rendering by decoupling geometry representation (meshes with per-vertex features) from appearance synthesis (shallow CNN) [S1]. Unlike its parent method which relies on CUDA-based neural volume rendering, this approach uses WebGL GLSL shaders to achieve cross-platform compatibility without requiring a GPU with CUDA support, trading some peak performance for broader accessibility [S1].

## How it works
The method renders a novel view in two main stages: feature buffer generation and neural aggregation [S1].

**Inputs:**
- Two trained meshes (inner and outer) representing the neural duplex radiance field [S1].
- Per-vertex radiance features attached to each mesh [S1].
- Camera parameters (view direction, projection) [S1].

**Outputs:**
- Final RGB image at the output resolution [S1].

**Data Structures:**
- **Feature Buffer:** A 2D texture at the output image resolution [S1]. Each pixel stores interpolated per-vertex features from the rasterized mesh [S1]. The feature dimension is typically 20 in the CUDA version, but reduced to 8 in the WebGL version for efficiency [S1].
- **View Direction Buffer:** A 2D texture storing the per-pixel view direction vector [S1].

**Steps:**
1. **Rasterization:** Use hardware rasterization to render the inner and outer meshes [S1]. Interpolate the per-vertex radiance features across screen space to fill the feature buffers at the output image resolution [S1].
2. **View Direction Calculation:** Compute the per-pixel view direction vector for each pixel in the output image [S1].
3. **CNN Aggregation:** Send the feature buffers and view direction buffer into a shallow CNN implemented as GLSL shaders [S1]. The CNN aggregates local radiance features to produce view-dependent RGB colors [S1].
   - The CNN is implemented in two rendering passes, one pass for each layer, to maximize efficiency [S1].
   - The convolution kernels are compact enough to be executed in a pixel-parallel manner [S1].

**Pseudocode:**
```python
def render_pipeline(inner_mesh, outer_mesh, camera, image_resolution, feature_dim):
    # Step 1: Rasterization
    # Hardware rasterization renders two feature buffers at the output image resolution
    feature_buffer_inner = empty_texture(image_resolution.width, image_resolution.height, feature_dim)
    feature_buffer_outer = empty_texture(image_resolution.width, image_resolution.height, feature_dim)
    for y in range(image_resolution.height):
        for x in range(image_resolution.width):
            feature_buffer_inner[x, y] = interpolate_vertex_features(inner_mesh, camera, x, y)
            feature_buffer_outer[x, y] = interpolate_vertex_features(outer_mesh, camera, x, y)

    # Step 2: View Direction Calculation
    view_direction_buffer = empty_texture(image_resolution.width, image_resolution.height, 3)
    for y in range(image_resolution.height):
        for x in range(image_resolution.width):
            view_direction_buffer[x, y] = compute_pixel_view_direction(camera, x, y)

    # Step 3: CNN Aggregation
    # The CNN aggregates local radiance features to produce view-dependent RGB colors
    # Implemented in two rendering passes, one pass for each layer
    intermediate_features = apply_convolution_layer_1(feature_buffer_inner, feature_buffer_outer, view_direction_buffer)
    rgb_image = apply_convolution_layer_2(intermediate_features)

    return rgb_image
```

**Parameters:**
- **Feature Dimension:** 20 (CUDA version), 8 (WebGL version) [S1].
- **Optimizer:** Adam with $\beta_1 = 0.9$ and $\beta_2 = 0.999$ [S1].
- **Training Iterations:** 200,000 total; first half optimized on distillation views, second half on original training images [S1].

**Edge Cases and Pitfalls:**
- **Precision:** Reducing feature dimension from 20 to 8 in the WebGL version results in performance degradation on datasets compared to the CUDA version [S1].
- **Compatibility:** The WebGL implementation sacrifices some performance for cross-platform compatibility and eliminates the CUDA requirement [S1].

## Subtopics

### Keyword-Gated Feature System
A feature management system used in the Unity-based implementation of the real-time rendering pipeline [S2, unofficial]. All shared features (directional light, ambient, color ramp, spot lights, shadow casting) use `shader_feature_local` for zero GPU cost when disabled [S2, unofficial]. This allows toggling features on/off and confirms that keyword gating produces no visual artifacts when disabled [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Real-time frame generation is achieved through hardware rasterization and pixel-parallel CNN execution [S1].
- **Memory Complexity:** Depends on the feature buffer size (image resolution $\times$ feature dimension) and the CNN model size [S1].
- **Performance:** The WebGL version results in performance degradation on both datasets compared with the CUDA version, but brings remarkable FPS improvement for cross-platform deployment and eliminates the CUDA requirement [S1].
- **Strengths:** Cross-platform compatibility, no CUDA requirement, real-time performance [S1].
- **Limitations:** Reduced accuracy compared to the CUDA version due to architectural simplifications [S1].
- **When to Use:** When cross-platform compatibility is required and CUDA is not available [S1].
- **When Not to Use:** When peak performance and highest visual fidelity are required, and CUDA is available [S1].

## Background
The method is based on "Learning Neural Duplex Radiance Fields for Real-Time View Synthesis" [S1]. The real-time renderer was implemented in WebGL using GLSL shaders for cross-platform compatibility [S1]. The training is built on top of PyTorch [S1]. The Unity-based implementation includes additional features like HDRP shader compatibility, occupancy grid empty-space skipping, adaptive stepping, temporal jitter, Henyey-Greenstein phase function, and multi-scatter approximation [S2, unofficial].
