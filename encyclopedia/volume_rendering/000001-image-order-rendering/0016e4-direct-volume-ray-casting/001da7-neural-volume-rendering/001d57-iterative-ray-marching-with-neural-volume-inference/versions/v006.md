# Iterative Ray Marching with Neural Volume Inference


## Overview
Iterative Ray Marching with Neural Volume Inference is a GPU-accelerated rendering technique that splits the evaluation of a neural volume along a ray into multiple kernel launches (iterations) to handle rays that do not fully converge (reach alpha $\ge 1$) in a single pass [S1, unofficial]. It distinguishes itself from single-pass methods like [In-Shader Neural Volume Ray Marching](1495-in-shader-neural-volume-ray-marching.md) by using a counter-based compaction mechanism to track active rays between kernel launches, allowing for dynamic handling of varying ray depths and complex occlusion without fixed iteration limits [S1, unofficial].

## How it works
The method processes rays in batches, launching separate CUDA kernels for ray generation, intersection, neural inference, and composition. It repeats these steps until all rays have either converged (alpha $\ge$ nearly_one) or are determined to be resumable but exhausted [S1, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   Camera parameters (origin, direction, frame index).
    *   Neural network model (or ground truth data if no network is provided).
    *   Transfer function (color and alpha mapping).
    *   Rendering mode (e.g., `SHADOW`, `GRADIENT_SHADING`, `SINGLE_SHADE_HEURISTIC`) [S1, unofficial].
    *   Parameters: `N_ITERS` (samples per kernel launch), `numCoordsPerSample` (4 for gradient shading, 1 otherwise) [S1, unofficial].
*   **Outputs**:
    *   Final pixel color and alpha buffer.
    *   Intermediate state for shadow rays (highest alpha/color/org) [S1, unofficial].

### Data Structures
*   **params.counter**: A GPU buffer tracking the number of active rays. Initialized to zero using `cudaMemsetAsync` [S1, unofficial].
*   **params.inference_output**: A buffer of float values containing the neural network output (sample value) at indices `[numRays * k + i]` [S1, unofficial].
*   **RayMarchingIter**: Payload structure saved for active rays, containing current ray state (origin, direction, current alpha, color, transmittance) [S1, unofficial].
*   **Shadow State (ssh)**: Tracks `highest_org`, `highest_color`, and `highest_alpha` for shadow and single-shade heuristic modes [S1, unofficial].

### Numbered Steps

1.  **Initialization**:
    *   Reset `params.counter` to zero [S1, unofficial].
    *   Launch `iterative_raygen_kernel` (either `iterative_raygen_kernel_camera` or `iterative_raygen_kernel_shadow` depending on mode) [S1, unofficial].

2.  **Main Loop**:
    *   Check if any rays remain active by asynchronously copying `params.counter` to host memory and synchronizing. If count > 0, continue [S1, unofficial].
    *   Launch `iterative_intersect_kernel<MODE>` with `N_ITERS` to compute sample coordinates for active rays. If `GRADIENT_SHADING`, compute gradient sample points by adding `gradientStep` to the current position [S1, unofficial].
    *   Perform neural network inference: Call `iterative_sampling_batch_inference` with input size `numCoordsPerSample * numRays`. If no network is provided, launch `iterative_sampling_groundtruth_kernel` [S1, unofficial].
    *   Reset `params.counter` to zero for the next iteration's compaction check [S1, unofficial].
    *   Launch `iterative_compose_kernel<MODE>` with `N_ITERS` to classify, shade, and blend samples for active rays. Rays that are not yet fully opaque (alpha < nearly_one) and are resumable are saved for the next iteration [S1, unofficial].

3.  **Finalization**:
    *   After the loop, if a ray is finished (alpha >= nearly_one or not resumable), write the final color to the pixel buffer based on the shading mode [S1, unofficial].

### Formulas and Logic

**Ray Generation (`iterative_raygen_kernel_camera`)**:
*   Generate random jitter using `RandomTEA` seeded by `params.frame_index` and ray index `i` [S1, unofficial].
*   Compute ray origin and direction. If the ray intersects the volume, initialize `RayMarchingIter` and save the payload; otherwise, write a default color if `SINGLE_SHADE_HEURISTIC` is not active [S1, unofficial].

**Ray Generation (`iterative_raygen_kernel_shadow`)**:
*   Use pre-computed `highest_org` and `jitter_ssh` from the previous camera pass. Create a shadow ray. If it intersects and the highest alpha > 0, save the payload; otherwise, write the existing shading color [S1, unofficial].

**Intersection (`iterative_intersect_kernel`)**:
*   For each sample `k`, compute the object space position `c` using linear interpolation:
    $$ c = \text{lerp}(\text{jitter}, t.x, t.y) $$
    where $t$ is the ray parameter range [S1, unofficial].
*   If `GRADIENT_SHADING`, compute gradient sample points $g_x, g_y, g_z$ by adding `gradientStep` to $c$, and store them in the inference input buffer [S1, unofficial].

**Composition (`iterative_compose_kernel`)**:
*   Retrieve sample value from `params.inference_output`.
*   Apply transfer function to get `sampleColor` and `sampleAlpha` [S1, unofficial].
*   Apply `opacityCorrection` [S1, unofficial].
*   If `GRADIENT_SHADING`:
    *   Compute normal $N_o$ from gradients and sample value.
    *   Transform to world space $N_w$.
    *   Calculate `shadingColor` and lerp with `sampleColor` using `shadingScale` [S1, unofficial].
*   If `SINGLE_SHADE_HEURISTIC`:
    *   Track the highest alpha sample. If `ssh.highest_alpha < (1.f - ray.alpha) * sampleAlpha`, update `ssh.highest_org`, `ssh.highest_color`, and `ssh.highest_alpha` [S1, unofficial].
*   Perform volume blending:
    $$ tr = 1.f - ray.alpha $$
    $$ ray.alpha += tr * sampleAlpha $$
    $$ ray.color += tr * sampleColor * sampleAlpha $$
    [S1, unofficial]
*   Continue iteration if $k < N\_ITERS$ and $ray.alpha < nearly\_one$. If the ray is finished:
    *   For `SHADOW` mode, lerp `shadingColor` with `final_highest_color * shadingColor.w * transmittance` [S1, unofficial].
    *   For `SINGLE_SHADE_HEURISTIC`, save final highest org/color/alpha and `shading_color` [S1, unofficial].
    *   Otherwise, write `ray.color` and `ray.alpha` [S1, unofficial].

### Pseudocode

```python
def iterative_ray_marching(camera, volume, transfer_function, mode, N_ITERS):
    # Initialize counter
    params.counter = cuda_memset_async(0)
    
    # Initial Ray Generation
    if mode == SHADOW:
        iterative_raygen_kernel_shadow(camera, params)
    else:
        iterative_raygen_kernel_camera(camera, params)
        
    # Main Loop
    while True:
        # Check active rays
        active_count = host_sync(params.counter)
        if active_count == 0:
            break
            
        # Intersection
        iterative_intersect_kernel<mode>(params, N_ITERS)
        
        # Neural Inference
        if volume.is_network():
            iterative_sampling_batch_inference(params, N_ITERS)
        else:
            iterative_sampling_groundtruth_kernel(params, N_ITERS)
            
        # Reset counter for compaction
        params.counter = cuda_memset_async(0)
        
        # Composition
        iterative_compose_kernel<mode>(params, N_ITERS, transfer_function)
        
    # Final Write
    write_final_results(params)
```

### Parameters
*   `N_ITERS`: The number of samples processed per kernel launch iteration. Used in assert checks and loop bounds [S1, unofficial].
*   `numCoordsPerSample`: The number of coordinate values written per sample. It is $4 \times N\_ITERS$ for `GRADIENT_SHADING` (position + 3 gradient components) and $N\_ITERS$ for other modes [S1, unofficial].

### Edge Cases and Pitfalls
*   **Intersection/Composition Separation**: The intersection step is separated from ray generation and composition due to a 'wired error' whose origin was not identified, and because merging them did not provide obvious performance benefits [S1, unofficial].
*   **Convergence**: Rays that do not reach alpha $\ge$ nearly_one within the loop limit may require additional iterations or heuristic handling (e.g., `SINGLE_SHADE_HEURISTIC`) to avoid artifacts [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Depends on the number of active rays and the depth of the volume. Each iteration processes `N_ITERS` samples per ray. Rays that do not converge quickly require multiple kernel launches, increasing overhead compared to single-pass methods.
*   **Memory Complexity**: Requires buffers for active ray state, inference inputs/outputs, and the counter. The separation of kernels allows for efficient memory reuse but adds synchronization overhead.
*   **Strengths**: Handles variable ray depths and complex occlusion dynamically. Suitable for scenes with varying density where some rays converge quickly and others require many samples.
*   **Limitations**: Kernel launch overhead for each iteration. Potential for "wired errors" if kernels are merged. Requires careful tuning of `N_ITERS` to balance between launch overhead and per-kernel work.
*   **When to Use**: Scenes with high variance in ray depth or density, where fixed-step methods might waste samples or fail to converge.
*   **When Not to Use**: Simple, uniform volumes where single-pass methods are sufficient and faster.

## Background
Iterative Ray Marching with Neural Volume Inference is part of the `instantvnr` library by VIDILabs [S1, unofficial]. It is designed to provide flexible and efficient neural volume rendering on GPUs, supporting various shading modes and integration strategies. The method addresses the challenge of handling rays that do not fully converge in a single pass, which is common in neural volume rendering due to the implicit nature of the data.
