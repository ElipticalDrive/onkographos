# Neural Network Volume Classification

Also called: Sample-based volume classification, Neural-network-driven volume renderer, Interactive classification via painting, Painting-Based Intelligent User Interface for Volume Classification

## Overview
Neural Network Volume Classification is an interactive method for partitioning volumetric data into material classes by training a neural network on user-provided samples [S1, S2]. Unlike traditional transfer function editing, which requires defining mappings in derived parameter spaces, this method replaces the transfer function space with a direct volume-space painting interface [S2]. It sets itself apart from other neural volume rendering methods (such as [NeRF Volumetric Rendering](979-nerf-volumetric-rendering-coarse-fine-sampling.md)) by focusing on explicit material classification for visualization rather than implicit scene reconstruction for novel view synthesis [S1, S2]. The system provides real-time visual feedback, allowing users to iteratively refine the classification by painting on slicing planes [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric data (scalar or color), user-painted sample points on slicing planes indicating membership (positive/negative) for a target material class.
*   **Output:** A classified volume where each voxel is assigned an uncertainty value (0 to 1) representing membership probability, which is mapped to opacity for rendering [S2].

**Data Structures:**
1.  **Sample Point Table:** Stores training data for the neural network. Each entry contains:
    *   Scalar value of the voxel (or R, G, B for color data).
    *   Gradient magnitude of the voxel.
    *   Scalar values of neighboring voxels (e.g., 6 neighbors: up, down, left, right, front, back) or RGB values for color data.
    *   Position coordinates ($x, y, z$).
    *   Desired output label (1 for material member, 0 for non-member) [S1, S2].
2.  **Neural Network Weights:** Stored in a table or memory buffer. For hardware implementation, weights are transferred to the GPU per frame [S2].

**Network Topology:**
A three-layer feed-forward perceptron [S1, S2]:
*   **Input Layer:** $m$ inputs. Dimensionality depends on data type and neighbor count.
    *   Scalar data: Scalar value + gradient magnitude + 6 neighbor scalars + 3 position coordinates = 11 inputs [S1, S2].
    *   Color data (6 neighbors): 3 RGB + 18 neighbor RGB + 3 position = 24 inputs [S1].
    *   Color data (12 neighbors): 3 RGB + 36 neighbor RGB + 3 position = 42 inputs [S2].
*   **Hidden Layer:** $n$ hidden nodes. Fully connected to input layer.
*   **Output Layer:** 1 output node. Fully connected to hidden layer.
*   **Activation Function:** Sigmoid function $f(x) = \frac{1}{1 + e^{-x}}$ [S1, S2].

**Algorithm Steps:**
1.  **Initialization:** Initialize network weights randomly [S1, S2].
2.  **User Interaction:** User paints sample points on a slice using two colors (e.g., red for target material, blue for background). Painted regions are projected to other slicers [S1, S2].
3.  **Data Collection:** Record painted voxel properties (value, gradient, neighbors, position) and labels into the Sample Point Table [S1, S2].
4.  **Training Loop (Iterative):**
    *   Perform incremental training in the system idle loop to maintain interactivity [S1, S2].
    *   **Forward Propagation:** For each sample point, compute input vector $\mathbf{I}$. Compute hidden layer activations $\mathbf{H}$ and output $O$:
        $$ H_j = f\left(\sum_{i=1}^{m} W_{ij}^{(1)} I_i + b_j^{(1)}\right) $$
        $$ O = f\left(\sum_{j=1}^{n} W_{j}^{(2)} H_j + b^{(2)}\right) $$
        Where $W^{(1)}$ are input-to-hidden weights, $W^{(2)}$ are hidden-to-output weights, and $b$ are biases [S1, S2].
    *   **Error Calculation:** Compare output $O$ with desired output $T$ (1 or 0). Calculate error [S1, S2].
    *   **Back-Propagation:** Propagate error back to input layer to adjust weights $W$ and biases $b$ to minimize error [S1, S2].
5.  **Visualization:** Apply the trained network to the volume to generate a classified uncertainty volume [S1, S2].
6.  **Refinement:** User views results. If classification is unsatisfactory, user adds/removes paint (Step 2) and training continues (Step 4) [S1, S2].

**Pseudocode:**
```python
# Data Structures
class SamplePoint:
    features: list[float]  # e.g., [scalar, gradient, n1..n6, x, y, z]
    label: float           # 1.0 for target, 0.0 for background

class NeuralNetwork:
    weights_input_hidden: list[list[float]]  # m x n
    weights_hidden_output: list[float]       # n
    biases_hidden: list[float]               # n
    biases_output: float                     # 1
    
    def __init__(self, m: int, n: int):
        # Initialize weights randomly [S1, S2]
        self.weights_input_hidden = random_matrix(m, n)
        self.weights_hidden_output = random_vector(n)
        self.biases_hidden = random_vector(n)
        self.biases_output = 0.0

    def sigmoid(self, x: float) -> float:
        return 1.0 / (1.0 + math.exp(-x))

    def forward(self, input_vector: list[float]) -> float:
        # Hidden layer
        hidden_activations = []
        for j in range(len(self.biases_hidden)):
            sum_val = self.biases_hidden[j]
            for i in range(len(input_vector)):
                sum_val += input_vector[i] * self.weights_input_hidden[i][j]
            hidden_activations.append(self.sigmoid(sum_val))
        
        # Output layer
        sum_val = self.biases_output
        for j in range(len(hidden_activations)):
            sum_val += hidden_activations[j] * self.weights_hidden_output[j]
        
        return self.sigmoid(sum_val)

    def train_step(self, samples: list[SamplePoint], learning_rate: float):
        # Incremental training in idle loop [S1, S2]
        for sample in samples:
            output = self.forward(sample.features)
            error = output - sample.label
            
            # Back-propagation [S1, S2]
            # Update output weights
            for j in range(len(self.weights_hidden_output)):
                delta = error * self.sigmoid_derivative(output) * hidden_activations[j] # [G] derivative of sigmoid
                self.weights_hidden_output[j] -= learning_rate * delta
                self.biases_output -= learning_rate * delta # [G] bias update
            
            # Update hidden weights
            for j in range(len(self.biases_hidden)):
                hidden_act = hidden_activations[j] # Recompute or store from forward
                delta_hidden = error * self.sigmoid_derivative(output) * self.weights_hidden_output[j] * self.sigmoid_derivative(hidden_act) # [G] chain rule
                for i in range(len(self.weights_input_hidden)):
                    self.weights_input_hidden[i][j] -= learning_rate * delta_hidden * sample.features[i]
                    self.biases_hidden[j] -= learning_rate * delta_hidden

    def sigmoid_derivative(self, x: float) -> float:
        return x * (1.0 - x) # Derivative of sigmoid(x)

# Main Loop
network = NeuralNetwork(m=11, n=8) # Example dimensions [S1, S2]
samples = []

while not user_satisfied:
    # User paints on slice
    new_samples = get_painted_voxels()
    samples.extend(new_samples)
    
    # Train incrementally
    network.train_step(samples, learning_rate=0.1)
    
    # Render classified volume
    classified_volume = apply_network_to_volume(network, volume_data)
    render(classified_volume)
```

**Edge Cases and Pitfalls:**
*   **Generalization Failure:** If position information is included in the input vector, painted voxels must be spread out across different slices. Painting only on one slice leads to poor generalization [S1, S2].
*   **Hardware Limits:** Hardware implementation is limited by pixel shader instruction count and data passing limits. Maximum 8 hidden nodes are supported in the cited hardware implementation [S2]. Hidden node count should be divisible by 4 for vectorization efficiency [S2].
*   **Interpolation Artifacts:** In software classification, interpolation is performed on the scalar-valued classified uncertainty volume, not an RGBA color volume [S1].

## Subtopics

### Hardware vs Software Neural Network Rendering
*   **Software:** Classifies each voxel before sending to hardware (preclassification). Allows arbitrary network size. Slow (e.g., 9 seconds for 256³ volume) [S1, S2].
*   **Hardware:** Classifies in the fragment program using interpolated data (postclassification). Limited network size (max 8 hidden nodes). Fast (e.g., 1.5 fps for 256³ volume) [S1, S2].

## Operating characteristics
*   **Time Complexity:** Training is iterative and incremental. Software classification is slow (9 seconds for 256³ volume on 2.8 GHz Pentium 4) [S1, S2]. Hardware rendering is limited by rasterization time and texture lookups (7 lookups per pixel) [S2].
*   **Memory Complexity:** Software requires storing the full classified volume. Hardware requires storing network weights (<1 KB) and volume texture [S2].
*   **Performance:** Hardware implementation achieves ~1.5 frames per second for a 256×256×256 volume rendered to a 512×512 window on an ATI Radeon 9700 Pro [S2].
*   **Strengths:** Intuitive user interface (painting in volume space); eliminates manual transfer function tuning; real-time feedback [S1, S2].
*   **Limitations:** Hardware implementation has strict limits on network size; software implementation is too slow for real-time training feedback; requires user to understand data structure for effective painting [S1, S2].
*   **When to use:** Interactive exploration and classification of biomedical or scientific volume data where user intuition guides segmentation [S1, S2].
*   **When not to use:** When high-performance real-time training feedback is required with large networks (use hardware if small network suffices, or accept slow software feedback) [S1, S2].

## Background
*   **Origin:** Proposed by [S1] and [S2] in the mid-2000s. [S2] was presented at IEEE Visualization 2003, and [S1] was published in IEEE Transactions on Visualization and Computer Graphics in 2005.
*   **Development:** The method builds on earlier work in neural networks for image segmentation [S2] and transfer function design [S2]. It addresses the difficulty users face in mapping high-dimensional data to 2D transfer functions [S2].
*   **Usage:** Primarily used in biomedical imaging for segmenting and visualizing structures like brain tissue in MRI scans [S1, S2].
