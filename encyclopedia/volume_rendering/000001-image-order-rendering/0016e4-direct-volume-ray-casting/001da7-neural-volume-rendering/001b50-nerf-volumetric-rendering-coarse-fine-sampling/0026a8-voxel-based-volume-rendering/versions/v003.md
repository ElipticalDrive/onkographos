# Voxel-based Volume Rendering

Also called: Voxel-based Radiance Field, Dense Voxel Volume Rendering

## Overview
Voxel-based Volume Rendering is a technique that trains a dense or semi-dense voxel representation of a radiance field, where multiple voxels contribute to a single sample during rendering [S1, unofficial]. It solves the problem of efficiently estimating scene opacity and color by using a structured 3D grid as a coarse model, often serving as the initial stage in two-tier sampling architectures to determine opaque regions in space [S1, unofficial]. What sets it apart from its siblings, such as [NeRF Importance Sampling](1565-nerf-importance-sampling.md) which relies on learned probability distributions, and [NerfAcc Rendering Pipeline](1619-nerfacc-rendering-pipeline.md) which uses acceleration structures like hash grids, is its reliance on a fixed, dense (or semi-dense) volumetric grid where the volume integral is approximated by summing contributions from intersected voxels [S1, unofficial]. Unlike [VF-NeRF](3138-vf-nerf.md) which may use sparse or hybrid representations, this method explicitly contrasts with sparse voxelization (octrees) by ensuring multiple voxels contribute to a single ray sample, providing structural consistency through opacity prediction independent of view direction [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ calibrated images with known camera poses $(R_i, t_i)$ and intrinsics.
*   **Output:** A rendered RGB image for a given camera pose, and optionally a depth map or opacity volume.

**Data Structures:**
*   **Voxel Grid:** A 3D tensor $V \in \mathbb{R}^{D \times D \times D \times C}$, where $D$ is the resolution (e.g., 128) and $C$ is the channel dimension.
    *   In standard implementations, $C$ typically stores density ($\sigma$) and color features ($c$).
    *   The grid is dense or semi-dense, covering the bounding box of the scene.
    *   [G] The grid is typically initialized with small random values or zeros, with density initialized to low values to represent empty space.

**Numbered Steps:**
1.  **Ray Generation:** For each pixel in the target image, generate a ray origin $o$ and direction $d$ based on the camera projection matrix.
2.  **Ray-Voxel Intersection:** Determine the interval $[t_{near}, t_{far}]$ where the ray intersects the voxel grid bounding box.
3.  **Discretization:** Divide the interval $[t_{near}, t_{far}]$ into $K$ sample points. In basic voxel rendering, these points may be uniformly spaced or aligned with voxel boundaries.
4.  **Voxel Query:** For each sample point $x_k = o + t_k d$, query the voxel grid to retrieve the density $\sigma_k$ and color feature $c_k$.
    *   If $x_k$ falls outside the grid, return zero/empty.
    *   If $x_k$ falls within a voxel, perform trilinear interpolation of the stored values from the 8 surrounding corners.
5.  **Opacity and Color Conversion:** Convert raw features to physical quantities.
    *   Density: $\sigma_k = \text{activation}(\sigma_k)$, typically using a softplus or exponential function to ensure $\sigma_k \ge 0$.
    *   Color: $c_k = \text{activation}(c_k)$, typically using sigmoid to bound RGB to $[0, 1]$.
    *   [S1, unofficial] The opacity is predicted without the view direction to encourage structural consistency.
6.  **Volume Rendering Integration:** Compute the accumulated color $C(r)$ and opacity $\alpha(r)$ along the ray using discrete integration:
    $$
    C(r) = \sum_{k=1}^{K} T_k \alpha_k c_k
    $$
    $$
    T_k = \exp\left(-\sum_{j=1}^{k-1} \sigma_j \delta_j\right), \quad \alpha_k = 1 - \exp(-\sigma_k \delta_k)
    $$
    where $\delta_k = t_{k} - t_{k-1}$ is the distance between samples, and $T_k$ is the transmittance up to sample $k$.
7.  **Loss Computation:** Compare the rendered image against the ground truth image using a loss function (e.g., MSE or LPIPS).

**Pseudocode:**
```python
def render_voxel_ray(ray_origin, ray_direction, voxel_grid, resolution, bbox_min, bbox_max):
    """
    Renders a single ray using a dense voxel grid.
    
    Args:
        ray_origin: (3,) float tensor, camera origin.
        ray_direction: (3,) float tensor, normalized ray direction.
        voxel_grid: (D, D, D, C) tensor, the trained voxel representation.
        resolution: int, D.
        bbox_min: (3,) float tensor, minimum corner of the voxel grid.
        bbox_max: (3,) float tensor, maximum corner of the voxel grid.
        
    Returns:
        color: (3,) float tensor, rendered RGB color.
        depth: float, accumulated depth.
        opacity: float, accumulated opacity.
    """
    # 1. Calculate intersection with bounding box
    t_min = (bbox_min - ray_origin) / ray_direction
    t_max = (bbox_max - ray_origin) / ray_direction
    t_near = max(max(t_min))
    t_far = min(min(t_max))
    
    if t_near > t_far:
        return torch.zeros(3), 0.0, 0.0

    # 2. Sample points along the ray
    num_samples = 128  # Typical value for coarse voxel rendering
    t_vals = torch.linspace(t_near, t_far, num_samples)
    points = ray_origin.unsqueeze(0) + t_vals.unsqueeze(1) * ray_direction.unsqueeze(0)
    
    # 3. Query voxel grid
    # Normalize points to [0, 1] range relative to bbox
    points_norm = (points - bbox_min) / (bbox_max - bbox_min)
    
    # Clamp to [0, 1] to handle boundary cases
    points_norm = torch.clamp(points_norm, 0.0, 1.0)
    
    # Trilinear interpolation
    # voxel_grid is (D, D, D, C)
    # points_norm is (num_samples, 3)
    # We need to interpolate C channels
    density_features = trilinear_interpolate(voxel_grid, points_norm)
    
    # density_features shape: (num_samples, C)
    # Assume first channel is density, rest are color features
    sigma_raw = density_features[:, 0]
    color_raw = density_features[:, 1:]
    
    # 4. Convert to physical quantities
    sigma = softplus(sigma_raw)  # Ensure non-negative density
    color = sigmoid(color_raw)   # Ensure RGB in [0, 1]
    
    # 5. Volume Rendering
    deltas = t_vals[1:] - t_vals[:-1]
    # Add a small epsilon to avoid division by zero or log(0)
    deltas = torch.cat([deltas, torch.tensor([1e-10])])
    
    alpha = 1.0 - torch.exp(-sigma * deltas)
    transmittance = torch.cumprod(torch.exp(-sigma * deltas), dim=0)
    transmittance = torch.cat([torch.tensor([1.0]), transmittance[:-1]])
    
    weights = alpha * transmittance
    color_out = torch.sum(weights.unsqueeze(1) * color, dim=0)
    opacity_out = torch.sum(weights)
    depth_out = torch.sum(weights * t_vals[:-1])
    
    return color_out, depth_out, opacity_out

def trilinear_interpolate(grid, points):
    """
    Performs trilinear interpolation on a 3D grid.
    grid: (D, D, D, C)
    points: (N, 3) in range [0, 1]
    returns: (N, C)
    """
    D = grid.shape[0]
    # Scale to voxel indices
    indices = points * (D - 1)
    x = indices[:, 0]
    y = indices[:, 1]
    z = indices[:, 2]
    
    # Get integer and fractional parts
    x0 = torch.floor(x).long()
    y0 = torch.floor(y).long()
    z0 = torch.floor(z).long()
    x1 = x0 + 1
    y1 = y0 + 1
    z1 = z0 + 1
    
    # Clamp indices
    x0 = torch.clamp(x0, 0, D - 1)
    x1 = torch.clamp(x1, 0, D - 1)
    y0 = torch.clamp(y0, 0, D - 1)
    y1 = torch.clamp(y1, 0, D - 1)
    z0 = torch.clamp(z0, 0, D - 1)
    z1 = torch.clamp(z1, 0, D - 1)
    
    # Extract values
    v000 = grid[x0, y0, z0, :]
    v100 = grid[x1, y0, z0, :]
    v010 = grid[x0, y1, z0, :]
    v110 = grid[x1, y1, z0, :]
    v001 = grid[x0, y0, z1, :]
    v101 = grid[x1, y0, z1, :]
    v011 = grid[x0, y1, z1, :]
    v111 = grid[x1, y1, z1, :]
    
    # Interpolate
    wx = x - x0
    wy = y - y0
    wz = z - z0
    
    c00 = v000 * (1 - wx) + v100 * wx
    c10 = v010 * (1 - wx) + v110 * wx
    c01 = v001 * (1 - wx) + v101 * wx
    c11 = v011 * (1 - wx) + v111 * wx
    
    c0 = c00 * (1 - wy) + c10 * wy
    c1 = c01 * (1 - wy) + c11 * wy
    
    result = c0 * (1 - wz) + c1 * wz
    
    return result
```

**Parameters:**
*   **Resolution ($D$):** Typically 64, 128, or 256. Higher resolution increases memory usage quadratically/cubically but improves detail [S1, unofficial].
*   **Number of Samples ($K$):** Typically 128–256 for coarse rendering.
*   **Activation Functions:** Softplus for density, Sigmoid for color [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Usage:** Dense voxel grids consume $O(D^3)$ memory. For $D=256$ and $C=10$, this is significant [S1, unofficial].
*   **Aliasing:** Uniform sampling may alias high-frequency details. Stratified sampling or adaptive sampling can mitigate this [S1, unofficial].
*   **Boundary Artifacts:** Rays intersecting the grid boundaries must be handled carefully to avoid out-of-bounds memory access [G].

## Subtopics

### [Coarse Ray Renderer](11371-coarse-ray-renderer.md)
The Coarse Ray Renderer (CRR) is a fast rendering technique that provides coarse density estimation and ray features for downstream processes in neural volume rendering, specifically serving the Fine Voxel Renderer (FVR) and Progressive Blur Estimation (PBE). It differs from standard per-voxel ray casting by aggregating features along a ray and inferring color once per ray rather than querying every voxel, which significantly reduces computational cost at the expense of per-voxel accuracy. It builds on [Voxel-based Volume Rendering](3845-voxel-based-volume-rendering.md) by utilizing a decomposed explicit feature volume.

### [Neural Voxel Renderer](16852-neural-voxel-renderer.md)
The Neural Voxel Renderer (NVR) is a neural network that takes a discrete voxel representation of a scene and a light position as input to produce a continuous, smooth rendered image. It solves the problem of mapping discrete geometric representations (voxels) to high-quality, physically-based renderings by implicitly learning the complex lighting and shading effects that traditional rasterization or simple volume rendering might miss. What sets it apart from its siblings, such as the Coarse Ray Renderer, is its explicit use of a dual-branch architecture (voxel encoding and light encoding) combined with a perceptual loss function to ensure photorealistic output from a structured 3D grid input.

### Deterministic Integration for Volume Rendering (DIVeR)
DIVeR is a method that jointly optimizes a feature voxel grid and a decoder MLP while applying sparsity regularization and voxel culling, innovating the volume rendering process by performing deterministic ray sampling on the voxel grid [S2]. It performs deterministic ray sampling on the voxel grid, producing an integrated feature for each ray interval defined by the intersection of the ray with a specific voxel. This integrated feature is then decoded by an MLP to produce the density and color of the ray interval [S2]. DIVeR effectively reverses the usual order of volume sampling and MLP evaluation found in NeRF methods [S2].

## Operating characteristics
*   **Time Complexity:** $O(K \cdot C)$ per ray, where $K$ is the number of samples and $C$ is the channel dimension. Trilinear interpolation is constant time per sample.
*   **Memory Complexity:** $O(D^3 \cdot C)$ for the voxel grid. This is the primary bottleneck, as memory scales cubically with resolution [S1, unofficial].
*   **Measured Performance:** On a standard GPU, a $128^3$ voxel grid can render at interactive rates for simple scenes, but performance degrades rapidly with higher resolutions or complex scenes [S1, unofficial].
*   **Strengths:** Simple implementation, differentiable, provides a good coarse approximation for two-tier sampling, structural consistency via view-independent opacity [S1, unofficial].
*   **Limitations:** High memory consumption for high resolution, potential aliasing with uniform sampling, less flexible than sparse representations for large scenes [S1, unofficial].
*   **When to Use:** As a coarse model in two-tier sampling architectures, or for scenes with moderate complexity where memory is not a constraint [S1, unofficial].
*   **When Not to Use:** For very large scenes requiring sparse representations, or when high-frequency detail is required without excessive memory usage.

## Background
Voxel-based Volume Rendering originated as a foundational technique in neural radiance field research. It was introduced in the context of Fourier Feature Networks and Neural Volume Rendering, where it served as a baseline for comparing against continuous MLP-based representations [S1, unofficial]. The method was used to demonstrate that discrete voxel representations could effectively model radiance fields, particularly when used as a coarse model for two-tier sampling [S1, unofficial]. It contrasts with sparse voxelization techniques, which use octrees to store only solid regions, by using dense or semi-dense grids where multiple voxels contribute to a single sample [S1, unofficial]. The technique has been extended in various ways, such as Deterministic Integration for Volume Rendering (DIVeR), which optimized the sampling and decoding process [S2].
