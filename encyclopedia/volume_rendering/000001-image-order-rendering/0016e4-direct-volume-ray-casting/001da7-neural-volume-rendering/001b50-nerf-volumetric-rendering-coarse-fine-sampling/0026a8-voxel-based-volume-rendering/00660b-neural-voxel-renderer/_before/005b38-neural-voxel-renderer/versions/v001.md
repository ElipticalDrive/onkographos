# Neural Voxel Renderer

Also called: NVR Architecture

## Overview
The Neural Voxel Renderer (NVR) is a neural network that takes a discrete voxel representation of a scene and a light position as input to produce a continuous, smooth rendered image [S1]. It solves the problem of mapping discrete geometric representations (voxels) to high-quality, physically-based renderings by implicitly learning the complex lighting and shading effects that traditional rasterization or simple volume rendering might miss [S1]. What sets it apart from its siblings, such as the Coarse Ray Renderer, is its explicit use of a dual-branch architecture (voxel encoding and light encoding) combined with a perceptual loss function to ensure photorealistic output from a structured 3D grid input [S1].

## How it works
**Inputs and Outputs:**
*   **Voxel Input ($V$):** A 3D grid of voxels. The source specifies dimensions $128 \times 128 \times 128$ with 4 channels (RGB + visibility), denoted as $V \in \mathbb{R}^{128 \times 4}$ [S1]. Note: The notation $\mathbb{R}^{128 \times 4}$ in the source text is likely a typo for a 3D grid structure, but the dimensions $128^3$ spatial and 4 channels are the operative parameters [S1].
*   **Light Input ($L$):** A 3D vector representing the light position, $L \in \mathbb{R}^3$ [S1].
*   **Output Image ($I$):** A 2D image with dimensions $256 \times 256$ and 3 channels (RGB), $I \in \mathbb{R}^{256 \times 3}$ [S1].

**Data Structures:**
The network $\theta$ processes $V$ and $L$ to produce $I$. The internal data structures consist of feature maps generated by convolutional layers. The voxel branch produces 2D feature maps of a specific spatial resolution (matching the tiled light features). The light branch produces a latent vector.

**Numbered Steps:**
1.  **Voxel Encoding:** Process the 3D input voxels $V$ through a series of 3D convolutions.
2.  **Reshaping:** Transform the 3D features into 2D by reshaping the last two dimensions. If the feature tensor is $h \times w \times d \times c$, it becomes $h \times w \times (d \times c)$ [S1]. This step is described as an orthographic projection in latent space, keeping all depth information [S1].
3.  **2D Convolution:** Process the reshaped features through a series of 2D convolutional blocks (followed by batch normalization and ReLU activations) to produce the final voxel encoding features [S1].
4.  **Light Encoding:** Process the light input $L$ through a separate branch consisting of 2 fully connected layers to deliver latent illumination features [S1].
5.  **Tiling:** Tile the latent illumination features to form an image with the same spatial dimensions as the final features from the voxel encoding branch [S1]. This ensures every spatial location has illumination information [S1].
6.  **Concatenation:** Concatenate the tiled light features with the voxel encoding features along the channel dimension [S1].
7.  **Decoding:** Feed the joint features to a decoder (a series of 2D convolutional layers) that outputs the final image $I$ at resolution $256 \times 256$ [S1].

**Formulas:**
The network is trained by minimizing the loss function $L(I, T)$:

$$
L(I, T) = ||I - T||_1 + \beta \sum_i w_i ||v_i(I) - v_i(T)||_2
$$

Where:
*   $I$ is the predicted image.
*   $T$ is the target image (produced by a traditional physically-based renderer like Blender Cycles) [S1].
*   $v_i$ is the response of the $i$-th layer of a pretrained VGG network [S1].
*   $w_i$ is the weighting factor for layer $i$. For layers conv1 and conv2, $w_i$ are set to 1.0 and 0.1 respectively [S1].
*   $\beta$ is a hyperparameter [S1].

**Parameters:**
*   **Optimizer:** Adam [S1].
*   **Learning Rate:** $10^{-4}$ [S1].
*   **Batch Size:** 10 [S1].
*   **VGG Layers:** conv1 and conv2 are used for perceptual loss [S1].

```python
           Source implies spatial dims 128x128x128. PyTorch Conv3d expects (N, C, D, H, W).
           Assuming input V is (B, 4, 128, 128, 128).
        L: Tensor of shape (B, 3)

        # 1. Voxel Encoding
        # Process through 3D convolutions
        x = self.voxel_3d_conv(V) # Shape: (B, C, 128, 128, 128)
        
        # 2. Reshaping: h x w x d x c -> h x w x (d * c)
        # Assuming x is (B, C, D, H, W) = (B, C, 128, 128, 128)
        # Reshape to (B, C, 128, 128*128) -> (B, C, 128, 16384)

        # However, standard "reshape" in these papers often implies flattening depth or spatial.
        # Source: "h x w x d x c becomes h x w x (d * c)".
        # This implies the tensor layout is (H, W, D, C).
        # Let's assume the feature tensor before reshape is (B, H, W, D, C).
        # PyTorch Conv3d outputs (B, C, D, H, W). We need to permute to (B, H, W, D, C) first.
        x = x.permute(0, 2, 3, 1, 4) # (B, D, H, W, C) -> wait, source says h x w x d x c.
        # Let's stick to the source's logical description:
        # Input to reshape: Features with dims h, w, d, c.
        # Output: h, w, d*c.
        # In PyTorch (N, C, D, H, W), if we treat D as depth, H,W as spatial.
        # The source likely refers to a specific memory layout or a conceptual step.
        # We will implement the logical transformation: flatten depth and channel, keep spatial.
        
        # Re-evaluating based on "orthographic projection in latent space":
        # Usually, this means projecting the 3D volume onto a 2D plane.
        # But the source says "reshaping its last two dimensions... h x w x (d * c)".
        # This keeps h and w, and merges d and c.
        # If tensor is (B, C, D, H, W), last two are H, W. Reshaping H, W to H*W gives (B, C, D, H*W).
        # This does not match "h x w x (d * c)".
        # If tensor is (B, H, W, D, C), last two are D, C. Reshaping D, C to D*C gives (B, H, W, D*C).
        # This matches "h x w x (d * c)".
        # So we must permute Conv3d output (B, C, D, H, W) to (B, H, W, D, C).
        
        # Step 1: Permute to (B, H, W, D, C)
        # Conv3d output: (B, C_in, D, H, W)
        # We need to assume the 3D convs preserve the spatial structure.
        # Let's assume the 3D conv block outputs (B, C, 128, 128, 128).
        # Permute to (B, 128, 128, 128, C) -> (B, H, W, D, C)
        x = x.permute(0, 2, 3, 1, 4) # (B, D, H, W, C) -> No, (B, C, D, H, W) -> (B, H, W, D, C)
        # Correct permutation for (B, C, D, H, W) to (B, H, W, D, C):
        # Indices: 0->0, 3->1, 4->2, 2->3, 1->4
        x = x.permute(0, 3, 4, 2, 1) # (B, H, W, D, C)
        
        # Step 2: Reshape last two dims (D, C) to (D*C)
        B, H, W, D, C = x.shape
        x = x.view(B, H, W, D * C) # (B, H, W, D*C)
        
        # Step 3: 2D Convolutional blocks
        # Input to 2D conv is (B, H, W, D*C). PyTorch Conv2d expects (B, C, H, W).
        x = x.permute(0, 3, 1, 2) # (B, D*C, H, W)
        x = self.voxel_2d_conv(x)
        
        # 4. Light Encoding
        l_feat = F.relu(self.light_fc1(L))
        l_feat = self.light_fc2(l_feat) # Shape: (B, 128)
        
        # 5. Tiling
        # Tile l_feat to match spatial dimensions of x (H, W)
        # x shape is (B, C_voxel, H, W)
        # l_feat needs to be (B, C_voxel, H, W)
        # Assuming l_feat dim matches C_voxel for concatenation.
        # Source says "same dimensions as the final features from the voxel encoding branch".
        # Let's assume the light branch outputs a vector of size C_voxel.
        # If not, we might need a linear layer to match channels.
        # For this implementation, we assume l_feat is reshaped/tiled to (B, C_voxel, H, W).
        # Since l_feat is (B, 128), and x is (B, C_voxel, H, W), we assume C_voxel = 128.
        l_tiled = l_feat.view(B, -1, 1, 1).expand(-1, -1, H, W)
        
        # 6. Concatenation
        joint = torch.cat([x, l_tiled], dim=1) # (B, 2*C_voxel, H, W)
        
        # 7. Decoding
        out = self.decoder(joint)
        return out
```

**Edge Cases and Pitfalls:**
*   **Precision:** The use of perceptual loss with VGG requires careful normalization of input images to match VGG's expected input distribution (typically mean/std normalization) [S1].
*   **Boundaries:** The voxel input is fixed at $128^3$. Scenes larger or smaller than this resolution may require preprocessing or interpolation [S1].
*   **Symmetry:** The source mentions taking advantage of symmetry for man-made objects by copying color from symmetric voxels if the original is not visible. This is a preprocessing step for the voxel data, not part of the network forward pass [S1].

## Subtopics

### NVR+
An extension of NVR that adds a rerendering network (using RenderNet as a backbone) to handle high-frequency and irregular textures that the base NVR might blur or artifact [S1]. It maintains high-quality textures while producing correct overall scene appearance [S1].

### Coarse Ray Renderer
A sibling method in the volume rendering hierarchy. While NVR uses a fixed voxel grid and neural network to map to images, Coarse Ray Rendering typically involves sampling rays through a volume representation. NVR is distinct in its explicit dual-branch architecture and direct image output from voxels [S1, Coarse Ray Renderer].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** The network is trained to produce smooth surfaces in the output image, implicitly learning to map discrete voxels to continuous renderings [S1].
*   **Strengths:** Can render overall structure, colors, reflections, and shadows well [S1]. Implicitly learns to smooth discrete geometric representations [S1].
*   **Limitations:** When the color pattern of the object in the input voxels forms a high-frequency and irregular texture, the output is blurry and has artifacts [S1]. This limitation led to the development of NVR+ [S1].
*   **When to use:** When a smooth, photorealistic rendering is needed from a voxel representation, and the scene does not have high-frequency irregular textures [S1].
*   **When not to use:** When the input voxels contain high-frequency, irregular textures, as the base NVR will produce blurry results with artifacts [S1].

## Background
The Neural Voxel Renderer was introduced in the paper "Neural Voxel Renderer: Learning an Accurate and Controllable Rendering Tool" [S1]. The method uses a traditional, physically-based renderer (Blender Cycles) to generate target images $T$ from 3D meshes, which are then used to train the neural network [S1]. The architecture is illustrated in Fig. 4 of the source paper [S1].
