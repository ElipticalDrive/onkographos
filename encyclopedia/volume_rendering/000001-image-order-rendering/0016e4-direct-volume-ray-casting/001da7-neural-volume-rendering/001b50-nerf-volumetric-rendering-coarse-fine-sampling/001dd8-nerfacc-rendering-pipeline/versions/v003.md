# NerfAcc Rendering Pipeline

Also called: Efficient Sampling for Volumetric Rendering, NeRF Volume Rendering (CPU/PyTorch), NerfAcc

## Overview
The NerfAcc Rendering Pipeline is a modular, high-performance volumetric rendering framework implemented as a PyTorch library that decouples efficient sampling from the radiance field representation [S1]. It solves the computational bottleneck of neural volume rendering by using a Transmittance Estimator (such as an Occupancy Grid or Proposal Network) to generate non-uniform sample intervals along rays, which are then integrated via differentiable rendering [S1]. Unlike standard uniform sampling or sibling methods like [NeRF Importance Sampling](1565-nerf-importance-sampling.md) which may sample the entire space, NerfAcc combines occupancy grids to skip empty space and proposal networks to concentrate samples on surfaces, achieving speedups of 1.5× to 20× with minimal code changes [S1].

## How it works
The pipeline initializes a transmittance estimator, generates coarse samples, performs efficient interval-based sampling, queries the neural network for RGB and density, integrates the results via differentiable volumetric rendering, and periodically updates the estimator [S1].

### Inputs and Outputs
*   **Inputs**: Ray origins $r_o \in \mathbb{R}^{N \times 3}$, ray directions $r_d \in \mathbb{R}^{N \times 3}$ (normalized), near/far clipping planes ($near, far$), and a neural radiance field model `nerf` providing `density` and `forward` (RGB + density) functions [S1].
*   **Outputs**: Rendered color $C$, opacity $\alpha$, depth $z$, and auxiliary data (e.g., depth variance) for the batch of rays [S1].

### Data Structures
Samples are represented as **intervals** $(t_0, t_1, r)$ rather than single points $x$, where $t_0$ and $t_1$ are the start and end distances along the $r$-th ray [S1]. This interval representation supports cone-based anti-aliasing (e.g., Mip-NeRF) and avoids redundant queries at interval boundaries [S1].

### Steps

1.  **Initialize Transmittance Estimator**: Create an estimator to guide sampling, such as an Occupancy Grid or Proposal Network [S1].
2.  **Initialize Coarse Samples**: Generate initial sample positions using log-space distribution, then map them to the $[near, far]$ range [S2, unofficial].
3.  **Define Density Query Function**: Create a wrapper that queries the neural network for density given interval endpoints and ray indices [S1].
4.  **Perform Efficient Sampling**: Use the estimator and density function to generate packed sample intervals $(t_0, t_1, r\_id)$ [S1].
5.  **Define RGB/Density Query Function**: Create a wrapper that returns both color and density for the rendered intervals [S1].
6.  **Differentiable Volumetric Rendering**: Integrate the samples to compute color, opacity, and depth [S1]. The internal rendering logic follows these formulas:
    *   **Deltas**: Compute interval lengths, appending a sample distance for the last interval [S2, unofficial].
    *   **Alpha**: Convert density $\sigma$ to opacity $\alpha$ [S2, unofficial].
    *   **Weights**: Compute rendering weights $w_i$ using the cumulative product of transmittance [S2, unofficial].
    *   **Color**: Weighted sum of colors $c_i$ [S2, unofficial].
    *   **Depth**: Weighted mean of midpoints $z_{mid}$ [S2, unofficial].
    *   **Depth Variance**: Weighted variance of depths [S2, unofficial].
7.  **Background Contribution**: If alpha is premultiplied, add background color based on accumulated opacity [S2, unofficial].
8.  **Update Transmittance Estimator**: Periodically update the estimator (e.g., every $n$ steps) using the sampled intervals and auxiliary data to improve future sampling [S1].
9.  **Loss and Backpropagation**: Compute loss against ground truth and backpropagate [S1].

```python
def volumetric_rendering(t0, t1, r_id, rgb_density_fn, sample_dist=0.01):
    # Query RGB and density for all intervals [S2, unofficial]
    rgbs, sigmas = rgb_density_fn(t0, t1, r_id)
    # Compute deltas (interval lengths) [S2, unofficial]
    deltas = t1 - t0
    # Append sample distance for the last interval [S2, unofficial]
    deltas = torch.cat([deltas, sample_dist * torch.ones_like(deltas[:, :, :1])], dim=-1)
    # Compute opacity alpha [S2, unofficial]
    alphas = 1.0 - torch.exp(-deltas * sigmas)
    # Compute shifted alphas for numerical stability [S2, unofficial]
    alphas_shifted = torch.cat([torch.ones_like(alphas[:, :, :1]), 1.0 - alphas + 1e-15], dim=-1)
    # Compute rendering weights [S2, unofficial]
    weights = alphas * torch.cumprod(alphas_shifted, dim=-1)[:, :, :-1]
    # Compute color [S2, unofficial]
    color = torch.sum(weights.unsqueeze(-1) * rgbs, dim=-2)
    # Compute depth [S2, unofficial]
    midpoints = (t0 + t1) / 2.0
    depth = torch.sum(weights * midpoints, dim=-1)
    # Compute depth variance [S2, unofficial]
    z = depth
    var = torch.sum(weights * ((t1 - z)**2 + (t1 - z)*(t0 - z) + (t0 - z)**2) / 3.0, dim=-1)
    return color, weights.sum(dim=-1), depth, {"var": var}
```

### Parameters and Typical Values
*   `num_steps`: Number of coarse samples per ray (e.g., 64, 128) [G].
*   `near`, `far`: Clipping distances (scene-dependent) [G].
*   `update_every_n_steps`: Frequency of estimator updates (e.g., 10, 100) [G].
*   `bound`: Clamping bound for hashgrid encoders to prevent NaNs (e.g., 1.0, 2.0) [S2, unofficial].

### Edge Cases and Pitfalls
*   **NaN in HashGrid Encoders**: Points must be clamped to $[-bound, bound]$ before querying hashgrid-based encoders to prevent NaN gradients [S2, unofficial].
    ```python
    pts = pts.clamp(-self.bound, self.bound)
    ```

*   **Numerical Stability**: When computing cumulative products for transmittance, add a small epsilon ($10^{-15}$) to $1 - \alpha$ to prevent underflow and NaNs [S2, unofficial].
*   **Interval Boundaries**: The interval-based representation $(t_0, t_1)$ avoids querying the same point twice at boundaries, but requires careful handling of the last interval's delta if it extends beyond the last sampled point [S1][S2, unofficial].

## Subtopics

### NeRF Upsampling (Fine Sampling)
A variant that refines coarse samples by resampling around high-weight intervals [S2, unofficial]. It computes deltas and alphas from coarse samples, derives weights for PDF sampling, calculates midpoints, and samples new $z$ values using `sample_pdf` [S2, unofficial]. New points are queried for density and RGB, and results are gathered using sort indices to maintain order [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: Depends on the number of samples generated by the estimator [S1]. By skipping empty space (Occupancy Grid) and concentrating on surfaces (Proposal Network), it reduces the number of neural network queries compared to uniform sampling [S1].
*   **Memory Complexity**: Linear with respect to the number of active samples [S1]. The interval-based representation $(t_0, t_1, r)$ stores only interval endpoints and ray indices [S1].
*   **Performance**: Reported speedups of 1.5× to 20× over baseline NeRF implementations with minor code modifications [S1].
*   **Strengths**: Modular design allows easy integration with various radiance fields (density-based or SDF-based, static or dynamic) [S1]. Combines the strengths of Occupancy Grids and Proposal Networks [S1].
*   **Limitations**: Requires careful tuning of the estimator parameters [S1]. The interval-based approach may complicate direct point-wise analysis if not handled correctly [S1].

## Background
NerfAcc was introduced in the paper "NerfAcc: Efficient Sampling Accelerates NeRFs" (ICCV 2023) [S1]. It was designed to address the computational inefficiency of neural radiance field rendering by providing a universal, decoupled sampling framework [S1]. The library fuses operations into CUDA kernels for maximum speed while exposing flexible Python APIs [S1]. It builds on techniques from Instant-NGP (Occupancy Grids) and Mip-NeRF 360 (Proposal Networks) [S1].
