# In-Shader Neural Volume Ray Marching

Also called: in-shader rendering

## Overview
In-Shader Neural Volume Ray Marching is a direct volume rendering technique where the neural network (MLP) is evaluated directly inside the CUDA kernel for each sample point during ray marching, rather than pre-decoding the volume into a 3D texture or using sample-streaming [S1, unofficial]. It replaces traditional texture lookups with neural network inference at runtime [S1, unofficial]. Unlike [Radiance-Predicting Neural Networks (RPNN)](7049-radiance-predicting-neural-networks-rpnn.md), which queries the network for accumulated multiple scattering contributions based on a global shading configuration, this method evaluates the network per sample point [S1, unofficial]. It supports multiple shading modes including gradient shading and single-shade heuristics [S1, unofficial].

## How it works
**Inputs:**
*   Camera parameters: origin $\mathbf{o}$, direction $\mathbf{d}$, and screen coordinates $(u, v)$.
*   Neural Volume model: A CUDA device class wrapping the neural network (e.g., `TcnnDeviceVolume` or `FvsrnDeviceVolume`) [S1, unofficial].
*   Transfer Function: Maps sampled values to color and alpha [S1, unofficial].
*   Rendering Parameters: Shading mode (`GRADIENT_SHADING` or `SINGLE_SHADE_HEURISTIC`), shading scale, gradient step size, and bounding box [S1, unofficial].

**Outputs:**
*   Final pixel color $C$ and alpha $\alpha$.

**Data Structures:**
*   `TcnnDeviceVolume<N, N_FEATURES_PER_LEVEL>`: CUDA device class for standard MLPs. Template parameters define network width ($N \in \{16, 32, 64\}$) and features per level [S1, unofficial].
*   `FvsrnDeviceVolume<N>`: CUDA device class for fV-SRN networks. Used when `N_FEATURES_PER_LEVEL == -2`. Supports widths from $16 \times 1$ to $16 \times 8$ [S1, unofficial].
*   `RenderContext`: Holds volume, camera, transfer function, framebuffer, and rendering mode [S1, unofficial].

**Steps:**

1.  **Ray Initialization:**
    Transform the ray origin from camera space to world space:
    $$ \mathbf{o}_{world} = \text{xfmPoint}(W_{to}, \mathbf{o}_{camera}) $$
    Construct the ray direction from the camera's forward, horizontal, and vertical vectors, shifted by normalized screen position $(u - 0.5)$ and $(v - 0.5)$, then normalized [S1, unofficial].

2.  **Bounding Box Intersection:**
    Intersect the ray with the volume bounding box to find entry $t_0$ and exit $t_1$ [S1, unofficial]. If no intersection is found, return the background color and alpha [S1, unofficial].

3.  **Ray Marching Loop:**
    Iterate through the ray segment $[t_0, t_1]$ using an iterator. For each step interval $[t_{start}, t_{end}]$:
    *   **Sample Position:** Compute the sample position $\mathbf{p}$ using jittered linear interpolation:
        $$ \mathbf{p} = \mathbf{o}_{world} + \text{lerp}(\text{jitter}, t_{start}, t_{end}) \cdot \mathbf{d}_{world} $$
    *   **Neural Query:** Evaluate the neural network at $\mathbf{p}$:
        $$ \text{value} = \text{neuralvolume.sample}(\mathbf{p}) $$
        This replaces traditional texture lookups [S1, unofficial].
    *   **Gradient Estimation (Optional):** If `params.mode == GRADIENT_SHADING`, estimate the gradient numerically using finite differences with step size `grad_step`:
        $$ \nabla \text{value} \approx \frac{\text{value}(\mathbf{p} + \Delta) - \text{value}(\mathbf{p} - \Delta)}{2 \Delta} $$
        Negate the gradient for shading purposes [S1, unofficial]. Otherwise, set gradient to zero [S1, unofficial].
    *   **Transfer Function:** Apply the transfer function to `value` to obtain `sampleColor` and `sampleAlpha` [S1, unofficial]. Apply opacity correction for the step size $\delta = t_{end} - t_{start}$ [S1, unofficial].
    *   **Shading (Optional):**
        *   If `GRADIENT_SHADING`: Transform the gradient to world space $\mathbf{N}_w$ and the ray direction to world space. Compute shaded color using `shade_scivis_light` with ambient and directional light parameters. Interpolate between raw sample color and shaded color using `shadingScale` [S1, unofficial]:
            $$ C_{shaded} = \text{lerp}(\text{shadingScale}, C_{raw}, C_{lighting}) $$
        *   If `SINGLE_SHADE_HEURISTIC`: Track the sample point with the highest density/alpha.
    *   **Compositing:** Composite the sample into the accumulated color and alpha using front-to-back blending:
        $$ C_{acc} += T \cdot C_{sample} \cdot \alpha_{sample} $$
        $$ \alpha_{acc} += T \cdot \alpha_{sample} $$
        $$ T = 1 - \alpha_{acc} $$
        where $T$ is the transmittance [S1, unofficial].
    *   **Termination:** Continue marching while `alive` is true and `alpha < nearly_one` [S1, unofficial].

4.  **Single Shade Heuristic (Optional):**
    If `params.mode == SINGLE_SHADE_HEURISTIC` and `highestAlpha > 0`:
    *   Calculate transmittance from the highest density point to the light source using a secondary ray march [S1, unofficial].
    *   Interpolate the final color:
        $$ C_{final} = \text{lerp}(\text{shadingScale}, C_{acc}, C_{highest} \cdot \alpha_{highest} \cdot T_{light}) $$
        [S1, unofficial].

**Pseudocode:**

```python
def in_shader_neural_volume_ray_marching(camera, neural_volume, transfer_function, params, framebuffer):
    """
    Renders a frame using in-shader neural volume ray marching.
    
    Args:
        camera: Camera object with position, forward, horizontal, vertical vectors.
        neural_volume: Object with sample(p) method.
        transfer_function: Object with apply(value) returning (color, alpha).
        params: Dict with 'mode', 'shading_scale', 'grad_step'.
        framebuffer: Output buffer.
    """
    width, height = framebuffer.size
    for y in range(height):
        for x in range(width):
            # 1. Ray Initialization
            # Normalize screen coordinates to [-0.5, 0.5]
            u = (x + 0.5) / width - 0.5
            v = (y + 0.5) / height - 0.5
            
            # Construct ray direction in camera space
            ray_dir_cam = camera.forward + u * camera.horizontal + v * camera.vertical
            ray_dir_cam = normalize(ray_dir_cam)
            
            # Transform origin to world space
            ray_org_world = xfm_point(camera.world_to_world_matrix, camera.position)
            ray_dir_world = xfm_vector(camera.world_to_world_matrix, ray_dir_cam)
            
            # 2. Bounding Box Intersection
            t0, t1 = intersect_volume_bbox(ray_org_world, ray_dir_world)
            if t0 > t1:
                framebuffer.set_pixel(x, y, camera.background_color, 0.0)
                continue
            
            # 3. Ray Marching
            accumulated_color = vec3(0.0)
            accumulated_alpha = 0.0
            highest_density_point = None
            highest_alpha = 0.0
            
            t = t0
            step_size = (t1 - t0) / params.num_samples
            
            while t < t1 and accumulated_alpha < 0.999:
                # Jittered sampling
                jitter = random_float()
                t_start = t + jitter * step_size
                t_end = t_start + step_size
                
                # Sample position
                p = ray_org_world + lerp(t_start, t_end, ray_dir_world)
                
                # Neural Query
                value = neural_volume.sample(p)
                
                # Gradient Estimation (if needed)
                gradient = vec3(0.0)
                if params.mode == GRADIENT_SHADING:
                    grad_step = params.grad_step
                    # Numerical gradient estimation
                    # Note: In practice, this might use automatic differentiation or finite differences
                    # Here we assume a helper function exists
                    gradient = sample_gradient(p, value, grad_step, neural_volume.sample)
                    gradient = -gradient # Negate for shading
                
                # Transfer Function
                sample_color, sample_alpha = transfer_function.apply(value)
                
                # Opacity correction for step size
                # Assuming sample_alpha is already scaled or needs scaling by delta_t
                # The source mentions "apply opacity correction for the step size"
                # Typically: alpha = 1 - exp(-sigma * delta_t)
                # If value is sigma, we compute alpha here. If value is already processed, adjust accordingly.
                # Based on source: "Apply opacity correction for the step size t.y - t.x"
                delta_t = t_end - t_start
                # If value is raw density sigma:
                # sample_alpha = 1.0 - exp(-value * delta_t)
                # If value is already processed by TF, the TF might handle it.
                # We assume TF returns alpha for the specific sample point.
                
                # Shading
                if params.mode == GRADIENT_SHADING:
                    # Transform gradient to world space
                    Nw = xfm_normal(camera.world_to_world_matrix, gradient)
                    # Compute shaded color
                    shaded_color = shade_scivis_light(Nw, ray_dir_world, params.light_params)
                    # Interpolate
                    sample_color = lerp(params.shading_scale, sample_color, shaded_color)
                
                # Track highest alpha for single shade heuristic
                if sample_alpha > highest_alpha:
                    highest_alpha = sample_alpha
                    highest_density_point = p
                
                # Compositing
                transmittance = 1.0 - accumulated_alpha
                accumulated_color += transmittance * sample_color * sample_alpha
                accumulated_alpha += transmittance * sample_alpha
                
                t = t_end
            
            # 4. Single Shade Heuristic
            if params.mode == SINGLE_SHADE_HEURISTIC and highest_alpha > 0.0:
                # Secondary ray march to light
                # Assuming light direction is known
                light_dir = normalize(params.light_direction)
                transmittance_to_light = network_raymarching_transmittance(
                    highest_density_point, light_dir, neural_volume, transfer_function
                )
                # Interpolate final color
                # highest_color is the color at the highest density point
                # This part is simplified; source implies interpolation with shadingScale
                final_color = lerp(params.shading_scale, accumulated_color, highest_density_point_color * highest_alpha * transmittance_to_light)
                accumulated_color = final_color
            
            framebuffer.set_pixel(x, y, accumulated_color, accumulated_alpha)
```

**Parameters:**
*   `params.mode`: Shading mode. `GRADIENT_SHADING` computes gradients for local Phong shading. `SINGLE_SHADE_HEURISTIC` tracks the highest density point for deferred shading [S1, unofficial].
*   `params.scivis_shading_scale`: Scalar float controlling interpolation between raw sample color and shaded color in gradient shading mode [S1, unofficial].
*   `params.grad_step`: Step size for numerical gradient estimation via finite differences [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Unsupported MLP Width:** If the network width is not 16, 32, or 64 for standard networks, or not a multiple of 16 (16*1 to 16*8) for fV-SRN, the renderer prints an error and returns without rendering [S1, unofficial].
*   **Incorrect Encoding Method:** If `N_FEATURES_PER_LEVEL` is -1, the renderer prints an error indicating an incorrect encoding method for in-shader rendering [S1, unofficial].

## Subtopics

### [Radiance-Predicting Neural Networks (RPNN)](7049-radiance-predicting-neural-networks-rpnn.md)
A technique that uses an MLP to predict radiance for multiple scattering events in high-order scattering media. It queries the network for accumulated contributions based on global shading configuration, enabling results nearly identical to path tracing but approximately a thousand times faster. Choose this for atmospheric clouds or high-order scattering; choose In-Shader Neural Volume Ray Marching for per-sample evaluation and general volume rendering.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is the number of samples per ray. Each sample requires a neural network inference, which is more expensive than a texture lookup.
*   **Memory Complexity:** Depends on the neural network size. The network weights are stored in GPU memory. The `TcnnDeviceVolume` and `FvsrnDeviceVolume` classes manage this [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Performance scales with network width and depth. Larger networks provide higher fidelity but slower inference [S1, unofficial].
*   **Strengths:** No need for pre-decoding the volume into a 3D texture. Supports complex neural network representations directly in the shader. Supports multiple shading modes [S1, unofficial].
*   **Limitations:** Computationally expensive due to per-sample neural network inference. Limited by supported network widths and encoding methods [S1, unofficial].
*   **When to use:** When high-fidelity neural volume representations are required and pre-decoding is not feasible or desirable. When gradient-based shading is needed [S1, unofficial].
*   **When not to use:** When real-time performance is critical and network inference is too slow. When the volume can be efficiently represented by a 3D texture [S1, unofficial].

## Background
In-Shader Neural Volume Ray Marching is part of the InstantVNR (Instant Neural Volume Rendering) framework developed by VIDILabs [S1, unofficial]. It was introduced to enable efficient rendering of neural volume representations directly in the GPU shader without pre-decoding [S1, unofficial]. The method supports various neural network architectures, including standard MLPs and fV-SRN networks [S1, unofficial].
