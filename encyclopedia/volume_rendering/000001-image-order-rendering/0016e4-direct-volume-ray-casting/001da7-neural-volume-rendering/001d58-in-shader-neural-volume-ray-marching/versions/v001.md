# In-Shader Neural Volume Ray Marching

Also called: in-shader rendering

## Overview
In-Shader Neural Volume Ray Marching is a direct volume rendering technique where the neural network (MLP) is evaluated directly inside the CUDA kernel for each sample point, rather than pre-decoding the volume into a 3D texture or using sample-streaming [S1, unofficial]. It supports multiple shading modes including gradient shading and single-shade heuristics [S1, unofficial]. Unlike [NeRF Volumetric Rendering (Coarse/Fine Sampling)](979-nerf-volumetric-rendering-coarse-fine-sampling.md) which often relies on hierarchical sampling strategies, this method performs a uniform or jittered march through the volume bounding box, evaluating the neural field on-the-fly to determine density and color at each step.

## How it works
**Inputs and Outputs:**
- **Input:** A trained neural volume model (MLP), camera parameters (position, orientation, field of view), transfer function, and rendering parameters (shading mode, step size, gradient step).
- **Output:** A 2D image (framebuffer) with accumulated color and alpha.

**Data Structures:**
The neural volume is wrapped in a CUDA device class. Two primary implementations are supported [S1, unofficial]:
1.  `TcnnDeviceVolume<N, N_FEATURES_PER_LEVEL>`: Wraps a standard tiny-cuda-nn MLP. Template parameters define network width ($N \in \{16, 32, 64\}$) and features per level. Provides `init()`, `launch2D()`, and `sample(p)` methods.
2.  `FvsrnDeviceVolume<N>`: Used when `N_FEATURES_PER_LEVEL == -2` (indicating fV-SRN networks). Supports widths from $16 \times 1$ to $16 \times 8$. Provides `init()`, `launch()`, and `sample(p)` methods.

**Parameters:**
-   `params.mode`: Shading mode. Values include `GRADIENT_SHADING` and `SINGLE_SHADE_HEURISTIC` [S1, unofficial].
-   `params.scivis_shading_scale`: Scalar float controlling interpolation between raw sample color and shaded color in gradient mode [S1, unofficial].
-   `params.grad_step`: Step size for numerical gradient estimation via finite differences [S1, unofficial].
-   `sampling_rate`: Controls the density of samples along the ray [S1, unofficial].
-   `density_scale`: Scales the output density from the neural network [S1, unofficial].

**Algorithm Steps:**

1.  **Ray Initialization:**
    Initialize the ray origin and direction in world space.
    -   Transform camera position to world space: `ray.org = xfmPoint(wto, camera.position)`.
    -   Construct ray direction from camera forward, horizontal, and vertical vectors, shifted by normalized screen position $(screen.x - 0.5f)$ and $(screen.y - 0.5f)$, then normalized.

2.  **Volume Intersection:**
    Intersect the ray with the volume bounding box using `intersectVolume(t0, t1, ray.org, ray.dir, self)`.
    -   If no intersection is found (`!block_any(...)`), return the background color and alpha.
    -   Otherwise, the ray segment of interest is $[t0, t1]$.

3.  **Ray Marching Loop:**
    Iterate through the ray using an iterator `network_raymarching_iterator`. For each step interval $[t.x, t.y]$:
    -   **Sample Position:** Compute position $p$ using jittered linear interpolation:
        $$ p = \text{ray.org} + \text{lerp}(\text{jitter}, t.x, t.y) \times \text{ray.dir} $$
    -   **Neural Inference:** Sample the neural volume at $p$:
        $$ \text{value} = \text{neuralvolume.sample}(p) $$
        This replaces traditional texture lookups with neural network inference [S1, unofficial].
    -   **Gradient Estimation (Optional):** If `params.mode == GRADIENT_SHADING`, estimate the volume gradient numerically:
        $$ \nabla \text{value} = \text{sampleGradient}(p, \text{value}, \text{grad\_step}, \text{sampler}) $$
        Negate the gradient for shading purposes. Otherwise, gradient is zero.
    -   **Transfer Function:** Apply the transfer function to `value` to get `sampleColor` and `sampleAlpha`:
        $$ (\text{sampleColor}, \text{sampleAlpha}) = \text{sampleTransferFunction}(\text{tfn}, \text{value}) $$
        Apply opacity correction for the step size $\Delta t = t.y - t.x$.
    -   **Shading (Optional):**
        -   If `GRADIENT_SHADING`: Transform gradient to world space $N_w = \text{xfmNormal}(otw, \nabla \text{value})$ and ray direction to world space. Compute shaded color using `shade_scivis_light` with ambient and directional lights. Interpolate:
            $$ \text{finalSampleColor} = \text{lerp}(\text{shadingScale}, \text{sampleColor}, \text{shadedColor}) $$
        -   If `SINGLE_SHADE_HEURISTIC`: Track the point with the highest density (`highestOrg`, `highestAlpha`) encountered so far.
    -   **Compositing:** Accumulate color and alpha using front-to-back blending:
        $$ \text{tr} = 1.0 - \text{alpha} $$
        $$ \text{color} += \text{tr} \times \text{finalSampleColor} \times \text{sampleAlpha} $$
        $$ \text{alpha} += \text{tr} \times \text{sampleAlpha} $$
    -   **Termination:** Continue while `alive` is true and `alpha < nearly_one`. The iterator callback returns `alive && (alpha < nearly_one)` [S1, unofficial].

4.  **Single Shade Heuristic (Post-March):**
    If `params.mode == SINGLE_SHADE_HEURISTIC` and `highestAlpha > 0.f`:
    -   Calculate transmittance from the highest density point (`highestOrg`) to the light source using a secondary ray march `network_raymarching_transmittance` towards the light direction.
    -   Apply the heuristic result by interpolating the final color:
        $$ \text{color} = \text{lerp}(\text{shadingScale}, \text{color}, \text{highestColor} \times \text{alpha} \times \text{transmittance}) $$

**Pseudocode:**

```python
def in_shader_neural_volume_ray_marching(camera, neural_volume, transfer_function, params):
    """
    Renders a frame using in-shader neural volume ray marching.
    
    Args:
        camera: Camera object with position, forward, horizontal, vertical vectors.
        neural_volume: Object with sample(p) method.
        transfer_function: Object mapping value to (color, alpha).
        params: Dict with 'mode', 'scivis_shading_scale', 'grad_step', 'sampling_rate', 'density_scale'.
        
    Returns:
        framebuffer: 2D array of (color, alpha).
    """
    width, height = camera.framebuffer_size
    framebuffer = zeros((width, height, 4)) # RGBA
    
    # Pre-compute world-to-camera and camera-to-world matrices if needed
    # wto = world_to_object(camera.transform)
    # otw = object_to_world(camera.transform)
    
    for y in range(height):
        for x in range(width):
            # 1. Ray Initialization
            # Normalize screen coordinates to [-0.5, 0.5]
            nx = (x + 0.5) / width - 0.5
            ny = (y + 0.5) / height - 0.5
            
            # Construct ray direction in camera space, then transform to world space
            # Assuming camera vectors are already in world space or transformed appropriately
            ray_dir_cam = camera.forward + nx * camera.horizontal + ny * camera.vertical
            ray_dir = normalize(ray_dir_cam)
            ray_org = camera.position # Transformed to world space if necessary
            
            # 2. Volume Intersection
            t0, t1 = intersect_volume_bounding_box(ray_org, ray_dir, neural_volume.bbox)
            
            if t0 > t1:
                # No intersection, return background
                framebuffer[y, x] = (0.0, 0.0, 0.0, 0.0)
                continue
            
            # 3. Ray Marching
            accumulated_color = vec3(0.0)
            accumulated_alpha = 0.0
            tr = 1.0
            highest_density = 0.0
            highest_org = ray_org
            highest_color = vec3(0.0)
            
            # Determine step size based on sampling_rate
            # Note: The exact iteration logic depends on the specific iterator implementation
            # Here we simulate a loop over intervals [t.x, t.y]
            t_current = t0
            step_size = (t1 - t0) * params['sampling_rate'] # Simplified step logic
            
            while t_current < t1 and accumulated_alpha < 0.999: # nearly_one
                t_next = min(t_current + step_size, t1)
                
                # Jittered interpolation
                jitter = random_float(0.0, 1.0)
                p = lerp(ray_org, ray_org + ray_dir * t_next, jitter) # Approximation of lerp(jitter, t.x, t.y)
                # More accurately: p = ray_org + (t_current + jitter * (t_next - t_current)) * ray_dir
                p = ray_org + (t_current + jitter * (t_next - t_current)) * ray_dir
                
                # Neural Inference
                value = neural_volume.sample(p)
                value *= params['density_scale'] # Apply density scale
                
                # Transfer Function
                sample_color, sample_alpha = transfer_function.apply(value)
                
                # Opacity correction for step size
                # sample_alpha *= (t_next - t_current) # Depending on TF definition
                
                # Shading
                if params['mode'] == 'GRADIENT_SHADING':
                    # Numerical Gradient
                    grad_step = params['grad_step']
                    eps = vec3(grad_step, 0, 0)
                    grad = vec3(
                        neural_volume.sample(p + eps) - neural_volume.sample(p - eps),
                        neural_volume.sample(p + vec3(0, grad_step, 0)) - neural_volume.sample(p - vec3(0, grad_step, 0)),
                        neural_volume.sample(p + vec3(0, 0, grad_step)) - neural_volume.sample(p - vec3(0, 0, grad_step))
                    )
                    grad = -grad # Negate for shading
                    
                    # Transform to world space
                    Nw = transform_normal(otw, grad)
                    Rw = transform_vector(otw, ray_dir) # Ray direction in world space
                    
                    # Shade
                    shaded_color = shade_scivis_light(Nw, Rw, params)
                    
                    # Interpolate
                    sample_color = lerp(params['scivis_shading_scale'], sample_color, shaded_color)
                    
                elif params['mode'] == 'SINGLE_SHADE_HEURISTIC':
                    if value > highest_density:
                        highest_density = value
                        highest_org = p
                        highest_color = sample_color
                
                # Composite
                accumulated_color += tr * sample_color * sample_alpha
                accumulated_alpha += tr * sample_alpha
                tr *= (1.0 - sample_alpha)
                
                t_current = t_next
            
            # 4. Single Shade Heuristic Post-Processing
            if params['mode'] == 'SINGLE_SHADE_HEURISTIC' and highest_density > 0.0:
                # Secondary ray march to light
                transmittance = compute_transmittance_to_light(highest_org, ray_dir, neural_volume, params)
                final_shaded_color = highest_color * transmittance
                
                accumulated_color = lerp(params['scivis_shading_scale'], accumulated_color, final_shaded_color * accumulated_alpha)
            
            framebuffer[y, x] = (accumulated_color.x, accumulated_color.y, accumulated_color.z, accumulated_alpha)
            
    return framebuffer
```

## Operating characteristics
-   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is the number of samples per ray. Each sample requires a neural network inference, which is significantly more expensive than a texture lookup.
-   **Memory Complexity:** Depends on the neural network size. `TcnnDeviceVolume` and `FvsrnDeviceVolume` store the MLP weights in GPU memory.
-   **Measured Performance:** Performance is heavily dependent on the MLP width and the hardware's FP32/FP16 throughput. Standard widths (16, 32, 64) are optimized. fV-SRN supports widths up to $16 \times 8$.
-   **Strengths:** High-quality rendering with continuous representations; supports complex shading (gradient, single-shade) directly in the shader; no need for pre-computed 3D textures.
-   **Limitations:** Computationally expensive due to per-sample neural inference; limited by MLP capacity for high-frequency details; requires specific network widths (16, 32, 64 or multiples of 16 for fV-SRN) [S1, unofficial].
-   **When to Use:** When high-quality, continuous volume rendering is required and computational resources allow for per-pixel neural inference. Suitable for scientific visualization and high-fidelity rendering.
-   **When Not to Use:** When real-time performance is critical and the scene is simple enough for texture-based rendering; when memory is constrained and the MLP is large.

## Background
In-Shader Neural Volume Ray Marching is part of the **instantvnr** (Instant Neural Volume Rendering) framework developed by **Qi Wu** and the **VIDILabs** team [S1, unofficial]. The framework provides a CUDA-based implementation for training and rendering neural volumes. It supports both standard MLPs (via tiny-cuda-nn) and fV-SRN networks. The method was designed to enable fast, high-quality volume rendering by integrating the neural network directly into the rendering pipeline, avoiding the overhead of decoding the volume into a 3D texture [S1, unofficial].
