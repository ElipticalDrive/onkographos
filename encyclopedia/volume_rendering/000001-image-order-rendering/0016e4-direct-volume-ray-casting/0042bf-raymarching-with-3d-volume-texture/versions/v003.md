# Raymarching with 3D Volume Texture

Also called: 3D Texture Raycasting, 3D texture raymarching, Ray tracing through 3D mesh, RayMarchedAtlasVolume, Wolfenstein-style 3D raycasting

## Overview
This method replaces 2D texture atlases with a single 3D volume texture (`sampler3D`) for raymarching, allowing larger XYZ volumes and sharing memory representation with pathtrace/isosurface modes [S2, unofficial]. It simplifies edge handling and reduces the complexity of GPU fusion required by atlas-based approaches [S2, unofficial]. It builds on [Direct volume ray casting](19-direct-volume-ray-casting.md) by moving the volume data representation directly into a 3D texture sampler [G].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A 3D volume texture (`volumeTexture`), a combined 256×4 LUT texture (`gLutTexture`), ray origin (`ray_origin`), ray direction (`eye_d`), camera near/far parameters (`tnear`, `tfar`), volume scaling factors (`volumeScale`), and step control parameters (`BREAK_STEPS`, `maxSteps`, `SLICES`, `gNChannels`, `maskAlpha`) [S2, unofficial].
*   **Outputs:** Final pixel color and accumulated opacity [S2, unofficial].

**Data Structures:**
*   `volumeTexture`: A 3D `Data3DTexture` (WebGL2) holding volume data with 8-bit precision [S2, unofficial].
*   `gLutTexture`: A 2D `DataTexture` of size 256×4, storing combined color/alpha lookup tables for up to 4 active channels [S2, unofficial].
*   **CPU Data Buffer Layout:** The data is packed in CPU memory as `data[i + ix * 4 + iy * 4 * sx + iz * 4 * sx * sy]`, where `i` is the channel index (0–3), `ix, iy, iz` are coordinates, and `sx, sy` are width/height [S2, unofficial].

**Parameters:**
*   `BREAK_STEPS`: Base number of steps (float/int) [S2, unofficial].
*   `volumeScale`: Scaling factor for volume dimensions (vec3) [S2, unofficial].
*   `gNChannels`: Number of active channels (int, up to 4) [S2, unofficial].
*   `SLICES`: Constant float indicating volume depth (used for dithering logic) [S2, unofficial].
*   `maskAlpha`: Uniform float for mask transparency (currently unused in shader but set in CPU code) [S2, unofficial].
*   `maxSteps`: Upper bound for step count [G].

**Steps:**
1.  **Calculate Scaled Steps:** Compute the number of steps based on ray length and volume scale:
    $$ \text{scaledSteps} = \text{BREAK\_STEPS} \times \text{length}\left(\frac{\mathbf{eye\_d.xyz}}{\text{volumeScale}}\right) $$
    Clamp to range $[1.0, \text{maxSteps}]$:
    $$ \text{csteps} = \text{clamp}(\text{scaledSteps}, 1.0, \text{maxSteps}) $$
    [S2, unofficial]

2.  **Calculate Inverse Step Size:**
    $$ \text{invstep} = \frac{t_{far} - t_{near}}{\text{csteps}} $$
    [S2, unofficial]

3.  **Compute Ray Dither:** Generate a random offset to reduce aliasing [S2, unofficial]. The original implementation disabled dithering for single-slice volumes ($SLICES == 1.0$) to avoid Moiré patterns, but the new implementation unconditionally applies dithering [S2, unofficial].
    $$ r = \text{rand}(\mathbf{eye\_d.xy}) $$
    [S2, unofficial]

4.  **Sample Volume Texture:** Sample the `volumeTexture` at the current ray position using `sampler3D` [S2, unofficial].

5.  **Reconstruct Color/Alpha:** Use the sampled intensity and the `gLutTexture` (256×4 combined LUT) to reconstruct color and alpha values [S2, unofficial].

**Pseudocode:**
```python
def raymarch_3d_texture(ray_origin, eye_d, tnear, tfar, volumeScale, BREAK_STEPS, maxSteps, SLICES, gNChannels, volumeTexture, gLutTexture):
    # 1. Calculate steps
    scaled_steps = BREAK_STEPS * length(eye_d.xyz / volumeScale)
    csteps = clamp(scaled_steps, 1.0, float(maxSteps))
    
    # 2. Inverse step size
    invstep = (tfar - tnear) / csteps
    
    # 3. Ray dither
    # Original code disabled dithering for single-slice volumes (SLICES == 1.0) to avoid Moiré patterns.
    # New implementation unconditionally applies dithering.
    r = hash_rand(eye_d.xy)
    
    # 4. Ray traversal and sampling
    t = tnear + r * invstep
    acc_color = vec3(0.0)
    acc_alpha = 0.0
    
    for i in range(int(csteps)):
        if acc_alpha >= 1.0:
            break
            
        # Sample position
        pos = ray_origin + t * eye_d
        
        # Sample volume texture
        intensity = texture(volumeTexture, pos).r
        
        # Reconstruct color/alpha using LUT
        lut_uv = vec2(intensity / 255.0, float(gNChannels) / 4.0)
        color_alpha = texture(gLutTexture, lut_uv)
        C_i = color_alpha.rgb
        alpha_i = color_alpha.a
        
        # Compositing (Front-to-Back)
        T = 1.0 - acc_alpha
        acc_color += T * alpha_i * C_i
        acc_alpha += T * alpha_i
        
        t += invstep
        
    return acc_color, acc_alpha

def hash_rand(v):
    # Deterministic hash for GLSL/Python compatibility [G]
    h = (v.x * 374761393.0 + v.y * 668265263.0)
    return (int(h * 12345.6789) & 0x7fffffff) / 2147483647.0
```

**Edge Cases and Pitfalls:**
*   **WebGL1 Compatibility:** The method requires WebGL2 (`Data3DTexture`/`sampler3D`). It fails on WebGL1 fallback paths [S2, unofficial].
*   **Single-Slice Moiré:** Random ray dithering causes Moiré patterns in single-slice volumes [S2, unofficial]. The original code disabled dithering for `SLICES==1.0`, but the new code unconditionally applies dithering, reintroducing the artifact [S2, unofficial].
*   **Masking Semantics:** Masking is applied by scaling per-voxel intensity before LUT lookup, affecting alpha/color, not just RGB [S2, unofficial]. It is applied up to 4 times (once per channel) [S2, unofficial].
*   **Performance:** `VolumeDataUpdater` traverses the full 3D volume twice per active channel when masking is enabled (once for intensity, once for mask) [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Renders 128×128×128 or 256×256×256 voxels in 12.4ms [S1, unofficial].
*   **Strengths:** Allows larger XYZ volumes, simpler edge handling, and shares memory representation with pathtrace/isosurface modes [S2, unofficial].
*   **Limitations:** Requires WebGL2, limited to 4 channels, and cannot "pre-fuse" with GPU as there are no writes to 3D textures [S2, unofficial]. Turning channels on/off requires rebuilding the 3D texture [S2, unofficial].
*   **When to use:** Preferred when memory sharing with pathtrace/isosurface modes is desired, or when volume dimensions exceed 2D atlas limits [S2, unofficial].
*   **When not to use:** Avoid on WebGL1-only hardware, or when single-slice rendering without Moiré artifacts is required without restoring the dithering guard [S2, unofficial].

## Background
This method was introduced by toloudis in Pull Request #370 for AllenCell/vole-core, dated Jan 30, 2026 [S2, unofficial]. It was developed to replace the texture atlas approach with a 3D volume texture to simplify representation and enable larger volumes [S2, unofficial]. It avoids the overhead of many draw calls and VBO management by using a single draw call and GPU-based raycasting, unlike meshing methods which require building and uploading geometry [S1, unofficial].
