# Raymarching with 3D Volume Texture

Also called: 3D texture raymarching, RayMarchedAtlasVolume

## Overview
This method replaces 2D texture atlases with a single 3D volume texture (`sampler3D`) for raymarching, allowing larger XYZ volumes and sharing memory representation with pathtrace/isosurface modes [S1, unofficial]. It simplifies edge handling and reduces the complexity of GPU fusion required by atlas-based approaches [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A 3D volume texture (`volumeTexture`), a combined 256x4 LUT texture (`gLutTexture`), ray origin/direction, camera parameters, and volume scaling factors.
*   **Outputs:** Final pixel color and opacity.

**Data Structures:**
*   `volumeTexture`: A 3D `Data3DTexture` (WebGL2) holding volume data with 8-bit precision [S1, unofficial].
*   `gLutTexture`: A 2D `DataTexture` of size 256x4, storing combined color/alpha lookup tables for up to 4 active channels [S1, unofficial].
*   **CPU Data Buffer Layout:** The data is packed in CPU memory as `data[i + ix * 4 + iy * 4 * sx + iz * 4 * sx * sy]`, where `i` is the channel index (0-3), `ix, iy, iz` are coordinates, and `sx, sy` are width/height [S1, unofficial].

**Parameters:**
*   `BREAK_STEPS`: Base number of steps (float/int) [S1, unofficial].
*   `volumeScale`: Scaling factor for volume dimensions (vec3) [S1, unofficial].
*   `gNChannels`: Number of active channels (int, up to 4) [S1, unofficial].
*   `SLICES`: Constant float indicating volume depth (used for dithering logic) [S1, unofficial].
*   `maskAlpha`: Uniform float for mask transparency (currently unused in shader but set in CPU code) [S1, unofficial].

**Steps:**
1.  **Calculate Scaled Steps:** Compute the number of steps based on ray length and volume scale:
    $$ \text{scaledSteps} = \text{BREAK\_STEPS} \times \text{length}\left(\frac{\mathbf{eye\_d.xyz}}{\text{volumeScale}}\right) $$
    Clamp to range $[1.0, \text{maxSteps}]$:
    $$ \text{csteps} = \text{clamp}(\text{scaledSteps}, 1.0, \text{maxSteps}) $$
    [S1, unofficial]

2.  **Calculate Inverse Step Size:**
    $$ \text{invstep} = \frac{t_{far} - t_{near}}{\text{csteps}} $$
    [S1, unofficial]

3.  **Compute Ray Dither:** Generate a random offset to reduce aliasing. Note: The original implementation disabled dithering for single-slice volumes ($SLICES == 1.0$) to avoid Moiré patterns, but the new implementation unconditionally applies dithering [S1, unofficial].
    $$ r = \text{rand}(\mathbf{eye\_d.xy}) $$
    [S1, unofficial]

4.  **Sample Volume Texture:** Sample the `volumeTexture` at the current ray position using `sampler3D` [S1, unofficial].

5.  **Reconstruct Color/Alpha:** Use the sampled intensity and the `gLutTexture` (256x4 combined LUT) to reconstruct color and alpha values [S1, unofficial].

**Pseudocode:**
```python
# Vertex/Fragment Shader Context
# Inputs: eye_d (ray direction), tfar, tnear, volumeScale, BREAK_STEPS, SLICES
# Uniforms: volumeTexture (sampler3D), gLutTexture (sampler2D), gNChannels (int)

def raymarch_3d_texture(eye_d, tfar, tnear, volumeScale, BREAK_STEPS, SLICES):
    # 1. Calculate steps
    scaled_steps = BREAK_STEPS * length(eye_d.xyz / volumeScale)
    csteps = clamp(scaled_steps, 1.0, maxSteps) # maxSteps is implementation-specific
    
    # 2. Inverse step size
    invstep = (tfar - tnear) / csteps
    
    # 3. Ray dither
    # Note: Original code had special case for SLICES==1.0 to set r=0.0
    # New code unconditionally uses rand
    r = rand(eye_d.xy)
    
    # 4. Ray traversal and sampling
    t = tnear + r * invstep
    acc_color = vec3(0.0)
    acc_alpha = 0.0
    
    for i in range(int(csteps)):
        if acc_alpha >= 1.0:
            break # Early ray termination
            
        # Sample position
        pos = origin + t * eye_d
        
        # Sample volume texture
        intensity = texture(volumeTexture, pos).r # Assuming single channel intensity or specific channel access
        
        # Reconstruct color/alpha using LUT
        # gLutTexture is 256x4, indexed by intensity and channel
        color_alpha = texture(gLutTexture, vec2(intensity * 255.0, float(gNChannels)))
        C_i = color_alpha.rgb
        alpha_i = color_alpha.a
        
        # Compositing (Front-to-Back)
        # Transmittance T = 1 - acc_alpha
        T = 1.0 - acc_alpha
        acc_color += T * alpha_i * C_i
        acc_alpha += T * alpha_i
        
        t += invstep
        
    return acc_color, acc_alpha
```

**Edge Cases and Pitfalls:**
*   **WebGL1 Compatibility:** The method requires WebGL2 (`Data3DTexture`/`sampler3D`). It fails on WebGL1 fallback paths [S1, unofficial].
*   **Single-Slice Moiré:** Random ray dithering causes Moiré patterns in single-slice volumes. The original code disabled dithering for `SLICES==1.0`, but the new code may have removed this check, reintroducing the artifact [S1, unofficial].
*   **Masking Semantics:** Masking is applied by scaling per-voxel intensity before LUT lookup, affecting alpha/color, not just RGB. It is applied up to 4 times (once per channel) [S1, unofficial].
*   **Performance:** `VolumeDataUpdater` traverses the full 3D volume twice per active channel when masking is enabled (once for intensity, once for mask) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of steps ($N$) and volume dimensions for data upload.
*   **Memory Complexity:** Proportional to the volume size ($W \times H \times D$) with 8-bit precision per channel [S1, unofficial].
*   **Strengths:** Allows larger XYZ volumes, simpler edge handling, and shares memory representation with pathtrace/isosurface modes [S1, unofficial].
*   **Limitations:** Requires WebGL2, limited to 4 channels, and cannot "pre-fuse" with GPU as there are no writes to 3D textures [S1, unofficial]. Turning channels on/off requires rebuilding the 3D texture [S1, unofficial].
