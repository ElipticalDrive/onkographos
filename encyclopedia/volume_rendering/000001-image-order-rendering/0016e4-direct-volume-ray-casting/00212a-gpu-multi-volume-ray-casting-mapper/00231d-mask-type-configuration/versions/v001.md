# Mask Type Configuration

Also called: Mask Type Selection, SetMaskTypeToBinary, SetMaskTypeToLabelMap

## Overview
Mask Type Configuration selects the interpretation of the mask volume used by the [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) to determine which voxels participate in ray casting. It distinguishes between binary masks, where any non-zero value indicates inclusion, and label maps, where specific integer values correspond to specific regions or objects. This configuration is critical when using [Label Map Masking for Volume Rendering](4788-label-map-masking-for-volume-rendering.md) or when rendering multiple volumes with distinct masking strategies.

## How it works
The method configures the internal `MaskType` member variable of the `vtkGPUMultiVolumeRayCastMapper` instance. The mapper uses this flag to determine how to evaluate the mask data (`TransformedInput`) during the ray casting loop.

**Inputs:**
- `MaskType`: An integer enum value representing the mask interpretation.

**Outputs:**
- Updated internal state of the mapper affecting subsequent `Render()` calls.

**Data Structures:**
The `vtkGPUMultiVolumeRayCastMapper` class contains the following relevant fields (as per source code [S1, S2, unofficial]):
- `int MaskType`: Stores the current mask type configuration.
- `vtkImageData* TransformedInput`: The mask volume data, transformed to the mapper's coordinate space.

**Enum Values:**
The source code references two specific enum values for `MaskType`:
1. `vtkGPUMultiVolumeRayCastMapper::BinaryMaskType`
2. `vtkGPUMultiVolumeRayCastMapper::LabelMapMaskType`

**Steps:**
1. Identify the target `vtkGPUMultiVolumeRayCastMapper` instance.
2. Assign the desired mask type to the `MaskType` member variable.
   - For binary masking: `this->MaskType = vtkGPUMultiVolumeRayCastMapper::BinaryMaskType;`
   - For label map masking: `this->MaskType = vtkGPUMultiVolumeRayCastMapper::LabelMapMaskType;`
3. Ensure the mask volume is set via `SetTransformedInput()` before rendering. The mapper will use the configured `MaskType` to interpret the values in `TransformedInput` during the ray casting process.

    """

**Edge Cases and Pitfalls:**
- **Mask Data Mismatch:** If `LabelMapMaskType` is selected but the mask volume contains floating-point values or non-integer labels, the behavior may be undefined or incorrect. Label maps typically require integer data types.
- **Uninitialized Mask:** If `MaskType` is set but no mask volume is provided via `SetTransformedInput()`, the ray casting may proceed without masking or fail depending on the implementation's null checks.
- **State Persistence:** The `MaskType` setting persists across render calls. Changing it requires explicit reassignment.

## Operating characteristics
- **Time Complexity:** O(1) for configuration. The actual masking cost is incurred during ray casting and depends on the mask volume size and resolution.
- **Memory Complexity:** O(1) additional memory for the configuration flag. The mask volume itself consumes memory proportional to its voxel count.
- **Strengths:** Simple API for switching between binary and label-based masking.
- **Limitations:** Limited to the two mask types defined in the VTK class. No support for custom mask functions or multi-label blending beyond the label map interpretation.

## Background
This configuration method is part of the VTK (Visualization Toolkit) library's GPU-accelerated volume rendering pipeline. It was introduced as part of the `vtkGPUMultiVolumeRayCastMapper` class, which supports advanced features like multiple volumes and adaptive sampling. The method allows users to choose between simple binary inclusion/exclusion and more complex label-based region selection.
