# GPU Multi-Volume Ray Casting Mapper

Also called: vtkGPUMultiVolumeRayCastMapper, GPU Multi Volume Ray Cast Mapper, Multi-volume ray casting

## Overview
The GPU Multi-Volume Ray Casting Mapper is a hardware-accelerated direct volume rendering technique that renders multiple 3D scalar fields simultaneously by compositing them along a single ray [S1, S2, unofficial]. It extends the single-volume `vtkGPUVolumeRayCastMapper` to accept multiple `vtkImageData` datasets and `vtkVolumeProperty` objects, using GPU fragment shaders for ray traversal and front-to-back alpha blending [S1, S2, unofficial]. It sets itself apart from its siblings by explicitly managing coordinate transformations between multiple volume textures and supporting features like masking, adaptive sampling, and clipping/cropping planes for each volume within a single render pass [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Two or more `vtkImageData` datasets (scalar fields) and corresponding `vtkVolumeProperty` objects (transfer functions). The primary input is at port 0; additional inputs are at ports 1 to $N$. A mask input (`vtkImageData`) is optional [S1, S2, unofficial].
*   **Outputs:** A 2D color buffer (framebuffer) containing the composited volume image [S1, S2, unofficial].

**Data Structures:**
*   **Transforms:** `AdditionalInputUserTransform[N]` stores user-defined `vtkTransform` objects for aligning additional volumes to the first volume's coordinate space [S1, unofficial].
*   **Uniforms (GPU Shader):**
    *   `sampler3D dataSetTexture[MAX_NUMBER_OF_VOLUMES]`: 3D textures for scalar data.
    *   `sampler1D opacityTexture[MAX_NUMBER_OF_VOLUMES]`: 1D textures for opacity transfer functions.
    *   `mat4 P1toPN[MAX_NUMBER_OF_VOLUMES-1]`: Transformation matrices converting texture coordinates from Volume 1 to Volume $N$ [S1, unofficial].
    *   `vec3 lowBounds[MAX_NUMBER_OF_VOLUMES]`, `vec3 highBounds[MAX_NUMBER_OF_VOLUMES]`: Bounding box limits for each volume [S1, unofficial].
    *   `vec3 ClippingplanesNormal[MAX_NUMBER_OF_VOLUMES]`, `vec3 ClippingplanesOrigins[MAX_NUMBER_OF_VOLUMES]`: Clipping plane definitions [S1, unofficial].
    *   `int clipped[MAX_NUMBER_OF_VOLUMES]`: Flags indicating if clipping is active [S1, unofficial].
    *   `int Number_Of_Volumes`: Count of active volumes [S1, unofficial].
*   **Memory Management:** `MaxMemoryInBytes` (default 128 MB if GPU info unavailable) and `MaxMemoryFraction` (default 0.75) control GPU texture allocation [S2, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    *   Probe GPU info to determine `MaxMemoryInBytes`. If dedicated video memory is 0, use dedicated system memory. If both are 0, default to 128 MB [S2, unofficial].
    *   Initialize `ClippedCroppingRegionPlanes` with `VTK_DOUBLE_MAX` for mins and `VTK_DOUBLE_MIN` for maxs [S2, unofficial].
    *   Set up input ports: `SetNumberOfInputPorts(NUMBER_OF_ADDITIONAL_VOLUMES + 1)` [S1, unofficial].

2.  **Input Validation and Preparation:**
    *   Check for null renderer or volume. If `Cropping` is true, verify that `CroppingRegionPlanes[0] < Planes[1]`, `Planes[2] < Planes[3]`, and `Planes[4] < Planes[5]`. If invalid, set `goodSoFar = 0` and fail silently [S2, unofficial].
    *   If `AutoAdjustSampleDistances` is enabled, adjust `ImageSampleDistance` based on allocated render time [S2, unofficial].
    *   Check if inputs have changed (`LastInput` vs `Input`). If so, create shallow copies into `TransformedInput` and `TransformedInput2` [S2, unofficial].
    *   **Extent Adjustment Workaround:** GPU ray casting requires extents starting from zero. For each input, adjust the origin by adding `extents[2*cc] * spacing[cc]` and shift extents by subtracting `extents[2*cc]` from both min and max for each axis `cc` [S2, unofficial].

3.  **Transform Setup:**
    *   For each additional volume $N$ (from 1 to $NUMBER_OF_ADDITIONAL\_VOLUMES-1$), compute the transformation matrix $P1toPN[N-1]$ [S1, unofficial]:
        $$ P1toPN[N-1] = T_{world \to tex, N} \times T_{world \to tex, 1}^{-1} \times T_{user, N} $$
        where $T_{world \to tex}$ is the world-to-texture coordinate transform, and $T_{user, N}$ is the user-defined transform from `AdditionalInputUserTransform[N]` [S1, unofficial].

4.  **Clipping/Cropping Setup:**
    *   Convert clipping and cropping planes from world coordinates to texture coordinates just before rendering [S1, unofficial].
    *   Compute `ClippedCroppingRegionPlanes` by intersecting user-defined cropping planes with the volume bounds [S1, unofficial].

5.  **Shader Compilation and Uniform Upload:**
    *   Load GLSL shaders (`vtkGPUVolumeRayCastMapper_CompositeFS`, `vtkGPUVolumeRayCastMapper_ShadeFS`) [S1, unofficial].
    *   Upload `P1toPN`, bounds, clipping planes, and texture handles to GPU uniforms [S1, unofficial].

6.  **Ray Casting Loop (Fragment Shader `trace()`):**
    *   **Initialization:** Set `pos` (entry position in Volume 1 texture space), `rayDir` (incremental vector in texture space), `tMax` (max ray length), `destColor` (initial color via `initialColor()`), and `remainOpacity = 1.0 - destColor.a` [S1, unofficial].
    *   **Loop:** While `inside` is true:
        *   `inside` is true if `t < tMax`, `remainOpacity >= 0.0039` (1/255), and `pos` is within `lowBounds[0]` and `highBounds[0]` [S1, unofficial].
        *   Compute transformed positions for additional volumes: `posX[iii] = vec3(P1toPN[iii] * vec4(pos, 1))` for `iii` from 0 to `Number_Of_Volumes-2` [S1, unofficial].
        *   **Sampling:**
            *   For Volume 0: If `pos` is within bounds and not clipped, sample `value[0] = texture3D(dataSetTexture[0], pos)`, compute `scalar[0] = scalarFromValue(value[0])`, and sample `opacity[0] = texture1D(opacityTexture[0], scalar[0])` [S1, unofficial].
            *   For Volumes $1$ to $N-1$: If `posX[xx-1]` is within bounds and not clipped, sample `value[xx] = texture3D(dataSetTexture[xx], posX[xx-1])`, compute `scalar[xx] = scalarFromValue(value[xx])`, and sample `opacity[xx] = texture1D(opacityTexture[xx], scalar[xx])` [S1, unofficial].
        *   **Compositing:** For each volume `vol` with `opacity[vol].a > 0`:
            *   Compute color: `color[vol] = shade(vol, value[vol]) * opacity[vol].a` [S1, unofficial].
            *   Update `destColor`: `destColor = destColor + color[vol] * remainOpacity` [S1, unofficial].
            *   Update `remainOpacity`: `remainOpacity = remainOpacity * (1.0 - opacity[vol].a)` [S1, unofficial].
        *   **Advance Ray:** `pos = pos + rayDir`, `t += 1.0` [S1, unofficial].
    *   **Output:** `gl_FragColor = destColor`, `gl_FragColor.a = 1.0 - remainOpacity` [S1, unofficial].

7.  **Masking (Optional):**
    *   If a mask input is provided, blend the standard color transfer function with the mask-specific color transfer function using `MaskBlendFactor` [S1, unofficial].
    *   For Label Map masks, label 0 uses component 0's CT; labels 1 and 2 use component 1/2's CT blended with component 0's CT [S1, unofficial].

**Pseudocode:**

```python
def gpu_multi_volume_ray_cast(input_volumes, properties, mask=None):
    # 1. Initialization
    max_memory = probe_gpu_memory() or 128 * 1024 * 1024
    num_volumes = len(input_volumes)
    
    # 2. Input Validation
    if not all(v is not None for v in input_volumes):
        raise ValueError("All volume inputs must be non-null")
    
    # 3. Transform Setup
    # Compute P1toPN matrices for each additional volume
    P1toPN = []
    for i in range(1, num_volumes):
        T_world_to_tex_i = compute_world_to_texture_transform(input_volumes[i])
        T_world_to_tex_0 = compute_world_to_texture_transform(input_volumes[0])
        T_user_i = get_additional_input_user_transform(i)
        P1toPN.append(T_world_to_tex_i @ T_world_to_tex_0.inverse() @ T_user_i)
    
    # 4. Clipping/Cropping Setup
    clipping_planes = convert_to_texture_space(clipping_planes_world, input_volumes[0])
    
    # 5. Shader Setup
    shader = load_glsl_shader("CompositeFS", "ShadeFS")
    shader.set_uniform("P1toPN", P1toPN)
    shader.set_uniform("dataSetTexture", [v.texture for v in input_volumes])
    shader.set_uniform("opacityTexture", [p.opacity_texture for p in properties])
    shader.set_uniform("lowBounds", [v.bounds.min for v in input_volumes])
    shader.set_uniform("highBounds", [v.bounds.max for v in input_volumes])
    shader.set_uniform("clipping_planes", clipping_planes)
    
    # 6. Ray Casting Loop (Executed per pixel on GPU)
    def trace_pixel(pixel_pos, ray_dir):
        pos = pixel_pos
        remain_opacity = 1.0
        dest_color = vec3(0.0)
        t = 0.0
        t_max = compute_max_ray_length(ray_dir)
        
        while t < t_max and remain_opacity > 0.0039:
            # Check bounds for Volume 0
            if not is_inside(pos, input_volumes[0].bounds):
                break
            
            # Compute positions for other volumes
            pos_x = [P1toPN[i] @ vec4(pos, 1.0) for i in range(len(P1toPN))]
            
            # Sample and Composite
            for vol_idx in range(num_volumes):
                sample_pos = pos if vol_idx == 0 else pos_x[vol_idx - 1]
                
                # Check clipping
                if is_clipped(sample_pos, clipping_planes[vol_idx]):
                    continue
                
                # Sample scalar and opacity
                value = texture3D(input_volumes[vol_idx].texture, sample_pos)
                scalar = scalar_from_value(value)
                opacity = texture1D(properties[vol_idx].opacity_texture, scalar).a
                
                if opacity > 0.0:
                    color = shade(vol_idx, value) * opacity
                    dest_color += color * remain_opacity
                    remain_opacity *= (1.0 - opacity)
            
            # Advance ray
            pos += ray_dir
            t += 1.0
            
        return dest_color, 1.0 - remain_opacity

    # 7. Masking (if applicable)
    if mask:
        # Blend standard and mask CTs using MaskBlendFactor
        pass

    return render_to_framebuffer(trace_pixel)
```

## Subtopics

### [OpenGL GPU Multi Volume Ray Cast Mapper](2919-opengl-gpu-multi-volume-ray-cast-mapper.md)
An OpenGL-specific subclass that handles hardware extension checks, OpenGL object lifecycle management, and clipping/cropping plane setup for GPU-accelerated volume rendering. It serves as the concrete implementation responsible for drawing the volume ray cast image to the screen by managing fragment shader programs, framebuffer objects, and texture uploads required for rendering multiple volumes simultaneously. It builds on [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) by providing the specific OpenGL API bindings and state management necessary for hardware-accelerated ray casting.

### [GPU Volume Ray Casting (VTK Composite Blend)](6912-gpu-volume-ray-casting-vtk-composite-blend.md)
A hardware-accelerated direct volume rendering technique that visualizes 3D scalar fields by accumulating color and opacity along rays cast through the volume. It sets itself apart from sibling mappers by explicitly using the `Composite` blend mode within VTK's `vtkGPUVolumeRayCastMapper`, which performs standard front-to-back alpha blending to integrate voxel contributions into the final pixel color. Unlike surface-based approaches, it renders the entire volume data directly without intermediate mesh extraction.

### [vtkSlicerGPURayCastVolumeMapper](7450-vtkslicergpuraycastvolumemapper.md)
Renders a volume using ray casting on a 3D texture. It builds on [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) to provide a specific implementation for the 3D Slicer environment, supporting adaptive sampling, masking, and AMR modes via the parent's pipeline hooks. It is distinguished from its siblings by its specific integration with CTK transfer functions and its handling of specific OpenGL uniform layouts for ray casting parameters.

### Mask Type Configuration
Methods to set the mask type for volume rendering, either Binary or LabelMap [S2, unofficial]. To set binary mask: assign `this->MaskType = vtkGPUMultiVolumeRayCastMapper::BinaryMaskType`. To set label map mask: assign `this->MaskType = vtkGPUMultiVolumeRayCastMapper::LabelMapMaskType` [S2, unofficial].

### Label Map Masking for Volume Rendering
A masking technique that confines volume rendering to specific regions using either a binary mask or a label map. Supports blending between standard and mask-specific color transfer functions [S1, unofficial]. Binary mask processing assumes UCHAR datatype with values 255 (inside) and 0 (outside), confining rendering strictly to regions where mask value is 255 [S1, unofficial]. Label map processing assumes UCHAR datatype with exactly 3 labels (0, 1, 2). Label 0 uses component 0's CT. Label 1 uses component 1's CT blended with component 0's CT using `MaskBlendFactor`. Label 2 uses component 2's CT blended with component 0's CT using `MaskBlendFactor` [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray and the number of volumes. Adaptive sampling can reduce the number of samples based on scene complexity [S2, unofficial].
*   **Memory Complexity:** Proportional to the total size of the 3D textures for all volumes, limited by `MaxMemoryInBytes` and `MaxMemoryFraction` [S2, unofficial].
*   **Measured Performance:** Performance depends heavily on GPU hardware and the number of volumes. Rendering two volumes is supported natively; more volumes may hit hardware limits (e.g., `MAX_NUMBER_OF_ADDITIONAL_VOLUMES` is 3 on Apple, 4 on others) [S1, unofficial].
*   **Scaling:** Scales well with resolution if adaptive sampling is enabled. `ReportProgress` uses `glFinish()`, which blocks the GPU and can significantly slow down rendering of small datasets; it should be disabled for small datasets [S2, unofficial].
*   **Strengths:** Simultaneous rendering of multiple volumes, support for clipping/cropping, masking, and adaptive sampling. Uses GLSL shaders for broad hardware support [S1, unofficial].
*   **Limitations:** Limited by hardware loop limits (requires nested while loops) and maximum number of additional volumes. Cannot handle extents starting from non-zero values without workaround [S2, unofficial]. Invalid cropping planes fail silently [S2, unofficial].

## Background
The GPU Multi-Volume Ray Casting Mapper was developed as an extension of the Visualization Toolkit (VTK) to support multi-volume rendering on the GPU. It was modified by Carlos Falcón and Karl Krissian to extend the single-volume `vtkGPUVolumeRayCastMapper` to handle multiple datasets [S1, unofficial]. The project uses GLSL shaders instead of OpenCL for general GPU programming because shaders are faster and supported by more devices [S1, unofficial]. It is used in medical imaging and scientific visualization applications where multiple volumes (e.g., different tissue types or time steps) need to be visualized simultaneously [S1, S2, unofficial].
