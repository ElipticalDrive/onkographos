# GPU Multi-Volume Ray Casting Mapper

Also called: vtkGPUMultiVolumeRayCastMapper, GPU Multi Volume Ray Cast Mapper, Multi-volume ray casting

## Overview
The GPU Multi-Volume Ray Casting Mapper is a volume rendering technique that renders multiple volume datasets simultaneously by extending the single-volume `vtkGPUVolumeRayCastMapper` to accept multiple `vtkImageData` datasets and `vtkVolumeProperty` objects, using GPU shaders for ray traversal and compositing [S1, S2, unofficial]. It sets itself apart from its siblings by explicitly compositing multiple 3D scalar fields along a single ray using coordinate transformation matrices to align samples from different volumes to a common ray space [S1, S2, unofficial]. Unlike [Direct Volume Rendering](1184-direct-volume-rendering.md) which typically handles one volume per pass or requires complex blending, this method integrates multiple volumes in a single fragment shader invocation [S1, unofficial].

## How it works
The method implements the emission-absorption optical model, computing the light intensity reaching the eye by integrating radiative energy along a ray through the scalar volume [S1, S5, S9, unofficial]. The process follows a strict pipeline for each pixel: ray generation, sampling, classification (transfer function application), shading, and compositing [S4, S34, unofficial].

### Inputs and Outputs
**Inputs:**
*   Primary volume: `vtkImageData` (Input Port 0).
*   Additional volumes: Up to `MAX_NUMBER_OF_ADDITIONAL_VOLUMES` `vtkImageData` datasets (Input Ports 1 to N).
*   Properties: `vtkVolumeProperty` for the primary volume and additional properties for each additional volume via `SetAdditionalProperty`.
*   Mask (Optional): `vtkImageData` for binary or label map masking.
*   Transforms: User-defined `vtkTransform` for each additional volume relative to the primary volume.

**Outputs:**
*   Final pixel color and opacity (`gl_FragColor`) on the framebuffer.

### Data Structures
**C++ Class Members (`vtkGPUMultiVolumeRayCastMapper`):**
*   `NUMBER_OF_ADDITIONAL_VOLUMES`: Integer, typically 3 (Apple) or 4 (others) [S1, unofficial].
*   `TransformedInput`, `TransformedInput2`: Pointers to `vtkImageData` storing transformed input data [S2, unofficial].
*   `LastInput`, `LastInput2`: Pointers to `vtkImageData` used to detect data changes (MTime) [S2, unofficial].
*   `ClippedCroppingRegionPlanes[6]`: Array of doubles for X, Y, Z min/max planes [S1, S2, unofficial].
*   `MaskInput`: Pointer to `vtkImageData` [S1, unofficial].
*   `MaskBlendFactor`: Float, range [0.0, 1.0], default 1.0 [S1, S2, unofficial].
*   `MaskType`: Enum, `BinaryMaskType` or `LabelMapMaskType` [S1, S2, unofficial].

**GPU Shader Uniforms:**
*   `sampler3D dataSetTexture[MAX_NUMBER_OF_VOLUMES]`: 3D textures for volume data [S1, unofficial].
*   `sampler1D opacityTexture[MAX_NUMBER_OF_VOLUMES]`: 1D textures for opacity transfer functions [S1, unofficial].
*   `mat4 P1toPN[MAX_NUMBER_OF_VOLUMES-1]`: Transformation matrices from volume 1 texture coordinates to volume N [S1, unofficial].
*   `vec3 lowBounds[MAX_NUMBER_OF_VOLUMES]`, `highBounds[MAX_NUMBER_OF_VOLUMES]`: Bounding box limits [S1, unofficial].
*   `int Number_Of_Volumes`: Count of active volumes [S1, unofficial].
*   `vec3 ClippingplanesNormal[MAX_NUMBER_OF_VOLUMES]`, `ClippingplanesOrigins[MAX_NUMBER_OF_VOLUMES]`: Clipping plane definitions [S1, unofficial].
*   `int clipped[MAX_NUMBER_OF_VOLUMES]`: Flags indicating if clipping is active [S1, unofficial].

### Steps

1.  **Initialization and Memory Management**:
    *   Probe GPU info to determine `MaxMemoryInBytes`. If dedicated video memory is 0, use dedicated system memory. If both are 0, default to 128 MB [S2, unofficial].
    *   Set `MaxMemoryFraction` to 0.75 of `MaxMemoryInBytes` [S1, S2, unofficial].
    *   Initialize `TransformedInput` and `TransformedInput2` as shallow copies of inputs if `LastInput` or `LastInput2` differ or if MTime has changed [S2, unofficial].

2.  **Extent Adjustment Workaround**:
    *   GPU ray casting requires extents starting from zero. For each transformed input:
        *   Get extents `[minX, maxX, minY, maxY, minZ, maxZ]` and origin `[ox, oy, oz]` and spacing `[sx, sy, sz]`.
        *   Adjust origin: `new_origin = origin + vec3(extents[0]*spacing[0], extents[2]*spacing[2], extents[4]*spacing[4])` [S2, unofficial].
        *   Adjust extents: `new_extents[0] = 0`, `new_extents[1] = extents[1] - extents[0]`, etc. [S2, unofficial].
        *   Update the `vtkImageData` with new origin and extents [S2, unofficial].

3.  **Transform Setup**:
    *   For each additional volume $N$ (from 1 to `NUMBER_OF_ADDITIONAL_VOLUMES`), compute the transformation matrix $P1toPN$ [S1, unofficial]:
        $$ P1toPN = T_{world \to tex_N} \times T_{world \to tex_1}^{-1} \times T_{user} $$
        where $T_{world \to tex}$ is the world-to-texture coordinate transform, and $T_{user}$ is the user-defined transform via `SetAdditionalInputUserTransform` [S1, unofficial].
    *   Store these matrices in the `P1toPN` uniform array [S1, unofficial].

4.  **Clipping and Cropping Initialization**:
    *   Compute `ClippedCroppingRegionPlanes` by intersecting user-defined cropping planes with the volume bounds [S1, unofficial].
    *   Convert clipping planes (origin and normal) from world coordinates to texture coordinates just before rendering [S1, unofficial].
    *   Validate cropping: If `Cropping` is true and any min plane $\ge$ max plane, set render validity to false (silent failure) [S2, unofficial].

5.  **Ray Traversal and Compositing (Shader `trace()`)**:
    *   **Initialization**:
        *   Calculate initial ray position `pos` for Volume 0 in texture space.
        *   Calculate initial positions `posX[i]` for additional volumes using `P1toPN[i] * vec4(pos, 1.0)` [S1, unofficial].
        *   Initialize `destColor` (via `initialColor()`) and `remainOpacity = 1.0 - destColor.a` [S1, unofficial].
        *   Set `t = 0.0`, `tMax` (max ray length), `rayDir` (incremental vector in texture space) [S1, unofficial].
    *   **Loop**:
        *   While `inside` is true:
            *   `inside` is true if `t < tMax`, `remainOpacity >= 0.0039` (1/255), and `pos` is within `lowBounds[0]` and `highBounds[0]` [S1, unofficial].
            *   **Sample Volume 0**:
                *   If `pos` is within bounds and not clipped:
                    *   `value[0] = texture3D(dataSetTexture[0], pos)` [S1, unofficial].
                    *   `scalar[0] = scalarFromValue(value[0])` [S1, unofficial].
                    *   `opacity[0] = texture1D(opacityTexture[0], scalar[0])` [S1, unofficial].
                    *   Apply masking if `MaskInput` is set (see Subtopics) [S1, unofficial].
                    *   Compute color: `color[0] = shade(0, value[0]) * opacity[0].a` [S1, unofficial].
                    *   Composite:
                        $$ destColor = destColor + color[0] \times remainOpacity $$
                        $$ remainOpacity = remainOpacity \times (1.0 - opacity[0].a) $$
            *   **Sample Additional Volumes ($i = 1$ to $N-1$)**:
                *   If `posX[i-1]` is within bounds and not clipped:
                    *   `value[i] = texture3D(dataSetTexture[i], posX[i-1])` [S1, unofficial].
                    *   `scalar[i] = scalarFromValue(value[i])` [S1, unofficial].
                    *   `opacity[i] = texture1D(opacityTexture[i], scalar[i])` [S1, unofficial].
                    *   Apply masking if applicable [S1, unofficial].
                    *   Compute color: `color[i] = shade(i, value[i]) * opacity[i].a` [S1, unofficial].
                    *   Composite:
                        $$ destColor = destColor + color[i] \times remainOpacity $$
                        $$ remainOpacity = remainOpacity \times (1.0 - opacity[i].a) $$
            *   **Advance Ray**:
                *   `pos = pos + rayDir` [S1, unofficial].
                *   `posX[i] = posX[i] + rayDir` for all additional volumes (assuming aligned sampling steps) [S1, unofficial].
                *   `t += 1.0` [S1, unofficial].
    *   **Final Output**:
        *   `gl_FragColor = destColor` [S1, unofficial].
        *   `gl_FragColor.a = 1.0 - remainOpacity` [S1, unofficial].

### Parameters
*   `ImageSampleDistance`: Base sample distance in XY image dimensions. Default 1.0 (1 ray/pixel). Clamped [0.1, 100.0] [S2, unofficial].
*   `MinimumImageSampleDistance`: Lower bound for adaptive sampling. Default 1.0 [S2, unofficial].
*   `MaximumImageSampleDistance`: Upper bound for adaptive sampling. Default 10.0 [S2, unofficial].
*   `AutoAdjustSampleDistances`: Boolean (0/1). Enables automatic adjustment of `ImageSampleDistance` based on render time [S1, S2, unofficial].
*   `SampleDistance`: Distance between sample points along the ray. Default 1.0 [S2, unofficial].
*   `MaxMemoryInBytes`: Maximum GPU memory allocation. Defaults to hardware info or 128 MB [S2, unofficial].
*   `MaxMemoryFraction`: Fraction of `MaxMemoryInBytes` used. Default 0.75 [S1, S2, unofficial].
*   `ReportProgress`: Boolean. If true, calls `glFinish()` to report progress. Should be false for small datasets to avoid slowdown [S2, unofficial].
*   `FinalColorWindow`: Window value for final color scaling. Default 1.0 [S2, unofficial].
*   `FinalColorLevel`: Level value for final color scaling. Default 0.5 [S2, unofficial].
*   `MaskBlendFactor`: Blending weight for mask CT vs standard CT. Default 1.0 [S2, unofficial].
*   `MaskType`: `BinaryMaskType` or `LabelMapMaskType` [S2, unofficial].

### Edge Cases and Pitfalls
*   **Hardware Loop Limits**: GPU hardware may limit loop iterations. The implementation uses a nested while loop structure to handle samples and volumes safely [S1, unofficial].
*   **Non-Zero Extents**: VTK's GPU mapper cannot handle extents starting from non-zero values. The extent adjustment workaround (Step 2) is mandatory [S2, unofficial].
*   **Invalid Cropping**: If cropping planes define a region with zero or negative volume, the render fails silently (`goodSoFar=0`) without an error message [S2, unofficial].
*   **ReportProgress Overhead**: Using `glFinish()` for progress reporting blocks the GPU and significantly slows down rendering of small datasets; it should be disabled for small datasets [S2, unofficial].
*   **Negative FinalColorWindow**: Setting `FinalColorWindow` to a negative value reverses the applied color values [S2, unofficial].
*   **Component Count**: Hardware rendering is unsupported if the input data has more than one independent component (e.g., vector fields) or if required extensions are missing [S3, unofficial].

## Subtopics

### [OpenGL GPU Multi Volume Ray Cast Mapper](2919-opengl-gpu-multi-volume-ray-cast-mapper.md)
The OpenGL GPU Multi Volume Ray Cast Mapper is an OpenGL-specific subclass of the GPU Multi-Volume Ray Casting Mapper that handles hardware extension checks, OpenGL object lifecycle management, and clipping/cropping plane setup for GPU-accelerated volume rendering. It serves as the concrete implementation responsible for drawing the volume ray cast image to the screen by managing fragment shader programs, framebuffer objects, and texture uploads required for rendering multiple volumes simultaneously. It builds on [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) by providing the specific OpenGL API bindings and state management necessary for hardware-accelerated ray casting.

### [GPU Volume Ray Casting (VTK Composite Blend)](6912-gpu-volume-ray-casting-vtk-composite-blend.md)
GPU Volume Ray Casting with VTK Composite Blend is a hardware-accelerated direct volume rendering technique that visualizes 3D scalar fields by accumulating color and opacity along rays cast through the volume. It sets itself apart from sibling mappers by explicitly using the `Composite` blend mode within VTK's `vtkGPUVolumeRayCastMapper`, which performs standard front-to-back alpha blending to integrate voxel contributions into the final pixel color. Unlike surface-based approaches, it renders the entire volume data directly without intermediate mesh extraction.

### [vtkSlicerGPURayCastVolumeMapper](7450-vtkslicergpuraycastvolumemapper.md)
Renders a volume using ray casting on a 3D texture. It builds on [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) to provide a specific implementation for the 3D Slicer environment, supporting adaptive sampling, masking, and AMR modes via the parent's pipeline hooks. It is distinguished from its siblings by its specific integration with CTK transfer functions and its handling of specific OpenGL uniform layouts for ray casting parameters.

### Mask Type Configuration
Methods to set the mask type for volume rendering, either Binary or LabelMap [S2, unofficial]. To set binary mask: assign `MaskType = vtkGPUMultiVolumeRayCastMapper::BinaryMaskType`. To set label map mask: assign `MaskType = vtkGPUMultiVolumeRayCastMapper::LabelMapMaskType` [S2, unofficial].

### Label Map Masking for Volume Rendering
A masking technique that confines volume rendering to specific regions using either a binary mask or a label map. Supports blending between standard and mask-specific color transfer functions [S1, unofficial].
*   **Binary Mask Processing**: Assumes `UCHAR` datatype with values 255 (inside) and 0 (outside). Rendering is confined strictly to regions where mask value is 255 [S1, unofficial].
*   **Label Map Processing**: Assumes `UCHAR` datatype with exactly 3 labels (0, 1, 2). Label 0 uses component 0's CT. Label 1 uses component 1's CT blended with component 0's CT using `MaskBlendFactor`. Label 2 uses component 2's CT blended with component 0's CT using `MaskBlendFactor` [S1, unofficial].
*   **Parameters**: `MaskInput` (`vtkImageData*`) is the mask data source. `MaskBlendFactor` (float, range [0.0, 1.0], default 1.0) controls blending weight between standard and mask color transfer functions [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(P \cdot N \cdot S)$, where $P$ is the number of pixels, $N$ is the number of volumes, and $S$ is the number of samples per ray. Adaptive sampling reduces $S$ dynamically [S2, unofficial].
*   **Memory Complexity**: $O(V \cdot D^3)$, where $V$ is the number of volumes and $D$ is the resolution of the volume data. Limited by `MaxMemoryInBytes` [S2, unofficial].
*   **Performance**: Performance is heavily dependent on GPU memory bandwidth and shader execution units. Using shaders is faster and more widely supported than OpenCL [S1, unofficial].
*   **Strengths**: Simultaneous rendering of multiple volumes in a single pass; support for masking and clipping; adaptive sampling for performance [S1, S2, unofficial].
*   **Limitations**: Limited by hardware loop limits and memory constraints; silent failures for invalid cropping; requires extent adjustment workaround [S1, S2, unofficial].
*   **When to Use**: When multiple volumes need to be composited together with accurate depth ordering and transparency, and when hardware acceleration is available [S1, unofficial].
*   **When Not to Use**: For single volume rendering where simpler mappers suffice; for datasets with non-zero extents without preprocessing; for small datasets where `ReportProgress` overhead is detrimental [S2, unofficial].

## Background
The GPU Multi-Volume Ray Casting Mapper was developed as an extension of the Visualization Toolkit (VTK) to support multi-volume rendering on the GPU. It was modified by Carlos Falcón and Karl Krissian to add support for multiple input datasets and properties [S1, unofficial]. The project leverages GLSL shaders for GPU programming, citing speed and device support as advantages over OpenCL [S1, unofficial]. It is part of the VTK ecosystem, specifically the `vtkGPUMultiVolumeRayCastMapper` class [S1, S2, unofficial].
