# GPU Multi-Volume Ray Casting Mapper

Also called: vtkGPUMultiVolumeRayCastMapper, GPU Multi Volume Ray Cast Mapper, Multi-volume ray casting

## Overview
The GPU Multi-Volume Ray Casting Mapper is a volume rendering technique that renders multiple volume datasets simultaneously by extending the single-volume `vtkGPUVolumeRayCastMapper` to accept multiple `vtkImageData` datasets and `vtkVolumeProperty` objects, using GPU shaders for ray traversal and compositing [S1, S2, unofficial]. It sets itself apart from its siblings by explicitly supporting the simultaneous rendering of two or more input datasets (up to 4 or 5 total volumes depending on platform) within a single ray casting pass, using coordinate transformation matrices to align samples from different volumes to a common ray space [S1, S2, unofficial]. Unlike [Back-face rasterized volume rendering](1296-back-face-rasterized-volume-rendering.md) which rasterizes volume geometry, or [Hardware-Accelerated Volume Rendering via 3D Texturing](2799-hardware-accelerated-volume-rendering-via-3d-texturing.md) which typically handles single volumes, this method manages the complexity of multi-volume alignment and compositing directly in the fragment shader [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Two or more `vtkImageData` datasets (scalar fields) and corresponding `vtkVolumeProperty` objects (transfer functions). The primary input is at port 0; additional inputs are at ports 1 to $N-1$. A mask input (`vtkImageData`) is optional for region-specific rendering [S1, S2, unofficial].
- **Outputs:** A 2D image (color and opacity) representing the composite view of all volumes [S1, S2, unofficial].

**Data Structures:**
- **Class Members:**
  - `NUMBER_OF_ADDITIONAL_VOLUMES`: Integer, max 3 on Apple platforms, 4 on others [S1, S2, unofficial].
  - `Property[MAX_NUMBER_OF_ADDITIONAL_VOLUMES]`: Array of `vtkVolumeProperty*` pointers for additional volumes [S1, S2, unofficial].
  - `TransformedInput`, `TransformedInput2`: `vtkImageData*` pointers storing transformed input data for primary and secondary volumes [S2, unofficial].
  - `ClippedCroppingRegionPlanes[6]`: Array of doubles for clipping planes (X min/max, Y min/max, Z min/max) [S1, S2, unofficial].
  - `MaskInput`: `vtkImageData*` pointer for mask data [S1, S2, unofficial].
  - `MaskType`: Enum (`BinaryMaskType` or `LabelMapMaskType`) [S2, unofficial].
  - `MaskBlendFactor`: Float, clamped [0.0, 1.0], default 1.0 [S1, S2, unofficial].
- **Shader Uniforms:**
  - `sampler3D dataSetTexture[MAX_NUMBER_OF_VOLUMES]`: 3D textures for volume data [S1, S2, unofficial].
  - `sampler1D opacityTexture[MAX_NUMBER_OF_VOLUMES]`: 1D textures for opacity transfer functions [S1, S2, unofficial].
  - `mat4 P1toPN[MAX_NUMBER_OF_VOLUMES-1]`: Transformation matrices from volume 1 texture coordinates to volume N texture coordinates [S1, S2, unofficial].
  - `vec3 lowBounds[MAX_NUMBER_OF_VOLUMES]`, `vec3 highBounds[MAX_NUMBER_OF_VOLUMES]`: Bounding box info for each volume [S1, S2, unofficial].
  - `int Number_Of_Volumes`: Integer count of active volumes [S1, S2, unofficial].
  - `vec3 ClippingplanesNormal[MAX_NUMBER_OF_VOLUMES]`, `vec3 ClippingplanesOrigins[MAX_NUMBER_OF_VOLUMES]`: Clipping plane definitions [S1, S2, unofficial].
  - `int clipped[MAX_NUMBER_OF_VOLUMES]`: Flags indicating if clipping is active for each volume [S1, S2, unofficial].

**Steps:**
1. **Input Setup:** Connect multiple `vtkImageData` datasets and `vtkVolumeProperty` objects using `SetInput(int port, vtkImageData *input)` and `SetAdditionalProperty(int volNumber, vtkVolumeProperty *property)` [S1, S2, unofficial].
2. **Initialization:** Probe GPU list for dedicated video memory. If 0, use dedicated system memory. If both 0, set `MaxMemoryInBytes` to 128MB. Ignore shared system memory [S2, unofficial].
3. **Transform Setup:** For each additional volume $N$, compute a transformation matrix $P1toPN$ from the first volume's texture coordinates to the $N$th volume's texture coordinates. This matrix combines the world-to-texture-$N$ transform, the inverse world-to-texture-1 transform, and a user-defined transform (`SetAdditionalInputUserTransform`) [S1, S2, unofficial].
4. **Render Entry:** If `GeneratingCanonicalView` is true, call `CanonicalViewRender` and return. Otherwise, invoke `VolumeMapperRenderStartEvent`, start timer, validate render, call `GPURender`, stop timer, record time, and invoke `VolumeMapperRenderEndEvent` [S2, unofficial].
5. **Clipping/Cropping Init:** Initialize clipping planes (up to 6 cropping planes, 1 clipping plane) per volume. Convert these planes from world coordinates to texture coordinates just before rendering and pass them to shaders via uniform variables [S1, S2, unofficial].
6. **Validation:** Check for null renderer or volume. Check that color channels are 3 (currently commented out). Check cropping planes: if `Cropping` is true and any min plane >= max plane, set `goodSoFar` to 0 silently [S2, unofficial].
7. **Shader Initialization (Shading):** In `vtkGPUVolumeRayCastMapper_ShadeFS`, the `InitShade()` function uses `P1toPN` uniforms to compute corrected x, y, z increments for shading based on the position of each additional volume [S1, S2, unofficial].
8. **Input Validation:** Get `Input(0)` and `Input(1)`. If either is NULL, set `goodSoFar` to 0 and log error. If good, call `Update()` on both inputs [S2, unofficial].
9. **Transform/Clone Logic:** If `LastInput != input` OR `input MTime > TransformedInput MTime` OR `LastInput2 != input2` OR `input2 MTime > TransformedInput2 MTime`, then update `LastInput`/`LastInput2` and create shallow copies into `TransformedInput`/`TransformedInput2` [S2, unofficial].
10. **Extent Adjustment Workaround:** For the cloned input, get extents and origin/spacing. Adjust origin by adding `extents[2*cc]*spacing[cc]`. Adjust extents by subtracting `extents[2*cc]` from both min and max (`extents[2*cc] -= extents[2*cc]; extents[2*cc+1] -= extents[2*cc];`). Set new origin and extent. Repeat for input2 [S2, unofficial].
11. **Ray Traversal Loop:** In `vtkGPUVolumeRayCastMapper_CompositeFS`, the `trace()` function executes a while loop for ray traversal. For each step, update the ray position (`pos`) for the first volume and (`posX[]`) for additional volumes using the ray direction (`rayDir`) and `P1toPN` transforms [S1, S2, unofficial].
12. **Bounding Box Test:** Test the ray position against `lowBounds[]` and `highBounds[]` (bounding box info for each volume, modified by cropping) to check if the ray is inside the volume [S1, S2, unofficial].
13. **Clipping Test:** Test clipping flags. If the ray position is not inside the clipped part of the volume, sample the volume texture [S1, S2, unofficial].
14. **Compositing:** Apply front-to-back alpha blending to accumulate color and opacity from samples across all volumes. The formula is:
    $$
    C_{out} = C_{in} + (1 - \alpha_{in}) \times \alpha_{sample} \times C_{sample}
    $$
    $$
    \alpha_{out} = \alpha_{in} + (1 - \alpha_{in}) \times \alpha_{sample}
    $$
    [S1, S2, unofficial].
15. **Initialize:** `pos` (entry position), `rayDir` (incremental vector in texture space), `tMax` (max ray length), and `destColor` (initial color via `initialColor()`). Set `remainOpacity = 1.0 - destColor.a` [S1, S2, unofficial].
16. **Loop:** While `inside` is true: `inside` is true if `t < tMax`, `remainOpacity >= 0.0039` (1/255), and `pos` is within `lowBounds[0]` and `highBounds[0]` [S1, S2, unofficial].
17. **Transform Positions:** For each additional volume `iii` from 0 to `Number_Of_Volumes-2`, compute transformed position: `posX[iii] = vec3(P1toPN[iii]*vec4(pos,1))` [S1, S2, unofficial].
18. **Sample Volume 0:** If `pos` is within bounds and not clipped (or clipping check passes), sample `value[0] = texture3D(dataSetTexture[0], pos)`, compute `scalar[0] = scalarFromValue(value[0])`, sample `opacity[0] = texture1D(opacityTexture[0], scalar[0])` [S1, S2, unofficial].
19. **Sample Volumes 1 to N-1:** If `posX[xx-1]` is within bounds and not clipped (or clipping check passes), sample `value[xx] = texture3D(dataSetTexture[xx], posX[xx-1])`, compute `scalar[xx] = scalarFromValue(value[xx])`, sample `opacity[xx] = texture1D(opacityTexture[xx], scalar[xx])` [S1, S2, unofficial].
20. **Composite:** If `opacity[vol].a > 0.0`, compute `color[vol] = shade(vol, value[vol]) * opacity[vol].a`, update `destColor = destColor + color[vol] * remainOpacity`, and update `remainOpacity = remainOpacity * (1.0 - opacity[vol].a)` [S1, S2, unofficial].
21. **Advance Ray:** `pos = pos + rayDir`, `t += 1.0` [S1, S2, unofficial].
22. **Final Output:** `gl_FragColor = destColor`, `gl_FragColor.a = 1.0 - remainOpacity` [S1, S2, unofficial].

**Pseudocode:**
```python
def trace(pos, rayDir, tMax, P1toPN, lowBounds, highBounds, clipped, dataSetTexture, opacityTexture, Number_Of_Volumes):
    posX = [vec3(0.0) for _ in range(Number_Of_Volumes - 1)]
    for iii in range(Number_Of_Volumes - 1):
        posX[iii] = vec3(dot(P1toPN[iii], vec4(pos, 1.0)))
    
    remainOpacity = 1.0
    destColor = vec4(0.0, 0.0, 0.0, 0.0)
    t = 0.0
    
    while t < tMax and remainOpacity >= 0.0039:
        inside = True
        for vol in range(Number_Of_Volumes):
            currentPos = pos if vol == 0 else posX[vol - 1]
            if not (lowBounds[vol].x <= currentPos.x <= highBounds[vol].x and
                    lowBounds[vol].y <= currentPos.y <= highBounds[vol].y and
                    lowBounds[vol].z <= currentPos.z <= highBounds[vol].z):
                inside = False
                break
            if clipped[vol] and not is_inside_clipping_planes(currentPos, ClippingplanesNormal[vol], ClippingplanesOrigins[vol]):
                inside = False
                break
        
        if not inside:
            break
            
        for vol in range(Number_Of_Volumes):
            currentPos = pos if vol == 0 else posX[vol - 1]
            value = texture3D(dataSetTexture[vol], currentPos)
            scalar = scalarFromValue(value)
            opacity = texture1D(opacityTexture[vol], scalar).a
            
            if opacity > 0.0:
                color = shade(vol, value) * opacity
                destColor = destColor + color * remainOpacity
                remainOpacity = remainOpacity * (1.0 - opacity)
        
        pos = pos + rayDir
        t += 1.0
        for iii in range(Number_Of_Volumes - 1):
            posX[iii] = vec3(dot(P1toPN[iii], vec4(pos, 1.0)))
            
    return vec4(destColor.rgb, 1.0 - remainOpacity)
```

**Edge Cases and Pitfalls:**
- Hardware loop limits require a nested while loop structure instead of a single loop over all samples and volumes [S1, S2, unofficial].
- Non-zero extents: The GPUVolumeRayCastMapper cannot handle extents starting from non-zero values. A workaround adjusts the origin and shifts extents to start from zero [S2, unofficial].
- Hardware rendering is unsupported if the input data has more than one independent component or if the hardware lacks required extensions [S3, unofficial].
- Clipping planes are handled by computing intersection points `clipMin[i]` for each axis and ensuring the sample position is greater than `clipMin[i]` on all axes [S1, S2, unofficial].
- Invalid Cropping: If cropping planes define a region with zero or negative volume, the render fails silently (goodSoFar=0) without an error message [S2, unofficial].
- ReportProgress uses glFinish(), which blocks the GPU and can significantly slow down rendering of small datasets; it should be disabled for small datasets [S2, unofficial].
- FinalColorWindow cannot be null, but setting it to a negative value reverses the applied color values [S2, unofficial].

## Subtopics

### [OpenGL GPU Multi Volume Ray Cast Mapper](2919-opengl-gpu-multi-volume-ray-cast-mapper.md)
The OpenGL GPU Multi Volume Ray Cast Mapper is an OpenGL-specific subclass of the GPU Multi-Volume Ray Casting Mapper that handles hardware extension checks, OpenGL object lifecycle management, and clipping/cropping plane setup for GPU-accelerated volume rendering. It serves as the concrete implementation responsible for drawing the volume ray cast image to the screen by managing fragment shader programs, framebuffer objects, and texture uploads required for rendering multiple volumes simultaneously. It builds on [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) by providing the specific OpenGL API bindings and state management necessary for hardware-accelerated ray casting.

### [GPU Volume Ray Casting (VTK Composite Blend)](6912-gpu-volume-ray-casting-vtk-composite-blend.md)
GPU Volume Ray Casting (VTK Composite Blend) is a hardware-accelerated direct volume rendering technique implemented in VTK via `vtkGPUVolumeRayCastMapper` that performs ray casting on the GPU to visualize 3D scalar fields. It transforms raw volumetric data into a 3D environment by accumulating color and opacity along rays using composite blending. It sets itself apart from its siblings by explicitly utilizing the **Composite** blend mode for standard alpha blending during the ray casting process, distinguishing it from the OpenGL-specific multi-volume mapper [2919-opengl-gpu-multi-volume-ray-cast-mapper.md] and the Slicer-specific mapper [7450-vtkslicergpuraycastvolumemapper.md].

### [vtkSlicerGPURayCastVolumeMapper](7450-vtkslicergpuraycastvolumemapper.md)
Renders a volume using ray casting on a 3D texture. It builds on [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) to provide a specific implementation for the 3D Slicer environment, supporting adaptive sampling, masking, and AMR modes via the parent's pipeline hooks. It is distinguished from its siblings by its specific integration with CTK transfer functions and its handling of specific OpenGL uniform layouts for ray casting parameters.

### Mask Type Configuration
- **Definition:** Methods to set the mask type for volume rendering, either Binary or LabelMap [S2, unofficial].
- **Steps:** To set binary mask: assign `this->MaskType = vtkGPUMultiVolumeRayCastMapper::BinaryMaskType`. To set label map mask: assign `this->MaskType = vtkGPUMultiVolumeRayCastMapper::LabelMapMaskType` [S2, unofficial].

### Label Map Masking for Volume Rendering
- **Definition:** A masking technique that confines volume rendering to specific regions using either a binary mask or a label map. Supports blending between standard and mask-specific color transfer functions [S1, unofficial].
- **Steps:** Binary mask processing: Assumes UCHAR datatype with values 255 (inside) and 0 (outside). Rendering is confined strictly to regions where mask value is 255. Label map processing: Assumes UCHAR datatype with exactly 3 labels (0, 1, 2). Label 0 uses component 0's CT. Label 1 uses component 1's CT blended with component 0's CT using MaskBlendFactor. Label 2 uses component 2's CT blended with component 0's CT using MaskBlendFactor [S1, unofficial].
- **Parameters:** `MaskInput`: `vtkImageData*`, the mask data source. `MaskBlendFactor`: Float, clamped [0.0, 1.0], default 1.0. Controls blending weight between standard and mask color transfer functions. 0.0 uses only standard CT; 1.0 uses only mask CT [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of sample points along the ray and the number of volumes [S1, S2, unofficial].
- **Memory Complexity:** Linear with respect to the number of volumes and the size of the 3D textures [S1, S2, unofficial].
- **Measured Performance:** Performance depends on GPU hardware, resolution, and scene complexity. Adaptive sampling can improve performance by reducing sample distances in less complex areas [S2, unofficial].
- **Scaling:** Scales with the number of volumes, but limited by `MAX_NUMBER_OF_VOLUMES` [S1, S2, unofficial].
- **Strengths:** Supports simultaneous rendering of multiple volumes, adaptive sampling, masking, and AMR modes [S1, S2, unofficial].
- **Limitations:** Limited by hardware loop limits, requires specific GPU extensions, and may fail silently if cropping planes are invalid [S1, S2, S3, unofficial].
- **When to Use:** When multiple volumes need to be rendered simultaneously with accurate compositing and shading [S1, S2, unofficial].
- **When Not to Use:** When hardware lacks required extensions or when rendering very large datasets with many volumes may exceed memory limits [S1, S2, S3, unofficial].

## Background
The GPU Multi-Volume Ray Casting Mapper was developed by Carlos Falcón and Karl Krissian at CTIM, extending the Visualization Toolkit (VTK) to support multi-volume rendering [S1, unofficial]. It builds on the single-volume `vtkGPUVolumeRayCastMapper` and uses GLSL shaders for GPU programming, chosen for their speed and broader device support compared to OpenCL [S1, unofficial]. The method is part of the VTK volume rendering pipeline and is used in applications requiring the visualization of multiple 3D scalar fields simultaneously [S1, S2, unofficial].
