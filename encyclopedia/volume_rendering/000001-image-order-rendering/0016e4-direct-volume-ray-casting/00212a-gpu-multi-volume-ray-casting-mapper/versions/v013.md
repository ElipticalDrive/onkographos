# GPU Multi-Volume Ray Casting Mapper

Also called: vtkGPUMultiVolumeRayCastMapper, GPU Multi Volume Ray Cast Mapper, Multi-volume ray casting

## Overview
The GPU Multi-Volume Ray Casting Mapper is a hardware-accelerated direct volume rendering technique that renders multiple 3D scalar fields simultaneously along a single ray [S1, S3, unofficial]. It extends the single-volume `vtkGPUVolumeRayCastMapper` by accepting multiple `vtkImageData` datasets and `vtkVolumeProperty` objects, using GPU shaders for ray traversal and compositing [S1, unofficial]. It sets itself apart from its siblings by explicitly managing coordinate transformations between disparate volume datasets to align samples in a common ray space, enabling the simultaneous visualization of registered or unregistered multi-modal data [S1, S2, unofficial].

## How it works
The method implements the emission-absorption optical model, building on [Hardware-Accelerated Volume Rendering](5616-hardware-accelerated-volume-rendering.md). It processes pixels in parallel using fragment shaders, handling ray generation, multi-volume sampling, classification, and front-to-back compositing [S1, S2, unofficial].

### Inputs and Outputs
**Inputs:**
1.  **Primary Volume:** `vtkImageData` dataset (Input Port 0).
2.  **Additional Volumes:** Up to `MAX_NUMBER_OF_ADDITIONAL_VOLUMES` (3 on Apple, 4 otherwise) `vtkImageData` datasets (Input Ports 1 to N) [S1, unofficial].
3.  **Properties:** `vtkVolumeProperty` objects for each volume, defining transfer functions and shading parameters [S1, unofficial].
4.  **Transforms:** User-defined `vtkTransform` objects for each additional volume to align them with the primary volume's texture coordinate space [S1, unofficial].
5.  **Mask (Optional):** A `vtkImageData` mask (Binary or LabelMap) to confine rendering to specific regions [S1, S2, unofficial].

**Outputs:**
*   A 2D image where each pixel contains the accumulated color and opacity from all volumes along the ray [S1, unofficial].

**C++ Class Members (`vtkGPUMultiVolumeRayCastMapper`):**
*   `NUMBER_OF_ADDITIONAL_VOLUMES`: Integer, max 3 (Apple) or 4 (others) [S1, unofficial].
*   `Property[MAX_NUMBER_OF_ADDITIONAL_VOLUMES]`: Array of `vtkVolumeProperty*` pointers [S1, unofficial].
*   `AdditionalInputUserTransform[MAX_NUMBER_OF_ADDITIONAL_VOLUMES]`: Array of `vtkTransform*` pointers [S1, unofficial].
*   `TransformedInput`, `TransformedInput2`: Pointers to `vtkImageData` holding shallow copies of inputs, adjusted for GPU constraints (e.g., zero-based extents) [S2, unofficial].
*   `ClippedCroppingRegionPlanes[6]`: Array of doubles for X, Y, Z min/max planes [S1, unofficial].
*   `MaskInput`: `vtkImageData*` for masking [S1, unofficial].
*   `MaskType`: Enum (`BinaryMaskType` or `LabelMapMaskType`) [S2, unofficial].
*   `MaskBlendFactor`: Float [0.0, 1.0], default 1.0 [S1, unofficial].

**GLSL Uniforms (Fragment Shader):**
*   `sampler3D dataSetTexture[MAX_NUMBER_OF_VOLUMES]`: 3D textures for scalar data [S1, unofficial].
*   `sampler1D opacityTexture[MAX_NUMBER_OF_VOLUMES]`: 1D textures for opacity transfer functions [S1, unofficial].
*   `mat4 P1toPN[MAX_NUMBER_OF_VOLUMES-1]`: Transformation matrices from Volume 1 texture coordinates to Volume N texture coordinates [S1, unofficial].
*   `vec3 lowBounds[MAX_NUMBER_OF_VOLUMES]`, `highBounds[MAX_NUMBER_OF_VOLUMES]`: Bounding box limits for each volume [S1, unofficial].
*   `int Number_Of_Volumes`: Count of active volumes [S1, unofficial].
*   `vec3 ClippingplanesNormal[MAX_NUMBER_OF_VOLUMES]`, `ClippingplanesOrigins[MAX_NUMBER_OF_VOLUMES]`: Clipping plane definitions [S1, unofficial].
*   `int clipped[MAX_NUMBER_OF_VOLUMES]`: Flags indicating if clipping is active [S1, unofficial].

### Parameters
*   `ImageSampleDistance`: Float, default 1.0. Controls sampling in XY image space. Clamped [0.1, 100.0] [S2, unofficial].
*   `MinimumImageSampleDistance`: Float, default 1.0. Lower bound for adaptive sampling [S2, unofficial].
*   `MaximumImageSampleDistance`: Float, default 10.0. Upper bound for adaptive sampling [S2, unofficial].
*   `AutoAdjustSampleDistances`: Int (0/1). Enables automatic adjustment of `ImageSampleDistance` based on render time [S1, S2, unofficial].
*   `SampleDistance`: Float, default 1.0. Base step size along the ray [S2, unofficial].
*   `MaxMemoryInBytes`: `vtkIdType`. Max GPU memory for textures. Defaults to dedicated video memory, or 128 MB if unavailable [S1, S2, unofficial].
*   `MaxMemoryFraction`: Float, default 0.75. Fraction of `MaxMemoryInBytes` used [S1, S2, unofficial].
*   `ReportProgress`: Bool, default true. Uses `glFinish()` to block and report progress. Should be false for small datasets to avoid slowdown [S1, S2, unofficial].
*   `FinalColorWindow`: Float, default 1.0. Window for final color scaling [S2, unofficial].
*   `FinalColorLevel`: Float, default 0.5. Level for final color scaling [S2, unofficial].
*   `GlobalAlpha`: Float, default 1.0. Overall alpha for blending with polygons [S3, unofficial].
*   `AMRMode`: Int (0/1). Enables Adaptive Mesh Refinement mode [S1, S2, unofficial].

### Algorithm Steps

1.  **Input Validation and Setup:**
    *   Check for null renderer, volume, or inputs. If `Input(0)` or `Input(1)` is NULL, abort [S2, unofficial].
    *   Validate cropping planes: if `Cropping` is true and any min plane >= max plane, fail silently (`goodSoFar = 0`) [S2, unofficial].
    *   Probe GPU memory to set `MaxMemoryInBytes`. If dedicated/shared memory is 0, default to 128 MB [S2, unofficial].
    *   Update `TransformedInput` and `TransformedInput2` if inputs have changed (check `MTime`). Adjust extents to start from zero if necessary (workaround for non-zero extents) [S2, unofficial].

2.  **Transformation Matrix Computation:**
    *   For each additional volume $N$ (from 2 to `Number_Of_Volumes`), compute the transformation matrix $P1toN$ [S1, unofficial]:
        $$ P1toN = T_{world \to tex_N} \cdot T_{tex_1 \to world} \cdot T_{user} $$
        where $T_{world \to tex_N}$ is the world-to-texture transform for volume $N$, $T_{tex_1 \to world}$ is the inverse of the world-to-texture transform for volume 1, and $T_{user}$ is the user-defined transform [S1, unofficial].
    *   Pass $P1toN$ matrices to the shader as `P1toPN` uniforms [S1, unofficial].

3.  **Clipping/Cropping Initialization:**
    *   Compute `ClippedCroppingRegionPlanes` by intersecting user-defined cropping planes with volume bounds [S1, unofficial].
    *   Convert clipping planes from world coordinates to texture coordinates just before rendering and pass them to shaders [S1, unofficial].

4.  **Ray Casting Loop (Fragment Shader `trace()`):**
    *   **Initialization:**
        *   Calculate initial ray position `pos` for Volume 1.
        *   Calculate initial positions `posX[i]` for additional volumes using `posX[i] = P1toPN[i] * vec4(pos, 1.0)` [S1, unofficial].
        *   Initialize `destColor` (via `initialColor()`) and `remainOpacity = 1.0 - destColor.a` [S1, unofficial].
        *   Set `t = 0.0`, `tMax` (max ray length) [S1, unofficial].
    *   **Traversal Loop:**
        *   While `inside` is true:
            *   `inside` is true if `t < tMax`, `remainOpacity >= 0.0039` (1/255), and `pos` is within `lowBounds[0]` and `highBounds[0]` [S1, unofficial].
            *   **Sample Volumes:**
                *   For Volume 0: If `pos` is within bounds and not clipped, sample `value[0] = texture3D(dataSetTexture[0], pos)`. Compute `scalar[0] = scalarFromValue(value[0])`. Sample `opacity[0] = texture1D(opacityTexture[0], scalar[0])` [S1, unofficial].
                *   For Volumes $i > 0$: If `posX[i-1]` is within bounds and not clipped, sample `value[i] = texture3D(dataSetTexture[i], posX[i-1])`. Compute `scalar[i] = scalarFromValue(value[i])`. Sample `opacity[i] = texture1D(opacityTexture[i], scalar[i])` [S1, unofficial].
            *   **Masking (if enabled):**
                *   If `MaskType` is `BinaryMaskType`: Assume UCHAR data. Values 255 (inside) and 0 (outside). Only render if mask value is 255 [S1, unofficial].
                *   If `MaskType` is `LabelMapMaskType`: Assume UCHAR data with 3 labels (0, 1, 2). Label 0 uses Component 0's CT. Label 1 uses Component 1's CT blended with Component 0's CT using `MaskBlendFactor`. Label 2 uses Component 2's CT blended with Component 0's CT using `MaskBlendFactor` [S1, unofficial].
            *   **Shading:**
                *   Compute `color[i] = shade(i, value[i]) * opacity[i].a` [S1, unofficial]. Shading uses gradients estimated via central differences or Sobel operators, adjusted by `P1toPN` for additional volumes [S1, unofficial].
            *   **Compositing:**
                *   If `opacity[i].a > 0.0`:
                    $$ destColor = destColor + color[i] \times remainOpacity $$
                    $$ remainOpacity = remainOpacity \times (1.0 - opacity[i].a) $$
            *   **Advance Ray:**
                *   `pos = pos + rayDir`
                *   `posX[i] = posX[i] + rayDir` (transformed by respective P1toPN if needed, or updated in texture space directly) [S1, unofficial].
                *   `t += 1.0`
    *   **Final Output:**
        *   `gl_FragColor = destColor`
        *   `gl_FragColor.a = 1.0 - remainOpacity` [S1, unofficial].

### Edge Cases and Pitfalls
*   **Hardware Loop Limits:** GPUs have limits on loop iterations. The implementation uses a nested while loop structure instead of a single loop over all samples and volumes to comply with hardware constraints [S1, unofficial].
*   **Non-Zero Extents:** The underlying mapper cannot handle extents starting from non-zero values. A workaround adjusts the origin and shifts extents to start from zero [S2, unofficial].
*   **Invalid Cropping:** If cropping planes define a region with zero or negative volume, the render fails silently (`goodSoFar=0`) without an error message [S2, unofficial].
*   **ReportProgress Overhead:** `ReportProgress` uses `glFinish()`, which blocks the GPU. It should be disabled for small datasets to avoid significant slowdowns [S2, unofficial].
*   **FinalColorWindow:** Setting `FinalColorWindow` to a negative value reverses the applied color values [S2, unofficial].
*   **Clipping:** Clipping planes are handled by computing intersection points `clipMin[i]` for each axis and ensuring the sample position is greater than `clipMin[i]` on all axes [S1, unofficial].

## Subtopics

### [OpenGL GPU Multi Volume Ray Cast Mapper](2919-opengl-gpu-multi-volume-ray-cast-mapper.md)
An OpenGL-specific subclass that handles hardware extension checks, OpenGL object lifecycle management, and clipping/cropping plane setup. It manages fragment shader programs, framebuffer objects, and texture uploads for rendering multiple volumes simultaneously [2919-opengl-gpu-multi-volume-ray-cast-mapper.md].

### [GPU Volume Ray Casting (VTK Composite Blend)](6912-gpu-volume-ray-casting-vtk-composite-blend.md)
A hardware-accelerated technique implemented in VTK via `vtkGPUVolumeRayCastMapper` that uses **Composite** blend mode for standard alpha blending during ray casting. It distinguishes itself from the OpenGL-specific multi-volume mapper by its explicit use of composite blending [6912-gpu-volume-ray-casting-vtk-composite-blend.md].

### [vtkSlicerGPURayCastVolumeMapper](7450-vtkslicergpuraycastvolumemapper.md)
A specific implementation for the 3D Slicer environment that builds on the parent to support adaptive sampling, masking, and AMR modes. It is distinguished by its integration with CTK transfer functions and specific OpenGL uniform layouts for ray casting parameters [7450-vtkslicergpuraycastvolumemapper.md].

### Mask Type Configuration
Methods to set the mask type for volume rendering, either `BinaryMaskType` or `LabelMapMaskType`. Binary masks assume UCHAR data with values 255 (inside) and 0 (outside). Label map masks assume UCHAR data with 3 labels (0, 1, 2), blending color transfer functions based on `MaskBlendFactor` [S2, unofficial].

### Label Map Masking for Volume Rendering
A masking technique that confines rendering to specific regions. Binary masks restrict rendering to regions where mask value is 255. Label map masks use component 0's CT for label 0, and blend component 1 or 2's CT with component 0's CT using `MaskBlendFactor` for labels 1 and 2, respectively [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray and the number of volumes. Adaptive sampling (`AutoAdjustSampleDistances`) can reduce complexity by varying `ImageSampleDistance` based on allocated render time [S1, S2, unofficial].
*   **Memory Complexity:** Linear with respect to the volume of the input datasets. Memory usage is bounded by `MaxMemoryInBytes` and `MaxMemoryFraction` [S1, S2, unofficial].
*   **Performance:** Shaders are faster than OpenCL and supported by more devices [S1, unofficial]. Performance is affected by `ReportProgress` (blocking `glFinish`) and the number of volumes [S1, S2, unofficial].
*   **Strengths:** Simultaneous rendering of multiple volumes, hardware acceleration, support for clipping/cropping, masking, and adaptive sampling [S1, S2, unofficial].
*   **Limitations:** Limited by hardware loop limits, requires zero-based extents (workaround needed), silent failure on invalid cropping, and potential slowdown from progress reporting [S1, S2, unofficial].
*   **When to Use:** Multi-modal volume visualization where volumes need to be rendered together with proper alignment [S1, unofficial].
*   **When Not to Use:** Small datasets where `ReportProgress` overhead is significant, or when hardware lacks required extensions [S2, S3, unofficial].

## Background
The GPU Multi-Volume Ray Casting Mapper was developed as an extension of the Visualization Toolkit (VTK) to support multi-volume rendering on the GPU. It was modified by Carlos Falcón and Karl Krissian to add support for multiple input datasets and properties, using GLSL shaders for ray traversal and compositing [S1, unofficial]. The project aims to leverage the parallel processing power of GPUs for general volume rendering algorithms, choosing shaders over OpenCL for speed and broader device support [S1, unofficial].
