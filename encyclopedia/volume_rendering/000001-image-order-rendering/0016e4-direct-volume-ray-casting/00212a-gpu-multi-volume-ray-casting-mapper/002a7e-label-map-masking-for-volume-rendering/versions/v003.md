# Label Map Masking for Volume Rendering

Also called: BinaryMaskType, LabelMapMaskType, MaskInput

## Overview
Label Map Masking confines volume rendering to specific regions using either a binary mask or a multi-label map, supporting blending between standard and mask-specific color transfer functions [S1, unofficial]. It differs from sibling mappers by explicitly mapping mask values to distinct color transfer function components and blending weights, rather than acting solely as a visibility gate [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A primary volume dataset and a mask dataset (`MaskInput`). The mask must be of type `UCHAR` (unsigned char) [S1, unofficial].
*   **Output:** A rendered image where pixel colors are determined by the volume data and the mask configuration [S1, unofficial].

**Data Structures:**
*   **Mask Data:** A 3D grid of `unsigned char` values [S1, unofficial].
    *   For **Binary Mask**: Values are strictly `0` (outside) or `255` (inside) [S1, unofficial].
    *   For **Label Map**: Values are restricted to exactly three labels: `0`, `1`, and `2` [S1, unofficial].

**Parameters:**
*   **MaskInput** (`vtkImageData*`): The source of the mask data [S1, unofficial].
*   **MaskBlendFactor** (`float`): Clamped to $[0.0, 1.0]$. Default is $1.0$. Controls the blending weight between the standard color transfer function and the mask-specific color transfer function [S1, unofficial]. A value of $0.0$ uses only the standard color transfer function, while $1.0$ uses only the mask color transfer function [S1, unofficial].

**Algorithm Steps:**
1.  **Determine Mask Type:** Check the configuration of `MaskInput` to determine if it is a Binary Mask or a Label Map [S1, unofficial].
2.  **Sample Volume Data:** For each ray, sample the primary volume at the current position to obtain the scalar value $v$ [S1, unofficial].
3.  **Sample Mask Data:** Retrieve the mask value $m$ at the corresponding spatial position [S1, unofficial].
4.  **Apply Mask Logic:**
    *   **If Binary Mask:** If $m = 255$, proceed with rendering; if $m = 0$, skip rendering for this ray segment [S1, unofficial].
    *   **If Label Map:** Identify the label $L \in \{0, 1, 2\}$ from $m$ [S1, unofficial]. Retrieve the color transfer function outputs for value $v$: $C_0, A_0$ for component 0; $C_1, A_1$ for component 1; $C_2, A_2$ for component 2 [S1, unofficial]. Calculate the final color $C_{\text{final}}$ and opacity $A_{\text{final}}$ based on $L$:
        *   If $L = 0$: $C_{\text{final}} = C_0$, $A_{\text{final}} = A_0$ [S1, unofficial].
        *   If $L = 1$: $C_{\text{final}} = (1 - \text{MaskBlendFactor}) \cdot C_0 + \text{MaskBlendFactor} \cdot C_1$, $A_{\text{final}} = (1 - \text{MaskBlendFactor}) \cdot A_0 + \text{MaskBlendFactor} \cdot A_1$ [S1, unofficial].
        *   If $L = 2$: $C_{\text{final}} = (1 - \text{MaskBlendFactor}) \cdot C_0 + \text{MaskBlendFactor} \cdot C_2$, $A_{\text{final}} = (1 - \text{MaskBlendFactor}) \cdot A_0 + \text{MaskBlendFactor} \cdot A_2$ [S1, unofficial].
5.  **Composite:** Perform standard front-to-back alpha blending using $C_{\text{final}}$ and $A_{\text{final}}$ [S1, unofficial].

**Pseudocode:**
```python
def render_label_map_masking(volume_data, mask_data, mask_blend_factor, ctf_0, ctf_1, ctf_2):
    """
    Renders volume data using label map masking.
    
    Args:
        volume_data: 3D array of scalar values.
        mask_data: 3D array of unsigned char values (0, 1, 2, or 255).
        mask_blend_factor: Float in [0.0, 1.0].
        ctf_0, ctf_1, ctf_2: Functions mapping scalar value to (color, opacity).
        
    Returns:
        Rendered image buffer.
    """
    height, width, depth = volume_data.shape
    output_image = [[[0.0, 0.0, 0.0] for _ in range(width)] for _ in range(height)]
    
    for y in range(height):
        for x in range(width):
            accum_color = [0.0, 0.0, 0.0]
            accum_opacity = 0.0
            for z in range(depth):
                v = volume_data[z][y][x]
                m = mask_data[z][y][x]
                
                c0, a0 = ctf_0(v)
                
                if m == 255:
                    final_color = c0
                    final_opacity = a0
                elif m == 0:
                    final_color = [0.0, 0.0, 0.0]
                    final_opacity = 0.0
                elif m == 1:
                    c1, a1 = ctf_1(v)
                    final_color = [(1.0 - mask_blend_factor) * c0[i] + mask_blend_factor * c1[i] for i in range(3)]
                    final_opacity = (1.0 - mask_blend_factor) * a0 + mask_blend_factor * a1
                elif m == 2:
                    c2, a2 = ctf_2(v)
                    final_color = [(1.0 - mask_blend_factor) * c0[i] + mask_blend_factor * c2[i] for i in range(3)]
                    final_opacity = (1.0 - mask_blend_factor) * a0 + mask_blend_factor * a2
                else:
                    final_color = [0.0, 0.0, 0.0]
                    final_opacity = 0.0
                    
                if final_opacity > 0.0:
                    for i in range(3):
                        accum_color[i] = accum_color[i] * (1.0 - final_opacity) + final_color[i] * final_opacity
                    accum_opacity += final_opacity * (1.0 - accum_opacity)
                    if accum_opacity >= 1.0:
                        break
            output_image[y][x] = accum_color
    return output_image
```

**Edge Cases and Pitfalls:**
*   **Data Type Mismatch:** The mask must be `UCHAR`. Using other types may lead to undefined behavior or incorrect label interpretation [S1, unofficial].
*   **Label Constraints:** Label maps are restricted to exactly three labels (0, 1, 2). Values outside this range are not defined in the source specification [S1, unofficial].
*   **Precision:** `MaskBlendFactor` is clamped to $[0.0, 1.0]$. Values outside this range should be clamped by the implementation [S1, unofficial].

## Subtopics

### Mask Volume Brushing
A technique using a 3D binary data structure (mask volume) linked between attribute space views and object space rendering to select and highlight features [S2, book]. It differs from standard label map masking by emphasizing an interactive workflow where the mask is created and modified by brushing tensor properties in attribute space, then evaluated for rendering in the spatial domain [S2, book]. It is chosen when interactive feature selection in high-dimensional attribute spaces is required [S2, book]. Mask values are binary (0 or 1) stored in a 3D structure of the same size as the input data [S2, book].

### Mask-Guided Ray Casting
A ray casting technique that utilizes tool masks to handle tool occlusion and recover hidden tissues [S3]. Tool masks are obtained by manual labeling [S3].
