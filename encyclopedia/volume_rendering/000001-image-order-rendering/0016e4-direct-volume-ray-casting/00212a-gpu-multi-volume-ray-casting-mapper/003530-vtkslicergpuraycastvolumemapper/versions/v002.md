# vtkSlicerGPURayCastVolumeMapper

Also called: GPGPU Ray Cast Mapper

## Overview
Renders a volume using ray casting on a 3D texture [S1, unofficial]. It builds on [GPU Multi-Volume Ray Casting Mapper](2461-gpu-multi-volume-ray-casting-mapper.md) to provide a specific implementation for the 3D Slicer environment [G]. It is distinguished from its siblings by its specific integration with CTK transfer functions and its handling of specific OpenGL uniform layouts for ray casting parameters [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume data (scalar or vector), volume property (opacity and color transfer functions), camera state, and clipping planes [G].
*   **Output:** A 2D image rendered to the framebuffer [G].

**Data Structures:**
The mapper maintains specific OpenGL handles and uniform buffers to communicate with the GPU shaders [S1, unofficial]:
*   `double VolumeBBoxVertices[8][3]`: Stores the 8 vertices of the volume's bounding box, each with 3 coordinates (x, y, z) [S1, unofficial].
*   `double VolumeBBoxVerticesColor[8][3]`: Stores the 8 bounding box vertices with associated color values, each with 3 coordinates [S1, unofficial].
*   `GLfloat ParaMatrix[16]`: A 4x4 matrix uniform containing ray casting parameters (e.g., view-projection transformations) [S1, unofficial].
*   `GLfloat ParaMatrix1[16]`: A second 4x4 matrix uniform for additional ray casting parameters [S1, unofficial].
*   `GLuint Volume1Index`: OpenGL handle for the volume texture [S1, unofficial].
*   `GLuint ColorLookupIndex`: OpenGL handle for the color lookup table (CLUT) [S1, unofficial].
*   `GLuint RayCastVertexShader`: OpenGL handle for the vertex shader [S1, unofficial].
*   `GLuint RayCastFragmentShader`: OpenGL handle for the fragment shader [S1, unofficial].
*   `GLuint RayCastProgram`: OpenGL handle for the linked shader program [S1, unofficial].

**Algorithm Steps:**
The sources do not provide a step-by-step execution flow or pseudocode [S1, unofficial]. The method relies on the parent class pipeline hooks (`PreRender`, `RenderBlock`, `PostRender`) for orchestration [G]. Implementation requires initializing the OpenGL handles, uploading the defined data structures to GPU memory, setting the parameters as uniforms, and invoking the shader program [G].

**Formulas:**
Not given in the sources.

**Parameters:**
*   `DistanceColorBlending` (float, default 0.0): Controls depth-based color blending. A value of 0.0 implies no blending; non-zero values make closer voxels brighter and farther voxels darker [S1, unofficial].
*   `DepthPeelingThreshold` (float): Threshold used for depth peeling operations to handle transparency sorting [S1, unofficial].
*   `ICPEScale` (float): Scale parameter for the ICPE algorithm [S1, unofficial].
*   `Clipping` (int): Boolean flag (0 or 1) to enable or disable clipping planes [S1, unofficial].
*   `Technique` (int): Integer selector to choose between different rendering techniques supported by the mapper [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Hardware Support:** Hardware rendering is unsupported if the input data has more than one independent component [S1, unofficial].
*   **Extensions:** Rendering fails if the hardware lacks required OpenGL extensions [S1, unofficial].
*   **Precision:** Calculations are computed using 8 bits per RGBA channel. 15-bit float compositing is not supported [S1, unofficial].

## Subtopics

### vtkSlicerGPUVolumeMapper
An abstract superclass for GPU volume rendering using 3D texture mapping in the fragment shader [S1, unofficial]. Actual rendering work is delegated to `vtkSlicerGPURayCastVolumeTextureMapper3D` [S1, unofficial]. It supports composite blending, intermixed opaque geometry, and multiple volumes sorted back-to-front [S1, unofficial]. Internal resolution is resampled to a power of two, capped at 128x256x256 for 1 or 2 component data, or 128x128x256 for 4 component data [S1, unofficial]. It is limited to single independent component data and does not support maximum intensity projection [S1, unofficial]. Use it for standard scalar volume rendering in 3D Slicer when higher precision compositing is not required [G].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial].

*   **Performance:** Not given in the sources [S1, unofficial].
*   **Strengths:** Supports multiple volumes, adaptive sampling, and masking via the parent class [G]. Integrates with 3D Slicer's transfer function widgets [S1, unofficial].
*   **Limitations:** Limited to single independent component data [S1, unofficial]. No maximum intensity projection support [S1, unofficial]. Precision limited to 8-bit per channel compositing [S1, unofficial].
*   **When to use:** When using 3D Slicer and requiring GPU-accelerated ray casting for single-component scalar volumes with transparency [G].
*   **When not to use:** For multi-component vector data, maximum intensity projection, or when higher precision compositing (15-bit float) is required [S1, unofficial].

## Background
The `vtkSlicerGPURayCastVolumeMapper` is part of the VolumeRenderer module within the 3D Slicer ecosystem, specifically leveraging the CTK (Common Toolkit) libraries for transfer function management [S1, unofficial]. It was developed to provide a GPU-accelerated alternative to CPU-based volume rendering within the Slicer platform [S1, unofficial].
