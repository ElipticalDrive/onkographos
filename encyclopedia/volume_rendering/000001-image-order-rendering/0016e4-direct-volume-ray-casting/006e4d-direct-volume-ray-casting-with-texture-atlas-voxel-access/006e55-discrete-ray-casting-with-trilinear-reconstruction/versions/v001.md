# Discrete Ray Casting with Trilinear Reconstruction

Also called: Trilinear Reconstruction Ray Casting

## Overview
Discrete Ray Casting with Trilinear Reconstruction is a direct volume rendering technique that samples volumetric data using discrete ray casting steps and reconstructs scalar values via trilinear interpolation [S1]. It differs from its parent, Direct Volume Ray Casting with Texture Atlas Voxel Access, by employing trilinear reconstruction within the ray casting loop rather than relying solely on bilinear interpolation of pre-sliced texture tiles for access [S1]. This method allows for continuous sampling along the ray path through the volume, improving visual quality over nearest-neighbor or purely 2D-interpolated approaches while maintaining the hardware-accelerated texture access patterns of the atlas-based parent [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A 2D texture atlas containing all vertical slices of the volume in grayscale, 32-bit floating-point format [S1].
*   Camera parameters (position, orientation) to define ray origins and directions [S1].
*   Clipping plane parameters: orientation (pitch, yaw) and depth, with an option to lock the plane to the camera [S1].
*   Rendering parameters: overall opacity control, intensity value clamping limits, and color mapping mode (grayscale or heatmap) [S1].

**Outputs:**
*   A 2D image where each pixel represents the accumulated color and opacity of the ray passing through the volume [S1].

### Data Structures
*   **Texture Atlas:** A 2D texture of arbitrary size, structured as a $10 \times 10$ grid of tiles [S1].
*   **Tile Layout:** The atlas contains 96 used tiles out of 100 [S1]. The layout is hardcoded: the top (first) slice is located at the top-left corner of the grid [S1]. The remaining 4 tiles are unused [S1].
*   **Ray State:** For each pixel, a ray origin $\mathbf{o}$ and direction $\mathbf{d}$ are computed in the vertex shader [S1].

### Algorithm Steps

1.  **Domain Construction:** The vertex shader generates the geometry (typically a screen-aligned quad) to produce fragments covering the viewport [S1].
2.  **Ray Initialization:** For each fragment, compute the ray origin $\mathbf{o}$ and direction $\mathbf{d}$ based on the camera position and the fragment's screen coordinates [S1].
3.  **Clipping Plane Intersection:**
    *   Define the clipping plane by its normal vector $\mathbf{n}$ and distance $d_{plane}$ from the origin [S1].
    *   Calculate the intersection parameter $t_{clip}$ where the ray intersects the plane:
        $$ t_{clip} = \frac{d_{plane} - \mathbf{o} \cdot \mathbf{n}}{\mathbf{d} \cdot \mathbf{n}} $$
    *   Determine the start of the volume traversal:
        *   If $\mathbf{n} \cdot \mathbf{d} < 0$ (normal faces the ray source), the ray enters the volume at the near plane or origin, and the clipping plane acts as a far boundary. The traversal starts at the volume entry point and stops at $t_{clip}$ [S1].
        *   If $\mathbf{n} \cdot \mathbf{d} \ge 0$ (normal does not face the ray source), the ray starts from the intersection point with the plane's surface. The traversal begins at $t_{clip}$ and proceeds into the volume [S1].
    *   Let $t_{start}$ be the starting parameter and $t_{end}$ be the ending parameter of the ray segment within the volume [S1].
4.  **Ray Casting Loop:** Iterate along the ray from $t_{start}$ to $t_{end}$ with a fixed step size $\Delta t$ [S1].
    *   Calculate the current 3D position $\mathbf{p} = \mathbf{o} + t \mathbf{d}$ [S1].
    *   Map $\mathbf{p}$ to the corresponding tile in the 2D atlas. Since the atlas stores vertical slices, the mapping involves determining which slice index $s$ corresponds to the $z$-coordinate (or depth axis) of $\mathbf{p}$, and the $(x, y)$ coordinates within that slice [S1].
    *   Compute the UV coordinates $(u, v)$ for the current position within the specific tile [S1].
    *   **Trilinear Reconstruction:** Sample the texture using trilinear interpolation. This involves:
        1.  Bilinear interpolation of the current slice's texture at $(u, v)$ to get scalar value $v_0$ [S1].
        2.  Bilinear interpolation of the adjacent slice's texture (previous or next, depending on interpolation direction) at $(u, v)$ to get scalar value $v_1$ [S1].
        3.  Linear interpolation between $v_0$ and $v_1$ based on the fractional distance of $\mathbf{p}$ between the two slice planes to obtain the final scalar value $s$ [S1].
    *   Apply intensity clamping: if $s$ is outside the defined visibility range, treat it as background or zero [S1].
    *   Apply color mapping: convert scalar $s$ to color $C$ and opacity $\alpha$ using the selected mode (grayscale or heatmap) [S1].
    *   Accumulate color and opacity using front-to-back compositing:
        $$ C_{out} = C_{in} + C \cdot \alpha \cdot (1 - \alpha_{in}) $$
        $$ \alpha_{out} = \alpha_{in} + \alpha \cdot (1 - \alpha_{in}) $$
    *   Apply global opacity control: multiply the final accumulated opacity by the user-defined opacity slider value [S1].
5.  **Fragment Output:** Output the final accumulated color and opacity to the framebuffer [S1].

### Pseudocode

```python
# Vertex Shader
def vertex_shader(vertex_position):
    # Generate screen-aligned quad or use built-in vertex attributes
    return vertex_position

# Fragment Shader
def fragment_shader(screen_uv, camera_params):
    # 1. Ray Initialization
    ray_origin = get_ray_origin(screen_uv, camera_params)
    ray_direction = get_ray_direction(screen_uv, camera_params)
    
    # 2. Clipping Plane Intersection
    # Plane defined by normal n and distance d_plane
    # Check if normal faces the ray source
    if dot(ray_direction, plane_normal) < 0:
        # Normal faces ray source: ray hits domain, progresses until plane surface
        t_clip = (plane_distance - dot(ray_origin, plane_normal)) / dot(ray_direction, plane_normal)
        t_start = volume_entry_t # Assumed known from volume bounds
        t_end = t_clip
    else:
        # Normal does not face ray source: start from plane surface
        t_clip = (plane_distance - dot(ray_origin, plane_normal)) / dot(ray_direction, plane_normal)
        t_start = t_clip
        t_end = volume_exit_t # Assumed known from volume bounds
    
    # 3. Ray Casting Loop
    accumulated_color = vec3(0.0)
    accumulated_alpha = 0.0
    
    t = t_start
    while t < t_end:
        # Current 3D position
        p = ray_origin + t * ray_direction
        
        # Map p to atlas tile and UV coordinates
        # This requires knowing the volume's spatial extent and slice spacing
        slice_index = get_slice_index(p.z) # Assuming z is the slice axis
        uv_in_tile = get_uv_in_tile(p.x, p.y)
        
        # Trilinear Reconstruction
        # Sample current slice
        val_current = texture(atlas_texture, uv_for_tile(slice_index, uv_in_tile))
        
        # Sample adjacent slice (interpolate between slice_index and slice_index + 1)
        # Determine fractional depth within the slice interval
        frac = get_fractional_depth(p.z, slice_index)
        
        val_next = texture(atlas_texture, uv_for_tile(slice_index + 1, uv_in_tile))
        
        # Linear interpolation between slices (trilinear reconstruction)
        scalar_value = lerp(val_current, val_next, frac)
        
        # Intensity Clamping
        if scalar_value < intensity_min or scalar_value > intensity_max:
            scalar_value = 0.0
            
        # Color Mapping
        color, alpha = map_color_and_alpha(scalar_value, color_mode)
        
        # Front-to-Back Compositing
        if accumulated_alpha >= 1.0:
            break
            
        accumulated_color = accumulated_color + color * alpha * (1.0 - accumulated_alpha)
        accumulated_alpha = accumulated_alpha + alpha * (1.0 - accumulated_alpha)
        
        t += step_size
        
    # Apply global opacity control
    final_alpha = accumulated_alpha * global_opacity_slider
    
    return vec4(accumulated_color, final_alpha)
```

### Parameters
*   **Atlas Grid:** Hardcoded $10 \times 10$ grid, using 96 tiles [S1].
*   **Clipping Plane:** Defined by pitch, yaw, and depth; can be locked to camera [S1].
*   **Opacity Slider:** Controls overall volume opacity [S1].
*   **Intensity Clamping:** Limits visibility based on scalar intensity values [S1].
*   **Color Mapping:** Modes include grayscale (default) and heatmap [S1].

### Edge Cases and Pitfalls
*   **Precision:** Using 32-bit floating-point textures ensures sufficient precision for scalar values [S1].
*   **Boundary Conditions:** The hardcoded 96-tile layout means rays hitting unused tiles (4 out of 100) will not contribute to the image [S1].
*   **Clipping Plane Orientation:** Incorrect handling of the normal vector direction relative to the ray source can lead to incorrect traversal start/end points [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is the number of ray steps per pixel. The trilinear reconstruction adds a constant factor of texture lookups per step [S1].
*   **Memory Complexity:** $O(S)$, where $S$ is the size of the texture atlas. The atlas size depends on the number of slices and the resolution of each slice [S1].

### Measured Performance
*   Not given in the sources.

### Scaling
*   The method scales with the number of slices and the resolution of the texture atlas. The hardcoded 96-tile limit may restrict the maximum number of slices unless the atlas layout is modified [S1].

### Strengths and Limitations
*   **Strengths:** Trilinear reconstruction provides smoother visual results than nearest-neighbor sampling. The use of a texture atlas allows for efficient hardware-accelerated texture sampling [S1].
*   **Limitations:** The hardcoded 96-tile layout limits flexibility. Trilinear reconstruction is more computationally expensive than bilinear or nearest-neighbor sampling [S1].

### When to Use
*   Use when smooth interpolation is required and the volume has a manageable number of slices that fit within the 96-tile constraint [S1].

### When Not to Use
*   Avoid when the volume has more than 96 slices or when higher performance is needed and visual smoothness is less critical [S1].
