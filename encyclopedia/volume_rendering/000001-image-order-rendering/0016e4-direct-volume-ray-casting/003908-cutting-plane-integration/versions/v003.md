# Cutting Plane Integration

Also called: CuttingPlaneRender, Interactive Cutting Plane

## Overview
Cutting Plane Integration is an interactive clipping technique that renders a semi-transparent plane mesh and normal arrow, dynamically updating raycasting uniforms to slice the volume and reveal internal structures [S1, unofficial]. It sets itself apart from sibling methods like [Customization Volume Integration](5291-customization-volume-integration.md) by using explicit geometric primitives (planes) rather than auxiliary scalar volumes or complex lighting models to define the visible region. It builds on the fundamental ray casting loop defined in [Direct volume ray casting](19-direct-volume-ray-casting.md) by modifying the ray traversal bounds based on the plane's position and orientation.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Volume data (scalar field), camera parameters, plane position (normalized height), plane rotation (X/Y axes), and a boolean flag for rendering orientation.
*   **Outputs:** A 2D image where the volume is clipped by the cutting plane, with the plane geometry and its normal vector rendered on top.

**Data Structures:**
*   **Volume:** Stored as a `Float32Array` of normalized values (0.0 to 1.0). The source data is loaded from a `uint16Array` where each voxel is divided by 4095.0 [S1, unofficial].
    *   Dimensions: `width`, `height`, `depth` (stored as `uint16`).
    *   Total size: `width * height * depth`.
*   **Plane Geometry:** A mesh representing the cutting surface.
*   **Normal Arrow:** An `ArrowHelper` object representing the plane's normal vector, positioned at the plane's center.

**Parameters:**
*   `planeHeight`: Normalized float in range [0, 1]. Maps to the world Z-axis position.
*   `planeRotX`, `planeRotY`: Rotation angles in degrees around the X and Y axes.
*   `renderAbove`: Boolean flag. If true, flips the plane 180° around the Y-axis [S1, unofficial].

**Steps:**
1.  **Load Volume:** Read the volume data into a `Float32Array`. Normalize voxel values by dividing by 4095.0. Create a 3D texture (`Data3DTexture`) with `RedFormat` and `FloatType` [S1, unofficial].
2.  **Calculate Plane Position:** Map the normalized `planeHeight` to the world Z-coordinate. The formula is:
    $$ z_{world} = 200 - 400 \times planeHeight $$
    This maps `planeHeight` 0 to Z=200 and `planeHeight` 1 to Z=-200 [S1, unofficial].
3.  **Calculate Plane Rotation:**
    *   Convert `planeRotX` and `planeRotY` from degrees to radians.
    *   If `renderAbove` is true, add $\pi$ (180°) to `planeRotY` to flip the plane orientation [S1, unofficial].
    *   Apply rotations to the plane mesh.
4.  **Setup Normal Arrow:**
    *   Create an arrow at the origin $(0,0,0)$ pointing along the Z-axis $(0,0,1)$.
    *   Set arrow length to 35 units.
    *   Disable depth testing and depth writing for the arrow's line material to ensure it renders on top of the volume [S1, unofficial].
5.  **Update Raycasting Uniforms:** Pass the plane's world position and orientation to the raycasting shader. The shader uses these uniforms to clip the ray traversal. Rays are typically clipped against the plane, and integration stops or changes behavior at the intersection point depending on the specific implementation of "cutting" (e.g., rendering only one side or showing the cross-section) [S1, unofficial].
6.  **Render:**
    *   Render the volume using ray casting, respecting the clipping defined by the plane uniforms.
    *   Render the plane mesh (semi-transparent).
    *   Render the normal arrow.

**Edge Cases and Pitfalls:**
*   **Precision:** The volume data is normalized from 16-bit integers. Ensure the division by 4095.0 is handled correctly to maintain dynamic range [S1, unofficial].
*   **Boundary Conditions:** The mapping formula assumes a specific world coordinate range (-200 to 200). If the volume or camera coordinates differ, the mapping must be adjusted [S1, unofficial].
*   **Rotation Order:** The order of rotations (X then Y, or Y then X) affects the final orientation. The source implies a specific order by applying the Y-rotation flip conditionally [S1, unofficial].

**Pseudocode:**
```python
def update_cutting_plane(plane_height, plane_rot_x, plane_rot_y, render_above):
    # Step 2: Calculate Plane Position
    # Map normalized height [0, 1] to world Z [-200, 200]
    plane_z = 200.0 - 400.0 * plane_height
    
    # Step 3: Calculate Plane Rotation
    # Convert degrees to radians
    rot_x_rad = math.radians(plane_rot_x)
    rot_y_rad = math.radians(plane_rot_y)
    
    # Apply 180 degree flip around Y if renderAbove is true
    if render_above:
        rot_y_rad += math.pi
        
    # Update plane mesh rotation
    plane_mesh.rotation.x = rot_x_rad
    plane_mesh.rotation.y = rot_y_rad
    plane_mesh.position.z = plane_z
    
    # Step 4: Setup Normal Arrow (if not already created)
    # Arrow origin at center (0,0,0)
    # Arrow direction along Z-axis (0,0,1)
    arrow_direction = Vector3(0, 0, 1).normalize()
    arrow_length = 35
    arrow_color = 0xff0000 # Red
    
    # Create or update ArrowHelper
    if normal_arrow is None:
        normal_arrow = ArrowHelper(arrow_direction, Vector3(0,0,0), arrow_length, arrow_color)
        normal_arrow.setLength(35, 20, 10) # Adjust head and shaft sizes
        normal_arrow.position.set(0, 0, 0)
        # Ensure arrow renders on top
        normal_arrow.line.material.depthTest = False
        normal_arrow.line.material.depthWrite = False
    
    # Step 5: Update Raycasting Uniforms
    # Pass plane_z, rot_x_rad, rot_y_rad to the raycasting shader
    raycasting_shader.uniforms.plane_position.value = Vector3(0, 0, plane_z)
    raycasting_shader.uniforms.plane_rotation.value = Vector3(rot_x_rad, rot_y_rad, 0)
    
    # Step 6: Render
    # Render volume with clipping
    renderer.render(volume_scene, camera)
    # Render plane mesh
    renderer.render(plane_mesh, camera)
    # Render normal arrow
    renderer.render(normal_arrow, camera)
```

## Subtopics

### Region of Interest (ROI) Rendering
A technique to visualize internal features by defining a region of interest and rendering only that portion of the dataset [S2, book]. It differs from standard cutting planes by allowing more complex region definitions (e.g., closed geometric objects, binary masks) rather than just a single half-space. For image-order ray casting, the ray is clipped against all geometric region definitions as a preprocessing step, and the ray function is evaluated only along segments within the ROI. Mask values are consulted at each sample to include or exclude contributions. For object-order methods, samples are checked against the ROI before incorporation. Hardware clipping planes can be used to support ROI [S2, book].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the number of samples per ray within the visible region. The clipping operation adds a constant overhead per ray.
*   **Memory Complexity:** Linear with respect to the volume size for storing the voxel data. The plane geometry and arrow add negligible memory overhead.
*   **Performance:** Interactive performance is achievable because the clipping is simple and can be handled efficiently in the shader or as a preprocessing step. The source demonstrates real-time interaction with plane parameters [S1, unofficial].
*   **Strengths:** Simple to implement, intuitive for users, allows immediate visual feedback of internal structures.
*   **Limitations:** Limited to planar cuts. Cannot easily handle complex, non-planar regions of interest without more advanced techniques like ROI rendering [S2, book].
*   **When to use:** When the user needs to quickly inspect internal structures by slicing the volume.
*   **When not to use:** When complex, non-planar regions of interest are required, or when the volume is too large to fit in memory for real-time ray casting.
