# Half-angle slicing

Also called: Halfway vector slicing, Half angle slice axis

## Overview
Half-angle slicing is a two-pass per-slice rendering technique for volumetric shadows that orients proxy slice planes perpendicular to the half-angle vector between the eye and light directions [S1, unofficial][S2][S4, unofficial][S5, book]. This orientation allows a single slice to be rendered from both the observer's and the light's points of view, minimizing the number of slices required to resolve lighting details compared to standard view-aligned or light-aligned slicing [S4, unofficial]. Unlike standard shadow mapping which requires pre-computation or large 3D shadow volumes, this method achieves high-resolution shadow effects using only a single additional 2D buffer [S2][S5, book].

## How it works
**Inputs and Outputs:**
- **Inputs:** 3D volume data (scalar field), camera position and projection, light direction (and position for point lights), number of slices ($N$).
- **Outputs:** Final composited image in the eye buffer.

**Data Structures:**
1.  **Light Buffer:** A 2D offscreen render buffer (texture) storing light transmissivity/attenuation. Initialized to $1 - \text{light intensity}$ [S5, book]. Resolution should be 30%–50% higher than the frame buffer to mitigate shadow boundary artifacts [S5, book]. Format: High Dynamic Range (e.g., `R16G16B16A16Sfloat`) [S1, unofficial].
2.  **Eye Buffer:** A 2D offscreen render buffer storing the accumulated color for the eye pass [S1, unofficial]. Format: High Dynamic Range [S1, unofficial].
3.  **Push Constants (Eye Pass):**
    -   `eyeMVP`: `glm::mat4` (64 bytes)
    -   `lightMVP`: `glm::mat4` (64 bytes)
    -   `opacityCorrection`: `float` (4 bytes)
    -   `ambient`: `float` (4 bytes)
    -   `densityMin`: `float` (4 bytes)
    -   `densityMax`: `float` (4 bytes)
    -   Total: 144 bytes [S1, unofficial]. *Note: Vulkan guarantees only 128 bytes; requires driver support for $\ge 256$ bytes* [S1, unofficial].
4.  **Push Constants (Light Pass):**
    -   `lightMVP`: `glm::mat4` (64 bytes)
    -   `opacityCorrection`: `float` (4 bytes)
    -   `densityMin`: `float` (4 bytes)
    -   `densityMax`: `float` (4 bytes)
    -   Total: 76 bytes [S1, unofficial].

**Algorithm Steps:**

1.  **Compute Half-Angle Vector:**
    Determine the direction for slice planes. Let $\mathbf{v}$ be the normalized view direction (from camera to object) and $\mathbf{l}$ be the normalized light direction.
    -   Calculate dot product: $d = \mathbf{l} \cdot \mathbf{v}$ [S2][S5, book].
    -   If $d \ge 0$: The half-vector $\mathbf{h}$ is halfway between $\mathbf{l}$ and $\mathbf{v}$ [S2][S5, book].
        $$ \mathbf{h} = \text{normalize}(\mathbf{l} + \mathbf{v}) $$
    -   If $d < 0$: The half-vector $\mathbf{h}$ is halfway between $\mathbf{l}$ and the inverted view direction ($-\mathbf{v}$) [S2][S5, book].
        $$ \mathbf{h} = \text{normalize}(\mathbf{l} - \mathbf{v}) $$
    *Implementation Note:* In local space, if `invCamVector` is the normalized vector from camera to object and `invLightVector` is the normalized light direction:
    ```python
    dot_product = dot(inv_light_vector, inv_cam_vector)
    b_view_inverted = dot_product >= 0
    if b_view_inverted:
        half_vector = normalize(inv_cam_vector + inv_light_vector)
    else:
        half_vector = normalize(-inv_cam_vector + inv_light_vector)
    ```
    [S4, unofficial][S5, book]

2.  **Determine Slice Bounds and Spacing:**
    -   Project the 8 bounding box vertices (local space $\pm 0.5$) onto $\mathbf{h}$ to find min and max distances:
        $$ \text{min\_dist} = \min_i (\mathbf{h} \cdot \mathbf{p}_i), \quad \text{max\_dist} = \max_i (\mathbf{h} \cdot \mathbf{p}_i) $$
        [S4, unofficial]
    -   Calculate total length along the half-vector:
        $$ L = \| (\mathbf{h} \cdot \text{max\_dist}) - (\mathbf{h} \cdot \text{min\_dist}) \| $$
        [S4, unofficial]
    -   Calculate step size for $N$ slices:
        $$ \text{step\_size} = L / N $$
        [S4, unofficial]
    -   *Alternative Spacing Formula:* If maintaining specific slice spacing $d_v$ along the view direction is required, and $\theta$ is the angle between view and light:
        $$ d_s = \frac{d_v}{\cos(\theta/2)} $$
        [S5, book]

3.  **Iterate Slices:**
    For each slice $s$ from $0$ to $N-1$:
    -   Calculate slice center position in world/local space:
        $$ \mathbf{C}_s = \mathbf{h} \cdot \text{min\_dist} + \mathbf{h} \cdot (s \cdot \text{step\_size}) + \frac{\mathbf{h} \cdot \text{step\_size}}{2} $$
        [S4, unofficial]
    -   **Generate Proxy Geometry:**
        -   Intersect the plane defined by $\mathbf{C}_s$ and normal $\mathbf{h}$ with the volume bounding box [S4, unofficial].
        -   Sort intersection vertices counter-clockwise around $\mathbf{C}_s$ using the cross-product test:
            ```python
            def sort_vertices(A, B, C, half_vector):
                # Returns 1 if B is clockwise from A relative to C, else -1
                if dot(half_vector, cross(A - C, B - C)) <= 0:
                    return 1
                else:
                    return -1
            ```
            [S4, unofficial]
        -   Construct a fan mesh: Add a central vertex (centroid of intersections) and connect to sorted boundary vertices. Handle winding order based on `b_view_inverted` [S4, unofficial].

    -   **Pass 1: Light Pass (Render from Light's POV):**
        -   Render the proxy slice geometry using the Light's View/Projection matrix.
        -   In the fragment shader, accumulate opacity $\alpha_i$ using the "over" operator to compute light transmissivity [S3, unofficial][S5, book].
        -   Write the accumulated transmissivity (or $1 - \text{accumulated opacity}$) to the **Light Buffer** [S1, unofficial][S5, book].
        -   *Order:* Render front-to-back with respect to the light [S3, unofficial][S5, book].

    -   **Pass 2: Eye Pass (Render from Eye's POV):**
        -   Render the *same* proxy slice geometry using the Eye's View/Projection matrix.
        -   Sample the **Light Buffer** at the current fragment's screen coordinates to retrieve the pre-computed light attenuation/transmissivity $\tau$ [S1, S3, unofficial].
        -   Compute the fragment color $C_i$ and opacity $\alpha_i$ from the volume data using the transfer function [S2][S5, book].
        -   Modulate the color by the light attenuation: $C_{final} = C_i \cdot \tau$ [S1, S3, unofficial].
        -   Composite into the **Eye Buffer** using front-to-back compositing (if $d \ge 0$) or back-to-front (if $d < 0$) with respect to the observer [S3, unofficial][S5, book].
        -   *Note:* The half-angle vector ensures the slice traversal order is always front-to-back from the light's perspective, simplifying the light pass [S1, unofficial].

4.  **Final Composition:**
    -   Copy the **Eye Buffer** to the screen [S1, unofficial].
    -   Apply gamma correction (typically 2.2) [S9].

**Pseudocode:**

```python
def half_angle_slice_render(volume, camera, light, num_slices=256):
    # 1. Setup Buffers
    light_buffer = create_2d_buffer(width=frame_width * 1.5, height=frame_height * 1.5, format=HDR)
    eye_buffer = create_2d_buffer(width=frame_width, height=frame_height, format=HDR)
    
    # Initialize light buffer to 1 - light_intensity (or arbitrary image for spotlights)
    light_buffer.clear(1.0 - light.intensity)

    # 2. Compute Half Vector
    inv_cam_vec = normalize(camera.position - volume.center) # Or object-space camera vector
    inv_light_vec = normalize(light.direction)
    
    dot_product = dot(inv_light_vec, inv_cam_vec)
    b_view_inverted = dot_product >= 0
    
    if b_view_inverted:
        half_vector = normalize(inv_cam_vec + inv_light_vec)
    else:
        half_vector = normalize(-inv_cam_vec + inv_light_vec)

    # 3. Compute Bounds
    box_vertices = get_box_vertices() # 8 vertices in local space
    projections = [dot(half_vector, v) for v in box_vertices]
    min_dist = min(projections)
    max_dist = max(projections)
    
    half_vector_length = magnitude(half_vector * max_dist - half_vector * min_dist)
    step_size = half_vector_length / num_slices
    
    newpos = half_vector * min_dist

    # 4. Iterate Slices
    for s in range(num_slices):
        # Calculate slice center
        center = newpos + (half_vector * s * step_size) + (half_vector * step_size / 2)
        
        # Generate Proxy Geometry (Intersection of plane and box)
        # This involves ray-box intersection along box edge directions
        # Sort vertices CCW around center using cross product with half_vector
        # Create fan mesh with centroid
        mesh = generate_slice_mesh(center, half_vector, box_vertices)

        # --- Light Pass ---
        # Render mesh from Light's POV
        # Shader: Accumulate opacity, write to light_buffer
        render(mesh, light.view_matrix, light.projection_matrix, light_buffer)

        # --- Eye Pass ---
        # Render mesh from Eye's POV
        # Shader: Sample light_buffer, modulate color, composite to eye_buffer
        render(mesh, camera.view_matrix, camera.projection_matrix, eye_buffer, light_buffer)

    # 5. Final Output
    screen.copy_from(eye_buffer)
    screen.apply_gamma(2.2)
```

## Operating characteristics
-   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of slices and $P$ is the number of pixels per slice (resolution). Two passes per slice are required.
-   **Memory Complexity:** $O(W \cdot H)$ for the two 2D buffers (Light and Eye). Significantly less than volumetric shadow maps which require $O(W \cdot H \cdot D)$ [S5, book].
-   **Performance:** Enables interactive frame rates by decoupling light transport resolution from volume data resolution [S5, book]. The use of "render to texture" extensions avoids costly copy operations between buffers [S5, book].
-   **Strengths:**
    -   Avoids attenuation leakage artifacts common in 2D shadow maps when view and light are perpendicular [S5, book].
    -   No pre-computation required [S2].
    -   High-resolution shadows without large memory overhead [S2][S5, book].
-   **Limitations:**
    -   **Shadow Boundary Artifacts:** Sharp opacity jumps can cause artifacts at shadow boundaries due to image-space sampling [S5, book]. Mitigated by using higher resolution for the light buffer (30-50% larger) [S5, book].
    -   **Push Constant Limits:** The eye pass push constants (144 bytes) exceed the Vulkan guaranteed minimum (128 bytes), requiring drivers that support $\ge 256$ bytes [S1, unofficial].
    -   **Perpendicular View/Light:** While the method handles this better than standard shadow maps, extreme angles may still require careful buffer resolution management to avoid blurriness [S5, book].

## Background
Half-angle slicing was proposed for volume shadow computation to address the limitations of standard shadow mapping and volumetric shadow maps in the context of GPU-based volume rendering [S1, unofficial][S5, book]. It was introduced in the context of interactive translucent volume rendering and procedural modeling [S2]. The technique modifies the proxy geometry slicing axis to be shared between the light and view directions, allowing a single slice to serve both viewpoints [S5, book]. It is described in *GPU Gems* (Chapter 39) and *The Visualization Handbook* (Chapter 9) [S1, unofficial][S5, book].
