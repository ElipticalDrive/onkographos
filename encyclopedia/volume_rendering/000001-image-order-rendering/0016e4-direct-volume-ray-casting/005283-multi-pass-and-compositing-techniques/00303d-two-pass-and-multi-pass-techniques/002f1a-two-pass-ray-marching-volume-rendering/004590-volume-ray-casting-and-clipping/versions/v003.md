# Volume Ray Casting and Clipping

Also called: Clip interval assembly and integration, Two-pass volume clipping

## Overview
Volume Ray Casting and Clipping is a two-pass ray tracing technique for volume rendering that supports arbitrarily many overlapping clip regions with arbitrary geometry types [S1]. It solves the problem of occluding specific parts of a volume dataset using external geometry or internal clip objects [S1]. Unlike standard ray casting which integrates along the entire ray segment within the volume bounds, this method assembles a set of valid clip intervals in the first pass and integrates the volume density only over the remaining segments in the second pass [S1]. It is distinguished by its ability to handle concavities and complex intersection geometries by using surface normals to determine valid entry and exit pairs for clipping [S1].

## How it works
The method operates in two logical passes, which can be combined into a single compute kernel to avoid regenerating viewing rays [S1].

**Inputs and Outputs:**
*   **Inputs:** Viewing position, viewing direction, volume dataset with axis-aligned bounding box (AABB), set of active clip objects, optional depth buffer from a previous render pass [S1].
*   **Outputs:** Rendered image where volume density is integrated only outside the defined clip intervals [S1].

**Data Structures:**
*   **Clip Intervals ($C$):** A set of intervals $[t_{start}, t_{end}]$ representing ray parameter ranges where the volume should *not* be evaluated [S1].
*   **Intersection List:** A sorted list of intersection distances $t$ and corresponding geometric normals $N$ for all active clip objects intersected by a ray [S1].

**Numbered Steps:**

1.  **Ray Generation and Volume Bounds:** Generate primary viewing rays from the viewing position [S1]. Determine $t_{near}$ and $t_{far}$, the distances from the ray's origin to the nearest and farthest intersection positions with the volume's AABB [S1].
2.  **Depth Buffer Integration (Optional):** If a depth buffer from a previous render pass exists, convert individual depth buffer entries to the volume coordinate system using the transformation outlined in [14] (not provided in [S1]) [S1]. Transform these to ray parameter space using vector operations to obtain $t_d$ [S1].
3.  **Update Ray Bounds:** Update the ray bounds to respect the depth buffer:
    $$ t_{near} := \max(t_d, t_{near}) $$
    $$ t_{max} := \min(t_d, t_{far}) $$
    These bounds remain valid for the subsequent clip interval assembly [S1].
4.  **Clip Object Intersection:** If the test against $t_{near}$ and $t_{far}$ yields a valid intersection, intersect the viewing ray with all active clip objects [S1]. Collect all intersection points [S1]. Let $M$ be the total number of intersections for a ray [S1]. Sort these intersections by distance from the ray origin [S1].
5.  **Interval Assembly:** For each ray, determine valid clip interval pairs using the geometric normal of the surface at intersection positions to handle concavities [S1]. Let $V$ be the normalized direction vector of the viewing ray [S1]. Let $\{N_{i-1}, N_i, N_{i+1}, N_{i+2}\}$ be the geometric normals at consecutive intersection indices [S1].

    Let indices be $1 \leq \dots \leq i-1 < i < i+1 < i+2 \leq \dots \leq M$ and distances be $t_1 \leq \dots \leq t_{i-1} \leq t_i \leq t_{i+1} \leq t_{i+2} \leq \dots \leq t_M$ [S1].

    The variables from Equation 1 denote indices over $M$ intersections, while the variables in Equation 2 denote distances from the origin of the viewing ray to the respective intersection position [S1]. The set of valid clip intervals $L$ is constructed by considering the dot product $V \cdot N$ [S1]. The source provides a partial definition for $L_j$ based on the normal at $i-1$ and $i+1$ relative to the ray direction [S1]. The specific cases provided are:
    *   If $V \cdot N_{i-1} > 0$: Add $[t_{i-1}, t_i]$ and $[t_{i+1}, t_{i+2}]$ to $L$ [S1].
    *   If $V \cdot N_{i-1} \leq 0$ and $i=2$: Add $[-\infty, t_{-1}]$ and $[t_i, t_{i+1}]$ to $L$ [S1].
    *   If $V \cdot N_{i+1} \dots$ (Source text cuts off): The logic implies checking normals to determine if the ray is entering or exiting the clip object, thereby identifying which segments between intersections are "inside" the clip volume and should be excluded from rendering [S1].

    The final set of clip intervals $C$ is the union of all such valid intervals $L$ for the ray [S1].

6.  **Integration (Pass 2):** Integrate over the volume density with respect to the clip intervals [S1]. The rendering integral is computed only for ray segments that are *not* covered by the intervals in $C$ [S1].

def intersect_aabb(origin, direction, aabb_min, aabb_max):
    tmin = -float('inf')
    tmax = float('inf')
    for k in range(3):
        if direction[k] == 0.0:
            if origin[k] < aabb_min[k] or origin[k] > aabb_max[k]:
                return None
        else:
            t1 = (aabb_min[k] - origin[k]) / direction[k]
            t2 = (aabb_max[k] - origin[k]) / direction[k]
            if t1 > t2: t1, t2 = t2, t1
            tmin = max(tmin, t1)
            tmax = min(tmax, t2)
    if tmin > tmax:
        return None
    return (tmin, tmax)

def subtract_intervals(base, exclusions):
    if not exclusions:
        return [base]
    exclusions.sort()
    result = []
    start, end = base
    for ex_start, ex_end in exclusions:
        if ex_end <= start:
            continue
        if ex_start >= end:
            break
        if ex_start > start:
            result.append([start, min(ex_start, end)])
        start = max(start, ex_end)
    if start < end:
        result.append([start, end])
    return result

def dot(v1, v2):
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

**Edge Cases and Pitfalls:**
*   **Concavities:** The method specifically addresses rays hitting concavities by using geometric normals to determine valid interval pairs [S1].
*   **Incomplete Source Logic:** The source text for the interval assembly logic cuts off at the condition involving $N_{i+1}$ and $N_{i+2}$ [S1]. Implementers must infer the remaining cases or consult the original paper for the complete normal-based interval selection logic [S1].
*   **Undefined Symbols:** The source uses $t_{-1}$ in a case where $i=2$, which is not defined in the provided equations [S1].

## Operating characteristics
*   **Time Complexity:** Dominated by ray-object intersection tests [S1].
*   **Memory Complexity:** Requires storage for the volume data, clip object structures, and the depth buffer if used [S1].
*   **Strengths:** Supports arbitrarily many overlapping clip regions and arbitrary geometry types. Interoperable with OpenGL rendering via depth buffer [S1].
*   **Limitations:** Requires two passes (or a complex single kernel). Logic for complex concavities is partially unspecified in the source text [S1].
*   **When to Use:** When precise clipping of volume data using complex external geometry is required [S1].
*   **When Not to Use:** When simple box clipping is sufficient, or when hardware does not support the required ray tracing primitives efficiently [S1].

## Background
The method was proposed in "Ray Traced Volume Clipping Using Multi-Hit BVH Traversal" [S1]. It builds on the concept of two-pass ray marching but extends it to handle arbitrary clip geometry and depth buffer interoperability [S1].
