# Two-Pass Ray Marching Volume Rendering

Also called: INTMeshVolumeRendering

## Overview
Two-Pass Ray Marching Volume Rendering is a GPU-accelerated technique that decouples the determination of ray entry and exit points from the color accumulation phase to optimize ray marching efficiency [S1, unofficial]. Unlike standard single-pass ray casting which may march through empty space or recompute depth bounds per pixel, this method first renders the volume's back-face to a depth buffer to establish the ray's exit point, then uses that information in a second pass to march rays from the camera only through the occupied volume [S1, unofficial]. It builds on [Two-pass and Multi-pass Techniques](6224-two-pass-and-multi-pass-techniques.md) by utilizing the light/depth pass to constrain the eye pass's marching range.

## How it works
The method operates in two distinct rendering passes using a `BoxGeometry` representing the volume bounding box.

**Inputs and Outputs:**
*   **Input:** 3D scalar volume data, camera parameters, volume bounding box dimensions ($size_x, size_y, size_z$), number of marching steps ($N_{steps}$), and an opacity correction factor ($\alpha_{corr}$).
*   **Output:** A 2D color image stored in a framebuffer.

**Data Structures:**
1.  **Volume Data Texture (`dataTex`):** A `THREE.DataTexture` (or equivalent 3D/2D array texture) storing the scalar field.
    *   **Layout:** The 1D array of voxel values is padded with zeros to fit a rectangular 2D texture of width $W_{tex} = \min(W_{max}, \text{data.length})$ and height $H_{tex} = \lceil \text{data.length} / W_{tex} \rceil$, where $W_{max}$ is the renderer's maximum texture size [S1, unofficial].
    *   **Format:** `AlphaFormat` (single channel) with `FloatType` precision [S1, unofficial].
2.  **Transfer Function Texture (`transfertTex`):** An 8x256 RGBA texture mapping scalar values to color and opacity [S1, unofficial].
    *   **Layout:** Linear gradient created on a canvas. The x-axis represents the normalized scalar value (0.0 to 1.0), and the y-axis is uniform. Color stops are defined by user-provided positions and colors [S1, unofficial].
    *   **Wrapping:** `ClampToEdgeWrapping` [S1, unofficial].
3.  **Intermediate Render Target (`rtTexture`):** A `WebGLRenderTarget` (or equivalent) storing the depth/position from the first pass.
    *   **Dimensions:** Matches the viewport width and height.
    *   **Format:** `RGBAFormat` with `FloatType` [S1, unofficial].
    *   **Filters:** `LinearFilter` [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Validate that renderer, camera, and volume size are provided [S1, unofficial].
    *   Create a `BoxGeometry` with `doubleSided = true` and dimensions equal to the volume size [S1, unofficial].
    *   Compute or accept `dataMin` and `dataMax` for normalization [S1, unofficial].
    *   Create `rtTexture` with screen dimensions, `FloatType`, `RGBAFormat`, and no mipmaps [S1, unofficial].

2.  **First Pass (Back-Face Depth/Position Pass):**
    *   Create a scene containing the `BoxGeometry` rendered with `BackSide` culling [S1, unofficial].
    *   Render this scene to `rtTexture`.
    *   **Shader Logic:** The fragment shader calculates the intersection of the ray (originating from the camera) with the back face of the box. It writes the world-space position or depth of this intersection point into `rtTexture` [S1, unofficial]. This establishes the exit point ($t_{end}$) for the volume traversal.

3.  **Second Pass (Eye Pass / Ray Marching):**
    *   Render the `BoxGeometry` again, this time with `FrontSide` culling, using the second pass material.
    *   The second pass material samples `rtTexture` to retrieve the exit point calculated in Pass 1.
    *   **Ray Marching Loop:**
        *   For each pixel, cast a ray from the camera origin.
        *   Determine the entry point ($t_{start}$) as the intersection with the front face of the box.
        *   Determine the exit point ($t_{end}$) from `rtTexture` [S1, unofficial].
        *   Iterate $i$ from 0 to $N_{steps}-1$:
            1.  Calculate current ray position: $P_i = P_{origin} + t_i \cdot \vec{d}$, where $t_i = t_{start} + \frac{i + \epsilon}{N_{steps}} (t_{end} - t_{start})$. $\epsilon$ is a small random offset to prevent banding artifacts [S18, unofficial].
            2.  Sample the volume data at $P_i$ from `dataTex`. Normalize the scalar value $d_i$ using `dataMin` and `dataMax`: $v_i = \frac{d_i - dataMin}{dataMax - dataMin}$ [S1, unofficial].
            3.  Lookup color $C_i$ and opacity $\alpha_i$ from `transfertTex` using $v_i$ [S1, unofficial].
            4.  Apply opacity correction: $\alpha_i' = \alpha_i \cdot \alpha_{corr}$ [S1, unofficial].
            5.  Perform front-to-back compositing:
                $$ C'_i = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i' C_i $$
                $$ \alpha'_i = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i' $$
            6.  **Early Ray Termination:** If $\alpha'_i \ge 0.99$ (or 1.0), terminate the loop [S2, S18, unofficial].

4.  **Post-Processing:**
    *   Apply gamma correction (typically 2.2) to the final accumulated color $C'_{N_{steps}}$ [S9, unofficial].

**Pseudocode:**

```python
# Initialization
def init(renderer, camera, size, steps=50, alpha_correction=0.2):
    if renderer is None or camera is None or size is None:
        raise Error("Renderer, camera, and size must be defined")
    
    # Create geometry
    geometry = BoxGeometry(size.x, size.y, size.z)
    geometry.double_sided = True
    
    # Create intermediate buffer
    rt_texture = WebGLRenderTarget(width=window.innerWidth, height=window.innerHeight,
                                   format=RGBAFormat, type=FloatType, 
                                   min_filter=LinearFilter, mag_filter=LinearFilter,
                                   wrap_s=ClampToEdgeWrapping, wrap_t=ClampToEdgeWrapping,
                                   generate_mipmaps=False)
    
    # Prepare volume data texture
    data_min, data_max = compute_min_max(data)
    padded_data = pad_to_rectangular(data, max_texture_size=renderer.capabilities.maxTextureSize)
    data_texture = DataTexture(data=padded_data, format=AlphaFormat, type=FloatType)
    
    # Prepare transfer function texture
    transfer_texture = create_transfer_texture(color_stops, canvas_size=(8, 256))

# First Pass: Render back face to get exit depth/position
def render_first_pass(renderer, scene, camera, rt_texture, geometry, back_face_material):
    renderer.render(scene, camera, rt_texture)

# Second Pass: Ray march from camera to exit point
def render_second_pass(renderer, scene, camera, rt_texture, geometry, front_face_material):
    renderer.render(scene, camera)

# Shader Logic for Second Pass (Fragment Shader)
def fragment_shader_second_pass(uv, uniforms):
    # 1. Get exit point from first pass buffer
    exit_pos = texture2D(uniforms.tex, uv).xyz
    
    # 2. Calculate ray direction and origin
    ray_origin = uniforms.camera_position
    ray_direction = normalize(uniforms.camera_position - uv_to_world_position(uv, uniforms.projection_matrix))
    
    # 3. Calculate entry point (front face intersection)
    # Note: In a box, this is often computed analytically or via a separate depth buffer.
    # Here we assume we have t_start and t_end.
    t_start = compute_front_face_intersection(ray_origin, ray_direction, uniforms.size)
    t_end = length(exit_pos - ray_origin) # Or depth value from rtTexture
    
    # 4. Ray Marching
    accumulated_color = vec3(0.0)
    accumulated_alpha = 0.0
    
    step_size = (t_end - t_start) / uniforms.steps
    
    for i in range(uniforms.steps):
        # Random offset to prevent banding
        offset = random_float() * step_size
        t = t_start + i * step_size + offset
        
        # Clamp to volume bounds
        if t > t_end:
            break
            
        current_pos = ray_origin + ray_direction * t
        
        # 5. Sample Volume
        # Normalize position to [0,1] for texture lookup
        normalized_pos = (current_pos - uniforms.box_min) / (uniforms.box_max - uniforms.box_min)
        scalar_value = texture3D(uniforms.dataTex, normalized_pos).r
        
        # Normalize scalar to [0,1]
        normalized_scalar = clamp((scalar_value - uniforms.minData) / (uniforms.maxData - uniforms.minData), 0.0, 1.0)
        
        # 6. Transfer Function
        color_sample = texture2D(uniforms.transfertTex, vec2(normalized_scalar, 0.5)).rgb
        alpha_sample = texture2D(uniforms.transfertTex, vec2(normalized_scalar, 0.5)).a
        
        # 7. Apply Correction
        alpha_corrected = alpha_sample * uniforms.alphaCorrection
        
        # 8. Composite
        weight = (1.0 - accumulated_alpha) * alpha_corrected
        accumulated_color += weight * color_sample
        accumulated_alpha += weight
        
        # 9. Early Termination
        if accumulated_alpha >= 0.99:
            break
            
    # 10. Gamma Correction
    final_color = pow(accumulated_color, vec3(1.0/2.2))
    
    return final_color
```

## Operating characteristics
*   **Time Complexity:** $O(N_{pixels} \cdot N_{steps})$, where $N_{pixels}$ is the screen resolution and $N_{steps}$ is the number of marching steps per ray [S1, unofficial].
*   **Memory Complexity:** $O(W_{tex} \cdot H_{tex})$ for the volume data texture and $O(W_{screen} \cdot H_{screen})$ for the intermediate render target [S1, unofficial].
*   **Performance:** The number of steps directly impacts FPS; higher steps improve quality but reduce performance [S1, unofficial].
*   **Strengths:** Avoids marching through empty space outside the volume bounds, improving efficiency compared to fixed-length ray casting. Simple to implement on standard WebGL/OpenGL pipelines.
*   **Limitations:** Requires two full render passes. The quality is limited by the fixed number of steps and the resolution of the transfer function texture. Precision issues may arise if `FloatType` is not supported or if the depth buffer lacks sufficient precision for large volumes [S1, unofficial].
*   **When to use:** Suitable for real-time visualization of volumetric data where the volume fits within a bounding box and empty space is significant.
*   **When not to use:** Not suitable for volumes with complex internal structures requiring adaptive step sizes or non-linear traversal, or when hardware does not support `FloatType` render targets.

## Background
The method is implemented in the `INTMeshVolumeRendering` class, part of the WebGLVolumeRendering library by Interactive Network Technologies (authors: Vincent Dumestre, Nathan Krupa) [S1, unofficial]. It leverages standard WebGL features such as `WebGLRenderTarget` and `ShaderMaterial` to achieve the two-pass effect. The technique is a practical application of the general two-pass volume rendering principles, adapted for the Three.js ecosystem [S1, unofficial].
