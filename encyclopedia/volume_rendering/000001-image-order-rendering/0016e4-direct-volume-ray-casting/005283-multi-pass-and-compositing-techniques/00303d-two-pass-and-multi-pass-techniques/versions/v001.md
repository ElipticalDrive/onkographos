# Two-pass and Multi-pass Techniques

Also called: Multi-pass volume rendering, Decoupled volume rendering

## Overview
Two-pass and multi-pass techniques decouple the computation of light attenuation (or depth) from the final color compositing by splitting the volume rendering process into distinct rendering passes [S1, unofficial][S5, book]. This approach solves the problem of efficiently computing accurate volumetric shadows and handling complex lighting interactions without the prohibitive memory cost of storing large 3D volumetric shadow maps or the complexity of full path tracing [S2][S5, book]. It differs from single-pass ray marching by allowing the reuse of intermediate buffers (such as a light transmissivity buffer) and leveraging hardware blending operations (like 'under' blending) to achieve correct front-to-back compositing [S1, unofficial].

## Shared principles
The family relies on the volume rendering integral, discretized into a summation over sample points along a ray [S3, S5, unofficial]. The method separates the rendering workload into at least two distinct stages, typically a "light pass" (or depth pass) and an "eye pass" (or color pass) [S1, unofficial].

In the light pass, the volume is rendered from the light's perspective (or a proxy geometry is used) to accumulate light transmissivity or depth information into a dedicated 2D buffer (Light Buffer or Depth Buffer) [S1, unofficial][S5, book]. This buffer stores the attenuation factor $\tau$ or the exit depth $t_{end}$ for each pixel [S1, unofficial][S5, book].

In the eye pass, the volume is rendered from the camera's perspective. The shader samples the intermediate buffer to retrieve the pre-computed attenuation or depth, which is then used to modulate the final color or constrain the ray marching range [S1, unofficial][S5, book]. The compositing is performed front-to-back [S2, S3, S8, S9, S11, S14, S16, S20, S23, S26, unofficial]. Let $C'_i$ be the accumulated color and $\alpha'_i$ be the accumulated opacity after sample $i$, with initial conditions $C'_0 = 0$ and $\alpha'_0 = 0$ [S9, unofficial]. For each sample $i$ along the ray:
1.  Sample the volume at the current ray position to get a scalar value $d_i$ [S2, S5, unofficial].
2.  Apply a transfer function to map the scalar value to color $C_i$ and opacity $\alpha_i$ [S2, S5, unofficial].
3.  Update accumulated color:
    $$ C'_i = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i $$
4.  Update accumulated opacity:
    $$ \alpha'_i = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i $$
5.  If $\alpha' \ge 1$ or a threshold (typically 0.99) [S2, S18, unofficial], terminate the ray (early ray termination) [S2, S3, S4, unofficial].

Rays are cast from the eyepoint, one for each pixel [S1][S4, unofficial]. The volume is typically represented as a 3D texture [S4, S3, unofficial]. Gradients for shading are calculated using a central difference operator [S6, unofficial]. To avoid normal discontinuities that cause visible rings on smooth surfaces, the gradient is computed using a two-voxel offset rather than a one-voxel offset [S18, unofficial]. Sampling is performed using trilinear interpolation [S1][S5, unofficial]. A fixed random offset is applied to each ray's start position to prevent sample layers from appearing as bands [S18, unofficial]. The final accumulated color is typically corrected with gamma 2.2 [S9, unofficial].

## Subtopics

### [Half-angle slicing](1255-half-angle-slicing.md)
Half-angle slicing is a two-pass per-slice rendering technique for computing volumetric shadows. It orients slice planes perpendicular to the half-angle vector between the eye and light directions, allowing a single slice to be rendered from both viewpoints to compute light attenuation and final color. This method achieves high-resolution shadow map effects without pre-computation or storage, using only a single additional 2D buffer instead of a potentially large 3D volumetric shadow map. It avoids attenuation leakage artifacts (blurry shadows and overly dark surfaces) that occur when view and light directions are perpendicular and a standard 2D shadow buffer is used.

### [Two-pass volume rendering](1292-two-pass-volume-rendering.md)
Two-pass volume rendering decouples light attenuation computation from color compositing by separating the volume rendering process into a light pass and an eye pass. The first pass renders volume slices to accumulate light in a dedicated light buffer, while the second pass composites slices front-to-back using the attenuated light from the light buffer, applying an 'under' blend to accumulate color and opacity. This method differs from single-pass ray marching by allowing efficient reuse of the light buffer and leveraging hardware 'under' blending for front-to-back compositing.

### [Two-Pass Ray Marching Volume Rendering](5965-two-pass-ray-marching-volume-rendering.md)
A two-pass GPU-based volume rendering technique that decouples depth estimation from ray marching to enable accurate front-to-back compositing within a single screen-space quad. It solves the problem of determining the correct entry and exit points of a ray through a volume bounding box without requiring complex ray-box intersection shaders in the final pass. It differs from [Half-angle slicing](1255-half-angle-slicing.md) by using full volumetric ray marching rather than slice accumulation, and from [Two-pass volume rendering](1292-two-pass-volume-rendering.md) by explicitly rendering the back-face depth to a texture to drive the marching range in the second pass.

## Background
The concept of decoupling lighting and shading in volume rendering emerged to address the performance limitations of real-time ray casting. Early implementations focused on slice-based rendering to leverage hardware rasterization [S5, book]. The specific use of half-angle vectors for shadow computation was introduced to mitigate the artifacts associated with standard shadow mapping in volumetric data [S5, book]. Modern implementations often utilize GPU compute shaders or fragment shaders with render targets to achieve these multi-pass effects efficiently [S1, unofficial].
