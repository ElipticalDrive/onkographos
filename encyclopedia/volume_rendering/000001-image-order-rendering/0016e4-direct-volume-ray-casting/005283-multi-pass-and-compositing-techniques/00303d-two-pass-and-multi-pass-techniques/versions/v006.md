# Two-pass and Multi-pass Techniques

Also called: Multi-pass Volume Rendering, Two-Pass Ray Casting

## Overview
Two-pass and multi-pass techniques decompose the volume rendering pipeline into sequential rendering passes, using intermediate 2D textures (render targets) to persist state such as ray boundaries, light attenuation, or contribution counts between stages [G]. This approach solves the limitations of single-pass hardware rasterization by decoupling geometric intersection logic from volumetric integration, or by isolating complex lighting calculations from color compositing, thereby enabling features like accurate volumetric shadows and early ray termination on hardware with limited shader capabilities [G]. It differs from [Image-Order Volumetric Compositing](1390-image-order-volumetric-compositing.md) by explicitly managing state persistence across distinct rasterization events rather than relying on a single continuous fragment shader loop, and from [Compositing and Output Generation](13463-compositing-and-output-generation.md) by structuring the computation into discrete, ordered stages that may involve multiple geometry draws per pixel.

## Shared principles
All methods in this family build on the core loop structure defined in [Image-order rendering](16-image-order-rendering.md) and [Direct volume ray casting](19-direct-volume-ray-casting.md) [G]. The core computational engine is split across $N$ passes ($N \ge 2$), where intermediate results are persisted in 2D textures (render targets) and accessed in subsequent passes [G].

The general mechanism involves:
1. **State Persistence**: Intermediate state (e.g., ray entry/exit points, accumulated light, accumulated color) is written to 2D textures after each pass and read in the next [G].
2. **Decoupling**: Distinct physical or logical operations are isolated into separate passes, such as separating light attenuation from color compositing, or boundary intersection from ray marching integration [G].
3. **Hardware Blending**: Many techniques rely on hardware-supported blending modes (e.g., 'over', 'under', additive) to accumulate values across passes, avoiding the need for complex atomic operations or conditional shader logic [G].
4. **Geometry Proxy**: Slicing or proxy geometry (e.g., slice planes, bounding box faces) is often used to drive the rendering passes, allowing the GPU rasterizer to handle ray intersection logic implicitly [G].

## Subtopics

### [Half-angle slicing](1255-half-angle-slicing.md)
Half-angle slicing is a two-pass per-slice rendering technique that synchronizes the slicing axis with the illumination computation to integrate volumetric lighting, including hard shadows and indirect scattering, within interactive applications. It solves the problem of computing accurate volumetric shadows without the memory overhead of pre-computed 3D shadow maps by orienting slice planes perpendicular to the half-angle vector between the eye and light directions. This orientation allows a single slice to be rendered from both the observer's and the light source's viewpoints, decoupling light transport from data volume resolution. Unlike standard view-aligned slicing, it minimizes the number of slices required to resolve lighting details such as specular highlights and avoids attenuation leakage artifacts common in 2D shadow buffer approaches.

### [Two-pass volume rendering](1292-two-pass-volume-rendering.md)
Two-pass volume rendering is a direct volume ray casting technique that decouples light attenuation computation from color compositing into two distinct rasterization passes. It solves the performance bottleneck of calculating complex illumination for every pixel in real-time by pre-computing light accumulation in a dedicated light buffer during the first pass, then using this data for a fast, real-time rendering pass. It differs from standard direct volume ray casting by moving the expensive light integration step off the critical rendering path, and from single-pass methods by requiring a two-stage data dependency between the light buffer and the frame buffer.

### [Two-Pass Ray Marching Volume Rendering](5965-two-pass-ray-marching-volume-rendering.md)
Two-Pass Ray Marching Volume Rendering is a GPU-based direct volume rendering technique that decouples the determination of ray entry and exit points from the actual volume integration (ray marching). It solves the problem of efficiently computing ray-volume intersections without requiring complex ray-triangle intersection logic in the main rendering pass by rasterizing the volume's bounding box faces into offscreen textures. Unlike single-pass raycasting, which must compute intersections within the fragment shader, this method uses hardware rasterization for boundary detection, reducing fragment shader complexity at the cost of an additional render pass and texture memory overhead.

### [Multi-pass GPU Ray-Casting with Early Ray Termination](7009-multi-pass-gpu-ray-casting-with-early-ray-termination.md)
This method implements direct volume ray casting on DirectX 9-level programmable graphics hardware (specifically Pixel Shader 2.0) by splitting the ray traversal into multiple rendering passes. It solves the performance bottleneck of single-pass ray casting on early GPUs by decoupling ray direction computation, traversal, and termination checking into separate stages, utilizing 2D texture render targets to persist state between passes. Unlike single-pass approaches that require dynamic flow control (available in later shader models), this method relies on hardware early z-testing and fixed-function blending to achieve early ray termination and empty-space skipping, significantly reducing fragment operations for opaque structures or void regions.

### [Locally Adaptive Volume Rendering](13045-locally-adaptive-volume-rendering.md)
Locally Adaptive Volume Rendering (LAVR) is a two-pass technique that enhances feature visibility and reduces noise in volume rendering by dynamically adjusting fragment opacity based on the local density of contributing voxels. Unlike standard direct volume rendering which uses a fixed per-voxel opacity, LAVR decouples the classification of relevant data from the final compositing, allowing the renderer to adaptively suppress noise in sparse regions while preserving sharp borders in dense regions. It sets itself apart from siblings like [Two-pass volume rendering](1292-two-pass-volume-rendering.md) by specifically targeting the statistical distribution of contributions per pixel rather than just splitting light transport or ray marching steps.

#### Multi-pass Stencil Occlusion for Volumetric Light Scattering
- **Definition**: An implementation approach for fixed-function hardware or Shader Model 2.0 limits, using additive frame-buffer blending over multiple passes with a stencil occlusion method [S1, book].
- **Parameter**: Shader Model 3.0 is required for the single-pass version because the number of texture samples needed exceeds the limits of Shader Model 2.0 [S1, book].

#### Anti-Aliased Binary Volume Rendering
- **Definition**: A method to alleviate aliasing in direct rendering of binary volumes by using iterative 3D texture mapping with trilinear interpolation to generate gray level intensity data around surface boundaries [S2].
- **Step**: Render the binary volume using 3D texture mapping, which uses trilinear interpolation for sample points around surface boundaries, generating intensity values between 0 and 1 [S2]. Iteratively repeat the process: Write each texture-mapped slice (without blending) from the frame buffer back to the texture memory as a slice of a refined volume [S2].
- **Parameter**: Iterations: Two or three iterations are normally sufficient for reasonably smooth surfaces, with higher rendering cost for more iterations [S2].

#### Intra-Node Compositing
- **Definition**: Compositing that takes place on the rendering engine. Multi-pass rendering is used. If rendering takes place on the VolumePro 1000 board, it leverages the capability of rendering multiple volumes in a single context with on-board image compositing [S3, unofficial].

#### Multi-Pass Multi-Buffer Transparency
- **Definition**: A technique using a combination of multiple RGBAZ value storage in the frame buffer and multi-pass rendering to yield correct transparency results with minimum performance hit [S4, book].
- **Pitfall**: Storing more than one set of RGBAZ values is costly due to additional memory requirements and is limited by the number of values the hardware can store [S4, book].

#### Multi-Pass Reflection/Refraction
- **Step**: Render the heterogeneous scene (containing both surface and volume objects) twice [S5]. First pass: render from the imaginary eye position [S5]. Second pass: render from the actual eye position [S5]. Combine the results of both passes to accomplish special effects such as reflection and refraction [S5].

## Background
The concept of splitting rendering tasks across multiple passes originated from the need to handle complex lighting and transparency effects on early graphics hardware with limited programmability. Early implementations, such as those for volumetric light scattering, utilized additive frame-buffer blending over multiple passes with stencil occlusion to work around Shader Model 2.0 limitations [S1, book]. The decoupling of ray intersection from integration became prominent with the rise of GPU-based ray casting, where hardware rasterization of bounding boxes provided a robust method for determining ray bounds without complex shader logic [S3, unofficial]. Techniques like half-angle slicing were developed to address specific artifacts in volumetric shadows, such as attenuation leakage, by aligning rendering geometry with light transport vectors . Locally adaptive methods emerged to improve visual quality in sparse data sets by decoupling statistical contribution analysis from final color compositing [S1, book].
