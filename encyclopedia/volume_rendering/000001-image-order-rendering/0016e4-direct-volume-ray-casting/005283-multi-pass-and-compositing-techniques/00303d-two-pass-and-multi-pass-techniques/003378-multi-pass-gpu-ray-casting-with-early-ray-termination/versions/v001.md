# Multi-pass GPU Ray-Casting with Early Ray Termination

Also called: DirectX9 volume ray-casting, GPU-based volume ray-casting, Pixel Shader 2.0 volume ray-casting, Stream model for volume ray-casting on DirectX9-level graphics hardware, Stream programming model for volume ray-casting

## Overview
This method implements direct volume ray casting on DirectX 9-level graphics hardware using the Pixel Shader 2.0 API [S1, unofficial]. It solves the performance bottleneck of per-fragment ray traversal by splitting the workload into multiple rendering passes, utilizing early ray termination and empty-space skipping to reduce texture fetches and arithmetic operations [S1, unofficial]. Unlike single-pass approaches, it decouples ray direction computation and opacity accumulation into distinct stages, allowing the hardware's early Z-test to cull fragments that have already reached opacity saturation or exited the volume [S1, unofficial].

## How it works
The method relies on the volume rendering integral, discretized into a summation over sample points along a ray [S3, S5, unofficial]. The rendering process is divided into four types of passes: entry point determination, ray direction determination, main ray traversal passes, and intermediate stopping criterion passes [S1, unofficial].

### Inputs and Outputs
*   **Input:** A 3D texture representing the volume data.
*   **Output:** A 2D color buffer containing the final rendered image.

### Data Structures
The method uses three 2D textures as render targets, all with the same resolution as the viewport (typically $512 \times 512$) [S1, unofficial]:

1.  **TMP (Texture Memory Position):**
    *   **Format:** 2D RGB texture.
    *   **Content:** Stores the 3D texture coordinates of the first intersection point between the ray of sight and the volume's front faces [S1, unofficial].
2.  **DIR (Direction):**
    *   **Format:** 2D RGBA floating-point texture.
    *   **Content:**
        *   RGB components: The normalized ray direction in local texture coordinates.
        *   A component: The length of the non-normalized direction (ray length within the volume) [S1, unofficial].
3.  **RES (Result):**
    *   **Format:** 2D texture render target.
    *   **Content:** Accumulates the ray-casting result (color and opacity) across main passes. It is accessed and written back in consecutive passes [S1, unofficial].

### Parameters
*   **$M$:** Number of steps along the rays performed in each main pass. Typical value: 8 [S1, unofficial]. This value is restricted by hardware shader limitations [S1, unofficial].
*   **$T$:** Constant threshold for opacity comparison in the intermediate pass to determine early ray termination [S1, unofficial].
*   **$\Delta$:** Step size along the rays of sight [S1, unofficial].

### Algorithm Steps

**Pass 1: Entry Point Determination**
1.  Set depth test to GREATER.
2.  Render the front faces of the volume bounding box to the **TMP** texture.
3.  Issue 3D texture coordinates of each vertex as per-vertex color `COL` [S1, unofficial].
4.  The result is a 2D texture where color components correspond to the first intersection point between rays of sight and the volume in local texture space [S1, unofficial].

**Pass 2: Ray Direction Determination**
1.  Set depth test to GREATER.
2.  Render the back faces of the volume bounding box to the **DIR** texture.
3.  For each fragment, fetch the value from **TMP** (entry point).
4.  Compute the normalized ray direction:
    $$ \vec{d} = \text{normalize}(\text{COL} - \text{TMP}) $$
    where `COL` is the current vertex color (back face intersection) and `TMP` is the entry point [S1, unofficial].
5.  Render $\vec{d}$ to the RGB components of **DIR**.
6.  Render the length of the non-normalized direction ($\|\text{COL} - \text{TMP}\|$) to the A component of **DIR** [S1, unofficial].

**Main Passes 3 to N: Ray Traversal**
These passes accumulate color and opacity. The number of passes $N$ depends on the maximum ray length and $M$.
1.  Set depth test to GREATER.
2.  Render the front faces of the volume bounding box.
3.  Vertex attributes:
    *   Texture Coordinate 1: Normalized device coordinate $(x,y)$ of the vertex. Used to index **DIR** and **RES**.
    *   Per-vertex Color $C$: 3D texture coordinates of the vertex (entry point) [S1, unofficial].
4.  Constants:
    *   $C1 = \Delta$ (step size).
    *   $C2 = \Delta \cdot M \cdot (N - 3)$ (offset for current pass) [S1, unofficial].
5.  Initialize parametric ray equation:
    $$ r(t) = C + t \cdot \text{DIR}[x][y] $$
    where $t$ is initialized to $C2$ [S1, unofficial].
6.  For $i = 0$ to $M-1$:
    a. Increment $t$ by $C1$ ($t \leftarrow t + \Delta$).
    b. Fetch 3D texture value at $r(t)$ to get scalar $d_i$ [S1, unofficial].
    c. Apply transfer function to map $d_i$ to color $C_i$ and opacity $\alpha_i$ [S2, S5, unofficial].
    d. Perform front-to-back compositing using accumulated color $C'_{i-1}$ and opacity $\alpha'_{i-1}$ from **RES**:
       $$ C'_i = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i $$
       $$ \alpha'_i = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i $$
    e. Write $C'_i$ and $\alpha'_i$ back to **RES** [S1, unofficial].
7.  Check if the ray has left the volume (opacity > threshold in **DIR** or $\alpha' \ge 1$). If so, write opacity 1 to **RES** [S1, unofficial].

**Intermediate Passes 3 to N: Stopping Criterion**
Because the early Z-test is disabled when the fragment's Z-value is replaced in the shader, an additional pass is required to enforce termination [S1, unofficial].
1.  Render the front faces.
2.  Shader accesses **RES**$[x][y]$ to get the current accumulated opacity $\alpha'$.
3.  Conditional statement:
    $$ \text{IF}(\alpha' > T) \text{ THEN } z = \text{MAX}, \text{out}(0) $$
    $$ \text{ELSE } z = 0, \text{out}(0) $$
    where $T$ is the threshold [S1, unofficial].
4.  If the ray is terminated, set the Z-buffer to MAX and output zero color/opacity. This prevents subsequent main passes from processing this fragment. Otherwise, the shader has no effect [S1, unofficial].

### Pseudocode
```python
# Pass 1: Entry Point
def pass_1_entry_point():
    set_depth_test(GREATER)
    render_target = TMP
    for vertex in volume_front_faces:
        col = vertex.texture_coordinates_3d
        write_to_2d_texture(TMP, vertex.ndc, col.rgb)

# Pass 2: Ray Direction
def pass_2_ray_direction():
    set_depth_test(GREATER)
    render_target = DIR
    for vertex in volume_back_faces:
        col = vertex.texture_coordinates_3d
        entry_point = read_2d_texture(TMP, vertex.ndc)
        direction_vec = col - entry_point
        normalized_dir = normalize(direction_vec)
        ray_length = length(direction_vec)
        write_to_2d_texture(DIR, vertex.ndc, normalized_dir.rgb, ray_length)

# Main Passes 3 to N
def pass_main_ray_traversal(pass_index, M, delta, N):
    set_depth_test(GREATER)
    render_target = RES
    offset = delta * M * (pass_index - 3)
    
    for vertex in volume_front_faces:
        ndc = vertex.ndc
        entry_point = vertex.texture_coordinates_3d # C
        dir_vec = read_2d_texture(DIR, ndc).rgb
        current_res = read_2d_texture(RES, ndc)
        
        accumulated_color = current_res.color
        accumulated_alpha = current_res.alpha
        
        t = offset
        for step in range(M):
            t += delta
            ray_pos = entry_point + t * dir_vec
            scalar = sample_3d_texture(ray_pos)
            color_i, alpha_i = transfer_function(scalar)
            
            # Front-to-back compositing
            new_color = accumulated_color + (1 - accumulated_alpha) * alpha_i * color_i
            new_alpha = accumulated_alpha + (1 - accumulated_alpha) * alpha_i
            
            accumulated_color = new_color
            accumulated_alpha = new_alpha
            
            if accumulated_alpha >= 1.0:
                break
        
        # Check if ray left volume (simplified check against DIR alpha if needed)
        # If terminated, force alpha to 1
        if accumulated_alpha >= 1.0:
             accumulated_alpha = 1.0
             
        write_to_2d_texture(RES, ndc, accumulated_color, accumulated_alpha)

# Intermediate Passes 3 to N
def pass_intermediate_stopping_criterion(pass_index, threshold):
    set_depth_test(GREATER)
    for vertex in volume_front_faces:
        ndc = vertex.ndc
        res = read_2d_texture(RES, ndc)
        alpha = res.alpha
        
        if alpha > threshold:
            set_z_buffer(vertex, MAX)
            write_color(0, 0, 0)
            write_alpha(0)
        else:
            set_z_buffer(vertex, 0)
            # No effect on color buffer
```

### Edge Cases and Pitfalls
*   **Value of $M$:** If $M$ is small, many fragments outside the volume or void samples may be processed unnecessarily ($M-1$ void samples). If $M$ is large, all rays compute the same number of samples even if shorter, due to the lack of shader discard. The optimal $M$ balances the number of passes against the overhead of rendering front faces and accessing textures [S1, unofficial].
*   **Early Z-Test Disablement:** The early Z-test is disabled as long as the fragment's Z-value is replaced in the shader program. This necessitates the intermediate pass to check the stopping criterion [S1, unofficial].
*   **Gradient Discontinuities:** To avoid normal discontinuities that cause visible rings on smooth surfaces, the gradient is computed using a two-voxel offset rather than a one-voxel offset [S18, unofficial].
*   **Banding:** A fixed random offset is applied to each ray's start position to prevent sample layers from appearing as bands [S18, unofficial].

## Operating characteristics
*   **Time Complexity:** The number of passes is $\lceil K/M \rceil$, where $K$ is the maximum number of steps for the longest ray through the volume. Each pass performs $M$ texture fetches per fragment [S1, unofficial].
*   **Memory Complexity:** Requires three 2D textures (TMP, DIR, RES) of viewport resolution. TMP is RGB, DIR is RGBA floating-point, RES is typically RGBA [S1, unofficial].
*   **Performance:** On an ATI 9700 with a $512 \times 512$ viewport and a $256^3$ MRI Head dataset:
    *   Slice-Based Volume Rendering (SBVR): 7.1 fps [S1, unofficial].
    *   Ray-Casting (RC, no acceleration): 4.8 fps [S1, unofficial].
    *   RC with Early Termination (RC-$\alpha$): 14.4 fps [S1, unofficial].
    *   RC with Early Termination and Empty-Space Skipping (RC-$\beta$): 23.4 fps [S1, unofficial].
    *   Other datasets (Aneurism, Foot, Engine) showed similar improvements with RC-$\beta$ [S1, unofficial].
*   **Strengths:** Reduces fragment operations for opaque structures or empty space. Provides equal sampling density along rays compared to object-order projection. Significantly faster than previous texture-based approaches for many real-world datasets [S1, unofficial].
*   **Limitations:** Requires multiple passes and texture lookups. The intermediate pass adds overhead. Shader limitations restrict $M$ to small values (e.g., 8) [S1, unofficial].

## Background
The method was described in a paper presenting a framework using the DirectX 9 SDK (Microsoft, 2002) and references prior work such as Cullip and Neumann (1993), Levoy (1990), and Purcell et al. (2002) [S1, unofficial]. It is part of the stream programming model for volume ray-casting on DirectX 9-level graphics hardware [S1, unofficial].
