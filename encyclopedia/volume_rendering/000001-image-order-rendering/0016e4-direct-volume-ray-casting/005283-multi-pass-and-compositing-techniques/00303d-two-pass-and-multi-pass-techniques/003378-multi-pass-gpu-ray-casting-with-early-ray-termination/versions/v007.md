# Multi-pass GPU Ray-Casting with Early Ray Termination

Also called: Multi-pass GPU Ray Casting, Multi-pass GPU Raycaster with Early Ray Termination, Multi-pass GPU Ray-Casting with Early Ray Termination and Empty Space Skipping

## Overview
Multi-pass GPU Ray-Casting is a stream-based rendering technique that implements direct volume ray casting by splitting the ray traversal loop across multiple rendering passes, using 2D texture render targets to persist intermediate ray state [S1, S3, unofficial]. It solves the limitation of early GPU hardware (specifically Pixel Shader 2.0 era) which lacked dynamic flow control, preventing single-pass ray marchers from terminating rays early [S3, unofficial]. By decoupling ray integration from termination checks, it achieves significant performance gains over unaccelerated ray casting and slice-based volume rendering (SBVR) through early ray termination and empty-space skipping [S1, unofficial].

## How it works
The method relies on the shared principles of the [Two-pass and Multi-pass Techniques](6224-two-pass-and-multi-pass-techniques.md) family [G]. It uses a sequence of passes to compute ray entry points, ray directions, and accumulated volume integration, separated by intermediate passes that enforce stopping criteria via the early Z-test [S1, S3, unofficial].

### Inputs and Outputs
*   **Input:** 3D volume texture $V$, transfer function (implicit in empty-space lookup), view matrix, projection matrix.
*   **Output:** 2D color/opacity texture (final image).

### Data Structures
The method requires several 2D and 3D textures. All 2D textures match the viewport resolution (e.g., $512 \times 512$) [S1, S3, unofficial].

1.  **TMP (Entry Point Texture):**
    *   **Layout:** 2D RGB texture.
    *   **Content:** Stores the 3D texture coordinates $(u, v, w)$ of the first intersection point between the ray of sight and the front faces of the volume bounding box [S1, S3, unofficial].
    *   **Encoding:** Vertex colors of the front faces are set to their 3D texture coordinates [S1, unofficial].

2.  **DIR (Ray Direction Texture):**
    *   **Layout:** 2D RGBA floating-point texture [S1, unofficial].
    *   **Content:**
        *   RGB components: Normalized ray direction vector in local texture coordinates [S1, S3, unofficial].
        *   Alpha component: Length of the non-normalized direction vector (ray length within the volume) [S1, unofficial].
    *   **Encoding:** Computed by subtracting TMP coordinates from back-face texture coordinates [S3, unofficial].

3.  **RES (Accumulation Texture):**
    *   **Layout:** 2D texture render target [S1, unofficial].
    *   **Content:** Accumulated color and opacity from previous ray-marching steps [S1, unofficial].

4.  **Skip Volume (Empty Space Acceleration):**
    *   **Layout:** 3D texture [S3, unofficial].
    *   **Content:** Each texel stores a 2D vector $(r, g)$ representing the minimum and maximum values of an $8 \times 8 \times 8$ block of the original volume data [S3, unofficial]. The volume is sampled down to $1/8$ in every dimension [S3, unofficial].

5.  **Empty Lookup Texture:**
    *   **Layout:** 2D texture [S3, unofficial].
    *   **Content:** Lookup table where $Lookup(x, y) = 1$ if all values between $x$ and $y$ in the skip-volume are 0 under the current transfer function; otherwise 0 [S3, unofficial].

### Numbered Steps

**Pass 1: Entry Point Determination**
1.  Set depth test to `GREATER`.
2.  Render the front faces of the volume bounding box.
3.  Issue 3D texture coordinates of each vertex as per-vertex color $C_{in}$ [S1, S3, unofficial].
4.  Write the fragment color to **TMP** [S1, unofficial]. This stores the entry point in local texture coordinates [S3, unofficial].

**Pass 2: Ray Direction Determination**
1.  Set depth test to `GREATER`.
2.  Render the back faces of the volume bounding box.
3.  For each fragment, fetch the entry point $P_{entry}$ from **TMP** using the fragment's texture coordinates [S1, S3, unofficial].
4.  Let $P_{back}$ be the 3D texture coordinates of the current back-face vertex (passed as per-vertex color) [S1, unofficial].
5.  Compute the non-normalized direction $D_{raw} = P_{back} - P_{entry}$ [S3, unofficial].
6.  Compute normalized direction $D_{norm} = \text{normalize}(D_{raw})$ [S1, unofficial].
7.  Write $D_{norm}$ to the RGB components and $\|D_{raw}\|$ to the Alpha component of **DIR** [S1, unofficial].

**Main Passes 3 to N: Ray Traversal**
These passes perform the actual volume integration. Let $M$ be the number of steps per pass (typically 8) [S1, unofficial]. Let $N$ be the total number of main passes required to traverse the longest ray.

1.  Set depth test to `GREATER`.
2.  Render the front faces of the volume bounding box.
3.  Vertex attributes:
    *   Texture Coordinate 1: Normalized Device Coordinates (NDC) $(x, y)$ to index **DIR** and **RES** [S1, unofficial].
    *   Per-vertex Color $C$: 3D texture coordinates of the front face (same as Pass 1) [S1, unofficial].
4.  Fragment Shader Logic:
    *   Fetch entry point $P_{entry} = \text{tex2D}(\text{TMP}, \text{NDC})$ [S3, unofficial].
    *   Fetch direction $D = \text{tex2D}(\text{DIR}, \text{NDC})$ [S3, unofficial].
    *   Fetch accumulated result $R_{prev} = \text{tex2D}(\text{RES}, \text{NDC})$ [S1, unofficial].
    *   Initialize parametric ray equation $r(t) = P_{entry} + t \cdot D$ [S1, unofficial].
    *   The parameter $t$ is incremented by step size $\Delta$ for $M$ steps [S1, unofficial].
    *   For $i = 0$ to $M-1$:
        *   Compute volume coordinate $V_{coord} = P_{entry} + (t + i \cdot \Delta) \cdot D$ [S3, unofficial].
        *   Sample volume: $S = \text{tex3D}(V, V_{coord})$ [S1, unofficial].
        *   Integrate using "over" compositing: $R_{curr} = \text{under}(S, R_{prev})$ [S3, unofficial].
        *   Update $R_{prev} = R_{curr}$ [S3, unofficial].
    *   Write $R_{curr}$ to **RES** [S1, unofficial].
    *   If the ray has left the volume (opacity > threshold), write opacity 1 to **RES** [S1, unofficial].

**Intermediate Passes 3 to N: Stopping Criterion**
Executed after every Main Pass to enable early Z-test acceleration [S1, S3, unofficial].

1.  Set depth test to `GREATER`.
2.  Render the front faces of the volume bounding box.
3.  Fragment Shader Logic:
    *   Fetch last accumulated value $R_{last} = \text{tex2D}(\text{RES}, \text{NDC})$ [S3, unofficial].
    *   Fetch direction $D = \text{tex2D}(\text{DIR}, \text{NDC})$ [S3, unofficial].
    *   Fetch entry point $P_{entry} = \text{tex2D}(\text{TMP}, \text{NDC})$ [S3, unofficial].
    *   Compute current volume coordinate $V_{coord} = P_{entry} + \text{Depth} \cdot D$ [S3, unofficial].
    *   **Empty Space Check:**
        *   Fetch min/max from Skip Volume: $MinMax = \text{tex3D}(\text{SkipVolume}, V_{coord})$ [S3, unofficial].
        *   Lookup emptiness: $E = \text{tex2D}(\text{EmptyLookup}, MinMax)$ [S3, unofficial].
    *   **Termination Logic:**
        *   If $R_{last}.a < 0.9999$ AND $E < 1$ (ray not terminated and not empty):
            *   Output Depth $= 0$ (resume rendering) [S3, unofficial].
        *   Else:
            *   Output Depth $= 100$ (discard subsequent fragments) [S3, unofficial].
            *   Output Color $= R_{last}$ (pass through last frame's color) [S3, unofficial].
    *   Formula:
        $$ \text{OUT.depth} = ((R_{last}.a < 0.9999) \land (E < 1)) ? 0 : 100 $$
        $$ \text{OUT.col} = R_{last} $$

### Parameters
*   **M (Steps per pass):** Number of ray steps performed in each main pass. Typical value: 8 [S1, unofficial]. Restricted by hardware shader limitations [S1, unofficial].
*   **T (Opacity Threshold):** Constant threshold for early ray termination. If accumulated opacity $> T$, the ray is terminated [S1, unofficial].
*   **Viewport Resolution:** Typically $512 \times 512$ [S1, unofficial].

### Edge Cases and Pitfalls
*   **Early Z-Test Restrictions:** On hardware of the era (Pixel Shader 2.0), the early Z-test is disabled if the Z-value is replaced in the shader, or if `clip`/`texkill` is used [S1, S3, unofficial]. This necessitates the separate intermediate pass [S3, unofficial].
*   **Step Size M:** If $M$ is small, many fragments outside the volume or void samples may be processed unnecessarily (up to $M-1$ void samples per ray) [S1, unofficial]. If $M$ is large, all rays compute the same number of samples even if shorter, due to the lack of shader discard [S1, unofficial].
*   **Shader Discard:** Fragment shaders cannot terminate themselves dynamically in this model; termination is enforced via the Z-buffer in the intermediate pass [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M \cdot W \cdot H)$, where $N$ is the number of main passes, $M$ is steps per pass, and $W \times H$ is viewport resolution. The number of passes $N \approx K/M$, where $K$ is the max ray length in samples [S1, unofficial].
*   **Memory Complexity:** Requires storage for TMP, DIR, RES, SkipVolume, and EmptyLookup textures. TMP, DIR, RES are $W \times H$ [S1, unofficial]. SkipVolume is $1/8$ volume size [S3, unofficial].
*   **Performance:** On an ATI Radeon 9800 Pro (Pixel Shader 2.0), for a $512^3$ MRI Head dataset at $512 \times 512$ viewport:
    *   Slice-Based Volume Rendering (SBVR): 7.1 fps [S1, unofficial].
    *   Ray Casting (RC) without acceleration: 4.8 fps [S1, unofficial].
    *   RC with Early Ray Termination (RC-$\alpha$): 14.4 fps [S1, unofficial].
    *   RC with Early Ray Termination and Empty-Space Skipping (RC-$\beta$): 23.4 fps [S1, unofficial].
    *   Other datasets (Aneurism, Foot, Engine) showed similar trends, with RC-$\beta$ significantly outperforming SBVR and unaccelerated RC [S1, unofficial].
*   **Strengths:** Reduces fragment operations for opaque structures and empty space. Provides equal sampling density along rays compared to object-order methods [S1, unofficial].
*   **Limitations:** Requires multiple passes and texture lookups. Overhead from intermediate passes. $M$ is constrained by hardware (typically 8) [S1, unofficial].

## Background
The method was described in a framework using the DirectX 9 SDK (Microsoft, 2002) and programmable via the Pixel Shader 2.0 API [S1, unofficial]. It builds on prior work such as Cullip and Neumann (1993), Levoy (1990), and Purcell et al. (2002) [S1, unofficial]. The approach was developed to leverage the data-parallel nature of fragment units on recent chips (at the time) while minimizing fragment operations [S1, unofficial]. It was demonstrated on hardware like the ATI Radeon 9800 Pro running Windows XP [S3, unofficial].
