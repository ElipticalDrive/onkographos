# Incremental Blending for In-scattering

Also called: Incremental In-scattering Blending

## Overview
Incremental Blending for In-scattering is a method for approximating volumetric light scattering (in-scattering) in direct volume rendering by accumulating scattered light contributions from multiple directions into a single stored intensity buffer. It solves the problem of efficiently computing the integral of scattered light over a sphere of directions without storing per-direction results, by blending new directional samples into a running average. It differs from [Lighting-Specific Compositing](5940-lighting-specific-compositing.md) by specifically targeting the in-scattering term $I_s$ and using a harmonic mean update strategy, and from [Incremental Lighting for In-Scattering](3401-incremental-lighting-for-in-scattering.md) by lacking the per-channel indirect attenuation and blur operations that allow light color to change with depth.

## How it works
The method discretizes the scattering sphere into $J$ directions and updates the stored in-scattering intensity $I_{stored}$ incrementally for each direction $j$.

**Inputs and Outputs:**
- Input: Volume data (opacity $\alpha$, color $c$), transfer function domain, light source direction, number of scattering directions $J$.
- Output: A volume buffer storing the accumulated in-scattering intensity $I_{stored}$ for each voxel.

**Data Structures:**
- $I_{stored}$: A 3D volume buffer (same resolution as the volume data or a reduced resolution SVR) storing the scalar intensity value for each voxel.
- $I_{final}$: A temporary scalar value computed for the current direction $j$ and voxel.

**Parameters:**
- $I_{bias}$: A parameter in the range $[0, 1]$ adjusting the minimum light level. Default behavior assumes a white light source. [S1]
- $J$: The total number of directions used to discretize the scattering sphere. [S1]

**Formulas:**
The eye-space intensity $I_{eye}$ is computed as a Riemann sum:
$$I_{eye} = \sum_{k=0}^n g_k \prod_{p=0}^{k-1} (1 - \alpha(s_p)) \quad (12)$$
where $g_k$ is the emitted color at sample $k$, $\alpha(s_p)$ is opacity, and $n$ is the total number of samples along the ray. [S1]

The term $g_k$ is defined as:
$$g_k = I_{final} \cdot c(s_k) \cdot \alpha(s_k)$$
where $c(s_k)$ is the color from the transfer function at sample point $s_k$, and $I_{final}$ is the in-scattering contribution for the current direction:
$$I_{final} = I_{bias} + (1 - I_{bias}) \cdot I_s(s_k)$$
Here, $I_s(s_k)$ is the scattered intensity at sample $s_k$. [S1]

The incremental blending step updates the stored intensity for direction $j$ (where $j$ ranges from 1 to $J$):
$$I_{blended} = \frac{1}{j} \cdot I_{final} + \left(1 - \frac{1}{j}\right) \cdot I_{stored} \quad (13)$$
where $I_{blended}$ is the new value to store, $I_{final}$ is the result from the current direction $j$, and $I_{stored}$ is the previously accumulated intensity. [S1]

**Steps:**
1. Initialize the $I_{stored}$ volume buffer to zero or an appropriate initial value. [G]
2. Compute the direction of the light source first to ensure shadows are correctly approximated. [S1]
3. Determine the subsequent $J-1$ directions of the scattering sphere by subdividing a tetrahedron, icosahedron, or octahedron to achieve the desired number of rays $J$. [S1]
4. For each incremental update step $j$ from 1 to $J$:
    a. For each voxel (or sample point $s_k$ along the ray), compute $I_{final}$ using the current direction's scattered intensity $I_s(s_k)$ and the bias parameter $I_{bias}$.
    b. Compute the blended intensity $I_{blended}$ using Eq. 13:
       $$I_{blended} = \frac{1}{j} \cdot I_{final} + \left(1 - \frac{1}{j}\right) \cdot I_{stored}$$
    c. Store $I_{blended}$ as the new $I_{stored}$ for that voxel.
5. Use the final $I_{stored}$ values in the compositing equation (Eq. 12) to compute the final eye-space intensity $I_{eye}$.

**Pseudocode:**
```python
def incremental_blending_in_scattering(volume, transfer_function, light_direction, J, I_bias):
    """
    volume: 3D array of opacity alpha and color c
    transfer_function: function to map density to color c and opacity alpha
    light_direction: vector for the primary light source
    J: number of scattering directions
    I_bias: minimum light level parameter [0, 1]
    """
    # Initialize stored intensity buffer
    # Resolution may be reduced (SVR) to save space [S1]
    I_stored = zeros_like(volume.opacity)
    
    # Compute scattering directions
    # Subdivide tetrahedron, icosahedron, or octahedron to get J directions [S1]
    scattering_directions = compute_sphere_sampling(J, light_direction)
    
    for j, direction in enumerate(scattering_directions, start=1):
        # Compute scattered intensity I_s for this direction
        # This requires ray casting through the volume for each voxel or sample
        # I_s depends on the specific light propagation model [S1]
        I_s = compute_scattered_intensity(volume, direction, transfer_function)
        
        # Compute I_final for each voxel
        # I_final = I_bias + (1 - I_bias) * I_s
        I_final = I_bias + (1.0 - I_bias) * I_s
        
        # Incremental blend
        # I_blended = (1/j) * I_final + (1 - 1/j) * I_stored
        weight_new = 1.0 / j
        weight_old = 1.0 - weight_new
        I_stored = weight_new * I_final + weight_old * I_stored
        
    return I_stored
```

**Edge Cases and Pitfalls:**
- **Memory Usage:** The method generates large amounts of data if computed at full resolution. For a $512^3$ volume, three additional $512^3$ volumes are needed to store intermediate results ($\alpha l_p$, $\alpha g$, $I_{final}$). It is recommended to reduce the resolution of the SVR (Sparse Voxel Representation) to mitigate this. [S1]
- **Precision:** The blending formula involves division by $j$. For large $J$, the contribution of new samples becomes small. Standard floating-point precision should be sufficient, but accumulation errors may occur over many steps. [G]
- **Boundary Conditions:** Rays originating in empty blocks (black squares) in a multi-resolution structure should be advanced to the next nonempty block to avoid incorrect sampling. [S1]

## Subtopics

### [Incremental Lighting for In-Scattering](3401-incremental-lighting-for-in-scattering.md)
Incremental Lighting for In-Scattering is a screen-space technique that approximates volumetric light scattering (translucency) by propagating and blurring indirect lighting components across volume slices. It extends the base Incremental Blending for In-scattering method by introducing per-channel indirect attenuation parameters and a blur operation, allowing light to change color as it penetrates deeper into the volume, similar to the effect of holding a flashlight under a hand. Choose this when color attenuation with depth is critical.

### [Hardware Blending Recurrence Evaluation](5317-hardware-blending-recurrence-evaluation.md)
Hardware Blending Recurrence Evaluation is a technique for evaluating the multiple forward scattering recurrence $I_k = g_{k-1} + T_{k-1} I_{k-1}$ by mapping the mathematical operation to GPU hardware blending and pixel read-back operations. It solves the problem of efficiently computing the incident light on a particle in a participating medium by leveraging the frame buffer as an accumulator. It differs from [Incremental Lighting for In-Scattering](3401-incremental-lighting-for-in-scattering.md) by using explicit pixel read-back to resolve the recurrence dependency, whereas its sibling uses a different accumulation strategy. Choose this when hardware blending capabilities can be exploited for recurrence evaluation.

## Operating characteristics
- **Time Complexity:** $O(J \cdot N)$, where $J$ is the number of scattering directions and $N$ is the number of voxels or samples. Each direction requires a full pass over the volume. [S1]
- **Memory Complexity:** $O(N)$ for the $I_{stored}$ buffer. Additional temporary buffers may be required for intermediate computations ($\alpha l_p$, $\alpha g$, $I_{final}$), potentially tripling the memory requirement if computed at full resolution. [S1]
- **Measured Performance:** Not given in the sources.
- **Scaling:** Performance scales linearly with the number of scattering directions $J$ and the volume resolution. Reducing the SVR resolution can significantly reduce memory and computation time. [S1]
- **Strengths:** Efficiently approximates in-scattering without storing per-direction results. Simple incremental update rule. [S1]
- **Limitations:** High memory usage if not using reduced resolution. Assumes white light source by default (though easily extended to colored light). [S1]
- **When to use:** When real-time or interactive global light propagation is needed in direct volume rendering. [S1]
- **When not to use:** When high-fidelity color attenuation with depth is required (use [Incremental Lighting for In-Scattering](3401-incremental-lighting-for-in-scattering.md) instead).

## Background
The method originates from the paper "Interactive Global Light Propagation in Direct Volume Rendering using Local Piecewise Integration" by [S1]. It is part of a broader effort to incorporate global illumination effects, specifically in-scattering, into interactive volume rendering systems. The approach uses local piecewise integration to approximate the light propagation within the volume.
