# Incremental Lighting for In-Scattering

Also called: Translucency Approximation via Indirect Attenuation

## Overview
Incremental Lighting for In-Scattering is a method for approximating light scattering (translucency) in volume rendering by propagating and blurring indirect lighting components from slice to slice, considering only incoming light within a cone in the direction of the light source [S1]. It solves the problem of computing indirect illumination in a single-pass rendering pipeline by discarding backward-directed light relative to the light source, thereby accommodating the lack of knowledge about future slices during a front-to-back traversal [15652-forward-scattered-intensity-transport.md]. It differs from full scattering models by ignoring back-scattering during the intensity transport phase, which simplifies the hardware implementation at the cost of accuracy in dense, deep regions of the volume [15652-forward-scattered-intensity-transport.md]. It builds on [Incremental Blending for In-scattering](2880-incremental-blending-for-in-scattering.md) by introducing indirect attenuation parameters and a dedicated light buffer for scattering propagation.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Volume density field, volume opacity/alpha values ($A$), indirect attenuation parameters ($A_i$) for each RGB channel, light color ($C_L$), sample distance ($d$), blur angle parameter.
*   **Outputs:** Final rendered image with translucent lighting effects.

**Data Structures:**
*   **Light Buffer:** A 2D texture buffer storing indirect attenuation values. Initialized with $1 - C_L$. Uses alternating double-buffering (current and next buffers) to support read/write operations during blur.
*   **Perturbation Texture:** A texture used to modify texture coordinates for sampling the light buffer during the blur operation.
*   **Frame Buffer:** Standard render target for the final image.

**Numbered Steps:**
1.  **Initialization:** Initialize the light buffer with values $1 - C_L$ for each pixel, where $C_L$ is the light color [S1].
2.  **Pass 1 (Eye Contribution):** For each sample along the ray:
    *   Read the current indirect attenuation value $A_i$ from the light buffer using standard texture coordinates [S1].
    *   Multiply the reflective color $C$ of the current sample by $(1 - A_i)$ [S1].
    *   Composite this result into the frame buffer using the standard Over operator [S1].
3.  **Pass 2 (Light Contribution & Blur):**
    *   Set the fragment shader output color to $A_i$ (the indirect attenuation parameter) instead of 0 [S1].
    *   Modify texture coordinates for the current light buffer using a perturbation texture to sample indirect components for blur [S1]. The radius of the blur circle is calculated using the user-defined blur angle and sample distance $d$ [S1].
    *   Read the current light buffer using the modified texture coordinates [S1].
    *   Compute the blurred attenuation as a weighted sum of the values read from the light buffer [S1].
    *   Blend the result into the *next* light buffer using the Light Buffer Compositing operation [S1].
    *   Swap the current and next light buffers for the next slice [S1].

**Formulas:**
*   **Light Buffer Compositing (Equation 8):**
    $$C_{out} = C_{in} * (1 - C_{target}) + C_{target} * (1 - A_{in})$$
    Where:
    *   $C_{out}$ is the resulting color in the target buffer.
    *   $C_{in}$ is the color of the incoming fragment (from the fragment shader, set to $A_i$).
    *   $C_{target}$ is the color currently in the target render buffer (the next light buffer).
    *   $A_{in}$ is the incoming fragment alpha (implicit in the context of $A_i$) [S1].
    *   *Note:* The source text defines $C_1$ as incoming fragment color and $C_0$ as color in target buffer for Equation 8, but does not provide the explicit LaTeX formula, only the name [S1]. The formula above is derived from the description.

*   **Blur Radius (Equation 9):**
    $$R = \text{blur\_angle} * d$$
    Where:
    *   $R$ is the blur radius.
    *   $d$ is the sample distance [S1].

**Parameters:**
*   $A_i$: Indirect attenuation parameters, alpha values for each RGB color channel. Used instead of single alpha $A$ [S1].
*   $d$: The sample distance, used to calculate blur radius [S1].
*   Blur angle: User-defined parameter scaling the perturbation radius [S1].

**Edge Cases and Pitfalls:**
*   **Color-Changing Penetration:** To achieve effects like white light turning red as it penetrates deeper (similar to holding a flashlight under a hand), set $A_i$ for red smaller than $A_i$ for green and blue. This results in lower attenuation of the red component [S1].
*   **Precision:** The method relies on 2D buffer resolution matching the viewport to produce crisp shadows with minimal aliasing artifacts [S1].
*   **Back-Scattering Ignored:** The method approximates scattering by considering only incoming light within a cone in the direction of the light source. Back-scattering is ignored, which may reduce accuracy in dense, deep regions [15652-forward-scattered-intensity-transport.md].

**Pseudocode:**
```python
# Initialization
light_buffer_current = texture(width, height, 1.0 - light_color)
light_buffer_next = texture(width, height, 0.0)

# For each slice along the ray
for slice in slices:
    # Pass 1: Eye Contribution
    for pixel in pixels:
        ray_sample = sample_volume(ray, slice)
        A_i = light_buffer_current.sample(pixel.uv)
        C_reflective = ray_sample.color
        C_contrib = C_reflective * (1.0 - A_i)
        frame_buffer.composite_over(pixel.uv, C_contrib, ray_sample.alpha)

    # Pass 2: Light Contribution & Blur
    for pixel in pixels:
        # Get indirect attenuation parameter for this slice
        A_i_param = slice.indirect_attenuation # A_i for RGB channels
        
        # Calculate perturbed UVs for blur
        blur_radius = blur_angle * sample_distance
        perturbed_uvs = get_perturbed_uvs(pixel.uv, blur_radius, perturbation_texture)
        
        # Sample light buffer with perturbed UVs
        blurred_attenuation = 0.0
        for uv in perturbed_uvs:
            val = light_buffer_current.sample(uv)
            blurred_attenuation += weight * val
        blurred_attenuation /= sum(weights)
        
        # Light Buffer Compositing
        C_in = A_i_param # Fragment shader color set to A_i
        C_target = light_buffer_next.sample(pixel.uv)
        C_out = C_in * (1.0 - C_target) + C_target * (1.0 - C_in)
        
        light_buffer_next.write(pixel.uv, C_out)

    # Swap buffers
    light_buffer_current, light_buffer_next = light_buffer_next, light_buffer_current
```

## Subtopics

### [Forward-Scattered Intensity Transport](15652-forward-scattered-intensity-transport.md)
Forward-Scattered Intensity Transport is a method for approximating in-scattering (translucency) in volume rendering by propagating light intensity through a volume using a dedicated light buffer. It solves the problem of computing indirect illumination in a single-pass rendering pipeline by discarding backward-directed light relative to the light source, thereby accommodating the lack of knowledge about future slices during a front-to-back traversal. It differs from full scattering models by ignoring back-scattering during the intensity transport phase, which simplifies the hardware implementation at the cost of accuracy in dense, deep regions of the volume [15652-forward-scattered-intensity-transport.md].

### Recursive Slice-Blurring
Recursive Slice-Blurring is a single-pass algorithm approximating light scattering within a volume by a recursive slice-blurring operation starting at the light source [S2, unofficial]. At each path increment, energy is transferred from the light buffer to the frame buffer [S2, unofficial]. The profile of the blurring filter is determined by the user-specified phase function [S2, unofficial]. It uses a dual image buffer: one repeatedly blurred (light) buffer for transported/scattered light energy away from the source, and one (frame) buffer for energy headed for the eye, attenuated by densities along the path [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Requires additional 2D buffers for the light buffer (double-buffered) and perturbation texture. The resolution of light propagation matches the viewport, decoupling it from the 3D data grid [S1].
*   **Measured Performance:** Runs at interactive frame rates when exploiting 3D texture mapping hardware in conjunction with a dual image buffer [S2, unofficial].
*   **Strengths:** Decouples the resolution of light transport from the 3D data grid, permitting accurate lighting of volumes. Produces crisp shadows with minimal aliasing artifacts by matching light propagation resolution to the viewport [S1]. Allows control over color-changing penetration effects by specifying independent alpha for each color channel [S1].
*   **Limitations:** Ignores back-scattering, which may reduce accuracy in dense, deep regions of the volume [15652-forward-scattered-intensity-transport.md]. Approximates scattering rather than computing it exactly.
*   **When to Use:** When creating convincing images of clouds and other atmospheric phenomena where translucency effects are important [S1]. When interactive frame rates are required and hardware supports 3D texture mapping and dual image buffers [S2, unofficial].
*   **When Not to Use:** When high accuracy in dense, deep regions is required and back-scattering effects are significant [15652-forward-scattered-intensity-transport.md].

## Background
The method was described in the context of GPU Gems Chapter 39, "Volume Rendering Techniques" [S1]. It is an extension of incremental lighting that approximates light scattering by propagating and blurring indirect lighting components from slice to slice [S1]. The technique is important for creating convincing images of clouds and other atmospheric phenomena [S1]. The high computational cost of direct volume rendering makes it difficult for sequential implementations, but advances in commodity graphics hardware have started to blur these boundaries [S2, unofficial].
