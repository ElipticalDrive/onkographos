# Forward-Scattered Intensity Transport

Also called: Light Buffer Intensity Calculation

## Overview
Forward-Scattered Intensity Transport calculates light intensity in a dedicated light buffer by transporting forward-scattered light from slice to slice, discarding backward-directed light to accommodate single-pass rendering [S1]. It solves the problem of computing indirect illumination in a single-pass pipeline by ignoring back-scattering during the intensity transport phase, which simplifies hardware implementation at the cost of accuracy in dense, deep volume regions [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume density $\alpha(\vec{s})$, light direction $\vec{m}_{\Omega_{lt}}$, sampling step size $\Delta$, and the expected number of scattering events $n(\vec{s})$ at position $\vec{s}$ [S1].
*   **Output:** Updated light intensity $I(\vec{s} + \vec{m}_{\Omega_{lt}}\Delta)$ and the scattering event count for the next slice, stored in the light buffer [S1].

**Data Structures:**
1.  **Light Buffer:** A texture storing two components per sample: the RGB channel holds light intensity $I(\vec{s})$, and the alpha channel stores the number of scattering events $n(\vec{s}_f + i\vec{m}_\Omega\Delta)$ [S1].
2.  **Phase Function Texture:** Floating-point textures store high-dynamic range multiple scattering phase functions $A^{ms}_\lambda^i(\Omega)$ for all particles with up to 26 convolutions at a resolution of approximately 0.18 degrees [S1]. The pre-computed forward-scattered factors $F_i^\lambda$ are also stored in this texture, as the light distribution is considered essentially isotropic after 26 convolutions [S1].

**Parameters:**
*   $\beta_{\lambda ex}$: Expected number of scattering events per unit distance for wavelength $\lambda$ [S1].
*   $\Delta$: Step size between sampling slices [S1].
*   $T(\vec{s}_1, \vec{s}_2)$: Transmittance from $\vec{s}_1$ to $\vec{s}_2$ [S1].

**Method Steps:**

1.  **Calculate Forward-Scattered Contribution ($F_i^\lambda$):** For each scattering event $i$, compute the integral of the phase function over the forward hemisphere relative to the light direction, discarding backward-directed light to ensure single-pass compatibility [S1].
    $$F_i^\lambda = \int_{\text{forward hemisphere}} A^{ms}_\lambda^i(\Omega) d\Omega \quad (23)$$
    These values are pre-computed and stored in the phase function texture [S1].

2.  **Retrieve Current State:** Sample the light buffer at the previous slice position $\vec{s}$ to retrieve the current intensity $I(\vec{s})$ and the accumulated scattering count $n(\vec{s})$ [S1].

3.  **Compute Transmittance:** Calculate the transmittance $T(\vec{s}, \vec{s} + \vec{m}_{\Omega_{lt}}\Delta)$ from the current sample to the next sample along the light direction [S1].

4.  **Update Intensity (Hardware-Efficient Approximation):** The exact discrete intensity update involves a product over the range of scattering events, which is impractical for graphics hardware [S1]. Instead, use the worst-case attenuation approximation using a single convolution index to avoid linear interpolation of floating-point textures, which was unavailable on the target hardware [S1].
    $$I(\vec{s} + \vec{m}_{\Omega_{lt}}\Delta) = I(\vec{s})T(\vec{s}, \vec{s} + \vec{m}_{\Omega_{lt}}\Delta) + I(\vec{s})(1 - T(\vec{s}, \vec{s} + \vec{m}_{\Omega_{lt}}\Delta)) \alpha(\vec{s}) F_{\lfloor n(\vec{s}) + 1 + \beta_{\lambda ex}\Delta \rfloor}^\lambda \quad (25)$$
    Where $\alpha(\vec{s})$ is the density/scattering coefficient at $\vec{s}$, and the index $\lfloor n(\vec{s}) + 1 + \beta_{\lambda ex}\Delta \rfloor$ determines which pre-computed $F$ factor to use [S1].

5.  **Update Scattering Count:** Increment the scattering event count for the next slice by the expected number of scattering events over the step $\Delta$ [S1].

6.  **Store Results:** Write the new intensity $I(\vec{s} + \vec{m}_{\Omega_{lt}}\Delta)$ to the RGB channel and the new scattering count to the Alpha channel of the light buffer at the next slice position [S1].

**Pseudocode:**

```python
import math

def forward_scattered_intensity_transport(
    light_buffer, 
    phase_function_texture, 
    current_pos, 
    light_direction, 
    step_size, 
    beta_lambda_ex,
    alpha_density
):
    """
    Updates light intensity and scattering count for the next slice.
    
    Args:
        light_buffer: Texture containing intensity (RGB) and scattering count (A).
        phase_function_texture: Texture containing pre-computed F factors.
        current_pos: Current sample position vector.
        light_direction: Normalized vector pointing towards the light source.
        step_size: Distance to the next sample.
        beta_lambda_ex: Expected scattering events per unit distance.
        alpha_density: Density/scattering coefficient at current_pos.
        
    Returns:
        next_intensity: Float, the updated light intensity.
        next_scattering_count: Int, the updated number of scattering events.
    """
    
    # 1. Retrieve current state from light buffer
    current_intensity = light_buffer.sample(current_pos).rgb
    current_scattering_count = light_buffer.sample(current_pos).a
    
    # 2. Calculate next position
    next_pos = current_pos + light_direction * step_size
    
    # 3. Compute transmittance (standard exponential attenuation) [G]
    transmittance = math.exp(-alpha_density * step_size)
    
    # 4. Determine the index for the F factor (Equation 25)
    f_index = math.floor(current_scattering_count + 1.0 + beta_lambda_ex * step_size)
    
    # 5. Retrieve the pre-computed forward-scattered factor F_i^lambda
    f_factor = phase_function_texture.sample_f_factor(f_index)
    
    # 6. Apply the intensity update formula (Equation 25)
    next_intensity = (
        current_intensity * transmittance + 
        current_intensity * (1.0 - transmittance) * alpha_density * f_factor
    )
    
    # 7. Update scattering count
    next_scattering_count = current_scattering_count + math.floor(beta_lambda_ex * step_size)
    
    return next_intensity, next_scattering_count
```

**Edge Cases and Pitfalls:**
*   **Linear Interpolation:** Linear interpolation is not available for floating-point textures on the target hardware, necessitating the worst-case attenuation approximation (Equation 25) instead of interpolating between scattering events [S1].
*   **Backward Light:** Backward-directed light is discarded during intensity transport because phase functions have weak back-scattered components and the system performs a single slicing pass without knowledge of future slices [S1]. This approximation introduces errors that increase with the number of scattering events, making it least accurate in dense inner regions of the cloud [S1].
*   **Final Gather:** While backward light is discarded during transport, light may still be backscattered towards the eye in the final gather step, where the angular distribution function for one more scattering event is applied [S1].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of sampling slices along the ray, as the method performs a single pass through the volume [S1].
*   **Memory Complexity:** Requires storage for the light buffer (intensity + scattering count) and the phase function texture (high-dynamic range, up to 26 convolutions) [S1].
*   **Performance:** The method achieves real-time performance (e.g., 3.0 fps for 512×512 resolution with 256 sampling planes) on the target hardware [S1].
*   **Strengths:** Enables single-pass rendering of atmospheric phenomena (rainbows, halos, glory, aerial perspective) with reasonable accuracy in optically thin regions and for the first few scattering events [S1].
*   **Limitations:** Accuracy degrades in dense, deep regions of the volume due to the approximation of backward light and the use of worst-case attenuation, with error increasing alongside the number of scattering events [S1].

## Background
Forward-Scattered Intensity Transport was introduced in "Efficient Rendering of Atmospheric Phenomena" [S1]. It is part of a system designed to capture essential optical effects in the atmosphere, such as rainbows, halos, the glory, and sunrise/sunset effects [S1]. The method was developed to address the limitations of previous techniques in handling multiple scattering and angular distribution efficiently on graphics hardware [S1].
