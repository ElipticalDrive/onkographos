# Accumulation-level intermixing

Also called: Accumulation-level intermixing of two datasets, Multi-modal Rendering with Data Intermixing

## Overview
Accumulation-level intermixing is a multi-modal rendering technique that resolves the depth ordering artifacts inherent in image-level intermixing by combining ray samples from multiple co-registered volumes at every step along the viewing ray [S1, unofficial]. Unlike image-level compositing, which blends final pixel colors and thus loses spatial precedence, this method preserves the physical depth relationships of the distinct datasets by integrating their optical properties during the ray-marching accumulation process [S1, unofficial].

## How it works
**Inputs:** Two or more co-registered volume datasets (e.g., CT and MRI) and their associated transfer functions mapping scalar values to color and opacity.
**Outputs:** A single composite image where depth ordering is preserved.

**Data Structures:**
*   **Ray State:** Accumulated color $C_{acc}$ (RGB), accumulated opacity $\alpha_{acc}$ (scalar).
*   **Sample State:** Per-volume sample color $c_i$, sample opacity $\alpha_i$.

**Steps:**
1.  **Ray Marching:** For each pixel, cast a ray through the volume space.
2.  **Sampling:** At each step $j$ along the ray, sample the scalar value $v_i$ from each volume $i$ (e.g., $v_{CT}, v_{MRI}$).
3.  **Transfer Function Lookup:** Compute the color $c_i$ and opacity $\alpha_i$ for each volume's sample using its specific transfer function.
    *   *Note:* For multi-channel data, gradients may be computed in perceptual spaces (e.g., $L^*u^*v^*$) to determine opacity [S2, book].
4.  **Mixing Function Application:** Combine the per-volume samples $(c_i, \alpha_i)$ into a single effective sample $(c_{mix}, \alpha_{mix})$ using a mixing function.
    *   *Intensity Comparison:* In some implementations, color is assigned based on the relative intensity of the datasets (e.g., blue if $CT > MRI$, green if $MRI > CT$) [S2, book].
    *   *Inclusive Opacity Mode:* A common mixing strategy for two volumes is the inclusive opacity model, where the combined opacity is derived from the unweighted product of individual opacities:
        $$ \alpha_{mix} = 1 - (1 - \alpha_{CT})(1 - \alpha_{MRI}) $$
        This is equivalent to the probability that at least one volume contributes to the sample [S2, book].
5.  **Accumulation:** Update the ray state using standard volume rendering compositing equations with the mixed sample:
    $$ C_{acc} = C_{acc} + c_{mix} \cdot \alpha_{mix} \cdot (1 - \alpha_{acc}) $$
    $$ \alpha_{acc} = \alpha_{acc} + \alpha_{mix} \cdot (1 - \alpha_{acc}) $$
6.  **Termination:** Repeat until the ray exits the volume or $\alpha_{acc}$ exceeds a threshold.

**Pseudocode:**
```python
def accumulation_level_intermixing(ray_origin, ray_direction, volumes, transfer_functions):
    # Initialize accumulation state
    acc_color = [0.0, 0.0, 0.0]
    acc_alpha = 0.0
    
    # Ray marching parameters
    step_size = 1.0
    num_steps = 100 # Placeholder for actual ray length calculation
    
    for step in range(num_steps):
        # 1. Sample positions
        pos = ray_origin + ray_direction * (step * step_size)
        
        # 2. Sample volumes and get per-volume properties
        samples = []
        for vol in volumes:
            val = vol.sample(pos)
            color, alpha = transfer_functions[vol.id].lookup(val)
            samples.append({'color': color, 'alpha': alpha, 'value': val})
            
        # 3. Mix samples
        # Example: Inclusive opacity mode for two volumes (CT, MRI)
        if len(samples) == 2:
            ct = samples[0]
            mri = samples[1]
            
            # Compute mixed opacity using inclusive model
            # alpha_mix = 1 - (1 - alpha_CT) * (1 - alpha_MRI)
            alpha_mix = 1.0 - (1.0 - ct['alpha']) * (1.0 - mri['alpha'])
            
            # Compute mixed color
            # Note: Specific color mixing logic (e.g., intensity comparison) 
            # is implementation-dependent. Here we assume a weighted average 
            # based on the inclusive probability contribution.
            # Weight of CT contribution relative to total alpha_mix:
            w_ct = (ct['alpha'] * (1.0 - mri['alpha'])) / alpha_mix if alpha_mix > 0 else 0
            w_mri = (mri['alpha'] * (1.0 - ct['alpha'])) / alpha_mix if alpha_mix > 0 else 0
            
            color_mix = [
                w_ct * ct['color'][0] + w_mri * mri['color'][0],
                w_ct * ct['color'][1] + w_mri * mri['color'][1],
                w_ct * ct['color'][2] + w_mri * mri['color'][2]
            ]
        else:
            # Fallback for other numbers of volumes or specific mixing rules
            # Not fully specified in sources [G]
            alpha_mix = samples[0]['alpha']
            color_mix = samples[0]['color']
            
        # 4. Accumulate
        # Standard front-to-back compositing
        contribution = color_mix * alpha_mix * (1.0 - acc_alpha)
        acc_color = [
            acc_color[0] + contribution[0],
            acc_color[1] + contribution[1],
            acc_color[2] + contribution[2]
        ]
        acc_alpha = acc_alpha + alpha_mix * (1.0 - acc_alpha)
        
        if acc_alpha >= 0.99:
            break
            
    return acc_color
```

**Parameters:**
*   **Mixing Function:** The specific formula used to combine $(c_i, \alpha_i)$. The "inclusive opacity mode" is a standard choice for preserving depth without occlusion [S2, book].
*   **Gradient Space:** For multi-channel data, gradients may be computed in $L^*u^*v^*$ space using the second derivative along the gradient direction to compute opacity [S2, book].

**Edge Cases:**
*   **Zero Opacity:** If both volumes have zero opacity at a step, the mixed opacity is zero, and no color contribution occurs.
*   **Degenerate Input:** If volumes are not co-registered, the intermixing will produce spatially misaligned artifacts.

## Subtopics

### [Illumination model level intermixing](13581-illumination-model-level-intermixing.md)
Combines ray samples *before* color/opacity computation, treating combined density as a single physical entity. Chosen when distinct physical properties (e.g., emission vs. attenuation) need to interact physically prior to lighting.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot V)$, where $N$ is the number of pixels and $V$ is the number of volumes. Each ray step requires sampling and transferring all volumes.
*   **Memory Complexity:** $O(V \cdot R)$, where $R$ is the ray length in steps. Requires storing intermediate samples for all volumes per step.
*   **Strengths:** Preserves depth ordering of multi-modal data; allows physically motivated mixing (e.g., SPECT emission within CT attenuation) [S1, unofficial].
*   **Limitations:** Computationally more expensive than image-level intermixing due to per-step mixing logic; requires precise co-registration.

## Background
Originating from multi-modal visualization research, this method addresses the limitations of image-level intermixing where depth ordering is lost [S1, unofficial]. It was notably demonstrated in the context of radiation therapy dose planning and the visualization of the Visible Man's CT and MRI datasets [S2, book]. Cai and Sakas [25] (cited in [S1, unofficial]) applied this to visualize emissive metabolic activities within attenuation volumes.
