# Multi-volume rendering
Also called: Multiple Volume Display
## Overview
Multi-volume rendering refers to rendering multiple co-registered volumes at once by evaluating each sample along a viewing ray for all channels currently visible [S1, unofficial]. It enables the simultaneous display of multiple deformed volumes using standard proxy geometries [S2]. It is distinguished from single-volume rendering by its ability to intermix data sources, and from image-level compositing by its preservation of depth ordering through per-sample combination [S1, S3, unofficial].
## How it works
Multi-volume rendering operates by passing multiple volume textures to the fragment shader and combining their contributions during the ray-marching process [S2]. The method is categorized into three intermixing levels based on when the combination occurs: classification-level, accumulation-level, and image-level [S1, S3, unofficial].

### Inputs and Outputs
*   **Inputs:** $N$ co-registered volume textures $V_1, \dots, V_N$ [S2]. A viewing ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ [G].
*   **Outputs:** A final pixel color and opacity.

### Data Structures
*   **Volume Textures:** $N$ 3D textures (or proxy geometry textures) storing the scalar fields [S2].
*   **Ray Sample State:** At each step $t$ along the ray, the method retrieves values $v_i = \text{sample}(V_i, \mathbf{r}(t))$ for all $i \in \{1, \dots, N\}$ [S1, unofficial].

### Steps and Formulas
1.  **Classification-Level Intermixing:** At each ray sample, the sampled values of two channels are linearly interpolated using a weighting factor $\omega$ (e.g., $\omega = 0.5$) to form $v_{\text{combined}} = \omega v_1 + (1-\omega) v_2$, then an illumination model is evaluated on $v_{\text{combined}}$ [S1, unofficial].
2.  **Accumulation-Level Intermixing:** The illumination model is separately evaluated for each channel at each ray sample, producing per-channel color and opacity, which are then combined using a mixing function (e.g., sum, difference, or emitted color mixing) [S1, unofficial][S2].
3.  **Image-Level Intermixing:** A complete image is rendered for each channel as a scalar dataset, then the final images are mixed using alpha blending or a weighting function that may incorporate the z-buffer or opacity channel [S1, S3, unofficial].

### Parameters
*   **Weighting factor $\omega$:** Controls the blend ratio in classification-level intermixing; typical value $\omega = 0.5$ [S1, unofficial].
*   **Channel count $n$:** Number of channels stored per octree brick in out-of-core implementations; implementation-defined (e.g., $n=4$) and fixed at runtime [S1, unofficial].

### Pitfalls and Edge Cases
*   **Depth Ordering:** Image-level intermixing cannot handle occlusions between different channels correctly due to missing depth information in the accumulated intermediate results [S1, unofficial].
*   **Proxy Geometry Overlap:** Proxy geometry samples cannot overlap; techniques adapting tessellation based on deformation must find a tessellation satisfying all volumes [S2].
*   **Performance:** Accumulation-level intermixing is more flexible but computationally more expensive than classification-level [S1, unofficial].
*   **Implementation Limits:** In out-of-core approaches using octrees, the number of channels $n$ stored in brick-cache entries is implementation-defined and cannot be changed at run-time [S1, unofficial].

## Subtopics

### Classification-level intermixing
Combines raw data values using a weighting factor before evaluating the illumination model [S1, unofficial]. It sets itself apart from accumulation-level by computing lighting on blended data rather than separate lighting, and from image-level by operating per-sample rather than per-image [S3, unofficial]. Choose it when computational cost must be minimized at the expense of accurate per-volume lighting [S3, unofficial].

### [Accumulation-level intermixing](13575-accumulation-level-intermixing.md)
Accumulation-level intermixing is a multi-modal volume rendering technique that resolves the depth-ordering artifacts inherent in image-level intermixing by combining ray samples from multiple co-registered volumes at every step along the viewing ray. Unlike image-level compositing, which blends final pixel colors and thus fails to preserve the correct occlusion relationships between distinct datasets, this method integrates physical properties (colors and opacities) from each volume's sample before the final accumulation, ensuring that the relative density and opacity of the constituent volumes are correctly composited. It is distinguished from its sibling [Illumination model level intermixing](13581-illumination-model-level-intermixing.md) by applying separate lighting models to each volume's sample before combination, whereas illumination-level intermixing merges raw data values prior to any lighting calculation.

### Image-level intermixing
Renders each volume separately as a scalar dataset and blends the final images using a weighting function that may include the z-buffer or opacity channel [S3, unofficial]. It sets itself apart by operating on complete rendered images rather than per-ray samples, making it the simplest to implement but failing to preserve correct occlusion relationships between distinct datasets [S1, S3, unofficial]. Choose it only for simple visual overlays where depth accuracy is not required [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Exact asymptotic complexity is not given in the sources. Relative complexity is noted: accumulation-level intermixing is computationally more expensive than classification-level [S1, unofficial].
*   **Memory Complexity:** Requires storing $N$ volume textures or proxy geometry textures in GPU memory [S2]. In out-of-core octree approaches, brick caches must store $n$ channels per entry, where $n$ is implementation-defined (e.g., $n=4$) and fixed at runtime [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths:** Allows visualization of multi-modal data; accumulation-level preserves depth cues and correct occlusion relationships [S1, S3, unofficial].
*   **Limitations:** Image-level lacks depth accuracy; accumulation-level is expensive; proxy geometry requires consistent adaptive tessellation for deformed volumes [S2].
*   **When to use:** Use classification-level for performance-critical applications where per-sample lighting accuracy is secondary [S3, unofficial]. Use accumulation-level when correct depth ordering and occlusion between distinct datasets are required [S1, S3, unofficial]. Avoid image-level for complex multi-modal interactions due to lost depth cues [S3, unofficial].

## Background
Multi-volume rendering was formalized by Schubert and Scholl [SS11], who differentiated between classification, accumulation, and image-level intermixing [S1, unofficial]. Brix et al. [BPH14] extended this to out-of-core rendering using octrees, storing up to $n$ channels per brick [S1, unofficial]. The concept of "Multiple Volume Display" using proxy geometries was explored by [S2] to handle deformed volumes. The Stony Brook overview [S3, unofficial] provides a foundational classification of these mixing techniques.
