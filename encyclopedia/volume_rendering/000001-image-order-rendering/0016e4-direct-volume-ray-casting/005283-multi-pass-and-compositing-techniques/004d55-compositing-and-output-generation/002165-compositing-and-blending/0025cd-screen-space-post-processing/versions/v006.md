# Screen-space Post-processing

Also called: Composite Shader, Compositing/Processing Pipeline, Screen Post-Processing

## Overview
Screen-space post-processing is a full-screen rendering pass that applies aspect-ratio preserving UV covering, luminance-based bright passes, color grading, underwater RGB channel splitting, cross-shaped bloom, 17-tap box blur, and 1-LSB dithering to a scene texture [S1, unofficial]. It differs from [Compositing](2436-compositing.md) by operating on the final rendered image rather than accumulating volume samples along rays [S1, unofficial].

## How it works
**Inputs and Outputs:**
* **Input:** A scene texture (typically the result of the opaque and transparent rendering passes), screen dimensions, and uniform parameters [S1, unofficial].
* **Output:** A final color buffer for display [S1, unofficial].

**Data Structures:**
The method relies on a uniform buffer containing camera and environment state, and vertex attributes for a full-screen quad [S1, unofficial].
* **Uniforms Struct:** `view_proj` (`mat4x4<f32>`), `inv_view_proj` (`mat4x4<f32>`), `camera_pos` (`vec3<f32>`), `time` (`f32`), `sun_position` (`vec3<f32>`), `is_underwater` (`f32`), `screen_size` (`vec2<f32>`), `water_level` (`f32`), `moon_position` (`vec3<f32>`), `moon_intensity` (`f32`), `wind_dir_x` (`f32`), `wind_dir_z` (`f32`), `wind_speed` (`f32`), `rain_factor` (`f32`), `sky_visibility` (`f32`), `menu_blur` (`f32`), `texture_size` (`vec2<f32>`), `_pad_uniforms` (`f32`) [S1, unofficial].
* **Vertex Attributes:** `positions` (`array<vec2<f32>, 3>` = `{(-1.0, -1.0), (3.0, -1.0), (-1.0, 3.0)}`), `uvs` (`array<vec2<f32>, 3>` = `{(0.0, 1.0), (2.0, 1.0), (0.0, -1.0)}`) [S1, unofficial].

**Parameters:**
* `menu_blur`: `f32`, controls blur intensity and vignette softening. Clamped to `[0.0, 1.0]` in the fragment shader [S1, unofficial].
* `is_underwater`: `f32`, enables RGB channel splitting refraction when `> 0.5` and `blur < 0.5` [S1, unofficial].

**Steps:**
The fragment shader processes each pixel of the full-screen quad [S1, unofficial]. The order of operations is:
1. **UV Covering:** Adjust UVs to preserve aspect ratio if the texture and screen dimensions differ [S1, unofficial].
    * Compute `texture_aspect = texture_size.x / max(texture_size.y, 1.0)` [S1, unofficial].
    * Compute `screen_aspect = screen_size.x / max(screen_size.y, 1.0)` [S1, unofficial].
    * If `screen_aspect > texture_aspect`: `covered.y = 0.5 + (uv.y - 0.5) * (texture_aspect / screen_aspect)` [S1, unofficial].
    * Else: `covered.x = 0.5 + (uv.x - 0.5) * (screen_aspect / texture_aspect)` [S1, unofficial].
    * Use `covered` as the UV coordinate for subsequent texture sampling [S1, unofficial].
2. **Luminance Calculation:** `luma = dot(color, vec3(0.2126, 0.7152, 0.0722))` [S1, unofficial].
3. **Bright Pass:** `weight = smoothstep(0.68, 0.96, luminance(color))`; `output = color * weight` [S1, unofficial].
4. **Underwater Refraction (Conditional):** If `is_underwater > 0.5` and `blur < 0.5`:
    * Compute `radial = (sample_uv - vec2(0.5)) * 1.6` [S1, unofficial].
    * Compute `shift = radial * texel * (1.2 + 0.25 * sin(time * 0.8))` [S1, unofficial].
    * `color.r = sample_scene(sample_uv + shift).r` [S1, unofficial].
    * `color.b = sample_scene(sample_uv - shift).b` [S1, unofficial].
    * `color = mix(color, color * vec3(0.83, 0.96, 1.08), 0.28)` [S1, unofficial].
5. **Cross-Shaped Bloom:**
    * `bloom_radius = texel * 3.25` [S1, unofficial].
    * `bloom = bright_pass(color) * 0.28` [S1, unofficial].
    * Add 4 neighbors at `±bloom_radius.x/y` with weight `0.18` each [S1, unofficial].
    * `color += bloom * mix(0.105, 0.025, blur)` [S1, unofficial].
6. **17-Tap Box Blur (Conditional):** If `blur > 0.001`:
    * `blurred = color * 0.08` [S1, unofficial].
    * Add neighbors at `texel * (±4,0), (0,±4)` weight `0.08` [S1, unofficial].
    * Add neighbors at `texel * (±5.5, ±5.5)` weight `0.07` [S1, unofficial].
    * Add neighbors at `texel * (±10,0), (0,±10)` weight `0.05` [S1, unofficial].
    * Add neighbors at `texel * (±14, ±14)` weight `0.03` [S1, unofficial].
    * `color = mix(color, blurred * 0.82, blur)` [S1, unofficial].
7. **Vignette:**
    * `centered = uv * 2.0 - 1.0` [S1, unofficial].
    * `centered.x *= screen_size.x / max(screen_size.y, 1.0)` [S1, unofficial].
    * `vignette = 1.0 - smoothstep(0.42, 1.82, dot(centered, centered)) * mix(0.045, 0.025, blur)` [S1, unofficial].
    * `output = clamp(color * vignette, vec3(0.0), vec3(1.0))` [S1, unofficial].
8. **Dithering:**
    * `pixel = floor(uv * max(screen_size, vec2(1.0)))` [S1, unofficial].
    * `hash = fract(sin(dot(pixel, vec2(12.9898, 78.233))) * 43758.5453)` [S1, unofficial].
    * `dither = (hash - 0.5) / 255.0` [S1, unofficial].
    * `color = clamp(color + vec3(dither), vec3(0.0), vec3(1.0))` [S1, unofficial].

**Pseudocode:**

```python
def sample_texture(texture, uv):
    # Standard texture lookup operation
    return texture[uv]

def screen_space_post_processing(uv, scene_texture, uniforms):
    # 1. UV Covering
    texture_aspect = uniforms.texture_size.x / max(uniforms.texture_size.y, 1.0)
    screen_aspect = uniforms.screen_size.x / max(uniforms.screen_size.y, 1.0)
    covered_uv = uv
    if screen_aspect > texture_aspect:
        covered_uv.y = 0.5 + (uv.y - 0.5) * (texture_aspect / screen_aspect)
    else:
        covered_uv.x = 0.5 + (uv.x - 0.5) * (screen_aspect / texture_aspect)
        
    color = sample_texture(scene_texture, covered_uv)
    texel = vec2(1.0) / uniforms.screen_size
    
    # 2. Luminance
    luma = dot(color, vec3(0.2126, 0.7152, 0.0722))
    
    # 3. Bright Pass
    weight = smoothstep(0.68, 0.96, luma)
    bright_pass_color = color * weight
    
    # 4. Underwater Refraction
    blur = uniforms.menu_blur
    if uniforms.is_underwater > 0.5 and blur < 0.5:
        radial = (covered_uv - vec2(0.5)) * 1.6
        shift = radial * texel * (1.2 + 0.25 * sin(uniforms.time * 0.8))
        r_val = sample_texture(scene_texture, covered_uv + shift).r
        b_val = sample_texture(scene_texture, covered_uv - shift).b
        color.r = r_val
        color.b = b_val
        color = mix(color, color * vec3(0.83, 0.96, 1.08), 0.28)
        
    # 5. Cross-Shaped Bloom
    bloom_radius = texel * 3.25
    bloom = bright_pass_color * 0.28
    bloom += sample_texture(scene_texture, covered_uv + vec2(bloom_radius.x, 0.0)) * 0.18
    bloom += sample_texture(scene_texture, covered_uv + vec2(-bloom_radius.x, 0.0)) * 0.18
    bloom += sample_texture(scene_texture, covered_uv + vec2(0.0, bloom_radius.y)) * 0.18
    bloom += sample_texture(scene_texture, covered_uv + vec2(0.0, -bloom_radius.y)) * 0.18
    
    bloom_final = bloom * mix(0.105, 0.025, blur)
    color += bloom_final
    
    # 6. 17-Tap Box Blur
    if blur > 0.001:
        blurred = color * 0.08
        blurred += sample_texture(scene_texture, covered_uv + vec2(4.0, 0.0) * texel) * 0.08
        blurred += sample_texture(scene_texture, covered_uv + vec2(-4.0, 0.0) * texel) * 0.08
        blurred += sample_texture(scene_texture, covered_uv + vec2(0.0, 4.0) * texel) * 0.08
        blurred += sample_texture(scene_texture, covered_uv + vec2(0.0, -4.0) * texel) * 0.08
        blurred += sample_texture(scene_texture, covered_uv + vec2(5.5, 5.5) * texel) * 0.07
        blurred += sample_texture(scene_texture, covered_uv + vec2(5.5, -5.5) * texel) * 0.07
        blurred += sample_texture(scene_texture, covered_uv + vec2(-5.5, 5.5) * texel) * 0.07
        blurred += sample_texture(scene_texture, covered_uv + vec2(-5.5, -5.5) * texel) * 0.07
        blurred += sample_texture(scene_texture, covered_uv + vec2(10.0, 0.0) * texel) * 0.05
        blurred += sample_texture(scene_texture, covered_uv + vec2(-10.0, 0.0) * texel) * 0.05
        blurred += sample_texture(scene_texture, covered_uv + vec2(0.0, 10.0) * texel) * 0.05
        blurred += sample_texture(scene_texture, covered_uv + vec2(0.0, -10.0) * texel) * 0.05
        blurred += sample_texture(scene_texture, covered_uv + vec2(14.0, 14.0) * texel) * 0.03
        blurred += sample_texture(scene_texture, covered_uv + vec2(14.0, -14.0) * texel) * 0.03
        blurred += sample_texture(scene_texture, covered_uv + vec2(-14.0, 14.0) * texel) * 0.03
        blurred += sample_texture(scene_texture, covered_uv + vec2(-14.0, -14.0) * texel) * 0.03
        
        color = mix(color, blurred * 0.82, blur)
        
    # 7. Vignette
    centered = uv * 2.0 - 1.0
    centered.x *= uniforms.screen_size.x / max(uniforms.screen_size.y, 1.0)
    vignette = 1.0 - smoothstep(0.42, 1.82, dot(centered, centered)) * mix(0.045, 0.025, blur)
    color = clamp(color * vignette, vec3(0.0), vec3(1.0))
    
    # 8. Dithering
    pixel = floor(uv * max(uniforms.screen_size, vec2(1.0)))
    hash_val = fract(sin(dot(pixel, vec2(12.9898, 78.233))) * 43758.5453)
    dither = (hash_val - 0.5) / 255.0
    color = clamp(color + vec3(dither), vec3(0.0), vec3(1.0))
    
    return color
```

## Subtopics

### [Cloud Compositing & Tone Mapping](3628-cloud-compositing-tone-mapping.md)
This method composites pre-resolved volumetric cloud data with a procedural sky and ground background, then applies tone mapping and gamma correction to produce a final displayable image. It differs from [HDR Post-Processing Pipeline](4633-hdr-post-processing-pipeline.md) by handling spatial cloud-background interaction (horizon culling, procedural sky/ground generation) rather than global image adjustments, and from [Bloom](4906-bloom.md) by focusing on radiance compositing rather than luminance-based glow.

### [HDR Post-Processing Pipeline](4633-hdr-post-processing-pipeline.md)
A 16-bit floating-point HDR rendering pipeline for scene post-processing. It sets itself apart from sibling methods like [Cloud Compositing & Tone Mapping](3628-cloud-compositing-tone-mapping.md) by integrating bloom and chromatic distortion directly into the tone-mapping fragment shader rather than using separate library passes, and from [Bloom](4906-bloom.md) by handling the bloom compositing within the same pass as tone mapping.

### [Bloom](4906-bloom.md)
Bloom is a screen-space post-processing effect that enhances the perception of brightness by isolating luminous regions via a soft threshold, blurring them across a pyramid of scales, and adding the result back to the original image. It differs from direct compositing methods by operating entirely in screen space on the final display image rather than during ray traversal.

### [Tilt-Shift Post-Processing](6901-tilt-shift-post-processing.md)
Tilt-Shift Post-Processing is a screen-space effect that simulates the shallow depth-of-field of a miniature model by keeping a horizontal band of the frame sharp while applying increasing Gaussian blur to areas above and below it, accompanied by increased color saturation. It distinguishes itself from general blur effects by its spatially varying strength profile (sharp band with falloff) and its specific aesthetic goal of mimicking macro photography of large-scale scenes. It is typically applied after the main scene render but before UI elements to ensure menus and text remain crisp.

#### Bilateral Upsampling and Dual-Source Blending
A post-processing step to upscale and blend volumetric lighting results with the scene, using bilateral upsampling for resolution enhancement and dual-source blending for attenuation [S2, unofficial]. It is particularly helpful at 1/4 resolution [S2, unofficial]. The process involves performing bilateral upsampling on the resolved accumulation buffer, additively blending the resolved/filtered output with the scene, and using dual-source blending to attenuate the result based on medium density and depth [S2, unofficial].

#### Frustum Raycasting and Blending
A post-processing step that casts rays from the camera through each pixel, intersects them with a cloud volume bounding box, and blends the resulting cloud color with the original scene color [S3, unofficial]. It differs from general screen-space effects by performing ray-box intersection in screen space to determine cloud visibility [S3, unofficial]. The steps are: sample the original scene color; set ray origin to camera world position; normalize ray direction; calculate ray-box intersection with cloud volume bounds; if intersection exists, march density to get cloud color; return `lerp(originalColour, cloudColour, cloudColour.a)`; if no intersection, return original color [S3, unofficial]. The frustum corners are calculated in C# using `Camera.CalculateFrustumCorners` and passed to the shader [S3, unofficial].

## Operating characteristics
* **Time Complexity:** O(1) per pixel, as it involves a fixed number of texture samples and arithmetic operations. The 17-tap blur and cross-shaped bloom involve a constant number of samples (17 + 4 = 21 samples per pixel in the worst case) [S1, unofficial].
* **Memory Complexity:** O(1) auxiliary memory, requiring only the input scene texture and output buffer [S1, unofficial].
* **Performance:** The method is lightweight and suitable for real-time rendering. The conditional execution of underwater refraction and blur allows for optimization based on scene state [S1, unofficial].
* **Strengths:** Provides immediate visual feedback, supports complex effects like refraction and bloom without requiring volumetric data, and is easily adjustable via uniforms [S1, unofficial].
* **Limitations:** Effects are limited to screen space; objects not rendered to the scene texture are not affected [S1, unofficial].

## Background
The method is implemented in the Minerust project, a voxel-based game engine using wgpu [S1, unofficial]. It is part of the full-screen composite stage, which also includes underwater fog and color grading [S1, unofficial]. The specific implementation details, including the 17-tap blur and cross-shaped bloom, are derived from the project's rendering code [S1, unofficial].
