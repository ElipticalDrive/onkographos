# Frustum Raycasting and Blending

Also called: FragmentProgram, OnRenderImage

## Overview
Frustum Raycasting and Blending is a screen-space post-processing technique that casts rays from the camera through each pixel, intersects them with a cloud volume bounding box, and blends the resulting cloud color with the original scene color [S1, unofficial]. It operates as a full-screen fragment shader pass that runs after the main scene render [S1, unofficial].

## How it works
**Inputs and Outputs:** The shader receives the scene texture (`_MainTex`), UV coordinates (`input.uv`), camera world position (`_CameraWorldPosition`), cloud volume bounds (`_CloudVolumeMinBound`, `_CloudVolumeMaxBound`), and frustum corners (`_FrustumCornerTR`, `_FrustumCornerBR`) [S1, unofficial]. The C# script additionally passes the density threshold, scatter factor, and wind offset [S1, unofficial]. The output is the final blended color for each fragment [S1, unofficial].

**Data Structures:** Positions, directions, and bounds use `Vector3` types [S1, unofficial]. UV coordinates use `Vector2` types [S1, unofficial]. Distances, color components, and thresholds use `float` types [S1, unofficial].

**Steps:** First, the shader samples the original scene color from `_MainTex` using the fragment's UV coordinates [S1, unofficial]. Second, it sets the ray origin to the camera's world position `_CameraWorldPosition` [S1, unofficial]. Third, it calculates the ray direction vector from the camera to the current pixel and normalizes it [S1, unofficial]. Fourth, it calculates the ray-box intersection of the ray $(O, D)$ with the axis-aligned bounding box defined by `_CloudVolumeMinBound` and `_CloudVolumeMaxBound`, returning entry distance $t_{entry}$ and exit distance $t_{exit}$ [S1, unofficial]. Fifth, if $t_{entry} < t_{exit}$, it marches along the ray segment $[t_{entry}, t_{exit}]$ to sample the cloud density and compute the cloud color [S1, unofficial]. Sixth, if an intersection occurred, it blends the cloud color with the scene color using the cloud's alpha via `lerp(originalColour, cloudColour, cloudColour.a)` [S1, unofficial]. If no intersection occurred, it returns the original scene color [S1, unofficial].

**Pseudocode:** The following Python-like implementation combines the shader logic and helper routines [S1, unofficial].
```python
def FrustumRaycastBlending(uv, cameraPos, frustumCorners, boundsMin, boundsMax, densityThreshold, scatterFactor, windOffset):
    # Compute ray direction from screen UV and frustum corners [G]
    # Standard full-screen quad mapping assumes corners are ordered [BL, BR, TL, TR]
    pixelWorld = lerp(lerp(frustumCorners[0], frustumCorners[1], uv.x), 
                      lerp(frustumCorners[2], frustumCorners[3], uv.x), uv.y)
    direction = normalize(pixelWorld - cameraPos)
    origin = cameraPos
    
    # Ray-box intersection [S1, unofficial]
    tEntry, tExit = RayBoxIntersection(origin, direction, boundsMin, boundsMax)
    
    if tEntry < tExit:
        cloudColour = MarchDensity(tEntry, tExit, origin, direction, boundsMin, boundsMax, densityThreshold, scatterFactor, windOffset)
        return lerp(sceneColour, cloudColour, cloudColour.a)
    else:
        return sceneColour

def RayBoxIntersection(origin, direction, boundsMin, boundsMax):
    # Standard slab method for AABB intersection [G]
    tMin = (boundsMin - origin) / direction
    tMax = (boundsMax - origin) / direction
    t1 = min(tMin, tMax)
    t2 = max(tMin, tMax)
    tEntry = max(t1.x, t1.y, t1.z)
    tExit = min(t2.x, t2.y, t2.z)
    return tEntry, tExit

def MarchDensity(tEntry, tExit, origin, direction, boundsMin, boundsMax, densityThreshold, scatterFactor, windOffset):
    # Step through the volume segment [S1, unofficial]
    steps = 32 # Not given in the sources.
    stepSize = (tExit - tEntry) / steps
    accumulatedDensity = 0.0
    accumulatedColor = vec3(0.0)
    for i in range(steps):
        t = tEntry + i * stepSize
        samplePos = origin + direction * t
        # Sample 3D noise (e.g., Perlin noise) scaled by frequency [S1, unofficial]
        noiseVal = SampleNoise(samplePos + windOffset)
        density = noiseVal * scatterFactor
        accumulatedDensity += density
        if accumulatedDensity > densityThreshold:
            break
        accumulatedColor += density
    alpha = clamp(accumulatedDensity, 0.0, 1.0)
    return vec4(accumulatedColor, alpha)
```

**C# Script Setup:** The Unity script initializes the material parameters each frame [S1, unofficial]. It retrieves the cloud volume bounds from a scene object's `Renderer.bounds` component [S1, unofficial]. It calculates the frustum corners at the far clip plane using `Camera.CalculateFrustumCorners` [S1, unofficial]. It transforms these corners from camera space to world space using `camera.transform.TransformDirection` [S1, unofficial]. It passes the transformed corners to the shader as `_FrustumCornerTR` and `_FrustumCornerBR` [S1, unofficial].
```csharp
void OnRenderImage(RenderTexture source, RenderTexture destination)
{
    if (CloudShaderMaterial != null && CloudVolumeBounds != null)
    {
        Bounds bounds = CloudVolumeBounds.GetComponent<Renderer>().bounds;
        CloudShaderMaterial.SetVector("_CloudVolumeMinBound", bounds.min);
        CloudShaderMaterial.SetVector("_CloudVolumeMaxBound", bounds.max);
        CloudShaderMaterial.SetFloat("_DensityThreshold", densityThreshold);
        CloudShaderMaterial.SetFloat("_ScatterFactor", scatterFactor);
        
        Camera cam = GetComponent<Camera>();
        Vector3[] corners = new Vector3[4];
        cam.CalculateFrustumCorners(new Rect(0, 0, 1, 1), cam.farClipPlane, Camera.MonoOrStereoscopicEye.Mono, corners);
        for (int i = 0; i < 4; i++) {
            corners[i] = cam.transform.TransformDirection(corners[i]);
        }
        CloudShaderMaterial.SetVector("_FrustumCornerTR", corners[2]);
        CloudShaderMaterial.SetVector("_FrustumCornerBR", corners[3]);
    }
    Graphics.Blit(source, destination, CloudShaderMaterial);
}
```

**Parameters:** The density threshold controls the accumulation cutoff for opacity [S1, unofficial]. The scatter factor scales the sampled noise values to determine opacity and color contribution [S1, unofficial]. The wind speed increments a global offset each frame to animate the noise sampling coordinates [S1, unofficial].

**Edge Cases and Pitfalls:** Ray-box intersection calculations can suffer from floating-point precision errors near the box boundaries [G]. If the camera is inside the cloud volume, $t_{entry}$ may be negative and requires clamping to zero [G]. Ray marching is computationally expensive, so the step count must be limited to maintain performance [G].

### [Cloud-Scene Occlusion Blending](20794-cloud-scene-occlusion-blending.md)
A post-processing technique that blends rendered clouds with the scene by using depth information from opaque objects and the cloud layer to determine visibility and occlusion. It prevents clouds from appearing in front of opaque objects incorrectly and is chosen when correct occlusion is critical.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the number of marching steps [G].
*   **Memory Complexity:** $O(1)$ per pixel, excluding the texture memory for the noise volume [G].
*   **Performance:** Dependent on the resolution and the number of marching steps [S1, unofficial].
*   **Strengths:** Provides accurate occlusion and blending without pre-computation [S1, unofficial].
*   **Limitations:** Computationally intensive and requires careful parameter tuning [S1, unofficial].
*   **When to Use:** When high-quality volumetric clouds are needed and performance allows for per-pixel ray marching [S1, unofficial].
*   **When Not to Use:** When performance is critical or the cloud volume is static and can be pre-composited [S1, unofficial].

## Background
This method originates from a volumetric cloud renderer implementation designed for the Unity engine [S1, unofficial]. It builds on direct volume ray casting principles and integrates into the `OnRenderImage` post-processing pipeline [S1, unofficial]. The noise generation relies on a 3D Perlin noise implementation that uses a permutation lookup table, gradient hashing, and smooth interpolation [S1, unofficial].
