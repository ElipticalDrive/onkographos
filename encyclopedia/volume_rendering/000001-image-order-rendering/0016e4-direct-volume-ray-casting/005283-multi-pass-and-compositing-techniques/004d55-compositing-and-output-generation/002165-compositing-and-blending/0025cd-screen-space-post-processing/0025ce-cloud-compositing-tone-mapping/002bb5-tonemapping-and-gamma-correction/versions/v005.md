# Tonemapping and Gamma Correction

Also called: Color Clamping, Exposure and Gamma Correction, Final image processing, Gamma Correction & PPM Output, PPM Writer, Tone Mapping, tonemap

## Overview
Tonemapping and Gamma Correction converts High Dynamic Range (HDR) radiance values into Low Dynamic Range (LDR) displayable images by compressing luminance and applying electro-optical transfer functions [S1, S3][S4, unofficial]. It differs from its sibling [ACES Filmic Tone Mapping](4228-aces-filmic-tone-mapping.md) by using a simpler global Reinhard operator with explicit exposure scaling rather than a perceptual filmic curve [S1].

## How it works
**Inputs:** HDR radiance image $I_h$ (or fragment color $I_F$), exposure value $EV$, gamma exponent $\gamma$.
**Outputs:** LDR color image $I_l$ (typically 8-bit sRGB or normalized float).

**Data Structures:**
- Input: Texture buffer of format `GL_RGBA32F` (or equivalent float buffer) containing HDR values.
- Parameters:
  - $EV$: Exposure value scalar.
  - $\gamma$: Gamma exponent, typically $2.2$ [S1][S4, unofficial].
  - Black point offset: Vector $\mathbf{b} = (b_R, b_G, b_B)$ [S6, unofficial].
  - Chroma mix factor: Scalar $k$, typically $1.32$ [S4, unofficial].

**Steps:**

1. **Exposure Scaling:** Scale the HDR pixel value $E$ by $2^{EV}$ to simulate camera exposure time $\Delta t = 2^{EV}$ [S1].
   $$ E' = 2^{EV} E $$

2. **Tone Mapping:** Apply the Reinhard tone-mapping operator to compress the dynamic range [S1]:
   $$ M(E') = \frac{E'}{E' + 1} $$
   *Note: Some implementations use an exponential variant $1 - \exp(-E \cdot I_F)$ [S3] or a specific constant exposure $1 - \exp(-col \cdot 1.35)$ [S4, unofficial]. The Reinhard form is the standard for HDR-NeRF evaluation [S1].*

3. **Gamma Correction:** Raise the tone-mapped result to the power of $1/\gamma$ (typically $1/2.2$) to compensate for display characteristics [S1][S4, unofficial]:
   $$ I_{linear} = M(E')^{\frac{1}{\gamma}} $$

4. **Black Point Correction (Optional but recommended for shadows):** Subtract channel-specific black point offsets to prevent gamma lifting from creating haze in near-black values [S6, unofficial]:
   $$ I_{corrected} = \max(I_{linear} - \mathbf{b}, \mathbf{0}) $$
   Typical values for $\mathbf{b}$ are $(0.0175, 0.0160, 0.0060)$ for Red, Green, Blue respectively [S6, unofficial].

5. **Chroma Preservation (Optional):** If exponential tonemapping desaturated bright colors, mix the original color with a luminance-only version to restore saturation [S4, unofficial]:
   $$ L = \text{dot}(I_{linear}, \mathbf{w}) $$
   where $\mathbf{w} = (0.2126, 0.7152, 0.0722)$ are standard luminance weights.
   $$ I_{final} = \text{clamp}(\text{mix}(\mathbf{L}, I_{linear}, k), 0.0, 1.0) $$
   where $k = 1.32$ [S4, unofficial].

6. **Quantization:** Scale to 8-bit range and clamp [S2, unofficial]:
   $$ I_{out} = \text{clamp}(\text{round}(255 \cdot I_{final}), 0, 255) $$
   *Note: Some renderers scale by $1/\sqrt{S}$ where $S$ is samples per pixel before clamping [S2, unofficial].*

**Pseudocode:**
```python
def tonemap_and_gamma(hdr_image, ev, gamma=2.2, black_point=None, chroma_mix=False, chroma_factor=1.32):
    """
    Convert HDR image to LDR with exposure, tone mapping, and gamma.
    
    Args:
        hdr_image: 2D array of floats (H, W, 3) or (H, W, 4) with HDR radiance.
        ev: Exposure value (scalar).
        gamma: Gamma exponent (default 2.2).
        black_point: Optional vec3 (R, G, B) for black point subtraction.
        chroma_mix: Boolean to enable chroma preservation.
        chroma_factor: Weight for original color in chroma mix (default 1.32).
        
    Returns:
        2D array of uint8 (H, W, 3) in sRGB-like range [0, 255].
    """
    # 1. Exposure Scaling
    # E' = 2^EV * E
    exposure_scale = 2.0 ** ev
    linear_color = hdr_image[..., :3] * exposure_scale
    
    # 2. Tone Mapping (Reinhard)
    # M(E') = E' / (E' + 1)
    tone_mapped = linear_color / (linear_color + 1.0)
    
    # 3. Gamma Correction
    # I_linear = M(E')^(1/gamma)
    inv_gamma = 1.0 / gamma
    gamma_corrected = tone_mapped ** inv_gamma
    
    # 4. Black Point Correction
    if black_point is not None:
        # col = max(col - black_point, 0)
        gamma_corrected = np.maximum(gamma_corrected - black_point, 0.0)
        
    # 5. Chroma Preservation (Optional)
    if chroma_mix:
        # Luminance weights
        lum_weights = np.array([0.2126, 0.7152, 0.0722])
        # Calculate luminance per pixel
        luminance = np.sum(gamma_corrected * lum_weights, axis=-1, keepdims=True)
        # Mix between luminance-only and original color
        # mix(vec3(lum), col, 1.32)
        mixed = np.where(
            luminance > gamma_corrected,
            luminance * (1.0 - chroma_factor) + gamma_corrected * chroma_factor,
            luminance * (1.0 - chroma_factor) + gamma_corrected * chroma_factor
        )
        # Clamp to [0, 1]
        gamma_corrected = np.clip(mixed, 0.0, 1.0)
        
    # 6. Quantization
    # Scale to 0-255 and clamp
    ldr_image = np.clip(gamma_corrected * 255.0, 0, 255).astype(np.uint8)
    
    return ldr_image
```

**Edge Cases and Pitfalls:**
- **Gamma Lifting:** Applying $x^{1/2.2}$ to near-zero linear values lifts them to visible levels, causing haze in shadows [S6, unofficial]. Black point subtraction is required to fix this [S6, unofficial].
- **Desaturation:** Exponential tonemapping can desaturate bright colors [S4, unofficial]. Chroma preservation mixing is needed to restore vividness [S4, unofficial].
- **Precision:** HDR inputs must be stored in high-precision formats (e.g., `GL_RGBA32F`) to avoid banding during tone mapping [S5, unofficial].
- **Boundary Clamping:** Output must be clamped to $[0, 1]$ (float) or $[0, 255]$ (uint8) to prevent invalid display values [S2, S4, unofficial].

## Subtopics

### [Explicit Tone Mapping](11070-explicit-tone-mapping.md)
Explicit Tone Mapping converts HDR radiance to LDR by modeling the physical image acquisition process of a digital camera. It differs from implicit or learned tone mapping by explicitly parameterizing white balance and the Camera Response Function (CRF) as distinct, differentiable stages, allowing for self-calibration during HDR radiance field optimization. It uses the Reinhard operator with exposure scaling $M(E, EV) = \left( \frac{2^{EV} E}{2^{EV} E + 1} \right)^{\frac{1}{2.2}}$. It is chosen when generating LDR ground truth views from Blender-rendered HDR views for evaluation or simulating multi-exposure inputs. See [Explicit Tone Mapping](11070-explicit-tone-mapping.md).

### Channel-wise Black Point Correction
A post-processing step to correct color purity in shadows by subtracting channel-specific black point offsets [S6, unofficial]. It addresses the issue where gamma lifting ($pow(col, 1/2.2)$) lifts near-black values, causing visible haze [S6, unofficial]. Without it, renders may carry excessive green (e.g., washed-out teal instead of deep blue-violet water) [S6, unofficial]. It uses offsets $\mathbf{b} = (0.0175, 0.0160, 0.0060)$ for R, G, B respectively [S6, unofficial]. Code: `col = max(col - vec3(0.0175, 0.0160, 0.0060), vec3(0.0))` [S6, unofficial].

### Chroma-Preserving Tonemapping
A post-processing step applied after tonemapping to restore saturation to bright colors desaturated by exponential tonemapping [S4, unofficial]. It mixes the original color with a luminance-only version weighted by $1.32$ to preserve chroma [S4, unofficial]. Code: `float lum = dot(col, vec3(0.2126, 0.7152, 0.0722)); col = clamp(mix(vec3(lum), col, 1.32), 0.0, 1.0);` [S4, unofficial].

### Final Fabric Enhancement
A postprocessing step that scales Red and Green channels by original color intensities to create a fabric-like impression, avoiding the misunderstanding of rotating ribbons [S7, book]. It applies image-space bump mapping and uses the bump-mapped Phong intensity $\mathcal{B}_{x,y}$ to modify channels: $R(x,y) = \mathcal{B}_{x,y}(R(x,y)G(x,y) + R^2(x,y)) + e_{x,y} + \text{light}(\mathcal{L}_{x,y})$ and $G(x,y) = \mathcal{B}_{x,y}(R(x,y)G(x,y) + G^2(x,y)) + e_{x,y} + \text{light}(\mathcal{L}_{x,y})$ [S7, book].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of pixels. The operations are element-wise and parallelizable on GPU [S5, unofficial].
- **Memory Complexity:** $O(N)$ for the input and output buffers. Intermediate buffers are not required if computed in-place [S5, unofficial].
- **Performance:** Dispatched as a compute shader or fragment shader with resolution $W \times H$ [S5, unofficial]. Performance is limited by memory bandwidth for large resolutions [S5, unofficial].
- **Strengths:** Simple, fast, and effective for standard HDR-to-LDR conversion [S1]. Explicit exposure control allows for multi-exposure simulation [S1].
- **Limitations:** Reinhard operator may not preserve perceptual contrast as well as filmic curves (e.g., ACES) [S1]. Requires additional steps (black point, chroma) for high-quality results [S4, S6, unofficial].
- **When to use:** Standard evaluation of NeRF/radiance fields, final image output for display, or when computational resources are limited [S1][S5, unofficial].
- **When not to use:** When perceptual color accuracy is critical and filmic response is preferred (use [ACES Filmic Tone Mapping](4228-aces-filmic-tone-mapping.md)) [S1].

## Background
Originated from classical tone-mapping techniques like Reinhard's operator [S1]. Used in HDR-NeRF for generating LDR ground truth views from Blender-rendered HDR views for evaluation and simulating multi-exposure inputs [S1]. Also used in various raytracers and visualizations for final image processing [S2, S4, S5, unofficial][S7, book].
