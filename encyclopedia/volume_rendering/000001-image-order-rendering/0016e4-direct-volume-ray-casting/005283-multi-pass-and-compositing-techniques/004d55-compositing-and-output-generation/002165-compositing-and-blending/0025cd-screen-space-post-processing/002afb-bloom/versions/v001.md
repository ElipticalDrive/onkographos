# Bloom

Also called: Bloom Post-Processing, Cross-shaped bloom, Luminance-based bright pass, Multi-Scale Gaussian Bloom

## Overview
Bloom is a screen-space post-processing effect that enhances the perception of brightness by blurring the luminous regions of an image and adding them back to the original [S1, S2, unofficial]. It solves the problem of limited dynamic range in display images by simulating the glow of bright light sources bleeding into surrounding darker areas [S1, S2, unofficial]. Unlike [Cloud Compositing & Tone Mapping](3628-cloud-compositing-tone-mapping.md) which focuses on atmospheric scattering and tone curve adjustments, or the [HDR Post-Processing Pipeline](4633-hdr-post-processing-pipeline.md) which handles high-dynamic-range data, Bloom specifically targets the isolation and diffusion of high-intensity pixels [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A display image (e.g., `.png`, `.ppm`) representing the rendered scene [S1, unofficial].
- Output: The same resolution image with the bloom effect applied [S1, unofficial].

**Data Structures:**
- The method operates on a 2D texture array of color values. No specific complex data structures (like BVH or voxel grids) are required for the bloom pass itself, though it may be part of a larger pipeline involving such structures [S1, S2, unofficial].

**Steps:**
1. **Luminance-based Bright Pass:** Identify bright parts of the image using a soft threshold [S1, S2, unofficial]. Pixels below this threshold contribute little or nothing to the bloom, while those above contribute proportionally to their excess brightness [S2, unofficial].
2. **Multi-Scale Gaussian Blur:** Apply a Gaussian blur to the bright parts [S1, S2, unofficial]. This is done over a pyramid of scales, meaning multiple blurred versions of the bright pass are generated at different resolutions or kernel sizes [S1, unofficial].
3. **Accumulation:** Add the blurred result back to the original image [S1, unofficial]. The final pixel color is the sum of the original pixel and the accumulated blurred bright pass [S1, unofficial].

**Formulas:**
Let $I(x,y)$ be the original image intensity at pixel $(x,y)$.
Let $T$ be the soft threshold for the bright pass [S2, unofficial].
Let $B(x,y)$ be the bright pass mask, where $B(x,y) = \max(0, I(x,y) - T)$ [S2, unofficial].
Let $G_k$ be a Gaussian kernel with scale $k$ [S1, S2, unofficial].
The blurred bright pass at scale $k$ is $B_k(x,y) = B(x,y) * G_k(x,y)$ [S1, S2, unofficial].
The total bloom contribution $W(x,y)$ is the sum of blurred bright passes over all scales $k$:
$$ W(x,y) = \sum_k B_k(x,y) $$
The final image $I_{final}(x,y)$ is:
$$ I_{final}(x,y) = I(x,y) + W(x,y) $$
Note: The exact definition of "soft threshold" and the specific Gaussian kernel parameters are not detailed in the sources [S1, S2, unofficial].

**Parameters:**
- Threshold $T$: Not given in the sources.
- Gaussian scales: Not given in the sources.
- Number of scales: Not given in the sources.

**Edge Cases and Pitfalls:**
- Precision: High-intensity values may overflow if the addition is not handled with sufficient bit depth [G].
- Boundaries: The blur operation requires handling image boundaries, typically by clamping or mirroring [G].

**Pseudocode:**
```python
def apply_bloom(image, threshold, scales):
    """
    Apply bloom effect to an image.
    
    Args:
        image: 2D array of pixel values (RGB).
        threshold: Soft threshold for bright pass.
        scales: List of Gaussian kernel sizes or standard deviations.
        
    Returns:
        Bloomed image.
    """
    # Step 1: Bright Pass
    # Identify bright parts using a soft threshold
    bright_pass = max(0, image - threshold)
    
    # Step 2: Multi-Scale Gaussian Blur
    # Apply Gaussian blur over a pyramid of scales
    blurred_bloom = zeros_like(image)
    for scale in scales:
        # Apply Gaussian blur with the given scale
        blurred_bloom += gaussian_blur(bright_pass, scale)
        
    # Step 3: Add blurred result back to original
    final_image = image + blurred_bloom
    
    return final_image
```

## Subtopics

### Cross-shaped bloom
A variant that uses a cross-shaped kernel for blurring, potentially for performance or specific artistic effects. Not given in the sources.

### Polygonal bokeh
A related effect where out-of-focus highlights become polygons, shaped by camera blades. This is mentioned in the context of the same pipeline but is distinct from the core bloom algorithm. [S1, unofficial]

## Operating characteristics
- **Time Complexity:** Depends on the number of scales and the size of the Gaussian kernels. Typically $O(N \cdot K \cdot S)$, where $N$ is the number of pixels, $K$ is the kernel size, and $S$ is the number of scales. Not given in the sources.
- **Memory Complexity:** Requires storage for the original image, the bright pass, and the blurred bloom at each scale. Not given in the sources.
- **Strengths:** Simple to implement, effective at enhancing perceived brightness and glow. [S1, S2, unofficial]
- **Limitations:** Can introduce halo artifacts if the threshold or blur radius is not chosen carefully. [G]
- **When to use:** When a glow effect is desired for bright light sources. [S1, S2, unofficial]
- **When not to use:** When performance is critical and the effect is not needed, or when precise control over light diffusion is required beyond simple blurring. [G]
