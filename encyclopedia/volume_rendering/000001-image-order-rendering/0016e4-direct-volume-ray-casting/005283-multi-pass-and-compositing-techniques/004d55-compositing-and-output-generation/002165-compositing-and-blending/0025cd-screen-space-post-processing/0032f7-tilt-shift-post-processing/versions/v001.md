# Tilt-Shift Post-Processing

Also called: Miniature Effect, Selective Focus Blur

## Overview
Tilt-Shift Post-Processing is a screen-space effect that simulates the shallow depth-of-field of a miniature model by keeping a horizontal band of the frame sharp while applying increasing Gaussian blur to areas above and below it, accompanied by increased color saturation [S1, unofficial]. It distinguishes itself from general blur effects by its spatially varying strength profile (sharp band with falloff) and its specific aesthetic goal of mimicking macro photography of large-scale scenes [S1, unofficial]. It is typically applied after the main scene render but before UI elements to ensure menus and text remain crisp [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** A single-sample render texture containing the resolved scene color (and alpha).
*   **Output:** A final color texture with the tilt-shift blur and saturation applied.

### Data Structures and Layout
The fragment shader operates on a texture with the following uniform inputs and varying inputs:

**Varying Input:**
*   `fragTexCoord`: `vec2`, the normalized texture coordinate (0.0 to 1.0) of the current fragment.

**Uniform Inputs:**
*   `texture0`: `sampler2D`, the input scene texture.
*   `blurStep`: `vec2`, the sampling direction vector. For the horizontal pass, this is `(1.0/width, 0.0)`. For the vertical pass, this is `(0.0, 1.0/height)`.
*   `focus`: `float`, the center Y-coordinate of the sharp band, normalized to [0.0, 1.0] (0.0 is top, 1.0 is bottom).
*   `halfBand`: `float`, half the height of the sharp band, normalized to [0.0, 1.0].
*   `maxRadius`: `float`, the maximum blur radius in pixels when strength is 1.0.
*   `saturation`: `float`, the saturation multiplier. 1.0 leaves colors unchanged.
*   `RAMP`: `float`, constant value `0.35`. Defines the distance past the band edge where blur reaches full strength.
*   `TAPS`: `int`, constant value `8`. Number of taps on each side of the center (17 total taps).
*   `SIGMA`: `float`, constant value `3.2`. Standard deviation for the Gaussian weight calculation.
*   `RadiusPerStrength`: `float`, constant value `0.012f`. Defines the blur radius scaling factor relative to frame height.

### Algorithm Steps

1.  **Framebuffer Resolution:** Resolve the multisampled window framebuffer into a single-sample render texture using a blit operation. This preserves antialiasing in the sharp band, as render textures are typically not multisampled [S1, unofficial].
2.  **Horizontal Blur Pass:** Draw the scene texture to an intermediate horizontal render target. The shader samples along the X-axis using `blurStep = (1.0/width, 0.0)`.
3.  **Vertical Blur Pass:** Draw the horizontal render target to the final output. The shader samples along the Y-axis using `blurStep = (0.0, 1.0/height)`. During this pass, saturation is applied.
4.  **Alpha Correction:** Force the final alpha channel to `1.0` to prevent the underlying sharp frame from showing through if particles or clouds left the framebuffer alpha below 1.0 [S1, unofficial].

### Formulas and Parameters

**Blur Strength Calculation:**
The blur strength is determined by the distance of the fragment from the focus band.
$$
\text{strength} = \text{smoothstep}(\text{halfBand}, \text{halfBand} + \text{RAMP}, |\text{fromTop} - \text{focus}|)
$$
Where:
*   `fromTop` is the Y-coordinate of the fragment (normalized 0.0 to 1.0).
*   `focus` is the center of the sharp band.
*   `halfBand` is half the height of the sharp band.
*   `RAMP` is `0.35`.
*   `smoothstep(edge0, edge1, x)` performs smooth Hermite interpolation between 0 and 1.

**Sampling Spacing:**
The distance between taps is scaled by the calculated strength and the maximum radius.
$$
\text{spacing} = \text{blurStep} \times \left( \frac{\text{strength} \times \text{maxRadius}}{\text{TAPS}} \right)
$$
Note: `maxRadius` is derived from `RadiusPerStrength` and frame height: $\text{maxRadius} = \text{RadiusPerStrength} \times \text{height}$.

**Gaussian Weight:**
The weight for each tap pair is calculated using a Gaussian function.
$$
\text{weight} = \exp\left( -0.5 \times \frac{i^2}{\text{SIGMA}^2} \right)
$$
Where `i` is the tap index (1 to `TAPS`) and `SIGMA` is `3.2`.

**Color Saturation:**
Saturation is applied by mixing the luminance of the color with the original color.
$$
\text{luma} = \text{dot}(\text{color}, \text{vec3}(0.299, 0.587, 0.114))
$$
$$
\text{finalColor} = \text{clamp}(\text{mix}(\text{vec3}(\text{luma}), \text{color}, \text{saturation}), 0.0, 1.0)
$$

### Pseudocode

```python
# Fragment Shader Logic for Vertical Pass (Horizontal pass is identical with X-axis step)

# Constants
RAMP = 0.35
TAPS = 8
SIGMA = 3.2
RadiusPerStrength = 0.012

# Inputs
fragTexCoord: vec2
texture0: sampler2D
blurStep: vec2
focus: float
halfBand: float
maxRadius: float
saturation: float
frameHeight: float

# Calculate maxRadius if not provided directly
# maxRadius = RadiusPerStrength * frameHeight

# 1. Calculate Blur Strength
# fromTop is fragTexCoord.y
distance_from_focus = abs(fragTexCoord.y - focus)
strength = smoothstep(halfBand, halfBand + RAMP, distance_from_focus)

# 2. Calculate Spacing
spacing = blurStep * (strength * maxRadius / float(TAPS))

# 3. Initialize Accumulators
sum_rgb = vec3(0.0)
weights = 0.0

# 4. Sample Center
sum_rgb += texture(texture0, fragTexCoord).rgb
weights += 1.0

# 5. Sample Taps
for i in range(1, TAPS + 1):
    weight = exp(-0.5 * (float(i) * float(i)) / (SIGMA * SIGMA))
    
    # Sample positive offset
    pos_coord = fragTexCoord + spacing * float(i)
    sum_rgb += texture(texture0, pos_coord).rgb * weight
    
    # Sample negative offset
    neg_coord = fragTexCoord - spacing * float(i)
    sum_rgb += texture(texture0, neg_coord).rgb * weight
    
    # Add both weights
    weights += 2.0 * weight

# 6. Normalize
final_color = sum_rgb / weights

# 7. Apply Saturation
luma = dot(final_color, vec3(0.299, 0.587, 0.114))
final_color = clamp(mix(vec3(luma), final_color, saturation), 0.0, 1.0)

# 8. Force Alpha
final_alpha = 1.0

# Output
out finalColor = vec4(final_color, final_alpha)
```

### Edge Cases and Pitfalls
*   **Multisampling:** The source framebuffer is multisampled, but render textures are not. Drawing directly to a texture would lose antialiasing in the sharp band. A blit operation must be used to resolve samples before post-processing [S1, unofficial].
*   **Alpha Transparency:** Particles and clouds may leave the framebuffer's alpha channel below 1.0. The shader must force the final alpha to 1.0 to prevent the sharp frame underneath from showing through the blurred areas [S1, unofficial].
*   **Band Boundaries:** If `focus` or `halfBand` are set such that the sharp band extends beyond the frame boundaries, the `smoothstep` function handles the clamping naturally, but care should be taken to ensure `halfBand + RAMP` does not exceed valid coordinate ranges unnecessarily, though `smoothstep` handles out-of-bounds inputs gracefully.

## Operating characteristics

### Time and Memory Complexity
*   **Time Complexity:** $O(N \cdot T)$, where $N$ is the number of pixels and $T$ is the number of taps ($2 \cdot \text{TAPS} + 1$). The effect requires two passes (horizontal and vertical), each performing $2 \cdot \text{TAPS} + 1$ texture samples per pixel. With $\text{TAPS}=8$, this is 17 samples per pixel per pass.
*   **Memory Complexity:** $O(W \cdot H)$ for the intermediate render target used in the separable blur.

### Measured Performance
*   **Hardware:** Performance depends on GPU texture sampling bandwidth. The separable blur approach (horizontal then vertical) is efficient for modern GPUs.
*   **Resolution:** The blur radius scales with resolution via `maxRadius`. Higher resolutions require larger `maxRadius` values to maintain the same visual effect, increasing the sampling distance but not the number of taps.

### Strengths and Limitations
*   **Strengths:** Simple to implement; effective at creating a miniature illusion; separable blur allows for efficient implementation.
*   **Limitations:** Screen-space only; does not account for true depth-based defocus (objects at different depths within the sharp band are not blurred differently); artifacts may occur at the edges of the sharp band if the transition is too abrupt (mitigated by `RAMP`).

### When to Use
*   Use when a stylistic "miniature" look is desired.
*   Use when UI elements need to remain sharp while the background is blurred.

### When Not to Use
*   Do not use when physically accurate depth-of-field is required.
*   Do not use if the scene contains significant transparency issues that cannot be resolved by forcing alpha to 1.0.

## Background

### Origin and History
The Tilt-Shift Post-Processing effect is implemented in the VoxelTerraformer engine [S1, unofficial]. It is part of a broader screen-space post-processing pipeline that includes bloom, color grading, and dithering [S1, unofficial]. The effect mimics the optical phenomenon of tilt-shift lenses, which allow the plane of focus to be tilted relative to the image plane, creating a shallow depth of field that makes full-scale scenes look like miniature models.

### Usage
The effect is applied after the main scene render but before UI elements are drawn, ensuring that menus and text remain sharp [S1, unofficial]. It is commonly used in voxel-based games and simulations to enhance the visual appeal of large-scale terrain.
