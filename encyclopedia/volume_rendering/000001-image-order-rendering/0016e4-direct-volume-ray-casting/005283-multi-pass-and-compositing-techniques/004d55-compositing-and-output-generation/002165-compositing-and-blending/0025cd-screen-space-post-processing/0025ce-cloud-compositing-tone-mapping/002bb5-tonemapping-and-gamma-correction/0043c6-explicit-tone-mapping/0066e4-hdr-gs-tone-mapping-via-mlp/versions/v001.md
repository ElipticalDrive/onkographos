# HDR-GS Tone Mapping via MLP

Also called: HDR-GS tone-mapper

## Overview
This method models the inverse tone-mapping function for High Dynamic Range Gaussian Splatting (HDR-GS) by transforming the input signal to a logarithmic domain, thereby enhancing Multi-Layer Perceptron (MLP) training stability and avoiding nonlinearity and discontinuity issues inherent in linear domain multiplication [S1]. It differs from traditional non-parametric calibration methods by parameterizing the Camera Response Function (CRF) as a learnable MLP, allowing for joint optimization with the scene representation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** HDR color $c_{hi}$ at view direction $d=(\theta, \phi)$, exposure time $\Delta t$, and SH coefficients $k$.
*   **Output:** LDR color $c_{li}$.

**Data Structures:**
*   **SH Coefficients ($k$):** A set of coefficients $k = \{k_{lm} \mid 0 \le l \le L, -l \le m \le l\} \in \mathbb{R}^{(L+1)^2 \times 3}$. Each $k_{lm} \in \mathbb{R}^3$ corresponds to the RGB components. $L$ is the SH degree [S1].
*   **Tone Mapper ($g_\theta$):** An MLP architecture per RGB channel consisting of:
    1.  Fully Connected (fc) layer.
    2.  ReLU activation.
    3.  Fully Connected (fc) layer.
    4.  Sigmoid activation [S1].

**Steps:**

1.  **Logarithmic Transformation:** Transform the HDR color $c_{hi}$ to the logarithmic domain to stabilize training. The natural logarithm (base $e$) is used [S1]:
    $$ \log f_{T_M}^{-1}(c_i) = \log c_i + \log \Delta t $$
    where $c_i$ is the color and $\Delta t$ is the exposure time [S1].

2.  **HDR Color Reconstruction via SH:** Model the HDR color $c_{hi}$ at direction $d=(\theta, \phi)$ using Spherical Harmonics (SH). The exponential function is applied to the SH sum to ensure positive radiance [S1]:
    $$ c_{hi}(d, k) = \exp\left(\sum_{l=0}^{L} \sum_{m=-l}^{l} k_{lm} Y_{lm}(\theta, \phi)\right) $$
    where $Y_{lm}: S^2 \to \mathbb{R}$ are the SH functions [S1].

3.  **Log-Domain Input Preparation:** Substitute the SH representation into the log-domain transformation. A constant bias $b \in \mathbb{R}$ is added to help the SH function fit the data better [S1]:
    $$ \text{Input to } g_\theta = \sum_{l=0}^{L} \sum_{m=-l}^{l} k_{lm} Y_{lm}(\theta, \phi) + \log \Delta t + b $$

4.  **MLP Tone Mapping:** Apply the MLP-based tone mapper $g_\theta$ to the log-domain input. The RGB channels are processed independently because they are tone-mapped by different CRFs [S1]:
    $$ c_{li}(d, k, \Delta t) = g_\theta\left(\sum_{l=0}^{L} \sum_{m=-l}^{l} k_{lm} Y_{lm}(\theta, \phi) + \log \Delta t + b\right) $$
    where $g_\theta(x) \triangleq (\log f_{T_M}^{-1})^{-1}(x)$ [S1].

**Edge Cases and Pitfalls:**
*   **Numerical Overflow/Underflow:** Multiplication operations in the linear domain can cause overflow or underflow. The logarithmic transformation mitigates this [S1].
*   **Training Instability:** Nonlinearity and discontinuity in the linear domain exacerbate MLP training instability. The log-domain transformation addresses this [S1].

## Background
The method originates from the HDR-GS paper, which introduces efficient high dynamic range novel view synthesis using Gaussian Splatting [S1]. It builds on the concept of explicit tone mapping by parameterizing the CRF with an MLP, moving away from fixed or non-parametric CRFs [S1].
