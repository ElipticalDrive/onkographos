# ACES Filmic Tone Mapping

Also called: ACES Filmic, ACES Tonemapping, ACES

## Overview
ACES Filmic Tone Mapping is a filmic tone mapping function that compresses High Dynamic Range (HDR) color values into the standard Low Dynamic Range (LDR) display range of $[0, 1]$ while preserving highlight detail through a characteristic "shoulder" curve [S3, S1, unofficial]. It is specifically designed to prevent "neon highlights" from clipping to flat white, a common artifact when mapping physical radiance to displayable values [S3, unofficial]. In the context of cloud rendering, it serves as the final color transformation step, converting the linear radiance output of the physical shading model into a display-ready image before gamma correction [S2, unofficial]. It is distinct from simple Reinhard tonemapping, which uses a basic division formula and lacks the nuanced highlight roll-off of the ACES curve [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A linear HDR color vector $\mathbf{c} = (r, g, b)$, where each component represents physical radiance or scene-referred luminance. The values are typically unbounded above but non-negative.
- **Output:** A linear LDR color vector $\mathbf{c}' = (r', g', b')$ with each component clamped to the range $[0.0, 1.0]$.

**Data Structures:**
No complex data structures are required. The method operates per-pixel on scalar color components.

**Parameters:**
The curve is defined by five constants. These values are fixed for the standard ACES approximation [S1, S3, S4, unofficial]:
- $a = 2.51$
- $b = 0.03$
- $c = 2.43$
- $d = 0.59$
- $e = 0.14$

**Formula:**
The tone mapping function is applied independently to each color channel $x \in \{r, g, b\}$:

$$
\text{toneMapACES}(x) = \text{clamp}\left( \frac{x (a x + b)}{x (c x + d) + e}, 0.0, 1.0 \right)
$$

Where:
- $x$ is the input linear color value for a single channel.
- $\text{clamp}(v, min, max)$ restricts $v$ to the interval $[min, max]$.
- The numerator $x(ax+b)$ provides a linear response for low values and quadratic growth for mid-values.
- The denominator $x(cx+d)+e$ ensures the curve asymptotically approaches a finite limit, creating the shoulder that compresses highlights.

**Steps:**
1. For each pixel in the image, retrieve the linear RGB color values $(r, g, b)$ from the rendering buffer.
2. For each color channel $x$ in $(r, g, b)$:
   a. Calculate the numerator: $num = x \cdot (a \cdot x + b)$.
   b. Calculate the denominator: $den = x \cdot (c \cdot x + d) + e$.
   c. Compute the ratio: $y = num / den$.
   d. Clamp the result: $x' = \max(0.0, \min(1.0, y))$.
3. Construct the output color vector $\mathbf{c}' = (r', g', b')$.
4. [G] The output $\mathbf{c}'$ is now in linear LDR space. It must be followed by gamma correction (typically $\gamma=2.2$) if the target display format (e.g., sRGB) requires it, as ACES Filmic itself outputs linear light [S1, S2, unofficial].

**Pseudocode:**
```python
def tone_map_aces(color: tuple[float, float, float]) -> tuple[float, float, float]:
    """
    Applies the ACES Filmic tone mapping curve to a linear RGB color.
    
    Args:
        color: A tuple (r, g, b) of linear HDR values.
        
    Returns:
        A tuple (r', g', b') of LDR values in [0.0, 1.0].
    """
    # ACES Filmic constants
    a = 2.51
    b = 0.03
    c = 2.43
    d = 0.59
    e = 0.14
    
    r, g, b_val = color
    
    # Apply curve to each channel
    def apply_channel(x: float) -> float:
        numerator = x * (a * x + b)
        denominator = x * (c * x + d) + e
        # Avoid division by zero, though e=0.14 ensures denominator >= 0.14
        result = numerator / denominator
        # Clamp to display range
        if result < 0.0:
            return 0.0
        elif result > 1.0:
            return 1.0
        else:
            return result

    r_out = apply_channel(r)
    g_out = apply_channel(g)
    b_out = apply_channel(b_val)
    
    return (r_out, g_out, b_out)
```

**Edge Cases and Pitfalls:**
- **Double Tonemapping:** If the rendering engine or pipeline already applies ACES tonemapping (e.g., Unreal Engine's default post-process stack), applying this function again will crush highlights and distort colors. In such cases, disable this step [S2, unofficial].
- **Identity Function Limitation:** The Narkowicz ACES approximation cannot represent the identity function (i.e., it cannot pass through $y=x$ for all $x$). If the ground truth data is already true linear HDR without tonemapping, do not use learnable ACES variants, as they will fail to model the identity mapping [S2, unofficial].
- **Precision:** For very high HDR values, the curve asymptotically approaches $a/c \approx 1.034$, which is then clamped to 1.0. This is the intended behavior for highlight compression.

## Subtopics

### Learnable ACES
A variant where the four coefficients $a, b, c, d$ are treated as learnable parameters during optimization, while $e$ remains fixed at 0.14 [S2, unofficial]. This adaptation allows the tone mapping curve to fit the specific display characteristics of the ground truth data or other filmic engines more closely. The learned coefficients are typically saved in a JSON file (e.g., `tonemap.json`) alongside the asset data [S2, unofficial]. It is chosen when the standard ACES curve does not adequately match the target display's response or when serving as a fallback for other filmic engines. It is not suitable if the input is true linear HDR requiring an identity mapping [S2, unofficial].

### Log-Contrast and Saturation Tone Curve
A post-processing adjustment that applies log contrast centered around mid-grey values and includes saturation controls [S5, unofficial]. Unlike ACES Filmic, which focuses on dynamic range compression and highlight preservation, this method primarily adjusts the perceptual contrast and color vibrancy of the image. It is applied to the scene-linear image before tone mapping in some pipelines (e.g., Photon Engine) to enhance visual appeal [S5, unofficial]. It is chosen when fine-tuning the mid-tone contrast and color richness is required, rather than solving HDR-to-LDR mapping issues.

## Operating characteristics
- **Time Complexity:** $O(1)$ per pixel. The calculation involves a fixed number of arithmetic operations (multiplications, additions, one division) and a clamp. It is extremely fast and suitable for real-time rendering or dense volume ray casting where it is applied per-sample or per-pixel.
- **Memory Complexity:** $O(1)$. No additional memory is required beyond the input and output color buffers.
- **Performance:** Measured performance is negligible in terms of computational cost compared to the volume ray casting or compositing steps. It is often implemented as a simple fragment shader operation [S1, S3, unofficial].
- **Strengths:**
  - Provides a natural, filmic look with smooth highlight roll-off.
  - Prevents harsh clipping of bright highlights (neon highlights) [S3, unofficial].
  - Simple to implement and computationally inexpensive.
  - Matches the "Ground Truth" display space used in some cloud rendering datasets [S2, unofficial].
- **Limitations:**
  - It is an approximation of the full ACES transform; the full transform may involve additional color space conversions (e.g., to AP1/ACEScg) [S1, unofficial].
  - Not suitable for scenes where the input is already LDR or where a linear pass-through is required [S2, unofficial].
  - Requires subsequent gamma correction for sRGB displays [S1, S2, unofficial].
- **When to use:** Use when rendering HDR physical shading outputs that need to be displayed on standard LDR monitors, especially in cloud rendering where bright sunlit cloud edges can exceed display range [S2, S3, unofficial].
- **When not to use:** Do not use if the pipeline already applies tonemapping (risk of double tonemapping) [S2, unofficial], or if the input data is true linear HDR and requires an identity mapping [S2, unofficial].

## Background
The ACES Filmic tone mapping curve is an approximation of the Academy Color Encoding System (ACES) look, originally described by Narkowicz in 2015 [S1, unofficial]. It was designed to provide a standardized, filmic response curve for digital intermediate workflows, mimicking the characteristic highlight roll-off of photographic film. In the context of computer graphics and volume rendering, it has been adopted as a standard post-processing step to ensure consistent and visually pleasing output from physically based renderers [S2, S3, unofficial]. It is widely used in real-time engines (like Unreal Engine) and offline renderers (like Photon Engine) as a default or configurable tone mapping option [S2, S5, unofficial].
