# Layer-Centric Volume Rendering Framework

Also called: 2.5D layer compositing engine, Multi-layer volume rendering framework

## Overview
The Layer-Centric Volume Rendering Framework is a visualization architecture that constructs the final image by compositing multiple distinct renderings, each treated as an independent layer [S1]. It solves the rigidity of traditional single-pass volume rendering by segmenting the workflow into a rendering phase for small regions of interest and a subsequent compositing phase [S1]. This approach provides a rich set of 2D operators and interactions, allowing for greater freedom and more intuitive user interaction compared to standard volume rendering techniques [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A scene defined by a hierarchy of Views, Layers, Drawables, and Materials, along with associated 3D data and transfer functions [S1].
*   **Output:** A final 2D image displayed in a viewport [S1].

**Data Structures**
The system hierarchy is defined as follows [S1]:
1.  **View:** The central component responsible for display. It contains a compositing camera, a viewport, and a list of Layers.
2.  **Layer:** Contains a list of Drawables. A layer may be composited multiple times with different materials. A layer generates a texture output.
3.  **Drawable:** An entity to be rendered. It is associated with a Material.
4.  **Material:** Contains attributes (e.g., color, opacity) and a GLSL shader program that implements the rendering functionality.
5.  **Null Layer:** A layer containing zero drawables. It uses shaders with access to texture resources to generate new textures or process another layer's texture.

**Steps**
1.  **Segmentation:** The user defines small regions of interest (3D boxes) within the volume data [S1].
2.  **Rendering Phase:** Traditional volume rendering is applied to these regions. Each Drawable renders its associated geometry/data using its Material's shader, producing a texture for its parent Layer [S1].
3.  **Compositing Phase:** The resulting renderings (textures) from the Layers are composited together. This phase utilizes a rich set of 2D operators, extending beyond standard Porter-Duff compositing to include general functional compositing functions [S1].
4.  **Event Propagation:** The system is event-based. When an entity changes, changes propagate upwards to entities above in the hierarchy [S1].
    *   Example: A material property change fires an event to all shared Drawables.
    *   Drawables fire events to their parent Layers.
    *   Layers fire events to the View.
    *   The View fires an event to invalidate the screen, triggering a re-render [S1].
5.  **Display:** The View composites the final image using the compositing camera and viewport settings [S1].

## Background
The framework was presented by S. Raman, O. Mishchenko, and R. Crawfis from the Department of Computer Science at The Ohio State University [S1]. It was published in 2008 in the Point-Based Graphics (PBG) workshop proceedings, edited by H.-C. Hege, D. Laidlaw, R. Pajarola, and O. Staadt [S1]. The work builds on previous research on segmenting and rendering volumes and examines a new system architecture that allows digital artists and technical illustrators to leverage the layer concept from paint packages like Photoshop [S1]. The system architecture is detailed in a technical report [MRC08] referenced in the source [S1].
