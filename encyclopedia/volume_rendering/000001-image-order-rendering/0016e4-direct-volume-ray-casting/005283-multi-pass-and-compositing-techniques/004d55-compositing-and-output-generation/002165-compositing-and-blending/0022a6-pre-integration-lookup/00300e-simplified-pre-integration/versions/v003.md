# Simplified Pre-integration

Also called: Pré-integração Simplificada, Simplified Pre-integrated Volume Rendering

## Overview
Simplified pre-integration is a faster approximation of full pre-integration used in direct volume ray casting to accelerate interactive transfer function (TF) editing [S1][S3, unofficial]. It solves the performance bottleneck of computing volume rendering integrals in real-time by neglecting color attenuation inside volume slabs, allowing for the pre-computation of color and opacity contributions based on scalar values and distance [S1][S2, S3, unofficial]. It is distinguished from full pre-integration by its omission of the exponential attenuation term within the lookup table calculation, trading visual accuracy for significant performance gains [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume texture, a transfer function (TF) mapping scalar values to color and opacity, and the distance between sample points.
*   **Output:** A pre-integration lookup table (LUT) stored as a 3D texture (or 2D RGBA texture depending on implementation details) containing pre-computed color and opacity values.

**Data Structures:**
*   **Volume Data:** Stored in GPU memory as a 3D texture with 8-bit precision per component [S1].
*   **Transfer Function:** Represented as a lookup table with 256 entries [S1].
*   **Pre-integration Table:**
    *   Full pre-integration typically uses a 3D texture accessed by scalar values $(s_1, s_2)$ and distance $d$ [S2, unofficial].
    *   Simplified pre-integration in the cited implementation stores results as 2D RGBA textures [S1]. The specific axis mapping for the 2D case is not explicitly defined in the sources, but the general pre-integration concept maps scalar values to x/y axes and distance to z [S2, unofficial].

**Method Steps:**
1.  **Pre-computation:** For each pair of scalar values $(s_1, s_2)$ sampled at two different positions along a ray and the distance $d$ between them, compute the color and opacity contributions using the transfer function [S2, unofficial].
2.  **Simplified Integral Calculation:** Compute the integral approximation by neglecting the color attenuation term. In full pre-integration, the contribution of a segment is weighted by the accumulated opacity of previous segments. In simplified pre-integration, this attenuation is disregarded [S3, unofficial].
    *   Let $c(s)$ be the color and $\alpha(s)$ be the opacity from the TF for scalar value $s$.
    *   The simplified contribution for a segment of length $d$ between $s_1$ and $s_2$ is computed without the exponential decay factor $\exp(-\sum \alpha_i \Delta x)$ that appears in the standard volume rendering equation [S1][S3, unofficial].
3.  **Storage:** Store the resulting color and opacity values in the lookup table [S2, unofficial].
4.  **Rasterization:** During rendering, access the pre-integration table using the scalar values sampled at the ray segment endpoints and the segment distance [S2, unofficial].
5.  **Compositing:** Combine the retrieved pre-computed color and opacity values into the accumulated final color for the pixel [S2, unofficial].

def compute_simplified_pre_integration_table(volume, transfer_function, num_samples):
    """
    Pre-computes the simplified pre-integration lookup table.
    
    Args:
        volume: 3D texture of scalar values.
        transfer_function: Function mapping scalar value -> (color, opacity).
        num_samples: Number of discrete steps for distance and scalar values.
        
    Returns:
        LUT: Pre-computed color and opacity values.
    """
    # Initialize LUT. Dimensions depend on implementation (2D RGBA or 3D).
    # Assuming 3D structure for generality: LUT[s1_idx, s2_idx, d_idx] = (color, opacity)
    LUT = empty_3d_texture()
    
    # Define ranges for scalar values and distance
    scalar_range = get_scalar_range(volume)
    distance_range = get_max_distance(volume)
    
    # Discretize ranges
    s_values = linspace(scalar_range.min, scalar_range.max, num_samples)
    d_values = linspace(0, distance_range.max, num_samples)
    
    for i, s1 in enumerate(s_values):
        for j, s2 in enumerate(s_values):
            for k, d in enumerate(d_values):
                # Get TF properties for the endpoints
                c1, a1 = transfer_function(s1)
                c2, a2 = transfer_function(s2)
                
                # Simplified Pre-integration Calculation
                # Full pre-integration would involve:
                # C = integral(c(s) * alpha(s) * exp(-integral(alpha(s) ds))) ds
                # Simplified pre-integration neglects the attenuation term exp(-...)
                # This is often approximated as a linear interpolation or simple average
                # weighted by the segment length, or specifically defined in [S1][S3, unofficial]
                # as neglecting color attenuation inside volume slabs.
                
                # Approximation: Linear interpolation of color and opacity
                # without the exponential opacity accumulation factor.
                # [G] Standard simplified pre-integration often uses:
                # Color = (c1 + c2) / 2 * (a1 + a2) / 2 * d
                # Or similar non-attenuated accumulation.
                # Since the exact formula is not provided, we note the neglect of attenuation.
                
                # Example implementation of "neglecting attenuation":
                # Accumulate color and opacity linearly without exponential decay.
                avg_color = (c1 + c2) / 2.0
                avg_opacity = (a1 + a2) / 2.0
                
                # Contribution is proportional to distance, but not attenuated by previous segments
                contribution_color = avg_color * avg_opacity * d
                contribution_opacity = avg_opacity * d
                
                # Store in LUT
                LUT[i, j, k] = (contribution_color, contribution_opacity)
                
    return LUT

**Parameters:**
*   **TF Entries:** 256 entries are typical for the transfer function lookup tables [S1].
*   **Volume Precision:** 8-bit precision is used for the 3D texture storage [S1].
*   **Interaction Level:** Simplified pre-integration is applied when multiple TFs are modified simultaneously (e.g., 36 TFs) to maintain interactivity [S1]. Full pre-integration is used when a single TF is modified [S1].

**Edge Cases and Pitfalls:**
*   **Discretization Artifacts:** The method assumes a linear progression of scalar values between slices, which can introduce discretization artifacts [S2, unofficial]. An adaptive sampling approach can mitigate this [S2, unofficial].
*   **Color Deviation:** Neglecting attenuation results in a deviation in the calculation of the total color contribution at each pixel compared to the physically correct result [S3, unofficial].
*   **Performance vs. Quality:** While it guarantees superior performance, the visual quality is lower than full pre-integration [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Faster than full pre-integration. The pre-computation is faster because it neglects the attenuation term [S1][S3, unofficial].
*   **Memory Complexity:** Stores pre-computed values in textures. The cited implementation uses 2D RGBA textures for the simplified case [S1], whereas full pre-integration may use 3D textures [S2, unofficial].
*   **Performance:** Guarantees superior performance, although of the same order of magnitude as efficient full pre-integration algorithms like Lum et al. [S3, unofficial].
*   **Strengths:** Enables real-time interaction when modifying multiple transfer functions simultaneously [S1].
*   **Limitations:** Introduces visual artifacts due to the neglect of color attenuation and linear scalar interpolation assumptions [S2, S3, unofficial].
*   **When to Use:** Interactive editing interfaces where multiple TFs are adjusted at once [S1].
*   **When Not to Use:** Final rendering or single-TF editing where higher visual fidelity is required (use full pre-integration instead) [S1].

## Background
*   **Origin:** The concept is described in the context of volume visualization and exploration through flexible transfer function design [S1]. It is also discussed in surveys of GPU-based volume rendering [S2, unofficial] and in the specification of 1D and multidimensional transfer functions [S3, unofficial].
*   **History:** The technique is presented as an alternative to full pre-integration [S3, unofficial] to handle the computational cost of per-fragment operations [S2, unofficial]. It is used in dual-domain interaction interfaces for TF design [S1].
*   **Usage:** Used in volume visualization tools to allow interactive modification of multiple transfer functions [S1].
