# Pre-integrated Volume Rendering with Dependent Texture Lookups

Also called: Dependent Texture Mapping for Volume Rendering, Dependent texture volume rendering, Pre-integrated Volume Rendering on GeForce3, Pre-integrated Volume Rendering with Lighting, Pre-shading

## Overview
A hardware-accelerated volume rendering technique that uses 2D dependent textures to store pre-integrated color and opacity values for ray segments, allowing for high-quality rendering with diffuse and specular lighting without polygon extraction or additional interpolated slices [S1]. It replaces slice-by-slice compositing with slab-by-slab rendering using two adjacent slices [S1]. Unlike [Simplified Pre-integration](6186-simplified-pre-integration.md), which neglects color attenuation inside volume slabs, this method computes full pre-integration for both color and opacity, achieving full quality without the slicing artifacts of pre-shading or the performance cost of post-shading with extra slices [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset, transfer functions (defining color $C(s)$ and opacity $\alpha(s)$ for scalar $s$), lighting parameters (ambient $I_a$, diffuse $I_d$, specular $I_s$, light directions $\mathbf{l}_1, \mathbf{l}_2$), and an isovalue $s_{iso}$ (for isosurface rendering).
*   **Output:** A 2D image with correct volume shading and transparency.

**Data Structures:**
1.  **Source Textures (Front and Back Slices):**
    *   **Direct Volume Rendering (No Lighting):** `GL_LUMINANCE8` (8-bit). Stores scalar values in the Red component.
    *   **Volume Shading / Isosurfaces:** `GL_RGBA`.
        *   RGB components: Volume gradient vector $\nabla V$.
        *   Alpha component: First gradient component (to be routed back to Red later).
        *   Red component: Scalar value $s$.
2.  **Dependent Texture (Lookup Table):**
    *   **Direct Volume Rendering:** `GL_RGBA` (or `GL_LUMINANCE8` if no lighting). Stores pre-integrated color and opacity for every combination of front scalar $s_f$ and back scalar $s_b$.
    *   **Isosurface Rendering (Approach 1):** `GL_RGBA`.
        *   R, G, B: Pre-integrated color/transparency data.
        *   A: Interpolation value $IP$ scaled to range [128, 255] (7-bit) for intersecting segments, or 0 for non-intersecting.
    *   **Isosurface Rendering (Approach 2):** `GL_RGBA`.
        *   R, G: Pre-integrated color/transparency data.
        *   B: Interpolation value $IP$ (8-bit).
        *   A: Transparency.
    *   **Static Lighting:** `GL_LUMINANCE_ALPHA`. Stores pre-calculated dot products of gradient and light vectors. Consumes half the memory of RGBA textures.

**Numbered Steps:**

1.  **Pre-computation (Offline):**
    *   For each pair of scalar values $(s_f, s_b)$ representing the front and back of a slab, calculate the pre-integrated color $C_{pre}$ and opacity $\alpha_{pre}$ using the compositing equations from [Simplified Pre-integration](6186-simplified-pre-integration.md) [S1].
    *   For isosurface rendering, calculate the interpolation parameter $IP = (s_{iso} - s_f) / (s_b - s_f)$ [S1]. Since division is not available in register combiners, pre-calculate $IP$ for all $(s_f, s_b)$ pairs and store it in the dependent texture [S1].
    *   For static lighting, pre-calculate dot products $\nabla V \cdot \mathbf{l}$ for each voxel and store them in the dependent texture [S1].

2.  **Rendering Loop (Back-to-Front):**
    *   Render the volume slab-by-slab from back to front [S1].
    *   For each slab, define a quadrilateral polygon textured with two adjacent slice textures (Front and Back) [S1].
    *   **Projection:** Project the texels of the two adjacent slices onto each other along the viewing ray. Adapt texture coordinates for the projected slice; retain coordinates for the other [S1].

3.  **Texel Fetch and Coordinate Extraction:**
    *   Fetch texels from the Front and Back source textures [S1].
    *   Extract the scalar values $s_f$ and $s_b$ from the Red components using dot product texture shader operations with a constant vector $\mathbf{v} = (1, 0, 0)^T$ [S1].
        *   Stage 1: Dot product of Front texel with $\mathbf{v}$.
        *   Stage 2: Dot product of Back texel with $\mathbf{v}$ [S1].

4.  **Dependent Texture Lookup:**
    *   Use the extracted scalars $s_f$ (as $s$-coordinate) and $s_b$ (as $t$-coordinate) to perform a dependent 2D texture lookup into the pre-integrated dependent texture [S1].
    *   Retrieve pre-integrated color $C_{pre}$ and opacity $\alpha_{pre}$ [S1].

5.  **Lighting Calculation (Optional):**
    *   **Volume Shading:** Use the average gradient at the front and back slice for lighting. No interpolation values are stored in the dependent texture for this mode [S1].
    *   **Isosurface Shading:**
        *   Reconstruct gradients: Route Alpha back to Red and rebuild gradient vectors in RGB components for both front and back slices [S1].
        *   Interpolate normals: Use the pre-stored $IP$ to interpolate the normal $\mathbf{n}$ between the front and back gradients [S1].
        *   Compute lighting:
            $$ I = I_a + I_d C_{pre} (\mathbf{n} \cdot \mathbf{l}_1) + I_s C_{pre} (\mathbf{n} \cdot \mathbf{l}_2)^{16} $$
            where $\mathbf{n}$ is the interpolated normal, $\mathbf{l}_1$ is the diffuse light direction, $\mathbf{l}_2$ is the specular light direction, and $C_{pre}$ is the pre-integrated color [S1].
    *   **Static Lighting:** Interpolate pre-calculated dot products for the start and end of the ray segment in the register combiners [S1].

6.  **Blending:**
    *   Blend the result into the frame buffer.
    *   For direct volume rendering without lighting: Route the fetched texel through register combiners without processing and blend using `glBlendFunc(GL_ONE, GL_ONE_MINUS_SRC_ALPHA)` [S1].

**Pseudocode:**
```python
# Offline Pre-computation
def precompute_lookup_table(volume_data, transfer_func, isovalue=None):
    """
    Generates the dependent texture map.
    """
    lookup_table = empty_2d_array(size=(max_scalar, max_scalar), dtype=RGBA)
    
    for s_f in range(max_scalar):
        for s_b in range(max_scalar):
            # Calculate pre-integrated color and opacity based on slab [s_f, s_b]
            c_pre, alpha_pre = integrate_slab(s_f, s_b, transfer_func)
            
            if isovalue is not None:
                # Isosurface mode: Calculate interpolation parameter
                denom = s_b - s_f
                if denom == 0:
                    ip = 0.0
                else:
                    ip = (isovalue - s_f) / denom
                
                # Store IP in Alpha channel (Approach 1) scaled to 128-255
                # 0 for non-intersecting, 128-255 for intersecting
                if s_f <= isovalue <= s_b or s_b <= isovalue <= s_f:
                    ip_scaled = int(ip * 127 + 128)
                else:
                    ip_scaled = 0
                
                lookup_table[s_f, s_b] = RGBA(c_pre, alpha_pre, ip_scaled)
            else:
                # Direct volume rendering
                lookup_table[s_f, s_b] = RGBA(c_pre, alpha_pre)
                
    return lookup_table

# Rendering Pass
def render_slab(front_slice_texture, back_slice_texture, lookup_texture, 
                isovalue=None, lighting_mode='dynamic'):
    """
    Renders a single slab using dependent texture lookups.
    """
    # 1. Project back slice onto front slice (or vice versa)
    # Adjust texture coordinates for projection
    proj_coords = project_coordinates(front_slice_texture, back_slice_texture)
    
    # 2. Fetch scalars using dot product with v=(1,0,0)
    # Stage 1: Extract s_f from front texel
    s_f = dot_product(front_slice_texture.texel(proj_coords), (1, 0, 0))
    
    # Stage 2: Extract s_b from back texel
    s_b = dot_product(back_slice_texture.texel(proj_coords), (1, 0, 0))
    
    # 3. Dependent Texture Lookup
    # Use s_f as s-coord, s_b as t-coord
    pre_integrated = lookup_texture.lookup(s_f, s_b)
    c_pre = pre_integrated.rgb
    alpha_pre = pre_integrated.a
    
    # 4. Lighting (if applicable)
    if lighting_mode == 'dynamic' and isovalue is not None:
        # Reconstruct gradients from source textures
        grad_f = reconstruct_gradient(front_slice_texture.texel(proj_coords))
        grad_b = reconstruct_gradient(back_slice_texture.texel(proj_coords))
        
        # Retrieve IP from lookup texture alpha (Approach 1)
        ip_raw = pre_integrated.a
        # Map back to 0-1 range (inverse of scaling)
        if ip_raw > 0:
            ip = (ip_raw - 128) / 127.0
        else:
            ip = 0.0
            
        # Interpolate normal
        n = interpolate_vector(grad_f, grad_b, ip)
        
        # Compute lighting
        # Note: Specular power is fixed at 16 in implementation
        diffuse_term = dot_product(n, light_dir_diffuse)
        specular_term = dot_product(n, light_dir_specular) ** 16
        
        final_color = ambient + diffuse * c_pre * diffuse_term + specular * c_pre * specular_term
        alpha = alpha_pre
    else:
        final_color = c_pre
        alpha = alpha_pre
        
    # 5. Blend
    blend_into_framebuffer(final_color, alpha)
```

**Parameters:**
*   **Specular Power:** 16 [S1].
*   **Lookup Table Dimensionality:** 2D, depending on front and back scalar values, assuming constant ray segment length [S1].
*   **Texture Bit Depth:** 8-bit for direct volume rendering; 32-bit for isosurface rendering [S1].
*   **Constant Vector for Scalar Extraction:** $\mathbf{v} = (1, 0, 0)^T$ [S1].

**Edge Cases and Pitfalls:**
*   **Division in Register Combiners:** Calculating $IP$ on-the-fly requires division, which is unavailable. Solution: Pre-calculate $IP$ for all scalar combinations [S1].
*   **Texture Operation Limit:** NVIDIA’s texture shader allows only four operations. Two are used for dot products, leaving only one for dependent lookup. Solution: Store $IP$ in the same dependent texture used for color/opacity [S1].
*   **Double-Rendering of Semi-Transparent Isosurfaces:** Pixels may be rendered twice if the surface intersects exactly at the front slice of one slab and the back slice of the next. Solution: Use the OpenGL stencil buffer. Clear stencil for each slab. Render slab into stencil using a second dependent texture that selects only pixels where the isosurface intersects at the front slice. In the next slab, use stencil test to only set pixels not rendered previously [S1]. This works only for a single semi-transparent isosurface [S1].
*   **Variable Ray Segment Lengths:** For object-aligned slices, ray segment lengths vary with volume rotation (max factor $\sqrt{3}$). Solution: Use a set of 2D lookup tables for different lengths [S1]. For unequal slice distances, different lookup textures must be calculated [S1].
*   **Transparency Constraint (Approach 1):** Storing $IP$ in Alpha makes transparency constant. Solution: Scale Alpha by 2 to get 1.0 for intersecting segments and 0 otherwise, then multiply by constant transparency [S1].
*   **Interpolation Range Mapping:** $IP$ stored in range 0.5-1.0 (after scaling) requires specific input mappings. Solution: Use `GL_HALF_BIAS_NORMAL_NV` and `GL_UNSIGNED_INVENT_NV` for general combiner 2 to map ranges 0-0.5 and 0.5-0, then scale result by 2 [S1].

## Operating characteristics
*   **Time Complexity:** Does not depend on the number of isosurfaces nor the definition of the transfer functions [S1].
*   **Memory Complexity:** Dependent textures consume significant memory. RGBA textures for dynamic lighting consume more memory than LUMINANCE_ALPHA for static lighting (half the memory) [S1].
*   **Performance (NVIDIA GeForce3, 64 MB DDR SDRAM, 200 MHz, 4x AGP, 512x512 viewport):**
    *   **Direct Volume Rendering:** ~90 fps (16³), ~50 fps (32³), ~21 fps (64³), ~13 fps (128³), ~4 fps (256³) [S1].
    *   **Isosurface Rendering:** ~70 fps (16³), ~40 fps (32³), ~21 fps (64³), ~11 fps (128³), ~1 fps (256³) [S1].
*   **Strengths:** High image quality without additional interpolated slices; interactive transfer function updates are fast for isosurfaces; supports arbitrary number of isosurfaces without performance penalty [S1].
*   **Limitations:** Requires specific hardware extensions (NVIDIA texture shader, register combiners); 3D texture support was not available in driver releases at the time, necessitating 2D workarounds; stencil buffer correction is limited to a single semi-transparent isosurface [S1].
*   **When to Use:** When high-quality volume rendering with lighting is required on hardware supporting dependent texture lookups, and interactive transfer function updates are needed [S1].
*   **When Not to Use:** On hardware lacking the required OpenGL extensions or 3D texture support; when multiple semi-transparent isosurfaces need to be rendered simultaneously with the stencil correction [S1].

## Background
Originated in a hardware-accelerated implementation on the NVIDIA GeForce3 graphics chip [S1]. The method leverages the OpenGL texture shader extension and register combiners, which were merged into Microsoft’s DirectX8 pixel shader API, though the DirectX8 API was found to be more restrictive (specifically regarding dot product references) [S1]. The approach was developed to overcome the limitations of pre-shading (slicing artifacts) and post-shading (need for additional slices) [S1].
