# Simplified Pre-integration

Also called: Pré-integração Simplificada, Simplified Pre-integrated Volume Rendering

## Overview
Simplified pre-integration is a faster approximation of full pre-integration used in direct volume ray casting to accelerate interactive transfer function (TF) editing [S1][S3, unofficial]. It solves the performance bottleneck of computing volume rendering integrals in real-time by neglecting color attenuation inside volume slabs, allowing for the pre-computation of color and opacity contributions based on scalar values and distance [S1][S2, S3, unofficial]. It is distinguished from full pre-integration by its omission of the exponential attenuation term within the lookup table calculation, trading visual accuracy for significant performance gains [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume texture, a transfer function (TF) mapping scalar values to color and opacity, and the distance between sample points [S2, unofficial].
*   **Output:** A pre-integration lookup table (LUT) containing pre-computed color and opacity values [S2, unofficial].

**Data Structures:**
*   **Volume Data:** Stored in GPU memory as a 3D texture with 8-bit precision per component [S1].
*   **Transfer Function:** Represented as a lookup table with 256 entries [S1].
*   **Pre-integration Table:** Typically stored as a 3D texture accessed by scalar values $(s_1, s_2)$ on the x/y-axes and distance $d$ on the z-axis [S2, unofficial]. In the cited implementation, simplified pre-integration results are stored as 2D RGBA textures [S1].

**Method Steps:**
1.  **Pre-computation:** For each pair of scalar values $(s_1, s_2)$ sampled at two different positions along a ray and the distance $d$ between them, compute the color and opacity contributions using the transfer function [S2, unofficial].
2.  **Simplified Integral Calculation:** Compute the integral approximation by neglecting the color attenuation term [S3, unofficial]. In full pre-integration, the contribution of a segment is weighted by the accumulated opacity of previous segments [G]. In simplified pre-integration, this attenuation is disregarded [S3, unofficial]. The standard volume rendering integral $C = \int c(s) \alpha(s) e^{-\int_0^s \alpha(t) dt} ds$ is approximated by removing the exponential decay factor [S1][S3, unofficial].
3.  **Storage:** Store the resulting color and opacity values in the lookup table [S2, unofficial].
4.  **Rasterization:** During rendering, access the pre-integration table using the scalar values sampled at the ray segment endpoints and the segment distance [S2, unofficial].
5.  **Compositing:** Combine the retrieved pre-computed color and opacity values into the accumulated final color for the pixel [S2, unofficial].

**Pseudocode:**
```python
def compute_simplified_pre_integration_table(s_min, s_max, d_max, num_s, num_d, transfer_function):
    """
    Pre-computes the simplified pre-integration lookup table.
    Args:
        s_min, s_max: Scalar value range.
        d_max: Maximum segment distance.
        num_s, num_d: Discretization steps for scalars and distance.
        transfer_function: Callable mapping scalar -> (color, opacity).
    Returns:
        LUT: 3D list of (color, opacity) tuples.
    """
    # Initialize 3D LUT: LUT[s1_idx, d_idx, s2_idx]
    LUT = [[[None for _ in range(num_d)] for _ in range(num_s)] for _ in range(num_s)]
    
    s_values = [s_min + i * (s_max - s_min) / (num_s - 1) for i in range(num_s)]
    d_values = [i * d_max / (num_d - 1) for i in range(num_d)]
    
    for i, s1 in enumerate(s_values):
        c1, a1 = transfer_function(s1)
        for j, s2 in enumerate(s_values):
            c2, a2 = transfer_function(s2)
            for k, d in enumerate(d_values):
                # Simplified calculation: linear interpolation of color and opacity
                # without the exponential attenuation term [G]
                t = d / d_max if d_max > 0 else 0.0
                avg_color = (c1 * (1 - t) + c2 * t)
                avg_opacity = a1 * (1 - t) + a2 * t
                # Accumulate linearly over distance without attenuation
                contribution_color = avg_color * avg_opacity * d
                contribution_opacity = avg_opacity * d
                LUT[i][k][j] = (contribution_color, contribution_opacity)
    return LUT
```

**Parameters:**
*   **TF Entries:** 256 entries are typical for the transfer function lookup tables [S1].
*   **Volume Precision:** 8-bit precision is used for the 3D texture storage [S1].
*   **Interaction Level:** Simplified pre-integration is applied when multiple TFs are modified simultaneously (e.g., 36 TFs) to maintain interactivity [S1]. Full pre-integration is used when a single TF is modified [S1].

**Edge Cases and Pitfalls:**
*   **Discretization Artifacts:** The method assumes a linear progression of scalar values between slices, which can introduce discretization artifacts [S2, unofficial]. An adaptive sampling approach can mitigate this by adjusting the sampling rate based on volume and TF information [S2, unofficial].
*   **Color Deviation:** Neglecting attenuation results in a deviation in the calculation of the total color contribution at each pixel compared to the physically correct result [S3, unofficial].
*   **Performance vs. Quality:** While it guarantees superior performance, the visual quality is lower than full pre-integration [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Faster than full pre-integration due to the omission of the attenuation term [S1][S3, unofficial].
*   **Memory Complexity:** Stores pre-computed values in textures. The cited implementation uses 2D RGBA textures for the simplified case [S1], whereas full pre-integration typically uses 3D textures [S2, unofficial].
*   **Performance:** Guarantees superior performance, although of the same order of magnitude as efficient full pre-integration algorithms like Lum et al. [S3, unofficial].
*   **Strengths:** Enables real-time interaction when modifying multiple transfer functions simultaneously [S1].
*   **Limitations:** Introduces visual artifacts due to the neglect of color attenuation and linear scalar interpolation assumptions [S2, S3, unofficial].
*   **When to Use:** Interactive editing interfaces where multiple TFs are adjusted at once [S1].
*   **When Not to Use:** Single-TF editing or final rendering where higher visual fidelity is required, as full pre-integration is applied in those contexts [S1].

## Background
*   **Origin:** The concept is described in the context of volume visualization and exploration through flexible transfer function design [S1]. It is also discussed in surveys of GPU-based volume rendering [S2, unofficial] and in the specification of 1D and multidimensional transfer functions [S3, unofficial].
*   **History:** The technique is presented as an alternative to full pre-integration [S3, unofficial] to handle the computational cost of per-fragment operations [S2, unofficial]. It is used in dual-domain interaction interfaces for TF design [S1].
*   **Usage:** Used in volume visualization tools to allow interactive modification of multiple transfer functions [S1].
