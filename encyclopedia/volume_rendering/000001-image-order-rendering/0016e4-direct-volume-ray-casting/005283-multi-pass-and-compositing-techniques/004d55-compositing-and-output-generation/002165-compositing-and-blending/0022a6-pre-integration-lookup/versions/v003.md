# Pre-Integration Lookup

Also called: 3D Pre-Integration Table, Pre-integrated Transfer Functions

## Overview
Pre-Integration Lookup is a method for direct volume ray casting that pre-calculates the optical properties (color and opacity) of volume slabs, assuming linear evolution of scalar data within each slab [S1, unofficial]. It solves the problem of accurately integrating light transport and color attenuation over a sampling step without performing expensive per-sample integration during rendering [S1, unofficial]. It sets itself apart from standard compositing [Compositing](2436-compositing.md) by replacing the iterative accumulation of individual sample contributions with a single lookup into a 3D texture, thereby reducing aliasing artifacts from under-sampling and improving performance [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset, a transfer function (TF) mapping scalar values to color and opacity, and a ray path through the volume.
*   **Output:** The final pixel color for each ray.

**Data Structures:**
*   **Pre-Integration Table (PIT):** A 3D texture (or 3D lookup table) storing pre-computed optical properties. The dimensions are typically $256 \times 256 \times 256$ for 8-bit scalar data [S2].
    *   **Indices:** The three dimensions correspond to:
        1.  Front sample scalar value ($s_f$).
        2.  Middle sample scalar value ($s_m$).
        3.  Back sample scalar value ($s_b$).
    *   **Values:** RGBA color and opacity resulting from the integration of the transfer function between $s_f$ and $s_b$ over the slab thickness [S2].
*   **Volume Data:** Stored as a 3D texture in GPU memory [S4].

**Method Steps:**
1.  **Pre-computation (Offline/Initialization):**
    *   Define the transfer function $TF(s) = (c(s), \alpha(s))$ where $s$ is the scalar value [S2].
    *   Assume linear interpolation of scalar values between samples. For a slab defined by front sample $s_f$, middle sample $s_m$, and back sample $s_b$, the scalar value $s(t)$ at position $t$ along the slab (normalized $0 \le t \le 1$) is interpolated [S1, unofficial].
    *   Compute the integrated color $C$ and opacity $\alpha$ for the slab by integrating the Beer-Lambert law over the slab thickness. The standard front-to-back compositing equations are integrated analytically or numerically for the linear scalar path:
        $$ C_{slab} = \int_0^1 c(s(t)) \alpha(s(t)) e^{-\int_0^t \alpha(s(u)) du} dt $$
        $$ \alpha_{slab} = 1 - e^{-\int_0^1 \alpha(s(t)) dt} $$
    *   Store $(C_{slab}, \alpha_{slab})$ in the 3D Pre-Integration Table at index $(s_f, s_m, s_b)$ [S1, unofficial][S2].
    *   *Note:* Simplified pre-integration may neglect color attenuation inside the slab for faster computation, storing only opacity or using approximations [S4].

2.  **Rendering (Per Ray):**
    *   For each pixel, cast a ray through the volume.
    *   Divide the ray into slabs. Each slab is defined by three successive scalar samples from the volume data: front ($s_f$), middle ($s_m$), and back ($s_b$) [S2].
    *   **Lookup:** Perform a 3D texture fetch using the indices $(s_f, s_m, s_b)$ to retrieve the pre-computed slab color $C_{slab}$ and opacity $\alpha_{slab}$ [S2].
    *   **Compositing:** Blend the retrieved slab properties into the accumulated color using standard front-to-back compositing:
        $$ C'_{i} = C'_{i-1} + C_{slab} \cdot \alpha_{slab} \cdot (1 - \alpha'_{i-1}) $$
        $$ \alpha'_{i} = \alpha'_{i-1} + \alpha_{slab} \cdot (1 - \alpha'_{i-1}) $$
        where $C'_{i-1}$ and $\alpha'_{i-1}$ are the accumulated color and opacity from previous slabs [S2].
    *   **Early Ray Termination:** If $\alpha'_{i}$ exceeds a threshold (e.g., $0.99$), terminate the ray [S2].

**Pseudocode:**
```python
# Pre-computation (done once or when TF changes)
def compute_pre_integration_table(tf, num_samples=256):
    """
    Computes the 3D Pre-Integration Table.
    tf: function mapping scalar s -> (color, opacity)
    num_samples: resolution of the table (e.g., 256)
    """
    table = empty_3d_texture(num_samples, num_samples, num_samples)
    
    # Iterate over all possible front, middle, back scalar values
    for sf in range(num_samples):
        for sm in range(num_samples):
            for sb in range(num_samples):
                # Assume linear scalar interpolation between sf, sm, sb
                # Integrate optical properties over the slab
                # This step involves numerical integration of the Beer-Lambert law
                # for the path defined by tf(sf), tf(sm), tf(sb)
                slab_color, slab_opacity = integrate_slab_optical_properties(sf, sm, sb, tf)
                table[sf, sm, sb] = (slab_color, slab_opacity)
    return table

def integrate_slab_optical_properties(sf, sm, sb, tf):
    """
    Integrates color and opacity for a slab with linear scalar evolution.
    Returns (color, opacity).
    """
    # Discretize the slab into small steps for numerical integration
    steps = 10
    total_alpha = 0.0
    total_color = (0.0, 0.0, 0.0)
    
    for i in range(steps):
        t = i / steps
        t_next = (i + 1) / steps
        
        # Interpolate scalar values linearly
        s_t = lerp(sf, sm, t) if t < 0.5 else lerp(sm, sb, (t - 0.5) * 2)
        s_t_next = lerp(sf, sm, t_next) if t_next < 0.5 else lerp(sm, sb, (t_next - 0.5) * 2)
        
        # Get TF values
        c_t, a_t = tf(s_t)
        c_next, a_next = tf(s_t_next)
        
        # Average TF values for the step
        c_avg = (c_t + c_next) / 2.0
        a_avg = (a_t + a_next) / 2.0
        
        # Integrate Beer-Lambert law for this step
        # Contribution = c_avg * a_avg * exp(-a_avg * step_size)
        # Note: step_size is normalized to 1.0 for the whole slab
        step_size = 1.0 / steps
        transmittance = exp(-a_avg * step_size)
        
        total_color += c_avg * a_avg * transmittance
        total_alpha += a_avg * transmittance # Accumulate opacity contribution
        
    # Normalize and finalize
    # Note: Exact integration formula may vary based on implementation details
    return total_color, 1.0 - exp(-total_alpha)

# Rendering
def render_with_pre_integration(ray, volume_tex, pit, tf):
    """
    Renders a single ray using the Pre-Integration Table.
    """
    accum_color = (0.0, 0.0, 0.0)
    accum_alpha = 0.0
    
    # Traverse the ray, dividing it into slabs
    # Each slab is defined by 3 samples: sf, sm, sb
    for slab in ray.slabs:
        sf = volume_tex.sample(slab.front)
        sm = volume_tex.sample(slab.middle)
        sb = volume_tex.sample(slab.back)
        
        # Fetch pre-integrated properties
        slab_color, slab_opacity = pit.sample(sf, sm, sb)
        
        # Front-to-back compositing
        weight = slab_opacity * (1.0 - accum_alpha)
        accum_color += slab_color * weight
        accum_alpha += weight
        
        # Early ray termination
        if accum_alpha > 0.99:
            break
            
    return accum_color
```

**Parameters:**
*   **Table Resolution:** Typically $256^3$ for 8-bit data [S2]. Higher resolutions increase accuracy but memory usage grows cubically.
*   **Slab Thickness:** Determined by the sampling rate of the volume data [S2].

**Edge Cases and Pitfalls:**
*   **Memory Usage:** The $256^3$ table requires significant GPU memory (e.g., $256^3 \times 4$ bytes $\approx 64$ MB for RGBA, or more if storing additional data) [S2].
*   **Interpolation Errors:** Assuming linear scalar evolution may introduce errors if the actual data varies non-linearly within the slab [S1, unofficial].
*   **Color Attenuation:** Simplified pre-integration neglects color attenuation, which may reduce visual quality [S4].

## Subtopics

### [Pre-Integrated Diffuse Shading with Non-Linear Gradient Interpolation](4932-pre-integrated-diffuse-shading-with-non-linear-gradient-inte.md)
This method computes the diffuse component of Blinn-Phong shading in direct volume ray casting by approximating the integral of light interaction over a sampling step using non-linear gradient interpolation [4932-pre-integrated-diffuse-shading-with-non-linear-gradient-inte.md]. It decomposes the shading integral into four 2D look-up tables (LUTs) indexed by front and back scalar values, weighted by coefficients derived from light direction and gradient angles. It sets itself apart from linear gradient interpolation by reducing shading errors caused by large angles between consecutive sample gradients, while avoiding the prohibitive memory cost of full 4D normal-based pre-integration.

### [Non-Linear Gradient Interpolation for Pre-Integrated Volume Rendering](4933-non-linear-gradient-interpolation-for-pre-integrated-volume-.md)
Non-linear gradient interpolation is a technique for pre-integrated direct volume rendering that reduces shading errors by interpolating gradients between front and back samples along a quadratic curve instead of a linear segment, allowing accurate computation of 2D pre-integration look-up tables. It sets itself apart from linear gradient interpolation by approximating the non-linear path of a normalized gradient vector as a quadratic polynomial, thereby avoiding the energy loss and shading errors inherent in linear interpolation which assumes the normalization term $\eta(t)=1$.

### Pre-integrated Volume Rendering with Shading
A method for efficiently reconstructing 3D medical images that combines pre-integrated volume rendering with the Shear-Warp algorithm to eliminate aliasing artifacts from under-sampling and improve reconstruction quality via Phong lighting shading [S3, unofficial]. It implements classification coding for volume data using the correlation of the opacity transfer function and a min-max Octree data structure, establishing a run-length encoded (RLE) data structure for fast reconstruction when the opacity transfer function and view angle change [S3, unofficial]. It incorporates pre-integrated volume rendering with Phong lighting shading calculation to eliminate aliasing artifacts [S3, unofficial].

### Simplified Pre-integration
A faster approximation of pre-integration that neglects color attenuation inside volume slabs, used in the first level of interaction where multiple transfer functions are modified [S4]. It is applied in the first level of the interface to handle actions that modify several TFs simultaneously, while full pre-integration is applied in the second level where a single TF is under modification to maintain quality without compromising interactivity [S4].

## Operating characteristics
*   **Time Complexity:** Rendering time is reduced to a single 3D texture fetch per slab plus standard compositing, which is $O(1)$ per slab compared to $O(N)$ per sample in standard integration [S2].
*   **Memory Complexity:** Requires $O(N^3)$ memory for the pre-integration table, where $N$ is the number of scalar levels (e.g., $256^3$) [S2].
*   **Performance:** Implemented on GPU for real-time performance [S1, unofficial]. The Shear-Warp variant improves reconstruction speed for medical images [S3, unofficial].
*   **Strengths:** Reduces aliasing, improves performance, and allows for complex shading integrations via pre-computation [S3, unofficial].
*   **Limitations:** High memory consumption for high-resolution tables; assumes linear scalar evolution which may not hold for all data [S1, unofficial]. Simplified versions may lose visual fidelity [S4].
*   **When to use:** Real-time volume rendering where aliasing is a concern and memory allows for large lookup tables [S2].
*   **When not to use:** When memory is constrained or data varies non-linearly within slabs [S1, unofficial].

## Background
Pre-integration lookup was introduced to address the computational cost and aliasing issues in direct volume rendering [S1, unofficial]. It was implemented on GPU in early 2000s [EKE01, RE02] as cited in [S1, unofficial]. The method assumes linear evolution of data within volume slices [S1, unofficial]. Variants incorporating shading and Shear-Warp algorithms were developed for medical image reconstruction [S3, unofficial]. Simplified versions were proposed for interactive transfer function design [S4].
