# Spatial Convolution

Also called: Direct Spatial Convolution, Discrete Convolution, Spatial Domain Convolution

## Overview
Spatial convolution is a neighborhood-based operation where output values are calculated from neighboring input samples using a filter kernel [S2, unofficial]. In volume rendering, it convolves discrete samples with a reconstruction kernel in the spatial domain [S1, unofficial]. It is distinguished from frequency-domain methods by operating directly on spatial data, which is preferred for discrete kernels of limited extent because transforming to and from the frequency domain is more compute-intensive than direct spatial convolution [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Discrete signal $f$ or $\mathbf{L}$ [S1, S2, unofficial].
- Input: Filter kernel $h$ or $\mathbf{K}$ [S1, S2, unofficial].
- Output: Convolved signal $g$ or $\mathbf{L}'$ [S1, S2, unofficial].

**Data Structures:**
Not given in the sources.

**Formulas:**
The continuous convolution integral is defined as [S1, unofficial]:
$$g(t) = \int_{-\infty}^{\infty} f(u)h(t-u) du$$
In two dimensions:
$$g(x, y) = \int_{-\infty}^{\infty} \int_{-\infty}^{\infty} f(u, v) h(x - u, y - v) du dv$$
In three dimensions:
$$g(x, y, z) = \int_{-\infty}^{\infty} \int_{-\infty}^{\infty} \int_{-\infty}^{\infty} f(u, v, w) h(x - u, y - v, z - w) du dv dw$$

For discrete signals, this becomes the convolution sum [S1, unofficial]:
$$g(x, y, z) = \sum_{i=-\infty}^{\infty} \sum_{j=-\infty}^{\infty} \sum_{k=-\infty}^{\infty} f(i, j, k) h(x - i, y - j, z - k)$$

In 2D discrete notation often used in image processing [S2, unofficial]:
$$(\mathbf{L} * \mathbf{K})(\mathbf{x}) = \sum_{\mathbf{x}'} \mathbf{L}(\mathbf{x}') \mathbf{K}(\mathbf{x}' - \mathbf{x})$$
where the sum iterates over all pixel positions or only the neighborhood of $\mathbf{x}$ [S2, unofficial].

**Parameters:**
- Kernel size: Typically small in volume rendering algorithms [S1, unofficial].
- Normalization: The sum of all kernel values should equal 1 for energy conservation:
$$\sum_{\mathbf{x}} K(\mathbf{x}) = 1$$ [S2, unofficial].

**Steps:**
1. For each output sample position $\mathbf{x}$, initialize an accumulator to zero [S1, S2, unofficial].
2. Iterate over the kernel support (neighborhood $\mathbf{x}'$) [S2, unofficial].
3. Retrieve the input sample value $\mathbf{L}(\mathbf{x}')$ and the kernel weight $\mathbf{K}(\mathbf{x}' - \mathbf{x})$ [S2, unofficial].
4. Multiply the sample value by the kernel weight and add to the accumulator [S2, unofficial].
5. Store the accumulator value in the output at $\mathbf{x}$ [S1, S2, unofficial].

**Pseudocode:**
```python
def spatial_convolution(input_signal, kernel):
    in_h, in_w, in_d = input_signal.shape
    k_h, k_w, k_d = kernel.shape
    output = [[[0.0 for _ in range(in_d)] for _ in range(in_w)] for _ in range(in_h)]
    
    kh_half, kw_half, kd_half = k_h // 2, k_w // 2, k_d // 2
    
    for x in range(in_h):
        for y in range(in_w):
            for z in range(in_d):
                acc = 0.0
                for dx in range(-kh_half, kh_half + 1):
                    for dy in range(-kw_half, kw_half + 1):
                        for dz in range(-kd_half, kd_half + 1):
                            nx, ny, nz = x + dx, y + dy, z + dz
                            if 0 <= nx < in_h and 0 <= ny < in_w and 0 <= nz < in_d:
                                acc += input_signal[nx][ny][nz] * kernel[dx + kh_half][dy + kw_half][dz + kd_half]
                output[x][y][z] = acc
    return output
```

**Edge Cases and Pitfalls:**
- **Normalization:** Discrete convolution of a normalized continuous function (like a Gaussian) is not normalized because sampling at discrete values breaks normalization, violating energy conservation [S2, unofficial]. To fix this, sum the values of the kernel and multiply the whole kernel by the reciprocal value [S2, unofficial].
- **Boundary Conditions:** Boundary handling is not specified in the sources; implementations typically use zero-padding or clamping to avoid out-of-bounds access [G].

## Subtopics

### [Separable Convolution](14593-separable-convolution.md)
Separable convolution is a method to accelerate hologram computation by exploiting the linear separability of the lens phase function $f_z$ into independent horizontal and vertical components. It solves the performance bottleneck of point-wise integration in direct volume ray casting for holographic displays by reducing the computational complexity of the spatial convolution operation. It is distinguished from FFT-based convolution by its reliance on spatial separability rather than frequency-domain transformation, making it faster for smaller sub-hologram sizes but inapplicable when the phase function is not separable.

### Spatially Varying Kernel Filtering
Filtering where each pixel has a different distribution/kernel, defined by weighting functions $w_{\mathbf{x}'}(\mathbf{x}' - \mathbf{x})$, which is not a standard convolution [S2, unofficial]. The formula is:
$$\mathbf{L}'(\mathbf{x}) = \sum_{\mathbf{x}'} w_{\mathbf{x}'}(\mathbf{x}' - \mathbf{x})\mathbf{L}(\mathbf{x}')$$ [S2, unofficial].
Unlike standard convolution, spatially varying kernels cannot be solved using convolution algorithms or FFT, requiring alternative algorithms like splatting or gathering [S2, unofficial].

## Operating characteristics
- **Time Complexity:** For an image size $n \times n$ and kernel size $m \times m$, the time complexity is generally $O(n^2 m^2)$ [S2, unofficial].
- **Memory Complexity:** Not given in the sources.
- **Performance:** Preferred over frequency domain multiplication for discrete kernels of limited extent because transforming back and forth is more compute-intensive than direct spatial convolution [S1, unofficial]. However, for discrete kernels with a large extent, the convolution will be more compute-intensive [S1, unofficial].
- **Strengths:** Direct spatial domain operation avoids FFT overhead; efficient for small kernels [S1, unofficial].
- **Limitations:** High computational cost for large kernels; normalization issues with sampled continuous functions; not applicable for spatially varying kernels without alternative algorithms [S2, unofficial].

## Background
The mathematical foundation is based on the convolution integral and sum [S1, unofficial]. It is widely used in volume rendering algorithms to convolve samples with reconstruction kernels in the spatial domain [S1, unofficial].
