# Ray Compositing for Training (Uncertainty)

## Overview
This method composites rays for training neural radiance fields by estimating and backpropagating uncertainty alongside standard volume rendering outputs (RGB, sigma, ambient light) [S1, unofficial]. It differs from standard training compositing by explicitly computing gradients for an uncertainty term, allowing the model to learn confidence metrics per pixel [S1, unofficial]. It builds on [Training Ray Compositing (Sigma)](3868-training-ray-compositing-sigma.md) by extending the output space to include uncertainty.

## How it works
**Inputs:**
- `sigma`: Tensor of volume densities, shape `[N, num_samples]` [S1, unofficial].
- `rgb`: Tensor of colors, shape `[N, num_samples, 3]` [S1, unofficial].
- `ambient`: Tensor of ambient light, shape `[N, num_samples, amb_dim]` [S1, unofficial].
- `uncertainty`: Tensor of per-sample uncertainty values (betas), shape `[N, num_samples]` [S1, unofficial].
- `T_thresh`: Float threshold for transmittance culling, default `1e-4` [S1, unofficial].

**Outputs:**
- `rgb_out`: Composite RGB, shape `[N, 3]`.
- `sigma_out`: Composite sigma, shape `[N]`.
- `ambient_out`: Composite ambient, shape `[N, amb_dim]`.
- `uncertainty_out`: Composite uncertainty, shape `[N]`.
- `weights`: Transmittance weights, shape `[N, num_samples]` (saved for backward).
- `uncertainty_sum`: Intermediate sum for backward pass, shape `[N]` (saved for backward).

**Data Structures:**
- Tensors are assumed to be contiguous in memory. If not, they are made contiguous before kernel invocation [S1, unofficial].

**Algorithm:**

1.  **Preprocessing:** Ensure `uncertainty` tensor is contiguous. Allocate `uncertainty_sum` tensor of size `[N]` initialized to zeros [S1, unofficial].
2.  **Forward Pass:** Call the CUDA kernel `_backend.composite_rays_train_uncertainty_forward`. This kernel performs the standard volume rendering integration for RGB, sigma, and ambient, while simultaneously accumulating the weighted uncertainty.
    - The composite uncertainty is calculated as:
      $$ \text{uncertainty\_out}_i = \sum_{j=1}^{M} w_{i,j} \cdot \beta_{i,j} $$
      where $w_{i,j}$ is the transmittance weight for ray $i$ at sample $j$, and $\beta_{i,j}$ is the per-sample uncertainty [S2, unofficial].
    - The kernel uses `T_thresh` to cull samples where transmittance drops below the threshold [S1, unofficial].
3.  **Save State:** Save `uncertainty`, `uncertainty_sum`, `weights`, and other necessary tensors for the backward pass [S1, unofficial].
4.  **Backward Pass:**
    - Ensure `grad_uncertainty_sum` (gradient of the loss w.r.t `uncertainty_out`) is contiguous.
    - Initialize `grad_uncertainty` tensor with zeros, shape `[N, num_samples]` [S1, unofficial].
    - Call the CUDA kernel `_backend.composite_rays_train_uncertainty_backward`. This kernel computes gradients for `sigma`, `rgb`, `ambient`, and `uncertainty` using the saved forward state [S1, unofficial].

**Pseudocode:**

    # T_0 = 1.0
    # For j in 0..num_samples-1:
    #   alpha = 1.0 - exp(-sigma[j] * dist[j])
    #   w = alpha * T_j
    #   rgb_out += w * rgb[j]
    #   sigma_out += w * sigma[j]
    #   ambient_out += w * ambient[j]

    Backward pass for training ray compositing with uncertainty.
    """

    if not grad_uncertainty_out.is_contiguous():
        grad_uncertainty_out = grad_uncertainty_out.contiguous()

    N, num_samples = sigma.shape
    amb_dim = ambient.shape[2]

    # Initialize gradients
    grad_sigma = torch.zeros_like(sigma)
    grad_rgb = torch.zeros_like(rgb)
    grad_ambient = torch.zeros_like(ambient)
    grad_uncertainty = torch.zeros_like(uncertainty)

    # Call CUDA kernel

**Edge Cases and Pitfalls:**
- Non-contiguous tensors cause kernel launch failures or incorrect results. Always ensure contiguity [S1, unofficial].
- `T_thresh` must be small enough to avoid premature culling but large enough to prevent numerical instability in transmittance calculations [S1, unofficial].
- Degenerate input (e.g., zero-length rays) should be handled by the backend kernel, typically resulting in zero outputs [G].

## Subtopics

### Uncertainty Rendering
Calculates uncertainty along a ray by weighting per-sample uncertainty betas by transmittance weights [S2, unofficial]. It is a simplified variant that focuses solely on the uncertainty accumulation formula $\text{uncertainty} = \sum \text{weights} \times \text{betas}$ without the full training backward pass for sigma/RGB [S2, unofficial]. Choose this when only uncertainty estimation is needed for inference or debugging, not for gradient-based training of the full model [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Linear in the number of rays $N$ and samples $M$, $O(N \cdot M)$, due to the per-sample integration [S1, unofficial].
- **Memory Complexity:** $O(N \cdot M)$ for storing weights and intermediate tensors [S1, unofficial].
- **Performance:** Depends on the efficiency of the CUDA kernel `_backend.composite_rays_train_uncertainty_forward` and `_backward` [S1, unofficial].
- **Strengths:** Enables uncertainty-aware training, potentially improving robustness in occluded or sparse regions [S1, unofficial].
- **Limitations:** Increased memory usage due to storing uncertainty gradients and intermediate sums [S1, unofficial].

## Background
Originated in the context of neural radiance field training frameworks that support uncertainty estimation, specifically referenced in the ER-NeRF project [S1, unofficial]. It extends the standard volume rendering compositing to include uncertainty gradients, allowing the network to learn confidence metrics [S1, unofficial].
