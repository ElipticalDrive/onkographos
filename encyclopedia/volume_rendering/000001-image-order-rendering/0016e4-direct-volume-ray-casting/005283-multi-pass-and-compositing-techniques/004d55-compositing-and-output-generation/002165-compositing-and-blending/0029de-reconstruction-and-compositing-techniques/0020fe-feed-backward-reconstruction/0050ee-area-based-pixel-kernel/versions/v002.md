# Area-based Pixel Kernel

Also called: Area kernel, Noyau de Pixel basé sur l’aire (Area-based Pixel Kernel), Noyau d’interpolation sur l’aire des pixels

## Overview
The Area-based Pixel Kernel is a reconstruction kernel that assigns pixel contributions proportional to the geometric area of intersection between a pixel and a thick projection line [S1, unofficial]. It solves the artifact issues inherent in Dirac and B-Spline kernels, which leave unreconstructed pixels during subsampling, and linear kernels, which fail to fully exploit available data during oversampling [S1, unofficial]. It is distinguished from its sibling [Spatial Convolution](2513-spatial-convolution.md) by its specific geometric interpretation of projection thickness and its optimization via a rotation-based approximation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Projection data $p(\theta, \rho)$, where $\theta$ is the angle and $\rho$ is the radial coordinate; pixel grid coordinates $(i, j)$; projection line thickness $d\rho$; pixel size $\Delta p$ [S1, unofficial].
*   **Outputs:** Reconstructed image intensity $I(i, j)$ [S1, unofficial].

**Data Structures:**
*   **Projection Buffer:** Array of values indexed by $(\theta, \rho)$ [S1, unofficial].
*   **Temporary Image $I_\theta$:** A 2D array used to store the backprojected contributions for a specific angle $\theta$ before rotation [S1, unofficial].
*   **Result Image $I$:** The final accumulated 2D array [S1, unofficial].

**Parameters:**
*   $d\rho$: Thickness of the projection line [S1, unofficial].
*   $\Delta p$: Pixel width [S1, unofficial].
*   $\theta$: Current projection angle [S1, unofficial].
*   $\rho$: Radial position of the projection line [S1, unofficial].
*   $i, j$: Integer pixel coordinates [S1, unofficial].

**Numbered Steps:**
1.  Initialize the result image $I$ to zero [S1, unofficial].
2.  For each projection angle $\theta$:
    a.  Create a temporary image $I_\theta$ of the same dimensions as $I$, initialized to zero [S1, unofficial].
    b.  For each radial sample $\rho$ in the projection $p(\theta, \cdot)$:
        i.  Calculate the kernel weight $\Lambda(\phi=0, \rho, i, j)$ for every pixel $(i, j)$ in $I_\theta$ using the formula below [S1, unofficial].
        ii. Add the contribution $p(\theta, \rho) \times \Lambda(\phi=0, \rho, i, j)$ to $I_\theta(i, j)$ [S1, unofficial].
    c.  Rotate the temporary image $I_\theta$ by the angle $-\theta$ [S1, unofficial].
    d.  Add the rotated $I_\theta$ to the result image $I$ [S1, unofficial].

**Formula:**
The kernel $\Lambda(\phi=0, \rho, i, j)$ for the approximation where the projection is aligned with the axes ($\phi=0$) is defined as [S1, unofficial]:

$$
\Lambda(\phi=0, \rho, i, j) = 
\begin{cases} 
d\rho & \text{if } [\rho - d\rho/2] = [\rho + d\rho/2] = [\rho] = i \\
\frac{d\rho + \Delta p}{2} + |\rho - i| & \text{if } [\rho - d\rho/2] < i \land [\rho + d\rho/2] = i \\
1 & \text{if } [\rho - d\rho/2] < i \land [\rho + d\rho/2] > i \\
0 & \text{otherwise}
\end{cases}
$$

Where $[\cdot]$ is the round function returning the nearest integer to the real parameter [S1, unofficial].

**Pseudocode:**
```python
import math

def area_kernel_weight(rho, d_rho, delta_p, pixel_i):
    """Calculates the kernel weight for a single pixel i given rho, d_rho, and delta_p."""
    def round_to_int(x):
        return int(math.floor(x + 0.5))

    rho_low = rho - d_rho / 2.0
    rho_high = rho + d_rho / 2.0
    
    i_low = round_to_int(rho_low)
    i_high = round_to_int(rho_high)
    i_mid = round_to_int(rho)
    
    if i_low == i_high == i_mid == pixel_i:
        return d_rho
    if i_low < pixel_i and i_high == pixel_i:
        return (d_rho + delta_p) / 2.0 + abs(rho - pixel_i)
    if i_low < pixel_i and i_high > pixel_i:
        return 1.0
    return 0.0

def backproject_area_kernel(projections, image_shape, d_rho, delta_p):
    """Reconstructs an image using the Area-based Pixel Kernel approximation."""
    height, width = image_shape
    result_image = [[0.0 for _ in range(width)] for _ in range(height)]
    
    for theta, rho_values in projections:
        temp_image = [[0.0 for _ in range(width)] for _ in range(height)]
        
        for rho, value in rho_values:
            rho_low = rho - d_rho / 2.0
            rho_high = rho + d_rho / 2.0
            
            start_i = max(0, int(math.floor(min(rho_low, rho_high) - 1)))
            end_i = min(width, int(math.ceil(max(rho_low, rho_high) + 1)))
            
            for i in range(start_i, end_i):
                weight = area_kernel_weight(rho, d_rho, delta_p, i)
                if weight > 0:
                    for j in range(height):
                        temp_image[j][i] += value * weight
                        
        # Rotation by -theta and accumulation.
        # The source does not specify the interpolation method for rotation [G].
        # Using nearest-neighbor sampling as a standard fallback [G].
        cos_t = math.cos(-theta)
        sin_t = math.sin(-theta)
        cx_center = width / 2.0
        cy_center = height / 2.0
        
        for r in range(height):
            for c in range(width):
                dx = c - cx_center
                dy = r - cy_center
                src_c = dx * cos_t - dy * sin_t + cx_center
                src_r = dx * sin_t + dy * cos_t + cy_center
                
                src_c_int = int(math.floor(src_c + 0.5))
                src_r_int = int(math.floor(src_r + 0.5))
                
                if 0 <= src_r_int < height and 0 <= src_c_int < width:
                    result_image[r][c] += temp_image[src_r_int][src_c_int]
                    
    return result_image
```

**Edge Cases and Pitfalls:**
*   **Complex Geometry:** The exact calculation of the common area between a thick line and a pixel generates complex shapes requiring non-trivial decomposition into simple shapes, which is why the rotation approximation is used [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Eliminates unreconstructed pixels (holes) present in Dirac and B-Spline kernels during subsampling [S1, unofficial]. Fully exploits data in oversampling scenarios, unlike linear kernels [S1, unofficial].
*   **Limitations:** The rotation approximation avoids exact geometric integration, which may lead to slight inaccuracies compared to a true area calculation [S1, unofficial].

## Background
The Area-based Pixel Kernel was introduced in the context of tomographic reconstruction to address the limitations of standard interpolators [S1, unofficial]. It is described in the thesis "Précision et qualité en reconstruction tomographique : algorithmes et applications" [S1, unofficial].
