# Feed-Backward Reconstruction

Also called: Gather-based reconstruction, Ray-casting approach

## Overview
Feed-Backward Reconstruction is a method for mapping discrete volume data to a continuous function by gathering contributions from neighboring input samples for each output sample [S1, unofficial]. It solves the problem of reconstructing a continuous signal from discrete samples by centering a reconstruction kernel at each output position and computing a weighted average of the input samples lying under that kernel [S1, unofficial]. It is distinguished from its sibling [Composition via Convolution (Power Form)](1591-composition-via-convolution-power-form.md) by its explicit spatial gathering approach, which accesses each output sample once but reads each input sample multiple times depending on the kernel extent [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A discrete volume dataset $V$ consisting of input samples $X_j$ at positions $P_j$.
*   **Output:** A set of reconstructed output samples $A_i$ at positions $Q_i$.
*   **Kernel:** A reconstruction kernel $K(x)$ (e.g., triangular pulse for linear interpolation) with a defined support extent.

**Data Structures:**
*   `InputSamples`: Array of values $X_j$ and their spatial coordinates.
*   `OutputSamples`: Array of values $A_i$, initialized to zero.
*   `Kernel`: Function or lookup table defining the weight $K(Q_i - P_j)$.

**Steps:**
1.  Initialize all output samples $A_i$ to 0.
2.  For each output sample $i$:
    a.  Center the reconstruction kernel at the output position $Q_i$.
    b.  Identify all input samples $j$ such that the input position $P_j$ lies within the support of the kernel centered at $Q_i$.
    c.  For each identified input sample $j$:
        i.  Calculate the kernel weight $w_{ij} = K(Q_i - P_j)$.
        ii. Accumulate the contribution: $A_i \leftarrow A_i + X_j \cdot w_{ij}$.

**Formula:**
The value of the $i$-th output sample $A_i$ is computed as:
$$ A_i = \sum_{j \in \text{neighbors}(i)} X_j \cdot K(Q_i - P_j) $$
Where:
*   $X_j$ is the value of the $j$-th input sample.
*   $K(\cdot)$ is the reconstruction kernel function.
*   $\text{neighbors}(i)$ is the set of input indices $j$ whose positions $P_j$ fall within the support of the kernel centered at $Q_i$.

**Parameters:**
*   **Kernel Type:** Commonly linear (triangular pulse) or higher-order splines. Linear reconstruction is equivalent to a triangular kernel [S1, unofficial].
*   **Kernel Support:** The spatial extent of the kernel determines the number of input samples accessed per output sample. For linear reconstruction with a support of 1 unit, typically 2 input samples are accessed per output sample [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Input samples near the volume boundaries may have fewer neighbors within the kernel support. The algorithm must handle cases where no input samples lie under the kernel (resulting in 0) or where the kernel extends beyond the data bounds [S1, unofficial].
*   **Precision:** Accumulating many small contributions can lead to floating-point precision errors. Using double precision for accumulation is recommended if high dynamic range is expected [G].
*   **Degenerate Input:** If input samples are not uniformly spaced, the kernel evaluation $K(Q_i - P_j)$ must account for the actual distance, not just index differences [G].

**Pseudocode:**
```python
def feed_backward_reconstruction(input_samples, output_positions, kernel_func):
    """
    Reconstructs output samples by gathering contributions from input samples.
    
    Args:
        input_samples: List of tuples (position, value) for each input sample X_j.
        output_positions: List of positions Q_i for each output sample.
        kernel_func: Function K(distance) that returns the kernel weight for a given distance.
        
    Returns:
        List of reconstructed output values A_i.
    """
    num_outputs = len(output_positions)
    output_values = [0.0] * num_outputs
    
    # Pre-calculate input positions and values for faster access
    input_positions = [pos for pos, val in input_samples]
    input_values = [val for pos, val in input_samples]
    num_inputs = len(input_samples)
    
    # Determine kernel support radius (half-width)
    # This depends on the specific kernel implementation. 
    # For a triangular kernel with support 1, radius is 0.5.
    # If not specified, assume a generic support radius R.
    # Note: The exact support radius must be known or derived from kernel_func.
    # For this implementation, we assume kernel_func returns 0 for distance > R.
    # We will iterate all inputs and check if they are within support.
    # Optimization: Spatial indexing (e.g., grid) can be used to find neighbors faster.
    
    for i in range(num_outputs):
        q_i = output_positions[i]
        total = 0.0
        
        for j in range(num_inputs):
            p_j = input_positions[j]
            distance = abs(q_i - p_j)
            
            # Check if input sample j is within the kernel support
            # The kernel function should return 0 outside its support.
            weight = kernel_func(distance)
            
            if weight != 0.0:
                total += input_values[j] * weight
        
        output_values[i] = total
        
    return output_values
```

## Subtopics

### Feed-Forward Reconstruction
Feed-Forward Reconstruction is the dual approach where each input sample distributes its energy to neighboring output samples [S1, unofficial]. It centers the reconstruction kernel at an input value and spreads the energy to each output lying under the kernel [S1, unofficial]. Unlike Feed-Backward, it accesses each input sample once and each output sample many times [S1, unofficial]. It is chosen when memory bandwidth for output writes is less constrained than input reads, or when parallelizing over input samples is more efficient [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time Complexity:** $O(N_{out} \cdot N_{kernel})$, where $N_{out}$ is the number of output samples and $N_{kernel}$ is the number of input samples within the kernel support for each output. In the example with 4 input samples and 13 output samples using linear reconstruction, it results in 39 sample accesses (2 input accesses per output * 13 outputs) plus 13 output writes [S1, unofficial].
*   **Memory Complexity:** $O(N_{in} + N_{out})$ to store input and output samples [S1, unofficial].

**Measured Performance:**
*   In a scenario with 4 input samples, 13 output samples, and linear reconstruction, Feed-Backward requires 39 sample accesses (input reads) and 13 output writes [S1, unofficial].
*   Feed-Forward requires 24 sample accesses (output writes) and 4 input reads in the same scenario [S1, unofficial].

**Scaling:**
*   Performance scales linearly with the number of output samples and the kernel support size [S1, unofficial].
*   For large kernels, spatial indexing structures (e.g., grids) can reduce the search for neighboring input samples [G].

**Strengths and Limitations:**
*   **Strengths:** Simple to implement; intuitive "gathering" model matches ray-casting where each ray step (output) gathers from volume data (input) [S1, unofficial].
*   **Limitations:** High input memory access overhead for large kernels or high-resolution outputs [S1, unofficial].

**When to Use:**
*   Use when the number of output samples is small relative to the kernel support, or when the rendering pipeline naturally processes outputs one by one (e.g., ray casting) [S1, unofficial].

**When Not to Use:**
*   Avoid when input memory bandwidth is a bottleneck and the kernel support is large, as each input sample is read multiple times [S1, unofficial].

## Background
Feed-Backward Reconstruction is a fundamental technique in volume rendering and signal processing, rooted in the principles of convolution and resampling [S1, unofficial]. It is often associated with early volume rendering algorithms that emphasized explicit control over the reconstruction process per output sample [S1, unofficial]. The method is described in the context of parallel volume rendering algorithms, highlighting its computational characteristics compared to feed-forward approaches [S1, unofficial].
