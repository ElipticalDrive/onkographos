# Alpha Compositing Ray Casting

Also called: Alpha Compositing and Weight Calculation, Front-to-back ray casting, Front-to-back ray casting with WebGL, Volume Compositing, Volumetric Compositing, raw2outputs

## Overview
Alpha Compositing Ray Casting is the standard image-order rendering technique for Direct Volume Ray Casting, solving the problem of projecting a semi-transparent 3D scalar field onto a 2D image plane without requiring binary classification of the data [S1, unofficial]. It differs from Maximum Intensity Projection (MIP) by preserving internal texture and visibility through opacity-weighted accumulation, rather than selecting only the highest intensity value [S2, S3, unofficial]. Unlike NeRF Volumetric Rendering, which often uses learned neural fields and coarse/fine sampling strategies, this method typically relies on explicit 3D textures and fixed-step or adaptive marching [S4, unofficial].

## How it works
The method discretizes the volume rendering integral into a summation over sample points along a ray, performing front-to-back compositing [S2, S3, S5].

### Inputs and Outputs
*   **Inputs**:
    *   `volume_texture`: A 3D texture storing scalar voxel values.
    *   `camera`: Defines ray origins and directions for each pixel.
    *   `transfer_function`: Maps scalar values to RGBA color and opacity. Implemented as a 2D texture in WebGL contexts [S3, unofficial] or a function in software [S2, unofficial].
    *   `step_size`: Fixed distance between samples, or derived from volume dimensions [S3, unofficial].
    *   `threshold`: Opacity threshold for early ray termination (typically 0.95–0.99) [S2, S3, unofficial].
*   **Outputs**:
    *   `image`: A 2D array of RGB (and optionally A) values representing the final rendered frame.

### Data Structures
*   **Volume Texture**: 3D array of scalar values. In WebGL implementations, sampled using `texture(volume, p)` [S3, unofficial].
*   **Transfer Function**: 2D texture where the x-coordinate is the scalar value and y-coordinate is fixed (e.g., 0.5) [S3, unofficial]. Output is RGBA.
*   **Accumulators**:
    *   `accumulated_color` ($C'$): `vec3`, initialized to $(0, 0, 0)$.
    *   `accumulated_opacity` ($\alpha'$): `float`, initialized to $0.0$.

### Steps
1.  **Ray Initialization**: For each pixel, compute ray origin $\bar{o}$ and direction $\bar{d}$. Apply a fixed random offset to the start position to prevent banding artifacts [S3, unofficial].
2.  **Bounding Box Intersection**: Intersect the ray with the volume bounds $[0,1]^3$ to find entry $t_0$ and exit $t_1$ [S3, unofficial]. If $t_0 > t_1$, discard the pixel. If the eye is inside the volume, clamp $t_0$ to $0.0$ [S3, unofficial].
3.  **Step Size Calculation**: Compute step size $dt$ based on volume dimensions $V_{dim}$ and ray direction $\bar{d}$:
    $$ dt = \min \left( \frac{1}{V_{dim,x} |d_x|}, \frac{1}{V_{dim,y} |d_y|}, \frac{1}{V_{dim,z} |d_z|} \right) $$
    [S3, unofficial].
4.  **Ray Marching Loop**: Iterate from $t = t_0$ to $t < t_1$ with increment $dt$:
    a.  **Sample**: Evaluate scalar value $s$ at position $\bar{p} = \bar{o} + t\bar{d}$ using trilinear interpolation [S1, S5].
    b.  **Transfer Function**: Map $s$ to color $\bar{c}_i$ and opacity $\alpha_i$.
        *   *Note*: In some WebGL implementations, the opacity $\alpha_i$ is taken directly from the scalar value $s$, ignoring the transfer function's alpha channel [S3, unofficial]. In standard implementations, $\alpha_i$ comes from the transfer function [S2, S5].
    c.  **Compositing**: Update accumulators:
        $$ C'_i = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i \bar{c}_i $$
        $$ \alpha'_i = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i $$
        [S2, S5].
    d.  **Early Termination**: If $\alpha' \ge \text{threshold}$ (e.g., 0.95 or 0.99), break the loop [S2, S3, unofficial].
5.  **Gamma Correction**: Apply gamma correction (typically 2.2) to the final accumulated color:
    $$ \bar{C}_{final} = \bar{C}'_{last}^{1/2.2} $$
    [S2, unofficial].

### Pseudocode
```python
def alpha_compositing_raycast(volume_texture, camera, transfer_function, volume_dims, threshold=0.99):
    """
    Renders a volume using front-to-back alpha compositing.
    
    Args:
        volume_texture: 3D array or texture object supporting trilinear sampling.
        camera: Object with method cast_ray(pixel) returning (origin, direction).
        transfer_function: Function or 2D texture mapping scalar value -> (color, opacity).
        volume_dims: Tuple (dim_x, dim_y, dim_z) of the volume grid.
        threshold: Opacity threshold for early ray termination.
        
    Returns:
        image: 2D array of RGB values.
    """
    # Initialize output image
    image = zeros_like(camera.screen)
    
    for pixel in camera.screen:
        ray_origin, ray_direction = camera.cast_ray(pixel)
        ray_direction = normalize(ray_direction)
        
        # Initialize accumulators
        accumulated_color = vec3(0.0)
        accumulated_opacity = 0.0
        
        # Ray initialization: Random offset to prevent banding [S3, unofficial]
        # Note: Step size calculation depends on implementation; here we use a fixed small step 
        # or derive it. For WebGL-style, dt is derived from volume_dims [S3, unofficial].
        # For simplicity, we assume a fixed step_size or derive it per ray.
        # Deriving dt as in [S3, unofficial]:
        inv_dir = 1.0 / ray_direction
        dt_vec = 1.0 / (vec3(volume_dims) * abs(ray_direction))
        step_size = min(dt_vec.x, min(dt_vec.y, dt_vec.z))
        
        # Intersection with unit cube [0,1]^3 [S3, unofficial]
        box_min = vec3(0.0)
        box_max = vec3(1.0)
        tmin_tmp = (box_min - ray_origin) * inv_dir
        tmax_tmp = (box_max - ray_origin) * inv_dir
        tmin = min(tmin_tmp, tmax_tmp)
        tmax = max(tmin_tmp, tmax_tmp)
        t0 = max(tmin.x, max(tmin.y, tmin.z))
        t1 = min(tmax.x, min(tmax.y, tmax.z))
        
        # If no intersection, skip
        if t0 > t1:
            continue
            
        # Clamp start to 0 if eye is inside volume [S3, unofficial]
        t0 = max(t0, 0.0)
        
        # Random offset [S3, unofficial]
        t = t0 + random_float(0.0, step_size)
        
        # Ray marching
        while t < t1 and accumulated_opacity < threshold:
            # Sample volume at current position [S1, S5]
            pos = ray_origin + t * ray_direction
            scalar_value = volume_texture.sample_trilinear(pos)
            
            # Apply transfer function [S2, S5]
            # Note: Some implementations use scalar_value as opacity directly [S3, unofficial]
            color, opacity = transfer_function(scalar_value)
            
            # Front-to-back compositing [S2, S5]
            accumulated_color += (1.0 - accumulated_opacity) * opacity * color
            accumulated_opacity += (1.0 - accumulated_opacity) * opacity
            
            # Advance position
            t += step_size
            
        # Gamma correction [S2, unofficial]
        image[pixel] = pow(accumulated_color, vec3(1.0/2.2))
        
    return image
```

### Parameters and Edge Cases
*   **Threshold**: Typically 0.95 [S3, unofficial] or 0.99 [S2, unofficial]. Higher thresholds improve accuracy but increase computation.
*   **Band Artifacts**: Prevented by adding a random offset to the ray start position [S3, unofficial].
*   **Normal Discontinuities**: Gradients for shading (if used) should use a two-voxel offset to avoid rings on smooth surfaces [S1, S3, unofficial].
*   **Numerical Stability**: In some variants (e.g., NeRF-style), a small epsilon ($\epsilon = 10^{-10}$) is added to the product term to prevent instability [S4, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is the number of samples per ray. $M$ depends on volume depth and step size.
*   **Memory Complexity**: $O(V)$ for the volume texture, where $V$ is the number of voxels.
*   **Performance**: Real-time rendering is achievable with hardware acceleration (e.g., WebGL fragment shaders) [S3, unofficial]. Software implementations may be slow without optimization [S1, unofficial].
*   **Strengths**: Preserves internal structure and texture better than MIP [S2, unofficial]. No binary classification required, reducing false positives/negatives [S1, unofficial].
*   **Limitations**: Computationally expensive for large volumes or high resolutions. Sensitive to transfer function design.

## Background
The technique was popularized by Drebin et al. [S1, unofficial], who introduced volumetric compositing to eliminate binary classification artifacts. It became a standard in volume rendering pipelines, enabling real-time rendering through hardware frameworks [S1, unofficial]. It is widely used in medical imaging and scientific visualization.
