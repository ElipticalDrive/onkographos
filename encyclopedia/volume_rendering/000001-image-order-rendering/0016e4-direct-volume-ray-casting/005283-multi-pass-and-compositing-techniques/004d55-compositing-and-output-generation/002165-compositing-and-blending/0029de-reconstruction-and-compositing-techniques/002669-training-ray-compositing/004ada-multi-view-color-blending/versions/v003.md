# Multi-View Color Blending
## Overview
Multi-View Color Blending fuses colors from $N$ reference views into query points using view-dependent weights derived from feature similarity and viewing directions [S1, S2]. It differs from standard alpha compositing by explicitly aggregating multi-view information before density and color prediction, addressing view-dependent appearance and occlusion in generalizable neural radiance fields [S1, S2].

## How it works
**Inputs:**
- $N$ reference views with colors $\{c_i\}_{i=1}^N$, updated multi-view features $\{f'_i\}_{i=1}^N$, and reference viewing directions $\{v_i\}_{i=1}^N$ [S1].
- A 3D query point $p$ and its target viewing direction $v$ [S1].

**Outputs:**
- Blending weights $\{\eta_i\}_{i=1}^N$ [S1].
- Final blended color $c$ [S1].

**Data Structures:**
- Arrays of size $N$ for colors, features, directions, and weights [S1].
- Vectors of dimension $C$ for features and directions [S1].

**Steps:**
1. For each view $i \in \{1, \dots, N\}$, compute the direction difference $\Delta v_i = v - v_i$ [S1].
2. Concatenate the updated feature $f'_i$ with $\Delta v_i$ along the feature dimension [S1].
3. Pass each concatenated vector through a shared MLP, followed by a Softmax activation across the $N$ views to produce blending weights $\eta_i$ [S1].
4. Compute the final color as the weighted sum: $c = \sum_{i=1}^N \eta_i c_i$ [S1].

**Formulas:**
$$ \eta_i = \text{Softmax}\left(\text{MLP}\left(\text{concat}(f'_i, v - v_i)\right)\right) $$
$$ c = \sum_{i=1}^N \eta_i c_i $$
Note: Some implementations replace the direction difference with a dot product or cosine similarity between the target view direction and reference view directions [S2].

**Parameters:**
- $N$: Number of reference views. Typical value: 3 to 24 depending on the scene and hardware [S1, S2].
- MLP architecture: Not given in the sources [S1, S2, S3].

**Edge Cases and Pitfalls:**
- If $N=1$, the Softmax output is always $1.0$ and the color equals $c_1$ [G].
- Direction vectors must be normalized before subtraction or dot product to ensure stable MLP training [G].
- Out-of-bounds projections for feature fetching require clamping or zero-padding [G].

**Pseudocode:**
```python
def multi_view_color_blending(colors, features, view_dirs, target_view_dir):
    N = len(colors)
    diffs = [target_view_dir - v for v in view_dirs]
    combined = [f + d for f, d in zip(features, diffs)]
    # MLP architecture not specified in sources [S1, S2]
    mlp_outputs = combined
    max_val = max(mlp_outputs)
    exp_vals = [x - max_val for x in mlp_outputs]
    weights = [e / sum(exp_vals) for e in exp_vals]
    color = sum(w * c for w, c in zip(weights, colors))
    return weights, color
```

## Subtopics

### Feature Blending
Aggregates pixel alignment features from multiple source views to provide input to the neural radiance field, using viewing directions and angles relative to source views [S3]. For each spatial point $p \in \mathbb{R}^3$, it projects $p$ into view $k$ at $q_k \in \mathbb{R}^2$ and fetches the feature vector $f^k_{q_k}$ [S3]. It computes the angle $\theta^k_q$ between the target view direction $\vec{v}$ and the ray from $p$ to $q_k$ [S3]. Blending weights are estimated by an MLP: $w^k_q = \text{MLP}_{\mathcal{B}}(\vec{v}, \theta^k_q, f^k_q)$ [S3]. The aggregated pixel alignment feature is $F_p = \sum_{k=1}^K w^k_q f^k_q$ [S3]. This variant is used in dynamic human radiance fields that warp bodies to a canonical pose using SMPL skeletons [S3].

## Background
Originated in generalizable neural radiance fields for efficient synthesis from sparse inputs [S1, S2]. HumanNeRF adapted the feature aggregation variant for dynamic human radiance fields [S3]. NeRF-SDP applied color blending for scene depth perception [S2].
