# Ray Compositing and Accumulation

Also called: Hardware Ray Compositing, Ray Beam FIFO, Ray Shift Register, Ray Slice FIFO

## Overview
Ray Compositing and Accumulation is a hardware-accelerated technique for aggregating color and opacity samples into final pixel values during direct volume ray casting, specifically designed to handle sample streams that are not presented in strict ray order [S1, unofficial]. It solves the dependency problem of front-to-back alpha blending by using dedicated buffering structures (FIFOs and shift registers) to retrieve the correct predecessor value from the previous slice, beam, or cycle based on view direction and geometry [S1, unofficial]. Unlike standard software-based accumulation which requires sorting or strict ordering, this method allows parallel slice-by-slice or beam-by-beam processing while maintaining correct compositing logic [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A stream of color ($C_{sample}$) and opacity ($\alpha_{sample}$) values generated by the Classification and Shading unit, presented in slice-by-slice, beam-by-beam order [S1, unofficial].
*   **Output:** Accumulated pixel values ($C_{acc}, acc$) written to Pixel Memory, which are then transferred to a companion 3D graphics card for final image warping [S1, unofficial].

**Data Structures:**
The method relies on three specific hardware buffers to manage the temporal and spatial dependencies of the compositing operation [S1, unofficial]:
1.  **Ray Slice FIFO:** Stores partially accumulated pixel values for compositing with the next slice [S1, unofficial].
2.  **Ray Beam FIFO:** Stores values for an additional "beam time" duration to handle downward-angled rays, allowing input retrieval from the beam above and before the current sample [S1, unofficial].
3.  **Ray Shift Register:** Stores values for one additional cycle to handle samples to the left of the current one [S1, unofficial].

**Parameters:**
*   **Precision:** 12 bits are maintained for accumulated color ($C_{acc}$), accumulated opacity ($acc$), and all intermediate compositing values to ensure correct alpha blending in large volumes [S1, unofficial].

**Steps:**
1.  **Predecessor Selection:** For a current sample $S(x,y,z)$, determine the required predecessor value from the previous slice. The predecessor is one of $S(x,y,z-1)$, $S(x-1,y,z-1)$, $S(x,y-1,z-1)$, or $S(x-1,y-1,z-1)$, selected based on the view direction and the $z$-value [S1, unofficial].
2.  **Alignment:** The Ray Alignment unit drives two multiplexers (MUX) to select the correct predecessor value from the available buffers (Ray Slice FIFO, Ray Beam FIFO, Ray Shift Register) [S1, unofficial].
3.  **Compositing:** Perform the compositing operation using the selected predecessor and the current sample's color and opacity. The default mode is Front-to-Back Alpha Blending [S1, unofficial]:
    $$ C_{acc}^{new} = C_{acc}^{old} + (1 - acc^{old}) \cdot C_{sample} $$
    $$ acc^{new} = acc^{old} + (1 - acc^{old}) \cdot \alpha_{sample} $$
    Alternative blending modes supported include Minimum Intensity and Maximum Intensity [S1, unofficial]:
    *   **Minimum Intensity:** If $sampleValue < minValue$, then $C_{acc} = C_{sample}$ and $minValue = sampleValue$.
    *   **Maximum Intensity:** If $sampleValue > maxValue$, then $C_{acc} = C_{sample}$ and $maxValue = sampleValue$.
4.  **Buffer Update:** Store the resulting partially accumulated values back into the Ray Slice FIFO, Ray Beam FIFO, and Ray Shift Register for use by subsequent samples [S1, unofficial].
5.  **Output:** When a ray passes through the back of the volume (maximum $z$) or a side face, output the final accumulated pixel value [S1, unofficial].
6.  **Memory Write:** Write the base plane pixel values to Pixel Memory and transfer them to a companion 3D graphics card for final image warping [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision Loss:** Insufficient bit depth in intermediate values leads to incorrect blending in large volumes. The method mandates 12-bit precision for $C_{acc}$, $acc$, and intermediates [S1, unofficial].
*   **Ray Angle:** Downward-angled rays require the Ray Beam FIFO to access data from previous beams; failure to buffer correctly results in incorrect predecessor selection [S1, unofficial].
*   **Termination:** Output must be triggered correctly when rays exit the volume bounds (back face or side faces) to prevent incomplete accumulation [S1, unofficial].

## Subtopics

### Ray Combing
Ray Combing is a post-processing step that walks an ordered list of ray intersection segments to correct numeric inaccuracies, remove duplicates, and fill gaps [S2, unofficial]. It is used when ray tracking produces segments that are not perfectly contiguous due to floating-point limitations [S2, unofficial].
*   **Definition:** A final cleanup process applied after all intersection segments for a ray are calculated and ordered by unit position along the ray (0.0 to 1.0) [S2, unofficial].
*   **Steps:**
    1.  Initiate combing after segment calculation and ordering [S2, unofficial].
    2.  Walk and preen the ordered ray segment list in its entirety [S2, unofficial].
    3.  Detect duplicate ray coverage segment sequences; keep the combination producing the "best fit" and longest ray segment span; delete duplicates [S2, unofficial].
    4.  Find contiguous segments with overlapping ray coverage but unique coverage length; crop both segments to eliminate the overlap [S2, unofficial].
    5.  Find gaps in ray path coverage; if simulation voids are prohibited, extend adjacent segment lengths to fill the gap [S2, unofficial].
*   **When to choose:** Use when numeric inaccuracies in ray/mesh intersection path lengths are unacceptable, particularly in hexahedral mesh tracing where floating-point errors may cause gaps or overlaps [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The compositing step is $O(1)$ per sample, as it involves a fixed number of multiplexer selections and arithmetic operations [S1, unofficial]. The Ray Combing post-process adds overhead proportional to the number of segments per ray, but is described as having "very little overhead" because it leverages existing ordered segment lists [S2, unofficial].
*   **Memory Complexity:** Requires dedicated hardware buffers (Ray Slice FIFO, Ray Beam FIFO, Ray Shift Register) per ray or per active beam. The size depends on the maximum ray angle and volume dimensions [S1, unofficial].
*   **Performance:** Designed for real-time ray casting on specialized hardware (VolumePro) [S1, unofficial].
*   **Strengths:** Enables parallel slice-by-slice processing without requiring global sorting of samples; handles complex ray angles via buffering [S1, unofficial].
*   **Limitations:** Hardware-dependent; requires precise synchronization between slicing, shading, and compositing units; 12-bit precision may still suffer from accumulation errors in extremely large volumes without additional techniques like Ray Combing [S1, unofficial][S2, unofficial].
*   **When to use:** Real-time volume rendering on hardware that supports FIFO-based accumulation; scenes with semi-transparent materials requiring correct alpha blending [S1, unofficial].
*   **When not to use:** Software-only implementations without FIFO support; scenes where voids are permitted and gap-filling is not required (Ray Combing may be skipped) [S2, unofficial].

## Background
Ray Compositing and Accumulation was developed as part of the VolumePro real-time ray-casting system by MERL (Mitsubishi Electric Research Laboratory) [S1, unofficial]. It was introduced to address the challenge of accumulating color and opacity values when samples are generated in slice-by-slice or beam-by-beam order rather than strict ray order [S1, unofficial]. The technique utilizes hardware buffers to manage the temporal dependencies of front-to-back compositing, enabling high-performance real-time visualization [S1, unofficial]. Ray Combing was later introduced in the HADES project to address numeric inaccuracies in ray tracing through hexahedral meshes, serving as a complementary post-processing step [S2, unofficial].
