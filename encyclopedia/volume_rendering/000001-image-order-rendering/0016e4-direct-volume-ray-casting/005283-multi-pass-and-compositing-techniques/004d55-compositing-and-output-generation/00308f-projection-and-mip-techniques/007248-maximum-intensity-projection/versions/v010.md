# Maximum Intensity Projection

Also called: MIP, Max Intensity Projection

## Overview
Maximum Intensity Projection (MIP) is a volume rendering technique that projects the maximum scalar value encountered along a viewing ray onto the 2D image plane [S3][S12, unofficial]. Unlike standard alpha blending which accumulates emission and absorption, MIP ignores intermediate values and opacity accumulation, making it order-independent [S2, unofficial][S12, unofficial]. It is primarily used in medical imaging to highlight high-intensity structures such as bones in CT scans or contrast-enhanced blood vessels in MRI/CT angiography [S1, unofficial][S3][S4, unofficial][S6, unofficial][S12, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset $V$ containing scalar values (density/intensity) $s$, and a viewing ray $R$ defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ for each pixel [S3].
*   **Output:** A 2D image where each pixel color is determined by the maximum scalar value $s_{max}$ found along the ray, mapped through a transfer function or direct intensity mapping [S4, unofficial][S12, unofficial][S32, unofficial].

**Data Structures:**
*   **Volume Texture:** Typically stored as a 3D texture [S5, unofficial][S13, unofficial]. Common layouts include `rg8unorm` where the red channel holds the low bits and the green channel holds the high bits of a 16-bit value [S32, unofficial], or single-channel float formats [S14, unofficial].
*   **Accumulator:** A single variable `max_val` (or `maximum_intensity`) initialized to the minimum possible value (e.g., $-\infty$, $-999999.0$, or $0.0$ depending on data range) [S2, unofficial][S12, unofficial][S16, unofficial][S17, unofficial][S22, unofficial][S24][S27, unofficial][S32, unofficial][S34][S42, unofficial][S43][S44, unofficial][S52, unofficial]. No opacity accumulator is needed [S2, unofficial][S10, unofficial][S12, unofficial][S25, unofficial][S50].

**Numbered Steps:**
1.  **Ray Setup:** For each pixel, compute the ray origin and direction in volume space [G].
2.  **Intersection:** Compute the entry (`near`) and exit (`far`) points of the ray with the volume's axis-aligned bounding box (AABB) using the slab method [S20, unofficial][S32, unofficial]. If the ray misses the volume (`near > far` or `far < 0`), output background color [S20, unofficial][S32, unofficial].
3.  **Initialization:** Initialize `max_val` to the minimum scalar value and `max_pos` to the ray origin or invalid [S2, unofficial][S12, unofficial][S16, unofficial][S17, unofficial][S22, unofficial][S24][S27, unofficial][S32, unofficial][S34][S42, unofficial][S43][S44, unofficial][S52, unofficial].
4.  **Ray Marching:** Iterate along the ray from `near` to `far` with a step size $\Delta t$ [S14, unofficial][S16, unofficial][S20, unofficial][S24][S32, unofficial][S34][S44, unofficial][S52, unofficial].
    *   Sample the volume at the current position $P = \mathbf{o} + t \cdot \mathbf{d}$ [S14, unofficial][S16, unofficial][S20, unofficial][S22, unofficial][S24][S34][S43][S44, unofficial][S52, unofficial].
    *   Retrieve the scalar value $s$ from the volume texture [S14, unofficial][S16, unofficial][S22, unofficial][S24][S34][S43][S44, unofficial][S52, unofficial].
    *   Update the maximum: $C_{dst} \leftarrow \max(C_{dst}, C_{src})$ [S2, unofficial][S10, unofficial][S11, unofficial][S12, unofficial][S22, unofficial][S34][S42, unofficial][S43][S44, unofficial][S52, unofficial].
    *   Optionally, track the position `max_pos` where `max_val` was updated [S22, unofficial][S35, unofficial][S52, unofficial].
    *   *Early Termination:* Some implementations break early if `max_val` exceeds a threshold (e.g., $0.75 \times \text{volume\_maximum}$) [S16, unofficial] or if the ray length is exhausted [S17, unofficial][S34]. Note: Standard MIP does not use opacity-based early termination like alpha blending [S2, unofficial][S10, unofficial][S12, unofficial][S25, unofficial][S50].
5.  **Color Mapping:** Map `max_val` to a color via a transfer function or colormap [S25, unofficial]. This can be a direct intensity-to-color mapping (e.g., window/level) [S32, unofficial][S45, unofficial][S53, unofficial] or a transfer function lookup [S22, unofficial][S34][S35, unofficial][S42, unofficial][S53, unofficial].
    *   If lighting is desired (e.g., DepthShaded MIP), compute gradients and lighting at `max_pos` [S35, unofficial][S52, unofficial].
6.  **Output:** Write the mapped color to the pixel buffer [S2, unofficial][S16, unofficial][S22, unofficial][S34][S35, unofficial][S42, unofficial][S44, unofficial][S52, unofficial][S53, unofficial].

**Pseudocode:**
```python
def render_mip_pixel(ray_origin, ray_direction, volume_min, volume_max, volume_texture, step_size):
    # 1. Intersection with AABB
    inv_dir = 1.0 / ray_direction
    bot = inv_dir * (volume_min - ray_origin)
    top = inv_dir * (volume_max - ray_origin)
    rmin = min(top, bot)
    rmax = max(top, bot)
    near = max(rmin.x, rmin.y, rmin.z)
    far = min(rmax.x, rmax.y, rmax.z)

    # Handle miss
    if near > far or far < 0:
        return vec3(0.0)

    # Clamp near to 0
    near = max(0.0, near)
    
    # 2. Initialize
    max_val = -float('inf')
    max_pos = ray_origin + ray_direction * near
    
    # 3. Ray Marching
    t = near
    while t < far:
        # Sample volume at current position
        sample_pos = ray_origin + ray_direction * t
        # Standard 3D texture lookup returns a vec4; take the scalar channel
        s = volume_texture.sample(sample_pos).r
        
        # Update maximum
        if s > max_val:
            max_val = s
            max_pos = sample_pos
            
        t += step_size

    # 4. Color Mapping
    # Map the maximum scalar value to a display color (e.g., window/level or transfer function) [S25, unofficial]
    color = vec3(max_val)  # Direct intensity mapping to grayscale
    
    return color
```

**Parameters:**
*   **Step Size:** Determines sampling density along the ray [S32, unofficial]. Can be fixed (e.g., 0.5 units) [S24] or adaptive. In interactive modes, larger steps (e.g., 50) are used [S16, unofficial][S18, unofficial]. Default values vary: some implementations use 200 samples per ray [S14, unofficial], while others use step sizes like 0.01 [S32, unofficial].
*   **Window Width/Level:** Controls contrast and brightness of the final intensity mapping [S32, unofficial][S45, unofficial][S53, unofficial]. Typical GUI values: Width $\approx 0.018$ (range 0–0.05), Level $\approx 0.498$ (range 0.48–0.52) [S32, unofficial].
*   **Thresholds:** Early exit thresholds (e.g., $0.75 \times \text{max\_density}$) [S16, unofficial] or density bounds ($minDensityThreshold$, $maxDensityThreshold$) to ignore noise [S22, unofficial].

**Edge Cases and Pitfalls:**
*   **Depth Ambiguity:** MIP loses all depth information [S2, unofficial][S4, unofficial][S11, unofficial][S12, unofficial][S16, unofficial][S20, unofficial][S36][S37, unofficial][S40, unofficial][S50]. A high-intensity structure in the foreground can obscure lower-intensity structures behind it, leading to misinterpretation of spatial relationships [S4, unofficial][S11, unofficial][S12, unofficial][S16, unofficial][S40, unofficial].
*   **Order Independence:** Since the operation is `max()`, the order of sample processing does not matter [S2, unofficial][S38, unofficial][S45, unofficial][S49]. This allows for parallelization and acceleration structures [S2, unofficial].
*   **Implementation Specifics:** Standard OpenGL blending cannot compute `max` without extensions (e.g., `GL_EXT_blend_minmax`) [S12, unofficial][S48, book]. Hardware sampling requires explicit LOD setting (e.g., `SampleLevel` with LOD 0) for 3D textures with a single mipmap level to avoid gradient calculation errors [S15, unofficial].

## Subtopics

### [Fast Maximum Intensity Projection (MIP)](6635-fast-maximum-intensity-projection-mip.md)
Accelerates MIP by decomposing the density domain into intervals and using shear-warp projection to skip low-density samples.

### [MIP with Offset Lookup](6637-mip-with-offset-lookup.md)
Uses binary volume masks and bitwise operations to identify the highest density interval along a ray, skipping low-density voxels entirely.

### [Priority Queue MIP with Min/Max Grids](10338-priority-queue-mip-with-min-max-grids.md)
Combines hierarchical spatial acceleration (min/max grids) with a priority queue to skip nodes whose maximum value is lower than the current ray's maximum.

### [Maximum Activity Projection](12564-maximum-activity-projection.md)
Used in nuclear medicine; applies simulated exponential attenuation before selecting the maximum to weight voxels by depth and prevent rotation illusions.

### [Attenuated Maximum-Intensity Projection](16662-attenuated-maximum-intensity-projection.md)
Enhances visibility of high-intensity structures by suppressing background noise and weaker signals that typically obscure details in standard MIP.

### Morphological Maximum Intensity Projection (MMIP) with Morphological Closing
Prevents hole formation in non-axial views caused by undersampling by applying a morphological closing operation (e.g., 2x2x2 structuring element) to the final 2D projection image [S76].

### Closest Vessel Projection
A local projection technique for vascular diagnosis that selects the first local maximum above a dataset-specific threshold [S46]. Requires careful threshold tuning.

### FVR Approximation of Maximum Intensity Projection
Approximates MIP using Fourier Volume Rendering by transforming voxel values $v \to b^v$ (e.g., $b=2$ or $1.1$), performing FVR projection, and applying a base-$b$ logarithm [S74, unofficial]. Suffers from artifacts due to non-linear compression of resampling filters [S74, unofficial].

### Maximum Importance Projection
An importance compositing method where for each ray, only the object with the highest importance is displayed densely; all remaining objects are fully transparent [S77]. Uses depth buffer clipping and gradient modification to enhance focus objects [S77].

### Maximal Intensity Projection with Depth Sorting
Maps voxel intensity to screen depth to resolve occlusion in dense volumes, ensuring highly conserved (high intensity) regions are displayed before less conserved ones using a Z-buffer algorithm [S78, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ per ray, where $N$ is the number of samples along the ray [S2, unofficial][S55, unofficial]. With acceleration structures (e.g., Priority Queue, Fast MIP), average case can be significantly lower [S1, unofficial].
*   **Memory Complexity:** $O(1)$ per ray accumulator (excluding volume storage) [S2, unofficial].
*   **Performance:** Very fast to calculate; often used as a default or preview rendering mode [S21, unofficial][S22, unofficial]. Suitable for real-time interactive visualization [S21, S39, unofficial].
*   **Strengths:** Highlights high-intensity structures (bones, contrast agents) clearly [S6, unofficial][S12, unofficial][S32, unofficial][S39, unofficial]. No transfer function required for basic intensity visualization [S4, unofficial][S12, unofficial]. Order-independent, allowing flexible rendering order [S45, unofficial][S49].
*   **Limitations:** Complete loss of depth information [S4, unofficial][S11, unofficial][S12, unofficial][S16, unofficial][S36][S37, unofficial][S40, unofficial][S50]. Misleading spatial correlation; foreground objects can hide background objects [S4, unofficial][S11, unofficial][S12, unofficial][S40, unofficial]. Less effective for MR images where contrast is lower or noise is higher compared to CT [S44, unofficial].

## Background
MIP was introduced as a simple compositing technique for direct volume rendering, particularly for medical imaging applications [S1, unofficial][S2, unofficial][S3]. It is widely used in Magnetic Resonance Angiography (MRA) and Computed Tomography Angiography (CTA) to visualize blood vessels without the need for complex transfer functions [S1, unofficial][S3][S4, unofficial][S6, unofficial][S12, unofficial]. The technique simplifies the volume rendering integral to a maximum operation [S11, unofficial][S12, unofficial].
