# MPI Defocus Rendering

Also called: Multiplane image defocus, Synthetic Defocus Rendering, Synthetic Defocus Rendering from MPI

## Overview
MPI Defocus Rendering synthesizes images with realistic depth-of-field effects and lateral camera translation by compositing a precomputed Multi-Plane Image (MPI) representation [S1]. It differs from standard ray casting by operating on discrete disparity planes rather than continuous volumetric samples, allowing for efficient simulation of defocus blur and parallax through 2D image-space convolutions and translations [S1]. This method is specifically designed for view synthesis from trained neural radiance fields (NeRFs), particularly those trained on raw sensor data, where it avoids the computational cost of per-pixel ray marching for every novel view [S1].

## How it works
**Inputs and Outputs**
*   **Input:** An MPI consisting of $N$ fronto-parallel RGBA planes. The planes are indexed from back to front ($i = 0$ to $N-1$). Colors are in linear HDR space [S1].
*   **Parameters:**
    *   $i_{focus}$: Integer index of the focal plane [S1].
    *   $\Delta r$: Scalar controlling the simulated aperture size (defocus strength) [S1].
    *   $\Delta d$: A 2D vector controlling camera translation parallel to the image plane [S1].
*   **Output:** A single composited image $C$ [S1].

**Data Structures**
The MPI is stored as a list or array of $N$ images. Each image has dimensions $H \times W$ and contains four channels: Red, Green, Blue, and Alpha ($\alpha$) [S1]. The planes are ordered such that index $0$ is the furthest back and index $N-1$ is the closest to the camera [S1].

**Algorithm Steps**
The rendering process iterates through each plane of the MPI, applying defocus blur and lateral shift based on the plane's distance from the focal plane, then compositing the result using front-to-back alpha blending [S1].

1.  Initialize the accumulator color $C$ to zero (black) [S1].
2.  For each plane $i$ from $0$ to $N-1$:
    a.  Calculate the defocus radius $r$ based on the distance of the current plane from the focal plane:
        $$ r = \Delta r \cdot |i - i_{focus}| $$
        [S1]
    b.  Generate a blur kernel $k_{blur}$ using a circular mask of radius $r$ centered at the origin. This is implemented as a 2D Fourier space convolution [S1].
    c.  Premultiply the plane's color $c_{mpi}^{(i)}$ by its alpha $\alpha_{mpi}^{(i)}$ before blurring [S1].
    d.  Convolve the premultiplied color with the blur kernel to get $c_{blur}$:
        $$ c_{blur} = \text{convolve}(c_{mpi}^{(i)} \cdot \alpha_{mpi}^{(i)}, k_{blur}) $$
        [S1]
    e.  Convolve the plane's alpha with the blur kernel to get $\alpha_{blur}$:
        $$ \alpha_{blur} = \text{convolve}(\alpha_{mpi}^{(i)}, k_{blur}) $$
        [S1]
    f.  Calculate the lateral translation offset $d$ for the current plane:
        $$ d = \Delta d \cdot i $$
        [S1]
    g.  Translate the blurred color and alpha images by $d$ using continuous 2D translation with bilinear resampling:
        $$ c_{trans} = \text{translate}(c_{blur}, d) $$
        $$ \alpha_{trans} = \text{translate}(\alpha_{blur}, d) $$
        [S1]
    h.  Composite the translated plane into the accumulator $C$ using front-to-back alpha blending. Since the color was premultiplied by alpha before blurring, the alpha term is not applied to $c_{trans}$ in the accumulation step:
        $$ C \leftarrow c_{trans} + (1 - \alpha_{trans}) C $$
        [S1]
3.  Return $C$ [S1].

**Edge Cases and Pitfalls**
*   **Premultiplication:** The color must be premultiplied by alpha *before* blurring. If alpha is applied after blurring, the results will be incorrect because the blur kernel mixes color and alpha values independently, violating the linear light assumption required for correct defocus simulation [S1].
*   **Indexing Order:** The MPI planes must be indexed from back to front ($i=0$ is furthest). The accumulation loop must follow this order to correctly simulate front-to-back compositing [S1].
*   **Translation Scaling:** The lateral translation $d$ scales linearly with the plane index $i$. This assumes a linear disparity sampling within the camera frustum [S1].
*   **Kernel Implementation:** The blur kernel is implemented via 2D Fourier space convolution. Care must be taken with boundary conditions and padding to avoid artifacts at image edges [S1].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot H \cdot W \cdot \log(H \cdot W))$ per frame, where $N$ is the number of MPI planes, and $H, W$ are image dimensions. The dominant cost is the 2D convolution (via FFT) and translation for each plane [S1].
*   **Memory Complexity:** $O(N \cdot H \cdot W)$ to store the MPI planes [S1].
*   **Performance:** The method is significantly faster than per-pixel ray marching for defocus because it leverages efficient 2D image operations. It is suitable for real-time or near-real-time view synthesis if the MPI is precomputed [S1].
*   **Strengths:** Efficient simulation of defocus and parallax; works well with HDR data; avoids expensive ray-volume intersection tests [S1].
*   **Limitations:** Requires precomputation of the MPI; quality depends on the density and coverage of the MPI planes; may exhibit artifacts if the disparity sampling is insufficient [S1].

## Background
MPI Defocus Rendering was introduced in the context of "NeRF in the Dark," a method for high dynamic range view synthesis from noisy raw images [S1]. The authors precomputed an MPI representation from a trained RawNeRF model to enable efficient synthetic defocus rendering, including lateral camera translation [S1]. This approach builds on prior work in MPI-based rendering and defocus simulation [S1].
