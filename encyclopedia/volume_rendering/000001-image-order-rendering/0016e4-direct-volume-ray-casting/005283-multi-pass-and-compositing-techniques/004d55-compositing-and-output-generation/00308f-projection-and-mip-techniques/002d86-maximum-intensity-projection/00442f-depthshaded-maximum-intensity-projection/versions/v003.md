# DepthShaded Maximum Intensity Projection

Also called: DEMIP with Depth Weighting, Depth-enhanced Maximum Intensity Projection (DeMIP)

## Overview
DepthShaded Maximum Intensity Projection (DSMIP) is a volume rendering technique that enhances depth perception in Maximum Intensity Projection (MIP) by modulating the final color based on the depth of the sampled structures [S1, unofficial][S3]. While standard MIP highlights high-intensity structures, it lacks depth cues, leading to ambiguities in interpreting spatial arrangement [S2, unofficial]. DSMIP addresses this by blending the standard MIP color with a depth-derived color, allowing viewers to distinguish between foreground and background structures with minimal information loss [S1, unofficial][S3]. It differs from [Local Maximum Intensity Projection](6054-local-maximum-intensity-projection.md) by retaining the global maximum along the ray but altering its visual presentation, and from [Fast Maximum Intensity Projection (MIP)](6635-fast-maximum-intensity-projection-mip.md) by adding a secondary depth-evaluation step [S3].

## How it works
**Inputs:**
*   Volume dataset $V$ (3D array of voxel intensities).
*   Camera parameters (view direction, position) [G].
*   Depth weight parameter $d_w$ (typical value: 0.15 or 0.3) [S3].

**Outputs:**
*   Final color image $C_{final}$ (2D array of RGB vectors).

**Data Structures:**
*   `MIP_color`: RGB vector of the color associated with the maximum intensity voxel found along the ray.
*   `depth`: Normalized depth value ($0 \le depth \le 1$) of the fragment/voxel contributing to the MIP result, where 0 is closest to the viewer and 1 is farthest [S3].

**Numbered Steps:**
1.  **Primary Ray Casting (MIP Pass):** Cast a ray through the volume using camera parameters [G]. Find the voxel with the maximum intensity value along the ray [S2, unofficial][S3]. Record its color as `MIP_color` and its depth as `depth` [S2, unofficial][S3].
2.  **Depth Shading Calculation:** Compute the final color by blending the `MIP_color` with a depth-derived intensity [S3].
3.  **Alternative Implementation (Modulation):** In some descriptions, the intensity of sampled values is modulated by their depth, and the result is written to the final image only if the modulated value is greater than the currently processed pixel's value [S2, unofficial]. This approach effectively suppresses far-away high-intensity values that might obscure closer features [S2, unofficial].

**Formulas:**
The final color is calculated using the depth and the depth weight parameter [S3]:
$$ C_{final} = MIP_{color} \times (1 - d_w) + 2 \times d_w \times (1 - depth) $$
*   $MIP_{color}$: RGB vector of the maximum intensity sample.
*   $d_w$: Depth weight parameter controlling the influence of the depth cue [S3].
*   $depth$: Normalized depth value of the fragment [S3].
*   The scalar term $2 \times d_w \times (1 - depth)$ is broadcast across the RGB channels of $MIP_{color}$ [G].

**Parameters:**
*   $d_w$: Depth weight parameter. Typical values are 0.15 or 0.3 [S3]. If $d_w = 0$, the result is the standard MIP color [S3].
*   $depth$: Normalized depth value used in the term $(1 - depth)$ to map depth to color intensity [S3].

**Edge Cases and Pitfalls:**
*   Values located far away from the current viewing point have less chance of being projected if using the modulation variant, which can result in obscuring volumetric features even if they have high intensity values [S2, unofficial].
*   Artifacts may appear near the bounding box boundaries when rotating the object if the depth evaluation is not handled carefully [S3].
*   Precision issues can arise when comparing modulated values in the modulation variant; using a small epsilon tolerance prevents flickering [G].

**Pseudocode:**
```python
def depth_shaded_mip(volume_data, camera, depth_weight):
    """
    Renders a single frame using DepthShaded MIP.
    
    Args:
        volume_data: 3D list/array of voxel intensities.
        camera: Object with resolution, step_size, and generate_ray(x, y) -> (origin, direction, length).
        depth_weight: Float d_w (e.g., 0.15).
        
    Returns:
        image: 2D list of RGB floats in [0, 1].
    """
    width, height = camera.resolution
    image = [[0.0, 0.0, 0.0] for _ in range(height)]
    
    for y in range(height):
        for x in range(width):
            origin, direction, length = camera.generate_ray(x, y)
            
            max_intensity = -1.0
            mip_color = [0.0, 0.0, 0.0]
            depth_at_max = 0.0
            
            step = camera.step_size
            num_samples = int(length / step)
            
            for i in range(num_samples):
                t = i * step
                pos = [origin[j] + t * direction[j] for j in range(3)]
                intensity = volume_data[pos[0]][pos[1]][pos[2]]
                
                if intensity > max_intensity:
                    max_intensity = intensity
                    mip_color = [intensity, intensity, intensity]
                    depth_at_max = t / length
            
            depth_factor = 1.0 - depth_at_max
            depth_term = 2.0 * depth_weight * depth_factor
            final_color = [
                mip_color[0] * (1.0 - depth_weight) + depth_term,
                mip_color[1] * (1.0 - depth_weight) + depth_term,
                mip_color[2] * (1.0 - depth_weight) + depth_term
            ]
            image[y][x] = final_color
    return image
```

## Subtopics

### Depth Perception in MIP via Polygonal Surfaces
A method to improve depth perception in MIP by extracting isosurfaces and modifying vertex coordinates before projection [S1, unofficial]. It replaces the z-coordinate of each vertex with its associated isovalue, modifying the depth buffer so that geometry with higher densities appears closer to the viewpoint [S1, unofficial]. This modified z-buffer is then used to enhance the MIP visualization [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Slower than standard MIP due to the extra ray-casting step or depth evaluation [S3]. Faster than Direct Volume Rendering (DVR) because the per-sample computation is simpler than the full DVR transfer function and lighting model [S3].
*   **Measured Performance:** On an Intel Core 2 Duo E8400 and NVIDIA GeForce GTX 280, DEMIP achieved 53.8 fps for a 512x512x40 Jaw model, compared to 64.7 fps for standard MIP [S3]. For a 512x512x485 Head model, DEMIP achieved 25.8 fps vs 28.9 fps for MIP [S3].
*   **Strengths:** Enhances depth perception with minimal information loss; provides color cues for spatial context [S1, unofficial][S3].
*   **Limitations:** Values located far away have less chance of being projected if using the modulation variant, potentially obscuring volumetric features even if they have high intensity [S2, unofficial]. Artifacts may appear near bounding box boundaries when rotating the object if not implemented carefully [S3].
*   **When to use:** When depth cues are critical for interpreting the spatial arrangement of high-intensity structures (e.g., vascular vessels) and performance constraints allow for slightly more computation than standard MIP [S1, unofficial][S3].

## Background
The method was introduced to address the lack of depth cues in standard MIP, which can lead to ambiguities in interpreting the resulting image [S2, unofficial]. It is based on slightly modifying the MIP shading to take into account the depth of closer structures with similar material [S1, unofficial]. The technique is also known as Depth-enhanced Maximum Intensity Projection (DeMIP) [S1, unofficial][S3].
