# MIP with Offset Lookup

Also called: Binary Density Interval Encoding for MIP, Binary volume mask, Density interval encoding, MaxInterval Search

## Overview
MIP with Offset Lookup is a preprocessing and acceleration technique for Maximum Intensity Projection (MIP) that avoids unnecessary volume resampling by decomposing the density domain into discrete intervals [S1, unofficial]. It assigns a binary code to each voxel representing its density interval, storing these codes in a compact binary volume mask [S1, unofficial]. The method determines the highest density interval present along a viewing ray using bitwise operations and then uses lookup tables to locate and compare only the voxel densities within that specific interval [S1, unofficial]. It sets itself apart from standard MIP by skipping low-density samples entirely, and from [Local Maximum Intensity Projection](6054-local-maximum-intensity-projection.md) by focusing on global maximums via interval encoding rather than local neighborhood analysis [G].

## How it works

### Inputs and Outputs
*   **Input:** A 3D volume array `volume` of size $X \times Y \times Z$ containing density values. Windowing parameters $L$ (lower threshold) and $H$ (higher threshold) define the relevant density range, where $M$ is the maximum density value in the volume [S1, unofficial].
*   **Output:** A rendered image pixel value (maximum density) for each screen coordinate $(i, j)$.
*   **Preprocessed Data:** A binary volume mask `mask` of size `depth` $\times Y \times X$, where `depth` is calculated based on $Z$ and integer bit-width [S1, unofficial].

### Data Structures

**1. Binary Volume Mask (`mask`)**
*   **Type:** 3D integer array `int mask[depth][height][width]` [S1, unofficial].
*   **Dimensions:**
    *   `width` = $X$
    *   `height` = $Y$
    *   `depth` = $(2 \times Z + 30) \text{ div } 32$ [S1, unofficial].
*   **Layout:** Each integer element (32 bits) stores the density interval codes of voxels along rows parallel to the $z$-axis [S1, unofficial]. For a volume size $X \times Y \times Z$, the mask packs multiple voxel codes into single integers to enable parallel bitwise processing [S1, unofficial].
*   **Code Size:** For $n=4$ intervals, each code is 2 bits [S1, unofficial]. Codes are assigned based on the interval index: $00$ for $I_0$, $01$ for $I_1$, $10$ for $I_2$, $11$ for $I_3$ [S1, unofficial].

**2. Lookup Tables (LUTs)**
*   **Structure:** Four LUTs, one for each possible interval pattern (00, 01, 10, 11) [S1, unofficial].
*   **Size:** Each LUT is 256 bytes [S1, unofficial].
*   **Content:** For a given pattern, the LUT stores the position (0–7) of the first occurrence of that pattern within a byte [S1, unofficial]. If the pattern is not present in the byte, the LUT stores 8 [S1, unofficial].
*   **Access:** Addressed by the byte value of the integer segment [S1, unofficial].

### Parameters
*   **Intervals ($n$):** The number of density intervals. The source details $n=4$ specifically. For $n=4$, 2 bits per voxel are used [S1, unofficial].
*   **Windowing:**
    *   $I_0 = [0, L)$
    *   $I_{n-1} = [H, M]$
    *   Intermediate intervals subdivide $[L, H)$ using uniform or balanced quantization based on the data histogram [S1, unofficial].

### Algorithm Steps

1.  **Preprocessing (Mask Creation):**
    *   Divide the density domain into $n$ intervals $I_0, \dots, I_{n-1}$ sorted by borders [S1, unofficial].
    *   Assign a unique binary code to each interval corresponding to its index [S1, unofficial].
    *   Create the `mask` array. For each voxel $(x, y, z)$, determine which interval its density falls into and store the corresponding code. Pack 16 codes (for 2-bit intervals) into one integer along the $z$-axis [S1, unofficial].

2.  **Ray Casting Loop (for each pixel $(i, j)$):**
    *   **Step 1: Find Highest Interval.** Call `MaxInterval(i, j)` to determine the highest density interval code present in the ray [S1, unofficial].
    *   **Step 2: Check for Valid Pattern.** If the returned pattern is 0 (interval $I_0$), return 0 (or background color) as no relevant density exists [S1, unofficial].
    *   **Step 3: Locate and Compare Densities.**
        *   Initialize `max` density to 0.
        *   Iterate through each integer segment `k` in the `mask` along the ray [S1, unofficial].
        *   While the current `segment` contains the target pattern:
            *   Call `Offset(segment, pattern)` to find the bit position `pos` of the first occurrence of the pattern [S1, unofficial].
            *   If `pos < 32`:
                *   Calculate the voxel index: `voxel_z = k * 16 + pos / 2` [S1, unofficial].
                *   Retrieve density: `density = volume[voxel_z][j][i]` [S1, unofficial].
                *   Update `max`: `if density > max: max = density` [S1, unofficial].
                *   Clear the found bit in the segment: `segment &= ~(0xC0000000 >> pos)` [S1, unofficial].
            *   Else (pattern not found in this segment): Break loop for this `k` [S1, unofficial].

### Pseudocode

```python
def max_interval(mask, depth, i, j):
    """
    Finds the highest density interval code present in the ray.
    Assumes 4 intervals (2-bit codes: 00, 01, 10, 11).
    Returns the index of the highest interval (0-3).
    """
    index = 0
    for k in range(depth):
        segment = mask[k][j][i]
        if segment != 0:
            i01or11 = segment & 0x55555555
            if i01or11 != 0:
                if (i01or11 & (segment >> 1)) != 0:
                    return 3
                elif index < 1:
                    index = 1
            else:
                index = 2
    return index

def offset(segment, pattern, LUTS):
    """
    Finds the position (0-7) of the first occurrence of 'pattern' in the current byte of segment.
    Checks bytes from MSB to LSB.
    Returns 32 if pattern not found in the integer.
    """
    lut = LUTS[pattern]
    
    pos = lut[(segment >> 24) & 0xFF]
    if pos < 8:
        return pos
    
    pos = lut[((segment << 8) >> 24) & 0xFF]
    if pos < 8:
        return pos + 8
    
    pos = lut[((segment << 16) >> 24) & 0xFF]
    if pos < 8:
        return pos + 16
    
    pos = lut[segment & 0xFF]
    if pos < 8:
        return pos + 24
        
    return 32

def mip(volume, mask, depth, i, j, LUTS):
    """
    Renders MIP for a single pixel (i, j).
    """
    pattern = max_interval(mask, depth, i, j)
    
    if pattern == 0:
        return 0
    
    max_density = 0
    
    for k in range(depth):
        segment = mask[k][j][i]
        
        while True:
            pos = offset(segment, pattern, LUTS)
            
            if pos >= 32:
                break
            
            voxel_z = k * 16 + (pos // 2)
            density = volume[voxel_z][j][i]
            
            if density > max_density:
                max_density = density
            
            segment &= ~(0xC0000000 >> pos)
            
    return max_density
```

### Edge Cases and Pitfalls
*   **Complexity with More Intervals:** For $n \ge 4$ intervals requiring more than 2 bits per voxel, the bitwise logic in `MaxInterval` becomes complex. The source suggests using a lookup table approach to find the bit pattern representing the highest density interval instead of pure bitwise operations [S1, unofficial].
*   **Segment Modification:** The `Offset` function relies on the `segment` variable being modified (`segment &= ...`) to remove processed samples. This allows the same LUT technique to be reused for subsequent samples in the same integer [S1, unofficial].
*   **Precision:** The method assumes piecewise constant density. Extending to bilinear interpolation requires additional handling not detailed in the core algorithm [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** Preprocessing is $O(V)$ where $V$ is the number of voxels [S1, unofficial]. Rendering is $O(R \cdot K)$ where $R$ is the number of rays and $K$ is the number of segments per ray [G]. However, the inner loop only processes voxels belonging to the highest density interval, significantly reducing the number of density lookups and comparisons compared to standard MIP [S1, unofficial].
*   **Memory Complexity:** Requires an additional `mask` array of size proportional to the volume, specifically `depth * height * width` integers [S1, unofficial]. For $n=4$, this is roughly $1/16$th the size of the original volume if stored as bits, but stored as integers, it is $1/16$th the number of elements but 32x the size per element, resulting in a net size of $1/2$ the original volume's memory footprint (assuming original volume is 8-bit or 16-bit) [G].
*   **Strengths:** Eliminates unnecessary resampling of low-density voxels [S1, unofficial]. Fast bitwise operations for interval detection [S1, unofficial].
*   **Limitations:** Discretization of density domain may lose precision if intervals are too coarse [G]. Bitwise logic complexity increases with more intervals [S1, unofficial].
*   **When to Use:** When the density distribution has a clear separation between background/low-density structures and high-density structures of interest, and windowing parameters $L$ and $H$ are well-defined [S1, unofficial].

## Background

*   **Origin:** The method was described in the context of interactive volume rendering for medical data visualization [S1, unofficial].
*   **History:** It is presented as an acceleration technique for MIP, building on the concept of interval encoding to avoid resampling irrelevant data [S1, unofficial].
*   **Usage:** Primarily used in medical data evaluation where windowing is standard practice to highlight specific tissue types (e.g., bone, soft tissue) [S1, unofficial].
