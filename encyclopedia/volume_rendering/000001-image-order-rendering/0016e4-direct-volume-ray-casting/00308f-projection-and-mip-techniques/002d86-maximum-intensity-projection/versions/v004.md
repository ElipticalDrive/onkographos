# Maximum Intensity Projection

Also called: Max Intensity Projection, Mip Shader, Ray Traversal -MIP, Local Maximum Intensity Projection (LMIP)

## Overview
Maximum Intensity Projection (MIP) is a volume rendering technique that projects the maximum scalar value encountered along each viewing ray onto the 2D image plane [S1, S2, unofficial][S3][S4, S5, S6, S7, S8, S9, S10, S11, S12, S13, S14, S15, S16, S17, S18, S19, S20, S21, S22, S23, S24, S25, S26, S27, unofficial][S28][S29, book][S30, unofficial][S31][S32, S33, S34, S35, S37, S38, S39, S40, unofficial]. It solves the problem of visualizing high-intensity structures, such as contrast-enhanced blood vessels in angiography or dense bone in CT scans, by emphasizing the brightest voxels while ignoring lower-intensity background or intermediate tissue [S5, S11, S23, S24, S25, S26, S27, unofficial][S28][S29, book][S30, S35, unofficial]. Unlike standard Direct Volume Ray Casting which accumulates opacity and color via the emission-absorption model [19-direct-volume-ray-casting.md], MIP is order-independent and does not require numerical integration of the radiative transfer equation [S2, S9, unofficial][S29, book][S37, unofficial]. It sets itself apart from siblings like [Minimum Intensity Projection](5299-minimum-intensity-projection.md) by selecting the global maximum rather than the minimum, and from [Projection](7205-projection.md) by focusing on intensity maximization rather than summation or average.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset $V$ with dimensions $D_x \times D_y \times D_z$, scalar values $s \in [s_{min}, s_{max}]$, a viewing ray $r(t) = \mathbf{o} + t\mathbf{d}$ for each pixel, and a transfer function $T(s)$ mapping scalar values to color [S2, S12, S16, S25, S26, S27, S32, S33, S34, S40, unofficial].
*   **Output:** A 2D image where each pixel $(u, v)$ contains the color $C$ derived from the maximum scalar value found along the corresponding ray [S1, S2, unofficial][S3][S4, S5, S6, S7, S8, S9, S10, S11, S12, S13, S14, S15, S16, S17, S18, S19, S20, S21, S22, S23, S24, S25, S26, S27, unofficial][S28][S29, book][S30, unofficial][S31][S32, S33, S34, S35, S37, S38, S39, S40, unofficial].

**Data Structures:**
*   **Volume Texture:** The volume data is typically stored in a 3D texture (e.g., `sampler3D` in OpenGL, `Texture3D` in DirectX) with linear filtering enabled for trilinear interpolation [S10, S11, S15, S17, S23, S25, unofficial].
*   **Accumulator:** A single scalar variable `max_val` (or `maximum_intensity`) initialized to the minimum representable value (e.g., $-\infty$, $-1.0$, or $0.0$ depending on data range) [S2, S12, S16, S17, S19, S20, S23, S25, S32, S33, S34, S40, unofficial].
*   **Position Tracker (Optional):** A variable `max_val_pos` to store the 3D coordinates of the sample that produced the maximum value, used for lighting calculations [S16, S26, S40, unofficial].

**Numbered Steps:**
1.  **Ray Generation:** For each pixel $(u, v)$ in the output image, generate a ray $r(t) = \mathbf{o} + t\mathbf{d}$ intersecting the volume domain [19-direct-volume-ray-casting.md]. Compute the entry ($t_{near}$) and exit ($t_{far}$) points of the ray with the volume's axis-aligned bounding box (AABB) [S15, S23, S25, unofficial]. If the ray does not intersect the volume ($t_{near} \ge t_{far}$), output a background color (e.g., black) [S15, unofficial].
2.  **Initialization:** Initialize the accumulator `max_val` to the identity element for the maximum operator (e.g., $-\infty$ or the minimum possible value in the data range) [S2, S16, S32, unofficial]. Initialize `max_val_pos` to the ray origin or null [S16, S26, unofficial].
3.  **Ray Marching Loop:** Iterate along the ray from $t_{near}$ to $t_{far}$ with a step size $\Delta t$ [S2, S12, S15, S17, S25, S34, S40, unofficial].
    *   Calculate the current sample position: $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ [S16, S20, S25, S34, unofficial].
    *   Sample the scalar value $s_i$ from the volume at $\mathbf{p}$ using trilinear interpolation [S12, S15, S23, S25, S33, S34, unofficial].
    *   **Update Rule:** Update the accumulator: $A \leftarrow \max(A, s_i)$ [S2, S12, S25, S32, S33, S34, unofficial].
    *   **Position Tracking:** If $s_i > A$, update $A = s_i$ and store $\mathbf{p}$ in `max_val_pos` [S16, S26, S40, unofficial].
    *   **Early Termination (Optional):** If $A$ exceeds a predefined threshold (e.g., $0.75 \times s_{max}$), break the loop [S4, S8, S12, S25, unofficial]. Note: Standard MIP does not strictly require early termination based on opacity, but threshold-based termination is common in practice [S4, S8, S12, unofficial].
4.  **Classification:** Map the final accumulated maximum value $A$ to a color $C$ using the transfer function: $C = T(A)$ [S2, S4, S14, S19, S26, S32, S33, S40, unofficial].
    *   If lighting is enabled, compute the normal at `max_val_pos` and apply shading to $C$ [S16, S26, S40, unofficial].
    *   Set the output pixel color to $C$ [S12, S16, S26, S32, S33, S40, unofficial].

**Formulas:**
The pixel intensity $I(\mathbf{x}, \omega)$ for a ray with origin $\mathbf{x}$ and direction $\omega$ is defined as [S8, S14, S30, unofficial]:
$$ I(\mathbf{x}, \omega) = \max_{t \in [0, L]} f(\mathbf{x} + \omega \cdot t) $$
where $L$ is the length of the ray within the volume and $f$ is the scalar field [S8, S14, S30, unofficial].

The update rule for the accumulator $C_{dst}$ and current sample $C_{src}$ is [S2, unofficial]:
$$ C_{dst} \leftarrow \max(C_{dst}, C_{src}) $$

**Parameters:**
*   **Step Size ($\Delta t$):** Determines the distance between samples. Can be fixed (e.g., $0.5$ units) or adaptive [S12, S15, S17, S25, unofficial]. In interactive modes, larger steps (e.g., 50) may be used, while final renders use smaller steps (e.g., 1) [S12, S19, unofficial].
*   **Threshold:** A value used for early termination, often set to $0.75 \times s_{max}$ [S4, S8, S12, unofficial].
*   **Density Thresholds:** Optional lower (`minDensityThreshold`) and upper (`maxDensityThreshold`) bounds to ignore noise or background [S16, unofficial].

**Edge Cases and Pitfalls:**
*   **Loss of Depth Information:** MIP projects the maximum value regardless of depth, causing closer structures to be occluded by further high-intensity structures [S8, S12, S27, unofficial][S28][S30, S38, unofficial]. This can lead to misinterpretation of spatial relationships [S9, S27, unofficial][S28][S30, S38, unofficial].
*   **No Opacity Accumulation:** Since opacity is not accumulated, standard alpha blending cannot be used. Hardware extensions like `GL_EXT_blend_minmax` are required if using GPU blending, or the logic must be implemented in the shader [S9, unofficial][S36].
*   **Degenerate Rays:** Rays missing the volume or having $t_{near} \ge t_{far}$ must be handled to avoid invalid memory access or incorrect results [S15, S23, unofficial].
*   **Data Range:** The initialization of `max_val` must be lower than any possible value in the volume (e.g., $-\infty$ for signed data, $0.0$ for unsigned data assumed to be non-negative) [S12, S17, S20, S23, S34, unofficial].

**Pseudocode:**
```python
def render_mip(volume_texture, transfer_function, ray_origin, ray_direction, t_near, t_far, step_size, threshold=None):
    """
    Renders a single pixel using Maximum Intensity Projection.
    
    Args:
        volume_texture: 3D texture object supporting trilinear sampling.
        transfer_function: Function mapping scalar value to color.
        ray_origin: 3D vector (x, y, z).
        ray_direction: 3D vector (x, y, z), assumed normalized.
        t_near: Entry point of ray into volume.
        t_far: Exit point of ray from volume.
        step_size: Distance between samples.
        threshold: Optional early termination threshold.
        
    Returns:
        color: 4D vector (r, g, b, a).
    """
    # 1. Initialize accumulator
    # Use negative infinity or minimum possible value for the data type
    max_val = -float('inf')
    max_val_pos = None
    
    # 2. Ray Marching
    t = t_near
    while t < t_far:
        # Calculate sample position
        pos = ray_origin + ray_direction * t
        
        # Sample volume value (trilinear interpolation)
        # Assuming volume_texture.sample(pos) returns a scalar or a vector where .r is the scalar
        sample_value = volume_texture.sample(pos).r
        
        # Update maximum
        if sample_value > max_val:
            max_val = sample_value
            max_val_pos = pos
            
        # Early termination if threshold is provided and exceeded
        if threshold is not None and max_val >= threshold:
            break
            
        # Advance along ray
        t += step_size
        
    # 3. Classification
    # If no valid value was found (e.g., ray missed volume, though t_near/t_far should prevent this)
    if max_val == -float('inf'):
        return vec4(0.0, 0.0, 0.0, 0.0) # Background color
        
    # Map max value to color
    color = transfer_function(max_val)
    
    # Optional: Lighting calculation if max_val_pos is available
    # if max_val_pos is not None:
    #     normal = compute_normal(max_val_pos)
    #     color = apply_lighting(color, normal, ray_direction)
        
    return color
```

## Subtopics

### [Local Maximum Intensity Projection](6054-local-maximum-intensity-projection.md)
Selects the first local intensity maximum above a threshold instead of the global maximum, preserving some depth information.

### [Fast Maximum Intensity Projection (MIP)](6635-fast-maximum-intensity-projection-mip.md)
Accelerates MIP using shear-warp projection and interval decomposition to avoid unnecessary resampling.

### [MIP with Offset Lookup](6637-mip-with-offset-lookup.md)
Uses binary volume masks and lookup tables to skip low-density intervals, focusing only on the highest density interval.

### [Priority Queue MIP with Min/Max Grids](10338-priority-queue-mip-with-min-max-grids.md)
Uses a priority queue and multilevel grids to efficiently find the maximum value, skipping regions with lower maximums.

### Morphological Maximum Intensity Projection (MMIP) with Morphological Closing
Prevents hole formation in non-axial views caused by undersampling by applying a morphological closing operation to the 2D projection image after voxel projection [S42]. Uses a 2x2x2 structuring element [S42]. Standard MIP for axial views can overwrite old values by projecting low-to-high, but non-axial views require this closing to handle undersampling holes [S42].

### Closest Vessel Projection
A local projection technique often used in slab imaging for vascular structure diagnosis [S28]. It requires setting an appropriate threshold for the local maximum, which is dataset-specific, making it more difficult to apply than standard MIP [S28].

### FVR Approximation of Maximum Intensity Projection
Approximates MIP using Fourier Volume Rendering (FVR) by preprocessing the dataset with $v = b^v$ (where $b$ is a small number, e.g., 2), performing FVR projection, and then taking the base-$b$ logarithm of the result [S41, unofficial]. This method suffers from artifacts due to non-linear compression of the resampling filter, worsening the signal-to-noise ratio [S41, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ per ray, where $N$ is the number of samples along the ray. With acceleration structures (e.g., multilevel grids, priority queues), the average case can be significantly faster by skipping empty or low-intensity regions [S2, S22, S41, unofficial].
*   **Memory Complexity:** $O(V)$ for the volume data, where $V$ is the number of voxels. Acceleration structures add overhead [S2, S22, unofficial].
*   **Measured Performance:** Performance depends heavily on the implementation (CPU vs. GPU) and acceleration techniques. GPU-based implementations using 3D textures and fragment shaders are common for real-time rendering [S11, S15, S25, unofficial].
*   **Strengths:** Simple to implement, order-independent, emphasizes high-intensity structures (vessels, bones), no need for complex transfer functions for opacity [S2, S5, S9, S11, S23, S25, unofficial][S29, book][S35, unofficial].
*   **Limitations:** Loss of depth information, occlusion of closer structures by further high-intensity ones, no differentiation of front/behind [S8, S12, S27, unofficial][S28][S30, S38, S39, unofficial].
*   **When to Use:** Visualization of angiography, bone structures in CT, or any scenario where high-intensity features are of primary interest and depth cues are secondary [S1, S2, S5, S8, S11, S23, S25, unofficial][S29, book][S30, S35, unofficial].
*   **When Not to Use:** When depth perception is critical, or when structures of interest have similar intensities to background noise [S8, S12, S27, unofficial][S28][S30, S38, unofficial].

## Background
Maximum Intensity Projection (MIP) originated as a simple compositing technique for volume rendering, particularly in medical imaging [S1, S2, unofficial][S3][S4, S5, S6, S7, S8, S9, S10, S11, S12, S13, S14, S15, S16, S17, S18, S19, S20, S21, S22, S23, S24, S25, S26, S27, unofficial][S28][S29, book][S30, unofficial][S31][S32, S33, S34, S35, S37, S38, S39, S40, unofficial]. It is widely used for Magnetic Resonance Angiography (MRA) and Computed Tomography Angiography (CTA) to visualize blood vessels [S1, S2, unofficial][S3][S5, S8, S9, S11, S23, S25, unofficial][S29, book][S30, S35, unofficial]. The technique approximates density integrals by the maximum density value along viewing rays [S8, S30, unofficial]. It is often implemented using GPU shaders, leveraging the `GL_EXT_blend_minmax` extension for hardware acceleration [S9, unofficial][S36]. Variants like LMIP were proposed to address the loss of depth information inherent in standard MIP [S8, S30, unofficial].
