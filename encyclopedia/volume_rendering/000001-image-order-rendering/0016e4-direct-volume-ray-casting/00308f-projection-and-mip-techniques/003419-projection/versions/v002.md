# Projection

Also called: Direct Volume Rendering via Projection, Orthographic Projection (Summation), Summation Projection, Total Intensity Projection, Voxel Projection

## Overview
Projection is a direct volume rendering technique that visualizes the total accumulated intensity of a 3D volume along a specific axis by summing voxel values [S1, S2, unofficial]. It differs from standard ray casting by using a commutative summation aggregation function instead of front-to-back compositing, making the result independent of sampling order and enabling simple parallelization [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D scalar volume $V$ with dimensions $D_x \times D_y \times D_z$.
- Output: A 2D image $I$ with dimensions $D_y \times D_z$ (assuming projection along the X-axis).

**Data Structures:**
- The input volume is stored as a contiguous 3D array. In the reference implementation, the first dimension corresponds to the X-axis (sagittal slices), the second to the Y-axis (coronal slices), and the third to the Z-axis (axial slices) [S1, unofficial].
- The output accumulator is a 2D array initialized to zero.

**Steps:**
1. Initialize the output image $I$ as a 2D array of zeros with shape $(D_y, D_z)$ [S1, unofficial].
2. Iterate through each index $i$ along the projection axis (X-axis, range $0$ to $D_x - 1$) [S1, unofficial].
3. Extract the 2D slice $S_i$ at index $i$, which has shape $(D_y, D_z)$ [S1, unofficial].
4. Add the slice $S_i$ to the accumulator $I$ element-wise: $I \leftarrow I + S_i$ [S1, unofficial].
5. Repeat steps 2-4 for all slices along the projection axis.

**Pseudocode:**
```python
def projection_sum(volume):
    """
    Computes the total intensity projection along the first axis (X-axis) of a 3D volume.
    
    Args:
        volume (list of lists of lists or numpy array): 3D array of shape (Dx, Dy, Dz).
        
    Returns:
        list of lists: 2D array of shape (Dy, Dz) containing the summed intensities.
    """
    # Get dimensions
    Dx = len(volume)
    Dy = len(volume[0])
    Dz = len(volume[0][0])
    
    # Initialize output accumulator with zeros
    # Shape: (Dy, Dz)
    accumulator = [[0.0 for _ in range(Dz)] for _ in range(Dy)]
    
    # Iterate through each slice along the X-axis
    for i in range(Dx):
        # Extract the 2D slice at index i
        # Slice shape: (Dy, Dz)
        slice_data = volume[i]
        
        # Add slice to accumulator element-wise
        for y in range(Dy):
            for z in range(Dz):
                accumulator[y][z] += slice_data[y][z]
                
    return accumulator
```

**Parameters:**
- The projection axis is determined by the iteration order. In the cited example, the X-axis is the projection axis [S1, unofficial].
- Typical input: Medical CT volumes, e.g., shape $360 \times 360 \times 330$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Axis Definition:** The mapping of array dimensions to anatomical axes (X, Y, Z) depends on the data format (e.g., NIfTI). The algorithm must align the iteration axis with the desired projection direction [S1, unofficial].
- **Precision:** Summing many voxels can lead to floating-point precision issues if the volume is large and values are small, though standard float32 is typically sufficient for medical imaging [S1, unofficial].
- **Boundary Conditions:** The method assumes the volume is fully contained within the defined grid. No ray intersection logic is required as it is a direct array summation [S1, unofficial].

## Subtopics

### [Maximum Intensity Projection](902-maximum-intensity-projection.md)
Uses the maximum value along the ray instead of the sum. Best for visualizing high-density structures like bones or contrast agents.

### [Minimum Intensity Projection](5299-minimum-intensity-projection.md)
Uses the minimum value along the ray. Useful for visualizing low-density structures like airways or vessels.

### [Forward Projection (aTx)](1492-forward-projection-atx.md)
A specific mathematical formulation often used in tomography, relating to the projection operation but typically involving interpolation and weighting not present in simple summation.

## Operating characteristics
- **Time Complexity:** $O(D_x \cdot D_y \cdot D_z)$, where $D_x$ is the number of slices along the projection axis, and $D_y, D_z$ are the image dimensions. It is linear with respect to the total number of voxels.
- **Memory Complexity:** $O(D_y \cdot D_z)$ for the output image. The input volume must be stored in memory.
- **Performance:** Extremely fast compared to ray casting as it involves simple addition without interpolation, transparency calculations, or sorting. It can be parallelized trivially across slices or pixels [S2, unofficial].
- **Strengths:** Simple implementation, high performance, no need for transfer functions or compositing logic.
- **Limitations:** Occlusion is not handled; overlapping structures are summed, which can obscure details. It does not provide depth cues or surface shading. It is sensitive to the projection axis choice [S1, unofficial].
- **When to use:** Quick visualization of total intensity, such as in medical imaging for assessing overall density or in scientific visualization for total mass projection.
- **When not to use:** When depth perception, surface detail, or isolation of specific structures is required.

## Background
The method is a fundamental technique in direct volume rendering, often introduced alongside Maximum Intensity Projection (MIP) [S1, S2, unofficial]. It is widely used in medical imaging (CT, MRI) to create orthogonal views (sagittal, coronal, axial) by summing along the respective axes [S1, unofficial]. The term "Orthographic Projection" is used to distinguish it from perspective projection, although in volume rendering, it specifically refers to the summation along parallel rays [S2, unofficial].
