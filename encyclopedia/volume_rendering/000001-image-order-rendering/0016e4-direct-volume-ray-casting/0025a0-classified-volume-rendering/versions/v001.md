# Classified Volume Rendering

Also called: DVR, Direct Volume Rendering, Fast Volume Rendering with Run-Length Encoded Classified Data, Volume Rendering (VR), vpRenderClassifiedVolume algorithm

## Overview
Classified Volume Rendering is a method that precomputes a volume dataset into a run-length encoded structure of classified voxels to enable rapid rendering with fixed classification but arbitrary view and shading parameters [S1]. It solves the performance bottleneck of repeated transfer function evaluation by decoupling the static classification step from the dynamic projection step, making it distinct from standard Direct Volume Rendering which evaluates transfer functions per sample [S1]. Unlike Cinematic Rendering, which uses HDR light maps for natural illumination, this method typically relies on synthetic light sources and standard compositing [S2, unofficial].

## How it works
The method consists of two distinct phases: a preprocessing phase that creates the classified data structure, and a rendering phase that projects this data.

### Inputs and Outputs
**Inputs:**
*   Raw volume data (e.g., CT or MR scalar values).
*   Classification function (typically trapezoidal functions for tissue types).
*   View transformation matrix and shading parameters (light position, camera orientation).

**Outputs:**
*   Precomputed run-length encoded classified volume data structure.
*   Final 2D image buffer.

### Data Structures
The core data structure is a **run-length encoded classified volume**. While the exact bit-packing is implementation-dependent, the logical layout consists of sequences of (Value, Count) pairs or similar run-length encoding (RLE) structures that store the pre-classified color and opacity contributions along rays or in voxel space. The VolPack implementation uses a context (`vpContext`) to store this precomputed data [S1].

### Steps

#### Phase 1: Precomputation
1.  **Load Volume Data**: Read the raw scalar volume dataset [S1].
2.  **Choose Classification Function**: Define the transfer functions. For medical imaging, trapezoidal functions are used to separate tissue types (e.g., bone, soft tissue) based on attenuation threshold levels (e.g., Hounsfield units) [S2, unofficial].
3.  **Precompute Classified Volume**:
    *   For each voxel in the volume, determine the tissue type(s) represented using the predefined attenuation thresholds [S2, unofficial].
    *   Assign specific color and opacity values to each tissue type [S2, unofficial].
    *   Calculate the weighted sum of the percentage of each tissue type represented in the voxel to determine the overall color and transparency of that voxel [S2, unofficial].
    *   Store this classified data in the run-length encoded structure [S1].
    *   *Note*: This step can take several minutes depending on volume size [S1].

#### Phase 2: Rendering Loop
1.  **Set View and Shading Parameters**: Configure the camera projection, view matrix, and light sources [S1].
2.  **Render**: Call the rendering routine (e.g., `vpRenderClassifiedVolume`) [S1].
    *   Simulate rays of light projected through the 3D volume containing the classified voxels [S2, unofficial].
    *   For each ray, traverse the run-length encoded data.
    *   Each voxel passed by the simulated ray modulates the color of the light depending on its pre-assigned color and transparency [S2, unofficial].
    *   Accumulate the contributions to form the final projection [S2, unofficial].
    *   Place the result in the image buffer declared by the image setting routine (e.g., `vpSetImage`) [S1].
3.  **Repeat**: Change view or shading parameters and repeat step 2 without re-precomputing the classified volume [S1].

### Formulas
The classification of a voxel $v$ with scalar value $d_v$ involves mapping $d_v$ to color $C_v$ and opacity $\alpha_v$ using the chosen transfer function $T(d)$ [S2, unofficial]. For trapezoidal functions, the opacity is non-zero within a specific range $[t_{min}, t_{max}]$ and varies linearly or is constant within that range [S2, unofficial].

The final pixel color $C_{pixel}$ is the result of the projection/compositing of the classified voxels along the ray. While the specific compositing formula is inherited from the parent [Direct volume ray casting](19-direct-volume-ray-casting.md), the key distinction is that $C_i$ and $\alpha_i$ are retrieved from the precomputed classified data rather than computed on the fly from the raw scalar $d_i$ [S1][S2, unofficial].

### Parameters
*   **Trapezoid Slope**: Manipulating the slope of the trapezoidal transfer function allows real-time adjustment of the visibility of structures. Sliding the trapezoid towards lower Hounsfield unit values includes more structures with lower attenuation (e.g., smaller vessels) [S2, unofficial].
*   **Precomputation Time**: Several minutes for large volumes [S1].

### Edge Cases and Pitfalls
*   **Masking Pathology**: VR can mask anatomical information and pathology. For example, in intracranial aneurysm visualization, bone subtraction is often required to avoid missing critical information, as the bone may obscure the aneurysm [S2, unofficial].
*   **Fixed Classification**: This method is not suitable if the classification (transfer function) needs to change frequently. In such cases, an unclassified volume with a min-max octree is preferred [S1].

## Subtopics

### Unclassified Volume Rendering with Min-Max Octree
Uses a min-max octree to allow frequent changes to the classification function (transfer function) without full precomputation. Choose this when the classification needs to be adjusted frequently [S1].

### Cinematic Rendering
Uses HDR rendering light maps for natural illumination, shadows, and ambient occlusion, unlike the synthetic light sources of Classified Volume Rendering. Choose this for photorealistic medical visualization where performance is less critical than physical accuracy [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: Precomputation is $O(N)$ where $N$ is the number of voxels, and can take several minutes [S1]. Rendering is fast, as it avoids per-sample transfer function evaluation, scaling with the number of rays and the length of runs in the encoded data [S1].
*   **Memory Complexity**: Requires additional memory to store the run-length encoded classified volume structure [S1].
*   **Strengths**: Extremely fast rendering speed for repeated views with fixed classification; allows real-time manipulation of shading and view parameters [S1][S2, unofficial].
*   **Limitations**: Not suitable for dynamic classification; precomputation time is significant; can mask pathology if not carefully configured (e.g., bone subtraction needed) [S1][S2, unofficial].
*   **When to use**: When many renderings will be made from the same volume without changing the classification [S1].
*   **When not to use**: When the classification (transfer function) needs to be adjusted frequently; when natural illumination and complex lighting effects (shadows, ambient occlusion) are required [S1][S2, unofficial].

## Background
Classified Volume Rendering is a technique described in the VolPack User's Guide, part of the VolPack library developed at Stanford University [S1]. It is a foundational method in direct volume rendering, specifically optimizing for the case where the transfer function is static. The technique is widely used in medical imaging visualization, particularly in CT and MR post-processing, to visualize complex anatomy [S2, unofficial].
