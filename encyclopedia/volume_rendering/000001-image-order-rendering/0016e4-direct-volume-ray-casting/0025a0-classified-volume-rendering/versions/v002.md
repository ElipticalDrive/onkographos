# Classified Volume Rendering

Also called: Fast Volume Rendering with Run-Length Encoded Classified Data, Volume Rendering (VR), vpRenderClassifiedVolume, vpRenderClassifiedVolume algorithm

## Overview
Classified Volume Rendering is a direct volume ray casting method that achieves maximum rendering speed by precomputing optical properties (color and opacity) for every voxel, storing them in a run-length encoded format [S1, S3]. Unlike standard direct volume rendering which applies the transfer function during ray casting, this method fixes the classification beforehand, allowing subsequent renders to vary view transformations and shading parameters without recomputing the material properties [S1, S3]. It is distinct from [Direct Volume Rendering](19-direct-volume-ray-casting.md) in that it trades flexibility in transfer function adjustment for significant performance gains, making it suitable for scenarios requiring many renders of the same volume with identical classification [S1, S3].

## How it works
The method operates in two distinct phases: a precomputation phase where the raw scalar volume is classified and compressed, and a rendering phase where the compressed data is projected using standard ray casting techniques.

### Inputs and Outputs
**Inputs:**
1.  **Raw Volume Data:** A 3D grid of scalar values (e.g., Hounsfield units for CT) [S1][S2, unofficial].
2.  **Classification Function:** A set of transfer functions, typically defined as trapezoids for different tissue types, mapping scalar values to color and opacity [S1][S2, unofficial].
3.  **View and Shading Parameters:** Camera position, orientation, and lighting model settings used only in the rendering phase [S1].

**Outputs:**
1.  **Preclassified Volume:** A data structure containing run-length encoded, classified voxel data (color and opacity) [S1, S3].
2.  **Rendered Image:** A 2D pixel buffer containing the final projected image [S1].

### Data Structures
The core data structure is the **Preclassified Volume**. While the exact internal bit-packing of the run-length encoding is not specified in the sources, it is described as a special data structure containing run-length encoded, classified volume data [S1]. The classification step assigns a specific color and opacity to each voxel based on the transfer function [S2, unofficial].

The rendering context (e.g., `vpContext` in VolPack) stores:
*   The preclassified volume data [S1, S3].
*   Current viewing parameters (camera origin $\mathbf{o}$, direction $\mathbf{d}$) [S1].
*   Current shading parameters (light positions, material properties) [S1].
*   The output image buffer, typically defined as an array of bytes per scan, height, and bytes per pixel (e.g., 4 bytes/pixel for RGB+opacity) [S1].

### Numbered Steps

**Phase 1: Precomputation**
1.  **Load Volume Data:** Read the raw scalar voxel grid into memory [S1].
2.  **Choose Classification Function:** Define the transfer function. For medical imaging, this often involves defining trapezoids for specific tissue types (e.g., bone, soft tissue) using predefined attenuation threshold levels [S2, unofficial].
3.  **Precompute Classified Volume:** Iterate through every voxel in the volume dataset [S1][S2, unofficial]:
    *   Determine the tissue type represented in the voxel using the attenuation thresholds [S2, unofficial].
    *   Calculate the weighted sum of the percentage of each tissue type represented in the voxel to determine the overall color $C$ and transparency (opacity) $\alpha$ [S2, unofficial].
    *   Store the resulting $(C, \alpha)$ pair for the voxel.
    *   Compress the resulting classified volume data using run-length encoding [S1].
    *   *Note:* This step can take several minutes depending on volume size [S1].

**Phase 2: Rendering (Repeatable)**
1.  **Set View and Shading Parameters:** Configure the camera and lighting for the desired view [S1].
2.  **Render:** Call the rendering routine (e.g., `vpRenderClassifiedVolume`) [S1, S3].
    *   Simulate rays of light projected through the 3D volume containing the classified voxels [S2, unofficial].
    *   For each pixel, perform ray casting through the preclassified volume [S2, unofficial].
    *   As rays pass through voxels, modulate the light color based on the pre-assigned color and transparency of the voxels [S2, unofficial].
    *   Composite the contributions along the ray to produce the final pixel value [S2, unofficial].
    *   Place the result in the image buffer declared by the image setup routine [S1].
3.  **Enhance Perception (Optional):** Apply additional effects such as reflections and shadows on the surface of the rendered image to enhance 3D perception [S1][S2, unofficial].

### Formulas
The classification of a voxel $v$ with scalar value $d_v$ involves mapping $d_v$ to color $C_v$ and opacity $\alpha_v$ using the transfer function $T$:
$$
(C_v, \alpha_v) = T(d_v)
$$
For tissue separation, $T$ is often defined by trapezoidal functions for each tissue type [S2, unofficial]. The final color and transparency of a voxel may be a weighted sum if multiple tissue types are represented within the voxel volume [S2, unofficial].

The rendering process uses the standard front-to-back compositing equation (as detailed in [Direct volume ray casting](19-direct-volume-ray-casting.md)) to integrate the pre-classified samples along the ray:
$$
C'_{i} = C'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i C_i
$$
$$
\alpha'_{i} = \alpha'_{i-1} + (1 - \alpha'_{i-1}) \alpha_i
$$
where $C_i$ and $\alpha_i$ are the precomputed color and opacity of the $i$-th voxel intersected by the ray [S2, unofficial].

### Parameters
*   **Precomputation Time:** Several minutes, depending on volume size [S1].
*   **Trapezoid Slope:** Can be adjusted to include/exclude structures with lower attenuation (e.g., smaller vessels) [S2, unofficial]. *Note: Adjusting this requires re-precomputation.*

### Edge Cases and Pitfalls
*   **Fixed Classification:** The opacity transfer function must not change between renderings because the voxel opacities are fixed in the preclassified volume [S3]. Changing the transfer function requires re-running the precomputation phase [S1].
*   **Masking Pathology:** Volume rendering can mask anatomical information and pathology. For example, in intracranial aneurysm visualization, VR without bone subtraction may hide critical details compared to methods with bone subtraction [S2, unofficial].
*   **Performance Trade-off:** While rendering is the fastest mode, the initial precomputation is expensive [S1]. It is not suitable if the classification needs to change frequently [S1].

### Pseudocode
```python
# Phase 1: Precomputation
def precompute_classified_volume(raw_volume, transfer_function):
    """
    raw_volume: 3D array of scalar values (e.g., Hounsfield units)
    transfer_function: Function mapping scalar value to (color, opacity)
    Returns: Run-length encoded classified volume data
    """
    classified_volume = []
    for voxel in raw_volume:
        scalar_value = voxel.value
        # Apply transfer function (e.g., trapezoid-based tissue classification)
        color, opacity = transfer_function(scalar_value)
        classified_volume.append((color, opacity))
    
    # Compress using run-length encoding
    compressed_data = run_length_encode(classified_volume)
    return compressed_data

# Phase 2: Rendering
def render_classified_volume(compressed_volume, view_params, shading_params):
    """
    compressed_volume: Precomputed run-length encoded classified data
    view_params: Camera origin, direction, etc.
    shading_params: Lighting model parameters
    Returns: 2D image buffer
    """
    image_buffer = initialize_image_buffer(view_params.resolution)
    
    for pixel in view_params.pixels:
        ray = generate_ray(pixel, view_params)
        accumulated_color = (0, 0, 0)
        accumulated_opacity = 0.0
        
        # Ray march through the compressed volume
        # The run-length encoding allows skipping empty or uniform regions
        for voxel_sample in ray_march_compressed(compressed_volume, ray):
            color, opacity = voxel_sample.color, voxel_sample.opacity
            
            # Front-to-back compositing
            transmittance = 1.0 - accumulated_opacity
            accumulated_color = accumulated_color + transmittance * opacity * color
            accumulated_opacity = accumulated_opacity + transmittance * opacity
            
            # Early termination if fully opaque
            if accumulated_opacity >= 1.0:
                break
        
        # Apply shading effects (e.g., reflections, shadows) if needed
        final_color = apply_shading(accumulated_color, shading_params)
        image_buffer[pixel] = final_color
        
    return image_buffer
```

## Subtopics

### Min-Max Octree Rendering
An alternative approach that precomputes a min-max octree to accelerate rendering of unclassified volumes, allowing flexible transfer functions but at a slower speed than classified rendering [S1].

### Raw Volume Rendering
Renders the raw voxel array directly, allowing dynamic transfer functions and octree acceleration, but is slower than classified rendering [S3].

## Operating characteristics
*   **Time Complexity:** Precomputation is $O(N)$ where $N$ is the number of voxels, taking several minutes for large volumes [S1]. Rendering is $O(P \cdot R)$ where $P$ is pixels and $R$ is ray length, but significantly faster than raw rendering due to optimized data access and lack of per-sample transfer function evaluation [S1, S3].
*   **Memory Complexity:** Requires storage for the raw volume and the preclassified volume. The run-length encoding helps compress the classified data [S1].
*   **Strengths:** Fastest rendering mode when the classification is fixed; allows rapid iteration over view transformations and shading parameters [S1, S3].
*   **Limitations:** Inflexible; cannot change the opacity transfer function without re-precomputing the entire volume [S3]. Precomputation time is high [S1].
*   **When to Use:** When many renderings of the same volume are required with the same classification [S1, S3].
*   **When Not to Use:** When the classification needs to be adjusted frequently or interactively [S1].

## Background
Classified Volume Rendering is part of the VolPack library, a software package for volume rendering [S1]. It was designed to provide a high-performance rendering option for scenarios where the volume data and classification are static [S1]. The method relies on the principle that classification is often the most computationally expensive part of the ray casting pipeline when done per-sample, and precomputing it allows the rendering loop to focus solely on projection and shading [S1][S2, unofficial].
