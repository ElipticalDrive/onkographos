# Parallel Domain-Decomposed Ray Casting

Also called: MPI Ray Casting, Distributed Ray Casting

## Overview
Parallel Domain-Decomposed Ray Casting is a parallel volume rendering technique that accelerates rendering by dividing a 3D volume dataset among multiple processing units (nodes), where each unit casts rays through its assigned subvolume independently using a front-to-back algorithm [S1, S3, unofficial]. It solves the scalability problem of direct volume ray casting for high-resolution datasets that exceed the memory of a single processor by distributing both data and computation [S2, unofficial]. Unlike image-order methods (e.g., [Image-order rendering](16-image-order-rendering.md)) or image-space subdivision, this method uses **data-space subdivision** (object-space partitioning), allowing nodes to perform local ray tracing without inter-processor communication during the sampling phase [S1, S2, unofficial]. The final image is constructed by compositing the resulting partial images (subimages) in a determined depth order [S1, S2, unofficial].

## How it works
The method consists of three phases: Data Distribution, Local Ray Casting, and Parallel Compositing. It builds on the core computational engine of [Direct volume ray casting](19-direct-volume-ray-casting.md).

### Inputs and Outputs
*   **Inputs**:
    *   Volume data: A 3D array of scalar values (e.g., `float32`), shape $(Z, Y, X)$ [S3, unofficial].
    *   Transfer functions:
        *   Opacity map: 2D array, 2 rows. Row 1: scalar positions; Row 2: opacity values [S3, unofficial].
        *   Color map: 2D array, 5 rows. Row 1: scalar positions; Rows 2-4: R, G, B values [S3, unofficial].
    *   Grid dimensions: Integers $p_x, p_y, p_z$ defining the 3D grid of processes [S3, unofficial].
    *   Sampling step size: $\Delta t$ (e.g., 0.5) [S3, unofficial].
*   **Outputs**:
    *   Final image: A 2D array of RGB color values (e.g., `uint8`) [S3, unofficial].

### Data Structures and Layout
The volume is partitioned into $p_x \times p_y \times p_z$ subvolumes. For a total volume size $(X_{Total}, Y_{Total}, Z_{Total})$, the segment sizes are:
$$
X_{seg} = \lfloor X_{Total} / p_x \rfloor, \quad Y_{seg} = \lfloor Y_{Total} / p_y \rfloor, \quad Z_{seg} = \lfloor Z_{Total} / p_z \rfloor
$$
Rank $k$ (where $k = i + j \cdot p_x + l \cdot p_x p_y$ for grid indices $i,j,l$) receives the slice:
$$
\text{data}[l \cdot Z_{seg} : (l+1) \cdot Z_{seg}, \quad j \cdot Y_{seg} : (j+1) \cdot Y_{seg}, \quad i \cdot X_{seg} : (i+1) \cdot X_{seg}]
$$
[S3, unofficial]. Boundary conditions apply for the last segments to cover the full extent [S3, unofficial].

### Algorithm Steps

1.  **Initialization and Distribution**:
    *   Rank 0 loads the full volume and transfer functions [S3, unofficial].
    *   Rank 0 partitions the volume into chunks based on $p_x, p_y, p_z$ [S3, unofficial].
    *   Rank 0 sends each chunk along with metadata (transfer functions, grid dimensions) to the corresponding rank using point-to-point communication (e.g., `MPI_Send`) [S3, unofficial].
    *   Other ranks receive their data chunk [S3, unofficial].

2.  **Local Ray Casting**:
    *   Each rank independently executes the front-to-back ray casting algorithm on its local subvolume [S1, S2, S3, unofficial].
    *   **Ray Generation**: For each pixel in the assigned image region, a ray is defined [S2, unofficial].
    *   **Sampling**: The ray is sampled at intervals $\Delta t$ [S3, unofficial].
    *   **Interpolation**: Trilinear interpolation is used to retrieve scalar values from the 8 nearest voxels in the local subvolume [S2, S3, unofficial].
    *   **Classification**: The scalar value is mapped to color $(C_i)$ and opacity $(\alpha_i)$ using the transfer functions [S2, S3, unofficial].
    *   **Compositing**: The front-to-back equation is applied locally:
        $$
        C_{acc}^{(i)} = C_{acc}^{(i-1)} + (1 - \alpha_{acc}^{(i-1)}) \alpha_i C_i
        $$
        $$
        \alpha_{acc}^{(i)} = \alpha_{acc}^{(i-1)} + (1 - \alpha_{acc}^{(i-1)}) \alpha_i
        $$
        [S2, S3, unofficial].
    *   **Result**: Each rank produces a partial image (subimage) consisting of color and opacity meshes for its portion of the image [S3, unofficial].

3.  **Parallel Compositing**:
    *   The subimages must be composited in a strict front-to-back order determined a priori by the spatial arrangement of the subvolumes [S2, unofficial].
    *   The compositing process uses a binary-swap or tree-based reduction strategy to merge partial images [S1, S2, unofficial].
    *   **Associativity**: The Porter-Duff "over" operator is associative: $a \text{ over } (b \text{ over } c) = (a \text{ over } b) \text{ over } c$, allowing independent segment processing [S2, unofficial].
    *   **Communication**: Ranks exchange their color and opacity meshes. For example, in a 2x2x2 grid, ranks with index $\ge p_x p_y$ send their meshes to the corresponding rank $< p_x p_y$ (where $surfaceProcess = rank \% t$ and $t = p_x p_y$) [S3, unofficial].
    *   The receiving rank composites the incoming mesh with its current accumulated result [S3, unofficial].
    *   This continues until all subimages are merged into a single final image [S2, S3, unofficial].
    *   Rank 0 gathers the final composited meshes, converts to `uint8`, and saves the image [S3, unofficial].

### Edge Cases and Pitfalls
*   **Load Imbalance**: Empty voxels (e.g., in head or vessel data) cause uneven computation loads compared to dense data (e.g., vorticity), reducing speedup [S2, unofficial].
*   **Communication Overhead**: On networked workstations, communication can account for ~97% of compositing time [S2, unofficial]. Compression (e.g., 4:1 ratio) can reduce this by 80% [S2, unofficial].
*   **Small Images**: Small image sizes (e.g., 64x64) exhibit less speedup due to fixed overhead costs in rendering and compositing steps [S2, unofficial].
*   **Ordering**: Subvolumes must be partitioned such that an unambiguous front-to-back ordering can be determined for compositing [S2, unofficial].
*   **Remote Execution**: On older systems, REX was unreliable; `rsh` was used as a slower alternative [S1, unofficial].

## Subtopics

### [Parallel Volume Rendering with Local Ray Tracing and Parallel Compositing](7841-parallel-volume-rendering-with-local-ray-tracing-and-paralle.md)
A variant that distributes both volume data and computation to individual processing units to render high-resolution datasets. It distinguishes itself by using data-space subdivision, which is better suited for distributed-memory environments where data can be partitioned, and composites subimages in a determined depth order using a binary-swap method.

## Operating characteristics
*   **Time Complexity**: The local ray casting phase is $O(N \cdot M)$ where $N$ is the number of pixels and $M$ is the number of samples per ray, distributed across $P$ processors, yielding $O(N \cdot M / P)$ for the rendering phase [S2, unofficial]. The compositing phase is $O(P \cdot C)$ where $C$ is the cost of compositing two images, typically logarithmic in $P$ due to binary-swap [S1, S2, unofficial].
*   **Memory Complexity**: Each node stores only its assigned subvolume, reducing memory requirements per node to $V/P$ where $V$ is the total volume size [S1, S2, unofficial].
*   **Performance**: On CM-5 with vorticity data, nearly linear speedup was achieved for image sizes above 64x64 [S2, unofficial]. On networked workstations, communication dominates compositing time [S2, unofficial].
*   **Strengths**: Scalability to large datasets that do not fit in single-node memory; no inter-node communication during the computationally intensive ray casting phase [S1, S2, unofficial].
*   **Limitations**: Load imbalance due to data sparsity; communication bottleneck during compositing on slow networks [S2, unofficial].

## Background
The method was developed to address the speed limitations of volume rendering on single processors. Early work by Dippe and Swensen parallelized geometric ray tracing by dividing world space [S1, unofficial]. Upson argued that ray casting was difficult to parallelize due to the need for global shared memory [S1, unofficial]. This method demonstrated that ray casting could be parallelized at the subvolume level on distributed systems without global shared memory [S1, unofficial]. It was implemented on Sun SPARC-2 and Sun-4/260 workstations (AFITNET) and the Connection Machine CM-5 [S1, S2, unofficial].
