# Mixel Partial-Volume Rendering

Also called: voxel model v2 phase C

## Overview
Mixel Partial-Volume Rendering is a technique that replaces synthetic, blur-derived partial-volume estimates with real, stored mixel fractions at tissue boundaries to blend rendered signals [S1, unofficial]. Unlike sibling methods that may rely on geometric approximations or gradient-based shading, this method preserves the voxel's own texture detail ($S_a$) while blending in the second tissue's slice-mean signal ($S_b$) based on the specific mixel fraction [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel's rendered signal value ($S_a$), the second tissue's slice-mean signal ($S_b$), the mixel fraction ($f$), and a control parameter $pv\_sigma$.
*   **Output:** The blended partial-volume signal value.

**Data Structures:**
The method relies on "sidecar" data structures containing pre-computed mixel fractions. These are stored as `.npy` files (NumPy arrays) associated with specific anatomical regions (e.g., `<Region>_mixel.npy`) [S1, unofficial]. The data must be aligned with the atlas transforms (straightening, flipping) applied to the volume [S1, unofficial].

**Parameters:**
*   $pv\_sigma$: Controls whether partial volume rendering is active. If $pv\_sigma = 0$, the method is disabled and returns the original signal [S1, unofficial].

**Steps:**
1.  Check if $pv\_sigma = 0$. If true, return $S_a$ unchanged [S1, unofficial].
2.  Determine if the current voxel is a "mixed voxel" (i.e., located at a tissue boundary where a second tissue exists).
    *   If the second tissue is absent, the voxel is "pure." Return $S_a$ unchanged [S1, unofficial].
    *   If the voxel is mixed, proceed to step 3.
3.  Retrieve the real stored mixel fraction $f$ for this voxel from the sidecar data [S1, unofficial].
4.  Calculate the output signal using the linear blend formula:
    $$ Output = f \cdot S_a + (1 - f) \cdot S_b $$
    Where:
    *   $f$ is the mixel fraction ($0 < f < 1$).
    *   $S_a$ is the voxel's own rendered value.
    *   $S_b$ is the second tissue's slice-mean signal [S1, unofficial].
5.  Return the calculated $Output$.

**Pseudocode:**
```python
def partial_volume_mixel(S_a, S_b, f, pv_sigma):
    """
    Blends voxel signal S_a with second tissue signal S_b using mixel fraction f.
    
    Args:
        S_a (float): The voxel's own rendered value.
        S_b (float): The second tissue's slice-mean signal.
        f (float): The real stored mixel fraction.
        pv_sigma (float): Control parameter. If 0, PV is disabled.
        
    Returns:
        float: The blended signal value.
    """
    # If partial volume rendering is disabled, return original signal [S1, unofficial]
    if pv_sigma == 0:
        return S_a
        
    # If the voxel is pure (second tissue absent), do not apply blending [S1, unofficial]
    # Note: In implementation, 'f' might be 0 or None for pure voxels, 
    # or a flag indicates absence. Based on notes, we check for mixed status.
    # Assuming f is provided only for mixed voxels, or 0 for pure.
    if f == 0:
        return S_a
        
    # Apply the partial-volume formula [S1, unofficial]
    output = f * S_a + (1 - f) * S_b
    
    return output
```

**Edge Cases and Pitfalls:**
*   **Atlas Transform Mismatch:** If atlas transforms (flip/straighten) are mismatched between the volume and the mixel sidecar, mixel fractions scatter off the 3x3x3 label boundaries, causing rendering errors [S1, unofficial].
*   **Guard Condition:** An objective test is required: >90% of mixed voxels must sit on the transformed atlas's 3x3x3 label boundaries [S1, unofficial].
*   **Sidecar-less Regions:** Regions without a mixel sidecar (e.g., Brain in some configurations, synthetic fallbacks) keep the synthetic path unchanged [S1, unofficial].

## Operating characteristics
*   **Accuracy:** Preserves texture detail in $S_a$ better than synthetic blur methods because it uses real stored mixel fractions rather than approximations [S1, unofficial].
*   **Performance:** Not explicitly quantified in terms of FLOPS, but relies on pre-computed sidecars, suggesting low runtime overhead compared to on-the-fly blur calculations [S1, unofficial].
*   **Limitations:** Highly dependent on the correctness of atlas transforms and the presence of valid mixel sidecars. Fails hard if the >90% boundary guard is not met [S1, unofficial].
*   **Usage Context:** Used in MRI physics simulation platforms for signal equations, k-space, EPI, Dixon, FSE/EPG, SENSE, diffusion, fMRI, and 3D slab acquisition [S1, unofficial].

## Background
This method was introduced as "voxel model v2, phase C" in the `mrisim` project by ea1188 [S1, unofficial]. It represents the final phase of the voxel-model-v2 specification, shifting from synthetic blur-derived mixel fractions to real stored ones [S1, unofficial]. It is wired at both partial-volume call sites: the image path and the quantitative-map PVE (Partial Volume Estimation) [S1, unofficial].
