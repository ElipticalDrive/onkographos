# VIPER Volume Rendering Configuration

Also called: VIPER, VIPER renderer

## Overview
VIPER is an interactive direct volume ray casting renderer designed for regularly spaced rectangular grid data [S1, unofficial]. It solves the problem of configuring visual parameters for volumetric display through a structured, interactive session rather than a single command-line flag set [S1, unofficial]. It differs from its sibling [MAP](13234-map-volume-rendering.md) by requiring strictly regular input data, whereas MAP handles irregular grids via interpolation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A properly formatted file containing regularly spaced 3D scalar data [S1, unofficial].
*   **Output:** A rendered image file with the `.rie` extension [S1, unofficial].

**Data Structures:**
The configuration is not stored in a persistent file but is entered interactively via standard input prompts upon startup [S1, unofficial]. The data structure for the volume is assumed to be a 3D array $V[x][y][z]$ with uniform spacing [S1, unofficial].

**Configuration Steps:**
Upon execution, the renderer prompts the user for the following parameters in order [S1, unofficial]:

1.  **Feedback:** Boolean flag. If true, prints `*` for every data value read. [G] Implementation note: This is a debugging aid and should be disabled for production.
2.  **Scaling:** Three floating-point factors $(s_x, s_y, s_z)$ for the x, y, and z axes.
    *   *Constraint:* $s_x = s_y = s_z$ is required to avoid geometric distortion. The recommended value is $1.0$ [S1, unofficial].
3.  **Volume Trimming:** Boolean flag. If true, prompts for trim distances for each of the six faces of the volume bounding box.
4.  **Object Distances:** Two floating-point values:
    *   $d_{center}$: Distance from eye to the center of the view volume. Recommended heuristic: $d_{center} = \text{volume\_size} + 1$ [S1, unofficial].
    *   $d_{plane}$: Distance from eye to the viewing plane. Recommended value: $1.0$ [S1, unofficial].
5.  **Data Orientation:** Three integer rotation angles $(\theta_x, \theta_y, \theta_z)$ for the x, y, and z axes.
    *   *Recommendation:* Start with $(0,0,0)$ and rotate one axis at a time for iterative exploration [S1, unofficial].
6.  **View Plane Dimensions:** Boolean flag. If true, prompts for horizontal and vertical screen size in pixels.
7.  **Ambient Light Level:** Floating-point value $L_{amb}$. Recommended value: $0.8$ for RCS data [S1, unofficial].
8.  **Light Sources:** Integer $N$ where $1 \le N \le 6$. For each light $i$, prompt for position $(l_{x,i}, l_{y,i}, l_{z,i})$.
    *   *Coordinate System:* Light positions are relative to the viewer's origin, not the volume's coordinate system [S1, unofficial].
9.  **Target Values:** Integer $M$ (number of targets). For each target $j$:
    *   Prompt for scalar value $v_j$.
    *   Prompt for variance $\sigma_j$.
    *   Prompt for RGB color $(r_j, g_j, b_j)$.
    *   Prompt for opacity $\alpha_j$.
    *   *Typical Values:* For Radar Cross Section (RCS) data, $M=3$ with values $\{50, 150, 200\}$ [S1, unofficial].
    *   *Variance:* $\sigma_j \in [8, 12]$ yields good results [S1, unofficial].
    *   *Colors:* Use primary colors. Set dominant color component to $0.8$ and minor components to $0.2$ [S1, unofficial].
10. **Border Matte:** RGB color $(m_r, m_g, m_b)$ for the background border. Recommended neutral blue: $(0.2, 0.2, 0.4)$ [S1, unofficial].

**Pseudocode:**
The following pseudocode represents the interactive configuration loop. It assumes a standard input/output stream.

```python
def viper_configuration():
    # 1. Feedback
    feedback = input("Enable feedback (* per value)? (y/n): ").lower() == 'y'
    if feedback:
        print("[G] Warning: Feedback significantly increases execution time for large files.")

    # 2. Scaling
    print("Enter scaling factors for x, y, z axes.")
    s_x = float(input("x scale: "))
    s_y = float(input("y scale: "))
    s_z = float(input("z scale: "))
    if not (abs(s_x - 1.0) < 1e-6 and abs(s_y - 1.0) < 1e-6 and abs(s_z - 1.0) < 1e-6):
        print("[G] Warning: Non-uniform scaling causes geometric distortion.")

    # 3. Volume Trimming
    trim_faces = input("Trim volume faces? (0/1): ") == '1'
    if trim_faces:
        trim_distances = []
        for face in range(6):
            dist = float(input(f"Trim distance for face {face}: "))
            trim_distances.append(dist)

    # 4. Object Distances
    volume_size = get_volume_size() # [G] Helper to determine max dimension of input grid
    d_center = float(input(f"Distance to center (recommended {volume_size + 1}): "))
    d_plane = float(input("Distance to viewing plane (recommended 1.0): "))

    # 5. Data Orientation
    print("Enter rotation angles for x, y, z axes.")
    theta_x = int(input("x rotation: "))
    theta_y = int(input("y rotation: "))
    theta_z = int(input("z rotation: "))

    # 6. View Plane Dimensions
    change_view = input("Change view plane dimensions? (y/n): ").lower() == 'y'
    if change_view:
        width = int(input("Horizontal size (pixels): "))
        height = int(input("Vertical size (pixels): "))
    else:
        width, height = default_screen_size() # [G] Default to input resolution or standard

    # 7. Ambient Light
    l_amb = float(input("Ambient light level (recommended 0.8): "))

    # 8. Light Sources
    n_lights = int(input("Number of light sources (1-6): "))
    if not (1 <= n_lights <= 6):
        raise ValueError("Light sources must be between 1 and 6.")
    
    lights = []
    for i in range(n_lights):
        print(f"Light {i+1} position (relative to viewer origin):")
        lx = float(input("x: "))
        ly = float(input("y: "))
        lz = float(input("z: "))
        lights.append((lx, ly, lz))

    # 9. Target Values
    m_targets = int(input("Number of target values: "))
    targets = []
    for j in range(m_targets):
        val = float(input(f"Target {j+1} value: "))
        var = float(input(f"Target {j+1} variance (recommended 8-12): "))
        r = float(input(f"Target {j+1} R (0.0-1.0): "))
        g = float(input(f"Target {j+1} G (0.0-1.0): "))
        b = float(input(f"Target {j+1} B (0.0-1.0): "))
        alpha = float(input(f"Target {j+1} opacity (0.0-1.0): "))
        targets.append({
            'value': val,
            'variance': var,
            'color': (r, g, b),
            'opacity': alpha
        })

    # 10. Border Matte
    mr = float(input("Border Matte R (recommended 0.2): "))
    mg = float(input("Border Matte G (recommended 0.2): "))
    mb = float(input("Border Matte B (recommended 0.4): "))
    border_color = (mr, mg, mb)

    return {
        'feedback': feedback,
        'scaling': (s_x, s_y, s_z),
        'trim_distances': trim_distances if trim_faces else None,
        'object_distances': (d_center, d_plane),
        'orientation': (theta_x, theta_y, theta_z),
        'view_plane': (width, height),
        'ambient_light': l_amb,
        'lights': lights,
        'targets': targets,
        'border_matte': border_color
    }
```

## Operating characteristics
*   **Time Complexity:** The rendering time is proportional to the number of voxels processed. Enabling the feedback option significantly increases execution time due to I/O overhead [S1, unofficial].
*   **Memory Complexity:** Requires memory to store the input volume grid and the configuration state [S1, unofficial].
*   **Strengths:** Interactive configuration allows for fine-tuning of transfer functions and lighting without recompilation or complex script writing [S1, unofficial]. The "One more time?" feature allows re-rendering with new parameters without reloading the dataset, saving time for large files [S1, unofficial].
*   **Limitations:** Strictly requires regularly spaced data. It cannot handle irregular grids natively [S1, unofficial].
*   **When to use:** When working with structured grid data (e.g., simulation outputs, medical scans) and interactive parameter adjustment is preferred over batch processing [S1, unofficial].
*   **When not to use:** When input data is irregularly spaced (use [MAP](13234-map-volume-rendering.md) instead) or when non-interactive batch rendering is required [S1, unofficial].

## Background
VIPER was developed as part of research into methods for viewing Radar Cross Section (RCS) data in three dimensions [S1, unofficial]. It is documented in the report "Methods for Viewing Radar Cross Section Data in Three Dimensions" (DTIC ADA258905) [S1, unofficial]. The tool is often compared with MAP, another volumetric rendering tool from the same era, with the primary distinction being VIPER's requirement for regular data spacing versus MAP's ability to interpolate irregular data [S1, unofficial].
