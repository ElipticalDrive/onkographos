# Bézier Curve Opacity Mapping

Also called: opacity curve editor, pokrytieKriv

## Overview
Bézier Curve Opacity Mapping maps scalar volume data values to opacity using a user-defined Bézier curve, allowing non-linear opacity control across a selected data range [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A scalar volume data value $i$ (UINT16, range 0–4095) [S1, unofficial].
*   **Input:** Control points defining the Bézier curve, stored in an array `kriv.suradnice[]` with size `kriv.pocet` [S1, unofficial].
*   **Input:** Editor geometry parameters: left coordinate `edt_left`, top coordinate `edt_top`, width `edt_sir`, and height `edt_vys` [S1, unofficial].
*   **Output:** Opacity $\alpha \in [0, 1]$ [S1, unofficial].

**Data Structures**
*   `kriv`: Structure containing `pocet` (integer count of control points) and `suradnice[]` (array of points with `x` and `y` coordinates in integer pixels relative to the editor) [S1, unofficial].
*   `edt_*`: Integer pixel coordinates defining the bounding box of the curve editor [S1, unofficial].

**Steps**
1.  **Validation:** Check if the curve has at least 2 points (`kriv.pocet > 1`) [S1, unofficial]. If not, return opacity 0.0 [S1, unofficial].
2.  **Normalize Input:** Normalize the input data value $i$ to the range $[0, 1]$ by dividing by the maximum data value (4095.0) [S1, unofficial]:
    $$ \text{norm\_i} = \frac{i}{4095.0} $$
3.  **Normalize Curve Boundaries:** Normalize the x-coordinates of the first ($x_0$) and last ($x_{n-1}$) control points to the range $[0, 1]$ relative to the editor width [S1, unofficial]:
    $$ \text{norm\_oa} = \frac{x_0 - \text{edt\_left}}{\text{edt\_sir}} $$
    $$ \text{norm\_ob} = \frac{x_{n-1} - \text{edt\_left}}{\text{edt\_sir}} $$
4.  **Calculate Parameter $t$:** Compute the normalized parameter $t$ along the curve's x-axis domain [S1, unofficial]:
    $$ t = \frac{\text{norm\_i} - \text{norm\_oa}}{\text{norm\_ob} - \text{norm\_oa}} $$
5.  **Boundary Check:** If $\text{norm\_i} < \text{norm\_oa}$ or $\text{norm\_i} > \text{norm\_ob}$, the input value lies outside the defined curve range [S1, unofficial]. Return opacity 0.0 [S1, unofficial].
6.  **Evaluate Bézier Curve:** Evaluate the Bézier curve at parameter $t$ using a function `vratKrivku(t, kriv)` [S1, unofficial]. This returns a point `krivka` with coordinates $(x(t), y(t))$ [S1, unofficial].
7.  **Normalize and Invert Opacity:** Normalize the y-coordinate to the editor height and invert it to derive opacity [S1, unofficial]:
    $$ \alpha = 1.0 - \frac{y(t) - \text{edt\_top}}{\text{edt\_vys}} $$
    The inversion assumes a screen coordinate system where $y=0$ is at the top and increases downwards [G].

**Pseudocode**
```python
def bezier_opacity_mapping(i, kriv, edt_left, edt_top, edt_sir, edt_vys):
    """
    Calculate opacity for input value i using Bézier curve mapping.
    
    Args:
        i (int): Input scalar value (0-4095).
        kriv (dict): Curve structure with 'pocet' (int) and 'suradnice' (list of dicts with 'x', 'y').
        edt_left (int): Editor left x-coordinate.
        edt_top (int): Editor top y-coordinate.
        edt_sir (int): Editor width.
        edt_vys (int): Editor height.
        
    Returns:
        float: Opacity alpha in [0.0, 1.0].
    """
    # Step 1: Validation
    if kriv['pocet'] < 2:
        return 0.0

    # Step 2: Normalize input
    norm_i = i / 4095.0

    # Step 3: Normalize curve endpoints
    x0 = kriv['suradnice'][0]['x']
    xn_1 = kriv['suradnice'][kriv['pocet'] - 1]['x']
    
    norm_oa = (x0 - edt_left) / edt_sir
    norm_ob = (xn_1 - edt_left) / edt_sir

    # Guard against division by zero if endpoints share the same x-coordinate [G]
    if norm_ob == norm_oa:
        return 0.0

    # Step 4: Calculate parameter t
    t = (norm_i - norm_oa) / (norm_ob - norm_oa)

    # Step 5: Boundary check
    if norm_i < norm_oa or norm_i > norm_ob:
        return 0.0

    # Step 6: Evaluate Bézier curve
    krivka = vrat_krivku(t, kriv)
    y_t = krivka['y']

    # Step 7: Normalize and invert
    alpha = 1.0 - (y_t - edt_top) / edt_vys
    
    return alpha

def vrat_krivku(t, kriv):
    """
    Evaluates the Bézier curve at parameter t using de Casteljau's algorithm [G].
    Returns a dict with 'y' coordinate.
    """
    points = kriv['suradnice']
    n = len(points)
    
    # Extract y-coordinates for evaluation [G]
    pts = [p['y'] for p in points]
    
    # De Casteljau evaluation [G]
    for r in range(1, n):
        for i in range(n - r):
            pts[i] = (1.0 - t) * pts[i] + t * pts[i + 1]
            
    return {'y': pts[0]}
```

**Parameters**
*   `i`: Input data value (UINT16, range 0-4095) [S1, unofficial].
*   `edt_sir`/`edt_vys`: Editor width and height in pixels [S1, unofficial].
*   `edt_left`/`edt_top`: Editor top-left coordinates in pixels [S1, unofficial].
*   `kriv.suradnice[]`: Array of control points with x, y coordinates [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Division by Zero:** If `norm_ob == norm_oa` (i.e., the first and last control points have the same x-coordinate), the denominator in the calculation of $t$ becomes zero [S1, unofficial]. The source implies distinct x-coordinates for at least 2 points, but explicit handling is not shown [S1, unofficial]. The pseudocode adds a guard returning 0.0 [G].
*   **Out-of-Bounds Input:** If the normalized input value falls outside the range $[\text{norm\_oa}, \text{norm\_ob}]$, the opacity is explicitly set to 0.0 [S1, unofficial].
*   **Coordinate System:** The inversion $1.0 - \dots$ assumes a specific y-axis direction (likely y=0 at top, increasing downwards, common in screen coordinates) [G].

## Subtopics

### [Range of Emphasis Opacity](13924-range-of-emphasis-opacity.md)
Range of Emphasis Opacity is a transfer function technique that emphasizes specific density ranges by scaling opacity differently inside and outside a user-defined interval $[\rho_{min}, \rho_{max}]$. It is distinct from its sibling [Bézier Curve Opacity Mapping](8485-b-zier-curve-opacity-mapping.md) in that it uses a piecewise linear function with explicit multipliers rather than a continuous Bézier curve, offering a simpler, more direct control over the visibility of target densities. A variant of this concept, used in encrypted volume rendering, encodes density values as vectors to compute similarity via dot products, avoiding the storage overhead of full oblivious lookup tables.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample, assuming the Bézier curve evaluation is a fixed-degree polynomial [G].
*   **Memory Complexity:** $O(1)$ auxiliary memory per sample, dependent on the number of control points stored in the curve structure [G].
*   **Strengths:** Provides smooth, non-linear control over opacity, allowing for fine-tuned emphasis of specific data ranges without the sharp transitions of linear interpolation [G].
*   **Limitations:** Requires user interaction to define control points [G]. Performance is negligible per sample, but the complexity of curve evaluation increases with the degree of the Bézier curve [G].
*   **When to Use:** When smooth transitions and precise control over opacity gradients are needed, especially for highlighting specific features in volumetric data [G].
*   **When Not to Use:** When simple, fast, and predictable opacity mapping is sufficient, or when the data range is uniform and does not require non-linear emphasis [G].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
