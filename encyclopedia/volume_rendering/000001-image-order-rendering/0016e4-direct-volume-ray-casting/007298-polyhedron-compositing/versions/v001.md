# Polyhedron Compositing

Also called: Cell Compositing, Tetrahedral subdivision compositing, Tetrahedron Compositing, Volume cell compositing

## Overview
Polyhedron Compositing is a direct volume ray casting method that combines contour surface rendering with ray integration by subdividing volume cells at contour surfaces into polyhedral pieces (typically tetrahedra), which are then composited in back-to-front order [S2, unofficial]. Unlike standard ray casting that samples a continuous scalar field, this method allows color and opacity to change discontinuously across surfaces and correctly sorts multiple transparent surfaces [S2, unofficial]. It sets itself apart from its siblings by replacing per-pixel ray marching with closed-form analytic integration over geometric primitives, leveraging graphics hardware scan conversion [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume defined on a grid of cells. Each cell vertex has associated quantities: emission coefficient $c$ (RGB vector) and absorption fraction per unit density-length $\alpha$ (scalar). A transfer function maps these to physical properties, or they are provided directly. The viewer position and projection matrix (orthographic or perspective) are required.
*   **Output:** The final frame buffer color $F_{out}$ and accumulated opacity.

**Data Structures:**
1.  **Subdivided Cells:** The volume is decomposed into convex polyhedra (tetrahedra). If a contour surface crosses a cell, the cell is split. If a tetrahedron is crossed by a discontinuity surface, it is sliced into two parts [S2, unofficial].
2.  **Face Graph:** A directed graph where edges correspond to cell faces. Edges are directed from the cell on the viewpoint side to the cell on the side facing away [S1, unofficial].
3.  **Temporary Buffers:**
    *   *Face Sorting Variant:* Two sets of temporary arrays sized for the whole image: one for front-facing polygons, one for back-facing. Stores interpolated values for $z$, $C$, and $a$ [S2, unofficial].
    *   *Cell Sorting Variant:* Buffers sized for one scan line (using incremental methods) [S2, unofficial].

**Numbered Steps:**

1.  **Subdivision:** Divide any volume cell crossed by a contour surface into tetrahedra. Slice each tetrahedron crossed by a contour surface into two parts to handle discontinuous color/opacity [S2, unofficial].
2.  **Sorting:**
    *   *Global Cell Sort:* Perform a topological sort of the directed face graph to determine a back-to-front order of cells. This is possible if the data volume is convex with no holes or concavities [S1, unofficial].
    *   *Face Sort:* Sort the resulting polyhedral pieces and surface polygons in back-to-front order relative to the viewer. If a face has a discontinuity, create two copies (one marked front, one unmarked) with distinct $C$ and $a$ values [S2, unofficial].
3.  **Scan Conversion (Projection):** Divide the screen projection of a cell into polygons bounded by projected cell edges. Each polygon represents a prismatic region bounded by a single front-facing and a single back-facing cell face [S1, unofficial].
4.  **Interpolation:** For each polygon, interpolate quantities linearly across the screen space.
    *   For orthographic projection, interpolate depth $z$ directly.
    *   For perspective projection, interpolate $1/z$ and derive $z$ [S2, unofficial].
    *   Interpolate $C$ (emission/color) and $a$ (absorption density product) at polygon vertices [S2, unofficial].
5.  **Compositing:** Calculate the contribution of each polygon to the frame buffer using the closed-form integral.

**Formulas:**

The basic compositing equation for a segment with transparency $T$ and added colored intensity $I$ is [S2, unofficial]:
$$
F_{new} = T \cdot F_{old} + I
$$

For a volume cell segment of length $L$, with average absorption density product $a$ and average emission color $C$ (where $C = c/\alpha$):
$$
T = \exp(-L \cdot a)
$$
$$
I = C \cdot (1 - T)
$$

The accumulated values for a pixel $(i, j)$ within a cell's projection are computed as the average of the front and back face values [S2, unofficial]:
$$
L = z_{back}(i, j) - z_{front}(i, j)
$$
$$
a = \frac{a_{back}(i, j) + a_{front}(i, j)}{2}
$$
$$
C = \frac{C_{back}(i, j) + C_{front}(i, j)}{2}
$$

**Perspective Projection Adjustment:**
For perspective projection, the length $L$ and interpolation must account for depth. The quantity to interpolate is $1/z$. The effective length $L$ is calculated as [S2, unofficial]:
$$
L = \left( \frac{1}{z_{front}(i, j)} - \frac{1}{z_{back}(i, j)} \right) \cdot \sqrt{1 + x^2 + y^2}
$$
where $x$ and $y$ are the coordinates where the ray from the eye through pixel $(i, j)$ intersects the plane $z=1$.

**Pseudocode (Face Sorting Variant):**

```python
# Initialize temporary buffers for the whole image
# ztemp, Ctemp, atemp store the last processed front-facing values
# Initialize ztemp to infinity, Ctemp to 0, atemp to 0

# Sort all polygons (from subdivided cells and surfaces) back-to-front
sorted_polygons = sort_back_to_front(polygons)

for polygon in sorted_polygons:
    # Determine if this polygon is a front-facing surface of a volume cell
    is_front = polygon.is_front_face
    
    # Scan convert the polygon to screen pixels
    for each pixel (i, j) inside polygon:
        # Interpolate values at (i, j)
        z_new = interpolate(polygon, i, j, field='z')
        C_new = interpolate(polygon, i, j, field='C')
        a_new = interpolate(polygon, i, j, field='a')
        
        if is_front:
            # Calculate segment length and average properties
            # L is depth difference (orthographic) or derived from 1/z (perspective)
            L = ztemp[i, j] - z_new
            
            # Average absorption and color between previous front face and current
            a_avg = (atemp[i, j] + a_new) / 2.0
            C_avg = (Ctemp[i, j] + C_new) / 2.0
            
            # Compute transparency and intensity
            T = exp(-L * a_avg)
            I = C_avg * (1.0 - T)
            
            # Composite into frame buffer
            F[i, j] = T * F[i, j] + I
            
            # Update temporary buffers for next front face
            ztemp[i, j] = z_new
            Ctemp[i, j] = C_new
            atemp[i, j] = a_new
```

**Edge Cases and Pitfalls:**
*   **Convexity:** The method requires each ray to intersect the volume cell in a single segment (single front and back entry). This is guaranteed if the cell is convex [S2, unofficial].
*   **Sorting Validity:** The face sorting variant requires a valid sort order for polygons, which is not always possible for arbitrary non-convex geometries [S2, unofficial].
*   **Discontinuities:** If a face has a discontinuity in opacity or color, it must be split into two copies (one marked front, one unmarked) with their own $C$ and $a$ values [S2, unofficial].
*   **Perspective Distortion:** Using linear interpolation of $z$ in perspective projection leads to errors. One must interpolate $1/z$ and compute $L$ using the derived formula [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The method eliminates the need for per-pixel sampling along the ray by using closed-form analytic integration. It relies on scan conversion and sorting. Sorting is $O(N \log N)$ where $N$ is the number of polygons. Scan conversion is linear in the number of pixels covered by the polygons [S2, unofficial].
*   **Memory Complexity:** The face sorting variant requires temporary buffers sized for the whole image ($O(W \times H)$) for $z$, $C$, and $a$ [S2, unofficial]. The cell sorting variant can use incremental methods requiring only $O(W)$ memory per scan line [S2, unofficial].
*   **Strengths:** Correctly handles discontinuous opacity and color changes across contour surfaces. Allows multiple transparent surfaces to be composited in the correct order. Leverages hardware scan conversion and texture mapping for efficiency [S1, unofficial][S2, unofficial].
*   **Limitations:** Requires subdivision of cells, which can increase the number of primitives. Sorting can be complex or impossible for non-convex shapes. The assumption of linear variation of density/color within cells may introduce approximation errors [S1, unofficial][S2, unofficial].
*   **When to use:** When accurate rendering of discontinuous features (e.g., isosurfaces) within a volume is required, and the volume can be decomposed into convex polyhedra.
*   **When not to use:** For highly non-convex volumes where sorting is intractable, or when continuous smooth shading is preferred over discrete cell-based compositing.

## Background
Polyhedron Compositing was introduced by Max, Hanrahan, and Crawfis as a technique to combine contour surface rendering with ray integration [S2, unofficial]. It builds on the idea of compositing polyhedra joining data points, where the integral is integrated separately along viewing ray segments within each polyhedron [S1, unofficial]. The method utilizes topological information for cell sorting (Garrity [11]) and directed graphs for back-to-front sorting (Edelsbrunner [14]) [S1, unofficial]. It is particularly relevant in flow visualization and scientific visualization where discontinuous data boundaries are common [S1, unofficial].
