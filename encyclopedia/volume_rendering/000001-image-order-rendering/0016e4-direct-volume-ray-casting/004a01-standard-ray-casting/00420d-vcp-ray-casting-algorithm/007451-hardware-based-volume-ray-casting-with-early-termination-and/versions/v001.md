# Hardware-Based Volume Ray Casting with Early Termination and Z-Updates

Also called: Cell-Projection based Ray Casting, Hardware-Based Ray Casting

## Overview
This method is a hardware-accelerated technique for volume rendering that exploits programmable graphics features, specifically early z-tests and occlusion queries, to manage ray traversal and termination efficiently [S1, unofficial]. It differs from software ray casting by leveraging rasterization hardware to reduce fragment operations, though it introduces more complex rasterization logic [S1, unofficial]. It builds on the [VCP Ray-Casting Algorithm](10664-vcp-ray-casting-algorithm.md) by adding specific mechanisms for handling ray termination and depth buffer synchronization within the GPU pipeline.

## How it works
The method uses a loop of traversal and z-update passes to advance rays through the volume data. It relies on a specific cell index value to manage state and termination.

**Inputs and Outputs:**
*   **Input:** Volume data, ray traversal parameters, current depth buffer state.
*   **Output:** Final rendered image stored in texture set 0.

**Data Structures:**
*   **Current Cell Index:** An integer value associated with each ray/fragment. A value of `-1` indicates an "imaginary cell," used to signal reentries or termination conditions [S1, unofficial].
*   **Depth Buffer:** Stores depth values to facilitate early z-testing.
*   **Color Buffer:** Stores the accumulated color for each ray.

**Parameters:**
*   **Current Cell Index:** `-1` is the sentinel value for imaginary cells [S1, unofficial].
*   **Comparison Function:** `GL_LESS` (or equivalent) for early z-tests [S1, unofficial].

**Algorithm Steps:**
1.  **Initialize:** Set up the first traversal pass. Ensure the final result will be stored in texture set 0 [S1, unofficial].
2.  **Traversal Pass:**
    *   For each fragment (ray), determine the current cell index.
    *   **Early Termination/Occlusion:** Use an early z-test (e.g., `GL_LESS`) to stop fragment processing for rays that have already been terminated or occluded [S1, unofficial].
    *   **Reentry/Imaginary Cell Handling:** If the current cell index equals `-1`:
        *   Write `z_near` to the depth buffer [S1, unofficial].
        *   Copy the current accumulated color into the result buffer [S1, unofficial].
    *   **Advancement:** Update the ray position and cell index based on neighbor cell data (e.g., `at,i`) [S1, unofficial].
3.  **Z-Update Pass:**
    *   Perform a z-update pass to update the depth buffer.
    *   **Synchronization:** Only perform z-update passes after **even** traversal passes (i.e., after 2, 4, 6... traversal passes) to ensure correct state synchronization [S1, unofficial].
4.  **Termination Check:**
    *   Use DirectX 9 occlusion queries (or equivalent) to determine if rendering is complete [S1, unofficial].
    *   Check if any pixels are still set (active).
    *   **Non-blocking:** Do not wait for the asynchronous delivery of occlusion query results to avoid pipeline stalls [S1, unofficial].
    *   Proceed with the assumption that rendering is complete when no pixels are set [S1, unofficial].
5.  **Repeat:** Continue the loop of traversal and z-update passes until the termination condition is met.

**Pseudocode:**
```python
# Initialize state
texture_set_0 = allocate_texture()
depth_buffer = allocate_depth_buffer()
current_cell_index = initialize_cell_indices() # Not -1 for active rays
is_rendering_complete = False

while not is_rendering_complete:
    # Traversal Pass 1
    execute_traversal_pass(
        depth_buffer=depth_buffer,
        current_cell_index=current_cell_index,
        texture_set=texture_set_0
    )
    
    # Traversal Pass 2
    execute_traversal_pass(
        depth_buffer=depth_buffer,
        current_cell_index=current_cell_index,
        texture_set=texture_set_0
    )
    
    # Z-Update Pass (only after even traversal passes)
    execute_z_update_pass(depth_buffer=depth_buffer)
    
    # Check for completion using occlusion query
    # Do not wait for async result; assume complete if no pixels set
    if not any_pixels_set():
        is_rendering_complete = True

# Final result is in texture_set_0
return texture_set_0

def execute_traversal_pass(depth_buffer, current_cell_index, texture_set):
    for each fragment (ray):
        # Early z-test to stop processing if occluded/terminated
        if not early_z_test(depth_buffer):
            continue
            
        if current_cell_index == -1:
            # Imaginary cell handling
            write_z_near_to_depth_buffer(depth_buffer)
            copy_color_to_result_buffer(texture_set)
        else:
            # Normal traversal
            update_ray_position(current_cell_index)
            update_current_cell_index(current_cell_index)

def execute_z_update_pass(depth_buffer):
    # Update depth buffer state for next passes
    synchronize_depth_buffer(depth_buffer)

def any_pixels_set():
    # Use occlusion query to check if any pixels are active
    return query_occlusion_status()
```

**Edge Cases and Pitfalls:**
*   **Asynchronous Stalls:** Waiting for occlusion query results can cause pipeline stalls. The method avoids this by assuming completion when no pixels are set [S1, unofficial].
*   **Synchronization:** Z-updates must only occur after even traversal passes to maintain correct state. Incorrect timing leads to wrong results [S1, unofficial].
*   **Imaginary Cells:** The use of `-1` for cell index requires careful handling to distinguish between reentry and termination [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Benefits from a reduced number of fragment operations due to early ray termination, space leaping, and adaptive sampling [S1, unofficial].
*   **Strengths:** Leverages hardware features for efficiency; reduces fragment processing overhead [S1, unofficial].
*   **Limitations:** Rasterization logic is more complex than software ray casting [S1, unofficial]. The overhead of additional rendering passes is considered negligible [S1, unofficial].
*   **When to use:** When hardware-accelerated volume rendering is required and the target GPU supports early z-tests and occlusion queries (e.g., DirectX 9 era hardware) [S1, unofficial].
*   **When not to use:** When simpler software ray casting is sufficient or when hardware features are not available [S1, unofficial].

## Background
This method was introduced by Manfred Weiler, M. Kraus, M. Merz, and T. Ertl in the paper "Hardware-Based Ray Casting for Tetrahedral Meshes" presented at IEEE Visualization 2003 [S1, unofficial]. It is part of the broader effort to accelerate volume rendering using programmable graphics hardware, building upon earlier work such as "Hardware-Accelerated Volume and Isosurface Rendering Based On Cell-Projection" by Röttger et al. (2000) [S1, unofficial].
