# Front-to-Back Ray Casting with Iso-value Thresholding

Also called: RayCastSimplePS, Simple Volume Ray Casting, Standard Ray Casting with Iso-value Thresholding

## Overview
Front-to-Back Ray Casting with Iso-value Thresholding is a direct volume rendering technique that accumulates color and opacity along a ray, but restricts contribution to samples where the scalar density exceeds a specific iso-value threshold [S1, S3, unofficial]. Unlike standard ray casting which blends all samples, this method acts as a hard or soft filter, rendering only structures above the threshold [S3, unofficial]. It differs from [Volume Ray Casting](2350-volume-ray-casting.md) by explicitly enforcing a density cutoff before compositing, and from [VCP Ray-Casting Algorithm](10664-vcp-ray-casting-algorithm.md) by using a simpler, fixed-step sampling loop rather than variable-step traversal [S1, S3, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: A 3D scalar volume texture $V$, a 1D transfer function texture $T$, 2D precomputed front/back intersection textures $F$ and $B$, camera parameters (pixel position, ray direction), and rendering parameters: IsoValue, SampleDist, Iterations.
*   **Output**: Final pixel color $\mathbf{C}_{out}$ and accumulated opacity $\alpha_{out}$.

**Data Structures**
1.  **Volume Texture ($V$)**: 3D texture. Linear filtering. Border address mode with border color $(1, 0, 0, 1)$ [S3, unofficial].
2.  **Transfer Function Texture ($T$)**: 1D texture. Linear filtering. Clamp address mode [S3, unofficial]. Maps scalar density to $(\mathbf{c}, \alpha)$ [S3, unofficial].
3.  **Front/Back Textures ($F, B$)**: 2D textures. Linear filtering. Border address mode with border color $(0, 0, 0, 0)$ [S3, unofficial]. Store the entry and exit points of the ray through the volume bounding box for each pixel [S3, unofficial].
4.  **Accumulators**: $\mathbf{C}_{acc}$ (RGB) and $\alpha_{acc}$ (A), initialized to $(0, 0)$ [S3, unofficial].

**Parameters**
*   **IsoValue**: The threshold density value. Typical value: $0.0$ (compared against `value.a * 255.0`) [S3, unofficial].
*   **SampleDist**: Distance between samples along the ray. Typical value: $0.5$ [S3, unofficial].
*   **Iterations**: Maximum number of samples per ray [S3, unofficial].
*   **BaseSampleDist**: Reference sample distance used for opacity correction. Not given in the sources.
*   **ActualSampleDist**: The actual physical distance between samples, derived from `SampleDist` and view geometry. Not given in the sources.

**Steps**
1.  **Ray Setup**: For each pixel, retrieve the front intersection point $\mathbf{p}_{front}$ from $F$ and the back intersection point $\mathbf{p}_{back}$ from $B$ using projective texture coordinates [S3, unofficial].
2.  **Direction Calculation**: Compute the normalized ray direction $\mathbf{d} = \text{normalize}(\mathbf{p}_{back} - \mathbf{p}_{front})$ [S3, unofficial].
3.  **Initialization**: Set current position $\mathbf{p} = \mathbf{p}_{front}$, accumulated color $\mathbf{C}_{acc} = (0, 0, 0)$, and accumulated opacity $\alpha_{acc} = 0$ [S3, unofficial]. Compute step vector $\mathbf{s} = \mathbf{d} \cdot \text{SampleDist}$ [S3, unofficial].
4.  **Sampling Loop**: For $i = 0$ to $\text{Iterations} - 1$:
    a.  **Sample Volume**: Retrieve the scalar value $v$ from the volume texture at position $\mathbf{p}$: $v = \text{tex3Dlod}(V, \mathbf{p})$ [S3, unofficial].
    b.  **Threshold Check**: If $v.a \cdot 255.0 < \text{IsoValue}$, skip blending for this step and proceed to step 4d [S3, unofficial].
    c.  **Transfer Function**: Sample the transfer function using the density value: $\mathbf{src} = \text{tex1Dlod}(T, v.a)$ [S3, unofficial].
    d.  **Opacity Correction**: Adjust the sampled opacity $\mathbf{src}.a$ to account for the sampling distance:
        $$ \mathbf{src}.a = 1 - |1 - \mathbf{src}.a|^{\frac{\text{ActualSampleDist}}{\text{BaseSampleDist}}} $$
        [S3, unofficial].
    e.  **Front-to-Back Blending**: Update accumulators:
        $$ \mathbf{C}_{acc} \leftarrow (1 - \alpha_{acc}) \cdot \mathbf{src}.rgb \cdot \mathbf{src}.a + \mathbf{C}_{acc} $$
        $$ \alpha_{acc} \leftarrow \alpha_{acc} + (1 - \alpha_{acc}) \cdot \mathbf{src}.a $$
        [S3, unofficial].
    f.  **Advance Position**: $\mathbf{p} \leftarrow \mathbf{p} + \mathbf{s}$ [S3, unofficial].
    g.  **Termination**: If $\alpha_{acc} \ge 0.95$ or $\mathbf{p}$ exceeds the unit cube bounds ($\mathbf{p}.x > 1.0, \mathbf{p}.y > 1.0, \mathbf{p}.z > 1.0$), break the loop [S3, unofficial].
5.  **Output**: Return $\mathbf{C}_{acc}$ and $\alpha_{acc}$ as the final pixel color and opacity [S3, unofficial].

**Pseudocode**
```python
def render_pixel_front_to_back_iso_threshold(pixel_pos, volume_tex, transfer_tex, front_tex, back_tex, iso_value, sample_dist, iterations, base_sample_dist):
    # 1. Ray Setup
    # Calculate projective texture coordinates
    tex_c = pixel_pos.xy / pixel_pos.w
    tex_c.x = 0.5 * tex_c.x + 0.5
    tex_c.y = -0.5 * tex_c.y + 0.5
    
    # Retrieve front and back intersection points
    front_point = front_tex.sample_linear(tex_c).xyz
    back_point = back_tex.sample_linear(tex_c).xyz
    
    # 2. Direction Calculation
    ray_dir = normalize(back_point - front_point)
    
    # 3. Initialization
    current_pos = front_point
    acc_color = (0.0, 0.0, 0.0)
    acc_alpha = 0.0
    step_vec = ray_dir * sample_dist
    
    # 4. Sampling Loop
    for i in range(iterations):
        # a. Sample Volume
        # Note: tex3Dlod expects normalized coordinates or specific format depending on implementation.
        # Assuming current_pos is already in the correct coordinate space for the texture.
        sample_val = volume_tex.sample_level_linear(current_pos, 0)
        density = sample_val.a
        
        # b. Threshold Check
        if density * 255.0 < iso_value:
            # Skip blending
            current_pos += step_vec
            continue
            
        # c. Transfer Function
        src_rgba = transfer_tex.sample_level_linear(density, 0)
        src_color = src_rgba.rgb
        src_alpha = src_rgba.a
        
        # d. Opacity Correction
        # ActualSampleDist and BaseSampleDist are assumed to be available or derived
        # For simplicity, assuming ActualSampleDist == sample_dist if not provided
        actual_sample_dist = sample_dist 
        correction_factor = actual_sample_dist / base_sample_dist
        src_alpha = 1.0 - abs(1.0 - src_alpha) ** correction_factor
        
        # e. Front-to-Back Blending
        # dst = (1.0 - dst.a) * src + dst
        acc_color = (1.0 - acc_alpha) * src_color * src_alpha + acc_color
        acc_alpha = acc_alpha + (1.0 - acc_alpha) * src_alpha
        
        # f. Advance Position
        current_pos += step_vec
        
        # g. Termination
        if acc_alpha >= 0.95:
            break
        if current_pos.x > 1.0 or current_pos.y > 1.0 or current_pos.z > 1.0:
            break
            
    return acc_color, acc_alpha
```

**Edge Cases and Pitfalls**
*   **Precision**: The opacity correction formula uses absolute values and powers, which can introduce numerical instability if $\mathbf{src}.a$ is very close to 1 or 0 [S3, unofficial].
*   **Boundaries**: The termination condition checks against the unit cube bounds ($1.0$). If the volume bounding box is not normalized to $[0,1]^3$, this check will fail to terminate rays correctly [S3, unofficial].
*   **Thresholding**: If the IsoValue is set too high, no samples may contribute, resulting in a black image. If set too low, the method degrades to standard ray casting [S1, S3, unofficial].
*   **Sampling Distance**: The opacity correction requires `BaseSampleDist`. If this parameter is not provided or mismatched with `SampleDist`, the resulting opacity will be incorrect, leading to over- or under-saturation [S3, unofficial].

## Subtopics

### Simple Volume Ray Casting
The general category of casting rays and accumulating color. This method is a specific implementation using iso-thresholding. [Simple Volume Ray Casting](2350-volume-ray-casting.md)

### VCP Ray-Casting Algorithm
Uses variable step sizes and more complex traversal. Choose this for higher performance on sparse volumes. [VCP Ray-Casting Algorithm](10664-vcp-ray-casting-algorithm.md)

### Volume Raycasting (Ray Driven)
A broader term for ray-driven rendering. This method is a specific ray-driven approach with fixed steps. [Volume Raycasting (Ray Driven)](17478-volume-raycasting-ray-driven.md)

## Operating characteristics
*   **Time Complexity**: $O(N)$ per pixel, where $N$ is the number of iterations (samples) per ray [S3, unofficial].
*   **Memory Complexity**: $O(1)$ per pixel for accumulators, plus storage for textures [S3, unofficial].
*   **Performance**: The method is computationally intensive due to the fixed number of iterations and texture lookups per sample [S3, unofficial]. The threshold check can skip blending, but sampling and transfer function lookup still occur [S3, unofficial].
*   **Strengths**: Simple to implement; effective for isolating specific structures within a volume [S1, S3, unofficial].
*   **Limitations**: Fixed step size may lead to aliasing or missed features if not tuned; opacity correction requires careful parameter tuning [S3, unofficial].
*   **When to Use**: When the goal is to visualize only high-density structures (e.g., bones in CT scans) and performance is not the primary constraint [S1, S3, unofficial].
*   **When Not to Use**: When the volume has low contrast or when smooth, semi-transparent visualization of all structures is required [S1, unofficial].

## Background
The technique is described in early online resources as a "reasonable introduction to simple raycasting" [S1, unofficial]. It is implemented in the Digital Volume Library (DVL) by Mihai Popescu, which uses cubic splines for transfer functions and a fixed-step ray casting loop with iso-value thresholding [S3, unofficial]. The method is often cited in the context of simple volume rendering tutorials [S1, S2, unofficial].
