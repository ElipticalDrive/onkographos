# Partial Ray Caching (Volumetric Lumigraph)

Also called: Intermediate Image Ray Casting, Lightfield Extension, Volumetric Lumigraph, Warping Ray Casting

## Overview
Partial Ray Caching accelerates volume rendering by decomposing the volume integral into segments, storing composited color and opacity for partial rays, and re-combining them for novel viewpoints near the original one to save integration cost [S1, unofficial][S2, book]. Unlike static lumigraph or lightfield methods, this approach is dynamically computed, though it can also be used statically for volumetric-style lumigraph rendering [S2, book]. It serves as a volumetric extension of the lumigraph [S1, unofficial][S2, book].

## How it works
**Inputs:** Volumetric dataset, initial view direction $V_a$, target novel view direction $V_b$ [G].  
**Outputs:** Rendered image for view $V_b$ [G].

**Data Structures:**
1. **Slab Images:** A stack of depth-layered images [S1, unofficial][S2, book]. Each image corresponds to a slab of the volume [S2, book].
2. **Partial Ray Data:** Stored within the slab images, containing composited color ($C$) and opacity ($\alpha$) for each ray segment [S1, unofficial][S2, book].
3. **Coarse Polygonal Mesh:** Computed on the fly for each layer to approximate the underlying object geometry [S1, unofficial][S2, book].

**Steps:**
1. **Decomposition:** Decompose the volume into slabs along $V_a$ [S2, book].
2. **Initial Rendering:** Render each slab into an image from $V_a$, storing the partial ray integrals (composited color and opacity) [S1, unofficial][S2, book].
3. **Mesh Generation:** Compute a coarse polygonal mesh on the fly for each layer to approximate the underlying object [S1, unofficial][S2, book].
4. **Warping and Composition:** For a novel viewpoint $V_b$:
    * Map the stored slab images onto the coarse polygonal meshes [S1, unofficial][S2, book].
    * Use interpolation to obtain partial integrals at non-grid positions when combining partial rays for $V_b$ [S2, book].
    * Composite the billboard images (slab images) for the desired view $V_b$ [S2, book].
    * Re-combine partial rays into complete rays for the new image [S1, unofficial].

**Parameters:**
* **View Cone:** The method is effective for viewpoints within a specific view cone. Mueller et al. rendered warped and composited images from novel viewpoints within a 30° view cone [S2, book].

**Edge Cases and Pitfalls:**
* **Gaps:** Gaps may quickly emerge when the layers are kept planar when rendering from novel viewpoints [S2, book]. This is mitigated by computing a coarse polygonal mesh for each layer [S1, unofficial][S2, book].

**Pseudocode:**
```python
def render_partial_ray_cache(volume, Va, Vb, view_cone_angle=30.0):
    # Va, Vb: view directions (unit vectors)
    # Check view cone constraint
    if dot(Va, Vb) < cos(radians(view_cone_angle)):
        raise ValueError("Target view outside valid cone.")

    # 1. Decompose volume into slabs along Va
    slabs = decompose_into_slabs(volume, Va)

    # 2. Cache partial ray integrals from Va
    slab_images = []
    for slab in slabs:
        img = render_slab_forward(volume, slab, Va)
        slab_images.append(img)

    # 3. Compute coarse polygonal meshes for each slab to prevent gaps
    meshes = []
    for slab in slabs:
        mesh = compute_coarse_mesh(slab, volume)
        meshes.append(mesh)

    # 4. Render for Vb by warping cached slabs
    width, height = volume.resolution
    output = zeros((height, width, 4))
    for y in range(height):
        for x in range(width):
            ray_o, ray_d = screen_to_ray(x, y, Vb, volume.camera_params)
            color, alpha = 0.0, 0.0
            # Composite slabs back-to-front relative to Vb
            for i in range(len(slabs) - 1, -1, -1):
                t = intersect_ray_plane(ray_o, ray_d, meshes[i])
                if t > 0:
                    C_s, A_s = interpolate_cached_partial(slab_images[i], t)
                    color = color + C_s * A_s * (1.0 - alpha)
                    alpha = alpha + A_s * (1.0 - alpha)
                    if alpha >= 1.0:
                        break
            output[y, x] = (color, alpha, 0.0, 1.0)
    return output

def decompose_into_slabs(volume, Va):
    # Split volume depth into N equal intervals along Va
    return [volume.depth_range[i:i+1] for i in range(N)]

def render_slab_forward(volume, slab, Va):
    # March rays from Va through slab, accumulate color/opacity
    img = zeros((height, width, 4))
    for y, x in pixels:
        ray_o, ray_d = screen_to_ray(x, y, Va, volume.camera_params)
        t_min, t_max = slab_bounds(ray_o, ray_d, slab)
        C, A = 0.0, 0.0
        for t in arange(t_min, t_max, step):
            density = sample_volume(volume, ray_o + t * ray_d)
            alpha_seg = 1.0 - exp(-density * step)
            C = C + sample_color(volume, ray_o + t * ray_d) * alpha_seg * (1.0 - A)
            A = A + alpha_seg * (1.0 - A)
        img[y, x] = (C, A, 0.0, 1.0)
    return img

def compute_coarse_mesh(slab, volume):
    # Approximate geometry of slab using marching cubes or similar
    return generate_mesh(volume, slab.bounds)

def screen_to_ray(x, y, V, params):
    # Standard pinhole camera ray generation
    return origin + x * dx + y * dy, normalize(V)

def intersect_ray_plane(ray_o, ray_d, mesh):
    # Return intersection distance t for ray and mesh plane
    return dot(mesh.normal, mesh.point - ray_o) / dot(mesh.normal, ray_d)

def interpolate_cached_partial(img, t):
    # Bilinear interpolation of cached color/opacity at position t
    return img[t.x, t.y], img[t.x, t.y+1] # Simplified
```

## Operating characteristics
* **Performance:** Saves the cost for fully integrating all rays for each new viewpoint, reducing it to the expense of compositing a few partial segments per ray, which is much lower [S1, unofficial][S2, book].
* **Hardware:** Can be rendered using standard graphics hardware [S1, unofficial][S2, book].
* **Limitations:** Limited to viewpoints near the original one (e.g., within a 30° view cone) [S2, book]. Gaps may emerge if layers are kept planar [S2, book].
* **Usage:** Suitable for volume rendering at great perspective distortions, such as in virtual endoscopy applications [S2, book].

## Background
* **Origin:** The method falls into the domain of image-based rendering (IBR) [S1, unofficial][S2, book]. It is a volumetric extension of the lumigraph [S1, unofficial][S2, book] or lightfield [S1, unofficial][S2, book], albeit dynamically computed.
* **Development:** Brady et al. exploited this idea for volume rendering at great perspective distortions, such as in virtual endoscopy applications [S1, unofficial][S2, book]. Mueller et al. stored the rays in the form of a stack of depth-layered images and rendered these images warped and composited from novel viewpoints within a 30° view cone, using standard graphics hardware [S1, unofficial][S2, book].
* **Alternatives:** An alternative method that uses a precomputed triangle mesh to achieve similar goals for iso-surface volume rendering was proposed by Chen et al. [S1, unofficial][S2, book]. Yagel and Shi warped complete images to nearby viewpoints, aided by a depth buffer [S1, unofficial][S2, book].
