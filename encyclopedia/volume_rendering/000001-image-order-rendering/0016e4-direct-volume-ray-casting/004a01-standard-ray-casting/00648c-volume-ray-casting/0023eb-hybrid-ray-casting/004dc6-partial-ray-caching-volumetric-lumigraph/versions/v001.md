# Partial Ray Caching (Volumetric Lumigraph)

Also called: Intermediate Image Ray Casting, Lightfield Extension, Volumetric Lumigraph, Warping Ray Casting

## Overview
Partial Ray Caching accelerates volume rendering by decomposing the volume integral into segments, storing composited color and opacity for partial rays, and re-combining them for novel viewpoints to save integration cost [S1, unofficial]. It is an image-based rendering (IBR) method that serves as a volumetric extension of the lumigraph or lightfield, albeit dynamically computed [S2, book]. Unlike static lumigraph methods, this approach computes the intermediate representation on the fly, though it can also be stored statically for volumetric-style lumigraph rendering [S1, unofficial][S2, book]. It sets itself apart from standard ray casting by trading full per-ray integration for the compositing of pre-cached partial segments, significantly reducing cost for viewpoints near the original capture direction [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volumetric dataset, an initial view direction ($V_a$), and a set of novel view directions ($V_b$) within a limited view cone.
*   **Output:** Rendered images for the novel viewpoints.

**Data Structures:**
The method stores partial ray integrals in a data structure. A common implementation uses a stack of depth-layered images (billboards) [S1, unofficial][S2, book].
*   **Slab Images:** The volume is decomposed into slabs. Each slab is rendered from view direction $V_a$ into a 2D image.
*   **Stored Data:** Each pixel in a slab image stores the composited color ($C$) and opacity ($\alpha$) accumulated along the ray segment passing through that specific slab.
*   **Mesh Data:** To prevent gaps, a coarse polygonal mesh approximating the underlying object is computed on the fly for each layer [S1, unofficial][S2, book].

**Steps:**
1.  **Decomposition:** Decompose the volume into a series of slabs along the view direction $V_a$ [S2, book].
2.  **Partial Rendering:** Render each slab into an image from view direction $V_a$. For each ray passing through a slab, compute the partial volume integral (composited color and opacity) for that segment [S1, unofficial][S2, book].
3.  **Storage:** Store these partial ray integrals in the stack of depth-layered images (slab images) [S1, unofficial][S2, book].
4.  **Mesh Generation (Optional but recommended):** Compute a coarse polygonal mesh for each layer that approximates the underlying object geometry [S1, unofficial][S2, book].
5.  **Warping and Compositing for Novel View:**
    *   For a new viewpoint with direction $V_b$, the partial ray integrals from the stored slab images are warped to the new perspective [S2, book].
    *   Interpolation is used to obtain partial integrals at non-grid positions during the warping process [S2, book].
    *   The warped slab images are composited together to form the final image for view $V_b$ [S2, book].
    *   If meshes are used, the images are mapped onto these meshes during rendering to ensure proper depth ordering and gap filling [S1, unofficial][S2, book].

**Formulas:**
The volume integral is broken into segments. Let $I$ be the total intensity, $\sigma_a$ be absorption coefficient, $\sigma_e$ be emission coefficient, and $T$ be transmittance. The partial integral for a segment $s$ is stored as $(C_s, \alpha_s)$.
The final color $C_{final}$ for a novel view is obtained by compositing these partial segments:
$$ C_{final} = \sum_{i} C_i \alpha_i \prod_{j < i} (1 - \alpha_j) $$
where $C_i$ and $\alpha_i$ are the warped and interpolated partial color and opacity from the $i$-th slab [S1, unofficial][S2, book].

**Parameters:**
*   **View Cone:** The method is effective for viewpoints within a specific view cone. Mueller et al. demonstrated rendering within a $30^\circ$ view cone [S1, unofficial][S2, book].
*   **Slab Count:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Gaps:** Gaps may quickly emerge between planar layers when rendering from novel viewpoints if the layers are kept strictly planar [S1, unofficial][S2, book]. This is mitigated by computing a coarse polygonal mesh for each layer [S1, unofficial][S2, book].
*   **View Angle Limit:** Performance and accuracy degrade outside the specified view cone (e.g., beyond $30^\circ$ in the cited implementation) [S1, unofficial][S2, book].
*   **Interpolation Artifacts:** Interpolation is required for non-grid positions, which may introduce artifacts if the view angle change is large or the slab resolution is low [S2, book].

    slabs = decompose_volume_into_slabs(volume_data)

    slab_images = []

    # Step 3: Compute coarse polygonal mesh for each layer (to prevent gaps)

    meshes = []
    for image in slab_images:
        mesh = compute_coarse_mesh_for_layer(image, volume_data)
        meshes.append(mesh)
        
    # Step 4: Warp and composite for novel viewpoint
    # Check if novel view is within view cone
    if angle_between(view_direction_va, novel_view_direction_vb) > view_cone_angle:
        raise ValueError("Novel view outside supported view cone")
        
    final_color = 0.0
    final_alpha = 0.0
    
    # Composite slabs in order (front to back relative to new view)
    # Not given in the sources: specific warping and compositing order.
    for i, (image, mesh) in enumerate(zip(slab_images, meshes)):
        # Warp image and mesh to novel_view_direction_vb
        # Use interpolation for non-grid positions
        warped_image = warp_image(image, view_direction_va, novel_view_direction_vb)
        warped_mesh = warp_mesh(mesh, view_direction_va, novel_view_direction_vb)
        
        # Composite warped slab
        # Not given in the sources: specific compositing function handling warped geometry.
        c_i, a_i = composite_warped_slab(warped_image, warped_mesh)
        
        # Standard front-to-back compositing
        final_color = final_color + c_i * (1 - final_alpha)
        final_alpha = final_alpha + a_i * (1 - final_alpha)
        
    return final_color

## Subtopics

### Static Volumetric Lumigraph
A variant where partial rays are precomputed and stored in a static data structure for later use, rather than being computed dynamically [S1, unofficial][S2, book].

### Iso-surface Warping
An alternative method using a precomputed triangle mesh to achieve similar goals for iso-surface volume rendering, proposed by Chen et al. [S1, unofficial][S2, book].

### Image Warping with Depth Buffer
A related technique by Yagel and Shi that warps complete images to nearby viewpoints, aided by a depth buffer, rather than caching partial ray integrals [S1, unofficial][S2, book].

## Operating characteristics
*   **Time Complexity:** Reduces rendering cost from full integration per ray to compositing a few partial segments per ray, which is much lower [S1, unofficial].
*   **Memory Complexity:** Requires storing a stack of depth-layered images (slab images) for the volume, plus optional mesh data [S1, unofficial][S2, book].
*   **Measured Performance:** Mueller et al. demonstrated rendering within a $30^\circ$ view cone using standard graphics hardware [S1, unofficial][S2, book].
*   **Strengths:** Significant speedup for viewpoints near the original view direction; leverages standard graphics hardware for warping and compositing [S1, unofficial][S2, book].
*   **Limitations:** Limited to a specific view cone (e.g., $30^\circ$); gaps can emerge between planar layers without mesh approximation; interpolation artifacts may occur [S1, unofficial][S2, book].
*   **When to Use:** Suitable for applications requiring rapid viewpoint changes within a limited cone, such as virtual endoscopy with great perspective distortions [S1, unofficial][S2, book].
*   **When Not to Use:** Unsuitable for large viewpoint changes outside the defined cone or when high accuracy across all angles is required without precomputation.

## Background
Partial Ray Caching was introduced as an acceleration technique in volume rendering, falling into the domain of image-based rendering (IBR) [S1, unofficial][S2, book]. It is conceptually a volumetric extension of the lumigraph [97] or lightfield [177] [S2, book]. Brady et al. exploited this idea for volume rendering at great perspective distortions, such as in virtual endoscopy applications [S1, unofficial][S2, book]. Mueller et al. implemented the method using a stack of depth-layered images rendered with standard graphics hardware, addressing the gap issue with on-the-fly mesh computation [S1, unofficial][S2, book].
