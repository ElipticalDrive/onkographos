# Hybrid Ray-Casting

Also called: Intermediate Image Ray Casting, Template-based Raycasting, Warping Ray Casting

## Overview
Hybrid Ray-Casting is a volume rendering technique that generates an intermediate image aligned with one of the volume's principal axes (faces) and then warps this image onto the final view plane [S1, S2]. It solves the problem of irregular memory access patterns inherent in standard image-order ray casting by ensuring that voxels are read in regular, object-order slices parallel to the base plane [S1, S2]. Unlike [Volume Ray Casting](3161-volume-ray-casting.md), which resamples the volume directly in view space, Hybrid Ray-Casting decouples the volume traversal from the final projection, enabling high-performance implementations on parallel architectures [S1, S2].

## How it works
**Inputs:** Volume dataset $V$ (typically a 3D grid of voxels), camera parameters (view direction, projection type), and base plane orientation [S1, S2].
**Outputs:** Final rendered image on the image plane [S1, S2].

**Data Structures:**
1. **Volume Data:** A 3D array of voxel values [G].
2. **Slice Access:** The algorithm assumes access to slices (2D planes) of this data [S1].
3. **Intermediate Image Buffer:** A 2D array storing the rendered pixels for the base plane [G].
4. **Warping Parameters:** Affine transformation matrices (shear, scale) derived from the camera view relative to the volume axes [S2].

**Steps:**
1. **Base Plane Selection:** Identify the volume face (slice direction) most parallel and nearest to the image plane [S1].
2. **Volume Transformation (Shear/Scale):** Transform the volume into an intermediate coordinate system such that the view direction aligns with one of the principal axes (typically the z-axis of the base plane) [S2]. This transformation typically involves a shear and, for perspective projections, a scale of the original slices [S2]. The transformation into an intermediate coordinate system achieves a one-to-one mapping of ray-samples onto the volume [S2].
3. **Ray Casting on Base Plane:** Send rays from each pixel on the base plane into the volume [S1]. Read and process voxels in planes (slices) parallel to the base plane [S1]. Within each slice, read voxels from memory a scanline at a time in top-to-bottom order [S1]. This provides regular, object-order data access [S1]. Accumulate color and opacity along the ray to produce the intermediate image [G].
4. **Warping:** Apply a 2D geometric transformation (warp) to the intermediate image to map it onto the final view plane [S1, S2]. This step corrects for the angle between the base plane and the image plane [S1].

**Pseudocode:**
```python
def hybrid_ray_casting(volume, volume_shape, camera):
    D, H, W = volume_shape
    base_res = camera.base_plane_res
    warp_matrix = camera.warp_matrix
    view_dir = camera.view_direction
    proj_type = camera.projection_type

    # 1. Select base plane axis (most parallel to view direction) [G]
    axis = 0 if abs(view_dir[0]) >= abs(view_dir[1]) and abs(view_dir[0]) >= abs(view_dir[2]) else \
           1 if abs(view_dir[1]) >= abs(view_dir[2]) else 2
    # Permute volume so base axis is Z
    vol = volume.transpose([2, 0, 1] if axis == 0 else ([0, 2, 1] if axis == 1 else [0, 1, 2]))
    D, H, W = vol.shape

    # 2. Compute shear and scale factors [S2]
    shear_x = -view_dir[0] / view_dir[2]
    shear_y = -view_dir[1] / view_dir[2]
    scale = 1.0
    if proj_type == 'perspective':
        scale = camera.focal_length / (camera.focal_length + view_dir[2])

    # 3. Generate intermediate image on base plane
    base_image = [[None] * W for _ in range(H)]
    for y in range(H):
        for x in range(W):
            color = [0.0, 0.0, 0.0]
            opacity = 0.0
            for z in range(D):
                # Sheared coordinates for current slice
                sx = (x + shear_x * z) * scale
                sy = (y + shear_y * z) * scale
                # Sample voxel (nearest neighbor) [G]
                vx, vy = int(sx) % W, int(sy) % H
                voxel = vol[z, vy, vx]
                # Front-to-back compositing [G]
                a = voxel[3]
                color = [c + v * a * (1.0 - opacity) for c, v in zip(color, voxel[:3])]
                opacity = opacity + a * (1.0 - opacity)
                if opacity >= 1.0:
                    break
            base_image[y][x] = (color, opacity)

    # 4. Warp intermediate image to final view plane
    final_res = camera.final_image_res
    final_image = [[None] * final_res[0] for _ in range(final_res[1])]
    inv_warp = invert_matrix(warp_matrix)
    for fy in range(final_res[1]):
        for fx in range(final_res[0]):
            bx, by = transform_point(inv_warp, fx, fy)
            if 0 <= by < H and 0 <= bx < W:
                final_image[fy][fx] = base_image[by][bx]
            else:
                final_image[fy][fx] = ([0.0, 0.0, 0.0], 0.0)
    return final_image

def invert_matrix(M):
    # Standard 2x2 or 3x3 matrix inversion [G]
    return [[M[0][0]*M[1][1]-M[0][1]*M[1][0], M[0][1]*M[1][0]-M[0][0]*M[1][1]], 
            [M[1][0]*M[0][1]-M[1][1]*M[0][0], M[1][1]*M[0][0]-M[1][0]*M[0][1]]]

def transform_point(M, x, y):
    # Standard affine point transformation [G]
    return M[0][0]*x + M[0][1]*y, M[1][0]*x + M[1][1]*y
```

**Parameters:**
* **Shear/Scale Factors:** Determined by the angle between the view direction and the volume axes [S2]. For perspective projections, scale factors are necessary to maintain correct depth relationships [S2].
* **Base Plane Resolution:** Matches the intermediate image resolution, which may differ from the final image resolution depending on the warping step [G].

**Edge Cases and Pitfalls:**
* **Perspective Distortion:** If perspective projection is used, the scale factor must be correctly applied to the slices to avoid geometric artifacts [S2].
* **Memory Access:** While object-order access is regular, the shear transformation may require careful handling of boundary conditions and non-integer coordinates if not implemented via pre-transformed data structures [S2].

## Subtopics

### Shear-Warp Transformation
A specific implementation of Hybrid Ray-Casting that decomposes the volume transformation into a sequence of shear and scale operations along orthogonal axes, optimizing for cache locality and parallel processing [S2].

### Template-Based Raycasting
Emphasizes the use of a fixed "template" or base plane structure, allowing for efficient hardware implementation where rays are cast in a regular pattern [S1].

## Operating characteristics
* **Time Complexity:** Not given in the sources.
* **Memory Complexity:** Not given in the sources.
* **Performance:** High performance on massively parallel architectures due to regular, object-order data access [S1, S2]. The VolumePro system demonstrated subsecond rendering for 128³ datasets on 1024 processors using this approach [S2].
* **Strengths:** Regular memory access patterns; efficient parallelization; simplified path generation for rays [S1, S2].
* **Limitations:** Requires additional memory for the intermediate image; less flexible for arbitrary view directions compared to pure image-order methods [S1, S2].
* **When to Use:** Ideal for hardware implementations and parallel architectures where memory access patterns are critical [S1, S2].
* **When Not to Use:** When memory is extremely constrained (due to intermediate buffer) or when arbitrary, dynamic view directions require frequent recomputation of shear/scale parameters [S2].

## Background
Hybrid Ray-Casting, also known as Template-Based Raycasting or Shear-Warp, was developed to address the inefficiencies of image-order ray casting on parallel hardware [S1, S2]. Key contributors include Yagel and Kaufman, who described the template-based scheme [S2], and Lacroute and Levoy, who reported on fast implementations using shear-warp transformations [S2]. The method is central to systems like VolumePro, a commercial volume rendering ASIC [S1]. It is widely used in high-performance volume rendering applications where regular data access is paramount [S1, S2].
