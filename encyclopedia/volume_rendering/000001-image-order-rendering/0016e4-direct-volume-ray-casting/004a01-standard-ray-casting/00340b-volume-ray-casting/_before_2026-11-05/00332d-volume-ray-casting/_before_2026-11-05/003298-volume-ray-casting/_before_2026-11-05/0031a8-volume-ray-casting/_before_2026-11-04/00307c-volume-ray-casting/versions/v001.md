# Volume Ray Casting

Also called: GPU-based ray casting, Ray Casting Volume Rendering

## Overview
Volume Ray Casting is an image-order direct volume rendering technique that computes the final pixel color by casting a ray from the camera center through each pixel into the 3D volume and evaluating the volume rendering integral along that path [S1, S3, unofficial][S4][S6, S11, unofficial][S12]. It solves the problem of visualizing the interior structure of volumetric data (such as medical scans or fluid simulations) without extracting explicit geometric surfaces [S3, S9, unofficial]. Unlike slice-based methods (e.g., [Shear-Warp](6225-slice-based-and-proxy-geometry-rendering.md)) which are view-dependent and prone to aliasing when the view angle changes, Volume Ray Casting is view-independent and produces high-quality images with smooth shading and accurate transparency [S3, S7, unofficial]. It builds on [Direct volume ray casting](19-direct-volume-ray-casting.md) by providing the specific implementation details for the per-pixel ray traversal and compositing loop.

## How it works
**Inputs:**
*   **Volume Data ($V$):** A 3D scalar field defined on a regular grid, $V: \mathbb{N}^3 \rightarrow \mathbb{R}$, where each voxel $(x,y,z)$ holds a scalar value (e.g., density or intensity) [S2, S11, unofficial].
*   **Camera:** Defined by an origin $O$ and a direction vector $D$ for each pixel $(u,v)$ on the image plane [S1, S11, unofficial].
*   **Transfer Function ($TF$):** A mapping from scalar values to optical properties: color $C \in [0,1]^3$ and opacity $\alpha \in [0,1]$ [S2, S6, unofficial].
*   **Volume Bounds:** The axis-aligned bounding box (AABB) of the volume data [G].
*   **Parameters:** Step size $\delta$ (distance between samples), early termination threshold $\alpha_{thresh}$ (typically 0.99) [S2, S18, unofficial].

**Outputs:**
*   **Image:** A 2D array of RGB colors, one per pixel [S1, S11, unofficial].

**Data Structures:**
*   **Volume Texture:** The scalar data is typically stored in a 3D texture or a contiguous 3D array to allow efficient trilinear interpolation [S4][S11, unofficial].
*   **Accumulators:** Per-pixel variables for accumulated color $C'$ and accumulated opacity $\alpha'$ [S9, unofficial].

**Algorithm Steps:**

1.  **Ray Generation:** For each pixel $(u,v)$ in the image, generate a ray $r(t) = O + tD$. The ray originates at the camera center and passes through the pixel center [S1, S11, unofficial].
2.  **Ray-Volume Intersection:** Compute the entry point $t_{start}$ and exit point $t_{end}$ of the ray with respect to the volume's bounding box [G]. If the ray does not intersect the volume, the pixel is background.
3.  **Initialization:** Initialize accumulated color $C' = (0,0,0)$ and accumulated opacity $\alpha' = 0$ [S9, unofficial].
4.  **Ray Marching Loop:** Iterate along the ray from $t_{start}$ to $t_{end}$ with a fixed step size $\delta$ (or adaptive step size) [S3, S11, unofficial].
    *   **Random Offset:** To prevent banding artifacts caused by regular sampling, add a small random offset $r \in [0, \delta)$ to the initial $t$ value [S18, unofficial].
    *   **Position Calculation:** Compute the current 3D position $P = O + tD$.
    *   **Sampling:** Sample the volume at $P$ using trilinear interpolation to obtain the scalar value $d$ [S1, S5, S11, unofficial].
        $$ V_{xyz} = \sum_{i,j,k \in \{0,1\}} V_{ijk} (1-x)^{1-i} x^i (1-y)^{1-j} y^j (1-z)^{1-k} z^k $$
        where $V_{ijk}$ are the 8 neighboring voxel values and $x,y,z$ are the fractional coordinates within the voxel [S11, unofficial].
    *   **Transfer Function:** Map the scalar value $d$ to color $C_i$ and opacity $\alpha_i$ using the transfer function [S2, S5, S6, unofficial].
    *   **Compositing:** Update the accumulated color and opacity using front-to-back compositing [S2, S3, S8, S9, S11, S14, S16, S20, S23, S26, unofficial]:
        $$ C'_{new} = C'_{old} + (1 - \alpha'_{old}) \alpha_i C_i $$
        $$ \alpha'_{new} = \alpha'_{old} + (1 - \alpha'_{old}) \alpha_i $$
    *   **Early Termination:** If $\alpha' \ge \alpha_{thresh}$ (typically 0.99), terminate the loop for this ray [S2, S18, unofficial].
    *   **Advance:** Increment $t$ by $\delta$ [S7, S11, unofficial].
5.  **Gamma Correction:** Apply gamma correction (typically $\gamma=2.2$) to the final accumulated color $C'$ to account for display characteristics [S9, unofficial].
    $$ C_{final} = (C')^{1/2.2} $$

**Pseudocode:**

```python
import random
import math

def vec3(x, y, z):
    return [x, y, z]

def pow_vec3(v, exponent):
    return [v[0]**exponent, v[1]**exponent, v[2]**exponent]

def compute_ray_exit(origin, direction, bounds):
    """
    Computes the intersection interval [t_min, t_max] of a ray with an AABB.
    bounds: [[min_x, min_y, min_z], [max_x, max_y, max_z]]
    Returns t_max (exit distance) if intersection exists, else None.
    """
    t_min = float('-inf')
    t_max = float('inf')
    
    for i in range(3):
        if direction[i] == 0:
            if origin[i] < bounds[0][i] or origin[i] > bounds[1][i]:
                return None # Ray is parallel and outside
            else:
                continue # Ray is parallel and inside, no contribution to t bounds
        
        t1 = (bounds[0][i] - origin[i]) / direction[i]
        t2 = (bounds[1][i] - origin[i]) / direction[i]
        
        if t1 > t2:
            t1, t2 = t2, t1
            
        if t1 > t_min:
            t_min = t1
        if t2 < t_max:
            t_max = t2
            
        if t_min > t_max:
            return None # No intersection
            
    if t_max < 0:
        return None # Intersection is behind the camera
        
    return t_max

def trilinear_interpolate(volume, pos, dims):
    """
    Performs trilinear interpolation on a 3D volume array.
    volume: 3D list or array of scalars.
    pos: [x, y, z] in texture coordinates [0, 1].
    dims: [dim_x, dim_y, dim_z] in voxels.
    """
    # Convert texture coordinates to voxel coordinates
    vx = pos[0] * (dims[0] - 1)
    vy = pos[1] * (dims[1] - 1)
    vz = pos[2] * (dims[2] - 1)
    
    # Floor and ceil indices
    x0, y0, z0 = int(math.floor(vx)), int(math.floor(vy)), int(math.floor(vz))
    x1, y1, z1 = x0 + 1, y0 + 1, z0 + 1
    
    # Clamp indices to valid range
    x0 = max(0, min(x0, dims[0]-1))
    x1 = max(0, min(x1, dims[0]-1))
    y0 = max(0, min(y0, dims[1]-1))
    y1 = max(0, min(y1, dims[1]-1))
    z0 = max(0, min(z0, dims[2]-1))
    z1 = max(0, min(z1, dims[2]-1))
    
    # Fractional parts
    wx = vx - x0
    wy = vy - y0
    wz = vz - z0
    
    # Interpolate along x
    c00 = volume[x0][y0][z0] * (1-wx) + volume[x1][y0][z0] * wx
    c01 = volume[x0][y0][z1] * (1-wx) + volume[x1][y0][z1] * wx
    c10 = volume[x0][y1][z0] * (1-wx) + volume[x1][y1][z0] * wx
    c11 = volume[x0][y1][z1] * (1-wx) + volume[x1][y1][z1] * wx
    
    # Interpolate along y
    r0 = c00 * (1-wy) + c10 * wy
    r1 = c01 * (1-wy) + c11 * wy
    
    # Interpolate along z
    return r0 * (1-wz) + r1 * wz

def direct_volume_raycast(volume_data, camera, transfer_function, volume_bounds, volume_dims, step_size=0.001, threshold=0.99):
    """
    Renders a volume using fixed-step raycasting with front-to-back compositing.
    """
    h, w = camera.screen_height, camera.screen_width
    image = [[vec3(0.0, 0.0, 0.0) for _ in range(w)] for _ in range(h)]
    
    for y in range(h):
        for x in range(w):
            ray_origin, ray_direction = camera.cast_ray(x, y)
            accumulated_color = vec3(0.0, 0.0, 0.0)
            accumulated_opacity = 0.0
            
            # Ray initialization: fixed random offset to prevent banding [S18, unofficial]
            t = random.uniform(0.0, step_size)
            
            # Compute ray exit distance from volume bounds [G]
            t_end = compute_ray_exit(ray_origin, ray_direction, volume_bounds)
            
            # If no intersection, skip
            if t_end is None:
                continue
                
            while accumulated_opacity < threshold and t < t_end:
                # Compute current position in texture space [0,1]
                # Note: ray_origin and direction are assumed to be in world space
                # and volume_bounds/dims map to world space. 
                # For simplicity, assuming camera.cast_ray returns world-space ray
                # and we normalize pos to [0,1] relative to volume bounds if needed.
                # Here we assume pos is directly usable by trilinear_interpolate
                # which expects [0,1] texture coordinates.
                
                # Convert world position to texture coordinate [0,1]
                # Assuming volume_bounds are in world space and map to [0,1]
                pos_world = [ray_origin[i] + t * ray_direction[i] for i in range(3)]
                
                # Map world pos to [0,1] texture space
                pos_tex = [
                    (pos_world[0] - volume_bounds[0][0]) / (volume_bounds[1][0] - volume_bounds[0][0]),
                    (pos_world[1] - volume_bounds[0][1]) / (volume_bounds[1][1] - volume_bounds[0][1]),
                    (pos_world[2] - volume_bounds[0][2]) / (volume_bounds[1][2] - volume_bounds[0][2])
                ]
                
                # Sample volume at current position using trilinear interpolation [S1, unofficial][S5, unofficial]
                scalar_value = trilinear_interpolate(volume_data, pos_tex, volume_dims)
                
                # Apply transfer function to get color and opacity [S2, S5, unofficial]
                color, opacity = transfer_function(scalar_value)
                
                # Front-to-back compositing [S2, S5, unofficial]
                accumulated_color[0] += (1.0 - accumulated_opacity) * opacity * color[0]
                accumulated_color[1] += (1.0 - accumulated_opacity) * opacity * color[1]
                accumulated_color[2] += (1.0 - accumulated_opacity) * opacity * color[2]
                accumulated_opacity += (1.0 - accumulated_opacity) * opacity
                
                t += step_size
                
            # Gamma correction [S9, unofficial]
            image[y][x] = pow_vec3(accumulated_color, 1.0/2.2)
            
    return image
```

## Subtopics

### [Object-Order Ray-Casting](6204-object-order-ray-casting.md)
A variant that transforms the volume to align with the view direction, allowing rays to sample at integer grid points. It combines the high-quality trilinear interpolation of image-order ray-casting with the cache-friendly, regular memory access patterns of object-order methods. Unlike standard image-order ray-casting, which suffers from cache misses due to irregular voxel access, or Shear-Warp, which introduces artifacts and blurring, this method maintains interactive frame rates (up to 10 fps) while preserving image quality.

## Operating characteristics
**Time Complexity:** $O(N \cdot M \cdot L)$, where $N$ is the number of pixels, $M$ is the number of samples per ray, and $L$ is the cost of sampling/compositing per sample [S7, unofficial]. The number of samples $M$ depends on the volume depth and step size.
**Memory Complexity:** $O(V)$, where $V$ is the size of the volume data, plus $O(N)$ for the output image [S7, S9, unofficial].
**Performance:** Historically, ray casting was slower than slice-based methods due to irregular memory access patterns and the need for multiple passes or complex data structures [S7, unofficial]. However, with the advent of GPGPU and optimized texture units, GPU-based ray casting can achieve interactive frame rates [S3, S7, S9, unofficial]. Performance is highly dependent on the density of the volume; early ray termination significantly reduces the average number of samples per ray [S3, S7, unofficial].
**Strengths:** View-independent, high image quality, supports complex transfer functions and shading (e.g., gradient-based lighting) [S3, S6, S7, unofficial].
**Limitations:** Computationally expensive for large volumes or high resolutions; prone to banding artifacts if sampling is not randomized; requires careful tuning of step size and transfer functions [S7, S18, unofficial].

## Background
Volume Ray Casting was first presented by Appel in 1968 [S10, unofficial]. It is based on the volume rendering integral, which models the attenuation and emission of light as it passes through a participating medium [S4][S11, unofficial]. The method was initially overlooked in favor of slicing methods due to hardware optimizations for 2D texturing [S7, unofficial]. However, with the rise of GPGPU and CUDA, ray casting has become a standard technique for high-quality volume visualization [S3, S7, S9, unofficial]. It is widely used in medical imaging (CT, MRI), scientific visualization (fluid dynamics), and computer graphics [S2, S5, S9, unofficial]. The technique is closely related to NeRF, which uses a similar volume rendering formula but with neural networks to represent the volume [S4].
