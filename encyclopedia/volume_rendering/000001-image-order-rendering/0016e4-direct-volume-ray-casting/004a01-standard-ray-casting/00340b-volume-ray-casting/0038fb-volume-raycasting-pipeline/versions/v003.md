# Volume Raycasting Pipeline

Also called: Direct Volume Raycasting Pipeline, Image-Order Volume Rendering Pipeline, Raycasting Pipeline

## Overview
The Volume Raycasting Pipeline is the standard procedural framework for direct volume rendering, calculating the volume rendering integral for every viewing ray originating at the image plane and passing through the volume [S1, unofficial]. It advances rays through the volume with regular increments, performing reconstruction, classification, shading, and compositing at each sample location [S1, unofficial]. It is distinguished from its siblings [Volume Ray Casting with Barycentric Interpolation and Phong Lighting](2419-volume-ray-casting-with-barycentric-interpolation-and-phong-.md), [Backward Mapping (Ray Tracing)](3009-backward-mapping-ray-tracing.md), [Hybrid Ray-Casting](3180-hybrid-ray-casting.md), [Two-Pass Depth Ray Casting](3377-two-pass-depth-ray-casting.md), [Van Hook-Levoy Ray-Casting](3594-van-hook-levoy-ray-casting.md), [Koyamada's Algorithm](4148-koyamada-s-algorithm.md), [Single-pass Raycasting](6121-single-pass-raycasting.md), [Object-Order Ray-Casting](6204-object-order-ray-casting.md), and [RaycastBrightnessControl](6526-raycastbrightnesscontrol.md) by its explicit separation of these four stages and the critical decision of whether classification and shading occur before or after reconstruction (pre- vs. post-), where post-classification and post-shading are preferred to avoid severe artifacts caused by non-linear reconstruction [S1, unofficial].

## How it works
The method evaluates the volume rendering integral by advancing rays through the volume with regular increments (the object sample distance) [S1, unofficial]. At each resample location along the ray, the pipeline executes four sequential steps: Reconstruction, Classification, Shading, and Compositing [S1, unofficial]. The pipeline supports four variants based on the ordering of Classification and Shading relative to Reconstruction: 1. Pre-classification, Pre-shading; 2. Pre-classification, Post-shading; 3. Post-classification, Pre-shading; 4. Post-classification, Post-shading [S1, unofficial]. The recommended configuration uses Post-classification and Post-shading [S1, unofficial].

### Inputs and Outputs
*   **Input:** A discrete scalar dataset $D$ defined on a 3D grid [S1, unofficial]; a viewing ray $R(t)$ defined by an origin $\mathbf{o}$ and direction $\mathbf{d}$ [G]; a transfer function $T(v)$ mapping scalar values to color and opacity [S1, unofficial]; an illumination model $L(g)$ mapping gradients to shading parameters [S1, unofficial].
*   **Output:** A final color value $C_{final}$ for each pixel [G].

### Data Structures
*   **Dataset $D$:** A 3D array of scalar values [G]. Layout is implementation-dependent but typically stored in row-major or column-major order [G].
*   **Ray $R(t)$:** Defined by origin $\mathbf{o}$ and direction $\mathbf{d}$, parameterized by distance $t$ [G].
*   **Sample Point:** A position $\mathbf{p}$ along the ray where data is sampled [G].

### Numbered Steps
1.  **Initialize Ray:** For each pixel, generate a viewing ray $R(t)$ originating from the image plane and passing through the volume [G].
2.  **Advance Ray:** Move along the ray with a regular increment $\Delta t$ (object sample distance) [S1, unofficial]. Let the current position be $\mathbf{p}$ [G].
3.  **Reconstruction:** Construct a continuous function from the discrete dataset $D$ at position $\mathbf{p}$ [S1, unofficial].
    *   If **Pre-classification/Pre-shading**: Sample the discrete data $D$ at $\mathbf{p}$ to get value $v$ [G].
    *   If **Post-classification/Post-shading**: Apply a reconstruction filter to the original sample values around $\mathbf{p}$ to estimate the continuous function value $v_{rec}$ and gradient $g_{rec}$ at $\mathbf{p}$ [S1, unofficial].
4.  **Classification:**
    *   If **Pre-classification**: Assign color $c$ and opacity $\alpha$ to the sampled value $v$ using transfer function $T$: $(c, \alpha) = T(v)$ [S1, unofficial].
    *   If **Post-classification**: Classify the reconstructed value $v_{rec}$: $(c, \alpha) = T(v_{rec})$ [S1, unofficial].
5.  **Shading:**
    *   If **Pre-shading**: Evaluate the illumination model $L$ at the grid points only (or use pre-computed shading values) [S1, unofficial].
    *   If **Post-shading**: Reconstruct the gradient $g_{rec}$ at $\mathbf{p}$ and evaluate the illumination model $L(g_{rec})$ to determine shading parameters (e.g., diffuse color, specular highlights) [S1, unofficial].
6.  **Compositing:** Determine the contribution of the classified and shaded sample to the final image [S1, unofficial]. This typically involves front-to-back alpha compositing, blending the current sample's color and opacity with the accumulated result from previous samples along the ray [G].
7.  **Repeat:** Continue steps 2-6 until the ray exits the volume or a termination condition is met [G].
8.  **Finalize:** Output the accumulated color for the pixel [G].

### Formulas
*   **Discrete Compositing:** $C_{out} = C_{in} + c \cdot \alpha \cdot T$, $T_{out} = T \cdot (1 - \alpha)$, where $C$ is accumulated color, $\alpha$ is sample opacity, $c$ is sample color, and $T$ is current transmittance [G].
*   **Pre-classification:** $(c, \alpha) = T(D(\mathbf{p}))$ [S1, unofficial].
*   **Post-classification:** $(c, \alpha) = T(\text{Reconstruct}(D, \mathbf{p}))$ [S1, unofficial].
*   **Pre-shading:** $L$ evaluated at grid points [S1, unofficial].
*   **Post-shading:** $L(\text{ReconstructGradient}(D, \mathbf{p}))$ [S1, unofficial].

### Parameters
*   **Object sample distance ($\Delta t$):** The regular increment for advancing rays [S1, unofficial]. Not given in the sources.
*   **Reconstruction filter:** The specific filter used to construct the continuous function [S1, unofficial]. Not given in the sources.
*   **Transfer function $T(v)$:** Maps scalar values to color and opacity [S1, unofficial]. Not given in the sources.
*   **Illumination model $L(g)$:** Evaluates lighting based on gradients [S1, unofficial]. Not given in the sources.

### Edge Cases and Pitfalls
*   **Non-commutativity:** Pre-classification and pre-shading cause severe artifacts because reconstruction is usually non-linear and does not commute with transfer functions or lighting models [S1, unofficial].
*   **Precision:** Using floating-point precision throughout the pipeline is recommended to minimize artifacts [S1, unofficial].
*   **Boundary Conditions:** Ray traversal must handle entry and exit from the volume correctly [G]. Not given in the sources.

### Pseudocode
```python
def volume_ray_casting_pipeline(dataset, origin, direction, step_size, transfer_function, illumination_model, volume_bounds):
    """
    Executes the Volume Raycasting Pipeline for a single ray.
    
    Args:
        dataset: 3D array of scalar values.
        origin: 3D vector (x, y, z) ray origin.
        direction: 3D vector (x, y, z) ray direction.
        step_size: Regular increment for advancing rays (object sample distance).
        transfer_function: Function mapping scalar value to (color, opacity).
        illumination_model: Function mapping gradient to shading parameters.
        volume_bounds: Tuple (min_x, max_x, min_y, max_y, min_z, max_z).
        
    Returns:
        Final color for the pixel.
    """
    accumulated_color = [0.0, 0.0, 0.0]
    transmittance = 1.0
    
    # Calculate entry and exit t values (slab method)
    t_min = 0.0
    t_max = float('inf')
    for i in range(3):
        if direction[i] == 0:
            if origin[i] < volume_bounds[2*i] or origin[i] > volume_bounds[2*i+1]:
                return [0.0, 0.0, 0.0]
        else:
            t1 = (volume_bounds[2*i] - origin[i]) / direction[i]
            t2 = (volume_bounds[2*i+1] - origin[i]) / direction[i]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
            
    if t_min > t_max:
        return [0.0, 0.0, 0.0]
        
    t = t_min
    while t <= t_max:
        pos = [origin[i] + t * direction[i] for i in range(3)]
        
        # Reconstruction: apply reconstruction filter to dataset at pos to estimate continuous value and gradient [G]
        reconstructed_value, reconstructed_gradient = 0.0, [0.0, 0.0, 0.0]
        
        # Classification
        color, opacity = transfer_function(reconstructed_value)
        
        # Shading
        shading_params = illumination_model(reconstructed_gradient)
        shaded_color = [color[i] * shading_params[i] for i in range(3)]
        
        # Compositing (Front-to-Back)
        contribution = [shaded_color[i] * opacity * transmittance for i in range(3)]
        accumulated_color = [accumulated_color[i] + contribution[i] for i in range(3)]
        transmittance = transmittance * (1.0 - opacity)
        
        # Early termination if fully opaque
        if transmittance < 0.001:
            break
            
        t += step_size
        
    return accumulated_color
```

## Subtopics

### Reconstruction
The process of constructing a continuous function from the dataset to allow sampling at arbitrary positions along the ray [S1, unofficial]. It is fundamental to post-classification and post-shading [S1, unofficial].

### Classification
The process of assigning color and opacity to data values using a transfer function [S1, unofficial]. Post-classification is preferred to avoid artifacts from non-linear reconstruction [S1, unofficial].

### Shading
The evaluation of the illumination model [S1, unofficial]. Post-shading reconstructs gradients at every resample location for better visual quality [S1, unofficial].

### Compositing
The process of blending sample contributions into the final image [S1, unofficial]. Typically uses front-to-back alpha compositing [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray and the number of rays (pixels) [G]. Not given in the sources.
*   **Memory Complexity:** Depends on the dataset size and the storage of intermediate values per sample [G]. Not given in the sources.
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Flexible pipeline allowing different combinations of classification and shading orders; post-classification and post-shading provide high visual quality [S1, unofficial].
*   **Limitations:** Pre-classification and pre-shading cause severe artifacts [S1, unofficial]. Performance can be high due to per-sample reconstruction and shading calculations [S1, unofficial].
*   **When to use:** When high-quality volume rendering is required and computational resources allow for post-classification and post-shading [S1, unofficial].
*   **When not to use:** When performance is critical and visual artifacts from pre-classification/pre-shading are acceptable, or when the reconstruction filter is not available [S1, unofficial].

## Background
The Volume Raycasting Pipeline framework was described in a master's thesis titled "The Raycasting Pipeline" [S1, unofficial]. The work compares four variants of the pipeline based on the ordering of classification and shading relative to reconstruction, demonstrating that post-classification and post-shading yield the best results [S1, unofficial].
