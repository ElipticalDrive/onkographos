# Single-pass Raycasting

Also called: Direct Volume Rendering via Raycasting, Single Pass GPU Ray Casting, Single execution ray casting

## Overview
Single-pass raycasting is a direct volume rendering technique that generates one ray per pixel, samples a 3D texture along the ray, and composites the results in a single GPU rendering pass to produce a 2D image [S1, unofficial]. It distinguishes itself from multi-pass approaches by avoiding temporary framebuffers for intermediate ray results, thereby addressing the low efficiency of multi-pass pipelines on modern graphics hardware [S2, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   **Volume Data:** A 3D grid of scalar values loaded from a `Uint16Array` where the first three elements are dimensions ($W, H, D$) and the remaining elements are voxel values normalized by dividing by 4095.0 [S1, unofficial]. The data is stored in a `THREE.Data3DTexture` with format `THREE.RedFormat`, type `THREE.FloatType`, and linear filtering [S1, unofficial].
*   **Camera:** Eye position and projection parameters [S1, unofficial].
*   **Lighting:** Light position (often fixed at the camera position in basic implementations) and color [S1, unofficial].
*   **Parameters:** Uniforms controlling rendering mode, thresholds, step size, and transfer functions [S1, unofficial][S4].

**Outputs:**
*   **2D Image:** A color buffer where each pixel contains the accumulated color and opacity from the ray traversal [S1, unofficial].

### Data Structures
The implementation relies on the following structures and uniforms:

1.  **Volume Texture (`sampler3D volume_data`):**
    *   Dimensions: $W \times H \times D$.
    *   Coordinate space: Unit cube $[0,1]^3$ [S1, unofficial].
2.  **Transfer Function Textures (`sampler2D`):**
    *   Lookup tables for color and opacity based on density and gradient magnitude [S4].
    *   Resolution controlled by `TransferSize` [S4].
3.  **Ray Entry/Exit Textures (FBOs):**
    *   Textures storing ray entry and exit positions for each fragment [S4].
    *   Resolution controlled by `FBOSize` [S4].
4.  **Uniforms:**
    *   `volume_size`: `vec3` containing the dimensions of the volume [S1, unofficial].
    *   `render_mode`: `int` (0 for First Hit, 1 for MIP) [S1, unofficial].
    *   `u_renderthreshold`: `float` iso-value threshold for First Hit mode [S1, unofficial].
    *   `StepSize`: `float` spatial distance between samples [S4].
    *   `MaxSamples`: `int` limit on samples per ray [S4].
    *   `Minclip`: `float` threshold to discard low-density samples [S4].
    *   `Apply Noise`: `bool` toggle for stochastic ray shifting [S4].
    *   `GradDelta`: `vec3` offsets for gradient computation [S4].
    *   `Threshold (Shadows)`: `float` occlusion threshold for shadow rays [S4].
    *   `Quality (Shadows)`: `int` (0-100) controlling shadow ray sample count [S4].

### Numbered Steps

1.  **Initialization and Coordinate Transformation:**
    *   Transform the camera eye position into the volume's unit cube space [S1, unofficial]. The transformed eye position is calculated as:
        $$ \text{transformed\_eye} = \frac{\text{cameraPosition}}{\text{volume\_size}} + (0.5, 0.5, 0.5) $$
        [S1, unofficial]
    *   For each fragment (pixel), calculate the ray direction in unit cube space [S1, unofficial]. The fragment position is normalized to $[0,1]$ [G]. The direction is:
        $$ \vec{vray\_dir} = \frac{\text{position}}{\text{volume\_size}} + (0.5, 0.5, 0.5) - \text{transformed\_eye} $$
        [S1, unofficial]
    *   *Note:* In some implementations, ray entry and exit positions are pre-rendered to textures (FBOs) and looked up in the fragment shader to compute directions [S4].

2.  **Ray-Box Intersection:**
    *   Calculate the intersection of the view ray with the unit cube bounds $[0,1]^3$ [S1, unofficial].
    *   If the ray does not intersect the cube ($t_{hit.x} > t_{hit.y}$), discard the fragment [S1, unofficial].
    *   Set the starting parameter $t = \max(t_{hit.x}, 0.0)$ [S1, unofficial].

3.  **Step Size Calculation:**
    *   Compute the step size $dt$ to ensure consistent sampling relative to the grid:
        $$ dt = \min \left( \frac{1}{W |v_x|}, \frac{1}{H |v_y|}, \frac{1}{D |v_z|} \right) $$
        where $\vec{v} = (v_x, v_y, v_z)$ is the ray direction and $W,H,D$ are volume dimensions [S1, unofficial].

4.  **Ray Marching Loop:**
    *   Initialize accumulation variables: `alpha = 0.0`, `color = (0,0,0)` [G].
    *   Initialize previous sample point `pointN0` and value `valueN0` at the start position [S1, unofficial].
    *   Iterate while $t < t_{hit.y}$ and sample count $< MaxSamples$:
        a.  **Stochastic Shifting:** If `Apply Noise` is true, perturb the ray position slightly to reduce banding artifacts [S4].
        b.  **Advance Ray:** Calculate next position `pointN1 = pointN0 + ray_dir * dt` [S1, unofficial].
        c.  **Sample Volume:** Read value `valueN1 = sample_volume(pointN1)` [S1, unofficial].
        d.  **Minclip Check:** If `valueN1 < Minclip`, continue to next sample (discard) [S4].
        e.  **Mode-Specific Processing:**
            *   **First Hit Mode (`render_mode == 0`):**
                *   If `valueN1 > u_renderthreshold`:
                    *   Interpolate to find the exact surface position $t_{surf}$ where the value equals the threshold:
                        $$ t_{surf} = t - dt \cdot \frac{valueN1 - u\_renderthreshold}{valueN1 - valueN0} $$
                        [S1, unofficial]
                    *   Calculate the surface normal using central differences (gradient) at the surface point [G]. Gradient computation uses offsets defined by `GradDelta` [S4].
                    *   Compute lighting (diffuse/specular) using the normal and light direction [S1, unofficial].
                    *   Apply transfer function to map density to color [S1, unofficial].
                    *   Set final pixel color to the lit surface color and break the loop [S1, unofficial].
                *   Else: Update `valueN0 = valueN1`, `pointN0 = pointN1`, $t += dt$.
            *   **MIP Mode (`render_mode == 1`):**
                *   Track the maximum value encountered along the ray [S1, unofficial].
                *   Update `max_val = max(max_val, valueN1)` [S1, unofficial].
                *   Continue to next sample.
                *   After loop, apply transfer function to `max_val` to determine color [S1, unofficial].
        f.  **Shadow Rays (Optional):**
            *   For each sample, cast a shadow ray towards the light source [S4].
            *   Sample until density exceeds `Threshold (Shadows)` [S4].
            *   Number of samples controlled by `Quality (Shadows)` [S4].
            *   Modulate lighting based on occlusion [S4].

5.  **Transfer Function Application:**
    *   Map the final scalar value (surface value for First Hit, max value for MIP) to color and opacity using the transfer function lookup tables [S4].
    *   The transfer function allows arbitrary modulation of density and gradient magnitude lookups [S4].
    *   Default color mapping may use the Viridis colormap [S1, unofficial].

6.  **Compositing:**
    *   In First Hit mode, the result is the color of the first surface hit [S1, unofficial].
    *   In MIP mode, the result is the color corresponding to the maximum intensity [S1, unofficial].
    *   Standard front-to-back alpha compositing is not explicitly detailed for the final pixel in the provided code snippets for First Hit/MIP modes, as they are "single hit" or "max" projections rather than volumetric integration [S1, unofficial]. The provided code for First Hit breaks on hit, and MIP takes the max, implying no alpha blending accumulation in the loop for these specific modes [S1, unofficial].

### Pseudocode

```python
import math
import random

def single_pass_raycasting(camera_position, volume_size, position, render_mode, u_renderthreshold, minclip, apply_noise, grad_delta, light_position, shininess, light_color, ambient, sample_volume, apply_transfer_function, intersect_box):
    # 1. Transform eye to unit cube space
    transformed_eye = camera_position / volume_size + vec3(0.5, 0.5, 0.5)

    # 2. Calculate ray direction in unit cube space
    ray_dir = (position / volume_size) + vec3(0.5, 0.5, 0.5) - transformed_eye

    # 3. Intersect ray with unit cube [0,1]^3
    t_hit = intersect_box(transformed_eye, ray_dir)
    if t_hit[0] > t_hit[1]:
        return None  # Discard

    t_start = max(t_hit[0], 0.0)

    # 4. Calculate step size
    dt_vec = vec3(1.0) / (volume_size * abs(ray_dir))
    dt = min(dt_vec[0], min(dt_vec[1], dt_vec[2]))

    # 5. Initialize variables
    alpha = 0.0
    color = vec3(0.0)
    pointN0 = transformed_eye + t_start * ray_dir
    valueN0 = sample_volume(pointN0)
    max_val = float('-inf')
    sample_count = 0

    # 6. Ray Marching Loop
    t = t_start
    while t < t_hit[1] and sample_count < MaxSamples:
        # Stochastic shifting if enabled
        if apply_noise:
            pointN1 = pointN0 + ray_dir * dt + vec3(random.uniform(-0.5, 0.5), random.uniform(-0.5, 0.5), random.uniform(-0.5, 0.5))
        else:
            pointN1 = pointN0 + ray_dir * dt

        valueN1 = sample_volume(pointN1)

        # Minclip check
        if valueN1 < minclip:
            valueN0 = valueN1
            pointN0 = pointN1
            t += dt
            sample_count += 1
            continue

        if render_mode == 0:  # First Hit
            if valueN1 > u_renderthreshold:
                # Interpolate surface position
                linear_interpolation = (u_renderthreshold - valueN0) / (valueN1 - valueN0)
                t_surf = t - dt * linear_interpolation
                surface_pos = pointN0 + ray_dir * (t - t_surf)

                # Calculate gradient for normal [G]
                grad = (sample_volume(surface_pos + grad_delta) - sample_volume(surface_pos - grad_delta)) / (2.0 * grad_delta)
                normal = normalize(grad)

                # Lighting (single scattering model)
                light_dir = normalize(light_position - surface_pos)
                diffuse = max(dot(normal, light_dir), 0.0)
                specular = pow(max(dot(reflect(-light_dir, normal), -ray_dir), 0.0), shininess)

                # Transfer function [G]
                tf_color = apply_transfer_function(valueN1)
                color = tf_color * (ambient + diffuse * light_color + specular * light_color)
                break  # Exit loop on first hit
            else:
                valueN0 = valueN1
                pointN0 = pointN1
        elif render_mode == 1:  # MIP
            if valueN1 > max_val:
                max_val = valueN1
            valueN0 = valueN1
            pointN0 = pointN1

        t += dt
        sample_count += 1

    # 7. Final Output
    if render_mode == 1:
        color = apply_transfer_function(max_val)

    return vec4(color, 1.0)
```

### Parameters
*   **StepSize:** Controls spatial distance between samples. Higher values reduce quality but increase speed [S4].
*   **MaxSamples:** Limits the total number of samples per ray to prevent infinite loops or excessive computation [S4].
*   **u_renderthreshold:** Iso-value threshold for First Hit rendering. Only values above this trigger surface detection [S1, unofficial].
*   **Minclip:** Threshold below which samples are discarded (treated as empty) [S4].
*   **FBOSize:** Resolution of textures storing ray entry/exit positions [S4].
*   **TransferSize:** Resolution of transfer function lookup textures [S4].
*   **Apply Noise:** Boolean to enable stochastic ray shifting, reducing banding artifacts [S4].
*   **GradDelta:** Offsets for finite difference gradient calculation [S4].
*   **Threshold (Shadows):** Density value for shadow ray occlusion [S4].
*   **Quality (Shadows):** Number of samples for shadow ray traversal (0-100) [S4].

### Edge Cases and Pitfalls
*   **Data Loading:** Volume data is often stored in a `Uint16Array` with the first 3 elements as dimensions [S1, unofficial]. The voxel values must be normalized by dividing by 4095.0 to fit in the $[0,1]$ range expected by the texture [S1, unofficial].
*   **Precision:** High precision (`highp float`) is required in shaders to avoid artifacts in ray marching and interpolation [S1, unofficial].
*   **Banding Artifacts:** Regular sampling can cause banding [S4]. Stochastic ray shifting (`Apply Noise`) is used to mitigate this [S4].
*   **Memory Limits:** Large volumes may exceed GPU texture memory [S3]. Hierarchical grid representations or out-of-core techniques are needed for very large datasets [S3].

## Subtopics

### Object-Order Ray-Casting
*   **What it is:** A raycasting method that iterates over volume primitives (voxels) and projects them onto the screen, rather than iterating over pixels [G].
*   **Difference:** Single-pass is image-order (pixel-driven), while Object-Order is primitive-driven. Object-order can be more efficient for sparse data but is harder to parallelize on GPUs compared to the regular access patterns of image-order raycasting.
*   **When to choose:** Use when the volume is sparse or when primitive-level manipulation is required. Single-pass is preferred for dense, regular grids on GPUs.
*   **Link:** [Object-Order Ray-Casting](6204-object-order-ray-casting.md)

### RaycastBrightnessControl
*   **What it is:** A method or parameterization technique related to controlling brightness and contrast in raycasting [G].
*   **Difference:** Single-pass is a rendering pipeline strategy. RaycastBrightnessControl likely refers to a specific shading or transfer function adjustment technique applied within a raycasting framework [G].
*   **When to choose:** Use when fine-tuning the visual appearance (brightness/contrast) of the raycast output is the primary goal [G].
*   **Link:** [RaycastBrightnessControl](6526-raycastbrightnesscontrol.md)

## Operating characteristics

*   **Time Complexity:** $O(P \cdot S)$, where $P$ is the number of pixels and $S$ is the number of samples per ray [G]. Shadow rays add a factor of $S_{shadow}$ per sample [S4].
*   **Memory Complexity:** $O(V)$ for the volume texture, where $V$ is the number of voxels [G]. Additional memory for FBOs and transfer functions [S4].
*   **Performance:** Single-pass solutions are more efficient than multi-pass approaches on modern GPUs because they avoid the overhead of rendering to and reading from temporary framebuffers [S2, unofficial].
*   **Strengths:** High flexibility (custom shaders), real-time potential on capable hardware, accurate lighting and transfer functions [S2, unofficial][S4].
*   **Limitations:** Performance degrades with high resolution, large volumes, or complex lighting (shadow rays). Memory bound for very large volumes [S2, unofficial].
*   **When to use:** Real-time visualization of moderate-sized volumes, interactive exploration, spectral DVR [S2, unofficial][S4].
*   **When not to use:** Extremely large volumes that do not fit in GPU memory without hierarchical streaming, or when offline, high-quality volume rendering is required (where path tracing or other offline methods might be better) [S2, unofficial].

## Background

*   **Origin:** The concept of single-pass GPU raycasting was developed to address the inefficiencies of multi-pass rendering pipelines on graphics hardware [S2, unofficial].
*   **Key Contributors:** Stegmaier and colleagues extended the framework to spectral DVR using Kubelka–Munk theory [S3]. Hadwiger et al. used single-pass raycasting for implicit isosurfaces on rectilinear grids [S3]. Roettger et al. built a real-time raycaster with adaptive pre-integrated voxel classification [S3].
*   **History:** Early GPU-based solutions relied on multiple rendering passes [S3]. Single-pass techniques emerged to improve efficiency and flexibility [S3].
*   **Usage:** Used in VStudio as the primary direct volume rendering method [S4]. Extended for spectral DVR [S3].
