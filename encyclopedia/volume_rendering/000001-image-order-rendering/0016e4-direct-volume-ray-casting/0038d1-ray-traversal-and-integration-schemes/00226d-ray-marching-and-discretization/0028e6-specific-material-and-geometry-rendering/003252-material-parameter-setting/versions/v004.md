# Material Parameter Setting

Also called: Material Format, Material object fields, Standard Volume Material, vpSetMaterial

## Overview
Material Parameter Setting defines the data structures and API calls required to configure how a volumetric medium interacts with light during ray marching. It solves the problem of mapping abstract physical or artistic properties (density, color, scattering behavior, emission) into a format consumable by the rendering engine's integration loop. It is distinguished from sibling methods by its focus on **configuration** rather than **sampling**: while [Ray Marching and Discretization](2788-ray-marching-and-discretization.md) handles the geometric traversal and [Specific Material and Geometry Rendering](4395-specific-material-and-geometry-rendering.md) handles the shading logic, this method establishes the state (textures, scalar multipliers, phase functions) that those processes read.

## How it works
The method operates through two primary paradigms: a structured object-based format (used in CUDA/physically-based renderers) and a procedural API-based format (used in legacy or specific SDKs like VolPack). Both paradigms share the goal of binding data sources (grids/textures) to shading parameters.

### Inputs and Outputs
*   **Inputs:** Raw volume data (VDB grids, 3D textures), scalar values (density, temperature), physical constants (wavelengths, Kelvin), and user-defined artistic controls (color, roughness).
*   **Outputs:** A configured `Material` object or context state that exposes fields for density, scatter, transparency, and emission to the ray marching shader.

### Data Structures

#### 1. Material Object (Structured Format)
Used in physically-based ray marching (e.g., CUDA implementations). The object holds shading parameters and texture descriptors.

**Fields:**
*   `albedo`: `float3` (linear RGB). Surface/medium color.
*   `metalness`: `float` in $[0, 1]$. Ratio of specular to diffuse response.
*   `roughness`: `float` in $[0, 1]$. Smoothness of reflections/scattering.
*   `F0`: `float3` (linear RGB). Base reflectivity at normal incidence.
*   `triplar`: `bool`. Projection mode flag (XZ planar vs. triplanar).
*   `normalStrength`: `float`. Multiplier for normal map influence.
*   `albedoTex`: `int` (texture descriptor). `-1` if unused.
*   `normalTex`: `int` (texture descriptor). `-1` if unused.
*   `roughnessTex`: `int` (texture descriptor). `-1` if unused.
*   `metalnessTex`: `int` (texture descriptor). `-1` if unused.
*   `heightmapTex`: `int` (texture descriptor). `-1` if unused. Used for geometric displacement.
*   `ambietTex`: `int` (texture descriptor). `-1` if unused. Ambient occlusion map.

#### 2. VolPack Material State (API Format)
Used in the VolPack SDK. State is managed via context handles and integer constants.

**Constants:**
*   `material_num`: `int`. Identifier for the material slot. Values: `VP_MATERIAL0` through `VP_MATERIAL5`.
*   `property`: `int`. The attribute to set.
    *   `VP_AMBIENT`: Sets R, G, B ambient reflection coefficients.
    *   `VP_DIFFUSE`: Sets R, G, B diffuse reflection coefficients.
    *   `SPECULAR`: Sets R, G, B specular reflection coefficients.
    *   `VP_SHINYNESS`: Sets specular exponent (G, B arguments ignored).
*   `surface_side`: `int`. Determines voxel selection based on gradient direction.
    *   `VP_EXTERIOR`: Voxels where gradient points towards viewer.
    *   `VP_INTERIOR`: Voxels where gradient points away from viewer.
    *   `VP_BOTH_SIDES`: All voxels.
    *   *Note:* `VP_REVERSE_SURFACE_SIDES` can invert exterior/interior logic.

#### 3. VRDF SDK Material State (Shader Uniforms)
Used in the VRDF SDK for labelmap and continuous transfer functions.

**Uniforms:**
*   `_IsLabelMap`: `int`. `1` if transfer function is a labelmap, `0` otherwise.
*   `_P1`, `_P99`: `float`. Intensity range clamping for continuous transfer functions.
*   `_Dim`: `Vector4`. Volume dimensions $(dimX, dimY, dimZ, 1.0)$.
*   `_Affine`: `mat4`. Affine transformation matrix from metadata.
*   `_InvAffine`: `mat4`. Inverse of `_Affine`.
*   `_VolumeTexLabels`: `sampler3D`. Label texture source.
*   `_VolumeTexWeights`: `sampler3D`. Weight texture source (optional).
*   `_HasWeights`: `int`. `1` if weights are present, `0` otherwise.
*   `_TFTex`: `sampler3D`. Transfer function texture.

### Numbered Steps

#### A. Structured Material Initialization (CUDA/PBR Style)
1.  **Define Parameters:** Determine `albedo`, `metalness`, `roughness`, and `F0`.
2.  **Select Constructor:**
    *   If full control is needed, use Constructor 1: `Material(albedo, metalness, roughness, F0)`.
    *   If standard dielectric behavior is desired, use Constructor 2: `Material(albedo, roughness, metalness)`. This internally calls Constructor 1 with `F0 = [0.04, 0.04, 0.04]` [S1].
3.  **Initialize Defaults:** The constructor sets all texture descriptors (`albedoTex`, etc.) to `-1` (textureless), projection mode to planar, and `normalStrength` to `1.0` [S1].
4.  **Bind Textures (Optional):** If procedural or texture-driven shading is required, attach input nodes or texture descriptors to the corresponding fields. This switches the material from the "fast path" (typed grid names) to the "fully programmable path" [S3].

#### B. VolPack API Configuration
1.  **Select Material Slot:** Choose `material_num` from `VP_MATERIAL0` to `VP_MATERIAL5`.
2.  **Set Properties:** Call `vpSetMaterial(vpc, material_num, property, surface_side, r, g, b)` for each attribute.
    *   For `VP_SHINYNESS`, pass `r` as the exponent; `g` and `b` are ignored.
    *   For color properties, `r`, `g`, `b` are the coefficients.
3.  **Define Surface Side:** Set `surface_side` to `VP_EXTERIOR`, `VP_INTERIOR`, or `VP_BOTH_SIDES` to control which voxels are shaded [S2].

#### C. VRDF SDK Initialization
1.  **Extract Metadata:** Read `dimX, dimY, dimZ` from `d.meta.dim` [S4, unofficial].
2.  **Determine Transfer Function Type:** Check `d.tf.type`.
    *   If `"continuous"` and `d.meta.intensity_range` exists (length 2), set `p1 = d.meta.intensity_range[0]` and `p99 = d.meta.intensity_range[1]`.
    *   Otherwise, set `p1 = 0.0`, `p99 = 1.0`.
3.  **Compute Inverse Affine:** Construct `invAffine` from `d.meta.affine` [S4, unofficial].
4.  **Select Textures:**
    *   `texLbl = volumeTexLabels ?? d.labelTexture ?? BlackTex3D`.
    *   `texW = volumeTexWeights ?? d.weightTexture ?? null`.
5.  **Bind Uniforms:** Set `_P1`, `_P99`, `_Dim`, `_Affine`, `_InvAffine`, `_IsLabelMap`, and `_HasWeights` in the shader program. Assign `volumeMaterial` to the `MeshRenderer` [S4, unofficial].

### Formulas and Parameters

#### Transparency and Depth
The `Standard Volume Material` uses Transparency Color and Depth to simulate per-wavelength travel distances [S3].
*   **Transparency Color:** A color vector where darker values imply thicker media (higher absorption) and brighter values imply thinner media.
*   **Transparency Depth:** A scalar value in centimeters. It defines the characteristic attenuation length.
    *   At depth $d$, the volume tints with the opposite color of the Transparency Color.
    *   Formula implication: Absorption coefficient $\sigma_a(\lambda) \propto \frac{1}{\text{Depth}} \cdot \text{Color}(\lambda)$ [S3].

#### Emission Modes
*   **Blackbody Mode:** Converts temperature $T$ (Kelvin) to color.
    *   Range: $3,000 \text{ K}$ (deep red) to $>9,000 \text{ K}$ (white/blue-white) [S3].
    *   Uses Planck's law or a spectral approximation to generate physically correct radiance.
*   **Color Mode:** Uses a fixed artistic gradient: Black $\rightarrow$ Red $\rightarrow$ Yellow. Ignores physics [S3].

#### Anisotropy (Phase Function)
*   **Henyey-Greenstein:** Controlled by asymmetry parameter $g \in [-1, 1]$. Default/All-rounder for isotropic smoke [S3].
*   **Jendersie-d’Eon:** Specialized for clouds, modeling light passing through water droplets [S3].

### Edge Cases and Pitfalls
*   **Case Sensitivity:** In the Standard Volume Material, channel names (e.g., grid names) are case-sensitive. Typing "Density" instead of "density" will fail to bind the volume channel [S3].
*   **Texture Descriptors:** Texture descriptors must be `-1` when unused. Leaving them uninitialized or using `0` (if `0` is a valid handle) may cause undefined behavior or incorrect sampling [S1].
*   **Surface Side Reversal:** The meaning of `VP_EXTERIOR` and `VP_INTERIOR` depends on the gradient direction. If the volume is inverted or the viewer position changes unexpectedly, `VP_REVERSE_SURFACE_SIDES` may be required to maintain correct shading [S2].
*   **Transparency Depth Scale:** `Transparency Depth` is measured in centimeters. Setting it relative to the wrong real-world scale will result in volumes that appear impossibly thick or thin [S3].

## Subtopics

### Volume Material Setup
A specific initialization variant used in the VRDF SDK context. It focuses on preparing the shader uniforms for labelmap and continuous transfer functions. It differs from the general Material Object by explicitly handling metadata extraction (affine matrices, intensity ranges) and texture binding logic (`_HasWeights`, `_IsLabelMap`) rather than just shading parameters. It is chosen when working with the VRDF SDK's specific data format (VRDF) which separates label/weight textures from the transfer function [S4, unofficial].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** The `Material` object is small, storing only a few floats and integer descriptors. The bulk of memory usage comes from the bound textures/grids (VDB, 3D textures), which are external to the material object itself.
*   **Time:** Initialization is $O(1)$ for the structured object. The VRDF SDK setup is $O(1)$ relative to volume size, but involves matrix inversion ($O(1)$ for 4x4) and texture binding. The actual rendering cost is determined by the ray marching loop, not the material setup.

### Measured Performance
*   **Fast Path:** The Standard Volume Material's "fast path" (typed grid names) is optimized for speed, avoiding procedural node evaluation overhead [S3].
*   **Programmable Path:** Attaching input nodes switches to a fully programmable path, which may incur overhead from procedural noise or remapping calculations during sampling [S3].

### Strengths and Limitations
*   **Strengths:**
    *   **Flexibility:** Supports both simple scalar multiplication (Density) and complex procedural driving (input nodes) [S3].
    *   **Physical Accuracy:** Blackbody emission and per-wavelength transparency provide physically plausible results [S3].
    *   **Standardization:** The Material Object format aligns with PBR workflows (albedo, metalness, roughness) [S1].
*   **Limitations:**
    *   **Complexity:** The programmable path can be difficult to debug compared to the fast path [S3].
    *   **Scale Dependency:** Transparency Depth requires careful real-world scaling [S3].
    *   **Legacy API:** VolPack's API is rigid and requires explicit property setting for each material slot [S2].

### When to Use
*   Use the **Structured Material Object** when integrating volumetric rendering into a PBR pipeline or CUDA-based renderer where texture-based shading is preferred [S1].
*   Use the **VolPack API** when working with legacy VolPack data or specific SDK constraints [S2].
*   Use the **VRDF SDK Setup** when processing VRDF-formatted volumes with labelmaps or weight textures [S4, unofficial].
*   Avoid the **Programmable Path** if performance is critical and simple density/color modulation is sufficient; stick to the **Fast Path** [S3].

## Background

### Origin
*   **Material Object:** Originated in CUDA-based ray marching frameworks for distance fields and volumes, designed to bridge the gap between SDF rendering and volumetric shading [S1].
*   **VolPack API:** Developed by Stanford University as part of the VolPack library for interactive volume rendering [S2].
*   **Standard Volume Material:** Developed by Maxon (Cinema 4D/Redshift) as part of their volumetric rendering toolkit, integrating VDB grid support with artistic controls [S3].
*   **VRDF SDK:** Developed by Guillaume Schneider as an open-source SDK for volume rendering, focusing on labelmap and transfer function handling [S4, unofficial].

### History and Development
*   VolPack was one of the earliest libraries to provide a standardized API for volume rendering, influencing later SDKs [S2].
*   The Material Object format evolved from surface PBR materials, adapting fields like `metalness` and `roughness` for volumetric scattering and absorption [S1].
*   The Standard Volume Material represents a modern approach, combining simulation data (VDB) with artistic controls (nodes) in a single interface [S3].
