# Ray-marched Volumetric Fog

Also called: Forward ray-marching fog, Full-screen volumetric fog

## Overview
Ray-marched volumetric fog simulates light absorption, scattering, soft shadows, and light shafts by treating fog as a 3D volume of participating media traced via forward ray-marching from the camera to the scene [S1, unofficial]. It differs from backward ray-marching by allowing early-out optimizations when transmittance becomes negligible [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Camera position, per-pixel UV coordinates, depth buffer, light position and intensity, fog density ($\tau$), scattering coefficient ($a$), and phase function parameters [S1, unofficial].
- **Outputs:** Final pixel radiance ($L$) [S1, unofficial].

**Data Structures:**
- **Depth Buffer:** 2D texture storing depth values $z$ for each pixel UV coordinate [S1, unofficial].
- **Ray:** Defined by origin (camera position) and direction (computed from UV and depth) [S1, unofficial].
- **Accumulators:** Floating-point variables for accumulated radiance and cumulative transmittance [G].

**Numbered Steps:**
1. **Ray Initialization:** For each pixel, reconstruct the 3D world position of the scene intersection by sampling the depth buffer at the current UV coordinate [S1, unofficial]. Define the ray origin as the camera position and the ray direction as the normalized vector from the camera to the reconstructed intersection point [G].
2. **Ray Clamping:** Clamp the maximum ray distance to a predefined `zfar` value to prevent infinite marching when the ray misses scene geometry [S1, unofficial].
3. **Jittering:** Add a pseudo-random delta step to the ray's starting position to fix slice artifacts caused by aligned samples [S1, unofficial].
4. **Ray Marching Loop:** Iterate from the camera (start) to the scene intersection (finish) at regular intervals $\Delta l$ [S1, unofficial].
    - Calculate the current sample position $x(l_n)$ along the ray.
    - Calculate the distance $l_n$ traveled from the camera to the current sample.
    - Calculate the in-scattering term $L_i(x(l_n), \omega)$ for the current sample.
    - Accumulate the contribution: $L \leftarrow L + L_i(x(l_n), \omega) \cdot e^{-\tau l_n} \cdot \Delta l$ [S1, unofficial].
    - Update cumulative transmittance: $T \leftarrow T \cdot e^{-\tau \Delta l}$.
    - Early-out: If cumulative transmittance drops below a threshold, break the loop [S1, unofficial].
5. **Final Composition:** Combine the accumulated fog radiance with the background scene color using the final transmittance [G].

**Formulas:**
The total radiance $L$ is approximated using the Riemann sum method [S1, unofficial]:
$$ L = \sum_{n=0}^{N} L_i(x(l_n), \omega) e^{-\tau l_n} \Delta l $$
Where:
- $L$: Calculated radiance.
- $N$: Total number of steps.
- $L_i(x(l_n), \omega)$: In-scattering term at step $n$.
- $e^{-\tau l_n}$: Transmittance for distance $l_n$ traveled from the camera.
- $\Delta l$: Ray-march step size.

The in-scattering term $L_i(x, \omega)$ for a point light source is [S1, unofficial]:
$$ L_i(x, \omega) = \frac{a \Phi}{4\pi d^2} v(x) e^{-\tau d} P(\omega, \omega') $$
Where:
- $\tau$: Fog density (thickness).
- $a$: Scattering coefficient (probability of photon scattering).
- $\Phi$: Point light intensity.
- $d$: Distance between the sample point $x$ and the light source.
- $v(x)$: Visibility of the sample point from the light source (1 if no shadow mapping, or sampled from a light's cube shadow map) [S1, unofficial].
- $e^{-\tau d}$: Transmittance from the sample point to the light source.
- $P(\omega, \omega')$: Phase function describing the probability density of scattering direction.

**Parameters:**
- **Density ($\tau$):** Constant for uniform fog. Can be procedurally generated, sampled from a texture, or from OpenVDB for non-uniform fog [S1, unofficial].
- **Visibility ($v(x)$):** Set to 1 in basic implementations. Can be sampled from a light's cube shadow map if available [S1, unofficial].
- **Phase Function ($P$):** Uses the Schlick phase function approximation of the Henyey-Greenstein (HG) function for real-time performance, as the original HG function is expensive [S1, unofficial].
- **Step Size ($\Delta l$):** Determines the resolution of the ray march. Smaller steps reduce artifacts but increase computation [S1, unofficial].

**Pitfalls:**
- **Slice Artifacts:** Occur when marching rays with the same step size starting at the same point, causing samples to align on the same "slices" [S1, unofficial].
- **Noise:** Jittering samples reduces slice artifacts but can introduce noise, especially at larger step sizes [S1, unofficial].
- **Banding:** Visible in the distance even with jittering; further jittering of every sample on a ray can mitigate this [S1, unofficial].

**Pseudocode:**
```python
def ray_marched_volumetric_fog(camera_pos, uv, depth_buffer, light_pos, light_intensity, fog_density, scattering_coeff, step_size, zfar, jitter_seed):
    # Reconstruct scene intersection from depth buffer
    depth = depth_buffer[uv]
    scene_pos = inverse_projection(uv, depth) # Standard inverse projection step [G]
    
    # Ray direction and length
    ray_dir = normalize(scene_pos - camera_pos)
    ray_length = length(scene_pos - camera_pos)
    if ray_length > zfar:
        ray_length = zfar
        
    # Jitter start position to fix slice artifacts
    jitter = pseudo_random(jitter_seed) * step_size
    current_pos = camera_pos + ray_dir * jitter
    current_dist = jitter
    
    accumulated_radiance = vec3(0.0)
    transmittance = 1.0
    
    # March from camera to scene
    while current_dist < ray_length:
        # Distance from sample to light
        dist_to_light = length(current_pos - light_pos)
        
        # Visibility (1 if no shadow map)
        visibility = 1.0 
        
        # Phase function (Schlick approximation of HG)
        phase = schlick_phase_function(ray_dir, normalize(light_pos - current_pos))
        
        # In-scattering term: L_i = (a * Phi / (4 * pi * d^2)) * v(x) * e^(-tau * d) * P
        in_scattering = (scattering_coeff * light_intensity / (4.0 * 3.14159 * dist_to_light * dist_to_light)) * visibility * exp(-fog_density * dist_to_light) * phase
        
        # Transmittance from camera to current sample
        camera_transmittance = exp(-fog_density * current_dist)
        
        # Accumulate radiance: L += L_i * T_camera * delta_l
        accumulated_radiance += in_scattering * camera_transmittance * step_size
        
        # Update transmittance for next step
        transmittance *= exp(-fog_density * step_size)
        
        # Early-out optimization
        if transmittance < 0.01:
            break
            
        # Move to next step
        current_dist += step_size
        current_pos = camera_pos + ray_dir * current_dist
        
    return accumulated_radiance

def pseudo_random(seed):
    # Deterministic hash for jitter [G]
    return fract(sin(seed * 12.9898) * 43758.5453)

def schlick_phase_function(view_dir, light_dir, g=0.7):
    # Schlick approximation of Henyey-Greenstein [G]
    cos_theta = dot(view_dir, light_dir)
    g_sq = g * g
    return (1.0 - g_sq) / (1.0 + g_sq - 2.0 * g * cos_theta)

def inverse_projection(uv, depth):
    # Standard reconstruction of world position from UV and depth [G]
    # Assumes normalized device coordinates and linear depth for simplicity
    return camera_pos + ray_dir * depth
```

## Operating characteristics
- **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the number of steps per ray [G].
- **Memory Complexity:** $O(1)$ per pixel, plus storage for depth buffer and light shadow maps if used [G].
- **Performance:** Real-time performance is achievable with Schlick phase function approximation and early-out optimizations [S1, unofficial]. Step size significantly impacts performance and visual quality [S1, unofficial].
- **Strengths:** Simple implementation, dynamic interaction with scene geometry and lights, early-out optimization [S1, unofficial].
- **Limitations:** Slice artifacts, noise with jittering, performance cost with large step counts or high resolutions [S1, unofficial].
- **When to Use:** Real-time fog effects in games or applications where dynamic lighting interaction is required [S1, unofficial].
- **When Not to Use:** When high-fidelity, artifact-free volumetric rendering is required without post-processing, or when performance is extremely constrained [G].

## Background
Ray-marched volumetric fog is used in games like *Horizon Zero Dawn*, *Death Stranding*, and *Returnal* to simulate dynamic fog interacting with world light and geometry [S1, unofficial]. The technique is based on the principles of participating media and ray-marching, as described in the paper "Real-time Volumetric Lighting in Participating Media" by Toth and Umenhofer [S1, unofficial].
