# Ray Marching Volume Rendering with Geometry Occlusion

Also called: GPU Ray Marching

## Overview
A front-to-back ray marching technique that renders a 3D volume texture by stepping along rays from the camera, compositing color and opacity, and using pre-rendered opaque geometry to occlude the volume and adjust sampling rates [S1, unofficial]. It solves the problem of self-occlusion in volume rendering without requiring full volumetric integration or multiple rendering passes, making it suitable for real-time applications where geometry occlusion is already handled by the parent method [S1, unofficial]. Unlike standard front-to-back ray casting which integrates opacity along the ray, this method decouples the occlusion estimation from the ray step, using spatial averaging of a pre-rendered occlusion texture to modulate the current slice's contribution [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `volume_dims`: Dimensions of the 3D volume texture (`ivec3`) [S1, unofficial].
    *   `dt_scale`: Scalar multiplier for base step size [S1, unofficial].
    *   `transformed_eye`: Camera position in world space [S1, unofficial].
    *   `pos`: World-space position of the current fragment (derived from screen coordinates and projection matrices) [S1, unofficial].
    *   `volume_texture`: 3D texture containing density/scalar values [S1, unofficial].
    *   `colormap`: 2D texture (`gl.SRGB8_ALPHA8`, size 180x1) mapping scalar values to RGBA colors [S1, unofficial].
    *   `depth_buffer`: Pre-rendered depth buffer of opaque geometry (`gl.DEPTH_COMPONENT32F`) [S1, unofficial].
*   **Outputs:**
    *   Final composited RGBA color for the pixel [S1, unofficial].

**Data Structures:**
*   **Render Targets:** Two textures created via `gl.texStorage2D` [S1, unofficial].
    *   Target 0: `gl.RGBA8` format, size `WIDTH x HEIGHT`.
    *   Target 1: `gl.DEPTH_COMPONENT32F` format, size `WIDTH x HEIGHT`.
*   **Framebuffers:**
    *   `depthColorFbo`: Attaches Target 0 to `COLOR_ATTACHMENT0` and Target 1 to `DEPTH_ATTACHMENT` [S1, unofficial].
    *   `colorFbo`: Attaches Target 0 to `COLOR_ATTACHMENT0` only [S1, unofficial].

**Algorithm Steps:**

1.  **Calculate Ray Direction:**
    Compute the ray direction vector in the vertex shader:
    $$ \text{vray\_dir} = \text{pos} - \text{transformed\_eye} $$
    Normalize the direction in the fragment shader [S1, unofficial].

2.  **Ray-Box Intersection:**
    Intersect the ray with the unit box $[0,1]^3$ using the slab method to determine entry ($t_{hit.x}$) and exit ($t_{hit.y}$) distances [S1, unofficial].
    $$ t_{min} = \frac{\text{box}_{min} - \text{orig}}{\text{dir}} $$
    $$ t_{max} = \frac{\text{box}_{max} - \text{orig}}{\text{dir}} $$
    $$ t_0 = \max(t_{min}.x, t_{min}.y, t_{min}.z) $$
    $$ t_1 = \min(t_{max}.x, t_{max}.y, t_{max}.z) $$
    If $t_{hit.x} > t_{hit.y}$, discard the pixel [S1, unofficial].

3.  **Calculate Base Step Size:**
    Compute the base step size $dt$ based on volume dimensions and ray direction magnitude [S1, unofficial]:
    $$ dt = dt\_scale \times \min\left(\frac{1.0}{\text{volume\_dims} \times |\text{ray\_dir}|}\right) $$
    *Note: The source code snippet implies `volume_dims` is used as a divisor, likely representing the inverse resolution or a scaling factor relative to the unit box.* [S1, unofficial].

4.  **Add Jitter Offset:**
    Add a jitter offset to the entry point $t_{hit.x}$ to reduce banding artifacts. The offset is calculated using a hash function (e.g., `wang_hash`) based on pixel coordinates or a random seed [S1, unofficial].
    $$ t_{hit.x} \leftarrow t_{hit.x} + \text{offset} $$

5.  **Check for Geometry Occlusion:**
    Sample the pre-rendered depth buffer $z$ at the current pixel [S1, unofficial].
    *   If $z \ge 1.0$, no opaque geometry is present. The ray marches through the entire box from $t_{hit.x}$ to $t_{hit.y}$.
    *   If $z < 1.0$, geometry is present. Reconstruct the geometry's world-space position from the depth value $z$ and the inverse projection/view matrices. Calculate the distance $t_{geom}$ along the ray to the geometry surface [S1, unofficial].
    *   Adjust the exit point: $t_{hit.y} = \min(t_{hit.y}, t_{geom})$.
    *   Adjust the step size $dt$ if necessary to ensure the final sample aligns with the geometry surface [S1, unofficial].

6.  **Ray Marching Loop:**
    Iterate from $t = t_{hit.x}$ to $t = t_{hit.y}$ with step $dt$:
    a.  **Sample Volume:** Sample the 3D volume texture at the current ray position $\text{orig} + t \times \text{dir}$ to get scalar value $s$ [S1, unofficial].
    b.  **Lookup Color:** Use $s$ to index into the `colormap` texture to get sample color $C_{sample}$ and opacity $a_{sample}$ [S1, unofficial].
    c.  **Opacity Correction:** Apply opacity correction to account for step size variations [S1, unofficial]:
        $$ a_{corrected} = 1.0 - (1.0 - a_{sample})^{dt_{correction}} $$
        Where $dt_{correction}$ scales the sample opacity based on step size relative to a reference [S1, unofficial].
    d.  **Front-to-Back Compositing:** Accumulate color and alpha [S1, unofficial]:
        $$ C_{out} = C_{in} + (1.0 - C_{in}.a) \times C_{sample}.a \times C_{sample}.rgb $$
        $$ A_{out} = A_{in} + (1.0 - A_{in}.a) \times C_{sample}.a $$
    e.  **Early Exit:** If $C_{out}.a \ge 0.99$, break the loop [S1, unofficial].

7.  **Final Composition with Geometry:**
    If geometry was present ($z < 1.0$), take a final sample at $t_{hit.y}$ (the geometry surface) and composite it. The code composites volume data at the surface location, implying the geometry acts as an occluder for the volume march, or the volume data at the surface is used to color the geometry [S1, unofficial].

## Subtopics

### [Direct Volume Rendering with Precomputed Occlusion (DOS)](4566-direct-volume-rendering-with-precomputed-occlusion-dos.md)
Direct Volume Rendering with Precomputed Occlusion (DOS) is a single-pass, image-order ray marching technique that approximates volumetric attenuation from behind the current sample using precomputed 2D occlusion maps. It solves the problem of self-occlusion in volume rendering without requiring full volumetric integration or multiple rendering passes, making it suitable for real-time applications where geometry occlusion is already handled by the parent method. Unlike standard front-to-back ray casting which integrates opacity along the ray, DOS decouples the occlusion estimation from the ray step, using spatial averaging of a pre-rendered occlusion texture to modulate the current slice's contribution.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples along the ray, which depends on the ray length through the volume and the step size $dt$. Step size is inversely proportional to volume dimensions and ray direction magnitude.
*   **Memory Complexity:** Depends on the size of the 3D volume texture, 2D colormap, and depth buffer.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Performance scales with volume resolution and camera distance (ray length).
*   **Strengths:** Real-time capable, handles geometry occlusion efficiently by stopping ray march, simple implementation.
*   **Limitations:** Approximate self-occlusion handling (geometry only, not volumetric), step size artifacts if not corrected, requires pre-rendered depth buffer.
*   **When to use:** Real-time applications with opaque geometry occluding volumes, where full volumetric self-occlusion is too expensive.
*   **When not to use:** Scenes with complex volumetric self-occlusion where geometry occlusion is not the primary factor, or when high accuracy is required.
