# Direct Volume Rendering with Precomputed Occlusion (DOS)

Also called: Direct Volume Rendering with Occlusion

## Overview
Direct Volume Rendering with Precomputed Occlusion (DOS) is a single-pass, image-order ray marching technique that approximates volumetric attenuation from behind the current sample using precomputed 2D occlusion maps [S1, unofficial]. It solves the problem of self-occlusion in volume rendering without requiring full volumetric integration or multiple rendering passes, making it suitable for real-time applications where geometry occlusion is already handled by the parent method [S1, unofficial]. Unlike standard front-to-back ray casting which integrates opacity along the ray, DOS decouples the occlusion estimation from the ray step, using spatial averaging of a pre-rendered occlusion texture to modulate the current slice's contribution [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
- `uVolume`: A 3D texture (`sampler3D`) storing volume density or scalar values.
- `uTransferFunction`: A 1D or 2D texture (`sampler2D`) mapping volume values to RGBA color and opacity.
- `uColor`: A 2D texture (`sampler2D`) storing the accumulated color and alpha from previous slices or frames.
- `uOcclusion`: A 2D texture (`sampler2D`) storing precomputed occlusion values (typically red channel).
- `uOcclusionSamples`: A 2D texture (`sampler2D`) storing 2D offset vectors used to sample the occlusion map.
- `uExtinction`: A float constant representing the extinction coefficient.
- `uSliceDistance`: A float constant representing the step size along the ray for the current pass.
- `uOcclusionScale`: A vec2 constant scaling the occlusion sample offsets.
- `uOcclusionSamplesCount`: A uint constant specifying the number of samples taken from the occlusion map.

**Outputs:**
- `oColor`: A `vec4` output at location 0, storing the accumulated color and alpha.
- `oOcclusion`: A `float` output at location 1, storing the updated occlusion value for the current pixel.

### Data Structures
The method relies on two render targets (framebuffers) bound to the fragment shader outputs:
1.  **Color Buffer**: `vec4` per pixel, initialized to `(0, 0, 0, 0)`.
2.  **Occlusion Buffer**: `float` per pixel, initialized to `1.0`.

The vertex shader renders a full-screen triangle using hardcoded vertices `(-1, -1)`, `(3, -1)`, and `(-1, 3)` [S1, unofficial]. This ensures that the fragment shader processes every pixel in the viewport. The vertex shader passes a normalized 2D position `vPosition2D` (in `[0, 1]` range) and the corresponding 3D world position `vPosition3D` to the fragment shader [S1, unofficial].

### Algorithm Steps
1.  **Initialization**: A reset shader clears the output buffers. `oColor` is set to `vec4(0)` and `oOcclusion` is set to `1.0` [S1, unofficial].
2.  **Boundary Check**: In the main shader, check if `vPosition3D` is outside the volume bounds `[0, 1]`. If `any(greaterThan(vPosition3D, vec3(1))) || any(lessThan(vPosition3D, vec3(0)))`, output the previous color and occlusion unchanged and terminate [S1, unofficial].
3.  **Volume Sampling**: Sample the volume value at `vPosition3D` using `uVolume`. Map this value through `uTransferFunction` to get `transferSample` (a `vec4` with RGB color and alpha) [S1, unofficial].
4.  **Extinction Calculation**: Calculate the extinction for the current step:
    $$ extinction = transferSample.a \times uExtinction $$
5.  **Alpha Contribution**: Calculate the alpha contribution for the current slice:
    $$ \alpha = 1.0 - \exp(-extinction \times uSliceDistance) $$
6.  **Occlusion Update**: Calculate the new occlusion value by sampling `uOcclusion` at multiple offsets defined in `uOcclusionSamples`. Average these samples and multiply by the exponential attenuation of the current slice:
    $$ oOcclusion = \left( \frac{1}{N} \sum_{i=0}^{N-1} texture(uOcclusion, vPosition2D + offset_i \times scale).r \right) \times \exp(-extinction \times uSliceDistance) $$
    where $N = uOcclusionSamplesCount$ and $offset_i$ is the $i$-th offset vector from `uOcclusionSamples` scaled by `uOcclusionScale` [S1, unofficial].
7.  **Color Blending**: Calculate the color contribution using the previous occlusion value (`prevOcclusion`, sampled from `uOcclusion` at `vPosition2D`):
    $$ color = transferSample.rgb \times prevOcclusion \times \alpha $$
    Update the output color using front-to-back blending:
    $$ oColor.rgb = prevColor.rgb + color \times (1.0 - prevColor.a) $$
    $$ oColor.a = \min(prevColor.a + \alpha, 1.0) $$
    where `prevColor` is sampled from `uColor` at `vPosition2D` [S1, unofficial].
8.  **Final Composite**: After all slices are processed, a final composite shader mixes the accumulated color with a white background:
    $$ oColor = mix(vec4(1), vec4(color.rgb, 1), color.a) $$
    [S1, unofficial].

        prev_occlusion = texture(uOcclusion, vPosition2D).r
        oColor = prev_color
        oOcclusion = prev_occlusion
        return

    # Step 3: Volume Sampling
    volume_value = texture(uVolume, vPosition3D).r
    transfer_sample = texture(uTransferFunction, vec2(volume_value, 0.5)) # Assuming 1D TF mapped to 2D
    
    # Step 4: Extinction Calculation
    extinction = transfer_sample.a * uExtinction
    
    # Step 5: Alpha Contribution
    alpha = 1.0 - exp(-extinction * uSliceDistance)
    
    # Step 6: Occlusion Update
    # Sample occlusion at multiple offsets
    occlusion_sum = 0.0
    for i in range(uOcclusionSamplesCount):
        # Get offset from uOcclusionSamples texture
        # Note: In practice, offsets might be stored in a uniform array or texture
        # Here we assume a helper to retrieve the i-th offset
        offset = get_offset(i, uOcclusionSamples, uOcclusionScale)
        sample_pos = vPosition2D + offset
        # Clamp sample_pos to [0,1] if necessary
        occlusion_sum += texture(uOcclusion, sample_pos).r
    
    avg_occlusion = occlusion_sum / uOcclusionSamplesCount
    oOcclusion = avg_occlusion * exp(-extinction * uSliceDistance)
    
    # Step 7: Color Blending
    prev_color = texture(uColor, vPosition2D)
    prev_occlusion = texture(uOcclusion, vPosition2D).r
    
    color_contribution = transfer_sample.rgb * prev_occlusion * alpha
    
    oColor.rgb = prev_color.rgb + color_contribution * (1.0 - prev_color.a)
    oColor.a = min(prev_color.a + alpha, 1.0)

# Final Composite Shader
def final_composite(color):

### Parameters
- `uExtinction`: Float constant, typical value depends on volume density scale.
- `uSliceDistance`: Float constant, step size along the ray.
- `uOcclusionScale`: Vec2 constant, scales the occlusion sample offsets.
- `uOcclusionSamplesCount`: Uint constant, number of occlusion samples.

### Edge Cases and Pitfalls
- **Boundary Conditions**: The method explicitly checks for volume bounds `[0, 1]` to avoid sampling outside the volume texture [S1, unofficial].
- **Precision**: The use of `exp()` and floating-point accumulation can lead to precision issues in high-density volumes.
- **Occlusion Map Quality**: The accuracy of the occlusion approximation depends on the resolution and precomputation of the `uOcclusion` texture.

## Operating characteristics
- **Time Complexity**: $O(N \times M)$, where $N$ is the number of slices and $M$ is the number of occlusion samples per slice. The single-pass nature per slice makes it efficient compared to multi-pass volumetric integration.
- **Memory Complexity**: $O(W \times H)$ for the color and occlusion buffers, where $W$ and $H$ are the screen dimensions.
- **Performance**: Suitable for real-time rendering due to its single-pass design and avoidance of complex volumetric integration. Performance is limited by the number of occlusion samples and the resolution of the volume texture.
- **Strengths**: Real-time capability, simplicity of implementation, effective approximation of self-occlusion.
- **Limitations**: Approximation of occlusion may lead to artifacts in complex volumes; dependent on the quality of precomputed occlusion maps.

## Background
Direct Volume Rendering with Precomputed Occlusion (DOS) is an unofficial technique described in the `terier/vpt` repository [S1, unofficial]. It builds upon the principles of ray marching volume rendering and geometry occlusion to provide a real-time solution for volumetric visualization. The method is particularly useful in applications where performance is critical, such as medical imaging or scientific visualization, where interactive frame rates are required.
