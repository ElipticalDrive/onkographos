# Runge-Kutta 4 (RK4) Integration

Also called: Fourth-order Runge-Kutta, Runge-Kutta 4 Integrator

## Overview
Runge-Kutta 4 (RK4) is a higher-order numerical integration technique for volume rendering that queries a vector field at four distinct positions to compute a single ray-marching step, significantly reducing trajectory error compared to the zero-order [Zero Order Integration (Rectangle Rule)](2082-zero-order-integration-rectangle-rule.md) or first-order Euler methods [S1, S2, unofficial]. It solves the initial value problem for a point in an unsteady vector field by taking four samples in the neighborhood of the current point and calculating the next position using a weighted sum [S2, unofficial]. It is chosen when accurate streamline visualization is required, trading approximately 4 times the computation of Euler for an order-of-magnitude reduction in local truncation error [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Current position $x_n$ (3D vector), step size $dt$ (scalar, also denoted $\delta$), vector field function $v(x, t)$ returning a 3D vector at position $x$ and time $t$ [S1, S2, unofficial].
*   **Output:** Next position $x_{n+1}$ (3D vector) [S1, unofficial].

**Data Structures:**
*   $x_n$: Current position coordinates $(x, y, z)$ [S1, unofficial].
*   $k_i$: Intermediate slope vectors $(k_{ix}, k_{iy}, k_{iz})$ representing displacement increments [S1, unofficial].
*   $dt$: Step size scalar [S1, unofficial].

**Formulas:**
The method computes four slope estimates $k_1, k_2, k_3, k_4$ and combines them into a weighted average step:

$$
\begin{aligned}
k_1 &= dt \cdot v(x_n) \\
k_2 &= dt \cdot v\left(x_n + \frac{k_1}{2}\right) \\
k_3 &= dt \cdot v\left(x_n + \frac{k_2}{2}\right) \\
k_4 &= dt \cdot v(x_n + k_3) \\
x_{n+1} &= x_n + \frac{1}{6}k_1 + \frac{1}{3}k_2 + \frac{1}{3}k_3 + \frac{1}{6}k_4 + O(dt^5)
\end{aligned}
$$

Where:
*   $x_n$ is the current position [S1, unofficial].
*   $x_{n+1}$ is the next position [S1, unofficial].
*   $dt$ is the time step (step size) [S1, unofficial].
*   $v(x)$ is the vector field value at position $x$ [S1, unofficial].
*   $O(dt^5)$ represents the local truncation error term [S1, unofficial].

**Parameters:**
*   **Step size ($dt$ or $\delta$):** Determines the distance advanced per step [S2, unofficial]. In real-time applications, this is often dynamic to maintain frame rate [S2, unofficial].
*   **Time ($t_{func}$):** Required for unsteady (time-varying) vector fields. Must be synchronized with the application's time step [S2, unofficial]. For steady fields, this argument is ignored or fixed [S2, unofficial].

**Pseudocode:**
```python
def rk4_integrate(pos, dt, vector_field_func, time_val=None):
    # 1. Sample k1 at current position
    v1 = vector_field_func(pos, time_val)
    k1 = (dt * v1.x, dt * v1.y, dt * v1.z)

    # 2. Sample k2 at pos + k1/2
    mid1 = (pos.x + k1[0] * 0.5, pos.y + k1[1] * 0.5, pos.z + k1[2] * 0.5)
    v2 = vector_field_func(mid1, time_val)
    k2 = (dt * v2.x, dt * v2.y, dt * v2.z)

    # 3. Sample k3 at pos + k2/2
    mid2 = (pos.x + k2[0] * 0.5, pos.y + k2[1] * 0.5, pos.z + k2[2] * 0.5)
    v3 = vector_field_func(mid2, time_val)
    k3 = (dt * v3.x, dt * v3.y, dt * v3.z)

    # 4. Sample k4 at pos + k3
    end = (pos.x + k3[0], pos.y + k3[1], pos.z + k3[2])
    v4 = vector_field_func(end, time_val)
    k4 = (dt * v4.x, dt * v4.y, dt * v4.z)

    # 5. Compute weighted sum: x_{n+1} = x_n + k1/6 + k2/3 + k3/3 + k4/6
    dt_sixth = dt / 6.0
    next_x = pos.x + dt_sixth * (k1[0] + 2.0 * k2[0] + 2.0 * k3[0] + k4[0])
    next_y = pos.y + dt_sixth * (k1[1] + 2.0 * k2[1] + 2.0 * k3[1] + k4[1])
    next_z = pos.z + dt_sixth * (k1[2] + 2.0 * k2[2] + 2.0 * k3[2] + k4[2])
    return (next_x, next_y, next_z)
```

**Edge Cases and Pitfalls:**
*   **Steady Fields:** No special implementation is needed; simply ignore the time argument or pass a fixed value [S2, unofficial].
*   **Precision:** RK4 has a local error of $O(dt^5)$, whereas Euler has $O(dt^2)$ local error [S1, unofficial].
*   **Vortices:** Euler integration tends to escape vortices even at low step sizes, whereas RK4 often converges toward the vortex center or follows the streamline more accurately [S1, unofficial].

## Subtopics

### Euler Integration
A first-order vector field integrator that computes the next step using only the current position and vector field value ($x_{n+1} = x_n + dt \cdot v(x_n)$) [S1, unofficial]. It has a local error of $O(dt^2)$ and is significantly faster but less accurate than RK4 [S1, unofficial]. It is suitable for quick previews or when computational resources are extremely limited, but it tends to escape vortices and accumulates error quickly [S1, unofficial].

### Runge-Kutta 2/3 ODE Solver
A 2nd/3rd order Runge-Kutta method for solving ODEs with adaptive step size control [S3, unofficial]. It estimates error using embedded formulas and adjusts the step size $h$ based on relative ($rtol$) and absolute ($atol$) tolerances [S3, unofficial]. Typical parameters are $rtol=10^{-2}$, $atol=10^{-4}$, and $h_{max}=0.1 \cdot t_{span}$ [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** RK4 requires four vector field evaluations per step, making it approximately 4 times slower than Euler integration [S1, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary memory per step (storing $k_1, k_2, k_3, k_4$) [G].
*   **Accuracy:** RK4 error is smaller by an order of magnitude compared to Euler. For example, RK4 with $dt=1$ can have less error than Euler with $dt=0.5$ [S1, unofficial].
*   **Strengths:** High accuracy for a fixed step size; robust handling of vortices; simple implementation [S1, unofficial].
*   **Limitations:** Fixed step size (unless combined with adaptive logic) [G]; higher computational cost than Euler; potential instability if $dt$ is too large for the field's curvature [G].
*   **When to use:** When visual fidelity of streamlines is critical and real-time performance allows for 4 times the cost of Euler [S1, unofficial].
*   **When not to use:** When extreme performance is required and approximate trajectories are acceptable (use Euler) [S1, unofficial].

## Background
The method was implemented as a standard improvement over Euler integration to reduce trajectory errors without the complexity of adaptive solvers [S1, unofficial]. It is used in real-time smoke volume rendering and vector field visualization, where the step size is dynamically adjusted to maintain real-time behavior [S2, unofficial].
