# Volume Raycasting Discretization

Also called: Volume ray marching, Front-to-Back Blending, Front-to-back Ray Casting, Discrete Volume Rendering Integral

## Overview
Volume Raycasting Discretization is a direct volume rendering technique that approximates the volume rendering integral by sampling a 3D scalar field at fixed intervals along rays cast from the camera [S1][S2, S4, unofficial]. It solves the problem of mapping volumetric data to a 2D image plane by performing front-to-back alpha compositing of sampled color and opacity values [S1][S2, S4, unofficial]. It is distinguished from its siblings by its explicit discretization of the continuous rendering integral into a fixed-step summation [S7, S9, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume texture (scalar field), camera parameters (origin, direction, screen dimensions), a transfer function mapping scalar values to color and opacity, a fixed step size $\Delta x$, and an early termination threshold $\alpha_{thresh}$ (typically 0.95 to 0.99) [S1][S2, S3, S4, unofficial].
*   **Output:** A 2D image where each pixel contains the accumulated color and opacity [S1][S2, unofficial].

**Data Structures:**
*   **Volume Data:** A 3D scalar field stored as a 1D array or 3D texture, typically accessed via row-major indexing or texture sampling [S3, S6, unofficial]. The layout for dimensions $dim.x \times dim.y \times dim.z$ uses stride $x \cdot (dim.y \cdot dim.z) + y \cdot dim.z + z$ [S3, unofficial].
*   **Ray Structure:** Defined by an origin point $\bar{O}$ and a direction vector $\bar{D}$ [S2, unofficial].
*   **Accumulators:** Per-pixel variables for accumulated color $C'$ (vector) and accumulated opacity $\alpha'$ (scalar), initialized to zero [S1][S2, unofficial].
*   **Transfer Function:** Maps scalar values to color and opacity, often implemented as a 1D texture or lookup table [S4, unofficial].
*   **Step Size ($\Delta x$):** The fixed distance between consecutive samples along the ray [S2, S7, unofficial]. Default is 0.001 [S2, unofficial].

**Numbered Steps:**
1.  **Initialization:** Initialize the output image with a black background (color $\{0,0,0\}$, opacity 0) [S1][S2, unofficial].
2.  **Ray Casting Loop:** Iterate over each pixel $(i, j)$ on the image plane [S1][S3, unofficial].
3.  **Ray Generation:** Compute the ray origin and direction for the current pixel based on camera parameters [S1][S4, unofficial].
4.  **Ray Initialization:** Compute the ray's entry and exit parameters ($t_{start}$, $t_{end}$) relative to the volume bounding box. Set accumulated color $C' = \{0,0,0\}$ and accumulated opacity $\alpha' = 0$ [G].
5.  **Sampling Loop:** While $\alpha' < \alpha_{thresh}$ and $t \le t_{end}$:
    a.  **Sample Volume:** Evaluate the scalar value $d$ at the current ray position $\bar{P} = \bar{O} + t \cdot \bar{D}$ using trilinear interpolation from the 8 surrounding voxels [S1][S5, unofficial].
    b.  **Transfer Function:** Map the scalar value $d$ to a color $C_{sample}$ and opacity $\alpha_{sample}$ using the transfer function [S2, S5, unofficial].
    c.  **Compositing:** Update the accumulated color and opacity using the front-to-back alpha compositing equations [S1][S2, S7, unofficial]:
        $$ C'_{new} = C'_{old} + (1 - \alpha'_{old}) \cdot \alpha_{sample} \cdot C_{sample} $$
        $$ \alpha'_{new} = \alpha'_{old} + (1 - \alpha'_{old}) \cdot \alpha_{sample} $$
    d.  **Advance Ray:** Increment $t$ by the step size $\Delta x$ [S2, S7, unofficial].
6.  **Final Color:** The final pixel color is the accumulated color $C'$ [S2, S7, unofficial].

**Pseudocode:**
```python
import random

def volume_raycasting_discretization(volume_data, volume_dims, camera, transfer_function, step_size=0.001, threshold=0.99):
    """
    Renders a volume using fixed-step raycasting with front-to-back compositing.
    volume_data: list of scalars in row-major order
    volume_dims: (dim_x, dim_y, dim_z)
    camera: object with .screen_height, .screen_width, and .cast_ray((x, y)) -> (origin, direction)
    transfer_function: callable(scalar) -> (color_vec3, opacity_float)
    """
    h, w = camera.screen_height, camera.screen_width
    image = [[(0.0, 0.0, 0.0) for _ in range(w)] for _ in range(h)]
    dim_x, dim_y, dim_z = volume_dims
    stride_y = dim_z
    stride_x = dim_y * dim_z

    def trilinear_interpolation(data, dims, x, y, z):
        # Clamp coordinates to valid range [0, dim-1]
        x = max(0.0, min(float(dims[0] - 1), x))
        y = max(0.0, min(float(dims[1] - 1), y))
        z = max(0.0, min(float(dims[2] - 1), z))
        x0, y0, z0 = int(x), int(y), int(z)
        x1, y1, z1 = min(x0 + 1, dims[0] - 1), min(y0 + 1, dims[1] - 1), min(z0 + 1, dims[2] - 1)
        fx, fy, fz = x - x0, y - y0, z - z0
        def get_val(ix, iy, iz): return float(data[ix * stride_x + iy * stride_y + iz])
        c00 = get_val(x0, y0, z0) * (1-fx) + get_val(x1, y0, z0) * fx
        c10 = get_val(x0, y1, z0) * (1-fx) + get_val(x1, y1, z0) * fx
        c01 = get_val(x0, y0, z1) * (1-fx) + get_val(x1, y0, z1) * fx
        c11 = get_val(x0, y1, z1) * (1-fx) + get_val(x1, y1, z1) * fx
        c0 = c00 * (1-fy) + c10 * fy
        c1 = c01 * (1-fy) + c11 * fy
        return c0 * (1-fz) + c1 * fz

    def ray_box_intersection(ray_o, ray_d, dims):
        t_min, t_max = 0.0, float('inf')
        for i in range(3):
            if ray_d[i] == 0.0:
                if ray_o[i] < 0.0 or ray_o[i] >= dims[i]: return None, None
            else:
                t1 = (0.0 - ray_o[i]) / ray_d[i]
                t2 = (dims[i] - 1.0 - ray_o[i]) / ray_d[i]
                if t1 > t2: t1, t2 = t2, t1
                t_min = max(t_min, t1)
                t_max = min(t_max, t2)
        if t_min > t_max: return None, None
        return t_min, t_max

    for y in range(h):
        for x in range(w):
            ray_o, ray_d = camera.cast_ray((x, y))
            t_start, t_end = ray_box_intersection(ray_o, ray_d, volume_dims)
            if t_start is None: continue

            acc_color = [0.0, 0.0, 0.0]
            acc_opacity = 0.0
            # Fixed random offset to prevent banding [S3, unofficial]
            t = t_start + random.uniform(0.0, step_size)

            while acc_opacity < threshold and t <= t_end:
                pos = (ray_o[0] + t * ray_d[0], ray_o[1] + t * ray_d[1], ray_o[2] + t * ray_d[2])
                scalar = trilinear_interpolation(volume_data, volume_dims, pos[0], pos[1], pos[2])
                color_s, opacity_s = transfer_function(scalar)

                weight = (1.0 - acc_opacity) * opacity_s
                acc_color[0] += weight * color_s[0]
                acc_color[1] += weight * color_s[1]
                acc_color[2] += weight * color_s[2]
                acc_opacity += weight

                t += step_size

            image[y][x] = acc_color

    return image
```

**Parameters:**
*   **Step Size ($\Delta x$):** The distance between consecutive samples. Too large causes undersampling (aliasing, missed features); too small causes oversampling (performance loss) [S7, unofficial]. Default is 0.001 [S2, unofficial].
*   **Threshold ($\alpha_{thresh}$):** The opacity value at which the ray terminates. Commonly 0.95 or 0.99 [S1][S2, S3, unofficial].
*   **Transfer Function:** Maps scalar values to color and opacity. A simple example provided in [S1] uses normalized data range to compute RGB and alpha: $r = (v - DATA_{MIN}) / (DATA_{MAX} - DATA_{MIN})$, $\alpha = 0.9$ if $|r - 0.8| < 0.1$ else $0.01$, R: $(DATA_{MAX} - v) / (DATA_{MAX} - DATA_{MIN})$, G: $1 - |(DATA_{MAX} + DATA_{MIN})/2 - v| \times 2 / (DATA_{MAX} - DATA_{MIN})$, B: $(v - DATA_{MIN}) / (DATA_{MAX} - DATA_{MIN})$ [S1].

**Edge Cases and Pitfalls:**
*   **Boundary Artifacts:** Incorrect handling of the first and last sample points (entry/exit) can cause stepping artifacts or gaps at the volume boundaries [S4, S9, unofficial]. Strategies must accurately sample corner voxels to avoid missing corner samples, which causes intensities to drop to zero prematurely when the ray length is shorter than the step size [S9, unofficial].
*   **Undersampling/Oversampling:** Choosing an inappropriate step size leads to visual artifacts or poor performance [S7, unofficial].
*   **Ray Alignment:** If a ray does not hit a voxel center exactly, simple nearest-neighbor selection causes reconstruction errors; trilinear interpolation is required [S10, unofficial].
*   **Gradient Calculation:** Not given in the sources for this specific method's core algorithm.

## Subtopics

### [Eye Align](849-eye-align.md)
A sample placement strategy where the first sample point in the volume is calculated as seen from the eye, creating a sampling pattern across pixels that forms concentric lines. Chosen to align sampling with the view direction, potentially reducing aliasing in specific geometries.

### [Partial Pre-Integration](1148-partial-pre-integration.md)
A technique to improve ray integration approximation by using a 2D ψ table independent of the transfer function, allowing interactive transfer function changes without recomputing the table.

### [CPU Volume Raycasting](1258-cpu-volume-raycasting.md)
A fully CPU-based direct volume rendering technique that uses volume raycasting with multithreaded pixel processing, supporting RGB+transparency transfer functions and Phong lighting (ambient + diffuse), without pixel interpolation or gradient smoothing.

### [Average Intensity Projection](1310-average-intensity-projection.md)
A volume rendering technique that casts rays from the camera through the volume and accumulates voxel values along the ray path. Unlike standard front-to-back compositing, this method computes the arithmetic mean of the sampled values (weighted by opacity) to produce an Average Intensity Projection.

### [Differential Sampling](1549-differential-sampling.md)
A sampling method that respects the Nyquist frequency of the image plane by using ray distance as a sampling metric, addressing the fact that transformations from world-space to image-space convolve the volume rendering integral.

### [In-Scattering Integral Approximation via Riemann Sum](1585-in-scattering-integral-approximation-via-riemann-sum.md)
A technique to approximate the continuous influx of light energy scattered toward the eye (in-scattering) along a camera ray segment by discretizing the integral into a sum of small rectangular areas.

## Operating characteristics
*   **Time Complexity:** $O(P \cdot W)$, where $P$ is the number of pixels and $W$ is the number of evenly spaced sample locations along a ray [S1].
*   **Memory Complexity:** $O(V)$ for the volume data, where $V$ is the number of voxels [S3, S6, unofficial].
*   **Performance:** Performance is highly dependent on the step size and volume density. Fixed step sizes do not adapt to density variations, risking aliasing or inefficiency [S7, S9, unofficial].
*   **Strengths:** Simple to implement and serves as a baseline for more complex methods [S1][S7, unofficial].
*   **Limitations:** Fixed step size does not adapt to density variations, risking aliasing or inefficiency [S7, S9, unofficial].
*   **When to Use:** Not given in the sources.
*   **When Not to Use:** Not given in the sources.

## Background
The method is derived from the continuous volume rendering integral by Lacroute using the rectangle rule for numerical integration [S10, unofficial]. The concepts were developed and evaluated in the Inviwo visualization framework, supported by grants from ELLIIT, SeRC, and VINNOVA [S9, unofficial].
