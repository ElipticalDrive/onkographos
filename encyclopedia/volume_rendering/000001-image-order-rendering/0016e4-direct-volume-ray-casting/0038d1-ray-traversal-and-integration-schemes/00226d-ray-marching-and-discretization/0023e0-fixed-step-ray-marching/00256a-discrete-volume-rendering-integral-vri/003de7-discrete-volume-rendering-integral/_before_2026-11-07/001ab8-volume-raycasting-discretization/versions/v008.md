# Volume Raycasting Discretization

Also called: Discrete Volume Rendering Integral, VRI, Discrete Volume Rendering Equation

## Overview
Volume Raycasting Discretization is a direct volume rendering technique that approximates the continuous Volume Rendering Integral (VRI) by tracing rays from an observer through a 3D data array, sampling at evenly spaced intervals, and compositing front-to-back [S1][S2, unofficial]. It solves the problem of projecting a 3D scalar field onto a 2D image plane by converting the continuous integrals (outer integral and inner transmittance integral) into discrete Riemann sums over $N$ points along the ray [S10, unofficial][S15]. Unlike [Classical Ray Tracing Integration](1334-classical-ray-tracing-integration.md), which may use adaptive step sizes or analytical solutions for specific functions, this method relies on fixed-step marching and zero-order approximation (constant opacity/color per segment) to balance computational efficiency with visual accuracy [S1][S9, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field (voxel grid) of dimensions $D_x \times D_y \times D_z$ [S3][S8, unofficial]; Camera parameters (eye position, view direction, up vector) [S4, unofficial]; Transfer function mapping scalar values to color $\hat{C}$ and opacity $\alpha$ [S1][S4, unofficial]; Step size $\Delta s$ [S4, unofficial][S11].
*   **Output:** A 2D image where each pixel $(u, v)$ contains the accumulated color $C(u)$ and opacity $\alpha(u)$ [S1][S3].

**Data Structures:**
*   **Volume Data:** Stored as a 1D array or 3D texture [S4, unofficial][S9, unofficial]. For CPU implementations, a common layout is row-major: `data[z * (width * height) + y * width + x]` [S9, unofficial]. For GPU, a 3D texture stores scalar values and optionally precomputed gradients [S4, unofficial].
*   **Transfer Function:** A 1D texture or lookup table mapping normalized scalar values to RGBA [S4, unofficial].
*   **Accumulators:** Per-pixel variables for accumulated color $C$ (RGB) and accumulated opacity $\alpha$ (float) [S1][S11].

**Numbered Steps:**

1.  **Initialize Image:** Set the background color to black (or transparent) and opacity to 0 for all pixels $(i, j)$ [S3].
2.  **Ray Generation:** For each pixel $(i, j)$, compute the ray origin $\mathbf{o}$ (eye position) and direction $\mathbf{d}$ based on the camera's projection matrix or view vectors [S4, unofficial].
3.  **Determine Bounds:** Calculate the entry point $s_{in}$ and exit point $s_{out}$ of the ray with the volume's bounding box (e.g., unit cube or voxel grid extents) [S1][S13, unofficial]. If the ray does not intersect the volume, skip to the next pixel [G].
4.  **Initialize Accumulators:** Set accumulated color $C = (0, 0, 0)$ and accumulated opacity $\alpha = 0$ [S1][S11].
5.  **Ray Marching Loop:** Iterate from sample index $k = 0$ to $N-1$, where $N = \lceil (s_{out} - s_{in}) / \Delta s \rceil$ is the number of samples along the ray segment $[s_{in}, s_{out}]$ [S11].
    *   **Sample Position:** Compute the current sample position $\mathbf{p}_k = \mathbf{o} + (s_{in} + k \cdot \Delta s) \mathbf{d}$ [S11].
    *   **Interpolation:** Sample the scalar value $v$ at $\mathbf{p}_k$ from the volume data using trilinear interpolation from the 8 surrounding voxels [S1][S15].
        *   Formula: $V_{xyz} = \sum_{i,j,k \in \{0,1\}} V_{ijk} (1-x_i)(1-y_j)(1-z_k)$, where $x,y,z$ are fractional distances to the voxel corners [S15].
    *   **Transfer Function:** Map $v$ to pre-multiplied color $\hat{C}_k$ and opacity $\alpha_k$ using the transfer function [S1][S4, unofficial].
    *   **Compositing:** Update accumulators using the front-to-back alpha compositing equations [S1][S11]:
        $$ \hat{C}_{\text{out}} = \hat{C}_{\text{in}} + \hat{C}_k (1 - \alpha_{\text{in}}) $$
        $$ \alpha_{\text{out}} = \alpha_{\text{in}} + \alpha_k (1 - \alpha_{\text{in}}) $$
        Where $\hat{C}$ is pre-multiplied color ($C \cdot \alpha$) [S1].
    *   **Early Termination:** If $\alpha_{\text{out}} \ge 0.95$ (or $1.0 - \epsilon$), break the loop [S2, unofficial][S10, unofficial].
6.  **Final Color:** If the background is not fully opaque, divide the accumulated pre-multiplied color by the accumulated opacity to get the final non-pre-multiplied color: $C_{\text{final}} = \hat{C}_{\text{out}} / \alpha_{\text{out}}$ [S1]. If a fully opaque background was composited, this step is omitted [S1].

**Pseudocode:**

```python
import math

def normalize(v):
    mag = math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    return (v[0]/mag, v[1]/mag, v[2]/mag)

def cross(a, b):
    return (a[1]*b[2] - a[2]*b[1],
            a[2]*b[0] - a[0]*b[2],
            a[0]*b[1] - a[1]*b[0])

def ray_aabb_intersect(origin, direction, vol_min, vol_max):
    t_min = -math.inf
    t_max = math.inf
    for i in range(3):
        if direction[i] == 0:
            if origin[i] < vol_min[i] or origin[i] > vol_max[i]:
                return None, None
        else:
            t1 = (vol_min[i] - origin[i]) / direction[i]
            t2 = (vol_max[i] - origin[i]) / direction[i]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
    if t_max < t_min or t_max < 0:
        return None, None
    return t_min, t_max

def trilinear_sample(volume, point, vol_min, vol_max):
    # Map world point to normalized [0,1] space
    nx = (point[0] - vol_min[0]) / (vol_max[0] - vol_min[0])
    ny = (point[1] - vol_min[1]) / (vol_max[1] - vol_min[1])
    nz = (point[2] - vol_min[2]) / (vol_max[2] - vol_min[2])
    
    # Map to voxel indices
    dx, dy, dz = volume.shape
    fx = nx * (dx - 1)
    fy = ny * (dy - 1)
    fz = nz * (dz - 1)
    
    x0, y0, z0 = int(math.floor(fx)), int(math.floor(fy)), int(math.floor(fz))
    x1, y1, z1 = min(x0 + 1, dx - 1), min(y0 + 1, dy - 1), min(z0 + 1, dz - 1)
    
    sx, sy, sz = fx - x0, fy - y0, fz - z0
    
    v000 = volume[x0, y0, z0]
    v100 = volume[x1, y0, z0]
    v010 = volume[x0, y1, z0]
    v110 = volume[x1, y1, z0]
    v001 = volume[x0, y0, z1]
    v101 = volume[x1, y0, z1]
    v011 = volume[x0, y1, z1]
    v111 = volume[x1, y1, z1]
    
    c00 = v000 + sx * (v100 - v000)
    c01 = v010 + sx * (v110 - v010)
    c10 = v001 + sx * (v101 - v001)
    c11 = v011 + sx * (v111 - v011)
    
    b0 = c00 + sy * (c01 - c00)
    b1 = c10 + sy * (c11 - c10)
    
    return b0 + sz * (b1 - b0)

def volume_raycasting_discretization(volume_data, transfer_func, camera, image_width, image_height, step_size):
    forward = normalize((camera['look_at'][0]-camera['eye'][0], camera['look_at'][1]-camera['eye'][1], camera['look_at'][2]-camera['eye'][2]))
    right = normalize(cross(forward, camera['up']))
    up = cross(right, forward)
    
    image = [[(0.0, 0.0, 0.0) for _ in range(image_width)] for _ in range(image_height)]
    
    vol_min = (0.0, 0.0, 0.0)
    vol_max = (1.0, 1.0, 1.0)
    
    for y in range(image_height):
        for x in range(image_width):
            ndc_x = (2.0 * (x + 0.5) / image_width) - 1.0
            ndc_y = 1.0 - (2.0 * (y + 0.5) / image_height)
            
            fov_rad = math.radians(camera['fov'])
            ray_dir = normalize(
                (right[0]*ndc_x*math.tan(fov_rad/2.0)*camera['aspect'] + up[0]*ndc_y*math.tan(fov_rad/2.0) + forward[0],
                 right[1]*ndc_x*math.tan(fov_rad/2.0)*camera['aspect'] + up[1]*ndc_y*math.tan(fov_rad/2.0) + forward[1],
                 right[2]*ndc_x*math.tan(fov_rad/2.0)*camera['aspect'] + up[2]*ndc_y*math.tan(fov_rad/2.0) + forward[2])
            )
            ray_origin = camera['eye']
            
            t_min, t_max = ray_aabb_intersect(ray_origin, ray_dir, vol_min, vol_max)
            if t_max is None:
                continue
                
            N = math.ceil((t_max - t_min) / step_size)
            
            acc_color = [0.0, 0.0, 0.0]
            acc_alpha = 0.0
            
            for k in range(N):
                t = t_min + k * step_size
                if t >= t_max:
                    break
                sample_pos = (ray_origin[0] + ray_dir[0]*t, ray_origin[1] + ray_dir[1]*t, ray_origin[2] + ray_dir[2]*t)
                
                scalar = trilinear_sample(volume_data, sample_pos, vol_min, vol_max)
                color_rgb, opacity = transfer_func(scalar)
                
                contribution = (color_rgb[0]*opacity, color_rgb[1]*opacity, color_rgb[2]*opacity)
                acc_color[0] += contribution[0] * (1.0 - acc_alpha)
                acc_color[1] += contribution[1] * (1.0 - acc_alpha)
                acc_color[2] += contribution[2] * (1.0 - acc_alpha)
                acc_alpha += opacity * (1.0 - acc_alpha)
                
                if acc_alpha >= 0.99:
                    break
            
            if acc_alpha > 0.0:
                image[y][x] = (acc_color[0]/acc_alpha, acc_color[1]/acc_alpha, acc_color[2]/acc_alpha)
            else:
                image[y][x] = (0.0, 0.0, 0.0)
                
    return image
```

**Parameters:**
*   **Step Size ($\Delta s$):** Controls sampling density [S4, unofficial][S11]. Default values vary by implementation; e.g., 0.001 in normalized space [S4, unofficial] or fixed increments like 0.75 units [S8, unofficial]. Too large causes undersampling artifacts; too small reduces performance [S11].
*   **Number of Samples ($N$):** Often derived from $\Delta s$ and ray length [S11]. Some implementations fix $N$ (e.g., 100-200) [S10, unofficial].
*   **Opacity Threshold:** Early termination threshold, typically 0.95 or 0.99 [S3][S10, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Artifacts:** If the ray entry/exit points do not align with sample positions, stepping artifacts or gaps can occur at the volume corners [S14, unofficial]. Strategies like "Entry Exit Align Corner" can mitigate this [S14, unofficial].
*   **Trilinear Interpolation:** Requires accessing 8 surrounding voxels [S1]. Out-of-bounds access must be handled via clamping or wrapping [S8, unofficial].
*   **Precision:** Intermediate terms should be computed in full precision rather than 8-bit fixed point to avoid round-off errors, especially for thin structures [S6, unofficial].
*   **Ordering:** Strict front-to-back ordering is required for the compositing formula to be valid [S15].

## Subtopics

### [Eye Align](849-eye-align.md)
Aligns sample placement to the viewer's perspective, creating concentric sampling lines. Chosen when view-dependent aliasing is a concern, but may introduce endpoint artifacts.

### [Self-Attenuation Integral Evaluation](1085-self-attenuation-integral-evaluation.md)
Uses a closed-form solution for Gaussian density fields. Chosen when exact attenuation is needed for specific analytic functions, avoiding numerical errors.

### [Partial Pre-Integration](1148-partial-pre-integration.md)
Replaces per-sample marching with a 2D lookup table. Chosen for interactive transfer function updates, trading some speed for accuracy.

### [CPU Volume Raycasting](1258-cpu-volume-raycasting.md)
Explicit multithreaded CPU implementation. Chosen for debugging or environments without GPU support, using standard compositing.

### [Average Intensity Projection](1310-average-intensity-projection.md)
A simplified projection averaging scalar values. Chosen for X-ray-like views where opacity/absorption is ignored.

### [Differential Sampling](1549-differential-sampling.md)
Adapts step size based on view-dependent frequency. Chosen to prevent aliasing for features close to the camera.

### [In-Scattering Integral Approximation via Riemann Sum](1585-in-scattering-integral-approximation-via-riemann-sum.md)
Extends discretization to include in-scattering. Chosen for volumetric lighting effects, requiring auxiliary light rays.

### [Zero Order Integration (Rectangle Rule)](2082-zero-order-integration-rectangle-rule.md)
Assumes constant opacity/color per segment. Chosen for simplicity and speed, accepting higher approximation errors.

## Operating characteristics
*   **Time Complexity:** $O(P \cdot N)$, where $P$ is the number of pixels and $N$ is the number of samples per ray [S1]. Rendering time grows linearly with dataset size if all voxels are sampled, but early termination can reduce this [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** On modern GPUs, this method is highly parallelizable, with one thread block or group per pixel. Rendering time grows linearly with dataset size if all voxels are sampled, but early termination reduces this [S1].
*   **Strengths:** Simple to implement; supports early ray termination; handles arbitrary transfer functions; produces high-quality results with sufficient sampling [S1][S2, unofficial].
*   **Limitations:** Susceptible to aliasing if step size is too large; computationally expensive for high-resolution volumes or large view distances; ignores scattering (unless extended) [S11][S15].
*   **When to Use:** General-purpose direct volume rendering; medical imaging; scientific visualization where transparency and depth cues are important [S1][S4, unofficial].
*   **When Not to Use:** When real-time performance is critical and the volume is very large (consider [Partial Pre-Integration](1148-partial-pre-integration.md) or [Average Intensity Projection](1310-average-intensity-projection.md)); when scattering effects are essential [S15].

## Background
The method was derived from the continuous volume rendering integral by Lacroute [Lac94] using the rectangle rule for numerical integration [S15]. It was popularized by Levoy's "Brute-Force Algorithm" for volume rendering, which established the front-to-back compositing approach [S1]. The approach is implemented in various frameworks, including Inviwo [S14, unofficial], and is foundational to techniques like Neural Radiance Fields (NeRF), where the discretization is differentiable [S9, unofficial].
