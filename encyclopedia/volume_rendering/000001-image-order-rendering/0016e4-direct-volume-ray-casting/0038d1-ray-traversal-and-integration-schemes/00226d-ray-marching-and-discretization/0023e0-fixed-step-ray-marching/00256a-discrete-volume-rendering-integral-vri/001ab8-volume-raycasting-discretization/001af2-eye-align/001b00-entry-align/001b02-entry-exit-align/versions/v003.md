# Entry Exit Align

Also called: Entry Exit Align Corner, Entry Exit Align Corner Sampling, Recommended Sampling Strategy

## Overview
Entry Exit Align is a sample placement strategy for fixed-length volume raycasting that aligns sample points with both the ray entry and exit points to minimize boundary artifacts [S1, unofficial]. Unlike its sibling [Entry Align](855-entry-align.md), which only aligns the first sample, Entry Exit Align ensures that neither the first nor the last sample under- or overestimates the integral by adjusting the step size per ray [S1, unofficial]. It is recommended as the best practice for volume raycasting due to zero performance impact and minimal errors [S1, unofficial].

## How it works
**Inputs:**
*   `entryPoint`: The 3D coordinate where the ray enters the volume, given in texture coordinates [S1, unofficial].
*   `exitPoint`: The 3D coordinate where the ray exits the volume, given in texture coordinates [S1, unofficial].
*   `samplingRate`: The desired number of samples per unit volume dimension [S1, unofficial].
*   `dim`: The dimensions of the volume texture (width, height, depth) [S1, unofficial].

**Outputs:**
*   `tStart`: The starting parameter along the ray for the first sample [S1, unofficial].
*   `tIncr`: The step increment (distance between samples) along the ray [S1, unofficial].
*   `tEnd`: The total length of the ray vector [S1, unofficial].

**Data Structures:**
*   `vec3`: A 3D vector type holding `x`, `y`, `z` components [G].
*   `float`: Standard floating-point number [G].

**Algorithm:**
The method calculates the number of samples required to cover the ray length while ensuring the first sample is half a step inside the entry and the last sample is half a step inside the exit [S1, unofficial]. To handle corner rays where the length is smaller than the standard step size, it uses a ceiling function applied to the scaled length of the ray against the volume dimensions minus one, ensuring at least one sample is placed at the midpoint of such short rays [S1, unofficial].

1.  Calculate the ray vector in texture coordinates:
    $$ \text{ray} = \text{exitPoint} - \text{entryPoint} $$ [S1, unofficial]
2.  Calculate the number of samples using the ceiling function applied to the scaled length of the ray against the volume dimensions minus one:
    $$ \text{samples} = \lceil \text{samplingRate} \times \|\text{ray} \times (\text{dim} - \vec{1})\| \rceil $$ [S1, unofficial]
    Where $\vec{1}$ is a vector $(1, 1, 1)$ and $\times$ denotes component-wise multiplication [S1, unofficial].
3.  Calculate the total ray length:
    $$ t_{\text{End}} = \|\text{ray}\| $$ [S1, unofficial]
4.  Calculate the step increment by dividing the total length by the number of samples:
    $$ t_{\text{Incr}} = \frac{t_{\text{End}}}{\text{samples}} $$ [S1, unofficial]
5.  Set the start parameter to half a step from the entry point:
    $$ t_{\text{Start}} = 0.5 \times t_{\text{Incr}} $$ [S1, unofficial]

**Pseudocode:**
```python
import math

def entry_exit_align(entryPoint, exitPoint, samplingRate, dim):
    """
    Calculates sampling parameters for Entry Exit Align Corner strategy.
    
    Args:
        entryPoint (tuple): Entry point in texture coordinates (x, y, z).
        exitPoint (tuple): Exit point in texture coordinates (x, y, z).
        samplingRate (float): Samples per unit dimension.
        dim (tuple): Volume dimensions (width, height, depth).
        
    Returns:
        tStart (float): Start parameter for first sample.
        tIncr (float): Step increment.
        tEnd (float): Total ray length.
    """
    # 1. Ray vector in texture coordinates
    ray = (exitPoint[0] - entryPoint[0],
           exitPoint[1] - entryPoint[1],
           exitPoint[2] - entryPoint[2])
    
    # 2. Number of samples
    adjusted_dim = (dim[0] - 1.0, dim[1] - 1.0, dim[2] - 1.0)
    scaled_ray = (ray[0] * adjusted_dim[0],
                  ray[1] * adjusted_dim[1],
                  ray[2] * adjusted_dim[2])
    scaled_length = math.sqrt(scaled_ray[0]**2 + scaled_ray[1]**2 + scaled_ray[2]**2)
    samples = math.ceil(samplingRate * scaled_length)
    
    # Ensure at least one sample is taken for degenerate rays
    if samples < 1:
        samples = 1
        
    # 3. Total ray length
    ray_length = math.sqrt(ray[0]**2 + ray[1]**2 + ray[2]**2)
    tEnd = ray_length
    
    # 4. Step increment
    tIncr = tEnd / samples
    
    # 5. Start parameter (half a step from entry)
    tStart = 0.5 * tIncr
    
    return tStart, tIncr, tEnd
```

**Edge Cases and Pitfalls:**
*   **Corner Rays:** Standard strategies may exclude contributions at corners where the ray length is smaller than the step size [S1, unofficial]. This method explicitly includes these by adjusting the step size to the ray length and placing a sample at the midpoint [S1, unofficial].
*   **Pre-integrated Rendering:** Implementations using pre-integrated volume rendering reduced to two dimensions require all rays to use the same step length [S1, unofficial]. Consequently, they cannot use this per-ray adaptive step size and must choose a strategy that under- or overestimates the integral [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [G].
*   **Memory Complexity:** Not given in the sources [G].
*   **Performance:** Zero performance impact compared to simpler strategies [S1, unofficial].
*   **Strengths:** Eliminates stepping artifacts and gaps at the bounding box [S1, unofficial]. It does not suffer from over- or underestimation of first/last samples [S1, unofficial].
*   **Limitations:** Requires per-ray calculation of step size, which may be incompatible with fixed-step pre-integrated rendering techniques [S1, unofficial].
*   **When to use:** Recommended as the best practice for general volume raycasting [S1, unofficial].
*   **When not to use:** When using pre-integrated volume rendering in 2D where a uniform step size across all rays is mandatory [S1, unofficial].

## Background
The method was developed and evaluated in the Inviwo framework [S1, unofficial]. It builds upon the "Eye Align" and "Entry Align" strategies, addressing their respective deficiencies regarding boundary estimation [S1, unofficial]. The authors note that while errors due to sample placement can be significant for data at the borders, they are often marginal in real-world use cases with higher resolution volumes [S1, unofficial]. However, artifacts can appear when zooming in on borders, justifying the recommendation of this method [S1, unofficial].
