# Semi-Analytical Fragment Shader Preintegration

Also called: Semi-Analytical Preintegration, Adaptive Preintegration with Extrema

## Overview
Semi-Analytical Fragment Shader Preintegration is a fragment shader-based technique that improves the accuracy of ray integration in volume rendering by adaptively subdividing the ray segment within a cell based on the local extrema of the scalar and shading polynomials [S1]. Unlike standard preintegration which assumes constant or linear variation over the entire interval, this method computes the roots of the derivative of the signal and shading functions to define integration boundaries, allowing for analytical or lookup-based integration over smaller, more uniform intervals [S1]. It sets itself apart from its parent [Partial Pre-Integration](1148-partial-pre-integration.md) by dynamically determining integration limits per fragment rather than using fixed uniform intervals, and from its sibling [Hybrid Volume and Isosurface Rendering with Partial Pre-Integration](1311-hybrid-volume-and-isosurface-rendering-with-partial-pre-inte.md) by focusing exclusively on the fragment shader computation for adaptive preintegration rather than hybrid isosurface extraction.

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin, ray direction, cell geometry (implicitly defined by the rasterized front face), and preintegration tables.
*   **Output:** Accumulated color and opacity for the fragment.

**Data Structures:**
*   **Preintegration Table:** A 256 × 256 × 32 RGBA texture where each component is 16-bit floating point [S1]. The dimensions correspond to scalar value, shading value, and interval length [S1]. Logarithmic table access is used for the length dimension to provide greater precision at small lengths [S1].
*   **Offscreen Buffer:** A 16-bit floating point buffer used for rendering to improve blending accuracy before copying to the front buffer [S1].

**Algorithm:**
The fragment shader performs the following steps [S1]:

1.  **Find Exit Point:** Compute the intersection of the ray with the back face of the cell to determine the parameter $t_{exit}$ (normalized to $[0,1]$ relative to the cell traversal).
2.  **Compute Polynomial Coefficients:**
    *   Compute cubic coefficients $a, b, c, d$ for the scalar signal polynomial $s(t) = at^3 + bt^2 + ct + d$ [S1].
    *   Compute quadratic coefficients $e, f, g$ for the shading polynomial $l(t) = et^2 + ft + g$ [S1].
3.  **Find Local Extrema:** Initialize a list of points $T = \emptyset$.
    *   For the scalar polynomial, find roots of the derivative $s'(t) = 3at^2 + 2bt + c = 0$.
        *   If $a \neq 0$ and $b \neq 0$: Calculate discriminant $\Delta = 4b^2 - 12ac$. Add roots $\frac{-2b + \sqrt{\Delta}}{6a}$ and $\frac{-2b - \sqrt{\Delta}}{6a}$ to $T$.
        *   Else if $a = 0$ and $b \neq 0$: Add root $\frac{-c}{2b}$ to $T$.
    *   For the shading polynomial, find root of the derivative $l'(t) = 2et + f = 0$.
        *   If $e \neq 0$: Add root $\frac{-f}{2e}$ to $T$.
4.  **Prune and Sort:**
    *   Remove any points $t \in T$ such that $t \le 0$ or $t \ge 1$ [S1].
    *   Add boundary points $0$ and $1$ to $T$.
    *   Sort $T$ in ascending order.
5.  **Adaptive Preintegration:**
    *   For each consecutive pair $(t_1, t_2)$ in $T$:
        *   Reconstruct scalar values $s_1 = d + t_1(c + t_1(b + t_1a))$ and $s_2 = d + t_2(c + t_2(b + t_2a))$ [S1].
        *   Reconstruct shading values $l_1$ and $l_2$ at $t_1$ and $t_2$ using the quadratic coefficients [S1].
        *   Compute interval length $l = t_2 - t_1$.
        *   Fetch values from the front-weighted and back-weighted preintegration textures using $(s_1, s_2, l)$ and $(s_2, s_1, l)$ respectively [S1].
        *   Combine the fetched textures (typically via linear interpolation or specific combination rules defined in the parent method) to get the contribution for this interval.
        *   Accumulate the contribution into the final color and opacity.

**Pseudocode:**
```python
def fragment_shader(ray_origin, ray_direction, cell_back_face_t):
    # 1. Find exit point (normalized to [0, 1])
    t_exit = compute_exit_point(ray_origin, ray_direction, cell_back_face_t)
    
    # 2. Compute polynomial coefficients (from vertex/geometry shader data)
    a, b, c, d = get_scalar_cubic_coefficients()
    e, f, g = get_shading_quadratic_coefficients()
    
    # 3. Find local extrema
    T = []
    
    # Scalar extrema (roots of 3at^2 + 2bt + c = 0)
    if a != 0 and b != 0:
        delta = 4 * b**2 - 12 * a * c
        if delta >= 0:
            sqrt_delta = math.sqrt(delta)
            T.append((-2 * b + sqrt_delta) / (6 * a))
            T.append((-2 * b - sqrt_delta) / (6 * a))
    elif a == 0 and b != 0:
        T.append(-c / (2 * b))
        
    # Shading extrema (root of 2et + f = 0)
    if e != 0:
        T.append(-f / (2 * e))
        
    # 4. Prune and Sort
    T = [t for t in T if 0 < t < 1]
    T.append(0.0)
    T.append(1.0)
    T.sort()
    
    # 5. Adaptive Preintegration
    accumulated_color = vec4(0.0)
    accumulated_opacity = 0.0
    
    for i in range(len(T) - 1):
        t1 = T[i]
        t2 = T[i+1]
        
        # Reconstruct scalar values
        s1 = d + t1 * (c + t1 * (b + t1 * a))
        s2 = d + t2 * (c + t2 * (b + t2 * a))
        
        # Reconstruct shading values
        l1 = g + t1 * (f + t1 * e)
        l2 = g + t2 * (f + t2 * e)
        
        # Interval length
        length = t2 - t1
        
        # Fetch preintegration tables
        # Assuming front and back tables are available
        front_val = fetch_preintegration_table(s1, s2, length)
        back_val = fetch_preintegration_table(s2, s1, length)
        
        # Combine and accumulate
        # Implementation detail: Combination logic depends on parent method [11]
        contribution = combine_front_back(front_val, back_val)
        accumulated_color += contribution.color
        accumulated_opacity += contribution.opacity
        
    return accumulated_color, accumulated_opacity
```

**Parameters:**
*   **Table Resolution:** 256 × 256 × 32 [S1].
*   **Precision:** 16-bit floating point per component [S1].
*   **Length Access:** Logarithmic mapping for the length dimension [S1].

**Edge Cases and Pitfalls:**
*   **Discriminant Negative:** If $\Delta < 0$ for the scalar polynomial, no real roots exist, and no extrema are added for that polynomial [S1].
*   **Degenerate Polynomials:** If $a=0$ and $b=0$, the scalar function is linear, and no quadratic extrema exist [S1]. If $e=0$, the shading function is linear [S1].
*   **Precision:** Small interval lengths require logarithmic access to maintain precision in the preintegration table lookup [S1].
*   **Boundary Conditions:** Points exactly at 0 or 1 are included to ensure full coverage of the cell [S1].

## Subtopics

### [Interval Integration for Volumetric Light Scattering](3090-interval-integration-for-volumetric-light-scattering.md)
Interval Integration computes in-scattered radiance by decomposing the ray path into intervals defined by the front and back faces of a light volume, allowing for the analytical evaluation of the scattering integral for directional lights and numerical or lookup-based evaluation for point and spot lights. It sets itself apart from sibling methods by explicitly treating light volume boundaries as integration limits, enabling a "sum and difference" approach where contributions are added for front-face intersections and subtracted for back-face intersections.

## Operating characteristics
*   **Time Complexity:** The fragment shader complexity depends on the number of extrema found. In the worst case, a cubic polynomial has 2 extrema and a quadratic has 1, leading to at most 3 internal points, resulting in 4 intervals. This is a small constant factor overhead compared to fixed-step ray marching.
*   **Memory Complexity:** Requires a 256 × 256 × 32 × 4 × 2 bytes = ~128 MB texture for the preintegration table [S1]. An additional 16-bit floating point offscreen buffer is used for blending [S1].
*   **Performance:** The method allows for high-quality rendering with fewer samples per ray compared to standard ray marching, as the integration is more accurate over adaptive intervals [S1].
*   **Strengths:** Improved accuracy over standard preintegration, especially for non-linear scalar fields. Interactive transfer function changes are supported via the 2D $\psi$ table structure inherited from the parent method.
*   **Limitations:** Requires computing polynomial roots in the fragment shader, which may be costly on older hardware. The logarithmic table access adds complexity to the texture lookup.
*   **When to Use:** When high-quality volume rendering is required for AMR (Adaptive Mesh Refinement) data with complex scalar fields, and interactive performance is needed.
*   **When Not to Use:** For simple linear scalar fields where standard preintegration suffices, or on hardware with limited fragment shader computational power.

## Background
The method was introduced in the context of high-quality volume rendering for Adaptive Mesh Refinement (AMR) data [S1]. It builds upon the concept of partial pre-integration to allow for adaptive subdivision of the integration interval based on the local behavior of the scalar and shading functions [S1]. The implementation was demonstrated using OpenGL on the GPU, leveraging the fragment shader for the adaptive preintegration computation [S1].
