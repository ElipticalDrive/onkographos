# Average Intensity Projection

Also called: Additive Reprojection, Average Intensity, Mean Density, Mean Density Projection, Simple Additive Projections, X-ray projection (average)

## Overview
Average Intensity Projection (AIP) is a volume rendering technique that computes the image by averaging the scalar intensities of voxels along rays through the volume onto the image plane [S1, S4, unofficial]. It serves as a simplified alternative to front-to-back compositing, producing an image equivalent to an X-ray projection through the data [S1, S4, unofficial]. Unlike standard ray casting which accounts for opacity and absorption, AIP treats the volume as a transparent medium where every sample contributes equally to the final pixel value, making it computationally inexpensive but prone to low contrast [S1, S2, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   **Volume Data:** A 3D grid of scalar values. Sources describe two common layouts:
    1.  **3D Texture:** Dimensions $X \times Y \times Z$ (e.g., $256 \times 256 \times 109$), stored in a `GL_TEXTURE_3D` with `GL_RGBA` internal format but `GL_RED` base format, using `GL_UNSIGNED_BYTE` type [S2, unofficial].
    2.  **Raw Array:** 1D array of `unsigned char` values with dimensions $N_x \times N_y \times N_z$, stored in row-major order [S4, unofficial].
*   **Camera/View:** Defined by a view position (`viewPos`) and a bounding box for the volume (e.g., min `vec3(-1.0)`, max `vec3(1.0)` or centered at volume origin) [S2, S4, unofficial].
*   **Parameters:**
    *   `num_steps`: Fixed number of sampling steps along the ray (e.g., 256) [S2, unofficial].
    *   `scale`: Scaling factor for output image dimensions ($ImageWidth = VolumeWidth \times scale$) [S4, unofficial].
    *   `isoSurf`: Optional uniform float for isosurface extraction mode, processed as `iso = isoSurf - floor(isoSurf)` [S2, unofficial].

**Outputs:**
*   **Image:** A 2D grid of pixel values.
    *   **Format:** `unsigned char` (0-255 range) [S2, S4, unofficial].
    *   **Dimensions:** Scaled width and height [S4, unofficial].
    *   **Value:** The arithmetic mean of the sampled voxel intensities along the ray [S3, unofficial].

### Data Structures
*   **Ray:** Defined by origin `or` and direction `dir` [S2, unofficial].
*   **Transfer Function (Optional):** A 1D texture (`GL_TEXTURE_1D`) mapping scalar values to color/opacity. In pure AIP, this is often bypassed or used only for final color mapping [S2, S4, unofficial].
*   **Accumulators:**
    *   `totalVoxelValue` or `meanSum`: Accumulates the sum of sampled intensities [S4, S3, unofficial].
    *   `cnt` or `validSamples`: Counts the number of valid samples taken [S2, S3, unofficial].

### Steps
1.  **Initialize:** For each pixel, initialize `totalVoxelValue = 0.0` and `cnt = 1` (to avoid division by zero) [S2, S4, unofficial].
2.  **Ray Setup:**
    *   Compute ray origin `fpos` (fragment position) and direction `direction = normalize(fpos - viewPos)` [S2, unofficial].
    *   Alternatively, for orthographic projections, map pixel coordinates to volume space: `originalX = pixelX / scale`, `originalY = pixelY / scale`, with ray origin at `(originalX, originalY, 0)` and direction `(0, 0, 1)` [S4, unofficial].
3.  **Intersection (Perspective):** Intersect the ray with the volume bounding box to find entry (`t_enter`) and exit (`t_exit`) distances using the slab method [S2, unofficial].
4.  **Step Calculation:** Calculate ray length `dist = distance(entry, exit)` and step size `stepsize = dist / num_steps` [S2, unofficial].
5.  **Sampling Loop:** Iterate `i` from 0 to `num_steps - 1`:
    *   Increment counter `cnt++` [S2, unofficial].
    *   Determine sample position `curPos` along the ray [S2, unofficial].
    *   **Coordinate Transformation:**
        *   Scale Z-coordinate if necessary: `tmp.z = curPos.z * 2.3486238532110093` (to handle non-isotropic data or texture normalization) [S2, unofficial].
        *   Map to texture coordinates: `texPos = (1 + tmp) / 2` [S2, unofficial].
        *   Invert Y-axis: `texPos.y = 1 - texPos.y` (due to image data inversion) [S2, unofficial].
    *   **Sampling:** Fetch value `val = texture(texVol, texPos).x` [S2, unofficial].
    *   **Accumulation:**
        *   If using raw array indexing (orthographic case): Translate sample to volume center, apply rotation matrix, translate back, check bounds, compute linear index, and fetch `voxelIntensity = vol.data[index] / 255.0f` [S4, unofficial].
        *   Add to sum: `totalVoxelValue += val` (or `voxelIntensity`) [S2, S4, unofficial].
    *   **Advance:** `curPos = curPos + direction * stepsize` [S2, unofficial].
6.  **Finalize:** Compute the average: `meanValue = totalVoxelValue / cnt` [S2, S4, unofficial].
7.  **Color Mapping (Optional):** Map `meanValue` to a final color using a transfer function or color map [S4, unofficial]. If lighting is enabled, calculate normals from the mean position and apply lighting [S4, unofficial].

### Pseudocode
```python
import math

def average_intensity_projection(volume_data, view_pos, image_width, image_height, num_steps=256, scale=1.0, fov_deg=60.0):
    """
    Renders an Average Intensity Projection of a 3D volume.
    
    Args:
        volume_data: 3D array of shape (Z, Y, X) with values in [0, 1]
        view_pos: Camera position (list/tuple of 3 floats)
        image_width: Output image width
        image_height: Output image height
        num_steps: Number of samples per ray
        scale: Scaling factor for image dimensions relative to volume
        fov_deg: Field of view in degrees for perspective projection
        
    Returns:
        image_data: 2D array of floats (0.0 to 1.0) representing average intensity
    """
    image_data = [[0.0 for _ in range(image_width)] for _ in range(image_height)]
    
    # Define bounding box for intersection (example: unit cube centered at origin)
    bbox_min = [-1.0, -1.0, -1.0]
    bbox_max = [1.0, 1.0, 1.0]
    
    for y in range(image_height):
        for x in range(image_width):
            # Calculate ray direction from pixel coordinates
            direction = compute_ray_direction(x, y, image_width, image_height, fov_deg)
            
            # Ray-Bbox Intersection (Slab Method)
            result = intersect_box(view_pos, direction, bbox_min, bbox_max)
            if result is None:
                continue
                
            t_enter, t_exit = result
            dist = t_exit - t_enter
            step_size = dist / num_steps
            
            total_value = 0.0
            count = 1  # Avoid division by zero, matches [S2, unofficial] initialization
            
            current_pos = [
                view_pos[0] + direction[0] * t_enter,
                view_pos[1] + direction[1] * t_enter,
                view_pos[2] + direction[2] * t_enter
            ]
            
            for _ in range(num_steps):
                count += 1
                
                # Coordinate transformation specific to source [S2, unofficial]
                tmp = [current_pos[0], current_pos[1], current_pos[2] * 2.3486238532110093]
                
                # Map to [0, 1] texture coordinates
                tex_pos = [(1.0 + tmp[0]) / 2.0, (1.0 + tmp[1]) / 2.0, (1.0 + tmp[2]) / 2.0]
                
                # Invert Y axis
                tex_pos[1] = 1.0 - tex_pos[1]
                
                # Sample volume
                val = sample_volume(volume_data, tex_pos)
                total_value += val
                
                # Advance position
                current_pos = [
                    current_pos[0] + direction[0] * step_size,
                    current_pos[1] + direction[1] * step_size,
                    current_pos[2] + direction[2] * step_size
                ]
                
            # Compute average
            mean_value = total_value / count
            image_data[y][x] = mean_value
            
    return image_data

def compute_ray_direction(pixel_x, pixel_y, img_w, img_h, fov_deg=60.0):
    """Computes a normalized ray direction for a given pixel in a perspective camera."""
    aspect = img_w / img_h
    fov_rad = math.radians(fov_deg)
    half_h = math.tan(fov_rad / 2.0)
    half_w = half_h * aspect
    dx = (pixel_x / img_w - 0.5) * 2.0 * half_w
    dy = (0.5 - pixel_y / img_h) * 2.0 * half_h
    # Camera looks down -Z axis
    dir_vec = [dx, dy, -1.0]
    length = math.sqrt(dir_vec[0]**2 + dir_vec[1]**2 + dir_vec[2]**2)
    return [dir_vec[0]/length, dir_vec[1]/length, dir_vec[2]/length]

def intersect_box(origin, direction, min_b, max_b):
    """
    Slab method for ray-box intersection.
    Returns (t_enter, t_exit) or None if no intersection.
    """
    t_min = [0.0, 0.0, 0.0]
    t_max = [0.0, 0.0, 0.0]
    
    for i in range(3):
        if direction[i] == 0.0:
            if origin[i] < min_b[i] or origin[i] > max_b[i]:
                return None
            t_min[i] = -float('inf')
            t_max[i] = float('inf')
        else:
            t_min[i] = (min_b[i] - origin[i]) / direction[i]
            t_max[i] = (max_b[i] - origin[i]) / direction[i]
            
    t_enter = max(t_min[0], t_min[1], t_min[2])
    t_exit = min(t_max[0], t_max[1], t_max[2])
    
    if t_enter > t_exit:
        return None
    if t_exit < 0:
        return None  # Box is behind the ray
        
    if t_enter < 0:
        t_enter = 0
    return t_enter, t_exit

def sample_volume(volume_data, tex_coords):
    """Samples a 3D volume using clamped nearest-neighbor for pseudocode simplicity."""
    # Clamp coordinates to [0, 1]
    c = [max(0.0, min(1.0, v)) for v in tex_coords]
    # Map to array indices (assuming volume_data is Z, Y, X)
    z_idx = int(c[2] * (len(volume_data) - 1))
    y_idx = int(c[1] * (len(volume_data[0]) - 1))
    x_idx = int(c[0] * (len(volume_data[0][0]) - 1))
    return volume_data[z_idx][y_idx][x_idx]
```

### Edge Cases and Pitfalls
*   **Division by Zero:** The sample counter `cnt` is initialized to 1 and incremented before sampling to ensure `color /= cnt` never divides by zero [S2, unofficial].
*   **Coordinate Inversion:** The texture Y-coordinate must be inverted (`1 - texPos.y`) because image data is often inverted on the Y-axis [S2, unofficial].
*   **Non-Isotropic Data:** The Z-coordinate may require scaling by a specific constant (e.g., `2.3486238532110093`) before mapping to texture space to handle non-isotropic voxels or specific normalization requirements [S2, unofficial].
*   **Low Contrast:** Additive projection techniques suffer from a confused or unclear appearance because all information is projected, resulting in very little contrast to distinguish gradual variations or small abrupt changes [S1, unofficial].
*   **Occlusion:** Unlike front-to-back compositing, AIP does not handle obscuration, which can hide structural details [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the number of samples per ray [G].
*   **Memory Complexity:** $O(V)$ for the volume data, where $V$ is the number of voxels [G].
*   **Performance:** Very fast due to the lack of complex compositing (opacity/alpha blending) and lighting calculations [G].
*   **Strengths:** Simple implementation, fast rendering, useful for quick overviews or X-ray-like visualizations [G].
*   **Limitations:** Low contrast, no depth cues from occlusion, sensitive to noise and background clutter [S1, unofficial].
*   **When to Use:** When speed is critical and depth perception is not required, or for initial data exploration [G].
*   **When Not to Use:** When detailed structural visualization, depth cues, or high contrast is needed [S1, unofficial].

## Background
Average Intensity Projection, also known as additive reprojection, was developed by Hohne et al. for medical imaging applications, specifically stereotactic neurosurgery planning [S1, unofficial]. It is one of their generalized projection images, designed to directly image the volume of data without surface shading [S1, unofficial]. The technique is equivalent to an X-ray projection through the volume [S1, unofficial]. It is often contrasted with techniques that use partial volume effects for surface shading or segmentation [S1, unofficial].
