# Screen-Space God Rays

Also called: Crepuscular Rays, Light Shafts, Radial Blur God Rays, Screen-Space Radial Blur, Volumetric Light Shaft

## Overview
Screen-Space God Rays is a post-processing technique that renders screen-space crepuscular rays by accumulating radial blur from the sun's screen position, modulated by density, decay, and weight [S1, unofficial]. It fakes volumetric light shafts using a radial blur on an occlusion map, dominating implementations for over a decade due to speed and simplicity [S2, unofficial]. It sets itself apart from physically based alternatives like volumetric ray marching by trading accuracy for a fraction of the computational cost [S2, unofficial].

## How it works
The method operates in three passes: generating an occlusion map, applying radial blur, and compositing [S2, unofficial].

### Inputs and Outputs
**Inputs:**
* `tDiffuse`: The main scene color buffer (sampler2D) [S1, unofficial].
* `tOcclusion`: The black-and-white occlusion map generated in Pass 1 (sampler2D) [S2, unofficial].
* `sunScreenPos` / `uLightPos`: The 3D light source projected to 2D screen coordinates in UV space [0,1] (vec2) [S1, unofficial].
* `density` / `uDensity`: Controls the spread of the ray delta or how far each ray extends outward from the light (float) [S1, unofficial].
* `decay` / `uDecay`: How quickly brightness falls off along each ray (float) [S2, unofficial].
* `weight` / `uWeight`: Sample weight multiplier or initial brightness of each sample (float) [S1, unofficial].
* `exposure` / `uExposure`: Final exposure multiplier scaling the composite brightness (float) [S1, unofficial].
* `NUM_SAMPLES`: Number of samples per ray (int). 64 is a common sweet spot balancing smoothness and cost [S2, unofficial].

**Outputs:**
* `godRaysTexture`: The final radial blur result containing only the god ray light shafts [S2, unofficial].
* `gl_FragColor`: The final composited color [S1, unofficial].

### Data Structures
**Uniforms (Pass 2):**
* `tOcclusion`: sampler2D [S2, unofficial].
* `uLightPos`: vec2 [S2, unofficial].
* `uExposure`: float [S2, unofficial].
* `uDecay`: float [S2, unofficial].
* `uDensity`: float [S2, unofficial].
* `uWeight`: float [S2, unofficial].
* `NUM_SAMPLES`: const int [S2, unofficial].

### Steps
1. **Pass 1: Occlusion Map Generation** Render the scene with all geometry as solid black and the light source as a bright shape (circle/sphere) to create a black-and-white occlusion map where bright pixels indicate direct light visibility [S2, unofficial].
2. **Pass 2: Radial Blur** Project the 3D light position into 2D screen coordinates [S2, unofficial]. For each pixel in the occlusion map, sample repeatedly along the line from that pixel toward the light's screen position [S2, unofficial]. Each successive sample is attenuated by a decay factor, simulating how scattered light diminishes with distance [S2, unofficial].
3. **Pass 3: Compositing** Composite the radial blur result onto the main scene render using additive blending to brighten pixels where rays fall [S2, unofficial].

### Formulas
* Delta vector: $\Delta_{UV} = (UV_{pixel} - UV_{light}) \times \frac{density}{NUM\_SAMPLES}$ [S1, unofficial][S2, unofficial].
* Accumulation: $Color = \sum_{i=0}^{NUM\_SAMPLES-1} (Sample_i \times Illumination_i \times weight)$ [S1, unofficial][S2, unofficial].
* Illumination decay: $Illumination_{i+1} = Illumination_i \times decay$ [S1, unofficial][S2, unofficial].
* Final output: $FinalColor = Color \times exposure$ [S1, unofficial].

### Parameters
* `density` / `uDensity`: Controls the spread of the ray delta. Higher values stretch rays longer. Default 0.92 [S1, unofficial].
* `weight` / `uWeight`: Sample weight multiplier. Controls overall ray intensity. Default 0.58 [S1, unofficial].
* `decay` / `uDecay`: How quickly brightness falls off along each ray. Values close to 1.0 (like 0.97) produce long, gradual rays [S2, unofficial].
* `exposure` / `uExposure`: Final exposure multiplier. Default 0.35 [S1, unofficial].
* `NUM_SAMPLES`: Number of samples per ray. 64 is a common sweet spot [S2, unofficial].

### Edge Cases and Pitfalls
* **Sun Behind Camera:** If `clipW <= 0.0001` during projection, the sun is behind the camera. Return center screen `(0.5, 0.5)` and set `inFront = false` [S1, unofficial].
* **Off-Screen Light:** The technique only works for a single, visible light source. If the light moves off-screen, the rays disappear [S2, unofficial].
* **Multiple Lights:** The technique fails with multiple light sources [S2, unofficial].

### Pseudocode (Pass 2)
```python
# Inputs: pixel_uv (vec2), occlusion_map (2D array), light_uv (vec2), exposure (float), decay (float), density (float), weight (float)
# Constants: NUM_SAMPLES = 64

def main(pixel_uv, occlusion_map, light_uv, exposure, decay, density, weight):
    # Calculate the step vector for radial blur
    delta_uv = (pixel_uv - light_uv) * density / NUM_SAMPLES
    
    uv = pixel_uv
    illumination = 1.0
    color = vec3(0.0)
    
    for i in range(NUM_SAMPLES):
        # Move towards the light source
        uv = uv - delta_uv
        
        # Clamp to [0, 1] for screen bounds
        uv = vec2(max(0.0, min(1.0, uv.x)), max(0.0, min(1.0, uv.y)))
        
        # Sample the occlusion map
        samp = occlusion_map.sample(uv)
        
        # Apply decay and weight
        samp = samp * illumination * weight
        
        # Accumulate
        color = color + samp
        
        # Update illumination decay
        illumination = illumination * decay
        
    # Final exposure
    return vec4(color * exposure, 1.0)
```

## Operating characteristics
* **Time Complexity:** O(N) per pixel, where N is `NUM_SAMPLES` [S2, unofficial].
* **Memory Complexity:** O(W*H) for the occlusion map and god rays texture, where W and H are screen dimensions [S2, unofficial].
* **Measured Performance:** Requires two extra render passes and a handful of texture samples per pixel, a fraction of the cost of volumetric ray marching [S2, unofficial].
* **Strengths:** Fast, simple, and produces convincing results for single light sources [S2, unofficial].
* **Limitations:** Less accurate than volumetric ray marching. Fails with multiple lights or off-screen lights [S2, unofficial].
* **When to use:** Mobile or lower-end hardware, single dominant light source (sun) [S2, unofficial].
* **When not to use:** Multiple light sources, physically accurate requirements, lights moving off-screen [S2, unofficial].

## Background
* **Origin:** Published by Kenny Mitchell in GPU Gems 3 in 2007 [S2, unofficial].
* **History:** One of the first mainstream implementations in games, notably Crysis (2007), setting a standard expectation for high-end PC games [S2, unofficial]. Dominated god ray implementations for over a decade [S2, unofficial].
