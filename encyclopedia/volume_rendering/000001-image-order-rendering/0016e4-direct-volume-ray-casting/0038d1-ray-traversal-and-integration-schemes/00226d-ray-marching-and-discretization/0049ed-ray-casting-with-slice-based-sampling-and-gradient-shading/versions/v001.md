# Ray Casting with Slice-Based Sampling and Gradient Shading

Also called: Ray Casting (Gradient Shading Variant), psTrace

## Overview
This method performs direct volume ray casting by sampling a 3D volume stored in a 2D texture atlas, computing surface normals via finite differences of sampled densities, and applying diffuse shading [S1, unofficial]. It stops sampling when a high-density threshold is reached or the ray exits the bounding box [S1, unofficial]. It is distinguished from standard ray marching by its specific use of a 2D texture atlas for 3D data storage and the explicit calculation of gradients for lighting, rather than relying solely on transmittance accumulation or pre-computed normals [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D texture (`volume`) containing a 256x256x256 volume packed into a 16x16 grid of 16x16 slices [S1, unofficial]. Camera parameters (eye position, view direction matrix) [S1, unofficial]. Light position (`lightPos`) and color (`lightcolor`) [S1, unofficial].
*   **Output:** A fragment color (`gl_FragColor`) representing the rendered pixel [S1, unofficial].

**Data Structures:**
*   **Volume Texture:** A `sampler2D` representing a 256x256x256 volume. The volume is packed into a 16x16 grid of slices. Each slice is 256x256 texels [S1, unofficial].
*   **Ray Parameters:** `tmin` and `tmax` defining the intersection interval with the bounding box [S1, unofficial].

**Parameters:**
*   `dt`: Step size for ray marching. Value: 0.008 [S1, unofficial].
*   `density_threshold`: The red channel value threshold to stop ray marching. Value: 0.3 [S1, unofficial].
*   `lightPos`: Position of the light source. Value: `vec3(4,4,4)` [S1, unofficial].
*   `lightcolor`: Color of the light. Value: `vec3(1,1,1)` [S1, unofficial].
*   `boxPoint1`: Lower bound of the volume bounding box. Value: `vec3(0,0,3)` [S1, unofficial].
*   `boxPoint2`: Upper bound of the volume bounding box. Value: `vec3(1,1,4)` [S1, unofficial].

**Algorithm Steps:**
1.  **Ray-Box Intersection:** Calculate the intersection parameters `tmin` and `tmax` for the ray against the bounding box defined by `boxPoint1` and `boxPoint2` using a function `intersectParams(boxPoint1, boxPoint2, eye, dir)` [S1, unofficial].
2.  **Initialization:** Initialize the ray parameter `t` to `tmin` (accessed as `t1t2.x`) and the accumulated color `color` to `vec3(0,0,0)` [S1, unofficial].
3.  **Ray Marching Loop:** Iterate `i` from 0 to 1499 (1500 iterations) [S1, unofficial]:
    a.  **Ray Position:** Calculate the current 3D point `point` as `eye + t * dir` [S1, unofficial].
    b.  **Gradient Sampling:** Sample the density at `point` and its neighbors (`point +/- dt` in x, y, z) using the `sliceSample` function [S1, unofficial].
        *   `sliceSample` performs linear interpolation between two slices (`slice1` and `slice2`) based on the normalized depth `rate` [S1, unofficial].
        *   Let `dx1` be the sample at `x + dt`, `dx2` at `x - dt`, `dy1` at `y + dt`, `dy2` at `y - dt`, `dz1` at `z + dt`, and `dz2` at `z - dt` [S1, unofficial].
    c.  **Normal Calculation:** Compute the surface normal using finite differences:
        $$ \text{normal} = \text{normalize}(\text{vec3}(dx1.x - dx2.x, dy1.y - dy2.y, dz1.z - dz2.z)) $$
        [S1, unofficial]
    d.  **Diffuse Shading:** Calculate the diffuse contribution:
        $$ \text{cosalpha} = \text{clamp}(\text{dot}(\text{normal}, \text{lightDir}), 0.0, 1.0) $$
        $$ \text{lightDir} = \text{normalize}(\text{lightPos} - \text{point.xyz}) $$
        $$ \text{color} = \text{sample} \times \text{cosalpha} \times \text{lightcolor} $$
        [S1, unofficial]
    e.  **Termination Check:** If the sampled density's red channel `sample.r` is greater than `density_threshold` (0.3) OR `t` exceeds `tmax` (`t1t2.y`), break the loop [S1, unofficial].
    f.  **Advance Ray:** Increment `t` by `dt` [G].
4.  **Output:** If `tmin` (`t1t2.x`) is greater than 0.0, output `gl_FragColor = vec4(color.xyz, 1.0)` [S1, unofficial]. Otherwise, output `vec4(0.5, 0.5, 0.5, 1.0)` [S1, unofficial].

**Pseudocode:**
```python
def ray_cast_slice_gradient(eye, dir, volume_texture, light_pos, light_color):
    # 1. Ray-Box Intersection
    # Bounding box defined by boxPoint1=(0,0,3) and boxPoint2=(1,1,4)
    t_min, t_max = intersect_params(vec3(0,0,3), vec3(1,1,4), eye, dir)
    
    # Pitfall: If ray does not intersect box, intersect_params returns (-1, -1)
    if t_min <= 0.0:
        return vec4(0.5, 0.5, 0.5, 1.0)

    # 2. Initialization
    t = t_min
    color = vec3(0, 0, 0)
    
    # Parameters
    dt = 0.008
    density_threshold = 0.3
    
    # 3. Ray Marching Loop
    for i in range(1500):
        # Calculate point
        point = eye + t * dir
        
        # Sample density and neighbors for gradient
        # sliceSample performs linear interpolation between slices based on rate
        # We need samples at point and point +/- dt in x, y, z
        dx1 = slice_sample(volume_texture, point + vec3(dt, 0, 0))
        dx2 = slice_sample(volume_texture, point - vec3(dt, 0, 0))
        dy1 = slice_sample(volume_texture, point + vec3(0, dt, 0))
        dy2 = slice_sample(volume_texture, point - vec3(0, dt, 0))
        dz1 = slice_sample(volume_texture, point + vec3(0, 0, dt))
        dz2 = slice_sample(volume_texture, point - vec3(0, 0, dt))
        
        # Current sample for shading
        sample = slice_sample(volume_texture, point)
        
        # Normal calculation
        normal = normalize(vec3(dx1.x - dx2.x, dy1.y - dy2.y, dz1.z - dz2.z))
        
        # Diffuse shading
        light_dir = normalize(light_pos - point)
        cos_alpha = clamp(dot(normal, light_dir), 0.0, 1.0)
        color = sample * cos_alpha * light_color
        
        # Termination check
        if sample.r > density_threshold or t > t_max:
            break
            
        # Advance ray
        t += dt
        
    return vec4(color, 1.0)

def slice_sample(texture, point):
    # Calculate texture coordinates for the 2D texture atlas
    # Volume is 256x256x256, packed in 16x16 grid of 16x16 slices
    # point is in [0,1] range relative to box? Or world? 
    # Based on box (0,0,3) to (1,1,4), point needs to be mapped to texture coords.
    # The source formula: tex256 = vec2(mod(slice,16.0), floor(slice/16.0))/16.0 + point.xy/16.0
    # This implies point.xy are used for S,T, and Z determines the slice.
    # However, standard volume rendering maps 3D point to 3D texture coords.
    # Given the specific formula in source, we assume point is normalized or mapped appropriately.
    # Let's assume point is in [0,1] for x,y and z determines slice index.
    
    # Extract slice index from Z coordinate
    # Assuming point.z is in [0, 1] range corresponding to 256 slices
    slice_float = point.z * 256.0
    slice_idx = floor(slice_float)
    slice_rate = slice_float - slice_idx
    
    # Clamp slice index
    slice_idx = clamp(slice_idx, 0.0, 255.0)
    
    # Calculate 2D texture coordinates
    # The source formula: tex256 = vec2(mod(slice,16.0), floor(slice/16.0))/16.0 + point.xy/16.0
    # This suggests the texture is 256x256, and each "slice" is 16x16 blocks of 16x16 texels?
    # 256x256 texture. 16x16 grid of slices. Each slice is 16x16 texels? 
    # 16*16 = 256. So each slice is 16x16 texels.
    # Total volume 256x256x256.
    # Texture size 256x256.
    # Grid 16x16 slices.
    # Each slice is 16x16 texels.
    
    # Calculate base offset for the slice in the 256x256 texture
    # Slice index 0..255.
    # Grid position: (slice % 16, slice / 16)
    # Each cell in grid is 16x16 texels.
    # So offset in texture coords (0..1) is:
    # u = (slice % 16) * 16 / 256 = (slice % 16) / 16
    # v = (slice / 16) * 16 / 256 = (slice / 16) / 16
    
    # The source formula: vec2(mod(slice,16.0), floor(slice/16.0))/16.0
    # This gives u,v in [0,1] for the slice block.
    
    # Then add point.xy/16.0? 
    # If point.xy are in [0,1], point.xy/16.0 is very small.
    # This implies point.xy might be in [0,16] range? Or the formula is specific to the implementation.
    # Let's follow the source formula exactly.
    
    slice_f = slice_idx
    u_base = (mod(slice_f, 16.0)) / 16.0
    v_base = (floor(slice_f / 16.0)) / 16.0
    
    # point.xy are assumed to be in [0,1] range? 
    # If point is in [0,1], then point.xy/16.0 is [0, 1/16].
    # This would mean the slice is 1/16th of the texture?
    # 1/16 of 256 is 16. So yes, each slice is 16x16 texels.
    
    u = u_base + point.x / 16.0
    v = v_base + point.y / 16.0
    
    # Sample texture
    # Assuming linear filtering
    return texture2D(volume_texture, vec2(u, v))
```

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of ray steps (1500 in the reference implementation). Each step involves 7 texture samples (current point + 6 neighbors) and vector operations [S1, unofficial].
*   **Memory Complexity:** $O(1)$ per pixel for the ray marching state, plus the memory for the volume texture (256x256x256 packed into 256x256 2D texture) [S1, unofficial].
*   **Performance:** The method is designed for real-time rendering on GPUs using WebGL [S1, unofficial]. The fixed iteration count and simple shading model allow for predictable performance [S1, unofficial].
*   **Strengths:** Simple implementation; provides basic surface-like shading via gradient estimation; efficient memory usage via texture atlas packing [S1, unofficial].
*   **Limitations:** No transmittance/absorption accumulation; limited to diffuse shading; fixed step size may lead to aliasing or missed features; gradient estimation is noisy and approximate [S1, unofficial].
*   **When to use:** Real-time visualization of volumetric data where approximate surface shading is sufficient and performance is critical [S1, unofficial].
*   **When not to use:** High-fidelity medical imaging requiring accurate light transport; scenes with complex lighting or transparency effects [S1, unofficial].
