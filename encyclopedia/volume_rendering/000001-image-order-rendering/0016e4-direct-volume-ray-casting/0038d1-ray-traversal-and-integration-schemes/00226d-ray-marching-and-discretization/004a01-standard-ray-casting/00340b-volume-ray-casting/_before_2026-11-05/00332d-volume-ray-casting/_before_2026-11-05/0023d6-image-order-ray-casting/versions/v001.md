# Image-order Ray-Casting

Also called: Levoy's Ray Casting, Levoy raycasting, Image-order Volume Rendering, Composite ray casting, Volume Ray Tracing

## Overview
Image-order Ray-Casting is a direct volume rendering technique that visualizes 3D scalar or vector data by casting primary rays from the viewpoint through a volumetric dataset, sampling values at regular intervals, and compositing colors and opacities to form a 2D projection [S1][S2, S3, S4, unofficial]. It solves the problem of rendering fuzzy, semi-transparent volumes without explicit geometric surface extraction, avoiding the aliasing artifacts associated with binary classification in surface extraction methods like marching cubes [S1][S4, unofficial]. Unlike surface ray tracing, it handles only primary rays (no secondary rays for shadows or reflections) and differs from object-order methods (like splatting) by processing the image pixel-by-pixel rather than projecting voxels onto the screen [S1][S3, S4, unofficial].

## How it works
**Inputs:** A 3D scalar voxel grid $V$ with dimensions $W \times H \times D$, a viewing frustum defined by eye point $E$, near plane, and pixel coordinates $(u,v)$, and a 1D transfer function mapping scalar values to color $c(s)$ and opacity $\alpha(s)$.
**Outputs:** A 2D image where each pixel $(u,v)$ contains an accumulated color $C_{out}$.

**Data Structures:**
*   **Voxel Grid:** A 3D array of scalar values. Access is typically via trilinear interpolation.
*   **Transfer Function:** A lookup table or function $T(s) = (c(s), \alpha(s))$.
*   **Ray State:** Accumulated color $C$, accumulated transmittance $T$, current position $X$, and step counter.

**Steps:**

1.  **Ray Generation:** For each pixel $(u,v)$, compute the ray origin $O = E$ and direction $D = \text{normalize}(P - E)$, where $P$ is the 3D position of the pixel on the near plane [S1][S4, unofficial].
2.  **AABB Intersection:** Intersect the ray $X(t) = O + tD$ with the volume's Axis-Aligned Bounding Box (AABB) defined by $[\min_x, \max_x] \times [\min_y, \max_y] \times [\min_z, \max_z]$ using the slab method [S1]:
    *   For each axis $i \in \{x, y, z\}$:
        $$ t_{i,\min} = \frac{\min_i - O_i}{D_i}, \quad t_{i,\max} = \frac{\max_i - O_i}{D_i} \quad (\text{if } D_i \neq 0; \infty \text{ otherwise}) $$
    *   Compute entry and exit distances:
        $$ t_{\text{entry}} = \max(0, \max(t_{x,\min}, t_{y,\min}, t_{z,\min})) $$
        $$ t_{\text{exit}} = \min(t_{x,\max}, t_{y,\max}, t_{z,\max}) $$
    *   If $t_{\text{entry}} > t_{\text{exit}}$, the ray misses the volume; output background color and continue to next pixel [S1].
3.  **Initialization:** Initialize accumulated color $C = (0,0,0)$ and transmittance $T = 1.0$ [S1][S3, unofficial]. Set current parameter $t = t_{\text{entry}}$.
4.  **Traversal Loop:** While $t < t_{\text{exit}}$:
    *   **Step Increment:** $t \leftarrow t + \Delta t$, where $\Delta t$ is the fixed step size (typically proportional to voxel size, e.g., $\Delta t = \text{voxel\_size} / n$) [S1].
    *   **Position Update:** $X = O + tD$ [S1].
    *   **Sampling:** Map $X$ to voxel coordinates and perform trilinear interpolation to get scalar value $s$ [S1][S4, unofficial]:
        Let $dx = x - \lfloor x \rfloor, dy = y - \lfloor y \rfloor, dz = z - \lfloor z \rfloor$.
        $$ s = \sum_{i,j,k \in \{0,1\}} (1-dx)^{1-i}dx^i (1-dy)^{1-j}dy^j (1-dz)^{1-k}dz^k \cdot v_{ijk} $$
        where $v_{ijk}$ are the 8 surrounding voxel values [S1].
    *   **Classification:** Map $s$ to color $c_s$ and opacity $\alpha_s$ using the transfer function [S1][S4, unofficial].
    *   **Shading (Optional):** Estimate gradient $\nabla s$ using central differences to compute normal $\mathbf{N} = \text{normalize}(-\nabla s)$ for local illumination (e.g., Phong) [S1][S4, unofficial].
    *   **Compositing (Front-to-Back):** Update $C$ and $T$ [S1][S3, unofficial]:
        $$ C \leftarrow C + T \cdot c_s \cdot \alpha_s $$
        $$ T \leftarrow T \cdot (1 - \alpha_s) $$
    *   **Early Termination:** If $T < \epsilon$ (e.g., 0.01) or accumulated opacity $1-T > 0.95$, break loop [S1][S3, unofficial].
5.  **Output:** Store $C$ as the final pixel color [S1].

**Pseudocode:**
```python
def image_order_ray_casting(volume, transfer_function, eye_point, near_plane, image_width, image_height, step_size, epsilon=0.01):
    # Precompute AABB bounds from volume
    aabb_min = volume.min_bounds
    aabb_max = volume.max_bounds
    
    image = empty_array(image_width, image_height, 3)
    
    for v in range(image_height):
        for u in range(image_width):
            # 1. Ray Generation
            pixel_pos = near_plane.project(u, v)
            ray_origin = eye_point
            ray_dir = normalize(pixel_pos - ray_origin)
            
            # 2. AABB Intersection (Slab Method)
            t_min = 0.0
            t_max = infinity
            
            for axis in ['x', 'y', 'z']:
                if abs(ray_dir[axis]) > 1e-8:
                    t1 = (aabb_min[axis] - ray_origin[axis]) / ray_dir[axis]
                    t2 = (aabb_max[axis] - ray_origin[axis]) / ray_dir[axis]
                    t_min = max(t_min, min(t1, t2))
                    t_max = min(t_max, max(t1, t2))
                else:
                    if ray_origin[axis] < aabb_min[axis] or ray_origin[axis] > aabb_max[axis]:
                        t_min = infinity # Ray misses
                        break
            
            if t_min > t_max or t_min == infinity:
                image[u, v] = background_color
                continue
            
            # 3. Initialization
            acc_color = (0.0, 0.0, 0.0)
            transmittance = 1.0
            
            # 4. Traversal Loop
            t = t_min
            while t < t_max:
                # Position
                pos = ray_origin + t * ray_dir
                
                # Sampling (Trilinear Interpolation)
                # Note: volume.sample() handles floor and interpolation internally
                scalar_val = volume.sample(pos)
                
                # Classification
                color_s, alpha_s = transfer_function(scalar_val)
                
                # Compositing (Front-to-Back)
                contribution = color_s * alpha_s * transmittance
                acc_color = acc_color + contribution
                transmittance = transmittance * (1.0 - alpha_s)
                
                # Early Termination
                if transmittance < epsilon:
                    break
                
                # Step
                t += step_size
            
            image[u, v] = acc_color
            
    return image
```

**Parameters:**
*   **Step Size ($\Delta t$):** Fixed distance between samples. Typically $\Delta t = \text{voxel\_size} / n$ where $n \ge 1$ [S1].
*   **Epsilon ($\epsilon$):** Threshold for early termination. Typical value 0.01 [S1][S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Division by Zero:** Handled in slab method by checking $D_i \neq 0$ [S1].
*   **Aliasing:** Undersampling causes aliasing artifacts. Supersampling (multiple rays per pixel) mitigates this but increases cost [S1].
*   **Boundary Conditions:** Interpolation must handle coordinates outside the voxel grid (clamp or repeat) [G].
*   **Precision:** Floating-point errors in $t$ accumulation can cause gaps or overlaps; using world-space coordinates for position calculation ($X = O + tD$) is preferred over incremental addition [G].

## Subtopics

### [Two-Pass Depth Ray Casting](3377-two-pass-depth-ray-casting.md)
Computes ray entry/exit points by rasterizing the volume's bounding box twice with different depth tests, then uses these coordinates for ray casting. Solves efficient interval determination on GPU without complex intersection algorithms.

### [Van Hook-Levoy Ray-Casting](3594-van-hook-levoy-ray-casting.md)
A variant focusing on specific traversal strategies for the ray-casting pipeline.

### [Koyamada's Algorithm](4148-koyamada-s-algorithm.md)
Uses image-space coherency to generate ray-segments by scan-converting front-facing faces, traversing them through the volume, and inserting composited segments into a RayBuffer.

### Volume Ray Casting with Barycentric Interpolation and Phong Lighting
A variant that casts rays through a 3D voxel grid, sampling values using barycentric interpolation within the unit cube, and accumulating lighting contributions (ambient, diffuse, specular) along the ray path [S6, unofficial]. It initializes viewing plane and volume structures, computes ray origin/direction per pixel, iterates along the ray with a fixed step size, samples via barycentric interpolation, calculates lighting, and clamps the accumulated result to [0, 1] [S6, unofficial].

### Backward Mapping (Ray Tracing)
A volumetric rendering technique where a ray is projected through the data volume for each pixel, and intersecting voxels influence the pixel value [S7, unofficial].

### Object Order Ray-Casting
A variant where the volume is transformed to align with the view direction prior to ray-casting, so resample locations coincide with integer grid points. It decomposes the transformation into affine transforms (shear/scale), resamples the volume for regular access, and casts rays based on the resampled data [S5].

### Hybrid Ray-Casting
Produces an intermediate image aligned with one of the volume faces (via shear/scale transform) and then warps (2D transform) it to the view plane to achieve a one-to-one mapping of ray-samples onto the volume [S5].

## Operating characteristics
*   **Time Complexity:** $O(N_{pixels} \cdot N_{samples})$, where $N_{samples}$ is the number of steps along the ray. Proportional to volume resolution and image resolution [S1].
*   **Memory Complexity:** $O(V)$ for the volume data, plus $O(1)$ per pixel for accumulation [S1].
*   **Performance:** Computationally expensive due to the large number of samples and interpolation operations per pixel [S4, unofficial]. GPU acceleration (fragment shaders) enables real-time performance for moderate resolutions [S1].
*   **Strengths:** High-fidelity visualization of fuzzy boundaries, no aliasing from surface extraction, flexible viewpoint and lighting, handles partial transparency naturally [S1][S4, unofficial].
*   **Limitations:** High computational cost, sensitive to aliasing if undersampled, requires careful tuning of transfer functions [S1][S4, unofficial].
*   **When to Use:** Medical imaging (CT/MRI), scientific visualization (fluids, clouds), and entertainment (smoke, fire) where visual quality and transparency are prioritized over speed [S1].
*   **When Not to Use:** Real-time applications with very large volumes and strict latency constraints without GPU acceleration, or when simple surface visualization suffices [S1][S4, unofficial].

## Background
Developed in the late 1980s, volume ray casting builds on foundational work in optical modeling. Marc Levoy introduced a practical algorithm in 1988 for displaying surfaces from volume data without intermediate geometric primitives [S1]. James T. Kajiya and Brian P. Von Herzen developed algorithms for tracing rays through volume densities in 1984 [S1]. The first ray casting algorithm for rendering was presented by Arthur Appel in 1968 [S4, unofficial]. It is used in medical imaging, molecular graphics, fluid dynamics, and entertainment, implemented in tools like VTK, Open Inventor, and hardware like VolumePro [S1].
