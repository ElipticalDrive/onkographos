# Koyamada's Algorithm

Also called: Koyamada's DVR algorithm, Sequential DVR Algorithm

## Overview
Koyamada's Algorithm is an image-order ray-casting method for unstructured tetrahedral volumes that leverages image-space coherency to generate and compose ray-segments in object space [S1, unofficial]. It differs from its siblings by explicitly constructing continuous ray-segments via scan-conversion of external faces and traversing them through the volume using cell connectivity, rather than sampling fixed intervals along a pixel ray [S1, unofficial].

## How it works
**Inputs:**
*   Volumetric dataset defined by tetrahedral cells [S1, unofficial].

**Outputs:**
*   A composited image where each pixel contains the final color and opacity derived from the composited ray-segments stored in the RayBuffer [S1, unofficial].

**Data Structures:**
The algorithm uses three primary data structures [S1, unofficial]:

1.  **VertexArray**: Stores per-vertex data [S1, unofficial].
    *   `scalar_value`: The scalar value at the vertex [S1, unofficial].
    *   `WSC`: World Space Coordinates $(x, y, z)$ [S1, unofficial].
    *   `NPC`: Normalized Projection Coordinates $(x, y, z)$ on the screen plane [S1, unofficial].

2.  **CellArray**: Stores per-cell topology [S1, unofficial].
    *   `Vertices`: An array of 4 integers, containing the indices of the four vertices of the tetrahedron [S1, unofficial].
    *   `NeighborCells`: An array of 4 integers. Each entry corresponds to a face of the tetrahedron [S1, unofficial].
        *   If the face is internal, the value is the index of the neighbor cell [S1, unofficial].
        *   The index within the neighbor cell's `NeighborCells` array that refers back to the current cell is also stored to avoid searching for the entry face of the next cell [S1, unofficial].
        *   If the face is external, a sentinel value (e.g., -1) is used [S1, unofficial].

3.  **RayBuffer**: A 2D virtual array indexed by pixel coordinates $(u, v)$ [S1, unofficial].
    *   Each entry holds a linked list of composited ray-segments [S1, unofficial].
    *   Each list element contains:
        *   `ZDepth`: The $z$-coordinate (in NPC) of the exit point of the ray-segment. Lists are maintained in increasing order of this value [S1, unofficial].
        *   `Color-Opacity`: The composited RGB color and opacity value for the segment [S1, unofficial].

**Algorithm Steps:**

1.  **Generate Ray-Segments (Scan Conversion):**
    *   Iterate through all front-facing (ff) external faces of the volume in any order [S1, unofficial].
    *   For each ff-external face, scan-convert its projection onto the screen [S1, unofficial].
    *   For each pixel $(u, v)$ covered by the face's projection:
        *   Determine the ray origin and direction corresponding to pixel $(u, v)$ [G].
        *   Calculate the entry point $P$ into the volume. The entry point is the intersection of the ray with the ff-external face [S1, unofficial].
        *   Initialize the composition state at $P$ (typically starting with background color/opacity) [G].
        *   Traverse the ray through the volume cells until it exits through a back-facing (bf) external face [S1, unofficial].
        *   Insert the resulting composited ray-segment into the linked list of the RayBuffer at pixel $(u, v)$ [S1, unofficial].

2.  **Trace Ray Inside Volume (Cell Traversal):**
    *   Given an entry point $P$ and entry face $F_{in}$ for a tetrahedral cell $C$: [S1, unofficial].
    *   Identify the three other faces of $C$ that are candidates for the exit face [S1, unofficial].
    *   For each candidate face $F_{cand}$:
        *   Let the vertices of $F_{cand}$ be $A, C, D$ [S1, unofficial].
        *   Check if the ray intersects the plane of $F_{cand}$ [S1, unofficial].
        *   If the projection of vectors $\vec{AC}$ and $\vec{AD}$ onto the screen are parallel, the face is perpendicular to the screen; skip this face and test the next candidate [S1, unofficial].
        *   Otherwise, calculate the intersection point $Q$ of the ray with the plane of $F_{cand}$ [S1, unofficial].
        *   Validate if $Q$ lies inside the triangle $ACD$ using barycentric coordinates [S1, unofficial].

3.  **Determine Exit Face and Point:**
    *   Express vector $\vec{AQ}$ as a linear combination of $\vec{AC}$ and $\vec{AD}$ [S1, unofficial]:
        $$ \vec{AQ} = \alpha \vec{AC} + \beta \vec{AD} $$
    *   Solve for $\alpha$ and $\beta$ using the 2x2 linear system derived from the NPC coordinates [S1, unofficial]:
        $$ \begin{bmatrix} x_C - x_A & x_D - x_A \\ y_C - y_A & y_D - y_A \end{bmatrix} \begin{bmatrix} \alpha \\ \beta \end{bmatrix} = \begin{bmatrix} x_r - x_A \\ y_r - y_A \end{bmatrix} $$
        Where $(x_A, y_A)$, $(x_C, y_C)$, and $(x_D, y_D)$ are the NPC coordinates of vertices $A, C, D$, and $(x_r, y_r)$ are the NPC coordinates of the ray (constant for the pixel) [S1, unofficial].
    *   Validate the intersection:
        *   If $\alpha > 0$, $\beta > 0$, and $\alpha + \beta < 1$, then $Q$ is inside triangle $ACD$. This face is the exit face. No further tests are needed for this ray-segment within this cell [S1, unofficial].
        *   Otherwise, $Q$ is not inside the triangle; test the next candidate face [S1, unofficial].
    *   If no candidate face yields a valid intersection, the ray exits through a back-facing external face (or the cell is degenerate) [S1, unofficial].

4.  **Calculate Exit Properties:**
    *   Once the exit face and point $Q$ are identified, calculate the $z$-coordinate of $Q$ in NPC space [S1, unofficial]:
        $$ z_Q = z_A + \alpha(z_C - z_A) - \beta(z_D - z_A) $$
        The source formula uses a minus sign for the $\beta$ term, consistent with the vector definition $\vec{AQ} = \alpha \vec{AC} + \beta \vec{AD}$ [S1, unofficial].
    *   Calculate the scalar value $s_Q$ at $Q$ using 2D inverse distance interpolation (barycentric interpolation) [S1, unofficial]:
        $$ s_Q = \alpha s_C + \beta s_D + (1 - \alpha - \beta) s_A $$
        Where $s_A, s_C, s_D$ are the scalar values at vertices $A, C, D$. The coefficients represent the area ratios of sub-triangles $QAD$, $QAC$, and $QCD$ to the area of triangle $ACD$ [S1, unofficial].

5.  **Resample and Composite:**
    *   With the entry point $P$ (known from the previous step or scan conversion) and exit point $Q$ (just calculated), resample the scalar values along the segment $PQ$ [S1, unofficial].
    *   Use equi-distant sampling with interval $\Delta s$. $\Delta s$ must be small enough to ensure at least one sample is taken in each cell [S1, unofficial].
    *   Composite the samples using standard volume rendering integration (e.g., front-to-back compositing) to update the color and opacity [G].
    *   The exit point $Q$ and its properties become the entry point for the next cell [S1, unofficial].
    *   Repeat steps 2-5 until a back-facing external face is reached [S1, unofficial].

6.  **Final Composition:**
    *   After all ff-external faces are processed, the RayBuffer contains all composited ray-segments [S1, unofficial].
    *   For each pixel, sort the linked list of ray-segments by `ZDepth` (if not already sorted during insertion) and composite them from front to back to produce the final pixel color and opacity [G].

**Pseudocode:**
```python
def koyamada_algorithm(vertices, cells, screen_width, screen_height):
    # Initialize RayBuffer: 2D virtual array of linked lists
    ray_buffer = [[[] for _ in range(screen_height)] for _ in range(screen_width)]
    
    # 1. Generate Ray-Segments via scan-conversion of ff-external faces
    for face in external_faces:
        if not is_front_facing(face):
            continue
        # Scan-convert face projection onto screen
        for pixel_u, pixel_v in scan_convert(face):
            ray_origin, ray_dir = get_ray(pixel_u, pixel_v)
            entry_point = intersect_ray_face(ray_origin, ray_dir, face)
            
            # Start traversal in the cell adjacent to the ff-external face
            current_cell = get_adjacent_cell(face)
            current_face = face
            color, opacity = background_color, 0.0
            
            # 2-5. Trace ray inside volume
            while not is_back_facing_external(current_face):
                # Determine exit point and face for current cell
                exit_point, exit_face = trace_ray_through_cell(
                    current_cell, current_face, entry_point, ray_origin, ray_dir
                )
                
                # Resample and composite along the segment
                segment_color, segment_opacity = resample_and_composite(
                    entry_point, exit_point, current_cell
                )
                color, opacity = composite_front_to_back(
                    color, opacity, segment_color, segment_opacity
                )
                
                # Move to next cell
                current_cell = neighbor_cell(current_cell, current_face, exit_face)
                current_face = exit_face
                entry_point = exit_point
                
            ray_buffer[pixel_u][pixel_v].append(
                RaySegment(z_depth=exit_point.z, color=color, opacity=opacity)
            )
            
    # 6. Final Composition
    for u in range(screen_width):
        for v in range(screen_height):
            ray_buffer[u][v].sort(key=lambda seg: seg.z_depth)
            final_color, final_opacity = composite_ray_segments(ray_buffer[u][v])
            set_pixel(u, v, final_color, final_opacity)
            
    return ray_buffer

def trace_ray_through_cell(cell, entry_face, entry_point, ray_origin, ray_dir):
    vertices = cell.Vertices
    # Candidate faces are the 3 faces of the tetrahedron not equal to entry_face
    for cand_face in get_candidate_faces(cell, entry_face):
        A, C, D = get_face_vertices(cand_face)
        
        # Check parallel projection (face perpendicular to screen)
        if is_parallel_projection(A, C, D):
            continue
            
        # Solve 2x2 system for alpha and beta
        alpha, beta = solve_barycentric(A, C, D, ray_origin, ray_dir)
        
        # Validate intersection
        if alpha > 0 and beta > 0 and (alpha + beta) < 1:
            # Calculate exit point properties
            z_Q = A.z + alpha * (C.z - A.z) - beta * (D.z - A.z)
            exit_point = Point(x=ray_origin.x + ray_dir.x * t, 
                               y=ray_origin.y + ray_dir.y * t, 
                               z=z_Q)
            return exit_point, cand_face
            
    # Fallback: exit through back-facing external face
    return entry_point, get_back_facing_external_face(cell)

def resample_and_composite(entry, exit, cell):
    # Equi-distant sampling along segment
    num_samples = int(distance(entry, exit) / delta_s) + 1
    color, opacity = 0.0, 0.0
    for i in range(num_samples):
        t = i / (num_samples - 1)
        sample_point = lerp(entry, exit, t)
        scalar = interpolate_scalar(sample_point, cell)
        color, opacity = composite_sample(color, opacity, scalar)
    return color, opacity
```

**Parameters:**
*   **Sampling Interval ($\Delta s$):** Equi-distant sampling is used. The value must be chosen such that $\Delta s$ is small enough to guarantee at least one sample per cell [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Sorting Order:** The original algorithm sorts ff-external faces by centroid x-coordinates, which is an approximate order that may be incorrect [S1, unofficial]. The modified approach described here avoids this by scan-converting faces in any order and generating rays per pixel, ensuring correctness [S1, unofficial].
*   **Parallel Vectors:** If the projection of vectors $\vec{AC}$ and $\vec{AD}$ are parallel, the face is perpendicular to the screen, and the ray cannot exit through that face in the projected sense. Test another face [S1, unofficial].
*   **Precision:** Barycentric coordinate validation ($\alpha > 0, \beta > 0, \alpha + \beta < 1$) is sensitive to floating-point precision. Use a small epsilon for comparisons [G].

## Subtopics

### [Local Rendering Phase](4496-local-rendering-phase.md)
The core computation step in the Object-Space parallel implementation. It handles spatial decomposition constraints within a single processing unit by treating local clusters as a single local subvolume, ensuring continuous ray-segments across pseudo-boundary faces.

### [Two-Pass Depth Ray Casting](3377-two-pass-depth-ray-casting.md)
A sibling method that uses two passes to determine depth and color, differing in its approach to handling occlusion and depth sorting.

### [Van Hook-Levoy Ray-Casting](3594-van-hook-levoy-ray-casting.md)
A sibling method that uses a different traversal strategy, often involving pre-sorted lists or different data structures for cell traversal.
