# Ray Marching and Discretization

Also called: Ray Marching (Core Algorithm), Ray Marching for Volume Rendering

## Overview
Ray Marching and Discretization is the fundamental image-order rendering technique for direct volume ray casting, solving the volume rendering equation by discretizing the continuous ray path into a finite sequence of sample points [S1][S6, unofficial]. It differs from [Ray Traversal Schemes](6890-ray-traversal-schemes.md) by using fixed or adaptive step sizes along the ray direction rather than traversing voxel connectivity, and from [Monte Carlo Path Tracing for Volume Rendering](4980-monte-carlo-path-tracing-for-volume-rendering.md) by using deterministic quadrature instead of stochastic sampling [S3][S6, unofficial]. The method is distinguished by its simplicity and GPU-friendliness, typically implemented in fragment shaders to accumulate color and opacity via front-to-back compositing [S2, S5, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera parameters (origin $\mathbf{o}$, direction $\mathbf{d}$), volume domain bounds (bounding box or implicit function), volume data (3D texture or procedural function), transfer function (mapping scalar values to color/opacity), and rendering parameters (number of steps $N$, step size $\Delta t$, clipping planes) [S2, S5, unofficial][S8].
*   **Outputs:** Final pixel color $C_{out}$ and opacity $\alpha_{out}$ [S1][S5, unofficial].

**Data Structures:**
*   **Volume Data:** Typically stored in a 3D texture (e.g., `volume` in [S8]) or accessed via a procedural function (e.g., `sampleValue` in [S5, unofficial]). The texture contains scalar values (density/extinction coefficient) [S8].
*   **Colormap/Transfer Function:** A 1D or 2D texture mapping scalar values to RGBA color and opacity [S8].
*   **Accumulators:** Two variables, $C_{in}$ (accumulated color) and $\alpha_{in}$ (accumulated opacity/transmittance), initialized to $(0, 0)$ [S15, S46, unofficial].

**Numbered Steps:**

1.  **Ray Generation and Discretization:**
    *   Define the ray $r(t) = \mathbf{o} + t\mathbf{d}$ [G].
    *   Intersect the ray with the volume's bounding box (or slice planes) to find the entry parameter $t_{start}$ and exit parameter $t_{end}$ [S1][S5, unofficial][S8]. If no intersection, discard the pixel [S8].
    *   Calculate the total path length $L = t_{end} - t_{start}$ [S5, unofficial].
    *   Discretize the segment into $N$ steps with step size $\Delta t = L / N$ [S5, S10, S17, unofficial]. Alternatively, $\Delta t$ may be a fixed uniform parameter [S8].

2.  **Sampling Loop:**
    *   Initialize $C_{in} = 0$, $\alpha_{in} = 0$ [S15, S46, unofficial].
    *   For $i = 0$ to $N-1$:
        *   Calculate sample position: $\mathbf{p}_i = \mathbf{o} + (t_{start} + i \cdot \Delta t) \mathbf{d}$ [S5, unofficial][S8].
        *   Query the volume at $\mathbf{p}_i$ to get scalar value $V_i$ [S2, S5, unofficial][S8].
        *   **Classification:** Map $V_i$ to color $C_i$ and extinction coefficient $\sigma_i$ using the transfer function/colormap [S2, unofficial][S8].
        *   **Opacity Correction:** Calculate the sample opacity $\alpha_i$ using the Beer-Lambert law approximation:
            $$ \alpha_i = 1 - e^{-\sigma_i \Delta t} $$
            where $\sigma_i$ is derived from $V_i$ (e.g., $V_i$ itself or scaled) [S2, S5, S24, S30, unofficial].
        *   **Compositing:** Update accumulators using front-to-back blending:
            $$ C_{out} = C_{in} + (1 - \alpha_{in}) \cdot C_i \cdot \alpha_i $$
            $$ \alpha_{out} = \alpha_{in} + (1 - \alpha_{in}) \cdot \alpha_i $$
            where $C_{in}$ and $\alpha_{in}$ are the values from the previous iteration (or initial 0) [S1, S2, S13, S52, S60, unofficial].
        *   **Early Termination:** If $\alpha_{out}$ exceeds a threshold (e.g., 0.95 or 0.99), break the loop [S1][S2, unofficial][S8]. This optimization does not affect the final appearance significantly [S1].

3.  **Output:**
    *   Write $C_{out}$ and $\alpha_{out}$ to the framebuffer [S5, unofficial][S8].

**Pseudocode (GLSL-like, adapted from [S5, unofficial][S8]):**

```glsl
// Inputs: rayOrigin, rayDirection, volumeTexture, colormapTexture, numSteps, boxMin, boxMax
// Outputs: fragColor

void main() {
    // 1. Ray-Box Intersection
    vec3 tMin = (boxMin - rayOrigin) / rayDirection;
    vec3 tMax = (boxMax - rayOrigin) / rayDirection;
    vec3 tEntry = max(max(tMin.x, tMin.y), tMin.z);
    vec3 tExit = min(min(tMax.x, tMax.y), tMax.z);

    if (tEntry > tExit || tExit < 0.0) {
        fragColor = vec4(0.0);
        return;
    }

    float tStart = max(tEntry.x, 0.0); // Handle rays starting inside
    float tEnd = tExit;
    float stepLength = (tEnd - tStart) / float(numSteps);

    // 2. Initialization
    vec3 accumulatedColor = vec3(0.0);
    float accumulatedAlpha = 0.0;
    float currentT = tStart;

    // 3. Marching Loop
    for (int i = 0; i < numSteps; ++i) {
        // Advance ray
        currentT += stepLength;
        
        // Check if still within bounds (for variable step or clipping)
        if (currentT > tEnd) break;

        // Sample position
        vec3 pos = rayOrigin + rayDirection * currentT;
        
        // Query Volume
        float density = texture(volumeTexture, pos).r; // Scalar value
        
        // Classification (Simplified: assuming density maps to alpha directly or via colormap)
        // In [S8], alpha is derived from colormap lookup and stepAlpha
        vec4 colorData = texture(colormapTexture, vec2(density, 0.5));
        float alphaSample = colorData.a; 
        
        // Opacity Correction (Beer-Lambert)
        // If using explicit extinction coefficient sigma:
        // float sigma = density; 
        // alphaSample = 1.0 - exp(-sigma * stepLength);
        
        // Compositing
        float transmittance = 1.0 - accumulatedAlpha;
        accumulatedColor += transmittance * colorData.rgb * alphaSample;
        accumulatedAlpha += transmittance * alphaSample;

        // Early Termination
        if (accumulatedAlpha >= 0.95) break;
    }

    fragColor = vec4(accumulatedColor, accumulatedAlpha);
}
```

**Parameters:**
*   `numSteps` ($N$): Number of samples per ray. Typical values: 32–256 [S5, unofficial][S8]. Higher values improve quality but increase cost [S5, unofficial].
*   `stepLength` ($\Delta t$): Can be fixed or derived from $N$ [S5, unofficial][S8].
*   `boxMin`, `boxMax`: World-space bounds of the volume [S5, unofficial][S8].
*   `colormapTexture`: Transfer function texture [S8].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point errors in ray-box intersection can cause gaps or overlaps; use epsilon offsets [S5, unofficial].
*   **Aliasing:** Fixed step sizes can cause aliasing if the step size is larger than the Nyquist limit of the volume data [S3].
*   **Early Termination Bias:** While early termination is standard, it can miss subtle transparent details if the threshold is too high [S8].
*   **Empty Space:** If the volume has large empty regions, fixed stepping is inefficient. Adaptive methods (e.g., [Exponential Approximation Method](2079-exponential-approximation-method.md) or [Discrete Ray Tracing](3020-discrete-ray-tracing.md)) are preferred [S3].

### Low Albedo Discrete VRE (Alpha Blending Form)
A discrete VRE form derived by approximating transmittance using the first two terms of its Taylor series expansion and assuming low albedo ($\sigma_t \approx \sigma_a, \sigma_s \approx 0$) [S10]. The opacity is approximated as $\alpha_i \approx \sigma_a(\mathbf{p}_i, \omega) \Delta s$ [S10]. The final color is computed as $C = \sum_{i=0}^{N-1} [ C_i \alpha_i \prod_{j=i+1}^{N-1} (1 - \alpha_j) ]$, interpreted as alpha blending where $C_i$ is the emission $L_e(\mathbf{p}_i, \omega)$ [S10]. This differs from standard discrete VRE by applying low albedo and Taylor approximations, replacing the source term $L_i \Delta s$ with emission $L_e$ [S10].

### Beam Pre-pass
A coarse pre-pass that computes first-hit distances at low resolution (1/8 resolution, one ray per 8×8 block) to fast-forward the main raymarch pass [S11, unofficial]. Each ray walks the world at tile granularity and writes the first-hit distance to an `r32float` texture [S11, unofficial]. The main pass fast-forwards each ray to that depth minus a 16-voxel safety margin [S11, unofficial].

### Hybrid Rendering
Combines semi-transparent volume representation with surface-based mesh representations [S12]. For rays intersecting the mesh, ray marching stops at $t_{max}$ (mesh depth), and the remaining color throughput is filled with the mesh color at the intersection point [S12].

### ROVER Volume Rendering Pipeline
A distributed ray casting method that initializes rays with a fixed direction $(1.0, 1.0, 1.0)$ and weight/alpha 0.0 [S13, unofficial]. It computes a uniform sample distance from domain bounds: $\text{sample\_distance} = \|\text{domain\_extent}\| / \text{num\_samples}$, where $\text{domain\_extent} = (X_{max}-X_{min}, Y_{max}-Y_{min}, Z_{max}-Z_{min})$ [S13, unofficial]. The marching loop is delegated to a VTK-m proxy tracer [S13, unofficial]. Pitfalls include runtime errors if no valid dataset is set or if surface rendering mode is called (unimplemented) [S13, unofficial].

### Parallel Analytic Marching
A parallelization strategy where multiple initial points are solved simultaneously to march towards all unsolved analytic cells in the active set [S14]. It initializes multiple points $\mathbf{x}$ in $\mathbb{Z}$ in parallel by solving Eq 17, then marches towards all analytic cells in $S$ that are unsolved [S14]. This provides an efficiency improvement of order 10 on Nvidia GPUs compared to sequential execution [S14].

### Interpolated Shading
Uses linear interpolation to shade entire patches of up to 10×10 pixels, allowing fewer than one sample per pixel [S15, unofficial]. When hitting an object, it queries ahead, checks if all four corners of the current quad are inside the object, and compares normals to ensure alignment [S15, unofficial]. This is an approximation best suited for flat-shaded objects [S15, unofficial]. On a MacBook Air M1, it renders a simple SDF object at up to 100 FPS [S15, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of steps per ray and $P$ is the number of pixels [S5, unofficial]. Performance scales linearly with $N$ [S5, unofficial].
*   **Memory Complexity:** $O(V)$ for volume storage, where $V$ is the number of voxels [S5, unofficial][S8].
*   **Performance:** Fixed-step ray marching is highly parallelizable on GPUs [S2, S5, unofficial]. Typical frame rates depend on $N$ and volume resolution; 32–64 steps are common for real-time [S5, unofficial].
*   **Strengths:** Simple implementation, efficient on GPUs, supports real-time rendering [S1][S2, unofficial].
*   **Limitations:** Fixed steps can be inefficient for sparse volumes (aliasing or wasted samples) [S3]. Early termination can introduce bias if not handled carefully [S8].
*   **When to Use:** Real-time volume rendering, dense volumes, GPU-based applications [S1][S2, unofficial].
*   **When Not to Use:** Sparse volumes with large empty regions (use [Discrete Ray Tracing](3020-discrete-ray-tracing.md) or [Ray Traversal Schemes](6890-ray-traversal-schemes.md)), or when exact physical accuracy with complex scattering is required (use [Monte Carlo Path Tracing](4980-monte-carlo-path-tracing.md)) [S3][S6, unofficial].

## Background
Ray marching for volume rendering originated as a practical method to solve the volume rendering equation with real-time performance by querying and accumulating contributions from sample points along rays [S1]. It was popularized in the context of GPU-based rendering, where fragment shaders perform the ray marching loop [S2, S5, unofficial]. The technique is widely used in medical imaging, scientific visualization, and real-time graphics (e.g., smoke, fog) [S1][S5, unofficial]. It is also the core algorithm for rendering Neural Radiance Fields (NeRF) and Signed Distance Functions (SDFs) [S6, unofficial].
