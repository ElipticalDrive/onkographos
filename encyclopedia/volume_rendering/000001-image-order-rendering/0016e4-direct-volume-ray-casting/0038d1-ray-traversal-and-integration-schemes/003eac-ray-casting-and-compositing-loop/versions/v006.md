# Ray Casting and Compositing Loop

Also called: Basic Ray Casting, Ray Casting Volume Rendering, Single pass GPU Ray casting, Standard Ray Casting Loop

## Overview
The Ray Casting and Compositing Loop is the fundamental image-order rendering technique for direct volume rendering, where scalar volume data is mapped directly to color and opacity without explicit surface extraction [S1, unofficial]. It solves the problem of visualizing internal structures by integrating light transport along rays cast from the camera through the volume [S1, unofficial]. Unlike [IsoSurface Ray Marching](4324-front-to-back-volume-ray-casting-with-hsv-shading-and-sos-at.md), which detects zero crossings and computes normals, this method uses direct scalar-to-color mapping and front-to-back compositing [S1, unofficial]. It builds on the [Image-order rendering](16-image-order-rendering.md) paradigm, operating on the fundamental loop structure where for each pixel, a ray is defined, intersected with the volume domain, and sampled/composited along its path [G].

## How it works
The method operates on the fundamental loop structure of [Image-order rendering](16-image-order-rendering.md): for each pixel, a ray $r(t) = \mathbf{o} + t\mathbf{d}$ is defined, intersected with the volume domain, and sampled/composited along its path [G]. The traversal order is determined by the pixel's position in the image plane [G].

The core computational engine consists of four sequential stages applied to each ray [S5, S10, S37, unofficial]:

1.  **Ray Generation and Discretization**: The ray segment $[t_{start}, t_{end}]$ intersecting the volume is determined, typically by intersecting the ray with the volume's bounding box [S1, unofficial][S8, S16, unofficial]. The segment is discretized into $N$ samples at equidistant intervals $\Delta t = (t_{end} - t_{start}) / N$ [S5, S10, S17, unofficial].
2.  **Sampling and Interpolation**: At each sample point $\mathbf{p}_i = r(t_i)$, the scalar value $V(\mathbf{p}_i)$ is retrieved from the volume data. This is typically performed by trilinear interpolation of the eight surrounding voxels [S9, S11, S47, unofficial].
3.  **Classification (Transfer Function)**: The scalar value $V(\mathbf{p}_i)$ is mapped to optical properties: color $C_i$ and opacity $\alpha_i$ [S2, S2789]. The opacity is often corrected for the step size $\Delta t$ to ensure physical consistency, using the Beer-Lambert law approximation:
    $$ \alpha_i = 1 - e^{-\sigma_i \Delta t} $$
    where $\sigma_i$ is the extinction coefficient derived from the scalar value [S24, S30, unofficial].
4.  **Compositing**: The samples are accumulated from front to back (closest to the eye to furthest) using the front-to-back alpha compositing equation [S1, unofficial][S2, S13, unofficial][S61]:
    $$ C_{out} = C_{in} + (1 - \alpha_{in}) \cdot C_{sample} \cdot \alpha_{sample} $$
    $$ \alpha_{out} = \alpha_{in} + (1 - \alpha_{in}) \cdot \alpha_{sample} $$
    where $C_{in}$ and $\alpha_{in}$ are the accumulated color and opacity from previous samples, and $C_{sample}$ and $\alpha_{sample}$ are the color and opacity of the current sample [S52, S60, unofficial]. The process initializes with $C_{in} = 0$ and $\alpha_{in} = 0$ [S15, S46, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   Volume data: 3D texture or scalar field $V(x,y,z)$ [S1, unofficial].
    *   Camera parameters: Origin $\mathbf{o}$, direction $\mathbf{d}$, field of view, and near/far planes [G].
    *   Transfer function: Mapping from scalar value to color $C$ and extinction coefficient $\sigma$ (or direct opacity) [S2, unofficial].
    *   Step size $\Delta t$ or number of steps $N$ [S1, unofficial].
*   **Outputs**:
    *   Final pixel color $C_{out}$ and opacity $\alpha_{out}$ [S1, unofficial].

### Data Structures
*   **Volume Data**: Stored as a 3D texture (e.g., `sampler3D` in OpenGL) or a linear array of voxels [S1, unofficial].
*   **Ray State**: Accumulated color $C_{in}$ (vec3) and opacity $\alpha_{in}$ (float) [S1, unofficial].
*   **Sample Point**: Current position $\mathbf{p}$ along the ray [S1, unofficial].

### Pseudocode
The following pseudocode implements the standard single-pass GPU ray casting loop as described in [S1, unofficial]. It assumes a fragment shader context where `FragColor` is the output variable.

```python
# Initialization
# oTexCoords: Interpolated 3D texture coordinates for the ray origin [S1, unofficial]
# u_cameraPosition: Camera position in world space [S1, unofficial]
# u_stepSize: Uniform step size for ray marching [S1, unofficial]
# MAX_SAMPLES: Maximum number of steps per ray (e.g., 300) [S1, unofficial]
# EarlyTerminationThreshold: Opacity threshold to stop (e.g., 0.99) [S2, unofficial]

# 1. Calculate Ray Direction
# geometryDirection is derived from texture coordinates and camera position
geometryDirection = normalize(oTexCoords - 0.5 - u_cameraPosition)

# 2. Initialize Accumulators
FragColor.rgb = vec3(0.0)
FragColor.a = 0.0

# 3. Ray Marching Loop
dataPosition = oTexCoords # Start at interpolated texture coordinates [S1, unofficial]

for i from 0 to MAX_SAMPLES:
    # 4. Sample Volume
    # fSample is the scalar value at the current position
    fSample = texture(u_Volume3DSampler, dataPosition).r
    
    # 5. Classification and Compositing
    # Map scalar to color and opacity. 
    # Note: In this specific implementation [S1, unofficial], 
    # the scalar value is used directly as color intensity 
    # and opacity contribution is derived from it.
    
    # Calculate contribution based on current accumulated opacity
    prev_alpha = fSample - (fSample * FragColor.a)
    
    # Update RGB: Add contribution weighted by new alpha
    FragColor.rgb = prev_alpha * vec3(fSample) + FragColor.rgb
    
    # Update Alpha: Accumulate opacity
    FragColor.a += prev_alpha
    
    # 6. Advance Ray
    directionStep = geometryDirection * u_stepSize
    dataPosition = dataPosition + directionStep
    
    # 7. Boundary Check
    # Check if dataPosition is outside the volume bounds [texMin, texMax]
    # If dot(sign(dataPosition - texMin), sign(texMax - dataPosition)) < 3.0, break
    if dot(sign(dataPosition - texMin), sign(texMax - dataPosition)) < 3.0:
        break
        
    # 8. Early Ray Termination
    if FragColor.a > EarlyTerminationThreshold:
        break

# Output FragColor
```

### Parameters
*   `MAX_SAMPLES`: Constant integer defining the maximum number of ray march steps per ray. Value: 300 [S1, unofficial].
*   `EarlyTerminationThreshold`: Opacity threshold for early ray termination. Value: 0.99 [S2, unofficial].
*   `u_stepSize`: Uniform step size for ray marching. Value: Not given in the sources.

### Edge Cases and Pitfalls
*   **Boundary Intersection**: The ray must be intersected with the boundary of the volume to find all intervals within the (possibly nonconvex) hull of the grid [S2, unofficial].
*   **Ill-defined Approximation**: If using MLS (Moving Least Squares) functions, the approximation is ill-defined away from data points, making boundary intersection points important [S2, unofficial].
*   **Precision**: Floating-point precision issues may arise when checking boundary conditions or accumulating opacity.

## Subtopics

### [Wavelet-Assisted Volume Ray Casting](10893-wavelet-assisted-volume-ray-casting.md)
Wavelet-Assisted Volume Ray Casting is an acceleration technique for direct volume rendering that uses wavelet coefficients to detect local frequency content and determine an adaptive sampling distance along each ray. It solves the problem of excessive computational cost in standard ray casting by avoiding on-the-fly reconstruction from the wavelet domain; instead, it pre-computes an "index volume" that guides the traversal of the original spatial volume. Unlike Westermann's method, which traverses wavelet coefficients directly, this approach uses a flat index volume to skip samples, combining spatial domain rendering with wavelet-based frequency analysis. See [Wavelet-Assisted Volume Ray Casting](10893-wavelet-assisted-volume-ray-casting.md).

### Multi-Cast / Super-Sampling Ray Casting
Instead of sampling one ray per pixel, sample 4 rays per pixel to improve image quality [S3, unofficial]. Produces better image quality but takes four times longer to render [S3, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(P \cdot N)$, where $P$ is the number of pixels and $N$ is the number of samples per ray [S3, unofficial].
*   **Memory Complexity**: $O(V)$, where $V$ is the volume of the 3D texture [S3, unofficial].
*   **Performance**: Single-pass GPU ray casting is efficient for real-time rendering but can be limited by memory bandwidth and interpolation costs [S1, unofficial].
*   **Strengths**: Simple to implement, supports arbitrary transfer functions, handles transparency well [S1, unofficial].
*   **Limitations**: High computational cost for large volumes, aliasing artifacts if step size is too large [S3, unofficial].
*   **When to Use**: Real-time visualization, interactive exploration [S1, unofficial].
*   **When Not to Use**: High-quality offline rendering requiring complex lighting effects [S1, unofficial].

## Background
The Ray Casting and Compositing Loop is a foundational technique in volume rendering, originating from the work of Levoy and others in the early 1990s [S1, unofficial]. It has been widely implemented in GPU-based renderers due to its parallelizable nature [S1, unofficial].
