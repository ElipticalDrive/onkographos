# Front-to-Back Volume Ray Casting with HSV Shading and SOS/Attenuation/Reflection Filtering

Also called: Front-to-Back Volume Ray Casting

## Overview
This method performs direct volume rendering by casting rays from the camera through a 3D volume, sampling voxel data, and compositing results front-to-back using alpha blending [S1, unofficial]. It distinguishes itself by mapping multi-component volume values (Scalar Output Scalar, Attenuation, Reflection) to an HSV color space for shading, rather than using standard gradient-based Phong lighting or direct RGBA transfer functions [S1, unofficial]. It employs specific thresholding filters on the SOS, Attenuation, and Reflection components to discard irrelevant samples before color conversion [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume represented as a set of 2D texture slices (`uSliceMaps`), entry and exit point coordinates for each pixel (stored in `frontColor` and `uBackCoord` textures), and rendering parameters (`uStepsI`, `uOpacityVal`, thresholds).
*   **Output:** A final RGBA color (`gl_FragColor`) for each pixel.

**Data Structures:**
*   **Volume Texture:** A collection of 2D textures (`uSliceMaps`) representing Z-slices of the volume. Each texel stores a 3-component vector (RGB) representing SOS, Attenuation, and Reflection values [S1, unofficial].
*   **Entry/Exit Textures:** `frontColor` (varying vec4) stores the entry point coordinates; `uBackCoord` (sampler2D) stores the exit point coordinates [S1, unofficial].
*   **Accumulators:** `accum` (vec4) stores the accumulated color and alpha; `sample` (vec4) stores the current sample's contribution [S1, unofficial].

**Parameters:**
*   `uStepsI`: Integer constant for the number of steps per ray (default 144) [S1, unofficial].
*   `uOpacityVal`: Float controlling opacity scaling (default 40) [S1, unofficial].
*   `minSos`, `maxSos`: Thresholds for the first component (SOS) [S1, unofficial].
*   `minAtten`, `maxAtten`: Thresholds for the second component (Attenuation) [S1, unofficial].
*   `minRefl`, `maxRefl`: Thresholds for the third component (Reflection) [S1, unofficial].
*   `uSlicesOverX`, `uSlicesOverY`: Dimensions of the texture atlas (e.g., 16x16) [S1, unofficial].
*   `uNumberOfSlices`: Total number of Z-slices [S1, unofficial].

**Steps:**

1.  **Ray Initialization:**
    For each pixel, calculate texture coordinates `texC` from the fragment position `pos`:
    $$ \text{texC} = \frac{(\text{pos}.xy / \text{pos}.w) + 1.0}{2.0} $$
    Retrieve the exit point `backColor` from `uBackCoord` using `texC` [S1, unofficial].
    Calculate the ray direction vector:
    $$ \mathbf{dir} = \text{backColor}.rgb - \text{frontColor}.rgb $$
    Initialize the current position `vpos` to `frontColor` [S1, unofficial].
    Calculate the step size vector:
    $$ \mathbf{Step} = \frac{\mathbf{dir}}{\text{uStepsI}} $$
    Initialize `accum` to $(0,0,0,0)$ and `sample` to $(0,0,0,0)$ [S1, unofficial].

2.  **Ray Marching Loop:**
    Iterate $i$ from $0$ to $\text{uStepsI} - 1$:
    
    a. **Volume Sampling:**
    Retrieve the volume value at `vpos.xyz` using `getVolumeValue(vpos.xyz)`. This function maps the 3D coordinate to the appropriate 2D slice texture based on `uSlicesOverX`, `uSlicesOverY`, and `uNumberOfSlices`, performing bilinear interpolation within the slice [S1, unofficial]. Let the result be `gray_val` (vec3) representing SOS, Attenuation, and Reflection [S1, unofficial].

    b. **Filtering:**
    If any of the following conditions are met, set `colorValue` to $(0,0,0,0)$ and skip shading:
    *   `gray_val.z < 0.05` (Reflection threshold) [S1, unofficial]
    *   `gray_val.x < minSos` or `gray_val.x > maxSos` (SOS threshold) [S1, unofficial]
    *   `gray_val.y < minAtten` or `gray_val.y > maxAtten` (Attenuation threshold) [S1, unofficial]
    *   `gray_val.z < minRefl` or `gray_val.z > maxRefl` (Reflection threshold) [S1, unofficial]

    c. **HSV Color Mapping:**
    If the sample passes filtering, compute `colorValue` components:
    $$ \text{colorValue}.x = \text{gray\_val}.x \quad (\text{Hue}) $$
    $$ \text{colorValue}.y = 1.0 - \frac{\text{gray\_val}.y}{0.6} \quad (\text{Saturation}) $$
    $$ \text{colorValue}.z = \text{gray\_val}.z \quad (\text{Value}) $$
    $$ \text{colorValue}.w = 0.1 \quad (\text{Base Alpha}) $$
    [S1, unofficial]

    d. **Alpha Calculation:**
    Compute the sample's alpha:
    $$ \text{sample}.a = \text{colorValue}.a \times \text{uOpacityVal} \times \frac{1.0}{\text{uStepsI}} $$
    [S1, unofficial]
    *Note: Some implementations adjust alpha for step size using `1.0 - pow(1.0 - colorSample.a, StepSize*200.0)` [S1, unofficial]. The primary method uses the linear scaling above.*

    e. **RGB Conversion and Accumulation:**
    Convert HSV to RGB:
    $$ \text{sample}.rgb = (1.0 - \text{accum}.a) \times \text{hsv2rgb}(\text{colorValue}.rgb) \times \text{sample}.a $$
    Update the accumulator:
    $$ \text{accum} += \text{sample} $$
    [S1, unofficial]

    f. **Termination Checks:**
    *   If `accum.a >= 1.0`, break the loop [S1, unofficial].
    *   Advance position: `vpos.xyz += Step` [S1, unofficial].
    *   If `vpos.x`, `vpos.y`, or `vpos.z` is outside $[0.0, 1.0]$, break the loop [S1, unofficial].

3.  **Output:**
    Output `accum` as `gl_FragColor` [S1, unofficial].

**HSV to RGB Conversion:**
The `hsv2rgb` function converts HSV coordinates to RGB. Standard conversion logic applies:
$$
\begin{aligned}
&\text{if } H \ge 1, H = 1 \\
&\text{if } S \le 0, \text{return } V \\
&\text{let } i = \lfloor H \times 6 \rfloor \\
&\text{let } f = H \times 6 - i \\
&\text{let } p = V \times (1 - S) \\
&\text{let } q = V \times (1 - f \times S) \\
&\text{let } t = V \times (1 - (1 - f) \times S) \\
&\text{switch } i \% 6: \\
&\quad 0: R=V, G=t, B=p \\
&\quad 1: R=q, G=V, B=p \\
&\quad 2: R=p, G=V, B=t \\
&\quad 3: R=p, G=q, B=V \\
&\quad 4: R=t, G=p, B=V \\
&\quad 5: R=V, G=p, B=q
\end{aligned}
$$
[G] Standard HSV to RGB conversion formula.

**Pseudocode:**

```python
def front_to_back_hsv_ray_casting(front_color, back_coord_texture, slice_maps, 
                                  u_steps_i, u_opacity_val, min_sos, max_sos, 
                                  min_atten, max_atten, min_refl, max_refl,
                                  u_slices_over_x, u_slices_over_y, u_number_of_slices):
    # 1. Ray Initialization
    # pos is assumed to be available from the fragment shader context
    tex_c = ((pos.xy / pos.w) + 1.0) / 2.0
    back_color = texture2D(back_coord_texture, tex_c)
    
    dir_vec = back_color.rgb - front_color.rgb
    vpos = front_color.xyz
    
    step_vec = dir_vec / u_steps_i
    
    accum = vec4(0.0, 0.0, 0.0, 0.0)
    
    # 2. Ray Marching Loop
    for i in range(u_steps_i):
        # a. Volume Sampling
        gray_val = get_volume_value(vpos, slice_maps, u_slices_over_x, 
                                    u_slices_over_y, u_number_of_slices)
        
        # b. Filtering
        if (gray_val.z < 0.05 or 
            gray_val.x < min_sos or gray_val.x > max_sos or
            gray_val.y < min_atten or gray_val.y > max_atten or
            gray_val.z < min_refl or gray_val.z > max_refl):
            color_value = vec4(0.0, 0.0, 0.0, 0.0)
        else:
            # c. HSV Color Mapping
            color_value = vec4(
                gray_val.x,          # H
                1.0 - gray_val.y / 0.6, # S
                gray_val.z,          # V
                0.1                  # A
            )
        
        # d. Alpha Calculation
        sample_alpha = color_value.w * u_opacity_val * (1.0 / u_steps_i)
        
        # e. RGB Conversion and Accumulation
        sample_rgb = (1.0 - accum.a) * hsv2rgb(color_value.rgb) * sample_alpha
        accum.rgb += sample_rgb
        accum.a += sample_alpha * (1.0 - accum.a) # Standard over operator for alpha
        
        # f. Termination Checks
        if accum.a >= 1.0:
            break
            
        vpos += step_vec
        
        if vpos.x < 0.0 or vpos.x > 1.0 or \
           vpos.y < 0.0 or vpos.y > 1.0 or \
           vpos.z < 0.0 or vpos.z > 1.0:
            break
            
    return accum

def get_volume_value(volpos, slice_maps, u_slices_over_x, u_slices_over_y, u_number_of_slices):
    slices_per_sprite = u_slices_over_x * u_slices_over_y
    s1_original = floor(volpos.z * u_number_of_slices)
    tex1_index = int(floor(s1_original / slices_per_sprite))
    s1 = mod(s1_original, slices_per_sprite)
    
    dx1 = fract(s1 / u_slices_over_x)
    dy1 = floor(s1 / u_slices_over_y) / u_slices_over_y
    
    texpos1 = vec2(
        dx1 + (volpos.x / u_slices_over_x),
        dy1 + (volpos.y / u_slices_over_y)
    )
    
    # Assuming slice_maps is an array of textures
    value = texture2D(slice_maps[tex1_index], texpos1).xyz
    return value

def hsv2rgb(hsv):
    h, s, v = hsv
    if h >= 1.0: h = 1.0
    if s <= 0.0: return vec3(v, v, v)
    
    i = floor(h * 6.0)
    f = h * 6.0 - i
    p = v * (1.0 - s)
    q = v * (1.0 - f * s)
    t = v * (1.0 - (1.0 - f) * s)
    
    i = int(i) % 6
    if i == 0: return vec3(v, t, p)
    if i == 1: return vec3(q, v, p)
    if i == 2: return vec3(p, v, t)
    if i == 3: return vec3(p, q, v)
    if i == 4: return vec3(t, p, v)
    if i == 5: return vec3(v, p, q)
```

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of pixels and $P$ is the number of steps per ray (fixed at 144 in the reference implementation) [S1, unofficial].
*   **Memory Complexity:** $O(V)$ for the volume data, stored as 2D texture slices [S1, unofficial].
*   **Performance:** The fixed step count (144) provides predictable performance but lacks the efficiency of adaptive stepping methods that vary step size based on density gradients [S1, unofficial]. Early termination on opacity saturation ($\alpha \ge 1.0$) or boundary exit reduces average computation time [S1, unofficial].
*   **Strengths:** Simple implementation using standard 2D texture lookups; HSV mapping provides intuitive color control for multi-component data; filtering reduces noise from irrelevant data [S1, unofficial].
*   **Limitations:** Fixed step size may lead to aliasing or slow convergence; HSV mapping may not preserve physical meaning of data as well as direct RGBA transfer functions; no gradient-based shading for depth cues [S1, unofficial].
*   **When to use:** Real-time visualization of multi-component volume data where color mapping is prioritized over physical accuracy; when hardware supports efficient 2D texture sampling but not 3D textures [S1, unofficial].
*   **When not to use:** High-quality offline rendering requiring gradient-based lighting; scenes with highly variable density requiring adaptive stepping [S1, unofficial].
