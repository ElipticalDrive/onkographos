# Dynamic Luminance Information (DLI) Smoke Animation

Also called: DLI compositing method, Illusive smoke animation

## Overview
Dynamic Luminance Information (DLI) Smoke Animation is a technique for creating the illusion of volumetric smoke animation by compositing a time-varying 2D luminance layer onto a static Computer Graphics (CG) base image [S1]. It solves the problem of high computational cost associated with frame-by-frame volume rendering of participating media [S1]. Unlike standard Direct Volume Ray Casting [19-direct-volume-ray-casting.md], which requires full integration for every frame due to medium movement, DLI renders a single static base image and overlays a procedurally generated noise texture, significantly shortening creation time while preserving perceptual quality [S1].

## How it works
The method operates in two main phases: base image generation and DLI compositing.

**Inputs and Outputs**
*   **Inputs:**
    *   Scene geometry and lighting parameters for a CG scene.
    *   Reference extinction coefficient $\sigma_0$ (from a volume-rendered reference image).
    *   Target extinction coefficient $\sigma_0'$ (for the desired animation intensity).
    *   Frame number $f$ for animation timing.
    *   Number of octaves $O$ for noise generation.
*   **Outputs:**
    *   A final animated image sequence where smoke appears to move over the static CG scene.

**Data Structures**
*   **Base Image:** A 2D grid of RGB color values, rendered without participating media effects.
*   **DLI Layer:** A 2D grid of values where each pixel stores a luminance value between 0 and 1 [S1]. This layer is generated per frame.

**Steps**

1.  **Render Base Image:** Render a single still image of the CG scene without considering the smoke medium. The method uses Multiplexed Metropolis Light Transport (MMLT) to efficiently calculate light paths connecting light sources to the camera, accounting for reflection and refraction but ignoring volumetric attenuation [S1].
2.  **Establish Reference:** Create a reference volume-rendered image to determine the baseline extinction coefficient $\sigma_0$ and the average luminance $L_{ref}$ of the first frame [S1].
3.  **Calculate Ratio:** Compute the ratio $r$ of the reference extinction coefficient to the target extinction coefficient:
    $$ r = \frac{\sigma_0}{\sigma_0'} $$
    This ratio determines the scaling factor for the luminance layer [S1].
4.  **Generate Noise:** Generate a Perlin noise image using the spatial coordinates of the reference image and the current frame number as the time argument. The function $N$ is defined as:
    $$ N(x, y, f, O, P) $$
    where $x$ and $y$ are the vertical and horizontal coordinates of the reference image, $f$ is the frame number, $O$ is the number of octaves, and $P$ represents other noise parameters [S1].
5.  **Apply Corrections:** Apply gamma correction and depth correction to the generated noise image to ensure the luminance values align with the lighting and depth cues of the base image [S1].
6.  **Composite:** Overlay the corrected DLI layer onto the base image. The luminance $L$ of the DLI is determined from the ratio $r$ calculated in Step 3 [S1].

**Pseudocode**

```python
def render_dli_smoke_animation(scene, sigma_0, sigma_0_prime, num_frames, octaves):
    """
    Renders an animated smoke illusion using DLI compositing.
    
    Args:
        scene: Object containing geometry and lighting for MMLT rendering.
        sigma_0: Reference extinction coefficient from a volume-rendered baseline.
        sigma_0_prime: Target extinction coefficient for the animation.
        num_frames: Total number of frames in the animation.
        octaves: Number of octaves for Perlin noise generation.
        
    Returns:
        List of rendered image frames.
    """
    # Step 1: Render static base image without medium
    base_image = render_mmlt(scene)
    
    # Step 3: Calculate luminance scaling ratio
    ratio = sigma_0 / sigma_0_prime
    
    frames = []
    
    for f in range(num_frames):
        # Step 4: Generate Perlin noise DLI layer
        # x, y are coordinates of the base image
        # f is the time argument
        dli_layer = generate_octave_perlin_noise(
            width=base_image.width,
            height=base_image.height,
            time_arg=f,
            octaves=octaves
        )
        
        # Step 5: Apply corrections
        # Gamma correction ensures perceptual linearity
        dli_layer = apply_gamma_correction(dli_layer)
        
        # Depth correction adjusts luminance based on scene depth
        # Note: Depth buffer from base_image is required
        depth_buffer = get_depth_buffer(base_image)
        dli_layer = apply_depth_correction(dli_layer, depth_buffer)
        
        # Scale luminance by the extinction ratio
        dli_layer = dli_layer * ratio
        
        # Step 6: Composite
        # Assuming additive or alpha blending depending on specific implementation
        # The source implies overlaying luminance information
        final_frame = composite(base_image, dli_layer)
        
        frames.append(final_frame)
        
    return frames

def generate_octave_perlin_noise(width, height, time_arg, octaves):
    """
    Generates a 2D noise texture using octave Perlin noise.
    """
    noise_image = empty_grid(width, height)
    
    for y in range(height):
        for x in range(width):
            # Generate noise value for this pixel
            # The source defines N(x, y, f, O, P)
            # We assume a standard Perlin noise implementation
            value = perlin_noise(x, y, time_arg, octaves)
            noise_image[y, x] = value
            
    return noise_image
```

**Edge Cases and Pitfalls**
*   **Precision:** The ratio $r$ must be handled carefully if $\sigma_0'$ is close to zero to avoid division by zero or extreme luminance values [S1].
*   **Boundary Conditions:** The Perlin noise generation uses image coordinates; ensure coordinate normalization matches the noise function's expectations [S1].
*   **Depth Correction:** Requires access to the depth buffer of the base image; if unavailable, depth correction cannot be applied, potentially reducing realism [S1].

## Operating characteristics
*   **Time Complexity:** Rendering time is dominated by the single MMLT base image render. The DLI layer generation is $O(W \times H \times F)$, where $W$ and $H$ are image dimensions and $F$ is the number of frames, but this is significantly faster than full volume rendering per frame.
*   **Memory Complexity:** Requires storing the base image, depth buffer, and the current DLI layer. Memory usage is $O(W \times H)$ per frame.
*   **Performance:** Significantly reduces creation time compared to frame-by-frame volume rendering [S1].
*   **Strengths:** Low computational cost; preserves perceptual quality of smoke movement; suitable for CG animations [S1].
*   **Limitations:** Does not account for dynamic lighting interactions with the moving smoke (e.g., shadows cast by smoke); relies on a static base image, so camera movement must be limited or simulated via 2D transforms [S1].
*   **When to Use:** When creating CG animations with volumetric smoke where real-time or near-real-time rendering is required, and the smoke does not significantly occlude dynamic light sources [S1].
*   **When Not to Use:** When accurate physical interaction between smoke and dynamic lighting is required, or when the camera moves extensively relative to the scene geometry [S1].

## Background
The method was proposed by the authors of [S1] to address the high computational cost of volume rendering for smoke animations. It builds on the concept of "HenGenTou," which projects DLI onto real-world still images, but extends it to Computer Graphics (CG) still images [S1]. The technique uses Multiplexed Metropolis Light Transport (MMLT) for the base image, combining Markov chain Monte Carlo methods with multi-focused sampling to efficiently construct light paths [S1].
