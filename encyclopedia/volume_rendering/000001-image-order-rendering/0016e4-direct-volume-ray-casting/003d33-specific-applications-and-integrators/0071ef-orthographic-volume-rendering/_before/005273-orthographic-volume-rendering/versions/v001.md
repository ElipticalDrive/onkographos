# Orthographic Volume Rendering

Also called: Canonical View Generation, Canonical View Setup

## Overview
Orthographic Volume Rendering generates a high-quality orthographic projection of a 3D volume by temporarily configuring a parallel projection camera, rendering to a full-resolution buffer, and resampling the result to the target resolution [S1, unofficial]. It differs from perspective-based volume rendering by eliminating depth-dependent distortion, ensuring that object sizes remain consistent regardless of their distance from the camera, which is critical for medical imaging and scientific visualization where metric accuracy is required [S1, unofficial].

## How it works
The method operates as a post-processing or specialized rendering pass that isolates the volume data, renders it with an orthographic camera, and downsamples the result.

**Inputs and Outputs:**
- **Input:** A `vtkRenderer` instance, a `vtkVolume` object, a target `vtkImageData` output buffer, a blend mode integer, and two 3D direction vectors (`viewDirection`, `viewUp`).
- **Output:** A 2D image (`vtkImageData`) representing the orthographic projection of the volume.

**Data Structures:**
- **`bigImage`**: A temporary RGB unsigned char image. Dimensions match the render window size (`size[0]`, `size[1]`, 1).
- **`scale`**: A 2D array of doubles storing magnification factors for resampling.
- **`bounds`**: The axis-aligned bounding box of the volume, typically an array of 6 doubles `[minX, maxX, minY, maxY, minZ, maxZ]`.
- **`center`**: The centroid of the volume bounds.

**Parameters:**
- **`viewDirection`**: The direction the camera is looking along (normalized).
- **`viewUp`**: The upward vector for the camera orientation (normalized and orthogonal to `viewDirection`).
- **`blend_mode`**: Integer specifying the compositing mode (e.g., additive, maximum intensity projection).

**Step-by-Step Procedure:**

1.  **Disable Buffer Swapping:** Prevent screen flicker during the temporary render setup by disabling buffer swapping on the render window [S1, unofficial].
    ```python
    ren.GetRenderWindow().SwapBuffersOff()
    ```

2.  **Allocate Temporary Buffer:** Create a temporary RGB unsigned char image (`bigImage`) with dimensions equal to the current render window size [S1, unofficial].
    ```python
    size = ren.GetRenderWindow().GetSize()
    bigImage = vtkImageData()
    bigImage.AllocateScalars(vtkUnsignedChar, 3) # RGB
    bigImage.SetDimensions(size[0], size[1], 1)
    ```

3.  **Compute Resampling Scale:** Calculate the scale factors needed to map the full-resolution render to the target output dimensions (`dim[0]`, `dim[1]`) [S1, unofficial].
    ```python
    # dim is the target output resolution
    scale[0] = dim[0] / size[0]
    scale[1] = dim[1] / size[1]
    ```

4.  **Isolate Volume Rendering:** Save the current visibility flags for all renderers and props in the scene. Set all visibility flags to `false` except for the target renderer and the specific volume to be rendered. This ensures no other scene elements interfere with the orthographic projection [S1, unofficial].

5.  **Compute Camera Geometry:**
    - Retrieve the volume's center and bounds.
    - Calculate the distance `d` as the span of the volume along the X-axis of its bounds:
      $$ d = bounds[1] - bounds[0] $$
    - Set the camera's focal point to the volume center [S1, unofficial].
    - Set the camera position to:
      $$ \text{position} = \text{center} - d \times \text{viewDirection} $$
    - Set the camera's view-up vector to `viewUp` [S1, unofficial].
    - Set the camera's parallel scale to:
      $$ \text{parallelScale} = \frac{d}{2} $$
    This configuration ensures the entire volume fits within the frustum of the orthographic camera [S1, unofficial].

6.  **Render:** Execute a single render pass using the configured orthographic camera [S1, unofficial].
    ```python
    ren.GetRenderWindow().Render()
    ```

7.  **Resample and Copy:** Restore the original camera settings. Resample `bigImage` to the target dimensions (`dim[0]`, `dim[1]`) using a resampling filter (e.g., `vtkImageResample`) with the calculated axis magnification factors. Copy the resulting pixels to the output image [S1, unofficial].

8.  **Restore State:** Restore all saved visibility flags for renderers and props. Re-enable buffer swapping on the render window [S1, unofficial].

**Pseudocode:**

```python
def CreateCanonicalView(ren, volume, image, blend_mode, viewDirection, viewUp):
    # 1. Disable buffer swapping
    ren.GetRenderWindow().SwapBuffersOff()

    # 2. Allocate temporary buffer matching window size
    size = ren.GetRenderWindow().GetSize()
    bigImage = vtkImageData()
    bigImage.AllocateScalars(vtkUnsignedChar, 3)
    bigImage.SetDimensions(size[0], size[1], 1)

    # 3. Compute scale factors for resampling
    dim = image.GetDimensions() # Target dimensions
    scale = [0.0, 0.0]
    scale[0] = dim[0] / size[0]
    scale[1] = dim[1] / size[1]

    # 4. Isolate volume
    # Save visibility flags for all renderers and props
    saved_flags = SaveVisibilityFlags(ren)
    SetAllVisibilityFalse(ren)
    SetVisibilityTrue(ren, volume)

    # 5. Configure Orthographic Camera
    bounds = volume.GetBounds()
    center = volume.GetCenter()
    
    # Distance d is the x-axis span of the bounds
    d = bounds[1] - bounds[0]
    
    camera = ren.GetActiveCamera()
    camera.SetFocalPoint(center)
    camera.SetPosition([
        center[0] - d * viewDirection[0],
        center[1] - d * viewDirection[1],
        center[2] - d * viewDirection[2]
    ])
    camera.SetViewUp(viewUp)
    camera.SetParallelScale(d / 2.0)
    camera.SetParallelProjection(True)

    # 6. Render
    ren.GetRenderWindow().Render()

    # 7. Resample to target dimensions
    # Note: Implementation details for vtkImageResample depend on VTK API
    resampler = vtkImageResample()
    resampler.SetInputData(bigImage)
    resampler.SetOutputDimensions(dim[0], dim[1], 1)
    resampler.SetMagnification(scale[0], scale[1], 1.0)
    resampler.Update()
    
    # Copy result to output image
    image.ShallowCopy(resampler.GetOutput())

    # 8. Restore state
    RestoreVisibilityFlags(ren, saved_flags)
    ren.GetRenderWindow().SwapBuffersOn()
```

**Edge Cases and Pitfalls:**
- **Precision:** The calculation of `d` relies on the X-axis span. If the volume is rotated or the bounding box is not aligned with the world axes, this may not represent the true extent along the view direction. The source specifies `d = bounds[1] - bounds[0]` explicitly [S1, unofficial].
- **Visibility:** Failure to isolate the volume may result in background elements or other volumes being rendered into the buffer, corrupting the orthographic projection [S1, unofficial].
- **Buffer Swapping:** If buffer swapping is not disabled, the user may see flickering or intermediate render states during the setup phase [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Dominated by the initial render pass and the resampling step. The render pass is $O(W \times H)$ where $W, H$ are window dimensions. Resampling is $O(W \times H)$ to $O(w \times h)$ depending on the filter.
- **Memory Complexity:** Requires temporary storage for a full-resolution RGB image (`bigImage`) in addition to the output image.
- **Strengths:** Produces metrically accurate orthographic views without perspective distortion. Simple to implement using standard VTK rendering pipelines.
- **Limitations:** Requires a full render pass to a temporary buffer, which can be memory-intensive for large window sizes. The method assumes the volume bounds are well-defined and accessible.
- **When to use:** When an orthographic view is required for scientific visualization, measurement, or comparison, and perspective distortion is undesirable.

## Background
The method is implemented in the `vtkGPUMultiVolumeRayCastMapper` class within the VTK (Visualization Toolkit) ecosystem, specifically in the `vtkMultiVolRen` extension [S1, unofficial]. It is part of a broader effort to support multi-volume rendering and advanced compositing techniques in VTK. The technique leverages VTK's camera manipulation and image processing filters to achieve the orthographic projection.
