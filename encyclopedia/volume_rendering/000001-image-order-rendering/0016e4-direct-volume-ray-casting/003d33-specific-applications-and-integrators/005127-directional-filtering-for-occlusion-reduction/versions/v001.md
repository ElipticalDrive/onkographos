# Directional Filtering for Occlusion Reduction

Also called: Directional transparency filtering, Eigenvector-based alpha modulation

## Overview
This method reduces occlusion in Diffusion Tensor Imaging (DTI) volume rendering by modulating voxel opacity based on the alignment between the local fiber direction (major eigenvector) and a user-defined direction vector. It allows for the selective fading of irrelevant fiber bundles while preserving contextual visibility, addressing the limitation that standard anisotropy measures do not provide information concerning specific fiber bundle boundaries [S1, book]. Unlike methods that rely on isosurfaces of anisotropy values, this approach uses directional tensor information to hide occluding structures without completely removing them, maintaining visual context [S1, book].

## How it works
**Inputs:**
*   DTI dataset (diffusion tensors).
*   User-defined direction vector $\mathbf{v}$ (normalized).
*   Transfer function parameters (base opacity, filtering function type).

**Outputs:**
*   Rendered image with reduced occlusion.

**Data Structures:**
*   **Tensor Field:** Each voxel stores a $3 \times 3$ symmetric positive-definite diffusion tensor.
*   **Eigenvector Field:** Pre-computed or on-the-fly computed major eigenvector $\mathbf{e}$ (normalized, $3 \times 1$ vector) for each voxel.
*   **Direction Vector:** User-defined normalized vector $\mathbf{v}$ ($3 \times 1$).

**Steps:**

1.  **Eigen-decomposition:** Compute the eigenvalues and the major eigenvector $\mathbf{e}$ for each voxel. This is performed on the GPU using a non-iterative approach [HBPA01] to ensure efficiency and accuracy [S1, book]. Note that eigenvector orientation is arbitrary (sign ambiguity); $\mathbf{e}$ and $-\mathbf{e}$ represent the same fiber orientation.

2.  **Hemisphere Restriction:** To maintain symmetry consistent with standard DTI color coding (where red/green/blue represent cardinal directions regardless of sign), the comparison must account for all directions with the same color. This involves up to eight vectors in general, or four due to eigenvector orientation independence [S1, book].
    *   Define the user-specified direction vector $\mathbf{v}$ in one hemisphere.
    *   Mirror $\mathbf{v}$ at a plane separating the two hemispheres of the brain (e.g., the coronal plane) to restrict comparison to one direction on the hemisphere. This ensures that fibers pointing in the "opposite" physical direction but mapped to the same color are treated consistently [S1, book].
    *   Let $\mathbf{v}_{hem}$ be the normalized direction vector in the hemisphere and $\mathbf{e}_{hem}$ be the normalized eigenvector projected into the same hemisphere logic.

3.  **Alignment Calculation:** Compute the dot product between the normalized eigenvector $\mathbf{e}$ and the normalized direction vector $\mathbf{v}$:
    $$ d = |\mathbf{e} \cdot \mathbf{v}| $$
    The absolute value is used because eigenvectors are undirected [S1, book].

4.  **Alpha Modulation:** Modify the base alpha value $\alpha_{base}$ using a filtering function $f(x)$ applied to the dot product $d$:
    $$ \alpha = \alpha_{base} \times f(d) $$
    The function $f(x)$ maps the alignment score $d \in [0, 1]$ to an opacity factor. The sources specify two common implementations:

    *   **GLSL Smoothstep:**
        $$ f(x) = \begin{cases} 0 & \text{when } x < 0 \\ 3x^2 - 2x^3 & \text{when } 0 \le x \le 1 \\ 1 & \text{when } x > 1 \end{cases} $$
        [S1, book]

    *   **Higher-Order Polynomial:**
        $$ f(x) = \begin{cases} 0 & \text{when } x < 0 \\ (126 + (-420 + (540 + (-315 + 70x)x)x)x)x^5 & \text{when } 0 \le x \le 1 \\ 1 & \text{when } x > 1 \end{cases} $$
        [S1, book]

5.  **Context Preservation:** To prevent confusion caused by completely transparent regions, the system allows selecting a non-zero opacity for "hidden" areas. This fades out uninteresting parts slightly, allowing the user to see important parts lying behind them [S1, book].

**Pseudocode:**

```python
def directional_filtering_alpha(eigenvector: Vec3, user_direction: Vec3, alpha_base: float, filter_type: str) -> float:
    """
    Computes the modulated alpha value for a voxel based on directional filtering.
    
    Args:
        eigenvector: Normalized major eigenvector (x, y, z) of the diffusion tensor.
        user_direction: Normalized user-defined direction vector.
        alpha_base: Base opacity from transfer function.
        filter_type: 'smoothstep' or 'polynomial'.
        
    Returns:
        Modulated alpha value.
    """
    # Ensure vectors are normalized
    e = normalize(eigenvector)
    v = normalize(user_direction)
    
    # Compute dot product. Use absolute value because eigenvector orientation is arbitrary.
    dot_product = abs(dot(e, v))
    
    # Clamp dot_product to [0, 1] for safety
    dot_product = clamp(dot_product, 0.0, 1.0)
    
    # Apply filtering function
    if filter_type == 'smoothstep':
        f = smoothstep(dot_product)
    elif filter_type == 'polynomial':
        f = polynomial_filter(dot_product)
    else:
        f = 1.0 # Fallback
        
    # Apply context preservation: if f is very low, use a minimum opacity
    # This is a general implementation detail inferred from "Preserving Context" section [S1, book]
    # The source mentions allowing one to select an opacity for "hidden" areas.
    # We assume a parameter min_alpha is available or defaults to 0.
    min_alpha = 0.0 # Not given in sources, but implied by "translucent" context preservation
    
    modulated_alpha = alpha_base * f
    if modulated_alpha < min_alpha:
        modulated_alpha = min_alpha
        
    return modulated_alpha

def smoothstep(x: float) -> float:
    if x < 0:
        return 0.0
    elif x > 1:
        return 1.0
    else:
        return 3 * x**2 - 2 * x**3

def polynomial_filter(x: float) -> float:
    if x < 0:
        return 0.0
    elif x > 1:
        return 1.0
    else:
        # f(x) = (126 + (-420 + (540 + (-315 + 70x)x)x)x)x^5
        # Rewritten for clarity and Horner's method
        term1 = 70 * x
        term2 = -315 + term1
        term3 = 540 + term2 * x
        term4 = -420 + term3 * x
        term5 = 126 + term4 * x
        return term5 * x**5
```

**Parameters:**
*   **Filter Function Type:** 'smoothstep' or 'polynomial'. The source notes that the type of function is not critical, but hard drop-offs should be avoided [S1, book].
*   **Minimum Opacity:** A user-defined value for "hidden" areas to preserve context. Not given in the sources as a specific default, but the mechanism is described [S1, book].

**Edge Cases and Pitfalls:**
*   **Symmetry Breaking:** Filtering out single directions breaks the typical symmetry of DTI data sets provided by standard color coding (red/green/blue for cardinal directions). This produces unfamiliar images and interferes with hemisphere comparison. To maintain symmetry, one must compare all directions that have the same color (up to eight vectors, or four due to eigenvector orientation independence) [S1, book].
*   **Hemisphere Comparison:** To provide more information about local fiber direction while maintaining symmetry, the comparison must be restricted to one direction on the hemisphere. This is achieved by defining the vector in one hemisphere and mirroring it at a plane separating both hemispheres [S1, book].
*   **Visual Clutter:** Selecting poor occlusion coefficients (e.g., making too many surfaces semitransparent) leads to visual clutter from the mixture of color and additional geometry [S1, book].

## Operating characteristics
*   **Time Complexity:** The method adds a constant-time operation per voxel during the compositing step (dot product and polynomial evaluation). The eigen-decomposition is performed per voxel, but the source specifies a non-iterative GPU approach [HBPA01], which is generally $O(1)$ per voxel with a small constant factor.
*   **Memory Complexity:** Requires storage for the tensor field and potentially pre-computed eigenvectors if not computed on-the-fly. The source implies on-the-fly computation on the GPU [S1, book].
*   **Strengths:**
    *   Selectively hides occluding fiber bundles while preserving context.
    *   Uses directional information, which is more relevant for fiber bundle selection than anisotropy invariants [S1, book].
    *   Interactive and user-driven.
*   **Limitations:**
    *   Requires computation of eigenvectors, which can be computationally expensive if not optimized (though the source claims a non-iterative GPU approach).
    *   Careful parameter tuning is required to avoid visual clutter or loss of context [S1, book].
    *   Specific to DTI data; not applicable to scalar volume data.

## Background
*   **Origin:** Proposed by M. Hlawitschka et al. in the paper "Interactive Volume Rendering of Diffusion Tensor Data" [S1, book].
*   **History:** The method builds upon basic volume rendering of DTI data, which maps normalized major eigenvectors to color and uses anisotropy (FA, RA, etc.) for opacity [S1, book]. It addresses the occlusion problem in 2D projections of volumetric data. Previous methods used isosurfaces of anisotropy values, which do not provide fiber bundle boundary information [S1, book].
*   **Usage:** Used in neuroimaging for visualizing white matter tracts in Diffusion Tensor Imaging (DTI) data.
