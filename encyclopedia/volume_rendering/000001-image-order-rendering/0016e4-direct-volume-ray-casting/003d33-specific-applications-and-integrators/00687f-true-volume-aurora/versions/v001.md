# True Volume Aurora

Also called: Interactive Volume Rendering Aurora, Lawlor and Genetti Aurora

## Overview
True Volume Aurora is a GPU-accelerated method for rendering aurorae as volumetric phenomena using height-based models and signed distance fields (SDFs) [S1, unofficial]. It solves the problem of efficiently generating interactive, physically plausible auroral displays by decoupling footprint generation from vertical electron deposition [S1, unofficial]. It differs from standard Direct Volume Ray Casting [19-direct-volume-ray-casting.md] by replacing generic scalar field sampling with a specialized SDF-based ray marching acceleration and a physically-based vertical stretching function, achieving 20–80 FPS [S1, unofficial].

## How it works
**Inputs:**
*   Camera position (`camPos`) and ray direction (`rayDir`).
*   Footprint texture (cubemap).
*   Signed Distance Field (SDF) texture (cubemap) generated from the footprint [S1, unofficial].
*   Base and high colors (passed via JSON descriptor) [S1, unofficial].
*   Auroral volume geometry (flipped sphere wrapping Earth) [S1, unofficial].

**Outputs:**
*   Final auroral color per pixel.

**Data Structures:**
*   **Cubemaps:** Footprint and SDF textures are stored as cubemaps to eliminate pole artifacts common in UV sphere mapping [S1, unofficial].
*   **Flipped Sphere:** The aurora volume is a programmatically generated sphere inverted to wrap around the Earth [S1, unofficial].

**Steps:**
1.  **Ray Marching:** Cast rays from the camera through the scene. Use the SDF texture to accelerate the march, skipping empty space until the ray intersects the auroral volume boundary [S1, unofficial].
2.  **UV Mapping:** For each sample point `p` within the volume, map the 3D position to 2D UV coordinates to sample the footprint texture.
3.  **Vertical Stretching:** Sample the footprint texture and stretch the color vertically based on a physically-based electron deposition function [S1, unofficial].
4.  **Compositing:** Accumulate the stretched colors along the ray using standard front-to-back compositing [S1, unofficial].

**UV Coordinate Mapping:**
To sample 2D textures from 3D ray marching samples, a projection function maps 3D points to UV coordinates. The point is normalized and converted to spherical coordinates [S1, unofficial]:

$$
\begin{aligned}
\hat{p} &= \frac{p}{\|p\|} \\
u &= 0.5 - \frac{\operatorname{atan}(-\hat{p}_z, -\hat{p}_x)}{2\pi} \\
v &= \frac{\operatorname{asin}(-\hat{p}_y)}{\pi} + 0.5
\end{aligned}
$$

**Pitfall Fix (Inside-Volume Artifacts):**
When the camera is inside the volume, standard UV mapping causes mirrored ghosting artifacts in the opposite direction of the camera [S1, unofficial]. To fix this, enforce that the sampling point must be on the "right" side of the ray (dot product of ray direction and point > 0). If invalid, return a sentinel value `vec2(5.0, 5.0)` [S1, unofficial].

**Pseudocode:**

```python
import math

def uv(p, ray_dir, cam_pos):
    """
    Maps 3D point p to 2D UV coordinates for footprint sampling.
    Includes fix for inside-volume artifacts.
    """
    # Check if point is on the right side of the ray
    if math.dot(ray_dir, p) > 0.0:
        # Normalize point
        p_norm = p / math.length(p)
        
        # Convert to spherical coordinates for UV mapping
        # atan2(y, x) returns angle in radians
        u = 0.5 - math.atan2(-p_norm.z, -p_norm.x) / (2 * math.pi)
        v = math.asin(-p_norm.y) / math.pi + 0.5
        
        return (u, v)
    else:
        # Invalid result for inside-volume artifacts
        return (5.0, 5.0)

def render_aurora(ray_dir, cam_pos, footprint_cubemap, sdf_cubemap, base_color, high_color):
    """
    Renders the aurora using ray marching and SDF acceleration.
    """
    # 1. Ray Marching with SDF acceleration
    # Start ray from cam_pos in direction ray_dir
    # Use sdf_cubemap to skip empty space
    # Stop when hitting the flipped sphere volume boundary
    
    sample_points = []
    t = 0.0
    step_size = 0.1 # Example step size
    
    while t < MAX_DISTANCE:
        p = cam_pos + ray_dir * t
        # Check if inside volume (simplified check)
        if is_inside_volume(p):
            sample_points.append(p)
        t += step_size
        
    # 2. Compositing
    color = vec3(0.0)
    alpha = 0.0
    
    for p in sample_points:
        # 3. UV Mapping
        u, v = uv(p, ray_dir, cam_pos)
        
        # If UV is invalid (sentinel), skip
        if u == 5.0 and v == 5.0:
            continue
            
        # 4. Sample Footprint and Stretch
        # Sample footprint texture at (u, v)
        footprint_color = sample_cubemap(footprint_cubemap, p) # Cubemap sample uses 3D direction
        
        # Stretch vertically using electron deposition function
        # This function depends on height relative to Earth center
        height_factor = compute_height_factor(p)
        stretched_color = mix(base_color, high_color, height_factor) * footprint_color
        
        # 5. Accumulate
        # Standard front-to-back compositing
        a = 0.5 # Example opacity
        color = color + stretched_color * a * (1.0 - alpha)
        alpha = alpha + a * (1.0 - alpha)
        
    return color
```

**Parameters:**
*   **Base and High Colors:** Passed from a JSON descriptor file [S1, unofficial].
*   **SDF Generation:** Generated using `sdfer`, a CLI utility [S1, unofficial].

## Operating characteristics
*   **Performance:** Achieves interactive frame rates of 20–80 FPS [S1, unofficial].
*   **Strengths:** GPU-friendly, efficient ray marching via SDFs, eliminates pole artifacts via cubemaps [S1, unofficial].
*   **Limitations:** Inside-volume camera positions cause artifacts without the dot-product fix; colors are not physically modeled (passed via JSON) [S1, unofficial].
*   **When to use:** Real-time visualization of aurorae in planetary simulators (e.g., Gaia Sky) [S1, unofficial].
*   **When not to use:** When physically accurate color modeling is required (future work suggests adopting upper atmosphere physical models) [S1, unofficial].

## Background
The method is based on the 2011 paper "Interactive Volume Rendering Aurora on the GPU" by O. Lawlor and J. Genetti [S1, unofficial]. It was implemented in the Gaia Sky application to replace previous integration attempts that produced poor results [S1, unofficial]. The implementation uses cubemaps for textures and a flipped sphere for the volume geometry [S1, unofficial].
