# ISMOS

Also called: Approximate Image-Space Multidirectional Occlusion Shading Model

## Overview
ISMOS is a unified image-space shading model for direct volume rendering that simulates various light sources, including hard shadows and ambient occlusion, while handling occlusion from both opaque and transparent media separately [S1]. It distinguishes itself from ray-casting-based shadow techniques like deep shadow maps by computing occlusion entirely in image space using multidirectional sampling, achieving visually identical results with decoupled post-processing overhead [S1]. Unlike simple local illumination, it provides depth cues via shadowing and ambient occlusion without requiring preprocessing or additional opacity buffers [S1].

## How it works
ISMOS operates as a post-processing pass applied to the output of a direct volume ray casting renderer. It decouples the shading computation from the volume rendering pass, allowing it to be integrated into any rendering system [S1]. The method computes approximated opacity to handle transparent layers and samples light directions in image space to determine occlusion.

### Inputs and Outputs
**Inputs:**
1.  **Color Buffer:** A floating-point texture storing the RGB color values from the volume rendering pass, along with an additional parameter $\beta$ [S1].
2.  **Depth Texture:** A floating-point texture storing depth information. The layout depends on the rendering mode:
    *   **Non-transparent rendering:** 1 component (depth only) [S1].
    *   **Transparent object occlusion or multiple layer rendering:** 4 components (depth and potentially layer identifiers or transmittance) [S1].
3.  **Light Parameters:** Number of light sources, positions, and radii [S1].

**Outputs:**
*   Shaded color image with applied shadows and ambient occlusion effects [S1].

### Data Structures
*   **Color Buffer:** Stores RGB color data and the parameter $\beta$. The parameter $\beta$ is embedded within the color buffer to eliminate the need for a separate opacity buffer [S1].
*   **Depth Texture:**
    *   Mode 1 (Opaque): 1-channel floating-point texture.
    *   Mode 2 (Transparent/Multi-layer): 4-channel floating-point texture [S1].

### Parameters
*   **$\beta$:** A parameter used to compute approximated opacity. Its specific numerical value is not specified in the sources [S1].
*   **$r$:** The radius of the disk on which light samples are placed [S1].
*   **$R$:** An offset added to the x-coordinate of the disk center. The center is defined at $(R + 0.5, 0.5, 0.0)$ to simplify calculations [S1].
*   **$\theta$:** Rotation angle about the z-axis. Range: $0 \le \theta \le 2\pi$ [S1].
*   **$\phi$:** Rotation angle about the y-axis. Range: $0 \le \phi \le \pi$ [S1]

### Algorithm Steps
1.  **Render Volume:** Perform direct volume ray casting to generate the initial color and depth buffers. Store these in floating-point textures [S1].
2.  **Store Opacity Proxy:** Compute the approximated opacity using parameter $\beta$ and store it within the color buffer. This avoids allocating an additional opacity buffer [S1].
3.  **Sample Light Directions:** For each light source, generate sample directions by rotating points on a disk.
    *   Define a disk with radius $r$ centered at $(R + 0.5, 0.5, 0.0)$ [S1].
    *   Apply rotation $R_y(\phi)$ about the y-axis.
    *   Apply rotation $R_z(\theta)$ about the z-axis.
    *   The combined rotation matrix $M$ is:
        $$
        M = R_z(\theta) R_y(\phi) = \begin{pmatrix} \cos(\theta)\cos(\phi) & -\sin(\theta) & \cos(\theta)\sin(\phi) \\ \sin(\theta)\cos(\phi) & \cos(\theta) & \sin(\theta)\sin(\phi) \\ -\sin(\phi) & 0 & \cos(\phi) \end{pmatrix}
        $$
        [S1]
4.  **Compute Occlusion:**
    *   **Full Occlusion:** Used for opaque media. Determines if a light ray is blocked by opaque geometry [S1].
    *   **Partial Occlusion:** Used for transparent media. Handles occlusion caused by transparent layers (e.g., skin occluding light on bone) [S1].
    *   The model blends occlusion shadings from multiple layers to produce realistic shading through transparent volumes [S1].
5.  **Apply Shading:** Combine the base color with the computed occlusion factors (shadow and ambient occlusion) to produce the final shaded image [S1].

### Edge Cases and Pitfalls
*   **Indirect Lighting:** The model does not support indirect lighting as it is not interpreted within the shading model [S1].
    *   *Mitigation:* The model can be extended by adding more buffers to store more precise transmittance for enclosed volumes with partially opaque objects [S1].
*   **Transparent Layers:** Handling transparent object occlusion requires a 4-component depth texture. Using a 1-component texture for transparent scenes will result in incorrect occlusion [S1].
*   **Performance Variance:** While overhead is constant for a fixed viewport, the number of light sources affects performance. Full occlusion is faster than partial occlusion by approximately 11.4 ms [S1].

## Operating characteristics
*   **Time Complexity:** The performance overhead is constant for a fixed viewport size [S1].
    *   Average overhead: 13.8 ms for full occlusion with 1 light source [S1].
    *   Average overhead: 25.6 ms for 2 light sources [S1].
    *   Difference between full and partial occlusion: ~11.4 ms [S1].
    *   Opacity approximation overhead: ~15.9 ms [S1].
    *   The number of light sources affects performance, but the difference is fairly small [S1].
*   **Memory Complexity:** Requires floating-point textures for color and depth. Uses 1 component for opaque rendering and 4 components for transparent/multi-layer rendering. Does not require an additional opacity buffer due to the $\beta$ parameter embedding [S1].
*   **Measured Performance:** Tested on Xeon CPU 2.66 GHz and NVidia GeForce GTX 295. Viewport: 580 × 580. Datasets included Engine (256×256×128), Teddy bear (512×512×63), Head (256×256×225), Abdomen (256×256×128), Carp (256×256×512), and Stag beetle (832×832×494). FPS ranged from 5.1 to 23.3 depending on the method and dataset [S1].
*   **Strengths:**
    *   Provides shadow and ambient occlusion effects that supply additional depth cues compared to simple local illumination [S1].
    *   Decoupled from the rendering pass, making it applicable to any rendering system [S1].
    *   Does not require preprocessing [S1].
    *   Transfer function and light position can be changed interactively [S1].
    *   Hard shadows are visually almost identical to deep shadow maps [S1].
*   **Limitations:**
    *   Does not support indirect lighting natively [S1].
    *   Performance on volume rendering itself might not be faster than highly optimized ray casting, as the focus was on shading overhead [S1].
*   **When to Use:** When real-time or near-real-time volume rendering requires realistic shading (shadows, AO) without the complexity of ray-traced shadows or preprocessing steps. Suitable for interactive applications where light positions and transfer functions change frequently [S1].
*   **When Not to Use:** When indirect lighting is required, or when the scene contains complex enclosed volumes with partially opaque objects that need precise transmittance storage beyond the model's default capabilities [S1].

## Background
ISMOS was introduced by Y. J. and S. K. in a 2021 paper titled "Approximate Image-Space Multidirectional Occlusion Shading Model for Direct Volume Rendering" [S1]. The work was supported by the Basic Research Program. The model was developed to provide more visual cues with minor performance overhead compared to using only local illumination in direct volume rendering. It extends ray-casting techniques using NVidia Cg shaders [S1].
