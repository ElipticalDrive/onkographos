# ISMOS

Also called: Approximate Image-Space Multidirectional Occlusion Shading Model

## Overview
ISMOS is a unified image-space shading model for direct volume ray casting that simulates various light sources, including hard shadows and ambient occlusion, while handling occlusion from both opaque and transparent media separately [S1]. It distinguishes itself from standard local illumination by providing depth cues through shadowing and from deep shadow maps by computing occlusion via multidirectional image-space sampling rather than projection [S1]. The method is decoupled from the volume rendering pass, allowing it to be applied as a post-processing or secondary pass to any rendering system [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:**
    *   Color buffer from volume ray casting (floating point texture) [S1].
    *   Depth buffer from volume ray casting (floating point texture) [S1].
    *   Light source parameters (position, type) [S1].
    *   Model parameters: $\beta$ (opacity approximation parameter), $r$ (disk radius), $R$ (x-offset) [S1].
*   **Outputs:**
    *   Shaded color image [S1].

**Data Structures**
*   **Color Buffer:** Stores RGB color data and the parameter $\beta$ [S1]. The source specifies $\beta$ is stored "together in the color buffer," eliminating the need for a separate opacity buffer [S1]. The exact bit-packing or channel assignment for $\beta$ is not specified [S1].
*   **Depth Texture:**
    *   For rendering without transparency: 1 component [S1].
    *   For transparent object occlusion or multiple layer rendering: 4 components [S1].
    *   The specific mapping of the 4 components (e.g., RGBA vs. specific layer depths) is not detailed in the sources [S1].

**Parameters**
*   $\beta$: Parameter used to compute approximated opacity. Value: Not specified in the sources [S1].
*   $r$: Radius of the disk on which light samples are placed. Value: Not specified in the sources [S1].
*   $R$: Offset added to the x-coordinate of the disk center. Value: Not specified in the sources [S1].

**Algorithm Steps**
1.  **Volume Rendering Pass:** Perform direct volume ray casting. Store the resulting color and depth in floating-point textures [S1].
2.  **Opacity Approximation:** Compute approximated opacity using the parameter $\beta$ stored in the color buffer [S1]. The specific formula for this approximation is not provided in the sources [S1].
3.  **Light Sample Generation:** Generate light samples by rotating points on a disk [S1].
    *   The disk has radius $r$ and is centered at $(R + 0.5, 0.5, 0.0)$ [S1].
    *   Samples are rotated by angle $\phi$ about the y-axis ($R_y(\phi)$) and then by angle $\theta$ about the z-axis ($R_z(\theta)$) [S1].
    *   The combined rotation matrix is:
        $$
        R_z(\theta) R_y(\phi) = \begin{pmatrix} \cos(\theta)\cos(\phi) & -\sin(\theta) & \cos(\theta)\sin(\phi) \\ \sin(\theta)\cos(\phi) & \cos(\theta) & \sin(\theta)\sin(\phi) \\ -\sin(\phi) & 0 & \cos(\phi) \end{pmatrix}
        $$
        where $0 \le \theta \le 2\pi$ and $0 \le \phi \le \pi$ [S1].
4.  **Occlusion Shading:** Apply shading based on the generated light samples [S1].
    *   **Full Occlusion:** Used for opaque media [S1].
    *   **Partial Occlusion:** Used for transparent media [S1].
    *   The method blends occlusion shadings from multiple layers to produce realistic shading through transparent volumes [S1].
    *   The specific integration formula combining the rotated samples with the depth/color buffers is not provided in the sources [S1].

## Subtopics

### Full Occlusion
Handles opaque media by treating light paths as blocked by fully opaque surfaces. Chosen when rendering solid structures [S1].

### Partial Occlusion
Handles transparent media by accounting for partial light transmission. Chosen when rendering translucent structures like skin or organs [S1].

### Opacity Approximation
A technique to estimate opacity values at any depth using a parameter $\beta$ stored in the color buffer, avoiding additional buffers. Chosen to reduce memory overhead [S1].

## Operating characteristics
*   **Time Complexity:** The performance overhead is constant for a fixed viewport size [S1].
*   **Memory Complexity:** Small overhead in texture memory compared to previous techniques; does not require preprocessing [S1].
*   **Measured Performance:**
    *   Hardware: Xeon CPU 2.66 GHz, NVidia GeForce GTX 295 [S1].
    *   Viewport: 580 × 580 [S1].
    *   Datasets: Engine (256×256×128), Teddy bear (512×512×63), Head (256×256×225), Abdomen (256×256×128), Carp (256×256×512), Stag beetle (832×832×494) [S1].
    *   FPS: Ranges from 5.1 to 23.3 depending on method and dataset [S1].
    *   Overhead:
        *   Full occlusion with 1 light: 13.8 ms average [S1].
        *   Full occlusion with 2 lights: 25.6 ms average [S1].
        *   Difference between full and partial occlusion: ~11.4 ms [S1].
        *   Opacity approximation: ~15.9 ms [S1].
*   **Strengths:**
    *   Provides shadow and ambient occlusion effects for better depth cues compared to simple local illumination [S1].
    *   Hard shadows are visually almost identical to deep shadow maps but computed via image-space multidirectional occlusion [S1].
    *   Decoupled from the rendering pass, making it applicable to any rendering system [S1].
    *   No preprocessing required [S1].
    *   Interactive changes to transfer function and light position are supported [S1].
*   **Limitations:**
    *   Indirect lighting is not supported because it is not interpreted within the model [S1].
    *   Performance on volume rendering itself may not be faster than highly optimized renderers, as the focus was on shading overhead [S1].
*   **When to use:** When realistic shading with shadows and ambient occlusion is needed for direct volume rendering, especially with transparent layers, and when avoiding the complexity of shadow map projection is desired [S1].
*   **When not to use:** When indirect lighting (global illumination) is required [S1].

## Background
ISMOS was introduced by Y.J. and S.K. in a 2021 paper published in *Applied Sciences* [S1]. The work presents a novel approximate image-space multidirectional occlusion shading model for direct volume rendering [S1]. It builds on the foundations of direct volume ray casting [19-direct-volume-ray-casting.md] but modifies the shading step to include multidirectional occlusion [S1]. The model was tested on various medical and synthetic datasets to demonstrate its ability to provide visual cues with minor performance overhead [S1].
