# TVAM Integrator

Also called: common TVAM integrator base class

## Overview
The TVAM Integrator is a base class for volumetric integrators in Tomographic Volumetric Additive Manufacturing (TVAM) that manages projector ray sampling, time sampling, and the selection between regular and stochastic sampling modes [S1, unofficial]. It solves the problem of correctly discretizing light patterns from digital projectors onto a 3D build volume by handling the geometric mapping from pixel coordinates to emitter rays and managing the temporal sequencing of projected patterns [S1, unofficial]. It is distinguished from sibling methods like the CornerIntegrator and Radon Integrator by providing the foundational sampling infrastructure without implementing specific physical models (such as absorption-only projection or corner-masking) [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Scene configuration containing a target shape (identified by `target_id`) and an interior medium; projector emitter definitions; sampling parameters (`regular_sampling`, `sample_time`, `spp`).
*   **Outputs:** A set of rays defined by origin, direction, and weight, sampled according to the selected mode.

**Data Structures:**
*   **Active Pixels:** A list of pixel indices corresponding to the projector's active area.
*   **Ray Buffer:** Stores ray origins, directions, and weights. The size is determined by `active_size * spp`.

**Parameters:**
*   `sample_time` (bool, default `False`): If true, adds a stochastic offset to the time sample [S1, unofficial].
*   `print_time` (float, default `1.0`): Scaling factor for ray weight [S1, unofficial].
*   `target_id` (str, default `'target'`): ID of the target shape for surface-aware discretization [S1, unofficial].
*   `transmission_only` (bool, default `True`): If true, only samples the transmission component of the BSDF at interfaces [S1, unofficial].
*   `regular_sampling` (bool, default `False`): If true, samples from the center of the pixel (0.5 offset) instead of using a random offset [S1, unofficial].
*   `K` (int, default `2`): Exponent for physical model evaluation [S1, unofficial].
*   `M` (int, default `4`): Exponent for sparsity evaluation [S1, unofficial].
*   `tp` (float, default `0.1`): Polymerization threshold parameter [S1, unofficial].
*   `top` (float, default `0.2`): Top threshold parameter [S1, unofficial].
*   `tinhibitor` (float, default `0.2`): Inhibitor threshold parameter [S1, unofficial].
*   `weight_object` (float, default `1`): Weight for object region evaluation [S1, unofficial].
*   `weight_void` (float, default `1`): Weight for void region evaluation [S1, unofficial].
*   `weight_limit` (float, default `1`): Weight for limit evaluation [S1, unofficial].
*   `weight_sparsity` (float, default `0`): Weight for sparsity evaluation [S1, unofficial].

**Steps:**

1.  **Parse Scene:** Iterate over scene shapes to identify the target shape (matching `target_id`) and the interior medium. Raise an error if more than one medium is found [S1, unofficial].
2.  **Prepare:**
    *   If `regular_sampling` is true, force `spp` (samples per pixel) to 1, as shooting from the pixel center makes `spp > 1` nonsensical [S1, unofficial].
    *   Check if `wavefront_size` (`active_size * spp`) exceeds $2^{32}$. If so, raise an exception [S1, unofficial].
3.  **Sample Rays:**
    *   Compute discrete sample position `idx` by repeating `active_pixels` `spp` times [S1, unofficial].
    *   Compute pixel coordinates `pos.y` and `pos.x` from `pixel_idx`:
        $$ pos.y = \lfloor pixel\_idx / w \rfloor $$
        $$ pos.x = pixel\_idx - pos.y \times w $$
        where $w$ is the projector width [S1, unofficial].
    *   Convert pixel position to floating point range $[0, 1]$:
        *   If `regular_sampling` is true, add 0.5 offset.
        *   Else, add `sampler.next_2d()` (stochastic offset).
        *   Scale by $1/w$ and $1/h$ respectively [S1, unofficial].
    *   Compute time sample:
        $$ time = emitter\_idx / n\_patterns $$
        *   If `sample_time` is true, add `sampler.next_1d()` before dividing [S1, unofficial].
    *   Sample ray from emitter using the computed position and time.
    *   Scale ray weight by `print_time` divided by the PDF of the time sample [S1, unofficial].

**Pseudocode:**

```python
def prepare(self):
    # Force spp to 1 if regular sampling is used
    if self.regular_sampling:
        self.spp = 1
    
    # Check for overflow in wavefront size
    wavefront_size = self.active_size * self.spp
    if wavefront_size > 2**32:
        raise ValueError("Wavefront size exceeds 2^32")

def sample_rays(self, sampler, emitter, n_patterns):
    rays = []
    # Repeat active pixels spp times
    for _ in range(self.spp):
        for pixel_idx in self.active_pixels:
            # Compute pixel coordinates
            row_idx = pixel_idx // self.w
            col_idx = pixel_idx - row_idx * self.w
            
            # Convert to [0, 1] range
            if self.regular_sampling:
                u = (col_idx + 0.5) / self.w
                v = (row_idx + 0.5) / self.h
            else:
                u = sampler.next_2d()[0] / self.w
                v = sampler.next_2d()[1] / self.h
            
            # Compute time sample
            time = self.emitter_idx / n_patterns
            if self.sample_time:
                time += sampler.next_1d()
            time /= n_patterns
            
            # Sample ray from emitter
            ray = emitter.sample(u, v, time)
            
            # Scale weight
            # Note: PDF of time sample is assumed to be 1/n_patterns if uniform
            # Weight scaling by print_time / pdf_time
            pdf_time = 1.0 / n_patterns
            ray.weight = self.print_time / pdf_time
            
            rays.append(ray)
    return rays
```

**Edge Cases and Pitfalls:**
*   **Overflow:** If `active_size * spp` exceeds $2^{32}$, the method raises an exception [S1, unofficial].
*   **Regular Sampling:** Using `spp > 1` with `regular_sampling` is logically inconsistent and is forced to 1 [S1, unofficial].
*   **Multiple Media:** The parser raises an error if more than one interior medium is found in the scene [S1, unofficial].

## Subtopics

### [CornerIntegrator](7445-cornerintegrator.md)
A specialized integrator that filters out rays intersecting the corners of the target build volume to solve discretization artifacts near DMD pixel boundaries. It builds on the TVAM Integrator base class but adds surface-aware masking logic.

### [Radon Integrator](7470-radon-integrator.md)
Computes the Radon transform (projection) of a volume by tracing rays through a purely absorptive medium. It builds on the TVAM Integrator base class, inheriting projector ray sampling and time sampling capabilities, but focuses on accumulated attenuation rather than general BSDF sampling.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of active pixels and samples per pixel ($O(active\_size \times spp)$).
*   **Memory Complexity:** Linear with respect to the wavefront size ($active\_size \times spp$) to store ray data.
*   **Strengths:** Provides a unified interface for regular and stochastic sampling in TVAM contexts; handles temporal discretization of projector patterns.
*   **Limitations:** Does not implement specific physical models (e.g., absorption, scattering) itself; relies on derived classes for specific manufacturing physics.
*   **When to use:** When implementing a new TVAM integrator that requires projector ray sampling and time management.
*   **When not to use:** When specific physical effects like corner masking or pure absorption projection are required; use derived classes instead.

## Background
The TVAM Integrator originates from the Dr. TVAM project, an inverse rendering framework for Tomographic Volumetric Additive Manufacturing [S1, unofficial]. It was developed to address the challenges of simulating light propagation in TVAM systems, where digital projectors pattern light onto a rotating vial of photopolymer resin. The base class provides the necessary infrastructure for sampling projector rays and managing the temporal sequence of patterns, which is critical for accurate simulation and optimization of the manufacturing process [S1, unofficial].
