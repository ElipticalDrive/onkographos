# TVAM Integrator

Also called: common TVAM integrator base class

## Overview
The TVAM Integrator is a base class for volumetric integrators in Tomographic Volumetric Additive Manufacturing (TVAM) that handles projector ray sampling, time sampling, and regular versus stochastic sampling modes [S1, unofficial]. It serves as the foundational component for computing light exposure in TVAM simulations, diverging from standard Direct Volume Ray Casting by focusing on the temporal and geometric sampling of projector emissions rather than material compositing [S1, unofficial]. It is distinguished from its siblings by providing the generic sampling infrastructure (pixel, time, and emitter selection) upon which specific integrators like the Radon Integrator or CornerIntegrator build their material-specific accumulation logic.

## How it works
The integrator manages the generation of rays from a projector array to simulate the light field incident on a build volume. It supports both regular (deterministic) and stochastic sampling strategies.

**Inputs and Outputs:**
*   **Inputs:** Scene configuration containing emitter positions, target geometry (by ID), and interior medium properties. Parameters include `sample_time`, `print_time`, `target_id`, `transmission_only`, `regular_sampling`, `K`, `M`, `tp`, `top`, `tinhibitor`, `weight_object`, `weight_void`, `weight_limit`, and `weight_sparsity` [S1, unofficial].
*   **Outputs:** A set of rays defined by origin, direction, and weight, ready for traversal through the volume.

**Data Structures:**
*   **Active Pixels:** A list of pixel indices to be sampled.
*   **Ray Buffer:** Stores ray origins, directions, and weights.
*   **Scene Data:** Contains the target shape (binary mask) and the interior medium [S1, unofficial].

**Parameters:**
*   `sample_time` (bool, default `False`): If true, adds a stochastic offset to the time sample [S1, unofficial].
*   `print_time` (float, default `1.0`): Used to scale the ray weight by $1/\text{print\_time}$ [S1, unofficial].
*   `target_id` (str, default `'target'`): The ID of the target shape used for surface-aware discretization [S1, unofficial].
*   `transmission_only` (bool, default `True`): If true, only samples the transmission component of the BSDF at interfaces [S1, unofficial].
*   `regular_sampling` (bool, default `False`): If true, samples from the center of the pixel (0.5 offset) instead of using a random offset [S1, unofficial].
*   `K` (int, default `2`): Exponent for loss evaluation functions [S1, unofficial].
*   `M` (int, default `4`): Exponent for sparsity evaluation [S1, unofficial].
*   `tp` (float, default `0.1`): Threshold parameter for polymerization [S1, unofficial].
*   `top` (float, default `0.2`): Threshold parameter for over-polymerization [S1, unofficial].
*   `tinhibitor` (float, default `0.2`): Threshold parameter for inhibitor concentration [S1, unofficial].
*   `weight_object` (float, default `1`): Weight for object region loss [S1, unofficial].
*   `weight_void` (float, default `1`): Weight for void region loss [S1, unofficial].
*   `weight_limit` (float, default `1`): Weight for limit region loss [S1, unofficial].
*   `weight_sparsity` (float, default `0`): Weight for sparsity penalty [S1, unofficial].

**Steps:**

1.  **Parse Scene:**
    *   Iterate over scene shapes to find the target shape identified by `target_id` and the interior medium [S1, unofficial].
    *   Raise an error if more than one interior medium is found [S1, unofficial].

2.  **Prepare:**
    *   If `regular_sampling` is `True`, force `spp` (samples per pixel) to 1, because shooting from the pixel center makes `spp > 1` nonsensical [S1, unofficial].
    *   Check if `wavefront_size` (calculated as `active_size * spp`) exceeds $2^{32}$. If so, raise an exception [S1, unofficial].

3.  **Sample Rays:**
    *   Compute discrete sample position `idx` by repeating `active_pixels` `spp` times [S1, unofficial].
    *   Compute pixel coordinates `pos.y` and `pos.x` from `pixel_idx`:
        $$ \text{pos.y} = \lfloor \text{pixel\_idx} / w \rfloor $$
        $$ \text{pos.x} = \text{pixel\_idx} - \text{row\_idx} \times w $$
        where $w$ is the image width and $\text{row\_idx} = \text{pos.y}$ [S1, unofficial].
    *   Convert pixel position to floating point range $[0, 1]$:
        *   If `regular_sampling` is `True`, add 0.5 offset to both coordinates.
        *   Else, add `sampler.next_2d()` (a random 2D value) to both coordinates.
        *   Scale by $1/w$ and $1/h$ respectively [S1, unofficial].
    *   Compute time sample:
        $$ \text{time} = \text{emitter\_idx} / n\_patterns $$
        *   If `sample_time` is `True`, add `sampler.next_1d()` (a random 1D value) to the numerator before dividing [S1, unofficial].
    *   Sample ray from emitter using the computed position and time.
    *   Scale ray weight by `print_time` (specifically, multiply by $1/\text{print\_time}$) [S1, unofficial].

**Pseudocode:**

```python
def sample_rays(self, active_pixels, sampler, n_patterns, emitter_idx, w, h):
    # 1. Compute discrete sample positions
    # Repeat active_pixels spp times. Assuming spp=1 for regular sampling logic described.
    # In a general loop over samples:
    for pixel_idx in active_pixels:
        # 2. Compute pixel coordinates
        row_idx = pixel_idx // w
        pos_y = row_idx
        pos_x = pixel_idx - row_idx * w
        
        # 3. Convert to [0, 1] range
        if self.regular_sampling:
            u = (pos_x + 0.5) / w
            v = (pos_y + 0.5) / h
        else:
            u = (pos_x + sampler.next_2d()[0]) / w
            v = (pos_y + sampler.next_2d()[1]) / h
            
        # 4. Compute time sample
        time = emitter_idx / n_patterns
        if self.sample_time:
            time = (emitter_idx + sampler.next_1d()) / n_patterns
            
        # 5. Sample ray from emitter
        # Assuming emitter is a function or object that takes u, v, time
        ray = self.emitter.sample_ray(u, v, time)
        
        # 6. Scale weight
        ray.weight *= 1.0 / self.print_time
        
        yield ray
```

**Edge Cases and Pitfalls:**
*   **Wavefront Overflow:** If `active_size * spp` exceeds $2^{32}$, the method raises an exception [S1, unofficial].
*   **Regular Sampling Conflict:** Setting `regular_sampling=True` with `spp > 1` is logically inconsistent and is forced to `spp=1` in the prepare step [S1, unofficial].
*   **Multiple Mediums:** The parser raises an error if more than one interior medium is detected in the scene [S1, unofficial].

## Subtopics

### [CornerIntegrator](7445-cornerintegrator.md)
Specialized integrator that filters rays intersecting build volume corners to mitigate DMD discretization artifacts.

### [Radon Integrator](7470-radon-integrator.md)
Computes the Radon transform by tracing rays through a purely absorptive medium.

### [HoloVAM](13314-holovam.md)
Uses holographic phase modulation instead of amplitude modulation for light projection.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of active pixels and samples per pixel ($O(N \cdot \text{spp})$) for the sampling phase [S1, unofficial].
*   **Memory Complexity:** Linear with respect to the wavefront size ($O(N \cdot \text{spp})$) to store ray data [S1, unofficial].
*   **Strengths:** Provides a unified interface for regular and stochastic sampling, essential for optimizing TVAM exposure patterns [S1, unofficial].
*   **Limitations:** As a base class, it does not define the material interaction model; specific integrators must implement the accumulation logic [S1, unofficial].
*   **When to use:** When implementing a new TVAM integrator that requires standard projector ray sampling infrastructure [S1, unofficial].

## Background
The TVAM Integrator originates from the Dr. TVAM project, an inverse rendering framework for Tomographic Volumetric Additive Manufacturing developed by the Robotic Systems Lab at EPFL [S1, unofficial]. It is part of a broader effort to optimize light patterns for 3D printing using differentiable rendering [S1, unofficial].
