# Compositional Rendering

Also called: GO-NeRF Compositional Rendering, GO-NeRF Rendering

## Overview
Compositional Rendering is a method for integrating newly generated 3D objects into an existing Neural Radiance Field (NeRF) scene by decoupling the rendering of the object from the background scene [S1]. It solves the problem of occlusion-aware compositing in image-order rendering by generating a 3D-aware opacity map for the new object and blending it with pre-rendered background RGB-D images [S1]. It differs from standard Direct Volume Ray Casting [19-direct-volume-ray-casting.md] by performing the final alpha-blending in image space using a pre-computed scene cache, rather than accumulating the entire scene in a single ray-casting pass [S1].

## How it works
**Inputs:**
*   Pre-rendered background RGB-D image sequences $\{(S_0, D_0), \dots, (S_n, D_n)\}$ for a set of camera viewpoints $\{C_0, \dots, C_n\}$ [S1].
*   A trained object NeRF $F(\theta_o)$ defining volume density $\delta$ and RGB color $c$ [S1].
*   A 3D bounding box defining the spatial extent of the object [S1].
*   A target camera viewpoint $v \in \{C_0, \dots, C_n\}$ [S1].

**Outputs:**
*   Final composited RGB image $I_v$ [S1].
*   Intermediate object RGB image $G_v$ [S1].
*   Intermediate object opacity map $O_v$ [S1].

**Data Structures:**
*   **Background Cache:** A list of tuples, where each tuple contains an RGB image $S_v$ and a depth image $D_v$ for each viewpoint $v$.
*   **Object NeRF:** A neural network $F(\theta_o)$ that takes a 3D coordinate $q$ and viewing direction as input and outputs volume density $\delta$ and RGB color $c$.
*   **Bounding Box:** Defined by minimum and maximum coordinates $(x_{min}, y_{min}, z_{min})$ and $(x_{max}, y_{max}, z_{max})$.

**Steps:**

1.  **Pre-render Background:** For each camera viewpoint $v$ in the predefined set $\{C_0, \dots, C_n\}$, render the background scene using the established scene NeRF $F(\theta_s)$ to generate the RGB image $S_v$ and depth image $D_v$. Store these as the background cache [S1].

2.  **Ray Casting:** For the target viewpoint $v$, cast a ray $r_i$ for each pixel $i$ in the image plane [S1].

3.  **Sampling:** Sample $K$ query points $q_k$ along the ray $r_i$ within the 3D bounding box of the object [S1]. Let $\Delta_k$ be the distance between adjacent query points $q_k$ and $q_{k+1}$ along the ray [S1].

4.  **Query NeRF:** For each query point $q_k$, query the object NeRF $F(\theta_o)$ to obtain the volume density $\delta_k$ and RGB color $c_k$ [S1].

5.  **Calculate Transmittance:** Compute the transmittance $\tau_k$ at sample $k$, representing the probability that a ray passes through the volume up to sample $k$ without being absorbed or scattered [S1]:
    $$ \tau_k = \exp\left(-\sum_{t=1}^{k-1} \delta_t \Delta_t\right) $$
    where $\tau_1 = 1$ [S1].

6.  **Calculate Object RGB:** Compute the accumulated RGB value $G_v(i)$ for pixel $i$ by summing the contribution of each sample weighted by its opacity contribution and transmittance [S1]:
    $$ G_v(i) = \sum_{k=1}^{K} \tau_k (1 - \exp(-\delta_k \Delta_k)) c_k $$

7.  **Calculate Object Opacity:** Compute the accumulated opacity $O_v(i)$ for pixel $i$. This step includes occlusion logic against the pre-rendered background depth $D_v(i)$ [S1]:
    $$ O_v(i) = \begin{cases} \sum_{k=1}^{K} \tau_k (1 - \exp(-\delta_k \Delta_k)), & \text{if } r_i \in \text{box} \text{ AND } D_{box}(i) \le D_v(i) \\ 0, & \text{otherwise} \end{cases} $$
    Here, $D_{box}(i)$ is the depth of the intersection of ray $r_i$ with the 3D bounding box [S1]. The condition $D_{box}(i) \le D_v(i)$ ensures that if the object's bounding box is behind the background scene's geometry, the object is treated as occluded [S1].

8.  **Composite:** Blend the rendered object $G_v$ and the pre-rendered background $S_v$ using the opacity map $O_v$ to produce the final image $I_v$ [S1]:
    $$ I_v = G_v \cdot O_v + S_v \cdot (1 - O_v) $$

**Pseudocode:**

```python
def compositional_rendering(viewpoint_index, background_cache, object_nerf, bounding_box, num_samples):
    """
    Renders the final composited image for a specific viewpoint.
    
    Args:
        viewpoint_index: Index of the camera viewpoint in the predefined set.
        background_cache: List of (S_v, D_v) tuples for all viewpoints.
        object_nerf: Function/Model F(theta_o) returning (delta, c) for a point.
        bounding_box: 3D bounding box defining the object's spatial extent.
        num_samples: Number of query points K along the ray.
        
    Returns:
        I_v: Final composited RGB image.
    """
    # Step 1: Retrieve pre-rendered background
    S_v, D_v = background_cache[viewpoint_index]
    height, width = S_v.shape[:2]
    
    # Initialize output images
    I_v = np.zeros((height, width, 3))
    
    # Get camera parameters for viewpoint v to construct rays
    # [G] Implementation detail: Ray construction depends on specific camera model.
    # Assuming a standard pinhole camera model with known intrinsics and extrinsics.
    rays = construct_rays(viewpoint_index) 
    
    for i in range(height * width):
        ray = rays[i]
        pixel_y, pixel_x = i // width, i % width
        
        # Step 2 & 3: Sample points within the bounding box
        # [G] Implementation detail: Intersect ray with bounding box to get t_min and t_max.
        # If no intersection, skip.
        t_min, t_max = intersect_ray_box(ray, bounding_box)
        
        if t_min is None:
            # No intersection with box, opacity is 0, use background
            I_v[pixel_y, pixel_x] = S_v[pixel_y, pixel_x]
            continue
            
        # Sample K points along the ray segment within the box
        t_values = np.linspace(t_min, t_max, num_samples + 2)[1:-1] # Exclude endpoints if desired, or include
        # [G] Standard DVR often includes endpoints. Let's assume K samples.
        # Adjust t_values to have exactly num_samples points.
        t_values = np.linspace(t_min, t_max, num_samples)
        
        query_points = ray.origin + ray.direction * t_values[:, np.newaxis]
        
        # Step 4: Query NeRF
        # [G] object_nerf should return (delta, color) for all points in batch.
        deltas, colors = object_nerf(query_points)
        
        # Step 5: Calculate Transmittance
        # tau_k = exp(-sum_{t=1}^{k-1} delta_t * delta_t_dist)
        # delta_t_dist is the distance between adjacent query points.
        # For uniform sampling, delta_t_dist is constant.
        # [G] Calculate distances between adjacent points.
        if num_samples > 1:
            deltas_dist = np.diff(t_values)
            # Pad with 0 for the first term's sum (which is empty)
            deltas_dist = np.insert(deltas_dist, 0, 0)
        else:
            # If only 1 sample, distance is effectively 0 or handled as a single term
            # The formula uses sum_{t=1}^{k-1}. For k=1, sum is 0.
            # We need delta_k * delta_k for the opacity term.
            # Let's assume a small epsilon or actual distance for the single sample.
            # [G] In practice, for a single sample, delta_k * delta_k is approximated.
            # Let's assume uniform spacing for simplicity if num_samples > 1.
            deltas_dist = np.zeros(num_samples)
            
        # Cumulative density
        cumulative_density = np.cumsum(deltas * deltas_dist)
        transmittance = np.exp(-cumulative_density)
        
        # Step 6: Calculate Object RGB
        # G_v(i) = sum_{k=1}^K tau_k * (1 - exp(-delta_k * delta_k_dist)) * c_k
        # Note: The formula in [S1] uses delta_k * delta_k. 
        # In standard DVR, the term is (1 - exp(-delta_k * dist_k)).
        # [S1] notation: delta_k * delta_k likely means delta_k * distance_k.
        # Let's use deltas_dist for distance.
        alpha_k = 1 - np.exp(-deltas * deltas_dist)
        weights = transmittance * alpha_k
        G_v_pixel = np.sum(weights[:, np.newaxis] * colors, axis=0)
        
        # Step 7: Calculate Object Opacity
        # O_v(i) = sum_{k=1}^K tau_k * (1 - exp(-delta_k * delta_k_dist))
        # Check occlusion: D_box(i) <= D_v(i)
        # D_box(i) is the depth of the box intersection along the ray direction.
        # D_v(i) is the depth from the background cache.
        
        # Calculate depth of box intersection
        # Depth is usually the z-coordinate in camera space or distance along ray.
        # [G] Assuming D_v is depth along ray (distance from camera).
        # D_box is t_max (distance to far plane of box) or t_min?
        # [S1] says "D_box(i) <= D_v(i)". If the box is behind the scene, it's occluded.
        # So D_box should be the depth of the *front* of the box? Or the depth of the object?
        # The text says: "if the generated content is occluded by the scene foreground (D_box(i) > D_v(i))".
        # This implies D_box is the depth of the object's bounding box intersection.
        # If the box is further away than the scene, the object is behind.
        # However, if the ray intersects the box, we are inside the box's depth range.
        # The condition "ri in box" is already checked.
        # The condition "D_box(i) <= D_v(i)" likely refers to the depth of the *front* of the box
        # or the depth of the *object* relative to the scene.
        # Let's assume D_box(i) is the depth of the front intersection of the ray with the box.
        # If the scene is closer (D_v < D_box), the object is behind the scene -> occluded.
        # Wait, if D_v < D_box, the scene is in front. So the object is behind.
        # The formula says: if D_box <= D_v, then render object.
        # This implies D_box is the depth of the *back* of the box? Or the object itself?
        # Let's re-read: "if the generated content is occluded by the scene foreground (D_box(i) > D_v(i))".
        # If D_box > D_v, the box is behind the scene. So the object is occluded.
        # So if D_box <= D_v, the box is in front of or at the same depth as the scene.
        # This suggests D_box is the depth of the *front* of the box?
        # If the front of the box is in front of the scene, the object is visible.
        # If the front of the box is behind the scene, the object is occluded.
        # So D_box should be the depth of the front intersection (t_min).
        
        t_min_depth = t_min # Distance along ray to front of box
        
        if t_min_depth <= D_v[pixel_y, pixel_x]:
            O_v_pixel = np.sum(weights)
        else:
            O_v_pixel = 0.0
            
        # Step 8: Composite
        # I_v = G_v * O_v + S_v * (1 - O_v)
        I_v[pixel_y, pixel_x] = G_v_pixel * O_v_pixel + S_v[pixel_y, pixel_x] * (1 - O_v_pixel)
        
    return I_v
```

**Parameters:**
*   `num_samples` ($K$): Number of query points along the ray. Typical values are not specified in the sources. [Not given in the sources.]
*   `bounding_box`: Defines the 3D extent of the object. [S1]

**Edge Cases and Pitfalls:**
*   **No Intersection:** If the ray $r_i$ does not intersect the 3D bounding box, the opacity $O_v(i)$ is set to 0, and the background $S_v$ is used directly [S1].
*   **Occlusion:** If the depth of the bounding box intersection $D_{box}(i)$ is greater than the background depth $D_v(i)$, the object is considered occluded by the scene foreground. In this case, $O_v(i)$ is set to 0, and the background $S_v$ is used [S1].
*   **Precision:** The exponential function in transmittance calculation can suffer from underflow for high densities or large distances. [G] Standard practice is to clamp densities or use log-space accumulation.

## Operating characteristics
*   **Time Complexity:** The method reduces computational load by pre-rendering the background scene [S1]. The object rendering cost is proportional to the number of pixels, the number of samples $K$, and the number of viewpoints if rendered for all [S1].
*   **Memory Complexity:** Requires storing the pre-rendered RGB-D image sequences for all viewpoints $\{C_0, \dots, C_n\}$ [S1].
*   **Strengths:** Decouples object and scene rendering, enhancing flexibility [S1]. Handles occlusions effectively using 3D-aware opacity maps [S1]. Plug-and-play compatibility with various scene pre-training methods [S1].
*   **Limitations:** Requires pre-rendering the background for all viewpoints, which may be memory-intensive for large scenes or many viewpoints [S1]. Limited to the predefined set of camera viewpoints [S1].
*   **When to Use:** When integrating generated objects into a static NeRF scene with known viewpoints, especially for VR content creation where specific viewpoints are important [S1].
*   **When Not to Use:** For dynamic scenes or viewpoints not included in the pre-rendered set [S1].

## Background
Compositional Rendering was introduced in the GO-NeRF paper [S1]. It is designed for virtual reality content creation, allowing users to generate and integrate objects into 3D scenes using a user-friendly interface [S1]. The method leverages the decoupling of object and scene rendering to simplify the process for casual users [S1].
