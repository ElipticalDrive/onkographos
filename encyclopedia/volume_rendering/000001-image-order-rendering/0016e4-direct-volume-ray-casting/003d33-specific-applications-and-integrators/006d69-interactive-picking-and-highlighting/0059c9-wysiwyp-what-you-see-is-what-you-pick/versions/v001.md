# WYSIWYP (What You See Is What You Pick)
Also called: Visibility-Oriented Picking, WYSIWYG picking, WYSIWYP Picking, opacity-jump picking

## Overview
WYSIWYP is a volume picking technique that enables users to intuitively select 3D spatial positions in volumetric renderings based solely on the volume data, the transfer function, and the user's perception of visibility, without requiring pre-segmented data or metadata [S1]. It identifies the 3D position corresponding to a 2D screen click by finding the interval along the viewing ray with the largest jump in accumulated opacity [S1]. Unlike standard Direct Volume Ray Casting (DVR) which integrates color and opacity for display, WYSIWYP analyzes the derivative of accumulated opacity to detect visible structures [S1]. It is distinguished from sibling methods like the [TVAM Integrator](6814-tvam-integrator.md) or [Cinematic Rendering](9473-cinematic-rendering.md) by its specific focus on interaction and selection rather than photorealistic shading or global illumination, and from [Compositional Rendering](11182-compositional-rendering.md) by its single-pass, visibility-oriented criterion [S1].

## How it works
**Inputs:**
*   Volume scalar field data $d(x)$.
*   Transfer function mapping data values to source color $C_{src}$ and source opacity $\alpha_{src}$.
*   Camera position (eye point) and screen click coordinates.
*   Step size $h$ (must match DVR rendering step size for consistency) [S1].

**Outputs:**
*   A 3D position $p$ representing the picked feature.

**Data Structures:**
*   Ray parameter $s$ (distance along ray).
*   Accumulated opacity $\alpha_{acc}(s)$.
*   First derivative $\beta_{acc}(s) = \frac{d\alpha_{acc}}{ds}$.
*   Second derivative $\gamma_{acc}(s) = \frac{d^2\alpha_{acc}}{ds^2}$.
*   Jump interval $I = [i_0, i_{max}]$ and magnitude $j$.

**Pseudocode:**

```python
def wysiwy_pick(camera_eye, screen_click, volume_data, transfer_function, step_size):
    # 1. Ray Definition
    # Transform screen click to world coordinates to get ray origin and direction
    ray_origin = screen_to_world(screen_click, camera_eye)
    ray_direction = normalize(ray_origin - camera_eye) # Note: ray goes from eye to screen
    
    # 2. Entry Point Determination
    # Use a transparent bounding cube (proxy geometry) around the volume
    entry_point = intersect_bounding_cube(ray_origin, ray_direction)
    
    # 3. Ray Casting and Accumulation
    # Initialize accumulated opacity
    alpha_acc = 0.0
    
    # Store history of alpha_acc for derivative calculation
    # We assume equidistant samples with step_size h
    alpha_history = []
    s_current = 0.0
    
    # Step through the volume until exit
    while True:
        # Current sample position in world coordinates
        pos = entry_point + ray_direction * s_current
        
        # Check if outside bounding box
        if not is_inside_volume(pos, volume_data.bounds):
            break
            
        # Sample data and apply transfer function
        d_val = sample_volume(pos, volume_data)
        alpha_src, _ = transfer_function(d_val)
        
        # Update accumulated opacity using front-to-back compositing
        # alpha_acc^{n+1} = alpha_acc^n + (1 - alpha_acc^n) * alpha_src
        alpha_acc_new = alpha_acc + (1.0 - alpha_acc) * alpha_src
        
        alpha_history.append(alpha_acc_new)
        alpha_acc = alpha_acc_new
        
        # Advance step
        s_current += step_size

    # 4. Derivative Calculation
    # Compute first and second derivatives of alpha_acc along the ray
    # beta_acc[i] approx (alpha[i+1] - alpha[i]) / h
    # gamma_acc[i] approx (beta[i+1] - beta[i]) / h
    beta_acc = []
    for i in range(len(alpha_history) - 1):
        beta = (alpha_history[i+1] - alpha_history[i]) / step_size
        beta_acc.append(beta)
        
    gamma_acc = []
    for i in range(len(beta_acc) - 1):
        gamma = (beta_acc[i+1] - beta_acc[i]) / step_size
        gamma_acc.append(gamma)

    # 5. Jump Interval Detection
    # Identify intervals where opacity jumps significantly
    # Lower bound i0: gamma_acc becomes positive after being negative or zero
    # Upper bound imax: gamma_acc becomes zero or positive after being negative
    
    intervals = []
    i = 0
    while i < len(gamma_acc):
        # Check for lower bound
        if gamma_acc[i] > 0 and (i == 0 or gamma_acc[i-1] <= 0):
            start_index = i # Corresponds to position in alpha_history
            
            # Find upper bound
            # Look for gamma becoming zero or positive after being negative
            # Note: gamma is defined at indices 0..N-2 for N alpha values
            # We need to map back to alpha indices carefully.
            # Let's find the end of the "negative gamma" region following this start
            
            end_index = None
            for k in range(i, len(gamma_acc)):
                # Upper bound condition: gamma becomes zero or positive after being negative
                # This implies the previous gamma was negative
                if k > 0 and gamma_acc[k-1] < 0 and gamma_acc[k] >= 0:
                    end_index = k
                    break
            
            if end_index is not None:
                # Map derivative indices to alpha indices
                # alpha_history has length L. beta has L-1. gamma has L-2.
                # gamma[i] is between alpha[i] and alpha[i+1] roughly?
                # Actually, beta[i] = (alpha[i+1]-alpha[i])/h.
                # gamma[i] = (beta[i+1]-beta[i])/h.
                # So gamma[i] relates to alpha[i], alpha[i+1], alpha[i+2].
                # The "jump" starts where alpha starts growing faster (gamma > 0).
                # The "jump" ends where alpha stops decreasing (gamma >= 0 after < 0).
                
                # Approximate interval in alpha_history indices
                # Lower bound i0 corresponds to the alpha index where the jump begins.
                # Based on the paper: "lower bounds i0 ... are positions where accumulated opacity starts to grow stronger"
                # "upper bounds imax ... is that alpha_acc stops decreasing again"
                
                # Let's use the indices in alpha_history directly for simplicity in mapping
                # i0 is the index in alpha_history corresponding to the start of the interval
                # imax is the index in alpha_history corresponding to the end
                
                # Refining mapping:
                # If gamma[i] > 0, it means beta is increasing.
                # The interval of the "jump" is roughly between the start of the rise and the end of the fall.
                # Paper says: "Select the interval I with the largest jump magnitude j"
                # j = alpha_acc(i0) - alpha_acc(imax)
                
                # Let's assume i0 is the index in alpha_history where the rise begins.
                # And imax is the index where the fall ends.
                
                # In the discrete sequence:
                # Start of rise: alpha[i0] is the first point in the rising segment.
                # End of fall: alpha[imax] is the last point in the falling segment? 
                # No, alpha is monotonically increasing. 
                # Wait, alpha_acc is monotonically increasing. 
                # The paper says: "j = alpha_acc(i0) - alpha_acc(imax)"? 
                # If alpha is increasing, alpha(i0) < alpha(imax) if i0 < imax.
                # Let's re-read carefully: "j = alpha_acc(i0) - alpha_acc(imax)"
                # This implies alpha_acc decreases? 
                # "alpha_acc is monotonically increasing along the ray" [S1].
                # "j = alpha_acc(i0) - alpha_acc(imax)" [S1].
                # If i0 is the start (front) and imax is the end (back), and alpha increases, 
                # then alpha(i0) < alpha(imax). The difference would be negative.
                # Perhaps i0 is the BACK and imax is the FRONT? 
                # "lower bounds i0 ... upper bounds imax"
                # "front position i0 ... center ic = 1/2(i0 + imax)"
                # If i0 is front and imax is back, and alpha increases, alpha(i0) < alpha(imax).
                # The formula j = alpha(i0) - alpha(imax) would be negative.
                # Maybe the formula is |alpha(i0) - alpha(imax)| or alpha(imax) - alpha(i0)?
                # Or maybe i0 is the index of the BACK of the feature and imax is the FRONT?
                # "lower bounds i0 ... upper bounds imax" usually implies i0 < imax in index.
                # "front position i0" implies i0 is the first point encountered (smallest s).
                # "upper bounds imax" implies imax is the last point encountered (largest s).
                # So i0 < imax.
                # If alpha is increasing, alpha(i0) < alpha(imax).
                # The "jump" is the change in opacity.
                # Maybe the formula in the source has a typo or I am misinterpreting "jump".
                # "largest jump of the accumulated opacity"
                # Usually jump = alpha_end - alpha_start.
                # Let's assume the magnitude is |alpha(imax) - alpha(i0)|.
                # The paper says: "j = alpha_acc(i0) - alpha_acc(imax)" [S1].
                # This is physically impossible for increasing alpha if i0 < imax.
                # However, if we look at the context: "difference between alpha_acc at the start and the end ... j = alpha_acc(i0) - alpha_acc(imax)".
                # If i0 is the START (front) and imax is the END (back), and alpha increases, 
                # then alpha(i0) is small, alpha(imax) is large.
                # Perhaps the paper defines i0 as the BACK and imax as the FRONT?
                # "lower bounds i0 ... upper bounds imax"
                # "front position i0"
                # This is contradictory if i0 is both lower bound (index) and front (position).
                # Let's look at the derivative logic.
                # Gamma > 0 means Beta is increasing. Beta is slope of Alpha.
                # If Alpha is convex, Gamma > 0.
                # If Alpha is concave, Gamma < 0.
                # A "jump" in opacity contribution often corresponds to a region of high opacity density.
                # High opacity density -> Alpha rises fast -> Beta is high.
                # Beta rises -> Gamma > 0.
                # Beta falls -> Gamma < 0.
                # So a "jump" interval is where Gamma goes from negative to positive (start of rise in slope) 
                # to positive to negative (end of rise in slope)?
                # Or negative to positive (start of convexity) to zero/positive after negative (end of concavity)?
                # The paper says: "lower bounds i0 ... gamma becomes positive after being negative or zero"
                # "upper bounds imax ... gamma becomes zero or positive after being negative"
                # This detects the start and end of a region where the slope is increasing or stabilizing?
                # Actually, if Alpha is monotonic, Beta is positive.
                # Gamma is the change in Beta.
                # A "feature" might be a region of high opacity.
                # Inside the feature, Alpha rises steeply (High Beta).
                # Before the feature, Alpha rises slowly (Low Beta).
                # So Beta increases -> Gamma > 0.
                # After the feature, Alpha rises slowly again (Low Beta).
                # So Beta decreases -> Gamma < 0.
                # So the interval of the feature is where Gamma > 0?

                # Start of feature: Gamma goes from <0 to >0.
                # End of feature: Gamma goes from >0 to <0.
                # The paper's criteria:
                # Lower bound i0: Gamma > 0 after <= 0. (Start of positive Gamma region).
                # Upper bound imax: Gamma >= 0 after < 0. (This seems to describe the start of a new positive region or end of negative?)
                # "upper bounds imax ... is that alpha_acc stops decreasing again" -> Alpha doesn't decrease.
                # "For gamma_acc this means that it becomes zero or positive after being negative."
                # This criterion for imax is identical to i0?
                # "The lower bounds i0 ... are the positions where accumulated opacity starts to grow stronger, that is where gamma_acc becomes positive after being negative or zero."
                # "The criterion for the upper bounds imax is that alpha_acc stops decreasing again. For gamma_acc this means that it becomes zero or positive after being negative."
                # This text is confusing. If alpha_acc is monotonic, it never decreases.
                # Perhaps "stops decreasing" refers to the derivative beta? No, beta is positive.
                # Let's assume the standard edge detection:
                # Interval is defined by Gamma > 0.
                # Start: Gamma crosses 0 from below.
                # End: Gamma crosses 0 from above.
                # The paper's text for imax might be a typo or specific to plateau handling.
                # "Plateaus ... gamma_acc is constantly zero."
                # "adapted ... lower bounds i0 ... gamma becomes positive after being negative or zero."
                # "upper bounds imax ... gamma becomes zero or positive after being negative."
                # If Gamma is 0 on a plateau, and then becomes positive, that's a start.
                # If Gamma is 0 on a plateau, and was negative before, that's a start.
                # If Gamma is 0 on a plateau, and becomes negative after, that's an end?
                # The text says "becomes zero or positive after being negative".
                # This sounds like a start condition.
                # However, we must follow the source.
                # Let's implement the detection of intervals where Gamma is positive.
                # i0 is the first index where Gamma > 0 (preceded by <= 0).
                # imax is the last index where Gamma > 0 (followed by <= 0)?
                # Or is imax the index where Gamma becomes 0/positive after negative?
                # If Gamma goes Neg -> Pos -> Neg, the Pos region is the feature.
                # i0 is the start of Pos.
                # imax is the end of Pos?
                # The text for imax: "becomes zero or positive after being negative".
                # If Gamma is Pos, then Neg, then 0/Pos, that's a new feature.
                # Maybe imax is the index of the LAST point of the feature?

                # And j = |alpha(imax) - alpha(i0)|.
                
                # Mapping indices:
                # gamma_acc has length L-2.
                # gamma_acc[k] corresponds to the change in slope between alpha[k], alpha[k+1], alpha[k+2].
                # If gamma_acc[k] > 0, the slope is increasing at k+1.
                # Let's define the interval in alpha indices.
                # Start index i0_alpha: The alpha index where the jump starts.
                # End index imax_alpha: The alpha index where the jump ends.
                
                # Based on "front position i0" and "center ic = 1/2(i0 + imax)", i0 and imax are positions.
                # Let's use the indices in alpha_history.
                
                # Detect start of positive gamma region
                start_alpha_idx = -1
                for k in range(len(gamma_acc)):
                    if gamma_acc[k] > 0 and (k == 0 or gamma_acc[k-1] <= 0):
                        # This gamma[k] is positive. It relates to alpha[k], alpha[k+1], alpha[k+2].
                        # The "start" of the feature is likely around alpha[k] or alpha[k+1].
                        # Let's assume i0 corresponds to alpha[k].
                        start_alpha_idx = k
                        break
                
                if start_alpha_idx == -1:
                    continue
                    
                # Detect end of positive gamma region
                # The paper's criterion for imax is tricky. 
                # "gamma becomes zero or positive after being negative"
                # If we are in a positive region, gamma is positive.
                # The end of the region is when gamma becomes negative.
                # But the text says "becomes zero or positive after being negative".
                # This might mean the end of the PRECEDING negative region? No.
                # Let's assume the interval ends when gamma becomes negative.
                end_alpha_idx = -1
                for k in range(start_alpha_idx, len(gamma_acc)):
                    if gamma_acc[k] < 0:
                        # The positive region ended at k-1.
                        # The end of the feature is around alpha[k] or alpha[k+1].
                        end_alpha_idx = k
                        break
                
                if end_alpha_idx == -1:
                    # Feature extends to end of ray
                    end_alpha_idx = len(gamma_acc)
                    
                # Calculate jump magnitude
                # j = alpha_acc(i0) - alpha_acc(imax) [Source formula]
                # Assuming absolute difference or correct order
                alpha_start = alpha_history[start_alpha_idx]
                alpha_end = alpha_history[end_alpha_idx]
                jump_magnitude = abs(alpha_end - alpha_start)
                
                intervals.append({
                    'start_idx': start_alpha_idx,
                    'end_idx': end_alpha_idx,
                    'magnitude': jump_magnitude,
                    'start_pos': entry_point + ray_direction * (start_alpha_idx * step_size),
                    'end_pos': entry_point + ray_direction * (end_alpha_idx * step_size)
                })

    # 6. Selection
    if not intervals:
        return None
        
    # Select interval with largest jump
    best_interval = max(intervals, key=lambda x: x['magnitude'])
    
    # Determine final position
    # For labeling, use front position i0
    # For repositioning slices, use center position ic
    # Default to front for general picking
    picked_position = best_interval['start_pos']
    
    return picked_position
```

**Parameters:**
*   **Step Size:** Must match the step size used for DVR rendering. If different, opacity correction must be applied [S1].
*   **Sample Density:** Assumes equidistant samples. Extendable to non-equidistant samples with opacity correction [S1].

**Edge Cases and Pitfalls:**
*   **Step Size Inconsistency:** If DVR uses half the step size (twice as many samples) as the picking ray, accumulated opacity varies differently, leading to incorrect picking [S1].
*   **Plateaus:** If $\alpha_{acc}$ has plateau-like regions, $\gamma_{acc}$ is constantly zero. The boundary detection is adapted to handle this by checking for transitions from negative/zero to positive for lower bounds, and zero/positive after negative for upper bounds [S1].
*   **Noisy Data:** The method does not ensure that close positions in screen space result in close 3D locations, particularly in noisy datasets [S1].
*   **Local Illumination:** The method is limited to the standard emission-absorption model and does not currently handle local illumination applied after evaluating the transfer function [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples along the ray, $O(N)$, where $N$ is the number of steps through the volume. Derivative calculation is also $O(N)$.
*   **Memory Complexity:** $O(N)$ to store the history of accumulated opacity for derivative calculation.
*   **Measured Performance:** In a user study with 36 test cases, WYSIWYP picked positions within one standard deviation of the mean perceived position for 89% (32 of 36) of cases [S1].
*   **Strengths:** Does not require metadata or pre-segmented data; applicable to any volumetric scalar dataset and all types of transfer functions, including "foggy" images; handles cases where threshold-based picking fails (thresholds too high/low) [S1].
*   **Limitations:** Does not handle local illumination; does not guarantee spatial coherence for adjacent screen pixels in noisy data; limited to standard emission-absorption model [S1].
*   **When to Use:** When users need to pick visible structures in arbitrary volume data without metadata, or for automated slice positioning [S1].
*   **When Not to Use:** When local illumination is present, or when high spatial coherence for adjacent clicks is required in noisy data [S1].

## Background
WYSIWYP was introduced by [S1] to overcome limitations of previous picking methods that required metadata, were designed for medical data only, or provided only basic techniques like first-hit or opacity-threshold. It is based on the principle that users want to examine structures made visible by DVR and suitable transfer functions. The method was implemented in the Amira visualization software and applied to abdominal MRI scans, flow simulation vorticity fields, synthetic scalar functions, and fuel injection combustion chamber simulations [S1].
