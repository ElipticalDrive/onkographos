# Depth-Enhanced Maximum Intensity Projection


## Overview
Depth-Enhanced Maximum Intensity Projection (DEMIP) is a volume rendering technique that improves depth perception in Maximum Intensity Projection (MIP) by modifying intensity accumulation via depth weighting and applying a sphere-based color mapping to disambiguate the ordering of internal structures [S1]. Unlike standard MIP, which loses spatial context, DEMIP provides depth cues and occlusion visibility without requiring the complex transfer function definition of Direct Volume Ray Casting (DVR) [S1]. It differs from isosurface-based depth methods by directly rendering the model using classical GPU raycasting [S1].

## How it works
DEMIP executes a two-pass GPU volume ray-casting within a single fragment shader to determine the final pixel color [S1]. The method combines occlusion revealing (via depth weighting) and spatial color-coding (via a color sphere) [S1].

### Inputs and Outputs
*   **Inputs:** Volumetric data, MIP transfer function, camera parameters, depth weight parameter $dw$, color sphere texture.
*   **Outputs:** Final color buffer with enhanced depth perception.

### Data Structures
*   **Material Value:** A scalar or vector representing the material property at a sample point, derived from the MIP transfer function applied to density [S1].
*   **Color Sphere:** An auxiliary sphere texture used for spatial color-coding. The color distribution on the sphere is mapped to the object's 3D position, allowing users to infer spatial distribution [S1].

### Algorithm Steps
1.  **First Ray Pass (MIP Detection):** Trace a ray through the volume. At each sample, apply the MIP transfer function to the density value to determine the material. Store the material value when the ray reaches the maximum intensity encountered along the ray [S1]. Let this maximum material value be $MIP_{mat}$ and its associated color be $MIP_{color}$ [S1].
2.  **Second Ray Pass (Depth and Occlusion Detection):** Trace a second ray along the same path. Look for the first point where the material value is equal to $MIP_{mat}$ (within a threshold $\epsilon$ to handle discrete sampling noise) [S1].
    *   If such a point is found, store its depth. This point represents the occluding structure if it is closer than the MIP point, or the same structure if no occlusion exists [S1].
    *   If no such point is found (or if the found point is the same as the MIP point), the depth is derived from the MIP point's position [S1].
3.  **Depth Calculation:** Compute the normalized depth $depth$ of the point to shade. The sources specify an approximation that yields the best results:
    $$ depth = OpenGL\_depth\_rayIn + ray\_length $$
    where $OpenGL\_depth\_rayIn$ is the initial ray start position's OpenGL depth, and $ray\_length$ is the number of steps traced inside the bounding box [S1]. This value is normalized such that it maps to zero at the near plane [S1].
    *   *Note:* Using only OpenGL depth yields poor results due to perspective projection inaccuracies. Using only ray length produces artifacts near the boundary when rotating the object [S1].
4.  **Color Composition:** Calculate the final color by weighting the $MIP_{color}$ with the depth value using the depth weight parameter $dw$, and optionally applying a color tint from the sphere-based mapping [S1].

### Formula
The final color is calculated as [S1]:
$$ color = MIP_{color} * (1 - dw) + 2 * dw * (1 - depth) $$
where:
*   $MIP_{color}$ is the color from the MIP transfer function.
*   $dw$ is the depth weight parameter.
*   $depth$ is the normalized distance of the point to the near plane.

If $dw = 0$, the result is the standard MIP color [S1].

### Parameters
*   **$dw$ (Depth Weight):** Controls the strength of the depth-based shading. A typical value is around 0.15, which is sufficient for enhancing occlusions while keeping details visible [S1].

### Edge Cases and Pitfalls
*   **Discrete Sampling Noise:** Due to discrete sampling, the algorithm may fail to detect the "same material" even if it exists, leading to noise in the images [S1]. This is handled by using a threshold to detect values around the value of interest [S1]. Changing this threshold may enhance different structures [S1].
*   **Depth Approximation Errors:** Using OpenGL depth directly yields poor results. Using only the number of ray steps inside the bounding box produces artifacts near the boundary when rotating the object [S1].

### Pseudocode
```python
# Pseudocode for Depth-Enhanced Maximum Intensity Projection (DEMIP)
# Assumes access to volume texture, MIP transfer function, and color sphere texture.

function fragment_shader():
    # 1. First Pass: Find Maximum Intensity (MIP)
    max_intensity = -infinity
    mip_material = 0
    mip_depth_pos = 0
    
    # Trace ray from near plane to far plane
    for sample in trace_ray():
        density = sample_volume(sample.position)
        material = mip_transfer_function(density)
        intensity = material # Assuming material maps to intensity for MIP
        
        if intensity > max_intensity:
            max_intensity = intensity
            mip_material = material
            mip_depth_pos = sample.position
            
    mip_color = get_color_from_material(mip_material)
    
    # 2. Second Pass: Find Occluding Structure with Same Material
    found_occlusion = false
    occlusion_depth = 0
    
    # Trace ray again
    for sample in trace_ray():
        density = sample_volume(sample.position)
        material = mip_transfer_function(density)
        
        # Check if material matches MIP material within threshold
        if abs(material - mip_material) < epsilon:
            # Store the first occurrence (closest to viewer)
            occlusion_depth = compute_depth(sample.position)
            found_occlusion = true
            break
            
    # If no occlusion found or same point, use MIP depth
    if not found_occlusion:
        occlusion_depth = compute_depth(mip_depth_pos)
        
    # 3. Compute Depth Value
    # Approximation: OpenGL depth of ray start + ray length inside bounding box
    # This maps to zero at the near plane
    depth = compute_depth_approximation(mip_depth_pos)
    
    # 4. Apply Depth Weighting
    dw = 0.15 # Typical value
    final_color = mip_color * (1 - dw) + 2 * dw * (1 - depth)
    
    # 5. Apply Color Sphere Tinting (Optional)
    # Map 3D position to sphere texture coordinates
    sphere_uv = map_to_sphere(mip_depth_pos)
    sphere_color = sample_color_sphere(sphere_uv)
    final_color = apply_tint(final_color, sphere_color)
    
    return final_color

function compute_depth_approximation(position):
    # OpenGL depth of the ray start position
    ray_in_depth = get_opengl_depth_at_ray_start()
    # Number of steps traced inside the bounding box
    ray_length = count_steps_inside_bbox(position)
    return ray_in_depth + ray_length
```

## Subtopics

### Single-Pass DEMIP Implementation
An implementation strategy where the entire DEMIP algorithm (two ray casts and color composition) is performed in a single fragment shader, avoiding the overhead of intermediate 2D texture storage and multiple rendering passes [S1]. It traces the first ray to find the maximum intensity (MIP) and stores the material/depth, then traces a second ray until reaching a material equal (within epsilon) to the one found in the first pass, and finally modifies the color using the depth computed in the second step [S1]. For the Jaw model, single-pass achieved 53.8 fps, while two-pass achieved 49.7 fps and three-pass achieved 49.4 fps [S1].

### Shape-enhanced Maximum Intensity Projection
An approach inspired by DEMIP that applies Phong shading using gradients of closest samples along viewing rays, followed by tone reduction [S2, unofficial]. It applies the Phong shading model using the gradient of the closest samples along viewing rays, performs a tone reduction operator to preserve the MIP local contrast in the shaded image, and uses depth-based color cues to better perceive depth information [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** DEMIP is slower than standard MIP because it requires an extra ray casting step (two rays per pixel) [S1]. However, it is usually faster than DVR [S1].
*   **Memory Complexity:** Requires storage for the volume data, MIP transfer function, and color sphere texture. Single-pass implementation avoids intermediate 2D texture storage [S1].
*   **Measured Performance:** For the Jaw model, single-pass achieved 53.8 fps, two-pass 49.7 fps, and three-pass 49.4 fps [S1]. For the Body model, single-pass achieved 24.0 fps, two-pass 22.7 fps, and three-pass 22.7 fps [S1]. For the Head model, single-pass achieved 25.8 fps, two-pass 25.0 fps, and three-pass 24.9 fps [S1].
*   **Strengths:** Provides depth cues and occlusion visibility; does not require complex transfer function definition; usually faster than DVR; maintains MIP's detail visibility [S1].
*   **Limitations:** Slower than standard MIP; discrete sampling may cause noise if threshold is not tuned; depth approximation may have inaccuracies [S1].
*   **When to Use:** When depth perception is critical in MIP-like visualizations, but complex transfer functions are undesirable [S1].
*   **When Not to Use:** When maximum performance is required and depth perception is not critical (use standard MIP); when exact isosurface extraction is needed (use other methods) [S1].

## Background
DEMIP was introduced by Díaz and Vázquez in 2010 [S1]. It was developed to address the lack of depth perception in MIP rendering, which impairs spatial comprehension of large, complex structures [S1]. The method lies between MIP and DVR, improving depth perception by changing how intensity is accumulated, while producing results similar to isosurface-based methods without the need for isosurface extraction [S1]. The authors conducted a user study to evaluate the results [S1]. Shape-enhanced MIP, inspired by DEMIP, was later presented by Zhou et al. [S2, unofficial].
