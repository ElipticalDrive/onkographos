# Basis Transform for Trivariate Polynomials

Also called: B-spline to Bernstein/Power Basis Transform

## Overview
This method transforms a trivariate polynomial from a B-spline basis to a scaled Bernstein or power basis to enable efficient root finding and volume compositing without storing explicit polynomial descriptions for every voxel [S1]. It distinguishes itself by leveraging the tensor product structure of the N-dimensional basis to decompose the transformation into efficient one-dimensional operations integrated into a Horner scheme [S1].

## How it works
The core problem addressed is that while B-spline representations are efficient for interpolation, algebraic methods often require the polynomial in a different basis [S1]. Storing the explicit coefficients for every voxel in these new bases increases memory consumption by a factor of $(d + 1)^3$ [S1]. Instead, this method computes the transformation on-the-fly [S1].

**Inputs and Outputs:**
*   **Input:** B-spline coefficients for a voxel, polynomial degree $d$, spatial dimension $N$ (typically 3), and target basis (Scaled Bernstein or Power) [S1].
*   **Output:** The transformed coefficients in the target basis, ready for evaluation via a Horner scheme [S1].

**Data Structures:**
*   **Basis Vector:** A vector of size $d+1$ representing the coefficients in the current basis [S1].
*   **Transform Matrix:** A square matrix of size $(d+1) \times (d+1)$ containing zeros and ones, scaled by a constant factor to reduce arithmetic operations [S1].

**Steps:**
1.  **One-Dimensional Basis Transform:**
    For a single dimension, the transformation from the B-spline basis to the target basis is performed by multiplying the basis vector $\mathbf{b}$ by the transform matrix $\mathbf{M}$:
    $$ \mathbf{b}_{\text{new}} = \mathbf{M} \cdot \mathbf{b} $$
    The matrix $\mathbf{M}$ is designed to contain zeros and ones [S1]. By factoring out a constant scaling factor, the number of multiplications is minimized [S1].
    *   For transition to the **Scaled Bernstein basis**, 6 multiplications are required per dimension [S1].
    *   For transition to the **Power basis**, 8 multiplications are required per dimension [S1].

2.  **N-Dimensional Basis Transform Construction:**
    The N-dimensional basis is a tensor product of the one-dimensional bases [S1]. Consequently, the N-dimensional basis transform is constructed from $N \cdot (d + 1)^{N-1}$ one-dimensional basis transforms [S1]. This decomposition exploits the separability of the basis functions [S1].

3.  **Integration with Horner Scheme:**
    The basis transform is integrated efficiently into the Horner scheme for polynomial composition [S1]. The Horner scheme evaluates the polynomial by iteratively applying operations that separate single dimensions, aligning with the tensor product structure of the transform [S1].

**Pseudocode:**
The following pseudocode demonstrates the one-dimensional transform and its integration into a 3D Horner evaluation. It assumes `basis_vector` contains the B-spline coefficients.

```python
def mat_vec_mul(matrix, vector):
    """Performs matrix-vector multiplication for a (d+1)x(d+1) matrix."""
    size = len(vector)
    result = [0.0] * size
    for i in range(size):
        s = 0.0
        for j in range(size):
            s += matrix[i][j] * vector[j]
        result[i] = s
    return result

def transform_basis_1d(basis_vector, degree, target_basis):
    """
    Transforms a 1D basis vector from B-spline to Scaled Bernstein or Power basis.
    Returns the transformed coefficients.
    """
    size = degree + 1
    # The source specifies operation counts (6 for scaled Bernstein, 8 for power)
    # but does not provide explicit matrix entries [G].
    # M contains zeros and ones, scaled by a constant factor.
    M = [[0.0] * size for _ in range(size)] # Populate M according to basis conversion
    return mat_vec_mul(M, basis_vector)

def evaluate_trivariate_horner(coeffs, x, y, z):
    """
    Evaluates the trivariate polynomial using the Horner scheme.
    coeffs is a nested array of size (d+1)^3 in the target basis.
    """
    degree = len(coeffs[0][0]) - 1
    result = 0.0
    for k in range(degree, -1, -1):
        for j in range(degree, -1, -1):
            for i in range(degree, -1, -1):
                result = result * x + coeffs[i][j][k]
            result = result * y
        result = result * z
    return result
```

**Parameters:**
*   **Degree ($d$):** The polynomial degree. For tri-cubic filtering, $d=3$ [S1].
*   **Target Basis:** "Scaled Bernstein" or "Power" [S1].

**Edge Cases and Pitfalls:**
*   **Memory:** Storing explicit descriptions for all voxels increases memory by $(d+1)^3$ [S1]. This method avoids that by computing on-the-fly [S1].
*   **Operations:** The use of matrices with zeros and ones, scaled by constants, reduces the number of floating-point multiplications, improving computational efficiency rather than numerical stability [S1].

## Subtopics

### [Polynomial Basis Vector Generation](3511-polynomial-basis-vector-generation.md)
Constructs the explicit monomial basis vector for a given spatial point and polynomial degree. It serves as the foundational step for the Basis Transform for Trivariate Polynomials, enabling the conversion of B-spline coefficients into a form suitable for efficient root finding and volume compositing. Unlike methods that store full polynomial descriptions, this method generates the basis vector on-the-fly or caches it, avoiding the memory overhead of storing every single polynomial's coefficients explicitly. It is distinct from the Basis Matrix Generation variant, which aggregates these vectors into a matrix structure for batch processing.

## Operating characteristics
*   **Time Complexity:** The one-dimensional basis transform requires a fixed number of multiplications: 6 for the scaled Bernstein basis and 8 for the power basis, regardless of the dataset size [S1]. The N-dimensional transform scales with $N \cdot (d + 1)^{N-1}$ one-dimensional transforms [S1].
*   **Memory Complexity:** Minimal additional memory is required as the transformation is performed on-the-fly [S1]. It avoids the $(d+1)^3$ memory multiplier associated with storing explicit polynomial descriptions [S1].
*   **Strengths:** Efficient for large datasets where memory is a constraint [S1]. The separation of dimensions allows for efficient integration with the Horner scheme [S1].
*   **Limitations:** Requires knowledge of the underlying data structure and memory location for efficient on-the-fly computation [S1].

## Background
The approach addresses the inefficiency of storing explicit polynomial descriptions for every voxel, which is particularly problematic in the context of tri-linear and tri-cubic filtering based on B-spline polynomials [S1].
