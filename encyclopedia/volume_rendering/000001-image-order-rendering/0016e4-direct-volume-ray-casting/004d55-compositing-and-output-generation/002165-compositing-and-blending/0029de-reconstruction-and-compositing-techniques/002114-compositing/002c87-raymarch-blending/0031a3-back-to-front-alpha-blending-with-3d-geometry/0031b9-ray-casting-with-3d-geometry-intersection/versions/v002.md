# Ray-Casting with 3D Geometry Intersection

Also called: Volume-Geometry Ray Casting

## Overview
This method extends direct volume ray casting by integrating pre-rendered 3D polygonal geometry depth data, allowing volumetric rays to detect intersections with opaque solid objects and terminate or blend correctly [S1]. Unlike standard ray casting which only evaluates volume density, this approach ensures correct occlusion of the volume by solid geometry, solving the problem of rendering transparent volumes over opaque meshes in a specific pipeline configuration [S1].

## How it works
The algorithm modifies the ray-casting traversal loop to compare the ray's current depth against the depth of 3D surfaces fetched from previous rendering passes [S1]. It assumes the scene contains no transparent 3D polygonal objects, though minor adjustments could support them [S1].

**Inputs and Outputs:**
*   **Inputs:** Volume texture, 3D surface depth texture (`uDepthSurface`), back surface depth texture (`uBackDepth`), current fragment coordinates (`texD`, `gl_FragCoord`), number of ray steps (`n_steps`), and object color (`objectColor.rgb`) [S1].
*   **Outputs:** Accumulated color (`accum.rgb`), accumulated alpha (`accum.a`), and final depth (`final_depth`) [S1].

**Data Structures and Layouts:**
*   `uBackDepth`: Texture storing the depth of the volume's back boundary [S1].
*   `uDepthSurface`: Texture storing the depth of the 3D mesh surface [S1].
*   `gl_FragCoord`: Built-in GLSL variable containing window-relative coordinates, where `.z` is depth and `.w` is used in the depth calculation [S1].
*   `ray_depth`: The current depth of the ray along its path in scene space [S1].

**Parameters:**
*   `n_steps`: The number of discrete steps the ray takes through the volume [S1].
*   `objectColor`: The RGB color of the opaque 3D object hit by the ray [S1].

**Step-by-Step Procedure:**

1.  **Initialization:** For each pixel, initialize ray parameters (`ray_origin`, `ray_direction`, `ray_step`) [S1]. Fetch depth data from previous passes to establish the depth range in scene space [S1].
2.  **Depth Calculation:** Calculate the specific depth values required for intersection testing using the following formulas [S1]:
    $$ \text{backDepth} = 1.0 - \text{unpackFloat}(\text{texture2D}(uBackDepth, \text{texD})) $$
    $$ \text{frontDepth} = 1.0 - \text{gl\_FragCoord.z} \times \text{gl\_FragCoord.w} $$
    $$ \text{surfDepth} = 1.0 - \text{unpackFloat}(\text{texture2D}(uDepthSurface, \text{texD})) $$
    $$ \text{depthStep} = \frac{\text{backDepth} - \text{frontDepth}}{n\_steps} $$
    *Note: `unpackFloat` converts the stored texture value to a linear depth value. The subtraction from 1.0 suggests the textures may store depth in a non-standard or inverted format, or this is a specific implementation detail of the source [S1].*
3.  **Ray Traversal Loop:** Iterate through the volume from `frontDepth` to `backDepth` in increments of `depthStep` [S1]. At each step, update `ray_depth` [S1].
4.  **Intersection Test:** Compare the current `ray_depth` with `surfDepth` [S1]. If the ray has intersected the surface thickness, execute the blending and termination logic [S1]:
    $$ \text{if } (\text{ray\_depth} - \text{surfDepth} > -\text{depthStep}) $$
    *Pitfall: The intersection check uses the specific inequality `(ray_depth - surfDepth) > -(depthStep)` to determine if the ray has hit the surface thickness [S1].*
5.  **Blending and Termination:** Upon intersection, update the accumulated color and alpha using front-to-back blending, update the final depth, and break the loop [S1]:
    $$ \text{accum.rgb} = (\text{accum.a} \times \text{accum.rgb}) + ((1.0 - \text{accum.a}) \times \text{objectColor.rgb}) $$
    $$ \text{accum.a} = (\text{accum.a} \times \text{accum.a}) + (1.0 - \text{accum.a}) $$
    $$ \text{final\_depth} = \text{surfDepth} $$
    $$ \text{break} $$

**Pseudocode:**

```python
def ray_cast_with_geometry(back_depth, front_depth, surf_depth, n_steps, object_color, volume_sampler):
    # Depth calculations
    depth_step = (back_depth - front_depth) / n_steps
    
    # Initialization
    ray_depth = front_depth
    accum_rgb = vec3(0.0)
    accum_a = 0.0
    final_depth = back_depth
    
    # Ray Traversal
    for _ in range(n_steps):
        ray_depth += depth_step  # Increment depth per step
        
        # [G] Standard volume ray casting: sample volume at ray_depth, update accum_rgb and accum_a based on density/color
        
        # Intersection Test
        if (ray_depth - surf_depth) > -depth_step:
            # Blend volume color with object color
            accum_rgb = (accum_a * accum_rgb) + ((1.0 - accum_a) * object_color)
            
            # Update alpha
            accum_a = (accum_a * accum_a) + (1.0 - accum_a)
            
            final_depth = surf_depth
            break
            
    return accum_rgb, accum_a, final_depth
```

**Edge Cases and Pitfalls:**
*   **Intersection Precision:** The check `(ray_depth - surfDepth) > -(depthStep)` is critical [S1].
*   **Opaque Assumption:** The method assumes opaque 3D objects [S1].
*   **Depth Space Consistency:** All depth values (`backDepth`, `frontDepth`, `surfDepth`, `ray_depth`) must be in the same coordinate space (scene space) for the comparison to be valid [S1].

## Background
This method was presented in the context of deploying volume rendering interactive visualizations in web platforms, specifically addressing the integration of intersected 3D geometry [S1]. It was published in Eurographics Proceedings in 2016 by A. Arbelaiz, A. Moreno, and L. Kabongo [S1]. The work focuses on enabling efficient volume rendering in web environments where standard GPU features for depth peeling or complex compositing might be limited or inefficient [S1].
