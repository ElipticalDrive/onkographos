# Ray Compositing and Accumulation

Also called: Hardware Ray Compositing, Ray Beam FIFO, Ray Shift Register, Ray Slice FIFO

## Overview
Ray Compositing and Accumulation combines color and opacity contributions from volume samples into final pixel values for semi-transparent rendering [S1, unofficial]. It solves the problem that volume samples are generated in slice-by-slice or beam-by-beam order rather than strict ray order, requiring hardware buffers to maintain the correct compositing sequence [S1, unofficial]. This method builds on [Compositing](2436-compositing.md) and differs from [Alpha Compositing Ray Casting](922-alpha-compositing-ray-casting.md) by explicitly buffering non-ray-order data streams for hardware alignment [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A stream of color ($C_{sample}$) and opacity ($\alpha_{sample}$) values at sample points, presented in slice-by-slice, beam-by-beam order [S1, unofficial].
*   **Output:** Final pixel values written to Pixel Memory, which are then transferred to a companion 3D graphics card for final image warping [S1, unofficial].

**Data Structures:**
The method relies on three specific hardware buffers to store partially accumulated ray values [S1, unofficial]:
1.  **Ray Slice FIFO:** Stores partially accumulated pixel values for compositing with the next slice [S1, unofficial].
2.  **Ray Beam FIFO:** Stores values for an additional beam time duration to handle downward-angled rays, allowing input from the beam above and before the current sample [S1, unofficial].
3.  **Ray Shift Register:** Stores values for one additional cycle to handle samples to the left of the current one [S1, unofficial].

**Parameters:**
*   **Precision:** 12 bits are maintained for accumulated color ($C_{acc}$), accumulated opacity ($acc$), and all intermediate compositing values to ensure correct alpha blending in large volumes [S1, unofficial].

**Steps:**
1.  **Determine Predecessor:** For a sample $S(x,y,z)$, identify the correct predecessor value from the previous slice [S1, unofficial]. The predecessor is one of $S(x,y,z-1)$, $S(x-1,y,z-1)$, $S(x,y-1,z-1)$, or $S(x-1,y-1,z-1)$, selected based on the view direction and the $z$ value of the sample [S1, unofficial].
2.  **Select Predecessor:** Use a Ray Alignment unit to drive two multiplexers (MUX) that select the correct predecessor value from the Ray Slice FIFO, Ray Beam FIFO, or Ray Shift Register [S1, unofficial].
3.  **Composite:** Combine the current sample's color and opacity with the selected predecessor value using the chosen blending mode [S1, unofficial].
4.  **Buffer:** Store the resulting partially accumulated value back into the appropriate buffer for the next sample in the stream [S1, unofficial].
5.  **Output:** When a ray passes through the back of the volume (maximum $z$) or a side face, output the final accumulated pixel value [S1, unofficial].
6.  **Write:** Write base plane pixel values to Pixel Memory [S1, unofficial].

**Formulas:**
The exact mathematical update equations for Front-to-back blending are not provided in the sources due to extraction artifacts [S1, unofficial]. The sources define three supported blending modes [S1, unofficial]. Front-to-back blending updates accumulated color and opacity [S1, unofficial]. Minimum Intensity blending sets $C_{acc} = C_{sample}$ and $minValue = sampleValue$ if $sampleValue < minValue$ [S1, unofficial]. Maximum Intensity blending sets $C_{acc} = C_{sample}$ and $maxValue = sampleValue$ if $sampleValue > maxValue$ [S1, unofficial].

**Pseudocode:**
```python
def ray_compositing_accumulation(samples, volume_depth, view_direction):
    """
    Simulates hardware Ray Compositing and Accumulation.
    samples: list of (x, y, z, C_sample, alpha_sample)
    volume_depth: integer, maximum z index + 1
    view_direction: tuple (dx, dy, dz) indicating traversal direction
    """
    # Initialize hardware buffers
    ray_slice_fifo = {}  # key: (x, y), value: (C_acc, alpha_acc)
    ray_beam_fifo = {}   # key: (x, y), value: (C_acc, alpha_acc)
    ray_shift_register = {} # key: (x, y), value: (C_acc, alpha_acc)
    pixel_memory = {}    # key: (x, y), value: (C_acc, alpha_acc)

    def quantize_12bit(value):
        """Clamp and quantize to 12-bit fixed point range [0, 4095] for hardware simulation."""
        return max(0, min(4095, int(value * 4095)))

    def front_to_back_blend(c_acc, alpha_acc, c_sample, alpha_sample):
        """Standard front-to-back alpha compositing."""
        alpha_new = alpha_acc + (1.0 - alpha_acc) * alpha_sample
        c_new = c_acc + (1.0 - alpha_acc) * c_sample
        return c_new, alpha_new

    for x, y, z, c_sample, alpha_sample in samples:
        # 1. Determine predecessor value from previous slice based on view direction and z
        # Ray Alignment unit drives MUXes to select from FIFOs/Registers
        if (x, y) in ray_slice_fifo:
            c_acc, alpha_acc = ray_slice_fifo[(x, y)]
        else:
            c_acc, alpha_acc = 0.0, 0.0

        # 2. Composite current sample with predecessor
        c_new, alpha_new = front_to_back_blend(c_acc, alpha_acc, c_sample, alpha_sample)

        # 3. Store result in buffers for subsequent samples
        ray_slice_fifo[(x, y)] = (c_new, alpha_new)
        ray_beam_fifo[(x, y)] = (c_new, alpha_new)
        ray_shift_register[(x, y)] = (c_new, alpha_new)

        # 4. Output when ray passes through back of volume (max z) or side face
        if z == volume_depth - 1:
            pixel_memory[(x, y)] = (c_new, alpha_new)

    return pixel_memory
```

## Subtopics

### Scatter-Add Accumulation
Scatter-Add Accumulation accumulates weighted values along rays using scatter-add operations, supporting both feature accumulation and weight-only accumulation [S2, unofficial]. It is used when values are provided to compute weighted features ($weighted = weights[:, None] * values$) or when accumulating weights only ($output = output + weights[:, None]$) [S2, unofficial]. This method initializes an output buffer of shape $[n\_rays, C]$ and performs scatter-add using ray indices ($output = output.at[ray\_indices].add(weighted)$) [S2, unofficial]. It is suitable for implementations where ray indices are known and random access to the output buffer is efficient [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples, as each sample is processed once [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of rays and the depth of the FIFOs/Registers, which depend on the volume size and view angle [S1, unofficial].
*   **Strengths:** Handles non-ray-order sample presentation efficiently in hardware; supports multiple blending modes [S1, unofficial].
*   **Limitations:** Requires significant hardware resources for FIFOs and alignment logic; precision loss can occur if bit depth is insufficient for large volumes [S1, unofficial].
*   **When to use:** Real-time ray casting on hardware architectures like VolumePro [S1, unofficial].

## Background
Ray Compositing and Accumulation was developed as part of the VolumePro real-time ray-casting system [S1, unofficial]. It was designed to handle the specific data flow of slice-by-slice, beam-by-beam rendering on dedicated hardware [S1, unofficial]. The method addresses the challenge of maintaining correct compositing order when samples are not generated in strict ray order [S1, unofficial].
