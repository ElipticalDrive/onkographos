# Separable Convolution

Also called: Linearly separable convolution, Two-pass convolution

## Overview
Separable convolution is a method to accelerate hologram computation by exploiting the linear separability of the lens phase function $f_z$ into independent horizontal and vertical components [S1]. It solves the performance bottleneck of point-wise integration in direct volume ray casting for holographic displays by reducing the computational complexity of the spatial convolution operation [S1]. It is distinguished from FFT-based convolution by its reliance on spatial separability rather than frequency-domain transformation, making it faster for smaller sub-hologram sizes but inapplicable when the phase function is not separable [S1].

## How it works
**Inputs and Outputs:**
*   Input: Target image data $A$ (containing the square root of image intensities) and the lens phase function $f_z$ [S1].
*   Output: Computed hologram $H$ [S1].

**Data Structures:**
*   $A$: A 2D array of complex or real values representing the source image intensities [S1].
*   $f_{z_x}$: A 1D vector representing the horizontal component of the lens phase function [S1].
*   $f_{z_y}$: A 1D vector representing the vertical component of the lens phase function [S1].
*   $H$: A 2D array of the same dimensions as $A$, storing the resulting hologram [S1].

**Prerequisites:**
The lens phase function $f_z$ must be linearly separable into vectors $f_{z_x}$ and $f_{z_y}$ [S1]. This condition holds for lens phase functions of any focal power and certain aberrations, such as horizontal astigmatism or vertical astigmatism [S1]. If $f_z$ is not linearly separable, this method cannot be applied [S1].

**Formulas:**
The hologram $H$ is computed by convolving the image $A$ with the separable components sequentially [S1]:

$$ H = (A * f_{z_x}) * f_{z_y} $$

where $*$ denotes the convolution operation [S1].

**Parameters:**
*   Sub-hologram width: The runtime scales linearly with the sub-hologram size [S1].
*   Typical Performance: Calculation of a hologram with 2 million object points takes just a few milliseconds on a GPU [S1].

**Pitfalls and Edge Cases:**
*   **Non-separable Phase Functions:** If the lens phase function contains aberrations or focal properties that cannot be decomposed into independent horizontal and vertical vectors, this method fails [S1].
*   **Spatial Variance:** This method assumes the lens phase function is spatially invariant (constant over the image) to allow standard convolution [S1]. It does not support per-pixel focal control or spatially variant aberration correction [S1].
*   **Sub-hologram Size Scaling:** Unlike FFT-based convolution, the runtime of separable convolution scales linearly with the sub-hologram width [S1]. It is faster than FFT-based convolution for smaller sub-hologram sizes, but the crossover point depends on the specific hardware and implementation [S1].

**Pseudocode:**
The implementation operates in two passes, one for each linearly separable axis [S1].

```python
def separable_convolution(A, f_zx, f_zy):
    """
    Computes hologram H using separable convolution.
    
    Args:
        A: 2D array of image intensities (square root).
        f_zx: 1D vector for horizontal phase component.
        f_zy: 1D vector for vertical phase component.
        
    Returns:
        H: 2D array representing the hologram.
    """
    # Pass 1: Convolve image A with horizontal kernel f_zx
    # Result is stored in intermediate buffer Temp
    Temp = convolve_2d_horizontal(A, f_zx)
    
    # Pass 2: Convolve intermediate result Temp with vertical kernel f_zy
    # Result is stored in H
    H = convolve_2d_vertical(Temp, f_zy)
    
    return H

def convolve_2d_horizontal(Image, Kernel):
    """
    Convolves each row of the image with the 1D horizontal kernel.
    """
    Height, Width = Image.shape
    Kernel_Length = len(Kernel)
    Output = zeros_like(Image)
    
    for y in range(Height):
        for x in range(Width):
            Sum = 0
            for k in range(Kernel_Length):
                # Handle boundary conditions (e.g., zero-padding or replication)
                # Not specified in sources; assume standard convolution boundary handling [G]
                x_idx = x - k + (Kernel_Length - 1) // 2
                if 0 <= x_idx < Width:
                    Sum += Image[y, x_idx] * Kernel[k]
            Output[y, x] = Sum
    return Output

def convolve_2d_vertical(Image, Kernel):
    """
    Convolves each column of the image with the 1D vertical kernel.
    """
    Height, Width = Image.shape
    Kernel_Length = len(Kernel)
    Output = zeros_like(Image)
    
    for y in range(Height):
        for x in range(Width):
            Sum = 0
            for k in range(Kernel_Length):
                # Handle boundary conditions
                y_idx = y - k + (Kernel_Length - 1) // 2
                if 0 <= y_idx < Height:
                    Sum += Image[y_idx, x] * Kernel[k]
            Output[y, x] = Sum
    return Output
```

## Subtopics

### FFT-based Convolution
A method to speed up hologram calculation by removing spatial variance of the lens phase function $f_z$ so it is the same for all object points, allowing substitution of point-wise integration with standard spatially invariant convolution [S1]. It computes $H = A * f_z$ using the Fast Fourier Transform: $H = FFT^{-1}(FFT(A) \times FFT(f_z))$, where $\times$ indicates point-wise multiplication [S1]. It requires a spatially invariant lens phase function, implying focus and aberration correction is constant over the image [S1]. A key pitfall is that it does not support per-pixel focal control because the lens phase function is not spatially variant [S1]. It runs in just a few milliseconds for 2 million object points on a GPU [S1]. Unlike separable convolution, FFT convolution does not depend on sub-hologram size, whereas separable convolution scales linearly with it [S1].

## Operating characteristics
*   **Time Complexity:** Scales linearly with the sub-hologram size [S1].
*   **Memory Complexity:** Requires storage for the image $A$, the hologram $H$, and intermediate buffers for the two-pass convolution [S1].
*   **Measured Performance:** For a 1920x1080 hologram with 2 million object points, computation takes just a few milliseconds on a GPU [S1].
*   **Scaling:** Runtime increases linearly with sub-hologram width [S1].
*   **Strengths:** Significantly faster than point-wise integration (orders of magnitude) [S1]. Faster than FFT-based convolution for smaller sub-hologram sizes [S1].
*   **Limitations:** Only applicable when the lens phase function is linearly separable [S1]. Does not support per-pixel focal control or spatially variant aberration correction [S1].
*   **When to use:** When the lens phase function is linearly separable and sub-hologram sizes are small to moderate [S1].
*   **When not to use:** When the lens phase function is not linearly separable or when per-pixel focal control is required [S1].

## Background
Separable convolution was introduced in the context of holographic near-eye displays for virtual and augmented reality by Maimone et al. in 2017 [S1]. The method leverages a common simplification in image processing, applying it to hologram computation for the first time in this context [S1]. It is used in real-time holographic displays to generate holograms directly from rendered polygonal models, enabling frame rates exceeding the display refresh rate [S1].
