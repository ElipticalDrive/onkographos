# Pre-Integration Lookup

Also called: 3D Pre-integration Table, Pre-integrated Transfer Functions

## Overview
Pre-integration lookup is a technique in direct volume ray casting that pre-computes the optical properties (color and opacity) of volume slabs to accelerate rendering and reduce aliasing artifacts caused by under-sampling [S1, unofficial][S2]. It solves the problem of expensive per-sample integration by assuming linear evolution of scalar data within a slab, allowing the renderer to fetch pre-calculated optical results from a 3D texture based on entry and exit densities [S1, unofficial]. It sets itself apart from standard compositing [Compositing](2436-compositing.md) by moving the integration burden from the rendering pass to a pre-computation phase, and from binary swap compositing [Binary Swap Compositing](3264-binary-swap-compositing.md) by handling continuous density transitions rather than discrete object boundaries.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset, a transfer function (TF) mapping scalar values to color and opacity, and a viewing direction.
*   **Output:** A 3D pre-integration lookup table (LUT) storing color and opacity for slab segments, and the final composited image.

**Data Structures:**
*   **3D Pre-integration Table:** A 3D texture (typically $256 \times 256 \times 256$ for 8-bit scalar data) where each voxel stores the accumulated color and opacity for a slab defined by front density ($s_f$), middle density ($s_m$), and back density ($s_b$) [S2].
*   **Volume Data:** Stored as a 3D texture in GPU memory [S4].
*   **Transfer Function:** Represented as a 1D lookup table (e.g., 256 entries) [S4].

**Steps:**
1.  **Pre-computation (Offline or Startup):**
    1.  Define the scalar domain (e.g., 8-bit, 256 values) [S2, S4].
    2.  For every possible triplet of scalar values $(s_f, s_m, s_b)$ within the domain:
        a.  Assume linear interpolation of scalar values between samples [S1, unofficial].
        b.  Compute the integral of the transfer function (color and opacity) over the slab defined by these densities [S1, unofficial].
        c.  Store the resulting color $(C)$ and opacity $(\alpha)$ in the 3D pre-integration table at index $(s_f, s_m, s_b)$ [S2].
    *   *Note:* Full pre-integration accounts for color attenuation inside the slab. Simplified pre-integration may neglect color attenuation for speed [S4].

2.  **Rendering (Per Frame):**
    1.  For each pixel, cast a ray through the volume.
    2.  Divide the ray into slabs of thickness $2d$, defined by three successive scalar samples $(s_f, s_m, s_b)$ [S2].
    3.  Retrieve the scalar values $s_f, s_m, s_b$ from the volume texture [S2].
    4.  Perform a 3D texture lookup in the pre-integration table using $(s_f, s_m, s_b)$ to obtain the slab's pre-computed color $C_{slab}$ and opacity $\alpha_{slab}$ [S2].
    5.  Composite the slabs using front-to-back alpha blending:
        $$ C_{out} = C_{in} + C_{slab} \cdot \alpha_{slab} \cdot (1 - \alpha_{in}) $$
        $$ \alpha_{out} = \alpha_{in} + \alpha_{slab} \cdot (1 - \alpha_{in}) $$
        where $C_{in}, \alpha_{in}$ are the accumulated color and opacity from previous slabs [S2].
    6.  Repeat for all slabs along the ray to obtain the final pixel color [S2].

**Parameters:**
*   **Scalar Precision:** Typically 8-bit (256 levels) [S2, S4].
*   **Slab Thickness:** Defined by the sampling distance; often related to the voxel size or a multiple thereof [S2].
*   **Table Size:** $256^3$ for 8-bit data [S2].

**Edge Cases and Pitfalls:**
*   **Precision:** Limited by the scalar precision of the pre-integration table. Higher precision increases table size exponentially [S2].
*   **Linear Assumption:** The method assumes linear evolution of data within the slab. Non-linear variations may introduce errors [S1, unofficial].
*   **Memory:** The $256^3$ 3D texture requires significant GPU memory (e.g., $256^3 \times 4$ bytes $\approx 64$ MB for RGBA8, more for higher precision) [S2, S4].

## Subtopics

### [Pre-Integrated Diffuse Shading with Non-Linear Gradient Interpolation](4932-pre-integrated-diffuse-shading-with-non-linear-gradient-inte.md)
This method computes the diffuse component of Blinn-Phong shading in direct volume ray casting by approximating the integral of light interaction over a sampling step using non-linear gradient interpolation [4932-pre-integrated-diffuse-shading-with-non-linear-gradient-inte.md]. It decomposes the shading integral into four 2D look-up tables (LUTs) indexed by front and back scalar values, weighted by coefficients derived from light direction and gradient angles [4932-pre-integrated-diffuse-shading-with-non-linear-gradient-inte.md]. It sets itself apart from linear gradient interpolation by reducing shading errors caused by large angles between consecutive sample gradients, while avoiding the prohibitive memory cost of full 4D normal-based pre-integration [4932-pre-integrated-diffuse-shading-with-non-linear-gradient-inte.md]. Choose this when high-quality shading is required and memory is constrained compared to full normal-based methods.

### [Non-Linear Gradient Interpolation for Pre-Integrated Volume Rendering](4933-non-linear-gradient-interpolation-for-pre-integrated-volume-.md)
Non-linear gradient interpolation is a technique for pre-integrated direct volume rendering that reduces shading errors by interpolating gradients between front and back samples along a quadratic curve instead of a linear segment, allowing accurate computation of 2D pre-integration look-up tables. It sets itself apart from linear gradient interpolation by approximating the non-linear path of a normalized gradient vector as a quadratic polynomial, thereby avoiding the energy loss and shading errors inherent in linear interpolation which assumes the normalization term $\eta(t)=1$. Choose this when shading accuracy is critical and the linear assumption introduces visible artifacts.

### Pre-integrated Volume Rendering with Shading
A method for efficiently reconstructing 3D medical images that combines pre-integrated volume rendering with the Shear-Warp algorithm to eliminate aliasing artifacts from under-sampling and improve reconstruction quality via Phong lighting shading [S3, unofficial]. It implements classification coding for volume data using the correlation of the opacity transfer function and a min-max Octree data structure, establishing a run-length encoded (RLE) data structure for fast reconstruction when the opacity transfer function and view angle change [S3, unofficial]. It incorporates pre-integrated volume rendering with Phong lighting shading calculation to eliminate aliasing artifacts [S3, unofficial]. Choose this for real-time 3D medical image reconstruction where aliasing and view-angle changes are concerns.

### Simplified Pre-integration
A faster approximation of pre-integration that neglects color attenuation inside volume slabs, used in the first level of interaction where multiple transfer functions are modified [S4]. It is applied in the first level of the interface to handle actions that modify several TFs simultaneously, while full pre-integration is applied in the second level where a single TF is under modification to maintain quality [S4]. Choose this when interactivity is prioritized over physical accuracy, particularly during multi-TF adjustments.

## Operating characteristics
*   **Time Complexity:** Pre-computation is $O(N^3)$ where $N$ is the scalar precision (e.g., $256^3$) [S2]. Rendering is $O(1)$ per slab for the lookup, plus compositing cost [S2].
*   **Memory Complexity:** $O(N^3)$ for the 3D pre-integration table [S2]. For 8-bit data, this is $256^3$ entries [S2].
*   **Measured Performance:** Implemented on GPU for real-time performance [S1, unofficial][S2]. The Shear-Warp variant improves reconstruction speed for medical images [S3, unofficial].
*   **Strengths:** Reduces aliasing, accelerates rendering by moving integration to pre-computation, supports interactive transfer function design [S1, unofficial][S2, S4].
*   **Limitations:** High memory usage for high-precision tables, assumes linear scalar evolution within slabs [S1, unofficial][S2].
*   **When to Use:** Real-time volume rendering, interactive transfer function design, medical imaging [S1, unofficial][S2][S3, unofficial][S4].
*   **When Not to Use:** Scenes with highly non-linear scalar variations where the linear assumption fails, or when memory is extremely constrained [S1, unofficial].

## Background
Pre-integration lookup was introduced to address aliasing and performance issues in direct volume ray casting [S1, unofficial][S2]. It was implemented on GPU in early 2000s [EKE01, RE02 cited in S1]. Variants have been developed for medical imaging, combining with Shear-Warp algorithms [S3, unofficial], and for interactive transfer function design [S4].
