# Tilt-Shift Post-Processing

Also called: Miniature Effect, Selective Focus Blur

## Overview
Tilt-Shift Post-Processing is a screen-space effect that simulates the shallow depth-of-field of a miniature model by keeping a horizontal band of the frame sharp while applying increasing Gaussian blur to areas above and below it, accompanied by increased color saturation [S1, unofficial]. It distinguishes itself from general blur effects by its spatially varying strength profile (sharp band with falloff) and its specific aesthetic goal of mimicking macro photography of large-scale scenes [S1, unofficial]. It is typically applied after the main scene render but before UI elements to ensure menus and text remain crisp [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** A single-sample render texture containing the resolved scene color and alpha.
*   **Output:** A final color texture with the tilt-shift blur and saturation applied.

### Data Structures and Layout
The fragment shader operates on a texture with the following uniform inputs and varying inputs [S1, unofficial]:

**Varying Input:**
*   `fragTexCoord`: `vec2`, the normalized texture coordinate (0.0 to 1.0) of the current fragment.

**Uniform Inputs:**
*   `texture0`: `sampler2D`, the input scene texture.
*   `blurStep`: `vec2`, the sampling direction vector. For the horizontal pass, this is `(1.0/width, 0.0)` [S1, unofficial]. For the vertical pass, this is `(0.0, 1.0/height)` [S1, unofficial].
*   `focus`: `float`, the center Y-coordinate of the sharp band, normalized to [0.0, 1.0] (0.0 is top, 1.0 is bottom) [S1, unofficial].
*   `halfBand`: `float`, half the height of the sharp band, normalized to [0.0, 1.0] [S1, unofficial].
*   `maxRadius`: `float`, the maximum blur radius in pixels when strength is 1.0 [S1, unofficial].
*   `saturation`: `float`, the saturation multiplier. 1.0 leaves colors unchanged [S1, unofficial].
*   `RAMP`: `float`, constant value `0.35`. Defines the distance past the band edge where blur reaches full strength [S1, unofficial].
*   `TAPS`: `int`, constant value `8`. Number of taps on each side of the center (17 total taps including center) [S1, unofficial].
*   `SIGMA`: `float`, constant value `3.2`. Standard deviation for the Gaussian weight calculation [S1, unofficial].
*   `RadiusPerStrength`: `float`, constant value `0.012f`. Defines the blur radius scaling factor relative to frame height [S1, unofficial].

### Algorithm Steps
1.  **Framebuffer Resolution:** Resolve the multisampled window framebuffer into a single-sample render texture using a blit operation [S1, unofficial]. This preserves antialiasing in the sharp band, as render textures are typically not multisampled [S1, unofficial].
2.  **Horizontal Blur Pass:** Draw the scene texture to an intermediate horizontal render target [S1, unofficial]. The shader samples along the X-axis using `blurStep = (1.0/width, 0.0)` [S1, unofficial].
3.  **Vertical Blur Pass:** Draw the horizontal render target to the final output [S1, unofficial]. The shader samples along the Y-axis using `blurStep = (0.0, 1.0/height)` [S1, unofficial]. During this pass, saturation is applied [S1, unofficial].
4.  **Alpha Correction:** Force the final alpha channel to `1.0` to prevent the underlying sharp frame from showing through if particles or clouds left the framebuffer alpha below 1.0 [S1, unofficial].

### Formulas and Parameters
**Blur Strength Calculation:**
The blur strength is determined by the distance of the fragment from the focus band [S1, unofficial].
$$ \text{strength} = \text{smoothstep}(\text{halfBand}, \text{halfBand} + \text{RAMP}, |\text{fromTop} - \text{focus}|) $$
Where:
*   `fromTop` is the Y-coordinate of the fragment (normalized 0.0 to 1.0) [S1, unofficial].
*   `focus` is the center of the sharp band [S1, unofficial].
*   `halfBand` is half the height of the sharp band [S1, unofficial].
*   `RAMP` is `0.35` [S1, unofficial].
*   `smoothstep(edge0, edge1, x)` performs smooth Hermite interpolation between 0 and 1 [G].

**Sampling Spacing:**
The distance between taps is scaled by the calculated strength and the maximum radius [S1, unofficial].
$$ \text{spacing} = \text{blurStep} \times \left( \frac{\text{strength} \times \text{maxRadius}}{\text{TAPS}} \right) $$

**Gaussian Weight:**
The weight for each tap pair is calculated using a Gaussian function [S1, unofficial].
$$ \text{weight} = \exp\left( -0.5 \times \frac{i^2}{\text{SIGMA}^2} \right) $$
Where `i` is the tap index (1 to `TAPS`) and `SIGMA` is `3.2` [S1, unofficial].

**Color Saturation:**
Saturation is applied by mixing the luminance of the color with the original color [S1, unofficial].
$$ \text{luma} = \text{dot}(\text{color}, \text{vec3}(0.299, 0.587, 0.114)) $$
$$ \text{finalColor} = \text{clamp}(\text{mix}(\text{vec3}(\text{luma}), \text{color}, \text{saturation}), 0.0, 1.0) $$

### Pseudocode
```python
import math

def smoothstep(edge0, edge1, x):
    t = max(0.0, min(1.0, (x - edge0) / (edge1 - edge0)))
    return t * t * (3.0 - 2.0 * t)

def clamp(x, lo, hi):
    return max(lo, min(hi, x))

# Constants
RAMP = 0.35
TAPS = 8
SIGMA = 3.2

# Inputs (example values)
fragTexCoord = (0.5, 0.5)
blurStep = (0.0, 1.0 / height)
focus = 0.5
halfBand = 0.1
maxRadius = 10.0
saturation = 1.5

# 1. Calculate Blur Strength
fromTop = fragTexCoord[1]
distance_from_focus = abs(fromTop - focus)
strength = smoothstep(halfBand, halfBand + RAMP, distance_from_focus)

# 2. Calculate Spacing
spacing = (blurStep[0] * (strength * maxRadius / TAPS),
           blurStep[1] * (strength * maxRadius / TAPS))

# 3. Initialize Accumulators
sum_rgb = [0.0, 0.0, 0.0]
weights = 0.0

# 4. Sample Center
center_color = texture(texture0, fragTexCoord).rgb
sum_rgb[0] += center_color[0]
sum_rgb[1] += center_color[1]
sum_rgb[2] += center_color[2]
weights += 1.0

# 5. Sample Taps
for i in range(1, TAPS + 1):
    weight = math.exp(-0.5 * (i * i) / (SIGMA * SIGMA))
    pos_coord = (fragTexCoord[0] + spacing[0] * i, fragTexCoord[1] + spacing[1] * i)
    neg_coord = (fragTexCoord[0] - spacing[0] * i, fragTexCoord[1] - spacing[1] * i)
    pos_color = texture(texture0, pos_coord).rgb
    neg_color = texture(texture0, neg_coord).rgb
    sum_rgb[0] += (pos_color[0] + neg_color[0]) * weight
    sum_rgb[1] += (pos_color[1] + neg_color[1]) * weight
    sum_rgb[2] += (pos_color[2] + neg_color[2]) * weight
    weights += 2.0 * weight

# 6. Normalize
final_color = (sum_rgb[0] / weights, sum_rgb[1] / weights, sum_rgb[2] / weights)

# 7. Apply Saturation
luma = 0.299 * final_color[0] + 0.587 * final_color[1] + 0.114 * final_color[2]
final_color = (
    clamp(luma + saturation * (final_color[0] - luma), 0.0, 1.0),
    clamp(luma + saturation * (final_color[1] - luma), 0.0, 1.0),
    clamp(luma + saturation * (final_color[2] - luma), 0.0, 1.0)
)

# 8. Force Alpha
final_alpha = 1.0

# Output
out finalColor = (final_color[0], final_color[1], final_color[2], final_alpha)
```

### Edge Cases and Pitfalls
*   **Multisampling:** The source framebuffer is multisampled, but render textures are not [S1, unofficial]. Drawing directly to a texture would lose antialiasing in the sharp band [S1, unofficial]. A blit operation must be used to resolve samples before post-processing [S1, unofficial].
*   **Alpha Transparency:** Particles and clouds may leave the framebuffer's alpha channel below 1.0 [S1, unofficial]. The shader must force the final alpha to 1.0 to prevent the sharp frame underneath from showing through the blurred areas [S1, unofficial].
*   **Band Boundaries:** If `focus` or `halfBand` are set such that the sharp band extends beyond the frame boundaries, the `smoothstep` function handles the clamping naturally, but care should be taken to ensure `halfBand + RAMP` does not exceed valid coordinate ranges unnecessarily, though `smoothstep` handles out-of-bounds inputs gracefully [G].

### Strengths and Limitations
*   **Strengths:** Simple to implement; effective at creating a miniature illusion; separable blur allows for efficient implementation [G].
*   **Limitations:** Screen-space only; does not account for true depth-based defocus (objects at different depths within the sharp band are not blurred differently); artifacts may occur at the edges of the sharp band if the transition is too abrupt (mitigated by `RAMP`) [G].

### When to Use
*   Use when a stylistic "miniature" look is desired [S1, unofficial].
*   Use when UI elements need to remain sharp while the background is blurred [S1, unofficial].

### When Not to Use
*   Do not use when physically accurate depth-of-field is required [G].
*   Do not use if the scene contains significant transparency issues that cannot be resolved by forcing alpha to 1.0 [S1, unofficial].

## Background

### Origin and History
The Tilt-Shift Post-Processing effect is implemented in the VoxelTerraformer engine [S1, unofficial]. The effect mimics the optical phenomenon of tilt-shift lenses, which allow the plane of focus to be tilted relative to the image plane, creating a shallow depth of field that makes full-scale scenes look like miniature models [G].

### Usage
The effect is applied after the main scene render but before UI elements are drawn, ensuring that menus and text remain sharp [S1, unofficial]. It is commonly used in voxel-based games and simulations to enhance the visual appeal of large-scale terrain [S1, unofficial].
