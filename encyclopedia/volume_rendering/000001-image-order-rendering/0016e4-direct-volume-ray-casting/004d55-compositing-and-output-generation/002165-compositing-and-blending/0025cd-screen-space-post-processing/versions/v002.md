# Screen-space Post-processing

Also called: Composite Shader, Compositing/Post-Processing Pipeline, Screen Post-Processing

## Overview
Screen-space post-processing is a full-screen pipeline that applies aspect-ratio preserving UV covering, luminance-based bright passes, color grading, underwater RGB channel splitting, cross-shaped bloom, multi-tap box blurring, and 1-LSB dithering to a scene texture [S1, unofficial]. It differs from sibling methods like [Compositing](2436-compositing.md) by operating on the final rendered image rather than accumulating volume samples along rays, and from [HDR Post-Processing Pipeline](4633-hdr-post-processing-pipeline.md) by applying specific spatial effects (vignette, underwater refraction) rather than global HDR tone mapping [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: A scene texture (RGB), screen dimensions (`screen_size`), UV coordinates (`uv`), and uniform parameters (`menu_blur`, `is_underwater`, `time`).
*   Output: A final processed color (`color`).

**Data Structures:**
*   **Uniforms:** A struct containing `view_proj`, `inv_view_proj`, `camera_pos`, `time`, `sun_position`, `is_underwater`, `screen_size` (vec2), `water_level`, `moon_position`, `moon_intensity`, `wind_dir_x`, `wind_dir_z`, `wind_speed`, `rain_factor`, `sky_visibility`, `menu_blur`, and `_pad_uniforms` [S1, unofficial].
*   **Vertex Attributes:** A triangle strip defined by positions `array<vec2<f32>, 3> = {(-1.0, -1.0), (3.0, -1.0), (-1.0, 3.0)}` and UVs `array<vec2<f32>, 3> = {(0.0, 1.0), (2.0, 1.0), (0.0, -1.0)}` [S1, unofficial].

**Steps:**
1.  **UV Covering:** Compute `texture_aspect = texture_size.x / max(texture_size.y, 1.0)` and `screen_aspect = screen_size.x / max(screen_size.y, 1.0)`. If `screen_aspect > texture_aspect`, adjust `covered.y = 0.5 + (uv.y - 0.5) * (texture_aspect / screen_aspect)`. Else, adjust `covered.x = 0.5 + (uv.x - 0.5) * (screen_aspect / texture_aspect)` [S1, unofficial].
2.  **Luminance Calculation:** Compute `luma = dot(color, vec3(0.2126, 0.7152, 0.0722))` [S1, unofficial].
3.  **Bright Pass:** Compute `weight = smoothstep(0.68, 0.96, luminance(color))`. Output `bright_pass_color = color * weight` [S1, unofficial].
4.  **Vignette:** Compute `centered = uv * 2.0 - 1.0`. Adjust `centered.x *= screen_size.x / max(screen_size.y, 1.0)`. Compute `vignette = 1.0 - smoothstep(0.42, 1.82, dot(centered, centered)) * mix(0.045, 0.025, blur)`. Output `color = clamp(color * vignette, vec3(0.0), vec3(1.0))` [S1, unofficial].
5.  **Underwater Refraction:** If `is_underwater > 0.5` and `blur < 0.5`, compute `radial = (sample_uv - vec2(0.5)) * 1.6` and `shift = radial * texel * (1.2 + 0.25 * sin(time * 0.8))`. Sample `color.r = sample_scene(sample_uv + shift).r` and `color.b = sample_scene(sample_uv - shift).b`. Mix result: `color = mix(color, color * vec3(0.83, 0.96, 1.08), 0.28)` [S1, unofficial].
6.  **Cross-shaped Bloom:** Compute `bloom_radius = texel * 3.25`. Initialize `bloom = bright_pass(color) * 0.28`. Add 4 neighbors at `±bloom_radius.x/y` with weight `0.18` each. Update `color += bloom * mix(0.105, 0.025, blur)` [S1, unofficial].
7.  **17-tap Box Blur:** If `blur > 0.001`, initialize `blurred = color * 0.08`. Add neighbors at `texel * (±4,0)` and `(0,±4)` with weight `0.08`; `texel * (±5.5, ±5.5)` with weight `0.07`; `texel * (±10,0)` and `(0,±10)` with weight `0.05`; `texel * (±14, ±14)` with weight `0.03`. Update `color = mix(color, blurred * 0.82, blur)` [S1, unofficial].
8.  **Dithering:** Compute `pixel = floor(uv * max(screen_size, vec2(1.0)))`. Compute `hash = fract(sin(dot(pixel, vec2(12.9898, 78.233))) * 43758.5453)`. Compute `dither = (hash - 0.5) / 255.0`. Output `color = clamp(color + vec3(dither), vec3(0.0), vec3(1.0))` [S1, unofficial].

**Pseudocode:**
```python
def screen_space_post_processing(uv, color, screen_size, texture_size, menu_blur, is_underwater, time, texel):
    # 1. UV Covering
    texture_aspect = texture_size.x / max(texture_size.y, 1.0)
    screen_aspect = screen_size.x / max(screen_size.y, 1.0)
    if screen_aspect > texture_aspect:
        covered_y = 0.5 + (uv.y - 0.5) * (texture_aspect / screen_aspect)
        # Note: Source implies only y is adjusted in this branch, x remains or is handled by other logic not fully specified for 'covered' variable usage in subsequent steps. 
        # Assuming standard aspect-ratio preservation where the other coordinate is centered or scaled similarly if not specified.
        # However, source only defines covered.y. We proceed with original uv for other calculations unless 'covered' is explicitly used.
        # The source uses 'uv' in subsequent steps, not 'covered'. This step may define a crop region not directly used in the pixel shader math provided, 
        # or 'uv' is already the covered UV. We use 'uv' as given.
        pass
    else:
        covered_x = 0.5 + (uv.x - 0.5) * (screen_aspect / texture_aspect)
        pass

    # 2. Luminance
    luma = dot(color, vec3(0.2126, 0.7152, 0.0722))

    # 3. Bright Pass
    weight = smoothstep(0.68, 0.96, luma)
    bright_pass_color = color * weight

    # 4. Vignette
    centered = uv * 2.0 - 1.0
    centered.x *= screen_size.x / max(screen_size.y, 1.0)
    vignette_factor = 1.0 - smoothstep(0.42, 1.82, dot(centered, centered)) * mix(0.045, 0.025, menu_blur)
    color = clamp(color * vignette_factor, vec3(0.0), vec3(1.0))

    # 5. Underwater Refraction
    if is_underwater > 0.5 and menu_blur < 0.5:
        radial = (uv - vec2(0.5)) * 1.6
        shift = radial * texel * (1.2 + 0.25 * sin(time * 0.8))
        # Assuming sample_scene is a function that samples the original scene texture at the given UV
        r_val = sample_scene(uv + shift).r
        b_val = sample_scene(uv - shift).b
        color.r = r_val
        color.b = b_val
        color = mix(color, color * vec3(0.83, 0.96, 1.08), 0.28)

    # 6. Cross-shaped Bloom
    bloom_radius = texel * 3.25
    bloom = bright_pass_color * 0.28
    # Add 4 neighbors at ±bloom_radius.x/y
    bloom += sample_scene(uv + vec2(bloom_radius.x, 0.0)) * 0.18
    bloom += sample_scene(uv + vec2(-bloom_radius.x, 0.0)) * 0.18
    bloom += sample_scene(uv + vec2(0.0, bloom_radius.y)) * 0.18
    bloom += sample_scene(uv + vec2(0.0, -bloom_radius.y)) * 0.18
    color += bloom * mix(0.105, 0.025, menu_blur)

    # 7. 17-tap Box Blur
    if menu_blur > 0.001:
        blurred = color * 0.08
        # Neighbors at texel * (±4,0), (0,±4) weight 0.08
        blurred += sample_scene(uv + vec2(4.0, 0.0) * texel) * 0.08
        blurred += sample_scene(uv + vec2(-4.0, 0.0) * texel) * 0.08
        blurred += sample_scene(uv + vec2(0.0, 4.0) * texel) * 0.08
        blurred += sample_scene(uv + vec2(0.0, -4.0) * texel) * 0.08
        # Neighbors at texel * (±5.5, ±5.5) weight 0.07
        blurred += sample_scene(uv + vec2(5.5, 5.5) * texel) * 0.07
        blurred += sample_scene(uv + vec2(5.5, -5.5) * texel) * 0.07
        blurred += sample_scene(uv + vec2(-5.5, 5.5) * texel) * 0.07
        blurred += sample_scene(uv + vec2(-5.5, -5.5) * texel) * 0.07
        # Neighbors at texel * (±10,0), (0,±10) weight 0.05
        blurred += sample_scene(uv + vec2(10.0, 0.0) * texel) * 0.05
        blurred += sample_scene(uv + vec2(-10.0, 0.0) * texel) * 0.05
        blurred += sample_scene(uv + vec2(0.0, 10.0) * texel) * 0.05
        blurred += sample_scene(uv + vec2(0.0, -10.0) * texel) * 0.05
        # Neighbors at texel * (±14, ±14) weight 0.03
        blurred += sample_scene(uv + vec2(14.0, 14.0) * texel) * 0.03
        blurred += sample_scene(uv + vec2(14.0, -14.0) * texel) * 0.03
        blurred += sample_scene(uv + vec2(-14.0, 14.0) * texel) * 0.03
        blurred += sample_scene(uv + vec2(-14.0, -14.0) * texel) * 0.03
        
        color = mix(color, blurred * 0.82, menu_blur)

    # 8. Dithering
    pixel = floor(uv * max(screen_size, vec2(1.0)))
    hash_val = fract(sin(dot(pixel, vec2(12.9898, 78.233))) * 43758.5453)
    dither = (hash_val - 0.5) / 255.0
    color = clamp(color + vec3(dither), vec3(0.0), vec3(1.0))

    return color
```

**Parameters:**
*   `menu_blur`: Float, controls blur intensity and vignette softening. Clamped to `[0.0, 1.0]` [S1, unofficial].
*   `is_underwater`: Float, enables RGB channel splitting refraction when `> 0.5` and `blur < 0.5` [S1, unofficial].

**Edge Cases:**
*   Division by zero in aspect ratio calculation is guarded by `max(..., 1.0)` [S1, unofficial].
*   Underwater effect is conditional on both `is_underwater` and `blur` thresholds [S1, unofficial].

## Subtopics

### Bilateral Upsampling and Dual-Source Blending
A post-processing step to upscale and blend volumetric lighting results with the scene, using bilateral upsampling for resolution enhancement and dual-source blending for attenuation [S2, unofficial]. It differs from standard box blurs by preserving edges during upscaling, particularly helpful at 1/4 resolution [S2, unofficial]. It is chosen when high-performance volumetric lighting needs to be integrated into the scene without significant aliasing artifacts. It uses dual-source blending to attenuate the result based on medium density and depth [S2, unofficial].

### Frustum Raycasting and Blending
A post-processing step that casts rays from the camera through each pixel, intersects them with a cloud volume bounding box, and blends the resulting cloud color with the original scene color [S3, unofficial]. It differs from screen-space techniques by using world-space raycasting for volumetric clouds [S3, unofficial]. It is chosen for rendering volumetric clouds that require accurate depth and density integration. The method samples the original scene color, calculates ray-box intersection, and if intersected, marches density to get cloud color, returning `lerp(originalColour, cloudColour, cloudColour.a)` [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the number of taps in the blur/bloom passes. The 17-tap blur and cross-shaped bloom involve a constant number of texture samples per pixel.
*   **Memory Complexity:** Low, primarily requiring the input scene texture and output framebuffer. Uniforms are small.
*   **Performance:** The method is efficient for real-time rendering as it operates in screen space. The specific implementation in [S1, unofficial] is part of a larger engine (Minerust) using wgpu.
*   **Strengths:** Simple to implement, low memory overhead, effective for atmospheric effects like bloom and vignette.
*   **Limitations:** Screen-space techniques cannot reconstruct geometry behind the camera or outside the view frustum. The specific underwater effect is limited to RGB splitting and does not simulate complex refraction physics.
*   **When to use:** For final image enhancement, atmospheric effects, and integrating volumetric lighting (via upsampling) into the scene.
*   **When not to use:** When accurate volumetric geometry is required (use raycasting/compositing instead) or when effects need to extend beyond the current frame's visible pixels.

## Background
The method is described in the context of the Minerust project, a voxel-based game engine using wgpu [S1, unofficial]. The bilateral upsampling technique is associated with volumetric light scattering in Fallout 4 [S2, unofficial]. The frustum raycasting technique is associated with a volumetric cloud renderer implementation [S3, unofficial].
