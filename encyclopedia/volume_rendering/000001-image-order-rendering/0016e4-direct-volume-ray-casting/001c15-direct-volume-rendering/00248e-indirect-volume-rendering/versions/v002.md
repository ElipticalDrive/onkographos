# Indirect Volume Rendering

## Overview
Indirect Volume Rendering (IVR) is a technique where volume data is converted into an intermediate traditional computer graphics representation, usually an isosurface or iso-contour, which is then rendered using standard hardware [S1, S2, unofficial]. Unlike [Direct Volume Rendering](1184-direct-volume-rendering.md), which processes the volume without generating any intermediate representation, IVR extracts an explicit geometric representation in a preprocessing step [S2, unofficial].

## Shared principles
IVR operates by converting the volumetric dataset into an intermediate representation during a preprocessing step, which is then handled by the graphics engine [S2, unofficial]. The mathematical basis for the most common extraction approach, Marching Cubes, classifies each volume cell of eight neighboring voxels according to a specified iso value [S1, unofficial]. Each voxel has two states (inside or outside an iso surface), yielding $2^8 = 256$ possible configurations for how a surface can intersect the cube [S1, unofficial].

## Subtopics

### Space Domain Volume Rendering
This approach extracts surfaces directly from the spatial domain of the volume data [S2, unofficial]. It differs from frequency domain methods by operating on voxel coordinates rather than spectral coefficients. Not given in the sources. See [Marching Cubes](52-marching-cubes.md).

### Frequency Domain Volume Rendering
This approach transforms the volume data into the frequency domain (e.g., using Fourier Transform) before rendering [S2, unofficial]. It differs from space domain methods by operating on spectral coefficients rather than voxel coordinates. Not given in the sources. See [Frequency Domain Rendering](52-frequency-domain-rendering.md).
