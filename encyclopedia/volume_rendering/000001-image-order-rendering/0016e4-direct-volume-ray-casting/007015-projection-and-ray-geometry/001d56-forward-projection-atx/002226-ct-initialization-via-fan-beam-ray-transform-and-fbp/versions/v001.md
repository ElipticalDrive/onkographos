# CT Initialization via Fan Beam Ray Transform and FBP

Also called: MFG (Multiplicative First Guess), Multiplicative First Guess

## Overview
This method initializes the intensity distribution of a 3D volume from pre-processed projection images to reduce calculation time and accelerate the convergence of iterative reconstruction algorithms [S1, unofficial]. It differs from sibling methods by combining a Fan beam ray transform with Filtered Back Projection (FBP) to generate a reference image, followed by a multiplicative update rule based on voxel visibility across all cameras [S1, unofficial]. Unlike [Cylindrical Symmetry Projector](3005-cylindrical-symmetry-projector.md) which assumes symmetry, or [Analytic 3D Gaussian Ray Tracing for Tomography](3017-analytic-3d-gaussian-ray-tracing-for-tomography.md) which models point spread functions, this method relies on geometric visibility and multiplicative updates [S1, unofficial].

## How it works
**Inputs:** Pre-processed projection images (one per camera/view).
**Outputs:** Initialized 3D volume intensity distribution.

**Data Structures:**
*   `sinogram`: Array of shape `[batch, 720, 720]`, dtype `float32`.
*   `sparse_sinogram`: Array of shape `[batch, 720, 720]`, dtype `float32`.
*   `ori_img`: Array of shape `[batch, 720, 720]`, dtype `float32`.
*   `sinogram_max`: Array of shape `[batch, 1]`, dtype `float32`.
*   `volume`: 3D grid of voxels with intensity values.

**Parameters:**
*   `r`: Subsampling stride for the sinogram along the first axis (angular/detector axis). Value not given in the sources.
*   `N`: Number of cameras/views.

**Steps:**
1.  **Identify Visible Regions:** Determine regions inside the volume such that their intensity values are non-zero for all cameras [S1, unofficial].
2.  **Zero Out Non-Visible Voxels:** Set the intensity value of any voxel outside these identified regions to zero [S1, unofficial].
3.  **Compute Reference Image (FBP):**
    a. Convert input image to CPU numpy array [S2, unofficial].
    b. Initialize `sinogram`, `sparse_sinogram`, and `ori_img` arrays with shape `[batch, 720, 720]` [S2, unofficial].
    c. For each batch element `i`:
        i. Compute `sinogram[i]` via Fan beam ray transform of the input image: `sinogram[i] = Fan_ray_trafo(img[i])` [S2, unofficial].
        ii. Compute reference image `ori_img[i]` via Filtered Back Projection (FBP) of the sinogram: `ori_img[i] = Fan_FBP(sinogram[i])` [S2, unofficial].
        iii. Store the maximum value of the sinogram: `sinogram_max[i] = max(sinogram[i])` [S2, unofficial].
    d. Subsample `sinogram[i]` along the first axis with stride `r`: `t = np.copy(sinogram[i,::r,:])` [S2, unofficial].
    e. Resize `t` to `[720, 720]` using bilinear interpolation (cv2.resize) and store in `sparse_sinogram` [S2, unofficial].
4.  **Multiplicative Update:** For each voxel `v` in the visible regions:
    a. Identify the corresponding pixel `P_i` on the projection for each camera `i` [S1, unofficial].
    b. Let `R_ij` be the weight of voxel `v` for camera `i` [S1, unofficial].
    c. Update voxel intensity: $V_{new} = V_{old} \times \prod_{i=1}^{N} (R_{ij} \times P_i)$ [S1, unofficial].
    d. Normalize the voxel by raising the new value to the power of $1/N$: $V_{final} = V_{new}^{1/N}$ [S1, unofficial]. This ensures continuity of the relative field amplitude [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The multiplicative update can lead to numerical underflow or overflow if intensities are very small or large. Normalization helps but may not be sufficient for extreme values [S1, unofficial].
*   **Boundaries:** Voxels near the boundary of the volume may not be visible to all cameras, leading to zero intensity if not handled by the visibility mask [S1, unofficial].
*   **Degenerate Input:** If any projection image is entirely zero or invalid, the visibility mask will be empty, resulting in a zero-initialized volume [S1, unofficial].

## Subtopics

### MFG-MART
Combines MFG initialization with MART (Multiplicative Algebraic Reconstruction Technique) for iterative refinement. Reduces calculation time by a factor of ~2.5 compared to standard MART, with a slight decrease in reconstruction precision [S1, unofficial].

### MinLOS/MLOS
Lines of Sight methods based on sparse volumes and initial particle location estimation. Not detailed in the sources beyond mentioning they eliminate background [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The number of operations $F_{MFG}$ for the MFG step is given by $F_{MFG} = N_{vox} (8N + 1)$, where $N_{vox}$ is the total number of voxels and $N$ is the number of cameras [S1, unofficial].
*   **Memory Complexity:** Requires storage for `sinogram`, `sparse_sinogram`, `ori_img`, and `sinogram_max`, all of shape `[batch, 720, 720]` or `[batch, 1]` [S2, unofficial].
*   **Measured Performance:** For a particle density of 0.05 ppp, MFG alone provides a displacement field with an average error of 0.18 pixels, compared to 0.15 pixels with five standard iterations of MART [S1, unofficial].
*   **Strengths:** Reduces calculation time and accelerates convergence of iterative reconstruction algorithms [S1, unofficial].
*   **Limitations:** Slight decrease in reconstruction precision compared to standard iterative methods like MART [S1, unofficial].
*   **When to Use:** When fast initialization is needed for iterative reconstruction, and a slight loss in precision is acceptable [S1, unofficial].
*   **When Not to Use:** When high precision is critical and computational time is not a constraint [S1, unofficial].

## Background
The MFG (Multiplicative First Guess) method was introduced by Worth and Nickels in 2008 [S1, unofficial]. It is used in tomographic reconstruction, particularly in particle image velocimetry (PIV) and 3D particle tracking, to estimate the initial intensity distribution of a volume from pre-processed projection images [S1, unofficial]. The method leverages the concept of visible regions and multiplicative updates to provide a good starting point for iterative algorithms like MART [S1, unofficial].
