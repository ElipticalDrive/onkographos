# Pre-computed Color/Opacity Volume Rendering

Also called: Levoy's method, Pre-computed Classification and Shading, Pre-computed Volume Rendering, Voxel space volume rendering

## Overview
Pre-computed Color/Opacity Volume Rendering is a voxel-space volume rendering technique that precomputes discrete opacity and color fields from the scalar data field, then uses standard ray casting with front-to-back composition to render pixels [S1, unofficial][S2]. It sets itself apart from its siblings, such as [Volumetric Isosurface Rendering with Intersection Refinement](958-volumetric-isosurface-rendering-with-intersection-refinement.md), by performing classification and shading in the data space (voxel space) rather than in the image space (ray space), thereby avoiding per-ray shading calculations at the cost of high memory usage and static lighting [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar data field $D$ of dimensions $n_x \times n_y \times n_z$.
*   **Outputs:** Two precomputed volumes: an opacity field $O$ and a color field $C$, both of dimensions $n_x \times n_y \times n_z$. The final rendered image is produced by ray casting through $O$ and $C$.

**Data Structures:**
1.  **Scalar Field $D$:** The original input data.
2.  **Gradient Field $\nabla D$:** A vector field of the same dimensions as $D$, storing the central difference gradient for each voxel.
3.  **Opacity Field $O$:** A scalar field where $O(x,y,z)$ stores the precomputed opacity.
4.  **Color Field $C$:** A vector field (typically RGB) where $C(x,y,z)$ stores the precomputed shaded color.

**Numbered Steps:**

1.  **Compute Gradient Field:** Calculate the volume gradient $\nabla D$ at each voxel location using central differences [S1, unofficial]. Let $\nabla D(x,y,z) = (\frac{\partial D}{\partial x}, \frac{\partial D}{\partial y}, \frac{\partial D}{\partial z})$.
2.  **Compute Opacity Field:** Apply a non-linear opacity transfer function $T_o$ to the data value and potentially the gradient magnitude at each voxel to determine the opacity [S1, unofficial][S2].
    $$ O(x,y,z) = T_o(D(x,y,z), \|\nabla D(x,y,z)\|) $$
    The function $T_o$ is user-definable [S2].
3.  **Compute Object Color:** Apply a non-linear color transfer function $T_c$ to the data value at each voxel to determine the base object color [S1, unofficial].
    $$ C_{obj}(x,y,z) = T_c(D(x,y,z)) $$
4.  **Compute Shading and Final Color Field:** For a **fixed** light direction $\mathbf{l}$, calculate the shading at each voxel. The local gradient $\nabla D$ is used as an approximation of the surface normal $\mathbf{n}$ [S2].
    $$ \mathbf{n}(x,y,z) = \frac{\nabla D(x,y,z)}{\|\nabla D(x,y,z)\|} $$
    The final color field $C$ is calculated from the shading and the object color [S1, unofficial]. Due to the fixed light direction and the inability to compute observer-dependent specular highlights efficiently, only diffuse shading is typically used [S1, unofficial].
    $$ C(x,y,z) = C_{obj}(x,y,z) \cdot (\mathbf{n}(x,y,z) \cdot \mathbf{l}) $$
    *Note: If the light source position changes, this entire step must be recomputed for the whole dataset [S1, unofficial].*
5.  **Ray Casting:** Cast rays into the precomputed $O$ and $C$ volumes for image generation [S2].
6.  **Re-sampling:** For each ray, calculate the opacity and color at re-sampling locations by re-sampling (interpolating) the discrete fields $O$ and $C$ [S1, unofficial].
7.  **Front-to-Back Composition:** Use front-to-back compositing to compute the final pixel colors [S1, unofficial]. For a ray with samples $i=1 \dots N$:
    $$ C_{pixel} = \sum_{i=1}^{N} C_i \cdot \alpha_i \cdot \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $C_i$ and $\alpha_i$ are the color and opacity values re-sampled at the $i$-th sample point.

**Parameters:**
*   **Transfer Functions $T_o, T_c$:** User-defined functions mapping data values to opacity and color.
*   **Light Direction $\mathbf{l}$:** Fixed vector for shading. Changing this requires full recomputation [S1, unofficial].
*   **Sampling Distance:** Determines the number of samples per ray. Changes to this may require recomputation of the opacity field if the opacity function depends on sampling distance [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Lighting Changes:** Changing the light source position requires recomputing the expensive color field for the entire dataset [S1, unofficial].
*   **Specular Shading:** Full Phong specular shading is impossible without recomputing the color field for every viewing angle because it requires the observer position relative to the surface normal [S1, unofficial]. Consequently, only diffuse shading is practical [S1, unofficial].
*   **Memory Usage:** Storing gradients and gradient magnitudes for all voxels, along with the color and opacity fields, becomes prohibitive for high-resolution datasets [S2].
*   **Parameter Changes:** Any change in classification or shading parameters requires the opacity and color arrays to be recomputed, which prohibits interactive exploration of dynamically changing datasets [S2].

## Operating characteristics
*   **Time Complexity:** Precomputation is $O(n_x n_y n_z)$ for gradient, opacity, and color field generation. Rendering is $O(N \cdot R)$ where $N$ is samples per ray and $R$ is number of rays. However, precomputation is expensive and static [S1, unofficial][S2].
*   **Memory Complexity:** Requires storing the original data, gradient field, opacity field, and color field. This results in high memory requirements, often 4-5 times the size of the original scalar field [S1, unofficial][S2].
*   **Strengths:** Fast rendering once precomputed, as shading is done in voxel space. The 2-D view can be calculated from an arbitrary viewing location without recomputing the opacity or color fields for each viewing angle [S1, unofficial].
*   **Limitations:** High memory usage. Static lighting (diffuse only). Recomputation required for any change in light direction, classification, or shading parameters. Not suitable for interactive exploration of dynamic datasets [S1, unofficial][S2].
*   **When to use:** When the lighting and classification parameters are fixed, and rendering speed is prioritized over interactivity or memory efficiency.
*   **When not to use:** When dynamic lighting, interactive parameter adjustment, or high-resolution data with limited memory is required.

## Background
This method is based on the work introduced by Marc Levoy [LEV88] [S1, unofficial]. It is a classic approach in volume rendering that shifts the computational burden of classification and shading from the ray space to the voxel space.
