# Pre-computed Color/Opacity Volume Rendering

Also called: Levoy's method, Pre-computed Classification and Shading, Pre-computed Volume Rendering, Voxel space volume rendering

## Overview
Pre-computed Color/Opacity Volume Rendering is a voxel-space technique that precomputes discrete opacity and color fields from the scalar data field, then uses standard front-to-back ray casting to render pixels [S2, unofficial]. It sets itself apart from its siblings by moving the expensive classification and shading calculations from the ray traversal loop into a one-time preprocessing step, allowing for fast, view-independent rendering [S1][S2, unofficial]. Unlike methods that compute shading per-sample during traversal, this method fixes the lighting model during precomputation [S2, unofficial].

## How it works
**Inputs:**
*   Scalar data field $D$ of dimensions $N_x \times N_y \times N_z$ [S2, unofficial].
*   Opacity transfer function $T_o(v)$, mapping data value $v$ to opacity $\alpha \in [0, 1]$ [S3].
*   Color transfer function $T_c(v)$, mapping data value $v$ to base object color $\mathbf{C}_{obj}$ [S2, unofficial].
*   Light direction vector $\mathbf{l}$ (fixed for the precomputation) [S2, unofficial].
*   Shading model parameters (e.g., ambient color $\mathbf{C}_{amb}$, diffuse coefficient $k_d$) [S2, unofficial].

**Outputs:**
*   Precomputed Opacity Volume $O$ of dimensions $N_x \times N_y \times N_z$ [S2, unofficial].
*   Precomputed Color Volume $C$ of dimensions $N_x \times N_y \times N_z$ [S2, unofficial].
*   Rendered image pixels [S2, unofficial].

**Data Structures:**
*   $D[i,j,k]$: Input scalar value at voxel $(i,j,k)$ [S2, unofficial].
*   $O[i,j,k]$: Precomputed opacity at voxel $(i,j,k)$ [S2, unofficial].
*   $C[i,j,k]$: Precomputed RGB color at voxel $(i,j,k)$ [S2, unofficial].
*   $\nabla D[i,j,k]$: Gradient vector at voxel $(i,j,k)$, computed via central differences [S2, unofficial].

**Steps:**

1.  **Compute Gradients:** Calculate the gradient $\nabla D[i,j,k]$ for every voxel in the dataset using central differences [S2, unofficial]. For interior voxels:
    $$ \nabla D[i,j,k] = \left( \frac{D[i+1,j,k] - D[i-1,j,k]}{2}, \frac{D[i,j+1,k] - D[i,j-1,k]}{2}, \frac{D[i,j,k+1] - D[i,j,k-1]}{2} \right) $$
    Boundary conditions must be handled appropriately (e.g., one-sided differences) [G].

2.  **Compute Opacity Field:** Apply a non-linear opacity function to the data value at each voxel to generate $O[i,j,k]$ [S2, unofficial]. This step is performed once, or whenever the opacity function or sampling distance changes [S2, unofficial].

3.  **Compute Object Color:** Apply a non-linear color function to the data value at each voxel to generate $\mathbf{C}_{obj}[i,j,k]$ [S2, unofficial].

4.  **Compute Shading and Final Color Field:** Approximate the surface normal $\mathbf{n}$ using the normalized gradient $\mathbf{n}[i,j,k] = \frac{\nabla D[i,j,k]}{\|\nabla D[i,j,k]\|}$ [S2, unofficial]. Calculate the shaded color $\mathbf{C}[i,j,k]$ using a local shading model for a fixed light direction $\mathbf{l}$ and ambient color $\mathbf{C}_{amb}$:
    $$ \mathbf{C}[i,j,k] = \mathbf{C}_{amb} + k_d (\mathbf{n}[i,j,k] \cdot \mathbf{l}) \mathbf{C}_{obj}[i,j,k] $$
    This results in the precomputed color volume $C$ [S2, unofficial]. Full Phong specular shading is impossible without recomputing for every view because it requires the view vector [S2, unofficial].

5.  **Ray Casting:** For each pixel, cast a ray through the volume [S2, unofficial]. Sample the precomputed volumes $O$ and $C$ at the ray's intersection points using tri-linear interpolation [S2, unofficial].

6.  **Front-to-Back Composition:** Accumulate the color and opacity along the ray using front-to-back compositing [S2, unofficial]:
    $$ C_{pixel} = \sum_{k=1}^{N} c_k \alpha_k \prod_{j=1}^{k-1} (1 - \alpha_j) $$
    where $c_k$ and $\alpha_k$ are the interpolated color and opacity from volumes $C$ and $O$ at the $k$-th sample [S2, unofficial].

**Pseudocode:**
```python
def PrecomputeColorOpacityVolume(D, T_o, T_c, l, k_d, C_amb):
    Nx, Ny, Nz = dimensions of D
    O = array of size Nx x Ny x Nz
    C = array of size Nx x Ny x Nz x 3
    for i from 0 to Nx-1:
        for j from 0 to Ny-1:
            for k from 0 to Nz-1:
                dx = (D[i+1, j, k] - D[i-1, j, k]) / 2 if 0 < i < Nx-1 else 0
                dy = (D[i, j+1, k] - D[i, j-1, k]) / 2 if 0 < j < Ny-1 else 0
                dz = (D[i, j, k+1] - D[i, j, k-1]) / 2 if 0 < k < Nz-1 else 0
                grad = (dx, dy, dz)
                O[i, j, k] = T_o(D[i, j, k])
                C_obj = T_c(D[i, j, k])
                n = grad / magnitude(grad)
                C[i, j, k] = C_amb + k_d * dot(n, l) * C_obj
    return O, C

def Render(O, C, ray_origin, ray_direction, image_width, image_height):
    image = array of size image_height x image_width x 3
    for y from 0 to image_height-1:
        for x from 0 to image_width-1:
            ray = compute_ray(ray_origin, ray_direction, x, y)
            samples = []
            t = ray_entry_t
            while t < ray_exit_t:
                voxel = sample_voxel_at(ray, t)
                alpha = trilinear_interpolate(O, voxel)
                color = trilinear_interpolate(C, voxel)
                samples.append((color, alpha))
                t += step_size
            pixel_color = front_to_back_composite(samples)
            image[y, x] = pixel_color
    return image
```

**Parameters:**
*   Transfer functions $T_o, T_c$: User-defined [S3].
*   Light direction $\mathbf{l}$: Fixed during precomputation [S2, unofficial].
*   Shading coefficients ($k_d, \mathbf{C}_{amb}$): Fixed during precomputation [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Light/View Changes:** Changing the light source position requires recomputing the entire color field $C$ for the whole dataset [S2, unofficial]. Changing the viewing angle requires recomputing $C$ if specular shading is desired, which is prohibitively expensive [S2, unofficial].
*   **Memory:** Storing gradients and gradient magnitudes for all voxels, plus the two output volumes ($O$ and $C$), increases memory requirements significantly [S2, unofficial].
*   **Interactivity:** Any change in classification or shading parameters requires recomputing $O$ and $C$, making interactive exploration of dynamic datasets difficult for high-resolution data [S3].

## Subtopics

### Voxel Space vs. Image Space
This method operates in voxel space by precomputing attributes, whereas image-space methods compute attributes on-the-fly during ray traversal [S3]. Choose voxel space for static lighting and classification; choose image space for interactive parameter tuning [S3].

## Operating characteristics
*   **Time Complexity:** Precomputation is $O(N_x N_y N_z)$ for gradient, opacity, and color field generation [S2, unofficial]. Rendering is $O(P \cdot S)$, where $P$ is pixels and $S$ is samples per ray, similar to standard ray casting but with faster per-sample processing (no shading/gradient calculation) [S2, unofficial].
*   **Memory Complexity:** Requires storage for the original data, gradients (3 components), opacity volume, and color volume [S2, unofficial].
*   **Strengths:** Fast rendering once precomputed; view-independent lighting; simple compositing [S2, unofficial].
*   **Limitations:** High memory usage; non-interactive for lighting/view changes; diffuse shading only (without expensive recomputation) [S2, unofficial].
*   **When to use:** Static scenes with fixed lighting and classification; offline rendering; low-to-medium resolution data where memory is not a bottleneck [S2, unofficial].
*   **When not to use:** Interactive visualization requiring dynamic light/view changes; high-resolution datasets with limited memory; scenes requiring view-dependent specular highlights [S2, unofficial].

## Background
This method is based on the work introduced by Marc Levoy [LEV88] and is widely referred to as Levoy's method [S1]. It was one of the early approaches to volume rendering, precomputing opacity and color fields to accelerate the rendering process [S1]. It is a foundational technique in voxel-space volume rendering [S2, unofficial].
