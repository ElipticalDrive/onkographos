# GPU-based Fast Ray Casting for Metaballs

Also called: Nishita and Nakamae's Algorithm

## Overview
This method renders particle-based implicit surfaces (metaballs) directly on the GPU by evaluating the isosurface condition per pixel, avoiding polygonization and expensive precomputation or acceleration structures [S1]. It solves the problem of high rendering costs for large numbers of moving metaballs by maintaining a limited-size list of contributing metaballs along each viewing ray and using Bézier Clipping to solve the resulting polynomial equations [S1]. Unlike sibling methods that rely on grid-based repulsion buffers or vertex attribute interpolation, this approach handles millions of particles and small objects smoothly by extracting metaballs via depth peeling and solving quartic or degree-six density functions exactly [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ metaballs, each defined by center $\mathbf{p}_i$, effective radius $R_i$, density coefficient $q_i$, and a density function $f_i(r)$ with finite support [S1]. The viewing ray $r(t) = \mathbf{o} + t\mathbf{d}$ for each pixel [G]. Threshold $T$ [S1].
*   **Outputs:** Color and normal for the closest isosurface intersection per pixel [S1].

**Data Structures:**
*   **ID List:** A dynamic list storing metaball IDs contributing to the current ray interval [S1]. Capacity is limited to $K$ [S1].
*   **Stored $t$:** The $t$-parameter of the last processed ray-sphere intersection [S1].
*   **Texture:** Stores the current ID list and stored $t$ for each pixel, updated via depth peeling [S1].

**Density Function:**
The density function $f_i$ for metaball $i$ is a function of $r = \|\mathbf{x} - \mathbf{p}_i\|$ and monotonically decreases as $r$ increases [S1]. If $f_i$ has finite support $R_i$, $f_i(r) = 0$ for $r \ge R_i$ [S1]. The method supports quartic and degree-six polynomials [S1]. The isosurface is defined by:
$$ f(\mathbf{x}) = \sum_{i=0}^{N-1} q_i f_i(\|\mathbf{x} - \mathbf{p}_i\|) - T = 0 $$
The normal vector at $\mathbf{x}$ is derived from $-\nabla f(\mathbf{x})$ [S1].

**Algorithm Steps:**
1.  **Initialize:** For each pixel, initialize the ID list as empty and stored $t$ to the near clipping plane [G].
2.  **Depth Peeling Loop:**
    a.  Render effective spheres (spheres with radius $R_i$) to find the $k$-th nearest ray-sphere intersection $(t_k, B_k)$ in parallel [S1].
    b.  If no intersection is found, terminate the loop for this pixel [S1].
    c.  Update the ID list:
        i.  If $B_k$ is not in the ID list, insert it [S1].
        ii. If $B_k$ is already in the ID list, remove it (handling occlusion) [S1].
        iii. If the ID list size exceeds $K$, treat the ray-sphere intersection as a ray-isosurface intersection (fallback) [S1].
    d.  **Ray-Isosurface Test:** In the interval $[t_{k-1}, t_k]$, perform a ray-isosurface test using the metaballs in the ID list [S1].
        i.  **Single Case:** If only one metaball is in the ID list, perform a ray-sphere intersection test. The radius can be precomputed [S1].
        ii. **Multiple Case:** If two or more metaballs are in the ID list, construct a degree-$M$ Bézier curve equation $d(u)=0$ representing the density function along the ray segment, and solve for roots using Bézier Clipping [S1].
        iii. If a root is found in $[t_{k-1}, t_k]$, record the intersection, shade the surface, and terminate the loop for this pixel [S1].
    e.  Update stored $t$ to $t_k$ [S1].
    f.  Repeat steps 2a-2e until an isosurface is found or no more intersections are available [S1].
3.  **Shading:** Evaluate and shade the isosurface closest to the viewpoint at every pixel [S1].

**Bézier Clipping:**
A degree-$M$ Bézier curve is denoted with parameter $u \in [0,1]$ as:
$$ \mathbf{D}(u) = (u, d(u)) = \sum_{i=0}^M \mathbf{D}_i \mathbf{B}_i^M(u) $$
where $\mathbf{B}_i^M(u) = \binom{M}{i} u^i (1-u)^{M-i}$ are Bernstein polynomials, and $\mathbf{D}_i = (i/M, d_i)$ are control points [S1]. The curve lies within the convex hull of $\mathbf{D}_i$ [S1]. The intersection with the $u$-axis lies between $u_{min}$ and $u_{max}$, where the convex hull intersects the axis [S1]. Iteratively clip the curve in $[u_{min}, u_{max}]$ using de Casteljau's algorithm [S1]. If the range does not converge past a threshold, split the curve in two and recurse [S1]. To mitigate root misdetection when the convex hull barely intersects the axis, slightly increase the clipping range [S1]. Unlike Newton's method, Bézier Clipping does not require an initial value and converges quickly [S1].

**Pseudocode:**
```python
import math

def render_metaballs(pixels, metaballs, threshold, max_id_list_size=14):
    results = []
    for o, d in pixels:
        id_list = []
        stored_t = 0.0  # near clipping plane [G]
        hit = False
        hit_t = 0.0
        hit_normal = None

        while not hit:
            # Step 2a: Find k-th intersection via depth peeling logic
            t_k, ball_id = find_kth_sphere_intersection(o, d, metaballs, stored_t, id_list)
            if t_k is None:
                break  # Step 2b: No more spheres

            # Step 2c: Update ID list
            if ball_id in id_list:
                id_list.remove(ball_id)
            else:
                if len(id_list) < max_id_list_size:
                    id_list.append(ball_id)
                else:
                    # Fallback for dense groups exceeding K [S1]
                    hit = True
                    hit_t = t_k
                    hit_normal = compute_normal_from_sphere(o, d, metaballs[ball_id])
                    break

            # Step 2d: Ray-Isosurface Test
            root = ray_isosurface_test(id_list, o, d, stored_t, t_k, threshold)
            if root is not None:
                hit = True
                hit_t = root
                hit_normal = compute_gradient_normal(id_list, o + root * d, threshold)

            # Step 2e: Update stored t
            stored_t = t_k

        if hit:
            results.append(shade_hit(hit_t, hit_normal, o, d))
        else:
            results.append((0.0, 0.0, 0.0))  # background_color [G]
    return results

def find_kth_sphere_intersection(o, d, metaballs, stored_t, id_list):
    # Simulates depth peeling: finds smallest t > stored_t among active spheres
    best_t = float('inf')
    best_id = None
    for i, (center, radius, coeff, func) in enumerate(metaballs):
        if i in id_list:
            continue
        t = ray_sphere_intersection(o, d, center, radius)
        if t is not None and t > stored_t and t < best_t:
            best_t = t
            best_id = i
    return (best_t, best_id) if best_id is not None else (None, None)

def ray_sphere_intersection(o, d, center, radius):
    oc = [o[i] - center[i] for i in range(3)]
    b = sum(oc[i] * d[i] for i in range(3))
    c = sum(oc[i] * oc[i] for i in range(3)) - radius * radius
    disc = b * b - c
    if disc < 0:
        return None
    sqrt_disc = math.sqrt(disc)
    t = -b - sqrt_disc
    return t if t > 0 else (-b + sqrt_disc if -b + sqrt_disc > 0 else None)

def ray_isosurface_test(id_list, o, d, t_start, t_end, threshold):
    if len(id_list) == 1:
        # Single Case: ray-sphere intersection test [S1]
        ball = metaballs[id_list[0]]
        t = ray_sphere_intersection(o, d, ball[0], ball[1])
        return t if t_start <= t <= t_end else None
    else:
        # Multiple Case: construct Bézier curve and solve [S1]
        # Note: Exact polynomial-to-Bézier conversion is not detailed in sources [Comment]
        ctrl_pts = convert_to_bezier_control_points(id_list, o, d, t_start, t_end, threshold)
        return bezier_clipping(ctrl_pts, 0.0, 1.0, tol=1e-4)

def convert_to_bezier_control_points(id_list, o, d, t_start, t_end, threshold):
    # Placeholder for polynomial-to-Bézier conversion [Comment]
    # Returns list of (x, y) control points D_i = (i/M, d_i) [S1]
    return [(i/2, 0.0) for i in range(3)]  # Dummy for structure

def bezier_clipping(ctrl_pts, u_min, u_max, tol):
    # Iteratively clip using de Casteljau's algorithm [S1]
    while u_max - u_min > tol:
        # Compute convex hull bounds to find new intersection range [S1]
        y_vals = [p[1] for p in ctrl_pts]
        new_u_min = u_min
        new_u_max = u_max
        if min(y_vals) > 0 or max(y_vals) < 0:
            return None  # No root in range
        
        # Apply Campagna heuristic: slightly increase clipping range to avoid misdetection [S1]
        range_width = new_u_max - new_u_min
        new_u_min = max(0.0, new_u_min - 0.01 * range_width)
        new_u_max = min(1.0, new_u_max + 0.01 * range_width)
        
        # Check convergence
        if new_u_max - new_u_min > tol * 0.5:
            # Split curve in two and recurse [S1]
            mid = (new_u_min + new_u_max) / 2
            left_pts, right_pts = de_casteljau_split(ctrl_pts, mid)
            root_left = bezier_clipping(left_pts, new_u_min, mid, tol)
            if root_left is not None:
                return root_left
            return bezier_clipping(right_pts, mid, new_u_max, tol)
        
        # Update range based on hull intersection [S1]
        u_min, u_max = new_u_min, new_u_max
        ctrl_pts = de_casteljau_clip(ctrl_pts, u_min, u_max)
        
    return (u_min + u_max) / 2

def de_casteljau_split(ctrl_pts, t):
    n = len(ctrl_pts) - 1
    left = [ctrl_pts[0]]
    right = [ctrl_pts[0]]
    for j in range(1, n + 1):
        for i in range(n, j - 1, -1):
            ctrl_pts[i] = [(1 - t) * ctrl_pts[i][k] + t * ctrl_pts[i - 1][k] for k in range(2)]
        left.append(ctrl_pts[j])
        right.insert(0, ctrl_pts[j])
    return left, right

def de_casteljau_clip(ctrl_pts, u_min, u_max):
    # Simplified clipping: retain control points within range bounds
    return [p for p in ctrl_pts if u_min <= p[0] <= u_max]

def compute_normal_from_sphere(o, d, ball):
    center, radius, _, _ = ball
    hit = [o[i] + ray_sphere_intersection(o, d, center, radius) * d[i] for i in range(3)]
    return [(hit[i] - center[i]) / radius for i in range(3)]

def compute_gradient_normal(id_list, point, threshold):
    # Analytical gradient for polynomial density functions [G]
    grad = [0.0, 0.0, 0.0]
    for i in id_list:
        ball = metaballs[i]
        center, radius, coeff, func = ball
        dist = math.sqrt(sum((point[j] - center[j])**2 for j in range(3)))
        if dist < radius:
            for j in range(3):
                grad[j] -= coeff * func_prime(dist) * (point[j] - center[j]) / dist
    norm = math.sqrt(sum(g**2 for g in grad))
    return [g / norm for g in grad] if norm > 0 else [0.0, 0.0, 1.0]

def func_prime(r):
    # Derivative of quartic/degree-six density function [S1]
    return -4 * r**3  # Example for quartic

def shade_hit(t, normal, o, d):
    # Simple Phong shading [G]
    hit = [o[i] + t * d[i] for i in range(3)]
    light = [1.0, 1.0, -1.0]
    l = [l / math.sqrt(sum(x**2 for x in light)) for l in light]
    diff = max(0, sum(normal[i] * l[i] for i in range(3)))
    return (0.5 + 0.5 * diff, 0.5 + 0.5 * diff, 0.5 + 0.5 * diff)
```

## Subtopics

### [Real-Time Metaball Ray Casting with Fragment Lists](9945-real-time-metaball-ray-casting-with-fragment-lists.md)
A real-time ray casting method for rendering particle-based medium representations (metaballs) that builds per-pixel lists of relevant metaballs, incrementally constructs a piecewise polynomial approximation of summed densities along rays, and finds intersections with the isosurface. It replaces the multipass depth peeling used in [GPU-based Fast Ray Casting for Metaballs](9502-gpu-based-fast-ray-casting-for-metaballs.md) with single-pass fragment list gathering, allowing robust handling of local extremities of depth complexity and scaling to millions of particles.

### Metaball Culling via Occlusion Queries
Reduces the number of rendered metaballs by culling effective spheres hidden from the viewpoint by 'kernel spheres' (spheres making up the isosurface) [S1]. Render the kernel spheres and save the ray parameters to a texture [S1]. Disable writes to the depth buffer [S1]. Render the effective spheres, using the occlusion query to determine which effective spheres were drawn [S1]. Cull the effective spheres that were not rendered in the above test [S1]. This culling can reduce the number of metaballs to be rendered to 10-20% in dense groups [S1].

### Ray-Isosurface Test Special Case Handling
Procedural rules for handling degenerate or dense ray-metaball intersections during depth peeling to prevent duplicate IDs, holes, or occlusion errors [S1]. When multiple effective spheres intersect the viewing ray at the same point, compare ray parameters and return only one metaball ID [S1]. Check if the ID is already stored in the list; discard fragments containing that ID if present [S1]. When dense groups exceed the ID list upper limit $K = 4 \times N_{buf} - 2$, the standard intersection test fails and causes holes [S1]. Fallback: treat the ray-sphere intersection as a ray-isosurface intersection [S1]. When the viewing ray intersects the isosurface only after crossing other metaballs, repeat depth peeling until termination to keep the isosurface visible, provided $K$ is not exceeded [S1]. Parameter: $K$ (Upper limit for the ID list capacity). Value used in experiments: 14. No visual artifacts observed with this value [S1]. Pitfall: Checking for duplicate IDs in the list drastically increases depth peeling cost. In 32-bit floating point computations, omitting this check produces no visible artifacts [S1].

### Depth Peeling for Ray-Sphere Intersection
A technique to obtain ray-sphere intersections in parallel from front to back by drawing effective spheres and storing IDs and ray parameters into a texture, discarding fragments whose parameters are less than previous ones [S1].

## Operating characteristics
*   **Time Complexity:** Depends on screen resolution and the number of metaballs intersecting each ray. Depth peeling requires multiple passes, one per intersecting sphere. Bézier Clipping converges quickly but requires iterative clipping [S1].
*   **Memory Complexity:** Limited by the ID list size $K$ and texture storage for depth peeling. $K$ is typically 14 [S1].
*   **Measured Performance:** An animation with 1,000 moving metaballs was rendered in 640×480 at 23.1 fps [S1].
*   **Strengths:** Handles large numbers of moving metaballs efficiently without precomputation or acceleration structures. Renders small objects smoothly, unlike grid-based methods [S1]. Solves quartic and degree-six polynomials accurately [S1].
*   **Limitations:** Performance degrades with very dense groups of metaballs due to ID list limits and depth peeling passes. Bézier Clipping can be computationally expensive [S1].
*   **When to Use:** Real-time visualization of particle-based simulations (fluid dynamics, molecular dynamics) with many moving metaballs [S1].

## Background
Originated from Nishita and Nakamae's algorithm for ray casting implicit surfaces [S1]. The method was adapted for the GPU by [S1] to handle large numbers of moving metaballs. It builds on the concept of finite support density functions (quartic and degree-six polynomials) proposed by Nishita and Nakamae [S1]. Bézier Clipping was introduced by Nishita and Nakamae [NN94] and later optimized for GPUs by Pabst et al. [PSS*06] and Campagna et al. [CSS97] [S1].
