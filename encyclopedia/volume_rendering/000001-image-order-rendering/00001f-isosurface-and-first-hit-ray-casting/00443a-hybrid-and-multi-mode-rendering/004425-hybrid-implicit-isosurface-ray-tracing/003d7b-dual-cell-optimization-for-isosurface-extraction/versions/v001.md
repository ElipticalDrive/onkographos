# Dual Cell Optimization for Isosurface Extraction

Also called: Optimization 1, Using Dual Cells at Same-level Regions

## Overview
This method optimizes the hybrid implicit isosurface extraction process by replacing octants with dual cells in non-boundary (same-level) regions, significantly reducing the number of primitives traversed during ray tracing. It achieves an approximate 4× speedup in extraction time by leveraging the fact that an octant of a cell remains an octant of the corresponding dual cell, ensuring the final isosurface geometry is unchanged when eight octants are merged into a single dual cell. It builds on [Hybrid Implicit Isosurface Ray Tracing](3832-hybrid-implicit-isosurface-ray-tracing.md) and is distinct from [Active Cell Filtering](9505-active-cell-filtering.md), which filters input cells before primitive generation.

## How it works
**Inputs and Outputs:**
- Input: A mesh of cells $C_i$ from TB-AMR (Tree-Based Adaptive Mesh Refinement) data, and a target isovalue.
- Output: A mesh `res` containing active cubic primitives (either dual cells $D_{ij}$ or octants $O_{ij}$).

**Data Structures:**
- **Cell $C_i$**: The input volume element.
- **Octant $O_{ij}$**: One of eight sub-cubes of $C_i$, indexed by $j \in \{0, \dots, 7\}$. Vertices require reconstruction via the GTI method if at a boundary.
- **Dual Cell $D_{ij}$**: A cell enclosed by data points of known values. Its vertices are data points, requiring no reconstruction kernel. The center of $C_i$ is a vertex of $D_{ij}$.

**Algorithm Steps:**
1. Iterate through each input cell $C_i$ in the input mesh.
2. For each of the 8 octants $j$ of $C_i$:
   a. Construct the candidate dual cell $D_{ij}$ using `findDualCell(Ci, j)`.
   b. Determine if $D_{ij}$ lies in a same-level region using `isDualCellInSameLevel(Dij)`.
   c. If $D_{ij}$ is in a same-level region:
      i. Check if the isovalue lies within the value range of $D_{ij}$ using `Dij.ValueRange().Contains(isovalue)`.
      ii. If true, and if $j=7$ (to avoid duplicate insertion for shared dual cells), insert $D_{ij}$ into `res`.
   d. If $D_{ij}$ is not in a same-level region (i.e., $C_i$ is at a level boundary):
      i. Initialize the octant $O_{ij}$ using `initOctant(Ci, j)`.
      ii. Compute vertex values for $O_{ij}$ using the GTI method.
      iii. Check if the isovalue lies within the value range of $O_{ij}$.
      iv. If true, insert $O_{ij}$ into `res`.

**Pseudocode:**
```python
def extract_cubic_primitives(input_mesh, isovalue):
    res = Mesh()
    for i in range(input_mesh.num_cells()):
        Ci = input_mesh.get_cell(i)
        for j in range(8):
            # Construct dual cell candidate
            Dij = find_dual_cell(Ci, j)
            
            # Check if the dual cell lies in a same-level region
            in_same_level = is_dual_cell_in_same_level(Dij)
            
            if in_same_level:
                # Dual cell vertices are data points of known values
                # Only insert once per dual cell (j=7 ensures this for shared cells)
                if j == 7 and Dij.value_range().contains(isovalue):
                    res.insert_cell(Dij)
            else:
                # Parent cell is at a level boundary
                Oij = init_octant(Ci, j)
                # Compute vertex values using GTI method
                gti_method(Oij)
                if Oij.value_range().contains(isovalue):
                    res.insert_cell(Oij)
    return res
```

**Parameters and Edge Cases:**
- **TB-AMR vs BS-AMR**: For BS-AMR (Brick-Based), cells are stored in uniform grids, making same-level checks trivial. For TB-AMR, cells are stored in an octree, and neighboring cell levels are not readily available. This requires checking if a dual cell lies in a same-level region during extraction, complicating the implementation [S1].
- **Duplicate Insertion**: The condition `j == 7` prevents inserting the same dual cell multiple times when it is shared by adjacent parent cells.

## Operating characteristics
- **Performance**: Achieves an approximate 4× speedup in extraction time compared to using octants exclusively [S1].
- **Complexity**: Reduces the number of primitives traversed by ray tracing, improving rendering performance.
- **Limitations**: The optimization is specific to same-level regions. At level boundaries, octants must still be used with GTI reconstruction, which is more costly.

## Background
This optimization was introduced by Wang et al. in the context of CPU ray tracing of Tree-Based Adaptive Mesh Refinement (TB-AMR) data [S1]. While similar optimizations were applied to BS-AMR data in previous work [WWW∗19], the TB-AMR implementation required additional complexity due to the octree data layout. The method is part of the hybrid implicit isosurface rendering pipeline integrated into OSPRay.
