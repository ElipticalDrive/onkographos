# Multi-Mode Rendering with Iso-surfaces and Meshes

Also called: Hybrid Ray Tracing for Iso-surfaces and Meshes, Surface-Volume Hybrid Rendering

## Overview
Multi-Mode Rendering with Iso-sururface and Meshes is a hybrid rendering technique that combines hardware-accelerated ray-triangle intersection for explicit surface geometry (meshes) and implicit iso-surfaces with volume ray marching for scalar field data [S1]. It solves the problem of efficiently rendering scenes containing both dense volumetric data and sparse, high-frequency surface details by leveraging separate bounding volume hierarchies (BVHs) and shortening the volume integration range based on the nearest surface hit [S1]. Unlike pure volume rendering, it prioritizes surface geometry for occlusion and depth cues, and unlike pure mesh rendering, it retains the ability to visualize internal structures up to the surface boundary [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A scalar field dataset (structured AMR or regular grid), a set of triangle meshes, an iso-value for implicit surface generation, a transfer function for volume coloring/opacity, and a camera ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$.
*   **Outputs:** A final color and opacity for each pixel, potentially including ambient occlusion values.

**Data Structures:**
The method maintains three distinct spatial acceleration structures [S1]:
1.  **Volume BVH:** A BVH built over the volume data bricks/regions to accelerate empty space skipping during ray marching.
2.  **Iso-surface BVH:** A BVH built over the implicit iso-surface geometry. This structure is rebuilt whenever the iso-value changes [S1].
3.  **Mesh BVH:** A BVH built over the explicit triangle meshes, utilizing hardware-accelerated ray-triangle intersection (e.g., RTX) [S1].

**Algorithm Steps:**
1.  **Mesh Intersection:** Trace the input ray against the Mesh BVH using hardware-accelerated ray-triangle intersection to find the nearest intersection distance $t_{mesh}$ [S1].
2.  **Iso-surface Intersection:** Transform the ray into the volume coordinate space. Trace the transformed ray against the Iso-surface BVH to find the nearest intersection distance $t_{iso}$ [S1].
3.  **Ray Shortening:** Determine the effective end of the volume integration range $t_{end}$ [S1]:
    *   If a surface hit exists ($t_{mesh} < \infty$ or $t_{iso} < \infty$), set $t_{end} = \min(t_{mesh}, t_{iso})$.
    *   If no surface hit exists, $t_{end}$ is determined by the clipping plane's $ray.tmax$ or the volume boundary.
    *   *Note:* Clipping planes are implemented by constraining the ray's $[ray.tmin, ray.tmax]$ intervals [S1].
4.  **Volume Integration:** Trace the shortened ray (from $ray.tmin$ to $t_{end}$) through the Volume BVH. Perform ray marching to integrate the volume data (color and opacity) up to the surface hit point [S1].
5.  **Surface Shading (Optional):** If a surface was hit, shade the surface point using local shading models and/or ambient occlusion [S1].
6.  **Composite:** Combine the volume contribution (from step 4) and the surface contribution (from step 5) using standard alpha compositing.

**Pseudocode:**
```python
def render_ray(ray_o, ray_d, mesh_bvh, iso_bvh, volume_bvh, transfer_func, clipping_planes):
    # 1. Clip ray based on clipping planes
    t_min = max(ray_o.tmin, clipping_planes.tmin)
    t_max = min(ray_o.tmax, clipping_planes.tmax)
    
    # 2. Trace against Mesh BVH (Hardware Accelerated)
    hit_mesh = mesh_bvh.intersect(ray_o, ray_d, t_min, t_max)
    t_mesh = hit_mesh.t if hit_mesh else float('inf')
    
    # 3. Transform ray to volume space and trace against Iso-surface BVH
    ray_vol = transform_to_volume_space(ray_o, ray_d)
    hit_iso = iso_bvh.intersect(ray_vol, t_min, t_max)
    t_iso = hit_iso.t if hit_iso else float('inf')
    
    # 4. Determine integration end point
    t_end = min(t_mesh, t_iso, t_max)
    
    # 5. Volume Ray Marching
    volume_color = vec3(0.0)
    volume_opacity = 0.0
    current_t = t_min
    
    # March through volume BVH
    while current_t < t_end:
        # Sample volume data at current_t
        sample = volume_bvh.sample(ray_o, ray_d, current_t)
        color, opacity = transfer_func(sample)
        
        # Composite
        alpha = opacity * (1.0 - volume_opacity)
        volume_color += color * alpha
        volume_opacity += alpha
        
        # Advance step size (could be adaptive or fixed)
        current_t += step_size
        
        if volume_opacity >= 1.0:
            break
            
    # 6. Surface Shading (if hit)
    surface_color = vec3(0.0)
    if t_mesh < t_iso:
        # Use mesh hit point
        hit_point = ray_o + ray_d * t_mesh
        normal = mesh_bvh.get_normal(hit_point)
        surface_color = shade_mesh(hit_point, normal, ambient_occlusion=True)
    elif t_iso < t_mesh:
        # Use iso-surface hit point
        hit_point_vol = ray_vol + ray_vol.d * t_iso
        hit_point = transform_to_world_space(hit_point_vol)
        normal = iso_bvh.get_normal(hit_point_vol)
        surface_color = shade_iso_surface(hit_point, normal, ambient_occlusion=True)
        
    # 7. Final Composite
    final_color = volume_color + surface_color * (1.0 - volume_opacity)
    return final_color
```

**Parameters:**
*   **Iso-value:** Threshold for generating the implicit surface. Changing this requires rebuilding the Iso-surface BVH [S1].
*   **Ambient Occlusion:** Supported for depth cues, typically requiring two additional rays per pixel for surface and iso-surface geometry [S1].
*   **Clipping Planes:** Defined by $[ray.tmin, ray.tmax]$ intervals to control the integration range [S1].

**Edge Cases and Pitfalls:**
*   **Iso-value Change:** The Iso-surface BVH must be fully rebuilt when the iso-value changes, which can be computationally expensive [S1].
*   **Coordinate Space:** Rays must be correctly transformed between world and volume space for accurate iso-surface intersection [S1].
*   **Precision:** Hardware-accelerated intersection may have precision limits; however, the method relies on the BVH for coarse culling and hardware for exact triangle tests [S1].

## Subtopics

### Iso-surface BVH Construction
Builds a BVH for implicit surfaces defined by a scalar field threshold. Chosen when the surface topology changes frequently or is defined analytically. Links to [Iso-surface and first-hit ray casting](20-isosurface-and-first-hit-ray-casting.md).

### Hardware-Accelerated Mesh Tracing
Uses RTX hardware for triangle intersection. Chosen for explicit, static, or frequently updated mesh geometry. Links to [Triangular Mesh Scene Rendering](4644-triangular-mesh-scene-rendering.md).

### Volume BVH Marching
Uses a BVH to skip empty space during ray marching. Chosen for sparse or large-scale volumetric data. Links to [Cell-Based First-Hit Ray Casting](1039-cell-based-first-hit-ray-casting.md).

## Operating characteristics
*   **Time Complexity:** Dominated by the cost of BVH traversals and ray marching. The mesh and iso-surface intersections are $O(\log N)$ due to BVHs, while volume marching is $O(K)$ where $K$ is the number of samples within the shortened ray segment [S1].
*   **Memory Complexity:** Requires storing three BVHs (Volume, Iso-surface, Mesh) and the underlying scalar field data [S1].
*   **Performance:** The method leverages hardware acceleration for mesh and iso-surface intersections, which are often sparse, allowing for efficient empty space skipping [S1]. Volume marching is optimized by shortening the ray length based on surface hits [S1].
*   **Strengths:** Supports mixed content (volumes, implicit surfaces, explicit meshes) in a single pipeline. Provides accurate depth cues via surface shading and ambient occlusion [S1].
*   **Limitations:** Requires rebuilding the Iso-surface BVH when the iso-value changes [S1]. Complex to implement due to the need for multiple BVHs and coordinate space transformations [S1].
*   **When to Use:** Ideal for scientific visualization where both internal volume structures and external surface boundaries need to be rendered simultaneously [S1].
*   **When Not to Use:** When only pure volume rendering or pure mesh rendering is required, as the overhead of managing multiple BVHs is unnecessary [S1].

## Background
The method was introduced in the context of the ExaBricks renderer, which targets large-scale structured AMR data [S1]. It was developed to support realistic evaluation conditions by combining various rendering modes, including implicit isosurfaces and direct volume rendering [S1]. The approach exploits the sparsity of iso-surfaces for efficient empty space skipping and leverages modern GPU hardware for ray-triangle intersection [S1].
