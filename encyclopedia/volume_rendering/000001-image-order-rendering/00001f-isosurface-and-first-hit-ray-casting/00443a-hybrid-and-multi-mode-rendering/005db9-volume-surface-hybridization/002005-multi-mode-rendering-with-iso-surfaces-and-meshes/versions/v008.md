# Multi-Mode Rendering with Iso-surfaces and Meshes

Also called: Hybrid Ray Tracing for Iso-surfaces and Meshes, Surface-Volume Hybrid Rendering

## Overview
Multi-Mode Rendering with Iso-surfaces and Meshes is a hybrid rendering technique that combines hardware-accelerated ray-triangle intersection for explicit surface geometry (meshes) and implicit iso-surfaces with volume ray marching for volumetric data [S1]. It solves the problem of efficiently rendering scenes containing both discrete surfaces and continuous volumetric fields by using clipping planes to control the integration range of the volume data [S1]. It sets itself apart from pure volume rendering by prioritizing surface geometry intersection to limit volume integration, and from pure mesh rendering by retaining the ability to render internal volumetric structures up to the surface boundary [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A camera ray $(O, D)$, a triangle mesh represented by a BVH, an implicit iso-surface defined by a scalar field and iso-value represented by a BVH, and volumetric data represented by a BVH.
*   **Outputs:** A color and opacity value for the pixel.

**Data Structures:**
*   **Mesh BVH:** Bounding Volume Hierarchy for triangle meshes.
*   **Iso-surface BVH:** Bounding Volume Hierarchy for the implicit iso-surface. Rebuilt when the iso-value changes [S1].
*   **Volume BVH:** Bounding Volume Hierarchy for the volumetric data.
*   **Clipping Planes:** Implemented by modifying the ray's intersection interval $[t_{min}, t_{max}]$ [S1].

**Steps:**
1.  **Mesh Intersection:** Trace the camera ray against the Mesh BVH using hardware-accelerated ray-triangle intersection to find the nearest surface hit point $t_{mesh}$ [S1].
2.  **Iso-surface Check:** Transform the ray into the volume space. Trace the transformed ray against the Iso-surface BVH to find the nearest iso-surface hit point $t_{iso}$ [S1].
3.  **Ray Shortening:** Determine the effective end of the volume integration range $t_{end}$. If a surface hit exists (either mesh or iso-surface), $t_{end}$ is the minimum of the valid hit distances. If no surface is hit, $t_{end}$ is determined by the volume bounds or clipping planes [S1].
    *   Specifically, if a mesh hit exists at $t_{mesh}$ and an iso-surface hit exists at $t_{iso}$, the ray is shortened to the nearest one: $t_{end} = \min(t_{mesh}, t_{iso})$ [S1].
    *   If only one exists, $t_{end}$ is that distance [S1].
    *   If neither exists, $t_{end}$ is the original ray limit or clipping plane limit [S1].
4.  **Volume Integration:** Trace the shortened ray (from $t_{min}$ to $t_{end}$) through the Volume BVH. Perform ray marching to integrate the volume density and color up to $t_{end}$ [S1].
5.  **Shading:** Apply local shading and optional ambient occlusion (using two rays per pixel on surface and iso-surface geometry) for depth cues [S1].

**Pseudocode:**
```python
def render_multi_mode(ray_origin, ray_direction, mesh_bvh, iso_surface_bvh, volume_bvh, iso_value, clipping_planes):
    """
    Renders a single ray using multi-mode hybrid rendering.
    
    Args:
        ray_origin: vec3, origin of the camera ray.
        ray_direction: vec3, direction of the camera ray.
        mesh_bvh: BVH, bounding volume hierarchy for triangle meshes.
        iso_surface_bvh: BVH, bounding volume hierarchy for the iso-surface.
        volume_bvh: BVH, bounding volume hierarchy for volumetric data.
        iso_value: float, threshold for iso-surface extraction.
        clipping_planes: list of planes, defining clipping intervals [t_min, t_max].
        
    Returns:
        color: vec3, final pixel color.
        opacity: float, final pixel opacity.
    """
    
    # 1. Trace against Mesh BVH
    t_mesh = mesh_bvh.intersect(ray_origin, ray_direction)
    
    # 2. Transform ray to volume space and trace against Iso-surface BVH
    # Note: Transformation matrix from world to volume space is assumed available
    volume_ray_origin, volume_ray_direction = transform_to_volume_space(ray_origin, ray_direction)
    t_iso = iso_surface_bvh.intersect(volume_ray_origin, volume_ray_direction)
    
    # 3. Determine integration end point
    # Initialize t_end with the far clipping plane or default max distance
    t_end = get_clipping_max(clipping_planes)
    
    # Check for mesh hit
    if t_mesh is not None:
        t_end = min(t_end, t_mesh)
        
    # Check for iso-surface hit
    if t_iso is not None:
        # t_iso is in volume space, need to convert back to world space for comparison with t_mesh
        # Or, if t_mesh is in world space, convert t_iso to world space.
        # Assuming iso_surface_bvh returns distance in volume space units, 
        # we must convert this distance to world space units or vice versa.
        # For simplicity, assume t_iso is converted to world space distance t_iso_world
        t_iso_world = convert_volume_distance_to_world(t_iso, volume_ray_direction)
        t_end = min(t_end, t_iso_world)
        
    # 4. Trace shortened ray through Volume BVH
    # The ray is integrated from t_min (near clipping) to t_end
    t_min = get_clipping_min(clipping_planes)
    
    # Perform volume ray marching
    color, opacity = volume_ray_march(
        ray_origin, 
        ray_direction, 
        volume_bvh, 
        t_min, 
        t_end,
        iso_value # Pass iso_value if needed for transfer functions
    )
    
    # 5. Apply Shading (Ambient Occlusion if enabled)
    if ambient_occlusion_enabled:
        ao_factor = compute_ambient_occlusion(ray_origin, ray_direction, mesh_bvh, iso_surface_bvh)
        color = color * ao_factor
        
    return color, opacity
```

**Parameters:**
*   **Iso-value:** Threshold for iso-surface generation. Changing this requires rebuilding the Iso-surface BVH [S1].
*   **Clipping Planes:** Define the $[t_{min}, t_{max}]$ intervals for the ray [S1].
*   **Ambient Occlusion:** Optional, uses two rays per pixel on surface and iso-surface geometry for depth cues [S1].

**Edge Cases and Pitfalls:**
*   **Iso-surface BVH Rebuild:** The Iso-surface BVH must be rebuilt whenever the iso-value changes, as the geometry changes [S1].
*   **Coordinate Spaces:** Care must be taken when comparing hit distances from the Mesh BVH (world space) and the Iso-surface BVH (volume space). Distances must be converted to a common space before determining the minimum [S1].
*   **Empty Space Skipping:** Iso-surfaces generally have more potential for empty space skipping due to sparsity compared to dense volume data, justifying separate BVHs [S1].

## Operating characteristics
*   **Time Complexity:** Dominated by ray-triangle intersection for meshes and ray marching for volumes. Hardware-accelerated intersection for meshes is efficient [S1].
*   **Memory Complexity:** Requires maintaining separate BVHs for mesh, iso-surface, and volume data. Iso-surface BVH size depends on the complexity of the iso-surface at the given iso-value [S1].
*   **Strengths:** Efficient handling of mixed scene types (surfaces and volumes). Hardware acceleration for meshes reduces overhead. Clipping planes allow flexible control of integration ranges [S1].
*   **Limitations:** Requires rebuilding the Iso-surface BVH for every iso-value change. Coordinate space conversions add complexity [S1].
*   **When to use:** Scenes containing both explicit surface geometry (meshes) and volumetric data, where surfaces occlude volume data.
*   **When not to use:** Scenes with only volumetric data (use pure volume rendering) or only meshes (use pure mesh rendering).

## Background
This method is part of the ExaBricks rendering framework, which supports various rendering modes including implicit isosurfaces and direct volume rendering [S1]. It was developed to evaluate data structures under realistic conditions involving mixed geometry types [S1].
