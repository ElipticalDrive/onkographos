# Hybrid Rendering
Also called: Vosh rendering

## Overview
Hybrid rendering combines volume rendering (ray marching) and surface rendering (rasterization) to optimize computational cost and representation fidelity [S1, unofficial][S2]. It restricts ray marching to the region between the viewpoint and a pre-existing mesh surface, using the mesh intersection to terminate volume integration and provide the final color contribution [S1, unofficial][S2]. This approach leverages the mesh for high-fidelity, simple geometry while using the volume for complex, semi-transparent regions [S1, unofficial][S2].

## How it works
**Inputs:**
*   A voxel grid (or neural volume) representing semi-transparent density and color.
*   A triangle mesh representing surface geometry.
*   Camera parameters (view and projection matrices).

**Outputs:**
*   Final color image $C_{vosh}$.
*   Diffuse color $C_{vosh,d}$.
*   View-dependent features $F_{vosh}$.

**Data Structures:**
*   **Voxel Grid:** Stores per-voxel density $\sigma$ and color/features.
*   **Mesh:** Stores vertices and faces for rasterization.
*   **Ray:** Defined by origin $o$ and direction $d$.

**Algorithm:**
1.  **Rasterization:** Render the mesh to a depth buffer to obtain the intersection distance $t_{max}$ for each pixel. [S2]
2.  **Ray Marching:** For each pixel, cast a ray. March through the voxel grid until either:
    *   The ray exits the volume bounds.
    *   The accumulated transmittance drops below a threshold.
    *   The ray distance $t$ reaches $t_{max}$ (the mesh depth) [S1, unofficial][S2].
3.  **Volume Integration:** Compute the accumulated volume color $C_{vol}$ and transmittance $T_{vol}$ up to the stopping point. [S1, unofficial][S2]
4.  **Mesh Sampling:** If the ray intersects the mesh (i.e., $t_{max}$ was reached), sample the mesh color $C_{mesh}$ and features $F_{mesh}$ at the intersection point. [S1, unofficial][S2]
5.  **Weight Calculation:** Compute the mesh weight $w_m$ as the remaining transmittance from the volume rendering:
    $$ w_m = 1 - \sum_i w_i $$
    where $w_i$ are the weights of the sampled voxels. [S1, unofficial]
6.  **Hybrid Color Computation:** Combine volume and mesh contributions. The final color $C_{vosh}$ is computed using a Multi-Layer Perceptron (MLP) that takes the volume diffuse color $C_{vosh,d}$, view-dependent features $F_{vosh}$, and depth $d$ as input:
    $$ C_{vosh} = C_{vosh,d} + \text{MLP}(C_{vosh,d}, F_{vosh}, d) $$
    The intermediate features $F_{vosh}$ and diffuse color $C_{vosh,d}$ are weighted sums of volume and mesh contributions:
    $$ F_{vosh} = \sum_i w_i f_i + w_m f_m $$
    $$ C_{vosh,d} = \sum_i w_i c_{d,i} + w_m c_{d,m} $$
    where $f_i, c_{d,i}$ are the view-dependent features and diffuse color of voxel $i$, and $f_m, c_{d,m}$ are those of the mesh intersection. [S1, unofficial]

**Pseudocode:**
```python
def hybrid_render(ray_origin, ray_direction, voxel_grid, mesh, depth_buffer):
    # 1. Get mesh intersection depth from depth buffer
    t_max = depth_buffer[ray_origin, ray_direction]
    
    # 2. Ray march through volume
    t = 0.0
    accumulated_color = 0.0
    accumulated_transmittance = 1.0
    accumulated_diffuse_color = 0.0
    accumulated_features = 0.0
    
    while t < t_max and accumulated_transmittance > epsilon:
        # Sample voxel grid at current t
        density, color, diffuse_color, features = voxel_grid.sample(ray_origin + t * ray_direction)
        
        # Volume rendering step
        weight = density * dt # dt is step size
        accumulated_color += weight * color * accumulated_transmittance
        accumulated_diffuse_color += weight * diffuse_color * accumulated_transmittance
        accumulated_features += weight * features * accumulated_transmittance
        accumulated_transmittance *= (1 - weight)
        
        t += dt
        
    # 3. Compute mesh weight
    w_m = 1 - accumulated_transmittance # Remaining transmittance
    
    # 4. Sample mesh if intersection exists
    if t_max is not None:
        mesh_color, mesh_diffuse_color, mesh_features = mesh.sample(ray_origin + t_max * ray_direction)
    else:
        mesh_color = 0.0
        mesh_diffuse_color = 0.0
        mesh_features = 0.0
        
    # 5. Combine contributions
    final_diffuse_color = accumulated_diffuse_color + w_m * mesh_diffuse_color
    final_features = accumulated_features + w_m * mesh_features
    
    # 6. Apply MLP for final color
    final_color = final_diffuse_color + MLP(final_diffuse_color, final_features, t_max)
    
    return final_color
```

**Parameters:**
*   $t_{max}$: Mesh depth from rasterization [S2].
*   $\epsilon$: Transmittance threshold for early ray termination [S1, unofficial][S2].
*   MLP: A small neural network for view-dependent shading [S1, unofficial].

**Edge Cases:**
*   **No Mesh Intersection:** If a ray does not intersect the mesh, $w_m = 0$ and only volume rendering contributes [S1, unofficial][S2].
*   **Precision:** Floating-point precision issues may arise when $t$ is very close to $t_{max}$ [G].

## Operating characteristics
*   **Time Complexity:** Reduced compared to full volume rendering because ray marching is truncated at the mesh surface [S1, unofficial].
*   **Memory Complexity:** Requires storage for both voxel grid and mesh [S1, unofficial][S2].
*   **Strengths:** High fidelity for surface details via mesh; efficient for complex scenes with simple geometry [S1, unofficial][S2].
*   **Limitations:** Requires a pre-existing or co-optimized mesh; may struggle with highly transparent volumes that occlude the mesh [S1, unofficial][S2].

## Background
*   **Origin:** Introduced in "Voxel-Mesh Hybrid Representation for Real-Time View Synthesis" (2024) as "Vosh rendering" [S1, unofficial]. Also discussed in "Neural Volumes" (2019) as a hybrid rendering technique [S2].
*   **History:** Developed to address the computational cost of ray marching in volume rendering by leveraging existing mesh representations [S1, unofficial][S2].
*   **Usage:** Used in real-time view synthesis and dynamic scene rendering [S1, unofficial][S2].
