# Hybrid Volume-Surface Rendering

Also called: Tri-MipRF Hybrid Rendering

## Overview
A rendering strategy combining volume rendering with a rasterized proxy mesh to boost speed by determining a rough distance to the object [S1]. It enables real-time performance on consumer hardware by reducing the number of volume samples required per pixel [S1]. Unlike pure volume rendering, it uses surface geometry to guide sampling; unlike pure surface rendering, it retains volumetric appearance details [S1].

## How it works
**Inputs:**
- A reconstructed density field (implicit volume) [S1].
- Camera parameters (position, orientation, intrinsics) [S1].
- A cone-casting configuration (pixel footprint) [S1].

**Outputs:**
- Final pixel color [S1].

**Data Structures:**
- **Proxy Mesh:** A triangle mesh generated from the density field.
  - *Generation:* Marching Cubes applied to the density field, followed by mesh decimation [S1].
  - *Properties:* High-fidelity quality, capturing complicated structure details [S1].
- **Sampling Interval:** Defined by $\Delta t$ [S1].

**Steps:**
1. **Proxy Mesh Generation:** Generate a proxy mesh by applying marching cubes on the reconstructed density field followed by mesh decimation [S1].
2. **Cone Axis Hit Detection:** For each pixel, define the central axis of the viewing cone. Rasterize the proxy mesh to obtain the hit point on the surface for this central axis [S1].
3. **Sphere Sampling:** Uniformly sample spheres within a distance of $\Delta t$ from the hit point along the central axis of the cone [S1].
   - This yields a $2\Delta t$ sampling interval centered on the surface hit [S1].
   - The occupied area of these sampling spheres connects the rendering distance and resolution, preventing blurring in close-up views and aliasing in distant views [S1].
4. **Volume Rendering:** Evaluate the volume density and radiance at the sampled sphere locations using the underlying radiance field (e.g., Tri-MipRF) [S1].
5. **Compositing:** Composite the sampled values along the cone axis to produce the final pixel color [S1].

**Parameters:**
- $\Delta t$: Sampling distance parameter. Typical values are not explicitly given in the sources, but the method relies on it to define the $2\Delta t$ interval [S1].
- Mesh Decimation Level: Not specified, but required to balance proxy mesh fidelity and rasterization speed [S1].

**Edge Cases and Pitfalls:**
- **Precision:** The method relies on accurate rasterization of the proxy mesh to find the central axis hit point. Errors here shift the sampling interval [S1].
- **Boundaries:** The proxy mesh must accurately represent the object's boundary to ensure the sampling interval is correctly positioned relative to the volume [S1].
- **Degenerate Input:** If the density field is empty or the proxy mesh fails to generate (e.g., no isosurface), the method cannot proceed [G].

**Pseudocode:**
```python
def hybrid_volume_surface_render(camera, proxy_mesh, density_field, delta_t):
    """
    Render a frame using hybrid volume-surface strategy.
    
    Args:
        camera: Camera object with position, orientation, and intrinsics.
        proxy_mesh: Triangle mesh generated from density field.
        density_field: Implicit function or grid providing density/radiance.
        delta_t: Sampling distance parameter.
        
    Returns:
        Image buffer.
    """
    image = create_empty_image(camera.resolution)
    
    for pixel in camera.pixels:
        # 1. Define central axis of the cone for this pixel
        cone_axis = pixel.get_ray_direction()
        ray_origin = camera.position
        
        # 2. Rasterize proxy mesh to find hit point on central axis
        hit_point = rasterize_proxy_mesh(proxy_mesh, ray_origin, cone_axis)
        
        # If no hit, fallback to pure volume or background
        if hit_point is None:
            image[pixel] = render_volume_fallback(ray_origin, cone_axis, density_field)
            continue
            
        # 3. Determine sampling interval
        # Sample spheres within distance delta_t from hit point along cone axis
        # This yields a 2*delta_t interval centered at hit_point
        start_dist = -delta_t
        end_dist = delta_t
        num_samples = estimate_num_samples(delta_t, pixel.footprint_area)
        
        samples = []
        for i in range(num_samples):
            # Uniformly sample along the axis
            t = start_dist + (i + 0.5) * (2 * delta_t / num_samples)
            sample_pos = hit_point + cone_axis * t
            samples.append(sample_pos)
            
        # 4. Evaluate volume at sample points
        colors = []
        alphas = []
        for pos in samples:
            density, radiance = density_field.query(pos)
            colors.append(radiance)
            alphas.append(density) # Simplified accumulation
            
        # 5. Composite
        color = composite_volume(colors, alphas)
        image[pixel] = color
        
    return image
```

## Subtopics

### Hybrid Rendering Framework
A rendering framework that integrates volume and surface models into a unified 3D space with correctly sorted depth information for occlusion calculation, using an intelligent switch mechanism to apply appropriate rendering strategies at runtime [S2, unofficial]. It introduces new scene graph node types: volume LOD, Segmental Replacer, Multi-Volume, and Clipping node [S2, unofficial]. The switch mechanism checks indicative parameter values and sets up thresholds to select between surface and volume rendering strategies at runtime [S2, unofficial].

## Operating characteristics
- **Performance:** Achieves 60 FPS on an Nvidia RTX 3060 graphics card [S1]. Enables real-time rendering at >60 FPS on consumer-level GPUs [S1].
- **Complexity:** Significantly reduces the number of volume samples compared to pure volume rendering by restricting sampling to a narrow interval around the surface [S1].
- **Strengths:** Real-time performance on consumer hardware; high-fidelity quality in proxy mesh; anti-aliased volume rendering [S1].
- **Limitations:** Requires generation and maintenance of a proxy mesh; quality depends on proxy mesh fidelity [S1].
- **When to use:** When real-time rendering of high-fidelity volumetric data is required on consumer hardware [S1].
- **When not to use:** When the volume has no clear surface structure or when proxy mesh generation is too costly [G].

## Background
Originated in the Tri-MipRF paper (2023) by the authors of "Tri-MipRF: Tri-Mip Representation for Efficient Anti-Aliasing Neural Radiance Fields" [S1]. The method was developed to enable real-time rendering on consumer-level GPUs by combining the benefits of surface rasterization and volume rendering [S1].
