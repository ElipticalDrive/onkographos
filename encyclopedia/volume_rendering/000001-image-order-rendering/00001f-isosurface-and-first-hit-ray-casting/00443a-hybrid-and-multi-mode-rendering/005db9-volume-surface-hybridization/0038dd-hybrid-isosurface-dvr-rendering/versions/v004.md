# Hybrid Isosurface/DVR Rendering

Also called: Hybrid isosurface rendering, direct volume rendering

## Overview
Hybrid isosurface/DVR rendering is a strategy for viewpoints located inside a volume with a wide field of view, such as virtual colonoscopy, that combines surface rendering for the near wall with direct volume rendering (DVR) for structures behind it [S1, S2, unofficial]. It sets itself apart from pure DVR by explicitly resolving the occluding boundary (e.g., the colon wall) as an isosurface first, then continuing the ray integration through the remaining volume [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A scalar volume dataset $V$, an isosurface value $t$, a ray origin $O$ (inside the volume), and a ray direction $D$.
- Output: A final pixel color $C_{final}$.

**Data Structures:**
- The volume data is typically stored in a hierarchical blocking structure (e.g., bricks or levels) to handle datasets larger than local GPU memory [S2, unofficial].
- A compositing buffer stores the accumulated color and opacity during the DVR phase.

**Steps:**
1. **Isosurface Detection:** March along the ray from the origin $O$ in direction $D$ to find the first intersection with the isosurface defined by value $t$. This can be done using a fixed number of bisection or binary search steps [S1, unofficial].
2. **Surface Rendering:** Render the isosurface at the intersection point. This step typically involves semi-transparent shading to provide surface information [S2, unofficial]. Let the resulting color be $C_{iso}$ and opacity be $\alpha_{iso}$.
3. **DVR Continuation:** Continue ray marching from the isosurface intersection point along the same direction $D$ for the remaining path through the volume.
4. **Unshaded DVR:** Render the volume behind the surface using unshaded DVR [S2, unofficial]. The integration starts with an initial opacity accumulation of $1.0 - \alpha_{iso}$ [S2, unofficial].
5. **Blending:** Composite the surface color and the DVR result.

**Formula:**
The final color is computed by blending the isosurface color $C_{iso}$ with the DVR color $C_{dvr}$ accumulated from the remaining ray segment:
$$ C_{final} = C_{iso} + (1.0 - \alpha_{iso}) \cdot C_{dvr} $$
where $C_{dvr}$ is computed via standard front-to-back alpha blending starting with opacity $1.0 - \alpha_{iso}$ [S2, unofficial].

**Parameters:**
- Isosurface threshold $t$: Depends on the data segmentation.
- Bisection steps: A fixed number is used, which has virtually no impact on performance [S1, unofficial].
- Sampling distance: Typical values mentioned are 1.0 (24 fps) and 5.0 (66 fps) [S1, unofficial].

**Edge Cases and Pitfalls:**
- Small features or silhouettes may require adaptive sampling to handle intersection problems correctly [S1, unofficial].
- Without refinement, sampling artifacts may occur; hiding these artifacts can be achieved using techniques similar to interleaved sampling [S2, unofficial].
- If the dataset is too large for local GPU memory, it must be divided into smaller chunks (bricks), requiring duplication of one plane of voxels between adjacent bricks [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the number of bisection steps for isosurface detection (fixed, low cost) and the remaining ray length for DVR [S1, unofficial].
- **Memory Complexity:** Requires storage for the volume data, potentially divided into bricks if it exceeds GPU memory [S1, unofficial].
- **Performance:** Sampling distance significantly impacts performance; e.g., sampling distance 1.0 yields 24 fps, while 5.0 yields 66 fps [S1, unofficial].
- **Strengths:** Efficiently handles viewpoints inside the volume by resolving the near occluder (wall) with surface rendering and the background with DVR [S1, S2, unofficial].
- **Limitations:** Shading is expensive; adaptive sampling may be needed for small features or silhouettes [S1, unofficial].

## Background
This technique is described in the context of advanced illumination techniques for GPU-based volume raycasting, specifically for scenarios like virtual colonoscopy where the viewpoint is inside the volume [S1, S2, unofficial]. It was presented by Markus Hadwiger from the VRVIS Research Center, Vienna, Austria [S2, unofficial].
