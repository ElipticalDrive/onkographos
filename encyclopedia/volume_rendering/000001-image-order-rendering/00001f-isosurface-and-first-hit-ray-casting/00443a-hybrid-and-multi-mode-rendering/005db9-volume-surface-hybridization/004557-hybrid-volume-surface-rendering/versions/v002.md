# Hybrid Volume-Surface Rendering

Also called: Tri-MipRF Hybrid Rendering

## Overview
A rendering strategy that combines volume rendering with a rasterized proxy mesh to boost speed by determining a rough distance to the object [S1]. It enables real-time performance on consumer hardware by using the surface mesh to guide volume sampling, significantly reducing the number of samples required compared to pure volume methods [S1].

## How it works
**Inputs:**
*   A reconstructed density field (e.g., from a neural radiance field or voxel grid).
*   Camera parameters (position, orientation, intrinsics).
*   A sampling interval parameter $\Delta t$.

**Outputs:**
*   A rendered image pixel color.

**Data Structures:**
*   **Proxy Mesh:** A triangle mesh generated from the density field.
    *   *Generation:* Marching Cubes [S1] applied to the density field, followed by mesh decimation [S1].
    *   *Properties:* High-fidelity quality, capturing complicated structure details [S1].
*   **Cone:** Defined by the camera pixel footprint and the ray direction.
*   **Sampling Spheres:** Uniformly distributed spheres used to sample the volume along the ray.

**Steps:**
1.  **Proxy Mesh Generation:** Generate the proxy mesh from the density field using Marching Cubes and decimation [S1].
2.  **Ray-Cone Intersection:** For each pixel, define a cone originating from the camera center.
3.  **Surface Hit Detection:** Rasterize the proxy mesh to find the hit point on the surface for the central axis of the cone [S1]. Let this hit point be $P_{hit}$ and the distance from the camera to $P_{hit}$ be $d_{hit}$ [S1].
4.  **Volume Sampling Interval Definition:** Define a sampling interval of $2\Delta t$ centered around $P_{hit}$ [S1].
5.  **Sphere Sampling:** Uniformly sample spheres within the distance $\Delta t$ from $P_{hit}$ along the central axis of the cone [S1]. This yields a total sampling interval of $2\Delta t$ [S1].
6.  **Volume Integration:** Evaluate the volume density and color at the centers of these sampled spheres and integrate them along the ray to produce the final pixel color [S1].

**Pseudocode:**
```python
def render_pixel(camera, proxy_mesh, density_field, delta_t):
    # 1. Define the ray cone for the current pixel
    ray_origin = camera.position
    ray_direction = camera.get_ray_direction(pixel_uv)
    
    # 2. Rasterize proxy mesh to find the hit point on the central axis
    # This is an efficient GPU rasterization step
    hit_point, distance_hit = rasterize_mesh_hit(proxy_mesh, ray_origin, ray_direction)
    
    # 3. Determine sampling range
    # Sample spheres within distance delta_t from hit_point
    # This yields a 2*delta_t sampling interval
    start_dist = distance_hit - delta_t
    end_dist = distance_hit + delta_t
    
    # 4. Uniformly sample spheres along the ray within the interval
    # The number of samples depends on the desired density of spheres
    # Let N be the number of samples
    samples = []
    for i in range(N):
        t = start_dist + (i + 0.5) * (2 * delta_t / N)
        sample_point = ray_origin + t * ray_direction
        samples.append(sample_point)
        
    # 5. Evaluate volume at sample points and integrate
    color = vec3(0.0)
    alpha_accum = 0.0
    for point in samples:
        density = evaluate_density(density_field, point)
        color_sample, alpha_sample = evaluate_radiance(density_field, point)
        
        # Standard volume rendering integration
        weight = alpha_sample * exp(-sum(alpha_sampled_so_far))
        color += weight * color_sample
        alpha_accum += weight
        
    return color
```

**Parameters:**
*   $\Delta t$: The half-width of the sampling interval around the surface hit point. Typical values are not explicitly given, but the method relies on this being small enough to capture surface details but large enough to cover the volume thickness [S1].
*   $N$: Number of spheres sampled within the $2\Delta t$ interval. Not explicitly given, but implied to be small to achieve real-time performance [S1].

**Edge Cases and Pitfalls:**
*   **Empty Space:** If the ray does not intersect the proxy mesh, the method may fail to sample the volume correctly. The sources do not specify a fallback for non-intersecting rays, though standard volume rendering techniques (e.g., empty space skipping) are implied as necessary for robustness [S1].
*   **Mesh Quality:** The proxy mesh must accurately represent the density field. Poor mesh quality (e.g., from aggressive decimation) can lead to incorrect hit points and thus incorrect sampling intervals [S1].
*   **Precision:** Rasterization of the proxy mesh must be precise enough to determine the hit point accurately [S1].

## Subtopics

### Hybrid Rendering Framework
A rendering framework that integrates volume and surface models into a unified 3D space with correctly sorted depth information for occlusion calculation, using an intelligent switch mechanism to apply appropriate rendering strategies at runtime [S2, unofficial]. It introduces new scene graph node types: volume LOD, Segmental Replacer, Multi-Volume, and Clipping node [S2, unofficial]. The switch mechanism checks indicative parameter values and sets up thresholds to select between surface and volume rendering strategies at runtime [S2, unofficial].

## Operating characteristics
*   **Performance:** Achieves 60 FPS on an Nvidia RTX 3060 graphics card [S1]. Enables real-time rendering at >60 FPS on consumer-level GPUs [S1].
*   **Complexity:** Significantly reduces the number of samples compared to pure volume rendering, thus reducing computational cost [S1].
*   **Strengths:** Real-time performance on consumer hardware; high-fidelity rendering; anti-aliased volume rendering with efficient area sampling (when combined with Tri-Mip encoding) [S1].
*   **Limitations:** Requires generation of a proxy mesh, which adds preprocessing overhead; quality depends on the accuracy of the proxy mesh [S1].
*   **When to use:** When real-time rendering of high-fidelity volume data is required on consumer hardware [S1].
*   **When not to use:** When the density field is too complex to generate an accurate proxy mesh efficiently, or when the highest possible accuracy is required regardless of performance [S1].

## Background
Originated in the Tri-MipRF paper [S1]. The method was developed to address the computational cost of volume rendering by leveraging the efficiency of surface rasterization. It builds on the principles of isosurface detection and ray casting [Parent].
