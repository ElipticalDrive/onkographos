# Cell Rasterisation with Tesselation Shader

Also called: Billboard Splatting with Tesselation, Clustered Grid Cell Rasterisation

## Overview
Cell Rasterisation with Tesselation Shader is an image-order rendering technique for isosurfaces that replaces traditional vertex shaders with a tesselation shader to efficiently rasterize clusters of grid cells as point sprites. It solves the performance bottleneck of rendering large volumes by grouping active cells into clusters, expanding them into individual points, and performing ray-box intersection and volume sampling in the fragment shader. Unlike sibling methods that rely on vertex shaders for individual cell rendering or complex mesh generation, this method leverages hardware tesselation to handle cluster expansion and uses a visibility buffer to cull occluded clusters, providing the same isosurface accuracy as isosurface raycasting with reduced overhead [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A Clustered Grid Cell (CGC) data structure containing metacells and grid cells. Each cluster is represented as a single `GL_PATCHES` primitive. The volume scalar field data is stored in GPU memory.
*   **Output:** A rendered image with isosurface shading, typically via a deferred shading pass using a Geometry Buffer (G-buffer).

**Data Structures:**
*   **Cluster Bound:** The last metacell of each cluster stores the cluster bounding box instead of cell metadata.
*   **Grid Position Storage:** 16 bits per component (x, y, z). This allows representation of a maximum grid size of $128K \times 128K \times 128K$ voxels [S1].
*   **Corner Values:** Two RGBA values per cell are stored to allow interpolation of scalar values in the fragment shader [S1].
*   **Visibility Buffer:** An `RG32UI` texture storing a bit per cluster to indicate visibility status across frames [S1].

**Numbered Steps:**

1.  **Tesselation Shader Expansion:**
    The tesselation shader receives one `GL_PATCHES` primitive per cluster. It expands this patch into individual points representing the cells within the cluster. For each cell, a normal is computed from the stored corner values. This normal is used for back-face culling [S1].

2.  **Culling and Rate Adjustment:**
    Clusters that were culled in the previous frame are rendered at a reduced rate of 1/8, with at most one point per metacell per frame, until they become visible again. This optimization prevents unnecessary computation for occluded geometry [S1].

3.  **Rasterization:**
    The expanded points are rasterized as point sprites (billboards). Each fragment corresponds to a potential intersection with the cell's bounding box [S1].

4.  **Ray-Box Intersection:**
    For each rasterized fragment, a ray-box intersection test is performed with the cell. The method uses the efficient slab test described by Majercik et al. [16]. This test determines if the camera ray intersects the cell's bounding box [S1].

5.  **Volume Sampling and Intersection:**
    If an intersection is found, the original volume data is sampled along the ray using tri-linear interpolation to find the isosurface intersection. The method stores corner values (two RGBA values per cell) and performs manual tri-linear interpolation in the fragment shader to determine the exact intersection point and compute smooth attribute interpolation [S1]. Typically, 3 samples per ray are used, which is found sufficient for accuracy [S1].

6.  **Normal Computation:**
    The surface normal is computed from the gradient $\nabla f$ of the volume data at the intersection point. This is achieved by computing the gradient from the interpolated scalar values. The normal is used for shading [S1].

7.  **G-Buffer Rasterization:**
    Cells are rasterized to a Geometry Buffer (G-buffer) containing position, normal, and other attributes. This allows for deferred shading [S1].

8.  **Deferred Shading:**
    In a separate pass, normalized Blinn-Phong shading is computed using the data from the G-buffer. This includes ambient, diffuse, and specular lighting components [S1].

9.  **Visibility Buffer Update:**
    After the cell rasterization pass, the visibility buffer is updated. An `RG32UI` texture captures cluster IDs of visible cells. A compute shader pass clears the current visibility buffer bits and updates them based on the ID texture, marking clusters as visible or occluded for the next frame [S1].

**Pseudocode:**

```python
# Tesselation Shader (per cluster patch)
def tesselation_shader(cluster_patch):
    # cluster_patch contains metadata for a cluster of cells
    cells = cluster_patch.cells
    normals = []
    
    for cell in cells:
        # Compute cell normal from corner values for back-face culling
        # Corner values are stored in the cell metadata
        corner_values = cell.get_corner_values()
        normal = compute_normal_from_corners(corner_values)
        normals.append(normal)
        
        # Emit point for the cell
        emit_point(cell.position, normal)

# Fragment Shader (per rasterized fragment)
def fragment_shader(fragment):
    # fragment contains the point position and normal from tesselation shader
    
    # 1. Ray-Box Intersection
    # Ray is defined by camera origin and direction through fragment
    ray_origin = camera.get_origin()
    ray_direction = camera.get_direction(fragment.screen_pos)
    
    # Use slab test (Majercik et al.) to check intersection with cell bounding box
    # Cell bounding box is derived from cell position and grid spacing
    cell_bbox = get_cell_bbox(fragment.point_position)
    
    t_min, t_max = slab_test(ray_origin, ray_direction, cell_bbox)
    
    if t_min > t_max or t_max < 0:
        discard() # No intersection
    
    # 2. Volume Sampling
    # Sample volume along the ray segment [t_min, t_max]
    # Typically 3 samples are used
    num_samples = 3
    isosurface_value = 0.5 # Example isovalue
    
    intersection_found = False
    intersection_point = None
    intersection_normal = None
    
    for i in range(num_samples):
        t = lerp(t_min, t_max, i / (num_samples - 1))
        sample_point = ray_origin + ray_direction * t
        
        # Manual tri-linear interpolation using stored corner values
        scalar_value = tri_linear_interpolate(sample_point, fragment.point_position)
        
        # Check for isosurface crossing
        if scalar_value >= isosurface_value:
            intersection_point = sample_point
            intersection_found = True
            break
            
    if not intersection_found:
        discard() # No isosurface intersection in this cell
    
    # 3. Normal Computation
    # Compute gradient from interpolated samples
    intersection_normal = compute_gradient(intersection_point)
    intersection_normal = normalize(intersection_normal)
    
    # 4. Write to G-Buffer
    g_buffer.write_position(intersection_point)
    g_buffer.write_normal(intersection_normal)
    g_buffer.write_cluster_id(fragment.cluster_id)

# Visibility Buffer Update (Compute Shader)
def update_visibility_buffer():
    # Read cluster IDs from G-buffer or ID texture
    visible_clusters = read_cluster_ids_from_g_buffer()
    
    # Clear current visibility buffer
    visibility_buffer.clear()
    
    # Update visibility buffer with visible clusters
    for cluster_id in visible_clusters:
        visibility_buffer.set_bit(cluster_id, 1)
```

**Parameters:**
*   **Samples per ray:** 3 [S1].
*   **Grid position bit depth:** 16 bits per component [S1].
*   **Culling rate:** 1/8 for culled clusters [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The 16-bit storage for grid positions limits the maximum grid size to $128K \times 128K \times 128K$ voxels. Larger grids require higher precision or different storage strategies [S1].
*   **Culling:** Culled clusters are rendered at a reduced rate (1/8) to avoid flickering when they re-enter the view. This requires maintaining state between frames [S1].
*   **Intersection Accuracy:** Using only 3 samples per ray may miss thin features or result in discretization artifacts. However, it was found sufficient for the intended use cases [S1].

## Subtopics

### Cell Rasterisation via Billboard Splatting
A variant of the method where active grid cells are rasterized as point sprites (billboards) using a vertex shader instead of a tesselation shader. It performs ray-box intersection and interpolates samples along the ray using stored corner values to find isosurface intersections. It uses 3 samples per ray and computes normals from interpolated samples. This variant is simpler but lacks the cluster-based optimization and visibility buffer culling of the tesselation shader version [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the number of active cells and clusters. The tesselation shader expands clusters into points, and the fragment shader performs ray-box intersection and volume sampling. The visibility buffer reduces the number of clusters processed in subsequent frames.
*   **Memory Complexity:** Requires storage for the CGC data structure, including metacells, grid cells, and corner values. The visibility buffer adds minimal overhead.
*   **Performance:** Provides fast rendering of isosurfaces by leveraging hardware tesselation and deferred shading. The visibility buffer improves performance by culling occluded clusters.
*   **Strengths:** Efficient handling of large volumes, reduced overhead compared to mesh-based methods, accurate isosurface rendering.
*   **Limitations:** Limited by the 16-bit grid position storage, potential discretization artifacts with few samples per ray.
*   **When to use:** Suitable for real-time isosurface rendering of large volumes where performance is critical and the grid size fits within the 16-bit precision limit.
*   **When not to use:** Not suitable for grids larger than $128K^3$ without modification, or when higher precision is required for thin features.

## Background
Cell Rasterisation was proposed by Liu et al. [13] as a fast method for rasterizing active grid cells of a volume. The technique was later enhanced with the Clustered Grid Cell (CGC) data structure and tesselation shaders to improve performance and reduce overhead. The method builds on the principles of image-order rendering and isosurface detection, integrating visibility buffering and deferred shading for efficient real-time rendering [S1].
