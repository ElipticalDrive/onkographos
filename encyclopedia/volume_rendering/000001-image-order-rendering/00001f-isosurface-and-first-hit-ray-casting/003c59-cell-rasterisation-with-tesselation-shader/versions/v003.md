# Cell Rasterisation with Tesselation Shader

Also called: Billboard Splatting with Tesselation, Clustered Grid Cell Rasterisation

## Overview
Cell Rasterisation with Tesselation Shader is an image-order rendering technique for isosurfaces that replaces traditional vertex shaders with tessellation shaders to efficiently rasterize clusters of grid cells as point sprites [S1]. It solves the performance bottleneck of rendering large volumes by grouping active cells into clusters, expanding them into individual points in the tessellation stage, and performing ray-box intersection and volume sampling in the fragment shader [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A Clustered Grid Cell (CGC) data structure containing metacells and grid cells. Each cluster is represented as a single `GL_PATCHES` primitive [S1]. The volume scalar field data is stored in GPU memory [S1].
*   **Output:** A color buffer with the rendered isosurface and a G-buffer containing geometric attributes (normals, positions) for deferred shading [S1].

**Data Structures:**
*   **Cluster Patch:** A single `GL_PATCHES` primitive per cluster. The tessellation shader expands this into points for each cell in the cluster [S1].
*   **Metacell/Cell Metadata:**
    *   Grid position: 16 bits per component (x, y, z). This limits the maximum representable grid size to $128K \times 128K \times 128K$ voxels [S1].
    *   Corner values: Two RGBA values per cell are stored to allow interpolation of scalar values in the fragment shader [S1].
    *   Cluster Bound: The last metacell of each cluster stores the cluster bounding box instead of cell metadata [S1].
*   **Visibility Buffer:** An `RG32UI` texture storing a bit per cluster to indicate visibility status across frames [S1].

**Algorithm Steps:**

1.  **Tessellation (Cluster Expansion):**
    The tessellation shader receives one `GL_PATCHES` primitive per cluster. It iterates through the cells defined in the cluster's metadata. For each active cell, it generates a point primitive [S1].
    *   **Cell Normal Computation:** The tessellation shader computes a normal vector for the cell using the stored corner scalar values. This normal is used for back-face culling [S1].
    *   **Culling:** If the cell is back-facing relative to the camera, it is discarded [S1].

2.  **Rasterization (Billboard Splatting):**
    The generated points are rasterized as billboards (point sprites). The size of the billboard corresponds to the cell's spatial extent [S1].
    *   **Reduced Rate Rendering:** Clusters that were culled in the previous frame are rendered at a reduced rate (1/8) with at most one point per metacell per frame until they become visible again [S1].

3.  **Fragment Shader (Ray-Box Intersection):**
    For each rasterized fragment of the billboard:
    *   **Ray Definition:** Define the view ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ originating from the camera [G].
    *   **Ray-Box Intersection:** Perform a ray-box intersection test between the view ray and the cell's bounding box. The implementation uses the efficient slab test described by Majercik et al. [S1]. If no intersection occurs, the fragment is discarded [S1].
    *   **Intersection Point:** Calculate the entry and exit points of the ray within the cell's bounding box [G].

4.  **Volume Sampling and Isosurface Detection:**
    *   **Interpolation:** Sample the scalar field $f(\mathbf{p})$ along the ray segment inside the cell. The scalar values are obtained by manually performing tri-linear interpolation using the stored corner values in the fragment shader [S1].
    *   **Sample Count:** The method uses a fixed number of samples per ray. The sources specify that 3 samples per ray are used, which was found sufficient for accurate intersection detection [S1].
    *   **Intersection Check:** Detect the isosurface intersection where $f(\mathbf{p}) = \tau$ (threshold). This is typically identified by a sign change or threshold crossing between consecutive samples [G].

5.  **Normal Computation:**
    *   Compute the gradient $\nabla f$ at the intersection point using the tri-linearly interpolated scalar values. This gradient serves as the surface normal for shading [S1].

6.  **G-Buffer Writing:**
    *   Rasterize the cell's geometric attributes (position, normal) to a Geometry Buffer (G-buffer) [S1].

7.  **Deferred Shading:**
    *   In a separate pass, compute normalized Blinn-Phong shading using the data from the G-buffer [S1].

**Pseudocode:**

```python
def lerp(a, b, t):
    return a + (b - a) * t

def vec3(x, y, z):
    return (x, y, z)

def dot(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def normalize(v):
    mag = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    return (v[0]/mag, v[1]/mag, v[2]/mag)

def slab_test(ray_origin, ray_dir, box_min, box_max):
    t_min = max((box_min[i] - ray_origin[i]) / ray_dir[i] for i in range(3))
    t_max = min((box_max[i] - ray_origin[i]) / ray_dir[i] for i in range(3))
    if t_min > t_max or t_max < 0:
        return False, 0.0, 0.0
    return True, t_min, t_max

def tri_linear_interpolate(p, corners):
    x, y, z = p
    c000, c100, c010, c110, c001, c101, c011, c111 = corners
    c00 = lerp(c000, c100, x)
    c10 = lerp(c010, c110, x)
    c01 = lerp(c001, c101, x)
    c11 = lerp(c011, c111, x)
    c0 = lerp(c00, c10, y)
    c1 = lerp(c01, c11, y)
    return lerp(c0, c1, z)

def compute_gradient_at_point(p, corners):
    eps = 1e-3
    fx = (tri_linear_interpolate((p[0]+eps, p[1], p[2]), corners) - tri_linear_interpolate((p[0]-eps, p[1], p[2]), corners)) / (2 * eps)
    fy = (tri_linear_interpolate((p[0], p[1]+eps, p[2]), corners) - tri_linear_interpolate((p[0], p[1]-eps, p[2]), corners)) / (2 * eps)
    fz = (tri_linear_interpolate((p[0], p[1], p[2]+eps), corners) - tri_linear_interpolate((p[0], p[1], p[2]-eps), corners)) / (2 * eps)
    return normalize(vec3(fx, fy, fz))

def compute_cell_normal_from_corners(corners):
    center = vec3(0.5, 0.5, 0.5)
    return compute_gradient_at_point(center, corners)

def tessellation_shader(cluster_patch):
    for cell in cluster_patch.cells:
        normal = compute_cell_normal_from_corners(cell.corners)
        if dot(normal, camera_view_direction) > 0:
            continue
        emit_point(cell.position, cell.size, normal)

def fragment_shader(point_sprite):
    ray_origin = camera_origin
    ray_dir = normalize(camera_view_direction)
    hit, t_entry, t_exit = slab_test(ray_origin, ray_dir, point_sprite.bbox_min, point_sprite.bbox_max)
    if not hit:
        return
    num_samples = 3
    samples = []
    for i in range(num_samples):
        t = lerp(t_entry, t_exit, i / (num_samples - 1))
        p = (ray_origin[0] + t * ray_dir[0], ray_origin[1] + t * ray_dir[1], ray_origin[2] + t * ray_dir[2])
        scalar = tri_linear_interpolate(p, point_sprite.corners)
        samples.append((p, scalar))
    intersection_found = False
    intersection_point = None
    intersection_normal = None
    threshold = 0.0
    for i in range(len(samples) - 1):
        p1, s1 = samples[i]
        p2, s2 = samples[i+1]
        if (s1 - threshold) * (s2 - threshold) < 0:
            t_refine = (threshold - s1) / (s2 - s1)
            intersection_point = (lerp(p1[0], p2[0], t_refine), lerp(p1[1], p2[1], t_refine), lerp(p1[2], p2[2], t_refine))
            intersection_normal = compute_gradient_at_point(intersection_point, point_sprite.corners)
            intersection_found = True
            break
    if not intersection_found:
        return
    write_gbuffer(intersection_point, intersection_normal)
```

**Parameters:**
*   **Samples per ray:** 3 [S1].
*   **Grid Position Storage:** 16 bits per component [S1].
*   **Culling Rate:** 1/8 for previously culled clusters [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The 16-bit storage for grid positions limits the maximum grid resolution to $128K^3$ [S1].
*   **Culled Clusters:** To avoid flickering, culled clusters are rendered at a reduced rate rather than being completely skipped [S1].
*   **Sample Sufficiency:** Only 3 samples are used; this may lead to aliasing or missed intersections in highly detailed regions, though the source claims it is sufficient for their use case [S1].

## Subtopics

### Cell Rasterisation via Billboard Splatting
A variant of the method that uses a vertex shader instead of a tessellation shader to render active grid cells as `GL_POINTS` primitives [S1]. It performs ray-box intersection and interpolates samples along the ray using stored corner values (two RGBA values per cell) to find intersections and compute normals [S1]. It uses 3 samples per ray [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the number of active cells and clusters. The tessellation shader expands clusters, and the fragment shader performs a fixed number of samples (3) per ray. The use of a visibility buffer reduces redundant rasterization of occluded clusters [S1].
*   **Memory Complexity:** Requires storage for the CGC data structure, including 16-bit grid positions and corner values for each cell [S1].
*   **Performance:** Fast due to hardware rasterization of point sprites and deferred shading [S1].
*   **Strengths:** High performance for large volumes; leverages GPU hardware rasterization; deferred shading allows for efficient lighting calculations [S1].
*   **Limitations:** Limited to 16-bit grid positions; fixed sample count may affect accuracy; requires a visibility buffer for optimal performance [S1].
*   **When to use:** Real-time isosurface rendering of large volumes where performance is critical and moderate accuracy is acceptable [S1].
*   **When not to use:** When high precision is required (e.g., scientific visualization requiring sub-voxel accuracy) or when grid sizes exceed $128K^3$ [S1].

## Background
Cell Rasterisation was proposed by Liu et al. [13] as a fast method for rasterizing active grid cells of a volume [S1]. The technique was originally implemented using vertex shaders for billboard splatting [S1]. The variant using tessellation shaders and the Clustered Grid Cell (CGC) data structure was developed to improve performance by reducing the number of draw calls and leveraging the tessellation pipeline for cluster expansion [S1]. The method is part of the broader family of image-order rendering techniques for isosurfaces [S1].
