# Differential Sampling and Peak Finding

Also called: Adaptive Surface Detection, Peak Finding, Surface Ray Marching, Surface Raycasting with Adaptive Step Size

## Overview
Differential Sampling and Peak Finding is a volume rendering technique that combines adaptive ray sampling with explicit root-finding to render sharp, Dirac-like features in transfer functions as semi-transparent isosurfaces [S1]. Unlike standard postclassification or preintegration methods, which struggle with high-frequency transfer function features due to undersampling or incorrect integration assumptions, this method solves directly for the roots of the transfer function to locate isosurface intersections [S1]. It sets itself apart by using a 2D lookup table to query potential peak isovales within a ray segment and employing a secant method for precise intersection detection, allowing for correct shading and opacity handling of narrow-band features [S1].

## How it works
The method operates on a per-pixel ray basis, traversing the volume domain and detecting intersections with specific isovalue peaks defined by the transfer function's opacity component.

### Inputs and Outputs
*   **Inputs**:
    *   Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ in world space.
    *   Scalar volume data $V$.
    *   Transfer function $\rho_\alpha(f)$, mapping scalar values to opacity.
    *   Isosurface threshold (peak isovalue) $\upsilon$.
    *   Lookup table `peakTable` mapping field value ranges to peak isovales.
    *   Parameters: `termination_alpha`, `invalid_flag`, initial step size `b`, adaptive step increment `a`.
*   **Outputs**:
    *   Final pixel color and opacity.

### Data Structures
*   **Globals**:
    *   `ps0`, `ps1`: `vec4` representing position $(x, y, z, t)$ at the start and end of the current ray segment.
    *   `fs0`, `fs1`: `float` representing the scalar field values $f(\mathbf{p})$ at `ps0` and `ps1`.
    *   `dt`: `float` representing the step size parameter.
    *   `iso`: `float` representing the isovalue retrieved from the lookup table.
*   **Lookup Table (`peakTable`)**:
    *   A 2D texture (or array) indexed by `float2(fs0, fs1)`.
    *   Each entry stores an isovalue $\upsilon$ (or a set of up to four sequential isovales $\upsilon_i$) that corresponds to a local maximum in the opacity component of the transfer function within the range $[f_i, f_o]$.
    *   Entries are sorted from first to last peak value encountered on the segment.
    *   If no peak exists, the entry contains `invalid_flag`.
    *   Discretization resolution: Typically 128 bins per dimension [S1].

### Algorithm Steps

1.  **Initialization**:
    *   Set `dt = b`.
    *   Set `ps1.w = 0` (time/parameter $t$).
    *   Set `ps1.xyz = ray.origin`.
    *   Compute `fs1 = volume_filter(ps1.xyz)`.

2.  **Main Ray Casting Loop**:
    *   Copy `ps1` to `ps0` and `fs1` to `fs0`.
    *   Advance position: `ps1.xyz += dt * ray.direction`.
    *   Update time: `ps1.w += dt`.
    *   **Differential Sampling**: If `DIFFERENTIAL_SAMPLING` is enabled, increment `dt` by `a` (adaptive step size adjustment based on image plane frequency) [S1].
    *   Compute current sample: `fs1 = volume_filter(ps1.xyz)`.

3.  **Peak Lookup**:
    *   If `!DVR_ONLY`, sample `peakTable` using `float2(fs0, fs1)`.
    *   Let the result be `iso`.
    *   If `iso != invalid_flag`, a potential peak exists in this segment.

4.  **Root Solving (Peak Finding)**:
    *   If a peak is found, perform root finding to locate the exact intersection.
    *   Define the implicit function $g(t) = f(\mathbf{R}(t)) - \upsilon$.
    *   Evaluate endpoints: $f_0 = fs0 - \upsilon$, $f_1 = fs1 - \upsilon$.
    *   **Descartes' Rule of Signs**: Check if the segment contains a root. (Note: The source pseudocode uses a sign change check `f0 * f1 < 0` as a proxy for root existence in the bisection context, but the text describes using Descartes' rule for robustness. The pseudocode implements a bisection-like secant approach) [S1].
    *   **Secant/Bisection Iteration**:
        *   Initialize bounds: $p_0 = ps0$, $p_1 = ps1$, $f_0 = fs0 - \upsilon$, $f_1 = fs1 - \upsilon$.
        *   Iterate $k$ from 0 to 1 (2 iterations) [S1]:
            *   Compute intermediate point using secant formula:
                $$ \mathbf{p}_{rt} = \mathbf{p}_0 - (\mathbf{p}_1 - \mathbf{p}_0) \frac{f_0}{f_1 - f_0} $$
            *   Evaluate field at intermediate point: $f_{rt} = \text{volume\_filter}(\mathbf{p}_{rt}.xyz) - \upsilon$.
            *   Update bounds:
                *   If $f_{rt} \cdot f_0 < 0$: Set $\mathbf{p}_1 = \mathbf{p}_{rt}$, $f_1 = f_{rt}$.
                *   Else: Set $\mathbf{p}_0 = \mathbf{p}_{rt}$, $f_0 = f_{rt}$.
            *   Recompute $\mathbf{p}_{rt}$ using the updated bounds.
    *   **Final Sample**:
        *   Set $f_{rt} = 0$ (assume the value is exactly the isovalue to avoid Moiré patterns) [S1].
        *   Set `dt = 1.0` (constant opacity scaling) [S1].
        *   Call `dvr_sample(p_rt, f_rt, dt)`.

5.  **Volume Rendering Sample (DVR)**:
    *   If `!PEAK_ONLY` (or if `PEAK_XOR_DVR` is set and no peak was found), call `dvr_sample(ps1, fs1, dt)`.
    *   This performs standard front-to-back compositing for the segment.

6.  **Termination**:
    *   If accumulated `color.a > termination_alpha`, break loop.

### Edge Cases and Pitfalls
*   **Moire Patterns**: Evaluating the field $f(\mathbf{R}(t))$ at the root estimate can cause Moire patterns with sharp transfer functions. The method assumes the value is exactly the isovalue ($\upsilon$) at the hit point to avoid this [S1].
*   **Opacity Scaling**: Standard DVR scales opacity by segment distance $\Delta t$. Peak finding uses a constant $\Delta t = 1.0$ to ensure correct opacity regardless of sampling rate [S1].
*   **Multiple Peaks**: If multiple peaks exist in a segment, the lookup table stores up to four sequential peaks. The algorithm must sequentially perform peak finding for each value [S1].
*   **Sign Change Detection**: The pseudocode uses a simple sign change check (`f0 * f1 < 0`). The text mentions Descartes' rule of signs for robustness. Implementers should be aware that simple sign changes may miss roots if the function touches the axis without crossing, though for transfer function peaks, crossing is typical [S1].

## Operating characteristics
*   **Time Complexity**: Building the lookup table is $O(N^2)$, where $N$ is the number of bins in the transfer function discretization [S1].
*   **Memory Complexity**: Requires a 2D lookup table. A coarser resolution (128 bins) is often sufficient, reducing memory compared to preintegration tables which require larger resolutions for comparable quality [S1].
*   **Performance**:
    *   Building the peak-finding table is roughly twice as fast as building a preintegrated table at the same resolution [S1].
    *   Heptane fire scene (1024x900): Peak finding renders at 7.1 fps, postclassification at 11.6 fps, preintegration at 8.8 fps [S1].
    *   Zebrafish optic tract (1600x512): Peak finding at 2.1 fps, Preintegration at 2.0 fps, Semi-transparent isosurfacing at 4.3 fps [S1].
    *   Finding multiple peaks costs roughly 20% more performance [S1].
*   **Strengths**:
    *   Correctly renders sharp, Dirac-like features in transfer functions as semi-transparent isosurfaces [S1].
    *   Avoids Moire patterns and incorrect opacity integration associated with preintegration and postclassification for high-frequency features [S1].
    *   Supports different rendering modalities (PEAK_ONLY, DVR_ONLY, PEAK_XOR_DVR) with no code overhead [S1].
*   **Limitations**:
    *   Introduces bias by assuming discrete impulses for the integral, which may not be ideal for smooth transfer functions where preintegration excels [S1].
    *   Requires construction of a 2D lookup table, which adds preprocessing time (though faster than preintegration) [S1].
*   **When to Use**: Use when rendering data with sharp, narrow-band transfer function features (e.g., noisy medical data, entropic data) that standard DVR or preintegration fails to reproduce correctly [S1].
*   **When Not to Use**: Use standard DVR or preintegration for smooth transfer functions where high-frequency features are not critical, or when performance is paramount and sharp features are not present [S1].

## Background
The method was introduced by Knoll et al. in "Volume Ray Casting with Peak Finding and Differential Sampling" [S1]. It addresses the limitations of postclassification and preintegration volume rendering when dealing with transfer functions containing sharp features approaching Dirac impulses. The technique combines concepts from isosurface ray casting (root solving) and volume rendering (compositing), using a 2D lookup table similar to preintegration but storing peak isovales instead of integrated radiance. It also incorporates differential sampling based on Igehy's ray differentials to respect the Nyquist frequency of the image plane [S1].
