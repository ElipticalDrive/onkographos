# Volume on Surface (VoS)

Also called: VoS (Volume on Surface)

## Overview
Volume on Surface (VoS) is a hybrid rendering technique that integrates surface and volume rendering to visualize internal volume structures using conventional surface rendering algorithms [S1, unofficial]. It solves the problem of efficiently displaying internal volume details without the high computational cost of full volume ray casting by mapping volumetric data onto a user-specified iso-surface extracted from the volume grid [S1, unofficial]. Unlike image-based hybrid approaches that use external bounding surfaces or texture mapping, VoS casts rays directly from the faces of the boundary surface during a pre-visualization step, storing results to allow interactive rendering on commodity graphics hardware [S1, unofficial].

## How it works
VoS is a two-step method: (i) Pre-visualization, which maps volume information onto an extracted iso-surface, and (ii) Surface rendering, which renders the surface using the pre-computed data [S1, unofficial].

### Inputs and Outputs
**Inputs:**
*   A regular volume grid of voxels [S1, unofficial].
*   An iso-surface $S$ extracted from the volume grid [S1, unofficial].
*   User-defined transfer functions for color and opacity [S1, unofficial].
*   Rendering parameters: number of cones per vertex, number of observation lines per cone, high-pass filter threshold, and opacity function type [S1, unofficial].

**Outputs:**
*   A rendered image of the iso-surface with internal volume structures visible [S1, unofficial].
*   Pre-computed color values stored at each surface vertex for each observation line [S1, unofficial].

### Data Structures
*   **Iso-surface Geometry:** Iso-surface geometry and other information required by the mapping process are stored in a topological data structure [S1, unofficial].
*   **High-Pass Filtered Volume:** The volume grid is filtered to identify material transitions; values are stored for ray sampling [S1, unofficial].
*   **Vertex Data:** Each vertex $v$ on the iso-surface stores a list of pre-computed colors; for each observation line $r_i$ originating from $v$, a color $C_i$ is stored [S1, unofficial].
*   **Ray Samples:** Each ray is associated with a list of samples, where a sample is a voxel along the ray trajectory whose high-pass filtered value is within a user-specified threshold [S1, unofficial].

### Parameters
*   **Cones:** Virtual cones are defined centered at each vertex, aligned with the vertex normal vector. Cones have equally spaced opening angles [S1, unofficial]. Typical values: 3, 6, or 8 cones per vertex [S1, unofficial]. Example angles: 15°, 45°, 75° [S1, unofficial].
*   **Observation Lines:** Uniformly distributed over the surface of each cone [S1, unofficial]. Typical values: 8 lines per cone [S1, unofficial]. If 4 lines are used, the angle between them is 90° [S1, unofficial].
*   **High-Pass Filter Threshold:** User-specified threshold to determine which voxels are stored as samples [S1, unofficial].
*   **Opacity Function:** Can be intensity-based or position-based [S1, unofficial]. Position-based functions assign opacity based on sample position along the ray to highlight internal or external structures [S1, unofficial].

### Steps

#### 1. Pre-visualization
1.  **Extract Iso-surface:** Extract the iso-surface $S$ from the volume grid. Store geometry and topology in a topological data structure [S1, unofficial].
2.  **Filter Volume:** Apply a high-pass filter to the volume grid to identify material transitions [S1, unofficial].
3.  **Define Observation Lines:** For each vertex $v$ on $S$:
    *   Define $k$ virtual cones centered at $v$ with normal-aligned axes and equally spaced opening angles [S1, unofficial].
    *   For each cone, generate observation lines by uniformly distributing directions over the cone's surface [S1, unofficial]. Let $R = \{r_1, ..., r_k\}$ be the set of all unit vectors pointing outwards from $S$, where $k$ equals the number of cones multiplied by the number of rays cast per cone [S1, unofficial].
4.  **Cast Rays and Store Samples:** For each observation line $r_i \in R$ starting at vertex $v$:
    *   Compute the discrete ray trajectory through the volume using a 3D scanline algorithm [S1, unofficial].
    *   For each voxel along the trajectory, check if its high-pass filtered value is within the user-specified threshold [S1, unofficial].
    *   If yes, store the voxel as a sample in the ray's list [S1, unofficial].
5.  **Compute Colors:** For each ray (observation line) with its list of samples:
    *   Apply the user-defined color and opacity transfer functions to each sample to get $c(i)$ and $\alpha(i)$ [S1, unofficial].
    *   Compute the final color $C$ using Levoy's optical model:
        $$ C = \sum_{i=1}^{N} c(i)\alpha(i) \prod_{j=1}^{i-1} (1 - \alpha(j)) $$
        where $N$ is the number of samples, $c(i)$ is the color of sample $i$, and $\alpha(i)$ is the opacity of sample $i$ [S1, unofficial].
    *   Store $C$ at vertex $v$ associated with observation line $r_i$ [S1, unofficial].

#### 2. Surface Rendering
1.  **Determine Viewer Direction:** For each visible face vertex $v$:
    *   Let $O$ be the viewer position. Compute the unit vector $r_o$ from $O$ to $v$ (pointing towards the viewer) [S1, unofficial].
2.  **Select Observation Line:** Find the observation line $r_i \in R$ such that the dot product $r_i \cdot r_o$ is the largest positive value. This $r_i$ best approximates the viewer's line of sight [S1, unofficial].
3.  **Assign Color:** Attribute the pre-computed color $C_i$ (associated with $r_i$) to vertex $v$ [S1, unofficial].
4.  **Render Faces:** For each face, compute its color as the average of the colors assigned to its vertices. Render all visible faces using standard surface rendering techniques (e.g., hidden element removal, lighting) [S1, unofficial].

import math

def normalize(v):
    mag = math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    return (v[0]/mag, v[1]/mag, v[2]/mag) if mag > 0 else (0, 0, 0)

def cross(a, b):
    return (a[1]*b[2] - a[2]*b[1], a[2]*b[0] - a[0]*b[2], a[0]*b[1] - a[1]*b[0])

def dot_product(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def uniform_distribution_on_cone(position, normal, cone_angle_deg, num_lines):
    lines = []
    cone_angle_rad = math.radians(cone_angle_deg)
    sin_theta = math.sin(cone_angle_rad)
    cos_theta = math.cos(cone_angle_rad)
    up = (0, 1, 0) if abs(normal[1]) < 0.9 else (1, 0, 0)
    u = normalize(cross(normal, up))
    v = cross(normal, u)
    for i in range(num_lines):
        phi = 2 * math.pi * i / num_lines
        dir_vec = (sin_theta * math.cos(phi) * u[0] + sin_theta * math.sin(phi) * v[0] + cos_theta * normal[0],
                   sin_theta * math.cos(phi) * u[1] + sin_theta * math.sin(phi) * v[1] + cos_theta * normal[1],
                   sin_theta * math.cos(phi) * u[2] + sin_theta * math.sin(phi) * v[2] + cos_theta * normal[2])
        lines.append(normalize(dir_vec))
    return lines

def ray_traverse_grid(origin, direction, grid_dims, cell_size=(1.0, 1.0, 1.0)):
    dx, dy, dz = cell_size
    x, y, z = int(math.floor(origin[0] / dx)), int(math.floor(origin[1] / dy)), int(math.floor(origin[2] / dz))
    step_x = 1 if direction[0] > 0 else (-1 if direction[0] < 0 else 0)
    step_y = 1 if direction[1] > 0 else (-1 if direction[1] < 0 else 0)
    step_z = 1 if direction[2] > 0 else (-1 if direction[2] < 0 else 0)

    if direction[0] != 0:
        boundary_x = (x + (1 if step_x > 0 else 0)) * dx
        t_max_x = abs(boundary_x - origin[0]) / abs(direction[0])
        t_delta_x = dx / abs(direction[0])
    else:
        t_max_x = float('inf')
        t_delta_x = float('inf')

    if direction[1] != 0:
        boundary_y = (y + (1 if step_y > 0 else 0)) * dy
        t_max_y = abs(boundary_y - origin[1]) / abs(direction[1])
        t_delta_y = dy / abs(direction[1])
    else:
        t_max_y = float('inf')
        t_delta_y = float('inf')

    if direction[2] != 0:
        boundary_z = (z + (1 if step_z > 0 else 0)) * dz
        t_max_z = abs(boundary_z - origin[2]) / abs(direction[2])
        t_delta_z = dz / abs(direction[2])
    else:
        t_max_z = float('inf')
        t_delta_z = float('inf')

    visited = []
    max_steps = grid_dims[0] * grid_dims[1] * grid_dims[2]
    steps = 0
    while 0 <= x < grid_dims[0] and 0 <= y < grid_dims[1] and 0 <= z < grid_dims[2] and steps < max_steps:
        visited.append((x, y, z))
        steps += 1
        if t_max_x < t_max_y:
            if t_max_x < t_max_z:
                x += step_x
                t_max_x += t_delta_x
            else:
                z += step_z
                t_max_z += t_delta_z
        else:
            if t_max_y < t_max_z:
                y += step_y
                t_max_y += t_delta_y
            else:
                z += step_z
                t_max_z += t_delta_z
    return visited

def compute_ray_color(samples, color_func, opacity_func):
    if not samples:
        return (0, 0, 0)
    final_color = (0.0, 0.0, 0.0)
    accumulated_opacity = 0.0
    for sample in samples:
        c = color_func(sample.value)
        alpha = opacity_func(sample.position_along_ray, sample.value)
        contribution = (c[0]*alpha, c[1]*alpha, c[2]*alpha)
        final_color = (final_color[0] + contribution[0]*(1-accumulated_opacity),
                       final_color[1] + contribution[1]*(1-accumulated_opacity),
                       final_color[2] + contribution[2]*(1-accumulated_opacity))
        accumulated_opacity += alpha * (1 - accumulated_opacity)
    return final_color

# Pre-visualization
def pre_visualization(volume_grid, iso_surface, num_cones, lines_per_cone, threshold, color_func, opacity_func):
    filtered_volume = apply_high_pass_filter(volume_grid)
    vertex_colors = {}
    cone_angles = [15, 45, 75]
    
    for vertex in iso_surface.vertices:
        normal = vertex.normal
        lines = []
        for i in range(num_cones):
            angle = cone_angles[i] if i < len(cone_angles) else (i * 30)
            lines.extend(uniform_distribution_on_cone(vertex.position, normal, angle, lines_per_cone))
        
        for line_index, line_direction in enumerate(lines):
            samples = []
            ray_trajectory = ray_traverse_grid(vertex.position, line_direction, volume_grid.grid_dims)
            for voxel in ray_trajectory:
                if abs(filtered_volume[voxel]) <= threshold:
                    samples.append(voxel)
            color = compute_ray_color(samples, color_func, opacity_func)
            vertex_colors[(vertex, line_index)] = color
    return vertex_colors, lines

# Surface Rendering
def render_surface(iso_surface, vertex_colors, lines, viewer_position):
    for face in iso_surface.faces:
        face_color = (0.0, 0.0, 0.0)
        for vertex in face.vertices:
            viewer_to_vertex = normalize((viewer_position[0]-vertex.position[0], viewer_position[1]-vertex.position[1], viewer_position[2]-vertex.position[2]))
            best_line_index = -1

            color = vertex_colors[(vertex, best_line_index)]

### Edge Cases and Pitfalls
*   **Precision:** Dot product computations for line selection should be performed in hardware for efficiency and precision [S1, unofficial].
*   **Boundaries:** Rays are cast from the surface into the volume; the ray trajectory algorithm must handle volume boundaries and zero direction components correctly [S1, unofficial].
*   **Degenerate Input:** If the iso-surface is empty or the volume grid is invalid, the method fails; valid input data is required [S1, unofficial].
*   **Transfer Function Changes:** If color or opacity functions are modified, the pre-computed colors must be recomputed, but ray casting does not need to be repeated [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Pre-visualization time is proportional to the number of surface vertices, the number of observation lines per vertex, and the number of samples per ray [S1, unofficial]. It is slightly greater than conventional DVR visualization time for small cone counts (e.g., 3 cones, 8 lines) but increases with more cones [S1, unofficial]. Rendering time is fast, comparable to conventional surface rendering, as it involves only dot products and face averaging [S1, unofficial].
*   **Memory Complexity:** Memory usage is proportional to the number of surface vertices and the number of observation lines [S1, unofficial]. For a dataset with 8 cones per vertex and 8 lines per cone, memory usage was close to 32 MB for a small dataset (86x42x59) [S1, unofficial].
*   **Measured Performance:** On a Pentium 4, 3.2 GHz, 1 GB RAM with a chest dataset (120x120x241):
    *   Conventional ray casting (VolView): ~20 seconds [S1, unofficial].
    *   Isosurface rendering (VTK): ~2 fps [S1, unofficial].
    *   VoS (3 cones, 8 lines): Pre-vis 41s, Best Case 0.25s, Worst Case 2.3s, 1.9 fps [S1, unofficial].
    *   VoS (6 cones, 8 lines): Pre-vis 1min 36s, Best Case 0.49s, Worst Case 3.85s, 1.3 fps [S1, unofficial].
    *   VoS (8 cones, 8 lines): Pre-vis 2min 10s, Best Case 0.64s, Worst Case 4.88s, 1.1 fps [S1, unofficial].
*   **Strengths:** Interactive rendering rates on commodity hardware; no camera position issues (unlike keyview-based methods); flexible transfer function updates without re-casting rays [S1, unofficial].
*   **Limitations:** Pre-visualization time can be significant; quality depends on the number of observation lines; only shows internal structures of the extracted iso-surface [S1, unofficial].
*   **When to Use:** When interactive visualization of internal volume structures is required and conventional ray casting is too slow, but full volume rendering is not necessary. Suitable for scenarios where the iso-surface is well-defined and internal details are of interest [S1, unofficial].
*   **When Not to Use:** When the iso-surface is not appropriate for the data, or when external structures are more important than internal ones. Also not suitable if real-time ray casting is required without pre-processing [S1, unofficial].

## Background
VoS was introduced in 2006 by researchers presenting at GRAPP 2006 [S1, unofficial]. It builds on the idea of enhancing surface rendering with volume information, similar to image-based approaches like Chen et al. (2001), but differs by using an internal iso-surface and direct ray casting from faces [S1, unofficial]. The method leverages Levoy's optical model for volume rendering [S1, unofficial].
