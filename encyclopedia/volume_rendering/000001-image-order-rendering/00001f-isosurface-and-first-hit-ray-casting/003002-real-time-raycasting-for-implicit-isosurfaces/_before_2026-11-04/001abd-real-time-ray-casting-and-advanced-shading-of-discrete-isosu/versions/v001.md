# Real-Time Ray-Casting and Advanced Shading of Discrete Isosurfaces

Also called: Real-Time Ray-Tracing for Isosurfaces

## Overview
This method is a real-time rendering pipeline for implicit surfaces defined by a regular volumetric grid of samples, using ray-casting on graphics hardware to directly render the isosurface without intermediate polygonal representation [S1][S2, book]. It solves the problem of rendering very large datasets interactively by combining object-space empty space skipping with image-space deferred shading [S1][S2, book]. It sets itself apart from sibling methods like [Isosurface and first-hit ray casting](20-isosurface-and-first-hit-ray-casting.md) by explicitly employing a two-level hierarchical representation (blocks and bricks) to manage memory and accelerate traversal, and by deferring all shading operations (including curvature-based effects) to image space using tri-cubic filtering for smooth normals [S1].

## How it works
The pipeline consists of three stages: Ray-Casting, Image Space Derivatives, and Image Space Shading [S1].

**Inputs and Outputs:**
*   **Input:** A regularly sampled scalar volume $\rho$, an isovalue $\rho_{iso}$, and camera parameters.
*   **Output:** A final shaded image, plus intermediate floating-point images for intersection positions, gradients, and Hessians [S1].

**Data Structures:**
1.  **Volume Grid:** Regular 3D grid of scalar samples [S1].
2.  **Two-Level Hierarchy:**
    *   **Fine Level (Blocks):** The volume is subdivided into blocks. Each block stores the minimum and maximum scalar values of its constituent voxels [S1][S2, book].
    *   **Coarse Level (Bricks):** The volume is subdivided into bricks (coarse blocks) to fit within graphics memory limits. A dynamic cache texture stores active bricks [S1].
    *   **Macrocells:** A trilevel spatial hierarchy is used for traversal acceleration. It consists of one top-level cell, two intermediate macrocell levels, and the data cells. Each macrocell stores the min/max values of its child cells [S2, book].
3.  **Textures:**
    *   **Cache Texture:** Stores the scalar values of active bricks [S1].
    *   **Position Texture:** A low-resolution texture referencing the positions of bricks in the cache [S1].
    *   **Intermediate Images:** Floating-point textures storing intersection positions, gradient components, and Hessian matrix elements [S1].

**Algorithm Steps:**

1.  **Initialization:**
    *   Determine if the volume fits in graphics memory. If not, initialize the dynamic cache with active bricks [S1].
    *   For each pixel on the screen, generate a ray originating from the eye [S2, book].

2.  **Ray Traversal (Object Space):**
    *   Traverse the ray through the volume using the incremental method by Amanatides and Woo [S2, book].
    *   Use the trilevel macrocell hierarchy to skip empty cells. Examine the min/max values at each macrocell level. If the isovalue $\rho_{iso}$ is not within $[min, max]$, skip the cell or its children [S2, book].
    *   If the ray enters a block (fine level) containing the isosurface, proceed to intersection computation [S1][S2, book].

3.  **Intersection Computation:**
    *   When a voxel containing the isosurface is found, solve for the ray parameter $t$ where the interpolated scalar field equals the isovalue [S2, book]:
        $$ \rho(x_a + t x_b, y_a + t y_b, z_a + t z_b) - \rho_{iso} = 0 $$
    *   Using trilinear interpolation, this equation expands to a cubic polynomial in $t$ [S2, book].
    *   Solve the cubic polynomial in closed form [S2, book].
    *   Examine only roots contained within the cell. If multiple roots exist, select the smallest $t$ (closest to the eye). If no roots exist, the ray misses the isosurface in that cell [S2, book].
    *   **Refinement:** Iteratively refine the hit-point with a constant number of steps to improve accuracy [S1].

4.  **Image Space Derivatives:**
    *   At the exact intersection position, compute the first and second partial derivatives of the scalar volume using tri-cubic filtering [S1].
    *   Store the gradient components (normal) and the Hessian matrix in floating-point images [S1].

5.  **Image Space Shading:**
    *   Use the gradient for surface normals in shading models like Blinn-Phong or tone shading [S1].
    *   Use the Hessian to compute curvature measures (mean and Gaussian curvature) [S1].
    *   Apply curvature-based transfer functions to generate effects such as ridge/valley lines or color mapping [S1].

**Pseudocode:**

```python
def render_volume(volume, isovalue, camera):
    # Initialize intermediate textures
    intersection_img = create_floating_point_texture()
    gradient_img = create_floating_point_texture()
    hessian_img = create_floating_point_texture()
    
    # Setup hierarchy and cache if needed
    hierarchy = build_trilevel_hierarchy(volume)
    cache = DynamicCache(volume) if volume.size > gpu_memory else volume
    
    for each pixel (u, v) in screen:
        ray = camera.generate_ray(u, v)
        
        # Ray Traversal
        hit_point = None
        current_cell = hierarchy.root
        
        while current_cell is not None:
            # Check if isovalue is within cell bounds
            if not (current_cell.min <= isovalue <= current_cell.max):
                current_cell = hierarchy.next_cell(ray, current_cell)
                continue
            
            # If leaf cell (voxel), compute intersection
            if current_cell.is_leaf():
                # Trilinear interpolation polynomial coefficients
                coeffs = compute_cubic_coeffs(ray, current_cell, volume)
                roots = solve_cubic(coeffs)
                
                # Filter valid roots within cell bounds
                valid_roots = [t for t in roots if 0 <= t <= current_cell.max_t]
                
                if valid_roots:
                    t_hit = min(valid_roots) # Closest intersection
                    hit_point = ray.origin + t_hit * ray.direction
                    break
                else:
                    # Missed in this cell, continue traversal
                    current_cell = hierarchy.next_cell(ray, current_cell)
            else:
                # Recurse or move to next sibling based on hierarchy structure
                current_cell = hierarchy.next_cell(ray, current_cell)
        
        if hit_point is not None:
            # Compute derivatives using tri-cubic filtering
            grad = compute_gradient(hit_point, volume)
            hess = compute_hessian(hit_point, volume)
            
            intersection_img[u, v] = hit_point
            gradient_img[u, v] = grad
            hessian_img[u, v] = hess
        else:
            intersection_img[u, v] = None

    # Shading Pass
    output_img = create_texture()
    for each pixel (u, v):
        if intersection_img[u, v] is not None:
            grad = gradient_img[u, v]
            hess = hessian_img[u, v]
            
            normal = normalize(grad)
            curvature = compute_curvature(hess)
            
            # Apply shading model
            color = blinn_phong(intersection_img[u, v], normal, camera)
            color = apply_curvature_transfer_function(color, curvature)
            
            output_img[u, v] = color
        else:
            output_img[u, v] = background_color
            
    return output_img
```

**Parameters:**
*   **Hierarchy Levels:** Trilevel hierarchy (one top-level, two intermediate, data cells) is optimal for average case complexity [S2, book].
*   **Tile Size:** Screen space can be split into tiles (e.g., 32x4 pixels) for dynamic load balancing [S2, book].
*   **Hardware Requirements:** Support for volumetric textures, render-to-texture, and looping in fragment programs (e.g., Shader Model 3.0) [S1].

**Pitfalls:**
*   **Multiple Roots:** Trilinear interpolation results in a cubic polynomial which may have multiple roots or no roots. The algorithm must handle these cases by selecting the closest valid root or skipping the cell [S2, book].
*   **Memory Limits:** The volume may not fit in graphics memory, requiring dynamic caching of bricks [S1].
*   **Precision:** Floating-point precision in intermediate images must be sufficient to store accurate intersection positions and derivatives [S1].

## Operating characteristics
*   **Complexity:** The ray-casting stage has object space complexity. All other computations (derivatives, shading) have image space complexity [S1]. The average complexity of search with a three-level hierarchy is $O(\sqrt{n})$, where $n$ is the volume dimension. The worst-case complexity is $O(n)$ [S2, book].
*   **Performance:** Ray-tracing runtime is expected to be $O(n/p)$ where $n$ is volume dimension and $p$ is number of processors, compared to $O(n^2)$ for z-buffer rendering of marching cubes polygons [S2, book].
*   **Memory:** Storage overhead for the trilevel hierarchy is negligible (< 0.5% of the data size) [S2, book]. Dynamic caching allows rendering volumes larger than GPU memory [S1].
*   **Strengths:** Interactive rendering of very large datasets; advanced shading (curvature, ridges) in real-time; no intermediate polygonal representation [S1][S2, book].
*   **Limitations:** Requires hardware support for volumetric textures and looping; performance depends on data sparsity and hierarchy effectiveness [S1][S2, book].

## Background
The method was introduced by Christoph Schüller, Hans-Peter Seidel, and others in the paper "Real-Time Ray-Casting and Advanced Shading of Discrete Isosurfaces" published in Eurographics 2005 [S1]. It addresses the limitations of existing GPU isosurface rendering approaches, particularly the lack of advanced shading and texture memory usage [S1]. The approach builds on earlier work in GPU ray-casting [KW03] and curvature-based transfer functions [HKG00, KWTM03]. It is used in visualization of levelset computations and other scientific visualization tasks requiring high-quality surface interrogation [S1].
