# GPU-based Volume Sculpting System
Also called: Weiskopf et al.38

## Overview
A texture-based volume rendering system that enables real-time interactive sculpting of volumetric datasets by voxelizing sculpting tools on the GPU via fragment shaders to create a 3D mask [S1]. It solves the problem of interactive volume modification by allowing users to clip, erase, or dig into volumes without complex transfer functions, building on the [Interactive Concave Volume Clipping via GPU Boolean Operations](3592-interactive-concave-volume-clipping-via-gpu-boolean-operatio.md) by providing the mechanism for generating the 3D mask used in subsequent rendering stages.

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric dataset, user interaction (2D point, line segment, or 3D geometry), tool parameters (radius $r$).
*   **Output:** A 3D mask (`SculptMap`) stored as a 3D texture on the GPU, where values indicate visibility or distance to the clipping boundary [S1].

**Data Structures:**
*   **3D Texture (`SculptMap`):** Stores the mask. Values are either binary (1.0 = visible, 0.0 = removed) or Euclidean distances to the closest point on the clipping object to avoid jaggy artifacts [S1].
*   **Proxy Geometric Shader:** Generates a proxy rectangle covering the view frustum or specific tool area to drive fragment shader execution [S1].
*   **Fragment Shaders:** `FSEraser` and `FSClipper` implement the voxelization logic [S1].

**Steps:**
1.  **Initialization:** Process the volumetric dataset and store it as a 3D texture in GPU memory [S1].
2.  **Update (Voxelization):** When the user interacts, the active sculpting tool geometry is voxelized on the GPU. Fragment shaders calculate the distance from each fragment's voxel center to the tool's geometric primitive. If the distance is within the tool's radius $r$, the voxel is marked for removal in the `SculptMap` [S1].
3.  **Drawing:** The rendering pipeline uses the `SculptMap` and clipping planes to render the volume. Fragments are discarded or modified based on the mask values [S1].

**Formulas and Logic:**
*   **Eraser Tool (`FSEraser`):**
    *   Input: 3D mask `SculptMap`, projection plane `ProjPlane`, 2D point $P$ (where $P.z = r$), `PolygonCoord` [S1].
    *   For each fragment, project the 3D texture coordinate `texCoord` to the 2D projection plane:
        $$ \text{PlaneCoordinates} = \frac{\text{mul}(\text{float4}(\text{texCoord.xyz} - 0.5f, 1.0f), \text{ProjPlane})}{\text{PlaneCoordinates.w}} $$
    *   Calculate 2D Euclidean distance $D$ from the projected coordinate to $P$:
        $$ D = \frac{\|\text{PlaneCoordinates.xy} - P.xy\|}{P.z} $$
    *   Update the mask alpha channel if $D$ is smaller than the current value:
        ```python
        if D < Col.a:
            Col.a = D
        ```
    *   [S1]

*   **Clipper Tool (`FSClipper`):**
    *   Input: 3D mask `SculptMap`, `clipPlane`, `PolygonCoord` [S1].
    *   The 2D Clipper defines a line segment on the view plane. The shader calculates the distance of the fragment to this plane/line.
    *   Update the mask alpha channel if the distance is smaller than the current value:
        ```python
        if D < Col.a:
            Col.a = D
        ```
    *   [S1]

**Parameters:**
*   $r$: Tool radius.
*   $P$: 2D point defining the eraser center.
*   `clipPlane`: Plane equation for the clipper.

**Edge Cases and Pitfalls:**
*   Jaggy artifacts can occur if binary masks are used; Euclidean distances are recommended [S1].
*   The system relies on GPU fragment shaders for voxelization, requiring hardware support for 3D textures and fragment shader output blending [S1].

## Subtopics

### [GPU-based Slice Rendering with SculptBuffer](15970-gpu-based-slice-rendering-with-sculptbuffer.md)
A rendering technique that uses the `SculptBuffer` (generated by this system) to render only slices contained in a `ClippedImage` as convex polygons, discarding fragments based on distance to the sculpted boundary. It sets itself apart by integrating real-time geometric modification directly into the rendering pipeline via GPU-based distance lookups.

## Operating characteristics
*   **Time Complexity:** Real-time interaction is achieved by performing voxelization on the GPU via fragment shaders, allowing for interactive tool manipulation [S1].
*   **Memory Complexity:** Requires storage for the volumetric dataset as a 3D texture and the `SculptMap` 3D texture on the GPU [S1].
*   **Strengths:** Enables real-time sculpting operations (clipping, erasing, digging) without complex transfer functions; tools can be changed interactively [S1].
*   **Limitations:** Dependent on GPU capabilities for 3D texture sampling and fragment shader execution; precision of sculpting depends on the resolution of the 3D mask [S1].
*   **When to use:** When interactive, real-time volume modification is required for visualization.
*   **When not to use:** When high-precision, non-voxelized geometric operations are required, or on hardware lacking 3D texture support.

## Background
The system is based on the paradigm proposed by Weiskopf et al. [S1]. It was developed to integrate sculpting tools (2D/3D Eraser, Digger, Clipper) into a texture-based volume rendering system, allowing users to modify volumes interactively by marking voxels for removal via GPU fragment shaders [S1].
