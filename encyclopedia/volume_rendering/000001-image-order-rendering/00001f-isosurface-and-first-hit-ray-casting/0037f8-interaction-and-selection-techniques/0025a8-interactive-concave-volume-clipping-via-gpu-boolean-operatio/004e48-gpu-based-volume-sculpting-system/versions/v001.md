# GPU-based Volume Sculpting System

Also called: Weiskopf et al.38

## Overview
A texture-based volume rendering system that enables real-time interactive sculpting of volumetric datasets by voxelizing geometric tools on the GPU via fragment shaders to generate a 3D mask [S1]. It differs from standard ray casting by decoupling the sculpting operation (mask generation) from the rendering pass, allowing for complex concave clipping and erasing without modifying the underlying scalar field data [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric dataset (stored as a 3D texture on GPU), user interaction parameters (tool type, position, radius/geometry), and the current 3D mask (SculptMap).
*   **Output:** Updated 3D mask (SculptMap) and the final rendered image in the Frame Buffer.

**Data Structures:**
*   **SculptMap:** A 3D texture storing mask values. Values are either binary ($1=$ visible, $0=$ removed) or Euclidean distances to the closest point on the clipping object to avoid jagged artifacts [S1].
*   **Proxy Geometry:** A geometric primitive (e.g., rectangle, plane) representing the tool's interaction area in screen space, processed by a Proxy Geometric Shader.

**Steps:**
1.  **Initialization:** Load the volumetric dataset into a 3D texture on the GPU [S1].
2.  **Tool Voxelization (Update):** When the user interacts, the active sculpting tool (e.g., Eraser, Clipper) is voxelized on the GPU. Fragment shaders process the proxy geometry to mark voxels for removal in the SculptMap [S1].
3.  **Rendering (Drawing):** The volume is rendered using the SculptMap and any clipping planes. Voxels marked in the mask are excluded or blended based on their mask values [S1].

**Pseudocode:**
The following pseudocode implements the `FSEraser` fragment shader logic described in [S1]. It calculates the distance from a fragment to a 2D point $P$ on the projection plane and updates the mask if the distance is within the tool radius.

```python
# FSEraser Fragment Shader Logic
# Inputs:
#   SculptMap: sampler3D, current 3D mask
#   PolygonCoord: sampler2D, texture coordinates for the proxy rectangle
#   P: float3, (x, y) is the 2D point on the projection plane, z is the tool radius r
#   ProjPlane: float4x4, projection matrix mapping voxel coordinates to the projection plane

def FSEraser_fragment_shader(P, ProjPlane, SculptMap, PolygonCoord):
    # 1. Get texture coordinates from the proxy geometry
    # Assuming v2f.Tex0 is the input texture coordinate from the vertex shader
    tex_coord_2d = sample_texture(PolygonCoord, v2f.Tex0)
    
    # 2. Map 3D voxel coordinates to the 2D projection plane
    # Convert normalized texture coordinates (0-1) to world/voxel space (-0.5 to 0.5)
    voxel_pos = float4(tex_coord_2d.xyz - 0.5f, 1.0f)
    
    # Project to plane
    plane_coords = mul(voxel_pos, ProjPlane)
    plane_coords.xyz /= plane_coords.w
    
    # 3. Calculate 2D Euclidean distance from the fragment's projected position to P
    # P.xy is the center of the eraser on the plane, P.z is the radius r
    distance = length(plane_coords.xy - P.xy) / P.z
    
    # 4. Update the mask
    # Read current mask value (stored in alpha channel 'a')
    current_mask = sample_texture(SculptMap, tex_coord_2d.xyz)
    
    # If the distance is less than the current mask value, update the mask
    # This implements the "closest point" logic to avoid jaggy artifacts
    if distance < current_mask.a:
        current_mask.a = distance
        
    return current_mask
```

*Note: The `FSClipper` shader follows a similar structure but uses a clipping plane defined by `clipPlane` instead of a point radius [S1].*

**Edge Cases and Pitfalls:**
*   **Jagged Artifacts:** Using binary masks can cause jagged edges. Using Euclidean distances to the closest point on the clipping object mitigates this [S1].
*   **Precision:** The distance calculation relies on the projection matrix `ProjPlane`. Incorrect projection setup will lead to misaligned sculpting [S1].

## Operating characteristics
*   **Performance:** Real-time interaction is achieved because tools are voxelized on the GPU using fragment shaders, allowing for real-time tool manipulation and volume sculpting operations [S1].
*   **Complexity:** The method offloads the computational burden of voxelization and masking to the GPU, keeping the CPU free for interface handling [S1].
*   **Limitations:** The quality of the sculpted boundary depends on the resolution of the 3D mask texture and the precision of the fragment shader distance calculations [S1].

## Background
The system is based on the paradigm proposed by Weiskopf et al. [S1]. It integrates six sculpting tools (2D/3D Eraser, Digger, Clipper) into a texture-based volume rendering framework [S1].
