# Opacity Peeling
Also called: Rezk-Salama and Kolb method
## Overview
Opacity peeling is an interaction technique that reveals interior hidden spatial structures by iteratively rendering layers of a volume based on accumulated opacity thresholds [S1, S2]. Unlike view-dependent occlusion culling methods that skip intersections, it uses multiple rounds of opacity accumulation to expose layers originally occluded behind rendered surfaces, allowing users to interactively select specific depth layers [S2].
## How it works
**Inputs:** Volume dataset $V$, transfer function $TF$, initial opacity threshold $\tau$, and maximum number of peeling passes $N_{max}$.
**Outputs:** Rendered image showing the selected internal layer.

**Data Structures:**
- Accumulated opacity buffer $A$: A 2D array matching the image resolution, initialized to 0.
- Current pass opacity buffer $P$: A 2D array matching the image resolution, initialized to 0 for each pass.

**Steps:**
1. Initialize accumulated opacity buffer $A$ to zero for all pixels.
2. For pass $k$ from 1 to $N_{max}$:
    a. Initialize current pass buffer $P$ to zero.
    b. For each pixel $(u, v)$ in the image plane:
        i. Cast a ray through the volume along the viewing direction.
        ii. Sample the volume along the ray to compute color $C$ and opacity $\alpha$ at each sample point.
        iii. Perform front-to-back compositing for the current ray, but only accumulate opacity into $P(u,v)$ if the ray's local opacity contribution is within the current peeling context. Specifically, the method accumulates opacity up to a threshold $\tau$. If the accumulated opacity in $P(u,v)$ reaches $\tau$, the ray is considered "peeled" for this layer, and the compositing for this pixel in this pass stops or contributes the final color of that layer segment [S2].
        iv. Note: The exact compositing equation for a single sample is $C_{out} = C_{in} + C_{sample} \cdot \alpha_{sample} \cdot (1 - \alpha_{in})$ and $\alpha_{out} = \alpha_{in} + \alpha_{sample} \cdot (1 - \alpha_{in})$. In opacity peeling, the accumulation is constrained by the threshold $\tau$ to define the "layer" [S2].
    c. Composite the result of pass $k$ into the final image, potentially blending with previous passes or replacing the view depending on the interaction mode.
    d. Update the accumulated opacity buffer $A$ by adding $P$ (or using $P$ to mask subsequent passes) to ensure previously revealed layers are handled correctly in subsequent iterations [S2].
3. Allow user interaction to select the desired layer from the sequence of peeled results.

**Parameters:**
- Opacity threshold $\tau$: Controls the thickness of the peeled layer. Typical values depend on the transfer function's opacity range. Not given in the sources.
- $N_{max}$: Maximum number of passes. Not given in the sources.

**Edge Cases:**
- If the volume has no opacity, no layers are peeled.
- Precision issues may arise if $\tau$ is very small, requiring high-precision accumulation buffers.
- Degenerate input (empty volume) results in no output.

**Pseudocode:**
```python
def opacity_peeling(volume, transfer_function, threshold, max_passes):
    # Initialize buffers
    accumulated_opacity = zeros(image_width, image_height)
    final_image = zeros(image_width, image_height, 3)
    
    for k in range(1, max_passes + 1):
        current_pass_opacity = zeros(image_width, image_height)
        current_pass_color = zeros(image_width, image_height, 3)
        
        for u in range(image_width):
            for v in range(image_height):
                ray = cast_ray(u, v)
                alpha_acc = 0.0
                color_acc = [0.0, 0.0, 0.0]
                
                # Sample along ray
                for sample in ray.samples:
                    density = volume.sample(sample.position)
                    color_sample, alpha_sample = transfer_function(density)
                    
                    # Front-to-back compositing
                    weight = alpha_sample * (1.0 - alpha_acc)
                    color_acc = color_acc + color_sample * weight
                    alpha_acc = alpha_acc + weight
                    
                    # Check if threshold reached for this layer
                    if alpha_acc >= threshold:
                        break
                
                current_pass_color[u, v] = color_acc
                current_pass_opacity[u, v] = alpha_acc
        
        # Composite current pass into final image
        # The exact blending strategy with previous passes is not fully specified in sources [S2]
        # Typically, this might replace the view or blend based on user selection
        final_image = composite(final_image, current_pass_color, current_pass_opacity)
        accumulated_opacity += current_pass_opacity
        
        # User interaction check would occur here to select layer k
        if user_selected_layer(k):
            return current_pass_color
            
    return final_image
```
## Subtopics

### [Brain Peeling](13890-brain-peeling.md)
Brain peeling is a view-independent volume visualization technique designed to reveal interior structures located in the vicinity of the brain surface by removing brain tissue step-by-step in the negative normal direction. Unlike its sibling [Opacity Peeling](8428-opacity-peeling.md), which relies on view-dependent occlusion culling, brain peeling uses a precomputed distance field to discard voxels based on their proximity to the surface, requiring fewer parameters and offering a more reliable exploration of surface-adjacent features like vessels and pathological lesions.

## Operating characteristics
**Time Complexity:** $O(N_{max} \cdot W \cdot H \cdot L)$, where $N_{max}$ is the number of passes, $W \times H$ is the image resolution, and $L$ is the number of samples per ray.
**Memory Complexity:** $O(W \cdot H)$ for the opacity and color buffers.
**Strengths:** Allows interactive selection of internal layers without complex 3D picking [S2]. Single-pass per layer can be efficient if $N_{max}$ is small.
**Limitations:** Requires multiple passes to reveal deep structures, which can be slow for large volumes or high $N_{max}$. Performance depends heavily on the opacity threshold and transfer function.
**When to use:** When users need to explore internal structures by peeling away outer layers interactively.
**When not to use:** When real-time performance is critical and deep structures need to be revealed instantly, or when view-independent peeling is preferred (use Brain Peeling instead).
## Background
Opacity peeling was introduced by Rezk-Salama and Kolb to reveal interior hidden spatial structures in volume rendering pipelines [S1]. It is described as a technique that uses several rounds of opacity accumulation to render layers originally occluded behind other rendered layers, enabling interactive layer selection [S2].
