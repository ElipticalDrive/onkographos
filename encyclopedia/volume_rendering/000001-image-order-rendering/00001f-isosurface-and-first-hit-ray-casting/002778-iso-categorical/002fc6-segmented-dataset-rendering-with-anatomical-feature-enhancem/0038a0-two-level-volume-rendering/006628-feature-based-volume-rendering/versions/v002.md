# Feature-based Volume Rendering

Also called: Feature-based volumetric visualization

## Overview
Feature-based Volume Rendering is a hybrid approach to volumetric flow visualization that reduces occlusion by applying volume rendering to data segmented via an interactive, implicit feature-based approach [S1, unofficial]. It sets itself apart from standard threshold-based methods by using a smooth Degree of Interest (DOI) function to map user-defined interest in n-dimensional attribute space to a continuous $[0,1]$ range, allowing for the compositing of multiple distinct feature objects in a two-level rendering style [S1, unofficial].

## How it works
The method divides the visualization mapping from raw data to the resulting image into three distinct phases [S1, unofficial].

**Inputs and Outputs**
*   **Input:** Raw simulation data (e.g., flow data) with multiple attributes (e.g., velocity, pressure, TKE) and user selections in an n-dimensional attribute space [S1, unofficial].
*   **Output:** A composited image where multiple feature objects are rendered with per-object appearance definitions [S1, unofficial].

**Data Structures**
*   **Degree of Interest (DOI) Function:** A smooth function that maps user interest to the $[0,1]$ range. For every sample point (voxel), a 1D DOI value is assigned [S1, unofficial].
    *   $DOI = 1$: Object of interest (in focus) [S1, unofficial].
    *   $DOI = 0$: Context (not depicted) [S1, unofficial].
    *   Values between 0 and 1 represent the smooth boundary transition [S1, unofficial].

**Steps**

1.  **Interactive Segmentation (Phase 1):**
    The user selects features from the raw data using interactive techniques (e.g., brushing in linked scatterplots or histograms) in the n-dimensional data attribute space. This results in the generation of a smooth DOI function for each selected feature [S1, unofficial].

2.  **Feature Representation Selection (Phase 2):**
    An appropriate volumetric representation model is chosen for the selected features from three available models [S1, unofficial]:
    *   **Isosurface-triplets:** (Details not provided in sources.)
    *   **Feature Volume:** Voxels with non-zero DOI values belonging to a feature are depicted as a volumetric object [S1, unofficial].
    *   **Feature Streamlines:** (Details not provided in sources.)

3.  **Rendering (Phase 3):**
    The entire feature set is rendered using a two-level rendering style. Multiple feature objects are composited into one scene. The appearance of each object is defined on a per-object basis [S1, unofficial].

**Formulas and Parameters**

*   **DOI Value Assignment:**
    Each sample point $p$ is assigned a DOI value $d(p)$ based on user interest.
    $$ d(p) \in [0, 1] $$
    Where $d(p)=1$ indicates full interest and $d(p)=0$ indicates no interest [S1, unofficial].

*   **Opacity Computation (Feature Volume Model):**
    For the feature volume representation, the opacity $\alpha$ of a voxel is computed by a linear ramp from its smooth DOI value $d$ [S1, unofficial]:
    $$ \alpha = d $$

*   **Color Mapping:**
    Object color can be determined in two ways [S1, unofficial]:
    1.  **Unique Color:** A unique color is assigned to each object to improve visual discrimination. Color intensity is used for shading or to depict another data attribute (e.g., velocity) [S1, unofficial].
    2.  **Attribute Mapping:** Color intensity depicts a specific data attribute (e.g., velocity), while the base color identifies the object [S1, unofficial].

**Pseudocode**

```python
import math

def feature_based_volume_rendering(raw_data, user_selections, ray_origin, ray_direction, step_size, image_width, image_height):
    # Phase 1: Generate DOI fields for each feature
    doi_fields = []
    for selection in user_selections:
        # [G] Interactive brushing selects regions in n-dimensional attribute space.
        # We assume a helper creates a smooth DOI field from the selection mask.
        binary_mask = [1.0 if raw_data[i,j,k].matches_criteria(selection) else 0.0 
                       for i in range(raw_data.dim_x) for j in range(raw_data.dim_y) for k in range(raw_data.dim_z)]
        smooth_doi = gaussian_smooth(binary_mask, kernel_size=5)
        max_val = max(smooth_doi) if smooth_doi else 1.0
        doi_fields.append([v / max_val for v in smooth_doi])

    # Phase 2 & 3: Raycast and composite features
    composited_image = [[0.0, 0.0, 0.0, 0.0] for _ in range(image_height * image_width)]
    
    for y in range(image_height):
        for x in range(image_width):
            t = 0.0
            r, g, b, a = 0.0, 0.0, 0.0, 0.0
            accumulated_alpha = 0.0
            
            while t < 100.0:
                pos = [ray_origin[i] + t * ray_direction[i] for i in range(3)]
                doi_val = 0.0
                for field in doi_fields:
                    val = trilinear_sample(field, pos)
                    if val > doi_val: doi_val = val
                
                if doi_val > 0.0:
                    alpha_voxel = doi_val
                    base_color = [1.0, 0.0, 0.0]
                    intensity = trilinear_sample(raw_data.velocity_field, pos)
                    color_voxel = [base_color[i] * intensity for i in range(3)]
                    
                    weight = alpha_voxel * (1.0 - accumulated_alpha)
                    r += color_voxel[0] * weight
                    g += color_voxel[1] * weight
                    b += color_voxel[2] * weight
                    accumulated_alpha += weight
                    
                    if accumulated_alpha > 0.99:
                        break
                t += step_size
            
            composited_image[y * image_width + x] = [r, g, b, accumulated_alpha]
            
    return composited_image

def gaussian_smooth(data, kernel_size):
    smoothed = [0.0] * len(data)
    for i in range(len(data)):
        total_weight = 0.0
        for j in range(-kernel_size, kernel_size + 1):
            if 0 <= i + j < len(data):
                w = math.exp(-0.5 * (j / (kernel_size / 2.0))**2)
                smoothed[i] += data[i + j] * w
                total_weight += w
        smoothed[i] /= total_weight
    return smoothed

def trilinear_sample(field, pos):
    ix, iy, iz = int(pos[0]), int(pos[1]), int(pos[2])
    if not (0 <= ix < field.dim_x and 0 <= iy < field.dim_y and 0 <= iz < field.dim_z):
        return 0.0
    return field[ix, iy, iz]
```

**Edge Cases and Pitfalls**
*   **Ambiguous Representation:** Using non-colored objects can lead to ambiguous representation of unequal features. Unique colors are recommended for object discrimination [S1, unofficial].
*   **Smooth Boundaries:** The method relies on smooth DOI functions. Sharp, discrete thresholds are not used, which requires careful smoothing to avoid visual artifacts at feature boundaries [S1, unofficial].
*   **Occlusion:** The primary motivation is to reduce occlusion problems inherent in raw flow data visualization [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:**
    *   Reduces occlusion in complex flow data [S1, unofficial].
    *   Interactive and intuitive feature specification via brushing [S1, unofficial].
    *   Allows compositing of multiple distinct features with per-object appearance control [S1, unofficial].
    *   Smooth boundaries separate objects in focus from context, while shading improves spatial perception [S1, unofficial].
*   **Limitations:**
    *   Requires user interaction for segmentation; non-interactive approaches may fail due to absence of sharp boundaries [S1, unofficial].
    *   Performance depends on the complexity of the smoothing and rendering of multiple volumes.
*   **When to use:** When visualizing complex flow simulation data where features lack sharp boundaries and occlusion is a significant problem.
*   **When not to use:** When fully automatic, non-interactive segmentation is required.

## Background
The method was proposed by M. Mlejnek in 2003 in the paper "Feature-based Volume Rendering of Simulation Data" [S1, unofficial]. It is part of a hybrid approach to volumetric flow visualization, building on the concept of Degree of Interest (DOI) functions for separating data in focus from context [S1, unofficial].
