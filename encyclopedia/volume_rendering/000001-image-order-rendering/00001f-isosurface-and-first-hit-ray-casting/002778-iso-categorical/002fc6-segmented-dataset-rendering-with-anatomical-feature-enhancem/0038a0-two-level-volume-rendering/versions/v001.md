# Two-level volume rendering

Also called: 2lVR, object-aware volume rendering

## Overview
Two-level volume rendering (2lVR) is an extension of standard 3D visualization that enables object-aware volume rendering by subdividing a volume into distinct "objects" (structures of interest) and assigning individual rendering modes to each [S1, S2, unofficial]. It solves the problem of rendering segmented datasets with high image quality and smooth subvolume boundaries by allowing different transfer functions, shading models, or compositing strategies per object [S2, unofficial]. Unlike standard direct volume rendering which applies a uniform model to the entire dataset, 2lVR distinguishes between volume objects using explicit identity numbers, allowing separate shading and compositing properties for each [S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A segmented volumetric dataset where each voxel contains a basic density value and an explicit object identity number [S2, unofficial].
*   **Output:** A final 2D image where pixels are composited from multiple local object renderings [S1, S2, unofficial].

**Data Structures**
The voxel data structure must contain:
1.  **Density Value:** The basic scalar value of the voxel [S2, unofficial].
2.  **Object Identity Number:** An explicit integer identifier referring to the specific volume object the voxel belongs to [S2, unofficial]. This number acts as a look-up table for shading and compositing properties [S2, unofficial].

**Parameters**
*   **Rendering Modes:** Per-object modes such as direct volume rendering, compositing, maximum-intensity projection (MIP), surface rendering, or non-photorealistic rendering (NPR) of contours [S1, unofficial].
*   **Clipping Parameters:** Per-object clipping planes and parameters for rendering clipped parts (e.g., low opacity or contour-only shading) [S1, unofficial].
*   **Interpolation Method:** Nearest Neighbor interpolation for object identity numbers [S2, unofficial].

**Algorithm Steps**
1.  **Segmentation and Identity Assignment:** Assign an explicit object identity number to every voxel during the segmentation phase [S2, unofficial].
2.  **Ray Casting Initialization:** For each pixel, cast a ray through the volume [S2, unofficial].
3.  **Sample Point Interpolation:** For each sample point along the ray, determine its associated volume object by interpolating the object membership identity numbers from the surrounding voxel identity numbers using Nearest Neighbor interpolation [S2, unofficial].
4.  **Local Rendering Pass:**
    *   Identify sample points associated with the same volume object that are located in a direct neighborhood of the ray section [S2, unofficial].
    *   Shade and composite these sample points using object-specific properties (transfer function, shading model) [S2, unofficial].
    *   If an object is clipped, render the clipped parts using a separate set of rendering parameters (e.g., very low opacity or NPR shading) to provide context [S1, unofficial].
    *   Blend the sample points associated with the same volume object to produce a local color and opacity value for that object [S2, unofficial].
5.  **Global Rendering Pass:**
    *   Combine the renderings of all objects using a global compositing method based on accumulated transparencies [S1, unofficial].
    *   Composite the object opacity and color values from the local pass into the final pixel color [S2, unofficial].

**Pseudocode**
```python
def two_level_volume_rendering(volume_data, ray_origin, ray_direction, object_configs):
    """
    volume_data: 3D array of (density, object_id) tuples.
    ray_origin: 3D vector.
    ray_direction: 3D vector.
    object_configs: Dictionary mapping object_id to rendering parameters (TF, shading, etc.).
    """
    # Initialize global accumulators
    global_color = [0.0, 0.0, 0.0, 0.0]
    
    # List to store local object results along the ray
    local_object_results = []

    # Step 1-3: Ray marching and sample point processing
    t = 0.0
    while t < volume_depth:
        sample_pos = ray_origin + ray_direction * t
        
        # Get voxel data at sample_pos
        density, voxel_id = volume_data.sample(sample_pos)
        
        # Interpolate object identity using Nearest Neighbor
        # [G] In a discrete grid, this is simply the voxel_id of the nearest voxel
        object_id = voxel_id 
        
        # Get rendering config for this object
        config = object_configs.get(object_id)
        if config is None:
            t += step_size
            continue

        # Step 4: Local Rendering Pass
        # Calculate optical properties for this sample point based on object-specific TF
        opacity = config.transfer_function(density)
        color = config.shading_model(density, sample_pos, ray_direction)
        
        # Store local result for this object at this position
        # [G] In a real implementation, we would accumulate these locally per object
        # before the global pass, or store them in a buffer keyed by object_id
        local_object_results.append({
            'object_id': object_id,
            'color': color,
            'opacity': opacity,
            'position': sample_pos
        })
        
        t += step_size

    # Step 5: Global Rendering Pass
    # Group local results by object_id
    objects = {}
    for res in local_object_results:
        oid = res['object_id']
        if oid not in objects:
            objects[oid] = []
        objects[oid].append(res)

    # Composite each object's local result
    # [G] The specific local compositing method (e.g., MIP, DVR) is defined in config
    # Here we assume standard front-to-back compositing for the local pass per object
    for oid, samples in objects.items():
        # Sort samples by depth (t)
        samples.sort(key=lambda s: s['position'])
        
        local_accum_color = [0.0, 0.0, 0.0, 0.0]
        local_accum_opacity = 0.0
        
        for sample in samples:
            c = sample['color']
            o = sample['opacity']
            
            # Local compositing
            alpha = o * (1.0 - local_accum_opacity)
            local_accum_color = local_accum_color + c * alpha
            local_accum_opacity = local_accum_opacity + alpha
            
        # Add this object's contribution to the global composite
        # [G] Standard front-to-back global compositing
        alpha = local_accum_opacity * (1.0 - global_color[3])
        global_color = global_color + local_accum_color * alpha
        global_color[3] = global_color[3] + alpha

    return global_color
```

**Edge Cases and Pitfalls**
*   **Identity Interpolation:** The method relies on Nearest Neighbor interpolation for object identity numbers. Degenerate cases where a ray passes through boundaries between many small objects may require careful handling to ensure correct identity assignment [S2, unofficial].
*   **Performance:** The approach increases computation and time consumption significantly compared to standard volume rendering. Software-based implementations suffer a significant efficiency decrease; a GPU-based approach is necessary for real-time performance [S2, unofficial].
*   **Clipping Context:** Clipping must be handled per-object. Clipped parts need specific rendering parameters (e.g., low opacity) to maintain context, otherwise structures may disappear entirely [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Higher than standard volume rendering due to the two-pass compositing structure and per-object property lookups. The complexity is proportional to the number of sample points and the number of distinct objects intersected by the ray [S2, unofficial].
*   **Memory Complexity:** Requires storing an additional integer (object identity) per voxel alongside the density value, increasing memory footprint [S2, unofficial].
*   **Performance:** On a single CPU, typical visualizations of $256^3$ medical data sets can render up to 35 frames per second [S1, unofficial]. However, software-based applications suffer significant efficiency decreases, making GPU-based approaches necessary for efficient realization [S2, unofficial].
*   **Strengths:** Allows fusion of data from multiple volumes; high flexibility in visualizing different structures with appropriate methods (e.g., MIP for vessels, DVR for tissue); effective per-object clipping [S1, unofficial].
*   **Limitations:** Increased computational cost; requires pre-segmented data with explicit identity numbers; software-only implementations are too slow [S2, unofficial].
*   **When to use:** When rendering segmented datasets where different anatomical features or structures require different visualization techniques (e.g., surface rendering for bones, DVR for soft tissue) and smooth boundaries between segmented objects are desired [S2, unofficial].
*   **When not to use:** For unsegmented data or when computational resources are extremely limited and GPU acceleration is unavailable [S2, unofficial].

## Background
Two-level volume rendering was introduced by H. Hagen, M. B. G. [S1, S2, unofficial]. It was developed to address the limitations of standard volume rendering in handling segmented data, where different objects benefit from different rendering modes [S1, unofficial]. The method forms the foundation for more advanced techniques like Importance-Driven Volume Rendering (IDVR) [S2, unofficial]. It is used in medical visualization applications to enhance the graphical representation of complex anatomical structures by allowing object-specific rendering attributes [S2, unofficial].
