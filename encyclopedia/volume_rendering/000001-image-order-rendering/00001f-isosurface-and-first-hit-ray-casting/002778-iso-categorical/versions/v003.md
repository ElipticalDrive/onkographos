# iso_categorical


## Overview
`iso_categorical` is a volume rendering method for categorical label data that replaces fixed-step ray marching with exact voxel traversal to eliminate sawtooth artifacts at grazing angles [S1, unofficial]. Unlike its parent [Isosurface and first-hit ray casting](20-isosurface-and-first-hit-ray-casting.md), which relies on discrete sampling intervals that may skip thin voxel corners, this method visits every voxel the ray intersects, ensuring the result is independent of the step size and geometrically robust [S1, unofficial]. It solves the problem of visual discontinuities and depth offset errors common in previous implementations of categorical label rendering [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D categorical label volume (integer labels), camera parameters (origin, direction), clipping planes, and a relative step size parameter (historically used for initialization, now irrelevant for correctness).
- Output: The color of the first non-transparent label hit by the ray, and the depth of the entry point into that voxel in data coordinates.

**Data Structures:**
- The volume is stored as a 3D grid of integer labels.
- Ray state includes current position $\mathbf{p}$, direction $\mathbf{d}$, and traversal coordinates $(x, y, z)$ in voxel space.

**Steps:**
1. **Ray Initialization:** Construct the ray from the camera through the pixel center. Apply any global clipping planes to determine the initial entry and exit bounds of the ray within the volume domain.
2. **Ray Shortening:** Shorten the ray segment by a tiny margin $\epsilon$ at both the entry and exit ends. This prevents floating-point rounding errors from reading neighboring voxels when a clipping plane coincides exactly with a voxel boundary [S1, unofficial].
3. **Traversal Start:** Begin traversal at the first unclipped sample point along the ray.
4. **Voxel Traversal:** Use the Amanatides & Woo algorithm to walk through every voxel the ray passes through in order [S1, unofficial].
   - For each voxel, evaluate the clipping planes to determine if the ray enters and leaves the voxel within the valid range.
   - Check the label value at the current voxel.
5. **Hit Detection:** Stop at the first voxel with a non-transparent label.
6. **Depth Calculation:** Set the pixel's depth to the point where the ray enters the hit voxel, expressed in data coordinates. This ensures correct occlusion relative to other layers, avoiding the half-voxel shift error present in older implementations where depth was calculated as $iloc \times u\_shape$ [S1, unofficial].
7. **Shading:** Compute the color of the hit voxel based on the label value and the rendering mode (e.g., flat color, gradient-based).

**Pseudocode:**
```python
def render_iso_categorical(ray_origin, ray_direction, volume, clipping_planes, epsilon=1e-6):
    # 1. Initialize ray bounds
    t_min, t_max = get_ray_volume_bounds(ray_origin, ray_direction, volume.shape)
    
    # Apply clipping planes
    for plane in clipping_planes:
        t_min, t_max = clip_ray_with_plane(t_min, t_max, ray_origin, ray_direction, plane)
        
    # 2. Shorten ray to avoid boundary rounding errors
    t_min += epsilon
    t_max -= epsilon
    
    if t_min >= t_max:
        return None, None  # Ray misses volume or is fully clipped

    # 3. Start Amanatides & Woo traversal
    # Initialize traversal state for the ray
    x, y, z = voxel_coordinates(ray_origin + ray_direction * t_min)
    step_x, step_y, step_z = sign(ray_direction)
    t_delta_x, t_delta_y, t_delta_z = abs(1.0 / ray_direction)
    
    # Calculate initial t_max values for crossing voxel boundaries
    if step_x > 0:
        t_max_x = (x + 1 - (ray_origin.x + ray_direction.x * t_min)) / ray_direction.x
    else:
        t_max_x = (x - (ray_origin.x + ray_direction.x * t_min)) / ray_direction.x
    # ... similarly for y and z ...

    t_current = t_min
    
    while t_current < t_max:
        # Determine which boundary is next
        if t_max_x < t_max_y and t_max_x < t_max_z:
            t_current = t_max_x
            x += step_x
            t_max_x += t_delta_x
            current_voxel = (x, y, z)
        elif t_max_y < t_max_z:
            t_current = t_max_y
            y += step_y
            t_max_y += t_delta_y
            current_voxel = (x, y, z)
        else:
            t_current = t_max_z
            z += step_z
            t_max_z += t_delta_z
            current_voxel = (x, y, z)
            
        # Check if current voxel is within clipping bounds
        if not is_within_clipping_planes(ray_origin, ray_direction, t_current, current_voxel):
            continue
            
        # 4. Check label
        label = volume[current_voxel]
        if label is not transparent:
            # 5. Hit found
            # 6. Depth is entry point into this voxel
            depth = t_current
            color = get_label_color(label)
            return color, depth
            
    return None, None
```

**Parameters:**
- `epsilon`: A small value (e.g., $10^{-6}$) to shorten the ray ends [S1, unofficial].
- `relative_step_size`: No longer affects correctness, but may be used for initial ray sampling in some implementations [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Sawtooth Edges:** Fixed-step sampling misses voxels clipped by corners between samples, causing shifting sawtooth artifacts at grazing angles. This method eliminates this by visiting every voxel [S1, unofficial].
- **Depth Offset Error:** Older methods shifted depth by half a voxel, causing incorrect occlusion between layers with different scales. This method uses the exact entry point in data coordinates [S1, unofficial].
- **Clipping Plane Precision:** Without ray shortening, rounding errors can cause reads from neighboring voxels when a plane starts exactly on a boundary [S1, unofficial].

## Subtopics

### translucent_categorical
A variant of `iso_categorical` used when `rendering='translucent'`. It shares the exact voxel traversal logic and depth calculation but differs in how the hit voxel is shaded, allowing for transparency effects [S1, unofficial]. Performance impact is similar to `iso_categorical`, with frame time increases ranging from 1.1x to 1.8x depending on scene density and view angle [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Time complexity increases compared to fixed-step sampling because the traversal visits every voxel along the ray. This cost is higher per visit than a simple sample lookup, especially at oblique angles where a ray crosses more voxels than it took samples in the old method [S1, unofficial].
- Memory complexity is dominated by the volume storage; no additional large structures are required, though a prototype using a coarse map of $8 \times 8 \times 8$ blocks for empty space skipping would require a second texture [S1, unofficial].

**Measured Performance:**
- On an M1 Max with a 2000x1800 px canvas and 256³ volume:
  - Axis-aligned view: 3.6 ms (old) → 4.3 ms (new), 1.2x increase [S1, unofficial].
  - Oblique view: 3.7 ms (old) → 6.3 ms (new), 1.7x increase [S1, unofficial].
  - Empty volume (worst case): 3.7 ms → 6.3 ms [S1, unofficial].
  - Dense labels (300 nuclei): 3.1 ms → 3.4 ms, 1.1x increase [S1, unofficial].
  - Dense labels (1500 nuclei, 512³): 6.7 ms → 7.2 ms, 1.1x increase [S1, unofficial].
- Compared to the old method with a smaller step size (0.4), the new method is as fast or faster (0.66x to 1.0x) while eliminating artifacts [S1, unofficial].
- Dense labels where rays stop almost immediately render in under 1 ms [S1, unofficial].

**Strengths and Limitations:**
- **Strengths:** Eliminates sawtooth artifacts; depth is accurate across different scales; result is independent of step size [S1, unofficial].
- **Limitations:** Higher computational cost per ray due to voxel traversal; performance degrades at oblique angles [S1, unofficial].

## Background
`iso_categorical` is used in the `napari` image viewer for rendering labels layers in 3D, specifically within the `iso_categorical` and `translucent_categorical` methods in `src/napari/_vispy/visuals/volume.py` [S1, unofficial]. The method was introduced to fix visual artifacts in the rendering of categorical data, addressing issues reported in GitHub PR #9674 [S1, unofficial].
