# iso_categorical


## Overview
`iso_categorical` is a volume rendering method designed for categorical label data (segmentations) that replaces fixed-step ray marching with exact voxel traversal to eliminate sawtooth artifacts at grazing angles [S1, unofficial]. Unlike its predecessor which sampled discrete points and missed voxels clipped by ray corners, this method visits every voxel the ray intersects, ensuring geometric correctness independent of step size [S1, unofficial]. It is primarily used in the `napari` viewer for rendering 3D labels layers [S1, unofficial].

## How it works
**Inputs:**
- Categorical volume data (labels).
- Camera ray origin $\mathbf{o}$ and direction $\mathbf{d}$ for each pixel.
- Volume bounding box and voxel dimensions.
- Clipping planes (optional).

**Outputs:**
- Color of the first non-transparent label encountered.
- Depth value corresponding to the entry point of the hit voxel.

**Data Structures:**
- The volume is treated as a regular grid. No acceleration structures (like VDB or sparse voxel octrees) are used in the base implementation; traversal is linear along the ray [S1, unofficial].

**Algorithm Steps:**
1. **Ray Initialization:** Construct the view ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$. Shorten the ray interval $[t_{min}, t_{max}]$ by a tiny margin $\epsilon$ at both ends to prevent rounding errors from reading neighboring voxels when a clipping plane or boundary aligns exactly with a voxel edge [S1, unofficial].
2. **Initial Marching:** March along the ray using the previous fixed-step logic (default `relative_step_size` = 0.8 voxels) only to find the first unclipped sample point. This determines the starting voxel for the traversal [S1, unofficial].
3. **Voxel Traversal:** From the starting voxel, walk through every subsequent voxel the ray passes through in order using the Amanatides & Woo traversal algorithm [S1, unofficial].
4. **Label Testing:** For each visited voxel, check if the label value is non-transparent.
5. **Termination:** Stop at the first voxel with a non-transparent label.
6. **Clipping Evaluation:** Evaluate clipping planes at the exact entry and exit points of the hit voxel to ensure cut surfaces remain in their correct positions [S1, unofficial].
7. **Depth Assignment:** Set the pixel's depth to the parameter $t$ where the ray enters the hit voxel, expressed in data coordinates. This replaces the old method which used `iloc * u_shape`, causing half-voxel shifts and occlusion errors between layers of different scales [S1, unofficial].

**Pseudocode:**
```python
def render_iso_categorical(ray_origin, ray_direction, volume, volume_shape, voxel_size, clip_planes, epsilon=1e-6):
    """
    Renders a categorical volume using exact voxel traversal.
    
    Args:
        ray_origin: (3,) float array, camera ray origin in world space.
        ray_direction: (3,) float array, normalized camera ray direction.
        volume: 3D array of categorical labels.
        volume_shape: (3,) int array, dimensions of the volume grid.
        voxel_size: (3,) float array, physical size of each voxel.
        clip_planes: List of plane equations (normal, distance) or None.
        epsilon: Small margin to shrink ray bounds.
        
    Returns:
        color: Color of the hit label.
        depth: Entry point of the hit voxel in data coordinates.
    """
    # 1. Define ray bounds in world space
    # Assuming volume is axis-aligned and centered or at origin for simplicity
    # In practice, transform ray to volume/local space or transform bounds to world space
    vol_min = volume_origin # Defined by volume metadata
    vol_max = vol_min + volume_shape * voxel_size
    
    # Calculate t_min and t_max for the volume bounds
    t_min, t_max = intersect_box(ray_origin, ray_direction, vol_min, vol_max)
    
    if t_min > t_max:
        return transparent_color, 0.0
        
    # Shorten ray by epsilon to avoid boundary rounding errors
    t_min += epsilon
    t_max -= epsilon
    
    if t_min > t_max:
        return transparent_color, 0.0

    # 2. Initial marching to find start voxel (simplified for logic flow)
    # The source describes marching with relative_step_size to find the first unclipped sample.
    # We convert this to a starting t value.
    step_size_voxels = 0.8
    step_size_world = step_size_voxels * mean(voxel_size)
    
    t_current = t_min
    start_voxel = None
    
    # Find first voxel to enter traversal
    while t_current < t_max:
        pos = ray_origin + t_current * ray_direction
        voxel_idx = world_to_voxel(pos, volume_origin, voxel_size)
        
        # Check if voxel is within bounds and unclipped
        if is_within_bounds(voxel_idx, volume_shape) and not is_clipped(pos, clip_planes):
            start_voxel = voxel_idx
            break
        t_current += step_size_world
        
    if start_voxel is None:
        return transparent_color, 0.0

    # 3. Amanatides & Woo Traversal
    # Initialize traversal parameters for the starting voxel
    t_max_x, t_max_y, t_max_z = compute_t_max(start_voxel, ray_direction, volume_origin, voxel_size)
    t_delta_x, t_delta_y, t_delta_z = compute_t_delta(ray_direction, volume_origin, voxel_size)
    
    current_voxel = start_voxel
    
    while True:
        # Check if current voxel is within volume bounds
        if not is_within_bounds(current_voxel, volume_shape):
            break
            
        # 4. Label Testing
        label = volume[current_voxel]
        if label != transparent_label:
            # 5. Termination
            # 6. Clipping Evaluation (ensure the hit point is valid relative to clips)
            hit_pos = ray_origin + (current_voxel_to_world_entry(current_voxel, ray_direction, volume_origin, voxel_size)) * ray_direction
            
            # If the entry point is clipped, we might need to continue or handle edge case
            # The source implies clipping planes are evaluated to keep cut surfaces correct.
            # Assuming the traversal finds the first valid non-transparent voxel.
            
            # 7. Depth Assignment
            # Depth is the entry point of the hit voxel in data coordinates
            depth = voxel_to_data_coord(current_voxel)
            
            color = get_label_color(label)
            return color, depth
            
        # Advance to next voxel
        # Determine which axis is crossed next
        if t_max_x < t_max_y:
            if t_max_x < t_max_z:
                current_voxel[0] += sign(ray_direction[0])
                t_max_x += t_delta_x
            else:
                current_voxel[2] += sign(ray_direction[2])
                t_max_z += t_delta_z
        else:
            if t_max_y < t_max_z:
                current_voxel[1] += sign(ray_direction[1])
                t_max_y += t_delta_y
            else:
                current_voxel[2] += sign(ray_direction[2])
                t_max_z += t_delta_z
                
        # Check if we have exceeded the shortened ray bound
        # Compute t for the next voxel entry to ensure we don't overshoot
        next_voxel_entry_t = compute_t_for_voxel_entry(current_voxel, ray_origin, ray_direction, volume_origin, voxel_size)
        if next_voxel_entry_t > t_max:
            break

    return transparent_color, 0.0
```

**Parameters:**
- `relative_step_size`: Default 0.8 voxels. Used only for the initial search phase, not the final traversal [S1, unofficial].
- `epsilon`: Tiny margin for ray shortening. Value not specified in sources [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Sawtooth Artifacts:** The old method caused shifting sawtooth edges at grazing angles because rays clipping voxel corners between samples missed them. This is eliminated by visiting every voxel [S1, unofficial].
- **Depth Offset Error:** The old method shifted depth by half a voxel along each axis, causing incorrect occlusion between layers with different scales. The new method uses the exact entry point in data coordinates [S1, unofficial].
- **Performance:** Traversal visits every voxel along the ray, which is more expensive per visit than the old sample loop, especially at oblique angles where a ray crosses more voxels than it took samples [S1, unofficial].

## Subtopics

### translucent_categorical
A variant of `iso_categorical` used when `rendering='translucent'`. It shares the exact same voxel traversal logic and fixes for sawtooth edges and depth offsets but differs in how the hit voxel is shaded (likely using translucency transfer functions instead of opaque color mapping) [S1, unofficial]. Performance impact is similar to `iso_categorical`, with frame time increases ranging from 1.1x to 1.8x depending on scene density and view angle [S1, unofficial].

### Segmented Dataset Rendering with Anatomical Feature Enhancement
An algorithm for rendering segmented datasets that "paints" various colors acquired from segmentation to the rendered volume. It delivers higher image quality with smoother subvolume boundaries compared to using different transfer functions for segmented object separation [S2].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of voxels intersected by the ray. Unlike the old method, cost does not depend on `relative_step_size` [S1, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary memory for traversal state. No additional acceleration structures are used in the base implementation [S1, unofficial].
- **Measured Performance:** On an M1 Max, canvas 2000 × 1800 px, iso_categorical, default step 0.8:
    - Axis-aligned view, empty 256³ volume: 3.6 ms → 4.3 ms (1.2× slower) [S1, unofficial].
    - Oblique view, empty 256³ volume: 3.7 ms → 6.3 ms (1.7× slower) [S1, unofficial].
    - 300 nuclei, 256³ volume: 3.1 ms → 3.4 ms (1.1× slower) [S1, unofficial].
    - Oblique view, 300 nuclei, 256³ volume: 3.7 ms → 4.6 ms (1.3× slower) [S1, unofficial].
    - 1500 nuclei, 512³ volume: 6.7 ms → 7.2 ms (1.1× slower) [S1, unofficial].
    - Oblique view, 1500 nuclei, 512³ volume: 8.1 ms → 9.8 ms (1.2× slower) [S1, unofficial].
    - Dense labels (rays stop immediately): < 1 ms [S1, unofficial].
- **Strengths:** Eliminates geometric artifacts (sawtooth edges) and depth occlusion errors. Result is independent of step size [S1, unofficial].
- **Limitations:** Higher computational cost per ray than fixed-step sampling, particularly at oblique angles. No built-in support for skipping empty space in the base implementation (though a prototype using a coarse 8×8×8 block map was mentioned) [S1, unofficial].
- **When to use:** When rendering categorical label data where geometric accuracy and correct occlusion between layers are critical, and performance constraints allow for linear traversal [S1, unofficial].

## Background
The method was developed to fix rendering artifacts in the `napari` volume viewer, specifically for labels layers. The original implementation used fixed-step marching which caused sawtooth edges and depth offset errors. The fix involved implementing Amanatides & Woo voxel traversal [S1, unofficial]. The code was implemented in `src/napari/_vispy/visuals/volume.py` and later ported to Vispy [S1, unofficial]. The concept of painting segmentation colors for smoother boundaries is also discussed in broader volume visualization literature [S2].
