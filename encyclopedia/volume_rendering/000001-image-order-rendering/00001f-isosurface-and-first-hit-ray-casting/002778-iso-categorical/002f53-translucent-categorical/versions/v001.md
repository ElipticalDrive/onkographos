# translucent_categorical

Also called: translucent label rendering

## Overview
A volume rendering method for categorical labels used when `rendering='translucent'`, which shares the new traversal logic with [iso_categorical](4049-iso-categorical.md) but differs only in how the hit voxel is shaded [S1, unofficial]. It solves the sawtooth edge artifacts and depth shifting issues of the previous fixed-step ray casting by entering and leaving voxels precisely, ensuring cut surfaces stay where they were and depth is consistent across scales [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: 3D integer label map (categorical data), view direction, camera parameters, label color map, opacity value.
- Output: Translucent RGBA image compositing the label volume over the primary slice.

**Data structures:**
- Label volume: 3D array of integers.
- RGBA overlay volume: 4D array of shape $(X, Y, Z, 4)$ with dtype `uint8` [S2, unofficial].
- Ray traversal state: Current position in data coordinates, entry/exit points per voxel.

**Steps:**
1. **Ray Traversal Setup:** For each pixel, cast a ray through the volume. Unlike the old method that sampled at fixed intervals, this method calculates the exact entry and exit points of the ray for each voxel it intersects [S1, unofficial].
2. **Voxel Boundary Handling:** The ray is shortened by a tiny margin at both ends to prevent rounding errors from reading neighboring voxels when a plane starts exactly on a voxel boundary [S1, unofficial].
3. **Hit Detection:** The ray traverses the volume. When a voxel containing a label is hit, the traversal stops for that ray (similar to iso_categorical) [S1, unofficial].
4. **Depth Assignment:** The depth for the pixel is set to the point where the ray enters the hit voxel, in data coordinates. This avoids the half-voxel shift along each axis present in the previous implementation, which caused depth inconsistencies between layers with different scales [S1, unofficial].
5. **Shading (Translucent):** The hit voxel is shaded as a translucent overlay.
    - Initialize an RGBA array of shape $(X, Y, Z, 4)$ with dtype `uint8` [S2, unofficial].
    - Iterate over unique labels $> 0$.
    - For each label $lid$:
        - Create boolean mask $m = (array == lid)$ [S2, unofficial].
        - Assign RGB from the label color map scaled to 0-255 [S2, unofficial].
        - Assign alpha from the opacity value (default 0.55) scaled to 0-255 [S2, unofficial].
        - Apply to `rgba[m]` [S2, unofficial].
6. **Compositing:** The resulting RGBA volume is flattened in Fortran order, converted to a VTK unsigned char array with 4 components, and attached to `vtkImageData` with dimensions, spacing, and origin. Scalars are set for compositing over the primary slice [S2, unofficial].

**Parameters:**
- `opacity`: Default 0.55 [S2, unofficial].
- `label_color_map`: Mapping from label ID to RGB color [S2, unofficial].

**Edge cases and pitfalls:**
- **Rounding errors:** If the ray starts exactly on a voxel boundary, rounding may read the neighboring voxel. The tiny margin shortening prevents this [S1, unofficial].
- **Depth inconsistency:** Previous implementations shifted depth by half a voxel along each axis, causing layers with different scales to misalign. The new method uses the entry point in data coordinates to fix this [S1, unofficial].
- **Empty space:** Rays spend time traversing empty space. A prototype optimization uses a coarse map of $8 \times 8 \times 8$ blocks to skip empty space, but this requires a second texture and maintenance [S1, unofficial].

## Subtopics

### Segmentation Overlay Rendering
Converts a 3D integer label map into a translucent RGBA overlay volume for compositing over the primary slice [S2, unofficial]. It initializes an RGBA array, iterates over unique labels, assigns RGB from a color map and alpha from a fixed opacity (0.55), and attaches the result to VTK data structures for rendering [S2, unofficial].

## Operating characteristics
- **Time complexity:** The new method's cost does not depend on the step size, unlike the old method where cost grew with $1/\text{step}$ [S1, unofficial].
- **Performance:** Frame time increases range from 1.1x to 1.8x depending on scene density and view angle compared to the previous implementation [S1, unofficial].
    - Empty 256³ volume: 3.6 ms → 4.3 ms (1.2x) axis-aligned, 3.7 ms → 6.3 ms (1.7x) oblique [S1, unofficial].
    - 300 nuclei, 256³: 3.1 ms → 3.4 ms (1.1x) axis-aligned, 3.7 ms → 4.6 ms (1.3x) oblique [S1, unofficial].
    - 1500 nuclei, 512³: 6.7 ms → 7.2 ms (1.1x) axis-aligned, 8.1 ms → 9.8 ms (1.2x) oblique [S1, unofficial].
- **Comparison with old step size:** Compared to the old method at step 0.4 (which had finer artifacts), the new method is as fast or faster (0.66x to 1.0x) [S1, unofficial].
- **Memory:** Dense labels render in under 1 ms [S1, unofficial]. An optimization using an $8 \times 8 \times 8$ block map could reduce time to 0.5x–0.93x but requires additional memory for the second texture [S1, unofficial].
- **Strengths:** Eliminates sawtooth edges and depth shifting artifacts. Performance is independent of step size.
- **Limitations:** Still reads every voxel along the ray unless optimized with a block map.

## Background
This method was introduced in the napari project to fix rendering artifacts in categorical label visualization [S1, unofficial]. It builds on the traversal logic of [iso_categorical](4049-iso-categorical.md) and adapts it for translucent rendering. The segmentation overlay rendering component is part of the MedViewer application [S2, unofficial].
