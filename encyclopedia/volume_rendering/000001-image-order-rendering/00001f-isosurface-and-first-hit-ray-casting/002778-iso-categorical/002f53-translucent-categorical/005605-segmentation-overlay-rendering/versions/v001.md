# Segmentation Overlay Rendering

Also called: Label Map Overlay, RGBA Segmentation Volume, Segmentation Alpha Blending

## Overview
Segmentation Overlay Rendering converts a 3D integer label map into a translucent RGBA volume to composite discrete semantic information over primary anatomical data [S1, unofficial]. Unlike its parent [translucent_categorical](6031-translucent-categorical.md), which shades the first-hit voxel based on categorical properties during ray traversal, this method pre-computes a static overlay volume that is blended in post-compositing or as a secondary pass, allowing the underlying intensity or volume rendering to remain visible through the label boundaries [S1, unofficial].

## How it works
**Inputs:**
- `label_map`: 3D numpy array of shape $(X, Y, Z)$ with integer dtype, where $0$ typically represents background.
- `label_colors`: Mapping from label ID to RGB color (normalized $[0, 1]$ or integer $[0, 255]$).
- `opacity`: Scalar float $\alpha \in [0, 1]$ controlling the translucency of the overlay.

**Outputs:**
- `overlay_volume`: 3D RGBA array of shape $(X, Y, Z, 4)$ with `uint8` dtype, ready for attachment to a VTK image data structure.

**Data Structures:**
- `rgba`: A 4D array of shape $(X, Y, Z, 4)$ initialized to zeros with `dtype=uint8`.
- `vtkImageData`: A VTK object holding dimensions, spacing, origin, and scalar data.

**Steps:**
1. Initialize `rgba` array of shape $(X, Y, Z, 4)$ with `dtype=uint8` set to zero.
2. Identify unique labels $L = \{l_1, l_2, \dots, l_n\}$ from `label_map` where $l_i > 0$.
3. For each label $l \in L$:
   a. Create a boolean mask $m = (\text{label\_map} == l)$.
   b. Retrieve the RGB color $(R_l, G_l, B_l)$ for label $l$. If the source provides normalized colors, scale to $[0, 255]$:
      $$ R' = \lfloor R_l \times 255 \rfloor, \quad G' = \lfloor G_l \times 255 \rfloor, \quad B' = \lfloor B_l \times 255 \rfloor $$
   c. Calculate the alpha value $\alpha_{uint8}$:
      $$ \alpha_{uint8} = \lfloor \text{opacity} \times 255 \rfloor $$
   d. Assign values to the overlay volume at masked positions:
      $$ \text{rgba}[m, 0] = R' $$
      $$ \text{rgba}[m, 1] = G' $$
      $$ \text{rgba}[m, 2] = B' $$
      $$ \text{rgba}[m, 3] = \alpha_{uint8} $$
4. Flatten the `rgba` array in Fortran (column-major) order to create a 1D sequence.
5. Convert the flattened array to a VTK unsigned char array with 4 components using `numpy_support.numpy_to_vtk`.
6. Attach the scalar data to a `vtkImageData` object configured with the original dimensions, spacing, and origin.

**Pseudocode:**
```python
import numpy as np
import vtk

def create_segmentation_overlay(label_map, label_colors, opacity=0.55):
    """
    Convert a 3D integer label map into a translucent RGBA overlay volume.
    
    Args:
        label_map: np.ndarray of shape (X, Y, Z), integer dtype.
        label_colors: dict mapping label_id to (R, G, B) in [0, 1] or [0, 255].
        opacity: float in [0, 1], default 0.55.
        
    Returns:
        vtkImageData: The overlay volume ready for rendering.
    """
    # 1. Initialize RGBA array
    shape = label_map.shape
    rgba = np.zeros((*shape, 4), dtype=np.uint8)
    
    # 2. Get unique labels > 0
    unique_labels = np.unique(label_map[label_map > 0])
    
    # 3. Iterate over labels
    for lid in unique_labels:
        # Create boolean mask
        mask = (label_map == lid)
        
        # Get color
        raw_color = label_colors[lid]
        
        # Normalize color to 0-255 if necessary
        if np.max(raw_color) <= 1.0:
            r, g, b = [int(c * 255) for c in raw_color]
        else:
            r, g, b = [int(c) for c in raw_color]
            
        # Calculate alpha
        alpha = int(opacity * 255)
        
        # Apply to rgba array
        rgba[mask, 0] = r
        rgba[mask, 1] = g
        rgba[mask, 2] = b
        rgba[mask, 3] = alpha
        
    # 4. Flatten in Fortran order
    rgba_flat = rgba.flatten(order='F')
    
    # 5. Convert to VTK array
    # Note: numpy_support is from vtk.util.numpy_support
    from vtk.util.numpy_support import numpy_to_vtk
    vtk_array = numpy_to_vtk(rgba_flat, deep=True)
    vtk_array.SetNumberOfComponents(4)
    vtk_array.SetName("SegmentationOverlay")
    
    # 6. Attach to VTKImageData
    vtk_image = vtk.vtkImageData()
    vtk_image.SetDimensions(shape)
    # Assuming unit spacing and origin for simplicity; real implementation 
    # should pass spacing and origin from the source label_map metadata.
    vtk_image.SetSpacing((1.0, 1.0, 1.0))
    vtk_image.SetOrigin((0.0, 0.0, 0.0))
    vtk_image.SetScalarTypeToUnsignedChar()
    vtk_image.SetNumberOfScalarComponents(4)
    vtk_image.SetNumberOfScalarPoints(rgba_flat.size)
    vtk_image.GetPointData().SetScalars(vtk_array)
    
    return vtk_image
```

**Parameters:**
- `opacity`: Default $0.55$ [S1, unofficial].
- `label_colors`: User-defined or default palette.

**Edge Cases:**
- Label $0$ is ignored (background) [S1, unofficial].
- Precision: Alpha is truncated to integer $[0, 255]$ [S1, unofficial].
- Color scaling: The source assumes colors might be normalized $[0, 1]$ or integer $[0, 255]$ and handles both [S1, unofficial].

## Subtopics

### [Statistical Volume Map Overlay](22572-statistical-volume-map-overlay.md)
Statistical Volume Map Overlay integrates statistical volume maps (VMP) into the ray-casting pipeline to visualize activated regions (e.g., in brain imaging) alongside underlying anatomical data. It differs from standard segmentation overlays by allowing map values to be rendered both outside and inside the anatomical volume with adjustable blending, rather than restricting the overlay to a binary or discrete label boundary. It builds on [Segmentation Overlay Rendering](15607-segmentation-overlay-rendering.md) by treating the statistical map as a continuous scalar field integrated during depth compositing.

### Intensity Rendering Overlay
An interactive plane rendered within the 3D endoscopic view to display original CT scan intensity values for manual surface analysis, moving with the camera [S2]. It renders a transparent border for depth impressions and a center area that cuts through the surface, displaying actual intensity values via an applied 1D transfer function [S2].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the label map, as it iterates once per unique label to set RGBA values.
- **Memory Complexity:** $O(N)$ for the RGBA overlay volume.
- **Strengths:** Simple to implement; allows underlying data to be seen through labels; decouples segmentation visualization from the primary ray-casting shader.
- **Limitations:** Static overlay; does not support depth-based occlusion of the overlay by the underlying volume during ray traversal (it is a post-compositing or secondary volume blend).
- **When to use:** When discrete semantic labels need to be visualized over anatomical data without obscuring it completely.
- **When not to use:** When depth-accurate occlusion between labels and anatomy is required during ray casting.

## Background
This method is implemented in the MedViewer application, an open-source medical imaging viewer [S1, unofficial]. It is used to visualize segmentation results (e.g., organ masks) overlaid on CT or MRI data. The approach of converting label maps to RGBA volumes is a standard technique in VTK-based viewers to leverage VTK's built-in volume rendering capabilities for categorical data without custom shaders.
