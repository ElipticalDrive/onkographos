# Shaded Surface Display (SSD)

Also called: SS-VRT

## Overview
Shaded Surface Display (SSD) is a surface rendering technique that creates a 3D visual illustration of CT volumetric data from any desired perspective, providing a sensation of three-dimensionality superior to other volume rendering techniques [S1]. It differs from direct volume rendering by extracting explicit surface geometry based on density thresholds and applying ray-traced shading, rather than compositing voxel contributions along rays [S1]. It builds on the boundary extraction logic of its parent, [Transparent-opaque Boundary Shader](14931-transparent-opaque-boundary-shader.md), by focusing on hard, opaque surface representation rather than transparent boundary blending.

## How it works
**Inputs and Outputs:**
*   **Input:** CT volumetric data (voxel grid), where each voxel has a Hounsfield Unit (HU) value.
*   **Output:** A 2D perspective image with surface shading.

**Data Structures:**
*   **Voxel Grid:** 3D array of integer or float values representing Hounsfield Units.
*   **Surface Mesh:** Implicitly or explicitly generated set of vertices and normals defining the boundary between selected tissue types. [G] In standard SSD implementations, this is often a marching cubes mesh or a set of surface normals derived from gradient analysis of the thresholded volume.

**Steps:**
1.  **Segmentation:** Select voxels to be included in the surface rendering based on a selected range of Hounsfield values [S1]. The volume is segmented into tissue types (e.g., parenchyma, bone, airways, vessels) by analyzing combinations of Hounsfield ranges [S1].
2.  **Surface Extraction:** Calculate the location of surfaces separating the segmented tissue types [S1]. This involves identifying the boundary where the Hounsfield value crosses the selected threshold.
3.  **Normal Calculation:** Compute surface normals at the extracted boundary points. [G] Normals are typically estimated using the gradient of the scalar field (Hounsfield values) at the surface location.
4.  **Ray Tracing/Shading:** Calculate a perspective visualization based on a selectable observer position and light source positioning using ray-tracing techniques [S1]. The opacity is set to high (opaque) for the selected surface, with low opacity only at steep gradients to create a hard, transparent boundary representation [S2, unofficial].
5.  **Rendering:** Render the shaded surface from the specified viewpoint.

**Parameters:**
*   **Hounsfield Range:** A selected range of Hounsfield values used to determine which voxels are included in the surface rendering [S1]. Typical values depend on the tissue: bone (~+400 to +3000 HU), soft tissue (~+20 to +100 HU), air (< -900 HU). [G] Specific ranges are not provided in sources; implementer must select based on target anatomy.

**Pitfalls:**
*   **Stair-step Artifact:** Discontinuities in the scanner dataset due to nonvolumetric data acquisition can cause stair-step artifacts [S1]. This is less frequent with Multi-Detector CT (MDCT) [S1].
*   **Detail Loss:** SSD may hide structures behind adjacent surfaces unless the region of interest is progressively trimmed or excluded/included interactively [S1].

    """

    # Step 1: Segment volume
    # Create a binary mask where voxels are within the Hounsfield range
    mask = (ct_volume >= hounsfield_range[0]) & (ct_volume <= hounsfield_range[1])
    
    # Step 2: Extract Surface

    surface_points = extract_surface_boundary(mask)
    
    # Step 3: Calculate Normals

    # Step 4: Ray Tracing for Shading

    return image

## Subtopics

### Virtual Endoscopy
A specific application of SSD used to visualize internal lumens (e.g., bile tree, pancreatic duct) by navigating along the extracted surface [S1].

### Articular Surface Analysis
SSD is particularly apt for studying fine details such as articular bone surfaces and revealing fracture lines hidden behind adjacent bone [S1].

## Operating characteristics
*   **Time Complexity:** Processor intensive due to the complexity of surface extraction and ray-tracing calculations [S1].
*   **Memory Complexity:** Requires storage for the volume data and the extracted surface mesh.
*   **Strengths:** Provides superior 3D sensation; excellent for visualizing fine details of specific density structures (e.g., bone fractures, ducts) [S1]. Allows real-time user manipulation of view perspective and virtual light sources [S1].
*   **Limitations:** Prone to stair-step artifacts from nonvolumetric acquisition (though less common with MDCT) [S1]; cannot see through opaque surfaces without interactive trimming/exclusion [S1].
*   **When to Use:** Studying fine anatomical details like articular bone surfaces, virtual endoscopy, and assessing structures with specific density ranges (e.g., biliary tree with contrast) [S1].
*   **When Not to Use:** When transparent visualization of internal structures is required without surface occlusion, or when the data has significant nonvolumetric acquisition artifacts.

## Background
SSD, also known as SS-VRT, was developed as a technique to create 3D visual illustrations of CT volumetric data [S1]. It became commonplace as processing power increased, allowing for real-time user manipulation [S1]. It is particularly useful for analyzing hypodense structures like the bile tree and pancreatic duct, especially during contrast agent administration phases [S1]. The technique's principle diagnostic utility lies in its ability to represent structures of a specific density with great detail [S1].
