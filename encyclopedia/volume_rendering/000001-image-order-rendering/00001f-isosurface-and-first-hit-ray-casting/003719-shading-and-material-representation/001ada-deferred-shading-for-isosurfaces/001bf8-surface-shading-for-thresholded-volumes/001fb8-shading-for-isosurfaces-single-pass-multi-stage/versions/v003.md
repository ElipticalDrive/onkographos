# Shading for Isosurfaces (Single-Pass Multi-Stage)

Also called: Fast Rendering of Shaded Isosurfaces, Isosurface shading with register combiners, Shaded Iso-surfaces via Register Combiners

## Overview
This method is a single-pass rendering technique that exploits rasterization hardware to display shaded isosurfaces using a 3D gradient map and multi-stage rasterization, computing dot products and compositing in register combiners [S1, unofficial][S2]. It eliminates the need for frame buffer copying required by earlier multi-pass approaches, allowing for colored ambient and diffuse light sources [S2]. Unlike [Shading and Frame Buffer Filling](1808-shading-and-frame-buffer-filling.md) which may require post-processing passes, this method performs all shading computations in the register combiners before fragments are combined [S1, unofficial].

## How it works
**Inputs:**
*   A set of 2D textures representing the volume, where RGB components store voxel gradients and the alpha component stores material information [S1, unofficial].
*   Primary color register ($I_d$) storing the diffuse light color [S1, unofficial][S2].
*   Secondary color register ($I_a$) storing the ambient light color [S1, unofficial][S2].
*   Second constant color register storing the light vector ($l$) [S1, unofficial].

**Outputs:**
*   A shaded image of the isosurface with correct lighting and transparency [S1, unofficial][S2].

**Data Structures:**
*   **Volume Textures:** A set of 2D textures [S1, unofficial]. Each texel's RGB channel holds the pre-computed gradient vector $(n_x, n_y, n_z)$ at that voxel location [S1, unofficial]. The alpha channel holds the material ID or opacity value [S1, unofficial].
*   **Register Combiner State:**
    *   **Stage 1 (General Combiner):** Configured for trilinear interpolation of intermediate slices (as described in [Multi-Texture Interpolation](link-to-multi-texture-interpolation.md)) [S1, unofficial]. It outputs the interpolated gradient vector $\mathbf{n}$ in its RGB output [S1, unofficial].
    *   **Stage 2 (General Combiner):** Computes the dot product between the interpolated gradient and the light vector [S2].
    *   **Stage 3 (Final Combiner):** Composites the diffuse and ambient lighting terms [S1, unofficial][S2].

**Numbered Steps:**

1.  **Texture Setup:** Compute voxel gradients for the volume data [S1, unofficial]. Write these gradients into the RGB components of a set of 2D textures [S1, unofficial]. Code the material information into the alpha component of these textures [S1, unofficial].
2.  **Register Combiner Stage 1 (Interpolation):** Program the first general combiner stage to perform trilinear interpolation of the volume slices [S1, unofficial]. This stage outputs the interpolated gradient vector $\mathbf{n}$ [S1, unofficial].
3.  **Register Combiner Stage 2 (Dot Product):**
    *   Map variable A to the RGB output of the first combiner stage (the interpolated gradient $\mathbf{n}$) [S1, unofficial].
    *   Map variable B to the second constant color register, which contains the light vector $\mathbf{l}$ [S1, unofficial].
    *   Configure the combiner to compute the dot product $\mathbf{n} \cdot \mathbf{l}$ in the RGB portion [S2].
    *   Do not modify the alpha component in this stage [S1, unofficial].
    *   Use signed fixed-point values to allow direct representation of negative dot products without scaling or biasing to the positive range [S1, unofficial].
4.  **Register Combiner Stage 3 (Compositing):**
    *   The final combiner computes the equation: $I = I_d \cdot (\mathbf{n} \cdot \mathbf{l}) + I_a$ [S1, unofficial][S2].
    *   Assign variable A to the primary color register ($I_d$, diffuse light color) [S1, unofficial][S2].
    *   Assign variable B to the output of the second combiner stage (the dot product $\mathbf{n} \cdot \mathbf{l}$) [S1, unofficial][S2].
    *   Set variable C to zero [S1, unofficial][S2].
    *   Assign variable D to the secondary color register ($I_a$, ambient light color) [S1, unofficial][S2].
    *   The combiner performs the operation: $A \cdot B + (1 - A) \cdot C + D$ [S2]. Since $C=0$, this simplifies to $I_d \cdot (\mathbf{n} \cdot \mathbf{l}) + I_a$ [S1, unofficial][S2].
5.  **Rendering Transparent Isosurfaces (Optional):**
    *   To display multiple transparent isosurfaces, configure the alpha lookup table such that material ranges to be displayed have alpha values $> 0$, and others have alpha $= 0$ [S1, unofficial].
    *   Disable the depth test [S1, unofficial].
    *   Enable the alpha test to discard fragments with alpha $= 0$ [S1, unofficial].
    *   Enable alpha blending [S1, unofficial].
    *   Render the slices in back-to-front order to correctly accumulate semi-transparent isosurfaces with respect to selected attenuation [S1, unofficial].

```python

    # Compute voxel gradients and write to RGB components of 2D textures.
    # Code material information into the alpha component.
    textures = []
    for grad, alpha in zip(volume_gradients, material_alphas):
        textures.append({"rgb": grad, "alpha": alpha})

    # Step 2: Configure Stage 1 (Interpolation)
    # Program first general combiner for trilinear interpolation of slices.
    # Maps input textures to interpolate intermediate slices.
    # Output: interpolated gradient n in RGB.
    stage1_config = {
        "stage": 1,
        "operation": "trilinear_interpolation",
        "input": textures,
        "output_rgb": "n"
    }

    # Step 3: Configure Stage 2 (Dot Product)
    # Variable A: interpolated gradient n (from Stage 1)
    # Variable B: light vector l (from second constant color register)
    # Computes dot product n . l in RGB. Alpha passes through unchanged.
    # Uses signed fixed-point values to handle negative components.
    stage2_config = {
        "stage": 2,
        "variable_a": "n",
        "variable_b": "light_vector",
        "operation_rgb": "dot_product",
        "operation_alpha": "pass_through",
        "signed_fixed_point": True
    }

    # Step 4: Configure Stage 3 (Final Compositing)
    # Final combiner computes A * B + (1 - A) * C + D
    # Variable A: primary color register (Id, diffuse light color)
    # Variable B: output of Stage 2 (dot product n . l)
    # Variable C: zero
    # Variable D: secondary color register (Ia, ambient light color)
    stage3_config = {
        "stage": 3,
        "variable_a": "primary_color",
        "variable_b": "stage2_output",
        "variable_c": "zero",
        "variable_d": "secondary_color",
        "operation": "A * B + (1 - A) * C + D"
    }
```

**Parameters:**
*   **Light Vector ($l$):** Normalized 3D vector. Stored in the second constant color register [S1, unofficial].
*   **Diffuse Color ($I_d$):** Stored in the primary color register [S1, unofficial][S2].
*   **Ambient Color ($I_a$):** Stored in the secondary color register [S1, unofficial][S2].
*   **Alpha Threshold:** For transparent rendering, alpha values $> 0$ are displayed, $= 0$ are discarded [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Limited Registers:** It is not possible to write initial values to the two spare registers displayed in Fig. 2 of the source, limiting the ability to add a second diffuse light source without sacrificing trilinear interpolation or separate ambient/diffuse colors [S2].
*   **Signed Values:** The method relies on signed fixed-point values in the general combiner stages [S1, unofficial]. If the hardware does not support this, vector components must be scaled and biased to the positive range, which is not required here [S1, unofficial].
*   **Single-Pass Limitation:** While efficient, this method is limited to the number of available combiner stages and registers [S2]. Complex lighting models requiring more than one diffuse light source or specular highlights may not be feasible without compromising other features [S2].

## Operating characteristics
*   **Time Complexity:** Single-pass rendering, meaning all computations are performed in the register combiners before fragments are combined [S1, unofficial]. This avoids the copy operation required to multiply pixel values with a properly initialized color matrix, making it faster than multi-pass approaches [S1, unofficial][S2].
*   **Memory Complexity:** Requires storing gradient vectors in RGB components and material info in alpha for a set of 2D textures [S1, unofficial].
*   **Performance:** Efficient on hardware supporting register combiners (e.g., GeForce graphics processor) [S1, unofficial].
*   **Strengths:** Single-pass execution, colored ambient and diffuse light sources, support for transparent isosurfaces [S1, unofficial][S2].
*   **Limitations:** Limited by available registers for additional light sources; requires hardware support for signed fixed-point values in combiners [S1, unofficial][S2].
*   **When to Use:** When real-time shaded isosurface rendering is required on hardware with register combiner support, and complex lighting (multiple diffuse lights) is not needed [S1, unofficial][S2].
*   **When Not to Use:** When multiple diffuse light sources are required, or when hardware does not support signed fixed-point values in combiners [S2].

## Background
This method was introduced as an efficient algorithm to exploit rasterization hardware for displaying shaded isosurfaces using a 3D gradient map [S1, unofficial]. It was adapted for the GeForce graphics processor using multi-stage rasterization [S1, unofficial]. The original work is attributed to Westermann and Ertl [S2].
