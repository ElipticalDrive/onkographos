# Surface shading for thresholded volumes

Also called: Boundary normal estimation, Z-buffer shading

## Overview
Surface shading for thresholded volumes applies illumination models to isosurfaces extracted from scalar volume data by determining the first hit of a ray against a thresholded boundary [S1, unofficial]. It distinguishes itself from direct volume rendering by computing shading only at the single intersection point where the scalar field exceeds a threshold, rather than integrating opacity and color along the entire ray path [S1, unofficial]. This method is a specific implementation within the broader framework of deferred shading for isosurfaces, focusing on efficient surface property estimation [S1, unofficial].

## How it works
### Inputs and outputs
**Inputs:**
*   Scalar volume dataset $V$ defined on a grid.
*   Threshold value $T$ defining the isosurface ($f(X) = T$).
*   Viewing parameters (camera position, orientation, projection matrix).
*   Lighting configuration (light direction $\mathbf{l}$, ambient color $\mathbf{c}_{amb}$, diffuse color $\mathbf{c}_{diff}$).

**Outputs:**
*   Final color image $C(x,y)$ for each pixel.

### Data structures
*   **Z-Buffer:** Stores the depth $z$ of the first surface hit for each pixel.
*   **Position Buffer (Optional but common in modern implementations):** Stores the 3D world position $\mathbf{p}$ of the intersection point for each pixel.
*   **Volume Data:** Accessible via texture lookup or memory array for gradient estimation.

### Steps
1.  **Thresholding and Ray Casting:**
    For each pixel, cast a ray into the volume. Determine the first voxel where the scalar value $f(\mathbf{x})$ exceeds the threshold $T$. Record the depth $z$ in the Z-buffer and the 3D position $\mathbf{p}$ in the Position Buffer [S1, unofficial][S3, unofficial]. If no hit is found (e.g., ray misses the volume), mark the pixel as empty [S3, unofficial].

2.  **Normal Estimation:**
    Estimate the surface normal $\mathbf{n}$ at the hit point $\mathbf{p}$. Three primary methods are cited in the literature [S1, unofficial]:
    *   **Z-Buffer Slope (Projected Slope):** Compute the slope of the projected surface using Z-buffer values at neighboring pixels $(x\pm1, y)$ and $(x, y\pm1)$. The normal is derived from the cross product of the tangent vectors in the image plane [S1, unofficial].
    *   **Geometry (Boundary Orientation):** Determine orientation based on the cube face and its neighbors in the boundary of the opaque volume (e.g., using marching cubes topology or simple face orientation) [S1, unofficial].
    *   **Gradient (Finite Differences):** Compute the gradient of the scalar field $f(\mathbf{x})$ using central finite differences at neighboring voxels. This is the most geometrically accurate method [S1, unofficial][S3, unofficial].

3.  **Shading Calculation:**
    Compute the final color using a shading model (typically Lambertian or Phong) [S1, unofficial][S3, unofficial].
    *   **Lambertian Diffuse:** $C_{diff} = \mathbf{c}_{diff} \cdot \max(\mathbf{n} \cdot \mathbf{l}, 0)$ [S3, unofficial].
    *   **Depth Shading:** Optionally, shade distant pixels darker using Z-buffer depth values $z$ [S1, unofficial].

### Formulas
**Gradient Estimation (Finite Differences):**
Let $h$ be the voxel spacing (or gradient step). The gradient $\nabla f$ at position $\mathbf{p}$ is:
$$ \nabla f(\mathbf{p}) \approx \frac{f(\mathbf{p} + h\mathbf{e}_i) - f(\mathbf{p} - h\mathbf{e}_i)}{2h} \mathbf{e}_i + \frac{f(\mathbf{p} + h\mathbf{e}_j) - f(\mathbf{p} - h\mathbf{e}_j)}{2h} \mathbf{e}_j + \frac{f(\mathbf{p} + h\mathbf{e}_k) - f(\mathbf{p} - h\mathbf{e}_k)}{2h} \mathbf{e}_k $$
where $\mathbf{e}_i, \mathbf{e}_j, \mathbf{e}_k$ are the unit vectors along the grid axes [S3, unofficial].

**Normal Normalization:**
$$ \mathbf{n} = \frac{\nabla f(\mathbf{p})}{\|\nabla f(\mathbf{p})\|} $$

**Lambertian Shading:**
$$ C_{final} = \mathbf{c}_{amb} + \mathbf{c}_{diff} \cdot \max(\mathbf{n} \cdot \mathbf{l}, 0) $$
If material color $\mathbf{m}$ is sampled from a transfer function based on position or scalar value:
$$ C_{final} = \mathbf{m} \cdot (\mathbf{c}_{amb} + \mathbf{c}_{diff} \cdot \max(\mathbf{n} \cdot \mathbf{l}, 0)) $$ [S3, unofficial].

**Proximity Shading (Variant):**
For proximity maps, the distance $d$ from the surface is normalized logarithmically [S2, unofficial]:
$$ P = \left( \frac{\log(d) - \min(\log)}{\max(\log) - \min(\log)} \right)^{1/2.33} $$
where $d$ is clamped to $[10^{-2}, \infty)$ before logging [S2, unofficial].

### Pseudocode
```python
def surface_shading_thresholded_volume(volume, threshold, light_dir, gradient_step):
    """
    Renders shaded isosurfaces for a thresholded volume.
    
    Args:
        volume: 3D array of scalar values.
        threshold: Scalar value defining the isosurface.
        light_dir: Normalized 3D vector for light direction.
        gradient_step: Step size h for finite difference gradient calculation.
        
    Returns:
        Image: 2D array of RGB colors.
    """
    height, width, depth = volume.shape
    image = np.zeros((height, width, 3))
    
    # Pass 1: Ray casting and hit detection
    # In a real implementation, this is done via GPU ray marching or rasterization.
    # Here we simulate the result: hit_positions and hit_depths.
    hit_positions = np.zeros((height, width, 3))
    hit_depths = np.zeros((height, width))
    hit_found = np.zeros((height, width), dtype=bool)
    
    for y in range(height):
        for x in range(width):
            # Cast ray, find first voxel where volume > threshold
            # This is a simplified placeholder for the ray-casting step
            pos, found = cast_ray_and_find_hit(volume, threshold, x, y)
            if found:
                hit_positions[y, x] = pos
                hit_depths[y, x] = pos.z # Assuming z is depth
                hit_found[y, x] = True
            else:
                hit_depths[y, x] = 0.0
                hit_found[y, x] = False

    # Pass 2: Shading
    for y in range(height):
        for x in range(width):
            if not hit_found[y, x]:
                # No hit: output white or background
                image[y, x] = [1.0, 1.0, 1.0]
                continue
            
            p = hit_positions[y, x]
            
            # Estimate normal using gradient
            grad = estimate_gradient(volume, p, gradient_step)
            normal = grad / np.linalg.norm(grad)
            
            # Lambertian shading
            dot_product = np.dot(normal, light_dir)
            diffuse = max(dot_product, 0.0)
            
            # Sample material color (simplified as constant white for this example)
            material_color = [1.0, 1.0, 1.0]
            
            # Combine
            ambient = [0.2, 0.2, 0.2]
            final_color = material_color * (np.array(ambient) + diffuse * np.array([1.0, 1.0, 1.0]))
            
            # Optional: Depth shading (darker for further away)
            # depth_factor = 1.0 / (1.0 + hit_depths[y, x])
            # final_color *= depth_factor
            
            image[y, x] = final_color
            
    return image

def estimate_gradient(volume, pos, h):
    """
    Computes the gradient at pos using central finite differences.
    Assumes pos is in voxel coordinates.
    """
    # Get neighbors, handling boundaries by clamping or assuming zero gradient
    def sample(v, x, y, z):
        # Clamp coordinates to volume bounds
        x = max(0, min(x, volume.shape[0]-1))
        y = max(0, min(y, volume.shape[1]-1))
        z = max(0, min(z, volume.shape[2]-1))
        return volume[x, y, z]
    
    ix, iy, iz = pos
    
    # Central differences
    dx = (sample(volume, ix + h, iy, iz) - sample(volume, ix - h, iy, iz)) / (2 * h)
    dy = (sample(volume, ix, iy + h, iz) - sample(volume, ix, iy - h, iz)) / (2 * h)
    dz = (sample(volume, ix, iy, iz + h) - sample(volume, ix, iy, iz - h)) / (2 * h)
    
    return np.array([dx, dy, dz])
```

### Parameters
*   **Threshold ($T$):** Determines the isosurface. Typical values depend on the data range (e.g., 0.5 for normalized data) [S1, unofficial].
*   **Gradient Step ($h$):** Step size for finite differences. Typically 1 voxel or the physical voxel size [S3, unofficial].
*   **Light Direction ($\mathbf{l}$):** Unit vector. Commonly set to $(0, 0, -1)$ or $(1, 1, -1)$ [S3, unofficial].

### Edge cases and pitfalls
*   **No Hit:** If the ray does not intersect the thresholded volume, the pixel should be handled explicitly (e.g., output white or background color) [S3, unofficial].
*   **Gradient Accuracy:** Finite difference gradients can be noisy if the volume is not smooth or if the threshold is near a noisy boundary [S1, unofficial].
*   **Distinction from DVR:** These shading functions are applied *after* thresholding and are distinct from direct volume rendering shading, which integrates along the ray [S1, unofficial].
*   **Z-Buffer Slope Artifacts:** Estimating normals from Z-buffer slopes can introduce artifacts if the surface is not smooth in screen space or if there are depth discontinuities [S1, unofficial].

## Subtopics

### [Shading and Frame Buffer Filling](1808-shading-and-frame-buffer-filling.md)
This method performs fast, shadow-less Lambertian shading for isosurfaces extracted from thresholded volumes. It distinguishes itself from sibling methods by explicitly avoiding deferred normal computation to prevent prohibitive memory and computational costs associated with per-ray cell storage or repeated neighbor-finding. While the underlying ray traversal remains single-ray based, the shading phase aggregates rays into packets to exploit parallelism.

### [Shading for Isosurfaces (Single-Pass Multi-Stage)](2094-shading-for-isosurfaces-single-pass-multi-stage.md)
This method is a single-pass rendering technique that exploits rasterization hardware to display shaded isosurfaces using a 3D gradient map and multi-stage rasterization, computing dot products and compositing in register combiners. It eliminates the need for frame buffer copying required by earlier multi-pass approaches, allowing for colored ambient and diffuse light sources. Unlike [Shading and Frame Buffer Filling](1808-shading-and-frame-buffer-filling.md) which may require post-processing passes, this method performs all shading computations in the register combiners before fragments are combined.

### [Fast Shaded Isosurfaces](2105-fast-shaded-isosurfaces.md)
Fast Shaded Isosurfaces is an efficient algorithm for displaying shaded isosurfaces by exploiting standard rasterization hardware to evaluate a local illumination equation. It is distinguished from its siblings by its specific two-pass technique that encodes surface normals in RGB texture components and uses the OpenGL color matrix for lighting, restricted to single light sources and monochrome display.

### [Volume Raycasting with Surface Extraction and Phong Shading](3662-volume-raycasting-with-surface-extraction-and-phong-shading.md)
This method extracts surfaces from 3D volume data using a scalar threshold and renders them via first-hit raycasting with Phong illumination. It differs from standard volume rendering by accumulating color only at the first voxel exceeding the threshold, rather than integrating opacity and color along the entire ray path.

### [Interval Shading](6414-interval-shading.md)
Interval Shading is a volume rendering technique that rasterizes tetrahedra via mesh shaders to generate depth intervals (front and back face depths) per fragment, enabling parallel evaluation of optical depth or ray marching without acceleration structures. Unlike [Shading and Frame Buffer Filling](1808-shading-and-frame-buffer-filling.md) which uses traditional depth buffers, or [Volume Raycasting with Surface Extraction and Phong Shading](3662-volume-raycasting-with-surface-extraction-and-phong-shading.md) which relies on acceleration structures, Interval Shading coerces the rasterizer to compute two depths per fragment in a single pass.

### [IsosurfaceClassifier Lighting Model](6676-isosurfaceclassifier-lighting-model.md)
The IsosurfaceClassifier Lighting Model is a volume rendering technique that visualizes an isosurface within a volume dataset by treating samples as surface points with opacity determined by a Gaussian transfer function, and computing color using a Phong illumination model (ambient, diffuse, specular) with normals derived from the volume gradient. It applies surface-like shading to volumetric data near an isovalue, with transparency based on distance from the isovalue.

### [Gaussian Grounded Inter-Reflection](13228-gaussian-grounded-inter-reflection.md)
A technique to model inter-reflection by separating direct light $L_{dir}$ and indirect light $L_{ind}$, approximating visibility $V$ via ray tracing on an extracted mesh to determine occlusion.

### [Boundary Shader](14912-boundary-shader.md)
A shader that traces the ray until its value exceeds a user-defined threshold, interpolates the exact threshold position, and illuminates the pixel based on position, precomputed volume normal, and lighting settings.

### Proximity Shading
A visualization technique that renders a surface proximity map by normalizing the logarithmic distance to the surface [S2, unofficial]. It visualizes precomputed surface distances using log normalization and gamma correction, identical in formula to Distance Shading but operating on a distance scalar field [S2, unofficial]. The formula is $P = \left( \frac{\log(d) - \min(\log)}{\max(\log) - \min(\log)} \right)^{1/2.33}$, where $d$ is surface distance, clamped to $[10^{-2}, \infty)$ before logging [S2, unofficial]. Brighter pixels indicate rays that terminated further away from the surface [S2, unofficial].

### Isosurface Shading (VPT)
A shading pass that computes lighting for the isosurface found in the previous pass, using gradient-based normals and Lambertian shading [S3, unofficial]. It samples the closest position buffer, computes the gradient using central differences, normalizes it to get the normal, and computes the Lambertian diffuse factor. The final color is the product of the material color (sampled from a transfer function) and the lighting factor [S3, unofficial]. A key pitfall is handling pixels with no hit (where `closest.w <= 0.0`), which should output white [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the average ray length to the first hit. Gradient estimation adds a constant factor (9 samples per pixel for central differences) [S3, unofficial].
*   **Memory Complexity:** Depends on the buffers used. Z-buffer shading requires only depth storage [S1, unofficial]. Gradient-based shading requires access to the volume data and potentially a position buffer [S3, unofficial].
*   **Strengths:** Computationally efficient for single-surface visualization. Provides realistic shading cues for shape perception [S1, unofficial].
*   **Limitations:** Only shows the first surface; internal structures are hidden. Normal estimation can be inaccurate at boundaries or noisy data [S1, unofficial].
*   **When to use:** When the primary interest is the outer boundary or a specific isosurface, and performance is critical [S1, unofficial].
*   **When not to use:** When internal structures or multiple surfaces need to be visualized simultaneously (use Direct Volume Rendering) [S1, unofficial].

## Background
The technique of shading thresholded volumes originated with the need to visualize medical data such as bone or tissue [S1, unofficial]. Early methods relied on simple Z-buffer depth shading, while more sophisticated approaches introduced normal estimation via finite differences of the scalar field [S1, unofficial]. The method is distinct from direct volume rendering, which integrates along the ray, and is often implemented as a post-processing step on thresholded opaque volumes [S1, unofficial]. Modern implementations leverage GPU hardware for efficient ray casting and shading [S3, unofficial].
