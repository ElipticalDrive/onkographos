# Surface shading for thresholded volumes

Also called: Boundary normal estimation, Z-buffer shading

## Overview
Surface shading for thresholded volumes applies illumination models to isosurfaces extracted from scalar volume data by determining the first intersection of a viewing ray with a voxel exceeding a user-defined threshold [S1, unofficial]. It distinguishes itself from direct volume rendering by accumulating color only at the first hit rather than integrating opacity along the entire ray path, and from mesh-based extraction by computing intersection and shading in image space without generating an intermediate polygonal mesh [S1, unofficial]. The method is a core component of [Deferred Shading for Isosurfaces](867-deferred-shading-for-isosurfaces.md), providing the geometric primitives (position, normal) required for lighting calculations.

## How it works
The method operates in two conceptual phases: surface identification and shading. While the underlying ray traversal is single-ray based, shading implementations often aggregate rays into packets to exploit parallelism [S1, unofficial][S2, unofficial][S3, unofficial].

### Inputs and Outputs
*   **Inputs**: Scalar volume data $V$, threshold value $T$, viewing ray origin $O$ and direction $D$, light direction $L$, and optionally a gradient step size $h$ [S3, unofficial].
*   **Outputs**: Final pixel color $C_{out}$ and depth $Z_{out}$ [S1, unofficial].

### Data Structures
1.  **Volume Grid**: A 3D array of scalar values $V(x,y,z)$.
2.  **Closest Position Buffer**: A frame buffer storing the 3D position $P$ of the first hit for each pixel, often packed as a `vec4` where $w$ indicates hit validity (e.g., $w \le 0$ for no hit) [S3, unofficial].
3.  **Depth Buffer (Z-buffer)**: Stores the depth $Z$ of the first hit for proximity shading [S1, unofficial].

### Steps

1.  **Ray Marching / First-Hit Detection**:
    For each pixel, cast a ray into the volume. Determine the first voxel $V_i$ where $V_i \ge T$. Record the exact entry position $P$ and depth $Z$ [S1, unofficial]. If no voxel exceeds $T$, mark the pixel as empty [S3, unofficial].

2.  **Normal Estimation**:
    Compute the surface normal $N$ at $P$ using one of the following methods [S1, unofficial]:
    *   **Gradient Method**: Compute the gradient of the scalar field $f(X)$ using finite differences at neighboring voxels [S1, unofficial].
    *   **Geometry Method**: Determine orientation from the cube face and its neighbors in the boundary of the opaque volume [S1, unofficial].
    *   **Projected Slope Method**: Estimate the slope of the projected surface using $Z$-buffer values at neighboring pixels [S1, unofficial].
    *   **Proximity Method**: Use the distance to the surface for visualization (see Subtopics) [S2, unofficial].

3.  **Shading Calculation**:
    Apply an illumination model using $N$, $P$, and $L$ [S1, unofficial]:
    *   **Lambertian**: Compute diffuse factor $k_d = \max(N \cdot L, 0)$ [S3, unofficial].
    *   **Proximity**: Normalize logarithmic distance to the surface [S2, unofficial].
    *   **Depth-based**: Shade distant pixels darker using $Z$ values [S1, unofficial].

4.  **Output**:
    Combine material color (from transfer function or texture) with shading factors to produce $C_{out}$ [S3, unofficial].

### Formulas

**Gradient Normal Estimation**:
$$ N = \frac{\nabla f(P)}{\|\nabla f(P)\|} $$
where $\nabla f(P)$ is computed via central differences:
$$ \nabla f(P) \approx \frac{f(P + h \mathbf{e}_i) - f(P - h \mathbf{e}_i)}{2h} $$
for basis vectors $\mathbf{e}_i \in \{(1,0,0), (0,1,0), (0,0,1)\}$ and step size $h$ [S3, unofficial].

**Proximity Shading**:
$$ P = \left( \frac{\log(d) - \min(\log)}{\max(\log) - \min(\log)} \right)^{1/2.33} $$
where $d$ is the surface distance, clamped to $[10^{-2}, \infty)$ before logging [S2, unofficial].

**Lambertian Diffuse**:
$$ C_{out} = C_{mat} \cdot \max(N \cdot L, 0) $$
where $C_{mat}$ is the material color sampled from the volume at $P$ [S3, unofficial].

### Parameters
*   **Threshold $T$**: The scalar value defining the isosurface [S1, unofficial].
*   **Gradient Step $h$**: Step size for finite difference gradient calculation [S3, unofficial].
*   **Light Direction $L$**: Vector from surface to light source [S3, unofficial].

### Edge Cases and Pitfalls
*   **No Hit**: If the ray does not intersect the thresholded volume, output a default color (e.g., white) or background [S3, unofficial].
*   **Gradient Noise**: Finite difference gradients can be noisy near the threshold boundary; smoothing or larger $h$ may be required [S3, unofficial].
*   **Distinct from DVR**: These shading functions are applied after thresholding and are distinct from direct volume rendering shading, which integrates along the ray [S1, unofficial].

### Pseudocode

```python
def surface_shading_for_thresholded_volumes(volume, threshold, ray_origin, ray_direction, light_dir, gradient_step):
    """
    Computes shading for a thresholded isosurface using gradient-based normals.
    
    Args:
        volume: 3D array of scalar values.
        threshold: Scalar threshold for isosurface extraction.
        ray_origin: vec3, origin of the viewing ray.
        ray_direction: vec3, direction of the viewing ray.
        light_dir: vec3, direction to the light source.
        gradient_step: float, step size h for finite differences.
        
    Returns:
        color: vec3, final shaded color.
        depth: float, depth of the first hit.
    """
    
    # 1. Ray Marching / First-Hit Detection
    # Simplified: Assume we have a function that finds the first voxel >= threshold
    # In practice, this involves traversing the grid or using acceleration structures.
    hit_point, hit_depth = find_first_hit(volume, threshold, ray_origin, ray_direction)
    
    if hit_point is None:
        return vec3(1.0, 1.0, 1.0), 0.0  # No hit, output white [S3, unofficial]
    
    # 2. Normal Estimation via Gradient
    # Compute gradient using central differences [S3, unofficial]
    grad_x = (sample_volume(volume, hit_point + vec3(gradient_step, 0, 0)) - 
              sample_volume(volume, hit_point - vec3(gradient_step, 0, 0))) / (2.0 * gradient_step)
    grad_y = (sample_volume(volume, hit_point + vec3(0, gradient_step, 0)) - 
              sample_volume(volume, hit_point - vec3(0, gradient_step, 0))) / (2.0 * gradient_step)
    grad_z = (sample_volume(volume, hit_point + vec3(0, 0, gradient_step)) - 
              sample_volume(volume, hit_point - vec3(0, 0, gradient_step))) / (2.0 * gradient_step)
              
    gradient = vec3(grad_x, grad_y, grad_z)
    normal = normalize(gradient)
    
    # 3. Shading Calculation (Lambertian)
    lambert = max(dot(normal, light_dir), 0.0)
    
    # Sample material color from transfer function using volume position [S3, unofficial]
    material_color = sample_volume_color(hit_point)
    
    # Output final color [S3, unofficial]
    final_color = material_color * lambert
    
    return final_color, hit_depth
```

## Subtopics

### [Shading and Frame Buffer Filling](1808-shading-and-frame-buffer-filling.md)
This method performs fast, shadow-less Lambertian shading for isosurfaces extracted from thresholded volumes. It distinguishes itself from sibling methods by explicitly avoiding deferred normal computation to prevent prohibitive memory and computational costs associated with per-ray cell storage or repeated neighbor-finding. While the underlying ray traversal remains single-ray based, the shading phase aggregates rays into packets to exploit parallelism.

### [Shading for Isosurfaces (Single-Pass Multi-Stage)](2094-shading-for-isosurfaces-single-pass-multi-stage.md)
This method is a single-pass rendering technique that exploits rasterization hardware to display shaded isosurfaces using a 3D gradient map and multi-stage rasterization, computing dot products and compositing in register combiners. It eliminates the need for frame buffer copying required by earlier multi-pass approaches, allowing for colored ambient and diffuse light sources. Unlike [Shading and Frame Buffer Filling](1808-shading-and-frame-buffer-filling.md) which may require post-processing passes, this method performs all shading computations in the register combiners before fragments are combined.

### [Fast Shaded Isosurfaces](2105-fast-shaded-isosurfaces.md)
Fast Shaded Isosurfaces is an efficient algorithm for displaying shaded isosurfaces by exploiting standard rasterization hardware to evaluate a local illumination equation. It is distinguished from its siblings by its specific two-pass technique that encodes surface normals in RGB texture components and uses the OpenGL color matrix for lighting, restricted to single light sources and monochrome display.

### [Volume Raycasting with Surface Extraction and Phong Shading](3662-volume-raycasting-with-surface-extraction-and-phong-shading.md)
This method extracts surfaces from 3D volume data using a scalar threshold and renders them via first-hit raycasting with Phong illumination. It differs from standard volume rendering by accumulating color only at the first voxel exceeding the threshold, rather than integrating opacity and color along the entire ray path.

### [Interval Shading](6414-interval-shading.md)
Interval Shading is a volume rendering technique that rasterizes tetrahedra via mesh shaders to generate depth intervals (front and back face depths) per fragment, enabling parallel evaluation of optical depth or ray marching without acceleration structures. Unlike [Shading and Frame Buffer Filling](1808-shading-and-frame-buffer-filling.md) which uses traditional depth buffers, or [Volume Raycasting with Surface Extraction and Phong Shading](3662-volume-raycasting-with-surface-extraction-and-phong-shading.md) which relies on acceleration structures, Interval Shading coerces the rasterizer to compute two depths per fragment in a single pass.

### [IsosurfaceClassifier Lighting Model](6676-isosurfaceclassifier-lighting-model.md)
The IsosurfaceClassifier Lighting Model is a volume rendering technique that visualizes an isosurface within a volume dataset by treating samples as surface points with opacity determined by a Gaussian transfer function, and computing color using a Phong illumination model (ambient, diffuse, specular) with normals derived from the volume gradient. It applies surface-like shading to volumetric data near an isovalue, with transparency based on distance from the isovalue.

### [Gaussian Grounded Inter-Reflection](13228-gaussian-grounded-inter-reflection.md)
Gaussian Grounded Inter-Reflection is a technique for modeling indirect illumination in reflective scenes by separating direct light $L_{\text{dir}}$ and indirect light $L_{\text{ind}}$. It approximates visibility $V$ via ray tracing on an extracted mesh to determine occlusion, allowing the indirect component to account for light bouncing off other surfaces. It differs from standard Phong or simple environment map shading by explicitly computing self-occlusion and secondary bounces using either mesh-based ray tracing or SDF-based ray marching.

### [Boundary Shader](14912-boundary-shader.md)
The Boundary Shader is an image-order rendering method for isosurfaces that identifies the first intersection of a ray with a volume data set exceeding a user-defined threshold, interpolates the exact entry position, and computes illumination based on precomputed normals. It differs from standard volume raycasting by rendering only the surface boundary rather than integrating along the entire ray, and from surface extraction methods by performing the intersection test and shading in a single pass without generating an intermediate mesh.

### Proximity Shading
A visualization technique that renders a surface proximity map by normalizing the logarithmic distance to the surface [S2, unofficial]. It visualizes precomputed surface distances using log normalization and gamma correction, identical in formula to Distance Shading but operating on a distance scalar field [S2, unofficial].
*   **Step**: Calculate the SDF value $f(p_i)$ at the intersection point. Compute $\log(f(p_i))$. Normalize this value to the range [0, 1]. Brighter pixels indicate rays that terminated further away from the surface [S2, unofficial].
*   **Formula**: $P = \left( \frac{\log(d) - \min(\log)}{\max(\log) - \min(\log)} \right)^{1/2.33}$, where $d$ is surface distance, clamped to $[10^{-2}, \infty)$ before logging [S2, unofficial].

### Isosurface Shading (VPT)
A shading pass that computes lighting for the isosurface found in the previous pass, using gradient-based normals and Lambertian shading [S3, unofficial].
*   **Step**: Sample the closest position buffer: `vec4 closest = texture(uClosest, vPosition);` Compute gradient using central differences: `positive` samples at `pos + vec3(h,0,0)`, etc., `negative` samples at `pos - vec3(h,0,0)`, etc. Gradient is `(positive - negative) / (2.0 * h)`. Normalize gradient to get normal: `vec3 normal = normalize(gradient(pos, uGradientStep));` Compute Lambertian diffuse factor: `float lambert = max(dot(normal, uLight), 0.0);` Sample material color from transfer function using volume position: `vec3 material = sampleVolumeColor(pos).rgb;` Output final color: `oColor = vec4(material * lambert, 1);` [S3, unofficial].
*   **Parameter**: `uGradientStep`: The step size `h` used for finite difference gradient calculation. `uLight`: The light direction vector [S3, unofficial].
*   **Pitfall**: If `closest.w <= 0.0` (no hit), output white `vec4(1)` [S3, unofficial].

### Deferred Volumetric Illumination
A rendering approach that reduces sampling costs by minimizing the number of sampling operations and lowering the complexity of individual sampling operations, specifically for multimodal volume illumination [S4, unofficial].
*   **Step**: Project visible volume parts to evaluate light source impact directly into screen space, avoiding the need for an intermediate illumination volume data structure [S4, unofficial].
*   **Comparison**: Unlike standard deferred shading which stores visibility in screen-space buffers (incompatible with semi-transparent structures without costly layering), this method projects illumination information directly into screen space in an order-independent manner to avoid intermediate data structures like illumination volumes [S4, unofficial].

## Operating characteristics
*   **Complexity**: Time complexity is linear with respect to the number of pixels and the average ray length within the volume [S1, unofficial]. Memory complexity is independent of grid size, relying on frame buffers for position and depth [S1, unofficial][S3, unofficial].
*   **Performance**: Fast for opaque isosurfaces as it avoids full volume integration [S1, unofficial]. Performance degrades if the thresholded surface is highly complex or if high-resolution gradients are required [S3, unofficial].
*   **Strengths**: Simple implementation, low memory footprint compared to mesh extraction, compatible with standard graphics pipelines [S1, unofficial][S3, unofficial].
*   **Limitations**: Limited to single isosurfaces (threshold-based), normals can be noisy without smoothing, and it does not support subsurface scattering or complex light transport [S1, unofficial][S3, unofficial].
*   **When to use**: Real-time visualization of opaque structures (e.g., bone in medical imaging) where speed is critical and surface detail is sufficient [S1, unofficial].
*   **When not to use**: When subsurface scattering, transparency, or multiple isosurfaces are required [S1, unofficial].

## Background
The method originated with the development of optical models for direct volume rendering, where shading techniques were adapted for thresholded opaque volumes [S1, unofficial]. It has been widely used in medical visualization for rendering bone and other tissues [S1, unofficial]. Variants have been implemented in various research projects and educational tools, such as VPT (Volume Processing Toolkit) and custom ray marching libraries [S2, unofficial][S3, unofficial].
