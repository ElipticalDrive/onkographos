# Deferred Shading for Isosurfaces

Also called: Curvature Estimation, Deferred Shading with Differential Properties, Differential Surface Properties Computation, Gradient and Hessian Estimation, Image-Space Shading

## Overview
Deferred Shading for Isosurfaces is a multi-pass image-space technique that decouples surface property computation from lighting by calculating position, gradient, Hessian, and curvature in separate rendering passes before applying shading [S1]. It solves the problem of achieving high-quality, physically-based shading and non-photorealistic effects on isosurfaces extracted from discrete scalar volumes without the overhead of reconstructing explicit triangle meshes [S1]. Unlike sibling methods that compute shading during ray-casting or rely on mesh generation, this approach computes differential properties in image space, making its complexity independent of the underlying grid size [S1].

## How it works
The method operates as a pipeline of five distinct rendering passes. Each pass renders a full-screen quad to invoke a fragment shader for every pixel, writing results to off-screen floating-point pixel buffers (textures) [S1].

### Inputs and Outputs
*   **Input:** A 3D scalar volume texture $V$.
*   **Intermediate Outputs:**
    *   Position image ($pos$): 3D coordinates of the isosurface intersection.
    *   Gradient image ($g$): RGB floating-point image storing $\nabla f$.
    *   Hessian image ($H$): Stored in two RGB floating-point images, storing the six unique second partial derivatives.
    *   Curvature images: Two floating-point targets storing principal curvatures ($\kappa_1, \kappa_2$) and directions ($e_1, e_2$).
*   **Final Output:** The shaded color image.

### Data Structures
*   **Volume Texture:** 3D texture containing the scalar field $f(x,y,z)$.
*   **1D Filter Weight Textures:** Used for tri-cubic B-spline convolution weights [S1].
*   **Off-screen Buffers:** Floating-point render targets (typically RGBA32F or similar) to store vector and matrix data per pixel.

### Numbered Steps

1.  **Pass 1: Ray-Casting (Position)**
    *   **Input:** Volume $V$.
    *   **Action:** Perform ray-casting to find the first intersection with the isosurface. Store the 3D world position of the intersection in the position image ($pos$) [S1].
    *   **Note:** This step typically requires 3 passes if using specific brick-based skipping optimizations, but fundamentally outputs the position [S1].

2.  **Pass 2: Gradient Computation**
    *   **Input:** Position image ($pos$), Volume $V$.
    *   **Action:** Compute the gradient $\mathbf{g} = \nabla f$ in three rendering passes (one for each component $g_x, g_y, g_z$) [S1].
    *   **Method:** For each component, evaluate a tri-cubic B-spline convolution sum. This requires 8 texture fetches from the 3D volume texture and 3 fetches from 1D filter weight textures [S1].
    *   **Output:** Store $\mathbf{g}$ in a single RGB floating-point image [S1].

3.  **Pass 3: Hessian Computation**
    *   **Input:** Position image ($pos$), Volume $V$.
    *   **Action:** Compute the Hessian matrix $\mathbf{H} = \nabla \mathbf{g}$ (second partial derivatives) in six rendering passes, one for each unique component ($f_{xx}, f_{yy}, f_{zz}, f_{xy}, f_{xz}, f_{yz}$) due to symmetry [S1].
    *   **Method:** Analogous to gradient computation, using tri-cubic filtering. Each pass uses either 11 or 14 texture fetches [S1].
    *   **Output:** Store the six coefficients in two RGB floating-point images [S1].

4.  **Pass 4: Curvature Estimation**
    *   **Input:** Gradient image ($\mathbf{g}$), Hessian images ($\mathbf{H}$).
    *   **Action:** Compute principal curvature magnitudes $\kappa_1, \kappa_2$ and directions $\mathbf{e}_1, \mathbf{e}_2$ in a single rendering pass [S1].
    *   **Formulas:**
        The shape operator $\mathbf{S}$ is defined as the tangent space projection of the normalized Hessian:
        $$ \mathbf{S} = \mathbf{P}^T \frac{\mathbf{H}}{|\mathbf{g}|} \mathbf{P} $$
        where $\mathbf{P} = \mathbf{I} - \frac{\mathbf{g}\mathbf{g}^T}{|\mathbf{g}|^2}$ is the projection matrix onto the tangent plane [S1].
        
        Let $\mathbf{A}$ be the $2 \times 2$ representation of $\mathbf{S}$ in the tangent basis. The principal curvatures are the eigenvalues of $\mathbf{A}$:
        $$ \kappa_{1,2} = \frac{1}{2} \left( \text{trace}(\mathbf{A}) \pm \sqrt{\text{trace}(\mathbf{A})^2 - 4 \det(\mathbf{A})} \right) $$
        [S1]
        
        The principal directions $\mathbf{e}_i$ in the tangent basis (defined by basis vectors $\mathbf{u}, \mathbf{v}$) are computed as:
        $$ \mathbf{e}_i = \kappa_i \mathbf{u} + (\kappa_i + a_{22} - a_{11}) \mathbf{v} $$
        [S1]
    *   **Output:** Store $\kappa_1, \kappa_2$ and $\mathbf{e}_1, \mathbf{e}_2$ in two floating-point targets [S1].

5.  **Pass 5: Shading**
    *   **Input:** Position ($pos$), Gradient ($\mathbf{g}$), Curvatures ($\kappa_1, \kappa_2, \mathbf{e}_1, \mathbf{e}_2$).
    *   **Action:** Render the final shaded image using the pre-computed properties [S1].
    *   **Effects:**
        *   **Blinn-Phong/Tone Shading:** Uses the normal vector $\mathbf{n} = \pm \mathbf{g}/|\mathbf{g}|$ [S1].
        *   **Curvature Color Mapping:** Maps $\kappa_1, \kappa_2$, mean curvature $(\kappa_1+\kappa_2)/2$, or Gaussian curvature $\kappa_1\kappa_2$ to colors via 1D or 2D lookup textures [S1].
        *   **Accessibility Shading:** Uses a 1D or 2D curvature transfer function to darken areas with large negative maximum curvature [S1].
        *   **Curvature-Aligned Flow Advection:** Projects 3D curvature direction vectors to the 2D image plane and advects flow on a per-pixel basis [S1].
        *   **Non-Photorealistic Effects:** Silhouette outlining (thickness controlled by curvature) and ridge/valley line depiction (specified in the $\kappa_1, \kappa_2$ domain) [S1].

### Pseudocode

```python
# Pass 1: Ray-Casting
def pass1_ray_casting(volume):
    # Output: pos_image (3D float)
    for each pixel (x, y):
        ray = generate_camera_ray(x, y)
        intersection = ray_cast_volume(ray, volume)
        pos_image[x, y] = intersection.position

# Pass 2: Gradient
def pass2_gradient(pos_image, volume):
    # Output: grad_image (3D float, RGB)
    # Compute one component per pass (gx, gy, gz)
    for component in [0, 1, 2]:
        for each pixel (x, y):
            p = pos_image[x, y]
            # Tri-cubic B-spline convolution for partial derivative
            # 8 fetches from volume, 3 from 1D filter weights
            val = tri_cubic_partial_derivative(volume, p, component)
            grad_image[x, y][component] = val

# Pass 3: Hessian
def pass3_hessian(pos_image, volume):
    # Output: hess_image_1, hess_image_2 (3D float, RGB each)
    # 6 unique components: fxx, fyy, fzz, fxy, fxz, fyz
    components = ['fxx', 'fyy', 'fzz', 'fxy', 'fxz', 'fyz']
    for i, comp in enumerate(components):
        for each pixel (x, y):
            p = pos_image[x, y]
            # 11 or 14 texture fetches depending on implementation
            val = tri_cubic_second_derivative(volume, p, comp)
            if i < 3:
                hess_image_1[x, y][i] = val
            else:
                hess_image_2[x, y][i-3] = val

# Pass 4: Curvature
def pass4_curvature(grad_image, hess_image_1, hess_image_2):
    # Output: curv_mag_image (2D float), curv_dir_image (2D float)
    for each pixel (x, y):
        g = grad_image[x, y]
        # Reconstruct Hessian matrix H from two RGB images
        H = reconstruct_hessian(hess_image_1[x, y], hess_image_2[x, y])
        
        norm_g = length(g)
        if norm_g < epsilon:
            curv_mag_image[x, y] = 0
            curv_dir_image[x, y] = 0
            continue
            
        # Shape operator S = P^T * (H / |g|) * P
        # P = I - (g * g^T) / |g|^2
        P = identity_matrix() - outer_product(g, g) / (norm_g * norm_g)
        S = transpose(P) @ (H / norm_g) @ P
        
        # Project S to 2x2 tangent basis A
        # Basis vectors u, v are orthogonal to g
        u, v = compute_tangent_basis(g)
        a11 = dot(u, S @ u)
        a12 = dot(u, S @ v)
        a21 = dot(v, S @ u)
        a22 = dot(v, S @ v)
        
        trace_A = a11 + a22
        det_A = a11 * a22 - a12 * a21
        
        discriminant = trace_A**2 - 4 * det_A
        if discriminant < 0:
            discriminant = 0
            
        sqrt_disc = sqrt(discriminant)
        
        k1 = 0.5 * (trace_A + sqrt_disc)
        k2 = 0.5 * (trace_A - sqrt_disc)
        
        curv_mag_image[x, y] = [k1, k2]
        
        # Principal directions in tangent basis
        e1_tangent = k1 * u + (k1 + a22 - a11) * v
        e2_tangent = k2 * u + (k2 + a22 - a11) * v
        
        curv_dir_image[x, y] = [e1_tangent, e2_tangent]

# Pass 5: Shading
def pass5_shading(pos_image, grad_image, curv_mag_image, curv_dir_image):
    # Output: final_image
    for each pixel (x, y):
        g = grad_image[x, y]
        k1, k2 = curv_mag_image[x, y]
        
        # Normal
        n = normalize(g)
        
        # Example: Blinn-Phong
        light_dir = ...
        view_dir = ...
        half_vec = normalize(light_dir + view_dir)
        diff = max(0, dot(n, light_dir))
        spec = pow(max(0, dot(n, half_vec)), shininess)
        
        color = ambient + diff * diffuse + spec * specular
        
        # Example: Curvature Mapping
        # color = map_curvature_to_color(k1, k2)
        
        final_image[x, y] = color
```

### Parameters and Edge Cases
*   **Filter Weights:** Tri-cubic B-spline filters are used for reconstruction [S1].
*   **Precision:** Floating-point render targets are required to store gradient, Hessian, and curvature data without quantization artifacts [S1].
*   **Degenerate Input:** If $|\mathbf{g}| \approx 0$ (flat regions or noise), the normal and curvature are undefined. A guard value (e.g., zero curvature) should be used [S1].
*   **Flow Advection Seams:** Curvature direction vectors are not uniquely oriented (sign ambiguity), which can cause visible seams in flow advection visualizations [S1].

## Operating characteristics
*   **Complexity:** The complexity is independent of the grid size, relying only on image-space operations [S1].
*   **Performance:** On an NVIDIA GeForce 6800, each property computation required 1 to 6 rendering passes, each rendering a single screen-aligned quad [S1].
*   **Memory:** Requires multiple floating-point off-screen buffers (position, gradient, Hessian, curvature) [S1].
*   **Strengths:** High-quality shading and non-photorealistic effects; decoupled from volume sampling; real-time rates for flow advection [S1].
*   **Limitations:** High number of rendering passes (up to 19 total including ray-casting); potential seams in flow advection due to orientation ambiguity [S1].
*   **When to use:** When high-quality differential property visualization (curvature, flow) is required for isosurfaces without mesh generation overhead [S1].

## Background
The method was introduced by Christoph Schüller, Daniel Weiskopf, and Thomas Ertl in their 2005 paper "Real-Time Ray-Casting and Advanced Shading of Discrete Isosurfaces" [S1]. It builds on earlier work in differential properties of volumes [SH05] and curvature estimation [KWTM03]. The technique is part of the broader field of image-space volume rendering and deferred shading.
