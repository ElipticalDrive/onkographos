# Depth-Gradient Shading

Also called: Z-buffer gradient shading

## Overview
Depth-Gradient Shading is an image-based shading technique that approximates the surface gradient by calculating differences between the depths of a given pixel and its neighbors in the z-buffer [S1, unofficial]. It solves the problem of computing lighting for isosurfaces without requiring explicit normal storage or complex object-space calculations, relying instead on the geometric information already present in the depth buffer [S1, unofficial]. It differs from its parent, [Normal-based Contextual Shading](6617-normal-based-contextual-shading.md), by operating in image space rather than object space, making it faster but prone to artifacts at object boundaries [S1, unofficial].

## How it works
**Inputs:**
- A rendered depth buffer (z-buffer) containing the depth values $z(x,y)$ for each pixel $(x,y)$ of the visible isosurface.
- The base color or material properties of the surface at each pixel.

**Outputs:**
- A shaded image with lighting effects derived from the estimated surface normals.

**Data Structures:**
- **Depth Buffer:** A 2D array of floating-point or fixed-point values representing the distance from the camera to the closest surface intersection for each pixel.

**Steps:**
1. **Sample Neighbors:** For each pixel $(x,y)$, retrieve its depth value $z(x,y)$ and the depth values of its immediate neighbors (typically the four cardinal neighbors: $(x-1,y), (x+1,y), (x,y-1), (x,y+1)$).
2. **Compute Depth Differences:** Calculate the finite differences in depth between the center pixel and its neighbors. Let $\Delta z_x$ be the difference in the x-direction and $\Delta z_y$ be the difference in the y-direction.
   $$ \Delta z_x = z(x+1, y) - z(x-1, y) $$
   $$ \Delta z_y = z(x, y+1) - z(x, y-1) $$
   [G] If the neighbors are not available (e.g., at image boundaries), clamp to the edge value or use one-sided differences.
3. **Estimate Gradient/Normal:** The depth differences approximate the surface gradient. The surface normal $\mathbf{n}$ can be estimated from the gradient vector. In a standard right-handed coordinate system where the z-axis points into the screen, the normal components are proportional to the negative depth gradients:
   $$ \mathbf{n} \approx \begin{bmatrix} \Delta z_x \\ \Delta z_y \\ -2 \end{bmatrix} $$
   [G] The denominator $-2$ comes from the central difference step size of 2 units. The normal must be normalized:
   $$ \mathbf{n}_{normalized} = \frac{\mathbf{n}}{\|\mathbf{n}\|} $$
4. **Lighting Calculation:** Use the estimated normal $\mathbf{n}_{normalized}$ to compute lighting (e.g., Phong or Lambertian shading) based on the light direction $\mathbf{L}$ and view direction $\mathbf{V}$.
   $$ I = K_d (\mathbf{n}_{normalized} \cdot \mathbf{L}) + K_s (\mathbf{R} \cdot \mathbf{V})^{\alpha} $$
   where $\mathbf{R}$ is the reflection vector.

**Parameters:**
- **Neighbor Offset:** Typically 1 pixel for immediate neighbors. Larger offsets can smooth noise but reduce detail.
- **Clamping:** Depth values should be clamped to valid ranges to prevent division by zero or invalid normals.

**Edge Cases and Pitfalls:**
- **Sharp Contours/Artifacts:** The method produces sharp contours (artifacts) when neighboring pixels show different objects or have drastic depth value jumps [S1, unofficial]. This occurs because the depth gradient becomes discontinuous at object boundaries or steep slopes.
- **Occlusion:** If a pixel is occluded, the depth value corresponds to the occluding object, not the intended surface, leading to incorrect normals.
- **Noise:** Depth buffers can contain noise, which amplifies when taking differences, leading to noisy shading.

**Pseudocode:**
```python
def depth_gradient_shading(depth_buffer, width, height, light_direction):
    """
    Computes shaded image using depth-gradient shading.
    
    Args:
        depth_buffer: 2D array of depth values [height][width]
        width: int, width of the image
        height: int, height of the image
        light_direction: 3D vector [lx, ly, lz]
        
    Returns:
        shaded_image: 2D array of RGB values [height][width]
    """
    shaded_image = np.zeros((height, width, 3))
    
    for y in range(height):
        for x in range(width):
            # Get depth of current pixel
            z_center = depth_buffer[y, x]
            
            # Get depths of neighbors, clamping to boundaries
            z_left = depth_buffer[y, max(0, x - 1)]
            z_right = depth_buffer[y, min(width - 1, x + 1)]
            z_up = depth_buffer[max(0, y - 1), x]
            z_down = depth_buffer[min(height - 1, y + 1), x]
            
            # Calculate depth differences (central differences)
            dz_dx = z_right - z_left
            dz_dy = z_down - z_up
            
            # Estimate normal vector
            # Assuming camera looks down -z axis, normal is [dz_dx, dz_dy, -2]
            # Note: The sign of z components depends on coordinate system.
            # Here we assume standard OpenGL-like: camera at origin, looking down -z.
            # Depth increases into the screen.
            normal = np.array([dz_dx, dz_dy, -2.0])
            
            # Normalize normal
            norm_length = np.linalg.norm(normal)
            if norm_length > 1e-6:
                normal = normal / norm_length
            else:
                normal = np.array([0.0, 0.0, 1.0]) # Default normal if undefined
            
            # Compute lighting (Lambertian diffuse)
            # Light direction should be normalized
            light_dir = light_direction / np.linalg.norm(light_direction)
            
            # Diffuse term
            diffuse = max(0.0, np.dot(normal, light_dir))
            
            # Simple shading: base color * diffuse
            # Assuming base color is white or stored separately
            base_color = np.array([1.0, 1.0, 1.0]) 
            shaded_image[y, x] = base_color * diffuse
            
    return shaded_image
```

## Subtopics

### [Depth-Gradient Shading with Ray-Layer Buffer](7010-depth-gradient-shading-with-ray-layer-buffer.md)
A technique to estimate surface gradients for shading by analyzing depth coherency in a ray-layer buffer, solving the problem of noisy shading in regions with low volume gradient magnitudes. It differs from its parent, [Depth-Gradient Shading](6618-depth-gradient-shading.md), by operating on the discrete layers of a multi-layer ray-casting buffer rather than a continuous z-buffer, allowing it to distinguish between different material surfaces encoded in the same pixel column.

### [Gradientless Shading via Pixel Textures](14491-gradientless-shading-via-pixel-textures.md)
Gradientless Shading via Pixel Textures is an image-based shading technique that approximates the diffuse lighting gradient by computing forward differences of scalar material values using OpenGL blending and pixel textures. It solves the problem of calculating surface normals for shading without storing or copying the entire frame buffer for gradient calculation, which is required by sibling methods like [Depth-Gradient Shading](6618-depth-gradient-shading.md). It sets itself apart by exploiting the rasterization pipeline's texture coordinate interpolation and pixel texturing to perform arithmetic on the frame buffer directly, rather than relying on explicit depth-difference calculations or texture lookups for gradients.

### Image-Space Bump Mapping
A modified bump mapping approach applied in image space only, avoiding the trivial task of transforming image-space normals back to world space under perspective projection. It uses gradient information from the composited image to modify surface normals for Phong lighting [S2, book].
**Steps:**
1. Calculate gradient $g(x,y) = \|\nabla(R+G)(x,y)\|$ from the Red and Green channels of the composited image [S2, book].
2. Exclude light $L_{x,y}$ and edge information $e_{x,y}$ from gradient calculation [S2, book].
3. Compute new surface normal as a weighted sum of the original surface normal and the gradient [S2, book].
4. Use this normal for Phong lighting $B_{x,y}$ [S2, book].
**Pitfall:** The blue color channel is not used for gradient calculation as it contains only lighting and edge information, which are handled separately [S2, book].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of pixels, as it requires a single pass over the depth buffer with constant-time neighbor lookups.
- **Memory Complexity:** $O(N)$ for the depth buffer and output image. No additional large data structures are required.
- **Strengths:** Simple to implement, fast, does not require explicit normal computation or storage during ray casting.
- **Limitations:** Prone to artifacts at object boundaries and depth discontinuities [S1, unofficial]. Sensitive to noise in the depth buffer. Does not account for object and slope discontinuities as well as context-sensitive methods [S1, unofficial].
- **When to Use:** Real-time applications where performance is critical and visual artifacts at boundaries are acceptable or can be mitigated by other means.
- **When Not to Use:** High-quality offline rendering where visual fidelity is paramount, or scenes with complex overlapping objects where depth discontinuities are frequent.

## Background
Depth-Gradient Shading was introduced as a simple 2D image-based shading technique for displaying shaded boundary isosurfaces without performing a shading procedure for the entire volume [S1, unofficial]. It is based on the idea that the depth buffer contains sufficient geometric information to approximate surface normals. The technique is discussed in the context of interactive volume-rendering techniques for medical data visualization [S1, unofficial]. Context-sensitive normal estimation was later proposed to avoid the sharp contour artifacts associated with depth-gradient shading [S1, unofficial].
