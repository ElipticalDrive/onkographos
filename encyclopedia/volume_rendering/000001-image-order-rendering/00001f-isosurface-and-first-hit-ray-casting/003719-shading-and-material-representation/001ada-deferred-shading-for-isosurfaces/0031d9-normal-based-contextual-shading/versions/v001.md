# Normal-based Contextual Shading

Also called: Contextual Shading

## Overview
Normal-based Contextual Shading is an object-space shading technique applied to isosurfaces to achieve higher visual quality than image-space depth-gradient shading [S1, unofficial]. It solves the problem of inaccurate surface normals in ray-casted volumes by fitting a local surface approximation to the set of closest intersection points, thereby estimating surface inclination more robustly [S1, unofficial]. It sets itself apart from its sibling [Surface shading for thresholded volumes](1159-surface-shading-for-thresholded-volumes.md) by explicitly using a larger voxel neighborhood to fit a function (linear or biquadratic) to the iso-surface points, rather than relying solely on immediate gradient calculations or thresholded binary data [S1, unofficial].

## How it works
**Inputs:**
- The set of closest intersection points for a given pixel or region on the iso-surface.
- The coordinates of these points in object space.
- A voxel neighborhood radius or size defining the local area for approximation.

**Outputs:**
- A normal vector for the shading calculation at the intersection point.
- Shaded color based on the estimated normal and lighting model.

**Data Structures:**
- A list or array of 3D points $(x_i, y_i, z_i)$ representing the iso-surface intersections within the defined neighborhood.
- Coefficients for the fitted function (linear or biquadratic).

**Steps:**
1. **Collect Points:** Gather the set of 3D points that belong to the same iso-surface within a larger voxel neighborhood around the point of interest [S1, unofficial].
2. **Fit Function:** Fit a linear or biquadratic function to these points to estimate the local surface geometry [S1, unofficial].
   - For a linear fit, approximate the surface as a plane $z = ax + by + c$.
   - For a biquadratic fit, approximate the surface as a higher-order polynomial to capture curvature [S1, unofficial].
3. **Estimate Normal:** Compute the normal vector from the gradient of the fitted function at the point of interest.
   - For a linear function $z = ax + by + c$, the normal is $\mathbf{n} = (-a, -b, 1)$ normalized.
   - For a biquadratic function, compute the partial derivatives with respect to $x$ and $y$ to find the gradient vector.
4. **Shade:** Apply a lighting model (e.g., Lambertian) using the estimated normal and the light direction $L$ [S1, unofficial].

**Formulas:**
The shaded color $C_{shaded}$ is computed using a Lambertian shading model:
$$C_{shaded} = C_{color} \cdot \frac{\nabla f(x, y, z)}{|\nabla f(x, y, z)|} \cdot L$$
where:
- $C_{color}$ is the intrinsic color of the voxel.
- $\nabla f(x, y, z)$ is the gradient of the fitted function $f$ at the point $(x, y, z)$, representing the surface normal.
- $L$ is the direction of the light source [S1, unofficial].

**Parameters:**
- **Voxel Neighborhood Size:** A larger voxel neighborhood is taken into account to estimate the surface inclination [S1, unofficial]. The exact size is not specified in the sources but must be large enough to capture the local surface geometry but small enough to avoid smoothing out fine details.

**Edge Cases and Pitfalls:**
- **Precision:** Fitting a function to noisy intersection points can lead to inaccurate normals if the neighborhood is too small or the points are sparse.
- **Boundaries:** At the edges of the volume or near discontinuities, the neighborhood may not have enough points, leading to undefined normals.
- **Degenerate Input:** If all points in the neighborhood are collinear or coplanar, the fit may be ill-conditioned.

**Pseudocode:**
```python
def normal_based_contextual_shading(intersection_points, neighborhood_radius, light_direction):
    """
    Estimate normal and compute shaded color using normal-based contextual shading.
    
    Args:
        intersection_points: List of 3D points (x, y, z) on the iso-surface.
        neighborhood_radius: Radius of the voxel neighborhood to consider.
        light_direction: 3D vector representing the light direction.
        
    Returns:
        shaded_color: The computed shaded color.
    """
    # Filter points within the neighborhood radius
    center_point = intersection_points[0]  # Assume first point is the center
    local_points = []
    for point in intersection_points:
        if distance(point, center_point) <= neighborhood_radius:
            local_points.append(point)
            
    if len(local_points) < 3:
        # Not enough points to fit a surface, use default normal or gradient
        return compute_default_normal_and_color(center_point, light_direction)
        
    # Fit a linear function z = ax + by + c to the local points
    # Using least squares to solve for a, b, c
    # Matrix form: [x y 1] * [a b c]^T = z
    A = []
    B = []
    for p in local_points:
        A.append([p.x, p.y, 1])
        B.append(p.z)
        
    # Solve for coefficients [a, b, c]
    coefficients = solve_least_squares(A, B)
    a, b, c = coefficients
    
    # Compute normal from linear fit: n = (-a, -b, 1)
    normal = normalize([-a, -b, 1])
    
    # Compute shaded color using Lambertian model
    # C_shaded = C_color * (normal . light_direction)
    # Assuming C_color is known or passed in
    # For simplicity, assume C_color is the color of the center point
    c_color = get_color_at_point(center_point)
    
    diffuse = max(dot(normal, light_direction), 0)
    shaded_color = c_color * diffuse
    
    return shaded_color

def solve_least_squares(A, B):
    """
    Solve the least squares problem Ax = B.
    
    Args:
        A: List of lists representing the design matrix.
        B: List representing the target values.
        
    Returns:
        x: Solution vector.
    """
    # Convert to numpy arrays for simplicity (standard math operation)
    import numpy as np
    A_np = np.array(A)
    B_np = np.array(B)
    
    # Use pseudo-inverse to solve
    x, _, _, _ = np.linalg.lstsq(A_np, B_np, rcond=None)
    return x

def distance(p1, p2):
    """Compute Euclidean distance between two 3D points."""
    return ((p1.x - p2.x)**2 + (p1.y - p2.y)**2 + (p1.z - p2.z)**2)**0.5

def normalize(v):
    """Normalize a 3D vector."""
    length = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    if length == 0:
        return [0, 0, 1]  # Default normal
    return [v[0]/length, v[1]/length, v[2]/length]

def dot(v1, v2):
    """Compute dot product of two 3D vectors."""
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

def get_color_at_point(point):
    """Get the color of the voxel at the given point."""

def compute_default_normal_and_color(point, light_direction):
    """Compute a default normal and color if fitting fails."""
```

## Subtopics

### Depth-Gradient Shading
An image-based shading technique that approximates the surface gradient by calculating differences between the depths of a given pixel and its neighbors in the z-buffer [S1, unofficial]. It is simpler to implement than object-space methods but produces sharp contour artifacts when neighboring pixels show different objects or have drastic depth value jumps [S1, unofficial]. Context-sensitive normal estimation is used to avoid these artifacts by accounting for object and slope discontinuities [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Time complexity depends on the number of points in the neighborhood and the cost of fitting the function. Fitting a linear function is $O(N)$ where $N$ is the number of points, while biquadratic is slightly higher.
- Memory complexity is proportional to the number of intersection points stored for each pixel.

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Performance scales with the size of the voxel neighborhood and the resolution of the volume.

**Strengths and Limitations:**
- **Strengths:** Provides more accurate surface normals than depth-gradient shading, leading to better visual quality. Object-space approach avoids artifacts from depth discontinuities.
- **Limitations:** Requires storing intersection points and performing local surface fitting, which can be computationally expensive. Sensitive to the choice of neighborhood size.

**When to Use:**
- Use when high-quality shading of isosurfaces is required and computational resources allow for object-space processing.

**When Not to Use:**
- Avoid when real-time performance is critical and the visual quality improvement is not necessary. Also avoid if the volume data is noisy, as it may affect the surface fit.

## Background
Normal-based Contextual Shading was introduced as an improvement over image-space depth-gradient shading for displaying shaded boundary isosurfaces in volume rendering [S1, unofficial]. It is part of the broader field of interactive volume-rendering techniques for medical data visualization [S1, unofficial]. The method builds on the idea of approximating local surface geometry to compute more accurate normals for lighting calculations.
