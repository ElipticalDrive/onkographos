# Multiple Flat Shaded Opaque Isosurfaces

Also called: Texture-map-based isosurface extraction, View-independent cell projection with alpha testing

## Overview
This method renders multiple opaque isosurfaces from an unstructured tetrahedral mesh without requiring explicit visibility sorting of the cells. It leverages a 2D texture map to identify isosurface fragments within each projected tetrahedron and uses a combination of the alpha test and the OpenGL z-test to guarantee correct occlusion. Unlike sibling methods that rely on geometric sorting or ray-marching refinement, this approach is view-independent and relies on fragment-level shading to handle multiple scalar values simultaneously.

## How it works
**Inputs:**
- A tetrahedral mesh where each tetrahedron $T$ has four vertices $v_0, v_1, v_2, v_3$.
- A scalar field value $s_i$ associated with each vertex $v_i$.
- A set of isovalue thresholds $\{s_{\text{iso}, k}\}$ for the desired isosurfaces.
- Lighting parameters: directional light vectors and diffuse colors.

**Outputs:**
- A 2D image where each pixel contains the color of the front-most isosurface fragment.

**Data Structures:**
- **Texture Map ($M$):** A 2D texture used to look up material properties based on the scalar values at the vertices of the projected tetrahedron.
  - The texture coordinates $(u, v)$ are derived from the scalar values of the tetrahedron vertices. Specifically, the texture map is indexed by the scalar values $s_f$ (scalar at the "front" vertex relative to view) and $s_b$ (scalar at the "back" vertex).
  - *Note:* The exact mapping of vertex scalars to texture coordinates is not explicitly defined in the source text, but it implies a lookup based on the range $[s_f, s_b]$ or similar. The source states the texture map is "modified to 'thicken' isosurfaces" to avoid gaps.
  - **Texel Layout:** Each texel stores:
    - RGB: Ambient material color of the isosurface corresponding to the specific isovalue.
    - Alpha: 1.0 if an isosurface is present at this scalar configuration; 0.0 otherwise.

**Numbered Steps:**

1.  **Vertex Processing:** For each tetrahedron in the mesh:
    a. Project the four vertices to screen space.
    b. Identify the "front" vertex $v_f$ and "back" vertex $v_b$ based on the viewing direction. The source defines visibility ordering: if $s_f < s_b$, the viewer looks along the gradient, so smaller isovalues occlude greater ones. If $s_f > s_b$, the order reverses.
    c. Retrieve the scalar values $s_f$ and $s_b$ from vertices $v_f$ and $v_b$.

2.  **Texture Lookup:**
    a. Use $s_f$ and $s_b$ as coordinates (or indices) to sample the texture map $M$.
    b. Let the result be $(C_{mat}, \alpha_{tex})$.
    c. The texture map is pre-computed such that:
       - If the isosurface condition is met (i.e., the ray through the tetrahedron intersects an isosurface), $\alpha_{tex} = 1.0$ and $C_{mat}$ is the assigned color for that isovalue.
       - If no isosurface is present in the tetrahedron for the current view configuration, $\alpha_{tex} = 0.0$.
    d. *Thickening:* The texture map is slightly modified (thickened) around the isovalue boundaries to prevent gaps between adjacent tetrahedra where the isosurface might otherwise be missed due to discretization or projection artifacts [S1].

3.  **Lighting Calculation:**
    a. Since the method does not provide interpolated gradients, lighting is calculated entirely in the vertex program (flat shading).
    b. For each directional light $L_j$:
       - Input: Light direction $\mathbf{d}_j$ (object coordinates) and diffuse color $\mathbf{c}_j$.
       - Operation: Compute diffuse contribution using the flat normal of the tetrahedron face or vertex. The source specifies "three vertex program operations per light" [S1].
    c. Combine ambient and diffuse contributions to form the final fragment color.

4.  **Fragment Shading and Occlusion:**
    a. For each fragment generated by the rasterizer:
       - Sample the texture map again (or use the interpolated value from step 2) to get $\alpha_{tex}$.
       - If $\alpha_{tex} == 0$, discard the fragment.
       - If $\alpha_{tex} == 1$, set the fragment's alpha to 1.0 (opaque) and color to the computed lit color.
    b. Enable the **Alpha Test** to discard fragments with alpha 0.
    c. Enable the **Z-Test** (depth test) to ensure that only the front-most isosurface fragment is written to the color buffer. This guarantees correct occlusion without sorting cells [S1].

5.  **Multiple Isosurfaces:**
    a. Assign a unique material color to each isovalue in the texture map.
    b. The visibility ordering is implicit: for $s_f < s_b$, smaller isovalues are rendered "in front" of greater isovalues because the texture map lookup returns the color of the isosurface that satisfies the condition first or is prioritized by the "thickening" and alpha test logic. The source states: "isosurfaces for smaller isovalues occlude those for greater isovalues" when $s_f < s_b$ [S1].

        # 3 operations per light: dot product, clamp, multiply
        diff = max(0, dot(N, L.direction))
        final_color += diff * L.diffuse

    if texel.alpha > 0:

**Parameters:**
- **Light Data:** Per light, two entries in the vertex program's attribute vector: light direction in object coordinates and diffuse light color [S1].
- **Lighting Cost:** Three vertex program operations per light [S1].

**Edge Cases and Pitfalls:**
- **Gaps between patches:** Without thickening the texture map, gaps may appear between isosurface patches in adjacent tetrahedra [S1].
- **No interpolated gradients:** The method is limited to flat shaded isosurfaces; it cannot provide smooth shading based on interpolated vertex normals [S1].
- **Visibility Ordering:** The occlusion behavior depends on the relative order of $s_f$ and $s_b$. If $s_f < s_b$, smaller isovalues occlude greater ones. If $s_f > s_b$, the reverse is true [S1].

## Subtopics

### Joint Rendering for Transparency
This variant addresses the rendering of multiple contour surfaces together to ensure transparency is handled correctly, particularly in engines like `rgl` that draw triangles in back-to-front order. Joint rendering is essential for standard and grid engines to maintain correct alpha blending when multiple isosurfaces intersect or overlap [S2].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of tetrahedra and lights. Each light adds a constant number of operations (3) per vertex/tetrahedron [S1].
- **Memory Complexity:** Dominated by the texture map size, which depends on the discretization of the scalar value space. The source does not specify the exact resolution or size of the texture map.
- **Strengths:**
  - No need for explicit cell sorting or visibility ordering [S1].
  - Supports a virtually arbitrary number of directional lights [S1].
  - Simple implementation using standard OpenGL features (alpha test, z-test) [S1].
- **Limitations:**
  - Limited to flat shading; no interpolated gradients [S1].
  - Requires a texture map lookup, which may have cache overhead.
  - "Thickening" may introduce slight geometric inaccuracies at the isosurface boundaries [S1].
- **When to use:** When rendering multiple opaque isosurfaces from unstructured tetrahedral meshes where view-independent performance is desired and flat shading is acceptable.
- **When not to use:** When smooth shading or high geometric precision is required, or when transparency blending is needed without joint rendering techniques [S1, S2].

## Background
This method was demonstrated in the context of hardware-based view-independent cell projection for unstructured grids. It builds on earlier work by Röttger et al. [14] and Stein et al. The approach was shown to be effective for rendering multiple isosurfaces without the overhead of sorting cells, as illustrated in Figure 11 of the source [S1].
