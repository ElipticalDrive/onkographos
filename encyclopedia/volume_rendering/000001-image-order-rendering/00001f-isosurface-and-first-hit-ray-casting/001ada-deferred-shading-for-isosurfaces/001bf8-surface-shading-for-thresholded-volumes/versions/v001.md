# Surface shading for thresholded volumes

Also called: Boundary normal estimation, Z-buffer shading

## Overview
Surface shading for thresholded volumes applies lighting models to isosurfaces extracted from scalar volumes by determining surface geometry and illumination in image space or via rasterization hardware, distinct from direct volume rendering shading [S1, unofficial]. It sets itself apart from sibling methods like [Deferred Shading for Isosurfaces](867-deferred-shading-for-isosurfaces.md) by avoiding the high memory and computational costs of per-ray cell storage or repeated neighbor-finding, often relying on z-buffer slopes or precomputed gradients rather than deferred multi-pass normal accumulation [S2, S3, unofficial].

## How it works
The method determines surface appearance for pixels where a ray intersects an isosurface defined by a threshold $f(X) = c$. The core challenge is estimating the surface normal $\mathbf{n}$ and applying a lighting model, typically Lambertian, without the overhead of full deferred shading.

### Inputs and Outputs
*   **Input:** Scalar volume data $f(x,y,z)$, threshold value $c$, light direction $\mathbf{l}$, ambient intensity $I_a$, diffuse intensity $I_d$, and depth buffer (z-buffer) or position/gradient buffers.
*   **Output:** Final color $C$ for each pixel.

### Data Structures
1.  **Z-Buffer:** Stores depth $z$ of the first hit for each pixel.
2.  **Position Buffer (Optional):** Stores 3D intersection point $\mathbf{p}$ and distance $d$ (if available from a previous pass).
3.  **Gradient Buffer (Optional):** Stores precomputed voxel gradients $\nabla f$ in RGB components of a texture or frame buffer [S3, unofficial].

### Normal Estimation Methods
Normals can be estimated using one of three approaches [S1, unofficial]:

1.  **Projected Slope (Z-buffer based):**
    Compute the slope of the projected surface using z-buffer values at neighboring pixels $(x \pm 1, y)$ and $(x, y \pm 1)$.
    $$ n_x \approx \frac{z(x+1, y) - z(x-1, y)}{2}, \quad n_y \approx \frac{z(x, y+1) - z(x, y-1)}{2} $$
    The normal is $\mathbf{n} = (-n_x, -n_y, 1)$ normalized [S1, unofficial].

2.  **Geometry (Boundary-based):**
    Determine orientation from the cube face and its neighbors in the boundary of the opaque volume. This requires knowing which voxel face was intersected and its adjacency [S1, unofficial].

3.  **Gradient (Finite Differences):**
    Compute the gradient of $f(X)$ using finite differences at neighboring voxels.
    $$ \nabla f \approx \left( \frac{f(x+h, y, z) - f(x-h, y, z)}{2h}, \dots \right) $$
    The normal is $\mathbf{n} = \nabla f / \|\nabla f\|$ [S1, unofficial].

### Shading Models

#### 1. Depth-based Shading
Shades distant pixels darker using only z-buffer depth values.
$$ C = I_a + I_d \cdot \frac{z_{max} - z}{z_{max} - z_{min}} $$
where $z$ is the depth, and $z_{min}, z_{max}$ are near and far plane depths [S1, unofficial].

#### 2. Lambertian Shading (Standard)
Uses the estimated normal $\mathbf{n}$ and light direction $\mathbf{l}$.
$$ I = I_a + I_d (\mathbf{n} \cdot \mathbf{l}) $$
where $\mathbf{n}$ is the normalized normal and $\mathbf{l}$ is the normalized light vector [S3, unofficial].

#### 3. Proximity Shading
Renders a surface proximity map by normalizing the logarithmic distance to the surface.
$$ P = \left( \frac{\log(d) - \min(\log)}{\max(\log) - \min(\log)} \right)^{1/2.33} $$
where $d$ is the surface distance, clamped to $[10^{-2}, \infty)$ before logging [S2, unofficial].

### Implementation Steps (General Pipeline)
1.  **Thresholding:** Render the volume to identify isosurface intersections. This can be done via raycasting or rasterization with alpha testing [S3, unofficial].
2.  **Buffer Population:**
    *   Store depth in Z-buffer.
    *   Optionally store position $\mathbf{p}$ and/or gradient $\nabla f$ in auxiliary buffers [S4, unofficial].
3.  **Normal Computation:**
    *   If using Z-buffer: Compute slopes from neighboring depth values [S1, unofficial].
    *   If using Gradient Buffer: Read $\nabla f$ directly [S4, unofficial].
    *   If using Raycasting: Compute $\nabla f$ via finite differences at intersection point [S4, unofficial].
4.  **Lighting Calculation:**
    *   Compute $\mathbf{n} = \text{normalize}(\text{estimated normal})$.
    *   Compute diffuse term $D = \max(\mathbf{n} \cdot \mathbf{l}, 0)$.
    *   Apply material color $M$ (from transfer function or constant).
    *   $C = M \cdot (I_a + I_d \cdot D)$.
5.  **Output:** Write $C$ to frame buffer.

### Pseudocode (Gradient-based Lambertian Shading)
```python
def surface_shading_thresholded(volume, threshold, light_dir, ambient_intensity, diffuse_intensity, gradient_step):
    """
    Computes surface shading for a thresholded volume using gradient-based normals.
    Assumes a previous pass has identified intersection points.
    """
    # 1. Identify intersection points (simplified: assume we have a list of hits)
    # In practice, this is done via raycasting or rasterization alpha-test.
    hits = find_isosurface_hits(volume, threshold)
    
    output_image = zeros_like(volume.shape[:2]) # 2D image
    
    for hit in hits:
        pos = hit.position
        # 2. Compute gradient using central differences
        grad_x = (volume[pos.x + gradient_step, pos.y, pos.z] - 
                  volume[pos.x - gradient_step, pos.y, pos.z]) / (2.0 * gradient_step)
        grad_y = (volume[pos.x, pos.y + gradient_step, pos.z] - 
                  volume[pos.x, pos.y - gradient_step, pos.z]) / (2.0 * gradient_step)
        grad_z = (volume[pos.x, pos.y, pos.z + gradient_step] - 
                  volume[pos.x, pos.y, pos.z - gradient_step]) / (2.0 * gradient_step)
        
        gradient = vec3(grad_x, grad_y, grad_z)
        normal = normalize(gradient)
        
        # 3. Compute Lambertian diffuse factor
        # Ensure light_dir is normalized
        light = normalize(light_dir)
        lambert = max(dot(normal, light), 0.0)
        
        # 4. Sample material color (simplified: constant or from transfer function)
        # For thresholded volumes, material is often uniform or based on value
        material_color = vec3(1.0) # Placeholder for transfer function lookup
        
        # 5. Final color
        color = material_color * (ambient_intensity + diffuse_intensity * lambert)
        
        # 6. Write to image
        output_image[hit.screen_x, hit.screen_y] = color
        
    return output_image
```

### Edge Cases and Pitfalls
*   **No Hit:** If no surface is intersected (e.g., `closest.w <= 0.0`), output a default color (e.g., white or background) [S4, unofficial].
*   **Gradient Noise:** Finite difference gradients can be noisy in low-resolution volumes. Smoothing or higher-order differences may be needed [S1, unofficial].
*   **Z-buffer Slopes:** Estimating normals from z-buffer slopes assumes smooth surfaces; sharp edges may produce incorrect normals [S1, unofficial].
*   **Lighting Limitations:** Hardware-based methods (e.g., using OpenGL color matrix) may be restricted to single light sources and monochrome displays if register space is limited [S3, unofficial].
*   **Distinct from DVR:** These shading functions are applied *after* thresholding and are distinct from direct volume rendering shading [S1, unofficial].

## Subtopics

### [Shading and Frame Buffer Filling](1808-shading-and-frame-buffer-filling.md)
A method that performs fast, shadow-less Lambertian shading for isosurfaces extracted from thresholded volumes. It distinguishes itself by explicitly avoiding deferred normal computation to prevent prohibitive memory and computational costs associated with per-ray cell storage or repeated neighbor-finding. While the underlying ray traversal remains single-ray based, the shading phase aggregates rays into packets to exploit parallelism.

### [Volume Raycasting with Surface Extraction and Phong Shading](3662-volume-raycasting-with-surface-extraction-and-phong-shading.md)
A volume rendering technique that extracts surfaces from a 3D volume using a threshold and renders them using raycasting with Phong illumination, operating on multiple object volumes simultaneously.

### Proximity Shading
A visualization technique that renders a surface proximity map by normalizing the logarithmic distance to the surface [S2, unofficial]. It visualizes precomputed surface distances using log normalization and gamma correction, identical in formula to Distance Shading but operating on a distance scalar field [S2, unofficial].
**Step:** Calculate the SDF value $f(p_i)$ at the intersection point. Compute $\log(f(p_i))$. Normalize this value to the range $[0, 1]$. Brighter pixels indicate rays that terminated further away from the surface [S2, unofficial].
**Formula:** $P = \left( \frac{\log(d) - \min(\log)}{\max(\log) - \min(\log)} \right)^{1/2.33}$, where $d$ is surface distance, clamped to $[10^{-2}, \infty)$ before logging [S2, unofficial].

### Shading for Isosurfaces (Single-Pass Multi-Stage)
A single-pass rendering technique for shaded isosurfaces using multi-stage rasterization, eliminating the need for frame buffer copying and allowing colored ambient and diffuse light sources [S3, unofficial].
**Step:** Map the interpolated gradient to the first constant color register (variable A in the final combiner's primary color context). Variable A is assigned to primary color ($I_d$) and multiplied with variable B mapped to the dot product. Compute the dot product of the light vector and the gradient in the RGB-portion of the second general combiner. Set variable C to zero and map variable D to secondary color ($I_a$) for the final combiner to compute the equation: $I_d \cdot (L \cdot N) + I_a$ [S3, unofficial].
**Pitfall:** It is not possible to write initial values to the two spare registers displayed in Fig. 2, limiting the ability to add a second diffuse light source without sacrificing trilinear interpolation or separate ambient/diffuse colors [S3, unofficial].

### Fast Shaded Isosurfaces
An efficient algorithm to display shaded isosurfaces by exploiting rasterization hardware, evaluating local illumination equation. Restricted to single light source and monochrome display [S3, unofficial].
**Step:** Store voxel gradient vector components in RGB components of a 3D-texture. Store intensity values in the alpha-component. Render into frame buffer using OpenGL alpha-test to display specified isovalues. Reinsert the frame buffer (containing voxel gradient in RGB) into the rasterization pipeline. Use OpenGL color matrix to compute dot-product with light vector. This is a two-pass technique [S3, unofficial].
**Formula:** Local illumination: $I = I_a + I_d \times (\tilde{n} \cdot \tilde{l})$, where $\tilde{l}$ is light direction, $\tilde{n}$ is isosurface normal (volume gradient), $I_a$ is ambient intensity, $I_d$ is diffuse intensity [S3, unofficial].

### Isosurface Shading (VPT)
A shading pass that computes lighting for the isosurface found in the previous pass, using gradient-based normals and Lambertian shading [S4, unofficial].
**Step:** Sample the closest position buffer. Compute gradient using central differences: positive samples at `pos + vec3(h,0,0)`, etc., negative samples at `pos - vec3(h,0,0)`, etc. Gradient is `(positive - negative) / (2.0 * h)`. Normalize gradient to get normal. Compute Lambertian diffuse factor: `float lambert = max(dot(normal, uLight), 0.0)`. Sample material color from transfer function using volume position. Output final color: `oColor = vec4(material * lambert, 1)` [S4, unofficial].
**Parameter:** `uGradientStep`: The step size `h` used for finite difference gradient calculation. `uLight`: The light direction vector [S4, unofficial].
**Pitfall:** If `closest.w <= 0.0` (no hit), output white `vec4(1)` [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the normal estimation method. Z-buffer slope estimation is $O(1)$ per pixel (constant number of neighbors). Gradient estimation via finite differences is $O(1)$ per hit if gradients are precomputed, or $O(N)$ if computed on-the-fly during raycasting.
*   **Memory Complexity:** Z-buffer shading requires only a depth buffer. Gradient-based methods may require storing gradients in a texture or buffer, increasing memory usage by $3 \times$ the resolution (for RGB gradients) [S3, unofficial].
*   **Performance:** Hardware-accelerated methods (e.g., Fast Shaded Isosurfaces) can achieve interactive frame rates by leveraging rasterization pipelines [S3, unofficial]. Deferred shading methods are more flexible but slower due to multiple passes.
*   **Strengths:** Simple to implement for basic shading; efficient for static scenes; leverages existing graphics hardware.
*   **Limitations:** Limited lighting models (often Lambertian only); single light source restrictions in some hardware implementations; normal estimation errors at boundaries or noisy data.
*   **When to Use:** Real-time visualization of isosurfaces where performance is critical and complex lighting is not required.
*   **When Not to Use:** When accurate, high-quality lighting with multiple light sources and shadows is needed; consider [Deferred Shading for Isosurfaces](867-deferred-shading-for-isosurfaces.md) or raytracing.

## Background
The technique originated with the need for efficient visualization of medical and scientific data, particularly bone and tissue structures [S1, unofficial]. Early methods relied on z-buffer slopes for simplicity [S1, unofficial]. Later, with the advent of programmable graphics hardware, methods like Fast Shaded Isosurfaces exploited rasterization pipelines for interactive performance [S3, unofficial]. The approach is distinct from direct volume rendering, focusing on the surface properties of thresholded data rather than the volumetric integration of light [S1, unofficial].
