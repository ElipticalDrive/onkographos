# GVDB Raycasting with Binary Search Surface Tracing

Also called: GVDB Shading and Screen-Space Flow/Depth, custom_iso_kernel shading, flow computation, raySurfaceTrilinearBrickCustom

## Overview
This method is a GPU raycasting kernel that traces rays through a GVDB sparse voxel dataset to find the first surface intersection using fixed-step marching followed by a binary search, then computes surface properties [S1, unofficial]. It is distinguished from sibling methods by its integration of screen-space flow computation and ambient occlusion directly within the surface tracing kernel, rather than relying on separate post-processing passes or mesh extraction [S1, unofficial]. It builds on [Isosurface and first-hit ray casting](20-isosurface-and-first-hit-ray-casting.md).

## How it works
**Inputs and Outputs:**
*   **Inputs:** GVDB sparse voxel dataset (`gvdb`), view matrices (current and next), light direction (`lightDir`), eye direction (`eyedir`), isosurface threshold (`SCN_THRESH`), fixed step size (`SCN_PSTEP`), binary search iterations (`binarySearchSteps`), specular exponent (`specularExponent`), viewport bounds (`viewport`).
*   **Outputs:** Per-pixel hit point, normal, color, flow vector, depth, and ambient occlusion value.

**Data Structures:**
*   **GVDB Dataset:** Contains node structures with minimum bounds (`v_min`), voxel size (`v_del`), and resolution (`res`). Nodes are accessed via `getNodeAtPoint`.
*   **Atlas Offset:** Per-node offset (`o`) for texture sampling.
*   **Ray State:** Origin (`rpos`), direction (`rdir`), current distance (`tCurrent`).

**Numbered Steps:**

1.  **Ray Initialization:** For each pixel within the `viewport` range `[minX, minY, maxX, maxY]`, compute ray origin `rpos` and direction `rdir` from the current view matrix.
2.  **Ray Marching:** Call `raySurfaceTrilinearBrickCustom`.
    *   Get the leaf node and atlas offset `o` for the current ray position.
    *   Convert world position `p_world` to index coordinates `p` using:
        $$ p = \frac{\text{world\_pos} - v_{min}}{v_{del}[0]} $$
        where $v_{min}$ is node minimum bounds and $v_{del}[0]$ is voxel size [S1, unofficial].
    *   Step ray by `SCN_PSTEP`. Check texture value `tex3D` against `SCN_THRESH`.
    *   If `tex3D >= SCN_THRESH`, the ray is inside the volume. Record the previous position (`tLower`) and current position (`tUpper`) to bracket the surface.
    *   If the ray exceeds volume bounds (`p.x/y/z < 0` or `>= gvdb->res[0]`) or hits an invalid node, terminate and return no hit [S1, unofficial].
3.  **Binary Search Refinement:** Perform `binarySearchSteps` iterations to find the closest point outside the isosurface [S1, unofficial].
    *   Initialize `tLower` to the last position outside the volume and `tUpper` to the first position inside.
    *   For each iteration `i`:
        $$ tMiddle = 0.5 \cdot (tLower + tUpper) $$
        $$ p = pStart + tMiddle \cdot dir $$
        If `tex3D(p) >= SCN_THRESH`, set `tUpper = tMiddle`. Else, set `tLower = tMiddle`.
    *   Final hit point: $p = pStart + tLower \cdot dir$ [S1, unofficial].
4.  **Surface Property Computation:**
    *   **Normal:** Compute via `getGradient` at the hit point.
    *   **Color:** Compute via `getColorF` at the hit point.
5.  **Shading:**
    *   Start with `ambientColor`.
    *   **Diffuse:** Add `diffuseColor * abs(dot(norm, lightDir))` [S1, unofficial].
    *   **Specular:** Compute reflection vector $R = \text{normalize}(\text{reflect3}(lightDir, norm))$. Add specular term:
        $$ \text{specular} = c_{spec} \cdot \frac{\alpha + 2}{6.82} \cdot \max(0, R \cdot E)^\alpha $$
        where $c_{spec}$ is specular color, $\alpha$ is `specularExponent`, $R$ is reflection vector, $E$ is eye direction [S1, unofficial].
6.  **Flow Computation:**
    *   Project hit point to screen space using current view matrix to get `screenCurrent`.
    *   Project hit point to screen space using next view matrix to get `screenNext`.
    *   Compute flow:
        $$ \text{flow} = 0.5 \cdot (\text{screenCurrent} - \text{screenNext}) $$
        where coordinates are normalized [S1, unofficial].
7.  **Depth and AO:**
    *   Compute depth from `screenCurrent.z`.
    *   Compute ambient occlusion via `computeAmbientOcclusion` [S1, unofficial].
8.  **Output:** Write hit point, normal, color, flow, depth, and AO to the output buffer.

**Pseudocode:**

```python
def raySurfaceTrilinearBrickCustom(gvdb, rpos, rdir, SCN_PSTEP, SCN_THRESH, binarySearchSteps, viewport):
    # Initialize ray
    tCurrent = 0.0
    pStart = rpos
    dir = rdir
    
    # Ray marching loop
    while True:
        # Check viewport bounds
        if not is_pixel_in_viewport(viewport):
            return None
            
        # Get node and offset
        node = getNodeAtPoint(gvdb, pStart + tCurrent * dir)
        if node is None:
            return None # Invalid node
            
        o = node.atlas_offset
        v_min = node.v_min
        v_del = node.v_del
        res = gvdb.res[0]
        
        # Convert to index coordinates
        p_world = pStart + tCurrent * dir
        p = (p_world - v_min) / v_del[0]
        
        # Check bounds
        if p.x < 0 or p.x >= res or p.y < 0 or p.y >= res or p.z < 0 or p.z >= res:
            return None
            
        # Sample texture
        val = tex3D(gvdb.volIn, p.x + o.x, p.y + o.y, p.z + o.z)
        
        if val >= SCN_THRESH:
            # Inside volume, perform binary search
            tLower = tCurrent - SCN_PSTEP
            tUpper = tCurrent
            
            for i in range(binarySearchSteps):
                tMiddle = 0.5 * (tLower + tUpper)
                p_mid = pStart + tMiddle * dir
                p_mid_idx = (p_mid - v_min) / v_del[0]
                
                # Check bounds for mid point
                if p_mid_idx.x < 0 or p_mid_idx.x >= res or p_mid_idx.y < 0 or p_mid_idx.y >= res or p_mid_idx.z < 0 or p_mid_idx.z >= res:
                    tUpper = tMiddle
                    continue
                    
                val_mid = tex3D(gvdb.volIn, p_mid_idx.x + o.x, p_mid_idx.y + o.y, p_mid_idx.z + o.z)
                
                if val_mid >= SCN_THRESH:
                    tUpper = tMiddle
                else:
                    tLower = tMiddle
            
            # Final hit point
            hit_point = pStart + tLower * dir
            return hit_point
        else:
            # Outside volume, step forward
            tCurrent += SCN_PSTEP
            if tCurrent > MAX_DISTANCE: # [G] Max distance guard
                return None

def compute_shading(hit_point, norm, lightDir, eyedir, specularExponent):
    # Diffuse
    diffuse = diffuseColor * abs(dot(norm, lightDir))
    
    # Specular
    R = normalize(reflect3(lightDir, norm))
    specular = specularColor * ((specularExponent + 2) / 6.82) * pow(max(0.0, dot(R, eyedir)), specularExponent)
    
    return ambientColor + diffuse + specular

def compute_flow(hit_point, viewCurrent, viewNext):
    screenCurrent = project_to_screen(hit_point, viewCurrent)
    screenNext = project_to_screen(hit_point, viewNext)
    flow = 0.5 * (screenCurrent - screenNext)
    return flow
```

**Parameters:**
*   `SCN_PSTEP`: Fixed step size for ray marching.
*   `SCN_THRESH`: Isosurface threshold value.
*   `binarySearchSteps`: Number of binary search iterations, typically 10.
*   `specularExponent`: Shininess exponent for specular highlight.
*   `viewport`: Valid pixel range `[minX, minY, maxX, maxY]`.

**Edge Cases and Pitfalls:**
*   Ray marching may exceed volume bounds or hit invalid nodes. Handled by checking `p.x/y/z >= 0` and `< gvdb->res[0]`, and checking if `getNodeAtPoint` returns `nullptr` [S1, unofficial].
*   Precision issues in binary search may occur if `SCN_PSTEP` is too large relative to voxel size.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of steps in ray marching plus logarithmic with respect to precision for binary search.
*   **Memory Complexity:** Low, as it operates per-pixel and does not require large auxiliary buffers beyond the GVDB structure.
*   **Strengths:** Efficient for sparse voxel datasets; integrates shading and flow computation in a single pass.
*   **Limitations:** Fixed step size may lead to aliasing or missed thin structures if not tuned properly.
*   **When to use:** Real-time visualization of sparse volumetric data with surface properties.
*   **When not to use:** Dense volumes where marching is too slow, or when high-precision surface reconstruction is required without post-processing.

## Background
This method originates from the GVDB (GPU Volume Database) project, specifically the `custom_iso_kernel` implementation [S1, unofficial]. It is used in interactive volume visualization tools that require real-time surface rendering and flow analysis.
