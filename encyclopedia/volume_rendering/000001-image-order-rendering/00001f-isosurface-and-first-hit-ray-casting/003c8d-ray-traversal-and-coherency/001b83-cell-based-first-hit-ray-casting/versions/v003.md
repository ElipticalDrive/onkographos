# Cell-Based First-Hit Ray Casting


## Overview
Cell-based first-hit ray casting is a volume rendering technique that accelerates isosurface extraction by dividing the volume into cubic sub-volumes called macro-cells, storing them in a min-max octree, and projecting only those containing iso-surface portions to the image plane [S1, unofficial][S2]. It differs from conventional ray casting by drastically reducing average ray path lengths through early termination and local ray casting within trimmed macro-cells, and from surface-fitting methods by supporting interactive threshold adjustment without dedicated acceleration hardware [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset, a camera position and orientation, an image resolution (e.g., $512 \times 512$), and one or more isovalue thresholds $\tau$ [S1, unofficial].
*   **Output:** A 2D image where each pixel contains the color of the first iso-surface intersection along the corresponding view ray [S1, unofficial].

**Data Structures:**
1.  **Min-Max Octree:**
    *   The volume is divided into cubic sub-volumes called macro-cells [S1, unofficial].
    *   Each macro-cell consists of $n^3$ data cells (where $n$ is typically between 3 and 10) [S1, unofficial][S2].
    *   The octree nodes store the minimum ($min$) and maximum ($max$) data values of the sub-space they represent [S1, unofficial][S2].
    *   Leaf nodes represent the macro-cells [S1, unofficial][S2].
2.  **Pixel Buffer:**
    *   Stores the final color for each pixel [S1, unofficial].
    *   Tracks which pixels have already been assigned a color to enable early termination [S1, unofficial].
3.  **Inter-Ray Coherency Buffer (Optional Optimization):**
    *   Stores cells encountered along the last ray and a flag indicating if an iso-surface portion is contained there [S1, unofficial].
    *   Avoids unnecessary intersection tests for rays visiting the same cells [S1, unofficial].
    *   Distance coding is not used as it would require recomputation for each new iso-value [S1, unofficial].

**Algorithm Steps:**
1.  **Octree Construction:** Divide the volume into macro-cells of size $n^3$ [S1, unofficial]. Build the min-max octree. For each node, compute $min$ and $max$ of the data values in its sub-space [S1, unofficial][S2].
2.  **Octree Traversal and Macro-Cell Selection:** Traverse the octree starting from the root [S1, unofficial][S2]. For a current node, check if any isovalue $\tau$ satisfies $min \le \tau \le max$ [S1, unofficial][S2]. If the condition is false, prune the node because the iso-surface does not pass through this sub-space [S1, unofficial][S2]. If true, process the 8 child nodes [S1, unofficial]. Child nodes must be processed in viewing order to ensure correct visibility (first-hit) [S1, unofficial][S2]. A representative ray direction vector intersecting all sub-volumes is used to sort the 8 children of the current node [S1, unofficial].
3.  **Macro-Cell Trimming and Projection:** When a leaf node (macro-cell) passes the min-max check, it contains part of the iso-surface [S2]. Trim the macro-cell to the smallest cuboid containing its portions of the iso-surfaces [S2]. This reduces the projection area [S1, unofficial]. Project the trimmed macro-cell onto the screen plane [S1, unofficial][S2]. Rasterize the projection to identify all pixels covered by the macro-cell [S1, unofficial][S2].
4.  **Local Ray Casting:** For each pixel covered by the projection that has not yet been assigned a color, cast a local ray through the macro-cell [S1, unofficial][S2]. The ray starts at the entry point into the macro-cell and stops when it leaves the macro-cell or hits an iso-surface [S1, unofficial]. Use a fast voxel traversal algorithm (e.g., Amanatides and Woo) to detect cells pierced by the ray [S1, unofficial][S2]. For each intersected cell, determine if it is a boundary cell (contains data values both above and below $\tau$) [S1, unofficial]. If it is a boundary cell, perform a ray-surface intersection test [S1, unofficial][S2].
5.  **Ray-Surface Intersection:** Use the fast intersection method: divide the ray segment passing through the surface cell into two equal parts [S1, unofficial]. Calculate density values at the endpoints of each part [S1, unofficial]. If an iso-surface intersection exists in a part, approximate the intersection point using linear interpolation [S1, unofficial]. This is computationally cheaper than exact inversion of trilinear interpolation but yields slightly less accurate results, though differences are often not visible [S1, unofficial]. Alternatively, invert trilinear interpolation to find all points on the ray with density $\tau$ and select the first point inside the cell [S1, unofficial].
6.  **Shading and Termination:** If an intersection is found, calculate the gradient vector $\nabla f$ at the intersection point using trilinear interpolation [S1, unofficial][S2]. Compute the color using a local lighting model (e.g., Phong) based on the gradient [S1, unofficial][S2]. Assign the color to the pixel [S1, unofficial][S2]. If the iso-surface is opaque, mark the pixel as done so no more local rays are cast at this pixel during the current frame [S2]. If a ray leaves the macro-cell without hitting an iso-surface, and the pixel is not yet colored, it may still be processed [S1, unofficial]. Early scanline termination can eliminate local rays that are highly probable not to find intersections, further reducing ray counts [S1, unofficial].

**Parameters:**
*   $n$: Macro-cell dimension parameter. Typical values: 3 to 10 [S1, unofficial][S2].
*   $\tau$: Iso-value threshold. Example: 0 HU (soft tissue) to 1100 HU (stent) [S1, unofficial].
*   Image Resolution: Example: $512 \times 512$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Macro-Cell Size:** Small $n$ increases octree traversal and projection time, splits rays into more segments, increases local rays, and increases expensive ray initialization steps for rays traveling along iso-surfaces without intersecting [S1, unofficial]. Large $n$ reduces the effectiveness of early scanline termination because small critical regions are less likely to be detected [S1, unofficial].
*   **Viewing Order:** Ray segments must be processed in correct viewing order to ensure the first intersection determines the final pixel color. Failure to sort child nodes by viewing vector causes visibility artifacts [S1, unofficial][S2].
*   **Low Thresholds:** When soft tissue (low threshold) hides deeper structures, conventional ray casting may be faster because ray-surface distances are short. Cell-based methods suffer because almost all macro-cells must be processed, and fine-structured tissue creates "peep holes" that delay termination [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of macro-cells intersecting the iso-surface and the local ray casting cost. Generally faster than conventional ray casting for high thresholds or when the iso-surface is sparse [S1, unofficial].
*   **Memory Complexity:** Requires storage for the min-max octree and the volume data. The octree size is proportional to the number of macro-cells [S2].
*   **Measured Performance:** Virtual angioscopy (stented aorta) minimum frame time is 1.103s (Cell-based) vs 1.783s (Conventional) [S1, unofficial]. Average frame time is 1.291s (Cell-based) vs 2.119s (Conventional) [S1, unofficial]. At a 450 HU threshold, cell-based takes 1.953s and conventional takes 8.563s (Speedup: 4.38x) [S1, unofficial]. At a 1100 HU threshold, cell-based takes 0.609s and conventional takes 12.781s (Speedup: 20.98x) [S1, unofficial].
*   **Ray Path Reduction:** Conventional ray casting uses 262,144 rays, 1 ray/pixel, and 35.494 steps/pixel [S1, unofficial]. Cell-based uses 1,147,347 rays, 4.376 rays/pixel, and 15.626 steps/pixel [S1, unofficial]. Cell-based with trimming and early termination uses 396,808 rays, 1.513 rays/pixel, and 3.932 steps/pixel [S1, unofficial].
*   **Strengths:** Significantly faster than conventional ray casting for sparse iso-surfaces or high thresholds [S1, unofficial]. Exploits cache coherency by accessing each macro-cell only once per frame [S1, unofficial]. Supports interactive threshold adjustment [S1, unofficial].
*   **Limitations:** Slower than conventional ray casting when the iso-surface is dense and close to the camera (e.g., low threshold hiding deep structures) [S1, unofficial]. Requires careful tuning of macro-cell size $n$ [S1, unofficial]. Does not support distance coding for inter-ray coherency due to iso-value dependency [S1, unofficial].

## Background
*   **Origin:** Proposed by André Neubauer, Lukas Mroz, H. Hauser, and R. Wegenkittl in 2002 [S1, unofficial].
*   **History:** Developed as part of the AlVis project for visualization of aluminium foam samples from high-resolution industrial CT and for virtual angioscopy (post-implantation assessment of stent placement) [S1, unofficial].
*   **Context:** It addresses the limitations of surface-fitting techniques (which lack interactive threshold adjustment and require dedicated hardware) and conventional ray casting (which is slow for large empty spaces) [S1, unofficial].
