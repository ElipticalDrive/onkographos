# Chunk Serialization with RLE

Also called: Run-Length Encoded chunk serialization

## Overview
Chunk serialization with RLE compresses voxel chunk data by storing it in Run-Length Encoded format when idle, decompressing it on first write access, and freeing memory if the chunk becomes empty [S2, unofficial]. It achieves a 58x size reduction compared to raw storage (39.06 MB to 0.67 MB) [S1, unofficial]. This method is distinct from static RLE storage by introducing lazy decompression and memory management based on access patterns.

## How it works
**Inputs and Outputs:**
- Input: A chunk containing voxel data, either in raw `Voxel*` format or `void*` RLE format.
- Output: The chunk's memory state is updated to either raw voxels (for modification) or compressed RLE (for idle storage).

**Data Structures:**
The `ChunkMD` struct manages the chunk's memory state [S2, unofficial]:
- `voxels`: Pointer to `Voxel*` (raw voxel data).
- `rle`: Pointer to `void*` (RLE compressed data).
- `count`: `uint32_t` number of voxels in the chunk (typically $root^3$, e.g., $8^3 = 512$) [S2, unofficial].
- `last_access`: `uint32_t` timestamp of last access [S2, unofficial].
- `dirty`: `uint8_t` flag indicating if data has been modified [S2, unofficial].
- `remesh`: `uint8_t` flag indicating if mesh needs update [S2, unofficial].
- `mesh_dirty`: `uint8_t` flag indicating if mesh is out of date [S2, unofficial].
- `mesh_vbo`: `void*` vertex buffer object [S2, unofficial].
- `mesh_ibo`: `void*` index buffer object [S2, unofficial].

**Steps:**
1. **Read Access (`chunk_open_ro`):**
   - If `voxels` is null and `rle` matches the null chunk's RLE, point `voxels` to `null_chunk->voxels` [S2, unofficial].
   - Otherwise, decompress `rle` into `voxels` [S2, unofficial].

2. **Write Access (`chunk_open_rw`):**
   - If the chunk is null, allocate a voxel array and copy null data [S2, unofficial].
   - If both `rle` and `voxels` exist, free `rle` [S2, unofficial].
   - If only `rle` exists, decompress `rle` into `voxels` and free `rle` [S2, unofficial].

3. **Idle/Compress (`chunk_compress`):**
   - If `voxels` exist and are not null, compress `voxels` to `rle` and free `voxels` [S2, unofficial].
   - If the resulting `rle` matches the null chunk's RLE, free `rle` and point to `null_chunk->rle` [S2, unofficial].

**Pseudocode:**
```python
def chunk_open_ro(chunk):
    if chunk.voxels is None and chunk.rle is null_chunk_rle:
        chunk.voxels = null_chunk.voxels
    else:
        chunk.voxels = decompress_rle(chunk.rle)

def chunk_open_rw(chunk):
    if chunk is null:
        chunk.voxels = allocate_voxel_array()
        copy_null_data(chunk.voxels)
    else:
        if chunk.rle is not None and chunk.voxels is not None:
            free(chunk.rle)
        elif chunk.rle is not None:
            chunk.voxels = decompress_rle(chunk.rle)
            free(chunk.rle)

def chunk_compress(chunk):
    if chunk.voxels is not None and chunk.voxels is not null_voxels:
        chunk.rle = compress_rle(chunk.voxels)
        free(chunk.voxels)
        chunk.voxels = None
        if chunk.rle is null_chunk_rle:
            free(chunk.rle)
            chunk.rle = null_chunk.rle
```

**Parameters:**
- `chunk_size`: Typically defined as $root^3$ voxels. In the source, `default_chunk_size` is 64, but `config.chunk_size` is derived via `ctz` (count trailing zeros) [S2, unofficial].

**Edge Cases:**
- Null chunk handling: Specific logic for null chunks to avoid unnecessary memory allocation [S2, unofficial].
- Precision: Not given in the sources.

## Subtopics

### Chunk RLE Compression & Lazy Loading
This variant manages chunk voxel memory by storing data in RLE format when idle, decompressing on first write access, and freeing memory if the chunk becomes empty [S2, unofficial]. It is chosen when memory efficiency is critical and access patterns allow for lazy loading. It differs from static RLE by integrating memory management with access control. Link: [Run-Length Encoding for Voxel Data](5051-run-length-encoding-for-voxel-data.md).

## Operating characteristics
- **Time Complexity:** Decompression and compression are linear with respect to the number of voxels in the chunk.
- **Memory Complexity:** RLE format significantly reduces memory usage. A 58x reduction was observed (39.06 MB to 0.67 MB) [S1, unofficial].
- **Measured Performance:** On an Apple M4, the largest world tested (276,889,600 voxels across 4,225 chunks) showed frame times of 8.2 ms for 32-radius cubes with 277M voxels [S1, unofficial].
- **Strengths:** High compression ratio, reduced memory footprint, lazy loading for efficient access.
- **Limitations:** Overhead of decompression/compression on access.
- **When to use:** When memory is constrained and data has high redundancy.
- **When not to use:** When frequent random access to voxel data is required without tolerance for decompression latency.

## Background
This method is part of the voxel engine implementations found in the `voxplat` and `voxel-engine` repositories [S1, unofficial][S2, unofficial]. It builds on the principles of Run-Length Encoding for voxel data [5051-run-length-encoding-for-voxel-data.md].
