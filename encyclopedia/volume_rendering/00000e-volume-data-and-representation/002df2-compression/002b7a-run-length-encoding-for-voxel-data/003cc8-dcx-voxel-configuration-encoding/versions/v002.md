# DCx Voxel Configuration Encoding


## Overview
DCx Voxel Configuration Encoding is a method for compactly representing the occupancy patterns of an expanded cube (a group of 8 voxels) within the Dual Contouring over Expanded Cubes (DCx) framework [S1]. It reduces the 256 possible binary occupancy states to 17 representative equivalence classes by grouping rotationally and mirror-symmetric patterns [S1].

## How it works
**Inputs:** An 8-bit binary occupancy mask for an expanded cube [S1].
**Outputs:** An integer index (1–17) representing the equivalence class of the configuration [S1].

**Data Structures:**
- **Expanded Cube Mask:** An 8-bit integer where bit $i$ is 1 if voxel $i$ is active, and 0 otherwise [S1]. The mapping of bit index $i$ to voxel position follows the DCx grid structure [G].
- **Lookup Table (LUT):** A static table of 17 entries, each corresponding to a representative category [S1]. Categories are labeled as $C$-$N$, where $C$ is the count of active voxels and $N$ is the serial index among categories with that count (e.g., 3-1, 4-2) [S1].

**Steps:**
1. **Input Validation:** Check if the number of active voxels (population count of the 8-bit mask) is less than 3. If so, the configuration is excluded because it provides insufficient geometry for face construction [S1].
2. **Symmetry Grouping:** Identify the equivalence class of the input mask by applying all rotational and mirror symmetries of the cube to the mask [S1]. All masks in the same symmetry orbit map to the same category [S1].
3. **Category Selection:** Map the canonical mask to one of the 17 representative categories [S1].
4. **Group Classification:** Determine if the category belongs to Group 1 or Group 2 [S1]. Group 1 patterns have self-contained face generation rules that do not require information from neighboring expanded cubes [S1]. Group 2 patterns require adaptive face construction based on the categories of neighboring expanded cubes without generating the mesh immediately [S1].
5. **Output:** Return the category index (1–17) [S1].

**Parameters:**
- **Minimum Active Voxels:** 3. Configurations with fewer than 3 active voxels are excluded [S1].
- **LUT Size:** 17 representative categories [S1].

**Edge Cases and Pitfalls:**
- **Insufficient Geometry:** Configurations with fewer than 3 active voxels are invalid for this encoding scheme [S1].
- **Ambiguity in Group 2:** Group 2 patterns require context from neighbors, introducing ambiguity if neighbor categories are not resolved first [S1].
- **Non-Manifold Structures:** The LUT design introduces non-manifold structures only when necessary to reduce holes, requiring careful handling during mesh generation [S1].

## Subtopics

### [Feature Prediction Table Construction](9411-feature-prediction-table-construction.md)
Feature Prediction Table Construction is a preprocessing step in lossless voxel compression that builds a lookup table mapping local voxel contexts to predicted occupancy values. It reduces redundancy by determining the most frequent target voxel state for every possible configuration of neighboring voxels, enabling efficient residual encoding. It differs from Sparse Voxel Octree (SVO) approaches by modeling prediction contexts at full grid resolution with varying strides, rather than using local contexts of SVO nodes with different resolutions at each level.

## Operating characteristics
- **Time Complexity:** Encoding is $O(1)$ per expanded cube, assuming a pre-computed LUT and symmetry group operations are constant-time (48 symmetries) [G].
- **Memory Complexity:** The LUT requires storage for 17 categories [S1]. The size of the encoded data is $\lceil \log_2(17) \rceil = 5$ bits per expanded cube, compared to 8 bits for the raw mask [G].
- **Strengths:** Significantly reduces redundancy by exploiting symmetry [S1]. Provides a compact representation for topological classification [G].
- **Limitations:** Excludes configurations with fewer than 3 active voxels [S1]. Group 2 patterns require neighbor context, complicating parallel processing [S1].
- **When to use:** When using the DCx method for zero-level set extraction from neural unsigned distance functions and symmetry-based compression is beneficial [G].
- **When not to use:** When configurations with fewer than 3 active voxels are common or important [G].

## Background
DCx Voxel Configuration Encoding is part of the Dual Contouring over Expanded Cubes (DCx) method for zero-level set extraction from neural unsigned distance functions [S1]. It was introduced to reduce redundancy in the 256 possible occupancy patterns of an expanded cube by grouping symmetric patterns into 17 equivalence classes [S1]. The method aims to introduce non-manifold structures only when necessary to reduce holes in the resulting mesh [S1].
