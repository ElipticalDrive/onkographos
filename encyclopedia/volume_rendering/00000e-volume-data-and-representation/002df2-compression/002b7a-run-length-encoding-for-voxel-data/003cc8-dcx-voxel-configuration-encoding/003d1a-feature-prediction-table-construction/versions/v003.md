# Feature Prediction Table Construction
## Overview
Feature Prediction Table Construction builds a compact lookup table that maps the occupancy values of a voxel's context (neighboring voxels) to a predicted occupancy value for the target voxel, reducing redundancy before sparse encoding [S1]. It employs multi-level context-aware prediction based on a sparser grid of uniformly spaced key voxels, rather than local contexts of SVO nodes at different resolutions [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A binary voxel grid representing the object geometry [S1].
*   **Output:** A set of Feature Prediction Tables (FPTs), one per prediction level, where each table maps a context index to a predicted occupancy bit [S1].

**Data Structures:**
*   **Feature Prediction Table:** A compact array where the index is formed by concatenating the binary occupancy values of the context voxels, and the value is the predicted occupancy (0 or 1) for the target voxel [S1].
*   **Context:** A fixed arrangement of nearby voxels with already known occupancy values surrounding the target voxel [S1].

**Steps:**
1.  **Define Prediction Levels:** Select multiple levels, each defined by a stride that creates a sparser grid of uniformly spaced key voxels [S1].
2.  **Iterate Grid:** For each level, iterate through all intermediate voxels (non-key voxels) in the grid [S1].
3.  **Extract Context:** For each target voxel, extract the occupancy values of its designated context voxels, which must have known occupancy values [S1].
4.  **Form Index:** Concatenate the binary occupancy values of the context voxels to form an integer index [S1]. For $N$ context voxels, there are $2^N$ possible indices [S1].
5.  **Statistical Analysis:** Accumulate occurrence counts for each context index [S1]. For every combination of context occupancies, count how many times the target voxel takes occupancy 0 versus 1 across the whole grid [S1].
6.  **Determine Prediction:** For each index, determine the more frequent occupancy value of the corresponding target voxels across the whole grid [S1].
7.  **Store Table:** Store this most frequent value as the prediction for that index in the Feature Prediction Table [S1].

**Formulas:**
Let $C = \{c_0, c_1, \dots, c_{N-1}\}$ be the set of context voxels for a target voxel $T$, and let $v(c_i) \in \{0, 1\}$ be the occupancy of context voxel $c_i$ [S1].
The context index $I$ is:
$$ I = \sum_{i=0}^{N-1} v(c_i) \cdot 2^i $$
The predicted occupancy $\hat{v}(T)$ for index $I$ is:
$$ \hat{v}(T) = \arg\max_{b \in \{0,1\}} \text{count}(I, b) $$
where $\text{count}(I, b)$ is the number of times target voxel occupancy $b$ occurred for context index $I$ in the grid [S1].

**Parameters:**
*   **Context Size ($N$):** Not explicitly defined in the sources, but implied to be small enough to allow full enumeration of $2^N$ indices [S1].
*   **Strides:** Uniform spacing between key voxels for each prediction level. Exact stride values are "Not given in the sources." [S1].

**Edge Cases and Pitfalls:**
*   **Undefined Indices:** If a context configuration never occurs in the grid, the prediction is undefined. [G] Implementation should default to 0 or a global majority.
*   **Ties:** If two occupancy values are equally frequent for an index, the source does not specify a tie-breaking rule. [G] Implementation should choose deterministically (e.g., lower value).
*   **Boundary Conditions:** Context voxels may fall outside the grid boundaries. [G] Implementation should clamp coordinates or assume 0 occupancy for out-of-bounds voxels.

**Pseudocode:**
```python
def construct_feature_prediction_table(voxel_grid, context_offsets):
    """
    Construct a Feature Prediction Table for a specific context geometry.
    Args:
        voxel_grid: 3D list/array of binary occupancy values.
        context_offsets: List of (dx, dy, dz) tuples for context voxels.
    Returns:
        prediction_table: List of length 2^N mapping context index to predicted occupancy.
    """
    N = len(context_offsets)
    num_indices = 1 << N
    # counts[index][0] stores count of target=0, counts[index][1] stores count of target=1
    counts = [[0, 0] for _ in range(num_indices)]
    
    depth = len(voxel_grid)
    height = len(voxel_grid[0])
    width = len(voxel_grid[0][0])
    
    for z in range(depth):
        for y in range(height):
            for x in range(width):
                index = 0
                for i, (dx, dy, dz) in enumerate(context_offsets):
                    cx, cy, cz = x + dx, y + dy, z + dz
                    # Handle boundaries: assume 0 for out-of-bounds [G]
                    if 0 <= cz < depth and 0 <= cy < height and 0 <= cx < width:
                        bit = voxel_grid[cz][cy][cx]
                    else:
                        bit = 0
                    index |= (bit << i)
                counts[index][voxel_grid[z][y][x]] += 1
                
    # Build prediction table: pick majority vote
    prediction_table = []
    for index in range(num_indices):
        c0, c1 = counts[index]
        # Tie-breaking: choose 0 if equal [G]
        prediction_table.append(1 if c1 > c0 else 0)
        
    return prediction_table
```

## Subtopics

### [Feature Prediction Table Encoding](9416-feature-prediction-table-encoding.md)
Encodes the constructed tables into the bitstream. It differs by focusing on the serialization of the LUTs rather than their construction. Choose it when you need to store the prediction rules for decoding.

## Operating characteristics
*   **Time Complexity:** $O(V \cdot N)$ per prediction level, where $V$ is the number of voxels and $N$ is the number of context voxels. The statistical scan requires one pass per level [S1].
*   **Memory Complexity:** $O(2^N)$ per prediction level, where $N$ is the number of context voxels. This is small for typical small contexts [S1].
*   **Performance:** Achieved 15.6% and 12.8% storage reduction on synthetic and real tree datasets, respectively, compared to plain PSVO. Average 11% improvement on diverse voxelized objects [S1].
*   **Strengths:** Highly parallelizable, suitable for GPU execution. Reduces redundancy before SVO encoding [S1].
*   **Limitations:** Requires a full statistical scan of the grid. Effectiveness depends on the regularity of the voxel structure [S1].
*   **When to use:** For voxelized models with strong local correlations, such as tree models or structured geometry [S1].
*   **When not to use:** For highly random or noisy voxel data where local context provides little predictive power [S1].

## Background
The method addresses efficient representation of voxelized tree models, which are among the most structurally complex natural objects, motivated by precision horticulture and forestry applications [S1]. It is designed for massively parallel GPU architectures to enable fast encoding and decoding [S1].
