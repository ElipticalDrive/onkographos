# GPU Decompression Pipeline

Also called: Asynchronous data transfer, Multi-threaded loading and LZO decompression

## Overview
The GPU Decompression Pipeline is a hybrid CPU/GPU method for streaming and decompressing time-varying volume data, serving as the execution engine for the [Two-stage compression approach](6805-two-stage-compression-approach.md) [S1]. It solves the bottleneck of transferring and unpacking compressed volume bricks from disk to GPU memory by overlapping I/O, decompression, and data upload [S1]. It sets itself apart from pure CPU decompression by offloading the resolution of variable-length codes, delta encoding, and brick assembly to CUDA kernels, utilizing asynchronous memory copies to hide latency [S1].

## How it works
The pipeline operates as a multi-threaded producer-consumer system where independent threads handle loading, decompression, and GPU transfer [S1].

### Inputs and Outputs
*   **Input:** Compressed brick data packets on disk, organized by time steps [S1].
*   **Output:** A CUDA array (3D texture) in GPU global memory ready for raycasting [S1].

### Data Structures
*   **Transfer Buffer:** A page-locked (pinned) memory region in host RAM [S1]. It holds a single large memory block containing all uncompressed bricks for a batch of time steps [S1].
*   **Shadow Copy:** A 1D or 3D array in GPU global memory where decompression kernels write intermediate results [S1].
*   **CUDA Array:** The final 3D texture object in GPU memory, used for rendering [S1].

### Parameters
*   **Loader Queue Size:** Up to 5 time steps [S1].
*   **Bit Lengths Supported:** 16, 8, 4, and 0 bits per voxel [S1].
*   **CUDA Block Size:** 64 threads per block [S1].

### Steps
1.  **Loading:** A loader thread reads compressed data from disk, buffering up to five time steps in advance [S1]. It feeds this data to the decompression thread when the latter is idle [S1].
2.  **Asynchronous Copy:** The uncompressed brick data is copied from the page-locked transfer buffer to the GPU using an asynchronous memory copy operation [S1]. This allows the copy to run in parallel with CPU operations and GPU kernel executions [S1].
3.  **Decompression Kernels:** The GPU executes specific kernels to resolve the compression [S1]. **Variable-Length Coding:** Separate kernels handle bricks encoded with 16, 8, 4, or 0 bits [S1]. **Delta Encoding:** A kernel adds the delta values to the previous time step's data to reconstruct the current absolute values [S1]. **Brick Assembly:** Kernels assemble the decompressed voxels into the shadow copy [S1].
4.  **Texture Upload:** The host code calls `cudaMemcpy3D()` to copy the shadow copy from global memory to the CUDA array (3D texture) [S1]. This on-device copy utilizes full GPU memory bandwidth [S1].

### Pseudocode
```python
# Global state definitions
transfer_buffer = allocate_pinned_memory(size=total_brick_size * num_brick_batches)
shadow_copy = allocate_gpu_global_memory(size=total_volume_size)
cuda_array = create_cuda_array_3d(dimensions=volume_dims)
running = True
max_queue_size = 5
block_size = 64
bit_lengths = [16, 8, 4, 0]

def allocate_pinned_memory(size):
    """Allocate page-locked (pinned) host memory."""
    return [0] * size

def allocate_gpu_global_memory(size):
    """Allocate GPU global memory."""
    return [0] * size

def create_cuda_array_3d(dimensions):
    """Create a 3D texture object in GPU memory."""
    return [0] * (dimensions[0] * dimensions[1] * dimensions[2])

def loader_thread(queue):
    """Loader thread: reads compressed data and feeds decompression thread."""
    while running:
        compressed_data = read_from_disk(time_steps=max_queue_size)
        unpack_compressed_packets(compressed_data, transfer_buffer)
        queue.put(transfer_buffer)

def decompression_thread(queue, gpu_stream, total_brick_size):
    """Decompression thread: manages GPU kernel launches and async copies."""
    while running:
        buffer = queue.get()
        cuda_stream_async_memcpy(gpu_stream, dest_gpu_ptr, buffer, size=total_brick_size)
        for bits in bit_lengths:
            launch_vl_decode_kernel(gpu_stream, input_ptr=dest_gpu_ptr, output_ptr=shadow_copy, bit_depth=bits)
        launch_delta_decode_kernel(gpu_stream, prev_time_step_ptr, delta_ptr, output_ptr=shadow_copy)
        launch_assembly_kernel(gpu_stream, input_ptr=shadow_copy, output_ptr=shadow_copy, brick_dims=brick_dims)

def launch_assembly_kernel(gpu_stream, input_ptr, output_ptr, brick_dims):
    """Assemble bricks using coalesced memory access."""
    # Distribute brick assembly onto blocks of 64 CUDA threads
    for block_id in range(0, len(input_ptr), block_size):
        # Each thread in a block is assigned an x-coordinate
        for thread_id in range(block_size):
            x_coord = thread_id
            # Process all voxels in the brick for this x-coordinate
            for y in range(brick_dims[1]):
                for z in range(brick_dims[2]):
                    index = x_coord + y * brick_dims[0] + z * brick_dims[0] * brick_dims[1]
                    output_ptr[index] = input_ptr[index]

def finalize_rendering(volume_dims):
    """Host function: copies shadow copy to CUDA array for rendering."""
    copy_memory_3d(src=shadow_copy, dst=cuda_array, width=volume_dims[0], height=volume_dims[1], depth=volume_dims[2])

def copy_memory_3d(src, dst, width, height, depth):
    """On-device copy utilizing full GPU memory bandwidth."""
    for z in range(depth):
        for y in range(height):
            for x in range(width):
                dst[x + y * width + z * width * height] = src[x + y * width + z * width * height]
```

### Edge Cases and Pitfalls
*   **Skipping Invisible Bricks:** Optimizations that skip loading bricks based on transfer function opacity are not implemented [S1]. Skipping breaks delta encoding because decoding requires access to all previous time steps' absolute values [S1]. It also complicates user interaction when transfer functions change dynamically [S1].
*   **Direct Texture Writing:** Current GPUs and drivers do not support direct writing to 3D textures (CUDA arrays) from kernel code [S1]. A shadow copy in global memory is required as an intermediate step [S1]. The OpenCL extension `cl_khr_3d_image_writes` supports this feature but is not yet supported by current hardware/drivers [S1].

## Operating characteristics
*   **Time Complexity:** The pipeline overlaps I/O, decompression, and transfer, effectively hiding latency [S1]. The bottleneck is typically data loading [S1].
*   **Memory Complexity:** Requires page-locked memory for the transfer buffer and a shadow copy in GPU global memory [S1].
*   **Performance:** Achieves maximum transfer bandwidth by copying one large memory block [S1]. The assembly kernel achieves full coalescing by assigning each thread an x-coordinate and processing all voxels in that column [S1].
*   **Strengths:** High throughput via asynchronous operations; efficient memory access patterns in CUDA kernels [S1].
*   **Limitations:** Requires a shadow copy due to hardware limitations on direct texture writes; cannot skip invisible bricks without breaking delta encoding [S1].

## Background
The method was introduced by J. Mensmann, T. Ropinski, and K. Hinrichs in 2010 as part of a lossless compression scheme for time-varying volume data [S1]. It addresses the limitations of CPU-only decompression by leveraging CUDA for parallel unpacking and assembly [S1].
