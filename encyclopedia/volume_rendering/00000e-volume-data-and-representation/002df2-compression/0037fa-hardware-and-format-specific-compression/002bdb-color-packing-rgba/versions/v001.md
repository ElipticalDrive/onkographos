# Color Packing (RGBA)


## Overview
Color Packing (RGBA) is a lossless compression method that maps 4-component floating-point color vectors into a compact 4-byte unsigned integer representation, reducing memory bandwidth and storage requirements for volume rendering data [S1, unofficial]. It differs from [16-bit Floating Point Format for Spectra](1163-16-bit-floating-point-format-for-spectra.md) by using 8-bit integer precision per channel instead of 16-bit floating point, offering higher density at the cost of quantization error [S1, unofficial].

## How it works
**Inputs:** A 4-component floating-point vector $C = [c_0, c_1, c_2, c_3]$ where each component is typically in the range $[0, 1]$ or $[-1, 1]$ depending on the specific color space convention, though standard packing assumes normalized $[0, 1]$ for direct mapping to $[0, 255]$.
**Outputs:** A 4-byte unsigned integer array or a single 32-bit unsigned integer containing the packed color.

**Data Structure:**
The output is a 32-bit unsigned integer (`uint32`) or a byte array of length 4. The layout is typically Little-Endian or Big-Endian depending on the hardware architecture, but the logical packing order is:
- Byte 0: Red ($c_0$)
- Byte 1: Green ($c_1$)
- Byte 2: Blue ($c_2$)
- Byte 3: Alpha ($c_3$)

**Steps:**
1. For each component $c_i$ in the input vector $C$:
   a. Scale the component by 255.0.
   b. Cast the result to an 8-bit unsigned integer (`u8`).
   c. Store the result in the corresponding byte position.
2. Combine the 4 bytes into a single 32-bit integer if required by the storage format.

**Pseudocode:**
```python
def pack_color_rgba(c: list[float]) -> int:
    """
    Packs a 4-component float color vector into a 32-bit unsigned integer.
    
    Args:
        c: List of 4 floats [R, G, B, A], expected in range [0.0, 1.0].
        
    Returns:
        A 32-bit unsigned integer representing the packed color.
    """
    # Ensure input has 4 components
    if len(c) != 4:
        raise ValueError("Input must have exactly 4 components")
    
    packed = 0
    for i in range(4):
        # Scale by 255 and cast to uint8
        # Note: In practice, clamping to [0, 255] is recommended to handle
        # values slightly outside [0, 1] due to floating point errors.
        val = int(c[i] * 255.0)
        # Guard against out-of-bounds values [G]
        val = max(0, min(255, val))
        
        # Pack into the integer
        # Assuming Little-Endian byte order for the final integer representation
        # where the first component (R) is the least significant byte.
        packed |= (val << (8 * i))
        
    return packed
```

**Parameters:**
- Scaling factor: 255.0
- Precision: 8-bit per channel

**Edge Cases and Pitfalls:**
- Values outside $[0, 1]$ will be clamped or truncated, leading to loss of information [G].
- Precision loss is inherent due to the reduction from 32-bit float to 8-bit integer.
- Endianness of the final 32-bit integer depends on the system architecture; explicit byte ordering should be used if cross-platform compatibility is required.

## Subtopics

### packDCColor
Packs the DC spherical harmonic coefficient (RGB) and alpha into a single 32-bit unsigned integer for GPU texture storage. It sets itself apart by quantizing spherical harmonic coefficients using a specific constant $k_{SH0}$ rather than simple linear scaling. Choose this when storing spherical harmonic data in volume rendering for real-time rendering. Link: [packDCColor](1164-packdccolor.md) (hypothetical link).

**Definition:**
Packs the DC spherical harmonic coefficient (RGB) and alpha into a single 32-bit unsigned integer for GPU texture storage.

**Steps:**
1. Define quantization lambda: clamp value to $[0, 1]$, multiply by 255, add 0.5, cast to `uint32`, mask with `0xFF`.
2. Compute R, G, B, A components:
   - $R = \text{quant}(k_{SH0} \times sh[0] + 0.5)$
   - $G = \text{quant}(k_{SH0} \times sh[1] + 0.5)$
   - $B = \text{quant}(k_{SH0} \times sh[2] + 0.5)$
   - $A = \text{quant}(\alpha)$
3. Pack as $R \mid (G \ll 8) \mid (B \ll 16) \mid (A \ll 24)$.

**Formula:**
$R = \text{quant}(k_{SH0} \times sh[0] + 0.5)$

**Parameter:**
$k_{SH0} = 0.28209479177387814$ (DC SH coefficient $Y_0^0$).

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(1)$ per color vector.
- Memory: Reduces storage from 16 bytes (4x 32-bit floats) to 4 bytes (4x 8-bit integers), a 4x reduction.

**Measured Performance:**
Not given in the sources.

**Scaling:**
Linear with the number of color vectors.

**Strengths and Limitations:**
- Strengths: High compression ratio, simple implementation, low computational overhead.
- Limitations: Loss of precision, potential banding artifacts in smooth gradients, limited dynamic range compared to floating point.

**When to Use:**
Use when memory bandwidth is a bottleneck and visual quality requirements allow for 8-bit precision.

**When Not to Use:**
Use when high dynamic range or precise color representation is critical, such as in scientific visualization requiring accurate spectral data.

## Background
Originated in computer graphics for efficient storage and transmission of color data [S1, unofficial]. Developed as a standard method for packing RGBA data into textures and buffers [S1, unofficial]. Used in volume rendering for storing color and opacity data in voxel grids [S1, unofficial].
