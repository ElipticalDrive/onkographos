# 2D B-spline Wavelet Masks (Quadtree)

Also called: Two-dimensional B-spline wavelet masks [S1, unofficial]

## Overview
This method defines convolution masks for lifting-based B-spline wavelet transforms on quadtree-organized vertex grids [S1, unofficial]. It generates multiresolution hierarchies for 2D volume data by handling two distinct types of new vertices introduced during subdivision: midpoints of old edges (blue) and centers of old faces (green) [S1, unofficial]. It sets itself apart from standard subdivision wavelets by using B-spline lifting to avoid over- and undershoots, and specifically addresses the data sparsity where values at "blue" positions are not directly available during detail calculation, requiring linear interpolation from black vertices [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 2D grid of scalar values organized in a quadtree structure. Vertices are classified as black (original coarse-grid), blue (midpoints of old edges), and green (centers of old faces) [S1, unofficial].
- Output: Wavelet detail coefficients and approximation coefficients for the next resolution level [S1, unofficial].

**Data Structures:**
- The grid follows a quadtree hierarchy [S1, unofficial].
- Masks are 2D convolution kernels. Due to irregular vertex availability, masks depend on local neighborhood topology [S1, unofficial].

**Steps:**
1. Derive 1D masks for approximation ($s$-lift) and detail ($w$-lift) [S1, unofficial].
2. Derive 2D masks by convolving the 1D masks in the two coordinate directions (horizontal and vertical) [S1, unofficial].
3. Apply 1D masks (4) and (6) in both directions [S1, unofficial].
4. Apply masks (3) and (4) simultaneously for approximation, and masks (5) and (6) simultaneously for detail [S1, unofficial].
5. When applying the 2D detail mask (5), linearly interpolate missing values at blue positions from black vertices, which modifies the effective coefficients of mask (5) [S1, unofficial].

**Formulas:**
The source text for the exact coefficients is garbled, but the context implies standard linear B-spline lifting coefficients [S1, unofficial]. Let $a$ be the lifting parameter.
- **2D s-lift mask (3):** Coefficients for black vertices: $1/4, 1/4$; for blue vertices: $1/2$ [S1, unofficial].
- **2D w-lift mask (5):** Coefficients for black vertices: $1, -1$; for blue vertices: $0$ [S1, unofficial]. The zero coefficient for blue vertices reflects that the detail is computed based on the difference between the actual green vertex value and the interpolated value from black/blue neighbors [S1, unofficial].

**Parameters:**
- $a$: Scaling factor for the B-spline lifting scheme. The exact numerical value of $a$ for the final 2D mask is not given in the sources, but it is part of the mask structure [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Missing Blue Values:** No values exist at blue positions required for mask (5). These must be linearly interpolated from black vertices, which changes the effective mask (5) [S1, unofficial].
- **Precision:** Linear interpolation introduces approximation errors. The source notes that viewing blue values as linear interpolations is an "approximation" [S1, unofficial].

**Pseudocode:**
```python
def apply_2d_b_spline_wavelet_masks(grid):
    # grid: dict mapping vertex coordinates (x, y) to scalar values
    # Black vertices: (2i, 2j)
    # Blue vertices: (2i+1, 2j) and (2i, 2j+1) [may be missing]
    # Green vertices: (2i+1, 2j+1)
    approx_coeffs = {}
    detail_coeffs = {}

    for (gx, gy), green_val in grid.items():
        # Process only green vertices (both coordinates odd)
        if gx % 2 == 1 and gy % 2 == 1:
            # Black neighbors (corners)
            b1, b2, b3, b4 = grid[(gx-1, gy-1)], grid[(gx+1, gy-1)], grid[(gx-1, gy+1)], grid[(gx+1, gy+1)]

            # Blue neighbors (edge midpoints) - interpolate if missing per pitfall [S1, unofficial]
            def get_blue(x, y):
                if (x, y) in grid:
                    return grid[(x, y)]
                # Linear interpolation from the two black vertices sharing the edge
                if y % 2 == 0: # horizontal edge midpoint
                    return 0.5 * grid[(x-1, y)] + 0.5 * grid[(x+1, y)]
                else: # vertical edge midpoint
                    return 0.5 * grid[(x, y-1)] + 0.5 * grid[(x, y+1)]

            bl1 = get_blue(gx, gy-1)
            bl2 = get_blue(gx, gy+1)

            # Apply s-lift mask (3): approx = 1/4*(b1+b2+b3+b4) + 1/2*(bl1+bl2)
            approx = 0.25 * (b1 + b2 + b3 + b4) + 0.5 * (bl1 + bl2)
            approx_coeffs[(gx, gy)] = approx

            # Apply w-lift mask (5): detail = green_val - approx
            # Blue coefficient is 0, so interpolated_blues do not affect detail directly
            detail = green_val - approx
            detail_coeffs[(gx, gy)] = detail

    return detail_coeffs, approx_coeffs
```

## Subtopics

### 3D B-spline Wavelet Masks (Octree)
This variant extends the 2D method to 3D octree-organized vertices [S1, unofficial]. It handles three types of new vertices: edge midpoints (blue), face centers (green), and cube centroids (red) [S1, unofficial]. The key difference is that no values are available at blue and green vertices during encoding, requiring linear interpolation for blue (from two black vertices) and bilinear interpolation for green (from four black vertices) [S1, unofficial]. The masks grow in size and lose some unique structure [S1, unofficial]. For decoding, the s-lift operation adjusts mask (7), where green vertex values are linear interpolations of red neighbors multiplied by $2a$, and blue vertex values are bilinear interpolations of red neighbors multiplied by $4a$ [S1, unofficial]. The factor $a$ is renamed to $H$ [S1, unofficial]. The final w-lift decoding reduces to an analogous mask (10) [S1, unofficial].

### Lifting Scheme for 3^2 Subdivision (2D)
This variant adjusts the 2D masks for $3^2$ subdivision, where only new vertices at face centers (green) are inserted, with no vertices at edge midpoints (blue) [S1, unofficial]. The w-lift operation is executed first using mask (5) [S1, unofficial]. The blue/black vertices are assumed to be similarly updated, so blue values remain linear interpolations [S1, unofficial]. This leads to modified masks `w-liftencode(a, b)` (mask 13) and `s-liftencode2(a, b)` (mask 14) [S1, unofficial]. The linear `s-liftencode1(a, b)` mask has coefficients $1/4, 1/4$ for black vertices and $1/2$ for green vertices [S1, unofficial]. The decoding mask `s-liftdecode2(a, b)` is derived from mask (3) by renaming factor $a$ to $H$ [S1, unofficial].

## Background
The method originates from the work on hierarchical volume representation using subdivision and B-spline wavelets [S1, unofficial]. It was developed to provide a multiresolution hierarchy for volume data that avoids the artifacts of standard wavelet transforms [S1, unofficial]. The specific 2D masks for quadtree organization were derived by convolving 1D B-spline lifting masks [S1, unofficial]. The method has been applied to 2D and 3D volume rendering, as well as surface representation [S1, unofficial].
