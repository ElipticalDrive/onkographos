# Progressive Compression System

Also called: Generalized Linear B-Spline Wavelets with SPIHT Coder, SPIHT, SPIHT Coder for Volumetric Subdivision, Set Partitioning in Hierarchical Trees

## Overview
The Progressive Compression System is a method for compressing volumetric subdivision meshes by constructing a progressive bit stream from a hierarchy of subdivision wavelets, optimized for coarse-to-fine reconstruction [S1]. It solves the problem of efficient storage and transmission of complex 3D meshes by exploiting the decay behavior of wavelet coefficients from coarse to fine spatial scales [S1]. Unlike standard zerotree algorithms that rely on a strict theoretical framework for parent-child relationships, this system applies intuitive spatial relationships analogous to image coding trees to define coefficient hierarchies for subdivision wavelets [S1]. It sets itself apart from its parent [B-spline Wavelet Compression](5377-b-spline-wavelet-compression.md) by specifically integrating the SPIHT coder to handle the hierarchical tree structure of subdivision wavelets, rather than relying solely on delta encoding and Huffman coding for general coefficient lists.

## How it works
The system compresses volumetric meshes by transforming vertex coordinates into wavelet coefficients, quantizing them, and encoding them using the Set Partitioning in Hierarchical Trees (SPIHT) algorithm [S1].

**Inputs and Outputs**
*   **Input:** A volumetric mesh defined by vertex coordinates and potentially scalar field values. The mesh is typically decomposed into domains, each with a base mesh (e.g., hexahedra) and a subdivision hierarchy [S1].
*   **Output:** A progressive bit stream that allows reconstruction of the mesh at varying levels of detail (coarse to fine) [S1].

**Data Structures**
*   **Wavelet Coefficients:** Vector quantities representing the detail information at each subdivision level [S1].
*   **Coefficient Trees:** Hierarchical structures defining parent-child relationships between wavelet coefficients based on spatial proximity [S1].
*   **Bit Streams:** Two primary streams are generated by the SPIHT coder: one for sign bits and one for magnitude bits (all other bits) [S1].

**Steps**
1.  **Preprocessing and Normalization:** Vertex coordinates and scalar field values are normalized to a standard range [S1].
2.  **Quantization:** Each component of each vertex coordinate is quantized to an integer. The sources specify quantization to 32 bits per coordinate [S1].
3.  **Wavelet Transform:** The quantized coordinates are transformed using a subdivision wavelet transform (e.g., Slow Growing Subdivision (SGS) or Linear B-spline) [S1]. The resulting wavelet coefficients are vector quantities [S1].
4.  **Tree Construction:** Parent-child relationships for the wavelet coefficients are defined intuitively based on spatial relationships, analogous to trees used in image coding literature [S1]. Note: No theoretical framework exists for this definition in subdivision wavelets [S1].
5.  **SPIHT Encoding:**
    *   The SPIHT algorithm processes the wavelet coefficients organized in trees [S1].
    *   It encodes each bit plane separately, starting from the most significant bit (MSB) to the least significant bit (LSB) [S1].
    *   A predefined traversal order is used for both encoder and decoder [S1].
    *   Trees of zeros (insignificant coefficients) are encoded efficiently by encoding a single bit for the root coefficient, exploiting the correlation where coarse coefficients predict fine-scale behavior [S1].
    *   Sign bits are encoded into a separate stream from the magnitude bits [S1].
6.  **Reconstruction:** For progressive viewing, a set number of bits are decompressed from the stream, and the fine-scale mesh is reconstructed from these bits [S1].

**Pseudocode**
```python
def progressive_compression_system(mesh_vertices, wavelet_type='bspline', alpha=0.9):
    """
    Compresses a volumetric mesh using subdivision wavelets and SPIHT.
    
    Args:
        mesh_vertices: List of 3D coordinates for all vertices.
        wavelet_type: Type of wavelet transform ('bspline' or 'sgs').
        alpha: Smoothing parameter for SGS (if applicable).
        
    Returns:
        bit_stream: The compressed progressive bit stream.
    """
    # Step 1: Normalization
    # Normalize vertex coordinates to a standard range [0, 1] or similar.
    normalized_vertices = normalize(mesh_vertices)
    
    # Step 2: Quantization
    # Quantize each coordinate component to 32-bit integers.
    quantized_vertices = quantize(normalized_vertices, bits=32)
    
    # Step 3: Wavelet Transform
    # Apply the chosen subdivision wavelet transform.
    # For SGS, alpha controls stability; alpha < 0.7 is unstable.
    if wavelet_type == 'sgs':
        wavelet_coeffs = apply_sgs_wavelet(quantized_vertices, alpha)
    elif wavelet_type == 'bspline':
        wavelet_coeffs = apply_bspline_wavelet(quantized_vertices)
    else:
        raise ValueError("Unsupported wavelet type")
        
    # Step 4: Tree Construction
    # Define parent-child relationships based on spatial proximity.
    # This is an intuitive definition, not theoretically derived.
    coefficient_trees = build_spatial_trees(wavelet_coeffs)
    
    # Step 5: SPIHT Encoding
    # Initialize SPIHT coder with the trees and quantized coefficients.
    spihit_coder = SPIHTCoder(coefficient_trees, wavelet_coeffs)
    
    # Encode bit planes from MSB to LSB.
    # Separate sign bits into one stream, magnitude bits into another.
    sign_stream, magnitude_stream = spihit_coder.encode()
    
    # Combine streams into a single progressive bit stream.
    bit_stream = combine_streams(sign_stream, magnitude_stream)
    
    return bit_stream

def reconstruct_mesh(bit_stream, original_vertex_count, wavelet_type='bspline', alpha=0.9):
    """
    Reconstructs the mesh from the progressive bit stream.
    
    Args:
        bit_stream: The compressed bit stream.
        original_vertex_count: Number of vertices in the original mesh.
        wavelet_type: Type of wavelet transform used during compression.
        alpha: Smoothing parameter for SGS.
        
    Returns:
        reconstructed_vertices: List of 3D coordinates for the reconstructed mesh.
    """
    # Step 1: SPIHT Decoding
    # Decode the bit stream to recover quantized wavelet coefficients.
    # The number of bits decoded determines the level of detail.
    sign_bits, magnitude_bits = split_streams(bit_stream)
    quantized_coeffs = SPIHTCoder.decode(sign_bits, magnitude_bits)
    
    # Step 2: Inverse Wavelet Transform
    # Apply the inverse subdivision wavelet transform.
    if wavelet_type == 'sgs':
        normalized_vertices = apply_inverse_sgs_wavelet(quantized_coeffs, alpha)
    elif wavelet_type == 'bspline':
        normalized_vertices = apply_inverse_bspline_wavelet(quantized_coeffs)
        
    # Step 3: De-quantization and De-normalization
    # Convert back to original scale.
    reconstructed_vertices = dequantize(normalized_vertices, bits=32)
    final_vertices = denormalize(reconstructed_vertices)
    
    return final_vertices
```

**Parameters**
*   **Quantization Bits:** 32 bits per coordinate component [S1].
*   **SGS Alpha ($\alpha$):** Smoothing parameter for Slow Growing Subdivision. Values less than 0.7 result in unstable wavelets and decreased compression efficiency [S1]. Typical tested values are 0.7 and 0.9 [S1].
*   **Bit Planes:** Encoded from most significant to least significant [S1].

**Edge Cases and Pitfalls**
*   **Mesh Interpenetration:** At low bit rates, errors in vertex locations can cause the mesh to interpenetrate, especially for unstable transforms like SGS with $\alpha < 0.7$ [S1].
*   **Extraordinary Vertices:** The system was not tested on base meshes with extraordinary vertices. Producing a base mesh from an arbitrary finite element mesh is an open problem [S1].
*   **Stability:** SGS wavelets are unstable for some settings of $\alpha$. B-spline transforms are generally well-behaved [S1].
*   **Theoretical Framework:** There is no theoretical framework to define parent-child relationships for subdivision wavelets; definitions are based intuitively on spatial relationships [S1].

## Subtopics

### [Multiresolution Distance Volumes for Progressive Surface Compression](11840-multiresolution-distance-volumes-for-progressive-surface-com.md)
A surface compression method that stores surfaces as wavelet-compressed signed-distance volumes, enabling the representation of surfaces with complex topology and arbitrary numbers of components within a single multiresolution data structure. It solves the problem of progressive surface transmission and storage by dispensing with the costly base mesh construction and explicit topology tracking required by subdivision surface methods. Unlike subdivision approaches, it operates entirely on regularly sampled volumes, allowing for elegant topological modification at high compression rates.

## Operating characteristics
*   **Time and Memory Complexity:** Not given in the sources.
*   **Measured Performance:**
    *   **Perturbed Ball Mesh:** 4913 vertices. Original size: 471,648 bits (32-bit quantization). SGS ($\alpha=0.7$): 429,344 bits. SGS ($\alpha=0.9$): 454,080 bits. Linear B-spline: 454,848 bits [S1].
    *   **Hohlraum Simulation:** 134,176 vertices. Decomposed into 32 domains. Each domain had a base mesh hexahedron subdivided 5 times [S1].
*   **Scaling:** Not given in the sources.
*   **Strengths:**
    *   B-spline wavelets show superior performance at small numbers of bits compared to SGS [S1].
    *   Progressive reconstruction allows coarse-to-fine viewing [S1].
    *   Efficient encoding of zerotrees (trees of insignificant coefficients) [S1].
*   **Limitations:**
    *   Instability of SGS for $\alpha < 0.7$ [S1].
    *   Mesh interpenetration at low bit rates [S1].
    *   Not tested on meshes with extraordinary vertices [S1].
    *   Back-end compression system does not achieve appreciable gains on SPIHT output [S1].
*   **When to use:** When progressive coarse-to-fine reconstruction of volumetric subdivision meshes is required, and B-spline wavelets are preferred for stability and performance at low bit rates [S1].
*   **When not to use:** When the mesh contains extraordinary vertices or when high stability is required for all parameter settings (SGS with low $\alpha$) [S1].

## Background
The Progressive Compression System was presented in the paper "Progressive Compression of Volumetric Subdivision Meshes" [S1]. It generalizes the SPIHT image coder to the slow growing subdivision refinement structure [S1]. The system was tested on synthetic data (Perturbed Ball Mesh) and simulation data (Hohlraum Simulation) [S1]. The work highlights the challenges of applying image coding techniques to volumetric subdivision meshes, particularly regarding the lack of a theoretical framework for parent-child relationships in subdivision wavelets [S1].
