# Progressive Compression System

Also called: Generalized Linear B-Spline Wavelets with SPIHT Coder, SPIHT, SPIHT Coder for Volumetric Subdivision, Set Partitioning in Hierarchical Trees

## Overview
The Progressive Compression System is a compression method for volumetric subdivision meshes that constructs a progressive bit stream optimized for coarse-to-fine reconstruction [S1]. It generalizes the Set Partitioning in Hierarchical Trees (SPIHT) image coder to the slow growing subdivision (SGS) and B-spline wavelet structures [S1]. Unlike zerotree algorithms that rely on a strict theoretical framework for parent-child relationships, this system uses intuitive spatial relationships analogous to image coding trees to define coefficient hierarchies [S1]. It is distinct from its parent [B-spline Wavelet Compression](5377-b-spline-wavelet-compression.md) by replacing delta encoding, run-length, and Huffman coding with the SPIHT algorithm, which exploits the decay behavior of wavelet coefficients from coarse to fine scales [S1].

## How it works
The system compresses volumetric meshes by transforming vertex coordinates and scalar fields into wavelet coefficients, quantizing them, and encoding them using SPIHT to produce a progressive bit stream [S1].

**Inputs and Outputs**
*   **Input:** A volumetric mesh defined by vertex coordinates and scalar field values, typically decomposed into domains (e.g., hexahedral base meshes) [S1].
*   **Output:** A progressive bit stream containing sign bits and magnitude bits, allowing reconstruction of the mesh at varying levels of detail [S1].

**Data Structures**
*   **Wavelet Coefficients:** Vector quantities representing the detail between subdivision levels [S1].
*   **Coefficient Trees:** Hierarchical structures linking parent coefficients to their descendants based on spatial proximity [S1].
*   **Bit Streams:** Two separate streams are generated: one for sign bits and one for all other bits (magnitudes) [S1].

**Steps**
1.  **Preprocessing:** Normalize vertex coordinates and scalar field values [S1].
2.  **Wavelet Transform:** Apply the wavelet transform (e.g., Slow Growing Subdivision or Linear B-spline) to compute wavelet coefficients for each vertex component [S1].
3.  **Quantization:** Quantize each component of each wavelet coefficient vector to an integer of a specific bit depth. In the cited implementation, each coordinate is quantized to 32 bits [S1].
4.  **Tree Construction:** Define parent-child relationships for the wavelet coefficients. Since no theoretical framework exists for subdivision wavelets, relationships are defined intuitively based on spatial relationships analogous to those in image coding [S1].
5.  **SPIHT Encoding:**
    *   Encode each bit plane separately, from the most significant bit (MSB) to the least significant bit (LSB) [S1].
    *   Use a predefined traversal order for both encoder and decoder [S1].
    *   Exploit the decay behavior of coefficients: if a parent coefficient is insignificant, its entire subtree (zerotree) can be encoded efficiently with a single bit [S1].
    *   Separate sign bits into a distinct stream from magnitude bits [S1].
6.  **Reconstruction:** For progressive viewing, decompress a set number of bits from the stream and reconstruct the fine-scale mesh from these bits [S1].

**Pseudocode**
```python
def progressive_compress(mesh):
    """
    Compress a volumetric mesh using SPIHT on subdivision wavelets.
    mesh: List of vertices with coordinates (x, y, z) and scalar values.
    Returns: Bit streams for signs and magnitudes.
    """
    # Step 1: Normalize inputs
    normalized_mesh = normalize(mesh)
    
    # Step 2: Compute Wavelet Coefficients
    # Apply SGS or B-spline transform to get vector coefficients
    coefficients = compute_wavelet_transform(normalized_mesh)
    
    # Step 3: Quantize
    # Quantize each component to 32-bit integers
    quantized_coeffs = [quantize_to_bits(coeff, 32) for coeff in coefficients]
    
    # Step 4: Build Coefficient Trees
    # Define parent-child links based on spatial proximity
    trees = build_spatial_trees(quantized_coeffs)
    
    # Step 5: SPIHT Encoding
    sign_stream = []
    magnitude_stream = []
    
    # Determine max bit depth
    max_bits = max_bit_depth(quantized_coeffs)
    
    for bit_plane in range(max_bits, -1, -1):
        # Traverse trees in predefined order
        for tree in trees:
            # Check significance of root
            if is_significant(tree.root, bit_plane):
                encode_significant_node(tree, bit_plane, sign_stream, magnitude_stream)
            else:
                # Encode zerotree if all descendants are insignificant
                encode_zerotree(tree, bit_plane, sign_stream, magnitude_stream)
                
    return sign_stream, magnitude_stream

def is_significant(node, bit_plane):
    """Check if node magnitude >= 2^bit_plane"""
    return abs(node.magnitude) >= (1 << bit_plane)

def encode_significant_node(node, bit_plane, sign_stream, mag_stream):
    """Encode sign and MSB of significant node"""
    sign_stream.append(node.sign_bit)
    mag_stream.append(node.msb_bit(bit_plane))
    # Recursively process children if necessary for full SPIHT logic
    # Note: Full SPIHT involves sorting and listing passes, simplified here
    # for the core concept of bit-plane encoding described in sources.
    for child in node.children:
        if is_significant(child, bit_plane):
            encode_significant_node(child, bit_plane, sign_stream, mag_stream)
        else:
            # Check if child is a zerotree
            if is_zerotree(child, bit_plane):
                encode_zerotree(child, bit_plane, sign_stream, mag_stream)

def is_zerotree(node, bit_plane):
    """Check if node and all descendants are insignificant"""
    if not is_significant(node, bit_plane):
        return all(is_zerotree(child, bit_plane) for child in node.children)
    return False

def encode_zerotree(node, bit_plane, sign_stream, mag_stream):
    """Encode a zerotree with a single bit"""
    mag_stream.append(0) # Indicator bit for zerotree
```

**Parameters**
*   **Quantization Bits:** 32 bits per coordinate component [S1].
*   **Smoothing Parameter ($\alpha$):** Used in Slow Growing Subdivision (SGS). Values less than 0.7 result in unstable wavelets and decreased compression efficiency [S1]. Typical tested values are 0.7 and 0.9 [S1].

**Edge Cases and Pitfalls**
*   **Mesh Interpenetration:** At low bit rates, errors in vertex locations can cause the mesh to interpenetrate, particularly with unstable transforms like SGS with $\alpha < 0.7$ [S1].
*   **Extraordinary Vertices:** The system was not tested on base meshes with extraordinary vertices. Producing a base mesh from an arbitrary finite element mesh is an open problem [S1].
*   **Stability:** SGS wavelets can be unstable for certain $\alpha$ settings, whereas B-spline transforms are well-behaved [S1].

## Operating characteristics
*   **Time and Memory Complexity:** Not given in the sources.
*   **Measured Performance:**
    *   **Perturbed Ball Mesh (4913 vertices):**
        *   Original size: 471,648 bits (32-bit quantization) [S1].
        *   SGS ($\alpha=0.7$): 429,344 bits [S1].
        *   SGS ($\alpha=0.9$): 454,080 bits [S1].
        *   Linear B-spline: 454,848 bits [S1].
    *   **Hohlraum Simulation (134,176 vertices):** Decomposed into 32 domains, each with a base hexahedron subdivided 5 times [S1].
*   **Scaling:** The system is designed for coarse-to-fine reconstruction, allowing progressive refinement [S1].
*   **Strengths:** B-spline wavelets show superior performance at small numbers of bits compared to SGS [S1]. The system effectively exploits coefficient decay for compression [S1].
*   **Limitations:** The back-end compression system does not achieve appreciable gains on the bit streams output by SPIHT [S1]. A progressive representation is not well adapted to local refinement [S1].
*   **When to Use:** Suitable for applications requiring progressive transmission or visualization of volumetric subdivision meshes where coarse-to-fine detail is prioritized [S1].
*   **When Not to Use:** Not suitable for meshes with extraordinary vertices (as tested) or when local refinement is required [S1]. Avoid SGS with $\alpha < 0.7$ due to instability [S1].

## Background
The method was presented in the paper "Progressive Compression of Volumetric Subdivision Meshes" at the 2nd International Symposium on 3D Data Processing, Visualization, and Transmission (3DPVT’04) [S1]. It generalizes the SPIHT image coder, originally described by Said and Perlman, to the slow growing subdivision refinement structure [S1]. The work addresses the challenge of compressing volumetric meshes derived from finite element simulations, such as laser indirect-drive fusion simulations [S1].
