# Block-based intra-band prediction

Also called: Intra-band prediction, Slice-based prediction

## Overview
Block-based intra-band prediction is a lossless compression technique applied to wavelet coefficients to exploit remaining anatomical symmetries and spatial correlations that persist after multi-level decomposition [S1]. It operates by predicting a current block of coefficients from previously encoded blocks using geometric transformations (rotations and mirroring), encoding the residual only if it yields a lower bit-rate than encoding the original block [S1]. Unlike generic volumetric compression methods, this technique is highly specialized for medical images with strong structural symmetries (particularly CT scans) and is ineffective on smooth or non-symmetrical data like MRI or Ultrasound [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sub-band of wavelet coefficients $V$ resulting from the transform described in [Wavelet and Pyramid Transforms](3856-wavelet-and-pyramid-transforms.md) [S1].
*   **Output:** A compressed bitstream containing either the original coefficients or the prediction parameters and residuals, compliant with EBCOT encoding standards [S1].

**Data Structures:**
*   **Prediction Blocks:** The sub-band is partitioned into square blocks of size $N \times N$, where $N \in \{4, 8, 16\}$ [S1].
*   **Candidate Set ($C$):** A dynamic list of previously encoded blocks in raster-scan order, $C = \{b_0, b_1, ..., b_{i-1}\}$ [S1].
*   **Transform Operator ($T_k$):** A function applying one of 8 geometric permutations to a block $b$: identity, 90° rotation, 180° rotation, 270° rotation, horizontal flip, vertical flip, and their combinations (diagonal flips) [S1].

**Algorithm Steps:**
1.  **Initialization:** Set the candidate set $C$ to empty [S1].
2.  **Iteration:** For each block $b_i$ in the sub-band in raster-scan order:
    a.  **Search:** Find the candidate block $b_p \in C$ and transform index $t \in [0, 7]$ that minimizes the $L_1$ norm of the difference:
        $$ L_1(T_t(b_p) - b_i) = \min_{k, b \in C} (L_1(T_k(b) - b_i)) $$
        where $L_1(x) = \sum |x|$ [S1].
    b.  **Encoding Comparison:**
        i.  Calculate the rate $R_{orig}$ required to losslessly encode the original block $b_i$ using EBCOT [S1].
        ii. Calculate the rate $R_{pred}$ required to encode the prediction parameters $(b_p, t)$ using Exponential Golomb ($k=0$) codes and arithmetic coding, plus the rate to losslessly encode the residual $r = T_t(b_p) - b_i$ using EBCOT [S1].
    c.  **Decision:** If $R_{pred} < R_{orig}$, encode the prediction parameters and the residual [S1]. Otherwise, encode the original block $b_i$ directly [S1].
    d.  **Update:** Add $b_i$ to the candidate set $C$ [S1].

**Pseudocode:**
```python
def block_based_intra_band_prediction(sub_band, block_size=16):
    """
    Applies block-based intra-band prediction to a wavelet sub-band.
    sub_band: 2D list of wavelet coefficients.
    block_size: Integer, 4, 8, or 16.
    Returns: List of encoded block records.
    """
    candidates = []
    output_stream = []
    rows = len(sub_band)
    cols = len(sub_band[0])
    num_block_cols = cols // block_size
    total_blocks = (rows // block_size) * num_block_cols
    
    for i in range(total_blocks):
        block_row = (i // num_block_cols) * block_size
        block_col = (i % num_block_cols) * block_size
        b_i = [sub_band[block_row + r][block_col:block_col + block_size] for r in range(block_size)]
        
        best_candidate = None
        best_transform_idx = -1
        best_l1_norm = float('inf')
        
        for b_p in candidates:
            for k in range(8):
                transformed_b_p = apply_transform(b_p, k)
                l1_norm = sum(abs(transformed_b_p[r][c] - b_i[r][c]) 
                              for r in range(block_size) for c in range(block_size))
                
                if l1_norm < best_l1_norm:
                    best_l1_norm = l1_norm
                    best_candidate = b_p
                    best_transform_idx = k
        
        rate_orig = estimate_ebcot_rate(b_i)
        rate_params = estimate_golomb_arithmetic(candidates.index(best_candidate), best_transform_idx)
        residual = apply_transform(best_candidate, best_transform_idx)
        rate_residual = estimate_ebcot_rate(residual)
        rate_pred = rate_params + rate_residual
        
        if rate_pred < rate_orig:
            output_stream.append(('predict', best_candidate, best_transform_idx, residual))
        else:
            output_stream.append(('original', b_i))
            
        candidates.append(b_i)
        
    return output_stream

def apply_transform(block, k):
    """Applies one of 8 geometric permutations to a 2D block [G]."""
    if k == 0: return block
    if k == 1: return [list(row)[::-1] for row in zip(*block)]
    if k == 2: return [row[::-1] for row in block[::-1]]
    if k == 3: return [list(row) for row in zip(*block[::-1])]
    if k == 4: return [row[::-1] for row in block]
    if k == 5: return block[::-1]
    if k == 6: return [list(row) for row in zip(*block)]
    if k == 7: return [list(row)[::-1] for row in zip(*block[::-1])]

def estimate_ebcot_rate(data):
    """Estimates bit-rate using standard EBCOT encoder [G]."""
    return sum(x.bit_length() for row in data for x in row)

def estimate_golomb_arithmetic(idx, transform_idx):
    """Estimates bit-rate using Exponential Golomb(k=0) and arithmetic coding [G]."""
    return idx.bit_length() + 1 + transform_idx.bit_length()
```

**Parameters:**
*   **Block Size:** 4x4, 8x8, or 16x16 coefficients [S1].
*   **Transform Set:** 8 geometric permutations (rotations and mirroring) [S1].
*   **Entropy Coding:** Exponential Golomb ($k=0$) codes and arithmetic coding for prediction parameters $(b, t)$; EBCOT for residuals and original blocks [S1].

**Edge Cases and Pitfalls:**
*   **Image Type Dependency:** The method fails on MRI and Ultrasound images, showing 0% bit-rate reduction or negative gains [S1].
*   **Smooth Regions:** Images with smooth regions have low energy in high-frequency sub-bands, leaving little potential for energy reduction via prediction [S1].
*   **Parameter Encoding Overhead:** The bit-rate savings depend heavily on the efficiency of encoding the prediction parameters $(b, t)$ [S1].
*   **Energy Condition:** Prediction is only applied if the resulting energy of the predicted block is lower than that of the original block [S1].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** The search step requires comparing the current block against all previously encoded blocks in the candidate set $C$ [S1]. Exact complexity formulas are not given in the sources [S1].
*   **Memory:** Requires storing all previously encoded blocks in the candidate set $C$ [S1]. Exact memory overhead formulas are not given in the sources [S1].

**Measured Performance:**
*   **CT Images:** Significant bit-rate reductions were observed [S1]. For example, on a dataset of CT images, JP3D (volumetric) achieved reductions of 0.00% to 4.43% (avg 0.87%), while J2K (slice-based) achieved 0.00% to 3.35% (avg 0.61%) [S1].
*   **MRI/US Images:** 0.00% reduction across all tested images [S1].

**Strengths and Limitations:**
*   **Strengths:** Effective for lossless compression of medical CT volumes with strong anatomical symmetries. Can be integrated as an additional coding mode in JPEG 2000 compliant codecs (JP3D+DA) [S1].
*   **Limitations:** Not a generic coding tool. High computational cost due to exhaustive search [S1]. Ineffective for non-symmetrical or smooth data [S1].

**When to Use:**
*   Use for lossless compression of CT medical volumes where symmetry is prevalent and computational resources allow for exhaustive search [S1].
*   Do not use for MRI, Ultrasound, or general-purpose volume data [S1].

## Background
**Origin:**
The method was proposed to exploit remaining anatomical symmetry correlations in wavelet coefficients of medical images [S1]. It builds upon earlier work by [42] which applied similar intra-band prediction to 2D slices, showing up to 15% bit-rate reduction compared to JPEG 2000 2D [S1].

**History and Development:**
The technique was implemented and tested as part of a volumetric compression framework called JP3D+DA, which extends JPEG 2000 Part 1 and Part 10 to support volumetric data and additional coding techniques [S1]. The study evaluated its performance on various medical image types (CT, MRI, US) using 5x3 wavelet kernels and different decomposition levels [S1].

**Usage:**
It is used as an optional, specialized coding mode within medical image compression pipelines, specifically for CT data, to improve lossless compression efficiency [S1].
