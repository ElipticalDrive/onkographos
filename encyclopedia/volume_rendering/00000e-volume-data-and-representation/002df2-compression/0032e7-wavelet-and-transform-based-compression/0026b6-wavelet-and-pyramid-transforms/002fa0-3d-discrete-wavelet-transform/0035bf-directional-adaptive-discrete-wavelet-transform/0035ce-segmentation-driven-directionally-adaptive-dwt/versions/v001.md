# Segmentation-Driven Directionally Adaptive DWT

Also called: Generic segmentation (SD-DA-DWT), SD-DA-DWT, Segmentation Driven DA-DWT, Slice-based SD-DA-DWT

## Overview
Segmentation-Driven Directionally Adaptive DWT (SD-DA-DWT) is a wavelet compression method that adapts the transform direction locally by segmenting the input data into regions of similar orientation [S1]. It solves the problem of inefficient energy compaction in data with varying local geometries, which fixed-direction transforms like the parent [Directional Adaptive Discrete Wavelet Transform](7554-directional-adaptive-discrete-wavelet-transform.md) handle only globally or via block-based heuristics [S1]. Unlike [Block-based DA-DWT](7586-block-based-da-dwt.md), which uses fixed rectangular blocks, SD-DA-DWT uses irregular, gradient-based segments to maximize directional adaptability at the sample resolution [S1].

## How it works
**Inputs:** Volumetric or 2D image data.
**Outputs:** Compressed bitstream containing segmentation metadata and wavelet coefficients.

**Data Structures:**
1.  **Segment Map:** A grid of segment IDs, one per input sample.
2.  **Segment Metadata:** For each unique segment ID, store the chosen direction vector $d$ and contour information for coding [S1].
3.  **Wavelet Coefficients:** Low-pass and high-pass sub-bands generated by the directional DWT [S1].

**Parameters:**
*   **Kernel:** (6,6) for 2D SD-DA-DWT [S1].
*   **Code-block size:** $64 \times 64 \times 1$ for volumetric slice-based processing to avoid inter-slice side effects [S1].
*   **Segmentation Metric:** L1-norm of prediction (high-pass) coefficients for direction selection [S1].

**Steps:**
1.  **Segmentation:** Apply the Edgementation algorithm to the input data [S1].
    *   Perform gradient-based segmentation to identify initial regions [S1].
    *   Apply rate-distortion-driven segment merging to reduce complexity [S1].
    *   Apply contour simplification using the algorithm from [53] to limit overhead [S1].
2.  **Direction Selection:** For each segment, determine the optimal direction vector $d$ by comparing the L1-norm of the high-pass prediction coefficients for all candidate directions [S1].
3.  **Transformation:** Apply the 2D SD-DA-DWT using the (6,6) kernel and the selected direction $d$ for each segment [S1].
4.  **Coding:** Encode the resulting coefficients using EBCOT (Embedded Block Coding with Optimized Truncation) [S1].
    *   Organize coefficients into code-blocks of size $64 \times 64 \times 1$ [S1].
    *   Encode the segmentation map and direction vectors (overhead often ignored in theoretical evaluations due to lack of suitable volumetric segmentation compression schemes) [S1].

**Pseudocode:**
```python
def sd_da_dwt_compress(volume_data):
    # volume_data: 3D array (Z, Y, X)
    compressed_stream = []
    
    # Process each slice separately for volumetric data
    for z in range(volume_data.shape[0]):
        slice_data = volume_data[z, :, :]
        
        # Step 1: Segment the slice
        # Edgementation algorithm: gradient-based segmentation + rate-distortion merging + contour simplification
        segments, contours = edgementation(slice_data)
        
        # Step 2: Determine direction for each segment
        # Metric: L1-norm of high-pass prediction coefficients
        directions = {}
        for seg_id in segments.unique():
            mask = (segments == seg_id)
            # Calculate L1-norm for candidate directions
            # Select direction d that maximizes energy compaction (minimizes high-pass energy)
            directions[seg_id] = select_optimal_direction(slice_data, mask)
            
        # Step 3: Apply Directional DWT per segment
        # Using (6,6) kernel
        coeffs = apply_directional_dwt_2d(slice_data, segments, directions, kernel=(6,6))
        
        # Step 4: Encode with EBCOT
        # Code-block size 64x64x1 to avoid inter-slice effects
        block_size = (64, 64)
        ebcot_stream = ebcot_encode(coeffs, block_size=block_size)
        
        # Store segmentation overhead (often ignored in practice for volumetric data)
        seg_overhead = encode_segmentation(contours, directions)
        
        compressed_stream.append(ebcot_stream)
        compressed_stream.append(seg_overhead)
        
    return compressed_stream

def select_optimal_direction(data, mask):
    # Candidate directions d
    candidates = [d1, d2, d3, d4] # Predefined set of direction vectors
    best_d = None
    min_l1_norm = infinity
    
    for d in candidates:
        # Apply directional prediction/filtering
        high_pass = directional_high_pass(data, d)
        # Mask to segment region
        high_pass_masked = high_pass * mask
        # L1-norm metric
        l1_norm = sum(abs(high_pass_masked))
        
        if l1_norm < min_l1_norm:
            min_l1_norm = l1_norm
            best_d = d
            
    return best_d
```

**Edge Cases and Pitfalls:**
*   **Volumetric Complexity:** Determining optimal 3D segmentation is complex; the method typically degrades to 2D slice-based processing for medical data [S1].
*   **Overhead:** Storing segmentation descriptions incurs severe overhead. In many evaluations, this overhead is ignored because no suitable volumetric segmentation compression scheme was available, potentially inflating perceived performance [S1].
*   **Failure Mode:** SD-DA-DWT can fail completely if segmentation does not match regions with similar directional features [S1].
*   **Coding Efficiency:** Non-alignment of segmentation boundaries with EBCOT code-block structures negatively influences entropy coder efficiency [S1].

## Subtopics

### [Direction-Adaptive DWT (DA-DWT)](7827-direction-adaptive-dwt-da-dwt.md)
DA-DWT is a wavelet transform technique where the direction vector $d$ changes dynamically based on spatial location to optimize energy compaction for localized directional features in volumetric data. It solves the problem of inefficient energy compaction when using fixed-direction transforms on data with varying local orientations. Unlike standard 3D DWT which uses fixed axes, DA-DWT adapts to the data's geometry, but requires signaling the chosen direction in the code-stream.

## Operating characteristics
*   **Performance:** For medical volumetric images, SD-DA-DWT delivers no significant overall compression improvements compared to classical DWT [S1]. Only specific datasets (CT5, CT6) show modest gains, but these results exclude segmentation signaling overhead [S1].
*   **Complexity:** High computational complexity due to the iterative Edgementation segmentation process and per-segment direction selection [S1].
*   **Overhead:** Significant overhead from segmentation metadata. The method's practical utility is limited by the lack of efficient volumetric segmentation compression [S1].
*   **Strengths:** Maximal directional adaptability at sample resolution [S1].
*   **Limitations:** Fails on images where segmentation cannot match directional features; sensitive to code-block alignment; high overhead [S1].
*   **When to use:** Theoretical analysis of directional adaptability limits.
*   **When not to use:** Practical volumetric medical image compression where overhead and complexity are critical [S1].

## Background
SD-DA-DWT was introduced in the work of [34] (cited in [S1]) as a generic segmentation-driven approach. It applies 2D SD-DA-DWT to volumetric datasets by segmenting slices separately, using the (6,6) kernel [S1]. The segmentation relies on the Edgementation algorithm [51, 52] and contour coding from [53] [S1].
