# Lifting-Based Integer Wavelet Transform Construction

Also called: Integer Lifting Scheme, Integer Wavelet Transform via Lifting, Rounding Lifting

## Overview
This method constructs integer-preserving wavelet transforms by approximating traditional non-integer wavelet filters (such as Daubechies 9/7) using the lifting scheme with rounding operations [S1]. It solves the problem of perfect reconstruction in lossless compression by ensuring that integer input data remains integer throughout the transform, avoiding the precision loss and infinite precision requirements of floating-point arithmetic [S1]. It sets itself apart from standard floating-point wavelet transforms by embedding the rounding steps directly into the filter decomposition, allowing for exact invertibility with finite precision arithmetic [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 1D signal array $x[n]$ of integers.
*   **Output:** Low-pass coefficients $s[n]$ and high-pass coefficients $d[n]$, both integers.

**Data Structures:**
The transform operates in-place or with minimal temporary storage. Due to the interleaved nature of lifting, low-pass and high-pass samples are available simultaneously [S1].

**Parameters:**
*   **Rounding:** Applied to every lifting step to ensure integer results. The rounding function $\lfloor \cdot \rceil$ denotes rounding to the nearest integer (ties may be handled by floor or ceil depending on specific implementation, but standard rounding is implied) [S1].
*   **Scaling Factors:** For the 9/7 transform, specific coefficients are used. The source notes that factors are approximated to allow fast integer implementation via bit shifts [S1]. For example, in the 9/7 transform, coefficients like $1.5861$ are approximated by $1.5$ ($3/2$) or similar rational numbers representable by bit shifts [S1].

**Steps:**
1.  **Decompose the Target Filter:** Identify the lifting steps for the desired non-integer wavelet (e.g., Daubechies 9/7). The standard 9/7 filter can be decomposed into a sequence of lifting steps [S1].
2.  **Approximate Coefficients:** Replace real-valued lifting coefficients with integer-friendly approximations (e.g., using bit shifts) [S1].
3.  **Apply Lifting Steps with Rounding:** Execute the lifting steps sequentially. Each prediction or update step involves a weighted sum followed by rounding to the nearest integer [S1].
    *   Let $s$ be the low-pass subband and $d$ be the high-pass subband.
    *   For a generic lifting step with coefficient $k$:
        $$ d[n] = d[n] + \lfloor k \cdot s[n] \rceil $$
        $$ s[n] = s[n] + \lfloor k \cdot d[n] \rceil $$
    *   The specific steps for the 9/7 filter are detailed in Table I of the source [S1].
4.  **Handle Scaling:** The final step in the standard lifting scheme involves scaling the subbands to maintain unitary energy. In the integer domain, this is handled by either:
    *   **Bit Shifting:** Using powers of two for scaling factors, implemented via arithmetic shifts [S1].
    *   **Lifting-Based Scaling:** Decomposing the scaling matrix into four additional lifting steps if the scaling factor is not a power of two [S1].

**Edge Cases and Pitfalls:**
*   **Rounding Direction:** Consistency in rounding (e.g., always floor, always round half up) is critical for invertibility. The inverse must use the exact same rounding logic [S1].
*   **Precision:** Using bit-shift approximations for coefficients introduces small errors compared to the original floating-point filter, but these are bounded and do not affect invertibility [S1].
*   **Scaling:** Scaling by non-power-of-two factors requires careful handling to maintain integer properties. The source suggests decomposing the scaling matrix into lifting steps to avoid real-number arithmetic [S1].

## Subtopics

### Scaling by Lifting
This variant addresses the final scaling step of the wavelet transform, which typically involves multiplying low-pass coefficients by $s_0$ and high-pass coefficients by $s_1$ (where $s_0 s_1 = 2$ for unitary transforms) [S1]. Instead of using floating-point multiplication, the scaling matrix is decomposed into a product of four specific lifting matrices [S1]. These four lifting steps replace the scaling process. This approach does not require more memory than a floating-point implementation because the low-pass and high-pass samples are interleaved and available simultaneously during the lifting process [S1].

## Operating characteristics
*   **Time Complexity:** Linear $O(N)$, same as standard wavelet transforms, but with slightly higher constant factors due to rounding and multiple lifting steps [S1].
*   **Memory Complexity:** $O(N)$ for the input/output arrays. The lifting scheme allows in-place computation, requiring no additional memory for intermediate subbands beyond the input size [S1].
*   **Performance:** The method is designed for lossless compression of medical volumetric data [S1]. It enables exact reconstruction, which is critical for medical imaging [S1].
*   **Strengths:** Perfect reconstruction with integer arithmetic; no precision loss; efficient implementation via bit shifts for common coefficients [S1].
*   **Limitations:** The approximation of non-integer filters (like 9/7) may result in slightly different frequency response characteristics compared to the original floating-point filter [S1].

## Background
The lifting scheme was introduced as a flexible framework for constructing wavelets [S1]. The specific application of lifting to construct integer wavelet transforms for lossless compression was detailed in research on medical volumetric data [S1]. The method allows traditionally non-integer transforms, which are difficult to implement exactly in integer arithmetic, to be approximated by integer versions through the addition of rounding to each lifting step [S1]. This approach simplifies the construction of integer wavelet transforms compared to earlier methods [S1].
