# Blockwise Wavelet Compression

Also called: Blockwise wavelet

## Overview
Blockwise wavelet compression is a volume data compression technique that decomposes 3D datasets into small, equal-sized blocks to enable independent compression and decompression along each axis [S1]. It differs from global wavelet methods by localizing the transform to fixed spatial regions [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset $V$ of dimensions $N_x \times N_y \times N_z$ [G].
*   **Output:** A set of compressed coefficient blocks or a bitstream [G].

**Data Structures:**
The volume is partitioned into non-overlapping blocks of equal size [G]. Let the block dimensions be $B_x \times B_y \times B_z$ [G]. The total number of blocks is $\lceil N_x/B_x \rceil \times \lceil N_y/B_y \rceil \times \lceil N_z/B_z \rceil$ [G]. Each block is treated as an independent 3D array for the transform [G].

**Steps:**
1.  **Partitioning:** Split the 3D data volume into small blocks of equal size [S1].
2.  **Transform:** Apply a 3D wavelet transform to each block individually along the three axes [S1]. This involves applying separable 1D wavelet filters along the x, y, and z axes [G]. For each block, the transform produces approximation coefficients (low-frequency) and detail coefficients (high-frequency) in various subbands [G].
3.  **Compression:** Quantize and entropy encode the coefficients of each block [G].
4.  **Decompression:** To reconstruct, decode the coefficients and apply the inverse wavelet transform to each block individually [S1].

**Formulas:**
Let $V_{i,j,k}$ be the voxel value at indices $(i,j,k)$ [G]. The block index $(b_x, b_y, b_z)$ is determined by:
$$ b_x = \lfloor i / B_x \rfloor, \quad b_y = \lfloor j / B_y \rfloor, \quad b_z = \lfloor k / B_z \rfloor $$
The local coordinates within a block are:
$$ r_x = i \mod B_x, \quad r_y = j \mod B_y, \quad r_z = k \mod B_z $$
The wavelet transform $W$ is applied to each block $V_{b_x, b_y, b_z}$:
$$ C_{b_x, b_y, b_z} = W(V_{b_x, b_y, b_z}) $$
Where $C$ represents the set of wavelet coefficients for that block [G].

**Parameters:**
*   **Block Size ($B_x, B_y, B_z$):** Not given in the sources [G].
*   **Wavelet Filter:** Not given in the sources [G].

**Edge Cases and Pitfalls:**
*   **Boundary Effects:** Blocks at the volume boundaries may be smaller than $B_x \times B_y \times B_z$ [G]. Boundary handling strategies are not given in the sources [G].

**Pseudocode:**
```python
def compress(V, Bx, By, Bz):
    blocks = []
    for bx in range(ceil(V.shape[0] / Bx)):
        for by in range(ceil(V.shape[1] / By)):
            for bz in range(ceil(V.shape[2] / Bz)):
                block = V[bx*Bx:(bx+1)*Bx, by*By:(by+1)*By, bz*Bz:(bz+1)*Bz]
                coeffs = wavelet_transform_3d(block) # Sources do not specify filter or boundary handling [G]
                blocks.append(quantize_and_encode(coeffs)) # Standard entropy coding [G]
    return blocks

def decompress(blocks, Bx, By, Bz, shape):
    V = zeros(shape)
    idx = 0
    for bx in range(ceil(shape[0] / Bx)):
        for by in range(ceil(shape[1] / By)):
            for bz in range(ceil(shape[2] / Bz)):
                coeffs = decode_and_dequantize(blocks[idx]) # Standard inverse entropy coding [G]
                block = inverse_wavelet_transform_3d(coeffs)
                V[bx*Bx:(bx+1)*Bx, by*By:(by+1)*By, bz*Bz:(bz+1)*Bz] = block
                idx += 1
    return V
```

## Subtopics

### [Hierarchical Wavelet Compression](6108-hierarchical-wavelet-compression.md)
Extends blockwise decomposition by organizing data into an octree structure for multi-resolution access. It groups low-frequency components into larger blocks recursively, differing from standard blockwise approaches that use fixed subregions. Choose it when adaptive multi-resolution rendering is required over fixed block boundaries.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels, $O(N)$, assuming constant block size and transform depth [G].
*   **Memory Complexity:** Requires storage for the original volume and the compressed coefficients [G].
*   **Measured Performance:** Not given in the sources [G].
*   **Scaling:** Linear scaling with block count [G].
*   **Strengths:** Enables parallel compression and decompression; supports localized detail extraction [S1].
*   **Limitations:** Not given in the sources [G].
*   **When to use:** Large datasets requiring parallel processing [S1].
*   **When not to use:** Not given in the sources [G].

## Background
Blockwise wavelet compression was proposed by Nguyen et al. as a method to split 3D data into small blocks for individual compression and decompression along the three axes [S1]. Guthe et al. later employed block-based wavelets to compress datasets and extract levels of detail on the fly [S1]. Xie et al. extended this concept by integrating hierarchical wavelet representation [S1]. Gao et al. proposed a parallel multiresolution technique to accelerate large dataset visualization [S1]. The technique is part of the broader field of wavelet compression for volume visualization [S1].
