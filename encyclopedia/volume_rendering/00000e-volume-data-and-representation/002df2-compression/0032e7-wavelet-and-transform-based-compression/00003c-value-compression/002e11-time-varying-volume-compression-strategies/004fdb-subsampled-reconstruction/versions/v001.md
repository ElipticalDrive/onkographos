# Subsampled Reconstruction

Also called: Partial Decoding for Fast Interaction, Subsampled Time Step Decoding

## Overview
Subsampled Reconstruction is a technique for time-varying volume rendering that enables fluent user interaction by decoding only a subsampled portion of the compressed data rather than the full time step [S1, unofficial]. It addresses the latency bottleneck in real-time exploration of large 4D datasets, where full reconstruction times can exceed 100ms [S1, unofficial]. Unlike full reconstruction or sibling methods like DCT-compressed time-runs rendering, it prioritizes interaction speed over spatial fidelity by skipping a significant fraction of the coefficient decoding [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A compressed bitstream of a time-varying volume dataset (e.g., 1:128 compression ratio) and a subsampling factor $k$ (e.g., 1:8).
*   **Output:** A reconstructed 3D volume slice at the current time step, containing only the subsampled voxels.

**Data Structures:**
The method operates on the coefficient hierarchy generated by the parent transform (e.g., Tensor-Train decomposition or wavelet transform). The coefficients are stored in a compressed format. The subsampling is applied to the spatial dimensions of the reconstructed volume.

**Steps:**
1.  **Identify Subsampled Indices:** Determine the set of spatial indices $(x, y, z)$ to reconstruct. For a 1:8 subsampling factor, this typically means selecting every 8th voxel along each axis, or a specific pattern that reduces the data volume by a factor of 8 [S1, unofficial].
2.  **Selective Decoding:** Decode only the coefficients required to reconstruct the values at the identified subsampled indices. This involves skipping the decoding of coefficients that contribute exclusively to the non-selected voxels [S1, unofficial].
3.  **Inverse Transform:** Apply the inverse transform (e.g., inverse Tensor-Train decomposition or inverse wavelet transform) to the decoded coefficients to compute the voxel values at the subsampled locations [S1, unofficial].
4.  **Render:** Pass the partially reconstructed volume to the rendering engine. The rendering engine may use interpolation or nearest-neighbor sampling to fill in the gaps for visualization, or the user accepts the lower spatial resolution for the sake of speed [S1, unofficial].

**Parameters:**
*   **Subsampling Factor ($k$):** The ratio of skipped voxels. A factor of 1:8 is cited as an example [S1, unofficial].
*   **Compression Ratio:** The underlying compression of the dataset (e.g., 1:128) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Aliasing:** Heavy subsampling may introduce aliasing artifacts if the scene contains high-frequency details [G].
*   **Visual Consistency:** The resulting volume may appear blocky or sparse, requiring careful integration with the rendering pipeline to avoid visual discontinuities [G].

**Pseudocode:**
```python
def subsampled_reconstruction(compressed_data, subsampling_factor):
    """
    Reconstructs a volume from compressed data using subsampled decoding.
    
    Args:
        compressed_data: The compressed bitstream or coefficient structure.
        subsampling_factor: Integer factor by which to subsample (e.g., 8 for 1:8).
        
    Returns:
        A 3D array containing the reconstructed voxel values at subsampled positions.
    """
    # Determine the full spatial dimensions
    full_dims = compressed_data.get_spatial_dimensions()
    
    # Calculate subsampled dimensions
    sub_dims = [d // subsampling_factor for d in full_dims]
    
    # Initialize output array
    reconstructed_volume = zeros(sub_dims)
    
    # Identify indices to decode
    # For a simple grid subsampling, select every k-th element
    indices_to_decode = []
    for x in range(0, full_dims[0], subsampling_factor):
        for y in range(0, full_dims[1], subsampling_factor):
            for z in range(0, full_dims[2], subsampling_factor):
                indices_to_decode.append((x, y, z))
    
    # Decode only the necessary coefficients
    # This step is specific to the underlying transform (e.g., TT4D)
    # and involves skipping coefficients that do not contribute to the selected indices.
    decoded_coefficients = selective_decode(compressed_data, indices_to_decode)
    
    # Apply inverse transform to reconstruct values
    # The inverse transform maps the selected coefficients back to spatial values
    for i, (x, y, z) in enumerate(indices_to_decode):
        # Map global index to local subsampled index
        lx = x // subsampling_factor
        ly = y // subsampling_factor
        lz = z // subsampling_factor
        
        # Reconstruct value at this position
        value = inverse_transform(decoded_coefficients, x, y, z)
        reconstructed_volume[lx, ly, lz] = value
        
    return reconstructed_volume
```

## Subtopics

### [Multiresolution Volume Sampling](14183-multiresolution-volume-sampling.md)
An adaptive spatial subsampling scheme that progressively reconstructs a 3D time-slice from a 4D base tensor. It differs by refining to full resolution when interaction slows and reusing previously computed values.

## Operating characteristics
*   **Time Complexity:** Significantly faster than full reconstruction. For a 1:8 subsampled time step from a 1:128 compressed dataset, reconstruction takes approximately 20.8ms [S1, unofficial].
*   **Memory Complexity:** Reduced memory bandwidth usage during decoding, as only a fraction of the coefficients are processed [S1, unofficial].
*   **Strengths:** Enables fluent interaction (e.g., time slider scrubbing) for large datasets where full reconstruction would cause lag (>100ms) [S1, unofficial].
*   **Limitations:** Lower spatial resolution and potential loss of fine details due to subsampling [S1, unofficial].
*   **When to use:** Real-time exploration of time-varying volumes where interaction speed is critical and visual fidelity can be temporarily compromised.
*   **When not to use:** Final visualization or analysis requiring high spatial accuracy.

## Background
The method was proposed in the context of Tensor-Train-based 4D time-dependent volume rendering (TT4D) to address the high reconstruction times associated with large datasets [S1, unofficial]. It is part of a family of compression strategies designed for real-time rendering of time-varying volumetric datasets [S1, unofficial].
