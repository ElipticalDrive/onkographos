# Multiresolution Volume Sampling

Also called: Adaptive progressive spatial reconstruction, Progressive decoding, Repetitive cube scheme

## Overview
Multiresolution Volume Sampling is an adaptive spatial subsampling scheme that progressively reconstructs a 3D time-slice from a 4D base tensor to provide smooth rendering during fast time slider interactions, refining to full resolution when interaction slows [S1]. It differs from complex interpolation schemes by computing a subset of final data values and copying them to non-computed voxels, allowing previously computed values to be reused during refinement steps [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 4D base tensor $T_c$ with spatial dimensions $X, Y, Z$ and time dimension $W$, and a time column vector from the last TT core $C_4$ corresponding to the requested time step [S1].
*   **Output:** A 3D volume grid of values for the specified time step, initially at low resolution and progressively refined to full resolution [S1].

**Data Structures:**
The volume is conceptually divided into disjoint $2 \times 2 \times 2$ cubes [S1]. Each cube contains 8 voxels. The subsampling pattern defines which voxels are computed and which are copied [S1].

**Parameters:**
*   **Initial Subsampling Ratio:** $1:8$ [S1].
*   **Intermediate Subsampling Ratio:** $1:4$ [S1].
*   **Target Resolution:** $1:1$ (full resolution) [S1].
*   **Time Budget:** $30$ ms per time step [S1].

**Steps:**
1.  **Initialize:** Start with the lowest subsampling ratio, typically $1:8$ [S1].
2.  **Define Subsampling Pattern:** Divide the 3D volume into disjoint $2 \times 2 \times 2$ cubes [S1].
3.  **Decode Subset:** Identify the subset of voxels to compute based on the current ratio. For $1:8$, this is one voxel per cube (e.g., the corner) [S1]. Extract the corresponding spatial subtensor from $T_c$ for these voxels [S1]. Perform tensor-vector multiplication: Multiply the partial subtensor with the time column vector of $C_4$ [S1]. This yields the values for the computed subset of voxels [S1].
4.  **Copy Values:** Copy the computed subset values to the remaining 7 voxels in each $2 \times 2 \times 2$ cube [S1]. This fills the volume at the current low resolution [S1].
5.  **Adaptive Refinement:** Measure the computation time for the current step [S1]. If the time is within the budget (e.g., $< 30$ ms) and interaction is still active, increase the resolution [S1]. Refine to $1:4$: Decode the cube's diagonal element (in addition to the corner) [S1]. Reuse the previously computed corner values [S1]. Refine to $1:1$: Decode all remaining voxels in the cube [S1]. Reuse previously computed values [S1]. Stop refining if the time budget is exceeded or if full resolution is reached [S1].

**Pseudocode:**
```python
def multiresolution_volume_sampling(T_c_shape, T_c_data, C4_col, time_budget_ms=30.0):
    """
    T_c_shape: tuple (X, Y, Z) of the spatial dimensions.
    T_c_data: 4D array/tensor of shape (X, Y, Z, W).
    C4_col: 1D array/vector of shape (W,) from the last TT core.
    time_budget_ms: Maximum allowed computation time per step.
    Returns: 3D array of shape (X, Y, Z).
    """
    X, Y, Z = T_c_shape
    W = len(C4_col)
    # Initialize output volume with zeros
    volume = [[0.0] * Z for _ in range(Y)]
    # Track computed voxels to avoid recomputation during refinement
    computed = set()
    start_time = time.time() * 1000

    # Subsampling patterns: relative coordinates within each 2x2x2 cube
    patterns = [
        [(0, 0, 0)],  # 1:8 ratio
        [(0, 0, 0), (1, 1, 1)],  # 1:4 ratio
        [(x, y, z) for x in range(2) for y in range(2) for z in range(2)]  # 1:1 ratio
    ]

    for pattern in patterns:
        # Iterate over all 2x2x2 cubes in the volume
        for cx in range(0, X, 2):
            for cy in range(0, Y, 2):
                for cz in range(0, Z, 2):
                    # Process each voxel defined by the current pattern
                    for dx, dy, dz in pattern:
                        vx, vy, vz = cx + dx, cy + dy, cz + dz
                        if (vx, vy, vz) in computed:
                            continue
                        # Extract spatial subtensor for this voxel along time dimension
                        subtensor = [T_c_data[vx][vy][vz][w] for w in range(W)]
                        # Tensor-vector multiplication (dot product)
                        value = sum(s * c for s, c in zip(subtensor, C4_col))
                        volume[vx][vy][vz] = value
                        computed.add((vx, vy, vz))

        # Check time budget
        if (time.time() * 1000 - start_time) > time_budget_ms:
            break

    # Fill non-computed voxels by copying from a computed voxel in the same cube
    for cx in range(0, X, 2):
        for cy in range(0, Y, 2):
            for cz in range(0, Z, 2):
                source_val = None
                # Find a computed voxel in this cube to copy from
                for dx, dy, dz in patterns[-1]: # Check all positions in cube
                    if (cx+dx, cy+dy, cz+dz) in computed:
                        source_val = volume[cx+dx][cy+dy][cz+dz]
                        break
                if source_val is None:
                    continue # Should not happen if 1:8 runs first
                # Copy to all 8 voxels in the cube
                for dx in range(2):
                    for dy in range(2):
                        for dz in range(2):
                            if (cx+dx, cy+dy, cz+dz) not in computed:
                                volume[cx+dx][cy+dy][cz+dz] = source_val
    return volume
```

**Edge Cases and Pitfalls:**
*   **Fast Changing Time Steps:** If the time slider moves too quickly, the system may not reach full resolution reconstruction, resulting in lower-quality rendering [S1].
*   **Precision:** Copying values introduces discontinuities at cube boundaries if the underlying data is not smooth, though this is accepted for the sake of performance [S1].
*   **Boundary Conditions:** The cube division must handle volume dimensions that are not multiples of 2. The source does not specify padding or truncation strategies for non-aligned boundaries [G].

## Operating characteristics
*   **Time Complexity:** The complexity is proportional to the number of computed voxels [G]. Initially, it is $1/8$ of the full volume, then $1/4$, then $1/1$ [S1]. The adaptive nature ensures that computation stops as soon as the time budget (30 ms) is exceeded [S1].
*   **Memory Complexity:** Requires storage for the 4D base tensor $T_c$ and the TT cores [G]. The sampling is sparse initially, decoding only a fraction of the base tensor, while the output volume is filled to full resolution by copying values [S1].
*   **Measured Performance:** The reduced number of operations per reconstructed time step, combined with GPU acceleration, allows for interactive, flexible reconstruction of any requested time step [S1].
*   **Strengths:** Provides a dynamic overview during fast interactions [S1]. Reuses computed values during refinement, avoiding redundant calculations [S1]. Simpler than complex interpolation schemes [S1].
*   **Limitations:** May not achieve fully smooth and fluid rendering for quickly changing time steps [S1]. Visual quality is lower at subsampled resolutions due to copying rather than interpolation [S1].
*   **When to Use:** During active sliding through time to give a dynamic overview, refining when interaction slows [S1].
*   **When Not to Use:** When high-fidelity, smooth rendering is required regardless of interaction speed, or when the time slider is static [S1].

## Background
*   **Origin:** Proposed in the context of Tensor-Train-based 4D Time-Dependent Volume Rendering (TT4D) [S1].
*   **History:** Developed to address the limitation of standard reconstruction strategies which, while achieving interactive rates for large data, may not reach fully smooth rendering for quickly changing time steps [S1].
*   **Usage:** Used in GPU-accelerated volume rendering systems where user interaction with the time selector is frequent [S1].
