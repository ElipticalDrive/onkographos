# Texture Format Compression

Also called: Block Compression, BCn, DXT, S3TC

## Overview
Texture Format Compression refers to the use of standardized, block-based compression algorithms originally designed for 2D image data to compress volumetric or texture data. It solves the problem of high memory bandwidth and storage requirements by compressing small blocks of texels (typically 4x4) into a fixed-size bitstream using endpoint interpolation and index lookup [S1, unofficial][S2, book]. What sets it apart from transform-based methods (like Wavelets) is its reliance on spatial locality and piecewise linear interpolation within fixed blocks, rather than frequency decomposition [S1, unofficial].

## Shared principles
The family shares the following mechanism:
1.  **Block Partitioning:** The input data is divided into fixed-size blocks (e.g., 4x4 texels).
2.  **Endpoint Encoding:** Each block is represented by one or two "endpoint" values (min/max or specific control points) stored explicitly in the compressed header.
3.  **Interpolation Table:** A set of intermediate values is generated by linearly interpolating between the endpoints. The number of interpolated values depends on the specific format (e.g., 4-value or 6-value modes).
4.  **Index Mapping:** Each texel in the block is mapped to the closest value in the interpolation table, storing only a small index (e.g., 2 or 3 bits) instead of the full precision value.
5.  **Fixed Bitrate:** The compression ratio is determined by the block size and the number of bits per texel, resulting in constant bitrate access regardless of data complexity.

## Subtopics

### [BC5 Compression](5013-bc5-compression.md)
BC5 is a block compression format for 2-channel (RG) textures, compressing 4x4 blocks (32 bytes) into 16 bytes. It supports two variants: BC5_UNORM (outputs [0, 1] floats) and BC5_SNORM (outputs [-1, 1] floats). It is the 2-channel extension of BC4, which handles single-channel (R) data.

### Distance Field Compression
#### definition
- [S1, unofficial] Compression of the distance field texture (e.g., using BCn) to save memory/bandwidth, ensuring compressed values remain lower than originals to avoid overshooting.
#### pitfall
- [S1, unofficial] Compressed values must stay lower than the original uncompressed values to avoid overshooting the cloud boundary.

### Quantized Texture Representation
#### definition
- [S2, book] Re-encoding NanoVDB float32 density data into compressed texture formats to reduce memory footprint.
#### parameter
- [S2, book] Selected format: BC4 (4 bits per texel).
#### number
- [S2, book] BC4 compression results in a PSNR of 54.34 dB and a FLIP error of 0.00738 compared to the baseline.

### HDR Image Compression via Log-RGB Tree
#### definition
- [S3, unofficial] A scheme to compress HDR images by capturing high-dynamic range variations using an aggressively compressed tree on log(RGB) data, and encoding the remaining low-dynamic range detail using standard DXT1 compression.
#### step
- [S3, unofficial] Apply tree compression to the log(RGB) image to capture HDR variation.
- [S3, unofficial] Quantize the channels of the detail image separately to 8 bits.
- [S3, unofficial] Compress the quantized detail image using ordinary DXT1 compression.
#### parameter
- [S3, unofficial] Bit rate for the tree-compressed log(RGB) component: 1 bit/pixel.
- [S3, unofficial] Bit rate for the DXT1 detail component: 4 bits/pixel.
- [S3, unofficial] Overall representation bit rate: 5 bits/pixel.
#### pitfall
- [S3, unofficial] Encoding all 3 color channels (rather than just luminance) reduces subsequent hue quantization artifacts.
#### comparison
- [S3, unofficial] Compares favorably with Munkberg et al [MCHA06] which uses 8 bits/pixel.

## Background
Block compression formats originated in the late 1990s with S3 Texture Compression (S3TC/DXT) to accelerate 2D texture rendering on GPUs [S1, unofficial]. The BC5 format extends this to dual-channel data, commonly used for normal maps or displacement fields [S1, unofficial]. In volume rendering, these formats are adapted for compressing density fields [S2, book] and distance fields [S1, unofficial]. The use of BC4 for NanoVDB data demonstrates its applicability to scientific volume data, achieving significant compression ratios with minimal perceptual error [S2, book]. HDR compression techniques have also adapted block-based principles by combining tree structures with DXT1 for detail layers [S3, unofficial].
