# BC5 Compression

## Overview
BC5 is a block compression format for 2-channel (RG) textures, compressing 4x4 blocks (32 bytes) into 16 bytes [S1, unofficial]. It supports two variants: BC5_UNORM (outputs [0, 1] floats) and BC5_SNORM (outputs [-1, 1] floats) [S1, unofficial]. It is the 2-channel extension of BC4, which handles single-channel (R) data [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 4x4 block of 16 unsigned 8-bit integers (u8) per channel (R and G), totaling 32 bytes.
*   **Output:** A 16-byte compressed block.

**Data Structures:**
The compressed block layout is fixed at 16 bytes:
1.  **Byte 0:** Minimum value for the channel (u8).
2.  **Byte 1:** Maximum value for the channel (u8).
3.  **Bytes 2–7:** 16 indices, each 3 bits wide, packed into 6 bytes. The indices are arranged in two rows of 8 indices, corresponding to the 4x4 texel grid [S1, unofficial].

**Algorithm:**
The compression is performed independently on each channel (R and G). The following steps describe the encoding for one channel:

1.  **Endpoint Calculation:**
    *   Initialize `colors[0]` and `colors[1]` to the first pixel value of the block.
    *   Iterate through all 16 pixel values in the block.
    *   Update `colors[0]` to be the minimum value found.
    *   Update `colors[1]` to be the maximum value found.
    *   Scale both endpoints by shifting left by 20 bits: `colors[0] <<= 20`, `colors[1] <<= 20` [S1, unofficial].

2.  **Interpolation Table Generation:**
    *   If `colors[1] < colors[0]` (which implies an edge case where max < min or specific overflow/initialization state, though typically `colors[1] >= colors[0]` holds for valid min/max pairs after shifting unless they are equal and handled specifically), use the **6-value mode**:
        *   `colors[2] = (6 * colors[0] + 1 * colors[1]) / 7`
        *   `colors[3] = (5 * colors[0] + 2 * colors[1]) / 7`
        *   `colors[4] = (4 * colors[0] + 3 * colors[1]) / 7`
        *   `colors[5] = (3 * colors[0] + 4 * colors[1]) / 7`
        *   `colors[6] = (2 * colors[0] + 5 * colors[1]) / 7`
        *   `colors[7] = (1 * colors[0] + 6 * colors[1]) / 7`
    *   Otherwise (if `colors[1] >= colors[0]`), use the **4-value mode**:
        *   `colors[2] = (4 * colors[0] + 1 * colors[1]) / 5`
        *   `colors[3] = (3 * colors[0] + 2 * colors[1]) / 5`
        *   `colors[4] = (2 * colors[0] + 3 * colors[1]) / 5`
        *   `colors[5] = (1 * colors[0] + 4 * colors[1]) / 5`
        *   `colors[6] = 0`
        *   `colors[7] = 255 << 20`
    *   *Note:* The source code uses `colors[1] < colors[0]` to trigger the 6-value mode. In standard BC5, the 6-value mode is used when the endpoints are equal to provide a gradient, but the provided implementation logic suggests this condition might be a specific implementation detail or error handling for degenerate cases [S1, unofficial].

3.  **Index Mapping:**
    *   For each of the 16 pixels in the block:
        *   Find the index `i` (0–7) in the `colors` array that minimizes the absolute difference `|colors[i] - pixel_value|`.
        *   Store the 3-bit index in the compressed block [S1, unofficial].

**Pseudocode:**

```python
def compress_bc5_channel(block: list[int]) -> tuple[int, int, list[int]]:
    """
    Compress a single channel of a 4x4 BC5 block.
    block: list of 16 integers (0-255) representing the 4x4 texel values.
    Returns: (min_val, max_val, indices) where indices is a list of 16 integers (0-7).
    """
    # Step 1: Find min and max
    min_val = block[0]
    max_val = block[0]
    for i in range(1, 16):
        if block[i] < min_val:
            min_val = block[i]
        if block[i] > max_val:
            max_val = block[i]
            
    # Step 2: Scale endpoints
    shift = 20
    c0 = min_val << shift
    c1 = max_val << shift
    
    # Step 3: Generate interpolation table
    colors = [0] * 8
    colors[0] = c0
    colors[1] = c1
    
    if c1 < c0:
        # 6-value mode
        colors[2] = (6 * c0 + 1 * c1) // 7
        colors[3] = (5 * c0 + 2 * c1) // 7
        colors[4] = (4 * c0 + 3 * c1) // 7
        colors[5] = (3 * c0 + 4 * c1) // 7
        colors[6] = (2 * c0 + 5 * c1) // 7
        colors[7] = (1 * c0 + 6 * c1) // 7
    else:
        # 4-value mode
        colors[2] = (4 * c0 + 1 * c1) // 5
        colors[3] = (3 * c0 + 2 * c1) // 5
        colors[4] = (2 * c0 + 3 * c1) // 5
        colors[5] = (1 * c0 + 4 * c1) // 5
        colors[6] = 0
        colors[7] = 255 << shift
        
    # Step 4: Find nearest index for each pixel
    indices = []
    for pixel in block:
        min_diff = abs(colors[0] - pixel)
        best_index = 0
        for i in range(1, 8):
            diff = abs(colors[i] - pixel)
            if diff < min_diff:
                min_diff = diff
                best_index = i
        indices.append(best_index)
        
    return min_val, max_val, indices
```

**Parameters:**
*   `Shift`: 20 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   The condition `colors[1] < colors[0]` in the source code is noted as potentially non-optimal or non-compliant with standard reference implementations like GPUOpen Compressonator [S1, unofficial].
*   The 4-value mode sets `colors[6]` to 0 and `colors[7]` to `255 << Shift`, which may not represent valid interpolated values if the endpoints are not at the extremes of the range [S1, unofficial].

## Operating characteristics
*   **Compression Ratio:** 2:1 (32 bytes to 16 bytes) [S1, unofficial].
*   **Bitrate:** Constant 8 bits per texel per channel [S1, unofficial].
*   **Performance:** Not given in the sources.
*   **Strengths:** Simple implementation, constant bitrate access [S1, unofficial].
*   **Limitations:** The provided implementation may not be fully compliant with standard reference implementations [S1, unofficial].

## Background
BC5 is part of the S3 Texture Compression (S3TC) family, specifically designed for 2-channel data. It is commonly used for normal maps, where the R and G channels represent the X and Y components of the normal vector [S1, unofficial].
