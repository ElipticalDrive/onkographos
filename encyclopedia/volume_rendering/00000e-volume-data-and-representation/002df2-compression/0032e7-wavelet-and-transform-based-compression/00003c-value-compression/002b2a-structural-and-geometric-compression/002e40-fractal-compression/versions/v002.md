# Fractal Compression

Also called: Block-based Fractal Compression, Iterative Function System Compression, 分形压缩

## Overview
Fractal compression is a lossy volume compression method that exploits self-similarity within the dataset by mapping each "range block" to a larger, most similar "domain block" from the same volume, storing only the affine transformation required to convert the domain block into the range block [S1]. Unlike vector quantization, which stores a reference to a codeword, fractal compression stores the geometric relationship between two different-sized blocks, allowing for high compression ratios at the cost of extreme encoding complexity and iterative reconstruction during decoding [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D volume dataset $V$.
*   **Output:** A compressed bitstream containing, for each range block, the position (coordinates) of the matched domain block and the parameters of the affine transformation mapping the domain to the range [S1].

**Data Structures**
The compressed data structure consists of a list of entries, one per range block [S1]. Each entry contains:
1.  **Domain Position:** 3D integer coordinates $(x_d, y_d, z_d)$ indicating the anchor of the domain block in the original volume grid [S1].
2.  **Transformation Parameters:** A set of coefficients defining the affine transform, including spatial scaling/translation and intensity adjustments (contrast/brightness) [S1].
*   **Bit Packing:** Not given in the sources.

**Parameters**
*   **Range Block Size ($N$):** Base subdivision dimension. Typical values: Not given in the sources.
*   **Domain Block Size ($M$):** Must be larger than $N$ to allow scaling. Typical values: Not given in the sources.
*   **Threshold:** Maximum allowed distortion for a match. Typical values: Not given in the sources.
*   **Max Depth:** Maximum recursion depth for subdivision. Typical values: Not given in the sources.

**Algorithm Steps**
1.  **Block Partitioning:** Divide the volume into non-overlapping range blocks of size $N \times N \times N$ [S1].
2.  **Domain Search:** For each range block $R$:
    *   Define a search space of potential domain blocks $D$. Domain blocks are typically larger than range blocks (e.g., $2N \times 2N \times 2N$) to allow for scaling [S1].
    *   Search for the domain block $D^*$ that minimizes the distortion metric between the transformed $D^*$ and $R$ [S1].
    *   If a match is found within a predefined threshold, store the position of $D^*$ and the transformation parameters [S1].
3.  **Recursive Subdivision (Fractal Step):** If no suitable domain block is found in the current search space (i.e., the distortion exceeds the threshold):
    *   Subdivide the current range block into smaller sub-blocks (e.g., 8 sub-blocks for a $2 \times 2 \times 2$ subdivision) [S1].
    *   Recursively apply the search process to each sub-block [S1].
    *   This recursion continues until a base block size is reached [S1].
4.  **Encoding:** Write the stored positions and transformation parameters to the output bitstream [S1].

**Formulas**
Let $R$ be the intensity values of a range block and $D$ be the intensity values of a domain block. The goal is to find an affine transformation $T$ such that:
$$ T(D) \approx R $$
The distortion $E$ is minimized:
$$ E = \| R - T(D) \|^2 $$
Where $T$ typically involves spatial scaling and translation, and a linear intensity transform $I' = aI + b$ [S1].

**Pseudocode**
```python
def fractal_compress(volume, range_size, domain_size, threshold, max_depth):
    """
    Compress a volume using fractal compression.
    Args:
        volume: 3D list of lists of lists representing the volume.
        range_size: Integer, size of the range block (N).
        domain_size: Integer, size of the domain block (M > N).
        threshold: Float, maximum allowed distortion for a match.
        max_depth: Integer, maximum recursion depth for subdivision.
    Returns:
        compressed_data: List of tuples (domain_pos, transform_params) for each range block.
    """
    compressed_data = []
    vol_shape = [len(volume), len(volume[0]), len(volume[0][0])]

    def search_and_store(z, y, x, current_range_size, depth):
        if depth <= 0 or current_range_size == 1:
            # Base case: store raw data or minimal representation if no match found
            # Sources do not specify the exact base case encoding, so we store a marker [G]
            compressed_data.append(((z, y, x), "raw_data"))
            return

        # Extract range block
        range_block = [row[x:x+current_range_size] for row in volume[z:z+current_range_size]]

        best_distortion = float('inf')
        best_pos = None
        best_transform = None

        # Search all valid domain blocks in the volume
        for dz in range(vol_shape[0] - domain_size + 1):
            for dy in range(vol_shape[1] - domain_size + 1):
                for dx in range(vol_shape[2] - domain_size + 1):
                    domain_block = [row[dx:dx+domain_size] for row in volume[dz:dz+domain_size]]

                    # Apply candidate transformations (scaling, translation, intensity)
                    # For simplicity, we test a uniform scale factor s = range_size/domain_size
                    s = current_range_size / domain_size
                    for a in [0.9, 1.0, 1.1]: # contrast
                        for b in [-10, 0, 10]: # brightness
                            transform = {'scale': s, 'contrast': a, 'brightness': b}
                            transformed_domain = apply_transform(domain_block, transform, current_range_size)
                            distortion = calculate_mse(range_block, transformed_domain)

                            if distortion < best_distortion:
                                best_distortion = distortion
                                best_pos = (dz, dy, dx)
                                best_transform = transform

        if best_distortion <= threshold:
            compressed_data.append((best_pos, best_transform))
        else:
            # Subdivide range block and recurse
            sub_size = current_range_size // 2
            for dz in range(0, current_range_size, sub_size):
                for dy in range(0, current_range_size, sub_size):
                    for dx in range(0, current_range_size, sub_size):
                        search_and_store(z + dz, y + dy, x + dx, sub_size, depth - 1)

    # Iterate over all range blocks
    for z in range(0, vol_shape[0] - range_size + 1, range_size):
        for y in range(0, vol_shape[1] - range_size + 1, range_size):
            for x in range(0, vol_shape[2] - range_size + 1, range_size):
                search_and_store(z, y, x, range_size, max_depth)

    return compressed_data

def apply_transform(block, transform, target_size):
    """Apply geometric scaling and intensity adjustment to a block."""
    s = transform['scale']
    a = transform['contrast']
    b = transform['brightness']
    result = [[[0.0 for _ in range(target_size)] for _ in range(target_size)] for _ in range(target_size)]
    for i in range(target_size):
        for j in range(target_size):
            for k in range(target_size):
                src_i = int(i / s)
                src_j = int(j / s)
                src_k = int(k / s)
                val = block[src_i][src_j][src_k]
                result[i][j][k] = a * val + b
    return result

def calculate_mse(block1, block2):
    """Calculate Mean Squared Error between two blocks."""
    total = 0.0
    count = 0
    for i in range(len(block1)):
        for j in range(len(block1[0])):
            for k in range(len(block1[0][0])):
                total += (block1[i][j][k] - block2[i][j][k]) ** 2
                count += 1
    return total / count
```

**Edge Cases and Pitfalls**
*   **Computational Intensity:** The block-based search procedure is extremely computationally intense due to the exhaustive matching and recursive subdivision [S1].
*   **Decompression & Rendering:** Decompression applies stored transformations iteratively until the volume converges, making rendering from compressed data problematic and slow [S1].
*   **Volume Size:** Due to high computational intensity, the technique is not currently applied on very large volumes [S1].

## Operating characteristics
*   **Time Complexity:** Encoding is extremely computationally intensive due to the exhaustive search for similar blocks and recursive subdivision [S1]. Decompression requires iterative application of transformations until convergence, which is slow [S1].
*   **Memory Complexity:** The compressed data size is small, as only positions and transformation parameters are stored [S1]. However, the encoding process requires significant memory to hold the volume and intermediate blocks during search [S1].
*   **Performance:** High compression ratios are achievable for self-similar data, but encoding time is prohibitive [S1].
*   **Strengths:** High compression ratio; effective for volumes with self-similar structures [S1].
*   **Limitations:** Extremely high encoding complexity; slow decompression; problematic for real-time rendering due to iterative reconstruction; not suitable for very large volumes [S1].
*   **When to Use:** Off-line volume compression where storage space is critical and encoding time is not a constraint [S1].
*   **When Not to Use:** Real-time rendering, large dynamic volumes, or volumes with low self-similarity [S1].

## Background
Fractal compression was proposed for volume data by Chentanez et al. [CHF96] [S1]. It is based on the mathematical theory of fractals and Iterative Function Systems (IFS), where complex shapes are generated by simple affine transformations [S1]. The method shares common problems with vector quantization, such as the computational intensity of the search process [S1]. Restricted forms of this method have been proposed for real-time rendering in combination with dictionary methods, as suggested for image coding [HS00] [S1].
