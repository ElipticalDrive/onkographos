# Lead-1 Encoding


## Overview
Lead-1 encoding is a lossless compression scheme for transform coefficients clustered near zero, designed to avoid the variable-length overhead of entropy coding like Huffman encoding [S1, unofficial]. It encodes the position of the leading 1 in the binary magnitude of each coefficient and passes all remaining bits, including the sign, unchanged [S1, unofficial]. Unlike standard Huffman coding, which can produce code lengths exceeding 16 bits for 512 symbols, Lead-1 limits the maximum code length to the number of magnitude bits, ensuring the decoding table fits in CPU cache [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of transform coefficients, each treated as a fixed-width binary integer with a magnitude of $N$ bits (typical value: $N=9$) [S1, unofficial].
*   **Output:** A compressed bitstream consisting of encoded leading-1 positions followed by the unmodified remaining bits of the coefficient [S1, unofficial].

**Data Structures:**
*   **Decoding Table:** A lookup table of size $2^N$ entries. For $N=9$, the table has 512 entries. Each entry is 1 byte, storing the position of the leading 1 (values 0–9). Total size: 512 bytes [S1, unofficial].
*   **Symbol Set:** The symbols to be encoded are the leading-1 positions. For an $N$-bit magnitude, there are $N$ possible positions for the leading 1, plus one symbol for the zero coefficient (where no 1 exists). Total symbols: $N+1$. For $N=9$, there are 10 symbols [S1, unofficial].

**Numbered Steps:**
1.  For each coefficient, determine its binary magnitude representation [S1, unofficial].
2.  Identify the position of the most significant bit (the leading 1) [S1, unofficial].
    *   If the coefficient is zero, the position is encoded as a special symbol (e.g., symbol 10 or a specific value indicating zero) [S1, unofficial].
    *   Otherwise, the position is the index of the highest bit set to 1. Let the bits be indexed from 0 (LSB) to $N-1$ (MSB). If bit $k$ is the leading 1, the position is $k$ [G].
3.  Encode the position using a fixed-length or entropy-coded scheme. Since the number of symbols is small ($N+1$), a fixed-length code of $\lceil \log_2(N+1) \rceil$ bits or a short Huffman code can be used. The maximum code length is bounded by $N$ bits [S1, unofficial].
4.  Append the remaining bits of the coefficient (bits below the leading 1, including the sign bit) to the output stream unchanged [S1, unofficial].

**Formulas:**
*   $pos = \text{bit\_length}(C_{mag}) - 1$ for $C_{mag} > 0$, where $pos$ is the leading-1 position and $C_{mag}$ is the coefficient magnitude [G].
*   $C_{out} = \text{Encode}(pos) \parallel C_{rem}$, where $C_{out}$ is the encoded output, $\text{Encode}()$ maps $pos$ to a symbol, and $C_{rem}$ are the remaining bits including the sign [S1, unofficial].
*   $C_{mag} = (1 \ll pos) \mid C_{rem\_lower}$ during decoding, where $C_{rem\_lower}$ are the lower magnitude bits extracted from $C_{rem}$ [G].

**Parameters:**
*   **Bit Width ($N$):** The number of bits used to represent the magnitude of the coefficient. Typical value: 9 bits [S1, unofficial].
*   **Sign Bit:** The sign of the coefficient is preserved in the "remaining bits" and is not part of the leading-1 position encoding [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Coefficients:** Must be handled as a distinct symbol. The source notes that "0 indicates a zero coefficient" in the count table [S1, unofficial].
*   **Precision:** The method assumes fixed-width coefficients. If coefficients have varying precision, padding or truncation may be required before encoding [G].
*   **Boundaries:** If a coefficient's magnitude exceeds $N$ bits, the leading-1 position must be clamped to $N-1$ to prevent out-of-bounds table access [G].

**Pseudocode:**
```python
def lead1_encode(coefficient, num_magnitude_bits=9):
    """
    Encodes a single coefficient using Lead-1 encoding.
    
    Args:
        coefficient: Integer value of the coefficient.
        num_magnitude_bits: Number of bits for magnitude (N).
        
    Returns:
        encoded_position: Integer symbol representing the leading-1 position.
        remaining_bits: Integer value of the remaining bits (magnitude lower bits + sign).
    """
    # Extract sign and magnitude. Sign is preserved in remaining bits [G].
    sign = 1 if coefficient < 0 else 0
    magnitude = abs(coefficient)
    
    if magnitude == 0:
        # Special symbol for zero. Source says "9 positions + 1 for zero coefficient".
        # Map zero to symbol N (e.g., 9 for N=9).
        encoded_position = num_magnitude_bits 
        remaining_bits = 0 
    else:
        # Find the position of the leading 1 (most significant bit)
        leading_bit_index = magnitude.bit_length() - 1
        
        # Ensure it fits within num_magnitude_bits (boundary guard)
        if leading_bit_index >= num_magnitude_bits:
            leading_bit_index = num_magnitude_bits - 1
            
        encoded_position = leading_bit_index
        
        # Remaining bits are all bits below the leading 1
        mask = (1 << leading_bit_index) - 1
        lower_bits = magnitude & mask
        
        # Pack sign into the remaining bits [G]
        remaining_bits = (lower_bits << 1) | sign
    
    return encoded_position, remaining_bits

def lead1_decode(encoded_position, remaining_bits, num_magnitude_bits=9):
    """
    Decodes a coefficient from Lead-1 encoded parts.
    
    Args:
        encoded_position: The symbol representing the leading-1 position.
        remaining_bits: The integer value of the remaining bits.
        num_magnitude_bits: Number of bits for magnitude (N).
        
    Returns:
        coefficient: Reconstructed integer coefficient.
    """
    if encoded_position == num_magnitude_bits:
        # Zero coefficient
        return 0
    else:
        # Extract sign and lower bits
        sign = remaining_bits & 1
        lower_bits = remaining_bits >> 1
        
        # Reconstruct magnitude
        magnitude = (1 << encoded_position) | lower_bits
        
        # Apply sign
        return -magnitude if sign else magnitude
```

## Operating characteristics
*   **Time Complexity:** Encoding and decoding are $O(1)$ per coefficient, dominated by bit manipulation and table lookup [G].
*   **Memory Complexity:** The decoding table requires $2^N$ bytes. For $N=9$, this is 512 bytes [S1, unofficial].
*   **Measured Performance:** On a $256^3 \times 274$ dataset (Richtmeyer–Meshkov instability), Lead-1 encoding compressed data to 54% of the original size [S1, unofficial]. The test system was a 2 GHz Pentium 4 with 1 GB RAM and GeForce Ti 4600. The compressed data resulted in identical frame rates to uncompressed data but with lower disk space usage and fewer page faults [S1, unofficial].
*   **Scaling:** Not given in the sources.
*   **Strengths:**
    *   Bounded code length (max 9 bits for 9-bit magnitude), ensuring predictable performance.
    *   Small decoding table fits in cache, reducing memory latency.
    *   Effective for data with many small coefficients (clustered near zero), which is common in wavelet-transformed volume data [S1, unofficial].
*   **Limitations:**
    *   Only encodes the position of the leading 1; remaining bits are passed unchanged, so it does not compress the lower bits.
    *   Less effective for data with large coefficients or uniform distribution.
*   **When to use/not:** Use for wavelet-transformed volume data with high sparsity near zero. Not given in the sources for explicit exclusion criteria beyond coefficient distribution.

## Background
Lead-1 encoding was described in the context of compressing time-varying volume data for visualization. The method was tested on the Richtmeyer–Meshkov instability dataset from Lawrence Livermore National Laboratory [S1, unofficial]. The approach leverages the observation that wavelet-transformed coefficients are often close to zero, meaning their binary representation consists of a string of zeros followed by a 1. The redundancy lies primarily in the position of this leading 1 [S1, unofficial].
