# Significance Maps and Bit-wise Encoding


## Overview
Significance Maps and Bit-wise Encoding is a lossless compression technique for volume data that avoids the computational overhead of traditional entropy coders and Run-Length Encoding by explicitly tracking the significance of transform coefficients [S1]. It operates directly on the bit-level significance of wavelet coefficients, enabling rapid decoding without complex parsing logic [S1].

## How it works
The method processes the coefficients $C = \{c_1, c_2, \dots, c_N\}$ generated by the [Wavelet and Pyramid Transforms](3856-wavelet-and-pyramid-transforms.md) described in the parent [Value compression](6-value-compression.md) [G].

**Inputs and Outputs:**
*   **Input:** A set of quantized or raw wavelet coefficients $C$ [G].
*   **Output:** A compressed bitstream containing a significance map and a sequence of bit-planes [S1].

**Data Structures:**
1.  **Significance Map:** A binary mask $M$ of size $N$, where $M_i = 1$ if coefficient $c_i$ is non-zero (significant) and $M_i = 0$ otherwise [G].
2.  **Bit-Planes:** A sequence of bits extracted from the magnitude of each significant coefficient, ordered from Most Significant Bit (MSB) to Least Significant Bit (LSB) [G].

**Steps:**
1.  **Transform:** Apply the separable 1D filter bank to the volume $V$ to obtain coefficients $C$ [see [Wavelet and Pyramid Transforms](3856-wavelet-and-pyramid-transforms.md)].
2.  **Significance Detection:** Iterate through all coefficients $c_i$ [G].
3.  **Significance Assignment:** If $c_i \neq 0$, mark $M_i = 1$; else $M_i = 0$ [G].
4.  **Bit-Plane Extraction:** For each $i$ where $M_i = 1$, determine the bit-depth $B$ of the coefficient [G].
5.  **Bit Extraction:** Extract bits $b_{B-1}, b_{B-2}, \dots, b_0$ from the magnitude of $c_i$ [G].
6.  **Encoding:** Store the significance map $M$, then store the extracted bit-planes for all significant coefficients in order of significance (MSB first) [S1].
7.  **Decoding:** Read $M$ [G].
8.  **Reconstruction:** For each $i$ where $M_i = 1$, read the corresponding bits to reconstruct the magnitude of $c_i$ [G].
9.  **Inverse Transform:** Apply the inverse transform to reconstruct $V$ [G].

**Pseudocode:**

```python
def encode_significance_map(coefficients):
    """
    Encodes wavelet coefficients using significance maps and bit-wise encoding.
    :param coefficients: List of integer wavelet coefficients.
    :return: Tuple of (significance_map, bit_planes, signs)
    """
    n = len(coefficients)
    significance_map = [0] * n
    bit_planes = []
    signs = []
    
    # Step 2-3: Significance Detection & Assignment
    for i, c in enumerate(coefficients):
        if c != 0:
            significance_map[i] = 1
            signs.append(1 if c < 0 else 0)
            # Step 4-5: Bit-Plane Extraction & Bit Extraction
            # Standard knowledge [G]: Extract magnitude bits MSB-first
            magnitude = abs(c)
            bit_depth = magnitude.bit_length() if magnitude > 0 else 1
            bits = format(magnitude, f'0{bit_depth}b')
            bit_planes.append(bits)
            
    return significance_map, bit_planes, signs

def decode_significance_map(significance_map, bit_planes, signs):
    """
    Decodes wavelet coefficients from significance map and bit-planes.
    :param significance_map: List of 0s and 1s.
    :param bit_planes: List of binary strings representing magnitudes.
    :param signs: List of 0/1 indicating negative/positive.
    :return: List of reconstructed coefficients.
    """
    coefficients = [0] * len(significance_map)
    plane_idx = 0
    
    # Step 7-8: Decoding & Reconstruction
    for i, is_significant in enumerate(significance_map):
        if is_significant:
            bits = bit_planes[plane_idx]
            magnitude = int(bits, 2)
            # Standard knowledge [G]: Reapply sign bit
            if signs[plane_idx] == 1:
                magnitude = -magnitude
            coefficients[i] = magnitude
            plane_idx += 1
            
    return coefficients
```

**Parameters:**
*   Bit-depth: Determined by the precision of the transform coefficients [G].

**Edge Cases and Pitfalls:**
*   **Zero Coefficients:** Handled by the significance map ($M_i=0$), requiring no bit-plane data [G].
*   **Precision:** Lossless reconstruction requires exact bit storage and consistent sign handling between encoding and decoding [G].
*   **Memory Complexity:** Requires storage for the significance map ($N$ bits) and the bit-planes [G].

## Subtopics

### [Lead-1 Encoding](17597-lead-1-encoding.md)
A lossless compression scheme for transform coefficients clustered near zero, specifically designed to avoid the variable-length overhead of entropy coding like Huffman encoding. It works by encoding the position of the most significant bit (the leading 1) in the binary magnitude of a coefficient and passing all remaining bits unchanged. Unlike standard Huffman coding where worst-case code lengths can exceed 16 bits, Lead-1 limits the maximum code length to the number of magnitude bits, ensuring the decoding table fits in CPU cache.

## Operating characteristics
*   **Time Complexity:** Encoding and decoding are linear with respect to the number of coefficients $N$, $O(N)$, as they involve simple bitwise operations and map lookups [G].
*   **Memory Complexity:** Requires storage for the significance map ($N$ bits) and the bit-planes [G].
*   **Performance:** Offers lower computational complexity compared to arithmetic coding and Huffman coding, facilitating better random access and faster decoding [S1].
*   **Strengths:** Hardware-friendly, low decoding latency, and no complex parsing logic [S1].
*   **Limitations:** Does not exploit statistical redundancy as effectively as entropy coders, potentially leading to larger file sizes compared to other compression formats in highly redundant data [G].

## Background
This approach was proposed as an alternative to entropy encoding and Run-Length Encoding for wavelet coefficient encoding [S1]. It is associated with works such as [LGK97], [Rod99], and [IP99] [S1]. It is often compared with Golomb-Rice encoding, which [WQ05] favored for its balance of computational complexity and random access capabilities [S1].
