# Hierarchical Progressive Encoding

Also called: HPC Encoding, Multi-resolution Residual Encoding

## Overview
Hierarchical Progressive Encoding (HPC) compresses dynamic volumetric video by representing feature grids as multi-resolution residuals relative to the previous frame, enabling scalable streaming under fluctuating bandwidth [S1]. It differs from sibling methods by decomposing the feature space into $L$ resolution levels and encoding each level's residual separately, allowing the decoder to reconstruct varying levels of detail without processing the full bitstream [S1].

## How it works
**Inputs and Outputs:**
- Input: A sequence of dynamic volumetric feature grids, segmented into Groups of Features (GoFs) of $N$ frames.
- Output: A compressed bitstream $B$ containing entropy-coded residuals for each resolution level.

**Data Structures:**
- Feature Grid $F$: Decomposed into $L$ levels $F = \{F_l \mid l \in [1, L]\}$, where $l=1$ is the lowest resolution and $l=L$ is the highest [S1].
- Residual Grid $R_t$: The difference between the current frame's features and the previous frame's features at each level [S1].
- Bitstream $B_t$: A collection of level-specific bitstreams $B_t = \{B_{tl} \mid l \in [1, L]\}$ [S1].

**Parameters:**
- $L$: Number of resolution levels. Typical value: 6 [S1].
- $q$: Quantization parameter. Used to expand data range for precision. Trade-off between quality and storage [S1].
- $N$: Number of frames per GoF. Typical value: 20 [S1].

**Steps:**
1. **Decomposition**: Decompose the feature grid $F$ of the current frame $t$ into $L$ resolution levels $F_l$ [S1].
2. **Residual Calculation**: Compute the residual $R_{tl}$ for each level $l$ by subtracting the previous frame's features $F_{l,t-1}$ from the current frame's features $F_{l,t}$:
   $$ R_{tl} = F_{l,t} - F_{l,t-1} $$
   For the first frame of a GoF, the full $L$-level feature grid is stored as the reference (residuals are effectively the full features or handled as a base case) [S1].
3. **Quantization**: Apply quantization to the residuals. To facilitate compression into uint8 format, residuals are shifted to be non-negative by subtracting the minimum value, then scaled by $q$:
   $$ Q_{tl} = Q(q \cdot R_{tl} - q \cdot \min(R_{tl})) $$
   where $Q(\cdot)$ represents the quantization operation (e.g., rounding to nearest integer) [S1].
4. **Entropy Encoding**: Encode the quantized residuals $Q_{tl}$ using a dedicated entropy encoder $E_l$ specific to level $l$:
   $$ B_{tl} = E_l(Q_{tl}) $$
   Separate encoders are used for each level to account for unique statistical properties [S1].
5. **Bitstream Assembly**: Collect all level-specific bitstreams for frame $t$:
   $$ B_t = \{B_{t1}, B_{t2}, \dots, B_{tL}\} $$
   [S1]

**Pseudocode:**
```python
def hierarchical_progressive_encode(feature_grids, L, q):
    """
    Encodes a sequence of feature grids using hierarchical progressive encoding.
    
    Args:
        feature_grids: List of feature grids, each decomposed into L levels.
                       feature_grids[t][l] is the l-th level of frame t.
        L: Number of resolution levels.
        q: Quantization parameter.
        
    Returns:
        bitstreams: List of lists of bitstreams.
                    bitstreams[t][l] is the encoded bitstream for level l of frame t.
    """
    bitstreams = []
    prev_features = None
    
    for t, frame_features in enumerate(feature_grids):
        level_bitstreams = []
        
        # Initialize previous features if this is the first frame of a GoF
        # In a continuous stream, prev_features persists. 
        # For a new GoF, the first frame acts as a keyframe/reference.
        if prev_features is None:
            # Store full features as reference (residual is effectively the feature itself 
            # or handled via a specific base encoding, but formula implies R = F - F_prev)
            # Assuming F_prev is zero or explicitly stored for the first frame of GoF.
            # Based on S1: "first group... store the full L-level feature grid as the reference"
            # and "F_t = F_{t-1} + R_t". If F_{t-1} is not available, R_t = F_t.
            current_residuals = frame_features
        else:
            current_residuals = []
            for l in range(L):
                # R_tl = F_tl - F_{t-1,l}
                residual = frame_features[l] - prev_features[l]
                current_residuals.append(residual)
        
        for l in range(L):
            residual = current_residuals[l]
            
            # Quantization: Shift to non-negative and scale
            min_val = min(residual.flatten())
            scaled_residual = q * (residual - min_val)
            
            # Quantize (round to nearest integer)
            quantized = round(scaled_residual)
            
            # Entropy Encoding
            # E_l is a dedicated entropy encoder for level l
            bitstream = entropy_encode(quantized, encoder=E_l)
            level_bitstreams.append(bitstream)
            
        bitstreams.append(level_bitstreams)
        
        # Update previous features for next frame
        prev_features = frame_features
        
    return bitstreams
```

**Edge Cases and Pitfalls:**
- **First Frame of GoF**: The first frame must be encoded as a full reference. If the residual calculation assumes a previous frame, the first frame's residual is effectively the frame itself (or the previous frame is zeroed/initialized) [S1].
- **Negative Residuals**: Residuals can be negative. The method explicitly shifts data to non-negative values before quantization to support uint8 compression formats [S1].
- **Precision**: The quantization parameter $q$ must be chosen carefully. Too small $q$ loses detail; too large $q$ increases bitstream size [S1].

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of frames and resolution levels, as each level is processed independently [S1].
- **Memory Complexity**: Depends on the storage of the previous frame's features and the current residuals. The bitstream size is reduced compared to transmitting full frames [S1].
- **Performance**: Tested on DNA-Rendering dataset (2048x2448, 48 views). Achieves efficient compression by exploiting temporal coherence within GoFs of 20 frames [S1].
- **Strengths**: Scalable quality adjustment; supports progressive streaming; reduces temporal redundancy [S1].
- **Limitations**: Requires temporal coherence; error propagation if residuals are corrupted (though not explicitly detailed, standard for delta encoding) [S1].

## Background
HPC was introduced in the paper "HPC: Hierarchical Progressive Coding Framework for Volumetric Video" [S1]. It addresses the inefficiency of transmitting full radiance fields for each frame by leveraging temporal coherence and multi-resolution representations [S1]. The method is part of a broader effort to enable high-fidelity dynamic volumetric content delivery over fluctuating network conditions [S1].
