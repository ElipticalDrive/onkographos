# Quantization and Entropy Encoding/Decoding Pipeline

Also called: Quantization and Entropy Coding

## Overview
This method compresses volumetric or radiance field data by applying quantization to reduce precision, followed by entropy encoding to eliminate statistical redundancy, and reverses the process for decompression [S1, S2]. It is distinguished from sibling methods by its explicit separation of precision reduction from statistical coding, often integrated into end-to-end rate-distortion optimization frameworks where the quantization parameter is tuned to balance reconstruction quality against storage size [S1, S2].

## How it works
**Inputs and Outputs**
*   **Input:** A set of data values $x$ (e.g., feature vectors, Gaussian attributes, or radiance field coefficients) [S1, S2].
*   **Output:** A compressed bitstream (encoding) or reconstructed values $\hat{x}$ (decoding) [S1].

**Data Structures**
*   **Quantized Values:** Integers (typically `int8` for compression, or `int16` for higher precision) resulting from the quantization operation $Q$ [S1, G].
*   **Bitstream:** A sequence of bits generated by the entropy encoder $E$ [S1].

**Parameters**
*   $q$: The quantization parameter. Data is multiplied by $q$ to expand the data range, which subtly enhances quantization precision [S1]. Adjusting $q$ trades off reconstruction quality and model storage size [S1].
*   $\lambda_1, \lambda_2$: Loss weighting factors used in rate-distortion optimization (e.g., in JointRF) [S1].

**Steps**

1.  **Preprocessing (Range Adjustment):**
    To enable compression into `int8` format, the input data $x$ is shifted to be non-negative by subtracting the minimum value $\min(x)$ [S1].

2.  **Quantization:**
    The shifted data is scaled by the quantization parameter $q$ and quantized using $Q$ [S1]. The term $Q(q \cdot \min(x))$ is preserved to allow range restoration during decompression [S1].

3.  **Entropy Encoding:**
    The quantized values are passed to an entropy encoder $E$ (such as a range coder) to produce the compressed bitstream [S1]. This step eliminates redundancy at the storage level [S2]. Optimization techniques like spherical harmonics (SH) masking or distillation reduce coefficient variability before encoding, improving efficiency [S2].

4.  **Entropy Decoding:**
    The bitstream is processed by the entropy decoder $D$ to recover the quantized values [S1].

5.  **Dequantization and Range Restoration:**
    The recovered quantized values are dequantized to approximate the original range [S1]. The formula for the reconstructed value $\hat{x}$ is:
    $$ \hat{x} = \frac{D(E(Q(q \cdot x) - Q(q \cdot \min(x)))) + Q(q \cdot \min(x))}{q} $$
    where $E$ is the entropy encoder, $D$ is the entropy decoder, $Q$ is quantization, and $q$ is the quantization parameter [S1].

**Pseudocode**

def encode_quantized_data(x, q):
    """
    Encodes data x using quantization and entropy encoding.
    x: Input array of values.
    q: Quantization parameter.
    Returns: Compressed bitstream.
    """
    # Step 1: Find minimum for range adjustment
    min_x = min(x)
    
    # Step 2: Scale by q
    q_x = [v * q for v in x]
    q_min = min_x * q
    
    # Step 3: Quantize and compute difference per source formula
    quant_x = quantize(q_x)
    quant_min = quantize([q_min])
    diff = [a - b for a, b in zip(quant_x, quant_min)]
    
    # Step 4: Entropy Encode
    bitstream = entropy_encode(diff)
    
    return bitstream, quant_min[0]

def decode_quantized_data(bitstream, q, quant_min):
    """
    Decodes a bitstream back to approximate original values.
    bitstream: Compressed data.
    q: Quantization parameter used during encoding.
    quant_min: The quantized value of the minimum input (Q(q * min(x))).
    Returns: Reconstructed array x_hat.
    """
    # Step 1: Entropy Decode
    diff = entropy_decode(bitstream)
    
    # Step 2: Add back the minimum offset
    shifted = [v + quant_min for v in diff]
    
    # Step 3: Dequantize (divide by q)
    x_hat = [v / q for v in shifted]
    
    return x_hat

**Edge Cases and Pitfalls**
*   **Precision Loss:** Quantization is lossy, and the choice of $q$ directly impacts the trade-off between reconstruction quality and storage size [S1].
*   **Computational Complexity:** Entropy encoding and decoding introduce additional computational complexity, particularly during decoding, which can impact rendering performance [S2].
*   **Range Handling:** Failure to correctly handle the minimum value offset ($\min(x)$) during dequantization will result in incorrect amplitude restoration [S1].

## Operating characteristics
*   **Time Complexity:** Encoding and decoding time depends on the entropy coder implementation [S2]. Entropy encoding introduces additional computational complexity during decoding [S2].
*   **Memory Complexity:** Significantly reduces memory footprint by storing only the bitstream and necessary parameters ($q$, $\min(x)$) [S1, S2].
*   **Performance:** When integrated with rate-distortion optimization (e.g., RDO-Gaussian), it achieves high compression ratios while maintaining fidelity (SSIM/PSNR) [S2].
*   **Strengths:** Flexible; can be combined with various transforms and pruning strategies (e.g., SH masking) [S1, S2].
*   **Limitations:** Decoding complexity can be a bottleneck for real-time applications if not parallelized (e.g., via 2D-grid organization) [S2].

## Background
The pipeline originates from general lossy compression techniques applied to neural radiance fields and 3D Gaussian Splatting [S1, S2]. JointRF introduced an end-to-end joint optimization framework where quantization and entropy encoding are trained together to match the data distribution [S1]. Subsequent works in 3DGS compression, such as RDO-Gaussian, CompGS, and ELMGS, adopted and refined this pipeline, incorporating run-length encoding, SH distillation, and grid-based entropy coding to handle the specific statistical properties of Gaussian attributes [S2].
