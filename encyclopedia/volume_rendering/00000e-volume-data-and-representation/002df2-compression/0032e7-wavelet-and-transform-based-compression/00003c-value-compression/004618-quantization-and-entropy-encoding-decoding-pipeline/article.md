# Quantization and Entropy Encoding/Decoding Pipeline

Also called: Quantization and Entropy Coding

## Overview
This method compresses volumetric or radiance field data by applying quantization to reduce precision, followed by entropy encoding to eliminate statistical redundancy, and reverses the process for decompression [S1, S2]. It is distinguished from sibling methods by its explicit separation of precision reduction (quantization) from statistical coding (entropy encoding), often integrated into end-to-end rate-distortion optimization frameworks where the quantization parameter is tuned to balance reconstruction quality against storage size [S1, S2].

## How it works
**Inputs and Outputs**
*   **Input:** A set of data values $x$ (e.g., feature vectors, Gaussian attributes, or radiance field coefficients).
*   **Output:** A compressed bitstream (encoding) or reconstructed values $\hat{x}$ (decoding).

**Data Structures**
*   **Quantized Values:** Integers (typically `int8` or `int16`) resulting from the quantization operation $Q$.
*   **Bitstream:** A sequence of bits generated by the entropy encoder $E$.

**Parameters**
*   $q$: The quantization parameter. It scales the data range to enhance quantization precision. A higher $q$ generally improves reconstruction quality but increases the compressed model size [S1].
*   $\lambda_1, \lambda_2$: Loss weighting factors used in rate-distortion optimization (e.g., in JointRF) [S1].

**Steps**

1.  **Preprocessing (Range Adjustment):**
    To enable efficient compression into integer formats (e.g., `int8`), the input data $x$ is shifted to be non-negative. This is achieved by subtracting the minimum value $\min(x)$ [S1].

2.  **Quantization:**
    The shifted data is scaled by the quantization parameter $q$ and quantized. The quantization operation $Q$ maps the continuous or high-precision values to discrete levels [S1].
    $$ \text{Quantized Input} = Q(q \cdot x - q \cdot \min(x)) $$
    Note: The term $Q(q \cdot \min(x))$ is preserved to allow range restoration during decoding [S1].

3.  **Entropy Encoding:**
    The quantized values are passed to an entropy encoder $E$ (such as a range coder) to produce the compressed bitstream. This step eliminates redundancy at the storage level [S1, S2].
    *   *Optimization:* In frameworks like RDO-Gaussian, spherical harmonics (SH) coefficients may be masked (zeroed out) or distilled (via LightGaussian) to reduce variability before encoding, improving efficiency [S2].
    *   *Organization:* Methods like Morgenstern et al. [S2] may organize attributes into a 2D grid to enable parallelized encoding [S2].

4.  **Entropy Decoding:**
    The bitstream is processed by the entropy decoder $D$ to recover the quantized values [S1].

5.  **Dequantization and Range Restoration:**
    The recovered quantized values are dequantized to approximate the original range. The formula for the reconstructed value $\hat{x}$ is:
    $$ \hat{x} = \frac{D(E(Q(q \cdot x) - Q(q \cdot \min(x)))) + Q(q \cdot \min(x))}{q} $$
    where $E$ is the entropy encoder, $D$ is the entropy decoder, $Q$ is quantization, and $q$ is the quantization parameter [S1].

**Edge Cases and Pitfalls**
*   **Precision Loss:** Quantization is lossy. The choice of $q$ directly impacts the trade-off between reconstruction quality and storage size [S1].
*   **Computational Complexity:** Entropy encoding and decoding introduce additional computational complexity, particularly during decoding, which can impact rendering performance [S2].
*   **Range Handling:** Failure to correctly handle the minimum value offset ($\min(x)$) during dequantization will result in incorrect amplitude restoration [S1].

## Operating characteristics
*   **Time Complexity:** Encoding and decoding time depends on the entropy coder implementation. Entropy coding is generally faster than transform-based methods but adds overhead compared to raw storage [S2].
*   **Memory Complexity:** Significantly reduces memory footprint by storing only the bitstream and necessary parameters ($q$, $\min(x)$) [S1, S2].
*   **Performance:** When integrated with rate-distortion optimization (e.g., RDO-Gaussian), it achieves high compression ratios while maintaining fidelity (SSIM/PSNR) [S2].
*   **Strengths:** Flexible; can be combined with various transforms and pruning strategies (e.g., SH masking) [S1, S2].
*   **Limitations:** Decoding complexity can be a bottleneck for real-time applications if not parallelized (e.g., via 2D-grid organization) [S2].

## Background
The pipeline originates from general lossy compression techniques applied to neural radiance fields and 3D Gaussian Splatting. JointRF introduced an end-to-end joint optimization framework where quantization and entropy encoding are trained together to match the data distribution [S1]. Subsequent works in 3DGS compression, such as RDO-Gaussian, CompGS, and ELMGS, adopted and refined this pipeline, incorporating run-length encoding, SH distillation, and grid-based entropy coding to handle the specific statistical properties of Gaussian attributes [S2].
