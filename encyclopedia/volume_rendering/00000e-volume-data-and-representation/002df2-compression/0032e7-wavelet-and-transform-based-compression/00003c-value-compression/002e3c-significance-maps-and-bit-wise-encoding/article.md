# Significance Maps and Bit-wise Encoding

Also called: Significance Map Encoding, Bit-plane Encoding, Wavelet Significance Map

## Overview
Significance Maps and Bit-wise Encoding is a lossless compression technique for volume data that eliminates the computational overhead of traditional entropy coders (like Huffman or Arithmetic coding) and Run-Length Encoding (RLE) by explicitly tracking the significance of transform coefficients [S1]. It sets itself apart from siblings like [Rational Bézier Deblocking Filter](832-rational-b-zier-deblocking-filter.md) or [Standard Image Compression Formats](4394-standard-image-compression-formats.md) by operating directly on the bit-level significance of wavelet coefficients, allowing for rapid decoding without complex parsing logic [S1].

## How it works
The method operates on the coefficients $C$ generated by the [Wavelet and Pyramid Transforms](3856-wavelet-and-pyramid-transforms.md) described in the parent [Value compression](6-value-compression.md).

**Inputs and Outputs:**
*   **Input:** A set of quantized or raw wavelet coefficients $C = \{c_1, c_2, \dots, c_N\}$ derived from the volume data.
*   **Output:** A compressed bitstream consisting of a significance map and a sequence of bit-planes.

**Data Structures:**
1.  **Significance Map:** A binary mask $M$ of size $N$, where $M_i = 1$ if coefficient $c_i$ is non-zero (significant) and $M_i = 0$ otherwise.
2.  **Bit-Planes:** For each significant coefficient, the bits are extracted from Most Significant Bit (MSB) to Least Significant Bit (LSB).

**Steps:**
1.  **Transform:** Apply the separable 1D filter bank to the volume $V$ to obtain coefficients $C$ [see [Wavelet and Pyramid Transforms](3856-wavelet-and-pyramid-transforms.md)].
2.  **Significance Detection:** Iterate through all coefficients $c_i$. If $c_i \neq 0$, mark $M_i = 1$; else $M_i = 0$.
3.  **Bit-Plane Extraction:** For each coefficient $c_i$ where $M_i = 1$:
    *   Determine the bit-depth $B$ of the coefficient.
    *   Extract bits $b_{B-1}, b_{B-2}, \dots, b_0$.
4.  **Encoding:**
    *   Store the significance map $M$.
    *   Store the extracted bit-planes for all significant coefficients in order of significance (MSB first).
5.  **Decoding:**
    *   Read $M$.
    *   For each $i$ where $M_i = 1$, read the corresponding bits to reconstruct $c_i$.
    *   Apply inverse transform to reconstruct $V$.

**Pseudocode:**

```python
def encode_significance_map(coefficients):
    """
    Encodes wavelet coefficients using significance maps and bit-wise encoding.
    :param coefficients: List of integer wavelet coefficients.
    :return: Tuple of (significance_map, bit_planes)
    """
    n = len(coefficients)
    significance_map = [0] * n
    bit_planes = []
    
    # Step 1: Identify significant coefficients
    for i, c in enumerate(coefficients):
        if c != 0:
            significance_map[i] = 1
            
    # Step 2: Extract bit-planes for significant coefficients
    # Note: This is a simplified representation. 
    # In practice, bits are often grouped by bit-plane level across all coefficients.
    for i, c in enumerate(coefficients):
        if significance_map[i]:
            # Convert to binary string, remove '0b' prefix, pad to fixed width if needed
            # Assuming 32-bit integers for example
            bits = format(abs(c), '032b')
            # Store sign separately if required, or include in bit pattern
            # Here we store magnitude bits
            bit_planes.append(bits)
            
    return significance_map, bit_planes

def decode_significance_map(significance_map, bit_planes):
    """
    Decodes wavelet coefficients from significance map and bit-planes.
    :param significance_map: List of 0s and 1s.
    :param bit_planes: List of binary strings.
    :return: List of reconstructed coefficients.
    """
    coefficients = [0] * len(significance_map)
    plane_idx = 0
    
    for i, is_significant in enumerate(significance_map):
        if is_significant:
            bits = bit_planes[plane_idx]
            # Convert binary string to integer
            # Note: Sign handling is implementation-specific and not detailed in sources [S1]
            coefficients[i] = int(bits, 2)
            plane_idx += 1
            
    return coefficients
```

**Parameters:**
*   Bit-depth: Determined by the precision of the transform coefficients. Not given in the sources.

**Edge Cases:**
*   **Zero Coefficients:** Handled by the significance map ($M_i=0$), requiring no bit-plane data.
*   **Precision:** Lossless reconstruction requires exact bit storage. [G] Sign bit handling must be consistent between encoding and decoding.

## Subtopics

## Operating characteristics
*   **Time Complexity:** Encoding and decoding are linear with respect to the number of coefficients $N$, $O(N)$, as they involve simple bitwise operations and map lookups [S1].
*   **Memory Complexity:** Requires storage for the significance map ($N$ bits) and the bit-planes.
*   **Performance:** Offers lower computational complexity compared to arithmetic coding and Huffman coding, facilitating better random access and faster decoding [S1].
*   **Strengths:** Hardware-friendly, low decoding latency, no complex parsing.
*   **Limitations:** Does not exploit statistical redundancy as effectively as entropy coders, potentially leading to larger file sizes compared to [Standard Image Compression Formats](4394-standard-image-compression-formats.md) or [Zerobit Encoding Scheme](1918-zerobit-encoding-scheme.md) in highly redundant data.

## Background
This approach was proposed as an alternative to entropy encoding and RLE for wavelet coefficient encoding [S1]. It is associated with works such as [LGK97], [Rod99], and [IP99] [S1]. It is often compared with Golomb-Rice encoding, which [WQ05] favored for its balance of complexity and random access [S1].
