# Splat parameter encoding and codec selection

Also called: Luxar store compression, quantised splat encoding

## Overview
This method defines the binary layout and compression pipeline for 3D Gaussian Splat parameters (centres, scales, rotations, amplitudes, and spherical harmonics) to minimize storage size while maintaining high-fidelity rendering. It solves the problem of excessive memory bandwidth and storage requirements for large-scale Gaussian splat scenes by applying specific quantization schemes per parameter type and a width-aware codec policy. It is distinguished from general volume compression by its focus on the specific statistical properties of Gaussian splat attributes (e.g., Cholesky factors for rotation) and its optimization for both native and WebAssembly browser decoding [S1, S2, unofficial].

## How it works
**Inputs:** Raw 3D Gaussian splat parameters (position, scale, rotation, color/amplitude, spherical harmonics coefficients) typically stored in float32.
**Outputs:** A compressed binary stream (`.ksplat` format) with a target size of 8.8–12.7 bytes/splat [S1, unofficial].

### Data Structures and Layout
The store organizes parameters into four primary arrays, each with specific quantization and encoding rules [S1, unofficial]:

1.  **Centres (Positions):**
    *   **Type:** `uint16` (16-bit unsigned integer).
    *   **Encoding:** Quantized coordinates.
2.  **Cholesky Factors (Rotation/Scale):**
    *   **Type:** `uint8` (8-bit unsigned integer).
    *   **Constraint:** "Certified" values, implying bounds checking or specific range constraints to ensure valid rotation matrices upon reconstruction.
3.  **Amplitudes (Color/Intensity):**
    *   **Type:** `uint8` or `uint16`.
    *   **Selection Logic:** Selected based on the array's dynamic range. Options include:
        *   Bounded-linear `uint8`/`uint16`.
        *   Geometric-log `uint16` grid.
4.  **Spherical Harmonics (SH):**
    *   **Type:** Implicitly handled within the codec sweep, though specific bit-depths are not detailed in the provided notes beyond the general codec policy.

### Compression Pipeline
The compression process follows these steps:

1.  **Quantization:**
    *   Centres are quantized to `uint16`.
    *   Cholesky factors are quantized to `uint8`.
    *   Amplitudes are quantized to either bounded-linear or geometric-log grids (`uint8`/`uint16`) based on dynamic range analysis [S1, unofficial].
    *   *Note:* The quantization fidelity loss is at most $-0.679$ dB (median $-0.012$ dB) relative to original float32 fits. The PSNR of the quantised render relative to the float32 render is 59–88 dB [S1, unofficial].

2.  **Prefiltering (Centres Only):**
    *   Apply **columnar delta prefiltering** to the centres array. This reduces redundancy between adjacent splats in the sorted order, improving compression ratio [S1, unofficial].

3.  **Codec Selection and Chunking:**
    *   **Codec:** Blosc with Zstd compressor at level 9.
    *   **Chunking:** Data is split into chunks. The default shipped configuration uses atom-aligned chunks. A specific anomaly occurs with Blosc shuffle on 64 KiB chunks, which is mitigated by atom alignment [S1, unofficial].
    *   **Byte Shuffle Policy:**
        *   **Multi-byte integer codes:** Apply byte shuffle.
        *   **Single-byte codes:** Skip byte shuffle.
        *   **Floating-point arrays:** Skip byte shuffle.
        *   **Optimized Configuration:** Leave log-companded amplitude codes unshuffled to reduce size by an additional 1.44% [S1, unofficial].

4.  **Entropy Coding:**
    *   Handled internally by the Blosc/Zstd pipeline. The policy is width-aware and per-dtype [S1, unofficial].

### Pseudocode
```python
def encode_splats(splats_float32):
    """
    Encodes splat parameters into the Luxar store format.
    splats_float32: List of dicts with keys 'pos', 'cholesky', 'amp', 'sh'
    Returns: bytes (compressed stream)
    """
    # 1. Separate arrays
    centres = [s['pos'] for s in splats_float32]
    choleskys = [s['cholesky'] for s in splats_float32]
    amplitudes = [s['amp'] for s in splats_float32]
    sh_coeffs = [s['sh'] for s in splats_float32]

    # 2. Quantization
    # Centres: uint16
    centres_quant = quantize_uint16(centres)
    
    # Cholesky: uint8 (certified)
    choleskys_quant = quantize_uint8_certified(choleskys)
    
    # Amplitudes: Select grid based on dynamic range
    amp_dynamic_range = calculate_dynamic_range(amplitudes)
    if amp_dynamic_range < THRESHOLD_LINEAR:
        amplitudes_quant = quantize_bounded_linear_uint8(amplitudes)
        amp_is_float = False
        amp_is_log = False
    elif amp_dynamic_range < THRESHOLD_LOG:
        amplitudes_quant = quantize_bounded_linear_uint16(amplitudes)
        amp_is_float = False
        amp_is_log = False
    else:
        amplitudes_quant = quantize_geometric_log_uint16(amplitudes)
        amp_is_float = False
        amp_is_log = True

    # 3. Prefiltering (Centres)
    # Columnar delta prefiltering on centres
    centres_prefiltered = columnar_delta_prefilter(centres_quant)

    # 4. Codec Configuration (Blosc-zstd level 9)
    # Determine shuffle policy per array
    def get_shuffle_policy(dtype, is_log_amp=False):
        if dtype == 'uint8':
            return False # Single-byte: skip shuffle
        elif dtype == 'uint16':
            if is_log_amp:
                return False # Optimized: leave log-companded unshuffled
            else:
                return True  # Multi-byte integer: apply shuffle
        elif dtype == 'float32':
            return False # Floating-point: skip shuffle
        return True # Default for others

    # Encode each array
    centres_bytes = blosc_compress(centres_prefiltered, 
                                   compressor='zstd', 
                                   level=9, 
                                   shuffle=get_shuffle_policy('uint16'))
    
    choleskys_bytes = blosc_compress(choleskys_quant, 
                                     compressor='zstd', 
                                     level=9, 
                                     shuffle=get_shuffle_policy('uint8'))
    
    amplitudes_bytes = blosc_compress(amplitudes_quant, 
                                      compressor='zstd', 
                                      level=9, 
                                      shuffle=get_shuffle_policy('uint16', is_log_amp=amp_is_log))
    
    # SH encoding details not fully specified in notes; assume standard float32 or quantized uint16/8
    # Placeholder for SH encoding logic
    sh_bytes = blosc_compress(sh_coeffs, 
                              compressor='zstd', 
                              level=9, 
                              shuffle=get_shuffle_policy('float32'))

    # 5. Assemble Stream
    # Header: metadata about chunk sizes, dtypes, shuffle flags
    header = create_header(centres_bytes, choleskys_bytes, amplitudes_bytes, sh_bytes)
    
    return header + centres_bytes + choleskys_bytes + amplitudes_bytes + sh_bytes
```

### Parameters and Typical Values
*   **Codec:** Blosc-zstd level 9 [S1, unofficial].
*   **Chunk Size:** Atom-aligned chunks recommended to avoid 64 KiB shuffle anomaly. Re-chunking to 64 KiB without prefilter increases size to 10.09 bytes/splat [S1, unofficial].
*   **Target Size:** 9.63 bytes/splat (shipped rule), 9.50 bytes/splat (optimized unshuffled log-amplitude config) [S1, unofficial].
*   **Baseline Comparison:** 14.3% below uniform Blosc-zstd level-3 bit-shuffle baseline; 15.6% below baseline at 64 KiB [S1, unofficial].

### Edge Cases and Pitfalls
*   **64 KiB Shuffle Anomaly:** Level-dependent Blosc shuffle anomaly occurs on 64 KiB chunks. Mitigation: Use atom-aligned chunks and columnar delta prefiltering on centres [S1, unofficial].
*   **Dynamic Range Selection:** Incorrect selection of amplitude quantization grid (linear vs. log) can lead to suboptimal compression or precision loss. Selection must be based on the array's dynamic range [S1, unofficial].
*   **Browser vs. Native Performance:** Decoding throughput varies significantly between environments. In-browser (WebAssembly): 138–215 MB/s. Native: 326–592 MB/s [S1, unofficial].

## Subtopics

### [Ksplat Decompression](6899-ksplat-decompression.md)
Decompresses a `.ksplat` file (compressed 3D Gaussian Splat) into a structured DataTable format for rendering. It handles position quantization, scale/rotation decompression, and spherical harmonics decoding. This is the inverse operation of the encoding method described above.

## Operating characteristics
*   **Compression Ratio:** Reduces store size from 30–37 bytes/splat (float32) to 8.8–12.7 bytes/splat [S1, unofficial].
*   **Quality:** Quantisation PSNR loss vs original is at most $-0.679$ dB (median $-0.012$ dB). Quantised render PSNR vs float32 render is 59–88 dB [S1, unofficial].
*   **Throughput:**
    *   In-browser (WebAssembly): 138–215 MB/s [S1, unofficial].
    *   Native: 326–592 MB/s [S1, unofficial].
*   **Strengths:** High compression ratio with minimal perceptual loss; optimized for both native and web environments; specific handling of Gaussian splat statistics (Cholesky, log-amplitude).
*   **Limitations:** Complexity in codec configuration (shuffle policies, chunk alignment); potential performance degradation in browsers due to WebAssembly overhead; specific anomaly on 64 KiB chunks requires careful chunking [S1, unofficial].
*   **When to Use:** When storage size and loading speed are critical, especially for web-based viewers or large-scale scenes. Not suitable if maximum floating-point precision is required for scientific analysis beyond the quantization error bounds [S1, S2, unofficial].

## Background
The method originates from the Luxar project, which focuses on Gaussian splatting for microscopy and scalable interactive web visualization of multidimensional scientific data. The specific encoding and codec selection strategies were detailed in supplementary documents accompanying the main publication, addressing quantization fidelity and codec sweep results [S1, unofficial]. The `.ksplat` format was also popularized by the GaussianSplats3D project (mkkellogg) as a trimmed-down, compressed version of `.ply` files for faster loading in web viewers [S2, unofficial].
