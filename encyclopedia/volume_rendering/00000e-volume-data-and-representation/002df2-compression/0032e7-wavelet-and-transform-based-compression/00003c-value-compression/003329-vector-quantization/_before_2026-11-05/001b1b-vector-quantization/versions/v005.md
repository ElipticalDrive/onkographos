# Vector Quantization

Also called: Cg decoding module, Codebook-based compression, Fixed-to-fixed compression, GPU-based Vector Quantization Decoding, Improved vector quantizer, LBG algorithm modification, Vector Quantization for Color Features

## Overview
Vector Quantization (VQ) is a lossy data compression algorithm that maps a set of $n$-dimensional input vectors to a single fixed-length index referencing an entry in a pre-defined $n$-dimensional codebook [S1, S3, unofficial]. It solves the problem of high storage and bandwidth requirements for volumetric data by replacing individual voxel values with compact indices, exploiting spatial and temporal redundancy [S1, unofficial][S2]. Unlike scalar quantization, VQ operates on multi-dimensional feature vectors (e.g., color or density gradients), allowing for higher compression ratios with lower distortion for data containing many similar sub-blocks [S1, unofficial]. It is distinguished from its sibling [Hierarchical Vector Quantization](827-hierarchical-vector-quantization.md) by its flat codebook structure and from [LBG Algorithm](840-lbg-algorithm.md) by its specific implementation variants (such as PCA-based splitting) designed to mitigate the "empty cell" problem and execution speed issues inherent in the original LBG method [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ $n$-dimensional source vectors $S = \{(x_1, \dots, x_N)\}$, where each vector typically represents a voxel's color features or a block of voxels [S1, unofficial][S2][S3, unofficial].
*   **Output:** A codebook $C$ of size $K = 2^r$ codewords, and for each source vector, a mapping index $j \in [0, K-1]$ referencing the closest codeword [S1, unofficial][S2][S3, unofficial].

**Data Structures:**
1.  **Codebook ($C$):** A table of $K$ vectors, each of dimension $n$. In GPU implementations, this is often stored as a 1D or 2D texture [S1, unofficial][S2].
2.  **Index Map:** For each voxel or block, an $r$-bit integer index pointing to the corresponding entry in $C$ [S1, unofficial][S2]. In sparse data scenarios, this index is stored as a 3D texture [S1, unofficial].

**Algorithm Steps:**

1.  **Codebook Initialization:**
    *   Select an initial set of $K$ codewords. Common methods include random sampling from $S$ or using Principal Component Analysis (PCA) to split the data space, which avoids empty cells and speeds up convergence [S1, S3, unofficial].
    *   *Note:* The standard Linde-Buzo-Gray (LBG) algorithm uses a splitting strategy that can result in empty cells, increasing distortion and execution time [S1, S3, unofficial].

2.  **Assignment (Quantization):**
    *   For each source vector $\vec{x}_m \in S$, find the codeword $\vec{c}_j \in C$ that minimizes the distortion metric $\delta(\vec{x}_m, \vec{c}_j)$.
    *   The most common metric is the squared Euclidean distance:
        $$ \delta(\vec{x}, \vec{y}) = \|\vec{x} - \vec{y}\|_2^2 $$
    *   Assign $\vec{x}_m$ to partition $p_j$ and store index $j$ [S1, S3, unofficial].

3.  **Codebook Update:**
    *   Recalculate each codeword $\vec{c}_j$ as the centroid of all vectors in partition $p_j$:
        $$ \vec{c}_j = \frac{1}{|p_j|} \sum_{\vec{x}_m \in p_j} \vec{x}_m $$
    *   If a partition is empty, the codeword remains unchanged or is re-initialized depending on the splitting strategy [S1, S3, unofficial].

4.  **Convergence Check:**
    *   Calculate the average distortion:
        $$ D_{avg} = \frac{1}{N} \sum_{m=1}^N \|\vec{x}_m - \vec{c}_{m}\|^2 $$
        *(Note: Source [S1, unofficial] defines this as $\frac{1}{Nr}$, but standard VQ literature and [S3, unofficial] imply normalization by $N$. The term $r$ in [S1, unofficial] may refer to a specific normalization factor or be a typo for the bit-depth. We use the standard form, but note the source's specific formula)* [S1, S3, unofficial].
    *   Repeat steps 2-3 until $D_{avg}$ stabilizes or a maximum iteration count is reached [S1, S3, unofficial].

5.  **Decoding (GPU Implementation Specifics):**
    *   To decode index $j$ to vector $\vec{c}_j$, the index is used as a texture coordinate to sample the codebook texture [S1, unofficial][S2].
    *   **Integer-to-Float Mapping:** GPU texture coordinates are floats in $[-1.0, 1.0]$ or $[0.0, 1.0]$. Integer coordinates $(x, y, z)$ must be mapped. For a dimension $D \in \{2^n | n \ge 3\}$, the mapping for address texture coordinates $(x_A, y_A, z_A)$ is:
        $$ x_A = (x \cdot 0.5 + 0.5) \cdot \frac{D_x}{4} $$
        $$ y_A = (x \cdot 0.5 + 0.5) \cdot \frac{D_y}{4} $$
        $$ z_A = (z \cdot 0.5 + 0.5) \cdot \frac{D_z}{4} $$
        [S1, unofficial]
    *   **Simulating Floor/Modulo:** Since Cg/GPU shaders lack bitwise operations, $\lfloor x/4 \rfloor$ is simulated using `GL_NEAREST` texture filtering on a specific address texture [S1, unofficial].
    *   **Clamping:** If calculated coordinates fall outside $[0.0, 1.0]$, `GL_CLAMP` is used to handle border issues [S1, unofficial].

**Pseudocode:**

```python
def vector_quantization_encode(source_vectors, codebook_size, max_iterations):
    """
    Encodes source vectors into indices using a learned codebook.
    source_vectors: List of n-dimensional vectors.
    codebook_size: K, number of codewords (2^r).
    max_iterations: Maximum number of LBG iterations.
    Returns: codebook (K x n matrix), indices (N list of ints).
    """
    # 1. Initialize Codebook
    # Use PCA splitting or random sampling to avoid empty cells [S1, S3, unofficial]
    codebook = initialize_codebook(source_vectors, codebook_size)
    
    indices = []
    
    for iteration in range(max_iterations):
        # 2. Assignment Step
        new_indices = []
        for vec in source_vectors:
            # Find closest codeword using squared Euclidean distance
            min_dist = infinity
            best_idx = -1
            for i, codeword in enumerate(codebook):
                dist = sum((v - c)**2 for v, c in zip(vec, codeword))
                if dist < min_dist:
                    min_dist = dist
                    best_idx = i
            new_indices.append(best_idx)
        
        # 3. Update Step
        new_codebook = []
        for i in range(codebook_size):
            # Get all vectors assigned to codeword i
            assigned_vectors = [v for v, idx in zip(source_vectors, new_indices) if idx == i]
            
            if len(assigned_vectors) > 0:
                # Calculate centroid
                centroid = [0.0] * len(vec)
                for v in assigned_vectors:
                    for d in range(len(vec)):
                        centroid[d] += v[d]
                for d in range(len(vec)):
                    centroid[d] /= len(assigned_vectors)
                new_codebook.append(centroid)
            else:
                # Handle empty cell: keep old codeword or re-initialize [S1, S3, unofficial]
                new_codebook.append(codebook[i])
        
        codebook = new_codebook
        indices = new_indices
        
        # Check convergence (optional)
        if is_converged(codebook, indices):
            break
            
    return codebook, indices

def vector_quantization_decode(indices, codebook):
    """
    Decodes indices back to approximate vectors.
    indices: List of integer indices.
    codebook: K x n matrix.
    Returns: List of decoded vectors.
    """
    decoded_vectors = []
    for idx in indices:
        decoded_vectors.append(codebook[idx])
    return decoded_vectors
```

**Parameters:**
*   **Bit-size of index ($r$):** Typically 8 bits, allowing $2^8 = 256$ codewords [S1, unofficial]. Controls the trade-off between compression ratio and distortion [S1, unofficial].
*   **Dimension ($n$):** Depends on the feature being compressed (e.g., 3 for RGB color, 4 for RGBA) [S1, unofficial][S2].

**Edge Cases and Pitfalls:**
*   **Empty Cells:** Standard LBG can create empty partitions, increasing distortion and execution time [S1, S3, unofficial]. Mitigated by PCA-based splitting [S1, unofficial].
*   **Accumulated Error:** In time-varying data, decoding difference frames (P-frames) leads to error accumulation [S1, unofficial]. Mitigated by periodically sending original data as I-frames [S1, unofficial].
*   **GPU Limitations:** Lack of bitwise operations in older shader languages (Cg) requires texture-based simulation for integer arithmetic [S1, unofficial].
*   **Sparse Data:** For highly sparse data (>99%), VQ can be used losslessly if identical blocks are mapped to the same codeword, but this is not generalizable to all volumetric data [S1, unofficial].

## Subtopics

### [Progressive Encoding of Time-Varying Sequences](959-progressive-encoding-of-time-varying-sequences.md)
Compresses time-varying volumetric data by encoding frames individually while reusing codebooks from previous frames. It distinguishes itself by introducing temporal dependencies (I-frames and P-frames), reducing memory and encoding time compared to independent frame encoding.

## Operating characteristics
*   **Time Complexity:** Encoding is iterative. Each iteration requires $O(N \cdot K \cdot n)$ operations for assignment and $O(N \cdot n)$ for updates, where $N$ is the number of vectors, $K$ is the codebook size, and $n$ is the dimensionality [S1, S3, unofficial]. The LBG algorithm is known to be slow for high-resolution data [S3, unofficial]. PCA-based splitting improves speed [S1, unofficial].
*   **Memory Complexity:** Storage is $O(K \cdot n + N \cdot r)$, where $r$ is the bit-depth of the index. This is significantly smaller than storing $N \cdot n$ original vectors if $K \ll N$ [S1, unofficial][S2].
*   **Measured Performance:** Can achieve ~100x storage reduction for Volumetric Radiance Fields (NeRF grids) with competitive rendering quality [S2]. For time-varying data, it exploits high spatial and temporal redundancy [S1, unofficial].
*   **Strengths:** High compression ratio for data with similar sub-blocks; simple decoding (texture lookup); portable to GPU via texture mapping [S1, unofficial][S2].
*   **Limitations:** Lossy compression; sensitive to codebook size; original LBG is slow and prone to empty cells; accumulated error in temporal sequences requires I-frames [S1, S3, unofficial].
*   **When to Use:** Large volumetric datasets with high redundancy (spatial or temporal); real-time rendering on GPUs where decoding speed is critical [S1, unofficial][S2].
*   **When Not to Use:** Data with low redundancy; applications requiring lossless compression (unless data is highly sparse and identical) [S1, unofficial].

## Background
Vector Quantization was developed in the context of speech and image compression, with the Linde-Buzo-Gray (LBG) algorithm introduced in 1980, improving upon scalar quantizers by Max (1960) and Lloyd (1982) [S3, unofficial]. In volume rendering, it was adapted to handle large time-varying volumetric data, leveraging the high spatial and temporal redundancy of such datasets [S1, unofficial]. Early implementations faced challenges with execution speed and the "empty cell" problem, leading to modifications such as PCA-based splitting [S1, S3, unofficial]. More recently, VQ has been applied to compressing Volumetric Radiance Fields (NeRFs), achieving significant storage reductions [S2].
