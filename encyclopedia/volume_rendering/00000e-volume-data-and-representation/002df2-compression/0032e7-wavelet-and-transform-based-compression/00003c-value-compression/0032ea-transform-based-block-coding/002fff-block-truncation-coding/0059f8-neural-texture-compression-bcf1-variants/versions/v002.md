# Neural Texture Compression (BCF1 Variants)

Also called: HW NBTC, Neural Block Texture Compression, Neural Block Texture Compression with Cooperative Vectors

## Overview
Neural Texture Compression (BCF1) is a method for compressing physically-based rendering (PBR) texture sets by storing latent features in BC1 format and decoding them using a Multi-Layer Perceptron (MLP) accelerated by hardware cooperative vectors [S1]. It solves the storage and memory bandwidth bottleneck of high-resolution PBR assets by leveraging existing block compression hardware for random access while using neural inference to reconstruct high-dimensional material properties [S1]. Unlike its sibling [Block Truncation Coding](6187-block-truncation-coding.md) which supports general hardware accelerated random access, BCF1 specifically targets PBR texture sets and uses low dynamic range (LDR) BC1 compression instead of high dynamic range (HDR) BC6, allowing for higher compression ratios or improved quality at the same footprint [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of PBR texture maps (albedo, normal, roughness, metalness, etc.) at resolution $W \times H$ [S1].
*   Network architecture parameters: Number of latent textures $K$, MLP hidden dimension $D$, number of layers $L$ [S1].
*   Training hyperparameters: Learning rates for MLP ($10^{-3}$) and BC1 textures ($10^{-2}$) [S1].

**Outputs:**
*   A set of $K$ BC1 compressed latent textures $T_0, \dots, T_{K-1}$ with varying resolutions [S1].
*   The weights of the Multi-Layer Perceptron (MLP) [S1].

### Data Structures

**BC1 Latent Texture Layout:**
Each latent texture $T_k$ is stored in standard BC1 format [S1].
*   **Block Size:** $4 \times 4$ texels [S1].
*   **Shared Data:** Two RGB endpoints $e_0, e_1$ per block [S1].
    *   $e_0$: 5 bits Red, 6 bits Green, 5 bits Blue [S1].
    *   $e_1$: 5 bits Red, 6 bits Green, 5 bits Blue [S1].
*   **Per-Texel Data:** Blending factor $\alpha$ per texel [S1].
    *   $\alpha$: 2 bits [S1].
*   **Decoding Formula:** For a texel at local coordinates $(u, v)$ within a block:
    $$ T(uv) = (1 - \alpha(uv)) e_0 + \alpha(uv) e_1 $$
    where $e_0$ and $e_1$ are block-shared constants and $\alpha(uv)$ is the per-texel normalized blending factor [S1].

**MLP Structure:**
*   Input vector $x$: Concatenation of latent colors from all $K$ textures evaluated at UV coordinate $p(uv)$ [S1].
*   Hidden layers: Linear transformations followed by activation functions [G].
*   Output vector $f$: The reconstructed PBR feature vector (e.g., albedo, normal, roughness) [S1].

**Resolution Variants:**
Two variants are defined based on the resolution of the $K$ latent textures relative to the original $W \times H$ resolution [S1]:
*   **VAR A:** Latent textures at resolutions $2 \times 2$, $4 \times 4$, $8 \times 8$, and $W \times H$ [S1]. Designed to have a compression ratio similar to BCF6 [S1].
*   **VAR B:** Latent textures at resolutions $2 \times 2$, $4 \times 4$, $8 \times 8$, and $W \times H$ [S1]. Designed to almost double the compression ratio of VAR A [S1].

### Training Procedure

1.  **Replicate BC1 Unit:** Implement a differentiable BC1 texture sampling unit in the training framework (e.g., PyTorch) [S1].
2.  **Initialize Parameters:** Initialize MLP weights and initialize BC1 texture endpoints and alphas as floating-point tensors [S1].
3.  **Forward Pass (Sampling):** For a given training sample (UV coordinate $p(uv)$ and LOD level):
    *   Sample each latent texture $T_k$ at $p(uv)$ to get latent color $c_k$ [S1].
    *   Apply sub-pixel shifts: Shift the sampling coordinate by half a texel for the second and fourth latent textures ($k=1, 3$) to avoid alignment artifacts [S1].
    *   Concatenate latent colors: $x = [c_0, \dots, c_{K-1}]$ [S1].
    *   Feed $x$ to the MLP to obtain feature vector $f = \text{MLP}(x)$ [S1].
4.  **Loss Calculation:** Compute L1 loss between the decoded feature vector $f$ and the reference PBR features sampled using trilinear filtering [S1].
5.  **Backpropagation and Quantization-Aware Training:**
    *   Gradients are passed through the MLP and the BC1 textures [S1].
    *   To simulate hardware quantization during training, apply sigmoid activation followed by quantization-aware operations [S1]:
        $$ \bar{\alpha} = \text{quant}(\text{sigmoid}(\alpha), 2) $$
        $$ \bar{e}_0 = \text{quant}(\text{sigmoid}(e_0), [5, 6, 5]) $$
        $$ \bar{e}_1 = \text{quant}(\text{sigmoid}(e_1), [5, 6, 5]) $$
    *   The `quant` function returns the quantized integer value but allows gradients to pass through the floating-point input [S1].
    *   Update BC1 texture parameters using Adam optimizer with learning rate $10^{-2}$ [S1].
    *   Update MLP weights using Adam optimizer with learning rate $10^{-3}$ [S1].
6.  **LOD Sampling:** During training, sample a LOD level for each texture and regress the associated mip level, similar to Vaidyanathan et al. [S1].

### Runtime Inference

1.  **Visibility Pass:** Determine which pixels are visible [S1].
2.  **Classification Pass:** Sort pixels/tiles requiring neural inference by classifying tiles into types (e.g., no neural, simple neural) to optimize processing [S1].
3.  **G-Buffer Pass:** For each pixel (or tile) requiring neural decoding:
    *   Fetch latent features from the BC1 textures using hardware texture filtering [S1].
    *   Concatenate fetched latent colors $x$ [S1].
    *   Evaluate the MLP to produce feature vector $f$ [S1].
    *   Accelerate MLP evaluation using hardware cooperative vectors (matrix multiplication engines) [S1].
    *   Store $f$ in the G-Buffer [S1].
4.  **Lighting Pass:** Use the G-Buffer data to shade the pixel using a shading model (e.g., diffuse + GGX + IBL) [S1].

### Pseudocode

```python
import torch
import torch.nn as nn

def quantize(x, bits):
    """Quantize float tensor x to integer bits using straight-through estimator."""
    max_val = 2**bits - 1
    q = torch.round(torch.clamp(x, 0.0, 1.0) * max_val).to(torch.int32)
    return q

def bc1_decode(alpha, e0, e1):
    """Decode BC1 block: T = (1 - alpha) * e0 + alpha * e1."""
    return (1.0 - alpha) * e0 + alpha * e1

class BCF1Network(nn.Module):
    def __init__(self, num_latents, hidden_dim, num_layers, output_channels=9):
        super().__init__()
        self.num_latents = num_latents
        input_dim = num_latents * 3
        layers = []
        for i in range(num_layers):
            in_ch = input_dim if i == 0 else hidden_dim
            layers.append(nn.Linear(in_ch, hidden_dim))
            layers.append(nn.ReLU()) # [G] Standard activation for MLP
        layers.append(nn.Linear(hidden_dim, output_channels))
        self.mlp = nn.Sequential(*layers)

    def forward(self, uv_coords, latent_params):
        """
        latent_params: dict with 'endpoints_0', 'endpoints_1', 'alphas'
        Returns feature vector f.
        """
        latent_colors = []
        for k in range(self.num_latents):
            uv = uv_coords.clone()
            if k in [1, 3]:
                uv += 0.5 # Shift second and fourth textures by half a texel [S1]
            e0 = latent_params['endpoints_0'][k]
            e1 = latent_params['endpoints_1'][k]
            alpha = latent_params['alphas'][k]
            c_k = bc1_decode(alpha, e0, e1)
            latent_colors.append(c_k)
        x = torch.cat(latent_colors, dim=-1)
        f = self.mlp(x)
        return f

def train_step(model, uv_coords, reference_features, latent_params, 
               opt_mlp, opt_bc1, lr_mlp=1e-3, lr_bc1=1e-2):
    """Single training step matching evidence procedure."""
    model.zero_grad()
    # Quantize BC1 parameters for forward pass
    q_alpha = quantize(torch.sigmoid(latent_params['alphas']), 2)
    q_e0 = quantize(torch.sigmoid(latent_params['endpoints_0']), [5, 6, 5])
    q_e1 = quantize(torch.sigmoid(latent_params['endpoints_1']), [5, 6, 5])
    q_params = {'alphas': q_alpha, 'endpoints_0': q_e0, 'endpoints_1': q_e1}
    
    # Forward pass
    predicted_features = model(uv_coords, q_params)
    # L1 Loss
    loss = torch.nn.functional.l1_loss(predicted_features, reference_features)
    # Backward pass
    loss.backward()
    # Update parameters
    opt_mlp.step()
    opt_bc1.step()
    return loss.item()
```

### Edge Cases and Pitfalls
*   **Block Artifacts:** Doubling the compression ratio (VAR B vs VAR A) increases block artifacts from BC1 compression, reducing quality [S1].
*   **Alignment Artifacts:** Latent blocks aligning with texel boundaries can cause artifacts [S1].
*   **Precision:** BC1 uses low precision (2-bit alpha, 5-6-5 endpoints) [S1].
*   **Hardware Dependency:** Runtime performance relies on hardware cooperative vectors extension [S1].

## Operating characteristics

**Time and Memory Complexity:**
*   **Memory:** The method stores $K$ BC1 textures [S1].
*   **Runtime:** The bottleneck is MLP evaluation [S1].

**Measured Performance:**
*   **Hardware:** Tested on Intel B580 and Nvidia RTX 4090 [S1].
*   **Scene:** 4 assets (robot, bee, bee hive, rocks) with 4096×4096 PBR textures [S1].
*   **Rendering Resolution:** 1080p [S1].
*   **Performance:** 0.55 ms rendering time for 4k texture sets (9 channels) at 1080p with anisotropic filtering on Intel B580, using 28MB VRAM per texture set [S1].
*   **Speedup:** Up to 23x speedup compared to software FMA implementation (13 ms vs 0.55 ms) [S1].

**Quality:**
*   **PSNR (D=64):**
    *   VAR A1: min 23.34, max 40.91, avg 50.02 [S1].
    *   VAR B1: min 22.91, max 39.02, avg 49.18 [S1].
*   **Comparison:** VAR A produces similar quality to Ubisoft's BCF6 with a small gain in compression [S1]. BCF1 variants are compared against Nvidia's NTC (1.0 and 0.5 bits per channel per pixel variants) and Ubisoft's BCF6 [S1].

**Strengths and Limitations:**
*   **Strengths:** High compression ratio, hardware-accelerated decoding, anisotropic filtering works without specific training, low VRAM usage (28MB for 4k sets) [S1].
*   **Limitations:** Block artifacts at high compression ratios, dependency on hardware cooperative vectors for optimal performance, LDR limitation (though deemed sufficient) [S1].

**When to Use:**
*   Use when VRAM is constrained and high-resolution PBR textures are needed [S1].
*   Use when hardware supports cooperative vectors for accelerated MLP inference [S1].
*   Use when anisotropic filtering is required without additional training overhead [S1].

**When Not to Use:**
*   Use when hardware does not support cooperative vectors and software fallback performance is unacceptable [S1].

## Background

**Origin:**
The method was introduced by L. Belcour and A. Benyoub from Intel Labs, France, in the paper "Hardware Accelerated Neural Block Texture Compression with Cooperative Vectors" presented at High-Performance Graphics (HPG) 2025 [S1]. It is an extension of the neural texture compression method by Weinreich and colleagues (BCF6) [S1].

**History and Development:**
The work builds on previous neural texture compression methods that used BC6 for HDR storage [S1]. The authors demonstrated that LDR BC1 compression is viable for PBR textures, allowing for higher compression ratios or improved quality [S1]. They introduced hardware acceleration using cooperative vectors to overcome the performance bottleneck of MLP inference [S1].

**Usage:**
The method is designed for modern games and rendering applications that rely on high-resolution PBR textures [S1]. It is integrated into a tile-based rendering pipeline with visibility, classification, G-Buffer, and lighting passes [S1].
