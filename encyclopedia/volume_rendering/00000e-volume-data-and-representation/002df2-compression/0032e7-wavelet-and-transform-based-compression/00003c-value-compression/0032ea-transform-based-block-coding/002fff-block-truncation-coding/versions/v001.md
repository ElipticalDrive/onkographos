# Block Truncation Coding

Also called: BTC, ETC2

## Overview
Block Truncation Coding (BTC) is a lossy image and volume compression technique that quantizes a block of data to a small set of representative values (typically two) to reduce memory bandwidth and storage requirements [S1]. It differs from transform-based methods like wavelets by operating directly on spatial blocks without frequency decomposition, making it suitable for hardware-accelerated random access in texture compression [S1].

## How it works
**Inputs and Outputs:**
- Input: A block of $N$ voxels (or pixels) with original values $v_i$.
- Output: A compressed block consisting of two representative values (means) $m_0, m_1$ and a bit mask $B$ of length $N$.

**Data Structures:**
The compressed block layout typically includes:
1. Two representative values $m_0, m_1$ (quantized means).
2. A bit mask $B$ where the $i$-th bit indicates whether voxel $i$ maps to $m_0$ (bit 0) or $m_1$ (bit 1).

**Algorithm:**
1. **Block Partitioning:** Divide the volume into non-overlapping blocks of size $B_x \times B_y \times B_z$.
2. **Mean Calculation:** Compute the mean of the block values.
3. **Quantization:** Map the block values to two representative levels. A common approach is to split the values at the median or mean, assigning lower values to $m_0$ and higher values to $m_1$.
4. **Mask Generation:** For each voxel $i$, set bit $i$ of the mask to 0 if $v_i \leq \text{threshold}$, else 1.
5. **Refinement (Optional):** Adjust $m_0$ and $m_1$ to minimize the mean squared error (MSE) for the assigned voxels.

**Formulas:**
Let $S_0$ be the set of indices where the mask bit is 0, and $S_1$ where it is 1.
$$ m_0 = \frac{1}{|S_0|} \sum_{i \in S_0} v_i $$
$$ m_1 = \frac{1}{|S_1|} \sum_{i \in S_1} v_i $$

**Parameters:**
- Block size: Typically $4 \times 4$ or $8 \times 8$ for 2D; 3D blocks are smaller (e.g., $4 \times 4 \times 4$) [S1].
- Number of levels: Usually 2 (binary truncation) [S1].

**Edge Cases:**
- If all values in a block are identical, $m_0 = m_1$ and the mask is irrelevant.
- Precision issues may arise if the dynamic range of the block is small relative to the quantization step.

**Pseudocode:**
```python
def block_truncation_coding(block_values):
    """
    Compress a block of values using Block Truncation Coding.
    :param block_values: List of original voxel values.
    :return: Tuple of (mean0, mean1, mask)
    """
    n = len(block_values)
    if n == 0:
        return None, None, None

    # Calculate mean of the block
    block_mean = sum(block_values) / n

    # Split values into two sets based on the mean
    set0 = []
    set1 = []
    mask = 0

    for i, val in enumerate(block_values):
        if val <= block_mean:
            set0.append(val)
            # Bit 0 for set0
        else:
            set1.append(val)
            # Bit 1 for set1
            mask |= (1 << i)

    # Calculate representative means
    mean0 = sum(set0) / len(set0) if set0 else block_mean
    mean1 = sum(set1) / len(set1) if set1 else block_mean

    return mean0, mean1, mask

def reconstruct_block(mean0, mean1, mask, block_size):
    """
    Reconstruct the block from BTC data.
    :param mean0: Representative value for mask bit 0.
    :param mean1: Representative value for mask bit 1.
    :param mask: Bitmask indicating assignment.
    :param block_size: Total number of voxels in the block.
    :return: List of reconstructed values.
    """
    reconstructed = []
    for i in range(block_size):
        bit = (mask >> i) & 1
        if bit == 0:
            reconstructed.append(mean0)
        else:
            reconstructed.append(mean1)
    return reconstructed
```

## Subtopics

### [Neural Texture Compression (BCF1 Variants)](16542-neural-texture-compression-bcf1-variants.md)
A compression method using low dynamic range latent representations (BC1) to achieve similar quality to previous high dynamic range storage methods at the same compression rate, or higher compression rates with reasonable quality drop.

## Operating characteristics
- **Compression Ratio:** High, typically 4:1 to 8:1 for 2D images, depending on block size and data variance.
- **Complexity:** Low computational complexity for both encoding and decoding, making it suitable for real-time applications.
- **Quality:** Lossy; quality degrades significantly for blocks with high variance or complex gradients.
- **Hardware Support:** Widely supported in GPU texture units (e.g., S3TC, ETC2) [S1].

## Background
Block Truncation Coding was originally developed for image compression. It has been adapted for 3D volume data and texture compression, including extensions like VTC (3D S3TC) and ETC2 [S1]. It is used in scenarios requiring fast random access and low decoding latency, such as real-time volume rendering on GPUs.
