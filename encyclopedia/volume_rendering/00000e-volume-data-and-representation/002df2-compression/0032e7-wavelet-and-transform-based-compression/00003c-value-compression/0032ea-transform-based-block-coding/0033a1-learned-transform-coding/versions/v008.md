# Learned Transform Coding

Also called: Lossy Transform Coding, Neural Transform Coding

## Overview
Learned transform coding is a compression approach used when direct rate-distortion optimization is intractable for high-dimensional data [S1]. It transforms input data $x$ into a latent representation $z$ via an encoder $E$, recovers a lossy version $\hat{x}$ from a quantized latent $\hat{z}$ via a decoder $D$, and optimizes both transformations jointly with a learned probability model for the latent [S1]. It differs from standard transform-based block coding (e.g., [JPEG2000](2883-jpeg2000.md), [ZFP Block-Based Compression](1504-zfp-block-based-compression.md)) by replacing fixed linear transforms and static entropy models with differentiable neural networks and learned priors, allowing for non-linear feature extraction and adaptive bit allocation [S1].

## How it works
**Inputs and Outputs:**
- Input: High-dimensional data block $x$ (e.g., a volume sub-block or image patch) [S1].
- Output: Compressed bitstream representing the quantized latent $\hat{z}$, and optionally the reconstructed data $\hat{x}$ for verification [S1].

**Data Structures:**
- Encoder Network $E$: Parameters $\theta_e$ [S1].
- Decoder Network $D$: Parameters $\theta_d$ [S1].
- Probability Model $p_{\hat{z}}$: Parameters $\phi$ [S1].
- Latent $z$: Continuous representation of $x$ [S1].
- Quantized Latent $\hat{z}$: Discretized version of $z$ [S1].

**Steps:**
1. **Encode:** Compute the continuous latent representation $z$ using the encoder network:
   $$ z = E(x; \theta_e) $$
2. **Quantize:** Discretize the latent $z$ to $\hat{z}$ using a quantization function $Q$ [S1]. Since quantization is non-differentiable, straight-through estimation or similar techniques are typically used during training [S1].
   $$ \hat{z} = Q(z) $$
3. **Model:** Compute the bit rate $R$ based on the learned probability model $p_{\hat{z}}$ for the quantized latent $\hat{z}$:
   $$ R(\hat{z}; \phi) = -\log p_{\hat{z}}(\hat{z}; \phi) $$
   The total loss function to optimize is:
   $$ \arg \min_{\theta, \phi} D(x, \hat{x}; \theta) + \lambda R(\hat{z}; \phi) $$
   where $D(x, \hat{x}; \theta)$ is the distortion metric (e.g., MSE, L1), $\lambda$ is the rate-distortion trade-off parameter, and $\hat{x} = D(\hat{z}; \theta_d)$ [S1].
4. **Decode:** Recover the approximate original data $\hat{x}$ using the decoder network:
   $$ \hat{x} = D(\hat{z}; \theta_d) $$
5. **Entropy Code:** Encode $\hat{z}$ into a variable-length bit string using the learned prior distribution $p_{\hat{z}}$ (e.g., via arithmetic coding) [S1].

**Parameters:**
- $\lambda$: Rate-distortion trade-off parameter. Higher values yield better bit rates at the expense of increased distortion [S1].
- $\theta = \{\theta_e, \theta_d\}$: Parameters of the encoder and decoder networks [S1].
- $\phi$: Parameters of the learned probability model (prior) for $\hat{z}$ [S1].

**Pseudocode:**
```python
def learned_transform_coding_encode(x, encoder, quantizer, probability_model):
    z = encoder(x)
    z_hat = quantizer(z)
    # Entropy code z_hat using learned prior p_z_hat to produce variable-length bit string [S1]
    bitstream = arithmetic_coding(z_hat, probability_model(z_hat))
    return bitstream

def learned_transform_coding_decode(bitstream, decoder, probability_model):
    # Decode bitstream using learned prior p_z_hat to recover z_hat [S1]
    z_hat = arithmetic_coding_decode(bitstream, probability_model(None))
    x_hat = decoder(z_hat)
    return x_hat

def train_step(x, encoder, decoder, quantizer, probability_model, lambda_param, optimizer):
    z = encoder(x)
    z_hat = quantizer(z)
    x_hat = decoder(z_hat)
    distortion = sum((a - b)**2 for a, b in zip(x, x_hat)) / len(x)
    probs = probability_model(z_hat)
    rate = -sum(math.log2(p) for p in probs)
    loss = distortion + lambda_param * rate
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    return loss.item(), rate.item(), distortion.item()
```

**Edge Cases and Pitfalls:**
- **Quantization Non-differentiability:** The quantization step $Q(z)$ is non-differentiable, requiring techniques like straight-through estimation or noise addition during training to allow gradient flow [S1].
- **Model Generalization:** Learned models may overfit to specific data distributions, necessitating per-image overfitting variants for single-input optimization [S3, unofficial].
- **Computational Cost:** Training and inference require neural network forward passes, which are significantly slower than traditional linear transforms [G].

## Subtopics

### [Variational Autoencoder-based Compression](10442-variational-autoencoder-based-compression.md)
Variational Autoencoder-based Compression uses encoder-decoder pairs to learn compressed latent codes that reconstruct input volume data, imposing a probabilistic latent structure that enables sampling and interpolation. It differs from standard autoencoders by enforcing this probabilistic structure, and from deterministic learned transform coding by optimizing the latent distribution rather than just a point estimate, making it suitable for both lossy compression (where the latent code replaces the original grid) and feature learning.

### Sliced-Wasserstein Autoencoder Compression
Replaces the linear regression predictor in SZ2.1 with a pre-trained Sliced-Wasserstein autoencoder (SWAE) in an error-bounded compression framework [S2, unofficial]. For each data block, it selects whichever predictor (autoencoder or Lorenzo) achieves lower l1 loss [S2, unofficial]. It applies linear-scale quantization followed by Huffman and Zstd encoding [S2, unofficial]. The SWAE is selected from eight autoencoder variants for its highest reconstruction PSNR [S2, unofficial]. On volumes up to $512^3$ (NYX cosmology), it achieved 100–800% higher compression ratios than SZ2.1 and ZFP at matched PSNR [S2, unofficial]. However, compression throughput is 12–68 MB/s, an order of magnitude below that of the unmodified SZ pipeline [S2, unofficial].

### Overfitted Image Codec with Common Randomness
A codec architecture overfitted to a single input image, using Wasserstein Distance (WD) as distortion objective, where pseudo-random Gaussian noise is shared between encoding and decoding via synchronized random seeds [S3, unofficial]. It back-propagates a training loss composed of rate and distortion terms to overfit all components to the input image [S3, unofficial]. Components include grid-based learnable image latents, a hyperprior network (models probability distribution for entropy coding), and a lightweight decoder (reconstructs RGB samples sample-by-sample) [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Training time is high due to the need to optimize neural networks and probability models jointly [S1]. Inference requires neural network forward passes, which are typically slower than fixed linear transforms [G].
- **Memory Complexity:** Requires storing network parameters ($\theta_e, \theta_d, \phi$) in addition to the compressed bitstream [S1]. The bitstream size is determined by the learned rate $R(\hat{z}; \phi)$ [S1].
- **Measured Performance:** On volumes up to $512^3$ (NYX cosmology), Sliced-Wasserstein Autoencoder Compression achieved 100–800% higher compression ratios than SZ2.1 and ZFP at matched PSNR [S2, unofficial]. However, throughput was 12–68 MB/s, significantly lower than traditional pipelines [S2, unofficial].
- **Strengths:** Can achieve higher compression ratios for specific data distributions by learning non-linear features and adaptive probability models [S1]. Can incorporate perceptual metrics (e.g., Wasserstein Distance) for better visual quality [S3, unofficial].
- **Limitations:** High computational cost for training and inference. Less generalizable than fixed transforms unless trained on diverse data [G]. Throughput can be an order of magnitude lower than optimized traditional codecs [S2, unofficial].
- **When to Use:** When high compression ratios are critical and computational resources allow for neural network inference, or when perceptual quality metrics like Wasserstein Distance are prioritized over exact numerical fidelity [S1][S3, unofficial].
- **When Not to Use:** When real-time throughput is required, as neural inference throughput is an order of magnitude below optimized traditional pipelines [S2, unofficial].

## Background
Learned transform coding addresses high-dimensional data where direct rate-distortion optimization is intractable [S1]. The concept of optimizing rate-distortion trade-offs via learned models has been applied in various domains, including image and video compression [S1]. The specific formulation using encoder-decoder pairs with learned priors for volume data has been explored in recent research, such as Deep Implicit Volume Compression [S1]. Variants integrating autoencoders into scientific volume compression frameworks, like AE-SZ, have been proposed to improve compression ratios for large-scale datasets [S2, unofficial]. Perceptual optimization using Wasserstein Distance and common randomness has been applied to image codecs, showing potential for volume rendering applications [S3, unofficial].
