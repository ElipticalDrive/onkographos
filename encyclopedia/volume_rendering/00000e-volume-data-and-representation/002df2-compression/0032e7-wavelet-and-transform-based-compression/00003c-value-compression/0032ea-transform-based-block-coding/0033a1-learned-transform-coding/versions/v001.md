# Learned Transform Coding

Also called: Lossy Transform Coding, Neural Transform Coding

## Overview
Learned Transform Coding addresses the intractability of direct rate-distortion optimization for high-dimensional data by replacing fixed linear transforms with trainable neural networks [S1]. Unlike its siblings [Transform-based Block Coding](6882-transform-based-block-coding.md), [TSDF Block Transform Coding](2548-tsdf-block-coding.md), and [JPEG2000](2883-jpeg2000.md) which rely on fixed bases like DCT or DWT, this method learns an encoder-decoder pair and a probability model jointly to minimize distortion and bit rate [S1].

## How it works
**Inputs and Outputs:**
- Input: Original data block $x$.
- Output: Reconstructed data block $\hat{x}$ and a variable-length bit string representing the quantized latent.

**Data Structures:**
- Encoder parameters $\theta_e$.
- Decoder parameters $\theta_d$.
- Probability model parameters $\phi$.
- Latent representation $z$.
- Quantized latent $\hat{z}$.

**Steps:**
1. **Encode:** Compute the latent representation $z$ using the encoder network $E$:
   $$ z = E(x; \theta_e) $$
2. **Quantize:** Discretize the continuous latent $z$ to $\hat{z}$ using a quantization function $Q$ [S1]. [G] Since $Q$ is non-differentiable, straight-through estimation or similar techniques are typically used during training to allow gradient flow, though the inference step is strictly discrete.
3. **Model:** Compute the bit rate $R$ based on the learned probability model (prior) $p_{\hat{z}}$ for the quantized latent $\hat{z}$:
   $$ R(\hat{z}; \phi) = -\log p_{\hat{z}}(\hat{z}; \phi) $$
   The model $p_{\hat{z}}$ is parameterized by $\phi$ and is learned jointly with the encoder and decoder [S1].
4. **Entropy Code:** Convert $\hat{z}$ into a variable-length bit string using entropy coding (e.g., arithmetic coding) guided by the learned prior $p_{\hat{z}}$ [S1].
5. **Decode:** Recover the lossy reconstruction $\hat{x}$ using the decoder network $D$:
   $$ \hat{x} = D(\hat{z}; \theta_d) $$

**Optimization:**
The network parameters $\theta = \{\theta_e, \theta_d\}$ and model parameters $\phi$ are optimized to minimize the Lagrangian rate-distortion cost [S1]:
$$ \arg \min_{\theta, \phi} D(x, \hat{x}; \theta) + \lambda R(\hat{z}; \phi) $$
where $D(x, \hat{x}; \theta)$ is the distortion metric (e.g., MSE) and $\lambda$ is the rate-distortion trade-off parameter [S1].

**Parameters:**
- $\lambda$: Rate-distortion trade-off parameter. Higher values yield better bit rates at the expense of increased distortion [S1].

**Edge Cases and Pitfalls:**
- **Quantization Non-differentiability:** The quantization step $Q(z)$ is non-differentiable, requiring specific training strategies (like straight-through estimators) to enable end-to-end optimization [S1].
- **Model Accuracy:** The effectiveness of entropy coding depends heavily on the accuracy of the learned prior $p_{\hat{z}}$. If the model poorly predicts the distribution of $\hat{z}$, the actual bit rate may exceed the estimated rate $R(\hat{z}; \phi)$ [S1].

## Subtopics

### Sliced-Wasserstein Autoencoder Compression
Replaces the linear regression predictor in SZ2.1 with a pre-trained Sliced-Wasserstein autoencoder (SWAE) in an error-bounded compression framework [S2, unofficial]. For each data block, it selects whichever predictor (autoencoder or Lorenzo) achieves lower $\ell_1$ loss, then applies linear-scale quantization followed by Huffman and Zstd encoding [S2, unofficial]. The SWAE is selected from eight autoencoder variants for its highest reconstruction PSNR [S2, unofficial]. On volumes up to $512^3$ (NYX cosmology), it achieved 100–800% higher compression ratios than SZ2.1 and ZFP at matched PSNR, though its compression throughput (12–68 MB/s) remains an order of magnitude below that of the unmodified SZ pipeline [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
Not given in the sources.

**Measured Performance:**
On volumes up to $512^3$ (NYX cosmology), the Sliced-Wasserstein variant achieved 100–800% higher compression ratios than SZ2.1 and ZFP at matched PSNR [S2, unofficial]. However, its compression throughput is 12–68 MB/s, which is an order of magnitude below that of the unmodified SZ pipeline [S2, unofficial].

**Strengths and Limitations:**
- **Strengths:** Can achieve significantly higher compression ratios than traditional methods like SZ2.1 and ZFP at matched PSNR [S2, unofficial].
- **Limitations:** Significantly lower compression throughput compared to traditional pipelines [S2, unofficial].

**When to use:**
Use when high compression ratios are prioritized over encoding speed and the data characteristics benefit from learned non-linear transforms [S2, unofficial].

**When not to use:**
Avoid when high throughput is required or when strict error bounds must be guaranteed with minimal computational overhead [S2, unofficial].

## Background
Lossy transform coding is often used when direct rate-distortion optimization is intractable for high-dimensional data [S1]. The approach transforms input data $x$ into a latent representation $z$ via an encoder $E$, recovers a lossy version $\hat{x}$ from a quantized latent $\hat{z}$ via a decoder $D$, and optimizes both transformations jointly with a learned probability model for the latent [S1]. The first systematic integration of autoencoders into an error-bounded compression framework produced AE-SZ [S2, unofficial].
