# Learned Transform Coding
Also called: Lossy Transform Coding, Neural Transform Coding

## Overview
Learned Transform Coding is a compression approach used when direct rate-distortion optimization is intractable due to high-dimensional input data [S1]. It transforms input data $x$ into a latent representation $z$ via an encoder $E$, recovers a lossy version $\hat{x}$ from a quantized latent $\hat{z}$ via a decoder $D$, and optimizes both transformations jointly with a learned probability model for the latent [S1]. It is distinguished from fixed-basis transform methods like JPEG2000 and TSDF Block Transform Coding by its ability to learn data-adaptive, non-linear transformations and probabilistic priors, allowing for superior rate-distortion trade-offs on complex volumetric data [S1].

## How it works
**Inputs and Outputs:**
*   Input: High-dimensional data block $x$.
*   Output: Variable-length bit string representing the compressed data.

**Data Structures:**
*   Encoder parameters $\theta_e$: Weights of the encoder network $E$.
*   Decoder parameters $\theta_d$: Weights of the decoder network $D$.
*   Prior parameters $\phi$: Parameters of the learned probability model $p_{\hat{z}}$.
*   Latent representation $z$: Continuous vector output by $E$.
*   Quantized latent $\hat{z}$: Discretized version of $z$.

**Steps:**
1.  **Encode:** Compute the continuous latent representation $z$ by applying the encoder to the input data:
    $$ z = E(x; \theta_e) $$
2.  **Quantize:** Discretize the latent representation to obtain $\hat{z}$. The quantization operation $Q$ is non-differentiable [S1].
    $$ \hat{z} = Q(z) $$
3.  **Model:** Compute the bit rate $R$ based on the learned probability model (prior) $p_{\hat{z}}$ for the quantized latent $\hat{z}$:
    $$ R(\hat{z}; \phi) = -\log p_{\hat{z}}(\hat{z}; \phi) $$
    Here, $p_{\hat{z}}$ is a probability model of $\hat{z}$ with parameters $\phi$ [S1].
4.  **Decode:** Recover the lossy reconstruction $\hat{x}$ from the quantized latent:
    $$ \hat{x} = D(\hat{z}; \theta_d) $$
5.  **Entropy Code:** Convert $\hat{z}$ to a variable-length bit string using entropy coding with the learned prior distribution $p_{\hat{z}}$ [S1].

**Optimization:**
The transformations $E$ and $D$ and the prior parameters $\phi$ are optimized jointly to minimize the rate-distortion cost [S1]:
$$ \arg \min_{\theta, \phi} D(x, \hat{x}; \theta) + \lambda R(\hat{z}; \phi) $$
where $\theta = \{\theta_e, \theta_d\}$, $\hat{x} = D(\hat{z}; \theta_d)$, $\hat{z} = Q(E(x; \theta_e))$, and $D$ is a distortion metric [S1].

**Parameters:**
*   $\lambda$: Rate-distortion trade-off parameter. Higher values yield better bit rates at the expense of increased distortion [S1].
*   $p_{\hat{z}}$: Learned probability model (prior) for the quantized latent $\hat{z}$, with parameters $\phi$ [S1].

**Edge Cases and Pitfalls:**
*   **Non-differentiable Quantization:** Since the quantization operation $Q$ is non-differentiable, training the network end-to-end requires specific techniques (e.g., straight-through estimator or relaxation) not detailed in the source [S1].
*   **Intractability:** Direct optimization of the rate-distortion problem is intractable for high-dimensional data, necessitating the transform-based approach [S1].

## Subtopics

### Sliced-Wasserstein Autoencoder Compression
Sliced-Wasserstein Autoencoder Compression replaces the linear regression predictor in SZ2.1 with a pre-trained Sliced-Wasserstein autoencoder (SWAE) in an error-bounded compression framework [S2, unofficial]. For each data block, it selects whichever predictor (autoencoder or Lorenzo) achieves lower $\ell_1$ loss, then applies linear-scale quantization followed by Huffman and Zstd encoding [S2, unofficial]. The SWAE is selected from eight autoencoder variants for its highest reconstruction PSNR [S2, unofficial]. On volumes up to $512^3$ (NYX cosmology), it achieved 100–800% higher compression ratios than SZ2.1 and ZFP at matched PSNR, though its compression throughput (12–68 MB/s) remains an order of magnitude below that of the unmodified SZ pipeline [S2, unofficial].

## Operating characteristics
*   **Complexity:** Not given in the sources.
*   **Performance:** On volumes up to $512^3$ (NYX cosmology), Sliced-Wasserstein variants achieved 100–800% higher compression ratios than SZ2.1 and ZFP at matched PSNR [S2, unofficial].
*   **Throughput:** Compression throughput is 12–68 MB/s, which is an order of magnitude below that of the unmodified SZ pipeline [S2, unofficial].
*   **Strengths:** Superior compression ratios compared to traditional methods like SZ2.1 and ZFP at matched PSNR [S2, unofficial].
*   **Limitations:** Significantly lower compression throughput compared to traditional pipelines [S2, unofficial].
*   **When to use:** When compression ratio is prioritized over throughput and the data benefits from learned non-linear representations [S2, unofficial].
*   **When not to use:** When high throughput is required or when error bounds must be strictly guaranteed without the overhead of neural network inference [S2, unofficial].

## Background
Learned Transform Coding addresses the intractability of direct rate-distortion optimization for high-dimensional data [S1]. It has been integrated into scientific volume compression frameworks, such as AE-SZ, which replaces linear predictors with autoencoders [S2, unofficial]. Variants like ZipGAN have also demonstrated the utility of learned representations in compressing DNS volumes, maintaining high fidelity at high compression ratios [S2, unofficial].
