# Learned Transform Coding

Also called: Lossy Transform Coding, Neural Transform Coding

## Overview
Learned Transform Coding addresses the intractability of direct rate-distortion optimization for high-dimensional volumetric data by mapping input data $x$ into a latent representation $z$ via a learned encoder $E$, quantizing it to $\hat{z}$, and recovering a lossy version $\hat{x}$ via a learned decoder $D$ [S1]. It distinguishes itself from traditional transform-based block coding (e.g., [JPEG2000](2883-jpeg2000.md)) by replacing fixed linear transforms (like DCT or DWT) with non-linear neural networks and replacing static entropy models with learned probability distributions, allowing for joint optimization of the transform and the coding model [S1].

## How it works
**Inputs and Outputs:**
*   Input: Volumetric data block $x$ (typically $B \times B \times B$).
*   Output: Bitstream representing the compressed block; reconstructed block $\hat{x}$.

**Data Structures:**
*   Encoder parameters $\theta_e$: Weights of the neural network $E$.
*   Decoder parameters $\theta_d$: Weights of the neural network $D$.
*   Entropy model parameters $\phi$: Parameters defining the probability distribution $p_{\hat{z}}$.
*   Latent representation $z$: Continuous tensor output by $E$.
*   Quantized latent $\hat{z}$: Discrete tensor output by $Q$.

**Numbered Steps:**
1.  **Encoding:** Compute the continuous latent representation $z$ by applying the encoder network to the input block:
    $$ z = E(x; \theta_e) $$
2.  **Quantization:** Discretize the latent representation to obtain $\hat{z}$. Since quantization is non-differentiable, straight-through estimation or similar techniques are used during training to allow gradient flow [S1].
    $$ \hat{z} = Q(z) $$
3.  **Rate Estimation:** Compute the bit rate $R$ for the quantized latent using the learned probability model (prior) $p_{\hat{z}}$:
    $$ R(\hat{z}; \phi) = -\log p_{\hat{z}}(\hat{z}; \phi) $$
    The total bit rate for a dataset of size $N$ is:
    $$ R(X) = -\frac{1}{N} \sum_{i=1}^{N} \log p_{\hat{z}}(\hat{z}_i; \phi) $$
4.  **Decoding:** Recover the lossy reconstruction $\hat{x}$ by applying the decoder network to the quantized latent:
    $$ \hat{x} = D(\hat{z}; \theta_d) $$
5.  **Entropy Coding:** Convert $\hat{z}$ into a variable-length bit string using an entropy coder (e.g., arithmetic coding) guided by the learned prior $p_{\hat{z}}$ [S1].

**Parameters:**
*   $\lambda$: Rate-distortion trade-off parameter. Higher values yield better bit rates at the expense of increased distortion [S1].
*   $\theta = \{\theta_e, \theta_d\}$: Network weights.
*   $\phi$: Entropy model weights.

**Optimization Objective:**
The system is trained by minimizing the joint objective:
$$ \arg \min_{\theta, \phi} D(x, \hat{x}; \theta) + \lambda R(\hat{z}; \phi) $$
where $D(x, \hat{x}; \theta)$ is a distortion metric (e.g., MSE or L1 loss) [S1].

**Pseudocode:**
```python
def learned_transform_encode(x, encoder, entropy_model):
    """
    Compress a volumetric block x using learned transform coding.
    """
    # Step 1: Encode to latent space
    z = encoder(x)
    
    # Step 2: Quantize latent
    # In inference, Q is a deterministic discretization (e.g., rounding)
    z_hat = quantize(z)
    
    # Step 3: Get probabilities for entropy coding
    # The entropy model predicts parameters (e.g., mean/variance) for p(z_hat)
    probs = entropy_model(z_hat)
    
    # Step 4: Entropy encode
    # Convert z_hat to bits using the probabilities
    bitstream = arithmetic_encode(z_hat, probs)
    
    return bitstream

def learned_transform_decode(bitstream, decoder, entropy_model):
    """
    Decompress a bitstream to recover volumetric block x_hat.
    """
    # Step 1: Entropy decode
    # Recover z_hat from bits using the same probabilities
    z_hat = arithmetic_decode(bitstream, entropy_model)
    
    # Step 2: Decode to reconstruction
    x_hat = decoder(z_hat)
    
    return x_hat
```

**Edge Cases and Pitfalls:**
*   **Non-differentiable Quantization:** The quantization step $Q$ breaks gradient flow. Training requires straight-through estimators or surrogate gradients [S1].
*   **Latent Dimensionality:** The choice of latent size affects compression ratio and reconstruction fidelity. Too small a latent causes high distortion; too large reduces compression benefits [S1].
*   **Boundary Effects:** Block-based processing can introduce discontinuities at block boundaries. [G] Post-processing or overlapping block prediction may be required to mitigate artifacts, though not explicitly detailed in the primary source.

## Subtopics

### Sliced-Wasserstein Autoencoder Compression
A variant that replaces the linear regression predictor in frameworks like SZ2.1 with a pre-trained Sliced-Wasserstein Autoencoder (SWAE) [S2, unofficial]. It selects the predictor (SWAE or Lorenzo) with the lower L1 loss for each block, applies linear-scale quantization, and uses Huffman and Zstd encoding [S2, unofficial]. On volumes up to $512^3$ (NYX cosmology), it achieved 100–800% higher compression ratios than SZ2.1 and ZFP at matched PSNR, but with throughput of 12–68 MB/s, an order of magnitude slower than unmodified SZ [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Encoding and decoding involve neural network inference, which is significantly more computationally expensive than linear transforms (DCT/DWT) [S2, unofficial].
*   **Memory Complexity:** Requires storing neural network weights ($\theta_e, \theta_d, \phi$) in addition to the compressed data.
*   **Performance:** Achieves higher compression ratios than traditional methods (e.g., JPEG2000, ZFP) at matched PSNR for certain data types [S2, unofficial]. However, throughput is lower (12–68 MB/s for SWAE variant) compared to traditional pipelines [S2, unofficial].
*   **Strengths:** Superior rate-distortion performance for complex, non-stationary volumetric data; adaptive to data statistics via learning.
*   **Limitations:** High computational cost for encoding/decoding; requires training data; less predictable error bounds compared to deterministic methods like SZ [S2, unofficial].
*   **When to use:** When compression ratio is critical and computational resources allow for neural inference; suitable for scientific volumes with complex structures.
*   **When not to use:** When real-time encoding/decoding is required; when strict error bounds are mandatory without probabilistic guarantees.

## Background
Learned Transform Coding originates from the application of deep learning to image and video compression, adapted for volumetric data [S1]. The formulation as a rate-distortion optimization problem with learned priors was formalized in works such as "Deep Implicit Volume Compression" [S1]. The integration of autoencoders into error-bounded scientific compression frameworks (e.g., AE-SZ) represents a later development, leveraging Sliced-Wasserstein distances for better latent space alignment [S2, unofficial].
