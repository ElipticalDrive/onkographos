# Transform-based Block Coding


## Overview
Transform-based block coding compresses volumetric data by partitioning it into fixed-size spatial blocks, applying a linear transform to decorrelate the data within each block, and entropy coding the resulting coefficients [S1, S2]. It solves the problem of high memory bandwidth and storage requirements in volume rendering by exploiting local spatial redundancy [S1, S2]. It is distinguished from its siblings by its reliance on fixed, data-independent linear transforms (such as DCT or DWT) applied to small, regular grids, contrasting with [Learned transform coding](7046-learned-transform-coding.md) which uses non-linear neural networks [S1].

## Shared principles
See [Value compression](6-value-compression.md) for the shared transform, quantization, and reconstruction principles of this family.

## Subtopics

### [TSDF Block Transform Coding](2548-tsdf-block-transform-coding.md)
[TSDF Block Transform Coding](2548-tsdf-block-transform-coding.md) is a lossy compression method for Truncated Signed Distance Function (TSDF) volumes designed to enable real-time streaming of dynamic implicit surfaces. It is distinguished from its siblings by its use of a fixed, data-independent 3D DCT and a strategy of grouping coefficients by DCT index across all active blocks to optimize probability models for range coding. Choose this method when encoding sparse, locally smooth TSDF data with strict real-time streaming constraints.

### [JPEG2000](2883-jpeg2000.md)
[JPEG2000](2883-jpeg2000.md) is a wavelet-based compression standard for still images that serves as the primary benchmark for 2-D coding systems in volumetric data compression. It is distinguished from 3D volumetric schemes by its individual layer coding approach, which ignores inter-slice correlations and results in visible artifacts at layer boundaries. Choose this method when compressing layered volumes where 3D redundancy is unavailable or when using a 2D baseline is required.

### [Learned Transform Coding](7046-learned-transform-coding.md)
[Learned Transform Coding](7046-learned-transform-coding.md) is a compression approach used when direct rate-distortion optimization is intractable for high-dimensional data. It is distinguished from its siblings by replacing fixed linear transforms with non-linear, data-driven neural networks that adapt to the specific statistical structure of the volume data. Choose this method when the data exhibits complex statistical patterns that fixed transforms cannot efficiently model.

#### ZFP Block-Based Compression
- **Definition:** A floating-point compression algorithm using fixed-rate compression, encoding blocks of $4 \times 4 \times 4$ floating-point values [S1]. It is a de facto standard in the HPC community [S1].
- **Steps:**
    1. Convert block values to a common fixed-point format by factoring out the largest exponent of floating-point values within each block [S1].
    2. Convert resulting normalized values to a two's complement fixed-point format [S1].
    3. Spatially decorrelate blocks by converting to a different basis based on a tensor product transformation (e.g., DWT, DCT) [S1].
    4. Encode the resulting transform coefficients per bit plane [S1].
- **Pitfalls:** Decompression is only efficient when using caches [S1]. For Monte Carlo rendering with incoherent memory access, it requires ray wavefronts, barrier synchronization, and sorting, resulting in overly complex control flow [S1].

#### Block Transformation Coding
- **Definition:** A technique based on block transformation coding to address difficulties of rendering large datasets on a GPU [S2].

## Background
The concept of block-based transform coding for volume rendering has been explored to address the challenges of rendering large datasets on GPUs [S2]. Fout and Ma proposed a real-time volume compression and decompression technique based on block transformation coding to handle large volumetric data [S2]. More recently, ZFP has become a de facto standard in the HPC community for fixed-rate floating-point compression, often used in conjunction with GPU rendering pipelines [S1].
