# Modified JPEG2000 for Tiled Pyramid

Also called: New Compression Scheme

## Overview
A modified JPEG2000 compression scheme adapted for tiled pyramid terrain visualization [S1, unofficial]. It modifies the image tiling process and wavelet transform application to allow efficient transmission and reconstruction of terrain data using tiled pyramids [S1, unofficial]. It sets itself apart from standard JPEG2000 by ensuring perfect tile reconstruction without visual artifacts at region frontiers, achieved by using the same coefficients for both synthesis and analysis processes [S1, unofficial].

## How it works
**Inputs:** A terrain image (or volume slice) to be compressed.
**Outputs:** Compressed data for a tiled pyramid structure, allowing progressive reconstruction of tiles.

**Data Structures:**
*   **Tiles:** The input image is split into several tiles of fixed size.
*   **Sub-bands:** Each tile undergoes a 2D analysis filter generating four coefficient sub-bands: LL (lowpass), HL, LH, HH (high-pass) [S1, unofficial].
*   **Codeblocks:** High-pass sub-band coefficients (HL, LH, HH) are grouped into codeblocks [S1, unofficial].
*   **LL Pyramid:** The LL sub-bands from all tiles at a given resolution are grouped to form a lower-resolution version of the image, which serves as the input for the next decomposition level [S1, unofficial].

**Steps:**

1.  **Tiling:** Split the input image into several tiles of fixed size [S1, unofficial].
2.  **Wavelet Transform (Analysis):** Apply a 2D analysis filter (Discrete Wavelet Transform, DWT) to each tile. This generates four coefficient sub-bands: LL, HL, LH, and HH [S1, unofficial].
3.  **Codeblock Formation:** Group the high-pass sub-band coefficients (HL, LH, HH) into codeblocks [S1, unofficial].
4.  **Quantization and Entropy Encoding:** Quantize and entropy encode each codeblock independently [S1, unofficial].
5.  **LL Sub-band Recombination:** Before applying the next wavelet transform step, group all LL sub-bands from the current level's tiles to form a lower-resolution version of the image [S1, unofficial].
6.  **Recursive Decomposition:** Repeat steps 2–5 on the new lower-resolution LL image until its size is smaller than the tile size [S1, unofficial].

**Decompression (Synthesis):**
1.  **Progressive Inverse Process:** Apply the inverse process progressively [S1, unofficial].
2.  **Modified Inverse DWT:** Use a modified inverse DWT module that applies only one step at a time [S1, unofficial].
3.  **Tile Reconstruction:** To reconstruct a specific tile, decompress its data and apply one wavelet transform step. This step joins the coefficients of the children tiles' sub-bands (HL, LH, HH) with the data of the father tile's sub-band (LL) [S1, unofficial].

**Pitfalls and Edge Cases:**
*   **Boundary Artifacts:** Standard JPEG2000 without tiling generates visual artifacts at the borders of reconstructed regions because the analysis and synthesis processes use different information [S1, unofficial]. This scheme avoids this by ensuring the same coefficients are used for both synthesis and analysis, avoiding the use of coefficients from neighboring tiles in both processes [S1, unofficial].
*   **Tile Size Constraint:** The decomposition continues until the lower-resolution version size is smaller than the tile size [S1, unofficial].

**Pseudocode:**

```python
def compress_tiled_pyramid(image, tile_size):
    """
    Compresses an image into a tiled pyramid structure using the Modified JPEG2000 scheme.
    
    Args:
        image: 2D array representing the terrain data.
        tile_size: Fixed size for each tile (width, height).
        
    Returns:
        A dictionary or structure containing compressed data for each tile level.
    """
    pyramid_levels = []
    current_image = image
    
    while True:
        # Step 1: Split image into tiles
        tiles = split_into_tiles(current_image, tile_size)
        level_data = []
        
        for tile in tiles:
            # Step 2: Apply 2D analysis filter (DWT) to each tile
            ll, hl, lh, hh = apply_dwt(tile)
            
            # Step 3: Group high-pass sub-bands into codeblocks
            codeblocks = group_into_codeblocks(hl, lh, hh)
            
            # Step 4: Quantize and entropy encode codeblocks independently
            compressed_codeblocks = []
            for cb in codeblocks:
                quantized = quantize(cb)
                encoded = entropy_encode(quantized)
                compressed_codeblocks.append(encoded)
            
            level_data.append({
                'tile_id': tile.id,
                'compressed_codeblocks': compressed_codeblocks,
                'll_subband': ll # Store LL for next level or reconstruction
            })
        
        pyramid_levels.append(level_data)
        
        # Step 5: Group all LL sub-bands into a lower resolution version
        # This assumes a specific arrangement of tiles to reconstruct the LL image
        next_image = recombine_ll_subbands(level_data, tile_size)
        
        # Step 6: Repeat until lower resolution version size is smaller than tile size
        if next_image.width < tile_size[0] or next_image.height < tile_size[1]:
            break
            
        current_image = next_image
        
    return pyramid_levels

def decompress_tile(pyramid_levels, target_tile_id, target_level):
    """
    Decompresses a specific tile from the tiled pyramid.
    
    Args:
        pyramid_levels: The compressed pyramid structure.
        target_tile_id: The ID of the tile to reconstruct.
        target_level: The level in the pyramid where the tile resides.
        
    Returns:
        The reconstructed tile data.
    """
    # Start from the target level
    level_data = pyramid_levels[target_level]
    
    # Find the specific tile data
    tile_data = None
    for item in level_data:
        if item['tile_id'] == target_tile_id:
            tile_data = item
            break
            
    if tile_data is None:
        raise ValueError("Tile not found")
        
    # Step 3 (Decompression): Decode and dequantize codeblocks
    # Note: The source mentions joining children's HL, LH, HH with father's LL.
    # This implies a hierarchical reconstruction. However, the basic step for a single tile
    # at a specific level involves decoding its own data.
    
    # For a complete reconstruction of a tile at a specific level, we need its LL subband
    # and potentially the high-pass coefficients if it's not the base level.
    # The source states: "joining the coefficients of the children tiles' sub-bands (HL, LH, HH) 
    # with the data of the father tile's sub-band (LL)."
    # This suggests that to reconstruct a tile, you might need data from its parent if it's 
    # not the root, or that the LL subband stored is the one from the *previous* level's 
    # decomposition of the parent.
    
    # Let's assume the stored 'll_subband' is the LL from the current tile's DWT.
    # To reconstruct the tile itself, we need to inverse DWT.
    
    # Step 2 (Decompression): Apply inverse DWT step
    # We need the high-pass coefficients (HL, LH, HH) which were encoded in codeblocks
    decoded_codeblocks = []
    for encoded_cb in tile_data['compressed_codeblocks']:
        quantized = entropy_decode(encoded_cb)
        dequantized = dequantize(quantized)
        decoded_codeblocks.append(dequantized)
        
    # Reconstruct HL, LH, HH from codeblocks
    hl, lh, hh = reconstruct_subbands_from_codeblocks(decoded_codeblocks)
    
    # The LL subband is stored directly
    ll = tile_data['ll_subband']
    
    # Apply Inverse DWT to get the tile
    reconstructed_tile = apply_inverse_dwt(ll, hl, lh, hh)
    
    return reconstructed_tile
```

## Operating characteristics
*   **Compression Time:** Slightly increases compared to the original scheme due to the process of recombining LL sub-bands [S1, unofficial].
*   **Decompression Time:** Similar to the original compression scheme. The difference is that inverse DWT steps are applied independently rather than consecutively [S1, unofficial].
*   **Performance Impact:** Compression is done off-line, so it does not affect real-time visualization performance [S1, unofficial].
*   **Strengths:** Perfect tile reconstruction without visual artifacts at region frontiers [S1, unofficial]. Allows the number of generated tiles to fit in the tiled pyramid [S1, unofficial].
*   **Limitations:** Slightly increased compression time due to LL recombination [S1, unofficial].

## Background
This strategy was used by Hayat et al. (2010) for online 3D terrain visualization [S1, unofficial]. It was proposed to solve problems found in previous strategies, such as visual artifacts at borders when using JPEG2000 without tiling [S1, unofficial].
