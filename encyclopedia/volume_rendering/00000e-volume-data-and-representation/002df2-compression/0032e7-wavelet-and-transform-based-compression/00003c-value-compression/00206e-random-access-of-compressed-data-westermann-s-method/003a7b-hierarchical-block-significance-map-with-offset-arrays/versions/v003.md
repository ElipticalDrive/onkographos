# Hierarchical Block Significance Map with Offset Arrays

Also called: Block 32/8 Significance Map, Slice Info / Block 32 Info / Block 8 Info structure

## Overview
This method provides fast random access to wavelet coefficients stored in compressed linear streams, overcoming the variable-length decoding overhead inherent in Huffman, arithmetic, or run-length coding [S1]. It achieves this by organizing significant coefficients into a hierarchy of quadratic blocks ($32 \times 32$, then $8 \times 8$) and lines, using bitmaps and split offset arrays to locate data directly [S1]. It sets itself apart from sibling methods by explicitly partitioning the offset space across three record levels to minimize storage overhead while maintaining constant-time lookup probabilities [S1].

## How it works

### Inputs and Outputs
*   **Input:** A 3D volume represented as wavelet coefficients, preprocessed with a wavelet transform (e.g., Haar) and quantized [S1].
*   **Output:** A set of four linear streams (Block 32 Stream, Block 8 Stream, Significance Map Stream, Byte Stream) and three types of metadata records (Slice Info, Block 32 Info, Block 8 Info) that allow retrieving any coefficient $(x, y, z)$ without decoding preceding data [S1].

### Data Structures and Layout
The structure is hierarchical. The volume is divided into slices $z$. Each slice is divided into $32 \times 32$ blocks [S1]. Each block is divided into $8 \times 8$ sub-blocks [S1].

**1. Slice Info Record**
Stored in an array indexed by slice $z$ [S1].
*   **Block 32 Significance Map:** A fixed-size bitmap for the slice [S1]. Each bit corresponds to a $32 \times 32$ block [S1]. If the bit is 1, the block contains nonzero coefficients; if 0, the block is all zeros [S1].
*   **Block 32 Offset:** A 16-bit integer pointing to the start of the corresponding Block 32 Info record in the Block 32 Stream [S1].
*   **Line Offset Array:** An array of integers [S1]. The entry for line $y$ contains the count of nonzero $32 \times 32$ blocks preceding line $y$ in the Block 32 Significance Map [S1]. This allows calculating the position of a block within the stream based on its line [S1].
*   **Significance Map Offset (High Bits):** The most significant bits of the 32-bit offset into the Significance Map Stream [S1].
*   **MSB Flag:** The Most Significant Bit (MSB) of the Block 32 Offset indicates the direction of prediction for I-slices [S1].

**2. Block 32 Info Record**
Stored in the Block 32 Stream. One record exists for each nonzero $32 \times 32$ block [S1].
*   **Block 8 Significance Map:** A bitmap for the $32 \times 32$ block [S1]. Each bit corresponds to an $8 \times 8$ sub-block [S1].
*   **Block 8 Offset:** A 16-bit integer pointing to the start of the corresponding Block 8 Info record in the Block 8 Stream [S1].
*   **Significance Map Offset (Middle Bits):** 8 bits of the 32-bit offset into the Significance Map Stream [S1].
*   **Byte Stream Offset (Low Bits):** The least significant 16 bits of the offset into the Byte Stream [S1].

**3. Block 8 Info Record**
Stored in the Block 8 Stream. One record exists for each nonzero $8 \times 8$ sub-block [S1].
*   **Zeroline Map:** A bitmap of size 8 bits (one per line in the $8 \times 8$ sub-block) [S1]. If bit $j$ is 0, line $j$ contains at least one nonzero coefficient [S1]. If bit $j$ is 1, line $j$ is all zeros [S1].
*   **Significance Map Offset (Low Bits):** 16 bits of the 32-bit offset into the Significance Map Stream [S1].
*   **Byte Stream Offset Field (16 bits):** Contains the 2 Most Significant Bits of the full Byte Stream Offset in bits 14–13, and the encoding mode flag in the MSB (bit 15) [S1].
*   **Encoding Mode Flag:** The MSB of the Byte Stream Offset field indicates the encoding mode: `1` for displacement encoding (offset $\theta$ + signed displacements), `0` for quantization encoding (A, B, x) [S1].

**4. Streams**
*   **Block 32 Stream:** Concatenation of all Block 32 Info records [S1].
*   **Block 8 Stream:** Concatenation of all Block 8 Info records [S1].
*   **Significance Map Stream:** Concatenation of 1-byte significance maps [S1]. For each nonzero line in a nonzero sub-block, 1 byte is stored per coefficient in that line (8 bytes per line) [S1].
*   **Byte Stream:** Concatenation of coefficient data [S1].

### Parameters
*   **Block Size ($B$):** 32. Chosen because Table 3 in [S1] shows that for PSNR 46, 38.4% of blocks are nonzero, balancing sparsity and overhead [S1].
*   **Sub-block Size:** $8 \times 8$. Chosen because Table 4 in [S1] shows a 67.6% probability (at PSNR 46) that an $8 \times 8$ sub-block is nonzero given its $32 \times 32$ parent is nonzero, justifying the second level of hierarchy [S1].
*   **R-slice Spacing ($F$):** Optimal spacing is $F=4$ ($k=2$, where $F=2^k$) [S1]. This yields the smallest compressed size (6.01 Mb at PSNR 46) compared to other spacings [S1].

### Numbered Steps for Random Access
To retrieve the wavelet coefficient at coordinates $(x, y, z)$:

1.  **Lookup Slice Info:** Retrieve the `Slice Info` record for slice $z$ [S1].
2.  **Check Block 32 Significance:** Calculate the block index $(bx, by)$ in the $32 \times 32$ grid: $bx = \lfloor x/32 \rfloor, by = \lfloor y/32 \rfloor$ [S1]. Check the bit at position $(by \times \text{width} + bx)$ in the `Block 32 Significance Map` [S1]. If the bit is 0, return 0 [S1].
3.  **Locate Block 32 Info:** Calculate the number of set bits preceding the current block in the same bitmap line [S1]. Sum the `Line Offset` entries for lines $0$ to $by-1$ (already provided by `Line Offset Array[by]`), plus the count of set bits in the current line from column 0 to $bx-1$ [S1]. Use a precomputed bit-count table (size 65,536 entries, $2^{16}$) to count bits in the current line segment efficiently [S1]. Add this count to the `Block 32 Offset` from the `Slice Info` record [S1]. Use this sum as the index into the `Block 32 Stream` to retrieve the `Block 32 Info` record [S1].
4.  **Check Block 8 Significance:** Calculate the sub-block index $(sbx, sby)$ within the $32 \times 32$ block: $sbx = \lfloor (x \pmod{32})/8 \rfloor, sby = \lfloor (y \pmod{32})/8 \rfloor$ [S1]. Check the bit at position $(sby \times 4 + sbx)$ in the `Block 8 Significance Map` of the retrieved record [S1]. If the bit is 0, return 0 [S1].
5.  **Locate Block 8 Info:** Calculate the number of set bits preceding the current sub-block in the `Block 8 Significance Map` [S1]. Add this count to the `Block 8 Offset` from the `Block 32 Info` record [S1]. Use this sum as the index into the `Block 8 Stream` to retrieve the `Block 8 Info` record [S1].
6.  **Check Zeroline Map:** Calculate the line index $ly$ within the $8 \times 8$ sub-block: $ly = (y \pmod 8)$ [S1]. Check the bit at position $ly$ in the `Zeroline Map` [S1]. If the bit is 1 (line is zero), return 0 [S1].
7.  **Locate Significance Map:** Construct the full 32-bit `Significance Map Offset` by concatenating: High bits from `Slice Info`, Middle 8 bits from `Block 32 Info`, Low 16 bits from `Block 8 Info` [S1]. The position in the `Significance Map Stream` is determined by this offset plus the offset of the specific line within the sub-block [S1]. Retrieve the 1-byte significance map for the line [S1].
8.  **Check Coefficient Significance:** Calculate the coefficient index $lx$ within the line: $lx = (x \pmod 8)$ [S1]. Check the bit at position $lx$ in the retrieved significance map byte [S1]. If the bit is 0, return 0 [S1].
9.  **Retrieve Coefficient Value:** Construct the full Byte Stream Offset by concatenating: Low 16 bits from `Block 32 Info`, High 2 bits from `Block 8 Info` (stored in bits 14–13 of its 16-bit field) [S1]. Access the `Byte Stream` at this offset [S1]. Decode the value based on the encoding mode flag (MSB of the combined offset): If mode is 1, read 2-byte offset $\theta$ and 1-byte signed displacement $d$; value is $\theta + d$ or $-\theta - d$ depending on the interval [S1]. If mode is 0, read 2-byte $A$, 2-byte $B$, and 1-byte $x$, then decode according to the quantization scheme [S1].

### Pseudocode
```python
def get_wavelet_coefficient(x, y, z, slice_info, block_32_stream, block_8_stream, sig_map_stream, byte_stream):
    # 1. Lookup Slice Info
    # slice_info contains: block_32_significance_map (bitarray), line_offset_array,
    # block_32_offset (16-bit), sig_map_offset_high (remaining bits), width_blocks

    # 2. Check Block 32 Significance
    bx = x // 32
    by = y // 32
    if not slice_info.block_32_significance_map[by * slice_info.width_blocks + bx]:
        return 0

    # 3. Locate Block 32 Info
    # Count set bits before bx in line by
    line_start = by * slice_info.width_blocks
    # Use precomputed table for 16-bit chunks in practice [S1]
    bits_before = slice_info.block_32_significance_map[line_start : line_start + bx].bit_count()
    block_32_index = slice_info.line_offset_array[by] + bits_before + slice_info.block_32_offset
    block_32_info = block_32_stream[block_32_index]

    # 4. Check Block 8 Significance
    sbx = (x % 32) // 8
    sby = (y % 32) // 8
    if not block_32_info.block_8_significance_map[sby * 4 + sbx]:
        return 0

    # 5. Locate Block 8 Info
    bits_before_8 = block_32_info.block_8_significance_map[:sby * 4 + sbx].bit_count()
    block_8_index = bits_before_8 + block_32_info.block_8_offset
    block_8_info = block_8_stream[block_8_index]

    # 6. Check Zeroline Map
    ly = y % 8
    if block_8_info.zeroline_map[ly]:
        return 0

    # 7. Locate Significance Map
    # Concatenate offsets: High (Slice Info) | Middle 8 (Block 32 Info) | Low 16 (Block 8 Info) [S1]
    sig_map_offset = (slice_info.sig_map_offset_high << 24) | \
                     (block_32_info.sig_map_offset_mid << 16) | \
                     (block_8_info.sig_map_offset_low)
    sig_map_pos = sig_map_offset + (ly * 8)
    sig_map_byte = sig_map_stream[sig_map_pos]

    # 8. Check Coefficient Significance
    lx = x % 8
    if not (sig_map_byte >> lx) & 1:
        return 0

    # 9. Retrieve Coefficient Value
    # Byte Stream Offset: Low 16 bits from Block 32 Info, High 2 bits from Block 8 Info (bits 14-13) [S1]
    high_2_bits = (block_8_info.byte_stream_offset_field >> 13) & 3
    full_byte_offset = (high_2_bits << 16) | block_32_info.byte_stream_offset
    mode = (block_8_info.byte_stream_offset_field >> 15) & 1

    if mode == 1:
        theta = byte_stream[full_byte_offset] | (byte_stream[full_byte_offset + 1] << 8)
        displacement = byte_stream[full_byte_offset + 2]
        value = theta + displacement if displacement >= 0 else -theta - displacement
    else:
        A = byte_stream[full_byte_offset] | (byte_stream[full_byte_offset + 1] << 8)
        B = byte_stream[full_byte_offset + 2] | (byte_stream[full_byte_offset + 3] << 8)
        x_val = byte_stream[full_byte_offset + 4]
        # Sources do not give the exact quantization formula for A, B, x [G]
        value = (A + B) * x_val  # [G] Standard linear quantization reconstruction

    return value
```

### Edge Cases and Pitfalls
*   **Byte Stream Offset Overflow:** 18 bits are required to offset all coefficients in a slice, but only 16 bits are available in the Block 32 Info record [S1]. The solution is to store the last 2 MSBs of the Byte Stream Offset in bits 14–13 of the Block 8 Offset field [S1].
*   **Precision:** Coefficients are scaled and rounded to integer intervals $[-4095, 4095]$ before encoding [S1].
*   **Boundary Conditions:** The bit-counting logic must correctly handle the boundaries of the bitmap lines and the 16-bit word alignment for the precomputed table [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Lookup Time:** On average, approximately 2 lookups in encoded data and 1 lookup in the bitcount table are performed to retrieve a single coefficient [S1]. The empirical probability of reaching each stage is roughly halved at each step (100%, 50%, 25%, 12.5%, 6%) [S1].
*   **Memory:** The overhead of the offset arrays is minimized by splitting offsets across the hierarchy [S1]. Block 32 Offset is 16 bits (in Block 32 Info) + 32 bits (in Slice Info) for Significance Map [S1]. Block 8 Offset is 16 bits (in Block 32 Info) [S1]. Significance Map Offset is split 8 bits (Block 32 Info) + 16 bits (Block 8 Info) + remaining bits (Slice Info) [S1].

### Measured Performance
*   **Hardware/Scene:** Visible Human dataset [S1].
*   **Compression Factors:**
    *   PSNR 46: Factor 42.6 (Size 6.01 Mb) [S1].
    *   PSNR 43: Factor 60.2 (Size 4.26 Mb) [S1].
    *   PSNR 55.8: Factor 14.5 (Size 17.68 Mb) [S1].
*   **Reconstruction Cost:** Decoding a voxel in an I-slice requires retrieving 14 wavelet coefficients (7 from I-slice, 7 from R-slice) and performing 12 additions on average [S1].

### Strengths and Limitations
*   **Strengths:** Fast random access without variable-length decoding overhead [S1]. Significant size reduction (approx. 50% compared to prior methods) by setting more coefficients to zero for a given PSNR [S1].
*   **Limitations:** Complexity of the data structure and offset management [S1]. The method is designed for preprocessed CT images of the Visible Human dataset but is easily extended to other volumes [S1].

## Background

### Origin
The method was proposed in the paper "Wavelet Based 3D Compression for Very Large Volume Data Supporting Fast Random Access" [S1]. It improves upon prior approaches by replacing variable-length coding with a hierarchical offset structure [S1].

### History and Development
The method addresses the limitation of variable-length codes (Huffman, arithmetic, run-length) which do not lend themselves to fast retrieval of individual coefficients [S1]. It was designed for preprocessed CT images of the Visible Human dataset but is easily extended to other volumes [S1].
