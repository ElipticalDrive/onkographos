# Variable-Block Color Compression

Also called: BC6H Block Compression (P1 Mode), BC6H Mode 11, P1 Compression

## Overview
Variable-Block Color Compression is a lossy compression method for sparse 3D color data that partitions a sequence of voxels into variable-length blocks, encoding each block with two base colors and a single interpolation weight [S1, unofficial]. It solves the problem of high memory overhead in sparse voxel representations by reducing the number of headers required through adaptive block merging, while maintaining a fixed-rate header structure for efficient decoding [S1, unofficial]. It sets itself apart from its sibling [ASTC](5729-astc.md) by using variable-length spatial blocks rather than fixed-size texture blocks, and from its parent [Standard Image Compression Formats](4394-standard-image-compression-formats.md) by targeting sparse 3D data with adaptive block sizes [S1, unofficial].

## How it works
**Inputs:** An array of 3D voxel colors $C_0, C_1, \dots, C_{N-1}$ [S1, unofficial].
**Outputs:** A list of block headers and a list of weights [S1, unofficial].

**Data Structures:**
1.  **Block Header:** Stored in a 32-bit array, containing Base Colors ($B_1, B_2$) and Start Voxel Index [S1, unofficial]. Total size: $2 \times 16 + 32$ bits [S1, unofficial].
2.  **Weights Array:** A separate array storing the weight $w$ for each block, with a fixed bit width per weight (e.g., 3 bits) [S1, unofficial].

**Parameters:**
*   **Error Threshold:** The maximum allowed Mean Square Error (MSE) for a block [S1, unofficial].
*   **Base Colors ($B_1, B_2$):** 16 bits per channel [S1, unofficial].
*   **Weight ($w$):** Scalar value used for interpolation [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Treat each voxel color as an individual block [S1, unofficial].
2.  **Merging Phase:** Iterate through the blocks sequentially [S1, unofficial]. For each block, attempt to merge it with its left neighbor and its right neighbor [S1, unofficial]. Calculate the MSE for the union of the block and the neighbor [S1, unofficial]. Select the merge (left or right) that results in the lowest MSE [S1, unofficial]. If the lowest MSE is within the Error Threshold, perform the merge, computing new base colors and weights for the combined set of voxels [S1, unofficial]. If both merges violate the error threshold, the block is marked as "done" [S1, unofficial].
3.  **Iteration:** Repeat the merging phase with the newly formed blocks until all blocks are considered done [S1, unofficial].
4.  **Endpoint Refinement (Optional):** If `INSET_COLOR_BBOX` is defined, refine the bounding box of the block in log2 RGB space to tighten the endpoints [S2, unofficial]. If `OPTIMIZE_ENDPOINTS` is defined, optimize endpoints via least squares [S2, unofficial].
5.  **Quantization:** Quantize the refined base colors to 10-bit precision [S2, unofficial]. Quantize the weight to the target bit width (e.g., 3 bits) [S1, unofficial].
6.  **Encoding:** Pack the header (Base Colors + Start Voxel Index) into the header array [S1, unofficial]. Pack the weight into the weights array [S1, unofficial].

**Decoding:**
1.  **Find Block:** Given a voxel index, perform a binary search on the headers' Start Voxel Index to find the block spanning that index [S1, unofficial].
2.  **Lookup Weight:** Use the voxel index (relative to the block start) to look up the weight in the weights array [S1, unofficial].
3.  **Reconstruct Color:** Retrieve Base Colors $B_1$ and $B_2$ from the header. Calculate the reconstructed color $C$ using linear interpolation:
    $$ C = w B_1 + (1 - w) B_2 $$
    where $w$ is the weight [S1, unofficial].

**Pseudocode:**
```python
def calculate_mse(colors, base1, base2, weight):
    if not colors:
        return 0.0
    mse_sum = 0.0
    for c in colors:
        reconstructed = [weight * base1[i] + (1.0 - weight) * base2[i] for i in range(3)]
        mse_sum += sum((c[i] - reconstructed[i]) ** 2 for i in range(3))
    return mse_sum / len(colors)

def find_optimal_base_colors_and_weight(colors):
    if not colors:
        return None, None, None
    c1 = min(colors, key=lambda x: x[0])
    c2 = max(colors, key=lambda x: x[0])
    for _ in range(10):
        group1 = [c for c in colors if sum((c[i] - c1[i])**2 for i in range(3)) < sum((c[i] - c2[i])**2 for i in range(3))]
        group2 = [c for c in colors if sum((c[i] - c1[i])**2 for i in range(3)) >= sum((c[i] - c2[i])**2 for i in range(3))]
        if not group1 or not group2:
            break
        c1 = [sum(c[i] for c in group1) / len(group1) for i in range(3)]
        c2 = [sum(c[i] for c in group2) / len(group2) for i in range(3)]
    diff = [c1[i] - c2[i] for i in range(3)]
    diff_sq_sum = sum(d * d for d in diff)
    if diff_sq_sum == 0:
        return c1, c2, 0.5
    numerator = sum(sum((colors[k][i] - c2[i]) * diff[i] for i in range(3)) for k in range(len(colors)))
    weight = numerator / diff_sq_sum
    weight = max(0.0, min(1.0, weight))
    return c1, c2, weight

def merge_blocks(block1, block2, error_threshold):
    all_colors = block1['colors'] + block2['colors']
    b1, b2, w = find_optimal_base_colors_and_weight(all_colors)
    mse = calculate_mse(all_colors, b1, b2, w)
    if mse <= error_threshold:
        return {'colors': all_colors, 'base1': b1, 'base2': b2, 'weight': w, 'start_index': block1['start_index']}
    return None

def compress_voxel_colors(colors, error_threshold):
    if not colors:
        return [], []
    blocks = [{'colors': [c], 'base1': c, 'base2': c, 'weight': 0.5, 'start_index': i, 'done': False} for i, c in enumerate(colors)]
    changed = True
    while changed:
        changed = False
        i = 0
        while i < len(blocks) - 1:
            if blocks[i]['done'] and blocks[i+1]['done']:
                i += 1
                continue
            options = []
            if i > 0:
                all_c = blocks[i-1]['colors'] + blocks[i]['colors']
                b1, b2, w = find_optimal_base_colors_and_weight(all_c)
                mse_l = calculate_mse(all_c, b1, b2, w)
                options.append(('left', i-1, i, mse_l))
            if i < len(blocks) - 1:
                all_c = blocks[i]['colors'] + blocks[i+1]['colors']
                b1, b2, w = find_optimal_base_colors_and_weight(all_c)
                mse_r = calculate_mse(all_c, b1, b2, w)
                options.append(('right', i, i+1, mse_r))
            if options:
                options.sort(key=lambda x: x[3])
                best_type, idx1, idx2, mse_val = options[0]
                if mse_val <= error_threshold:
                    merged = merge_blocks(blocks[idx1], blocks[idx2], float('inf'))
                    blocks[idx1] = merged
                    blocks.pop(idx2)
                    changed = True
                    if best_type == 'left':
                        i = max(0, idx1)
                    else:
                        i += 1
                else:
                    blocks[i]['done'] = True
                    i += 1
            else:
                blocks[i]['done'] = True
                i += 1
    headers = [{'base1': b['base1'], 'base2': b['base2'], 'start_index': b['start_index']} for b in blocks]
    weights = [b['weight'] for b in blocks]
    return headers, weights
```

## Subtopics

### [Variable Bit Rate Color Compression with Macro Blocks](1886-variable-bit-rate-color-compression-with-macro-blocks.md)
Variable Bit Rate Color Compression with Macro Blocks is a compression format for sparse 3D color data that uses variable bits per weight (bpw) to optimize compression ratio, addressing the limitation of fixed bpw methods where theoretical optimal compression is constrained by header overhead. It sets itself apart from its sibling [Variable-Block Color Compression](1878-variable-block-color-compression.md) by introducing macro blocks to localize header offsets, thereby reducing the bit-width required for pointers and enabling efficient variable bit-rate encoding without prohibitive header sizes.

### [GPURealTimeBC6H](13886-gpurealtimebc6h.md)
GPURealTimeBC6H is a GPU-based real-time compressor for the BC6H texture format. It solves the problem of high-quality HDR texture compression by pruning the BC6H block mode search space to specific modes tailored for speed or quality presets. It sets itself apart from offline compressors by performing all arithmetic in log2 space to optimize for perceptual error after tone mapping, and by restricting the search to modes 11 (fast) or 2 and 6 (quality).

## Operating characteristics
*   **Time Complexity:** Encoding is iterative and depends on the number of merges [S1, unofficial]. In the worst case, it is $O(N^2)$ or $O(N \log N)$ depending on implementation, as each pass may merge $O(N)$ blocks, and there may be $O(N)$ passes [S1, unofficial]. Decoding is $O(\log B)$ where $B$ is the number of blocks, due to binary search on headers [S1, unofficial].
*   **Memory Complexity:** The compressed size is proportional to the number of blocks $B$ [S1, unofficial]. Each block adds a fixed-size header (approx. 128 bits + 32 bits = 160 bits) and a weight (3-4 bits) [S1, unofficial]. The overhead is low compared to storing all voxel colors [S1, unofficial].
*   **Performance:** The method is designed for sparse 3D data where spatial coherence allows large blocks to be formed, reducing the number of headers [S1, unofficial]. It outperforms previous attempts in compression/quality [S1, unofficial].
*   **Strengths:** Adaptive block size allows for high compression ratios in smooth regions [S1, unofficial]. Fixed-size headers allow for efficient binary search decoding [S1, unofficial].
*   **Limitations:** Encoding is computationally expensive due to iterative merging and MSE calculations [S1, unofficial]. Not suitable for real-time encoding without optimization [S1, unofficial].

## Background
The method serves as a novel compression format for sparse 3D data and an alternative to mapping attributes to a DAG [S1, unofficial]. It provides negligible memory overhead compared to previous methods which doubled the size of the DAG [S1, unofficial].
