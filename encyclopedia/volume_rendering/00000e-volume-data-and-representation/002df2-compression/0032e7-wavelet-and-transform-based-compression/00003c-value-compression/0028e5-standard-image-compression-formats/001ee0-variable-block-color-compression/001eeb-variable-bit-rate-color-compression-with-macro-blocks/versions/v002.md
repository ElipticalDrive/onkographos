# Variable Bit Rate Color Compression with Macro Blocks

Also called: Compressing Color Data for Voxelized Surface Geometry (Extension), Paper IB

## Overview
Variable Bit Rate Color Compression with Macro Blocks is a compression format for sparse 3D color data that uses variable bits per weight (bpw) to optimize compression ratio, addressing the limitation of fixed bpw methods where theoretical optimal compression is constrained by header overhead [S1, unofficial]. It sets itself apart from its sibling [Variable-Block Color Compression](1878-variable-block-color-compression.md) by introducing macro blocks to localize header offsets, thereby reducing the bit-width required for pointers and enabling efficient variable bit-rate encoding without prohibitive header sizes [S1, unofficial].

## How it works
**Inputs:** A sparse 3D color dataset (voxel colors) [S1, unofficial].
**Outputs:** Compressed data stream containing macro block headers, base colors, weight bits, and weight pointers [S1, unofficial].

**Data Structures:**
The data is organized into **Macro Blocks** and **Block Headers** [S1, unofficial].
*   **Macro Block:** A fixed-size partition of the color array [S1, unofficial].
    *   Size: $2^{14}$ colors (16,384 colors) [S1, unofficial].
    *   Each macro block is compressed independently [S1, unofficial].
*   **Block Header (32-bit section):**
    *   **Voxel Index Offset:** 14 bits. Stores the macro-local voxel index offset of the first voxel in the block [S1, unofficial].
    *   **Bits/Weight:** 2 bits. Enumerates the number of bits per weight for this block. Values 1, 2, 3, 4 correspond to 1-4 bpw. The value 3 (binary `11`) is unused as a sentinel to allow a fifth case (implied 0 bpw) [S1, unofficial].
    *   **Weight Pointer:** 16 bits. Stores the macro-local bit pointer (offset into the weight array) for this block [S1, unofficial].

**Algorithm:**
1.  **Segregation:** Segregate the underlying color array into sets of size $2^{14}$, called macro blocks [S1, unofficial].
2.  **Tree Construction:** Create a tree structure of blocks with different weight bit-rates [S1, unofficial]. Construct leaf-level blocks at 0 bpw [S1, unofficial]. Recursively create new blocks with higher bit rates using the lower bit-rate blocks [S1, unofficial].
3.  **Optimal Cut:** Find the optimal cut through the tree by comparing the sum of memory overhead of blocks with lower bit rates against the parent block (which describes the same set of colors) [S1, unofficial]. Keep the configuration(s) with the lowest overhead [S1, unofficial]. Repeat recursively up to the root [S1, unofficial].
4.  **Encoding:** For each block in the optimal cut, store the 32-bit header (14-bit voxel offset, 2-bit bpw, 16-bit weight pointer) [S1, unofficial]. Store the base colors and weight bits for the block [S1, unofficial].
5.  **Decoding:** Given a voxel index, calculate the macro block index directly [S1, unofficial]. Use the header index of the comprising and directly following macro blocks to define a range of header candidates [S1, unofficial]. Perform a binary search on the headers' first voxel index to find the block spanning the color [S1, unofficial]. Perform a direct lookup in the weight array using the same index [S1, unofficial]. Reconstruct color, base colors (from header), and weight [S1, unofficial].

**Pseudocode:**
```python
import bisect

def encode(colors, macro_block_size=16384):
    # 1. Segregate color array into macro blocks
    macro_blocks = [colors[i : i + macro_block_size] for i in range(0, len(colors), macro_block_size)]

    headers = []
    base_colors = []
    weight_bits = []
    weight_bit_offsets = []

    for mb in macro_blocks:
        # 2 & 3. Tree construction: leaf blocks at 0 bpw, recursively build higher bpw
        # [S1, unofficial] Algorithm is identical to Paper IA. Not given in sources.
        optimal_blocks = build_optimal_block_tree(mb)

        current_weight_offset = 0
        for block in optimal_blocks:
            bpw = block.bpw
            # 2-bit field: 1-4 bpw. Value 3 (11) is sentinel for 5th case
            bpw_field = 3 if bpw == 0 else bpw

            # 14-bit macro-local voxel index offset
            local_voxel_offset = block.first_voxel_index % macro_block_size
            # 16-bit macro-local bit pointer
            local_weight_pointer = current_weight_offset

            # Pack 32-bit header: 14 bits offset, 2 bits bpw, 16 bits pointer
            header_val = (local_voxel_offset << 18) | (bpw_field << 16) | local_weight_pointer
            headers.append(header_val)
            base_colors.append(block.base_colors)
            weight_bits.extend(block.weight_bits)
            weight_bit_offsets.append(current_weight_offset)
            current_weight_offset += len(block.weight_bits)

    return headers, base_colors, weight_bits, weight_bit_offsets

def decode(headers, base_colors, weight_bits, weight_bit_offsets, voxel_index, macro_block_size=16384):
    # 5. Index macro blocks directly
    mb_idx = voxel_index // macro_block_size
    # Define range of header candidates from comprising and following macro blocks
    # Headers are stored sequentially per macro block
    headers_per_mb = len(headers) // (len(weight_bit_offsets) // macro_block_size + 1)
    start_header = mb_idx * headers_per_mb
    end_header = (mb_idx + 1) * headers_per_mb + headers_per_mb
    candidate_headers = headers[start_header : end_header]

    # Binary search on headers' first voxel index
    voxel_offsets = [(h >> 18) & 0x3FFF for h in candidate_headers]
    target_idx = bisect.bisect_right(voxel_offsets, voxel_index % macro_block_size) - 1
    target_header = candidate_headers[target_idx]

    # Extract fields
    bpw_field = (target_header >> 16) & 0x3
    bpw = 0 if bpw_field == 3 else bpw_field
    weight_pointer = target_header & 0xFFFF
    block_base_colors = base_colors[target_idx + start_header]

    # Direct lookup in weight array
    weight_bits_for_block = weight_bits[weight_pointer : weight_pointer + bpw]

    # [G] Standard fixed-point to float conversion
    weight = sum(b * (2 ** i) for i, b in enumerate(reversed(weight_bits_for_block))) / (2 ** bpw) if bpw > 0 else 0.0

    # [G] Standard color reconstruction (weighted interpolation of base colors)
    color = sum(bc * weight for bc in block_base_colors)
    return color
```

**Parameters:**
*   Macro block size: $2^{14}$ colors (16,384 colors) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   Blocks ideally residing on the border between two macro blocks are forced to be (up to) two blocks, causing slight overhead [S1, unofficial].
*   The 2-bit field for bits/weight enumerates 1-4 bpw; the value 3 (`11`) is unused as a sentinel to allow a 5th case (implied 0 bpw) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Lookup times are slightly more expensive than fixed bpw methods due to the binary search, but decoding is as fast or faster than previous formats due to the reduced binary search range [S1, unofficial].
*   **Memory Complexity:** Memory overhead is practically negligible compared to previous methods which doubled DAG size [S1, unofficial]. The overhead is 1/128 extra bits per color for the macro-block header, plus a small extra overhead due to border blocks [S1, unofficial].
*   **Strengths:** Significantly decreases compressed size given the same error thresholds compared to fixed bpw methods [S1, unofficial].
*   **Limitations:** Slightly more expensive lookup times than fixed bpw methods [S1, unofficial].

## Background
This method was introduced in "Paper IB - Compressing Color Data for Voxelized Surface Geometry (Extension)" as an alternative to mapping attributes to a DAG [S1, unofficial]. It addresses the limitations of fixed bit rate weights (Paper IA) where the theoretical optimal compression ratio is constrained by header overhead [S1, unofficial]. The method allows higher bit rates to span larger areas, decreasing the headers footprint at the cost of weights, while lower bit rates are suitable for large regions of similar or identical colors [S1, unofficial].
