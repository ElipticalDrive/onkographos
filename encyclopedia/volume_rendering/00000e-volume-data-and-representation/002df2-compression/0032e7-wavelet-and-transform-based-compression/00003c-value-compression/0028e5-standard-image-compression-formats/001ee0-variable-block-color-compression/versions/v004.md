# Variable-Block Color Compression


## Overview
Variable-Block Color Compression is a lossy compression method for sparse 3D color data that uses variable-length spatial blocks to optimize compression ratios [S1, unofficial]. It sets itself apart from its sibling [ASTC](5729-astc.md) and other fixed-block formats by allowing block dimensions to vary based on an error threshold, thereby reducing header overhead while maintaining a fixed-rate decoding structure through separate weight arrays [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of voxel colors $C_i$ and an error threshold $\tau$ (Mean Square Error limit).
*   **Output:** A compressed representation consisting of a fixed-size header array and a variable-length weight array.

**Data Structures:**
1.  **Header Array:** A 32-bit integer array. Each entry represents one block and contains:
    *   Base Color 1 ($B_1$): 16 bits.
    *   Base Color 2 ($B_2$): 16 bits.
    *   Start Voxel Index: 32 bits (indicating the first voxel in the block).
    *   *Note:* The header size is fixed at 2x16 + 32 bits, stored in 32-bit words.
2.  **Weight Array:** A separate array storing weights $w$. Each weight is quantized to a fixed bit width (e.g., 3 bits) [S1, unofficial].

**Formulas:**
*   **Color Reconstruction:** For a voxel with weight $w$, the color $C$ is reconstructed as:
    $$C = wB_1 + (1 - w)B_2$$
    Where $B_1$ and $B_2$ are the base colors from the header, and $w$ is the weight from the weight array [S1, unofficial].
*   **Error Metric:** The Mean Square Error (MSE) of the reconstructed color must not exceed the threshold $\tau$ [S1, unofficial].

**Parameters:**
*   **Base Colors ($B_1, B_2$):** 16 bits each [S1, unofficial].
*   **Weight ($w$):** 3 bits (fixed width per weight) [S1, unofficial].
*   **Error Threshold ($\tau$):** The maximum allowed MSE for a block [S1, unofficial].

**Algorithm Steps:**

**Encoding:**
1.  Initialize each voxel color as a separate block.
2.  Iterate through the blocks sequentially. For each block, attempt to merge it with its left or right neighbor, whichever results in the lowest MSE after merging.
3.  If both potential merges violate the error threshold $\tau$, the current block is finalized. This involves calculating new base colors ($B_1, B_2$) and weights for the union of voxels in the block.
4.  Repeat the iteration with the newly merged blocks until all blocks are considered "done" (i.e., no further merges are possible within the error threshold) [S1, unofficial].

**Decoding:**
1.  Determine the target voxel index.
2.  Perform a binary search on the `Start Voxel Index` field in the Header Array to find the specific header entry corresponding to the block spanning the target voxel [S1, unofficial].
3.  Perform a direct lookup in the Weight Array using the voxel's local index within the block to retrieve the weight $w$.
4.  Retrieve $B_1$ and $B_2$ from the found header.
5.  Reconstruct the color using $C = wB_1 + (1 - w)B_2$ [S1, unofficial].

## Subtopics

### [Variable Bit Rate Color Compression with Macro Blocks](1886-variable-bit-rate-color-compression-with-macro-blocks.md)
Variable Bit Rate Color Compression with Macro Blocks is a compression format for sparse 3D color data that uses variable bits per weight (bpw) to optimize compression ratio, addressing the limitation of fixed bpw methods where theoretical optimal compression is constrained by header overhead. It sets itself apart from its sibling [Variable-Block Color Compression](1878-variable-block-color-compression.md) by introducing macro blocks to localize header offsets, thereby reducing the bit-width required for pointers and enabling efficient variable bit-rate encoding without prohibitive header sizes.

## Operating characteristics
*   **Time Complexity:** Encoding is iterative and depends on the merging strategy; decoding requires a binary search over headers ($O(\log N)$) and a direct weight lookup ($O(1)$).
*   **Memory Complexity:** Storage consists of fixed-size headers and a weight array. The overhead is negligible compared to the DAG structure it complements [S1, unofficial].
*   **Performance:** Outperforms previous attempts in both compression ratio and quality for sparse 3D data [S1, unofficial].
*   **Strengths:** Low memory overhead, straightforward implementation, variable block sizes adapt to data complexity.
*   **Limitations:** Lookup times are more expensive than fixed-block formats due to the binary search requirement [S1, unofficial].

## Background
This method was introduced as an alternative to mapping attributes to a DAG, aiming to reduce memory overhead while maintaining compression quality [S1, unofficial]. It is described in the context of sparse voxel DAGs and memory-efficient compression of surface representations [S1, unofficial].
