# Triadic frequency band decomposition

Also called: Hierarchical Data Decomposition, Hierarchical quantization scheme

## Overview
Triadic frequency band decomposition is a lossy compression method for volumetric scalar fields that partitions data into $4^3$ blocks and decomposes each block into a multiresolution representation of three frequency bands: high-frequency differences, mid-frequency differences, and the block mean [S1, unofficial]. It differs from its sibling [Laplacian Pyramid](2250-laplacian-pyramid.md) by using fixed $4^3$ spatial blocks with hardware-friendly dependent texture fetches for decoding, and from [Wavelet Kernel Selection](7035-wavelet-kernel-selection.md) by relying on vector quantization codebooks rather than adaptive kernel selection [S1, unofficial].

## How it works
**Inputs:** A 3D scalar field of size $N_x \times N_y \times N_z$.
**Outputs:** An RGB index texture $I$, two codebook textures $C_1$ and $C_2$, and an address texture $A$.

**Data Structures:**
1.  **Index Texture $I$:** A 3D texture of size $(N_x/4) \times (N_y/4) \times (N_z/4)$. Each texel stores three 8-bit values:
    *   R-component: The mean value of the $4^3$ block.
    *   G-component: An 8-bit index into codebook $C_1$ (high-frequency band).
    *   B-component: An 8-bit index into codebook $C_2$ (mid-frequency band).
2.  **Codebook $C_1$:** A 2D texture of size $256 \times 64$. The s-coordinate is the index from $I$'s G-component. The t-coordinate is determined by the address texture $A$. It stores 64-component codewords representing high-frequency differences.
3.  **Codebook $C_2$:** A 2D texture of size $256 \times 8$. The s-coordinate is the index from $I$'s B-component. The t-coordinate is determined by the address texture $A$. It stores 8-component codewords representing mid-frequency differences.
4.  **Address Texture $A$:** A 2D texture of size $4^3$ (matching the encoded texel region size). It is mapped via nearest-neighbor interpolation.
    *   R-component: Stores 64 different addresses to index components within a codeword in $C_1$.
    *   G-component: Stores 8 different addresses to index components within a codeword in $C_2$.

**Algorithm Steps:**
1.  **Partitioning:** Divide the input scalar field into disjoint blocks of size $4^3$ voxels [S1, unofficial].
2.  **First Down-sampling (High-Frequency Band):** For each block, down-sample by a factor of two by averaging disjoint sets of $2^3$ voxels. This produces $4^3 / 2^3 = 8$ mean values. Calculate the difference between the original 64 data samples and their respective down-sampled values. Store these 64 differences in a vector $v_{high}$ [S1, unofficial].
3.  **Second Down-sampling (Mid-Frequency Band):** Apply the same down-sampling process to the 8 mean values obtained in Step 2. This produces 1 single value representing the mean of the entire block. Calculate the difference between the 8 mean values and the final single mean value. Store these 8 differences in a vector $v_{mid}$ [S1, unofficial].
4.  **Mean Storage:** Store the single mean value in a scalar $v_{mean}$ [S1, unofficial].
5.  **Thresholding:** Apply thresholding to $v_{high}$ and $v_{mid}$. If the detail coefficients are small or zero (indicating homogeneous or empty regions), map the respective vector to the zero vector. This maximizes codeword usage for significant non-zero vectors and simplifies quantization [S1, unofficial].
6.  **Vector Quantization:** Quantize $v_{high}$ and $v_{mid}$ separately using pre-computed codebooks. The codebooks contain 256 entries each. The index into each codebook is stored as one 8-bit value [S1, unofficial].
7.  **Encoding:** Assemble the encoded block into a single texel in texture $I$:
    *   $I.r = v_{mean}$ (8-bit).
    *   $I.g = \text{index}(v_{high})$ (8-bit).
    *   $I.b = \text{index}(v_{mid})$ (8-bit).

**Pseudocode:**

```python
def triadic_decomposition(volume, codebook_high, codebook_mid):
    """
    Decomposes a volume into triadic frequency bands and encodes them.
    volume: 3D array of shape (Nx, Ny, Nz)
    codebook_high: 2D array of shape (256, 64)
    codebook_mid: 2D array of shape (256, 8)
    Returns: index_texture, address_texture
    """
    Nx, Ny, Nz = volume.shape
    # Output textures
    # Index texture size: (Nx/4, Ny/4, Nz/4)
    index_texture = np.zeros((Nx // 4, Ny // 4, Nz // 4), dtype=np.uint8)
    
    # Address texture size: 4x4x4 (flattened to 2D 16x16 or similar for storage, 
    # but logically 4^3 entries)
    # R: 64 addresses for C1, G: 8 addresses for C2
    address_texture = np.zeros((4, 4, 4, 2), dtype=np.uint8)
    
    # Pre-compute address texture for one block
    # C1 has 64 components. We need 64 addresses.
    # C2 has 8 components. We need 8 addresses.
    # The source states A stores relative addresses. 
    # For simplicity in decoding, these map to the t-coordinate in the codebook textures.
    # Assuming linear addressing for the codeword components:
    for i in range(64):
        address_texture[i // 16, (i // 4) % 4, i % 4, 0] = i % 64 # R component stores index for C1
    for i in range(8):
        address_texture[i // 4, i % 4, 0, 1] = i % 8 # G component stores index for C2
        # Note: The source says "blocks of 2^3 adjacent texels get assigned the same address"
        # for C2. This implies the address texture is sampled such that it yields 8 unique values.
        # The exact mapping depends on the hardware texture fetcher, but logically it provides the offset.
        
    for x in range(0, Nx, 4):
        for y in range(0, Ny, 4):
            for z in range(0, Nz, 4):
                # Extract 4x4x4 block
                block = volume[x:x+4, y:y+4, z:z+4]
                
                # Step 2: High-frequency band (64 components)
                # Down-sample by averaging disjoint sets of 2^3 voxels
                # 4x4x4 block -> 2x2x2 means. 8 means.
                # The difference is between original 64 voxels and their corresponding mean.
                # Each 2x2x2 sub-block averages to one mean.
                high_diffs = []
                for i in range(0, 4, 2):
                    for j in range(0, 4, 2):
                        for k in range(0, 4, 2):
                            sub_block = block[i:i+2, j:j+2, k:k+2]
                            mean_val = np.mean(sub_block)
                            # Difference for each of the 8 voxels in this sub-block
                            for di in range(2):
                                for dj in range(2):
                                    for dk in range(2):
                                        diff = block[i+di, j+dj, k+dk] - mean_val
                                        high_diffs.append(diff)
                
                # Thresholding for high band
                # Map small/zero vectors to zero vector
                if np.all(np.abs(high_diffs) < threshold_high): # threshold_high is implementation detail [G]
                    high_diffs = [0.0] * 64
                
                # Quantize high band
                idx_high = find_best_codebook_entry(high_diffs, codebook_high)
                
                # Step 3 & 4: Mid-frequency band (8 components) and Mean
                # The 8 means calculated above
                means = []
                for i in range(0, 4, 2):
                    for j in range(0, 4, 2):
                        for k in range(0, 4, 2):
                            sub_block = block[i:i+2, j:j+2, k:k+2]
                            means.append(np.mean(sub_block))
                
                # Down-sample the 8 means to 1 mean
                global_mean = np.mean(means)
                
                # Mid-frequency differences: difference between the 8 means and the global mean
                mid_diffs = [m - global_mean for m in means]
                
                # Thresholding for mid band
                if np.all(np.abs(mid_diffs) < threshold_mid): # threshold_mid is implementation detail [G]
                    mid_diffs = [0.0] * 8
                
                # Quantize mid band
                idx_mid = find_best_codebook_entry(mid_diffs, codebook_mid)
                
                # Store in index texture
                # R: mean (8-bit), G: idx_high, B: idx_mid
                # Note: Mean might need scaling/clamping to 8-bit range
                index_texture[x//4, y//4, z//4, 0] = clamp_to_uint8(global_mean)
                index_texture[x//4, y//4, z//4, 1] = idx_high
                index_texture[x//4, y//4, z//4, 2] = idx_mid
                
    return index_texture, address_texture

def find_best_codebook_entry(vector, codebook):
    """
    Finds the index of the codeword in the codebook that minimizes the distance to the vector.
    vector: list of floats
    codebook: 2D array (N, L)
    Returns: int index
    """
    best_idx = 0
    best_dist = float('inf')
    for i in range(codebook.shape[0]):
        # Euclidean distance or similar metric
        dist = np.sum((np.array(vector) - codebook[i]) ** 2)
        if dist < best_dist:
            best_dist = dist
            best_idx = i
    return best_idx
```

**Edge Cases and Pitfalls:**
*   **Precision:** Mean values and difference coefficients must be handled with sufficient precision before quantization to avoid artifacts. The mean is stored directly as 8-bit, which may limit dynamic range [S1, unofficial].
*   **Boundaries:** The method assumes the volume dimensions are divisible by 4. Boundary conditions for volumes not divisible by 4 are not specified in the sources [S1, unofficial].
*   **Homogeneous Regions:** Thresholding maps zero-difference vectors to the zero vector. If the codebook does not contain a zero vector, this may lead to suboptimal reconstruction for empty regions [S1, unofficial].

## Subtopics

### [Triadic Vector Quantization](6504-triadic-vector-quantization.md)
Triadic Vector Quantization is a lossy compression method for volumetric data that partitions scalar fields into $4^3$ blocks, decomposes each block into a multiresolution representation of three frequency bands, and quantizes the resulting vectors using discrete codebooks. It differs from scalar quantization by grouping spatially correlated differences into fixed-length vectors, and from pure transform coding by relying on hardware-friendly texture lookups for decoding. Choose this when hardware acceleration via dependent texture fetches is available and the data exhibits strong spatial correlation within $4^3$ blocks.

### Spectral decomposition and error band partitioning
Spectral decomposition and error band partitioning computes centered Fourier spectra and partitions frequency coordinates into low, mid, and high bands to measure spectral magnitude reconstruction errors [S2, unofficial]. It differs from Triadic Frequency Band Decomposition by operating in the frequency domain using 2D DFTs rather than spatial block decomposition. Choose this for analyzing reconstruction errors in spectral magnitude rather than compressing volumetric data directly.

## Operating characteristics
*   **Time Complexity:** Encoding involves block-wise averaging and vector quantization. Vector quantization is $O(N \cdot M)$ where $N$ is the number of blocks and $M$ is the codebook size (256) [S1, unofficial]. Decoding is $O(1)$ per voxel using texture lookups [S1, unofficial].
*   **Memory Complexity:** The compressed representation requires 3 bytes per $4^3$ block (24 bytes for 64 voxels), plus codebook storage. Codebooks are $256 \times 64$ and $256 \times 8$ floats/vectors [S1, unofficial].
*   **Measured Performance:** The method was tested on an ATI 9700 GPU, exploiting per-fragment arithmetic and dependent texture fetches [S1, unofficial].
*   **Strengths:** Hardware-friendly decoding; maximizes codeword usage for homogeneous regions; enhances fidelity by assembling signals from separate bands [S1, unofficial].
*   **Limitations:** Fixed block size ($4^3$); requires pre-computed codebooks; 8-bit mean storage may limit dynamic range [S1, unofficial].
*   **When to use:** Real-time volume rendering on GPUs with dependent texture fetch support; data with strong spatial correlation.
*   **When not to use:** Data with large homogeneous regions where thresholding might discard significant detail; data requiring high dynamic range in the mean value.

## Background
The method was introduced in "Compression Domain Volume Rendering" (2003) by researchers associated with the Technical University of Munich, targeting the ATI 9700 GPU [S1, unofficial]. It is part of the broader field of wavelet and transform-based compression for volume data.
