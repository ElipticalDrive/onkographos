# Value compression
## Overview
Value compression reduces the storage footprint and memory bandwidth requirements of volumetric datasets by encoding the scalar or vector values of voxels, distinct from spatial compression which addresses the geometry or sparsity of the data [S1][S5]. It solves the problem of high memory consumption in large-scale scientific visualization and real-time rendering by exploiting statistical redundancy, spatial correlation, and quantization limits [S1][S2]. What sets it apart from its siblings, such as [Sparse structures](5-sparse-structures.md) which handle empty space, and [Deferred Filtering Architecture for Compressed Volumes](857-deferred-filtering-architecture-for-compressed-volumes.md) which handles filtering artifacts, is its direct manipulation of the amplitude domain through transforms, quantization, or predictive coding to minimize the bit-depth of the signal itself [S1][S5].

## Subtopics

### [Triadic frequency band decomposition](828-triadic-frequency-band-decomposition.md)
Triadic frequency band decomposition partitions a scalar field into disjoint blocks and decomposes each block into three hierarchical frequency bands (high-frequency details, mid-frequency details, and mean). It sets itself apart from standard scalar quantization by encoding spatially correlated differences into low-dimensional vectors, and from pure transform coding by using discrete codebooks for efficient hardware decoding. Choose it when hardware-accelerated, direct GPU rendering of compressed scalar fields is required without full CPU decompression.

### [Rational Bézier Deblocking Filter](832-rational-b-zier-deblocking-filter.md)
The Rational Bézier Deblocking Filter is a post-processing technique applied during GPU volume rendering to reduce blocking artifacts at block boundaries in compressed volumetric data. It solves the problem of signal discontinuities introduced by block-based compression by projecting voxel scalar values onto rational Bézier curves. Unlike standard Bézier filtering, it uses adjustable weights based on local gradient magnitude to preserve high-frequency features while smoothing homogeneous regions. It is distinct from its siblings in [Value compression](6-value-compression.md) because it is a data-dependent, block-aware filter that requires no knowledge of the specific compression algorithm used and modifies no stored data. Choose it as a post-processing step for block-based compressed volumes to improve visual quality without re-encoding.

### [Vector Quantization](907-vector-quantization.md)
Vector Quantization (VQ) is a lossy compression technique that maps $n$-dimensional input vectors to a fixed-length index referencing an entry in a pre-defined or learned codebook (dictionary). It solves the problem of high storage requirements for volumetric data by exploiting spatial redundancy: identical or similar data blocks are replaced by a single compact index, reducing storage from individual voxel storage to codebook storage plus mapping indices. Unlike scalar quantization which processes values independently, VQ treats blocks of data as vectors, allowing it to capture correlations within the block. It sets itself apart from transform-based methods (like wavelets) by enabling extremely fast, parallel decompression on the GPU, as decoding is reduced to a simple texture lookup. Choose it when data exhibits strong local correlations and fast, parallel GPU decoding via texture lookups is prioritized.

### [Differential Data Stream (DDS) File Format](1754-differential-data-stream-dds-file-format.md)
The Differential Data Stream (DDS) format is a lossless compression method for volume data that encodes differential values using run-length encoding and adaptive bit allocation per run. It handles multi-channel volume data by interleaving channels and processing them in blocks, selecting between two file versions based on data size. It sets itself apart from general-purpose codecs by specializing in spatial and channel correlations found in scientific volume data, offering a lightweight alternative to transform-based methods. Choose it for lossless storage and transmission of multi-channel scientific datasets where exact reconstruction is mandatory.

### [Zerobit Encoding Scheme](1918-zerobit-encoding-scheme.md)
The Zerobit Encoding Scheme is a value compression method for volume rendering data that improves compression ratio and random access speed by exploiting spatial coherence in wavelet coefficients. It modifies the cell tag table to indicate whether the coefficient vector $c_0$ is zero, reducing storage waste for zero-valued coefficients. It sets itself apart from its siblings by using a variable-length significance map driven by "zerobits" (flags indicating if all 7 detail coefficients of a node are zero) rather than fixed-size maps or purely predictive differential coding. Choose it when working with wavelet-compressed volumes that exhibit large homogeneous regions or sparse detail coefficients.

### [Laplacian Pyramid](2250-laplacian-pyramid.md)
The Laplacian Pyramid is a multiresolution decomposition technique that represents a volume by a coarse base layer and a series of residual difference layers (Laplacian levels). It solves the problem of high inter-pixel correlation in volumetric data by decorrelating the signal, concentrating values around zero to reduce entropy, and enabling efficient compression via quantization and entropy coding. It is distinguished from wavelet-based methods like Triadic frequency band decomposition by its use of non-orthogonal, redundant filter banks that guarantee perfect reconstruction through simple addition, albeit at the cost of oversampling. Choose it when a redundant, non-orthogonal decomposition that guarantees perfect reconstruction through simple addition is preferred over orthogonal wavelet bases.

### [Random Access of Compressed Data (Westermann's Method)](2269-random-access-of-compressed-data-westermann-s-method.md)
A data layout technique to support random access to wavelet coefficients stored in compressed linear arrays, overcoming the variable length of Huffman codes. It sets itself apart from standard entropy-coded layouts by organizing coefficients into fixed-size blocks with metadata masks and offsets, enabling fast voxel reconstruction without full stream decoding. Choose it when interactive, non-sequential voxel access is required on wavelet-compressed volumes.

### [Predictive and Differential Coding](4393-predictive-and-differential-coding.md)
Predictive and Differential Coding compresses volumetric data by storing the difference (residual) between a predicted value and the actual value, exploiting spatial or temporal redundancy. It distinguishes itself from sibling methods by focusing on the raw residual stream before entropy coding, often resulting in uniform bricks of zeros for static regions, whereas siblings like [Triadic frequency band decomposition](828-triadic-frequency-band-decomposition.md) operate in the transform domain. Choose it for data with strong local smoothness or temporal coherence where transform overhead is undesirable.

### [Standard Image Compression Formats](4394-standard-image-compression-formats.md)
Standard Image Compression Formats refers to the application of established 2D texture compression standards (specifically BC7 and ASTC) and specialized variable-block methods to compress volumetric data, typically by mapping 3D structures (like splats or voxels) onto 2D texture atlases or by treating volume slices as texture blocks. This approach solves the problem of high memory bandwidth and storage requirements for dense volumetric representations by leveraging hardware-accelerated decompression. It sets itself apart from general volume compression methods by relying on fixed-rate, block-based codecs originally designed for surface rendering, often requiring spatial mapping (e.g., UV unwrapping or atlas packing) rather than direct 3D transform coding. Choose it when leveraging existing 2D texture compression hardware for rapid prototyping or when inter-slice correlation is negligible.

### [Structural and Geometric Compression](4959-structural-and-geometric-compression.md)
Structural and Geometric Compression is a lossless or lossy compression method for volumetric data that exploits the spatial connectivity and geometric regularity of the underlying structures, such as isosurfaces or particle boundaries, rather than relying solely on statistical redundancy in scalar values. It sets itself apart from sibling methods like [Value compression](6-value-compression.md) by encoding the topological relationships (e.g., surface links) and geometric attributes (e.g., normals) directly, allowing for efficient on-the-fly rendering without full volume reconstruction. Unlike [Triadic frequency band decomposition](828-triadic-frequency-band-decomposition.md) which operates in the frequency domain, this method operates in the spatial domain, preserving exact geometric boundaries. Choose it for particle-based, isosurface, or highly sparse volumetric data where surface connectivity and normals are the primary rendering targets.

### [Splat parameter encoding and codec selection](5019-splat-parameter-encoding-and-codec-selection.md)
This method defines the storage format and compression pipeline for 3D Gaussian Splat parameters, reducing file size from 30–37 bytes/splat to 8.8–12.7 bytes/splat while maintaining high rendering fidelity. It differs from generic volume compression by applying width-aware, per-data-type codec policies and specific byte-shuffling rules to spatially bucketed splat attributes, rather than treating the volume as a uniform grid. Choose it for 3D Gaussian Splatting workflows requiring efficient web-based or disk-based storage of splat attributes.

### [Texture Format Compression](5623-texture-format-compression.md)
Texture Format Compression refers to the use of standardized block-based compression algorithms (such as BCn/DXT/S3TC) to compress volumetric data stored in texture memory. It solves the problem of high memory bandwidth and capacity requirements for large volume datasets by mapping 3D voxel data into 2D texture arrays or 3D textures, leveraging GPU hardware decompression for efficient ray-marching access. It is distinguished from general volume compression by its reliance on fixed-rate, block-localized quantization schemes originally designed for 2D images, adapted for volumetric storage, often trading reconstruction fidelity for hardware-accelerated decompression speed and cache efficiency. Choose it when hardware-accelerated decompression speed and cache efficiency are prioritized over perfect scalar reconstruction fidelity.

### [Time-Varying Volume Compression Strategies](5714-time-varying-volume-compression-strategies.md)
Time-varying volume compression strategies address the bandwidth and memory limitations inherent in real-time rendering of animated volumetric datasets, where loading, decoding, and rendering every time step on the GPU is often infeasible. This family is distinguished from static volume compression by its explicit exploitation of temporal coherence (correlation between frames) alongside spatial redundancy, typically through 4D transforms, key-frame/differential schemes, or per-step encoding. Choose them for animated or simulation-driven volumes where temporal coherence can be leveraged to reduce per-frame bandwidth.

### [Quantization](5935-quantization.md)
Quantization is the process of mapping a large set of input values, typically continuous or high-precision discrete data, to a smaller, discrete set of output values. In volume rendering, it serves as the primary lossy compression step that reduces memory bandwidth and storage requirements by limiting the precision of voxel attributes or scalar fields. It sets itself apart from sibling methods like [Vector Quantization](907-vector-quantization.md) or [Triadic frequency band decomposition](828-triadic-frequency-band-decomposition.md) by operating on individual values (scalar or attribute) rather than grouping them into codebooks or transforming them into frequency coefficients, although it often precedes entropy coding in the compression pipeline. Choose it as a foundational preprocessing or standalone step when reducing bit-depth is the primary compression goal.

### [Burrows-Wheeler Transform](6541-burrows-wheeler-transform.md)
A reversible permutation scheme that re-sorts a block of data according to context, organizing it in a compression-friendly way for entropy coders. It sets itself apart from direct transform methods by operating in the spatial domain to group similar contexts together before entropy encoding. Choose it when applied as a preprocessing step to improve the efficiency of subsequent entropy coders like Huffman or Arithmetic coding.

### [Transform-based Block Coding](6882-transform-based-block-coding.md)
Transform-based block coding compresses volumetric data by partitioning it into fixed-size spatial blocks, applying a linear transform (such as DCT or DWT) to concentrate energy into a few coefficients, and entropy coding the result. It solves the problem of efficiently storing and transmitting large, correlated volumetric datasets by exploiting local spatial redundancy. It is distinguished from its siblings by its reliance on fixed-size spatial tiling and frequency-domain transformation, contrasting with [Triadic frequency band decomposition](828-triadic-frequency-band-decomposition.md) which uses hierarchical subband structures, and [Vector Quantization](907-vector-quantization.md) which maps blocks to codebook indices without explicit frequency transformation. Choose it for dense volumes with strong local spatial correlation where block-wise processing enables parallelization.

### [Wavelet Kernel Selection](7035-wavelet-kernel-selection.md)
Selection of reversible Haar, 5x3, irreversible 9x7, and (6,6) wavelet kernels for compression experiments. It sets itself apart by focusing on the choice of the transform basis itself rather than the encoding pipeline. Choose it when optimizing the trade-off between compression ratio, visual fidelity, and reversibility for a specific dataset.
#### Progressive Encoding of Volumetric Data
Progressive encoding enables scalability on the whole volume by allowing decoding to be stopped at any point into the bitstream [S2]. In G-PROG mode, the set of quantizers is applied to the whole set of subband images before passing to the next subband [S2]. The scanning order follows the decomposition level: all subbands at level $l$ are scanned before passing to level $l+1$ [S2]. During step $l$, the quantizer is applied to each image of each subband [S2]. In G-PROG mode, the compression ratio is maximized, but 3-D encoding/2-D decoding functionalities are not enabled [S2]. Choose it when bandwidth-constrained streaming or quality scalability is required [S2].
#### Zarr-based Archive Encoding
Zarr-based archive encoding involves writing fitted splats to Zarr9 archives with semantic encoding (8 semantic types) [S3, unofficial]. It applies a width-aware Blosc-zstd compression policy: byte shuffle for multi-byte integer codes; no shuffle for single-byte codes and floating-point arrays [S3, unofficial]. The server requirement is a static HTTP host allowing cross-origin reads and range requests for zipped form [S3, unofficial]. The archive format is a directory of chunk files, or a single uncompressed `.luxar.zarr.zip` file where each chunk is a member fetched by HTTP range request without unpacking [S3, unofficial]. Choose it for web-based visualization of multidimensional scientific data requiring efficient chunked fetching [S3, unofficial].
#### Significance Maps and Bit-wise Encoding
Significance maps and bit-wise encoding approaches fully avoid entropy encoding and RLE by using significance maps of wavelet coefficients and bit-wise encodings [S4]. This method is often used in conjunction with wavelet transforms to provide efficient random access and progressive transmission [S4]. Choose it when hardware random access speed is critical and entropy decoding overhead must be eliminated [S4].
#### Block Truncation Coding
Block Truncation Coding (BTC) is an adaptation of BTC supporting hardware accelerated random access, specifically texture compression using invalid combinations [S6, unofficial]. During BTC, the data is decomposed into equal-sized blocks [S1]. Then each block is truncated as long as a given criteria is satisfied (e.g., standard deviation and average value of the original data are maintained) [S1][S6, unofficial]. This means the error tolerance (threshold level) is different per block [S6, unofficial]. Adaptations include VTC (3D extension of S3TC), ETC2, and ASTC [S1][S6, unofficial]. BTC is the most common choice for fixed hardware implementations due to very simple decompression and fast random access, though it exhibits a lower signal over noise ratio compared to transform methods [S1][S6, unofficial]. Choose it for fixed-function GPU rendering pipelines requiring deterministic decompression latency [S1].
#### Volumetric Coding Scheme
The Volumetric Coding Scheme separates volumetric data into model $m$ (binary volume: 1=existing, 0=transparent) and texture $T$ (luminance Y, chrominance U,V) to allow lossless model coding and scalable bitstreams [S5]. Luminance Y is used to identify the model structure [S5]. Input Y to depth-plane reduction; subsample chrominance U,V before depth-plane reduction [S5]. The model $m$ is losslessly and independently coded [S5]. Texture $T$ is lossily coded [S5]. Y and U,V are reorganized into appropriate forms (via chroma subsampling and depth-plane reduction) before applying lossy coding [S5]. The data stream is organized in this order: 1) Half resolution volume data ($m_h, T_h$), 2) Additional data for full resolution ($m_f, T_f$), 3) Remaining data for double resolution ($m_d, T_d$) [S5]. Camera parameters are separately coded using Huffman coding as side information [S5]. The background (same geometry as volume) is independently coded from the volumetric data [S5]. Choose it for view synthesis applications requiring scalable bitstreams and accurate geometric reconstruction [S5].
#### General Lossy Compression Flow
The decompression process is the reverse of the 3 stages mentioned above [S6, unofficial]. Choose it as a conceptual baseline for designing custom lossy pipelines where data transformation, quantization, and entropy coding are explicitly separated [S6, unofficial].
#### 4×4×4 Block Reconstruction
A block-wise decoding optimization for wavelet-compressed volumes that processes voxels in 4×4×4 blocks to reuse R-slice values across adjacent blocks, reducing decoding overhead for spatially coherent access patterns [S7]. Partition the volume into 4×4×4 blocks, each structurally containing 3 I-slices followed by 1 R-slice [S7]. Begin decoding a block by computing the 4×4 voxels of its R-slice [S7]. Compute the 4×4 voxels for each of the 3 I-slices in the current block by reusing the retained R-slice values from the block above [S7]. Block dimensions: 4 × 4 × 4 voxels. Block slice composition: 3 I-slices followed by 1 R-slice [S7]. Purely random access patterns negate the block reuse optimization; the method assumes regular or spatially coherent access [S7]. Random voxel access slowdown: compressed data is 3 to 5 times slower than uncompressed data on average [S7]. Whole-volume reconstruction overhead: compressed volumes take roughly 30-40 seconds longer than original volumes [S7]. Random access is 3-5x slower for compressed data, but this is acceptable compared to disk/network latency and typical non-random access patterns [S7]. Choose it for ray-casting workloads with spatially coherent traversal patterns to minimize decoding latency [S7].

## Background
Value compression in volume rendering has evolved from simple scalar quantization to complex transform-based and hardware-accelerated methods [G]. Early approaches relied on basic run-length encoding and variable bit-length encoding [S1]. The introduction of wavelet transforms allowed for multiresolution analysis and progressive transmission [S1][S2]. Block Truncation Coding and its derivatives became prominent for hardware-accelerated rendering due to their simplicity and random access capabilities [S1][S6, unofficial]. More recently, methods like ZFP have gained traction in HPC for fixed-rate floating-point compression [S2], while GPU-specific formats address the specific constraints of real-time raycasting [S1]. The field continues to integrate optimized data structures for web-based visualization [S3, unofficial].
