# TT4D GPU Decoder and Renderer

Also called: GPU-based TT decoding, GPU-based partial preprocessing, On-the-fly adaptive reconstruction, On-the-fly decoding scheme

## Overview
TT4D is a GPU-based, on-the-fly decoding and rendering scheme for 4D time-varying volume data that avoids reconstructing the entire volume to support interactive visualization [S1][S2, unofficial]. It distinguishes itself from standard Tensor-Train (TT) reconstruction by employing efficient partial preprocessing and adaptive multiresolution strategies, enabling random-access decompression and interactive filtering at rates prohibitively slow for standard implementations [S1][S2, unofficial]. Unlike non-tensor-based compressors, it leverages the linear nature of TT cores for quick spatio-temporal data selection in the compressed domain [S1][S2, unofficial].

## How it works
The method consists of a compression phase (using Sequential SVD with subsampling) and a GPU-based decoding/rendering phase. The decoder reconstructs data fully based on multilinear transformations (matrix and tensor products), allowing slicing or linear filtering operations at interactive rates without decompressing the complete 4D dataset [S1][S2, unofficial].

### Inputs and Outputs
*   **Input:** Compressed 4D volume data in Tensor-Train format (cores $G^{(1)}, \dots, G^{(4)}$) and a target time step $t$.
*   **Output:** Rendered image or sliced volume data for the specified time step, potentially at reduced resolution.

### Data Structures
The 4D volume $V \in \mathbb{R}^{N_1 \times N_2 \times N_3 \times N_4}$ is represented by TT cores $G^{(k)} \in \mathbb{R}^{r_{k-1} \times n_k \times r_k}$ for $k=1,\dots,4$, where $r_k$ are the TT-ranks and $n_k$ are the mode sizes [S1][S2, unofficial].
*   **TT Cores:** Stored on the GPU. The decomposition uses Sequential SVD (SSVD) with efficient subsampling to avoid full-scale tensor reshaping and SVD computations on large imbalanced matrices [S1][S2, unofficial].
*   **Preprocessed Data:** Partially preprocessed cores or intermediate products stored on the GPU to reduce computational load for decoding arbitrary time steps [S1][S2, unofficial].

### Steps
1.  **Partial Preprocessing:** Perform efficient partial preprocessing of the compressed TT data on the GPU. This step reduces the computational load for decoding arbitrary time steps interactively [S1][S2, unofficial].
2.  **Adaptive Multiresolution Selection:** Determine the required resolution based on user interaction (e.g., subsampling factor). The strategy decodes data partially as needed to speed up rendering during heavy user interactions [S1][S2, unofficial].
3.  **On-the-Fly Reconstruction:** Reconstruct the data for the target time step $t$ using multilinear transformations.
    *   The reconstruction is fully based on matrix and tensor products [S1][S2, unofficial].
    *   For a specific time step $t$, the 4D tensor is contracted along the time dimension (mode 4) to yield a 3D spatial volume.
    *   Let $G^{(4)}_t$ be the slice of the 4th core at time $t$. The 3D volume $V_t$ is computed as:
        $$ V_t = \text{reshape}\left( G^{(1)} \times_2 G^{(2)} \times_2 G^{(3)} \times_2 G^{(4)}_t \right) $$
        where $\times_2$ denotes the mode-2 product (matrix multiplication along the second dimension of the core) [S1][S2, unofficial].
    *   *Note:* The exact contraction order and GPU kernel implementation for these multilinear transformations are not specified in the sources [G].
4.  **Rendering/Filtering:** Apply slicing or linear filtering operations directly to the reconstructed or partially reconstructed data at interactive rates [S1][S2, unofficial].

### Parameters
*   **Subsampling Factor:** Used for adaptive multiresolution rendering (e.g., 1:8 subsampling) [S2, unofficial].
*   **TT Ranks ($r_k$):** Determined during the compression phase via SSVD with subsampling [S1][S2, unofficial].

### Edge Cases and Pitfalls
*   **Standard TT Reconstruction Speed:** Standard TT reconstruction is prohibitively slow for interactive visualization of large time-varying volume data due to multiple tensor-tensor multiplications, especially for non-sequential or rapidly changing access patterns [S1][S2, unofficial].
*   **Memory Consumption:** Full-scale tensor reshaping and SVD computations on large imbalanced matrices during decomposition must be avoided to prevent excessive memory consumption [S1][S2, unofficial].

### Pseudocode
```python
# GPU-based TT Decoder for 4D Volume
# Inputs:
#   cores: List of 4 TT cores [G1, G2, G3, G4] on GPU
#   t: Target time step index
#   subsample_factor: Integer, e.g., 8 for 1:8 subsampling

def decode_and_render(cores, t, subsample_factor):
    # Step 1: Extract time slice from the 4th core
    # G4 is shape [r3, N4, r4]
    G4_t = cores[3][t, :, :]  # Shape [r3, r4]
    
    # Step 2: Partial Preprocessing (Conceptual)
    # The sources mention "efficient partial preprocessing" but do not specify the exact algorithm.
    # This step likely involves pre-computing products of spatial cores or optimizing the contraction order.
    # [G] Implementation detail: Precompute spatial contractions if multiple time steps are accessed frequently.
    
    # Step 3: Multilinear Reconstruction for Time Step t
    # Contract G1, G2, G3, and G4_t
    # G1: [1, N1, r1], G2: [r1, N2, r2], G3: [r2, N3, r3]
    
    # Contract G1 and G2: Result shape [1, N1, r2]
    temp1 = matmul(G1, G2) 
    
    # Contract temp1 and G3: Result shape [1, N1*N2, r3] (flattened spatial dims)
    temp2 = matmul(temp1, G3)
    
    # Contract temp2 and G4_t: Result shape [1, N1*N2*N3, r4]
    # This yields the full 3D volume tensor in TT-vector form for time t
    volume_tensor = matmul(temp2, G4_t)
    
    # Reshape to 3D volume [N1, N2, N3]
    # [G] The exact reshape logic depends on the memory layout of the cores.
    volume_3d = reshape(volume_tensor, (N1, N2, N3))
    
    # Step 4: Adaptive Multiresolution Subsampling
    if subsample_factor > 1:
        # Downsample the volume for faster rendering
        volume_render = subsample(volume_3d, subsample_factor)
    else:
        volume_render = volume_3d
        
    # Step 5: Render
    # Apply direct volume rendering or slicing to volume_render
    image = render(volume_render)
    
    return image
```

## Subtopics

### Sequential SVD with Subsampling
A decomposition method used in the compression phase of TT4D. It avoids full-scale tensor reshaping and SVD computations on large imbalanced matrices to speed up computation and reduce memory consumption [S1][S2, unofficial].

### Adaptive Multiresolution Rendering
A strategy integrated into TT4D to speed up rendering during heavy user interactions by decoding data partially as needed [S1][S2, unofficial].

## Operating characteristics
*   **Performance:** On a 4D turbulence dataset of size $(512^3 \times 64)$ compressed with a ratio of 1:290:
    *   Full resolution reconstruction at $t=1$ takes 70ms [S2, unofficial].
    *   1:8 subsampled rendering at $t=21$ takes 11ms [S2, unofficial].
    *   1:8 subsampled rendering at $t=42$ takes 9ms [S2, unofficial].
    *   Full resolution reconstruction at $t=63$ takes 37ms [S2, unofficial].
*   **Scalability:** TT4D outperforms other transform-based compressors at random-access decompression across datasets up to 64GB at equivalent error levels [S1][S2, unofficial].
*   **Strengths:** Enables real-time rendering capabilities with interactive filtering and data selection; allows rendering data originally larger than available GPU memory by avoiding full decompression [S1][S2, unofficial].
*   **Limitations:** Prioritizes real-time exploration, random access, and scalability over highest-accuracy reconstruction [S1][S2, unofficial]. Standard TT reconstruction is too slow for interactive use without the proposed optimizations [S1][S2, unofficial].

## Background
TT4D was introduced by Clara Hartmann, Rafael Ballester-Ripoll, and Renato Pajarola from the University of Zurich and IE University [S2, unofficial]. The method is based on the Sequential SVD (SSVD) TT decomposition method [Ose11] [S1][S2, unofficial]. It is designed for interactive visualization of high-resolution, time-varying volume data, such as in bio-medical applications [S1].
