# Zerobit Encoding Scheme

Also called: Enhanced Encoding Scheme

## Overview
The Zerobit Encoding Scheme is a compression method for wavelet-transformed volume data that improves compression ratio and random access speed by exploiting spatial coherence in coefficient clusters [S1, unofficial]. It modifies the cell tag table to indicate whether the coefficient vector $c_0$ is zero and uses a variable-length significance map based on "zerobits" to avoid storing positional information for nodes where all detail coefficients are zero [S1, unofficial]. Unlike previous schemes that used fixed-size significance maps, this method reduces storage waste for zero-valued coefficients while maintaining fast, direct access to individual coefficients [S1, unofficial].

## How it works
**Inputs and Outputs:** Input is a 16x16x16 unit block of wavelet coefficients; output is a compressed bitstream containing cell tags, cell information blocks, and byte streams [S1, unofficial].

**Data Structures and Layout:**
*   **Cell Tag Table:** One byte per cell; cells are enumerated front-to-back, top-to-bottom, left-to-right [S1, unofficial].
    *   **Tag Value 0:** Indicates the cell contains all zero coefficients [S1, unofficial].
    *   **Tag Value > 0:** Indicates the cell contains non-zero coefficients; the value is the index into the Cell Information array [S1, unofficial].
    *   **Bit 0 (Left-most):** Zerobit for the root node (Level 0) [S1, unofficial]. If 0, all 7 detail coefficients of the root are zero [S1, unofficial].
    *   **Bit 1:** Adjacent to Bit 0 [S1, unofficial]. For CT data, it is the bytetag for coefficient $c_0$ [S1, unofficial]. For RGB data, it indicates whether the $c_0$ vector $(r,g,b)$ is $(0,0,0)$ [S1, unofficial].
*   **Cell Information:** Stored in one-byte blocks, indexed by the positive tag value from the Cell Tag Table [S1, unofficial].
    *   **Zerobits (Level 1):** The first byte contains 8 bits representing the zerobits for the 8 nodes at Level 1 of the octree [S1, unofficial]. If a zerobit is 0, the corresponding Level 1 node has all zero detail coefficients [S1, unofficial].
    *   **Significance Map:** Variable-length array of bytes following the zerobits byte [S1, unofficial]. Length equals the number of zerobits with value 1 (maximum 9 bytes) [S1, unofficial]. Each byte corresponds to a node with a zerobit of 1 [S1, unofficial]. Bits 1-7 are significance flags for the 7 detail coefficients; if 1, the coefficient is non-zero and stored in a data stream [S1, unofficial]. Bit 0 (Left-most) is the two-byte flag; if 0, at least one coefficient in this node is stored in the two-byte stream [S1, unofficial].
*   **Bytetag:** A single byte used to track which specific detail coefficients (among those with significance flag 1) are stored in the two-byte stream; a value of 1 means the corresponding detail coefficient is stored in the two-byte stream [S1, unofficial].
*   **Byte Streams:** Two streams per cell (one-byte stream and two-byte stream), each maintaining an offset value within the cell information to locate coefficients [S1, unofficial].
*   **Indexing Table T(*):** A precomputed table with $2^8 = 256$ entries; given a one-byte word (8 bit flags), it returns the number of bit 1s in the byte [S1, unofficial].

**Encoding Steps:**
1.  Enumerate cells front-to-back, top-to-bottom, left-to-right [S1, unofficial].
2.  Tag cells with 0 if all coefficients are zero, or with positive integers if they contain non-zero coefficients [S1, unofficial].
3.  Determine the zerobit for each of the 9 nodes in the cell's octree [S1, unofficial]. If a node's zerobit is 0, all 7 detail coefficients are zero; no significance map is needed for that node [S1, unofficial].
4.  Store the significance map only for nodes with zerobit 1; the number of bytes in the significance map equals the number of zerobits with value 1 (up to 9 bytes) [S1, unofficial].
5.  For each byte in the significance map, use the left-most bit to flag if any coefficient in that node is stored in two bytes; if so, update the bytetag to mark which specific coefficients are two-byte [S1, unofficial].
6.  Store coefficient $c_0$; for CT data, it is always stored in the one-byte stream (even if zero) [S1, unofficial]. For RGB data, $c_0$ is a 3-component vector $(r,g,b)$ stored in a three-byte stream, and the adjacent bit in the cell tag indicates if it is $(0,0,0)$ [S1, unofficial].
7.  Store detail coefficients; coefficients with significance flag 1 are stored in either one-byte or two-byte streams based on the two-byte flag in the significance map and the bytetag [S1, unofficial].

**Decoding Pseudocode:**
```python
def decode_coefficient(unit_block, i, j, k):
    # Find the cell C containing the coefficient (i, j, k)
    C = find_cell(unit_block, i, j, k)
    # Case 1: If the cell tag is 0, the coefficient is 0
    if C.tag == 0:
        return 0
    # Compute the local index (i', j', k') in C
    i_prime, j_prime, k_prime = compute_local_index(C, i, j, k)
    # Case 2: If the zerobit for the coefficient's index within the cell is 0, the coefficient is 0
    if C.zerobit_level0 == 0:
        return 0
    # Get the significance map byte for the node containing (i', j', k')
    sig_byte = get_significance_map_byte(C, i_prime, j_prime, k_prime)
    # Case 3: If the bit-flag in the significance map for the coefficient's index is 0, the coefficient is 0
    if (sig_byte & 0x7E) == 0:
        return 0
    # Case 4: Calculate the address in the byte stream
    # Count the number of preceding non-zero coefficients by table access
    displacement = 0
    for byte in C.significance_map:
        displacement += T(byte)
    # Add the displacement to the cell's offset value
    address = C.offset + displacement
    # Access the appropriate data stream, and return the value
    stream = get_stream(C, i_prime, j_prime, k_prime)
    return stream[address]
```

**Parameters and Typical Values:**
*   **Zerobit Ratio:** The ratio of nodes where all 7 detail coefficients are zero [S1, unofficial].
    *   CT Data at 3.0% desired ratio: Level 0 zerobit ratio = 0.230; Level 1 zerobit ratio = 0.949 [S1, unofficial].
    *   RGB Data at 1.0% desired ratio: Level 0 zerobit ratio = 0.754; Level 1 zerobit ratio = 0.993 [S1, unofficial].
*   **Data Types:** CT data coefficients typically fit in one-byte or two-byte streams [S1, unofficial]. RGB data $c_0$ components range [0, 255] (unsigned char) and detail components range [-128, 127] (signed char), requiring three-byte streams [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **CT Data $c_0$ Storage:** In CT data, $c_0$ is stored in the one-byte stream even if its value is zero, which is an unnecessary storage overhead but considered acceptable because $c_0$ being zero often implies the cell is null [S1, unofficial].
*   **RGB Data $c_0$:** The bit adjacent to the Level 0 zerobit in the Cell Tag Table is repurposed to indicate if $c_0=(0,0,0)$, reducing waste compared to the CT bytetag approach [S1, unofficial].
*   **Two-Byte Stream Flag:** The left-most bit of the significance map byte is repurposed from unused space to indicate the existence of two-byte coefficients; a value of 0 indicates existence [S1, unofficial].

## Operating characteristics
*   **Time and Memory Complexity:** Decoding a single coefficient requires constant-time cell lookup, bit checks, and a linear scan of the significance map bytes proportional to the number of nodes (max 9) [S1, unofficial]. Memory usage is dominated by the Cell Tag Table, Cell Information blocks, and the two byte streams per cell [S1, unofficial].
*   **Measured Performance:** Compared to previous schemes using fixed 8-byte significance maps, this method uses a variable-length significance map that averages less than 8 bytes for non-null cells, improving the compression ratio [S1, unofficial].
*   **Scaling:** The method scales with the number of cells in the 16x16x16 unit block; spatial coherence ensures that as the desired coefficient ratio decreases, the Level 1 zerobit ratio increases significantly, further reducing map size [S1, unofficial].
*   **Strengths and Limitations:** Supports fast random access and high compression ratio without image quality loss compared to prior methods [S1, unofficial]. Limitations include slightly more complex decoding logic due to variable-length maps and two-byte stream flags, plus minor overhead from storing zero $c_0$ values in CT data [S1, unofficial].
*   **When to Use:** Ideal for interactive visualization systems requiring fast random access to sparse wavelet coefficients [S1, unofficial]. Not recommended when hardware lacks efficient bitwise operations or when coefficient sparsity is consistently low [S1, unofficial].

## Background
The Zerobit Encoding Scheme (also called Enhanced Encoding Scheme) was proposed to address the trade-off between compression ratio, reconstruction speed, and image quality in interactive volume visualization systems [S1, unofficial]. It builds on previous wavelet-based compression methods by exploiting the spatial coherence of wavelet coefficients, where null coefficients often form thick clusters [S1, unofficial]. The scheme modifies existing cell tag and significance map structures to skip decoding for zero-valued nodes, enabling direct coefficient retrieval without full block reconstruction [S1, unofficial].
