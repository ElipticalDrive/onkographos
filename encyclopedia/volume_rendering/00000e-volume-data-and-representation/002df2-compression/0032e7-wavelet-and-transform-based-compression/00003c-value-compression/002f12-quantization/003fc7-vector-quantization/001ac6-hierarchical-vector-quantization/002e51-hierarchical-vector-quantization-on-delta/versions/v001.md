# Hierarchical Vector Quantization on Delta

Also called: HVQ on Delta

## Overview
Hierarchical Vector Quantization on Delta is a compression method for time-varying volumetric data that combines temporal delta encoding with hierarchical vector quantization (HVQ) [S1]. It solves the problem of efficiently storing and rendering large dynamic volume datasets by exploiting temporal coherence between adjacent frames. Unlike static HVQ which encodes spatial redundancy, this variant first computes the difference (delta) between consecutive time steps, then applies HVQ to these residuals, resulting in smaller quantization ranges and higher compression ratios for smooth temporal transitions [S1].

## How it works
**Inputs and Outputs:**
- Input: A sequence of volumetric data frames $V_t$ for $t = 0, \dots, T-1$.
- Output: A compressed bitstream representing the delta-encoded residuals quantized via HVQ.

**Data Structures:**
The method operates on blocks or bricks of voxels. For each time step $t$, the data is partitioned into spatial blocks. The core data structure is the residual block $R_t$, defined as the difference between the current frame's block and the previous frame's block.

**Steps:**
1. **Delta Encoding:** For each time step $t > 0$, compute the residual volume $R_t$ by subtracting the voxel values of the previous frame $V_{t-1}$ from the current frame $V_t$. For the first frame $t=0$, $R_0 = V_0$.
   $$ R_t(x,y,z) = V_t(x,y,z) - V_{t-1}(x,y,z) $$
   where $(x,y,z)$ are voxel coordinates [S1].

2. **HVQ Quantization:** Apply Hierarchical Vector Quantization to the residual blocks $R_t$. This involves:
   - Partitioning the residual data into vectors (blocks of voxels).
   - Using a hierarchical codebook structure to quantize these vectors. The codebook is trained on the residual data to minimize quantization error.
   - Assigning a bit count per voxel based on the range of data inside the brick, allowing variable precision [S1].

3. **Entropy Coding:** Encode the quantized indices and side information using a lossless compression algorithm, such as LZO, to further reduce the bitstream size [S1].

**Parameters:**
- Block size for HVQ: Not given in the sources.
- LZO compression level: Not given in the sources.

**Edge Cases and Pitfalls:**
- Large temporal changes between frames result in large residuals, reducing the effectiveness of delta encoding.
- Precision loss in delta subtraction may accumulate if not handled carefully, though HVQ quantization mitigates this by focusing on the residual range.

## Operating characteristics
- **Time Complexity:** Depends on the HVQ quantization and LZO compression. HVQ quantization is typically $O(N)$ where $N$ is the number of voxels, assuming a fixed codebook size. LZO compression is linear in the size of the input data.
- **Memory Complexity:** Requires storing the codebook for HVQ and the compressed bitstream. The codebook size depends on the number of codewords and their dimensionality.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales well with the number of frames due to the efficiency of delta encoding for temporally coherent data.
- **Strengths:** High compression ratios for smooth temporal changes; leverages existing HVQ infrastructure.
- **Limitations:** Less effective for data with large temporal discontinuities; requires training a codebook on residual data.
- **When to use:** Suitable for time-varying volumetric data with high temporal coherence, such as fluid simulations or medical imaging sequences.
- **When not to use:** Not suitable for data with frequent, large temporal changes or non-temporal redundancy.

## Background
The method was proposed by She et al. [SBN11] as part of a broader survey on compressed GPU-based direct volume rendering [S1]. It builds on the idea of using delta encoding to exploit temporal redundancy, combined with HVQ for efficient spatial quantization. This approach is part of the evolution of wavelet and transform-based compression techniques for volume data, which have been frequently applied to time-varying volumes [S1].
