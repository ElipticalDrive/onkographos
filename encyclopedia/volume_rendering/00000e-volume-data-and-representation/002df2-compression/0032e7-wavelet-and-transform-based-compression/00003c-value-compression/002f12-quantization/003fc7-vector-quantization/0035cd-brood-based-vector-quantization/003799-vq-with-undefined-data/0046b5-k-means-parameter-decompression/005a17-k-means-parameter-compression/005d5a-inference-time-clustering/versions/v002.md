# Inference-Time Clustering

Also called: K-Means Token Merging, Token Clustering, Spherical K-Means Clustering, complexity-weighted initialization clustering, k-means on geometry tokens, k-means token clustering, strided initialization clustering

## Overview
Inference-Time Clustering is a token compression technique that groups geometry tokens into clusters via k-means and merges each cluster into a single scene token, reducing the Gaussian budget while preserving cross-view consistency [S1, unofficial]. It solves the problem of redundant information in multi-view inputs by allowing adjustable compression at inference without retraining [S1, unofficial]. It sets itself apart from static compression methods by dynamically determining the cluster count based on a runtime compression ratio, and from simple nearest-neighbor merging by using iterative spherical k-means to refine cluster centers in cosine space [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A set of $N$ views, each containing $T$ patches. Each patch $i$ has an associated geometry token $g_i \in \mathbb{R}^d$ (typically normalized).
- **Output:** $K$ scene tokens (centroids) $z_k$ and their associated supporting observations (member patches).

**Data Structures:**
- **Geometry Tokens:** A list of vectors $g_i$.
- **Clusters:** A mapping from cluster index $k \in \{0, \dots, K-1\}$ to a set of member indices $C_k$.
- **Centroids:** Vectors $z_k$ representing the mean geometry of cluster $C_k$.

**Parameters:**
- **Compression Ratio ($r$):** Determines the target number of clusters $K$. $r \in (0, 1]$.
- **Number of Views ($N$):** Total input views.
- **Patches per View ($T$):** Number of patches per view.
- **Max Iterations:** Capped at 50 [S1, unofficial].

**Formulas:**
The number of clusters $K$ is derived from the compression ratio:
$$ K = \lceil r \cdot N \cdot T \rceil $$
The compression ratio is defined as:
$$ r = \frac{K}{N \cdot T}, \quad r \in (0, 1] \quad \text{[S1, unofficial]} $$
During training, $r$ is sampled uniformly from $[r_{min}, 1]$ where $r_{min} = 0.2/N$, ensuring a minimum budget of approximately 2K Gaussians (or at least ~65 scene tokens) [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    -   Compute a complexity score $c_i$ for each patch $i$ based on mean image-gradient energy. Rank patches by this score within the scene [S1, unofficial].
    -   Sample $K$ initial seeds without replacement. The probability of selecting patch $i$ as a seed is proportional to $(0.05 + c_i)^2$ [S1, unofficial].
    -   *Alternative:* Use a strided grid pattern for initialization [S1, unofficial].

2.  **Spherical K-Means Iteration:**
    -   **Assignment:** For each token $g_i$, assign it to the cluster $k$ whose centroid $z_k$ has the highest cosine similarity (or lowest cosine distance). This is equivalent to Euclidean distance on $\ell_2$-normalized vectors [S1, unofficial].
    -   **Update:** Recompute each centroid $z_k$ as the mean of its assigned members:
        $$ z_k = \frac{1}{|C_k|} \sum_{i \in C_k} g_i $$
    -   **Renormalization:** Renormalize $z_k$ to unit length after each update [S1, unofficial].
    -   **Differentiability:** Assignments remain discrete (hard assignment), but gradients propagate through the cluster means $z_k$ during training [S1, unofficial].
    -   Repeat until convergence or max iterations (50) reached. Convergence typically takes 2–3 iterations at $r=0.5$ and 7–9 at $r=0.1$ [S1, unofficial].

3.  **Token Fusion (Merging):**
    -   Merge all tokens assigned to cluster $C_k$ into a single scene token $z_k$.
    -   The merged scene token inherits the patches of all its members as supporting observations.
    -   *Note:* Skipping the merge step and keeping only the seed tokens degrades quality significantly (loss of 1.8 dB at $r=0.25$ and 5.7 dB at $r=0.1$) [S1, unofficial].

**Pseudocode:**

```python
import numpy as np

def inference_time_clustering(geometry_tokens, num_views, patches_per_view, compression_ratio):
    """
    geometry_tokens: np.ndarray of shape (N * T, D)
    num_views: int N
    patches_per_view: int T
    compression_ratio: float r
    """
    N = num_views
    T = patches_per_view
    total_tokens = N * T
    
    # Calculate number of clusters K
    K = int(np.ceil(compression_ratio * total_tokens))
    
    # Step 1: Initialization
    # Compute complexity scores (placeholder for gradient energy calculation)
    # c_i is rank of patch i by mean image-gradient energy, normalized to [0, 1]
    complexity_scores = compute_gradient_energy_scores(geometry_tokens) 
    # Normalize scores to [0, 1]
    c = (complexity_scores - complexity_scores.min()) / (complexity_scores.max() - complexity_scores.min() + 1e-8)
    
    # Sample seeds without replacement with probability proportional to (0.05 + c_i)^2
    probs = (0.05 + c) ** 2
    probs = probs / probs.sum()
    seed_indices = np.random.choice(total_tokens, size=K, replace=False, p=probs)
    
    # Initialize centroids as the mean of their initial members (initially just the seed itself)
    # Or simply use the seed tokens as initial centroids
    centroids = geometry_tokens[seed_indices].copy()
    
    # Normalize centroids for spherical k-means
    centroids = centroids / (np.linalg.norm(centroids, axis=1, keepdims=True) + 1e-8)
    
    # Step 2: Spherical K-Means
    assignments = np.zeros(total_tokens, dtype=int)
    max_iter = 50
    
    for iteration in range(max_iter):
        # Assignment: Cosine similarity on normalized vectors
        # Similarity = dot product of normalized token and normalized centroid
        similarities = np.dot(geometry_tokens, centroids.T)
        assignments = np.argmax(similarities, axis=1)
        
        # Update: Recompute centroids as mean of members
        new_centroids = np.zeros_like(centroids)
        for k in range(K):
            members = geometry_tokens[assignments == k]
            if len(members) > 0:
                new_centroids[k] = members.mean(axis=0)
            else:
                # Handle empty cluster: keep old centroid or reinitialize [G]
                new_centroids[k] = centroids[k]
        
        # Renormalize centroids
        norms = np.linalg.norm(new_centroids, axis=1, keepdims=True)
        centroids = new_centroids / (norms + 1e-8)
        
        # Check convergence [G]
        if np.allclose(centroids, new_centroids, atol=1e-6):
            break
            
    # Step 3: Token Fusion
    # The final centroids z_k are the scene tokens
    # The assignments define the clusters C_k
    return centroids, assignments

def compute_gradient_energy_scores(tokens):
    """
    Placeholder for computing per-scene rank of patch i by mean image-gradient energy.
    In practice, this requires access to the image gradients from the backbone network.
    """
    # [G] Assuming tokens are related to image features, we might use feature variance or norm as proxy
    # if gradients are not directly available in this function scope.
    return np.linalg.norm(tokens, axis=1)
```

## Subtopics

### [K-Means++ Initialization](18746-k-means-initialization.md)
K-Means++ Initialization is a strategy for selecting initial cluster centers in k-means clustering that ensures the centers are relatively spread out across the data space. It addresses the problem that standard random initialization can lead to exponential runtime and locally optimal solutions far from the global optimum. By selecting subsequent centers with probability proportional to their squared distance from existing centers, it improves theoretical guarantees for both efficiency and clustering quality.

## Operating characteristics
- **Time Complexity:** The cost of k-means scales with $Tokens \times Clusters \times Iterations$. At 192 views with $r=0.5$, k-means iterations add 4.2 s over full capacity, making it the dominant overhead at high view counts [S1, unofficial]. At 128 views, k-means needs 17–45 iterations to converge, costing 1.9 s at 524K Gaussians [S1, unofficial].
- **Memory Complexity:** Reduces Gaussian memory footprint by storing only $K$ centroids and labels instead of $N \cdot T$ tokens. At $r=0.5$, storage is halved [S1, unofficial].
- **Performance:** At $r=0.1$ and 6 views, 91% of geometry token clusters span at least two input views, matching the cross-view consistency of clustering ground-truth 3D points directly [S1, unofficial].
- **Strengths:** Allows adjustable compression at inference without retraining. Preserves cross-view consistency better than clustering in other spaces (e.g., backbone tokens, patch colors) [S1, unofficial].
- **Limitations:** High compression (e.g., 20×, $r=0.05$) fails to fully recover thin structures and grass, which require over 8K Gaussians even with TokenBA refinement [S1, unofficial]. The clustering space choice dominates quality: geometry tokens outperform backbone tokens (-0.7 dB), patch colors (-3.7 dB), image positions (-1.0 dB), and even ground-truth 3D points (-0.1 dB) at $r=0.1$ [S1, unofficial].
- **When to use:** When memory or bandwidth is constrained, and cross-view consistency is important.
- **When not to use:** When rendering fine, thin structures at very high compression ratios ($r < 0.1$) [S1, unofficial].

## Background
Inference-Time Clustering was introduced in the ZipSplat paper [S1, unofficial]. It builds on the idea that many patches observe the same surface from different viewpoints, carrying redundant information that can be merged. The method was evaluated on DL3DV and RealEstate10K datasets [S1, unofficial].
