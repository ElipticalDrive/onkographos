# K-means Parameter Compression

Also called: K-means clustering compression, torchpq K-means

## Overview
K-means Parameter Compression reduces the memory footprint of Gaussian Splatting parameters by clustering high-dimensional feature vectors into a fixed set of centroids using K-means clustering, then storing only the cluster labels and quantized centroid values [S1, unofficial]. It differs from scalar quantization by exploiting correlations between parameter dimensions through vector quantization, and from lossless compression by accepting reconstruction error in exchange for significant size reduction [S1, unofficial].

## How it works
**Inputs:** A parameter tensor of shape $(N, D)$, where $N$ is the number of elements (e.g., Gaussians) and $D$ is the dimensionality of each element's parameter vector.
**Outputs:** A compressed archive containing quantized centroids, cluster labels, and metadata; a decompression function to reconstruct the original tensor.

**Data Structures:**
1.  **Centroids:** A tensor of shape $(D, K)$, where $K$ is the number of clusters. Stored as `uint8` after quantization.
2.  **Labels:** A tensor of shape $(N,)$, storing the index of the closest centroid for each input element. Stored as `uint16`.
3.  **Metadata:** A dictionary containing:
    *   `shape`: Original tensor shape $(N, D)$.
    *   `dtype`: Original data type.
    *   `mins`: Array of shape $(D,)$ containing the minimum value per dimension across all centroids.
    *   `maxs`: Array of shape $(D,)$ containing the maximum value per dimension across all centroids.
    *   `quantization`: Number of bits used for centroid quantization (default 6).

**Parameters:**
*   `n_clusters`: Number of K-means clusters. Default: 65536 [S1, unofficial].
*   `quantization`: Number of bits for centroid quantization. Default: 6 [S1, unofficial].
*   `distance`: Distance metric for K-means. Default: 'manhattan' [S1, unofficial].

**Algorithm Steps:**

1.  **Preprocessing:**
    Reshape the input parameter tensor $P$ of shape $(N, D)$ into a 2D tensor $X$ of shape $(N, D)$. Ensure the tensor is contiguous in memory [S1, unofficial].

2.  **Clustering:**
    Fit a K-means model on $X$ with $K$ clusters using the Manhattan distance. Obtain the cluster labels $L \in \{0, \dots, K-1\}^N$ and the centroid matrix $C_{raw} \in \mathbb{R}^{D \times K}$ [S1, unofficial].

3.  **Centroid Normalization:**
    Compute the per-dimension minimum and maximum values across all centroids:
    $$ mins_d = \min_{k} C_{raw}[d, k] $$
    $$ maxs_d = \max_{k} C_{raw}[d, k] $$
    Normalize the centroids to the range $[0, 1]$:
    $$ C_{norm}[d, k] = \frac{C_{raw}[d, k] - mins_d}{maxs_d - mins_d} $$
    Handle degenerate cases where $maxs_d = mins_d$ by setting the denominator to 1 or the normalized value to 0 [G].

4.  **Quantization:**
    Quantize the normalized centroids to `uint8` using $B$ bits:
    $$ C_{quant}[d, k] = \text{round}\left( C_{norm}[d, k] \times (2^B - 1) \right) $$
    Cast the result to `uint8` [S1, unofficial].

5.  **Label Conversion:**
    Convert the cluster labels $L$ to `uint16` to support up to 65536 clusters [S1, unofficial].

6.  **Storage:**
    Save $C_{quant}$, $L$, and the metadata dictionary to a compressed NPZ file [S1, unofficial].

**Decompression Steps:**

1.  **Load Data:**
    Retrieve $C_{quant}$, $L$, and metadata from the NPZ file [S1, unofficial].

2.  **Dequantization:**
    Convert `uint8` centroids back to float32 normalized values:
    $$ C_{norm\_rec}[d, k] = \frac{C_{quant}[d, k]}{2^B - 1} $$

3.  **Denormalization:**
    Recover the raw centroid values:
    $$ C_{rec}[d, k] = C_{norm\_rec}[d, k] \times (maxs_d - mins_d) + mins_d $$

4.  **Reconstruction:**
    Map labels to centroids:
    $$ P_{rec}[n] = C_{rec}[:, L[n]] $$
    Reshape $P_{rec}$ to the original shape $(N, D)$ and cast to the original `dtype` [S1, unofficial].

**Pseudocode:**

```python
import numpy as np
from torchpq.clustering import KMeans

def kmeans_compress(params, n_clusters=65536, quantization_bits=6):
    """
    Compress parameter tensor using K-means clustering.
    
    Args:
        params: Tensor of shape (N, D)
        n_clusters: Number of clusters
        quantization_bits: Bits for centroid quantization
        
    Returns:
        centroids_quant: uint8 array of shape (D, K)
        labels: uint16 array of shape (N,)
        metadata: dict with shape, dtype, mins, maxs, quantization
    """
    # 1. Preprocessing
    # Ensure contiguous and correct shape
    x = params.reshape(params.shape[0], -1).contiguous()
    # Permute to match torchpq expectation if necessary, though torchpq usually expects (N, D)
    # The source notes mention permute to (-1, params.shape[0]), which implies transposing if input was (D, N)
    # Assuming standard (N, D) input, we use x directly. 
    # Note: Source says "permute to (-1, params.shape[0])". If params is (N, D), this makes it (D, N).
    # K-means typically takes (N, D). We assume the source code handles this transposition internally or 
    # the input is expected in a specific layout. We follow the source's reshape/permute logic strictly.
    x = x.permute(1, 0).contiguous() # Shape (D, N) -> (N, D) if we view it as samples? 
    # Actually, torchpq KMeans expects (N, D). The source note "permute to (-1, params.shape[0])" 
    # on a tensor of shape (N, D) results in (D, N). This suggests the source might be treating 
    # dimensions differently or there's a specific layout requirement. 
    # However, standard K-means is (N, D). Let's assume the source code's `x` is the input to KMeans.
    
    # 2. Clustering
    kmeans = KMeans(n_clusters=n_clusters, distance='manhattan', verbose=False)
    labels = kmeans.fit(x)
    
    # Extract centroids
    centroids = kmeans.centroids
    # Source says permute to (-1, n_clusters). If centroids are (D, K), this is (D, K).
    centroids_np = centroids.permute(1, 0).cpu().numpy() # Shape (K, D) -> (D, K) if we transpose?
    # Let's stick to the source's extraction: "permute to (-1, n_clusters)"
    # If centroids are (D, K), permute(1,0) is (K, D). 
    # The source says "permute to (-1, n_clusters)". 
    # Let's assume centroids are stored as (D, K) in the object.
    
    # 3. Normalization
    mins = centroids_np.min(axis=1) # Min per dimension (axis 0 of D, axis 1 of K? No, axis 1 is K)
    # If shape is (D, K), min over K is axis 1.
    mins = centroids_np.min(axis=1)
    maxs = centroids_np.max(axis=1)
    
    # Handle division by zero
    denom = maxs - mins
    denom[denom == 0] = 1.0
    
    centroids_norm = (centroids_np - mins[:, np.newaxis]) / denom[:, np.newaxis]
    
    # 4. Quantization
    scale = (2 ** quantization_bits) - 1
    centroids_quant = np.round(centroids_norm * scale).astype(np.uint8)
    
    # 5. Labels
    labels_uint16 = labels.cpu().numpy().astype(np.uint16)
    
    # 6. Metadata
    metadata = {
        'shape': params.shape,
        'dtype': params.dtype,
        'mins': mins,
        'maxs': maxs,
        'quantization': quantization_bits
    }
    
    return centroids_quant, labels_uint16, metadata

def kmeans_decompress(centroids_quant, labels, metadata):
    """
    Decompress K-means compressed parameters.
    """
    mins = metadata['mins']
    maxs = metadata['maxs']
    quantization_bits = metadata['quantization']
    original_shape = metadata['shape']
    original_dtype = metadata['dtype']
    
    scale = (2 ** quantization_bits) - 1
    
    # 1. Dequantization
    centroids_norm = centroids_quant.astype(np.float32) / scale
    
    # 2. Denormalization
    centroids = centroids_norm * (maxs[:, np.newaxis] - mins[:, np.newaxis]) + mins[:, np.newaxis]
    
    # 3. Reconstruction
    # labels is (N,), centroids is (D, K)
    # We need to gather centroids based on labels
    # labels[n] gives the index k for sample n
    # We want result[n] = centroids[:, k]
    # This is equivalent to centroids[:, labels]
    params_rec = centroids[:, labels]
    
    # Reshape to original shape
    params_rec = params_rec.reshape(original_shape)
    
    return params_rec.astype(original_dtype)
```

**Edge Cases and Pitfalls:**
*   **Zero Variance:** If a dimension has identical values across all centroids ($maxs_d = mins_d$), the normalization denominator becomes zero. The implementation must handle this by setting the normalized value to 0 or 0.5, or skipping quantization for that dimension [G].
*   **Cluster Empty:** If a cluster receives no points, its centroid may remain at its initialization value, potentially causing bias. K-means implementations often reinitialize empty clusters [G].
*   **Precision Loss:** Quantizing to 6 bits introduces significant error. The choice of `quantization_bits` trades off memory size for reconstruction fidelity [S1, unofficial].
*   **Memory Usage:** Storing centroids as `uint8` and labels as `uint16` is efficient, but the initial K-means fitting requires loading the full float32 tensor into memory [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The compression step is dominated by K-means clustering, which is $O(N \cdot D \cdot K \cdot I)$, where $I$ is the number of iterations. Decompression is $O(N)$ due to the lookup table operation [S1, unofficial].
*   **Memory Complexity:** The compressed size is $O(D \cdot K \cdot 1 \text{ byte} + N \cdot 2 \text{ bytes})$. For $N=10^6, D=10, K=65536$, this is approximately $6.4 \text{ MB} + 2 \text{ MB} = 8.4 \text{ MB}$, compared to $40 \text{ MB}$ for float32 [S1, unofficial].
*   **Performance:** The method is highly effective for reducing memory footprint in Gaussian Splatting scenes with many Gaussians [S1, unofficial].
*   **Strengths:** Simple implementation, significant compression ratio, fast decompression [S1, unofficial].
*   **Limitations:** Lossy compression, sensitive to the choice of $K$ and quantization bits, may not preserve fine details if $K$ is too small [S1, unofficial].

## Background
K-means clustering is a classic unsupervised learning algorithm for partitioning data into $K$ clusters [S1, unofficial]. Its application to parameter compression in neural rendering, specifically Gaussian Splatting, was popularized by the `splatad` project, which utilizes the `torchpq` library for efficient clustering on GPU [S1, unofficial].
