# Vector Quantization

Also called: Codebook Quantization, LBG algorithm modification, 基于字典的压缩

## Overview
Vector Quantization (VQ) is a lossy compression technique that maps $n$-dimensional input vectors to a single fixed-length index referencing an entry in a pre-defined or learned codebook (dictionary) [S1, S3, unofficial][S5]. It solves the problem of high storage and bandwidth requirements for volumetric data by exploiting spatial redundancy, replacing individual voxel blocks with compact indices [S2, S5]. Unlike [Scalar Quantization](5726-scalar-quantization.md) which processes values independently, VQ groups data into blocks to capture correlations, and unlike [Hierarchical Vector Quantization](827-hierarchical-vector-quantization.md) which uses multiple resolution levels, standard VQ typically employs a single dictionary for the entire dataset [S3, unofficial][S5].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ $n$-dimensional vectors (e.g., voxel color features or small volume blocks) $S = \{(x_1, y_1, \dots), \dots, (x_N, y_N, \dots)\}$ [S1, S3, unofficial].
*   **Output:** A codebook $C$ of size $K = 2^r$ entries, where $r$ is the bit-size of the index, and a mapping of each input vector to an index $j \in [0, K-1]$ [S1, unofficial][S2].

**Data Structures:**
*   **Codebook ($C$):** A table of $K$ vectors, each of dimension $n$. Stored as $C = \{(c_{x1}, c_{y1}, \dots), \dots, (c_{xK}, c_{yK}, \dots)\}$ [S1, unofficial].
*   **Index Map:** A list of integers (indices) corresponding to the input vectors, where each index points to an entry in $C$ [S2, S5].

**Algorithm Steps:**
1.  **Block Division:** Divide the input volume into small data blocks of size $B \times B \times B$ (commonly $4 \times 4 \times 4$) [S5][S7, unofficial]. Each block is treated as an $n$-dimensional vector.
2.  **Codebook Training:** Learn the codebook $C$ from the training data.
    *   *Metric:* Minimize the average squared-distance distortion:
        $$ D_{avg} = \frac{1}{N} \sum_{m=1}^N \| \vec{x}_m - \vec{c}_m \|^2_2 $$
        where $\vec{x}_m$ is the original vector and $\vec{c}_m$ is the codebook entry assigned to it [S1, S3, unofficial].
    *   *Optimization:* Use an iterative algorithm such as the Linde-Buzo-Gray (LBG) algorithm or a Principal Component Analysis (PCA) splitting strategy to avoid empty cells and improve speed [S1, S3, unofficial].
3.  **Encoding:** For each input vector $\vec{x}_i$, find the codebook entry $\vec{c}_j$ that minimizes the distortion metric $\delta(\vec{x}_i, \vec{c}_j) = \|\vec{x}_i - \vec{c}_j\|^2_2$ [S3, unofficial]. Store the index $j$ in the index map [S2].
4.  **Decoding:** To reconstruct the volume, look up the index $j$ in the codebook $C$ to retrieve the vector $\vec{c}_j$, which replaces the original block [S1, unofficial][S5].

**GPU Implementation Details (Cg/OpenGL):**
For hardware-accelerated decoding, integer arithmetic limitations in shading languages (e.g., Cg) are handled using texture mapping [S1, unofficial]:
1.  **Coordinate Mapping:** Map integer block coordinates $(x, y, z)$ to float texture coordinates in $[-1.0, 1.0]$ for a viewport of size $D_x \times D_y \times D_z$:
    $$ x' = (x \cdot 0.5 + 0.5) \cdot \frac{D_x - 1}{\frac{D_x - 4}{D_y - 1}} - \frac{2 D_x - 8}{3} $$
    $$ y' = (x \cdot 0.5 + 0.5) \cdot \frac{D_y - 4}{\frac{D_y - 1}{D_z - 1}} - \frac{2 D_y - 8}{3} $$
    $$ z' = (z \cdot 0.5 + 0.5) \cdot \frac{D_z - 1}{D_z - 4} - \frac{2 D_z - 8}{3} $$
    where $D_{x,y,z} = 2^n$ for $n \ge 3$ [S1, unofficial].
2.  **Address Texture:** Use a $4^3$ "Address Texture" (Texture A) to store $w$ coordinates for codebook lookups. The texture is repeated using `GL_REPEAT` to handle block boundaries. Coordinates for the address texture are:
    $$ x_A = (x \cdot 0.5 + 0.5) \cdot (D_x/4) $$
    $$ y_A = (y \cdot 0.5 + 0.5) \cdot (D_y/4) $$
    $$ z_A = (z \cdot 0.5 + 0.5) \cdot (D_z/4) $$
    [S1, unofficial].
3.  **Filtering:** Use `GL_NEAREST` to simulate integer division (e.g., $\lfloor x/4 \rfloor$) and `GL_CLAMP` to handle boundary conditions where coordinates fall outside $[0.0, 1.0]$ [S1, unofficial].

**Parameters:**
*   **Index Bit-size ($r$):** Controls the trade-off between compression ratio and distortion. Typical value: 8 bits [S1, unofficial].
*   **Block Size:** Commonly $4 \times 4 \times 4$ [S7, unofficial].

**Edge Cases and Pitfalls:**
*   **Empty Cell Problem:** Iterative algorithms like LBG may create unused codebook entries, increasing distortion and execution time [S1, S3, unofficial]. PCA splitting strategies mitigate this [S1, unofficial].
*   **Accumulated Error:** In time-varying data, reconstructing differences (P-frames) leads to error accumulation. Mitigated by periodically transferring original data (I-frames) to reset the state [S1, unofficial].
*   **Pre-processing Time:** Learning dictionaries for massive volumes requires significant pre-processing time [S5].

## Subtopics

### [Hierarchical Vector Quantization](827-hierarchical-vector-quantization.md)
Uses multiple resolution levels (codebooks) to capture coarse and fine details, allowing direct GPU decoding and minimizing CPU-GPU transfer.

### [LBG Algorithm](840-lbg-algorithm.md)
The standard iterative method for finding optimal codebooks by minimizing distortion, though prone to empty cells and slow execution.

### [Progressive Encoding of Time-Varying Sequences](959-progressive-encoding-of-time-varying-sequences.md)
Extends VQ to time-varying data by reusing codebooks across frames, treating frames as I-frames or P-frames.

### [Vector Quantization for Volumetric Radiance Fields](1870-vector-quantization-for-volumetric-radiance-fields.md)
Applies VQ to compress voxel color features in NeRF-like grids, achieving high compression ratios with minimal quality loss.

### [Fortune's Palette Compression](4988-fortune-s-palette-compression.md)
A lossless variant for sparse data, mapping unique values to a compact palette.

### [Compact3D / C3DGS / EAGLES](6139-compact3d-c3dgs-eagles.md)
Applies VQ to 3D Gaussian Splatting attributes (SH coefficients, scale) to reduce model size.

### [Codebook Sharing](7563-codebook-sharing.md)
Reuses a single codebook across multiple levels or images to save memory.

### [Brood-based Vector Quantization](7595-brood-based-vector-quantization.md)
Applies VQ to residuals in adaptive trees (quadtrees/octrees) to exploit spatial coherence.

### [Residual Vector Quantization (R-VQ)](12711-residual-vector-quantization-r-vq.md)
Decomposes quantization error across multiple stages for higher precision in geometric attributes.

## Operating characteristics
*   **Time Complexity:** Encoding is $O(N \cdot K \cdot n)$ for naive search, where $N$ is the number of vectors, $K$ is codebook size, and $n$ is dimensionality. Decoding is $O(1)$ per vector (lookup) [S1, unofficial][S5].
*   **Memory Complexity:** Storage is $O(K \cdot n + N)$ for the codebook and indices [S2].
*   **Performance:** Decompression is extremely fast, suitable for real-time rendering [S5]. Achieves high compression ratios (e.g., ~20:1) with minimal artifacts for data with high spatial redundancy [S5].
*   **Strengths:** Fast decoding, good compression for redundant data, hardware-friendly [S1, unofficial][S5].
*   **Limitations:** Lossy, pre-processing time for codebook generation, dictionary size limits quality [S1, unofficial][S5].

## Background
Vector Quantization was first introduced in volume rendering by [NH92, NH93] [S5]. The foundational LBG algorithm was developed by Linde, Buzo, and Gray in 1980, improving upon scalar quantizers by Max (1960) and Lloyd (1982) [S3, unofficial]. It is widely used for large time-varying volumetric data due to high spatial and temporal redundancy [S1, unofficial].
