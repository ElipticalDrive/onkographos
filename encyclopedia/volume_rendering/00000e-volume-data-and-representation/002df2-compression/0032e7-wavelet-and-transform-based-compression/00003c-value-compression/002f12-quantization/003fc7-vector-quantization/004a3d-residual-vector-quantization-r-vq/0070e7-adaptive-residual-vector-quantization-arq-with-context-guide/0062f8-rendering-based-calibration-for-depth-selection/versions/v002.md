# Rendering-based calibration for depth selection

Also called: Rendering-based calibration

## Overview
A post-selection refinement step that evaluates candidate depth changes by rendering held-out calibration views to account for visibility, Gaussian overlap, and alpha-compositing interactions which are not explicitly modeled by the local proxy [S1, unofficial]. It is applied after local proxy depth selection to verify that proposed depth changes improve the rendered image quality [S1, unofficial].

## How it works
**Inputs and outputs:**
*   **Inputs:**
    *   $I^{\text{Stu,old}}$: The current rendered image using the existing depth and RVQ indices [S1, unofficial].
    *   $I^{\text{GT}}$: Ground-truth reference images for the calibration views [S1, unofficial].
    *   $\mathcal{V}_{\text{cal}}$: The set of held-out calibration views [S1, unofficial].
    *   Candidate groups of pending anchors with proposed depth changes [S1, unofficial].
    *   $\lambda_R$: Rate-distortion trade-off parameter [S1, unofficial].
    *   $N_a$: Total number of anchors [S1, unofficial].
*   **Outputs:**
    *   Accepted or rejected depth changes for each candidate group [S1, unofficial].
    *   Final depths and RVQ indices for bitstream regeneration [S1, unofficial].

**Data structures:**
*   **Candidate Groups:** A list of anchor subsets, each containing proposed depth modifications [S1, unofficial].
*   **Calibration Views:** A set of camera poses and intrinsics used for evaluation [S1, unofficial].

**Numbered steps:**
1.  **Divide candidates:** Partition the pending anchors into candidate groups to limit computational cost [S1, unofficial].
2.  **Evaluate sequentially:** For each candidate group $b$:
    a.  Apply the candidate depth changes to the current state [S1, unofficial].
    b.  Render the scene from all views in $\mathcal{V}_{\text{cal}}$ using the modified depths to obtain $I_b^{\text{Stu,new}}$ [S1, unofficial].
    c.  Calculate the average rendering distortion $\mathcal{D}_{\text{cal}}$ using the formula below [S1, unofficial].
    d.  Compute the induced change in distortion $\Delta \mathcal{D}_{\text{cal},b}$ relative to the previous state $I^{\text{Stu,old}}$ [S1, unofficial].
    e.  Calculate the change in code length $\Delta \widetilde{R}_b^{\text{CDF}}$ from integer CDFs after applying the candidate group [S1, unofficial].
    f.  Compute the rendering-based rate-distortion cost $\Delta \mathcal{J}_b^{\text{cal}}$ [S1, unofficial].
    g.  If $\Delta \mathcal{J}_b^{\text{cal}} \le 0$, accept the candidate update; otherwise, retain the previous state [S1, unofficial].
    h.  Update $I^{\text{Stu,old}}$ to $I_b^{\text{Stu,new}}$ if accepted, or keep it unchanged if rejected [S1, unofficial].
3.  **Regenerate bitstream:** After all candidate groups are evaluated, regenerate the arithmetic-coded bitstream using the final accepted depths and RVQ indices [S1, unofficial].

**Formulas:**
*   **Rendering Loss:**
    $$ \mathcal{L}_{\text{render}}(I, I^{\text{ref}}) = (1 - \gamma_{\text{SSIM}}) \text{MAE}(I, I^{\text{ref}}) + \gamma_{\text{SSIM}} [1 - \text{SSIM}(I, I^{\text{ref}})] $$
    where $I^{\text{ref}} \in \{I^{\text{GT}}, I^{\text{Tea}}\}$ denotes either the ground-truth image or the teaching image [S1, unofficial]. $\gamma_{\text{SSIM}}$ is a weighting factor [S1, unofficial].
*   **Average Rendering Distortion:**
    $$ \mathcal{D}_{\text{cal}} \left( I^{\text{Stu}}, I^{\text{GT}} \right) = \frac{1}{|\mathcal{V}_{\text{cal}}|} \sum_{v \in \mathcal{V}_{\text{cal}}} \mathcal{L}_{\text{render}} \left( I_v^{\text{Stu}}, I_v^{\text{GT}} \right) $$
    where $\mathcal{V}_{\text{cal}}$ is the set of calibration views [S1, unofficial].
*   **Distortion Change:**
    $$ \Delta \mathcal{D}_{\text{cal},b} = \mathcal{D}_{\text{cal}} \left( I_b^{\text{Stu,new}}, I^{\text{GT}} \right) - \mathcal{D}_{\text{cal}} \left( I^{\text{Stu,old}}, I^{\text{GT}} \right) $$
    where $I_b^{\text{Stu,new}}$ is the rendering with the candidate applied and $I^{\text{Stu,old}}$ is the previous rendering [S1, unofficial].
*   **Rate-Distortion Cost:**
    $$ \Delta \mathcal{J}_b^{\text{cal}} = \Delta \mathcal{D}_{\text{cal},b} + \lambda_R \frac{\Delta \widetilde{R}_b^{\text{CDF}}}{N_a} $$
    where $\Delta \widetilde{R}_b^{\text{CDF}}$ is the change in code length from integer CDFs after applying candidate group $b$, $N_a$ is the number of anchors, and $\lambda_R$ controls the rate-distortion trade-off [S1, unofficial].

**Parameters:**
*   $\lambda_R$: Rate-distortion trade-off parameter during calibration. Typical value: Not given in the sources.
*   $\gamma_{\text{SSIM}}$: Weighting factor for SSIM in the rendering loss. Typical value: Not given in the sources.

**Edge cases and pitfalls:**
*   **Computational Cost:** Rendering calibration views for every candidate group is expensive, which is why grouping candidates is necessary to limit cost [S1, unofficial].
*   **Visibility and Overlap:** The local proxy does not model visibility, Gaussian overlap, or alpha-compositing interactions, making full rendering evaluation critical for accuracy [S1, unofficial].
*   **Bitstream Regeneration:** The bitstream must be regenerated after calibration, not just updated incrementally, to ensure consistency with the final depths and indices [S1, unofficial].

**Pseudocode:**
```python
def rendering_based_calibration(candidates, calibration_views, current_depths, current_rvq_indices,
                                ground_truth_images, lambda_R, N_a, gamma_SSIM):
    """Evaluates candidate depth changes using rendering-based calibration."""
    current_depths = list(current_depths)
    current_rvq_indices = list(current_rvq_indices)

    for group in candidates:
        temp_depths = list(current_depths)
        for anchor_idx, new_depth in group.proposed_changes:
            temp_depths[anchor_idx] = new_depth

        # Render scene from all calibration views with new depths
        # (Standard 3D Gaussian Splatting rasterization [G])
        I_new = render_gaussian_splatting(temp_depths, current_rvq_indices, calibration_views)
        I_old = render_gaussian_splatting(current_depths, current_rvq_indices, calibration_views)

        D_new = 0.0
        D_old = 0.0
        for view in calibration_views:
            I_stu_new = I_new[view.id]
            I_stu_old = I_old[view.id]
            I_gt = ground_truth_images[view.id]
            D_new += rendering_loss(I_stu_new, I_gt, gamma_SSIM)
            D_old += rendering_loss(I_stu_old, I_gt, gamma_SSIM)
        D_new /= len(calibration_views)
        D_old /= len(calibration_views)

        delta_D = D_new - D_old

        # Change in code length from integer CDFs after applying candidate group
        # (Depends on arithmetic coding implementation [G])
        delta_R = compute_delta_r_cdf(group, current_depths)

        delta_J = delta_D + lambda_R * (delta_R / N_a)

        if delta_J <= 0:
            current_depths = temp_depths

    # Regenerate arithmetic-coded bitstream using final depths and RVQ indices
    return current_depths, current_rvq_indices

    mae = sum(abs(p - r) for p, r in zip(I_pred, I_ref)) / len(I_pred)
    ssim = structural_similarity(I_pred, I_ref)
    return (1 - gamma_SSIM) * mae + gamma_SSIM * (1 - ssim)

def render_gaussian_splatting(depths, rvq_indices, views):
    # Standard 3D Gaussian Splatting rasterization [G]
    return {v.id: render_view(depths, rvq_indices, v) for v in views}

def compute_delta_r_cdf(group, current_depths):
```

## Operating characteristics
*   **Time Complexity:** Proportional to the number of candidate groups and the number of calibration views, as each evaluation requires rendering the scene from all calibration views [S1, unofficial].
*   **Memory Complexity:** Requires storing ground-truth images for calibration views and intermediate rendered images, scaling with the number of calibration views and image resolution [S1, unofficial].
*   **Strengths:** Accounts for complex interactions like visibility and alpha-compositing that local proxies miss, leading to higher rendering quality [S1, unofficial].
*   **Limitations:** High computational cost due to repeated rendering, and requires a set of held-out calibration views [S1, unofficial].
*   **When to use:** Applied after local proxy depth selection to refine quality by evaluating full rendering interactions [S1, unofficial].
*   **When not to use:** Not given in the sources.

## Background
*   **Origin:** Introduced in "3D Gaussian Splatting Data Compression via Adaptive Residual Quantization and Error Compensation" [S1, unofficial].
*   **History:** Part of the ARQ method for compressing 3D Gaussian Splatting data, addressing the limitations of local proxy-based depth selection by incorporating full rendering feedback [S1, unofficial].
*   **Usage:** Used in the context of 3D Gaussian Splatting compression to refine depth selections and improve the visual quality of the compressed representation [S1, unofficial].
