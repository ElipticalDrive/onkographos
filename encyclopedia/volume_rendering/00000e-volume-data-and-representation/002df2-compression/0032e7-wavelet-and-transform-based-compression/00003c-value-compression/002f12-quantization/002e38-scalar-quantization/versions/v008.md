# Scalar Quantization

Also called: Per-block scalar quantization, Scalar Quantization Impact

## Overview
Scalar quantization is a lossy compression technique that maps continuous or high-precision volume data to a discrete set of values by partitioning the value range into a finite number of intervals (bins) [S1, S2]. In the context of compressed volume rendering, it is primarily implemented as a **per-block** random-access decompression method, where each spatial block of voxels is represented by a local minimum, a local maximum, and a set of local indices [S2, S3]. This approach differs from global quantization by adapting the value range to local data variations, thereby reducing reconstruction error for data with high dynamic ranges or non-uniform distributions [S2, S3]. It enables efficient GPU-based direct volume rendering by allowing on-the-fly decompression without loading the entire volume into main memory [S2, S3].

## How it works
The method operates on a block-based structure, where the volume is divided into spatial blocks (e.g., $4 \times 4 \times 4$ or similar dimensions). Each block is processed independently to store a compact representation that allows for random access and parallel decompression.

### Inputs and Outputs
*   **Input:** A block of $N$ voxel values $\{v_1, v_2, \dots, v_N\}$, where each $v_i$ is a floating-point number (typically 32-bit or 64-bit).
*   **Output:** A compressed block representation consisting of:
    1.  A minimum value $min$.
    2.  A maximum value $max$.
    3.  A set of local indices $\{idx_1, idx_2, \dots, idx_N\}$, where each $idx_i$ is an integer stored using $ibits$ bits.

### Data Structures
The compressed block is stored in memory as a contiguous sequence of values. The exact layout depends on the implementation, but typically follows this order:
1.  $min$: The minimum value in the block (same precision as input, e.g., 32-bit float).
2.  $max$: The maximum value in the block (same precision as input).
3.  Indices: $N$ integers, each occupying $ibits$ bits. The total size for indices is $N \times ibits$ bits.

### Parameters
*   $ibits$: The number of bits used to represent each local index. Common values are 4, 5, 6, 7, or 8 bits, depending on the desired compression ratio and precision [S1, S3].
*   Block size: The spatial dimensions of the block (e.g., $4 \times 4 \times 4$). Not given in the sources for the general method, but implied by the block-based nature [S2, S3].

### Steps
1.  **Compute Extremes:** For each block, find the minimum value $min = \min(v_i)$ and the maximum value $max = \max(v_i)$ among all voxels in the block [S2, S3].
2.  **Compute Local Indices:** For each voxel value $v_i$ in the block, compute a local index $idx_i$ that maps $v_i$ to a discrete level between $min$ and $max$. The index is calculated as:
    $$ idx_i = \text{round}\left( \frac{v_i - min}{max - min} \times (2^{ibits} - 1) \right) $$
    The index is clamped to the range $[0, 2^{ibits} - 1]$ to handle potential floating-point errors or values exactly at the boundaries [G].
3.  **Store Block:** Store $min$, $max$, and the array of $idx_i$ values in the compressed data structure.

### Decompression Formula
To reconstruct the voxel value $v_{ijk}$ from the compressed block, use the following linear interpolation formula [S2, S3]:
$$ v_{ijk} = min + (max - min) \times \frac{index}{2^{ibits} - 1} $$
Where:
*   $v_{ijk}$ is the decompressed value.
*   $min$ and $max$ are the block minimum and maximum values.
*   $index$ is the local index for the voxel.
*   $ibits$ is the number of bits used to represent the index values.

### Edge Cases and Pitfalls
*   **Zero Range:** If $min = max$, the denominator $max - min$ becomes zero. In this case, all indices should be set to 0, and the reconstructed value should be $min$ [G].
*   **Precision Loss:** Lower bitrates (fewer $ibits$) lead to higher reconstruction error. The error roughly doubles for each reduction by one bit in the scalar quantizer [S1].
*   **Quantization Bins:** The quantization bins store interpolation weights, and the error is in the range $[0, 1]$ for normalized weights [S1].

### Pseudocode
```python
def compress_block(values, ibits):
    """
    Compress a block of voxel values using per-block scalar quantization.
    
    Args:
        values: List of float values in the block.
        ibits: Number of bits for the index.
        
    Returns:
        min_val: Minimum value in the block.
        max_val: Maximum value in the block.
        indices: List of integer indices.
    """
    min_val = min(values)
    max_val = max(values)
    
    # Handle zero range case
    if max_val == min_val:
        indices = [0] * len(values)
        return min_val, max_val, indices
    
    # Calculate the scale factor
    # Note: Source [S3] uses 2^(ibits-1), but standard practice is 2^ibits - 1.
    # We use the standard formula for correctness.
    scale = (1 << ibits) - 1
    
    indices = []
    for v in values:
        # Compute normalized position
        normalized = (v - min_val) / (max_val - min_val)
        # Clamp to [0, 1] to handle floating point errors
        normalized = max(0.0, min(1.0, normalized))
        # Compute index
        idx = int(round(normalized * scale))
        indices.append(idx)
        
    return min_val, max_val, indices

def decompress_block(min_val, max_val, indices, ibits):
    """
    Decompress a block of voxel values.
    
    Args:
        min_val: Minimum value of the block.
        max_val: Maximum value of the block.
        indices: List of integer indices.
        ibits: Number of bits for the index.
        
    Returns:
        values: List of decompressed float values.
    """
    scale = (1 << ibits) - 1
    values = []
    for idx in indices:
        # Reconstruct value
        # Note: Source [S3] uses 2^(ibits-1) in denominator, but we use standard formula.
        normalized = idx / scale
        v = min_val + (max_val - min_val) * normalized
        values.append(v)
    return values
```

## Subtopics

### [Fixed-rate Block-coding (VTC/S3TC)](5727-fixed-rate-block-coding-vtc-s3tc.md)
Fixed-rate block-coding, specifically Volume Texture Compression (VTC), is a hardware-accelerated compression method that extends the 2D S3TC algorithm to 3D volumes by retiling in the Z direction. It solves the problem of storing large volumetric datasets in limited GPU memory by approximating voxel values through linear interpolation from a small set of representative values, enabling real-time rendering without decompressing the entire volume into RAM. Unlike general-purpose codecs, VTC is a fixed-rate format with specific block sizes (4x4x1, 4x4x2, or 4x4x4) and is distinct from its sibling(52-s3tc.md) by its native support for 3D textures.

### [Uniform Quantization](5855-uniform-quantization.md)
Uniform quantization is a lossy compression method that maps a continuous or high-precision range of source data values to a limited set of discrete levels with equal spacing. It solves the problem of reducing the memory footprint of volume data, typically achieving a 4:1 compression ratio by representing 32-bit floating-point data with 8-bit integers. It differs from [Non-uniform Quantization](5858-non-uniform-quantization.md) by using fixed-width intervals for all levels, which makes it simple to implement but prone to losing features in data with wide dynamic ranges.

### [Quantization Functions](13871-quantization-functions.md)
Quantization Functions map floating-point values to discrete integer representations for storage or transmission, serving as the final encoding step in scalar quantization pipelines. Unlike [Uniform Quantization](5855-uniform-quantization.md) which maps directly from float to integer, these functions explicitly handle half-precision conversion and scaling to specific bit-depths (7, 9, or 10 bits) to optimize compression ratios for block-based formats like BC6H. They differ from [Fixed-rate Block-coding (VTC/S3TC)](5727-fixed-rate-block-coding-vtc-s3tc.md) by operating on individual scalar values rather than compressing spatial blocks of texture data.

## Operating characteristics
*   **Time Complexity:** Encoding time decreases as the number of nodes (in a graph-based context) decreases, but the relationship is not linear. Encoding time decreases faster than the number of nodes because similar choices are made in early stages of the greedy algorithm, reducing the search space by roughly the same absolute amount early on [S1]. Decompression is $O(1)$ per voxel, making it suitable for real-time rendering [S2, S3].
*   **Memory Complexity:** The output size is dominated by the voxel data at the finest level, so the output size stays more or less constant regardless of the quantization bitrate [S1]. The compressed block size is $2 \times \text{float\_size} + N \times ibits$ bits.
*   **Performance:** Lower bitrates lead to fewer nodes but higher reconstruction error [S1]. The reconstruction error roughly doubles for each reduction by one bit in the scalar quantizer [S1].
*   **Strengths:** Simple to implement, supports random access, and is efficient for GPU decompression [S2, S3].
*   **Limitations:** Reconstruction error increases significantly with lower bitrates [S1]. Not suitable for data with very high dynamic ranges if global quantization is used, but per-block scalar quantization mitigates this [S2, S3].

## Background
Scalar quantization is a fundamental technique in data compression. In the context of volume rendering, per-block scalar quantization has been used in various compressed GPU-based direct volume rendering systems [S2, S3]. The method was proposed in works such as [YNV08] and [IGM10], which are cited in the sources [S2, S3]. The impact of scalar quantization on performance, particularly in terms of node count and reconstruction error, has been studied in the context of Mixture Graphs [S1].
