# Quantization Functions

Also called: Quantize10, Quantize7, Quantize9

## Overview
Quantization Functions map floating-point values to discrete integer representations for storage or transmission, serving as the final encoding step in scalar quantization pipelines. Unlike [Uniform Quantization](5855-uniform-quantization.md) which maps directly from float to integer, these functions explicitly handle half-precision conversion and scaling to specific bit-depths (7, 9, or 10 bits) to optimize compression ratios for block-based formats like BC6H. They differ from [Fixed-rate Block-coding (VTC/S3TC)](5727-fixed-rate-block-coding-vtc-s3tc.md) by operating on individual scalar values rather than compressing spatial blocks of texture data.

## How it works
**Inputs:** A single 32-bit floating-point value $x$.
**Outputs:** A quantized integer $Q$ in the range $[0, 2^b - 1]$, where $b$ is the bit depth (7, 9, or 10).

**Data Structures:**
No persistent data structures are required. The operation is stateless and per-voxel.

**Parameters:**
*   $b \in \{7, 9, 10\}$: The target bit depth.
*   $Scale$: A scaling factor determined by $b$.
    *   For $b=7$: $Scale = 128$
    *   For $b=9$: $Scale = 512$
    *   For $b=10$: $Scale = 1024$

**Steps:**
1.  Convert the input float $x$ to half-precision (16-bit float, `float16`). Let this value be $x_{half}$.
2.  Compute the intermediate scaled value: $v = x_{half} \times Scale$.
3.  Normalize to the integer range by dividing by the maximum representable magnitude of a signed 16-bit integer, which is $32767$.
4.  The quantized integer is:
    $$ Q = \left\lfloor \frac{v}{32767} \right\rfloor $$
    *Note: The source formula implies a direct mapping where the half-precision value is treated as a normalized coordinate relative to the full 16-bit range, scaled by the specific block factor.*

**Pseudocode:**
```python
def quantize_function(x: float, bit_depth: int) -> int:
    """
    Quantizes a float32 value to a specific bit depth using half-precision scaling.
    
    Args:
        x: Input 32-bit float.
        bit_depth: Target bit depth (7, 9, or 10).
        
    Returns:
        Quantized integer value.
    """
    # Step 1: Convert to half-precision
    # In Python, we simulate float16 conversion. 
    # Standard float16 has 1 sign bit, 5 exponent bits, 10 mantissa bits.
    # Range is approx -65504 to +65504.
    x_half = float_to_float16(x)
    
    # Step 2: Determine Scale
    if bit_depth == 7:
        scale = 128
    elif bit_depth == 9:
        scale = 512
    elif bit_depth == 10:
        scale = 1024
    else:
        raise ValueError("Bit depth must be 7, 9, or 10")
        
    # Step 3 & 4: Apply formula Q = (Half(x) * Scale) / 32767
    # Note: The source formula [S1, unofficial] does not specify rounding mode or clamping.
    # Standard implementation usually rounds to nearest integer.
    # The denominator 32767 corresponds to the max positive value of a signed 16-bit int.
    
    numerator = x_half * scale
    result = numerator / 32767.0
    
    # Round to nearest integer
    q = round(result)
    
    # Clamp to valid range for the bit depth
    max_val = (1 << bit_depth) - 1
    if q < 0:
        q = 0
    elif q > max_val:
        q = max_val
        
    return q

def float_to_float16(x: float) -> float:
    """
    Converts a float32 to float16 and back to float32 to simulate the quantization loss.
    This is a standard IEEE 754 conversion.
    """
    import struct
    # Pack as float32, unpack as float16 (using half precision struct format)
    # Note: Python's struct module doesn't directly support 'e' (half) in all versions,
    # but numpy or standard library conversions are assumed for implementation.
    # For pure Python without numpy, this is a complex bit-manipulation task.
    # We assume a standard IEEE 754 half-precision conversion is available.
    import numpy as np
    return np.float16(x).astype(np.float32)
```

**Edge Cases and Pitfalls:**
*   **Precision Loss:** Converting to `float16` introduces significant quantization error for values outside the range $[-65504, 65504]$ or with high precision requirements.
*   **Clamping:** The source formula does not explicitly define clamping behavior. Implementers must clamp the final integer to $[0, 2^b - 1]$ to prevent out-of-bounds access during block encoding.
*   **Rounding:** The source formula uses division, implying floating-point arithmetic. The final step to an integer requires a defined rounding mode (e.g., round-to-nearest-even).

## Subtopics

### Amplitude-Only Hologram Quantization
A method to generate an amplitude-only hologram $H$ by quantizing the real part of the object wave $O$, normalized between -1 and +1, using a uniform mid-rise quantizer $Q$ with $L$ discrete levels [S2]. It is chosen when energy efficiency is critical for holographic displays, as amplitude-only holograms discard phase information. It differs from standard scalar quantization by using a specific clipping parameter $\Delta$ to balance granular and overload distortions.
*   **Formula:**
    $$
    Q(X, L, \Delta) = 
    \begin{cases} 
    0 & \text{if } X < -\Delta \\
    \frac{(X + \Delta)L}{2\Delta} & \text{if } -\Delta \le X < \Delta \\
    L - 1 & \text{otherwise}
    \end{cases}
    $$
    Where $X$ is the normalized input value ($\Re\{O\}$), $L$ is the number of levels, and $\Delta$ is the clipping value [S2].
*   **Parameters:**
    *   $L$: Number of discrete quantization levels. Typical value: 256 [S2].
    *   $\Delta$: Input quantizer range clipping value. Typical value: 0.4 (compromise between energy efficiency and image quality) [S2].
*   **Pitfalls:** Increasing $\Delta$ improves imaging quality (PSNR/SSIM) but decreases energy efficiency. At $\Delta = 0.5$, energy efficiency drops to 1.4% for amplitude holograms [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per value. The operation involves a single float-to-half conversion, a multiplication, a division, and rounding.
*   **Memory Complexity:** $O(1)$. No auxiliary memory is required.
*   **Strengths:** Optimizes storage for specific bit-depths (7, 9, 10) used in modern compression formats like BC6H. The half-precision step reduces precision before integer mapping, aligning with hardware capabilities.
*   **Limitations:** The explicit conversion to half-precision may introduce artifacts if the input data requires higher precision than float16 can represent. The method is specific to the bit-depths 7, 9, and 10; other depths require different scaling factors not defined in the source.
*   **When to use:** When compressing volume data or textures using block-based formats that support 7, 9, or 10-bit scalar quantization (e.g., BC6H).
*   **When not to use:** When higher precision is required (use full float32 or 16-bit int without scaling), or when the bit-depth is not 7, 9, or 10.

## Background
The specific quantization functions for 7, 9, and 10-bit depths are associated with real-time BC6H compression on the GPU [S1, unofficial]. BC6H is a block-compression format for 32-bit floating-point HDR textures. The quantization functions map the half-precision intermediate values to the specific integer ranges required by the BC6H encoding scheme. The amplitude-only hologram quantization is described in the context of holographic near-eye displays for AR/VR applications [S2].
