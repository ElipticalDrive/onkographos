# Quantization Functions

Also called: Quantize10, Quantize7, Quantize9

## Overview
Quantization functions map continuous floating-point values to discrete integer representations to enable storage or transmission via standard codecs. This method defines the mathematical mapping and packing strategies required to convert multichannel feature planes into fixed-precision integer canvases compatible with image and video compression standards. It differs from [Scalar Quantization](5726-scalar-quantization.md) by focusing on global or channel-wise normalization for codec compatibility rather than per-block random-access reconstruction, and from [Uniform Quantization](5855-uniform-quantization.md) by explicitly handling multichannel packing strategies and specific codec constraints.

## How it works

### Inputs and Outputs
*   **Input:** Multichannel floating-point tensor $X$ with dimensions $[C, H, W]$.
*   **Output:** Quantized integer tensor $X_{01}$ in range $[0, 1]$ (or mapped to codec bit-depth), and packed canvas $Y$ with dimensions $[C_{out}, H', W']$ where $C_{out} \in \{1, 3\}$.

### Data Structures
*   **Float Tensor:** $X \in \mathbb{R}^{C \times H \times W}$.
*   **Canvas:** $Y \in \mathbb{Z}^{C_{out} \times H' \times W'}$, where pixel values are integers suitable for standard codecs (e.g., 8-bit or 10-bit).

### Steps and Formulas

1.  **Range Estimation:** Determine the normalization bounds $[\alpha, \beta]$ for each channel.
    *   **AbsMax:** A fixed range shared by all channels.
    *   **Channelwise:** Estimate the per-channel central 95% range. Let $\alpha_c$ and $\beta_c$ be the lower and upper bounds for channel $c$.

2.  **Normalization and Quantization:** Map each element $X_{c,h,w}$ to $[0, 1]$ using the estimated bounds.
    $$
    X_{01, c, h, w} = \text{clip}\left( \frac{X_{c, h, w} - \alpha_c}{\beta_c - \alpha_c}, 0, 1 \right)
    $$
    Where $\text{clip}(v, 0, 1)$ limits the value to the interval $[0, 1]$.

3.  **Dequantization (Reconstruction):** To recover the approximate original value $\widehat{X}$:
    $$
    \widehat{X}_{c, h, w} = X_{01, c, h, w} (\beta_c - \alpha_c) + \alpha_c
    $$

4.  **Packing:** Rearrange the normalized tensor $X_{01}$ into a codec-friendly canvas $Y$ with $C_{out} \in \{1, 3\}$ channels. Three strategies are defined for an input with $C=48$ channels:
    *   **FlattenGray:** Stacks all channels spatially into a single monochrome canvas. For $C=48$, the layout becomes $[1, 6H, 8W]$. This avoids cross-channel mixing.
    *   **FlattenRGB:** Groups channels into three equal groups. For $C=48$, each group has 16 channels. The layout becomes $[3, 4H, 4W]$.
    *   **PixelShuffle:** Rearranges channels into spatial neighborhoods (spatial-to-depth). For $C=48$, the layout also becomes $[3, 4H, 4W]$.

5.  **Density Grid Handling:** For density grids $D$ controlling opacity, tile the grid into a single monochrome canvas and encode as grayscale to avoid mixing across channels.

### Pseudocode

```python
def quantize_and_pack(X, strategy='FlattenGray', density_grid=None):
    """
    Quantize multichannel float tensor X and pack into a codec-compatible canvas.
    
    Args:
        X: Float tensor of shape [C, H, W].
        strategy: 'FlattenGray', 'FlattenRGB', or 'PixelShuffle'.
        density_grid: Optional float tensor for density, handled separately.
        
    Returns:
        Y: Packed integer canvas ready for codec encoding.
        bounds: List of (alpha, beta) tuples per channel for dequantization.
    """
    C, H, W = X.shape
    bounds = []
    X_01 = np.zeros_like(X)
    
    # Step 1 & 2: Channelwise Quantization
    for c in range(C):
        channel_data = X[c, :, :]
        # Estimate central 95% range
        alpha = np.percentile(channel_data, 2.5)
        beta = np.percentile(channel_data, 97.5)
        bounds.append((alpha, beta))
        
        # Normalize to [0, 1]
        normalized = (channel_data - alpha) / (beta - alpha)
        X_01[c, :, :] = np.clip(normalized, 0, 1)
        
    # Step 4: Packing
    if strategy == 'FlattenGray':
        # Stack all channels spatially: [1, 6H, 8W] for C=48
        # General formula: reshape [C, H, W] to [1, H * (C//W_factor), W * W_factor]
        # Assuming C is divisible by appropriate factors for square-ish packing
        # For general C, flatten channels into spatial dimensions
        # Example for C=48, H=H, W=W: [1, 6H, 8W] implies 6*8=48
        # Reshape to [1, 6*H, 8*W]
        Y = X_01.reshape(1, 6*H, 8*W) # Specific to C=48 example; general case requires dynamic reshaping
        
    elif strategy == 'FlattenRGB':
        # Group into 3 channels of 16 each: [3, 4H, 4W]
        # Reshape [48, H, W] -> [3, 16, H, W] -> [3, 4H, 4W]
        Y = X_01.reshape(3, 16, H, W).transpose(0, 1, 2, 3).reshape(3, 4*H, 4*W)
        
    elif strategy == 'PixelShuffle':
        # Spatial-to-depth rearrangement
        # Similar output dimensions to FlattenRGB but different spatial arrangement
        # Reshape [48, H, W] -> [3, 16, H, W] -> shuffle spatial dims
        # Implementation depends on specific shuffle kernel; here assumed to result in [3, 4H, 4W]
        Y = X_01.reshape(3, 16, H, W).transpose(0, 2, 3, 1).reshape(3, H*4, W*4) # Placeholder for specific shuffle logic
        
    else:
        raise ValueError("Unknown strategy")

    # Handle Density Grid if provided
    if density_grid is not None:

        pass

    return Y, bounds
```

### Parameters
*   **Strategy:** Determines packing layout. 'FlattenGray' minimizes cross-channel mixing but may reduce spatial locality for codecs optimized for RGB. 'FlattenRGB' and 'PixelShuffle' group channels to fit standard 3-channel video codecs.
*   **Range Estimation Method:** 'Channelwise' uses the central 95% percentile range per channel. 'AbsMax' uses a fixed global range.

### Edge Cases and Pitfalls
*   **Outliers:** If the central 95% range is heavily skewed by outliers, quantization precision for the majority of the data decreases. [G] Consider using robust statistics or clipping extreme values before range estimation.
*   **Channel Mixing:** Using 'FlattenRGB' or 'PixelShuffle' mixes information from different feature channels into the same spatial location. This may confuse codecs that assume color correlation between channels. 'FlattenGray' avoids this but may be less efficient for RGB-optimized codecs.
*   **Density Grid:** Encoding density as grayscale prevents mixing opacity information with color features, which is critical for correct volume rendering reconstruction.

## Subtopics

### Amplitude-Only Hologram Quantization
A method to generate an amplitude-only hologram $H$ by quantizing the real part of the object wave $O$, normalized between -1 and +1, using a uniform mid-rise quantizer $Q$ with $L$ discrete levels. It is chosen when energy efficiency is critical for holographic displays. It differs from standard scalar quantization by using a specific clipping parameter $\Delta$ to balance granular and overload distortions. [S2]
*   **Formula:**
    $$
    Q(X, L, \Delta) = 
    \begin{cases} 
    0 & \text{if } X < -\Delta \\
    \frac{(X + \Delta)L}{2\Delta} & \text{if } -\Delta \le X < \Delta \\
    L - 1 & \text{otherwise}
    \end{cases}
    $$
*   **Parameters:**
    *   $L$: Number of discrete quantization levels. Typical value: 256.
    *   $\Delta$: Input quantizer range clipping value. Typical value: 0.4. Controls the balance between energy efficiency and image quality.
*   **Pitfall:** Increasing $\Delta$ improves imaging quality (PSNR/SSIM) but decreases energy efficiency. At $\Delta = 0.5$, energy efficiency drops to 1.4% for amplitude holograms. [S2]

### Bit Depth Conversion with Windowing
Converting 16-bit input data to 8-bit output during resampling, using a defined intensity window to preserve relevant contrast. It is used in medical imaging (e.g., dry bone scans) where the signal range is well-defined. It differs from general quantization by recording the window (min/max or percentile) in metadata for accurate dequantization. [S3, unofficial]
*   **Steps:**
    1.  Perform interpolation in floating-point precision.
    2.  Map the floating-point result to the output bit depth using the recorded window.
*   **Comparison:** 8-bit is sufficient for dry bone because the signal range (26k-36k) maps well to 8-bit steps without losing real data, whereas contrast-stained scans retain 16-bit to preserve lower-intensity details. [S3, unofficial]
*   **Pitfall:** Rounding error for 0-40,000 to 8-bit is ~45 grey levels (RMS), against 1678 grey levels of natural variation in bone. [S3, unofficial]

### Quantization and Packing for Standard Codecs
Mapping multichannel floating-point feature planes to fixed-precision integer canvases compatible with standard image/video codecs (e.g., JPEG, AV1). It is used in neural radiance field (NeRF) compression. It differs from other methods by explicitly defining packing strategies (FlattenGray, FlattenRGB, PixelShuffle) to adapt multichannel tensors to 1- or 3-channel codec inputs. [S4]
*   **Formulas:**
    *   Quantization: $X_{01} = \text{clip}((X - \alpha) / (\beta - \alpha), 0, 1)$.
    *   Dequantization: $\widehat{X} = X_{01}(\beta - \alpha) + \alpha$.
*   **Strategies:**
    *   **AbsMax:** Fixed range $[\alpha, \beta]$ shared by all channels.
    *   **Channelwise:** Per-channel central 95% range.
*   **Packing:**
    *   **FlattenGray:** Stacks channels spatially into $[1, 6H, 8W]$ for $C=48$.
    *   **FlattenRGB:** Groups channels into three groups of 16, resulting in $[3, 4H, 4W]$.
    *   **PixelShuffle:** Rearranges channels into spatial neighborhoods, resulting in $[3, 4H, 4W]$. [S4]

## Operating characteristics

*   **Time Complexity:** $O(C \cdot H \cdot W)$ for quantization and packing. Range estimation is $O(C \cdot H \cdot W)$ if percentiles are computed per channel.
*   **Memory Complexity:** $O(C \cdot H \cdot W)$ for the input and output tensors.
*   **Strengths:** Compatible with standard, highly optimized codecs. Channelwise quantization preserves dynamic range per feature.
*   **Limitations:** Packing strategies may introduce cross-channel mixing or reduce spatial locality, potentially reducing codec efficiency. Range estimation requires a pass over the data.
*   **When to Use:** When compressing neural radiance fields or other multichannel volumetric data for streaming via standard video/image codecs.
*   **When Not to Use:** When random-access decompression is required (use [Scalar Quantization](5726-scalar-quantization.md)) or when the data has extreme outliers that skew the central 95% range.

## Background

Quantization functions for multichannel data have emerged with the rise of neural radiance fields (NeRFs) and their compression. The specific packing strategies (FlattenGray, FlattenRGB, PixelShuffle) and channelwise quantization for codec compatibility were introduced in the context of CATRF (Codec-Adaptive TriPlane Radiance Fields) for volumetric content delivery [S4]. Earlier work in holography used similar quantization principles for amplitude-only holograms [S2], and medical imaging has long used windowing for bit-depth conversion [S3, unofficial]. The specific 7/9/10-bit quantization for half-precision floats is associated with GPU real-time BC6H compression implementations [S1, unofficial].
