# Scalar Quantization

Also called: Per-block scalar quantization, Scalar Quantization Impact

## Overview
Scalar quantization maps continuous or high-precision volume data to a discrete, lower-precision set of values to reduce memory footprint and bandwidth requirements [S1, S2, S3]. In the context of compressed volume rendering, it is primarily implemented as a per-block random-access decompression method where each spatial block is represented by its local minimum and maximum values alongside a compact index for each voxel [S2, S3]. Unlike global quantization which applies a single scale to the entire dataset, per-block scalar quantization adapts to local data ranges, offering a trade-off between compression ratio and reconstruction fidelity [S2, S3].

## How it works
**Inputs and Outputs:**
*   **Input:** A block of $N$ voxel values $\{v_{ijk}\}$, where $i,j,k$ denote spatial coordinates within the block.
*   **Output:** A compressed representation consisting of the block minimum ($min$), block maximum ($max$), and a set of local indices $\{index_{ijk}\}$ for each voxel in the block.

**Data Structures:**
The compressed block layout typically includes:
1.  **Header:** Two floating-point values (or high-precision integers) for $min$ and $max$.
2.  **Index Data:** A bit-packed array of $N$ integers, each using $ibits$ bits. The total size of the index data is $N \times ibits$ bits.

**Algorithm Steps:**
1.  **Block Partitioning:** Divide the volume data into fixed-size spatial blocks (e.g., $4 \times 4 \times 4$ or similar, depending on the specific implementation [S2, S3]).
2.  **Range Computation:** For each block, compute the minimum value ($min$) and the maximum value ($max$) among all voxels in that block [S2, S3].
3.  **Index Calculation (Encoding):** For each voxel $v_{ijk}$ in the block, compute the local index. The index represents the relative position of the value within the $[min, max]$ range. The standard formula for the index is derived from the reconstruction formula (see below) [S2, S3]:
    $$ index_{ijk} = \text{round}\left( \frac{v_{ijk} - min}{max - min} \times (2^{ibits} - 1) \right) $$
    *Note: The sources provide the reconstruction formula explicitly. The encoding formula is the inverse. The sources specify the denominator as $2^{ibits-1}$ in the reconstruction, which implies a specific scaling. We must adhere to the source's reconstruction formula for consistency.*
    
    *Correction based on Source [S2, S3]:* The source formula is $v_{ijk} = min + (max - min) * \frac{index}{2^{ibits-1}}$. This implies the maximum index value corresponds to $max$. If $index = 2^{ibits-1}$, then $v_{ijk} = max$. Thus, the index range is $[0, 2^{ibits-1}]$. The number of distinct levels is $2^{ibits-1} + 1$.
    
    Revised Index Calculation:
    $$ index_{ijk} = \text{clamp}\left( \text{round}\left( \frac{v_{ijk} - min}{max - min} \times (2^{ibits-1}) \right), 0, 2^{ibits-1} \right) $$
4.  **Bit Packing:** Pack the $index_{ijk}$ values into a contiguous bit stream using $ibits$ bits per index.

**Reconstruction Formula:**
To decompress a voxel $v_{ijk}$:
$$ v_{ijk} = min + (max - min) \times \frac{index_{ijk}}{2^{ibits-1}} $$
Where:
*   $v_{ijk}$ is the decompressed value.
*   $min$ is the block minimum.
*   $max$ is the block maximum.
*   $index_{ijk}$ is the stored local index.
*   $ibits$ is the number of bits used to represent the index values [S2, S3].

**Parameters:**
*   **$ibits$ (Index Bit Depth):** The number of bits per index. Common values are 4, 5, 6, 7, 8, or 9 bits, depending on the desired compression ratio and accuracy [S1, S2, S3].
*   **Block Size:** Not explicitly defined in the provided notes for the general method, but VTC (a variant) uses 4x4x1, 4x4x2, or 4x4x4 [S3]. For general per-block scalar quantization, the block size is a design choice.

**Edge Cases and Pitfalls:**
*   **Zero Range:** If $min = max$ (constant block), the denominator $max - min$ becomes zero. The reconstruction formula yields $min$ regardless of the index. Implementation must handle this division by zero, typically by storing a flag or ensuring the index is ignored when the range is zero [G].
*   **Precision Loss:** Reconstruction error roughly doubles for each reduction by one bit in the scalar quantizer [S1]. This is because each bit reduction halves the precision of the quantized interpolation weight [S1].
*   **Quantization Bins:** In some contexts (e.g., mixture graphs), quantization bins store interpolation weights, and the error is normalized to $[0, 1]$ [S1].

**Pseudocode:**

```python
def encode_block_scalar_quantization(block_values, ibits):
    """
    Encodes a block of voxel values using per-block scalar quantization.
    
    Args:
        block_values: List or array of float voxel values in the block.
        ibits: Number of bits for the index (integer).
        
    Returns:
        min_val: The minimum value in the block.
        max_val: The maximum value in the block.
        indices: List of integer indices.
    """
    min_val = min(block_values)
    max_val = max(block_values)
    
    # Handle constant block case to avoid division by zero
    if max_val == min_val:
        indices = [0] * len(block_values)
        return min_val, max_val, indices
    
    # Calculate the maximum index value based on the source formula
    # v = min + (max - min) * (index / 2^(ibits-1))
    # => index = (v - min) / (max - min) * 2^(ibits-1)
    max_index = 2 ** (ibits - 1)
    
    indices = []
    for v in block_values:
        # Calculate raw index
        raw_index = (v - min_val) / (max_val - min_val) * max_index
        # Round to nearest integer
        index = round(raw_index)
        # Clamp to valid range [0, 2^(ibits-1)]
        index = max(0, min(index, max_index))
        indices.append(index)
        
    return min_val, max_val, indices

def decode_block_scalar_quantization(min_val, max_val, indices, ibits):
    """
    Decodes a block of voxel values from per-block scalar quantization.
    
    Args:
        min_val: The minimum value of the block.
        max_val: The maximum value of the block.
        indices: List of integer indices.
        ibits: Number of bits used for the index (used for validation, not strictly in formula).
        
    Returns:
        decoded_values: List of reconstructed float values.
    """
    max_index = 2 ** (ibits - 1)
    decoded_values = []
    
    for index in indices:
        # Formula from [S2, S3]: v_ijk = min + (max - min) * index / 2^(ibits-1)
        if max_val == min_val:
            val = min_val
        else:
            val = min_val + (max_val - min_val) * (index / max_index)
        decoded_values.append(val)
        
    return decoded_values
```

## Subtopics

### [Fixed-rate Block-coding (VTC/S3TC)](5727-fixed-rate-block-coding-vtc-s3tc.md)
Fixed-rate block-coding, specifically Volume Texture Compression (VTC), is a hardware-accelerated compression method that extends the 2D S3TC algorithm to 3D volumes by retiling in the Z direction. It solves the problem of storing large volumetric datasets in limited GPU memory by approximating voxel values through linear interpolation from a small set of representative values, enabling real-time rendering without decompressing the entire volume into RAM. Unlike general-purpose codecs, VTC is a fixed-rate format with specific block sizes (4x4x1, 4x4x2, or 4x4x4) and is distinct from its sibling(52-s3tc.md) by its native support for 3D textures.

### [Uniform Quantization](5855-uniform-quantization.md)
Uniform quantization is a lossy compression method that maps a continuous or high-precision range of source data values to a limited set of discrete levels with equal spacing. It solves the problem of reducing the memory footprint of volume data, typically achieving a 4:1 compression ratio by representing 32-bit floating-point data with 8-bit integers. It differs from [Non-uniform Quantization](5858-non-uniform-quantization.md) by using fixed-width intervals for all levels, which makes it simple to implement but prone to losing features in data with wide dynamic ranges.

### [Quantization Functions](13871-quantization-functions.md)
Quantization Functions map floating-point values to discrete integer representations for storage or transmission, serving as the final encoding step in scalar quantization pipelines. Unlike [Uniform Quantization](5855-uniform-quantization.md) which maps directly from float to integer, these functions explicitly handle half-precision conversion and scaling to specific bit-depths (7, 9, or 10 bits) to optimize compression ratios for block-based formats like BC6H. They differ from [Fixed-rate Block-coding (VTC/S3TC)](5727-fixed-rate-block-coding-vtc-s3tc.md) by operating on individual scalar values rather than compressing spatial blocks of texture data.

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** The output size is dominated by the voxel data at the finest level in hierarchical structures, so the impact of scalar quantization on total output size may be marginal if the bulk of the data is stored at higher resolutions [S1]. However, for a single block, the memory is $2 \times \text{float\_size} + N \times ibits$ bits.
*   **Time:** Encoding time decreases as the bitrate (and thus $ibits$) decreases, but not strictly linearly with the number of nodes in complex structures like Mixture Graphs, because similar choices are made in early stages of greedy algorithms, reducing the search space by a roughly constant absolute amount [S1]. Decompression is parallelizable on GPU as each voxel can be decompressed independently by accessing its block's min/max and its local index [S2, S3].

**Measured Performance:**
*   In Mixture Graph applications, reducing the scalar quantizer bitrate from 9 bits to 4 bits reduces the number of nodes significantly (e.g., from ~1M to ~460k for Hippocampus) but increases reconstruction error [S1].
*   Reconstruction error roughly doubles for each reduction by one bit in the scalar quantizer [S1].

**Strengths and Limitations:**
*   **Strengths:** Simple implementation, parallelizable decompression, random-access capability [S2, S3].
*   **Limitations:** High reconstruction error at low bitrates (error doubles per bit reduction) [S1]. Performance is sensitive to the dynamic range within blocks; blocks with large ranges suffer more quantization error [G].

**When to Use:**
*   Use when random-access decompression is required and hardware acceleration for block-based formats is not available or suitable [S2, S3].
*   Use when the data has local coherence, allowing min/max values to tightly bound the block content.

**When Not to Use:**
*   Avoid when global quantization provides sufficient compression with lower overhead [S15134-global-quantization.md].
*   Avoid when high fidelity is required at very low bitrates, as the error accumulation is significant [S1].

## Background
Scalar quantization, specifically per-block scalar quantization, has been employed in compressed GPU-based direct volume rendering since at least 2008 [YNV08, IGM10, cited in S2, S3]. It is a fundamental technique for enabling random-access decompression on GPUs, allowing voxels to be reconstructed on-the-fly without decompressing the entire volume into main memory [S2, S3]. The method is widely cited in surveys of compressed volume rendering as a standard approach for balancing compression ratio and rendering performance [S2, S3].
