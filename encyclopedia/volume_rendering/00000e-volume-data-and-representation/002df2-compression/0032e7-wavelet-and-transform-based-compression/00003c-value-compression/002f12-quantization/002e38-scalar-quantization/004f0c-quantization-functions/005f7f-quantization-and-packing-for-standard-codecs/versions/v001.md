# Quantization and Packing for Standard Codecs

Also called: Canvas Packing, Feature Quantization

## Overview
This method maps multichannel floating-point feature planes to fixed-precision integer canvases compatible with standard image and video codecs (e.g., JPEG, AV1) [S1]. It solves the incompatibility between neural volume representations (which output high-dimensional, continuous tensors) and standard compression pipelines (which expect 1- or 3-channel, fixed-bit-depth images) [S1]. It sets itself apart from generic quantization by explicitly coupling the numerical range mapping with spatial channel packing strategies designed to minimize cross-channel mixing artifacts during codec encoding [S1].

## How it works
**Inputs:**
- Appearance planes $P$: A tensor of shape $[C, H, W]$ where $C$ is the number of channels (e.g., $C=48$).
- Density grid $D$: A tensor representing opacity/density.
- Quantization strategy: `AbsMax` or `Channelwise` [S1].

**Outputs:**
- Packed canvases $Y$: Tensors with $C_{out} \in \{1, 3\}$ channels, ready for codec input.
- Metadata: Quantization bounds $[\alpha, \beta]$ per channel or global [S1].

**Data Structures:**
- **Canvas:** A 3D tensor $Y \in \mathbb{R}^{C_{out} \times H' \times W'}$ with values in $[0, 1]$ (normalized) or integer range depending on codec stage.
- **Bounds:** For `AbsMax`, a single pair $[\alpha, \beta]$. For `Channelwise`, a list of pairs $[\alpha_c, \beta_c]$ for each channel $c$.

**Steps:**

1. **Quantization Range Estimation:**
   - If `AbsMax`: Determine a fixed range $[\alpha, \beta]$ shared by all channels. Typically, this is the global minimum and maximum of the tensor $X$ [S1].
   - If `Channelwise`: For each channel $c$, compute the central 95% range. Let $\alpha_c$ be the 2.5th percentile and $\beta_c$ be the 97.5th percentile of channel $c$'s values [S1].

2. **Normalization to [0, 1]:**
   For each element $X$ in the input tensor (or per-channel element $X_c$):
   $$
   X_{01} = \mathrm{clip}\left(\frac{X - \alpha}{\beta - \alpha}, 0, 1\right)
   $$
   Dequantization for reconstruction is:
   $$
   \widehat{X} = X_{01}(\beta - \alpha) + \alpha
   $$
   [S1]

3. **Packing:**
   Map the normalized tensor $X_{01}$ to a canvas $Y$ with $C_{out} \in \{1, 3\}$ channels. Three strategies are defined for appearance planes $P$ with $C=48$ [S1]:
   - **FlattenGray:** Stacks all channels spatially into a single monochrome canvas. For $C=48$, the layout becomes $[1, 6H, 8W]$. This avoids cross-channel mixing [S1].
   - **FlattenRGB:** Groups channels into three equal groups (e.g., 16 channels each). The layout becomes $[3, 4H, 4W]$ [S1].
   - **PixelShuffle:** Rearranges channels into spatial neighborhoods (spatial-to-depth). The layout also becomes $[3, 4H, 4W]$ [S1].

   For the density grid $D$, tile it into a single monochrome canvas (1 channel) and encode as grayscale to avoid mixing across channels [S1].

4. **Codec Encoding:**
   Invoke the codec $\mathcal{C}_q$ on each canvas $Y$ to produce a bitstream $b$ and reconstructed canvas $\widehat{Y}$ [S1].

**Edge Cases and Pitfalls:**
- **Precision:** Quantization introduces error. `Channelwise` preserves per-channel dynamic range better than `AbsMax` if channels have different scales [S1].
- **Boundary:** Clipping to $[0, 1]$ discards outliers outside the estimated range [S1].
- **Mixing:** Packing strategies like `FlattenRGB` and `PixelShuffle` mix channel information spatially, which may interact poorly with codecs that assume color correlation. `FlattenGray` avoids this but may be less efficient for RGB codecs [S1].

## Subtopics

### 16-bit PNG Parameter Compression
- **Definition:** Compresses parameters into two 8-bit PNG files representing the low and high bytes of 16-bit quantized values [S2, unofficial].
- **Method:** Reshape the parameter grid to a target image side length `n_sidelen`. Compute per-channel min/max. Normalize to $[0, 1]$, scale to $[0, 65535]$, round to `uint16`. Split into low and high bytes. Save as separate PNGs [S2, unofficial].
- **Formula:** $img = \lfloor \frac{grid - mins}{maxs - mins} \times 65535 \rceil$ [S2, unofficial].
- **Parameters:** `n_sidelen` (int): target image side length for reshaping the parameter grid [S2, unofficial].
- **Code:**
  ```python
  img_l = img & 0xFF
  img_u = (img >> 8) & 0xFF
  ```
  [S2, unofficial]

## Operating characteristics
- **Time Complexity:** Quantization is $O(C \cdot H \cdot W)$. Packing is $O(C \cdot H \cdot W)$. Codec encoding depends on the specific codec (e.g., JPEG, AV1) but is generally linear in the number of pixels.
- **Memory Complexity:** The packed canvas requires $C_{out} \cdot H' \cdot W'$ space. For `FlattenGray`, $H' \cdot W' = C \cdot H \cdot W$, so memory is similar to the input. For `FlattenRGB` and `PixelShuffle`, the spatial dimensions are reduced, but the total number of pixels remains $C \cdot H \cdot W$ [S1].
- **Performance:** CATRF with this method achieves BD-rate improvements of -40.5% to -63.3% compared to TeTriRF across different codecs and bitrates [S1].
- **Strengths:** Compatible with standard, widely available codecs. `Channelwise` quantization preserves detail in high-dynamic-range channels.
- **Limitations:** Quantization error is irreversible. Packing strategies may introduce artifacts if the codec does not handle the spatial arrangement well. `FlattenGray` may not be efficient for RGB-optimized codecs [S1].

## Background
This method is part of the CATRF (Codec-Adaptive TriPlane Radiance Fields) framework for volumetric content delivery [S1]. It addresses the need to compress neural radiance fields (NeRFs) and similar representations for streaming and storage using standard image/video codecs [S1]. The approach was introduced in the CATRF paper [S1].
