# TetSplat Pre-processing and Data Layout

Also called: TetSplat Quantization and Bitstring Packing

## Overview
TetSplat Pre-processing and Data Layout is the method for converting a tetrahedral mesh into a compressed, hierarchical binary format suitable for real-time volume rendering and clipping [S1, unofficial]. It solves the problem of efficiently storing and transmitting multi-field scalar data on unbalanced tree structures (Shell quadtree and Solid octree) by quantizing values into a compact bitstring and embedding traversal pointers [S1, unofficial]. It differs from general volume compression by specifically targeting the hybrid Shell/Solid representation of tetrahedral meshes, where the Shell stores boundary triangles and the Solid stores interior tetrahedra, requiring distinct node layouts and boundary label management [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A tetrahedral mesh partitioned across multiple CPU nodes, containing multiple scalar field values per element.
*   **Output:** A single binary data stream on the filesystem, containing the compressed Shell and Solid hierarchical structures in breadth-first order [S1, unofficial].

**Data Structures and Layout**
The method uses two primary node types: Solid nodes (for tetrahedra) and Shell nodes (for triangles).

1.  **Solid Node Layout:**
    *   **Base Size:** 6 bytes.
    *   **Content:** Contains two scalar field values packed into a binary bitstring.
    *   **Expansion:** Each additional field value adds 2 bytes to the bitstring [S1, unofficial].
    *   **Pointer:** For unbalanced octrees, a 4-byte integer pointer is inserted for each group of parents to the first node of their group of children to enable fast traversal [S1, unofficial].

2.  **Shell Node Layout:**
    *   **Base Size:** 8 bytes (6 bytes base + 2 bytes extra).
    *   **Content:** The extra 2 bytes hierarchically encode:
        *   Normal vector: 14 bits.
        *   Width of normal cone: 2 bits [S1, unofficial].
    *   **Pointer:** For unbalanced quadtrees, a 4-byte integer pointer is inserted for each group of parents to the first node of their group of children [S1, unofficial].

**Parameters**
*   **Quantization Precision:** 15 bits per scalar field value is sufficient for the studied datasets [S1, unofficial].
*   **Normalization:** Scalar field values are normalized to the range $[0, 1]$ before quantization [S1, unofficial].

**Algorithm Steps**
1.  **Partitioning:** Partition the tetrahedral mesh onto multiple CPU nodes [S1, unofficial].
2.  **Parallel Pre-processing:** Each node runs its own pre-processing on its mesh fragment [S1, unofficial].
3.  **Normalization and Quantization:**
    *   Normalize each scalar field value to $[0, 1]$ [S1, unofficial].
    *   Quantize values using a lookup table. The bitstring is constructed by packing the quantized values. For a node with $k$ field values, the bitstring length is $6 + 2(k-2)$ bytes for Solid nodes, assuming $k \ge 2$ [S1, unofficial].
4.  **Boundary Label Update (Cleanup):**
    *   Trim triangles from the Shell that are shared between fragments.
    *   Add these shared triangles to the Solid [S1, unofficial].
    *   Update the boundary label assignment for tetrahedra and triangles in the Solid [S1, unofficial].
5.  **Tree Construction:**
    *   Build the Shell quadtree and Solid octree.
    *   Insert 4-byte integer pointers for parent groups to the first child in each group to handle unbalanced tree traversal [S1, unofficial].
6.  **File Output:**
    *   Flush the compressed hierarchical data structures to the filesystem as a single binary data stream [S1, unofficial].
    *   Save trees in breadth-first order to facilitate fast top-down multi-resolution rendering [S1, unofficial].

**Pseudocode**
```python
def preprocess_tetmesh(mesh, num_fields):
    """
    Pre-processes a tetrahedral mesh for TetSplat rendering.
    
    Args:
        mesh: Tetrahedral mesh data structure.
        num_fields: Number of scalar field values per element.
        
    Returns:
        binary_stream: Single binary data stream of Shell and Solid nodes.
    """
    # Step 1: Partition mesh (conceptual, handled by parallel framework)
    partitions = partition_mesh(mesh)
    
    all_shell_nodes = []
    all_solid_nodes = []
    
    for partition in partitions:
        # Step 2: Parallel Pre-processing
        shell_nodes, solid_nodes = process_partition(partition, num_fields)
        
        # Step 3: Cleanup and Boundary Label Update
        # Trim shared triangles from Shell and add to Solid
        shared_triangles = find_shared_triangles(shell_nodes, solid_nodes)
        for tri in shared_triangles:
            shell_nodes.remove(tri)
            solid_nodes.append(tri)
            
        # Update boundary labels for Solid
        update_boundary_labels(solid_nodes)
        
        all_shell_nodes.extend(shell_nodes)
        all_solid_nodes.extend(solid_nodes)
        
    # Step 4: Construct Trees and Insert Pointers
    shell_tree = build_quadtree(all_shell_nodes)
    solid_tree = build_octree(all_solid_nodes)
    
    insert_traversal_pointers(shell_tree)
    insert_traversal_pointers(solid_tree)
    
    # Step 5: Flatten to Binary Stream (Breadth-First)
    binary_stream = flatten_tree_breadth_first(shell_tree)
    binary_stream += flatten_tree_breadth_first(solid_tree)
    
    return binary_stream

def quantize_value(value, min_val, max_val):
    """
    Normalize to [0, 1] and quantize to 15-bit integer.
    """
    normalized = (value - min_val) / (max_val - min_val)
    # Clamp to [0, 1]
    normalized = max(0.0, min(1.0, normalized))
    # Quantize to 15 bits (0 to 32767)
    quantized = int(normalized * 32767)
    return quantized

def pack_solid_node(field_values):
    """
    Pack field values into a 6-byte Solid node bitstring.
    Assumes 2 base fields + 2 bytes per additional field.
    """
    # 6 bytes = 48 bits
    # 15 bits per field
    # 2 fields = 30 bits used. 18 bits padding/reserved?
    # The source says "6 bytes total. Contains two field values packed into the bitstring."
    # It does not specify padding bits, but 2*15 = 30 bits < 48 bits.
    # We assume the bitstring is packed sequentially.
    
    bitstring = ""
    for val in field_values:
        q_val = quantize_value(val)
        # Convert to 15-bit binary string
        bits = format(q_val, '015b')
        bitstring += bits
        
    # Pad to 48 bits if necessary (though 2 fields = 30 bits)
    # The source implies fixed 6-byte layout for 2 fields.
    # We assume the remaining bits are zero or reserved.
    bitstring = bitstring.ljust(48, '0')
    
    return bytes_from_bitstring(bitstring)

def pack_shell_node(field_values, normal, cone_width):
    """
    Pack field values and normal info into an 8-byte Shell node bitstring.
    """
    # 8 bytes = 64 bits
    # 6 bytes for fields (same as Solid)
    # 2 bytes for normal (14 bits) and cone width (2 bits)
    
    field_bits = ""
    for val in field_values:
        q_val = quantize_value(val)
        bits = format(q_val, '015b')
        field_bits += bits
        
    # Pad field bits to 48 bits
    field_bits = field_bits.ljust(48, '0')
    
    # Encode normal (14 bits) and cone width (2 bits)
    # Normal encoding details are referenced as [20, 18], not fully specified here.
    # We assume a hierarchical encoding scheme.
    normal_bits = encode_normal_hierarchically(normal) # 14 bits
    cone_bits = format(cone_width, '02b') # 2 bits
    
    extra_bits = normal_bits + cone_bits
    
    return bytes_from_bitstring(field_bits + extra_bits)

def insert_traversal_pointers(tree):
    """
    Insert 4-byte int pointers for parent groups to first child.
    """
    for node in tree.nodes:
        if node.has_children():
            # Group children
            child_groups = group_children(node.children)
            for group in child_groups:
                # Insert 4-byte pointer to first child of group
                node.pointers.append(group[0].address)
```

## Operating characteristics
*   **Memory Overhead:** The inclusion of 32-bit traversal pointers has a much lower relative memory overhead for the Solid structure than for the Shell. Although the Solid is typically several orders of magnitude larger than the Shell, its average branching factor is twice as high, leading to fewer internal nodes and thus fewer pointers [S1, unofficial].
*   **Performance:** The breadth-first storage order facilitates fast top-down multi-resolution rendering [S1, unofficial]. The use of `mmap` allows the visualization CPU node to avoid loading the entire data structure into physical memory [S1, unofficial].
*   **Scalability:** The pre-processing is readily parallelized by partitioning the tetrahedral mesh onto multiple computational nodes [S1, unofficial].

## Background
TetSplat was introduced by Museth and Lombeyda in 2004 for the real-time rendering and volume clipping of large tetrahedral meshes [S1, unofficial]. The method builds on the QSplat rendering strategy, adapting it for tetrahedral volumes by separating the mesh into a Shell (boundary) and Solid (interior) representation [S1, unofficial]. The normal encoding in Shell nodes references prior work [20, 18], which are not included in the provided sources [S1, unofficial].
