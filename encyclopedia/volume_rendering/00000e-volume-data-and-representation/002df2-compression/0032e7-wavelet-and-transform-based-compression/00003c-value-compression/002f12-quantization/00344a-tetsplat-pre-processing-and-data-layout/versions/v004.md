# TetSplat Pre-processing and Data Layout

Also called: TetSplat Quantization and Bitstring Packing

## Overview
TetSplat Pre-processing and Data Layout is the final stage of the TetSplat pipeline, responsible for quantizing scalar field values, packing them into a compact binary format, and serializing the hierarchical Shell and Solid data structures to disk [S1, unofficial]. It solves the problem of efficiently storing large tetrahedral meshes with multiple scalar fields for interactive visualization, enabling fast top-down multi-resolution rendering via memory-mapped file access [S1, unofficial]. It differs from general volume compression by specifically targeting unbalanced octrees (Solid) and quadtrees (Shell) with embedded traversal pointers and hierarchical normal encoding, rather than using uniform grid quantization or standard wavelet transforms [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   Partitioned tetrahedral mesh fragments (Shell and Solid components) [S1, unofficial].
*   Scalar field values associated with tetrahedra [S1, unofficial].
*   Normal vectors for Shell triangles [S1, unofficial].

**Outputs:**
*   A single binary data stream per mesh partition, containing the serialized Shell and Solid hierarchical structures [S1, unofficial].

### Data Structures and Layout

#### Solid Node Layout
The Solid structure uses an unbalanced octree. Each node contains:
*   **Field Data:** A bitstring containing quantized scalar field values.
    *   Base size: 6 bytes (48 bits) for two field values.
    *   Expansion: Each additional field value adds 2 bytes (16 bits) to the bitstring [S1, unofficial].
*   **Traversal Pointers:** For unbalanced trees, a 4-byte integer pointer is inserted for each group of parents to the first node of their group of children [S1, unofficial].

#### Shell Node Layout
The Shell structure uses an unbalanced quadtree. Each node contains:
*   **Field Data:** Same bitstring layout as Solid (6 bytes base + 2 bytes per additional field) [S1, unofficial].
*   **Normal Encoding:** An extra 2 bytes (16 bits) hierarchically encoding:
    *   Normal vector: 14 bits [S1, unofficial].
    *   Width of normal cone: 2 bits [S1, unofficial].
*   **Traversal Pointers:** Same 4-byte integer pointer mechanism as Solid [S1, unofficial].

### Parameters
*   **Quantization Precision:** 15 bits per scalar field value. This was found sufficient to represent all relevant field values for the studied datasets [S1, unofficial].
*   **Normalization:** Scalar field values are normalized to the range $[0, 1]$ before quantization [S1, unofficial].
*   **Lookup Table:** Quantization is performed using a lookup table [S1, unofficial].

### Steps

1.  **Parallel Partitioning:** Partition the tetrahedral mesh onto multiple CPU nodes. Each node runs its own pre-processing on its fragment [S1, unofficial].
2.  **Cleanup and Boundary Update:**
    *   Trim shared triangles from the Shell components of adjacent fragments.
    *   Add these trimmed triangles to the Solid components [S1, unofficial].
    *   Update the boundary label assignment for tetrahedra and triangles in the Solid [S1, unofficial].
3.  **Normalization and Quantization:**
    *   Normalize each scalar field value to $[0, 1]$.
    *   Quantize the normalized values using a lookup table with 15-bit precision [S1, unofficial].
4.  **Bitstring Packing:**
    *   Pack the quantized field values into a bitstring.
    *   Start with a 6-byte block for the first two field values.
    *   Append 2-byte blocks for each subsequent field value [S1, unofficial].
5.  **Normal Encoding (Shell only):**
    *   Encode the normal vector (14 bits) and normal cone width (2 bits) into an additional 2-byte block for each Shell node [S1, unofficial].
6.  **Pointer Insertion:**
    *   For unbalanced Shell (quadtree) and Solid (octree) nodes, insert a 4-byte integer pointer for each group of parents to the first node of their group of children to enable fast traversal [S1, unofficial].
7.  **Serialization:**
    *   Flush the compressed hierarchical data structures to the filesystem as a single binary data stream [S1, unofficial].
    *   Save trees in breadth-first order to facilitate fast top-down multi-resolution rendering [S1, unofficial].

### Edge Cases and Pitfalls
*   **Memory Overhead:** The relative memory overhead of 32-bit traversal pointers is much higher for the Shell than for the Solid. Although the Solid is typically larger, its average branching factor is twice as high, leading to fewer internal nodes and thus fewer pointers [S1, unofficial].
*   **Unbalanced Trees:** Pointers are only needed for unbalanced trees. Balanced trees do not require embedded pointers [S1, unofficial].
*   **Precision:** 15 bits is sufficient for the studied datasets, but may not be sufficient for all data types. Lower precision may lead to loss of relevant field information [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** Pre-processing is parallelizable across CPU nodes. The cleanup process requires synchronization to trim shared triangles [S1, unofficial].
*   **Memory Complexity:** The memory overhead of traversal pointers is significant for the Shell due to its lower branching factor. The Solid has lower relative overhead due to its higher branching factor [S1, unofficial].
*   **Performance:** Enables interactive visualization by allowing memory-mapped file access (`mmap`) to avoid loading the entire structure into physical memory [S1, unofficial].
*   **Strengths:** Compact storage, fast top-down rendering, parallelizable pre-processing [S1, unofficial].
*   **Limitations:** Requires unbalanced tree traversal logic, 15-bit precision may not be sufficient for all datasets [S1, unofficial].

## Background

*   **Origin:** TetSplat was introduced by Museth and Lombeyda in 2004 [S1, unofficial].
*   **History:** The method builds on QSplat's file layout strategy, adapting it for tetrahedral meshes with multiple scalar fields [S1, unofficial].
*   **Usage:** Used for interactive visualization and volume clipping of large tetrahedral meshes [S1, unofficial].
