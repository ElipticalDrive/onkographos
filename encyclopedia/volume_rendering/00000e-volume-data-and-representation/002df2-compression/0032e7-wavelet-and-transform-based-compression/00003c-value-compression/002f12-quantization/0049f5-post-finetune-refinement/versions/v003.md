# Post-finetune Refinement

Also called: Post-finetune process, finetuning procedure, post-finetune

## Overview
Post-finetune Refinement is a method that uses a small number of bits to enhance the reconstruction quality of important voxels, compensating for losses introduced by coarse quantization [S1]. It addresses the trade-off between bitrate and rendering fidelity by allowing the model to recover detail that would otherwise be lost during the discretization step of the compression pipeline [S1]. Unlike standard quantization which maps values to a fixed grid, this method actively adjusts the latent representation after an initial training or coding phase to optimize the rate-distortion performance [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** The quantized or coarse latent representation of the volume data (e.g., voxel grid features), depth maps $D$, and camera parameters ($K, T$) for multiple views [S2, unofficial].
*   **Output:** A refined feature representation $F_{dec}$ (or $F_c$) that yields higher PSNR/SSIM with minimal additional bitrate overhead [S2, unofficial].

**Data Structures:**
*   **Feature Tensor ($F$):** A 3D or 4D tensor representing voxel intensities or neural network features [S2, unofficial].
*   **Depth Map ($D$):** A 2D map storing depth values for each pixel in a view [S2, unofficial].
*   **Camera Parameters:** Intrinsic matrix $K$ and extrinsic matrix $T$ for source and reference views [S2, unofficial].

**Steps:**
1.  **Geometry-Aligned Multi-View Feature Aggregation:** For each reference view $r$, obtain geometry-aligned multi-view features $A_r$ by warping neighboring source-view features to the reference view [S2, unofficial]. This involves back-projecting reference-view pixels using reference depth $D_r$ to 3D, projecting these 3D points to source view $s$, bilinearly sampling the source feature tensor $F_s$ at the projected coordinates, encoding the inverse depth $d^{-1}_{r \to s}$ of the back-projected point in the source camera, fusing the reference feature $F_r$ and the warped source feature using a learned operator $\Phi$, and aggregating valid pairwise features using an averaging operator $\text{Avg}$ [S2, unofficial]. The formula is [S2, unofficial]:
    $$ A_r(F, D) = \text{Avg}_{s \neq r} \Phi \left( F_r, \text{Warps}_{\to r}(F_s; D_r, K_r, T_r, K_s, T_s), E(d^{-1}_{r \to s}) \right) $$
    Where:
    *   $\text{Warps}_{\to r}$ back-projects reference-view pixels using $D_r$, projects to source view $s$, and bilinearly samples $F_s$ [S2, unofficial].
    *   $d_{r \to s}$ is the depth of the back-projected reference point in the source camera [S2, unofficial].
    *   $E$ encodes the inverse depth [S2, unofficial].
    *   $\Phi$ is a learned pairwise feature fusion operator [S2, unofficial].
    *   $\text{Avg}$ averages valid pairwise features [S2, unofficial].

2.  **Residual Update:** 
    *   **Pre-Codec Refinement:** The feature to be compressed $F_c$ is produced by a residual update [S2, unofficial]:
        $$ F_c = F_g + R_{pre}(F_g, A(F_g, D_{enc})) $$
        Where $F_g$ is the initial feature and $D_{enc}$ is the encoded depth [S2, unofficial].
    *   **Post-Codec Refinement:** Once the reconstructed feature $\hat{F}_c$ and codec-side depth $\hat{D}$ are available, the post-codec refiner produces the final decoded feature $F_{dec}$ [S2, unofficial]:
        $$ F_{dec} = \hat{F}_c + R_{post}(\hat{F}_c, A(\hat{F}_c, \hat{D})) $$
        Where $R_{pre}$ and $R_{post}$ are learned refinement networks [S2, unofficial].

**Parameters:**
*   **Rate Parameter ($\lambda$):** Selects the rate point of the model [S2, unofficial]. A larger $\lambda$ emphasizes bitrate reduction during training [S1].
*   **Typical Values:** Not given in the sources [S1][S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Disabling Refinement:** Disabling post-finetune saves bits but inevitably deteriorates rendering quality [S1]. On the Synthetic-NeRF dataset, disabling it causes a $\Delta$PSNR of $-1.72$ dB, $\Delta$SSIM of $-0.07$, and $\Delta$Size of $-0.079$ MB [S1].
*   **Precision:** The method relies on accurate depth estimation and warping; errors in depth $D$ can lead to misaligned features and artifacts [S2, unofficial].

**Pseudocode:**
```python
def post_finetune_refinement(F_hat, D_hat, K_ref, T_ref, source_views, Phi, R_post):
    """
    Performs post-codec refinement for a single reference view.
    Args:
        F_hat: Reconstructed feature tensor for the reference view (H, W, C).
        D_hat: Codec-side depth map for the reference view (H, W).
        K_ref, T_ref: Intrinsic (3x3) and extrinsic (4x4) parameters for the reference view.
        source_views: List of dicts with keys 'F_s', 'D_s', 'K_s', 'T_s' for neighboring source views s.
        Phi: Learned pairwise feature fusion operator [G].
        R_post: Learned post-codec refinement network [G].
    Returns:
        F_dec: Refined decoded feature tensor.
    """
    import numpy as np
    H, W = D_hat.shape
    A_r = np.zeros_like(F_hat)
    valid_count = np.zeros((H, W), dtype=np.float32)

    for view in source_views:
        F_s, D_s, K_s, T_s = view['F_s'], view['D_s'], view['K_s'], view['T_s']
        
        # 1. Back-project reference-view pixels using reference depth D_hat to 3D
        inv_K_ref = np.linalg.inv(K_ref)
        y, x = np.meshgrid(np.arange(H), np.arange(W))
        ones = np.ones_like(x)
        pix = np.stack([x, y, ones], axis=-1).astype(np.float32)
        cam_pts = (inv_K_ref @ pix.reshape(-1, 3).T).T.reshape(H, W, 3)
        pts_3d_ref = cam_pts * D_hat[:, :, np.newaxis]
        pts_3d_world = (T_ref[:3, :3] @ pts_3d_ref.reshape(-1, 3).T).T.reshape(H, W, 3) + T_ref[:3, 3]

        # 2. Project 3D points to source view s
        inv_T_src = np.linalg.inv(T_s)
        pts_3d_src_cam = (inv_T_src[:3, :3] @ (pts_3d_world - inv_T_src[:3, 3]).T).T.reshape(H, W, 3)
        pix_src = (K_s @ pts_3d_src_cam.T).T.reshape(H, W, 3)
        u_src = pix_src[:, :, 0] / (pix_src[:, :, 2] + 1e-6)
        v_src = pix_src[:, :, 1] / (pix_src[:, :, 2] + 1e-6)
        d_r_to_s = pts_3d_src_cam[:, :, 2]

        # 3. Bilinearly sample source feature tensor F_s
        u_c = np.clip(u_src, 0, F_s.shape[1] - 1)
        v_c = np.clip(v_src, 0, F_s.shape[0] - 1)
        warped = bilinear_sample(F_s, v_c, u_c)

        # 4. Encode inverse depth (standard quantization step) [G]
        inv_depth = 1.0 / (d_r_to_s + 1e-6)
        enc_depth = np.round(inv_depth * 1000).astype(np.int32)

        # 5. Learned pairwise feature fusion
        fused = Phi(F_hat, warped, enc_depth)

        # 6. Aggregate valid pairwise features
        valid_mask = (d_r_to_s > 0) & (u_src >= 0) & (u_src < F_s.shape[1]) & (v_src >= 0) & (v_src < F_s.shape[0])
        A_r = np.where(valid_mask, A_r + fused, A_r)
        valid_count = np.where(valid_mask, valid_count + 1, valid_count)

    # Average valid pairwise features
    valid_count = np.maximum(valid_count, 1.0)
    A_r = A_r / valid_count[:, :, np.newaxis]

    # Residual update
    residual = R_post(F_hat, A_r)
    F_dec = F_hat + residual
    return F_dec

def bilinear_sample(tensor, y, x):
    y0, x0 = np.floor(y).astype(int), np.floor(x).astype(int)
    y1, x1 = np.clip(y0 + 1, 0, tensor.shape[0] - 1), np.clip(x0 + 1, 0, tensor.shape[1] - 1)
    y0, x0 = np.clip(y0, 0, tensor.shape[0] - 1), np.clip(x0, 0, tensor.shape[1] - 1)
    wa, wb, wc, wd = (x1 - x) * (y1 - y), (x1 - x) * (y - y0), (x - x0) * (y1 - y), (x - x0) * (y - y0)
    return wa * tensor[y0, x0] + wb * tensor[y0, x1] + wc * tensor[y1, x0] + wd * tensor[y1, x1]
```

## Subtopics

### Depth-guided Multi-view Feature Refinement
A pre- and post-codec refinement step that uses depth-guided multi-view interaction to align features geometrically and reduce cross-view redundancy before latent coding, and to compensate for compression artifacts after decoding [S2, unofficial]. It is chosen when multi-view consistency is critical and depth information is available [S2, unofficial]. It differs from single-view refinement by explicitly leveraging geometric alignment across views [S2, unofficial]. See [CodecSplat](52-codecsplat.md) for implementation details [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** The refinement step adds computational overhead due to warping, sampling, and neural network inference ($\Phi$ and $R_{post}$) [S2, unofficial]. The exact complexity depends on the number of views and resolution [S2, unofficial].
*   **Memory:** Requires storing depth maps and intermediate warped features. The refinement networks add model size [S2, unofficial].

**Measured Performance:**
*   On the Synthetic-NeRF dataset, disabling post-finetune results in a $-1.72$ dB drop in PSNR and a $-0.07$ drop in SSIM, while saving $0.079$ MB [S1].
*   The method allows for a small number of bits to enhance reconstruction quality, compensating for coarse quantization losses [S1].

**Scaling:**
*   Performance scales with the number of views and the accuracy of depth estimation [S2, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Significantly improves rendering quality (PSNR/SSIM) with minimal bitrate increase. Effective at recovering details lost during quantization [S1].
*   **Limitations:** Requires accurate depth information. Adds computational complexity. If depth is inaccurate, artifacts may be introduced [S2, unofficial].

**When to Use:**
*   Use when high-fidelity reconstruction is required and a small bitrate overhead is acceptable [S1].
*   Use when depth information is available and reliable [S2, unofficial].

**When Not to Use:**
*   Use when bitrate is extremely constrained and quality degradation is acceptable [S1].
*   Use when depth information is unavailable or unreliable [S2, unofficial].

## Background
Post-finetune Refinement originates from research into spatial predictive compression for voxel-based radiance fields, specifically in the context of SPC-NeRF [S1]. It was developed to address the limitations of coarse quantization in neural radiance field compression [S1]. The method was further adapted in CodecSplat for 3D Gaussian Splatting compression, where it was extended to multi-view settings [S2, unofficial].
