# Unquantization Functions

Also called: Unquantize10, Unquantize7, Unquantize9

## Overview
Unquantization functions reconstruct continuous floating-point values from discrete integer indices produced by quantization schemes, specifically within the context of BC6H texture compression [S1, unofficial]. While the parent [Quantization](5935-quantization.md) maps continuous space to discrete indices, unquantization performs the inverse mapping. This method is distinct from general scalar or vector quantization by its specific integration into block-based compression pipelines where endpoint reconstruction and interpolation are required for final pixel values [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: Integer quantized values (indices), scale factors, and optionally interpolation weights.
*   Output: Half-precision (16-bit) or full-precision (32-bit) floating-point values.

**Data Structures:**
The implementation relies on standard integer types (`uint8_t`, `int`) and floating-point types (`half`, `float`). No complex custom structures are required for the core unquantization logic itself, though it operates on data loaded into memory buffers as shown in the source [S1, unofficial].

**Formulas and Steps:**

1.  **Half-Precision Unquantization:**
    Converts an integer index back to a half-precision float range.
    $$ \text{Half}(x) = \frac{\text{Int}(x) \times 65536 + 32768}{\text{Scale}} $$
    *   $\text{Int}(x)$: The quantized integer value.
    *   $65536$: Scaling factor related to the half-precision dynamic range.
    *   $32768$: Bias term for rounding.
    *   $\text{Scale}$: The quantization scale factor derived during the encoding phase.

2.  **Finish Unquantization (Interpolation):**
    Interpolates between two unquantized endpoints using a weight to produce a final 32-bit float result. This is typically used for intermediate values in block compression.
    $$ \text{Result} = \text{f16tof32}\left( \frac{(\text{endpoint0Unq} \times (64 - \text{weight}) + \text{endpoint1Unq} \times \text{weight} + 32) \times 31}{4096} \right) $$
    *   $\text{endpoint0Unq}$: The first unquantized endpoint value (half-precision).
    *   $\text{endpoint1Unq}$: The second unquantized endpoint value (half-precision).
    *   $\text{weight}$: The interpolation weight (integer, typically 0-63).
    *   $\text{f16tof32}$: Conversion from half-precision to single-precision float.
    *   $31/4096$: Scaling factor for the interpolation result.

**Pseudocode:**
```python
def unquantize_half(int_val: int, scale: float) -> float:
    """
    Converts integer quantized value to half-precision float range.
    """
    # Formula: (Int(x) * 65536 + 32768) / Scale
    numerator = (int_val * 65536) + 32768
    return numerator / scale

def finish_unquantize(endpoint0: float, endpoint1: float, weight: int) -> float:
    """
    Interpolates between two unquantized endpoints and converts to float3.
    Assumes endpoints are already in half-precision float format.
    """
    # Formula: f16tof32( (endpoint0Unq * (64 - weight) + endpoint1Unq * weight + 32) * (31 / 4096) )
    
    # Perform interpolation in integer-like arithmetic space before scaling
    # Note: endpoint0 and endpoint1 are floats representing half-precision values.
    # The formula implies a specific fixed-point or scaled integer arithmetic context
    # often found in BC6H implementations. We follow the literal formula.
    
    term1 = endpoint0 * (64 - weight)
    term2 = endpoint1 * weight
    sum_terms = term1 + term2 + 32
    
    scaled_result = sum_terms * (31 / 4096)
    
    # Convert to final float32. In many GPU implementations, this might involve
    # specific hardware instructions or bit-casting. Here we assume standard float conversion.
    return float(scaled_result)
```

**Edge Cases:**
*   **Division by Zero:** The `scale` parameter in `unquantize_half` must not be zero. If scale is zero, the input data is likely invalid or requires special handling (e.g., treating as zero or infinity) [G].
*   **Precision Loss:** Converting from half-precision to float32 (`f16tof32`) is generally lossless in terms of value representation, but the initial quantization step is lossy [S1, unofficial].

## Subtopics

### Finish Unquantize
Interpolates between two unquantized endpoints using a weight and converts to final float3. It is used when a block compression scheme (like BC6H) requires generating intermediate values between two base endpoints. Choose this when the compression format uses linear interpolation between quantized endpoints to represent pixel values within a block. It differs from basic unquantization by including the interpolation step and final float32 conversion [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per value. The operations involve basic arithmetic (multiplication, addition, division).
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Performance:** Extremely fast, suitable for real-time GPU execution. The BC6H decoder relies on these functions for every texel in a block [S1, unofficial].
*   **Strengths:** Low computational overhead, precise control over the reconstruction range via the scale factor.
*   **Limitations:** Accuracy is limited by the initial quantization step. The specific constants (65536, 32768, 31/4096) are tied to the BC6H standard and may not be directly applicable to other compression formats without modification [S1, unofficial].

## Background
Unquantization functions are a critical component of block-compressed texture formats, specifically BC6H (Block Compression 6H) for HDR floating-point textures. The specific formulas and constants (e.g., 65536, 31/4096) are derived from the BC6H specification and its implementation details. The reference implementation provided in the source is part of a real-time GPU BC6H compression library [S1, unofficial].
