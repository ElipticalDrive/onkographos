# Unquantization Functions

Also called: Unquantize10, Unquantize7, Unquantize9

## Overview
Unquantization functions map discrete integer codes back to floating-point values, serving as the inverse of the quantization step in volume data compression. In the context of BC6H-based volume rendering, these functions reconstruct half-precision or full-precision color/volume values from compressed 8-bit indices. They are distinguished from general scalar quantization by their specific fixed-point arithmetic optimizations designed for GPU real-time decompression, particularly handling non-linear weight interpolation for endpoint blending.

## How it works
The method consists of two primary operations: basic unquantization for single endpoints and finish unquantization for interpolated values.

**Inputs and Outputs:**
- **Basic Unquantization:**
  - Input: `Int(x)` (integer quantized value, typically 10-bit or 7-bit depending on variant), `Scale` (scaling factor).
  - Output: Half-precision float (`f16`).
- **Finish Unquantization:**
  - Input: `endpoint0Unq` (unquantized endpoint 0), `endpoint1Unq` (unquantized endpoint 1), `weight` (interpolation weight, 0-63).
  - Output: Full-precision float (`f32`).

**Data Structures:**
- Values are stored as `uint8_t` in the compressed bitstream.
- Intermediate calculations use integer arithmetic to maintain precision before final conversion.

**Formulas:**

1.  **Basic Unquantization (Half):**
    $$ \text{Half}(x) = \frac{\text{Int}(x) \times 65536 + 32768}{\text{Scale}} $$
    Where:
    - $\text{Int}(x)$ is the integer code.
    - $65536$ is $2^{16}$.
    - $32768$ is $2^{15}$, acting as a rounding offset for the fixed-point shift.
    - $\text{Scale}$ is the normalization factor derived from the quantization step.

2.  **Finish Unquantization (Interpolation):**
    $$ \text{Result} = \text{f16tof32}\left( \frac{(\text{endpoint0Unq} \times (64 - \text{weight}) + \text{endpoint1Unq} \times \text{weight} + 32) \times 31}{4096} \right) $$
    Where:
    - $\text{endpoint0Unq}$ and $\text{endpoint1Unq}$ are the half-precision values obtained from the basic unquantization step.
    - $\text{weight}$ is an integer in $[0, 63]$.
    - $32$ is the rounding offset for the 5-bit shift ($2^5$).
    - $31/4096$ is the final scaling factor to map the interpolated integer result back to the float range.
    - $\text{f16tof32}$ converts the resulting half-precision float to a 32-bit float.

**Pseudocode:**

```python
def unquantize_half(int_val: int, scale: float) -> float:
    """
    Converts an integer quantized value back to a half-precision float range.
    Formula: (Int(x) * 65536 + 32768) / Scale
    """
    # Integer arithmetic for precision
    numerator = (int_val * 65536) + 32768
    return numerator / scale

def finish_unquantize(endpoint0_unq: float, endpoint1_unq: float, weight: int) -> float:
    """
    Interpolates between two unquantized endpoints using a weight and converts to final float3.
    Formula: f16tof32( (endpoint0Unq * (64 - weight) + endpoint1Unq * weight + 32) * (31 / 4096) )
    """
    # Calculate weighted sum with rounding offset
    # Note: endpoint values are assumed to be in half-precision range or scaled integers
    # based on the source formula structure.
    
    # If endpoints are already half-floats, we treat them as fixed-point integers for the interpolation
    # or apply the formula directly if they are normalized. 
    # The source formula implies endpoint0Unq and endpoint1Unq are the results of unquantize_half.
    
    # To implement strictly from formula:
    # We assume endpoint0Unq and endpoint1Unq are values in the range [0, 1] or similar,
    # but the formula uses integer-like operations. 
    # Re-interpreting the source formula for float implementation:
    
    # The source formula: (endpoint0Unq * (64 - weight) + endpoint1Unq * weight + 32) * (31 / 4096)
    # This suggests endpoint0Unq and endpoint1Unq might be scaled integers or the formula 
    # is a specific fixed-point approximation.
    
    # Let's implement the exact arithmetic as described:
    term1 = endpoint0_unq * (64 - weight)
    term2 = endpoint1_unq * weight
    sum_val = term1 + term2 + 32
    scaled_val = sum_val * (31 / 4096)
    
    # Convert to float32 (standard float in Python)
    return float(scaled_val)
```

**Edge Cases and Pitfalls:**
- **Precision Loss:** The use of fixed-point arithmetic with rounding offsets ($32768$, $32$) is critical. Using standard floating-point division without these offsets may introduce bias.
- **Weight Range:** The weight must be in $[0, 63]$. Values outside this range will produce incorrect interpolation results.
- **Scale Factor:** The `Scale` parameter must be consistent with the quantization step used during encoding. An incorrect scale will result in values outside the expected range.

## Subtopics

### Finish Unquantize
Interpolates between two unquantized endpoints using a weight and converts to final float3. It is used when a voxel or texel value is derived from a blend of two base endpoints. Choose this when the compression scheme uses weighted interpolation (like BC6H) rather than direct endpoint selection. It differs from basic unquantization by handling the interpolation logic and final scaling to float32.

## Operating characteristics
- **Time Complexity:** $O(1)$ per value. The operations are simple arithmetic additions, multiplications, and divisions.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Performance:** Optimized for GPU execution due to the use of integer arithmetic and fixed-point scaling, minimizing the need for expensive floating-point operations during decompression.
- **Strengths:** High precision reconstruction from low-bit integers; efficient hardware implementation.
- **Limitations:** Limited to the specific quantization scheme (BC6H-like); not general-purpose for arbitrary quantization functions.

## Background
Originating from the BC6H texture compression standard, these functions are adapted for real-time volume rendering. The specific formulas are derived from the need to efficiently decompress 16-bit floating-point data compressed into 8-bit indices on the GPU. The "Finish Unquantize" variant is specific to the interpolation step in BC6H block compression.
