# Unquantization Functions

Also called: Unquantize10, Unquantize7, Unquantize9

## Overview
Unquantization functions map integer quantized values back to half-precision float range [S1, unofficial]. This method is used in the context of BC6H texture compression to reconstruct floating-point color data from compressed integer indices [S1, unofficial]. It differs from general scalar quantization by using specific fixed-point scaling and rounding constants tailored for 16-bit half-precision output [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Integer quantized value $Int(x)$, typically 10-bit or 7-bit depending on the variant, and a scaling factor $Scale$.
- Output: Half-precision float value $Half(x)$.

**Data Structures:**
- The input is an integer index.
- The output is a 16-bit IEEE 754 half-precision float.

**Steps:**
1. Multiply the integer input by 65536.
2. Add 32768 to the result.
3. Divide by the $Scale$ factor.

**Formula:**
$$Half(x) = \frac{Int(x) \times 65536 + 32768}{Scale}$$

**Parameters:**
- $Scale$: A scaling factor determined by the quantization step size. Not given in the sources.

**Edge Cases and Pitfalls:**
- Precision loss occurs if the integer input is not properly aligned with the scale.
- The addition of 32768 acts as a rounding offset for the division.

**Pseudocode:**
```python
def unquantize_half(int_val: int, scale: float) -> float:
    """
    Converts integer quantized values back to half-precision float range.
    Formula: (Int(x) * 65536 + 32768) / Scale
    """
    # Multiply by 65536 and add rounding offset 32768
    numerator = int_val * 65536 + 32768
    # Divide by scale
    result = numerator / scale
    return result
```

## Subtopics

### Finish Unquantize
Interpolates between two unquantized endpoints using a weight and converts to final float3 [S1, unofficial]. Formula: $Result = f16tof32( (endpoint0Unq \times (64 - weight) + endpoint1Unq \times weight + 32) \times (31 / 4096) )$ [S1, unofficial]. Used when blending between two quantized values to produce a 32-bit float result.

## Operating characteristics
Time complexity is $O(1)$ per value. Memory complexity is minimal, requiring only the storage of the integer index and the scale factor. Performance is limited by the precision of the floating-point conversion and the accuracy of the scale factor. Strengths include efficient reconstruction of half-precision data. Limitations include potential quantization error if the scale factor is not accurately determined.

## Background
Originated in the context of BC6H texture compression, specifically in implementations like GPURealTimeBC6H [S1, unofficial]. It is used in real-time graphics applications where efficient texture decompression is required.
