# Unquantization Functions

Also called: Unquantize10, Unquantize7, Unquantize9

## Overview
Unquantization functions convert integer quantized values back to their original floating-point range, serving as the inverse operation to the quantization step in volume data compression [S1, unofficial]. Unlike general scalar quantization which may use uniform or non-uniform tables, these specific functions are tailored for half-precision float reconstruction and weighted interpolation of endpoints, primarily found in block-based compression schemes like BC6H [S1, unofficial].

## How it works
The method consists of two primary operations: basic unquantization to half-precision floats and finish unquantization for interpolated results.

### Inputs and Outputs
- **Input:** Integer quantized values (typically 10-bit or 7-bit indices), scale factors, and optionally a weight for interpolation.
- **Output:** Half-precision floats (`half` or `float16`) or final 32-bit floats (`float3`).

### Data Structures
No complex data structures are required. The operations are element-wise or per-block arithmetic.

### Steps and Formulas

#### 1. Basic Unquantization (Half Conversion)
Converts an integer index to a half-precision float value.

**Formula:**
$$ \text{Half}(x) = \frac{\text{Int}(x) \times 65536 + 32768}{\text{Scale}} $$

**Definitions:**
- $x$: The integer quantized value.
- $\text{Int}(x)$: The integer value of $x$.
- $65536$: Scaling factor related to the half-precision range ($2^{16}$).
- $32768$: Bias term for rounding ($2^{15}$).
- $\text{Scale}$: The quantization scale factor derived from the compression parameters.

**Pseudocode:**
```python
def unquantize_half(int_val, scale):
    # Calculate numerator with rounding bias
    numerator = (int_val * 65536) + 32768
    # Divide by scale to get half-precision float
    return numerator / scale
```

#### 2. Finish Unquantization (Interpolation)
Interpolates between two unquantized endpoints using a weight and converts the result to a final 32-bit float. This is used in block compression (e.g., BC6H) where colors are defined by two endpoints and a 3-bit weight.

**Formula:**
$$ \text{Result} = \text{f16tof32}\left( \frac{(\text{endpoint0Unq} \times (64 - \text{weight}) + \text{endpoint1Unq} \times \text{weight} + 32) \times 31}{4096} \right) $$

**Definitions:**
- $\text{endpoint0Unq}$: The first unquantized endpoint (half-precision).
- $\text{endpoint1Unq}$: The second unquantized endpoint (half-precision).
- $\text{weight}$: The interpolation weight (integer, typically 0-7 for 3-bit weights).
- $64$: $2^6$, representing the total number of weight steps (0 to 63).
- $32$: Rounding bias for the weighted sum.
- $31$: Maximum value for 5-bit precision (often used in RGB channels).
- $4096$: $2^{12}$, normalization factor.
- $\text{f16tof32}$: Conversion from half-precision float to 32-bit float.

**Pseudocode:**
```python
def finish_unquantize(endpoint0_unq, endpoint1_unq, weight):
    # Calculate weighted sum with rounding bias
    # weight is typically 0-7, but formula uses 0-63 range logic
    # Note: The source formula implies weight is scaled or the formula handles the 3-bit weight directly
    # Based on [S1, unofficial]: (endpoint0Unq * (64 - weight) + endpoint1Unq * weight + 32)
    # Then multiplied by 31/4096
    
    weighted_sum = (endpoint0_unq * (64 - weight) + endpoint1_unq * weight + 32)
    
    # Apply scaling factor
    scaled_value = weighted_sum * 31 / 4096
    
    # Convert to float32
    result = float(scaled_value)
    
    return result
```

### Parameters
- **Scale:** Specific to the compression block and channel.
- **Weight:** Integer, typically 0-7 for 3-bit weights in BC6H.

## Subtopics

### Finish Unquantize
Interpolates between two unquantized endpoints using a weight and converts to final float3. It is used in block compression schemes like BC6H to reconstruct pixel values from endpoints and weights. It is chosen when high-quality interpolation between two quantized values is required within a compressed block. Link to [Quantization](5935-quantization.md).

## Operating characteristics
- **Time Complexity:** $O(1)$ per value. The operations are simple arithmetic.
- **Memory Complexity:** $O(1)$. No additional memory is required beyond the input values.
- **Strengths:** Fast, deterministic, and suitable for real-time GPU implementation.
- **Limitations:** Precision is limited by the half-precision format and the quantization scale.
- **When to use:** When decompressing volume data or images compressed with block-based methods like BC6H.
- **When not to use:** When higher precision is required or when the compression scheme does not use these specific unquantization functions.

## Background
Unquantization functions are part of the broader field of data compression, specifically in the context of block-based compression standards like BC6H. The specific formulas and functions described here are derived from implementations of real-time BC6H compression on the GPU [S1, unofficial]. The method is used in graphics APIs and rendering engines to efficiently decode compressed texture data.
