# Unquantization Functions

Also called: Unquantize10, Unquantize7, Unquantize9

## Overview
Unquantization functions reconstruct continuous floating-point values from discrete integer indices produced by quantization schemes, specifically within the context of BC6H texture compression for HDR data [S1, unofficial]. Unlike general scalar quantization which may use linear scaling, these functions employ specific rounding and scaling constants to map 10-bit or 7-bit integers back to half-precision or full float ranges [S1, unofficial]. They serve as the inverse operation to the quantization step, ensuring that the dynamic range and precision characteristics of the original data are preserved as closely as possible within the constraints of the compressed format [S1, unofficial].

## How it works
The method takes integer quantized values and applies a linear transformation with an offset to recover the original floating-point representation. The core operation involves scaling the integer value by a specific factor and adding a rounding bias to ensure correct rounding to the nearest representable float value.

**Inputs:**
- `Int(x)`: The quantized integer value (e.g., 10-bit or 7-bit unsigned integer).
- `Scale`: A normalization constant specific to the quantization range.

**Outputs:**
- `Half(x)`: The reconstructed half-precision floating-point value.

**Data Structures:**
- No complex data structures are required; the operation is element-wise.

**Formulas:**
The primary unquantization formula for converting an integer to a half-precision float is defined as [S1, unofficial]:

$$ \text{Half}(x) = \frac{\text{Int}(x) \times 65536 + 32768}{\text{Scale}} $$

Where:
- `Int(x)` is the input integer.
- `65536` is the scaling multiplier (equivalent to $2^{16}$).
- `32768` is the rounding bias (equivalent to $2^{15}$), ensuring that the result is rounded to the nearest integer before division.
- `Scale` is the divisor that normalizes the value into the target range.

**Pseudocode:**
```python
def unquantize_half(int_val, scale):
    """
    Converts an integer quantized value back to a half-precision float range.
    
    Args:
        int_val (int): The quantized integer value.
        scale (float): The normalization scale factor.
        
    Returns:
        float: The reconstructed half-precision float value.
    """
    # Apply scaling and rounding bias
    # 65536 is 2^16, 32768 is 2^15
    numerator = (int_val * 65536) + 32768
    result = numerator / scale
    return result
```

**Edge Cases and Pitfalls:**
- **Precision Loss:** The use of fixed-point arithmetic with specific biases assumes that the input integers are within the expected range. Out-of-bounds values may produce incorrect results.
- **Scale Factor:** The `Scale` parameter must be consistent with the quantization step used during encoding. An incorrect scale will result in incorrect dynamic range mapping.

## Subtopics

### Finish Unquantize
This variant is used in BC6H compression to interpolate between two unquantized endpoints. It takes two unquantized endpoint values and a weight, then interpolates and converts the result to a final 32-bit float [S1, unofficial]. The formula is [S1, unofficial]:

$$ \text{Result} = \text{f16tof32}\left( \left( \text{endpoint0Unq} \times (64 - \text{weight}) + \text{endpoint1Unq} \times \text{weight} + 32 \right) \times \frac{31}{4096} \right) $$

Where:
- `endpoint0Unq` and `endpoint1Unq` are the unquantized endpoint values (half-precision floats).
- `weight` is the interpolation weight (0 to 63).
- `f16tof32` converts the half-precision result to a full 32-bit float.
- The term `(64 - weight)` and `weight` ensure linear interpolation.
- `+ 32` is a rounding bias.
- `31 / 4096` is the final scaling factor.

## Operating characteristics
- **Time Complexity:** $O(1)$ per value. The operations are simple arithmetic (multiplication, addition, division).
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Performance:** Highly efficient on GPU hardware, as these operations map directly to SIMD instructions.
- **Strengths:** Provides a precise inverse to the quantization step, minimizing reconstruction error when combined with the correct scale factor.
- **Limitations:** Limited to the specific quantization schemes defined by the constants. Not a general-purpose unquantization method.

## Background
The unquantization functions described here originate from the implementation of real-time BC6H compression on the GPU [S1, unofficial]. BC6H is a block compression format for HDR textures, and these functions are part of the decoding pipeline to reconstruct the original floating-point data from the compressed block [S1, unofficial]. The specific constants (65536, 32768, 31/4096) are derived from the BC6H specification and the need to maintain precision in half-precision arithmetic.
