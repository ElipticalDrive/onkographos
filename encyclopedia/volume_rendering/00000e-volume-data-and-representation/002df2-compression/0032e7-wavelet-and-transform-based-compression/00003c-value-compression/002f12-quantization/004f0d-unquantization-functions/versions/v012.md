# Unquantization Functions

Also called: Unquantize10, Unquantize7, Unquantize9

## Overview
Unquantization functions reconstruct continuous floating-point values from discrete integer indices produced by [Quantization](5935-quantization.md). In the context of BC6H compression, these functions map compressed half-precision or 7/9-bit integer representations back to their original dynamic range. They differ from sibling methods like [Scalar Quantization](5726-scalar-quantization.md) by being tightly coupled to the specific bit-packing and endpoint generation logic of block-based texture compression, specifically handling the non-linear or scaled linear mappings required for BC6H.

## How it works
The method operates on integer inputs derived from compressed bitstreams. It performs arithmetic scaling and bias addition to recover the original floating-point magnitude.

**Inputs:**
- `Int(x)`: The quantized integer value (e.g., 10-bit, 9-bit, or 7-bit index).
- `Scale`: The scaling factor derived from the block's endpoints.
- `endpoint0Unq`, `endpoint1Unq`: The unquantized half-precision endpoints for interpolation.
- `weight`: The interpolation weight (typically 6-bit or 7-bit).

**Outputs:**
- Reconstructed half-precision float (`f16`) or final 32-bit float (`f32`) value.

**Data Structures:**
- The implementation assumes access to standard IEEE 754 half-precision and single-precision conversion routines (`f16tof32`).

**Steps:**

1. **Basic Unquantization (Half Reconstruction):**
   For standard half-precision reconstruction from a 10-bit or similar integer index:
   $$ \text{Half}(x) = \frac{\text{Int}(x) \times 65536 + 32768}{\text{Scale}} $$
   - `Int(x)`: The integer quantized value.
   - `65536`: The scaling multiplier (likely related to $2^{16}$ for fixed-point or half-precision alignment).
   - `32768`: The bias term for rounding (half of the multiplier).
   - `Scale`: The normalization factor.

2. **Finish Unquantization (Interpolation):**
   For generating the final 32-bit float value by interpolating between two unquantized endpoints:
   $$ \text{Result} = \text{f16tof32}\left( \frac{(\text{endpoint0Unq} \times (64 - \text{weight}) + \text{endpoint1Unq} \times \text{weight} + 32) \times 31}{4096} \right) $$
   - `endpoint0Unq`, `endpoint1Unq`: Unquantized half-precision endpoint values.
   - `weight`: The interpolation weight (integer, range 0-63 implied by the factor 64).
   - `32`: Rounding bias for the weighted sum.
   - `31 / 4096`: Final scaling factor to map the interpolated integer result back to the float range.

**Edge Cases:**
- **Division by Zero:** If `Scale` is zero, the result is undefined. The source does not specify handling, but in practice, `Scale` should be non-zero.
- **Overflow:** The intermediate calculation `Int(x) * 65536` can overflow 32-bit integers if `Int(x)` is large. Use 64-bit integers for intermediate calculations.
- **Precision Loss:** The rounding bias (`32768` and `32`) helps mitigate precision loss during quantization, but some error is inherent.

## Subtopics

### Finish Unquantize
This variant specifically handles the interpolation step in BC6H compression. It takes two unquantized half-precision endpoints and a weight, computes a weighted average with rounding bias, and applies a final scaling factor before converting to 32-bit float. It is chosen when the compression mode requires interpolation between endpoints (e.g., BC6H mode 0-5). It differs from basic unquantization by including the interpolation logic and the specific `31/4096` scaling factor.

## Operating characteristics
- **Time Complexity:** O(1) per value. The operations are simple arithmetic (multiplication, addition, division).
- **Memory Complexity:** O(1). No additional data structures are required beyond the input integers and endpoints.
- **Performance:** Very fast, suitable for real-time GPU decompression. The source [S1, unofficial] indicates this is used in real-time BC6H compression.
- **Strengths:** Simple arithmetic, low latency.
- **Limitations:** Precision is limited by the quantization step size and the scaling factor. Not suitable for high-precision scientific data without careful scaling.

## Background
Unquantization functions are a critical part of the BC6H texture compression standard, which is used for high-quality compression of floating-point textures. The specific formulas and variants described here are derived from the GPURealTimeBC6H implementation [S1, unofficial], which provides an efficient GPU-based decompression method. The method is part of the broader family of transform-based compression techniques used in graphics hardware.
