# Unquantization Functions

Also called: Unquantize10, Unquantize7, Unquantize9

## Overview
Unquantization functions reconstruct continuous floating-point values from discrete integer indices produced by [Quantization](5935-quantization.md). In the context of BC6H compression, these functions specifically map 10-bit or 7-bit integer representations back to half-precision or full-precision float ranges. They differ from sibling methods like [Scalar Quantization](5726-scalar-quantization.md) by being tightly coupled to the specific bit-depths and interpolation logic of the BC6H block structure, rather than generic scalar mapping.

## How it works
The method operates on the output of the BC6H decoder, where each block contains two endpoints and a set of interpolation weights. The core task is to convert the stored integer indices into usable float values for color or density reconstruction.

### Inputs and Outputs
- **Input**: Integer quantized values (10-bit or 7-bit indices), scale factors, and interpolation weights.
- **Output**: Half-precision floats (for endpoints) or full-precision floats (for interpolated values).

### Data Structures
The implementation relies on the following integer types:
- `Int(x)`: The integer index, typically 10-bit or 7-bit unsigned.
- `weight`: An interpolation weight, typically 6-bit (0–63) for BC6H.

### Formulas
Two primary unquantization steps are defined in the source material [S1, unofficial]:

1. **Endpoint Unquantization (Half Precision)**:
   Converts a 10-bit integer index back to a half-precision float.
   $$ \text{Half}(x) = \frac{\text{Int}(x) \times 65536 + 32768}{\text{Scale}} $$
   Where:
   - $\text{Int}(x)$ is the 10-bit integer value.
   - $65536$ is $2^{16}$, representing the range of the 10-bit value shifted to 16-bit precision.
   - $32768$ is $2^{15}$, acting as a bias for rounding.
   - $\text{Scale}$ is the normalization factor derived from the block's endpoint range.

2. **Interpolated Value Unquantization (Full Precision)**:
   Interpolates between two unquantized endpoints using a weight and converts to a final 3-component float.
   $$ \text{Result} = \text{f16tof32}\left( \frac{(\text{endpoint0Unq} \times (64 - \text{weight}) + \text{endpoint1Unq} \times \text{weight} + 32) \times 31}{4096} \right) $$
   Where:
   - $\text{endpoint0Unq}$ and $\text{endpoint1Unq}$ are the half-precision floats obtained from the first formula.
   - $\text{weight}$ is the 6-bit interpolation weight (0–63).
   - $\text{f16tof32}$ converts the half-precision intermediate result to a 32-bit float.
   - The constants $31/4096$ and the bias $+32$ handle the specific scaling and rounding required for the BC6H format's 7-bit or 10-bit interpolation precision.

### Pseudocode
```python
def unquantize_endpoint(int_index, scale):
    """
    Converts a 10-bit integer index to a half-precision float.
    Source: [S1, unofficial]
    """
    # int_index is assumed to be 10-bit unsigned (0-1023)
    # scale is the normalization factor
    numerator = (int_index * 65536) + 32768
    return numerator / scale

def unquantize_interpolated(endpoint0_unq, endpoint1_unq, weight):
    """
    Interpolates between two unquantized endpoints using a 6-bit weight.
    Source: [S1, unofficial]
    """
    # endpoint0_unq, endpoint1_unq are half-precision floats
    # weight is 6-bit unsigned (0-63)
    
    # Calculate weighted sum with bias
    # Note: The formula uses integer-like arithmetic on floats before final conversion
    weighted_sum = (endpoint0_unq * (64 - weight)) + (endpoint1_unq * weight)
    
    # Apply bias and scaling
    # The source formula implies integer arithmetic context for the bias, 
    # but applied to float endpoints. We follow the exact arithmetic order.
    intermediate = (weighted_sum + 32) * (31 / 4096)
    
    # Convert to full float32
    return f16_to_f32(intermediate)

def f16_to_f32(half_val):
    """
    Converts a half-precision float to a 32-bit float.
    Standard IEEE 754 conversion.
    """
    # Implementation depends on language, but conceptually maps 16-bit IEEE 754 to 32-bit
    return float(half_val)
```

### Parameters and Edge Cases
- **Scale**: Must be non-zero. If the block has zero range, special handling is required (not detailed in sources) [G].
- **Weight Range**: The weight is strictly 0–63. Values outside this range are invalid for BC6H [S1, unofficial].
- **Precision**: The use of $65536$ and $32768$ suggests fixed-point arithmetic emulation in the quantization step, which is preserved during unquantization [S1, unofficial].

## Subtopics

### Finish Unquantize
This variant specifically handles the final interpolation step in BC6H decoding. It takes two already-unquantized endpoints and a weight, performing the weighted average and converting the result to a full 32-bit float. It is distinct from the basic endpoint unquantization because it involves interpolation and a different scaling factor ($31/4096$) tailored to the 7-bit or 10-bit interpolation precision of BC6H [S1, unofficial]. Choose this when reconstructing the final pixel values from block endpoints.

## Operating characteristics
- **Time Complexity**: $O(1)$ per value. The operations are simple arithmetic and type conversions.
- **Memory Complexity**: $O(1)$. No additional data structures are required beyond the input indices and weights.
- **Performance**: Highly efficient on GPUs due to the simplicity of the arithmetic. The use of half-precision intermediates can leverage FP16 units, though the final conversion to FP32 may require FP32 units [S1, unofficial].
- **Limitations**: The formulas are specific to the BC6H format. They are not general-purpose unquantization functions for other compression schemes [S1, unofficial].

## Background
The unquantization functions described here originate from the BC6H texture compression standard, specifically in the context of real-time GPU implementations. The formulas are derived from the BC6H specification's handling of 10-bit and 7-bit endpoints and interpolation weights. The source [S1, unofficial] provides an unofficial implementation of real-time BC6H compression on the GPU, which includes these specific unquantization steps.
