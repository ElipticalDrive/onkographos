# Unquantization Functions

Also called: Unquantize10, Unquantize7, Unquantize9

## Overview
Unquantization functions convert integer quantized values back to half-precision float range, serving as the inverse operation to the quantization steps described in [Quantization](5935-quantization.md). This method is specifically designed for BC6H compression, where it reconstructs floating-point color data from compressed integer indices. It differs from general scalar quantization by using specific scaling factors and rounding offsets tailored to the 10-bit and 7-bit partition structures of BC6H.

## How it works
**Inputs and Outputs:**
- Input: An integer value `Int(x)` (typically 10-bit or 7-bit depending on the variant) and a `Scale` factor derived from the partition and mode.
- Output: A half-precision float `Half(x)`.

**Data Structures:**
The implementation relies on standard integer types (`uint8_t`, `uint16_t`) and half-precision float representations. The `Scale` is a precomputed floating-point value.

**Steps:**
1. Retrieve the integer quantized value `Int(x)`.
2. Retrieve the `Scale` factor associated with the current partition and mode.
3. Apply the unquantization formula to map the integer to the half-precision range.

**Formula:**
The core unquantization formula is defined as [S1, unofficial]:

$$
\text{Half}(x) = \frac{\text{Int}(x) \times 65536 + 32768}{\text{Scale}}
$$

Where:
- `Int(x)` is the integer quantized value.
- `65536` is $2^{16}$, scaling the integer to the full half-precision range before adjustment.
- `32768` is $2^{15}$, acting as a rounding offset to ensure correct rounding during the division.
- `Scale` is the normalization factor.

**Pseudocode:**
```python
def unquantize(int_val, scale):
    """
    Converts an integer quantized value back to half-precision float range.
    
    Args:
        int_val (int): The integer quantized value.
        scale (float): The scale factor for the partition/mode.
        
    Returns:
        float: The unquantized half-precision float value.
    """
    # Apply the formula: (Int(x) * 65536 + 32768) / Scale
    # Note: In practice, this result is often cast to half-precision.
    result = (int_val * 65536 + 32768) / scale
    return result
```

**Parameters:**
- `Scale`: Varies based on the BC6H mode and partition. Typical values are not explicitly listed in the sources but are derived from the compression algorithm's range normalization.

**Edge Cases and Pitfalls:**
- Division by zero: Ensure `Scale` is non-zero.
- Precision: The addition of `32768` is critical for correct rounding. Omitting it may lead to biased results.

## Subtopics

### Finish Unquantize
**Definition:** Interpolates between two unquantized endpoints using a weight and converts to final float3. This variant is used in BC6H to reconstruct the final color value from the two endpoints and the interpolated weight.
**Formula:**
$$
\text{Result} = \text{f16tof32}\left( \left( \text{endpoint0Unq} \times (64 - \text{weight}) + \text{endpoint1Unq} \times \text{weight} + 32 \right) \times \frac{31}{4096} \right)
$$
Where:
- `endpoint0Unq` and `endpoint1Unq` are the unquantized endpoint values.
- `weight` is the interpolation weight (0-63).
- `f16tof32` converts the half-precision result to a 32-bit float.
- The factor `31/4096` scales the result appropriately.
**When to choose:** Use this when reconstructing the final pixel color from BC6H compressed data, specifically after the initial unquantization of endpoints.

## Operating characteristics
**Time and Memory Complexity:**
- Time: O(1) per pixel, as it involves a fixed number of arithmetic operations.
- Memory: O(1), requiring only the storage of the integer value and the scale factor.

**Measured Performance:**
- Performance is highly dependent on the hardware's ability to perform fast floating-point division and multiplication. On modern GPUs, this operation is typically very fast due to hardware support for half-precision arithmetic.

**Scaling:**
- Scales linearly with the number of pixels, as each pixel is processed independently.

**Strengths and Limitations:**
- Strengths: Simple and efficient; well-suited for GPU implementation.
- Limitations: Precision loss is inherent in the quantization process; the quality of the result depends on the accuracy of the `Scale` factor.

**When to use and when not:**
- Use: When decompressing BC6H compressed textures.
- Do not use: For general-purpose quantization/dequantization where different scaling factors or rounding methods are required.

## Background
**Origin:**
The unquantization functions described here originate from the BC6H compression algorithm, specifically as implemented in the GPURealTimeBC6H project [S1, unofficial]. BC6H is a block compression format for 32-bit floating-point textures, commonly used in real-time graphics.

**History and Development:**
BC6H was developed as part of the DirectX Compression (DXTC) family, providing high-quality compression for HDR textures. The specific unquantization formulas are tailored to the 10-bit and 7-bit partition structures used in BC6H to balance compression ratio and visual quality.

**Where it is used:**
- Real-time graphics engines (e.g., Unity, Unreal Engine) for texture compression.
- GPU-based image processing pipelines.
