# Unquantization Functions

Also called: Unquantize10, Unquantize7, Unquantize9

## Overview
Unquantization functions reconstruct continuous or high-precision floating-point values from discrete, integer-encoded representations, serving as the inverse operation to the quantization step in [Quantization](5935-quantization.md). Specifically, these functions map integer quantized values back to a half-precision float range, enabling the decoding of compressed volume data or textures. They are distinct from sibling methods like [Vector Quantization](907-vector-quantization.md) or [Scalar Quantization](5726-scalar-quantization.md) by their specific implementation within block-compression schemes (such as BC6H) where they handle the reconstruction of endpoint values and interpolated texels using fixed-point arithmetic to maintain precision and performance.

## How it works
**Inputs and Outputs:**
*   Input: An integer quantized value (typically 10-bit or 7-bit depending on the variant), a scale factor, and optionally two endpoint values and a weight for interpolation.
*   Output: A half-precision float (or converted to float32) representing the reconstructed value.

**Data Structures:**
The implementation relies on standard integer types (`uint8_t`, `int`) and floating-point types (`half`, `float`). No complex data structures are required beyond the raw integer codes and pre-computed scale factors.

**Formulas and Steps:**

1.  **Basic Unquantization (Unquantize10/9/7):**
    The core unquantization converts an integer code $I$ into a half-precision float $H$. The formula provided in the sources is:
    $$ H = \frac{I \times 65536 + 32768}{Scale} $$
    Where:
    *   $I$ is the integer quantized value.
    *   $65536$ is $2^{16}$, used to shift the integer into a fixed-point representation suitable for half-precision scaling.
    *   $32768$ is $2^{15}$, acting as a rounding bias to ensure correct rounding during the division.
    *   $Scale$ is a normalization factor derived from the quantization step size.

2.  **Finish Unquantize (Interpolation):**
    For interpolated values, the function combines two unquantized endpoints $E_0$ and $E_1$ using a weight $W$. The formula is:
    $$ Result = \text{f16tof32}\left( \frac{(E_0 \times (64 - W) + E_1 \times W + 32) \times 31}{4096} \right) $$
    Where:
    *   $E_0, E_1$ are the unquantized endpoint values (in half-precision or fixed-point).
    *   $W$ is the interpolation weight (typically 6-bit, range 0-63).
    *   $64$ is the maximum weight value plus one.
    *   $32$ is a rounding bias.
    *   $31$ and $4096$ are scaling factors to map the result to the final float32 range.
    *   $\text{f16tof32}$ converts the intermediate half-precision result to a 32-bit float.

**Pseudocode:**
```python
def unquantize_basic(int_code: int, scale: float) -> float:
    """
    Converts an integer quantized value back to a float.
    Formula: (Int(x) * 65536 + 32768) / Scale
    """
    # Apply bias for rounding
    numerator = (int_code * 65536) + 32768
    return numerator / scale

def unquantize_interpolate(endpoint0: float, endpoint1: float, weight: int) -> float:
    """
    Interpolates between two unquantized endpoints using a weight.
    Formula: f16tof32( (endpoint0Unq * (64 - weight) + endpoint1Unq * weight + 32) * (31 / 4096) )
    """
    # Calculate weighted sum with bias
    # Note: endpoint0 and endpoint1 are assumed to be in the same fixed-point/half-precision domain
    weighted_sum = (endpoint0 * (64 - weight)) + (endpoint1 * weight) + 32
    
    # Apply scaling factor
    scaled_result = weighted_sum * (31 / 4096)
    
    # Convert to float32 (simulated)
    return float(scaled_result)
```

**Parameters:**
*   `scale`: Specific to the quantization mode. Not given in the sources.
*   `weight`: Integer in range [0, 63] for Finish Unquantize.

**Edge Cases:**
*   Division by zero if `scale` is 0.
*   Overflow if `int_code` is extremely large before scaling.

## Subtopics

### Finish Unquantize
This variant handles the interpolation between two unquantized endpoints using a weight. It is used when a value is not an endpoint but lies between them. It sets itself apart by performing a weighted average with specific fixed-point arithmetic adjustments (bias and scaling) to maintain precision during the interpolation process. ## Operating characteristics
**Time and Memory Complexity:**
The operations are $O(1)$ in time and memory, involving basic arithmetic operations.

**Measured Performance:**
Not given in the sources.

**Scaling:**
Linear with the number of values to unquantize.

**Strengths and Limitations:**
*   Strengths: Fast, deterministic, preserves precision through fixed-point arithmetic.
*   Limitations: Dependent on accurate scale factors; potential for precision loss if scale factors are not carefully chosen.

**When to use:**
Use when decoding compressed volume data or textures that use block compression with unquantization steps.
