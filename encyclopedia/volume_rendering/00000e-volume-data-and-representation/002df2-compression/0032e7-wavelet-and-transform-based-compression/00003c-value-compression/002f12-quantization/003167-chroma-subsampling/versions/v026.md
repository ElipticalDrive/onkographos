# Chroma Subsampling
Also called: Chroma Subsampling for Volumetric Data, Chroma subsampling for volume, Color component subsampling

## Overview
Chroma subsampling for volumetric data reduces the bitrate of color information by lowering the spatial resolution of chrominance components (U, V) while maintaining full resolution for luminance (Y) [S1]. Unlike direct subsampling which causes significant information loss in sparse volumes, this method defines one color value for every eight adjacent corners of a voxel grid, preserving color fidelity at low bitrates [S1]. It is distinct from sibling quantization methods because it operates on the spatial arrangement of existing voxels to handle sparsity, rather than merely reducing the precision of existing values [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sparse volumetric dataset where voxels have associated luminance (Y) and chrominance (U, V) values. The volume is represented as a set of existing voxels at specific grid coordinates.
*   **Output:** A compressed representation where chrominance data is stored at 1/8th the spatial density of the original voxel grid, with a mechanism for reconstruction.

**Data Structures:**
The method operates on a grid where chroma samples are aligned with the corners of the underlying voxel cells. For a standard 3D grid, a single chroma sample corresponds to a $2 \times 2 \times 2$ block of eight adjacent voxel corners.
*   **Chroma Grid:** A 3D array where each element represents the aggregated color of a $2 \times 2 \times 2$ corner group.
*   **Voxel Presence Flag:** Implicitly derived from the input data; indicates whether a voxel exists at a specific coordinate.

**Algorithm Steps:**

1.  **Grouping:** Divide the volume grid into non-overlapping $2 \times 2 \times 2$ blocks of voxel corners. Each block consists of eight adjacent corners.
2.  **Existence Check:** For each block, determine which of the eight corners contain existing voxels.
3.  **Color Aggregation (Encoder):**
    *   If **no** voxels exist in any of the eight corners, define the subsampled chroma value as **transparent** (or null).
    *   If **one or more** voxels exist in the eight corners, calculate the **median** value of the chrominance components (U, V) from the existing voxels.
    *   *Note:* The median is chosen over the average because it provides better sharpness and is less influenced by outlier values, ignoring high-difference values [S1].
4.  **Storage:** Store the aggregated median chroma value (or transparent flag) in the corresponding position of the subsampled chroma grid. Luminance (Y) is stored at full resolution for all existing voxels.
5.  **Reconstruction (Decoder):**
    *   Retrieve the subsampled chroma values.
    *   For missing or transparent chroma values in the target resolution grid, interpolate from neighboring voxels or repeat the preceding sample [S1].
    *   *Implementation Note:* In simulation, the repeating approach is employed for missing values as viewers' sense of color is barely affected by this approximation [S1].

    """
    Encodes chrominance components using corner-based median subsampling.
    
    Args:

    # Iterate through each 2x2x2 block
    for cx in range(0, max_x - 1, 2):
        for cy in range(0, max_y - 1, 2):
            for cz in range(0, max_z - 1, 2):
                
                # Collect chroma values from the 8 corners of this block
                corner_colors = []
                
                # Check all 8 corners: (cx+dx, cy+dy, cz+dz) for dx,dy,dz in {0,1}
                for dx in [0, 1]:

                                corner_colors.append((u, v))
                
                # Determine the subsampled value
                if len(corner_colors) == 0:
                    # No voxels present: define as transparent
                    chroma_grid[cx // 2][cy // 2][cz // 2] = None
                else:
                    # One or more voxels present: use median
                    # Extract U and V components separately for median calculation
                    u_values = [c[0] for c in corner_colors]
                    v_values = [c[1] for c in corner_colors]
                    
                    median_u = calculate_median(u_values)
                    median_v = calculate_median(v_values)
                    
                    chroma_grid[cx // 2][cy // 2][cz // 2] = (median_u, median_v)
                    
    return chroma_grid

**Parameters:**
*   **Subsampling Factor:** Fixed at 8:1 for chroma (1 sample per 8 corners).
*   **Aggregation Function:** Median.
*   **Reconstruction Method:** Repeating (simulation) or Interpolation (general).

**Edge Cases and Pitfalls:**
*   **Empty Blocks:** If no voxels exist in a $2 \times 2 \times 2$ block, the chroma value is transparent. Failure to handle this results in incorrect color assignment [S1].
*   **Outliers:** Using the mean instead of the median can lead to poor sharpness and sensitivity to outlier color values [S1].
*   **Low Bitrate Loss:** Without chroma subsampling, chroma information can be completely lost at low bitrates, resulting in grey objects [S1].

## Operating characteristics
*   **Compression Ratio:** Chroma subsampling significantly reduces the bitrate required for color components. In the Leo sequence experiment, chroma subsampling achieved 39.30 dB PSNR at 1.18 bits per voxel (bpv), whereas non-subsampling required 2.90 bpv for the same quality [S1].
*   **Quality:** Subjective results show that objects retain color at low bitrates (e.g., 0.2 bpv) when subsampling is applied, whereas non-subsampled volumes appear grey [S1].
*   **Complexity:** The encoding complexity is linear with respect to the number of voxels, as each voxel is visited once to contribute to its corner block. The median calculation is constant time for the fixed 8-neighbor group.
*   **Strengths:** Preserves color quality at very low bitrates; robust against outliers; simple to implement.
*   **Limitations:** Introduces spatial aliasing in the chroma channels; reconstruction requires interpolation or repetition which may blur color boundaries.

## Background
Chroma subsampling is a well-known technique in image and video compression (e.g., 4:2:0, 4:2:2) that exploits the human visual system's lower sensitivity to color detail compared to luminance detail [S1]. Its application to volumetric data was proposed to address the specific challenge of sparse volumes where direct subsampling causes significant information loss [S1]. The method was tested on multiview captured volumes for realistic view synthesis applications [S1].
