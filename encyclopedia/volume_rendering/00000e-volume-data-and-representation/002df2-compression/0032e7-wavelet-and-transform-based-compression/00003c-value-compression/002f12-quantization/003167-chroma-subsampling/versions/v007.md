# Chroma Subsampling

Also called: Chroma Subsampling for Volumetric Data, Chroma subsampling for volume, Color component subsampling

## Overview
Chroma subsampling reduces the bitrate of volumetric data by lowering the spatial resolution of chrominance components (U, V) while retaining luminance (Y) at full resolution, thereby preventing color loss at low bitrates [S1]. It differs from direct subsampling by aggregating color information from eight adjacent voxel corners using a median filter, which preserves sharpness and reduces outlier influence compared to averaging [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of existing voxels, each with a position and a color value in YUV format.
*   **Output:** A subsampled volume where chrominance values are defined at a coarser grid (one value per $2 \times 2 \times 2$ corner group), while luminance remains at the original resolution.

**Data Structures:**
The method operates on groups of eight adjacent corners in the voxel grid. For each group, a single chrominance value is computed. The luminance component is not subsampled and retains its original per-voxel resolution.

**Steps:**
1.  **Grouping:** Divide the voxel grid into non-overlapping groups of eight adjacent corners (a $2 \times 2 \times 2$ block).
2.  **Existence Check:** Determine if any voxel exists within the eight corners of the current group.
    *   If no voxels exist in any of the eight corners, define the subsampled voxel as transparent [S1].
    *   If one or more voxels exist, proceed to step 3.
3.  **Median Calculation:** Compute the median value of the chrominance components (U, V) of all existing voxels within the eight corners. The luminance (Y) is not part of this median calculation for the subsampled value [S1].
    *   The median is chosen over the average because it provides better sharpness and is less influenced by outlier values [S1].
4.  **Storage:** Store the computed median chrominance value for the group. The luminance values for the individual voxels remain unchanged.

**Decoder Side Reconstruction:**
1.  **Interpolation/Repetition:** For missing chrominance values in the reconstructed volume, interpolate from neighboring voxels or repeat the preceding sample [S1].
2.  **Simulation Choice:** In simulations, the repeating approach is employed because viewers' sense of color is barely affected by this method [S1].

**Pseudocode:**
```python
def chroma_subsample_volumetric_data(voxels):
    """
    voxels: List of voxel objects. Each voxel has:
        - pos: (x, y, z) integer coordinates
        - color: (Y, U, V) float values
        - exists: boolean (True if voxel is present, False otherwise)
    
    Returns:
        subsampled_chroma: Dictionary mapping group_key -> (U, V)
    """
    subsampled_chroma = {}
    
    # Group voxels by their 2x2x2 block key
    # Key is derived from the floor of coordinates divided by 2
    groups = {}
    for voxel in voxels:
        if not voxel.exists:
            continue
            
        # Determine the group index for this voxel
        gx = voxel.pos[0] // 2
        gy = voxel.pos[1] // 2
        gz = voxel.pos[2] // 2
        group_key = (gx, gy, gz)
        
        if group_key not in groups:
            groups[group_key] = []
        groups[group_key].append(voxel)

    # Process each group
    for group_key, group_voxels in groups.items():
        if len(group_voxels) == 0:
            # No existing voxels in this group
            # Define as transparent
            subsampled_chroma[group_key] = None
        else:
            # Extract U and V components from existing voxels
            u_values = [v.color[1] for v in group_voxels]
            v_values = [v.color[2] for v in group_voxels]
            
            # Compute median
            median_u = median(u_values)
            median_v = median(v_values)
            
            subsampled_chroma[group_key] = (median_u, median_v)
            
    return subsampled_chroma

def median(values):
    """Helper function to compute median of a list of numbers."""
    sorted_vals = sorted(values)
    n = len(sorted_vals)
    if n % 2 == 1:
        return sorted_vals[n // 2]
    else:
        return (sorted_vals[n // 2 - 1] + sorted_vals[n // 2]) / 2.0
```

**Parameters:**
*   **Subsampling Factor:** $2 \times 2 \times 2$ (one value per 8 corners) [S1].
*   **Aggregation Method:** Median [S1].

**Edge Cases and Pitfalls:**
*   **Empty Groups:** If no voxels exist in a $2 \times 2 \times 2$ group, the result is transparent [S1].
*   **Color Loss:** Without chroma subsampling, chroma information can be completely lost at low bitrates, resulting in grey objects [S1].
*   **Outliers:** The median method is robust against outlier color values, which might skew an average [S1].

## Operating characteristics
*   **Bitrate Reduction:** Chroma subsampling significantly reduces bitrate for chrominance components. In the Leo sequence experiment, it achieved 39.30 dB PSNR at 1.18 bpv, whereas non-subsampling required 2.90 bpv for the same quality [S1].
*   **Quality:** Preserves color quality at low bitrates where direct subsampling would fail [S1].
*   **Complexity:** The method involves grouping and median calculation, which is computationally lightweight compared to transform-based compression.
*   **Limitations:** Only applies to chrominance; luminance is not compressed. The effectiveness depends on the accuracy of the available geometry model [S1].

## Background
Chroma subsampling for volumetric data was proposed in the context of color volumetric compression for realistic view synthesis applications [S1]. It addresses the issue that direct subsampling of volume causes significant information loss, as intensity and color are defined only for existing voxels [S1]. The technique is particularly useful for multiview captured volumes where the object's surface is the primary focus, and the inside is generally occluded [S1].
