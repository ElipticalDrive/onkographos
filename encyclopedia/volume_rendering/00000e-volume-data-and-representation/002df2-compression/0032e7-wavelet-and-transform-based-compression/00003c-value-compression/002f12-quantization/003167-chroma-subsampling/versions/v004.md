# Chroma Subsampling

Also called: Chroma Subsampling for Volumetric Data, Chroma subsampling for volume, Color component subsampling

## Overview
Chroma subsampling is a data rearrangement technique that reduces the resolution of chrominance components (U, V) in volumetric data while maintaining luminance (Y) at full resolution, thereby lowering bitrate without significant perceptual quality loss [S1]. Unlike direct subsampling which causes severe information loss in sparse volumes, this method defines one color value for every eight adjacent corners, preserving color integrity better than naive averaging or dropping [S1]. It is distinct from sibling methods like [Scalar Quantization](5726-scalar-quantization.md) or [Uniform Quantization](5855-uniform-quantization.md) because it operates on the spatial arrangement of color components relative to voxel geometry rather than just reducing bit-depth [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of existing voxels, each with a position and a color value represented in YUV format (Luminance $Y$, Chrominance $U, V$).
*   **Output:** A subsampled volume where chrominance data is stored at a lower resolution (1 value per 8-corner group), while luminance remains per-voxel.

**Data Structures:**
The method operates on groups of eight adjacent corners in the voxel grid. For each group, a single chrominance value is computed if any voxel exists within that group. The structure does not explicitly store a new grid; rather, it defines a mapping rule for accessing chrominance data during encoding/decoding.

**Parameters:**
*   **Group Size:** 8 adjacent corners (typically a $2 \times 2 \times 2$ block of potential voxel positions).
*   **Color Space:** YUV (separating Luminance $Y$ from Chrominance $U, V$).

**Steps:**
1.  **Partitioning:** Divide the voxel grid into non-overlapping groups of eight adjacent corners.
2.  **Existence Check:** For each group, determine if any existing voxel occupies any of the eight corners.
3.  **Transparent Handling:** If no existing voxel is present in any of the eight corners, define the subsampled voxel for that group as transparent (or null).
4.  **Median Calculation:** If one or more voxels are present in the eight adjacent corners, compute the median value of the existing voxels' chrominance components ($U, V$). The luminance component $Y$ is not subsampled in this specific step; it remains associated with individual voxels.
    *   Formula for Chrominance $C \in \{U, V\}$:
        $$ C_{sub} = \text{median}(\{C_i \mid \text{voxel } i \text{ exists in the group}\}) $$
    *   The median is chosen over the average to provide better sharpness and reduce influence from outlier values [S1].
5.  **Decoding (Interpolation/Repetition):** When reconstructing the volume for rendering:
    *   If a subsampled chrominance value is missing (due to transparency in step 3), interpolate from neighboring voxels or repeat the preceding sample.
    *   In simulation, the repeating approach is employed because viewers' sense of color is barely affected by these gaps [S1].

**Pseudocode:**
```python
def chroma_subsampling_encode(existing_voxels):
    """
    existing_voxels: List of objects with attributes:
        - pos: (x, y, z) integer coordinates
        - color: (Y, U, V) float values
    Returns:
        subsampled_chroma: Dictionary mapping group_key -> (U, V)
        transparent_groups: Set of group_keys that are fully empty
    """
    subsampled_chroma = {}
    transparent_groups = set()
    
    # Group size is 8 corners. Assuming a standard 2x2x2 block alignment.
    # Group key is the minimum coordinate of the 2x2x2 block.
    def get_group_key(pos):
        x, y, z = pos
        # Align to 2x2x2 grid
        gx = (x // 2) * 2
        gy = (y // 2) * 2
        gz = (z // 2) * 2
        return (gx, gy, gz)

    # Initialize groups to track existence
    group_voxels = {}

    for voxel in existing_voxels:
        key = get_group_key(voxel.pos)
        if key not in group_voxels:
            group_voxels[key] = []
        group_voxels[key].append(voxel)

    for key, voxels_in_group in group_voxels.items():
        if len(voxels_in_group) == 0:
            transparent_groups.add(key)
            continue
        
        # Extract U and V components
        u_values = [v.color[1] for v in voxels_in_group]
        v_values = [v.color[2] for v in voxels_in_group]
        
        # Compute median
        u_median = sorted(u_values)[len(u_values) // 2]
        v_median = sorted(v_values)[len(v_values) // 2]
        
        subsampled_chroma[key] = (u_median, v_median)

    return subsampled_chroma, transparent_groups

def chroma_subsampling_decode(subsampled_chroma, transparent_groups, render_order):
    """
    subsampled_chroma: Dict mapping group_key -> (U, V)
    transparent_groups: Set of group_keys that are empty
    render_order: List of group_keys in rendering order (e.g., front-to-back)
    
    Returns:
        color_map: Dict mapping group_key -> (Y, U, V) 
        Note: Y is assumed to be available from the base volume structure.
    """
    color_map = {}
    
    for key in render_order:
        if key in transparent_groups:
            # Missing value handling: repeat preceding sample
            # In a real implementation, 'preceding' refers to the last valid 
            # chroma value encountered in the render order.
            if color_map:
                prev_u, prev_v = list(color_map.values())[-1][1:]
                color_map[key] = (None, prev_u, prev_v) # Y is None/transparent
            else:
                color_map[key] = (None, 0, 0) # Default fallback
        else:
            u, v = subsampled_chroma[key]
            # Y is retrieved from the original voxel data associated with this group
            # For the purpose of this method, we assume Y is handled separately.
            color_map[key] = (None, u, v)
            
    return color_map
```

**Edge Cases and Pitfalls:**
*   **Low Bitrate Loss:** Without chroma subsampling, chroma information can be completely lost at low bitrates, resulting in grey objects [S1].
*   **Outliers:** Using the mean instead of the median would make the result more sensitive to outlier color values in sparse regions [S1].
*   **Transparency:** Correctly identifying "no existing voxel" is critical; treating empty space as a zero-color value instead of transparent would introduce artifacts [S1].

## Operating characteristics
*   **Compression Ratio:** In the Leo sequence experiment, chroma subsampling achieved 39.30 dB PSNR at 1.18 bits per voxel (bpv), whereas the non-subsampling approach required 2.90 bpv for the same quality [S1].
*   **Quality:** Subjective results show that at 0.2 bpv, non-subsampled objects appear grey, while subsampled objects retain color [S1].
*   **Complexity:** The encoding complexity is linear with respect to the number of voxels, dominated by the median calculation per group. Decoding involves simple lookup and repetition.
*   **Strengths:** Preserves color quality at very low bitrates; robust against outliers; simple to implement.
*   **Limitations:** Only applies to chrominance; requires YUV color space separation; assumes a regular grid structure for grouping.

## Background
Chroma subsampling for volumetric data was proposed in the context of realistic view synthesis applications, specifically for multiview video and volume compression [S1]. The method was tested on the multiview Leo sequence captured at the University of Bristol [S1]. It addresses the specific challenge that in volumes, intensity and color are defined only for existing voxels, making direct subsampling ineffective compared to image-based approaches [S1].
