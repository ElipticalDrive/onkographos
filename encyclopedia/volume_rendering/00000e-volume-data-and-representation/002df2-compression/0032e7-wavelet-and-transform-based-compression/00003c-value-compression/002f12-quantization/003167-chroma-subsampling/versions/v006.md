# Chroma Subsampling

Also called: Chroma Subsampling for Volumetric Data, Chroma subsampling for volume, Color component subsampling

## Overview
Chroma subsampling for volumetric data reduces the bitrate of color information by lowering the resolution of chrominance components (U, V) while maintaining full resolution for luminance (Y) [S1]. Unlike direct subsampling which causes significant information loss in sparse volumes, this method aggregates color values from groups of eight adjacent voxel corners to preserve color quality at low bitrates [S1]. It is distinct from general quantization methods by specifically addressing the spatial sparsity and geometric structure of volumetric data, preventing the complete loss of color information that occurs when chroma is coded without subsampling [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of existing voxels, each defined by its spatial position (corner coordinates) and color attributes (Luminance $Y$, Chrominance $U, V$).
*   **Output:** A compressed representation where chrominance values are defined at a lower resolution (one value per $2 \times 2 \times 2$ group of corners), while luminance remains at full resolution.

**Data Structures:**
The method operates on groups of eight adjacent corners forming a $2 \times 2 \times 2$ block.
*   **Block Definition:** A block is identified by its base corner coordinates $(x, y, z)$ where $x, y, z$ are even integers.
*   **Voxel Status:** Each corner in the block has a binary status: `existing` (contains a voxel) or `non-existing` (empty/transparent).
*   **Color Storage:** The output stores a single chrominance triplet $(U, V)$ for the entire block if at least one voxel exists in the block.

**Algorithm Steps:**

1.  **Grouping:** Partition the volume space into non-overlapping $2 \times 2 \times 2$ blocks of corners.
2.  **Existence Check:** For each block, determine which of the eight corners contain existing voxels. Let $E$ be the set of existing voxels in the current block.
3.  **Transparency Handling:** If $E$ is empty (no voxels in any of the eight corners), define the subsampled voxel for this block as transparent. The chrominance values are undefined or set to a default background color.
4.  **Chroma Aggregation:** If $E$ is not empty, compute the chrominance values for the block using the median of the chrominance components of all voxels in $E$.
    *   Let $U_i$ and $V_i$ be the chrominance components of the $i$-th existing voxel in $E$.
    *   The subsampled chrominance values $U_{block}$ and $V_{block}$ are:
        $$ U_{block} = \text{median}(\{U_i \mid i \in E\}) $$
        $$ V_{block} = \text{median}(\{V_i \mid i \in E\}) $$
    *   The median is chosen over the average to provide better sharpness and reduce influence from outlier values [S1].
5.  **Luminance Preservation:** Luminance values $Y$ for existing voxels are stored at full resolution and are not subsampled.

**Decoder Side Reconstruction:**
When reconstructing the volume from the compressed data:
1.  **Interpolation/Repetition:** For blocks where the subsampled chrominance is defined, assign this value to all eight corners.
2.  **Missing Values:** If a corner in the original grid corresponds to a block with no existing voxels (transparent), the chrominance value is missing. The decoder handles this by either:
    *   Interpolating from neighboring voxels' chrominance values.
    *   Repeating the preceding sample's chrominance value [S1].
    *   The repeating approach is employed in simulations because viewers' sense of color is barely affected by these gaps [S1].

**Pseudocode:**

```python
def chroma_subsample_volume(voxels):
    """
    voxels: list of objects with attributes:
        - pos: tuple (x, y, z) integer coordinates
        - Y: float luminance
        - U: float chrominance U
        - V: float chrominance V
        - exists: boolean, True if voxel is present
    Returns:
        subsampled_data: dict mapping block_key -> (U_block, V_block)
        full_luminance: dict mapping pos -> Y
    """
    subsampled_data = {}
    full_luminance = {}
    
    # Group voxels into 2x2x2 blocks
    # Block key is the base corner (x, y, z) where x,y,z are even
    blocks = {}
    
    for v in voxels:
        if not v.exists:
            continue
            
        # Calculate block base coordinates
        bx = (v.pos[0] // 2) * 2
        by = (v.pos[1] // 2) * 2
        bz = (v.pos[2] // 2) * 2
        block_key = (bx, by, bz)
        
        if block_key not in blocks:
            blocks[block_key] = []
        blocks[block_key].append(v)
        
        # Store full resolution luminance
        full_luminance[v.pos] = v.Y

    # Process each block
    for block_key, existing_voxels in blocks.items():
        if not existing_voxels:
            # No voxels in this block, mark as transparent
            # Chrominance is not stored or set to background
            continue
            
        # Extract U and V values from existing voxels
        u_values = [v.U for v in existing_voxels]
        v_values = [v.V for v in existing_voxels]
        
        # Compute median for chrominance
        u_median = median(u_values)
        v_median = median(v_values)
        
        # Store subsampled chrominance for the block
        subsampled_data[block_key] = (u_median, v_median)
        
    return subsampled_data, full_luminance

def median(values):
    """Helper to compute median of a list of numbers."""
    sorted_vals = sorted(values)
    n = len(sorted_vals)
    if n % 2 == 1:
        return sorted_vals[n // 2]
    else:
        return (sorted_vals[n // 2 - 1] + sorted_vals[n // 2]) / 2.0
```

**Parameters:**
*   **Subsampling Factor:** $2 \times 2 \times 2$ (one color value per 8 corners) [S1].
*   **Aggregation Function:** Median [S1].

**Edge Cases and Pitfalls:**
*   **Empty Blocks:** If no voxels exist in a $2 \times 2 \times 2$ block, the chrominance is undefined. The decoder must handle this via interpolation or repetition [S1].
*   **Outliers:** Using the median prevents outlier voxels from skewing the block's color, which is critical for sparse volumes where a single noisy voxel could otherwise dominate an average [S1].
*   **Color Loss:** Without subsampling, chroma information can be completely lost at low bitrates, resulting in grey objects [S1].

## Operating characteristics
*   **Bitrate Reduction:** Chroma subsampling significantly reduces the bitrate required for color components. In the Leo sequence experiment, chroma subsampling achieved 39.30 dB PSNR at 1.18 bpv (bits per voxel), whereas non-subsampling required 2.90 bpv for the same quality [S1].
*   **Quality:** At low bitrates (e.g., 0.2 bpv), non-subsampled chroma results in grey objects due to complete loss of color information, while subsampled chroma retains color [S1].
*   **Complexity:** The method adds a grouping and median calculation step to the compression pipeline. The median calculation is $O(N \log N)$ or $O(N)$ for small fixed-size groups (8 voxels), which is negligible compared to transform and entropy coding steps.
*   **Strengths:** Preserves color quality at low bitrates; robust to outliers; simple to implement.
*   **Limitations:** Reduces spatial resolution of color; requires decoder-side interpolation/repetition for missing values; only applicable to color volumes (not scalar fields).

## Background
Chroma subsampling is a well-known technique in image and video compression (e.g., YCbCr 4:2:0) that exploits the human visual system's lower sensitivity to color detail compared to luminance detail [S1]. Its application to volumetric data was proposed to address the specific challenge of sparse volumetric representations where direct subsampling leads to significant information loss [S1]. The method was tested on multiview captured volumes, such as the Leo sequence, demonstrating its effectiveness in realistic view synthesis applications [S1].
