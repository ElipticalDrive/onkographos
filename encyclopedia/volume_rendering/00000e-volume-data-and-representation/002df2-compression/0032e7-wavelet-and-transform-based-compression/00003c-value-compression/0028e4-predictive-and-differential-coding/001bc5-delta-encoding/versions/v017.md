# Delta Encoding

Also called: Differential pulse-code modulation, Heightfield Compression, Temporal prediction

## Overview
Delta encoding is a predictive compression method that exploits temporal or spatial coherence by storing the difference (residual) between a predicted value and the actual value, rather than the absolute value itself [S1]. It is primarily used for time-varying volume data where voxel values exhibit high correlation between consecutive time steps, or for heightfields where values vary progressively [S1][S2, unofficial]. Unlike sibling methods that may use complex linear predictors or transform-domain residuals, delta encoding typically relies on the simplest prediction model: the previous value (temporal) or a base value (spatial/block) [S1][S2, unofficial]. Its key limitation is that it prevents random access to specific time steps or spatial locations without decompressing preceding data, unless absolute reference values are stored alongside the deltas [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of volume data frames (time-varying) or a heightfield grid. Let $V_t(x,y,z)$ be the voxel value at position $(x,y,z)$ in time step $t$.
*   **Output:** A stream of delta values (residuals) $R_t(x,y,z)$, which are subsequently entropy-coded.

**Data Structures:**
*   **Original Data:** $V_t$ (full precision, e.g., 16-bit or 32-bit integers/floats).
*   **Predicted Data:** $V_{pred}$ (same precision as $V_t$).
*   **Residual Data:** $R_t = V_t - V_{pred}$ (typically smaller dynamic range than $V_t$, allowing for reduced bit-depth or efficient entropy coding).

**Prediction Model:**
For time-varying data, the prediction model assumes the voxel value does not change between time steps [S1]:
$$ V_{pred}(x,y,z) = V_{t-1}(x,y,z) $$
For heightfields, the prediction may use a block base value (e.g., minimum height in a block) [S2, unofficial].

**Steps:**
1.  **Prediction:** For each voxel in the current time step $t$, calculate the predicted value $V_{pred}$ using the previous time step's value $V_{t-1}$ [S1].
2.  **Residual Calculation:** Compute the delta (residual) $R_t$ as the difference between the actual value and the predicted value:
    $$ R_t(x,y,z) = V_t(x,y,z) - V_{pred}(x,y,z) $$
3.  **Storage/Encoding:** Store or entropy-code the residual values $R_t$ [S1].
    *   If regions do not change between time steps, $R_t$ will be zero, creating uniform bricks that compress efficiently with variable-length coding [S1].
    *   The distribution of $R_t$ is typically non-uniform and has a smaller range than $V_t$, allowing for further compression [S1].
4.  **Decompression (GPU/CPU):**
    *   Decode the residuals $R_t$.
    *   Reconstruct the current volume by adding the decoded residual to the previously reconstructed (or original, depending on loop type) value:
        $$ V_{rec}(x,y,z) = V_{pred}(x,y,z) + R_t(x,y,z) $$
    *   On GPU, this is implemented by adding the calculated delta to the existing value in the volume buffer instead of overwriting it [S1].

**Pseudocode:**
```python
def delta_encode_time_varying(volume_prev, volume_curr):
    """
    Encodes time-varying volume data using delta encoding.
    volume_prev: 3D array of values at time t-1
    volume_curr: 3D array of values at time t
    Returns: 3D array of delta values
    """
    # Initialize delta array with same shape and dtype as volume_curr
    deltas = empty_like(volume_curr)
    
    # Calculate residuals
    for x in range(volume_curr.shape[0]):
        for y in range(volume_curr.shape[1]):
            for z in range(volume_curr.shape[2]):
                # Prediction: assume no change
                predicted = volume_prev[x, y, z]
                # Residual
                deltas[x, y, z] = volume_curr[x, y, z] - predicted
                
    return deltas

def delta_decode_time_varying(volume_prev_reconstructed, deltas):
    """
    Decodes time-varying volume data using delta encoding.
    volume_prev_reconstructed: 3D array of reconstructed values at time t-1
    deltas: 3D array of decoded delta values
    Returns: 3D array of reconstructed values at time t
    """
    # Initialize reconstructed array
    volume_curr_reconstructed = empty_like(deltas)
    
    # Reconstruct values
    for x in range(deltas.shape[0]):
        for y in range(deltas.shape[1]):
            for z in range(deltas.shape[2]):
                # Add delta to previous reconstructed value
                volume_curr_reconstructed[x, y, z] = volume_prev_reconstructed[x, y, z] + deltas[x, y, z]
                
    return volume_curr_reconstructed
```

**Parameters:**
*   **Bit-depth of Residuals:** Not explicitly defined in sources, but implied to be reduced compared to original data due to smaller dynamic range [S1].
*   **Block Size (for Heightfields):** Equal-sized blocks (e.g., $m \times n$) used to partition heightfields for independent compression [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Random Access:** Delta encoding prevents jumping directly to a certain time step because all previous time steps must be read to reconstruct the data [S1]. This can be resolved by saving absolute values in addition to delta values and loading them on demand, at the cost of increased storage [S1].
*   **Decompression Overhead:** Decompressing the whole dataset is required for any data access, which limits practical use in applications requiring efficient queries or traversals (e.g., realtime visualization) [S2, unofficial].
*   **Precision:** Not given in the sources. [G] Ensure integer overflow/underflow is handled if using fixed-point arithmetic for residuals.

## Subtopics

### [Heightfield Compression with Block-Based Delta Encoding](1116-heightfield-compression-with-block-based-delta-encoding.md)
This method compresses heightfields by partitioning them into equal-sized blocks, where each block is encoded relative to its minimum height value using a reduced bit-depth for the differences. It solves the primary limitation of standard delta encoding—where accessing any single value requires decompressing the entire dataset—by enabling random access with only two reads: one for the block header and one for the block's data.

### [Differences-based Compression](5723-differences-based-compression.md)
Differences-based Compression is a value compression method that stores quantized differences relative to a block base value, expanding them to 16-bit integers during decompression to reconstruct final data. It distinguishes itself from sibling methods by utilizing pre-computed shift patterns to handle variable bit-depths efficiently during SIMD-based decompression, avoiding runtime bit-manipulation overhead.

### Parallelogram Prediction with Diamond Residuals
Lossless compression of height fields using linear prediction. Height values are uniformly quantized to 16 bits. Parallelogram prediction is used for the z-component. Vertices are traversed in diagonal rows. The first three vertices of the first triangle are stored uncompressed. Subsequent vertices are predicted using a diamond configuration to maximize square diamond configurations, ensuring predictor vertices are close in the domain [S3].

## Operating characteristics
*   **Time Complexity:** Encoding and decoding are $O(N)$ where $N$ is the number of voxels, as each voxel requires one subtraction and one addition.
*   **Memory Complexity:** $O(N)$ for storing the original data (if needed for reference) and the delta data. If absolute values are stored for random access, memory usage increases [S1].
*   **Measured Performance:** Not given in the sources. [G] Performance depends heavily on the entropy coding efficiency of the resulting delta distribution.
*   **Scaling:** Not given in the sources.
*   **Strengths:** Simple to implement; effective for data with high temporal or spatial coherence; results in uniform bricks of zeros for unchanged regions, which compress well [S1].
*   **Limitations:** Prevents random access to time steps without storing absolute values; requires decompressing the whole dataset for any data access, limiting use in realtime visualization [S1][S2, unofficial].
*   **When to Use:** Time-varying volume data with high temporal coherence; heightfields with progressive variation.
*   **When Not to Use:** Applications requiring efficient random access to specific time steps or spatial locations without decompressing preceding data; data with low coherence.

## Background
Delta encoding, also known as Differential Pulse-Code Modulation (DPCM), was proposed for time-varying volume data to exploit temporal coherence [S1]. It was suggested as a simple method providing good results for heightfield compression because height values usually vary progressively [S2, unofficial]. The method is part of a broader family of predictive and differential coding techniques used in volume rendering and compression [S1].
