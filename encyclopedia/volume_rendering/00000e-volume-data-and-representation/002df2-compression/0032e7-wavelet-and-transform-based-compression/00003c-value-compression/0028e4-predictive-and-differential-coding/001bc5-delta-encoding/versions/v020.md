# Delta Encoding

Also called: Differential pulse-code modulation, Heightfield Compression, Temporal prediction

## Overview
Delta encoding (also known as Differential Pulse-Code Modulation or DPCM) is a predictive compression method that exploits redundancy in volume data by storing the difference between a predicted value and the actual value [S1]. It solves the problem of high storage requirements for volumetric data with high temporal or spatial coherence by transforming the data into residuals that have a smaller dynamic range and a higher probability of being zero [S1]. Unlike sibling methods that may use complex linear combinations or transform-domain residuals, standard delta encoding typically relies on simple prediction models such as temporal coherence (previous time step) or spatial progression, making it computationally trivial to implement but limited in random access capabilities [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A sequence of volume data (e.g., time-varying scalar fields or heightfields) where values exhibit coherence.
- Output: A compressed stream of residual (delta) values, often accompanied by base values or absolute values for specific access points.

**Data Structures:**
- **Residuals:** Integers representing $d_i = v_i - \hat{v}_i$. These are typically stored with reduced bit-depth if the range is small, or entropy-coded (e.g., variable-length coding) if the distribution is non-uniform [S1].
- **Base Values:** For block-based variants, a minimum or reference value per block [S1].
- **Absolute Values:** Optional storage of original values at keyframes or block headers to enable random access [S1].

**Steps:**
1. **Prediction:** Estimate the current voxel value $\hat{v}_i$ based on previously encoded data.
   - For time-varying data: $\hat{v}_i = v_{i-1}$ (predicting no change from the previous time step) [S1].
   - For spatial/heightfield data: $\hat{v}_i$ is estimated from adjacent neighbors or a block base value [S2, unofficial].
2. **Residual Calculation:** Compute the difference between the actual value $v_i$ and the prediction $\hat{v}_i$:
   $$ d_i = v_i - \hat{v}_i $$
   [S1]
3. **Encoding:** Store the residual $d_i$.
   - If regions are unchanged, $d_i = 0$, creating uniform bricks that compress efficiently with variable-length coding [S1].
   - If the residual range is small, store with reduced bit-depth [S1].
4. **Reconstruction:** The decoder retrieves $\hat{v}_i$ and adds the decoded residual:
   $$ v_i = \hat{v}_i + d_i $$
   [S1]

**Pseudocode (Time-Varying Volume Decompression on GPU):**
```python
# Assume 'volume' is the target texture/array, 'deltas' is the compressed residual data,
# and 'base_values' are optional absolute values for keyframes.
def decompress_delta_encoding(volume, deltas, base_values, time_step):
    # If base_values exist for this time_step, use them as the starting prediction
    if time_step in base_values:
        volume[:] = base_values[time_step]
        # Apply deltas for changes after the keyframe if needed, 
        # or treat base_values as the full state and deltas as incremental updates.
        # Standard DPCM implies sequential accumulation.
    
    # Iterate through deltas. In a GPU kernel, this is done in parallel threads.
    # Each thread processes a voxel or a block of voxels.
    for i in range(num_voxels):
        # Prediction: The current value in 'volume' is the previous state (or base)
        # The delta is added to it.
        delta = deltas[i]
        volume[i] = volume[i] + delta
        
    return volume
```
*[G] The pseudocode assumes a sequential dependency where `volume[i]` holds the predicted value $\hat{v}_i$ before the addition. In a parallel GPU kernel, this requires careful handling of dependencies or the use of base values for independent blocks.*

**Parameters:**
- **Prediction Model:** Simple temporal ($v_{t-1}$) or spatial [S1].
- **Bit Depth:** Determined by the range of residuals. If $\max(d) - \min(d) < 2^n$, store with $n$ bits [S1].

**Edge Cases and Pitfalls:**
- **Random Access Limitation:** Standard delta encoding prevents jumping to a specific time step because all previous time steps must be read to reconstruct the current state [S1].
- **Solution:** Save absolute values (keyframes) in addition to deltas. This increases storage but allows random access [S1].
- **Precision:** Ensure that the residual calculation does not overflow the storage type, especially if the prediction error is large [S1].

## Subtopics

### [Heightfield Compression with Block-Based Delta Encoding](1116-heightfield-compression-with-block-based-delta-encoding.md)
This method partitions a heightfield into equal-sized blocks and encodes each block relative to its minimum height value using a reduced bit-depth for the differences. It solves the primary limitation of standard delta encoding—where accessing any single value requires decompressing the entire dataset—by enabling random access with only two reads: one for the block header (containing the base value) and one for the block's data.

### [Differences-based Compression](5723-differences-based-compression.md)
Differences-based Compression stores quantized differences relative to a block base value, expanding them to 16-bit integers during decompression to reconstruct final data. It distinguishes itself from sibling methods by utilizing pre-computed shift patterns to handle variable bit-depths efficiently during SIMD-based decompression, avoiding runtime bit-manipulation overhead.

### Parallelogram Prediction with Diamond Residuals
A lossless compression method for height fields using linear prediction where height values are uniformly quantized to 16 bits [S3]. It uses parallelogram prediction for the z-component (height) and traverses vertices in diagonal rows to maximize square diamond configurations, ensuring predictor vertices are close in the domain [S3]. The first three vertices of the first triangle are stored uncompressed, and subsequent vertices are predicted using the diamond configuration [S3].

## Operating characteristics
- **Time Complexity:** Encoding and decoding are $O(N)$ where $N$ is the number of voxels, as each voxel requires one prediction and one addition/subtraction [S1].
- **Memory Complexity:** Storage is proportional to the entropy of the residuals. If residuals are zero or small, compression ratios are high [S1].
- **Performance:** On GPUs, implementation is trivial and can achieve full memory coalescing if threads are organized to process adjacent memory cells (e.g., by x-coordinate) [S1].
- **Strengths:** Simple to implement; highly effective for data with strong temporal or spatial coherence (e.g., time-varying volumes, heightfields) [S1][S2, unofficial].
- **Limitations:** Lack of random access in sequential encoding schemes; requires reading all previous data to reconstruct a specific time step [S1]. Not suitable for data with high-frequency noise or random changes [S1].

## Background
Delta encoding, also known as Differential Pulse-Code Modulation (DPCM), has been used in volume rendering to exploit temporal coherence in time-varying data [S1]. It was proposed as a simple method providing good results for heightfields because height values usually vary progressively [S2, unofficial]. The method is often combined with variable-length coding to compress the resulting uniform bricks of zero residuals [S1]. Variants like parallelogram prediction are used in terrain compression to maximize prediction accuracy by leveraging spatial proximity [S3].
