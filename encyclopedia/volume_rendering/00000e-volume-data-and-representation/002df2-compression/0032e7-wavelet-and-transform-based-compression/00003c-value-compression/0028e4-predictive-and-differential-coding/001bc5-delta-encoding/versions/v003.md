# Delta Encoding

Also called: Heightfield Compression

## Overview
Delta encoding is a predictive value compression method that stores the difference between a data element and a predicted value (typically the preceding element) rather than the absolute value [S1, unofficial]. It solves the problem of high entropy in smoothly varying volumetric data by reducing the dynamic range of the residuals, making them more amenable to entropy coding [S1, unofficial]. It is distinguished from sibling methods by its simplicity and reliance on local sequential correlation, though it suffers from poor random access capabilities because decoding any single value requires decompressing the entire preceding sequence [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of numeric values $V = \{v_0, v_1, \dots, v_{N-1}\}$ representing voxel heights or scalar fields.
*   **Output:** A sequence of residuals $E = \{e_0, e_1, \dots, e_{N-1}\}$ and potentially a base value for the first element.

**Data Structures:**
*   The input is treated as a 1D linearized sequence of the 3D volume, typically following a specific traversal order (e.g., row-major, Z-order).
*   Residuals $e_i$ are stored as signed integers. The bit-depth required depends on the maximum difference between adjacent values.

**Steps:**
1.  **Encode the first element:** The first value $v_0$ is stored explicitly as it has no predecessor.
    $$ e_0 = v_0 $$
2.  **Compute residuals:** For each subsequent element $v_i$ where $i > 0$, compute the difference from the previous value $v_{i-1}$.
    $$ e_i = v_i - v_{i-1} $$
3.  **Store residuals:** Store the sequence $E$. The original data can be reconstructed by cumulative summation.

**Pseudocode:**
```python
def delta_encode(values):
    """
    Compresses a sequence of values using delta encoding.
    Args:
        values: List of numeric values to compress.
    Returns:
        List of residuals.
    """
    if not values:
        return []
    
    residuals = [values[0]]
    for i in range(1, len(values)):
        # Calculate difference from previous value
        diff = values[i] - values[i-1]
        residuals.append(diff)
    return residuals

def delta_decode(residuals):
    """
    Decompresses a sequence of residuals back to values.
    Args:
        residuals: List of numeric residuals.
    Returns:
        List of reconstructed values.
    """
    if not residuals:
        return []
    
    values = [residuals[0]]
    for i in range(1, len(residuals)):
        # Reconstruct value by adding residual to previous value
        current_val = values[i-1] + residuals[i]
        values.append(current_val)
    return values
```

**Parameters:**
*   **Precision:** Residuals must be stored with sufficient bit-depth to avoid quantization error. If the original data is 16-bit, residuals may require fewer bits if the gradient is low.
*   **Traversal Order:** The linearization order of the 3D volume significantly impacts compression ratio. Orders that preserve spatial locality (e.g., Morton/Z-order) often yield smaller residuals for smooth volumes [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Random Access Limitation:** Accessing $v_i$ requires decoding all $e_0 \dots e_i$. This makes delta encoding unsuitable for applications requiring efficient random access or traversal without full decompression [S1, unofficial].
*   **Error Propagation:** In lossy variants, quantization errors in residuals propagate to all subsequent values.
*   **Large Gradients:** If the data contains sharp discontinuities or high-frequency noise, residuals may be large, negating the compression benefit.

## Subtopics

### [Heightfield Compression with Block-Based Delta Encoding](1116-heightfield-compression-with-block-based-delta-encoding.md)
This method compresses heightfields by partitioning them into equal-sized blocks, where each block is encoded relative to its minimum height value using a reduced bit-depth for the differences. It solves the primary limitation of standard delta encoding—where accessing any single value requires decompressing the entire dataset—by enabling random access with only two reads: one for the block header and one for the block's data.

### [Differences-based Compression](5723-differences-based-compression.md)
Differences-based Compression is a value compression method that stores quantized differences relative to a block base value, expanding them to 16-bit integers during decompression to reconstruct final data. It distinguishes itself from sibling methods by utilizing pre-computed shift patterns to handle variable bit-depths efficiently during SIMD-based decompression, avoiding runtime bit-manipulation overhead.

## Operating characteristics
*   **Time Complexity:** Encoding and decoding are $O(N)$, where $N$ is the number of voxels. The operations are simple subtractions and additions.
*   **Memory Complexity:** $O(N)$ for storing residuals. The storage size depends on the bit-depth required for the maximum residual.
*   **Performance:** Provides good compression ratios for data with progressive variation (e.g., heightfields, smooth scalar fields) [S1, unofficial].
*   **Strengths:** Extremely low computational overhead; simple to implement; effective for smooth data.
*   **Limitations:** No random access support without full decompression; sensitive to data ordering; poor performance on noisy or discontinuous data [S1, unofficial].
*   **When to use:** Ideal for streaming scenarios or when the entire dataset is accessed sequentially. Suitable for heightfields with smooth gradients.
*   **When not to use:** Unsuitable for interactive visualization requiring random access or ray-casting into specific regions without decompressing the whole volume [S1, unofficial].

## Background
Delta encoding is a classic technique in data compression. In the context of volume rendering and layered datasets, it is often applied to heightfields or interval data where values change progressively. The QuadStack representation notes that while simple delta encoding provides good results for heightfields, its lack of random access limits its practical use in real-time visualization, leading to block-based variants [S1, unofficial].
