# Residual Updates in Transform Domain

Also called: Inter-frame DCT coding

## Overview
Residual Updates in Transform Domain is a temporal compression method for volumetric data that operates in the frequency domain rather than the spatial domain. It solves the problem of encoding time-varying volumes by predicting current transform coefficients from the previously reconstructed frame's coefficients, rather than predicting voxel values directly. It sets itself apart from spatial predictors like [Delta Encoding](1096-delta-encoding.md) by concentrating residual energy near regions of surface change in the transform domain, which improves compressibility for subsequent entropy coding [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of volumetric frames. Each frame is divided into fixed-size blocks. For each block $b$ at time $t$, the input is the 3D DCT coefficient vector $\mathbf{c}_t^{(b)}$.
*   **Output:** A bitstream containing entropy-coded residuals $\Delta \mathbf{c}_t^{(b)}$ and block activity flags.

**Data Structures:**
*   **Reference Buffer:** A map keyed by block coordinates $(x, y, z)$ storing the reconstructed DCT coefficients $\tilde{\mathbf{c}}_{t-1}^{(b)}$ from the previous frame.
*   **Block Activity:** A flag indicating if block $b$ is active (present) or inactive (absent) in the current frame.

**Steps:**
1.  **Initialization:** For the first frame ($t=0$), encode the block using standard intra-coding (DCT + quantization + entropy coding). Initialize the reference buffer $\tilde{\mathbf{c}}_{-1}^{(b)}$ with the reconstructed coefficients of this frame.
2.  **Transform:** For each subsequent frame $t$, compute the 3D DCT for every active block $b$ to obtain $\mathbf{c}_t^{(b)}$.
3.  **Residual Formation:** For each block $b$:
    *   If block $b$ is **active** in frame $t$:
        *   Retrieve the reference coefficients $\tilde{\mathbf{c}}_{t-1}^{(b)}$ from the buffer. If block $b$ was inactive in $t-1$, $\tilde{\mathbf{c}}_{t-1}^{(b)} = \mathbf{0}$.
        *   Compute the residual:
            $$ \Delta \mathbf{c}_t^{(b)} = \mathbf{c}_t^{(b)} - \tilde{\mathbf{c}}_{t-1}^{(b)} $$
    *   If block $b$ is **inactive** in frame $t$ but was active in $t-1$:
        *   Treat as a removal event. Set $\mathbf{c}_t^{(b)} = \mathbf{0}$ effectively, or explicitly signal the removal. The residual is formed against the reference:
            $$ \Delta \mathbf{c}_t^{(b)} = \mathbf{0} - \tilde{\mathbf{c}}_{t-1}^{(b)} = -\tilde{\mathbf{c}}_{t-1}^{(b)} $$
        *   Update the reference buffer for this block to $\mathbf{0}$ after encoding.
    *   If block $b$ is **inactive** in both frames:
        *   No data needs to be encoded for this block.
4.  **Quantization:** Quantize the residual coefficients $\Delta \mathbf{c}_t^{(b)}$ using the same quantization steps (DC and AC handling) as intra coding. Let $Q(\cdot)$ denote the quantization function.
5.  **Entropy Coding:** Range-encode the quantized residual integers using the same per-coefficient entropy coding strategy as intra coding. This requires maintaining adaptive probability models for the coefficient streams [S1].
6.  **Closed-Loop Update:** To prevent encoder-decoder drift, the encoder must update its reference buffer using the reconstructed (dequantized) residual, not the raw residual:
    $$ \tilde{\mathbf{c}}_t^{(b)} = \tilde{\mathbf{c}}_{t-1}^{(b)} + Q^{-1}(Q(\Delta \mathbf{c}_t^{(b)})) $$
    where $Q^{-1}(\cdot)$ is the dequantization function. This updated buffer is used for predicting the next frame $t+1$.

**Pseudocode:**

```python
def encode_transform_domain_residual(frame_blocks, prev_ref_buffer, quantizer, entropy_coder):
    """
    Encodes a frame using residual updates in the DCT domain.
    
    Args:
        frame_blocks: Dict mapping block_id -> DCT_coefficients (vector)
        prev_ref_buffer: Dict mapping block_id -> reconstructed DCT_coefficients from t-1
        quantizer: Function Q(x) that quantizes coefficients
        entropy_coder: Function that range-encodes integers
        
    Returns:
        bitstream: Encoded data
        new_ref_buffer: Updated reference buffer for next frame
    """
    bitstream = []
    new_ref_buffer = {}
    
    # Identify active blocks in current frame
    current_block_ids = set(frame_blocks.keys())
    previous_block_ids = set(prev_ref_buffer.keys())
    
    # Process all blocks that were active in previous frame or are active now
    all_block_ids = current_block_ids.union(previous_block_ids)
    
    for block_id in all_block_ids:
        is_active_now = block_id in current_block_ids
        has_ref = block_id in prev_ref_buffer
        
        if is_active_now:
            c_t = frame_blocks[block_id]
            if has_ref:
                c_tilde_prev = prev_ref_buffer[block_id]
            else:
                c_tilde_prev = np.zeros_like(c_t)
            
            # Step 3a: Compute residual
            delta_c = c_t - c_tilde_prev
            
            # Step 4: Quantize
            quantized_delta = quantizer(delta_c)
            
            # Step 5: Encode
            entropy_coder.encode(quantized_delta)
            
            # Step 6: Closed-loop update
            reconstructed_delta = quantizer.inverse(quantized_delta)
            new_c_tilde = c_tilde_prev + reconstructed_delta
            new_ref_buffer[block_id] = new_c_tilde
            
        else:
            # Block is inactive in current frame
            if has_ref:
                # Removal event: residual is negative of reference
                c_tilde_prev = prev_ref_buffer[block_id]
                delta_c = -c_tilde_prev
                
                # Quantize and encode
                quantized_delta = quantizer(delta_c)
                entropy_coder.encode(quantized_delta)
                
                # Update reference to zero (block removed)
                new_ref_buffer[block_id] = np.zeros_like(c_tilde_prev)
            else:
                # Block was never active and is not active now: do nothing
                pass
                
    return bitstream, new_ref_buffer
```

**Parameters:**
*   **Block Size:** Fixed size for 3D DCT. Not given in the sources.
*   **Quantization Step:** Same as intra coding. Not given in the sources.

**Edge Cases:**
*   **Block Appearance/Disappearance:** If a block appears (was inactive, now active), the reference is treated as zero. If a block disappears (was active, now inactive), the residual is the negative of the reference, and the reference is reset to zero [S1].
*   **Drift Prevention:** Failure to use the closed-loop update (using reconstructed values for prediction) will cause encoder-decoder mismatch and error propagation [S1].

## Subtopics

### Zero-Motion Block Prediction
A specific application of residual updates in transform domain for TSDF (Truncated Signed Distance Field) volumes. It reuses the previous reconstructed TSDF on the same voxel block grid as a "zero-motion predictor." Only blockwise residual updates are encoded, which concentrates residual energy near regions of surface change, improving compressibility for subsequent transform and range encoding [S1]. It requires sending one intra-coded frame to initialize the decoder reference [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of blocks and coefficients, dominated by the DCT transform and entropy coding. It is computationally efficient and does not require explicit correspondence tracking [S1].
*   **Memory Complexity:** Requires storing the reference coefficient buffer for all active blocks.
*   **Strengths:** Simple and efficient for temporally coherent volumes. Effective for TSDF volumes where surface changes are localized [S1].
*   **Limitations:** Requires temporal coherence. Random access to specific time steps is limited because the reference buffer depends on the previous frame's reconstruction [1096-delta-encoding.md].
*   **When to use:** When encoding time-varying volumetric data with slow or local changes (e.g., animation, medical time-series).
*   **When not to use:** When there is no temporal coherence or when random access to arbitrary time steps is required without decoding all preceding frames.

## Background
Originated in the context of implicit surface compression using DCT and motion compensation [S1]. It leverages the regular, indexable structure of block-based DCT to simplify temporal coding compared to explicit geometry codecs [S1].
