# Optimal Linear Volumetric Predictor with Truncated Huffman Coding

Also called: DPCM with Huffman Coding, DPCM-Huffman, Predictive Huffman Coding for Volumes, Volume DPCM with Huffman Coding, compvox algorithm, volumetric DPCM with optimal coefficients, 差值编码与霍夫曼编码结合

## Overview
This method is a lossless compression algorithm for 3D volume data that removes spatial redundancy by predicting voxel values from previously encoded neighbors and encoding the residual error using a truncated Huffman code [S1, unofficial]. It distinguishes itself from generic compressors (e.g., gzip, zip) by explicitly modeling the spatial coherence of volumetric data through an optimal linear predictor derived from the data's global statistics, rather than relying solely on statistical redundancy removal [S1, unofficial].

## How it works
The algorithm operates in two phases: a preprocessing phase to determine optimal predictor coefficients and a Huffman codebook, and an encoding/decoding phase that scans the volume to generate and compress residuals.

### Inputs and Outputs
- **Input**: A 3D volume array $v(x, y, z)$ of size $X \times Y \times Z$. The source specifies 16-bit integer voxels, implying a difference value range of $[-66535, 65536]$ and a total alphabet size of $L = 131,071$ possible symbols [S1, unofficial].
- **Output**: A compressed bitstream containing the encoded difference values, preceded by a header storing the mean, predictor coefficients, and Huffman table [S1, unofficial].

### Data Structures
1.  **Volume Data**: Stored in raster-scan order (x, then y, then z) to ensure causality [S1, unofficial].
2.  **Covariance Matrix**: A $3 \times 3$ symmetric matrix $A$ and vector $b$ used to solve for predictor coefficients. The elements are derived from the estimated covariance $r(x, y, z)$ for lags in $\{-1, 0, 1\}$ [S1, unofficial].
3.  **Huffman Table**: A mapping from difference values (symbols $s_i$) to variable-length bit codes. It is a "truncated" table where the $L_1$ most frequent symbols are Huffman-coded, and the remaining $L - L_1$ symbols are assigned fixed-length codes [S1, unofficial].

### Parameters
-   **Predictor Order**: 3 coefficients ($a_1, a_2, a_3$) using the 6-neighborhood (face-sharing neighbors only) [S1, unofficial].
-   **Truncation Parameter ($L_1$)**: The number of most frequent symbols to Huffman code. Default value is $L_1 = 256$ [S1, unofficial].
-   **Scan Order**: Raster-scan (x-major, then y, then z) [S1, unofficial].

### Steps

#### 1. Estimate Global Statistics
The algorithm assumes wide-sense stationarity and calculates global mean and covariance [S1, unofficial].

**Step 1: Estimate Mean**
Scan the entire volume to calculate the mean $\bar{v}$:
$$ \bar{v} = \frac{1}{XYZ} \sum_{x=0}^{X-1} \sum_{y=0}^{Y-1} \sum_{z=0}^{Z-1} v(x, y, z) $$

**Step 2: Estimate Covariance**
Scan the volume to estimate the covariance $r(x, y, z)$ for lags $x, y, z \in \{-1, 0, 1\}$:
$$ r(x, y, z) = \frac{1}{(X-2)(Y-2)(Z-2)} \sum_{x'=1}^{X-2} \sum_{y'=1}^{Y-2} \sum_{z'=1}^{Z-2} [v(x', y', z') - \bar{v}] [v(x'+x, y'+y, z'+z) - \bar{v}] $$
*Note: The source notes that while these two scans could theoretically be combined, separate scans are used for greater mathematical precision [S1, unofficial].*

#### 2. Calculate Predictor Coefficients
Solve the linear system derived from the Yule-Walker equations to minimize the mean-square error of the prediction [S1, unofficial]. The system is:
$$ A \mathbf{a} = \mathbf{b} $$
Where $\mathbf{a} = [a_1, a_2, a_3]^T$ and the matrix $A$ and vector $\mathbf{b}$ are defined by the estimated covariance values as follows (as per Eq. 8 in the source):
$$
\begin{bmatrix}
r(0,0,0) & r(1,-1,0) & r(1,0,-1) \\
r(-1,1,0) & r(0,0,0) & r(0,1,-1) \\
r(-1,0,1) & r(0,-1,1) & r(0,0,0)
\end{bmatrix}
\begin{bmatrix}
a_1 \\
a_2 \\
a_3
\end{bmatrix}
=
\begin{bmatrix}
r(1,0,0) \\
r(0,1,0) \\
r(0,0,1)
\end{bmatrix}
$$
*Note: The source explicitly provides this matrix layout, noting it may contain index typos compared to standard Yule-Walker forms, but instructs to solve this specific system [S1, unofficial].*

#### 3. Calculate Difference Values (First Pass)
Scan the volume to compute the residuals $d(x, y, z)$. The predictor uses mean-subtracted neighbors to ensure orthogonality [S1, unofficial].

For each voxel $(x, y, z)$:
1.  Determine neighbor values $v_1, v_2, v_3$:
    $$
    v_1(x, y, z) = \begin{cases} 0 & \text{if } x = 0 \\ v(x-1, y, z) - \bar{v} & \text{if } x > 0 \end{cases}
    $$
    $$
    v_2(x, y, z) = \begin{cases} 0 & \text{if } y = 0 \\ v(x, y-1, z) - \bar{v} & \text{if } y > 0 \end{cases}
    $$
    $$
    v_3(x, y, z) = \begin{cases} 0 & \text{if } z = 0 \\ v(x, y, z-1) - \bar{v} & \text{if } z > 0 \end{cases}
    $$
2.  Calculate predicted value:
    $$ \tilde{v}(x, y, z) = a_1 v_1(x, y, z) + a_2 v_2(x, y, z) + a_3 v_3(x, y, z) $$
3.  Calculate difference:
    $$ d(x, y, z) = v(x, y, z) - \tilde{v}(x, y, z) $$

*Note: The source states these difference values are not stored to prevent excessive memory costs, necessitating a fourth scan later [S1, unofficial].*

#### 4. Build Huffman Table
1.  Count the occurrences of each difference value $s_i$ across the volume to estimate symbol probabilities $p_i$ [S1, unofficial].
2.  Construct a truncated Huffman code:
    -   Sort symbols by frequency.
    -   Assign Huffman codes to the $L_1$ most frequent symbols (default $L_1 = 256$) [S1, unofficial].
    -   Assign fixed-length codes to the remaining $L - L_1$ symbols [S1, unofficial].

#### 5. Encode Volume (Second Pass)
Scan the volume again in raster-scan order. For each voxel:
1.  Recalculate $d(x, y, z)$ using the same predictor logic as Step 3.
2.  Encode $d(x, y, z)$ using the Huffman table.
3.  Write the encoded bits to the output stream. Do not store the difference values themselves [S1, unofficial].

#### 6. Compressed File Header
The compressed file must begin with:
-   The estimated mean $\bar{v}$ [S1, unofficial].
-   The three predictor coefficients $a_1, a_2, a_3$ [S1, unofficial].
-   The Huffman code table (mapping source symbols $s_i$ to their assigned codes) [S1, unofficial].

#### Decompression Algorithm
1.  Read $\bar{v}$, $a_1, a_2, a_3$, and the Huffman table from the header [S1, unofficial].
2.  Read the next Huffman code from the stream and look up the corresponding difference value $d(x, y, z)$ [S1, unofficial].
3.  Calculate the predicted value $\tilde{v}(x, y, z)$ using the same causal predictor logic (using previously reconstructed voxels) [S1, unofficial].
4.  Reconstruct the voxel:
    $$ v(x, y, z) = \tilde{v}(x, y, z) + d(x, y, z) $$
5.  Repeat for all voxels [S1, unofficial].

```python
def compress_volume(volume, L1=256):
    """
    Compress a 3D volume using Optimal Linear Predictor and Truncated Huffman Coding.
    volume: 3D array of shape (X, Y, Z) containing 16-bit integers.
    L1: Number of most frequent symbols to Huffman code.
    """
    X, Y, Z = volume.shape
    
    # Step 1: Estimate Mean
    mean_v = sum(volume[x, y, z] for x in range(X) for y in range(Y) for z in range(Z)) / (X * Y * Z)
    
    # Step 2: Estimate Covariance
    # Covariance r(x, y, z) for lags in {-1, 0, 1}
    # Note: Source uses specific summation bounds and normalization factor
    cov = {}
    norm_factor = (X - 2) * (Y - 2) * (Z - 2)
    for dx in [-1, 0, 1]:
        for dy in [-1, 0, 1]:
            for dz in [-1, 0, 1]:
                sum_val = 0
                for x_prime in range(1, X - 1):
                    for y_prime in range(1, Y - 1):
                        for z_prime in range(1, Z - 1):
                            val1 = volume[x_prime, y_prime, z_prime] - mean_v
                            val2 = volume[x_prime + dx, y_prime + dy, z_prime + dz] - mean_v
                            sum_val += val1 * val2
                cov[(dx, dy, dz)] = sum_val / norm_factor

    # Step 3: Solve for Predictor Coefficients
    # Matrix A and vector b as defined in source Eq. 8
    # A = [[r(0,0,0), r(1,-1,0), r(1,0,-1)],
    #      [r(-1,1,0), r(0,0,0), r(0,1,-1)],
    #      [r(-1,0,1), r(0,-1,1), r(0,0,0)]]
    # b = [r(1,0,0), r(0,1,0), r(0,0,1)]
    
    r = cov
    A = [
        [r[(0,0,0)], r[(1,-1,0)], r[(1,0,-1)]],
        [r[(-1,1,0)], r[(0,0,0)], r[(0,1,-1)]],
        [r[(-1,0,1)], r[(0,-1,1)], r[(0,0,0)]]
    ]
    b = [r[(1,0,0)], r[(0,1,0)], r[(0,0,1)]]
    
    # Solve linear system A * a = b for a = [a1, a2, a3]
    # Using a standard linear solver (e.g., Gaussian elimination)
    a = solve_linear_system(A, b)
    a1, a2, a3 = a

    # Step 4: Calculate Difference Values (First Pass - not stored)
    # We need to count frequencies for Huffman table
    diff_counts = {}
    
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                # Determine neighbors
                v1 = 0 if x == 0 else volume[x-1, y, z] - mean_v
                v2 = 0 if y == 0 else volume[x, y-1, z] - mean_v
                v3 = 0 if z == 0 else volume[x, y, z-1] - mean_v
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                diff = volume[x, y, z] - pred
                
                # Count frequency
                diff_counts[diff] = diff_counts.get(diff, 0) + 1

    # Step 5: Build Huffman Table
    # Sort symbols by frequency
    sorted_symbols = sorted(diff_counts.keys(), key=lambda s: diff_counts[s], reverse=True)
    
    # Truncated Huffman: Top L1 symbols get Huffman codes, rest get fixed length
    huffman_table = {}
    top_symbols = sorted_symbols[:L1]
    other_symbols = sorted_symbols[L1:]
    
    # Generate Huffman codes for top symbols
    # (Implementation of Huffman tree construction omitted for brevity, 
    # assuming a function generate_huffman_codes exists)
    huffman_codes = generate_huffman_codes(top_symbols)
    for sym in top_symbols:
        huffman_table[sym] = huffman_codes[sym]
        
    # Assign fixed length codes to remaining symbols
    # Fixed length must be sufficient to represent L - L1 symbols
    fixed_len_bits = ceil(log2(len(other_symbols))) if other_symbols else 0
    for i, sym in enumerate(other_symbols):
        huffman_table[sym] = format(i, f'0{fixed_len_bits}b')

    # Step 6: Encode Volume (Second Pass)
    output_bits = []
    
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                v1 = 0 if x == 0 else volume[x-1, y, z] - mean_v
                v2 = 0 if y == 0 else volume[x, y-1, z] - mean_v
                v3 = 0 if z == 0 else volume[x, y, z-1] - mean_v
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                diff = volume[x, y, z] - pred
                
                # Encode diff
                code = huffman_table[diff]
                output_bits.append(code)
                
    return mean_v, a1, a2, a3, huffman_table, "".join(output_bits)
```

### Edge Cases and Pitfalls
-   **Causality**: The predictor must strictly use only previously processed voxels ($x-1, y, z$), ($x, y-1, z$), and ($x, y, z-1$). Violating this makes the decoder unable to reproduce the prediction [S1, unofficial].
-   **Non-stationarity**: The optimal predictor assumes wide-sense stationarity. Real volume data is not stationary, making global statistics suboptimal. The source suggests dividing the volume into an octree for local predictors as a future improvement [S1, unofficial].
-   **Memory vs. Speed**: The algorithm scans the volume four times (two for statistics, one for calculating differences, one for encoding). Difference values are not stored to save memory, requiring the redundant calculation in the final scan [S1, unofficial].
-   **Boundary Handling**: Neighbors on the boundary ($x=0, y=0, z=0$) are treated as having a mean-subtracted value of 0. This ensures the prediction error is orthogonal to the input variables [S1, unofficial].

## Operating characteristics
-   **Time Complexity**: The algorithm is computationally intensive due to multiple full-volume scans. On a HP 9000 Series 735, compression of the 3dhead.vox dataset took 4.7 minutes, while decompression took 1.4 minutes [S1, unofficial]. The calculation of optimal predictor coefficients takes approximately 6% of the total compression time [S1, unofficial].
-   **Memory Complexity**: Low memory footprint during encoding/decoding as difference values are not stored. However, the Huffman table and covariance calculations require auxiliary memory proportional to the alphabet size and fixed matrix sizes [S1, unofficial].
-   **Compression Ratio**: Achieves approximately 50% compression (reducing file size to ~50% of original) for a set of volume data files [S1, unofficial]. Specific results on 3dhead.vox (256x256x109, 13.6 Mb) showed 48.5% compression (compvox) compared to 36.1% (gzip) and 33.8% (zip) [S1, unofficial].
-   **Strengths**: Removes spatial redundancy effectively, outperforming generic compressors (gzip, zip, compress, pack) on volume data [S1, unofficial]. The optimal predictor automatically compensates for non-isotropic sampling [S1, unofficial].
-   **Limitations**: Assumes global stationarity, which may not hold for complex volumes. The four-pass nature makes it slower than generic compressors (e.g., gzip compressed 3dhead.vox in 1.4 min vs compvox 4.7 min) [S1, unofficial].

## Background
-   **Origin**: Introduced by James Edwin Fowler and Roni Yagel in January 1995 at the Proceedings of the 1994 Symposium on Volume Visualization [S1, unofficial].
-   **History**: The algorithm was developed to address the high storage costs of volumetric data in biomedical and scientific applications where lossless compression is required. It was named "compvox" in the source literature [S1, unofficial].
-   **Usage**: Primarily used for archiving and transmitting medical imaging data (MRI, CT) and scientific volume datasets where lossless reconstruction is critical [S1, unofficial].
