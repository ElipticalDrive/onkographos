# Optimal Linear Volumetric Predictor with Truncated Huffman Coding

Also called: DPCM with Huffman Coding, DPCM-Huffman, Predictive Huffman Coding for Volumes, Volume DPCM with Huffman Coding, compvox algorithm, volumetric DPCM with optimal coefficients, 差值编码与霍夫曼编码结合

## Overview
This method is a lossless compression algorithm for 3D volume data that exploits spatial coherence by predicting voxel values from previously encoded neighbors and encoding the difference (residual) using a truncated Huffman code [S1, unofficial]. It sets itself apart from generic compressors (like gzip or zip) by explicitly removing spatial redundancy through a causal linear predictor derived from the data's local statistics, rather than relying solely on statistical redundancy removal [S1, unofficial]. It builds on [DPCM with Huffman Coding](16225-dpcm-with-huffman-coding.md) by specifying the optimal calculation of predictor coefficients via the Yule-Walker equations and the use of truncated Huffman coding to manage codebook size for large alphabets.

## How it works
The algorithm operates in two phases: coefficient estimation and encoding/decoding. It assumes the volume data is wide-sense stationary to derive optimal predictor coefficients [S1, unofficial].

### Inputs and Outputs
- **Input**: A 3D volume array $v(x, y, z)$ of size $X \times Y \times Z$. The source specifies 16-bit voxels, implying difference values $d(x, y, z)$ range from $-66535$ to $65536$, resulting in an alphabet size $L = 131,071$ [S1, unofficial].
- **Output**: A compressed bitstream containing the Huffman-encoded difference values, preceded by a header storing the mean, predictor coefficients, and the Huffman code table [S1, unofficial].

### Data Structures
1.  **Volume Data**: Stored in raster-scan order (x, then y, then z) to ensure causality [S1, unofficial].
2.  **Covariance Matrix**: A $3 \times 3$ symmetric matrix $A$ and vector $b$ used to solve for predictor coefficients. Elements are derived from covariance estimates $r(x, y, z)$ for lags in $\{-1, 0, 1\}$ [S1, unofficial].
3.  **Huffman Table**: A mapping from source symbols (difference values $s_i$) to codewords. It handles the top $L_1$ most frequent symbols with variable-length Huffman codes and the remaining $L - L_1$ symbols with fixed-length codes [S1, unofficial].

### Parameters
-   **Predictor Order**: 3 coefficients ($a_1, a_2, a_3$) using the 6-neighborhood (face-sharing neighbors only) [S1, unofficial].
-   **Truncated Huffman Parameter ($L_1$)**: The number of most frequent symbols Huffman coded. Default value: $L_1 = 256$ [S1, unofficial].
-   **Scan Order**: Raster-scan order [S1, unofficial].

### Step-by-Step Method

#### 1. Estimate Mean
Scan the entire volume to calculate the mean $\bar{v}$:
$$ \bar{v} = \frac{1}{XYZ} \sum_{x=0}^{X-1} \sum_{y=0}^{Y-1} \sum_{z=0}^{Z-1} v(x, y, z) $$
[S1, unofficial]

#### 2. Estimate Covariance
Scan the volume to estimate the covariance $r(x, y, z)$ for lags $x, y, z \in \{-1, 0, 1\}$:
$$ r(x, y, z) = \frac{1}{(X-2)(Y-2)(Z-2)} \sum_{x'=1}^{X-2} \sum_{y'=1}^{Y-2} \sum_{z'=1}^{Z-2} [v(x', y', z') - \bar{v}] [v(x'+x, y'+y, z'+z) - \bar{v}] $$
[S1, unofficial]

#### 3. Calculate Predictor Coefficients
Solve the linear system $A \mathbf{a} = \mathbf{b}$ for coefficients $\mathbf{a} = [a_1, a_2, a_3]^T$. The matrix $A$ and vector $\mathbf{b}$ are defined by the estimated covariance values:
$$
\begin{bmatrix}
r(0,0,0) & r(1,-1,0) & r(1,0,-1) \\
r(-1,1,0) & r(0,0,0) & r(0,1,-1) \\
r(-1,0,1) & r(0,-1,1) & r(0,0,0)
\end{bmatrix}
\begin{bmatrix}
a_1 \\
a_2 \\
a_3
\end{bmatrix}
=
\begin{bmatrix}
r(1,0,0) \\
r(0,1,0) \\
r(0,0,1)
\end{bmatrix}
$$
Note: The source provides this specific matrix layout in Eq (8), which may contain index typos compared to standard Yule-Walker formulations, but this is the implementation instruction [S1, unofficial].

#### 4. Calculate Difference Values (First Pass)
Scan the volume to calculate difference values $d(x, y, z)$. For each voxel, calculate the predicted value $\tilde{v}(x, y, z)$:
$$ \tilde{v}(x, y, z) = a_1 v_1(x, y, z) + a_2 v_2(x, y, z) + a_3 v_3(x, y, z) $$
The neighbor values are mean-subtracted and zeroed at boundaries to ensure orthogonality:
$$
v_1(x, y, z) = \begin{cases} 
0 & \text{if } x = 0 \\
v(x-1, y, z) - \bar{v} & \text{else}
\end{cases}
$$
$$
v_2(x, y, z) = \begin{cases} 
0 & \text{if } y = 0 \\
v(x, y-1, z) - \bar{v} & \text{else}
\end{cases}
$$
$$
v_3(x, y, z) = \begin{cases} 
0 & \text{if } z = 0 \\
v(x, y, z-1) - \bar{v} & \text{else}
\end{cases}
$$
Then compute the difference:
$$ d(x, y, z) = v(x, y, z) - \tilde{v}(x, y, z) $$
[S1, unofficial]

#### 5. Count Symbol Frequencies
Count the occurrences of each difference value $d(x, y, z) = s_i$ across the volume. These counts estimate the symbol probabilities $p_i$ [S1, unofficial].

#### 6. Build Huffman Table
Determine a truncated Huffman code table using probabilities $p_i$. The first $L_1=256$ most frequent symbols are Huffman coded. The remaining $L - L_1$ symbols are assigned fixed-length codes. The maximum code length is restricted to a manageable size [S1, unofficial].

#### 7. Encode
Scan the volume again. Calculate $d(x, y, z)$ using the predictor (same as Step 4) and encode each $d(x, y, z)$ using the Huffman table. Do not store the difference values, only the encoded bits [S1, unofficial].

#### Decompression
1.  Read the estimated mean $\bar{v}$, predictor coefficients $a_1, a_2, a_3$, and the Huffman code table from the compressed file header [S1, unofficial].
2.  For each voxel in raster-scan order:
    a. Read the next Huffman code from the compressed file and look up the difference value $d(x, y, z)$ in the Huffman table [S1, unofficial].
    b. Calculate the predicted value $\tilde{v}(x, y, z)$ using the same predictor logic (Step 4) and the *reconstructed* previous voxel values [S1, unofficial].
    c. Reconstruct the current voxel: $v(x, y, z) = \tilde{v}(x, y, z) + d(x, y, z)$ [S1, unofficial].

### Pseudocode

```python
def compress_volume(volume: Array3D, L1: int = 256) -> bytes:
    """
    Compress a 3D volume using Optimal Linear Predictor and Truncated Huffman Coding.
    volume: 3D array of shape (X, Y, Z) with 16-bit integers.
    Returns: bytes containing header and compressed bitstream.
    """
    X, Y, Z = volume.shape
    
    # Step 1: Estimate Mean
    mean_v = sum(volume[x, y, z] for x in range(X) for y in range(Y) for z in range(Z)) / (X * Y * Z)
    
    # Step 2: Estimate Covariance
    # Covariance r(x, y, z) for lags in {-1, 0, 1}
    # Note: Implementation must handle the specific summation bounds and normalization factor
    # r(lag_x, lag_y, lag_z) = (1 / ((X-2)(Y-2)(Z-2))) * sum(...)
    # We compute the 9 unique covariances needed for the matrix A and vector b.
    cov = {}
    norm_factor = 1.0 / ((X - 2) * (Y - 2) * (Z - 2))
    
    # Helper to compute covariance for specific lag
    def get_cov(lag_x, lag_y, lag_z):
        total = 0.0
        for x_prime in range(1, X - 1):
            for y_prime in range(1, Y - 1):
                for z_prime in range(1, Z - 1):
                    val1 = volume[x_prime, y_prime, z_prime] - mean_v
                    val2 = volume[x_prime + lag_x, y_prime + lag_y, z_prime + lag_z] - mean_v
                    total += val1 * val2
        return norm_factor * total

    # Compute required covariances
    r_000 = get_cov(0, 0, 0)
    r_100 = get_cov(1, 0, 0)
    r_010 = get_cov(0, 1, 0)
    r_001 = get_cov(0, 0, 1)
    r_1_10 = get_cov(1, -1, 0)
    r_10_1 = get_cov(1, 0, -1)
    r_1_10_sym = get_cov(-1, 1, 0) # Should equal r_1_10 if symmetric, but source uses specific indices
    r_01_1 = get_cov(0, 1, -1)
    r_1_01 = get_cov(-1, 0, 1)
    r_0_11 = get_cov(0, -1, 1)
    
    # Step 3: Solve for Predictor Coefficients
    # Matrix A and Vector b as defined in Eq (8)
    A = [
        [r_000, r_1_10, r_10_1],
        [r_1_10_sym, r_000, r_01_1],
        [r_1_01, r_0_11, r_000]
    ]
    b = [r_100, r_010, r_001]
    
    # Solve linear system A * a = b
    # Using a standard linear solver (e.g., Gaussian elimination or numpy.linalg.solve)
    coeffs = solve_linear_system(A, b)
    a1, a2, a3 = coeffs
    
    # Step 4 & 5: Calculate Differences and Count Frequencies
    # We do not store differences to save memory, so we count frequencies on the fly
    # and store differences in a temporary buffer if needed for Huffman building, 
    # but the source says "Count the number of times... These counts are estimates".
    # To build the Huffman tree, we need the actual symbols or their counts.
    # We will count frequencies first.
    
    freq = {} # Map difference value -> count
    
    # First pass: Count frequencies
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                # Calculate predicted value
                v1 = 0 if x == 0 else volume[x-1, y, z] - mean_v
                v2 = 0 if y == 0 else volume[x, y-1, z] - mean_v
                v3 = 0 if z == 0 else volume[x, y, z-1] - mean_v
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                diff = volume[x, y, z] - pred
                
                freq[diff] = freq.get(diff, 0) + 1
                
    # Step 6: Build Huffman Table
    # Sort symbols by frequency descending
    sorted_symbols = sorted(freq.keys(), key=lambda s: freq[s], reverse=True)
    
    # Top L1 symbols get Huffman codes
    huffman_symbols = sorted_symbols[:L1]
    remaining_symbols = sorted_symbols[L1:]
    
    # Generate Huffman codes for top L1
    huffman_codes = generate_huffman_codes(huffman_symbols, [freq[s] for s in huffman_symbols])
    
    # Generate fixed-length codes for remaining
    # Number of remaining symbols
    num_remaining = len(remaining_symbols)
    if num_remaining > 0:
        fixed_len_bits = ceil(log2(num_remaining))
        fixed_codes = {}
        for i, sym in enumerate(remaining_symbols):
            fixed_codes[sym] = format(i, f'0{fixed_len_bits}b')
    else:
        fixed_codes = {}
        
    # Merge tables
    full_huffman_table = {}
    for sym in huffman_symbols:
        full_huffman_table[sym] = huffman_codes[sym]
    for sym in remaining_symbols:
        full_huffman_table[sym] = fixed_codes[sym]
        
    # Step 7: Encode
    bitstream = []
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                v1 = 0 if x == 0 else volume[x-1, y, z] - mean_v
                v2 = 0 if y == 0 else volume[x, y-1, z] - mean_v
                v3 = 0 if z == 0 else volume[x, y, z-1] - mean_v
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                diff = volume[x, y, z] - pred
                
                code = full_huffman_table[diff]
                bitstream.append(code)
                
    # Construct Header
    header = {
        'mean': mean_v,
        'coeffs': (a1, a2, a3),
        'huffman_table': full_huffman_table
    }
    
    return encode_header(header) + join_bits(bitstream)

def decompress_volume(compressed_data: bytes, X: int, Y: int, Z: int) -> Array3D:
    """
    Decompress a 3D volume.
    """
    header, bitstream = decode_header_and_bitstream(compressed_data)
    mean_v = header['mean']
    a1, a2, a3 = header['coeffs']
    huffman_table = header['huffman_table']
    
    # Inverse Huffman map for fast lookup
    inv_huffman = {code: sym for sym, code in huffman_table.items()}
    
    volume = zeros((X, Y, Z))
    bits = iter(bitstream)
    
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                # Read next Huffman code
                # Note: In practice, bitstream reading is more complex due to variable lengths
                # This is a simplified representation
                code = read_next_huffman_code(bits, inv_huffman)
                diff = inv_huffman[code]
                
                # Calculate predicted value using RECONSTRUCTED neighbors
                v1 = 0 if x == 0 else volume[x-1, y, z] - mean_v
                v2 = 0 if y == 0 else volume[x, y-1, z] - mean_v
                v3 = 0 if z == 0 else volume[x, y, z-1] - mean_v
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                volume[x, y, z] = pred + diff
                
    return volume
```

### Edge Cases and Pitfalls
-   **Causality**: The predictor must only use previously processed voxels ($x-1, y, z$), ($x, y-1, z$), and ($x, y, z-1$) so the decoder can generate identical predictions [S1, unofficial].
-   **Non-stationarity**: The optimal predictor assumes wide-sense stationarity. Real volume data is not stationary, making global statistics suboptimal. The algorithm does not handle this locally [S1, unofficial].
-   **Memory vs Speed**: The algorithm scans the volume 4 times. Difference values are not saved to prevent excessive memory costs, necessitating the fourth scan for encoding [S1, unofficial].
-   **Boundary Handling**: Neighbors at boundaries ($x=0, y=0, z=0$) are treated as 0 in the mean-subtracted space. This ensures the prediction error is orthogonal to the input variables [S1, unofficial].

## Operating characteristics
-   **Time Complexity**: The algorithm scans the volume four times. Two scans for statistics (mean and covariance), one for calculating differences (not stored), and one for encoding. The calculation of optimal predictor coefficients takes approximately 6% of the total compression time [S1, unofficial].
-   **Memory Complexity**: Low, as difference values are not stored in memory during the encoding pass [S1, unofficial].
-   **Performance**: Achieves approximately 50% lossless compression for volume data [S1, S2, unofficial]. On the `3dhead.vox` dataset (256x256x109, 13.6 Mb), it achieved 48.5% compression compared to 36.1% for gzip and 33.8% for zip on an HP 9000 Series 735 [S1, unofficial]. Compression time was 4.7 minutes, decompression 1.4 minutes [S1, unofficial].
-   **Entropy**: Voxel entropies for test datasets ranged from 3.28 bits/voxel (`sod.30.vox`) to 10.29 bits/voxel (`hipiph.vox`) [S1, unofficial].
-   **Strengths**: Removes spatial redundancy effectively, outperforming generic compressors that only remove statistical redundancy [S1, unofficial]. The optimal predictor automatically compensates for non-isotropic sampling [S1, unofficial].
-   **Limitations**: Assumes wide-sense stationarity, which may not hold for real data. The 6-neighborhood predictor may be less effective than 18- or 26-neighborhood predictors, though the latter were not implemented in the core algorithm [S1, unofficial].

## Background
-   **Origin**: Introduced by James Edwin Fowler and Roni Yagel in January 1995 at the Proceedings of the 1994 symposium on Volume visualization [S1, unofficial].
-   **History**: The algorithm was developed to address the high storage costs of volumetric data in biomedical and scientific applications where lossless compression is required. It was compared against generic algorithms (gzip, zip, compress, pack) and found to achieve greater compression by removing spatial redundancy [S1, unofficial].
-   **Usage**: Used for archiving CT-image volumes and other scientific volume data [S1, unofficial].
