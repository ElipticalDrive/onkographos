# Delta Encoding

Also called: DPCM, Differential pulse-code modulation, Heightfield Compression, Temporal prediction

## Overview
Delta encoding (also known as Differential Pulse-Code Modulation or DPCM) is a predictive compression method that exploits temporal or spatial coherence by storing the difference between a predicted value and the actual value [S1][S2, unofficial]. It solves the problem of high redundancy in time-varying or smoothly varying volume data by transforming the signal into residuals that are often zero or have a smaller dynamic range, making them highly compressible via entropy coding [S1]. Unlike sibling methods that may operate in the transform domain or use complex linear predictors, delta encoding typically relies on the simplest possible predictor (e.g., the previous time step or spatial neighbor), offering minimal computational overhead for decompression at the cost of random access limitations [S1].

## How it works
**Inputs and Outputs:**
- Input: A sequence of volume data frames (time-varying) or a spatially coherent volume (e.g., heightfield). Let $V_t$ be the volume at time step $t$.
- Output: A compressed stream of delta values (residuals) and, optionally, keyframe data for random access.

**Data Structures:**
- **Delta Brick:** A block of voxels where each voxel stores the difference $d_i = v_i - \hat{v}_i$.
- **Keyframe (Optional):** A full-resolution copy of the volume at specific time steps $t_k$ to allow random access.

**Steps:**
1. **Prediction:** For each voxel $v_i$ in the current frame $t$, predict its value $\hat{v}_i$.
   - For time-varying data: $\hat{v}_i = v_i^{(t-1)}$ (the value from the previous time step) [S1].
   - For spatial data (e.g., heightfields): $\hat{v}_i$ is often the minimum value in the local block or a spatial neighbor [S2, unofficial].
2. **Residual Calculation:** Compute the delta value $d_i$:
   $$ d_i = v_i - \hat{v}_i $$
   [S1][S2, unofficial]
3. **Encoding:** Encode the sequence of $d_i$ values.
   - If regions are unchanged, $d_i = 0$, creating uniform bricks suitable for variable-length coding (e.g., Huffman) [S1].
   - The distribution of $d_i$ is typically non-uniform and concentrated around zero, allowing efficient entropy coding [S1].
4. **Reconstruction:** To decompress, add the decoded residual to the predicted value:
   $$ v_i = \hat{v}_i + d_i $$
   [S1]
   - On the GPU, this is implemented by adding the delta value to the existing value in the volume buffer rather than overwriting it [S1].

**Parameters:**
- **Block Size:** For spatial applications, heightfields are partitioned into equal-sized blocks (e.g., $m \times n$) [S2, unofficial].
- **Keyframe Interval:** The frequency of storing absolute values to mitigate random access penalties [S1].

**Edge Cases and Pitfalls:**
- **Random Access Limitation:** Standard delta encoding requires reading all previous time steps to reconstruct a specific frame, as each frame depends on the prior one [S1]. This prevents jumping directly to a certain time step [S1].
- **Solution:** Save absolute values (keyframes) in addition to delta values and load them on demand [S1]. This increases storage requirements but enables random access [S1].
- **Precision:** Ensure that the residual values fit within the chosen bit-depth. If the prediction error exceeds the representable range, clipping or overflow may occur [G].

**Pseudocode:**

```python
def encode_delta_encoding(volume_current, volume_previous):
    """
    Encodes a volume frame using delta encoding relative to the previous frame.
    
    Args:
        volume_current: 3D array of voxel values at time t.
        volume_previous: 3D array of voxel values at time t-1.
        
    Returns:
        deltas: 3D array of delta values.
    """
    # Initialize deltas array with the same dimensions as volume_current
    deltas = empty_array_like(volume_current)
    
    # Iterate over all voxels
    for x in range(volume_current.shape[0]):
        for y in range(volume_current.shape[1]):
            for z in range(volume_current.shape[2]):
                # Prediction: assume value does not change from previous time step
                predicted_value = volume_previous[x, y, z]
                
                # Calculate residual
                actual_value = volume_current[x, y, z]
                delta = actual_value - predicted_value
                
                deltas[x, y, z] = delta
                
    return deltas

def decode_delta_encoding(deltas, volume_previous):
    """
    Decodes a volume frame from delta values and the previous frame.
    
    Args:
        deltas: 3D array of delta values.
        volume_previous: 3D array of voxel values at time t-1.
        
    Returns:
        volume_current: 3D array of reconstructed voxel values at time t.
    """
    # Initialize current volume array
    volume_current = empty_array_like(deltas)
    
    # Iterate over all voxels
    for x in range(deltas.shape[0]):
        for y in range(deltas.shape[1]):
            for z in range(deltas.shape[2]):
                # Reconstruct value
                predicted_value = volume_previous[x, y, z]
                delta = deltas[x, y, z]
                
                volume_current[x, y, z] = predicted_value + delta
                
    return volume_current
```

## Subtopics

### [Heightfield Compression with Block-Based Delta Encoding](1116-heightfield-compression-with-block-based-delta-encoding.md)
This method compresses heightfields by partitioning them into equal-sized blocks, where each block is encoded relative to its minimum height value using a reduced bit-depth for the differences. It solves the primary limitation of standard delta encoding—where accessing any single value requires decompressing the entire dataset—by enabling random access with only two reads: one for the block header and one for the block's data.

### [Differences-based Compression](5723-differences-based-compression.md)
Differences-based Compression is a value compression method that stores quantized differences relative to a block base value, expanding them to 16-bit integers during decompression to reconstruct final data. It distinguishes itself from sibling methods by utilizing pre-computed shift patterns to handle variable bit-depths efficiently during SIMD-based decompression, avoiding runtime bit-manipulation overhead.

## Operating characteristics
- **Time Complexity:** Encoding and decoding are $O(N)$, where $N$ is the number of voxels, as each voxel requires a single subtraction and addition operation [S1].
- **Memory Complexity:** Storage is $O(N)$ for the delta values. If keyframes are used, storage increases proportionally to the keyframe interval [S1].
- **Measured Performance:** Delta encoding provides good results for heightfields because height values usually vary progressively [S2, unofficial]. For time-varying data, it exploits temporal coherence, resulting in uniform bricks of zeros in unchanged regions, which compress efficiently [S1].
- **Strengths:** Simple implementation, low computational overhead for decompression (especially on GPU), effective for data with high temporal or spatial coherence [S1][S2, unofficial].
- **Limitations:** Prevents random access to specific time steps without keyframes, as all previous steps must be read [S1]. Decompressing the whole dataset is required for any data access in the basic form, limiting practical use in applications requiring efficient queries or traversals (e.g., realtime visualization) [S2, unofficial].
- **When to Use:** Ideal for time-varying volume data with high temporal coherence or spatially smooth data like heightfields, where sequential access is sufficient or keyframes are acceptable [S1][S2, unofficial].
- **When Not to Use:** When random access to arbitrary time steps or spatial locations is required without the overhead of keyframes or block-based partitioning [S1][S2, unofficial].

## Background
Delta encoding, also known as Differential Pulse-Code Modulation (DPCM), has been used in various forms for audio and video compression. In the context of volume rendering, it was applied to time-varying volume data to exploit temporal coherence [S1]. The method was highlighted in studies such as [AABY06, FBS07] for its ability to reduce storage requirements when changes between time steps are not random [S1]. It has also been suggested as a simple yet effective method for compressing heightfields in layered datasets like QuadStack [S2, unofficial].
