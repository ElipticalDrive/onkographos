# Delta Encoding

Also called: Heightfield Compression

## Overview
Delta encoding is a value compression technique that exploits the progressive variation of height values in volume data by storing differences between adjacent elements rather than absolute values [S1, unofficial]. It sets itself apart from sibling methods like Run-Length Encoding by focusing on local correlation rather than global repetition, though it lacks the random access capabilities of its child, Block-Based Delta Encoding, which partitions data to mitigate the latter's sequential access bottleneck [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of height values $H = [h_0, h_1, \dots, h_{N-1}]$ representing a heightfield or gstack interval.
*   **Output:** A compressed sequence of delta values $D = [d_0, d_1, \dots, d_{N-1}]$ and optionally a base value or header.

**Data Structures:**
The output is typically a flat array of integers. If bit-depth reduction is used (as in block variants), the deltas are packed into a reduced number of bits per element. For standard delta encoding, the layout is a contiguous stream of signed integers representing the difference between consecutive heights.

**Steps:**
1.  **Initialize:** Set the first delta value $d_0$ equal to the first height value $h_0$ (or store $h_0$ separately as a base, depending on implementation specifics; standard delta often stores $h_0$ directly).
2.  **Compute Differences:** For each subsequent index $i$ from $1$ to $N-1$:
    $$d_i = h_i - h_{i-1}$$
3.  **Store:** Write $d_0, d_1, \dots, d_{N-1}$ to the output buffer.

**Parameters:**
*   **Bit Depth:** The number of bits used to store each delta. Since deltas are often small, they can be stored in fewer bits than the original height values (e.g., 8-bit or 16-bit instead of 32-bit) [S1, unofficial]. Not given in the sources for the base method.

**Edge Cases and Pitfalls:**
*   **Random Access Limitation:** Decompressing any single value $h_i$ requires reading and summing all preceding deltas $d_0 \dots d_i$. This necessitates decompressing the whole dataset for any data access, limiting practical use in applications requiring efficient queries or traversals (e.g., real-time visualization) [S1, unofficial].
*   **Precision:** Accumulated errors can occur if floating-point deltas are summed, though integer heights are typical for heightfields.
*   **Boundary:** The first element $h_0$ must be preserved exactly, either as $d_0$ or in a header.

**Pseudocode:**
```python
def delta_encode(heights):
    """
    Compresses a sequence of height values using delta encoding.
    
    Args:
        heights: List of integers representing height values [h0, h1, ..., hN-1]
        
    Returns:
        List of integers representing delta values [d0, d1, ..., dN-1]
    """
    if not heights:
        return []
        
    deltas = [0] * len(heights)
    deltas[0] = heights[0]
    
    for i in range(1, len(heights)):
        deltas[i] = heights[i] - heights[i-1]
        
    return deltas

def delta_decode(deltas):
    """
    Decompresses a sequence of delta values back to height values.
    
    Args:
        deltas: List of integers representing delta values [d0, d1, ..., dN-1]
        
    Returns:
        List of integers representing height values [h0, h1, ..., hN-1]
    """
    if not deltas:
        return []
        
    heights = [0] * len(deltas)
    heights[0] = deltas[0]
    
    for i in range(1, len(deltas)):
        heights[i] = heights[i-1] + deltas[i]
        
    return heights
```

## Subtopics

### [Heightfield Compression with Block-Based Delta Encoding](1116-heightfield-compression-with-block-based-delta-encoding.md)
This method compresses heightfields by partitioning them into equal-sized blocks, where each block is encoded relative to its minimum height value using a reduced bit-depth for the differences. It solves the primary limitation of standard delta encoding—where accessing any single value requires decompressing the entire dataset—by enabling random access with only two disk reads: one for the block header and one for the block's data. Unlike its parent method, Delta Encoding, which decouples interval heights in gstacks but lacks efficient random access, this approach balances compression ratio and access time, making it suitable for applications requiring efficient queries or traversals, such as real-time visualization.

## Operating characteristics
*   **Time Complexity:** Encoding is $O(N)$ where $N$ is the number of elements. Decoding is $O(N)$ for full reconstruction, but $O(i)$ to access the $i$-th element, making random access inefficient [S1, unofficial].
*   **Memory Complexity:** $O(N)$ for the compressed deltas. Compression ratio depends on the distribution of deltas; if deltas are small, they can be stored in fewer bits, achieving significant compression [S1, unofficial].
*   **Strengths:** Simple to implement; effective when height values vary progressively (smooth surfaces) [S1, unofficial].
*   **Limitations:** Poor random access performance; requires sequential decompression for any query [S1, unofficial].
*   **When to use:** When data is accessed sequentially or stored in a way that allows full decompression (e.g., gstacks in offline processing) [S1, unofficial].
*   **When not to use:** When real-time visualization or efficient random access queries are required [S1, unofficial].

## Background
Delta encoding is suggested as a simple method providing good results because height values usually vary progressively [S1, unofficial]. It is used in the context of QuadStack, where attribute and heightfield representation are decoupled, allowing heightfields to be compressed by existing methods such as delta encoding [S1, unofficial]. The method is inspired by the work of Andujar [56] in the context of block-based variants [S1, unofficial].
