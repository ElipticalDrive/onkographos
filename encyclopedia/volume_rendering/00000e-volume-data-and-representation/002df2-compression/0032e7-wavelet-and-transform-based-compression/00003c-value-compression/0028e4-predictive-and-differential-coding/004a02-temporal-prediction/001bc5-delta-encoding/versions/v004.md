# Delta Encoding

Also called: Differential pulse-code modulation, Heightfield Compression, Temporal prediction

## Overview
Delta encoding (also known as Differential Pulse-Code Modulation or DPCM) is a predictive compression method that stores the difference between a current data value and a predicted value based on previously processed data [S1]. In volume rendering, it is primarily used to exploit temporal coherence in time-varying datasets or progressive variation in heightfields, converting raw values into residuals that often contain large uniform regions (e.g., zeros) suitable for subsequent entropy coding [S1]. It differs from transform-based methods by operating directly in the spatial or temporal domain without frequency decomposition, and from block-based variants by typically applying prediction across the entire dataset or sequence unless explicitly partitioned [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of values $V = \{v_1, v_2, \dots, v_N\}$ (e.g., voxel intensities over time or height values in a grid).
*   **Output:** A sequence of residuals (deltas) $E = \{e_1, e_2, \dots, e_N\}$, where $e_i = v_i - \hat{v}_i$.

**Data Structures:**
*   **History Buffer:** A storage structure maintaining the decoded values $v_{i-1}, v_{i-2}, \dots$ required for prediction. In streaming contexts, this is often a circular buffer or a simple pointer to the last decoded value [G].
*   **Residual Stream:** The output array of integers. If the original data uses $B$ bits, the residuals may use fewer bits if the dynamic range is reduced, or the same number of bits if the range is not reduced [S1].

**Prediction Model:**
The most common predictor for time-varying volume data assumes temporal coherence, predicting that the current voxel value equals the value at the previous time step [S1]:
$$ \hat{v}_t = v_{t-1} $$
For spatial heightfields, predictors may use neighboring spatial values, but the core principle remains the difference from a local reference [S2, unofficial].

**Algorithm Steps:**
1.  **Initialize:** Set the history buffer with the first value $v_0$ (or a zero prediction if no prior data exists) [G].
2.  **Iterate:** For each value $v_i$ in the input sequence:
    a.  **Predict:** Compute $\hat{v}_i$ using the predictor function on the history buffer.
    b.  **Encode:** Calculate the residual $e_i = v_i - \hat{v}_i$.
    c.  **Store:** Append $e_i$ to the output residual stream.
    d.  **Update History:** Append the original value $v_i$ to the history buffer (required for decoding the next step) [G].
3.  **Post-process:** The residual stream is typically passed to an entropy coder (e.g., Huffman or Arithmetic coding) or a block-based compressor. Uniform regions of zeros in the residuals are highly compressible [S1].

**Decoding:**
1.  **Initialize:** Set the history buffer with the first decoded value (recovered from the first residual and initial prediction) [G].
2.  **Iterate:** For each residual $e_i$ in the input stream:
    a.  **Predict:** Compute $\hat{v}_i$ using the same predictor function on the history buffer.
    b.  **Reconstruct:** Calculate $v_i = \hat{v}_i + e_i$.
    c.  **Store:** Append $v_i$ to the output value stream.
    d.  **Update History:** Append $v_i$ to the history buffer.

**Pseudocode:**
```python
def delta_encode(values):
    """
    Compresses a sequence using first-order temporal delta encoding.
    Args:
        values: List of numeric values (e.g., voxel intensities over time).
    Returns:
        List of residuals.
    """
    residuals = []
    # Initialize history with the first value to allow prediction for the second
    # Note: The first value itself must be stored or predicted from a known constant.
    # Here we assume the first residual is the value itself (prediction = 0) or
    # that the history is initialized with a known baseline.
    # Standard approach: Store v[0] explicitly or predict v[0]=0.
    
    if not values:
        return []

    # Initialize history with the first value
    history = [values[0]]
    
    # If the first value is not a residual of a previous state, 
    # we typically store it as-is or assume a zero prediction.
    # For simplicity in this generic implementation, we store the first value 
    # as the first residual (assuming prediction was 0) or handle it separately.
    # A more robust approach for streaming:
    # residuals.append(values[0]) # Store absolute first value
    
    # However, standard DPCM often predicts v[0] from a constant (e.g., 0).
    # Let's assume prediction for index 0 is 0.
    residuals.append(values[0] - 0)
    
    for i in range(1, len(values)):
        v_current = values[i]
        v_prev = history[-1]
        
        # Prediction: v_prev
        pred = v_prev
        
        # Calculate delta
        delta = v_current - pred
        
        residuals.append(delta)
        
        # Update history with the actual value (not the delta)
        history.append(v_current)
        
    return residuals

def delta_decode(residuals):
    """
    Decompresses a sequence using first-order temporal delta encoding.
    Args:
        residuals: List of numeric residuals.
    Returns:
        List of reconstructed values.
    """
    if not residuals:
        return []

    values = []
    history = []
    
    # Reconstruct first value (assuming prediction was 0)
    v_first = residuals[0] + 0
    values.append(v_first)
    history.append(v_first)
    
    for i in range(1, len(residuals)):
        e = residuals[i]
        v_prev = history[-1]
        
        # Prediction: v_prev
        pred = v_prev
        
        # Reconstruct value
        v_current = pred + e
        
        values.append(v_current)
        history.append(v_current)
        
    return values
```

**Parameters and Edge Cases:**
*   **Prediction Order:** First-order (using $v_{t-1}$) is standard. Higher-order predictors (using $v_{t-1}, v_{t-2}$) can improve compression for smooth data but increase complexity [G].
*   **Precision:** Residuals must be stored with sufficient bit-depth to avoid quantization error if lossless compression is required. If the original data is 16-bit, residuals may still require 16-bit storage if the dynamic range is not reduced [S1].
*   **Random Access Pitfall:** Delta encoding creates a dependency chain. To access value $v_t$, all previous values $v_0 \dots v_{t-1}$ must be decoded. This prevents efficient random access to specific time steps [S1].
*   **Mitigation:** To enable random access, absolute values can be stored at regular intervals (keyframes) alongside the deltas. This increases storage but allows jumping to keyframes [S1].

## Subtopics

### [Heightfield Compression with Block-Based Delta Encoding](1116-heightfield-compression-with-block-based-delta-encoding.md)
This method compresses heightfields by partitioning them into equal-sized blocks, where each block is encoded relative to its minimum height value using a reduced bit-depth for the differences. It solves the primary limitation of standard delta encoding—where accessing any single value requires decompressing the entire dataset—by enabling random access with only two reads: one for the block header and one for the block's data.

### [Differences-based Compression](5723-differences-based-compression.md)
Differences-based Compression is a value compression method that stores quantized differences relative to a block base value, expanding them to 16-bit integers during decompression to reconstruct final data. It distinguishes itself from sibling methods by utilizing pre-computed shift patterns to handle variable bit-depths efficiently during SIMD-based decompression, avoiding runtime bit-manipulation overhead.

## Operating characteristics
*   **Time Complexity:** Encoding and decoding are $O(N)$, where $N$ is the number of voxels/values. The operations are simple subtractions and additions, making them extremely fast and suitable for GPU implementation [S1].
*   **Memory Complexity:** $O(N)$ for storing the residuals. The history buffer requires $O(1)$ memory if only the last value is needed for first-order prediction [G].
*   **Compression Ratio:** Depends heavily on the data's coherence. For time-varying volumes with high temporal coherence, residuals are often zero or small, leading to high compression ratios after entropy coding [S1]. For random data, compression may be worse than raw storage due to overhead.
*   **Strengths:** Simple implementation, low computational overhead, effective for temporal coherence, GPU-friendly [S1].
*   **Limitations:** No random access without keyframes, sensitive to prediction errors (error propagation is limited to the next step in first-order, but decoding errors can persist if the history is corrupted) [G].
*   **When to Use:** Time-varying volume data with high temporal coherence, heightfields with progressive variation.
*   **When Not to Use:** Data with random noise, scenarios requiring efficient random access to arbitrary time steps without keyframes.

## Background
Delta encoding, or DPCM, is a classic technique in signal processing and data compression. In the context of volume rendering, it was adapted to exploit temporal coherence in time-varying datasets [S1]. The method was highlighted in works such as [AABY06] and [FBS07] for compressing time-varying volume data, where it serves as a preprocessing step before entropy coding [S1]. It is also used in heightfield compression for layered datasets like gstacks, where height values vary progressively [S2, unofficial].
