# Delta Encoding
Also called: Differential pulse-code modulation, Heightfield Compression, Temporal prediction

## Overview
Delta encoding is a predictive compression technique that exploits temporal or spatial coherence by storing the difference (residual) between a predicted voxel value and its actual value, rather than the absolute value [S1]. It sets itself apart from sibling methods like [Residual Updates in Transform Domain](5256-residual-updates-in-transform-domain.md) by operating directly in the spatial/time domain without prior transform steps, making it particularly effective for data with high temporal stability or smooth spatial gradients [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of volume data frames (time-varying) or a spatial heightfield. Let $V_t(x,y,z)$ be the value at position $(x,y,z)$ in time step $t$.
*   **Output:** A stream of delta values (residuals) $D_t(x,y,z)$, which are subsequently entropy-coded.

**Data Structures:**
*   **Delta Buffer:** An array of integers with the same dimensions as the input volume. The bit-depth of this buffer is determined by the maximum expected difference between consecutive frames or the local height variation.
*   **Base Value (Optional):** For block-based variants, a minimum value per block is stored to allow reduced bit-depth encoding of residuals [S1].

**Steps:**
1.  **Prediction:** For each voxel, predict the current value $V_{pred}$ based on the previous time step's value.
    $$ V_{pred}(x,y,z) = V_{t-1}(x,y,z) $$
    [S1]
2.  **Residual Calculation:** Compute the difference between the actual value and the prediction.
    $$ D_t(x,y,z) = V_t(x,y,z) - V_{pred}(x,y,z) $$
    [S1]
    In lossless contexts, this difference is exact. If the data does not change between time steps, $D_t(x,y,z) = 0$ [S1].
3.  **Storage/Encoding:** Store or entropy-code the delta values $D_t$. Because unchanged regions produce zeros and small changes produce small integers, the distribution is non-uniform and concentrated near zero, allowing efficient compression via variable-length coding (e.g., Huffman or Arithmetic coding) [S1].
4.  **Decompression (GPU/CPU):** To reconstruct the volume, add the decoded delta value to the previously reconstructed value.
    $$ V_{reconstructed}(x,y,z) = V_{prev\_reconstructed}(x,y,z) + D_{decoded}(x,y,z) $$
    [S1]
    On the GPU, this is implemented as a kernel that adds the calculated delta value to the existing value in the volume texture instead of overwriting it [S1].

**Parameters:**
*   **Bit-depth:** Not fixed; depends on the dynamic range of changes. If the difference between max and min values in a brick is less than $2^n$ with $n < 16$, the brick size can be reduced by storing the minimum as a base and encoding residuals with $n$ bits [S1].

**Edge Cases and Pitfalls:**
*   **Random Access:** Standard delta encoding prevents jumping directly to a specific time step because all previous time steps must be read to reconstruct the current state [S1]. This can be mitigated by storing absolute values (keyframes) in addition to delta values, loading them on demand at the cost of increased storage [S1].
*   **Error Accumulation:** In closed-loop decoding, using the reconstructed value for prediction prevents error accumulation from quantization or transmission errors [S1].

## Subtopics

### [Heightfield Compression with Block-Based Delta Encoding](1116-heightfield-compression-with-block-based-delta-encoding.md)
This method partitions a heightfield into equal-sized blocks, encoding each block relative to its minimum height value using a reduced bit-depth for the differences. It solves the primary limitation of standard delta encoding—where accessing any single value requires decompressing the entire dataset—by enabling random access with only two reads: one for the block header and one for the block's data.

### [Differences-based Compression](5723-differences-based-compression.md)
Differences-based Compression stores quantized differences relative to a block base value, expanding them to 16-bit integers during decompression to reconstruct final data. It distinguishes itself from sibling methods by utilizing pre-computed shift patterns to handle variable bit-depths efficiently during SIMD-based decompression, avoiding runtime bit-manipulation overhead.

### Parallelogram Prediction with Diamond Residuals
A lossless compression method for height fields using linear prediction where height values are uniformly quantized to 16 bits [S3]. It uses parallelogram prediction for the z-component (height) while vertices are traversed in diagonal rows [S3]. The first three vertices of the first triangle are stored uncompressed [S3]. Subsequent vertices are predicted using a diamond configuration to maximize square diamond configurations, ensuring predictor vertices are as close as possible in the domain [S3].

## Operating characteristics
*   **Time Complexity:** Encoding and decoding are linear with respect to the number of voxels $N$, $O(N)$, as each voxel requires one subtraction and one addition [S1].
*   **Memory Complexity:** Requires storage for the delta buffer, which is typically smaller than the original data if the residuals are small and entropy-coded [S1].
*   **Performance:** Highly effective for time-varying data with high temporal coherence (e.g., fluid simulations with slow changes) [S1]. On GPUs, it achieves full memory coalescing if threads are organized to process adjacent memory cells [S1].
*   **Strengths:** Simple implementation; excellent compression ratios for smooth or slowly changing data; low computational overhead [S1].
*   **Limitations:** Poor compression for random or rapidly changing data; lack of random access in pure delta streams [S1].

## Background
Delta encoding, also known as Differential Pulse-Code Modulation (DPCM), was introduced for time-varying volume data to exploit temporal coherence [S1]. It was notably applied in GPU-supported lossless compression schemes for rendering time-varying volume data, where it was shown to create uniform bricks of zero deltas in unchanged regions, facilitating efficient variable-length coding [S1]. The method has also been adapted for heightfield compression in layered datasets like QuadStack, where it serves as a simple yet effective baseline due to the progressive variation of height values [S2, unofficial].
