# Differences-based Compression
Also called: Smelyanskiy, Smelyanskiy differences scheme
## Overview
Differences-based Compression is a value compression method that stores quantized differences relative to a block base value, expanding them to 16-bit integers during decompression to reconstruct final data [S1][S2]. It distinguishes itself from sibling methods by utilizing pre-computed shift patterns to handle variable bit-depths efficiently during SIMD-based decompression, avoiding runtime bit-manipulation overhead [S1][S2].
## How it works
**Inputs:** A block of volume data with a known bit-depth per element ($i_{bits}$), a minimum value ($min$), and a maximum value ($max$) for the block.
**Outputs:** A block of 16-bit integer values representing the final volume data.

**Data Structures:**
1.  **Block Header:** Contains $min$, $max$, and $i_{bits}$ (the number of bits used to represent the index/difference values).
2.  **Compressed Data:** A bit-stream where each element is stored using $i_{bits}$ bits.
3.  **Shift Pattern Table:** A pre-computed lookup table mapping $i_{bits}$ to specific SIMD shuffle/mask instructions required to extract and align the variable-length fields into 16-bit registers.

**Steps:**
1.  **Pre-computation (Offline):** For each supported bit-depth $i_{bits}$, compute the SIMD shuffle patterns (masks and indices) required to extract $i_{bits}$-bit chunks from the compressed bit-stream and align them into 16-bit slots. Store these patterns in the Shift Pattern Table [S1][S2].
2.  **Decompression Load:** Load the compressed data for a block. For SIMD efficiency, load data for multiple elements (e.g., eight elements for 128-bit SSE) into a register [S1][S2].
3.  **Pattern Lookup:** Retrieve the appropriate shuffle pattern from the Shift Pattern Table based on the block's $i_{bits}$ [S1][S2].
4.  **Expansion:** Apply the shuffle pattern to expand the stored $i_{bits}$-bit differences into 16-bit integer values. This effectively unpacks the variable-length data into fixed-width 16-bit slots [S1][S2].
5.  **Reconstruction:** Add the expanded 16-bit difference values to the block's base value ($min$) to obtain the final volume data values [S1][S2].

**Formula:**
The decompressed value $v_{ijk}$ is computed as:
$$ v_{ijk} = min + (max - min) \times \frac{index}{2^{i_{bits}} - 1} $$
Where:
*   $min$ is the minimum value in the block.
*   $max$ is the maximum value in the block.
*   $index$ is the integer value represented by the $i_{bits}$ bits stored for the element.
*   $i_{bits}$ is the number of bits used to represent the index values [S1][S2].

**Parameters:**
*   $i_{bits}$: Variable, determined per block. Common values depend on the compression ratio target.
*   SIMD Width: 128-bit SSE is cited as a typical implementation target, processing eight 16-bit elements per instruction [S1][S2].

**Edge Cases and Pitfalls:**
*   **Variable Bit-Depth:** The method must handle blocks with different $i_{bits}$ values. The pre-computed table ensures that the correct expansion logic is applied without runtime branching for bit manipulation [S1][S2].
*   **Precision:** The expansion to 16-bit integers preserves the quantization error introduced by the $i_{bits}$-bit storage. The final addition of $min$ is exact if $min$ fits in the 16-bit range or if appropriate scaling is used [S1][S2].
*   **Lookup Overhead:** The overhead of looking up shuffle patterns is negligible in practice [S1][S2].

**Pseudocode:**
```python
# Pre-computed shift patterns for supported bit depths
# shift_patterns[i_bits] = (mask, shuffle_indices)
shift_patterns = {
    4: (0xF, [0, 1, 2, 3, 4, 5, 6, 7]), # Example for 4-bit
    8: (0xFF, [0, 1, 2, 3, 4, 5, 6, 7]), # Example for 8-bit
    12: (0xFFF, [0, 1, 2, 3, 4, 5, 6, 7]) # Example for 12-bit
}

def decompress_block(compressed_data, min_val, max_val, i_bits):
    """
    Decompress a block of volume data using differences-based compression.
    
    Args:
        compressed_data: Bit-stream of compressed values.
        min_val: Minimum value of the block.
        max_val: Maximum value of the block.
        i_bits: Number of bits per element in the compressed data.
        
    Returns:
        List of 16-bit integer values.
    """
    # Step 1: Load multiple elements (e.g., 8 for 128-bit SSE)
    # In a real SIMD implementation, this would be a vector load.
    # Here, we simulate loading 8 elements.
    num_elements = 8
    loaded_values = compressed_data[0:num_elements]
    
    # Step 2: Lookup shift pattern
    pattern = shift_patterns[i_bits]
    mask, shuffle_indices = pattern
    
    # Step 3: Expand to 16-bit values using shuffle/mask
    # This step extracts i_bits from each element and places them into 16-bit slots.
    expanded_values = []
    for i in range(num_elements):
        # Extract i_bits from the loaded value
        # Note: In SIMD, this is done via the shuffle pattern.
        # Here, we simulate the extraction.
        val = (loaded_values[i] >> (i_bits * (i % (16 // i_bits)))) & mask
        expanded_values.append(val)
        
    # Step 4: Add base value to obtain final values
    final_values = []
    for val in expanded_values:
        # Reconstruct using the formula
        # v_ijk = min + (max - min) * index / (2^i_bits - 1)
        # Note: The source describes adding the expanded difference to the base value.
        # The formula provided in the source is for quantization.
        # The "difference" expansion likely yields the quantized index directly.
        # We assume the expanded value is the quantized index.
        index = val
        reconstructed = min_val + (max_val - min_val) * index / (2**i_bits - 1)
        final_values.append(reconstructed)
        
    return final_values
```
[G] The pseudocode assumes the compressed data is already aligned to element boundaries for the sake of simulation. In practice, the SIMD shuffle handles bit-level extraction from a packed bit-stream. The formula uses integer division or floating-point multiplication depending on the implementation; the source implies a linear interpolation based on the index.

## Subtopics

### [Differences-based Compression (Mensmann)](5733-differences-based-compression-mensmann.md)
Differences-based Compression (Mensmann) is a hybrid compression scheme that resolves variable-length coding, delta encoding, and brick assembly during decompression. It sets itself apart from its siblings by implementing individual kernels for each supported bit length to handle the variable-length coding addressing modes, while performing delta encoding by adding calculated values to existing volume data rather than overwriting it.

## Operating characteristics
**Time Complexity:** Decompression is efficient due to SIMD parallelism. The overhead of lookup tables is negligible [S1][S2].
**Memory Complexity:** Requires storage for the shift pattern table, which is small and constant size relative to the number of supported bit depths [S1][S2].
**Performance:** Optimized for 128-bit SSE, processing eight elements per instruction [S1][S2].
**Strengths:** Efficient handling of variable bit-depths via pre-computed patterns; low overhead [S1][S2].
**Limitations:** Requires pre-computation of shift patterns; specific to SIMD architectures [S1][S2].
**When to use:** When decompression speed is critical and the hardware supports SIMD operations with variable bit-width extraction [S1][S2].
**When not to use:** On hardware without SIMD support or where pre-computation is not feasible [S1][S2].
## Background
Differences-based Compression was employed by Smelyanskiy et al. [SHC* 09] in the context of compressed GPU-based direct volume rendering [S1][S2]. It is part of the broader family of predictive and differential coding methods for volume data [S1][S2].
