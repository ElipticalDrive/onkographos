# Delta Encoding

Also called: Differential pulse-code modulation, Heightfield Compression, Temporal prediction

## Overview
Delta encoding is a predictive compression method that exploits coherence in data by storing the difference (residual) between a current sample and a predicted value derived from previously encoded neighbors, rather than the absolute value [S1]. In volume rendering, it is primarily used to compress time-varying data by assuming temporal coherence (that voxel values do not change between time steps) or spatially coherent heightfields [S1][S2, unofficial]. It sets itself apart from sibling methods like [Optimal Linear Volumetric Predictor](7759-optimal-linear-volumetric-predictor-with-truncated-huffman-c.md) by using a simple identity or nearest-neighbor prediction model, which minimizes computational overhead during encoding/decoding but requires sequential access for reconstruction [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of data samples $v_t$ (e.g., voxel values at time $t$ or height values in a grid).
*   **Output:** A sequence of residuals (deltas) $d_t$, which are subsequently entropy-coded.

**Data Structures:**
The method does not define a unique complex data structure but relies on the input data layout. For time-varying data, the input is a sequence of volumes $V_0, V_1, \dots$. For spatial data, it is a grid or mesh. The residuals $d_t$ are typically stored in a linear array or brick structure compatible with the entropy coder [S1].

**Prediction Model:**
The predictor $\hat{v}$ depends on the data type:
1.  **Temporal (Time-Varying):** The current value is predicted to be identical to the value at the previous time step [S1].
    $$ \hat{v}_t = v_{t-1} $$
2.  **Spatial (Heightfields):** The current value is predicted from spatially adjacent neighbors. Common models include linear combinations of neighbors or specific geometric predictors like parallelogram prediction for terrain meshes [S3].

**Residual Calculation:**
The residual $d_t$ is calculated as the difference between the actual value $v_t$ and the prediction $\hat{v}_t$ [S1, S3]:
$$ d_t = v_t - \hat{v}_t $$
If the prediction is accurate, $d_t$ will be small, often zero for unchanged regions [S1].

**Entropy Coding:**
The residuals $d_t$ are encoded using entropy coding (e.g., Huffman, Arithmetic, or Variable-Length Coding) [S1]. Because the distribution of $d_t$ is often non-uniform and concentrated around zero, this step achieves significant compression [S1].

**Decompression:**
To reconstruct the original value, the decoder adds the decoded residual to the previously reconstructed value (for temporal) or the predicted spatial neighbor [S1].
$$ v_t = \hat{v}_t + d_t $$
For GPU decompression, this is implemented by adding the delta value to the existing value in the volume buffer rather than overwriting it [S1].

**Pseudocode (Temporal Delta Encoding):**

```python
def encode_temporal_delta(volumes):
    """
    Encodes a sequence of volumes using temporal delta encoding.
    volumes: List of 3D arrays (volumes), where volumes[0] is the first time step.
    Returns: List of 3D arrays of residuals.
    """
    residuals = []
    prev_volume = None
    
    for t, current_volume in enumerate(volumes):
        if t == 0:
            # First time step: store absolute values (no previous reference)
            # In practice, these might be entropy-coded differently or stored as base
            residuals.append(current_volume)
            prev_volume = current_volume
        else:
            # Calculate delta: current - previous
            # Assuming same dimensions and alignment
            delta = current_volume - prev_volume
            residuals.append(delta)
            prev_volume = current_volume
    return residuals

def decode_temporal_delta(residuals):
    """
    Decodes a sequence of volumes from temporal delta residuals.
    residuals: List of 3D arrays of residuals.
    Returns: List of 3D arrays (reconstructed volumes).
    """
    volumes = []
    prev_volume = None
    
    for t, delta in enumerate(residuals):
        if t == 0:
            # First volume is stored as absolute values (or base)
            current_volume = delta
        else:
            # Reconstruct by adding delta to previous reconstructed volume
            current_volume = prev_volume + delta
        
        volumes.append(current_volume)
        prev_volume = current_volume
    return volumes
```

**Parameters:**
*   **Bit Depth:** The bit depth of the residuals should match the expected range of differences. If the difference between max and min values in a brick is less than $2^n$, the brick size can be reduced [S1].
*   **Base Value Storage:** To enable random access, absolute values for specific time steps (keyframes) may be stored alongside deltas, increasing storage cost [S1].

**Edge Cases and Pitfalls:**
*   **Sequential Access Dependency:** Delta encoding prevents jumping directly to a specific time step because all previous time steps must be read to reconstruct the data [S1]. This limits practical use in applications requiring efficient queries or traversals, such as real-time visualization [S2, unofficial].
*   **Drift:** In floating-point data, small errors in prediction or rounding during entropy coding can accumulate if not handled carefully, though lossless coding avoids this.
*   **Unchanged Regions:** Regions with no change produce zero deltas, which are highly compressible [S1].

## Subtopics

### [Heightfield Compression with Block-Based Delta Encoding](1116-heightfield-compression-with-block-based-delta-encoding.md)
This method compresses heightfields by partitioning them into equal-sized blocks, where each block is encoded relative to its minimum height value using a reduced bit-depth for the differences. It solves the primary limitation of standard delta encoding—where accessing any single value requires decompressing the entire dataset—by enabling random access with only two reads: one for the block header and one for the block's data.

### [Differences-based Compression](5723-differences-based-compression.md)
Differences-based Compression is a value compression method that stores quantized differences relative to a block base value, expanding them to 16-bit integers during decompression to reconstruct final data. It distinguishes itself from sibling methods by utilizing pre-computed shift patterns to handle variable bit-depths efficiently during SIMD-based decompression, avoiding runtime bit-manipulation overhead.

### Parallelogram Prediction with Diamond Residuals
This variant uses linear prediction for lossless compression of height fields, specifically for the z-component (height) of terrain meshes [S3]. Height values are uniformly quantized to 16 bits. Vertices are traversed in diagonal rows, and the first three vertices of the first triangle are stored uncompressed [S3]. Subsequent vertices are predicted using a diamond configuration (parallelogram prediction) to maximize square diamond configurations, ensuring predictor vertices are as close as possible in the domain [S3].

## Operating characteristics
*   **Time Complexity:** Encoding and decoding are $O(N)$ where $N$ is the number of samples, as each sample requires one subtraction and one addition. This is computationally cheaper than linear predictors that require multiple multiplications [S1].
*   **Memory Complexity:** $O(N)$ for storing the residuals. If keyframes are stored for random access, memory usage increases proportionally to the frequency of keyframes [S1].
*   **Compression Ratio:** High for data with strong coherence (e.g., smooth temporal changes or gradual height variations) [S1][S2, unofficial]. Low for random or noisy data where residuals are large and uniformly distributed [S1].
*   **Strengths:** Simple implementation, low computational overhead, effective for time-varying data with high temporal coherence [S1].
*   **Limitations:** Requires sequential access for full reconstruction, making it unsuitable for random-access-heavy applications without additional structures (like keyframes) [S1][S2, unofficial].

## Background
Delta encoding, also known as Differential Pulse-Code Modulation (DPCM), is a classic technique in signal processing and data compression [S1]. In the context of volume rendering, it was adapted to exploit temporal coherence in time-varying volume data, where voxel values often remain stable between time steps [S1]. It has also been applied to heightfield compression for terrain rendering, leveraging the progressive variation of height values [S2, unofficial]. The method is often combined with entropy coding to achieve lossless compression [S1].
