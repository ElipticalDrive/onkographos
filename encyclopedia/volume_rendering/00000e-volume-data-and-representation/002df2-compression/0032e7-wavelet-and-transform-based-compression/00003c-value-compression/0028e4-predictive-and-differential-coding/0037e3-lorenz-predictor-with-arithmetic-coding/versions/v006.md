# Lorenz Predictor with Arithmetic Coding

Also called: Lorenzo, Lorenz预测与算术编码, n-dimensional Lorenzo predictor, n-dimensional parallelogram predictor

## Overview
The Lorenz Predictor with Arithmetic Coding is a lossless compression method for $n$-dimensional scalar fields that estimates each sample value from its $2^n - 1$ previously visited neighbors in a regular grid to generate residuals, which are then encoded using arithmetic coding [S1, unofficial]. It is distinguished from anisotropic scanline predictors (like simple delta encoding) by being isotropic, exploiting data coherence in all dimensions, and is the simplest isotropic predictor capable of exactly reconstructing all polynomials of degree less than $n$ [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An $n$-dimensional scalar field $F$ with dimensions $D_1 \times D_2 \times \dots \times D_n$.
*   **Output:** A compressed bitstream representing the residuals.

**Data Structures:**
*   **Footprint Buffer:** A circular FIFO buffer storing the values of the "footprint" (the immediate neighbors required for prediction). For an $n$-dimensional dataset with ranges $X_1, \dots, X_n$, the buffer size is sufficient to hold one slice of the data plus the footprint for a dataset of dimension $n-1$ [S1, unofficial]. Specifically, for $R^4$, the size is $X_M Y_M Z_M + X_M Y_M + X_M + 1$ [S1, unofficial].
*   **Arithmetic Encoder:** A context arithmetic encoder is used for residuals, using the predicted value as context [S1, unofficial].

**Prediction Model:**
The predictor estimates the value $F(v)$ at a sample point $v$ using the values at the $2^n - 1$ previously visited neighbors $u$ that form the other vertices of the $n$-dimensional unit hypercube $\{0,1\}^n$ of which $v$ is the vertex $(1, \dots, 1)$ [S1, unofficial].

Let the local coordinate system be defined such that $v$ has coordinates $(1, \dots, 1)$ and the previously visited neighbors $u$ have coordinates in $\{0,1\}^n \setminus \{(1, \dots, 1)\}$ [S1, unofficial]. The predicted value $P(v)$ is calculated as:

$$ P(v) = \sum_{u \in \{0,1\}^n \setminus \{(1,\dots,1)\}} (-1)^{g(u)} F(u) $$

where $g(u)$ is the number of coordinates of $u$ that equal 0 [S1, unofficial]. Equivalently, $g(u) = n - (u \cdot v)$, where $u \cdot v$ is the dot product of $u$ and $v$ [S1, unofficial]. Note that immediate neighbors (Hamming distance 1 from $v$) have weight $+1$ [S1, unofficial].

**Residual Calculation:**
The residual $d$ is computed as:
$$ d = F(v) - P(v) $$

**Encoding:**
The residual $d$ is encoded using a context arithmetic encoder, where the context is the predicted value $P(v)$ [S1, unofficial].

**Algorithm Steps (Scanline Order):**
The data is visited in a specific recursive scanline order defined by the function `Lorenzo(d, x_1, \dots, x_n)`, where $d$ is the current dimension being processed, $x_i$ are the coordinates, and $d_{max}$ is the size of the $d$-th dimension [S1, unofficial].

1.  **Initialization:** Start with `Lorenzo(n, -1, \dots, -1)` [S1, unofficial].
2.  **Recursive Visit:**
    *   If all coordinates $x_1, \dots, x_n$ are not $-1$ (i.e., a valid sample point is reached):
        1.  Compute prediction $p = \text{LorenzoPredictor}(d, x_1, \dots, x_n)$ using the formula above.
        2.  Encode the residual $F[x_1, \dots, x_n] - p$ using the arithmetic encoder [S1, unofficial].
    *   If any coordinate is $-1$ (indicating a boundary or dimension switch):
        1.  Find the first index $k$ such that $x_k = -1$.
        2.  Recursively call `Lorenzo(k-1, x_1, \dots, x_{k-1}, 0, x_{k+1}, \dots, x_n)` to initialize the lower dimensions [S1, unofficial].
        3.  Loop $i$ from 1 to $d_{max}$:
            *   Call `Lorenzo(k, x_1, \dots, x_{k-1}, i, x_{k+1}, \dots, x_n)` [S1, unofficial].

**Pseudocode:**

```python
def lorenzo_predictor(coords, field_buffer):
    """
    Computes the Lorenzo prediction for a point given its local coordinates
    and the values of its neighbors stored in the field_buffer.
    coords: tuple of length n, values in {0, 1}
    field_buffer: dictionary or array mapping neighbor coordinates to F(u)
    """
    n = len(coords)
    prediction = 0
    # Iterate over all 2^n corners of the hypercube
    for i in range(1 << n):
        # Convert integer i to binary tuple representing u
        u = tuple((i >> j) & 1 for j in range(n))
        
        # Skip the current point v itself (1, 1, ..., 1)
        if all(c == 1 for c in u):
            continue
            
        # Calculate g(u): number of coordinates equal to 0
        g_u = sum(1 for c in u if c == 0)
        
        # Weight is (-1)^g(u)
        weight = 1 if g_u % 2 == 0 else -1
        
        # Retrieve F(u) from the buffer
        # Note: In implementation, u must be mapped to global indices
        # to retrieve the value from the footprint buffer.
        f_u = field_buffer.get(u)
        if f_u is None:
            raise ValueError(f"Neighbor {u} not found in buffer")
            
        prediction += weight * f_u
        
    return prediction

def encode_residual(residual, arithmetic_encoder, context):
    """
    Encodes the residual using context arithmetic coding.
    """
    arithmetic_encoder.encode(residual, context=context)

def lorenzo_compress(field, dimensions):
    """
    Compresses an n-dimensional field using the Lorenzo predictor.
    field: n-dimensional array or callable F(x1, ..., xn)
    dimensions: tuple (D1, D2, ..., Dn)
    """
    n = len(dimensions)
    d_max = dimensions
    arithmetic_encoder = ContextArithmeticEncoder()
    
    # Buffer to store footprint values
    # Implementation detail: This must be a circular FIFO buffer
    # sized appropriately for the n-dimensional footprint.
    footprint_buffer = FootprintBuffer(dimensions)
    
    def visit(d, coords):
        """
        Recursive function to traverse the data in scanline order.
        d: current dimension index (1-based)
        coords: current coordinates for dimensions 1 to d-1
        """
        if d == 0:
            # Base case: all dimensions visited, process the point
            # coords is now a full tuple (x1, ..., xn)
            # Map local coords (0/1) to global indices to fetch from buffer
            # and compute prediction
            pred = lorenzo_predictor(coords, footprint_buffer)
            actual = field[coords] # Access field at global coords
            residual = actual - pred
            encode_residual(residual, arithmetic_encoder, pred)
            # Update footprint buffer with actual value at coords
            footprint_buffer.update(coords, actual)
            return

        # Recursive step
        if coords[d-1] == -1:
            # Initialize this dimension to 0
            # Call for dimension d-1 with 0 at position d-1
            new_coords = list(coords)
            new_coords[d-1] = 0
            visit(d-1, tuple(new_coords))
            
            # Loop through the rest of the dimension
            for i in range(1, d_max[d-1] + 1):
                new_coords = list(coords)
                new_coords[d-1] = i
                visit(d, tuple(new_coords))
        else:
            # Dimension already initialized, recurse to next dimension
            visit(d-1, coords)

    # Initial call with -1 for all dimensions
    initial_coords = tuple([-1] * n)
    visit(n, initial_coords)
    
    return arithmetic_encoder.get_bitstream()
```

**Parameters:**
*   $n$: The dimension of the data (e.g., 3 for volumetric, 4 for spatiotemporal) [S1, unofficial].
*   Arithmetic Encoder: Context-based arithmetic encoder is recommended over adaptive arithmetic encoder for a 25% gain [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The predictor is exact for polynomials of degree $< n$. For a 3D predictor applied to a cubic function, the error is between 3% and 8% (L-infinity sense) [S1, unofficial]. For a 4D predictor applied to a quartic function, the error is less than 1% [S1, unofficial].
*   **Boundaries:** The algorithm handles boundaries by initializing dimensions recursively. The footprint buffer must correctly manage the circular nature and size to avoid memory overflow for large datasets [S1, unofficial].
*   **Causality:** The predictor only uses previously visited neighbors, ensuring causality [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** The memory footprint is small, proportional to one slice of the data plus the footprint of the lower-dimensional data. For $R^4$, the buffer size is $X_M Y_M Z_M + X_M Y_M + X_M + 1$ [S1, unofficial]. This makes it suitable for out-of-core implementations [S1, unofficial].
*   **Time:** The prediction involves $2^n - 1$ lookups and additions per sample. The arithmetic encoding is linear in the number of samples.

**Measured Performance:**
*   On a 4D dataset of a house on fire (43,202,395 bytes uncompressed), 4D Lorenzo compression reduced the size to 524,768 bytes (1.21% of total), outperforming 3D slice compression (1,076,587 bytes, 2.49%) by 50% [S1, unofficial].
*   On a fluid mixing simulation dataset, 3D time slice predictor produced 304,937,058 bytes (1.77 bits/symbol) and 4D Lorenzo produced 318,871,620 bytes (1.85 bits/symbol) [S1, unofficial].
*   Context arithmetic encoder gives a 25% gain over adaptive arithmetic encoder [S1, unofficial].
*   In lossless compression, cubic wavelets are slightly better than the Lorenzo predictor in terms of residual entropy for 4D datasets (e.g., 0.16 vs 0.20 bits/symbol for smooth data, 3.28 vs 3.73 bits/symbol for harsh data) [S1, unofficial].
*   In lossy L-infinity compression, the Lorenzo predictor performs better than SPIHT (a wavelet implementation using S+P transform) on tested 2D datasets [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Isotropic, exploits coherence in all dimensions, exact for polynomials of degree $< n$, small memory footprint suitable for out-of-core processing [S1, unofficial].
*   **Limitations:** For data with high-frequency components or non-polynomial behavior, the residuals may be larger than those from wavelet transforms. The recursive scanline order may not be cache-optimal for all hardware architectures compared to block-based methods [S1, unofficial].

## Background
The Lorenz Predictor was introduced by S. Mennon and M. Rizk in the paper "Out-of-Core Compression and Decompression of Large n-Dimensional Scalar Fields" [S1, unofficial]. It extends the simple two-dimensional parallelogram predictor to higher dimensions. The method is particularly noted for its application in large-scale scientific simulations, such as fluid dynamics and combustion, where data coherence exists in multiple dimensions [S1, unofficial]. The name "Lorenz" is used in the source, though it is commonly referred to as "Lorenzo" in the literature [S1, unofficial].
