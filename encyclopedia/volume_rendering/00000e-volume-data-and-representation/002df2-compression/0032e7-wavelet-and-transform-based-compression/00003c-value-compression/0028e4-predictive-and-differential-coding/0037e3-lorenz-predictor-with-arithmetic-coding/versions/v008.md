# Lorenz Predictor with Arithmetic Coding

Also called: Lorenzo, Lorenz预测与算术编码, n-dimensional Lorenzo predictor, n-dimensional parallelogram predictor

## Overview
The Lorenz Predictor with Arithmetic Coding is a lossless compression method for $n$-dimensional scalar fields that estimates a sample value from its $2^n - 1$ immediate neighbors in a regular grid to generate residuals, which are then encoded using arithmetic coding [S1, unofficial]. It is distinguished from anisotropic scanline predictors by exploiting data coherence in all dimensions isotropically and is the simplest isotropic predictor capable of exactly reconstructing all polynomials of degree less than $n$ [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An $n$-dimensional scalar field $F$ defined on a grid with dimensions $D_1 \times D_2 \times \dots \times D_n$.
*   **Output:** A compressed bitstream representing the residuals between actual values and predictions.

**Data Structures:**
*   **Footprint Buffer:** A circular FIFO buffer storing the "footprint" of previously processed values required for prediction. For an $n$-dimensional dataset with ranges $X_1, \dots, X_n$, the buffer size is sufficient to hold the current slice and the footprint of the $(n-1)$-dimensional sub-problem. Specifically, for $R^4$, the size is $X_M Y_M Z_M + X_M Y_M + X_M + 1$ [S1, unofficial]. The buffer allows out-of-core processing by only keeping necessary neighbors in memory [S1, unofficial].

**Prediction Formula:**
The predicted value $P(v)$ for a sample at vertex $v = (1, 1, \dots, 1)$ in a local coordinate system where previously visited neighbors have coordinates in $\{0, 1\}^n$ is given by [S1, unofficial]:

$$ P(v) = \sum_{u \in \{0,1\}^n \setminus \{v\}} (-1)^{g(u)} F(u) $$

where:
*   $u$ iterates over the $2^n - 1$ other corners of the unit hypercube.
*   $g(u)$ is the number of coordinates of $u$ that equal 0 (equivalently, the Hamming distance from $v$ if $v$ is all 1s, or $n - u \cdot v$ where $v$ is the all-ones vector) [S1, unofficial].
*   Weights are $+1$ if $g(u)$ is even, and $-1$ if $g(u)$ is odd.

**Algorithm Steps:**
The compression visits the data in a specific recursive scanline order. The algorithm `Lorenzo(d, x_1, \dots, x_n)` processes the data as follows [S1, unofficial]:

1.  **Base Case / Initialization:** If any coordinate $x_i$ is $-1$ (indicating the start of a new dimension traversal), the algorithm recurses to initialize the lower dimensions.
2.  **Prediction and Encoding:** If all coordinates are valid (not $-1$), compute the prediction $p$ using the formula above, then encode the residual $r = F[x_1, \dots, x_n] - p$ using arithmetic coding.
3.  **Recursion:** To traverse the grid, the algorithm uses a recursive structure that effectively iterates through the $n$ dimensions.

**Parameters:**
*   **Dimension $n$:** The number of dimensions in the scalar field. Typical values are 3 or 4 [S1, unofficial].
*   **Encoder:** Context arithmetic encoder is recommended, providing a 25% gain over adaptive arithmetic coding [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Polynomial Degree:** The predictor is exact for polynomials of degree less than $n$. For a 3D predictor applied to a cubic function, the error is between 3% and 8% (L-infinity sense) [S1, unofficial]. For a 4D predictor applied to a quartic function, the error is less than 1% [S1, unofficial].
*   **Memory Footprint:** The buffer size must be carefully managed for out-of-core processing. The size is $X_M Y_M Z_M + X_M Y_M + X_M + 1$ for $R^4$ [S1, unofficial].
*   **Boundary Conditions:** The predictor requires $2^n - 1$ neighbors. At the boundaries of the grid, the "previous" neighbors must be handled carefully, typically by assuming the scanline order ensures that only previously visited neighbors are used [S1, unofficial].

## Subtopics

### [Lorenzo Predictor](10120-lorenzo-predictor.md)
The Lorenzo predictor is an isotropic predictive coding method for $n$-dimensional scalar fields that estimates a sample value from its $2^n - 1$ immediate neighbors in a regular grid to generate residuals for compression [S1, unofficial]. It is distinguished from anisotropic scanline predictors by exploiting data coherence in all dimensions and is the simplest isotropic predictor capable of exactly reconstructing all polynomials of degree less than $n$ [S1, unofficial].

### [SZ-L/R](11010-sz-l-r.md)
SZ-L/R is a block-based lossless/lossy compression algorithm for volumetric data that employs Lorenzo and linear regression predictors [S1, unofficial]. It partitions input data into independent 6×6×6 blocks, allowing for cache-friendly processing and random access without inter-block dependencies [S1, unofficial]. Unlike global interpolation methods such as [SZ-Interp](52-sz-interp.md), SZ-L/R prioritizes local feature preservation, making it suitable for unsmooth and irregular datasets, though it may introduce block-wise artifacts [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The prediction requires $O(2^n)$ operations per sample to sum the neighbors. The encoding is linear in the number of samples.
*   **Memory Complexity:** The memory footprint is small, proportional to the size of one slice plus the footprint of the $(n-1)$-dimensional sub-problem. For $R^4$, the buffer size is $X_M Y_M Z_M + X_M Y_M + X_M + 1$ [S1, unofficial]. This makes it suitable for out-of-core implementations [S1, unofficial].
*   **Measured Performance:**
    *   On a 3D model of a house on fire (43,202,395 bytes uncompressed), 4D Lorenzo compression reduced the size to 524,768 bytes (1.21% of total), outperforming 3D slice compression (1,076,587 bytes, 2.49%) by 50% [S1, unofficial].
    *   On a fluid mixing simulation dataset, 3D time slice predictor produced 304,937,058 bytes (1.77 bits/symbol) and 4D Lorenzo produced 318,871,620 bytes (1.85 bits/symbol) [S1, unofficial].
    *   In lossless compression, cubic wavelets are slightly better than the Lorenzo predictor in terms of residual entropy for 4D datasets [S1, unofficial].
    *   In lossy L-infinity compression, the Lorenzo predictor performs better than SPIHT on tested 2D datasets [S1, unofficial].
*   **Strengths:** Isotropic prediction, small memory footprint, exact reconstruction of low-degree polynomials, suitable for out-of-core processing.
*   **Limitations:** Slightly lower compression ratio than wavelets for some 4D datasets in lossless scenarios. Performance degrades for high-degree polynomials.

## Background
The Lorenz Predictor was introduced by S. Mennon and M. Rizk in the paper "Out-of-Core Compression and Decompression of Large n-Dimensional Scalar Fields" [S1, unofficial]. It extends the simple two-dimensional parallelogram predictor to higher dimensions. The method is designed to handle large $n$-dimensional scalar fields where the total size exceeds available memory, making it particularly useful for volume rendering and scientific visualization of large datasets.
