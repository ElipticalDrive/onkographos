# Lorenz Predictor with Arithmetic Coding

Also called: Lorenzo, Lorenz预测与算术编码, n-dimensional Lorenzo predictor, n-dimensional parallelogram predictor

## Overview
The Lorenz Predictor with Arithmetic Coding is a predictive compression method for $n$-dimensional scalar fields that estimates a sample value from its $2^n - 1$ immediate neighbors in a regular grid to generate residuals, which are then entropy-coded using arithmetic coding [S1, unofficial]. It is distinguished from anisotropic scanline predictors by exploiting data coherence in all dimensions isotropically and is the simplest isotropic predictor capable of exactly reconstructing all polynomials of degree less than $n$ [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: An $n$-dimensional scalar field $F$ defined on a grid with dimensions $D_1 \times D_2 \times \dots \times D_n$.
- Output: A compressed bitstream representing the residuals of the prediction.

**Data Structures:**
- **Footprint Buffer:** A circular FIFO buffer storing the values of previously processed neighbors required for prediction. For an $n$-dimensional dataset with ranges $X_1, X_2, \dots, X_n$, the buffer size is determined by the sum of the sizes of all lower-dimensional slices. Specifically, for $R^4$ with ranges $XM, YM, ZM, TM$, the buffer size is $XM \cdot YM \cdot ZM + XM \cdot YM + XM + 1$ [S1, unofficial]. In general $R^n$, the buffer stores the "footprint" of the current hyperplane being processed, which consists of the values from the previous $(n-1)$-dimensional slice and all lower-dimensional boundaries [S1, unofficial].
- **Arithmetic Encoder:** A context arithmetic encoder is used to encode the residuals. The context is the predicted value itself [S1, unofficial].

**Prediction Formula:**
Let $v$ be the current sample point with coordinates $(1, 1, \dots, 1)$ in a local coordinate system where all previously visited neighbors have coordinates in $\{0, 1\}^n$. The predicted value $P(v)$ is calculated as:
$$ P(v) = \sum_{u \in \{0,1\}^n \setminus \{v\}} (-1)^{g(u)} F(u) $$
where:
- $u$ iterates over all $2^n - 1$ previously visited neighbors (vertices of the unit hypercube excluding $v$).
- $g(u)$ is the number of coordinates of $u$ that equal 0. Equivalently, $g(u) = n - (u \cdot v)$, where $u \cdot v$ is the dot product of $u$ and $v$ (assuming $v=(1,\dots,1)$) [S1, unofficial].
- The weight $(-1)^{g(u)}$ is $1$ if $u$ has an even number of 0-coordinates and $-1$ if it has an odd number [S1, unofficial].

**Residual Calculation:**
The residual $R$ is computed as:
$$ R = F(v) - P(v) $$

**Compression Steps:**
1. **Initialization:** Start the recursive traversal with $Lorenzo(n, -1, \dots, -1)$ [S1, unofficial].
2. **Traversal:** Process the data in a specific recursive order that ensures neighbors are available when needed.
3. **Prediction:** For each sample $v$, compute $P(v)$ using the footprint buffer.
4. **Encoding:** Encode the residual $R = F(v) - P(v)$ using a context arithmetic encoder, where the context is derived from the predicted value $P(v)$ [S1, unofficial].
5. **Update:** Update the footprint buffer with the current value $F(v)$ (or the reconstructed value if lossy, though the source emphasizes lossless context coding) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Polynomial Degree:** The predictor is exact for polynomials of degree less than $n$. For a 3D predictor applied to a cubic function, the error is between 3% and 8% (L-infinity sense). For a 4D predictor applied to a quartic function, the error is less than 1% [S1, unofficial].
- **Memory Footprint:** The buffer size grows exponentially with dimension. For $R^4$, the buffer size is $XM \cdot YM \cdot ZM + XM \cdot YM + XM + 1$ [S1, unofficial]. This makes it suitable for out-of-core implementations [S1, unofficial].
- **Boundary Conditions:** The recursive traversal ensures that all necessary neighbors are processed before the current sample. The starting call for a 4D dataset is $Lorenzo(4, -1, \dots, -1)$ [S1, unofficial].

## Subtopics

### [Lorenzo Predictor](10120-lorenzo-predictor.md)
The Lorenzo predictor is an isotropic predictive coding method for $n$-dimensional scalar fields that estimates a sample value from its $2^n - 1$ immediate neighbors in a regular grid to generate residuals for compression. It is distinguished from anisotropic scanline predictors by exploiting data coherence in all dimensions and is the simplest isotropic predictor capable of exactly reconstructing all polynomials of degree less than $n$.

### [SZ-L/R](11010-sz-l-r.md)
SZ-L/R is a block-based lossless/lossy compression algorithm for volumetric data that employs Lorenzo and linear regression predictors. It partitions input data into independent 6×6×6 blocks, allowing for cache-friendly processing and random access without inter-block dependencies. Unlike global interpolation methods such as [SZ-Interp](52-sz-interp.md), SZ-L/R prioritizes local feature preservation, making it suitable for unsmooth and irregular datasets, though it may introduce block-wise artifacts.

## Operating characteristics
- **Time Complexity:** The prediction for each sample involves $2^n - 1$ lookups and additions. The traversal is $O(N)$ where $N$ is the total number of samples.
- **Memory Complexity:** The memory footprint is proportional to the size of the $(n-1)$-dimensional slice plus lower-dimensional boundaries. For $R^n$, the buffer size is $\sum_{i=0}^{n-1} \prod_{j=1}^{i} D_j$ (with appropriate indexing) [S1, unofficial]. This is significantly smaller than storing the entire dataset, enabling out-of-core processing [S1, unofficial].
- **Performance:**
    - On a 3D model of a house on fire (43,202,395 bytes uncompressed), 4D Lorenzo compression reduced the size to 524,768 bytes (1.21% of total), outperforming 3D slice compression (1,076,587 bytes, 2.49%) by 50% [S1, unofficial].
    - On a fluid mixing simulation dataset, 3D time slice predictor produced 304,937,058 bytes (1.77 bits/symbol) and 4D Lorenzo produced 318,871,620 bytes (1.85 bits/symbol) [S1, unofficial].
    - Context arithmetic encoder gives a 25% gain over adaptive arithmetic encoder for encoding residuals [S1, unofficial].
    - In lossless compression, cubic wavelets are slightly better than the Lorenzo predictor in terms of residual entropy for 4D datasets [S1, unofficial].
    - In lossy L-infinity compression, the Lorenzo predictor performs better than SPIHT (a wavelet implementation using S+P transform) on the tested 2D dataset [S1, unofficial].
- **Strengths:** Isotropic prediction, exact reconstruction of polynomials of degree $< n$, small memory footprint suitable for out-of-core processing, high compression ratios for coherent data [S1, unofficial].
- **Limitations:** Less effective than wavelets for lossless compression of some 4D datasets, error increases for data with high-degree polynomial components [S1, unofficial].

## Background
The Lorenz Predictor was introduced by S. Mennon and M. Rizk in the paper "Out-of-Core Compression and Decompression of Large n-Dimensional Scalar Fields" [S1, unofficial]. It extends the simple two-dimensional parallelogram predictor to higher dimensions. The method is designed for large $n$-dimensional scalar fields, particularly in scientific visualization and simulation data, where data coherence exists in all dimensions. It is used in contexts requiring efficient out-of-core compression and decompression, such as large-scale fluid dynamics simulations and climate modeling [S1, unofficial].
