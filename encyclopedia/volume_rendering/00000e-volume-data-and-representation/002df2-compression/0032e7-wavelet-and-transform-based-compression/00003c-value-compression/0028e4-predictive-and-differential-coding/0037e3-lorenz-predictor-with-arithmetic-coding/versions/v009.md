# Lorenz Predictor with Arithmetic Coding

Also called: Lorenzo, Lorenz预测与算术编码, n-dimensional Lorenzo predictor, n-dimensional parallelogram predictor

## Overview
The Lorenz Predictor with Arithmetic Coding is a lossless compression method for $n$-dimensional scalar fields that estimates the value of a sample point from its $2^n - 1$ previously processed neighbors forming the other corners of an $n$-dimensional unit hypercube, then encodes the resulting residual using arithmetic coding [S1, unofficial]. It is distinguished from anisotropic scanline predictors by being isotropic, exploiting data coherence in all dimensions, and is the simplest isotropic predictor capable of exactly reconstructing all polynomials of degree less than $n$ [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An $n$-dimensional scalar field $F$ with dimensions $D_1 \times D_2 \times \dots \times D_n$.
*   **Output:** A compressed bitstream representing the residuals of the prediction.

**Data Structures:**
*   **Footprint Buffer:** A circular FIFO buffer storing the values of the "footprint" required for prediction. For an $n$-dimensional dataset with ranges $X_1, X_2, \dots, X_n$ (where $X_i$ is the size of dimension $i$), the buffer size is sufficient to hold the current slice and the footprint of the lower-dimensional recursion. Specifically, for $R^4$, the size is $X_M \cdot Y_M \cdot Z_M + X_M \cdot Y_M + X_M + 1$ [S1, unofficial]. In general, the buffer must store the values of the $2^n - 1$ neighbors for the current prediction step, but due to the scan order, only a subset (the "footprint") needs to be kept in memory at any time [S1, unofficial].
*   **Arithmetic Encoder:** A context-based arithmetic encoder that uses the predicted value as context for the residual [S1, unofficial].

**Prediction Formula:**
Let $v$ be the current sample point with local coordinates $(1, 1, \dots, 1)$ in a system where previously visited neighbors have coordinates in $\{0, 1\}^n$. The predicted value $P(v)$ is:

$$ P(v) = \sum_{u \in \{0,1\}^n \setminus \{v\}} (-1)^{g(u)} F(u) $$

where $g(u)$ is the number of coordinates of $u$ that equal 0 (i.e., the Hamming distance from $u$ to $v$ in the hypercube, or equivalently $n - u \cdot v$ where $u \cdot v$ is the dot product) [S1, unofficial]. The weight is $+1$ if $g(u)$ is even and $-1$ if $g(u)$ is odd.

**Algorithm Steps:**
1.  **Initialization:** Initialize the arithmetic encoder. Initialize the footprint buffer.
2.  **Recursive Scan:** Traverse the $n$-dimensional grid using a recursive function `Lorenzo(d, x_1, ..., x_n)` where $d$ is the current dimension being processed (from $n$ down to 1) and $x_i$ are the coordinates.
    *   If $d > 0$:
        *   If all coordinates $x_1, \dots, x_n$ are initialized (not -1):
            *   Compute prediction $p = \text{LorenzoPredictor}(d, x_1, \dots, x_n)$ using the formula above, accessing values from the footprint buffer.
            *   Compute residual $r = F[x_1, \dots, x_n] - p$.
            *   Encode $r$ using the context arithmetic encoder with context $p$ [S1, unofficial].
            *   Store $F[x_1, \dots, x_n]$ in the footprint buffer for future predictions.
        *   Else (coordinates not fully initialized):
            *   Call `Lorenzo(d - 1, x_1, \dots, x_{d-1}, 0, x_{d+1}, \dots, x_n)` to initialize the $d$-th coordinate to 0.
            *   Loop $i$ from 1 to $D_d$ (size of dimension $d$):
                *   Call `Lorenzo(d, x_1, \dots, x_{d-1}, i, x_{d+1}, \dots, x_n)`.
    *   Base case ($d=0$): This corresponds to the innermost loop over the last dimension. The prediction is performed for each sample in this dimension using the previously computed values in the footprint [S1, unofficial].
3.  **Termination:** After all samples are processed, finalize the arithmetic encoder.

def lorenzo_predictor(values, n):
    """
    Computes the Lorenzo prediction for the corner (1,1,...,1)
    given the values at the other 2^n - 1 corners of the unit hypercube.
    values: list of values F(u) for u in {0,1}^n \ {(1,...,1)}
    n: dimension
    Returns: predicted value P(v)
    """
    pred = 0
    # Iterate through all 2^n - 1 neighbors
    # We can map the index i (0 to 2^n - 2) to the coordinate vector u
    for i in range(2**n - 1):
        # Construct u from i
        u = []
        temp_i = i
        for dim in range(n):
            u.append(temp_i % 2)
            temp_i //= 2
        # Note: The order of bits in u corresponds to dimensions 1..n
        # g(u) is the number of zeros in u
        g_u = n - sum(u)
        weight = 1 if (g_u % 2 == 0) else -1
        pred += weight * values[i]
    return pred

def encode_residual(residual, context, encoder):
    """
    Encodes the residual using context arithmetic coding.
    """
    encoder.encode(residual, context)

**Parameters:**
*   $n$: The dimension of the data. Typical values are 3 or 4 [S1, unofficial].
*   Arithmetic Encoder: Context-based encoder is recommended for a 25% gain over adaptive arithmetic encoder [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The predictor is exact for polynomials of degree less than $n$. For a 3D predictor on a cubic function, the error is 3-8% (L-infinity). For a 4D predictor on a quartic function, the error is <1% [S1, unofficial].
*   **Boundaries:** The predictor requires $2^n - 1$ neighbors. At the boundaries of the grid, some neighbors may not exist. The scan order ensures that only previously visited neighbors are used, so boundary conditions are handled by the scan order itself (e.g., the first sample has no neighbors, but the source implies a specific order where the first sample is handled by the recursion initializing the coordinates). The source example for 2D shows the first sample H[0,0] is encoded without prediction (or with a null prediction). The pseudocode handles this by the recursion structure.
*   **Memory:** The footprint buffer size is critical for out-of-core implementations. For $R^4$, the size is $X_M \cdot Y_M \cdot Z_M + X_M \cdot Y_M + X_M + 1$ [S1, unofficial].

## Subtopics

### [Lorenzo Predictor](10120-lorenzo-predictor.md)
The Lorenzo predictor is an isotropic predictive coding method for $n$-dimensional scalar fields that estimates a sample value from its $2^n - 1$ immediate neighbors in a regular grid to generate residuals for compression. It is distinguished from anisotropic scanline predictors by exploiting data coherence in all dimensions and is the simplest isotropic predictor capable of exactly reconstructing all polynomials of degree less than $n$.

### [SZ-L/R](11010-sz-l-r.md)
SZ-L/R is a block-based lossless/lossy compression algorithm for volumetric data that employs Lorenzo and linear regression predictors. It partitions input data into independent 6×6×6 blocks, allowing for cache-friendly processing and random access without inter-block dependencies. Unlike global interpolation methods such as [SZ-Interp](52-sz-interp.md), SZ-L/R prioritizes local feature preservation, making it suitable for unsmooth and irregular datasets, though it may introduce block-wise artifacts.

## Operating characteristics
*   **Time Complexity:** The prediction for each sample involves $2^n - 1$ lookups and additions. The arithmetic encoding is linear in the number of samples.
*   **Memory Complexity:** The memory footprint is proportional to the size of the current slice and the footprint of the lower-dimensional recursion. For $R^4$, the buffer size is $X_M \cdot Y_M \cdot Z_M + X_M \cdot Y_M + X_M + 1$ [S1, unofficial]. This makes it suitable for out-of-core implementations [S1, unofficial].
*   **Measured Performance:** On a 3D model of a house on fire (43,202,395 bytes uncompressed), 4D Lorenzo compression reduced the size to 524,768 bytes (1.21% of total), outperforming 3D slice compression (1,076,587 bytes, 2.49%) by 50% [S1, unofficial]. On a fluid mixing simulation dataset, 3D time slice predictor produced 304,937,058 bytes (1.77 bits/symbol) and 4D Lorenzo produced 318,871,620 bytes (1.85 bits/symbol) [S1, unofficial].
*   **Strengths:** Isotropic prediction, exact reconstruction of polynomials of degree < $n$, small memory footprint, suitable for out-of-core processing [S1, unofficial].
*   **Limitations:** For data with high-frequency components or non-polynomial behavior, the residuals may be larger. In lossless compression, cubic wavelets are slightly better than the Lorenzo predictor in terms of residual entropy for 4D datasets [S1, unofficial].
*   **When to use:** When data has high coherence in all dimensions and is smooth enough to be approximated by low-degree polynomials. When out-of-core processing is required.
*   **When not to use:** When data is highly irregular or has high-frequency components that are not well-approximated by polynomials. When lossless compression with minimal residual entropy is critical and wavelets are an option.

## Background
The Lorenz Predictor was introduced by S. Mennon and M. Rizk in the paper "Out-of-Core Compression and Decompression of Large n-Dimensional Scalar Fields" [S1, unofficial]. It is an extension of the 2D parallelogram predictor to higher dimensions. The method is designed for large $n$-dimensional scalar fields, particularly in scientific visualization and volume rendering, where data coherence in all dimensions can be exploited for compression.
