# Lorenz Predictor with Arithmetic Coding

Also called: Lorenzo, Lorenz预测与算术编码, n-dimensional Lorenzo predictor, n-dimensional parallelogram predictor

## Overview
The Lorenz Predictor with Arithmetic Coding is a lossless compression method for $n$-dimensional scalar fields that combines an isotropic predictive coding scheme with entropy coding [S1, unofficial]. It solves the problem of compressing large volumetric or spatiotemporal datasets by exploiting data coherence in all dimensions, unlike anisotropic scanline predictors that only use preceding neighbors in a single direction [S1, unofficial]. It is distinguished from its siblings by being the simplest isotropic predictor capable of exactly reconstructing all polynomials of degree less than $n$, and by using arithmetic coding (specifically context-based) to encode the resulting residuals [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: An $n$-dimensional scalar field $F$ with dimensions $D_1 \times D_2 \times \dots \times D_n$.
- Output: A bitstream representing the compressed residuals.

**Data Structures:**
- **Footprint Buffer:** A circular FIFO buffer storing the values of the "footprint" neighbors required for prediction. For an $n$-dimensional dataset, the buffer size is determined by the sum of the sizes of all lower-dimensional slices. For example, in $R^4$ with ranges $XM, YM, ZM, TM$, the buffer size is $XM \cdot YM \cdot ZM + XM \cdot YM + XM + 1$ [S1, unofficial]. This allows out-of-core processing where only the immediate neighborhood is kept in memory [S1, unofficial].
- **Arithmetic Encoder:** A context-based arithmetic encoder that uses the predicted value as context for the residual [S1, unofficial].

**Prediction Formula:**
Let $v$ be the current sample point with local coordinates $(1, 1, \dots, 1)$ in a system where previously visited neighbors have coordinates in $\{0, 1\}^n$. The prediction $P(v)$ is the weighted sum of the values $F(u)$ at the other $2^n - 1$ corners $u$ of the unit hypercube:

$$ P(v) = \sum_{u \in \{0,1\}^n \setminus \{v\}} (-1)^{g(u)} F(u) $$

where $g(u)$ is the number of coordinates of $u$ that equal 0 (i.e., the Hamming distance from $u$ to $v$ in the $\{0,1\}^n$ grid, or equivalently $n - u \cdot v$ if $v$ is all 1s) [S1, unofficial]. The weight is $+1$ if $g(u)$ is even, and $-1$ if $g(u)$ is odd [S1, unofficial].

**Residual Calculation:**
The residual $d$ is computed as:
$$ d = F(v) - P(v) $$

**Encoding:**
The residual $d$ is encoded using an arithmetic coder. A context-based arithmetic encoder, which uses the predicted value $P(v)$ as context, provides a 25% gain over an adaptive arithmetic encoder [S1, unofficial].

**Decompression:**
The decoder reconstructs $F(v)$ using the same predictor logic and the decoded residual:
$$ F(v) = P(v) + d $$

**Pseudocode:**
The compression visits samples in a specific recursive scanline order. The function `Lorenzo` processes the data. `d` is the current dimension being processed, `x` is the array of coordinates, and `dmax` is the size of the dimension.

def encode_lorenzo(d, x, dmax, n, F, footprint, encoder):
    """
    Recursive function to compress the n-dimensional field F.
    d: current dimension index (1 to n).
    x: array of coordinates [x_1, ..., x_n].
    dmax: array of sizes [D_1, ..., D_n].
    """
    # Check if all coordinates for dimensions 1..d are set (not -1)
    all_set = True
    for i in range(d):
        if x[i] == -1:
            all_set = False
            break
            
    if all_set:
        # We are at a leaf in the recursion tree for this dimension block
        # Compute prediction using the footprint
        p = lorenzo_predictor(d, x)
        
        # Get actual value F[x]
        # Note: x is 0-indexed or 1-indexed? The paper uses 0-indexed for array access usually.
        # The local coordinate system is for the predictor logic.

        residual = actual_val - p
        
        # Encode residual
        encoder.encode(residual, context=p)

    else:

                break
        
        # Set this dimension to 0 and recurse
        x[dim_to_fill] = 0

        # Loop through the rest of the values for this dimension
        for i in range(1, dmax[dim_to_fill]):
            x[dim_to_fill] = i
            encode_lorenzo(d, x, dmax, n, F, footprint, encoder)

# x is initialized to [-1, -1, ..., -1]
# d starts at n
encode_lorenzo(n, [-1]*n, dmax, n, F, footprint, encoder)

**Parameters:**
- $n$: The dimension of the data (e.g., 3 for volume, 4 for spatiotemporal volume) [S1, unofficial].
- $dmax$: The size of each dimension [S1, unofficial].
- Encoder: Context-based arithmetic encoder [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Polynomial Degree:** The predictor is exact for polynomials of degree less than $n$. For a 3D predictor applied to a cubic function, the error is between 3% and 8% (L-infinity sense) [S1, unofficial]. For a 4D predictor applied to a quartic function, the error is less than 1% [S1, unofficial].
- **Memory Footprint:** The method is designed for out-of-core processing. The footprint buffer size must be carefully managed. In $R^4$, the buffer size is $XM \cdot YM \cdot ZM + XM \cdot YM + XM + 1$ [S1, unofficial].
- **Boundary Conditions:** The recursive scanline order ensures that all required neighbors are available when the prediction is made. The starting call for a 4D dataset is `Lorenzo(4, -1, -1, -1, -1)` [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The prediction for each sample takes $O(2^n)$ time to sum the neighbors. The arithmetic coding is approximately linear in the number of bits.
- **Memory Complexity:** $O(\sum_{i=1}^{n-1} \prod_{j=1}^i D_j)$ for the footprint buffer, which is significantly smaller than the full dataset size, enabling out-of-core processing [S1, unofficial].
- **Performance:** On a 4D dataset of a house on fire (43 MB uncompressed), 4D Lorenzo compression reduced the size to 524 KB (1.21%), outperforming 3D slice compression (2.49%) by 50% [S1, unofficial]. On a fluid mixing simulation, 4D Lorenzo produced 318 MB (1.85 bits/symbol) vs 304 MB (1.77 bits/symbol) for 3D, showing that 4D coherence can sometimes be less effective if temporal coherence is low [S1, unofficial].
- **Strengths:** Isotropic prediction, exact reconstruction of low-degree polynomials, small memory footprint, suitable for out-of-core processing [S1, unofficial].
- **Limitations:** For data with high-frequency components or high-degree polynomials, the residuals may not be as small, leading to lower compression ratios. In lossless compression, cubic wavelets can be slightly better than Lorenzo for 4D datasets [S1, unofficial].

## Background
The Lorenz Predictor was introduced by S. Mennon and M. Rizk in their work on out-of-core compression of large n-dimensional scalar fields [S1, unofficial]. It extends the 2D parallelogram predictor to higher dimensions. The method is particularly useful for scientific simulations involving large spatiotemporal datasets, such as fluid dynamics and climate modeling [S1, unofficial].
