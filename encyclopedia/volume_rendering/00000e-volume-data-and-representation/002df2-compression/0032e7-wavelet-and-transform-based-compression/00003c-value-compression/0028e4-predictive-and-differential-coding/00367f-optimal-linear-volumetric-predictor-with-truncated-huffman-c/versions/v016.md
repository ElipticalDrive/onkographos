# Optimal Linear Volumetric Predictor with Truncated Huffman Coding

Also called: DPCM with Huffman Coding, DPCM-Huffman, Predictive Huffman Coding for Volumes, Volume DPCM with Huffman Coding, compvox algorithm, volumetric DPCM with optimal coefficients, 差值编码与霍夫曼编码结合

## Overview
This method is a lossless compression algorithm for 3D volume data that exploits spatial coherence by predicting voxel values from previously encoded neighbors and encoding the difference (residual) using a truncated Huffman code [S1, unofficial]. It achieves approximately 50% compression ratios on medical volume datasets, outperforming generic compressors like gzip and zip by explicitly removing spatial redundancy rather than just statistical redundancy [S1, unofficial]. Unlike [Delta Encoding](1096-delta-encoding.md) which uses fixed differences, this method derives optimal linear predictor coefficients for each volume to minimize mean-square error, and unlike [Lorenz Predictor with Arithmetic Coding](8070-lorenz-predictor-with-arithmetic-coding.md), it uses a truncated Huffman code with a fixed alphabet size limit to manage codebook complexity.

## How it works
**Inputs:** A 3D volume array $V$ of size $X \times Y \times Z$, where each voxel $v(x,y,z)$ is a 16-bit integer.
**Outputs:** A compressed bitstream containing the encoded residuals, preceded by a header storing the mean, predictor coefficients, and Huffman table.

**Data Structures:**
1.  **Volume Data:** $v(x,y,z)$ for $0 \le x < X, 0 \le y < Y, 0 \le z < Z$.
2.  **Covariance Matrix $A$:** A $3 \times 3$ symmetric matrix used to solve for predictor coefficients.
3.  **Covariance Vector $b$:** A $3 \times 1$ vector.
4.  **Predictor Coefficients $a$:** A $3 \times 1$ vector $[a_1, a_2, a_3]^T$.
5.  **Huffman Table:** A mapping from difference values (symbols) to bit codes.

**Parameters:**
*   **Truncation Limit $L_1$:** The number of most frequent symbols to be Huffman coded. Default $L_1 = 256$ [S1, unofficial].
*   **Total Symbol Space $L$:** For 16-bit voxels, difference values range from $-66535$ to $65536$, resulting in $L = 131,071$ possible symbols [S1, unofficial].
*   **Scan Order:** Raster-scan order (lexicographic: $x$ varies fastest, then $y$, then $z$) to ensure causality [S1, unofficial].

**Algorithm Steps:**

1.  **Estimate Mean:** Scan the entire volume to calculate the mean value $\bar{v}$:
    $$ \bar{v} = \frac{1}{XYZ} \sum_{x=0}^{X-1} \sum_{y=0}^{Y-1} \sum_{z=0}^{Z-1} v(x,y,z) $$
    [S1, unofficial]

2.  **Estimate Covariance:** Scan the volume to estimate the covariance $r(x,y,z)$ for lags $x,y,z \in \{-1, 0, 1\}$. To avoid boundary issues in the estimation, the summation indices are shifted:
    $$ r(x,y,z) = \frac{1}{(X-2)(Y-2)(Z-2)} \sum_{x'=1}^{X-2} \sum_{y'=1}^{Y-2} \sum_{z'=1}^{Z-2} [v(x',y',z') - \bar{v}] [v(x'+x, y'+y, z'+z) - \bar{v}] $$
    [S1, unofficial]

3.  **Calculate Predictor Coefficients:** Solve the linear system $A \mathbf{a} = \mathbf{b}$ for $\mathbf{a} = [a_1, a_2, a_3]^T$. The matrix $A$ and vector $\mathbf{b}$ are constructed from the estimated covariances:
    $$
    \begin{bmatrix}
    r(0,0,0) & r(1,-1,0) & r(1,0,-1) \\
    r(-1,1,0) & r(0,0,0) & r(0,1,-1) \\
    r(-1,0,1) & r(0,-1,1) & r(0,0,0)
    \end{bmatrix}
    \begin{bmatrix}
    a_1 \\ a_2 \\ a_3
    \end{bmatrix}
    =
    \begin{bmatrix}
    r(1,0,0) \\ r(0,1,0) \\ r(0,0,1)
    \end{bmatrix}
    $$
    Note: The source provides this specific matrix layout in Equation (8) [S1, unofficial]. While standard Yule-Walker equations for a causal predictor typically involve $r(1,0,0)$, $r(0,1,0)$, etc., in the first column/row, the implementation instruction is to solve the linear system as defined in the source [S1, unofficial].

4.  **Calculate Residuals (First Pass):** Scan the volume in raster-scan order. For each voxel $v(x,y,z)$, calculate the predicted value $\tilde{v}(x,y,z)$ using mean-subtracted neighbors. Define the neighbor contributions $v_1, v_2, v_3$:
    $$
    v_1(x,y,z) = \begin{cases} 0 & \text{if } x=0 \\ v(x-1,y,z) - \bar{v} & \text{if } x>0 \end{cases}
    $$
    $$
    v_2(x,y,z) = \begin{cases} 0 & \text{if } y=0 \\ v(x,y-1,z) - \bar{v} & \text{if } y>0 \end{cases}
    $$
    $$
    v_3(x,y,z) = \begin{cases} 0 & \text{if } z=0 \\ v(x,y,z-1) - \bar{v} & \text{if } z>0 \end{cases}
    $$
    The prediction is:
    $$ \tilde{v}(x,y,z) = a_1 v_1(x,y,z) + a_2 v_2(x,y,z) + a_3 v_3(x,y,z) $$
    The residual (difference) is:
    $$ d(x,y,z) = v(x,y,z) - \tilde{v}(x,y,z) $$
    [S1, unofficial]

5.  **Count Symbol Frequencies:** Count the occurrences of each unique difference value $s_i$ across the volume. These counts estimate the symbol probabilities $p_i$. [S1, unofficial]

6.  **Build Huffman Table:** Construct a truncated Huffman code table. The $L_1$ most frequent symbols (where $L_1=256$) are assigned variable-length Huffman codes. The remaining $L - L_1$ symbols are assigned fixed-length codes. [S1, unofficial]

7.  **Encode (Second Pass):** Scan the volume again in raster-scan order. Recalculate $d(x,y,z)$ using the same predictor logic (Step 4). Encode each $d(x,y,z)$ using the Huffman table from Step 6. Write the encoded bits to the output stream. Do not store the difference values in memory to save space. [S1, unofficial]

**Decompression:**
1.  Read the header: mean $\bar{v}$, coefficients $a_1, a_2, a_3$, and the Huffman table. [S1, unofficial]
2.  For each voxel in raster-scan order:
    a. Read the next Huffman code from the stream and look up the difference value $d(x,y,z)$. [S1, unofficial]
    b. Calculate the predicted value $\tilde{v}(x,y,z)$ using the same causal logic and stored coefficients. [S1, unofficial]
    c. Reconstruct the voxel: $v(x,y,z) = \tilde{v}(x,y,z) + d(x,y,z)$. [S1, unofficial]

**Pseudocode:**

```python
def compress_volume(volume: Array3D, L1: int = 256) -> bytes:
    X, Y, Z = volume.shape
    
    # Step 1: Estimate Mean
    mean_val = sum(volume[x, y, z] for x in range(X) for y in range(Y) for z in range(Z)) / (X * Y * Z)
    
    # Step 2: Estimate Covariance
    # We need r(x,y,z) for x,y,z in {-1, 0, 1}
    cov = {}
    for dx in [-1, 0, 1]:
        for dy in [-1, 0, 1]:
            for dz in [-1, 0, 1]:
                sum_val = 0.0
                count = (X - 2) * (Y - 2) * (Z - 2)
                for x in range(1, X - 1):
                    for y in range(1, Y - 1):
                        for z in range(1, Z - 1):
                            term1 = volume[x, y, z] - mean_val
                            term2 = volume[x + dx, y + dy, z + dz] - mean_val
                            sum_val += term1 * term2
                cov[(dx, dy, dz)] = sum_val / count
                
    # Step 3: Solve for Predictor Coefficients
    # Matrix A and Vector b as defined in source Eq (8)
    # Note: The source matrix indices are specific. 
    # Row 1: r(0,0,0), r(1,-1,0), r(1,0,-1)
    # Row 2: r(-1,1,0), r(0,0,0), r(0,1,-1)
    # Row 3: r(-1,0,1), r(0,-1,1), r(0,0,0)
    # RHS: r(1,0,0), r(0,1,0), r(0,0,1)
    
    A = [
        [cov[(0,0,0)], cov[(1,-1,0)], cov[(1,0,-1)]],
        [cov[(-1,1,0)], cov[(0,0,0)], cov[(0,1,-1)]],
        [cov[(-1,0,1)], cov[(0,-1,1)], cov[(0,0,0)]]
    ]
    b = [
        cov[(1,0,0)],
        cov[(0,1,0)],
        cov[(0,0,1)]
    ]
    
    # Solve linear system A * a = b
    # Using a standard linear solver (e.g., Gaussian elimination or numpy.linalg.solve)
    a = solve_linear_system(A, b) 
    a1, a2, a3 = a
    
    # Step 4 & 5: Calculate Residuals and Count Frequencies
    # We do not store residuals to save memory, but we need counts for Huffman table
    freq = {}
    
    # Helper to get neighbor value with mean subtraction
    def get_neighbor_val(x, y, z, axis):
        if axis == 0: # x-1
            if x == 0: return 0
            return volume[x-1, y, z] - mean_val
        elif axis == 1: # y-1
            if y == 0: return 0
            return volume[x, y-1, z] - mean_val
        else: # z-1
            if z == 0: return 0
            return volume[x, y, z-1] - mean_val

    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                v1 = get_neighbor_val(x, y, z, 0)
                v2 = get_neighbor_val(x, y, z, 1)
                v3 = get_neighbor_val(x, y, z, 2)
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                diff = volume[x, y, z] - pred
                
                # Count frequency
                freq[diff] = freq.get(diff, 0) + 1
                
    # Step 6: Build Truncated Huffman Table
    # Sort symbols by frequency descending
    sorted_symbols = sorted(freq.keys(), key=lambda s: freq[s], reverse=True)
    
    huffman_table = {}
    # First L1 symbols get Huffman codes
    symbols_to_huffman = sorted_symbols[:L1]
    # Remaining symbols get fixed length codes
    symbols_fixed = sorted_symbols[L1:]
    
    # Generate Huffman codes for top L1 symbols
    # (Implementation of Huffman tree generation omitted for brevity, assumed available)
    huffman_codes = generate_huffman_codes(symbols_to_huffman)
    for sym, code in huffman_codes.items():
        huffman_table[sym] = code
        
    # Assign fixed length codes to remaining symbols
    # Fixed length needs ceil(log2(L - L1)) bits
    fixed_len_bits = ceil(log2(len(symbols_fixed))) if symbols_fixed else 0
    for i, sym in enumerate(symbols_fixed):
        huffman_table[sym] = (i, fixed_len_bits) # Store as (index, bit_length) or similar structure
        
    # Step 7: Encode
    bitstream = []
    
    # Write Header
    write_header(bitstream, mean_val, a1, a2, a3, huffman_table)
    
    # Re-scan to encode
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                v1 = get_neighbor_val(x, y, z, 0)
                v2 = get_neighbor_val(x, y, z, 1)
                v3 = get_neighbor_val(x, y, z, 2)
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                diff = volume[x, y, z] - pred
                
                code = huffman_table[diff]
                if isinstance(code, tuple): # Fixed length
                    idx, bits = code
                    bitstream.append(f"{idx:0{bits}b}")
                else: # Huffman code
                    bitstream.append(code)
                    
    return join_bits(bitstream)

def decompress_volume(compressed_data: bytes, X: int, Y: int, Z: int) -> Array3D:
    # Step 1: Read Header
    mean_val, a1, a2, a3, huffman_table = read_header(compressed_data)
    
    volume = empty_array(X, Y, Z)
    bitstream = get_bits(compressed_data)
    
    # Helper to get neighbor value with mean subtraction
    def get_neighbor_val(x, y, z, axis):
        if axis == 0: # x-1
            if x == 0: return 0
            return volume[x-1, y, z] - mean_val
        elif axis == 1: # y-1
            if y == 0: return 0
            return volume[x, y-1, z] - mean_val
        else: # z-1
            if z == 0: return 0
            return volume[x, y, z-1] - mean_val

    # Step 2-3: Decode and Reconstruct
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                # Decode difference
                diff = decode_huffman(bitstream, huffman_table)
                
                # Predict
                v1 = get_neighbor_val(x, y, z, 0)
                v2 = get_neighbor_val(x, y, z, 1)
                v3 = get_neighbor_val(x, y, z, 2)
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                
                # Reconstruct
                volume[x, y, z] = pred + diff
                
    return volume
```

## Operating characteristics
*   **Time Complexity:** The algorithm scans the volume four times: two for statistics (mean and covariance), one for calculating residuals (not stored), and one for encoding. The covariance calculation is $O(XYZ)$ with a constant factor related to the 27 lags. Solving the $3 \times 3$ linear system is $O(1)$. Building the Huffman table is $O(L \log L)$ or $O(L)$ depending on implementation, where $L$ is the alphabet size. Encoding is $O(XYZ)$.
*   **Memory Complexity:** $O(XYZ)$ for the input volume. The algorithm explicitly avoids storing the difference array to save memory, requiring the fourth scan [S1, unofficial]. The Huffman table size is bounded by $L_1$ (256 entries) plus fixed-length entries, which is small relative to the volume.
*   **Performance:** On a HP 9000 Series 735, compression of `3dhead.vox` (256x256x109) took 4.7 minutes, and decompression took 1.4 minutes [S1, unofficial]. It achieves an average compression ratio of 50.8% on the test set, significantly better than gzip (41.9%), zip (39.6%), and compress (36.9%) [S1, unofficial].
*   **Strengths:** Removes spatial redundancy effectively. The optimal predictor compensates for non-isotropic voxel sampling. Calculation of optimal coefficients takes only ~6% of total compression time [S1, unofficial].
*   **Limitations:** Assumes wide-sense stationarity, which real volume data often violates, making global statistics suboptimal. The four-pass nature is I/O intensive. The truncated Huffman code limits the maximum code length but may not be optimal for all distributions.

## Background
This method was introduced by James Edwin Fowler and Roni Yagel in January 1995 at the Proceedings of the 1994 Symposium on Volume Visualization [S1, unofficial]. It is designed specifically for lossless compression of biomedical and scientific volume data where lossy methods are unacceptable. The algorithm, often referred to as `compvox`, combines Differential Pulse-Code Modulation (DPCM) with Huffman coding. It builds on the principles of predictive coding by using a causal linear predictor to estimate voxel values based on previously encoded neighbors, calculating the difference, and encoding these differences using a truncated Huffman code. The assumption of wide-sense stationarity allows the use of the Yule-Walker equations to derive optimal predictor coefficients. Future improvements suggested by the authors include dividing the volume into an octree and using local predictors to address non-stationarity [S1, unofficial].
