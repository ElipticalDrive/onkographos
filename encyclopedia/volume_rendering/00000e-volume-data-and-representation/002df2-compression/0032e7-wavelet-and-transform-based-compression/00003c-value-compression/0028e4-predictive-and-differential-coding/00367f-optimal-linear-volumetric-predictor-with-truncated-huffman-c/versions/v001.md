# Optimal Linear Volumetric Predictor with Truncated Huffman Coding

Also called: DPCM with Huffman Coding, DPCM-Huffman, Predictive Huffman Coding for Volumes, Volume DPCM with Huffman Coding, compvox algorithm, volumetric DPCM with optimal coefficients, 差值编码与霍夫曼编码结合

## Overview
This method is a lossless compression algorithm for 3D volume data that exploits spatial coherence by predicting voxel values from previously encoded neighbors and encoding the difference (residual) using a truncated Huffman code [S1, unofficial]. It achieves approximately 50% compression ratios on biomedical volume datasets, outperforming generic compressors like gzip and zip by removing spatial redundancy rather than just statistical redundancy [S1, unofficial]. Unlike simple delta encoding, it uses an optimal linear predictor derived from the data's covariance to minimize residual variance [S1, unofficial].

## How it works
The algorithm operates in two main phases: coefficient estimation and encoding/decoding. It assumes the volume data is wide-sense stationary and uses a causal 6-neighborhood predictor (face-sharing neighbors only) [S1, unofficial].

### Inputs and Outputs
*   **Input:** A 3D volume array $v(x, y, z)$ of size $X \times Y \times Z$. The source data is typically 16-bit integers [S1, unofficial].
*   **Output:** A compressed bitstream containing the Huffman-encoded residuals, preceded by a header storing the mean, predictor coefficients, and the Huffman code table [S1, unofficial].

### Data Structures
*   **Compressed File Header:**
    *   Estimated mean $\bar{v}$ (float or fixed-point).
    *   Predictor coefficients $a_1, a_2, a_3$ (float or fixed-point).
    *   Huffman Code Table: A mapping from source symbols (difference values $s_i$) to their assigned Huffman codes.
*   **Huffman Table Structure:**
    *   The table handles $L$ possible source symbols. For 16-bit input, difference values range from $-66535$ to $65536$, so $L = 131,071$ [S1, unofficial].
    *   The $L_1$ most frequent symbols are assigned variable-length Huffman codes.
    *   The remaining $L - L_1$ symbols are assigned fixed-length codes [S1, unofficial].
    *   Default parameter: $L_1 = 256$ [S1, unofficial].

### Parameters
*   **Predictor Order:** 3 coefficients ($a_1, a_2, a_3$) corresponding to the X, Y, and Z predecessors [S1, unofficial].
*   **Scan Order:** Raster-scan order (lexicographic order of indices) to ensure causality [S1, unofficial].
*   **Truncation Parameter:** $L_1 = 256$ (number of symbols Huffman-coded) [S1, unofficial].

### Formulas
**Entropy:**
$$ H = - \sum_{i=1}^{k} p_i \log_2(p_i) $$
where $k = |\Sigma|$ is the size of the alphabet and $p_i$ is the probability of the $i$-th symbol [S1, unofficial].

**Prediction:**
$$ \hat{v}(x, y, z) = a_1 v_1(x, y, z) + a_2 v_2(x, y, z) + a_3 v_3(x, y, z) $$
where $v_1, v_2, v_3$ are mean-subtracted neighbors [S1, unofficial]:
$$
v_1(x, y, z) = \begin{cases} 
0 & \text{if } x = 0 \\
v(x-1, y, z) - \bar{v} & \text{otherwise}
\end{cases}
$$
$$
v_2(x, y, z) = \begin{cases} 
0 & \text{if } y = 0 \\
v(x, y-1, z) - \bar{v} & \text{otherwise}
\end{cases}
$$
$$
v_3(x, y, z) = \begin{cases} 
0 & \text{if } z = 0 \\
v(x, y, z-1) - \bar{v} & \text{otherwise}
\end{cases}
$$
[S1, unofficial]

**Residual:**
$$ d(x, y, z) = v(x, y, z) - \hat{v}(x, y, z) $$
[S1, unofficial]

**Covariance Estimation:**
$$ r(x, y, z) = \frac{1}{(X-2)(Y-2)(Z-2)} \sum_{x'=1}^{X-2} \sum_{y'=1}^{Y-2} \sum_{z'=1}^{Z-2} [v(x', y', z') - \bar{v}] [v(x'+x, y'+y, z'+z) - \bar{v}] $$
for lags $x, y, z \in \{-1, 0, 1\}$ [S1, unofficial].

**Predictor Coefficients (Yule-Walker):**
The coefficients $\mathbf{a} = [a_1, a_2, a_3]^T$ are found by solving:
$$
\begin{bmatrix}
r(0,0,0) & r(1,-1,0) & r(1,0,-1) \\
r(-1,1,0) & r(0,0,0) & r(0,1,-1) \\
r(-1,0,1) & r(0,-1,1) & r(0,0,0)
\end{bmatrix}
\begin{bmatrix}
a_1 \\ a_2 \\ a_3
\end{bmatrix}
=
\begin{bmatrix}
r(1,0,0) \\ r(0,1,0) \\ r(0,0,1)
\end{bmatrix}
$$
Note: The source provides this specific matrix layout in Eq (8), which contains index patterns distinct from the standard symmetric Yule-Walker form, but the implementation instruction is to solve this specific linear system using the estimated covariance values [S1, unofficial].

### Steps

#### Encoding
1.  **Estimate Mean:** Scan the volume to calculate the mean $\bar{v}$:
    $$ \bar{v} = \frac{1}{XYZ} \sum_{x=0}^{X-1} \sum_{y=0}^{Y-1} \sum_{z=0}^{Z-1} v(x, y, z) $$
    [S1, unofficial]
2.  **Estimate Covariance:** Scan the volume to estimate the covariance $r(x, y, z)$ for lags in $\{-1, 0, 1\}$ using the formula above. [S1, unofficial]
3.  **Calculate Coefficients:** Solve the linear system $A\mathbf{a} = \mathbf{b}$ defined by the covariance estimates to obtain $a_1, a_2, a_3$. [S1, unofficial]
4.  **Calculate Residuals (First Pass):** Scan the volume. For each voxel, compute the predicted value $\hat{v}(x, y, z)$ using the mean-subtracted neighbors and coefficients. Compute the difference $d(x, y, z) = v(x, y, z) - \hat{v}(x, y, z)$. Do **not** store these differences to save memory. [S1, unofficial]
5.  **Count Frequencies:** Count the occurrences of each difference value $s_i$ across the volume to estimate symbol probabilities $p_i$. [S1, unofficial]
6.  **Build Huffman Table:** Construct a truncated Huffman code table. Assign Huffman codes to the $L_1$ most frequent symbols and fixed-length codes to the rest. [S1, unofficial]
7.  **Encode (Second Pass):** Scan the volume again. Recompute $d(x, y, z)$ for each voxel and encode it using the Huffman table. Write the bits to the output stream. [S1, unofficial]
8.  **Write Header:** Prepend the compressed stream with $\bar{v}$, $a_1, a_2, a_3$, and the Huffman code table. [S1, unofficial]

#### Decoding
1.  **Read Header:** Read $\bar{v}$, $a_1, a_2, a_3$, and the Huffman code table from the compressed file. [S1, unofficial]
2.  **Decode Residuals:** Read the next Huffman code from the stream. Look up the corresponding difference value $d(x, y, z)$ in the Huffman table. [S1, unofficial]
3.  **Reconstruct Voxel:** Calculate the predicted value $\hat{v}(x, y, z)$ using the same causal predictor logic (using previously reconstructed neighbors). Reconstruct the voxel:
    $$ v(x, y, z) = \hat{v}(x, y, z) + d(x, y, z) $$
    [S1, unofficial]
4.  **Repeat:** Continue until the volume is fully reconstructed. [S1, unofficial]

### Edge Cases and Pitfalls
*   **Causality:** The predictor must strictly use only previously processed voxels ($x-1, y, z$), ($x, y-1, z$), and ($x, y, z-1$) to ensure the decoder can generate identical predictions [S1, unofficial].
*   **Non-stationarity:** The optimal predictor assumes wide-sense stationarity. Real volume data is not stationary, making global statistics suboptimal. The algorithm does not handle this locally; future improvements involve octree-based local predictors [S1, unofficial].
*   **Memory vs. Speed:** The algorithm scans the volume four times (2 for stats, 1 for residuals, 1 for encoding). Residuals are not stored to prevent excessive memory costs, necessitating the fourth scan [S1, unofficial].
*   **Precision:** The covariance calculation involves sums over the volume. Using single precision for covariance estimation may reduce mathematical precision compared to double precision, though the source notes greater precision is obtained by separating the mean and variance scans [S1, unofficial].

## Operating characteristics
*   **Compression Ratio:** Achieves approximately 50% compression (reducing size by half) on a set of volume data files [S1, unofficial]. Specifically, on `3dhead.vox`, it achieves 48.5% compression compared to 36.1% for gzip and 33.8% for zip [S1, unofficial].
*   **Performance:** On an HP 9000 Series 735, compression of `3dhead.vox` took 4.7 minutes, and decompression took 1.4 minutes [S1, unofficial].
*   **Complexity:** The calculation of the optimal predictor takes only about 6% of the total compression time [S1, unofficial]. The majority of time is spent in the scanning and Huffman encoding steps.
*   **Strengths:** Removes spatial redundancy effectively, outperforming generic statistical compressors (gzip, zip, compress, pack) on volume data [S1, unofficial]. The optimal predictor automatically compensates for non-isotropic sampling [S1, unofficial].
*   **Limitations:** Assumes wide-sense stationarity, which may not hold for all datasets. The 4-pass nature is I/O intensive. The fixed $L_1=256$ truncation parameter is arbitrary [S1, unofficial].

## Background
*   **Origin:** Introduced by James Edwin Fowler and Roni Yagel in January 1995 at the Proceedings of the 1994 Symposium on Volume Visualization [S1, unofficial].
*   **Context:** Developed to address the large storage requirements of volume data in biomedical and scientific applications where lossless compression is mandatory [S1, unofficial].
*   **Comparison:** It combines Differential Pulse-Code Modulation (DPCM) and Huffman coding. It is distinct from simple delta encoding by using an optimal linear predictor derived from the data's covariance structure [S1, unofficial].
