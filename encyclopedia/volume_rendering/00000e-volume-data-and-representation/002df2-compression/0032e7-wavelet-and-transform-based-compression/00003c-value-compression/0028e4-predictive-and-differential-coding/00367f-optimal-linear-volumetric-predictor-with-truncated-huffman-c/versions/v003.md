# Optimal Linear Volumetric Predictor with Truncated Huffman Coding

Also called: DPCM with Huffman Coding, DPCM-Huffman, Predictive Huffman Coding for Volumes, Volume DPCM with Huffman Coding, compvox algorithm, volumetric DPCM with optimal coefficients, 差值编码与霍夫曼编码结合

## Overview
This method is a lossless compression algorithm for 3D volume data that exploits spatial coherence by predicting voxel values from previously encoded neighbors and encoding the difference (residual) using a truncated Huffman code [S1, unofficial]. It achieves approximately 50% compression ratios on medical volume datasets, outperforming generic compressors like gzip and zip by explicitly removing spatial redundancy rather than just statistical redundancy [S1, unofficial]. It builds on [Predictive and Differential Coding](4393-predictive-and-differential-coding.md) by using an optimal linear predictor derived from the data's global statistics and a truncated Huffman coder to handle the large dynamic range of residuals [S1, unofficial].

## How it works
**Inputs:** A 3D volume array $v(x, y, z)$ of size $X \times Y \times Z$, where voxels are typically 16-bit integers [S1, unofficial].
**Outputs:** A compressed bitstream containing the encoded residuals, preceded by a header storing the mean, predictor coefficients, and Huffman table [S1, unofficial].

**Data Structures:**
1.  **Volume Data:** Array $v$ of integers.
2.  **Covariance Matrix:** $3 \times 3$ symmetric matrix $A$ and vector $b$ used to solve for predictor coefficients.
3.  **Huffman Table:** A mapping from difference values (symbols) to variable-length bit codes. The table stores the symbol value and its corresponding code.

**Parameters:**
*   **Predictor Order:** 3 coefficients ($a_1, a_2, a_3$) using the 6-neighborhood (face-sharing neighbors) [S1, unofficial].
*   **Truncation Parameter ($L_1$):** The number of most frequent symbols to be Huffman coded. Default $L_1 = 256$ [S1, unofficial].
*   **Scan Order:** Raster-scan order (increasing $x$, then $y$, then $z$) to ensure causality [S1, unofficial].

**Algorithm Steps:**

1.  **Estimate Mean:** Scan the entire volume to calculate the mean voxel value $\bar{v}$ [S1, unofficial]:
    $$ \bar{v} = \frac{1}{XYZ} \sum_{x=0}^{X-1} \sum_{y=0}^{Y-1} \sum_{z=0}^{Z-1} v(x, y, z) $$

2.  **Estimate Covariance:** Scan the volume to estimate the covariance $r(x, y, z)$ for lags in $\{-1, 0, 1\}$ [S1, unofficial]:
    $$ r(x, y, z) = \frac{1}{(X-2)(Y-2)(Z-2)} \sum_{x'=1}^{X-2} \sum_{y'=1}^{Y-2} \sum_{z'=1}^{Z-2} [v(x', y', z') - \bar{v}] [v(x'+x, y'+y, z'+z) - \bar{v}] $$
    *Note: The source specifies this normalization factor [S1, unofficial].*

3.  **Calculate Predictor Coefficients:** Solve the linear system $A \mathbf{a} = \mathbf{b}$ for coefficients $\mathbf{a} = [a_1, a_2, a_3]^T$ [S1, unofficial]. The matrix $A$ and vector $\mathbf{b}$ are constructed from the estimated covariances:
    $$
    \begin{bmatrix}
    r(0,0,0) & r(1,-1,0) & r(1,0,-1) \\
    r(-1,1,0) & r(0,0,0) & r(0,1,-1) \\
    r(-1,0,1) & r(0,-1,1) & r(0,0,0)
    \end{bmatrix}
    \begin{bmatrix}
    a_1 \\ a_2 \\ a_3
    \end{bmatrix}
    =
    \begin{bmatrix}
    r(1,0,0) \\ r(0,1,0) \\ r(0,0,1)
    \end{bmatrix}
    $$
    *Note: The source provides this specific matrix layout in Eq (8), noting it may contain index typos compared to standard Yule-Walker derivations, but instructs to solve this specific system [S1, unofficial].*

4.  **Calculate Residuals (First Pass):** Scan the volume to compute difference values $d(x, y, z)$ [S1, unofficial]. The prediction $\hat{v}(x, y, z)$ uses mean-subtracted neighbors to ensure orthogonality:
    $$ \hat{v}(x, y, z) = a_1 v_1(x, y, z) + a_2 v_2(x, y, z) + a_3 v_3(x, y, z) $$
    Where the neighbor terms $v_i$ are defined as:
    $$
    v_1(x, y, z) = \begin{cases} 0 & \text{if } x=0 \\ v(x-1, y, z) - \bar{v} & \text{otherwise} \end{cases}
    $$
    $$
    v_2(x, y, z) = \begin{cases} 0 & \text{if } y=0 \\ v(x, y-1, z) - \bar{v} & \text{otherwise} \end{cases}
    $$
    $$
    v_3(x, y, z) = \begin{cases} 0 & \text{if } z=0 \\ v(x, y, z-1) - \bar{v} & \text{otherwise} \end{cases}
    $$
    The residual is $d(x, y, z) = v(x, y, z) - \hat{v}(x, y, z)$ [S1, unofficial].

5.  **Count Symbol Frequencies:** Count the occurrences of each unique difference value $s_i$ across the volume to estimate symbol probabilities $p_i$ [S1, unofficial].

6.  **Build Huffman Table:** Construct a truncated Huffman code table [S1, unofficial]. The $L_1$ most frequent symbols are assigned Huffman codes based on $p_i$. The remaining $L - L_1$ symbols (where $L$ is the total number of possible difference values) are assigned fixed-length codes. For 16-bit voxels, $L = 131,071$ (range $-66,535$ to $65,536$) [S1, unofficial].

7.  **Encode (Second Pass):** Scan the volume again. For each voxel, calculate $d(x, y, z)$ using the predictor (Step 4) and encode it using the Huffman table from Step 6. Write the bits to the output stream. Do not store the difference values to save memory [S1, unofficial].

**Decompression:**
1.  Read the header: mean $\bar{v}$, coefficients $a_1, a_2, a_3$, and the Huffman table [S1, unofficial].
2.  For each voxel in raster-scan order:
    a. Read the next Huffman code from the stream and look up the difference value $d(x, y, z)$ [S1, unofficial].
    b. Calculate the predicted value $\hat{v}(x, y, z)$ using the same causal predictor logic as Step 4 (using previously reconstructed voxels) [S1, unofficial].
    c. Reconstruct the voxel: $v(x, y, z) = \hat{v}(x, y, z) + d(x, y, z)$ [S1, unofficial].

**Pseudocode:**

```python
def compress_volume(volume: Array[int], X: int, Y: int, Z: int, L1: int = 256) -> bytes:
    # Step 1: Estimate Mean
    total_sum = 0
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                total_sum += volume[x, y, z]
    mean_v = total_sum / (X * Y * Z)

    # Step 2: Estimate Covariance
    # Covariance r(x, y, z) for x,y,z in {-1, 0, 1}
    # Normalization factor
    norm = 1.0 / ((X - 2) * (Y - 2) * (Z - 2))
    cov = {}
    for dx in [-1, 0, 1]:
        for dy in [-1, 0, 1]:
            for dz in [-1, 0, 1]:
                sum_val = 0
                for x_prime in range(1, X - 1):
                    for y_prime in range(1, Y - 1):
                        for z_prime in range(1, Z - 1):
                            v_curr = volume[x_prime, y_prime, z_prime] - mean_v
                            v_lag = volume[x_prime + dx, y_prime + dy, z_prime + dz] - mean_v
                            sum_val += v_curr * v_lag
                cov[(dx, dy, dz)] = norm * sum_val

    # Step 3: Solve for Predictor Coefficients
    # Matrix A and Vector b as defined in Eq (8)
    # A = [[r(0,0,0), r(1,-1,0), r(1,0,-1)],
    #      [r(-1,1,0), r(0,0,0), r(0,1,-1)],
    #      [r(-1,0,1), r(0,-1,1), r(0,0,0)]]
    # b = [r(1,0,0), r(0,1,0), r(0,0,1)]
    
    r000 = cov[(0, 0, 0)]
    r1m10 = cov[(1, -1, 0)]
    r10m1 = cov[(1, 0, -1)]
    rm110 = cov[(-1, 1, 0)]
    r01m1 = cov[(0, 1, -1)]
    rm101 = cov[(-1, 0, 1)]
    r0m11 = cov[(0, -1, 1)]
    
    r100 = cov[(1, 0, 0)]
    r010 = cov[(0, 1, 0)]
    r001 = cov[(0, 0, 1)]

    # Solve linear system A * a = b
    # Using a standard linear solver (e.g., Gaussian elimination)
    A = [
        [r000, r1m10, r10m1],
        [rm110, r000, r01m1],
        [rm101, r0m11, r000]
    ]
    b = [r100, r010, r001]
    coeffs = solve_linear_system(A, b)
    a1, a2, a3 = coeffs

    # Step 4 & 5: Calculate Residuals and Count Frequencies
    # We do not store residuals to save memory, but we need frequencies for Huffman
    freq_map = {}
    
    # Helper to get neighbor value with mean subtraction
    def get_neighbor_val(x, y, z, dx, dy, dz):
        nx, ny, nz = x + dx, y + dy, z + dz
        if nx < 0 or ny < 0 or nz < 0:
            return 0
        return volume[nx, ny, nz] - mean_v

    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                # Prediction
                v1 = get_neighbor_val(x, y, z, -1, 0, 0)
                v2 = get_neighbor_val(x, y, z, 0, -1, 0)
                v3 = get_neighbor_val(x, y, z, 0, 0, -1)
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                residual = volume[x, y, z] - pred
                
                # Count frequency
                freq_map[residual] = freq_map.get(residual, 0) + 1

    # Step 6: Build Truncated Huffman Table
    # Sort symbols by frequency descending
    sorted_symbols = sorted(freq_map.keys(), key=lambda s: freq_map[s], reverse=True)
    
    huffman_table = {}
    # Assign Huffman codes to top L1 symbols
    # Note: Standard Huffman construction is implied but not detailed in source.
    # We assume a function build_huffman_codes exists that returns a dict {symbol: bitstring}
    # for the given probabilities.
    # The source states: "Determine a truncated Huffman code table using the pi probabilities."
    # "The first L1 symbols are Huffman coded. The remaining L-L1 symbols are assigned fixed-length codes."
    
    top_symbols = sorted_symbols[:L1]
    # Create probability distribution for top symbols
    total_freq_top = sum(freq_map[s] for s in top_symbols)
    probs_top = {s: freq_map[s] / total_freq_top for s in top_symbols}
    
    huffman_codes = build_huffman_codes(probs_top) # [G] Standard Huffman algorithm
    for s in top_symbols:
        huffman_table[s] = huffman_codes[s]
        
    # Assign fixed-length codes to remaining symbols
    # L = 131071 for 16-bit voxels. 
    # Number of remaining symbols
    remaining_symbols = sorted_symbols[L1:]
    fixed_len_bits = ceil(log2(len(remaining_symbols))) # [G] To ensure unique codes
    for i, s in enumerate(remaining_symbols):
        huffman_table[s] = format(i, f'0{fixed_len_bits}b')

    # Step 7: Encode
    output_bits = []
    
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                v1 = get_neighbor_val(x, y, z, -1, 0, 0)
                v2 = get_neighbor_val(x, y, z, 0, -1, 0)
                v3 = get_neighbor_val(x, y, z, 0, 0, -1)
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                residual = volume[x, y, z] - pred
                
                code = huffman_table[residual]
                output_bits.append(code)
                
    return pack_bits(output_bits)

def decompress_volume(compressed_data: bytes, X: int, Y: int, Z: int, header: dict) -> Array[int]:
    mean_v = header['mean']
    a1, a2, a3 = header['coeffs']
    huffman_table = header['huffman_table'] # Map: bitstring -> symbol
    
    # Reverse Huffman table for decoding: Map: symbol -> bitstring is not needed, 
    # we need Map: bitstring -> symbol.
    # The source says "look up the difference value... in the Huffman table for that code"
    # So we assume the stored table is indexed by code or we build a reverse map.
    # Let's assume huffman_table_dec is {code: symbol}
    huffman_table_dec = {v: k for k, v in huffman_table.items()}

    volume = zeros((X, Y, Z))
    bit_stream = unpack_bits(compressed_data)
    bit_idx = 0
    
    # Helper to get neighbor value with mean subtraction (using reconstructed volume)
    def get_neighbor_val(x, y, z, dx, dy, dz):
        nx, ny, nz = x + dx, y + dy, z + dz
        if nx < 0 or ny < 0 or nz < 0:
            return 0
        return volume[nx, ny, nz] - mean_v

    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                # Read code
                # Note: Huffman codes are variable length. 
                # We must read bits until we match a code in the table.
                # This requires a prefix tree or a lookup map for all prefixes.
                # For simplicity in pseudocode, we assume a function read_huffman_code
                # that advances bit_idx and returns the symbol.
                residual = read_huffman_code(bit_stream, bit_idx, huffman_table_dec)
                bit_idx = read_huffman_code.bit_idx # Update index
                
                # Predict
                v1 = get_neighbor_val(x, y, z, -1, 0, 0)
                v2 = get_neighbor_val(x, y, z, 0, -1, 0)
                v3 = get_neighbor_val(x, y, z, 0, 0, -1)
                
                pred = a1 * v1 + a2 * v2 + a3 * v3
                volume[x, y, z] = pred + residual
                
    return volume
```

## Subtopics

### Simple Predictive Huffman Coding
Uses fixed predictor coefficients (e.g., $a_1=a_2=a_3=1/3$) instead of calculating optimal coefficients. It is faster to set up but less effective for non-isotropic voxels. Choose when computational resources for covariance estimation are limited or voxels are known to be cubic [S1, unofficial].

### Local Predictive Coding
Divides the volume into an octree or blocks and calculates local predictor coefficients. This addresses the non-stationarity of real volume data, which the global optimal predictor assumes [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The algorithm scans the volume four times. Two scans are for statistics (mean and covariance), one for calculating residuals (not stored), and one for encoding. The covariance calculation is $O(XYZ)$ but with a large constant factor due to the nested loops for lags. The optimal predictor calculation takes approximately 6% of the total compression time [S1, unofficial].
*   **Memory Complexity:** Low. The algorithm does not store the difference values, requiring only the original volume and the covariance/mean statistics in memory during the first two passes. This prevents excessive memory costs for large volumes [S1, unofficial].
*   **Performance:** Achieves approximately 50% compression ratio (or ~50.8% average on test datasets) for medical volume data [S1, unofficial]. On the `3dhead.vox` dataset (256x256x109, 13.6 MB), it achieved 48.5% compression, outperforming gzip (36.1%) and zip (33.8%) [S1, unofficial]. Decompression is significantly faster than compression (1.4 min vs 4.7 min on HP 9000 Series 735) [S1, unofficial].
*   **Strengths:** High compression ratio for volumetric data by removing spatial redundancy; lossless; efficient memory usage during encoding.
*   **Limitations:** Assumes wide-sense stationarity, which may not hold for all volume data, making global coefficients suboptimal; requires multiple passes over the data; causal predictor limits prediction accuracy compared to non-causal methods.

## Background
The method was introduced by James Edwin Fowler and Roni Yagel in January 1995 at the Proceedings of the 1994 Symposium on Volume Visualization [S1, unofficial]. It was designed to address the large storage requirements of volumetric data in biomedical and scientific applications where lossless compression is mandatory [S1, unofficial]. The algorithm combines Differential Pulse-Code Modulation (DPCM) with Huffman coding, leveraging the spatial coherence of volume data [S1, unofficial].
