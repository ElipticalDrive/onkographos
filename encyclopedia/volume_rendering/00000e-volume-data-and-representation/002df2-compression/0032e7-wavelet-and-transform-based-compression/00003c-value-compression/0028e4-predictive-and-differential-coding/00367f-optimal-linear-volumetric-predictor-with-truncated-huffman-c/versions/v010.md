# Optimal Linear Volumetric Predictor with Truncated Huffman Coding

Also called: DPCM with Huffman Coding, DPCM-Huffman, Predictive Huffman Coding for Volumes, Volume DPCM with Huffman Coding, compvox algorithm, volumetric DPCM with optimal coefficients, 差值编码与霍夫曼编码结合

## Overview
This method is a lossless compression algorithm for 3D volume data that removes spatial redundancy by predicting voxel values from previously encoded neighbors and encoding the resulting residuals using a truncated Huffman code [S1, unofficial]. It differs from generic compressors (e.g., gzip, zip) by explicitly modeling spatial coherence via a causal linear predictor, and from fixed-coefficient predictors by deriving optimal coefficients from the data's global statistics [S1, unofficial]. It achieves approximately 50% compression ratios on biomedical volume datasets, outperforming standard general-purpose tools [S1, unofficial].

## How it works
### Inputs and Outputs
*   **Input:** A 3D volume array $v(x, y, z)$ of size $X \times Y \times Z$. The source uses 16-bit integer voxels [S1, unofficial].
*   **Output:** A compressed bitstream containing the Huffman-encoded residuals, preceded by a header storing the mean, predictor coefficients, and the Huffman code table [S1, unofficial].

### Data Structures
1.  **Volume Data:** Stored as a 3D array or flattened 1D array accessed in raster-scan order [S1, unofficial].
2.  **Covariance Matrix ($A$):** A $3 \times 3$ symmetric matrix used to solve for predictor coefficients. Elements are derived from estimated covariances $r(\cdot)$ [S1, unofficial].
3.  **Covariance Vector ($b$):** A $3 \times 1$ vector containing cross-covariances between the current voxel and its neighbors [S1, unofficial].
4.  **Huffman Table:** A mapping from difference values (symbols) to variable-length bit codes. It consists of two parts:
    *   **Huffman-coded symbols:** The $L_1$ most frequent symbols [S1, unofficial].
    *   **Fixed-length codes:** The remaining $L - L_1$ symbols [S1, unofficial].
5.  **Header:** Stores the estimated mean $\bar{v}$, coefficients $a_1, a_2, a_3$, and the Huffman table structure [S1, unofficial].

### Parameters
*   **$L_1$:** The number of most frequent symbols to Huffman code. Default: $L_1 = 256$ [S1, unofficial].
*   **$L$:** Total number of possible difference values. For 16-bit input, $L = 131,071$ (range $-66,535$ to $65,536$) [S1, unofficial].
*   **Neighbor Order:** Raster-scan order $(x, y, z)$ ensuring causality [S1, unofficial].
*   **Predictor Order:** Uses 3 coefficients corresponding to the 6-neighborhood (face-sharing neighbors only) [S1, unofficial].

### Algorithm Steps

#### 1. Statistics Estimation
The algorithm assumes wide-sense stationarity to derive optimal coefficients [S1, unofficial].

**Step 1: Estimate Mean**
Scan the entire volume to calculate the mean $\bar{v}$:
$$ \bar{v} = \frac{1}{XYZ} \sum_{x=0}^{X-1} \sum_{y=0}^{Y-1} \sum_{z=0}^{Z-1} v(x, y, z) $$
[S1, unofficial]

**Step 2: Estimate Covariance**
Scan the volume to estimate the covariance $r(x, y, z)$ for lags in $\{-1, 0, 1\}$:
$$ r(x, y, z) = \frac{1}{(X-2)(Y-2)(Z-2)} \sum_{x'=1}^{X-2} \sum_{y'=1}^{Y-2} \sum_{z'=1}^{Z-2} [v(x', y', z') - \bar{v}] [v(x'+x, y'+y, z'+z) - \bar{v}] $$
[S1, unofficial]

**Step 3: Solve for Predictor Coefficients**
Solve the linear system $A \mathbf{a} = \mathbf{b}$ for $\mathbf{a} = [a_1, a_2, a_3]^T$. The matrix $A$ and vector $\mathbf{b}$ are constructed from the estimated covariances [S1, unofficial]:
$$
\begin{bmatrix}
r(0,0,0) & r(1,-1,0) & r(1,0,-1) \\
r(-1,1,0) & r(0,0,0) & r(0,1,-1) \\
r(-1,0,1) & r(0,-1,1) & r(0,0,0)
\end{bmatrix}
\begin{bmatrix}
a_1 \\
a_2 \\
a_3
\end{bmatrix}
=
\begin{bmatrix}
r(1,0,0) \\
r(0,1,0) \\
r(0,0,1)
\end{bmatrix}
$$
Note: The indices in the matrix $A$ follow the specific layout provided in the source derivation [S1, unofficial].

#### 2. Residual Calculation and Encoding
The volume is scanned again to compute residuals and encode them. To save memory, residuals are not stored; the volume is scanned a fourth time for final encoding [S1, unofficial].

**Step 4: Calculate Residuals (First Pass for Encoding)**
For each voxel $(x, y, z)$, compute the predicted value $\hat{v}(x, y, z)$ and residual $d(x, y, z)$:
$$ \hat{v}(x, y, z) = a_1 v_1(x, y, z) + a_2 v_2(x, y, z) + a_3 v_3(x, y, z) $$
$$ d(x, y, z) = v(x, y, z) - \hat{v}(x, y, z) $$
The neighbor values $v_i$ are mean-subtracted and zeroed at boundaries to ensure orthogonality [S1, unofficial]:
$$
v_1(x, y, z) = \begin{cases} 
0 & \text{if } x = 0 \\
v(x-1, y, z) - \bar{v} & \text{otherwise}
\end{cases}
$$
$$
v_2(x, y, z) = \begin{cases} 
0 & \text{if } y = 0 \\
v(x, y-1, z) - \bar{v} & \text{otherwise}
\end{cases}
$$
$$
v_3(x, y, z) = \begin{cases} 
0 & \text{if } z = 0 \\
v(x, y, z-1) - \bar{v} & \text{otherwise}
\end{cases}
$$
[S1, unofficial]

**Step 5: Count Symbol Frequencies**
Count the occurrences of each difference value $d(x, y, z) = s_i$ across the volume. These counts estimate the symbol probabilities $p_i$ [S1, unofficial].

**Step 6: Build Truncated Huffman Table**
Construct a Huffman code table using probabilities $p_i$. The $L_1$ most frequent symbols are assigned Huffman codes. The remaining $L - L_1$ symbols are assigned fixed-length codes [S1, unofficial].

**Step 7: Encode**
Scan the volume a fourth time. For each voxel, calculate $d(x, y, z)$ using the predictor (identical to Step 4) and encode it using the Huffman table from Step 6. Write the bits to the output stream. Do not store the difference values [S1, unofficial].

#### 3. Decompression
**Step 1:** Read $\bar{v}$, $a_1, a_2, a_3$, and the Huffman table from the header [S1, unofficial].
**Step 2:** For each voxel in raster-scan order:
1.  Read the next Huffman code from the stream and look up the residual $d(x, y, z)$ [S1, unofficial].
2.  Calculate the predicted value $\hat{v}(x, y, z)$ using the same causal neighbor logic and coefficients [S1, unofficial].
3.  Reconstruct the voxel: $v(x, y, z) = \hat{v}(x, y, z) + d(x, y, z)$ [S1, unofficial].

### Pseudocode

```python
import numpy as np

def compress_volume(volume: np.ndarray) -> bytes:
    """
    Compress a 3D volume using Optimal Linear Predictor + Truncated Huffman.
    volume: np.ndarray of shape (X, Y, Z), dtype int16.
    Returns: bytes containing header and compressed data.
    """
    X, Y, Z = volume.shape
    
    # Step 1: Estimate Mean
    mean_v = np.mean(volume)
    
    # Step 2: Estimate Covariance
    # Center the volume for covariance calculation
    centered = volume.astype(np.float64) - mean_v
    
    # Calculate covariances for lags in {-1, 0, 1}
    # We need r(0,0,0), r(1,-1,0), r(1,0,-1), r(-1,1,0), r(0,1,-1), r(-1,0,1), r(0,-1,1)
    # and r(1,0,0), r(0,1,0), r(0,0,1)
    
    # Helper to compute covariance for specific lag (dx, dy, dz)
    # r(dx, dy, dz) = E[(v - mean)(v+dx, dy+dy, dz+dz)]
    # Using the formula from source: sum over valid interior points
    # The source sums x'=1..X-2, y'=1..Y-2, z'=1..Z-2
    # This corresponds to comparing v(x',y',z') with v(x'+dx, y'+dy, z'+dz)
    
    def get_cov(dx, dy, dz):
        # Indices for base voxel
        x_start, x_end = 1, X - 2
        y_start, y_end = 1, Y - 2
        z_start, z_end = 1, Z - 2
        
        # Indices for neighbor voxel
        x2_start, x2_end = 1 + dx, X - 2 + dx
        y2_start, y2_end = 1 + dy, Y - 2 + dy
        z2_start, z2_end = 1 + dz, Z - 2 + dz
        
        # Slice the centered volume
        # Base: centered[x_start:x_end+1, y_start:y_end+1, z_start:z_end+1]
        # Neighbor: centered[x2_start:x2_end+1, y2_start:y2_end+1, z2_start:z2_end+1]
        
        base_slice = centered[x_start:x_end+1, y_start:y_end+1, z_start:z_end+1]
        neighbor_slice = centered[x2_start:x2_end+1, y2_start:y2_end+1, z2_start:z2_end+1]
        
        count = (X - 2) * (Y - 2) * (Z - 2)
        if count == 0:
            return 0.0
            
        return np.sum(base_slice * neighbor_slice) / count

    r_000 = get_cov(0, 0, 0)
    r_1_10 = get_cov(1, -1, 0)
    r_10_1 = get_cov(1, 0, -1)
    r_100 = get_cov(1, 0, 0)
    r_010 = get_cov(0, 1, 0)
    r_001 = get_cov(0, 0, 1)
    
    # Note: Covariance is symmetric for real signals, so r(-1,1,0) = r(1,-1,0) etc.
    # Matrix A from source:
    # [ r(0,0,0)   r(1,-1,0)   r(1,0,-1) ]
    # [ r(-1,1,0)  r(0,0,0)    r(0,1,-1) ]
    # [ r(-1,0,1)  r(0,-1,1)   r(0,0,0)  ]
    
    A = np.array([
        [r_000, r_1_10, r_10_1],
        [r_1_10, r_000, get_cov(0, 1, -1)], # r(0,1,-1)
        [r_10_1, get_cov(0, -1, 1), r_000]  # r(-1,0,1) = r(1,0,-1)? No, r(-1,0,1) is lag -1,0,1
    ])
    
    # Correction: The source matrix indices are specific.
    # Row 2, Col 3 is r(0,1,-1).
    # Row 3, Col 2 is r(0,-1,1).
    # Row 3, Col 1 is r(-1,0,1).
    
    r_01_1 = get_cov(0, 1, -1)
    r_0_11 = get_cov(0, -1, 1)
    r_10_1 = get_cov(1, 0, -1) # Already computed
    r_1_10 = get_cov(1, -1, 0) # Already computed
    
    # Re-building A strictly per source Eq (8)
    # A[0,0]=r(0,0,0), A[0,1]=r(1,-1,0), A[0,2]=r(1,0,-1)
    # A[1,0]=r(-1,1,0), A[1,1]=r(0,0,0), A[1,2]=r(0,1,-1)
    # A[2,0]=r(-1,0,1), A[2,1]=r(0,-1,1), A[2,2]=r(0,0,0)
    
    A = np.array([
        [r_000, r_1_10, r_10_1],
        [r_1_10, r_000, r_01_1],
        [r_10_1, r_0_11, r_000]
    ])
    
    b = np.array([r_100, r_010, r_001])
    
    # Step 3: Solve for coefficients
    a = np.linalg.solve(A, b)
    a1, a2, a3 = a
    
    # Step 4 & 5: Calculate residuals and count frequencies
    # We need to scan the volume to compute d(x,y,z)
    # To save memory, we can compute d, count, and then discard d.
    # However, we need the full list of d to build the Huffman table.
    # Given L=131071, we can use a histogram array.
    
    # Difference range: -66535 to 65536. Offset by 66535 to index 0..131070
    OFFSET = 66535
    HIST_SIZE = 131071
    hist = np.zeros(HIST_SIZE, dtype=np.int64)
    
    # Pre-calculate mean-subtracted volume for speed
    v_centered = volume.astype(np.float64) - mean_v
    
    # We need the original volume for reconstruction logic, but prediction uses centered neighbors
    # d = v - (a1*v1 + a2*v2 + a3*v3)
    # v1, v2, v3 are centered neighbors (or 0 at boundary)
    
    # Vectorized calculation might be complex due to boundary conditions.
    # We will iterate.
    
    # To optimize, we can compute d in place or store it if memory allows.
    # The source says "difference values are not saved", implying we re-scan.
    # But for Huffman table construction, we MUST see them.
    # So we either store them (memory heavy) or scan twice (slow).
    # The source says: "The last two scans... calculate the same difference values... 
    # to prevent excessive memory costs, these difference values are not saved, 
    # making a fourth scan necessary."
    # This implies: Scan 3 computes d, counts hist, discards d. Scan 4 computes d, encodes.
    
    # Implementation for Scan 3: Compute d and update histogram
    # We assume volume is small enough to hold in memory for the loop, 
    # but we don't store the array of d.
    
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                # Get centered neighbors
                v1 = v_centered[x-1, y, z] if x > 0 else 0.0
                v2 = v_centered[x, y-1, z] if y > 0 else 0.0
                v3 = v_centered[x, y, z-1] if z > 0 else 0.0
                
                pred_centered = a1 * v1 + a2 * v2 + a3 * v3
                
                # d = v - pred
                # Note: pred is in centered space? 
                # Source: v1 = v(x-1)-v. pred = a1*v1...
                # d = v - pred.
                # If v is original, pred is centered.
                # d = v_original - (a1*(v_x-1-v_mean) + ...)
                # This d is not centered.
                
                v_orig = volume[x, y, z]
                d = v_orig - pred_centered
                
                # Map to histogram index
                idx = int(round(d)) + OFFSET
                if 0 <= idx < HIST_SIZE:
                    hist[idx] += 1

    # Step 6: Build Truncated Huffman Table
    # L1 = 256 most frequent symbols
    L1 = 256
    # Get indices of top L1 frequencies
    # hist contains counts. We need the symbol values (idx - OFFSET)
    
    # Find top L1 indices
    # Using argsort is O(N log N) where N=131071, which is fast.
    sorted_indices = np.argsort(hist)[::-1]
    
    top_symbols = sorted_indices[:L1]
    other_symbols = sorted_indices[L1:]
    
    # Build Huffman codes for top_symbols
    # Standard Huffman coding algorithm
    symbol_to_code = {}
    
    # Create frequency map for top symbols
    top_freqs = {sym: hist[sym] for sym in top_symbols}
    
    # Huffman construction
    import heapq
    heap = [[freq, [sym, ""]] for sym, freq in top_freqs.items()]
    heapq.heapify(heap)
    
    while len(heap) > 1:
        lo = heapq.heappop(heap)
        hi = heapq.heappop(heap)
        for pair in lo[1:]:
            pair[1] = '0' + pair[1]
        for pair in hi[1:]:
            pair[1] = '1' + pair[1]
        heapq.heappush(heap, [lo[0] + hi[0]] + lo[1:] + hi[1:])
        
    root = heap[0]
    for sym, code in root[1:]:
        symbol_to_code[sym] = code
        
    # Assign fixed-length codes to remaining symbols
    # L - L1 symbols. 
    # Code length needed: ceil(log2(L - L1))
    remaining_count = len(other_symbols)
    if remaining_count > 0:
        fixed_len = int(np.ceil(np.log2(remaining_count)))
        for i, sym in enumerate(other_symbols):
            symbol_to_code[sym] = format(i, f'0{fixed_len}b')
            
    # Step 7: Encode
    # Scan volume again, compute d, write bits
    
    output_bits = []
    
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                v1 = v_centered[x-1, y, z] if x > 0 else 0.0
                v2 = v_centered[x, y-1, z] if y > 0 else 0.0
                v3 = v_centered[x, y, z-1] if z > 0 else 0.0
                
                pred_centered = a1 * v1 + a2 * v2 + a3 * v3
                v_orig = volume[x, y, z]
                d = v_orig - pred_centered
                idx = int(round(d)) + OFFSET
                
                code = symbol_to_code[idx]
                output_bits.append(code)
                
    # Convert bits to bytes
    bit_string = "".join(output_bits)
    # Pad to byte boundary
    if len(bit_string) % 8 != 0:
        bit_string += '0' * (8 - len(bit_string) % 8)
        
    compressed_data = bytes(int(bit_string[i:i+8], 2) for i in range(0, len(bit_string), 8))
    
    # Header: mean, a1, a2, a3, Huffman Table
    # Huffman Table: List of (symbol, code)
    # We can serialize this as a list of tuples or a dict.
    header = {
        'mean': mean_v,
        'a1': a1,
        'a2': a2,
        'a3': a3,
        'huffman_table': symbol_to_code
    }
    
    # Return header and data (serialization logic omitted for brevity)
    return header, compressed_data

def decompress_volume(header: dict, compressed_data: bytes, X: int, Y: int, Z: int) -> np.ndarray:
    """
    Decompress volume.
    """
    mean_v = header['mean']
    a1, a2, a3 = header['a1'], header['a2'], header['a3']
    symbol_to_code = header['huffman_table']
    
    # Inverse map for decoding
    code_to_symbol = {code: sym for sym, code in symbol_to_code.items()}
    
    # Convert bytes to bit string
    bit_string = "".join(format(byte, '08b') for byte in compressed_data)
    
    volume = np.zeros((X, Y, Z), dtype=np.int16)
    
    # We need to reconstruct the centered volume to get neighbors for prediction
    # But we only have original volume.
    # Prediction uses: v1 = v(x-1) - mean.
    # So we need the original reconstructed v(x-1) to compute v1.
    
    v_centered = np.zeros((X, Y, Z), dtype=np.float64)
    
    bit_idx = 0
    
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                # Read code
                # Find matching code in symbol_to_code
                # Since codes are variable length, we must match greedily or use a tree.
                # For simplicity, assume we can look up. In practice, use a Huffman tree.
                # Here, we iterate to find the code.
                
                code = None
                for c, s in symbol_to_code.items():
                    if bit_string[bit_idx:bit_idx+len(c)] == c:
                        code = c
                        break
                bit_idx += len(code)
                
                sym = code_to_symbol[code]
                d = sym - OFFSET
                
                # Calculate prediction
                v1 = v_centered[x-1, y, z] if x > 0 else 0.0
                v2 = v_centered[x, y-1, z] if y > 0 else 0.0
                v3 = v_centered[x, y, z-1] if z > 0 else 0.0
                
                pred_centered = a1 * v1 + a2 * v2 + a3 * v3
                
                # Reconstruct original v
                v_orig = pred_centered + d
                volume[x, y, z] = int(round(v_orig))
                
                # Store centered version for next predictions
                v_centered[x, y, z] = v_orig - mean_v
                
    return volume
```

### Edge Cases and Pitfalls
*   **Causality:** The predictor must strictly use only previously processed voxels ($x-1, y, z$), ($x, y-1, z$), and ($x, y, z-1$). Any lookahead breaks decompression synchronization [S1, unofficial].
*   **Boundary Handling:** At boundaries ($x=0, y=0, z=0$), the neighbor contribution is zeroed. This is critical for the orthogonality assumption [S1, unofficial].
*   **Non-Stationarity:** The method assumes wide-sense stationarity. Real volumes may violate this, leading to suboptimal coefficients. The source suggests octree-based local predictors as an improvement [S1, unofficial].
*   **Memory vs. Speed:** The algorithm scans the volume four times. Storing all residuals would require significant memory ($X \times Y \times Z$ integers). The fourth scan is necessary to avoid this memory cost [S1, unofficial].
*   **Precision:** Covariance calculations use floating-point arithmetic. Coefficients $a_i$ are solved via linear system. Small errors in $a_i$ can accumulate, but the source notes the method is robust enough for 16-bit data [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The algorithm performs 4 full scans of the volume. Statistics estimation (2 scans) is $O(N)$. Residual calculation and encoding (2 scans) is $O(N)$. Solving the linear system is $O(1)$ (fixed $3 \times 3$). Huffman table construction is $O(L \log L)$ where $L$ is alphabet size. Total time is dominated by $O(N)$ scans.
*   **Memory Complexity:** $O(N)$ for the volume data. No residual array is stored. Header size is small (constants + Huffman table).
*   **Performance:** Achieves ~50% compression ratio on biomedical volumes [S1, unofficial]. On `3dhead.vox` (HP 9000 Series 735), compression took 4.7 minutes and decompression 1.4 minutes [S1, unofficial]. Outperforms gzip and zip [S1, unofficial].
*   **Strengths:** High compression ratio for volumetric data; lossless; handles non-isotropic sampling via optimal coefficients [S1, unofficial].
*   **Limitations:** Slow due to multiple scans; assumes stationarity; not suitable for real-time streaming without buffering [S1, unofficial].

## Background
The method was introduced by James Edwin Fowler and Roni Yagel in January 1995 at the Proceedings of the 1994 Symposium on Volume Visualization [S1, unofficial]. It is based on Differential Pulse-Code Modulation (DPCM) combined with Huffman coding, specifically tailored for the spatial coherence of volume data [S1, unofficial]. It is often referred to as the `compvox` algorithm [S1, unofficial].
