# 3D Shape Autoencoder

Also called: Shape prior autoencoder

## Overview
The 3D Shape Autoencoder is a convolutional autoencoder architecture designed to learn a compact prior distribution of 3D shapes [S1, unofficial]. It solves the problem of reconstructing complex 3D geometry from limited input data by encoding spatial structures into a low-dimensional latent vector and decoding them back into volumetric representations [S1, unofficial]. It differs from its parent, the Convolutional Autoencoder for Volume Compression, by focusing specifically on learning a generalizable shape prior for geometric reconstruction tasks (such as novel-view synthesis and relighting) rather than compressing time-varying multivariate scientific data [S1, unofficial]. It is distinct from [Deep Implicit Volume Compression](6807-deep-implicit-volume-compression.md), which uses implicit neural representations rather than explicit voxel-based convolutional encoding/decoding [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume tensor representing a shape (e.g., a voxelized object) [S1, unofficial].
*   **Output:** A reconstructed 3D volume tensor of the same spatial dimensions as the input [S1, unofficial].

**Data Structures:**
The network consists of an Encoder, a Latent Bottleneck, and a Decoder [S1, unofficial]. All weights are learned parameters.

**Parameters:**
*   **Activation Function:** Exponential Linear Unit (ELU) is used for all convolutional layers except the final layer of the encoder and the final layer of the decoder [S1, unofficial].
*   **Final Layer Activation:** Sigmoid is used for the last convolutional layer in both the encoder and the decoder [S1, unofficial].
*   **Kernel Sizes, Strides, Channels:** Defined per layer in the sequence below [S1, unofficial].

**Algorithm Steps:**

1.  **Encoder Forward Pass:**
    The input volume $V_{in}$ is processed through a series of 3D convolutional layers [S1, unofficial]. Let $C_i, K_i, S_i$ denote the number of output channels, kernel size, and stride for layer $i$ [S1, unofficial].
    *   Layer 1: Conv3D($V_{in}$, channels=64, kernel=5, stride=2, activation=ELU) $\rightarrow$ $H_1$ [S1, unofficial]
    *   Layer 2: Conv3D($H_1$, channels=128, kernel=5, stride=2, activation=ELU) $\rightarrow$ $H_2$ [S1, unofficial]
    *   Layer 3: Conv3D($H_2$, channels=256, kernel=2, stride=2, activation=ELU) $\rightarrow$ $H_3$ [S1, unofficial]
    *   Layer 4: Conv3D($H_3$, channels=512, kernel=2, stride=2, activation=Sigmoid) $\rightarrow$ $H_4$ [S1, unofficial]
    *   *Note: The source specifies ELU for "all layers" except the last conv layer in encoder/decoder, which uses Sigmoid [S1, unofficial].*

2.  **Latent Bottleneck:**
    *   **Flatten:** Flatten $H_4$ into a 1D vector [S1, unofficial].
    *   **Encode Vector:** Fully Connected (FC) layer maps the flattened $H_4$ to a 200-dimensional vector $z_{raw}$ [S1, unofficial].
    *   **Latent Activation:** Apply Sigmoid activation to $z_{raw}$ to produce the latent code $z$ [S1, unofficial].
    *   **Decode Vector:** Fully Connected (FC) layer maps the 200-dimensional latent vector to a $(4 \times 4 \times 512)$-dimensional vector $v_{flat}$ [S1, unofficial].

3.  **Reshape:**
    *   Reshape $v_{flat}$ into a 3D tensor $H_{dec\_in}$ of shape $(4, 4, 512)$ [S1, unofficial].

4.  **Decoder Forward Pass:**
    The tensor $H_{dec\_in}$ is processed through a series of 3D up-convolutional layers (transposed convolutions or upsampling + convolution) [S1, unofficial]. Let $C_j, K_j, S_j$ denote channels, kernel size, and stride for decoder layer $j$ [S1, unofficial].
    *   Layer 1: UpConv3D($H_{dec\_in}$, channels=256, kernel=4, stride=2, activation=ELU) $\rightarrow$ $D_1$ [S1, unofficial]
    *   Layer 2: UpConv3D($D_1$, channels=128, kernel=4, stride=2, activation=ELU) $\rightarrow$ $D_2$ [S1, unofficial]
    *   Layer 3: UpConv3D($D_2$, channels=64, kernel=4, stride=2, activation=ELU) $\rightarrow$ $D_3$ [S1, unofficial]
    *   Layer 4: UpConv3D($D_3$, channels=32, kernel=4, stride=2, activation=ELU) $\rightarrow$ $D_4$ [S1, unofficial]
    *   Layer 5: UpConv3D($D_4$, channels=1, kernel=4, stride=1, activation=Sigmoid) $\rightarrow$ $V_{out}$ [S1, unofficial]

**Pseudocode:**

```python
import torch
import torch.nn as nn

class ShapePriorAutoencoder(nn.Module):
    def __init__(self):
        super(ShapePriorAutoencoder, self).__init__()
        
        # Encoder
        self.enc_conv1 = nn.Conv3d(1, 64, kernel_size=5, stride=2, padding=2)
        self.enc_conv2 = nn.Conv3d(64, 128, kernel_size=5, stride=2, padding=2)
        self.enc_conv3 = nn.Conv3d(128, 256, kernel_size=2, stride=2, padding=0)
        self.enc_conv4 = nn.Conv3d(256, 512, kernel_size=2, stride=2, padding=0)
        
        # Bottleneck
        self.fc_encode = nn.Linear(512 * 4 * 4, 200)
        self.fc_decode = nn.Linear(200, 4 * 4 * 512)
        
        # Decoder
        self.dec_conv1 = nn.ConvTranspose3d(512, 256, kernel_size=4, stride=2, padding=1)
        self.dec_conv2 = nn.ConvTranspose3d(256, 128, kernel_size=4, stride=2, padding=1)
        self.dec_conv3 = nn.ConvTranspose3d(128, 64, kernel_size=4, stride=2, padding=1)
        self.dec_conv4 = nn.ConvTranspose3d(64, 32, kernel_size=4, stride=2, padding=1)
        self.dec_conv5 = nn.ConvTranspose3d(32, 1, kernel_size=4, stride=1, padding=1)
        
        # Activations
        self.elu = nn.ELU()
        self.sigmoid = nn.Sigmoid()

    def forward(self, x):
        # x shape: (B, 1, D, H, W)
        
        # Encoder
        h1 = self.elu(self.enc_conv1(x))
        h2 = self.elu(self.enc_conv2(h1))
        h3 = self.elu(self.enc_conv3(h2))
        h4 = self.sigmoid(self.enc_conv4(h3))
        
        # Flatten
        batch_size = h4.shape[0]
        h_flat = h4.view(batch_size, -1)
        
        # Bottleneck
        z_raw = self.fc_encode(h_flat)
        z = self.sigmoid(z_raw)
        
        # Reshape for Decoder
        z_decoded = self.fc_decode(z)
        h_dec_in = z_decoded.view(batch_size, 512, 4, 4)
        
        # Decoder
        d1 = self.elu(self.dec_conv1(h_dec_in))
        d2 = self.elu(self.dec_conv2(d1))
        d3 = self.elu(self.dec_conv3(d2))
        d4 = self.elu(self.dec_conv4(d3))
        out = self.sigmoid(self.dec_conv5(d4))
        
        return out
```

## Subtopics

### SurroFlow
SurroFlow is a variant that integrates normalizing flows into the latent space of a 3D convolutional autoencoder [S2, unofficial]. It learns an invertible transformation between a simple base distribution and the data distribution, enabling bidirectional prediction: forward mapping from simulation parameters to outputs, and reverse mapping from observed data to likely parameter values [S2, unofficial]. It is chosen when bidirectional inference is required for scientific simulations [S2, unofficial]. However, the constant-dimensionality constraint of normalizing flows limits it to lower resolutions than the native simulation grid [S2, unofficial]. On MPAS-Ocean (192 × 96 × 12), it achieved 46.69 dB PSNR with a 48 MB model trained in 11.5 hours, outperforming VDL-Surrogate (45.82 dB, 0.63 GB, 139.8 hours) [S2, unofficial]. On Nyx at 128³, its PSNR drops to 30.93 dB, below VDL-Surrogate’s 33.66 dB [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial].
*   **Memory Complexity:** Not given in the sources for the base 3D Shape Autoencoder [S1, unofficial]. SurroFlow variant uses 48 MB for MPAS-Ocean [S2, unofficial].
*   **Measured Performance:** The base method is evaluated qualitatively on novel-view synthesis and relighting [S1, unofficial]. SurroFlow achieves 46.69 dB PSNR on MPAS-Ocean [S2, unofficial].
*   **Strengths:** Learns a generalizable shape prior; enables sharper results in novel-view synthesis and relighting [S1, unofficial]. SurroFlow offers significant parameter efficiency (1.5–6.7× fewer parameters than some baselines) and fast inference (1.70 s per field) [S2, unofficial].
*   **Limitations:** The base method requires further work to improve speed and performance [S1, unofficial]. SurroFlow is limited by the constant-dimensionality constraint of normalizing flows, preventing it from operating at native high resolutions (e.g., 512³) [S2, unofficial]. SurroFlow does not provide uncertainty estimates in its base form [S2, unofficial].
*   **When to use:** Use the base 3D Shape Autoencoder for learning geometric shape priors for rendering tasks [S1, unofficial]. Use SurroFlow for scientific surrogate modeling where bidirectional inference and parameter efficiency are critical, and resolution requirements are moderate [S2, unofficial].

## Background
The 3D Shape Autoencoder was introduced in the context of differentiable rendering from 3D shapes, specifically to learn a shape prior $g(z_0)$ that improves reconstruction quality compared to methods without such a prior [S1, unofficial]. It was proposed as an alternative to feed-forward networks used in prior work like Tulsiani et al. [S1, unofficial]. SurroFlow was developed later for scientific volume data compression and surrogate modeling, leveraging the autoencoder structure combined with normalizing flows [S2, unofficial].
