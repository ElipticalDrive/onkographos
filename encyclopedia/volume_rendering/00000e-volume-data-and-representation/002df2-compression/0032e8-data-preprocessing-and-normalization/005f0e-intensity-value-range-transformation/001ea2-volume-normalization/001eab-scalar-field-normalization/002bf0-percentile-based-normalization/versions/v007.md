# Percentile-based Normalization

Also called: DRR Image Normalization, Grayscale Mapping

## Overview
Percentile-based Normalization scales scalar field data to a target range (typically [0, 1] or [0, 255]) by using percentile bounds instead of global extrema to determine the clipping window. This method solves the problem of outlier sensitivity in global normalization, where extreme values compress the dynamic range of the majority of the data. It differs from [Scaling](2287-scaling.md) and [Scalar Field Normalization](1842-scalar-field-normalization.md) by ignoring values outside the chosen percentile interval, thereby enhancing contrast for the central distribution of the data.

## How it works
**Inputs and Outputs:**
- Input: A scalar field (image or volume) $I$ of arbitrary numeric type.
- Output: A normalized scalar field $I_{norm}$ in the range $[0, 1]$ or an 8-bit integer representation $I_{8bit}$.

**Data Structures:**
- The input is treated as a dense array or tensor. No specific bit-packing is required for the input; the output is typically `uint8` for visualization or `float32` for further processing.

**Steps:**
1. **Calculate Percentile Bounds:** Compute the lower bound $min\_val$ and upper bound $max\_val$ as the $\alpha$-th and $(100-\alpha)$-th percentiles of the input data $I$. A common choice is $\alpha=5$ (5th and 95th percentiles) to exclude outliers [S1, unofficial].
   $$ min\_val = \text{percentile}(I, \alpha) $$
   $$ max\_val = \text{percentile}(I, 100 - \alpha) $$
2. **Clip Data:** Clip the input values to the calculated bounds to handle values outside the range.
   $$ I_{clipped} = \text{clip}(I, min\_val, max\_val) $$
3. **Normalize:** Linearly scale the clipped data to $[0, 1]$. A small epsilon $\epsilon$ is added to the denominator to prevent division by zero if $min\_val = max\_val$.
   $$ I_{normalized} = \frac{I_{clipped} - min\_val}{max\_val - min\_val + \epsilon} $$
   Where $\epsilon = 10^{-8}$ [S1, unofficial].
4. **Scale to Target Range (Optional):** To convert to 8-bit grayscale for visualization:
   $$ I_{8bit} = \text{astype}\left( \lfloor I_{normalized} \times 255 \rfloor, \text{uint8} \right) $$

**Parameters:**
- $\alpha$: The lower percentile cutoff. Typical value: 5 [S1, unofficial].
- $\epsilon$: Epsilon for numerical stability. Typical value: $10^{-8}$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- If the data contains only one unique value, $max\_val - min\_val = 0$. The epsilon term ensures the result is 0.0 rather than NaN or Inf [S1, unofficial].
- Outliers are strictly ignored. If the "outliers" are actually meaningful signal, this method will clip them to the bounds, potentially losing information [S1, unofficial].
- NaN values in the input can affect percentile calculation depending on the implementation. In some contexts (like [Weighted Percentile Computation](7031-weighted-percentile-computation.md)), NaNs must be handled explicitly [S2, unofficial].

**Pseudocode:**
```python
import numpy as np

def percentile_normalize(image, alpha=5, epsilon=1e-8, to_8bit=True):
    """
    Normalizes an image using percentile-based clipping.
    
    Args:
        image: Input numpy array of floats.
        alpha: Percentile cutoff (default 5, i.e., 5th and 95th percentiles).
        epsilon: Small constant to avoid division by zero.
        to_8bit: If True, return uint8 [0, 255]; else return float [0, 1].
        
    Returns:
        Normalized image.
    """
    # Step 1: Calculate bounds
    min_val = np.percentile(image, alpha)
    max_val = np.percentile(image, 100 - alpha)
    
    # Step 2: Clip
    image_clipped = np.clip(image, min_val, max_val)
    
    # Step 3: Normalize
    normalized = (image_clipped - min_val) / (max_val - min_val + epsilon)
    
    # Step 4: Scale
    if to_8bit:
        return (normalized * 255).astype(np.uint8)
    else:
        return normalized
```

## Subtopics

### Median Normalization
Normalizes a tensor by dividing valid positive values by their median and multiplying by a configuration multiplier. It handles NaNs by replacing them with 0 and ignores non-positive values. Unlike percentile normalization which uses a range, this uses a single central tendency metric (median) for scaling [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ to compute percentiles, where $N$ is the number of voxels/pixels. Percentile calculation is typically linear or near-linear depending on the algorithm (e.g., QuickSelect).
- **Memory Complexity:** $O(N)$ for the input and output arrays.
- **Strengths:** Robust to outliers; enhances contrast for the majority of the data; simple to implement.
- **Limitations:** Loses information outside the percentile bounds; sensitive to the choice of $\alpha$; not suitable if global intensity relationships are critical.
- **When to use:** Visualization of medical images (DRR), CT data, or any scalar field with heavy-tailed distributions or significant outliers [S1, unofficial].
- **When not to use:** When absolute intensity values must be preserved for quantitative analysis, or when the data distribution is uniform and outliers are meaningful.

## Background
This method is widely used in medical imaging, particularly in the generation of Digital Radiography (DRR) images from CT data. It serves as a preprocessing step to map Hounsfield units or attenuation coefficients to a displayable grayscale range. The approach is documented in practical implementations for ray casting and DRR generation [S1, unofficial]. It is also related to intensity-to-grayscale mapping techniques that use saturation thresholds to ignore outliers [S2, unofficial].
