# Median Normalization

Also called: Value Normalization, normalize

## Overview
Median Normalization scales a scalar field by dividing each valid value by the median of the valid values and multiplying by a configurable multiplier [S1, unofficial]. It solves the problem of intensity range inconsistency in volume data by using the median, which is robust to outliers compared to mean-based methods [S1, unofficial]. It differs from [Weighted Percentile Computation](7031-weighted-percentile-computation.md) by using a single central point (the median) rather than a weighted distribution, and from [Intensity-to-Grayscale Mapping](11937-intensity-to-grayscale-mapping.md) by preserving the relative magnitude of values rather than mapping them to a fixed output range [S1, unofficial].

## How it works
**Inputs:**
- `value_tensor`: A tensor of scalar values representing the volume data.
- `config_value`: A floating-point multiplier applied after normalization.

**Outputs:**
- `ret_value`: A tensor of the same shape and dtype as `value_tensor` (converted to float32), containing the normalized values.

**Data Structures:**
- The input and output are dense tensors. No auxiliary structures are required beyond temporary masks and slices.

**Steps:**
1. Initialize `ret_value` as a tensor of zeros with the same shape as `value_tensor` and dtype `torch.float32` [S1, unofficial].
2. Replace all `NaN` values in `value_tensor` with `0` [S1, unofficial].
3. Identify `valid_indices` where `value_tensor > 0` [S1, unofficial].
4. Extract `valid_value` from `value_tensor` at `valid_indices`, cast to `torch.float32` [S1, unofficial].
5. Compute `median_val` as the median of `valid_value` [S1, unofficial].
6. If `median_val` is zero or `valid_value` is empty, return `ret_value` (all zeros) [G].
7. For each index in `valid_indices`, set `ret_value[index] = config_value * (valid_value / median_val)` [S1, unofficial].
8. Return `ret_value` [S1, unofficial].

**Pseudocode:**
```python
import torch

def median_normalization(value_tensor: torch.Tensor, config_value: float) -> torch.Tensor:
    # Step 1: Initialize output with zeros
    ret_value = torch.zeros_like(value_tensor, dtype=torch.float32)
    
    # Step 2: Replace NaN with 0
    value_tensor = torch.nan_to_num(value_tensor, nan=0.0)
    
    # Step 3: Identify valid indices (value > 0)
    valid_mask = value_tensor > 0
    valid_indices = torch.nonzero(valid_mask, as_tuple=False).squeeze()
    
    # Handle edge case: no valid values
    if valid_indices.numel() == 0:
        return ret_value
    
    # Step 4: Extract valid values and cast to float32
    valid_value = value_tensor[valid_indices].to(torch.float32)
    
    # Step 5: Compute median
    median_val = torch.median(valid_value)
    
    # Handle edge case: median is zero
    if median_val == 0:
        return ret_value
        
    # Step 6 & 7: Normalize and assign
    normalized_valid = config_value * (valid_value / median_val)
    ret_value[valid_indices] = normalized_valid
    
    # Step 8: Return result
    return ret_value
```

**Parameters:**
- `config_value`: The multiplier to apply after normalization. Typical values depend on the downstream application; [S1, unofficial] uses it as a configuration parameter without specifying a default.
- `value_tensor`: The input tensor. Must support boolean indexing and median computation.

**Edge Cases and Pitfalls:**
- **Zero Median:** If all valid values are identical and non-zero, the median is non-zero, and normalization is valid. If all valid values are zero (impossible by definition of `valid_indices` where `>0`), or if the median calculation returns zero due to numerical issues, division by zero occurs. The pseudocode guards against this [G].
- **NaN Handling:** NaNs are replaced with 0 before masking, ensuring they are excluded from the median calculation and the output [S1, unofficial].
- **Negative Values:** Values $\le 0$ are ignored and remain 0 in the output [S1, unofficial].

## Subtopics

### Statistical Normalization (Z-Score)
Data is normalized to have zero mean and a standard deviation of one before training to allow consistent hyperparameters and initial parameters across models [S2, unofficial]. When all data is available, statistics are computed from the data itself, considering each dimension individually [S2, unofficial]. When data is not available, it is assumed that the variable is uniformly distributed $x \sim U(r_{min}, r_{max})$, and the normalized value $\hat{x}$ is calculated as $\hat{x} = \frac{x - E[x]}{\sqrt{Var[x]}}$, where $E[x]$ is the expected value and $Var[x]$ is the variance of the uniform distribution [S2, unofficial]. Ranges for normalization parameters are specified in Table 4 of [S2, unofficial]: for 2D spatial ($s_i$): [0, 64]; for 2D color ($c_i$): [0, 255]; for 3D spatial ($s_i$): [-1, 1] (Objects) or [-5, 5] (Rooms); for 3D color ($c_i$): [0, 255] [S2, unofficial].

## Operating characteristics
**Time Complexity:** $O(N)$, where $N$ is the number of elements in `value_tensor`, due to the linear scan for valid indices and the median computation (which is typically $O(N)$ for selection algorithms) [S1, unofficial].
**Memory Complexity:** $O(N)$ for the output tensor and temporary masks [S1, unofficial].
**Strengths:** Robust to outliers in the data due to the use of the median [S1, unofficial]. Simple to implement [S1, unofficial].
**Limitations:** Only scales positive values; negative and zero values are discarded or set to zero [S1, unofficial]. Sensitive to the distribution of positive values; if the median is very small, scaling factors can become large [G].
**When to use:** When the data contains significant outliers and the primary interest is in the central tendency of positive values [S1, unofficial].
**When not to use:** When negative values are meaningful or when a zero-mean normalization is required [S2, unofficial].

## Background
Median Normalization is used in the context of Gaussian Splatting and volume rendering preprocessing, specifically in the FastGS implementation [S1, unofficial]. It is part of a broader set of data normalization techniques used to prepare input data for machine learning models, such as the Z-Score normalization described in Variational Bayes Gaussian Splatting [S2, unofficial].
