# Geometric Normalization

Also called: Data Normalization, Viewport-Fitting Grid Normalization, Volume Centering and Scaling

## Overview
Geometric Normalization is a preprocessing step that translates and scales the input grid to prevent screen clipping during volume rendering [S1, unofficial][S2]. It centers the object at the origin and scales it to fit within a specific display resolution [S2]. It differs from [Volume Normalization](1823-volume-normalization.md), which typically adjusts scalar values (intensity/color) rather than spatial coordinates.

## How it works
**Inputs:** A set of 3D points or voxels with coordinates $(x, y, z)$ and associated data (e.g., RGB color) [S2].
**Outputs:** Transformed coordinates $(x', y', z')$ centered at the origin and scaled to fit a target viewport [S1, unofficial][S2].

**Data Structures:**
The input is typically stored as a list of tuples or arrays containing vertex coordinates and color data, e.g., $(x, y, z, r, g, b)$ [S2].

**Steps:**
1.  **Compute Bounds:** Determine the minimum and maximum coordinates along each axis: $x_{min}, x_{max}, y_{min}, y_{max}, z_{min}, z_{max}$ [S2].
2.  **Compute Center:** Calculate the center of the bounding box for each axis [S2]:
    $$x_{center} = \frac{x_{max} + x_{min}}{2}$$
    $$y_{center} = \frac{y_{max} + y_{min}}{2}$$
    $$z_{center} = \frac{z_{max} + z_{min}}{2}$$
3.  **Translate:** Shift all coordinates to the origin [S2]:
    $$x' = x - x_{center}$$
    $$y' = y - y_{center}$$
    $$z' = z - z_{center}$$
4.  **Scale:** Scale the translated grid so that it fits completely within a target screen resolution at any viewing angle [S1, unofficial]. The target resolution is typically 1024 x 768 pixels [S1, unofficial][S2]. The scaling factor is derived from the maximum dimension of the centered bounding box relative to the target viewport size [S1, unofficial][S2].

**Pseudocode:**
```python
def geometric_normalization(points, target_width=1024, target_height=768):
    """
    Normalize 3D points to fit a target screen resolution.
    points: list of tuples (x, y, z, r, g, b)
    """
    if not points:
        return []

    # Extract coordinates
    coords = [(p[0], p[1], p[2]) for p in points]
    
    # Compute bounds
    xs = [c[0] for c in coords]
    ys = [c[1] for c in coords]
    zs = [c[2] for c in coords]
    
    x_min, x_max = min(xs), max(xs)
    y_min, y_max = min(ys), max(ys)
    z_min, z_max = min(zs), max(zs)
    
    # Compute center
    x_center = (x_max + x_min) / 2.0
    y_center = (y_max + y_min) / 2.0
    z_center = (z_max + z_min) / 2.0
    
    # Compute dimensions
    width = x_max - x_min
    height = y_max - y_min
    depth = z_max - z_min
    
    # Determine scaling factor to fit target viewport
    # Note: The exact scaling logic for 3D to 2D viewport fitting 
    # is not fully specified in sources beyond "fits completely" [S1, unofficial][S2].
    # A common approach is to scale by the minimum of the ratios of 
    # target dimensions to object dimensions, considering the largest 
    # spatial extent.
    # Assuming the object fits within a cube or box defined by max(width, height, depth).
    max_dim = max(width, height, depth)
    
    # Target aspect ratio
    target_aspect = target_width / target_height
    
    # Simple scaling: fit the largest dimension to the smaller target dimension 
    # to ensure it fits at any angle (conservative estimate) [S1, unofficial].
    # Or scale based on the diagonal. Sources do not specify the exact scalar formula.
    # We use a placeholder for the specific scaling constant K.
    # K = min(target_width / width, target_height / height) if 2D projection assumed.
    # For 3D volume fitting, K is often derived from the bounding box diagonal 
    # relative to the screen diagonal, or simply scaling the max dimension 
    # to fit the screen.
    
    # Implementation note: Sources state "fits completely within a screen of size 
    # 1024 x 768 pixel resolution" [S1, unofficial]. This implies a uniform scale factor S.
    # S = min(target_width / width, target_height / height) is a safe 2D fit.
    # For 3D, we might scale by S such that the projected bounding box fits.
    
    scale_factor = min(target_width / width, target_height / height) if width > 0 and height > 0 else 1.0
    
    normalized_points = []
    for p in points:
        x, y, z, r, g, b = p
        x_norm = (x - x_center) * scale_factor
        y_norm = (y - y_center) * scale_factor
        z_norm = (z - z_center) * scale_factor
        normalized_points.append((x_norm, y_norm, z_norm, r, g, b))
        
    return normalized_points
```

**Parameters:**
- Target screen resolution: 1024 x 768 pixels [S1, unofficial][S2].
- Input data format: $(x, y, z, r, g, b)$ [S2].

**Edge Cases:**
- Zero-width/height/depth: If $width=0$ or $height=0$, scaling is undefined. A guard should return the original points or handle division by zero [G].
- Precision: Floating point precision issues may arise with very large coordinate ranges before normalization [G].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of points/voxels, as it requires a single pass to find bounds and another to transform.
- **Memory Complexity:** $O(N)$ to store the transformed points.
- **Strengths:** Prevents clipping during rendering; standardizes input for downstream processing [S1, unofficial][S2].
- **Limitations:** Does not handle non-uniform scaling of axes differently (uniform scale only); assumes a rectangular bounding box [S2].
- **When to use:** When rendering arbitrary 3D grids that may exceed the viewport [S1, unofficial].

## Background
Originating from early volume visualization systems like VIPER, this method was developed to handle scattered data on rectangular grids [S1, unofficial]. It was later adopted in 3D swept-volume volumetric displays to fit display parameters [S2].
