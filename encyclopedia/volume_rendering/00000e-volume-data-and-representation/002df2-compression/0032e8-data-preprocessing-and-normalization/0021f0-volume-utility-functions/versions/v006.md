# Volume Utility Functions

Also called: volume size fixing, region normalization, volpack normal encoding, memory alignment, scale unpacking, nifti analysis

## Overview
Volume Utility Functions constitute a collection of low-level preprocessing, validation, and format-conversion routines required to prepare raw volume data for rendering or analysis. They solve problems of dimensional compatibility, intensity standardization, geometric consistency, and memory layout. Unlike [Volume Normalization](1823-volume-normalization.md), which focuses on global intensity scaling, these utilities handle structural adjustments (dimensionality, voxel scale), strict numerical conversions (half-precision, normal encoding), and data integrity checks (size fixing, region clamping). They serve as the foundational layer for the [Preprocessing Pipeline](6733-preprocessing-pipeline.md).

## How it works
The methods are categorized by function: dimensional/structural manipulation, intensity normalization, geometric validation, and format conversion.

### Dimensional and Structural Manipulation

#### `make_nd`
Ensures a volume tensor has a specific number of dimensions by prepending singleton dimensions.

**Inputs:**
- `t`: Input tensor (numpy or torch).
- `n`: Target number of dimensions (integer).

**Outputs:**
- Tensor with shape `(1, 1, ..., t.shape)` such that `len(shape) == n`.

**Steps:**
1. Let $d = \text{t.ndim}$.
2. If $n < d$, raise an exception.
3. Prepend $n - d$ singleton dimensions to `t`.

**Pseudocode:**
```python
def make_nd(t, n):
    """
    Prepends singleton dimensions to tensor t until it is n-dimensional.
    Raises exception if n < t.ndim.
    """
    current_ndim = len(t.shape)
    if n < current_ndim:
        raise ValueError(f"Target dimensions {n} is less than current dimensions {current_ndim}")
    
    # Prepend singleton dimensions
    # In numpy/torch, adding a dimension at the front can be done via reshape or unsqueeze
    # We need to add (n - current_ndim) dimensions at the start
    new_shape = [1] * (n - current_ndim) + list(t.shape)
    return t.reshape(new_shape)
```

#### Volume Size Fixing
Corrects the Z-dimension (frame count) of a volume when the stored metadata `image_size[2]` is incorrect, deriving the true size from the raw data byte length.

**Inputs:**
- `data`: Raw byte buffer of the volume.
- `volumeSize`: Array `[X, Y, Z]` from metadata.
- `bytesPerVoxel`: Size of a single voxel in bytes (e.g., 4 for float32).

**Outputs:**
- `volumeSizeFixed`: Corrected `[X, Y, Z_fixed]`.

**Steps:**
1. Calculate `realFrameCount` as:
   $$ \text{realFrameCount} = \frac{\text{data.byteLength}}{\text{volumeSize}[0] \times \text{volumeSize}[1] \times \text{bytesPerVoxel}} $$
2. If `realFrameCount != volumeSize[2]`:
   - Log a warning.
   - Set `volumeSizeFixed[0] = volumeSize[0]`.
   - Set `volumeSizeFixed[1] = volumeSize[1]`.
   - Set `volumeSizeFixed[2] = realFrameCount`.
3. Return `volumeSizeFixed`.

**Pitfall:** The original file's `image_size[2]` attribute may be wrong, requiring correction based on actual data size [S2, unofficial].

### Intensity Normalization

#### `normalize_hounsfield`
Normalizes a CT volume to the [0, 1] range by dividing by the maximum Hounsfield unit scale (4095) and clamping.

**Inputs:**
- `vol`: Volume data (numpy array or torch tensor).
- `dtype`: Optional output data type.

**Outputs:**
- Normalized volume with values in $[0, 1]$.

**Steps:**
1. Divide `vol` by 4095.
2. Clamp values to the range $[0, 1]$.
   $$ v_{out} = \max(0, \min(1, \frac{v_{in}}{4095})) $$

**Pseudocode:**
```python
def normalize_hounsfield(vol, dtype=None):
    """
    Normalizes volume by 4095 and clamps to [0, 1].
    Handles torch tensors and numpy arrays.
    """
    # Divide by max Hounsfield scale
    normalized = vol / 4095.0
    
    # Clamp to [0, 1]
    normalized = torch.clamp(normalized, 0.0, 1.0) if hasattr(normalized, 'clamp') else \
                 np.clip(normalized, 0.0, 1.0)
                 
    if dtype is not None:
        normalized = normalized.to(dtype) if hasattr(normalized, 'to') else normalized.astype(dtype)
        
    return normalized
```

#### `normalize_voxel_scale`
Resamples a volume to a new shape based on a target voxel scale, preserving physical dimensions.

**Inputs:**
- `vol`: Input volume.
- `vox_scl`: Target voxel scale as a tensor/array of shape `[3]` (sx, sy, sz).

**Outputs:**
- Resampled volume with shape adjusted to match the new voxel scale.

**Steps:**
1. Determine current voxel scale from volume metadata or assume unit scale if unknown.
2. Calculate new shape based on the ratio of current scale to `vox_scl`.
3. Resample using trilinear interpolation.

**Pseudocode:**
```python
def normalize_voxel_scale(vol, vox_scl):
    """
    Resamples volume to new shape based on voxel scale using trilinear interpolation.
    vox_scl: Voxel scale as a tensor of shape [3].
    """
    # Assuming vol has associated spacing or we infer from shape if not provided.
    # For implementation completeness, we assume a helper `get_spacing(vol)` exists
    # or that the input `vol` object carries this metadata.
    # If not, this step requires external metadata. [G]
    
    current_spacing = get_spacing(vol) # Placeholder for metadata retrieval
    if current_spacing is None:
        raise ValueError("Volume spacing must be known to normalize voxel scale")
        
    # Calculate scaling factors
    scale_factors = [c / t for c, t in zip(current_spacing, vox_scl)]
    
    # Calculate new shape
    new_shape = [int(round(s * f)) for s, f in zip(vol.shape, scale_factors)]
    
    # Resample using trilinear interpolation
    # Implementation depends on library (scipy.ndimage.zoom, torch.nn.functional.interpolate, etc.)
    resampled = resample_trilinear(vol, new_shape)
    
    return resampled
```

### Geometric Validation and Region Handling

#### Region Normalization and Validation
Clamps region coordinates to valid chunk bounds and checks for empty regions.

**Inputs:**
- `region`: Tuple or array `[min_x, min_y, min_z, max_x, max_y, max_z]`.
- `height`: Y-dimension limit.
- `CHUNK_SIZE`: Maximum X and Z dimension limit.
- `FIRST_INDEX`: Minimum valid index (typically 0).

**Outputs:**
- Clamped region and boolean indicating if empty.

**Steps:**
1. Extract min coordinates $(min_x, min_y, min_z)$ and max coordinates $(max_x, max_y, max_z)$.
2. Clamp min coordinates:
   - $min_x, min_z \in [\text{FIRST\_INDEX}, \text{CHUNK\_SIZE}]$
   - $min_y \in [\text{FIRST\_INDEX}, \text{height}]$
3. Clamp max coordinates:
   - $max_x, max_z \in [min_x, \text{CHUNK\_SIZE}]$
   - $max_y \in [min_y, \text{height}]$
4. Check if region is empty:
   - If $min_x \ge max_x$ OR $min_y \ge max_y$ OR $min_z \ge max_z$, the region is empty.

**Pseudocode:**
```python
def normalize_region(region, height, chunk_size, first_index=0):
    """
    Clamps region coordinates to valid chunk bounds and checks if a region is empty.
    """
    min_x, min_y, min_z, max_x, max_y, max_z = region
    
    # Clamp min coordinates
    min_x = max(first_index, min(min_x, chunk_size))
    min_y = max(first_index, min(min_y, height))
    min_z = max(first_index, min(min_z, chunk_size))
    
    # Clamp max coordinates
    max_x = max(min_x, min(max_x, chunk_size))
    max_y = max(min_y, min(max_y, height))
    max_z = max(min_z, min(max_z, chunk_size))
    
    # Check if empty
    is_empty = (min_x >= max_x) or (min_y >= max_y) or (min_z >= max_z)
    
    return (min_x, min_y, min_z, max_x, max_y, max_z), is_empty
```

### Format Conversion and Encoding

#### VolPack Normal Vector Encoding/Decoding
Encodes a normalized 3D vector into a 16-bit integer format for VolPack shaders and decodes it back.

**Inputs (Encode):**
- `nx, ny, nz`: Normalized vector components ($nx^2 + ny^2 + nz^2 = 1$).

**Outputs (Encode):**
- 16-bit integer `n`.

**Inputs (Decode):**
- `n`: 16-bit encoded normal.

**Outputs (Decode):**
- `nx, ny, nz`: Pointer-stored components.

**Steps (Encode):**
1. Validate that $nx^2 + ny^2 + nz^2 \approx 1$.
2. Call `vpNormalIndex(nx, ny, nz)` to return 16-bit integer.

**Steps (Decode):**
1. Call `vpNormal(n, &nx, &ny, &nz)` to retrieve components.

**Pseudocode:**
```python
# Note: Exact encoding algorithm for VolPack is proprietary/complex.
# This pseudocode represents the API interface described in the source.
def volpack_encode_normal(nx, ny, nz):
    """
    Encodes a normalized 3D vector into a 16-bit integer format expected by VolPack shaders.
    """
    # Validation
    if abs(nx*nx + ny*ny + nz*nz - 1.0) > 1e-6:
        raise ValueError("Vector must be normalized")
    
    # Call underlying C function vpNormalIndex
    # Implementation detail: This typically involves quantizing the vector to a 
    # specific 16-bit lattice or octahedral encoding.
    # Since the exact algorithm is not provided in the source, we assume a wrapper.
    return vpNormalIndex_c_wrapper(nx, ny, nz)

def volpack_decode_normal(n):
    """
    Decodes a 16-bit encoded normal back into its vector components.
    """
    nx, ny, nz = vpNormal_c_wrapper(n)
    return nx, ny, nz
```

#### Half-Precision Float Conversion
Converts between 32-bit IEEE 754 single-precision floats and 16-bit binary16 half-precision floats.

**Inputs:**
- `val`: 32-bit float or 16-bit half.

**Outputs:**
- Converted value.

**Steps:**
1. For float32 to float16:
   - Handle subnormal numbers, overflow, and NaN preservation.
   - Avoid undefined behavior from direct type punning.
2. For float16 to float32:
   - Sign-extend and adjust exponent bias.

**Pitfall:** Direct type punning (casting pointers) can cause undefined behavior or alignment issues [S1, S3, unofficial].

#### Scale Unpacking
Decodes packed scale data from a buffer into floating-point log-scale values.

**Inputs:**
- `src`: Byte buffer of packed scale data.
- `coordCount`: Number of scale values ($pointCount \times 3$).

**Outputs:**
- `out`: Array of float32 log-scale values.

**Steps:**
1. Iterate $i$ from 0 to $coordCount - 1$.
2. Compute:
   $$ out[i] = \frac{src[i]}{16.0} - 10.0 $$

**Pseudocode:**
```python
def unpack_scales(src, coord_count):
    """
    Decodes packed scale data from a buffer into floating-point log-scale values.
    src: Byte buffer.
    coord_count: Number of scale values (pointCount * 3).
    """
    out = [0.0] * coord_count
    for i in range(coord_count):
        out[i] = src[i] / 16.0 - 10.0
    return out
```

#### Memory Alignment / Word Alignment
Rounds up a byte count to the nearest word size.

**Inputs:**
- `byteCount`: Input byte count.
- `wordSize`: Alignment size in bytes.

**Outputs:**
- Aligned byte count.

**Steps:**
1. Compute:
   $$ \text{aligned} = \left\lceil \frac{\text{byteCount}}{\text{wordSize}} \right\rceil \times \text{wordSize} $$
   Or equivalently:
   $$ \text{aligned} = (\text{byteCount} + \text{wordSize} - 1) \ \& \ \sim(\text{wordSize} - 1) $$

**Pseudocode:**
```python
def align_up(byte_count, word_size):
    """
    Rounds up byteCount to the nearest wordSize.
    """
    return (byte_count + word_size - 1) & ~(word_size - 1)
```

#### NIfTI Analysis and Multi-Channel Debugging
Inspects NIfTI files, displaying metadata, voxel statistics, and multi-channel analysis.

**Inputs:**
- `path`: Path to NIfTI file.

**Outputs:**
- Printed statistics and metadata.

**Steps:**
1. Load NIfTI file using `nibabel`, get data as `np.float32`.
2. Describe file: path, dtype, shape, num dimensions, voxel size (mm), affine 4x4 matrix, axis orientation.
3. Describe voxel statistics: min, max, mean, std, non-zero count.
4. Describe header fields: `descrip`, `datatype`, `bitpix`, `scl_slope`, `scl_inter`, `qform_code`, `sform_code`, `xyzt_units`, `toffset`, `intent_name`, `intent_code`, `cal_min`, `cal_max`.
5. If 4D, describe multi-channel:
   - Central voxel values across channels.
   - Argmax channel.
   - Per-channel statistics.
6. If 4D, create winner-takes-all map:
   - `winner_channel = np.argmax(data, axis=3)`
   - `winner_value = np.max(data, axis=3)`
   - `hard_labels`: if `winner_value > 0`, label is `winner_channel + 1`, else 0.
   - Print histogram of winning labels.

**Pseudocode:**
```python
import nibabel as nib
import numpy as np

def analyze_nifti(path):
    """
    Inspects NIfTI files, displaying metadata, voxel statistics, and multi-channel analysis.
    """
    img = nib.load(path)
    data = img.get_fdata().astype(np.float32)
    
    # Basic metadata
    print(f"Path: {path}")
    print(f"Dtype: {data.dtype}")
    print(f"Shape: {data.shape}")
    print(f"Num Dimensions: {data.ndim}")
    print(f"Voxel Size (mm): {img.header.get_zooms()}")
    print(f"Affine:\n{img.affine}")
    
    # Voxel statistics
    finite_data = data[np.isfinite(data)]
    if finite_data.size > 0:
        print(f"Min: {finite_data.min()}, Max: {finite_data.max()}")
        print(f"Mean: {finite_data.mean()}, Std: {finite_data.std()}")
        print(f"Non-zero count: {np.count_nonzero(data)}")
        
    # Header fields
    header = img.header
    print(f"Header Keys: descrip={header.get_description()}, datatype={header.get_data_dtype()}, bitpix={header.get_bitpix()}")
    print(f"Slope/Inter: scl_slope={header.get_slope_inter()[0]}, scl_inter={header.get_slope_inter()[1]}")
    print(f"Forms: qform_code={header['qform_code']}, sform_code={header['sform_code']}")
    print(f"Units: xyzt_units={header['xyzt_units']}, toffset={header['toffset']}")
    print(f"Intent: intent_name={header['intent_name']}, intent_code={header['intent_code']}")
    print(f"Cal: cal_min={header['cal_min']}, cal_max={header['cal_max']}")
    
    # Multi-channel analysis
    if data.ndim == 4:
        print("Multi-channel analysis:")
        center = tuple(s // 2 for s in data.shape[:3])
        print(f"Central voxel values: {data[center]}")
        winner_channel = np.argmax(data, axis=3)
        winner_value = np.max(data, axis=3)
        print(f"Winner channel at center: {winner_channel[center]}")
        
        # Per-channel stats
        for c in range(data.shape[3]):
            ch_data = data[..., c]
            print(f"Channel {c}: min={ch_data.min()}, max={ch_data.max()}, mean={ch_data.mean()}, std={ch_data.std()}, non-zero={np.count_nonzero(ch_data)}")
            
        # Winner-takes-all map
        hard_labels = np.where(winner_value > 0, winner_channel + 1, 0)
        unique, counts = np.unique(hard_labels, return_counts=True)
        print("Winner-takes-all histogram:")
        for u, c in zip(unique, counts):
            print(f"Label {u}: count={c}, percentage={c/hard_labels.size*100:.2f}%")
```

## Subtopics

### [Volume Resize and Save](2904-volume-resize-and-save.md)
Performs post-processing on reconstructed 3D volumes by resizing to target dimensions, normalizing intensity, and saving as slices or raw binary. Differs from [Image Resizing Utilities](11843-image-resizing-utilities.md) by including normalization/rotation and from [Vector Normalization](3145-vector-normalization.md) by handling 3D tensors and I/O.

### [Vector Normalization](3145-vector-normalization.md)
Converts 3D vectors to unit vectors or identifies dominant axes. Differs from [Octahedral Normal Encoding](5029-octahedral-normal-encoding.md) by producing full float vectors and from [Half-Precision Float Conversion](3267-half-precision-float-conversion.md) by focusing on direction rather than bit-depth.

### [Half-Precision Float Conversion](3267-half-precision-float-conversion.md)
Converts between float32 and float16, handling subnormals, overflow, and NaNs. Differs from sibling utilities by strict numerical format conversion.

### [Image Resizing Utilities](11843-image-resizing-utilities.md)
Deterministic image array manipulation (resizing, type conversion, geometric adjustments). Enforces integer-scale operations and helpers like `make_divisible`.

## Operating characteristics
- **Time Complexity:** Most operations are $O(N)$ where $N$ is the number of voxels or bytes. `normalize_voxel_scale` involves interpolation, typically $O(N \cdot k)$ where $k$ is the kernel size (e.g., 27 for trilinear).
- **Memory Complexity:** $O(N)$ for storing the output volume. `make_nd` may create a view or copy depending on implementation.
- **Performance:** `make_nd` and `normalize_hounsfield` are very fast, limited by memory bandwidth. `normalize_voxel_scale` is slower due to interpolation. `VolPack` encoding/decoding is $O(1)$ per vector but involves complex bit manipulation.
- **Strengths:** Robust handling of edge cases (empty regions, incorrect metadata), standardized formats for downstream tools.
- **Limitations:** `normalize_voxel_scale` requires accurate metadata. `VolPack` encoding is opaque. Half-precision conversion requires careful handling of edge cases to avoid precision loss [S1, S3, unofficial].

## Background
Volume Utility Functions are not a single algorithm but a collection of utilities found in various volume rendering and medical imaging libraries. `make_nd` and `normalize_hounsfield` are common in deep learning pipelines for medical imaging (e.g., FlashDRR) [S1, unofficial]. Volume size fixing and region normalization are found in web-based volume viewers (e.g., Janelia SciComp) [S2, unofficial] and meshing libraries (e.g., MC-Meshing) [S3, unofficial]. VolPack normal encoding is part of the VolPack shading library [S4]. Memory alignment and scale unpacking are found in graphics and compression libraries (OpenVDB, SpZ) [S5][S6, unofficial]. NIfTI analysis is standard in medical imaging toolkits (NiBabel) [S7, unofficial].
