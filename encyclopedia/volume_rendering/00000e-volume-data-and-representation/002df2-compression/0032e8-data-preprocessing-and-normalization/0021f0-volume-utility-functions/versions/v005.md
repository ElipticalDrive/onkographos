# Volume Utility Functions


## Overview
Volume Utility Functions provide a collection of low-level operations for tensor manipulation, data validation, and format conversion required before or after volume rendering pipelines. They solve the problem of ensuring data consistency across heterogeneous sources (e.g., NIfTI, raw binary, web viewers) by handling dimensionality expansion, intensity normalization, voxel resampling, and memory alignment. Unlike [Volume Normalization](1823-volume-normalization.md) which focuses on statistical scaling, these functions handle structural integrity and format compatibility. They differ from [Image Resizing Utilities](11843-image-resizing-utilities.md) by including specific medical intensity handling (Hounsfield units) and 3D tensor-aware operations.

## How it works
The module comprises several distinct utility functions. The core methods are `make_nd`, `normalize_hounsfield`, and `normalize_voxel_scale`. Additional variants handle region validation, vector encoding, and memory alignment.

### Inputs and Outputs
- **`make_nd`**: Input is a tensor `t` of arbitrary dimensionality `t.ndim`. Output is a tensor of dimensionality `n`.
- **`normalize_hounsfield`**: Input is a volume `vol` (torch tensor or numpy array). Output is a volume with values clamped to $[0, 1]$.
- **`normalize_voxel_scale`**: Input is a volume `vol` and a voxel scale tensor `vox_scl` of shape $[3]$. Output is a resampled volume with new dimensions derived from `vox_scl`.
- **`vpNormalIndex` / `vpNormal`**: Input is a normalized 3D vector $(n_x, n_y, n_z)$ or a 16-bit integer. Output is a 16-bit integer or a 3D vector, respectively.
- **`AlignUp`**: Input is `byteCount` and `wordSize`. Output is the aligned byte count.
- **`Scale Unpacking`**: Input is a buffer of bytes `src`. Output is an array of floats `out`.

### Data Structures
- **Tensor**: A multi-dimensional array (e.g., PyTorch `torch.Tensor` or NumPy `ndarray`).
- **Voxel Scale**: A 1D tensor/array of length 3, representing scaling factors for X, Y, and Z axes.
- **Region Coordinates**: A tuple or array containing minimum and maximum coordinates for X, Y, and Z axes.
- **Encoded Normal**: A 16-bit integer (`int16` or `uint16`) representing a quantized 3D vector.

### Numbered Steps and Formulas

#### 1. Dimensionality Expansion (`make_nd`)
1. Check if $n < t.ndim$. If true, raise an exception.
2. While $t.ndim < n$:
   - Prepend a singleton dimension to `t`.
   - Update `t.ndim`.
3. Return `t`.

#### 2. Hounsfield Normalization (`normalize_hounsfield`)
1. If `dtype` is provided, cast `vol` to `dtype`.
2. Divide all voxel values in `vol` by 4095.
3. Clamp the resulting values to the range $[0, 1]$.
   - Formula: $v_{out} = \text{clamp}\left(\frac{v_{in}}{4095}, 0, 1\right)$.
4. Return the normalized volume.

#### 3. Voxel Scale Resampling (`normalize_voxel_scale`)
1. Calculate the new shape of the volume based on the original shape and `vox_scl`.
   - Let $S_{old} = [W, H, D]$ be the original dimensions.
   - Let $S_{new} = [W', H', D']$ be the target dimensions.
   - The relationship is determined by the voxel scale: $W' = W \times \frac{s_x}{s_{target}}$, etc. (Note: The source [S1, unofficial] states it resamples based on voxel scale using trilinear interpolation, implying a change in physical extent or resolution).
2. Perform trilinear interpolation to resample `vol` from $S_{old}$ to $S_{new}$.
3. Return the resampled volume.

#### 4. Normal Vector Encoding/Decoding (`vpNormalIndex` / `vpNormal`)
1. **Encoding**:
   - Input: Normalized vector $(n_x, n_y, n_z)$ such that $n_x^2 + n_y^2 + n_z^2 = 1$.
   - Compute a 16-bit integer index using the VolPack encoding scheme [S4].
2. **Decoding**:
   - Input: 16-bit integer `n`.
   - Decode `n` back into components $(n_x, n_y, n_z)$ stored at provided pointers [S4].

#### 5. Region Normalization and Validation
1. Extract minimum coordinates $(min_x, min_y, min_z)$ and maximum coordinates $(max_x, max_y, max_z)$ from the region.
2. Clamp minimum coordinates:
   - $min_x, min_z \leftarrow \text{clamp}(min, \text{FIRST\_INDEX}, \text{CHUNK\_SIZE})$
   - $min_y \leftarrow \text{clamp}(min, \text{FIRST\_INDEX}, \text{height})$
3. Clamp maximum coordinates:
   - $max_x, max_z \leftarrow \text{clamp}(max, min_x, \text{CHUNK\_SIZE})$
   - $max_y \leftarrow \text{clamp}(max, min_y, \text{height})$
4. Check if the region is empty:
   - If $min_i \ge max_i$ for any axis $i \in \{x, y, z\}$, the region is empty.
5. Return the clamped region or an empty indicator.

#### 6. Memory Alignment (`AlignUp`)
1. Input: `byteCount` (uint64), `wordSize` (uint64).
2. Calculate aligned size:
   - Formula: $\text{aligned} = \left\lceil \frac{\text{byteCount}}{\text{wordSize}} \right\rceil \times \text{wordSize}$.
   - Implementation: `(byteCount + wordSize - 1) // wordSize * wordSize` using integer division.
3. Return `aligned`.

#### 7. Scale Unpacking
1. Input: Byte buffer `src`, integer `coordCount` (where `coordCount = pointCount * 3`).
2. Initialize output array `out` of size `coordCount`.
3. For each index $i$ from 0 to `coordCount - 1`:
   - $out[i] = \frac{src[i]}{16.0} - 10.0$.
4. Return `out`.

import numpy as np

def make_nd(t: torch.Tensor, n: int) -> torch.Tensor:
    """
    Prepends singleton dimensions to tensor t until it is n-dimensional.
    Raises exception if n < t.ndim.
    """
    if n < t.ndim:
        raise ValueError(f"Target dimension {n} is less than current dimension {t.ndim}")
    
    while t.ndim < n:
        t = t.unsqueeze(0)
    return t

def normalize_hounsfield(vol, dtype=None):
    """
    Normalizes volume by 4095 and clamps to [0, 1].
    Handles torch tensors and numpy arrays.

    return vol

def clamp_region(region_min, region_max, chunk_size, height, first_index=0):
    """
    Clamps region coordinates to valid chunk bounds.
    """
    min_x, min_y, min_z = region_min
    max_x, max_y, max_z = region_max
    
    # Clamp min
    min_x = max(first_index, min_x)
    min_y = max(first_index, min_y)
    min_z = max(first_index, min_z)

### Parameters with Typical Values
- **`n`** (in `make_nd`): Typically 3, 4, or 5 for volume data (e.g., batch, channel, depth, height, width).
- **`vox_scl`**: Shape $[3]$. Values depend on the desired physical voxel size (e.g., $[1.0, 1.0, 1.0]$ mm).
- **`wordSize`**: Typically 4, 8, or 16 bytes, depending on the architecture.
- **`FIRST_INDEX`**: Typically 0.
- **`CHUNK_SIZE`**: Varies by implementation, often a power of 2 (e.g., 64, 128).

### Edge Cases and Pitfalls
- **`make_nd`**: If $n < t.ndim$, an exception is raised. Implementers must check dimensions before calling.
- **`normalize_hounsfield`**: Division by 4095 assumes the input data is in Hounsfield Units (HU) with a range of approximately -1000 to 3000. If the data is not HU, the normalization is incorrect.
- **`normalize_voxel_scale`**: Trilinear interpolation may introduce artifacts if the volume contains sharp edges or non-continuous data.
- **Region Validation**: If the original file's `image_size[2]` is incorrect, the calculated `realFrameCount` may differ from the stored size, requiring correction [S2, unofficial].
- **Scale Unpacking**: The formula $out[i] = src[i] / 16.0 - 10.0$ assumes a specific quantization scheme. Deviations will result in incorrect scale values.

## Subtopics

### [Volume Resize and Save](2904-volume-resize-and-save.md)
This method performs post-processing on a reconstructed 3D volume by resizing it to a target dimension, normalizing intensity values, and optionally saving the data as image slices or raw binary files. It solves the problem of converting raw reconstruction outputs into standardized formats for visualization or downstream analysis. It differs from [Image Resizing Utilities](11843-image-resizing-utilities.md) by including specific normalization and rotation steps, and from [Vector Normalization](3145-vector-normalization.md) by handling 3D tensor structures and file I/O.

### [Vector Normalization](3145-vector-normalization.md)
Vector Normalization converts a 3D vector into a unit vector, or returns a zero vector if the input magnitude is below a precision threshold. Some implementations modify the input vector in place rather than returning a new instance. It is used to process direction data such as sun vectors.

### [Half-Precision Float Conversion](3267-half-precision-float-conversion.md)
This method converts between 32-bit IEEE 754 single-precision floats and 16-bit binary16 half-precision floats, and vice versa. It solves the problem of reducing memory bandwidth and storage for volume data while maintaining sufficient precision for rendering, avoiding undefined behavior associated with direct type punning. Unlike sibling utilities that normalize vectors or resize images, this method performs strict numerical format conversion with specific handling for subnormal numbers, overflow, and NaN preservation.

### [Image Resizing Utilities](11843-image-resizing-utilities.md)
Image Resizing Utilities provide a suite of deterministic functions for manipulating image tensors, including resizing (downsampling, upsampling, rescaling), type conversion, and geometric adjustments. They solve the problem of preparing image data for downstream volume rendering or NeRF training pipelines by ensuring consistent data types and dimensions. What sets this implementation apart from general-purpose libraries is its strict adherence to integer-scale operations where possible to avoid interpolation artifacts, and its integration with camera parameter scaling to maintain geometric consistency between resized images and their corresponding camera intrinsics.

### Volume Size Fixing
Corrects the volume size's Z dimension (frame count) based on the actual data byte length and X/Y dimensions, handling cases where the stored image_size[2] is incorrect.
- **Step**: Calculate `realFrameCount` as `data.byteLength` divided by `(volumeSize[0] * volumeSize[1])`. If `realFrameCount` does not equal `volumeSize[2]`, log a warning and update `volumeSizeFixed[2]` to `realFrameCount`. Return `volumeSizeFixed`.
- **Pitfall**: The original file's `image_size[2]` attribute may be wrong, requiring correction based on actual data size [S2, unofficial].

### Region Normalization and Validation
Utility functions to clamp region coordinates to valid chunk bounds and check if a region is empty.
- **Step**: Extract min and max coordinates from the region. Clamp min coordinates: X and Z to `[FIRST_INDEX, CHUNK_SIZE]`, Y to `[FIRST_INDEX, height]`. Clamp max coordinates: X and Z to `[minX, CHUNK_SIZE]`, Y to `[minY, height]`. Check if region is empty by comparing min and max coordinates; if `min >= max` in any axis, the region is empty.
- **Parameter**: `FIRST_INDEX`: The minimum valid index for chunk coordinates [S3, unofficial].

### VolPack Normal Vector Encoding/Decoding
A function to encode a normalized 3D vector into a 16-bit integer format expected by VolPack shaders, and a function to decode a 16-bit encoded normal back into its vector components.
- **Step**: Call `int vpNormalIndex(double nx, double ny, double nz)` where `nx, ny, nz` are normalized components (`nx*nx + ny*ny + nz*nz == 1`). Returns a 16-bit encoded normal. Call `vpResult vpNormal(int n, double *nx, double *ny, double *nz)` to decode the encoded normal `n` into the components stored at the provided pointers [S4].

### Memory Alignment / Word Alignment
Rounds up `byteCount` to the nearest `wordSize`.
- **Parameter**: `wordSize`: Alignment size in bytes. `byteCount`: Input byte count [S5].

### Scale Unpacking
Decodes packed scale data from a buffer into floating-point log-scale values.
- **Step**: Iterate `coordCount` (`pointCount * 3`). For each byte `src[i]`, compute `out[i] = src[i] / 16.0f - 10.0f` [S6, unofficial].

### NIfTI Analysis and Multi-Channel Debugging
A Python script `analyze.py` for inspecting NIfTI files, displaying metadata, voxel statistics, multi-channel analysis, and winner-takes-all (argmax) labelmap simulation.
- **Step**: `load_nifti(path)`: Load NIfTI file using nibabel, get `fdata` as `np.float32`. `describe_nifti(img, data, name)`: Print file path, dtype, shape, num dimensions, voxel size (mm), affine 4x4 matrix, axis orientation, finite voxel statistics (min, max, mean, std, non-zero count), and header key fields (descrip, datatype, bitpix, scl_slope, scl_inter, qform_code, sform_code, xyzt_units, toffset, intent_name, intent_code, cal_min, cal_max). `describe_multichannel(data, name)`: If data is 4D, print central voxel values across all channels, argmax channel, and per-channel statistics (min, max, mean, std, non-zero voxels, percentage, value at center, distinct values sample). `describe_multichannel_as_winner_map(data, name)`: If data is 4D, compute `winner_channel = np.argmax(data, axis=3)` and `winner_value = np.max(data, axis=3)`. Create `hard_labels`: if `winner_value > 0`, label is `winner_channel + 1`, else 0. Print histogram of winning labels with counts and percentages [S7, unofficial].

## Operating characteristics
- **Time Complexity**:
  - `make_nd`: $O(1)$ (dimensionality check and unsqueeze operations are constant time relative to data size).
  - `normalize_hounsfield`: $O(N)$ where $N$ is the number of voxels.
  - `normalize_voxel_scale`: $O(N \cdot M)$ where $N$ is the number of output voxels and $M$ is the number of neighbors for interpolation (typically 8 for trilinear).
  - `AlignUp`: $O(1)$.
  - `Scale Unpacking`: $O(N)$ where $N$ is the number of scale values.
- **Memory Complexity**:
  - `make_nd`: $O(1)$ additional memory (in-place or shallow copy).
  - `normalize_hounsfield`: $O(N)$ if a new array is created, $O(1)$ if in-place.
  - `normalize_voxel_scale`: $O(N_{new})$ for the output volume.
  - `AlignUp`: $O(1)$.
  - `Scale Unpacking`: $O(N)$ for the output array.
- **Strengths**:
  - Handles diverse input formats (torch, numpy, raw bytes).
  - Provides essential validation and correction for corrupted or inconsistent data.
  - Efficient memory alignment and scale unpacking for high-performance rendering.
- **Limitations**:
  - `normalize_voxel_scale` may introduce interpolation artifacts.
  - `normalize_hounsfield` is specific to medical imaging data (HU).
  - `Scale Unpacking` assumes a specific quantization scheme.
- **When to Use**:
  - Before rendering: Normalize intensities, align memory, and ensure correct dimensions.
  - After reconstruction: Resize, save, and validate output volumes.
  - When dealing with heterogeneous data sources requiring standardization.
- **When Not to Use**:
  - For general-purpose image processing where specific volume rendering constraints do not apply.
  - When high-precision interpolation is required and trilinear is insufficient (consider higher-order interpolation).

## Background
Volume Utility Functions are a collection of utilities found in various open-source volume rendering and medical imaging libraries. The `make_nd` and `normalize_hounsfield` functions are part of the `flashdrr` library [S1, unofficial]. The `Volume Size Fixing` and `Region Normalization` utilities are from the `web-vol-viewer` [S2, unofficial] and `mc-meshing` [S3, unofficial] projects, respectively. The VolPack normal vector encoding/decoding is documented in the VolPack User's Guide [S4]. Memory alignment utilities are part of the OpenVDB library [S5]. Scale unpacking is used in the `spz` library [S6, unofficial]. NIfTI analysis tools are part of the `vrdf-sdk` [S7, unofficial]. These utilities address common pain points in volume data handling, such as dimensionality mismatches, intensity scaling, and memory alignment.
