# Power-of-2 Ceiling Padding

Also called: Power-of-two volume padding, padOut, pow2Celing

## Overview
Power-of-2 Ceiling Padding is a data preprocessing step that expands a volume dataset's dimensions to the next power of two if they are not already powers of two. This is primarily required to satisfy GPU texture hardware constraints or specific rendering algorithms that mandate power-of-two dimensions [S1, unofficial]. It differs from general volume resizing by strictly enforcing power-of-two boundaries without interpolation, preserving the original data integrity in the padded region.

## How it works
**Inputs:**
- Original volume dimensions: $sx, sy, sz$ (integers).
- Original physical spacings: $xfSize, yfSize, zfSize$ (floats).
- Original data buffer: `currentData` of size $sx \times sy \times sz \times nelts$.
- Original gradient buffer: `currentGrad` of size $sx \times sy \times sz \times 3$.
- `nelts`: Number of elements per voxel (e.g., 1 for scalar, 3 for gradient) [S1, unofficial].

**Outputs:**
- New dimensions: $nx, ny, nz$ (powers of two).
- New data buffer: `newdata0` of size $nx \times ny \times nz \times nelts$.
- New gradient buffer: `newgrad` of size $nx \times ny \times nz \times 3$.
- Updated physical spacings: $xfSize, yfSize, zfSize$.

**Data Structures:**
- Buffers are contiguous arrays. The layout is row-major (or linearized) with the innermost index being the voxel component (if $nelts > 1$) or the Z-dimension, depending on the specific implementation's memory layout assumption. The source code implies a linear index calculation: `index = (z * ny + y) * nx + x` for the padded space, mapping to `old_index = (z * sx + y) * sx + x` for the original space.

**Steps:**
1. **Check Power-of-Two:** Determine if $sx, sy, sz$ are powers of two.
   - *Note:* The source implementation uses a numerically fragile floating-point check `isPow2` which divides by 2.0 repeatedly. A robust integer implementation should use bitwise operations: `(n & (n - 1)) == 0` and `n > 0` [S1, unofficial][G].
   - *Pitfall:* The source code contains a bug where it checks `!isPow2(sx)` three times, ignoring $sy$ and $sz$. Correct logic must check all three dimensions [S1, unofficial].
2. **Compute Ceiling:** If any dimension is not a power of two, compute the next power of two for each:
   $$ nx = \text{nextPow2}(sx) $$
   $$ ny = \text{nextPow2}(sy) $$
   $$ nz = \text{nextPow2}(sz) $$
   Where $\text{nextPow2}(n)$ returns the smallest power of two greater than or equal to $n$. If $n$ is already a power of two, it returns $n$.
3. **Allocate Buffers:** Allocate `newdata0` of size $nx \times ny \times nz \times nelts$ and `newgrad` of size $nx \times ny \times nz \times 3$. Initialize all elements to zero.
4. **Copy Data:** Copy the original data from `currentData` into `newdata0` at the corresponding indices. The mapping preserves the spatial origin (typically $(0,0,0)$).
   $$ \text{newdata0}[z \cdot ny \cdot nx \cdot nelts + y \cdot nx \cdot nelts + x \cdot nelts + c] = \text{currentData}[z \cdot sy \cdot sx \cdot nelts + y \cdot sx \cdot nelts + x \cdot nelts + c] $$
   for $0 \le x < sx, 0 \le y < sy, 0 \le z < sz$.
   Similarly for gradients if present.
5. **Update Dimensions:** Set $sx = nx, sy = ny, sz = nz$.
6. **Scale Physical Spacings:** Adjust the physical size parameters to maintain the correct world-space extent relative to the new grid density, or as defined by the specific rendering engine's coordinate system. The source formula is:
   $$ xfSize_{new} = xfSize_{old} \times \frac{nx}{sx_{old}} $$
   $$ yfSize_{new} = yfSize_{old} \times \frac{ny}{sy_{old}} $$
   $$ zfSize_{new} = zfSize_{old} \times \frac{nz}{sz_{old}} $$
   *Note:* This scaling effectively changes the voxel size in world units if the physical size represents the total extent, or adjusts the sampling rate. The source code applies this scaling to `xfSize`, `yfSize`, `zfSize` variables which appear to represent the total physical dimensions or a related scaling factor [S1, unofficial].

**Pseudocode:**
```python
def next_pow2(n):
    """Returns the smallest power of 2 >= n."""
    if n <= 0:
        return 1
    p = 1
    while p < n:
        p <<= 1
    return p

def is_pow2(n):
    """Returns True if n is a power of 2."""
    return n > 0 and (n & (n - 1)) == 0

def power_of_2_ceiling_padding(current_data, current_grad, sx, sy, sz, nelts, xf_size, yf_size, zf_size):
    """
    Pads volume data to next power of 2 dimensions.
    
    Args:
        current_data: 1D array of size sx * sy * sz * nelts
        current_grad: 1D array of size sx * sy * sz * 3
        sx, sy, sz: Original dimensions
        nelts: Elements per voxel
        xf_size, yf_size, zf_size: Physical size parameters
        
    Returns:
        new_data, new_grad, new_sx, new_sy, new_sz, new_xf_size, new_yf_size, new_zf_size
    """
    # Step 1 & 2: Compute new dimensions
    nx = next_pow2(sx)
    ny = next_pow2(sy)
    nz = next_pow2(sz)
    
    # If already power of 2, no padding needed (but spacing might still be scaled if logic dictates, 
    # though typically scaling is only for the expansion factor)
    if nx == sx and ny == sy and nz == sz:
        return current_data, current_grad, sx, sy, sz, xf_size, yf_size, zf_size

    # Step 3: Allocate new buffers
    new_data_size = nx * ny * nz * nelts
    new_grad_size = nx * ny * nz * 3
    
    new_data = [0.0] * new_data_size
    new_grad = [0.0] * new_grad_size
    
    # Step 4: Copy original data
    # Assuming row-major order: z, y, x, component
    for z in range(sz):
        for y in range(sy):
            for x in range(sx):
                # Calculate indices
                old_idx = ((z * sy + y) * sx + x) * nelts
                new_idx = ((z * ny + y) * nx + x) * nelts
                
                # Copy data elements
                for c in range(nelts):
                    new_data[new_idx + c] = current_data[old_idx + c]
                
                # Copy gradient elements (if applicable)
                if current_grad is not None:
                    old_grad_idx = ((z * sy + y) * sx + x) * 3
                    new_grad_idx = ((z * ny + y) * nx + x) * 3
                    for g in range(3):
                        new_grad[new_grad_idx + g] = current_grad[old_grad_idx + g]

    # Step 5: Update dimensions
    new_sx, new_sy, new_sz = nx, ny, nz
    
    # Step 6: Scale physical spacings
    # Formula from source: xfSize *= sx / xiSize (where xiSize is old sx)
    new_xf_size = xf_size * (nx / sx)
    new_yf_size = yf_size * (ny / sy)
    new_zf_size = zf_size * (nz / sz)
    
    return new_data, new_grad, new_sx, new_sy, new_sz, new_xf_size, new_yf_size, new_zf_size
```

## Operating characteristics
- **Time Complexity:** $O(nx \cdot ny \cdot nz)$ for allocation and zero-initialization, plus $O(sx \cdot sy \cdot sz)$ for copying. Since $nx \ge sx$, the complexity is dominated by the padded volume size.
- **Memory Complexity:** Increases by a factor of $\frac{nx \cdot ny \cdot nz}{sx \cdot sy \cdot sz}$. For dimensions just above a power of two, this can be up to $8\times$ the original memory usage (e.g., $129 \to 256$).
- **Strengths:** Ensures compatibility with hardware requiring power-of-two textures. Simple to implement.
- **Limitations:** Significant memory overhead for non-power-of-two volumes. The source implementation's floating-point `isPow2` check is numerically fragile for large integers [S1, unofficial]. The bug in checking only $sx$ is a critical pitfall in the reference implementation [S1, unofficial].

## Background
This method is part of the preprocessing pipeline in the Simian Spacemonkey volume rendering system, developed by Joe Kniss around 2001. It addresses the limitations of early GPU texture hardware which often required power-of-two dimensions for 3D textures [S1, unofficial].
