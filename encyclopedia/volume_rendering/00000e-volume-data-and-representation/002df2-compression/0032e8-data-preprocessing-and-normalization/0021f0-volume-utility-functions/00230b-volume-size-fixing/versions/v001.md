# Volume Size Fixing

Also called: Correct Volume Z Dimension, Fix Frame Count

## Overview
Volume Size Fixing corrects the Z dimension (frame count) of a volume dataset when the stored metadata `image_size[2]` is inconsistent with the actual binary data length [S1, unofficial]. It solves the problem of corrupted or malformed volume headers that would otherwise cause rendering artifacts or memory access errors. Unlike [Volume Resize and Save](2904-volume-resize-and-save.md), which alters spatial resolution, this method strictly adjusts the frame count to match the data payload without interpolation or spatial resampling.

## How it works
**Inputs and Outputs:**
- Input: `data` (binary buffer containing volume data), `volumeSize` (array `[X, Y, Z]` from metadata).
- Output: `volumeSizeFixed` (corrected array `[X, Y, Z']`).

**Data Structures:**
- `volumeSize`: Array of 3 integers representing width, height, and frame count.
- `data`: Byte array or buffer. `data.byteLength` provides total bytes.

**Steps:**
1. Calculate the expected number of frames (`realFrameCount`) using the total byte length and the X/Y dimensions. Assuming a single byte per voxel (common in raw volume formats like those in `web-vol-viewer`), the formula is:
   $$ \text{realFrameCount} = \left\lfloor \frac{\text{data.byteLength}}{\text{volumeSize}[0] \times \text{volumeSize}[1]} \right\rfloor $$
   [S1, unofficial]
2. Compare `realFrameCount` with the stored `volumeSize[2]`.
3. If `realFrameCount != volumeSize[2]`, log a warning indicating a metadata mismatch.
4. Set `volumeSizeFixed[2] = realFrameCount`.
5. Return `volumeSizeFixed`.

**Pitfalls:**
- The original file's `image_size[2]` attribute may be incorrect, requiring correction based on actual data size [S1, unofficial].
- This method assumes a fixed byte-per-voxel format. If the volume uses multi-byte types (e.g., 16-bit floats), the divisor must account for the element size. The source implies 1-byte elements [S1, unofficial].

**Pseudocode:**
```python
def fix_volume_size(data, volume_size):
    """
    Corrects the Z dimension of a volume based on actual data length.
    
    Args:
        data: Buffer or array with byteLength property.
        volume_size: List or tuple [width, height, stored_z].
        
    Returns:
        List [width, height, corrected_z].
    """
    width = volume_size[0]
    height = volume_size[1]
    stored_z = volume_size[2]
    
    # Calculate area of one frame
    frame_area = width * height
    
    # Avoid division by zero
    if frame_area == 0:
        raise ValueError("Volume width or height cannot be zero.")
        
    # Calculate real frame count based on byte length
    # Assumes 1 byte per voxel as per source context
    real_frame_count = data.byteLength // frame_area
    
    # Check for mismatch
    if real_frame_count != stored_z:
        print(f"Warning: Stored Z ({stored_z}) does not match calculated Z ({real_frame_count}). Correcting.")
        
    # Return fixed size
    return [width, height, real_frame_count]
```

## Subtopics

### [Power-of-2 Ceiling Padding](22070-power-of-2-ceiling-padding.md)
Expands dimensions to power-of-two boundaries. Chosen when GPU hardware constraints require power-of-two textures. Differs by enforcing spatial boundaries rather than correcting metadata consistency.

## Operating characteristics
- **Time Complexity:** $O(1)$ arithmetic operations.
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Strengths:** Fast, non-destructive to data content, fixes critical header errors.
- **Limitations:** Only corrects the Z dimension; does not handle X/Y mismatches or multi-byte voxel formats without modification.
- **When to use:** When loading raw volume data where metadata is known to be unreliable or manually edited.

## Background
Originated in the `web-vol-viewer` project by JaneliaSciComp [S1, unofficial]. It addresses common issues in web-based volume visualization where raw binary data is loaded without strict schema validation, leading to discrepancies between file headers and actual byte counts.
