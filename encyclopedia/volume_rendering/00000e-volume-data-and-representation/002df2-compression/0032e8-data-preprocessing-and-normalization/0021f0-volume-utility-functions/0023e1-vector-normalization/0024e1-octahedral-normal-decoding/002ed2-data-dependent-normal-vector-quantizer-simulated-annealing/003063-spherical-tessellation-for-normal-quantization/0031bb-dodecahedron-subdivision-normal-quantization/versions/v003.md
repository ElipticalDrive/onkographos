# Dodecahedron Subdivision Normal Quantization

Also called: Static Normal Vector Quantizer (Dodecahedron Subdivision)

## Overview
A static method for generating a fixed set of normal vector directions by tessellating a unit sphere using a subdivided regular dodecahedron [S1]. It solves the problem of directional aliasing in volume rendering by providing a nearly uniform distribution of 240 quantized normal vectors [S1][S2, unofficial]. It sets itself apart from octahedron-based quantizers by using triangles that are more nearly planar and undergo less distortion during subdivision, avoiding the retention of 90° angles that cause uneven gradient distribution [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A continuous 3D gradient vector $\mathbf{g}$ (or any direction vector).
*   **Output:** A quantized normal vector $\mathbf{n}_q$ from a predefined set of 240 unit vectors.

**Data Structures:**
*   **Quantization Table:** A static array of 240 precomputed unit vectors. These vectors correspond to the centers of gravity of the 240 triangles in the tessellated sphere.
*   **Index Mapping:** A lookup mechanism (e.g., a hash map or spatial partitioning) to map an input vector to one of the 240 indices.

**Steps:**
1.  **Generate Base Geometry:** Start with a regular dodecahedron inscribed in a unit sphere.
2.  **Initial Tessellation:** Subdivide the dodecahedron into 60 triangles. This is achieved by triangulating each of the 12 pentagonal faces uniformly [S1][S2, unofficial].
3.  **Recursive Subdivision:** Subdivide each of the 60 triangles into four smaller triangles. This is typically done by connecting the midpoints of the edges or using a standard barycentric subdivision scheme [S1][S2, unofficial].
4.  **Projection:** Project the vertices of the resulting 240 triangles onto the unit sphere surface [S1].
5.  **Compute Centers:** Calculate the center of gravity (centroid) for each of the 240 triangles. Normalize these centroids to unit length to form the final set of 240 quantization vectors [S1][S2, unofficial].
6.  **Quantization:** For any input gradient vector $\mathbf{g}$:
    a. Determine which of the 240 triangles on the sphere the vector $\mathbf{g}$ falls into.
    b. Quantize $\mathbf{g}$ to the precomputed center of gravity of that respective triangle [S1].

**Parameters:**
*   **Total Normal Vectors:** 240. Derived from $60 \times 4$ triangles [S1].
*   **Angular Resolution:** The angle between two adjacent normals is approximately 23 degrees [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Directional Aliasing:** If the number of vectors (240) is insufficient for the required visual fidelity, strong "directional aliasing" artifacts may appear in the rendered image [S1].
*   **Hardware Limits:** Standard hardware color maps often support 256 entries. This method uses 240, leaving 16 entries unused or requiring padding if strict 256-entry alignment is needed [S1].
*   **Static Nature:** Because the quantizer is static and data-independent, it may not be optimal for datasets with specific, non-uniform gradient distributions compared to data-dependent methods like Simulated Annealing [S1].

## Subtopics

### [Gradient Quantization via Polyhedron Tesselation](6591-gradient-quantization-via-polyhedron-tesselation.md)
Gradient Quantization via Polyhedron Tesselation quantizes the 3D gradient direction space into a finite set of unit vectors by tessellating a unit sphere with triangles derived from an icosahedron and its dual, the dodecahedron. It solves the problem of uneven distribution of normal vectors for directional lighting in volume rendering, which arises when using simpler polyhedra like the octahedron. It sets itself apart from octahedron-based methods by using triangles that are more nearly planar and undergo less distortion during subdivision, avoiding the retention of 90° angles that cause uneven gradient distribution.

### Point-Based Data Encoding with Quantized Normals
A storage scheme for voxel data that reduces file size by quantizing surface normals to 240 discrete directions and storing positions relative to the first valid point [S2, unofficial]. It quantizes normals using the 240 points generated by the dodecahedron subdivision method [S2, unofficial]. It stores point positions relative to the first valid point, determining the number of bytes per dimension based on the bounding box size of all valid data-points [S2, unofficial]. It stores only the number of points for each z-plane, with the z-value given implicitly, followed by the x- and y-coordinates of the corresponding points [S2, unofficial]. The worst-case storage is calculated as:
$$ \text{Storage} \approx (\#colors \times \#slices \times \text{sizeof(counter)}) + (\#points \times 1 \text{ byte normal}) + (\#points \times 3 \text{ bytes xy}) \text{ bytes} $$
For example, with 255 colors, 4096 slices, and $4096^3$ points, this equals approximately 256 Gigabytes [S2, unofficial]. A pitfall is that background noise in datasets can inflate histogram counts and storage requirements; this is handled by using background-images to zero out histogram entries for background colors before encoding [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Quantization is $O(N)$ where $N=240$ is the number of normals, or $O(1)$ if a spatial hash or lookup table is used to map vectors to indices.
*   **Memory Complexity:** The quantization table requires storage for 240 vectors. If stored as 3 floats per vector, this is $240 \times 12 = 2880$ bytes. If stored as indices into a 256-entry color map, it is negligible.
*   **Measured Performance:** In a point-based encoding scheme, using 1 byte for the normal index reduces the per-voxel overhead compared to storing full 3-byte normals [S2, unofficial].
*   **Strengths:** Provides a nearly uniform distribution of normals, reducing directional aliasing compared to octahedral quantization [S1][S2, unofficial]. Simple to implement and static.
*   **Limitations:** Static distribution may not be optimal for all datasets. 240 vectors may cause visible aliasing in high-resolution renders if not sufficient [S1].
*   **When to use:** When a static, uniform normal quantization is sufficient and hardware supports 256-entry color maps.
*   **When not to use:** When data-dependent optimization is required for better visual quality (use Simulated Annealing variant) or when higher precision is needed.

## Background
The method originates from the Voltx project and related interactive volume rendering research [S1][S2, unofficial]. It was introduced as a static normal vector quantizer to minimize directional aliasing artifacts in volume rendering [S1]. The approach was compared to octahedral quantization, noting the superior uniformity of the dodecahedron-based tessellation [S1][S2, unofficial]. It is used in point-based rendering and out-of-core visualization of large datasets [S2, unofficial].
