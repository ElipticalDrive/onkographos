# Octahedral Direction Encoding for Gradient Storage

Also called: Octahedral Normal Quantization, Octahedral Sphere Subdivision for Gradients, Precomputed Gradient Storage with Octahedral Direction Encoding

## Overview
Octahedral Direction Encoding is a technique to reduce memory usage for precomputed volume gradients by quantizing direction using uniform fractal subdivision of an octahedron into a sphere, rather than storing raw floating-point vectors [S1, book]. It solves the problem of excessive memory consumption in gradient-based volume rendering methods, where storing full 3D gradient vectors for every voxel is prohibitive [S1, book]. It sets itself apart from naive component-wise quantization by providing a uniform distribution of directions on the sphere, avoiding the clustering artifacts inherent in dividing bits among three independent components [S1, book].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D gradient direction vector.
*   **Output:** An integer index representing the quantized direction [S1, book].

**Data Structures:**
*   **Index Table:** An array mapping normalized direction vectors to integer indices [S1, book].
*   **Storage Type:** Unsigned short (16-bit) is sufficient for typical recursion depths [S1, book].
*   **Table Size:** For recursion depth 6, the table contains 16,642 indices representing 16,386 unique directions [S1, book].

**Algorithm Steps:**

1.  **Tessellation Generation:** Generate vertices by recursively replacing each triangle with four new triangles, where the recursion depth determines the resolution [S1, book].
2.  **Projection:** Map vector directions (rays from sphere center through vertices) to indices by pushing vertices back onto original octahedron faces [S1, book].
3.  **Flattening:** Flatten the sphere onto the plane $z=0$ [S1, book].
4.  **Rotation:** Rotate the resulting grid by $45^\circ$ [S1, book].
5.  **Indexing:** Label vertices with indices starting at 0 at top-left, continuing across rows then down columns [S1, book].
6.  **Hemisphere Split:** Use indices 0 through 40 for positive $z$ components (half the normals) and indices 41 through 81 for negative $z$ components [S1, book].
7.  **Edge Handling:** Vertices on edges represent vectors with no $z$ component; represent them with two indices to keep the scheme consistent [S1, book].

**Pseudocode:**

```python
import math

def normalize(v):
    mag = math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    if mag == 0: return (0.0, 0.0, 0.0)
    return (v[0]/mag, v[1]/mag, v[2]/mag)

def project_to_octahedron(v):
    """Push unit vector v back onto the surface of the original octahedron."""
    x, y, z = v
    abs_x, abs_y, abs_z = abs(x), abs(y), abs(z)
    max_abs = max(abs_x, abs_y, abs_z)
    if max_abs == 0: return (0.0, 0.0, 0.0)
    return (x / max_abs, y / max_abs, z / max_abs)

def generate_lookup_table(recursion_depth):
    """Generates the index lookup table following the source steps."""
    # Step 1: Generate vertices by recursively replacing each triangle with four new triangles
    base_triangles = [
        ((1,0,0), (0,1,0), (0,0,1)), ((1,0,0), (0,0,1), (0,-1,0)),
        ((1,0,0), (0,-1,0), (0,0,-1)), ((1,0,0), (0,0,-1), (0,1,0)),
        ((-1,0,0), (0,0,1), (0,1,0)), ((-1,0,0), (0,-1,0), (0,0,1)),
        ((-1,0,0), (0,0,-1), (0,-1,0)), ((-1,0,0), (0,1,0), (0,0,-1))
    ]
    current_triangles = base_triangles
    vertices = set()
    for _ in range(recursion_depth):
        new_triangles = []
        for t in current_triangles:
            v0, v1, v2 = t
            m0 = normalize((v0[0]+v1[0], v0[1]+v1[1], v0[2]+v1[2]))
            m1 = normalize((v1[0]+v2[0], v1[1]+v2[1], v1[2]+v2[2]))
            m2 = normalize((v2[0]+v0[0], v2[1]+v0[1], v2[2]+v0[2]))
            new_triangles.extend([(v0, m0, m2), (m0, v1, m1), (m2, m1, v2), (m0, m1, m2)])
        current_triangles = new_triangles
        for t in current_triangles:
            vertices.add(t[0]); vertices.add(t[1]); vertices.add(t[2])

    # Step 2: Map vector directions to indices by pushing vertices back onto original octahedron faces
    projected = [project_to_octahedron(v) for v in vertices]

    # Step 3: Flatten the sphere onto the plane z=0
    # Step 4: Rotate the resulting grid by 45 degrees
    cos_a, sin_a = math.cos(math.radians(45)), math.sin(math.radians(45))
    rotated = []
    for p in projected:
        x, y, z = p
        rotated.append((x * cos_a - y * sin_a, x * sin_a + y * cos_a, z))

    # Step 5 & 6: Label vertices starting at 0 at top-left, across rows then down columns
    # Separate by z-component sign as per evidence
    pos_verts = [p for p in rotated if p[2] >= 0]
    neg_verts = [p for p in rotated if p[2] < 0]

    # Sort to match grid traversal (top-left to bottom-right)
    pos_verts.sort(key=lambda p: (-p[1], p[0]))
    neg_verts.sort(key=lambda p: (-p[1], p[0]))

    lookup_table = {}
    idx = 0
    for p in pos_verts:
        lookup_table[normalize(p)] = idx
        idx += 1
    for p in neg_verts:
        lookup_table[normalize(p)] = idx
        idx += 1

    return lookup_table

def encode_gradient(gradient, lookup_table):
    """Encodes a 3D gradient vector to an octahedral index."""
    norm = math.sqrt(gradient[0]**2 + gradient[1]**2 + gradient[2]**2)
    if norm == 0: return 0
    v = (gradient[0]/norm, gradient[1]/norm, gradient[2]/norm)
    # Find nearest vertex in lookup table
    best_idx = 0
    best_dist = float('inf')
    for dir_v, idx in lookup_table.items():
        dist = (v[0]-dir_v[0])**2 + (v[1]-dir_v[1])**2 + (v[2]-dir_v[2])**2
        if dist < best_dist:
            best_dist = dist
            best_idx = idx
    return best_idx

def decode_index(index, lookup_table_reverse):
    """Decodes an index back to an approximate direction vector."""
    return lookup_table_reverse[index]
```

**Parameters:**
*   **Recursion Depth:** Determines the number of quantization levels. Depth 6 is a common choice, yielding 16,642 indices [S1, book].
*   **Storage Type:** Unsigned short (16-bit) is sufficient for depth 6 [S1, book].

**Edge Cases and Pitfalls:**
*   **Zero Z-Component:** Vertices on the edges of the octahedron have a zero $z$ component. The scheme uses two indices for these to maintain consistency, rather than a single index [S1, book].
*   **Precision:** Floating-point comparisons for direction matching may require tolerance or nearest-neighbor search [G].
*   **Memory:** While reduced compared to full float storage, the lookup table itself consumes memory. For depth 6, the table size is manageable [S1, book].

## Subtopics

### Gradient Direction Encoding via Octahedron Flattening
A method to encode 3D gradient directions into a compact index by flattening an octahedron, using two sets of indices to handle positive and negative z-components [S1, book]. It uses indices 0 through 40 to represent vectors with a positive or zero z component, where index 40 is at the lower right vertex [S1, book]. It uses indices 41 through 81 to represent vectors with a negative z component [S1, book]. For vertices on the edges (vectors with no z component), it uses two indices instead of one to keep the indexing scheme consistent [S1, book]. Storage type is unsigned short [S1, book]. Recursion depth is 6 when generating vertices with unsigned short storage [S1, book]. Degenerate edge cases (vectors with zero z component) are handled by duplicating indices to maintain consistency, rather than using a single index [S1, book]. With recursion depth 6, there are 16,642 indices representing 16,386 unique directions [S1, book].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Naive storage for a $256^3$ dataset with 1-byte scalars increases from 16 Mbytes to 218 Mbytes when storing 4-byte floats per gradient component per scalar [S1, book]. Octahedral encoding significantly reduces this by storing only indices (e.g., 2 bytes per index) plus a small lookup table [S1, book].
*   **Time:** Encoding requires normalizing the gradient and looking up the index. Decoding requires a table lookup. Precomputing illumination for each index allows fast rendering [S1, book].

**Measured Performance:**
*   For a $256^3$ dataset, naive storage is 218 Mbytes [S1, book].
*   With recursion depth 6, 16,642 indices are used [S1, book].

**Scaling:**
*   Memory usage scales linearly with the number of voxels and the size of the lookup table (which grows exponentially with recursion depth) [S1, book].

**Strengths and Limitations:**
*   **Strengths:** Uniform distribution of directions, significant memory reduction, simple indexing scheme [S1, book].
*   **Limitations:** Limited number of directions (quantization error), only applicable to precomputed gradients [S1, book].

**When to Use:**
*   Use when memory is constrained and gradients are precomputed [S1, book].

## Background
**Origin:**
The technique is based on the uniform fractal subdivision of an octahedron into a sphere [S1, book].

**History and Development:**
It was proposed as a solution to the memory bottleneck in precomputed volume rendering [S1, book].

**Where it is Used:**
Precomputed volume rendering, specifically in methods that store precomputed gradients for illumination calculations [S1, book].
