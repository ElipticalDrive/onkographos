# Octahedral Normal Decoding
## Overview
Decodes a 2D octahedral coordinate into a 3D unit vector [S1, unofficial]. It serves as the inverse operation for octahedral normal encoding, reconstructing surface normals from compressed 2D representations. It differs from [Octahedral Normal Encoding](5029-octahedral-normal-encoding.md) by performing the inverse mapping (index to vector) rather than the forward mapping, and from [Data-Dependent Normal Vector Quantizer (Simulated Annealing)](5865-data-dependent-normal-vector-quantizer-simulated-annealing.md) by using a fixed geometric distribution rather than a data-driven one.
## How it works
**Inputs:** A 2D vector `e` representing the octahedral coordinate.
**Outputs:** A 3D unit vector `v`.

**Data Structures:**
- `e`: `vec2` (float), the encoded coordinate.
- `v`: `vec3` (float), the decoded normal.

**Steps:**
1. Construct an intermediate vector `v` using the formula:
   $$v = \text{vec3}(e, 1.0 - |e.x| - |e.y|)$$
2. If `v.z < 0`:
   - Compute the sign factors for x and y based on the signs of `e.x` and `e.y`.
   - Update `v.xy` using:
     $$v.xy = (1.0 - |e.yx|) \cdot \text{vec2}(\text{sign}(e.x), \text{sign}(e.y))$$
     where $\text{sign}(a) = 1$ if $a \ge 0$ else $-1$.
3. Calculate the length `len` of `v`.
4. If `len > 0`, return `v / len`. Otherwise, return `vec3(0, 0, 1)` [G].

**Pseudocode:**
```python
def oct_decode(e_x, e_y):
    # Step 1: Initial construction
    v_z = 1.0 - abs(e_x) - abs(e_y)
    v = (e_x, e_y, v_z)
    
    # Step 2: Handle negative z
    if v[2] < 0:
        # Calculate sign factors
        sign_x = 1.0 if e_x >= 0 else -1.0
        sign_y = 1.0 if e_y >= 0 else -1.0
        
        # Update xy components
        # Note: e.yx means (e_y, e_x) for the abs calculation in the source
        factor_x = 1.0 - abs(e_y)
        factor_y = 1.0 - abs(e_x)
        
        v = (factor_x * sign_x, factor_y * sign_y, v[2])
        
    # Step 3: Normalize
    length = sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    
    # Step 4: Return
    if length > 0:
        return (v[0] / length, v[1] / length, v[2] / length)
    else:
        # Guard for zero-length vector [G]
        return (0.0, 0.0, 1.0)
```

**Parameters:**
- None.

**Edge Cases:**
- If the resulting vector has zero length (e.g., if `e` is such that `v` becomes `(0,0,0)`), the method returns `(0,0,1)` [S1, unofficial]. This typically occurs if the input `e` is invalid or results in a degenerate case, though valid octahedral coordinates should generally yield non-zero vectors.
## Subtopics

### [Octahedral Normal Encoding](5029-octahedral-normal-encoding.md)
Compresses a 3D unit normal into a single 8-bit integer. Choose when memory bandwidth is critical and 6 discrete directions are sufficient.

### [Data-Dependent Normal Vector Quantizer (Simulated Annealing)](5865-data-dependent-normal-vector-quantizer-simulated-annealing.md)
Generates a quantizer optimized for a specific dataset. Choose when shading quality is paramount and hardware limits allow for custom quantization tables.

## Operating characteristics
Time complexity: $O(1)$. Memory complexity: $O(1)$. The method involves basic arithmetic operations and a single normalization step. It is extremely fast and suitable for real-time rendering. Limitations include the inherent quantization error from the octahedral projection, which may result in less accurate normals compared to higher-bit formats.
## Background
Originated in the context of Gaussian Splatting rendering techniques, specifically within the `godot-gaussian-splatting` project [S1, unofficial]. It is used to efficiently decode normal vectors stored in compressed textures or buffers for shading calculations.
