# Preprocessing Pipeline

Also called: VolCon and Compress Pipeline, Volume Preprocessing Pipeline, buildVolumeImage, crop-downsample-convert

## Overview
The Preprocessing Pipeline prepares raw volumetric data for efficient rendering by applying label banding, cropping to the body bounding box, downsampling, adjusting spacing, and optionally converting to 16-bit float before wrapping in VTK `imageData` [S2, unofficial]. It differs from sibling methods like [Sparse structures](5-sparse-structures.md) by focusing on a fixed-grid transformation pipeline rather than sparse data structures, and from [VolumeSegmenter Pipeline](11584-volumesegmenter-pipeline.md) by its explicit grouping of bricks via intensity bands and adjacency rather than purely spatial partitioning [S1]. It builds on the general [Compression](4-compression.md) principles by exploiting spatial redundancy through cropping and downsampling [G].

## How it works
**Inputs and Outputs:**
*   **Input:** Raw volumetric data (e.g., DICOM slices, RAW files), potentially with existing labels.
*   **Output:** A processed volume dataset (e.g., VTK `imageData`) ready for rendering, or intermediate octree/wavelet files depending on the specific toolchain variant [S1][S2, unofficial].

**Data Structures:**
*   **VTK `imageData`:** Contains dimensions, spacing, origin, and scalar data array. The scalar array type depends on the `PERF.tex` parameter (e.g., `Float32Array` for standard, `Float16` for 16-bit float) [S2, unofficial].
*   **Octree Bricks:** Intermediate files storing octree structure, generated by tools like VolCon [S1].

**Parameters:**
*   `AIR_HU`: Threshold value for air outside the body, typically -500 [S2, unofficial].
*   `PERF.crop`: Boolean flag enabling body bounding box cropping [S2, unofficial].
*   `PERF.down`: Integer downsampling factor applied to dimensions and spacing [S2, unofficial].
*   `PERF.tex`: String flag; when 'f16', triggers 16-bit float conversion and sets mapper size preference [S2, unofficial].
*   Octree depth and maximum level of wavelet compression: User-defined parameters for multi-resolution structures [S1].

**Steps:**
1.  **Label Banding:** If labels exist, apply `bandLabeledHuValues` to raw values; otherwise, use raw values [S2, unofficial].
2.  **Cropping:** If `PERF.crop` is true, compute the body bounding box using the `AIR_HU` threshold (-500). Crop the volume to this box and shift the origin to preserve world coordinates [S2, unofficial].
3.  **Downsampling:** Downsample the volume by `PERF.down` factor using `strideDownsample` [S2, unofficial].
4.  **Spacing Adjustment:** Multiply the volume spacing by `PERF.down` to maintain physical dimensions [S2, unofficial].
5.  **Format Conversion:** If `PERF.tex` is 'f16', convert values to 16-bit float [S2, unofficial].
6.  **Data Structure Construction:** Build a VTK `imageData` object with the new dimensions, spacing, origin, and scalars [S2, unofficial].
7.  **Mapper Configuration:** Set mapper `preferSizeOverAccuracy` if using f16 format [S2, unofficial].
8.  **Binding:** Bind the data to the mapper [S2, unofficial].

**Pseudocode:**
```python
def preprocess_volume(raw_volume, labels, perf_config):
    """
    Preprocess raw volume data for rendering.
    
    Args:
        raw_volume: 3D array of raw voxel values.
        labels: Optional 3D array of label values.
        perf_config: Dictionary containing PERF.crop, PERF.down, PERF.tex, and AIR_HU.
        
    Returns:
        vtk_image_data: Processed volume data structure.
    """
    # Step 1: Label Banding
    if labels is not None:
        volume = band_labeled_hu_values(raw_volume, labels)
    else:
        volume = raw_volume.copy()
        
    # Step 2: Cropping
    if perf_config.get('crop', False):
        # Compute body bounding box using AIR_HU threshold
        air_threshold = perf_config.get('AIR_HU', -500)
        body_mask = volume > air_threshold
        bbox = compute_bounding_box(body_mask)
        
        # Crop volume to box
        cropped_volume = crop_to_bbox(volume, bbox)
        
        # Shift origin to preserve world coordinates
        origin_shift = bbox.min_coords
        volume = cropped_volume
        origin = origin_shift
    else:
        origin = [0, 0, 0]
        
    # Step 3: Downsampling
    down_factor = perf_config.get('down', 1)
    if down_factor > 1:
        volume = stride_downsample(volume, down_factor)
        
    # Step 4: Spacing Adjustment
    original_spacing = [1.0, 1.0, 1.0] # Assume unit spacing if not provided
    new_spacing = [s * down_factor for s in original_spacing]
    
    # Step 5: Format Conversion
    if perf_config.get('tex') == 'f16':
        volume = convert_to_float16(volume)
        use_float16 = True
    else:
        use_float16 = False
        
    # Step 6: Data Structure Construction
    dimensions = volume.shape
    vtk_data = build_vtk_image_data(dimensions, new_spacing, origin, volume)
    
    # Step 7: Mapper Configuration
    if use_float16:
        set_mapper_prefer_size_over_accuracy(True)
        
    # Step 8: Binding
    bind_data_to_mapper(vtk_data)
    
    return vtk_data
```

**Edge Cases and Pitfalls:**
*   **Precision:** Reinterpreting a `Uint8Array` buffer as `Float32Array` is safe because JS engines are natively little-endian and metadata validates `byte_order === 'little'`. Using `DataView` for byte-by-byte reading takes ~15s+ for a 145MB volume, causing stale canvas frames during dataset switches [S2, unofficial].
*   **Boundaries:** Cropping must preserve world coordinates by adjusting the origin [S2, unofficial].
*   **Degenerate Input:** If no labels exist, the pipeline proceeds with raw values [S2, unofficial].

## Subtopics

### [VolumeSegmenter Pipeline](11584-volumesegmenter-pipeline.md)
The VolumeSegmenter Pipeline is an end-to-end method for compressing large RAW volumetric datasets into compact, spatially mapped bricks organized into selectable logical groups, enabling efficient rendering in WebGL2. It reduces stored and GPU-resident voxel data significantly, though it may increase rendering time due to sparse lookup and ray-marching overhead compared to monolithic source rendering. It differs from the [Volume Partitioning Pipeline](11585-volume-partitioning-pipeline.md) by explicitly grouping bricks via intensity bands and adjacency rather than purely spatial partitioning, and builds on the general [Preprocessing Pipeline](6733-preprocessing-pipeline.md) framework.

### [Volume Partitioning Pipeline](11585-volume-partitioning-pipeline.md)
The Volume Partitioning Pipeline splits a 3D volume into foreground regions, optionally partitions them spatially or by intensity, crops them to bounding boxes, downsamples, and exports them as raw files with metadata. It differs from the [VolumeSegmenter Pipeline](11584-volumesegmenter-pipeline.md) by focusing on explicit component partitioning and compact export rather than semantic segmentation, and from the [3D Seismic Data Compression Pipeline](11727-3d-seismic-data-compression-pipeline.md) by its general-purpose intensity-based foreground detection and flexible partitioning strategies.

### [3D Seismic Data Compression Pipeline](11727-3d-seismic-data-compression-pipeline.md)
The 3D Seismic Data Compression Pipeline is a lossy compression method for 3D seismic data that processes volumes in 3D blocks (cubes), applying normalization, closed-loop differential pulse-code modulation (DPCM) with quantization, and Deflate compression to reduce file size while preserving trace integrity. It differs from its sibling [VolumeSegmenter Pipeline](11584-volumesegmenter-pipeline.md) and [Volume Partitioning Pipeline](11585-volume-partitioning-pipeline.md) by operating on fixed 3D spatial-temporal blocks rather than semantic segments or arbitrary partitions, and from the legacy [**.sdc v2 Trace Compression Pipeline**](#-sdc-v2-trace-compression-pipeline) by using 3D predictive coding instead of 1D trace-level encoding.

### Slice Preprocessing
Slice Preprocessing is a preprocessing phase used for creating cropped slices to be distributed across the network for rendering. Each raw data slice is read once. Non-empty regions are segmented using a mask volume, cropped and written to disc memory. Out-of-core region growing is used if no mask has been provided. Concurrently, data extent information is consolidated into a series of slab-projection slices [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Preprocessing time depends on the octree depth and wavelet compression levels. Deeper octrees generate smaller brick files but increase file access overhead [S1].
*   **Memory Complexity:** Reduces stored and GPU-resident voxel data significantly [S1].
*   **Measured Performance:** On a Core2Duo laptop with 2GB RAM, preprocessing time varies with dataset size and octree depth [S1].
*   **Strengths:** Efficiently reduces data size for rendering, supports multi-resolution structures [S1][S2, unofficial].
*   **Limitations:** May increase rendering time due to sparse lookup and ray-marching overhead [S1].
*   **When to Use:** When rendering large volumetric datasets with limited bandwidth or memory [S1][S4, unofficial].
*   **When Not to Use:** When real-time performance is critical and preprocessing overhead is unacceptable [S1].

## Background
The Preprocessing Pipeline originated in the context of gigascale multiresolution volume rendering on distributed display clusters [S1]. It has been developed and refined for various applications, including medical imaging and seismic data visualization [S1][S3, S4, unofficial].
