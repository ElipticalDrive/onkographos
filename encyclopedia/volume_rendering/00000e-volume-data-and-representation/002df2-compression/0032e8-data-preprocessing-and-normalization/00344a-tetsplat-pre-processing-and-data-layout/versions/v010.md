# TetSplat Pre-processing and Data Layout
Also called: TetSplat Quantization and Bitstring Packing

## Overview
TetSplat Pre-processing and Data Layout quantizes scalar field values to $[0, 1]$, packs them into a binary bitstring, and serializes hierarchical Shell and Solid structures into a single binary stream for efficient storage and transmission [S1, unofficial]. It enables interactive visualization of large tetrahedral meshes by minimizing memory overhead through compact bit-packing and breadth-first serialization with embedded traversal pointers [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A partitioned tetrahedral mesh with associated scalar field values [S1, unofficial].
*   **Output:** A single binary data stream file containing the serialized Shell and Solid hierarchical structures [S1, unofficial].

**Data Structures and Layout:**
The method uses two primary hierarchical structures: the **Solid** (an octree) and the **Shell** (a quadtree) [S1, unofficial].

1.  **Solid Node Layout:**
    *   Base size: 6 bytes total [S1, unofficial].
    *   Content: Two scalar field values packed into the bitstring [S1, unofficial].
    *   Extension: Each additional scalar field value adds 2 bytes to the bitstring [S1, unofficial].

2.  **Shell Node Layout:**
    *   Base size: 8 bytes total (6 bytes for fields + 2 bytes extra compared to Solid) [S1, unofficial].
    *   Content: The extra 2 bytes hierarchically encode the normal vector (14 bits) and width of normal cone (2 bits) [S1, unofficial].

3.  **Tree Traversal Pointers:**
    *   For unbalanced trees (Shell quadtree, Solid octree), a 4-byte integer pointer is inserted for each group of parents to the first node of their group of children to allow fast traversal [S1, unofficial].

**Parameters:**
*   **Quantization Precision:** 15 bits per scalar field value is sufficient to represent all relevant field values for the studied datasets [S1, unofficial].
*   **Number of Fields:** Arbitrary, with each additional field adding 2 bytes to the node layout [S1, unofficial].

**Steps:**
1.  **Parallel Partitioning:** Partition the tetrahedral mesh onto multiple CPU nodes, where each node runs its own pre-processing [S1, unofficial].
2.  **Cleanup:** Trim shared triangles from the Shell and add them to the Solid [S1, unofficial].
3.  **Boundary Label Update:** Update boundary label assignments to tetrahedra and triangles in the Solid after cleanup [S1, unofficial].
4.  **Quantization and Packing:** Normalize each scalar field value to $[0, 1]$ and quantize using a lookup table [S1, unofficial]. Pack values into the bitstring layout (2 bytes per field for Solid, plus 2 bytes for Shell geometry) [S1, unofficial].
5.  **Serialization:** Flush the compressed hierarchical data structures to the filesystem as a single binary data stream [S1, unofficial]. Trees are saved in breadth-first order to facilitate fast top-down multi-resolution rendering [S1, unofficial]. Embed 4-byte traversal pointers for unbalanced tree groups [S1, unofficial].

**Pseudocode:**
```python
import struct
import math

def preprocess_tetsplat(mesh_fragments, scalar_fields):
    """
    Pre-processes partitioned tetrahedral mesh fragments for TetSplat.
    Args:
        mesh_fragments: List of dicts, each containing 'shell_triangles', 'solid_tetrahedra', 'solid_triangles'.
        scalar_fields: List of 1D arrays of scalar values.
    Returns:
        binary_stream: bytes object containing the serialized data.
    """
    all_nodes = []
    for frag in mesh_fragments:
        # Step 2: Cleanup
        shared = find_shared_triangles(frag['shell_triangles'], frag['solid_triangles'])
        frag['shell_triangles'] = [t for t in frag['shell_triangles'] if t not in shared]
        frag['solid_triangles'].extend(shared)
        
        # Step 3: Boundary Label Update
        update_boundary_labels(frag['solid_tetrahedra'], frag['solid_triangles'])
        
        # Step 4: Quantization and Packing
        quantized = []
        for field in scalar_fields:
            min_v, max_v = min(field), max(field)
            if max_v == min_v:
                norm_field = [0.5] * len(field)
            else:
                norm_field = [(v - min_v) / (max_v - min_v) for v in field]
            # 15 bits precision per source
            quantized.append([int(v * 32767) for v in norm_field])
            
        for tet in frag['solid_tetrahedra']:
            bits = pack_fields(quantized[:2], 15)
            for i in range(2, len(scalar_fields)):
                bits += pack_field(quantized[i], 15)
            all_nodes.append({'type': 'solid', 'data': bits})
            
        for tri in frag['shell_triangles']:
            bits = pack_fields(quantized[:2], 15)
            for i in range(2, len(scalar_fields)):
                bits += pack_field(quantized[i], 15)
            # Hierarchical encoding of normal (14 bits) and cone width (2 bits)
            # Exact hierarchical scheme not specified in source [S1, unofficial]
            normal_bits = format(0, '014b')
            cone_bits = format(0, '02b')
            bits += normal_bits + cone_bits
            all_nodes.append({'type': 'shell', 'data': bits})
            
    # Step 5: Serialization
    solid_nodes = [n for n in all_nodes if n['type'] == 'solid']
    shell_nodes = [n for n in all_nodes if n['type'] == 'shell']
    solid_tree = build_octree(solid_nodes)
    shell_tree = build_quadtree(shell_nodes)
    
    insert_traversal_pointers(solid_tree)
    insert_traversal_pointers(shell_tree)
    
    solid_stream = serialize_breadth_first(solid_tree)
    shell_stream = serialize_breadth_first(shell_tree)
    
    return solid_stream + shell_stream

def pack_field(value, bits):
    return format(value, f'0{bits}b')

def pack_fields(values, bits):
    return ''.join(pack_field(v, bits) for v in values)

def find_shared_triangles(shell_tris, solid_tris):
    return set(shell_tris) & set(solid_tris)

def build_octree(nodes):
    class Node:
        def __init__(self, data):
            self.data = data
            self.children = []
            self.traversal_pointer = None
    root = Node(None)
    for i in range(0, len(nodes), 8):
        chunk = nodes[i:i+8]
        parent = Node(None)
        for child_data in chunk:
            parent.children.append(Node(child_data))
        root.children.append(parent)
    return root

def build_quadtree(nodes):
    class Node:
        def __init__(self, data):
            self.data = data
            self.children = []
            self.traversal_pointer = None
    root = Node(None)
    for i in range(0, len(nodes), 4):
        chunk = nodes[i:i+4]
        parent = Node(None)
        for child_data in chunk:
            parent.children.append(Node(child_data))
        root.children.append(parent)
    return root

def insert_traversal_pointers(tree):
    def traverse(node):
        if node.children:
            node.traversal_pointer = id(node.children[0])
            for child in node.children:
                traverse(child)
    traverse(tree)

def serialize_breadth_first(tree):
    stream = b""
    queue = [tree]
    while queue:
        node = queue.pop(0)
        data_bytes = node.data.encode() if node.data else b""
        if node.traversal_pointer is not None:
            data_bytes += struct.pack("I", node.traversal_pointer)
        stream += data_bytes
        queue.extend(node.children)
    return stream
```

**Edge Cases and Pitfalls:**
*   **Memory Overhead:** The relative memory overhead of 32-bit traversal pointers is much less for the Solid than for the Shell [S1, unofficial]. Although the Solid is typically several orders of magnitude larger than the Shell, its average branching factor is twice as high, leading to fewer internal nodes and thus fewer pointers [S1, unofficial].
*   **Unbalanced Trees:** Pointers must be embedded to allow fast traversal of the unbalanced Shell quadtree and Solid octree [S1, unofficial].
*   **Boundary Labels:** Boundary labels must be updated after the cleanup process to ensure consistency between Shell and Solid assignments [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** The Solid structure has lower relative memory overhead for traversal pointers due to its higher branching factor (octree) compared to the Shell (quadtree) [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** The method is readily parallelized by partitioning the tetrahedral mesh onto multiple CPU nodes, each running its own pre-processing [S1, unofficial].
*   **Strengths:** Efficient storage via bit-packing; fast top-down rendering via breadth-first serialization and embedded pointers; parallelizable pre-processing [S1, unofficial].
*   **Limitations:** Requires unbalanced tree traversal logic; memory overhead for pointers is significant for the Shell relative to its size [S1, unofficial].
*   **When to use:** When interactive visualization of large tetrahedral meshes with multiple scalar fields is required, and memory bandwidth or storage is constrained [S1, unofficial].
*   **When not:** Not given in the sources.

## Background
*   **Origin:** The method is described in "TetSplat: Real-time Rendering and Volume Clipping of Large Tetrahedral Meshes" by Museth and Lombeyda (2004) [S1, unofficial].
*   **History:** The approach builds on QSplat's file layout strategy (breadth-first order) and extends it to tetrahedral meshes with multiple scalar fields and hierarchical geometric encoding for the Shell [S1, unofficial].
*   **Usage:** Used for interactive visualization of large tetrahedral meshes, allowing users to edit transfer functions and highlight interesting regions [S1, unofficial].
