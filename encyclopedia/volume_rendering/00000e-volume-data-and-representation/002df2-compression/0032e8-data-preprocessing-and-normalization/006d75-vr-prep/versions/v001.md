# VR-prep


## Overview
VR-prep is a data preprocessing and normalization workflow designed to transform medical imaging datasets (primarily DICOM series) into a standardized, optimized format for efficient 3D volume rendering in Augmented Reality (AR) applications, specifically the 'Medical Imaging XR' (MIXR) app [S1]. It solves the problem of large file sizes, inconsistent intensity ranges, and non-isotropic voxel dimensions in raw medical data, which cause slow upload/download times and poor visual quality in mobile AR environments [S1]. Unlike simple resolution reduction, VR-prep maintains high diagnostic quality by enforcing isotropic resolution and correcting intensity inversions, setting it apart from siblings like [Byte/Short Conversion](11742-byte-short-conversion.md) by integrating spatial resampling and orientation standardization into a single pipeline [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A medical image dataset, typically a DICOM series (CT, MRI, PET), but also supporting microscopy (.png), ultrasound (.jpeg), and time-comparison stacks [S1].
*   **Output:** A single `.tiff` file containing the processed image stack, which is subsequently converted into a modified DICOM stack by 3D Slicer for AR ingestion [S1].

**Data Structures:**
*   The core data structure is a 3D volume represented as a stack of 2D slices.
*   **Bit Depth:** Unsigned 16-bit integer (`uint16`) [S1].
*   **Voxel Size:** Isotropic, with a target resolution of 1 mm per dimension [S1].
*   **Orientation:** The stack must be ordered such that the first slice is caudal and subsequent slices progress cranially [S1].

**Parameters:**
*   **Target Resolution:** 1 mm isotropic [S1].
*   **Target Bit Depth:** Unsigned 16-bit [S1].
*   **Intensity Range:** Positive values only [S1].

**Steps:**
1.  **Intensity Verification and Correction:** Verify the intensity values of the input series. If inverted (occurring in ~43% of cases), invert the intensity values to ensure anatomical structures are correctly represented (e.g., bone appears bright, air appears dark) [S1].
2.  **Positive Range Conversion:** Convert intensity values to a strictly positive range [S1].
3.  **Isotropic Resampling:** Resample the image series to an isotropic voxel size of 1 mm [S1].
4.  **Bit-Depth Conversion:** Convert the image series to unsigned 16-bit format [S1].
5.  **Orientation Standardization:** Ensure the image series initiates caudally and moves cranially. If the series is oriented incorrectly, reorder the slices [S1].
6.  **Stacking:** Combine the individual processed images into a single `.tiff` file encompassing the entire stack [S1].
7.  **DICOM Generation (Post-Processing):** Import the `.tiff` file into 3D Slicer and use the 'Create DICOM series' plugin to generate a modified DICOM stack [S1].
8.  **AR Upload:** Upload the generated DICOM series to the MIXR application for 3D object generation [S1].

**Edge Cases and Pitfalls:**
*   **Inverted Intensities:** Original DICOM series often have inverted intensity values (43% of tested cases), which makes identifying anatomical structures difficult, worsens sharpness and SNR, and lowers diagnostic confidence [S1]. VR-prep corrects this [S1].
*   **Orientation:** The series must initiate caudally and move cranially. Incorrect orientation leads to incorrect 3D reconstruction in AR [S1].
*   **Non-DICOM Data:** Ultrasound and microscopy data are not native DICOM series and require format conversion (e.g., .jpeg to .tiff) before processing [S1].

## Subtopics

### [CT/PET Modality Fusion via Pseudo-HU Mapping](21465-ct-pet-modality-fusion-via-pseudo-hu-mapping.md)
This method aligns independently acquired CT and PET image stacks voxel-wise and merges their intensity values into a single dataset using a continuous "pseudo-Hounsfield Unit" (pseudo-HU) scale. It solves the problem of visualizing joint structural (CT) and functional (PET) information in a single volume for Augmented Reality (AR) display, extending the MIXR application's native CT-only support to PET-CT data. It sets itself apart from simple overlay techniques by creating a single scalar field where PET signal intensity overrides CT values above a specific threshold, mapping both modalities into a unified 0–999 integer range.

### Alternative PET-CT Integration (8-bit range splitting)
An alternative method to integrate PET and CT datasets into a single DICOM series for MIXR by splitting 8-bit intensity ranges rather than using pseudo-HU mapping [S1]. It sets itself apart by using discrete 8-bit ranges (CT: 0–100, PET: 105–255) instead of a continuous pseudo-HU scale [S1].
*   **Steps:**
    1.  Adjust CT series intensity values to a range of 0 to 100 in 8-bit [S1].
    2.  Adjust PET series intensity values to a range of 105 to 255 in 8-bit [S1].
    3.  Add the two series together [S1].
    4.  Run the combined series through VR-prep [S1].
*   **Parameters:** CT 8-bit range: 0 to 100; PET 8-bit range: 105 to 255 [S1].

### Multi-modal and multi-temporal integration
Converts the temporal dimension of ultrasound video sequences into a spatial volume dimension to enable 3D volume rendering in AR [S1]. It adapts the VR-prep pipeline for MRI, microscopy, ultrasound, and time-comparison datasets by converting them to compatible formats and stacking them appropriately [S1].
*   **Steps:**
    1.  Import the ultrasound image sequence (time series) [S1].
    2.  Treat each frame in the sequence as a distinct slice along a new spatial axis [S1].
    3.  Stack the frames sequentially to form a 3D pseudo-volume [S1].
    4.  Process the resulting pseudo-volume through the standard VR-prep pipeline [S1].
    5.  For MRI: Procure DICOM series from PACS and run directly through VR-prep [S1].
    6.  For microscopy: Download .png images, import to Fiji, convert to .tiff, and process with VR-prep [S1].
    7.  For ultrasound: Open continuous .jpeg probe data in Fiji, convert to .tiff, and process with VR-prep [S1].
    8.  For time comparison: Use Fiji command 'combine stack' to place different time point series side by side, then run through VR-prep [S1].
*   **Parameters:** Microscopy input format: .png; Ultrasound input format: continuous .jpeg [S1].

## Operating characteristics
*   **Time and Memory Complexity:** Not given in the sources.
*   **Measured Performance:**
    *   **File Size:** Reduced average DICOM file size from 382.2 ± 201.0 MB (original) to 145.3 ± 94.1 MB (p = 0.0014, n = 14) [S1].
    *   **Frame Count:** Reduced average DICOM frame number from 528.1 ± 178.3 to 435.9 ± 143.4 frames (p = 0.0161) [S1].
    *   **Upload Time:** Reduced upload time to MIXR to generate a QR-code from 136.1 ± 71.3 s to 38.1 ± 19.8 s (p = 0.0003) [S1].
    *   **Normalized Upload Time:** Reduced from 0.25 ± 0.10 s/frame to 0.08 ± 0.03 s/frame (p < 0.0001) [S1].
    *   **Download Time:** Reduced download time of the generated 3D object to an iPad Pro from 13.60 ± 6.77 s to 3.22 ± 0.97 s (p < 0.0001) [S1].
    *   **Normalized Download Time:** Reduced from 0.027 s/frame to 0.007 s/frame (p < 0.0001) [S1].
*   **Image Quality:** Improved LUT representation (median 5 vs 4, p = 0.0022), SNR (median 5 vs 4, p = 0.0036), and diagnostic confidence (median 4 vs 4, p = 0.0073) compared to original images [S1].
*   **Comparison with Lower Resolution:** VR-prep produces superior 3D objects compared to exporting original DICOM series at lower resolutions (e.g., 3 mm or 5 mm increments). While 3 mm and 5 mm increments yielded insufficient sharpness and clarity, VR-prep maintained high frame number and sharp contrast with clearly defined contours (e.g., left clavicle, diaphragm, interlobar fissure) comparable to original 1 mm data [S1].
*   **Strengths and Limitations:**
    *   **Strengths:** Significantly reduces file size and processing time without sacrificing image quality or readability; extends MIXR's native support (CT only) to MRI, US, PET-CT, and microscopy data; user-friendly [S1].
    *   **Limitations:** Relies on open-source software (Fiji, 3D Slicer) which may require manual intervention for orientation and intensity verification; not given in the sources for other limitations.
*   **When to Use:** When preparing medical imaging data for AR visualization on smartphones using the MIXR application, especially for non-CT modalities or when original DICOM files are too large or poorly oriented [S1].
*   **When Not to Use:** When high-resolution non-isotropic data is required for clinical diagnosis outside of AR; when real-time processing on mobile devices without pre-processing is required [S1].

## Background
VR-prep was devised by researchers to improve the speed of generation of 3D medical objects in the 'Medical Imaging XR' (MIXR) application [S1]. It relies exclusively on open-source products: Fiji, 3D Slicer, and MIXR [S1]. The workflow was designed to expedite and optimize the 3D rendering of DICOM series in MIXR, addressing the challenges of relaying complex anatomical information between clinicians and to patients via direct 3D visualization in augmented reality on portable devices [S1]. The method was tested on a dataset of 14 cases, demonstrating significant improvements in file size, upload/download times, and image quality ratings [S1].
