# Scaling and Biasing

Also called: BuildScaleBiasProgram, Window/Level (Windowing) Adjustment

## Overview
Scaling and Biasing applies a linear transformation to volume texture samples to adjust contrast and brightness, commonly known as window/level adjustment [S1, unofficial]. It maps a specific range of input intensities to the full display range [S2, unofficial]. Unlike non-linear methods such as [Power Transformation](2346-power-transformation.md), it preserves the linear relationship between input intensity and output brightness within the window [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A texture sample value $x$ (float) [G].
*   **Parameters:** `windowWidth` ($w$): range of intensities mapped to the display. Default value: 1048 [S2, unofficial]. `windowLevel` ($c$): center of the intensity window. Default value: 0 [S2, unofficial].
*   **Output:** A normalized float value $y$ in the range $[0, 1]$ [G].

**Data Structures:**
The parameters are passed as uniform floats to a fragment shader [S1, unofficial]. In some implementations, UI slider input events parse float values and call `volume.setWindowLevel(value)` or `volume.setWindowWidth(value)`, then invalidate the viewport [S2, unofficial].

**Formula:**
The transformation is defined as:
$$ y = \frac{x - (c - w/2)}{w} $$
Where $x$ is the input sample, $c$ is `windowLevel`, and $w$ is `windowWidth` [S2, unofficial].

**Steps:**
1. Retrieve the current texture sample value $x$ [G].
2. Calculate the lower bound of the window: $L = c - w/2$ [G].
3. Calculate the upper bound of the window: $U = c + w/2$ [G].
4. If $x < L$, set $y = 0$ [G].
5. If $x > U$, set $y = 1$ [G].
6. Otherwise, compute $y = (x - L) / w$ [G].

**Pseudocode:**
```python
def scale_and_bias(x: float, window_level: float, window_width: float) -> float:
    lower_bound = window_level - window_width / 2.0
    upper_bound = window_level + window_width / 2.0
    if x < lower_bound:
        return 0.0
    elif x > upper_bound:
        return 1.0
    else:
        return (x - lower_bound) / window_width
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If `window_width` is 0, the division is undefined [G]. Implementations should clamp `window_width` to a minimum positive value or handle this case explicitly [G].
*   **Precision:** Floating-point precision in the shader may cause slight inaccuracies at the boundaries of the window [G].

## Subtopics

### Volume Slide Down
A variant where the volume of the current sample is adjusted by a fixed amount before further processing [S3, unofficial]. It increments or decrements the volume, with clamping to legal bounds [S3, unofficial].
*   **Definition:** Increments or decrements the volume of the current sample by $x$ at the beginning of the division. No sliding occurs [S3, unofficial].
*   **Steps:** Set `cptr->volume += (effect & 0xF)`. If `cptr->volume > 64`, set `cptr->volume = 64` [S3, unofficial]. Or, Set `cptr->volume -= (effect & 0xF)`. If `cptr->volume > 200`, set `cptr->volume = 0` [S3, unofficial].
*   **Pitfalls:** Cannot slide beyond volume 64 (for increment) or 0 (for decrement) [S3, unofficial].

### Texture Format Remapping
A variant used when GPU texture formats (e.g., `r16float`) do not natively support the required precision or range for uint16 data [S4, unofficial]. It applies a scale and bias to map texels back to normalized float values [S4, unofficial].
*   **Definition:** Converts uint16 data stored in `r16float` textures back to normalized float values for rendering by applying scale and bias [S4, unofficial].
*   **Steps:** If `gpu.textureFormat` is `'r16float'` and `!metadata.isFloat`, set `renderer.texelScale = 65535` and `renderer.texelBias = -UINT16_FLOAT16_OFFSET` [S4, unofficial]. The renderer applies these to map texels back to `value / 65535` [S4, unofficial].
*   **Parameters:** `UINT16_FLOAT16_OFFSET`: constant offset used when storing uint16 in r16float format; exact value not given in this section [S4, unofficial].
