# Video Frame Extraction and Preprocessing

Also called: Laparoscopic Video Preprocessing

## Overview
This method extracts and cleans video frames from laparoscopic surgical recordings to create a high-quality input dataset for 3D scene reconstruction. It solves the problem of degraded input quality caused by camera motion artifacts, lighting inconsistencies, and redundant video borders. It is distinguished from general volume preprocessing by its specific focus on surgical video characteristics, such as discarding frames based on camera pose discontinuities and handling specific black-bar cropping ratios.

## How it works
**Inputs and Outputs**
- Input: Raw laparoscopic video file (e.g., MP4).
- Output: A set of $n_{frame}$ preprocessed image frames and associated metadata (camera poses, UV coordinates if applicable).

**Data Structures**
- Frame List: A sequence of $n_{frame}$ images.
- Metadata: Camera pose matrices and UV coordinates for texture mapping.

**Steps**
1. **Extraction**: Extract $n_{frame}$ equidistant frames from the source video [S1].
2. **Quality Filtering**: Discard frames with severe under-exposure, over-exposure, or motion blur. Detection is performed by analyzing the difference in camera pose between adjacent frames [S2].
3. **Cropping**: Remove redundant black areas from the frame borders. Crop 6.6% from the left and 9.1% from the right [S1].
4. **Color Correction**: Linearize the image gamma and apply white balancing [S2].
5. **Distortion Removal**: Remove lens distortion from the images [S2].
6. **Geometry Representation**: Represent the scene geometry using a standard triangle mesh with UV texture parameterization. If UV coordinates are missing (e.g., in synthetic datasets like Replica), generate them automatically using Blender’s “Smart UV Project” operator [S2].

**Parameters**
- Original Resolution: $3840 \times 2160$ pixels [S1].
- Cropped Resolution: $3237 \times 2160$ pixels [S1].
- Video Duration: 93 seconds [S1].
- Frame Rate: $\approx 29.935$ fps [S1].
- Total Available Frames: 2784 [S1].
- $n_{frame}$: Variable number of extracted frames (e.g., 310, 1392, 2784) to test sparsity levels [S1].

**Pseudocode**
```python
def preprocess_video(video_path, n_frame):
    # Step 1: Extract equidistant frames
    # Calculate step size based on total frames and n_frame
    total_frames = get_total_frames(video_path)
    step = total_frames // n_frame
    frames = []
    for i in range(n_frame):
        idx = i * step
        frame = extract_frame(video_path, idx)
        frames.append(frame)

    # Step 2: Filter bad frames using camera pose differences
    # Note: Camera pose estimation is required here.
    # Discard frames where pose difference to adjacent frame exceeds threshold
    poses = estimate_camera_poses(frames)
    valid_frames = []
    valid_poses = []
    for i in range(len(frames)):
        if i == 0 or i == len(frames) - 1:
            # Keep first and last, or apply specific boundary logic
            valid_frames.append(frames[i])
            valid_poses.append(poses[i])
        else:
            diff = pose_difference(poses[i], poses[i-1])
            diff_next = pose_difference(poses[i], poses[i+1])
            if diff < threshold and diff_next < threshold:
                valid_frames.append(frames[i])
                valid_poses.append(poses[i])
            # Else: discard due to motion blur/exposure issues detected via pose jump
    
    # Step 3: Crop frames
    # Remove 6.6% from left, 9.1% from right
    h, w = valid_frames[0].shape[:2]
    crop_left = int(w * 0.066)
    crop_right = int(w * 0.091)
    cropped_frames = []
    for frame in valid_frames:
        cropped = frame[:, crop_left:w-crop_right, :]
        cropped_frames.append(cropped)

    # Step 4: Linearize and White-Balance
    corrected_frames = []
    for frame in cropped_frames:
        linear = linearize_gamma(frame)
        white_balanced = apply_white_balance(linear)
        corrected_frames.append(white_balanced)

    # Step 5: Remove Lens Distortion
    undistorted_frames = []
    for frame in corrected_frames:
        undistorted = remove_lens_distortion(frame, camera_intrinsics)
        undistorted_frames.append(undistorted)

    # Step 6: Generate UVs if needed (Mesh context)
    # This step is typically performed on the reconstructed mesh, not individual frames,
    # but is part of the preprocessing pipeline for the final representation.
    return undistorted_frames, valid_poses
```

## Operating characteristics
- **Time Complexity**: Depends on $n_{frame}$ and the cost of camera pose estimation. For $n_{frame}=2784$, COLMAP takes ~4.5 hours, HLOC ~22 hours, and LocalRF ~75 hours on an RTX A6000 GPU [S1].
- **Memory Complexity**: Scales linearly with the number of frames and resolution. High-resolution frames ($3840 \times 2160$) require significant RAM/VRAM for processing [S1].
- **Strengths**: Handles surgical video specific artifacts (motion blur, exposure) effectively. Standardizes input for NeRF and mesh-based reconstruction.
- **Limitations**: Camera pose estimation can be slow for large $n_{frame}$. Discarding frames reduces data density.
- **When to Use**: Laparoscopic surgical video reconstruction.
- **When Not to Use**: Non-surgical videos without significant motion blur/exposure issues, or real-time applications where pose estimation latency is prohibitive.

## Background
Originated in the context of abdominal 3-D scene rendering from laparoscopic surgical videos using NeRFs [S1]. The method addresses the need for high-quality, sparse view inputs for neural rendering in medical settings. It also incorporates techniques from texture-space differentiable rendering for complex indoor scenes, such as UV generation for synthetic data [S2].
