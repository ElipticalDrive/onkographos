# Recursive Heuristic
Also called: Recursive subdivision scheme
## Overview
The Recursive Heuristic is a load-balancing strategy for parallel volume rendering that recursively partitions the image plane into smaller rectangular regions until each processor manages a single region [S1, unofficial]. It serves as a general superset of simpler 1D horizontal and vertical division schemes, dynamically choosing between horizontal and vertical cuts at each recursion level to optimize load balance [S1, unofficial]. Unlike fixed-axis partitioning, it adapts the division orientation based on the computed load distribution, offering greater scalability flexibility at the cost of increased data exchange and loss of scanline coherency [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: The current image plane region assigned to a cluster of processors, the total number of processors $P$, and the local load distribution within that region [S1, unofficial].
- Output: A partitioned image plane where each processor holds a distinct rectangular sub-region, along with the migrated data required to render that sub-region [S1, unofficial].

**Data Structures:**
- Image plane region boundaries: Not given in the sources.
- Load metric: A scalar value representing the computational cost within a region [G].
- Processor set: A list or array of processor IDs currently responsible for the region [G].

**Algorithm Steps:**
1. Find the overall load in the local image plane [S1, unofficial].
2. Divide this load into two horizontally [S1, unofficial].
3. Divide this load into two vertically [S1, unofficial].
4. Compare these two division options and choose the best one (best load balance) [S1, unofficial].
5. Exchange local data with respect to this new division [S1, unofficial].
6. Set half of the processors to one region and the other half to the other region [S1, unofficial].
7. Repeat steps 1–6 until one region per processor is reached [S1, unofficial].

**Parameters:**
- $P$: Total number of processors. Determines the depth of recursion, which is $\log_2(P)$ passes [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Coherency Loss:** Vertical division disturbs intra-scanline coherency, causing loss of active polygon, edge, x-bucket, and z-list information [S1, unofficial]. Horizontal division disturbs inter-scanline coherency, causing loss of active polygon information between scanlines [S1, unofficial]. This necessitates recreation of incremental structures, increasing processing time [S1, unofficial].
- **Job Approximation Deviation:** The disturbance of coherencies can cause job approximations within a region to deviate drastically [S1, unofficial].

## Subtopics

### [Rectangular Heuristic](18043-rectangular-heuristic.md)
A load-balancing partitioning method for parallel volume rendering that divides the image plane into rectangular regions by organizing processors into a 2D mesh. It solves the scalability limitations of 1D horizontal division schemes, where the number of partitions is restricted by the number of scanlines and large workload disparities cause significant imbalance. By partitioning in both dimensions, it improves load distribution across a 2D processor topology.

## Operating characteristics
- **Time Complexity:** The recursion depth is $\log_2(P)$, leading to $O(\log P)$ passes of data exchange and partitioning [S1, unofficial]. Each pass involves load calculation and data migration, which depends on the scene complexity and communication bandwidth [G].
- **Memory Complexity:** Requires storage for the image plane regions and temporary buffers for data exchange during migration [G]. The sources do not specify additional memory overhead beyond the scene data [S1, unofficial].
- **Measured Performance:** The method offers greater scalability flexibility compared to fixed-axis division but incurs extra processing time due to the loss of scanline coherency [S1, unofficial]. The trade-off is between the improved load balance (scalability) and the overhead of recreating coherency structures [S1, unofficial].
- **Strengths:** Dynamic load balancing; adapts to scene complexity; scalable to large numbers of processors [G].
- **Limitations:** High communication overhead due to data exchange; loss of coherency leads to increased computational work per pixel/voxel; job approximation errors [S1, unofficial].
- **When to Use:** When the scene load is unevenly distributed and fixed-axis partitioning would lead to significant load imbalance [G]. Suitable for large-scale parallel rendering where scalability is prioritized over minimal coherency overhead [G].
- **When Not to Use:** When the scene is uniformly distributed or when coherency preservation is critical for performance (e.g., simple scenes where horizontal/vertical division suffices) [G].

## Background
The Recursive Heuristic was introduced as a general subdivision heuristic in the context of parallel volume rendering, specifically as a superset of earlier 1D horizontal and vertical division algorithms [S1, unofficial]. It was developed to address the limitations of fixed-axis partitioning by allowing dynamic choice of division orientation to achieve better load balance [S1, unofficial]. The method is discussed in the context of parallel algorithms for volume rendering, often in conjunction with scanline z-buffer paradigms [S1, unofficial].
