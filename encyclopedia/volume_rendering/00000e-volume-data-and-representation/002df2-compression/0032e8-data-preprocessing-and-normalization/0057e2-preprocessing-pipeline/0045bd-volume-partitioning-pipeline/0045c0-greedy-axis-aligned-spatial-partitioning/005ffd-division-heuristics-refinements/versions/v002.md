# Division Heuristics Refinements


## Overview
Division Heuristics Refinements are minor algorithmic optimizations applied to spatial partitioning to improve load-balancing accuracy during volume data subdivision [S1, unofficial]. These refinements address approximation errors inherent in linear division schemes by introducing binary search for cut location, recursive load recalculation, and multi-array workload tracking [S1, unofficial].

## How it works
**Inputs:** A spatial region $R$, a set of work items $W$ (e.g., triangles or volume primitives), and a chosen split axis [S1, unofficial].
**Outputs:** A split plane position $p$ along the axis, and two new sub-regions $R_{left}$ and $R_{right}$ [S1, unofficial].

**Data Structures:**
- **Workload Arrays:** Multiple arrays store the workload contributions of individual items to improve approximation accuracy [S1, unofficial].
- **Region State:** Each region maintains a current estimated workload value [S1, unofficial].

**Steps:**
1. **Initialize Search Range:** Define the search interval $[L, H]$ for the split position along the chosen axis, bounded by the region's extent [S1, unofficial].
2. **Binary Search for Cut:** Perform a binary search within $[L, H]$ to find the optimal split position $p$, which speeds up the division process [S1, unofficial].
3. **Recursive Load Recalculation:** Immediately re-calculate the workload for each resulting sub-region after a division is performed to reduce approximation errors [S1, unofficial].
4. **Recursive FIND-DIVISION:** Use recursion in the `FIND-DIVISION` procedure rather than a linear iterative approach to avoid cumulative errors introduced by linear division [S1, unofficial].

**Pseudocode:**
```python
def find_division_recursive(region, items, axis, max_iter=20):
    low = region.min(axis)
    high = region.max(axis)
    for _ in range(max_iter):
        mid = (low + high) / 2.0
        left_work = 0.0
        right_work = 0.0
        for item in items:
            if item.coord[axis] < mid:
                left_work += item.workload_contribution()
            else:
                right_work += item.workload_contribution()
        if left_work < right_work:
            low = mid
        else:
            high = mid
    split_pos = (low + high) / 2.0
    left_region, right_region = region.split(axis, split_pos)
    left_region.workload = 0.0
    right_region.workload = 0.0
    for item in items:
        if item.coord[axis] < split_pos:
            left_region.workload += item.workload_contribution()
        else:
            right_region.workload += item.workload_contribution()
    return split_pos, left_region, right_region
```
*Note: The sources specify using multiple arrays for workload contributions per item for better approximation, but do not detail the exact memory layout [G].*

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point precision in binary search may lead to non-optimal splits if the iteration limit is too low [G]. A typical iteration count for spatial coordinates is 20 to 30, depending on the volume resolution.
- **Degenerate Input:** If all items are concentrated in one sub-region, the binary search may converge to the boundary [G]. Handle this by checking for zero-width regions and skipping division.
- **Cumulative Errors:** Linear division can accumulate errors; recursion mitigates this but increases call stack depth [S1, unofficial].

## Subtopics

### [Recursive Heuristic](18040-recursive-heuristic.md)
The Recursive Heuristic is a load-balancing strategy for parallel volume rendering that recursively partitions the image plane into smaller rectangular regions until each processor manages a single region. It serves as a general superset of simpler 1D horizontal and vertical division schemes, dynamically choosing between horizontal and vertical cuts at each recursion level to optimize load balance. Unlike fixed-axis partitioning, it adapts the division orientation based on the computed load distribution, offering greater scalability flexibility at the cost of increased data exchange and loss of scanline coherency.

## Operating characteristics
- **Time Complexity:** The binary search reduces the time to find the optimal split from $O(N)$ to $O(\log N)$ per division step, but recursive recalculation adds overhead [S1, unofficial].
- **Memory Complexity:** Using multiple arrays for workload contributions increases memory usage compared to a single scalar value [S1, unofficial].
- **Performance Impact:** These refinements do not significantly affect the overall runtime or results of the algorithm compared to earlier rasterization-stage refinements [S1, unofficial].
- **Strengths:** Reduces approximation errors, speeds up division via binary search, avoids cumulative errors via recursion [S1, unofficial].
- **Limitations:** Increased implementation complexity and higher memory usage for multi-array tracking [S1, unofficial].

## Background
These refinements were proposed in the context of parallel volume rendering and spatial partitioning for load balancing [S1, unofficial]. They represent minor but practical improvements to greedy axis-aligned spatial partitioning algorithms, focusing on reducing the error in workload estimation during the partitioning phase [S1, unofficial].
