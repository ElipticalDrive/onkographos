# Rectangular Heuristic

Also called: Rectangular division scheme

## Overview
The Rectangular Heuristic is a load-balancing partitioning method for parallel volume rendering that divides the image plane into rectangular regions by organizing processors into a 2D $M \times K$ mesh [S1, unofficial]. It solves the scalability limitations of 1D horizontal division schemes, where the partition count is restricted by the number of scanlines and large workload disparities cause significant imbalance [S1, unofficial]. By partitioning in both dimensions, it improves load distribution across a 2D processor topology [S1, unofficial].

## How it works
**Inputs:**
- Image plane dimensions (width $W$, height $H$) [S1, unofficial].
- Set of local triangles with their 3D bounding boxes [S1, unofficial].
- Processor topology: $M$ clusters of $K$ processors each (total $P = M \times K$) [S1, unofficial].

**Outputs:**
- Vertical division boundaries for all $M$ clusters, distributed to all processors [S1, unofficial].

**Data Structures:**
- `SWLA` (Scanline Work Load Array): Size $H$. `SWLA[i]` stores the workload contribution of horizontal scanline $i$. Used to determine the $M$ horizontal bands [S1, unofficial].
- `XWLA` (X-dimension Work Load Arrays): A 2D array of size $M \times W$. `XWLA[v][j]` stores the workload contribution of vertical scanline $j$ within horizontal region (band) $v$. $v \in \{1, \dots, M\}$, $j \in \{1, \dots, W\}$ [S1, unofficial].

**Steps:**
1. Partition the image plane into $M$ horizontal bands using the Horizontal Division Scheme [S1, unofficial].
2. Calculate the workload distribution in the x-dimension for each horizontal band using local triangle information [S1, unofficial]:
   a. Project the bounding boxes of each triangle onto the image plane [S1, unofficial].
   b. If a bounding box spans two or more horizontal regions, divide it into segments corresponding to the intersection with each band [S1, unofficial].
   c. Update the corresponding entries of `XWLA` for each region covered by the bounding box segments [S1, unofficial].
3. Perform a global sum operation on the `XWLA` arrays across all processors to obtain the global workload distribution in the x-dimension for each region [S1, unofficial].
4. Perform a prefix sum operation on `XWLA[m_y_cluster]`, where $m\_y\_cluster$ is the cluster the processor belongs to [S1, unofficial].
5. Calculate average load: Let $L$ be the number of vertical scanlines in the x-dimension. Set $AvrgLd = XWLA[m\_y\_cluster][L] / K$, where $K$ is the number of processors in the cluster [S1, unofficial].
6. Call `FIND_DIVISION(K, XWLA[m_y_cluster])` to determine $K$ vertical bands of consecutive vertical scanlines in the x-dimension for the cluster's horizontal region [S1, unofficial].
7. Perform a global concatenate operation on the vertical divisions from each cluster so that every processor has the division information for all $M$ clusters [S1, unofficial]. This operation can be implemented in $\log_2(M)$ steps [S1, unofficial].

**Pseudocode:**
```python
def rectangular_heuristic(triangles, image_width, image_height, num_clusters_M, processors_per_cluster_K):
    # Step 1: Horizontal Partitioning
    # [G] Calls parent method Horizontal Division Scheme to determine M horizontal bands.
    horizontal_bands = horizontal_division_scheme(triangles, image_height, num_clusters_M)

    # Initialize XWLA: M bands x W scanlines
    XWLA = [[0.0] * image_width for _ in range(num_clusters_M)]

    # Step 2: Local Workload Calculation
    for triangle in triangles:
        bbox = triangle.get_bounding_box()
        x_min, y_min, x_max, y_max = bbox
        for v in range(num_clusters_M):
            band_y_min, band_y_max = horizontal_bands[v]
            if y_max <= band_y_min or y_min >= band_y_max:
                continue
            overlap_y_min = max(y_min, band_y_min)
            overlap_y_max = min(y_max, band_y_max)
            for j in range(x_min, x_max):
                if 0 <= j < image_width:
                    XWLA[v][j] += triangle.get_workload_contribution()

    # Step 3: Global Sum
    # [G] Standard parallel reduction: XWLA[v][j] = sum over all processors of local XWLA[v][j]
    XWLA = global_sum(XWLA)

    # Step 4 & 5: Prefix Sum and Average Load
    divisions = []
    for v in range(num_clusters_M):
        prefix_sum_array = prefix_sum(XWLA[v])
        L = image_width
        total_workload = prefix_sum_array[L - 1]
        avg_load = total_workload / processors_per_cluster_K

        # Step 6: Vertical Division
        cuts = find_division(processors_per_cluster_K, XWLA[v], avg_load)
        divisions.append(cuts)

    # Step 7: Global Concatenate
    # [G] Standard parallel gather: all_divisions = gather all divisions from all clusters
    all_divisions = global_concatenate(divisions)
    return all_divisions

def prefix_sum(arr):
    result = [0.0] * len(arr)
    acc = 0.0
    for i in range(len(arr)):
        acc += arr[i]
        result[i] = acc
    return result

def global_sum(arr):
    # [G] Simulates parallel reduction; in practice uses MPI_Allreduce or similar
    return arr

def global_concatenate(arr_list):
    # [G] Simulates parallel gather; in practice uses MPI_Allgather or similar
    return arr_list

def find_division(num_regions, workload_array, avg_load):
    # [G] Standard greedy partitioning: accumulate workload and cut when target is reached
    cuts = []
    current_workload = 0.0
    idx = 0
    for i in range(1, num_regions):
        target = i * avg_load
        while current_workload < target and idx < len(workload_array) - 1:
            current_workload += workload_array[idx]
            idx += 1
        cuts.append(idx)
    return cuts
```

## Operating characteristics
- **Scalability:** Improves upon 1D horizontal division by allowing the number of partitions to scale with the number of processors in both dimensions, rather than being limited by the number of scanlines [S1, unofficial].
- **Load Balance:** Reduces load imbalance when there are large differences in workload among scanlines, as it can balance load in both x and y directions [S1, unofficial].
- **Complexity:** The algorithm involves global sum and prefix sum operations, which are $O(P)$ or $O(\log P)$ depending on the parallel implementation, plus the cost of finding divisions [S1, unofficial]. The global concatenate step takes $\log_2(M)$ steps [S1, unofficial].
- **Limitations:** Requires communication between all processors for global sums and concatenation, which can be a bottleneck on large-scale systems if not optimized [S1, unofficial].

## Background
The Rectangular Heuristic was introduced as an improvement over the Horizontal Division Scheme to address its scalability and load-balancing limitations [S1, unofficial]. It is part of a family of greedy axis-aligned spatial partitioning methods used in parallel volume rendering [S1, unofficial]. The method is described in the context of a 2D processor mesh organization [S1, unofficial].
