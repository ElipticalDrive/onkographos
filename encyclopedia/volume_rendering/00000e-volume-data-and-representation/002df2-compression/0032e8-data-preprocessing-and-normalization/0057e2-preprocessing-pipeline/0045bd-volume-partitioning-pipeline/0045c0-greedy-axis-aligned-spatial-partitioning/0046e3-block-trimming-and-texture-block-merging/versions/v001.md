# Block Trimming and Texture Block Merging

Also called: Block Trimming, Block Trimming and Classification, Empty voxel trimming, Four-level volume-loading pipeline with empty voxel trimming, Volume Partitioning Pipeline with Block Trimming

## Overview
Block Trimming and Texture Block Merging is a preprocessing pipeline that reduces texture memory I/O and resampling overhead for large volume datasets by discarding empty space and packing remaining data into hardware-friendly chunks [S2]. It differs from sibling partitioning methods like [Median-Cut](13179-median-cut.md) or [Division Heuristics Refinements](18019-division-heuristics-refinements.md) by explicitly optimizing for texture cache residency through irregular block merging, rather than solely minimizing spatial partition volume [S2].

## How it works
**Inputs:** A set of axis-aligned volume blocks (partitions) produced by [Greedy Axis-Aligned Spatial Partitioning](11589-greedy-axis-aligned-spatial-partitioning.md), a classification threshold, and texture cache parameters.
**Outputs:** A set of merged texture chunks resident in texture memory, with block nodes containing bounding box metadata and texture coordinates.

### Data Structures
*   **Volume Block:** Represents a partition from the parent method. Contains raw voxel data or pointers to compressed storage.
*   **Block Node:** Metadata stored for each texture block/chunk. Fields:
    *   `world_pos`: $(x, y, z)$ offset in world space (preserved during rotation/merge).
    *   `tex_coords`: $(u, v, w)$ offset in texture memory.
    *   `thickness`: Original thickness $d_s$ along the trimming axis.
    *   `trimming_axis`: The axis along which the block was trimmed (X, Y, or Z).
    *   `chunk_ptr`: Pointer to the merged texture chunk in memory (shared if merged).
*   **Texture Chunk:** A contiguous block in texture memory. Dimensions vary based on merge operations.

### Parameters
*   $d$: Base dimension of the original volume block (e.g., $2^d$).
*   $u, v$: Cluster dimensions. Computed such that a cluster of $u \times v$ blocks fits in the texture cache [S2].
*   Classification threshold: Used to distinguish "object voxels" from empty voxels [S2].

### Steps

1.  **Classification and Block Typing:**
    For each volume block, determine the bounding box of non-empty "object voxels" using min-max arrays [S2]. Calculate the bounding box volume $V_{bb}$ and compare to the block volume $V_{block}$:
    *   If $V_{bb} = 0$: Mark as **White Block** (all empty).
    *   If $V_{bb} = V_{block}$: Mark as **Black Block** (no trimming possible).
    *   Otherwise: Mark as **Grey Block** [S2].

2.  **Block Trimming:**
    *   **White Blocks:** Discard. Store empty parts in the volume buffer (or discard if not needed for reconstruction) [S2].
    *   **Black Blocks:** Move entire block to texture buffer as a texture block of size $2^d \times 2^d \times 2^d$ [S2].
    *   **Grey Blocks:**
        1.  Identify the trimming axis $s$ as the axis with the shortest interval length among the bounding box extents [S2].
        2.  Let $[L_s, R_s]$ be the lower and upper bounds of object voxels along axis $s$.
        3.  Trim the block along axis $s$. The resulting texture block size is $2^d \times 2^d \times d_s$, where $d_s = R_s - L_s + 1$ [S2].
        4.  Empty voxels outside the bounding box on the four faces *perpendicular* to the trimming axis are retained in the texture block but marked to be skipped during resampling [S2].
        5.  Store bounding box info and `trimming_axis` in the Block Node [S2].

3.  **Clustering:**
    Group texture blocks into clusters of size $u \times v$ containing adjacent blocks with the same index along the Z-axis. If necessary, add White Blocks to the last clusters to fill them. Record initial `tex_coords` in Block Nodes [S2].

4.  **Texture Block Merging:**
    Merge texture blocks into larger chunks to optimize texture cache I/O. This involves two phases:

    **Phase 4a: Merging Within Cluster**
    1.  **Rotation:** If a block's `trimming_axis` is not Z, rotate and reorganize the block in the texture buffer so the trimming axis becomes Z. Update `tex_coords` to maintain correct mapping, while keeping `world_pos` fixed [S2].
    2.  **Horizontal Merge:**
        *   Select two blocks with the smallest difference in thickness (length along Z).
        *   Merge into a chunk of size $2^{d+1} \times 2^d \times d_m$, where $d_m = \max(d_{block1}, d_{block2})$ [S2].
        *   Fill the extended part of the thinner block with empty voxels.
        *   Save original thickness in Block Node [S2].
    3.  **Vertical Merge:**
        *   If $d_{block1} + d_{block2} \leq d$: Pile blocks to form a chunk of size $2^d \times 2^d \times (d_{block1} + d_{block2})$ [S2].
        *   If one block is already horizontally merged ($2^{d+1} \times 2^d \times d_m$): Exclude its extended part, pile the other block. Resulting size is $2^{d+1} \times 2^d \times d_{new}$, where $d_{new} = \max(d_m, d_{block1} + d_{block2})$. Fill extended parts with empty voxels if necessary [S2].
    4.  Repeat merges until no pairs can be merged. Horizontal merge pairs are selected in ascending order of thickness difference [S2].

    **Phase 4b: Merging Between Clusters**
    1.  Traverse clusters along Z, then Y, then X axes (order determined by view direction) [S2].
    2.  For each row of clusters along Z (same X, Y indices), execute horizontal and vertical merges on unmerged texture blocks from adjacent clusters along Z [S2].
    3.  **Storage:** Store the merged chunk only once in texture memory. Reference it via pointers in the Block Nodes of both clusters. This ensures the chunk remains resident for rendering clusters with different traversing orders [S2].

def block_trimming_and_merging(volume_blocks, classification_threshold, cache_size):
    """
    volume_blocks: List of VolumeBlock objects from Greedy Axis-Aligned Spatial Partitioning.
    classification_threshold: Scalar value for object/empty voxel distinction.
    cache_size: Size of texture cache in bytes.
    """
    texture_blocks = []
    
    # Step 1 & 2: Classification and Trimming
    for block in volume_blocks:
        # Classify voxels based on threshold
        object_voxels = [v for v in block.voxels if v.value >= classification_threshold]
        
        if not object_voxels:
            # White Block: All empty
            continue
        
        # Find bounding box of object voxels
        min_x, max_x = min(v.x for v in object_voxels), max(v.x for v in object_voxels)
        min_y, max_y = min(v.y for v in object_voxels), max(v.y for v in object_voxels)
        min_z, max_z = min(v.z for v in object_voxels), max(v.z for v in object_voxels)
        
        bb_volume = (max_x - min_x + 1) * (max_y - min_y + 1) * (max_z - min_z + 1)
        block_volume = block.width * block.height * block.depth
        
        if bb_volume == 0:
            continue # Should be caught by empty check, but for safety
        elif bb_volume == block_volume:
            # Black Block: No trimming
            tex_block = TextureBlock(
                data=block.voxels,
                width=block.width,
                height=block.height,
                depth=block.depth,
                trimming_axis='Z', # Default, no trim needed
                world_pos=block.world_pos,
                thickness=block.depth
            )
            texture_blocks.append(tex_block)
        else:
            # Grey Block: Trim
            # Determine trimming axis: shortest interval
            len_x = max_x - min_x + 1
            len_y = max_y - min_y + 1
            len_z = max_z - min_z + 1
            
            lengths = {'X': len_x, 'Y': len_y, 'Z': len_z}
            trimming_axis = min(lengths, key=lengths.get)
            
            # Extract trimmed data
            # Note: Retain empty voxels on faces perpendicular to trimming axis
            # but mark them to skip resampling.
            trimmed_data = extract_trimmed_data(block.voxels, min_x, max_x, min_y, max_y, min_z, max_z)
            
            if trimming_axis == 'X':
                new_width = len_x
                new_height = block.height
                new_depth = block.depth
            elif trimming_axis == 'Y':
                new_width = block.width
                new_height = len_y
                new_depth = block.depth
            else: # Z
                new_width = block.width
                new_height = block.height
                new_depth = len_z
                
            tex_block = TextureBlock(
                data=trimmed_data,
                width=new_width,
                height=new_height,
                depth=new_depth,
                trimming_axis=trimming_axis,
                world_pos=block.world_pos,
                thickness=len_z if trimming_axis == 'Z' else (len_y if trimming_axis == 'Y' else len_x)
            )
            texture_blocks.append(tex_block)

    # Step 3: Clustering
    clusters = create_clusters(texture_blocks, cache_size)
    
    # Step 4: Merging
    merged_chunks = []
    
    # Phase 4a: Within Cluster
    for cluster in clusters:
        # Rotate blocks so trimming axis is Z
        for block in cluster:
            if block.trimming_axis != 'Z':
                rotate_block_to_z(block)
                block.trimming_axis = 'Z'
        
        # Merge until stable
        while True:
            merged = False
            # Horizontal Merge: Smallest thickness difference
            pairs = get_mergeable_pairs(cluster, type='horizontal')
            if not pairs:
                break
            for b1, b2 in pairs:
                chunk = horizontal_merge(b1, b2)
                b1.chunk_ptr = chunk
                b2.chunk_ptr = chunk
                merged = True
                # Remove b1, b2 from cluster, add chunk? 
                # Or mark as merged. The source implies replacing blocks with chunks.
                # For simplicity, we assume the cluster list is updated or pointers handle it.
                # Here we just update pointers and mark blocks as part of a chunk.
            
            # Vertical Merge
            pairs = get_mergeable_pairs(cluster, type='vertical')
            if not pairs:
                break
            for b1, b2 in pairs:
                chunk = vertical_merge(b1, b2)
                b1.chunk_ptr = chunk
                b2.chunk_ptr = chunk
                merged = True
                
            if not merged:
                break

    # Phase 4b: Between Clusters
    # Traverse along Z, then Y, then X
    for axis in ['Z', 'Y', 'X']:
        for cluster_i, cluster_j in get_adjacent_clusters(clusters, axis):
            for b1 in cluster_i:
                if b1.chunk_ptr: continue # Already merged
                for b2 in cluster_j:
                    if b2.chunk_ptr: continue
                    # Try merge
                    chunk = try_merge(b1, b2)
                    if chunk:
                        b1.chunk_ptr = chunk
                        b2.chunk_ptr = chunk
                        merged_chunks.append(chunk)
                        break # Found a merge for b1

    return merged_chunks

### Edge Cases and Pitfalls
*   **Memory Swapping:** If the volume data exceeds main memory (e.g., HEAD III dataset), preprocessing time increases due to swapping. Solution: Compress data in the volume buffer and reconstruct only necessary texture blocks on the fly [S2].
*   **Resampling Skips:** Empty voxels retained on the four faces perpendicular to the trimming axis must be explicitly skipped during resampling to avoid unnecessary computation [S2].
*   **Texture Coordinates:** When rotating or moving blocks during merging, `tex_coords` must be updated to maintain correct texture mapping, while `world_pos` remains fixed. This ensures trimmed blocks "stay" in their original world position during rendering [S2].
*   **Merge Order:** Different orderings of merge operations lead to different results. Adjusting the order (e.g., horizontal before vertical) can produce chunks that match hardware loading speeds for higher I/O performance [S2].

## Operating characteristics
*   **Time Complexity:** Preprocessing time is proportional to the number of blocks and the cost of merging. For datasets too large for main memory, reconstruction time adds overhead [S2].
*   **Memory Complexity:** Reduces texture memory usage by discarding empty voxels and packing remaining data into dense chunks [S2].
*   **Performance:** Boosts rendering speed of large volume data with texture mapping hardware by approximately a factor of 2 [S2].
*   **Strengths:** Effective reduction of texture I/O and resampling operations; handles large datasets via on-the-fly reconstruction [S2].
*   **Limitations:** Preprocessing time can be significant for very large datasets; requires careful tuning of merge order for optimal hardware performance [S2].
*   **When to Use:** Rendering large volume datasets with texture mapping hardware where memory bandwidth is a bottleneck.
*   **When Not to Use:** When preprocessing time is prohibitive and real-time classification updates are not required, or when the dataset is small enough to fit in texture memory without optimization.

## Background
The method was proposed by Tone et al. in 1999 as part of a four-level volume-loading pipeline to efficiently render large volume data using texture mapping hardware [S2]. It was tested on the Head I, Frog, and Foot datasets [S2]. The approach addresses the limitations of conventional texture mapping methods by introducing a preprocessing stage that optimizes data layout for texture cache residency [S2].
