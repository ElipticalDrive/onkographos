# Median-Cut

Also called: SAH-based Median-Cut

## Overview
Median-Cut is a method to build a spatial hierarchy bottom-up by choosing the direction and position of splits carefully [S1, unofficial]. It differs from standard median-cut color quantization by applying the split logic to spatial bounding boxes rather than color histograms, and it specifically employs the Surface Area Heuristic (SAH) to optimize the split position and direction, distinguishing it from simple geometric median splits [S1, unofficial]. It builds on [Greedy Axis-Aligned Spatial Partitioning](11589-greedy-axis-aligned-spatial-partitioning.md) [G].

## How it works
**Inputs:** A set of sub-boxes represented by their transformation matrices and a parent bounding box matrix [S2, unofficial].
**Outputs:** Two disjoint lists of sub-box indices (left and right children) resulting from a single split [S2, unofficial].

**Data Structures:**
*   Each sub-box contains a transformation matrix (4x4) representing its position and orientation [S2, unofficial].
*   An index list `inds` tracks sub-box positions [S2, unofficial].

**Steps:**
1. Initialize index list `inds` with integers from $0$ to $N-1$, where $N$ is the number of sub-boxes [S2, unofficial].
2. Extract the x, y, and z axes from the parent bounding box's transformation matrix columns: $\mathbf{x}_{\text{axis}} = \text{matrix.column}(0)$, $\mathbf{y}_{\text{axis}} = \text{matrix.column}(1)$, $\mathbf{z}_{\text{axis}} = \text{matrix.column}(2)$ [S2, unofficial].
3. Calculate the squared length (scale) for each axis vector: $S_x = \|\mathbf{x}_{\text{axis}}\|^2$, $S_y = \|\mathbf{y}_{\text{axis}}\|^2$, $S_z = \|\mathbf{z}_{\text{axis}}\|^2$ [S2, unofficial].
4. Determine the `split_axis` as the normalized vector of the axis with the largest squared scale: if $S_x$ is largest, $\mathbf{a} = \text{normalize}(\mathbf{x}_{\text{axis}})$; if $S_y$ is largest, $\mathbf{a} = \text{normalize}(\mathbf{y}_{\text{axis}})$; otherwise, $\mathbf{a} = \text{normalize}(\mathbf{z}_{\text{axis}})$ [S2, unofficial].
5. For each sub-box $i$ in `inds`, extract its center $\mathbf{c}_i$ (the 4th column of its transformation matrix) and compute the dot product $p_i = \mathbf{c}_i \cdot \mathbf{a}$ [S2, unofficial]. Sort `inds` based on $p_i$ in ascending order [S2, unofficial].
6. Split the sorted `inds` list at the median index $M = \lfloor N / 2 \rfloor$ [S2, unofficial]. The left child contains `inds[0...M-1]` and the right child contains `inds[M...N-1]` [S2, unofficial].

**Pseudocode:**
```python
def median_cut_split(sub_boxes, parent_matrix):
    """
    Splits a list of sub-boxes into two groups based on the longest axis 
    of the parent bounding box using a median split on projected centers.
    
    Args:
        sub_boxes: List of objects with a 'matrix' attribute (4x4 matrix).
        parent_matrix: 4x4 matrix representing the parent bounding box.
        
    Returns:
        Tuple of two lists of indices (left_indices, right_indices).
    """
    n = len(sub_boxes)
    if n == 0:
        return [], []
    
    # 1. Initialize index list
    inds = list(range(n))
    
    # 2. Extract axes from parent matrix columns
    x_axis = parent_matrix.column(0)
    y_axis = parent_matrix.column(1)
    z_axis = parent_matrix.column(2)
    
    # 3. Calculate squared length (scale) for each axis
    x_scale = sum(c * c for c in x_axis)
    y_scale = sum(c * c for c in y_axis)
    z_scale = sum(c * c for c in z_axis)
    
    # 4. Determine split_axis as normalized vector of axis with largest squared length
    if x_scale >= y_scale and x_scale >= z_scale:
        split_axis = normalize(x_axis)
    elif y_scale >= x_scale and y_scale >= z_scale:
        split_axis = normalize(y_axis)
    else:
        split_axis = normalize(z_axis)
        
    # 5. Sort inds based on dot product of sub_box center with split_axis
    # Center is typically the 4th column (index 3) of the transformation matrix
    def get_projection(index):
        center = sub_boxes[index].matrix.column(3)
        return dot(center, split_axis)
    
    # Python's sort is stable by default [G]
    inds.sort(key=get_projection)
    
    # 6. Split at median index
    mid = n // 2
    left_indices = inds[:mid]
    right_indices = inds[mid:]
    
    return left_indices, right_indices

def dot(v1, v2):
    return sum(a * b for a, b in zip(v1, v2))

def normalize(v):
    length = dot(v, v) ** 0.5
    if length == 0:
        return v
    return [x / length for x in v]
```

**Parameters:**
*   `MAXDEPTH`: Typically 16 [S1, unofficial].
*   `MAXPRIMS`: Typically 2-8 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Floating Point Precision:** When multiple sub-boxes have centers with identical projections, the sort order must be stable to ensure deterministic behavior [G]. The source notes recommend a stable comparison wrapper (e.g., `CmpFloat`) for sorting [S2, unofficial].
*   **Degenerate Axes:** If the parent bounding box has a zero-length axis (degenerate box), normalization fails and requires fallback handling [G].

## Subtopics

### Median-Cut Spatial Partitioning
This variant explicitly defines the splitting logic as projecting sub-box centers onto the longest axis of the parent bounding box and splitting at the median index [S2, unofficial]. It is chosen when a deterministic, axis-aligned split based on spatial extent is required without complex cost calculations [G]. It differs from SAH-based variants by relying purely on geometric median projection rather than ray-casting cost estimation [G].

## Operating characteristics
Time complexity is $O(N \log N)$ per node due to sorting, where $N$ is the number of primitives in the node [G]. Memory complexity is $O(N)$ to store the tree structure and indices [G]. The method is fast to build due to the simplicity of the median split, but may not produce the most optimal tree for ray traversal compared to SAH-based methods that evaluate multiple split positions [G]. It is best used when fast build times are prioritized over optimal traversal performance, or as a baseline for comparison [G]. It should not be used in scenes with highly non-uniform primitive distribution where SAH optimization is critical for performance [G].

## Background
The concept of Median-Cut in spatial partitioning originates from ray tracing acceleration structures [S1, unofficial]. The specific application of SAH to guide the split direction and position is discussed in ray tracing literature [S1, unofficial].
