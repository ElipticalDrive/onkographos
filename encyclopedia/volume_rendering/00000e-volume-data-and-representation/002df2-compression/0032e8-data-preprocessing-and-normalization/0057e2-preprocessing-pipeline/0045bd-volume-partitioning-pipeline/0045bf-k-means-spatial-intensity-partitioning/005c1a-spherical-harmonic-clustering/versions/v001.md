# Spherical Harmonic Clustering

Also called: ClusterSHs, K-Means Clustering for SH, SH Clustering

## Overview
Spherical Harmonic Clustering reduces the memory footprint of Gaussian Splatting assets by clustering spherical harmonic (SH) coefficients using K-Means, trading precision for storage efficiency [S1, unofficial]. Unlike [K-Means Spatial-Intensity Partitioning](11588-k-means-spatial-intensity-partitioning.md) which groups voxels by spatial and intensity coordinates, this method operates exclusively on the SH coefficient vectors to compress the color representation of splats [S1, unofficial].

## How it works
**Inputs:** A source splat data structure (`InputSplatData`) containing SH coefficients.
**Outputs:** A compressed SH table (`GaussianSplatAsset.SHTableItemFloat16`) where each entry represents a cluster center.

**Data Structures:**
1.  **`shData`**: A temporary `float` array of size `splatData.Length * kShDim`. It stores the raw SH coefficients from the input.
2.  **`shMeans`**: A `float` array of size `shCount * kShDim`. It stores the resulting cluster centers (means) after K-Means convergence. `shCount` is the number of clusters.
3.  **`shIndices`**: An integer array of size `splatData.Length`. It maps each original splat to its assigned cluster index.
4.  **`shs`**: The final output array of type `GaussianSplatAsset.SHTableItemFloat16` with size `shCount`.
5.  **`ConvertSHClustersJob`**: A compute job structure with:
    *   `m_Input`: `NativeArray<float>` reinterpreted as `float3`.
    *   `m_Output`: `NativeArray<GaussianSplatAsset.SHTableItemFloat16>`.

**Parameters:**
*   `kShDim`: Constant dimension of SH data per splat, equal to $15 \times 3 = 45$ floats [S1, unofficial].
*   `kBatchSize`: Constant batch size for K-Means calculation, equal to 2048 [S1, unofficial].
*   `passesOverData`: Number of passes over the data for K-Means. Values depend on the target cluster count format:
    *   Cluster64k: 0.3
    *   Cluster32k: 0.4
    *   Cluster16k: 0.5
    *   Cluster8k: 0.8
    *   Cluster4k: 1.2 [S1, unofficial].

**Algorithm Steps:**
1.  **Check Necessity:** Calculate `shCount` using `GaussianSplatAsset.GetSHCount(format, splatData.Length)`. If `shCount >= splatData.Length`, return early as no clustering is needed [S1, unofficial].
2.  **Gather SH Data:** Allocate `shData` (size `splatData.Length * kShDim`). Copy SH coefficients from `splatData` into `shData`. The SH data starts at offset 9 floats from the start of each splat's data block [S1, unofficial].
3.  **K-Means Clustering:** Allocate `shMeans` (size `shCount * kShDim`) and `shIndices` (size `splatData.Length`). Call `KMeansClustering.Calculate` with parameters: `kShDim`, `shData`, `kBatchSize`, `passesOverData`, a progress callback, `shMeans`, and `shIndices`. Dispose of `shData` after this step [S1, unofficial].
4.  **Quantize and Pack:** Allocate `shs` (size `shCount`). Create a `ConvertSHClustersJob` with `m_Input` set to `shMeans` reinterpreted as `float3` and `m_Output` set to `shs`. Schedule and complete the job with a batch size of 256. The job maps each input float to a half-precision 3-component vector (`half3`) [S1, unofficial]. Dispose of `shMeans` [S1, unofficial].

**Pseudocode:**
```python
def spherical_harmonic_clustering(splat_data, format, progress_callback):
    # Step 1: Check necessity
    sh_count = get_sh_count(format, len(splat_data))
    if sh_count >= len(splat_data):
        return None  # No clustering needed

    k_sh_dim = 45  # 15 * 3
    k_batch_size = 2048
    
    # Step 2: Gather SH Data
    # SH data starts at offset 9 floats per splat
    sh_data = allocate_array(len(splat_data) * k_sh_dim)
    for i in range(len(splat_data)):
        # Copy 45 floats starting from offset 9
        src_ptr = splat_data[i].ptr + 9 * sizeof(float)
        mem_copy(sh_data[i * k_sh_dim], src_ptr, k_sh_dim * sizeof(float))

    # Step 3: K-Means Clustering
    sh_means = allocate_array(sh_count * k_sh_dim)
    sh_indices = allocate_array(len(splat_data))
    
    # Determine passes based on format
    passes_map = {
        "Cluster64k": 0.3,
        "Cluster32k": 0.4,
        "Cluster16k": 0.5,
        "Cluster8k": 0.8,
        "Cluster4k": 1.2
    }
    passes = passes_map.get(format, 1.0) # [G] Default fallback if format not in map
    
    k_means_calculate(
        k_sh_dim=k_sh_dim,
        data=sh_data,
        batch_size=k_batch_size,
        passes=passes,
        callback=progress_callback,
        means=sh_means,
        indices=sh_indices
    )
    
    free(sh_data)

    # Step 4: Quantize and Pack
    shs = allocate_array(sh_count, type=GaussianSplatAsset.SHTableItemFloat16)
    
    # ConvertSHClustersJob execution
    # Input is sh_means reinterpreted as float3
    # Output is shs
    # Batch size 256
    job_input = sh_means.view_as_float3()
    job_output = shs
    
    for i in range(sh_count):
        addr = i * 15
        # Map 15 floats to 5 half3 components (sh1 to shF)
        # Each half3 takes 3 floats
        for c in range(5):
            base_idx = addr + c * 3
            r = float_to_half(job_input[base_idx])
            g = float_to_half(job_input[base_idx + 1])
            b = float_to_half(job_input[base_idx + 2])
            job_output[i].sh[c] = half3(r, g, b)
            
    free(sh_means)
    
    return shs
```

**Edge Cases and Pitfalls:**
*   **Precision Loss:** Converting from `float` to `half` (16-bit) during the packing step introduces quantization error [S1, unofficial].
*   **Early Return:** If the target cluster count is not smaller than the input splat count, the method returns early to avoid unnecessary computation [S1, unofficial].
*   **Memory Management:** Temporary arrays (`shData`, `shMeans`) must be explicitly disposed of to prevent memory leaks, as indicated by the use of persistent allocators [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the K-Means clustering step, which runs for `passesOverData` iterations over `splatData.Length` items. The constant factor is influenced by `kShDim` (45) and `kBatchSize` (2048) [S1, unofficial].
*   **Memory Complexity:** Requires temporary storage for `shData` ($N \times 45$ floats) and `shMeans` ($K \times 45$ floats), where $N$ is splat count and $K$ is cluster count. The final output is $K$ half-precision entries [S1, unofficial].
*   **Strengths:** Significantly reduces memory usage for SH coefficients, which can be large for high-order harmonics [S1, unofficial].
*   **Limitations:** Loss of precision due to clustering and half-precision quantization. Performance depends on the number of passes, which varies by target cluster count [S1, unofficial].
*   **When to Use:** When memory bandwidth or storage is a bottleneck and slight color fidelity loss is acceptable.
*   **When Not to Use:** When high-fidelity color reproduction is critical or when the number of splats is small enough that compression benefits are negligible.

## Background
This method is part of the preprocessing pipeline for Gaussian Splatting assets in Unity, specifically within the `worldlabs_unity` implementation. It is designed to optimize the rendering of large-scale Gaussian Splat scenes by reducing the size of the SH data stored in GPU memory [S1, unofficial].
