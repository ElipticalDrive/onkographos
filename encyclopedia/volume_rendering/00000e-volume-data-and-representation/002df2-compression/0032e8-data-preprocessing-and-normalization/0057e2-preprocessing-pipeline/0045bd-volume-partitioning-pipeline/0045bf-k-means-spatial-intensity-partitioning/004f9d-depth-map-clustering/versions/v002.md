# Depth Map Clustering

Also called: Depth Interval Clustering, K-Means Depth Clustering

## Overview
Depth Map Clustering reduces the number of depth layers in a depth map to accelerate hologram calculation with minimal visual quality decrease [S1]. It partitions the depth range into a limited set of intervals using k-means clustering on the depth map histogram [S1]. Unlike [K-Means Spatial-Intensity Partitioning](11588-k-means-spatial-intensity-partitioning.md), which clusters voxels based on spatial coordinates and intensity, this method operates solely on the 1D histogram of depth values to determine layer boundaries [S1].

## How it works
**Inputs:**
- Depth map $D(x, y)$ with resolution $N_x \times N_y$.
- Maximum number of depth intervals $N_z \le 256$ [S1].
- Initial depth range $[0, 256]$ [S1].

**Outputs:**
- $N_z$ depth intervals $[d_i, d_{i+1}[$ for $i \in \{0, \dots, N_z - 1\}$ [S1].
- Cluster centers $d_i$ representing the average depth value of each cluster [S1].

**Data Structures:**
- Histogram $H_D$: Array of size 257 (for depth values 0 to 256), where $H_D[n]$ is the count of pixels with depth value $n$ [S1].
- Cluster centers: Array of size $N_z + 1$, storing the average depth value for each cluster and the upper boundary [S1].

**Algorithm:**
1. **Histogram Computation:** Compute $H_D$ from the input depth map $D$ [S1].
2. **Initialization:** Set initial boundaries $d_0 = 0$ and $d_{N_z} = 256$ [S1].
3. **Initial Interval Calculation:** For $i = 0, \dots, N_z - 2$, compute the next boundary:
   $$ d_{i+1} = \left\lceil \frac{1}{N_z} \sum_{n=d_i}^{d_{i+1}} H_D[n] \right\rceil $$
   [S1].
4. **Iteration:** Repeat the following steps until cluster centers $d_i$ no longer change:
   - **Assignment Step:** For each $i = 0, \dots, N_z - 1$, update the boundary $d_{i+1}$ to the minimum integer $d$ such that:
     $$ |d - d_i| > |d - d_{i+1}| $$
     where $d_i$ is the current average depth value of cluster $i$ [S1].
   - **Update Step:** Re-compute $d_i$ as the average depth value of all pixels assigned to cluster $i$ [S1].

**Pseudocode:**
```python
def depth_map_clustering(depth_map, N_z):
    # depth_map: 2D array of shape (Nx, Ny) with integer depth values in [0, 256]
    # N_z: integer, max number of depth intervals (<= 256)
    
    # 1. Compute Histogram
    H_D = [0] * 257
    for y in range(depth_map.shape[0]):
        for x in range(depth_map.shape[1]):
            d = depth_map[y, x]
            if 0 <= d <= 256:
                H_D[d] += 1
                
    # 2. Initialize Boundaries & Centers
    d = [0] * (N_z + 1)
    d[0] = 0
    d[N_z] = 256
    
    # 3. Initial Interval Calculation
    # Source formula: d[i+1] = ceil((1/Nz) * sum_{n=d[i]}^{d[i+1]} H_D[n])
    # The formula is implicit (d[i+1] appears on both sides). 
    # A linear initialization is used as a practical fallback [G].
    for i in range(N_z - 1):
        d[i+1] = (i + 1) * (256 // N_z)
        
    # 4. Iteration
    while True:
        d_old = d.copy()
        
        # Assignment Step: Update boundaries based on nearest center
        # d[i] is the center of cluster i. The boundary between cluster i and i+1 is updated.
        # Source: d[i+1] = min { d | |d - d[i]| > |d - d[i+1]| }
        for i in range(N_z):
            boundary = (d[i] + d[i+1]) // 2 + 1
            d[i+1] = boundary
            
        # Update Step: Re-compute d[i] as the average depth value of pixels in [d[i], d[i+1][
        for i in range(N_z):
            count = 0
            total_depth = 0
            for y in range(depth_map.shape[0]):
                for x in range(depth_map.shape[1]):
                    val = depth_map[y, x]
                    if d[i] <= val < d[i+1]:
                        total_depth += val
                        count += 1
            if count > 0:
                d[i] = total_depth // count
            else:
                d[i] = d[i] # Keep previous value if cluster is empty
                
        if d == d_old:
            break
            
    return d
```

**Edge Cases and Pitfalls:**
- The initialization formula in the source is implicit due to recursive dependency on $d_{i+1}$ within the summation bounds [S1]. A linear or cumulative histogram initialization is required for implementation [G].
- Depth values are assumed to be integers in the range $[0, 256]$ [S1].
- Empty clusters may occur during the update step if no pixels fall within $[d_i, d_{i+1}[$; the center should retain its previous value to prevent divergence [G].

## Subtopics

### [Depth Clipping for DDGI Probes](17139-depth-clipping-for-ddgi-probes.md)
A compression technique for DDGI light probe depth maps that reduces the dynamic range of stored depth values by clipping them to the maximum distance between adjacent probes, allowing probes with no nearby geometry to be identified as 'dead' and compressed efficiently.

## Operating characteristics
- **Time Complexity:** Depends on the number of k-means iterations and the depth map resolution $N_x \times N_y$ [S1]. Each iteration requires histogram computation ($O(N_x N_y)$) and cluster updates ($O(N_x N_y)$ or $O(N_z)$ depending on implementation) [S1].
- **Memory Complexity:** Not given in the sources.
- **Performance:** Accelerates hologram calculation by reducing the number of depth layers to $N_z \le 256$ [S1].
- **Strengths:** Minimal decrease in visual quality [S1]. Suitable for embedded platforms like NVIDIA Jetson AGX Orin [S1].
- **Limitations:** Designed for depth maps in holographic near-eye displays [S1].

## Background
- **Origin:** Proposed by Antonin Gilles, Pierre Le Gargasson, Grégory Hocquet, and Patrick Gioia in 2023 [S1].
- **Context:** Part of an embedded hologram rendering engine for a holographic near-eye display [S1].
- **Application:** Used in layer-based hologram synthesis to reduce the number of depth layers [S1].
