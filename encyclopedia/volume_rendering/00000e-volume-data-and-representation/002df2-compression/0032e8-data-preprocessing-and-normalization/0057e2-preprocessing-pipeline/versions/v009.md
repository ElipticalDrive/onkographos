# Preprocessing Pipeline

Also called: VolCon and Compress Pipeline, Volume Preprocessing Pipeline, buildVolumeImage, crop-downsample-convert

## Overview
The Preprocessing Pipeline prepares raw volumetric data for rendering by applying label banding, cropping to the body bounding box, downsampling, adjusting spacing, and optionally converting to 16-bit float before wrapping in VTK `imageData` [S2, unofficial]. It differs from the [Volume Partitioning Pipeline](11585-volume-partitioning-pipeline.md) by operating on the full volume extent rather than splitting it into disjoint foreground regions, and from the [3D Seismic Data Compression Pipeline](11727-3d-seismic-data-compression-pipeline.md) by using generic intensity thresholds rather than seismic-specific physics [S1]. It serves as the foundational data normalization step before multi-resolution structures like octrees are built [S1].

## How it works
**Inputs:** Raw volume data (e.g., DICOM slices, raw binary files), configuration parameters (`PERF` object).
**Outputs:** A VTK `vtkImageData` object containing the processed voxel data, spacing, and origin.

**Data Structures:**
*   `PERF`: Configuration object containing:
    *   `crop` (boolean): Enable body bounding box cropping.
    *   `down` (integer): Downsampling stride factor.
    *   `tex` (string): Texture format flag. `'f16'` triggers 16-bit float conversion.
*   `AIR_HU`: Constant threshold value for air, typically -500 [S2, unofficial].

**Steps:**
1.  **Label Banding:** If the input volume contains semantic labels, apply `bandLabeledHuValues` to map raw Hounsfield Unit (HU) values to labeled bands. If no labels exist, use raw values [S2, unofficial].
2.  **Cropping:** If `PERF.crop` is true:
    *   Compute the body bounding box by thresholding the volume with `AIR_HU` (-500) to identify non-air regions [S2, unofficial].
    *   Crop the volume to this bounding box.
    *   Shift the volume origin to preserve world coordinates relative to the original dataset [S2, unofficial].
3.  **Downsampling:** Apply `strideDownsample` to the volume using `PERF.down` as the stride factor. This reduces the spatial dimensions by the factor [S2, unofficial].
4.  **Spacing Adjustment:** Multiply the original voxel spacing by `PERF.down` to maintain the correct physical dimensions of the cropped/downsampled volume [S2, unofficial].
5.  **Format Conversion:** If `PERF.tex` equals `'f16'`, convert the voxel data values to 16-bit floating point format [S2, unofficial].
6.  **VTK Construction:** Create a `vtkImageData` object with the new dimensions, adjusted spacing, and shifted origin. Assign the processed scalar values to the image data [S2, unofficial].
7.  **Mapper Configuration:** If `PERF.tex` is `'f16'`, set the mapper's `preferSizeOverAccuracy` flag to true to optimize rendering performance for the lower-precision data [S2, unofficial].
8.  **Binding:** Bind the `vtkImageData` data to the volume mapper [S2, unofficial].

**Pseudocode:**
```python
def preprocess_volume(raw_volume, spacing, origin, perf_config):
    """
    Preprocesses a raw volume for rendering.
    
    Args:
        raw_volume: 3D numpy array or similar structure of raw voxel values.
        spacing: Tuple (sx, sy, sz) of original voxel spacing.
        origin: Tuple (ox, oy, oz) of original volume origin.
        perf_config: Dict with keys 'crop' (bool), 'down' (int), 'tex' (str).
        
    Returns:
        vtkImageData object ready for rendering.
    """
    AIR_HU = -500
    
    # Step 1: Label Banding
    # If labels exist, apply bandLabeledHuValues; otherwise use raw values.
    # [G] Assuming raw_volume is already labeled or raw HU values.
    if has_labels(raw_volume):
        volume = bandLabeledHuValues(raw_volume)
    else:
        volume = raw_volume
        
    # Step 2: Cropping
    new_origin = origin
    if perf_config['crop']:
        # Compute body bounding box using AIR_HU threshold
        # [G] Find min/max indices where volume > AIR_HU
        mask = volume > AIR_HU
        if not np.any(mask):
            # Handle case where no body is found; return original or empty
            pass
        else:
            z_min, z_max = np.where(mask.any(axis=(0, 1)))[0][[0, -1]]
            y_min, y_max = np.where(mask.any(axis=(0, 2)))[0][[0, -1]]
            x_min, x_max = np.where(mask.any(axis=(1, 2)))[0][[0, -1]]
            
            # Crop volume to box
            volume = volume[z_min:z_max+1, y_min:y_max+1, x_min:x_max+1]
            
            # Shift origin to preserve world coordinates
            # [G] Adjust origin by subtracting the offset in world space
            new_origin = (
                origin[0] + x_min * spacing[0],
                origin[1] + y_min * spacing[1],
                origin[2] + z_min * spacing[2]
            )
            
    # Step 3: Downsampling
    down_factor = perf_config['down']
    if down_factor > 1:
        # Apply stride downsampling
        # [G] Select every down_factor-th voxel
        volume = volume[::down_factor, ::down_factor, ::down_factor]
        
    # Step 4: Adjust Spacing
    new_spacing = (
        spacing[0] * down_factor,
        spacing[1] * down_factor,
        spacing[2] * down_factor
    )
    
    # Step 5: Format Conversion
    if perf_config['tex'] == 'f16':
        # Convert to 16-bit float
        # [G] Cast to float16. Note: Precision loss may occur.
        volume = volume.astype(np.float16)
        
    # Step 6: Build vtkImageData
    # [G] Assuming a helper function to create VTK image data
    vtk_image = create_vtk_image_data(
        dimensions=volume.shape,
        spacing=new_spacing,
        origin=new_origin,
        scalars=volume
    )
    
    # Step 7: Set mapper preference
    # [G] This step affects the rendering pipeline, not the data structure itself.
    # The caller should set mapper.preferSizeOverAccuracy = True if perf_config['tex'] == 'f16'
    
    # Step 8: Bind data
    # [G] The vtkImageData object is returned to be bound by the rendering engine.
    return vtk_image
```

**Edge Cases and Pitfalls:**
*   **Precision:** Reinterpreting a `Uint8Array` buffer as `Float32Array` is safe in JavaScript engines due to native little-endian architecture, provided metadata validates `byte_order === 'little'`. Using `DataView` for byte-by-byte reading is significantly slower (~15s+ for a 145MB volume) and causes stale canvas frames during dataset switches [S2, unofficial].
*   **Empty Volumes:** If cropping results in an empty volume (e.g., no voxels exceed `AIR_HU`), the pipeline should handle this gracefully, potentially returning the original data or an error state [G].
*   **Origin Shift:** Incorrectly calculating the new origin after cropping can misalign the volume in world space, leading to incorrect rendering relative to other scene objects [S2, unofficial].

## Subtopics

### [VolumeSegmenter Pipeline](11584-volumesegmenter-pipeline.md)
The VolumeSegmenter Pipeline is an end-to-end method for compressing large RAW volumetric datasets into compact, spatially mapped bricks organized into selectable logical groups, enabling efficient rendering in WebGL2. It reduces stored and GPU-resident voxel data significantly, though it may increase rendering time due to sparse lookup and ray-marching overhead compared to monolithic source rendering. It differs from the [Volume Partitioning Pipeline](11585-volume-partitioning-pipeline.md) by explicitly grouping bricks via intensity bands and adjacency rather than purely spatial partitioning, and builds on the general [Preprocessing Pipeline](6733-preprocessing-pipeline.md) framework [G].

### [Volume Partitioning Pipeline](11585-volume-partitioning-pipeline.md)
The Volume Partitioning Pipeline is a data preprocessing method that splits a 3D volume into disjoint foreground regions, optionally partitions them spatially or by intensity, crops them to bounding boxes, downsamples, and exports them as raw files with metadata. It solves the problem of managing large 3D datasets by reducing memory footprint and enabling efficient out-of-core or chunked processing. It differs from its sibling [VolumeSegmenter Pipeline](11584-volumesegmenter-pipeline.md) by focusing on intensity-based foreground extraction and spatial partitioning rather than semantic segmentation, and from [3D Seismic Data Compression Pipeline](11727-3d-seismic-data-compression-pipeline.md) by using a generic intensity-threshold approach rather than seismic-specific physics.

### [3D Seismic Data Compression Pipeline](11727-3d-seismic-data-compression-pipeline.md)
The 3D Seismic Data Compression Pipeline is a lossy compression method for 3D seismic data that processes volumes in 3D blocks (cubes), applying normalization, closed-loop differential pulse-code modulation (DPCM) with quantization, and Deflate compression to reduce file size while preserving trace integrity. It operates on fixed 3D spatial-temporal blocks rather than semantic segments or arbitrary partitions.

### [Wild Scene Preprocessing & Test Set Selection](13103-wild-scene-preprocessing-test-set-selection.md)
A coarse pre-filtering pipeline to remove low-quality images dominated by transient objects from unconstrained photo collections, ensuring robust training and evaluation for view synthesis systems. It differs from sibling pipelines by focusing specifically on semantic quality (NIMA) and transient occlusion metrics (DeepLab) rather than geometric consistency or voxel-based segmentation.

### [Video Frame Extraction and Preprocessing](15598-video-frame-extraction-and-preprocessing.md)
This method extracts and cleans video frames from laparoscopic surgical recordings to create a high-quality input dataset for 3D scene reconstruction. It solves the problem of degraded input quality caused by camera motion artifacts, lighting inconsistencies, and redundant video borders. It is distinguished from general volume preprocessing by its specific focus on surgical video characteristics, such as discarding frames based on camera pose discontinuities and handling specific black-bar cropping ratios.

#### Slice Preprocessing
A preprocessing phase used for creating cropped slices to be distributed across the network for rendering. Each raw data slice is read once. Non-empty regions are segmented using a mask volume, cropped and written to disc memory. Out-of-core region growing is used if no mask has been provided. Concurrently, data extent information is consolidated into a series of slab-projection slices [S4, unofficial].

#### Feature Map Preprocessing for Visualization
A procedure to transform and normalize feature maps from encoders (LSeg or SAM) for visualization by centering, projecting, and scaling values to a consistent range [S5].
**Steps:**
1.  Use `sklearn.decomposition.PCA` with 3 components (RGB channels) [S5].
2.  Calculate PCA mean by sampling every third element along $h \times w$ vectors (dim 512 for LSeg, 256 for SAM) [S5].
3.  Center features with PCA mean and project onto PCA components [S5].
4.  Normalize transformed features based on min/max values with outliers removed to standardize range [S5].
**Parameters:**
*   Number of PCA components: 3 [S5].
*   LSeg feature dimension: 512 [S5].
*   SAM feature dimension: 256 [S5].
*   LSeg feature map size: $360 \times 480$ [S5].

#### Raw Image Tile Processing
A pipeline stage that generates 2D mipmaps for image tiles emitted by the EM as they arrive, chopping them into sub-tiles for efficient storage and resampling [S6].
**Steps:**
1.  Chop image tiles into $128 \times 128$ sub-tiles [S6].
2.  Store sub-tiles in the visualization archive. They inherit the transformation matrix from the image tile (stored only once), augmented by an offset [S6].
3.  Only meta data are forwarded to the volume construction stage. Actual data are only transmitted if the volume construction stage forwards an actual request from the visualization stage [S6].
**Parameters:**
*   Compression: Sub-tiles are optionally compressed using JPEG at 2bpp [S6].
**Pitfalls:**
*   This stage is independent of registration and subsequent alignment/stitching, allowing it to be fully interleaved with dynamic registration and data acquisition [S6].

#### TripoSR Image Preprocessing
Image preprocessing pipeline that removes background, resizes foreground, and converts to a 50% gray background format required by the TripoSR model [S7, unofficial].
**Steps:**
1.  Initialize rembg session: `rembg_session = rembg.new_session()`.
2.  Remove background: `image = remove_background(image, rembg_session)` [S7, unofficial].
3.  Resize foreground to target ratio: `image = resize_foreground(image, foreground_ratio)`. Default `foreground_ratio` is 0.85 [S7, unofficial].
4.  Convert to float32 and normalize to [0, 1]: `image = np.array(image).astype(np.float32) / 255.0` [S7, unofficial].
5.  Composite RGB over 50% gray background using alpha channel: `image = image[:, :, :3] * image[:, :, 3:4] + (1 - image[:, :, 3:4]) * 0.5` [S7, unofficial].
6.  Convert back to uint8: `image = Image.fromarray((image * 255.0).astype(np.uint8))` [S7, unofficial].

## Operating characteristics
*   **Time Complexity:** The preprocessing steps (cropping, downsampling, conversion) are linear with respect to the number of voxels in the input volume. The VTK construction is also linear. The overall time is dominated by I/O and memory bandwidth for large volumes [S2, unofficial].
*   **Memory Complexity:** The output volume size is reduced by a factor of $down^3$ compared to the original if downsampling is applied. The VTK `imageData` object stores the processed data in memory. For 16-bit float conversion, memory usage per voxel is 2 bytes, compared to 4 bytes for 32-bit float or 1 byte for 8-bit unsigned int [S2, unofficial].
*   **Performance:** On a Core2Duo laptop with 2GB RAM, preprocessing time varies with data set size and octree depth. Deeper octrees generate smaller brick files but increase file access overhead during rendering [S1].
*   **Strengths:** Reduces memory footprint, improves cache efficiency during rendering, and allows for efficient network transmission of cropped data [S4, unofficial].
*   **Limitations:** Loss of detail due to downsampling and cropping. Incorrect origin calculation can lead to misalignment. 16-bit float conversion may introduce precision artifacts [S2, unofficial].
*   **When to use:** When rendering large medical or scientific volumes where full resolution is not necessary for all views, or when memory/bandwidth is constrained.
*   **When not to use:** When high-precision analysis of fine details is required, or when the volume is already small enough to fit comfortably in GPU memory.

## Background
The Preprocessing Pipeline is a fundamental component in volume rendering systems, particularly those dealing with large-scale medical imaging data. It was formalized in the context of gigascale multiresolution volume rendering on distributed display clusters [S1]. The specific implementation described here, involving `VolCon` and `Compress` tools, is part of a two-stage preprocessing step where the first stage computes the octree structure and the second calculates the wavelet representation [S1]. The use of `vtkImageData` and specific parameters like `AIR_HU` for body bounding box detection is common in medical visualization frameworks [S2, unofficial]. The pipeline addresses the challenge of managing large datasets by reducing data size and optimizing it for rendering hardware [S1].
