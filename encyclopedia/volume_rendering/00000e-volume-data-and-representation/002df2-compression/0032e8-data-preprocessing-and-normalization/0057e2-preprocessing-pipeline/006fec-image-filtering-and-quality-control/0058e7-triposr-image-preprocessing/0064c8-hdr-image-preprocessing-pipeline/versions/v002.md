# HDR Image Preprocessing Pipeline

Also called: Bracketed Exposure HDR Construction, CRF Recovery and Normalization

## Overview
This pipeline converts a series of bracketed Low Dynamic Range (LDR) exposures into a normalized 32-bit High Dynamic Range (HDR) radiance image suitable for training Neural Radiance Fields (NeRF) and diffusion-based inverse rendering models [S1, S2]. It solves the problem of capturing and representing scene illumination beyond the limited range of standard 8-bit sensors by recovering the camera's nonlinear tone-mapping function and linearizing the data [S1]. It differs from standard LDR preprocessing by explicitly reconstructing linear radiance values and preserving relative intensity differences through uniform scaling rather than quantization, ensuring numerical stability during deep learning training [S1].

## How it works
**Inputs:** A set of bracketed LDR image series captured from fixed camera poses [S1]. Each series consists of $n$ images (typically 7) with varying exposure durations [S1].
**Outputs:** A single 32-bit HDR image per series, stored as an EXR file, with radiance values linearly scaled to the range $[0, 255]$ [S1].

**Data Structures:**
*   **LDR Input:** $n$ 8-bit JPEG images, dimensions $W \times H$ [S1].
*   **Aligned Series:** $n$ images of same dimensions, registered to a common coordinate frame [S1].
*   **CRF Model:** A function mapping LDR pixel values to linear radiance [S1].
*   **HDR Image:** 32-bit floating-point image, dimensions $W/4 \times H/4$ [S1].

**Steps:**

1.  **Capture:** Acquire a bracketed series of $n$ LDR images from a fixed camera pose [S1]. Use a tripod to minimize pose perturbations [S1]. Keep aperture fixed; vary only exposure duration (shutter speed) [S1]. Maintain a constant relative exposure difference of 1–2 stops between consecutive images [S1]. Ensure the dynamic range covers the scene's limits, such that every pixel is "well-exposed" in at least one image [S1].
2.  **Alignment:** Align the $n$ images in the series to compensate for minor camera pose perturbations [S1]. This step is critical to prevent degradation in the final HDR reconstruction [S1].
3.  **Representative Selection:** Select one "representative" bracketed series from the dataset [S1]. This series should roughly cover the upper and lower limits of the overall dynamic range of the lighting conditions [S1].
4.  **CRF Recovery:** Recover the Camera Response Function (CRF), which is the camera's nonlinear tone-mapping function, from the representative series [S1]. Use the method described in [17] (referenced in [S1]) [S1]. The CRF maps LDR pixel values to linear radiance [S1]. While the linear system could theoretically incorporate pixels from all series, solving it on one representative series is sufficient for consistent exposure levels across the dataset [S1].
5.  **CRF Application:** Apply the recovered CRF uniformly to all bracketed series in the dataset [S1]. This ensures consistent exposure levels and linear radiance values across all images [S1].
6.  **Downsampling:** Downsample each resulting 32-bit HDR image by a factor of 4x to improve computational efficiency [S1].
7.  **Normalization:** Normalize all radiance values by linearly scaling them to the range $[0, 255]$ [S1]. This scaling is uniform, preserving relative differences between values [S1]. Values are not quantized to integers; they remain 32-bit floats to avoid quantization artifacts [S1]. Store the final images as EXR files [S1].

```python
        return image
        
    # Step 5, 6, 7: Apply CRF, Downsample, Normalize
    hdr_images = []
    for aligned_series in aligned_series_list:
        # Step 5: Apply CRF uniformly to all bracketed series [S1]
        linear_radiance_images = [apply_crf(img) for img in aligned_series]
        
        # Step 6: Downsample by factor of 4 for computational efficiency [S1]
        downscaled_image = linear_radiance_images[0][::4, ::4]  # Nearest-neighbor downsampling [G]
        
        # Step 7: Normalize to [0, 255] preserving relative differences, no quantization [S1]
        min_val = downscaled_image.min()
        max_val = downscaled_image.max()
        normalized_image = (downscaled_image - min_val) / (max_val - min_val) * 255.0
        
        hdr_images.append(normalized_image)
        
    return hdr_images
```

**Parameters:**
*   **Bracket Size ($n$):** Number of LDR exposures per HDR image. Typical value: 7 [S1].
*   **Exposure Step:** Relative difference in exposure between consecutive images. Typical value: 1–2 stops [S1].

**Edge Cases and Pitfalls:**
*   **Camera Pose Perturbations:** Slight movements during capture can degrade HDR quality. Mitigated by using a tripod and performing image alignment [S1].
*   **Dynamic Range Coverage:** If the bracketed series does not cover the full dynamic range, some pixels may be clipped in all exposures. Ensure the series covers upper and lower limits [S1].
*   **Quantization:** Normalization must not quantize values to integers. Values must remain 32-bit floats to preserve relative differences [S1].

## Subtopics

### HDR Compression for Stable Training
A preprocessing step used in diffusion-based inverse rendering to ensure stable training of DDPM models [S2]. It compresses HDR content using a global invertible mapping before training and applies the inverse mapping before path tracing [S2]. For outdoor data, the mapping is $f(x) = 0.5 x^{1/2.4}$; for indoor data, it is $f(x) = 0.9 x^{1/6}$ [S2].

### HDR Image Merging with Robustified Poisson Estimator
A merging technique that combines multiple exposure bracketed images into a single HDR image using a robustified Poisson photon noise estimator to provide an unbiased estimate of scene radiance [S3]. It debays raw images to 16-bit linear TIFF images using LibRaw 0.21 [S3]. It tracks the minimum radiance estimate per pixel and color channel during merging to ignore outliers caused by non-saturating raw values [S3]. It sets fully saturated pixels to the lowest radiance that saturates in all images [S3]. The typical number of exposures merged is 9 [S3]. A known pitfall is that Sony α1 raw image values do not saturate as quickly as expected, producing outliers that reduce estimated radiance and cause visible color changes [S3].

## Operating characteristics
*   **Time Complexity:** Dominated by image alignment and CRF recovery [S1]. CRF recovery involves solving a linear system, which can be computationally intensive if all pixels are used, but is optimized by using a single representative series [S1].
*   **Memory Complexity:** Requires storing $n$ LDR images and the resulting 32-bit HDR images [S1]. Downsampling by 4x reduces memory usage by 16x for the HDR images [S1].
*   **Performance:** The pipeline is designed for computational efficiency, with downsampling and single-series CRF recovery reducing training time [S1]. Training HDR NeRF models with this data is comparable to LDR training, with Instant-NGP supporting 32-bit HDR inputs [S1].
*   **Strengths:** Preserves high dynamic range information, ensures numerical stability during training, and is compatible with standard NeRF implementations [S1].
*   **Limitations:** Requires careful capture setup (tripod, fixed aperture) and alignment [S1]. CRF recovery assumes a consistent camera response across all images [S1].
*   **When to Use:** When training HDR NeRF models or comparing against LDR counterparts [S1]. Also used in diffusion-based inverse rendering for stable training [S2].
*   **When Not to Use:** When computational resources are extremely limited and HDR is not required, or when camera pose cannot be stabilized during capture [S1].

## Background
The HDR Image Preprocessing Pipeline was introduced in the context of training HDR NeRF models [S1]. It builds on the standard NeRF formulation by extending it to handle high dynamic range data [S1]. The method for recovering the CRF is based on the work of [17] (referenced in [S1]) [S1]. The pipeline has been used in experiments with the Instant-NGP implementation, which supports 32-bit HDR images in EXR format [S1]. It is also used in diffusion-based inverse rendering for stable training of DDPM models [S2].
