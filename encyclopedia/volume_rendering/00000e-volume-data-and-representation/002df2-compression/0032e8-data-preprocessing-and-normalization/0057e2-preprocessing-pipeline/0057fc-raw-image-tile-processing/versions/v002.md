# Raw Image Tile Processing
## Overview
Raw Image Tile Processing is a pipeline stage that generates 2D mipmaps for image tiles emitted by an Electron Microscope (EM) as they arrive, chopping them into sub-tiles for efficient storage and resampling [S1]. It solves the problem of managing large, high-throughput raw image data streams by decoupling storage formatting from registration and alignment [S1]. Unlike its siblings, which may focus on segmentation or partitioning, this method specifically handles the immediate tiling and optional compression of incoming EM image tiles, forwarding only metadata to the volume construction stage while keeping actual data transmission on-demand [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Raw image tiles emitted by the EM, each containing an affine transformation matrix corresponding to the EM's movement [S1].
*   **Output:** Sub-tiles stored in a visualization archive and metadata forwarded to the volume construction stage [S1].

**Data Structures:**
*   **Image Tile:** Contains pixel data and an attached affine transformation matrix [S1].
*   **Sub-tile:** A $128 \times 128$ block of the original image tile [S1].
*   **Transformation Inheritance:** Each sub-tile inherits the parent image tile's transformation matrix, augmented by an offset corresponding to the sub-tile's position within the parent tile [S1]. The parent matrix is stored only once [S1].

**Steps:**
1.  Continuously poll the acquisition archive for newly arrived image tiles [S1].
2.  Chop each incoming image tile into $128 \times 128$ sub-tiles [S1].
3.  For each sub-tile, inherit the parent image tile's affine transformation matrix and augment it with an offset corresponding to the sub-tile's position within the parent [S1]. Store the parent matrix only once [S1].
4.  Optionally compress each sub-tile using JPEG at 2 bits per pixel (bpp) [S1].
5.  Store the sub-tiles (compressed or uncompressed) in the visualization archive [S1].
6.  Forward only metadata to the volume construction stage [S1].
7.  Transmit actual sub-tile data only if the volume construction stage forwards a specific request from the visualization stage [S1].

**Parameters:**
*   **Sub-tile Size:** $128 \times 128$ pixels [S1].
*   **Compression:** JPEG at 2 bpp [S1].

**Edge Cases and Pitfalls:**
*   **Independence:** This stage is completely independent of registration and subsequent alignment/stitching [S1]. It can be fully interleaved with dynamic registration and data acquisition by the EM [S1].
*   **Performance:** Processing must be fast enough to keep up with the acquisition rate of the EM (e.g., $12,000 \times 12,000$ luminance pixels at 8-bit precision emitted every 15 seconds, $\approx 10$ Mpixels/s) [S1].

## Subtopics

### Independent Tile Compression
A compression strategy for tiled pyramid terrain data where each resolution level is treated as a separate image [S2, unofficial]. Tiles are transmitted and decompressed independently without using information from lower resolution levels [S2, unofficial]. The process involves defining a multiresolution hierarchy, splitting each level into fixed-size regular tiles, generating a separate image for each level, compressing each tile as an isolated image, and transmitting them independently [S2, unofficial]. This strategy incurs an overhead of 33% with respect to the image with the highest resolution level [S2, unofficial]. It is used in applications like Google Earth [S2, unofficial].

## Operating characteristics
*   **Processing Speed:** Fast enough to keep up with the EM acquisition rate [S1].
*   **Storage Efficiency:** Chopping into $128 \times 128$ sub-tiles allows for more efficient disk storage [S1].
*   **Resampling Efficiency:** Sub-tiles enable more efficient resampling in the volume construction stage compared to processing large raw image tiles [S1].
*   **Bandwidth:** Actual data is only transmitted on request, reducing unnecessary bandwidth usage [S1].
*   **Scope:** The stage focuses on dynamic stitching and resampling of multiple image tiles rather than rendering a single clipmap [S1].
*   **Limitations:** The method does not handle registration or alignment; these are external processes [S1].

## Background
This method is part of a pipeline for interactive volume exploration of petascale microscopy data streams [S1]. It was developed to handle data from Scanning Electron Microscopes (SEM) acquiring large image tiles (e.g., $12,000 \times 12,000$ luminance pixels at 8-bit precision) [S1]. The approach allows for dynamic stitching and resampling of multiple image tiles, distinct from rendering a single clipmap [S1].
