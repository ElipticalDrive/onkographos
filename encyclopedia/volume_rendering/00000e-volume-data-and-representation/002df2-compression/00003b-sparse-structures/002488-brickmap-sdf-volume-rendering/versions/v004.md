# Brickmap SDF Volume Rendering

Also called: CSG SDF Raymarching, SDF-based volume algorithm

## Overview
Brickmap SDF Volume Rendering is a technique that represents 3D scenes as Constructive Solid Geometry (CSG) trees of Signed Distance Function (SDF) primitives, evaluates the resulting distance field on the CPU, compresses it into a sparse Brickmap structure, and raymarches through it on the GPU [S1, unofficial]. It differs from direct GPU CSG evaluation by offloading the complex tree traversal and branching logic to the CPU, thereby avoiding high branching overhead on the GPU, and from dense volume rendering by using spatial compression to reduce memory footprint by 10-100x [S1, unofficial].

## How it works
**Inputs:** A CSG tree defining primitive shapes (e.g., cylinders, boxes) and their transformations (translation, rotation, scaling) and operations (union, intersection, difference) [S1, unofficial].
**Outputs:** A rendered image via GPU raymarching through the compressed Brickmap [S1, unofficial].

**Data Structures:**
The Brickmap consists of four dynamic arrays storing $n_{used}$ elements out of $n_{available}$ slots [S1, unofficial]:
1.  **Brick Indices:** A 3D grid of indices with dimensions $73^3$, storing 4 bytes per element, totaling ~1.5 MB [S1, unofficial]. This maps spatial coordinates to brick locations.
2.  **Distance Bricks:** Stores 1-byte signed distance values for voxels within active bricks. The number of bricks varies based on surface area (e.g., 14,716 used out of 19,683 available), totaling ~7.6–10 MB [S1, unofficial]. Each brick contains $8^3$ voxels.
3.  **Color Index Remapping:** An array mapping distance brick indices to color brick indices, storing 4 bytes per brick (e.g., 14,716/16,384 elements), totaling ~0.06 MB [S1, unofficial].
4.  **Color Bricks:** Stores 3-byte RGB color values for voxels in active bricks. The number of bricks varies based on color mixing (e.g., 2,312 used out of 2,744 available), totaling ~4.0 MB [S1, unofficial]. Each brick contains $8^3$ voxels [S1, unofficial].

**Parameters:**
*   **Grid Resolution:** Effective $512^3$ grid evaluated within a bounding box of $[-1, 1]^3$ [S1, unofficial].
*   **Brick Dimensions:** $8^3$ voxels per brick [S1, unofficial].

**Steps:**
1.  **CSG Tree Construction:** Define the scene geometry using a CSG tree. Primitives include basic shapes (e.g., `Cylinder`, `Rect`) and operations (`union`, `intersect`, `diff`, `smooth_union`) [S1, unofficial].
2.  **CPU Distance Field Evaluation:** Evaluate the CSG tree on the CPU to generate a 3D distance field array. Optimizations include skipping empty regions and locally irrelevant SDF nodes [S1, unofficial].
3.  **Brickmap Compression:** Compress the 3D distance field into the Brickmap structure. Only non-empty bricks are stored, achieving 10-100x compression [S1, unofficial].
4.  **GPU Raymarching:** Raymarch through the Brickmap on the GPU. Sample distance and color data per brick. The GPU decodes the brick indices to locate the appropriate distance and color bricks [S1, unofficial].

**Pseudocode:**
```python
# Pseudocode for CPU-side CSG evaluation and Brickmap generation
# Note: This is a simplified representation based on the source description.

def evaluate_csg_tree(tree, grid_resolution, bounding_box):
    """
    Evaluates a CSG tree on the CPU to produce a 3D distance field.
    """
    # Initialize empty distance field
    distance_field = zeros(grid_resolution, grid_resolution, grid_resolution)
    
    # Define grid parameters
    step_size = (bounding_box.max - bounding_box.min) / grid_resolution
    
    # Iterate over all voxels in the grid
    for x in range(grid_resolution):
        for y in range(grid_resolution):
            for z in range(grid_resolution):
                # Convert grid index to world position
                pos = bounding_box.min + Vec3(x, y, z) * step_size
                
                # Evaluate the CSG tree at this position
                # This involves traversing the tree and evaluating SDF primitives
                # and operations (union, intersect, diff, etc.)
                dist = evaluate_sdf_at_position(tree, pos)
                
                distance_field[x, y, z] = dist
                
    return distance_field

def compress_to_brickmap(distance_field, brick_size=8):
    """
    Compresses a dense distance field into a Brickmap structure.
    """
    grid_res = distance_field.shape[0]
    num_bricks_x = grid_res // brick_size
    num_bricks_y = grid_res // brick_size
    num_bricks_z = grid_res // brick_size
    
    brick_indices = zeros(num_bricks_x, num_bricks_y, num_bricks_z, dtype=int32)
    distance_bricks = []
    color_bricks = []
    color_index_map = []
    
    brick_index_counter = 0
    
    for bx in range(num_bricks_x):
        for by in range(num_bricks_y):
            for bz in range(num_bricks_z):
                # Extract brick data
                x_start = bx * brick_size
                y_start = by * brick_size
                z_start = bz * brick_size
                
                brick_data = distance_field[x_start:x_start+brick_size, 
                                            y_start:y_start+brick_size, 
                                            z_start:z_start+brick_size]
                
                # Check if brick is non-empty (e.g., contains surface)
                if is_brick_active(brick_data):
                    # Store brick index
                    brick_indices[bx, by, bz] = brick_index_counter
                    
                    # Store distance data
                    distance_bricks.append(brick_data.flatten())
                    
                    # Placeholder for color extraction (not fully detailed in source)
                    # color_bricks.append(extract_colors(brick_data))
                    # color_index_map.append(brick_index_counter)
                    
                    brick_index_counter += 1
                else:
                    brick_indices[bx, by, bz] = -1 # Mark as empty
                    
    return {
        'brick_indices': brick_indices,
        'distance_bricks': distance_bricks,
        'color_bricks': color_bricks,
        'color_index_map': color_index_map
    }

def raymarch_brickmap(brickmap, ray_origin, ray_direction, max_steps=100):
    """
    Raymarches through the Brickmap on the GPU.
    """
    pos = ray_origin
    total_transmittance = 1.0
    color = Vec3(0, 0, 0)
    
    for step in range(max_steps):
        # Determine which brick the current position is in
        bx, by, bz = get_brick_index(pos, brickmap['brick_indices'])
        
        if bx == -1: # Empty space
            break
            
        # Get the distance brick and color brick
        dist_brick_idx = brickmap['brick_indices'][bx, by, bz]
        dist_brick = brickmap['distance_bricks'][dist_brick_idx]
        color_brick_idx = brickmap['color_index_map'][dist_brick_idx]
        color_brick = brickmap['color_bricks'][color_brick_idx]
        
        # Sample distance and color from the brick
        # This requires mapping world position to local brick coordinates
        local_pos = get_local_brick_position(pos, bx, by, bz)
        dist = sample_distance(dist_brick, local_pos)
        col = sample_color(color_brick, local_pos)
        
        if dist < 0.001: # Hit surface
            color += total_transmittance * col
            break
        else:
            pos += ray_direction * dist
            total_transmittance *= 0.9 # Simple attenuation
            
    return color
```

**Edge Cases and Pitfalls:**
*   **GPU Branching Overhead:** Direct GPU computation of CSG operations causes high branching overhead due to decoding operation types (e.g., `if (operation == op_translation) ...`) and evaluating multiple operations per raymarch step [S1, unofficial].
*   **Precision:** The source notes 1-byte distance storage, which may limit precision compared to dense 2-byte or 4-byte arrays [S1, unofficial].
*   **Boundary Conditions:** The bounding box is $[-1, 1]^3$. Rays starting outside this box or missing the volume entirely must be handled [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** CPU generation time for a $512^3$ grid with 32 operations was 19.3s unoptimized, reduced to 0.28s with optimizations (skipping empty regions, locally irrelevant SDF nodes) [S1, unofficial].
*   **Memory Complexity:** Dense array usage is 640 MB ($512^3 \times 2$ bytes for distance + $512^3 \times 3$ bytes for RGB) [S1, unofficial]. Brickmap usage is ~13.2 MB (1.5 MB indices + 7.6 MB distances + 0.06 MB color remapping + 4.0 MB colors) [S1, unofficial]. This represents a compression ratio of approximately 48x [S1, unofficial].
*   **Strengths:** Faster and higher quality on the GPU than direct GPU CSG evaluation or uncompressed dense arrays [S1, unofficial].
*   **Limitations:** Requires CPU pre-computation of the distance field, which may not be suitable for highly dynamic scenes where the CSG tree changes frequently [S1, unofficial].
*   **When to use:** Suitable for static or slowly changing scenes defined by CSG primitives where memory bandwidth is a bottleneck [S1, unofficial].
*   **When not to use:** Unsuitable for scenes requiring real-time CSG modifications or where the CPU pre-computation time is prohibitive [S1, unofficial].
