# Brickmap SDF Volume Rendering

Also called: CSG SDF Raymarching, SDF-based volume algorithm

## Overview
Brickmap SDF Volume Rendering is a technique that represents 3D scenes as Constructive Solid Geometry (CSG) trees of Signed Distance Function (SDF) primitives, evaluates the resulting distance field on the CPU, compresses it into a sparse Brickmap structure, and raymarches through it on the GPU [S1, unofficial]. It differs from direct GPU CSG evaluation by offloading the complex tree traversal and branching logic to the CPU, thereby avoiding high branching overhead on the GPU, and from dense volume rendering by using spatial compression to reduce memory footprint by 10-100x [S1, unofficial].

## How it works
**Inputs:** A CSG tree defining primitive shapes (e.g., cylinders, boxes) and their transformations (translation, rotation, scaling) and operations (union, intersection, difference) [S1, unofficial].
**Outputs:** A rendered image via GPU raymarching through the compressed Brickmap [S1, unofficial].

**Data Structures:**
The Brickmap consists of four dynamic arrays storing $n_{used}$ elements out of $n_{available}$ slots [S1, unofficial]:
1.  **Brick Indices:** A 3D grid of indices with dimensions $73^3$, storing 4 bytes per element, totaling ~1.5 MB [S1, unofficial]. This maps spatial coordinates to brick locations [S1, unofficial].
2.  **Distance Bricks:** Stores 1-byte signed distance values for voxels within active bricks [S1, unofficial]. The number of bricks varies based on surface area (e.g., 14,716 used out of 19,683 available), totaling ~7.6–10 MB [S1, unofficial]. Each brick contains $8^3$ voxels [S1, unofficial].
3.  **Color Index Remapping:** An array mapping distance brick indices to color brick indices, storing 4 bytes per brick (e.g., 14,716/16,384 elements), totaling ~0.06 MB [S1, unofficial].
4.  **Color Bricks:** Stores 3-byte RGB color values for voxels in active bricks [S1, unofficial]. The number of bricks varies based on color mixing (e.g., 2,312 used out of 2,744 available), totaling ~4.0 MB [S1, unofficial]. Each brick contains $8^3$ voxels [S1, unofficial].

**Parameters:**
*   **Grid Resolution:** Effective $512^3$ grid evaluated within a bounding box of $[-1, 1]^3$ [S1, unofficial].
*   **Brick Dimensions:** $8^3$ voxels per brick [S1, unofficial].

**Steps:**
1.  **CSG Tree Construction:** Define the scene geometry using a CSG tree [S1, unofficial]. Primitives include basic shapes (e.g., `Cylinder`, `Rect`) and operations (`union`, `intersect`, `diff`, `smooth_union`) [S1, unofficial].
2.  **CPU Distance Field Evaluation:** Evaluate the CSG tree on the CPU to generate a 3D distance field array [S1, unofficial]. Optimizations include skipping empty regions and locally irrelevant SDF nodes [S1, unofficial].
3.  **Brickmap Compression:** Compress the 3D distance field into the Brickmap structure [S1, unofficial]. Only non-empty bricks are stored, achieving 10-100x compression [S1, unofficial].
4.  **GPU Raymarching:** Raymarch through the Brickmap on the GPU [S1, unofficial]. Sample distance and color data per brick [S1, unofficial]. The GPU decodes the brick indices to locate the appropriate distance and color bricks [S1, unofficial].

**Pseudocode:**
```python
def evaluate_csg_tree(tree, grid_resolution, bbox_min, bbox_max):
    """Evaluates a CSG tree on the CPU to produce a 3D distance field [S1, unofficial]."""
    res = int(grid_resolution)  # Fix: ensure integer type for array dimensions
    step = (bbox_max - bbox_min) / res
    # Initialize 3D distance field
    distance_field = [[[0.0] * res for _ in range(res)] for _ in range(res)]
    
    for x in range(res):
        for y in range(res):
            for z in range(res):
                pos_x = bbox_min + x * step
                pos_y = bbox_min + y * step
                pos_z = bbox_min + z * step
                # Evaluate CSG tree at position [S1, unofficial]
                dist = tree.evaluate(pos_x, pos_y, pos_z)
                distance_field[x][y][z] = dist
    return distance_field

def compress_to_brickmap(distance_field, brick_size=8):
    """Compresses a dense distance field into the Brickmap structure [S1, unofficial]."""
    res = len(distance_field)
    num_bricks = res // brick_size
    # Brick indices array (dimensions match source: 73^3 in implementation)
    brick_indices = [[[-1] * num_bricks for _ in range(num_bricks)] for _ in range(num_bricks)]
    distance_bricks = []
    color_bricks = []
    color_index_map = []
    brick_counter = 0
    
    for bx in range(num_bricks):
        for by in range(num_bricks):
            for bz in range(num_bricks):
                x0, y0, z0 = bx * brick_size, by * brick_size, bz * brick_size
                # Extract brick voxels
                brick_voxels = [distance_field[x][y][z] for x in range(x0, x0+brick_size)
                                                for y in range(y0, y0+brick_size)
                                                for z in range(z0, z0+brick_size)]
                if is_brick_active(brick_voxels):
                    brick_indices[bx][by][bz] = brick_counter
                    distance_bricks.append(brick_voxels)
                    # Color extraction per source [S1, unofficial]
                    color_bricks.append([0.0] * (brick_size**3 * 3))
                    color_index_map.append(brick_counter)
                    brick_counter += 1
                else:
                    brick_indices[bx][by][bz] = -1
    return brick_indices, distance_bricks, color_bricks, color_index_map

def is_brick_active(brick_voxels):
    """A brick is active if it contains surface voxels (distance near zero)."""
    return any(abs(d) < 0.5 for d in brick_voxels)

def raymarch_brickmap(brick_indices, distance_bricks, color_bricks, color_index_map,
                      ray_origin, ray_direction, brick_size, grid_res, bbox_min, bbox_max):
    """Raymarches through the Brickmap on the GPU [S1, unofficial]."""
    pos = list(ray_origin)
    color = [0.0, 0.0, 0.0]
    transmittance = 1.0
    step = (bbox_max - bbox_min) / grid_res
    max_steps = 100
    
    for _ in range(max_steps):
        # Compute brick indices from world position
        bx = int((pos[0] - bbox_min) / step / brick_size)
        by = int((pos[1] - bbox_min) / step / brick_size)
        bz = int((pos[2] - bbox_min) / step / brick_size)
        
        # Check bounds
        if not (0 <= bx < len(brick_indices) and 0 <= by < len(brick_indices[0]) and 0 <= bz < len(brick_indices[0][0])):
            break
            
        idx = brick_indices[bx][by][bz]
        if idx == -1:
            # Empty brick: step forward by one brick width in world units
            pos[0] += ray_direction[0] * brick_size * step
            pos[1] += ray_direction[1] * brick_size * step
            pos[2] += ray_direction[2] * brick_size * step
            continue
            
        # Get brick data
        dist_data = distance_bricks[idx]
        col_data = color_bricks[color_index_map[idx]]
        
        # Map world pos to local brick coordinates
        local_x = int((pos[0] - (bx * brick_size * step + bbox_min)) / step)
        local_y = int((pos[1] - (by * brick_size * step + bbox_min)) / step)
        local_z = int((pos[2] - (bz * brick_size * step + bbox_min)) / step)
        local_idx = local_x * brick_size**2 + local_y * brick_size + local_z
        
        dist = dist_data[local_idx]
        col = [col_data[local_idx*3], col_data[local_idx*3+1], col_data[local_idx*3+2]]
        
        if dist < 0.001:
            color = [color[i] + transmittance * col[i] for i in range(3)]
            break
        else:
            pos[0] += ray_direction[0] * dist
            pos[1] += ray_direction[1] * dist
            pos[2] += ray_direction[2] * dist
            transmittance *= 0.9
            
    return color
```

**Edge Cases and Pitfalls:**
*   **GPU Branching Overhead:** Direct GPU computation of CSG operations causes high branching overhead due to decoding operation types (e.g., `if (operation == op_translation) ...`) and evaluating multiple operations per raymarch step [S1, unofficial].
*   **Precision:** The source notes 1-byte distance storage, which may limit precision compared to dense 2-byte or 4-byte arrays [S1, unofficial].
*   **Boundary Conditions:** The bounding box is $[-1, 1]^3$ [S1, unofficial]. Rays starting outside this box or missing the volume entirely must be handled [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** CPU generation time for a $512^3$ grid with 32 operations was 19.3s unoptimized, reduced to 0.28s with optimizations (skipping empty regions, locally irrelevant SDF nodes) [S1, unofficial].
*   **Memory Complexity:** Dense array usage is 640 MB ($512^3 \times 2$ bytes for distance + $512^3 \times 3$ bytes for RGB) [S1, unofficial]. Brickmap usage is ~13.2 MB (1.5 MB indices + 7.6 MB distances + 0.06 MB color remapping + 4.0 MB colors) [S1, unofficial]. This achieves a compression ratio of 10-100x [S1, unofficial].
*   **Strengths:** Faster and higher quality on the GPU than direct GPU CSG evaluation or uncompressed dense arrays [S1, unofficial].
*   **Limitations:** Requires CPU pre-computation of the distance field, which may not be suitable for highly dynamic scenes where the CSG tree changes frequently [S1, unofficial].
*   **When to use:** Suitable for static or slowly changing scenes defined by CSG primitives where memory bandwidth is a bottleneck [S1, unofficial].
*   **When not to use:** Unsuitable for scenes requiring real-time CSG modifications or where the CPU pre-computation time is prohibitive [S1, unofficial].

## Background
The method was inspired by a gamedev YouTube video and shape functions/CSG operations derived from Inigo Quilez's articles on 3D signed distance functions [S1, unofficial]. It was implemented in Makie.jl (Julia) as `csgplot` with `Brickmap` compression [S1, unofficial].
