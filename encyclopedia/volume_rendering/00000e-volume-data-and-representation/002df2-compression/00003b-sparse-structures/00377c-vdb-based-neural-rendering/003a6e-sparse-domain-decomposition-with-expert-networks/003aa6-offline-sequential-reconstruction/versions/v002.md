# Offline Sequential Reconstruction

Also called: NeuralVDB Decoding, NeuralVDB [Hash, NN(4), NN(3)] Decoding, Offline VDB reconstruction, Sequential decoding

## Overview
Offline Sequential Reconstruction decodes a NeuralVDB representation into a standard VDB tree in a single sequential pass, prioritizing memory efficiency over reconstruction time [S1][S2, unofficial]. It targets offline storage and low-bandwidth network transmission where the entire volume must be reconstructed into memory [S1][S2, unofficial]. Unlike online random access methods, it does not support immediate point queries without full reconstruction, but achieves a smaller in-memory footprint by compressing the lower VDB hierarchy with neural networks [S1][S2, unofficial].

## How it works
**Inputs:**
- Compressed NeuralVDB data using the `[Hash, 5, NN(4), NN(3)]` configuration [S1][S2, unofficial].
- A list of false positives explicitly encoded during training [S1].
- Disjoint blocked ranges of the volume domain [S1].

**Outputs:**
- A standard VDB tree in memory [S1][S2, unofficial].

**Data Structures:**
- **Standard VDB Nodes (Levels 3, 2, 1 masks):** Encoded identically to standard VDB structures, including bit-masks that compactly encode coordinates [S1].
- **Level 1 Nodes:** Size $16^3$ [S1][S2, unofficial]. Each node has associated classifiers (for child and active masks) and a value regressor (for tile values) [S1].
- **Level 0 Nodes (Leaves):** Size $8^3$ [S1][S2, unofficial]. Each leaf has an associated binary classifier (for active state) and a value regressor (for voxel values) [S1].
- **False Positive List:** Coordinates or identifiers for incorrect active voxels/tiles identified during training, used to correct masks [S1].

**Steps:**
1. **Reconstruct Upper Levels:** Process root and child nodes (levels 3, 2, and 1 masks) using standard VDB decoding methods, as they are encoded identically to standard VDB [S1][S2, unofficial].
2. **Sequential Pass Setup:** Distribute the volume into disjoint blocked ranges, assigning each range to a GPU for concurrent processing [S1]. Each blocked range has dedicated classifiers and regressors but accesses all networks to ensure continuity [S1].
3. **Level 1 Reconstruction:** Sequentially access level 1 nodes. Their coordinates are derived trivially from the child masks at level 3 [S1]. For each level 1 node (size $16^3$): use standard inference with the associated classifiers to reconstruct the child mask and active mask [S1]. Use the value regressor to reconstruct tile values [S1]. Correct the reconstructed masks using the explicitly encoded list of false positives [S1].
4. **Level 0 Reconstruction:** Using the corrected child masks from level 1, visit all leaf nodes (size $8^3$) [S1]. Sequentially infer voxel values and active states for each leaf node using the level 0 value regressor and binary classifier [S1].
5. **Merge Results:** Merge the reconstructed blocked ranges from multiple GPUs into a single output VDB [S1].

**Pseudocode:**
```python
def offline_sequential_reconstruction(neural_vdb_data, false_positives, blocked_ranges):
    # Step 1: Decode upper levels (Root, Level 3, 2, 1 masks) identically to standard VDB [S1]
    standard_vdb = {
        'root': neural_vdb_data.root,
        'level_3': neural_vdb_data.level_3,
        'level_2': neural_vdb_data.level_2,
        'level_1_masks': neural_vdb_data.level_1_masks
    }

    reconstructed_ranges = []
    for range_id, range_data in enumerate(blocked_ranges):
        range_vdb = {'level_1_nodes': [], 'level_0_nodes': []}

        # Step 2: Sequential pass over Level 1 nodes (size 16^3) [S1]
        for node_id in range_data.level_1_nodes:
            # Coordinates derived trivially from child masks at level 3 [S1]
            coords = extract_coords_from_level3_masks(node_id, standard_vdb['level_3'])

            # Infer child and active masks from classifiers [S1]
            child_mask, active_mask = neural_vdb_data.classifiers[node_id].forward(coords)

            # Correct masks with explicitly encoded false positives [S1]
            active_mask = set(active_mask) - set(false_positives.get(node_id, []))

            # Infer tile values from value regressor [S1]
            tile_values = neural_vdb_data.regressors[node_id].forward(coords)

            range_vdb['level_1_nodes'].append({
                'id': node_id, 'coords': coords,
                'child_mask': child_mask, 'active_mask': active_mask,
                'tile_values': tile_values
            })

        # Step 3: Sequential pass over Level 0 leaf nodes (size 8^3) using level 1 child masks [S1]
        for l1_node in range_vdb['level_1_nodes']:
            if l1_node['active_mask']:
                for leaf_id in l1_node['child_mask'].get_active_indices():
                    # Infer active state from level 0 binary classifier [S1]
                    active_state = neural_vdb_data.classifiers[leaf_id].forward(leaf_id)
                    # Infer voxel values from level 0 value regressor [S1]
                    voxel_values = neural_vdb_data.regressors[leaf_id].forward(leaf_id)

                    range_vdb['level_0_nodes'].append({
                        'id': leaf_id, 'active_state': active_state,
                        'voxel_values': voxel_values
                    })

        reconstructed_ranges.append(range_vdb)

    # Step 4: Merge results into single output VDB [S1]
    return merge_vdb_ranges(reconstructed_ranges)

def extract_coords_from_level3_masks(node_id, level3_masks):
    # Standard VDB bit-mask coordinate extraction [S1]
    return level3_masks.get_coords(node_id)

def merge_vdb_ranges(ranges):
    # Standard VDB merge operation [S1]
    merged = {'level_1_nodes': [], 'level_0_nodes': []}
    for r in ranges:
        merged['level_1_nodes'].extend(r['level_1_nodes'])
        merged['level_0_nodes'].extend(r['level_0_nodes'])
    return merged
```

**Parameters:**
- **Configuration:** `[Hash, 5, NN(4), NN(3)]` [S1][S2, unofficial].
- **Level 1 Node Size:** $16^3$ [S1][S2, unofficial].
- **Level 0 Leaf Node Size:** $8^3$ [S1][S2, unofficial].

**Edge Cases and Pitfalls:**
- **False Positives:** Masks must be corrected using the explicitly encoded list of false positives to ensure accuracy [S1].
- **Discontinuity:** Although each blocked range has dedicated networks, access to all networks ensures no discontinuity at range boundaries [S1].
- **Memory Efficiency:** This method prioritizes low memory footprint, so it is not suitable for applications requiring fast random access [S1][S2, unofficial].

## Subtopics

### Online Random Access — NeuralVDB [Hash, 5, 4, NN(3)] Decoding
A reconstruction method for applications requiring fast random access and a small memory footprint, using standard VDB acceleration techniques for tree traversal and neural representation only for voxel values [S2, unofficial]. It uses the `[Hash, 5, 4, NN(3)]` configuration, where the upper levels (3, 2, 1) are standard VDB structures, and only the leaf level (0) uses neural networks [S2, unofficial]. To query a point, standard VDB acceleration is used to determine if it maps to a tile or a voxel; if it is a tile, the value is returned directly; if it is a voxel, the value is predicted by the regressor [S2, unofficial]. Compared to `[Hash, 5, NN(4), NN(3)]`, this method is faster for real-time random access because it avoids hierarchical neural network inference for the upper levels, making it suitable for rendering and collision detection [S2, unofficial]. It can be trivially reconstructed from `[Hash, 5, NN(4), NN(3)]` by leaving the voxel regressor unchanged, acting as a pre-cached representation [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Single sequential pass over the compressed data [S1][S2, unofficial]. Reconstruction time is higher than online random access methods due to the sequential nature and neural inference for lower levels [S1][S2, unofficial].
- **Memory Complexity:** Low memory footprint, as it reconstructs the entire VDB tree into memory [S1][S2, unofficial]. The in-memory footprint is an order of magnitude smaller than `[Hash, 5, 4, 3]` (standard VDB with explicit values) [S2, unofficial].
- **Performance:** Suitable for offline storage and low-bandwidth transmission [S1][S2, unofficial]. Not suitable for real-time random access applications due to the slowness of hierarchical neural network inference for two levels [S1][S2, unofficial].
- **Strengths:** Low memory usage, efficient for sequential reconstruction, concurrent processing on multiple GPUs [S1][S2, unofficial].
- **Limitations:** Requires full sequential reconstruction before use; not suitable for real-time random access due to hierarchical neural inference overhead [S1][S2, unofficial].
- **When to Use:** Offline storage, network transmission, applications prioritizing memory efficiency over reconstruction time [S1][S2, unofficial].
- **When Not to Use:** Real-time rendering, collision detection, applications requiring fast random access [S1][S2, unofficial].

## Background
Originated in the NeuralVDB paper [S1][S2, unofficial], which introduced hierarchical neural networks for sparse volume representation. The offline sequential reconstruction method was developed to address the need for efficient decoding of NeuralVDBs for offline applications, such as storage on slow secondary-storage devices or transmission over low-bandwidth networks [S1][S2, unofficial]. It builds on the standard VDB structure for upper levels and uses neural networks for the lower levels to achieve high compression ratios [S1][S2, unofficial].
