# Offset Compression
Also called: DAG Offset Compression
## Overview
Offset Compression is a memory optimization technique for sparse voxel tree structures that reduces the storage footprint of child pointers by exploiting structural properties of depth-first node assignment. It specifically targets the offset from a node to its first child, storing it implicitly, and compressing subsequent sibling offsets based on level-specific bit requirements. It sets itself apart from general entropy encoding by using fixed-width, level-adaptive bit-packing for offsets, which is more efficient for GPU texture lookups than variable-length codes.
## How it works
**Inputs and Outputs:**
- Input: A sparse voxel tree (or DAG) structure where nodes contain child pointers and offsets to siblings.
- Output: A compressed representation of the tree where offsets are stored using minimal bits per level, and the first-child offset is implicit.

**Data Structures:**
The method modifies the storage of the offset field within a node. Instead of a fixed-size integer (e.g., 32-bit or 64-bit), the offset is stored in a variable number of bits determined by the node's depth level.
- **First Child Offset:** Implicitly defined as $+1$. No bits are stored for this value.
- **Sibling Offset:** Stored in $B_L$ bits, where $L$ is the tree level. $B_L$ is the smallest integer such that $2^{B_L} > \max(\text{offsets at level } L)$.

**Steps:**
1. **Analyze Tree Levels:** Iterate through all nodes in the tree. For each level $L$, determine the maximum offset value $M_L$ required to reach the next sibling.
2. **Calculate Bit Depth:** For each level $L$, calculate the minimum number of bits $b_L$ required:
   $$ b_L = \lceil \log_2(M_L + 1) \rceil $$
   If $M_L = 0$ (no siblings), $b_L = 0$.
3. **Round to Bytes:** Round $b_L$ up to the nearest multiple of 8 to form $B_L$:
   $$ B_L = \lceil \frac{b_L}{8} \rceil \times 8 $$
   This ensures alignment with GPU texture fetch granularity.
4. **Store Offsets:**
   - For the first child of any node, the offset is implicitly $+1$.
   - For subsequent children, store the offset relative to the previous child using $B_L$ bits.
   - Child pointers themselves may be compressed separately (see Pointer Compression), but Offset Compression specifically handles the sibling linkage.

**Parameters:**
- **Offset Size:** In typical examples, a two-byte ($16$-bit) offset is sufficient for the lowest five levels. Four or five bytes are required for the highest levels.
- **Level Thresholds:** The highest levels (near the root) contain very few nodes ($\approx 0.1\%$), making the increased bit-width non-critical for overall memory usage.

**Edge Cases and Pitfalls:**
- **Precision:** Ensure that the maximum offset at any level fits within the calculated $B_L$ bits. If a level has a sparse distribution with large gaps, $B_L$ may be larger than necessary, but this is unavoidable without more complex variable-length encoding.
- **GPU Performance:** Failing to round up to byte boundaries can lead to inefficient memory access patterns on GPUs, where texture lookups typically retrieve at least one byte.
- **Implicit First Child:** The assumption that the first child offset is always $+1$ relies on a specific depth-first assignment order. If the tree structure changes, this assumption must be re-evaluated.

## Subtopics

### DAG Offset Compression
A variant of Offset Compression applied to Directed Acyclic Graph (DAG) structures where attribute decoupling introduces additional offsets. It compresses both DAG offsets and child pointers to reduce memory consumption. The method stores the offset from a node to its first child implicitly as $+1$, analyzes each level to determine the minimum bit depth, and rounds up to bytes for GPU performance. In examples, a two-byte offset is sufficient for the lowest five levels, while four or five bytes are required for the highest levels, which represent $\approx 0.1\%$ of nodes [S1].

## Operating characteristics
**Time and Memory Complexity:**
- **Memory:** Reduces the storage size of offsets from a fixed width (e.g., 32 or 64 bits) to a level-dependent width (typically 16 bits for lower levels). The total memory savings depend on the tree depth and the distribution of offsets.
- **Time:** The compression process requires a single pass to analyze levels and calculate bit depths. Decompression is efficient as it involves simple bit-shifting and masking.

**Measured Performance:**
- In typical datasets (e.g., citadel, city, San Miguel, arena), using two-byte offsets for the lowest five levels leads to significant memory improvement [S1].
- The highest levels require 4-5 bytes, but since they represent only $\approx 0.1\%$ of nodes, the impact on total memory is minimal.

**Strengths and Limitations:**
- **Strengths:** Simple to implement, efficient for GPU access due to byte-aligned storage, significant memory reduction for deep trees.
- **Limitations:** Less effective for pointer compression compared to offset compression, as pointers often require full 4 bytes even at lower levels. Not suitable for trees with non-depth-first assignment or irregular sibling distributions.

**When to Use:**
- Use when memory bandwidth is a bottleneck and the tree structure follows a depth-first assignment.
- Ideal for GPU-based rendering where texture lookups benefit from byte-aligned data.

**When Not to Use:**
- Avoid if the tree has a very shallow depth or if the offset distribution is highly irregular, requiring large bit-widths for most levels.
- Not suitable if variable-length encoding is preferred for better compression ratios at the cost of decompression complexity.

## Background
Offset Compression was introduced in the context of geometry and attribute compression for voxel scenes, specifically to reduce the memory consumption of DAG structures where attribute decoupling increases the size of the structure [S1]. It builds on the observation that offsets in depth-first trees are typically small in lower levels, allowing for efficient bit-packing.
