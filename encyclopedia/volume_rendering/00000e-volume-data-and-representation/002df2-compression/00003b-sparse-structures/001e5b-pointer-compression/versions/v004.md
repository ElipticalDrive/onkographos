# Pointer Compression

Also called: Frequency-Based Pointer Encoding, Pointer Table Encoding

## Overview
Pointer Compression is a technique for compressing child pointers in sparse voxel structures, such as DAGs, by replacing absolute memory addresses with indices into a frequency-based lookup table [S1]. It sets itself apart from general entropy encoding by using a fixed-width, level-adaptive bit-packing scheme that explicitly handles both common relative pointers (via the table) and rare absolute pointers, thereby reducing memory usage at the cost of increased decoding complexity [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sparse voxel structure (e.g., a Sparse Voxel DAG) containing child pointers [S1].
*   **Output:** A compressed bitstream where pointers are encoded as either table indices or absolute addresses, along with the per-level pointer lookup tables [S1].

**Data Structures:**
1.  **Pointer Lookup Table:** A list of the most common absolute pointers per tree level, sorted by occurrence in descending order [S1].
2.  **Encoded Pointer:** A variable-length field stored in the node structure [S1].

**Numbered Steps:**
1.  **Frequency Analysis:** Traverse the structure and count the occurrence of each unique child pointer value for each tree level [S1].
2.  **Table Construction:** For each level, select the most frequent pointers and store them in a lookup table, sorted by frequency [S1].
3.  **Index Mapping:** Replace each absolute pointer in the DAG with its index in the corresponding level's lookup table [S1]. Pointers not present in the table fall back to absolute encoding [S1].
4.  **Bit-Packing:** Encode each pointer using a 1-byte initial assumption where the first two bits indicate the type and actual bit length [S1]. The first two bits indicate the **type** [S1]. **Types 0, 1, 2** indicate that the remaining bits represent an index into the lookup table, with fixed lengths of 6, 14, or 22 bits respectively [S1]. **Type 3** indicates that the remaining 30 bits represent an absolute pointer [S1].
5.  **Alignment:** Ensure the total bit length for any pointer is a multiple of 8 bits (bytes) [S1].

**Formulas:**
Let $P$ be the original absolute pointer. Let $T_L$ be the lookup table for level $L$.
If $P \in T_L$ at index $i$, and the table size requires $b$ bits:
$$ \text{Encoded} = \text{Type}_k \parallel \text{Index}_i $$
Where $\text{Type}_k$ is 2 bits and $\text{Index}_i$ is $b$ bits (6, 14, or 22) [S1].

If $P \notin T_L$:
$$ \text{Encoded} = \text{Type}_3 \parallel P_{30} $$
Where $P_{30}$ is the 30-bit representation of the absolute pointer [S1].

**Parameters:**
*   **Table Size:** Determined by the number of most common pointers per level. Not given in the sources.
*   **Bit Lengths:** 6, 14, 22 for table indices; 30 for absolute pointers [S1].
*   **Header Size:** 2 bits per pointer [S1].

**Edge Cases and Pitfalls:**
*   **Performance:** Entropy encoding decreases rendering performance due to the overhead of decoding variable-length pointers [S1].
*   **Pointer Sufficiency:** 30-bit absolute pointers proved sufficient for the DAG nodes in all evaluated examples [S1].
*   **High-Level Inefficiency:** Compression is less effective for pointers on the highest tree levels because those levels generally require the full four bytes per pointer, though these nodes represent only ≈ 0.1% of the structure [S1].

**Pseudocode:**
```python
def compress_pointers(nodes_by_level):
    """
    Compress child pointers using frequency-based lookup tables.
    nodes_by_level: List of lists, where each inner list contains node objects with a 'children' attribute.
    Returns:
        compressed_bytes: List of integers (0-255) representing the packed bitstream.
        lookup_tables: Dict mapping level index to list of pointers.
    """
    lookup_tables = {}
    bit_buffer = 0
    bits_in_buffer = 0
    compressed_bytes = []

    # Step 1 & 2: Build lookup tables per level
    for level_idx, nodes in enumerate(nodes_by_level):
        counts = {}
        for node in nodes:
            for ptr in node.children:
                if ptr is not None:
                    counts[ptr] = counts.get(ptr, 0) + 1
        sorted_ptrs = sorted(counts.keys(), key=lambda k: counts[k], reverse=True)
        lookup_tables[level_idx] = sorted_ptrs

    # Step 3 & 4: Encode pointers
    for level_idx, nodes in enumerate(nodes_by_level):
        table = lookup_tables[level_idx]
        for node in nodes:
            for ptr in node.children:
                if ptr is None: continue

                if ptr in table:
                    idx = table.index(ptr)
                    if idx < 64: type_code, payload_bits = 0, 6
                    elif idx < 16384: type_code, payload_bits = 1, 14
                    else: type_code, payload_bits = 2, 22
                    payload = idx
                else:
                    type_code, payload_bits = 3, 30
                    payload = ptr & 0x3FFFFFFF

                # Pack: 2 bits type, then payload_bits bits
                total_bits = 2 + payload_bits
                combined = (type_code << payload_bits) | payload

                # Write to bit stream MSB-first
                for i in range(total_bits - 1, -1, -1):
                    bit = (combined >> i) & 1
                    bit_buffer = (bit_buffer << 1) | bit
                    bits_in_buffer += 1
                    if bits_in_buffer == 8:
                        compressed_bytes.append(bit_buffer)
                        bit_buffer = 0
                        bits_in_buffer = 0

    # Flush remaining bits
    if bits_in_buffer > 0:
        compressed_bytes.append(bit_buffer << (8 - bits_in_buffer))

    return compressed_bytes, lookup_tables

def decompress_pointers(compressed_bytes, lookup_tables):
    """
    Decompress pointers back to absolute addresses.
    """
    decompressed = []
    bit_buffer = 0
    bits_in_buffer = 0
    byte_idx = 0

    while byte_idx < len(compressed_bytes):
        # Read next byte
        bit_buffer = (bit_buffer << 8) | compressed_bytes[byte_idx]
        bits_in_buffer += 8
        byte_idx += 1

        # Extract type (first 2 bits of the current pointer)
        type_code = (bit_buffer >> (bits_in_buffer - 2)) & 0x03
        bits_in_buffer -= 2

        if type_code == 0:
            payload_bits = 6
        elif type_code == 1:
            payload_bits = 14
        elif type_code == 2:
            payload_bits = 22
        else: # type_code == 3
            payload_bits = 30

        # Extract payload
        payload = (bit_buffer >> (bits_in_buffer - payload_bits)) & ((1 << payload_bits) - 1)
        bits_in_buffer -= payload_bits

        # Reconstruct pointer
        if type_code < 3:
            # Table index lookup (assumes level 0 for demo; in practice, track level context)
            decompressed.append(lookup_tables[0][payload])
        else:
            decompressed.append(payload)

    return decompressed
```

## Subtopics

### [Offset Compression](1819-offset-compression.md)
Offset Compression is a technique for compressing tree offsets in sparse voxel structures. It exploits the fact that the offset from a node to its first child is always $+1$, allowing it to be stored implicitly, and that offsets are typically small in lower tree levels due to depth-first assignment. It sets itself apart from general entropy encoding by using fixed-width, level-adaptive bit-packing for offsets, which aligns with GPU texture lookup granularity.

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Reduces memory usage for child pointers, particularly in scenes with repetitive subtrees [S1]. The compression is less effective for pointers on the highest levels, but these nodes are rare (≈ 0.1%) [S1].
*   **Time:** Encoding requires frequency analysis and table construction [S1]. Decoding requires table lookups and bit extraction, which increases CPU/GPU overhead compared to direct pointer access [S1].

**Measured Performance:**
*   The method was evaluated on architectural structures (citadel, city), complex geometry (tree, plants), and real-life 3D models (arena) [S1].
*   Significant compression was achieved, but rendering performance decreased due to the entropy encoding overhead [S1].

**Strengths and Limitations:**
*   **Strengths:** Effective for scenes with repetitive subtrees; reduces memory footprint for pointers [S1].
*   **Limitations:** Decreases rendering performance; less effective for high-level pointers that require full 4-byte storage [S1].
