# Pointer Compression

Also called: Frequency-Based Pointer Encoding, Pointer Table Encoding

## Overview
Pointer Compression is a technique for compressing child pointers in sparse voxel structures, such as DAGs, by replacing absolute memory addresses with indices into a frequency-based lookup table [S1]. It sets itself apart from general entropy encoding by using a fixed-width, level-adaptive bit-packing scheme that explicitly handles both common relative pointers (via the table) and rare absolute pointers, thereby reducing memory usage at the cost of increased decoding complexity [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sparse voxel structure (e.g., a Sparse Voxel DAG) containing child pointers.
*   **Output:** A compressed bitstream where pointers are encoded as either table indices or absolute addresses, along with the pointer lookup tables.

**Data Structures:**
1.  **Pointer Lookup Table:** A list of the most common absolute pointers per tree level, sorted by occurrence in descending order [S1].
2.  **Encoded Pointer:** A variable-length field stored in the node structure.

**Numbered Steps:**
1.  **Frequency Analysis:** Traverse the structure and count the occurrence of each unique child pointer value for each tree level [S1].
2.  **Table Construction:** For each level, select the most frequent pointers and store them in a lookup table, sorted by frequency [S1].
3.  **Index Mapping:** Replace each absolute pointer in the DAG with its index in the corresponding level's lookup table. If a pointer is not in the table, it is treated as an absolute pointer [S1].
4.  **Bit-Packing:** Encode each pointer using a 1-byte initial header to determine the encoding type and length [S1]:
    *   The first two bits indicate the **type**.
    *   **Types 0, 1, 2:** Indicate that the remaining bits represent an index into the lookup table. The bit lengths are fixed at 6, 14, or 22 bits respectively [S1].
    *   **Type 3:** Indicates that the remaining 30 bits represent an absolute pointer [S1].
5.  **Alignment:** Ensure the total bit length for any pointer is a multiple of 8 bits (bytes) [S1].

**Formulas:**
Let $P$ be the original absolute pointer. Let $T_L$ be the lookup table for level $L$.
If $P \in T_L$ at index $i$, and the table size requires $b$ bits:
$$ \text{Encoded} = \text{Type}_k \parallel \text{Index}_i $$
Where $\text{Type}_k$ is 2 bits and $\text{Index}_i$ is $b$ bits (6, 14, or 22).

If $P \notin T_L$:
$$ \text{Encoded} = \text{Type}_3 \parallel P_{30} $$
Where $P_{30}$ is the 30-bit representation of the absolute pointer [S1].

**Parameters:**
*   **Table Size:** Determined by the number of most common pointers per level. Not given in the sources.
*   **Bit Lengths:** 6, 14, 22 for table indices; 30 for absolute pointers [S1].
*   **Header Size:** 2 bits per pointer [S1].

**Edge Cases and Pitfalls:**
*   **Performance:** Entropy encoding decreases rendering performance due to the overhead of decoding variable-length pointers [S1].
*   **Pointer Sufficiency:** 30-bit absolute pointers were found sufficient for the DAG nodes in the evaluated examples [S1].
*   **Precision:** The method assumes pointers can be mapped to indices. Degenerate cases where a pointer is not in the table fall back to absolute encoding [S1].

**Pseudocode:**
```python
def compress_pointers(nodes, levels):
    """
    Compress child pointers using frequency-based lookup tables.
    nodes: List of node objects, each having a 'children' list of absolute pointers.
    levels: List of levels, each containing a list of nodes belonging to that level.
    Returns:
        compressed_data: List of encoded integers (bit-packed).
        lookup_tables: Dict mapping level index to list of pointers.
    """
    lookup_tables = {}
    compressed_data = []

    # Step 1 & 2: Build lookup tables per level
    for level_idx, level_nodes in enumerate(levels):
        pointer_counts = {}
        for node in level_nodes:
            for child_ptr in node.children:
                if child_ptr is not None:
                    pointer_counts[child_ptr] = pointer_counts.get(child_ptr, 0) + 1
        
        # Sort by occurrence descending
        sorted_pointers = sorted(pointer_counts.keys(), key=lambda k: pointer_counts[k], reverse=True)
        lookup_tables[level_idx] = sorted_pointers

    # Step 3 & 4: Encode pointers
    for level_idx, level_nodes in enumerate(levels):
        table = lookup_tables[level_idx]
        table_size = len(table)
        
        for node in level_nodes:
            for child_ptr in node.children:
                if child_ptr is None:
                    # Handle null pointers if necessary [G]
                    continue
                
                # Check if pointer is in table
                if child_ptr in table:
                    index = table.index(child_ptr)
                    
                    # Determine bit length based on index size
                    # Heuristic: 6 bits for small indices, 14 for medium, 22 for large
                    # The source specifies fixed types for 6, 14, 22 bits [S1]
                    if index < 64: # 2^6
                        type_code = 0
                        bits = 6
                    elif index < 16384: # 2^14
                        type_code = 1
                        bits = 14
                    else:
                        type_code = 2
                        bits = 22
                    
                    # Pack: 2 bits type + bits index
                    encoded = (type_code << bits) | index
                else:
                    # Absolute pointer
                    type_code = 3
                    bits = 30
                    # Mask pointer to 30 bits [S1]
                    encoded = (type_code << bits) | (child_ptr & 0x3FFFFFFF)
                
                compressed_data.append(encoded)

    return compressed_data, lookup_tables

def decompress_pointers(compressed_data, lookup_tables, num_children):
    """
    Decompress pointers back to absolute addresses.
    """
    decompressed = []
    for encoded in compressed_data:
        # Extract type (first 2 bits) and payload
        # Note: The source implies the type is in the first 2 bits of the byte,
        # but the bit packing logic suggests the type determines the length.
        # We assume the type is stored in the most significant bits of the first byte.
        
        # Reconstruct based on type
        # Since the encoding is variable length, we need to know the length.
        # The type bits are part of the first byte.
        
        # Extract type from the first 2 bits of the first byte
        # Assuming big-endian bit packing for simplicity [G]
        first_byte = (encoded >> 24) & 0xFF # Assuming 32-bit int storage
        type_code = (first_byte >> 6) & 0x03
        
        if type_code == 0:
            # 6 bits index
            index = encoded & 0x3F
            decompressed.append(lookup_tables[0][index]) # Assuming level 0 for demo
        elif type_code == 1:
            # 14 bits index
            index = encoded & 0x3FFF
            decompressed.append(lookup_tables[1][index])
        elif type_code == 2:
            # 22 bits index
            index = encoded & 0x3FFFFF
            decompressed.append(lookup_tables[2][index])
        elif type_code == 3:
            # 30 bits absolute
            ptr = encoded & 0x3FFFFFFF
            decompressed.append(ptr)
            
    return decompressed
```

## Subtopics

### [Offset Compression](1819-offset-compression.md)
Offset Compression is a technique for compressing tree offsets in sparse voxel structures. It exploits the fact that the offset from a node to its first child is always $+1$, allowing it to be stored implicitly, and that offsets are typically small in lower tree levels due to depth-first assignment. It sets itself apart from general entropy encoding by using fixed-width, level-adaptive bit-packing for offsets, which aligns with GPU texture lookup granularity.

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Reduces memory usage for child pointers, particularly in scenes with repetitive subtrees [S1]. The compression is less effective for offsets on the highest levels, but these nodes are rare (≈ 0.1%) [S1].
*   **Time:** Encoding requires frequency analysis and table construction. Decoding requires table lookups and bit extraction, which increases CPU/GPU overhead compared to direct pointer access [S1].

**Measured Performance:**
*   The method was evaluated on architectural structures (citadel, city), complex geometry (tree, plants), and real-life 3D models (arena) [S1].
*   Significant compression was achieved, but rendering performance decreased due to the entropy encoding overhead [S1].

**Strengths and Limitations:**
*   **Strengths:** Effective for scenes with repetitive subtrees; reduces memory footprint for pointers [S1].
*   **Limitations:** Decreases rendering performance; less effective for offsets on high levels [S1].

**When to Use:**
*   Use when memory bandwidth is a bottleneck and the scene has high structural redundancy [S1].
*   Avoid when rendering performance is critical and the scene has low pointer redundancy [S1].

## Background
