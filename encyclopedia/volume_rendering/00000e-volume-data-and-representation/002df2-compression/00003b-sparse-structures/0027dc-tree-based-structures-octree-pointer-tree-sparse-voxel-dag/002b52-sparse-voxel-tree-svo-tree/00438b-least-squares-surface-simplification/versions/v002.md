# Least Squares Surface Simplification

Also called: Energy minimization simplification, Inverse prolongation via least squares

## Overview
Least Squares Surface Simplification reduces the resolution of a Sparse Voxel Octree (SVO) by finding the best-fit scalar field values for a coarser voxel level [S1, unofficial]. It solves the data reduction problem by minimizing the energy difference between the prolonged coarse field and the original fine field, formulated as a least squares problem [S1, unofficial]. It sets itself apart from sibling methods like Morton-coded SVOs by explicitly optimizing field values to minimize approximation error rather than relying solely on structural sparsity or hashing [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A fine-level scalar field $F_0$ stored in an SVO structure; a user-defined error tolerance $\tau$ [S1, unofficial].
*   **Output:** A coarse-level scalar field $F_1$ and a simplified SVO structure where child voxels are removed if the approximation error is below $\tau$ [S1, unofficial].

**Data Structures**
The SVO uses a pointerless format, removing built-in external pointers to simplify the structure at the cost of GPU lookup efficiency [S1, unofficial]. All attribute data are stored in separate arrays [S1, unofficial]. Child indices in the SVO structure are used to find corresponding attributes in these arrays [S1, unofficial].

**Steps**
1.  **Identify Unique Corners:** Convert all voxel corners to Morton codes, sort the list, and remove duplicates to avoid solving for the same point multiple times [S1, unofficial].
2.  **Construct Local Matrices:** Calculate the prolongation matrix $P$ and weight matrix $M$ locally from neighboring voxels as dense matrices, then combine them into global sparse matrices [S1, unofficial].
3.  **Transpose:** Compute the transpose of the prolongation matrix, $P^T$ [S1, unofficial].
4.  **Solve Linear System:** Solve the system $P^T M P F_1 = P^T M F_0$ for $F_1$ using a least-squares solver (e.g., Intel MKL) [S1, unofficial].
5.  **LOD Optimization:** Traverse the tree bottom-up starting at the parents of the finest level [S1, unofficial]. For each parent, prolong the parent voxel using trilinear interpolation, compare the prolonged values to the original child voxels, sum all errors, and divide by the voxel size to obtain a normalized comparison [S1, unofficial]. If the energy is smaller than $\tau$, remove all child voxels [S1, unofficial].

**Formulas**
The energy function to minimize is:
$$E = (P(F_1) - F_0)^T M (P(F_1) - F_0)$$
where $P$ is the prolongation matrix, $F_1$ is the coarse field, $F_0$ is the fine field, and $M$ is a symmetric weight matrix [S1, unofficial].

Expanding the equation (using the symmetry of $M$):
$$E = (PF_1)^T M(PF_1) - 2(PF_1)^T MF_0 + F_0^T MF_0$$

The gradient with respect to $F_1$ is:
$$\nabla_{F_1} E = 2P^T M P F_1 - 2P^T M F_0$$

Setting the gradient to zero yields the linear system:
$$P^T M P F_1 = P^T M F_0$$

This is a standard least squares problem of the form $A^T A x = A^T b$, where $A=P$ and $b=F_0$ [S1, unofficial].

**Parameters**
*   $\tau$: User-defined error tolerance. Determines when child voxels can be removed during LOD optimization [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Non-invertibility:** The prolongation operator $P$ is not invertible, so an exact inverse cannot be computed; the least squares solution provides the best fit [S1, unofficial].
*   **Exact Solution:** If the energy is zero, an exact solution exists where $P F_1 = F_0$ [S1, unofficial].
*   **Duplicate Corners:** Voxel corners may be shared by multiple voxels, requiring an encoding pass to avoid solving for the same point multiple times [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Solving the linear system is the dominant cost [S1, unofficial]. It depends on the sparsity and size of $P^T M P$ [S1, unofficial]. Pre-factorization is recommended for efficiency [S1, unofficial].
*   **Memory Complexity:** Requires storage for the SVO structure, attribute arrays, and the sparse matrices $P$ and $M$ during the solve phase [S1, unofficial].
*   **Strengths:** Provides a mathematically optimal fit for the coarse field given the prolongation operator [S1, unofficial]. Handles global effects while solving sparsely [S1, unofficial].
*   **Limitations:** The prolongation operator is not invertible, so it is an approximation [S1, unofficial]. Requires a robust sparse linear solver [S1, unofficial].
*   **When to use:** When preserving the visual or physical accuracy of the scalar field during compression is more important than raw structural sparsity [S1, unofficial].
