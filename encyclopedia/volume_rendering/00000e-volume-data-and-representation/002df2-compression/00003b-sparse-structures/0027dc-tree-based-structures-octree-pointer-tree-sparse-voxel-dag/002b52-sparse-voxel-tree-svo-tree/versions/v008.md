# Sparse Voxel Tree (SVO Tree)

Also called: ESVO, Hierarchical Voxel Storage, Sparse Voxel Octree (OpenVDB), Voxel Tree

## Overview
A Sparse Voxel Tree (SVO) is a hierarchical data structure for representing sparse volumetric data, typically an octree where each node partitions 3D space into 8 children [S3, S4, unofficial]. It solves the storage and traversal inefficiency of dense 3D grids by storing samples of occupancy or density fields only in leaf nodes where data exists, allowing ray marching to skip empty space efficiently [S3, unofficial]. Unlike its sibling [Sparse Voxel DAGs](2791-sparse-voxel-dags.md) which merge identical subtrees to reduce redundancy, the SVO maintains a strict tree topology, relying on pointer-based or block-indexed navigation [S1, unofficial][S2].

## How it works
**Inputs:** A 3D position vector $(x, y, z)$ and a voxel data value (e.g., density, color).
**Outputs:** A pointer or reference to the voxel data stored in the tree structure.

**Data Structures:**
The implementation relies on a template class `tree<FORMAT_T, BIT_WIDTH, DETAILS>` [S1, unofficial].
1.  **`node_format`**: Stores node metadata.
    *   `_depth` (uint32_t): The depth of the node in the tree.
    *   `_mask` (bitmask): An 8-bit integer where the $i$-th bit is set if the $i$-th child exists.
    *   `_block_index` (index): An index into the memory pool's block array, identifying which block contains this node's children or the node itself if it is a leaf.
2.  **`mem_pool<T>`**: Manages fixed-size blocks of memory.
    *   `_blocks`: An array of blocks, where each block holds exactly 8 elements of type $T$ (nodes or voxels).
    *   `_free`: A free list for reusable blocks.
3.  **`_root_node`**: The root of the tree, initialized at depth 0.
4.  **`_node_pool`**: Memory pool for internal nodes.
5.  **`_voxel_pool`**: Memory pool for leaf voxels.

**Parameters:**
*   `BIT_WIDTH`: Template parameter determining coordinate precision. Values are 16 or 32 [S1, unofficial].
*   `MAX_DEPTH`: Derived from `BIT_WIDTH`. For 16-bit, `MAX_DEPTH` is 5; for 32-bit, it is 10 [S1, unofficial].
*   `AXIS_WIDTH`: $2^{\text{MAX\_DEPTH}}$. For 16-bit, 32; for 32-bit, 1024 [S1, unofficial].
*   `BOUNDS[3]`: Maximum bounds per axis. Defaults to `AXIS_WIDTH` if not specified [S1, unofficial].
*   `_discard_overflow`: Boolean flag. If `true`, out-of-bounds voxels are silently dropped; if `false`, an assertion triggers [S1, unofficial].

**Algorithm (Allocation):**
The `alloc` function inserts a voxel at a given position.

1.  **Overflow Check:** Compare `voxel_position` components against `BOUNDS[0..2]`. If any exceed bounds, handle per `_discard_overflow` flag [S1, unofficial].
2.  **Coordinate Transform:** Shift position left by 1 bit (multiply by 2) to align with even-space grid [S1, unofficial].
3.  **Root Initialization:** Start traversal at `_root_node`. Set `node_position` to $\{0,0,0\}$ [S1, unofficial].
4.  **Internal Node Traversal:** Iterate $i$ from 0 to `MAX_DEPTH`-2.
    *   Compute `depth_` = $i$.
    *   Compute `node_extent` = `AXIS_WIDTH` >> `depth_`.
    *   Compute child index, child bit, existence flag, and `next_node_position` using spatial relation math (based on `voxel_position` and `node_extent`) [S1, unofficial].
    *   Set `node_->_mask |= child_bit`.
    *   Fetch `node_block_` from `_node_pool._blocks[node_->_block_index]`.
    *   If `!exist`:
        *   Allocate new node block.
        *   Set `new_node_._depth` = `depth_`+1, `_mask` = 0.
        *   Set `new_node_._block_index` = `_node_pool.acquire_next_index()`.
        *   Store `new_node_` in `node_block_[index]`.
        *   Allocate new block in `_node_pool`.
        *   Update `node_` to `&node_block_[index]`.
    *   Else: Update `node_` to `&node_block_[index]`.
    *   Set `node_position` = `next_node_position` [S1, unofficial].
5.  **Voxel Octant Allocation:**
    *   Set `depth_` = `MAX_DEPTH`-1.
    *   Set `node_extent` = 4.
    *   Run spatial relation math.
    *   Set mask.
    *   If `!exist`:
        *   Create node with `_depth`=`MAX_DEPTH`-1, `_block_index`=`_voxel_pool.acquire_next_index()`.
        *   Store in block, allocate voxel block, update `node_` [S1, unofficial].
6.  **Voxel Allocation:**
    *   Set `depth_` = `MAX_DEPTH`.
    *   Set `node_extent` = 2.
    *   Run spatial relation math.
    *   Fetch `voxel_block_` from `_voxel_pool._blocks[node_->_block_index]`.
    *   Store voxel in `voxel_block_[index]` [S1, unofficial].

**Pseudocode:**
```python
def alloc(voxel_position, voxel_data):
    # 1. Overflow check
    if voxel_position.x >= BOUNDS[0] or voxel_position.y >= BOUNDS[1] or voxel_position.z >= BOUNDS[2]:
        if _discard_overflow:
            return
        else:
            assert False, "Out of bounds"

    # 2. Coordinate transform
    voxel_transformed = voxel_position << 1

    # 3. Root initialization
    node = _root_node
    node_position = Vector3(0, 0, 0)

    # 4. Internal node traversal
    for i in range(MAX_DEPTH - 2):
        depth_ = i
        node_extent = AXIS_WIDTH >> depth_
        
        # Compute child index and existence based on voxel_transformed and node_position
        # This involves determining which octant the voxel falls into relative to the node
        index, child_bit, exist, next_node_position = compute_svo_relation(voxel_transformed, node_position, node_extent)
        
        node._mask |= child_bit
        
        # Fetch current node's block
        node_block = _node_pool._blocks[node._block_index]
        
        if not exist:
            # Allocate new node
            new_node = NodeFormat()
            new_node._depth = depth_ + 1
            new_node._mask = 0
            new_node._block_index = _node_pool.acquire_next_index()
            
            node_block[index] = new_node
            _node_pool.alloc() # Allocate new block for the new node's children
            node = node_block[index]
        else:
            node = node_block[index]
            
        node_position = next_node_position

    # 5. Voxel Octant Allocation (Parent of leaf)
    depth_ = MAX_DEPTH - 1
    node_extent = 4
    index, child_bit, exist, next_node_position = compute_svo_relation(voxel_transformed, node_position, node_extent)
    node._mask |= child_bit
    
    if not exist:
        new_node = NodeFormat()
        new_node._depth = MAX_DEPTH - 1
        new_node._mask = 0
        new_node._block_index = _voxel_pool.acquire_next_index()
        
        node_block = _node_pool._blocks[node._block_index]
        node_block[index] = new_node
        _voxel_pool.alloc() # Allocate block for voxels
        node = node_block[index]
    else:
        node = node_block[index]

    # 6. Voxel Allocation
    node_extent = 2
    index, child_bit, exist, next_node_position = compute_svo_relation(voxel_transformed, node_position, node_extent)
    node._mask |= child_bit
    
    voxel_block = _voxel_pool._blocks[node._block_index]
    voxel_block[index] = voxel_data
```

**Deallocation:**
1.  **Trace:** Call `get_traced` to retrieve the voxel pointer and fill `path_` and `child_bits` arrays up to the reached depth [S1, unofficial]. Return false if not found.
2.  **Voxel Block Deallocation:** Clear child bit from `path_[depth_]->_mask`. If mask is not 0, return true. Else, dealloc voxel block via `_voxel_pool.dealloc(path_[depth_]->_block_index)` [S1, unofficial].
3.  **Node Block Deallocation:** Loop `depth_` from current down to 1. If `path_[depth_]->_mask` is not 0, break. Else, dealloc node block via `_node_pool.dealloc(path_[depth_]->_block_index)`. Clear child bit from `path_[depth_-1]->_mask`. Decrement `depth_` [S1, unofficial].

**Pitfalls:**
*   **Compiler Performance:** The traversal loop causes significant branch/pipeline overhead on MSVC. Applying loop unrolling yields ~2x speedup on Clang/Windows [S1, unofficial].
*   **Bulk Allocation:** Pre-allocating blocks for bulk insertion is avoided because accurate spatial analysis is too expensive and overestimation hurts performance [S1, unofficial].

## Subtopics

### [Morton-coded Sparse Voxel Tree](5212-morton-coded-sparse-voxel-tree.md)
A Morton-coded Sparse Voxel Tree (SVO) is a flat-array sparse voxel tree that uses Morton codes (Z-order curve) for spatial ordering and an 8-bit mask per node to track children. It avoids recursive pointers by storing nodes in contiguous blocks of 8 elements, indexed via `node_format::_block_index`. Unlike its sibling [Linear Octree with Z-order curve (Morton tree)](7054-linear-octree-with-z-order-curve-morton-tree.md) which flattens the tree to store only relevant data trading traversal speed for memory efficiency, this method retains a hierarchical mask structure.

### [Hashed-Octree](7486-hashed-octree.md)
The Hashed-Octree is a sparse voxel representation that combines octrees with hash tables to provide constant-time data access complexity for huge 3D environments, addressing the $O(d)$ access time of standard Sparse Voxel Octrees (SVOs). It eliminates the need for explicit pointers by storing octants in a hash map using a unique 53-bit locational code key, allowing intermediate octants to be omitted. Unlike its siblings which may rely on Morton codes or pointer trees, this method uses a direct hash of coordinate-aligned root keys for top-level access, reducing data access complexity from $O(d)$ to $O(d_b)$ where $d_b$ is the depth of internal octrees (typically $d=1$).

### [Spatio-Temporal Sparse Voxel Octree (STSVO)](7493-spatio-temporal-sparse-voxel-octree-stsvo.md)
The Spatio-Temporal Sparse Voxel Octree (STSVO) is a hierarchical data structure for representing the geometry of time-variable 3D scenes by treating the scene as a 4D static space (3 spatial dimensions + 1 time dimension). It uses a single SVO-like structure instead of a set of separate SVOs for each time frame. Compared to storing each time frame as a separate SVO (SVO set), STSVO provides a more compact binary representation, achieving 1.73 to 2.08 times more compactness.

### [n-Dimensional Sparse Voxel Tree (nD SVT)](7999-n-dimensional-sparse-voxel-tree-nd-svt.md)
The n-Dimensional Sparse Voxel Tree (nD SVT) is a hierarchical data structure that generalizes Sparse Voxel Octrees (SVOs) to $n$-dimensional grids, where $n > 3$, to achieve a more compact binary representation of voxelized scenes. It solves the problem of storage efficiency in 3D volume rendering by upscaling the dimensionality of the scene from 3D to $m$D ($m > 3$), reducing the total number of nodes and pointers required to represent the geometry. Unlike its sibling [Morton-coded Sparse Voxel Tree](5212-morton-coded-sparse-voxel-tree.md) which remains strictly 3D, or [Hashed-Octree](7486-hashed-octree.md) which uses hashing for flat storage, the nD SVT trades increased per-node complexity (larger child masks) for a significantly reduced tree depth and node count.

### [Sparse Voxel Octree for Indirect Illumination](8483-sparse-voxel-octree-for-indirect-illumination.md)
This method uses a pre-filtered dynamic sparse voxel octree (SVO) on the GPU to efficiently estimate visibility and integrate incoming indirect energy without involving the actual mesh geometry. It solves the problem of real-time indirect illumination in complex scenes by replacing dense mip-mapped volume grids, which suffer from resolution loss and temporal discontinuities, with a sparse, adaptive hierarchy. Unlike [KD10], which uses nested regular voxel grids and lacks precision, this approach uses sparse storage and ray tracing to maintain high precision and support specular indirect lighting. Unlike path-tracing or photon mapping, it always gives smooth results and does not suffer from noise or temporal discontinuities.

### [Least Squares Surface Simplification](11029-least-squares-surface-simplification.md)
Least Squares Surface Simplification is a method for reducing the resolution of a Sparse Voxel Octree (SVO) by finding the best-fit scalar field values for a coarser voxel level. It solves the problem of data reduction by minimizing the energy difference between the prolonged coarse field and the original fine field, formulated as a least squares problem. It sets itself apart from sibling methods like Morton-coded SVOs by explicitly optimizing field values to minimize approximation error rather than relying solely on structural sparsity or hashing.

### SVO Culling and Sorting
Post-processing steps for the SVO: culling unfilled branches, breadth-sorting for cache locality, and depth-sorting for traversal order [S5, unofficial].
*   **Cull unfilled:** Recursively traverse from root. If leaf node has color 0, return false (cull). If internal node, recursively cull children. If a child is culled, remove its bit from parent.occupancy. If parent becomes a leaf (only 1 child or 0 children depending on logic, code checks is_leaf after loop), return false. Otherwise update parent in nodes array and return true [S5, unofficial].
*   **Breadth-sort:** Create new nodes vector. Queue root. While queue not empty, pop node_ref. Clone node. For each child, push child_ref to queue front, update child reference in node to cursor, increment cursor. If node has color, encode node_ref into color (shifted and masked). Push node to new nodes vector [S5, unofficial].
*   **Depth-sort:** Create new nodes vector. Recursively traverse from root. For each node, create new reference (current nodes.len()), clone node, push to new nodes. Recursively update child references. Update node in new nodes array with updated children. Return new reference [S5, unofficial].

### VOLA (Octree with branching factor 64)
An efficient file format for storing quantized point cloud data with no attributes other than geometry, using an octree where two layers are combined into one [S6].
*   Store voxels as an octree rather than an array [S6].
*   Combine two layers of the octree into one, creating a tree with a branching factor of 64 [S6].

### Sparse Voxel Octree Traversal
A sparse voxel octree traversal method as described by Laine & Karras (2010) [S7, unofficial]. Performed well compared to other techniques in complex scenes, speculated due to improved cache coherency from more compact data storage [S7, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(\text{MAX\_DEPTH})$ for allocation, lookup, and deallocation. Since `MAX_DEPTH` is constant (3 to 10), operations are effectively $O(1)$ with a small constant factor [S1, unofficial].
*   **Memory Complexity:** $O(N)$ where $N$ is the number of allocated voxels. Each block holds exactly 8 elements (nodes or voxels). Overhead includes block metadata and free lists [S1, unofficial].
*   **Measured Performance:** ESVO requires about 5 bytes per voxel with color, normal, and contour, or 6.67 bytes per finest-level sample once the mip hierarchy is counted [S2]. If only surfaces are encoded, memory usage drops to $O(N^2)$ [S2].
*   **Strengths:** Adapts to the location of scene geometry, storing only leaf nodes where data exists, unlike dense 3D grids which require $4096^3$ cells (~128 GB for rgb$\sigma$) [S3, unofficial]. Octree data in blocks with relative pointers facilitates dynamic updates and streaming [S2].
*   **Limitations:** Octree traversal is worse than hierarchical-grid methods by as much as 60% [S2]. SVOs are considered good only for storage and rendering, and "not even great" at those tasks compared to other specialized structures [S2]. MSVC compilation can cause significant branch/pipeline overhead in traversal loops [S1, unofficial].

## Background
The Sparse Voxel Octree (SVO) is a tree-structure for representing sparse volumetric data, inspired by B+ trees used in databases [S3, unofficial]. It was popularized by Laine & Karras (2010) for efficient ray marching and rendering [S7, unofficial]. The structure partitions 3D space recursively, with interior nodes having no children implying the same value for all children in the subtree [S3, unofficial]. It is widely used in volume rendering to accelerate ray marching by skipping empty space [S3, unofficial].
