# Sparse Voxel Octree for Real-Time GI

Also called: Sparse Voxel Octree (ID Software)

## Overview
A real-time global illumination technique developed by ID Software that approximates indirect lighting by traversing a sparse voxel octree (SVO) with secondary rays after visibility buffer generation [S1, unofficial]. It distinguishes itself from [Sparse Voxel Octree for Indirect Illumination](8483-sparse-voxel-octree-for-indirect-illumination.md) by focusing on a dynamic, player-centric voxel representation optimized for runtime updates and single-bit occupancy storage, whereas the parent method emphasizes pre-filtered hierarchical representations for visibility estimation [S1, unofficial].

## How it works
**Inputs:** Current camera position, object transforms, and visibility buffer data.
**Outputs:** Indirect illumination contribution per pixel.

**Data Structures:**
1.  **Cluster:** A block of $8^3$ voxels.
    *   **Occupancy Cluster:** A bitfield where each voxel is represented by 1 bit. `1` indicates solid geometry, `0` indicates air [S1, unofficial].
    *   **Material Cluster:** An array of 8-bit indices pointing to a Material Look-Up Table (LUT). The LUT contains properties like albedo and roughness, defined per object, with up to 256 entries [S1, unofficial].
    *   **Cluster Index:** 31 bits, allowing representation of $>10^{12}$ voxels [S1, unofficial].
2.  **Object:** Contains a transform (rotation/translation), the index of its first cluster, and the number of clusters in each axis direction. Object extents are multiples of 8 voxels [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Compute the SVO around the player at start-up [S1, unofficial].
2.  **Approximation:** Represent cluster content in a grid-like manner to handle freely rotating and translating objects [S1, unofficial].
3.  **Visibility Buffer Generation:** Render the scene to generate the primary visibility buffer [S1, unofficial].
4.  **Ray Traversal:** Shoot secondary rays from the visible surface points. Traverse the SVO using the occupancy cluster to quickly skip empty space [S1, unofficial].
5.  **Shading:** Upon hitting a solid voxel, use the material cluster index to fetch material properties from the LUT and compute indirect illumination [S1, unofficial].
6.  **Update:** Update the SVO at runtime when objects move to ensure the GI solution reflects the current world state [S1, unofficial].

**Pseudocode:**
```python
def compute_gi(visibility_buffer, player_pos, objects):
    # 1. Build or update SVO around player
    svo = build_svo_around_player(player_pos, objects)
    
    # 2. Generate visibility buffer (assumed external step)
    # visibility_buffer contains screen-space hit info
    
    indirect_color = zeros_like(visibility_buffer.color)
    
    for pixel in visibility_buffer:
        if not pixel.is_visible:
            continue
            
        # 3. Cast secondary ray for GI
        ray = create_secondary_ray(pixel.position, pixel.normal)
        
        # 4. Traverse SVO
        hit = traverse_svo(svo, ray)
        
        if hit is not None:
            # 5. Retrieve material from LUT
            material_index = hit.cluster.material_data[hit.voxel_offset]
            material = get_material_from_lut(material_index, hit.object_id)
            
            # 6. Compute indirect contribution
            # Simplified: assume hit provides incoming radiance approximation
            indirect_color[pixel.coords] = compute_indirect_radiance(ray, material)
            
    return indirect_color

def traverse_svo(svo, ray):
    # Traverse octree levels
    node = svo.root
    while node is not None:
        # Check intersection with node bounding box
        if not ray_intersects_box(ray, node.bbox):
            return None
            
        # Check occupancy bit for the specific voxel/cluster region
        if node.is_empty:
            return None
            
        # Descend to children or return hit
        if node.is_leaf:
            return node.hit_info
        else:
            node = get_child_node(node, ray)
    return None
```

**Parameters:**
*   **Voxel Representation:** Single bit for occupancy [S1, unofficial].
*   **Cluster Size:** $8^3$ voxels [S1, unofficial].
*   **Material LUT Size:** Up to 256 entries [S1, unofficial].

**Edge Cases:**
*   **Precision:** Floating-point errors in ray-box intersection may cause missed hits or false positives in sparse structures.
*   **Boundaries:** Objects must be properly bounded to ensure the SVO covers the relevant view frustum.
*   **Degenerate Input:** Empty scenes or objects with no geometry should result in empty SVOs to avoid traversal overhead.

## Subtopics

### Efficient Sparse Voxel Octrees
A real-time global illumination solution using voxel-based representations developed by NVIDIA [S2]. It is a variant of the SVO approach, optimized for performance on NVIDIA hardware, differing from the ID Software implementation in its specific acceleration structure optimizations and integration with NVIDIA's rendering pipeline [S2].

## Operating characteristics
*   **Time Complexity:** Depends on SVO depth and ray traversal efficiency. Traversal is logarithmic with respect to scene complexity but linear with respect to ray length in dense regions.
*   **Memory Complexity:** Dominated by the SVO structure. Single-bit occupancy reduces memory footprint significantly compared to full voxel grids. Material LUTs add overhead proportional to unique materials.
*   **Performance:** Suitable for real-time applications on modern GPUs. Performance scales with resolution and SVO density.
*   **Strengths:** Efficient handling of dynamic scenes, low memory usage for occupancy, compatibility with visibility buffer pipelines.
*   **Limitations:** Approximate nature of GI, potential for aliasing or artifacts in sparse regions, dependency on accurate visibility buffer generation.
*   **When to Use:** Real-time applications requiring dynamic global illumination with moving objects.
*   **When Not to Use:** Offline rendering requiring high-fidelity indirect lighting, or scenes with extremely static geometry where precomputed solutions are more efficient.

## Background
Developed by ID Software as a real-time global illumination solution using voxel-based representations [S1, unofficial]. It is part of a family of SVO-based GI techniques, including those by Epic Games and NVIDIA [S2]. The method leverages the efficiency of sparse voxel structures to approximate indirect lighting in real-time, addressing the computational intensity of full ray tracing on voxel sets [S2].
