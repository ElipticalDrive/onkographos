# Tree-based structures (Octree, Pointer Tree, Sparse Voxel DAG)

Also called: Sparse Voxel Octrees (SVO), Pointer Trees, DAG-based Voxel Structures

## Overview
Tree-based structures represent volumetric data using a recursive spatial subdivision where empty or uniform regions are collapsed into single nodes, providing compression proportional to data sparsity [S2, 2792-octree-based-structures.md]. This family solves the memory and bandwidth bottlenecks of dense voxel grids by enabling efficient culling of empty space and adaptive resolution [2792-octree-based-structures.md]. Unlike sibling structures like [Hash Grids](936-hash-grids.md) or [Stack-Based Representation (SBR)](1081-stack-based-representation-sbr.md), tree-based methods prioritize hierarchical traversal and spatial locality, with variants like [Sparse Voxel DAGs](2791-sparse-voxel-dags.md) adding structural deduplication and [Compact Pointer Trees](844-compact-pointer-tree.md) adding lossy compression [2792-octree-based-structures.md, 844-compact-pointer-tree.md, 2791-sparse-voxel-dags.md].

## Shared principles
All structures in this family share the following mechanism:

1.  **Recursive Subdivision:** The 3D domain is recursively divided into sub-volumes. In standard octrees, each node has 8 children. In pointer trees, the branching factor $N$ varies ($N^3$ children) [2792-octree-based-structures.md].
2.  **Sparsity Encoding:** Empty regions are represented by null pointers or absence of children, rather than storing zero-valued voxels. This provides compression proportional to the sparsity of the data [2792-octree-based-structures.md].
3.  **Hierarchical Traversal:** Rendering or access requires traversing from the root to the leaf. This allows skipping large empty volumes (culling) and adapting resolution to view distance or detail requirements [2792-octree-based-structures.md].
4.  **Spatial Locality:** Children of a node are spatially contiguous. This locality is often exploited via Morton ordering (Z-order curve) to map 3D coordinates to 1D keys, enabling efficient neighbor lookups and linear array representations in implicit variants [G].

## Subtopics

### [Compact pointer tree](844-compact-pointer-tree.md)
The Compact Pointer Tree is a tree-based data structure designed for the interactive visualization of terabyte-scale volumetric RGBA data. It solves the problem of memory bandwidth and storage limitations by compressing color values using wavelet transforms and encoding spatial locality via compact 8-bit offsets. It sets itself apart from standard octrees by using a variable branching factor ($N^3$) and storing min/avg/max color attributes to enable lossy compression of the color space, allowing for on-demand voxel reconstruction from compressed nodes [844-compact-pointer-tree.md].

### [Sparse Voxel DAGs](2791-sparse-voxel-dags.md)
Sparse Voxel DAGs (SVDAGs) are a memory-efficient 3D data structure that extends the Sparse Voxel Octree (SVO) by merging identical subtrees into shared nodes, forming a Directed Acyclic Graph [2791-sparse-voxel-dags.md]. While SVOs efficiently encode spatial sparsity, they store redundant copies of identical non-empty geometry, leading to high memory consumption at high resolutions [2791-sparse-voxel-dags.md]. SVDAGs solve this by allowing multiple parent nodes to share pointers to the same child instance, achieving lossless compression of topological redundancy without decompression overhead during traversal [2791-sparse-voxel-dags.md]. This sets them apart from siblings like [Compact pointer tree](844-compact-pointer-tree.md) or [OpenVDB (VDB)](1508-openvdb-vdb.md), which focus on spatial sparsity or pointer compression rather than structural isomorphism [G].

### [Octree-based structures](2792-octree-based-structures.md)
Octree-based structures represent volumetric data using a recursive spatial subdivision where empty or uniform regions are collapsed into single nodes, providing compression proportional to data sparsity. This family solves the memory and bandwidth bottlenecks of dense voxel grids by enabling efficient culling of empty space and adaptive resolution. Unlike sibling structures like Pointer Trees or Sparse Voxel DAGs, standard octrees rely on a fixed 8-way branching factor and explicit or implicit parent-child pointers, prioritizing hierarchical traversal and spatial locality over the deduplication or pointer-free compactness of their variants [2792-octree-based-structures.md].

### [Span Space Tree](4379-span-space-tree.md)
The Span Space Tree (SST) is a hierarchical data structure designed to manage scene complexity for large-scale volume data rendering. It refines the interval tree concept to reduce the visited set of cells during rendering, enabling interactive visualization of datasets larger than the 512³ resolution typically supported by earlier techniques. It sets itself apart from sibling structures like the Sparse Voxel Octree by focusing on spatial span culling rather than just empty voxel skipping, often building upon min-max hierarchies to trivially ignore empty regions.

### [Sparse Voxel Tree (SVO Tree)](4983-sparse-voxel-tree-svo-tree.md)
The Sparse Voxel Tree (SVO) is a hierarchical data structure that represents 3D volumetric data by recursively subdividing space into octants, storing data only in non-empty leaf nodes. It solves the problem of excessive memory usage in dense voxel grids by exploiting spatial sparsity, allowing for the representation of large, detailed scenes with minimal storage. Unlike its siblings, the standard SVO uses a fixed octree topology with pointer-based or block-indexed navigation, distinguishing it from the DAG's shared nodes [Parent](4139-tree-based-structures-octree-pointer-tree-sparse-voxel-dag.md) and the Hashed-Octree's constant-time access [7486-hashed-octree.md].

### [Tiny LOD](6968-tiny-lod.md)
Tiny LOD is a method for constructing a hierarchical level-of-detail (LOD) representation from a set of input splats, specifically designed for integration with sparse voxel tree structures. It solves the problem of efficiently managing geometric detail across varying distances by generating a compressed tree structure that can be encoded for opacity values and subsequently used to build a chunk tree. It is distinguished from sibling methods by its specific parameterization via `lod_base` and `merge_filter`, and its role as a preprocessing step for opacity encoding in the Spark ecosystem.

### NerfTree
#### definition
- [S1] A two-level octree structure called NerfTree, consisting of a coarse density voxel volume for approximate geometry caching and fine sparse voxel grids localized around the surface for refinement.
#### step
- [S1] Use the coarse density voxel volume to localize the object's surface.
- [S1] Use the fine sparse voxel grids to refine geometry and radiance estimation in surface-adjacent regions.
- [S1] Progressively update the density voxel volumes during the training process.
#### pitfall
- [S1] Introduces a trade-off between memory usage and precision arising from the voxel structure and density grid, resulting in a larger memory footprint.
#### number
- [S1] Reduces training time by up to 88% compared to traditional NeRF.
- [S1] Improves inference speed to more than 200 fps.

## Background
Tree-based sparse structures are inspired by classical computer graphics techniques such as the Bounding Volume Hierarchy (BVH) [RW80] and the Sparse Voxel Octree (SVO) [LK10], which model a scene in a sparse hierarchical form to accelerate ray tracing [S1]. The SVO was introduced by Laine and Karras in 2010 [LK10, S1]. More recently, these structures have been adapted for learning-based 3D representations, such as NerfTree, which was proposed in the context of Efficient-NeRF [HLC∗ 22, S1] to accelerate training and inference for neural radiance fields.
