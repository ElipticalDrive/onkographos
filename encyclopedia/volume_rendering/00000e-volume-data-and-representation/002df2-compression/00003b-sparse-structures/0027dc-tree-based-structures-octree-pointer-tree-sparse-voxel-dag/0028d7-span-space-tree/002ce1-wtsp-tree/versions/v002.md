# WTSP Tree

Also called: Spatio-Temporal Wavelet Tree Construction, WTSP Tree Construction, WTSP Tree Hierarchical Structure, Wavelet Tree Spatial and Temporal, Wavelet-Based Time-Space Partitioning (WTSP) Tree, Wavelet-Based Time-Space Partitioning (WTSP) Tree Construction

## Overview
The Wavelet-Based Time-Space Partitioning (WTSP) tree is a hierarchical data structure for organizing multiresolution time-varying volumetric data [S1, S2]. It solves the problem of efficiently compressing and rendering large-scale dynamic volumes by exploiting both spatial coherence (via an octree) and temporal coherence (via a binary tree) within a unified structure [S1, S2]. Unlike methods that process space and time separately, the WTSP tree integrates them by embedding temporal information directly within spatial nodes, allowing for flexible spatio-temporal level-of-detail selection based on user-defined error tolerances [S1, S2]. It builds on the Span Space Tree concept by introducing a specific wavelet-based compression strategy for time-varying data [S1, S2].

## How it works
The WTSP tree construction involves a blockwise two-stage wavelet transform and compression process [S1, S2]. The structure is defined as an octree (spatial hierarchy) of binary trees (temporal hierarchy), where there is only one octree skeleton, and at each octree node, there is a binary time tree spanning the entire time sequence [S1, S2].

### Inputs and Outputs
**Inputs:**
- Time-varying volumetric data consisting of $T$ time steps.
- Spatial block size $n$ (number of voxels per block).
- Spatial error tolerance $e_s$ and temporal error tolerance $e_t$ [S2].
- Threshold for wavelet coefficient pruning [S1].

**Outputs:**
- A unified WTSP tree structure containing compressed wavelet coefficients and low-pass filtered subblocks [S1, S2].

### Data Structures
**Spatial Octree Node Layout:**
- **Parent Node:** Stores a low-pass filtered subblock of size $n$ voxels [S1, S2].
- **Child Nodes:** Store wavelet coefficients of size $7n/8$ [S1, S2].

**Temporal Hierarchy Structure:**
- A binary time tree associated with each spatial octree node [S1, S2].
- For non-root spatial nodes, the time tree stores 1D wavelet coefficients derived from the spatial wavelet coefficients across time [S1].
- For root spatial nodes, the time tree stores low-resolution data blocks rather than wavelet coefficients [S1].

### Construction Steps

1. **Spatial Hierarchy Construction (Stage 1):**
   For each time step $t$:
   1. Subdivide the volumetric data into data blocks/subvolumes of size $n$ voxels [S1, S2].
   2. Consider one voxel overlapping boundaries between neighboring blocks in each dimension to ensure correct rendering results [S2].
   3. Perform a 3D wavelet transform on each volume block [S1, S2].
      - This produces a low-pass filtered subblock of size $n/8$ and wavelet coefficients of size $7n/8$ [S1].
   4. **Uniform Block Check:** If a data block is uniform, skip the 3D wavelet transform. Set the low-pass filtered subblock to the uniform value and all corresponding wavelet coefficients to zero [S1].
   5. **Thresholding:** Compare wavelet coefficients against a user-specified threshold. Clamp coefficients smaller than the threshold to zero [S1].
   6. **Parent Formation:** Collect low-pass filtered subblocks from eight neighboring subvolumes. Group them into a single block of $n$ voxels to form the parent node. Keep the wavelet coefficients at the child nodes [S1].
   7. **Recursion:** Recursively apply steps 3-6 until the root of the octree is reached, where a single block of size $n$ represents the entire volume [S1, S2].
   8. Repeat for every time step to construct one multiresolution spatial octree hierarchy per time step [S1].

2. **Temporal Hierarchy Construction (Stage 2):**
   1. Identify octree nodes that have the same spatial location and resolution across all time steps [S1, S2].
   2. **Zero Coefficient Check:** If the wavelet coefficients of corresponding octree nodes in the time sequence are all zero, skip the 1D wavelet transform process [S1].
   3. For non-root spatial nodes: Apply 1D wavelet transforms to the wavelet coefficients associated with the identified octree nodes across the time sequence [S1, S2].
      - Use Haar wavelets for the 1D temporal transform [S1, S2].
      - This produces a binary time tree similar to the error tree algorithm [S1, S2].
   4. **Compression:** Compress the 1D wavelet transform coefficients using run-length encoding combined with a fixed Huffman encoder [S1].
   5. For root spatial nodes: Build the temporal hierarchy from the low-resolution data blocks rather than wavelet coefficients [S1].
   6. Merge all spatial octrees across time into a single unified spatio-temporal hierarchical data structure (WTSP tree) [S1, S2].

3. **Error Metric Calculation:**
   During the bottom-up construction, calculate the hierarchical spatial and temporal error metric for each time tree node [S1, S2].
   - **Spatial Error ($se$):** For a time tree leaf node $T$ (corresponding to a single time step), calculate the spatial error as the sum of the Mean Square Error (MSE) between the data at node $T$ and the data of the same time step at $T$'s eight spatial child nodes in the next spatial level of the octree, plus the maximum spatial error of the child nodes [S1].
     $$ se(T) = \sum_{i=0}^{7} MSE(T, T_i) + \max_{i=0}^{7} \{se(T_i)\} $$
     where $T_i$ are the eight spatial child nodes [S1].
   - **Temporal Error ($te$):** Calculated similarly for temporal dependencies [S1, S2].
   - Users specify separate spatial ($e_s$) and temporal ($e_t$) error tolerances to select data blocks with various spatio-temporal resolutions [S2].

### Parameters
- **Wavelet Type (Spatial):** 3D spatial wavelet transforms are not limited to Haar wavelets; higher order wavelets can be used for better image quality [S1].
- **Wavelet Type (Temporal):** Haar wavelets are used for the 1D temporal transform [S1, S2].
- **Spatial Error Tolerance ($e_s$):** User-specified at run time [S2].
- **Temporal Error Tolerance ($e_t$):** User-specified at run time [S2].
- **Threshold:** User-specified threshold for clamping spatial wavelet coefficients to zero [S1].

### Edge Cases and Pitfalls
- **Uniform Data Blocks:** If a data block is uniform, skip the 3D wavelet transform. Set the low-pass filtered subblock to the uniform value and all corresponding wavelet coefficients to zero [S1].
- **Zero Coefficients:** If wavelet coefficients of corresponding octree nodes in the time sequence are all zero, skip the 1D wavelet transform process [S1].
- **Boundary Overlap:** Consider one voxel overlapping boundaries between neighboring blocks in each dimension when loading volume data to produce correct rendering results [S2].
- **Reconstruction Dependencies:** Parent-child data dependency for reconstruction can cause long chains of dependencies. This is alleviated by storing reconstructed data at nodes in selective WTSP tree levels [S1].

## Subtopics

### [Time-Space Partitioning Tree](5382-time-space-partitioning-tree.md)
The Time-Space Partitioning Tree (TSP) is a hierarchical data structure designed for the compression and rendering of time-varying volumetric data. It addresses the challenge of exploiting both spatial coherence (via an octree) and temporal coherence (via a binary tree) within a single unified structure. Unlike methods that process space and time separately, TSP integrates them by embedding temporal information directly within spatial nodes, allowing for efficient traversal of dynamic volumes. The WTSP tree originates from the TSP tree.

## Operating characteristics
- **Time Complexity:** Construction involves 3D wavelet transforms for each time step and 1D wavelet transforms across time steps. The complexity is proportional to the number of voxels and time steps. Compression using RLE and Huffman is efficient for sparse coefficients [S1].
- **Memory Complexity:** The WTSP tree stores low-pass subblocks and wavelet coefficients. Compression reduces memory usage significantly, especially when many coefficients are zero [S1].
- **Measured Performance:** The algorithm can reduce run-time communication cost to a minimum and ensure well-balanced workload among processors when visualizing gigabytes of time-varying data on a PC cluster [S1].
- **Scaling:** Suitable for large-scale time-varying data visualization [S1].
- **Strengths:** Exploits both spatial and temporal coherence; flexible spatio-temporal LOD selection; efficient compression for sparse data; parallel rendering support [S1, S2].
- **Limitations:** Trade-off between image quality and reconstruction cost when choosing spatial wavelets; parent-child dependencies can cause reconstruction delays if not managed [S1].
- **When to Use:** Large-scale time-varying volumetric data visualization requiring efficient compression and flexible LOD [S1].
- **When Not to Use:** Static volume data (simpler structures suffice); data with low temporal coherence (temporal compression gains are minimal) [S1].

## Background
The WTSP tree originates from the Time-Space Partitioning (TSP) tree [SCM99] [S1, S2]. It was introduced by Wang, Shen, et al. in 2004/2005 [WS04] [S1, S2]. The method is used for large-scale time-varying data visualization, particularly in parallel volume rendering frameworks [S1].
