# Span Space Tree

Also called: SST

## Overview
The Span Space Tree (SST) is a hierarchical data structure designed to manage scene complexity for large-scale volume data rendering [S1, unofficial]. It refines the interval tree concept to reduce the visited set of cells during rendering, enabling interactive visualization of datasets larger than the 512³ resolution typically supported by earlier techniques [S1, unofficial]. It sets itself apart from sibling structures like the Sparse Voxel Octree by focusing on spatial span culling rather than just empty voxel skipping, often building upon min-max hierarchies to trivially ignore empty regions [S1, unofficial].

## How it works
The SST organizes volume data to facilitate efficient traversal and culling. While the parent structures (Octree, Pointer Tree) rely on recursive subdivision and sparsity encoding, the SST specifically refines interval tree concepts to manage spatial spans [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** A large volumetric dataset (e.g., >512³) and a rendering query (view frustum, isosurface threshold).
*   **Output:** A set of visible primitives or traversal path for rendering.

**Data Structures:**
The SST is built upon a branch-on-need octree structure [S1, unofficial].
*   **Node Layout:** Each node represents a sub-volume. It contains metadata for culling, specifically min-max values (bounding box of values) to allow trivial rejection of empty or irrelevant regions [S1, unofficial].
*   **Hierarchy:** The structure is hierarchical, allowing for view-dependent frustum culling [S1, unofficial].

**Steps:**
1.  **Build Min-Max Hierarchy:** Embed min-max values into the octree nodes. This allows the renderer to check if a node's value range intersects the rendering criteria (e.g., isosurface threshold) [S1, unofficial].
2.  **Trivial Rejection:** During traversal, if a node's min-max range does not intersect the rendering criteria, the entire subtree is ignored [S1, unofficial].
3.  **View-Dependent Culling:** Apply shearing transformation visibility tests to perform frustum culling at the node level [S1, unofficial].
4.  **Traversal:** Traverse the tree from root to leaf, skipping nodes that fail the min-max or frustum tests [S1, unofficial].

## Subtopics

### [WTSP Tree](5371-wtsp-tree.md)
The WTSP Tree is a hierarchical data structure designed to organize multiresolution time-varying volume data by combining spatial and temporal hierarchies into a unified structure. It solves the problem of efficiently storing and rendering large-scale time-varying volumetric datasets by allowing independent control over spatial and temporal resolution. Unlike its parent, the Span Space Tree, which primarily manages spatial complexity, the WTSP Tree explicitly integrates a temporal dimension via wavelet transforms, creating a single unified spatio-temporal hierarchy. It is distinguished from the Time-Space Partitioning Tree by its use of wavelet-based compression and error metrics for both spatial and temporal domains.

## Background
The Span Space Tree was proposed by Livnat et al. as a refinement of the interval tree concept to manage scene complexity for larger volume data [S1, unofficial]. It builds on earlier work by Wilhelms and Van Gelder, who proposed a min-max hierarchy embedded in a branch-on-need octree for trivially ignoring empty regions [S1, unofficial]. Livnat and Hansen further extended the min-max octree technique with view-dependent frustum culling using a shearing transformation visibility test [S1, unofficial]. The method is part of a lineage of techniques aimed at enabling interactive rendering of large volumetric datasets, preceding more recent topologically-guided extraction techniques [S1, unofficial].
