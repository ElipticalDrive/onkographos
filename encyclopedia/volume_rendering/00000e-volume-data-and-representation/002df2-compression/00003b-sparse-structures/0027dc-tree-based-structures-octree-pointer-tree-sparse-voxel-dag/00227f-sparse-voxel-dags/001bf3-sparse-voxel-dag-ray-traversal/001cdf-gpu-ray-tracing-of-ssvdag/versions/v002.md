# GPU Ray-tracing of SSVDAG

Also called: Inverse transformation approach, SSVDAG Ray Traversal (Ray Transformation)

## Overview
A GPU-based ray traversal method for Sparse Voxel Symmetry-aware Voxel DAGs (SSVDAG) that adapts standard octree traversal to handle variable-rate encoded child pointers and apply symmetry transformations upon entering subtrees [S2, unofficial]. It differs from standard SVDAG traversal by explicitly managing the coordinate system transformations associated with symmetry nodes, enabling efficient visibility queries and primary ray intersection on compressed data [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** SSVDAG structure stored in GPU memory; ray origin, direction, and span (near/far).
*   **Output:** Intersection point or `None` if no non-empty voxel is found within the span.

**Data Structures:**
The dataset is stored in two Texture Buffer Objects (TBOs):
1.  **Inner Nodes TBO:** Stores the layout of inner nodes.
2.  **Leaves TBO:** Stores leaf node data.
*   **Constraint:** If the dataset exceeds texture buffer object addressing limits, 3D textures are used instead of TBOs [S2, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Push the root node and initial ray state onto a full stack to support backtracking [S2, unofficial].
2.  **Traversal Loop:** Perform a depth-first visit of the octree using a recursive Digital Differential Analyzer (DDA) implemented via the full stack [S2, unofficial].
3.  **Voxel Intersection:** Determine the next voxel intersected by the ray within the current node's bounds.
4.  **Termination Check:** Stop traversal if a non-empty voxel is found or the ray span is terminated [S2, unofficial].
5.  **Child Pointer Handling:** When following child pointers, decode the variable-rate encoding and apply the transformation stored with the pointer every time a child subtree is entered [S2, unofficial].
6.  **Transformation Application:** Apply the inverse transformation to the ray using mirroring with respect to the node's center `c` [S1, unofficial].
7.  **Backtracking:** If a branch is exhausted, pop the stack to restore the previous node context [S2, unofficial].

**Formulas:**
The ray transformation uses a mirroring vector `s ∈ R^3` where each component is `-1` for mirrored axes and `+1` otherwise [S1, unofficial]:
$$ \text{org} = c + s \cdot (\text{org} - c) $$
$$ \text{dir} *= s $$
where `c` is the node center maintained during tree descent [S1, unofficial].

**Parameters:**
*   **Rendering Setup:** Deferred shading with screen-space normal estimation and hard shadows for one point light [S2, unofficial].
*   **Normals:** Obtained by finite differences in the frame buffer using a discontinuity preserving filter [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Addressing Limits:** Large datasets may exceed texture buffer object addressing limits, requiring a switch to 3D textures [S2, unofficial].
*   **Memory Pressure:** In pushdown or short-stack implementations, storing the modified local ray together with the restart node increases register or local memory pressure and reduces GPU parallelization efficiency [S1, unofficial].
*   **Book-keeping Costs:** Handling direction changes during traversal due to reflections increases book-keeping costs in methods not based on repeated octree point location, such as kd-restart [S1, unofficial].

**Pseudocode:**
```python
def traverse_ssvdag(ray_origin, ray_dir, t_min, t_max):
    # Ray state
    o = list(ray_origin)
    d = list(ray_dir)
    t = t_min
    t_end = t_max

    # Stack stores (node_index, ray_origin, ray_dir, t_start, mirroring_signs)
    # mirroring_signs is a 3D list of 1.0 or -1.0
    stack = [(0, o, d, t, [1.0, 1.0, 1.0])]

    while stack:
        node_idx, cur_o, cur_d, cur_t, s = stack.pop()

        # Digital Differential Analyzer step
        t_next = cur_t
        while t_next <= t_end:
            # Determine voxel type at current t_next
            # (Standard DDA voxel lookup; implementation depends on SSVDAG node layout)
            voxel_type = lookup_voxel_type(node_idx, t_next)

            if voxel_type == "LEAF":
                return (cur_o[0] + cur_d[0] * t_next, cur_o[1] + cur_d[1] * t_next, cur_o[2] + cur_d[2] * t_next)

            if voxel_type == "INNER":
                # Decode variable-rate child pointer and get mirroring signs
                # (Variable-rate decoding logic defined in SSVDAG Node Layout)
                next_node_idx, child_s = decode_child_pointer(node_idx, t_next)
                
                # Apply transformation stored with the pointer
                c = get_node_center(next_node_idx)
                new_o = [c[i] + child_s[i] * (cur_o[i] - c[i]) for i in range(3)]
                new_d = [cur_d[i] * child_s[i] for i in range(3)]
                
                stack.append((next_node_idx, new_o, new_d, t_next, child_s))
                break

            # Advance DDA to next voxel boundary
            # (Standard 3D DDA boundary computation)
            t_next = compute_next_dda_boundary(cur_o, cur_d, t_next)

    return None
```

## Subtopics

### Sparse Voxel DAG Ray Traversal
The parent method focusing on general SVDAG traversal without symmetry handling. Choose SSVDAG when symmetry compression is active. [Sparse Voxel DAG Ray Traversal](1147-sparse-voxel-dag-ray-traversal.md)

## Operating characteristics
*   **Performance:** Interactive frame rates are achieved on large models; for the Powerplant model at 64K³ resolution, SSVDAG achieved 74fps, compared to 86fps for USSVDAG and 87fps for SVDAG [S2, unofficial].
*   **Strengths:** Supports interactive navigation of very large models compressed to the GPU without requiring additional acceleration or shading structures beyond the SSVDAG itself [S2, unofficial].
*   **Limitations:** The basic setup focuses on hard shadows and primary rays; soft shadows and ambient occlusion are not covered in the primary implementation details [S2, unofficial]. Voxelization artifacts are most evident in these effects [S2, unofficial].
*   **Scaling:** Performance scales with resolution and model complexity, but remains comparable to uncompressed SVDAG within a small percentage difference [S2, unofficial].

## Background
The method was implemented as part of an experimental software library, preprocessor, and viewer application on Linux using C++, OpenGL, and GLSL [S2, unofficial]. It was designed to test the SSVDAG structure in a simple setting, focusing on visibility queries and secondary ray effects where voxelization artifacts are evident [S2, unofficial]. The approach demonstrates that a terse compressed structure can support real-time navigation of very large scenes [S2, unofficial].
