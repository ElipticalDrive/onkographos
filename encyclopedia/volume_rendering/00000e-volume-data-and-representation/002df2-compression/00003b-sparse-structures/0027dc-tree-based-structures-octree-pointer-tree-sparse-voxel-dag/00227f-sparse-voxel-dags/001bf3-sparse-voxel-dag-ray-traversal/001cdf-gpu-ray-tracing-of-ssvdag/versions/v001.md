# GPU Ray-tracing of SSVDAG

Also called: SSVDAG Ray Traversal

## Overview
A GPU-based ray traversal method for Sparse Voxel Symmetry-aware Voxel DAGs (SSVDAG) that adapts standard octree traversal to handle variable-rate encoded child pointers and apply symmetry transformations upon entering subtrees [S1, unofficial]. It differs from standard SVDAG traversal by explicitly managing the coordinate system transformations associated with symmetry nodes, enabling efficient visibility queries and primary ray intersection on compressed data [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** SSVDAG structure stored in GPU memory; ray origin and direction; ray span (near/far).
*   **Output:** Intersection point or null if no non-empty voxel is found within the span.

**Data Structures:**
The dataset is stored in two Texture Buffer Objects (TBOs):
1.  **Inner Nodes TBO:** Stores the layout of inner nodes (see Figure 6 in [S1, unofficial] for layout details, though specific bit-packing is not detailed in text, it follows the compact representation).
2.  **Leaves TBO:** Stores leaf node data.
*   **Constraint:** If the dataset exceeds texture buffer object addressing limits, 3D textures are used instead of TBOs [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Push the root node and current node onto a full stack to support backtracking [S1, unofficial]. Initialize the ray traversal state (origin, direction, t-min, t-max).
2.  **Traversal Loop:** Perform a depth-first visit of the octree using a recursive Digital Differential Analyzer (DDA) implemented via the full stack [S1, unofficial].
3.  **Voxel Intersection:** Determine the next voxel intersected by the ray.
4.  **Termination Check:** Stop traversal if:
    *   A non-empty voxel is found [S1, unofficial].
    *   The ray span is terminated (ray exits the bounding box or t-max is reached) [S1, unofficial].
5.  **Child Pointer Handling:** When following child pointers:
    *   Decode the child pointer using the variable-rate encoding logic defined in the SSVDAG Node Layout [S1, unofficial].
    *   Retrieve the transformation matrix stored with the pointer [S1, unofficial].
    *   Apply this transformation to the ray or coordinate system every time a child subtree is entered [S1, unofficial].
6.  **Backtracking:** If a branch is exhausted, pop the stack to restore the previous node context [S1, unofficial].

**Pseudocode:**
```python
# Assumes global access to InnerNodesTBO and LeavesTBO
# Assumes Ray structure: origin, direction, t_min, t_max

function traverse_ssvdag_ray(ray):
    stack = Stack()
    # Push root node index and identity transformation or initial context
    stack.push(NodeContext(node_index=ROOT, transform=IDENTITY))
    
    while not stack.is_empty():
        context = stack.peek()
        node = read_node_from_tbo(context.node_index)
        
        # Apply DDA to find next voxel in current node's local space
        # Note: Ray coordinates must be transformed to node's local space
        # if the node has a non-identity transform relative to parent
        local_ray = transform_ray(ray, context.transform)
        
        next_voxel = dda_step(local_ray, node.bounds)
        
        if next_voxel is EMPTY:
            # No intersection in this node's children or empty space
            stack.pop()
            continue
            
        if next_voxel is LEAF:
            # Found a non-empty leaf
            return compute_intersection(ray, next_voxel)
            
        if next_voxel is INNER:
            # Get child pointer index and its associated symmetry transform
            child_idx = node.get_child_index(next_voxel)
            child_transform = node.get_child_transform(next_voxel)
            
            # Combine current transform with child's specific transform
            new_transform = multiply(context.transform, child_transform)
            
            # Push new context
            stack.push(NodeContext(node_index=child_idx, transform=new_transform))
            
        # If ray span exceeded, stop
        if ray.t_max < 0: # Or appropriate termination condition
            break
            
    return NULL
```

**Parameters:**
*   **Rendering Setup:** Deferred shading with screen-space normal estimation and hard shadows for one point light [S1, unofficial].
*   **Normals:** Obtained by finite differences in the frame buffer using a discontinuity preserving filter [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Addressing Limits:** Large datasets may exceed texture buffer object addressing limits, requiring a switch to 3D textures [S1, unofficial].
*   **Transformation Accumulation:** Failure to apply the transformation stored with the pointer upon entering a child will result in incorrect ray intersection tests in symmetric subtrees [S1, unofficial].

## Subtopics

### Sparse Voxel DAG Ray Traversal
The parent method focusing on general SVDAG traversal without symmetry handling. Choose SSVDAG when symmetry compression is active. [Sparse Voxel DAG Ray Traversal](1147-sparse-voxel-dag-ray-traversal.md)

## Operating characteristics
*   **Performance:** Interactive frame rates achieved on large models. For the Powerplant model at 64K³ resolution, SSVDAG achieved 74fps, compared to 86fps for USSVDAG and 87fps for SVDAG [S1, unofficial].
*   **Strengths:** Supports interactive navigation of very large models compressed to the GPU; no additional acceleration or shading structures required beyond the SSVDAG itself [S1, unofficial].
*   **Limitations:** The basic setup focuses on hard shadows and primary rays; soft shadows and ambient occlusion are not covered in the primary implementation details [S1, unofficial]. Voxelization artifacts are most evident in these effects [S1, unofficial].
*   **Scaling:** Performance scales with resolution and model complexity, but remains comparable to uncompressed SVDAG within a small percentage difference [S1, unofficial].

## Background
The method was implemented as part of an experimental software library, preprocessor, and viewer application on Linux using C++, OpenGL, and GLSL [S1, unofficial]. It was designed to test the SSVDAG structure in a simple setting, focusing on visibility queries and secondary ray effects where voxelization artifacts are evident [S1, unofficial]. The approach demonstrates that a terse compressed structure can support real-time navigation of very large scenes [S1, unofficial].
