# Sparse Voxel DAG Ray Traversal

Also called: Ray tracing a sparse voxel DAG, SVO DAG Ray Tracer

## Overview
A GPU-based ray traversal method for Sparse Voxel DAGs (SVDAG) that efficiently computes visibility queries (shadows, ambient occlusion) and primary ray intersections by exploiting the shared structure of the DAG [S1]. It differs from standard Sparse Voxel Octree (SVO) traversal by handling node indirection, where multiple parent nodes may point to the same child instance, requiring careful stack management or pointer dereferencing [S1]. Unlike [Pointerless Sparse Voxel Directed Acyclic Graph (PSVDAG)](949-pointerless-sparse-voxel-directed-acyclic-graph-psvdag.md) which eliminates pointers entirely, this method retains explicit pointers but optimizes traversal for the DAG topology [S1].

## How it works
**Inputs:** A Sparse Voxel DAG structure (nodes with childmasks and pointers to children), a set of rays (primary, shadow, or ambient occlusion), and a traditional SVO structure containing material/attribute information [S1].
**Outputs:** Hit distances, visibility flags, and occlusion values.

**Data Structures:**
*   **DAG Node:** Contains a 4-byte `childmask` (indicating existence of 8 children) and an array of pointers to non-empty children. The size of the pointer array depends on the number of set bits in the mask [S1].
*   **Ray State:** Since voxels are traversed in ray order and no contour intersection tests are performed, the distance traveled along the ray does not need to be explicitly maintained in the traversal state [S1].

**Algorithm Steps:**
1.  **Initialization:** Start traversal from the root of the DAG for each ray or beam [S1].
2.  **Traversal Loop:** Use a stack-based approach similar to Laine and Karras [2010a] [S1].
    *   Pop the current node from the stack.
    *   Check the `childmask` to determine which children are occupied.
    *   For each occupied child, calculate the entry and exit distances of the child voxel relative to the ray.
    *   If the child voxel intersects the ray, push the child node onto the stack [S1].
    *   **DAG Specifics:** Since multiple parents may point to the same child, the traversal must handle indirection. The standard SVO logic applies, but the "current node" is a pointer that may be shared [S1].
3.  **Termination:** Stop when the stack is empty or the ray exits the bounding volume of the scene [S1].
4.  **Attribute Lookup:** Upon finding a hit (leaf node or voxel boundary), query the separate traditional SVO structure using the hit position to retrieve material properties [S1].

**Beam Optimization (Primary Rays):**
1.  Group primary rays into beams of size $8 \times 8$ pixels [S1].
2.  Traverse the DAG for the entire beam simultaneously to exploit coherence [S1].
3.  If the beam passes through empty space, skip further processing for those pixels [S1].

**Soft Shadow Optimization:**
1.  For each pixel, shoot a beam of four rays from the view-sample position to the area light [S1].
2.  Traverse the DAG to find the conservative furthest distance along these rays where no geometry is intersected [S1].
3.  Shorten all shadow rays for that pixel to this distance [S1].
4.  Trace the same beam rays in reverse (from light to view) to find a conservative interval where geometry *may* be intersected [S1].
5.  This reduces the number of shadow rays required, as pixels with no intersections in the beam require no additional shadow rays [S1].

**Ambient Occlusion:**
1.  Cast rays over the hemisphere at the hit point [S1].
2.  Map the first-hit distance to a falloff function to approximate the occlusion integral [S1].

**Pseudocode:**
```python
def traverse_dag_ray(ray_origin, ray_direction, dag_root, material_svo):
    stack = [dag_root]
    closest_hit_dist = infinity
    
    while stack is not empty:
        node = stack.pop()
        
        # Get children pointers and mask from node
        mask = node.childmask
        children = node.children_pointers
        
        # Determine which children are intersected by the ray
        # This involves calculating entry/exit t-values for each of the 8 sub-voxels
        intersected_children = []
        for i in 0..7:
            if (mask >> i) & 1:
                child_bbox = get_voxel_bbox(i, node.level)
                t_min, t_max = ray_intersect_bbox(ray_origin, ray_direction, child_bbox)
                if t_max > 0 and t_min < closest_hit_dist:
                    intersected_children.append((children[i], t_min, t_max))
        
        # Sort children by t_min to process closest first (optional but efficient)
        intersected_children.sort(key=lambda x: x[1])
        
        for child_node, t_min, t_max in intersected_children:
            if t_min < closest_hit_dist:
                # Check if this is a leaf or if we need to go deeper
                if is_leaf(child_node):
                    # Query material SVO for attributes at the hit point
                    hit_point = ray_origin + ray_direction * t_min
                    material = material_svo.query(hit_point)
                    closest_hit_dist = t_min
                    # Depending on application, break or continue for transparency
                else:
                    stack.push(child_node)
                    
    return closest_hit_dist
```

## Subtopics

### [GPU Ray-tracing of SSVDAG](1361-gpu-ray-tracing-of-ssvdag.md)
A GPU raycasting algorithm for Symmetry-aware Sparse Voxel DAGs (SSVDAG) that uses a multi-resolution Digital Differential Analyzer (DDA) with a full stack. It differs from standard SVDAG traversal by handling tagged pointers that encode reflective transformations (symmetry), requiring coordinate system transformations upon entering subtrees. The tracing overhead is less than 15% compared to standard SVO/SVDAG tracing. It is used for primary ray tracing and hard shadow ray tracing directly in the SSVDAG structure.

## Operating characteristics
*   **Time Complexity:** Similar to SVO traversal, $O(depth)$ per ray, but with overhead for indirection. Beam optimization improves throughput for primary rays [S1].
*   **Memory Complexity:** Depends on the DAG compression ratio. Significantly less than SVO for scenes with repetitive geometry [S1].
*   **Performance:** Tracing overhead for SSVDAG is less than 15% compared to standard SVO/SVDAG [S2, unofficial].
*   **Strengths:** Efficient for scenes with repetitive geometry or symmetry; supports high-resolution scenes within strict GPU memory budgets [S1][S2, unofficial].
*   **Limitations:** Requires a separate SVO structure for material attributes [S1]; DAG traversal may have slightly higher overhead due to indirection [S1].

## Background
The method was introduced in "High resolution sparse voxel DAGs" [S1], implementing a GPU-based raytracer in CUDA for visibility queries and primary ray intersection. It builds on the bottom-up reduction mechanism described in [Sparse Voxel DAGs](2791-sparse-voxel-dags.md) and [Bottom-up SVO to DAG Reduction](898-bottom-up-svo-to-dag-reduction.md). The SSVDAG variant was introduced in "Symmetry-aware Sparse Voxel DAGs (SSVDAGs) for compression-domain tracing of high-resolution geometric scenes" [S2, unofficial], extending the DAG concept to include symmetry transformations.
