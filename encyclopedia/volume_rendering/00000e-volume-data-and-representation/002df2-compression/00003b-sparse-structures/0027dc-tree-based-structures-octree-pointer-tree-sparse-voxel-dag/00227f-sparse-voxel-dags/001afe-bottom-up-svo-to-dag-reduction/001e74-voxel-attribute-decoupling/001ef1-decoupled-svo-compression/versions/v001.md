# Decoupled SVO Compression

Also called: Palette Compression for SVOs, SVO Compression Scheme

## Overview
Decoupled SVO Compression is a memory optimization technique for Sparse Voxel Octrees (SVOs) that separates the geometric topology from voxel attributes (such as color, normals, or reflectance) to allow independent, specialized compression of each component [S1]. Unlike standard SVOs or naive colored DAGs that store attributes redundantly with every node, this method achieves significant memory reduction by compressing the sparse geometry structure and applying lossless palette-based compression to the decoupled attribute array, outperforming existing methods like PSVOs, ESVOs, and CDAGs in both memory footprint and visual quality [S1].

## How it works
The method operates in two parallel streams: topology compression and attribute compression, followed by a unified storage format.

### Inputs and Outputs
*   **Input:** A Sparse Voxel Octree (SVO) or Directed Acyclic Graph (DAG) representing a voxel scene, where each leaf or internal node may possess associated attributes (e.g., RGB color, surface normals).
*   **Output:** A compressed data structure consisting of a compacted geometry array and a separate, compressed attribute array, along with metadata required for traversal and index reconstruction.

### Data Structures

#### 1. Geometry Structure
The topology is stored in a linearized array. The standard DAG node structure is modified to reduce overhead:
*   **Child Pointers:** Compressed using implicit first-child offsets and per-level byte-precise offset compression. Pointers are entropy-encoded [S1].
*   **Childmasks:** Reduced from the standard 24-bit padding to 8-bit masks, indicating the presence of children [S1].
*   **Layout:** The geometry array contains nodes with fields for the compressed child pointer offset, the 8-bit childmask, and potentially a pointer to the attribute index if the node is a leaf or contains attributes.

#### 2. Attribute Structure
Attributes are decoupled from the geometry and stored in a dense array.
*   **Attribute Array:** A linear array of attribute values (e.g., 24-bit colors, 32-bit normals).
*   **Indexing:** Each geometry node that has an attribute stores an index (or offset) into this attribute array. In the context of the parent method [Voxel Attribute Decoupling](1761-voxel-attribute-decoupling.md), this index is often stored as a child index minus parent index offset, but the core compression here focuses on the attribute array itself [S1].

### Steps

1.  **Decoupling:** Traverse the original SVO/DAG. Separate the geometric topology (child pointers, masks) from the voxel attributes (colors, normals). Store attributes in a temporary dense list, preserving the order of traversal or spatial locality to exploit coherence [S1].
2.  **Topology Compression:** Apply the following compression techniques to the geometry array [S1]:
    *   **Implicit First Child Offset:** Store the offset to the first child implicitly rather than explicitly for every node.
    *   **Per-Level Byte-Precise Offset Compression:** Compress the offsets for child pointers on a per-level basis.
    *   **Pointer Compression:** Further compress the pointer values.
    *   **8-bit Childmasks:** Replace 24-bit padding masks with 8-bit masks.
    *   **Pointer Entropy Encoding:** Apply entropy encoding (e.g., Huffman or Arithmetic coding) to the compressed pointer data.
3.  **Attribute Compression:** Compress the decoupled attribute array using a lossless palette compression scheme [S1]:
    *   **Quantization:** Quantize attribute values (e.g., 12-bit or 24-bit colors, 32-bit normals) to a manageable precision.
    *   **Palette Construction:** Identify unique attribute values within localized blocks of the attribute array.
    *   **Indexing:** Replace attribute values with indices pointing to a global or local palette of unique values.
    *   **Variable-Length Encoding:** Use variable-length codes for indices, adapting bit-width to the number of unique attributes in the local block [S1].
4.  **Storage Assembly:** Combine the compressed geometry array and the compressed attribute array (palette + indices) into the final data structure.

### Formulas and Parameters

*   **Compression Rate:** Calculated as the ratio of the compressed size to the original uncompressed SVO size.
    $$ \text{Compression Rate} = \frac{\text{Compressed Size}}{\text{Original SVO Size}} \times 100\% $$
*   **Memory Footprint:** The total memory is the sum of geometry size and attribute size.
    $$ \text{Total Size} = \text{Geometry Size} + \text{Attribute Size} $$

**Typical Parameters:**
*   **Color Precision:** 12-bit colors are used for primary comparisons [S1]. For higher quality comparisons against ESVOs, 24-bit colors and 32-bit ONV (One-Value Normal) normals are used [S1].
*   **SVO Levels:** Supports up to 17 levels (128K^3 resolution) [S1].

### Edge Cases and Pitfalls
*   **ESVO Compatibility:** ESVO implementations require contour data to avoid cutting off attributes during traversal. Without contours, quality degrades significantly [S1]. The decoupled method avoids this by storing attributes separately and using palette compression, which does not rely on contour-based traversal cuts [S1].
*   **Dense Data:** While designed for sparse data, the method can compress dense data. For example, a dense Christmas tree dataset achieved a lossless compression rate of 38.6% compared to the original input file [S1].
*   **Precision:** Using lower precision (12-bit) for colors reduces memory further but may impact visual quality. Higher precision (24-bit colors, 32-bit normals) ensures better quality but increases attribute size [S1].

## Subtopics

### [Palette Compression](1873-palette-compression.md)
A variable-length compression scheme for the attribute array that reduces memory footprint by exploiting spatial coherence through global material arrays and local palettes. It differs from fixed-width indexing by allowing the bit-width of indices to adapt to the number of unique attributes within localized blocks, achieving higher compression ratios for scenes with large homogeneous regions.

### [Decoupled DAG with Palette Compression](1893-decoupled-dag-with-palette-compression.md)
A method to compress arbitrary voxel data (colors, normals, reflectance) by decoupling geometry topology from voxel attributes. It uses a DAG to encode the topology (geometry) and a palette-based compression scheme for the extracted attributes, allowing efficient GPU storage and real-time raytracing.

## Operating characteristics
*   **Memory Footprint:** The method significantly reduces memory usage compared to standard SVOs, PSVOs, ESVOs, and CDAGs.
    *   **Citadel:** 0.65 bytes/voxel (22% compression rate vs standard SVO) [S1].
    *   **City:** 0.59 bytes/voxel (21% compression rate) [S1].
    *   **San Miguel:** 0.24 bytes/voxel (8.7% compression rate) [S1].
    *   **Arena:** 0.33 bytes/voxel (11% compression rate) [S1] (Note: ESVO failed to load this scene) [S1].
*   **Performance:** The method supports real-time rendering of colored SVOs with up to 17 levels (128K^3 resolution) on GPU [S1]. It enables applications such as hard shadows, reflections (secondary rays), and color bleeding (single-bounce global illumination) with interactive rates (e.g., 8 secondary rays per pixel) [S1].
*   **Strengths:**
    *   Outperforms state-of-the-art SVO compression methods in memory footprint [S1].
    *   Lossless attribute compression ensures higher quality than lossy schemes like ESVO's DXT1 compression [S1].
    *   Flexible attribute handling allows for various data types (colors, normals) [S1].
*   **Limitations:**
    *   Requires separate compression pipelines for geometry and attributes, increasing implementation complexity.
    *   Performance on very dense datasets may vary, though it still achieves good compression rates (e.g., 38.6% for dense tree data) [S1].

## Background
The method was introduced in the paper "Geometry and Attribute Compression for Voxel Scenes" [S1]. It builds upon the Directed Acyclic Graph (DAG) representation of SVOs [KSA13] and addresses the limitations of existing compression techniques like PSVOs [SK06] and ESVOs [LK10]. The approach was developed to enable real-time rendering of large, detailed voxel scenes with full attribute data, such as colors and normals, on GPU hardware. It is used in applications requiring high-fidelity voxel rendering, including global illumination and reflection effects [S1].
