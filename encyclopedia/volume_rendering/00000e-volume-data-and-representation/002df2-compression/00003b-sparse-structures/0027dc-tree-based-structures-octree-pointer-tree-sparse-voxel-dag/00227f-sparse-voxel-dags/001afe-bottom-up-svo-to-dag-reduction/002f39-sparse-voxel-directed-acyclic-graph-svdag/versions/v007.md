# Sparse Voxel Directed Acyclic Graph (SVDAG)
Also called: Common Subtrees Merge, Sparse Voxel Directed Acyclic Graph (SVDAG) with Common Subtrees Merge (CSM)

## Overview
A Sparse Voxel Directed Acyclic Graph (SVDAG) is a hierarchical data structure that transforms a Sparse Voxel Octree (SVO) into a Directed Acyclic Graph (DAG) by identifying identical subtrees and representing them as a single fully expanded instance, which is multi-referenced from parent nodes [S1][S3, unofficial][S4]. This reduces the number of nodes, particularly at leaf layers, achieving significant compression while enabling quick traversal during visualization [S2][S3, unofficial]. Unlike an SVO, which only encodes empty regions efficiently, the DAG additionally encodes identical regions of space by sharing pointers to identical subtrees [S3, unofficial]. It builds on [Bottom-up SVO to DAG Reduction](898-bottom-up-svo-to-dag-reduction.md) by explicitly storing pointers to enable this merging, distinguishing it from pointerless variants like PSVDAG [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A Sparse Voxel Octree (SVO) or a raw voxel grid of resolution $N^3$, where $N \ge 2$ and $N = 2^m$ [S2][S3, unofficial]. The grid contains binary geometry (active/passive voxels) [S6].
*   **Output:** A Sparse Voxel Directed Acyclic Graph (SVDAG) data structure [S1][S3, unofficial].

**Data Structures:**
The SVDAG consists of two node types: Internal Nodes (INODE) and Leaf Nodes (LNODE) [S1, S2].

1.  **Internal Node (INODE):**
    *   **Child Node Mask (CHNM):** An 8-bit field containing 1-bit Header Tags (HT) for each of the 8 potential children [S1, S2].
        *   $HT = 0$: The sub-DAG is homogeneously filled with passive voxels (pruned, no pointer needed) [S2].
        *   $HT = 1$: At least one voxel is active (child node present, pointer included in PTS) [S2].
    *   **Reserved Bits ($p$):** Concatenated after CHNM for alignment [S1, S2].
    *   **Pointer Table (PTS):** An array of 1 to 8 child node pointers (PT) [S1, S2].
        *   Pointers are arranged in the same order as the HTs in the CHNM [S1].
        *   Each pointer $PT$ is $r$ bits long [S2].
    *   **Constraint:** An INODE must have at least one active child node (1 to 8 pointers) [S1].

2.  **Leaf Node (LNODE):**
    *   Consists of a CHNM only [S1, S2].
    *   Does not contain an array of child node pointers because it is not further decomposed [S1].
    *   Represents a homogeneous block of voxels (e.g., $2^3$ voxels) [S1].

**Formal Layout (BNF):**
$$
\begin{aligned}
\text{SVDAG} &::= (n) \ \text{NODE} \\
\text{NODE} &::= \text{INODE} \mid \text{LNODE} \\
\text{INODE} &::= \text{CHNM} \ (p) \ \text{PTS} \\
\text{LNODE} &::= \text{CHNM} \ (q) \\
\text{CHNM} &::= (8) \ \text{HT} \\
\text{PTS} &::= (1) \dots (8) \ \text{PT} \\
\text{PT} &::= (r) \ \text{BIT} \\
\text{HT} &::= \text{BIT} ::= "0" \mid "1"
\end{aligned}
$$
Where juxtaposition denotes concatenation, $(n)$ denotes $n$ repetitions, and $(1)\dots(8)$ denotes 1 to 8 repetitions [S2].

**Parameters:**
*   **Standard Alignment:** $p = 24$ bits, $r = 32$ bits [S1, S2]. This ensures 32-bit alignment for the CHNM (8b + 24b) and pointers (32b) [S2].
*   **Pointer Size:** Typically 32 bits, allowing 32-bit addressing word length [S1].
*   **CHNM Order:** The order of HTs in the CHNM and pointers in PTS is determined by a space-filling curve, such as the Morton Space Filling Curve (MSFC) or Hilbert Space Filling Curve (HSFC) [S1].
*   **Leaf Uniqueness:** There are at most 255 different versions of leaf nodes (a $(00000000)_2$ configuration does not exist as it represents a passive octant with no separate node) [S1].

**Algorithm (Bottom-Up Reduction):**
The reduction algorithm proceeds from leaves upward, searching the tree for common subtrees and referencing only unique instances [S3, unofficial].

1.  **BuildDAG(grid, depth):**
    *   **Base Case (Leaf Creation):** If `depth == 0` OR `IsHomogeneous(grid)` is true:
        *   Create a Leaf Node (LNODE).
        *   Set `IsLeaf = true`.
        *   Set `Value = grid[0, 0, 0]`.
        *   Assign color based on homogeneity (e.g., green if homogeneous, red if not) [S6].
        *   Generate a unique string key for the current grid section using `GenerateSubtreeKey(grid)` [S6].
        *   **Cache Check:** If `subtreeCache.TryGetValue(key, out VoxelNode existingNode)` returns true, return `existingNode` immediately to merge identical subtrees [S6].
        *   **Cache Insertion:** Add the new node to the cache: `subtreeCache[key] = node` [S6].
        *   Return the created or cached node [S6].
    *   **Recursive Step (Internal Node):**
        *   Create an Internal Node (INODE) with `IsLeaf = false` and color blue [S6].
        *   Initialize `CHNM` to 0.
        *   Initialize `PTS` as an empty list.
        *   Loop `i` from 0 to 7:
            *   Extract the octant using `GetOctant(grid, i, newSize)` [S6].
                *   Calculate start indices: `xStart = (i & 1) * size`, `yStart = (i & 2) * size / 2`, `zStart = (i & 4) * size / 4` [S6].
            *   Recursively call `BuildDAG(octant, depth - 1)` to get `childNode` [S6].
            *   If `childNode` is not null (i.e., the octant is active):
                *   Set the $i$-th bit of `CHNM` to 1 [S2].
                *   Add `childNode` to `PTS`.
        *   **Cache Check:** Generate a key for the current internal node (based on CHNM and PTS content) [S6].
        *   If the key exists in `subtreeCache`, return the cached node [S6].
        *   Add the new INODE to `subtreeCache` [S6].
        *   Return the node [S6].

**Edge Cases and Pitfalls:**
*   **Memory Layout:** Identical pointers exist because nodes can have multiple parents. Rearranging nodes could potentially share pointers and amortize their cost, but this is an open issue [S4].
*   **Attributes:** Adding extra bits of information (e.g., color, material) to leaf nodes reduces the number of identical elements, abolishing compression because previously identical leaves become unique [S5, unofficial][S7, unofficial]. Materials hurt DAGs significantly; subtrees only match if shape and material are identical [S7, unofficial].
*   **Subtree Key Generation:** The method relies on `GenerateSubtreeKey(grid)` to create a unique identifier. The implementation is critical for the caching mechanism but is not provided in the sources [S6].
*   **Passive Octants:** A leaf node with a $(00000000)_2$ configuration does not exist, as it represents a passive octant with no separate node being created [S1].

## Subtopics

### [Symmetry-aware Sparse Voxel DAG (SSVDAG)](1285-symmetry-aware-sparse-voxel-dag-ssvdag.md)
SSVDAG is a compact, lossless representation of voxelized geometry that achieves higher compression than standard Sparse Voxel DAGs (SVDAG) by merging subtrees that are identical through similarity transforms, specifically planar reflections along the main grid directions. It solves the problem of limited GPU memory for high-resolution voxel data by reducing the memory footprint while maintaining real-time traversal performance. Unlike SVDAG, which only shares identical subtrees, SSVDAG exploits reflective symmetry to further reduce node count, and unlike Sparse Voxel Octrees (SVO), it uses variable-bit-rate encoding for pointers to exploit the skewed distribution of node references. [See [Symmetry-aware Sparse Voxel DAG (SSVDAG)](1285-symmetry-aware-sparse-voxel-dag-ssvdag.md)]

### [PSVDAG–SVDAG Conversion Algorithm](1727-psvdag-svdag-conversion-algorithm.md)
The PSVDAG–SVDAG Conversion Algorithm transforms a Pointerless Sparse Voxel Directed Acyclic Graph (PSVDAG) into a Sparse Voxel Directed Acyclic Graph (SVDAG). While PSVDAGs use variable-length Labels/Callers and intermittent binary encoding to minimize storage, SVDAGs use constant-length 32-bit pointers and uninterrupted binary sequences to enable efficient rendering and editing. This conversion replaces the pointerless structure with a pointer-based one, allowing for Child Subtree Merging (CSM) and random access, at the cost of increased memory usage (inflation factor 3.01x–3.70x). [See [PSVDAG–SVDAG Conversion Algorithm](1727-psvdag-svdag-conversion-algorithm.md)]

### Encoding Occupancy in Memory Location
A novel encoding for SVDAGs that utilizes the memory location of nodes to carry data about their internal geometric structure, eliminating the need for an explicit mask to define the node's geometric structure [S4]. It stores node data in memory such that the address/location implicitly encodes the geometric structure (e.g., which children are present) [S4]. During traversal, the node's structure is derived directly from its memory location without performing additional memory accesses for a mask [S4]. This reduces size and improves traversal performance by avoiding memory accesses for the mask [S4]. It is demonstrated compatible with HashDAG data structures and methods for storing voxel attributes such as colours [S4].

### PSVDAG Child Node Mask Compression
Compresses the 8-octant child node mask by replacing a fixed 32-bit representation with a variable-length encoding consisting of an Active Child Node Count and a compacted mask [S8]. It counts the number of active (non-empty) child nodes, encodes the count using a 3-bit Active Child Node Count (ACHNC), and encodes the identities of the active children using a binary Child Node Mask (CHNM) with 2 bits per potential child node [S8]. The total size ranges from 5 bits (1 active child) to 19 bits (8 active children), achieving a compression ratio compared to SVDAG ranging from 1.68 to 6.4 [S8].

## Operating characteristics
**Time and Memory Complexity:**
*   **Node Reduction:** The CSM reduces node counts by one to three orders of magnitude [S3, unofficial][S7, unofficial]. For example, the CRYSPONZA scene achieved a 576x reduction in node count at the highest built resolution, while the HAIRBALL scene achieved a 28x reduction despite lacking obvious regularities [S3, unofficial].
*   **Memory Consumption:** The DAG consumes 8 to 36 bytes per node [S3, unofficial]. It reduces total memory consumption by up to 38x compared to ESVO and up to 26x compared to a minimal pointer-less SVO [S3, unofficial].
*   **Geometry Cost:** Geometry alone costs 0.08–2.24 bits per Voxel across test scenes [S7, unofficial].

**Measured Performance:**
*   **EPICCITADEL Scene (128K³, 19 billion voxels):** The SVDAG stores the scene in 945 MB of GPU memory. An SVO would require 5.1 GB (excluding pointers) [S3, unofficial][S7, unofficial].
*   **Ray Tracing:** On an NVIDIA GTX680, ray tracing in the sparse voxel DAG achieves 170 MRays/sec for ambient occlusion and 240 MRays/sec for shadows [S3, unofficial][S7, unofficial].
*   **Build Time:** Building the DAG for CRYSPONZA at 512³ takes 8.4ms total (1.9ms sorting). At 8K³, it takes 4.5s total (0.6s sorting). For HAIRBALL at 8K³, it takes 40.6s total (4.5s sorting) [S3, unofficial].

**Scaling:**
*   The method scales to resolutions as high as 128K³ [S4].
*   The probability of finding identical subtrees increases with the depth at which their root nodes are located, maximizing compression at leaf nodes [S1].

**Strengths and Limitations:**
*   **Strengths:** Lossless compression without decompression overhead; efficient traversal; supports real-time rendering and interactive editing [S2, S4].
*   **Limitations:** Adding attributes (color, material) to leaves reduces compression significantly [S5, unofficial][S7, unofficial]. Memory layout optimization (sharing pointers among multiple parents) is not fully optimized [S4].

**When to Use:**
*   Use for high-resolution voxel geometry where sparsity and repetitive structures are present [S4].
*   Use when real-time traversal and ray tracing are required [S2][S4].
*   Do not use if the scene has high attribute variation that prevents subtree merging, or if memory layout optimization is critical and not implemented [S5, unofficial][S7, unofficial][S4].

## Background
**Origin:**
High Resolution Sparse Voxel Directed Acyclic Graphs (SVDAGs) were proposed by Viktor Kämpe, Erik Sintorn, and Ulf Assarsson in 2013 [S2][S3, unofficial][S4]. The paper "High Resolution Sparse Voxel DAGs" was published in the ACM SIGGRAPH proceedings [S4].

**History and Development:**
*   The method generalizes the Sparse Voxel Octree (SVO) by allowing nodes to share pointers to identical subtrees [S3, unofficial].
*   Subsequent variants include Symmetry-aware SVDAG (SSVDAG) in 2016, which incorporates pointers of varying lengths (0b, 16b, 32b, 33b) and 2-bit header tags [S2].
*   Parameter optimizations for SVDAGs (SVDAG1-SVDAG6) were explored in 2025, introducing 16-bit CHNMs and varying pointer types [S1].
*   Encoding Occupancy in Memory Location was introduced by Modisett and Billeter in 2025, reducing geometric data size by 13%-18% compared to the original SVDAG [S4].

**Usage:**
*   Used for real-time ray tracing of hard and soft shadows, ambient occlusion, and primary rays in extremely high-resolution voxel scenes [S3, unofficial].
*   Used in interactive editing of voxel models, with GPU editing on an RTX 4080 placing spheres of 1140–1820 Voxel radius in 15–18 ms [S7, unofficial].
