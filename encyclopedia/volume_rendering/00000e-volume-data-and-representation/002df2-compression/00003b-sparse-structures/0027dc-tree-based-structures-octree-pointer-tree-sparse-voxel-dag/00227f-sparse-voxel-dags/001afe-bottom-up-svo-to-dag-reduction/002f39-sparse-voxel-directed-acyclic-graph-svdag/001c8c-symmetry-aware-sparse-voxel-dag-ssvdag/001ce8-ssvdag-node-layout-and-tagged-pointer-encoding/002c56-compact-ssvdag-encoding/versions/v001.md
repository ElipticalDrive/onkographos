# Compact SSVDAG Encoding

Also called: Frequency-based pointer compaction, Leaf grouping, Memory-aligned encoding

## Overview
Compact SSVDAG Encoding is a GPU-friendly memory layout for Symmetry-aware Sparse Voxel Directed Acyclic Graphs (SVDAGs) that minimizes pointer overhead while enabling fast, decompression-free ray tracing [S1, unofficial]. It distinguishes itself from standard SVDAGs by combining leaf grouping, frequency-based pointer compaction, and half-word memory alignment to reduce the memory footprint of high-resolution scenes [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A constructed SVDAG (typically from bottom-up construction using $2^3$ leaf matching) [S1, unofficial].
*   **Output:** A compact binary representation consisting of an indexing structure, an inner node array, and a leaf node array [S1, unofficial].

**Data Structures:**
1.  **Indexing Structure:**
    *   `max_level`: 32-bit integer, the maximum depth $L$ of the tree.
    *   `level_offsets`: Array of three 32-bit integers. Each offset points to the start of a specific level's inner node array within the inner level array [S1, unofficial].
2.  **Inner Node Array:**
    *   A contiguous array of inner nodes.
    *   Nodes are reordered by reference count (descending) before encoding [S1, unofficial].
    *   Each node is encoded as a variable-length sequence of 16-bit half-words [S1, unofficial].
3.  **Leaf Node Array:**
    *   A contiguous array of leaf nodes (bricks).
    *   Each leaf is fixed at 64 bits (8 bytes) [S1, unofficial].

**Inner Node Layout:**
Each inner node begins with a 16-bit header containing four 2-bit tags, one for each of the 8 potential children (grouped as two tags per 16-bit word, or packed into the 16 bits as specified by the source's "16-bit header with 2-bit code for each of 8 potential children" which implies 16 bits total for 8 children, i.e., 2 bits per child) [S1, unofficial].

*   **Tag 00 (Null):** The child is not stored. No pointer data follows [S1, unofficial].
*   **Tag 01 (16-bit Child):** Followed by a 16-bit child pointer.
    *   Bits [15:13]: 3-bit transformation code.
    *   Bits [12:0]: 13-bit offset (in level-words) from the start of the next level's array [S1, unofficial].
*   **Tag 10 (32-bit Child):** Followed by a 32-bit child pointer.
    *   Bits [31:29]: 3-bit transformation code.
    *   Bits [28:0]: Lowest 29 bits of the offset [S1, unofficial].
*   **Tag 11 (32-bit Child with MSB):** Followed by a 32-bit child pointer.
    *   Bits [31:29]: 3-bit transformation code.
    *   Bit [28]: Highest bit of the offset (MSB).
    *   Bits [27:0]: Lowest 28 bits of the offset [S1, unofficial].
    *   *Note:* The source states "highest bit of offset in rightmost header bit" for tags 10/11. This implies the header tag itself might indicate the presence of the MSB, or the tag value 11 specifically carries the MSB in the header's least significant bit. The text says "Tag 10/11... highest bit of the offset is set to the rightmost bit of the header tag." This suggests Tag 10 has MSB=0 in header, Tag 11 has MSB=1 in header. The 32-bit payload contains the remaining 29 bits [S1, unofficial].

**Level-Word Size:**
*   For inner levels: 1 level-word = 2 bytes (16 bits) [S1, unofficial].
*   For leaf level: 1 level-word = 8 bytes (64 bits) [S1, unofficial].

**Algorithm Steps:**
1.  **Leaf Grouping:** Coarsen the construction graph by one level. Instead of storing $2^3$ leaves as individual nodes, group $4^3$ grids into simple grids (bricks) stored in a single array. Each brick occupies 64 bits [S1, unofficial]. This avoids new matching passes; it operates on the graph from the bottom-up construction [S1, unofficial].
2.  **Frequency Analysis:** Count the reference count for every node at each level in the DAG [S1, unofficial].
3.  **Reordering:** Sort the nodes at each level in descending order of their reference counts. Most referenced nodes appear first in the level's array [S1, unofficial].
4.  **Offset Calculation:** Replace absolute pointers with offsets from the beginning of the respective level's array. Calculate the offset in level-words [S1, unofficial].
5.  **Pointer Compaction:**
    *   Determine the number of bits required for each offset based on its magnitude and the available bit slots in the encoding format (16-bit or 32-bit child pointers) [S1, unofficial].
    *   Assign the smallest valid tag (01, 10, or 11) that can represent the offset [S1, unofficial].
6.  **Encoding:**
    *   Write the 16-bit header with the 2-bit tags for each of the 8 children [S1, unofficial].
    *   Write the child pointer data (transformation + offset) immediately after the header for each non-null child [S1, unofficial].
    *   Pack the resulting bytes into 16-bit half-words for memory alignment [S1, unofficial].
7.  **Indexing:** Construct the indexing structure with `max_level` and the starting offsets for each level in the inner node array [S1, unofficial].

**Pseudocode:**

```python
def encode_compact_ssvdag(nodes_by_level):
    """
    nodes_by_level: List of lists. nodes_by_level[l] is a list of node objects.
    Each node has:
      - children: list of 8 child references (or None)
      - ref_count: integer
    """
    inner_arrays = []
    leaf_array = []
    
    # Step 1: Leaf Grouping
    # Coarsen by one level. Leaves are grouped into bricks.
    # Assuming input nodes_by_level includes leaf level L.
    # We process levels 0 to L-1 as inner, and L as leaves.
    # However, the text says "coarsen... encoding 4^3 grids as simple grids".
    # This implies the leaf level nodes are aggregated into bricks.
    
    # Step 2 & 3: Frequency Analysis and Reordering
    for level_idx, level_nodes in enumerate(nodes_by_level):
        # Sort by reference count descending
        level_nodes.sort(key=lambda n: n.ref_count, reverse=True)
        
        if level_idx == len(nodes_by_level) - 1:
            # Leaf Level
            # Encode leaves as 64-bit bricks
            for node in level_nodes:
                # Assuming node.data is the 64-bit voxel data
                leaf_array.append(node.data)
        else:
            # Inner Level
            inner_arrays.append([])
            current_level_nodes = level_nodes
            next_level_nodes = nodes_by_level[level_idx + 1]
            
            # Map next level nodes to their new index for offset calculation
            # Since next level is also sorted, we need to know the mapping.
            # The source implies offsets are relative to the sorted array.
            # We need a map from original node ID to new index in sorted array.
            
            # For simplicity, assume we have a way to identify nodes.
            # In practice, nodes are identified by their position in the sorted array.
            
            for node in current_level_nodes:
                header = 0
                child_data = []
                
                for child_idx in range(8):
                    child = node.children[child_idx]
                    if child is None:
                        # Tag 00
                        header |= (0x00 << (child_idx * 2))
                    else:
                        # Find child's index in the next level's sorted array
                        # This requires a lookup table built during sorting
                        child_offset_words = get_offset_in_words(child, next_level_nodes, level_idx + 1)
                        
                        # Determine tag and encode
                        tag, ptr_bits = encode_pointer(child_offset_words)
                        header |= (tag << (child_idx * 2))
                        
                        # Encode transformation and offset
                        transform = child.transform_code
                        ptr_bits = (transform << 13) | (child_offset_words & 0x1FFF) # For 16-bit
                        # Or 32-bit logic...
                        
                        child_data.append(ptr_bits)
                
                # Pack header and child_data into 16-bit half-words
                inner_arrays[-1].append(pack_to_halfwords(header, child_data))

    # Step 7: Indexing
    indexing = {
        'max_level': len(nodes_by_level) - 1,
        'level_offsets': calculate_offsets(inner_arrays)
    }
    
    return indexing, inner_arrays, leaf_array

def encode_pointer(offset_words):
    # Determine smallest tag that fits offset_words
    if offset_words < (1 << 13):
        # Fits in 16-bit child (13 bits offset)
        # Tag 01
        # Check if MSB is needed? No, 13 bits is enough for small offsets
        # But we must check if it fits in 13 bits.
        # If it fits, use Tag 01.
        return 0x01, offset_words # Simplified
    elif offset_words < (1 << 29):
        # Fits in 32-bit child (29 bits offset)
        # Check MSB
        if offset_words & (1 << 28):
            # Tag 11, MSB in header
            return 0x03, offset_words & 0x1FFFFFF # 29 bits? No, 28 bits in payload
        else:
            # Tag 10
            return 0x02, offset_words & 0x1FFFFFF
    else:
        # Error: Offset too large
        raise ValueError("Offset exceeds addressable space")

def pack_to_halfwords(header, child_data):
    # Pack header (16 bits) and child_data (variable) into 16-bit words
    # The source says "use half-words (16 bits) as the basis".
    # This likely means the entire node is stored as a sequence of 16-bit words.
    # Header is 16 bits. Child pointers are 16 or 32 bits.
    # 32-bit pointers are 2 half-words.
    words = []
    words.append(header)
    for ptr in child_data:
        if ptr is 16-bit:
            words.append(ptr)
        else:
            # 32-bit ptr split into two 16-bit words
            words.append(ptr & 0xFFFF)
            words.append((ptr >> 16) & 0xFFFF)
    return words
```

**Parameters:**
*   **Encoding Basis:** 16-bit half-words [S1, unofficial].
*   **Leaf Size:** 64 bits (8 bytes) [S1, unofficial].
*   **Addressable Space:** >2 GB for inner levels, 8 GB for leaves [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Offset Overflow:** If a node's offset exceeds 29 bits (for inner) or the leaf limit, it cannot be encoded with the current scheme [S1, unofficial].
*   **Memory Alignment:** The use of 16-bit half-words ensures alignment but may introduce padding if the total node size is not a multiple of 16 bits [S1, unofficial].
*   **Reference Count Skew:** The effectiveness relies on the skewed distribution of reference counts. If references are uniform, compaction gains are minimal [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Encoding requires sorting nodes by reference count ($O(N \log N)$ per level) and traversing the DAG to build pointers. Decoding is $O(1)$ per node access if the structure is loaded in memory, as no decompression is needed [S1, unofficial].
*   **Memory Complexity:** Significantly reduced compared to standard SVDAGs due to variable-length pointers and leaf grouping. The addressable space is limited to 2 GB (inner) and 8 GB (leaves) [S1, unofficial].
*   **Performance:** Optimized for GPU ray tracing. The memory-aligned encoding simplifies decoding on GPUs [S1, unofficial].
*   **Strengths:** Low memory footprint, fast tracing, no decompression overhead [S1, unofficial].
*   **Limitations:** Addressable space limits, complexity of encoding due to reordering and offset calculation [S1, unofficial].

## Background
