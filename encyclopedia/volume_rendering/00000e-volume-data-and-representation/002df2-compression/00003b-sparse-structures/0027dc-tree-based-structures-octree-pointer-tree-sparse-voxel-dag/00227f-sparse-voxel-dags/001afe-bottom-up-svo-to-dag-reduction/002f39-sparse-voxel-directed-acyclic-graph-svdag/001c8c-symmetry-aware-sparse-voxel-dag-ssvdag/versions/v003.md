# Symmetry-aware Sparse Voxel DAG (SSVDAG)


## Overview
SSVDAG is a compact, lossless representation of voxelized geometry that achieves higher compression than standard Sparse Voxel DAGs (SVDAG) by merging subtrees that are identical through similarity transforms, specifically planar reflections along the main grid directions [S1, S2, unofficial]. It solves the problem of limited GPU memory for high-resolution voxel data by reducing the memory footprint while maintaining real-time traversal performance [S1, S2, unofficial]. Unlike SVDAG, which only shares identical subtrees, SSVDAG exploits reflective symmetry to further reduce node count, and unlike Sparse Voxel Octrees (SVO), it uses variable-bit-rate encoding for pointers to exploit the skewed distribution of node references [S1, S2, unofficial].

## How it works
**Inputs:** A Sparse Voxel Octree (SVO) or an existing SVDAG.
**Outputs:** A Symmetry-aware Sparse Voxel DAG (SSVDAG) stored in a GPU-friendly format.

**Data Structures:**
1.  **Leaf Node:** Represents a $2^3$ voxel grid.
    *   Canonical Representation: A unique identifier for the leaf's geometry after optimal reflection.
    *   Invariant Bits: Three bits (X, Y, Z) indicating if the subtree is invariant under reflection along each axis.
2.  **Inner Node:**
    *   Header: 16 bits. Contains a 2-bit code for each of the 8 potential children.
    *   Child Pointers: Variable length (0, 2, or 4 bytes) depending on the tag in the header.
    *   Tag '00': Null pointer.
    *   Tag '01': 2-byte pointer. 3 bits encode the transformation (reflection), 13 bits encode the offset in level-words.
    *   Other Tags: Indicate 4-byte pointer formats (details in [1349-ssvdag-node-layout-and-tagged-pointer-encoding.md]).
3.  **Indexing Structure:**
    *   Maximum level $L$.
    *   Three 32-bit offsets indicating the start of each level in the inner level array.

**Construction Algorithm (Bottom-Up):**
The construction reduces an SVO to a minimal SSVDAG by alternating phases at each level, starting from the finest level $L-1$ up to the root at level 0 [S1, S2, unofficial].

1.  **Leaf Clustering:**
    *   Each leaf node represents a $2^3$ voxel grid $G$.
    *   Compute the binary number $B(G)$ by concatenating all 8 voxel occupancy bits in linear order.
    *   Determine the canonical transformation $T^*_{x,y,z}$ that maximizes this binary value:
        $$ T^*_{x,y,z} = \arg \max_{T_{x,y,z}} B(T_{x,y,z}(G)) $$
        where $T_{x,y,z}$ is a combination of reflections along the X, Y, and Z axes.
    *   The canonical representation $G^*$ is the grid resulting from $T^*_{x,y,z}(G)$. This is precomputed in a lookup table of 256 entries mapping all possible $2^3$ voxel combinations to the canonical transformation and the unique canonical representation (one of 46 possible ones) [S1, S2, unofficial].
    *   Sort leaves by their canonical representation.
    *   Perform a streaming pass: merge nearby nodes with the same canonical representation into a single representative.
    *   Compute invariant bits for leaves: A leaf is invariant to a direction if its canonical representation is unchanged by reflection in that direction [S1, unofficial].

2.  **Inner Node Clustering:**
    *   Sort inner nodes by the lexicographically sorted set of their child pointers.
    *   Perform a streaming pass to group self-similar nodes. Two nodes $n_1$ and $n_2$ are similar under transformation $T$ if:
        *   For every tagged pointer $(tag, p)$ in $n_1$, there is a corresponding pointer in $n_2$.
        *   If the child $p$ is **not invariant** to $T$, the pointer in $n_2$ must be $(T(tag), p)$.
        *   If the child $p$ **is invariant** to $T$, the pointer in $n_2$ must be $(T(tag) \oplus T(tag), p)$ (effectively swapping tags if necessary to maintain consistency, or checking that the pointed subtree has the required symmetry) [S1, S2, unofficial].
    *   Repeat this check for all 8 possible reflection combinations. Stop at the first transformation that generates a match with an existing representative. If no match is found, create a new representative.
    *   Pull up invariant bits from children to the parent: An inner node is invariant to a direction if all its children are invariant to that direction, or if the left children are the mirror of the right ones [S1, unofficial].

3.  **Pointer Update:**
    *   Replace pointers to clustered nodes in the immediately higher level with tagged pointers to the single representative.
    *   The tag encodes the transformation $T$ required to recover the original subtree from the representative.

4.  **Encoding (Variable Bit-Rate):**
    *   Sort the representative nodes at each level by their reference count (frequency of occurrence) in descending order [S1, S2, unofficial].
    *   Replace child pointers with offsets from the beginning of the level array.
    *   Assign the smallest available bit-width to the most frequently referenced nodes to exploit the skewed distribution of references [S1, S2, unofficial].
    *   **Leaf Grouping (Coarsening):** Group $2^3$ leaves into $4^3$ inner nodes at level $L-2$ without performing new matches. Encode these as simple grids in a single array of bricks, each occupying 64 bits [S1, S2, unofficial].

## Subtopics

### [SSVDAG Node Layout and Tagged Pointer Encoding](1349-ssvdag-node-layout-and-tagged-pointer-encoding.md)
This method defines the memory layout of inner nodes in an SSVDAG to minimize memory consumption while supporting GPU-friendly traversal [1349-ssvdag-node-layout-and-tagged-pointer-encoding.md]. It replaces the fixed-size child pointers of standard SVDAGs with variable-length tagged pointers (2 or 4 bytes) that embed transformation codes, allowing the representation of symmetry-related subtrees with reduced overhead [1349-ssvdag-node-layout-and-tagged-pointer-encoding.md]. Unlike standard SVDAGs which use only 0 or 4-byte pointers, this layout introduces 2-byte pointers for frequent, close-range references, significantly compressing the data structure for high-resolution scenes [1349-ssvdag-node-layout-and-tagged-pointer-encoding.md].

### [SSVDAG Ray Traversal](5175-ssvdag-ray-traversal.md)
SSVDAG Ray Traversal is a shader-based ray traversal algorithm designed for Symmetry-aware Sparse Voxel Directed Acyclic Graphs (SSVDAGs) [5175-ssvdag-ray-traversal.md]. It solves the problem of efficiently rendering high-resolution, compressed voxel data on the GPU by handling variable-size tagged pointers and symmetry transformations (planar reflections) during the traversal process [5175-ssvdag-ray-traversal.md]. It sets itself apart from standard SVDAG traversal by supporting 0, 2, and 4-byte pointers and applying mirror masks to access child nodes, while distinguishing itself from sibling methods by its specific integration of Level of Detail (LOD) and beam optimization tailored to the SSVDAG memory layout [5175-ssvdag-ray-traversal.md].

## Operating characteristics
**Time and Memory Complexity:**
*   Construction is an external-memory process, allowing it to handle models larger than RAM [S1, S2, unofficial].
*   Memory footprint is significantly lower than SVO and SVDAG. For the PowerPlant scene (256K^3 resolution, ~100 billion non-empty voxels), SSVDAG storage is less than 575 MB (0.048 bits/voxel), compared to 31.1 GB for SVO (55x more) and 1.0 GB for SVDAG (2x more) [S1, unofficial]. For the PowerPlant scene (64K^3 resolution, ~6 billion non-empty voxels), SSVDAG stores data in <86MB (0.123 bits/voxel), compared to 16.2GB for SVO and 167MB for SVDAG [S2, unofficial].
*   The most common 10% of nodes account for nearly 90% of references at level 14 and nearly 50% at level 11 in the Powerplant dataset, justifying the variable-bit-rate encoding [S2, unofficial].

**Performance:**
*   Real-time GPU in-core visualization with shading and shadows is achieved for high-resolution models like the full Boeing 777 at sub-millimetric precision [S1, S2, unofficial].
*   Tracing overhead for SSVDAG compared to standard SVO/SVDAG is less than 15% [S2, unofficial].
*   Node sharing is transparent to the traversal code, allowing the use of the same ray-casting algorithm as SVOs [S2, unofficial].

**Strengths and Limitations:**
*   **Strengths:** High compression ratio, lossless, GPU-friendly, supports real-time rendering.
*   **Limitations:** Construction is complex and requires careful out-of-core management for very large models. Symmetry detection is limited to planar reflections along main grid directions [S1, S2, unofficial].

## Background
SSVDAG was introduced by Alberto Jaspe Villanueva, Fabio Marton, and Enrico Gobbetti from CRS4 [S1, S2, unofficial]. It is based on the earlier work "SSVDAGs: Symmetry-aware Sparse Voxel DAGs" presented at the 20th ACM SIGGRAPH Symposium on Interactive 3D Graphics and Games in 2016 [S1, S2, unofficial]. The method extends the concept of Sparse Voxel DAGs (SVDAG) by incorporating symmetry-aware merging and variable-bit-rate encoding to achieve superior compression for high-resolution voxelized scenes [S1, S2, unofficial].
