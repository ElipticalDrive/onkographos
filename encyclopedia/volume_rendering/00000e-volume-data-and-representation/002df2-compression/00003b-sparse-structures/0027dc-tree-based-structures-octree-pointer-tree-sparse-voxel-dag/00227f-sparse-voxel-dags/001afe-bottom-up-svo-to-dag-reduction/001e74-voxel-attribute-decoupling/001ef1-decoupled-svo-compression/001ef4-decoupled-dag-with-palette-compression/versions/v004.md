# Decoupled DAG with Palette Compression

Also called: Decoupled DAG, Geometry and Attribute Compression for Voxel Scenes

## Overview
Decoupled DAG with Palette Compression is a method for compressing arbitrary voxel data (colors, normals, reflectance) by separating geometry topology from voxel attributes. It uses a Directed Acyclic Graph (DAG) to encode the topology and a palette-based compression scheme for the extracted attributes, allowing efficient GPU storage and real-time raytracing. It sets itself apart from standard DAGs, which are restricted to single-bit geometry information, and from Moxel DAGs, which require more memory for indices due to large empty leaf counts and lack multi-resolution support.

## How it works
**Inputs:** A Sparse Voxel Octree (SVO) containing voxel attributes (e.g., colors, normals).
**Outputs:** A compressed DAG structure for geometry and a compressed attribute array.

**Data Structures:**
1.  **DAG Node:** Contains pointers to children. Unlike an SVO, pointers are not grouped consecutively. The node stores offsets or indices to map to the attribute array.
2.  **Dense Attribute Array:** A linear array storing the extracted attributes for all leaf nodes (or relevant nodes) in the order they appear in the traversal.
3.  **Palette:** A smaller array of unique attribute values used to replace repeated attributes in the dense array.

**Steps:**

1.  **Construct DAG Topology:**
    *   Start with the leaves at the lowest level of the input SVO.
    *   Compare subtrees in a greedy bottom-up fashion.
    *   If two subtrees are identical in geometry (topology), merge them by changing parent pointers to reference a single common subtree.
    *   This reduces the node count significantly, especially at low levels where the number of unique combinations is small (e.g., max 256 nodes at the second-lowest level for 8-child nodes).

2.  **Decouple Attributes:**
    *   Extract voxel attributes from the SVO/DAG structure.
    *   Store these attributes in a dense attribute array.
    *   Store offsets or indices in the DAG node pointers to map each node to its position in the attribute array.
    *   *Note:* This decoupling allows the geometry to be merged even if attributes differ, as attributes are no longer tied to the topology during the merging process.

3.  **Compress Attribute Array:**
    *   Apply palette-based compression to the dense attribute array.
    *   Exploit spatial coherence where large blocks contain similar attributes.
    *   Replace sequences of similar attributes with indices into a local palette.
    *   *Optional:* Quantize attributes beforehand to improve compression performance, trading quality for memory savings.

4.  **Render via DAG Traversal:**
    *   During raytracing, traverse the DAG.
    *   Use the accumulated offsets/indices in the node pointers to retrieve the correct attribute from the compressed attribute array.
    *   Decompress the attribute using the palette if necessary.

**Pseudocode:**

```python
def construct_dag(svo):
    """
    Construct a DAG from an SVO by merging identical subtrees bottom-up.
    """
    # Start with leaves
    nodes = svo.get_leaves()
    
    # Process from bottom to top
    for level in reversed(svo.levels):
        current_level_nodes = []
        seen_subtrees = {}
        
        for node in level:
            # Get the unique signature of the subtree rooted at this node
            # Signature includes child pointers and structure
            subtree_sig = get_subtree_signature(node)
            
            if subtree_sig in seen_subtrees:
                # Merge: point to existing node
                seen_subtrees[subtree_sig].children = node.children
                current_level_nodes.append(seen_subtrees[subtree_sig])
            else:
                # New unique subtree
                seen_subtrees[subtree_sig] = node
                current_level_nodes.append(node)
        
        nodes = current_level_nodes

    return nodes

def decouple_attributes(svo, dag_root):
    """
    Extract attributes into a dense array and map DAG nodes to indices.
    """
    attribute_array = []
    node_to_index_map = {}
    
    # Traverse DAG to collect attributes in a consistent order
    # For example, pre-order traversal
    def traverse(node, index_counter):
        if node.is_leaf():
            attr = node.get_attribute()
            index = index_counter[0]
            node_to_index_map[node] = index
            attribute_array.append(attr)
            index_counter[0] += 1
        else:
            for child in node.children:
                traverse(child, index_counter)
                
    index_counter = [0]
    traverse(dag_root, index_counter)
    
    return attribute_array, node_to_index_map

def compress_attributes(attribute_array):
    """
    Compress attribute array using palette compression.
    """
    # Identify unique attributes and create a palette
    palette = []
    palette_index_map = {}
    compressed_indices = []
    
    for attr in attribute_array:
        if attr not in palette_index_map:
            palette_index_map[attr] = len(palette)
            palette.append(attr)
        compressed_indices.append(palette_index_map[attr])
        
    return palette, compressed_indices

def render_raytrace(dag_root, palette, compressed_indices, node_to_index_map):
    """
    Render using DAG traversal and decompressed attributes.
    """
    # During traversal, retrieve attribute index from node
    # Then decompress from palette
    def get_attribute(node):
        index = node_to_index_map[node]
        attr_index = compressed_indices[index]
        return palette[attr_index]

    pass
```

**Parameters:**
*   **Resolution:** Supports up to 17 hierarchical levels, corresponding to a $128K^3$ voxel resolution (2.25 quadrillion voxels) [S1].
*   **Memory Usage:** For a $128K^3$ scene with 18.4 billion colored nodes, the compressed representation requires 7.63 GB of GPU memory [S1].

**Edge Cases and Pitfalls:**
*   **Merging Failure:** Merging subtrees fails to compress sufficiently when attributes are tightly linked to topology because adding voxel data reduces the probability of equal subtrees. The decoupling scheme solves this by separating geometry and attributes [S1].
*   **Precision:** Quantization of attributes can lead to quality loss. The trade-off between quality and memory must be managed [S1].
*   **Boundary Conditions:** The DAG construction assumes a consistent traversal order for attribute mapping.

## Subtopics

### [Packed Vertex Attribute Encoding](2334-packed-vertex-attribute-encoding.md)
Packed Vertex Attribute Encoding is a compression scheme for vertex attributes in hardware-accelerated volume splatting that reduces memory usage by packing volume texture coordinates and Gaussian texture coordinates into 32-bit integers per vertex. It sets itself apart from sibling methods by specifically targeting the attribute storage of proxy geometry in EWA splatting, decoupling the coordinate components into fixed-width bit fields to achieve high compression ratios (e.g., 171:1) while allowing fast decompression via lookup tables.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** The DAG compression gain is highest at low levels in the tree. For an SVO with 17 levels, the second-lowest level has billions of nodes, while the DAG has at most 256 nodes (the amount of possible unique combinations of eight child voxels having each one bit) [S1].
*   **Measured Performance:** For a $128K^3$ scene with 18.4 billion colored nodes, the compressed representation requires 7.63 GB of GPU memory [S1]. Real-time performance is achieved on commodity hardware for colored scenes with up to 17 hierarchical levels [S1].
*   **Scaling:** The method supports up to 17 hierarchical levels, corresponding to a $128K^3$ voxel resolution [S1].
*   **Strengths:** Drastic memory reduction, efficient GPU storage, real-time raytracing, handles arbitrary voxel data (colors, normals, reflectance).
*   **Limitations:** Merging subtrees is difficult when attributes are tightly linked to topology (solved by decoupling). The DAG overhead (pointers per node) is higher than SVOs if not compressed effectively.
*   **When to Use:** When compressing arbitrary voxel data (colors, normals) is required, and real-time raytracing on GPU is needed.
*   **When Not to Use:** When memory is not a constraint and simplicity of implementation is preferred. When attributes are not spatially coherent, palette compression may not be effective.

## Background
The method was introduced in the paper "Geometry and Attribute Compression for Voxel Scenes" by Timothy Kol et al. from Delft University of Technology. It addresses the limitation of previous DAG-based compression methods that were restricted to single-bit geometry information. The method builds on the concept of DAGs for sparse voxel scenes but extends it to arbitrary data through decoupling and palette compression. It outperforms existing state-of-the-art techniques, such as Moxel DAGs, which require more memory for indices and lack multi-resolution support.
