# Arbitrary Permutation Transformations for SVDAG

Also called: Arbitrary Transformations, Permutation-aware SVDAG

## Overview
This method extends Symmetry-aware Sparse Voxel DAGs (SSVDAG) by defining all $8!$ permutation transformations of child octants to maximize geometric redundancy removal [S1]. While the theoretical framework supports arbitrary reordering of the eight child pointers to capture rotational symmetries, practical implementations restrict the transformation set to mirror symmetries and axis permutations to balance compression gains with encoding cost [S1].

## How it works
The method operates recursively on the voxel graph, replacing nodes with canonical representations that account for all possible permutations of their children [S1].

### Inputs and Outputs
*   **Input:** A Sparse Voxel Octree (SVO) or existing SVDAG structure [S1].
*   **Output:** A compressed SVDAG where nodes are canonicalized under arbitrary permutations, reducing the total node count [S1].

### Data Structures
**Node Layout:**
A node $N$ is a tuple of eight child pointers:
$$N \doteq (c_0, \dots, c_7)$$
Each child pointer $c_i$ consists of a memory address and a transformation $T$ applied to that child [S1]. Empty octants use a null pointer ($c_i = \emptyset$) [S1].

**Leaf Layout:**
Leaves at level $L=1$ are flattened into $2^3$ voxel grids [S1]. Each leaf is replaced by:
1.  A **canonical-transform pointer**: Contains the canonical grid $g^\star$ and the transformation $T$ such that $T(g^\star) \equiv g$ [S1].
2.  A **temporary bitmask**: Stores the invariance of $g^\star$ with respect to all possible transformations [S1]. Size: $8! = 40,320$ bits [S1].

**Transformation Definition:**
A permutation is a bijective function $T: \{0, \dots, 7\} \to \{0, \dots, 7\}$ [S1]. A transformed child pointer $T(c_i)$ is the concatenation of $T$ with the transform stored in $c_i$ [S1].

### Algorithm Steps

#### 1. Leaf Canonicalization
For each leaf node (level $L=1$):
1.  Flatten the subtree into a voxel grid $g$ [S1].
2.  Generate the set of all grids transformable to $g$:
    $$\hat{G} = \{ \hat{g} \mid T(\hat{g}) \equiv g \}$$
    where $T$ ranges over all $8!$ permutations [S1].
3.  Compute the canonical representation $g^\star$ as the "highest-value" grid in $\hat{G}$:
    $$g^\star = \arg\max_{\hat{g} \in \hat{G}} B(\hat{g})$$
    where $B(g)$ is the binary number obtained by concatenating all voxels of grid $g$ [S1].
4.  Compute the invariance bitmask for $g^\star$. For each permutation $T$, set the bit to 1 if $g^\star \equiv T(g^\star)$, else 0 [S1].
5.  Store the pointer to $g^\star$ and the corresponding transformation $T$ such that $T(g^\star) = g$ [S1].

#### 2. Inner Node Canonicalization
Process nodes level by level from bottom to top [S1]. For a given level $L$:
1.  **Clustering:** Group nodes that have the same set of child pointer addresses (ignoring order and child transformations) to reduce the search space [S1].
2.  **Iteration:** Iterate through nodes $N_i$ in each cluster [S1].
3.  **Matching:** For each $N_i$, test if there exists a previous node $N_j$ ($j < i$) and a permutation $T$ such that:
    $$N_i \equiv_T (N_j)$$
    This is done via exhaustive search over all $T$ [S1].
4.  **Equivalence Test:** To test $N_i \equiv_T (N_j)$:
    a. Apply permutation $T$ to $N_j$, shuffling children and updating their stored transforms [S1].
    b. Two transformed child subtrees $T_i(c_k)$ and $T_j(c_k)$ are equivalent if they have the same canonical representation address and their transformations result in the same geometry [S1].
    c. Geometry equivalence is tested by checking the invariance bitmask of the canonical representation for the composite transformation $T_i^{-1} \circ T_j$:
    $$c_k \equiv_{T_i^{-1} \circ T_j} c_k$$
    d. If all 8 children match, $N_i \equiv_T (N_j)$ [S1].
5.  **Canonicalization:** If no match is found, $N_i$ is canonical. Compute its invariance bitmask (similar to leaves) and output it [S1]. If a match is found, replace $N_i$ with a pointer to $N_j$ and the transformation $T$ [S1].

### Pseudocode
```python
def permutations(elements):
    """Generate all permutations of a list of elements."""
    if len(elements) == 0:
        yield []
        return
    for i, el in enumerate(elements):
        for p in permutations(elements[:i] + elements[i+1:]):
            yield [el] + p

def apply_permutation_to_grid(grid, perm):
    """Apply a permutation of octant indices to a 2x2x2 voxel grid."""
    new_grid = [0] * 8
    for i in range(8):
        new_grid[perm[i]] = grid[i]
    return new_grid

def binary_value(grid):
    """Convert a 2x2x2 voxel grid (list of 0/1) to an integer."""
    val = 0
    for v in grid:
        val = (val << 1) | v
    return val

def compose_transforms(T1, T2):
    """Compose two permutations: T1 applied after T2."""
    return [T1[T2[i]] for i in range(8)]

def inverse_permutation(perm):
    """Compute the inverse of a permutation."""
    inv = [0] * 8
    for i, p in enumerate(perm):
        inv[p] = i
    return inv

def canonicalize_leaf(grid):
    """Canonicalize a 2x2x2 voxel grid under all 8! permutations."""
    best_grid = None
    best_val = -1
    canonical_transform = None
    invariance_mask = 0

    for T in permutations(range(8)):
        transformed_grid = apply_permutation_to_grid(grid, T)
        val = binary_value(transformed_grid)
        if val > best_val:
            best_val = val
            best_grid = transformed_grid
            canonical_transform = T

    for i, T in enumerate(permutations(range(8))):
        if apply_permutation_to_grid(best_grid, T) == best_grid:
            invariance_mask |= (1 << i)

    return best_grid, canonical_transform, invariance_mask

def is_equivalent(child_info1, child_info2, T1, T2):
    """Check if two child pointers are equivalent under transforms T1 and T2."""
    addr1, _, mask1 = child_info1
    addr2, _, mask2 = child_info2
    if addr1 != addr2:
        return False
    composite = compose_transforms(inverse_permutation(T1), T2)
    # In practice, composite is mapped to its enumeration index to check the mask
    idx = find_permutation_index(composite)
    return (mask1 >> idx) & 1

def find_permutation_index(perm):
    """Map a permutation to its index in the enumeration of all 8! permutations."""
    # Standard combinatorial number system implementation
    return 0

def canonicalize_inner_node(node, child_canonicals, previous_canonicals):
    """
    Canonicalize an inner node.
    node: tuple of 8 child pointers (address, transform_perm)
    child_canonicals: dict mapping address -> (canonical_grid_or_node, transform, mask)
    previous_canonicals: list of previously accepted canonical nodes for this cluster
    Returns (canonical_node, invariance_mask) or None if duplicate.
    """
    for T in permutations(range(8)):
        for N_j, mask_j in previous_canonicals:
            match = True
            for k in range(8):
                inv_T = inverse_permutation(T)
                orig_idx = inv_T[k]
                c_j_addr, c_j_trans = N_j[orig_idx]
                c_i_addr, c_i_trans = node[k]

                if c_i_addr != c_j_addr:
                    match = False
                    break

                c_i_info = child_canonicals[c_i_addr]
                c_j_info = child_canonicals[c_j_addr]

                T_i = compose_transforms(T, c_j_trans)
                if not is_equivalent(c_i_info, c_j_info, T_i, c_i_trans):
                    match = False
                    break
            if match:
                return None

    node_invariance_mask = 0
    for i, T in enumerate(permutations(range(8))):
        if is_node_invariant(node, T, child_canonicals):
            node_invariance_mask |= (1 << i)
    return (node, node_invariance_mask)

def is_node_invariant(node, T, child_canonicals):
    """Check if a node is invariant under permutation T."""
    inv_T = inverse_permutation(T)
    for k in range(8):
        orig_idx = inv_T[k]
        c_i_addr, c_i_trans = node[k]
        c_j_addr, c_j_trans = node[orig_idx]
        if c_i_addr != c_j_addr:
            return False
        c_i_info = child_canonicals[c_i_addr]
        c_j_info = child_canonicals[c_j_addr]
        T_i = compose_transforms(T, c_j_trans)
        if not is_equivalent(c_i_info, c_j_info, T_i, c_i_trans):
            return False
    return True
```

### Parameters and Edge Cases
*   **Mask Size:** The invariance bitmask for leaves is $8! = 40,320$ bits, which limits the practical scene size due to memory constraints [S1].
*   **Canonical Selection:** The canonical grid is chosen as the one with the highest binary value $B(g)$ [S1]. This differs from SSVDAG, which assumed $T^{-1} = T$ [S1].
*   **Edge Cases:** Empty octants use null pointers. The method applies the permutation to all children rather than a variable subset for practical reasons [S1].

## Subtopics

### Practical Transformation Subset (Symmetry + Axis Permutation)
A restricted subset of transformations used to achieve practical compression while maintaining most reuse [S1]. It includes mirror symmetries (flipping along primary axes) and axis permutations (swapping primary axes, e.g., $(x,y,z) \to (z,x,y)$) [S1]. The subset $\Omega$ must be closed under composition ($\forall T_i, T_j \in \Omega: T_i \circ T_j \in \Omega$) and contain inverses ($\forall T_i \in \Omega: T_i^{-1} \in \Omega$) [S1]. This subset accounts for almost all reuse, with only a small difference in node count compared to using all permutations (e.g., Bistro scene: 4.94M nodes with S+A vs 4.77M with All) [S1]. It represents any 90-degree rotation along primary axes, forming the symmetry group of the cube and octahedron [S1].

## Operating characteristics
*   **Time Complexity:** The method involves an exhaustive search over all $8!$ permutations for each node, which is computationally expensive [S1].
*   **Memory Complexity:** The invariance bitmask for leaves is 40,320 bits, which is significant and limits the practical scene size [S1]. The use of a practical subset reduces this to a manageable size (e.g., 48 permutations for S+A) [S1].
*   **Performance:** The method reduces the number of nodes significantly compared to SVDAG and SSVDAG. For example, the Bistro scene has 4.94M nodes with S+A, compared to 5.59M with S and 6.74M with SVDAG [S1].
*   **Strengths:** Maximizes geometric redundancy removal by capturing all permutation symmetries.
*   **Limitations:** High computational cost and memory usage for the full permutation set. The practical subset is a compromise between compression and efficiency [S1].

## Background
This method extends the concept of SSVDAGs to support all transformations that can be described by reordering the children of the nodes [S1]. It was introduced to remove geometric redundancy that mirror symmetries alone cannot capture, such as rotations [S1]. The method builds on the work of Villanueva et al. (2016) on SSVDAGs [S1].
