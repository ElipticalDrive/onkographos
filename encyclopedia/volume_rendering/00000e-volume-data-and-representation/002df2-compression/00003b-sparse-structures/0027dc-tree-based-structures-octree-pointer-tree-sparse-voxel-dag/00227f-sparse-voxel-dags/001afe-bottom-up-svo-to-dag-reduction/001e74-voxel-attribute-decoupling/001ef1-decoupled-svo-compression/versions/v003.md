# Decoupled SVO Compression

Also called: Palette Compression for SVOs, SVO Compression Scheme

## Overview
Decoupled SVO Compression is a memory optimization technique for Sparse Voxel Octrees (SVOs) that separates geometric topology from voxel attributes (such as color, normals, or reflectance) to allow independent, specialized compression of each component [S1]. Unlike standard SVOs or naive colored DAGs that store attributes redundantly with every node, this method achieves significant memory reduction by compressing the sparse geometry structure and applying lossless palette-based compression to the decoupled attribute data, outperforming existing methods like PSVOs, ESVOs, and CDAGs in both memory footprint and visual quality [S1].

## How it works
### Inputs and Outputs
*   **Input:** A Sparse Voxel Octree (SVO) or Directed Acyclic Graph (DAG) representing a voxel scene, where nodes may possess associated attributes (e.g., RGB color, surface normals) [S1].
*   **Output:** A compressed data structure consisting of a compacted geometry array and a separate, compressed attribute representation (palette and indices), along with metadata required for traversal and index reconstruction [S1].

### Data Structures
#### 1. Geometry Structure
The topology is stored in a compacted array using the following fields and techniques [S1]:
*   **Child Pointers:** Compressed using implicit first-child offsets and per-level byte-precise offset compression [S1].
*   **Childmasks:** Reduced from the standard 24-bit padding to 8-bit masks, indicating the presence of children [S1].
*   **Pointer Encoding:** Further compressed and entropy-encoded [S1].
*   **Layout:** Exact bit-packing layouts for the geometry nodes are not given in the sources [G].

#### 2. Attribute Structure
Attributes are decoupled from the geometry and organized into a palette-based representation that exploits spatial coherence [S1]:
*   **Attribute Values:** Quantized to a specified precision (e.g., 12-bit or 24-bit colors, 32-bit normals) [S1].
*   **Palette & Indices:** Unique attribute values are stored in a palette, and each geometry node references an attribute via an index into this palette rather than storing raw values [G].
*   **Layout:** The attribute structure consists of the palette array and a parallel index array mapping nodes to palette entries [G].

### Steps
1.  **Decoupling:** Traverse the original SVO/DAG and separate the geometric topology (child pointers, masks) from the voxel attributes (colors, normals) [S1].
2.  **Topology Compression:** Apply implicit first-child offset storage, per-level byte-precise offset compression, pointer compression, 8-bit childmasks, and pointer entropy encoding to the geometry data [S1].
3.  **Attribute Compression:** Quantize attribute values and apply a lossless palette compression scheme that exploits spatial coherence [S1].
4.  **Storage Assembly:** Combine the compressed geometry array and the compressed attribute palette/indices into the final data structure [S1].

### Formulas and Parameters
*   **Compression Rate:** Calculated as the ratio of the compressed size to the original uncompressed SVO size [G].
    $$ \text{Compression Rate} = \frac{\text{Compressed Size}}{\text{Original SVO Size}} \times 100\% $$
*   **Memory Footprint:** The total memory is the sum of geometry size and attribute size [G].
    $$ \text{Total Size} = \text{Geometry Size} + \text{Attribute Size} $$

**Typical Parameters:**
*   **Color Precision:** 12-bit colors are used for the main comparison in Table 4 and Figure 6 [S1]. For attribute precision in ESVO comparison, 24-bit colors and 32-bit ONV normals are used for palette compression to ensure better quality than ESVO's lossy schemes [S1].
*   **SVO Levels:** Supports up to 17 levels (128K^3 resolution) [S1].

### Edge Cases and Pitfalls
*   **ESVO Compatibility:** ESVO implementations require contour data to avoid cutting off attributes during traversal [S1]. Without contours, quality degrades significantly [S1]. The decoupled method avoids this by storing attributes separately and using palette compression, which does not rely on contour-based traversal cuts [S1].
*   **Dense Data:** While designed for sparse data, the method can compress dense data [S1]. For example, a dense Christmas tree dataset achieved a lossless compression rate of 38.6% compared to the original input file [S1]. When applying a simple filtering to remove scanning noise in the air, additional sparsity benefits achieve rates below 10% [S1].
*   **Precision:** Using lower precision (12-bit) for colors reduces memory further but may impact visual quality [S1]. Higher precision (24-bit colors, 32-bit normals) ensures better quality but increases attribute size [S1].

## Subtopics

### [Palette Compression](1873-palette-compression.md)
A variable-length compression scheme for the attribute array that reduces memory footprint by exploiting spatial coherence through global material arrays and local palettes. It differs from fixed-width indexing by allowing the bit-width of indices to adapt to the number of unique attributes within localized blocks, achieving higher compression ratios for scenes with large homogeneous regions.

### [Decoupled DAG with Palette Compression](1893-decoupled-dag-with-palette-compression.md)
A method to compress arbitrary voxel data (colors, normals, reflectance) by decoupling geometry topology from voxel attributes. It uses a DAG to encode the topology (geometry) and a palette-based compression scheme for the extracted attributes, allowing efficient GPU storage and real-time raytracing. It outperforms Moxel DAGs by requiring less memory and supporting multi-resolution level-of-detail rendering, whereas Moxel DAGs store empty leaf counts and use two running sums that become prohibitive at quadrillion-scale resolutions.

## Operating characteristics
*   **Memory Footprint:** The method significantly reduces memory usage compared to standard SVOs, PSVOs, ESVOs, and CDAGs [S1].
    *   **Citadel:** 0.65 bytes/voxel (22% compression rate vs standard SVO) [S1].
    *   **City:** 0.59 bytes/voxel (21% compression rate) [S1].
    *   **San Miguel:** 0.24 bytes/voxel (8.7% compression rate) [S1].

*   **Performance:** The method supports real-time rendering of colored SVOs with up to 17 levels (128K^3 resolution) on GPU [S1]. It enables applications such as hard shadows, reflections (secondary rays), and color bleeding (single-bounce global illumination) with interactive rates (e.g., 8 secondary rays per pixel) [S1].
*   **Strengths:**
    *   Outperforms state-of-the-art SVO compression methods in memory footprint [S1].
    *   Lossless attribute compression ensures higher quality than lossy schemes like ESVO's DXT1 compression [S1].
    *   Flexible attribute handling allows for various data types (colors, normals) [S1].
*   **Limitations:**
    *   Requires separate compression pipelines for geometry and attributes, increasing implementation complexity [G].
    *   Performance on very dense datasets may vary, though it still achieves good compression rates (e.g., 38.6% for dense tree data) [S1].

## Background
The method was introduced in the paper "Geometry and Attribute Compression for Voxel Scenes" [S1]. It builds upon the Directed Acyclic Graph (DAG) representation of SVOs [KSA13] and addresses the limitations of existing compression techniques like PSVOs [SK06] and ESVOs [LK10]. The approach was developed to enable real-time rendering of large, detailed voxel scenes with full attribute data, such as colors and normals, on GPU hardware. It is used in applications requiring high-fidelity voxel rendering, including global illumination and reflection effects [S1].
