# SSVDAG Node Layout and Tagged Pointer Encoding

Also called: Compact representation, Tagged pointer encoding

## Overview
This method defines the binary layout of inner nodes in a Symmetry-aware Sparse Voxel DAG (SSVDAG) to minimize memory footprint while supporting GPU-friendly traversal. It replaces fixed-size child pointers with variable-length tagged pointers (2 or 4 bytes) that embed transformation codes, solving the memory overhead problem of standard SVDAGs where all pointers are fixed at 4 bytes [S1, unofficial]. It differs from its parent [Symmetry-aware Sparse Voxel DAG (SSVDAG)](1285-symmetry-aware-sparse-voxel-dag-ssvdag.md) by explicitly detailing the bit-packing scheme for these pointers and the associated traversal state management.

## How it works

### Inputs and Outputs
*   **Input:** A voxelized scene represented as a Sparse Voxel DAG with symmetry-aware compression.
*   **Output:** A memory layout for inner nodes where child pointers are encoded as variable-length tagged pointers, and a traversal algorithm that maintains a cumulative transformation status.

### Data Structures

#### Inner Node Header
Each inner node begins with a 16-bit header. This header contains 8 entries, each 2 bits wide, corresponding to the 8 potential children (octant order).
*   **Tag 00:** Null pointer. No child data follows.
*   **Tag 01:** 16-bit child pointer.
*   **Tag 10:** 32-bit child pointer.
*   **Tag 11:** 32-bit child pointer.

#### Child Pointer Encoding
Child pointers are stored immediately after the header. The size and format depend on the header tag.

**1. 16-bit Pointer (Tag 01)**
*   **Size:** 2 bytes (16 bits).
*   **Layout:**
    *   Bits [15:13]: Transformation code (3 bits).
    *   Bits [12:0]: Offset in number of level-words (13 bits).
*   **Addressing:**
    *   For inner levels: Level-word size is 2 bytes. Max addressable offset is $2^{13} \times 2 = 2^{14}$ bytes (16 KB).
    *   For leaf levels: Level-word size is 8 bytes. Max addressable offset is $2^{13} \times 8 = 2^{16}$ bytes (64 KB).

**2. 32-bit Pointers (Tags 10 and 11)**
*   **Size:** 4 bytes (32 bits).
*   **Layout:**
    *   Bits [31:29]: Transformation code (3 bits).
    *   Bits [28:0]: Lowest 29 bits of the offset.
    *   Bit [29] (Highest bit of offset): Set to the value of the rightmost bit of the header tag (bit 1 of the 2-bit tag).
        *   If Tag is 10 (binary `10`), rightmost bit is 0. Offset high bit is 0.
        *   If Tag is 11 (binary `11`), rightmost bit is 1. Offset high bit is 1.
*   **Addressing:**
    *   For inner levels: Max addressable offset > 2 GB.
    *   For leaf levels: Max addressable offset > 8 GB.

### Traversal State
During ray traversal, a 3-bit **Transformation Status** variable is maintained.
*   **Initialization:** 0.
*   **Update:** When descending to a child, XOR the current status with the 3-bit transformation code extracted from the child's pointer.
*   **Restoration:** The status must be pushed to a stack along with the current node index to allow restoration upon backtracking.
*   **Application:** This status indicates which reflections must be applied to indices when accessing child pointers in inner nodes or voxel contents in leaf nodes.

### Algorithm: Accessing the i-th Child Pointer
Accessing the $i$-th child requires computing the byte offset within the node's data stream. Unlike SVDAG, where pointers are either 0 or 4 bytes, SSVDAG pointers are 0, 2, or 4 bytes.

1.  Read the 16-bit header.
2.  Extract the 2-bit tag for child $i$.
3.  Compute the byte offset from the start of the child pointer array:
    $$ \text{Offset} = \sum_{j=0}^{i-1} \text{Size}(\text{Tag}_j) $$
    Where $\text{Size}(\text{Tag}_j)$ is 0 if $\text{Tag}_j = 00$, 2 if $\text{Tag}_j = 01$, and 4 if $\text{Tag}_j \in \{10, 11\}$.
4.  Read the pointer data at this offset.
5.  Extract the transformation code from the top 3 bits.
6.  Decode the offset based on the pointer size (see formulas below).

### Formulas

**16-bit Pointer Offset Decoding:**
Let $P_{16}$ be the 16-bit integer value of the pointer.
$$ \text{Transform} = P_{16} \gg 13 $$
$$ \text{WordOffset} = P_{16} \ \& \ 0x1FFF $$
$$ \text{ByteOffset} = \text{WordOffset} \times \text{LevelWordSize} $$
Where $\text{LevelWordSize} = 2$ for inner levels, $8$ for leaf levels.

**32-bit Pointer Offset Decoding:**
Let $P_{32}$ be the 32-bit integer value of the pointer.
$$ \text{Transform} = P_{32} \gg 29 $$
$$ \text{LowOffset} = P_{32} \ \& \ 0x1FFFFFFF $$
$$ \text{HighBit} = (\text{HeaderTag} \ \& \ 1) $$
$$ \text{FullOffset} = (\text{HighBit} \ll 29) \ | \ \text{LowOffset} $$
$$ \text{ByteOffset} = \text{FullOffset} \times \text{LevelWordSize} $$

### Pseudocode

```python
def decode_child_pointer(header_16bit, child_index, level_word_size):
    """
    Decodes the child pointer for a specific child index in an SSVDAG inner node.
    
    Args:
        header_16bit (int): The 16-bit header value.
        child_index (int): The index of the child to access (0-7).
        level_word_size (int): 2 for inner levels, 8 for leaf levels.
        
    Returns:
        tuple: (transform_code, byte_offset)
    """
    # Extract the 2-bit tag for the specific child
    # Each tag is 2 bits, located at bit position (child_index * 2)
    tag = (header_16bit >> (child_index * 2)) & 0x3
    
    if tag == 0x0:
        # Null pointer
        return (0, None)
    
    # Calculate byte offset within the child pointer array
    # Sum sizes of all previous children
    byte_offset_in_array = 0
    for j in range(child_index):
        prev_tag = (header_16bit >> (j * 2)) & 0x3
        if prev_tag == 0x0:
            byte_offset_in_array += 0
        elif prev_tag == 0x1:
            byte_offset_in_array += 2
        else: # 0x2 or 0x3
            byte_offset_in_array += 4
            
    # Read pointer data based on size
    # Note: In a real implementation, this reads from a byte buffer.
    # Here we assume a helper function to read bytes from a buffer at a given offset.
    # The buffer starts immediately after the header.
    
    if tag == 0x1:
        # 16-bit pointer
        # Read 2 bytes
        ptr_val = read_16bit_from_buffer(byte_offset_in_array)
        
        transform_code = ptr_val >> 13
        word_offset = ptr_val & 0x1FFF
        byte_offset = word_offset * level_word_size
        
        return (transform_code, byte_offset)
        
    else:
        # 32-bit pointer (tags 0x2 or 0x3)
        # Read 4 bytes
        ptr_val = read_32bit_from_buffer(byte_offset_in_array)
        
        transform_code = ptr_val >> 29
        low_offset = ptr_val & 0x1FFFFFFF
        
        # Determine high bit from header tag
        # Header tag is 2 bits: 0x2 is '10', 0x3 is '11'
        # Rightmost bit of header tag
        header_tag_low_bit = tag & 0x1
        
        high_bit = header_tag_low_bit << 29
        full_offset = high_bit | low_offset
        byte_offset = full_offset * level_word_size
        
        return (transform_code, byte_offset)
```

### Edge Cases and Pitfalls
*   **Variable Size Access:** Accessing the $i$-th child requires summing the sizes of all preceding pointers $[0, i-1]$. This differs from SVDAG, which only had sizes 0 and 4. This computation must be performed in the shader, typically via a manually unrolled loop [S1, unofficial].
*   **Precision:** The 13-bit offset in 16-bit pointers limits addressing to the first 16 KB of inner levels and 64 KB of leaf levels. If a node is located beyond this range, it must use a 32-bit pointer (Tag 10 or 11).
*   **Transformation Accumulation:** The transformation status is cumulative. It must be XOR-ed with each pointer's transformation code as the traversal descends. It must be saved to the stack to be restored upon backtracking [S1, unofficial].

## Operating characteristics

*   **Memory Footprint:** Significantly reduced compared to fixed-pointer SVDAGs. Null children consume 0 bytes, common children consume 2 bytes, and rare/distant children consume 4 bytes.
*   **Complexity:**
    *   **Time:** Traversal is slightly more expensive than fixed-pointer SVDAG due to the need to compute variable offsets via a loop (or bit manipulation) for each child access.
    *   **Space:** Inner node headers are fixed at 16 bits. Child data is variable.
*   **Performance:** Designed for GPU efficiency. The variable-length encoding allows compact storage, improving cache utilization. The transformation status is a simple 3-bit integer, minimizing register pressure.
*   **Limitations:** The 16-bit pointer is limited to small offsets. Large scenes may require more 32-bit pointers, reducing the compression benefit.

## Background

The SSVDAG node layout was introduced by Kämpe et al. in 2016 as an extension of the Sparse Voxel DAG (SVDAG) [Kämpe et al. 2013]. The original SVDAG used fixed 4-byte pointers. The SSVDAG method was developed to further reduce memory consumption by exploiting the fact that many child pointers are null or point to nearby nodes, allowing for variable-length encoding. It also integrates symmetry-aware compression, storing transformation codes directly in the pointers [S1, unofficial].
