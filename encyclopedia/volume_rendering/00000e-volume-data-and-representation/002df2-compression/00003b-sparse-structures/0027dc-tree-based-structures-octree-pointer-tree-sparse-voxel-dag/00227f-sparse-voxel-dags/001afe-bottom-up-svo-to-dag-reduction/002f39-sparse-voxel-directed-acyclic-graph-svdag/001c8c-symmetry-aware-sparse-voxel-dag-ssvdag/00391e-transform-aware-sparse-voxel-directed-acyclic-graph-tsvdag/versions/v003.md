# Transform-Aware Sparse Voxel Directed Acyclic Graph (TSVDAG)

Also called: Destructive Translation Matching, Destructive Translations, Translation-aware SVDAG

## Overview
TSVDAG extends Sparse Voxel Directed Acyclic Graphs (SVDAG) by detecting and encoding repeating geometry that aligns with node boundaries through destructive translations, mirror symmetries, and axis permutations [S1]. It solves the limitation of standard SVDAGs, which only merge subtrees that are identical in position and orientation, by allowing voxels to be translated out of a subtree (disappearing) to match translated counterparts [S1]. This enables significantly higher compression ratios for scenes with repetitive structures, at the cost of increased preprocessing complexity and rendering overhead due to variable-length pointer encoding and additional traversal state [S1].

## How it works
**Inputs:** A Sparse Voxel Octree (SVO) or a pre-computed SVDAG/SSVDAG structure [S1].
**Outputs:** A TSVDAG structure with transformed pointers and a compressed memory layout [S1].

### Data Structures and Layout

**1. Node Header**
Each node begins with a 16-bit mask [S1]. This mask represents eight 2-bit integers, where each integer specifies the length (in bits) of the corresponding child pointer [S1]. A length of 0 indicates an empty child [S1].
*   **Field:** `mask` (16 bits)
*   **Layout:** 8 x 2-bit fields.

**2. Child Pointers**
Pointers are variable-length: 16, 32, or 48 bits [S1]. They are sorted by frequency so that the most referenced nodes have the shortest pointers [S1].
*   **16-bit pointers:** Always encode an index into a Level-specific Look-Up Table (LUT) [S1].
*   **32-bit pointers:** The most significant bit (MSB) indicates if it is a LUT index (MSB=1) or a direct pointer (MSB=0) [S1]. If direct, it points to a 16-bit aligned address [S1].
*   **48-bit pointers:** Always direct pointers [S1].

**3. Transform ID**
Stored in the least-significant bits of the pointer (before the address) [S1]. It combines:
*   **Child-Reorder Transformation ID:** Identifies symmetry or axis permutation [S1].
*   **Translation Mask:** A 3-bit mask indicating zero translation along each of the primary axes (X, Y, Z) [S1]. A bit value of 1 indicates zero translation, while 0 indicates non-zero translation [S1].
*   **Encoding:** The Transform ID is Huffman-coded to minimize bits for frequent transforms [S1].

**4. Translation Data**
If the Translation Mask indicates non-zero translation for an axis, the translation distance is stored in the next significant bits [S1].
*   **Size:** 5 bits per axis with non-zero translation [S1].

**5. Memory Address**
The remaining most-significant bits store the memory address of the child node [S1]. The address space is indexed at 16-bit intervals [S1].

**6. Look-Up Table (LUT)**
One LUT is constructed per SVDAG level [S1].
*   **Entry Size:** Fixed 64 bits [S1].
*   **Content:** Stores the full pointer (Transform ID + Translation + Address) for frequently used pointers [S1].
*   **Construction:** Greedy algorithm [S1]. Sort pointers by frequency [S1]. Iterate and insert into LUT if `Cost(Direct) > Cost(LUT)` [S1].
    *   `Cost(Direct) = Rounded_Pointer_Length * Occurrences`
    *   `Cost(LUT) = 64 * Occurrences` [S1].

### Algorithm Steps

#### 1. Fast Translation Search
To find destructive translation matches between subtrees (flattened to $(2^L)^3$ voxel grids, with $L=4$):
1.  Compute a hash for each voxel describing the area to the top/right [S1].
2.  Compute hashes horizontally, then vertically [S1].
3.  A match between the lower/left voxel of grid B and a voxel in grid A indicates B is constructable from A by a translation of $(-1, -1)$ in the hash space [S1].
4.  Test for symmetry simultaneously: A voxel in direction $(+x, +y, -z)$ matching a corner voxel in $(+x, +y, +z)$ indicates a transformation by translation and z-axis symmetry [S1].
5.  Complexity: $O(NV)$, where $N$ is the number of grids and $V=(2^L)^3$ [S1].

#### 2. Dependency Graph Construction
1.  Flatten subtrees into voxel grids [S1].
2.  Identify parent-child relationships where a parent subtree can be transformed into a child subtree [S1].
3.  If multiple parents exist, store the one with the highest memory address to encourage clustering [S1].
4.  Sort subtrees by the number of occupied voxels to favor destructive translations [S1].
5.  Limit translation search to subtrees of up to $16^3$ voxels ($L=4$) [S1]. Higher levels have diminishing returns and require more bits for the translation range $[-2^L+1, +2^L-1]^3$ [S1].

#### 3. Pointer Encoding and LUT Construction
1.  Sort nodes such that the most referenced ones appear first in memory [S1].
2.  For each level, collect all child pointers [S1].
3.  Sort pointers by frequency [S1].
4.  Iterate through sorted pointers:
    *   Calculate direct cost: Length in bits (rounded up to 32 or 48) $\times$ occurrences [S1].
    *   Calculate LUT cost: 64 bits $\times$ occurrences [S1].
    *   If LUT cost is lower, add pointer to LUT [S1].
5.  Encode pointers:
    *   If in LUT: Encode as 16-bit index [S1].
    *   Else: Encode as 32-bit (with MSB flag) or 48-bit direct pointer [S1].
6.  Apply Huffman coding to the Transform ID field [S1].

#### 4. Rendering (Ray Traversal)
1.  **Ray-Node Intersection:** Compute intersection points between the ray and the three primary planes passing through the node center [S1]. Create a bitmask of intersected children [S1].
2.  **Traversal Order:** Determine order by sign bits of the ray direction [S1].
3.  **Child Reordering:**
    *   Store transformation state on a traversal stack [S1].
    *   Use a GPU constant memory LUT to apply permutations and pre-composed transformations ($T = T_i \circ T_j$) [S1].
4.  **Translation Handling:**
    *   Use a second stack for levels containing translations (up to $16^3$) [S1].
    *   Stack entry stores: Accumulated translation, ray entry distance ($t_{min}$), and ray exit distance ($t_{max}$) [S1].
    *   Translate child node centers using accumulated translation [S1].
    *   Limit intersection bounds to remove voxels moved outside subtree bounds [S1].

### Pseudocode

```python
import math
from collections import Counter

def compute_hash(grid):
    """Compute hash for each voxel describing area to top/right."""
    rows, cols = len(grid), len(grid[0])
    # Horizontal pass
    h_hash = [[0] * cols for _ in range(rows)]
    for y in range(rows):
        acc = 0
        for x in range(cols):
            acc = (acc * 31 + grid[y][x]) & 0xFFFFFFFF
            h_hash[y][x] = acc
    # Vertical pass
    final_hash = [[0] * cols for _ in range(rows)]
    for x in range(cols):
        acc = 0
        for y in range(rows):
            acc = (acc * 31 + h_hash[y][x]) & 0xFFFFFFFF
            final_hash[y][x] = acc
    return final_hash

def find_translation_match(grid_A, grid_B, max_offset):
    """Check if grid_B can be constructed from grid_A by destructive translation."""
    hash_A = compute_hash(grid_A)
    hash_B = compute_hash(grid_B)
    rows, cols = len(grid_A), len(grid_A[0])
    
    # Check offsets in hash space
    for tx in range(-max_offset, max_offset + 1):
        for ty in range(-max_offset, max_offset + 1):
            match = True
            for y in range(rows):
                for x in range(cols):
                    src_x, src_y = x - tx, y - ty
                    if 0 <= src_x < cols and 0 <= src_y < rows:
                        if hash_A[src_y][src_x] != hash_B[y][x]:
                            match = False
                            break
                    else:
                        # Destructive translation: out-of-bounds voxels disappear
                        if hash_B[y][x] != 0:
                            match = False
                            break
                if not match: break
            if match:
                return (tx, ty, 0)
    return None

def build_lut_and_pointers(nodes):
    """Build variable-length pointers and LUT for a specific level."""
    # Count pointer frequencies
    pointer_counts = Counter(nodes)
    sorted_pointers = sorted(pointer_counts.items(), key=lambda x: x[1], reverse=True)
    
    lut = {}
    direct_pointers = []
    
    for pointer, count in sorted_pointers:
        # Calculate costs
        # Direct cost: rounded length (32 or 48) * count
        direct_cost = (48 if len(pointer) > 32 else 32) * count
        # LUT cost: 64 * count
        lut_cost = 64 * count
        
        if lut_cost < direct_cost:
            if pointer not in lut:
                lut[pointer] = len(lut)
            direct_pointers.append((pointer, 'lut', lut[pointer]))
        else:
            direct_pointers.append((pointer, 'direct', None))
            
    return lut, direct_pointers

def decode_pointer(pointer_bits):
    """Decode variable-length pointer into transform_id, translation, address."""
    # Simplified bit extraction based on evidence layout
    transform_id = pointer_bits & 0xFF
    translation_mask = (pointer_bits >> 8) & 0x07
    translation = []
    for i in range(3):
        if not (translation_mask & (1 << i)):
            translation.append((pointer_bits >> (11 + i*5)) & 0x1F)
        else:
            translation.append(0)
    address = pointer_bits >> 26
    return transform_id, translation, address

def ray_traverse(node, ray, transform_stack, translation_stack):
    """Traverse TSVDAG node."""
    # Base case: leaf or out of bounds
    if node.is_leaf or ray.tmax < node.tmin or ray.tmin > node.tmax:
        return
    
    # 1. Compute intersection with node center planes
    intersection_mask = 0
    for i in range(8):
        cx = (i & 1) * 2 - 1
        cy = ((i >> 1) & 1) * 2 - 1
        cz = ((i >> 2) & 1) * 2 - 1
        # Check if child center is within ray bounds after translation
        if translation_stack:
            acc_trans = translation_stack[-1].accumulated
            center = (node.center + acc_trans)
        else:
            center = node.center
        child_center = (center[0] + cx, center[1] + cy, center[2] + cz)
        # Simple AABB check against ray tmin/tmax
        if ray.intersects_box(child_center, node.half_size):
            intersection_mask |= (1 << i)
            
    # 2. Determine traversal order based on ray direction signs
    order = []
    for i in range(8):
        if intersection_mask & (1 << i):
            sx = 1 if ray.dir[0] > 0 else -1
            sy = 1 if ray.dir[1] > 0 else -1
            sz = 1 if ray.dir[2] > 0 else -1
            # Order by distance along ray direction
            order.append(i)
    order.sort(key=lambda idx: (
        (ray.dir[0] > 0) * 4 + (ray.dir[1] > 0) * 2 + (ray.dir[2] > 0)
    ))
    
    # 3. For each intersected child
    for child_idx in order:
        if not (intersection_mask & (1 << child_idx)):
            continue
            
        # Get pointer for child
        pointer = node.children[child_idx]
        if pointer is None:
            continue
            
        # Decode pointer
        transform_id, translation, address = decode_pointer(pointer)
        
        # Handle Transform (Symmetry/Permutation)
        current_transform = transform_stack[-1] if transform_stack else 0
        new_transform = apply_permutation(current_transform, transform_id)
        transform_stack.append(new_transform)
        
        # Handle Translation
        if any(t != 0 for t in translation):
            acc_trans = translation_stack[-1].accumulated if translation_stack else (0,0,0)
            new_acc = tuple(a + t for a, t in zip(acc_trans, translation))
            # Adjust tmin/tmax based on translation
            new_tmin = max(0, ray.tmin - math.dist(ray.origin, new_acc) / max(1e-6, abs(ray.dir[0])))
            new_tmax = ray.tmax
            translation_stack.append({
                'accumulated': new_acc,
                'tmin': new_tmin,
                'tmax': new_tmax
            })
            
            # Recurse with translated bounds
            child_node = get_node(address)
            ray_traverse(child_node, ray, transform_stack, translation_stack)
            
            translation_stack.pop()
        else:
            # Recurse normally
            child_node = get_node(address)
            ray_traverse(child_node, ray, transform_stack, translation_stack)
            
        transform_stack.pop()
```

### Parameters
*   **Translation Search Limit:** Subtrees up to $16^3$ voxels ($L=4$) [S1].
*   **Translation Range:** $[-2^L+1, +2^L-1]^3$ [S1].
*   **Translation Mask:** 3-bit mask for zero/non-zero axes [S1].
*   **Translation Bits:** 5 bits per axis with non-zero translation [S1].
*   **Pointer Sizes:** 16, 32, or 48 bits [S1].
*   **LUT Entry Size:** 64 bits [S1].
*   **Base Pointer Space:** 48 bits [S1].

### Edge Cases and Pitfalls
*   **Complex Dependencies:** Destructive translations can create multi-level indirection in the dependency graph [S1]. Due to SVDAG encoding limitations, subtrees in these cases must be duplicated [S1].
*   **Variable-Length Overhead:** GPU memory systems are not optimized for variable-length data, causing render overhead [S1].
*   **Registry Pressure:** Maintaining the additional translation stack increases GPU registry pressure or causes spilling [S1].
*   **Search Complexity:** Naive translation search is $O(NV^2)$, which is impractical [S1]. The optimized $O(NV)$ search is required [S1].
*   **Address Space Gaps:** Variable-length pointers index the address space at 16-bit intervals, leaving many indices unreferenced, reducing the effectiveness of compact encodings [S1].

## Subtopics

### [Arbitrary Permutation Transformations for SVDAG](8412-arbitrary-permutation-transformations-for-svdag.md)
Extends SSVDAG by supporting all $8!$ permutation transformations of child octants to maximize geometric redundancy removal. It differs from SSVDAG, which only supports mirror symmetries, by allowing arbitrary reordering of the eight child pointers, thereby capturing rotational symmetries and complex spatial redundancies that mirror operations alone miss.

## Operating characteristics
*   **Compression:** TSVDAG achieves 20% to 30% (up to 35%) memory improvement over SSVDAG [S1]. SVO memory usage is 516% to 1456% larger than TSVDAG across tested scenes (Bistro, Bunny, Crown, Citadel, Lucy, Dragon at 64k³) [S1]. A dense voxel grid for these scenes would require 35TB [S1].
*   **Encoding Overhead:** Pointer LUT + Huffman coding reduces size by 4% to 8% compared to Pointer LUT alone [S1]. However, enabling LUT and Huffman increases frame time by ~12% [S1].
*   **Translation Overhead:** Adding translation transformations increases frame time by ~30% [S1].
*   **Render Performance:** SVDAG with fixed 32-bit pointer encoding outperforms variable-length methods by ~10% [S1]. Rendering benchmarks were captured on an NVIDIA RTX4070 using a CUDA-based path tracer [S1].
*   **Preprocessing:** Fast translation search takes a couple of hours for a 64k³ scene on CPU, significantly slower than hierarchical symmetry/permutation search (<1 minute) [S1].
*   **Strengths:** Highest compression ratio among compared methods (SVO, SVDAG, SSVDAG) [S1].
*   **Limitations:** High preprocessing cost; increased rendering overhead due to variable-length pointers and translation stack; complex dependency handling requires duplication [S1].

## Background
TSVDAG was introduced in the paper "Transform-Aware Sparse Voxel Directed Acyclic Graphs" [S1]. It builds upon SVDAG [Kämpe et al. 2013] and SSVDAG [Villanueva et al. 2016] [S1]. The method was evaluated on scenes including Bistro, Bunny, Crown, Citadel, Lucy, and Dragon at 64k³ resolution [S1]. Rendering benchmarks were captured on an NVIDIA RTX4070 using a CUDA-based path tracer [S1].
