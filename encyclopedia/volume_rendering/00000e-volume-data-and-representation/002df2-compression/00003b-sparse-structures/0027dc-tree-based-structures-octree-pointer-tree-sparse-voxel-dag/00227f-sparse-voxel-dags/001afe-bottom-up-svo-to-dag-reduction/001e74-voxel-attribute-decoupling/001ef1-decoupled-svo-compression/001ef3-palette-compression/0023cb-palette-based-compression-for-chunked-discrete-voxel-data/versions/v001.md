# Palette-based compression for chunked discrete voxel data

Also called: BlockStorage, Minecraft 1.13 compression

## Overview
Palette-based compression for chunked discrete voxel data is a lossless compression technique for discrete voxel data (e.g., Minecraft blocks) that separates block groups/chunks from their actual storage using a structure called `BlockStorage` [S1, unofficial]. It uses a palette of block types/states and variable-bit-length indices pointing to that palette, similar to GIF color palettes [S1, unofficial]. It achieves memory reduction where regions with few block types (e.g., air/stone) use only 1-2 bits per block, while high-entropy regions (forests, structures) use more bits, balanced by the palette size [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A chunk of discrete voxel data of size $N = \text{CHUNK\_SIZE}^3$.
*   **Output:** A compressed representation consisting of a bit buffer of indices and a palette array.

**Data Structures:**
1.  **Chunk:** Contains a static constant `CHUNK_SIZE` and a `BlockStorage` instance initialized with size $\text{CHUNK\_SIZE}^3$. Methods `setBlock(x,y,z,type)` and `getBlock(x,y,z)` convert coordinates to an index and delegate to storage [S1, unofficial].
2.  **BlockStorage:**
    *   `size` (int): Total number of blocks in the chunk ($N$).
    *   `data` (BitBuffer): A buffer holding variable-bit-length indices.
    *   `palette` (PaletteEntry[]): Array of palette entries.
    *   `paletteCount` (int): Number of active entries in the palette.
    *   `indicesLength` (int): Bit width of each index in the `BitBuffer`. Starts at 1. Grows exponentially (powers of two) when palette fills. Shrinks when palette is less than half full [S1, unofficial].
3.  **PaletteEntry:**
    *   `refcount` (int): Default 0. Tracks usage frequency.
    *   `type` (BlockType): The actual block type/state data.
    *   Recommended to be implemented as a struct/value-type [S1, unofficial].
4.  **BitBuffer:**
    *   Represents a memory region (array of bytes/ints/longs) allowing arbitrary bit-range access.
    *   Methods: `set(int bitIndex, int bitLength, int bits)` and `get(int bitIndex, int bitLength)` [S1, unofficial].

**Initialization:**
`BlockStorage` is initialized with `indicesLength=1`, `paletteCount=0`, `palette` size $2^1$, and `data` size $size \times 1$ bits [S1, unofficial].

**Algorithm Steps:**

1.  **Reading a Block (`getBlock`):**
    1.  Read palette index from `data` at `index * indicesLength` with length `indicesLength` [S1, unofficial].
    2.  Return `palette[paletteIndex].type` [S1, unofficial].

2.  **Writing a Block (`setBlock`):**
    1.  Read current palette index from `data` at `index * indicesLength` with length `indicesLength` [S1, unofficial].
    2.  Get current `PaletteEntry` from `palette[paletteIndex]` [S1, unofficial].
    3.  Decrement current entry's `refcount` [S1, unofficial].
    4.  Search palette for existing entry matching `type` [S1, unofficial].
    5.  If found:
        *   Update `data` at `index * indicesLength` with that index, length `indicesLength` [S1, unofficial].
        *   Increment its `refcount` [S1, unofficial].
        *   Return [S1, unofficial].
    6.  If not found and current entry `refcount` is 0:
        *   Overwrite current entry with `type` [S1, unofficial].
        *   Set `refcount` to 1 [S1, unofficial].
        *   Return [S1, unofficial].
    7.  If not found and current `refcount` > 0:
        *   Call `newPaletteEntry()` to get a free slot (growing if necessary) [S1, unofficial].
        *   Create new `PaletteEntry` with `refcount` 1 and `type` [S1, unofficial].
        *   Set `data` at `index * indicesLength` to new entry index, length `indicesLength` [S1, unofficial].
        *   Increment `paletteCount` [S1, unofficial].

3.  **Finding a New Palette Entry (`newPaletteEntry`):**
    1.  Find first free entry in `palette` (entry is null or `refcount` is 0) [S1, unofficial].
    2.  If found, return its index [S1, unofficial].
    3.  If not found, call `growPalette()` [S1, unofficial].
    4.  Recursively call `newPaletteEntry()` to find the new free slot [S1, unofficial].

4.  **Growing the Palette (`growPalette`):**
    1.  Decode all indices from current `data` into an int array `indices` of size `size` [S1, unofficial].
    2.  Double `indicesLength` (`indicesLength << 1`) [S1, unofficial].
    3.  Create new `palette` array of size $2^{\text{indicesLength}}$ [S1, unofficial].
    4.  Copy existing palette entries to new array [S1, unofficial].
    5.  Allocate new `BitBuffer` of size `size * indicesLength` bits [S1, unofficial].
    6.  Encode all indices from `indices` array into new `data` buffer [S1, unofficial].

5.  **Fitting/Shrinking the Palette (`fitPalette`):**
    1.  Iterate palette, setting entries with `refcount` 0 to null and decrementing `paletteCount` [S1, unofficial].
    2.  If `paletteCount` is not less than half of its closest power of two, return (do not shrink) [S1, unofficial].
    3.  Decode all indices from current `data` into `indices` [S1, unofficial].
    4.  Halve `indicesLength` (`indicesLength >> 1`) [S1, unofficial].
    5.  Create new `palette` array of size $2^{\text{indicesLength}}$ [S1, unofficial].
    6.  Iterate old palette, copying non-null entries to new palette at `paletteCounter` [S1, unofficial].
    7.  For each moved entry, re-encode indices: if old index matches current old palette index, update `indices[di]` to `paletteCounter` and increment `fc` (found count) until `fc` equals entry's `refcount` [S1, unofficial].
    8.  Allocate new `BitBuffer` of size `size * indicesLength` bits [S1, unofficial].
    9.  Encode all indices from `indices` array into new `data` buffer [S1, unofficial].

        self.palette_count = 0

        self.data = BitBuffer(self.size * self.indices_length)

    def set_block(self, index, block_type):
        palette_index = self.data.get(index * self.indices_length, self.indices_length)
        current_entry = self.palette[palette_index]

        # Whatever block is there will cease to exist in but a moment...
        current_entry.refcount -= 1

        # Is the block-type already in the palette?
        replace = -1
        for i, entry in enumerate(self.palette):
            if entry is not None and entry.type == block_type:
                replace = i
                break
        
        if replace != -1:
            # YES: Use the existing palette entry.
            self.data.set(index * self.indices_length, self.indices_length, replace)
            self.palette[replace].refcount += 1
            return

        # If not found and current refcount is 0, overwrite current entry
        if current_entry.refcount == 0:
            current_entry.type = block_type
            current_entry.refcount = 1
            return

        # A new palette entry is needed!
        new_entry_index = self.new_palette_entry()
        self.palette[new_entry_index] = PaletteEntry(refcount=1, type=block_type)
        self.data.set(index * self.indices_length, self.indices_length, new_entry_index)
        self.palette_count += 1

    def get_block(self, index):
        palette_index = self.data.get(index * self.indices_length, self.indices_length)
        return self.palette[palette_index].type

    def new_palette_entry(self):
        first_free = -1
        for i, entry in enumerate(self.palette):
            if entry is None or entry.refcount == 0:
                first_free = i
                break
        
        if first_free != -1:
            return first_free

        # No free entry? Grow the palette, and thus the BitBuffer
        self.grow_palette()
        
        # Just try again now!
        return self.new_palette_entry()

    def grow_palette(self):
        # Decode the indices
        indices = []
        for i in range(self.size):
            indices.append(self.data.get(i * self.indices_length, self.indices_length))

        # Create new palette, doubling it in size
        self.indices_length = self.indices_length << 1
        new_palette = [None] * (2 ** self.indices_length)
        
        # We gotta compress the palette entries!
        palette_counter = 0
        for pi in range(len(self.palette)):
            entry = self.palette[pi]
            if entry is not None:
                new_palette[palette_counter] = entry
                # Re-encode the indices (find and replace; with limit)
                fc = 0
                for di in range(len(indices)):
                    if fc < entry.refcount and indices[di] == pi:
                        indices[di] = palette_counter
                        fc += 1
                palette_counter += 1

        self.palette = new_palette

        # Allocate new BitBuffer
        self.data = BitBuffer(self.size * self.indices_length)

        # Encode the indices
        for i in range(len(indices)):
            self.data.set(i * self.indices_length, self.indices_length, indices[i])

    def fit_palette(self):

        new_palette_count = 0
        for i, entry in enumerate(self.palette):
            if entry is None or entry.refcount == 0:
                self.palette[i] = None
            else:
                new_palette_count += 1
        self.palette_count = new_palette_count

        # Assuming it means: if palette_count >= 2^(indices_length - 1), do not shrink.

        indices = []
        for i in range(self.size):
            indices.append(self.data.get(i * self.indices_length, self.indices_length))

        # Halve indicesLength
        self.indices_length = self.indices_length >> 1

        # Create new palette array
        new_palette = [None] * (2 ** self.indices_length)
        
        # Iterate old palette, copying non-null entries to new palette at paletteCounter
        palette_counter = 0
        for pi in range(len(self.palette)):
            entry = self.palette[pi]
            if entry is not None:

                # Re-encode the indices

        # Encode all indices from indices array into new data buffer

**Parameters:**
*   `indicesLength`: The bit width of each index in the `BitBuffer`. Starts at 1. Grows exponentially (powers of two) when palette fills. Shrinks when palette is less than half full [S1, unofficial].
*   `CHUNK_SIZE`: The dimension of the chunk. Recommended limit is $32^3$ or $64^3$. Larger chunks reduce performance [S1, unofficial].

**Edge Cases and Pitfalls:**
*   Using a Dictionary/HashMap for the palette is discouraged. Linear search over a small array of structs is faster than dictionary index calculation [S1, unofficial].
*   Delta-compression is pointless because block types fit the bit-length of indices, and it would make reading blocks O(n) in the worst case [S1, unofficial].
*   Chunk size must be limited. Too large chunks reduce performance and increase memory usage worse than plain arrays [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Reading blocks (`getBlock`) is O(1) time [S1, unofficial]. Writing blocks (`setBlock`) involves linear search through the palette (O(P) where P is palette size) to find existing types or free slots [S1, unofficial]. Palette growth/shrinkage involves O(N) bit operations where N is chunk size [S1, unofficial].
*   **Memory Complexity:** Reduces memory footprint for low-entropy regions (air/stone) to 1-2 bits per block, while supporting thousands of block types [S1, unofficial].
*   **Strengths:** Massively reduces memory footprint of blocks as a whole. A single block ideally takes up one single bit of memory. The common case is three to four bits. This leads to less RAM usage and faster transmission of block groups (chunks) across network connections [S1, unofficial]. Supports practically infinite block types & states as long as not every single block in a block group is completely different from one another [S1, unofficial].
*   **Limitations:** Writing blocks is more expensive than reading due to palette management. Performance degrades if chunk size is too large [S1, unofficial].
*   **When to use:** When discrete voxel data has high spatial coherence (large areas of identical block types) and a need for lossless compression with variable block types [S1, unofficial].
*   **When not to use:** When block types are completely random (high entropy) or when chunk sizes are very large [S1, unofficial].
