# Transform-Aware Sparse Voxel Directed Acyclic Graph (TSVDAG)
Also called: our method

## Overview
TSVDAG is a lossless compression method for sparse voxel data that extends SSVDAG by supporting destructive translations, mirror symmetry, and axis permutations on child pointers to reduce memory usage during compression [S1]. It solves the problem of geometric redundancy in voxelized scenes by allowing subtrees to be reconstructed from other subtrees via similarity transforms, combined with a novel pointer compression scheme using look-up tables and Huffman coding [S1]. Unlike SSVDAG, which only handles symmetry, TSVDAG handles translations and arbitrary axis permutations, achieving 20% to 35% memory improvement over SSVDAG depending on the scene [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A Sparse Voxel Octree (SVO) or a base SVDAG representing a voxel grid at a given resolution (e.g., $64k^3$) [S1].
*   **Output:** A TSVDAG structure consisting of nodes with variable-length pointers, a look-up table (LUT) for pointers, and transformation metadata [S1].

**Data Structures:**
*   **Node Header:** A 16-bit mask at the start of each node. Conceptually represents eight 2-bit integers storing the length of the child pointers, where a length of 0 represents an empty child [S1].
*   **Child Pointer:** Variable-length encoding (16, 32, or 48 bits). The layout is:
    1.  **Transform ID:** Stored in the least-significant bits. Combines a child-reorder transformation identifier (symmetry/permutation) with a 3-bit mask for zero translations along primary axes [S1]. Encoded using Huffman coding [S1].
    2.  **Translation Distances:** For each axis with a non-zero translation, 5 bits are stored in more significant bits than the Transform ID [S1].
    3.  **Memory Address:** The address to which the pointer points [S1].
*   **Look-Up Table (LUT):** Fixed 64-bit entries per SVDAG level [S1].
    *   16-bit pointers always encode a table index.
    *   32-bit pointers reserve 1 bit to indicate if they are a table index or direct pointer.
    *   48-bit pointers are always direct pointers [S1].
*   **Traversal Stacks:**
    *   **Transform Stack:** Stores unique identifiers for child-reordering transformations (symmetry/permutation) for backtracking [S1].
    *   **Translation Stack:** Stores accumulated translation amounts and ray entry/exit distances ($t_{min}$ & $t_{max}$) for levels containing translations (up to $16^3$ levels) [S1].

**Algorithm Steps:**

1.  **Hash Computation for Translation Detection:**
    For each voxel, compute a hash describing the area to the top/right. First compute the hash horizontally, then vertically [S1]. A match between the lower/left voxel of grid B and a voxel in grid A indicates B is constructable from A by a translation of $(-1, -1)$ [S1].

2.  **Transformation Testing:**
    Test for symmetry and permutations by checking matching voxels in different directions. For example, if a voxel in direction $(+x, +y, -z)$ matches a corner voxel in direction $(+x, +y, +z)$, it indicates a transformation by translation and z-axis symmetry [S1]. Similarly, search for permutations of axes [S1].

3.  **Dependency Graph Construction:**
    Build a dependency graph where each subtree stores only a single 'parent' (another subtree that can be transformed into the current one) [S1].
    *   If multiple parents exist, store the one with the highest memory address to encourage clustering [S1].
    *   Sort subtrees by number of occupied voxels to favor destructive translations [S1].
    *   Note: Due to SVDAG encoding limitations, subtrees in complex dependency graphs with multiple levels of indirection must be duplicated [S1].

4.  **Pointer Encoding Setup:**
    *   Sort nodes such that the most referenced ones appear first, ensuring frequently used pointers are shortest [S1].
    *   Assign unique identifiers to child-reorder transformations [S1].

5.  **Look-Up Table Construction:**
    Construct the LUT per SVDAG level using a greedy algorithm [S1]:
    *   Sort pointers by frequency (how often they occur in the parent level) [S1].
    *   Iterate over sorted pointers. Compare the cost of storing directly vs. in the table [S1].
    *   Direct cost: Length in bits (rounded up to 32 or 48) $\times$ occurrences [S1].
    *   Table cost: 64 bits per entry [S1].
    *   Insert into table if cheaper [S1].

6.  **Huffman Coding:**
    Encode the Transform ID using Huffman coding to ensure frequent transformations use fewer bits. Limit Huffman code length to prevent extremely long pointers for rare transforms [S1].

```python
def compute_voxel_hash(voxel_grid, x, y, z):
    """
    Computes a hash for a voxel describing the area to the top/right.
    First horizontally, then vertically.
    """
    # Horizontal hash
    h_hash = hash(voxel_grid[x+1:, y, z]) # Conceptual: hash of row to the right
    # Vertical hash
    v_hash = hash(h_hash, voxel_grid[x+1:, y+1:, z]) # Conceptual: hash of area above/right
    return v_hash

def find_translation_candidates(grid_a, grid_b):
    """
    Finds potential translation relationships between two grids.
    """
    candidates = []
    for x in range(grid_b.width):
        for y in range(grid_b.height):
            for z in range(grid_b.depth):
                hash_b = compute_voxel_hash(grid_b, x, y, z)
                # Check if hash_b matches any voxel in grid_a
                # A match indicates B could be constructed from A by translation (-1, -1)
                if hash_b in grid_a_hashes:
                    candidates.append((x, y, z, -1, -1))
    return candidates

def build_dependency_graph(subtrees):
    """
    Builds a dependency graph where each subtree has a single parent.
    """
    # Sort subtrees by number of occupied voxels to favor destructive translations
    subtrees.sort(key=lambda s: s.occupied_voxel_count, reverse=True)
    
    graph = {}
    for subtree in subtrees:
        parents = find_transform_parents(subtree)
        if parents:
            # Store parent with highest memory address to encourage clustering
            parent = max(parents, key=lambda p: p.memory_address)
            graph[subtree.id] = parent
        else:
            graph[subtree.id] = None # Root or unique subtree
    return graph

def construct_pointer_lut(level_pointers):
    """
    Constructs a look-up table for pointers at a specific level.
    """
    # Sort pointers by frequency
    freq_map = count_frequencies(level_pointers)
    sorted_pointers = sorted(freq_map.items(), key=lambda item: item[1], reverse=True)
    
    lut = {}
    for pointer, count in sorted_pointers:
        # Cost of direct pointer: length rounded to 32 or 48 bits * count
        direct_cost = (round_up_bits(pointer.length) * count)
        # Cost of table pointer: 64 bits per entry
        table_cost = 64
        
        if table_cost < direct_cost:
            lut[pointer] = len(lut) # Assign index
        else:
            lut[pointer] = None # Direct pointer
    
    return lut

def encode_pointer(transform_id, translation, address, lut):
    """
    Encodes a child pointer with variable length.
    """
    # Transform ID is Huffman encoded
    huffman_code = huffman_encode(transform_id)
    
    # Translation distances (5 bits per non-zero axis)
    translation_bits = encode_translation_bits(translation)
    
    # Address
    address_bits = encode_address_bits(address)
    
    # Combine: Transform ID (LSB) -> Translation -> Address (MSB)
    # Determine if pointer is in LUT
    if address in lut:
        index = lut[address]
        # 16-bit pointer always encodes table index
        return encode_16bit_pointer(index, transform_id, translation)
    elif address in lut and is_32bit_optimized(address):
        # 32-bit pointer: 1 bit indicates table index or direct
        return encode_32bit_pointer(index, transform_id, translation, is_table=True)
    else:
        # 48-bit pointer is always direct
        return encode_48bit_pointer(address, transform_id, translation)

def ray_traverse_tsvdag(ray, node, transform_stack, translation_stack):
    """
    Stack-based ray traversal for TSVDAG.
    """
    # Compute intersection points between ray and three primary planes through node center
    intersections = compute_plane_intersections(ray, node.center)
    
    # Create bitmask of intersected children
    intersected_mask = create_intersection_bitmask(intersections, ray.direction)
    
    # Determine traversal order by sign bits of ray direction
    traversal_order = get_traversal_order(intersected_mask, ray.direction)
    
    for child_idx in traversal_order:
        if child_idx is empty:
            continue
            
        # Get child pointer
        pointer = get_child_pointer(node, child_idx)
        
        # Decode pointer
        transform_id, translation, address = decode_pointer(pointer)
        
        # Apply child reordering if transform_id indicates permutation/symmetry
        if transform_id.has_reorder():
            new_transform_stack = transform_stack.copy()
            new_transform_stack.append(transform_id)
            # Apply permutation using GPU constant memory LUT
            transformed_ray = apply_permutation(ray, transform_id)
        else:
            new_transform_stack = transform_stack
            
        # Handle translation
        if translation.is_non_zero():
            new_translation_stack = translation_stack.copy()
            # Accumulate translation and ray entry/exit distances
            new_entry = translate_ray_bounds(ray.tmin, translation)
            new_exit = translate_ray_bounds(ray.tmax, translation)
            new_translation_stack.append({
                'accumulated_translation': translation,
                'tmin': new_entry,
                'tmax': new_exit
            })
            # Translate child node centers and limit intersection bounds
            child_center = translate_vector(node.children[child_idx].center, translation)
            # Remove voxels moved outside subtree bounds
            if not is_within_bounds(child_center, new_entry, new_exit):
                continue
        else:
            new_translation_stack = translation_stack
            
        # Recurse or process leaf
        if node.children[child_idx].is_node():
            ray_traverse_tsvdag(transformed_ray, node.children[child_idx], new_transform_stack, new_translation_stack)
        else:
            process_leaf(transformed_ray, node.children[child_idx], new_translation_stack)
```

**Parameters:**
*   **Translation Mask:** 3-bit mask indicating 0 translation along each of the primary axes, combined with child-reorder transformation identifier [S1].
*   **Pointer Sizes:** 16-bit, 32-bit, or 48-bit variable-length pointers [S1].
*   **Look-Up Table Entry Size:** Fixed 64 bits [S1].
*   **Base Pointer Encoding:** Uses a 48-bit pointer space [S1].
*   **Translation Storage:** Requires 5 bits per axis plus a Transform ID [S1].

**Edge Cases and Pitfalls:**
*   **Complex Dependency Graphs:** Destructive translations can create complex dependency graphs with multiple levels of indirection. Due to SVDAG encoding limitations, subtrees in these cases must be duplicated [S1].
*   **Variable-Length Pointer Inefficiency:** Variable-length pointer encoding indexes the address space at 16-bit intervals, leaving many memory indices unreferenced. This reduces the effectiveness of compact 16-bit and 32-bit encodings [S1].
*   **Render Overhead:** Variable-length pointers cause render overhead because the GPU memory system is not optimized for efficient reads of variable-length data [S1].
*   **Registry Pressure:** Translations require maintaining an additional short traversal stack, which increases registry pressure or causes registry spilling on the GPU [S1].
*   **Search Cost:** Finding translation transformations is computationally expensive due to a very large search space [S1].

## Operating characteristics
*   **Time Complexity:** Finding translation transformations is computationally expensive due to a very large search space, taking a couple of hours for a $64k^3$ scene on the CPU [S1]. Hierarchical search for mirror symmetry and axis permutations is faster, typically less than a minute [S1].
*   **Memory Complexity:** TSVDAG achieves significantly lower memory usage than SVO, SVDAG, and SSVDAG. SVO memory usage is 516% to 1456% larger than TSVDAG across tested scenes (Bistro, Bunny, Crown, Citadel, Lucy, Dragon at $64k^3$) [S1]. A dense voxel grid for these scenes would require 35TB of memory [S1].
*   **Measured Performance:**
    *   Render performance was measured on an NVIDIA RTX4070 GPU [S1].
    *   Rendering benchmark uses 1080p path-traced images with up to four random bounces, lit by a constant environment light without next-event estimation [S1].
    *   SVDAG with fixed 32-bit pointer encoding outperforms variable pointer length methods in render time by approximately 10% [S1].
    *   Enabling pointer look-up tables and Huffman coding increases frame time by approximately 12% compared to disabling them [S1].
    *   Adding translation transformations increases frame time by approximately 30% [S1].
*   **Scaling:** The method scales with scene complexity and resolution. The compression ratio improves with larger scenes containing more repetitive structures.
*   **Strengths:** High compression ratio, lossless, supports various transformations (symmetry, permutation, translation).
*   **Limitations:** High computational cost for building the structure (especially translations), increased render overhead due to variable-length pointers and stack management, GPU registry pressure.
*   **When to use:** When memory footprint is critical and the scene contains significant geometric redundancy including translations and permutations.
*   **When not to use:** When render performance is the primary concern and the scene has low redundancy, or when hardware does not support efficient variable-length pointer access.

## Background
TSVDAG was introduced in the paper "Transform-Aware Sparse Voxel Directed Acyclic Graphs" [S1]. It builds on the SVDAG [Kämpe et al. 2013] and SSVDAG [Villanueva et al. 2016] methods. The work was partially supported by TKI HTSM PGT 2019 CREW [S1]. The method was evaluated on scenes like Bistro, Bunny, Crown, Citadel, Lucy, and Dragon at $64k^3$ resolution [S1].
