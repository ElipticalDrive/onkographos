# Mixture Graph

Also called: Mixture Graph representation

## Overview
The Mixture Graph is a data structure for compressing, rendering, and querying segmentation histograms derived from volumetric segment ID data [S1]. It solves the problem of efficiently handling the high dimensionality and storage requirements of hierarchical histograms by factorizing normalized mixture vectors into a directed acyclic graph (DAG) of linear interpolations [S1]. Unlike traditional paletted textures where the palette is static, the Mixture Graph’s palette stores mixtures of multiple colors and is updated efficiently in parallel, allowing for pre-filtered anti-aliasing and interactive rendering [S1].

## How it works
The method operates in three main phases: construction of a normalized histogram mipmap, factorization of the mipmap into a DAG, and compression/quantization of the DAG [S1].

### Inputs and Outputs
*   **Input:** A volume of segment IDs $S: D \rightarrow \mathbb{N}_0$ over a discrete domain $D \subseteq \mathbb{N}_0^3$, and a transfer function mapping segment IDs to RGB$\alpha$ colors [S1].
*   **Output:** A compressed binary representation of the Mixture Graph stored in GPU Shader Storage Buffer Objects (SSBOs), and a decoded color lookup table [S1].

### Data Structures
The binary representation consists of the following components [S1]:
1.  **Voxel Data:** One mixture ID per voxel, stored in an SSBO [S1].
2.  **Mixture Descriptions:** Node weights and standard deviations stored in an SSBO [S1].
3.  **Quantizer Codebook:** Scalar quantizer codebook stored in an SSBO [S1].
4.  **Index Structures:** Node offsets and bit allocation counts stored as shader uniform constants [S1].
5.  **Color Lookup Table:** A separate SSBO holding one `vec4` color entry per node [S1].

### Algorithm Steps

#### 1. Normalized Histogram Mipmap Construction
Construct a hierarchical segmentation histogram $H: D \times \{0, \dots, l_{max}\} \rightarrow \mathcal{M}$, where $\mathcal{M}$ is the set of mixtures [S1]. A mixture $m \in \mathbb{R}^\infty$ satisfies $\|m\|_1 = 1$, $[m]_n \ge 0$, and $\|m\|_0 < \infty$ [S1].

1.  **Level 0:** For each voxel $(i,j,k) \in D$, set $H(i,j,k,0) = e_{S(i,j,k)}$, where $e_b$ is the unit vector with 1 at index $b$ and 0 elsewhere [S1].
2.  **Higher Levels ($l > 0$):** For each voxel $(i,j,k)$ at level $l$, compute the mixture by averaging the mixtures from its 8 children at level $l-1$:
    $$ H(i,j,k,l) = \frac{1}{N} \sum_{u=2i}^{2i+1} \sum_{v=2j}^{2j+1} \sum_{w=2k}^{2k+1} H(u,v,w,l-1) $$
    where $N$ is the number of voxels in the support (typically 8, but adjusted for borders or non-power-of-two resolutions) [S1].
3.  **Termination:** Continue until level $l_{max}$ where the resolution is $1^3$ [S1].

#### 2. DAG Factorization
Factorize the histogram mipmap into a DAG where each node represents a linear interpolation (mixture) of two predecessor nodes or source segments [S1].

1.  **Embedding:** Embed mixtures in $\mathbb{R}^\infty$ [S1].
2.  **Greedy Factorization:** Iteratively select two non-zero positions in the mixture vector $m$, create a new linear interpolation $\lambda$, and update $m$ by subtracting the contribution of $\lambda$ [S1]. This process is repeated until $m$ is fully represented by the list of interpolations $\Lambda$ [S1].
3.  **Graph Construction:** The resulting DAG nodes are topologically ordered [S1].

#### 3. Quantization and Compression
1.  **Scalar Quantization:** Apply scalar quantization to the interpolation weights to prune redundant nodes. Nodes with identical quantized weights are merged [S1].
2.  **Error Storage:** Store quantization errors for each bin to estimate reconstruction error for approximate queries [S1].
3.  **Compression:** Compress the pruned DAG at a fixed bitrate [S1].

#### 4. Rendering and Querying
1.  **Upload:** Upload the binary representation to GPU SSBOs [S1].
2.  **Color Lookup Update:** Use a compute shader to update the color lookup table based on the transfer function. Traverse nodes in topological order, gather two colors, and linearly interpolate using the quantized weight [S1].
3.  **Ray Marching:** For each voxel, retrieve the node ID from the raw data buffer. Compute the mip level manually in the shader based on pixel coverage and viewspace depth $z$ [S1].
4.  **LOD Bias:** Use a uniform shader constant `LOD bias` to adjust the level of detail calculation [S1].
5.  **Range Queries:** For sub-volume queries, assemble histogram contributions across the footprint of the volume using a lookup table built on the CPU. The lookup table stores expected value $\mu$ and variance $\delta\mu$ as sparse vectors for each node [S1].

### Pseudocode

```python
def build_mipmap(segment_ids, domain_dims):
    # segment_ids: list of integers representing segment IDs per voxel at level 0
    # domain_dims: tuple (Dx, Dy, Dz)
    levels = []
    # Level 0: unit vectors e_{S(i,j,k)}
    max_id = max(segment_ids) + 1
    level_0 = [[1.0 if sid == i else 0.0 for i in range(max_id)] for sid in segment_ids]
    levels.append(level_0)

    current_level = level_0
    for l in range(1, 30):
        dim_l = tuple(max(1, (d + (1 << l) - 1) // (1 << l)) for d in domain_dims)
        if dim_l == (1, 1, 1):
            break
        next_level = []
        for i in range(dim_l[0]):
            for j in range(dim_l[1]):
                for k in range(dim_l[2]):
                    children = []
                    for u in range(2*i, 2*i+2):
                        for v in range(2*j, 2*j+2):
                            for w in range(2*k, 2*k+2):
                                if u < len(current_level) and v < len(current_level[0]) and w < len(current_level[0][0]):
                                    children.append(current_level[u][v][w])
                    N = len(children)
                    mixture = [sum(c[idx] for c in children) / N for idx in range(max_id)]
                    next_level.append(mixture)
        levels.append(next_level)
        current_level = next_level
    return levels

def factorize_mixture(mixture_vector):
    nodes = []
    current_m = mixture_vector.copy()
    while sum(current_m) > 1e-9:
        indices = [i for i, v in enumerate(current_m) if v > 1e-9]
        if len(indices) < 2:
            break
        i, j = indices[0], indices[1]
        w = current_m[i] + current_m[j]
        nodes.append((i, j, w))
        current_m[i] = 0.0
        current_m[j] = 0.0
    return nodes

def render_voxel(voxel_id, node_offsets, bit_allocations, color_lut):
    # Retrieve node ID from raw data buffer using bit addressing
    node_id = (voxel_id >> node_offsets) & ((1 << bit_allocations) - 1)
    # Retrieve predecessors and quantized weight from DAG node data
    pred1, pred2, weight = node_data[node_id]
    # Interpolate colors
    color1 = color_lut[pred1]
    color2 = color_lut[pred2]
    final_color = tuple(c1 * (1 - weight) + c2 * weight for c1, c2 in zip(color1, color2))
    return final_color
```

### Parameters
*   **LOD Bias:** Uniform shader constant used to adjust the level of detail calculation based on pixel coverage in viewspace depth $z$ [S1].
*   **Quantization Bits:** Controls the trade-off between compression ratio and reconstruction error. Each reduction by one bit roughly doubles the reconstruction error [S1].

### Edge Cases and Pitfalls
*   **Non-power-of-two Resolution:** If input resolution is not power-of-two, the resolution of subsequent levels is rounded up, and summation limits and $N$ in the mipmap equation are adjusted accordingly [S1].
*   **Bit Addressing:** Address computations must be performed in the shader because the binary representation is accessed based on bit addresses, requiring the `uint64` data type provided by the GPU shader extension [S1].
*   **Precision:** Lower bitrates in scalar quantization lead to higher ambiguities between nodes and fewer nodes, but increase reconstruction error [S1].

## Subtopics

### Normalized Histogram Mipmap
A hierarchical segmentation histogram $H$ constructed from a volume of segment IDs $S$ [S1]. It stores mixtures (convex combinations of segment IDs) at multiple resolution levels [S1]. It uses the traditional average-of-eight mipmap filter, but other low-pass filters can be used if they can be normalized to a mixture [S1].

### Mixture Lookup Table for Range Queries
A lookup table assembled on the CPU for range queries [S1]. Each node stores two sparse vectors over $\mathbb{R}^\infty$: the expected value $\mu$ and its variance $\delta\mu$ [S1]. Build time depends on the number of nodes, topological depth, initial number of segments, and number of non-zero entries [S1]. For example, the Neocortex lookup table size is around 251MB [S1].

## Operating characteristics
*   **Performance:** Achieves up to 178x speed-up over naive parallelized range queries for partial histogram queries [S1].
*   **Memory:** The Neocortex dataset (2048 × 2048 × 300) results in a lookup table of 251MB [S1].
*   **Build Time:** Mixture lookup table build times are 68ms for Hippocampus, 389ms for Neocortex, and 171ms for Polymer [S1].
*   **Strengths:** Enables pre-filtered anti-aliasing, efficient transfer function propagation, and interactive frame rates [S1]. Supports fast, approximate queries of partial histograms [S1].
*   **Limitations:** Requires manual computation of mip level and interpolation in the shader [S1]. Address computations require `uint64` support [S1]. Unlike sparse coding which uses orthogonal matching pursuit optimization, the Mixture Graph performs a greedy factorization of the computations necessary to compute a palette [S1].

## Background
The Mixture Graph was introduced in a paper published in IEEE Transactions on Visualization and Computer Graphics (IEEE Vis 2020) [S1]. It addresses challenges in rendering and querying segmented volumes by treating the histogram mipmap as a set of linear interpolations that can be compressed efficiently [S1].
