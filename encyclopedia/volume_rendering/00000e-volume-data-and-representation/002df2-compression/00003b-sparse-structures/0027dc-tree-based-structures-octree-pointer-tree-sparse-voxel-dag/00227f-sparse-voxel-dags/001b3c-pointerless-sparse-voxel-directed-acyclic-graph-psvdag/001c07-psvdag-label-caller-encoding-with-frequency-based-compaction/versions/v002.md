# PSVDAG Label/Caller Encoding with Frequency-Based Compaction

Also called: Level-wise label assignment, frequency-sorted caller encoding

## Overview
This method replaces the fixed 32-bit child node pointers used in Sparse Voxel Directed Acyclic Graphs (SVDAG) with variable-length binary labels (callers) to enable pointerless traversal while minimizing memory footprint [S1]. It sets itself apart from standard SVDAG by achieving significant compression (up to 5.33-fold) through frequency-based sorting and level-wise label space reset, at the cost of requiring label reconstruction during traversal [S1].

## How it works
**Inputs:** A PSVDAG structure where nodes are organized into levels, and each Inner Node (INODE) references child subgraph roots from the previous level [S1].
**Outputs:** A compacted representation where child references are encoded as variable-length binary labels [S1].

**Data Structures:**
*   **Label Table (per level):** A mapping from subgraph root node identifiers to binary codes [S1].
*   **Binary Code:** Variable-length bit sequence with a minimum length of 6 bits [S1].

**Steps:**
1.  **Collect References:** For each graph level $l$, identify all unique subgraph root nodes referenced by nodes at level $l-1$ [S1].
2.  **Count Frequency:** Count the number of times each unique subgraph root node is referenced from level $l-1$ [S1].
3.  **Sort Nodes:** Sort the unique subgraph root nodes in descending order of their frequency [S1].
4.  **Assign Labels:** Assign binary labels to the sorted nodes [S1].
    *   The most frequent node receives the shortest label [S1].
    *   The minimum label length is 6 bits [S1].
    *   Subsequent nodes receive longer labels as needed to maintain unique codes [S1].
    *   The length increases gradually with the number of unique labels/callers at that level [S1].
5.  **Reset Label Space:** Repeat steps 1–4 independently for each graph level [S1]. This resets the label assignment, ensuring that the most frequent nodes at every level get the shortest 6-bit codes rather than competing for short codes globally [S1].

**Formulas:**
*   **Compression Ratio:** The shortest labels achieve a 5.33-fold compression rate compared to 32-bit pointers [S1].
    $$ \text{Compression Ratio} = \frac{32 \text{ bits}}{6 \text{ bits}} \approx 5.33 $$
*   **Space Occupancy:** The shortest labels occupy 18.75% of the space of a 32-bit pointer [S1].
    $$ \text{Space Occupancy} = \frac{6}{32} = 0.1875 = 18.75\% $$

**Parameters:**
*   **Minimum Label Length:** 6 bits [S1].
*   **SVDAG Pointer Size:** 32 bits [S1].

**Edge Cases and Pitfalls:**
*   **Unique Subgraphs:** If a subgraph is unique, the SVDAG pointer is 32 bits, but in PSVDAG it becomes 0 bits at its root node [S1]. However, references to it from other levels still require a valid label/caller with at least 6 bits [S1].
*   **Precision and Range:** The binary representation length ranges from 6 bits to 16 bits depending on the number of unique nodes per level [S1]. Auxiliary fields (ACHNC and CHNM) sum to 5–19 bits, which is significantly less than SVDAG's fixed overhead [S1].
*   **Level-wise Reset:** Failing to reset the label space per level would force a global frequency count, potentially assigning long codes to frequently occurring nodes at deeper levels if they are less frequent globally [S1].

**Pseudocode:**
```python
def encode_labels_per_level(level_nodes, previous_level_references):
    """
    Encodes child references for a specific level using frequency-based compaction.
    
    Args:
        level_nodes: List of nodes at the current level.
        previous_level_references: List of subgraph root node IDs referenced by level_nodes.
        
    Returns:
        label_map: Dictionary mapping node_id to binary string.
    """
    # Step 1 & 2: Count frequency of each referenced subgraph root
    frequency_map = {}
    for ref_id in previous_level_references:
        frequency_map[ref_id] = frequency_map.get(ref_id, 0) + 1
        
    # Step 3: Sort nodes by frequency (descending)
    sorted_nodes = sorted(frequency_map.keys(), key=lambda x: frequency_map[x], reverse=True)
    
    # Step 4: Assign binary labels
    label_map = {}
    current_length = 6  # Minimum label length per evidence
    index = 0
    
    for node_id in sorted_nodes:
        # Assign current index as binary code with current_length bits
        label_map[node_id] = format(index, f'0{current_length}b')
        index += 1
        
        # Increase bit length when the current length can no longer uniquely represent the next index
        if index >= (1 << current_length):
            current_length += 1
            
    return label_map
```

## Operating characteristics
*   **Time Complexity:** Encoding requires sorting nodes by frequency per level, which is $O(N \log N)$ where $N$ is the number of unique references per level [G]. Traversal requires label reconstruction, adding overhead compared to direct pointer dereferencing [S1].
*   **Memory Complexity:** Significantly reduced compared to SVDAG [S1]. The average label/caller size ranges from 0.625 to 2.375 bits per child node, depending on the scene and resolution [S1].
*   **Measured Performance:** On the tested scenes, the compression ratio ranges from 1.68 to 6.4 compared to SVDAG [S1]. The reduction in data structure size is between 15.63% and 59.38% [S1].
*   **Strengths:** High compression ratio for scenes with frequent subgraph reuse; pointerless traversal enables efficient streaming/archival [S1].
*   **Limitations:** Requires label reconstruction during traversal, which may be slower than direct pointer access; performance depends on the frequency distribution of subgraphs [S1].
*   **When to Use:** Ideal for archival, streaming, or memory-constrained environments where subgraph reuse is high [S1].
*   **When Not to Use:** When fast, direct traversal is critical and memory is not a constraint, SVDAG may be preferable [S1].

## Background
The PSVDAG structure builds on the advantages of both Pointerless SVO and SVDAG, aiming to provide a compact encoding suitable for 3D scene representation [S1]. The method addresses the need for efficient storage and traversal in voxelized 3D scenes [S1].
