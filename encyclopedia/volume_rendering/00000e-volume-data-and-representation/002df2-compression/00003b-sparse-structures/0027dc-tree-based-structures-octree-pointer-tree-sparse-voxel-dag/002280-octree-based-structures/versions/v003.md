# Octree-based structures
## Overview
[G] Octree-based structures organize sparse volumetric data into a hierarchical tree where each node has eight children, enabling efficient storage and traversal of large datasets with significant empty space. [G] This family differs from sibling tree-based structures by its fixed 8-way branching factor and specific implementation strategies for memory layout (implicit vs. explicit) and topology (shallow fixed-depth vs. deep variable-depth). [G] Unlike [Sparse Voxel DAGs](2791-sparse-voxel-dags.md) which merge identical nodes to save space, or [Compact pointer trees](844-compact-pointer-tree.md) which use pointer compression, octrees typically rely on Morton ordering or fixed bit-masks for navigation.

## Shared principles
[G] All octree-based structures share the fundamental property of recursive spatial subdivision. [G] The 3D domain is divided into a bounding box, which is recursively split into eight octants until a stopping criterion (such as uniform data density or maximum depth) is met.
1. [G] **Morton Ordering (Z-order curve):** Many implementations, particularly implicit ones, map 3D coordinates $(x, y, z)$ to a 1D integer key using Morton codes. [G] This preserves spatial locality, allowing linear arrays to represent tree structures and enabling efficient neighbor lookups and range queries.
2. [G] **Sparsity Handling:** Empty or uniform regions are represented by a single node (or null pointer in implicit structures) rather than storing individual voxel values, providing compression ratios proportional to the sparsity of the data.
3. [G] **Traversal:** Accessing data requires traversing from the root to the leaf. [G] The complexity is $O(\log N)$ for deep trees or $O(1)$ for shallow trees with direct indexing, where $N$ is the resolution.

## Subtopics

### [Implicit Octree Storage](939-implicit-octree-storage.md)
[G] Stores the octree hierarchy and data in a linear array or hash map using Morton keys, avoiding explicit node objects and parent pointers. [G] Sets it apart by prioritizing compact storage and cache-friendly linear access over random-access speed. [G] Choose when memory overhead of node objects is prohibitive or when streaming and persistent storage are required.

### [Implicit Octree Traversal](1220-implicit-octree-traversal.md)
[G] Constructs sparse octrees from distance fields to facilitate isosurface extraction, specifically targeting dual contouring or marching cubes on sparse data. [G] Sets it apart by defining traversal algorithms to build the primal vertex map and locate dual vertices for mesh generation, rather than focusing on storage layout. [G] Choose when generating meshes from distance fields on sparse data without storing explicit parent pointers.

### [OpenVDB (VDB)](1508-openvdb-vdb.md)
[G] A sparse voxel representation used for the hierarchical encoding and compression of volumetric grids, featuring fast $O(1)$ random access for modification and retrieval operations. [G] Sets it apart by its specific four-level topology and 64-bit direct access bit masks that encode topology and data pointers. [G] Choose for production visual effects and scientific visualization requiring efficient modification and retrieval of large sparse datasets.

### [Time-Variant Volume Rendering with Octrees](2232-time-variant-volume-rendering-with-octrees.md)
[G] Rendering technique for time-variant volumes using octree compression to fit multiple timesteps into main memory, overcoming GPU memory and bus bandwidth limitations. [G] Sets it apart by compressing multiple timesteps into a single structure to keep large animated sequences in-core. [G] Choose when rendering large volumetric sequences on commodity hardware where VRAM is insufficient.

### [Domain-based Octree with Range Bounding Boxes](2806-domain-based-octree-with-range-bounding-boxes.md)
[G] An acceleration structure using an octree over the domain to store interval ranges (RBBs) at each node, allowing filtering of tetrahedra that cannot intersect a given FSCP edge by comparing the edge against the node's RBB. [G] Sets it apart by its domain-focused spatial filtering for tetrahedral meshes. [G] Choose for ray tracing against tetrahedral volumes requiring efficient edge intersection culling.

### [Tree64](3486-tree64.md)
[G] A sparse voxel tree with a 4³ branching factor, also known as a contree. [G] Sets it apart by its quaternary branching structure instead of the standard octal split. [G] Choose when a reduced branching factor is preferred for specific memory or traversal characteristics.

### Dynamic Adaptive Octree Grid (DAOG)
[S1, unofficial] A voxel representation structure that offers significant memory savings compared to Regular Grid and standard Octree, allowing representation of large surfaces with little space. [S1, unofficial] For a 1024x1024x1024 Cornell Box model: Regular Grid uses 1048576 KB, Octree uses 158087 KB, DAOG uses 269 KB. [S1, unofficial] For a 1024x1024x1024 Batman model: Regular Grid uses 1048576 KB, Octree uses 106303 KB, DAOG uses 813 KB. [S1, unofficial] Construction time for 1024x1024x1024 Cornell Box: Octree takes 5.153s, DAOG takes 67.680s, DAOG serialized takes 0.142ms.

## Background
[G] The concept of octrees for volume representation dates back to the early days of 3D computer graphics, with foundational work by Meagher (1982) and others. [S1, unofficial] The Dynamic Adaptive Octree Grid (DAOG) is a variant discussed in academic studies on compression efficiency, highlighting extreme memory savings for specific surface representations.
