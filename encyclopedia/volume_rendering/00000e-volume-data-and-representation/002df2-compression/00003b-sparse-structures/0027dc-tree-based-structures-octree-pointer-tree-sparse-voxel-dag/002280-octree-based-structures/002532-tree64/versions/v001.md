# Tree64

Also called: contree, wide 4³ trees

## Overview
Tree64 is a sparse voxel tree data structure with a 4³ (64-way) branching factor, designed to reduce tree depth and per-voxel overhead compared to standard octrees [S1, unofficial]. It achieves higher ray traversal throughput by utilizing compact node layouts and optimized GPU traversal strategies, making it suitable for real-time ray tracing of large voxel scenes [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A sparse voxel dataset (e.g., Eco House 2k, Bistro 4k, Forest Lake 2k) with resolution typically in the range of hundreds of thousands to millions of 8³ voxel chunks [S1, unofficial].
- Output: A Tree64 structure optimized for ray traversal, producing rendered images with primary and diffuse bounce rays [S1, unofficial].

**Data Structures:**
- **Node Layout:** Each node has a fixed memory cost of 12 bytes [S1, unofficial].
- **Address Field:** The address field packs node type information and pointers [S1, unofficial].
- **Pointer Encoding:** Relative pointers are "backwards" (parent nodes appear after children in memory) to allow building without intermediate buffers. Far pointers are signaled by a reserved upper range rather than a dedicated bit [S1, unofficial].
- **Chunk Hierarchy:** Uses a traditional chunk hierarchy for bookkeeping [S1, unofficial].

**Traversal Algorithm:**
1. **Initialization:** Mirror the coordinate system to the negative ray octant to simplify intersection calculations and node bounds clamping [S1, unofficial].
2. **Stack Management:** Use group-shared memory for the ancestor node stack to reduce latency [S1, unofficial].
3. **Ray Marching:** Perform ray marching using bitmasks for longer steps, which reduces divergence compared to recursive DDA [S1, unofficial].
4. **Node Access:** Traverse the tree using the encoded pointers. The shallow depth (due to 4³ branching) reduces the number of iterations per ray [S1, unofficial].

**Pseudocode:**
```python
def traverse_tree64(ray_origin, ray_direction, root_node):
    # Mirror coordinates to negative ray octant for simplified bounds
    mirrored_origin = mirror_to_negative_octant(ray_origin)
    mirrored_direction = mirror_to_negative_octant(ray_direction)
    
    # Initialize stack in group-shared memory
    stack = GroupSharedStack()
    stack.push(root_node)
    
    while not stack.is_empty():
        node = stack.pop()
        
        # Check if node is a leaf or contains data
        if node.is_leaf():
            # Sample voxel data
            color = sample_voxel(node.data, mirrored_origin, mirrored_direction)
            return color
        
        # Use bitmasks to determine which children to traverse
        children_mask = node.get_children_mask(mirrored_origin, mirrored_direction)
        
        # Push children to stack in reverse order for correct traversal
        for child_index in reversed(range(64)):
            if (children_mask >> child_index) & 1:
                child_ptr = node.get_child_pointer(child_index)
                # Handle far pointers via reserved upper range
                if is_far_pointer(child_ptr):
                    child_ptr = resolve_far_pointer(child_ptr)
                stack.push(child_ptr)
                
    return background_color
```

**Parameters:**
- **Branching Factor:** 4³ (64 children per node) [S1, unofficial].
- **Node Size:** 12 bytes [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Editing Cost:** Trees within each chunk are fully rebuilt upon changes, leading to an editing cost of approximately O(log m) due to path copying [S1, unofficial].
- **Memory Bandwidth:** Performance may be limited by memory bandwidth if nodes are very small and localized [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- **Editing Cost:** O(log m) due to path copying [S1, unofficial].
- **Traversal Complexity:** Reduced iterations per ray due to shallower tree depth [S1, unofficial].

**Measured Performance:**
- **Eco House 2k (448k * 8³ voxels):**
  - Primary rays: 107.5 Mrays/s [S1, unofficial].
  - Primary + 1 diffuse bounce: 93.9 Mrays/s (0.87x ratio) [S1, unofficial].
  - Iterations/ray: 26.8 [S1, unofficial].
  - Clocks/iter: 231.1 [S1, unofficial].
- **Bistro 4k (975k * 8³ voxels):**
  - Primary rays: 109.7 Mrays/s [S1, unofficial].
  - Primary + 1 diffuse bounce: 92.6 Mrays/s (0.84x ratio) [S1, unofficial].
  - Iterations/ray: 30.9 [S1, unofficial].
  - Clocks/iter: 193.3 [S1, unofficial].
- **Forest Lake 2k (807k * 8³ voxels):**
  - Primary rays: 112.1 Mrays/s [S1, unofficial].
  - Primary + 1 diffuse bounce: 99.5 Mrays/s (0.89x ratio) [S1, unofficial].
  - Iterations/ray: 28.8 [S1, unofficial].
  - Clocks/iter: 205.7 [S1, unofficial].

**Strengths and Limitations:**
- **Strengths:** Shallower trees, lower overhead per voxel, high throughput for coherent rays, efficient GPU traversal with shared memory [S1, unofficial].
- **Limitations:** Full tree rebuilds on edits, potential memory bandwidth bottlenecks, high CPU sync times in some scenarios [S1, unofficial].

**When to Use:**
- Real-time ray tracing of large, sparse voxel scenes where traversal performance is critical [S1, unofficial].

**When Not to Use:**
- Scenes requiring frequent dynamic updates where editing cost is a concern [S1, unofficial].
- Environments with severe memory bandwidth constraints [S1, unofficial].

## Background
Tree64 was introduced as part of the VoxelRT project, an unofficial implementation focused on high-performance voxel rendering [S1, unofficial]. It builds on the concept of wide 4³ trees to improve upon standard octree traversal performance [S1, unofficial]. The method was evaluated against other sparse voxel structures like ESVO and BrickMap on various test scenes [S1, unofficial].
