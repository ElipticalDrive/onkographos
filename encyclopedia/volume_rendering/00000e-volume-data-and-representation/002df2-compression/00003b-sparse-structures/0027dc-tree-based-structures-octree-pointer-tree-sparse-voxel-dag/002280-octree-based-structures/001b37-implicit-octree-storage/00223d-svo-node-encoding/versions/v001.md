# SVO Node Encoding

Also called: Octree Node Encoding, SVO Binary Format, SVO file format, SVO node structure, Sparse Voxel Octree (SVO) Binary Format, octree layout, raw_val format

## Overview
SVO Node Encoding is a compact binary serialization format for Sparse Voxel Octrees (SVO) that stores both structural topology and leaf attributes within a single 32-bit integer per node. It solves the problem of efficiently storing sparse 3D volumetric data by using a contiguous array of `uint32_t` values where the Most Significant Bit (MSB) distinguishes between internal pointers and leaf data. It differs from explicit pointer trees by eliminating separate child pointer arrays, and from attribute-only encodings by embedding the address offset directly in the node value.

## How it works
**Inputs:** A Sparse Voxel Octree structure with leaf values (e.g., color, density) and internal node relationships.
**Outputs:** A binary file containing a header followed by a contiguous array of `uint32_t` values representing the octree.

**Data Structures:**
The file consists of a header followed by the octree data.
1.  **Header:** A sequence of `uint32_t` fields:
    *   `version`: Expected value `0x01`.
    *   `volume_size.x`, `volume_size.y`, `volume_size.z`: Dimensions of the bounding volume.
    *   `octree_resolution`: The depth of the octree.
    *   `octree_bytesize`: Total byte count of the octree array.
2.  **Octree Array:** A contiguous sequence of `uint32_t` entries. The array is organized by levels, where each level contains 8 entries per node from the previous level (conceptually), but stored linearly.

**Node Encoding Layout:**
Each `uint32_t` node entry uses the MSB (bit 31) as a type flag.
*   **Internal Node (Parent):** MSB is `1`. The remaining 31 bits store the index (offset) of the first child node in the octree array.
*   **Leaf Node:** MSB is `0`. The remaining 31 bits store the leaf's attribute value. For color, this is packed as 7 bits Alpha, 8 bits Blue, 8 bits Green, 8 bits Red (ABGR).
*   **Null/Empty Node:** Value is `0`. Indicates no children and no data.

**Formulas:**
Let $V$ be the 32-bit node value.
*   If $V == 0$: Null node.
*   If $(V \gg 31) \& 1 == 1$: Internal node. Child index $I = V \& 0x7FFFFFFF$.
*   If $(V \gg 31) \& 1 == 0$: Leaf node. Value $L = V \& 0x7FFFFFFF$.

**Pseudocode:**
```python
def encode_node(is_internal, child_index_or_value):
    """
    Encodes a single SVO node into a uint32_t.
    :param is_internal: Boolean, True if node has children, False if leaf.
    :param child_index_or_value: Integer. If internal, the index of the first child in the octree array.
                                 If leaf, the packed attribute value (e.g., ABGR color).
    :return: uint32_t encoded node.
    """
    if is_internal:
        # MSB set to 1, remaining 31 bits store child index
        return (1 << 31) | (child_index_or_value & 0x7FFFFFFF)
    else:
        # MSB set to 0, remaining 31 bits store leaf value
        return child_index_or_value & 0x7FFFFFFF

def decode_node(node_value):
    """
    Decodes a single SVO node from a uint32_t.
    :param node_value: uint32_t encoded node.
    :return: Tuple (node_type, data).
             node_type: 'null', 'internal', 'leaf'
             data: Child index (if internal) or attribute value (if leaf).
    """
    if node_value == 0:
        return ('null', 0)
    
    msb = (node_value >> 31) & 1
    data = node_value & 0x7FFFFFFF
    
    if msb == 1:
        return ('internal', data)
    else:
        return ('leaf', data)

def write_svo_file(header, octree_nodes, output_path):
    """
    Writes the SVO binary file.
    :param header: Dict with keys 'version', 'volume_size', 'octree_resolution', 'octree_bytesize'.
    :param octree_nodes: List of uint32_t values representing the octree.
    :param output_path: String path to the output file.
    """
    import struct
    
    with open(output_path, 'wb') as f:
        # Write header
        # version (uint32_t)
        f.write(struct.pack('<I', header['version']))
        # volume_size.x, y, z (uint32_t)
        f.write(struct.pack('<III', header['volume_size']['x'], header['volume_size']['y'], header['volume_size']['z']))
        # octree_resolution (uint32_t)
        f.write(struct.pack('<I', header['octree_resolution']))
        # octree_bytesize (uint32_t)
        f.write(struct.pack('<I', header['octree_bytesize']))
        
        # Write octree data
        # Each node is a little-endian uint32_t
        for node in octree_nodes:
            f.write(struct.pack('<I', node))
```

**Edge Cases and Pitfalls:**
*   **Null Nodes:** A value of `0` is reserved for null nodes. Ensure that valid leaf values or child indices never result in `0` unless explicitly intended as null.
*   **Endianness:** The format specifies little-endian byte order. Implementations must handle byte swapping if reading/writing on big-endian systems.
*   **Index Bounds:** The child index stored in internal nodes must be a valid offset within the octree array. Out-of-bounds indices will cause memory access violations.
*   **Color Packing:** The leaf value for color uses 7 bits for alpha. Ensure alpha values are scaled to 0-127 range before packing.

## Subtopics

### [Block Writer for SVO Serialization](2741-block-writer-for-svo-serialization.md)
A class to write SVO nodes to a binary file, tracking byte count and element count. It abstracts the low-level file I/O and header management, ensuring that the `octree_bytesize` in the header accurately reflects the number of bytes written. It typically buffers nodes and writes them in chunks to optimize I/O performance.

## Operating characteristics
*   **Time Complexity:** Encoding/Decoding is $O(1)$ per node. Writing the entire structure is $O(N)$ where $N$ is the number of nodes.
*   **Memory Complexity:** The format stores one `uint32_t` per node. This is highly compact compared to explicit pointer trees which require separate arrays for children.
*   **Performance:** Efficient for random access if the entire file is memory-mapped. Sequential access is also efficient due to contiguous storage.
*   **Strengths:** Simple binary format, no external dependencies for parsing, compact storage.
*   **Limitations:** Fixed 32-bit node size limits the maximum octree depth and addressable space. Not suitable for very large octrees that exceed $2^{31}$ nodes.

## Background
The SVO Node Encoding format is described in the `loryruta/voxelizer` repository [S1, unofficial]. It is used in voxelization pipelines to store the resulting sparse voxel octree for efficient rendering or further processing. The format is designed for simplicity and ease of integration into C++ projects using CMake.
