# Hierarchical Partition Optimization

Also called: Bottom-up Lagrangian optimization, Dynamic programming for hierarchical partitions, Offline optimization setup, Preprocessing Algorithm

## Overview
Hierarchical Partition Optimization (HPO) is an offline preprocessing method that constructs an optimal adaptive-resolution octree and assigns extraction algorithms to its nodes, balancing memory consumption against expected extraction time. It solves the problem of finding a partition that minimizes a global Lagrangian cost function under a memory constraint. It sets itself apart from sibling methods like [Min/Max Tree Construction](1623-min-max-tree-construction.md) by explicitly optimizing the trade-off between storage size and computational cost via dynamic programming, rather than solely focusing on geometric homogeneity or structural compactness.

## How it works
**Inputs and Outputs**
- **Input:** A 3D scalar volume dataset; a set of $m$ candidate extraction methods (algorithms); a minimal block size parameter (e.g., $2 \times 2 \times 2$); a sequence of Lagrange multipliers; and a resolution parameter $\delta$.
- **Output:** An optimal hierarchical partition $P^*$ and an assignment vector $A^*$ mapping each leaf node to one of the $m$ methods.

**Data Structures**
- **Maximal Partition Tree ($P_{max}$):** A full octree where leaf nodes correspond to the minimal block size. Each node $\nu$ stores its spatial bounds and a list of children.
- **Cost Estimates:** For every node $\nu$ and method $a \in \{1, \dots, m\}$, precomputed values for:
  - $M(B_\nu, a)$: Required memory space for block $B_\nu$ using method $a$.
  - $E[T(B_\nu, a, t)]$: Expected extraction time for block $B_\nu$ using method $a$ at isovalue $t$.
- **Optimal Cost Table:** For each node $\nu$ and multiplier $\lambda$, stores $J_\lambda^*(P_\nu, A_\nu)$, the minimum local Lagrangian cost.

**Formulas**
The global Lagrangian cost function is defined as [S1, unofficial]:
$$ J_\lambda(P, A) := E[T(P, A, t)] + \lambda \cdot M(P, A) $$
where $E[T]$ is the total expected extraction time and $M$ is the total memory usage.

The local Lagrangian cost at node $\nu$ is [S1, unofficial]:
$$ J_\lambda(P_\nu, A_\nu) := E[T(P_\nu, A_\nu, t)] + \lambda \cdot M(P_\nu, A_\nu) $$

Let $P_{\nu 0}$ denote the trivial partition at node $\nu$ (the single block $B_\nu$ itself). The optimal local cost at node $\nu$ is computed recursively [S1, unofficial]:
$$ \min_{P_\nu, A_\nu} J_\lambda(P_\nu, A_\nu) = \min \left( \min_{a=1,\dots,m} J_\lambda(P_{\nu 0}, (a)), \min_{P_\nu, A_\nu} \left( \Delta E[T](\nu) + \lambda \Delta M + \sum_{\mu \in \text{children}(\nu)} \min_{P_\mu, A_\mu} J_\lambda(P_\mu, A_\mu) \right) \right) $$
Here, $\Delta M$ is the additional storage space needed to indicate that $B_\nu$ is partitioned, and $\Delta E[T](\nu)$ is the expected time to check node $\nu$ during extraction. The first term handles the case where the volume is not further partitioned; the second term handles the partitioned case.

**Steps**
1. Read volume data.
2. Build the full partitioning tree $P_{max}$ using a minimal block size (e.g., $2 \times 2 \times 2$) for the termination criterion at leaf nodes.
3. For all nodes $\nu$ and methods $a = 1, \dots, m$, estimate the required space $M(B_\nu, a)$ and the expected extraction time $E[T(B_\nu, a, t)]$.
4. Choose a sequence of Lagrange multipliers $(\lambda_i)$ with $0 < \lambda_1 < \lambda_2 < \dots < \lambda_l$. Also choose a resolution parameter $\delta > 0$.
5. For each $\lambda_i$, run the bottom-up Lagrangian optimization:
   - For each leaf node $\nu$, compute $J_\lambda(P_{\nu 0}, (a))$ for all $a$ and select the best $a$.
   - For each inner node $\nu$ in bottom-up order:
     - Compute the cost of the trivial partition: $C_{triv} = \min_{a} J_\lambda(P_{\nu 0}, (a))$.
     - Compute the cost of partitioning: $C_{part} = \Delta E[T](\nu) + \lambda \Delta M + \sum_{\mu \in \text{children}(\nu)} \min_{P_\mu, A_\mu} J_\lambda(P_\mu, A_\mu)$.
     - Store $\min(C_{triv}, C_{part})$ as the optimal local cost for $\nu$.
   - Record the total memory $M(P^*_{\lambda_i}, A^*_{\lambda_i})$ of the resulting optimal partition.
6. Insert more $\lambda$-values and repeat Step 5 to ensure that $M(P^*_{\lambda_i}, A^*_{\lambda_i}) / M(P^*_{\lambda_{i+1}}, A^*_{\lambda_{i+1}}) \le 1 + \delta$ for all $i$. This ensures a dense enough sampling of the memory-time trade-off curve.

**Pseudocode**
```python
def hierarchical_partition_optimization(volume, methods, min_block_size, delta):
    # Step 1 & 2: Build maximal tree
    P_max = build_full_octree(volume, min_block_size)
    
    # Step 3: Estimate costs for all nodes and methods
    # M[node][method] = memory cost
    # E[node][method] = expected time cost
    M = {}
    E = {}
    for node in P_max.all_nodes():
        for method in methods:
            M[node][method] = estimate_memory(node.block, method)
            E[node][method] = estimate_time(node.block, method)
            
    # Precompute overheads for partitioning
    # Delta_M and Delta_E_T are constants per node indicating overhead of splitting
    Delta_M = {}
    Delta_E_T = {}
    for node in P_max.inner_nodes():
        Delta_M[node] = overhead_space_for_split_indicator()
        Delta_E_T[node] = overhead_time_for_node_check()

    # Step 4: Choose lambda sequence
    # Initial guess for lambda range based on min/max possible costs
    lambdas = generate_lambda_sequence()
    
    results = []
    
    # Step 5 & 6: Iterate and refine
    for lam in lambdas:
        # Bottom-up DP
        optimal_costs = {} # node -> min cost
        optimal_assignments = {} # node -> (partition_type, method_or_children_assignments)
        
        for node in P_max.bottom_up_order():
            # Option 1: Trivial partition (no split)
            best_triv_cost = float('inf')
            best_triv_method = None
            for method in methods:
                cost = E[node][method] + lam * M[node][method]
                if cost < best_triv_cost:
                    best_triv_cost = cost
                    best_triv_method = method
            
            # Option 2: Partition (split into children)
            if node.is_leaf():
                best_part_cost = float('inf')
            else:
                sum_children_costs = 0
                for child in node.children:
                    sum_children_costs += optimal_costs[child]
                best_part_cost = Delta_E_T[node] + lam * Delta_M[node] + sum_children_costs
            
            if best_triv_cost <= best_part_cost:
                optimal_costs[node] = best_triv_cost
                optimal_assignments[node] = ('trivial', best_triv_method)
            else:
                optimal_costs[node] = best_part_cost
                optimal_assignments[node] = ('partition', None) # Children already assigned
        
        # Extract global memory usage from the optimal structure
        # This requires traversing the tree with the decisions made
        total_memory = compute_total_memory(P_max, optimal_assignments)
        results.append((lam, total_memory, optimal_assignments))
        
    # Refine lambdas to ensure density condition
    # Insert new lambdas between existing ones if memory ratio > 1 + delta
    refined_lambdas = refine_lambda_sequence(results, delta)
    
    # Re-run optimization with refined lambdas to get final result
    final_result = run_optimization_with_lambdas(P_max, M, E, Delta_M, Delta_E_T, refined_lambdas)
    
    return final_result.optimal_partition, final_result.optimal_assignment
```

**Edge Cases and Pitfalls**
- **Precision:** The comparison between trivial and partition costs must handle floating-point precision issues, especially when $\lambda$ is small.
- **Boundary Conditions:** The minimal block size must be chosen such that it is smaller than any meaningful feature in the volume, otherwise the tree cannot refine sufficiently.
- **Degenerate Input:** If the volume is uniform, the trivial partition will always be optimal for any $\lambda > 0$.

## Subtopics

### Restricted Adjacency Merging
Restricted Adjacency Merging is a strategy for merging extracted isosurface components from adjacent spatial blocks in sparse volume rendering. It solves the problem of inefficiently merging blocks that do not share a true geometric boundary by restricting merges to only those blocks (brothers or nephews) that are adjacent in space. It sets itself apart from unrestricted merging by enforcing an ancestry-based type check to ensure a common boundary exists, preventing the merging of non-adjacent components [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The preprocessing phase runs in $O(N \cdot m)$, where $N$ is the number of nodes in $P_{max}$ and $m$ is the number of methods. Each node is processed once per lambda value.
- **Memory Complexity:** $O(N \cdot m)$ to store cost estimates and optimal assignments.
- **Performance:** The method is designed for offline use. The preprocessing needs to be executed only once and can be carried out offline. Results can be stored to a file and used multiple times for different memory constraints [S1, unofficial].
- **Strengths:** Provides an optimal trade-off between memory and time for a given $\lambda$. Can handle multiple extraction methods simultaneously.
- **Limitations:** Requires prior knowledge of memory and time costs for all blocks and methods. The bottom-up approach assumes that the optimal solution for a node depends only on the optimal solutions of its children (Principle of Optimality).

## Background
Hierarchical Partition Optimization was introduced in the context of optimal hybrid memory-constrained isosurface extraction. It uses dynamic programming to solve the global Lagrangian optimization problem for hierarchical partitions. The method relies on the Principle of Optimality, which states that the subtree rooted at any node in the optimal partition, together with the method assignment vector attached to the leaf nodes, provides the solution of the local Lagrangian optimization problem relative to that node [S1, unofficial].
