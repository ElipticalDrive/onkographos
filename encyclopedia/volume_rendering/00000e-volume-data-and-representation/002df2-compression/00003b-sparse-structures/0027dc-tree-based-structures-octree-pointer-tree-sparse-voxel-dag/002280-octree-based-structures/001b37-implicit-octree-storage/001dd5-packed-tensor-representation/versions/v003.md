# Packed Tensor Representation

Also called: packed tensors, variable-length sample storage

## Overview
Packed Tensor Representation is a data structure used in volume rendering to store ray samples where rays have varying numbers of valid samples, avoiding the memory inefficiency of fixed-size tensors with masks when large portions of space are empty [S1]. It packs per-sample ray indices into per-ray chunk information (start index and count) for flattened tensors [S2, unofficial]. Unlike fixed-size storage or mask-based approaches, it replaces a sequence of $N$ samples with a compact representation, which is particularly effective when large portions of the ray consist of transparent or empty space [S1]. It is similar to approaches used in Instant-NGP and PyTorch3D but explicitly described as a solution to the memory inefficiency of $(n\_rays, n\_samples, ...)$ with a mask [S1].

## How it works
**Inputs and Outputs:**
- Input: `ray_indices`, a 1D tensor of shape $(n\_sample)$ containing the ray index for each sample [S2, unofficial].
- Input: `n_rays`, optional integer specifying the total number of rays. If `None`, it is inferred as `ray_indices.max().item() + 1` [S2, unofficial].
- Output: `packed_info`, a tensor of shape $(n\_rays, 2)$ where `packed_info[i, 0]` is the start index of ray $i$'s samples in the flattened data tensor, and `packed_info[i, 1]` is the count of samples for ray $i$ [S2, unofficial].
- Output: The actual data is stored in a separate data tensor of shape `(all_samples, ...)` containing only valid samples [S1].

**Data Structures:**
1.  **Data Tensor**: A flattened tensor containing only the valid samples for all rays. Its first dimension size is the total number of valid samples across all rays [S1].
2.  **Packed Info Tensor**: An integer tensor of shape $(n\_rays, 2)$ [S2, unofficial].
    -   Column 0: Start index in the Data Tensor for each ray.
    -   Column 1: Count of valid samples for each ray [S2, unofficial].

**Steps:**
1.  Assert that `ray_indices` is 1-dimensional [S2, unofficial].
2.  Determine device and data type from `ray_indices` [S2, unofficial].
3.  If `n_rays` is not provided, set `n_rays = ray_indices.max().item() + 1` [S2, unofficial].
4.  Initialize `chunk_cnts` as a zero tensor of shape $(n\_rays)$ with the same device and data type as `ray_indices` [S2, unofficial].
5.  Accumulate sample counts per ray: `chunk_cnts.index_add_(0, ray_indices, torch.ones_like(ray_indices))` [S2, unofficial].
6.  Compute cumulative sums to determine start indices: `chunk_starts = chunk_cnts.cumsum(dim=0, dtype=dtype) - chunk_cnts` [S2, unofficial].
7.  Stack `chunk_starts` and `chunk_cnts` along the last dimension to form `packed_info` of shape $(n\_rays, 2)$ [S2, unofficial].

**Pseudocode:**
```python
def pack_tensor(ray_indices, n_rays=None):
    """
    Packs ray indices into start and count information for flattened tensors.
    
    Args:
        ray_indices: 1D LongTensor of shape (n_samples) containing ray indices.
        n_rays: Optional int. If None, inferred from ray_indices.
        
    Returns:
        packed_info: Tensor of shape (n_rays, 2).
    """
    # Assert 1D
    assert ray_indices.dim() == 1, "ray_indices must be 1D"
    
    # Determine device and dtype
    device = ray_indices.device
    dtype = ray_indices.dtype
    
    # Infer n_rays if not provided
    if n_rays is None:
        n_rays = ray_indices.max().item() + 1
        
    # Initialize counts tensor
    chunk_cnts = torch.zeros(n_rays, device=device, dtype=dtype)
    
    # Accumulate counts: add 1 for each occurrence of a ray index
    # Equivalent to: for i in range(len(ray_indices)): chunk_cnts[ray_indices[i]] += 1
    chunk_cnts.index_add_(0, ray_indices, torch.ones_like(ray_indices))
    
    # Compute start indices using cumulative sum
    # chunk_starts[i] = sum(chunk_cnts[0...i-1])
    chunk_starts = chunk_cnts.cumsum(dim=0, dtype=dtype) - chunk_cnts
    
    # Stack start and count
    packed_info = torch.stack([chunk_starts, chunk_cnts], dim=-1)
    
    return packed_info
```

**Parameters:**
-   `ray_indices`: Input LongTensor of shape $(n\_sample)$ [S2, unofficial].
-   `n_rays`: Optional number of rays. If `None`, inferred as `ray_indices.max().item() + 1` [S2, unofficial].

**Edge Cases and Pitfalls:**
-   Only CUDA inputs are supported; CPU inputs raise `NotImplementedError` [S2, unofficial].
-   The function is not differentiable [S2, unofficial].
-   Precision issues may arise if `ray_indices` contains large values, though standard integer types are used [S2, unofficial].
-   The method assumes `ray_indices` are contiguous and valid (i.e., $0 \le ray\_indices[i] < n\_rays$) [G].

## Subtopics

### [Partial Composite Storage](11434-partial-composite-storage.md)
Partial Composite Storage is a data compression technique used in volume rendering to reduce memory footprint and communication overhead by aggregating consecutive ray samples into a single representative entity. Unlike fixed-size storage or mask-based approaches (such as those in [Packed Tensor Representation](1611-packed-tensor-representation.md)), it replaces a sequence of $N$ samples with a fixed-size structure containing the accumulated color, opacity, and depth bounds, regardless of $N$. This method is particularly effective when large portions of the ray consist of transparent or empty space, allowing for significant reduction in data volume during the exchange phase of distributed rendering.

## Operating characteristics
-   **Time Complexity**: $O(n\_samples)$ for counting and $O(n\_rays)$ for cumulative sum, resulting in $O(n\_samples + n\_rays)$ total time [S2, unofficial].
-   **Memory Complexity**: $O(n\_valid\_samples + 2 \cdot n\_rays)$ integers for the packed info, plus the data tensor size [S1]. This is significantly more memory-efficient than $(n\_rays, n\_samples, ...)$ with a mask when $n\_valid\_samples \ll n\_rays \cdot n\_samples$ [S1].
-   **Performance**: Enables efficient sampling with spatial skipping by supporting various numbers of samples across rays [S1].
-   **Strengths**: Reduces memory footprint for sparse samples; supports variable-length samples per ray; compatible with CUDA operations [S1][S2, unofficial].
-   **Limitations**: Not differentiable; CPU support is not available in the reference implementation [S2, unofficial].
-   **When to use**: When rays have highly variable numbers of valid samples, especially in sparse scenes or with spatial skipping [S1].
-   **When not to use**: When all rays have the same number of samples, or when differentiability through the packing step is required [S2, unofficial].

## Background
Packed Tensor Representation was introduced in the context of efficient NeRF sampling to address memory inefficiencies in handling variable-length ray samples [S1]. It is similar to approaches used in Instant-NGP and PyTorch3D but explicitly described in NerfAcc [S1]. It is used in NerfAcc and Nerfstudio to support various radiance fields and efficient sampling with spatial skipping [S1].
