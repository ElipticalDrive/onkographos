# Bottom-up Octree Construction

Also called: Bottom-up Octree Building, Lossless/Lossy Octree Compression, Octree Volume Build, Octree Volume Construction, Octree Volume Construction via Variance Consolidation

## Overview
Bottom-up Octree Construction is a method for compressing a 3D scalar array into an adaptive-resolution octree by recursively grouping 8 voxels into a parent node if they are identical (lossless) or have combined variance below a threshold (lossy), storing the average value at the parent [S1][S3, unofficial]. It solves the problem of efficiently storing and rendering large scalar fields by reducing memory footprint while enabling accelerated ray traversal via a simultaneously built min/max tree [S4, unofficial]. It differs from top-down approaches by starting from the finest grid and merging up, and from static structures by integrating compression and acceleration data (min/max) into a single cohesive build process [S2][S3, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** A 3D scalar array of rectilinear grid data [S4, unofficial].
*   **Output:** An octree volume structure containing interior nodes, cap nodes, and scalar leaves, along with an embedded min/max tree for acceleration [S3, unofficial].

### Data Structures
To avoid explicitly storing a full node for each leaf, the method stores nodes corresponding to the parent [S4, unofficial]. The layout is as follows:

1.  **Interior Node (Depth $< d_{max}-1$):**
    *   Contains pointers to 8 children [S4, unofficial].
    *   Contains min/max pairs for each of the 8 children [S4, unofficial].
    *   Contains scalar values for children that are leaves (scalar leaves) [S4, unofficial].
    *   **Pointer Storage:** Rather than full pointers, the structure uses a 32-bit `child_start` index and a single-byte offset per child [S4, unofficial].
    *   **Leaf Indicator:** An array indicates the offset of each child; a value of $-1$ indicates that child is a leaf (scalar leaf) [S4, unofficial].
    *   **Scalar Storage:** A second array, `child_scalars`, contains the value of each child [S4, unofficial].

2.  **Cap Node (Depth $d_{max}-1$):**
    *   Consists simply of 8 scalar values [S4, unofficial].
    *   These correspond to the finest available data resolution [S2].
    *   Caps are not separate structures but contain eight scalars at the maximal depth [S3, unofficial].

3.  **Scalar Leaf:**
    *   Not a separate structure, but a single value embedded inside its parent interior node [S3, unofficial].
    *   Indicated by a null child pointer (offset $-1$) [S4, unofficial].

### Parameters
*   **$N$:** The smallest power of 2 that encompasses the largest dimension of the input 3D volume [S3, S4, unofficial].
*   **$d_{max}$:** Maximum depth of the octree, calculated as $\log_2(N)$ [S3, S4, unofficial].
*   **Variance Threshold:** Used for lossy compression to determine if 8 voxels should be consolidated. If variance is below this threshold, voxels are merged [S1, S2]. Typical value: Not specified in sources [S2].
*   **Isovalue Clamping Range:** A user-specified range of isovalues; data outside this range is clamped to reduce memory footprint (e.g., 64-127) [S5].

### Algorithm Steps

1.  **Initialization:**
    *   Determine $N$, the smallest power of 2 encompassing the largest dimension of the input volume [S3, S4, unofficial].
    *   Set maximum depth $d_{max} = \log_2(N)$ [S3, S4, unofficial].
    *   Assign groups of 8 voxels from the original structured grid to the caps at depth $d_{max}-1$ [S3, S4, unofficial].

2.  **Bottom-Up Consolidation:**
    *   Proceed from the bottom-up (from depth $d_{max}-1$ towards the root) [S3, S4, unofficial].
    *   For each group of 8 voxels (or child nodes) nested within a parent:
        *   Check if the voxels are identical (lossless) or have combined variance below the threshold (lossy) [S1, S2].
        *   If the condition is met:
            *   Compute the average of the 8 values.
            *   Consolidate them into a single scalar leaf at the parent's depth level [S1, S2].
            *   Remove the corresponding child nodes [S3, S4, unofficial].
        *   If the condition is not met:
            *   Keep the 8 children as distinct nodes (pointers are filled) [S3, S4, unofficial].
    *   Recursively repeat this process at the parent level until the root node is completed [S1][S4, unofficial].
    *   **Constraint:** Only scalar children (leaves) may be consolidated [S4, unofficial].

3.  **Min/Max Tree Construction:**
    *   The min/max tree is computed simultaneously alongside bottom-up consolidation [S3, S4, unofficial].
    *   **Voxel-Cell Duality:** The volume data consists of voxels, but the isosurface is defined within cells of 8 voxels. To avoid 8x storage expansion, the method retrieves the 7 forward neighbors of a voxel at intersection time [S4, unofficial].
    *   **Leaf Min/Max:** For leaf nodes (caps), compute the min/max pair based on the 27 voxel values (the 8 voxels of the cell plus their forward neighbors) [S3, S4, unofficial].
        *   To save storage, min/max pairs are not stored at the leaf level (depth $d_{max}$). Instead, computation is deferred to neighbor-finding during traversal [S4, unofficial].
        *   Min/max storage begins at depth $d_{max}-1$ [S4, unofficial].
    *   **Interior Min/Max:** For each parent node, compute the minimum and maximum based on the min/max pairs of its 8 children [S4, unofficial].
        *   Store these min/max values within the parent node, not the child nodes, to allow rejection of children without traversal [S3, S4, unofficial].
    *   **Overhead:** This approach entails an overhead of approximately 22% additional footprint on top of raw scalar octree-compressed data [S4, unofficial].

4.  **Point Location and Neighbor Finding (Runtime/Traversal Prep):**
    *   **Coordinate System:** Octree cells are defined on the interval $[0, 2^{d_{max}}]$ [S4, unofficial].
    *   **Point Location:** Given a vector, cast components to integers and perform top-down search from the root [S4, unofficial].
    *   **Optimization:** Precompute `child_bit_depth[d] = 1 << (max_depth - depth - 1)`. Compute the target child octant using binary `&` and integer inequality operations. Mask with destination coordinates and bit-shift by constants for X, Y, Z components to yield the 0-7 octant offset [S4, unofficial].
    *   **Neighbor Finding:** To retrieve forward neighbors for cell intersection, use neighbor-finding techniques. Worst-case complexity is $O(\log(N))$, but best-case is $O(1)$ when neighbors lie within the same parent [S4, unofficial].

### Pseudocode

```python
import math

def build_octree(volume_data, variance_threshold):
    """
    Builds a bottom-up octree from a 3D scalar array.
    volume_data: 3D list of lists of lists of scalars.
    variance_threshold: float, max variance for lossy consolidation.
    Returns: Root node of the octree.
    """
    # 1. Determine dimensions and max depth
    dims = (len(volume_data), len(volume_data[0]), len(volume_data[0][0]))
    max_dim = max(dims)
    N = 1
    while N < max_dim:
        N *= 2
    d_max = int(math.log2(N))
    
    # Pad volume to N^3 with zeros
    padded_volume = [[[0 for _ in range(N)] for _ in range(N)] for _ in range(N)]
    for z in range(dims[0]):
        for y in range(dims[1]):
            for x in range(dims[2]):
                padded_volume[z][y][x] = volume_data[z][y][x]
                
    # 2. Initialize Caps at depth d_max - 1
    current_level_nodes = []
    for z in range(0, N, 2):
        for y in range(0, N, 2):
            for x in range(0, N, 2):
                voxels = [
                    padded_volume[z][y][x], padded_volume[z][y][x+1],
                    padded_volume[z][y+1][x], padded_volume[z][y+1][x+1],
                    padded_volume[z+1][y][x], padded_volume[z+1][y][x+1],
                    padded_volume[z+1][y+1][x], padded_volume[z+1][y+1][x+1]
                ]
                current_level_nodes.append({'type': 'cap', 'scalars': voxels})
                
    # 3. Bottom-Up Consolidation
    current_depth = d_max - 1
    while current_depth >= 0:
        next_level_nodes = []
        for i in range(0, len(current_level_nodes), 8):
            children = current_level_nodes[i:i+8]
            
            # Check if all children are scalar leaves (caps or scalar leaves)
            all_leaves = all(child['type'] in ('cap', 'scalar_leaf') for child in children)
            
            if all_leaves:
                scalars = []
                for child in children:
                    if child['type'] == 'cap':
                        scalars.extend(child['scalars'])
                    elif child['type'] == 'scalar_leaf':
                        scalars.append(child['value'])
                
                mean = sum(scalars) / 8.0
                variance = sum((s - mean)**2 for s in scalars) / 8.0
                
                if variance <= variance_threshold:
                    # Consolidate into a single scalar leaf
                    next_level_nodes.append({
                        'type': 'interior',
                        'child_start': 0,
                        'child_offsets': [-1] * 8,
                        'child_scalars': [mean],
                        'child_mins': [mean],
                        'child_maxs': [mean],
                        'value': mean
                    })
                else:
                    # Keep as 8 children
                    child_mins = []
                    child_maxs = []
                    child_offsets = []
                    child_scalars = []
                    for idx, child in enumerate(children):
                        if child['type'] == 'cap':
                            c_min = min(child['scalars'])
                            c_max = max(child['scalars'])
                            child_mins.append(c_min)
                            child_maxs.append(c_max)
                            child_offsets.append(i + idx)
                            child_scalars.append(None)
                        elif child['type'] == 'scalar_leaf':
                            val = child['value']
                            child_mins.append(val)
                            child_maxs.append(val)
                            child_offsets.append(i + idx)
                            child_scalars.append(val)
                    next_level_nodes.append({
                        'type': 'interior',
                        'child_start': 0,
                        'child_offsets': child_offsets,
                        'child_scalars': child_scalars,
                        'child_mins': child_mins,
                        'child_maxs': child_maxs,
                        'value': None
                    })
            else:
                # Mixed types: cannot consolidate, treat as non-consolidated interior node
                child_mins = []
                child_maxs = []
                child_offsets = []
                child_scalars = []
                for idx, child in enumerate(children):
                    if child['type'] == 'cap':
                        c_min, c_max = min(child['scalars']), max(child['scalars'])
                    elif child['type'] == 'scalar_leaf':
                        c_min = c_max = child['value']
                    else:
                        c_min = child['child_mins'][0]
                        c_max = child['child_maxs'][0]
                    child_mins.append(c_min)
                    child_maxs.append(c_max)
                    child_offsets.append(i + idx)
                    child_scalars.append(None)
                next_level_nodes.append({
                    'type': 'interior',
                    'child_start': 0,
                    'child_offsets': child_offsets,
                    'child_scalars': child_scalars,
                    'child_mins': child_mins,
                    'child_maxs': child_maxs,
                    'value': None
                })
        current_level_nodes = next_level_nodes
        current_depth -= 1
        
    return current_level_nodes[0]
```

## Subtopics

### [Min/Max Tree Construction](1623-min-max-tree-construction.md)
A min/max tree stored within the octree structure to accelerate ray traversal by skipping cells where the isovalue is outside the node's min/max scalar range. It is computed simultaneously with the bottom-up consolidation. For leaf nodes, min/max is based on 27 voxels (cell + forward neighbors). For interior nodes, min/max is derived from the min/max pairs of the 8 children. This adds ~22% overhead but allows rejection of children without traversal.

### [Octree Construction from Structured Volumes](1854-octree-construction-from-structured-volumes.md)
Generation of an octree from a 3D grid by consolidating voxels with zero inter-voxel variance, extending the principle of quadtree generation from 2D grids by consolidating pixels with zero inter-pixel variance. It uses a 3D array of rectilinear grid data as input and determines $N$ and $d_{max}$ based on the largest dimension.

### [Omnitree Refinement](2222-omnitree-refinement.md)
Omnitrees partition a d-dimensional Cartesian domain $\Omega \subset \mathbb{R}^d$ into N nonoverlapping subdomains $Q_i$, where boundaries occur at dyadic rationals (multiples of $2^{-k}$). An omnitree node $v$ is characterized by a binary splitting label $b(v) \in \{0, 1\}^d$, where $b_j = 1$ indicates bisection in dimension $j$, yielding $2^{|\sigma(v)|}$ children. The all-zero label $b = 0$ is reserved for leaf nodes. Normalization enforces that splits are gathered as high in the tree as possible, guaranteeing a unique, shallowest representation.

### Hierarchical Partition Optimization
A method to optimize the octree structure for memory and extraction time trade-offs. It uses a global Lagrangian cost function $J_\lambda(P, A) := E[T(P, A, t)] + \lambda \cdot M(P, A)$, where $E[T]$ is expected extraction time and $M$ is memory [S6, unofficial]. It builds a full partitioning tree $P_{max}$ and runs bottom-up Lagrangian optimization for a sequence of $\lambda_i$ values to find optimal partitions and method assignments for each node [S6, unofficial].

## Operating characteristics

*   **Time Complexity:** The build process is bottom-up and recursive [S3, S4, unofficial]. Point location is $O(\log(N))$ in the worst case, but neighbor-finding skews heavily toward $O(1)$ in practice [S4, unofficial].
*   **Memory Complexity:** The structure stores min/max pairs and pointers [S4, unofficial]. The min/max tree adds approximately 22% overhead to the raw scalar octree-compressed data [S4, unofficial].
*   **Performance:** Accelerates ray tracing by allowing rejection of children whose min/max range does not contain the isovalue [S3, S4, unofficial].
*   **Strengths:** Adaptive resolution, lossless/lossy compression, integrated acceleration structure [S1][S3, unofficial].
*   **Limitations:** Neighbor-finding overhead for cell intersection; potential for looser min/max tree if leaf min/max is omitted (mitigated by runtime computation) [S4, unofficial].

## Background

*   **Origin:** The method was introduced in "Interactive Isosurface Ray Tracing of Large Octree Volumes" by Knoll et al. (2006) [S1][S3, unofficial].
*   **Development:** It extends the principle of quadtree generation from 2D grids to 3D octrees [S2]. It builds on voxel-cell duality concepts and neighbor-finding techniques from prior work [S4, unofficial].
*   **Usage:** Used in interactive isosurface ray tracing of large scalar fields [S1][S3, unofficial].
