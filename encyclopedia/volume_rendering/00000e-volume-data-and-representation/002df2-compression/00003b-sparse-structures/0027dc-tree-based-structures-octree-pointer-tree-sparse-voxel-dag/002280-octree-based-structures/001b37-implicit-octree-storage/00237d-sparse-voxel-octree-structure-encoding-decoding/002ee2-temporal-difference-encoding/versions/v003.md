# Temporal Difference Encoding

Also called: Difference Encoding, Incremental Tree Merging, Tree merging

## Overview
Temporal Difference Encoding is a compression technique for time-varying volume data that exploits high temporal correlation between consecutive time steps [S1, unofficial][S2, unofficial]. It predicts each sample based on past data and encodes the difference between the prediction and the actual value [S1, unofficial][S2, unofficial]. Structurally, it merges octrees from consecutive time steps by storing pointers to unchanged subtrees from previous steps instead of duplicating data [S1, unofficial][S2, unofficial]. Unlike methods that treat all dimensions uniformly, this approach applies difference encoding specifically to the time domain [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input:** A sequence of time-varying volume datasets, where each time step $t$ is represented as an octree structure [S1, unofficial][S2, unofficial].
- **Output:** A compressed representation where identical subtrees across time steps are linked via pointers, reducing storage requirements [S1, unofficial].

**Data Structures**
The method operates on the existing Sparse Voxel Octree (SVO) structure [G]. Each node in the octree represents a spatial region [G]. For temporal encoding, the structure is augmented to support references to nodes from previous time steps [S1, unofficial].
- **Node Structure:** Standard SVO node fields (e.g., child pointers, data values, metadata) [G].
- **Temporal Pointer:** A reference or index pointing to the corresponding node in the previous time step's octree if the subtree is identical [S2, unofficial].

**Steps**
1. **Quantization:** Apply quantization to the volume data to attain voxel-level compression [S1, unofficial][S2, unofficial]. This step significantly influences the performance of subsequent encoding and visualization [S1, unofficial][S2, unofficial].
2. **Octree Encoding:** Encode the spatial structure of the volume at the current time step using standard octree encoding [S1, unofficial][S2, unofficial].
3. **Incremental Merging:** Compare the octree of the current time step $t$ with the octree of the previous time step $t-1$ [S1, unofficial][S2, unofficial].
   - Traverse both trees simultaneously [S1, unofficial].
   - If a subtree at time step $t$ is identical to the corresponding subtree at time step $t-1$, store only a pointer to the subtree from time step $t-1$ in the current time step's structure [S1, unofficial][S2, unofficial].
   - If the subtree has changed, recursively process the children or store the new data [S1, unofficial][S2, unofficial].
4. **Difference Prediction:** For individual samples, predict the value based on past data and encode the difference between the prediction and the actual sample value [S1, unofficial][S2, unofficial]. This is particularly effective because time-varying volume data are highly correlated from time step to time step, similar to video and speech data [S1, unofficial][S2, unofficial].

**Formulas**
Let $V_t$ be the volume at time $t$. The encoded representation $E_t$ for a subtree $S$ is:
$$
E_t(S) = 
\begin{cases} 
\text{Pointer}(E_{t-1}(S)) & \text{if } S_t = S_{t-1} \\
\text{Encode}(S_t) & \text{otherwise}
\end{cases}
$$
Where $S_t = S_{t-1}$ denotes structural and value identity [S1, unofficial][S2, unofficial].

**Parameters**
- **Quantization Step:** Not given in the sources. The sources note that quantization is applied to attain voxel-level compression and influences subsequent encoding [S1, unofficial][S2, unofficial].
- **Merging Threshold:** Not given in the sources. Merging requires exact structural and value identity between subtrees [S1, unofficial][S2, unofficial].

**Edge Cases and Pitfalls**
- **Precision:** Quantization errors may prevent exact subtree matching, reducing compression efficiency. The sources emphasize the importance of investigating how quantization assists subsequent compression [S1, unofficial].
- **Degenerate Input:** Not given in the sources. The method is tested on datasets that are not all highly spatially and temporally coherent, implying reduced compression benefits in such cases [S1, unofficial].

**Pseudocode**
```python
class Node:
    def __init__(self, value=None, children=None):
        self.value = value
        self.children = children if children is not None else [None] * 8
        self.is_leaf = children is None

class PointerNode:
    def __init__(self, ref_node):
        self.ref_node = ref_node
        self.is_leaf = True

def temporal_difference_encoding(current_node, previous_node):
    # Handle null cases
    if current_node is None and previous_node is None:
        return None
    if previous_node is None:
        # Standard octree encoding [G]
        return encode_spatial_structure(current_node)
    
    # Check for exact subtree identity
    if is_subtree_identical(current_node, previous_node):
        return PointerNode(previous_node)
    
    # Recurse on children if structure differs
    new_node = Node()
    new_node.children = []
    for i in range(8):
        child_current = current_node.children[i] if i < len(current_node.children) else None
        child_previous = previous_node.children[i] if previous_node and i < len(previous_node.children) else None
        new_node.children.append(temporal_difference_encoding(child_current, child_previous))
    return new_node

def is_subtree_identical(node_a, node_b):
    if node_a is None and node_b is None:
        return True
    if node_a is None or node_b is None:
        return False
    if node_a.is_leaf != node_b.is_leaf:
        return False
    if node_a.is_leaf:
        return node_a.value == node_b.value
    for i in range(8):
        if not is_subtree_identical(node_a.children[i], node_b.children[i]):
            return False
    return True

def encode_spatial_structure(node):
    new_node = Node(value=node.value, children=[None]*8)
    new_node.is_leaf = node.is_leaf
    if not node.is_leaf:
        for i in range(8):
            if node.children and i < len(node.children) and node.children[i] is not None:
                new_node.children[i] = encode_spatial_structure(node.children[i])
    return new_node
```

## Subtopics

### Hierarchical Temporal Grouping
Building a hierarchical structure for each time step, then grouping and encoding together space-corresponding nodes [S3]. This approach extends the basic temporal difference encoding by organizing nodes hierarchically before applying temporal grouping, potentially improving compression efficiency for complex temporal variations [S3].

## Operating characteristics
**Time and Memory Complexity**
- **Memory:** Significantly reduced storage for time-varying data with high temporal coherence, as identical subtrees are represented by pointers rather than duplicated data [S1, unofficial][S2, unofficial].
- **Time:** Encoding time depends on the comparison of subtrees across time steps. Merging is incremental over the time dimension [S1, unofficial].

**Measured Performance**
- Not given in the sources. The authors report that combined spatial and temporal savings reduce I/O costs and increase user interactivity [S1, unofficial][S2, unofficial].

**Scaling**
- Not given in the sources. The merging process is incremental over the time dimension, so complexity scales linearly with the number of time steps and depends on the degree of temporal coherence [S1, unofficial].

**Strengths and Limitations**
- **Strengths:** Reduces I/O costs and enables selective rendering by reusing rendered subtrees from previous time steps [S1, unofficial][S2, unofficial]. The associativity of the over operation for compositing guarantees the correctness of composited results when reusing subtrees [S1, unofficial].
- **Limitations:** Effectiveness depends on the level of temporal coherence. Quantization can impact performance [S1, unofficial][S2, unofficial].

**When to Use**
- Use for time-varying volume data with high temporal correlation, such as fluid simulations or medical imaging sequences [S1, unofficial][S2, unofficial].

**When Not to Use**
- Not given in the sources.

## Background
**Origin**
- Developed in the context of efficient encoding and rendering of time-varying volume data [S1, unofficial][S2, unofficial]. The method is attributed to the authors of the NASA Technical Reports Server document [S1, unofficial] and the DTIC document [S2, unofficial].

**History and Development**
- The method builds on the observation that time-varying volume data are highly correlated from time step to time step, similar to video and speech data [S1, unofficial][S2, unofficial]. It contrasts with Wilhelms and Van Gelder's model, which treats all dimensions the same way, by applying difference encoding specifically to the time domain [S1, unofficial].

**Where it is Used**
- Used in software rendering processes tailored to tree structures for time-varying volume data, enabling selective rendering and reduced I/O costs [S1, unofficial][S2, unofficial].
