# Adaptive Octree Encoding

Also called: Adaptive Octree Representation for TB-AMR, Compact Sparse Octree, Sparse Octree for AMR

## Overview
Adaptive Octree Encoding is a memory layout for storing Tree-Based Adaptive Mesh Refinement (TB-AMR) data as an adaptive-resolution octree to preserve hierarchy information, enabling faster ray traversal and higher quality rendering than flattening to unstructured or rectilinear grids [S1]. Unlike Sparse Voxel Octrees (SVO) which typically store uniform voxels, this structure supports storing voxels of different resolutions to handle AMR data [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Tree-Based AMR (TB-AMR) cell-centered data with a 2:1 refinement ratio [S1].
*   **Output:** Contiguous arrays of node descriptors and value ranges representing the adaptive octree hierarchy [S1].

**Data Structures:**
The structure consists of two contiguous arrays:
1.  **Node Descriptors:** A 64-bit integer per node [S1]. Leaf nodes pack a single-precision data value directly into the descriptor [S1]. Internal nodes encode the existence and location of children [S1].
2.  **Value Ranges:** An additional 64 bits per node storing a pair of 32-bit floats (min/max) [S1]. This enables empty-space skipping and active-cell filtering [S1].

**64-bit Descriptor Layout:**
The descriptor is divided into three fields [S1]:
*   **Bits 0-7 (8 bits):** Child mask. Bit $i$ is 1 if the $i$-th child exists, 0 otherwise [S1].
*   **Bits 8-62 (55 bits):** Offset to children in the contiguous array [S1].
*   **Bit 63 (1 bit):** Leaf flag [S1].

**Numbered Steps:**
1.  **Construct Octree:** Build the octree from TB-AMR data using an offline top-down serial builder [S1]. The framework assumes a 2:1 refinement ratio between parent and child cells, which is the most frequently found factor in practice [S1].
2.  **Encode Internal Nodes:** For each internal node, determine which of the 8 potential children exist. Set the corresponding bits in the 8-bit child mask. Calculate the offset to the first child in the contiguous array. Set the leaf flag to 0 [S1].
3.  **Encode Leaf Nodes:** For each leaf node, pack the single-precision data value into the descriptor. Set the leaf flag to 1. The offset and mask fields are left unused for leaf nodes [S1].
4.  **Store Value Ranges:** For every node (internal and leaf), store the min/max value range in the separate 64-bit range array. The current implementation redundantly stores ranges for leaf nodes, though this is not strictly required [S1].
5.  **Serialize:** Output the arrays of nodes and ranges to a binary file for use by the renderer [S1].

**Formulas:**
*   **Child Fetching:** To fetch a specific child node $c$ (where $c \in [0, 7]$) from an internal node:
    $$ \text{ChildIndex} = \text{Offset} + \sum_{i=0}^{c-1} \text{Mask}[i] $$
    Where $\text{Mask}[i]$ is the $i$-th bit of the child mask [S1].

**Parameters:**
*   **Refinement Factor:** 2 [S1].
*   **Descriptor Size:** 64 bits [S1].
*   **Value Range Size:** 64 bits (2 $\times$ 32-bit floats) [S1].

**Edge Cases and Pitfalls:**
*   **Redundancy:** Leaf nodes redundantly store value ranges in the current approach. This is not required and optimized layouts are possible [S1].
*   **Refinement Assumption:** The method assumes a refinement factor of two. While larger factors exist, they are less common [S1].

**Pseudocode:**
```python
# Data structures matching the 64-bit descriptor layout
class NodeDescriptor:
    mask: int      # 8-bit child mask
    offset: int    # 55-bit offset to children array
    is_leaf: bool  # 1-bit leaf flag
    value: float   # Single-precision data (only for leaves)

class NodeRange:
    min_val: float
    max_val: float

def encode_amr_to_octree(amr_cells):
    """
    Encodes TB-AMR data into the adaptive octree layout.
    Assumes a 2:1 refinement ratio and offline top-down construction [S1].
    """
    nodes = []
    ranges = []
    # Tree construction logic is not detailed in the sources [G]
    tree = amr_cells.tree

    for node in tree.traverse():
        if node.is_leaf:
            descriptor = NodeDescriptor()
            # Pack single-precision value directly into descriptor [S1]
            descriptor.value = node.value
            descriptor.is_leaf = True
            descriptor.mask = 0
            descriptor.offset = 0
            nodes.append(descriptor)
            ranges.append(NodeRange(node.value, node.value))
        else:
            descriptor = NodeDescriptor()
            descriptor.is_leaf = False
            mask = 0
            for i in range(8):
                if node.children[i] is not None:
                    mask |= (1 << i)
            descriptor.mask = mask & 0xFF
            # Offset points to the first child in the contiguous array [S1]
            descriptor.offset = node.first_child_index
            nodes.append(descriptor)
            ranges.append(NodeRange(node.min_val, node.max_val))

    return nodes, ranges

def fetch_child(descriptor: NodeDescriptor, child_id: int, nodes: list) -> NodeDescriptor:
    """
    Fetches a specific child node from the array based on the descriptor.
    Increments the offset by the number of existing children before the target [S1].
    """
    if descriptor.is_leaf:
        raise ValueError("Leaf nodes have no children")
    count_before = 0
    for i in range(child_id):
        if (descriptor.mask >> i) & 1:
            count_before += 1
    child_index = descriptor.offset + count_before
    return nodes[child_index]
```

## Subtopics

### SVO Node Encoding
A 32-bit integer encoding used for octree nodes where the most significant bit distinguishes between leaf nodes and internal nodes [S1]. Chosen when compact uniform voxel addressing is required. [Link](2705-svo-node-encoding.md)

## Operating characteristics
*   **Time Complexity:** Ray traversal is logarithmic-time due to the hierarchical representation [S1].
*   **Memory Complexity:** Each node uses 64 bits for the descriptor and 64 bits for the value range, totaling 128 bits per node [S1].
*   **Strengths:** Preserves AMR hierarchy, enabling faster and higher quality rendering than flattening to unstructured or rectilinear grids. Supports variable resolution voxels. Maps well to parallel ray traversal on multicore CPUs [S1].
*   **Limitations:** Assumes a 2:1 refinement ratio. Redundant storage of value ranges for leaf nodes increases memory usage unnecessarily [S1].
*   **When to Use:** Interactive high-quality visualization of Tree-Based AMR data, especially when using ray tracing [S1].
*   **When Not to Use:** When the AMR data does not follow a 2:1 refinement ratio, or when memory is extremely constrained and the redundancy of leaf ranges is unacceptable [S1].

## Background
The method was introduced by Wan et al. in 2020 for efficient ray-tracing based visualization of TB-AMR data in the OSPRay library [S1]. It addresses the limitations of previous AMR rendering approaches, such as cell projection [MC97], 3D slicing [KH02], and resampling to rectilinear grids, which either discard hierarchy information or suffer from lower quality and performance [S1]. The approach is motivated by the prevalence of 2:1 refinement ratios in popular TB-AMR frameworks like Paramesh and p4est [S1].
