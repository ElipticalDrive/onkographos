# Octree Compaction & Construction

Also called: Binvox Octree Compaction, Compact Octree Layout

## Overview
This method converts a dynamically allocated, pointer-heavy octree (typically built from a voxel grid) into a dense, cache-friendly contiguous memory layout. It solves the problem of poor spatial locality and high memory overhead associated with traditional pointer-based tree structures by computing relative offsets for children and siblings. It sets itself apart from sibling methods like [Min/Max Tree Construction](1623-min-max-tree-construction.md) by focusing specifically on the binary encoding of validity/filled masks and the compact storage of child pointers, rather than just hierarchical aggregation.

## How it works
The method operates in two phases: a top-down pass to compute the required memory size and pointer offsets, and a bottom-up pass to write the compacted nodes into the allocated buffer.

### Inputs and Outputs
- **Input**: A root node of a dynamically allocated octree where each node contains an array of 8 child pointers and a type enum (`NT_PARTIAL` or `NT_FILLED`).
- **Output**: A contiguous array of `CNode` structures.

### Data Structures
The compacted node `CNode` layout is not explicitly defined in terms of byte offsets in the sources, but the fields are:
- `valid_mask`: 8-bit integer (or bitfield). Bit $i$ is set if child $i$ exists.
- `leaf_mask`: 8-bit integer (or bitfield). Bit $i$ is set if child $i$ is a filled leaf (`NT_FILLED`).
- `child_ptr`: A pointer or offset. If the child is close, it stores a relative offset. If far, it stores a flag bit (bit 15) and a far pointer index.
- `far_ptr`: (Implicitly stored in a separate structure or array when `child_ptr` indicates a far reference) Stores the absolute or larger relative offset.

The sources imply a 16-bit or 32-bit integer for `child_ptr` where bit 15 distinguishes short vs. far pointers.

### Parameters
- `_shortPtrTop`: Threshold for short vs. far pointer encoding. If the relative offset exceeds this value, a far pointer is allocated. Exact numeric value not specified in the sources [S1, unofficial].
- `NT_PARTIAL`: Enum value indicating a node has children.
- `NT_FILLED`: Enum value indicating a solid leaf node.

### Algorithm Steps

1. **Initialization**: Set `rootNode->farAdr = 0` and `rootNode->childAdr = 0`.
2. **Size Calculation**: Call `compactAllocate(rootNode, 1)` to compute the total `dataSize` required.
3. **Allocation**: Allocate `data = (CNode*)malloc(dataSize * sizeof(CNode))`.
4. **Compaction**: Call `compactNode(rootNode, dataSize)` to fill the `data` array.

#### `compactAllocate(node, pos)`
This function computes the memory footprint and sets up far pointer addresses.
1. Initialize `pos` (current memory position).
2. Iterate $i$ from 0 to 7 (children):
   - Reset `node->children[i]->farAdr = 0` and `node->children[i]->childAdr = 0`.
   - If `node->children[i]` exists and `node->children[i]->type == NT_PARTIAL`:
     - Recursively call `pos = compactAllocate(node->children[i], pos)`.
3. **Far Pointer Check**: Iterate $i$ from 0 to 7:
   - If `node->children[i]` exists and `node->children[i]->childAdr` is set:
     - Compute `gchildAdrMax = pos - node->children[i]->childAdr + 16`.
     - If `gchildAdrMax > _shortPtrTop`:
       - Set `node->children[i]->farAdr = pos`.
       - Increment `pos` (allocate space for the far pointer entry).
4. **Child Address Assignment**: Iterate $i$ from 0 to 7:
   - If `node->children[i]` exists and `node->children[i]->type == NT_PARTIAL`:
     - Set `node->childAdr = pos`.
     - Increment `pos`.
5. Return `pos`.

#### `compactNode(node, dataSize)`
This function writes the compacted nodes into the `data` array.
1. Iterate $i$ from 0 to 7 (children):
   - If `node->children[i]` exists and `node->children[i]->type == NT_PARTIAL`:
     - Recursively call `compactNode(node->children[i], childAdr)`.
     - Decrement `childAdr` (tracking the position in the output buffer).
2. Assert `pos <= dataSize`.
3. Set `cnode = &data[dataSize - pos]`.
4. Initialize `cnode->valid_mask = 0` and `cnode->leaf_mask = 0`.
5. Iterate $i$ from 0 to 7:
   - If `node->children[i]` exists:
     - Set `cnode->valid_mask |= (1 << i)`.
   - If `node->children[i]` exists and `node->children[i]->type == NT_FILLED`:
     - Set `cnode->leaf_mask |= (1 << i)`.
6. Compute `childPtr = pos - node->childAdr`.
7. If `node->farAdr` is set:
   - Compute `farPtr = pos - node->farAdr`.
   - Assert `farPtr < _shortPtrTop`.
   - Set `farPtrEntry->far_ptr = childPtr`.
   - Set `cnode->child_ptr = (1 << 15) | farPtr`.
8. Else:
   - Set `cnode->child_ptr = childPtr`.

### Edge Cases and Pitfalls
- **Precision**: The assertion `farPtr < _shortPtrTop` requires careful management of `_shortPtrTop`. If the tree is very deep or sparse, far pointers may be needed frequently.
- **Boundaries**: The `pos` variable must be carefully managed to avoid buffer overflows. The source uses `dataSize - pos` to index backwards, ensuring that children are written before parents in the contiguous array (if `pos` decrements).
- **Degenerate Input**: If the input tree is empty, `dataSize` will be small, and the algorithm should handle it gracefully.

## Operating characteristics
- **Time Complexity**: $O(N)$ where $N$ is the number of nodes in the octree. Two passes are made: one for allocation/offset calculation and one for writing.
- **Memory Complexity**: $O(N)$ for the compacted array. The original pointer-based tree is typically freed after compaction.
- **Strengths**: High spatial locality, reduced memory overhead (no pointers per node, just offsets), cache-friendly traversal.
- **Limitations**: Static structure; inserting or deleting nodes requires full or partial recompaction. The `_shortPtrTop` parameter may lead to inefficient far pointer usage if not tuned.

## Background
This method is derived from the "Binvox" format and related sparse voxel octree implementations, specifically as seen in the `svo-workbench` repository [S1, unofficial]. It is commonly used in real-time volume rendering and ray tracing where memory bandwidth and cache efficiency are critical.
