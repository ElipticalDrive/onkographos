# Sparse Voxel Octree Structure Encoding/Decoding
## Overview
This method defines the CPU-side algorithms for serializing and deserializing the structural topology of a Sparse Voxel Octree (SVO) to and from disk [S1, S2, unofficial]. It solves the problem of persisting the hierarchical spatial partitioning of volume data, separating the tree structure (node connectivity and empty space) from the leaf data (voxel attributes) [S1, S2, unofficial]. Unlike [Octree Volume Structure](1978-octree-volume-structure.md) which may focus on in-memory layout, this method specifically addresses the file I/O format and binary packing required for reconstruction [S2, unofficial]. It differs from [Sparse Voxel DAG](5866-sparse-voxel-dag.md) by maintaining a strict tree hierarchy without merging identical nodes, ensuring simpler traversal logic at the cost of potentially higher memory usage for repetitive structures [S3, unofficial].
## How it works
### Inputs and Outputs
**Input:** An in-memory SVO representation containing an `OctreeInfo` header, a list of internal nodes, and a list of leaf voxels.
**Output:** A binary file (and optional ASCII header) representing the serialized SVO structure.

### Data Structures
The structure is defined by the `OctreeInfo` header and two binary data blocks.

**OctreeInfo Header Fields:**
*   `version` (`int`): The format version. Default is `1` [S2, unofficial].
*   `base_filename` (`string`): Metadata reference, not strictly part of the binary stream but part of the struct definition [S2, unofficial].
*   `gridlength` (`size_t`): The side length of the root bounding box in voxels. Default is `1024` [S2, unofficial].
*   `n_nodes` (`size_t`): The count of internal (non-leaf) nodes in the tree [S2, unofficial].
*   `n_data` (`size_t`): The count of leaf voxels (data nodes) in the tree [S2, unofficial].

**Binary Layout:**
1.  **Header Block:** An ASCII text file containing key-value pairs [S2, unofficial].
2.  **Voxel Data Block:** A binary block of size `VOXELDATA_SIZE` containing the Morton codes for all leaf voxels [S2, unofficial].
3.  **Node Data Block:** A binary block containing `n_nodes` entries, where each entry consists of three `size_t` values representing the children pointers or data indices for internal nodes [S2, unofficial].

### Steps

#### Encoding (Serialization)
1.  **Initialize Header:** Create an ASCII file. Write the version line `#octreeheader 1` [S2, unofficial].
2.  **Write Metadata:** Write the following key-value pairs:
    *   `gridlength <value>`
    *   `n_nodes <value>`
    *   `n_data <value>`
3.  **Terminate Header:** Write the line `END` to mark the end of the ASCII header [S2, unofficial].
4.  **Write Voxel Data:** Iterate through the leaf voxels. For each voxel, compute its Morton code (Z-order curve index) based on its 3D coordinates and the `gridlength`. Write these Morton codes as a contiguous binary block [S2, unofficial].
5.  **Write Node Data:** Iterate through the internal nodes. For each node, write three `size_t` values. These values typically represent the indices or pointers to the node's eight children (or null/empty indicators) [S2, unofficial].

#### Decoding (Deserialization)
1.  **Parse Header:** Open the ASCII file. Read the first line to verify the version (`#octreeheader 1`) [S2, unofficial].
2.  **Read Metadata:** Loop through subsequent lines.
    *   If the keyword is `gridlength`, read the integer value.
    *   If the keyword is `n_nodes`, read the integer value.
    *   If the keyword is `n_data`, read the integer value.
    *   If the keyword is `END`, stop parsing the header [S2, unofficial].
    *   Skip any unknown keywords [S2, unofficial].
3.  **Read Voxel Data:** Read a binary block of size `VOXELDATA_SIZE`. Parse this block into a list of Morton codes [S2, unofficial].
4.  **Read Node Data:** Read a binary block containing `n_nodes` entries. Each entry is three `size_t` values. Reconstruct the internal node structure using these values [S2, unofficial].
5.  **Reconstruct Tree:** Use the `gridlength`, `n_nodes`, and `n_data` to allocate memory. Map the Morton codes to leaf positions and link the internal nodes according to the decoded child pointers [S2, unofficial].

def encode_svo_octree(filepath: str, octree_info: OctreeInfo, nodes: List[Node], leaves: List[Voxel]):
    """
    Encodes the SVO structure to disk.
    """
    # 1. Write ASCII Header
    with open(filepath, 'w') as f_header:
        f_header.write("#octreeheader 1\n")
        f_header.write(f"gridlength {octree_info.gridlength}\n")
        f_header.write(f"n_nodes {octree_info.n_nodes}\n")
        f_header.write(f"n_data {octree_info.n_data}\n")
        f_header.write("END\n")

    # 2. Write Binary Voxel Data (Morton Codes)
    # Assuming Morton code calculation is available
    morton_codes = [calculate_morton_code(voxel.xyz, octree_info.gridlength) for voxel in leaves]
    
    with open(filepath, 'ab') as f_data: # Append binary

            f_data.write(pack_morton(code))

```python
def decode_svo_octree(filepath: str) -> Tuple[OctreeInfo, List[Voxel], List[Node]]:
    """
    Decodes the SVO structure from disk.
    """
    octree_info = OctreeInfo()
    octree_info.version = 1
    octree_info.gridlength = 1024 # Default
    
    # 1. Parse ASCII Header
    with open(filepath, 'r') as f_header:
        lines = f_header.readlines()
        if not lines:
            raise ValueError("Empty header")
        
        # Check version
        if not lines[0].strip().startswith("#octreeheader 1"):
            raise ValueError("Unsupported version")
            
        for line in lines[1:]:
            parts = line.strip().split()
            if not parts:
                continue
            key = parts[0]
            if key == "END":
                break
            if len(parts) < 2:
                continue
            value = int(parts[1])
            if key == "gridlength":
                octree_info.gridlength = value
            elif key == "n_nodes":
                octree_info.n_nodes = value
            elif key == "n_data":
                octree_info.n_data = value
            # Unknown keywords are skipped

    # 2. Read Binary Voxel Data
    # Determine file size to read remaining binary content
    file_size = os.path.getsize(filepath)
    header_size = sum(len(line) for line in lines) # Approximate
    
    with open(filepath, 'rb') as f_data:
        # Skip header
        f_data.seek(header_size)
        
        # Read all remaining bytes as voxel data
        remaining_bytes = f_data.read()
        
        # Parse Morton codes
        # Assuming fixed size per morton code, e.g., 64-bit integer
        morton_code_size = 8 
        num_leaves = octree_info.n_data
        leaves = []
        
        for i in range(num_leaves):
            start_idx = i * morton_code_size
            end_idx = start_idx + morton_code_size
            if start_idx >= len(remaining_bytes):
                break
            code_bytes = remaining_bytes[start_idx:end_idx]
            code = unpack_morton(code_bytes)
            xyz = morton_to_xyz(code, octree_info.gridlength)
            leaves.append(Voxel(xyz))

    # 3. Read Binary Node Data
    # The source [S2, unofficial] implies node data follows or is interleaved. 
    # Based on "Voxel data is written... Octree nodes are written...", 
    # we assume sequential blocks.
    # Re-reading from start or seeking past voxel data is required.
    # For simplicity, assuming voxel data block size is known or calculated.
    
    nodes = []
    # Calculate node block size: n_nodes * 3 * sizeof(size_t)
    node_block_size = octree_info.n_nodes * 3 * 8 # Assuming 64-bit size_t
    
    # Seek to node data (after header and voxel data)
    # Note: Exact offset depends on implementation details not fully specified in [S2, unofficial]
    # Assuming voxel data is immediately after header, and nodes after voxel data.
    voxel_data_size = num_leaves * morton_code_size
    node_start_offset = header_size + voxel_data_size
    
    with open(filepath, 'rb') as f_nodes:
        f_nodes.seek(node_start_offset)
        node_bytes = f_nodes.read(node_block_size)
        
        for i in range(octree_info.n_nodes):
            offset = i * 24 # 3 * 8 bytes
            child_0 = unpack_size_t(node_bytes[offset:offset+8])
            child_1 = unpack_size_t(node_bytes[offset+8:offset+16])
            child_2 = unpack_size_t(node_bytes[offset+16:offset+24])
            nodes.append(Node(child_0, child_1, child_2))

    return octree_info, leaves, nodes
```

### Parameters
*   `gridlength`: Default `1024` [S2, unofficial].
*   `version`: Default `1` [S2, unofficial].

### Edge Cases and Pitfalls
*   **Unknown Keywords:** The parser must skip unknown keywords in the header to maintain forward compatibility [S2, unofficial].
*   **Precision:** `size_t` is used for node data, implying 64-bit pointers/indices on modern systems. Ensure consistent endianness if cross-platform [S2, unofficial].
*   **Boundary Conditions:** If `n_nodes` or `n_data` is zero, the binary blocks may be empty. The decoder must handle empty reads gracefully [S2, unofficial].
*   **Morton Code Bounds:** Ensure Morton codes fit within the `gridlength`. If `gridlength` is not a power of two, padding or specific mapping logic is required [S1, unofficial].

## Subtopics

### [Tolerance-based Voxel Fusion](5866-tolerance-based-voxel-fusion.md)
Tolerance-based Voxel Fusion is a performance optimization strategy that renders volume data at variable resolutions across the spatial domain by fusing voxels with similar values. It solves the trade-off between rendering fidelity and computational cost by coarsening the representation in regions where visual detail is less critical, achieving significant savings in storage and rendering time without perceptible quality loss in moderate coarsening modes. It differs from image-space skipping, which creates blocky artifacts, by operating in the spatial domain to maintain visual continuity.

### [Temporal Difference Encoding](5869-temporal-difference-encoding.md)
Temporal Difference Encoding is a compression technique for time-varying volume data that exploits high temporal correlation between consecutive time steps. It predicts each sample based on past data and encodes the difference between the prediction and the actual value. Structurally, it merges octrees from consecutive time steps by storing pointers to unchanged subtrees from previous steps instead of duplicating data. Unlike methods that treat all dimensions uniformly, this approach applies difference encoding specifically to the time domain.

### Octree File I/O Format
The Octree File I/O Format is the specific ASCII/Binary hybrid structure used by the `cpu_voxel_raycaster` implementation to store SVO data [S2, unofficial]. It consists of an ASCII header for metadata (`gridlength`, `n_nodes`, `n_data`) followed by binary blocks for voxel Morton codes and node pointers [S2, unofficial]. This format is simple and human-readable for debugging but lacks advanced compression features [S2, unofficial].

### Sparse Voxel DAG
Sparse Voxel Directed Acyclic Graphs (SV-DAG) are an extension to the SVO technique that merge identical nodes and redirect parent pointers to single nodes to decrease memory footprint further [S3, unofficial]. This is capable of decreasing the memory footprint further compared to standard SVOs [S3, unofficial]. However, it has limited utility for radiance storage; merging nodes is less effective when storing complex data like diffuse albedo compared to simple occlusion values, as identical child nodes become rare [S3, unofficial]. If storing complex data, the extra time to build the tree may not be worth the savings [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Encoding/Decoding is linear with respect to the number of nodes and leaves, $O(N + L)$, where $N$ is the number of internal nodes and $L$ is the number of leaves [S2, unofficial].
*   **Memory Complexity:** The memory footprint is proportional to the serialized file size. The ASCII header is negligible. The binary blocks are compact, storing only Morton codes and pointers [S2, unofficial].
*   **Performance:** The ASCII header parsing is fast. Binary I/O is efficient. The method is designed for CPU-side serialization, not real-time GPU streaming [S2, unofficial].
*   **Strengths:** Simple implementation, human-readable header, compact binary storage for structure [S2, unofficial].
*   **Limitations:** No compression of the binary data itself (Morton codes are stored raw). Not suitable for very large datasets without further compression [S2, unofficial].
*   **When to Use:** When persisting SVO structures for later reconstruction or transfer between CPU modules [S1, S2, unofficial].
*   **When Not to Use:** When real-time streaming to GPU is required (use [Packed Tensor Representation](1611-packed-tensor-representation.md) or similar) or when storage space is extremely constrained (use [Octree Volume Compression](1979-octree-volume-compression.md)) [S2, unofficial].

## Background
The method originates from the `cpu_voxel_raycaster` project by Forceflow, which implements a CPU-based raycaster using Sparse Voxel Octrees [S2, unofficial]. It is part of the broader field of Volume Rendering and Sparse Voxel Techniques, which aim to efficiently represent and render large 3D datasets [S1, S3, unofficial]. The SVO structure itself was popularized by [S1, unofficial] and [S3, unofficial] for applications like VXGI (Voxel Cone Traced Global Illumination) [S3, unofficial]. The specific encoding format described here is a practical implementation detail from the `cpu_voxel_raycaster` repository [S2, unofficial].
