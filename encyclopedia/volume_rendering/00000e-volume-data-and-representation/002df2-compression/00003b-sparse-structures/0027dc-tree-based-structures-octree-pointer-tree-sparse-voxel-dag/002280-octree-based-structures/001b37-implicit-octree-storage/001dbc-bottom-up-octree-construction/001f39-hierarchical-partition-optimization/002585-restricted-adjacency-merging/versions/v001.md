# Restricted Adjacency Merging

Also called: Brother/Nephew Merging

## Overview
Restricted Adjacency Merging is a strategy for merging extracted isosurface components from adjacent spatial blocks in sparse volume rendering. It solves the problem of inefficiently merging blocks that do not share a true geometric boundary by restricting merges to only those blocks (brothers or nephews) that are adjacent in space. It sets itself apart from unrestricted merging by enforcing an ancestry-based type check to ensure a common boundary exists, preventing the merging of non-adjacent components [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of extracted isosurface components from leaf nodes of an octree. Each component consists of triangles.
*   **Output:** A set of merged, simplified isosurface components ready for dumping to disk.

**Data Structures:**
*   **Node Type:** An enum or integer representing the position of a node relative to its father's split plane: `left`, `right`, `up`, `down`, `front`, `back`.
*   **Ancestry Set ($A_{p,n}$):** A set of nodes containing node $n$ and its recursive fathers up to root $p$.

**Definitions:**
1.  **Opposite Operator:** Defines the spatial relationship between siblings.
    $$
    \begin{aligned}
    \text{left} &= \text{right}, & \text{right} &= \text{left} \\
    \text{up} &= \text{down}, & \text{down} &= \text{up} \\
    \text{front} &= \text{back}, & \text{back} &= \text{front}
    \end{aligned}
    $$
2.  **Ancestry ($A_{p,n}$):** The set of nodes on the path from $n$ to $p$. Defined recursively [S1]:
    $$
    A_{p,n} = \begin{cases} 
    \{n\} & \text{if } n = p \\
    \{n\} \cup A_{p,f_n} & \text{else}
    \end{cases}
    $$
    Where $f_n$ is the father of node $n$.
3.  **Restricted Adjacency Criterion:** A nephew node $n$ belonging to the tree of root $p_2$ ($T_{p2}$) has a common boundary with block $p_1$ if and only if [S1]:
    $$
    \forall n' \in A_{c_{p2},n}, \text{type}(n') \neq \text{type}(p1)
    $$
    Where $c_{p2}$ is the child of $p_2$ that is an ancestor of $n$ (or $n$ itself if $n$ is a child of $p_2$). Essentially, no ancestor of the nephew (up to the sibling of the target) can have the same type as the target block.

**Algorithm Steps:**
1.  **Identify Candidates:** For each unprocessed leaf node $n$, identify potential merge partners: its brother node $b$ and any nephew nodes $neph$ in the subtrees of the brother's siblings.
2.  **Check Adjacency:**
    *   For a brother $b$: They always share a boundary.
    *   For a nephew $neph$: Compute $A_{c_{p2},neph}$ (ancestry from the relevant child of the brother's parent up to $neph$). Verify that for all $n' \in A_{c_{p2},neph}$, $\text{type}(n') \neq \text{type}(target)$. If the condition holds, $neph$ is a valid merge partner [S1].
3.  **Merge Geometry:**
    *   Identify common points on the shared boundary. Use the property that a cell edge generates at most one point in Marching Cubes. Points on common cell edges are identical and can be merged [S1].
    *   Combine the triangle lists of the merging blocks.
4.  **Simplify Merged Component:**
    *   Apply edge collapse simplification using the same error criterion $E_0$ used for initial surface extraction [S1].
    *   **Time Lag Guard:** Prevent contraction of an edge $ab$ if the sphere centered on the midpoint of $ab$ with radius $rad(c)$ is not totally included in the merged blocks. This preserves quality near block boundaries [S1].
5.  **Mark Processed:** When two brothers are merged, their father node is considered completely processed. Mark the merged component as finished.
6.  **Dump:** Write finished components to disk [S1].

**Pseudocode:**

```python
def get_ancestry(node, root):
    """Returns the set of nodes from node up to root (inclusive)."""
    ancestry = set()
    current = node
    while current is not None:
        ancestry.add(current)
        if current == root:
            break
        current = current.father
    return ancestry

def has_common_boundary(nephew_node, target_node):
    """
    Checks if nephew_node (in the subtree of target_node's sibling) 
    shares a common boundary with target_node.
    """
    # Find the child of target_node's father that is an ancestor of nephew_node
    # In a bottom-up traversal, we can track this or compute it.
    # Let's assume we have access to the path or can compute the relevant child.
    # The criterion is: for all n' in ancestry of nephew up to the sibling of target,
    # type(n') != type(target).
    
    # Identify the root of the subtree containing the nephew relative to the merge context.
    # This is typically the child of the common father that contains the nephew.
    common_father = nephew_node.father
    while common_father is not None:
        # Check if common_father is the father of target_node
        if common_father.left == target_node or common_father.right == target_node or \
           common_father.up == target_node or common_father.down == target_node or \
           common_father.front == target_node or common_father.back == target_node:
            break
        common_father = common_father.father
    
    if common_father is None:
        return False # Not in the same immediate parent context for nephew check

    # The relevant child is the one that is NOT target_node
    if common_father.left == target_node:
        relevant_child = common_father.right
    elif common_father.right == target_node:
        relevant_child = common_father.left
    elif common_father.up == target_node:
        relevant_child = common_father.down
    elif common_father.down == target_node:
        relevant_child = common_father.up
    elif common_father.front == target_node:
        relevant_child = common_father.back
    elif common_father.back == target_node:
        relevant_child = common_father.front
    else:
        return False # Should not happen if logic is correct

    # Compute ancestry from relevant_child down to nephew_node
    # Actually, the definition A_{c_p2, n} is nodes containing n and recursive fathers UP TO p.
    # Here p is the relevant_child (c_p2). So we go from nephew up to relevant_child.
    ancestry = get_ancestry(nephew_node, relevant_child)
    
    for n_prime in ancestry:
        if n_prime.type == target_node.type:
            return False
            
    return True

def merge_components(comp1, comp2):
    """Merges two components and simplifies."""
    merged_triangles = comp1.triangles + comp2.triangles
    merged_vertices = merge_vertices(merged_triangles) # Handle common boundary points
    
    # Simplify with error criterion E0
    simplified_triangles = simplify(merged_triangles, merged_vertices, error_criterion=E0)
    
    # Apply time lag guard during simplification
    # This is handled inside the simplify function by checking sphere inclusion
    return Component(simplified_triangles)

def restricted_adjacency_merge(leaf_nodes):
    """
    Main loop for merging.
    Assumes leaf_nodes are processed in an order that allows bottom-up merging.
    """
    processed = set()
    
    for node in leaf_nodes:
        if node in processed:
            continue
            
        # Check for brother merge
        brother = get_brother(node)
        if brother and brother not in processed:
            merged = merge_components(node.component, brother.component)
            node.component = merged
            processed.add(brother)
            # Mark father as processed if both children are done
            if is_father_processed(node.father):
                processed.add(node.father)
            continue
            
        # Check for nephew merges
        # Iterate through nephews in the subtree of the brother's siblings
        nephews = get_nephews(node)
        for nephew in nephews:
            if nephew in processed:
                continue
            if has_common_boundary(nephew, node):
                merged = merge_components(node.component, nephew.component)
                node.component = merged
                processed.add(nephew)
                # Note: Nephew merge doesn't necessarily mark father as fully processed 
                # in the same way as brother merge, but the component is done.
                break # One merge per node is sufficient for this step? Or merge all?
                      # The text implies merging available adjacent components.
    
    # Dump finished components
    for node in leaf_nodes:
        if node not in processed:
            dump_to_disk(node.component)
```

**Parameters:**
*   $E_0$: Error criterion for simplification. Typical value: Not given in the sources.
*   $rad(c)$: Radius for the time lag guard. Typical value: Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Numerical Inaccuracy:** Common points on shared boundaries cannot be identified by simple coordinate comparison. Must rely on the Marching Cubes property that a cell edge generates at most one point [S1].
*   **Ancestry Check Failure:** If the ancestry check is not performed correctly, non-adjacent blocks may be merged, leading to topological errors. Specifically, if an ancestor of the nephew has the same type as the target, they do not share a boundary [S1].
*   **Processing Order:** The algorithm requires a specific traversal order (bottom-up) to ensure that when a merge happens, the components are ready. If a brother is merged, the father is considered processed [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. Depends on the number of leaves and the depth of the tree for ancestry checks.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Reduces the number of triangles significantly by merging adjacent components. Avoids waiting for slower blocks by allowing selective merging with nephews. Improves quality near block boundaries by using the time lag method during simplification [S1].
*   **Limitations:** Requires careful implementation of the ancestry check. Merging is restricted, so not all adjacent components may be merged if they don't meet the strict adjacency criteria.
*   **When to use:** When extracting isosurfaces from large volumes partitioned into blocks, especially when parallel extraction leads to fragmented components that need to be recombined.

## Background
Restricted Adjacency Merging was introduced in the context of parallel extraction and simplification of large isosurfaces using an extended tandem algorithm. It addresses the issue of non-uniform distribution of iso-surface components in sub-blocks, which can lead to load imbalance and inefficient merging if all brothers are forced to merge [S1].
