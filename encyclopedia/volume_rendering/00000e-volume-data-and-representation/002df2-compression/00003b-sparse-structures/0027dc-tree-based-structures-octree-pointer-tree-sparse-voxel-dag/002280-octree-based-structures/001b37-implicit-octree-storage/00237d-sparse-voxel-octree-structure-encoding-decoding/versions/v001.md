# Sparse Voxel Octree Structure Encoding/Decoding


## Overview
This method defines the CPU-side serialization and deserialization of the Sparse Voxel Octree (SVO) structure itself, separating the structural metadata from the voxel data. It solves the problem of persisting or transmitting the octree topology and leaf occupancy information in a format that allows efficient reconstruction on the host. It is distinguished from [SVO Node Encoding](2705-svo-node-encoding.md) by focusing on the file-level I/O protocol and header parsing rather than the in-memory node bit-packing, and from [Implicit Octree Storage](939-implicit-octree-storage.md) by using an explicit ASCII header and binary data blocks rather than a purely implicit or compressed memory layout.

## How it works
The method operates in two phases: parsing the ASCII header to establish the tree's global parameters, and reading/writing the binary payload containing the leaf nodes.

### Inputs and Outputs
- **Input**: A file path or stream, and an `OctreeInfo` structure to hold the parsed metadata.
- **Output**: An `OctreeInfo` instance populated with `version`, `gridlength`, `n_nodes`, and `n_data`, and a binary buffer or stream pointer positioned after the header, ready for voxel data extraction.

### Data Structures
The primary data structure for metadata is `OctreeInfo` [S2, unofficial]:

```cpp
struct OctreeInfo {
    int version;          // Default: 1
    string base_filename; // Associated file name
    size_t gridlength;    // Default: 1024
    size_t n_nodes;       // Number of internal nodes
    size_t n_data;        // Number of leaf data entries
};
```

### Numbered Steps

1.  **Open File**: Open the target file for reading (or writing).
2.  **Read Header Line 1**: Read the first line as a string. It must match `#octreeheader 1`. Parse the integer version. If the version is not 1, the format is unsupported [S2, unofficial].
3.  **Parse Key-Value Pairs**: Loop through subsequent lines until the `END` keyword is encountered:
    a.  Read a keyword string.
    b.  If the keyword is `gridlength`, read the following integer into `info.gridlength`.
    c.  If the keyword is `n_nodes`, read the following integer into `info.n_nodes`.
    d.  If the keyword is `n_data`, read the following integer into `info.n_data`.
    e.  If the keyword is `END`, break the loop.
    f.  For any other keyword, skip the line (ignore unknown fields) [S2, unofficial].
4.  **Read Voxel Data**: Read a binary block of size `VOXELDATA_SIZE`. This block contains the `morton` code for the leaf nodes. The number of such blocks corresponds to `n_data` [S2, unofficial].
5.  **Read Node Data**: Read three `size_t` values for each node. These represent `n.data` (likely child pointers or data indices). The number of such triplets corresponds to `n_nodes` [S2, unofficial].

### Formulas
-   **Morton Code Mapping**: The `morton` code maps 3D coordinates $(x, y, z)$ to a 1D index. While the specific bit-interleaving algorithm is not detailed in the source, the `morton` code is stored directly in the binary block [S2, unofficial].
-   **Data Size**: The total binary size of the voxel data section is $n\_data \times VOXELDATA\_SIZE$ [S2, unofficial].

### Parameters
-   `version`: Integer, typically 1 [S2, unofficial].
-   `gridlength`: Size of the root bounding box in voxels, default 1024 [S2, unofficial].
-   `VOXELDATA_SIZE`: Size of the binary block for a single voxel's morton code. Not given in the sources.

### Edge Cases and Pitfalls
-   **Unknown Keywords**: The parser must skip unknown keywords to maintain forward compatibility. Failure to skip may cause desynchronization [S2, unofficial].
-   **Precision**: `size_t` is used for node counts and data indices, ensuring 64-bit support on modern systems [S2, unofficial].
-   **Binary/ASCII Mismatch**: The header is ASCII, but the voxel data is binary. Care must be taken not to mix text and binary I/O modes without proper flushing or seeking [S2, unofficial].

### Pseudocode

```python
def decode_sparse_voxel_octree_cpu(file_path):
    """
    Decodes the SVO structure from a file.
    Returns OctreeInfo and raw binary data for nodes/voxels.
    """
    info = OctreeInfo()
    info.version = 1
    info.gridlength = 1024
    info.n_nodes = 0
    info.n_data = 0
    
    with open(file_path, 'rb') as f:
        # Step 1: Read Header
        header_line = f.readline().decode('utf-8').strip()
        if not header_line.startswith('#octreeheader'):
            raise ValueError("Invalid header format")
        
        # Parse version (assuming format "#octreeheader <version>")
        parts = header_line.split()
        if len(parts) >= 2:
            info.version = int(parts[1])
        else:
            info.version = 1 # Default if version missing
            
        # Step 2: Parse Key-Value Pairs
        while True:
            line = f.readline().decode('utf-8').strip()
            if not line:
                break
                
            if line == 'END':
                break
                
            parts = line.split()
            if len(parts) < 2:
                continue
                
            key = parts[0]
            value_str = parts[1]
            
            if key == 'gridlength':
                info.gridlength = int(value_str)
            elif key == 'n_nodes':
                info.n_nodes = int(value_str)
            elif key == 'n_data':
                info.n_data = int(value_str)
            else:
                # Skip unknown keywords
                pass
        
        # Step 3: Read Voxel Data (Morton Codes)
        # Note: VOXELDATA_SIZE is not defined in sources. 
        # Assuming it is the size of a single morton code integer (e.g., 8 bytes for 64-bit).
        # [G] Placeholder for actual VOXELDATA_SIZE constant.
        voxel_data_size = 8 
        voxel_data = []
        for _ in range(info.n_data):
            morton_bytes = f.read(voxel_data_size)
            if len(morton_bytes) < voxel_data_size:
                raise EOFError("Unexpected end of file while reading voxel data")
            morton_code = int.from_bytes(morton_bytes, byteorder='little') # [G] Endianness assumed little
            voxel_data.append(morton_code)
            
        # Step 4: Read Node Data
        # Three size_t values per node. size_t is typically 8 bytes on 64-bit systems.
        # [G] Assuming 64-bit size_t.
        node_data_size = 8 * 3
        node_data = []
        for _ in range(info.n_nodes):
            node_bytes = f.read(node_data_size)
            if len(node_bytes) < node_data_size:
                raise EOFError("Unexpected end of file while reading node data")
            # Unpack three size_t values
            n0 = int.from_bytes(node_bytes[0:8], byteorder='little')
            n1 = int.from_bytes(node_bytes[8:16], byteorder='little')
            n2 = int.from_bytes(node_bytes[16:24], byteorder='little')
            node_data.append((n0, n1, n2))
            
    return info, voxel_data, node_data

def encode_sparse_voxel_octree_cpu(file_path, info, voxel_data, node_data):
    """
    Encodes the SVO structure to a file.
    """
    with open(file_path, 'wb') as f:
        # Write Header
        f.write(f"#octreeheader {info.version}\n".encode('utf-8'))
        f.write(f"gridlength {info.gridlength}\n".encode('utf-8'))
        f.write(f"n_nodes {info.n_nodes}\n".encode('utf-8'))
        f.write(f"n_data {info.n_data}\n".encode('utf-8'))
        f.write(b"END\n")
        
        # Write Voxel Data
        voxel_data_size = 8 # [G] Must match decode
        for morton in voxel_data:
            f.write(morton.to_bytes(voxel_data_size, byteorder='little'))
            
        # Write Node Data
        node_data_size = 24 # 3 * 8 bytes
        for n0, n1, n2 in node_data:
            f.write(n0.to_bytes(8, byteorder='little'))
            f.write(n1.to_bytes(8, byteorder='little'))
            f.write(n2.to_bytes(8, byteorder='little'))
```

## Subtopics

### [Tolerance-based Voxel Fusion](5866-tolerance-based-voxel-fusion.md)
A performance optimization that renders data at different resolutions in different areas of the spatial domain by fusing voxels with high tolerance values. It reduces the number of nodes by merging nearby voxels that have similar properties within a defined tolerance threshold. Choose this when rendering large scenes with varying detail requirements and when memory bandwidth is a bottleneck. See [Tolerance-based Voxel Fusion](5866-tolerance-based-voxel-fusion.md).

### [Temporal Difference Encoding](5869-temporal-difference-encoding.md)
A temporal domain compression technique where subtrees at consecutive time steps are merged if they are identical. It reduces redundancy in animated sequences by storing only the differences between frames. Choose this for dynamic scenes with high temporal coherence. See [Temporal Difference Encoding](5869-temporal-difference-encoding.md).

### Octree File I/O Format
This variant refers to the specific ASCII header and binary payload structure described in the main method. It is the standard format for the `cpu_voxel_raycaster` implementation. It is chosen when compatibility with this specific legacy CPU raycaster is required.

### Sparse Voxel DAG
An extension to SVO that merges identical nodes and redirects parent pointers to single nodes to decrease memory footprint further. It is distinct from the standard SVO encoding by introducing graph-like sharing of subtrees. Choose this when storing simple data like occlusion values where node duplication is high. It is less effective for complex data like diffuse albedo, as identical child nodes become rare, making the overhead of building the DAG unjustified [S3, unofficial].

## Operating characteristics
-   **Time Complexity**: Encoding/Decoding is linear with respect to the number of nodes and data entries, $O(n\_nodes + n\_data)$, as it involves a single pass over the file [S2, unofficial].
-   **Memory Complexity**: The memory footprint is proportional to the number of nodes and data entries stored in the `OctreeInfo` and binary buffers. The SVO structure itself avoids storing empty areas, offering significant memory savings over dense grids [S3, unofficial].
-   **Performance**: The ASCII header parsing is fast, but the binary I/O dominates the cost. The method is designed for CPU-side processing, as indicated by the aliases `encode_sparse_voxel_octree_cpu` [S1, unofficial].
-   **Strengths**: Simple format, easy to debug (ASCII header), efficient storage for sparse data.
-   **Limitations**: The ASCII header adds some overhead. The binary format is not self-describing beyond the header. The method does not include compression of the binary data itself, unlike [Octree Volume Compression](1979-octree-volume-compression.md).
-   **When to Use**: When persisting an SVO for a CPU-based raycaster or when interoperability with the `cpu_voxel_raycaster` tool is needed.
-   **When Not to Use**: When high compression ratios are required (use [Octree Volume Compression](1979-octree-volume-compression.md) or [Packed Tensor Representation](1611-packed-tensor-representation.md)), or when GPU-side direct loading is required without CPU parsing.

## Background
The method originates from the `cpu_voxel_raycaster` project by Forceflow, which implements a CPU-based raycasting engine using sparse voxel octrees [S2, unofficial]. The Sparse Voxel Octree (SVO) technique itself was popularized for voxel cone-traced global illumination (VXGI) by the paper "Voxel Cone Traced Global Illumination" (2015), which highlighted the memory efficiency of storing only occupied voxels [S3, unofficial]. The Sparse Voxel Directed Acyclic Graph (SVO DAG) extension was also discussed in the context of VXGI to further reduce memory usage by merging identical nodes [S3, unofficial]. The specific file format described here is an implementation detail of the `cpu_voxel_raycaster` repository.
