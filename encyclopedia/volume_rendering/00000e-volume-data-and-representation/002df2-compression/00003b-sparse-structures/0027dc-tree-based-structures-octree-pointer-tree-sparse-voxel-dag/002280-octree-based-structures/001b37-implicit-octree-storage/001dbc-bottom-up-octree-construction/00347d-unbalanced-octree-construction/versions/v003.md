# Unbalanced Octree Construction

Also called: Bottom-up recursive construction of an unbalanced octree

## Overview
This method constructs an adaptive-resolution octree from an array of leaf nodes by recursively grouping bounding spheres into clusters of up to eight [S1, unofficial]. It is designed for 3-manifold solids where an unbalanced octree is preferred over an unbalanced quadtree because the increased average branching factor reduces the number of interior nodes, memory footprint, and traversal time [S1, unofficial].

## How it works
**Inputs:** An array of leaf nodes representing bounding spheres of mesh primitives [S1, unofficial].
**Outputs:** A root node representing the constructed unbalanced octree [S1, unofficial].

**Data Structures:**
*   `Node`: Represents a tree node.
    *   `center`: 3D vector, center of the bounding sphere [S1, unofficial].
    *   `radius`: Scalar, radius of the bounding sphere [S1, unofficial].
    *   `field_values`: Scalar or vector, averaged from children [S1, unofficial].
    *   `boundary_label`: Integer/bitmask, combined via bitwise OR from children [S1, unofficial].
*   `I`: Integer array of size 9, tracking split indices during recursion. `I[0]` is the start index, `I[8]` is the end index, and `I[1..7]` store intermediate split points (initialized to `-1`) [S1, unofficial].

**Algorithm Steps:**
1.  **Base Case:** If the range `[i1, i2)` contains 8 or fewer leaf nodes (`i2 - i1 <= 8`), merge them directly into a single node and return [S1, unofficial].
2.  **Recursive Splitting:** If the range contains more than 8 nodes, the algorithm performs a series of binary splits to divide the nodes into up to 8 clusters [S1, unofficial].
    *   Initialize `I` with `I[0] = i1`, `I[8] = i2`, and `I[1..7] = -1` [S1, unofficial].
    *   Compute the first split point: `I[4] = Split(i1, i2)`, where `Split` bi-sects the array along the longest edge of the axis-aligned bounding box (AABB) of the nodes in the range and returns the index of the middle leaf node [S1, unofficial].
    *   Use a loop variable `N` (initially 0) to process left and right halves. For each `N`, if the sub-range `[I[N], I[N+4])` exceeds 8 nodes, split it at `I[2+N] = Split(I[N], I[N+4])` [S1, unofficial].
    *   If the left sub-range `[I[N], I[2+N])` exceeds 8 nodes, split it at `I[1+N] = Split(I[N], I[2+N])` [S1, unofficial].
    *   If the right sub-range `[I[2+N], I[N+4])` exceeds 8 nodes, split it at `I[3+N] = Split(I[2+N], I[N+4])` [S1, unofficial].
    *   Increment `N` by 4. Repeat the process for `N=4` (the right half of the original range), then terminate [S1, unofficial].
3.  **Recursive Construction:** Iterate through `I` from index 1 to 8. For each valid split point `I[i] != -1`, recursively call the build function on the range `[first, I[i])`, where `first` tracks the start of the current segment, and collect the resulting child nodes [S1, unofficial].
4.  **Merge Function:** Combine the collected child nodes (1 to 8) into a new parent node [S1, unofficial].
    *   **Center:** Simple average of the children's centers [S1, unofficial].
    *   **Field Values:** Simple average of the children's field values [S1, unofficial].
    *   **Boundary Label:** Binary OR of the children's labels [S1, unofficial].
    *   **Radius:** Derived from the bounding sphere enclosing all child spheres [S1, unofficial].

**Pseudocode:**
```python
import math

class Node:
    def __init__(self, center, radius, field_values, boundary_label):
        self.center = center
        self.radius = radius
        self.field_values = field_values
        self.boundary_label = boundary_label

def build_tree(leaf_nodes, i1, i2):
    if i2 - i1 <= 8:
        return merge_nodes(leaf_nodes[i1:i2])

    I = [-1] * 9
    I[0] = i1
    I[8] = i2
    I[4] = split_range(leaf_nodes, i1, i2)

    N = 0
    while True:
        if I[4 + N] - I[N] > 8:
            I[2 + N] = split_range(leaf_nodes, I[N], I[4 + N])
            if I[2 + N] - I[N] > 8:
                I[1 + N] = split_range(leaf_nodes, I[N], I[2 + N])
            if I[4 + N] - I[2 + N] > 8:
                I[3 + N] = split_range(leaf_nodes, I[2 + N], I[4 + N])
        N += 4
        if N == 4:
            continue
        else:
            break

    children = []
    first = I[0]
    for i in range(1, 9):
        if I[i] == -1:
            continue
        children.append(build_tree(leaf_nodes, first, I[i]))
        first = I[i]

    return merge_nodes(children)

def split_range(leaf_nodes, start_idx, end_idx):
    min_pt = [min(n.center[j] for n in leaf_nodes[start_idx:end_idx]) for j in range(3)]
    max_pt = [max(n.center[j] for n in leaf_nodes[start_idx:end_idx]) for j in range(3)]
    extents = [max_pt[j] - min_pt[j] for j in range(3)]
    axis = extents.index(max(extents))
    if max(extents) == 0:
        axis = 0  # Fallback to x-axis for degenerate AABB [G]
    indices = sorted(range(start_idx, end_idx), key=lambda k: leaf_nodes[k].center[axis])
    return indices[len(indices) // 2]

def merge_nodes(nodes):
    if not nodes:
        return None
    center = [sum(n.center[j] for n in nodes) / len(nodes) for j in range(3)]
    field_values = sum(n.field_values for n in nodes) / len(nodes)
    boundary_label = 0
    for n in nodes:
        boundary_label |= n.boundary_label
    max_r = 0
    for n in nodes:
        dist = math.sqrt(sum((center[j] - n.center[j])**2 for j in range(3)))
        r = dist + n.radius
        if r > max_r:
            max_r = r
    return Node(center, max_r, field_values, boundary_label)
```

**Edge Cases and Pitfalls:**
*   **Degenerate Input:** If all nodes in a range are identical, the bounding box has zero volume and the longest edge is undefined. The split function must fallback to a default axis (e.g., x-axis) to avoid division by zero or infinite loops [G].
*   **Radius Approximation:** The parent radius is derived from the bounding sphere of child spheres. Simple averaging of centers combined with a max-distance radius calculation may include empty space if children are widely separated [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. [S1, unofficial].
*   **Memory Complexity:** The higher branching factor (up to 8) reduces the number of interior nodes compared to a quadtree, leading to a smaller memory footprint [S1, unofficial].
*   **Strengths:** Faster traversal times and more compact data structures for 3-manifold solids compared to unbalanced quadtrees [S1, unofficial].
*   **Limitations:** Not given in the sources. [S1, unofficial].

## Background
This method is part of a pipeline for constructing a "Solid" mesh representation from triangulated 3-manifold data [S1, unofficial]. The use of an unbalanced octree is motivated by the 3D nature of the data, where an octree provides a better balance between spatial resolution and memory usage than a quadtree [S1, unofficial].
