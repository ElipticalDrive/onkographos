# Adaptive Octree Encoding

Also called: Adaptive Octree Representation for TB-AMR, Compact Sparse Octree, Sparse Octree for AMR

## Overview
Adaptive Octree Encoding is a memory layout for storing Tree-Based Adaptive Mesh Refinement (TB-AMR) data as an adaptive-resolution octree to preserve hierarchy information, enabling faster ray traversal and higher quality rendering than flattening to unstructured or rectilinear grids [S1]. Unlike Sparse Voxel Octrees (SVO) which typically store uniform voxels, this structure supports storing voxels of different resolutions to handle AMR data [S1]. It builds on [SVO Node Encoding](2705-svo-node-encoding.md) by extending the concept of compact node descriptors to support variable refinement levels inherent to AMR simulations.

## How it works
**Inputs and Outputs:**
*   **Input:** Tree-Based AMR (TB-AMR) data, specifically cell-centered data with a refinement factor of two [S1].
*   **Output:** A contiguous array of node descriptors and value ranges, representing the adaptive octree hierarchy [S1].

**Data Structures:**
The structure consists of two main components stored in contiguous arrays:
1.  **Node Descriptors:** A 64-bit integer per node.
    *   **Leaf Nodes:** Pack the single-precision data value directly in the descriptor [S1].
    *   **Internal Nodes:** Encode existence and location of children.
2.  **Value Ranges:** An additional 64 bits per node (two 32-bit floats) storing the minimum and maximum data values of the node's children (or the leaf value itself) [S1]. This enables empty-space skipping and active-cell filtering [S1].

**64-bit Descriptor Layout:**
The 64-bit descriptor is divided into three fields [S1]:
*   **Bits 0-7 (8 bits):** Child mask. Bit $i$ is 1 if the $i$-th child exists, 0 otherwise.
*   **Bits 8-62 (55 bits):** Offset to children in the array.
*   **Bit 63 (1 bit):** Leaf flag.

**Numbered Steps:**
1.  **Construct Octree:** Build the octree from TB-AMR data using a top-down serial builder [S1]. The framework assumes a 2:1 refinement ratio between parent and child cells, which is the most frequently found factor in practice [S1].
2.  **Encode Internal Nodes:** For each internal node, determine which of the 8 potential children exist. Set the corresponding bits in the 8-bit child mask. Calculate the offset to the first child in the contiguous array. Set the leaf flag to 0.
3.  **Encode Leaf Nodes:** For each leaf node, pack the single-precision data value into the descriptor. Set the leaf flag to 1. The offset and mask fields are unused or zeroed [S1].
4.  **Store Value Ranges:** For every node (internal and leaf), store the min/max value range in the separate 64-bit range array. Note: The current implementation redundantly stores ranges for leaf nodes, though this is not strictly required [S1].
5.  **Serialize:** Output the array of nodes and ranges to a binary file for use by the renderer [S1].

**Formulas:**
*   **Child Fetching:** To fetch a specific child node $c$ (where $c \in [0, 7]$) from an internal node:
    $$ \text{ChildIndex} = \text{Offset} + \sum_{i=0}^{c-1} \text{Mask}[i] $$
    Where $\text{Mask}[i]$ is the $i$-th bit of the child mask [S1].

**Parameters:**
*   **Refinement Factor:** 2 [S1].
*   **Descriptor Size:** 64 bits [S1].
*   **Value Range Size:** 64 bits (2 $\times$ 32-bit floats) [S1].

**Edge Cases and Pitfalls:**
*   **Redundancy:** Leaf nodes redundantly store value ranges in the current approach. This is not required and optimized layouts are possible [S1].
*   **Refinement Assumption:** The method assumes a refinement factor of two. While larger factors exist, they are less common [S1].

**Pseudocode:**
```python
# Data structures
class NodeDescriptor:
    mask: int      # 8-bit integer
    offset: int    # 55-bit integer
    is_leaf: bool  # 1-bit flag
    value: float   # Single precision, used only if is_leaf

class NodeRange:
    min_val: float
    max_val: float

def encode_amr_to_octree(amr_cells):
    """
    Encodes TB-AMR data into the adaptive octree layout.
    Assumes a 2:1 refinement ratio.
    """
    nodes = []
    ranges = []
    
    # Placeholder for actual tree construction logic
    # This function assumes a pre-existing tree structure `tree`
    # where each node has children and a value.
    tree = build_adaptive_octree(amr_cells)
    
    # Traverse tree and encode
    for node in tree.traverse():
        if node.is_leaf:
            # Pack single precision value into descriptor
            # Note: Exact bit-packing of float into 64-bit int depends on implementation
            # Here we assume a helper to pack float into the lower bits
            descriptor = pack_float_to_descriptor(node.value)
            descriptor.is_leaf = True
            descriptor.mask = 0
            descriptor.offset = 0
            nodes.append(descriptor)
            
            # Store range (redundant but done in current implementation)
            ranges.append(NodeRange(node.value, node.value))
        else:
            # Internal node
            # Calculate mask and offset
            mask = 0
            child_count = 0
            for i in range(8):
                if node.children[i] is not None:
                    mask |= (1 << i)
                    child_count += 1
            
            # Offset is relative to the start of children array
            # In a flat array, this would be the index of the first child
            # For this encoding, we store the offset to the first child
            # The actual offset calculation depends on the serialization order
            # Assuming children are stored contiguously after the parent's descriptor
            # and we have a global index map.
            first_child_index = get_first_child_index(node)
            
            descriptor = NodeDescriptor()
            descriptor.mask = mask & 0xFF
            descriptor.offset = first_child_index
            descriptor.is_leaf = False
            descriptor.value = 0.0 # Unused
            nodes.append(descriptor)
            
            # Store range
            ranges.append(NodeRange(node.min_val, node.max_val))
            
    return nodes, ranges

def fetch_child(node_descriptor, child_index):
    """
    Fetches a specific child node from the array based on the descriptor.
    """
    if node_descriptor.is_leaf:
        raise ValueError("Cannot fetch child of a leaf node")
    
    # Count existing children before the desired one
    count_before = 0
    for i in range(child_index):
        if (node_descriptor.mask >> i) & 1:
            count_before += 1
            
    # Calculate absolute index of the child
    child_absolute_index = node_descriptor.offset + count_before
    return nodes[child_absolute_index]
```

## Operating characteristics
*   **Time Complexity:** Ray traversal is logarithmic-time due to the hierarchical representation [S1].
*   **Memory Complexity:** Each node uses 64 bits for the descriptor and 64 bits for the value range, totaling 128 bits per node. This is more compact than storing explicit pointers but includes redundancy for leaf nodes [S1].
*   **Strengths:** Preserves AMR hierarchy, enabling faster and higher quality rendering than flattening to unstructured or rectilinear grids. Supports variable resolution voxels. Maps well to parallel ray traversal on multicore CPUs [S1].
*   **Limitations:** Assumes a 2:1 refinement ratio. Redundant storage of value ranges for leaf nodes increases memory usage unnecessarily [S1].
*   **When to Use:** Interactive high-quality visualization of Tree-Based AMR data, especially when using ray tracing [S1].
*   **When Not to Use:** When the AMR data does not follow a 2:1 refinement ratio, or when memory is extremely constrained and the redundancy of leaf ranges is unacceptable [S1].

## Background
The method was introduced by Wan et al. in 2020 for efficient ray-tracing based visualization of TB-AMR data in the OSPRay library [S1]. It addresses the limitations of previous AMR rendering approaches, such as cell projection [MC97], 3D slicing [KH02], and resampling to rectilinear grids, which either discard hierarchy information or suffer from lower quality and performance [S1]. The approach is motivated by the prevalence of 2:1 refinement ratios in popular TB-AMR frameworks like Paramesh and p4est [S1].
