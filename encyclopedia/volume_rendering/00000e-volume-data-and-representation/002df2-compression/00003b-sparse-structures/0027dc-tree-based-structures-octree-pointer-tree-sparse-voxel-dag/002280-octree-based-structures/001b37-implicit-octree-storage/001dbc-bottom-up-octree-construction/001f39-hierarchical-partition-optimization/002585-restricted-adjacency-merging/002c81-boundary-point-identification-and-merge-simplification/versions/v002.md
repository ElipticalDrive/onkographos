# Boundary Point Identification and Merge Simplification

Also called: Boundary Point Identification, Merge Simplification

## Overview
Boundary Point Identification and Merge Simplification is a post-processing step in parallel isosurface extraction that resolves geometric inconsistencies at the interfaces between independently processed sub-blocks. It solves the problem of non-manifold geometry and visual artifacts caused by numerical discrepancies in vertex extraction when adjacent blocks generate slightly different coordinates for the same boundary points. It sets itself apart from general mesh simplification by specifically targeting the "pasted area" where blocks meet, using topological properties of the marching cubes algorithm to identify coincident points and applying a conservative error criterion to ensure the merged surface remains within the original extraction tolerance.

## How it works
The method operates on the set of isosurface triangles generated by independent workers for each sub-block. The goal is to merge these disjoint surfaces into a single, watertight mesh.

### Inputs and Outputs
*   **Input:** A list of sub-blocks, each containing a set of extracted triangles (vertices and connectivity). Each triangle vertex has 3D coordinates $(x, y, z)$.
*   **Output:** A unified list of triangles representing the global isosurface, with boundary vertices merged and simplified.

### Data Structures
*   **Vertex:** A structure containing floating-point coordinates $(x, y, z)$ and a unique global ID.
*   **Triangle:** A structure containing three vertex indices.
*   **Boundary Edge:** A pair of vertices $(v_a, v_b)$ that lie on the shared boundary between two adjacent sub-blocks.

### Steps

1.  **Identify Common Points:**
    For every pair of adjacent sub-blocks, identify vertices that lie on their shared boundary. Due to floating-point precision errors, vertices extracted independently by different workers may have slightly different coordinates for the same geometric location. Simple coordinate comparison is insufficient. Instead, leverage the property of the marching cubes algorithm: a cell edge generates either zero or one intersection point. Therefore, if two vertices from adjacent blocks lie on the same cell edge, they are topologically identical and must be merged.
    *   *Implementation Note:* Group vertices by the cell edge they belong to. Vertices sharing the same edge index are candidates for merging.

2.  **Merge Points:**
    Merge the identified common points. This involves selecting a representative coordinate (e.g., the average of the coincident vertices) and updating all triangle references to point to the single merged vertex. This eliminates duplicate vertices and ensures connectivity across block boundaries.

3.  **Simplify the Pasted Area:**
    Apply simplification to the triangles located at the merged boundaries to remove artifacts caused by the "time lag" or independent processing. The simplification uses the same error criterion $E_0$ as the initial surface extraction.
    *   **Error Criterion $E_0$:** The maximum allowed distance between the simplified surface and the original isosurface.
    *   **Edge Contraction Guard:** When considering the contraction of an edge $ab$ during simplification, the contraction is **prevented** if the sphere centered on the midpoint of $ab$ with radius $rad(c)$ is not totally included in the merged blocks. Here, $rad(c)$ is the radius associated with the cell $c$ containing the edge. This ensures that the simplification does not introduce geometry outside the valid domain of the merged blocks, preserving the topological integrity of the boundary.

4.  **Dump Components:**
    Once all merges and simplifications are complete, dump the finished global mesh components to disk or pass them to the rendering pipeline.

### Pseudocode

```python
def boundary_point_identification_and_merge_simplification(sub_blocks):
    """
    sub_blocks: List of objects, each containing:
        - id: int
        - vertices: List of Vertex objects (x, y, z)
        - triangles: List of Triangle objects (v1_idx, v2_idx, v3_idx)
        - boundary_edges: List of Edge objects (cell_edge_id, local_vertex_indices)
    """
    global_vertices = []
    vertex_map = {}  # Maps (cell_edge_id, normalized_position) -> global_vertex_index
    
    # Step 1 & 2: Identify and Merge Common Points
    # We iterate over all boundary edges shared between adjacent blocks.
    # Since adjacency is implicit in the grid, we process all boundary edges.
    
    for block in sub_blocks:
        for edge in block.boundary_edges:
            cell_edge_id = edge.cell_edge_id
            local_vertex_indices = edge.local_vertex_indices
            
            # For each vertex on this boundary edge in this block
            for local_idx in local_vertex_indices:
                vertex = block.vertices[local_idx]
                
                # Create a key based on the cell edge.
                # In a real implementation, we might need to normalize the position
                # or use a spatial hash to handle the "identical" check robustly.
                # The source states: "two points belonging to common cell edges are identical"
                key = (cell_edge_id, vertex.x, vertex.y, vertex.z)
                
                if key not in vertex_map:
                    # Create new global vertex
                    global_idx = len(global_vertices)
                    global_vertices.append(Vertex(vertex.x, vertex.y, vertex.z))
                    vertex_map[key] = global_idx
                else:
                    global_idx = vertex_map[key]
                
                # Store mapping from local block index to global index
                # This requires a block-local to global mapping structure
                block.vertex_to_global[local_idx] = global_idx

    # Step 3: Simplify the pasted area
    # We need to identify triangles that are on the boundary
    boundary_triangles = []
    for block in sub_blocks:
        for tri in block.triangles:
            # Check if any vertex of the triangle is on a boundary
            is_boundary = False
            for local_idx in [tri.v1, tri.v2, tri.v3]:
                if local_idx in block.vertex_to_global:
                    # Check if the global vertex was part of a merge (i.e., had a neighbor)
                    # This logic depends on how vertex_map is populated.
                    # A simpler heuristic: if the triangle has any vertex that was 
                    # identified as a boundary vertex in Step 1.
                    is_boundary = True
                    break
            
            if is_boundary:
                # Convert local indices to global
                global_v1 = block.vertex_to_global[tri.v1]
                global_v2 = block.vertex_to_global[tri.v2]
                global_v3 = block.vertex_to_global[tri.v3]
                
                v1 = global_vertices[global_v1]
                v2 = global_vertices[global_v2]
                v3 = global_vertices[global_v3]
                
                boundary_triangles.append(Triangle(v1, v2, v3))

    # Apply simplification with error criterion E0
    # The source specifies a guard for edge contraction:
    # "Prevent edge contraction ab ... as long as the sphere centered on the middle 
    # of ab with radius rad(c) is not totally included in the merged blocks."
    
    simplified_triangles = simplify_mesh(boundary_triangles, error_criterion=E0, guard_function=boundary_guard)
    
    # Step 4: Dump finished components
    final_mesh = Mesh(global_vertices, simplified_triangles)
    return final_mesh

def boundary_guard(edge_ab, cell_radius_rad_c, merged_blocks):
    """
    Returns True if the edge contraction is ALLOWED.
    Returns False if the edge contraction is PREVENTED.
    """
    midpoint = (edge_ab.v1 + edge_ab.v2) / 2.0
    sphere = Sphere(center=midpoint, radius=cell_radius_rad_c)
    
    # Check if sphere is totally included in merged blocks
    # This requires checking if the sphere volume is contained within the union of the 
    # geometries of the merged blocks.
    if not sphere.is_contained_in(merged_blocks):
        return False  # Prevent contraction
    
    return True  # Allow contraction
```

### Parameters
*   **$E_0$:** The error criterion for simplification. Typically the same value used during the initial marching cubes extraction. Not given in the sources.
*   **$rad(c)$:** The radius associated with cell $c$. Not given in the sources.

### Edge Cases and Pitfalls
*   **Numerical Inaccuracy:** Simple coordinate comparison fails to identify common points due to floating-point errors. The method relies on the topological property of marching cubes (one point per edge) rather than geometric proximity.
*   **Boundary Artifacts:** If simplification is applied naively near block boundaries, it can lead to poor triangulation quality or non-manifold edges. The guard function prevents this by ensuring the simplification sphere remains within the valid block domain.
*   **Time Lag Effect:** Independent processing can cause a "time lag" in refinement, leading to visible seams. The simplification step mitigates this by merging and smoothing the boundary triangles.

## Subtopics

### [Valley Cell Simplification](7572-valley-cell-simplification.md)
Valley Cell Simplification is a topological noise reduction method that removes insignificant "valley cells" from a decomposition of a scalar field (typically a 2D density plot for transfer function design) by merging adjacent cells based on boundary persistence. It solves the problem of over-segmentation caused by noise, where small, semantically irrelevant features fragment the data space. Unlike standard watershed transformations which produce a flat partition, this method operates hierarchically, allowing the user to control the level of detail via a persistence threshold, effectively filtering out noise while preserving significant peaks.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Ensures watertight, manifold meshes from parallel extraction; handles numerical precision issues robustly; prevents topological errors at block boundaries.
*   **Limitations:** Requires post-processing step; depends on the correctness of the marching cubes implementation (specifically the edge-point property).
*   **When to use:** When using parallel isosurface extraction with block-based decomposition and marching cubes.
*   **When not to use:** When using a single-threaded extraction or a method that does not produce boundary vertices (e.g., ray marching without block decomposition).

## Background
The method originates from the work on parallel extraction and simplification of large isosurfaces using an extended tandem algorithm [S1]. It addresses the challenges of scaling isosurface extraction to large datasets by dividing the volume into sub-blocks processed by different workers. The need for boundary point identification arises from the inherent parallelism, where independent workers may generate slightly different vertices for the same geometric location. The merge simplification step ensures that the final global mesh is consistent and visually correct.
