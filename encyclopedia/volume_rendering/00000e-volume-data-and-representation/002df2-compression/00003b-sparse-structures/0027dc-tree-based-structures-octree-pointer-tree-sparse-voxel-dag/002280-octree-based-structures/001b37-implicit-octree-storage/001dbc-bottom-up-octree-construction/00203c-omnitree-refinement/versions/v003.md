# Omnitree Refinement

Also called: Anisotropic refinement, Omnitree construction

## Overview
Omnitree refinement transforms an initial hierarchical dyadic partition of a $d$-dimensional Cartesian domain into a target partition with higher resolution in specific dimensions [S1, unofficial]. It solves the problem of anisotropically increasing the granularity of a sparse voxel representation by attaching refinement markers to nodes and propagating them through the tree structure [S1, unofficial]. The method explicitly supports per-dimension refinement levels ($\vec{m} \in \mathbb{N}^d$), allowing for non-cubic, rectangular subdomains [S1, unofficial]. It builds on [Bottom-up Octree Construction](1590-bottom-up-octree-construction.md) by providing the mechanism to adjust the topology of the resulting tree after initial construction or during dynamic updates [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
1. An initial omnitree $T$ with $N$ nodes, linearized in Z-curve order [S1, unofficial].
2. A set of refinement markers $\vec{m}(v) \in \mathbb{N}^d$ attached to nodes $v \in T$ [S1, unofficial].
3. The dimensionality $d$ [S1, unofficial].

**Outputs:**
1. A target omnitree $T'$ with $N'$ nodes, representing the refined partition [S1, unofficial].
2. An index mapping $M: \{0, \dots, N-1\} \rightarrow \mathcal{P}(\{0, \dots, N'-1\})$ that maps initial nodes to their corresponding regions in the target tree [S1, unofficial].

### Data Structures
The omnitree is stored as a binary descriptor linearized via Z-curve order [S1, unofficial].
*   **Splitting Label ($\vec{b}(v)$):** For a node at index $i$, the splitting label is a tuple of $d$ bits. $\vec{b}(v)_j = 1$ indicates a bisection in dimension $j$. $\vec{b}(v) = \vec{0}$ denotes a leaf node [S1, unofficial].
*   **Marker ($\vec{m}(v)$):** A vector of $d$ non-negative integers. $\vec{m}(v)_j$ specifies the number of *additional* refinement levels required in dimension $j$ [S1, unofficial].
*   **Rectangle ($Q_{\vec{i},\vec{\ell}}$):** Each node maps to a hyper-rectangle defined by per-dimension refinement levels $\vec{\ell} \in \mathbb{N}^d$ and index $\vec{i}$ [S1, unofficial]. The extent in dimension $j$ is $2^{-\ell_j}$ [S1, unofficial].

### Algorithm Steps
Refinement proceeds in four distinct phases [S1, unofficial]:

1.  **Marker Attachment:**
    Assign the initial refinement markers $\vec{m}(v)$ to each node $v$ in the input tree $T$. If no specific refinement is requested for a node, $\vec{m}(v) = \vec{0}$ [S1, unofficial].

2.  **Bottom-Up Sweep:**
    Propagate markers from children to parents to consolidate refinement requirements [S1, unofficial].
    *   For each node $v$ and each dimension $j$:
        *   If all siblings of $v$ share a common positive marker component $m_j > 0$, or if the siblings already possess a split in dimension $j$ ($\vec{b}(v)_j = 1$), the marker migrates upward [S1, unofficial].
        *   If siblings already have a split ($\vec{b}(v)_j = 1$), this is compensated by attaching a negative marker to the parent to prevent over-refinement [S1, unofficial].
        *   The marker value at the parent is updated to reflect the maximum required refinement level among siblings, adjusted for existing splits [S1, unofficial].

3.  **Top-Down Sweep:**
    Correct markers that were propagated too high in the tree [S1, unofficial].
    *   Traverse the tree from root to leaves [S1, unofficial].
    *   If a node carries a marker $\vec{m}(v)$ that cannot be resolved by its current children (e.g., the children are leaves but $m_j > 0$), push the excess refinement down to the children [S1, unofficial].
    *   This ensures that refinement levels are applied at the deepest possible nodes that still maintain the hierarchical structure [S1, unofficial].

4.  **Tree Construction:**
    Build the target tree $T'$ using a preorder depth-first traversal [S1, unofficial].
    *   For each node $v$ in the initial tree $T$:
        *   Locate the initial node $s$ whose rectangle covers the current target rectangle $q$ [S1, unofficial].
        *   Determine the target splitting label $\vec{b}(v')$ based on the accumulated markers [S1, unofficial].
        *   If $\vec{b}(v') \neq \vec{0}$, create children by substituting trailing $\lambda$ entries in $\vec{b}(v)$ with 0 or 1, and recurse [S1, unofficial].
        *   If $v$ is a leaf in the initial tree, expand the subtree directly from its marker $\vec{m}(v)$ [S1, unofficial].
    *   **Structural Changes:**
        *   Positive markers increase branching, potentially requiring the adoption of grandchildren nodes to maintain the Z-curve order [S1, unofficial].
        *   Negative markers decrease branching, requiring node culling (merging children back into the parent) [S1, unofficial].

        markers: Dict mapping node index to tuple of d ints (refinement request)
        d: int (dimensionality)

        target_tree: List of nodes in Z-curve order
        mapping: Dict mapping initial index to list of target indices
    """

    for node in initial_tree:
        idx = node['idx']
        node['m'] = markers.get(idx, (0,) * d)
        
    # Step 2: Bottom-Up Sweep
    # Process nodes in reverse Z-curve order (leaves to root)

        siblings = get_siblings(node['idx'], initial_tree)

            all_siblings_marker = all(s['m'][dim] == m_dim for s in siblings)

                if all_siblings_split:
                    # Compensate with negative marker
                    parent['m'] = list(parent['m'])
                    parent['m'][dim] = parent['m'][dim] - 1
                    parent['m'] = tuple(parent['m'])
                else:
                    parent['m'] = list(parent['m'])
                    parent['m'][dim] = max(parent['m'][dim], m_dim)
                    parent['m'] = tuple(parent['m'])
                    
    # Step 3: Top-Down Sweep
    # Process nodes in Z-curve order (root to leaves)
    sorted_nodes = sorted(initial_tree, key=lambda n: n['idx'])
    
    for node in sorted_nodes:
        children = get_children(node['idx'], initial_tree)
        if not children:

                    child['m'] = tuple(child['m'])

                node['m'][dim] = 0
                node['m'] = tuple(node['m'])

            child_b = list(b)
            for k, dim in enumerate(split_dims):

            children.append(tuple(child_b))
        return children

        b = node['b']
        m = node['m']

        target_b = tuple(max(b[j], m[j]) for j in range(d))

            'b': target_b,

        num_targets = num_children(target_b)
        mapping[idx] = list(range(target_index, target_index + num_targets))

    while True:

        for node in normalized_tree:

                continue

### Normalization
The algorithm guarantees a valid omnitree but not necessarily the unique normalized representation [S1, unofficial]. Normalization ensures that splits are gathered as high in the tree as possible [S1, unofficial].
*   To normalize, detect nodes that violate the uniqueness condition (i.e., a node has a split in dimension $j$ but its parent also has a split in dimension $j$) [S1, unofficial].
*   Attach a positive marker to the violating node and negative markers to its children [S1, unofficial].
*   Apply the Tree Construction step again [S1, unofficial].
*   Repeat until no nodes violate the uniqueness condition [S1, unofficial].

### Index Mapping
The mapping $M$ from initial tree $T$ to target tree $T'$ is computed during construction [S1, unofficial].
*   For a refined leaf node $v_i$ with target refinement $\vec{b}(v_i)$, the mapping is:
    $$ M[i] = \{i', i'+1, \dots, i'+2^{|\vec{b}(v_i)|}\} $$
    where $i'$ is the target index of $v_i$ [S1, unofficial].
*   For all other nodes $j > i$, the shift is $\delta = 2^{|\vec{b}(v_i)|}$:
    $$ M[j] = \{j + \delta\} $$
    This accounts for the expansion of the tree due to refinement [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision:** Marker values must be handled as integers. Negative markers are used for compensation and must not result in negative final marker values at leaves [S1, unofficial].
*   **Boundaries:** The domain is normalized to $(0,1)^d$. Refinement levels $\vec{\ell}$ must ensure that indices $\vec{i}$ remain within bounds $\{0, \dots, 2^{\ell_j}-1\}$ [S1, unofficial].
*   **Degenerate Input:** If the initial tree is empty, the output is empty. If markers are all zero, the output tree is identical to the input [G].
*   **Uniqueness:** Failure to normalize results in a valid but non-unique tree, which may cause inconsistencies in downstream applications like compression or rendering [S1, unofficial].

*   **Degenerate Input:** If the initial tree is empty, the output is empty. If markers are all zero, the output tree is identical to the input [G].
*   **Uniqueness:** Failure to normalize results in a valid but non-unique tree, which may cause inconsistencies in downstream applications like compression or rendering [S1, unofficial].

## Background
Omnitrees were introduced to provide a flexible representation for hierarchical dyadic partitions in $d$-dimensions [S1, unofficial]. The method is described in "Towards Fully Dynamic Omnitrees: Moment-Conserving Anisotropic Compression With Wavelets" [S1, unofficial]. The approach allows for dynamic updates and anisotropic compression, making it suitable for applications such as volume rendering and scientific visualization where data may have varying levels of detail in different dimensions [S1, unofficial].
