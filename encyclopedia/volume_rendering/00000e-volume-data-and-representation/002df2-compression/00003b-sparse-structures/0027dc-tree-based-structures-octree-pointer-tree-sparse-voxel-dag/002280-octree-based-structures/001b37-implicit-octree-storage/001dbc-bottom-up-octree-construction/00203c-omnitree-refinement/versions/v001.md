# Omnitree Refinement

Also called: Anisotropic refinement, Omnitree construction

## Overview
Omnitree refinement is a method for transforming an initial hierarchical dyadic partition of a $d$-dimensional Cartesian domain into a target partition with higher resolution in specific dimensions. It solves the problem of anisotropically increasing the granularity of a sparse voxel representation by attaching refinement markers to nodes and propagating them through the tree structure. Unlike sibling methods that may rely on isotropic splitting or global restructuring, omnitree refinement explicitly supports per-dimension refinement levels ($\vec{m} \in \mathbb{N}^d$), allowing for non-cubic, rectangular subdomains. It builds on [Bottom-up Octree Construction](1590-bottom-up-octree-construction.md) by providing the mechanism to adjust the topology of the resulting tree after initial construction or during dynamic updates.

## How it works
### Inputs and Outputs
**Inputs:**
1.  An initial omnitree $T$ with $N$ nodes, linearized in Z-curve order.
2.  A set of refinement markers $\vec{m}(v) \in \mathbb{N}^d$ attached to nodes $v \in T$. The default marker is $\vec{0}$.
3.  The dimensionality $d$ (typically 3 for volume rendering).

**Outputs:**
1.  A target omnitree $T'$ with $N'$ nodes, representing the refined partition.
2.  An index mapping $M: \{0, \dots, N-1\} \rightarrow \mathcal{P}(\{0, \dots, N'-1\})$ that maps initial nodes to their corresponding regions in the target tree.

### Data Structures
The omnitree is stored as a binary descriptor linearized via Z-curve order.
*   **Splitting Label ($\vec{b}(v)$):** For a node at index $i$, the splitting label is a tuple of $d$ bits. $\vec{b}(v)_j = 1$ indicates a bisection in dimension $j$. $\vec{b}(v) = \vec{0}$ denotes a leaf node.
*   **Marker ($\vec{m}(v)$):** A vector of $d$ non-negative integers. $\vec{m}(v)_j$ specifies the number of *additional* refinement levels required in dimension $j$.
*   **Rectangle ($Q_{\vec{i},\vec{\ell}}$):** Each node maps to a hyper-rectangle defined by per-dimension refinement levels $\vec{\ell} \in \mathbb{N}^d$ and index $\vec{i}$. The extent in dimension $j$ is $2^{-\ell_j}$.

### Algorithm Steps
Refinement proceeds in four distinct phases:

1.  **Marker Attachment:**
    Assign the initial refinement markers $\vec{m}(v)$ to each node $v$ in the input tree $T$. If no specific refinement is requested for a node, $\vec{m}(v) = \vec{0}$.

2.  **Bottom-Up Sweep:**
    Propagate markers from children to parents to consolidate refinement requirements.
    *   For each node $v$ and each dimension $j$:
        *   If all siblings of $v$ share a common positive marker component $m_j > 0$, or if the siblings already possess a split in dimension $j$ ($\vec{b}(v)_j = 1$), the marker migrates upward.
        *   If siblings already have a split ($\vec{b}(v)_j = 1$), this is compensated by attaching a negative marker to the parent to prevent over-refinement. Specifically, if a split exists, the parent receives a marker adjustment to account for the existing division.
        *   The marker value at the parent is updated to reflect the maximum required refinement level among siblings, adjusted for existing splits.

3.  **Top-Down Sweep:**
    Correct markers that were propagated too high in the tree.
    *   Traverse the tree from root to leaves.
    *   If a node carries a marker $\vec{m}(v)$ that cannot be resolved by its current children (e.g., the children are leaves but $m_j > 0$), push the excess refinement down to the children.
    *   This ensures that refinement levels are applied at the deepest possible nodes that still maintain the hierarchical structure.

4.  **Tree Construction:**
    Build the target tree $T'$ using a preorder depth-first traversal.
    *   For each node $v$ in the initial tree $T$:
        *   Locate the initial node $s$ whose rectangle covers the current target rectangle $q$.
        *   Determine the target splitting label $\vec{b}(v')$ based on the accumulated markers.
        *   If $\vec{b}(v') \neq \vec{0}$, create children by substituting trailing $\lambda$ entries in $\vec{b}(v)$ with 0 or 1.
        *   If $v$ is a leaf in the initial tree, expand the subtree directly from its marker $\vec{m}(v)$.
    *   **Structural Changes:**
        *   Positive markers increase branching, potentially requiring the adoption of grandchildren nodes to maintain the Z-curve order.
        *   Negative markers decrease branching, requiring node culling (merging children back into the parent).

### Normalization
The algorithm guarantees a valid omnitree but not necessarily the unique normalized representation. Normalization ensures that splits are gathered as high in the tree as possible.
*   To normalize, detect nodes that violate the uniqueness condition (i.e., a node has a split in dimension $j$ but its parent also has a split in dimension $j$).
*   Attach a positive marker to the violating node and negative markers to its children.
*   Apply the Tree Construction step again.
*   Repeat until no nodes violate the uniqueness condition.

### Index Mapping
The mapping $M$ from initial tree $T$ to target tree $T'$ is computed during construction.
*   For a refined leaf node $v_i$ with target refinement $\vec{b}(v_i)$, the mapping is:
    $$ M[i] = \{i', i'+1, \dots, i'+2^{|\vec{b}(v_i)|}\} $$
    where $i'$ is the target index of $v_i$.
*   For all other nodes $j > i$, the shift is $\delta = 2^{|\vec{b}(v_i)|}$:
    $$ M[j] = \{j + \delta\} $$
    This accounts for the expansion of the tree due to refinement.

### Edge Cases and Pitfalls
*   **Precision:** Marker values must be handled as integers. Negative markers are used for compensation and must not result in negative final marker values at leaves.
*   **Boundaries:** The domain is normalized to $(0,1)^d$. Refinement levels $\vec{\ell}$ must ensure that indices $\vec{i}$ remain within bounds $\{0, \dots, 2^{\ell_j}-1\}$.
*   **Degenerate Input:** If the initial tree is empty, the output is empty. If markers are all zero, the output tree is identical to the input.
*   **Uniqueness:** Failure to normalize results in a valid but non-unique tree, which may cause inconsistencies in downstream applications like compression or rendering.

## Operating characteristics
*   **Time Complexity:** The refinement process involves a bottom-up and top-down sweep, which is $O(N)$ where $N$ is the number of nodes in the initial tree. Tree construction is also $O(N')$ where $N'$ is the number of nodes in the target tree. Normalization may require multiple passes, but typically converges quickly.
*   **Memory Complexity:** The output tree requires $O(N')$ space for the splitting labels and $O(L')$ space for leaf data, where $L'$ is the number of leaves. The mapping $M$ requires $O(N)$ space.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales linearly with the number of nodes. Anisotropic refinement allows for efficient handling of non-cubic features, potentially reducing $N'$ compared to isotropic refinement for elongated structures.
*   **Strengths:** Supports anisotropic refinement, allowing for efficient representation of non-cubic features. Provides a unique normalized representation.
*   **Limitations:** Requires careful handling of markers and normalization. The Z-curve linearization can complicate parent-child lookups.
*   **When to use:** When anisotropic refinement is needed, or when dynamic updates to the tree structure are required.
*   **When not to use:** When isotropic refinement is sufficient, or when the overhead of marker management is prohibitive.

## Background
Omnitrees were introduced to provide a flexible representation for hierarchical dyadic partitions in $d$-dimensions. The method is described in "Towards Fully Dynamic Omnitrees: Moment-Conserving Anisotropic Compression With Wavelets" [S1, unofficial]. The approach allows for dynamic updates and anisotropic compression, making it suitable for applications such as volume rendering and scientific visualization where data may have varying levels of detail in different dimensions.
