# Octree Compaction & Construction

Also called: Binvox Octree Compaction, Compact Octree Layout

## Overview
This method converts a dynamically allocated, pointer-heavy octree into a dense, cache-friendly contiguous memory layout [S1, unofficial]. It solves the problem of poor spatial locality and high memory overhead associated with traditional pointer-based tree structures by computing relative offsets for children and siblings [S1, unofficial]. It sets itself apart from sibling methods like [Min/Max Tree Construction](1623-min-max-tree-construction.md) by focusing specifically on the binary encoding of validity/filled masks and the compact storage of child pointers, rather than just hierarchical aggregation [S1, unofficial].

## How it works
The method operates in two phases: a top-down pass to compute the required memory size and pointer offsets, and a bottom-up pass to write the compacted nodes into the allocated buffer [S1, unofficial].

### Inputs and Outputs
- **Input**: A root node of a dynamically allocated octree where each node contains an array of 8 child pointers and a type enum (`NT_PARTIAL` or `NT_FILLED`) [S1, unofficial].
- **Output**: A contiguous array of `CNode` structures and a parallel far-pointer table [S1, unofficial].

### Data Structures
The compacted node `CNode` layout is not explicitly defined in terms of byte offsets in the sources, but the fields are [S1, unofficial]:
- `valid_mask`: 8-bit integer. Bit $i$ is set if child $i$ exists.
- `leaf_mask`: 8-bit integer. Bit $i$ is set if child $i$ is a filled leaf (`NT_FILLED`).
- `child_ptr`: Integer storing either a short relative offset or a far pointer index. The sources imply a 16-bit or 32-bit integer where bit 15 distinguishes short vs. far pointers [S1, unofficial].
- `far_ptr_table`: Array storing the absolute or larger relative offsets for far references [S1, unofficial].

### Parameters
- `_shortPtrTop`: Threshold for short vs. far pointer encoding. Exact numeric value not specified in the sources [S1, unofficial].
- `NT_PARTIAL`: Enum value indicating a node has children [S1, unofficial].
- `NT_FILLED`: Enum value indicating a solid leaf node [S1, unofficial].

### Algorithm Steps

1. **Initialization**: Set `rootNode->farAdr = 0` and `rootNode->childAdr = 0` [S1, unofficial].
2. **Size Calculation**: Call `compactAllocate(rootNode, 1)` to compute the total `dataSize` required [S1, unofficial].
3. **Allocation**: Allocate `data = (CNode*)malloc(dataSize * sizeof(CNode))` and a `far_ptr_table` of the same size [S1, unofficial].
4. **Compaction**: Call `compactNode(rootNode, data, far_ptr_table, pos_ref)` to fill the `data` array [S1, unofficial].

#### `compactAllocate(node, pos)`
This function computes the memory footprint and sets up far pointer addresses [S1, unofficial].
1. Iterate $i$ from 0 to 7 (children):
   - Reset `node->children[i]->farAdr = 0` and `node->children[i]->childAdr = 0`.
   - If `node->children[i]` exists and `node->children[i].type == NT_PARTIAL`:
     - Recursively call `pos = compactAllocate(node->children[i], pos)`.
2. **Far Pointer Check**: Iterate $i$ from 0 to 7:
   - If `node->children[i]` exists and `node->children[i].childAdr` is non-zero:
     - Compute `gchildAdrMax = pos - node->children[i].childAdr + 16`.
     - If `gchildAdrMax > _shortPtrTop`:
       - Set `node->children[i].farAdr = pos`.
       - Increment `pos` (allocate space for the far pointer entry).
3. **Child Address Assignment**: Iterate $i$ from 0 to 7:
   - If `node->children[i]` exists and `node->children[i].type == NT_PARTIAL`:
     - Set `node->childAdr = pos`.
     - Increment `pos`.
4. Return `pos`.

#### `compactNode(node, data, far_ptr_table, pos_ref)`
This function writes the compacted nodes into the `data` array [S1, unofficial].
1. Iterate $i$ from 0 to 7 (children):
   - If `node->children[i]` exists and `node->children[i].type == NT_PARTIAL`:
     - Recursively call `compactNode(node->children[i], data, far_ptr_table, pos_ref)`.
     - Decrement `pos_ref[0]` (tracking the position in the output buffer).
2. Assert `pos_ref[0] <= len(data)`.
3. Set `cnode = data[len(data) - pos_ref[0]]`.
4. Initialize `cnode.valid_mask = 0` and `cnode.leaf_mask = 0`.
5. Iterate $i$ from 0 to 7:
   - If `node.children[i]` exists:
     - Set `cnode.valid_mask |= (1 << i)`.
   - If `node.children[i]` exists and `node.children[i].type == NT_FILLED`:
     - Set `cnode.leaf_mask |= (1 << i)`.
6. Compute `childPtr = pos_ref[0] - node.childAdr`.
7. If `node.farAdr` is non-zero:
   - Compute `farPtr = pos_ref[0] - node.farAdr`.
   - Assert `farPtr < _shortPtrTop`.
   - Set `far_ptr_table[farPtr] = childPtr`.
   - Set `cnode.child_ptr = (1 << 15) | farPtr`.
8. Else:
   - Set `cnode.child_ptr = childPtr`.

### Pseudocode

```python
class Node:
    def __init__(self):
        self.children = [None] * 8
        self.type = 0  # NT_PARTIAL or NT_FILLED
        self.farAdr = 0
        self.childAdr = 0

class CNode:
    def __init__(self):
        self.valid_mask = 0
        self.leaf_mask = 0
        self.child_ptr = 0

NT_PARTIAL = 1
NT_FILLED = 2
_shortPtrTop = 32768  # Exact value not given in the sources [S1, unofficial]

def compact_tree(root_node):
    root_node.farAdr = 0
    root_node.childAdr = 0
    pos = compact_allocate(root_node, 1)
    dataSize = pos
    data = [CNode() for _ in range(dataSize)]
    far_ptr_table = [0] * dataSize
    pos_ref = [dataSize]
    compact_node(root_node, data, far_ptr_table, pos_ref)
    return data, far_ptr_table

def compact_allocate(node, pos):
    for i in range(8):
        child = node.children[i]
        if child is not None:
            child.farAdr = 0
            child.childAdr = 0
            if child.type == NT_PARTIAL:
                pos = compact_allocate(child, pos)
    for i in range(8):
        child = node.children[i]
        if child is not None and child.childAdr != 0:
            gchildAdrMax = pos - child.childAdr + 16
            if gchildAdrMax > _shortPtrTop:
                child.farAdr = pos
                pos += 1
    for i in range(8):
        child = node.children[i]
        if child is not None and child.type == NT_PARTIAL:
            node.childAdr = pos
            pos += 1
    return pos

def compact_node(node, data, far_ptr_table, pos_ref):
    pos = pos_ref[0]
    for i in range(8):
        child = node.children[i]
        if child is not None and child.type == NT_PARTIAL:
            compact_node(child, data, far_ptr_table, pos_ref)
            pos_ref[0] -= 1
    pos = pos_ref[0]
    assert pos <= len(data)
    cnode = data[len(data) - pos]
    cnode.valid_mask = 0
    cnode.leaf_mask = 0
    for i in range(8):
        if node.children[i] is not None:
            cnode.valid_mask |= (1 << i)
            if node.children[i].type == NT_FILLED:
                cnode.leaf_mask |= (1 << i)
    childPtr = pos - node.childAdr
    if node.farAdr != 0:
        farPtr = pos - node.farAdr
        assert farPtr < _shortPtrTop
        far_ptr_table[farPtr] = childPtr
        cnode.child_ptr = (1 << 15) | farPtr
    else:
        cnode.child_ptr = childPtr
```

### Edge Cases and Pitfalls
- **Precision**: The assertion `farPtr < _shortPtrTop` requires careful management of `_shortPtrTop` [S1, unofficial]. If the tree is very deep or sparse, far pointers may be needed frequently [S1, unofficial].
- **Boundaries**: The `pos` variable must be carefully managed to avoid buffer overflows [S1, unofficial]. The source uses `dataSize - pos` to index backwards, ensuring that children are written before parents in the contiguous array [S1, unofficial].
- **Degenerate Input**: If the input tree is empty, `dataSize` will be small, and the algorithm should handle it gracefully [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N)$ where $N$ is the number of nodes in the octree [G]. Two passes are made: one for allocation/offset calculation and one for writing [S1, unofficial].
- **Memory Complexity**: $O(N)$ for the compacted array [G]. The original pointer-based tree is typically freed after compaction [S1, unofficial].
- **Strengths**: High spatial locality, reduced memory overhead (no pointers per node, just offsets), cache-friendly traversal [S1, unofficial].
- **Limitations**: Static structure; inserting or deleting nodes requires full or partial recompaction [G]. The `_shortPtrTop` parameter may lead to inefficient far pointer usage if not tuned [S1, unofficial].

## Background
The implementation follows the compact octree layout and allocation routines found in the `svo-workbench` repository, which also includes a `readFromBinvox_rec` function for loading voxel data [S1, unofficial]. It is commonly used in real-time volume rendering and ray tracing where memory bandwidth and cache efficiency are critical [S1, unofficial].
