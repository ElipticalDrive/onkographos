# Implicit Min/Max KD-Trees
Also called: Wald et al

## Overview
Implicit Min/Max KD-Trees are a memory-efficient acceleration structure for coherent iso-surface ray tracing that stores min/max scalar values in a balanced binary kd-tree to enable early subtree culling [S1, unofficial]. They differ from standard kd-trees by eliminating explicit node pointers and split-plane coordinates, relying instead on implicit addressing derived from a balanced tree structure and precomputed level-wise splitting dimensions [S1, unofficial]. This approach significantly reduces memory overhead compared to naive implementations, which require 12 bytes per node (8 bytes for plane/pointers, 4 bytes for min/max), resulting in a 12x input data size overhead [S1, unofficial].

## How it works
**Inputs:** A 3D volume dataset of size $N_x \times N_y \times N_z$.
**Outputs:** An implicit kd-tree structure defined by splitting dimensions and min/max bounds, enabling ray traversal.

**Data Structures:**
The tree is balanced and binary. Nodes are addressed implicitly.
- **Split Dimensions:** A precomputed array `split_dim[d]` for each depth $d$ of the tree, storing the axis (0, 1, or 2) along which the split occurs.
- **Min/Max Bounds:** For each node, store the minimum and maximum scalar values of the voxels in its subtree. Leaves store the value of a single voxel.

**Construction Steps:**
1. **Build Base KD-Tree:** Construct a kd-tree over all voxels of the entire dataset. Split planes must coincide with cell boundaries of the volume, yielding a one-to-one mapping between volume cells and kd-tree voxels [S1, unofficial].
2. **Determine Splitting Axis:** For a node covering a range of voxels, identify the dimension with the largest extent (number of cells). Split at the cell boundary closest to the center of the node in that largest dimension [S1, unofficial].
3. **Compute Min/Max Recursively:**
   - For leaf nodes: Store the scalar value of the associated voxel as both min and max.
   - For inner nodes: Compute min as $\min(\text{min}_{left}, \text{min}_{right})$ and max as $\max(\text{max}_{left}, \text{max}_{right})$ [S1, unofficial].

**Pseudocode:**
```python
def build_implicit_kd_tree(voxels, min_idx, max_idx, depth):
    """
    Recursively builds the implicit kd-tree.
    voxels: 3D array of scalar values.
    min_idx, max_idx: inclusive bounds of the current node's voxel range.
    depth: current tree depth.
    Returns: (min_val, max_val) for this node.
    """
    # Base case: leaf node
    if min_idx == max_idx:
        # Assuming linearized index or specific voxel access
        val = get_voxel_value(voxels, min_idx)
        return val, val

    # Determine split dimension: largest extent
    extent_x = max_idx[0] - min_idx[0] + 1
    extent_y = max_idx[1] - min_idx[1] + 1
    extent_z = max_idx[2] - min_idx[2] + 1
    
    # Find dimension with max extent
    if extent_x >= extent_y and extent_x >= extent_z:
        split_axis = 0
    elif extent_y >= extent_x and extent_y >= extent_z:
        split_axis = 1
    else:
        split_axis = 2
        
    # Store split dimension for this depth
    split_dim[depth] = split_axis
    
    # Find split plane: cell boundary closest to center in split_axis
    center = (min_idx[split_axis] + max_idx[split_axis]) / 2.0
    split_val = round(center) # Closest integer boundary
    
    # Split ranges
    left_max = list(max_idx)
    right_min = list(min_idx)
    
    left_max[split_axis] = split_val
    right_min[split_axis] = split_val + 1
    
    # Recurse
    min_left, max_left = build_implicit_kd_tree(voxels, min_idx, tuple(left_max), depth + 1)
    min_right, max_right = build_implicit_kd_tree(voxels, tuple(right_min), max_idx, depth + 1)
    
    # Compute min/max for current node
    node_min = min(min_left, min_right)
    node_max = max(max_left, max_right)
    
    return node_min, node_max
```

- **Splitting Strategy:** Largest extent, split at center [S1, unofficial].
- **Precision:** Floating point for scalar values. Integer indices for bounds.

**Edge Cases:**
- **Degenerate Input:** If a node has only one voxel, it is a leaf.
- **Boundary Conditions:** Split planes must align with voxel boundaries to ensure correct mapping [S1, unofficial].

## Subtopics

### [Implicit KD-Tree for Iso-Surface Ray Tracing](8881-implicit-kd-tree-for-iso-surface-ray-tracing.md)
The Implicit KD-Tree is a memory-efficient acceleration structure for coherent iso-surface ray tracing that stores min/max values in a balanced binary kd-tree to enable early subtree culling, avoiding the storage of pointers and splitting plane positions. It differs from standard kd-trees by eliminating explicit node pointers and split-plane coordinates, relying instead on implicit addressing derived from a balanced tree structure and precomputed level-wise splitting dimensions. This approach significantly reduces memory overhead compared to naive implementations, which require 12 bytes per node (8 bytes for plane/pointers, 4 bytes for min/max), resulting in a 12x input data size overhead.

## Operating characteristics
**Time Complexity:** Construction is $O(N \log N)$ for $N$ voxels due to recursive splitting. Traversal is $O(\sqrt{N})$ in the worst case for coherent rays, but typically much faster due to culling.
**Memory Complexity:** $O(N)$ for min/max values. No pointers or split-plane coordinates stored explicitly, reducing overhead to 12x input data size compared to naive implementations [S1, unofficial].
**Measured Performance:**
- Single PC (Dual-CPU): Bonsai 3.4 fps, Aneurysm 3.0 fps, ML 512^3 1.2 fps, Female 2.7 fps, Female (zoom) 2.3 fps [S1, unofficial].
- 5-Node Cluster: Bonsai 16.2 fps, Aneurysm 14.6 fps, ML 512^3 6.1 fps, Female 13.6 fps, Female (zoom) 11.2 fps [S1, unofficial].
**Strengths:** Low memory footprint, fast construction, effective culling for coherent rays.
**Limitations:** Memory footprint for LLNL dataset exceeded 2 GB RAM per client, preventing rendering [S1, unofficial]. Performance scales with cluster size [S1, unofficial].

## Background
Originated by Wald et al. [WFM* 05]. The acceleration structure is similar to the one used by Wilhelm and van Gelder [WV92] [S1, unofficial]. It is used in interactive volume rendering frameworks, including scenes with diffuse shading and global illumination [S1, unofficial].
