# Sparse Octree Terrain Representation

Also called: Sparse Octree Reconstruction Model, Sparse Octree Terrain

## Overview
Sparse Octree Terrain Representation replaces dense heightmap diffusion with a sparse octree structure that stores only occupied voxels, aligning with the Voxy schema to avoid wasting compute on empty cells [S1, unofficial]. Unlike previous methods that diffuse all 256 values of a full 16x16 heightmap regardless of terrain presence, this method works only over the occupied 8x8 patch surface, storing only non-empty octree nodes [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A chunk coordinate pair $(chunkX, chunkZ)$, an $8 \times 8$ heightmap ($heightmap_{8 \times 8}$), biome data ($biomes_{64}$), and a Level of Detail integer ($lod$).
*   **Output:** A `TerrainPatch` object containing a set of occupied voxels and a binary occupancy grid.

**Data Structures:**
1.  **Voxel:** An immutable value class representing a single occupied voxel at $(x, y, z)$ in octree-local space. It implements `equals` and `hashCode` to be safe as a `Set` key [S1, unofficial].
2.  **TerrainPatch:** Contains two fields computed from the heightmap:
    *   `Set<Voxel> occupiedVoxels`: An unmodifiable set of terrain positions [S1, unofficial].
    *   `int[][][] octreeStructure`: An $8 \times 8 \times 8$ binary occupancy grid indexed by $[x][y][z]$, where the Y-axis quantizes the height range into $OCTREE\_SIZE$ levels [S1, unofficial].

**Parameters:**
*   $OCTREE\_SIZE$: A constant integer with value 8, defining the dimension of the binary occupancy grid and the number of Y-axis quantization levels [S1, unofficial].

**Steps:**
1.  **Validation:** Validate that the input $heightmap_{8 \times 8}$ has exactly $8 \times 8$ dimensions. Reject input of wrong size [S1, unofficial].
2.  **Smoothing:** Apply $OCTREE\_SIZE - lod$ smoothing passes to the heightmap.
    *   If $lod = 0$, apply 8 smoothing passes (most detail).
    *   If $lod \ge 8$, apply 0 smoothing passes (no-op) [S1, unofficial].
3.  **Quantization and Occupancy:**
    *   Quantize the height range of the smoothed heightmap into $OCTREE\_SIZE$ levels along the Y-axis.
    *   Populate the `octreeStructure` $8 \times 8 \times 8$ binary grid based on the quantized heights.
    *   Populate the `occupiedVoxels` set with the coordinates of all non-zero entries in the grid [S1, unofficial].
4.  **Invariant Enforcement:** Ensure the lowest Y-level in the `octreeStructure` is always occupied, even in the edge case of a flat heightmap [S1, unofficial].
5.  **Return:** Return the constructed `TerrainPatch` [S1, unofficial].

**Pseudocode:**
```python
def build_sparse_octree(chunk_x, chunk_z, heightmap_8x8, biomes_64, lod):
    # Step 1: Validation
    if len(heightmap_8x8) != 8 or any(len(row) != 8 for row in heightmap_8x8):
        raise ValueError("Heightmap must be 8x8")

    # Step 2: Smoothing
    # Apply smoothing passes based on LOD
    num_passes = OCTREE_SIZE - lod
    if num_passes > 0:
        smoothed_heightmap = apply_smoothing(heightmap_8x8, num_passes)
    else:
        smoothed_heightmap = heightmap_8x8

    # Step 3: Quantization and Occupancy
    octree_structure = [[[0 for z in range(OCTREE_SIZE)] for y in range(OCTREE_SIZE)] for x in range(OCTREE_SIZE)]
    occupied_voxels = set()

    # Quantize height to Y-levels
    # Note: Exact quantization formula depends on heightmap value range.
    # Assuming heightmap values are normalized or mapped to [0, OCTREE_SIZE-1]
    for x in range(OCTREE_SIZE):
        for z in range(OCTREE_SIZE):
            height_val = smoothed_heightmap[x][z]
            # Quantize height to integer level y
            y_level = quantize_height(height_val, OCTREE_SIZE)
            
            # Clamp y_level to valid range [0, OCTREE_SIZE-1]
            y_level = max(0, min(y_level, OCTREE_SIZE - 1))
            
            # Mark occupancy in grid
            octree_structure[x][y_level][z] = 1
            occupied_voxels.add(Voxel(x, y_level, z))

    # Step 4: Invariant Enforcement
    # Ensure lowest Y-level (y=0) is always occupied
    has_occupancy_at_y0 = False
    for x in range(OCTREE_SIZE):
        for z in range(OCTREE_SIZE):
            if octree_structure[x][0][z] == 1:
                has_occupancy_at_y0 = True
                break
        if has_occupancy_at_y0:
            break
    
    if not has_occupancy_at_y0:
        # Force occupancy at lowest level for all x, z
        for x in range(OCTREE_SIZE):
            for z in range(OCTREE_SIZE):
                octree_structure[x][0][z] = 1
                occupied_voxels.add(Voxel(x, 0, z))

    # Step 5: Return
    return TerrainPatch(occupied_voxels, octree_structure)

def quantize_height(height_val, octree_size):

    return int(height_val) % octree_size
```

**Edge Cases and Pitfalls:**
*   **Lowest-Y-level Invariant:** The lowest Y-level in the octree structure must always be occupied, even in the edge case of a flat heightmap [S1, unofficial].
*   **Input Size:** The input heightmap must be exactly $8 \times 8$. Wrong-size input is rejected [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The build process is $O(OCTREE\_SIZE^2)$ for the heightmap processing and smoothing, where $OCTREE\_SIZE = 8$. This is significantly faster than the previous dense $16 \times 16$ diffusion which processed 256 values [S1, unofficial].
*   **Memory Complexity:** Memory usage is proportional to the number of occupied voxels and the fixed $8 \times 8 \times 8$ grid. The `occupiedVoxels` set stores only non-empty nodes, providing compression proportional to sparsity [S1, unofficial].
*   **Strengths:** Avoids wasting compute on empty cells; aligns with Voxy schema; backward-compatible [S1, unofficial].
*   **Limitations:** Limited to $8 \times 8$ patches; fixed resolution defined by $OCTREE\_SIZE$ [S1, unofficial].
*   **When to use:** When terrain sparsity is high and compute efficiency is critical; when integrating with Voxy storage schema [S1, unofficial].
*   **When not to use:** When high-resolution continuous heightmaps are required without quantization; when terrain is dense and sparse representation offers no benefit [S1, unofficial].

## Background
This method was introduced in a pull request to the LODiffusion project to replace the existing LOD pipeline that forced dense 16x16 heightmap diffusion for every chunk [S1, unofficial]. It aligns the data contract with Voxy's octree storage schema [S1, unofficial].
