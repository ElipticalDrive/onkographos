# NanoVDB Volume Loading and GPU Transfer

Also called: NanoVDB Grid Reading, NanoVDB IO and Transfer

## Overview
This method reads a NanoVDB volume file from disk, validates that the grid contains `float` values, and transfers the raw voxel data to a GPU compute buffer [S1, unofficial]. It operates on the linear, contiguous memory layout of the grid, allowing direct memory copying without CPU-side tree traversal [G].

## How it works
### Inputs and Outputs
- **Input**: A file path string pointing to a `.nvdb` file [S1, unofficial].
- **Output**: A GPU-ready compute buffer containing the raw voxel data, and a host-side metadata structure (`NanoVolume`) describing the buffer layout [S1, unofficial].

### Data Structures
The host-side `NanoVolume` struct uses a sequential layout and contains the following fields [S1, unofficial]:
- `buf`: Pointer to the raw voxel data (`uint32_t*` in C++, `uint*` in C#) [S1, unofficial].
- `byteSize`: Total size of the data in bytes (`uint64_t` / `ulong`) [S1, unofficial].
- `elementCount`: Number of elements in the buffer (`uint64_t` / `ulong`) [S1, unofficial].
- `structStride`: Stride between elements in bytes (`uint64_t` / `ulong`) [S1, unofficial].

### Steps
1. Read the grid from the file path using `nanovdb::io::readGrid(path)` to obtain a `GridHandle` [S1, unofficial].
2. Retrieve the raw pointer to the grid data as a `FloatGrid` using `gridHandle.grid<float>()` [S1, unofficial].
3. Validate that the buffer pointer is not null; if null, throw a `std::runtime_error` stating "File did not contain a grid with value type float" [S1, unofficial].
4. Calculate `byteSize` from `gridHandle.buffer().bufferSize()` and `elementCount` as `byteSize / sizeof(float)` [S1, unofficial].
5. Set `structStride` to `sizeof(float)` [S1, unofficial].
6. Allocate memory for the `NanoVolume` struct using `malloc(sizeof(struct NanoVolume))` [S1, unofficial].
7. Cast the grid buffer data to `uint32_t*` and assign it to `(*volume)->buf` [S1, unofficial].
8. Assign `byteSize`, `elementCount`, and `structStride` to the corresponding fields in the `NanoVolume` struct [S1, unofficial].
9. In the C# loader, allocate a `uint[]` array `buf` with size `elementCount` [S1, unofficial].
10. Copy elements from the native `nanoVolume->buf` to the C# `buf` array using a loop from `i = 0` to `elementCount - 1` [S1, unofficial].
11. Create a Unity `ComputeBuffer` with size `elementCount`, stride `structStride`, and type `ComputeBufferType.Default` [S1, unofficial].
12. Upload the data to the GPU buffer using `gpuBuffer.SetData(buf)` [S1, unofficial].

### Pseudocode
```python
class NanoVolume:
    buf: list
    byte_size: int
    element_count: int
    struct_stride: int

def load_nanovdb_to_gpu(file_path):
    # Step 1: Read Grid Handle
    grid_handle = nanovdb_io_read_grid(file_path)
    
    # Step 2: Retrieve Grid Pointer
    float_grid = grid_handle.get_grid_float()
    
    # Step 3: Validate Buffer
    if float_grid.buffer is None:
        raise RuntimeError("File did not contain a grid with value type float")
    
    # Step 4: Calculate Metadata
    byte_size = grid_handle.buffer.buffer_size()
    element_count = byte_size // 4  # sizeof(float) is 4 bytes
    struct_stride = 4               # sizeof(float) is 4 bytes
    
    # Step 5: Allocate Host Structure
    nano_volume = NanoVolume()
    
    # Step 6: Assign Buffer Pointer (Cast to uint32_t*)
    nano_volume.buf = float_grid.buffer.data
    
    # Step 7: Assign Metadata
    nano_volume.byte_size = byte_size
    nano_volume.element_count = element_count
    nano_volume.struct_stride = struct_stride
    
    # Step 8: Prepare for GPU Transfer (C# Host Copy)
    host_buf = [0] * element_count
    
    # Copy data from native buffer to host array
    for i in range(element_count):
        host_buf[i] = nano_volume.buf[i]
        
    # Step 9: Create GPU Buffer
    gpu_buffer = create_compute_buffer(size=element_count, stride=struct_stride, type=ComputeBufferType.Default)
    
    # Step 10: Upload Data
    gpu_buffer.set_data(host_buf)
    
    return gpu_buffer, nano_volume
```

### Parameters
- **Value Type**: The grid is expected to have value type `float` [S1, unofficial].

### Edge Cases and Pitfalls
- **Invalid Data Type**: If the file does not contain a grid with value type `float`, the loader throws an exception and fails to load [S1, unofficial].
- **Null Buffer**: If the buffer pointer is null after retrieval, the same exception is thrown [S1, unofficial].
- **Memory Alignment**: The `structStride` is set to `sizeof(float)` (4 bytes), implying no padding between elements [S1, unofficial].

## Background
This method is derived from the Unity NanoVDB renderer project, which provides an implementation for integrating NanoVDB volumes into Unity's compute shader pipeline [S1, unofficial]. NanoVDB is a GPU-optimized implementation of OpenVDB that uses a linear representation for compact copying [G].
