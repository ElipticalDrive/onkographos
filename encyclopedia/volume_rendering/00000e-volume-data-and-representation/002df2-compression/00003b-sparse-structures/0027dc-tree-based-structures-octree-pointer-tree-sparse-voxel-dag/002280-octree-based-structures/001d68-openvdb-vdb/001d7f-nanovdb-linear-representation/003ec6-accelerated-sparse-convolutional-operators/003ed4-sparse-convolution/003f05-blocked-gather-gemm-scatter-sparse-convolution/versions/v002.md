# Blocked Gather-GEMM-Scatter Sparse Convolution

Also called: Shared memory blocked sparse convolution, SpConv v2 optimization

## Overview
Blocked Gather-GEMM-Scatter Sparse Convolution is an optimization for sparse convolution that minimizes wasted MAC operations and global memory traffic by blocking the gather-GEMM-scatter operation on contiguous subsequences of output indices from a VDB data structure, using shared memory for intermediate accumulation [S1]. It sets itself apart from standard sparse convolution by explicitly addressing the inefficiency of multiple streaming passes over input activations and suboptimal scattering to global memory, which are common pitfalls in straightforward gather-GEMM-scatter implementations [S1]. It improves upon [SpConv v2](9837-sparse-convolution.md) by leveraging the locality of the NanoVDB mapping to cluster geometric coordinates, thereby reducing global memory bandwidth pressure [S1].

## How it works
**Inputs:**
- A minibatch of sparse voxel grids encoded in NanoVDB format, consisting of a `GridBatch` (containing `IndexGrid` leaf nodes) and a `JaggedTensor` (per-voxel features) [S1].
- Convolution kernel weights.
- Stencil offsets (typically 27 for a 3x3x3 neighborhood) [S1].

**Outputs:**
- Updated per-voxel feature tensors for the minibatch [S1].

**Data Structures:**
- **IndexGrid:** Maps active voxel coordinates to linear indices in the feature tensor; indices are clustered geometrically [S1].
- **Shared Memory Buffers:**
  - `InputBuffers[27][N]`: Stores packed input feature vectors for each of the 27 stencil offsets, where $N$ is the number of valid input indices for the current block, padded to the next multiple of 16 [S1].
  - `OutputAccum[64][F]`: Temporary buffer in GPU shared memory for accumulating output vectors for 64 output indices, where $F$ is the feature length [S1].
  - `IndexPairs[27][N]`: Stores packed input/output index pairs linked by each stencil offset, padded to the next multiple of 16 [S1].

**Parameters:**
- **Block Size:** 64 output indices. This is the typical number of indices processed in a contiguous subsequence [S1].
- **Stencil Offsets:** 27. The number of stencil offsets processed in the sparse convolution [S1].
- **Padding Alignment:** Multiple of 16. Input/output index pairs are padded to this multiple to map to tensorcore-accelerated GEMM [S1].

**Steps:**
1. **Block Selection:** Select a contiguous subsequence of 64 output indices from the NanoVDB data structure [S1]. Due to the locality of the NanoVDB mapping, these indices correspond to highly clustered geometric coordinates from one or more `IndexGrid` leaf nodes [S1].
2. **Index Pair Collection:** For each of the 27 stencil offsets, identify all input/output index pairs $(i, o)$ such that the output index $o$ is within the current block's range [S1]. Pack these pairs contiguously in shared memory buffers `IndexPairs[offset]` [S1].
3. **Padding:** Pad the packed collections of input/output index pairs in `IndexPairs` to the next multiple of 16 [S1]. This ensures compatibility with tensorcore-accelerated GEMM operations [S1]. This padding is the only source of wasted MACs, limited to at most 15 MACs per block of 64 output indices (expected ~8 entries per 64 output indices) [S1].
4. **Input Gathering:** For each stencil offset, gather the input feature vectors from global memory using the packed indices in `IndexPairs[offset]` and store them in `InputBuffers[offset]` [S1]. This benefits from locality across offsets [S1].
5. **GEMM Computation:** Perform a GEMM operation for each stencil offset using `InputBuffers[offset]` and the kernel weights [S1]. The result is produced in packed format [S1].
6. **Shared Memory Scattering:** Scatter the GEMM results purely in shared memory into the `OutputAccum` buffer, which stores all 64 output vectors [S1]. This avoids scattering to global memory during the accumulation phase [S1].
7. **Global Memory Update:** After processing all 27 stencil offsets, sequentially copy the accumulated results from `OutputAccum` back to global memory at the corresponding output indices [S1]. This avoids the need for a scatter operation to global memory [S1].

**Pseudocode:**
```python
def blocked_gather_gemm_scatter(active_indices, features, kernel_weights, stencil_offsets, block_size=64, padding_alignment=16):
    """
    Performs blocked gather-GEMM-scatter sparse convolution.
    active_indices: list of global voxel indices (simulates IndexGrid)
    features: list of feature vectors per active index (simulates JaggedTensor)
    kernel_weights: list of 27 weight matrices (list of lists)
    stencil_offsets: list of 27 integer offsets
    block_size: number of output indices per block (default 64)
    padding_alignment: padding multiple for tensorcore GEMM (default 16)
    """
    output_features = [None] * len(active_indices)
    active_set = set(active_indices)
    feature_dim = len(features[0])
    
    for block_start in range(0, len(active_indices), block_size):
        block_end = min(block_start + block_size, len(active_indices))
        block_indices = active_indices[block_start:block_end]
        num_outputs = block_end - block_start
        
        # Initialize OutputAccum[64][F] in shared memory
        output_accum = [[0.0] * feature_dim for _ in range(block_size)]
        
        for offset_idx, offset in enumerate(stencil_offsets):
            # Step 2: Index Pair Collection
            pairs = []
            for local_idx, global_out in enumerate(block_indices):
                global_in = global_out - offset
                if global_in in active_set:
                    pairs.append((global_in, local_idx))
            
            # Step 3: Padding
            padded_len = ((len(pairs) + padding_alignment - 1) // padding_alignment) * padding_alignment
            padded_pairs = pairs + [(None, None)] * (padded_len - len(pairs))
            
            # Step 4: Input Gathering
            input_buf = [features[p[0]] if p[0] is not None else [0.0] * feature_dim for p in padded_pairs]
            
            # Step 5: GEMM Computation
            kernel = kernel_weights[offset_idx]
            # GEMM: input_buf (M x F) @ kernel (F x F) -> out_buf (M x F)
            out_buf = [[sum(a * b for a, b in zip(row, col)) for col in zip(*kernel)] for row in input_buf]
            
            # Step 6: Shared Memory Scattering
            for i, (_, local_out) in enumerate(padded_pairs):
                if local_out is not None:
                    for f in range(feature_dim):
                        output_accum[local_out][f] += out_buf[i][f]
        
        # Step 7: Global Memory Update
        for local_idx, global_out in enumerate(block_indices):
            output_features[global_out] = output_accum[local_idx]
            
    return output_features
```

**Edge Cases and Pitfalls:**
- **Wasted MACs:** The padding to the next multiple of 16 introduces wasted MACs, limited to at most 15 MACs per block of 64 output indices (expected ~8 entries per 64 output indices) [S1].
- **Global Memory Traffic:** Scattering to shared memory and sequentially copying to global memory avoids the suboptimality of scattering results directly to global memory [S1].
- **Multiple Streaming Passes:** The blocking strategy reduces the need for multiple independent streaming passes over input activations (one for each of the 27 stencil offsets) by packing and gathering data locally [S1].

## Operating characteristics
- **Time Complexity:** The method reduces the number of global memory accesses by blocking and using shared memory [S1]. The GEMM operation is accelerated by tensorcores due to padding alignment [S1].
- **Memory Complexity:** Requires shared memory for input buffers, output accumulation, and index pairs [S1]. The size of shared memory depends on the block size (64) and feature length [S1].
- **Measured Performance:** Benchmarks demonstrate a runtime that is approximately 25% faster than SpConv v2 for feature length 128 or higher on the SemanticKITTI single-scan point clouds [S1].
- **Strengths:** Minimizes wasted MAC operations and global memory traffic [S1]. Leverages locality of NanoVDB mapping [S1]. Accelerated by tensorcores [S1].
- **Limitations:** Padding introduces some wasted MACs, though limited [S1]. Requires careful management of shared memory [G].
- **When to Use:** Suitable for large-scale sparse voxel grids where global memory bandwidth is a bottleneck and tensorcores are available [G]. Particularly effective for feature lengths 128 or higher [S1].
- **When Not to Use:** For very small feature lengths or small block sizes where the overhead of blocking and shared memory management outweighs the benefits [G].

## Background
- **Origin:** This method is part of the fVDB deep learning framework for sparse, large-scale, and high-performance spatial intelligence [S1].
- **Development:** It was developed to address the performance limitations of the traditional gather-GEMM-scatter paradigm in sparse convolution, specifically the inefficiencies caused by multiple streaming passes and suboptimal global memory scattering [S1].
- **Usage:** Used in the fVDB framework for processing minibatches of sparse voxel grids, leveraging NanoVDB data structures for efficient memory access and computation [S1].
