# Implicit Octree Traversal

Also called: ImplicitOctree

## Overview
Implicit Octree Traversal is a method for extracting isosurfaces from sparse volumetric data by building a sparse octree indexed by Morton coordinates and traversing leaf nodes to invoke callbacks for 2x2x2 cubes of neighboring vertices [S1, unofficial]. It solves the problem of efficiently locating leaf nodes and their adjacent neighbors in a sparse representation without explicitly storing the full cell structure, which would cause storage explosion [S1, unofficial]. It differs from [Pointerless Octree for Seed Placement](5280-pointerless-octree-for-seed-placement.md) by focusing on general point-location and neighbor-finding for surface extraction rather than specific seed placement logic, and from [Cell Retrieval via Neighbor-Finding](1822-cell-retrieval-via-neighbor-finding.md) by providing the underlying hashing primitives for corner value retrieval [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A distance field (scalar or vector) defined over a 3D domain.
- Output: A set of primal vertices and their connectivity, typically used to generate meshes via dual contouring or marching cubes.

**Data Structures:**
1.  **ImplicitOctree:** Contains `max_depth` (usize). Internally uses a `LinearHashedOctree` structure.
2.  **primal_vertices:** A `HashMap<Morton, usize>` mapping Morton coordinates of vertices to their tree level [S1, unofficial].
3.  **Morton:** An integer key representing 3D coordinates via Z-order curve mapping.

**Parameters:**
- `max_depth` ($N$): The maximum depth of the octree. The domain is equivalent to a cubic grid with dimensions $2^N$ along each axis [S1, unofficial].

**Steps:**

1.  **Initialization:**
    Create an `ImplicitOctree` with the specified `max_depth` $N$. This defines the resolution limit of the sparse representation [S1, unofficial].

2.  **Collect Primal Vertices:**
    Iterate through all leaf nodes of the octree. For each leaf key, iterate $i$ from 0 to 7 (representing the 8 corners of the leaf cell).
    - Compute the vertex coordinate: $v = \text{key.primal\_vertex}(level, i)$.
    - If $v \neq \text{Morton::with\_key}(0)$:
        - Check if $v$ exists in `primal_vertices`.
        - If it exists and the current $level > \text{existing\_level}$, update the entry.
        - Otherwise, insert $(v, level)$ into `primal_vertices` [S1, unofficial].

3.  **Traverse Primal Vertices:**
    For each $(key, level)$ in `primal_vertices`:
    - Iterate $i$ from 0 to 7.
    - Compute the dual vertex key: $m = \text{key.dual\_vertex}(level, \text{REMAP\_CUBE}[i])$.
    - While $m > \text{Morton::new()}$:
        - Query the octree: `result = octree.get_node(&m)`.
        - If `result` returns `Some(distance)`:
            - Set $keys[i] = m$.
            - Set $corners[i] = m.center()$.
            - Set $values[i] = distance$.
            - Break the while loop.
        - If `result` returns `None`:
            - Set $m = m.parent()$.
    - If the loop completes without finding a node, the corner is considered empty or undefined [S1, unofficial].

**Formulas:**
- **Linear Interpolation for Crossing Point:**
  Given two points $p_a, p_b$ with distance values $a, b$:
  $$ \Delta = b - a $$
  $$ t = \begin{cases} 0.5 & \text{if } \Delta = 0.0 \\ -a / \Delta & \text{otherwise} \end{cases} $$
  $$ p_{cross} = p_a (1 - t) + p_b t $$
  For directed distance fields (vector-valued), the interpolation is performed along the dominant axis $axis = \text{argmax}(|p_a - p_b|)$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Directed Distance Fields:** Constructing an octree over a directed distance field (where the distance is a vector) is not fully implemented in the reference source; it requires special handling for crossing point calculation along the dominant axis [S1, unofficial].
- **Empty Vertices:** Vertices at the origin key (0) are excluded from processing [S1, unofficial].
- **Precision:** Morton coordinate arithmetic must handle large integers correctly to avoid overflow at high depths [G].

**Pseudocode:**
```python
def implicit_octree_traversal(distance_field, max_depth):
    # 1. Initialization
    octree = LinearHashedOctree(max_depth=max_depth)
    # Populate octree with distance values from the field
    for leaf in octree.leaves():
        octree.set_node(leaf.key, distance_field.sample(leaf.center()))

    primal_vertices = {}

    # 2. Collect primal vertices
    for leaf_key, leaf_level in octree.leaves_with_level():
        for i in range(8):
            vertex_morton = leaf_key.primal_vertex(level=leaf_level, corner_index=i)
            if vertex_morton != Morton.with_key(0):
                if vertex_morton in primal_vertices:
                    existing_level = primal_vertices[vertex_morton]
                    if leaf_level > existing_level:
                        primal_vertices[vertex_morton] = leaf_level
                else:
                    primal_vertices[vertex_morton] = leaf_level

    # 3. Traverse primal vertices
    results = []
    for key, level in primal_vertices.items():
        keys = [None] * 8
        corners = [None] * 8
        values = [None] * 8
        
        for i in range(8):
            m = key.dual_vertex(level=level, remap_index=REMAP_CUBE[i])
            found = False
            while m > Morton.new():
                node_data = octree.get_node(m)
                if node_data is not None:
                    keys[i] = m
                    corners[i] = m.center()
                    values[i] = node_data.distance
                    found = True
                    break
                else:
                    m = m.parent()
            if not found:
                # Corner not found in octree
                pass
        
        results.append({
            'keys': keys,
            'corners': corners,
            'values': values
        })
    
    return results
```

## Subtopics

### [Cell Reconstruction via Octree Hashing](1595-cell-reconstruction-via-octree-hashing.md)
Locates leaf nodes and neighbors using bitwise arithmetic on integer coordinates to reconstruct 8-voxel cells for isosurface primitives. Choose when efficient neighbor finding without explicit cell storage is required.

### [Pointerless Octree for Seed Placement](5280-pointerless-octree-for-seed-placement.md)
Uses a hierarchical pyramid structure to dynamically select seed points for volume hatching based on curvature and gradient. Choose when generating hatching strokes rather than extracting meshes.

## Operating characteristics
- **Time Complexity:** Depends on the number of leaves and the depth of traversal to find dual vertices. In the worst case, traversal may go up to the root, but sparsity limits this.
- **Memory Complexity:** Proportional to the number of non-empty leaves and primal vertices. Significantly less than a dense grid for sparse data.
- **Strengths:** Efficiently handles sparse volumes; avoids storing empty space; supports adaptive resolution via depth.
- **Limitations:** Does not support directed distance fields in the reference implementation; requires careful handling of vertex sharing across cells.
- **When to use:** Sparse volumetric data extraction where memory is constrained and sparsity is high.
- **When not to use:** Dense volumes where a uniform grid is more efficient; directed distance fields if the reference implementation is used without modification.

## Background
The method is described in the source code of the `isosurface` library by Tristam MacDonald [S1, unofficial]. It builds on the principles of sparse octree structures and Morton ordering for spatial indexing. The approach is particularly relevant for dual contouring and marching cubes algorithms that require access to corner values of cells.
