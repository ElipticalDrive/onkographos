# LBVH Construction for Sparse Volumetric Data
Also called: GPU LBVH for Sparse Volumes, Zellmann et al. LBVH

## Overview
This method constructs a Linear Bounding Volume Hierarchy (LBVH) acceleration structure specifically for sparse volumetric data to enable efficient empty-space skipping during ray marching. It adapts the LBVH construction algorithm originally designed for triangle geometry [S1, unofficial]. By organizing non-empty volume bricks into a hierarchy, it allows for two to three times higher frame rates compared to ray marching without empty-space skipping [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A sparse volumetric dataset represented as a uniform grid of bricks.
*   **Output:** A Bounding Volume Hierarchy (BVH) tree structure stored on the GPU.

**Data Structures**
The volume is divided into a uniform grid with a fixed brick size [S1, unofficial]. The boundaries of non-empty bricks serve as the bounding geometry for the LBVH nodes [S1, unofficial].

**Steps**
1.  **Grid Partitioning:** Divide the entire volume domain into a uniform grid of bricks with a fixed size [S1, unofficial].
2.  **Geometry Extraction:** Identify all non-empty bricks. For each non-empty brick, compute its spatial boundaries [S1, unofficial].
3.  **LBVH Construction:** Apply the linear LBVH construction algorithm (typically a surface-area heuristic based split) using the brick boundaries as the primitive set [S1, unofficial]. This step is performed on the GPU to achieve interactive frame rates [S1, unofficial].

**Parameters**
*   **Brick Size:** Fixed size for the uniform grid division. The specific value is not given in the sources [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Empty Space:** The method relies on the sparsity of the data. If the volume is dense, the overhead of the hierarchy may outweigh the benefits of empty-space skipping.
*   **GPU Memory:** The construction must fit within GPU memory constraints for large volumes (e.g., $1024^3$) [S1, unofficial].

## Operating characteristics
*   **Performance:** Allows constructing the acceleration structure on the GPU at interactive frame rates for $1024^3$ volumes [S1, unofficial].
*   **Rendering Speed:** The resulting LBVH structure allows for two to three times higher frame rates than using no empty-space skipping during ray marching [S1, unofficial].
*   **Complexity:** Not given in the sources.
*   **Strengths:** Efficient GPU construction; significant speedup for sparse data.
*   **Limitations:** Requires uniform grid partitioning; performance depends on sparsity.

## Background
Zellmann et al. [ZHL19] proposed this adaptation of a linear bounding volume hierarchy (LBVH) construction algorithm for triangle geometry to sparse volumetric data [S1, unofficial]. They demonstrated that using the boundaries of non-empty bricks as bounding geometry enables efficient GPU-based construction [S1, unofficial]. This work is part of a broader effort to support run-time re-construction of acceleration data structures for empty-space skipping in volume rendering [S1, unofficial].
