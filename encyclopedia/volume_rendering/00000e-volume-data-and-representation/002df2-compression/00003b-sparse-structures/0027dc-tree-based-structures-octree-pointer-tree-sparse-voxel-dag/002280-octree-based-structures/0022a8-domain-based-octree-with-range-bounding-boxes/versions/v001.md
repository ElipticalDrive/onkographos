# Domain-based Octree with Range Bounding Boxes

Also called: Domain-Based Acceleration (Octree), Domain-based acceleration data-structure (Octree), Octree Acceleration, Range Bounding Box (RBB) Octree

## Overview
The Domain-based Octree with Range Bounding Boxes is an acceleration structure for fiber surface extraction in tetrahedral meshes. It solves the problem of efficiently identifying tetrahedra that intersect a given Fiber Surface Control Polygon (FSCP) edge by filtering candidates via 2-D intersection tests in range space [S1]. Unlike its sibling [Domain-based BVH with Range Bounding Boxes](2808-domain-based-bvh-with-range-bounding-boxes.md), the octree is strictly domain-based, which may result in more returned tetrahedra and higher memory usage, but provides a robust spatial hierarchy for conservative culling [S1].

## How it works
**Inputs:**
- A tetrahedral mesh with a scalar function $f$ defined on it.
- A Fiber Surface Control Polygon (FSCP) defined by a sequence of vertices, forming edges $e$.
- Parameters: $n_T$ (minimum tetrahedra per node threshold), $\alpha$ (RBB size fraction termination threshold).

**Outputs:**
- A set of candidate tetrahedra that intersect the FSCP edges, used for subsequent exact fiber surface extraction.

**Data Structures:**
The structure is an implicit or explicit octree over the domain $\text{Dom } f$.
- **Node:** Contains a Range Bounding Box (RBB).
- **RBB Layout:** A 2D axis-aligned bounding box in the range space (value space), defined by minimum and maximum scalar values: $[v_{min}, v_{max}]$.
- **Tree Structure:** Recursive subdivision of the 3D domain. Nodes store the RBB of all tetrahedra contained within their spatial extent.

**Algorithm Steps:**

1. **Off-line Construction:**
   1. Compute the octree of the domain $\text{Dom } f$ in a top-to-bottom fashion by recursively dividing the domain into octants [S1].
   2. For each node, determine the set of tetrahedra contained within its spatial bounds.
   3. If the number of tetrahedra in the node is greater than or equal to $n_T$:
      - Do not descend further for this branch if other termination criteria are met, or continue subdivision based on spatial density (implementation detail not fully specified, but typically continues until $n_T$ is met or depth limit reached) [S1].
      - *Note:* The source states "we do not descend all the way to individual tetrahedra, instead providing a threshold $n_T$ on the minimum number of tetrahedra per node, below which the base level RBB is computed from the vertices of the tetrahedra" [S1]. This implies that if a node has $\ge n_T$ tets, it is a leaf for the purpose of RBB computation, or the recursion stops there.
   4. If the number of tetrahedra is less than $n_T$:
      - Compute the RBB for the node by taking the union of the RBBs of its children (if they exist) or directly from the vertices of the tetrahedra contained in the node [S1].
      - Specifically, compute $v_{min} = \min(f(v))$ and $v_{max} = \max(f(v))$ for all vertices $v$ of the tetrahedra in the node [S1].
   5. **Termination Criterion:** Stop recursion for a node if its RBB height ($v_{max} - v_{min}$) is smaller than a fraction $\alpha$ of the RBB height of the entire mesh. This prevents arbitrarily deep sub-trees in regions where the function values concentrate [S1].

2. **On-line Query:**
   1. Start at the root node of the octree.
   2. For a given FSCP edge $e$ (projected into range space as a line segment or polygon):
      - Check if the node's RBB intersects or overlaps with the projection of edge $e$ in the range space [S1].
      - The intersection test is a conservative axis-aligned bounding box (AABB) test in 2D range space [S1].
   3. If the RBB intersects $e$:
      - Recursively visit the children of the node.
   4. If the RBB does not intersect $e$:
      - Prune this branch; no tetrahedra in this subtree can intersect the FSCP edge.
   5. If the node is a leaf (or the recursion terminates):
      - Return all tetrahedra contained in this node as candidates.
   6. The union of all returned tetrahedra from all FSCP edges forms the candidate set for exact extraction [S1].

**Formulas:**
- RBB for a node $N$:
  $$ \text{RBB}(N) = [\min_{t \in T_N} (\min_{v \in \text{vertices}(t)} f(v)), \max_{t \in T_N} (\max_{v \in \text{vertices}(t)} f(v))] $$
  where $T_N$ is the set of tetrahedra in node $N$.
- Termination condition:
  $$ \text{RBB}(N).height < \alpha \times \text{RBB}(\text{Root}).height $$

**Parameters:**
- $n_T$: Threshold for minimum number of tetrahedra per node. Default/typical value: 1 (if desired), but set to 5 for 5-subdivided regular grids in experiments [S1].
- $\alpha$: Fraction of the entire mesh's RBB used as a termination criterion. Typical value: 0.001 offered the best trade-off in experiments [S1].

**Edge Cases and Pitfalls:**
- The octree is not necessarily balanced, and sub-trees can be arbitrarily deep, leading to many line-bounding-box intersection tests [S1].
- For 5-subdivided regular grids, the minimum number of tets per octree leaf is 5 (one voxel), causing the RBB of a leaf to intersect a FSCP edge even if none of its tets are actually intersected (false positives) [S1].
- The conservative AABB test in range space may return tetrahedra that do not actually intersect the FSCP edge, but these are discarded during the subsequent exact extraction step [S1].

## Subtopics

## Operating characteristics
- **Time Complexity:** Construction is $O(N)$ where $N$ is the number of tetrahedra, assuming constant work per tetrahedron to update RBBs. Query time depends on the selectivity of the RBBs; in the worst case, it visits all nodes, but typically prunes significantly [S1].
- **Memory Complexity:** Stores one RBB per octree node. The number of nodes depends on the data distribution and parameters $n_T$ and $\alpha$.
- **Measured Performance:** On the EthaneDiol dataset, an octree with $\alpha=0.001$ used 649.736 MB memory, took 2.362s pre-processing, queried 35.260% of tetrahedra, and took 0.311s for extraction [S1]. Average speedup over non-accelerated algorithm: 18x [S1].
- **Strengths:** Simple to implement; provides good culling for sparse fiber surfaces; conservative nature ensures no false negatives [S1].
- **Limitations:** Conservative AABB test leads to false positives; unbalanced tree can lead to deep recursion; less efficient than BVH for complex FSCP shapes [S1].

## Background
The method was introduced in the context of fast and exact fiber surface extraction for tetrahedral meshes [S1]. It extends the concept of using octrees to store interval ranges (RBBs) at each node for isosurface extraction [36] to the more complex case of polygonal FSCP edges, requiring 2-D intersection tests in range space [S1].
