# VDB-based Occupancy Grid Conversion

Also called: Sparse OG via VDB, VDB + DDA, VDB + HDDA, VDB OG, VDB-based Occupancy Grid Ray Sampling

## Overview
This method replaces the dense binary grid of an Occupancy Grid (OG) with a VDB (Volume Data Base) grid to reduce spatial redundancy caused by empty voxels, accelerating ray-sampling without re-training the NeRF model [S1, unofficial]. It sets itself apart from sibling methods like Instant-NGP's Octree-like structure by fully exploiting VDB’s hierarchical structure for ray-traversal, specifically using Hierarchical Digital Differential Analyzer (HDDA) to skip merged empty regions in a single operation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A trained NeRF model with its associated dense Occupancy Grid (OG). Typical grid sizes are 256KiB for NeRF-Synthetic and 1024KiB for Mip-NeRF 360 [S1, unofficial].
*   **Output:** A read-only VDB grid on the GPU and a ray-sampling kernel that traverses this grid to collect sample points.

**Data Structures:**
*   **VDB Grid:** A tree-like data structure that fixes the depth of its tree to save computational cost during traversal [S1, unofficial]. It provides a caching mechanism to accelerate accessing neighboring voxels [S1, unofficial].
*   **Tiles:** Large occupied or unoccupied regions are managed as tiles, where a tile contains multiple voxels sharing the same values [S1, unofficial].

**Steps:**
1.  **Conversion:** Convert the dense OG of the trained NeRF model into a VDB-based structure using OpenVDB [S1, unofficial].
2.  **Transfer:** Transfer the VDB grid to the GPU using NanoVDB [S1, unofficial].
3.  **Pruning:** Prune redundancies in the VDB grid by managing large occupied or unoccupied regions as tiles [S1, unofficial].
4.  **Ray Sampling:** Execute ray sampling using either Digital Differential Analyzer (DDA) or Hierarchical Digital Differential Analyzer (HDDA) analyzers on the VDB grid [S1, unofficial]. The VDB grid is read-only on the GPU [S1, unofficial].
5.  **Point Collection:** When the ray-sampler finds an occupied voxel or a fully occupied tile, it samples points along the ray at specified intervals [S1, unofficial].
    *   For NeRF-Synthetic: Use a constant step size [S1, unofficial].
    *   For Mip-NeRF 360: Use a linearly increasing step size [S1, unofficial].

**Pseudocode:**
The following pseudocode illustrates the GPU-side ray sampling kernel using HDDA on a VDB grid. It assumes standard vector operations and a `VDBGrid` structure with `traverse` and `is_occupied` methods.

```python
def sample_ray_vdb(ray_origin, ray_direction, vdb_grid, step_strategy):
    """
    Samples points along a ray using VDB-based traversal.
    
    Args:
        ray_origin: vec3, origin of the ray.
        ray_direction: vec3, normalized direction of the ray.
        vdb_grid: VDBGrid, the read-only VDB structure on GPU.
        step_strategy: str, 'constant' for NeRF-Synthetic, 'linear' for Mip-NeRF 360.
        
    Returns:
        list of vec3, sample points along the ray.
    """
    samples = []
    t = 0.0
    max_t = 10.0  # Example max distance, scene-dependent [G]
    
    # Initial step size
    step = 0.01 
    
    while t < max_t:
        # Traverse the VDB grid to find the next occupied region
        # Returns the distance to the next occupied voxel/tile or max_t if empty
        next_t = vdb_grid.traverse(ray_origin + ray_direction * t, ray_direction)
        
        if next_t >= max_t:
            break
            
        # Advance to the occupied region
        t = next_t
        
        # Determine step size based on strategy
        if step_strategy == 'constant':
            current_step = 0.01  # Fixed step for NeRF-Synthetic [S1, unofficial]
        else:
            # Linearly increasing step for Mip-NeRF 360 [S1, unofficial]
            current_step = 0.01 * (1.0 + t * 0.1) 
            
        # Sample points within the occupied region
        # The VDB structure may return a tile, requiring multiple samples
        # This loop handles sampling within the current occupied block
        while t < next_t + current_step and t < max_t:
            point = ray_origin + ray_direction * t
            samples.append(point)
            t += current_step
            
    return samples
```

**Parameters:**
*   **Conversion Time:** Approximately 60 msec in the worst case to convert dense grids to VDB [S1, unofficial].
*   **Step Size:** Constant for NeRF-Synthetic; linearly increasing for Mip-NeRF 360 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Floating-Point Errors:** Replacing the ray-sampler with VDB causes floating-point errors, resulting in rendered images that are not entirely identical to the original ray-sampler's output [S1, unofficial].
*   **DDA Skip Inefficiency:** Using "DDA skip" (skipping leading empty cells in advance) did not work well with DDA, but HDDA effectively reduces the number of operations for skipping voxels [S1, unofficial].
*   **Training Updates:** The method is not suitable for frequent updates during training because VDB grids on GPU are read-only; pruning on CPU requires re-transferring the grid to GPU, creating high overhead [S1, unofficial].

## Operating characteristics
*   **Performance:** On the NeRF-Synthetic dataset, the method improves rendering FPS in all cases, with the VDB + HDDA with DDA skip kernel recording the fastest FPS, accelerating rendering by 12% on average (up to 16% for the hotdog scene) [S1, unofficial]. On the Mip-NeRF 360 dataset, it improves FPS by 4-5% on average [S1, unofficial].
*   **Quality:** No scene got significantly worse PSNR than the baseline [S1, unofficial].
*   **Memory:** The VDB grid size varies by scene. For NeRF-Synthetic, sizes range from ~316 KiB to ~410 KiB (average 352.4 KiB) [S1, unofficial]. For Mip-NeRF 360, sizes range from ~1999 KiB to ~2279 KiB (average 2145.5 KiB) [S1, unofficial].
*   **Strengths:** Reduces spatial redundancy, accelerates ray-tracing by skipping large empty regions, and requires no re-training [S1, unofficial].
*   **Limitations:** Not suitable for frequent updates during training due to GPU read-only constraints and CPU-GPU transfer overhead [S1, unofficial].

## Background
This method was proposed in 2024 as a way to accelerate Occupancy Grid-based NeRF rendering [S1, unofficial]. It builds on the concept of using VDB for sparse volumes [11, unofficial] and HDDA for efficient ray-tracing [12, unofficial]. It is distinct from PlenVDB, which uses VDB for radiance field representation but does not utilize VDB’s hierarchical structure for ray-tracing [S1, unofficial]. The implementation was forked from NerfAcc, which is noted as the fastest implementation of OG at the time [S1, unofficial].
