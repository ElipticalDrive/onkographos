# Tiny LOD


## Overview
Tiny LOD is a method for computing a hierarchical level-of-detail (LOD) structure from volumetric data, specifically designed to generate a tree suitable for subsequent chunk-based storage and rendering [S1, unofficial]. It solves the problem of efficiently reducing the complexity of dense volumetric representations by aggregating voxels into coarser primitives while preserving structural detail [S1, unofficial]. It differs from sibling methods like [Compact pointer tree](844-compact-pointer-tree.md) by focusing on the computational generation of the LOD hierarchy itself, rather than the final memory layout or traversal optimization [S1, unofficial].

## How it works
Tiny LOD operates as a preprocessing step that transforms raw volumetric input into a compressed hierarchical tree. The method relies on the `tiny_lod` library to perform the core aggregation logic [S1, unofficial].

### Inputs and Outputs
*   **Input:** A volumetric data structure (referred to as "inner data") containing active voxels or splats.
*   **Parameters:**
    *   `lod_base` (f32): The base value controlling the granularity of the LOD computation [S1, unofficial].
    *   `merge_filter` (bool): A flag indicating whether to apply a merge filter during the tree computation to reduce node count [S1, unofficial].
    *   `log_callback`: A function for logging progress or errors [S1, unofficial].
*   **Output:** A computed LOD tree structure, followed by encoded opacity values and a chunk tree representation [S1, unofficial].

### Data Structures
The method produces an intermediate LOD tree. The specific internal layout of this tree is not detailed in the sources, but it serves as the basis for the subsequent "chunk tree" build step [S1, unofficial]. The final output involves encoding opacity values, implying a mapping from the tree nodes to scalar opacity fields [S1, unofficial].

### Steps
1.  **Sanitization:** Remove invalid splats or voxels from the inner data structure to ensure data integrity [S1, unofficial].
2.  **LOD Tree Computation:** Compute the level-of-detail tree using the `tiny_lod` library. This step aggregates voxels based on `lod_base` and optionally applies `merge_filter` [S1, unofficial].
3.  **Opacity Encoding:** Encode the opacity values for the computed LOD structure. This likely involves quantizing or compressing the scalar values associated with the tree nodes [S1, unofficial].
4.  **Chunk Tree Construction:** Build the chunk tree starting at index 0. This organizes the LOD data into chunks suitable for efficient memory access or rendering [S1, unofficial].

### Pseudocode
```python
def compute_tiny_lod(inner_data, lod_base, merge_filter, log_callback):
    """
    Computes the Tiny LOD hierarchy from volumetric data.
    
    Args:
        inner_data: The raw volumetric data (e.g., splats or voxels).
        lod_base (float): Base value for LOD granularity.
        merge_filter (bool): Whether to apply merge filtering.
        log_callback: Function to log progress.
        
    Returns:
        tuple: (lod_tree, chunk_tree)
    """
    # Step 1: Remove invalid splats
    clean_data = remove_invalid_splats(inner_data)
    
    # Step 2: Compute LOD tree
    # The specific aggregation algorithm is encapsulated in the tiny_lod library
    lod_tree = tiny_lod_library.compute(
        data=clean_data,
        lod_base=lod_base,
        merge_filter=merge_filter,
        log=log_callback
    )
    
    # Step 3: Encode opacity values
    # This step prepares the scalar data for storage/rendering
    encoded_opacities = encode_opacity(lod_tree)
    
    # Step 4: Build chunk tree
    # Organizes the tree into chunks starting at index 0
    chunk_tree = build_chunk_tree(
        lod_tree=lod_tree,
        start_index=0,
        log=log_callback
    )
    
    return lod_tree, chunk_tree
```

### Edge Cases and Pitfalls
*   **Invalid Data:** The method explicitly requires the removal of invalid splats before processing. Failure to sanitize input may lead to undefined behavior in the LOD computation [S1, unofficial].
*   **Precision:** The `lod_base` is a 32-bit float. Precision issues may arise if the value is extremely small or large relative to the voxel grid scale [S1, unofficial].
*   **Merge Filter:** If `merge_filter` is enabled, adjacent nodes with similar properties may be merged. This can reduce memory usage but may introduce artifacts if the threshold is too aggressive [S1, unofficial].

### [Trilinear Evaluation on Compressed Trees](7074-trilinear-evaluation-on-compressed-trees.md)
This method evaluates a signal value at an arbitrary point $\mathbf{x}$ within a compressed tree structure, supporting trilinear filtering and adaptive traversal. It serves as the evaluation engine for the Compressed Random-Access Tree (CRAT) framework, enabling fine-grain random queries required by rendering algorithms. Unlike block-based decompression schemes (e.g., DXT1) that rely on specialized hardware, this method uses adaptive tree traversal to reconstruct data on the fly, trading raw decompression speed for spatial coherence and high-quality filtering.

### [LODTree Storage Layout](16362-lodtree-storage-layout.md)
The LODTree storage layout is a sparse, hierarchical data structure designed to store volumetric data with multiple levels of detail (LOD) in a compact format, enabling efficient dynamic isosurface extraction. It differs from sibling methods like [Trilinear Evaluation on Compressed Trees](7074-trilinear-evaluation-on-compressed-trees.md) by explicitly managing virtual voxel expansion across discrete LOD levels using a bit-mapped cell representation to minimize storage overhead.

### High LOD Approximation
The highest LOD level that retains local detail by using smaller subdivision blocks for dense nodes and per-voxel mapping for sparse nodes [S2, unofficial].

#### Definition
High LOD approximates the volumetric field by aggregating dense regions into 2x2x2 Gaussian blocks while preserving individual voxels in sparse regions [S2, unofficial].

#### Steps
1.  **For dense leaf nodes:** Subdivide into 2x2x2 blocks, aggregating every 8 adjacent voxels into a single Gaussian [S2, unofficial].
2.  **For dense leaf nodes:** Average the scalar values of the 8 voxels to compute the Gaussian’s opacity [S2, unofficial].
3.  **For dense leaf nodes:** Transform the block center in index space (offset by `voxelSize`) into world space to serve as the Gaussian’s position [S2, unofficial].
4.  **For dense leaf nodes:** Set covariance to be axis-aligned and correspond to the full voxel size along each axis [S2, unofficial].
5.  **For non-dense leaf nodes:** Treat at per-voxel level, converting each active voxel individually into a Gaussian primitive [S2, unofficial].
6.  **For non-dense leaf nodes:** Use voxel center (offset by half the `voxelSize`) as the mean and opacity taken directly from the voxel value [S2, unofficial].
7.  **For non-dense leaf nodes:** Set Gaussian radii to half the voxel size [S2, unofficial].
