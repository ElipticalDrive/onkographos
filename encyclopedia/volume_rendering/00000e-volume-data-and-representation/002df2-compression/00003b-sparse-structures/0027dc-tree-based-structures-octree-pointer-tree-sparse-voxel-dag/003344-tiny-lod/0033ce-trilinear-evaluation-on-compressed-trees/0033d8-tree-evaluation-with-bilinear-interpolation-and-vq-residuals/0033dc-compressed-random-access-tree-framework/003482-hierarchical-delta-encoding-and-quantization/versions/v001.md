# Hierarchical Delta Encoding and Quantization

Also called: Tree Compression

## Overview
Hierarchical Delta Encoding and Quantization is a compression method for adaptive multiresolution tree structures (specifically octrees and quadtrees) used in volume rendering. It solves the problem of efficiently storing and traversing large, unbalanced hierarchical meshes by encoding node attributes relative to their parents and quantizing spatial and field data into compact bit-fields [S1, unofficial]. It sets itself apart from sibling methods by using a fixed 13-bit lookup index for spatial/radius deltas and specific bit-packing for field values, enabling fast top-down traversal from a single binary stream [S1, unofficial].

## How it works
**Inputs:**
- A hierarchical tree structure (Solid Octree or Shell Quadtree) where each node has a bounding sphere defined by center $(x, y, z)$ and radius $r$.
- Scalar field values associated with each node, normalized to $[0, 1]$.
- For Shell nodes: normal vectors and normal cone widths.

**Outputs:**
- A compressed binary stream of nodes, stored in breadth-first order.
- Each node is encoded into a fixed-size byte record (6 bytes for Solid, 8 bytes for Shell).

**Data Structures and Layout:**
The core data structure is the **Solid Node**, which is 48 bits (6 bytes) long. The layout is little-endian byte order, with bits ordered MSB leftmost within each byte. The fields are packed as follows:

1.  **Spatial/Radius Index (13 bits):** Encodes the quantized spatial offsets $(x, y, z)$ and radius $r$.
2.  **Children Count (3 bits):** Number of children (0–8).
3.  **Grandchildren Flag (1 bit):** Indicates presence of grandchildren.
4.  **Field Value 1 (15 bits):** Quantized value of the first scalar field.
5.  **Field Value 2 (15 bits):** Quantized value of the second scalar field.
6.  **Boundary Flag (1 bit):** Identifies if the node is a boundary node.

*Note: The total bit count is $13 + 3 + 1 + 15 + 15 + 1 = 48$ bits. The source text mentions "2 extra bytes per field value" for arbitrary numbers of fields, but the primary example and layout description focus on two fields totaling 6 bytes. For Shell nodes, the layout is identical to Solid nodes but replaces the Boundary Flag and adds an 18-bit field (2 bytes) for the normal vector (14 bits) and normal cone width (2 bits), totaling 8 bytes [S1, unofficial].*

**Parameters:**
- **Radius Quantization:** $r$ is quantized to 13 discrete values relative to the parent radius.
- **Spatial Offset Quantization:** $x, y, z$ are quantized to 13 discrete values relative to the parent diameter.
- **Field Quantization:** 15 bits per field value is sufficient for the studied datasets [S1, unofficial].

**Steps:**

1.  **Normalize Field Values:**
    For each scalar field value $v$, normalize it to the range $[0, 1]$.
    $$ v_{norm} = \frac{v - v_{min}}{v_{max} - v_{min}} $$
    Quantize $v_{norm}$ using a lookup table to a 15-bit integer index.

2.  **Compute Delta Coordinates:**
    For each child node, compute the spatial offsets $(dx, dy, dz)$ from the parent center $(x_p, y_p, z_p)$:
    $$ dx = x_c - x_p, \quad dy = y_c - y_p, \quad dz = z_c - z_p $$
    Compute the radius $r_c$.

3.  **Quantize Spatial Attributes:**
    - Quantize $r_c$ to one of 13 discrete values based on the parent radius $r_p$.
    - Quantize $dx, dy, dz$ to one of 13 discrete values based on the parent diameter $2r_p$.
    *Note: The exact quantization function maps the continuous offset/radius to a discrete index $0..12$.*

4.  **Encode Spatial/Radius Index:**
    - Form a tuple of quantized values $(idx_x, idx_y, idx_z, idx_r)$.
    - Only a subset of these combinations satisfy the hierarchical bounding sphere condition (i.e., the child sphere must be contained within the parent sphere).
    - Map the valid tuple to a pre-computed fixed lookup table index. This index is 13 bits wide.
    *Note: The lookup table maps the valid combinations of $(idx_x, idx_y, idx_z, idx_r)$ to a compact 13-bit integer.*

5.  **Determine Node Metadata:**
    - Count the number of children $N_c$ (0–8). Encode in 3 bits.
    - Check if any child has children (grandchildren). Encode in 1 bit.
    - For Solid nodes, set the Boundary Flag (1 bit) if the node is on the boundary.

6.  **Pack the Byte Record:**
    - Combine the 13-bit Spatial/Radius Index, 3-bit Children Count, 1-bit Grandchildren Flag, two 15-bit Field Values, and 1-bit Boundary Flag into a 48-bit integer.
    - Write the 48-bit integer as 6 bytes in little-endian order.

7.  **Handle Shell Nodes (if applicable):**
    - Compute the normal vector $\mathbf{n}$ by averaging child normals.
    - Quantize $\mathbf{n}$ to 14 bits.
    - Quantize the normal cone width to 2 bits.
    - Pack these 16 bits into the extra 2 bytes, replacing the Boundary Flag and adjusting the layout accordingly.

8.  **Flush to Stream:**
    - Write all nodes to a single binary stream in breadth-first order.

**Edge Cases and Pitfalls:**
- **Invalid Bounding Spheres:** Only a subset of quantized $(x,y,z,r)$ combinations are valid. The lookup table must only contain valid entries. Invalid combinations must be handled (e.g., by encoding a special "null" index or ensuring the quantization step guarantees validity).
- **Precision:** 15 bits for field values may not be sufficient for all datasets. The source states it was sufficient for the studied datasets [S1, unofficial].
- **Byte Order:** Little-endian byte order must be respected when writing the binary stream.
- **Bit Order:** MSB leftmost bit order within each byte.

## Operating characteristics
- **Time Complexity:** Encoding is linear in the number of nodes. Decoding is also linear, allowing fast top-down traversal.
- **Memory Complexity:** Each node is compressed to 6 bytes (Solid) or 8 bytes (Shell), significantly reducing memory footprint compared to uncompressed pointers and floating-point coordinates.
- **Performance:** Enables real-time rendering and volume clipping of large datasets by facilitating fast traversal from a single binary stream [S1, unofficial].
- **Strengths:** Compact representation, fast traversal, support for multiple field values, support for interactive transfer function editing.
- **Limitations:** Fixed quantization levels may introduce artifacts. Unbalanced trees require embedded pointers (encoded in the node structure) for traversal, which adds complexity.

## Background
The method was introduced by Museth and Lombeyda in 2004 in the paper "TetSplat: Real-time Rendering and Volume Clipping of Large ..." [S1, unofficial]. It builds on earlier work in splatting and hierarchical data structures, such as QSplat, and aims to improve upon them by providing a more compact and efficiently traversable format for large volume datasets. The method is part of the TetSplat system, which uses tetrahedral splatting for volume rendering.
