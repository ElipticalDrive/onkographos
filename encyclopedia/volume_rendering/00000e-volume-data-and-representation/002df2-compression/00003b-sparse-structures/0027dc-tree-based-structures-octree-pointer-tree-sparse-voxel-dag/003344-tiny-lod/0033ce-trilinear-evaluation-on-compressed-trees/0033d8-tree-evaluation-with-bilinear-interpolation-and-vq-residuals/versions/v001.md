# Tree Evaluation with Bilinear Interpolation and VQ Residuals

Also called: Adaptive Tree Evaluation, Primal Subdivision Evaluation

## Overview
This method evaluates a signal value at a point $\mathbf{x}$ by traversing an adaptive quadtree structure, using bilinear interpolation of node values and Vector Quantization (VQ) residuals to reconstruct the signal [S1, unofficial]. It serves as the evaluation engine for the Compressed Random-Access Tree (CRAT) framework, enabling fine-grain random queries required by rendering algorithms [S1, unofficial]. Unlike its parent method which supports trilinear filtering, this variant is specialized for 2D spatial coherence or specific projection steps, relying on fixed-rate encoding for topology and data to enable efficient random access [S1, unofficial].

## How it works
**Inputs:**
- Point $\mathbf{x}$ in world or texture coordinates.
- A forested mipmap structure where the coarsest levels are collapsed into a root forest [S1, unofficial].
- VQ codebook: A lookup table storing residual values for quantized node differences [S1, unofficial].

**Outputs:**
- Reconstructed signal value at $\mathbf{x}$.

**Data Structures:**
- **Node:** Contains an address (offset to child nodes) and a base value. Addresses are stored as local offsets rather than pointers [S1, unofficial].
- **Codebook:** A 1D array of residual values indexed by quantized indices [S1, unofficial].

**Algorithm Steps:**
1. **Initialization:** Identify the cell containing $\mathbf{x}$ at the starting level (e.g., level 4 in the forested mipmap) [S1, unofficial]. Retrieve the root node address and value for each of the four corners of this cell.
2. **Coordinate Transformation:** Re-express point $\mathbf{x}$ in the local coordinates of the current cell [S1, unofficial].
3. **Traversal Loop:**
    a. **Interpolation:** At the current local point $\mathbf{x}$, bilinearly interpolate the four node values from the current level to obtain a predicted value $V_{interp}$ [S1, unofficial].
    b. **Termination Check:** If the current depth $l < 1$ or all four node addresses are NULL (indicating no children exist), return the value at $\mathbf{x}$ linearly interpolated (lerp) with the value from the prior level using the depth parameter $l$ [S1, unofficial].
    c. **Quadrant Selection:** Set the new cell as the quadrant containing point $\mathbf{x}$ [S1, unofficial].
    d. **Prediction:** For each of the four corners of the new cell, predict the new node value using bilinear interpolation of the parent's children or available data [S1, unofficial].
    e. **Residual Application:** If the node parent address is non-NULL, access the VQ codebook using the appropriate index to retrieve the residual value and add it to the predicted value [S1, unofficial].
    f. **Address Update:** Update the node address to the appropriate child node based on the selected quadrant [S1, unofficial].
    g. **Re-coordinatization:** Re-express point $\mathbf{x}$ in the new cell’s coordinates [S1, unofficial].
    h. **Repeat:** Continue the loop until termination conditions are met.

**Pseudocode:**
```python
def evaluate_tree(x_world, forest_mipmap, codebook, start_level=4):
    # 1. Find initial cell at start_level
    cell = find_cell_containing(forest_mipmap, start_level, x_world)
    
    # 2. Get root nodes for the 4 corners of this cell
    corners = get_cell_corners(cell)
    node_values = [get_node_value(c) for c in corners]
    node_addresses = [get_node_address(c) for c in corners]
    
    # 3. Re-express x in local cell coordinates
    x_local = reexpress_in_cell(x_world, cell)
    
    depth = start_level
    
    while True:
        # 4. Bilinearly interpolate the four node values
        val_interp = bilinear_interpolate(x_local, node_values)
        
        # 5. Check termination: depth < 1 or all addresses NULL
        if depth < 1 or all(addr is NULL for addr in node_addresses):
            # Return value lerp'ed with prior level using l
            # Note: 'prior level' implies a fallback or blending mechanism
            # If no prior level exists, return val_interp
            return val_interp 
        
        # 6. Set new cell as the quadrant containing x
        quadrant = get_quadrant(x_local)
        new_cell = get_child_cell(cell, quadrant)
        
        # 7. Predict new node values for the 4 corners of the new cell
        # This involves accessing children or predicting from current structure
        new_corners = get_cell_corners(new_cell)
        
        predicted_values = []
        new_addresses = []
        
        for corner in new_corners:
            addr = get_node_address(corner)
            new_addresses.append(addr)
            
            if addr is not NULL:
                # Access VQ codebook to add residual
                residual = codebook[get_codebook_index(corner)]
                # Predict base value (e.g., from parent interpolation or stored value)
                base_val = predict_node_value(corner)
                predicted_values.append(base_val + residual)
            else:
                # If address is NULL, value might be inherited or zero
                # Implementation detail [G]: Handle NULL child gracefully
                predicted_values.append(0.0) 
        
        # 8. Update state
        node_values = predicted_values
        node_addresses = new_addresses
        cell = new_cell
        
        # 9. Re-express x in new cell coordinates
        x_local = reexpress_in_cell(x_world, new_cell)
        depth -= 1
```

**Parameters:**
- **VQ Codebook:** A lookup table storing residual values. The size and precision depend on the quantization scheme used during compression [S1, unofficial].
- **Start Level:** The depth in the forested mipmap where traversal begins (e.g., level 4) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **NULL Addresses:** If node addresses are NULL or depth is insufficient, the algorithm must blend with the prior level to avoid undefined behavior [S1, unofficial].
- **Precision:** Bilinear interpolation requires careful handling of floating-point precision when re-expressing coordinates across multiple levels [S1, unofficial].

## Subtopics

### [Compressed Random-Access Tree Framework](7109-compressed-random-access-tree-framework.md)
The CRAT framework compresses adaptive multiresolution hierarchies into a compact, randomly-accessible structure. It replaces pointers with local offsets, uses a forested mipmap structure, and applies vector quantization (VQ) to inter-level residuals, storing both offsets and codebook indices as byte records.

## Operating characteristics
- **Time Complexity:** The number of tree levels traversed is relatively low on average due to tree adaptivity and the collapse of coarsest levels into a forested mipmap [S1, unofficial].
- **Memory Complexity:** Fixed-rate encoding for topology and data allows for compact storage. The use of 1D memory buffers enables better caching behavior than complex addressing from 2D textures [S1, unofficial].
- **Performance:** Implemented within a GPU pixel program, leveraging DirectX 10's unfiltered access to 1D memory buffers (max 128 MB) for efficient caching [S1, unofficial].
- **Strengths:** Data coherence permits a very adaptive hierarchy. The fixed-rate encoding supports fine-grain random queries [S1, unofficial].
- **Limitations:** Relies on the assumption of spatial coherence; performance may degrade on highly noisy or non-coherent data.

## Background
The method originates from the work on Compressed Random-Access Trees for Spatially Coherent Data [S1, unofficial]. It was developed to address the limitations of prior schemes that used entropy coding on sequential traversals, which did not support the random access required by rendering algorithms. The approach leverages the benefits of tree structures, where data coherence permits a very adaptive hierarchy, as demonstrated in the representation of signed distance functions [S1, unofficial].
