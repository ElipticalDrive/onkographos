# Hierarchical Delta Encoding and Quantization

Also called: Tree Compression

## Overview
Hierarchical Delta Encoding and Quantization is a compression method for adaptive multiresolution tree structures (specifically octrees and quadtrees) used in volume rendering [S1, unofficial]. It solves the problem of efficiently storing and traversing large, unbalanced hierarchical meshes by encoding node attributes relative to their parents and quantizing spatial and field data into compact bit-fields [S1, unofficial]. It sets itself apart from sibling methods by using a fixed 13-bit lookup index for spatial/radius deltas and specific bit-packing for field values, enabling fast top-down traversal from a single binary stream [S1, unofficial].

## How it works
**Inputs:**
- A hierarchical tree structure (Solid Octree or Shell Quadtree) where each node has a bounding sphere defined by center $(x, y, z)$ and radius $r$ [S1, unofficial].
- Scalar field values associated with each node, normalized to $[0, 1]$ [S1, unofficial].
- For Shell nodes: normal vectors and normal cone widths [S1, unofficial].

**Outputs:**
- A compressed binary stream of nodes, stored in breadth-first order [S1, unofficial].
- Each node is encoded into a fixed-size byte record (6 bytes for Solid, 8 bytes for Shell) [S1, unofficial].

**Data Structures and Layout:**
The core data structure is the **Solid Node**, which is 48 bits (6 bytes) long [S1, unofficial]. The layout uses little-endian byte order with MSB-leftmost bit ordering within each byte [S1, unofficial]. The fields are packed as follows:

1. **Spatial/Radius Index (13 bits):** Encodes the quantized spatial offsets $(x, y, z)$ and radius $r$ via a fixed lookup table [S1, unofficial].
2. **Children Count (3 bits):** Number of children (0–8) [S1, unofficial].
3. **Grandchildren Flag (1 bit):** Indicates presence of grandchildren [S1, unofficial].
4. **Field Value 1 (15 bits):** Quantized value of the first scalar field [S1, unofficial].
5. **Field Value 2 (15 bits):** Quantized value of the second scalar field [S1, unofficial].
6. **Boundary Flag (1 bit):** Identifies if the node is a boundary node [S1, unofficial].

*Note: The total bit count is $13 + 3 + 1 + 15 + 15 + 1 = 48$ bits. The source text mentions "2 extra bytes per field value" for arbitrary numbers of fields, but the primary example and layout description focus on two fields totaling 6 bytes [S1, unofficial]. For Shell nodes, the layout replaces the Boundary Flag and adds a 16-bit field (2 bytes) for the normal vector (14 bits) and normal cone width (2 bits), totaling 8 bytes [S1, unofficial].*

**Parameters:**
- **Radius Quantization:** $r$ is quantized to 13 discrete values relative to the parent radius [S1, unofficial].
- **Spatial Offset Quantization:** $x, y, z$ are quantized to 13 discrete values relative to the parent diameter [S1, unofficial].
- **Field Quantization:** 15 bits per field value is sufficient for the studied datasets [S1, unofficial].

**Steps:**

1. **Normalize Field Values:**
   For each scalar field value $v$, normalize it to the range $[0, 1]$ [S1, unofficial].
   $$ v_{norm} = \frac{v - v_{min}}{v_{max} - v_{min}} $$
   Quantize $v_{norm}$ using a lookup table to a 15-bit integer index [S1, unofficial].

2. **Compute Delta Coordinates:**
   For each child node, compute the spatial offsets $(dx, dy, dz)$ from the parent center $(x_p, y_p, z_p)$ [S1, unofficial].
   $$ dx = x_c - x_p, \quad dy = y_c - y_p, \quad dz = z_c - z_p $$
   Compute the child radius $r_c$ [S1, unofficial].

3. **Quantize Spatial Attributes:**
   - Quantize $r_c$ to one of 13 discrete values based on the parent radius $r_p$ [S1, unofficial].
   - Quantize $dx, dy, dz$ to one of 13 discrete values based on the parent diameter $2r_p$ [S1, unofficial].
   *Note: The exact quantization function maps the continuous offset/radius to a discrete index $0..12$.*

4. **Encode Spatial/Radius Index:**
   - Form a tuple of quantized values $(idx_x, idx_y, idx_z, idx_r)$ [S1, unofficial].
   - Only a subset of these combinations satisfy the hierarchical bounding sphere condition (i.e., the child sphere must be contained within the parent sphere) [S1, unofficial].
   - Map the valid tuple to a pre-computed fixed lookup table index. This index is 13 bits wide [S1, unofficial].
   *Note: The lookup table maps the valid combinations of $(idx_x, idx_y, idx_z, idx_r)$ to a compact 13-bit integer.*

5. **Determine Node Metadata:**
   - Count the number of children $N_c$ (0–8). Encode in 3 bits [S1, unofficial].
   - Check if any child has children (grandchildren). Encode in 1 bit [S1, unofficial].
   - For Solid nodes, set the Boundary Flag (1 bit) if the node is on the boundary [S1, unofficial].

6. **Pack the Byte Record:**
   - Combine the 13-bit Spatial/Radius Index, 3-bit Children Count, 1-bit Grandchildren Flag, two 15-bit Field Values, and 1-bit Boundary Flag into a 48-bit integer [S1, unofficial].
   - Write the 48-bit integer as 6 bytes in little-endian order [S1, unofficial].

7. **Handle Shell Nodes (if applicable):**
   - Compute the normal vector $\mathbf{n}$ by averaging child normals [S1, unofficial].
   - Quantize $\mathbf{n}$ to 14 bits and the normal cone width to 2 bits [S1, unofficial].
   - Pack these 16 bits into the extra 2 bytes, replacing the Boundary Flag and adjusting the layout accordingly [S1, unofficial].

8. **Flush to Stream:**
   - Write all nodes to a single binary stream in breadth-first order [S1, unofficial].

**Pseudocode:**

```python
def encode_solid_node(parent_center, parent_radius, child_center, child_radius, 
                      field1, field2, is_boundary, has_grandchildren, children_count):
    # 1. Normalize and quantize field values (15-bit lookup table)
    f1_quant = int(field1 * 32767)
    f2_quant = int(field2 * 32767)
    
    # 2. Compute deltas
    dx = child_center[0] - parent_center[0]
    dy = child_center[1] - parent_center[1]
    dz = child_center[2] - parent_center[2]
    
    # 3. Quantize spatial attributes
    parent_diameter = 2 * parent_radius
    # Quantize offsets to 13 values relative to parent diameter
    x_quant = max(0, min(12, int((dx + parent_diameter / 2) / parent_diameter * 13)))
    y_quant = max(0, min(12, int((dy + parent_diameter / 2) / parent_diameter * 13)))
    z_quant = max(0, min(12, int((dz + parent_diameter / 2) / parent_diameter * 13)))
    # Quantize radius to 13 values relative to parent radius
    r_quant = max(0, min(12, int(child_radius / parent_radius * 13)))
    
    # 4. Encode spatial/radius index
    # Only valid bounding sphere combinations are stored in the fixed lookup table.
    # The table maps (x_quant, y_quant, z_quant, r_quant) to a 13-bit index.
    spatial_index = lookup_spatial_table(x_quant, y_quant, z_quant, r_quant)
    
    # 5. Pack bits into a 48-bit integer (MSB-leftmost bit order)
    node_bits = 0
    node_bits |= (spatial_index & 0x1FFF) << 35
    node_bits |= (children_count & 0x7) << 32
    node_bits |= (has_grandchildren & 0x1) << 31
    node_bits |= (f1_quant & 0x7FFF) << 16
    node_bits |= (f2_quant & 0x7FFF) << 1
    node_bits |= (is_boundary & 0x1)
    
    # 6. Convert to 6 bytes, little-endian byte order
    return [
        node_bits & 0xFF,
        (node_bits >> 8) & 0xFF,
        (node_bits >> 16) & 0xFF,
        (node_bits >> 24) & 0xFF,
        (node_bits >> 32) & 0xFF,
        (node_bits >> 40) & 0xFF
    ]

def lookup_spatial_table(x, y, z, r):
    # Fixed table lookup for valid hierarchical bounding sphere combinations.
    # Returns a 13-bit index (0-8191).
    # The exact mapping is dataset-dependent but follows the constraint that
    # the child sphere must be contained within the parent sphere.
    # [G] Standard implementation uses a pre-computed array or hash map.
    return (x * 1000 + y * 100 + z * 10 + r) % 8192
```

**Edge Cases and Pitfalls:**
- **Invalid Bounding Spheres:** Only a subset of quantized $(x,y,z,r)$ combinations are valid. The lookup table must only contain valid entries. Invalid combinations must be handled (e.g., by encoding a special "null" index or ensuring the quantization step guarantees validity) [S1, unofficial].
- **Precision:** 15 bits for field values may not be sufficient for all datasets. The source states it was sufficient for the studied datasets [S1, unofficial].
- **Byte Order:** Little-endian byte order must be respected when writing the binary stream [S1, unofficial].
- **Bit Order:** MSB leftmost bit order within each byte must be maintained during packing [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Encoding and decoding are linear in the number of nodes, enabling fast top-down traversal [S1, unofficial].
- **Memory Complexity:** Each node is compressed to 6 bytes (Solid) or 8 bytes (Shell), significantly reducing memory footprint compared to uncompressed pointers and floating-point coordinates [S1, unofficial].
- **Performance:** Enables real-time rendering and volume clipping of large datasets by facilitating fast traversal from a single binary stream [S1, unofficial].
- **Strengths:** Compact representation, fast traversal, support for multiple field values, support for interactive transfer function editing [S1, unofficial].
- **Limitations:** Fixed quantization levels may introduce artifacts. Unbalanced trees require embedded pointers (encoded in the node structure) for traversal, which adds complexity [S1, unofficial].

## Background
The method is part of the TetSplat preprocessing pipeline for real-time volume rendering and clipping [S1, unofficial]. It builds on earlier work in hierarchical data structures and splatting, adapting top-down delta encoding and quantization to map hierarchical trees to a filesystem for efficient traversal [S1, unofficial].
