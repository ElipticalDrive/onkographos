# Absolute Position Node Encoding

Also called: Absolute position of nodes

## Overview
Absolute Position Node Encoding is a steganographic technique that hides information within the addressing space of a Sparse Voxel Directed Acyclic Graph (SVDAG) by exploiting the relationship between a node's absolute address and its structural features, specifically the parity of its child count [S1]. It distinguishes itself from relative position encoding by using the absolute memory address rather than the offset between parent and child nodes [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** The absolute memory address of a node in the SVDAG addressing space and the count of its child nodes.
*   **Output:** A single encoded bit (0 or 1) embedded in the node's structural properties or address interpretation.

**Data Structures:**
The method operates on the node layout defined in [SSVDAG Node Layout and Tagged Pointer Encoding](15401-ssvdag-node-layout-and-tagged-pointer-encoding.md). The key feature is the node's absolute address in the linear addressing space and the child node mask which determines the number of valid children.

**Steps:**
1.  Determine the absolute address $A$ of the current node in the SVDAG addressing space.
2.  Select a specific bit position $k$ within the address $A$ (e.g., the third least significant bit, $k=2$).
3.  Count the number of child nodes $C$ associated with the current node, derived from the child node mask.
4.  Evaluate the parity of $C$:
    *   If $C$ is even, encode bit 0.
    *   If $C$ is odd, encode bit 1.
5.  The encoded bit is implicitly stored by ensuring the selected bit $k$ of the address $A$ aligns with the parity of $C$ (or by interpreting the address/parity combination as the payload) [S1].

**Pseudocode:**
```python
def encode_absolute_position(node_address, child_count):
    """
    Encodes a bit based on the absolute position of the node and child count parity.
    
    Args:
        node_address (int): The absolute memory address of the node.
        child_count (int): The number of valid child nodes.
        
    Returns:
        int: The encoded bit (0 or 1).
    """
    # Select a specific bit position, e.g., the third least significant bit (index 2)
    bit_position = 2
    
    # Extract the specific bit from the absolute address
    address_bit = (node_address >> bit_position) & 1
    
    # Determine parity of child count
    # Even number of children -> 0
    # Odd number of children -> 1
    parity_bit = child_count % 2
    
    # The method relies on the correlation between address_bit and parity_bit
    # to hide information. The encoded value is effectively the parity_bit,
    # potentially constrained or verified against address_bit depending on 
    # implementation specifics not fully detailed in sources [S1].
    # For the purpose of extraction, the decoder reads the parity of child_count.
    
    return parity_bit

def decode_absolute_position(node_address, child_count):
    """
    Extracts the hidden bit from a node.
    
    Args:
        node_address (int): The absolute memory address of the node.
        child_count (int): The number of valid child nodes.
        
    Returns:
        int: The decoded bit (0 or 1).
    """
    # Decode by checking the parity of the child count
    # Even -> 0, Odd -> 1 [S1]
    return child_count % 2
```

**Parameters:**
*   **Bit Position ($k$):** The specific bit in the node address used for encoding. Typical examples include the third least significant bit [S1]. Not given in the sources for other positions.
*   **Node Size:** The method applies to nodes with sizes ranging from 32 bits to 288 bits [S1].

**Edge Cases and Pitfalls:**
*   **Detection:** The primary pitfall is detectability. Analysis of irregularities in the addressing of nodes can identify the use of this data hiding technique [S1].
*   **Capacity Limitation:** The method hides only one bit of information per node [S1].

## Subtopics

## Operating characteristics
*   **Capacity:** The capacity is very low, ranging from 0.347% to 3.125% of the node size in bits, depending on the node size (32 to 288 bits) [S1].
*   **Complexity:** The computational complexity is minimal, requiring only a parity check on the child count and potentially a bit extraction from the address [S1].
*   **Strengths:** Simple to implement; utilizes existing structural data (address and child count) without requiring additional storage fields [S1].
*   **Limitations:** Low capacity; susceptible to detection through address irregularity analysis [S1].
*   **When to use:** Suitable for hiding small amounts of metadata in SVDAG structures where minimal overhead is acceptable and detection risk is mitigated [S1].

## Background
This technique was proposed in the context of data hiding using domain-specific hierarchical data structures for the geometry representation of voxelized three-dimensional scenes [S1]. It is part of a family of steganographic methods applied to Sparse Voxel Directed Acyclic Graphs (SVDAG) and Symmetry-Aware Sparse Voxel Directed Acyclic Graphs (SSVDAG) [S1].
