# SVDAG Parameter Configurations

Also called: SVDAG Configurations, SVDAG1-6

## Overview
SVDAG Parameter Configurations define the memory layout and pointer encoding schemes for Sparse Voxel Directed Acyclic Graphs (SVDAGs) to optimize the trade-off between compression ratio and traversal complexity. While the parent method [SSVDAG Node Layout and Tagged Pointer Encoding](1349-ssvdag-node-layout-and-tagged-pointer-encoding.md) establishes the variable-length tagged pointer mechanism, these configurations specify the exact bit-widths for the Child Node Mask (CHNM), the three distinct Child Pointer Types (PT1, PT2, PT3), and the Addressing Word size. They differ from fixed-size SVO layouts by allowing mixed pointer lengths, enabling the structure to adapt to the spatial locality of shared nodes in the scene.

## How it works
The configurations determine the binary layout of internal nodes in the SVDAG. The core principle is that shorter pointers (PT1, PT2) are used for nodes that are spatially close (small offsets), while longer pointers (PT3) are used for distant nodes. The Addressing Word size determines the granularity of the offset calculation.

### Inputs and Outputs
- **Input**: A voxelized 3D scene (triangle mesh voxelized to $N^3$ resolution).
- **Output**: A binary representation of the SVDAG structure with a specific configuration (SVO, SVDAG1, or SVDAG2–6).

### Data Structures and Layout
Each configuration defines the bit-widths of the following fields within an internal node:
1.  **Child Node Mask (CHNM)**: Indicates which of the 8 octants are active.
2.  **Child Pointers (PT)**: Variable-length pointers to child nodes.
    -   **PT1**: Shortest pointer.
    -   **PT2**: Medium pointer.
    -   **PT3**: Longest pointer.
3.  **Addressing Word**: The unit size used to calculate the offset for the pointers.

The total size of a node is the sum of the CHNM, the active pointers, and any padding/alignment bits. The addressing word size ($W_{addr}$) limits the maximum offset value representable by a pointer of length $L_{pt}$ to $2^{L_{pt}} - 1$ words.

### Configuration Parameters
The following table defines the six tested configurations [S1]. Note that SVO and SVDAG1 use a single pointer type, while SVDAG2–6 use three.

| Configuration | CHNM [bits] | PT1 [bits] | PT2 [bits] | PT3 [bits] | Addressing Word [bits] | Notes |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **SVO** | 8 (aligned to 32) | 32 | - | - | 32 | Single pointer type. 24 reserved bits for alignment. |
| **SVDAG1** | 8 (aligned to 32) | 32 | - | - | 32 | Identical to SVO. Based on reference [17]. |
| **SVDAG2** | 16 | 8 | 8 | - | 8 | Two pointer types (PT1, PT2). |
| **SVDAG3** | 16 | 8 | 16 | 32 | 8 | Three pointer types. |
| **SVDAG4** | 16 | 16 | 16 | 32 | 8 | Three pointer types. |
| **SVDAG5** | 16 | 16 | 16 | 32 | 16 | Three pointer types. |
| **SVDAG6** | 16 | 16 | 16 | 32 | 32 | Three pointer types. |

*Note: For SVO and SVDAG1, the 8-bit CHNM is padded with 24 reserved bits to align to a 32-bit boundary [S1].*

### Addressing and Pointer Logic
The addressable space for a pointer depends on its bit length and the addressing word size [S1].
-   An 8-bit pointer with an 8-bit addressing word can address $2^8 = 256$ bytes (if word=1B) or 256 words.
-   A 32-bit pointer with a 32-bit addressing word can address $2^{32}$ words.

The choice of addressing word size affects the maximum offset that can be stored in shorter pointers. For example, in SVDAG2, the 8-bit addressing word means offsets are counted in 8-bit chunks. If the distance between two shared nodes exceeds the range of the 8-bit pointer (255 words), the system must use a longer pointer or fail to share the node.

### Edge Cases and Pitfalls
-   **Pointer Overflow**: If the distance between a parent node and a shared child node exceeds the addressable range of the assigned pointer type (PT1 or PT2), the node cannot be shared using that pointer type. It must either use PT3 (if available) or remain unshared.
-   **Alignment**: SVO and SVDAG1 require 32-bit alignment, adding 24 bits of overhead to the CHNM. SVDAG2–6 use 16-bit CHNMs, which may align to 16-bit or 32-bit boundaries depending on the implementation, but the source specifies 16-bit CHNM without explicit padding details for the node start, implying compact packing [S1].
-   **Small Scenes**: 8-bit pointers are impractical for very small scenes due to limited addressable space [S1].

## Operating characteristics
### Time and Memory Complexity
-   **Memory**: The configurations significantly reduce memory compared to SVO. For the Angel Lucy model at $4096^3$ resolution, SVO size is 59,581.0 KB, while SVDAG3 achieves 7,637.6 KB [S1].
-   **Compression Ratio**: Compared to a 1-bit-per-voxel grid, SVDAG configurations achieve ratios around 16.1 for Angel Lucy at $4096^3$, whereas SVO achieves 140.8 [S1].
-   **Success Rate**: SVDAG3 shows the highest compression success rate (1.95x better than SVDAG1) for Angel Lucy at $4096^3$ [S1].

### Measured Performance
Tests were conducted on an AMD Ryzen 7 7435HS, nVidia GeForce RTX3060, 12 GB RAM [S1].
-   **Angel Lucy ($4096^3$)**:
    -   SVO: 59,581.0 KB
    -   SVDAG1: 14,928.3 KB
    -   SVDAG2: 8,731.5 KB
    -   SVDAG3: 7,637.6 KB (Best size)
    -   SVDAG4: 8,934.0 KB
    -   SVDAG5: 8,864.9 KB
    -   SVDAG6: 9,138.0 KB
-   **Compression Success Rate (vs SVDAG1)** for Angel Lucy ($4096^3$):
    -   SVDAG2: 1.71
    -   SVDAG3: 1.95
    -   SVDAG4: 1.67
    -   SVDAG5: 1.68
    -   SVDAG6: 1.63

### Scaling and Limitations
-   **Scaling**: As resolution increases, the proportion of PT1 (8-bit) pointers decreases (from 81.17% at $128^3$ to 51.13% at $4096^3$ for SVDAG2), while PT2 and PT3 proportions increase, reflecting the larger addressable space required [S1].
-   **Limitations**: Shorter pointers (8b) are impractical for very small scenes [S1]. Mixed pointer lengths increase traversal complexity due to mixed alignment [S1].

## Background
The configurations were introduced in the context of optimizing Sparse Voxel DAGs for efficient geometry representation of voxelized 3D scenes. The study tested three polygonal surface models: Angel Lucy (489k triangles), Porsche (22k triangles), and Skull (80k triangles), voxelized at resolutions from $128^3$ to $4096^3$ [S1]. The goal was to determine the optimal balance between pointer length and addressing word size to minimize binary representation size [S1].
