# pbrt-q16

Also called: BVH layout for pbrt-q16, pbrt-q16-soaos

## Overview
pbrt-q16 is a compact Bounding Volume Hierarchy (BVH) data layout designed to reduce memory footprint while maintaining portability across CPU and GPU architectures [S1]. It solves the trade-off between aggressive compression and computational cost by combining PBRTv4’s implicit indexing with 16-bit fixed-point quantization relative to a global coordinate frame [S1]. Unlike its predecessor [Snapped Grid Extent Quantization](19480-snapped-grid-extent-quantization.md), which uses 10-bit quantization and expensive directed rounding intrinsics, pbrt-q16 uses standard arithmetic operations, eliminating architecture-specific dependencies [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of triangle primitives and their world-space bounding box ($world\_low, world\_high$) [S1].
*   **Output:** A serialized BVH structure in memory, consisting of a root header, a contiguous array of nodes, and a contiguous array of primitives [S1].

**Data Structures:**
The layout is defined by the following types and structures [S1]:

1.  **Root Header:**
    *   `primitive_count`: `u32` (32-bit unsigned integer).
    *   `primitives`: Array of `Triangle` of size `primitive_count`.
    *   `world_low`: `f32x3` (32-bit float vector). The minimum corner of the world-space bounding box [S1].
    *   `world_extent`: `f32x3` (32-bit float vector). The size of the world-space bounding box ($world\_high - world\_low$) [S1].
    *   `node_count`: `u32`. The total number of nodes in the hierarchy [S1].

2.  **Node Array:**
    *   A contiguous array of `node_count` nodes, aligned to 16 bytes [S1].
    *   Each node is indexed sequentially from 0 [S1].
    *   **Node Layout (16 bytes total):**
        *   `bounds_q`: `q16x3` (stores `lo: u16x3` and `hi: u16x3`). Stores the quantized lower and upper bounds for each axis [S1].
        *   `nprims`: `u4` (4-bit unsigned integer). The number of primitives in the node [S1].
        *   **Interior Node (if `nprims == 0`):**
            *   `c_offset`: `u28` (28-bit unsigned integer). The offset to the right child [S1].
            *   Left child index: `index + 1`.
            *   Right child index: `index + c_offset` [S1].
        *   **Leaf Node (if `nprims > 0`):**
            *   `p_offset`: `u28` (28-bit unsigned integer). The offset into the `primitives` array [S1].
            *   Primitives are stored at `primitives[p_offset : p_offset + nprims]` [S1].

**Numbered Steps:**

1.  **Root Initialization:**
    *   Compute the world-space bounding box of all input primitives: $world\_low = \min_i(P_i)$, $world\_high = \max_i(P_i)$ [G].
    *   Compute $world\_extent = world\_high - world\_low$ [G].
    *   Store `primitive_count`, the primitive array, `world_low`, `world_extent`, and `node_count` in the root header [S1].

2.  **Quantization Helper Functions:**
    *   Define the inverse bin size: $bins\_inv = \frac{1.0}{world\_extent}$ [S1].
    *   Define the quantization scale factor: $rcp = \frac{1.0}{65535.0}$ [S1].
    *   Implement `quantize_lo(coord, mlo, mex)`:
        $$ q_{lo} = \text{clamp}(\lfloor (\text{coord} - \text{mlo}) \times \frac{65535.0}{\text{mex}} \rfloor, 0, 65535) $$
    *   Implement `quantize_hi(coord, mlo, mex)`:
        $$ q_{hi} = \text{clamp}(\lceil (\text{coord} - \text{mlo}) \times \frac{65535.0}{\text{mex}} \rceil, 0, 65535) $$
    *   Implement `dequantize_lo(mlo, mex, bound)`:
        $$ \text{low} = \text{mlo} + (\text{bound.lo} \times rcp) \times \text{mex} $$
    *   Implement `dequantize_hi(mlo, mex, bound)`:
        $$ \text{high} = \text{mlo} + (\text{bound.hi} \times rcp) \times \text{mex} $$
    *   Note: `floor` and `ceil` are standard floating-point operations. Clamping ensures values stay within $[0, 65535]$ [S1].

3.  **BVH Construction:**
    *   Build the BVH tree recursively using a standard algorithm (e.g., SAH or surface area heuristic) [G].
    *   For each **Interior Node**:
        *   Compute the node's local bounding box $[low, high]$ [G].
        *   Quantize the bounds relative to the global root frame:
            *   $q_{lo} = \text{quantize\_lo}(low, world\_low, world\_extent)$
            *   $q_{hi} = \text{quantize\_hi}(high, world\_low, world\_extent)$
        *   Store $q_{lo}$ and $q_{hi}$ in `bounds_q` [S1].
        *   Set `nprims` to 0 [S1].
        *   Recursively build left and right children [G].
        *   Let $R$ be the index of the right child. Let $I$ be the index of the current node.
        *   Set `c_offset` = $R - I$ [S1].
    *   For each **Leaf Node**:
        *   Compute the node's local bounding box $[low, high]$ [G].
        *   Quantize the bounds relative to the global root frame (same as interior nodes) [S1].
        *   Store $q_{lo}$ and $q_{hi}$ in `bounds_q` [S1].
        *   Set `nprims` to the number of primitives in the leaf [S1].
        *   Store the offset of the first primitive in the global primitive array in `p_offset` [S1].

4.  **Memory Layout:**
    *   Nodes are stored in a single contiguous array, indexed by their position in the traversal order (typically pre-order or similar, ensuring left child is at `index+1`) [S1].
    *   The layout uses implicit indexing: the left child of node $i$ is always at $i+1$. The right child is at $i + c\_offset$. This eliminates the need to store child pointers explicitly, saving space [S1].

**Pseudocode:**

```python
# Helper functions for quantization and dequantization
def quantize_coord(coord: float, mlo: float, mex: float) -> int:
    """Quantize a single coordinate value to 16-bit fixed point."""
    # Formula: clamp(floor((coord - mlo) * 65535.0 / mex), 0, 65535)
    val = (coord - mlo) * (65535.0 / mex)
    val_floor = floor(val)
    clamped = max(0.0, min(val_floor, 65535.0))
    return int(clamped)

def dequantize_coord(q: int, mlo: float, mex: float) -> float:
    """Dequantize a 16-bit fixed point value back to float."""
    # Formula: mlo + (q * 1.0 / 65535.0) * mex
    return mlo + (q * (1.0 / 65535.0)) * mex

def build_bvh(primitives: List[Triangle], world_low: Vec3, world_extent: Vec3) -> BVH:
    """
    Builds the BVH structure using implicit indexing and 16-bit quantization.
    Returns a BVH object containing nodes and primitives.
    """
    # 1. Compute world bounds if not provided [G]
    if world_low is None or world_extent is None:
        all_points = [p.vertices for p in primitives]
        world_low = min(all_points)
        world_high = max(all_points)
        world_extent = world_high - world_low

    nodes = []
    primitive_offsets = []
    
    def build_recursive(prims: List[Triangle], current_node_idx: int) -> int:
        # Compute local bounds [G]
        local_low = min([p.vertices for p in prims])
        local_high = max([p.vertices for p in prims])
        
        # Quantize bounds relative to global root [S1]
        q_lo_x = quantize_coord(local_low.x, world_low.x, world_extent.x)
        q_lo_y = quantize_coord(local_low.y, world_low.y, world_extent.y)
        q_lo_z = quantize_coord(local_low.z, world_low.z, world_extent.z)
        q_hi_x = quantize_coord(local_high.x, world_low.x, world_extent.x)
        q_hi_y = quantize_coord(local_high.y, world_low.y, world_extent.y)
        q_hi_z = quantize_coord(local_high.z, world_low.z, world_extent.z)
        
        bounds_q = Q16x3(lo=(q_lo_x, q_lo_y, q_lo_z), hi=(q_hi_x, q_hi_y, q_hi_z))
        
        # Leaf threshold and split heuristic are standard BVH build parameters [G]
        if len(prims) <= 1: 
            # Leaf Node [S1]
            node = Node(
                bounds_q=bounds_q,
                nprims=len(prims),
                p_offset=len(primitive_offsets),
                is_leaf=True
            )
            nodes.append(node)
            primitive_offsets.extend(prims)
            return current_node_idx
        else:
            # Interior Node [S1]
            # Split primitives into left and right [G]
            left_prims, right_prims = split_primitives(prims)
            
            # Reserve space for left child (implicit index +1) [S1]
            left_idx = current_node_idx + 1
            left_size = build_recursive(left_prims, left_idx)
            
            # Right child index is determined by the size of the left subtree [S1]
            right_idx = current_node_idx + 1 + left_size
            right_size = build_recursive(right_prims, right_idx)
            
            # Calculate c_offset = right_index - current_index [S1]
            c_offset = right_idx - current_node_idx
            
            node = Node(
                bounds_q=bounds_q,
                nprims=0,
                c_offset=c_offset,
                is_leaf=False
            )
            nodes.append(node)
            return 1 + left_size + right_size

    # Start build at index 0 [S1]
    build_recursive(primitives, 0)
    
    return BVH(nodes=nodes, primitives=primitive_offsets, world_low=world_low, world_extent=world_extent)

# Layout definition [S1]
class Q16x3:
    lo: Tuple[int, int, int] # 3 x u16
    hi: Tuple[int, int, int] # 3 x u16

class Node:
    bounds_q: Q16x3
    nprims: int # u4
    c_offset: int # u28 (if interior)
    p_offset: int # u28 (if leaf)
    is_leaf: bool
```

**Edge Cases and Pitfalls:**
*   **Precision:** The 16-bit quantization provides $2^{16}-1 = 65535$ bins, which is a 64× increase over [Snapped Grid Extent Quantization](19480-snapped-grid-extent-quantization.md)'s 10-bit bins. This reduces representational errors in bounding volume extents, leading to fewer false negative intersections [S1].
*   **Rounding:** Unlike [Snapped Grid Extent Quantization](19480-snapped-grid-extent-quantization.md), pbrt-q16 does not require directed rounding modes (e.g., round-to-zero, round-to-infinity) for watertight dequantization. It uses standard `floor` and `ceil` operations, which are portable across CPUs and GPUs [S1].
*   **Boundary Conditions:** The quantization function clamps values to $[0, 65535]$. If a primitive's coordinate falls exactly on the boundary, the clamping ensures it maps to the maximum bin value. Dequantization will map this back to a value close to the boundary, potentially introducing a small error. However, this is generally acceptable for BVH traversal [S1].
*   **Node Alignment:** Nodes are 16-byte aligned. This aligns with cache line boundaries on contemporary architectures, improving memory access performance [S1].

## Subtopics

### pbrt-q16-soaos
A variant of pbrt-q16 that reorganizes the data into a Struct-of-Arrays-of-Structs (SOAoS) format. It dominates 4 of the 7 non-dominating instances where pbrt-q16 is not Pareto-optimal, particularly on CUDA architectures [S1]. See [pbrt-q16-soaos](pbrt-q16-soaos.md).

### Snapped Grid Extent Quantization (sg-eq)
The parent method that uses 10-bit quantization and directed rounding. pbrt-q16 improves upon it by using 16-bit quantization and standard arithmetic, at the cost of slightly larger node size (16 bytes vs 12 bytes) [S1]. See [Snapped Grid Extent Quantization](19480-snapped-grid-extent-quantization.md).

## Operating characteristics
*   **Memory Footprint:** Each node is 16 bytes. This is larger than [Snapped Grid Extent Quantization](19480-snapped-grid-extent-quantization.md)'s 12 bytes but smaller than PBRTv4's 32 bytes [S1].
*   **Performance:** pbrt-q16 achieves Pareto optimality in 35 of 42 evaluation contexts spanning three architectures, seven scenes, and two ray distribution patterns [S1].
*   **Portability:** By avoiding directed rounding intrinsics, pbrt-q16 is portable across CPU and GPU targets, unlike sg-eq which may suffer performance penalties on architectures lacking explicit support for such intrinsics [S1].
*   **Accuracy:** The 16-bit quantization reduces false negative intersections compared to 10-bit quantization, potentially improving traversal accuracy [S1].
*   **When to use:** Use pbrt-q16 when memory footprint and portability are critical, and when the target hardware does not support efficient directed rounding operations. It is suitable for general-purpose ray tracing on diverse hardware [S1].
*   **When not to use:** If maximum compression is required and the target hardware supports efficient directed rounding, [Snapped Grid Extent Quantization](19480-snapped-grid-extent-quantization.md) may be preferable [S1].

## Background
pbrt-q16 was introduced in the paper "Decoupling Data Layouts from Bounding Volume Hierarchies" (2026) [S1]. It combines techniques from disparate sources: implicit indexing from PBRTv4 [S1], global coordinate framing from molecular simulation neighbor search [S1], and quantization from Benthin et al. [S1]. The design aims to discover a layout that achieves Pareto-optimality across diverse evaluation contexts. It addresses the portability-performance trade-off of existing quantization schemes by using standard arithmetic operations [S1].
