# Tiny LOD


## Overview
Tiny LOD is a method for constructing a hierarchical level-of-detail (LOD) representation of volumetric data, specifically designed to integrate with sparse voxel structures and splat-based rendering pipelines. It solves the problem of efficiently managing resolution trade-offs in large, sparse volumetric datasets by generating a tree structure that aggregates voxel data into coarser primitives. It is distinguished from sibling methods like [Compact pointer tree](844-compact-pointer-tree.md) by its specific integration with the "spark" ecosystem's data structures, utilizing a configurable merge filter and base LOD parameter to control the granularity of the hierarchy [S1, unofficial].

## How it works
The method constructs an LOD tree from an input volumetric dataset (often represented as splats or voxels) and outputs a hierarchical structure suitable for encoding opacity and building a chunk tree for rendering.

**Inputs:**
- `inner_data`: The source volumetric data structure (e.g., splats or voxels).
- `lod_base`: A floating-point value ($f32$) controlling the base level of detail for the tree computation [S1, unofficial].
- `merge_filter`: A boolean flag ($bool$) determining whether a merge filter is applied during the LOD tree computation [S1, unofficial].
- `log_callback`: A function for logging progress or errors.

**Outputs:**
- An LOD tree structure.
- Encoded opacity values associated with the LOD structure.
- A chunk tree rooted at index 0.

**Data Structures:**
The specific internal layout of the LOD tree is not fully detailed in the sources, but it is implied to contain nodes that aggregate voxel data. The opacity values are encoded separately or within the structure for efficient access [S1, unofficial].

**Steps:**
1.  **Sanitize Input:** Remove any invalid splats or data points from the `inner_data` structure to ensure data integrity [S1, unofficial].
2.  **Compute LOD Tree:** Invoke the `tiny_lod` computation routine. Pass the sanitized `inner_data`, the `lod_base` parameter, the `merge_filter` flag, and the `log_callback` to generate the hierarchical LOD structure [S1, unofficial].
3.  **Encode Opacity:** Process the computed LOD structure to encode opacity values. This step prepares the data for rendering by mapping scalar values to opacity representations suitable for the target pipeline [S1, unofficial].
4.  **Build Chunk Tree:** Construct a chunk tree starting at index 0. This step likely organizes the LOD data into chunks for efficient memory access and traversal during rendering, using the provided `log_callback` [S1, unofficial].

**Pseudocode:**
```python
def compute_tiny_lod(inner_data, lod_base, merge_filter, log_callback):
    # Step 1: Remove invalid splats from the inner data structure
    clean_data = remove_invalid_splats(inner_data)
    
    # Step 2: Compute the level-of-detail tree
    # Pass inner data, lod_base, merge_filter, and log callback
    lod_tree = tiny_lod_library.compute(
        data=clean_data,
        lod_base=lod_base,
        merge_filter=merge_filter,
        log=log_callback
    )
    
    # Step 3: Encode the opacity values for the computed LOD structure
    encoded_opacities = encode_opacity(lod_tree)
    
    # Step 4: Build the chunk tree starting at index 0
    chunk_tree = build_chunk_tree(
        lod_tree=lod_tree,
        start_index=0,
        log=log_callback
    )
    
    return lod_tree, encoded_opacities, chunk_tree
```

**Parameters:**
- `lod_base` ($f32$): The base value for LOD computation. It influences the initial granularity or depth of the tree [S1, unofficial].
- `merge_filter` ($bool$): Controls whether to apply a merge filter during LOD tree computation. This likely affects how adjacent or similar nodes are combined [S1, unofficial].

**Edge Cases and Pitfalls:**
- Invalid splats in the input data must be handled; failure to remove them may lead to errors during tree construction [S1, unofficial].
- The exact impact of `lod_base` and `merge_filter` on the final visual quality or memory footprint is not quantified in the sources [S1, unofficial].

## Subtopics

### [Trilinear Evaluation on Compressed Trees](7074-trilinear-evaluation-on-compressed-trees.md)
This method evaluates a signal value at an arbitrary point $\mathbf{x}$ within a compressed tree structure, supporting trilinear filtering and adaptive traversal. It serves as the evaluation engine for the Compressed Random-Access Tree (CRAT) framework, enabling fine-grain random queries required by rendering algorithms. Unlike block-based decompression schemes (e.g., DXT1) that rely on specialized hardware, this method uses adaptive tree traversal to reconstruct data on the fly, trading raw decompression speed for spatial coherence and high-quality filtering.

### [LODTree Storage Layout](16362-lodtree-storage-layout.md)
The LODTree storage layout is a sparse, hierarchical data structure designed to store volumetric data with multiple levels of detail (LOD) in a compact format, enabling efficient dynamic isosurface extraction. It differs from sibling methods like [Trilinear Evaluation on Compressed Trees](7074-trilinear-evaluation-on-compressed-trees.md) by explicitly managing virtual voxel expansion across discrete LOD levels using a bit-mapped cell representation to minimize storage overhead.

### High LOD Approximation
A strategy for preserving local detail in the highest LOD level of a Gaussian particle approximation.
**Definition:**
The highest LOD level that retains local detail by using smaller subdivision blocks for dense nodes and per-voxel mapping for sparse nodes [S2, unofficial].
**Steps:**
1.  For dense leaf nodes: Subdivide into $2 \times 2 \times 2$ blocks, aggregating every 8 adjacent voxels into a single Gaussian [S2, unofficial].
2.  For dense leaf nodes: Average the scalar values of the 8 voxels to compute the Gaussian’s opacity [S2, unofficial].
3.  For dense leaf nodes: Transform the block center in index space (offset by `voxelSize`) into world space to serve as the Gaussian’s position [S2, unofficial].
4.  For dense leaf nodes: Set covariance to be axis-aligned and correspond to the full voxel size along each axis [S2, unofficial].
5.  For non-dense leaf nodes: Treat at per-voxel level, converting each active voxel individually into a Gaussian primitive [S2, unofficial].
6.  For non-dense leaf nodes: Use voxel center (offset by half the `voxelSize`) as the mean and opacity taken directly from the voxel value [S2, unofficial].
7.  For non-dense leaf nodes: Set Gaussian radii to half the voxel size [S2, unofficial].
