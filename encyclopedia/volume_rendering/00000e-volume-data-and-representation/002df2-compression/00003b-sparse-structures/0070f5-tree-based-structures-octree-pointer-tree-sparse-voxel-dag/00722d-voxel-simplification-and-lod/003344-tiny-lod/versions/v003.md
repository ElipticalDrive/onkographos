# Tiny LOD


## Overview
Tiny LOD is a method for generating hierarchical level-of-detail (LOD) structures from sparse volumetric data, specifically designed for integration with sparse voxel DAGs and similar tree-based representations. It solves the problem of efficiently compressing volumetric splats or voxel fields into a multi-resolution hierarchy that supports fast rendering and memory-efficient storage. It is distinguished from general-purpose LOD generators by its tight coupling with the "chunk tree" data structure used in the Spark rendering framework, focusing on opacity encoding and subtree merging for sparse data [S1, unofficial].

## How it works
Tiny LOD operates on a pre-processed inner data structure (typically a collection of splats or voxels) to produce a compressed LOD tree. The process involves cleaning the input, computing the hierarchical structure, encoding attributes, and building the final chunk tree.

### Inputs and Outputs
- **Input:** An inner data structure containing volumetric primitives (e.g., splats or voxels).
- **Parameters:**
  - `lod_base` (f32): The base value for LOD computation, influencing the granularity of the hierarchy [S1, unofficial].
  - `merge_filter` (bool): A flag controlling whether a merge filter is applied during LOD tree computation to reduce node count [S1, unofficial].
  - `log_callback`: A function for logging progress or errors [S1, unofficial].
- **Output:** A chunk tree structure starting at index 0, ready for rendering or further processing [S1, unofficial].

### Data Structures
The method relies on the **Chunk Tree** structure, which is a sparse voxel DAG variant.
- **Chunk Tree:** A graph-based structure where nodes represent spatial chunks. Nodes are identified by indices. The root is at index 0.
- **LOD Structure:** An intermediate hierarchical representation of the data before final chunk tree assembly.

### Steps
1. **Remove Invalid Splats:** Filter out any invalid or degenerate primitives from the inner data structure to ensure data integrity [S1, unofficial].
2. **Compute LOD Tree:** Use the `tiny_lod` library to compute the level-of-detail tree. Pass the cleaned inner data, `lod_base`, `merge_filter`, and the `log_callback` [S1, unofficial].
3. **Encode Opacity:** Encode the opacity values for the computed LOD structure. This step prepares the scalar field data for efficient storage and retrieval [S1, unofficial].
4. **Build Chunk Tree:** Construct the final chunk tree starting at index 0. Use the `log_callback` for progress tracking [S1, unofficial].

### Pseudocode
```python
def compute_tiny_lod(inner_data, lod_base, merge_filter, log_callback):
    """
    Computes the Tiny LOD structure from inner volumetric data.
    
    Args:
        inner_data: The raw volumetric primitives (splats/voxels).
        lod_base (float): Base value for LOD computation.
        merge_filter (bool): Whether to apply merge filter.
        log_callback (function): Function to log progress.
        
    Returns:
        chunk_tree: The final chunk tree structure.
    """
    # Step 1: Remove invalid splats from the inner data structure
    cleaned_data = remove_invalid_splats(inner_data)
    
    # Step 2: Compute the level-of-detail tree
    lod_tree = compute_lod_tree(
        data=cleaned_data,
        lod_base=lod_base,
        merge_filter=merge_filter,
        log_callback=log_callback
    )
    
    # Step 3: Encode the opacity values for the computed LOD structure
    encoded_lod_tree = encode_opacity(lod_tree)
    
    # Step 4: Build the chunk tree starting at index 0
    chunk_tree = build_chunk_tree(
        lod_structure=encoded_lod_tree,
        start_index=0,
        log_callback=log_callback
    )
    
    return chunk_tree
```

### Edge Cases and Pitfalls
- **Invalid Data:** The first step explicitly removes invalid splats. Failure to do so may lead to undefined behavior in the LOD computation [S1, unofficial].
- **Precision:** The `lod_base` is a 32-bit float. Precision issues may arise if the data scale is significantly different from the base value [S1, unofficial].
- **Merge Filter:** Setting `merge_filter` to `True` may reduce memory usage but could potentially merge distinct features if the threshold is too aggressive. The exact behavior of the merge filter is not detailed in the sources [S1, unofficial].

## Subtopics

### [Trilinear Evaluation on Compressed Trees](7074-trilinear-evaluation-on-compressed-trees.md)
This method evaluates a signal value at an arbitrary point $\mathbf{x}$ within a compressed tree structure, supporting trilinear filtering and adaptive traversal. It serves as the evaluation engine for the Compressed Random-Access Tree (CRAT) framework, enabling fine-grain random queries required by rendering algorithms. Unlike block-based decompression schemes (e.g., DXT1) that rely on specialized hardware, this method uses adaptive tree traversal to reconstruct data on the fly, trading raw decompression speed for spatial coherence and high-quality filtering.

### Bhatt LOD
Bhatt LOD is a variant of the LOD computation method that uses the `bhatt_lod` library instead of `tiny_lod`. It follows a similar pipeline: removing invalid splats, computing the LOD tree, encoding opacity, and building the chunk tree [S1, unofficial]. The primary difference is the underlying algorithm used for LOD computation, which may offer different trade-offs in terms of detail retention and compression ratio. It takes `lod_base` as a parameter [S1, unofficial].

### High LOD Approximation
High LOD Approximation is a specific strategy for preserving local detail in sparse voxel data by using smaller subdivision blocks for dense nodes and per-voxel mapping for sparse nodes [S2, unofficial]. It is not a separate library but a configuration or mode within a LOD generation pipeline.

#### Steps
1. **Dense Leaf Nodes:** Subdivide into 2x2x2 blocks, aggregating every 8 adjacent voxels into a single Gaussian [S2, unofficial].
2. **Dense Leaf Nodes:** Average the scalar values of the 8 voxels to compute the Gaussian’s opacity [S2, unofficial].
3. **Dense Leaf Nodes:** Transform the block center in index space (offset by `voxelSize`) into world space to serve as the Gaussian’s position [S2, unofficial].
4. **Dense Leaf Nodes:** Set covariance to be axis-aligned and correspond to the full voxel size along each axis [S2, unofficial].
5. **Non-Dense Leaf Nodes:** Treat at the per-voxel level, converting each active voxel individually into a Gaussian primitive [S2, unofficial].
6. **Non-Dense Leaf Nodes:** Use voxel center (offset by half the `voxelSize`) as the mean and opacity taken directly from the voxel value [S2, unofficial].
7. **Non-Dense Leaf Nodes:** Set Gaussian radii to half the voxel size [S2, unofficial].

#### Characteristics
- **Dense Regions:** Results in a dense tiling of Gaussians that approximates the field at near-voxel resolution while reducing primitive count through regular grouping [S2, unofficial].
- **Sparse Regions:** Produces a one-to-one mapping between active voxels and Gaussians, maximizing detail retention in sparse regions [S2, unofficial].
- **Trade-offs:** While treating one Gaussian per voxel may seem simplistic, it serves as a starting point for exploring feature-preserving optimal clustering strategies in sparse leaves where voxels are unevenly spread [S2, unofficial].
