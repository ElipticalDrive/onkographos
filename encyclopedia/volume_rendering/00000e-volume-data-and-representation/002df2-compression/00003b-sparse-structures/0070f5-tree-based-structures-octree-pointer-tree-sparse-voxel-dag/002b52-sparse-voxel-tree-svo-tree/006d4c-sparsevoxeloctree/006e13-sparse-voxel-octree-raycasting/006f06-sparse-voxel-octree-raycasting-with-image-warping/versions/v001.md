# Sparse Voxel Octree Raycasting with Image Warping

Also called: Sparse Voxel Octree Raycasting with Image Warping exploiting Frame-to-Frame Coherence

## Overview
This method accelerates Sparse Voxel Octree (SVO) raycasting by exploiting temporal coherence between consecutive frames. Instead of raycasting every pixel, it reprojects pixel coordinates from the previous frame to the current frame using the differential view matrix, raycasting only the "holes" (pixels that moved or were occluded) and empty regions. It sets itself apart from standard SVO raycasting [Sparse Voxel Octree Raycasting](21492-sparse-voxel-octree-raycasting.md) by reducing the number of raycasts per frame significantly, trading off visual smoothness during fast motion for performance.

## How it works
**Inputs:** Previous frame's coordinate buffer, current view/projection matrices, SVO data structure.
**Outputs:** Current frame's color buffer.

**Data Structures:**
1.  **Coordinate Buffer:** Stores the 3D world coordinates $(x, y, z)$ for each pixel of the previous frame.
2.  **Index Buffer:** Stores indices of empty 2x2 pixel blocks identified for raycasting.
3.  **Triple Buffer System:** Two image caches (copy buffers) and one write buffer. This handles cases where a pixel overwritten in one frame becomes visible in the next.

**Steps:**
1.  **Reprojection:** For each pixel in the current frame, retrieve its $(x, y, z)$ from the coordinate buffer of the previous frame. Reproject these coordinates into the current screen space using the differential view matrix. If the reprojection is valid and the pixel is not occluded, reuse the previous color.
2.  **Hole Gathering:** Identify pixels that could not be reused (holes). The method gathers empty 2x2 pixel blocks on the screen and stores their indices in the index buffer for raycasting. Raycasting single pixels is considered inefficient; thus, blocks are used [S1, unofficial].
3.  **Hole Filling:** Raycast the holes identified in the index buffer.
4.  **Image Filtering:** Close small holes remaining after the hole-filling pass with a simple image filter to reduce visual artifacts [S1, unofficial].
5.  **Tile-Based Refresh:** To ensure the cache is fully refreshed and prevent stale data accumulation, the screen is updated in tiles of 8x4 pixels. An entire tile is raycasted and overwrites the cache. With this tile size, the entire cache is refreshed after 32 frames [S1, unofficial].
6.  **Buffer Management:** Before hole filling starts, project the two cache buffers to the main image buffer to handle visibility changes [S1, unofficial].

**Pseudocode:**
```python
def render_frame_svo_warping(prev_coord_buffer, prev_color_buffer, current_view_matrix, current_proj_matrix, svo_tree, width, height):
    # Initialize current color buffer
    current_color_buffer = zeros((height, width, 3))
    
    # Triple buffer management: Project two cache buffers to main buffer
    # This handles pixels overwritten in one frame but visible in the next
    main_image_buffer = project_cache_buffers(prev_color_buffer)
    
    # Step 1: Reprojection
    index_buffer = []
    for y in range(height):
        for x in range(width):
            # Get previous 3D coordinate
            prev_coord = prev_coord_buffer[y, x]
            
            # Reproject using differential view matrix
            # Note: Differential view matrix implies using the change in view matrix
            # to estimate the new screen position of the previous 3D point
            new_screen_pos = reproject(prev_coord, current_view_matrix, current_proj_matrix)
            
            # Check if reprojection is valid and pixel is not occluded
            if is_valid_reprojection(new_screen_pos, x, y, main_image_buffer):
                current_color_buffer[y, x] = prev_color_buffer[y, x]
            else:
                # Mark as hole
                index_buffer.append((x, y))
    
    # Step 2: Gather empty 2x2 pixel blocks
    # Convert individual holes into 2x2 blocks for efficiency
    block_index_buffer = gather_2x2_blocks(index_buffer)
    
    # Step 3: Raycast holes
    for (bx, by) in block_index_buffer:
        # Raycast the 2x2 block
        raycast_block(svo_tree, bx, by, current_color_buffer)
    
    # Step 4: Image filtering for small remaining holes
    current_color_buffer = apply_image_filter(current_color_buffer)
    
    # Step 5: Tile-based refresh
    # Update screen in tiles of 8x4 pixels
    tile_width = 8
    tile_height = 4
    for ty in range(0, height, tile_height):
        for tx in range(0, width, tile_width):
            # Raycast entire tile and overwrite cache
            raycast_tile(svo_tree, tx, ty, tile_width, tile_height, current_color_buffer)
    
    # Update coordinate buffer for next frame
    # Store the 3D coordinates of the current frame's pixels
    new_coord_buffer = compute_coordinates(current_color_buffer, current_view_matrix, current_proj_matrix)
    
    return current_color_buffer, new_coord_buffer

    # Transform 3D coordinate to clip space
    clip_pos = proj_matrix * view_matrix * coord

    # Convert to screen space
    screen_pos = ndc_to_screen(ndc_pos)
    return screen_pos
```

**Parameters:**
-   Tile size: 8x4 pixels [S1, unofficial].
-   Cache refresh interval: 32 frames [S1, unofficial].
-   Block size for hole gathering: 2x2 pixels [S1, unofficial].

**Edge Cases and Pitfalls:**
-   During fast motions, silhouettes of geometry close to the camera lose precision [S1, unofficial].
-   Geometry in the background moves less smoothly than full per-frame raytracing [S1, unofficial].
-   The method is only suitable for primary rays and pixel properties that remain constant over multiple frames, such as static ambient lighting [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** Reduced by a factor of up to 5x compared to standard SVO raycasting, depending on scene motion [S1, unofficial].
-   **Memory Complexity:** Requires additional memory for coordinate buffers and triple buffering.
-   **Measured Performance:** Tested at 1920x1024 resolution, achieving 30-50 fps [S1, unofficial].
-   **Strengths:** Significant speedup in static or slowly moving scenes.
-   **Limitations:** Visual artifacts during fast motion, unsuitable for dynamic lighting or secondary rays.

## Background
This method was developed as part of the HVOX engine, leveraging the Sparse Voxel Octree data structure for efficient volume rendering. It addresses the computational cost of raycasting by reusing information from previous frames.
