# Explicit Radiance Field (ERF) Reconstruction

Also called: Direct SVO Reconstruction

## Overview
Explicit Radiance Field (ERF) Reconstruction is a direct, uniform 3D reconstruction method from registered multi-view images that utilizes an explicit Sparse Voxel Octree (SVO) representation with dynamic voxel allocations [S1, unofficial]. It solves the problem of reconstructing unbounded, freely captured static radiance fields without relying on implicit neural networks or external initialization constraints [S1, unofficial]. Unlike implicit methods such as VolSDF, ERF avoids the need for segmentation masks and discontinuities in the objective function by modeling geometry via an opacity field rather than a Signed Distance Field (SDF) [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:**
    1.  An unstructured set of unordered multi-view images.
    2.  Sensor poses and intrinsics (obtained via Structure from Motion, SfM).
    3.  A coarse, conservative Axis-Aligned Bounding Box (AABB) defining the reconstruction volume.
*   **Outputs:**
    1.  An SVO representing the scene geometry and appearance within the AABB.
    2.  A background model (environment map) for distant regions (e.g., sky).

**Data Structures**
The core data structure is the Sparse Voxel Octree (SVO). Each node in the SVO stores:
1.  **Opacity Field:** A volumetric scalar field defining surface geometry. This models "soft-relaxed" surfaces rather than occupied space, making it suitable for opaque surfaces and intricate geometry like fur [S1, unofficial].
2.  **Spherical Harmonics (SHs):** A volumetric vector field encoding the scene's Surface Light Field (SLF). This represents the total outgoing radiance for each surface point along each hemispherical direction [S1, unofficial].
3.  **Level of Detail (LoD):** Each tree level represents the scene at a specific resolution, analogous to mipmap textures, allowing inner nodes to store coarser approximations and leaves to store detailed surfaces [S1, unofficial].

**Algorithm Steps**
1.  **Preprocessing:** Run Structure from Motion (SfM) using COLMAP on the input unordered multi-view images to obtain sensor poses, camera intrinsics, and a sparse feature point cloud [S1, unofficial].
2.  **AABB Estimation:** Manually estimate the conservative minimum and maximum corners of the scene's AABB using the SfM feature points to bound the reconstruction volume [S1, unofficial].
3.  **Initialization:** Initialize the SVO structure. Since free space and surfaces are initially unknown, the method employs dynamic voxel allocations to prevent memory exhaustion [S1, unofficial].
4.  **Optimization:** Optimize the SVO parameters (opacity and SH coefficients) using the Adam optimizer. This process follows a coarse-to-fine strategy [S1, unofficial].
5.  **Local Plane Storage:** Apply a local plane-based storage and interpolation scheme to the volumetric fields attached to SVO nodes. This allows the approximation of thin and fine geometric details even when the SVO is initially coarse [S1, unofficial].
6.  **Importance Sampling:** Perform scene sampling using an importance sampling scheme. This scheme gradually filters sampling points based on the current geometry estimate, allowing the SVO structure to adapt dynamically to scene content without external guides [S1, unofficial].
7.  **Rendering:** Render the scene using traditional opacity compositing. This differs from the exponential transmittance model used in other methods, avoiding blurry transitions from free to occupied space and achieving clear surface boundaries [S1, unofficial].

**Pseudocode**
```python
def erf_reconstruction(images, target_aabb):
    """
    Reconstructs an Explicit Radiance Field from multi-view images.
    
    Args:
        images: List of unordered multi-view images.
        target_aabb: Axis-aligned bounding box (min_corner, max_corner) 
                     estimated from SfM points.
    
    Returns:
        svo: The optimized Sparse Voxel Octree.
        env_map: Background environment map.
    """
    # Step 1: Preprocessing with COLMAP
    # Obtain sensor poses, intrinsics, and sparse feature cloud
    poses, intrinsics, sparse_cloud = colmap_sfm(images)
    
    # Step 2: Refine AABB if necessary (manual estimation assumed done)
    # The target_aabb is provided as input, derived from sparse_cloud
    
    # Step 3: Initialize SVO with dynamic allocation
    # Start with a coarse root node; allocate children dynamically during optimization
    svo = SVO(root_node=Node(), aabb=target_aabb)
    
    # Step 4: Optimization Loop (Coarse-to-Fine)
    optimizer = AdamOptimizer(params=svo.get_parameters())
    
    while not converged:
        # Step 6: Importance Sampling
        # Filter sampling points based on current geometry estimate
        samples = importance_sample(svo, poses, intrinsics)
        
        # Step 7: Rendering
        # Use traditional opacity compositing
        rendered_images = []
        for sample in samples:
            # Traverse SVO to find opacity and SH values at sample point
            opacity = svo.get_opacity(sample.position)
            sh_coeffs = svo.get_sh_coeffs(sample.position)
            
            # Compute radiance using SHs
            radiance = evaluate_sh(sh_coeffs, sample.direction)
            
            # Composite using opacity
            # Note: Traditional opacity compositing is used instead of 
            # exponential transmittance to avoid blurry free-space transitions
            color = composite_opacity(opacity, radiance)
            rendered_images.append(color)
        
        # Compute loss against input images
        loss = compute_loss(rendered_images, images)
        
        # Step 5: Local Plane Storage Update
        # Update volumetric fields using local plane-based interpolation
        svo.update_fields_with_local_planes()
        
        # Update SVO structure dynamically
        svo.allocate_dynamic_voxels()
        
        # Backpropagate and update parameters
        optimizer.step(loss)
        
        # Check convergence criteria
        if check_convergence(svo, loss):
            break
            
    # Extract background model for regions outside SVO
    env_map = compute_background_model(images, poses)
    
    return svo, env_map
```

**Parameters**
*   **Opacity Field:** Models soft-relaxed surfaces. Used for inverse differentiable rendering of opaque surfaces and intricate geometry like fur [S1, unofficial].
*   **Spherical Harmonics (SHs):** Encode the scene SLF, representing the total outgoing radiance for each surface point along each hemispherical direction [S1, unofficial].
*   **Optimizer:** Adam optimizer [S1, unofficial].
*   **Strategy:** Coarse-to-fine optimization with dynamic voxel allocations [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Memory Exhaustion:** Without dynamic voxel allocations, the method may run out of memory when optimizing freely captured scenes [S1, unofficial].
*   **Free Space Transitions:** Using an exponential transmittance model (common in other volume rendering methods) results in blurry transitions from free to occupied space. ERF avoids this by using traditional opacity compositing [S1, unofficial].
*   **Initialization:** Unlike methods that use an initial implicit model (e.g., NeRF) as a free-space constraint, ERF starts with no prior knowledge of free space or surfaces, requiring the importance sampling scheme to guide the SVO adaptation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Managed via dynamic voxel allocations and the sparse nature of the SVO. The coarse-to-fine strategy prevents memory exhaustion [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:**
    *   Direct reconstruction from scratch without implicit network-based parts [S1, unofficial].
    *   Handles unbounded volumes (e.g., outdoor scenes) [S1, unofficial].
    *   Clear surface boundaries due to traditional opacity compositing [S1, unofficial].
    *   Suitable for intricate geometry like fur [S1, unofficial].
*   **Limitations:**
    *   Requires manually estimated conservative AABB [S1, unofficial].
    *   Designed for static scenes with sensor poses roughly facing the same direction [S1, unofficial].
    *   Does not use external guides for initialization, relying on dynamic adaptation [S1, unofficial].
*   **When to use:** For freely captured, uncontrolled static radiance fields, including outdoor scenes with unbounded volumes [S1, unofficial].
*   **When not to use:** For scenes requiring dynamic content or where manual AABB estimation is impractical [S1, unofficial].

## Background
*   **Origin:** The method was introduced in "ERF: Explicit Radiance Field Reconstruction From Scratch" [S1, unofficial].
*   **History:** It was developed as an alternative to implicit methods like VolSDF and hybrid approaches like PlenOctree. While PlenOctree also uses SVOs and SHs, it requires a multi-step pipeline starting from a registered image set and an initial NeRF model. ERF distinguishes itself by reconstructing directly from images without implicit network parts or external initialization [S1, unofficial].
*   **Usage:** It is used for 3D reconstruction of static scenes, particularly those with unbounded volumes or intricate details, where explicit representation is preferred over implicit neural fields [S1, unofficial].

## Subtopics

### Sparse Voxel Octree (SVO)
The underlying data structure used by ERF. It provides a hierarchical, sparse representation of 3D space, allowing for efficient storage and rendering of large scenes. [S1, unofficial] See [SparseVoxelOctree](21324-sparsevoxeloctree.md).

### Spherical Harmonics (SH)
Used in ERF to encode view-dependent appearance (SLF) at each node of the SVO. This allows for efficient storage of complex lighting and material properties. [S1, unofficial]

### Opacity Field
The geometric representation used in ERF, modeling soft-relaxed surfaces rather than occupied space or signed distances. This avoids the need for segmentation masks and handles discontinuities better than SDF-based methods. [S1, unofficial]
