# Sparse Voxel Octree Raycasting

Also called: Hierarchical SVO Ray Traversal, Nav3D Raycaster, Ray Tracing in Octree

## Overview
Sparse Voxel Octree (SVO) Raycasting is a hierarchical traversal algorithm designed to efficiently intersect rays with sparse voxel data structures, primarily for 3D navigation and visibility analysis [S2, unofficial]. Unlike uniform grid raycasting, it skips empty space by traversing only occupied nodes from the highest layer down to the leaves [S1, unofficial][S2, unofficial]. It distinguishes itself by handling arbitrary ray directions through a coordinate reflection technique, ensuring the traversal logic remains consistent regardless of the ray's orientation relative to the world axes [S1, unofficial][S2, unofficial].

## How it works
The method transforms the ray into a canonical positive-direction space, traverses the octree hierarchy, and inverse-transforms the result [S1, unofficial]. This avoids complex branching logic for negative direction components during the core traversal loop [S1, unofficial]. The implementation relies on specific structures to manage traversal state and ray bounds [S2, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   `RayOrigin`: 3D vector $(O_x, O_y, O_z)$ representing the ray start point.
    *   `RayDirection`: 3D vector $(D_x, D_y, D_z)$ representing the ray direction.
    *   `VolumeCenter`: 3D vector $(C_x, C_y, C_z)$ defining the center of the navigation volume.
    *   `NavigationBounds`: Axis-aligned bounding box (AABB) defined by `Min` and `Max` vectors.
    *   `Octree`: The Sparse Voxel Octree structure, accessed via `HighestLayer` and node indices.
*   **Outputs**:
    *   `Hit`: Boolean indicating if a valid intersection was found.
    *   `ImpactPoint`: 3D vector of the intersection point (if `Hit` is true).
    *   `OccludedVoxelCount`: Integer count of empty voxels traversed (optional metric).

### Data Structures
**FNav3DNodeAddress**
Used to identify nodes within the octree hierarchy [S2, unofficial].
*   `LayerIndex`: `int32` – The depth level in the octree.
*   `NodeIndex`: `int32` – The index of the node within the layer.
*   `SubNodeIndex`: `int32` – The child index (0-7) within the node.

**FOctreeRay**
Represents the ray's intersection interval with the axis-aligned bounding box of the current traversal scope [S2, unofficial]. It stores 6 floats:
*   `tMinX`, `tMaxX`: Entry and exit distances along the X-axis [S2, unofficial].
*   `tMinY`, `tMaxY`: Entry and exit distances along the Y-axis [S2, unofficial].
*   `tMinZ`, `tMaxZ`: Entry and exit distances along the Z-axis [S2, unofficial].

**RayState.A**
A bitmask register storing the transformation state [S2, unofficial].
*   Bit 1 (value 1): X-axis reflection flag [S2, unofficial].
*   Bit 2 (value 2): Y-axis reflection flag [S2, unofficial].
*   Bit 4 (value 4): Z-axis reflection flag [S2, unofficial].

### Parameters
*   `KINDA_SMALL_NUMBER`: Epsilon threshold for clamping near-zero ray direction components to prevent division by zero [S2, unofficial].

### Algorithm Steps

1.  **Ray Direction Normalization and Clamping**:
    Compute the raw direction vector:
    $$ \vec{D} = \vec{O}_{target} - \vec{O}_{start} $$
    Clamp any component $D_i$ where $|D_i| < \text{KINDA\_SMALL\_NUMBER}$ to $\text{KINDA\_SMALL\_NUMBER}$ (preserving sign) or a small non-zero value to ensure valid inverse calculations [S1, unofficial][S2, unofficial].

2.  **Coordinate Reflection for Negative Directions**:
    Initialize `RayState.A` to 0. For each axis $i \in \{X, Y, Z\}$:
    *   If $D_i < 0$:
        *   Reflect the origin component: $O_i = 2 \cdot C_i - O_i$ [S2, unofficial].
        *   Negate the direction component: $D_i = -D_i$ [S2, unofficial].
        *   Set the corresponding bit in `RayState.A` (Bit 1 for X, Bit 2 for Y, Bit 4 for Z) [S2, unofficial].

3.  **Inverse Direction Calculation**:
    Compute the inverse direction components:
    $$ \text{Div}_i = \frac{1.0}{D_i} \quad \text{for } i \in \{X, Y, Z\} $$
    [S2, unofficial]

4.  **Ray-Bounds Intersection**:
    Compute the intersection interval $[t_{min}, t_{max}]$ of the ray with the `NavigationBounds` AABB [S2, unofficial].
    For each axis $i$:
    $$ t_{min,i} = (\text{Bounds.Min}_i - O_i) \cdot \text{Div}_i $$
    $$ t_{max,i} = (\text{Bounds.Max}_i - O_i) \cdot \text{Div}_i $$
    Construct `FOctreeRay` with these values [S2, unofficial].
    *   If the ray does not intersect the bounds (i.e., $t_{min} > t_{max}$ for any axis, or the intervals do not overlap), terminate and return no hit [S2, unofficial].

5.  **Hierarchical Traversal**:
    Initialize `OccludedVoxelCount = 0`.
    Start traversal at `HighestLayer = LayerCount - 1` with `NodeIndex = 0` (root) [S2, unofficial].
    *   Determine which octant the ray origin lies in, repeating until an empty voxel is reached [S1, unofficial].
    *   Compute which internal face of the current octant the ray hits, and update the ray origin to the intersection position [S1, unofficial].
    *   If the space adjacent to the intersected face is another octant of the same parent (sibling nodes), update the current octant and repeat the process [S1, unofficial].
    *   If not a sibling, search up the parent node until sibling nodes are found [S1, unofficial].
    *   If the search reaches the root (no more parent), the ray is considered out of scene [S1, unofficial].
    *   If the ray intersects a leaf node, reproduce the node's color to the pixel [S1, unofficial].
    *   Maintain a stack of nodes for spatial search. When the ray origin's octant is updated, push the previous octant onto the stack. When searching for sibling nodes in the parent, pop the current node from the stack [S1, unofficial].

6.  **Inverse Transformation of Result**:
    If a hit is found at `ImpactPoint`:
    *   If `RayState.A` has Bit 1 set: $ImpactPoint.X = 2 \cdot C_x - ImpactPoint.X$ [S2, unofficial].
    *   If `RayState.A` has Bit 2 set: $ImpactPoint.Y = 2 \cdot C_y - ImpactPoint.Y$ [S2, unofficial].
    *   If `RayState.A` has Bit 4 set: $ImpactPoint.Z = 2 \cdot C_z - ImpactPoint.Z$ [S2, unofficial].

### Pseudocode

```python
def svo_raytrace(ray_origin, ray_target, volume_center, nav_bounds_min, nav_bounds_max, octree):
    # 1. Compute direction and clamp near-zero components
    ray_dir = [ray_target[i] - ray_origin[i] for i in range(3)]
    KINDA_SMALL_NUMBER = 1e-6
    for i in range(3):
        if abs(ray_dir[i]) < KINDA_SMALL_NUMBER:
            ray_dir[i] = KINDA_SMALL_NUMBER if ray_dir[i] >= 0 else -KINDA_SMALL_NUMBER

    # 2. Handle negative directions via reflection
    ray_state_a = 0
    for i in range(3):
        if ray_dir[i] < 0:
            ray_origin[i] = 2.0 * volume_center[i] - ray_origin[i]
            ray_dir[i] = -ray_dir[i]
            ray_state_a |= (1 << i)

    # 3. Compute inverse direction
    div = [1.0 / ray_dir[i] for i in range(3)]

    # 4. Compute ray bounds intersection with NavigationBounds
    t_min = [(nav_bounds_min[i] - ray_origin[i]) * div[i] for i in range(3)]
    t_max = [(nav_bounds_max[i] - ray_origin[i]) * div[i] for i in range(3)]
    for i in range(3):
        if t_min[i] > t_max[i]:
            t_min[i], t_max[i] = t_max[i], t_min[i]

    t_enter = max(t_min)
    t_exit = min(t_max)
    if t_enter > t_exit:
        return False, None, 0

    # 5. Initialize traversal
    occluded_count = 0
    stack = [octree.root]
    current_layer = octree.layer_count - 1
    current_node = octree.root

    while True:
        # Determine octant of ray origin within current node
        node_size = octree.get_size_from_depth(current_layer)
        node_lower = octree.get_lower_corner(current_node)
        node_center = [node_lower[i] + node_size / 2.0 for i in range(3)]
        octant = 0
        for i in range(3):
            if ray_origin[i] >= node_center[i]:
                octant |= (1 << i)

        # Check if leaf
        if current_node.is_leaf:
            hit_point = [ray_origin[i] + t_enter * ray_dir[i] for i in range(3)]
            # Inverse transform hit point if needed
            for i in range(3):
                if ray_state_a & (1 << i):
                    hit_point[i] = 2.0 * volume_center[i] - hit_point[i]
            return True, hit_point, occluded_count

        # Compute intersection with current node's internal faces
        face_t = float('inf')
        hit_face = -1
        for i in range(3):
            t_face = (node_center[i] - ray_origin[i]) / ray_dir[i]
            if 0.0 < t_face < face_t:
                face_t = t_face
                hit_face = i

        # Update ray origin to intersection position
        ray_origin = [ray_origin[i] + face_t * ray_dir[i] for i in range(3)]

        # Check if adjacent space is sibling
        next_octant = octant ^ (1 << hit_face)
        if octree.is_sibling(current_node, octant, next_octant):
            octant = next_octant
            stack.append(current_node)
            continue
        else:
            # Search up parent for sibling
            while current_node.parent is not None:
                current_node = current_node.parent
                current_layer -= 1
                found_sibling = False
                for child_idx in range(8):
                    if current_node.children[child_idx] is not None:
                        current_node = current_node.children[child_idx]
                        octant = child_idx
                        found_sibling = True
                        break
                if found_sibling:
                    stack.pop()
                    break
            else:
                # Reached root without finding sibling
                return False, None, occluded_count

        occluded_count += 1
```

### Edge Cases and Pitfalls
*   **Division by Zero**: Near-zero ray direction components cause division by zero or infinite traversal steps. This is handled by clamping components to `KINDA_SMALL_NUMBER` [S2, unofficial].
*   **Negative Directions**: Standard positive-axis traversal algorithms fail if the ray direction has negative components. This is handled by reflecting the origin across the volume center and negating the direction, storing flags for inverse transformation of the final hit point [S1, unofficial][S2, unofficial].

## Subtopics

### [Sparse Voxel Octree Raycasting with Image Warping](21725-sparse-voxel-octree-raycasting-with-image-warping.md)
Accelerates standard SVO raycasting by exploiting temporal coherence between consecutive frames. Instead of raycasting every pixel, it reprojections pixel coordinates from the previous frame to the current frame using the differential view matrix, raycasting only the "holes" (pixels that moved or were occluded) and empty regions. It sets itself apart from standard SVO raycasting [Sparse Voxel Octree Raycasting](21492-sparse-voxel-octree-raycasting.md) by reducing the number of raycasts per frame significantly, trading off visual smoothness during fast motion for performance.

## Background
The method is implemented in the **Nav3D** plugin for Unreal Engine 5, which provides true volumetric pathfinding and tactical reasoning using Sparse Voxel Octrees [S2, unofficial]. The system is based on Daniel Brewer's "3D Flight Navigation Using Sparse Voxel Octrees" from *Game AI Pro 3* [S2, unofficial]. It is used for AI agents navigating in 3D space, including flying units, swimming creatures, and zero-gravity environments [S2, unofficial].
