# Sparse Voxel Octree Raycasting

Also called: Hierarchical SVO Ray Traversal, Nav3D Raycaster

## Overview
Sparse Voxel Octree (SVO) Raycasting is a hierarchical traversal algorithm designed to efficiently intersect rays with sparse voxel data structures, primarily for 3D navigation and visibility analysis. Unlike uniform grid raycasting, it skips empty space by traversing only occupied nodes from the highest layer down to the leaves. It distinguishes itself by handling arbitrary ray directions through a coordinate reflection technique, ensuring the traversal logic remains consistent regardless of the ray's orientation relative to the world axes.

## How it works
The method transforms the ray into a canonical positive-direction space, traverses the octree hierarchy, and inverse-transforms the result. This avoids complex branching logic for negative direction components during the core traversal loop.

### Inputs and Outputs
*   **Inputs**:
    *   `RayOrigin`: 3D vector $(O_x, O_y, O_z)$ representing the ray start point.
    *   `RayDirection`: 3D vector $(D_x, D_y, D_z)$ representing the ray direction.
    *   `VolumeCenter`: 3D vector $(C_x, C_y, C_z)$ defining the center of the navigation volume.
    *   `NavigationBounds`: Axis-aligned bounding box (AABB) defined by `Min` and `Max` vectors.
    *   `Octree`: The Sparse Voxel Octree structure, accessed via `HighestLayer` and node indices.
*   **Outputs**:
    *   `Hit`: Boolean indicating if a valid intersection was found.
    *   `ImpactPoint`: 3D vector of the intersection point (if `Hit` is true).
    *   `OccludedVoxelCount`: Integer count of empty voxels traversed (optional metric).

### Data Structures
The implementation relies on specific structures to manage traversal state and ray bounds.

**FNav3DNodeAddress**
Used to identify nodes within the octree hierarchy.
*   `LayerIndex`: `int32` – The depth level in the octree.
*   `NodeIndex`: `int32` – The index of the node within the layer.
*   `SubNodeIndex`: `int32` – The child index (0-7) within the node.

**FOctreeRay**
Represents the ray's intersection interval with the axis-aligned bounding box of the current traversal scope. It stores 6 floats:
*   `tMinX`, `tMaxX`: Entry and exit distances along the X-axis.
*   `tMinY`, `tMaxY`: Entry and exit distances along the Y-axis.
*   `tMinZ`, `tMaxZ`: Entry and exit distances along the Z-axis.

**RayState.A**
A bitmask register storing the transformation state.
*   Bit 1 (value 1): X-axis reflection flag.
*   Bit 2 (value 2): Y-axis reflection flag.
*   Bit 4 (value 4): Z-axis reflection flag.

### Parameters
*   `KINDA_SMALL_NUMBER`: An epsilon threshold (e.g., $10^{-6}$ or similar small float) used to clamp near-zero ray direction components. This prevents division by zero and infinite traversal steps [S1, unofficial].

### Algorithm Steps

1.  **Ray Direction Normalization and Clamping**:
    Compute the raw direction vector:
    $$ \vec{D} = \vec{O}_{target} - \vec{O}_{start} $$
    Clamp any component $D_i$ where $|D_i| < \text{KINDA\_SMALL\_NUMBER}$ to $\text{KINDA\_SMALL\_NUMBER}$ (preserving sign) or a small non-zero value to ensure valid inverse calculations [S1, unofficial].

2.  **Coordinate Reflection for Negative Directions**:
    Initialize `RayState.A` to 0. For each axis $i \in \{X, Y, Z\}$:
    *   If $D_i < 0$:
        *   Reflect the origin component: $O_i = 2 \cdot C_i - O_i$.
        *   Negate the direction component: $D_i = -D_i$.
        *   Set the corresponding bit in `RayState.A` (Bit 1 for X, Bit 2 for Y, Bit 4 for Z) [S1, unofficial].

3.  **Inverse Direction Calculation**:
    Compute the inverse direction components:
    $$ \text{Div}_i = \frac{1.0}{D_i} \quad \text{for } i \in \{X, Y, Z\} $$
    [S1, unofficial]

4.  **Ray-Bounds Intersection**:
    Compute the intersection interval $[t_{min}, t_{max}]$ of the ray with the `NavigationBounds` AABB.
    For each axis $i$:
    $$ t_{min,i} = \frac{\text{Bounds.Min}_i - O_i}{\text{Div}_i^{-1}} = (\text{Bounds.Min}_i - O_i) \cdot \text{Div}_i $$
    $$ t_{max,i} = (\text{Bounds.Max}_i - O_i) \cdot \text{Div}_i $$
    Construct `FOctreeRay` with these values.
    *   If the ray does not intersect the bounds (i.e., $t_{min} > t_{max}$ for any axis, or the intervals do not overlap), terminate and return no hit [S1, unofficial].

5.  **Hierarchical Traversal**:
    Initialize `OccludedVoxelCount = 0`.
    Start traversal at `HighestLayer = LayerCount - 1` with `NodeIndex = 0` (root).
    *   *Note: The specific node selection logic (e.g., checking child occupancy) is not detailed in the provided source text, but the traversal proceeds from the highest layer down to leaf nodes to detect occluded voxels and compute hit points [S1, unofficial].*

6.  **Inverse Transformation of Result**:
    If a hit is found at `ImpactPoint`:
    *   If `RayState.A` has Bit 1 set: $ImpactPoint.X = 2 \cdot C_x - ImpactPoint.X$.
    *   If `RayState.A` has Bit 2 set: $ImpactPoint.Y = 2 \cdot C_y - ImpactPoint.Y$.
    *   If `RayState.A` has Bit 4 set: $ImpactPoint.Z = 2 \cdot C_z - ImpactPoint.Z$.
    [S1, unofficial]

def SVO_Raycast(RayOrigin, RayTarget, VolumeCenter, NavigationBounds, Octree):
    # 1. Compute Direction
    RayDirection = RayTarget - RayOrigin
    
    # 2. Clamp near-zero components to prevent division by zero
    KINDA_SMALL_NUMBER = 1e-6 # Example value
    for axis in ['X', 'Y', 'Z']:
        if abs(RayDirection[axis]) < KINDA_SMALL_NUMBER:
            RayDirection[axis] = KINDA_SMALL_NUMBER if RayDirection[axis] >= 0 else -KINDA_SMALL_NUMBER

    # 3. Handle negative directions via reflection
    RayState_A = 0
    for i, axis in enumerate(['X', 'Y', 'Z']):
        if RayDirection[axis] < 0:
            # Reflect origin across volume center
            RayOrigin[axis] = 2.0 * VolumeCenter[axis] - RayOrigin[axis]
            # Negate direction
            RayDirection[axis] = -RayDirection[axis]
            # Set flag bit (1 for X, 2 for Y, 4 for Z)
            RayState_A |= (1 << i)

    # 4. Compute inverse direction
    DivX = 1.0 / RayDirection.X
    DivY = 1.0 / RayDirection.Y
    DivZ = 1.0 / RayDirection.Z

    # 5. Compute ray bounds intersection
    # Calculate t_min and t_max for each axis against NavigationBounds
    t_min_x = (NavigationBounds.Min.X - RayOrigin.X) * DivX
    t_max_x = (NavigationBounds.Max.X - RayOrigin.X) * DivX
    t_min_y = (NavigationBounds.Min.Y - RayOrigin.Y) * DivY
    t_max_y = (NavigationBounds.Max.Y - RayOrigin.Y) * DivY
    t_min_z = (NavigationBounds.Min.Z - RayOrigin.Z) * DivZ
    t_max_z = (NavigationBounds.Max.Z - RayOrigin.Z) * DivZ

    # Ensure t_min < t_max for each axis
    if t_min_x > t_max_x: t_min_x, t_max_x = t_max_x, t_min_x
    if t_min_y > t_max_y: t_min_y, t_max_y = t_max_y, t_min_y
    if t_min_z > t_max_z: t_min_z, t_max_z = t_max_z, t_min_z

    # Check for intersection with the AABB
    # The ray intersects if max(t_min) <= min(t_max)
    t_enter = max(t_min_x, t_min_y, t_min_z)
    t_exit = min(t_max_x, t_max_y, t_max_z)

    if t_enter > t_exit:
        return Hit=False, ImpactPoint=None, OccludedVoxelCount=0

    # 6. Initialize Traversal
    OccludedVoxelCount = 0

### Edge Cases and Pitfalls
*   **Division by Zero**: Near-zero ray direction components cause division by zero or infinite traversal steps. This is handled by clamping components to `KINDA_SMALL_NUMBER` [S1, unofficial].
*   **Negative Directions**: Standard positive-axis traversal algorithms fail if the ray direction has negative components. This is handled by reflecting the origin across the volume center and negating the direction, storing flags for inverse transformation of the final hit point [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Not given in the sources. Typically $O(\log N)$ for sparse structures where $N$ is the number of voxels, depending on the depth of the octree and the number of occupied nodes intersected.
*   **Memory Complexity**: Not given in the sources. Depends on the SVO structure itself.
*   **Strengths**: Efficiently handles arbitrary ray directions without complex branching logic during traversal. Optimized for 3D navigation and visibility analysis in large volumes.
*   **Limitations**: The specific traversal performance metrics (e.g., rays per second) are not provided in the sources.
*   **When to use**: When performing raycasting against a Sparse Voxel Octree for navigation or visibility in 3D space, particularly when ray directions are arbitrary.

## Background
The method is implemented in the **Nav3D** plugin for Unreal Engine 5, which provides true volumetric pathfinding and tactical reasoning using Sparse Voxel Octrees. The system is based on Daniel Brewer's "3D Flight Navigation Using Sparse Voxel Octrees" from *Game AI Pro 3*. It is used for AI agents navigating in 3D space, including flying units, swimming creatures, and zero-gravity environments.
