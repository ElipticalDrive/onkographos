# Sparse Voxel Octree for Real-Time GI

Also called: Sparse Voxel Octree (ID Software)

## Overview
A real-time global illumination technique that approximates indirect lighting by computing a sparse voxel octree (SVO) around the player and traversing it with secondary rays after visibility buffer generation [S1, unofficial]. It distinguishes itself from [Sparse Voxel Octree for Indirect Illumination](8483-sparse-voxel-octree-for-indirect-illumination.md) by using a dynamic, player-centric voxel representation with single-bit occupancy storage optimized for runtime updates, whereas the parent method emphasizes pre-filtered hierarchical representations for visibility estimation.

## How it works
**Inputs:** Current camera position, object transforms, and visibility buffer data [G].
**Outputs:** Indirect illumination contribution per pixel [G].

**Data Structures:**
1.  **Cluster:** A block of $8^3$ voxels [S1, unofficial].
    *   **Occupancy Cluster:** A bitfield where each voxel is represented by 1 bit. `1` indicates solid geometry, `0` indicates air [S1, unofficial].
    *   **Material Cluster:** An array of 8-bit indices per voxel pointing to a Material Look-Up Table (LUT) of up to 256 entries [S1, unofficial]. The LUT is defined per object and stores properties like albedo and roughness [S1, unofficial].
    *   **Cluster Index:** 31 bits, allowing representation of $>10^{12}$ voxels [S1, unofficial].
2.  **Object:** Contains a transform (rotation/translation), the index of its first cluster, and the number of clusters in each axis direction [S1, unofficial]. Object extents are always a multiple of 8 voxels in each dimension [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Compute the SVO around the player at start-up [S1, unofficial].
2.  **Approximation:** Represent cluster content in a grid-like manner to handle freely rotating and translating objects [S1, unofficial].
3.  **Visibility Buffer Generation:** Render the scene to generate the primary visibility buffer [S1, unofficial].
4.  **Ray Traversal:** Shoot secondary rays from visible surface points and traverse the SVO to approximate GI [S1, unofficial].
5.  **Update:** Update the SVO at runtime when objects move to ensure the GI solution reflects the current world state [S1, unofficial].

**Parameters:**
*   **Voxel Representation:** Single bit for occupancy [S1, unofficial].
*   **Cluster Size:** $8^3$ voxels [S1, unofficial].

**Edge Cases:**
*   **Precision:** Floating-point errors in ray-box intersection may cause missed hits or false positives in sparse structures [G].
*   **Boundaries:** Objects must be properly bounded to ensure the SVO covers the relevant view frustum [G].
*   **Degenerate Input:** Empty scenes or objects with no geometry should result in empty SVOs to avoid traversal overhead [G].

## Subtopics

### Efficient Sparse Voxel Octrees
A real-time global illumination solution using voxel-based representations developed by NVIDIA [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Dominated by the SVO structure. Single-bit occupancy reduces memory footprint significantly compared to full voxel grids [S1, unofficial]. Material LUTs add overhead proportional to unique materials [G].
*   **Performance:** Not given in the sources.
*   **Strengths:** Efficient handling of dynamic scenes, low memory usage for occupancy, compatibility with visibility buffer pipelines [S1, unofficial].
*   **Limitations:** Approximate nature of GI, dependency on accurate visibility buffer generation [S1, unofficial].
*   **When to Use:** Real-time applications requiring dynamic global illumination with moving objects [S1, unofficial].
*   **When Not to Use:** Offline rendering requiring high-fidelity indirect lighting, or scenes with extremely static geometry where precomputed solutions are more efficient [G].

## Background
Developed by ID Software as a real-time global illumination solution using voxel-based representations [S1, unofficial]. It is listed alongside Epic Games and NVIDIA implementations as examples of real-time global illumination using voxel-based representations [S2]. The method leverages sparse voxel structures to approximate indirect lighting, addressing the computational intensity of full ray tracing on voxel sets [S2].
