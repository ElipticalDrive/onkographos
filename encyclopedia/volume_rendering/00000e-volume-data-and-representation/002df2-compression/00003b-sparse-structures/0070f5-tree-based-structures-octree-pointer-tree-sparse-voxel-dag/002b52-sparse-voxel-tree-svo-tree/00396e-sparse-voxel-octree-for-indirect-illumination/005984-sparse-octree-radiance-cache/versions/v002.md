# Sparse Octree Radiance Cache

Also called: Octree GI cache

## Overview
The Sparse Octree Radiance Cache is a CPU-built hierarchical data structure that replaces dense mip-mapped volume grids for storing aggregated radiance, albedo, alpha, and emission data [S1, unofficial]. It solves the resolution loss inherent in uniform grids, where thin features (e.g., 3-voxel thick objects) are averaged into indistinct smears [S1, unofficial].

## How it works
**Inputs:**
- Scene dimensions (e.g., $640 \times 640 \times 640$) [S1, unofficial].
- Voxel data (radiance, albedo, alpha, emission) [S1, unofficial].
- Leaf block size parameter $L$ (not hard-coded) [S1, unofficial].

**Outputs:**
- A sparse octree where leaves store aggregated block data and interior nodes are DAG-deduplicated [S1, unofficial].

**Data Structures:**
- **Leaf Node:** Stores aggregated radiance, albedo, alpha, and emission for a block of $L^3$ voxels [S1, unofficial].
- **Interior Node:** Contains pointers to up to 8 child octants. Identical regions share nodes via DAG deduplication [S1, unofficial].
- **DAG Structure:** Interior nodes with identical content share the same memory reference [S1, unofficial].

**Steps:**
1. **Enclose Scene:** Pad non-power-of-two scene dimensions to the next power-of-two cube (e.g., 640 $\rightarrow$ 1024). The padded region produces no nodes [S1, unofficial].
2. **Build Tree:** Recursively subdivide the scene. At each level, aggregate voxel data into blocks of size $L$ [S1, unofficial].
3. **Deduplicate:** Apply DAG deduplication to interior nodes. Identical regions (e.g., repeated bookshelf shelves) share nodes [S1, unofficial].
4. **Cone Level Selection:** During traversal, determine the node level based on the cone's cross-section radius, which grows with distance. A far sample stops at a coarse node; a tight cone reaches the leaf. No mip chain or LOD parameter is used [S1, unofficial].

**Formulas:**
- **Leaf Grid Size:** For a scene enclosed in $P$ (power-of-two) and leaf block size $L$, the leaf grid resolution is $P/L$ [S1, unofficial].
- **Interior Levels:** The number of interior levels is $\log_2(P/L)$ [S1, unofficial].

**Parameters:**
- **Leaf Size ($L$):** A parameter, not hard-coded. Must be small enough to preserve thin features (e.g., a 3-voxel leg is not averaged away) [S1, unofficial].

**Pitfalls:**
- **Empty Octants:** Must produce no nodes to maintain sparsity. A chain of 7 single-child levels dedupes to ONE 2-word node [S1, unofficial].
- **Non-Power-of-Two:** Incorrect handling of scene dimensions leads to incorrect node counts or padding artifacts [S1, unofficial].

    # Step 1: Enclose scene in power-of-two cube
    enclosing_size = 1 << (scene_width - 1).bit_length() if scene_width > 0 else 1
    leaf_grid_res = enclosing_size // leaf_block_size
    interior_levels = leaf_grid_res.bit_length() - 1  # e.g., 1024/8=128 -> 7 levels [S1, unofficial]
    seen_nodes = {}
    root = _build_node(voxel_data, 0, enclosing_size, leaf_block_size, interior_levels, seen_nodes)
    return root

def _build_node(data, level, current_size, leaf_block_size, interior_levels, seen_nodes):
    # Step 2: Base case for leaf node
    if level == interior_levels:
        aggregated = _aggregate_block(data, leaf_block_size)
        return _LeafNode(aggregated)
    # Recursive case: interior node
    children = []
    half = current_size // 2
    for octant_idx in range(8):
        octant_data = _get_octant(data, octant_idx, current_size)
        if not _is_empty(octant_data):
            child = _build_node(octant_data, level + 1, half, leaf_block_size, interior_levels, seen_nodes)
            children.append(child)
    # Step 3: DAG deduplication
    node_key = tuple(id(c) for c in children)
    if node_key in seen_nodes:
        return seen_nodes[node_key]
    new_node = _InteriorNode(children)
    seen_nodes[node_key] = new_node
    return new_node

## Subtopics

### [Sparse Voxel Octree for Indirect Illumination](8483-sparse-voxel-octree-for-indirect-illumination.md)
A pre-filtered hierarchical voxel representation of scene geometry stored as a dynamic sparse voxel octree on the GPU, used to efficiently estimate visibility and integrate incoming indirect energy without involving the actual mesh.

## Operating characteristics
- **Memory Complexity:** Significantly reduced compared to dense grids due to sparsity and DAG deduplication. Node count is far below voxel count [S1, unofficial].
- **Strengths:** Preserves thin features; handles non-power-of-two scenes; efficient memory usage via DAG deduplication [S1, unofficial].
- **Limitations:** CPU-only build (in this implementation); no GPU-side cone rule integration yet [S1, unofficial].
- **When to Use:** When thin features must be preserved and memory efficiency is critical [S1, unofficial].
- **When Not to Use:** When GPU-side geometry visibility is the primary concern (use [Sparse Voxel Octree for Indirect Illumination](8483-sparse-voxel-octree-for-indirect-illumination.md) instead) [G].

## Background
The Sparse Octree Radiance Cache was proposed by ZhouXiaolin in October 2026 as an enhancement to replace dense uniform grids in GI caching [S1, unofficial]. It addresses the resolution problem where thin features are averaged away in dense grids. The implementation was completed in commit `27e45be` and verified with CPU-side tests [S1, unofficial].
