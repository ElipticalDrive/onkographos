# Sparse Voxel Octree for Indirect Illumination
Also called: Hierarchical Voxel Representation, SVOctree

## Overview
This method uses a pre-filtered dynamic sparse voxel octree (SVO) on the GPU to efficiently estimate visibility and integrate incoming indirect energy without involving the actual mesh geometry [S1]. It solves the problem of real-time indirect illumination in complex scenes by replacing dense mip-mapped volume grids, which suffer from resolution loss and temporal discontinuities, with a sparse, adaptive hierarchy [S1]. Unlike [KD10], which uses nested regular voxel grids and lacks precision, this approach uses sparse storage and ray tracing to maintain high precision and support specular indirect lighting [S1]. Unlike path-tracing or photon mapping, it always gives smooth results and does not suffer from noise or temporal discontinuities [S1].

## How it works
**Inputs:** Triangle meshes representing the scene geometry; light source positions, intensities, and cone angles; viewing and lighting configuration parameters [G].
**Outputs:** Indirect illumination contribution per pixel or surface point [G].

**Data Structures:**
The core data structure is a dynamic sparse voxel octree stored on the GPU [S1].
*   **Root Node:** Represents the entire scene bounding box [S1].
*   **Internal Nodes:** Each node represents an eighth of the parent's volume (a child octant) [S1].
*   **Leaf Nodes:** Store filtered scene information, specifically energy intensity, direction, occlusion, and local normal distribution functions (NDFs) [S1].
*   **Hierarchy:** The structure allows querying filtered scene information with increasing precision by descending the tree hierarchy [S1].

**Algorithm Steps:**
1.  **Voxelization and Octree Building:** Convert triangle meshes into a voxel representation and build the sparse voxel octree dynamically on the GPU, exploiting the rasterization pipeline for efficiency [S1]. This step handles fully dynamic scenes [S1].
2.  **Pre-filtering:** Apply a filtering algorithm to the octree to aggregate energy and occupancy information, allowing abstraction of details farther away while maintaining precision near the observer [S1]. Exact mathematical formulas for the filtering kernel are not provided in the sources [S1].
3.  **Light Integration (Cone Tracing):** Use an approximate voxel cone tracing technique to integrate incoming indirect energy splatted into the structure from light sources [S1]. This involves tracing cones through the octree to estimate visibility and accumulate energy [S1].
4.  **Radiance Reconstruction:** The stored data (energy intensity and direction) is convolved with a set of pre-defined BRDFs to reconstruct the radiance response [S1].

**Parameters:**
*   **Scene Resolution:** Chosen suitable to the viewing and lighting configuration to avoid light undersampling or geometric LOD issues [S1]. The exact resolution values are not specified in the sources [S1].

**Edge Cases and Pitfalls:**
*   **Light Undersampling:** If the scene resolution is too low relative to the lighting configuration, light undersampling may occur [S1].
*   **Geometric LOD Issues:** Insufficient resolution may lead to loss of geometric detail [S1].
*   **Temporal Discontinuities:** Unlike [KD10], this method avoids temporal discontinuities due to its sparse storage and precision [S1].

**Pseudocode:**
```python
def build_and_filter_svo(meshes, scene_bbox, resolution):
    # Voxelize meshes into occupancy grid
    grid = voxelize_meshes(meshes, scene_bbox, resolution)
    # Build octree and pre-filter
    root = build_octree_recursive(grid)
    filter_octree(root)
    return root

def voxelize_meshes(meshes, bbox, res):
    # Rasterize triangles into a 3D occupancy grid
    grid = empty_3d_grid(res)
    for tri in meshes:
        rasterize_triangle_to_grid(tri, grid)
    return grid

def build_octree_recursive(grid):
    # Recursive subdivision into 8 octants
    if grid.is_leaf():
        return LeafNode(grid.data)
    children = []
    for i in range(8):
        children.append(build_octree_recursive(grid.get_octant(i)))
    return InternalNode(children)

def filter_octree(node):
    if node.is_leaf():
        node.energy = compute_energy(node.data)
        node.direction = compute_direction(node.data)
        node.occlusion = compute_occlusion(node.data)
        node.ndf = compute_ndf(node.data)
    else:
        for child in node.children:
            filter_octree(child)
        # Aggregate children's data into parent
        node.energy = aggregate_energy(node.children)
        node.direction = aggregate_direction(node.children)
        node.occlusion = aggregate_occlusion(node.children)
        node.ndf = aggregate_ndf(node.children)

def trace_cone(svo, origin, direction, cone_angle, max_depth):
    accumulated_energy = 0.0
    current_node = svo
    depth = 0
    while current_node and depth < max_depth:
        # Intersect cone with current node's bounding box
        if not cone_intersects_bbox(origin, direction, cone_angle, current_node.bbox):
            break
        if current_node.is_leaf():
            accumulated_energy += current_node.energy
            break
        # Descend to child containing the cone axis
        child_idx = get_child_octant(origin, direction, current_node.bbox)
        current_node = current_node.children[child_idx]
        depth += 1
    return accumulated_energy

def compute_indirect_illumination(svo, surface_points, light_sources, brdf_func):
    for point in surface_points:
        indirect = 0.0
        for light in light_sources:
            energy = trace_cone(svo, point.position, light.direction, light.cone_angle, svo.max_depth)
            radiance = brdf_func(point.normal, light.color, energy)
            indirect += radiance
        point.indirect_color = indirect
```

## Subtopics

### [Sparse Octree Radiance Cache](16429-sparse-octree-radiance-cache.md)
The Sparse Octree Radiance Cache is a CPU-built hierarchical data structure that replaces dense mip-mapped volume grids for storing aggregated radiance, albedo, alpha, and emission data. It solves the resolution loss inherent in uniform grids, where thin features (e.g., 3-voxel thick objects) are averaged into indistinct smears. Unlike its sibling [Sparse Voxel Octree for Indirect Illumination](8483-sparse-voxel-octree-for-indirect-illumination.md), which focuses on GPU-side geometry visibility, this method provides a sparse, DAG-deduplicated representation optimized for cone-integration semantics on the CPU.

### [Sparse Voxel Octree for Real-Time GI](18076-sparse-voxel-octree-for-real-time-gi.md)
A real-time global illumination technique developed by ID Software that approximates indirect lighting by traversing a sparse voxel octree (SVO) with secondary rays after visibility buffer generation. It distinguishes itself from [Sparse Voxel Octree for Indirect Illumination](8483-sparse-voxel-octree-for-indirect-illumination.md) by focusing on a dynamic, player-centric voxel representation optimized for runtime updates and single-bit occupancy storage, whereas the parent method emphasizes pre-filtered hierarchical representations for visibility estimation.

## Operating characteristics
*   **Time Complexity:** The method achieves real-time frame rates even for highly detailed environments [S1]. The cost is described as "almost geometry-independent" [S1].
*   **Memory Complexity:** Uses sparse storage, which is more memory-efficient than nested regular voxel grids [S1]. The resolution is limited by memory occupancy in similar approaches like [KD10], implying this method mitigates that constraint through sparsity [S1].
*   **Measured Performance:** Reaches real-time frame rates for highly detailed environments [S1].
*   **Strengths:** Always gives smooth results; no noise or temporal discontinuities; supports specular indirect lighting; handles fully dynamic scenes; high precision near the observer; abstracts energy farther away [S1].
*   **Limitations:** Requires pre-filtering and cone tracing, which may have specific resolution constraints to avoid undersampling [S1].
*   **When to Use:** Real-time indirect illumination in complex, dynamic scenes where smooth results and specular lighting are required [S1].
*   **When Not to Use:** When absolute physical accuracy via path-tracing is needed, or when the hardware lacks the GPU rasterization pipeline required for the dynamic voxelization and octree building step [S1].

## Background
The method was published in the paper "Interactive Indirect Illumination Using Voxel Cone Tracing" [S1]. It derives from the need to produce real-time indirect illumination, building upon the concept of hierarchical voxel representations [S1]. It contrasts with earlier approaches like [KD10] which used diffusion processes in regular voxel grids [S1]. The approach relies on dynamic sparse voxel octrees [CNLE09, LK10] and approximate voxel cone tracing [S1].
