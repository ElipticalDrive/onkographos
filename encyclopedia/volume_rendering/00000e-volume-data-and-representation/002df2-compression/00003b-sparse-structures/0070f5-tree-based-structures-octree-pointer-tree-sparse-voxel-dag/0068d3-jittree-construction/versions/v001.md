# JiTTree Construction

Also called: Just-In-Time Tree, JIT Tree

## Overview
JiTTree Construction is a method for generating GPU-executable code from a hierarchical volume representation, specifically targeting sparse voxel structures like kd-trees or octrees [S1, unofficial]. It solves the problem of efficient, branch-heavy tree traversal on GPUs by unrolling the traversal logic into a single, large kernel function at runtime [S1, unofficial]. Unlike static tree representations that require dynamic pointer chasing or complex traversal loops, JiTTree compiles the spatial logic directly into the shader, allowing the GPU compiler to optimize control flow and data access patterns [S1, unofficial]. It is distinct from [Implicit Octree Storage](939-implicit-octree-storage.md) because it generates explicit procedural code rather than relying on mathematical coordinate mapping, and from [OpenVDB (VDB)](1508-openvdb-vdb.md) which typically uses static kernel structures for its linked-list or brick-based access [S1, unofficial].

## How it works
The method consists of two phases: CPU-side tree construction and GPU-side code generation.

**Inputs:**
1. A volumetric dataset.
2. A chosen "brick type" representation (a discrete set of data types used to represent local volume content) [S1, unofficial].

**Outputs:**
1. A compiled OpenCL kernel (or equivalent GPU shader) containing the unrolled traversal logic [S1, unofficial].
2. The kernel contains embedded constants (brick size, volume size) and data pointers [S1, unofficial].

**Data Structures:**
1. **Volumetric Array of Types:** An initial array representing the volume, where each element is assigned a type from the chosen brick type set [S1, unofficial].
2. **Entropy-Minimized Tree:** A hierarchical structure (e.g., kd-tree or octree) built by recursively splitting the volumetric array. Split planes are chosen to minimize the entropy of brick types in the resulting sub-volumes [S1, unofficial]. The recursion stops when a leaf node contains only a single brick type [S1, unofficial].

**Algorithm Steps:**

1. **Initialize Type Array:** Create an array representing the volume, assigning each voxel a type from the optimal brick type representation [S1, unofficial].
2. **Construct Tree (CPU):**
   - Recursively traverse the type array.
   - For each node, evaluate all possible split planes.
   - Select the split plane that results in the two sub-volumes having the lowest combined entropy of brick types [S1, unofficial].
   - Repeat until each leaf node contains voxels of a single brick type.
3. **Generate GPU Code:**
   - Start a GPU code generator [S1, unofficial].
   - Recursively traverse the constructed tree.
   - **For Internal Nodes:** Generate an `if/else` statement. The condition compares input coordinates against the split plane to determine the traversal direction [S1, unofficial].
   - **For Leaf Nodes:** Generate a local array holding pointers to the data for that specific brick type. This allows direct volume bricking without further traversal [S1, unofficial].
4. **Optimize Code:**
   - Apply single-branch optimizations (see Subtopics).
   - Compile constants (brick size, volume dimensions) into the generated code to enable partial evaluation by the GPU compiler [S1, unofficial].

**Pseudocode:**

```python
def jit_tree_construct(volume_data, brick_types):
    # Step 1: Initialize volumetric array of types
    type_array = assign_types(volume_data, brick_types)
    
    # Step 2: Construct tree on CPU
    # Entropy minimization is handled by the tree builder
    tree = build_entropy_minimized_tree(type_array)
    
    # Step 3: Generate GPU code
    kernel_code = generate_kernel(tree)
    
    # Step 4: Compile and return
    return compile_opencl(kernel_code)

def generate_kernel(node):
    """
    Recursively generates OpenCL code for a tree node.
    """
    if node.is_leaf():
        # Leaf node: generate local array with pointers for single-type bricking
        # The code will perform a direct lookup into the elemental data structure
        code = f"""
        // Leaf node for type {node.brick_type}
        local_data_ptr = get_pointer_to_brick_data({node.brick_type});
        return lookup_volume_bricks(local_data_ptr, input_coords);
        """
        return code
    else:
        # Internal node: generate if/else for split plane
        split_plane = node.split_plane
        direction = node.traversal_direction
        
        # Generate condition based on split plane
        # Example: if (x < split_plane_x)
        condition = generate_split_condition(split_plane)
        
        # Recursively generate code for children
        true_code = generate_kernel(node.left_child)
        false_code = generate_kernel(node.right_child)
        
        # Combine into if/else statement
        code = f"""
        if ({condition}) {{
            {true_code}
        }} else {{
            {false_code}
        }}
        """
        return code

def generate_split_condition(split_plane):
    """
    Generates the coordinate comparison condition for a split plane.
    """
    # Simplified for 3D axis-aligned split
    # Returns string like "x < 64"
    return f"{split_plane.axis} < {split_plane.value}"
```

**Parameters:**
- **Brick Types:** The set of discrete data types used to represent volume content. The choice affects the tree structure and entropy [S1, unofficial].
- **Volume Size:** Embedded into the kernel for compiler optimization [S1, unofficial].
- **Brick Size:** Embedded into the kernel for compiler optimization [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Compilation Time:** OpenCL compilation time is a significant limiting factor. Code for large trees can reach thousands of lines, taking minutes to compile [S1, unofficial].
- **Hardware Variance:** Nvidia OpenCL compilers can handle unrolling up to several thousand leaf nodes, while Intel compilers show worse performance in compile time [S1, unofficial].
- **Single Brick Volumes:** If the volume is represented by a single brick, the JIT compilation removes all bricking code and performs a single lookup [S1, unofficial].

## Subtopics

### Single Branch Optimization
A code generation optimization that simplifies `if/else` statements in the tree traversal logic [S1, unofficial]. If an `else` branch is unnecessary, it is omitted. If the `if` branch is unnecessary, the condition is reversed, and the return value is moved to the end of the code block [S1, unofficial]. This simplification is primarily for code readability and debug purposes, as performance benefits were not observed, likely because the OpenCL compiler removes unnecessary branches automatically [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Construction time is dominated by the CPU-side tree building (entropy minimization) and the GPU-side code generation. The most significant time cost is the OpenCL compilation time, which can take minutes for large trees [S1, unofficial].
- **Memory Complexity:** The generated kernel code size scales with the number of nodes in the tree. Large trees result in thousands of lines of code [S1, unofficial].
- **Performance:** The approach allows for efficient traversal on the GPU by unrolling the tree, reducing branch divergence and pointer chasing overhead [S1, unofficial]. However, the compilation latency is a major drawback for dynamic scenes [S1, unofficial].
- **Strengths:** High traversal efficiency on GPU; compiler optimizations via embedded constants; simplified leaf access [S1, unofficial].
- **Limitations:** Long compilation times; poor scalability on some hardware (e.g., Intel OpenCL); static nature of the generated code makes it unsuitable for frequently changing data without recompilation [S1, unofficial].
- **When to Use:** Suitable for static or slowly changing volume data where the compilation overhead can be amortized over many frames [S1, unofficial].
- **When Not to Use:** Unsuitable for highly dynamic data requiring frequent tree updates, or on hardware with slow OpenCL compilation [S1, unofficial].

## Background
JiTTree Construction was proposed in the context of adaptive, hybrid data structures for volume datasets on the GPU [S1, unofficial]. It leverages the Just-In-Time (JIT) compilation capabilities of OpenCL to generate optimized traversal code from a CPU-constructed tree [S1, unofficial]. The method was developed to address the inefficiencies of traditional tree traversal on GPUs, where branch divergence and pointer indirection can degrade performance [S1, unofficial].
