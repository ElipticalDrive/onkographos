# Delayed Loading with Memory Mapping

Also called: Lazy Grid Loading, Mapped File I/O

## Overview
Delayed Loading with Memory Mapping loads OpenVDB (VDB) files on-demand by mapping the file into virtual memory rather than reading all grids into RAM immediately, thereby minimizing memory usage [S1, unofficial]. It sets itself apart from standard eager loading by deferring disk I/O until specific data structures are accessed, trading off potential page-fault latency for reduced peak memory footprint.

## How it works
**Inputs and Outputs:**
- Input: A path to a VDB file (or `std::istream`), a boolean flag `delayLoad` indicating if delayed loading is requested, and a threshold `copyMaxBytes` for temporary file creation.
- Output: An `std::istream` object configured to read from either a temporary copy or a memory-mapped buffer of the source file.

**Data Structures:**
- `MappedFile`: An internal helper class that manages the file descriptor and memory mapping lifecycle. It holds the filename and an `autoDelete` flag.
- `TempFile`: A helper class that creates a temporary file in the system's temp directory to store a copy of the source file.
- `std::ifstream`: Standard binary input stream used for non-mapped reading.
- `std::istream`: The final stream interface returned to the caller, backed by either `std::ifstream` or a buffer from `MappedFile`.

**Parameters:**
- `DEFAULT_COPY_MAX_BYTES`: 500,000,000 bytes (500 MB). This is the threshold below which files are copied to a temporary location to ensure thread safety during concurrent access. It is overridable via the environment variable `OPENVDB_DELAYED_LOAD_COPY_MAX_BYTES` [S1, unofficial].

**Steps:**
1. Check if delayed loading is enabled globally (`Archive::isDelayedLoadingEnabled()`) and if the caller requested it (`delayLoad`).
2. If delayed loading is disabled, open the file directly using `std::ifstream` in binary mode.
3. If delayed loading is enabled:
    a. Retrieve the file size.
    b. If the file size is less than `copyMaxBytes`:
        i. Create a `TempFile` instance.
        ii. Open the source file with `std::ifstream`.
        iii. Copy the contents of the source file to the `TempFile` using `boost::iostreams::copy`.
        iv. Set the filename to the temporary file's path and mark `isTempFile` as true.
        v. If the copy fails (exception), log a warning and fall back to reading directly from the original file (bypassing memory mapping for this file).
    c. If the file size is greater than or equal to `copyMaxBytes`, use the original filename and set `isTempFile` to false.
    d. Instantiate a `MappedFile` object with the chosen filename and the `isTempFile` flag.
    e. Call `MappedFile::createBuffer()` to generate a stream buffer backed by the memory mapping.
    f. Wrap this buffer in a new `std::istream`.
4. Return the configured `std::istream`.

**Pseudocode:**
```python
def delayed_load_file(filename: str, delay_load: bool, copy_max_bytes: int = 500000000) -> std_istream:
    """
    Loads a VDB file using delayed loading/memory mapping if enabled.
    
    Args:
        filename: Path to the VDB file.
        delay_load: Boolean flag requesting delayed loading.
        copy_max_bytes: Threshold for copying files to temp location.
        
    Returns:
        An std::istream configured for reading the file.
    """
    # Check global and local flags for delayed loading
    if not delay_load or not Archive.is_delayed_loading_enabled():
        # Fallback to standard eager loading
        stream = std_ifstream(filename, ios_base_in | ios_base_binary)
        return std_istream(stream)

    is_temp_file = False
    current_filename = filename

    # Determine if we need to copy the file for safety
    file_size = get_file_size(filename)
    if file_size < copy_max_bytes:
        try:
            temp_file = TempFile()
            source_stream = std_ifstream(filename, ios_base_in | ios_base_binary)
            # Copy contents to temporary file
            boost_iostreams_copy(source_stream, temp_file)
            current_filename = temp_file.filename()
            is_temp_file = True
        except Exception as e:
            # Log warning and fall back to direct reading if copy fails
            log_warning(f"Failed to copy file for delayed loading: {e}")
            stream = std_ifstream(filename, ios_base_in | ios_base_binary)
            return std_istream(stream)

    # Create memory-mapped file object
    mapped_file = MappedFile(current_filename, auto_delete=is_temp_file)
    
    # Create buffer from memory mapping
    stream_buffer = mapped_file.create_buffer()
    
    # Wrap buffer in stream
    stream = std_istream(stream_buffer)
    return stream
```

**Edge Cases and Pitfalls:**
- **Concurrent Modification:** If the source file is modified while being read via memory mapping, data corruption may occur. This is mitigated by copying small files (< 500 MB) to a temporary location, ensuring the mapped view remains stable [S1, unofficial].
- **Copy Failure:** If copying to a temporary file fails (e.g., due to permissions or disk space), the system logs a warning and falls back to standard file reading, potentially losing the benefits of delayed loading for that specific file [S1, unofficial].
- **Large Files:** Files larger than `copy_max_bytes` are memory-mapped directly. If these files are modified concurrently, the reader may see inconsistent data or crashes [S1, unofficial].

## Subtopics

### Standard Eager Loading
Reads the entire file into RAM immediately. Choose this when memory is abundant and access patterns are random across the whole file, avoiding page-fault overhead. [Standard Eager Loading](52-standard-eager-loading.md)

### Streaming I/O
Reads data sequentially from disk without mapping. Choose this for very large files where memory mapping is not supported or when sequential access is guaranteed. [Streaming I/O](52-streaming-io.md)

## Operating characteristics
- **Time Complexity:** Initialization is $O(1)$ for memory mapping setup, but actual data access incurs page fault latency. Total load time is proportional to the amount of data accessed, not the file size.
- **Memory Complexity:** $O(1)$ relative to file size for the mapping overhead, plus the memory required for the accessed tiles. Significantly lower than eager loading for sparse or large grids.
- **Measured Performance:** Effective for scenes where only a fraction of the volume is visible or processed at any time. Performance degrades if the working set exceeds physical RAM, causing thrashing.
- **Strengths:** Drastically reduces peak memory usage for large VDB files. Enables loading of files larger than available RAM (provided the working set fits).
- **Limitations:** Not suitable for concurrent modification of source files without copying. Page faults can cause latency spikes during initial access.
- **When to Use:** When memory is constrained, or when loading very large VDB files where only a subset of voxels is needed.
- **When Not to Use:** When the entire file must be accessed immediately, or when the source file is actively being written to and cannot be safely copied.

## Background
This technique is implemented within the OpenVDB library to address the high memory overhead associated with loading large sparse voxel grids. It leverages the operating system's virtual memory manager to map file contents directly into the process address space, deferring physical memory allocation until pages are accessed.
