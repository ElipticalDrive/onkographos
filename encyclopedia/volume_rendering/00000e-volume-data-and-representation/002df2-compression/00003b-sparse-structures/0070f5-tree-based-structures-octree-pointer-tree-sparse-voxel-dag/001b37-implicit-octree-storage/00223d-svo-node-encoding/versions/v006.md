# SVO Node Encoding

Also called: Octree Node Encoding, SVO Binary Format, SVO file format, SVO node structure, Sparse Voxel Octree (SVO) Binary Format, octree layout, raw_val format

## Overview
SVO Node Encoding is a compact binary serialization format for Sparse Voxel Octrees (SVO) that stores node type, child pointers, and voxel attributes in a single 32-bit integer [S1, unofficial]. It eliminates explicit null pointers and reduces memory overhead by packing hierarchical data into a contiguous little-endian array with a fixed header [S1, unofficial].

## How it works
**Inputs:** A Sparse Voxel Octree structure containing nodes with attributes (color/density) and child pointers [S1, unofficial].
**Outputs:** A binary file containing a header followed by the octree data array [S1, unofficial].

**Data Structures:**
The file is a contiguous array of little-endian `uint32_t` values [S1, unofficial]. The header contains six fields: `version` (expected `0x01`), `volume_size.x`, `volume_size.y`, `volume_size.z`, `octree_resolution`, and `octree_bytesize` [S1, unofficial]. The octree data follows immediately after the header [S1, unofficial]. The octree is stored as a sequence of levels, each allocated contiguously after the previous [S1, unofficial]. Each level consists of 8 `uint32_t` entries representing nodes at that depth [S1, unofficial]. The first 8 `uint32_t` correspond to the first octree level [S1, unofficial].

**Node Encoding (32-bit `uint32_t`):**
Each node is a `uint32_t` value [S1, unofficial]. Bit 31 (MSB) acts as a type flag [S1, unofficial]. Bits 0–30 store the payload [S1, unofficial]. A value of `0` indicates a null node (no children and no data) [S1, unofficial]. If MSB is `0`, the node is a leaf; the remaining 31 bits store the leaf's value packed as 7 bits alpha, 8 bits blue, 8 bits green, 8 bits red (ABGR) [S1, unofficial]. If MSB is `1`, the node is an internal node; the remaining 31 bits store the memory index (offset) of its first child node in the octree array [S1, unofficial].

**Formulas:**
*   Leaf extraction: `alpha = val & 0x7F`, `blue = (val >> 7) & 0xFF`, `green = (val >> 15) & 0xFF`, `red = (val >> 23) & 0xFF` [S1, unofficial].
*   Internal extraction: `child_index = val & 0x7FFFFFFF` [S1, unofficial].

**Steps to Encode:**
1. Initialize an empty list `nodes` and a queue for level-order traversal [G].
2. Traverse the SVO in level-order (BFS) to collect all nodes and record their indices [G].
3. For each node, determine its type and payload:
   - If empty/null, append `0` [S1, unofficial].
   - If leaf, pack color/attribute into 31 bits (ABGR) and append with MSB=0 [S1, unofficial].
   - If internal, record the index of its first child in the `nodes` list, then append with MSB=1 [S1, unofficial].
4. Construct the header with `version=0x01`, `volume_size`, `octree_resolution`, and `octree_bytesize = len(nodes) * 4` [S1, unofficial].
5. Write the header (6 `uint32_t`s) followed by the `nodes` array in little-endian format [S1, unofficial].

**Pseudocode:**
```python
class Node:
    def __init__(self, children=None, color=None):
        self.children = children
        self.color = color

def encode_svo(root_node, volume_size, octree_resolution):
    # Pass 1: Level-order traversal to collect nodes and determine indices
    level_order = []
    node_to_index = {}
    queue = [root_node]
    while queue:
        node = queue.pop(0)
        idx = len(level_order)
        level_order.append(node)
        node_to_index[id(node)] = idx
        if node.children is not None:
            queue.extend(node.children)

    # Pass 2: Encode nodes into 32-bit integers
    nodes = []
    for node in level_order:
        if node.children is None and node.color is None:
            nodes.append(0)
        elif node.children is None:
            r, g, b, a = node.color
            packed = (a & 0x7F) | ((b & 0xFF) << 7) | ((g & 0xFF) << 15) | ((r & 0xFF) << 23)
            nodes.append(packed)
        else:
            first_child = node.children[0]
            child_index = node_to_index[id(first_child)]
            packed = child_index | 0x80000000
            nodes.append(packed)

    # Build and serialize header
    header = [0x01, volume_size[0], volume_size[1], volume_size[2], octree_resolution, len(nodes) * 4]
    import struct
    data = struct.pack('<' + 'I' * len(header), *header)
    data += struct.pack('<' + 'I' * len(nodes), *nodes)
    return data
```

**Edge Cases and Pitfalls:**
*   A value of `0` indicates an empty node [S1, unofficial].
*   The format explicitly uses little-endian byte order [S1, unofficial].
*   The alpha channel uses 7 bits, leaving 1 bit unused in the 31-bit leaf payload [S1, unofficial].

## Subtopics

### [Block Writer for SVO Serialization](2741-block-writer-for-svo-serialization.md)
The Block Writer is a class that serializes Sparse Voxel Octree (SVO) nodes to a binary file while tracking cumulative byte and element counts. It is chosen when streaming large trees to disk without loading the entire structure into memory.

### [SVO Mask Mapping](5103-svo-mask-mapping.md)
SVO Mask Mapping is a bit-mapping scheme for encoding the existence of 8 child voxels within a Sparse Voxel Octree (SVO) node, stored in a single `uint32_t` mask field. It solves the problem of efficiently tracking which octants are occupied without storing explicit pointers for empty children, enabling compact tree traversal. It is chosen when pointer overhead must be minimized further than raw indices allow.

### [Texel-per-Node Octree Encoding](6861-texel-per-node-octree-encoding.md)
Texel-per-Node Octree Encoding is a storage optimization for Sparse Voxel Octrees that maps each octree node to exactly one texture texel to maximize tree depth within hardware texture size limits. It differs from general SVO Node Encoding by packing node type and child pointers directly into 2D texture channels rather than using raw integer arrays. It is chosen when GPU texture sampling is preferred over CPU array traversal.

### [Adaptive Octree Encoding](9453-adaptive-octree-encoding.md)
Adaptive Octree Encoding is a memory layout for storing Tree-Based Adaptive Mesh Refinement (TB-AMR) data as an adaptive-resolution octree to preserve hierarchy information, enabling faster ray traversal and higher quality rendering than flattening to unstructured or rectilinear grids. Unlike Sparse Voxel Octrees (SVO) which typically store uniform voxels, this structure supports storing voxels of different resolutions to handle AMR data. It builds on [SVO Node Encoding](2705-svo-node-encoding.md) by extending the concept of compact node descriptors to support variable refinement levels inherent to AMR simulations. It is chosen for scientific visualization of multi-resolution simulation data.

## Operating characteristics
*   **Time Complexity:** Encoding is $O(N)$ where $N$ is the number of nodes, requiring two passes (or complex queue management) to resolve child indices [G]. Decoding is $O(N)$ for traversal [G].
*   **Memory Complexity:** $32$ bits per node [S1, unofficial]. This is highly compact compared to pointer-based trees [G].
*   **Performance:** Fast random access to nodes via index [G]. Cache-friendly due to contiguous array storage [G].
*   **Strengths:** Small file size, simple structure, easy to serialize/deserialize [S1, unofficial].
*   **Limitations:** Sparse trees with many empty nodes still store `0` entries [S1, unofficial]. Not suitable for dynamic updates (requires rebuilding the array) [G].

## Background
The format is described in the `voxelizer` repository [S1, unofficial]. It is used for storing voxelized models for efficient rendering and processing [S1, unofficial].
