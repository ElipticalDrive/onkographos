# User-Defined ROI Refinement

Also called: Local Refinement, Octree-based Multiresolution Volume Rendering, Octree-based approach, ROI-based Octree Refinement

## Overview
User-Defined ROI Refinement is an interactive technique for multiresolution volume rendering of large scattered datasets, allowing users to specify Regions of Interest (ROI) in a coarse preview to generate higher-fidelity views of specific areas [S1, unofficial]. It distinguishes itself from static multiresolution methods by enabling dynamic, user-driven subdivision of octree leaf nodes covering the ROI, balancing global performance with local detail [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of scattered 3D points with associated scalar function values (no connectivity) [S1, unofficial].
*   **Output:** A rendered image where the ROI is displayed with higher resolution (finer octree depth) than the background [S1, unofficial].

**Data Structures:**
*   **Octree:** A hierarchical structure where each node represents a bounding box. Nodes are subdivided until a termination criterion is met.
*   **Node Attributes:** Each node stores the average alpha ($A$) and color ($C$) of all points contained within its bounding box [S1, unofficial].
*   **Global/Local Structure:** The method may use a single global octree for the entire dataset, or a global octree combined with one or more local octrees dedicated to specific ROIs [S1, unofficial].

**Algorithm Steps:**

1.  **Pre-processing (Global Octree Construction):**
    *   Compute the bounding box of all original scattered points [S1, unofficial].
    *   Subdivide the bounding box octree-fashion.
    *   **Termination Criteria:** Stop subdividing a node if:
        1.  The number of points in the node is below a threshold, OR
        2.  The error between the function values of points in the node and the node's average value is below an error threshold [S1, unofficial].

2.  **Coarse Approximation Generation:**
    *   Select a maximum depth $K$ for the initial preview.
    *   Process only nodes at depth $\le K$.
    *   Approximate all points inside a node by a single representative point at the node center, using the average alpha $A$ and color $C$ of the contained points [S1, unofficial].

3.  **Weight Function Optimization:**
    *   Pre-compute a threshold $l'$ for various opacity values.
    *   If the intersection length $l > l'$, set the weight function $F(l, A) = 1$ to avoid expensive power calculations, as the function saturates quickly [S1, unofficial].

4.  **Ray Traversal and Blending:**
    *   Traverse the octree recursively.
    *   **Intersection Length ($l$):** Calculate the approximate number of points along the ray inside a cell:
        $$ l = \frac{n d}{\text{edge}} $$
        Where:
        *   $n = \sqrt[3]{N_{pts}}$, with $N_{pts}$ being the number of points in the cell (assuming uniform distribution).
        *   $d$ is the Euclidean distance between the ray's entry and exit points in the cell.
        *   $\text{edge}$ is the length of the cell's bounding box edge [S1, unofficial].
    *   **Weight Function:**
        $$ F(l, A) = 1 - (1 - A)^l $$
        This function weights the contribution of the node's color based on the effective number of points intersected [S1, unofficial].
    *   **Blending Formula:**
        $$ B_i = F(l_{i+1}, A_{i+1})C_{i+1} + (1 - F(l_{i+1}, A_{i+1}))B_{i+1} $$
        Where $B_i$ is the accumulated color at node $i$, $A_{i+1}$ and $C_{i+1}$ are the average alpha and color of the next node $(i+1)$ along the ray [S1, unofficial].
    *   **Ray Termination:** Stop traversal when:
        $$ (1 - A_1)(1 - A_2)\dots(1 - A_i) < e $$
        Where $e$ is a small threshold value (e.g., 0.01) [S1, unofficial].

5.  **Local Refinement (ROI Specification):**
    *   After generating the coarse image, the user specifies an ROI (e.g., via a bounding box) [S1, unofficial].
    *   Identify all octree leaf nodes that intersect or cover the ROI coordinates [S1, unofficial].
    *   **Subdivision:** Subdivide these identified leaf nodes to a deeper level (higher resolution) to improve image quality in the ROI [S1, unofficial].
    *   If using **Local Octrees**, build a new, shallower but denser octree specifically for the ROI points, using the global octree as a search tree to locate the relevant bounding box [S1, unofficial].

6.  **Coarsening (Inverse Operation):**
    *   To reduce storage or accelerate rendering, users can merge leaf nodes back into larger nodes.
    *   This involves fusing children along specified dimensions, effectively reversing the refinement process [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Calculating $l$ involves floating-point division and cube roots. Use the precomputed threshold $l'$ to avoid expensive power operations when $l$ is large [S1, unofficial].
*   **Boundaries:** Ray-box intersection distance $d$ must be calculated efficiently. Using Euclidean distance is expensive; use the cosine-based approximations provided in the source if the ray is axis-aligned or close to it, though the source notes the general Euclidean formula is computationally expensive [S1, unofficial].
*   **Degenerate Input:** If a node has 0 points or 0 edge length, handle division by zero in the $l$ calculation [S1, unofficial].

## Subtopics

### Global and Local Octrees
A variant where the dataset is represented by one global octree for the entire volume and one or more local octrees for specific ROIs [S1, unofficial]. The global octree is pre-constructed to save interactive time. Local octrees are built in real-time by using the global octree to locate the bounding box containing the ROI, then constructing a new octree only for points within that box [S1, unofficial]. Local octrees typically have less depth than the global octree but approximate fewer points per node, yielding better approximation quality for the covered space (e.g., global depth 7 vs. local depth 3 for the same data density) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Pre-processing is $O(N)$ or $O(N \log N)$ depending on the octree construction algorithm, where $N$ is the number of points. Interactive rendering is $O(R \cdot L)$, where $R$ is the number of rays and $L$ is the average depth of the octree traversed. Refinement increases local $L$ for the ROI but keeps it low for the background.
*   **Memory Complexity:** $O(N)$ in the worst case, but significantly reduced by the error-based termination criterion which merges nodes with similar values [S1, unofficial].
*   **Performance:** The coarse approximation allows for fast preview. Refinement adds overhead only for the ROI. Coarsening reduces memory and speeds up rendering by merging nodes [S1, unofficial].
*   **Strengths:** Interactive exploration of large datasets; user-driven focus; efficient storage via error-controlled compression.
*   **Limitations:** Requires pre-processing; scattered data assumption (no connectivity); weight function approximation may introduce artifacts if $l$ is estimated poorly.

## Background
The method was proposed by E. Brugger, B. Hamann, and colleagues at Lawrence Livermore National Laboratory and UC Davis [S1, unofficial]. It addresses the challenge of rendering large scattered volume datasets (e.g., from scientific simulations) where traditional ray casting is too slow. The approach builds on Levoy's ray termination condition and Wan et al.'s empty space skipping, but adapts them for an octree-based multiresolution framework [S1, unofficial].
