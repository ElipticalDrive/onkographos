# SparseGrid

Also called: SparseGrid Data Structure

## Overview
SparseGrid is a sparse adaptive grid that allocates memory only for cells explicitly added to the domain, making it suitable for large 3D spaces containing small iso-surface regions [S1, unofficial]. It differs from hash grids by maintaining an explicit lattice structure defined by a shape and axis-aligned bounding box (AABB), rather than relying solely on hash collisions for spatial mapping [S1, unofficial].

## How it works
**Inputs and Outputs:**
The structure is initialized with a 3D integer `shape` (number of sample points per dimension), an AABB (`aabb_min`, `aabb_max`), and a `default_value` for unset regions [S1, unofficial]. It accepts 1D `int32` tensors of linear cell indices for adding or removing cells [S1, unofficial]. It outputs tensors of corner coordinates, scalar values, and connectivity data for active cells [S1, unofficial].

**Data Structures:**
The core storage resides on the GPU device using Thrust device vectors [S1, unofficial]:
- `thrust::device_vector<float> values`: Stores scalar values at cell corners. Layout is $(N, 8)$, where $N$ is the number of active cells [S1, unofficial].
- `thrust::device_vector<uint> cell_indices`: Stores linear indices of active cells. Layout is 1D, size $N$ [S1, unofficial].
- `uint3 shape`: Dimensions of the implied lattice [S1, unofficial].
- `float3 aabb_min`: Minimum corner of the bounding box. Default: $[-1, -1, -1]$ [S1, unofficial].
- `float3 aabb_max`: Maximum corner of the bounding box. Default: $[1, 1, 1]$ [S1, unofficial].
- `float default_value`: Value for unset points. Default: `FLT_MAX` [S1, unofficial].

**Linear Indexing:**
Cells are identified by linear indices within the implied lattice defined by `shape` [S1, unofficial]. The linear index $L$ for grid coordinates $(x, y, z)$ follows standard row-major ordering: $L = x \cdot (shape.y \cdot shape.z) + y \cdot shape.z + z$ [G].

**Algorithm Steps:**

1.  **Initialization:** Construct the grid with `shape`, `aabb_min`, `aabb_max`, and `default_value` [S1, unofficial].
2.  **Add Cells:** `add_cells` accepts a 1D `int32` tensor of linear cell indices to add cells to the grid [S1, unofficial].
3.  **Remove Cells:** `remove_cells` accepts a 1D `int32` tensor of linear cell indices to remove cells from the grid [S1, unofficial].
4.  **Get Points:** `get_points_by_cell_indices` accepts a 1D `int32` tensor of cell indices and returns an $(N, 8, 3)$ `float32` tensor of corner coordinates [S1, unofficial].
5.  **Get Values:** `get_values` returns an $(N, 8)$ `float32` tensor of scalar values at active cell corners [S1, unofficial].
6.  **Get Cell Indices:** `get_cell_indices` returns a 1D `int32` tensor of linear indices of all active cells [S1, unofficial].
7.  **Filter Iso-surface:** `filter_cell_indices` accepts `cell_indices`, `values` $(N, 8)$, and `level` (default 0.0), returning a 1D `int32` tensor of indices for cells crossing the iso-surface [S1, unofficial].
8.  **Get Dual Quads:** `get_dual_quads` takes `NDArray<uint2> edges` and `NDArray<bool> is_out` as input, returning a tuple of `thrust::device_vector<int4>`, `thrust::device_vector<bool>`, and `thrust::device_vector<uint2>` [S1, unofficial].
9.  **Get Grid View:** Returns a `GridView` struct containing `shape`, `aabb_min`, `aabb_max`, `values.data().get()`, `cell_indices.data().get()`, and a boolean flag `true` [S1, unofficial].
10. **Get Cell Connectivity:** `get_cells` returns cell connectivity as point indices [S1, unofficial].

**Pseudocode:**

```python
import numpy as np

class SparseGrid:
    def __init__(self, shape: tuple, aabb_min: tuple = (-1, -1, -1), 
                 aabb_max: tuple = (1, 1, 1), default_value: float = float('inf')):
        self.shape = shape
        self.aabb_min = np.array(aabb_min, dtype=np.float32)
        self.aabb_max = np.array(aabb_max, dtype=np.float32)
        self.default_value = default_value
        self.cell_indices = []
        self.values = {}

    def add_cells(self, indices: np.ndarray) -> None:
        """Add cells to the grid."""
        for idx in indices:
            if idx not in self.cell_indices:
                self.cell_indices.append(idx)
                self.values[idx] = [self.default_value] * 8

    def remove_cells(self, indices: np.ndarray) -> None:
        """Remove cells from the grid."""
        for idx in indices:
            if idx in self.cell_indices:
                self.cell_indices.remove(idx)
                del self.values[idx]

    def get_points_by_cell_indices(self, indices: np.ndarray) -> np.ndarray:
        """Return (N, 8, 3) float32 tensor of corner coordinates."""
        if len(indices) == 0:
            return np.empty((0, 8, 3), dtype=np.float32)
        points = []
        for idx in indices:
            if idx in self.values:
                x = idx // (self.shape[1] * self.shape[2])
                rem = idx % (self.shape[1] * self.shape[2])
                y = rem // self.shape[2]
                z = rem % self.shape[2]
                dx = (self.aabb_max[0] - self.aabb_min[0]) / self.shape[0]
                dy = (self.aabb_max[1] - self.aabb_min[1]) / self.shape[1]
                dz = (self.aabb_max[2] - self.aabb_min[2]) / self.shape[2]
                corners = []
                for cx in [x, x + 1]:
                    for cy in [y, y + 1]:
                        for cz in [z, z + 1]:
                            corners.append([self.aabb_min[0] + cx * dx,
                                           self.aabb_min[1] + cy * dy,
                                           self.aabb_min[2] + cz * dz])
                points.append(corners)
        return np.array(points, dtype=np.float32)

    def get_values(self) -> np.ndarray:
        """Return (N, 8) float32 tensor of scalar values at active cell corners."""
        if not self.cell_indices:
            return np.empty((0, 8), dtype=np.float32)
        return np.array([self.values[idx] for idx in self.cell_indices], dtype=np.float32)

    def get_cell_indices(self) -> np.ndarray:
        """Return 1D int32 tensor of linear indices of all active cells."""
        return np.array(self.cell_indices, dtype=np.int32)

    def filter_cell_indices(self, level: float = 0.0) -> np.ndarray:
        """Return 1D int32 tensor of indices for cells crossing the iso-surface."""
        crossing = []
        for idx in self.cell_indices:
            vals = self.values[idx]
            if not all(v >= level for v in vals) and not all(v <= level for v in vals):
                crossing.append(idx)
        return np.array(crossing, dtype=np.int32)

    def get_num_cells(self) -> int:
        """Return cell_indices.size()."""
        return len(self.cell_indices)

    def get_num_points(self) -> int:
        """Return cell_indices.size() * 8."""
        return len(self.cell_indices) * 8

    def get_dual_quads(self, edges: np.ndarray, is_out: np.ndarray) -> tuple:
        """Return tuple of quad definitions, output flags, and deduplicated edges."""
```

**Edge Cases and Pitfalls:**
- Cells are added based on linear indices within the `shape` [S1, unofficial].
- If `shape` is large but only a few cells are added, the structure remains sparse [S1, unofficial].
- [G] Guard against zero dimensions in `shape` during coordinate conversion to prevent division by zero.
- Not given in the sources for overflow behavior or precision limits.

## Subtopics

### Hash Grids
Hash Grids use hash functions to map 3D coordinates to memory locations, offering $O(1)$ average access time but no inherent spatial locality [G]. Choose SparseGrid when explicit lattice structure and AABB-based world space mapping are required, or when traversal order matters [S1, unofficial]. [Link](936-hash-grids.md)

### Stack-Based Representation (SBR)
SBR stores active voxels in a linear stack, often with run-length encoding [G]. It is highly compact for contiguous regions [G]. Choose SparseGrid when random access to specific cell indices is needed or when dynamic addition/removal of arbitrary cells is frequent [S1, unofficial]. [Link](1081-stack-based-representation-sbr.md)

### Pointer Compression
Pointer Compression reduces memory overhead by compressing pointers in tree structures [G]. SparseGrid does not use pointers for spatial traversal, relying instead on linear indices [S1, unofficial]. Choose Pointer Compression for deep tree structures where pointer overhead dominates [G]. [Link](1770-pointer-compression.md)

### Brick-based Hierarchical Storage
Brick-based storage divides the volume into bricks (sub-grids), allowing for hierarchical compression [G]. Choose this for large volumes with multi-resolution requirements [G]. SparseGrid is flat and adaptive at the cell level [S1, unofficial]. [Link](2793-brick-based-hierarchical-storage.md)

### Brickmap SDF Volume Rendering
Brickmap SDF uses brick-based storage specifically for Signed Distance Fields [G]. Choose this for SDF rendering where hierarchical LOD is beneficial [G]. SparseGrid is a general-purpose sparse grid for scalar fields [S1, unofficial]. [Link](3310-brickmap-sdf-volume-rendering.md)

### Compaction of Update Information
Compaction optimizes the storage of changes to sparse volumes [G]. SparseGrid supports dynamic add/remove operations, which may benefit from compaction techniques [S1, unofficial]. [Link](3364-compaction-of-update-information.md)

### Tree-based structures (Octree, Pointer Tree, Sparse Voxel DAG)
Tree-based structures recursively subdivide space, offering hierarchical traversal and efficient empty space skipping [G]. Choose SparseGrid when a flat, adaptive grid with explicit linear indexing is preferred over recursive traversal [S1, unofficial]. [Link](4139-tree-based-structures-octree-pointer-tree-sparse-voxel-dag.md)

### Out-of-Core Rendering with Virtual Page Tables
Out-of-core rendering manages volumes larger than RAM using virtual memory [G]. SparseGrid can be adapted for out-of-core use by paging `cell_indices` and `values` to disk [S1, unofficial]. [Link](5359-out-of-core-rendering-with-virtual-page-tables.md)

## Operating characteristics
- **Time Complexity:** Voxel read and write access operates in constant time $O(k)$, though with a larger constant factor $k$ than an ordinary dense buffer due to the overhead of locating the relevant data [S4, unofficial].
- **Memory Complexity:** $O(N)$ where $N$ is the number of active cells, as only explicitly added cells allocate memory [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales linearly with the number of active cells; performance is independent of the total volume size defined by `shape` [S1, unofficial].
- **Strengths:** Efficient for large domains with small active regions; explicit lattice structure allows easy coordinate conversion; supports dynamic add/remove operations [S1, unofficial].
- **Limitations:** No inherent spatial locality for traversal compared to tree structures; hash/set overhead for index management [G].
- **When to use:** Large sparse volumes, dynamic updates, explicit lattice requirements [S1, unofficial].
- **When not to use:** Dense volumes, hierarchical traversal needed, multi-resolution requirements [G].

## Background
SparseGrid is described in the context of GPU-based volume rendering and iso-surface extraction, specifically within the `isoext` project [S1, unofficial]. It is designed to work with marching tetrahedra and dual mesh generation algorithms [S1, unofficial]. The structure inherits from a base `Grid` class and stores data on the device using Thrust [S1, unofficial].
