# Reprojected Spatial Hash Map Indices

Also called: Temporal Reprojection of Hash Indices

## Overview
This method optimizes spatial hash lookups in temporal volume rendering by reusing hash indices from the previous frame, thereby reducing the frequency of expensive atomic memory operations on the hash grid [S1, unofficial]. It differs from standard spatial hash lookups by splitting the Ray Traced Ambient Occlusion (RTAO) pass into a reprojection step and a fullscreen shading step, using a texture-based history buffer to validate and propagate indices across frames [S1, unofficial].

## How it works
### Inputs and Outputs
*   **Inputs**:
    *   Previous frame’s history texture containing hash indices and checksums [S1, unofficial].
    *   Current frame’s scene state and camera parameters for reprojection and fallback computation [S1, unofficial].
    *   Hash grid data structure for fallback index lookups [S1, unofficial].
    *   Frame counter uniform (`uniforms.frame_index`) [S1, unofficial].
    *   Touch mask parameter derived from `VX_AO_HASH_TOUCH_PERIOD` [S1, unofficial].
*   **Outputs**:
    *   Current frame’s hash index texture written to GPU memory [S1, unofficial].
    *   Updated hash grid frame counters modified via atomic operations [S1, unofficial].

### Data Structures
The method relies on a texture storing the hash indices from the previous frame [S1, unofficial]. The history buffer contains at least two fields per entry: the spatial hash index and a checksum value used to validate that the spatial location and scene state have not changed significantly [S1, unofficial]. The hash grid maintains a frame counter array to track entry freshness [S1, unofficial].

### Steps
1.  **Reproject**: Look up the hash index from the previous frame [S1, unofficial]. If the history and checksum are valid, use the reprojected index [S1, unofficial]. Otherwise, compute the new hash index [S1, unofficial].
2.  **Write**: Write the current frame’s hash index to a texture [S1, unofficial].
3.  **Render**: Perform a fullscreen RTAO pass using the gbuffer and the hashmap index texture [S1, unofficial].
4.  **Update Frame Counter**: Atomically update the frame counter for the hash entry [S1, unofficial]. To reduce atomic traffic, this update is performed only periodically based on a touch mask [S1, unofficial].

```python
# Constants
VX_AO_HASH_TOUCH_PERIOD = 8  # Example value; source uses VX_AO_HASH_TOUCH_PERIOD
touch_mask = VX_AO_HASH_TOUCH_PERIOD - 1

    frame_counters = {}

def atomic_exchange(addr, new_value):
    """Simulates GPU atomic exchange for frame counter update."""
    old_value = addr.value
    addr.value = new_value
    return old_value

def check_checksum(prev_checksum, current_scene_state):

    # Exact validation logic is not detailed in source [G]
    return True

def compute_spatial_hash(position, hash_grid):
    """Computes the new hash index using the standard spatial hash function [G]."""
    # Exact hash function details are in SpatialHash3D [G]
    return hash_grid.compute(position)

def reproject_hash_index(previous_index_texture, current_scene_state, hash_grid, frame_index, screen_position):
    """Determines the hash index for the current frame."""
    prev_index, prev_checksum = previous_index_texture.read(screen_position)
    is_valid = check_checksum(prev_checksum, current_scene_state)
    if is_valid:
        return prev_index, True
    else:
        new_index = compute_spatial_hash(current_scene_state.position, hash_grid)
        return new_index, False

def update_frame_counter(hash_frames, hash_index, frame_index, touch_mask):
    """Atomically updates the frame counter for a hash entry using a touch mask."""
    if (frame_index & touch_mask) == (hash_index & touch_mask):
        atomic_exchange(hash_frames[hash_index], frame_index)

def rtao_index_pass(previous_index_texture, hash_grid, frame_index, screen_position):
    # Step 1: Reproject
    current_index, _ = reproject_hash_index(previous_index_texture, current_scene_state, hash_grid, frame_index, screen_position)
    # Step 2: Write index to texture
    current_index_texture.write(screen_position, current_index)
    # Step 3: Update frame counter
    update_frame_counter(hash_grid.frame_counters, current_index, frame_index, touch_mask)
    return current_index_texture
```

### Parameters
*   **`VX_AO_HASH_TOUCH_PERIOD`**: Determines the frequency of frame counter updates [S1, unofficial]. The touch mask is derived as `VX_AO_HASH_TOUCH_PERIOD - 1` [S1, unofficial]. The source does not specify the exact value used, but implies it is a power of two to facilitate bitwise masking [S1, unofficial].

### Edge Cases and Pitfalls
*   **Atomic Traffic**: Atomic reads and writes to the hash map cause high MMU activity and latency [S1, unofficial]. Without reprojection, the index pass can take over 6 milliseconds on hardware like the MacBook Air (M2) [S1, unofficial].
*   **Invalid History**: If the history is invalid due to camera movement or scene changes, the fallback to computing a new hash index incurs the full cost of atomic operations [S1, unofficial].
*   **Checksum Mismatch**: A mismatching checksum triggers a recomputation, which is more expensive than a reprojected lookup [S1, unofficial].

## Subtopics

### SpatialHash3D
A spatial index structure using a uniform 3D hash grid to enable efficient nearest-neighbor and radius-based queries for static datasets [Parent]. It provides O(1) cell lookup and serves as the fallback mechanism when reprojection fails [Parent]. Choose it when static spatial queries are required without temporal dependencies [Parent]. [SpatialHash3D](5113-spatialhash3d.md)

### RTAO
A fullscreen shading pass that consumes the reprojected hash index texture to compute ambient occlusion. It is decoupled from the index computation to improve shader occupancy and reduce atomic contention. Choose it when decoupling shading from index generation improves performance. [RTAO](5114-rtao.md)

## Operating characteristics
*   **Measured Performance**:
    *   **monu2.vox**: Average GPU walltime reduced from 6.46 ms to 5.88 ms (-9.01%) [S1, unofficial]. FPS remained stable at ~144 [S1, unofficial].
    *   **sponza-1024.vox**: Average GPU walltime reduced from 26.17 ms to 24.95 ms (-4.68%) [S1, unofficial]. FPS increased from 64.81 to 67.72 (+4.49%) [S1, unofficial].
*   **Memory Usage Reduction**:
    *   Device Atomic Bytes Read dropped from 309.19 MiB to 4 KiB [S1, unofficial].
    *   Device Atomic Bytes Written dropped from 617.13 MiB to 19.16 MiB [S1, unofficial].
*   **Strengths**: Significantly reduces atomic memory traffic and MMU activity, leading to lower latency in the index pass [S1, unofficial].
*   **Limitations**: The performance gain is modest in heavy scenes (e.g., Sponza) and depends on the validity of the history buffer [S1, unofficial].
*   **When to Use**: When atomic operations on the hash grid are a bottleneck and the scene/camera motion is smooth enough to allow valid history reprojection [S1, unofficial].

## Background
This optimization was introduced in the development of the `vxray` voxel raytracer, specifically in commit `c41b366` dated 2026-09-01 [S1, unofficial]. It was developed to address high MMU activity and latency observed during the spatial hash lookup pass on Apple Silicon hardware (MacBook Air M2) [S1, unofficial]. The technique is part of a broader effort to optimize sparse voxel rendering by reducing the cost of hash map interactions [S1, unofficial].
