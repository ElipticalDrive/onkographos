# Hash Map-based Sparse Data Structure

Also called: Surface Cell Hash Map, Rendering Data Structure (Implicit Surface Cell Hash Map)

## Overview
A hash map-based sparse data structure that maps spatial particle positions to memory locations using a compact cell list sorted by Morton codes, designed to reduce Smoothed Particle Hydrodynamics (SPH) neighbor search complexity from $O(n^2)$ to $O(n \cdot c)$ [S2]. It distinguishes itself from its sibling [Perfect Spatial Hashing](8448-perfect-spatial-hashing.md) by supporting variable cell sizes and adaptive resolutions through multi-level structures, and from [Reprojected Spatial Hash Map Indices](5180-reprojected-spatial-hash-map-indices.md) by explicitly managing surface detection for ray tracing [S2]. It solves the problem of efficient spatial lookup in highly adaptive particle simulations where dense grids are memory-prohibitive [S2].

## How it works
### Inputs and Outputs
**Inputs:**
*   Particle positions $x_i$ and rest volumes $V_i$ [S2].
*   Simulation domain bounds $D_{min}, D_{max}$ [S2].
*   Target hash table size $n_{hash}$ [S2].
*   Mode: Simulation (neighbor search) or Rendering (surface intersection) [S2].

**Outputs:**
*   **Simulation Structure:** Hash map $H$ with `begin` and `length` arrays, and compacted cell list $C_{begin, compact}$ allowing $O(1)$ cell lookup for any coordinate [S2].
*   **Rendering Structure:** Hash map $H_R$ storing Morton codes or collision markers for cells containing fluid surfaces [S2].

### Data Structures
1.  **Particle List:** Array of particles sorted by Morton code $Z_i$ [S2].
2.  **Cell List ($C$):** Array of length $n_{particles} + 1$.
    *   $C[i]$ stores the index of the first particle in cell $i$, or $-1$ if empty, or $n_{particles}$ if end of list [S2].
3.  **Compacted Cell List ($C_{begin, compact}$):** Array of length $n_{occupied} + 1$.
    *   Stores the indices into the sorted particle list where each occupied cell begins [S2].
4.  **Hash Map ($H$):**
    *   `H_begin`: Array of size $n_{hash}$. Stores the index in $C_{begin, compact}$ where cells mapping to hash bucket $k$ start [S2].
    *   `H_length`: Array of size $n_{hash}$. Stores the number of cells mapping to hash bucket $k$ [S2].
5.  **Rendering Hash Map ($H_R$):**
    *   Stores either a Morton code $Z_q$ (if the cell contains surface particles and no collision occurred) or a collision marker [S2].

### Parameters
*   $N_h$: Number of neighbors for cubic spline kernel, typically 50 [S2].
*   $n_{hash}$: Smallest prime number larger than the maximum number of particles in the simulation [S2].
*   Hash Primes (Simulation only): $p_1 = 73,856,093$, $p_2 = 19,349,663$, $p_3 = 83,492,791$ [S2].
*   Morton Code Width: 30-bit (non-adaptive) or 60-bit (adaptive) [S2]. 32-bit allows 10 bits/dimension (1024 cells/dim); 64-bit allows 21 bits/dimension (2,097,152 cells/dim) [S2].

### Formulas
*   **Support Radius:** $h_i = \sqrt[3]{\frac{3 N_h V_i}{4 \pi}}$ [S2].
*   **Effective Support Extent:** $h_i = \max(h_{ii}, h_{xi}, \max(h_{ii}, h_{yi}, \max(h_{ii}, h_{zi})))$ [S2].
*   **Max Cell Size:** $C_{max} = \max\{h_0, \dots, h_{n-1}\}$ [S2].
*   **Domain Bounds:** $D_{min} = \min\{x_0, \dots, x_{n-1}\}$, $D_{max} = \max\{x_0, \dots, x_{n-1}\}$ [S2].
*   **Normalized Coordinate:** $\bar{x} = \frac{x - D_{min}}{C_{max}}$ [S2].
*   **Linear Index:** $L(\bar{x}) = \bar{x}_x + D_x \bar{x}_y + D_y \bar{x}_z$ [S2].
*   **Morton Code:** $Z(\bar{x})$ interleaves binary bits of $\bar{x}_x, \bar{x}_y, \bar{x}_z$ [S2].
*   **Simulation Hash:** $H(\bar{x}) = (p_1 \bar{x}_x + p_2 \bar{x}_y + p_3 \bar{x}_z) \pmod{n_{hash}}$ [S2].
*   **Rendering Hash:** $H(\bar{x}) = Z(\bar{x}) \pmod{n_{hash}}$ [S2].

### Steps

#### 1. Simulation Data Structure Construction
1.  **Calculate Bounds and Cell Size:** Compute $D_{min}, D_{max}$ and $C_{max}$ from particle positions and support radii [S2].
2.  **Normalize and Sort:** For each particle $i$, compute $\bar{x}_i$ and Morton code $Z_i = Z(\bar{x}_i)$. Sort all particles by $Z_i$ [S2].
3.  **Build Cell List $C$:** Create array $C$ of size $n_{particles} + 1$:
    $$
    C[i] = \begin{cases} 
    i & \text{if } i=0 \lor Z_i \neq Z_{i-1} \\
    -1 & \text{if } Z_i = Z_{i-1} \\
    n_{particles} & \text{else}
    \end{cases}
    $$
    [S2].
4.  **Compact Cell List:** Remove all $-1$ entries from $C$ to create $C_{begin, compact}$ of length $n_{occupied} + 1$ [S2].
5.  **Sort for Hashing:** Sort the occupied cells based on their hash values $H(\bar{x})$ derived from their Morton codes or linear coordinates [S2].
6.  **Build Hash Map $H$:**
    *   Initialize `H_begin` and `H_length` to 0.
    *   For each occupied cell $i$ in the sorted list:
        *   Calculate $H_i = H(\bar{x}_i)$.
        *   If $i=0$ or $H_i \neq H_{i-1}$, set `H_begin`[$H_i$] = $i$ [S2].
        *   If $i=n_{occupied}$ or $H_i \neq H_{i+1}$, set `H_length`[$H_i$] = $i - \text{H\_begin}[H_i] - 1$ [S2].

#### 2. Rendering Data Structure Construction
1.  **Identify Surface Particles:** Calculate signed surface distance $\phi_i$ for all particles [S2]. Mark particle $i$ as surface if $\phi_i < r_i$ [S2].
2.  **Build Surface Cell List $R$:** Iterate over occupied cells $C_{compact}$. For cell $i$, let $c_0$ be the first particle in the cell ($c_0 = C_{begin, compact}[i]$).
    $$
    R[i] = \begin{cases} 
    Z(x_{c0}) & \text{if } \exists c \in C_i \text{ such that } c \text{ is a surface particle} \\
    -1 & \text{else}
    \end{cases}
    $$
    [S2].
3.  **Compact Surface List:** Compact $R$ to remove $-1$ entries, yielding list $F$ of cells containing surface particles [S2].
4.  **Build Rendering Hash Map $H_R$:**
    *   Sort $F$ by hash key $H_q = Z(q) \pmod{n_{hash}}$ [S2].
    *   Initialize $H_R$ entries as empty.
    *   For each cell $q \in F$:
        *   Calculate $H_q$.
        *   If $H_R[H_q]$ is empty, store $Z_q$ (Morton code of the cell) [S2].
        *   If $H_R[H_q]$ is occupied, mark as collision [S2].
5.  **Expand Neighbors:** For every cell $i \in F$:
    *   Calculate AABB of cell $i$ based on contained particles [S2].
    *   Check surrounding cells $N_i$.
    *   If neighbor $n$ overlaps $AABB_i$ and $n \notin F$:
        *   If hash entry for $n$ is empty, mark $n$ as potentially having fluid surface [S2].
        *   If hash entry is occupied, mark as collision [S2].

### Pseudocode

```python
def build_simulation_structure(particles, n_hash):
    n_particles = len(particles)
    D_min = min(p.pos for p in particles)
    D_max = max(p.pos for p in particles)
    C_max = max(p.h for p in particles)
    
    for p in particles:
        x_norm = (p.pos - D_min) / C_max
        p.z_code = morton_encode(x_norm)
        
    sorted_particles = sorted(particles, key=lambda p: p.z_code)
    
    C = [0] * (n_particles + 1)
    for i in range(n_particles):
        if i == 0 or sorted_particles[i].z_code != sorted_particles[i-1].z_code:
            C[i] = i
        else:
            C[i] = -1
    C[n_particles] = n_particles
    
    C_begin_compact = [idx for idx in C if idx != -1]
    C_begin_compact.append(n_particles)
    
    hash_entries = []
    for idx, cell_start_idx in enumerate(C_begin_compact[:-1]):
        p = sorted_particles[cell_start_idx]
        x_bar = (p.pos - D_min) / C_max
        p1, p2, p3 = 73856093, 19349663, 83492791
        h_key = (p1 * x_bar.x + p2 * x_bar.y + p3 * x_bar.z) % n_hash
        hash_entries.append((h_key, idx))
        
    hash_entries.sort(key=lambda x: x[0])
    
    H_begin = [0] * n_hash
    H_length = [0] * n_hash
    
    for i, (h_key, cell_idx) in enumerate(hash_entries):
        if i == 0 or h_key != hash_entries[i-1][0]:
            H_begin[h_key] = cell_idx
        if i == len(hash_entries) - 1 or h_key != hash_entries[i+1][0]:
            H_length[h_key] = i - H_begin[h_key]
            
    return H_begin, H_length, C_begin_compact, sorted_particles

def query_simulation(H_begin, H_length, C_begin_compact, sorted_particles, target_pos, D_min, C_max):
    x_bar = (target_pos - D_min) / C_max
    p1, p2, p3 = 73856093, 19349663, 83492791
    h_key = (p1 * x_bar.x + p2 * x_bar.y + p3 * x_bar.z) % len(H_begin)
    
    begin_idx = H_begin[h_key]
    length = H_length[h_key]
    if length == 0:
        return []
        
    target_z = morton_encode(x_bar)
    found_particles = []
    for k in range(begin_idx, begin_idx + length):
        cell_start_idx = C_begin_compact[k]
        if cell_start_idx < len(sorted_particles):
            cell_z = sorted_particles[cell_start_idx].z_code
            if cell_z == target_z:
                next_cell_start = C_begin_compact[k+1] if k+1 < len(C_begin_compact) else len(sorted_particles)
                for p_idx in range(cell_start_idx, next_cell_start):
                    found_particles.append(sorted_particles[p_idx])
                break
    return found_particles

def build_rendering_structure(particles, C_begin_compact, sorted_particles, n_hash, D_min, C_max):
    surface_particles = [p for p in particles if p.phi < p.r]
    
    R = []
    for idx, cell_start_idx in enumerate(C_begin_compact[:-1]):
        has_surface = False
        next_cell_start = C_begin_compact[idx+1]
        for p_idx in range(cell_start_idx, next_cell_start):
            if sorted_particles[p_idx] in surface_particles:
                has_surface = True
                break
        if has_surface:
            R.append(sorted_particles[cell_start_idx].z_code)
        else:
            R.append(-1)
            
    F = [z for z in R if z != -1]
    
    hash_entries = []
    for z_code in F:
        h_key = z_code % n_hash
        hash_entries.append((h_key, z_code))
        
    hash_entries.sort(key=lambda x: x[0])
    
    H_R_begin = [0] * n_hash
    H_R_length = [0] * n_hash
    H_R_data = [None] * n_hash
    
    for i, (h_key, z_code) in enumerate(hash_entries):
        if i == 0 or h_key != hash_entries[i-1][0]:
            H_R_begin[h_key] = i
        if i == len(hash_entries) - 1 or h_key != hash_entries[i+1][0]:
            H_R_length[h_key] = i - H_R_begin[h_key]
            
    for i, (h_key, z_code) in enumerate(hash_entries):
        is_last = (i == len(hash_entries) - 1) or (hash_entries[i+1][0] != h_key)
        if is_last:
            begin_idx = H_R_begin[h_key]
            length = H_R_length[h_key]
            if length == 1:
                H_R_data[h_key] = z_code
            else:
                H_R_data[h_key] = "COLLISION"
                
    for z_code in F:
        x_bar = morton_decode(z_code)
        cell_pos = x_bar * C_max + D_min
        aabb_min = cell_pos - C_max / 2
        aabb_max = cell_pos + C_max / 2
        neighbors = get_3x3x3_neighbors(z_code)
        
        for n_z in neighbors:
            if n_z == z_code: continue
            h_n = n_z % n_hash
            if H_R_length[h_n] == 0:
                H_R_data[h_n] = "POTENTIAL_SURFACE"
            elif H_R_data[h_n] == "COLLISION":
                pass
            elif H_R_data[h_n] == "POTENTIAL_SURFACE":
                pass
            else:
                pass
                
    return H_R_begin, H_R_length, H_R_data

def query_rendering(H_R_begin, H_R_length, H_R_data, target_pos, D_min, C_max):
    x_bar = (target_pos - D_min) / C_max
    z_q = morton_encode(x_bar)
    h_q = z_q % len(H_R_data)
    
    if H_R_length[h_q] == 0:
        return "NO_SURFACE"
        
    data = H_R_data[h_q]
    if data == "COLLISION" or data == "POTENTIAL_SURFACE":
        return "POTENTIAL_SURFACE"
    elif isinstance(data, int):
        if data == z_q:
            return "HAS_SURFACE"
        else:
            return "POTENTIAL_SURFACE"
    return "NO_SURFACE"

def morton_encode(x):
    xx, yy, zz = int(x.x * 1024), int(x.y * 1024), int(x.z * 1024)
    code = 0
    for i in range(10):
        code |= ((xx & (1 << i)) << (2*i)) | ((yy & (1 << i)) << (2*i+1)) | ((zz & (1 << i)) << (2*i+2))
    return code

def morton_decode(code):
    xx, yy, zz = 0, 0, 0
    for i in range(10):
        xx |= (code >> (2*i)) & 1
        yy |= (code >> (2*i+1)) & 1
        zz |= (code >> (2*i+2)) & 1
    return Vector3(xx / 1024, yy / 1024, zz / 1024)

def get_3x3x3_neighbors(z_code):
    coords = morton_decode(z_code)
    neighbors = []
    for dx in [-1, 0, 1]:
        for dy in [-1, 0, 1]:
            for dz in [-1, 0, 1]:
                if dx == 0 and dy == 0 and dz == 0: continue
                neighbors.append(morton_encode(coords + Vector3(dx, dy, dz)))
    return neighbors
```

### Edge Cases and Pitfalls
*   **Hash Collisions:** An empty cell can map to the same hash entry as an occupied cell. This is handled by checking $Z_c = Z_j$ for the candidate particle index $j$ during simulation queries [S2]. In rendering, collisions are explicitly marked [S2].
*   **Precision:** Floating-point normalization errors can lead to incorrect Morton codes. Use consistent normalization [S2].
*   **Boundary Conditions:** Particles moving outside the simulation domain require domain expansion or clamping. Dense structures require known a priori bounds; sparse structures handle dynamic bounds better [S2].
*   **Adaptive Resolution:** Multi-level structures are required to handle varying cell sizes. A single cell size $C_{max}$ is used for the base structure, but additional levels are built for finer resolutions [S2].

## Subtopics

### Multi-Level Memory Structures
Extends the single-level hash map to support adaptive SPH by creating multiple data structures for different cell sizes, utilizing the self-similarity of the Morton code ordering. Choose when particle density varies significantly [S2].

### Surface Cell Hash Map
A specialized rendering structure that implicitly marks cells containing fluid surfaces to avoid checking empty cells during ray casting. Choose when direct ray tracing of fluid surfaces is required [S2].

## Operating characteristics
*   **Time Complexity:** Reduces particle accesses from $O(n^2)$ to $O(n \cdot c)$ where $c$ is the number of particles accessed per particle [S2]. Hash map queries are $O(1)$ on average [S2].
*   **Memory Complexity:** Constant memory consumption regardless of simulation domain size, particle resolution, or particle distribution [S2]. Memory scales with the number of occupied cells, not the domain volume [S2].
*   **Performance:** Significant performance improvement for spatially adaptive fluid simulations and direct ray tracing with little memory overhead [S2].
*   **Strengths:** Efficient neighbor search, low memory usage, supports adaptive resolution, enables direct ray tracing [S2].
*   **Limitations:** Hash collisions require verification (simulation) or result in conservative surface detection (rendering). Morton code generation can be computationally expensive [S2].
*   **When to Use:** Highly adaptive SPH simulations, real-time fluid rendering, scenarios with large empty spaces [S2].
*   **When Not to Use:** Uniform density simulations where dense grids are more cache-friendly, or when exact surface reconstruction without potential false positives is critical without additional checks [S2].

## Background
The hash map-based sparse data structure was introduced by Winchenbach and Kolb in 2020 [S2]. It was developed to address the limitations of dense data structures in Smoothed Particle Hydrodynamics (SPH) simulations, particularly for adaptive resolutions and real-time rendering. The method builds on earlier work by Green [Gre10] and Teschner et al. [THM*03], combining Morton codes with hash maps to achieve efficient spatial indexing. It is used in computer graphics for fluid simulation and rendering, specifically in the context of the Eurographics Computer Graphics Forum publication [S2].
