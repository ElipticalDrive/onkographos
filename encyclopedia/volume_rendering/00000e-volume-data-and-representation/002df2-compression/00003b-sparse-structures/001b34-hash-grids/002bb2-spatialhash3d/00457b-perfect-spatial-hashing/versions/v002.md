# Perfect Spatial Hashing

Also called: Perfect Spatial Hash, Perfect Spatial Hashing (PSH) Encoding

## Overview
Perfect Spatial Hashing (PSH) is a hashing technique for the compact storage and efficient indexing of sparse volume data, using an injective map to store volume data in a hash table and offsets in a separate table [S1]. It is a single-resolution spatial hashing encoding method that uses a precomputed offset table to ensure zero hash collisions and maximize cache coherence by mapping spatially adjacent points to adjacent slots in the hash table [S2, unofficial]. Unlike standard multiresolution hash encoding, which suffers from cache thrashing due to uniform memory distribution, PSH minimizes hash collisions and improves memory request efficiency [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of occupied block positions $S$ (where $|S| = N_{occ}$) [S1]. For encoding queries, an input position $x$ [S2, unofficial].
*   **Output:** A hash table $H$ storing volume data and an offset table $\Phi$ [S1]. For a query $x$, the final encoding $E(x)$ [S2, unofficial].

**Data Structures:**
1.  **Hash Table $H$:** A 3D hash table of size $m = \bar{m}^3 \approx N_{occ}$, storing volume data (feature vectors) [S1]. The table contains features $F$ indexed by hash values [S2, unofficial].
2.  **Offset Table $\Phi$:** A 3D offset table of size $r = \bar{r}^3 = \sigma N_{occ}$, where $1/6 \le \sigma < 1$ [S1]. $\Phi$ is a lookup table for offsets constructed by a heuristic approach to minimize hash collisions and maximize cache coherence [S1][S2, unofficial].

**Parameters:**
*   $N_{occ}$: Number of occupied blocks (size of set $S$) [S1].
*   $N_{res}$: Grid resolution used to scale input coordinates. Typical values tested: 128, 256, 512 [S2, unofficial].
*   $\sigma$: Scaling factor for offset table size, $1/6 \le \sigma < 1$ [S1].
*   $\Phi$: The precomputed offset table [S2, unofficial].

**Formulas:**
The hash function $h(p)$ maps an integer coordinate $p$ to a unique slot in the hash table $H$ [S1].

$$ h(p) = ((p \mod \bar{m}) + (\Phi[p] \mod \bar{r})) \mod \bar{m} $$

Where:
*   $h$ is the hash function [S1].
*   $p$ is the integer vertex coordinate [S1].
*   $\bar{m}$ is the cube root of the hash table size ($m = \bar{m}^3$) [S1].
*   $\bar{r}$ is the cube root of the offset table size ($r = \bar{r}^3$) [S1].
*   $\Phi[p]$ is the value from the offset table at index $p$ [S1].

Alternatively, expressed with two hashing functions $h_0$ and $h_1$:
$$ h(p) = h_0(p) + \Phi(h_1(p)) $$
Where $h_0$ maps to base indices and $h_1$ maps to indices $q$ for the offset table [S2, unofficial].

**Steps:**
1.  **Construct Offset Table:** Perform a Shape-from-Silhouette (SfS) algorithm to obtain a coarse occupancy field from static data [S2, unofficial]. Use a heuristic approach to compute the offset table $\Phi$ from this occupancy field, ensuring that spatially adjacent points are mapped to adjacent slots in the hash table [S2, unofficial].
2.  **Scale Input:** For a given input position $x$, scale it by grid resolution $N_{res}$ and round to find the integer vertex coordinate $p = \lfloor N_{res} * x \rfloor$ [S2, unofficial].
3.  **Hash Coordinates:** Hash the integer coordinate $p$ using two hashing functions $h_0$ and $h_1$ to get base indices and offset indices [S2, unofficial]. Specifically, compute $q = h_1(p)$ [S2, unofficial].
4.  **Look Up Features:** Look up feature vectors from the hash table using corner indices derived from $h_0(p) + \Phi(h_1(p))$ [S2, unofficial]. This involves retrieving the feature vectors for each vertex of the voxel containing $x$ [S2, unofficial].
5.  **Interpolate:** Generate the final encoding $E(x)$ by tri-linearly interpolating the feature vectors of the voxel corners [S2, unofficial].

**Pseudocode:**

```python
import math

def perfect_spatial_hash_encode(x, N_res, hash_table, offset_table, m_bar, r_bar):
    """
    Computes the final encoding E(x) for a position x using Perfect Spatial Hashing.
    
    Args:
        x: Input position (3D vector/list of floats).
        N_res: Grid resolution used to scale input coordinates.
        hash_table: List or array of feature vectors indexed by hash values.
        offset_table: 3D array of offsets, size r_bar^3.
        m_bar: Cube root of hash table size.
        r_bar: Cube root of offset table size.
    Returns:
        E_x: Tri-linearly interpolated feature vector.
    """
    # 1. Scale and round to find integer vertex coordinate p
    p = [math.floor(N_res * coord) for coord in x]
    
    # 2. Generate the 8 voxel corners relative to p
    corners = []
    for i in range(2):
        for j in range(2):
            for k in range(2):
                corner_p = [p[d] + (i if d == 0 else 0) + (j if d == 1 else 0) + (k if d == 2 else 0) for d in range(3)]
                corners.append(corner_p)
    
    # 3. Hash each corner and look up features
    features = []
    for corner_p in corners:
        # Compute base index h0(p) and offset index h1(p) using standard 3D integer hashing [G]
        h0 = hash_3d(corner_p, m_bar)
        h1 = hash_3d(corner_p, r_bar)
        
        # Look up offset from Phi table
        # Note: offset_table is indexed by h1. In practice, h1 is wrapped to r_bar bounds.
        offset = offset_table[h1 % r_bar][h1 % r_bar][h1 % r_bar]
        
        # Compute final hash index: h(p) = h0(p) + Phi(h1(p))
        index = (h0 + offset) % m_bar
        
        # Retrieve feature vector from hash table
        feature = hash_table[index]
        features.append(feature)
    
    # 4. Tri-linear interpolation
    # Fractional part of x within the voxel
    frac = [N_res * coord - math.floor(N_res * coord) for coord in x]
    
    # Interpolate along z (k)
    f00 = lerp(features[0], features[1], frac[2])
    f01 = lerp(features[2], features[3], frac[2])
    f10 = lerp(features[4], features[5], frac[2])
    f11 = lerp(features[6], features[7], frac[2])
    
    # Interpolate along y (j)
    f0 = lerp(f00, f01, frac[1])
    f1 = lerp(f10, f11, frac[1])
    
    # Interpolate along x (i)
    E_x = lerp(f0, f1, frac[0])
    
    return E_x

def hash_3d(coord, mod):
    """Standard 3D integer hash function [G]."""
    h = 0
    for c in coord:
        h = (h * 31 + c) % mod
    return h

def lerp(a, b, t):
    """Linear interpolation between two vectors."""
    return [a[i] + t * (b[i] - a[i]) for i in range(len(a))]
```

**Edge Cases and Pitfalls:**
*   **Cache Thrashing:** Standard hash encoding causes cache thrashing because memory access is distributed evenly across the entire hash table [S2, unofficial]. PSH mitigates this by mapping spatially adjacent points to adjacent slots [S2, unofficial].
*   **Memory Bandwidth Waste:** Independent memory requests at each level in multiresolution hash encoding waste memory bandwidth because only a small fraction of the returned cache line is used [S2, unofficial]. PSH uses single-resolution feature vectors, reducing memory requests to one per sample point and consuming half of the returned cache line [S2, unofficial].
*   **Collision:** The offset table $\Phi$ is constructed to ensure zero hash collisions for the static data [S2, unofficial]. If the heuristic fails to find a collision-free mapping, the injectivity is lost [S1].

## Operating characteristics
*   **Time Complexity:** Access time is O(1) for arbitrary locations [S1].
*   **Memory Complexity:** The hash table size is $m \approx N_{occ}$ and the offset table size is $r = \sigma N_{occ}$ where $1/6 \le \sigma < 1$ [S1].
*   **Measured Performance:** On the 'ficus' scene at 4K resolution, PSH-256 achieved 17.83 FPS and 94.18% L2 cache hit rate, compared to i-NGP's 14.38 FPS and 72.82% L2 hit rate [S2, unofficial].
*   **Strengths:** Maximizes cache coherence by mapping spatially adjacent points to adjacent slots [S2, unofficial]. Reduces memory requests to one per sample point [S2, unofficial].
*   **Limitations:** Requires precomputation of the offset table $\Phi$ from static data [S2, unofficial]. Single-resolution encoding may not capture multi-scale details as effectively as multiresolution approaches, though it offers better memory efficiency [S2, unofficial].

## Background
Perfect Spatial Hashing was introduced by Lefebvre and Hoppe in 2006 [S1]. It has been adapted for use in neural rendering, specifically to improve the memory request efficiency of i-NGP [S2, unofficial]. The offset table construction is inspired by a heuristic approach from Fox et al. 1992 [S2, unofficial].
