# SpatialHash3D
Also called: Uniform 3D Hash Grid
## Overview
SpatialHash3D is a spatial index structure that uses a uniform 3D hash grid to enable efficient nearest-neighbor and radius-based queries for static datasets, providing O(1) cell lookup [S1, unofficial]. It is distinguished from sibling structures like KD-trees or Octrees by its simplicity and predictable performance for static data, where implementation complexity is low and radius queries are straightforward [S1, unofficial].
## How it works
**Inputs:** A static array of 3D points, each containing coordinates $(x, y, z)$ and an associated value [S1, unofficial]. A cell size parameter `cellSize` defining the granularity of the grid [S1, unofficial].
**Outputs:** A hash table mapping cell indices to lists of points contained within those cells [S1, unofficial].
**Data Structures:**
- `cellSize`: A scalar float representing the side length of each cubic cell [S1, unofficial].
- `hashTable`: A dictionary or array mapping integer cell keys to lists of point references [S1, unofficial].
- `Point`: A structure with fields `x`, `y`, `z`, and `value` [S1, unofficial].

**Steps:**
1. **Build:** Iterate through all input points [S1, unofficial]. For each point $p_i$ with coordinates $(x_i, y_i, z_i)$, calculate the cell index $(cx, cy, cz)$ using integer division:
   $$ cx = \lfloor x_i / \text{cellSize} \rfloor $$
   $$ cy = \lfloor y_i / \text{cellSize} \rfloor $$
   $$ cz = \lfloor z_i / \text{cellSize} \rfloor $$
   Hash the tuple $(cx, cy, cz)$ into a unique integer key using a multiplicative hash with prime constants [G] and insert $p_i$ into the list associated with that key in the `hashTable` [S1, unofficial].
2. **Query Radius:** To find points within a radius $r$ of a query point $q(x_q, y_q, z_q)$: calculate the center cell of $q$ using the same floor division [S1, unofficial]. Determine the range of cells to check. The search radius $r$ spans $\lceil r / \text{cellSize} \rceil$ cells in each direction [S1, unofficial]. Let $k = \lceil r / \text{cellSize} \rceil$ [G]. Iterate $dx$ from $-k$ to $k$, $dy$ from $-k$ to $k$, and $dz$ from $-k$ to $k$ [G]. For each neighbor cell $(cx_q+dx, cy_q+dy, cz_q+dz)$, compute its hash key and retrieve the list of points [S1, unofficial]. For each point in these lists, calculate the Euclidean distance to $q$ [S1, unofficial]. If the distance is $\le r$, include the point in the result set [S1, unofficial].
3. **Query K-Nearest:** Similar to radius query, but return all points found within the radius, optionally capped to the $k$-nearest [S1, unofficial].

**Parameters:**
- `cellSize`: Determines the granularity of the spatial partition [S1, unofficial].

**Edge Cases:**
- Empty neighbor cells: The hash table lookup should handle missing keys gracefully (return empty list) [G].
- Degenerate input: Points with identical coordinates will be stored in the same cell; the list structure handles this naturally [G].

**Pseudocode:**
```python
import math

class SpatialHash3D:
    def __init__(self, cell_size):
        self.cell_size = cell_size
        self.hash_table = {}

    def _hash_key(self, cx, cy, cz):
        # Multiplicative hash with prime constants [G]
        return ((cx * 73856093) ^ (cy * 19349663) ^ (cz * 83492791)) & 0xFFFFFFFF

    def build(self, points):
        for point in points:
            cx = math.floor(point.x / self.cell_size)
            cy = math.floor(point.y / self.cell_size)
            cz = math.floor(point.z / self.cell_size)
            key = self._hash_key(cx, cy, cz)
            if key not in self.hash_table:
                self.hash_table[key] = []
            self.hash_table[key].append(point)

    def query_radius(self, query_point, radius):
        cx_q = math.floor(query_point.x / self.cell_size)
        cy_q = math.floor(query_point.y / self.cell_size)
        cz_q = math.floor(query_point.z / self.cell_size)
        
        k = math.ceil(radius / self.cell_size)
        results = []
        radius_sq = radius * radius
        
        for dx in range(-k, k + 1):
            for dy in range(-k, k + 1):
                for dz in range(-k, k + 1):
                    key = self._hash_key(cx_q + dx, cy_q + dy, cz_q + dz)
                    if key in self.hash_table:
                        for point in self.hash_table[key]:
                            dist_sq = (point.x - query_point.x)**2 + \
                                      (point.y - query_point.y)**2 + \
                                      (point.z - query_point.z)**2
                            if dist_sq <= radius_sq:
                                results.append(point)
        return results

    def query_k_nearest(self, query_point, k):
        if k <= 0:
            return []
        # Estimate a radius large enough to likely contain k points [G]
        radius = self.cell_size * math.ceil(k ** 0.33)
        candidates = self.query_radius(query_point, radius)
        candidates.sort(key=lambda p: (p.x - query_point.x)**2 + (p.y - query_point.y)**2 + (p.z - query_point.z)**2)
        return candidates[:k]
```
## Subtopics

### [Reprojected Spatial Hash Map Indices](5180-reprojected-spatial-hash-map-indices.md)
Optimizes temporal lookups by reusing indices from previous frames, reducing atomic operations. It differs from standard spatial hash lookups by splitting the Ray Traced Ambient Occlusion pass into a reprojection step and a fullscreen shading step, using a texture-based history buffer to validate and propagate indices across frames. Choose it when rendering temporal volume data with high frame coherence.

### [Perfect Spatial Hashing](8448-perfect-spatial-hashing.md)
Uses an injective map and offset table to ensure zero collisions and improve cache coherence. It is a single-resolution spatial hashing encoding method that minimizes hash collisions and improves memory request efficiency compared to standard hash encoding. Choose it when cache thrashing from uniform memory distribution is a bottleneck.

## Operating characteristics
- **Time Complexity:** Build time is O(N) where N is the number of points [G]. Query time is O(1) for cell lookup, but the radius query depends on the number of points in the surrounding cells [S1, unofficial].
- **Memory Complexity:** O(N) to store the points and the hash table entries [G].
- **Performance:** Predictable for static datasets [S1, unofficial]. Not given in the sources.
- **Scaling:** Query cost scales linearly with the number of points in the checked cells, which remains small for sparse data [S1, unofficial].
- **Strengths:** Simple implementation, low overhead, efficient for static data [S1, unofficial].
- **Limitations:** Not suitable for dynamic data without rebuilding or complex updates [G]. Hash collisions can degrade performance [G].
- **When to use:** Static 3D datasets requiring nearest-neighbor or radius queries [S1, unofficial].
- **When not to use:** Dynamic datasets requiring frequent insertions/deletions, or when hierarchical structures like Octrees are more appropriate for varying densities [G].
## Background
SpatialHash3D is used in interpolation pipelines for volume rendering, such as generating scalar fields from drill-hole sample data [S1, unofficial]. It was proposed as a recommended v1 implementation for spatial indexing in the Baselode project due to its straightforward implementation and predictable performance for static data [S1, unofficial].
