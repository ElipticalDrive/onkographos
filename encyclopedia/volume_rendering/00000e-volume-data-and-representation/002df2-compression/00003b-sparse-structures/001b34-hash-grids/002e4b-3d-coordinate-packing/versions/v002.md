# 3D Coordinate Packing

Also called: Voxel Key Generation, getKey

## Overview
3D Coordinate Packing encodes three spatial coordinates into a single integer key for hash map indexing in sparse volume structures [S1, S2, unofficial]. It preserves spatial locality through deterministic bit-shifting, unlike general-purpose hash functions [S1, unofficial].

## How it works
**Inputs:** Three integer coordinates $(x, y, z)$ [S1, unofficial].
**Outputs:** A single packed integer key [S1, unofficial].

**Data Structures:**
The primary implementation uses a 64-bit integer key [S1, unofficial]. It can be implemented via a union of a struct with three 16-bit fields and a 64-bit integer, relying on memory overlap [S1, unofficial].

**Steps:**
1. Validate coordinates fit in the 16-bit signed range ($-32768$ to $32767$) [S1, unofficial].
2. Shift $z$ to bits 32–47.
3. Shift $y$ to bits 16–31.
4. Place $x$ in bits 0–15.
5. Combine with bitwise OR [S1, unofficial].

**Formula:**
$$ K = (z \ll 32) \mid (y \ll 16) \mid x $$
Where $K$ is the 64-bit key, $\ll$ denotes left bitwise shift, and $\mid$ denotes bitwise OR [S1, unofficial].

**Parameters:**
*   **Bit Width:** 16 bits per coordinate [S1, unofficial].
*   **Range:** $-32768 \le x, y, z \le 32767$ (signed 16-bit integer range) [S1, unofficial].
*   **Key Size:** 64-bit integer [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Endianness:** The union-based implementation relies on little-endian architecture and assumes no struct padding [S1, unofficial].
*   **Overflow:** Coordinates outside the 16-bit signed range will overflow or wrap, corrupting the key [S1, unofficial].
*   **Padding:** The union method assumes no struct padding between fields; explicit bit-shifting is recommended for portability [G].

**Pseudocode:**
```python
def pack_coordinates(x: int, y: int, z: int) -> int:
    # Mask to 16-bit unsigned for shifting to match 16-bit signed range assumption
    x_val = x & 0xFFFF
    y_val = y & 0xFFFF
    z_val = z & 0xFFFF
    return (z_val << 32) | (y_val << 16) | x_val

def unpack_coordinates(key: int) -> tuple:
    x = key & 0xFFFF
    y = (key >> 16) & 0xFFFF
    z = (key >> 32) & 0xFFFF
    # Convert to signed 16-bit if required by the application
    if x >= 32768: x -= 65536
    if y >= 32768: y -= 65536
    if z >= 32768: z -= 65536
    return (x, y, z)
```

## Subtopics

### Grid Index Packing & Unpacking
Maps 3D grid coordinates $(ix, iy, iz)$ to a single 32-bit integer index for compact sparse grid storage, and reverses the operation for retrieval [S2, unofficial]. It sets itself apart by using asymmetric bit allocation (10-11-11 bits) compared to the symmetric 16-16-16 packing of the parent method, optimizing for specific grid dimensions [S2, unofficial]. Choose this when memory is constrained to 32-bit keys and grid dimensions fit within 1024×2048×2048 [S2, unofficial].

**Formula:**
$$ \text{index} = (ix \ll 22) \mid (iy \ll 11) \mid iz $$
$$ ix = \text{packed} \gg 22 $$
$$ iy = (\text{packed} \gg 11) \ \& \ 0x7FF $$
$$ iz = \text{packed} \ \& \ 0x7FF $$

**Parameters:**
*   $ix$: 10 bits (max 1024) [S2, unofficial].
*   $iy$: 11 bits (max 2048) [S2, unofficial].
*   $iz$: 11 bits (max 2048) [S2, unofficial].
*   Total: 32 bits [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ for both packing and unpacking [G].
*   **Memory Complexity:** $O(1)$ auxiliary space [G].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales linearly with the number of voxels in the hash map, independent of grid density [G].
*   **Strengths:** Extremely fast; preserves spatial locality (nearby voxels have similar keys); no collision resolution logic required for the packing step itself [G].
*   **Limitations:** Fixed coordinate range; endianness dependency if using union-based implementations; not a hash function itself (collisions occur if coordinates exceed bit limits or if distinct coordinates map to the same key due to overflow) [G].
*   **When to use:** Sparse voxel grids with known, bounded dimensions; when deterministic coordinate retrieval from a hash key is required [G].
*   **When not to use:** When coordinates exceed the bit capacity (e.g., >16-bit); when spatial locality is not desired and uniform distribution is preferred (use [Hash Grids](936-hash-grids.md) instead) [G].

## Background
This technique is a fundamental building block in sparse voxel octrees and hash-based volume renderers [G]. The specific 16-bit signed variant is documented in the [AfterHumanDeclined](https://github.com/nustxujun/AfterHumanDeclined) repository [S1, unofficial], while the 32-bit asymmetric variant appears in [Volumetric-display](https://github.com/quertzuiop/Volumetric-display) [S2, unofficial].
