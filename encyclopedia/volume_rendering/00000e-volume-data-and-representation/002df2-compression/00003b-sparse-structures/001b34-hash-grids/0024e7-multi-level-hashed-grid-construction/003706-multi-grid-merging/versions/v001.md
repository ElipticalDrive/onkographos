# Multi-Grid Merging
Also called: Merging Multiple Grids
## Overview
Multi-Grid Merging is a post-processing step in multi-level hashed grid construction that combines data from multiple propagation grids into a unified representation. It solves the problem of undersampling artifacts that arise when individual propagation grids are oriented arbitrarily in space. It sets itself apart from standard grid merging by explicitly upscaling the resolution to ensure isotropic sampling, a requirement specific to principal-ordinates propagation methods [S1].
## How it works
**Inputs and Outputs:**
- Input: A set of sparse hashed grids, each associated with a specific propagation direction (ordinate).
- Output: A single merged hashed grid with doubled resolution relative to the individual input grids.

**Data Structures:**
The output is a standard sparse hashed grid. The hash function maps 3D coordinates $(x, y, z)$ to memory locations. The resolution of the coordinate space is doubled compared to the source grids to prevent aliasing.

**Steps:**
1. **Determine Target Resolution:** Calculate the resolution of the individual propagation grids. The merged grid resolution is set to double this value in each dimension. This step is determined at initialization [S1].
2. **Upsample and Merge:** Iterate through all cells in the input grids. For each non-empty cell in an input grid at position $P_{in}$, map its value to the corresponding position $P_{out}$ in the merged grid. Since the merged grid has double the resolution, the mapping involves scaling the coordinates by a factor of 2.
   - If the input grid spacing is $\Delta x$, the merged grid spacing is $\Delta x / 2$.
   - A value at index $i$ in an input grid corresponds to index $2i$ in the merged grid.
   - Values are accumulated or overwritten based on the specific merging policy (e.g., sum, max, or average) for overlapping regions.
3. **Handle Arbitrary Orientations:** Because the input grids are oriented arbitrarily, simple coordinate scaling is insufficient if the grids are rotated relative to each other. However, in the context of Principal-Ordinates Propagation, the grids are typically aligned with the principal axes or specific ordinates. The upsampling ensures that even with arbitrary orientations, the sampling density is sufficient to avoid undersampling artifacts [S1].
4. **Convergence Check:** The merging process assumes that the solution is converged when all $L_n$ (error metrics or residuals) are below a small threshold $\epsilon_L$. This check is performed on the merged data or the underlying propagation results [S1].

**Formulas:**
- Upsampling factor: $2$ [S1].
- Anisotropy threshold condition for distance $t$:
  $$ a_b \cdot g_{\sigma_s \cdot t} = \epsilon_a $$
  where $\sigma_s$ is the average scattering coefficient, $a_b$ is a coefficient, and $g$ is a function of the scattering coefficient and travel distance [S1].
- Convergence condition:
  $$ L_n < \epsilon_L $$
  where $L_n$ represents the residual or error metric for the $n$-th ordinate [S1].

**Parameters:**
- $\epsilon_a$: Anisotropy threshold. Typical value not given in sources.
- $\epsilon_L$: Convergence threshold. Typical value not given in sources.
- Resolution multiplier: $2$ [S1].

**Edge Cases and Pitfalls:**
- **Undersampling:** Failing to double the resolution results in undersampling due to the arbitrary orientations of the propagation grids [S1].
- **Precision:** The upsampling step is described as "very fast," implying it does not significantly impact performance, but precision must be maintained during coordinate mapping [S1].
- **Initialization:** The resolution is determined at initialization, so the merging step must be aware of the initial grid setup [S1].

**Pseudocode:**
```python
def merge_grids(input_grids, initial_resolution):
    """
    Merges multiple propagation grids into a single grid with doubled resolution.
    
    Args:
        input_grids: List of sparse hashed grids. Each grid is a dictionary 
                     mapping (x, y, z) tuples to values.
        initial_resolution: The resolution of the individual input grids.
        
    Returns:
        merged_grid: A sparse hashed grid with resolution 2 * initial_resolution.
    """
    merged_resolution = 2 * initial_resolution
    merged_grid = {}
    
    # Iterate through each input grid
    for grid in input_grids:
        for coords, value in grid.items():
            # Scale coordinates by 2 to upsample
            # Assuming coords are integers representing indices
            x, y, z = coords
            new_coords = (2 * x, 2 * y, 2 * z)
            
            # Merge value into the new grid
            # Depending on the specific merging policy (e.g., sum, max),
            # this step might need adjustment. Here we assume simple overwriting
            # or accumulation if the key exists.
            if new_coords in merged_grid:
                merged_grid[new_coords] += value  # Example: accumulation
            else:
                merged_grid[new_coords] = value
                
    return merged_grid
```
Note: The pseudocode assumes a simple coordinate scaling. In practice, if the grids are rotated, a rotation matrix would be applied before scaling. However, the sources emphasize the resolution doubling to handle arbitrary orientations in the context of principal-ordinates, suggesting the orientations are handled by the grid structure itself or the propagation method [S1].

## Subtopics

### Grid Deformation with Entropy Coding
This variant involves compressing the data differences between registered adjacent data slices using entropy coding. It uses a Lorenz predictor to estimate current voxel values based on neighboring voxels, and the prediction error is compressed using arithmetic coding. This method is used for efficient compression of volume data, particularly in medical imaging, where it supports fast visualization and selective decompression [S2, unofficial].

## Operating characteristics
- **Time Complexity:** The merging step is described as "very fast" [S1]. The complexity is linear with respect to the number of non-empty cells in the input grids.
- **Memory Complexity:** The output grid has double the resolution in each dimension, leading to a potential $2^3 = 8$ times increase in the coordinate space size. However, since it is a sparse grid, the actual memory usage depends on the number of non-empty cells.
- **Performance:** The upsampling step allows the remainder of the pipeline to stay virtually identical to the single-ordinate setting, maintaining real-time rendering capabilities [S1].
- **Strengths:** Prevents undersampling artifacts; fast execution; compatible with existing pipelines.
- **Limitations:** Increases memory usage due to higher resolution; requires careful initialization of resolution.

## Background
Multi-Grid Merging is part of the Principal-Ordinates Propagation method for real-time volume rendering. It was introduced in the context of handling anisotropic scattering in participating media. The method leverages the self-convolution property of hashed grids to approximate the distance light travels before its anisotropy falls below a threshold [S1]. The approach allows for efficient rendering of complex volumetric scenes by breaking down the problem into multiple propagation directions and merging the results.
