# Multi-Level Hashed Grid Construction

Also called: Grid Encoding (Hash Grid), Hash Grid, Hashed grid with macrocells, Multi-Level Hashed Grid, Multi-level Hash Tables, Row Displacement Compressed Grid

## Overview
Multi-Level Hashed Grid Construction is a method for rapidly building a sparse acceleration structure for volume rendering that combines the memory efficiency of hashed grids with the traversal speed of multi-level structures [S1, S2, unofficial]. It solves the problem of high memory consumption in classic multi-level array grids and the poor render performance of one-level hashed grids on large, sparse scenes [S1, unofficial]. It sets itself apart from its parent [Hash Grids](936-hash-grids.md) by adding a hierarchical macrocell layer to skip empty regions in larger steps, and from [Voxel World Data Structure](1101-voxel-world-data-structure.md) by using row displacement compression to avoid storing empty cells entirely [S1, unofficial].

## How it works
The method constructs a multi-resolution hash table for feature storage and a macrocell structure for spatial traversal. It uses row displacement compression to map 3D coordinates to a compact hash table, ensuring no memory is wasted on empty cells [S1, unofficial].

### Inputs and Outputs
**Inputs:**
- Scene geometry (e.g., triangle meshes) or 3D points.
- Grid density parameter $\rho$ [S1, unofficial].
- Hash grid configuration: `base_res`, `level` (number of levels), `per_level_scales`, `max_params`, `numof_hash_feet` [S2, unofficial].
- Macrocell downscaling factor (empirically 6) [S1, unofficial].

**Outputs:**
- A compressed hash table `H` and item list `L` for the finest level [S1, unofficial].
- A multi-level hash embedding buffer storing feature vectors [S2, unofficial].
- A multi-level macrocell bit array for empty space skipping [S1, unofficial].

### Data Structures

**Hash Table H (Row Displacement Compression):**
- Type: Array of machine words (integers).
- Size: $N_H$, determined by the last non-empty bit in the temporary bit array `bH` plus one [S1, unofficial].
- Content: After the prefix sum step, `H[i]` stores the starting index in `L` for cell `i`. Initially, it stores the count of items in cell `i` [S1, unofficial].

**Item List L:**
- Type: Linear array of object indices (integers).
- Size: $H[N_H - 1]$ (sum of all item counts) [S1, unofficial].
- Content: Indices of scene objects intersecting each cell, sorted by insertion order (reverse iteration ensures sorted indices) [S1, unofficial].

**Offset Array O:**
- Type: Array of integers.
- Size: $M_y \times M_z$, where $M_y, M_z$ are grid dimensions in y and z directions [S1, unofficial].
- Content: Precomputed offsets for rows: $o(y, z) = (M_y \times z) + y$ [S1, unofficial].

**Hash Table Metadata (Multi-Level):**
- `offsets`: Vector of 16 `int32`, storing cumulative offsets for each level [S2, unofficial].
- `hash_map_sizes`: Vector of 16 `uint32`, storing the size (number of parameters) for each level [S2, unofficial].
- `hash_map_indicator`: Vector of 16 `int32`, indicator (1 if $resolution^3 \le params\_in\_level$, else 0) [S2, unofficial].

**Hash Embedding Buffer:**
- Type: 1D field of `data_type` (e.g., float32).
- Size: Sum of parameters across all levels.
- Content: Feature vectors for each hash entry [S2, unofficial].

**Macrocell Bit Array:**
- Type: 3D bit array.
- Content: Indicates if a region of space is empty (1) or not (0) [S1, unofficial].

### Algorithm Steps

#### 1. Hash Table Initialization (Multi-Level)
For each level $i$ from $0$ to $level-1$:
1. Calculate resolution:
   $$res_i = \lceil base\_res \times \exp(i \times \log(per\_level\_scales)) - 1.0 \rceil + 1$$
2. Calculate parameters in level:
   $$params\_in\_level = res_i^3$$
3. Round $params\_in\_level$ up to the nearest multiple of 8 if not divisible by 8.
4. Cap $params\_in\_level$ at $max\_params$ [S2, unofficial].
5. Set indicator: $1$ if $res_i^3 \le params\_in\_level$, else $0$ [S2, unofficial].
6. Accumulate offset for the next level.
7. Verify: Final accumulated offset equals the shape of the `hash_embedding` array [S2, unofficial].

#### 2. Finely Divided Hashed Grid Construction (Row Displacement Compression)
This step builds the base hash table for the finest level using row displacement compression [S1, unofficial].

1. **Compute Offsets:**
   Calculate offsets for each row $(y, z)$:
   $$o(y, z) = (M_y \times z) + y$$
   Store in `O[o(y,z)]` [S1, unofficial].

2. **Allocate Hash Table:**
   Allocate `H` with size $N_H$ equal to the position of the last non-empty bit in temporary bit array `bH` plus one. Initialize `H` to zero [S1, unofficial].

3. **Count Items:**
   For each scene item whose bounding box intersects cell $i = (x, y, z)$:
   $$h(x, y, z) = O[(M_y \times z) + y] + x$$
   Increment `H[h(x, y, z)]` by one [S1, unofficial].

4. **Prefix Sum:**
   Compute prefix sums to determine starting indices:
   ```python
   for i from 1 to N_H:
       H[i] += H[i-1]
   ```
   `H[N_H - 1]` now holds the total number of items [S1, unofficial].

5. **Allocate Item List:**
   Allocate `L` with size $H[N_H - 1]$ [S1, unofficial].

6. **Insert Items:**
   Iterate backwards through objects $i$ from $NI-1$ down to $0$:
   For each cell $j$ intersected by object $i$:
   ```python
   L[--H[j]] = i
   ```
   This ensures item indices in `L` are sorted [S1, unofficial].

#### 3. Macrocell Construction
Build a coarser grid to skip empty cells during traversal [S1, unofficial].

1. **Overlay Coarser Grid:**
   Overlay a coarser grid over the finely divided grid [S1, unofficial].

2. **Downscale:**
   Downscale the 3D bitmap `D` (representing non-empty cells) by a factor of 6 on each extent using a quick 3D bitmap scaling operation [S1, unofficial].
   - The factor 6 is empirically determined [S1, unofficial].

3. **Bit Array:**
   The resulting multi-level macrocells are represented as a 3D bit array indicating if a region is empty [S1, unofficial].

### Parameters
- **Grid density parameter ($\rho$):** Empirically chosen as 32 for the Buddha scene to balance render time and build time [S1, unofficial].
- **per_level_scales:** Scaling factor between levels. Value: $1.3195079565048218$ [S2, unofficial].
- **Macrocell downscaling factor:** 6 on each extent [S1, unofficial].
- **base_res:** Base resolution for the lowest level [S2, unofficial].
- **max_params:** Maximum parameters per level, calculated as $2^{\log_2\_T}$ [S2, unofficial].
- **level:** Number of levels in the hierarchy [S2, unofficial].
- **numof_hash_feet:** Feature dimensions per hash entry. Value: 2 [S2, unofficial].

### Edge Cases and Pitfalls
- **Memory Exhaustion:** Non-compressed multi-level array grids may exhaust system memory for large scenes (e.g., Lucy scene), whereas hashed grids have roughly one order of magnitude lower memory footprint [S1, unofficial].
- **Storage Cost:** Storage cost increases as video length increases due to multi-level hash tables [S3].
- **Hash Function Complexity:** Worst-case time complexity for hash function computation is $O(M \times 4/3)$, where $M$ is the number of cells [S1, unofficial].

## Subtopics

### [Multi-Grid Merging](7905-multi-grid-merging.md)
Multi-Grid Merging is a post-processing step that combines data from multiple propagation grids into a unified representation. It solves undersampling artifacts from arbitrarily oriented grids by explicitly upscaling resolution to ensure isotropic sampling, a requirement specific to principal-ordinates propagation methods.

### Multigrid Volume Compression Header Generation
An algorithm to generate compression headers for a multigrid volume representation [S4, unofficial]. It determines the dominant label and constant subregion status for each node in the hierarchy by analyzing child elements [S4, unofficial]. It iterates through 8 child elements, skipping those with label `0xFFFFFFFF` (outside volume), counts label occurrences to find the max label, and updates a constant flag if all children share the same label and are constant [S4, unofficial]. It writes the max label and constant flag to the output array and updates the LOD start position [S4, unofficial].

## Operating characteristics
- **Time Complexity:** Linear in the number of scene items, except for hash function computation which has a worst-case time complexity of $O(M \times 4/3)$, where $M$ is the number of cells [S1, unofficial].
- **Memory Complexity:** Roughly one order of magnitude lower than regular, non-compressed grids [S1, unofficial]. Multi-level hashed grids have slightly higher memory consumption than one-level hashed grids [S1, unofficial].
- **Performance:** Multi-level hashed grids provide around twice the render time performance of one-level hashed grids for large scanned scenes with many empty cells, due to macrocells [S1, unofficial]. For small non-uniform density scenes (e.g., Office, Conference), classic adaptive multi-level array grid schemes perform better [S1, unofficial].
- **Build Time:** Short and roughly linear with the number of triangles [S1, unofficial].
- **Query Time:** Querying multi-level hash tables takes approximately 7ms per inference step [S3].
- **Strengths:** Low memory footprint, fast build time, good render performance for large sparse scenes [S1, unofficial].
- **Limitations:** Higher storage cost for long videos [S3]. Poor performance on small non-uniform density scenes compared to adaptive array grids [S1, unofficial].

## Background
The method was introduced to address the limitations of one-level hashed grids (lower render performance) and classic multi-level grids (high memory consumption) [S1, unofficial]. It builds on row displacement compression [S1, unofficial] and macrocell concepts from Wald et al. (2006) [S1, unofficial]. The specific multi-resolution hash grid encoding with multiple levels of resolution is also used in neural rendering contexts, such as Neural Radiance Fields (NeRF) variants, to map 3D coordinates to feature vectors for MLP networks [S2, unofficial][S3].
