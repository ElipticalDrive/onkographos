# Instant-NGP Grid Hierarchy

Also called: Cascaded Hierarchy of 128^3 Resolution Grids, Instant-NGP Multi-Level Hashed Grid

## Overview
The Instant-NGP Grid Hierarchy is a multi-resolution feature storage system that uses a cascaded set of hash grids to encode scene features at varying spatial frequencies [S1, S2]. It solves the problem of efficiently storing high-dimensional feature vectors for neural radiance fields by combining dense storage for coarse levels with spatial hashing for fine levels, ensuring a fixed parameter count regardless of resolution [S2]. It differs from its siblings by using a specific geometric progression of grid domains centered around $(0.5, 0.5, 0.5)$ with a fixed base resolution of 16, whereas [Multi-Grid Merging](7905-multi-grid-merging.md) focuses on combining grids, and [Neuralangelo Hashgrid Configuration](8523-neuralangelo-hashgrid-configuration.md) adapts the configuration for surface reconstruction [S2].

## How it works
**Inputs:**
- $L$: Number of levels (default 16) [S1, S2].
- $R_{min}$: Coarsest resolution (default 16) [S2].
- $R_{max}$: Finest resolution (default 2048) [S2].
- $T$: Maximum number of feature vectors per grid (default $2^{19}$) [S2].
- $F$: Dimensionality of feature vectors (default 2) [S1, S2].
- $K$: Number of cascaded domains (default 5, range [1, 5]) [S1].
- $\pi_i$: Unique large prime numbers for hashing [S2].

**Outputs:**
- A set of $L$ feature grids, each containing up to $T$ feature vectors of size $F$ [S2].

**Data Structures:**
Each level $l \in \{0, \dots, L-1\}$ has an associated resolution $R_l$ and domain size [S1, S2].
- If $R_l^3 \le T$, the grid is stored as a dense array of size $R_l^3 \times F$ [S2].
- If $R_l^3 > T$, the grid is stored as a hash table mapping indices to feature vectors of size $F$ [S2].

**Steps:**
1. **Calculate Resolutions:** For each level $l \in \{0, \dots, L-1\}$, compute the resolution $R_l$ using geometric sampling [S2]:
   $$
   b := \exp\left(\frac{\ln R_{max} - \ln R_{min}}{L - 1}\right)
   $$
   $$
   R_l := \lfloor R_{min} \cdot b^l \rfloor
   $$
   [S2]

2. **Define Domains:** For each level $l$, the grid spans a 3D domain [S1]. In the Instant-NGP implementation, this forms a cascaded hierarchy where each grid $k \in \{1, \dots, K\}$ spans a domain:
   $$
   \left[-2^{k-1} + 0.5, 2^{k-1} + 0.5\right]^3
   $$
   centered around $(0.5, 0.5, 0.5)$ [S1]. The sources describe resolution $R_l$ scaling geometrically [S2] and domain scaling exponentially with $k$ [S1]; the exact mapping between $l$ and $k$ is not explicitly defined, but both describe the multi-level nature [S1, S2]. The base resolution is 16 entries [S1].

3. **Store Features:** For a query point $x$ at level $l$:
   - If $R_l^3 \le T$: Map $x$ to grid coordinates $g$ within the domain of resolution $R_l$ [G]. Retrieve feature vector $v$ from the dense array at index $g$ [G].
   - If $R_l^3 > T$: Compute hash index $h(x)$:
     $$
     h(x) = \bigoplus_{i=1}^{3} (x_i \cdot \pi_i) \mod T
     $$
     where $\oplus$ is bit-wise XOR, $x_i$ are coordinates scaled to the grid domain, and $\pi_i$ are unique large primes [S2]. Retrieve feature vector $v$ from the hash table at index $h(x)$ [G].

**Parameters:**
- $L=16$, $R_{min}=16$, $R_{max}=2048$, $F=2$, $T=2^{19}$ [S2].
- $K \in [1, 5]$ [S1].

**Edge Cases:**
- Hash collisions: The hash function uses modulo $T$, so collisions are possible [S2]. The sources do not specify the collision resolution strategy [G].
- Boundary conditions: The domain is defined as $\left[-2^{k-1} + 0.5, 2^{k-1} + 0.5\right]^3$ [S1]. Points outside this domain are not handled by this specific grid level [G].

## Subtopics

### Multi-Res. Grids
A scene representation using $L$ levels of feature grids with resolutions sampled in geometric space to combine features at different frequencies, using a spatial hash function to index feature vectors at finer levels to keep parameter count fixed. It differs from the Instant-NGP hierarchy by explicitly defining the resolution calculation via geometric progression and the hash function formula, whereas Instant-NGP uses a cascaded domain structure. Choose this when a fixed parameter count with explicit geometric resolution scaling is required. Link: [Multi-Res. Grids](7905-multi-grid-merging.md) is a sibling, but this variant is the core definition of the multi-resolution approach in MonoSDF.

## Operating characteristics
**Time Complexity:** $O(1)$ per feature lookup per level, assuming $O(1)$ hash computation and retrieval [S2].
**Memory Complexity:** $O(L \cdot T \cdot F)$ for the hash tables, plus $O(R_{coarse}^3 \cdot F)$ for dense grids [S2]. With $T=2^{19}$ and $L=16$, memory is fixed regardless of scene size [S2].
**Measured Performance:** In NeRFshop, rendering time was 0.189 s before edits and 0.243 s after edits, significantly faster than Deforming-NeRF (0.954 s, 2.561 s) and NeRF-Editing (4.503 s, 35.696 s) [S1].
**Strengths:** Fast updates and rendering due to fixed parameter count and efficient hashing [S1, S2].
**Limitations:** Hash collisions may occur due to the modulo operation in the hash function [S2]; domain boundaries are fixed as defined in the cascaded hierarchy [S1].
**When to use:** Interactive editing and real-time rendering where speed is critical [S1].

## Background
Originated in Instant-NGP [Müller et al. 2022] [S1, S2]. Used in NeRFshop for interactive editing of neural radiance fields [S1] and in MonoSDF for monocular geometric cues [S2].
