# Volumetric Mesh Generation with Spatial Hashing

Also called: Efficient Volumetric Mesh Representation, Real-Time Scene Reconstruction Using Spatial Hashing

## Overview
This method generates a watertight triangular mesh from a Truncated Signed Distance Function (TSDF) volume by integrating Marching Cubes (MC) with a spatially hashed block structure, enabling real-time incremental reconstruction on GPUs [S1]. It distinguishes itself from standard MC implementations by introducing temporal consistency checks to minimize triangle allocation, a lock-based vertex sharing mechanism to prevent memory leaks during parallel execution, and a disturbance detection algorithm to correct topological irregularities caused by limited resolution [S1]. Unlike the parent [Volumetric Triangle Representation with Spatial Hashing](13835-volumetric-triangle-representation-with-spatial-hashing.md) which focuses on compact vertex binding, this method explicitly manages the lifecycle of mesh primitives (vertices and triangles) via reference counting and garbage collection to maintain memory efficiency in dynamic scenes [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   Depth image $D_i: \mathbb{R}^2 \rightarrow \mathbb{R}$ and sensor pose $^w_s T_i = [^w_s R_i | ^w_s t_i] \in SE(3)$ [S1].
*   Intrinsic matrix $K$ of the sensor [S1].
*   Current TSDF volume $d(c)$ stored in a spatial hash grid [S1].
*   Previous cube types $t_{i-1}$ for temporal consistency [S1].

**Outputs:**
*   A triangular mesh consisting of vertices (position, normal, color) and triangles (vertex indices) [S1].

### Data Structures

**Block Structure:**
*   The 3D space is divided into blocks. Each block contains an $8 \times 8 \times 8$ array of cubes [S1].
*   Blocks are managed via a spatial hash table to allow $O(1)$ access and lazy allocation [S1].

**Cube Structure:**
*   Each cube stores its current type $t_i \in \{0,1\}^8$ and previous type $t_{i-1} \in \{0,1\}^8$ [S1].
*   $t_i$ is an 8-bit integer where the $k$-th bit is 1 if the TSDF value at corner $k$ is below the isovalue (0), and 0 otherwise [S1].

**Vertex Structure:**
*   **Position:** 3D vector $(x, y, z)$ [S1].
*   **Normal:** 3D vector $(n_x, n_y, n_z)$ [S1].
*   **Color:** Reserved space (implementation dependent) [S1].
*   **Reference Count:** Integer indicating the number of triangles referencing this vertex [S1].
*   **Allocation:** Vertices are stored on the memory heap and allocated lazily upon first use [S1].

**Triangle Structure:**
*   **Indices:** 3 pointers/indices referencing the vertex structure [S1].
*   **Storage:** Edges and triangles within a cube are stored in pointer arrays of size 3 and 5 respectively, with pointed data managed on the heap [S1]. Optimization allows saving only 1 pointer each for edges and triangles, with arrays dynamically managed on the heap [S1].

### Parameters
*   **$\lambda$ (Ray Length Parameter):** Range $[1 - \delta, 1 + \delta]$ around the scanned point to determine which blocks to process [S1].
*   **$\epsilon$ (Epsilon):** A preset threshold proportional to cube size, used to determine if TSDF values at corners are close to zero (disturbed) [S1].
*   **$t_{r1 \dots 6}$ (Regular Cube Types):** A set of 6 predefined 8-bit vectors representing regular triangle shapes: $\{11001100, 00110011, 10011001, 01100110, 11110000, 00001111\}$ [S1].
*   **Hamming Distance Threshold:** 3. Used to discriminate between valid transitions and disturbances [S1].
*   **Block Size:** $8 \times 8 \times 8$ cubes [S1].
*   **Cube Resolution:** Varies from 8mm (fine-grained) to 3cm (global SLAM) [S1].

### Algorithm Steps

1.  **Block Collection:**
    For each valid pixel $p$ in the depth image $D_i$, form a ray:
    $$ ^w r = ^w_s T_i^{-1} \tilde{p} + \lambda \cdot ^w_s T_i^{-1} \begin{bmatrix} D_i(p) K^{-1} \tilde{p} \\ 0 \end{bmatrix} $$
    where $\tilde{p}$ is the 3D homogeneous coordinate of the pixel [S1]. Collect all blocks intersected by rays where $\lambda \in [1 - \delta, 1 + \delta]$. Allocate blocks if not already present in the hash table [S1].

2.  **TSDF Integration (Data Fusion):**
    For every cube $c$ in the gathered blocks, project its 8 corners to the depth image to find the closest scanned point. Compute the truncated distance $\tilde{d}_i(c)$:
    $$ \tilde{d}_i(c) = \phi(D_i(K \cdot ^w_s T_i c) - (^w_s T_i c)_z) $$
    where $\phi(\cdot)$ is the truncation function and $(_z)$ denotes the z-component in the camera coordinate system [S1]. Integrate $\tilde{d}_i(c)$ into the stored TSDF volume $d(c)$ using standard TSDF fusion techniques [S1].

3.  **Cube Type Determination:**
    For each cube $c$, determine the current cube type $t_i$ by comparing the TSDF value $d(c_k)$ at each corner $k$ against the isovalue (0). If $d(c_k) < 0$, the $k$-th bit of $t_i$ is 1; otherwise, it is 0 [S1]. If a neighbor cube providing a shared corner is not in the same block, perform an $O(1)$ spatial hash table lookup to retrieve its TSDF values [S1]. Store $t_i$ alongside the previous type $t_{i-1}$ [S1].

4.  **Mesh Refinement (Disturbance Detection):**
    Check if the transition from $t_{i-1}$ to $t_i$ represents a disturbance (irregular triangle flip) using Hamming distance [S1]. If the following conditions are met for some $j \in \{1 \dots 6\}$:
    $$ d_H(t_i, t_{i-1}) \le 3 $$
    $$ d_H(t_i, t_{rj}) \le 3 $$
    $$ |d(c_k)| < \epsilon, \quad \forall k \text{ such that } t_{i,k} \oplus t_{rj,k} = 1 $$
    then assume a disturbance occurred at corner $k$. Replace $t_i$ with the regular type $t_{rj}$ before proceeding to Marching Cubes [S1]. Here, $d_H$ is the Hamming distance, $\oplus$ is XOR, and $\epsilon$ is the threshold [S1].

5.  **Triangulation Optimization:**
    Compare $t_i$ with $t_{i-1}$. If $t_i = t_{i-1}$, keep the existing list of triangles and vertices for this cube unchanged (temporal consistency) [S1]. If they differ, clear the previous triangles and prepare to create new ones [S1].

6.  **Vertex Initialization and Update:**
    Using the Marching Cubes lookup table $T: \{0,1\}^8 \rightarrow \{0,1\}^{12}$, identify edges with indicator bit 1 [S1]. For each such edge, compute the vertex position via linear interpolation of the endpoints' positions based on the TSDF values [S1].
    *   **Lock-based Vertex Sharing:** To handle parallel vertex creation on GPUs, use atomic operations. Only the first thread to atomically acquire a vertex allocates and assigns it. Other threads use the pre-determined interpolation ratio from the data fusion stage to retrieve the existing vertex [S1].
    *   **Lazy Initialization:** Vertices are initialized only when first used; otherwise, an update is sufficient [S1].

7.  **Triangle Creation:**
    Create triangles based on the updated cube type $t_i$ (or $t_{rj}$ if refined). Each triangle consists of 3 vertices. For each new triangle, increment the reference count of its 3 vertices by 1 [S1].

8.  **Garbage Collection:**
    When a triangle is destroyed (due to $t_i \neq t_{i-1}$), decrement the reference count of its 3 vertices by 1 [S1]. If a vertex's reference count reaches 0, mark it as garbage and recycle it (free memory or add to a free list) [S1].

### Pseudocode

```python
# Constants
BLOCK_SIZE = 8
ISOSURFACE_VALUE = 0.0
HAMMING_THRESHOLD = 3
REGULAR_TYPES = [
    0b11001100, 0b00110011, 0b10011001, 
    0b01100110, 0b11110000, 0b00001111
]

def process_frame(depth_image, sensor_pose, intrinsic_matrix, tsdf_volume, hash_grid):
    """
    Main pipeline for one frame.
    """
    # Step 1: Block Collection
    blocks_to_process = set()
    for pixel in valid_pixels(depth_image):
        ray = compute_ray(pixel, sensor_pose, intrinsic_matrix, depth_image[pixel])
        # Determine blocks intersected by ray within lambda range
        blocks = get_blocks_intersected_by_ray(ray, lambda_min=1-delta, lambda_max=1+delta)
        blocks_to_process.update(blocks)
        
        # Allocate if not present
        for b in blocks:
            if b not in hash_grid:
                hash_grid[b] = allocate_block(BLOCK_SIZE)

    # Step 2 & 3: TSDF Integration and Cube Type Determination
    for block in blocks_to_process:
        for cube in block.cubes:
            # Project corners to depth image and compute truncated distance
            truncated_distances = []
            for corner in cube.corners:
                cam_pos = transform_to_camera(corner, sensor_pose)
                depth_val = get_depth_at_pixel(cam_pos, depth_image, intrinsic_matrix)
                trunc_dist = truncate_distance(depth_val, cam_pos.z)
                truncated_distances.append(trunc_dist)
            
            # Integrate into TSDF volume (details in [3], simplified here)
            integrate_tsdf(cube, truncated_distances, tsdf_volume)
            
            # Determine cube type t_i
            t_i = 0
            for k, dist in enumerate(truncated_distances):
                if dist < ISOSURFACE_VALUE:
                    t_i |= (1 << k)
            
            cube.t_prev = cube.t_curr
            cube.t_curr = t_i

    # Step 4, 5, 6, 7, 8: Mesh Generation
    for block in blocks_to_process:
        # Lock-based approach: Use atomic operations for vertex sharing
        for cube in block.cubes:
            t_curr = cube.t_curr
            t_prev = cube.t_prev
            
            # Step 4: Mesh Refinement
            refined_type = t_curr
            if is_disturbance(t_curr, t_prev, cube.tsdf_corners, epsilon):
                refined_type = find_closest_regular_type(t_curr, t_prev)
            
            # Step 5: Triangulation Optimization
            if t_curr == t_prev:
                continue # Keep existing triangles
            
            # Clear old triangles and update reference counts
            for tri in cube.triangles:
                for v_idx in tri.vertices:
                    vertex = get_vertex(v_idx)
                    vertex.ref_count -= 1
                    if vertex.ref_count == 0:
                        recycle_vertex(vertex)
            cube.triangles.clear()
            
            # Step 6 & 7: Vertex Initialization and Triangle Creation
            # Get MC table entries for refined_type
            mc_edges = marching_cubes_table[refined_type]
            
            for edge in mc_edges:
                # Linear interpolation to find vertex position
                v_pos = interpolate_vertex(edge, cube.tsdf_corners)
                v_normal = compute_normal(edge, cube.tsdf_corners)
                
                # Atomic vertex sharing
                vertex = get_or_create_vertex(v_pos, v_normal)
                vertex.ref_count += 1 # Increment for this triangle usage
                
                # Store vertex index
                edge_vertex_indices.append(vertex.index)
            
            # Create triangles from edge vertices
            # MC table defines which edges form triangles
            triangles = generate_triangles_from_edges(edge_vertex_indices, refined_type)
            cube.triangles.extend(triangles)

def is_disturbance(t_curr, t_prev, tsdf_corners, epsilon):
    """
    Check if the cube type change is a disturbance.
    """
    for trj in REGULAR_TYPES:
        if hamming_distance(t_curr, t_prev) <= HAMMING_THRESHOLD:
            if hamming_distance(t_curr, trj) <= HAMMING_THRESHOLD:
                # Check if TSDF values at differing bits are close to zero
                disturbance = True
                for k in range(8):
                    if (t_curr[k] ^ trj[k]) == 1:
                        if abs(tsdf_corners[k]) >= epsilon:
                            disturbance = False
                            break
                if disturbance:
                    return True
    return False

def find_closest_regular_type(t_curr, t_prev):
    """
    Find the regular type trj that satisfies the disturbance conditions.
    """
    for trj in REGULAR_TYPES:
        if hamming_distance(t_curr, t_prev) <= HAMMING_THRESHOLD:
            if hamming_distance(t_curr, trj) <= HAMMING_THRESHOLD:
                return trj
    return t_curr

def get_or_create_vertex(position, normal):
    """
    Lock-based vertex sharing.
    """
    # Use atomic operation to check if vertex exists at this position/normal
    # If not, allocate new vertex. If yes, return existing.
    # Note: Exact atomic implementation depends on GPU/CPU architecture.
    # Here we assume a hypothetical atomic lookup.
    existing = atomic_lookup_vertex(position, normal)
    if existing is None:
        new_v = allocate_vertex(position, normal)
        atomic_store_vertex(position, normal, new_v)
        return new_v
    return existing

def hamming_distance(a, b):
    return bin(a ^ b).count('1')
```

### Edge Cases and Pitfalls
*   **Neighbor Cube Access:** If a neighbor cube providing a shared corner is not in the same block, an additional $O(1)$ spatial hash table lookup is required [S1].
*   **Parallel Vertex Sharing:** On GPU, parallel vertex determination can cause memory leaks (2-3x additional consumption) and unexpected results if sharing is not handled correctly [S1]. The lock-based solution is preferred over lock-free to avoid this [S1].
*   **Mesh Irregularities (Cracks):** Limited resolution and MC principles cause irregular triangles when planes intersect cubes at corners, leading to sign flips in TSDF and abrupt triangle changes [S1]. The disturbance detection algorithm mitigates this [S1].
*   **Precision:** The threshold $\epsilon$ must be proportional to cube size to effectively detect disturbances [S1].

## Operating characteristics

**Time and Memory Complexity:**
*   **Time:** The algorithm is designed for real-time performance. The lock-based version is preferred for its speed, as the lock-free version is 2 to 3 times slower due to group-level serial launches [S1].
*   **Memory:** The lock-free implementation causes 2 to 3 times additional memory consumption compared to the lock-based version due to memory leaks from unshared vertices [S1]. The lock-based version manages memory efficiently via reference counting and garbage collection [S1].

**Measured Performance:**
*   Implemented in C++ with CUDA 8.0 and OpenGL 3.3 [S1].
*   Tested on ICL-NUIM, TUM, and Zhou/Koltun datasets [S1].
*   Cube resolutions vary from 8mm (fine-grained) to 3cm (global SLAM) [S1].
*   The method outperforms baseline implementations in running time and memory usage when using the lock-based approach [S1].

**Strengths and Limitations:**
*   **Strengths:** Real-time capability, memory efficiency through garbage collection, robustness against mesh irregularities via disturbance detection, and parallelizability on GPU [S1].
*   **Limitations:** Performance degradation if lock-free approach is used; sensitivity to $\epsilon$ threshold; limited resolution can still cause some irregularities if disturbance detection fails [S1].

**When to Use:**
*   Real-time 3D reconstruction from depth sensors (RGB-D, LiDAR).
*   SLAM systems requiring incremental mesh generation.
*   Scenes with dynamic changes where memory efficiency is critical.

**When Not to Use:**
*   Offline high-quality meshing where memory usage is not a constraint and higher resolution is available.
*   Scenes with extremely high-frequency details that exceed the cube resolution limits, leading to frequent disturbances that the algorithm cannot correct.
