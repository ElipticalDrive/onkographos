# Sparse Chunk (Brick) Storage
Also called: Brick storage

## Overview
Sparse chunk storage replaces a dense voxel layer with a hash map of fixed-size 16³ chunks to decouple scene resolution from memory usage, storing only non-empty regions [S1, unofficial]. It differs from its parent [Adaptive Bit-Packed Voxel Array](4986-adaptive-bit-packed-voxel-array.md) by operating at a coarser granularity (chunks rather than individual voxels or small bit-packed sections) and from [Octree](5000-octree.md) by avoiding tree traversal for reads, using arithmetic addressing instead [S1, unofficial].

## How it works
**Inputs:** A voxel coordinate $p = (x, y, z)$ and a palette index $c \in [0, 255]$ (where $0$ represents empty/air) [S1, unofficial].
**Outputs:** A `VoxelGrid` structure containing a hash map of chunks [S1, unofficial].

**Data Structures:**
The grid is defined as `struct VoxelGrid { chunks: HashMap<IVec3, Chunk> }` where the key is an `IVec3` representing the chunk coordinate and the value is an enum `Chunk` [S1, unofficial]. The `Chunk` enum has two variants: `Solid(u8)`, which stores a single palette index implying all 4096 voxels in the chunk have that value, and `Dense(Box<[u8; 4096]>)`, which stores a contiguous array of 4096 bytes, one per voxel in the 16³ block [S1, unofficial]. Absence of a key from the map implies an empty chunk [S1, unofficial].

**Addressing:**
Given a global voxel coordinate $p$, the chunk coordinate $C$ and local coordinate $L$ within the chunk are calculated using bitwise operations [S1, unofficial]:
$$ C = p \gg 4 $$
$$ L = p \ \& \ 15 $$
The index within the `Dense` array is derived from $L$ using standard row-major ordering: $L_x + 16(L_y + 16L_z)$ [G].

**Invariant Maintenance:**
The storage maintains two invariants to ensure compression [S1, unofficial]:
1. If a `Dense` chunk contains only empty voxels (value $0$), it is removed from the `chunks` map [S1, unofficial].
2. If a `Dense` chunk contains only voxels of a single colour $c$, it is promoted to `Solid(c)` [S1, unofficial].

**Pseudocode:**
```python
# Constants
CHUNK_SIZE = 16
CHUNK_SIZE_SQ = 256
CHUNK_SIZE_CUBE = 4096

class IVec3:
    def __init__(self, x, y, z):
        self.x, self.y, self.z = x, y, z
    def __hash__(self): return hash((self.x, self.y, self.z))
    def __eq__(self, other): return (self.x, self.y, self.z) == (other.x, other.y, other.z)

class VoxelGrid:
    def __init__(self):
        self.chunks = {}  # HashMap<IVec3, Chunk>

    def get(self, p):
        """Retrieve voxel value at global coordinate p."""
        cx, cy, cz = p.x >> 4, p.y >> 4, p.z >> 4
        key = IVec3(cx, cy, cz)
        if key not in self.chunks:
            return 0  # Empty chunk
        chunk = self.chunks[key]
        if chunk[0] == 'Solid':
            return chunk[1]
        # chunk[0] == 'Dense'
        lx, ly, lz = p.x & 15, p.y & 15, p.z & 15
        idx = lx + CHUNK_SIZE * (ly + CHUNK_SIZE * lz)
        return chunk[1][idx]

    def set(self, p, value):
        """Set voxel value at global coordinate p."""
        cx, cy, cz = p.x >> 4, p.y >> 4, p.z >> 4
        key = IVec3(cx, cy, cz)
        lx, ly, lz = p.x & 15, p.y & 15, p.z & 15
        idx = lx + CHUNK_SIZE * (ly + CHUNK_SIZE * lz)

        if key not in self.chunks:
            if value == 0:
                return
            data = [0] * CHUNK_SIZE_CUBE
            data[idx] = value
            self.chunks[key] = ('Dense', data)
            return

        chunk = self.chunks[key]
        if chunk[0] == 'Solid':
            # Demote to Dense before modifying
            data = [chunk[1]] * CHUNK_SIZE_CUBE
            data[idx] = value
            self.chunks[key] = ('Dense', data)
            return

        # chunk[0] == 'Dense'
        chunk[1][idx] = value
        # Check uniformity for promotion
        first = chunk[1][0]
        if all(v == first for v in chunk[1]):
            self.chunks[key] = ('Solid', first)

    def fill_box(self, min_p, max_p, value):
        """Bulk fill a box region. Optimized to avoid materializing all cells."""
        if value == 0:
            return
        min_c = IVec3(min_p.x >> 4, min_p.y >> 4, min_p.z >> 4)
        max_c = IVec3(max_p.x >> 4, max_p.y >> 4, max_p.z >> 4)
        for cx in range(min_c.x, max_c.x + 1):
            for cy in range(min_c.y, max_c.y + 1):
                for cz in range(min_c.z, max_c.z + 1):
                    key = IVec3(cx, cy, cz)
                    # Check if chunk is fully inside box
                    c_min = IVec3(cx * 16, cy * 16, cz * 16)
                    c_max = IVec3((cx + 1) * 16 - 1, (cy + 1) * 16 - 1, (cz + 1) * 16 - 1)
                    if c_min.x >= min_p.x and c_max.x <= max_p.x and \
                       c_min.y >= min_p.y and c_max.y <= max_p.y and \
                       c_min.z >= min_p.z and c_max.z <= max_p.z:
                        self.chunks[key] = ('Solid', value)
                    else:
                        # Boundary chunk: materialize and fill intersecting voxels
                        if key not in self.chunks:
                            self.chunks[key] = ('Dense', [0] * CHUNK_SIZE_CUBE)
                        chunk = self.chunks[key]
                        if chunk[0] == 'Solid':
                            data = [chunk[1]] * CHUNK_SIZE_CUBE
                            self.chunks[key] = ('Dense', data)
                            chunk = self.chunks[key]
                        for lx in range(16):
                            for ly in range(16):
                                for lz in range(16):
                                    gx, gy, gz = cx * 16 + lx, cy * 16 + ly, cz * 16 + lz
                                    if min_p.x <= gx <= max_p.x and min_p.y <= gy <= max_p.y and min_p.z <= gz <= max_p.z:
                                        idx = lx + CHUNK_SIZE * (ly + CHUNK_SIZE * lz)
                                        chunk[1][idx] = value
```

**Meshing Optimization:**
The method uses chunk-level dirty tracking [S1, unofficial]. When a chunk is edited, the mesh is rebuilt for that chunk and its six immediate spatial neighbours [S1, unofficial]. Empty chunks are skipped during extraction [S1, unofficial]. Solid chunks have their interior faces dropped entirely, exposing only the boundary faces adjacent to non-solid chunks [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Non-aligned Translation:** Moving an object by a coordinate not a multiple of 16 requires touching every chunk in the object's grid, as rekeying the hash map is insufficient for misaligned offsets [S1, unofficial].
*   **Stale Solid Chunks:** A `Solid` chunk is a lazy representation of a uniform colour [S1, unofficial]. If any voxel in a `Solid` chunk is edited, it must be demoted to `Dense` immediately to avoid reading the wrong colour everywhere in that chunk [S1, unofficial].
*   **Empty Chunk Removal:** Removing a voxel that makes a chunk empty must trigger the removal of the key from the hash map to maintain the sparsity invariant [S1, unofficial].

## Operating characteristics
**Time Complexity:**
*   **Read/Write:** $O(1)$ average case for hash map lookup and arithmetic addressing, avoiding tree traversal required by octrees [S1, unofficial].
*   **Meshing:** $O(1)$ per dirty chunk; rebuilding a screenshot with one dirty chunk takes 13 ms, compared to 236 ms for full extraction on a 256³ scene [S1, unofficial].
*   **Bulk Fill:** $O(N_{boundary})$ where $N_{boundary}$ is the number of voxels on the surface of the filled box, rather than $O(N_{total})$ [S1, unofficial]. A full 256³ fill takes 486 ms [S1, unofficial].

**Memory Complexity:**
*   Scales with the number of non-empty chunks, not the total volume resolution [S1, unofficial].
*   **Dense Chunk Size:** 4 KB (4096 bytes) per chunk [S1, unofficial].
*   **Overhead:** Hash map overhead per chunk [S1, unofficial].
*   **Measured Performance:** A terrain slab (256×5×256, 327,680 voxels) uses 35 MB RSS with a 1.0× allocation ratio [S1, unofficial]. A character (32³ scene, 1,088 voxels) uses 29 MB RSS with a 1.0× allocation ratio [S1, unofficial]. 256 scattered specks use 456 MB RSS with a 65,536× allocation ratio (16,777,216 allocated cells) [S1, unofficial].
*   **Limitations:** Performance degrades significantly when content is sparse and scattered across a large volume, as each speck may occupy its own chunk, leading to high hash map overhead and memory fragmentation [S1, unofficial].

**When to Use:**
*   Scenes with large uniform interiors (captured by `Solid` chunks) [S1, unofficial].
*   Scenes with sparse shells or surfaces where most of the bounding box is empty [S1, unofficial].
*   When resolution needs to be decoupled from memory usage [S1, unofficial].

**When Not to Use:**
*   Compact, dense content where the parent [Adaptive Bit-Packed Voxel Array](4986-adaptive-bit-packed-voxel-array.md) is already optimal (1.0× ratio) [S1, unofficial].
*   Scenes with highly scattered, non-uniform data across a large volume, leading to high memory overhead [S1, unofficial].
*   Applications requiring frequent non-aligned translations of objects [S1, unofficial].

## Background
The sparse chunk storage method was proposed by fpt on September 7, 2026, in Issue #18 of the `rs-voxeler` repository [S1, unofficial]. It was designed to address the limitations of dense layer boxes, which allocate memory for the entire bounding box even if hollow, and the complexity of octrees, which require tree traversal and split/merge operations on every brush stroke crossing a node boundary [S1, unofficial]. The proposal suggested a two-level adaptivity: chunks for spatial sparsity and the existing adaptive bit-packing within dense chunks for data density [S1, unofficial]. While the storage swap was gated due to performance measurements showing no benefit for compact content, the chunk-level dirty tracking optimization was implemented in PR #27 [S1, unofficial].
