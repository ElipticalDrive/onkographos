# Volumetric Triangle Representation with Spatial Hashing

Also called: Cube-based mesh representation, Spatial-hashed cube field

## Overview
Volumetric Triangle Representation with Spatial Hashing is a compact data structure that embeds mesh vertices directly into a volumetric grid using spatial hashing, eliminating vertex redundancies by binding continuous vertex positions to discrete voxel edges [S1]. It solves the problem of memory inefficiency and topological inconsistency in real-time dense reconstruction by maintaining both TSDF values and triangle connectivity at the fine cube scale, rather than managing triangles coarsely at the block level [S1]. Unlike standard Marching Cubes implementations that may allocate duplicate vertices, this method enforces a one-to-one correspondence between voxel edges and mesh vertices, enabling $O(1)$ vertex access and preventing memory leaks during parallel execution [S1].

## How it works
**Inputs:** Depth images from a sensor (e.g., Kinect) with known poses; initial empty spatial hash structure.
**Outputs:** A watertight triangular mesh formatted for traditional rendering.

**Data Structures:**
The structure uses a 2-level spatial management system [S1]:
1.  **Block Level:** Space is divided into large blocks allocated only around object surfaces. These blocks are managed by a hash table. This constrains the hash table size and reduces collision probability [S1].
2.  **Cube Level:** Each block is divided into an array of small cubes (typically $8 \times 8 \times 8$) [S1].
    *   **Cube Layout:** To handle overlap between adjacent cubes, each cube stores only:
        *   1 corner vertex $c = (x_0, y_0, z_0)$ [S1].
        *   3 edge vectors starting from $c$: $e_x = (l, 0, 0)$, $e_y = (0, l, 0)$, $e_z = (0, 0, l)$, where $l$ is the cube side length [S1].
        *   TSDF value $d(c)$ stored at corner $c$ [S1].
        *   Up to 5 triangles connecting vertices on the edges [S1].
        *   Cube type (from Marching Cubes lookup table) indicating the number and shape of triangles [S1].
    *   **Vertex Storage:** Vertices $v_x, v_y, v_z$ are stored on the respective edges $e_x, e_y, e_z$. The position is continuous but bound to the discrete edge coordinate [S1].
    *   **Memory Layout:** Edges and triangles are stored in pointer arrays of size 3 and 5, respectively. The pointed data (vertex coordinates, triangle indices) are managed on the memory heap [S1].

**Algorithm Steps:**
1.  **Data Fusion:** For each incoming depth image, fuse the data into the volumetric cube field. This involves updating the TSDF distribution $d(c)$ at the corner of each affected cube [S1].
2.  **Mesh Generation/Update:** Perform local mesh generation or update based on the updated TSDF values using Marching Cubes (MC) [S1].
    *   Determine the cube type based on the sign of $d(c)$ at the corner and neighbors.
    *   Calculate vertex positions on edges $e_x, e_y, e_z$ where the TSDF crosses zero.
    *   Generate triangles connecting these vertices according to the MC configuration [S1].
3.  **Vertex Binding:** Bind the calculated continuous vertex positions to the discrete edges. Since each edge is shared by adjacent cubes, the vertex is stored once and referenced by all cubes sharing that edge [S1].
4.  **Garbage Collection:** Manage the lifecycle of mesh primitives (vertices and triangles) via reference counting to maintain memory efficiency in dynamic scenes [S1]. Remove primitives that are no longer referenced [S1].
5.  **Rendering:** Reformat the mesh data into a standard triangle buffer for traditional rendering [S1].

**Pseudocode:**
```python
# Data Structures
class Cube:
    corner: Vector3  # c = (x0, y0, z0)
    tsdf: float      # d(c)
    edges: List[Edge] # Size 3, pointers to heap-allocated Edge objects
    triangles: List[Triangle] # Size up to 5, pointers to heap-allocated Triangle objects
    cube_type: int   # MC configuration index

class Edge:
    start: Vector3   # Vertex position on the edge
    direction: Vector3 # e_x, e_y, or e_z
    length: float    # l

class Triangle:
    vertices: List[Vector3] # 3 vertices

# Spatial Hash Table
hash_table: Dict[BlockKey, List[Cube]]

def fuse_depth_image(depth_image, pose):
    """Update TSDF values in affected cubes."""
    for each voxel in depth_image:
        world_pos = transform(depth_pos, pose)
        block_key = get_block_key(world_pos)
        cube = get_cube_in_block(block_key, world_pos)
        if cube:
            update_tsdf(cube.corner, depth_value)

def update_mesh(cube: Cube):
    """Generate or update triangles for a cube based on TSDF."""
    # Determine cube type based on TSDF signs at corner and neighbors
    cube_type = compute_marching_cubes_type(cube, get_neighbors(cube))
    
    # Clear old triangles if type changed or update in place
    if cube.cube_type != cube_type:
        clear_triangles(cube)
        cube.cube_type = cube_type
    
    # Calculate vertex positions on edges
    # Vertices are bound to edges, ensuring one-to-one correspondence
    vx = interpolate_vertex_on_edge(cube.edges[0], cube.tsdf, get_neighbor_tsdf(cube, 0))
    vy = interpolate_vertex_on_edge(cube.edges[1], cube.tsdf, get_neighbor_tsdf(cube, 1))
    vz = interpolate_vertex_on_edge(cube.edges[2], cube.tsdf, get_neighbor_tsdf(cube, 2))
    
    # Generate triangles based on cube_type
    triangles = generate_triangles_from_mc(cube_type, vx, vy, vz)
    
    # Add triangles to cube, handling reference counting for vertices
    for tri in triangles:
        add_triangle_to_cube(cube, tri)

def get_cube_in_block(block_key, pos):
    """O(1) access via hash table and local indexing."""
    block = hash_table.get(block_key)
    if not block:
        return None
    local_idx = get_local_cube_index(pos)
    return block[local_idx]

def garbage_collect():
    """Remove unreferenced vertices and triangles."""
    for cube in all_cubes:
        for tri in cube.triangles:
            decrement_reference_count(tri.vertices)
    for edge in all_edges:
        if edge.reference_count == 0:
            free_heap_memory(edge)
```

**Parameters:**
*   **Cube Resolution:** 8mm (used in experiments for scene 'burghers') [S1].
*   **Block Subdivision:** Blocks are divided into cubes, typically $8 \times 8 \times 8$ [S1].

**Edge Cases and Pitfalls:**
*   **Memory Redundancy:** Loose mesh storage strategies prone to duplicate vertex allocation. This method forbids this by using one-to-one correspondence between voxel edges and mesh vertices [S1].
*   **Topological Irregularities:** Limited resolution can cause topological issues. A disturbance detection algorithm is used to correct these [S1].
*   **Parallel Execution:** Lock-based vertex sharing mechanism is required to prevent memory leaks during parallel execution [S1].

## Subtopics

### [Volumetric Mesh Generation with Spatial Hashing](14155-volumetric-mesh-generation-with-spatial-hashing.md)
This method generates a watertight triangular mesh from a Truncated Signed Distance Function (TSDF) volume by integrating Marching Cubes (MC) with a spatially hashed block structure, enabling real-time incremental reconstruction on GPUs. It distinguishes itself from standard MC implementations by introducing temporal consistency checks to minimize triangle allocation, a lock-based vertex sharing mechanism to prevent memory leaks during parallel execution, and a disturbance detection algorithm to correct topological irregularities caused by limited resolution. Unlike the parent [Volumetric Triangle Representation with Spatial Hashing](13835-volumetric-triangle-representation-with-spatial-hashing.md) which focuses on compact vertex binding, this method explicitly manages the lifecycle of mesh primitives (vertices and triangles) via reference counting and garbage collection to maintain memory efficiency in dynamic scenes.

## Operating characteristics
*   **Time Complexity:** Vertex accessing is $O(1)$ via hash table visiting plus local indexing [S1].
*   **Memory Complexity:** Compact due to one-to-one vertex-edge correspondence and heap-managed primitives. Avoids memory redundancy [S1].
*   **Performance:** Used in real-time dense reconstruction for robotics, specifically for online mesh storage and manipulation [S1].
*   **Strengths:** Eliminates vertex redundancies, enables $O(1)$ vertex access, supports parallel execution with lock-based mechanisms, and maintains mesh quality via local shape regularization [S1].
*   **Limitations:** Requires careful management of reference counting and garbage collection to maintain memory efficiency in dynamic scenes [S1].
