# Voxel Caching with Cuckoo Hashing

Also called: CSGV-R Cuckoo Caching, Voxel Cache

## Overview
An optional voxel cache using Cuckoo hashing to store labels $\lambda$ for tuples of voxel coordinates $v \in \mathbb{N}^3$ and requested LODs $l$, allowing direct access without one-frame latency [S1, unofficial]. It differs from its parent [Hash Grid with Multiple Hash Functions](7678-hash-grid-with-multiple-hash-functions.md) by using a single combined table with a compact 32-bit key and specific rounding to handle multi-resolution queries, and from its sibling [Adapted Cuckoo Hashing for Voxel Labels](10183-adapted-cuckoo-hashing-for-voxel-labels.md) by its specific 4D tuple handling and PCG hash integration [S1, unofficial].

## How it works
**Inputs:** Voxel coordinates $v \in \mathbb{N}^3$ (in finest resolution), requested LOD $l$, and label $\lambda$.
**Outputs:** Hash table $M$ containing entries $(\lambda, k)$.

**Data Structures:**
*   $M$: A single array of size $|M|$ (power of two). Each slot stores a 32-bit key $k$ and a label $\lambda$.
*   The table $M$ conceptually holds two hash tables $M_1$ and $M_2$ of size $|M|/2$ each, packed contiguously.

**Hash Functions:**
The method uses the PCG family [O'N14, JO20] instead of the universal family [PR04] for 3D/4D tuples.
1.  **Base Hash $h^a(x)$:**
    $$h^a(x) = (ax \bmod 2^{32}) / 2^{32-m}$$
    where $a$ is an odd number and $m$ is the MSB of the power-of-two hash table size [S1, unofficial].
2.  **Coordinate Rounding:**
    Voxels are rounded to powers-of-two to force collisions for different LODs in the same spatial region:
    $$\mathbf{s} = \lfloor v/2^l \rfloor \cdot 2^l$$
    This ensures different LODs of a region are never accessed simultaneously [S1, unofficial].
3.  **Key Hash $h_k(\mathbf{v}, l)$:**
    Computes a 32-bit key $k$ to identify collisions. Let $\mathbf{t} = (pcg4d(\mathbf{s}, l))$ be a 4D vector hash.
    $$k = h^5(\mathbf{t}, x) \oplus h^{149}(\mathbf{t}, y) \oplus h^{61}(\mathbf{t}, z) \oplus h^{2877}(\mathbf{t}, w)$$
    where $\oplus$ is bitwise XOR [S1, unofficial].
4.  **First Position Hash $h_1(\mathbf{v}, l)$:**
    Computes the index in $M$. Let $\mathbf{s} = pcg3d(\lfloor v/2^l \rfloor \cdot 2^l)$.
    $$h_1(\mathbf{v}, l) = h^{19}(\mathbf{s}, x) \oplus h^{47}(\mathbf{s}, y) \oplus h^{101}(\mathbf{s}, z) \bmod |M|$$
    [S1, unofficial].

**Algorithm:**
*   **Lookup:** Constant time. Check $M[h_1(\mathbf{v}, l)]$ and $M[u]$ where $u$ is the alternative position.
*   **Insertion:**
    1.  Compute $p_1 = h_1(\mathbf{v}, l)$.
    2.  If $M[p_1]$ is empty, store $(\lambda, k)$ and set MSB of $k$ to 0.
    3.  If occupied by $k'$, check if $k' == k$ (collision). If so, update $\lambda$.
    4.  If occupied by different $k'$, evict $k'$. Store new $(\lambda, k)$ with MSB 0.
    5.  Move evicted $k'$ to its second position $p_2$. The alternative position is determined by $u = pcg2d(h_k(\mathbf{v}, l), h_1(\mathbf{v}, l))$ [S1, unofficial].
    6.  If $M[p_2]$ is empty, store $k'$ with MSB 1.
    7.  If occupied, recursively evict and swap until an empty slot is found, a loop depth limit is reached, or a cycle is detected [S1, unofficial].

def h_a(a, x_vec, dim):

    val = (a * x_vec[dim]) & 0xFFFFFFFF

def insert(M, v, l, lambda_val):
    # Round coordinates
    s = (v // (1 << l)) * (1 << l)
    
    # Compute key k
    t = pcg_hash_4d(s, l)
    k = (h_a(5, t, 0) ^ h_a(149, t, 1) ^ h_a(61, t, 2) ^ h_a(2877, t, 3)) & 0xFFFFFFFF
    
    # Compute first position p1
    s_3d = pcg_hash_3d(s)
    p1 = (h_a(19, s_3d, 0) ^ h_a(47, s_3d, 1) ^ h_a(101, s_3d, 2)) % len(M)
    
    # Compute alternative position p2 using key hash
    # u = pcg2d(h_k, h_1)
    p2 = pcg2d(k, p1)
    
    # Try to insert at p1
    if M[p1].key is None:
        M[p1].key = k
        M[p1].label = lambda_val
        M[p1].msb = 0
        return True
        
    if M[p1].key == k:
        M[p1].label = lambda_val
        return True
        
    # Evict from p1
    evicted_k = M[p1].key
    evicted_label = M[p1].label
    M[p1].key = k
    M[p1].label = lambda_val
    M[p1].msb = 0
    
    # Insert evicted at p2
    if M[p2].key is None:
        M[p2].key = evicted_k
        M[p2].label = evicted_label
        M[p2].msb = 1
        return True

**Edge Cases:**
*   **Cycle Detection:** If an element is inserted into a position it occupied before, stop and report failure [S1, unofficial].
*   **Loop Depth Limit:** Stop if a predetermined number of swaps is reached [S1, unofficial].
*   **Precision:** Use 32-bit arithmetic for hash components [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Lookup is constant time $O(1)$ [S1, unofficial]. Insertion is amortized constant time but can degrade with high load factors or cycles.
*   **Memory:** Single table $M$ stores label and 32-bit key per entry [S1, unofficial].
*   **Strengths:** Direct access without one-frame latency; handles multi-resolution queries via rounding [S1, unofficial].
*   **Limitations:** Requires careful handling of cycles and eviction limits; PCG hash implementation required [S1, unofficial].

## Background
Originated in CSGV-R for interactive volume rendering [S1, unofficial]. Based on Cuckoo hashing [PR04] and PCG hash functions [O'N14, JO20]. Used to cache decoded voxel labels for fast access during rendering [S1, unofficial].
