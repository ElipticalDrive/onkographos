# Adapted Cuckoo Hashing for Voxel Labels

Also called: Cuckoo hashing variant for voxel label caching

## Overview
Adapted Cuckoo Hashing for Voxel Labels is a sparse data structure method for caching voxel labels ($\lambda$) and their corresponding keys ($k$) in 4D space (voxel coordinate $\mathbf{v}$ and level of detail $l$) during volume rendering [S1]. It solves the problem of efficiently retrieving pre-computed labels for sparse visible regions while minimizing memory footprint and lookup latency [S1]. Unlike standard Cuckoo hashing which guarantees insertion via complex reorganization, this variant is adapted to handle cases where an element cannot be moved back to its first position by removing it instead, and limits ejection recursion depth to 1 to reduce thread divergence in parallel renderers [S1].

## How it works
**Inputs:** Voxel coordinate $\mathbf{v}$ (in finest LOD), accessed level of detail $l$, label $\lambda$ [S1].
**Outputs:** Cached label $\lambda$ or a cache miss indicating the label must be decoded [S1].
**Data Structures:**
*   Hash Table $M$: An array of slots. Each slot stores a tuple $(k, \lambda)$ [S1].
    *   $k$: Integer key. The Most Significant Bit (MSB) indicates position: 0 for first position, 1 for second position [S1].
    *   $\lambda$: The voxel label [S1].
    *   Size $|M|$: Not given in the sources.
*   Hash Functions:
    *   $h_k(\mathbf{v}, l)$: Computes the primary key [S1].
    *   $h_1(\mathbf{v}, l)$: Computes the first table index [S1].
    *   $\tilde{h}_2(k, p)$: Computes the second table index given a key and first position [S1].
    *   $\text{pcg*2*d}(k, p)$: A 2D pseudo-random number generator producing a 4D vector $\mathbf{u}$ from key $k$ and position $p$ [S1].
    *   $\text{pcg4d}(\mathbf{v}_{\text{coarse}}, l)$: A 4D PCG producing a 4D vector $\mathbf{t}$ from coarse voxel and LOD [S1].
    *   $h^n(\mathbf{x}, c)$: A hash function component using constant $n$ applied to vector $\mathbf{x}$ and component $c$ [S1].

**Formulas:**
The key $k$ is computed as:
$$k = h_k(\mathbf{v}, l) = h^5(\mathbf{t}, x) \oplus h^{149}(\mathbf{t}, y) \oplus h^{61}(\mathbf{t}, z) \oplus h^{2877}(\mathbf{t}, w)$$
where $\mathbf{t} = \text{pcg4d}(\lfloor \mathbf{v}/2^l \rfloor \cdot 2^l, l)$ is a 4D vector derived from the coarse voxel coordinate and LOD [S1]. The MSB of $k$ tracks the position: 0 for first, 1 for second [S1].

The alternative position is determined by:
$$\tilde{h}_2(\mathbf{v}, l) = h^7(\mathbf{u}.x) \oplus h^{31}(\mathbf{u}.y) \oplus h^{97}(\mathbf{u}.x) \oplus h^{173}(\mathbf{u}.y) \bmod |M|$$
where $\mathbf{u} = \text{pcg*2*d}(h_k(\mathbf{v}, l), h_1(\mathbf{v}, l))$ [S1]. The source notes typos in the variable names for $\mathbf{u}$, but defines it structurally as a function of the key and first position [S1]. For ejection, the position is computed as $p' = \tilde{h}_2(k', p)$ using $\mathbf{u} = \text{pcg*2*d}(k', p)$ [S1].

**Pseudocode:**
```python
def lookup(v, l, M, h1, hk, h2):
    p1 = h1(v, l)
    k = hk(v, l) & 0x7FFFFFFF  # Clear MSB [S1]
    k1, lambda1 = M[p1]
    if k1 == k:
        return lambda1
    p2 = h2(k, p1)  # Compute second position [S1]
    k2, lambda2 = M[p2]
    if k2 == (k | 0x80000000):  # Check with MSB set [S1]
        return lambda2
    return None  # Cache miss [S1]

def insert(v, l, k, lambda_val, M, h1, h2):
    p1 = h1(v, l)
    k1, lambda1 = M[p1]
    M[p1] = (k, lambda_val)  # Insert, possibly overwriting [S1]
    if k1 is not None and (k1 & 0x80000000) == 0:  # Ejected element at first position [S1]
        p_prime = h2(k1, p1)
        k1_prime = k1 | 0x80000000  # Set MSB to 1 [S1]
        M[p_prime] = (k1_prime, lambda1)  # Insert at second position [S1]
        # If M[p_prime] was occupied, the new element is discarded due to depth limit 1 [S1]
    return lambda_val
```

**Parameters:**
*   Ejection recursion depth: Limited to 1 [S1].

**Pitfalls:**
*   If an ejected element $(\lambda', k')$ is already at its second position $p$ (MSB of $k'$ is 1), it cannot be moved back to its first position because the input parameters for $h_1$ are not available for the alternative hash calculation in this context [S1]. In this case, the element is removed from the hash table entirely [S1]. It will be reinserted later when the renderer accesses the associated voxel again, causing a cache miss [S1].
*   If the insertion at the second position $p'$ also ejects an element, the adaptation does not recurse further (depth limit 1), potentially leading to removal of the newly inserted element if it hits the same pitfall [S1].

## Subtopics

### [Empty Space Caching with Bit Vector E](10189-empty-space-caching-with-bit-vector-e.md)
A fine-granular optimization that uses a compact bit vector $E$ to skip hash table lookups for blocks of invisible voxels, reducing memory pressure and lookup latency compared to storing all invisible voxels in $M$.

## Operating characteristics
*   **Time Complexity:** Lookup is $O(1)$ with at most 2 memory accesses to $M$ [S1]. Insertion is $O(1)$ with at most one ejection step [S1].
*   **Memory Complexity:** $O(|M|)$ where $|M|$ is the number of slots in the hash table [S1].
*   **Performance:** Constant-time lookups support real-time rendering [S1]. Limiting ejection depth reduces thread divergence in GPU implementations [S1].
*   **Strengths:** Constant-time lookup and reduced thread divergence compared to full Cuckoo hashing [S1].
*   **Limitations:** Higher miss rate than standard Cuckoo hashing due to element removal when collision chains cannot be resolved within the depth limit [S1].

## Background
The method originates from the paper "Random Access Segmentation Volume Compression for Interactive Volume Rendering" [S1]. It is designed for interactive volume rendering to cache voxel labels used for visibility determination and transfer function application [S1]. The adaptation of Cuckoo hashing is specifically tailored for GPU rendering constraints, such as thread divergence and the need for constant-time operations [S1].
