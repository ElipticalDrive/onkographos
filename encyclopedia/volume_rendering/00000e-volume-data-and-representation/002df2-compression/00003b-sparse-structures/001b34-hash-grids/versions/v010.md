# Hash Grids

Also called: Coordinate Hashing, Vertex Hashing for Voxel Grid

## Overview
Hash Grids map 3D spatial coordinates to a compact, sparse data structure to enable efficient storage and retrieval of volumetric features or geometry. Unlike dense voxel grids, which waste memory on empty space, Hash Grids use a hash function to map non-empty cells to a linear array, achieving constant-time access with minimal memory overhead [S1][S2, unofficial]. This method is distinct from tree-based structures (like Octrees) by avoiding pointer overhead and traversal costs, and from brick maps by using a flat array with displacement compression or modular hashing [S1][S2, unofficial]. It is primarily used in real-time ray tracing and neural rendering to accelerate lookups for sparse scenes or feature embeddings [S1][S5, unofficial].

## How it works
Hash Grids generally fall into two implementation categories based on the hashing strategy: **Perfect Hashing via Row Displacement** (for static, pre-computed grids) and **Modular Multiplicative Hashing** (for dynamic or neural rendering grids).

### Inputs and Outputs
*   **Inputs:** 3D coordinates $(x, y, z)$, grid dimensions $(M_x, M_y, M_z)$, and optionally a hash table size $T$ or number of non-empty cells $N_{nz}$.
*   **Outputs:** A bucket index in the hash table $H$, or a feature value stored at that index.

### Data Structures

#### 1. Perfect Hashing (Static Sparse Matrix)
Used for static geometry where the set of occupied cells is known beforehand. It uses four static arrays [S1][S2, unofficial]:
*   **Array L:** 1D array of machine words containing indexes of all cell items (features/geometry).
*   **Array H:** Linearized and hashed 3D array of machine word indexes into L. The item list size for cell $i$ is $H[i] - H[i+1]$.
*   **Array O:** Offset table, a linearized 2D array of machine word indexes into H. Size is $M_y \times M_z$.
*   **Array D:** Domain bits, a bit array of size $N = M_x \times M_y \times M_z$. $D[d(x,y,z)] = 1$ if the cell is non-empty, $0$ otherwise.

#### 2. Modular Hashing (Dynamic/Neural)
Used for dynamic updates or neural feature grids (e.g., Instant NGP).
*   **Hash Table:** A 1D array of size $T = 2^{\text{log2\_hashmap\_size}}$.
*   **Coordinates:** Input tensor of shape $(N, D)$, where $D \le 7$ [S5, unofficial].

### Algorithm: Perfect Hash Construction (Row Displacement)
This algorithm computes a collision-free hash function for a static sparse 3D matrix [S1][S2, unofficial].

1.  **Compute Bounding Box:** Determine the scene's bounding box.
2.  **Determine Dimensions:** Calculate grid dimensions $M_x, M_y, M_z$ using a grid heuristic [S2, unofficial].
3.  **Initialize Domain Bits:** Allocate Array $D$ of size $N = M_x M_y M_z$. Initialize all bits to 0.
4.  **Mark Occupied Cells:** For each item (e.g., triangle or voxel) in the scene:
    *   Determine which grid cells its bounding box intersects.
    *   For each intersected cell $(x, y, z)$, set $D[d(x, y, z)] = 1$.
    *   The 1D index is calculated as:
        $$d(x, y, z) = ((M_y \times z) + y) \times M_x) + x$$
5.  **Allocate Offset Table:** Allocate Array $O$ of size $M_y \times M_z$.
6.  **Allocate Temporary Buffer:** Allocate a temporary bit array $bH$ of size $2 \times N_{nz}$ (where $N_{nz}$ is the count of non-empty cells), initialized to 0.
7.  **Compute Offsets (Row Displacement):**
    *   For each row $(y, z)$ in the grid:
        *   Find the smallest offset $O[y, z]$ starting from the previous row's offset.
        *   Check for collisions in the hash table $H$ for the cells in this row (indices $d(0, y, z)$ to $d(M_x-1, y, z)$).
        *   If a collision occurs (bit in $bH$ is set), increment the offset and re-check.
        *   Once a collision-free offset is found, mark the corresponding positions in $bH$ as used.
8.  **Populate Hash Table:** Copy non-zero elements from the sparse matrix $C$ to $H$ using the computed offsets. The hash function is $h(i, j) = O[i] + j$ [S1].

### Algorithm: Modular Hashing (Dynamic/Neural)
This method hashes coordinates to a bucket index using a multiplicative hash with prime constants [S4, S5, unofficial].

1.  **Define Primes:** Use a pre-defined array of prime numbers for each dimension.
    ```python
    primes = [1, 2654435761, 805459861, 3674653429, 2097192037, 1434869437, 2165219737]
    ```
2.  **Hash Function:**
    For a coordinate vector $\mathbf{p} = (p_0, p_1, \dots, p_{D-1})$ and hash table size $T = 2^{\text{log2\_hashmap\_size}}$:
    ```python
    def hash(coords, log2_hashmap_size):
        # coords: tensor of shape (N, D)
        # log2_hashmap_size: integer
        T = 1 << log2_hashmap_size
        # Example for 3D:
        # hash_val = ((coords[:, 0] * primes[1]) ^ 
        #             (coords[:, 1] * primes[2]) ^ 
        #             (coords[:, 2] * primes[3])) % T
        # Note: The exact folding logic (XOR vs Sum) and modulo operation 
        # must be implemented. Sources indicate XOR folding with primes [S4, S5, unofficial].
        pass
    ```
    *   **Formula:** A common implementation is:
        $$h(\mathbf{p}) = \left( \bigoplus_{i=0}^{D-1} (p_i \times \text{primes}[i+1]) \right) \pmod T$$
        Where $\oplus$ is bitwise XOR [S4, S5, unofficial].

### Parameters
*   **Grid Dimensions ($M_x, M_y, M_z$):** Determined by scene bounding box and desired resolution [S2, unofficial].
*   **Hash Table Size ($T$):** For modular hashing, $T = 2^{\text{log2\_hashmap\_size}}$. Typical values for neural rendering are $2^{18}$ to $2^{24}$ [S5, unofficial].
*   **Primes:** Large prime numbers to ensure uniform distribution [S4, S5, unofficial].

### Edge Cases and Pitfalls
*   **Hash Collisions (Modular):** In modular hashing, different coordinates may map to the same bucket. This causes feature interference. Mitigation strategies include using larger hash tables, multiple hash levels (Multi-Level Hashed Grids), or hash fusion techniques [S1, S8].
*   **Hash Collisions (Perfect):** Row displacement guarantees no collisions for the *static* set of occupied cells. If new cells are added, the hash function is invalid and must be recomputed [S1].
*   **Memory Leaks:** In implementations using chaining (e.g., Integer Hash Map with Chaining), failure to call the destructor leads to memory leaks [S6, unofficial].
*   **Inverse Mapping:** Standard hash functions are unidirectional ($n \to \theta$). Retrieving original indices ($\theta \to n$) requires storing a reverse map, which consumes significant memory (e.g., 5 GB for large voxel sets) [S8].

## Subtopics

### [Hash Grid Loss](2093-hash-grid-loss.md)
A compression-oriented regularization term that minimizes the bit consumption of binary hash grids during encoding. It optimizes the statistical distribution of hash grid values to encourage a concentrated grid structure, yielding higher compression ratios at the cost of reconstruction fidelity.

### [Dual Point Map Insertion with Linear Probing](3043-dual-point-map-insertion-with-linear-probing.md)
Stores dual points in a hash table using linear probing to handle collisions. It maps unique point identifiers to 3D positions via a combined 64-bit key-value pair, building on the hashing strategy of Hash Grids by hashing vertex positions to bucket indices.

### [Multi-Level Hashed Grid Construction](3402-multi-level-hashed-grid-construction.md)
Combines the render-time performance of multi-level grids with the low memory footprint of hashed grids. It adds macrocells to skip empty regions during traversal, solving the high memory consumption of classic multi-level array grids and the poor traversal performance of one-level hashed grids for large, sparse scanned scenes.

### [Universal Hash Optimization](3456-universal-hash-optimization.md)
Mitigates hash collisions in Sparse Voxel Octree (SVO) structures by replacing deterministic hashing with a randomized universal hash function. This ensures distinct non-isomorphic nodes are distributed uniformly across hash table buckets, reducing the average number of equality checks required during lookups.

### SpatialHash3D
A spatial index structure using a uniform 3D hash grid for efficient nearest-neighbor and radius-based queries on static datasets. It provides O(1) cell lookup with low implementation complexity, distinguished from KD-trees or Octrees by its simplicity and predictable performance for static data [S1].

### [3D Coordinate Packing](5755-3d-coordinate-packing.md)
Encodes 3D spatial coordinates into a single integer key to serve as an index in hash maps. Unlike general-purpose hash functions, it preserves spatial locality through bit-shifting, allowing deterministic reconstruction of coordinates from the key.

### [Hash Grid with Multiple Hash Functions](7678-hash-grid-with-multiple-hash-functions.md)
Extends the standard Hash Grid by assigning a distinct hash function to each leaf node in the spatial hierarchy. This reduces hash collisions caused by feature vector interference, ensuring geometrically distinct regions maintain independent feature spaces.

### Integer Hash Map with Chaining
A hash table implementation for integer keys using open addressing via chaining. It supports hashing 2 or 4 integer keys into a single index, with separate structures for storing associated integer or float data. Key generation involves masking and shifting bits (e.g., 10 bits per key for 2 keys) [S6, unofficial].

### Hash Map Operations
CUDA implementations for hash map insertion and lookup operations, including 3D specific variants and one where the 3D index is used as the value [S7, unofficial].

### Hash Fusion with Occupancy Grid
A technique to address hash collision issues by estimating individual probabilities for vertices corresponding to a feature vector. It calculates an Area of Effect (AOE) for each vertex to weigh the probability prediction, computing a final weighted probability $p_i = \sum_{k=1}^K w_i^k \times p_i^k$ [S8].

### Inverse Hash Mapping
A mechanism to retrieve original voxel indices from feature embeddings. It requires traversing all voxels during initialization to store corresponding embeddings, consuming significant GPU memory (e.g., 5 GB) [S8].

## Operating characteristics
*   **Time Complexity:** Lookup is O(1) for both perfect hashing (after construction) and modular hashing [S1][S2, unofficial]. Construction of perfect hash is O(M^{3/2}) in the worst case [S1].
*   **Memory Complexity:** Proportional to the number of non-empty cells $N_{nz}$ for perfect hashing, plus the domain bits $N$ [S1][S2, unofficial]. For modular hashing, proportional to the hash table size $T$ [S5, unofficial].
*   **Performance:** Hash Grids offer significant memory savings over dense grids for sparse scenes. Test results show memory usage scaling with triangle count (e.g., 18.67 MB for 1.09M triangles in the Buddha scene) [S2, unofficial].
*   **Strengths:** Constant-time access, low memory overhead for sparse data, simple implementation [S1][S2, unofficial].
*   **Limitations:** Perfect hashing is static; modular hashing suffers from collisions; inverse mapping is expensive [S1, S8].

## Background
Hash Grids were introduced in 1977 by Aho and Ullman as a compaction scheme for transition diagrams of deterministic finite automata [S1]. The row displacement compression algorithm was later adapted for sparse 3D matrix compression in computer graphics by Lagae and Dutre (2008) [S1][S2, unofficial]. The method has since been widely adopted in ray tracing acceleration structures and neural rendering (e.g., Instant NGP) for efficient feature storage [S1][S5, unofficial].
