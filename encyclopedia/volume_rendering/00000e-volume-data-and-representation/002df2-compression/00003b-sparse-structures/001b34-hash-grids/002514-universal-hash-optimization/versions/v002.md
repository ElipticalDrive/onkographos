# Universal Hash Optimization

Also called: Universal Hash Function for Hash Grids

## Overview
Universal Hash Optimization is a technique used within Sparse Voxel Octree (SVO) structures to mitigate hash collisions in the underlying hash table [S1, unofficial]. It replaces standard deterministic hashing with a randomized universal hash function, ensuring that distinct non-isomorphic nodes are distributed uniformly across hash table buckets [S1, unofficial]. This reduces the average number of equality checks required during lookups, thereby improving search performance compared to naive hashing methods that may cluster nodes in specific buckets [S1, unofficial].

## How it works
The method operates on a node $n$ within an octree structure [S1, unofficial]. It computes a hash value $k$ recursively for internal nodes and directly from metadata for leaf nodes (voxels), then applies a linear congruential transformation to map this value to a bucket index [S1, unofficial].

**Inputs and Outputs:**
*   Input: A node $n$ in the octree [S1, unofficial].
*   Output: An integer hash value representing the bucket index [S1, unofficial].

**Data Structures:**
*   **Node $n$**: Represents a voxel or an internal octree node [S1, unofficial].
*   **info(n)**: A function returning the unique identifier or metadata hash associated with a voxel node $n$ [S1, unofficial].
*   **Children**: For non-voxel nodes, a list of 8 child nodes [S1, unofficial].
*   **Parameters**:
    *   $p$: A prime number [S1, unofficial].
    *   $m$: The number of buckets in the hash table [S1, unofficial].
    *   $a, b$: Integers such that $a, b \in \{0, \dots, p-1\}$ [S1, unofficial].

**Algorithm Steps:**
1. Initialize accumulator $k = 0$ [S1, unofficial].
2. Check if $n$ is a voxel (leaf node) [S1, unofficial].
3. If $n$ is **not** a voxel: iterate through all children $c$ of node $n$ [S1, unofficial]. Recursively compute the hash for each child $c$ [S1, unofficial]. XOR the child's hash into the accumulator: $k \leftarrow k \oplus \text{recursive}(c)$ [S1, unofficial]. Apply the universal hash transformation to the accumulator: $k \leftarrow (a \cdot k + b) \pmod p$ [S1, unofficial].
4. If $n$ **is** a voxel: set $k \leftarrow \text{info}(n)$ [S1, unofficial].
5. Return the final hash value: $((a \cdot k + b) \pmod p) \pmod m$ [S1, unofficial].

**Formula:**
The bucket index is computed as $H_{ab}(k) = ((a \cdot k + b) \pmod p) \pmod m$, where $p$ is a prime, $m$ is the number of buckets, and $a, b$ are integers in $\{0, \dots, p-1\}$ [S1, unofficial].

**Pseudocode:**
```python
def universal_hash(n, a, b, p, m):
    # n: node to hash
    # a, b: integers in [0, p-1]
    # p: prime modulus
    # m: number of buckets
    # n.is_voxel: boolean attribute indicating leaf status
    # n.children: iterable of child nodes
    # n.info: metadata/identifier value for voxel nodes
    k = 0
    if n.is_voxel:
        k = n.info
    else:
        for c in n.children:
            child_hash = universal_hash(c, a, b, p, m)
            k = k ^ child_hash
            k = (a * k + b) % p
    return ((a * k + b) % p) % m
```

**Edge Cases and Pitfalls:**
*   **Parameter Selection**: The choice of $a$ and $b$ is critical [S1, unofficial]. They must be chosen from the specified range to ensure the probability of collision between distinct nodes is low [S1, unofficial].
*   **Modulus Arithmetic**: The intermediate calculations $(a \cdot k + b)$ can overflow standard integer types if $p$ is large [G]. Implementation must handle modular arithmetic carefully to prevent overflow before the modulo operation [G].
*   **Voxel Info**: The `info(n)` value must effectively distinguish between different voxel contents or states [S1, unofficial].

## Subtopics

### Memoization for Hash Lookup
An optimization to avoid redundant recursive hash computations by caching results in an external hash table [S1, unofficial]. When searching for a node, the system checks an external hash table using the node's memory address as the key [S1, unofficial]. If the address is found, the cached hash value is returned immediately [S1, unofficial]. If not found, the recursive hash computation is executed, the result is stored in the external hash table, and then returned [S1, unofficial]. If the structure of a node is modified, its entry must be removed from the external hash table to ensure consistency [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Not given in the sources.
*   **Memory Complexity**: Not given in the sources.
*   **Performance**: The universal hash function reduces the clustering of nodes in hash table buckets, leading to fewer collisions and faster average-case lookup times compared to non-universal hashing [S1, unofficial].
*   **Strengths**: Uniform distribution of nodes minimizes worst-case collision scenarios [S1, unofficial].
*   **Limitations**: Requires storing parameters $a, b, p$ and potentially maintaining the memoization table [S1, unofficial].

## Background
This method originates from research into the compression and efficiency of Sparse Voxel Octrees for Global Illumination calculations [S1, unofficial]. The specific implementation was developed to address the inefficiency of standard hash tables in SVO structures, where naive hashing caused a significant percentage of nodes to accumulate in single buckets, slowing down searches [S1, unofficial]. The universal hash function used is adapted from the family of universal hash functions described by Braverman et al. (cited as [BB11] in the source) [S1, unofficial].
