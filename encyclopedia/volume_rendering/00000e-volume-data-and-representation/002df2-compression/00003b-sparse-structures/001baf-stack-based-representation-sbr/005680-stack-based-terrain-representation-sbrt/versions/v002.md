# Stack-Based Terrain Representation (SBRT)
Also called: Enfoque 1, Representación de Terrenos Basada en Stacks

## Overview
Stack-Based Terrain Representation (SBRT) is a compact 3D data structure that generalizes heightmaps by storing a vertical sequence of intervals for each $(x,y)$ coordinate, where each interval consists of a start height and an attribute (e.g., material type) [S1]. It solves the high memory footprint of voxel-based representations and the inability of 2.5D Digital Elevation Models (DEMs) to model complex internal structures like caves or overhangs [S1]. Unlike its siblings, SBRT uses 1D-like structures (textures) which favor prefetching and stack-level caching, resulting in better performance than single-texture approaches [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D terrain dataset defined on a grid of width $W$ and height $H$, consisting of volumetric layers or geological samples (boreholes) interpolated into layers [S1].
*   **Output:** A GPU-resident memory layout consisting of two 2D textures: an interval texture and an index texture [S1].

**Data Structures:**
The grid dimensions are $W \times H$ (denoted as `gridancho` $\times$ `gridalto` in sources) [S1]. For each grid cell $(x,y)$, the structure stores a list of intervals [S1]. Each interval is defined by two values:
1.  **Start Height ($z$):** The z-coordinate where the interval begins [S1].
2.  **Attribute:** A material or property ID [S1].

This is analogous to Run-Length Encoding (RLE) along the z-axis [S1]. The memory layout utilizes two 2D textures:
1.  **Interval Texture (`Textura de intervalos`):** Stores the interval data (start height and attribute) [S1].
2.  **Index Texture (`Textura de índices`):** Stores indices to spatially identify stack starts without fixed-size interval storage [S1].

**Implementation Approaches (Enfoques):**
The source describes five specific memory layout approaches ("Enfoques") for implementing SBRT on GPU hardware [S1]:

*   **Enfoque 1:** Uses two separate 2D textures for intervals and indices [S1]. The grid dimensions are $W \times H$ [S1]. The last cells of the last row may remain unoccupied, wasting memory [S1].
*   **Enfoque 2:** Uses a single texture where regions of $(3 \times 2)$ texels are determined by the size of the largest stack (e.g., 5 intervals) [S1]. The texture contains these fixed regions [S1].
*   **Enfoque 3 & 4:** Similar to Enfoque 2 but with different texel region configurations [S1]. Enfoque 3 has restrictions and cannot be used for especially large datasets due to maximum texture size limits of graphics cards [S1].
*   **Enfoque 5:** Uses two separate Shader Storage Buffer Objects (SSBOs) for intervals and indices, similar to Enfoque 1 but using SSBOs instead of textures [S1].

**Rendering Algorithm:**
The visualization method is based on GPU raycasting [S1]. Rays are launched from the virtual camera through each pixel of the output buffer, composing colors sampled along the ray [S1]. The structure is introduced in a compact and complete manner into GPU memory, avoiding data transfer between CPU and GPU [S1].

**Pseudocode:**
The following pseudocode outlines the data preparation for Enfoque 1, the primary approach described with specific memory layout details [S1].

```python
import math

def ray_box_intersection(origin, direction, grid_min, grid_max):
    inv_dir = [1.0/d if d != 0 else 1e8 for d in direction]
    t1 = [(grid_min[i] - origin[i]) * inv_dir[i] for i in range(3)]
    t2 = [(grid_max[i] - origin[i]) * inv_dir[i] for i in range(3)]
    t_min = max(min(t1[i], t2[i]) for i in range(3))
    t_max = min(max(t1[i], t2[i]) for i in range(3))
    if t_max < t_min: return None, None
    return t_min, t_max

def grid_traversal(origin, direction, t_min, t_max, grid_width, grid_height, grid_depth, voxel_size):
    cells = []
    ox, oy, oz = origin[0]/voxel_size, origin[1]/voxel_size, origin[2]/voxel_size
    cx, cy, cz = int(ox), int(oy), int(oz)
    cx = max(0, min(cx, grid_width-1))
    cy = max(0, min(cy, grid_height-1))
    cz = max(0, min(cz, grid_depth-1))
    step_x = 1 if direction[0] > 0 else -1
    step_y = 1 if direction[1] > 0 else -1
    step_z = 1 if direction[2] > 0 else -1
    t_delta_x = voxel_size / abs(direction[0]) if direction[0] != 0 else 1e8
    t_delta_y = voxel_size / abs(direction[1]) if direction[1] != 0 else 1e8
    t_delta_z = voxel_size / abs(direction[2]) if direction[2] != 0 else 1e8
    t_max_x = (step_x * (grid_width - 0.5 - ox) if direction[0] > 0 else step_x * (-0.5 - ox)) * t_delta_x
    t_max_y = (step_y * (grid_height - 0.5 - oy) if direction[1] > 0 else step_y * (-0.5 - oy)) * t_delta_y
    t_max_z = (step_z * (grid_depth - 0.5 - oz) if direction[2] > 0 else step_z * (-0.5 - oz)) * t_delta_z
    if t_max_x < t_min: t_max_x += t_delta_x
    if t_max_y < t_min: t_max_y += t_delta_y
    if t_max_z < t_min: t_max_z += t_delta_z
    t_enter = t_min
    while t_enter < t_max:
        cells.append((cx, cy, t_enter))
        if t_max_x < t_max_y:
            if t_max_x < t_max_z:
                cx += step_x; t_enter = t_max_x; t_max_x += t_delta_x
            else:
                cz += step_z; t_enter = t_max_z; t_max_z += t_delta_z
        else:
            if t_max_y < t_max_z:
                cy += step_y; t_enter = t_max_y; t_max_y += t_delta_y
            else:
                cz += step_z; t_enter = t_max_z; t_max_z += t_delta_z
    return cells

def render_sbrt_raycast(ray_origin, ray_direction, interval_texture, index_texture, grid_width, grid_height, grid_depth, voxel_size, grid_min, grid_max):
    t_min, t_max = ray_box_intersection(ray_origin, ray_direction, grid_min, grid_max)
    if t_min is None: return [0.0, 0.0, 0.0, 0.0]
    cells = grid_traversal(ray_origin, ray_direction, t_min, t_max, grid_width, grid_height, grid_depth, voxel_size)
    color = [0.0, 0.0, 0.0, 0.0]
    alpha = 0.0
    for (cx, cy, t_enter) in cells:
        idx = cy * grid_width + cx
        start_offset = index_texture[idx][0]
        count = index_texture[idx][1]
        for i in range(count):
            offset = start_offset + i * 2
            z_start = interval_texture[offset]
            attr = interval_texture[offset + 1]
            z_end = interval_texture[start_offset + (i+1)*2] if (i+1) < count else grid_max[2]
            inv_dz = 1.0 / ray_direction[2] if ray_direction[2] != 0 else 1e8
            t1 = (z_start - ray_origin[2]) * inv_dz
            t2 = (z_end - ray_origin[2]) * inv_dz
            t_enter_z = max(t1, t2) if ray_direction[2] > 0 else max(t2, t1)
            t_exit_z = min(t1, t2) if ray_direction[2] > 0 else min(t2, t1)
            if t_exit_z < t_enter or t_enter_z > t_max: continue
            t_seg_start = max(t_enter, t_enter_z)
            t_seg_end = min(t_exit_z, t_max)
            if t_seg_end <= t_seg_start: continue
            mat_color = [0.5, 0.5, 0.5]
            mat_alpha = 0.8
            seg_len = t_seg_end - t_seg_start
            alpha_seg = 1.0 - math.exp(-mat_alpha * seg_len)
            contrib = [alpha_seg * c for c in mat_color]
            color[0] += contrib[0] * (1.0 - alpha)
            color[1] += contrib[1] * (1.0 - alpha)
            color[2] += contrib[2] * (1.0 - alpha)
            alpha += alpha_seg * (1.0 - alpha)
            if alpha >= 0.95: break
    return color
```

**Parameters and Edge Cases:**
*   **Grid Dimensions:** SBRT does not require power-of-two dimensions, unlike octrees which require padding (e.g., 200x250x320 becomes 512x512x512) [S1].
*   **Memory Waste:** In Enfoque 1, the last cells of the last row may remain unoccupied, wasting memory [S1].
*   **Material Mixing:** SBRT handles heterogeneous materials (mixing/overlapping) more simply at the stack level than hierarchical structures like octrees [S1].
*   **Large Datasets:** Enfoque 3 cannot be used for especially large datasets due to maximum texture size limits [S1].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** SBRT uses significantly less memory than voxel models (e.g., 2.628 MB vs 61.035 MB for Terreno 1) and less than octrees (e.g., 2.628 MB vs 20.004 MB for Terreno 1) [S1]. It consumes less than 10% of the memory of an equivalent voxel model and between 13% and 30% of an octree [S1].
*   **Performance:** Enfoques 1 and 5 (using 1D-like structures/SSBOs) achieve the best performance (279-61 fps for Enfoque 5, 256-55 fps for Enfoque 1) due to favorable prefetching and stack-level caching [S1]. Enfoques 2, 3, and 4 (single-texture approaches) have worse performance due to lack of cache-friendly organization [S1].

**Strengths and Limitations:**
*   **Strengths:** Compact memory footprint; supports non-power-of-two dimensions; supports heterogeneous materials; suitable for real-time visualization and geological operations (slicing, layer attenuation) [S1].
*   **Limitations:** Not suitable for volumetric data not organized in layers (e.g., medical data) [S1]; Enfoque 3 has size limits; Enfoque 1 has some memory waste at grid boundaries [S1].

## Background
**Origin and History:**
SBRT was proposed in the paper "Direct Volume Rendering of Stack-Based Terrains" by A. Graciano, A.J. Rueda, and F.R. Feito, published in Eurographics Proceedings in 2017 [S1].

**Usage:**
It is used for the visualization of terrains and geological structures, adapting raycasting techniques for efficient visualization and operations without auxiliary structures [S1]. It is particularly suited for modeling subsurface data obtained from geological boreholes (catas) and interpolated layer models [S1].
