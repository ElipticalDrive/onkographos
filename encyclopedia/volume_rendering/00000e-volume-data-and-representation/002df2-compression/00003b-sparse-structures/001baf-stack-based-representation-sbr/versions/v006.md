# Stack-Based Representation (SBR)
Also called: Stacks
## Overview
Stack-Based Representation (SBR) is a sparse volume data structure that decomposes a voxel grid into vertical columns, or "stacks," where each column is compressed via run-length encoding of attribute values along the vertical axis [S1, unofficial]. It solves the memory inefficiency of dense voxel grids for layered or stratified datasets by exploiting vertical coherence, storing only the boundaries between attribute changes [S1, unofficial]. Unlike general sparse structures like Hash Grids or SparseGrids that treat all spatial dimensions symmetrically, SBR assumes a strong directional anisotropy (typically vertical), making it distinct from siblings that rely on isotropic subdivision [S1, 1081-stack-based-representation-sbr.md, unofficial].
## How it works
**Inputs and Outputs:**
*   **Input:** A voxel grid $V$ of resolution $w \times h \times d$, where each voxel $v_{x,y,z}$ stores one or more attributes (e.g., color, material, density) [S1, unofficial].
*   **Output:** A set $S$ of vertical stacks, where each stack $S_{x,y}$ corresponds to a column at $(x,y)$ and is represented as a sequence of intervals [S1, unofficial].

**Data Structures:**
1.  **Stack ($S_{x,y}$):** A list of intervals representing the column $V_{x,y}$.
2.  **Interval ($i_k$):** A tuple $\langle a_k, h_k \rangle$ where:
    *   $a_k$: The attribute value (e.g., material ID) shared by all voxels in the interval.
    *   $h_k$: The height (z-index) of the top voxel of the interval.
    *   The interval covers voxels from $z = 1 + h_{k-1}$ to $z = h_k$ [S1, unofficial].
    *   For the first interval ($k=1$), $h_0$ is assumed to be 0 [S1, unofficial].

**Algorithm Steps:**
1.  Iterate through every column $(x,y)$ in the grid $w \times h$.
2.  For each column, iterate through the voxels $v_{x,y,z}$ from $z=1$ to $d$.
3.  Identify contiguous sequences of voxels with identical attribute values.
4.  For each sequence, create an interval $i_k = \langle a_k, h_k \rangle$, where $a_k$ is the attribute value and $h_k$ is the z-index of the last voxel in the sequence.
5.  Append $i_k$ to the stack $S_{x,y}$.
6.  Ensure intervals are sorted by height in ascending order ($h_k < h_{k+1}$) [S1, unofficial].

**Pseudocode:**
```python
def build_sbr(voxel_grid, width, height, depth):
    """
    Builds the Stack-Based Representation from a dense voxel grid.
    voxel_grid: 3D array [width][height][depth] containing attribute values.
    Returns: A 2D array of lists, stacks[width][height], where each list contains intervals.
    """
    stacks = [[[] for _ in range(height)] for _ in range(width)]

    for x in range(width):
        for y in range(height):
            current_stack = []
            current_attr = None
            current_height = 0
            
            # Iterate through the vertical column
            for z in range(1, depth + 1):
                attr = voxel_grid[x][y][z]
                
                # If attribute changes or we are at the end of the column
                if attr != current_attr:
                    # If we had a previous attribute, finalize the interval
                    if current_attr is not None:
                        current_stack.append((current_attr, current_height))
                    
                    # Start new interval
                    current_attr = attr
                    current_height = z
                else:
                    # Continue the current interval, update height
                    current_height = z
            
            # Finalize the last interval for this column
            if current_attr is not None:
                current_stack.append((current_attr, current_height))
            
            stacks[x][y] = current_stack
            
    return stacks
```

**Parameters:**
*   **Attribute Type:** The specific data stored in $a_k$ (e.g., uint8 for material ID, float for density). Not given in the sources.
*   **Sorting:** Intervals must be sorted by $h_k$ ascending. This is naturally achieved by processing $z$ from 1 to $d$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Empty Columns:** If a column contains no voxels (or all voxels are "empty" with a null attribute), the stack may be empty or contain a single interval with a null attribute. The sources do not specify a default "empty" attribute handling [S1, unofficial].
*   **Precision:** Height values $h_k$ must be stored with sufficient bits to represent the maximum depth $d$. Not given in the sources.
*   **Parallelism:** Construction is embarrassingly parallel as stack construction does not require information about neighboring stacks [S1, unofficial].

## Subtopics

### [QuadStack](1113-quadstack.md)
Extends SBR by organizing stacks into a quadtree to compress regions with identical interval sequences, achieving higher compression for datasets with spatial coherence in layer topology.

### [Group of Stacks (gstack)](1169-group-of-stacks-gstack.md)
Groups spatially adjacent stacks with identical attribute sequences into a single structure, separating attribute compression from geometric heightfield storage.

### [Stack-Based Terrain Representation (SBRT)](15717-stack-based-terrain-representation-sbrt.md)
Generalizes SBR for terrain data, using 1D-like textures for better prefetching and caching performance compared to single-texture approaches.

## Operating characteristics
*   **Time Complexity:** Construction is $O(n)$, where $n = w \times h \times d$ is the total number of voxels, because each voxel is processed exactly once [S1, unofficial].
*   **Memory Complexity:** Depends on the number of layers. In the worst case (every voxel has a different attribute), memory usage is proportional to the number of voxels. In the best case (single attribute per column), memory is proportional to $w \times h$. Not given in the sources for exact ratios.
*   **Strengths:** Embarrassingly parallel construction; efficient for layered/stratified data; simple data structure [S1, unofficial].
*   **Limitations:** Assumes vertical anisotropy; inefficient for data with high vertical variation or no layering; does not inherently compress horizontal redundancy (addressed by children like QuadStack) [S1, 1081-stack-based-representation-sbr.md, unofficial].
*   **When to Use:** Layered volumetric datasets (e.g., geological strata, terrain with subsurface layers) where vertical coherence is high [S1, unofficial].
*   **When Not to Use:** Isotropic volumes or data with significant horizontal coherence but vertical variation [S1, 1081-stack-based-representation-sbr.md, unofficial].

## Background
The Stack-Based Representation was introduced as a method for efficiently storing and rendering layered volumetric datasets. It was developed by researchers at the Czech Technical University in Prague (DCGI), as detailed in the QuadStack paper [S1, unofficial]. The method addresses the limitations of traditional voxel grids for data that can be naturally decomposed into vertical columns with constant attributes [S1, unofficial].
