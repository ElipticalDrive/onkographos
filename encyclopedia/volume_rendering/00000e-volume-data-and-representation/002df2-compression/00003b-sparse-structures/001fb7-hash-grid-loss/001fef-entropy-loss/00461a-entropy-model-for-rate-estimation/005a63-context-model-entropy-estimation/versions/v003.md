# Context Model Entropy Estimation
Also called: Bit Consumption Calculation, Bit Estimator, Bit cost estimation, Information Entropy Loss, Entropy calculation

## Overview
Context Model Entropy Estimation calculates the differentiable bit consumption for binary feature values based on their predicted probabilities, serving as a differentiable proxy for the bitrate in loss functions [S2]. It distinguishes itself from sibling methods by explicitly modeling the spatial context of 3D features to refine probability estimates, rather than relying on global occurrence frequencies [S2].

## How it works
**Inputs and Outputs:**
- Input: Binary feature value $\theta_i \in \{-1, +1\}$ and its predicted probability $p_i = P(\theta_i = +1)$ [S2].
- Input (Attribute): Attribute variable $\hat{y}_{i,j}$ and its channel-wise probability distribution $p(\hat{y}_{i,j})$ [S1, unofficial].
- Input (Hyperprior): Hyperprior variable $\hat{z}_{i,j}$ and its channel-wise probability distribution $p(\hat{z}_{i,j})$ [S1, unofficial].
- Output: Estimated bit consumption (scalar loss value) [S1, unofficial][S2].

**Data Structures:**
- $\theta_i$: Scalar binary feature. Values are $\{-1, +1\}$ [S2].
- $p_i$: Scalar probability in range $[0, 1]$ [S2].
- $\hat{y}_{i,j}$: Attribute variable with $D_y$ channels [S1, unofficial].
- $\hat{z}_{i,j}$: Hyperprior variable with $D_z$ channels [S1, unofficial].
- $D_y$: Number of channels of the attribute variable $\hat{y}_i$ [S1, unofficial].
- $D_z$: Number of channels of the hyperprior variable $\hat{z}_i$ [S1, unofficial].

**Steps:**
1. Estimate the probability $p_i$ for each feature $\theta_i$ using spatial context from 3D space to enhance precision, rather than using global occurrence frequency [S2].
2. Calculate the bit consumption for the binary feature $\theta_i$ using the entropy formula [S2]:
   $$ \text{bit}(p_i|\theta_i) = -\left( \frac{1+\theta_i}{2}\log_2(p_i) + \frac{1-\theta_i}{2}\log_2(1-p_i) \right) $$
   This simplifies to:
   $$ \text{bit}(p_i|\theta_i) = \begin{cases} -\log_2(p_i) & \text{if } \theta_i = +1 \\ -\log_2(1-p_i) & \text{if } \theta_i = -1 \end{cases} $$
3. For hyperprior variables $\hat{z}$, estimate probabilities $p(\hat{z}_{i,j})$ using a factorized module following Ballé et al. (2018) [S1, unofficial].
4. Sum the bit consumption over all channels for both attribute and hyperprior variables [S1, unofficial]:
   $$ \text{bit}_i = \sum_{j=1}^{D_y} \left( -\log_2 p(\hat{y}_{i,j}) \right) + \sum_{j=1}^{D_z} \left( -\log_2 p(\hat{z}_{i,j}) \right) $$

**Pseudocode:**
```python
import math

def context_model_entropy_estimation(theta, p_i, p_y, p_z, D_y, D_z):
    """
    Calculate bit consumption for binary features and hyperprior variables.
    
    Args:
        theta: Binary feature value, +1 or -1.
        p_i: Probability that theta == +1, scalar in [0, 1].
        p_y: List/array of probabilities for attribute channels, length D_y.
        p_z: List/array of probabilities for hyperprior channels, length D_z.
        D_y: Number of channels for attribute variable.
        D_z: Number of channels for hyperprior variable.
        
    Returns:
        Total estimated bit consumption.
    """
    # Clamp probabilities to avoid log(0) [G]
    eps = 1e-7
    p_i_safe = max(min(p_i, 1.0 - eps), eps)
    p_y_safe = [max(min(p, 1.0 - eps), eps) for p in p_y]
    p_z_safe = [max(min(p, 1.0 - eps), eps) for p in p_z]
    
    # Step 2: Binary feature bit cost
    if theta == 1:
        bit_theta = -math.log2(p_i_safe)
    elif theta == -1:
        bit_theta = -math.log2(1.0 - p_i_safe)
    else:
        raise ValueError("Theta must be +1 or -1")
        
    # Step 4: Attribute and hyperprior bit costs
    bit_y = sum(-math.log2(p) for p in p_y_safe)
    bit_z = sum(-math.log2(p) for p in p_z_safe)
    
    return bit_theta + bit_y + bit_z
```

**Parameters:**
- $p_i$: Probability that $\theta_i = +1$. Range: $[0, 1]$ [S2].
- $D_y$: Number of channels of the attribute variable $\hat{y}_i$ [S1, unofficial].
- $D_z$: Number of channels of the hyperprior variable $\hat{z}_i$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- Logarithm of zero: Probabilities $p$ or $1-p$ must be clamped away from 0 to avoid undefined values [G].
- Binary constraint: $\theta_i$ must strictly be $+1$ or $-1$ [S2].

## Operating characteristics
- Time Complexity: The computation scales linearly with respect to the number of channels $D_y$ and $D_z$ for the hyperprior summation [S1, unofficial].
- Memory Complexity: The method requires storing probabilities for all channels [S1, unofficial].
- Strengths: The estimator is differentiable, allowing gradient backpropagation through the bit estimation [S2]. Context-aware estimation improves accuracy over global frequency [S2].
- Limitations: The method relies on accurate probability estimation from context models [S2].

## Background
The method originated in the context of compressing Instant-NGP-based NeRFs [S2]. It draws inspiration from binarization concepts from BiRF [S2]. The hyperprior probability estimation follows Ballé et al. (2018) [S1, unofficial].
