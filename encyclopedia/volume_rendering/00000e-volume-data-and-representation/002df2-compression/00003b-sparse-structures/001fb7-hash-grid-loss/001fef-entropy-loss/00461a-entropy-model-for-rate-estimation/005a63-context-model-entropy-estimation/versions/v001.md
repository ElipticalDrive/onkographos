# Context Model Entropy Estimation
Also called: Bit Consumption Calculation, Bit Estimator, Bit cost estimation, Information Entropy Loss, Entropy calculation

## Overview
Context Model Entropy Estimation calculates the differentiable bit consumption for binary feature values based on their predicted probabilities, serving as a differentiable proxy for the bitrate in loss functions [S2]. It distinguishes itself from sibling methods by explicitly modeling the spatial context of 3D features to refine probability estimates, rather than relying on global occurrence frequencies [S2].

## How it works
**Inputs and Outputs:**
- Input: Binary feature value $\theta_i \in \{-1, +1\}$ and its predicted probability $p_i = P(\theta_i = +1)$ [S2].
- Input (Hyperprior): Hyperprior variable $\hat{z}_{i,j}$ and its probability $p(\hat{z}_{i,j})$ [S1, unofficial].
- Input (Attribute): Attribute variable $\hat{y}_{i,j}$ and its probability $p(\hat{y}_{i,j})$ [S1, unofficial].
- Output: Estimated bit consumption (loss value) [S1, unofficial][S2].

**Data Structures:**
- $\theta_i$: Scalar binary feature. Values are $\{-1, +1\}$ [S2].
- $p_i$: Scalar probability in range $[0, 1]$ [S2].
- $\hat{y}_{i,j}$: Attribute variable with $D_y$ channels [S1, unofficial].
- $\hat{z}_{i,j}$: Hyperprior variable with $D_z$ channels [S1, unofficial].
- $D_y$: Number of channels of the attribute variable $\hat{y}_i$ [S1, unofficial].
- $D_z$: Number of channels of the hyperprior variable $\hat{z}_i$ [S1, unofficial].

**Steps:**
1. Estimate the probability $p_i$ for each feature $\theta_i$. While a baseline approach uses global occurrence frequency $f_G$, this method uses spatial context from 3D space to enhance precision [S2].
2. Calculate the bit consumption for the binary feature $\theta_i$ using the entropy formula [S2]:
   $$ \text{bit}(p_i|\theta_i) = -\left( \frac{1+\theta_i}{2}\log_2(p_i) + \frac{1-\theta_i}{2}\log_2(1-p_i) \right) $$
   This simplifies to:
   $$ \text{bit}(p_i|\theta_i) = \begin{cases} -\log_2(p_i) & \text{if } \theta_i = +1 \\ -\log_2(1-p_i) & \text{if } \theta_i = -1 \end{cases} $$
3. For hyperprior variables $\hat{z}$, estimate probabilities $p(\hat{z}_{i,j})$ using a factorized module following Ballé et al. (2018) [S1, unofficial].
4. Sum the bit consumption over all channels for both attribute and hyperprior variables [S1, unofficial]:
   $$ \text{bit}_i = \sum_{y}^{D_y} \sum_{z}^{D_z} \left( -\log_2 p(\hat{y}_{i,j}) \right) + \sum_{y}^{D_y} \sum_{z}^{D_z} \left( -\log_2 p(\hat{z}_{i,j}) \right) $$
   Note: The source [S1, unofficial] notation $\sum_{y}^{D_y} \sum_{z}^{D_z}$ implies summation over the channel indices $y$ and $z$ up to their respective counts $D_y$ and $D_z$.

**Pseudocode:**
```python
def context_model_entropy_estimation(theta, p_y, p_z, D_y, D_z):
    """
    Calculate bit consumption for binary features and hyperprior variables.
    
    Args:
        theta: Binary feature value, +1 or -1.
        p_y: Probability of attribute variable y, shape (D_y, D_z) or scalar.
        p_z: Probability of hyperprior variable z, shape (D_y, D_z) or scalar.
        D_y: Number of channels for attribute variable.
        D_z: Number of channels for hyperprior variable.
        
    Returns:
        Total estimated bit consumption.
    """
    # Calculate bit cost for binary feature theta
    # Formula: -((1+theta)/2 * log2(p) + (1-theta)/2 * log2(1-p))
    # If theta = +1: -log2(p)
    # If theta = -1: -log2(1-p)
    
    # Handle potential numerical instability with log(0)
    epsilon = 1e-7
    p_clipped = max(min(p_y, 1.0 - epsilon), epsilon)
    
    if theta == 1:
        bit_theta = -math.log2(p_clipped)
    elif theta == -1:
        bit_theta = -math.log2(1.0 - p_clipped)
    else:
        raise ValueError("Theta must be +1 or -1")
        
    # Calculate bit cost for hyperprior variables
    # Sum over all channels y and z
    bit_hyperprior = 0.0
    for y in range(D_y):
        for z in range(D_z):
            p_z_clipped = max(min(p_z[y][z], 1.0 - epsilon), epsilon)
            bit_hyperprior += -math.log2(p_z_clipped)
            
    return bit_theta + bit_hyperprior
```

**Parameters:**
- $p_i$: Probability that $\theta_i = +1$. Range: $[0, 1]$ [S2].
- $D_y$: Number of channels of the attribute variable $\hat{y}_i$ [S1, unofficial].
- $D_z$: Number of channels of the hyperprior variable $\hat{z}_i$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- Logarithm of zero: Probabilities $p$ or $1-p$ must be clamped away from 0 to avoid undefined values [G].
- Binary constraint: $\theta_i$ must strictly be $+1$ or $-1$ [S2].

## Operating characteristics
- Time Complexity: Linear with respect to the number of channels $D_y$ and $D_z$ for the hyperprior summation [S1, unofficial].
- Memory Complexity: Requires storing probabilities for all channels [S1, unofficial].
- Strengths: Differentiable, allowing gradient backpropagation through the bit estimation [S2]. Context-aware estimation improves accuracy over global frequency [S2].
- Limitations: Relies on accurate probability estimation from context models [S2].

## Background
Originated in the context of compressing Instant-NGP-based NeRFs [S2]. Inspired by binarization concepts from BiRF [S2]. The hyperprior probability estimation follows Ballé et al. (2018) [S1, unofficial].
