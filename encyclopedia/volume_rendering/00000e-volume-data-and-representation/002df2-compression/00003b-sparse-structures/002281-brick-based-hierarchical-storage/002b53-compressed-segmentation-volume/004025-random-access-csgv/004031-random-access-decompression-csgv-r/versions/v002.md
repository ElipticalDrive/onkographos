# Random Access Decompression (CSGV-R)

Also called: no cache, voxel cache

## Overview
Random Access Decompression (CSGV-R) is a rendering mode for Compressed Segmentation Volumes that leverages the true random access capabilities of the CSGV-R compression format to decode voxel labels on demand without decoding entire bricks serially [S1]. It solves the memory overhead and latency issues inherent in the standard CSGV brick cache approach, allowing for immediate, artifact-free rendering in the first frame [S1]. Unlike sibling methods that rely on pre-decoded brick caches, CSGV-R offers three distinct access strategies: direct "no cache" access, a "voxel cache" using hash-based storage, and an optimized "voxel cache (es)" that incorporates an empty space bit vector to skip invisible labels [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A CSGV-R compressed volume dataset, a camera ray, and a target voxel coordinate $(x, y, z)$.
*   **Output:** The segmentation label (palette index) for the specified voxel.

**Data Structures**
1.  **CSGV-R Structure:** The compressed volume data, including the wavelet matrix and operation list, stored in GPU memory [S1].
2.  **Voxel Hash Table:** A custom hash table using Cuckoo hashing to store recently decoded voxel labels [S1].
3.  **Empty Space Bit Vector:** An optional bit vector tracking which palette indices are currently visible or accessed, filled on-the-fly during rendering [S1].

**Algorithm Steps**
The decompression process for a single voxel access follows these steps [S1]:
1.  **Cache Check:** If a "voxel cache" or "voxel cache (es)" mode is active, check if the target voxel $(x, y, z)$ exists in the voxel hash table. If found, return the cached label to avoid decompression traversals [S1].
2.  **Empty Space Check (Optional):** If "voxel cache (es)" is active, check the empty space bit vector for the label associated with the current traversal path. If the label is marked as invisible, skip further processing or return a default background value [S1].
3.  **Operation Chase:** Traverse the CSGV-R operation list sequentially from the start until a **palette operation** is encountered [S1].
4.  **Wavelet Traversal:** For the identified segment, traverse the wavelet matrix to determine the specific coefficient value corresponding to the target voxel coordinates [S1].
5.  **Palette Index Rank Query:** Perform a rank query on the palette indices to resolve the final segmentation label from the wavelet coefficient [S1].
6.  **Cache Update:** If caching is enabled, insert the decoded label and its coordinates into the voxel hash table using the custom Cuckoo hashing scheme [S1].

**Pseudocode**
```python
def decompress_voxel_csgv_r(volume_data, x, y, z, cache_mode='no_cache', empty_space_vector=None):
    """
    Decompress a single voxel from a CSGV-R compressed volume.
    """
    cache = {}  # Voxel hash table using Cuckoo hashing [S1]

    # Step 1: Check Voxel Cache
    if cache_mode in ('voxel_cache', 'voxel_cache_es'):
        label = cache.get((x, y, z))
        if label is not None:
            return label

    # Step 2: Check Empty Space Vector (Optional)
    if cache_mode == 'voxel_cache_es' and empty_space_vector is not None:
        # Check if the current traversal path corresponds to an invisible label
        if is_label_empty(empty_space_vector, x, y, z):
            return 0  # BACKGROUND_LABEL

    # Step 3: Chase Operations to Palette Operation
    # Traverse the CSGV-R operation list sequentially until a palette operation is found [S1]
    palette_op = None
    for op in volume_data.operations:
        if op.type == 'PALETTE':
            palette_op = op
            break

    # Step 4: Traverse Wavelet Matrix
    # Navigate the hierarchical wavelet structure to find the coefficient for (x, y, z) [S1]
    coefficient = traverse_wavelet_matrix(volume_data.wavelet_matrix, palette_op, x, y, z)

    # Step 5: Palette Index Rank Query
    # Resolve the final segmentation label from the wavelet coefficient [S1]
    label = palette_index_rank_query(palette_op, coefficient)

    # Step 6: Update Voxel Cache
    if cache_mode in ('voxel_cache', 'voxel_cache_es'):
        cache[(x, y, z)] = label
        if cache_mode == 'voxel_cache_es':
            mark_label_in_vector(empty_space_vector, label)

    return label

# Helper definitions (standard operations or CSGV-R specific logic)
def is_label_empty(bit_vector, x, y, z):
    # Check bit vector for empty space flag at coordinates [S1]
    return bit_vector.get(x, y, z)

def traverse_wavelet_matrix(matrix, palette_op, x, y, z):
    # Navigate wavelet tree to extract coefficient for voxel [S1]
    return matrix.query(x, y, z)

def palette_index_rank_query(palette_op, coefficient):
    # Map coefficient to palette index using rank operation [S1]
    return palette_op.rank(coefficient)

def mark_label_in_vector(bit_vector, label):
    # Set empty space bit for the decoded label on-the-fly [S1]
    bit_vector.set(label, True)
```

**Parameters and Typical Values**
*   **Cache Size:** The voxel cache size can be chosen freely and does not need to fit all visible areas, unlike the fixed brick cache [S1].
*   **Empty Space Bit Vector:** Filled on-the-fly during rendering [S1].

**Edge Cases and Pitfalls**
*   **Performance Cost:** Direct "no cache" access incurs high performance costs due to multiple traversals of the operation list and wavelet matrix for each voxel [S1].
*   **Empty Space Vector Overhead:** For large datasets like H01, the empty space bit vector causes significant performance degradation due to many distant memory reads in the longer bit vector and the high cost of querying $2^3$ voxels in the finest and most expensive LOD, while common accesses are to coarser and faster accessible LODs [S1].
*   **Small Label Regions:** For datasets with small label regions and few stop bits (e.g., CELLS), frame times can almost double in "no cache" mode compared to cached modes [S1].

### [Cooperative Decoding (CSGV-R)](10190-cooperative-decoding-csgv-r.md)
A GPU shader stage where a single wavefront cooperatively decompresses one brick, eliminating thread divergence and leveraging shared memory for the wavelet tree.

## Operating characteristics
**Time and Memory Complexity**
*   **Time Complexity:** Direct "no cache" access has high latency due to per-voxel traversal of operations and wavelet matrices. Caching reduces this significantly, with performance improvements up to a factor of 5 [S1].
*   **Memory Complexity:** "No cache" uses minimal memory. "Voxel cache" uses memory proportional to the number of cached voxels. "Voxel cache (es)" adds memory for the empty space bit vector [S1].

**Measured Performance**
Performance is measured in milliseconds per frame (ms) for local shading on different datasets [S1]:

| Mode | CELLS | FIBER | H01 | AZBA |
| :--- | :--- | :--- | :--- | :--- |
| **No Cache** | 44.9 | 12.8 | 6.5 | 28.6 |
| **Voxel Cache** | 9.7 | 6.3 | 1.2 | 8.8 |
| **Voxel Cache (es)** | 6.1 | 7.1 | 75.8 | 8.1 |

*   **Scaling:** The voxel cache does not need to fit all visible areas, allowing for flexible scaling based on available memory [S1].
*   **Strengths:** Produces artifact-free images in the first frame, unlike CSGV which has latency [S1].
*   **Limitations:** "No cache" mode is slow. "Voxel cache (es)" can be significantly slower on large datasets like H01 due to memory access patterns [S1].

**When to Use**
*   Use "no cache" when memory is extremely constrained, accepting higher latency [S1].
*   Use "voxel cache" for general cases to balance performance and memory, especially when label regions are small [S1].
*   Use "voxel cache (es)" for datasets with many invisible labels and moderate dimensions, but avoid for very large datasets like H01 where the bit vector overhead dominates [S1].

## Background
Random Access Decompression (CSGV-R) was introduced as part of the Compressed Segmentation Volume Random Access (CSGV-R) compression method, which allows random access to voxel labels without decoding the entire brick serially [S1]. It addresses the limitations of the original CSGV brick cache, which suffered from memory overhead and one-frame latency [S1]. The method was developed to enable interactive volume rendering of segmentation volumes with minimal preprocessing and immediate visual feedback [S1].
