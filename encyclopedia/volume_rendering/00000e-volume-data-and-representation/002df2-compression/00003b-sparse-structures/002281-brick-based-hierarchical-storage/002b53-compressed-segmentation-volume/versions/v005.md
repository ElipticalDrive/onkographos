# Compressed Segmentation Volume

Also called: Brick-based Iterative Refinement, CSVD, CSVE, CSVol, Fast Compressed Segmentation Volumes, Iterative Refinement Compression for Segmentation Volumes

## Overview
Compressed Segmentation Volume (CSV) is a lossless compression technique for voxel-based segmentation volumes that encodes individual bricks using a multi-resolution label pyramid and an iterative refinement scheme [S1]. It solves the storage and transfer bottlenecks of high-label-count segmentation data by exploiting spatial homogeneity through parent, neighbor, and palette-based operations, followed by rANS entropy coding [S1]. Unlike general-purpose compressors (e.g., HDF5, PNG) or quantitative volume compressors (e.g., OpenVDB, Compresso), CSV is tailored for discrete label data, achieving compression ratios of 1–3% of the original size while supporting GPU-based on-the-fly decompression and level-of-detail (LoD) rendering [S1][S3, unofficial].

## How it works
**Inputs:** A segmentation volume (array of `uint32_t` labels) and a brick size $b$ (power of two, typically 16, 32, or 64) [S1][S2, unofficial].
**Outputs:** A compressed encoding array `m_encoding` (vector of `uint32_t`), a brick start index array `m_brick_starts`, and a palette of labels [S2, unofficial].

**Data Structures:**
*   **MultiGridNode:** Contains `uint32_t label` and `bool constant_subregion` [S2, unofficial].
*   **MultiGrid:** A hierarchical structure for a single brick. Level $L_l$ stores $(b/2^l)^3$ nodes. $L_0$ is the finest level (original brick). $L_N$ (where $N = \log_2 b$) is the root [S1][S2, unofficial].
*   **Palette:** A list of unique labels encountered during encoding, indexed by `ip` [S1].
*   **Encoding Stream:** A sequence of operation codes and stop bits, compressed via rANS [S1].

**Algorithm Steps:**

1.  **MultiGrid Construction (Per Brick):**
    *   Initialize $L_0$ with the brick's voxel labels. Voxels outside the volume boundary are set to `0xFFFFFFFF` [S2, unofficial].
    *   Iterate $l$ from $1$ to $N$. For each node in $L_l$, gather its 8 children from $L_{l-1}$.
    *   Skip children with label `0xFFFFFFFF`.
    *   Determine the node's label as the most frequent label among valid children. If ambiguous, choose the one occurring first in the child array [S1].
    *   Set `constant_subregion` to `true` if all valid children have the same label and are constant [S2, unofficial].

2.  **Encoding (Per Brick):**
    *   Initialize palette with the label of the root node ($L_N$). Set palette index `ip = 0` [S1].
    *   Iterate levels $l$ from $N$ down to $1$.
    *   For each node $i$ in $L_l$ (Morton Z-curve order):
        *   If `pyramid[i].constantChildren` is true, skip [S1].
        *   Store `parent = pyramid[i].label` [S1].
        *   Iterate child nodes $j$ of $i$ in Z-curve order.
        *   Let $L = \text{pyramid}[j].\text{label}$ and `stop = pyramid[j].constantChildren` [S1].
        *   Determine operation `op` using `bestOperation(parent, pyramid, palette, L)` [S1]. The function checks operations in this fixed order:
            1.  **Parent Reuse (Rp):** If $L == \text{parent}$.
            2.  **Neighbor Reuse (Rx, Ry, Rz):** If $L$ matches a neighbor node adjacent to $j$ along axis $x, y,$ or $z$, pointing outside the current $2^3$ sibling block. If the referenced neighbor has a later Z-index (not yet decoded), reinterpret as a reference to the neighbor's parent [S1]. Neighbor nodes in other bricks are not referenced [S1].
            3.  **Palette Back Reference P*0:** If $L == \text{palette}[ip]$.
            4.  **Palette Back Reference P*$\delta$:** If $L == \text{palette}[ip - \delta - 1]$ for some $\delta \in [0, 15]$.
            5.  **Palette Advance (Pa):** Otherwise, assign $L$ to a new palette entry [S1].
        *   Output `(op, stop)` tuple. If `op` is Pa, append $L$ to palette. If `op` is P*$\delta$, output $\delta$ as an additional 4-bit value [S1].

3.  **Entropy Coding:**
    *   Compute global frequency tables for rANS via a prepass over a subset of bricks (e.g., every 512th brick) [S1]. Two tables are used: one for interior nodes ($L_N \dots L_1$) and one for leaf nodes ($L_0$, where stop bits are always 0) [S1].
    *   Normalize frequencies: set any zero frequency to 1 to prevent rANS undefined behavior [S2, unofficial].
    *   Encode the operation stream using rANS [S1].

4.  **Decompression (Per Brick, Target LoD $t$):**
    *   Initialize `ip = 0`. Allocate output array `out` of size $2^{3(N-t)}$ [S1].
    *   Set `out[0] = palette[ip]` [S1].
    *   Iterate levels $l$ from $N$ down to $t+1$.
    *   For each decoded node $i$ in $L_l$ (Z-order):
        *   If `out[lastChildOf(i)]` is not empty (all children decoded), continue [S1].
        *   Set `parent = out[i]` [S1].
        *   Iterate child nodes $j$ in Z-order.
        *   Read `(op, stop)` from rANS decoder [S1].
        *   Apply operation:
            *   Rp: `out[j] = parent`
            *   Rx/Ry/Rz: `out[j] = neighbor value` (handle boundary/late-Z references as parent) [S1].
            *   Pa: `out[j] = palette[++ip]`
            *   P*0: `out[j] = palette[ip]`
            *   P*$\delta$: `out[j] = palette[ip - \delta]`
        *   If `stop` is true, fill the entire sub-block of $2^{3(l-t-1)}$ labels in `out` starting at $j$ with `out[j]` [S1].

**Pseudocode:**

```python
def compress_brick(brick_voxels, brick_size):
    # brick_voxels: list of uint32_t labels, size brick_size^3
    # Returns: palette, operation_stream (list of tuples)
    
    N = int(log2(brick_size))
    # Build MultiGrid
    pyramid = []
    # Level 0
    level_0 = []
    for v in brick_voxels:
        level_0.append(MultiGridNode(label=v, constant_subregion=False))
    pyramid.append(level_0)
    
    # Coarsen
    for l in range(1, N + 1):
        prev_level = pyramid[l-1]
        curr_level = []
        dim = brick_size // (2**l)
        for i in range(dim**3):
            children = get_children(prev_level, i)
            valid_labels = [c.label for c in children if c.label != 0xFFFFFFFF]
            if not valid_labels:
                label = 0xFFFFFFFF
                constant = False
            else:
                label = most_frequent(valid_labels)
                constant = all(c.label == label for c in children if c.label != 0xFFFFFFFF)
            curr_level.append(MultiGridNode(label=label, constant_subregion=constant))
        pyramid.append(curr_level)

    palette = [pyramid[N][0].label]
    ip = 0
    ops = []
    
    # Encode
    for l in range(N, 0, -1):
        level = pyramid[l]
        for i in range(len(level)):
            node = level[i]
            if node.constant_subregion:
                continue
            
            parent_label = node.label
            children = get_children(pyramid[l-1], i)
            
            for j, child in enumerate(children):
                L = child.label
                stop = child.constant_subregion
                
                # Determine best operation
                op = None
                delta = None
                
                if L == parent_label:
                    op = 'Rp'
                elif is_neighbor_match(child, i, l, pyramid):
                    op = get_neighbor_axis(child, i, l, pyramid)
                elif L == palette[ip]:
                    op = 'P*0'
                else:
                    found_delta = False
                    for d in range(16):
                        idx = ip - d - 1
                        if idx >= 0 and palette[idx] == L:
                            op = 'P*delta'
                            delta = d
                            found_delta = True
                            break
                    if not found_delta:
                        op = 'Pa'
                        palette.append(L)
                        ip += 1
                
                ops.append((op, stop, delta))
                
    return palette, ops
```

## Subtopics

### [Multi-resolution Brick Encoding](5775-multi-resolution-brick-encoding.md)
Multi-resolution Brick Encoding is a lossless compression technique for segmentation volumes that exploits homogeneous label neighborhoods to compactly encode label data and boundaries. It builds a per-brick resolution pyramid to generate a sequence of operations and a label palette, forming the foundational representation for Compressed Segmentation Volume (CSV) compression. Unlike flat storage, it separates the label values from the structural assignment logic, enabling efficient entropy coding.

### Segmented Dataset Quantization
A method for segmented datasets where small blocks are quantized to have only one or two different components inside. Encoded data consists of the block type and the splitting plane which subdivides the block [S4].

## Operating characteristics
**Time and Memory Complexity:**
*   Compression and decompression throughput is high, up to gigabytes per second [S1][S3, unofficial].
*   Temporary memory overhead for pyramid generation is approximately 14% of the brick size [S1].
*   Parallelization is naive: $T$ threads compress $T$ bricks in parallel, which leads to suboptimal utilization for larger brick sizes due to divergent processing times [S1].

**Measured Performance:**
*   **Compression Ratio (CR):** Achieves 1–3% of the original data set size [S1][S3, unofficial].
    *   CELLS (1M labels): 2.805% (b=64, rANS) [S1].
    *   FIBER (32K labels): 0.899% (b=64, rANS) [S1].
    *   CORTEX (15M labels): 1.590% (b=64, rANS) [S1].
*   **Comparison:** Outperforms HDF5 (gzip), PNG, and Neuroglancer in CR. Comparable to Compresso+LZMA for CELLS/CORTEX, but significantly better for FIBER. 8–30x faster than Compresso+LZMA [S1].
*   **rANS Impact:** Improves CR by ~40% over raw 4-bit nibbles, with only ~2.5% throughput impact [S1].

**Strengths and Limitations:**
*   **Strengths:** Lossless, high throughput, supports GPU rendering, adaptive LoD, out-of-core processing [S1][S3, unofficial].
*   **Limitations:** Neighbor references cannot cross brick borders, reducing efficiency for large homogeneous regions spanning bricks. Larger bricks improve CR but increase parallelization divergence [S1].

## Background
Originating from the paper "Fast Compressed Segmentation Volumes for Scientific Visualization" (2023) [S1], CSV was developed to address the challenges of storing and visualizing voxel-based segmentation volumes with millions of labels. It builds on the principles of brick-based hierarchical storage, specifically leveraging multi-resolution representations and entropy coding [S1]. It is used in GPU-based volume visualization with on-the-fly decompression and level-of-detail rendering [S1][S3, unofficial].
