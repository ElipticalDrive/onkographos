# Evolutionary Volumetric Data Structure (EVDS) / L-Block Compression (LBC)

Also called: L-block Covering, L-blocks, Polymerization Strategy

## Overview
The Evolutionary Volumetric Data Structure (EVDS), stored as an L-block Covering (LBC), is a hierarchical sparse data structure designed for the real-time incremental compression and segmentation of filamentary volumetric data, such as neuronal tissue [S1, unofficial]. It solves the problem of managing massive, sparse datasets by packaging significant data into connected L-blocks (LBs) while ignoring "white space," allowing for on-the-fly generation without storing the entire volume in memory [S1, unofficial]. Unlike standard AABB-trees, the LBC allows for easy incremental box building and maintains connectivity between nodes without requiring traversal through a parent node [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** A stream of consecutive 2D image slices (serial sections) scanned in the XY plane at depths $Z$ and $Z+1$, where each voxel contains a grayscale value [S1, unofficial].
*   **Output:** An L-block Covering (LBC) representing the Enhanced Volume Data Set (EVDS), consisting of a set of connected L-blocks and their hierarchical relationships [S1, unofficial].

### Data Structures
**L-Block (LB)**
The basic unit of storage. An LB is an axis-aligned box containing voxel data [S1, unofficial].
*   **Dimensions:** The basic unit is a $(2, 2, 2)$ L-block, though the structure supports $(m, n, 1)$ or other dimensions [S1, unofficial].
*   **Content:** Stores valid voxels and associated "white space" (empty voxels within the bounding box) [S1, unofficial].
*   **Storage Cost:** In the reference implementation, 6 bytes per LB are used for data and whitespace [S1, unofficial].

**L-Block Covering (LBC)**
A hierarchical structure storing connected LBs [S1, unofficial].
*   **Structure:** Similar to an AABB-tree but optimized for incremental updates and local connectivity [S1, unofficial].
*   **Header Cost:** One bit for marking leaf nodes, and a 2-byte pointer for each node [S1, unofficial].
*   **Connectivity:** LBs sharing an active edge are assumed to be connected, and the structure maintains this connectivity explicitly without parent traversal [S1, unofficial].

### Algorithm Steps
1.  **Thresholding and Labeling:** Apply a conservative labeling function initially to quickly segment and compress a superset of critical data [S1, unofficial]. Vertices are considered "significant" if their grayscale values pass a threshold test (e.g., above a minimum and below a maximum level) [S1, unofficial]. Edges are labeled "active" if and only if both adjacent vertices are significant [S1, unofficial]. Voxels that do not pass the threshold are treated as "white space" [S1, unofficial].
2.  **Partitioning:** Partition the EVDS into $2 \times 2 \times 2$ cells [S1, unofficial]. If any voxel in a cell is valid (significant), store that cell as a $(2, 2, 2)$ LB [S1, unofficial].
3.  **Incremental Generation (Polymerization):** Process consecutive serial sections scanned in the XY plane at depths $Z$ and $Z+1$ [S1, unofficial]. Retain only the immediate predecessor ($Z$) in memory while the current image data ($Z+1$) is used to enhance the $Z$-plane data [S1, unofficial]. Package regions of interest in the $Z$-plane into $(m, n, 1)$ L-blocks and add them to the evolving EVDS [S1, unofficial]. Focus on connected components in the extended volume data set [S1, unofficial]. Isolated vertices outside connected components may be retained as individual LBs, while remaining vertices are treated as whitespace and ignored [S1, unofficial].
4.  **Noise Removal:** Apply Noise Removal I (Smear) to remove large smear noise that exists on single layers [S1, unofficial]. Apply Noise Removal II (Isolated) to eliminate small disconnected LBs, since the LBC is a local packaging structure and noise is wrapped in small isolated packages [S1, unofficial].
5.  **Merging:** Combine LBs to minimize header overhead [S1, unofficial]. Extend LBs in positive X, Y, and Z axis directions if the space saved by eliminating L-block overhead is greater than the space lost by storing empty data (whitespace) [S1, unofficial].
6.  **Neuron Reconstruction (Optional Post-Processing):** Dilate LBs within each cluster so they overlap "nearby" LBs [S1, unofficial]. Join overlapping LBCs to fill gaps caused by noise [S1, unofficial]. Form an expanded connectivity graph linking overlapping dilated LBs [S1, unofficial]. Reduce complexity by identifying short cycles that do not change global topology [S1, unofficial].

### Pseudocode
```python
def process_serial_sections(current_slice, previous_slice, evds, width, height, depth):
    """
    Incrementally updates the EVDS with the current slice.
    current_slice: 2D array of grayscale values at depth Z+1
    previous_slice: 2D array of grayscale values at depth Z (retained in memory)
    evds: The evolving L-block Covering structure
    width, height, depth: Dimensions of the volumetric grid
    """
    # Step 1: Thresholding and Labeling
    MIN_VAL = 100
    MAX_VAL = 255
    significant_vertices = set()
    for y in range(height):
        for x in range(width):
            val = current_slice[y, x]
            if MIN_VAL <= val <= MAX_VAL:
                significant_vertices.add((x, y))

    # Step 2: Partitioning into 2x2x2 L-Blocks
    new_lbs = []
    block_size = 2
    for z in range(0, depth, block_size):
        for y in range(0, height, block_size):
            for x in range(0, width, block_size):
                is_valid = False
                for dz in range(block_size):
                    for dy in range(block_size):
                        for dx in range(block_size):
                            if (x + dx, y + dy) in significant_vertices:
                                is_valid = True
                                break
                        if is_valid: break
                    if is_valid: break
                
                if is_valid:
                    lb = create_lb(x, y, z, block_size, block_size, block_size)
                    new_lbs.append(lb)

    # Step 3: Incremental Packaging (m, n, 1) for current slice
    # In practice, regions of interest in the Z-plane are packaged as (m, n, 1) LBs
    # and added to the evolving EVDS alongside the 2x2x2 blocks.
    for lb in new_lbs:
        evds.add_lb(lb)

    # Step 4: Merging
    # Extend LBs in positive X, Y, Z directions if space saved > space lost
    evds.merge_lbs()

    # Step 5: Noise Removal
    # Remove isolated small LBs wrapped by the local packaging structure
    evds.remove_isolated_noise()
    
    return evds

def create_lb(x, y, z, w, h, d):
    """
    Creates an L-Block with exact layout.
    Stores valid/invalid flags for all voxels in the bounding box.
    Reference implementation uses 6 bytes per LB for data and whitespace.
    """
    total_voxels = w * h * d
    # Boolean grid representing valid voxels and associated whitespace
    data = [False] * total_voxels
    return {
        'origin': (x, y, z),
        'dimensions': (w, h, d),
        'valid_flags': data,
        'cost_bytes': 6
    }
```

### Parameters
*   **LB Size:** The basic unit is a $(2, 2, 2)$ L-block, though the structure supports $(m, n, 1)$ or other dimensions [S1, unofficial].
*   **Voxel Dimensions:** Each voxel represents a volume of $0.37 \, \mu m \times 0.37 \, \mu m \times 0.5 \, \mu m$ [S1, unofficial].
*   **Thresholds:** A conservative labeling function is used initially to quickly segment a superset of critical data, with more sophisticated techniques applied later to adjust edge labeling [S1, unofficial].

### Edge Cases and Pitfalls
*   **Merging Complexity:** Combining larger LBs with smaller ones is problematic because expanding an LB may require storing "white" space along with relevant data [S1, unofficial].
*   **Connectivity Ambiguity:** Two neighboring LBs might not be physically connected; the EVDS must be checked to determine if a connection actually exists [S1, unofficial].
*   **False Positives in Reconstruction:** Dilating LBs and joining overlapping LBCs may join LBCs that should be kept separate [S1, unofficial].

## Subtopics

### Incremental Generation
*   **What it is:** A processing mode where the EVDS is built on-the-fly as serial sections are scanned, retaining only the immediate predecessor in memory.
*   **Difference:** Unlike batch processing methods, it allows real-time compression and segmentation with bounded memory usage.
*   **When to choose:** When processing continuous data streams (e.g., KESM microscopy) where total data size exceeds available RAM.
*   **Link:** [Incremental Generation](5378-incremental-generation.md)

### Noise Removal
*   **What it is:** Strategies to eliminate smear noise (single-layer artifacts) and isolated disconnected LBs.
*   **Difference:** LBC's local packaging structure naturally isolates noise, making it easier to remove compared to global volumetric filters.
*   **When to choose:** When the input data contains significant artifacts from the scanning process.
*   **Link:** [Noise Removal](5379-noise-removal.md)

### Neuron Reconstruction
*   **What it is:** Post-processing step involving dilation, joining overlapping LBCs, and graph simplification to model neuronal threads.
*   **Difference:** Uses the LBC's connectivity graph to identify major threads and reduce complexity by removing short cycles.
*   **When to choose:** When the goal is biological modeling rather than just visualization.
*   **Link:** [Neuron Reconstruction](5380-neuron-reconstruction.md)

## Operating characteristics
*   **Time Complexity:** Real-time incremental generation is possible, with merging and noise removal bounded by the size of the current section [S1, unofficial].
*   **Memory Complexity:** Bounded by the size of the current and previous sections, avoiding full volume storage [S1, unofficial].
*   **Measured Performance:**
    *   **Neuron Data (250x230x90):** Uncompressed 5 MB becomes 1.1 MB (65,611 LBs), yielding a compression factor of ~4 (20% of original size) [S1, unofficial]. Merging reduces LB count twofold to 28,938 (<0.4 MB) and fourfold to 10,684 (<0.18 MB) [S1, unofficial].
    *   **Cell Body Data (500x500x100):** Uncompressed 25 MB becomes 0.8 MB (50,218 LBs), yielding a compression factor of ~31 (3.2% of original size) [S1, unofficial]. Merging reduces LB count to 10,684 (<0.18 MB) [S1, unofficial].
*   **Scaling:** The method is designed for continuous data streams where raw data for an entire mouse brain requires approximately 30 terabytes [S1, unofficial].
*   **Strengths:** Real-time processing, low memory footprint, efficient compression for filamentary data, and easy incremental updates [S1, unofficial].
*   **Limitations:** Higher overhead for short, blobby structures (cell bodies) compared to octrees, merging complexity, and potential for false positives in reconstruction [S1, unofficial].
*   **When to use:** Filamentary volumetric data (neurons) from serial sectioning microscopy [S1, unofficial].
*   **When not to use:** Dense volumetric data or data with short, blobby structures where octrees may be more efficient [S1, unofficial].

## Background
*   **Origin:** Developed by B. McCormick et al. for processing data from the Knife Edge Scanning Microscope (KESM) [S1, unofficial].
*   **History:** Presented in 2004 at the Eurographics Symposium on Rendering [S1, unofficial].
*   **Usage:** Used in the KESM pipeline for processing stained mouse brain tissue data, and for isosurface generation via isosplats and raytracing visualization [S1, unofficial].
