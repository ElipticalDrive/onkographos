# Segmented Dataset Quantization

Also called: Block-based segmented quantization, Agus et al. method

## Overview
Segmented Dataset Quantization is a compression technique for volumetric datasets where data is divided into small blocks, each quantized to contain only one or two distinct component values [S1]. It solves the problem of efficiently storing segmented data (such as material labels or discrete scalar fields) by reducing the storage requirement per block to a block type identifier and a splitting plane definition [S1]. It differs from general texture compression standards like VTC or ASTC by explicitly modeling the discrete, segmented nature of the data rather than approximating continuous values [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A volumetric dataset partitioned into small 3D blocks (e.g., $4 \times 4 \times 4$ or similar small cuboids).
*   **Output:** A compressed bitstream consisting of, for each block, a block type identifier and the parameters defining a splitting plane.

**Data Structures:**
The encoded representation for each block consists of:
1.  **Block Type:** An integer or bit-field indicating the quantization mode (e.g., single-component vs. two-component).
2.  **Splitting Plane:** Parameters defining a plane that separates the two components if the block type indicates two components. In a 3D grid, a splitting plane is typically defined by a normal vector and a distance, or by a specific axis-aligned cut if restricted to axis-aligned splits. The source notes do not specify the exact bit-packing or resolution of the plane parameters.

**Steps:**
1.  **Partitioning:** Divide the input volume into small, non-overlapping 3D blocks.
2.  **Analysis:** For each block, identify the set of unique component values present within it.
3.  **Quantization Decision:**
    *   If the block contains only one unique component value, assign the "single-component" block type.
    *   If the block contains exactly two unique component values, assign the "two-component" block type.
    *   If the block contains more than two unique values, the method as described in the source does not specify a fallback. [G] Typically, this would involve either splitting the block recursively, using a higher-precision quantization, or treating it as an error case, but this detail is not provided in [S1].
4.  **Plane Definition:** For blocks with two components, determine the splitting plane that separates the voxels belonging to the first component from those belonging to the second. The source notes do not specify the algorithm for finding this plane (e.g., axis-aligned, arbitrary normal) or how it is encoded.
5.  **Encoding:** Write the block type and the splitting plane parameters to the output stream.

**Strengths and Limitations:**
*   **Strengths:** Highly efficient for segmented data where blocks naturally contain few distinct values.
*   **Limitations:** Limited to blocks with at most two components. Generalization to more complex data is not described.

**When to use:**
Use for real-time rendering of time-varying volumetric datasets that are segmented and exhibit local homogeneity [S1].

## Background
The method was proposed by Agus et al. [AGIM10] as a way to handle segmented datasets [S1]. It is mentioned in the context of compressed GPU-based direct volume rendering, alongside other techniques like VTC, ETC2, and ASTC [S1].
