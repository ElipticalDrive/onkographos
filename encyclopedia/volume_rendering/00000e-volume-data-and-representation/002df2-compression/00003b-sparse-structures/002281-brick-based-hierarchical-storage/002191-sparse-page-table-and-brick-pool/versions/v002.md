# Sparse Page Table and Brick Pool

Also called: MRMS sparse volume, VDB-style sparse volume for web

## Overview
Sparse Page Table and Brick Pool is a memory-bounded sparse volume representation that avoids materializing a dense 3D grid by using a two-level structure: a page table mapping logical $8^3$-texel regions to resident bricks, and a pool of apron-padded bricks [S1, unofficial]. It solves the problem of rendering high-resolution sparse volumes (e.g., weather data at source resolution) within limited GPU memory while enabling empty-space skipping [S1, unofficial]. Unlike its sibling [ExaBricks Hierarchy](2182-exabricks-hierarchy.md) which uses a fixed hierarchy, or [Compressed Segmentation Volume](4985-compressed-segmentation-volume.md) which focuses on segmentation, this method relies on a flat page table for spatial mapping and a bounded brick pool for residency [S1, unofficial]. It builds on [Brick-based Hierarchical Storage](2793-brick-based-hierarchical-storage.md) principles but replaces hierarchical traversal with direct page-table lookup [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A logical 3D volume grid (up to $2048^3$ cells) and a terrain heightfield.
*   **Output:** A page table texture (RG8 format) and a brick pool texture (RGB8 or similar, containing $10^3$ texels per brick).

**Data Structures:**
1.  **Page Table:** A 2D or 1D texture/array where each entry corresponds to a logical $8^3$-texel page.
    *   **Layout:** RG8 (Red, Green, 8-bit each).
    *   **Encoding:** The value encodes a pool slot index + 1 if the page contains data (echo), or 0 if the page is empty (no echo) [S1, unofficial].
2.  **Brick Pool:** A collection of resident bricks.
    *   **Layout:** Each brick is a $10^3$ texel cube.
    *   **Core:** The inner $8^3$ texels contain the actual volume data.
    *   **Apron:** A one-texel border surrounding the core. The apron is filled by copying neighboring logical texels, clamped at the grid edge, to ensure trilinear filtering stays within the brick [S1, unofficial].

**Parameters:**
*   `MAX_VOLUME_BRICKS`: Maximum number of resident bricks in the pool. Default: 8192 [S1, unofficial]. This caps the pool size at approximately 16.4 MB (assuming 2 KB per brick) [S1, unofficial].
*   `Extinction Power`: The extinction ramp uses a power function `pow(t, 2.75)` to correct for light echo inflation caused by source-resolution rendering [S1, unofficial].
*   `MAX_RAY_STEPS`: Maximum steps per ray. Default: 384 [S1, unofficial].

**Algorithm Steps:**

1.  **Build Phase (`build_volume_texture`):**
    1.  Iterate through the logical grid pages.
    2.  For each logical $8^3$ page:
        a.  Check if the page is empty.
        b.  If empty, set the corresponding Page Table entry to 0.
        c.  If not empty:
            i.  If `current_brick_count < MAX_VOLUME_BRICKS`, allocate a brick in the pool.
            ii. Copy the $8^3$ core data into the brick.
            iii. Fill the one-texel apron with neighboring logical texels (clamped at edges).
            iv. Set the Page Table entry to `pool_slot_index + 1`.
            v. Increment `current_brick_count`.
        d.  If the pool is full and more data exists, trigger grid coarsening by the next whole footprint multiple after a count-only pass [S1, unofficial].
    2.  Compute terrain occlusion data (`buildGroundPageMax`):
        a.  For each page column, compute the highest ground height, including a one-column halo for linear filtering [S1, unofficial].

2.  **Raymarching Step (Shader):**
    1.  Calculate the logical page index for the current ray position.
    2.  Fetch the RG8 entry from the Page Table.
    3.  **Empty Space Skipping:**
        a.  If entry == 0:
            i.  Jump the ray to the exit face of that $8^3$ page in one loop iteration.
            ii. Adjust the ray position to land back on the jittered sample lattice to maintain consistent sampling cadence [S1, unofficial].
            iii. Check terrain occlusion: If the page lies wholly above the precomputed `buildGroundPageMax` height, skip entirely. Otherwise, step through the page with per-sample ground tests but without volume fetches [S1, unofficial].
    4.  **Resident Page Sampling:**
        a.  If entry != 0:
            i.  Lookup the brick in the pool at index `(entry - 1)`.
            ii. Sample the volume trilinearly using the brick data [S1, unofficial].

**Pseudocode:**

```python
# Constants
MAX_VOLUME_BRICKS = 8192
PAGE_SIZE = 8
APRON_SIZE = 1
BRICK_SIZE = PAGE_SIZE + 2 * APRON_SIZE  # 10

# Data Structures
# page_table: Array of RG8 entries, size determined by logical grid dimensions / PAGE_SIZE
# brick_pool: Array of 10^3 texel bricks
# terrain_max_height: Array of max ground heights per page column

def build_volume_texture(logical_grid, terrain_grid):
    page_table = []
    brick_pool = []
    brick_count = 0
    
    # Precompute terrain max height per page column with halo
    terrain_max_height = compute_terrain_max_with_halo(terrain_grid, PAGE_SIZE)
    
    # Iterate logical pages
    for page_coords in logical_grid.pages():
        # Check if page has any data
        if not logical_grid.is_empty(page_coords):
            if brick_count < MAX_VOLUME_BRICKS:
                # Allocate brick
                brick = allocate_brick()
                
                # Copy core
                for x in range(PAGE_SIZE):
                    for y in range(PAGE_SIZE):
                        for z in range(PAGE_SIZE):
                            brick.core[x][y][z] = logical_grid.get_voxel(page_coords, x, y, z)
                
                # Fill apron
                for x in range(BRICK_SIZE):
                    for y in range(BRICK_SIZE):
                        for z in range(BRICK_SIZE):
                            # Map brick coordinate to logical coordinate
                            logical_x = page_coords.x * PAGE_SIZE + x - APRON_SIZE
                            logical_y = page_coords.y * PAGE_SIZE + y - APRON_SIZE
                            logical_z = page_coords.z * PAGE_SIZE + z - APRON_SIZE
                            
                            # Clamp to grid edges
                            logical_x = clamp(logical_x, 0, logical_grid.width - 1)
                            logical_y = clamp(logical_y, 0, logical_grid.height - 1)
                            logical_z = clamp(logical_z, 0, logical_grid.depth - 1)
                            
                            brick.apron[x][y][z] = logical_grid.get_voxel_at(logical_x, logical_y, logical_z)
                
                # Store brick
                slot_index = len(brick_pool)
                brick_pool.append(brick)
                
                # Update page table
                page_table.append(RG8(slot_index + 1, 0))
                brick_count += 1
            else:
                # Pool full, trigger coarsening logic (not implemented here)
                pass
        else:
            page_table.append(RG8(0, 0))
            
    return page_table, brick_pool, terrain_max_height

def raymarch_page_table(ray, page_table, brick_pool, terrain_max_height):
    while ray.t < MAX_RAY_STEPS:
        # Calculate page index
        page_coords = ray.get_page_coords()
        
        # Fetch page table entry
        entry = page_table[page_coords]
        
        if entry == 0:
            # Empty page
            # Check terrain occlusion
            if ray.position.z > terrain_max_height[page_coords.x][page_coords.y]:
                # Skip to page exit
                ray.jump_to_page_exit(page_coords)
                ray.adjust_to_lattice()
            else:
                # Step through with ground test, no volume fetch
                ray.step_with_ground_test(page_coords, terrain_max_height)
        else:
            # Resident page
            slot_index = entry - 1
            brick = brick_pool[slot_index]
            
            # Sample trilinearly
            value = sample_trilinear(brick, ray.position)
            
            # Accumulate color/opacity
            accumulate(value)
            
            ray.step()
```

## Subtopics

### [Sparse Brickmap Volume Rendering](2978-sparse-brickmap-volume-rendering.md)
Sparse Brickmap Volume Rendering is a voxel rendering technique that uses a two-level data structure (coarse brick grid and fine voxel bricks) to render sparse volumes efficiently, integrating hardware depth for correct compositing with rasterized geometry. It builds on [Sparse Page Table and Brick Pool](2550-sparse-page-table-and-brick-pool.md) by replacing the generic page-table indirection with a fixed $8^3$ brick hierarchy optimized for two-level Digital Differential Analyzer (DDA) traversal. Unlike dense voxel grids, it significantly reduces memory footprint by collapsing fully-buried terrain into uniform entries and storing only mixed (surface) bricks in a compact pool.

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Bounded by `MAX_VOLUME_BRICKS`. With 8192 bricks, the pool is ~16.4 MB [S1, unofficial]. The page table size is proportional to the logical grid volume divided by $8^3$.
*   **Time:** Reduces per-pixel work by skipping empty pages [S1, unofficial]. `MAX_RAY_STEPS` remains constant at 384, but the number of volume fetches is reduced [S1, unofficial].

**Measured Performance:**
*   On live KATL (wide) data: Old dense grid 6.11M, Sparse source res 5.08M (-17%), with 2.75 power correction 6.12M (0%) [S1, unofficial].
*   On KATL close: Old 4.57M, Sparse 3.65M (-20%), with 2.75 power 4.75M (+4%) [S1, unofficial].
*   On KSEA stratiform: Old 270k, Sparse 193k (-28%), with 2.75 power 259k (-4%) [S1, unofficial].
*   Smoke test on KATL weather payload (456 × 385 × 96 logical texels): Used 2,158 bricks and a 5.0 MB pool [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Allows full source resolution (up to 2048 cells per axis) while bounding memory usage [S1, unofficial]. Enables efficient empty-space skipping [S1, unofficial].
*   **Limitations:** Requires careful handling of terrain occlusion to avoid skipping rays that pass through terrain [S1, unofficial]. Phase bleed can occur where empty texels bordering echo adopt the neighbor's phase [S1, unofficial].

**When to Use:**
*   Use when rendering sparse volumes with high resolution requirements and limited GPU memory.
*   Use when empty-space skipping is critical for performance.

**When Not to Use:**
*   Use when the volume is dense and fully occupied, as the overhead of page table lookups may not be justified.
*   Use when fine-grained empty-space skipping within a brick is required (e.g., for multi-channel datasets with varying transfer functions), as this method only skips entirely empty bricks [S3].

## Background
The method was implemented for the web raymarcher in the `approach-viz` project to replace a dense RG8 3D texture capped at 256 cells per axis [S1, unofficial]. The dense grid capped each axis at 256 cells, so a ~440-cell request was coarsened 2× horizontally, resulting in up to 12.6 MB of mostly zeros [S1, unofficial]. The sparse representation allows a 2048-cell logical axis with coarsenX/Z = 1 in the common case [S1, unofficial]. It implements two OpenVDB/NanoVDB ideas: empty-space skipping via page table lookup and leaf bricks with a page table [S1, unofficial].
