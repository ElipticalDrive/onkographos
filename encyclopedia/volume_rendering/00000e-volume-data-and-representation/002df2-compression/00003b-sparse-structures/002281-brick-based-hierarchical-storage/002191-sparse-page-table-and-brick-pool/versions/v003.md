# Sparse Page Table and Brick Pool

Also called: MRMS sparse volume, VDB-style sparse volume for web

## Overview
Sparse Page Table and Brick Pool is a memory-efficient volume representation that avoids materializing a dense 3D grid by using a two-level structure: a page table mapping logical $8^3$-texel regions to resident bricks, and a pool of apron-padded bricks [S1, unofficial]. It allows full source resolution (up to 2048 cells per axis) while bounding memory usage and enabling empty-space skipping [S1, unofficial]. Unlike dense voxel grids, it significantly reduces memory footprint by collapsing fully-buried terrain into uniform entries and storing only mixed (surface) bricks in a compact pool [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A logical volume grid (e.g., MRMS weather data) and a terrain heightfield.
*   **Output:** A page table texture (RG8 format) and a brick pool (array of $10^3$ texels per brick).

**Data Structures:**
1.  **Page Table:** A 2D texture (or array) with one RG8 entry per logical $8^3$-texel page. The entry encodes a pool slot index + 1 if the page has echo, or 0 if empty/no echo [S1, unofficial].
2.  **Brick Pool:** A collection of resident bricks. Each brick is an $8^3$ texel core wrapped in a one-texel apron (total $10^3$ texels) [S1, unofficial]. The apron is filled by copying neighboring logical texels, clamped at the grid edge, to ensure trilinear filtering stays within the brick [S1, unofficial].

**Parameters:**
*   `MAX_VOLUME_BRICKS`: Maximum number of resident bricks allowed in the pool. Default value is 8192. This caps the pool size at approximately 16.4 MB (assuming 2 KB per brick) [S1, unofficial].
*   `Extinction Power`: The extinction ramp uses a power function $\text{pow}(t, 2.75)$ to correct for the fact that source-resolution rendering does not artificially inflate light echo [S1, unofficial].
*   `MAX_RAY_STEPS`: Remains at 384 [S1, unofficial].

**Build Phase:**
The `build_volume_texture` function emits the page table and brick pool [S1, unofficial].
1.  Iterate through the logical grid.
2.  If a logical $8^3$ page is empty, the page table entry is 0 [S1, unofficial].
3.  If it contains data, a brick is allocated in the pool (if under `MAX_VOLUME_BRICKS`), the $8^3$ core is copied, and the apron is filled from neighbors [S1, unofficial].
4.  If the pool is full, the grid coarsens by the next whole footprint multiple after a count-only pass [S1, unofficial].
5.  Compute `buildGroundPageMax`: records the highest ground under each page column (including a one-column halo for linear filtering) [S1, unofficial].

**Raymarching Step:**
For each ray step, the shader calculates the logical page index for the current ray position [S1, unofficial].
1.  Fetch the corresponding RG8 entry from the page table [S1, unofficial].
2.  **Empty Space Skipping:** If the page table entry is 0 (empty page), the ray is jumped to the exit face of that $8^3$ page in one loop iteration [S1, unofficial]. The ray position is adjusted to land back on the jittered sample lattice to maintain consistent sampling cadence [S1, unofficial].
3.  **Terrain Occlusion Check:** An empty page is only skipped if the entire page lies wholly above the maximum ground height recorded in `buildGroundPageMax` [S1, unofficial]. Otherwise, the ray steps through the page with per-sample ground tests but without volume fetches [S1, unofficial].
4.  **Resident Page Sampling:** If the page table entry is non-zero, the ray samples the volume trilinearly using the brick data from the pool slot indicated by $(\text{entry} - 1)$ [S1, unofficial].

**Pseudocode:**

```python
# Constants
MAX_VOLUME_BRICKS = 8192
EXTINCTION_POWER = 2.75
MAX_RAY_STEPS = 384
BRICK_CORE_SIZE = 8
BRICK_TOTAL_SIZE = 10 # 8 + 2 aprons (1 on each side)

# Data Structures
# page_table: 2D array of RG8 entries. 
#   R channel: pool slot index + 1 (if resident), 0 (if empty)
#   G channel: unused or auxiliary
# brick_pool: array of 1D arrays of size BRICK_TOTAL_SIZE^3
# ground_max: 2D array of max ground heights per logical page

def build_volume_texture(logical_grid, terrain_heightfield):
    page_table = {}
    brick_pool = []
    
    # Pre-compute ground max for each page
    # Each page covers an 8x8 area in X/Y
    for page_x, page_y in logical_grid.dimensions:
        max_h = -infinity
        # Include one-column halo for linear filtering safety
        for dx in range(-1, BRICK_CORE_SIZE + 1):
            for dy in range(-1, BRICK_CORE_SIZE + 1):
                gx, gy = page_x * BRICK_CORE_SIZE + dx, page_y * BRICK_CORE_SIZE + dy
                if terrain_heightfield.has(gx, gy):
                    max_h = max(max_h, terrain_heightfield.get(gx, gy))
        ground_max[page_x, page_y] = max_h

    # Build bricks and page table
    for page_x, page_y, page_z in logical_grid.pages():
        page_key = (page_x, page_y, page_z)
        
        # Check if page is empty
        if not logical_grid.has_data(page_key):
            page_table[page_key] = 0
            continue
            
        # Check if pool is full
        if len(brick_pool) >= MAX_VOLUME_BRICKS:
            # Coarsen grid logic would happen here at a higher level
            # For this function, we assume coarsening reduces the number of pages
            # or this page is skipped/merged. 
            # As per source, grid coarsens by next whole footprint multiple.
            # Implementation detail: If pool full, we might not add this brick.
            # However, source implies coarsening happens *after* count-only pass.
            # Simplified: if full, skip adding brick, treat as empty or handled by coarsening logic outside.
            # For correctness of "bounded uploads", we stop adding.
            continue 
            
        # Allocate brick
        brick_idx = len(brick_pool)
        brick = [0] * (BRICK_TOTAL_SIZE ** 3)
        
        # Copy core
        for x in range(BRICK_CORE_SIZE):
            for y in range(BRICK_CORE_SIZE):
                for z in range(BRICK_CORE_SIZE):
                    lx, ly, lz = page_x * BRICK_CORE_SIZE + x, page_y * BRICK_CORE_SIZE + y, page_z * BRICK_CORE_SIZE + z
                    val = logical_grid.get(lx, ly, lz)
                    # Map to brick index (apron is 1 texel thick)
                    # Brick indices 0..9, 0 is apron, 1..8 is core? 
                    # Source says "8^3 core wrapped in one-texel apron". 
                    # Let's assume core is centered or offset. 
                    # Standard: apron at 0 and 9. Core at 1..8.
                    brick_idx_x = x + 1
                    brick_idx_y = y + 1
                    brick_idx_z = z + 1
                    brick[brick_idx_x + brick_idx_y * BRICK_TOTAL_SIZE + brick_idx_z * BRICK_TOTAL_SIZE**2] = val
        
        # Fill apron
        for x in range(BRICK_TOTAL_SIZE):
            for y in range(BRICK_TOTAL_SIZE):
                for z in range(BRICK_TOTAL_SIZE):
                    # If on edge, clamp to neighbor
                    if x == 0:
                        src_x = 1
                    elif x == BRICK_TOTAL_SIZE - 1:
                        src_x = BRICK_CORE_SIZE
                    else:
                        src_x = x
                        
                    if y == 0:
                        src_y = 1
                    elif y == BRICK_TOTAL_SIZE - 1:
                        src_y = BRICK_CORE_SIZE
                    else:
                        src_y = y
                        
                    if z == 0:
                        src_z = 1
                    elif z == BRICK_TOTAL_SIZE - 1:
                        src_z = BRICK_CORE_SIZE
                    else:
                        src_z = z
                        
                    # Get logical coordinate for source
                    lx = page_x * BRICK_CORE_SIZE + src_x - 1
                    ly = page_y * BRICK_CORE_SIZE + src_y - 1
                    lz = page_z * BRICK_CORE_SIZE + src_z - 1
                    
                    # Clamp to grid bounds
                    lx = clamp(lx, 0, logical_grid.width - 1)
                    ly = clamp(ly, 0, logical_grid.height - 1)
                    lz = clamp(lz, 0, logical_grid.depth - 1)
                    
                    val = logical_grid.get(lx, ly, lz)
                    brick[x + y * BRICK_TOTAL_SIZE + z * BRICK_TOTAL_SIZE**2] = val
                    
        brick_pool.append(brick)
        page_table[page_key] = brick_idx + 1

    return page_table, brick_pool, ground_max

def raymarch_ray(ray_origin, ray_direction, page_table, brick_pool, ground_max, logical_to_world):
    t = 0.0
    steps = 0
    jitter_offset = get_jittered_sample_offset() # [G] Helper to maintain lattice
    
    while t < ray_length and steps < MAX_RAY_STEPS:
        # Calculate logical page index
        pos = ray_origin + ray_direction * t
        logical_pos = world_to_logical(pos)
        page_x = floor(logical_pos.x / BRICK_CORE_SIZE)
        page_y = floor(logical_pos.y / BRICK_CORE_SIZE)
        page_z = floor(logical_pos.z / BRICK_CORE_SIZE)
        
        entry = page_table.get((page_x, page_y, page_z), 0)
        
        if entry == 0:
            # Empty page
            # Check terrain occlusion
            # Get max ground height for this page
            max_ground_h = ground_max.get((page_x, page_y), -infinity)
            
            # Check if ray is below max ground height within this page
            # Page bounds in logical space:
            p_min_x = page_x * BRICK_CORE_SIZE
            p_max_x = (page_x + 1) * BRICK_CORE_SIZE
            p_min_y = page_y * BRICK_CORE_SIZE
            p_max_y = (page_y + 1) * BRICK_CORE_SIZE
            p_min_z = page_z * BRICK_CORE_SIZE
            p_max_z = (page_z + 1) * BRICK_CORE_SIZE
            
            # Convert page bounds to world space to check intersection with terrain
            # Simplified: if ray z is below max_ground_h at any point in page, don't skip
            # Source: "An empty page is jumped only when it lies wholly above that value"
            # This implies checking if the entire page volume is above the terrain height.
            # If the ray passes through a region where terrain is higher than the page's bottom,
            # we must step.
            
            # Check if page is wholly above terrain
            # Page bottom in world Z: world_z_min = logical_to_world(p_min_z).z
            # If world_z_min > max_ground_h, skip.
            # Note: Terrain height is usually defined at X,Y.
            
            page_bottom_world_z = logical_to_world(p_min_z).z
            if page_bottom_world_z > max_ground_h:
                # Jump to exit face of page
                # Calculate distance to exit of current page along ray
                t_exit = distance_to_page_exit(ray_origin, ray_direction, page_x, page_y, page_z)
                t = t_exit
                # Adjust to lattice
                t = adjust_to_lattice(t, jitter_offset)
                continue
            else:
                # Step through page, no volume fetch
                # Advance by one voxel step
                t += ray_step_size
                steps += 1
                continue
        else:
            # Resident page
            brick_idx = entry - 1
            brick = brick_pool[brick_idx]
            
            # Sample trilinearly
            # Map ray position to brick local coordinates
            local_pos = get_local_brick_coords(pos, page_x, page_y, page_z)
            value = trilinear_sample(brick, local_pos, BRICK_TOTAL_SIZE)
            
            # Apply extinction
            alpha = 1.0 - exp(-value * EXTINCTION_POWER) # [G] Standard Beer-Lambert with power
            
            # Composite
            color = composite(color, value, alpha)
            
            t += ray_step_size
            steps += 1
            
    return color
```

## Subtopics

### [Sparse Brickmap Volume Rendering](2978-sparse-brickmap-volume-rendering.md)
Sparse Brickmap Volume Rendering is a voxel rendering technique that uses a two-level data structure (coarse brick grid and fine voxel bricks) to render sparse volumes efficiently, integrating hardware depth for correct compositing with rasterized geometry. It builds on Sparse Page Table and Brick Pool by replacing the generic page-table indirection with a fixed $8^3$ brick hierarchy optimized for two-level Digital Differential Analyzer (DDA) traversal. Unlike dense voxel grids, it significantly reduces memory footprint by collapsing fully-buried terrain into uniform entries and storing only mixed (surface) bricks in a compact pool.

## Operating characteristics
**Time and Memory Complexity:**
*   Memory usage is bounded by `MAX_VOLUME_BRICKS`. For 8192 bricks, the pool is ~16.4 MB [S1, unofficial].
*   Time complexity per pixel is reduced due to empty-space skipping, but `MAX_RAY_STEPS` remains constant at 384 [S1, unofficial].

**Measured Performance:**
*   On live KATL (wide) data: Old dense grid 6.11M, Cubic at source res 5.08M (-17%), 2.75 power 6.12M (0%) [S1, unofficial].
*   On KATL close: Old 4.57M, Cubic 3.65M (-20%), 2.75 power 4.75M (+4%) [S1, unofficial].
*   On KSEA stratiform: Old 270k, Cubic 193k (-28%), 2.75 power 259k (-4%) [S1, unofficial].
*   Smoke Test: On a live KATL weather payload (456 × 385 × 96 logical texels at 1× coarsening), the system used 2,158 bricks and a 5.0 MB pool [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Full source resolution (up to 2048 cells per axis) without coarsening in common cases [S1, unofficial]. Bounded memory uploads [S1, unofficial].
*   **Limitations:** Limited to skipping only entirely empty bricks (unless combined with terrain checks) [S1, unofficial]. Trilinear filtering requires aprons, increasing brick size from $8^3$ to $10^3$ [S1, unofficial].

## Background
This method was implemented for the web raymarcher in the `approach-viz` project, applying OpenVDB/NanoVDB concepts without the library [S1, unofficial]. It addresses the limitations of dense grids capped at 256 cells per axis, which required coarsening for 120 NM requests [S1, unofficial]. The extinction power of 2.75 was tuned to match the visual brightness of the old renderer within 4% across multiple scenes [S1, unofficial].
