# ExaBricks Hierarchy

Also called: ExaBricks, ExaBricks data structure

## Overview
ExaBricks is a rendering method for Block-Structured Adaptive Mesh Refinement (BS-AMR) data that re-organizes input cells into compact, non-overlapping bricks and builds a spatial partitioning structure called Active Brick Regions (ABRs) to support smooth, high-quality interpolation across level boundaries [S1]. It solves the problem of discontinuous reconstruction and costly cell-location kernels inherent in standard AMR rendering by decoupling storage from the original hierarchy and using hardware-accelerated ray traversal [S1]. Unlike its siblings, which focus on sparse page tables or compressed segmentation, ExaBricks explicitly constructs a secondary spatial index (ABRs) to manage the overlapping support regions of smooth basis functions, enabling efficient space skipping and adaptive sampling via an RTX BVH [S1].

## How it works
The method operates in three stages: brick generation, ABR construction, and ray traversal. It discards the original AMR hierarchy to create a flat, memory-efficient representation suitable for GPU rendering.

### Inputs and Outputs
- **Input:** A set of AMR cells, each defined by lower-left coordinates $(i, j, k)$, level $l$, and a scalar value $v$. Level 0 is the finest level with implicit cell size $1^3$; level $l$ has cell size $2^l$. Cells do not overlap, and coordinates are multiples of $2^l$ [S1].
- **Output:** A set of Bricks, a set of Active Brick Regions (ABRs), and an RTX Bounding Volume Hierarchy (BVH) built over the ABRs [S1].

### Data Structures

**Brick**
Each brick stores a dense 3D array of scalars. The metadata fields are:
- `lower_left`: $(i, j, k)$, the integer coordinates of the brick's corner.
- `level`: $l$, the AMR level of the cells contained.
- `dims`: $(N, M, K)$, the number of cells in each dimension.
- `data`: A 3D array of size $N \times M \times K$ storing the scalar values [S1].

**Active Brick Region (ABR)**
Each ABR represents a rectangular region of space and stores:
- `bbox`: The bounding box of the region.
- `active_bricks`: A list of brick IDs that have non-zero support in this region.
- `min_val`: The minimum scalar value of any cell whose support overlaps the region.
- `max_val`: The maximum scalar value of any cell whose support overlaps the region.
- `finest_cell_width`: The cell width of the finest AMR level influencing this region [S1].

### Step 1: Brick Generation
The input AMR cells are reorganized into bricks using a top-down k-d tree construction. The original hierarchy is discarded.

1.  **Initialize:** Create a root node containing all input cells.
2.  **Check Leaf Condition:** For the current node, check if all cells are on the same AMR level $l$ and if they completely fill their combined bounding box.
    -   If yes, create a leaf node (a Brick). Store its metadata and scalar data.
    -   If no, proceed to split.
3.  **Split:**
    -   Identify the longest axis of the current node's bounding box.
    -   Determine a split position along this axis. The split position must be rounded to an integer multiple of the coarsest cell width present in the node (typically $2^l$ where $l$ is the level of the cells, or the global coarsest level if mixed, but the source specifies "integer multiple of current coarsest cell width" [S1]).
    -   Partition the cells into left and right child nodes based on the split.
4.  **Size Limit:** Ensure no leaf node exceeds 32 cells in width on any axis. If a potential leaf would exceed this, force a split even if the leaf condition is met, or adjust the split to respect the limit [S1].
5.  **Recurse:** Recursively apply steps 2–4 to the child nodes.

### Step 2: ABR Construction
ABRs are built to handle the overlapping support regions of the smooth reconstruction filter.

1.  **Compute Support Fragments:** For each Brick $B$ with level $l$ and cell width $C_w = 2^l$, compute its support region. The support of a cell extends half a cell width beyond its bounds. Thus, the support of a brick is a box exactly half the brick's cell width larger than the brick itself. Create a "brick support fragment" for each brick, storing its support bounding box and the brick's ID [S1].
2.  **Initialize Root:** Compute the bounding box of all support fragments. Create the root ABR node covering this global bounding box, with an initial list of all fragments overlapping it.
3.  **Recursive Subdivision:**
    -   Let $R$ be the current region and $F$ be the list of overlapping fragments.
    -   If $F$ is empty, the region is empty; discard.
    -   If no partitioning plane can be found (all fragments cover the region or boundaries are coincident), create a leaf ABR. Set `active_bricks` to the IDs in $F$, and compute `min_val`, `max_val`, and `finest_cell_width` from the cells in those bricks.
    -   Otherwise, find a partitioning plane. Iterate through the boundaries of the fragments in $F$. Select the plane closest to the spatial center of $R$, preferring the widest dimension of $R$ [S1].
    -   Split $R$ into left ($R_L$) and right ($R_R$) sub-regions.
    -   Partition $F$ into $F_L$ (overlapping $R_L$) and $F_R$ (overlapping $R_R$).
    -   Recurse on $(R_L, F_L)$ and $(R_R, F_R)$.

### Step 3: Ray Traversal and Reconstruction
1.  **Build BVH:** Construct an RTX BVH over the leaf ABRs.
2.  **Ray Marching:** For each ray, traverse the BVH.
    -   **Space Skipping:** If a ray intersects an ABR leaf where `min_val` == `max_val` (and the value is background/empty), skip the region.
    -   **Adaptive Sampling:** Use `finest_cell_width` of the current ABR leaf to determine the sampling step size, ensuring the sampling frequency adapts to the finest level in that region [S1].
3.  **Sample Reconstruction:** When a sample point $p$ falls within an ABR leaf:
    -   Retrieve the list of `active_bricks`.
    -   For each brick, iterate through its cells. A cell $C_i$ contributes if $p$ is within its support.
    -   Compute the basis function value and accumulate the weighted sum.

#### Basis Function and Reconstruction Formula
The method uses the hat-shaped basis function (linear B-spline) [S1]:

$$ \hat{h}(x) = \max(1 - x, 0) $$

For a cell $C$ of width $C_w$, the basis function at position $p$ is:

$$ \hat{H}_C(p) = \hat{h}\left(\frac{|C_{p_x} - p_x|}{C_w}\right) \hat{h}\left(\frac{|C_{p_y} - p_y|}{C_w}\right) \hat{h}\left(\frac{|C_{p_z} - p_z|}{C_w}\right) $$

The reconstructed value $B(p)$ is the normalized weighted sum of all cells $C_i$ with non-zero support at $p$:

$$ B(p) = \frac{\sum_{C_i} \hat{H}_{C_i}(p) C_{v_i}}{\sum_{C_i} \hat{H}_{C_i}(p)} $$

where $C_{v_i}$ is the scalar value of cell $C_i$ [S1].

def create_brick(cells, level):
    """
    Creates a Brick data structure from a list of cells at the same level.
    """
    # Determine dimensions and lower-left
    # Cells are at integer coordinates multiples of 2^level
    # Brick dims N, M, K are derived from the extent of cells
    min_i = min(c['i'] for c in cells)
    min_j = min(c['j'] for c in cells)
    min_k = min(c['k'] for c in cells)
    
    # Assuming cells form a contiguous block
    # N = (max_i - min_i) / 2^level + 1
    # ... similar for M, K
    
    brick = Brick(
        lower_left=(min_i, min_j, min_k),
        level=level,
        dims=(N, M, K), # Calculated from extent
        data=map_cells_to_array(cells, N, M, K)
    )
    return brick

def build_abrs(bricks):
    """
    Builds Active Brick Regions.
    bricks: List of Brick objects.
    Returns: List of ABR leaf nodes.
    """
    # 1. Create support fragments
    fragments = []
    for brick in bricks:
        l = brick.level
        cell_width = 2**l
        # Support extends half cell width beyond brick bounds
        # Brick bounds: [i, i + N*cell_width)
        # Support bounds: [i - cell_width/2, i + N*cell_width + cell_width/2)
        bbox = expand_bbox(brick.bbox, cell_width / 2.0)
        fragments.append(SupportFragment(bbox=bbox, brick_id=brick.id))
        
    if not fragments:
        return []
        
    global_bbox = get_union_bbox([f.bbox for f in fragments])
    root_abr = ABRNode(bbox=global_bbox, fragments=fragments)
    
    stack = [root_abr]
    leaves = []
    
    while stack:
        node = stack.pop()
        frags = node.fragments
        
        # Find partitioning plane
        plane = find_best_split_plane(node.bbox, frags)
        
        if plane is None:
            # Leaf
            active_ids = [f.brick_id for f in frags]
            # Compute min/max/finest from the actual cells in these bricks
            # This requires accessing the original cell data or storing it in Brick
            min_val, max_val, finest_w = compute_region_stats(active_ids, bricks)
            
            leaf = ABRLeaf(
                bbox=node.bbox,
                active_bricks=active_ids,
                min_val=min_val,
                max_val=max_val,
                finest_cell_width=finest_w
            )
            leaves.append(leaf)
        else:
            # Split
            left_frags, right_frags = partition_frags(frags, plane)
            
            if left_frags:
                left_bbox = split_bbox(node.bbox, plane, side='left')
                stack.append(ABRNode(bbox=left_bbox, fragments=left_frags))
            if right_frags:
                right_bbox = split_bbox(node.bbox, plane, side='right')
                stack.append(ABRNode(bbox=right_bbox, fragments=right_frags))
                
    return leaves

        # Iterate over cells in brick that could influence p
        # Optimization: only check cells whose support overlaps p
        # Support of cell (i,j,k) is [i-Cw/2, i+Cw/2) etc.
        
        # Determine range of cell indices to check
        # ...
        
        for cell in get_cells_in_range(brick, p, Cw):
            # Compute basis function
            # h_hat(x) = max(1 - |x|/Cw, 0)
            hx = max(1.0 - abs(cell.i - p.x) / Cw, 0.0)
            hy = max(1.0 - abs(cell.j - p.y) / Cw, 0.0)
            hz = max(1.0 - abs(cell.k - p.z) / Cw, 0.0)

                numerator += H * cell.v
                denominator += H
                
    if denominator == 0:
        return 0.0 # Or background color
        
    return numerator / denominator

### Edge Cases and Pitfalls
-   **Precision:** The split positions in brick generation must be rounded to integer multiples of the cell width to ensure alignment. Failure to do so may result in gaps or overlaps between bricks [S1].
-   **Empty Regions:** ABRs with no overlapping fragments should be discarded or marked as empty to enable space skipping [S1].
-   **Degenerate Input:** If the input AMR data has gaps (cells do not form a contiguous block), the "completely fill bounding box" check in brick generation will fail, forcing further subdivision. The method assumes Block-Structured AMR layouts where refinement rules prevent arbitrary gaps [S1].

## Subtopics

### [Octant Method](2648-octant-method.md)
A reconstruction strategy for BS-AMR data that maps sample points to scalar values using non-overlapping rectilinear octants. It solves discontinuous interpolation at level boundaries by tiling the domain without gaps, unlike ExaBricks which uses overlapping support regions managed by ABRs. Choose when strict non-overlapping geometric decomposition is preferred over smooth basis function overlap.

## Operating characteristics
-   **Time Complexity:** Brick generation is $O(N \log N)$ or $O(N)$ depending on the k-d tree implementation, where $N$ is the number of cells. ABR construction is also recursive and depends on the number of support overlaps. Ray traversal is $O(\log M)$ for BVH traversal, where $M$ is the number of ABRs.
-   **Memory Complexity:** Stores all cell data in bricks (compact) plus ABR metadata. The ABR structure adds overhead proportional to the number of regions and active bricks per region.
-   **Performance:** The method enables hardware-accelerated ray marching via RTX BVH, allowing for interactive frame rates. It avoids costly per-sample k-d tree traversals for cell location, which were a bottleneck in prior methods like Wald et al. [37] [S1].
-   **Strengths:** High-quality smooth interpolation across AMR level boundaries; efficient space skipping and adaptive sampling; hardware-accelerated traversal.
-   **Limitations:** The basis function's support is not truncated, leading to larger support overlaps and potentially more cells contributing to a single sample compared to nearest-neighbor methods. The ABR construction can be complex for highly heterogeneous data [S1].
-   **When to use:** Interactive direct volume rendering of large AMR datasets requiring smooth gradients and adaptive sampling.
-   **When not to use:** When memory is extremely constrained and the overhead of ABRs is prohibitive, or when nearest-neighbor interpolation is sufficient.

## Background
ExaBricks was introduced by Wald et al. in 2020 in the paper "Ray Tracing Structured AMR Data Using ExaBricks" [S1]. It builds on previous work by Kähler et al. [17] for brick generation and Wald et al. [37] for the basis reconstruction method. The method addresses the limitations of prior AMR rendering techniques that required costly cell location kernels or failed to provide smooth interpolation across level boundaries. It is designed for high-performance computing environments, leveraging RTX hardware for ray traversal.
