# ExaBricks Hierarchy
Also called: ExaBricks, ExaBricks data structure

## Overview
The ExaBricks Hierarchy is a rendering method for Block-Structured Adaptive Mesh Refinement (BS-AMR) data that reorganizes input cells into compact, non-overlapping "bricks" and builds a spatial partitioning structure called Active Brick Regions (ABRs) to support smooth interpolation across level boundaries [S1]. It solves the problem of efficient ray marching and sample reconstruction in AMR data by avoiding costly per-sample cell location kernels and deep hierarchy traversals [S1]. Unlike its siblings, which focus on sparse page tables or compressed segmentation, ExaBricks explicitly constructs a secondary spatial index (ABRs) over brick support regions to enable hardware-accelerated traversal via an RTX BVH while maintaining $C^0$ continuity using a basis reconstruction filter [S1].

## How it works
The method operates in three stages: brick generation, ABR construction, and ray traversal.

### Inputs and Outputs
**Inputs:**
*   A set of AMR cells, each defined by lower-left coordinates $(i, j, k)$, level $l$, and a scalar value $v$.
*   Level $0$ is the finest level with implicit cell size $1^3$. Level $l$ has cell size $2^l$. Coordinates are multiples of $2^l$ [S1].

**Outputs:**
*   A set of Bricks.
*   A set of Active Brick Regions (ABRs).
*   An RTX Bounding Volume Hierarchy (BVH) built over the ABRs.

### Data Structures

**Brick**
Each brick stores:
*   `lower_left`: Tuple $(i, j, k)$ of the lower-left corner coordinates.
*   `level`: Integer $l$.
*   `dimensions`: Tuple $(N, M, K)$, the number of cells in each dimension.
*   `values`: A separate 3D array of scalars, indexed by local brick coordinates [S1].

**Active Brick Region (ABR)**
Each ABR leaf stores:
*   `bounding_box`: The spatial extent of the region.
*   `active_bricks`: List of Brick IDs that influence this region.
*   `min_value`: Minimum scalar value of any cell whose support overlaps the region.
*   `max_value`: Maximum scalar value of any cell whose support overlaps the region.
*   `finest_cell_width`: Cell width of the finest AMR level influencing the region [S1].

### Step 1: Brick Generation
Bricks are generated by discarding the original AMR hierarchy and reorganizing cells into compact, non-overlapping groups of same-level cells [S1].

1.  Build a k-d tree top-down from the input cells.
2.  For the current node, check if all cells are on the same AMR level and completely fill their combined bounding box.
3.  If yes, create a leaf node (a Brick).
4.  If no, split the node along the longest axis of the bounding box.
5.  Round split positions to an integer multiple of the current coarsest cell width.
6.  Limit leaf dimensions to at most 32 cells wide on any axis to ensure fine granularity for space skipping [S1].

### Step 2: Active Brick Region (ABR) Construction
ABRs partition space based on the support regions of the bricks, handling the overlap caused by smooth interpolation [S1].

1.  **Compute Support:** For each brick $B$, compute its support region. The support of a cell $C$ is a box extending half a cell width beyond the cell. The support of a brick is the union of its cells' supports, resulting in a box exactly half the brick's cell width larger than the brick itself [S1].
2.  **Create Fragments:** Create a list of "brick support fragments," where each fragment contains the brick's support bounding box and its Brick ID.
3.  **Compute Global Bounds:** Calculate the bounding box of all fragments.
4.  **Recursive Subdivision:**
    *   Input: A region (initially global bounds) and a list of overlapping fragments.
    *   Find a partitioning plane: Iterate through fragment boundaries. Select the plane closest to the region's spatial center, preferring the widest dimension [S1].
    *   If no valid plane exists (all fragments overlap the entire region), create a leaf node containing the current list of brick IDs.
    *   Else, partition the region into left and right sub-regions. Sort fragments into left/right subtrees based on overlap. Recurse [S1].
5.  **Compute Metadata:** For each resulting leaf ABR, compute `min_value`, `max_value`, and `finest_cell_width` from the active bricks [S1].

### Step 3: Ray Traversal and Reconstruction
1.  Build an RTX BVH over the ABRs [S1].
2.  For each ray, traverse the BVH to identify active ABRs.
3.  For each sample point $p$ within an active ABR:
    *   Retrieve the list of active bricks from the ABR leaf.
    *   Identify cells within those bricks that have non-zero support at $p$.
    *   Compute the reconstructed value using the basis function [S1].

#### Basis Reconstruction Formula
The basis function for a cell $C$ of width $C_w$ is:
$$ \hat{H}_C(p) = \hat{h}\left(\frac{|C_{p_x} - p_x|}{C_w}\right) \hat{h}\left(\frac{|C_{p_y} - p_y|}{C_w}\right) \hat{h}\left(\frac{|C_{p_z} - p_z|}{C_w}\right) $$
where $\hat{h}(x) = \max(1 - x, 0)$ [S1].

The reconstruction at position $p$ is:
$$ B(p) = \frac{\sum_{C_i} \hat{H}_{C_i}(p) C_{v_i}}{\sum_{C_i} \hat{H}_{C_i}(p)} $$
where $C_i$ are cells with non-zero support at $p$, and $C_{v_i}$ is the data value [S1].

#### Pseudocode

```python
def generate_bricks(cells):
    """
    Reorganizes AMR cells into non-overlapping bricks.
    cells: List of dicts with keys 'i', 'j', 'k', 'l', 'v'.
    Returns: List of Brick objects.
    """
    # Build k-d tree top-down
    root = KDNode(cells)
    bricks = []
    
    def build(node):
        # Check if leaf condition is met
        levels = set(c['l'] for c in node.cells)
        if len(levels) == 1 and cells_fill_bbox(node.cells, node.bbox):
            # Create Brick
            level = node.cells[0]['l']
            cell_width = 2 ** level
            # Determine dimensions N, M, K
            # (Implementation detail: count cells in each dim based on bbox and level)
            brick = Brick(
                lower_left=node.bbox.min,
                level=level,
                dimensions=compute_dimensions(node.cells, level),
                values=extract_values(node.cells, level)
            )
            bricks.append(brick)
            return
        
        # Split along longest axis
        axis = longest_axis(node.bbox)
        split_pos = round_to_multiple(find_split(node.cells, axis), cell_width_of_coarsest(node.cells))
        
        left_cells, right_cells = split_cells(node.cells, axis, split_pos)
        node.left = KDNode(left_cells)
        node.right = KDNode(right_cells)
        build(node.left)
        build(node.right)

    build(root)
    return bricks

def compute_brick_support(brick):
    """
    Computes the support box for a brick.
    Extends half the cell width beyond the brick bounds.
    """
    cell_width = 2 ** brick.level
    half_width = cell_width / 2.0
    support_min = brick.lower_left - half_width
    support_max = brick.lower_left + brick.dimensions * cell_width + half_width
    return BBox(support_min, support_max)

def construct_abrs(bricks):
    """
    Builds Active Brick Regions via recursive subdivision of support fragments.
    """
    # 1. Create fragments
    fragments = []
    for brick_id, brick in enumerate(bricks):
        support = compute_brick_support(brick)
        fragments.append(SupportFragment(box=support, brick_id=brick_id))
    
    # 2. Global bounds
    global_bbox = union_boxes([f.box for f in fragments])
    
    # 3. Recursive subdivision
    abrs = []
    
    def subdivide(region, overlapping_fragments):
        # Find best partitioning plane
        plane = find_best_plane(region, overlapping_fragments)
        
        if plane is None:
            # Leaf node
            min_val = min(bricks[f.brick_id].values) for f in overlapping_fragments)
            max_val = max(bricks[f.brick_id].values) for f in overlapping_fragments)
            finest_level = min(f.brick_id.level for f in overlapping_fragments)
            
            leaf = ABRLeaf(
                bounding_box=region,
                active_bricks=[f.brick_id for f in overlapping_fragments],
                min_value=min_val,
                max_value=max_val,
                finest_cell_width=2 ** finest_level
            )
            abrs.append(leaf)
            return leaf
        
        # Split
        left_fragments, right_fragments = partition_fragments(overlapping_fragments, plane)
        left_region, right_region = split_region(region, plane)
        
        left_node = subdivide(left_region, left_fragments)
        right_node = subdivide(right_region, right_fragments)
        
        return BVHNode(left_node, right_node, region)

    root = subdivide(global_bbox, fragments)
    return root

def reconstruct_sample(p, abr_leaf, bricks):
    """
    Reconstructs value at point p using basis function.
    """
    numerator = 0.0
    denominator = 0.0
    
    for brick_id in abr_leaf.active_bricks:
        brick = bricks[brick_id]
        # Find cells in brick that influence p
        # Since brick is a 3D grid, compute local indices
        # Only consider cells where basis function > 0
        for cell in get_cells_in_support(p, brick):
            cell_width = 2 ** brick.level
            # Basis function components
            hx = max(1.0 - abs((cell.center_x - p.x) / cell_width), 0.0)
            hy = max(1.0 - abs((cell.center_y - p.y) / cell_width), 0.0)
            hz = max(1.0 - abs((cell.center_z - p.z) / cell_width), 0.0)
            
            weight = hx * hy * hz
            numerator += weight * cell.value
            denominator += weight
            
    if denominator == 0:
        return 0.0 # Or handle as out-of-bounds
    return numerator / denominator
```

### Edge Cases and Pitfalls
*   **Precision:** Split positions in brick generation must be rounded to integer multiples of the coarsest cell width to ensure alignment [S1].
*   **Boundary Conditions:** The basis function support extends beyond the brick. ABRs must correctly handle these overlapping supports to ensure continuity [S1].
*   **Degenerate Input:** If cells do not completely fill their bounding box, they are not merged into a brick leaf and the tree continues splitting [S1].

## Subtopics

### [Octant Method](2648-octant-method.md)
A reconstruction strategy for BS-AMR data that maps sample points to scalar values using non-overlapping rectilinear octants. It ensures $C^0$ continuity across level boundaries without crossing them, unlike dual cell methods. Choose this when strict geometric tiling without boundary crossing is required.

## Operating characteristics
*   **Time Complexity:** Brick generation is $O(N \log N)$ due to k-d tree construction. ABR construction is recursive and depends on the complexity of support overlaps. Ray traversal is $O(\log R)$ where $R$ is the number of ABRs, leveraging hardware acceleration [S1].
*   **Memory Complexity:** Stores bricks (compact same-level cells) and ABRs. ABRs can be more numerous and complex than original bricks due to support overlap [S1].
*   **Performance:** Enables interactive high-quality direct volume rendering with adaptive sampling. Hardware-accelerated ray marching allows for space skipping and adaptive sampling based on ABR metadata [S1].
*   **Strengths:** Avoids costly per-sample k-d tree traversals for cell location. Supports smooth interpolation across level boundaries.
*   **Limitations:** ABRs can be complex in shape and number. The method requires reorganizing data, discarding the original hierarchy [S1].

## Background
The ExaBricks Hierarchy was introduced in a 2020 paper by Wald et al. [S1]. It builds on prior work by Kähler et al. [17] for brick generation and Wald et al. [37] for the basis reconstruction method. The method is designed for rendering large-scale AMR data, such as that from the Exajet simulation, on modern GPUs with RTX capabilities [S1].
