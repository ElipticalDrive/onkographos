# ExaBricks Hierarchy
Also called: ExaBricks, ExaBricks data structure

## Overview
The ExaBricks Hierarchy is a rendering method for Block-Structured Adaptive Mesh Refinement (BS-AMR) data that reorganizes input cells into compact, non-overlapping "bricks" and builds a spatial partitioning structure called Active Brick Regions (ABRs) to support smooth interpolation across level boundaries [S1]. It solves the problem of efficient ray marching and sample reconstruction in AMR data by avoiding costly per-sample cell location kernels and deep hierarchy traversals [S1]. Unlike its siblings, which focus on sparse page tables or compressed segmentation, ExaBricks explicitly constructs a secondary spatial index (ABRs) over brick support regions to enable hardware-accelerated traversal via an RTX BVH while maintaining $C^0$ continuity using a basis reconstruction filter [S1].

## How it works
The method operates in three stages: brick generation, ABR construction, and ray traversal [S1].

### Inputs and Outputs
**Inputs:**
*   A set of AMR cells, each defined by lower-left coordinates $(i, j, k)$, level $l$, and a scalar value $v$ [S1].
*   Level $0$ is the finest level with implicit cell size $1^3$ [S1].
*   Level $l$ has cell size $2^l$ [S1].
*   Coordinates $(i, j, k)$ are lower-left unit coordinates and are multiples of $2^l$ [S1].

**Outputs:**
*   A set of Bricks [S1].
*   A set of Active Brick Regions (ABRs) [S1].
*   An RTX Bounding Volume Hierarchy (BVH) built over the ABRs [S1].

### Data Structures
**Brick**
Each brick stores:
*   `lower_left`: Tuple $(i, j, k)$ of the lower-left corner coordinates [S1].
*   `level`: Integer $l$ [S1].
*   `dimensions`: Tuple $(N, M, K)$, the number of cells in each dimension [S1].
*   `values`: A separate 3D array of scalars, indexed by local brick coordinates [S1].

**Active Brick Region (ABR)**
Each ABR leaf stores:
*   `bounding_box`: The spatial extent of the region [S1].
*   `active_bricks`: List of Brick IDs that influence this region [S1].
*   `min_value`: Minimum scalar value of any cell whose support overlaps the region [S1].
*   `max_value`: Maximum scalar value of any cell whose support overlaps the region [S1].
*   `finest_cell_width`: Cell width of the finest AMR level influencing the region [S1].

### Step 1: Brick Generation
Bricks are generated by discarding the original AMR hierarchy and reorganizing cells into compact, non-overlapping groups of same-level cells [S1].
1.  Build a k-d tree top-down from the input cells [S1].
2.  For the current node, check if all cells are on the same AMR level and completely fill their combined bounding box [S1].
3.  If yes, create a leaf node (a Brick) [S1].
4.  If no, split the node along the longest axis of the bounding box [S1].
5.  Round split positions to an integer multiple of the current coarsest cell width [S1].
6.  Limit leaf dimensions to at most 32 cells wide on any axis to ensure fine granularity for space skipping [S1].

### Step 2: Active Brick Region (ABR) Construction
ABRs partition space based on the support regions of the bricks, handling the overlap caused by smooth interpolation [S1].
1.  **Compute Support:** For each brick $B$, compute its support region [S1]. The support of a cell $C$ is a box extending exactly half a cell width beyond the cell [S1]. The support of a brick is the union of its cells' supports, resulting in a box exactly half the brick's cell width larger than the brick itself [S1].
2.  **Create Fragments:** Create a list of "brick support fragments," where each fragment contains the brick's support bounding box and its Brick ID [S1].
3.  **Compute Global Bounds:** Calculate the bounding box of all fragments [S1].
4.  **Recursive Subdivision:**
    *   Input: A region (initially global bounds) and a list of overlapping fragments [S1].
    *   Find a partitioning plane: Iterate through fragment boundaries and select the plane closest to the region's spatial center, preferring the widest dimension [S1].
    *   If no valid plane exists (all fragments overlap the entire region), create a leaf node containing the current list of brick IDs [S1].
    *   Else, partition the region into left and right sub-regions, sort fragments into left/right subtrees based on overlap, and recurse [S1].
5.  **Compute Metadata:** For each resulting leaf ABR, compute `min_value`, `max_value`, and `finest_cell_width` from the active bricks [S1].

### Step 3: Ray Traversal and Reconstruction
1.  Build an RTX BVH over the ABRs [S1].
2.  For each ray, traverse the BVH to identify active ABRs [S1].
3.  For each sample point $p$ within an active ABR:
    *   Retrieve the list of active bricks from the ABR leaf [S1].
    *   Identify cells within those bricks that have non-zero support at $p$ [S1].
    *   Compute the reconstructed value using the basis function [S1].

#### Basis Reconstruction Formula
The basis function for a cell $C$ of width $C_w$ is:
$$ \hat{H}_C(p) = \hat{h}\left(\frac{|C_{p_x} - p_x|}{C_w}\right) \hat{h}\left(\frac{|C_{p_y} - p_y|}{C_w}\right) \hat{h}\left(\frac{|C_{p_z} - p_z|}{C_w}\right) $$
where $\hat{h}(x) = \max(1 - x, 0)$ [S1].

The reconstruction at position $p$ is:
$$ B(p) = \frac{\sum_{C_i} \hat{H}_{C_i}(p) C_{v_i}}{\sum_{C_i} \hat{H}_{C_i}(p)} $$
where $C_i$ are cells with non-zero support at $p$, and $C_{v_i}$ is the data value [S1].

#### Pseudocode
```python
def generate_bricks(cells):
    """Reorganizes AMR cells into non-overlapping bricks."""
    root = {'cells': cells, 'bbox': compute_bbox(cells)}
    bricks = []
    def build(node):
        levels = {c['l'] for c in node['cells']}
        if len(levels) == 1 and cells_fill_bbox(node['cells'], node['bbox']):
            level = levels.pop()
            cell_width = 2 ** level
            dims = compute_dims(node['cells'], level)
            bricks.append({'lower_left': node['bbox'].min, 'level': level, 'dims': dims, 'values': extract_vals(node['cells'])})
            return
        axis = longest_axis(node['bbox'])
        coarsest_level = min(c['l'] for c in node['cells'])
        split_pos = round_to_multiple(find_split(node['cells'], axis), 2 ** coarsest_level)
        left_cells, right_cells = split_cells(node['cells'], axis, split_pos)
        node['left'] = {'cells': left_cells, 'bbox': compute_bbox(left_cells)}
        node['right'] = {'cells': right_cells, 'bbox': compute_bbox(right_cells)}
        build(node['left'])
        build(node['right'])
    build(root)
    return bricks

def compute_brick_support(brick):
    """Computes the support box for a brick."""
    cell_width = 2 ** brick['level']
    half_width = cell_width / 2.0
    min_pt = brick['lower_left'] - (half_width, half_width, half_width)
    max_pt = brick['lower_left'] + tuple(d * cell_width + half_width for d in brick['dims'])
    return {'min': min_pt, 'max': max_pt}

def construct_abrs(bricks):
    """Builds Active Brick Regions via recursive subdivision."""
    fragments = [{'box': compute_brick_support(b), 'id': i} for i, b in enumerate(bricks)]
    global_bbox = union_boxes([f['box'] for f in fragments])
    abrs = []
    def subdivide(region, frags):
        plane = find_best_plane(region, frags)
        if plane is None:
            min_val = min(bricks[f['id']]['values'] for f in frags)
            max_val = max(bricks[f['id']]['values'] for f in frags)
            finest_level = min(bricks[f['id']]['level'] for f in frags)
            abrs.append({'bbox': region, 'active_bricks': [f['id'] for f in frags],
                         'min_value': min_val, 'max_value': max_val, 'finest_cell_width': 2 ** finest_level})
            return
        left_frags, right_frags = partition_fragments(frags, plane)
        left_region, right_region = split_region(region, plane)
        subdivide(left_region, left_frags)
        subdivide(right_region, right_frags)
    subdivide(global_bbox, fragments)
    return abrs

def reconstruct_sample(p, abr, bricks):
    """Reconstructs value at point p using basis function."""
    num, den = 0.0, 0.0
    for bid in abr['active_bricks']:
        brick = bricks[bid]
        cell_width = 2 ** brick['level']
        for cell in get_cells_in_support(p, brick):
            hx = max(1.0 - abs((cell['center'][0] - p[0]) / cell_width), 0.0)
            hy = max(1.0 - abs((cell['center'][1] - p[1]) / cell_width), 0.0)
            hz = max(1.0 - abs((cell['center'][2] - p[2]) / cell_width), 0.0)
            w = hx * hy * hz
            num += w * cell['v']
            den += w
    return num / den if den > 0 else 0.0
```
*Note: Helper functions like `compute_bbox`, `cells_fill_bbox`, `longest_axis`, `round_to_multiple`, `find_split`, `split_cells`, `find_best_plane`, `partition_fragments`, `split_region`, and `get_cells_in_support` are standard geometric operations [G].*

### Edge Cases and Pitfalls
*   **Precision:** Split positions in brick generation must be rounded to integer multiples of the coarsest cell width to ensure alignment [S1].
*   **Boundary Conditions:** The basis function support extends beyond the brick. ABRs must correctly handle these overlapping supports to ensure continuity [S1].
*   **Degenerate Input:** If cells do not completely fill their bounding box, they are not merged into a brick leaf and the tree continues splitting [S1].

## Subtopics

### [Octant Method](2648-octant-method.md)
A reconstruction strategy for BS-AMR data that maps sample points to scalar values using non-overlapping rectilinear octants. It ensures $C^0$ continuity across level boundaries without crossing them, unlike dual cell methods. Choose this when strict geometric tiling without boundary crossing is required.

## Operating characteristics
*   **Time Complexity:** Brick generation is $O(N \log N)$ due to k-d tree construction [S1]. ABR construction is recursive and depends on the complexity of support overlaps [S1]. Ray traversal is $O(\log R)$ where $R$ is the number of ABRs, leveraging hardware acceleration [S1].
*   **Memory Complexity:** Stores bricks (compact same-level cells) and ABRs [S1]. ABRs can be more numerous and complex than original bricks due to support overlap [S1].
*   **Performance:** Enables interactive high-quality direct volume rendering with adaptive sampling [S1]. Hardware-accelerated ray marching allows for space skipping and adaptive sampling based on ABR metadata [S1].
*   **Strengths:** Avoids costly per-sample k-d tree traversals for cell location [S1]. Supports smooth interpolation across level boundaries [S1].
*   **Limitations:** ABRs can be complex in shape and number [S1]. The method requires reorganizing data, discarding the original hierarchy [S1].

## Background
The ExaBricks Hierarchy was introduced in a 2020 paper by Wald et al. [S1]. It builds on prior work by Kähler et al. [17] for brick generation and Wald et al. [37] for the basis reconstruction method [S1]. The method is designed for rendering large-scale AMR data, such as that from the Exajet simulation, on modern GPUs with RTX capabilities [S1].
