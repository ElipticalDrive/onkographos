# Octant Method

Also called: BS-AMR reconstruction strategy

## Overview
The Octant Method is a reconstruction strategy for cell-centered Block-Structured Adaptive Mesh Refinement (BS-AMR) data that maps a sample point $p=(x,y,z)$ to a scalar value $F(p)$ by decomposing the domain into non-overlapping rectilinear octants [S1, unofficial]. It solves the problem where standard interpolation fails at refinement level boundaries due to missing or misaligned neighbors, ensuring $C^0$ continuity across these boundaries while supporting fast implicit ray-isosurface intersections [S1, unofficial]. Unlike dual cell methods which require stitching unstructured meshes and can have dual cells crossing level boundaries, the octant method uses octants that do not extend beyond parent cell bounds, do not cross level boundaries, tile the domain without gaps/overlap, and are rectilinear [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A sample point $P=(x,y,z)$ in 3D space; BS-AMR data consisting of bricks (typically $16 \times 16 \times 16$ cells) with cell-centered data values associated with refinement levels [S1, unofficial]. Each coarser cell is covered by exactly $R \times R \times R$ finer cells, where $R$ is the refinement factor [S1, unofficial].
*   **Output:** A scalar value $F(P)$ representing the interpolated field value at $P$ [S1, unofficial].

**Data Structures:**
*   **Cell ($C$):** The leaf cell containing point $P$. It has a center value $C.v$ and a refinement level $L$ [S1, unofficial].
*   **Octant ($O$):** One of eight sub-cubes into which $C$ is evenly split along unit vectors $(\pm \hat{X}, \pm \hat{Y}, \pm \hat{Z})$ from $C$'s center [S1, unofficial]. Each octant has 8 vertices.
    *   $O(0)$: Coincides with the cell center $C$'s center.
    *   $O(X), O(Y), O(Z)$: Face vertices, lying on the cell faces.
    *   $O(XY), O(YZ), O(XZ)$: Edge vertices, lying on the cell edges.
    *   $O(XYZ)$: Corner vertex, lying on the cell corner.
    *   Vertex naming is based on the direction from the cell center [S1, unofficial].
*   **Dual Cell ($D$):** A logical cell associated with the octant, used to determine vertex values via symmetry [S1, unofficial]. Its vertices $D(0), D(X), \dots$ follow the same naming scheme [S1, unofficial].

**Parameters:**
*   $R$: Refinement factor (integer, typically $>1$) [S1, unofficial].
*   $\epsilon$: A small epsilon value used to minutely shift vertex positions away from the cell center to find coarsest level neighbors [S1, unofficial].

**Algorithm Steps:**
For any point $P$:
1.  **Find Leaf Octant and Dual Cell:** Identify the leaf cell $C$ containing $P$ and its corresponding octant $O$. Identify the corresponding dual cell $D$ on this level [S1, unofficial].
2.  **Initialize Center Vertex:** Set the value of the center vertex $O(0)$ to the cell center value:
    $$ O(0).v = C.v $$
3.  **Compute Boundary Vertices:** For each boundary vertex (face, edge, corner), determine if it lies on a refinement boundary [S1, unofficial].
    *   **Non-Boundary Case:** If all required dual cell corners (e.g., $D(0), D(X)$ for face vertex $O(X)$) exist and are at the same level as $C$, compute the value using non-boundary averaging rules [S1, unofficial]:
        *   Face vertex $O(X)$: Average of two cells.
            $$ O(X).v = \frac{1}{2} (D(0).v + D(X).v) $$
        *   Edge vertex $O(XY)$: Average of four cells spanning the face.
            $$ O(XY).v = \frac{1}{4} (D(0).v + D(X).v + D(Y).v + D(XY).v) $$
        *   Corner vertex $O(XYZ)$: Average of eight vertices of the dual cell.
            $$ O(XYZ).v = \frac{1}{8} \sum_{v \in D.vertices} v.v $$
    *   **Boundary Case:** If at least one input lies on a coarser level [S1, unofficial]:
        *   **Fine Side:** If the current octant $O$ is on the finer level ($O.l > \min(\text{input levels})$), the vertex value is determined by the coarser side [S1, unofficial]. Shift the vertex position $O(v).p$ minutely away from the cell center $C$ in the direction of the vertex offset $dX$ by $\epsilon$, and recursively call the octant function on the shifted position:
            $$ O(v).v = \text{octant}(O(v).p + \epsilon \cdot dX) $$
        *   **Coarse Side:** If the current octant is on the coarser side, compute the vertex value locally using one of four coarser side interpolant options (see below) [S1, unofficial].
4.  **Trilinear Interpolation:** Once all 8 vertex values of octant $O$ are set, perform trilinear interpolation within $O$ to find $F(P)$ [S1, unofficial].

**Coarser Side Interpolant Options:**
When computing the value for the coarser side octant, four options exist [S1, unofficial]:
1.  **Coarsest-Level Lerp:** Perform trilinear interpolation on the coarsest level involved for any of the inputs [S1, unofficial].
2.  **Current-Level Lerp:** Perform trilinear interpolation on the current level [S1, unofficial].
3.  **Basis Function:** Use a basis function interpolation [S1, unofficial].
4.  **Finest-Level Lerp:** Perform trilinear interpolation on the finest level involved [S1, unofficial].

**Pseudocode:**
```python
def octant(P: Point3D) -> float:
    # 1. Find leaf cell C and octant O containing P
    # Implementation details for AMR traversal are not given in the sources. [G]
    oct = find_leaf_octant(P)
    C = oct.cell
    # Implementation details for dual cell construction are not given in the sources. [G]
    D = find_dual_cell(oct)
    
    # 2. Initialize center vertex
    oct.vertices[0].v = C.v
    
    # 3. Compute face vertices (e.g., O(X))
    l_X_min = min(D.vertices[0].level, D.vertices['X'].level)
    l_X_max = max(D.vertices[0].level, D.vertices['X'].level)
    
    if l_X_min == l_X_max:
        oct.vertices['X'].v = (D.vertices[0].v + D.vertices['X'].v) / 2.0
    elif l_X_min < oct.level:
        shift = oct.direction_vector('X') * EPSILON
        oct.vertices['X'].v = octant(oct.vertices['X'].position + shift)
    else:
        # Coarse side: compute locally using one of four interpolant options
        # Implementation details for coarser side vertex computation are not given in the sources. [G]
        oct.vertices['X'].v = compute_coarser_side_vertex(D, 'X')
        
    # 4. Compute edge vertices (e.g., O(XY))
    l_XY_min = min(D.vertices[0].level, D.vertices['X'].level, 
                   D.vertices['Y'].level, D.vertices['XY'].level)
    l_XY_max = max(D.vertices[0].level, D.vertices['X'].level, 
                   D.vertices['Y'].level, D.vertices['XY'].level)
    
    if l_XY_min == l_XY_max:
        oct.vertices['XY'].v = (D.vertices[0].v + D.vertices['X'].v + 
                                D.vertices['Y'].v + D.vertices['XY'].v) / 4.0
    elif l_XY_min < oct.level:
        shift = oct.direction_vector('XY') * EPSILON
        oct.vertices['XY'].v = octant(oct.vertices['XY'].position + shift)
    else:
        oct.vertices['XY'].v = compute_coarser_side_vertex(D, 'XY')

    # 5. Compute corner vertex (O(XYZ))
    l_XYZ_min = min(D.vertices[0].level, D.vertices['X'].level, 
                    D.vertices['Y'].level, D.vertices['Z'].level,
                    D.vertices['XY'].level, D.vertices['YZ'].level, 
                    D.vertices['XZ'].level, D.vertices['XYZ'].level)
    l_XYZ_max = max(D.vertices[0].level, D.vertices['X'].level, 
                    D.vertices['Y'].level, D.vertices['Z'].level,
                    D.vertices['XY'].level, D.vertices['YZ'].level, 
                    D.vertices['XZ'].level, D.vertices['XYZ'].level)
    
    if l_XYZ_min == l_XYZ_max:
        sum_v = (D.vertices[0].v + D.vertices['X'].v + D.vertices['Y'].v + 
                 D.vertices['Z'].v + D.vertices['XY'].v + D.vertices['YZ'].v + 
                 D.vertices['XZ'].v + D.vertices['XYZ'].v)
        oct.vertices['XYZ'].v = sum_v / 8.0
    elif l_XYZ_min < oct.level:
        shift = oct.direction_vector('XYZ') * EPSILON
        oct.vertices['XYZ'].v = octant(oct.vertices['XYZ'].position + shift)
    else:
        oct.vertices['XYZ'].v = compute_coarser_side_vertex(D, 'XYZ')

    # 6. Trilinear interpolation within octant O at point P
    dx = (P.x - oct.origin.x) / oct.size
    dy = (P.y - oct.origin.y) / oct.size
    dz = (P.z - oct.origin.z) / oct.size
    v000 = oct.vertices[0].v
    v100 = oct.vertices['X'].v
    v010 = oct.vertices['Y'].v
    v001 = oct.vertices['Z'].v
    v110 = oct.vertices['XY'].v
    v101 = oct.vertices['XZ'].v
    v011 = oct.vertices['YZ'].v
    v111 = oct.vertices['XYZ'].v
    return ((1-dx)*(1-dy)*(1-dz)*v000 + dx*(1-dy)*(1-dz)*v100 + 
            (1-dx)*dy*(1-dz)*v010 + dx*dy*(1-dz)*v110 + 
            (1-dx)*(1-dy)*dz*v001 + dx*(1-dy)*dz*v101 + 
            (1-dx)*dy*dz*v011 + dx*dy*dz*v111)
```

**Edge Cases and Pitfalls:**
*   **Accuracy Sacrifice:** Setting fine-side vertex values based on the coarse-side interpolant ensures continuity but sacrifices some accuracy at the boundary [S1, unofficial].
*   **Recursion Depth:** The recursive call for fine-side vertices must terminate [S1, unofficial]. Since the shift moves the point to the coarser side, and the coarser side computes locally, recursion depth is limited by the refinement levels [S1, unofficial].
*   **Epsilon Value:** A small epsilon value is used to minutely shift vertex positions away from the cell center to find coarsest level neighbors [S1, unofficial].

## Subtopics

### [Optimized Octant Generation](3412-optimized-octant-generation.md)
An optimization for isosurface extraction on AMR data that reduces redundant computation by merging 'inner' octants into dual cells, preserving crack-free continuity at level boundaries. It builds on the [Octant Method](2648-octant-method.md) by avoiding the recomputation of vertex values for shared inner octants, which the naïve approach computes eight times. Choose it when minimizing redundant vertex computations is critical.

### [Generalized Trilinear Interpolation](9462-generalized-trilinear-interpolation.md)
A reconstruction method for cell-centered BS-AMR data that computes field values at arbitrary points, specifically octant vertices, ensuring $C^0$ continuity across refinement level boundaries. It solves the problem where standard trilinear interpolation fails due to missing or misaligned neighbors at different resolution levels, by using virtual unstructured elements to initialize octant vertices with precomputed weights from a multivariate polynomial basis. Choose it when high-quality vertex initialization is required before trilinear interpolation within an octant.

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial]. The method involves finding the leaf cell, computing vertex values (potentially recursively), and trilinear interpolation [S1, unofficial]. The recursion depth is bounded by the number of refinement levels [S1, unofficial].
*   **Memory Complexity:** Not given in the sources [S1, unofficial]. The method requires storing cell-centered data and potentially dual cell information [S1, unofficial].
*   **Measured Performance:** Not given in the sources [S1, unofficial].
*   **Strengths:**
    *   Ensures $C^0$ continuity across level boundaries [S1, unofficial].
    *   Uses rectilinear octants that do not cross level boundaries, simplifying implementation compared to unstructured dual cell methods [S1, unofficial].
    *   Tiles the domain without gaps or overlap [S1, unofficial].
    *   Supports fast implicit ray-isosurface intersections [S1, unofficial].
*   **Limitations:**
    *   Sacrifices accuracy at refinement boundaries to maintain continuity [S1, unofficial].
    *   Requires careful handling of boundary conditions and recursive calls [S1, unofficial].
*   **When to Use:** Suitable for BS-AMR data visualization and isosurface ray tracing where continuity across level boundaries is critical and rectilinear interpolation is desired [S1, unofficial].
*   **When Not to Use:** When high accuracy at refinement boundaries is more important than continuity, or when non-rectilinear interpolation methods are preferred [S1, unofficial].

## Background
The Octant Method was introduced as a novel BS-AMR reconstruction strategy in the paper "CPU Isosurface Ray Tracing of Adaptive Mesh Refinement Data" by Feng et al. (VIS 2018) [S1, unofficial]. It addresses the challenges of interpolating BS-AMR data, where standard interpolation methods fail due to grid topology changes at level boundaries [S1, unofficial]. The method leverages the symmetry between cells and octants to construct a locally rectilinear interpolation scheme [S1, unofficial].
