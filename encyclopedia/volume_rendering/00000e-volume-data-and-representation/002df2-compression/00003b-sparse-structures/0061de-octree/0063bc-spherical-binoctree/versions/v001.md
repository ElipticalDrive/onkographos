# Spherical Binoctree

Also called: sphoxel

## Overview
The Spherical Binoctree is a spatial partitioning structure designed to efficiently represent 3D data within a spherical volume, primarily for omnidirectional or spherical volume rendering. It solves the problem of sphoxel elongation (where cells become excessively stretched radially) by using binary subdivision in the radial direction while maintaining octree-like subdivision in angular directions. It is distinct from standard Cartesian octrees by its spherical bounds and from standard spherical octrees by its radial binary splitting.

## How it works
**Inputs:** A spherical volume defined by near and far radii; a minimum solid angle threshold $\alpha_{min}$ for leaf nodes; camera poses and depth estimates for initialization.
**Outputs:** A tree structure where each node (sphoxel) stores its boundary coordinates and index; a list of intersecting sphoxels for a given ray.

**Data Structures:**
Each sphoxel stores its boundary in spherical coordinates as a tuple: $[r_{min}, r_{max}, \theta_{min}, \theta_{max}, \phi_{min}, \phi_{max}]$ and its unique index [S1].

**Algorithm Steps:**

1.  **Initialization:** Estimate depth for the initial tree construction using a trained model [S1]. Estimate camera poses using Structure from Motion (e.g., OpenVSLAM) [S1]. Extract a dense 3D point cloud using spherical rectification [S1].
2.  **Tree Construction:** Subdivide the spherical space recursively.
    *   **Radial Direction:** Use binary subdivision (split into two) to prevent elongation as $r$ increases [S1].
    *   **Angular Direction:** Use octree subdivision (split into eight) in polar ($\theta$) and azimuthal ($\phi$) directions [S1].
    *   **Termination:** Continue subdivision until all sphoxels reach a minimum solid angle $\alpha_{min}$ [S1].
3.  **Parameter Setting:** Set $\alpha_{min}$ between $5 \times 10^{-4}$ and $10^{-3}$, derived from the baseline and image sizes [S1].
4.  **Pole Handling:** If an angular subdivision spans a pole, the resulting structure is a spherical sector (cone and spherical cap) containing the polar axis. Divide this sector around the polar axis and approximate the segments as triangle-based frusta [S1].
5.  **Ray Intersection (Sphoxel Test):**
    *   Approximate each sphoxel as a trapezoidal prism (square-based frustum) sharing the same vertices as the curved surfaces [S1].
    *   Define the sphoxel center as the mean position of its eight vertices [S1].
    *   Define the sphoxel radius $R$ as the distance from the center to the farthest vertex [S1].
    *   Perform ray-triangle intersection tests for all triangles comprising the cuboid faces of the approximation [S1].
    *   A ray intersects a sphoxel if intersections are detected with a pair of triangles—one front-facing, one back-facing—that form the faces [S1].
6.  **Surface Existence Test:**
    *   Compute the absolute Signed Distance Function (SDF) value $\|d\|$ at the sphoxel center [S1].
    *   A surface exists in the sphoxel if $\|d\| < R$ [S1].
7.  **Traversal:** Traverse the binoctree in breadth-first order to fetch intersecting sphoxels $V$. This order relieves bottlenecks caused by unnecessary intersection computations when the number of marked voxels exceeds 10,000 [S1].

def sphoxel_intersect(ray_origin, ray_direction, sphoxel):
    """
    Tests if a ray intersects a sphoxel using the trapezoidal prism approximation.
    """
    # 1. Approximate sphoxel as trapezoidal prism (square-based frustum)
    vertices = sphoxel.get_vertices()
    triangles = sphoxel.get_triangles_from_vertices(vertices)
    
    # 2. Perform ray-triangle intersection tests
    front_intersections = []
    back_intersections = []
    
    for tri in triangles:
        hit = ray_triangle_intersect(ray_origin, ray_direction, tri)
        if hit:
            if tri.is_front_facing(ray_direction):
                front_intersections.append(hit)
            else:
                back_intersections.append(hit)
                
    # 3. Check for pair of intersections (one front, one back)
    if front_intersections and back_intersections:
        return True
    return False

def sphoxel_surface_exists(sphoxel, sdf_value_at_center):
    """
    Determines if a surface exists within the sphoxel.
    """
    # Center is mean of 8 vertices
    center = mean(sphoxel.vertices)
    # Radius is distance from center to farthest vertex
    R = max(distance(center, v) for v in sphoxel.vertices)
    
    # Surface exists if absolute SDF < R
    return abs(sdf_value_at_center) < R

## Subtopics

### Sphoxel Intersection and Surface Existence Test
A novel intersection and surface existence test for sphoxels, replacing conventional Cartesian grid-based algorithms due to irregular sphoxel shapes. It approximates each sphoxel as a trapezoidal prism (square-based frustum) sharing the same vertices as the original curved surfaces. A ray intersects a sphoxel if intersections are detected with a pair of triangles—one front-facing, one back-facing—that form the faces. Surface existence is determined by comparing the absolute SDF value at the sphoxel center to the sphoxel radius $R$ (distance from center to farthest vertex); a surface exists if $\|d\| < R$ [S1].

## Operating characteristics
**Time Complexity:** Breadth-first traversal is used to relieve bottlenecks when the number of marked voxels exceeds 10,000 [S1].
**Memory Complexity:** Stores boundary coordinates $[r_{min}, r_{max}, \theta_{min}, \theta_{max}, \phi_{min}, \phi_{max}]$ and index for each sphoxel [S1].
**Strengths:** Prevents sphoxel elongation in radial direction; efficient for large spherical spaces; handles omnidirectional data well [S1].
**Limitations:** Irregular shapes require complex intersection tests (triangle-based) instead of simple AABB checks; pole handling requires special approximation [S1].
**When to use:** Omnidirectional volume rendering, spherical scene reconstruction [S1].
**When not to use:** Cartesian grid-based scenes where standard octrees are sufficient [S1].

## Background
The Spherical Binoctree was introduced in the context of OmniSDF, a method for scene reconstruction using omnidirectional signed distance functions. It builds on the concept of binoctrees but adapts them for spherical spaces. The method uses structure from motion (OpenVSLAM) for camera pose estimation and spherical rectification for point cloud extraction [S1].
