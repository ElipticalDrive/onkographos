# fV-SRN
## Overview
fV-SRN is an interactive rendering method for compressed Implicit Neural Representations (INRs) that uses a volumetric latent grid and a lightweight MLP to achieve real-time frame rates by fusing network evaluation into shared memory [S2, unofficial]. It differs from its sibling [Context-based NeRF Compression (CNC)](16592-context-based-nerf-compression-cnc.md) and the baseline [Neurcomp](16592-context-based-nerf-compression-cnc.md) by eliminating global memory access during inference, achieving a 150–200× rendering speedup [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volumetric dataset (up to $1024^3$ resolution) and camera parameters.
*   **Output:** Rendered images at interactive frame rates (5–10 FPS at $512^2$ resolution) [S2, unofficial].

**Data Structures:**
1.  **Volumetric Latent Grid:** A 3D grid storing learned features.
    *   **Resolution:** Typically $32^3$ [S2, unofficial].
    *   **Features:** 16 features per vertex [S2, unofficial].
    *   **Layout:** Uniformly spaced in the domain of the input volume.
2.  **Lightweight MLP:** A small neural network that decodes the latent features.
    *   **Architecture:** Four layers, 32 channels [S2, unofficial].
    *   **Function:** Maps latent features to density, gradient, and curvature.

**Algorithm Steps:**
1.  **Training:** Train the volumetric latent grid and the lightweight MLP to represent the input volume. The training loop follows the configuration recommended in the original study [S1].
    *   **Training Details:** The method was optimized for 200 epochs, generating 2563 samples per epoch, equivalent to 51.2k steps [S1].
    *   **Implementation:** The training system is implemented using PyTorch [S1].
2.  **Inference (Rendering):**
    1.  For each ray, sample points in the volume.
    2.  Retrieve the latent features from the volumetric latent grid for the sampled points.
    3.  Execute a custom GPU TensorCore kernel that fuses the entire network evaluation (grid lookup + MLP forward pass) into 48 kB of on-chip shared memory [S2, unofficial].
    4.  This fusion eliminates global memory access during inference [S2, unofficial].
    5.  Predict density, gradient, and curvature in a single forward pass [S2, unofficial].
    6.  Use the predicted gradient and curvature to avoid finite-difference gradient computation, yielding an additional 12× speedup for shaded rendering [S2, unofficial].

**Pseudocode:**
```python
# fV-SRN Inference Kernel (Conceptual)
# Assumes a custom CUDA kernel implementation for the fusion step

def render_fvsrn(volume_data, camera_params, latent_grid, mlp_weights):
    """
    Renders a volume using fV-SRN.
    
    Args:
        volume_data: Input 3D volume (used for training, not inference).
        camera_params: Camera position and orientation.
        latent_grid: 3D tensor of shape (32, 32, 32, 16) containing learned features.
        mlp_weights: Weights for the 4-layer, 32-channel MLP.
        
    Returns:
        Rendered image.
    """
    # 1. Initialize output image
    image = zeros(camera_params.resolution)
    
    # 2. For each pixel, cast a ray
    for y in range(camera_params.height):
        for x in range(camera_params.width):
            ray = cast_ray(camera_params, x, y)
            
            # 3. Sample points along the ray
            samples = sample_ray(ray, volume_bounds)
            
            # 4. Retrieve latent features for samples
            # This step is fused into the shared memory kernel in practice
            latent_features = trilinear_interpolate(latent_grid, samples)
            
            # 5. Execute fused kernel: Grid Lookup + MLP Forward Pass
            # The kernel loads latent_features and mlp_weights into 48 kB shared memory
            # and performs the matrix multiplications for the 4-layer MLP
            density, gradient, curvature = fused_tensor_core_kernel(
                latent_features, 
                mlp_weights,
                shared_memory_size=48*1024 # 48 kB
            )
            
            # 6. Compute color using density and shading (using predicted gradient/curvature)
            color = compute_shading(density, gradient, curvature, ray)
            image[y, x] = color
            
    return image
```

**Parameters:**
*   **Latent Grid Resolution:** $32^3$ [S2, unofficial].
*   **MLP Layers:** 4 [S2, unofficial].
*   **MLP Channels:** 32 [S2, unofficial].
*   **Shared Memory Size:** 48 kB [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Training Memory:** Training requires the full volume in GPU memory, limiting use to offline workflows or requiring sufficient VRAM [S2, unofficial].
*   **Precision:** The method relies on a custom GPU TensorCore kernel; precision issues may arise if the shared memory fusion is not carefully implemented [S2, unofficial].

## Subtopics

### Context-based NeRF Compression (CNC)
A sibling method that uses context-based compression for NeRFs. It differs from fV-SRN by focusing on compression efficiency rather than inference speed via shared memory fusion. Choose CNC when storage/bandwidth is the primary constraint. [Link](16592-context-based-nerf-compression-cnc.md)

## Operating characteristics
*   **Time Complexity:** Rendering is accelerated by 150–200× over Neurcomp [S2, unofficial]. Shaded rendering is accelerated by an additional 12× [S2, unofficial].
*   **Memory Complexity:** Training requires the full volume in GPU memory [S2, unofficial]. The latent grid is small ($32^3 \times 16$ features), but the MLP weights are minimal (4 layers, 32 channels).
*   **Measured Performance:** 5–10 FPS at $512^2$ resolution on volumes up to $1024^3$ [S2, unofficial].
*   **Strengths:** Real-time interactive rendering; high speedup over previous methods; avoids finite-difference gradient computation.
*   **Limitations:** Training requires significant GPU memory; PyTorch implementation may exaggerate training time differences compared to custom C++ implementations [S1].
*   **When to Use:** When interactive rendering of compressed INRs is required and sufficient GPU memory is available for training.
*   **When Not to Use:** When VRAM is limited during training or when offline rendering is acceptable.

## Background
fV-SRN was introduced by Weiss et al. [S2, unofficial]. It was compared against the proposed method in [S1] on a Linux machine with an NVIDIA RTX 3090Ti using the same number of trainable parameters [S1]. The method addresses the inefficiency of feature grids with fixed, uniform placement by using a lightweight MLP to decode a compressed latent grid [S2, unofficial].
