# Compression Domain Rendering

Also called: Hardware accelerated texture decoding, On-chip decoding

## Overview
Compression Domain Rendering reconstructs volumetric data on the GPU per-fragment by fetching indices from a compressed RGB index texture, using dependent texture fetches to retrieve difference vectors from codebook textures, and adding them to the mean value [S1, unofficial]. It performs on-chip decoding by leveraging the GPU's texture hardware for parallel reconstruction of compressed vector-quantized data [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A compressed volumetric dataset represented as a 3D index texture $I$ and two dependent codebook textures $C_1$ and $C_2$ [S1, unofficial]. The index texture stores RGB values where $R$ is the mean value, and $G, B$ are indices into the codebooks [S1, unofficial]. An address texture $A$ provides relative coordinates within codewords [S1, unofficial].
*   **Output:** Color and opacity values drawn to the framebuffer [S1, unofficial].

**Data Structures**
*   **Index Texture $I$:** A 3D texture map [S1, unofficial]. Each texel is an RGB vector [S1, unofficial]. The resolution is $1/4$ of the original data size in every dimension, assuming $4^3$ blocks [S1, unofficial].
*   **Codebook Textures $C_1, C_2$:** Dependent 2D textures storing difference vectors [S1, unofficial].
*   **Address Texture $A$:** A 3D texture of the same size as the encoded texel region ($4^3$ in the example) [S1, unofficial]. It stores relative addresses to access components within a codeword [S1, unofficial].
    *   $R$-component of $A$: Stores 64 different addresses to index $C_1$ [S1, unofficial].
    *   $G$-component of $A$: Stores 8 different addresses to index $C_2$ [S1, unofficial]. Blocks of $2^3$ adjacent texels share the same address [S1, unofficial].

**Parameters**
*   **Texture Coordinate Wrap Mode:** `GL_REPEAT` for the index texture [S1, unofficial].
*   **Address Texture Interpolation:** Nearest neighbor [S1, unofficial].

**Algorithm Steps**
1.  **Slicing:** Render the 3D index texture sliced in back-to-front or front-to-back order via planes orthogonal to the viewing direction [S1, unofficial]. The number of slices must be sufficient to render the original data, accounting for the expansion of each texel to a $4^3$ block [S1, unofficial].
2.  **Index Fetch:** For each fragment, fetch the texture sample from the index texture $I$ [S1, unofficial]. Let the sample be $I_{rgb} = (I_r, I_g, I_b)$ [S1, unofficial].
3.  **Codebook Fetch:**
    *   Use $I_g$ and $I_b$ to determine the $s$ texture coordinates for $C_1$ and $C_2$ [S1, unofficial].
    *   Determine the $t$ texture coordinates using the address texture $A$ [S1, unofficial]. Let $A_{rgb} = (A_r, A_g, A_b)$ [S1, unofficial].
    *   Fetch the difference vector from $C_1$ using coordinates $(I_g, A_r)$ [S1, unofficial]. Let this be $d_1$ [S1, unofficial].
    *   Fetch the difference vector from $C_2$ using coordinates $(I_b, A_g)$ [S1, unofficial]. Let this be $d_2$ [S1, unofficial].
4.  **Reconstruction:** Add the mean value $I_r$ to the fetched difference information [S1, unofficial]. The final scalar value $v$ is:
    $$ v = I_r + d_1 + d_2 $$
    [S1, unofficial]
5.  **Shading:** Map the final scalar value $v$ to color and opacity via a 1D dependent texture map (color table) [S1, unofficial].
6.  **Rendering:** Draw the color and opacity to the framebuffer [S1, unofficial].

**Pseudocode**
```python
# Inputs:
#   index_tex: 3D texture map for compressed indices (wrap mode: GL_REPEAT)
#   cb1_tex: 2D texture map for first codebook difference vectors
#   cb2_tex: 2D texture map for second codebook difference vectors
#   addr_tex: 3D texture map for relative codeword addresses (interpolation: nearest neighbor)
#   color_tex: 1D texture map for scalar-to-color/opacity mapping
#   uv: fragment coordinates in the current slice
# Outputs:
#   color_opacity: final RGBA value for the framebuffer

def compression_domain_render_fragment(index_tex, cb1_tex, cb2_tex, addr_tex, color_tex, uv):
    # 1. Fetch index sample
    I_sample = texture_fetch(index_tex, uv)
    mean_val = I_sample.r
    index_g = I_sample.g
    index_b = I_sample.b

    # 2. Fetch address sample
    A_sample = texture_fetch(addr_tex, uv)
    addr_r = A_sample.r
    addr_g = A_sample.g

    # 3. Fetch difference vectors from dependent textures
    diff1 = texture_fetch(cb1_tex, vec2(index_g, addr_r))
    diff2 = texture_fetch(cb2_tex, vec2(index_b, addr_g))

    # 4. Reconstruct scalar value
    scalar_value = mean_val + diff1 + diff2

    # 5. Map to color and opacity
    color_opacity = texture_fetch(color_tex, scalar_value)

    # 6. Output
    return color_opacity
```

**Edge Cases and Pitfalls**
*   **Slice Count:** Because each texel of the index texture is expanded to a $4^3$ block during rendering, care must be taken to perform the slicing with as many slices as necessary to render the original data [S1, unofficial].
*   **Address Texture Size:** The address texture only holds addresses for one single block [S1, unofficial]. An enlarged texture as large as the original dataset would allow correct addressing but negates memory savings [S1, unofficial]. The solution is to set the wrap parameter for texture coordinates to `GL_REPEAT` for the index texture, and to periodically repeat the address texture over the domain to yield correct addresses at every fragment [S1, unofficial].
*   **Performance:** There is a loss in performance of about a factor of 2-3 compared to rendering uncompressed data, primarily due to the overhead of dependent texture fetches and shader execution [S1, unofficial].

## Subtopics

### [GPU Decoder with Texture Mapping](1050-gpu-decoder-with-texture-mapping.md)
This method reconstructs volumetric data values on the GPU by mapping output coordinates to texture memory indices, retrieving codebook vectors via dependent texture fetches, and combining them with mean values. It differs from CPU-based decoding by minimizing data transfer between main memory and GPU memory, leveraging the GPU's texture hardware for parallel reconstruction of compressed vector-quantized data.

### Pure Random-Access Decompression
**Definition:** A strategy where data decompression is performed each time the renderer needs to access a single voxel, transmitting data in compressed form from CPU to GPU [S2].
**Steps:** Transmit compressed data from CPU to GPU [S2]. Perform on-demand, fast, and spatially independent decompression for each requested voxel [S2].
**Pitfall:** GPU implementations of random-access (e.g., VQ, HVQ) are costly in performance and rarely implement multisampling or high-quality shading without deferred filtering [S2].
**Comparison:** Unlike partial decompression, this method never fully decompresses the dataset in GPU memory, better exploiting memory bandwidth during transmission [S2].

## Operating characteristics
*   **Time Complexity:** The per-fragment cost involves multiple texture fetches (index, address, two codebooks, color table) [S1, unofficial]. The total time is proportional to the number of fragments and the cost of dependent texture lookups [S1, unofficial].
*   **Memory Complexity:** The index texture is $1/4$ the size of the original data in every dimension, resulting in a significant reduction in memory footprint compared to uncompressed data [S1, unofficial]. The codebook textures and address texture add overhead but are generally small relative to the full dataset [S1, unofficial].
*   **Performance:** The method suffers a performance loss of a factor of 2-3 compared to rendering uncompressed data [S1, unofficial]. This is attributed to the computational cost of the on-chip decoding process [S1, unofficial].
*   **Strengths:** Minimizes data transfer between main memory and GPU memory [S1, unofficial]. Leverages GPU texture hardware for parallel reconstruction [S1, unofficial].
*   **Limitations:** Performance overhead compared to uncompressed rendering [S1, unofficial]. Requires careful handling of texture coordinates and slicing to ensure correct reconstruction of the original data blocks [S1, unofficial].

## Background
The method addresses the challenge of rendering massive volumetric datasets by keeping data in compressed format at all stages except during transient local reconstruction [S1, unofficial]. It builds on the Deferred Filtering Architecture for Compressed Volumes, which coordinates visibility- and resolution-aware adaptive data loading with GPU-accelerated per-frame data decompression, deblocking, and rendering [S1, unofficial].
