# Stripe-based On-the-fly Decoding

Also called: Fraedrich stripe decoding, Stripe-based Block Decompression (Fraedrich)

## Overview
Stripe-based On-the-fly Decoding is a general approach for applying sequential data compression schemes to blocks of data, decoded on-the-fly by the GPU in a single render pass by decomposing blocks into parallel stripes [S1, S2]. Unlike [Compression Domain Rendering](960-compression-domain-rendering.md), which often operates directly in the transform domain, or [CPU-Based Block Decompression](7197-cpu-based-block-decompression.md), which offloads decompression to the host, this method performs decompression entirely on the GPU [S1, S2], integrating with the [Deferred Filtering Architecture for Compressed Volumes](857-deferred-filtering-architecture-for-compressed-volumes.md) [Parent].

## How it works
**Inputs:** Compressed block data (index texture) and block dimensions [S1, S2].
**Outputs:** Multiple render targets (MRTs) containing decoded scalar voxel values, formatted as textures for subsequent volume rendering [S1, S2].

**Data Structures:**
1. **Index Texture:** A 2D texture storing compressed indices or control data for the block [S1, S2].
2. **Multiple Render Targets (MRTs):** Framebuffer attachments for decoded scalar values, written into different color channels [S1, S2].

**Steps:**
1. Decompose the compressed block into parallel stripes of voxels [S1, S2].
2. Render a quad with the size of the index texture [S1, S2].
3. Each fragment decodes one stripe of the block [S1, S2].
4. The decoded scalar values are written into different color channels of the multiple render targets [S1, S2].
5. These render targets are used as textures for volume rendering in a subsequent render pass [S1, S2].

**Pseudocode:**
```python
def decode_stripe_fragment(stripe_id, index_texture_data):
    # Fetch compressed data for the current stripe
    compressed_data = index_texture_data[stripe_id]
    # [G] The exact decoding algorithm depends on the compression format
    decoded_voxels = apply_inverse_compression(compressed_data)
    # Write decoded scalar values to MRT color channels
    for i, value in enumerate(decoded_voxels):
        channel_index = i % 4
        mrt_channels[channel_index][i // 4] = value

def run_decompression_pass(index_texture_data, num_stripes):
    # Initialize MRT storage for decoded voxels
    mrt_channels = [[0.0] * num_stripes for _ in range(4)]
    # Process each stripe via fragment shader simulation
    for stripe_id in range(num_stripes):
        decode_stripe_fragment(stripe_id, index_texture_data)
    return mrt_channels
```

**Edge Cases and Pitfalls:**
*   **Compression Scheme Compatibility:** The method is a general approach but requires the sequential compression scheme to be decodable on the GPU [S1, S2].
*   **Precision:** The precision of decoded values depends on the compression scheme and MRT bit depth [G].
*   **Boundary Conditions:** Decoding logic must correctly handle block and stripe boundaries [G].

## Subtopics

### [Independent Block Encoding](5373-independent-block-encoding.md)
Independent Block Encoding is a local data compression pass where a volume is divided into independent sub-blocks, each encoded separately, potentially using a global representation learned in a preprocessing step. It solves the problem of compressing large volumetric datasets for GPU-based rendering by ensuring that memory usage during encoding remains independent of the total input size, while allowing linear scaling and easy parallelization. It is distinguished from global processing methods by its reliance on local block operations rather than whole-volume transforms, and from stripe-based decoding by being the encoding counterpart that prepares data for on-the-fly GPU reconstruction [Parent].

## Operating characteristics
*   **Time Complexity:** Decoding time is proportional to the number of stripes (and thus voxels), as each fragment processes one stripe [S1, S2].
*   **Memory Complexity:** Memory usage is proportional to the compressed block size and the MRTs, avoiding full-volume decompression storage [S1, S2].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Enables local and transient reconstruction, reducing memory bandwidth requirements [S1, S2]. Leverages GPU parallelism for decompression [S1, S2]. Integrates with deferred rendering architectures [Parent].
*   **Limitations:** Requires the compression scheme to be decodable in a fragment shader [S1, S2].
*   **When to Use:** When rendering large compressed volumes on the GPU with limited memory bandwidth, and when the compression scheme supports on-the-fly decoding [S1, S2].
*   **When Not to Use:** Not given in the sources.

## Background
Stripe-based On-the-fly Decoding was proposed by Fraedrich et al. in 2007 [S1, S2]. It was introduced as a general approach for applying common sequential data compression schemes to blocks of data, allowing them to be decoded on-the-fly by the GPU in a single render pass [S1, S2]. The method was designed to improve upon industry standards such as DXT [Bro01], ETC2 [SP07], and PVRTC [Fen03], and to support the 3D part of the ASTC specification [S1, S2]. It is a key component of the Deferred Filtering Architecture for Compressed Volumes, enabling efficient local and transient reconstruction of compressed volumes [Parent].
