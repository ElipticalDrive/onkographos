# PngCompression

Also called: PNG-based Gaussian Splat Compression, VKGS Compression

## Overview
PngCompression is a lossy compression method for 3D Gaussian Splatting (3DGS) data that encodes spatial parameters into PNG image files and spherical harmonic (SH) coefficients into quantized K-means clusters [S1, unofficial]. It differs from generic entropy coding by leveraging the spatial locality of Gaussian means and scales, allowing standard image codecs to handle redundancy, while using vector quantization for high-dimensional SH data [S1, unofficial]. It is specifically designed for the VKGS (Vulkan Gaussian Splatting) pipeline [S1, unofficial].

## How it works
**Inputs:** A dictionary of Gaussian splat parameters: `means` (3D position), `scales` (3D scale), `quats` (4D rotation quaternion), `opacities` (scalar), `sh0` (SH degree 0 coefficients), and `shN` (higher-degree SH coefficients).
**Outputs:** A set of PNG files for spatial parameters, an NPZ file for SH coefficients, and a `meta.json` file containing metadata for reconstruction.

**Data Structures:**
*   **Grid:** A 2D square grid of size $n_{sidelen} \times n_{sidelen}$, where $n_{sidelen} = \lfloor \sqrt{n_{gs}} \rfloor$ and $n_{gs}$ is the number of Gaussians.
*   **PNG Files:**
    *   8-bit: Single channel or interleaved RGB/RGBA, storing quantized values in `uint8`.
    *   16-bit: Split into two 8-bit PNGs (`_l.png` for low byte, `_u.png` for high byte) to store `uint16` values.
*   **NPZ File:** Stores `centroids_quant` (uint8) and `labels` (uint16) for K-means compressed SH coefficients.

**Parameters:**
*   `use_sort` (bool): Whether to sort splats before compression. Default: `True` [S1, unofficial].
*   `n_clusters` (int): Number of K-means clusters for SH compression. Default: `65536` [S1, unofficial].
*   `quantization` (int): Number of bits for centroid quantization. Default: `6` [S1, unofficial].
*   `verbose` (bool): Print progress. Default: `True` [S1, unofficial].

**Steps:**

1.  **Preprocessing:**
    *   Apply a logarithmic transform to `means`: $m' = \log(m + \epsilon)$ [S1, unofficial].
    *   Normalize quaternions: $q' = \text{normalize}(q)$ [S1, unofficial].

2.  **Grid Preparation:**
    *   Calculate side length: $n_{sidelen} = \lfloor \sqrt{n_{gs}} \rfloor$ [S1, unofficial].
    *   Calculate crop count: $n_{crop} = n_{gs} - n_{sidelen}^2$ [S1, unofficial].
    *   If $n_{crop} > 0$, remove the $n_{crop}$ Gaussians with the lowest opacity [S1, unofficial].

3.  **Sorting (Optional):**
    *   If `use_sort` is `True`, sort the remaining splats. The specific sorting metric is not detailed in the source, but it is intended to improve compression efficiency by grouping similar values [S1, unofficial].

4.  **Compression by Parameter Type:**
    *   **Means:** Use 16-bit PNG compression (`_compress_png_16bit`) [S1, unofficial].
    *   **Scales, Quats, Opacities, SH0:** Use 8-bit PNG compression (`_compress_png`) [S1, unofficial].
    *   **SHN (Higher Degrees):** Use K-means compression (`_compress_kmeans`) [S1, unofficial].
    *   **Other:** Save as NPZ (`_compress_npz`) [S1, unofficial].

5.  **8-bit PNG Compression (`_compress_png`):**
    *   Reshape parameter array to $(n_{sidelen}, n_{sidelen}, -1)$ [S1, unofficial].
    *   Compute global minimum ($min$) and maximum ($max$) of the grid [S1, unofficial].
    *   Normalize to $[0, 1]$: $v_{norm} = \frac{v - min}{max - min}$ [S1, unofficial].
    *   Quantize to `uint8`: $v_{out} = \text{round}(v_{norm} \times 255)$ [S1, unofficial].
    *   Save as PNG [S1, unofficial].

6.  **16-bit PNG Compression (`_compress_png_16bit`):**
    *   Follow steps 5.1–5.3, but quantize to `uint16`: $v_{out} = \text{round}(v_{norm} \times 65535)$ [S1, unofficial].
    *   Split into low and high bytes:
        *   $low = v_{out} \ \& \ 0xFF$
        *   $high = (v_{out} \gg 8) \ \& \ 0xFF$
    *   Save $low$ as `_l.png` and $high$ as `_u.png` [S1, unofficial].

7.  **K-means Compression (`_compress_kmeans`):**
    *   Reshape SH coefficients to $(dim, n_{gs})$ [S1, unofficial].
    *   Fit K-means with $n_{clusters}=65536$ and Manhattan distance [S1, unofficial].
    *   Assign each Gaussian to the nearest cluster center (label) [S1, unofficial].
    *   Quantize cluster centers to `uint8` using `quantization` bits (default 6) [S1, unofficial].
    *   Save `centroids_quant` (uint8) and `labels` (uint16) in an NPZ file [S1, unofficial].

8.  **Metadata:**
    *   Save compression parameters and grid dimensions to `meta.json` [S1, unofficial].

**Decompression:**
1.  Load `meta.json` [S1, unofficial].
2.  Load PNGs and reconstruct 8/16-bit grids. Denormalize using stored min/max [S1, unofficial].
3.  Load NPZ and reconstruct SH coefficients from labels and quantized centroids [S1, unofficial].
4.  **Postprocessing:** Apply inverse log transform to means [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by K-means clustering for SH coefficients, which is $O(n_{gs} \cdot dim \cdot n_{clusters} \cdot iterations)$ [S1, unofficial]. PNG compression is linear $O(n_{gs})$ [S1, unofficial].
*   **Memory Complexity:** Storage is proportional to the number of Gaussians. 8-bit PNGs use 1 byte per value, 16-bit use 2 bytes (split into two 1-byte PNGs) [S1, unofficial]. K-means stores $n_{clusters} \cdot dim$ centroids and $n_{gs}$ labels [S1, unofficial].
*   **Performance:** The method is designed for fast decoding, suitable for real-time rendering in the VKGS viewer [S1, unofficial].
*   **Strengths:** Leverages highly optimized PNG decoders; simple implementation; good compression for spatial parameters [S1, unofficial].
*   **Limitations:** Requires cropping if $n_{gs}$ is not a perfect square, leading to loss of low-opacity Gaussians [S1, unofficial]. K-means quantization introduces error for SH coefficients [S1, unofficial].
*   **When to use:** When integrating with VKGS or similar Vulkan-based renderers that support this specific compression format [S1, unofficial].
*   **When not to use:** For general-purpose 3DGS storage where standard codecs or other compression methods (e.g., [Splat parameter encoding and codec selection](5019-splat-parameter-encoding-and-codec-selection.md)) are preferred [S1, unofficial].

## Background
PngCompression was introduced as part of the CLOD-3DGS project by Meta Research (Milef et al., 2025) [S1, unofficial]. It is designed to support the Vulkan-based Gaussian Splatting (VKGS) renderer, enabling efficient loading and rendering of large-scale 3DGS scenes [S1, unofficial]. The method addresses the need for fast decompression and compatibility with GPU-based rendering pipelines [S1, unofficial].
