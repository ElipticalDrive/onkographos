# Splat Quality Format Mapping


## Overview
Splat Quality Format Mapping is a codec selection strategy that maps a target quality level to specific data storage formats for position, scale, color, and spherical harmonics (SH) coefficients [S1, unofficial]. It balances visual fidelity against memory usage and download size by selecting from a predefined set of compression levels [S1, unofficial]. It differs from raw storage by introducing a discrete set of presets (VeryHigh to VeryLow) that dictate the bit-depth and encoding scheme for each splat attribute [S1, unofficial].

## How it works
**Inputs:** A target quality level from the `SplatQuality` enum and the total number of splats.
**Outputs:** A tuple of four format identifiers `(posFormat, scaleFormat, colorFormat, shFormat)` used by the processing pipeline [S1, unofficial].

**Data Structures:**
The mapping is defined by the `SplatQuality` enum, which contains five levels. Each level maps to specific formats for four attributes:
1.  **Position:** `Float32`, `Norm11`, or `Norm6`.
2.  **Scale:** `Float32`, `Norm11`, or `Norm6`.
3.  **Color:** `Float32x4`, `Float16x4`, `Norm8x4`, or `BC7`.
4.  **Spherical Harmonics (SH):** `Float32`, `Float16`, `Norm6`, `Cluster64k`, or `Cluster4k` [S1, unofficial].

**Format Definitions:**
*   `Float32`: 32-bit floating point.
*   `Float16`: 16-bit half-precision floating point.
*   `Norm11`: 11-bit normalized integer (typically 10.10.10.2 for rotations, or similar fixed-point representations for vectors).
*   `Norm8`: 8-bit normalized integer.
*   `Norm6`: 6-bit normalized integer.
*   `BC7`: Block-compressed 7 texture format (applied to color).
*   `Cluster64k` / `Cluster4k`: Cluster-based compression for SH coefficients, likely involving codebook lookup with 64k or 4k entries [S1, unofficial].

**Mapping Table:**
The `GetFormats(quality)` function returns the format tuple based on the input `SplatQuality` [S1, unofficial]:

| Quality Level | Position | Scale | Color | SH |
| :--- | :--- | :--- | :--- | :--- |
| `VeryHigh` | `Float32` | `Float32` | `Float32x4` | `Float32` |
| `High` | `Norm11` | `Norm11` | `Float16x4` | `Float16` |
| `Medium` (Default) | `Norm11` | `Norm11` | `Norm8x4` | `Norm6` |
| `Low` | `Norm6` | `Norm6` | `Norm8x4` | `Cluster64k` |
| `VeryLow` | `Norm6` | `Norm6` | `BC7` | `Cluster4k` |

**Pseudocode:**
The following Python-like pseudocode implements the mapping logic. It assumes `SplatQuality` is an enum and `GetFormats` returns a tuple of strings representing the format names.

```python
def GetFormats(quality: SplatQuality) -> tuple:
    """
    Returns the format tuple (posFormat, scaleFormat, colorFormat, shFormat)
    based on the requested quality level.
    """
    if quality == SplatQuality.VeryHigh:
        return ("Float32", "Float32", "Float32x4", "Float32")
    elif quality == SplatQuality.High:
        return ("Norm11", "Norm11", "Float16x4", "Float16")
    elif quality == SplatQuality.Medium:
        return ("Norm11", "Norm11", "Norm8x4", "Norm6")
    elif quality == SplatQuality.Low:
        return ("Norm6", "Norm6", "Norm8x4", "Cluster64k")
    elif quality == SplatQuality.VeryLow:
        return ("Norm6", "Norm6", "BC7", "Cluster4k")
    else:
        # Fallback to Medium if an undefined quality level is passed
        return ("Norm11", "Norm11", "Norm8x4", "Norm6")

class SplatQuality:
    VeryHigh = 0
    High = 1
    Medium = 2
    Low = 3
    VeryLow = 4
```

**Edge Cases and Pitfalls:**
*   **Resolution Fallback:** If the requested resolution key (from `SplatResolution` enum: `FullRes`, `_500k`, `_100k`) is missing from the world assets, the pipeline must call `GetBestResolutionUrl()` to avoid download failure [S1, unofficial].
*   **Format Compatibility:** The decoder must handle the specific bit-packing for each format. For example, `Norm11` for position/scale may use different bit layouts than `Norm11` for rotation (10.10.10.2) [S1, unofficial].
*   **SH Compression:** `Cluster64k` and `Cluster4k` imply a codebook-based approach. The decoder must have access to the corresponding codebook or reconstruct coefficients using the cluster index [S1, unofficial].

## Operating characteristics
**Time Complexity:** The mapping itself is O(1) as it is a simple lookup. However, the decoding complexity varies significantly by format. `Float32` formats are O(1) per component. `Norm` formats require normalization (O(1)). `BC7` requires block decoding (O(1) per 4x4 block, but higher constant factor). `Cluster` formats require codebook lookup (O(1) if hash map, O(log N) if sorted).
**Memory Complexity:** The memory footprint is directly determined by the selected formats. `VeryHigh` uses the most memory (32-bit floats for all attributes). `VeryLow` uses the least, leveraging `BC7` for color and cluster compression for SH.
**Performance:** Higher quality levels (VeryHigh, High) provide better visual fidelity but require more bandwidth and memory. Lower levels (Low, VeryLow) reduce bandwidth and memory usage at the cost of visual artifacts, particularly in SH coefficients where cluster compression may introduce quantization errors.
**Strengths:** Simple to implement, provides a clear trade-off curve between quality and resources.
**Limitations:** Discrete quality levels may not allow fine-grained tuning. Cluster compression for SH may not adapt well to all scene content.

## Background
This method is part of the Gaussian Splatting rendering pipeline, specifically within the compression and streaming subsystems. It was developed to enable efficient transmission and rendering of large-scale 3D scenes using 3D Gaussian Splatting. The approach is documented in the `worldlabs_unity` repository, which implements a Unity-based viewer for such scenes [S1, unofficial].
