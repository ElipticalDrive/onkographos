# Splat parameter encoding and codec selection

Also called: Luxar store compression, quantised splat encoding

## Overview
This method defines the binary layout and compression pipeline for 3D Gaussian Splat parameters to minimize storage size while maintaining rendering fidelity. It solves the problem of high memory bandwidth and storage costs associated with raw float32 Gaussian data by applying specialized quantization schemes per parameter type and a width-aware codec policy. It is distinguished from sibling methods like [PngCompression](11785-pngcompression.md) by its use of spatial bucketing, Cholesky factor certification, and specific byte-shuffle optimizations for integer codes, resulting in significantly smaller store sizes (8.8–12.7 bytes/splat) compared to standard formats [S1, unofficial].

## How it works
**Inputs:** Raw 3D Gaussian Splat parameters (centres, scales, rotations, opacities, spherical harmonics coefficients) typically stored in float32.
**Outputs:** A compressed binary stream (`.ksplat` format) containing quantized and encoded parameter arrays.

### Data Structures and Layout
The store consists of four primary parameter arrays, each with specific quantization and encoding rules [S1, unofficial]:

1.  **Centres:**
    *   **Type:** `uint16` (16-bit unsigned integer).
    *   **Encoding:** Spatially bucketed. Quantized positions are stored as 16-bit integers.
    *   **Optimization:** Columnar delta prefiltering is applied to the centres array to improve compressibility [S1, unofficial].

2.  **Cholesky Factors (Scale/Rotation):**
    *   **Type:** `uint8` (8-bit unsigned integer).
    *   **Constraint:** "Certified" uint8, meaning the quantization range and mapping are mathematically guaranteed to preserve the positive-definiteness of the covariance matrix derived from scale and rotation [S1, unofficial].

3.  **Amplitudes (Opacity/Spherical Harmonics):**
    *   **Type:** `uint8` or `uint16`.
    *   **Selection:** The bit-depth (8 or 16) and grid type (bounded-linear or geometric-log) are selected based on the dynamic range of the specific amplitude array [S1, unofficial].
    *   **Encoding:** If geometric-log, codes are log-companded.

4.  **Spherical Harmonics (SH):**
    *   Stored as part of the amplitude arrays or separate coefficient arrays, subject to the same quantization rules as amplitudes [S1, unofficial].

### Compression Pipeline
The compression process follows these steps [S1, unofficial]:

1.  **Quantization:**
    *   Centres are quantized to `uint16`.
    *   Cholesky factors are quantized to `uint8` with certification.
    *   Amplitudes are quantized to `uint8` or `uint16` using either bounded-linear or geometric-log grids, chosen to minimize loss within the array's dynamic range.
    *   *Note:* The quantization fidelity results in a PSNR loss of at most −0.679 dB (median −0.012 dB) against the original float32 fits [S1, unofficial].

2.  **Filtering (Prefiltering):**
    *   Apply **columnar delta prefiltering** to the Centres array. This computes the difference between adjacent values in columns to create sparse residuals, improving compression ratio [S1, unofficial].

3.  **Chunking:**
    *   Split the filtered data into chunks.
    *   **Atom-aligned chunks:** To mitigate compression anomalies, chunks must be aligned to atom boundaries (typically 64 bytes or cache line sizes) [S1, unofficial].
    *   **Chunk Size:** The default shipped configuration uses 64 KiB chunks, but the optimized configuration may vary to avoid the Blosc shuffle anomaly [S1, unofficial].

4.  **Codec Selection and Encoding:**
    *   **Codec:** Blosc with Zstd compressor at level 9 [S1, unofficial].
    *   **Policy:** Width-aware per-dtype compressor policy is applied natively and via WebAssembly in-browser [S1, unofficial].
    *   **Byte Shuffle:**
        *   **Multi-byte integer codes:** Apply byte shuffle. This rearranges bytes to group identical bytes together, improving Zstd compression [S1, unofficial].
        *   **Single-byte codes:** Skip byte shuffle.
        *   **Floating-point arrays:** Skip byte shuffle.
        *   **Log-companded amplitude codes:** In the optimized configuration, leave these unshuffled to reduce size by 1.44% [S1, unofficial].
    *   **Anomaly Mitigation:** A level-dependent Blosc shuffle anomaly occurs on 64 KiB chunks. This is mitigated by using atom-aligned chunks and the columnar delta prefiltering on centres [S1, unofficial].

5.  **Assembly:**
    *   Assemble the compressed chunks into the final `.ksplat` file.

### Pseudocode
```python
def compress_splats(centres_f32, cholesky_f32, amplitudes_f32):
    # 1. Quantization
    # Centres: uint16
    centres_u16 = quantize_uint16(centres_f32)
    
    # Cholesky: certified uint8
    cholesky_u8 = quantize_certified_uint8(cholesky_f32)
    
    # Amplitudes: select uint8/uint16 and linear/log based on dynamic range
    amp_config = select_amplitude_config(amplitudes_f32)
    amplitudes_quantized = quantize_amplitudes(amplitudes_f32, amp_config)
    
    # 2. Filtering
    # Apply columnar delta prefiltering to centres
    centres_delta = columnar_delta_prefilter(centres_u16)
    
    # 3. Chunking and Encoding
    # Define chunk size and alignment
    chunk_size = 64 * 1024  # 64 KiB
    atom_alignment = 64     # Bytes
    
    # Encode Centres
    centres_chunks = split_into_chunks(centres_delta, chunk_size, atom_alignment)
    encoded_centres = []
    for chunk in centres_chunks:
        # Multi-byte integer: apply byte shuffle
        shuffled_chunk = byte_shuffle(chunk)
        compressed_chunk = blosc_compress(shuffled_chunk, compressor='zstd', level=9)
        encoded_centres.append(compressed_chunk)
        
    # Encode Cholesky (uint8, single-byte)
    cholesky_chunks = split_into_chunks(cholesky_u8, chunk_size, atom_alignment)
    encoded_cholesky = []
    for chunk in cholesky_chunks:
        # Single-byte: skip byte shuffle
        compressed_chunk = blosc_compress(chunk, compressor='zstd', level=9)
        encoded_cholesky.append(compressed_chunk)
        
    # Encode Amplitudes
    amplitudes_chunks = split_into_chunks(amplitudes_quantized, chunk_size, atom_alignment)
    encoded_amplitudes = []
    for chunk in amplitudes_chunks:
        # Check if log-companded
        if amp_config.type == 'geometric-log':
            # Optimized config: leave unshuffled to save 1.44%
            compressed_chunk = blosc_compress(chunk, compressor='zstd', level=9)
        else:
            # Multi-byte integer: apply byte shuffle
            shuffled_chunk = byte_shuffle(chunk)
            compressed_chunk = blosc_compress(shuffled_chunk, compressor='zstd', level=9)
        encoded_amplitudes.append(compressed_chunk)
        
    # Assemble KSplat file
    ksplat_file = assemble_ksplat(encoded_centres, encoded_cholesky, encoded_amplitudes, amp_config)
    return ksplat_file
```

### Parameters and Typical Values
*   **Blosc Level:** 9 [S1, unofficial].
*   **Chunk Size:** 64 KiB (default), but atom-aligned chunks are critical [S1, unofficial].
*   **Quantization Loss:** Max −0.679 dB PSNR loss vs original [S1, unofficial].
*   **Render PSNR:** 59–88 dB (quantised vs float32 render) [S1, unofficial].
*   **Store Size:** 8.8–12.7 bytes/splat (down from 30–37 bytes/splat) [S1, unofficial].
*   **Shipped Rule Storage:** 9.63 bytes/splat (10.09 bytes/splat if re-chunked to 64 KiB without prefilter) [S1, unofficial].
*   **Optimized Unshuffled Config:** 9.50 bytes/splat (15.6% below baseline at 64 KiB) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Blosc Shuffle Anomaly:** A level-dependent anomaly occurs on 64 KiB chunks when byte shuffle is applied. Mitigation: Use atom-aligned chunks and columnar delta prefiltering on centres [S1, unofficial].
*   **Dynamic Range Selection:** Incorrect selection of amplitude quantization grid (linear vs log) based on dynamic range can lead to suboptimal compression or precision loss [S1, unofficial].
*   **Precision:** Quantization is lossy. While PSNR loss is low (median −0.012 dB), it is not zero [S1, unofficial].

## Subtopics

### [Ksplat Decompression](6899-ksplat-decompression.md)
Ksplat Decompression reads and decompresses `.ksplat` files, which contain spatially bucketed and quantized 3D Gaussian Splat data, into a structured `DataTable` format suitable for rendering. It handles position quantization, scale/rotation compression, and spherical harmonics decoding. Unlike raw PLY formats, it supports three distinct compression modes (Float32, Float16, Uint8) to balance file size and precision, and uses spatial bucketing to optimize position storage.

## Operating characteristics
*   **Time Complexity:** Decompression throughput is 138–215 MB/s in-browser (WebAssembly) and 326–592 MB/s natively on a benchmark workstation [S1, unofficial].
*   **Memory Complexity:** Store size is 8.8–12.7 bytes/splat, significantly lower than the 30–37 bytes/splat of raw float32 [S1, unofficial].
*   **Strengths:**
    *   High compression ratio (14.3–15.6% below uniform Blosc-zstd level-3 bit-shuffle baseline) [S1, unofficial].
    *   Fast loading times due to cache-optimized ordering and format matching internal splat data structure [S2, unofficial].
    *   Low quantization loss (median −0.012 dB PSNR) [S1, unofficial].
*   **Limitations:**
    *   Requires specific codec (Blosc-zstd level 9) and prefiltering (columnar delta) for optimal performance [S1, unofficial].
    *   Anomaly on 64 KiB chunks requires careful chunk alignment [S1, unofficial].
    *   Not suitable for progressive loading without optimization; progressive loading of `.ply`/`.splat` skips cache-optimized ordering [S2, unofficial].
*   **When to Use:** Ideal for web-based viewers and applications requiring fast loading and low memory footprint for large-scale 3D Gaussian Splat scenes [S2, unofficial].
*   **When Not to Use:** When progressive loading without conversion to `.ksplat` is required, or when maximum possible fidelity (float32) is needed without any quantization loss [S2, unofficial].

## Background
The method originates from the Luxar project, which focuses on Gaussian splatting for microscopy and scalable interactive web visualization of multidimensional scientific data [S1, unofficial]. The `.ksplat` format was developed as a trimmed-down and compressed version of the original `.ply` files to match the internal format for splat data, enabling fastest loading times [S2, unofficial]. The compression techniques, including quantization fidelity and codec selection, were benchmarked on 17 benchmark volumes and are documented in supplementary documents from the Luxar project [S1, unofficial]. The format is supported by libraries such as `mkkellogg/GaussianSplats3D` [S2, unofficial].
