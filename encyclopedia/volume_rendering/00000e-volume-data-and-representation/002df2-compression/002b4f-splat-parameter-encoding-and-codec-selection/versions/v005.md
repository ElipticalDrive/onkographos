# Splat parameter encoding and codec selection

Also called: Luxar store compression, quantised splat encoding

## Overview
This method defines the binary layout and compression pipeline for 3D Gaussian Splat parameters (centres, scales, rotations, and amplitudes) to minimize storage size while maintaining rendering fidelity. It solves the problem of transmitting and loading large-scale Gaussian splat scenes efficiently by applying specific quantization strategies per parameter type and selecting an optimal codec configuration. It differs from generic volume compression by treating splat parameters as distinct, heterogeneous arrays with different dynamic ranges and statistical properties, rather than a uniform scalar field.

## How it works
**Inputs:** A set of 3D Gaussian splats, each defined by position ($\mathbf{p}$), covariance matrix (derived from scale $\mathbf{s}$ and rotation $\mathbf{q}$), and spherical harmonic coefficients (amplitudes $\mathbf{a}$).
**Outputs:** A compressed bitstream (`.ksplat` format) containing quantized and encoded parameter arrays.

### Data Structures and Layout
The store organizes splat parameters into four distinct arrays, processed independently for compression:

1.  **Centres ($\mathbf{p}$):**
    *   **Type:** `uint16` (16-bit unsigned integer).
    *   **Encoding:** Positions are quantized to a fixed grid. The specific quantization range depends on the scene bounds, but the storage format is fixed-width 16-bit integers per coordinate component.
2.  **Cholesky Factors (Scale/Rotation):**
    *   **Type:** `uint8` (8-bit unsigned integer).
    *   **Encoding:** The covariance matrix is decomposed into Cholesky factors to ensure positive definiteness. These factors are "certified" to fit within the dynamic range of 8-bit integers, providing a compact representation of scale and orientation.
3.  **Amplitudes (Spherical Harmonics):**
    *   **Type:** `uint8` or `uint16`.
    *   **Encoding:** Selection is based on the array's dynamic range.
        *   **Bounded-linear:** Used for lower dynamic range data (stored as `uint8` or `uint16`).
        *   **Geometric-log:** Used for higher dynamic range data (stored as `uint16`). This uses log-companding to preserve precision for small values.
4.  **Spherical Harmonics Coefficients:**
    *   Included in the amplitude arrays above, encoded using the same grid selection logic.

### Compression Pipeline
The compression process applies a width-aware per-dtype compressor policy using **Blosc-zstd** at level 9. The steps are:

1.  **Quantization:**
    *   Centres are quantized to `uint16`.
    *   Cholesky factors are quantized to `uint8`.
    *   Amplitudes are quantized to `uint8` or `uint16` based on dynamic range analysis.
2.  **Pre-filtering (Centres only):**
    *   Apply **columnar delta pre-filtering** to the centre coordinates. This predicts the current coordinate based on previous ones in the column, reducing entropy for the compressor.
3.  **Chunking:**
    *   Data is divided into chunks. The optimized configuration uses **atom-aligned chunks** to mitigate specific codec anomalies.
4.  **Byte Shuffle:**
    *   Apply byte shuffle for multi-byte integer codes (e.g., `uint16` centres, `uint16` amplitudes) to improve compression ratios by aligning identical bytes.
    *   **Skip** byte shuffle for single-byte codes (`uint8` Cholesky) and floating-point arrays (if any were used, though the shipped config avoids this).
    *   **Optimization:** Leave log-companded amplitude codes unshuffled in the final optimized configuration to reduce size by 1.44%.
5.  **Encoding:**
    *   Encode each chunk using Blosc with zstd compression at level 9.

### Pseudocode

```python
def compress_splats(splats):
    """
    Compress 3D Gaussian Splat parameters into .ksplat format.
    splats: List of objects with attributes:
        - position: (x, y, z) float32
        - scale: (sx, sy, sz) float32
        - rotation: (qw, qx, qy, qz) float32
        - sh_coeffs: array of float32
    """
    # 1. Extract and Quantize Parameters
    
    # Centres: uint16
    # Quantize positions to uint16 grid based on scene bounds
    centres_uint16 = quantize_uint16([s.position for s in splats])
    
    # Cholesky Factors: uint8
    # Compute Cholesky decomposition of covariance matrix from scale/rotation
    # Certify that values fit in uint8 range
    cholesky_uint8 = quantize_uint8_cholesky([s.scale, s.rotation for s in splats])
    
    # Amplitudes: uint8 or uint16
    # Analyze dynamic range of SH coefficients
    amplitudes_raw = [s.sh_coeffs for s in splats]
    if dynamic_range_is_low(amplitudes_raw):
        amplitudes_uint8 = quantize_uint8(amplitudes_raw)
        amplitude_type = 'uint8'
    else:
        # Use geometric-log encoding for high dynamic range
        amplitudes_uint16 = quantize_geometric_log_uint16(amplitudes_raw)
        amplitude_type = 'uint16'
        
    # 2. Pre-filtering
    # Apply columnar delta pre-filtering to centres to reduce entropy
    centres_filtered = apply_columnar_delta_filter(centres_uint16)
    
    # 3. Chunking
    # Create atom-aligned chunks for each parameter array
    # Atom alignment mitigates Blosc shuffle anomaly on 64 KiB chunks
    centres_chunks = create_atom_aligned_chunks(centres_filtered)
    cholesky_chunks = create_atom_aligned_chunks(cholesky_uint8)
    
    if amplitude_type == 'uint8':
        amplitude_chunks = create_atom_aligned_chunks(amplitudes_uint8)
    else:
        amplitude_chunks = create_atom_aligned_chunks(amplitudes_uint16)
        
    # 4. Byte Shuffle and Encoding
    # Codec: Blosc-zstd level 9
    
    # Centres: Multi-byte (uint16), apply shuffle
    centres_encoded = []
    for chunk in centres_chunks:
        shuffled_chunk = apply_byte_shuffle(chunk)
        encoded_chunk = blosc_compress(shuffled_chunk, compressor='zstd', level=9)
        centres_encoded.append(encoded_chunk)
        
    # Cholesky: Single-byte (uint8), skip shuffle
    cholesky_encoded = []
    for chunk in cholesky_chunks:
        # No shuffle for uint8
        encoded_chunk = blosc_compress(chunk, compressor='zstd', level=9)
        cholesky_encoded.append(encoded_chunk)
        
    # Amplitudes: Variable
    amplitude_encoded = []
    for chunk in amplitude_chunks:
        if amplitude_type == 'uint16':
            # Optimized config: leave log-companded codes unshuffled
            # No shuffle
            encoded_chunk = blosc_compress(chunk, compressor='zstd', level=9)
        else:
            # uint8: skip shuffle
            encoded_chunk = blosc_compress(chunk, compressor='zstd', level=9)
        amplitude_encoded.append(encoded_chunk)
        
    # 5. Assemble Store
    store = {
        'centres': centres_encoded,
        'cholesky': cholesky_encoded,
        'amplitudes': amplitude_encoded,
        'metadata': {
            'amplitude_type': amplitude_type,
            'quantization_params': get_quantization_params()
        }
    }
    return store
```

### Parameters and Typical Values
*   **Codec:** Blosc-zstd.
*   **Compression Level:** 9 (highest zstd level).
*   **Chunk Size:** Atom-aligned chunks (size not explicitly given, but anomaly occurs at 64 KiB).
*   **Quantization:**
    *   Centres: `uint16`.
    *   Cholesky: `uint8`.
    *   Amplitudes: `uint8` or `uint16` (geometric-log).

### Edge Cases and Pitfalls
*   **Blosc Shuffle Anomaly:** A level-dependent anomaly occurs on 64 KiB chunks when byte shuffle is applied. This is mitigated by using atom-aligned chunks and columnar delta pre-filtering on centres [S1, unofficial].
*   **Dynamic Range:** Incorrect selection of amplitude encoding (linear vs. log) can lead to significant precision loss. The method selects based on the array's dynamic range [S1, unofficial].
*   **Precision:** Quantization introduces PSNR loss. The shipped encoding results in a PSNR loss of at most -0.679 dB compared to the original float32 fits, with a median loss of -0.012 dB [S1, unofficial].

## Subtopics

### [Ksplat Decompression](6899-ksplat-decompression.md)
Ksplat Decompression reads and decompresses `.ksplat` files, which contain spatially bucketed and quantized 3D Gaussian Splat data, into a structured `DataTable` format suitable for rendering. It handles position quantization, scale/rotation compression, and spherical harmonics decoding. Unlike raw PLY formats, it supports three distinct compression modes (Float32, Float16, Uint8) to balance file size and precision, and uses spatial bucketing to optimize position storage.

## Operating characteristics
*   **Store Size:** 8.8–12.7 bytes/splat, down from 30–37 bytes/splat for uncompressed float32 data [S1, unofficial].
*   **Shipped Rule Storage:** 9.63 bytes/splat under the shipped rule (10.09 bytes/splat if re-chunked to 64 KiB without prefilter, 14.3% below uniform Blosc-zstd level-3 bit-shuffle baseline) [S1, unofficial].
*   **Optimized Configuration:** 9.50 bytes/splat (15.6% below baseline at 64 KiB) when log-companded amplitude codes are left unshuffled [S1, unofficial].
*   **Quantisation Fidelity:** PSNR against original changes by at most -0.679 dB (median -0.012 dB). Quantised render PSNR vs float32 render is 59–88 dB [S1, unofficial].
*   **Decoding Throughput:** 138–215 MB/s in-browser (WebAssembly), 326–592 MB/s natively on identical chunk sets on a benchmark workstation [S1, unofficial].
*   **Strengths:** Significant reduction in file size while maintaining high rendering fidelity. Optimized for fast loading times in web viewers.
*   **Limitations:** Requires specific codec support (Blosc-zstd). The optimization relies on specific chunk alignment and pre-filtering strategies that may not be universally applicable without tuning.

## Background
This method originates from the Luxar project, which focuses on Gaussian splatting for microscopy and scalable interactive web visualization of multidimensional scientific data. The technique was developed to address the large file sizes associated with 3D Gaussian Splatting, particularly for web-based viewers. The `.ksplat` format was introduced as a trimmed-down and compressed version of the original `.ply` files, designed for fastest loading times by matching the internal format for splat data [S2, unofficial]. The compression details, including quantization fidelity and codec selection, were documented in supplementary materials for the Luxar preprint [S1, unofficial].
