# Triple Plane (TP) Decomposition

Also called: CP decomposition variant using 2D factor matrices, TP Decomposition

## Overview
Triple Plane (TP) Decomposition is a tensor factorization method for 3D scene representation that replaces the 1D vectors of standard Canonical Polyadic (CP) decomposition with 2D factor matrices (planes) [S1]. It solves the problem of high computational cost and poor representation quality associated with the extremely high ranks required by vector-based CP decomposition for complex scenes [S1]. Unlike its sibling [Decomposed Low-Rank Tensor (VM-Decomposition)](7116-decomposed-low-rank-tensor-vm-decomposition.md), which relaxes low-rank constraints for specific modes, TP decomposition uniformly adopts 2D structures across all three spatial axes to trade storage compactness for computational efficiency and improved quality at lower ranks [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scene tensor $\mathcal{T} \in \mathbb{R}^{H \times W \times D}$ representing volumetric properties (e.g., density $\sigma$ or color $c$) [S1].
*   **Output:** A set of factor matrices $\{U_{x,y}, U_{y,z}, U_{x,z}\}$ and a core tensor $S$ that reconstruct the scene [S1].

**Data Structures:**
The method decomposes the 3D space into three 2D planes along the coordinate axes. Each factor matrix contains $R$ components (ranks).
*   $U_{x,y} \in \mathbb{R}^{H \times W \times R}$: Factor matrix for the $x,y$ plane.
*   $U_{y,z} \in \mathbb{R}^{W \times D \times R}$: Factor matrix for the $y,z$ plane.
*   $U_{x,z} \in \mathbb{R}^{H \times D \times R}$: Factor matrix for the $x,z$ plane.
*   $S \in \mathbb{R}^{R}$: A 1D core tensor (or scalar per rank) scaling the contributions [S1].

**Parameters:**
*   $R$: The number of components (ranks) along each plane. This is the primary hyperparameter controlling the trade-off between model size and performance [S1].

**Algorithm:**
The reconstruction of a value at 3D coordinate $(i, j, k)$ is computed by slicing the 3D space and applying a CP decomposition on the flattened dimensions, effectively using a Hadamard product of the corresponding entries from the three factor matrices [S1].

1.  Initialize factor matrices $U_{x,y}, U_{y,z}, U_{x,z}$ and core tensor $S$ with random values.
2.  For each 3D location $(i, j, k)$ in the grid:
    a. Retrieve the $r$-th component from each plane: $u_{x,y}^{(r)} = U_{x,y}[i, j, r]$, $u_{y,z}^{(r)} = U_{y,z}[j, k, r]$, $u_{x,z}^{(r)} = U_{x,z}[i, k, r]$.
    b. Compute the contribution of rank $r$: $val^{(r)} = S[r] \cdot u_{x,y}^{(r)} \cdot u_{y,z}^{(r)} \cdot u_{x,z}^{(r)}$.
    c. Sum contributions over all ranks $R$:
       $$ T_{i,j,k} = \sum_{r=1}^{R} S[r] \cdot U_{x,y}[i, j, r] \cdot U_{y,z}[j, k, r] \cdot U_{x,z}[i, k, r] $$
3.  Optimize $S, U_{x,y}, U_{y,z}, U_{x,z}$ via differentiable rendering to minimize the difference between rendered images and ground truth [S1].

**Pseudocode:**
```python
def tp_decompose_reconstruct(U_xy, U_yz, U_xz, S, coords):
    """
    Reconstructs the tensor value at given 3D coordinates using TP decomposition.
    
    Args:
        U_xy: Tensor of shape (H, W, R)
        U_yz: Tensor of shape (W, D, R)
        U_xz: Tensor of shape (H, D, R)
        S: Tensor of shape (R,)
        coords: List of tuples (i, j, k)
        
    Returns:
        List of reconstructed values
    """
    results = []
    for i, j, k in coords:
        # Gather values for all ranks R
        # U_xy[i, j, :] has shape (R,)
        # U_yz[j, k, :] has shape (R,)
        # U_xz[i, k, :] has shape (R,)
        
        vals_xy = U_xy[i, j, :]
        vals_yz = U_yz[j, k, :]
        vals_xz = U_xz[i, k, :]
        
        # Hadamard product of the three vectors, scaled by S
        # Element-wise multiplication: (R,) * (R,) * (R,) -> (R,)
        rank_contributions = S * vals_xy * vals_yz * vals_xz
        
        # Sum over ranks
        value = sum(rank_contributions)
        results.append(value)
    return results
```

**Edge Cases and Pitfalls:**
*   **Precision:** The Hadamard product of three matrices can lead to vanishing or exploding gradients if values are not normalized, especially with high $R$ [S1].
*   **Storage:** TP decomposition is less compact than vector-based CP. The storage cost is $O(R \cdot (HW + WD + HD))$ compared to $O(R \cdot (H + W + D))$ for standard CP [S1].

## Subtopics

### Micro-Macro Tri-Plane Decomposition
A variant that decomposes a scene's Tri-Plane representation into a locally trained part ($T_{smic}$) and a globally shared part ($T_{smac}$) to reduce capacity and memory footprint [S2, unofficial]. It is chosen when training numerous scenes to leverage shared information [S2, unofficial]. The total Tri-Plane $T_s$ is the concatenation of local and global parts along the feature dimension: $T_s = T_{smic} \oplus T_{smac}$ [S2, unofficial]. $T_{smac}$ is computed as a weighted sum of $M$ globally shared Tri-Planes $B_i$: $T_{smac} = W_s B = \sum_{i=1}^{M} w_{si} B_i$ [S2, unofficial]. $T_{smic}$ is retrieved via a one-hot vector $e_s$ from scene-specific planes [S2, unofficial]. This reduces the number of trainable features by a factor of $\frac{F_{mac}}{F_{mic} + F_{mac}}$ [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Computation per location is $O(R)$ for the Hadamard product and summation, but the constant factor is higher than vector-based CP due to matrix indexing [S1].
*   **Memory Complexity:** $O(R \cdot (HW + WD + HD))$ for the factor matrices [S1]. This is significantly higher than vector-based CP but allows for smaller $R$ [S1].
*   **Performance:** TP decomposition achieves better quality with smaller ranks $R$ compared to vector-based CP, which requires very high ranks for complex scenes [S1].
*   **Strengths:** Computation-friendly, better representation quality for complex scenes, lower rank requirements [S1].
*   **Limitations:** Less storage compact than vector-based CP [S1].
*   **When to use:** When computational efficiency and quality are prioritized over storage size, or when vector-based CP requires prohibitively high ranks [S1].
*   **When not to use:** When storage is the primary constraint and scenes are simple enough for low-rank vector CP [S1].

## Background
TP decomposition was introduced as a variant of CP decomposition to address the limitations of 1D vector factorization in 3D scene representation [S1]. It was proposed in the context of compressible-composable NeRFs, where differentiable rendering is used to learn the decomposition [S1]. The method builds on the idea that 2D structures (planes) are more natural for representing spatial correlations in 3D volumes than 1D vectors [S1].
