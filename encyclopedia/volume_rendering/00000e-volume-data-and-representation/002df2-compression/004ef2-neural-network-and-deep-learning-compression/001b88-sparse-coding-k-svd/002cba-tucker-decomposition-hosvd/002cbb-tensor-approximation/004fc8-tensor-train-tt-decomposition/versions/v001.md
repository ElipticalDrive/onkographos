# Tensor-Train (TT) Decomposition
Also called: 4D Volume to TT Cores, TT Decomposition, TT Format Decomposition, Tensor-Train (TT) Format Decomposition and Reshaping, Tensor-Train Singular Value Decomposition (TT-SVD)

## Overview
Tensor-Train (TT) Decomposition factorizes a high-dimensional input tensor into a sequence of two- and three-dimensional tensors called TT cores, reducing memory complexity from quartic to linear growth with respect to dimensionality [S1, [S2][S2, unofficial]]. It solves the problem of high-dimensional data storage and computation by avoiding the exponential growth of parameters associated with dense tensor representations [S2, [S2, unofficial]]. Unlike [Tucker Decomposition (HOSVD)](5363-tucker-decomposition-hosvd.md), where core dimensionality grows with tensor dimensionality, TT cores maintain fixed rank dimensions, making it especially suitable for high-dimensional data such as 4D volumes [S1, [S2][S2, unofficial]].

## How it works
**Inputs and Outputs:**
- Input: A tensor $T \in \mathbb{R}^{N_1 \times \dots \times N_d}$ (typically a 4D volume $N_1 \times N_2 \times N_3 \times N_4$).
- Parameters: Predefined ranks $R_1, \dots, R_{d-1}$ (for 4D: $R_1, R_2, R_3$). These control the size of the TT cores and the approximation quality [S1, [S2][S2, unofficial]].
- Output: A sequence of TT cores $C_1, \dots, C_d$, where $C_i \in \mathbb{R}^{R_{i-1} \times N_i \times R_i}$, with boundary conditions $R_0 = R_d = 1$ [S1, [S2][S2, unofficial]].

**Data Structures:**
- TT Core $C_i$: A 3D tensor (or 2D matrix if $R_{i-1}=1$ or $R_i=1$) with dimensions $R_{i-1} \times N_i \times R_i$.
- Unfolded Matrix $A$: A 2D matrix obtained by reshaping $T$. For mode-$k$ unfolding, $A \in \mathbb{R}^{N_k \times (N_1 \dots N_{k-1} N_{k+1} \dots N_d)}$ [S1, [S2][S2, unofficial]].

**Formula:**
The tensor $T$ is reconstructed from the cores via the outer product $\circ$:
$$ T = \sum_{r_1} \cdots \sum_{r_{d-1}} C_1[:, r_1] \circ C_2[r_1, :, r_2] \circ \cdots \circ C_d[r_{d-1}, :] $$
where $C_i \in \mathbb{R}^{R_{i-1} \times N_i \times R_i}$ and $R_0 = R_d = 1$ [S1, [S2][S2, unofficial]].

**Algorithm (Sequential SVD / TT-SVD):**
The naive implementation computes the decomposition via Sequential SVD (SSVD) [S1, [S2][S2, unofficial]].

1.  **Mode-1 Unfolding:** Reshape $T$ into a matrix $A \in \mathbb{R}^{N_1 \times (N_2 \dots N_d)}$ by flattening all dimensions except the first [S1, [S2][S2, unofficial]].
2.  **SVD:** Compute the SVD of $A$: $A \approx U \Sigma V^\top$.
3.  **Extract First Core:** The first TT core $C_1$ is formed by reshaping the matrix $U \Sigma^{1/2}$ into shape $1 \times N_1 \times R_1$ (since $R_0=1$) [S1, [S2][S2, unofficial]]. Note: The source describes $U \in \mathbb{R}^{N_1 \times R_1}$ as the left singular vectors and $V^\top$ multiplied by singular values. Specifically, $C_1$ corresponds to the first block.
4.  **Iterate:** For $k = 2$ to $d-1$:
    a. Reshape the remaining part of the decomposition (involving $V^\top$ and subsequent cores) into a matrix suitable for mode-$k$ unfolding.
    b. Compute SVD on this unfolded matrix.
    c. Extract core $C_k$ of size $R_{k-1} \times N_k \times R_k$.
5.  **Last Core:** The final core $C_d$ is determined by the remaining factors, with size $R_{d-1} \times N_d \times 1$ [S1, [S2][S2, unofficial]].

**Pseudocode (Standard TT-SVD):**
```python
def tt_svd(T, ranks):
    """
    T: Tensor of shape (N1, N2, ..., Nd)
    ranks: List of ranks [R1, R2, ..., R_{d-1}]
    Returns: List of TT cores [C1, C2, ..., Cd]
    """
    d = len(T.shape)
    cores = []
    
    # Current tensor state, initially T
    current_tensor = T
    
    for k in range(1, d):
        # Mode-k unfolding: reshape to (N_k, product of others)
        # Dimensions: [0, ..., k-1, k, k+1, ..., d-1]
        # We want row index = k, column index = all others
        perm = [k] + [i for i in range(d) if i != k]
        current_tensor = current_tensor.transpose(perm)
        N_k = current_tensor.shape[0]
        other_dims = current_tensor.shape[1:]
        A = current_tensor.reshape(N_k, -1)
        
        # Compute SVD
        # U: (N_k, R_{k-1}), S: (R_{k-1},), Vt: (R_{k-1}, prod_others)
        # Note: ranks[k-1] is R_{k-1} for this step (which becomes R_i in formula)
        # For k=1, R_0 = 1. So we take top 1 singular vector? 
        # Actually, standard TT-SVD takes top R_{k-1} vectors for U and 
        # combines with Vt to pass to next step.
        
        R_prev = ranks[k-2] if k > 1 else 1
        R_curr = ranks[k-1]
        
        # Truncated SVD
        U, S, Vt = svd(A, full_matrices=False)
        U = U[:, :R_curr]
        S = S[:R_curr]
        Vt = Vt[:R_curr, :]
        
        # Form Core C_k
        # C_k shape: (R_{k-1}, N_k, R_k)
        # Here R_{k-1} is the "left" rank of this core.
        # For k=1, R_0=1. U is (N_1, R_1). 
        # We need to incorporate S into the next step or current core.
        # Standard approach: C_k = reshape(U * sqrt(S), (R_{k-1}, N_k, R_k)) ?
        # Or pass sqrt(S)*Vt to next step.
        
        # Let's follow the source description: 
        # "U represents the first R1 left-singular vectors... Vt the right-singular vectors multiplied with singular values"
        # This implies the "remainder" passed to next step is Vt * diag(S).
        
        # Construct Core C_k
        # If k=1, R_prev=1. U is (N_1, R_1). 
        # C_1 shape: (1, N_1, R_1).
        C_k = U.reshape(1, N_k, R_curr) # Assuming R_prev=1 for k=1
        
        # For k>1, U is (R_{k-1}, R_k) ? No, U is (R_{k-1}, R_k) only if we reshaped previous remainder.
        # In standard TT-SVD, we unfold the *remainder* tensor.
        
        # Let's refine:
        # Step 1: Unfold T to A1 (N1, N2...Nd). SVD -> U1 (N1, R1), V1 (R1, N2...Nd).
        # C1 = reshape(U1, (1, N1, R1)).
        # Remainder = V1. Reshape V1 to (R1, N2, ..., Nd).
        
        # Step 2: Unfold Remainder to A2 (R1, N2...Nd). SVD -> U2 (R1, R2), V2 (R2, N3...Nd).
        # C2 = reshape(U2, (R1, N2, R2)).
        # Remainder = V2. Reshape V2 to (R2, N3, ..., Nd).
        
        # This matches the "U * Vt" structure where U carries the left rank.
        
        cores.append(C_k)
        
        # Prepare remainder for next iteration
        # Vt is (R_curr, prod_others). 
        # We need to reshape Vt into a tensor of shape (R_curr, N_{k+1}, ..., N_d)
        remainder_shape = [R_curr] + list(other_dims[1:]) # other_dims was (N_{k+1}, ..., N_d)
        current_tensor = Vt.reshape(remainder_shape)
        
    # Last core Cd
    # After loop k=d-1, current_tensor is shape (R_{d-1}, N_d)
    # C_d shape: (R_{d-1}, N_d, 1)
    C_d = current_tensor.reshape(ranks[d-2], T.shape[d-1], 1)
    cores.append(C_d)
    
    return cores
```

**Edge Cases and Pitfalls:**
- **Memory/Time Intensity:** Naive SSVD requires repeatedly unfolding and reshaping the full tensor, which is extremely memory- and time-intensive for large data [S1, [S2][S2, unofficial]].
- **Imbalanced Matrices:** The unfolded matrices are highly imbalanced (far more columns than rows), leading to numerical instability and high computational cost [S1, [S2][S2, unofficial]].
- **Rank Selection:** Predefined ranks $R_i$ must be chosen carefully; too low causes poor approximation, too high negates compression benefits [S1, [S2][S2, unofficial]].

## Subtopics

### [Efficient TT Decomposition (Proposed Variant)](14084-efficient-tt-decomposition-proposed-variant.md)
A memory-optimized variant of the TT-SVD that avoids processing the full unfolded tensor by working only on parts of the full data. It addresses the memory and time intensity of standard SSVD by using column sampling (random or maximum volume) to approximate the left singular vectors from a subset of columns].

## Operating characteristics
- **Time Complexity:** Standard TT-SVD is $O(d \cdot N \cdot R^3)$ or worse depending on unfolding size, where $N$ is total elements. The imbalanced SVDs make it slow for large $N$ [S1, [S2][S2, unofficial]].
- **Memory Complexity:** Linear growth with dimensionality $d$ for fixed ranks, compared to quartic growth for Tucker on 4D data [S1, [S2][S2, unofficial]]. Storage is $O(d \cdot N_i \cdot R^2)$ [S1, [S2][S2, unofficial]].
- **Strengths:** Suitable for high-dimensional data (e.g., 4D volumes) where Tucker decomposition becomes impractical due to memory constraints [S1, [S2][S2, unofficial]]. Supports interactive reconstruction and rendering by decoding time steps on demand without reconstructing the full 4D tensor [S2, [S2, unofficial]].
- **Limitations:** Standard TT-SVD is impractical for large datasets due to memory and time requirements [S1, [S2][S2, unofficial]]. Requires predefined ranks [S1, [S2][S2, unofficial]].
- **When to use:** When dealing with high-dimensional volume data (e.g., time-varying volumes) and memory is a constraint, and when interactive access to specific time steps is required [S1, [S2][S2, unofficial]].
- **When not to use:** When the tensor dimensionality is low (e.g., 2D/3D) and Tucker decomposition is sufficient, or when real-time compression is needed without pre-processing [S1, [S2][S2, unofficial]].

## Background
The Tensor-Train decomposition was introduced by Oseledets in 2011 [S1, [S2][S2, unofficial]]. It is based on the idea of factorizing a tensor into a chain of low-rank matrices (cores). The method has been applied to 4D time-dependent volume rendering to support interactive visualization of individual time steps with random and continuous time access [S1, [S2][S2, unofficial]]. The naive implementation is known as TT-SVD [S1, [S2][S2, unofficial]].
