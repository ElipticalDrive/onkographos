# Tensor Approximation
Also called: Tensor Decomposition, Tensor Reconstruction, Tucker Approximation, Tucker formulation, Tucker model

## Overview
Tensor Approximation (TA) is a compression and feature extraction method for volume data that interprets the dataset (or blocks thereof) as a multi-dimensional tensor and factorizes it into a core tensor and a set of factor matrices (the Tucker model) [S1, unofficial][S2][S3]. Unlike standard Level-of-Detail (LOD) reduction which typically results in blurring, lower-rank TA removes small-scale features while highlighting specific structural features at different spatial scales, such as non-axis aligned patterns [S2]. It builds on [Tucker Decomposition (HOSVD)](5352-tucker-decomposition-hosvd.md) by applying the decomposition to learn rank-reducible bases directly from the input data, allowing for data reduction through rank truncation [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A third-order tensor $A \in \mathbb{R}^{I_1 \times I_2 \times I_3}$ representing a volume block (e.g., a brick in a multiresolution hierarchy) [S1, unofficial].
*   **Output:** A low-rank approximation $\tilde{A}$, represented by a core tensor $B \in \mathbb{R}^{R_1 \times R_2 \times R_3}$ and three factor matrices $U^{(1)} \in \mathbb{R}^{I_1 \times R_1}$, $U^{(2)} \in \mathbb{R}^{I_2 \times R_2}$, $U^{(3)} \in \mathbb{R}^{I_3 \times R_3}$, where $R_n < I_n$ [S1, unofficial][S2].

**Data Structures:**
*   **Core Tensor $B$:** Stores the interaction coefficients between the basis vectors [S2]. In optimized GPU implementations, these are quantized using 8-bit logarithmic encoding [S2][S3].
*   **Factor Matrices $U^{(n)}$:** Store the learned basis vectors for each mode [S2]. These are quantized using 16-bit linear encoding [S2][S3].
*   **Multilinear Rank $(R_1, R_2, R_3)$:** User-defined parameters controlling the number of retained coefficients and the resulting compression ratio [S2]. Example configurations include rank 8 for $16^3$ voxel blocks [S2][S3], or multilinear ranks set to half the block size ($R_1=R_2=R_3=2$ for $4^3$ blocks) [S3].

**Algorithm Steps:**
1.  **Decomposition (Encoding):** Compute the Tucker decomposition of the input tensor $A$ [S2]. This can be done via:
    *   **HOSVD (Higher-Order SVD):** Compute matrix SVD along every data mode to obtain orthogonal factor matrices and a core tensor [S1, unofficial]. Truncating the core tensor to the desired ranks $R_n$ follows this step [S2]. Note: Truncating HOSVD results is suboptimal compared to direct reduced-rank methods [S1, unofficial].
    *   **HOOI (Higher-Order Orthogonal Iteration):** Directly obtain a reduced-rank Tucker decomposition, avoiding the suboptimal truncation of HOSVD [S1, unofficial][S2].
    *   **TUCKALS3:** An Alternating Least Squares (ALS) approach for 3D Tucker decompositions [S1, unofficial][S2].
2.  **Quantization (Optional but standard in GPU implementations):** Apply tensor-specific quantization to the floating-point coefficients [S2][S3]. Encode core tensor coefficients $b_{r_1 r_2 r_3}$ using 8-bit logarithmic encoding [S2][S3]. Encode factor matrix coefficients $u_{i_n r_n}^{(n)}$ using 16-bit linear encoding [S2][S3].
3.  **Reconstruction (Decoding):** Reconstruct the volume data from the compressed representation [S2]. Three approaches exist:
    *   **Progressive Reconstruction:** Sum weighted outer products of factor matrix columns scaled by core coefficients [S1, unofficial][S2].
    *   **Voxel-wise Reconstruction:** Compute each voxel individually by summing products of core and factor coefficients [S1, unofficial][S2].
    *   **Tensor Times Matrix (TTM) / n-mode Product:** Sequentially apply n-mode products along every mode [S1, unofficial][S2]. This is the preferred method for GPU acceleration due to lower computational complexity per voxel [S2][S3].

**Formulas:**
The Tucker model approximation is defined as:
$$ \tilde{A} = B \times_1 U^{(1)} \times_2 U^{(2)} \times_3 U^{(3)} $$
where $\times_n$ denotes the n-mode product [S2].

The n-mode product between a tensor $X$ and matrix $U$ is equivalent to a matrix product of the mode-n unfolded tensor $X^{(n)}$ and $U$:
$$ Y = X \times_n U \iff Y^{(n)} = U X^{(n)} $$
where $X^{(n)}$ is the mode-n unfolding of $X$ into a matrix [S2].

**Progressive Reconstruction Formula:**
$$ \tilde{A} = \sum_{r_1} \sum_{r_2} \sum_{r_3} b_{r_1 r_2 r_3} \cdot u_{r_1}^{(1)} \cdot u_{r_2}^{(2)} \cdot u_{r_3}^{(3)} $$
where $u_{r_n}^{(n)}$ are column vectors from the factor matrices [S2].

**Voxel-wise Reconstruction Formula:**
$$ a_{i_1 i_2 i_3} = \sum_{r_1} \sum_{r_2} \sum_{r_3} b_{r_1 r_2 r_3} \cdot u_{i_1 r_1}^{(1)} \cdot u_{i_2 r_2}^{(2)} \cdot u_{i_3 r_3}^{(3)} $$
where $u_{i_n r_n}^{(n)}$ is the coefficient at index $i_n$ in the $r_n$-th column of factor matrix $U^{(n)}$ [S2].

**Parameters:**
*   **Multilinear Ranks $(R_1, R_2, R_3)$:** Control the compression ratio and feature retention [S2]. Typical values include $R_1=R_2=R_3=8$ for $16^3$ voxel blocks [S2][S3], or $R_n = \text{block\_size}/2$ for smaller blocks [S3].

**Edge Cases and Pitfalls:**
*   **Block Boundaries:** At low ranks, block boundaries become apparent as artifacts [S2]. These are inherent to brick-based lossy compression [S2]. They can be alleviated by interblock interpolation (sampling neighboring bricks) or deferred filtering, at the cost of higher rendering time [S2].
*   **Feature Loss:** High rank reduction removes small-scale features [S2]. While this can highlight larger structures (e.g., growth prisms in dental enamel), it may make irregular spatial distributions difficult to identify if the rank is too low [S2].
*   **Suboptimal Truncation:** Truncating the core tensor after HOSVD is not optimal in terms of difference between approximated and original data compared to HOOI [S1, unofficial][S2].

**Pseudocode (GPU Voxel-wise Reconstruction):**
```python
def reconstruct_voxel(i1, i2, i3, core_tensor, factor_matrices):
    """
    Computes the value of a single voxel using the Tucker model.
    Complexity: O(R1 * R2 * R3) per voxel.
    """
    R1, R2, R3 = core_tensor.shape
    U1, U2, U3 = factor_matrices
    result = 0.0
    for r1 in range(R1):
        for r2 in range(R2):
            for r3 in range(R3):
                b = core_tensor[r1, r2, r3]
                u1_val = U1[i1, r1]
                u2_val = U2[i2, r2]
                u3_val = U3[i3, r3]
                result += b * u1_val * u2_val * u3_val
    return result
```

## Subtopics

### [Hierarchical Tensor-based Transform](5369-hierarchical-tensor-based-transform.md)
A compression scheme that recursively partitions the input domain into smaller blocks, defining a truncated tensor-product basis for each block. It represents the volume as a summation of incomplete tensor approximations across multiple resolution levels, with residual tensors passed from higher levels. Choose this when a global multiscale hierarchy with residual propagation is needed rather than independent per-brick approximations.

### [Tensor Times Matrix (TTM) Reconstruction](7404-tensor-times-matrix-ttm-reconstruction.md)
A GPU-accelerated decoding method that reconstructs volume bricks by sequentially applying n-mode products. It reduces computational complexity per voxel from cubic to linear with respect to the rank $R$ by storing intermediate tensors in global memory. Choose this for interactive frame rates on large datasets where naive reconstruction is too slow.

## Operating characteristics
*   **Time Complexity:**
    *   **Progressive Reconstruction:** Cubic rank complexity $O(R_1 \cdot R_2 \cdot R_3)$ [S2]. For $R=16$, this is 4096 operations per voxel [S2].
    *   **TTM/n-mode Product Reconstruction:** Linear rank complexity $O(M)$ where $M$ is the rank (assuming symmetric ranks or referring to the cost per mode relative to the full grid generation cost) [S2]. The improvement from cubic to linear is significant (e.g., 256-fold for $R=16$) [S2][S3].
*   **Memory Complexity:** Proportional to the size of the core tensor ($R_1 R_2 R_3$) plus the factor matrices ($I_1 R_1 + I_2 R_2 + I_3 R_3$) [S2]. Quantization reduces this further (8-bit core, 16-bit bases) [S2][S3].
*   **Performance:** Enables interactive exploration of massive volumes in real-time by allowing high data reduction ratios while maintaining high display resolution [S2].
*   **Strengths:** Captures non-axis aligned features at different scales better than wavelet transforms using the same amount of coefficients [S2][S3]. Allows highlighting of specific structural features (e.g., layered periodic arrangements) by adjusting rank [S2].
*   **Limitations:** Wavelet transforms still outperform TA in reconstructing overall statistical distributions at coarse resolutions [S2][S3]. Block boundary artifacts appear at low ranks [S2].
*   **When to use:** Interactive large volume visualization, microstructural analysis where specific features at different scales need to be highlighted, and scenarios requiring high compression ratios with feature preservation [S2][S3].
*   **When not to use:** When preserving the exact statistical distribution of the volume at coarse resolutions is critical (wavelets are preferred) [S2][S3].

## Background
Tensor Approximation was introduced to Direct Volume Rendering (DVR) by Suter et al. [SIM* 11] [S2][S3]. It applies SVD/PCA-like tools to volume data by interpreting blocks as tensors [S2]. The method was further developed to include tensor-specific quantization and optimized GPU reconstruction [S2][S3]. It is used in interactive large volume visualization and microstructural analysis (e.g., dental enamel, chameleon bone) [S2][S3].
