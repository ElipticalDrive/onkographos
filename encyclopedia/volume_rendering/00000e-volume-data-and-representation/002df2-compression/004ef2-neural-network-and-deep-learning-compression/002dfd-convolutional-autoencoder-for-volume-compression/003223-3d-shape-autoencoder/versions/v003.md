# 3D Shape Autoencoder

Also called: Shape prior autoencoder

## Overview
The 3D Shape Autoencoder is a convolutional neural network architecture designed to learn a compact prior distribution of 3D shapes [S1, unofficial]. It solves the problem of representing complex volumetric or geometric data by mapping high-dimensional 3D inputs into a low-dimensional latent vector and reconstructing them, thereby enabling tasks such as novel-view synthesis and image relighting [S1, unofficial]. It differs from standard autoencoders by explicitly focusing on learning a "shape prior" using 3D convolutions, which allows for the recovery of pose and shape factors from single images, outperforming feed-forward networks in structural consistency [S1, unofficial].

## How it works
The method consists of an encoder, a bottleneck, and a decoder, all utilizing 3D convolutions to process volumetric data.

**Inputs and Outputs:**
*   **Input:** A 3D volume or shape representation (e.g., a voxel grid or signed distance function).
*   **Output:** A reconstructed 3D volume identical in dimensions to the input.

**Data Structures and Layout:**
The network parameters are defined by specific channel counts, kernel sizes, and strides. The activation functions are strictly defined per layer type.

1.  **Encoder:**
    *   Consists of a series of 3D convolutional layers.
    *   **Layer 1:** Channels = 64, Kernel Size = 5, Stride = 2.
    *   **Layer 2:** Channels = 128, Kernel Size = 5, Stride = 2.
    *   **Layer 3:** Channels = 256, Kernel Size = 2, Stride = 2.
    *   **Layer 4:** Channels = 512, Kernel Size = 2, Stride = 2.
    *   **Activation:** Exponential Linear Unit (ELU) is applied after every convolutional layer in the encoder, except for the final one [S1, unofficial].

2.  **Bottleneck (Middle):**
    *   A fully connected (linear) layer maps the flattened output of the last encoder convolution to a 200-dimensional vector [S1, unofficial].
    *   **Activation:** Sigmoid activation is applied to this 200-dimensional vector [S1, unofficial].
    *   A second fully connected layer maps the 200-dimensional vector to a $(4 \times 4 \times 512)$-dimensional vector (total 8192 elements) [S1, unofficial].

3.  **Decoder:**
    *   The vector from the bottleneck is reshaped into a tensor of size $4 \times 4 \times 512$ [S1, unofficial].
    *   Consists of a series of 3D transposed convolutional (up-convolution) layers.
    *   **Layer 1:** Channels = 256, Kernel Size = 4, Stride = 2.
    *   **Layer 2:** Channels = 128, Kernel Size = 4, Stride = 2.
    *   **Layer 3:** Channels = 64, Kernel Size = 4, Stride = 2.
    *   **Layer 4:** Channels = 32, Kernel Size = 4, Stride = 2.
    *   **Layer 5:** Channels = 1, Kernel Size = 4, Stride = 1.
    *   **Activation:** ELU is applied after every convolutional layer in the decoder, except for the final one [S1, unofficial].

**Formulas and Parameters:**
*   **Activation Functions:**
    *   Hidden layers: $ELU(x) = \max(0, x) + \min(0, \alpha(e^x - 1))$ where $\alpha=1.0$ is the standard default for ELU [S1, unofficial].
    *   Final layers (Encoder output, Decoder output): $Sigmoid(x) = \frac{1}{1 + e^{-x}}$ [S1, unofficial].
*   **Reshaping:** The 200-dim vector $v$ is reshaped to tensor $T$ such that $T[i, j, k]$ corresponds to the appropriate index in $v$ based on row-major or column-major ordering (implementation detail, not specified in source, but standard for reshape operations) [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn

class ShapePriorAutoencoder(nn.Module):
    def __init__(self):
        super(ShapePriorAutoencoder, self).__init__()
        
        # Encoder
        # Conv3d(in_channels, out_channels, kernel_size, stride, padding)
        # Note: Padding is not specified in sources. Standard 'same' padding 
        # is assumed to maintain spatial dimensions relative to stride/kernel.
        self.enc_conv1 = nn.Conv3d(1, 64, kernel_size=5, stride=2, padding=2)
        self.enc_conv2 = nn.Conv3d(64, 128, kernel_size=5, stride=2, padding=2)
        self.enc_conv3 = nn.Conv3d(128, 256, kernel_size=2, stride=2, padding=0)
        self.enc_conv4 = nn.Conv3d(256, 512, kernel_size=2, stride=2, padding=0)
        
        # Bottleneck
        self.fc1 = nn.Linear(512 * 4 * 4, 200) # 4x4x512 derived from input size reduction
        self.fc2 = nn.Linear(200, 4 * 4 * 512)
        
        # Decoder
        self.dec_conv1 = nn.ConvTranspose3d(512, 256, kernel_size=4, stride=2, padding=1)
        self.dec_conv2 = nn.ConvTranspose3d(256, 128, kernel_size=4, stride=2, padding=1)
        self.dec_conv3 = nn.ConvTranspose3d(128, 64, kernel_size=4, stride=2, padding=1)
        self.dec_conv4 = nn.ConvTranspose3d(64, 32, kernel_size=4, stride=2, padding=1)
        self.dec_conv5 = nn.ConvTranspose3d(32, 1, kernel_size=4, stride=1, padding=1)

    def forward(self, x):
        # Encoder
        x = torch.elu(self.enc_conv1(x))
        x = torch.elu(self.enc_conv2(x))
        x = torch.elu(self.enc_conv3(x))
        x = torch.sigmoid(self.enc_conv4(x)) # Last encoder layer uses sigmoid
        
        # Bottleneck
        x = x.view(x.size(0), -1) # Flatten
        x = self.fc1(x)
        x = torch.sigmoid(x) # Sigmoid activation after 200-dim vector
        x = self.fc2(x)
        x = x.view(x.size(0), 512, 4, 4) # Reshape to 4x4x512
        
        # Decoder
        x = torch.elu(self.dec_conv1(x))
        x = torch.elu(self.dec_conv2(x))
        x = torch.elu(self.dec_conv3(x))
        x = torch.elu(self.dec_conv4(x))
        x = torch.sigmoid(self.dec_conv5(x)) # Last decoder layer uses sigmoid
        
        return x
```

**Edge Cases and Pitfalls:**
*   **Input Dimensions:** The architecture assumes an input size that reduces to $4 \times 4$ spatially after the encoder's strided convolutions. If the input resolution is not compatible with the kernel/stride sequence (5,5,2,2 with strides 2,2,2,2), the final spatial dimensions before the bottleneck may not be $4 \times 4$, causing the reshape operation to fail or produce incorrect latent tensors [S1, unofficial].
*   **Activation Mismatch:** Using ReLU or other activations for the specified layers will deviate from the trained prior, potentially leading to poor reconstruction quality or mode collapse in generative tasks [S1, unofficial].

## Subtopics

### [Latent Voxel Auto-Encoder](17589-latent-voxel-auto-encoder.md)
The Latent Voxel Auto-Encoder (LAE) is a hierarchical neural network that compresses 3D voxel grids into a structured latent space consisting of a global 1D vector, a coarse 3D tensor, and a fine 2D tensor. It solves the dimensionality bottleneck of training diffusion models on high-resolution 3D data by reducing the representation size while preserving semantic structure. Unlike standard auto-encoders that map directly to a single latent space, LAE separates global scene properties from local geometric details using 2D CNNs applied to concatenated vertical slices, enabling efficient generation in [Hierarchical Latent Diffusion Models](17598-hierarchical-latent-diffusion-models.md).

### SurroFlow
SurroFlow uses normalizing flows to learn an invertible transformation between a simple base distribution and the data distribution [S2, unofficial]. It trains a conditional normalizing flow in the latent space of a 3D convolutional autoencoder [S2, unofficial]. It supports bidirectional prediction: forward mapping from parameters to simulation outputs, and reverse mapping from observed data back to likely parameter values [S2, unofficial]. The constant-dimensionality constraint of normalizing flows limits SurroFlow to operating at lower resolution than the native simulation grid [S2, unofficial]. On MPAS-Ocean (192 × 96 × 12, 128 training members), it achieved 46.69 dB PSNR with a 48 MB model trained in 11.5 hours [S2, unofficial]. On Nyx at $128^3$ rather than $512^3$, PSNR drops to 30.93 dB, below VDL-Surrogate’s 33.66 dB [S2, unofficial]. Compared to VDL-Surrogate’s 45.82 dB at 0.63 GB and 139.8 hours, SurroFlow offers significantly faster training and smaller model size [S2, unofficial].

### Conditional Adversarial Autoencoder
This variant drops the latent space from the pipeline of the standard autoencoder [S3]. It trains only the reconstruction and conditional adversarial objectives [S3]. Optimization difficulty with these remaining objectives causes visible 3D inconsistency, despite decent reconstruction quality [S3].

### 3Da-AE Training
This variant involves a specific training procedure for 3Da-AE [S4, unofficial].
**Steps:**
1.  **Input:** Training set $X_{train}$, Encoder $E_\phi$, Decoder $D_\psi$, Renderer $R_\alpha$, number of steps $N$, loss weights $\lambda_{ae}, \lambda_{Enc}, \lambda_{Dec}$, and optimizer [S4, unofficial].
2.  **Initialization:** Random initialization of local triplanes $T_{mic}$, weights $W$, and global triplanes $T_{mac}$ [S4, unofficial].
3.  **Loop:** For $N$ steps, for each batch $\{s, p, x_p\}$ in shuffled $X_{train}$:
    *   Compute local representation $T_{smic}$ and global representation $T_{smac}$ from $T_{mic}, W_s, B$ [S4, unofficial].
    *   Compute total representation $T_s = T_{smic} \oplus T_{smac}$, where $\oplus$ concatenates along the feature dimension [S4, unofficial].
    *   Encode input: $z_p = E_\phi(x_p)$ [S4, unofficial].
    *   Decode latent: $\hat{x}_p = D_\psi(z_p)$ [S4, unofficial].
    *   Render from triplanes: $\tilde{z}_p = R_\alpha(T_s, p)$ [S4, unofficial].
    *   Decode rendered latent: $\tilde{x}_p = D_\psi(\tilde{z}_p)$ [S4, unofficial].
    *   Compute losses:
        *   $L_{ae} = \|x_p - \hat{x}_p\|^2$ [S4, unofficial].
        *   $L_{Enc} = \|z_p - \tilde{z}_p\|^2$ [S4, unofficial].
        *   $L_{Dec} = \|x_p - \tilde{x}_p\|^2$ [S4, unofficial].
    *   Compute total loss: $L = \lambda_{ae}L_{ae} + \lambda_{Enc}L_{Enc} + \lambda_{Dec}L_{Dec}$ [S4, unofficial].
    *   Optimize $T_{mic}, W_s, B, \alpha, \phi, \psi$ with $L$ [S4, unofficial].
**Pitfall:** During warmup, only local triplanes, global triplanes, and scene-specific coefficients are optimized; the autoencoder is kept frozen to prevent random gradients from back-propagating into $E_\phi$ and $D_\psi$ [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** The bottleneck size is fixed at 200 dimensions for the latent vector, plus the parameters of the convolutional layers. The decoder expands this to $4 \times 4 \times 512$ before reconstruction.
*   **Measured Performance:** Not given in the sources for the base 3D Shape Autoencoder. Variants like SurroFlow achieve 46.69 dB PSNR on MPAS-Ocean with a 48 MB model [S2, unofficial].
*   **Strengths:** Effective at learning shape priors for tasks like novel-view synthesis and relighting [S1, unofficial]. The use of 3D convolutions preserves spatial structure better than feed-forward networks [S1, unofficial].
*   **Limitations:** Speed and performance require further improvement [S1, unofficial]. Resolution is limited by the fixed bottleneck and convolutional strides [S1, unofficial].
*   **When to use:** When a compact prior of 3D shapes is needed for generative tasks or reconstruction from limited data [S1, unofficial].
*   **When not to use:** When high-resolution simulation grids are required without resolution reduction (e.g., SurroFlow fails at native $512^3$ resolution) [S2, unofficial].

## Background
The 3D Shape Autoencoder was introduced in the context of differentiable rendering and 3D shape representation [S1, unofficial]. It was proposed as an alternative to feed-forward networks, aiming to learn a prior of 3D shapes using 3D convolutions [S1, unofficial]. The method was used to reconstruct chairs from single images, recovering pose and shape factors for sharper novel-view synthesis and relighting [S1, unofficial]. It is a foundational component in methods that require a structured latent space for 3D data, such as the SurroFlow variant for scientific simulations [S2, unofficial] and the 3Da-AE for efficient scene learning [S4, unofficial].
