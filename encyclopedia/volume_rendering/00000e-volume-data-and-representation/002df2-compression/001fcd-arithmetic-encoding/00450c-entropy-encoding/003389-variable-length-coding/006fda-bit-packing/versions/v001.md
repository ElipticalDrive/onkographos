# Bit Packing

Also called: Packing multiple cells into a single byte

## Overview
Bit packing is a lossless compression technique that reduces memory footprint by storing multiple voxel values into a single byte, utilizing fewer bits per voxel than a standard byte (char) [S1, unofficial]. It solves the problem of excessive memory usage in dense voxel chunks by providing linear compression relative to the bit-depth reduction [S1, unofficial]. Unlike its sibling [Variable Bit Length Encoding](7195-variable-bit-length-encoding.md), which varies the bit width per voxel, bit packing uses a fixed, uniform bit width across a chunk to align values into byte boundaries [S1, unofficial].

## How it works
**Inputs:** A chunk of voxel data (e.g., an $8 \times 8 \times 8$ grid) where each voxel value fits within $n$ bits, where $n < 8$.
**Outputs:** A compressed byte array where each byte contains $\lfloor 8/n \rfloor$ voxel values.
**Data Structures:**
- Input: Array of $N$ voxels, each represented by an integer requiring $n$ bits.
- Output: Array of $M$ bytes, where $M = \lceil N \times n / 8 \rceil$.

**Steps:**
1. Determine the minimum number of bits $n$ required to represent the range of values in the chunk.
2. Calculate the number of voxels per byte: $k = \lfloor 8/n \rfloor$.
3. Iterate through the input voxel array in steps of $k$.
4. For each group of $k$ voxels, pack them into a single byte:
   - Initialize a byte `b` to 0.
   - For $i$ from 0 to $k-1$:
     - Shift `b` left by $n$ bits.
     - OR `b` with the $i$-th voxel value (masked to $n$ bits).
   - Store `b` in the output array.
5. If the total number of voxels is not a multiple of $k$, handle the remaining voxels by packing them into the final byte, padding the unused bits with zeros or a defined sentinel value [G].

**Formula:**
For a chunk of size $V$ voxels with $n$ bits per voxel, the compressed size $S$ in bytes is:
$$ S = \left\lceil \frac{V \times n}{8} \right\rceil $$

**Parameters:**
- $n$: Bits per voxel. Typical values are 4, 5, 6, or 7, depending on the data range [S1, unofficial].
- Chunk size: Commonly $8 \times 8 \times 8$ (512 voxels) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Ensure voxel values are truncated or masked to $n$ bits before packing to avoid overflow into adjacent voxels [G].
- **Boundaries:** If $V \times n$ is not divisible by 8, the last byte contains unused bits. These must be handled consistently during unpacking [G].
- **Degenerate Input:** If $n \ge 8$, bit packing provides no compression benefit and may introduce overhead due to alignment [S1, unofficial].

**Pseudocode:**
```python
def bit_pack(voxels: list[int], bits_per_voxel: int) -> list[int]:
    """
    Pack a list of voxel integers into a list of bytes.
    
    Args:
        voxels: List of integer voxel values.
        bits_per_voxel: Number of bits used per voxel (must be < 8).
        
    Returns:
        List of integers (bytes) representing the packed data.
    """
    if bits_per_voxel >= 8:
        raise ValueError("Bits per voxel must be less than 8 for compression.")
    
    voxels_per_byte = 8 // bits_per_voxel
    packed = []
    
    # Process full groups
    for i in range(0, len(voxels), voxels_per_byte):
        byte_val = 0
        for j in range(voxels_per_byte):
            if i + j < len(voxels):
                voxel_val = voxels[i + j] & ((1 << bits_per_voxel) - 1)
                byte_val = (byte_val << bits_per_voxel) | voxel_val
            else:
                # Pad remaining bits with 0 if chunk is not full
                byte_val = byte_val << bits_per_voxel
        packed.append(byte_val)
        
    return packed
```

## Subtopics

### Generic Leaf Compression (RLE/Zip/Bit Quantization)
Generic leaf compression applies lossless RLE, Zip, or lossy bit quantization directly to the `mLeafDAT` for cases with an arbitrary number of inactive voxel values, rather than just one or two [S2, unofficial]. These schemes can be applied to special cases but are orders of magnitude slower than bit-mask-based codes like bit packing [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(N)$ for packing and unpacking, where $N$ is the number of voxels.
- Memory: Reduces storage by a factor of $8/n$ [S1, unofficial].

**Measured Performance:**
- For an $8 \times 8 \times 8$ chunk (512 voxels) with 4-bit packing, the size reduces from 512 bytes to 256 bytes [S1, unofficial].

**Scaling:**
- Compression is linear with respect to the chunk size [S1, unofficial].

**Strengths and Limitations:**
- Strengths: Simple implementation, low CPU overhead, effective for dense data with small ranges [S1, unofficial].
- Limitations: Ineffective if $n \ge 8$ or if data distribution is highly variable requiring large $n$ [S1, unofficial].

**When to Use:**
- Use when voxel values have a small, known range and memory bandwidth is a bottleneck [S1, unofficial].
- Avoid when data has large dynamic ranges or when compression speed is less critical than decompression flexibility [S2, unofficial].

## Background
Bit packing originated as a practical optimization in voxel engine development to reduce memory usage for chunk-based world storage [S1, unofficial]. It is a fundamental technique in volume data compression, often used in conjunction with other methods like variable-length coding [S1, unofficial].
