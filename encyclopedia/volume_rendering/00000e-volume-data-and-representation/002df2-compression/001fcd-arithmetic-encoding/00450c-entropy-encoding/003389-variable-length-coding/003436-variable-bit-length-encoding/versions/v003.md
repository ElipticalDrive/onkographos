# Variable Bit Length Encoding

Also called: 可变字长编码

## Overview
Variable Bit Length Encoding (VBLE) is a lossless compression technique for volume data that reduces storage by encoding the difference between each voxel and the minimum value in its local block, using only the number of bits necessary to represent that difference [S1, unofficial]. It is particularly effective for scientific and medical volume data where background voxels have small values and non-background voxels have larger values, allowing significant bit savings when data variation within a block is low [S1, unofficial]. Unlike fixed-length encoding, VBLE adapts the bit depth per block based on the local range, though it typically requires combination with Run-Length Encoding (RLE) to efficiently store the variable bit-length metadata [S1, unofficial].

## How it works
**Inputs:** A volume dataset, typically processed as a collection of 2D slices or 3D blocks.
**Outputs:** A compressed bitstream containing the base values, bit-length metadata, and encoded residuals.

**Data Structures:**
1.  **Block/Quadtree Structure:** For each data slice, a quadtree structure is built to represent the spatial hierarchy of the data [S1, unofficial].
2.  **Bitstream:** Contains three components:
    *   Base value (minimum value of the block).
    *   Bit-length metadata (encoded via RLE).
    *   Residual values (differences from the base, packed into the specified number of bits).

**Steps:**
1.  **Partitioning:** Divide the volume data into blocks (or slices). For each slice, construct a quadtree structure [S1, unofficial].
2.  **Base Value Selection:** Identify the minimum value ($min$) within the current block. This value is stored explicitly as the base [S1, unofficial].
3.  **Residual Calculation:** For each voxel $v$ in the block, calculate the residual $r = v - min$ [S1, unofficial].
4.  **Bit-Length Determination:** Determine the number of bits $n$ required to represent the maximum residual in the block. If $max\_r$ is the maximum residual, $n = \lceil \log_2(max\_r + 1) \rceil$ [S1, unofficial].
5.  **Metadata Encoding:** Encode the bit-length $n$ for each voxel (or block, depending on granularity). Since $n$ varies, this metadata is typically compressed using Run-Length Encoding (RLE) to handle sequences of identical bit-lengths [S1, unofficial].
6.  **Residual Encoding:** Pack the residuals $r$ into the bitstream using $n$ bits per voxel.

**Parameters:**
*   Block size: Not given in the sources.
*   Quadtree depth: Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Metadata Overhead:** VBLE alone incurs overhead because the bit length for each voxel must be stored. This is usually mitigated by combining VBLE with RLE [S1, unofficial].
*   **Precision:** The method assumes integer or quantized data. Floating-point data requires preprocessing (e.g., prediction and conversion to integers) before VBLE can be applied effectively [S1, unofficial].

**Pseudocode:**
```python
def vble_encode(volume_slice):
    # Step 1: Build quadtree (conceptual, as per [S1, unofficial])
    # quadtree = build_quadtree(volume_slice)
    
    # Step 2: Partition into blocks (simplified to single block for this example)
    block = volume_slice
    
    # Step 3: Find minimum value
    min_val = min(block)
    
    # Step 4: Calculate residuals
    residuals = [v - min_val for v in block]
    
    # Step 5: Determine bit length for the block
    max_residual = max(residuals)
    if max_residual < 0:
        n = 0
    else:
        n = ceil(log2(max_residual + 1))
        
    # Step 6: Encode metadata (bit length)
    # In practice, this is done per-voxel or per-subblock and compressed with RLE
    # Here we assume a single bit-length for the whole block for simplicity
    metadata = rle_encode([n] * len(block))
    
    # Step 7: Encode residuals
    residual_bits = []
    for r in residuals:
        residual_bits.append(format(r, f'0{n}b'))
        
    return metadata, residual_bits

def vble_decode(metadata, residual_bits, block_size, n):
    # Step 1: Decode metadata to get bit length
    # In practice, RLE decoding is needed
    bit_lengths = rle_decode(metadata)
    
    # Step 2: Decode residuals
    # Note: The base value must be stored separately and is not part of residual_bits
    # This function assumes base_val is passed or known
    residuals = []
    for bits in residual_bits:
        # Convert binary string to integer
        r = int(bits, 2)
        residuals.append(r)
        
    # Step 3: Reconstruct values
    # base_val is required but not returned by encode in this simplified pseudocode
    # Reconstructed values = residuals + base_val
    return residuals 
```
*[G] The pseudocode assumes a single block for clarity. Real implementations process blocks hierarchically via the quadtree. The base value is not included in `residual_bits` and must be stored separately.*

## Subtopics

### [Greedy Merging for VV Codes](17555-greedy-merging-for-vv-codes.md)
A method for constructing Variable-length Variable-length (VV) codes by iteratively merging the least-probable leaf in a parse tree to reduce code length, aiming to minimize coding rate. It is chosen when optimizing for the most efficient code length for a given probability distribution of residuals. Link: [Greedy Merging for VV Codes](17555-greedy-merging-for-vv-codes.md).

### RBUC Decoder Implementation
Decompression uses pre-order traversal of the RBUC tree, replaced by three nested loops (one per level) maintaining 'current' bit length on each level. Loops are unrolled in GPU implementation for conditional-free code. Decoder determines number of bits to read for next few nodes, fetches variable-length residuals from bit stream. Signed residuals are stored biased by $2^{w-1}$ to move into unsigned range $[0, 2^{w-1}]$ [S2].

### RBUC Residual Coding
Variable-length lossless coding for residuals. Based on RBUC, which amortizes length bits over several consecutive residuals using a tree structure. Each interior node stores $w = \max_i(\lceil \log_2(x_i + 1) \rceil)$ over child nodes with unsigned values $x_i$. Residuals are mapped to unsigned ordinals $(0, -1, +1, -2, +2...)$ for computing $w$. Trees are shallow (4 levels for residuals up to 127 bits). Static branching is used: lowest-level branching factor 4-5 vertices, second-level branching ~16 nodes. Trees avoid grouping residuals from end of one row with start of next (spatial locality). Each row partitioned into groups of 3-5 vertices, second-level groups span whole rows [S2].

## Operating characteristics
*   **Time Complexity:** Encoding is linear with respect to the number of voxels, plus the overhead of building the quadtree and RLE compression. Decoding is also linear, with the overhead of RLE decoding and bit-packing.
*   **Memory Complexity:** Requires storage for the quadtree structure and the compressed bitstream. The quadtree adds overhead proportional to the number of nodes.
*   **Measured Performance:** Effective for data with low intra-block variance. For data with high variance, the bit-length overhead may reduce compression ratios.
*   **Strengths:** Simple to implement, effective for scientific/medical data with distinct background/foreground, adaptive bit depth.
*   **Limitations:** Overhead of storing bit-lengths (mitigated by RLE), less effective for high-entropy data.
*   **When to use:** Scientific and medical volume data with significant background regions.
*   **When not to use:** Data with high random noise or high entropy where fixed-length or entropy coding (like Huffman) might be more efficient.

## Background
VBLE is a technique adapted from document and image compression for volume data [S1, unofficial]. It is particularly relevant in medical imaging and scientific visualization, where lossless compression is required for archival purposes [S1, unofficial]. The technique leverages the spatial coherence of volume data, often processing data slice by slice [S1, unofficial]. Klajnsek et al. proposed building a quadtree for each slice and using VBLE on the differences between slices [S1, unofficial].
