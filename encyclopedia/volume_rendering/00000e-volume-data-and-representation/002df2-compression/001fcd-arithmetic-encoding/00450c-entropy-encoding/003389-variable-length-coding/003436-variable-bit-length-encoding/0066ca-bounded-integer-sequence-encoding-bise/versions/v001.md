# Bounded Integer Sequence Encoding (BISE)
## Overview
Bounded Integer Sequence Encoding (BISE) is a variable-length coding method that stores sequences of integers from arbitrary alphabets (up to 256 symbols) using a fractional number of bits per symbol [S1]. It solves the inefficiency of rounding up symbol counts to the next power of two by packing symbols into groups that align with bit boundaries, specifically using binary, trit (3-symbol), and quint (5-symbol) encodings [S1]. Unlike standard binary encoding, BISE allows the compressor to select the most space-efficient alphabet representation for a given symbol count, significantly reducing storage waste for non-power-of-two alphabet sizes [S1].

## How it works
**Inputs:** A sequence of $S$ integers (symbols), where each integer is in the range $[0, N-1]$ for an alphabet size $N$.
**Outputs:** A bit string of fixed length determined by $N$ and $S$.

**Data Structures:**
The encoding relies on three primitive alphabet types:
1.  **Binary:** Alphabet size up to $2^n - 1$.
2.  **Trit:** Alphabet size up to $3 \cdot 2^n - 1$. Uses a trit $t \in [0, 2]$ and $n$ bits $m$.
3.  **Quint:** Alphabet size up to $5 \cdot 2^n - 1$. Uses a quint $q \in [0, 4]$ and $n$ bits $m$.

**Parameters:**
*   $S$: Number of symbols in the sequence.
*   $N$: Size of the alphabet (number of distinct symbol values).
*   $n$: Integer parameter such that $2^n$ is the base power of two for the encoding scheme.

**Formulas:**
The compressor selects the encoding scheme that minimizes storage. The storage cost for a sequence of $S$ symbols with alphabet size $N$ is:

1.  **Binary Encoding:**
    If $N \le 2^n - 1$:
    $$ \text{Bits} = N \cdot S $$

2.  **Trit Encoding:**
    If $N \le 3 \cdot 2^n - 1$:
    $$ \text{Bits} = n \cdot S + \lceil \frac{8S}{5} \rceil $$
    Reconstruction of a symbol $x$ from trit $t$ and bits $m$:
    $$ x = t \cdot 2^n + m $$

3.  **Quint Encoding:**
    If $N \le 5 \cdot 2^n - 1$:
    $$ \text{Bits} = n \cdot S + \lceil \frac{7S}{3} \rceil $$
    Reconstruction of a symbol $x$ from quint $q$ and bits $m$:
    $$ x = q \cdot 2^n + m $$

**Numbered Steps:**
1.  Determine the alphabet size $N$ required for the data.
2.  Identify the smallest integer $n$ such that the alphabet fits into one of the three schemes:
    *   Binary: $N \le 2^n - 1$
    *   Trit: $N \le 3 \cdot 2^n - 1$
    *   Quint: $N \le 5 \cdot 2^n - 1$
3.  Calculate the storage cost for each valid scheme using the formulas above.
4.  Select the scheme with the minimum storage cost.
5.  Encode the sequence of $S$ symbols using the selected scheme.
    *   For **Binary**: Pack $n$ bits per symbol directly.
    *   For **Trit**: Pack groups of 5 symbols. Each group uses 8 bits. **Edge Cases and Pitfalls:**
*   **Non-multiple of 3 or 5:** When $S$ is not a multiple of 3 (for quint) or 5 (for trit), the "last few bits" constraint must be carefully managed to avoid wasting storage. The encoder must ensure that any unused bits at the end of the sequence are zero if the corresponding symbols are zero [S1].
*   **Precision:** The formulas use ceiling functions for the overhead bits. Incorrect rounding can lead to storage miscalculations.
*   **Alphabet Size Limits:** BISE supports alphabets up to 256 symbols. For larger alphabets, other methods are required.

## Operating characteristics
*   **Time Complexity:** Encoding requires determining the optimal $n$ and scheme, which is $O(1)$ for fixed alphabet sizes, followed by $O(S)$ for packing the symbols.
*   **Memory Complexity:** $O(S)$ bits for the output.
*   **Performance:** BISE is significantly more efficient than simple binary encoding for alphabet sizes that are not powers of two. For example, a 5-symbol alphabet (quint) uses 7 bits for 3 symbols (2.33 bits/symbol) instead of 6 bits (2 bits/symbol) or 9 bits (3 bits/symbol) [S1].
*   **Strengths:** High compression efficiency for small, arbitrary alphabets; no padding overhead.
*   **Limitations:** Complex bit-packing logic for trits and quints; only supports alphabets up to 256 symbols.

## Background
BISE was developed as part of the Adaptive Scalable Texture Compression (ASTC) format by ARM [S1]. It was designed to allow fine-grained control over compression quality and size by efficiently encoding quantized color and weight values per texel [S1]. The technique leverages the mathematical properties of small prime numbers (3 and 5) to pack symbols into bit boundaries with minimal waste [S1].
