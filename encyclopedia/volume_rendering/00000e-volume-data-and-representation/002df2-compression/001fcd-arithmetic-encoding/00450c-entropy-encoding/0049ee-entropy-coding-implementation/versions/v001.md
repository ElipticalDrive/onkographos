# Entropy Coding Implementation

Also called: Huffman coding

## Overview
Entropy coding implementation finalizes the compression of volumetric data by mapping quantized syntax elements to bitstreams using statistical models. It solves the problem of residual storage overhead after prediction and quantization. Unlike [Variable-Length Coding](7012-variable-length-coding.md), which relies on fixed prefix codes, this method typically employs arithmetic coding or Huffman coding to achieve near-entropy-limit compression ratios [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Quantized syntax elements (coarse residuals, fine residuals, reference indexes) and other minor metadata [S1].
*   **Output:** A compressed binary bitstream [S1, S2].

**Data Structures:**
*   **Syntax Elements:** Integers representing prediction errors or indices.
*   **Probability Model:** Implicit or explicit frequency counts used to determine code lengths or arithmetic intervals [S1, S2].

**Steps:**
1.  **Preprocessing (Reference Rearrangement):** For reference indexes, rearrange the candidate list by placing the most recently selected candidate in the first position. This exploits temporal or spatial locality to improve coding efficiency [S1].
2.  **Classification:**
    *   Identify syntax elements with significant storage requirements (coarse residuals, fine residuals, reference indexes) [S1].
    *   Identify syntax elements with negligible storage requirements [S1].
3.  **Encoding:**
    *   **Primary Elements:** Encode significant elements using a sample arithmetic coding implementation [S1]. The arithmetic coder maintains a current interval $[L, H)$, initially $[0, 1)$. For each symbol, the interval is subdivided based on the symbol's probability mass. The final output is a binary fraction within the final interval [G].
    *   **Secondary Elements:** Encode minor syntax elements using an LZ77 codec [S1].
    *   **Alternative/Additional:** In some pipelines, the resulting model file is compressed using Huffman coding [S2]. Huffman coding assigns shorter bit codes to more frequent symbols and longer codes to less frequent symbols based on a constructed binary tree [S2].
4.  **Finalization:** Output the concatenated bitstream [S1, S2].

**Parameters:**
*   **Arithmetic Coding Implementation:** A standard reference implementation (e.g., Nayuki's reference) is used [S1].
*   **LZ77 Window:** Not specified [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** Arithmetic coding requires high-precision interval arithmetic to avoid underflow/overflow; standard implementations handle this via renormalization [G].
*   **Boundary Artifacts:** While entropy coding itself is lossless, inconsistent outputs between adjacent blocks (if the volume is decomposed into disjoint blocks) can cause rendering artifacts. This is mitigated by a lightweight CNN module applied to MLP outputs, not by the entropy coder itself [S2].

## Operating characteristics
*   **Compression Ratio:** Entropy encoding provides an additional 10% model size reduction on top of previous compression steps [S2].
*   **Complexity:** Arithmetic coding is computationally more intensive than Huffman coding due to floating-point interval updates, but offers better compression for non-power-of-two probability distributions [G]. Huffman coding is faster but suboptimal for probabilities that are not negative powers of two [G].
*   **Performance:** Experiments conducted on an Nvidia RTX 4090 with CUDA 11.8 showed effective integration with the prediction pipeline [S1].
*   **Strengths:** Lossless; adapts to symbol frequency; handles arbitrary probability distributions (arithmetic) or simple frequency tables (Huffman).
*   **Limitations:** Arithmetic coding is slower; Huffman coding requires transmitting the codebook or having a static one.

## Background
*   **Arithmetic Coding:** Used in SPC-NeRF for encoding feature grid syntax elements (coarse/fine residuals, reference indexes) [S1]. The implementation referenced is from Nayuki [S1].
*   **Huffman Coding:** Used in ECNR for final compression of the model file [S2].
*   **LZ77:** Used for minor syntax elements in SPC-NeRF [S1].
