# Entropy-Based Compression Estimation

Also called: Information Entropy Estimation, HLoC Entropy Estimation

## Overview
Entropy-Based Compression Estimation calculates the theoretical lower bound of the compressed size of a token sequence by computing its Shannon entropy. It solves the problem of predicting storage requirements for arithmetic coding without performing the actual encoding, allowing for rapid evaluation of coding efficiency. It differs from [Level-Wise Context Model](12628-entropy-coding-implementation.md#level-wise-context-model) by providing a global statistical estimate rather than a local, causal probability prediction for individual tokens.

## How it works
**Inputs:** A sequence of tokens $T$ (e.g., from a Hashed Linear Octree Code, HLoC) and the total number of tokens $N$.
**Outputs:** An estimated byte count $B_{est}$.

**Data Structures:**
- Frequency Map $F$: A dictionary or array mapping each unique token value $t$ to its occurrence count $f_t$.

**Steps:**
1. **Count Frequencies:** Iterate through the token sequence $T$ to populate $F$. For each token $t \in T$, increment $f_t$.
2. **Calculate Probabilities:** For each unique token $t$, calculate its probability $p_t$:
   $$ p_t = \frac{f_t}{N} $$
   [G] Handle the case where $N=0$ by returning 0 bytes.
3. **Calculate Entropy:** Compute the information entropy $H$ in bits:
   $$ H = - \sum_{t \in \text{unique}(T)} p_t \log_2(p_t) $$
   [G] If $p_t = 0$, the term $p_t \log_2(p_t)$ is defined as 0.
4. **Estimate Bits:** Multiply the entropy by the total number of tokens to get the total bit count:
   $$ B_{bits} = H \times N $$
5. **Estimate Bytes:** Convert bits to bytes, rounding up to the nearest integer:
   $$ B_{est} = \lceil \frac{B_{bits}}{8} \rceil $$

**Parameters:**
- None. The method relies entirely on the input token distribution.

**Edge Cases:**
- **Uniform Distribution:** If all tokens are equally likely, $H$ approaches $\log_2(|\Sigma|)$, where $|\Sigma|$ is the alphabet size. This yields the highest entropy and largest estimated size.
- **Degenerate Input:** If the sequence contains only one unique token, $H=0$, resulting in an estimated size of 0 bytes (theoretical limit; practical arithmetic coding requires overhead).
- **Precision:** Floating-point precision in logarithm calculations should be sufficient to avoid significant error in $H$ for large $N$.

## Subtopics

### Level-Wise Context Model
A variant that estimates bit consumption by establishing contextual dependencies among feature vectors $\theta_i$ across different resolution levels. It predicts probability $p_i$ more accurately by using previously decoded features. It is chosen when spatial coherence across levels can be exploited to reduce entropy. It differs from the global entropy estimate by being causal (coarse-to-fine) and adaptive. [S2]

## Operating characteristics
- **Time Complexity:** $O(N)$ to count frequencies and compute entropy, where $N$ is the number of tokens.
- **Memory Complexity:** $O(|\Sigma|)$ to store the frequency map, where $|\Sigma|$ is the size of the token alphabet.
- **Strengths:** Fast, non-invasive estimation; provides a theoretical lower bound for compression.
- **Limitations:** Ignores arithmetic coding overhead (header, end-of-stream markers); assumes ideal arithmetic coding efficiency; does not account for context model storage costs.
- **When to use:** Rapid prototyping, comparing different tokenization schemes (e.g., 11-token vs 9-token alphabets), or estimating baseline compression ratios.
- **When not to use:** When exact byte counts including headers are required, or when context models significantly alter the probability distribution beyond the global histogram.

## Background
The method is based on Shannon's source coding theorem, which states that the entropy $H$ is the lower bound on the average number of bits per symbol required for lossless compression. It is applied in volume rendering compression, specifically in evaluating the efficiency of token sequences generated by methods like HLoC [S1]. The Level-Wise Context Model variant was introduced to improve compression in Instant-NGP-based NeRFs by leveraging spatial dependencies [S2].
