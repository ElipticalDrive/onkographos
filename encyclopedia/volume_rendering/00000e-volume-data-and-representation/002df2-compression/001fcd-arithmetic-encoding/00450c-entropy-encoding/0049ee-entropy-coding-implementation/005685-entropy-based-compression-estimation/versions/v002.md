# Entropy-Based Compression Estimation


## Overview
Entropy-Based Compression Estimation calculates the information entropy $H$ of tokens from a Hashed Linear Octree Code (HLoC) based on their frequencies, then multiplies $H$ by the number of tokens and divides by 8, rounding up, to estimate the byte count [S1]. It provides a global statistical estimate of compression size, differing from [Level-Wise Context Model](12628-entropy-coding-implementation.md#level-wise-context-model) which predicts local, causal probabilities for individual tokens [S2].

## How it works
**Inputs:** A sequence of tokens $T$ (e.g., from an HLoC) and the total number of tokens $N$ [S1].
**Outputs:** An estimated byte count $B_{est}$ [S1].

**Data Structures:**
- Frequency Map $F$: A dictionary or array mapping each unique token value $t$ to its occurrence count $f_t$ [G].

**Steps:**
1. **Count Frequencies:** Iterate through $T$ to populate $F$. For each token $t \in T$, increment $f_t$ [G].
2. **Calculate Probabilities:** For each unique token $t$, calculate $p_t = f_t / N$ [G]. Handle $N=0$ by returning 0 [G].
3. **Calculate Entropy:** Compute $H = - \sum_{t \in \text{unique}(T)} p_t \log_2(p_t)$ in bits [G]. Define $0 \log_2 0 = 0$ [G].
4. **Estimate Bytes:** Compute $B_{est} = \lceil (H \times N) / 8 \rceil$ [S1].

**Pseudocode:**
```python
import math

def estimate_bytes(tokens, N):
    F = {}
    for t in tokens:
        F[t] = F.get(t, 0) + 1
    H = 0.0
    for f_t in F.values():
        p_t = f_t / N
        if p_t > 0:
            H -= p_t * math.log2(p_t)
    return math.ceil((H * N) / 8)
```

**Parameters:**
- None. The method relies entirely on the input token distribution [G].

**Edge Cases:**
- **Uniform Distribution:** If all tokens are equally likely, $H$ approaches $\log_2(|\Sigma|)$, where $|\Sigma|$ is the alphabet size, yielding the highest entropy and largest estimated size [G].
- **Degenerate Input:** If the sequence contains only one unique token, $H=0$, resulting in an estimated size of 0 bytes (theoretical limit; practical arithmetic coding requires overhead) [G].
- **Precision:** Floating-point precision in logarithm calculations should be sufficient to avoid significant error in $H$ for large $N$ [G].

## Subtopics

### Level-Wise Context Model
A variant that estimates bit consumption by establishing contextual dependencies among feature vectors $\theta_i$ across different resolution levels to predict probability $p_i$ more accurately [S2]. It decodes features in a coarse-to-fine manner (shallow to deep levels) [S2]. For a vertex $n_i$ at level $l$, it gathers context from interpolated features at the corresponding location from the previous $L_c$ levels [S2]. This context information is concatenated with the occurrence frequency $f_G$ of the current level and fed into a context model to estimate $p_i$ [S2]. If the number of previous layers is less than $L_c$, all available previous layers are used ($L_c = l - 1$) [S2]. For level $l=1$, only $f_G$ is used to estimate bit consumption [S2]. If all associated vertices are invalid, the corresponding $\theta_i$ is discarded to save storage [S2]. The preset constant $L_c$ controls the number of previous levels used for context, with a typical value of 3 [S2]. It is chosen when spatial coherence across levels can be exploited to reduce entropy [S2].

## Operating characteristics
- **Time Complexity:** $O(N)$ to count frequencies and compute entropy, where $N$ is the number of tokens [G].
- **Memory Complexity:** $O(|\Sigma|)$ to store the frequency map, where $|\Sigma|$ is the size of the token alphabet [G].
- **Strengths:** Fast, non-invasive estimation; provides a theoretical lower bound for compression [G].
- **Limitations:** Ignores arithmetic coding overhead (header, end-of-stream markers); assumes ideal arithmetic coding efficiency; does not account for context model storage costs [G].
- **When to use:** Rapid prototyping, comparing different tokenization schemes (e.g., 11-token vs 9-token alphabets), or estimating baseline compression ratios [S1].
- **When not to use:** When exact byte counts including headers are required, or when context models significantly alter the probability distribution beyond the global histogram [G].

## Background
The method is applied in volume rendering compression to evaluate the efficiency of token sequences generated by methods like HLoC [S1]. The Level-Wise Context Model variant was introduced to improve compression in Instant-NGP-based NeRFs by leveraging spatial dependencies [S2].
