# Arithmetic Encoding

Also called: Arithmetic Coding

## Overview
Arithmetic encoding is a lossless entropy coding technique that maps a sequence of input symbols to a single fractional number within the interval $[0, 1)$ [G]. It solves the inefficiency of fixed-length or symbol-by-symbol variable-length codes by encoding the entire message as one number, achieving a bit rate approaching the Shannon entropy limit [G]. In volume rendering, it is used to compress anchor attributes and other metadata in neural representations by encoding them into a binary bitstream based on probabilities estimated by a context model [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A sequence of symbols $S = s_1, s_2, \dots, s_N$ drawn from an alphabet $\Sigma$, and a probability model $P(s_i | \text{context})$ for each symbol.
- Output: A binary bitstream representing the final sub-interval.

**Data Structures:**
- `current_interval`: A pair of floating-point numbers $[L, H)$ representing the current range, initialized to $[0.0, 1.0)$ [G].
- `output_buffer`: A list of bits to be flushed.
- `pending_zeros`: An integer counter for deferred zero bits [G].

**Steps:**
1. **Initialization**: Set $L = 0.0$, $H = 1.0$, `pending_zeros` = 0 [G].
2. **Encoding Loop**: For each symbol $s_i$ in the input sequence:
   a. Determine the cumulative probability range $[p_{low}, p_{high})$ based on the current context model.
   b. Calculate the interval width: $W = H - L$.
   c. Update the interval:
      $$L_{new} = L + W \times p_{low}$$
      $$H_{new} = L + W \times p_{high}$$
   d. Set $L = L_{new}$, $H = H_{new}$.
   e. **Renormalization**: While the interval is entirely within $[0, 0.5)$ or $[0.5, 1.0)$:
      - If $H \le 0.5$: Output bit `0`. Update $L = 2L$, $H = 2H$. Increment `pending_zeros` by 1.
      - If $L \ge 0.5$: Output bit `1`. Update $L = 2(L - 0.5)$, $H = 2(H - 0.5)$. Increment `pending_zeros` by 1.
3. **Finalization**: After processing all symbols, output the shortest binary fraction that uniquely identifies the final interval $[L, H)$, followed by a bit opposite to the last output bit to disambiguate [G]. Flush any remaining `pending_zeros` by outputting the opposite bit and then zeros [G].

**Pseudocode:**
```python
def encode_arithmetic(symbols, context_model):
    L = 0.0
    H = 1.0
    pending_zeros = 0
    output_bits = []
    
    for s in symbols:
        p_low, p_high = context_model.cumulative_range(s)
        W = H - L
        H = L + W * p_high
        L = L + W * p_low
        
        while H <= 0.5:
            output_bits.append(0)
            L *= 2
            H *= 2
            pending_zeros += 1
        while L >= 0.5:
            output_bits.append(1)
            L = 2 * (L - 0.5)
            H = 2 * (H - 0.5)
            pending_zeros += 1
            
    # Finalization: output the shortest binary fraction in [L, H)
    val = L
    while True:
        bit = int(val * 2)
        output_bits.append(bit)
        val = 2 * val - bit
        if L <= val < H:
            break
    return output_bits
```

**Parameters:**
- Precision: Typically 32-bit or 64-bit floating point for interval calculations [G].
- Context Model: Probabilities are estimated dynamically based on previous symbols [S1, unofficial].

**Edge Cases:**
- **Precision Loss**: If the interval becomes too small relative to floating-point precision, renormalization must occur frequently. If precision is insufficient, the decoder may fail to distinguish the final interval [G].
- **Boundary Conditions**: The interval is half-open $[L, H)$. Care must be taken when $H$ approaches 1.0 [G].

### [MLZC 3-D Encoding/2-D Decoding](2501-mlzc-3-d-encoding-2-d-decoding.md)

### [Entropy Encoding](5360-entropy-encoding.md)
General category of which arithmetic encoding is a specific, optimal instance. Chosen as the foundational layer for variable-length compression schemes.

## Operating characteristics
- **Time Complexity**: Encoding and decoding are linear in the number of symbols $O(N)$, but each step involves floating-point multiplication and interval updates, which are more expensive than integer operations [G].
- **Memory Complexity**: Low, requiring only the current interval state and probability tables [G].
- **Performance**: Achieves near-optimal compression ratios, often outperforming Huffman coding [G]. It is sensitive to probability model accuracy; poor models lead to significant compression loss [G].
- **Strengths**: Optimal compression for known distributions; handles arbitrary alphabets.
- **Limitations**: Sequential dependency prevents parallel encoding/decoding of large blocks; floating-point precision issues can cause decoding errors if not handled carefully [G].

## Background
Arithmetic coding was originally developed by Shannon, Fano, and Elias in the 1940s and 1950s but became practical with the work of Rissanen in the 1970s [G]. It is widely used in modern standards such as JPEG 2000, H.264/AVC, and HEVC [G]. In volume rendering, it is used to compress anchor attributes and other metadata in neural representations [S1, unofficial].
