# Volume Data Loading (PNG Slices)

Also called: PNG Slice Loading

## Overview
This method loads a single PNG image containing stacked 2D volume slices, parses its dimensions to reconstruct the 3D volume, converts pixel data to floating-point scalars, applies optional filtering, and optionally saves the result as a binary volume file. It differs from [DICOM Slice Processing](6713-dicom-slice-processing.md) by handling raw raster images rather than medical metadata, and from [Slice to Binary Volume Conversion](6714-slice-to-binary-volume-conversion.md) by accepting a single multi-slice image file rather than a directory of individual slice files.

## How it works
**Inputs:**
- Path to a PNG image file.
- `slices`: Integer specifying the number of Z-slices (ZDIM). Default value is 176 [S1, unofficial].
- `S_FILTER`: A filter identifier or function to apply to the scalar data [S1, unofficial].

**Outputs:**
- `scalars`: A vector of floating-point values representing the volume data.
- Optional: A binary volume file named `file_S_FILTER.vol` if it does not already exist [S1, unofficial].

**Data Structures:**
- `scalars`: A 1D vector of floats. The size is $X_{DIM} \times Y_{DIM} \times Z_{DIM}$.
- Image dimensions:
  - $X_{DIM}$: Width of the image in pixels.
  - $Y_{DIM}$: Total height of the image in pixels.
  - $Z_{DIM}$: Number of slices (input parameter).
  - Effective slice height: $H_{slice} = Y_{DIM} / Z_{DIM}$.

**Steps:**
1. Load the PNG image using `stbi_load` with the `STBI_grey` format to retrieve raw pixel data, $X_{DIM}$, $Y_{DIM}$, and component count [S1, unofficial].
2. Calculate the effective slice height: $H_{slice} = Y_{DIM} / Z_{DIM}$ [S1, unofficial].
3. Convert the loaded image data into a vector of floats named `scalars` [S1, unofficial].
4. Apply the filter specified by `S_FILTER` to the `scalars` vector [S1, unofficial].
5. Check if a pre-filtered binary file named `file_S_FILTER.vol` exists:
   - If it does not exist, save the filtered `scalars` data to this file [S1, unofficial].
   - If it exists, load the data from this file directly into `scalars` [S1, unofficial].

**Pseudocode:**
```python
import stbi
import os
import struct

def load_png_slices(image_path: str, slices: int = 176, S_FILTER=None) -> list[float]:
    """
    Load PNG slices, filter, and return float scalars.
    """
    # Step 1: Load PNG
    # stbi_load returns raw bytes, width, height, channels
    # STBI_grey ensures 1 channel output
    data, x_dim, y_dim, channels = stbi.load(image_path, channels=1)
    
    if data is None:
        raise ValueError(f"Failed to load image {image_path}")
    
    # Step 2: Calculate slice height
    # Note: Sources assume Y_DIM is divisible by Z_DIM
    if y_dim % slices != 0:
        raise ValueError(f"Image height {y_dim} is not divisible by slice count {slices}")
    
    slice_height = y_dim // slices
    
    # Step 3: Convert to floats
    # Assuming 8-bit grayscale input
    scalars = [byte / 255.0 for byte in data]
    
    # Step 4: Filter scalars
    if S_FILTER is not None:
        scalars = apply_filter(scalars, S_FILTER)
    
    # Step 5: Handle binary file persistence
    binary_filename = f"file_{S_FILTER}.vol" if S_FILTER else "filtered.vol"
    
    if not os.path.exists(binary_filename):
        save_binary_volume(binary_filename, scalars)
    else:
        scalars = load_binary_volume(binary_filename)
        
    return scalars

    return scalars

def save_binary_volume(filename: str, data: list[float]):
    with open(filename, 'wb') as f:
        f.write(struct.pack(f'{len(data)}f', *data))

def load_binary_volume(filename: str) -> list[float]:
    with open(filename, 'rb') as f:
        data = f.read()
        count = len(data) // 4
        return list(struct.unpack(f'{count}f', data))
```

**Edge Cases and Pitfalls:**
- Precision: The source uses `stbi_load` with `STBI_grey`, implying 8-bit input converted to float. Loss of precision occurs during this conversion if the original data was higher bit-depth [S1, unofficial].
- Boundaries: The method assumes $Y_{DIM}$ is perfectly divisible by $Z_{DIM}$. Non-divisible dimensions will cause errors or incorrect slicing [S1, unofficial].
- Degenerate Input: Empty or corrupted PNG files will fail at the load step [S1, unofficial].

## Subtopics

### Image Import and Slicing
This variant handles more complex layouts including RGBA images, multi-frame sources, and grid-based slice arrangements. It determines slice origins based on layout (vertical strip, horizontal strip, or grid), extracts individual slices from the image, and supports multi-file imports where each file is a separate frame. It raises a `ValueError` if no valid origins are found for the given layout [S2, unofficial].

## Operating characteristics
- Time Complexity: Linear with respect to the number of pixels in the input image for loading and conversion. Filtering adds additional linear time.
- Memory Complexity: Proportional to the volume size ($X \times Y \times Z$) for storing the `scalars` vector.
- Strengths: Simple to implement using standard image libraries; supports caching via binary file persistence.
- Limitations: Assumes a specific stacking order (top-to-bottom for Y-dimension); limited to grayscale or single-channel interpretation unless extended [S1, unofficial]. Not suitable for multi-frame or grid layouts without significant modification [S2, unofficial].

## Background
This method originates from a computer graphics course project (CSE-333) involving volume ray casting, using the `stb_image` library for loading [S1, unofficial]. It is designed for basic volume visualization where data is pre-packaged into a single image file for ease of distribution.
