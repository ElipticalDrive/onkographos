# Slice to Binary Volume Conversion

Also called: Volume Data Loading from Slices

## Overview
Converts a directory of 2D image slices into a binary volume file (`.bin`) by assuming slices are ordered and calculating bounding box dimensions based on a fixed X width [S1, unofficial]. It differs from PNG-based loading by relying on explicit directory structure and fixed world-space constraints rather than parsing a single multi-slice image file [S1, unofficial][S2, unofficial].

## How it works
**Inputs:** Directory of 2D image slices and a fixed bounding box width parameter [S1, unofficial].
**Outputs:** Binary volume file (`.bin`) containing float data [S1, unofficial].

**Data Structures:**
- `grid_dim`: Tuple `(w, h, z)` representing voxel grid dimensions [S1, unofficial].
- `bbox_size`: Tuple `(x, y, z)` representing world-space bounding box dimensions [S1, unofficial].

**Steps:**
1. Read the first slice image to determine width ($w$) and height ($h$) [S1, unofficial].
2. Calculate grid dimensions: $grid\_dim = (w, h, N)$, where $N$ is the number of slices [S1, unofficial].
3. Calculate bounding box size: $bbox\_size[0] = BBOX\_SIZE\_X$ and $bbox\_size[1] = \left(\frac{BBOX\_SIZE\_X}{grid\_dim[0]}\right) \times \left(\frac{vol\_size[1]}{vol\_size[0]}\right) \times grid\_dim[1]$ [S1, unofficial].
4. Load the ordered slices, convert pixel values to floats, and write the data to the binary volume file [S1, unofficial].

**Parameters:**
- `BBOX_SIZE_X`: Fixed width of the bounding box in world units. Default: 5.0 [S1, unofficial].
- `vol_size`: Tuple providing the original volume dimensions for aspect ratio scaling. Not given in the sources.

**Edge Cases:**
- The method assumes slices are strictly ordered in the directory, and incorrect ordering will produce an invalid volume layout [S1, unofficial].

```python
def convert_slices_to_binary(slice_directory, bbox_size_x=5.0, vol_size=(1.0, 1.0)):
    # 1. Read first slice image to determine width (w) and height (h)
    first_slice_path = os.path.join(slice_directory, os.listdir(slice_directory)[0])
    w, h = read_image_dimensions(first_slice_path) # [G] Standard image dimension retrieval

    # 2. Calculate grid dimensions
    num_slices = len(os.listdir(slice_directory))
    grid_dim = (w, h, num_slices)

    # 3. Calculate bounding box size
    bbox_size = [0.0, 0.0, 0.0]
    bbox_size[0] = bbox_size_x
    bbox_size[1] = (bbox_size_x / grid_dim[0]) * (vol_size[1] / vol_size[0]) * grid_dim[1]

    # 4. Load ordered slices, convert to float, and write to binary file
    # [S1, unofficial] Assumes slices are strictly ordered
    float_data = []
    for slice_path in sorted(os.listdir(slice_directory)):
        img_pixels = read_image_pixels(os.path.join(slice_directory, slice_path)) # [G] Standard pixel extraction
        float_data.extend(pixel_to_float(img_pixels))

    write_binary_volume("volume.bin", float_data, grid_dim, bbox_size)
```

## Subtopics

### Volume Data Loading (PNG Slices)
Loads a single PNG image representing multiple volume slices, parses dimensions, converts to float, filters, and optionally saves as a binary volume file [S2, unofficial]. It differs from the standard slice conversion by treating a single file as a multi-slice container and using a default slice count [S2, unofficial].
- **Definition:** Loads PNG, parses XDIM, YDIM, and components; sets ZDIM to `slices`; adjusts YDIM [S2, unofficial].
- **Steps:** Load PNG with `stbi_load` using `STBI_grey` format; set `ZDIM = slices`; adjust `YDIM = YDIM / ZDIM`; convert to floats; filter using `S_FILTER`; save to `file_S_FILTER.vol` if not pre-filtered [S2, unofficial].
- **Parameters:** `slices` is an integer specifying the number of Z-slices, with a default value of 176 [S2, unofficial].
