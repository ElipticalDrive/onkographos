# Volume Loading and Preprocessing

Also called: CT Volume Loading

## Overview
This method handles the ingestion, coordinate alignment, and intensity normalization of volumetric data, specifically targeting medical imaging formats like CT scans. It solves the problem of converting raw, device-specific metadata (such as IJK-to-RAS affine transforms) into a standardized, GPU-ready tensor format. It differs from [Raw Volume Data Reader](2259-raw-volume-data-reader.md) by handling structured medical metadata and from [DICOM Volume Loading and Coordinate Reconstruction](2574-dicom-volume-loading-and-coordinate-reconstruction.md) by focusing on the post-loading transform application and intensity scaling rather than the initial file parsing and geometry extraction.

## How it works
**Inputs:** Raw volumetric data (e.g., DICOM series or NIfTI), metadata containing affine transformation matrices, and configuration parameters for spacing and intensity scaling.
**Outputs:** A normalized, channel-first tensor on the target device (e.g., CUDA), aligned to a standard coordinate system (e.g., RAS).

**Data Structures:**
*   **Affine Matrix:** A $4 \times 4$ matrix representing the linear transformation between coordinate spaces (e.g., IJK to RAS).
*   **Tensor:** A multi-dimensional array (typically $C \times D \times H \times W$ or $C \times Z \times Y \times X$) with floating-point values.

**Steps:**
1.  **Load Image:** Read the raw voxel data and associated metadata using a library such as MONAI's `LoadImage` [S1, unofficial].
2.  **Ensure Channel First:** Reshape the data to ensure the channel dimension is first (e.g., $1 \times D \times H \times W$) using `EnsureChannelFirst` [S1, unofficial].
3.  **Resample (Spacing):** If the source voxel spacing differs from the target spacing, resample the volume. The target spacing is defined by a vector, e.g., $[2.5, 2.5, 3.0]$ mm [S1, unofficial]. This step interpolates values to maintain physical consistency.
4.  **Intensity Scaling:** Apply `ScaleIntensityRange` to map the raw intensity values (e.g., Hounsfield Units) to a normalized range, typically $[0, 1]$. The source range is clipped, e.g., $[-3024, 3024]$, and linearly mapped to $[0, 1]$ [S1, unofficial].
5.  **Extract Affine:** Retrieve the IJK-to-RAS affine matrix from the volume metadata [S1, unofficial].
6.  **Compute Inverse Affine:** Calculate the inverse of the RAS-to-IJK matrix to facilitate coordinate mapping during rendering or further processing [S1, unofficial].
7.  **Batch Dimension:** Add a batch dimension to the tensor using `unsqueeze(0)`, resulting in shape $(1, C, D, H, W)$ [S1, unofficial].
8.  **Device Transfer:** Move the tensor to the target hardware (e.g., CUDA) [S1, unofficial].

**Pseudocode:**
```python
import torch
import monai.transforms as mt

def load_and_preprocess_volume(file_path, target_spacing_mm, intensity_min, intensity_max):
    # 1. Load image and metadata
    loader = mt.LoadImage()
    image, meta = loader(file_path)
    
    # 2. Ensure channel first (e.g., D, H, W -> 1, D, H, W)
    ensure_ch = mt.EnsureChannelFirst()
    image = ensure_ch(image)
    
    # 3. Resample to target spacing
    # Note: MONAI Spacing transform uses affine from metadata to determine physical size
    spacing_transform = mt.Spacing(new_spacing=target_spacing_mm)
    image = spacing_transform(image)
    
    # 4. Scale intensity to [0, 1] with clipping
    # Values < intensity_min become 0, > intensity_max become 1
    scale_transform = mt.ScaleIntensityRange(
        minval=intensity_min,
        maxval=intensity_max,
        out_min=0.0,
        out_max=1.0
    )
    image = scale_transform(image)
    
    # 5. Extract IJK to RAS affine from metadata
    # meta['affine'] is typically a 4x4 numpy array or tensor
    ijk_to_ras_affine = meta['affine']
    
    # 6. Compute RAS to IJK inverse affine
    # Ensure it is a tensor for GPU operations if needed
    ras_to_ijk_affine = torch.inverse(torch.tensor(ijk_to_ras_affine, dtype=torch.float32))
    
    # 7. Add batch dimension
    image = torch.unsqueeze(image, dim=0)
    
    # 8. Move to CUDA
    if torch.cuda.is_available():
        image = image.to('cuda')
        ras_to_ijk_affine = ras_to_ijk_affine.to('cuda')
        
    return image, ras_to_ijk_affine
```

**Parameters:**
*   `target_spacing_mm`: List of floats representing voxel dimensions in millimeters (e.g., `[2.5, 2.5, 3.0]`) [S1, unofficial].
*   `intensity_min`, `intensity_max`: Floats defining the clipping range for intensity scaling (e.g., `-3024`, `3024` for CT) [S1, unofficial].

## Subtopics

### Brick Density Volume Loading
This variant loads volumetric data into a "BrickGrid" structure, supporting both CT and Ocean Data formats. For CT data, it iterates over the Y-axis, loading slices via `loadVolSlice` with configurable intensity thresholds (`iso_min`, `iso_max`) defaulting to `0` and `USHRT_MAX` [S2, unofficial]. For Ocean Data, it parses SciData files, normalizes spatial locations and O2 concentration values to $[0, 1]$ based on min/max bounds, and applies a density multiplier (`m_density_mult`) [S2, unofficial]. A key pitfall is index bounds checking; the `set()` method validates that coordinates $(i, j, k)$ are within `m_brickData` dimensions before assignment [S2, unofficial].

### Brick Loading Pre-processing
This method applies pre-processing in a brick-loading thread to convert high-precision data (e.g., 16-bit) to unsigned 8-bit integers for efficient transfer [S3, unofficial]. It supports three scaling methods: `scale` (division by a user-defined constant), `scaleToMax` (division by the max value of the lowest resolution representation), and `logTransform` (common logarithm) [S3, unofficial]. User-defined thresholds `min` and `max` in $[0, 1]$ are applied; values outside $[min \times 255, max \times 255]$ are set to zero to remove noise [S3, unofficial]. If a brick contains only zeros after processing, a special `EMPTY` value is transmitted instead of the data to optimize bandwidth [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by I/O and resampling interpolation. Intensity scaling is linear $O(N)$ where $N$ is the number of voxels.
*   **Memory Complexity:** Requires holding the full volume in memory during loading and resampling. The output tensor size depends on the target resolution and data type (e.g., float32).
*   **Strengths:** Standardizes heterogeneous medical data formats into a single GPU-ready representation; handles coordinate system mismatches automatically.
*   **Limitations:** Resampling can introduce interpolation artifacts; requires sufficient RAM to hold the uncompressed volume during preprocessing.
*   **When to use:** When the rendering pipeline requires data in a specific physical spacing and intensity range, and the source data contains complex metadata (affines).

## Background
This workflow is commonly associated with deep learning-based volume rendering pipelines, such as those using MONAI for medical image preprocessing [S1, unofficial]. It bridges the gap between raw DICOM/NIfTI files and neural rendering engines that expect normalized, aligned tensors.
