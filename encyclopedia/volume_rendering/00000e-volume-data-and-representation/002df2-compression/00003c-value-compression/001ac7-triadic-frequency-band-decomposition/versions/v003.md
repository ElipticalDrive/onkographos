# Triadic frequency band decomposition

Also called: Hierarchical Data Decomposition, Hierarchical quantization scheme

## Overview
Triadic frequency band decomposition is a volume data compression method that partitions a scalar field into disjoint $4^3$ blocks and decomposes each block into a multiresolution representation of three triadic frequency bands: high-frequency differences, mid-frequency differences, and mean [S1, unofficial]. It solves the problem of efficient storage and rendering of large volumetric datasets by reducing data size through vector quantization of these bands [S1, unofficial]. What sets it apart from its siblings, such as [Wavelet-based Volume Rendering](1052-wavelet-based-volume-rendering.md) or [Laplacian Pyramid](2250-laplacian-pyramid.md), is its specific use of a fixed $4^3$ block size with a two-level hierarchical downsampling (factor of 2) to generate exactly three bands (64, 8, and 1 components), and its reliance on a specific GPU-friendly texture-based decoding architecture using dependent texture fetches [S1, unofficial].

## How it works
### Inputs and Outputs
**Input:** A 3D scalar field $V$ of dimensions $N_x \times N_y \times N_z$ [S1, unofficial].
**Output:** An RGB index texture $I$ of size $(N_x/4) \times (N_y/4) \times (N_z/4)$, and two codebook textures $C_1$ and $C_2$, and an address texture $A$ [S1, unofficial].

### Data Structures
The method relies on four primary data structures stored in GPU textures:

1.  **Index Texture $I$**:
    *   Dimensions: $(N_x/4) \times (N_y/4) \times (N_z/4)$ [S1, unofficial].
    *   Format: RGB 8-bit per channel [S1, unofficial].
    *   Layout:
        *   $R$: 8-bit mean value of the block [S1, unofficial].
        *   $G$: 8-bit index into Codebook $C_1$ (high-frequency band) [S1, unofficial].
        *   $B$: 8-bit index into Codebook $C_2$ (mid-frequency band) [S1, unofficial].

2.  **Codebook $C_1$**:
    *   Dimensions: $256 \times 64$ (2D texture) [S1, unofficial].
    *   Format: Floating-point per component [S1, unofficial].
    *   Layout: Indexed by $s$ (0-255) and $t$ (0-63). The $s$-coordinate comes from the $G$-component of $I$, and the $t$-coordinate comes from the $R$-component of Address Texture $A$ [S1, unofficial]. Stores 64-component codewords representing high-frequency differences [S1, unofficial].

3.  **Codebook $C_2$**:
    *   Dimensions: $256 \times 8$ (2D texture) [S1, unofficial].
    *   Format: Floating-point per component [S1, unofficial].
    *   Layout: Indexed by $s$ (0-255) and $t$ (0-7). The $s$-coordinate comes from the $B$-component of $I$, and the $t$-coordinate comes from the $G$-component of Address Texture $A$ [S1, unofficial]. Stores 8-component codewords representing mid-frequency differences [S1, unofficial].

4.  **Address Texture $A$**:
    *   Dimensions: $4^3 = 64$ texels (mapped as a 2D texture) [S1, unofficial].
    *   Format: RGB [S1, unofficial].
    *   Layout:
        *   $R$: 64 distinct addresses (indices into $C_1$'s $t$-coordinate) [S1, unofficial].
        *   $G$: 8 distinct addresses (indices into $C_2$'s $t$-coordinate) [S1, unofficial].
        *   $B$: Unused or padding.
    *   Interpolation: Nearest-neighbor [S1, unofficial]. Blocks of $2^3$ adjacent texels are assigned the same address for $C_2$ to yield the 8 necessary values [S1, unofficial].

### Algorithm Steps

1.  **Partitioning**: Divide the input volume $V$ into disjoint blocks of size $4^3$ voxels [S1, unofficial].
2.  **First Downsampling (High-Frequency Band)**: Down-sample each $4^3$ block by a factor of 2 by averaging disjoint sets of $2^3$ voxels each to create a coarser $2^3$ representation [S1, unofficial]. Calculate the difference between each of the 64 original data samples and the respective down-sampled value, storing these in a 64-component vector $D_1$ [S1, unofficial].
3.  **Second Downsampling (Mid-Frequency Band)**: Apply the same down-sampling process to the $2^3$ mean values to produce one single value representing the mean of the entire block [S1, unofficial]. Store the $2^3$ difference values (carrying information lost when going from the $2^3$ mean values to the final one) in an 8-component vector $D_2$ [S1, unofficial].
4.  **Mean Storage**: Store the single mean value of the entire block in a 1-component vector [S1, unofficial].
5.  **Thresholding**: Apply thresholding to vectors $D_1$ and $D_2$: if detail coefficients are small or zero (in homogeneous or empty regions), map the vector to the zero vector to maximize codeword usage for significant non-zero vectors and increase quantization performance [S1, unofficial].
6.  **Vector Quantization**: Quantize each frequency band separately using vector quantization, then assemble the original signal from these contributions to enhance fidelity [S1, unofficial]. Quantize $D_1$ using codebook $C_1$ (length 256) and $D_2$ using codebook $C_2$ (length 256), storing the resulting indices as 8-bit values [S1, unofficial]. Quantize the mean directly as an 8-bit value without a codebook lookup [S1, unofficial].
7.  **Packaging**: Store the 8-bit mean in the $R$-component of $I$, the $C_1$ index in the $G$-component, and the $C_2$ index in the $B$-component [S1, unofficial].

### Pseudocode

```python
def triadic_decomposition(volume, codebook_c1, codebook_c2, threshold=0.0):
    """
    Compresses a volume using Triadic Frequency Band Decomposition.
    Args:
        volume: 3D list/array of shape (Nx, Ny, Nz)
        codebook_c1: 2D list/array of shape (256, 64)
        codebook_c2: 2D list/array of shape (256, 8)
        threshold: Minimum absolute value to keep a difference vector non-zero [G]
    Returns:
        index_texture: 3D list/array of shape (Nx/4, Ny/4, Nz/4), dtype uint8, RGB
    """
    Nx, Ny, Nz = len(volume), len(volume[0]), len(volume[0][0])
    assert Nx % 4 == 0 and Ny % 4 == 0 and Nz % 4 == 0

    index_texture = [[[0, 0, 0] for _ in range(Nz // 4)] for _ in range(Ny // 4)]

    for x in range(0, Nx, 4):
        for y in range(0, Ny, 4):
            for z in range(0, Nz, 4):
                # Extract 4x4x4 block
                block = [[[volume[x+dx][y+dy][z+dz] for dz in range(4)] for dy in range(4)] for dx in range(4)]

                # Step 1: High-frequency band (64 components)
                # Downsample by averaging disjoint 2x2x2 sets
                downsampled_2x2x2 = [[[0.0 for _ in range(2)] for _ in range(2)] for _ in range(2)]
                for i in range(2):
                    for j in range(2):
                        for k in range(2):
                            region_sum = 0.0
                            for di in range(2):
                                for dj in range(2):
                                    for dk in range(2):
                                        region_sum += block[2*i+di][2*j+dj][2*k+dk]
                            downsampled_2x2x2[i][j][k] = region_sum / 8.0

                # Calculate differences for the 64 voxels
                d1 = [0.0] * 64
                for dx in range(4):
                    for dy in range(4):
                        for dz in range(4):
                            region_i = dx // 2
                            region_j = dy // 2
                            region_k = dz // 2
                            diff = block[dx][dy][dz] - downsampled_2x2x2[region_i][region_j][region_k]
                            idx = dx * 16 + dy * 4 + dz
                            d1[idx] = diff

                # Step 2: Mid-frequency band (8 components)
                # Downsample 2x2x2 to 1x1x1 (global mean)
                global_mean = 0.0
                for i in range(2):
                    for j in range(2):
                        for k in range(2):
                            global_mean += downsampled_2x2x2[i][j][k]
                global_mean /= 8.0

                # Calculate differences for the 8 downsampled values
                d2 = [0.0] * 8
                for i in range(2):
                    for j in range(2):
                        for k in range(2):
                            idx = i * 4 + j * 2 + k
                            d2[idx] = downsampled_2x2x2[i][j][k] - global_mean

                # Step 3: Mean
                mean_val = global_mean

                # Step 4: Thresholding
                if max(abs(v) for v in d1) < threshold:
                    d1 = [0.0] * 64
                if max(abs(v) for v in d2) < threshold:
                    d2 = [0.0] * 8

                # Step 5: Vector Quantization
                idx1 = find_best_codebook_entry(d1, codebook_c1)
                idx2 = find_best_codebook_entry(d2, codebook_c2)

                # Step 6: Quantize mean to 8-bit [S1, unofficial]
                # Assuming input volume is normalized to [0, 255] range for 8-bit storage [G]
                mean_8bit = int(round(mean_val))
                mean_8bit = max(0, min(255, mean_8bit))

                # Step 7: Store in Index Texture
                index_texture[x//4][y//4][z//4] = [mean_8bit, idx1, idx2]

    return index_texture

def find_best_codebook_entry(vector, codebook):
    """Finds the index of the codeword minimizing Euclidean distance."""
    best_idx = 0
    min_dist = float('inf')
    for i in range(len(codebook)):
        dist = sum((vector[k] - codebook[i][k])**2 for k in range(len(vector)))
        if dist < min_dist:
            min_dist = dist
            best_idx = i
    return best_idx
```

### Parameters
*   **Block Size**: $4^3$ voxels [S1, unofficial].
*   **Down-sampling Factor**: 2 [S1, unofficial].
*   **Codebook Length**: 256 entries for both $C_1$ and $C_2$ [S1, unofficial].
*   **Index Size**: 8-bit per index [S1, unofficial].
*   **Mean Size**: 8-bit [S1, unofficial].
*   **Threshold**: Not given in the sources. [G] A small epsilon or a fraction of the data range is typically used.

### Edge Cases and Pitfalls
*   **Homogeneous Regions**: Thresholding maps these to zero vectors [S1, unofficial]. This maximizes the usage of codewords for significant non-zero vectors and increases quantization performance [S1, unofficial].
*   **Boundary Conditions**: The source assumes volume dimensions are divisible by 4 for uniform block partitioning [S1, unofficial]. Handling non-divisible dimensions is not specified in the sources [G]. Standard practice is to pad the volume to the nearest multiple of 4.
*   **Precision**: The mean is stored as an 8-bit value, which may introduce quantization error for the DC component. The AC components are reconstructed from codebooks, which also have quantization error. [G]

## Subtopics

### Compression Domain Rendering
This method is designed to be rendered directly from the compressed domain using GPU fragment shaders, avoiding full decompression [S1, unofficial]. It builds on [Value compression](6-value-compression.md) [G].

### Vector Quantization
The core quantization technique used for the difference bands. See [Vector Quantization](907-vector-quantization.md).

## Operating characteristics
*   **Time Complexity**: Encoding processes each voxel once in block-wise fashion [S1, unofficial], yielding $O(N)$ time complexity [G]. Decoding performs $O(1)$ texture lookups and additions per voxel during rendering [S1, unofficial].
*   **Memory Complexity**: The index texture occupies $3 \times (N_x/4)(N_y/4)(N_z/4)$ bytes [S1, unofficial]. Codebooks $C_1$ and $C_2$ occupy $256 \times 64$ and $256 \times 8$ elements respectively [S1, unofficial]. This yields a compressed size significantly smaller than the original $N_x N_y N_z$ voxels [G].
*   **Measured Performance**: The method was tested on an ATI 9700 GPU [S1, unofficial]. The use of dependent texture fetches allows for efficient on-chip decoding [S1, unofficial].
*   **Strengths**: High compression ratio, efficient GPU rendering, enhanced fidelity through separate quantization of bands [S1, unofficial].
*   **Limitations**: Fixed block size, requires specific GPU features (dependent texture fetches), codebook training is required [S1, unofficial].

## Background
The method was introduced in the paper "Compression Domain Volume Rendering" [S1, unofficial]. It was developed to enable real-time volume rendering of large datasets by compressing the data in a way that is compatible with GPU hardware, specifically leveraging the ATI 9700's capabilities for per-fragment arithmetic and dependent texture fetches [S1, unofficial].
