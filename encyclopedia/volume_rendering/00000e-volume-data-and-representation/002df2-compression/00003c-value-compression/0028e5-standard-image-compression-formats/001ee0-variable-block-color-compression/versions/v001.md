# Variable-Block Color Compression


## Overview
Variable-Block Color Compression is a lossy compression method for sparse 3D color data that groups voxels into variable-length blocks to optimize the compression ratio. It sets itself apart from fixed-size block methods by allowing block boundaries to adapt to local color similarity, thereby reducing the number of headers required for large homogeneous regions while maintaining a strict error threshold [S1, unofficial].

## How it works
**Inputs:** A sequence of voxel colors; an error threshold $\epsilon$ (Mean Square Error).
**Outputs:** A block header array and a weight array.

**Data Structures:**
1.  **Block Header Array:** A 32-bit integer array. Each header is 64 bits total, stored as two 32-bit words.
    *   Word 0: Base Color $B_1$ (16 bits).
    *   Word 1: Base Color $B_2$ (16 bits).
    *   Word 2: Start Voxel Index (32 bits).
    *   Word 3: Reserved/Unused or part of the 32-bit packing constraint (Note: Source specifies "2x16 + 32 bits" stored in a 32-bit array, implying the header size is 64 bits or 2 words, but the text says "stored in a 32-bit array" which likely refers to the word-width of the storage unit, not the total size. The text explicitly states "Total size: 2x16 + 32 bits" = 64 bits. We assume 2 words per header).
2.  **Weight Array:** An array of weights, each stored with a fixed bit width (e.g., 3 bits).

**Parameters:**
*   $B_1, B_2$: Base colors, 16 bits each.
*   $w$: Weight, 3 bits.
*   $\epsilon$: Error threshold (MSE).

**Algorithm:**

**Encoding:**
1.  Initialize each voxel color as a separate block.
2.  Iterate through the blocks. For each block, attempt to merge it with its left neighbor or right neighbor.
3.  Calculate the Mean Square Error (MSE) for both potential merges.
4.  Select the merge with the lowest MSE.
5.  If the lowest MSE is greater than $\epsilon$, the block is considered "done" and is not merged further in this pass.
6.  If a merge is performed, update the base colors and weights for the new union block.
7.  Repeat steps 2-6 until no more merges can be performed within the error threshold.
8.  Store the resulting blocks' base colors and start voxel indices in the Header Array.
9.  Store the corresponding weights in the Weight Array.

**Decoding:**
1.  Given a voxel index $i$, find the block containing it.
2.  Perform a binary search on the Start Voxel Index field in the Block Header Array to find the header $H_k$ such that $H_k.\text{StartVoxel} \le i < H_{k+1}.\text{StartVoxel}$.
3.  Retrieve the weight $w$ from the Weight Array at index $i$.
4.  Retrieve base colors $B_1$ and $B_2$ from header $H_k$.
5.  Reconstruct the color $C$ using the formula:
    $$ C = wB_1 + (1 - w)B_2 $$

                current_block['colors'] = merged_colors
                current_block['base_colors'] = merged_base

                blocks.pop(i+1)

                # Merge failed, move to next block
                i += 1

            weights.append(block['weights'][j - block['start']])

def decode_color(header, weight, voxel_index_in_block):

    Reconstructs a color from a header and a weight.

    B1 = header['B1']
    B2 = header['B2']
    w = weight
    
    # Formula: C = w*B1 + (1-w)*B2
    C = w * B1 + (1 - w) * B2

## Operating characteristics
*   **Time Complexity:** Encoding is iterative and depends on the number of merges. Each pass processes all blocks. Decoding requires a binary search on headers ($O(\log N)$) and a direct lookup in weights ($O(1)$).
*   **Memory Complexity:** Storage consists of fixed-size headers (64 bits per block) and a weight array (3 bits per voxel). The number of blocks is variable, depending on the error threshold.
*   **Strengths:** Outperforms previous attempts in compression/quality for sparse 3D data. Memory overhead is negligible compared to previous methods that doubled DAG size.
*   **Limitations:** Lookup times are more expensive than fixed-block methods due to the binary search.
*   **When to use:** When sparse 3D color data requires high compression ratios with controlled error, and memory overhead must be minimized.

## Background
Originated in the context of sparse voxel DAGs and memory efficient compression of surface representations. The method was introduced as an alternative to mapping attributes to a DAG, aiming to reduce memory overhead while maintaining compression quality [S1, unofficial].
