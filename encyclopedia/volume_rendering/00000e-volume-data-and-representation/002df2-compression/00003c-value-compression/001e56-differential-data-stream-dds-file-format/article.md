# Differential Data Stream (DDS) File Format

Also called: Differential Data Stream, Differential Data Stream (DDS) Compression

## Overview
The Differential Data Stream (DDS) format is a lossless compression method for volume data that encodes differential values using run-length encoding and adaptive bit allocation per run [S1, unofficial]. It is designed to handle multi-channel volume data by interleaving channels and processing them in blocks, selecting between two file versions based on data size [S1, unofficial]. Unlike general-purpose codecs, DDS is specialized for the spatial and channel correlations found in scientific volume data, offering a lightweight alternative to transform-based methods like [Triadic frequency band decomposition](828-triadic-frequency-band-decomposition.md) or [Laplacian Pyramid](2250-laplacian-pyramid.md).

## How it works
**Inputs and Outputs:**
- Input: Raw volume data array `data` of size `bytes` (in bytes), channel count `skip` (1-4), and spatial stride `strip`.
- Output: Compressed byte stream `chunk` of size `size`.

**Data Structures:**
- **Header:**
  - Bytes 0-3: Magic ID (`DDS_ID` for version 1, `DDS_ID2` for version 2).
  - Bytes 4-5: `skip - 1` (2 bits) and `strip - 1` (16 bits). *Note: The source specifies 2 bits for skip and 16 for strip, packed into the header. The exact byte alignment of these fields within the header is not explicitly detailed beyond the bit counts, but they precede the chunk data.* [S1, unofficial].
- **Chunk:** The compressed bitstream generated by the encoder.

**Constants:**
- `DDS_BLOCKSIZE`: Block processing limit (value not given in sources, used in loop condition `while (blkcnt == DDS_BLOCKSIZE)`) [S1, unofficial].
- `DDS_INTERLEAVE`: Threshold for version selection. If `bytes > DDS_INTERLEAVE`, version 2 is used; otherwise version 1 [S1, unofficial].
- `DDS_RL`: Maximum run length encoded in 7 bits (127) [S1, unofficial].

**Algorithm Steps:**

1. **Version Selection:**
   - If `bytes > DDS_INTERLEAVE`, set `version = 2`, else `version = 1`.

2. **Header Writing (Encoding):**
   - Write `DDS_ID` if `version == 1`, else write `DDS_ID2`.
   - Write `skip - 1` (2 bits) and `strip - 1` (16 bits).

3. **Data Preparation (Interleaving):**
   - If `version == 2`, deinterleave the input byte stream based on channel `skip` and block size using `DDS_deinterleave`. This prepares the data for channel-wise processing [S1, unofficial].
   - If `version == 1`, process data in its original interleaved or planar format as implied by the lack of deinterleaving step (the source implies version 1 does not use `DDS_INTERLEAVE` logic in the encode call, passing 0) [S1, unofficial].

4. **Differential Encoding & Bit Allocation:**
   - Initialize a lookup table `lookup` mapping differential values in `[-128, 127]` to required bit counts:
     ```python
     lookup = [0] * 256
     for i in range(-128, 128):
         if i <= 0:
             bits = 0
             while (1 << bits) // 2 < -i:
                 bits += 1
         else:
             bits = 0
             while (1 << bits) // 2 <= i:
                 bits += 1
         lookup[i + 128] = bits
     ```
   - Iterate through the data bytes. For each byte `tmp1` at position `ptr1`, compute the differential value `act1`:
     - If `strip == 1`: `act1 = tmp1 - pre1` (where `pre1` is the previous byte).
     - If `strip > 1`: `act1 = tmp1 - pre1 - *(ptr1 - strip) + *(ptr1 - strip - 1)` [S1, unofficial].
     - Clamp `act1` to `[-128, 127]` to avoid out-of-bounds access [S1, unofficial].
     - Map `act1` to bit count `bits1 = lookup[act1 + 128]`.

5. **Run-Length Encoding of Bit Counts:**
   - Track runs of identical bit counts. Maintain two runs: current `(cnt1, bits1)` and previous `(cnt2, bits2)`.
   - Merge runs if:
     1. `cnt1 + cnt2 < (1 << DDS_RL)` (i.e., `< 128`)
     2. `(cnt1 + cnt2) * max(bits1, bits2) < cnt1 * bits1 + cnt2 * bits2 + DDS_RL + 3` [S1, unofficial].
   - When a run ends (or at the end of data), write the run:
     - `DDS_writebits(cnt2, DDS_RL)` (7 bits for length)
     - `DDS_writebits(DDS_code(bits2), 3)` (3 bits for bit count, encoded via `DDS_code`)
     - For each value in the run, write the differential value: `DDS_writebits(act2 + (1 << bits2) // 2, bits2)` [S1, unofficial].

6. **Bitstream Packing:**
   - Use `DDS_writebits` to pack bits into 32-bit words.
   - Mask input value to `bits`: `value &= (1 << bits) - 1`.
   - If `DDS_bufsize + bits < 32`, pack into current buffer: `DDS_buffer = (DDS_buffer << bits) | value; DDS_bufsize += bits;`
   - Otherwise, flush 32-bit word to cache (swapping bytes if little-endian), then pack remaining bits into new buffer [S1, unofficial].

7. **Finalization:**
   - Flush remaining bits.
   - If `version == 2`, re-interleave the original data (or the processed stream) using `DDS_interleave` [S1, unofficial].
   - Write `chunk` of size `size` to file.

**Decoding:**
1. Read header bytes. Compare against `DDS_ID`. If mismatch, compare against `DDS_ID2` to determine version.
2. Read `skip` and `strip` from header.
3. Read compressed chunk size and data.
4. If `version == 2`, deinterleave the input byte stream using `DDS_deinterleave` [S1, unofficial].
5. Initialize the same lookup table as encoding.
6. Iterate through the bitstream:
   - Read run length `cnt` (7 bits) and bit count `bits` (3 bits, decoded via `DDS_code`).
   - For each value in the run, read `val` (`bits` bits).
   - Recover differential: `act = val - (1 << bits) // 2`.
   - Reconstruct original byte: `tmp1 = pre1 + act` (or using the `strip` formula if `strip > 1`) [S1, unofficial].
   - Update `pre1` and write to output.
7. If `version == 2`, re-interleave the output data [S1, unofficial].

**Parameters:**
- `skip`: Number of channels (1-4). Stored as 2 bits (`skip-1`).
- `strip`: Spatial/temporal stride for differential calculation. Stored as 16 bits (`strip-1`).
- `DDS_BLOCKSIZE`: Cache allocation size (1 MiB) [S1, unofficial].

**Edge Cases and Pitfalls:**
- Differential values must be clamped to `[-128, 127]` before lookup to avoid out-of-bounds access [S1, unofficial].
- Run length is limited to 127 (`DDS_RL`). Longer runs must be split.
- Endianness handling is required when flushing 32-bit words to cache [S1, unofficial].

## Subtopics

### DDS Bitstream Packing/Unpacking
A variable-length bitstream encoder/decoder that packs/unpacks bits into 32-bit words with automatic cache management and endianness handling [S1, unofficial]. It uses a buffer (`DDS_buffer`) and size counter (`DDS_bufsize`) to manage bit alignment. When the buffer is full, it flushes the 32-bit word to the output cache, swapping bytes if the system is little-endian [S1, unofficial]. The cache allocation size is defined by `DDS_BLOCKSIZE` (1 MiB) [S1, unofficial]. This component is essential for the efficient storage of the variable-length bit counts and differential values generated by the main DDS algorithm.

## Operating characteristics
- **Time Complexity:** Not given in the sources. The algorithm involves linear iteration through data with constant-time lookup and bit manipulation.
- **Memory Complexity:** Not given in the sources. Requires a 256-byte lookup table, a 32-bit buffer, and a cache of 1 MiB (`DDS_BLOCKSIZE`) [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Strengths:** Lossless compression tailored for volume data with strong local correlations. Adaptive bit allocation reduces overhead for small differential values.
- **Limitations:** Limited to 8-bit differential precision (`[-128, 127]`). Run-length encoding is limited to 127, which may reduce efficiency for very long constant bit-count sequences.
- **When to use:** Suitable for lossless storage of multi-channel volume data where spatial correlation is high and data size exceeds `DDS_INTERLEAVE` (version 2) or is smaller (version 1).
- **When not to use:** For data with large differential values exceeding 8-bit range, or when lossy compression is acceptable and higher compression ratios are needed from transform methods.

## Background
The Differential Data Stream (DDS) format is described in the context of volume rendering data compression, specifically within the `SRaimondi/VolumeRender` repository [S1, unofficial]. It is presented as a specialized codec for volume data, distinct from general image or video codecs. The format supports two versions to handle different data sizes via the `DDS_INTERLEAVE` parameter [S1, unofficial].
