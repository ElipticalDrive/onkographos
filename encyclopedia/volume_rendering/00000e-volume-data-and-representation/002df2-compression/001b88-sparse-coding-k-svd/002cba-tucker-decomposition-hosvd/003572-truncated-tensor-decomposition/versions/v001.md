# Truncated Tensor Decomposition

Also called: Low-Rank Approximation via Truncation, Rank Truncation, Rank-reduced tensor decomposition

## Overview
Truncated Tensor Decomposition is a rank-reduction technique applied to the Tucker model to achieve data compression by explicitly choosing a multilinear rank $(R_1, R_2, ..., R_N)$ smaller than the initial dimensions $(I_1, I_2, ..., I_N)$ [S1, unofficial]. It solves the problem of storing or transmitting large volume datasets by retaining only the most significant principal components, thereby preserving major data structures while discarding negligible details [S1, unofficial]. Unlike CP decomposition, which cannot be trivially truncated after computation, Tucker decomposition allows for ex post truncation due to the all-orthogonality property of its core tensor [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A full Tucker decomposition of an $N$-dimensional tensor $\mathcal{A}$, consisting of an $N$-dimensional core tensor $\mathcal{B} \in \mathbb{R}^{R_1 \times R_2 \times \cdots \times R_N}$ and $N$ factor matrices $\mathbf{U}^{(n)} \in \mathbb{R}^{I_n \times R_n}$ for $n=1,\dots,N$.
*   **Output:** A rank-reduced approximation $\tilde{\mathcal{A}}$ defined by a lower multilinear rank $(K_1, K_2, \dots, K_N)$ where $K_n < R_n$.

**Data Structures:**
*   **Core Tensor $\mathcal{B}$:** An $N$-dimensional array. In the truncated version, it is a sub-block of size $K_1 \times K_2 \times \cdots \times K_N$.
*   **Factor Matrices $\mathbf{U}^{(n)}$:** 2D matrices where each column represents a basis vector. The truncated matrices $\mathbf{U}_k^{(n)}$ consist of the first $K_n$ columns of the original $\mathbf{U}^{(n)}$.

**Method Steps:**
The truncation process reduces the rank from $(R_1, \dots, R_N)$ to $(K_1, \dots, K_N)$ by selecting the most significant components. This is possible because the Tucker core tensor is all-orthogonal, meaning its diagonal entries (generalized singular values) represent the energy contribution of each component, and off-diagonal entries are zero [S1, unofficial].

1.  **Select Target Ranks:** Determine the desired lower ranks $K_n$ for each mode $n$, such that $1 \le K_n < R_n$.
2.  **Truncate Factor Matrices:** For each mode $n$, extract the first $K_n$ columns from the original factor matrix $\mathbf{U}^{(n)}$ to form the truncated factor matrix $\mathbf{U}_k^{(n)}$:
    $$ \mathbf{U}_k^{(n)} = \mathbf{U}^{(n)}[:, 0:K_n] \in \mathbb{R}^{I_n \times K_n} $$
3.  **Truncate Core Tensor:** Extract the sub-block of the core tensor $\mathcal{B}$ corresponding to the first $K_1$ indices of mode 1, $K_2$ indices of mode 2, ..., and $K_N$ indices of mode $N$. This forms the truncated core tensor $\mathcal{B}_k$:
    $$ \mathcal{B}_k = \mathcal{B}[0:K_1, 0:K_2, \dots, 0:K_N] \in \mathbb{R}^{K_1 \times K_2 \times \cdots \times K_N} $$
4.  **Reconstruct Approximation:** Compute the rank-reduced approximation $\tilde{\mathcal{A}}$ using the multilinear product:
    $$ \tilde{\mathcal{A}} = \mathcal{B}_k \times_1 \mathbf{U}_k^{(1)} \times_2 \mathbf{U}_k^{(2)} \times_3 \cdots \times_N \mathbf{U}_k^{(N)} $$

**Formulas:**
The approximation minimizes the least-squares error between the original tensor $\mathcal{A}$ and the reconstructed tensor $\tilde{\mathcal{A}}$ [S1, unofficial]:
$$ \widetilde{\mathcal{A}} = \arg \min_{\tilde{\mathcal{A}}} \left\| \mathcal{A} - \tilde{\mathcal{A}} \right\|^2 $$
The general Tucker model with reduced ranks is expressed as [S1, unofficial]:
$$ \tilde{\mathcal{A}} \approx \mathcal{B}_k \times_1 \mathbf{U}_k^{(1)} \times_2 \mathbf{U}_k^{(2)} \times_3 \cdots \times_N \mathbf{U}_k^{(N)} $$

**Parameters:**
*   **Target Ranks $(K_1, \dots, K_N)$:** These determine the compression ratio. Typically, the first few principal components define most of the total variability, so $K_n$ is chosen small relative to $R_n$ [S1, unofficial].
*   **Error Threshold:** In adaptive implementations, a PSNR or reconstruction error threshold determines the maximum allowable $K_n$ [S2].

**Edge Cases and Pitfalls:**
*   **CP Decomposition:** CP decomposition produced via Alternating Least Squares (ALS) cannot be truncated in the same manner as Tucker decomposition because it lacks the all-orthogonality property of the core [S1, unofficial].
*   **Precision:** Truncating components with values close to zero is safe as they are negligible [S1, unofficial]. However, removing components with non-negligible diagonal entries in the core tensor will increase reconstruction error significantly.
*   **Ordering:** The columns of $\mathbf{U}^{(n)}$ must be ordered by significance (typically corresponding to decreasing singular values in the core tensor's diagonal) before truncation. If the decomposition is not ordered, truncation may remove important features [S2].

**Pseudocode:**
```python
def truncated_tucker_decomposition(core_tensor, factor_matrices, target_ranks):
    """
    Performs rank truncation on a Tucker decomposition.
    
    Args:
        core_tensor: N-dimensional numpy array of shape (R1, R2, ..., RN).
        factor_matrices: List of N numpy arrays, where factor_matrices[n] has shape (In, Rn).
        target_ranks: List of N integers (K1, K2, ..., KN) where Kn < Rn.
        
    Returns:
        truncated_core: N-dimensional numpy array of shape (K1, K2, ..., KN).
        truncated_factors: List of N numpy arrays, where truncated_factors[n] has shape (In, Kn).
    """
    N = len(target_ranks)
    truncated_factors = []
    slices = []
    
    # Step 1 & 2: Truncate factor matrices
    for n in range(N):
        Kn = target_ranks[n]
        Un = factor_matrices[n]
        # Take the first Kn columns
        Uk_n = Un[:, :Kn]
        truncated_factors.append(Uk_n)
        # Prepare slice for core tensor extraction
        slices.append(slice(0, Kn))
        
    # Step 3: Truncate core tensor
    # Extract the sub-block defined by the first Kn indices for each mode
    truncated_core = core_tensor[tuple(slices)]
    
    return truncated_core, truncated_factors

def reconstruct_approximation(truncated_core, truncated_factors):
    """
    Reconstructs the tensor from the truncated Tucker components.
    
    Args:
        truncated_core: N-dimensional numpy array.
        truncated_factors: List of N numpy arrays.
        
    Returns:
        reconstructed_tensor: N-dimensional numpy array of original shape.
    """
    N = len(truncated_factors)
    # Start with the core tensor
    result = truncated_core
    
    # Apply multilinear product mode by mode
    for n in range(N):
        # Mode-n product: result = result x_n factor_matrix
        # Using einsum for clarity: result[i1, i2, ..., In] = sum_k(result[..., k, ...] * factor[k, i_n])
        # Here, the factor matrix is (In, Kn). The core has dimension Kn at mode n.
        # We contract the n-th mode of the core with the factor matrix.
        result = np.tensordot(result, truncated_factors[n], axes=([n], [1]))
        # Move the new dimension (from the factor matrix's row index) to the correct position
        # The factor matrix shape is (In, Kn). The contraction removes the Kn dimension from result
        # and adds the In dimension.
        # tensordot puts the free indices of the factor matrix (In) at the end.
        # We need to move the In dimension to position n.
        # Let's assume result shape before this step is (..., Kn, ...)
        # After tensordot(result, U, axes=([n], [1])), shape is (..., In, ...)
        # The In dimension is at the end. We need to move it to index n.
        # Number of dimensions in result before this step is N.
        # After contraction, dimensions are still N (one replaced).
        # The new dimension is at the end.
        # Permutation: move last axis to position n.
        axes = list(range(N))
        axes.append(axes.pop(n)) # This logic is tricky with tensordot. 
        # Simpler: use standard mode-n product logic.
        # result = core x1 U1 x2 U2 ...
        # Let's restart the reconstruction loop properly.
        pass

    # Correct reconstruction logic:
    # Start with core.
    # For n=0 to N-1:
    #   result = core x_n U_n
    # But core changes shape? No, the core is fixed. The factors are applied sequentially.
    # Actually, the definition is A = B x1 U1 x2 U2 ...
    # This is equivalent to unfolding B and multiplying by U matrices.
    
    # Let's use a standard iterative approach:
    current_tensor = truncated_core
    for n in range(N):
        # Mode-n product of current_tensor with truncated_factors[n]
        # current_tensor shape: (..., Kn, ...) where Kn is at index n
        # truncated_factors[n] shape: (In, Kn)
        # Result shape: (..., In, ...)
        # We need to permute so In is at index n.
        
        # Using einsum is safer and clearer
        # Indices: i1...iN for tensor, k for core mode n, j for factor row
        # core[i1...kn...iN] * factor[kn, j] -> result[i1...j...iN]
        
        # Construct einsum string
        # Tensor indices: 0, 1, ..., N-1
        # Factor indices: n, 'k' (contracted), 'j' (new)
        # We want output indices: 0, 1, ..., n-1, 'j', n+1, ..., N-1
        
        tensor_indices = ''.join([chr(ord('a') + i) for i in range(N)])
        factor_indices = tensor_indices[n] + 'k' + 'j' # 'k' is contracted, 'j' is new
        output_indices = tensor_indices[:n] + 'j' + tensor_indices[n+1:]
        
        einsum_str = f"{tensor_indices},{factor_indices}->{output_indices}"
        current_tensor = np.einsum(einsum_str, current_tensor, truncated_factors[n])
        
    return current_tensor
```

## Subtopics

### [Adaptive Rank Selection via Binary Search](9822-adaptive-rank-selection-via-binary-search.md)
A method to adaptively determine the optimal Tucker decomposition rank $(R_1, R_2, R_3)$ for each data block in multi-resolution volume rendering. It solves the trade-off between compression ratio and reconstruction error (PSNR) by finding the smallest rank that satisfies a specific error threshold, avoiding the inefficiency of uniform high-rank decomposition or the quality loss of uniform low-rank decomposition.

## Operating characteristics
*   **Time Complexity:** The truncation step itself is $O(\sum I_n K_n + \prod K_n)$, which is significantly faster than recomputing the full decomposition. The dominant cost is the initial Tucker decomposition.
*   **Memory Complexity:** The storage requirement drops from $O(\sum I_n R_n + \prod R_n)$ to $O(\sum I_n K_n + \prod K_n)$. Since $K_n < R_n$, this yields substantial compression, especially for high-dimensional data where $\prod R_n$ is large [S1, unofficial].
*   **Performance:** Reconstruction error decreases as $K_n$ increases. Typically, the first few principal components capture most of the variability, allowing for high compression with minimal quality loss [S1, unofficial].
*   **Strengths:** Allows progressive refinement; can be applied ex post to an existing decomposition; leverages all-orthogonality for optimal low-rank approximation in the least-squares sense [S1, unofficial].
*   **Limitations:** Requires the initial decomposition to be computed first; not applicable to CP decomposition in the same direct manner [S1, unofficial]; requires careful ordering of components to ensure significant features are retained [S2].

## Background
Truncated tensor decomposition is rooted in the theory of multilinear algebra and the Tucker Higher-Order Singular Value Decomposition (HOSVD) [S1, unofficial]. The concept of selecting principal components to reduce dimensionality parallels Principal Component Analysis (PCA) in matrix decomposition [S1, unofficial]. The specific property of all-orthogonality in the Tucker core tensor, which enables this truncation, was formalized by De Lathauwer et al. [S1, unofficial]. In the context of volume rendering, this method is used to compress large volume datasets into multi-resolution structures, allowing for efficient visualization by storing only the essential frequency components [S1, unofficial][S2].
