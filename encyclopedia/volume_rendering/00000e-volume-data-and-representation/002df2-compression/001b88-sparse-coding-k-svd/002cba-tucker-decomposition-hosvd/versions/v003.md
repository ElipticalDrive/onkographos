# Tucker Decomposition (HOSVD)

Also called: Higher-Order SVD, Higher-Order Singular Value Decomposition, Tucker Model

## Overview
Tucker Decomposition (specifically via Higher-Order SVD) approximates an $N$-dimensional input tensor $\mathcal{A}$ by a product of a core tensor $\mathcal{B}$ and $N$ factor matrices $\mathbf{U}^{(n)}$, capturing the multi-linear structure of volume data [S1, unofficial][S2]. It sets itself apart from sibling methods like CP Decomposition by providing a compact model with rank-reducible bases that capture non-axis aligned features, unlike fixed-basis transforms [S2][S3]. It serves as the foundational compression step for Tensor Approximation, enabling multiresolution volume rendering by learning global bases [S2][S3].

## How it works
**Inputs and Outputs:**
*   **Input:** An $N$-dimensional input tensor (volume data) $\mathcal{A} \in \mathbb{R}^{I_1 \times I_2 \times \cdots \times I_N}$.
*   **Outputs:**
    *   Factor matrices (basis matrices) $\mathbf{U}^{(n)} \in \mathbb{R}^{I_n \times R_n}$ for each mode $n=1 \dots N$.
    *   Core tensor $\mathcal{B} \in \mathbb{R}^{R_1 \times R_2 \times \cdots \times R_N}$.
    *   Multilinear rank $(R_1, R_2, \dots, R_N)$.

**Data Structures:**
*   **Factor Matrices:** Stored as 2D arrays. Columns are orthonormal vectors representing principal components [S1, unofficial].
*   **Core Tensor:** Stored as an $N$-dimensional array. It represents the projection of $\mathcal{A}$ onto the factor matrices [S1, unofficial][S3].
*   **Multiresolution Structure (Optional/Advanced):** For volume rendering, lower-resolution basis matrices $\mathbf{U}^{(n)}_{\downarrow k}$ are generated via mipmap reduction on the row space of $\mathbf{U}^{(n)}$, and an octree is defined with small core tensors per node [S2].

**Parameters:**
*   **Multilinear Rank $(R_1, \dots, R_N)$:** One rank $R_n$ per dimension. Typically, $R_n$ is chosen as half the input size $I_n$ (i.e., $R_n = I_n/2$) for initial data reduction [S2][S3]. For equally sized blocks in volume rendering, $R_1 = R_2 = R_3$ [S3].
*   **Quantization:** In practical volume rendering implementations, 16-bit encoding is used for basis matrices and 8-bit encoding for core tensor coefficients [S3].

**Formulas:**
The Tucker model approximation is defined as [S1, unofficial]:
$$ \mathcal{A} \approx \mathcal{B} \times_1 \mathbf{U}^{(1)} \times_2 \mathbf{U}^{(2)} \times_3 \cdots \times_N \mathbf{U}^{(N)} $$
where $\times_n$ denotes the $n$-mode product. This can be expanded as a sum of rank-one tensors [S1, unofficial]:
$$ \mathcal{A} \approx \sum_{r_1=1}^{R_1} \sum_{r_2=1}^{R_2} \dots \sum_{r_N=1}^{R_N} b_{r_1 r_2 \dots r_N} \cdot \mathbf{u}_{r_1}^{(1)} \circ \mathbf{u}_{r_2}^{(2)} \circ \dots \circ \mathbf{u}_{r_N}^{(N)} $$
where $\circ$ is the outer product and $\mathbf{u}_{r_n}^{(n)}$ is the $r_n$-th column of $\mathbf{U}^{(n)}$ [S1, unofficial].

The core tensor $\mathcal{B}$ is computed by projecting $\mathcal{A}$ onto the factor matrices. For orthogonal factor matrices, this uses transposes [S1, unofficial]:
$$ \mathcal{B} = \mathcal{A} \times_1 \mathbf{U}^{(1)T} \times_2 \mathbf{U}^{(2)T} \times_3 \cdots \times_N \mathbf{U}^{(N)T} $$
Element-wise, this is [S1, unofficial]:
$$ b_{r_1 r_2 \dots r_N} = \sum_{i_1=1}^{I_1} \sum_{i_2=1}^{I_2} \dots \sum_{i_N=1}^{I_N} a_{i_1 i_2 \dots i_N} \cdot u_{i_1 r_1}^{(1)} \cdot u_{i_2 r_2}^{(2)} \cdots u_{i_N r_N}^{(N)} $$

**Algorithm Steps:**
1.  **Generate Basis Matrices:** Apply Higher-Order Singular Value Decomposition (HOSVD) or Higher-Order Orthogonal Iteration (HOOI) to the input volume $\mathcal{A}$ along every data direction [S2][S3]. HOOI uses an Alternating Least Squares (ALS) algorithm to optimize basis matrices one after another [S3].
2.  **Compute Core Tensor:** Once basis matrices cannot be improved further, compute the core tensor $\mathcal{B}$ using the formula above. $\mathcal{B}$ represents the projection of $\mathcal{A}$ onto $\mathbf{U}^{(n)}$ [S2][S3].
3.  **Rank Truncation:** Apply rank-truncation to the core tensor. Since the core tensor from HOSVD is all-orthogonal, a rank-reduction similar to matrix SVD can be applied to achieve compression ($R_n < I_n$) [S2][S3]. Further adaptive rank reductions can be applied [S3].
4.  **Multiresolution Generation (for Volume Rendering):**
    *   Generate lower resolution basis matrices $\mathbf{U}^{(n)}_{\downarrow k}$ by employing mipmap reduction on the row space of $\mathbf{U}^{(n)}$ [S2].
    *   Perform re-orthogonalization to match basis matrix row blocks to multiresolution volume octree nodes [S2].
    *   Define a multiresolution volume octree with one small core tensor per node, constructed by projecting the input volume brick onto the corresponding basis matrix rows [S2].

**Pseudocode:**
```python
def tucker_decomposition_hosvd(A, target_ranks):
    """
    Computes the Tucker decomposition of tensor A using HOSVD/HOOI.
    
    Args:
        A: Input N-dimensional tensor of shape (I1, I2, ..., IN).
        target_ranks: List of target ranks (R1, R2, ..., RN).
        
    Returns:
        B: Core tensor of shape (R1, R2, ..., RN).
        U: List of factor matrices [U1, U2, ..., UN], where Un has shape (In, Rn).
    """
    N = A.ndim
    U = []
    
    # Step 1: Generate Basis Matrices using HOOI/HOSVD
    # HOOI iteratively optimizes each mode's basis matrix
    for n in range(N):
        # Mode-n unfolding of A
        # Reshape A such that mode n is the first dimension
        # Shape becomes (In, I1*I2*...*In-1*In+1*...*IN)
        A_unfolded = mode_n_fold(A, n)
        
        # Compute covariance matrix or use SVD on unfolded matrix
        # For HOSVD: U_n = U_svd[:, :Rn] from SVD(A_unfolded)
        # For HOOI: Iterate ALS to optimize Un
        # Here we assume HOSVD for direct computation as per standard definition
        # In practice, HOOI might be used for better accuracy
        U_svd, _, _ = svd(A_unfolded)
        
        # Truncate to target rank
        Un = U_svd[:, :target_ranks[n]]
        
        # Ensure orthonormality (HOSVD guarantees this, but numerical stability check)
        Un = normalize_columns(Un)
        U.append(Un)
        
    # Step 2: Compute Core Tensor
    # B = A x1 U1^T x2 U2^T ... xN UN^T
    B = A
    for n in range(N):
        # n-mode product with transpose of Un
        # B = B x_n Un^T
        # This contracts the n-th mode of B with Un
        B = mode_n_product(B, U[n].T, n)
        
    # Step 3: Rank Truncation (Optional/Adaptive)
    # If target_ranks were not strict, one might truncate B further
    # based on singular values of matricizations of B.
    # For HOSVD, the ranks are fixed by the input target_ranks.
    
    return B, U

def mode_n_fold(T, n):
    """
    Unfolds tensor T along mode n.
    Returns matrix of shape (In, Product of other dimensions).
    """
    # Move mode n to the front
    axes = [n] + [i for i in range(T.ndim) if i != n]
    T_permuted = numpy.transpose(T, axes)
    In = T.shape[n]
    other_dims = numpy.prod([T.shape[i] for i in range(T.ndim) if i != n])
    return T_permuted.reshape(In, other_dims)

def mode_n_product(T, M, n):
    """
    Computes the n-mode product of tensor T with matrix M.
    T is shape (I1, ..., IN). M is shape (In, Rn) or (Rn, In) depending on context.
    Here M is Un^T, shape (Rn, In).
    Result shape is (I1, ..., Rn, ..., IN).
    """
    # Reshape T to 2D: (In, Product of others)
    # But standard n-mode product definition:
    # B(i1...in-1 r in+1...iN) = sum_in T(i1...iN) * M(r, in)
    
    # Efficient implementation using einsum or reshape
    # Let's use reshape approach for clarity
    axes = [n] + [i for i in range(T.ndim) if i != n]
    T_permuted = numpy.transpose(T, axes)
    In = T.shape[n]
    other_shape = [T.shape[i] for i in range(T.ndim) if i != n]
    T_2d = T_permuted.reshape(In, -1)
    
    # M is (Rn, In). We want to contract In.
    # Result_2d = M @ T_2d -> Shape (Rn, Product of others)
    Result_2d = M @ T_2d
    
    # Reshape back to tensor shape with Rn in position n
    new_shape = list(other_shape)
    new_shape.insert(n, M.shape[0])
    Result_permuted = Result_2d.reshape(new_shape)
    
    # Inverse permutation
    inv_axes = [0] * T.ndim
    for i, ax in enumerate(axes):
        if i == 0:
            inv_axes[n] = 0 # The new mode is at index 0 in permuted
        else:
            inv_axes[ax] = i - 1 # Shifted back
            
    # Actually, simpler: just transpose back
    # The new mode is at index 0 in Result_permuted
    # We need to move it back to index n
    final_axes = [0] + [i for i in range(T.ndim) if i != n] # Wait, this is wrong logic for inverse
    # Correct inverse:
    # Original axes: [n, 0, 1, ..., n-1, n+1, ...]
    # We want: [0, 1, ..., n-1, new_n, n+1, ...]
    # So we need to move index 0 to index n.
    
    # Let's rebuild axes list properly
    current_axes = [n] + [i for i in range(T.ndim) if i != n]
    # We want to reverse this permutation
    inv_perm = [0] * T.ndim
    for new_idx, old_idx in enumerate(current_axes):
        inv_perm[old_idx] = new_idx
        
    # But current_axes has the new mode at 0.
    # We need to map the result's axes back to original order.
    # Result shape: (Rn, I1, ..., In-1, In+1, ..., IN)
    # We want: (I1, ..., In-1, Rn, In+1, ..., IN)
    
    # Move axis 0 to position n
    final_axes = list(range(T.ndim))
    final_axes.insert(n, 0)
    final_axes.pop(n+1) # Remove the old n which is now shifted? No.
    
    # Simpler:
    # Result_permuted has shape (Rn, I1, ..., In-1, In+1, ..., IN)
    # We want to move the first axis (Rn) to position n.
    final_axes = [i for i in range(1, T.ndim + 1)] # This is getting messy.
    
    # Standard numpy transpose for moving axis 0 to n:
    # axes = [1, 2, ..., n, 0, n+1, ...]
    move_axes = list(range(1, T.ndim + 1))
    move_axes.insert(n, 0)
    
    return numpy.transpose(Result_permuted, move_axes)
```

## Subtopics

### [Tensor Approximation](5362-tensor-approximation.md)
Tensor Approximation (TA) is a compression technique where a multi-dimensional input dataset (tensor) is factorized into a product of a core tensor and factor matrices (one for each dimension), known as the Tucker model. It solves the problem of compactly representing volume data by learning rank-reducible bases that capture non-axis aligned features at different scales, providing a highly compact model compared to fixed-basis transforms. Unlike wavelet transforms which follow a multiresolution behavior, TA follows a multiscale behavior, making it more capable of capturing specific statistical features and non-axis aligned structures with the same number of coefficients, though wavelets may still outperform TA in reconstructing overall statistical distributions at very coarse resolutions.

### [Tensor-Specific Quantization](6775-tensor-specific-quantization.md)
Tensor-Specific Quantization is a fixed bit-length encoding strategy used to compactly represent the coefficients of a Tucker decomposition, thereby reducing disk-to-host-to-device bandwidth during volume rendering. It distinguishes itself from generic floating-point storage by applying uniform linear quantization to factor matrices and logarithmic quantization to the core tensor, a design choice that simplifies parallel decoding on the GPU.

## Operating characteristics
*   **Time Complexity:** Computing HOSVD involves SVDs of mode-n unfoldings. For an $N$-dimensional tensor of size $I^N$ and rank $R$, the complexity is roughly $O(N \cdot I^N \cdot R^2)$ or higher depending on implementation [S2]. HOOI adds iterative ALS steps, increasing time cost [S3].
*   **Memory Complexity:** The uncompressed core tensor has size $\prod R_n$. Factor matrices have size $\sum I_n R_n$. For compression, $R_n < I_n$. Large volumes require memory-mapped files and parallel memory-aligned matrix-matrix multiplications [S2].
*   **Measured Performance:** In volume rendering, using global bases with multiresolution octrees allows reducing the multilinear rank to half the block size ($R_1=R_2=R_3=B/2$), keeping storage costs low while maintaining only one set of global bases [S2].
*   **Strengths:** Captures non-axis aligned features; provides a compact model; supports multiresolution rendering via mipmap reduction of bases [S2][S3].
*   **Limitations:** The decomposition is not unique (core tensor rotations allow rearrangement of B and U without affecting fit) [S1, unofficial]. The core tensor coefficients are not strictly decreasing like in matrix SVD, though progressive truncation works well in practice [S2][S3].
*   **When to use:** When volume data exhibits strong multi-linear correlations and non-axis aligned structures that fixed-basis transforms (like wavelets) miss [S2][S3].
*   **When not to use:** When strict multiresolution hierarchy (like wavelets) is required for very coarse resolution statistical reconstruction [S2].

## Background
Tucker Decomposition, also known as the Tucker Model, is a widely used approach for tensor decompositions [S1, unofficial]. It was formalized in the context of higher-order SVD (HOSVD) and Higher-Order Orthogonal Iteration (HOOI) [S2][S3]. In volume rendering, it was notably applied by Suter et al. [SMP13] and [SIM*11] for global multiresolution basis generation, enabling Tensor Approximation-based Direct Volume Rendering (DVR) [S2][S3]. It builds on the concept of PCA extended to higher dimensions [S3].
