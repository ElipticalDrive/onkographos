# Decomposed Low-Rank Tensor (VM-Decomposition)
Also called: 4D Tensor Decomposition, TensoRF VM Decomposition, TensoRRF Scene Representation, Tensorial Scene Representation with Vector-Matrix Factorization, VM Decomposition, Vector-Matrix Decomposition

## Overview
Decomposed Low-Rank Tensor (VM-Decomposition) is a scene representation method that factorizes the spatial dimensions of a 4D feature tensor (encoding 3D coordinates and a feature channel) into compact vector and matrix factors to reduce memory footprint and accelerate training [S2, unofficial][S3, unofficial]. It builds on [Vector-Matrix (VM) Decomposition](3452-vector-matrix-vm-decomposition.md) by explicitly handling the feature dimension through characteristic components, allowing the storage of features decoded by an MLP rather than direct color values [S3, unofficial]. Unlike CP-decomposition which uses only vectors, VM-decomposition relaxes low-rank constraints for two modes of the tensor, acting as a special case of Block Term Decomposition [S1][S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A 4D scene tensor $G_S \in \mathbb{R}^{I \times J \times K \times L}$, where $I, J, K$ correspond to spatial dimensions (e.g., $x, y, z$) and $L$ is the feature vector length [S2, unofficial][S3, unofficial].
*   **Output:** A decomposed representation consisting of vector factors $v$, matrix factors $M$, and characteristic components $b$ [S2, unofficial][S3, unofficial]. The scene feature vector $F(x)$ at any 3D coordinate $x$ is retrieved via linear interpolation of these factors [S2, unofficial].

**Data Structures**
The tensor is decomposed into three terms, one for each spatial axis [S2, unofficial]. For a rank $R$, the storage consists of:
1.  **Vector factors:** $v_{S,r}^m \in \mathbb{R}^{D_m}$ for each rank $r \in \{1, \dots, R\}$ and axis $m \in \{X, Y, Z\}$ [S2, unofficial].
2.  **Matrix factors:** $M_{S,r}^m \in \mathbb{R}^{D_{e_m} \times D_{e_m}}$ where $e_m$ denotes the two axes orthogonal to $m$ (e.g., if $m=X$, $e_m=\{Y,Z\}$) [S2, unofficial][S3, unofficial].
3.  **Characteristic components:** $b_r^m \in \mathbb{R}$ for each rank $r$ and axis $m$ [S2, unofficial].

**Steps**
1.  Initialize the feature vector $F(x)$ of length $L$ to zeros [G].
2.  For each rank $r$ from $1$ to $R$:
3.  For each spatial axis $m \in \{X, Y, Z\}$:
4.  Identify the vector axis $m$ and the two matrix axes $e_m$ [S3, unofficial].
5.  Retrieve the coordinate values $(i, j, k)$ of point $x$ along the orthogonal axes [S3, unofficial]. If $m=Y$, then $e_m=XZ$, so $i$ corresponds to $y$, and $j,k$ correspond to $x,z$ [S3, unofficial].
6.  Perform linear interpolation on $v_{S,r}^m$ along axis $m$ using coordinate $i$ [S2, unofficial].
7.  Perform bilinear interpolation on $M_{S,r}^m$ along axes $e_m$ using coordinates $j,k$ [S2, unofficial].
8.  Compute the contribution: $\text{term} = v_{\text{interp}} \times M_{\text{interp}} \times b_r^m$ [S3, unofficial].
9.  Add $\text{term}$ to $F(x)$.
10. Extract density $\sigma(x) = F[0]$ and appearance features $a(x) = F[1, L]$ [S2, unofficial].
11. Decode color via MLP: $F_c(x, \vec{d}) = S(T_c(x), \vec{d})$ [S1].

**Formulas**
The decomposition of the scene tensor $G_S$ is defined as [S2, unofficial]:
$$
G_S = \sum_{r=1}^{R} \sum_{m \in \{X,Y,Z\}} v_{S,r}^m \circ M_{S,r}^m \circ b_r^m
$$
where $\circ$ denotes the outer product. Here, $v_{S,r}^m$ is the $r$-th vector factor for axis $m$, $M_{S,r}^m$ is the $r$-th matrix factor for axis $m$, and $b_r^m$ is the $r$-th characteristic component for axis $m$ [S2, unofficial].

To retrieve the feature vector $F(x)$ at a point $x$ with coordinates $(i, j, k)$ corresponding to axes $X, Y, Z$:
$$
F(x) = \sum_{r=1}^{R} \sum_{m \in \{X,Y,Z\}} v_{m}^{r}(i) \cdot M_{m}^{r}(j, k) \cdot b_{r}^{m}
$$
The indices $i,j,k$ correspond to the coordinate values of point $x$ along the orthogonal axes. If $m=Y$, then $e_m=XZ$, so $i$ corresponds to $y$, and $j,k$ correspond to $x,z$ [S3, unofficial].

The output features are extracted from $F(x)$:
*   Volume density: $\sigma(x) = F[0]$ [S2, unofficial].
*   Appearance feature: $a(x) = F[1, L]$ [S2, unofficial].

**Parameters**
*   $R$: The number of components (rank) in the decomposition [S1][S2, unofficial].
*   $L$: The length of the feature vector [S2, unofficial].
*   $v_{S,r}^m$: Vector factor for axis $m$, rank $r$ [S2, unofficial].
*   $M_{S,r}^m$: Matrix factor for axis $m$, rank $r$ [S2, unofficial].
*   $b_r^m$: Characteristic component for axis $m$, rank $r$ [S2, unofficial].

**Pseudocode**
```python
import math

def vm_decomposition_interpolate(x, y, z, factors, rank, feature_len):
    """
    Interpolates the scene feature vector F(x) at coordinate (x,y,z) using VM-decomposed factors.
    """
    F = [0.0] * feature_len
    axes_map = {
        'X': ('X', ('Y', 'Z')),
        'Y': ('Y', ('X', 'Z')),
        'Z': ('Z', ('X', 'Y'))
    }
    coords_map = {'X': x, 'Y': y, 'Z': z}

    for r in range(rank):
        for m in ['X', 'Y', 'Z']:
            vec_axis, mat_axes = axes_map[m]
            v_r = factors['v'][vec_axis][r]
            M_r = factors['M'][m][r]
            b_r = factors['b'][m][r]

            idx_v = coords_map[vec_axis]
            ax1, ax2 = mat_axes
            idx_m1 = coords_map[ax1]
            idx_m2 = coords_map[ax2]

            v_val = lerp_1d(v_r, idx_v)
            M_val = lerp_2d(M_r, idx_m1, idx_m2)

            # b_r^m is a scalar per source [S2, unofficial], but F(x) has length L.
            # Implementation treats b_r as a vector of length L to expand the feature axis [G].
            scale = v_val * M_val
            for k in range(feature_len):
                F[k] += scale * b_r[k]

    return F

def lerp_1d(data, coord):
    i = math.floor(coord)
    w = coord - i
    if i < 0:
        i = 0
        w = 0.0
    if i >= len(data) - 1:
        i = len(data) - 2
        w = 1.0
    return data[i] * (1.0 - w) + data[i + 1] * w

def lerp_2d(data, coord1, coord2):
    i = math.floor(coord1)
    w1 = coord1 - i
    j = math.floor(coord2)
    w2 = coord2 - j
    if i < 0:
        i = 0
        w1 = 0.0
    if j < 0:
        j = 0
        w2 = 0.0
    if i >= len(data) - 1:
        i = len(data) - 2
        w1 = 1.0
    if j >= len(data[0]) - 1:
        j = len(data[0]) - 2
        w2 = 1.0
    v00 = data[i][j]
    v01 = data[i][j + 1]
    v10 = data[i + 1][j]
    v11 = data[i + 1][j + 1]
    v0 = v00 * (1.0 - w1) + v10 * w1
    v1 = v01 * (1.0 - w1) + v11 * w1
    return v0 * (1.0 - w2) + v1 * w2
```

**Edge Cases and Pitfalls**
*   **Boundary Conditions:** Linear interpolation must handle coordinates outside the grid bounds. [G] Clamp indices to $[0, D-1]$ or use reflection padding.
*   **Numerical Stability:** When using Gaussian kernels for filtering (as in [S1]), if $\sigma < 0.001$, the kernel should be assigned as a discrete impulse function $\delta$ to avoid numerical instability [S1].
*   **Feature Dimension Ambiguity:** The sources state $b_r^m \in \mathbb{R}$ [S2, unofficial], but the feature vector $F(x)$ has length $L$. Implementers should treat $b_r^m$ as a vector of length $L$ to expand the feature axis, or apply the decomposition per feature channel [G].

## Operating characteristics
*   **Time Complexity:** Retrieval is $O(R \cdot D^2)$ for interpolation, where $R$ is rank and $D$ is grid dimension [S2, unofficial]. Training is expedited compared to dense tensors [S2, unofficial].
*   **Memory Complexity:** $O(R \cdot (D + D^2))$ per axis, significantly less than $O(D^3)$ for dense tensors [S3, unofficial].
*   **Strengths:** Reduces memory footprint and accelerates training [S2, unofficial][S3, unofficial].
*   **Limitations:** Naive application may result in suboptimal reconstruction quality and inaccurate poses due to lack of internal bias [S1]. Requires coarse-to-fine training schedule [S1].
*   **When not to use:** When high-fidelity joint camera pose optimization is required without careful training scheduling [S1].

## Background
*   **Origin:** Proposed by Chen et al. in TensoRF (2022) [S1][S3, unofficial].
*   **History:** VM-decomposition is a variant of tensor decomposition used in scene representation. It was introduced to address the high memory cost of dense voxel grids [S3, unofficial].
*   **Usage:** Used in TensoRF and subsequent works like STensoRRF [S1][S2, unofficial].
