# Octree Hashing for Point Location and Neighbor Finding

Also called: Integer coordinate hashing

## Overview
This method provides fast point location and neighbor finding in an implicit octree structure by mapping 3D coordinates to integer indices within a fixed interval $[0, 2^{d_{max}}]$. It solves the problem of locating a leaf node or its neighbors without storing explicit parent pointers, relying instead on bitwise arithmetic and a traversal stack. It differs from Frisken and Perry [5] by omitting the distinction of "left" or "right" midplane neighbors and by precomputing bit-depth shifts to avoid expensive arbitrary left-shifts, thereby optimizing for integer arithmetic performance [S1].

## How it works
**Inputs:**
- $d_{max}$: The maximum depth of the octree.
- $P_{origin}$: The 3D integer coordinates of the current node.
- $P_{dest}$: The 3D integer coordinates of the target node.
- $parent\_trace[]$: An array filled during ray traversal containing the indices of parent nodes for the current cap [S1].

**Outputs:**
- The scalar value of the leaf node at $P_{dest}$ (for point location).
- The coordinates or index of the neighbor node (for neighbor finding).

**Data Structures:**
- **Coordinate Space:** Vectors are defined on the interval $[0, 2^{d_{max}}]$. Components are cast to integers [S1].
- **Precomputed Table:** `child_bit_depth[d]` stores the bit mask for depth $d$.
- **Parent Trace:** An array `parent_trace[]` storing parent indices, used to replace explicit parent pointers in nodes [S1].

**Formulas:**
1.  **Bit Depth Precomputation:**
    $$ \text{child\_bit\_depth}[d] = 1 \ll (d_{max} - d - 1) $$
    where $d$ is the current depth [S1].

2.  **Octant Offset Calculation:**
    The target child octant offset $o \in [0, 7]$ is computed by masking the destination coordinates with the depth bit and shifting by constants for X, Y, and Z components:
    $$ o = \left( (P_{dest}.x \ \& \ \text{child\_bit\_depth}[d]) \gg s_x \right) + \left( (P_{dest}.y \ \& \ \text{child\_bit\_depth}[d]) \gg s_y \right) + \left( (P_{dest}.z \ \& \ \text{child\_bit\_depth}[d]) \gg s_z \right) $$
    where $s_x, s_y, s_z$ are constant shift amounts corresponding to the interleaving of X, Y, and Z components [S1].

**Steps:**

**Point Location:**
1.  Start at an initial node (root for full location, or a deeper node for neighbor-finding context) with current coordinates $P_{curr}$ and depth $d$.
2.  Compute the target child octant offset $o$ using the formula above with $P_{dest}$ and `child_bit_depth[d]` [S1].
3.  Determine the child node index based on $o$.
4.  If the child is a leaf, return the scalar value (either a scalar leaf in an interior node or a voxel within a cap node) [S1].
5.  If the child is an interior node, update $P_{curr}$ to the child's coordinates, increment $d$, and repeat from step 2 [S1].

**Neighbor Finding:**
1.  Begin at the depth of the origin node's parent. Let $d = d_{origin} - 1$ [S1].
2.  Recurse up the octree to find a common parent:
    a.  Check if the origin and destination nodes share the same parent at depth $d$ by &-masking both $P_{origin}$ and $P_{dest}$ with `child_bit_depth[d]` and performing integer equality [S1].
    b.  If they are equal, a common parent is found. Proceed to point location from this common parent to $P_{dest}$ [S1].
    c.  If not equal, decrement $d$ and repeat.
3.  To navigate up the tree without explicit parent pointers, use the `parent_trace[]` array filled during the initial ray traversal to retrieve parent indices [S1].
4.  Once the common parent is identified, use the Point Location algorithm to find the leaf at $P_{dest}$ [S1].

**Pseudocode:**

```python
def precompute_child_bit_depth(max_depth):
    """Precompute bit masks for each depth level."""
    child_bit_depth = []
    for d in range(max_depth + 1):
        child_bit_depth.append(1 << (max_depth - d - 1))
    return child_bit_depth

def get_octant_offset(dest_coords, depth, child_bit_depth):
    """
    Compute the 0-7 octant offset for a destination coordinate at a given depth.
    Assumes constants SHIFT_X, SHIFT_Y, SHIFT_Z are defined for X, Y, Z interleaving.
    """
    mask = child_bit_depth[depth]
    x_part = (dest_coords.x & mask) >> SHIFT_X
    y_part = (dest_coords.y & mask) >> SHIFT_Y
    z_part = (dest_coords.z & mask) >> SHIFT_Z
    return x_part + y_part + z_part

def point_location(initial_node, dest_coords, child_bit_depth, max_depth):
    """
    Perform top-down search to find the leaf value at dest_coords.
    initial_node: The starting node index or object.
    """
    current_node = initial_node
    current_depth = initial_node.depth # Assume node has a depth attribute
    
    # If starting from root, current_depth is 0. 
    # If starting from neighbor-finding context, it is deeper.
    
    while current_depth < max_depth:
        # Compute target child octant
        octant = get_octant_offset(dest_coords, current_depth, child_bit_depth)
        
        # Determine child node index based on octant
        # Implementation detail: specific to the octree storage scheme
        child_node = current_node.get_child(octant)
        
        if child_node.is_leaf:
            # Return scalar value: scalar leaf in interior node or voxel in cap node
            return child_node.value
        
        current_node = child_node
        current_depth += 1
        
    # If loop completes without finding leaf (should not happen if dest is valid)
    return None

def find_neighbor(origin_node, dest_coords, child_bit_depth, parent_trace):
    """
    Find the neighbor of origin_node in the direction of dest_coords.
    """
    # Start at the depth of the origin node's parent
    origin_depth = origin_node.depth
    d = origin_depth - 1
    
    # Recurse up to find common parent
    while d >= 0:
        mask = child_bit_depth[d]
        
        # Check if origin and dest share the same parent at depth d
        # Mask coordinates to get the parent's coordinate at this depth
        origin_parent_coord = origin_node.coords & mask # Simplified: actual logic requires tracking coords
        dest_parent_coord = dest_coords & mask
        
        if origin_parent_coord == dest_parent_coord:
            # Common parent found
            # Use point location from this common parent to find the leaf at dest_coords
            # Note: The common parent index must be retrieved from parent_trace or calculated
            common_parent = get_parent_at_depth(origin_node, d, parent_trace)
            return point_location(common_parent, dest_coords, child_bit_depth, origin_node.max_depth)
        
        d -= 1
        
    # If no common parent found (should not happen for valid neighbors)
    return None
```

**Parameters:**
- $d_{max}$: Maximum octree depth. Typical values depend on the volume resolution and required detail [S1].
- `SHIFT_X`, `SHIFT_Y`, `SHIFT_Z`: Constants for interleaving X, Y, Z components. Exact values depend on the bit-interleaving scheme used [S1].

**Edge Cases and Pitfalls:**
- **Precision:** The method relies on integer arithmetic, avoiding floating-point issues. Coordinates must be cast to integers within the $[0, 2^{d_{max}}]$ range [S1].
- **Boundaries:** Neighbor finding assumes the destination is within the octree bounds. Out-of-bounds checks are not explicitly described in the source [S1].
- **Parent Trace:** The method requires `parent_trace[]` to be correctly filled during ray traversal. If the trace is incomplete or incorrect, neighbor finding will fail [S1].

## Operating characteristics
- **Time Complexity:** Point location is $O(\log N)$ where $N$ is the number of nodes, as it traverses from root to leaf [S1]. Neighbor finding involves recursing up the tree, which is also bounded by the depth $d_{max}$, so $O(d_{max})$ [S1].
- **Memory Footprint:** The method omits parent pointers from nodes to minimize memory footprint, relying on the `parent_trace[]` array instead [S1].
- **Performance:** The precomputation of `child_bit_depth` and use of bitwise operations ($\&$, $\gg$) are optimized for integer arithmetic, avoiding expensive arbitrary left-shifts [S1].
- **Strengths:** Fast point location and neighbor finding without explicit parent pointers; simplified logic compared to Frisken and Perry [5] [S1].
- **Limitations:** Requires precomputation of bit depths; requires `parent_trace[]` to be maintained during traversal; limited to integer coordinate spaces [S1].

## Background
This method is based on the octree hashing scheme described in "PDF Interactive Isosurface Ray Tracing of Large Octree Volumes" [S1]. It adapts the approach of Frisken and Perry [5] but simplifies the neighbor-finding logic by omitting the "left"/"right" midplane distinction and removes parent pointers to reduce memory usage [S1].
