# Palette Compression
Also called: Block-based palette compression, Variable-length palette compression

## Overview
Palette compression is a variable-length compression scheme for the attribute array in decoupled Sparse Voxel Octrees (SVOs) that reduces memory footprint by exploiting spatial coherence through global material arrays and local palettes [S1]. It differs from fixed-width indexing by allowing the bit-width of indices to adapt to the number of unique attributes within localized blocks of the depth-first attribute array, achieving higher compression ratios for scenes with large homogeneous regions [S1].

## How it works
**Inputs and Outputs**
- **Input**: An indexed attribute array $A^e = \{m_0, \dots, m_{\Lambda-1}\}$, where each $m_i$ is an index into the global material array $M$. $\Lambda$ is the total number of entries (equal to the voxel count in the original SVO) [S1].
- **Output**: An array of blocks $\{B_0, \dots, B_{\gamma-1}\}$, an array of palettes $\{P_0, \dots, P_{\rho-1}\}$, and a block directory mapping block start indices to palette indices [S1].

**Data Structures**
1.  **Global Material Array ($M$)**: Stores all $\lambda$ unique attributes in the scene. $\lambda \ll \Lambda$ [S1].
2.  **Block Directory**: An array of entries ordered by the starting node index of each block. Each entry stores the starting index and the index of the associated palette in the palette array. This ordering enables binary search for random access [S1].
3.  **Block ($B$)**: A contiguous sub-segment of the attribute array. It stores indices into its associated palette rather than into $M$.
4.  **Palette ($P$)**: An array of unique indices into $M$ required to retrieve all attributes present in its associated block. A palette can be shared by multiple blocks [S1].

**Parameters**
-   $\Lambda$: Total number of entries in $A^e$ [S1].
-   $\lambda$: Number of unique voxel attributes in $M$ [S1].
-   $\omega$: The bit-width used for indices within a block. $\omega = \lceil \log_2 |P| \rceil$, where $|P|$ is the number of unique entries in the palette [S1].

**Algorithm Steps**
The compression uses a greedy heuristic to partition $A^e$ into blocks. The process consists of two phases [S1]:

1.  **Phase 1 (Greedy Heuristic for Large Blocks)**:
    -   Iterate $\omega$ from 0 to 3.
    -   Find the largest contiguous block $B$ within the current unassigned range that contains exactly $2^\omega$ unique material indices.
    -   Calculate the memory cost of this block using the formula below.
    -   If the memory cost is less than the cost of storing the block without compression (i.e., using $\omega+1$ bits or the previous width plus directory overhead), create the palette $P$, replace the material indices in $B$ with local indices into $P$, and recursively process the remaining unassigned data before and after $B$.
    -   If the criterion fails, increment $\omega$ and repeat.
    -   Terminate Phase 1 if $\omega \ge 4$ (16 unique indices), as finding the largest block becomes computationally infeasible [S1].

2.  **Phase 2 (Remaining Data)**:
    -   For the remaining unassigned data, consider blocks starting at the current index $m_i$ for $\omega \in \{0, \dots, 8\}$.
    -   For each $\omega$, find the largest block $B_\omega$ starting at $m_i$ with $2^\omega$ unique indices.
    -   Calculate the memory per entry $S_\omega$ for each candidate block.
    -   Select the block with the minimal $S_\omega$.
    -   Create the palette, replace indices, and recursively process the remainder [S1].

**Memory Formula**
The memory required for a block $B$ spanning indices $m_i$ to $m_j$ with bit-width $\omega$ is [S1]:
$$ \text{MEMORY}(\{m_i, \dots, m_j\}, \omega) = (j - i + 1) \cdot \omega + 2^\omega \cdot \lceil \log_2 \lambda \rceil + \text{size}(\text{directory entry}) $$
Where:
-   $(j - i + 1) \cdot \omega$ is the size of the block data (number of entries $\times$ bits per index).
-   $2^\omega \cdot \lceil \log_2 \lambda \rceil$ is the size of the palette (number of unique entries $\times$ bits per material index).
-   $\text{size}(\text{directory entry})$ is the overhead for the block directory entry [S1].

        # Map global index to local index
        index_map = {val: i for i, val in enumerate(unique_indices)}

        """

        best_start = -1

**Edge Cases and Pitfalls**
-   **Combinatorial Complexity**: Finding the optimal block partition is a hard combinatorial problem [S1]. The greedy heuristic is an approximation [S1].
-   **Phase 1 Termination**: Phase 1 terminates when $\omega \ge 4$ because finding the largest block with 16 or more unique indices becomes computationally infeasible [S1].
-   **Palette Sharing**: Palettes can be shared by multiple blocks. The algorithm must check if an existing palette matches the required unique indices before creating a new one [S1].

## Operating characteristics
-   **Time Complexity**: The greedy heuristic involves searching for the largest block with a specific number of unique indices. Phase 1 is limited to small $\omega$ ($<4$) to keep this search feasible. Phase 2 searches for blocks starting at the current index for $\omega \in \{0, \dots, 8\}$. The overall complexity depends on the number of blocks and the cost of finding these blocks, which is linear in the worst case per block search but optimized by the greedy choice [S1].
-   **Memory Complexity**: The memory footprint is reduced by storing indices into palettes instead of full attributes or global indices. The overhead includes the palettes themselves and the block directory. The directory overhead is described as negligible [S1].
-   **Performance**: The method is efficient for scenes with high spatial coherence, where large areas share a limited set of attributes [S1].
-   **Strengths**: Exploits spatial coherence; variable-length indices allow fine-grained compression; fast runtime access due to local palettes [S1].
-   **Limitations**: Approximate solution due to greedy heuristic; Phase 1 is limited to small palettes for performance [S1].

## Background
Palette compression was introduced in the context of geometry and attribute compression for voxel scenes, specifically as part of a decoupled SVO compression scheme [S1]. It addresses the memory bottleneck of uncompressed attribute arrays in high-resolution voxel scenes by leveraging the observation that the number of unique attributes is often much smaller than the total voxel count and that attributes exhibit spatial coherence [S1].
