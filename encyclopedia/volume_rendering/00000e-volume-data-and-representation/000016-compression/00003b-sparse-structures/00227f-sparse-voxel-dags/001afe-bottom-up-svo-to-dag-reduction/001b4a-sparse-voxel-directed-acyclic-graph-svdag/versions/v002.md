# Sparse Voxel Directed Acyclic Graph (SVDAG)
Also called: SVO to DAG reduction, Sparse Voxel DAG, Sparse Voxel DAG Construction and Reduction, Sparse Voxel DAG Construction via Subtree Caching

## Overview
The Sparse Voxel Directed Acyclic Graph (SVDAG) is a compressed hierarchical data structure for representing 3D voxel grids that reduces memory footprint by identifying and merging identical subtrees, allowing multiple parent nodes to share the same child node instance [S1, S3]. Unlike a Sparse Voxel Octree (SVO) which only encodes empty regions efficiently, the DAG additionally encodes identical regions of space by sharing pointers to identical subtrees [S1]. It transforms the tree structure into a directed acyclic graph to reduce memory footprint while supporting real-time rendering and interactive editing [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A binary voxel grid (3D array of bytes, 0 for empty, 1 for filled) and a maximum recursion depth `gridDepth` [S3].
*   **Output:** A root `VoxelNode` representing the Sparse Voxel DAG [S3].

**Data Structures:**
*   `VoxelNode`:
    *   `IsLeaf` (bool): Indicates if the node is a leaf.
    *   `Value` (byte): The voxel value (0 or 1) if `IsLeaf` is true.
    *   `Children` (VoxelNode[8]): Array of 8 child pointers.
    *   `NodeColor` (Color): Debug/visualization color (Green for homogeneous leaf, Red for non-homogeneous leaf, Blue for internal) [S3].
*   `SparseVoxelDAG`:
    *   `voxelGrid` (byte[,,]): The input raw voxel data.
    *   `gridDepth` (int): Maximum recursion depth (default 4) [S3].
    *   `rootNode` (VoxelNode): The root of the constructed DAG.
    *   `subtreeCache` (Dictionary<string, VoxelNode>): Maps a unique string key to a `VoxelNode` instance to enable sharing [S3].

**Algorithm Steps:**
1.  **Initialization:** Create an empty `subtreeCache` dictionary [S3].
2.  **Recursive Construction (`BuildDAG`):** Call `BuildDAG` on the full `voxelGrid` with `depth = gridDepth`, `position = (0,0,0)`, and `size = 2^gridDepth` [S3].
3.  **Key Generation:** For the current `grid` section, generate a unique string key representing its content using `GenerateSubtreeKey(grid)` [S3].
    *   *Note:* The specific implementation of `GenerateSubtreeKey` is not provided in the sources, but it is critical for caching [S3].
4.  **Cache Check:** Check if `subtreeCache` contains the key. If `subtreeCache.TryGetValue(key, out VoxelNode existingNode)` returns true, return `existingNode` immediately to merge identical subtrees [S3].
5.  **Leaf Creation:** If `depth == 0` OR `IsHomogeneous(grid)` is true:
    *   Create a new `VoxelNode`.
    *   Set `IsLeaf = true`.
    *   Set `Value = grid[0, 0, 0]`.
    *   Set `NodeColor` to Green if homogeneous, Red if not [S3].
6.  **Internal Node Creation:** If not a leaf:
    *   Create a new `VoxelNode`.
    *   Set `IsLeaf = false`.
    *   Set `NodeColor` to Blue [S3].
    *   Calculate `newSize = size / 2`.
    *   Loop `i` from 0 to 7:
        *   Extract the octant using `GetOctant(grid, i, newSize)` [S3].
        *   Calculate `childPosition` based on `position`, `newSize`, and `i` [S3].
        *   Recursively call `BuildDAG(octant, depth - 1, childPosition, newSize)` and assign the result to `node.Children[i]` [S3].
7.  **Cache Insertion:** Add the created node to the cache: `subtreeCache[key] = node` [S3].
8.  **Return:** Return the created or cached node [S3].

**Helper Functions:**
*   `IsHomogeneous(grid)`:
    *   Retrieve `firstValue = grid[0, 0, 0]` [S3].
    *   Iterate through all bytes in `grid`.
    *   If any `value != firstValue`, return false [S3].
    *   If loop completes, return true [S3].
*   `GetOctant(grid, octantIndex, size)`:
    *   Calculate start indices using bitmasks on `octantIndex`:
        *   `xStart = (octantIndex & 1) * size` [S3].
        *   `yStart = (octantIndex & 2) * size / 2` [S3].
        *   `zStart = (octantIndex & 4) * size / 4` [S3].
    *   Copy data from `grid` to a new `octant` array of size `size x size x size` [S3].

```python
class VoxelNode:
    def __init__(self, is_leaf, value=None, children=None, color=None):
        self.IsLeaf = is_leaf
        self.Value = value
        self.Children = children if children else [None] * 8
        self.NodeColor = color

class SparseVoxelDAG:
    def __init__(self, voxel_grid, grid_depth=4):
        self.voxelGrid = voxel_grid
        self.gridDepth = grid_depth
        self.rootNode = None
        self.subtreeCache = {}

    def build(self):

        self.rootNode = self._build_dag(self.voxelGrid, self.gridDepth, (0,0,0), size)
        return self.rootNode

    def _is_homogeneous(self, grid):
        if not grid:
            return True
        first_value = grid[0][0][0]
        for z in range(len(grid)):
            for y in range(len(grid[0])):
                for x in range(len(grid[0][0])):
                    if grid[z][y][x] != first_value:
                        return False
        return True

    def _get_octant(self, grid, octant_index, size):
        # size here is the child octant size (newSize from parent)
        x_start = (octant_index & 1) * size
        y_start = (octant_index & 2) * (size // 2)
        z_start = (octant_index & 4) * (size // 4)
        
        octant = [[[0 for _ in range(size)] for _ in range(size)] for _ in range(size)]
        for z in range(size):
            for y in range(size):
                for x in range(size):
                    octant[z][y][x] = grid[z_start + z][y_start + y][x_start + x]
        return octant

    def _build_dag(self, grid, depth, position, size):
        key = self._generate_subtree_key(grid)
        
        if key in self.subtreeCache:
            return self.subtreeCache[key]
        
        if depth == 0 or self._is_homogeneous(grid):
            value = grid[0][0][0]
            is_hom = self._is_homogeneous(grid)
            color = "Green" if is_hom else "Red"
            node = VoxelNode(is_leaf=True, value=value, color=color)
        else:
            color = "Blue"
            node = VoxelNode(is_leaf=False, color=color)
            new_size = size // 2
            for i in range(8):
                octant = self._get_octant(grid, i, new_size)
                # Calculate child position: x: bit 0, y: bit 1, z: bit 2
                cx = position[0] + ((i & 1) * new_size)
                cy = position[1] + ((i & 2) * (new_size // 2))
                cz = position[2] + ((i & 4) * (new_size // 4))
                node.Children[i] = self._build_dag(octant, depth - 1, (cx, cy, cz), new_size)
        
        self.subtreeCache[key] = node
        return node
```

**Parameters:**
*   `gridDepth`: Integer defining the maximum recursion depth. Default 4. Determines resolution; max grid size is $2^{\text{gridDepth}}$ per dimension [S3].
*   `voxelGrid`: 3D array of bytes. Binary format assumed (0 empty, 1 filled) [S3].
*   **Pointer Sizes:** SVDAG1 uses 32-bit child node pointers and 32-bit addressing words, with a 32-bit CHNM (Child Node Mask/Map) [S2]. SVDAG2 to SVDAG6 use 16-bit CHNMs, permitting three distinct child node pointer types and varying addressing word lengths [S2].

**Edge Cases and Pitfalls:**
*   The algorithm assumes the original SVO contains a large amount of redundant subtrees, which is observed in all tested scenes at moderate to high resolutions considering only geometry information [S1].
*   The algorithm can be applied even when the complete original SVO does not fit in memory, as it reduces the SVO to a minimal DAG during the process [S1].
*   Memory layout optimization is an open issue; identical pointers exist because nodes can have multiple parents, and rearranging nodes could potentially share pointers and amortize their cost [S2].
*   The implementation of `GenerateSubtreeKey` is not provided in the sources, but it is critical for the caching mechanism to work correctly [S3].

## Subtopics

### Encoding Occupancy in Memory Location
A novel encoding for SVDAGs that utilizes the memory location of nodes to carry data about their internal geometric structure, eliminating the need for an explicit mask to define the node's geometric structure [S2]. Unlike standard SVDAGs which require an explicit mask, this method reduces size and improves traversal performance by avoiding memory accesses for the mask [S2]. It demonstrates compatibility with HashDAG data structures and methods for storing voxel attributes such as colours [S2]. The memory layout could potentially be improved by mixing tree nodes (with one pointer) and DAG nodes (with up to eight pointers) and rearranging nodes to share pointers [S2].

### PSVDAG Child Node Mask Compression
Compresses the 8-octant child node mask by replacing a fixed 32-bit representation with a variable-length encoding consisting of an Active Child Node Count (ACHNC) and a compacted mask [S4].
*   **Step:** 1. Count the number of active (non-empty) child nodes. 2. Encode the count using a 3-bit ACHNC. 3. Encode the identities of the active children using a binary Child Node Mask (CHNM) with 2 bits per potential child node. 4. Concatenate ACHNC and CHNM [S4].
*   **Layout:** Total size = 3 bits (ACHNC) + variable bits (CHNM). CHNM length = 2 * (number of active children). Total length ranges from 5 bits (1 active child) to 19 bits (8 active children) [S4].
*   **Performance:** Compression ratio compared to SVDAG ranges from 1.68 to 6.4. Reduction in size ranges from 15.63% to 59.38% [S4].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory Consumption:** The DAG consumes 8 to 36 bytes per node [S1]. It reduces total memory consumption by up to 38x compared to ESVO and up to 26x compared to a minimal pointer-less SVO [S1].
*   **Node Reduction:** The CRYSPONZA scene achieved a 576x reduction in node count at the highest built resolution. The HAIRBALL scene achieved a 28x reduction despite lacking obvious regularities [S1].
*   **Build Time:** Building the DAG for CRYSPONZA at 512^3 takes 8.4ms total (1.9ms sorting). At 8K^3, it takes 4.5s total (0.6s sorting). For HAIRBALL at 8K^3, it takes 40.6s total (4.5s sorting) [S1].

**Measured Performance:**
*   In the EPICCITADEL scene voxelized to 128K^3 resolution, the Sparse Voxel DAG stores 19 billion voxels in 945MB of GPU memory. An SVO would require 5.1GB (excluding pointers) [S1].
*   Demonstrated ability to store and render voxel geometry of resolutions as high as (128k)^3 in real time [S2].
*   On an NVIDIA GTX680, ray tracing in the sparse voxel DAG achieves 170 MRays/sec for ambient occlusion and 240 MRays/sec for shadows [S1].
*   The new encoding (Modisett & Billeter) reduces geometric data size by 13%-18% compared to the original SVDAG [KSA13] and improves rendering time by around 10%-12% for static models and by up to 20%-25% for editable voxel models [S2].

**Strengths and Limitations:**
*   **Strengths:** Requires no decompression and can be traversed very efficiently [S1]. Outperforms pointer-less SVO consistently at all but lower resolutions [S1].
*   **Limitations:** The algorithm requires significant memory for the cache during construction if the full SVO fits in memory, though it can operate on streaming data [S1]. The memory layout optimization remains an open issue [S2].

## Background
The Sparse Voxel Directed Acyclic Graph (SVDAG) was introduced by Kämpe et al. in 2013 [S2, S4]. It generalizes the Sparse Voxel Octree (SVO) by allowing nodes to share pointers to identical subtrees, thereby encoding identical regions of space efficiently [S1]. It is used for high-resolution voxel geometry storage and real-time rendering, including ray tracing for shadows and ambient occlusion [S1, S2].
