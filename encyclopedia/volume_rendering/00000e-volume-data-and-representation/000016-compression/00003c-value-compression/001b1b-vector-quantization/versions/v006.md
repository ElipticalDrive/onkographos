# Vector Quantization

Also called: Cg decoding module, Codebook-based compression, Fixed-to-fixed compression, GPU-based Vector Quantization Decoding, Improved vector quantizer, LBG algorithm modification, Vector Quantization for Color Features

## Overview
Vector Quantization (VQ) is a lossy data compression algorithm that maps a set of $n$-dimensional input vectors to a single fixed-length index referencing an entry in a pre-defined $n$-dimensional codebook [S1, S3]. It solves the problem of high storage and bandwidth requirements for volumetric data by replacing individual voxel values with compact indices, exploiting spatial and temporal redundancy [S1, S2]. Unlike scalar quantization, VQ operates on multi-dimensional feature vectors (e.g., color or density gradients), allowing for higher compression ratios with lower distortion for data containing many similar sub-blocks [S1]. It is distinguished from its sibling [Hierarchical Vector Quantization](827-hierarchical-vector-quantization.md) by its flat codebook structure and from [LBG Algorithm](840-lbg-algorithm.md) by its specific implementation variants (such as PCA-based splitting) designed to mitigate the "empty cell" problem and execution speed issues inherent in the original LBG method [S1, S3].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ $n$-dimensional source vectors $S = \{(x_1, \dots, x_N)\}$, where each vector typically represents a voxel's color features or a block of voxels [S1, S2, S3].
*   **Output:** A codebook $C$ of size $K = 2^r$ codewords, and for each source vector, a mapping index $j \in [0, K-1]$ referencing the closest codeword [S1, S2, S3].

**Data Structures:**
1.  **Codebook ($C$):** A table of $K$ vectors, each of dimension $n$ [S1, S3]. In GPU implementations, the codebook and indices are stored as 3D textures [S1, S2].
2.  **Index Map:** For each voxel or block, an $r$-bit integer index pointing to the corresponding entry in $C$ [S1, S2]. In sparse data scenarios, this index is stored as a 3D texture [S1].

**Algorithm Steps:**

1.  **Codebook Initialization:**
    *   Select an initial set of $K$ codewords [S1, S3]. Common methods include random sampling from $S$ or using Principal Component Analysis (PCA) to split the data space, which avoids empty cells and speeds up convergence [S1, S3].
    *   The standard Linde-Buzo-Gray (LBG) algorithm uses a splitting strategy that can result in empty cells, increasing distortion and execution time [S1, S3].

2.  **Assignment (Quantization):**
    *   For each source vector $\vec{x}_m \in S$, find the codeword $\vec{c}_j \in C$ that minimizes the distortion metric $\delta(\vec{x}_m, \vec{c}_j)$ [S3].
    *   The most common metric is the squared Euclidean distance:
        $$ \delta(\vec{x}, \vec{y}) = \|\vec{x} - \vec{y}\|_2^2 $$
    *   If $\vec{x}_m \in p_j$, map $\vec{x}_m$ to an $r$-bit index $j$ referencing $(c_{xj}, c_{yj})$ in the codebook [S1].

3.  **Codebook Update:**
    *   Recalculate each codeword $\vec{c}_j$ as the centroid of all vectors in partition $p_j$ [S1, S3].
    *   If a partition is empty, the enhanced splitting strategy automatically avoids the issue without special treatment [S3].

4.  **Convergence Check:**
    *   Calculate the average distortion:
        $$ D_{avg} = \frac{1}{Nr} \sum_{m=1}^N \| \vec{x}_m - \vec{c}_m \|^2 $$
        where $\vec{x}_m$ is the original vector and $\vec{c}_m$ is the corresponding approximation in codebook $C$ [S1].
    *   Repeat steps 2-3 until $D_{avg}$ stabilizes or a maximum iteration count is reached [S1, S3].

5.  **Decoding (GPU Implementation Specifics):**
    *   To decode index $j$ to vector $\vec{c}_j$, the index is used as a texture coordinate to sample the codebook texture [S1, S2].
    *   **Integer-to-Float Mapping:** GPU texture coordinates are floats, but the algorithm assumes integer $(x, y, z)$ [S1]. Integer coordinates must be mapped to the float range $[-1.0, 1.0]$ by dividing by $(Dimension - 1)$ and subtracting $1.0$ [S1].
    *   For address texture coordinates $(x_A, y_A, z_A)$, the transformation is:
        $$ x_A = (x \cdot 0.5 + 0.5) \cdot \frac{D_x}{4} $$
        $$ y_A = (y \cdot 0.5 + 0.5) \cdot \frac{D_y}{4} $$
        $$ z_A = (z \cdot 0.5 + 0.5) \cdot \frac{D_z}{4} $$
        where $D_{(x,y,z)} = \{2^n \mid n \ge 3\}$ [S1].
    *   **Simulating Floor/Modulo:** Since Cg/GPU shaders lack bitwise operations, $\lfloor x/4 \rfloor$ is simulated using `GL_NEAREST` texture filtering, which maps integers 4, 5, 6, 7 to the same texel [S1].
    *   **Clamping:** If calculated coordinates fall outside $[0.0, 1.0]$, `GL_CLAMP` is used to handle border issues [S1].

**Pseudocode:**

```python
def vector_quantization_encode(source_vectors, codebook_size, max_iterations, convergence_threshold=1e-6):
    """
    Encodes source vectors into indices using a learned codebook.
    source_vectors: List of n-dimensional vectors.
    codebook_size: K, number of codewords (2^r).
    max_iterations: Maximum number of LBG iterations.
    convergence_threshold: Minimum change in average distortion to stop.
    Returns: codebook (K x n matrix), indices (N list of ints).
    """
    # 1. Initialize Codebook (random sampling from source vectors)
    import random
    codebook = [random.choice(source_vectors) for _ in range(codebook_size)]
    
    indices = []
    prev_distortion = float('inf')
    
    for iteration in range(max_iterations):
        # 2. Assignment Step
        new_indices = []
        for vec in source_vectors:
            min_dist = float('inf')
            best_idx = -1
            for i, codeword in enumerate(codebook):
                dist = sum((v - c)**2 for v, c in zip(vec, codeword))
                if dist < min_dist:
                    min_dist = dist
                    best_idx = i
            new_indices.append(best_idx)
        
        # 3. Update Step
        new_codebook = []
        for i in range(codebook_size):
            assigned_vectors = [v for v, idx in zip(source_vectors, new_indices) if idx == i]
            
            if len(assigned_vectors) > 0:
                # Calculate centroid
                dim = len(source_vectors[0])
                centroid = [0.0] * dim
                for v in assigned_vectors:
                    for d in range(dim):
                        centroid[d] += v[d]
                for d in range(dim):
                    centroid[d] /= len(assigned_vectors)
                new_codebook.append(centroid)
            else:
                # Keep old codeword if partition is empty
                new_codebook.append(codebook[i])
        
        codebook = new_codebook
        indices = new_indices
        
        # 4. Convergence Check
        current_distortion = sum(sum((v - codebook[idx])**2 for v, idx in zip(source_vectors, indices))) / len(source_vectors)
        if abs(prev_distortion - current_distortion) < convergence_threshold:
            break
        prev_distortion = current_distortion
            
    return codebook, indices

def vector_quantization_decode(indices, codebook):
    """
    Decodes indices back to approximate vectors.
    indices: List of integer indices.
    codebook: K x n matrix.
    Returns: List of decoded vectors.
    """
    decoded_vectors = []
    for idx in indices:
        decoded_vectors.append(codebook[idx])
    return decoded_vectors
```

**Parameters:**
*   **Bit-size of index ($r$):** Typically 8 bits, allowing $2^8 = 256$ codewords [S1]. Controls the trade-off between compression ratio and distortion [S1].
*   **Dimension ($n$):** Depends on the feature being compressed (e.g., 3 for RGB color, 4 for RGBA) [S1, S2].

**Edge Cases and Pitfalls:**
*   **Empty Cells:** Standard LBG can create empty partitions, increasing distortion and execution time [S1, S3]. Mitigated by PCA-based splitting [S1].
*   **Accumulated Error:** In time-varying data, decoding difference frames (P-frames) leads to error accumulation [S1]. Mitigated by periodically sending original data as I-frames [S1].
*   **GPU Limitations:** Lack of bitwise operations in older shader languages (Cg) requires texture-based simulation for integer arithmetic [S1].
*   **Sparse Data:** For highly sparse data (>99%), VQ can be used losslessly if identical blocks are mapped to the same codeword, though this is limited to datasets with high redundancy [S1].

## Subtopics

### [Progressive Encoding of Time-Varying Sequences](959-progressive-encoding-of-time-varying-sequences.md)
Compresses time-varying volumetric data by encoding frames individually while reusing codebooks from previous frames. It distinguishes itself by introducing temporal dependencies (I-frames and P-frames), reducing memory and encoding time compared to independent frame encoding.

## Operating characteristics
*   **Time Complexity:** Encoding is iterative, requiring $O(N \cdot K \cdot n)$ operations per iteration for assignment and $O(N \cdot n)$ for updates [S1, S3]. The LBG algorithm is known to be slow for high-resolution data [S3]. PCA-based splitting improves speed [S1].
*   **Memory Complexity:** Storage is $O(K \cdot n + N \cdot r)$, where $r$ is the bit-depth of the index [S1, S2]. This is significantly smaller than storing $N \cdot n$ original vectors if $K \ll N$ [S1, S2].
*   **Measured Performance:** Can achieve ~100x storage reduction for Volumetric Radiance Fields (NeRF grids) with competitive rendering quality [S2]. For time-varying data, it exploits high spatial and temporal redundancy [S1].
*   **Strengths:** High compression ratio for data with similar sub-blocks; simple decoding (texture lookup); portable to GPU via texture mapping [S1, S2].
*   **Limitations:** Lossy compression; sensitive to codebook size; original LBG is slow and prone to empty cells; accumulated error in temporal sequences requires I-frames [S1, S3].
*   **When to Use:** Large volumetric datasets with high redundancy (spatial or temporal); real-time rendering on GPUs where decoding speed is critical [S1, S2].
*   **When Not to Use:** Data with low redundancy; applications requiring lossless compression (unless data is highly sparse and identical) [S1].

## Background
Vector Quantization was developed in the context of speech and image compression, with the Linde-Buzo-Gray (LBG) algorithm introduced in 1980, improving upon scalar quantizers by Max (1960) and Lloyd (1982) [S3]. In volume rendering, it was adapted to handle large time-varying volumetric data, leveraging the high spatial and temporal redundancy of such datasets [S1]. Early implementations faced challenges with execution speed and the "empty cell" problem, leading to modifications such as PCA-based splitting [S1, S3]. More recently, VQ has been applied to compressing Volumetric Radiance Fields (NeRFs), achieving significant storage reductions [S2].
