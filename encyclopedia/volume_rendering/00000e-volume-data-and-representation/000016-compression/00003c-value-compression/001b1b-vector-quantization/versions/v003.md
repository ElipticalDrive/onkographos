# Vector Quantization

Also called: Cg decoding module, Codebook-based compression, Fixed-to-fixed compression, GPU-based Vector Quantization Decoding, Improved vector quantizer, LBG algorithm modification, Vector Quantization for Color Features

## Overview
Vector Quantization (VQ) is a lossy data compression algorithm that maps a set of $n$-dimensional input vectors to a single fixed-length index referencing an entry in an $n$-dimensional codebook [S1, S3]. It solves the problem of storing large volumes of high-dimensional data, such as voxel color features or time-varying volumetric blocks, by exploiting redundancy [S2]. Instead of storing every vector individually, it stores a compact codebook and a mapping index for each data element [S1, S2]. The method is characterized as a fixed-to-fixed compression algorithm [S1].

## How it works
**Inputs:** An $n$-dimensional vector $\vec{x}$ [S3]. For GPU decoding, inputs are compressed indices and the codebook [S1, S2].
**Outputs:** A single index $j$ referencing a codebook entry $\vec{c}_j$ [S3].

**Data Structures:**
1. **Codebook ($C$):** A set of $K = 2^r$ codewords, each of dimension $n$ [S1, S3]. Stored in memory or as a 3D texture on the GPU [S1, S2].
2. **Index Map:** For each input vector, an $r$-bit integer index $j$ pointing to the closest codeword in $C$ [S1, S2].

**Algorithm Steps:**
1. **Codebook Initialization:** Generate an initial set of $K$ codewords [S3]. Random selection or Principal Component Analysis (PCA) splitting can be used to avoid empty cells and speed up compression [S1, S3].
2. **Assignment (Partitioning):** For each input vector $\vec{x}_i$, find the codeword $\vec{c}_j$ in $C$ that minimizes the distortion metric $\delta(\vec{x}_i, \vec{c}_j)$ [S3]. The standard metric is squared Euclidean distance: $\delta(\vec{x}, \vec{y}) = \|\vec{x} - \vec{y}\|^2_2$ [S3]. Assign $\vec{x}_i$ to partition $p_j$ [S1].
3. **Codebook Update:** Recalculate each codeword $\vec{c}_j$ as the centroid of vectors in $p_j$ [G]. If a partition is empty (the "empty cell problem"), re-initialize or merge it to prevent increased distortion and execution time [S1, S3].
4. **Convergence Check:** Compute average distortion $D_{avg} = \frac{1}{N} \sum_{i=1}^N \|\vec{x}_i - \vec{c}_{j_i}\|^2_2$ [S1, S3]. Iterate until distortion stabilizes or a maximum iteration count is reached [G].

**GPU Decoding Implementation (Cg/GL):**
Decoding on a GPU using Cg requires handling float coordinates and missing bitwise/shift operations [S1]:
1. **Coordinate Mapping:** Map integer voxel coordinates $(x, y, z)$ to float texture coordinates in $[-1.0, 1.0]$ by dividing by $(D_x - 1)$, $(D_y - 1)$, or $(D_z - 1)$ and subtracting $1.0$ [S1].
2. **Simulate Integer Division:** To compute $\lfloor x/4 \rfloor$ without shifts, use `GL_NEAREST` texture filtering [S1]. Map integers $4, 5, 6, 7$ to texture coordinates that sample the same texel [S1]. The transformation for texture $I$ uses:
   $$ x' = (x \cdot 0.5 + 0.5) \cdot \frac{D_x - 1}{\frac{D_x - 4}{D_y - 1}} - \frac{2 D_x - 8}{3} $$
   $$ y' = (y \cdot 0.5 + 0.5) \cdot \frac{D_y - 4}{\frac{D_y - 1}{D_z - 1}} - \frac{2 D_y - 8}{3} $$
   $$ z' = (z \cdot 0.5 + 0.5) \cdot \frac{D_z - 1}{D_z - 4} - \frac{2 D_z - 8}{3} $$
   where $D(x,y,z) = \{2^n \mid n \ge 3\}$ [S1]. Clamp results to $[0.0, 1.0]$ using `GL_CLAMP` if outside bounds [S1].
3. **Address Texture Sampling:** Use a $4^3$ address texture (Texture A) to retrieve block-specific weights [S1]. Texture coordinates are:
   $$ x_A = (x \cdot 0.5 + 0.5) \cdot \frac{D_x}{4}, \quad y_A = (y \cdot 0.5 + 0.5) \cdot \frac{D_y}{4}, \quad z_A = (z \cdot 0.5 + 0.5) \cdot \frac{D_z}{4} $$
   Use `GL_REPEAT` to handle coordinates exceeding texture bounds [S1].
4. **Reconstruction:** Combine sampled weights with codebook lookups [S1]. For time-varying data, add decompressed difference data (P-frames) to previously reconstructed volumetric data [S1]. Reset accumulated error by transferring original data as I-frames periodically [S1].

**Parameters:**
*   **Index Bit-size ($r$):** Determines codebook size $K=2^r$ [S1]. A typical value is 8 bits, controlling the compression quality/distortion trade-off [S1].
*   **Dimension ($n$):** Dimensionality of input vectors (e.g., 3 for RGB color) [S3].

**Edge Cases and Pitfalls:**
*   **Empty Cells:** Iterative algorithms like LBG can produce empty partitions, increasing distortion and execution time [S1, S3]. PCA-based splitting avoids this automatically [S1, S3].
*   **Accumulated Error:** Repeatedly adding difference data in time-varying sequences causes error growth [S1]. Mitigated by periodic I-frame transfers [S1].
*   **GPU Limitations:** Cg lacks bitwise/shift operations and uses float coordinates [S1]. Integer coordinates must be mapped to float ranges, and border conditions must be clamped [S1].

**Pseudocode (Python-like decoding transformation):**
```python
def decode_voxel(x, y, z, Dx, Dy, Dz, codebook, address_texture):
    # 1. Coordinate mapping to [-1.0, 1.0]
    x_norm = x / (Dx - 1) - 1.0
    y_norm = y / (Dy - 1) - 1.0
    z_norm = z / (Dz - 1) - 1.0
    # 2. Simulate floor(x/4) via GL_NEAREST texture filtering
    x_prime = (x * 0.5 + 0.5) * (Dx - 1) / ((Dx - 4) / (Dy - 1)) - (2 * Dx - 8) / 3
    y_prime = (y * 0.5 + 0.5) * (Dy - 4) / ((Dy - 1) / (Dz - 1)) - (2 * Dy - 8) / 3
    z_prime = (z * 0.5 + 0.5) * (Dz - 1) / (Dz - 4) - (2 * Dz - 8) / 3
    # Clamp to [0.0, 1.0]
    x_prime = max(0.0, min(1.0, x_prime))
    y_prime = max(0.0, min(1.0, y_prime))
    z_prime = max(0.0, min(1.0, z_prime))
    # 3. Address texture sampling with GL_REPEAT
    x_A = (x * 0.5 + 0.5) * (Dx / 4)
    y_A = (y * 0.5 + 0.5) * (Dy / 4)
    z_A = (z * 0.5 + 0.5) * (Dz / 4)
    # 4. Reconstruction (simplified lookup)
    index = lookup_index(x_prime, y_prime, z_prime)
    return codebook[index]
```

## Subtopics

### [Progressive Encoding of Time-Varying Sequences](959-progressive-encoding-of-time-varying-sequences.md)
A scheme for encoding time-varying volumetric data where frames are encoded individually but reuse codebooks from previous frames to improve performance and compression.

## Operating characteristics
*   **Time Complexity:** Encoding (codebook generation) is iterative and can be slow, especially with the LBG algorithm [S3]. Decoding is $O(1)$ per vector (index lookup), making it suitable for real-time rendering [S1].
*   **Memory Complexity:** Storage is $O(K \cdot n + N)$, where $K$ is codebook size, $n$ is vector dimension, and $N$ is the number of input vectors (stored as indices) [S2]. This is significantly smaller than storing $N \cdot n$ raw vectors [S2].
*   **Performance:** High compression ratios are achieved for data with high spatial or temporal redundancy (e.g., highly sparse data or time-varying sequences) [S1].
*   **Strengths:** Fast decoding; effective for high-dimensional data; portable via texture-based GPU implementation [S1].
*   **Limitations:** Lossy compression; encoding can be slow; sensitive to the "empty cell problem" in naive implementations; requires careful handling of GPU coordinate systems [S1, S3].
*   **When to use:** Large time-varying volumetric data, highly sparse volumetric data, or compressing color features in neural radiance fields [S1, S2].
*   **When not to use:** Not suitable for lossless compression, as the method is inherently lossy [S1]. Encoding speed can be a bottleneck for real-time applications due to iterative codebook optimization [S3].

## Background
Vector Quantization was developed for volumetric texture compression and hardware accelerated texture decoding in computer graphics applications [S3]. The Linde-Buzo-Gray (LBG) algorithm was introduced in 1980 by Linde, Buzo, and Gray, improving upon scalar quantizers by Max (1960) and Lloyd (1982) [S3]. In volume rendering, it was adapted to handle large volumetric datasets by exploiting spatial and temporal redundancy [S1]. Recent applications include compressing Volumetric Radiance Fields (NeRFs) to reduce storage by approximately 100× [S2].
