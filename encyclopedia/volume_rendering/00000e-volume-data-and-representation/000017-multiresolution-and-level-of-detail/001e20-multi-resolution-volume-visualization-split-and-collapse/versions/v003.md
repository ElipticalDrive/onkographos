# Multi-Resolution Volume Visualization (Split-and-Collapse)

Also called: Split-and-Collapse

## Overview
Multi-Resolution Volume Visualization (Split-and-Collapse) is an interactive volume rendering method that dynamically adjusts the spatial resolution of different volume regions to fit within available hardware memory constraints [S1, unofficial]. It solves the problem of rendering large volumetric datasets interactively by applying a greedy algorithm that selects between refinement (split) and reduction (collapse) operations based on an error metric [S1, unofficial]. Unlike static level-of-detail approaches, it continuously updates the multi-resolution representation frame-to-frame to accommodate changes in viewpoint or region of interest [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A high-resolution volumetric dataset, hardware memory constraints (e.g., GPU memory capacity), and a current view state (camera position, region of interest) [S1, unofficial].
*   **Output:** A multi-resolution representation of the volume, rendered as an image using either GPU-based ray casting or viewport-aligned planes with pre-integrated classification [S1, unofficial].

**Data Structures:**
The volume is decomposed into subvolumes or bricks, where each brick maintains a current resolution level [S1, unofficial]. The structure supports out-of-core techniques compatible with the memory page demands of the algorithm [S1, unofficial].

**Algorithm Steps:**
1.  **Error Measurement:** Calculate an error metric for each volume area (brick) that quantifies the approximation quality at the current resolution [S1, unofficial].
2.  **Greedy Selection:** Use a greedy algorithm to select the next refinement (split) or collapse (reduce) operation [S1, unofficial]. The selection is based on which operation provides the greatest improvement in multi-resolution approximation relative to the error metric, while respecting hardware memory constraints [S1, unofficial].
3.  **Operation Execution:** Apply the selected split or collapse operation to the chosen brick [S1, unofficial].
4.  **Optimization Verification:** An optimal polynomial algorithm can be used to compute the multi-resolution representation with minimum error, primarily to verify that the greedy algorithm's results are near-optimal [S1, unofficial].
5.  **Rendering:** Render the current multi-resolution representation [S1, unofficial]. Acceleration techniques include empty space skipping, early ray termination, and adaptive sampling [S1, unofficial]. Ray segments are adjusted appropriately at subvolume or brick boundaries [S1, unofficial].

**Formulas and Parameters:**

*   The specific polynomial algorithm for the optimal solution is not detailed in the sources [S1, unofficial].
*   Typical parameters include the memory limit, base resolution, and minimum resolution, which are not explicitly quantified in the sources [S1, unofficial].

    # Decompose volume into bricks and initialize with base resolution
    bricks = []
    for region in decompose_volume_into_bricks(volume_data):
        bricks.append({
            'region': region,
            'resolution': base_resolution,
            'data': load_voxel_data(region, base_resolution)
        })

    while True:
        # 1. Calculate error metric for each brick based on current view and resolution
        errors = []
        for brick in bricks:
            errors.append(compute_approximation_error(brick['data'], brick['resolution'], view_state))

        # 2. Calculate current memory usage and available budget
        current_memory = sum(brick['resolution'] ** 3 for brick in bricks)
        available_memory = memory_limit - current_memory

        # 3. Greedy selection: find operation (split/collapse) maximizing error improvement within budget
        best_op = None
        best_gain = -1
        for i, brick in enumerate(bricks):
            # Try split
            if available_memory >= brick['resolution'] ** 3:
                gain_split = compute_error_improvement(brick, 'split')
                if gain_split > best_gain:
                    best_gain = gain_split
                    best_op = ('split', i)
            # Try collapse
            if brick['resolution'] > min_resolution:
                gain_collapse = compute_error_improvement(brick, 'collapse')
                if gain_collapse > best_gain:
                    best_gain = gain_collapse
                    best_op = ('collapse', i)

        if best_op is not None:
            op_type, idx = best_op
            if op_type == 'split':
                bricks[idx]['resolution'] *= 2
                bricks[idx]['data'] = upsample_voxel_data(bricks[idx]['data'])
            else:
                bricks[idx]['resolution'] //= 2
                bricks[idx]['data'] = downsample_voxel_data(bricks[idx]['data'])

        # 4. Render current multi-resolution representation
        image = render_bricks(bricks, view_state)

**Edge Cases and Pitfalls:**
*   **Memory Bandwidth:** Limited bandwidth between main memory and GPU may prevent satisfying the required resolution across all volume areas during interaction [S1, unofficial].
*   **LOD Artifacts:** Artifacts may appear between bricks with different levels of detail in GPU ray casting [S1, unofficial]. A technique based on weighted blending of adjacent LOD bricks is used to reduce these artifacts [S1, unofficial].

## Subtopics

### Greedy vs. Optimal Selection
The method uses a greedy algorithm for real-time performance but validates it against a polynomial optimal algorithm [S1, unofficial].

### Rendering Backends
Supports both GPU-based ray casting and viewport-aligned planes with pre-integrated classification [S1, unofficial].
