# Out-of-Core GPU-Accelerated Multi-Resolution Rendering Framework


## Overview
This framework provides an out-of-core rendering pipeline for large-scale volumetric datasets, managing data movement between storage, system RAM, and GPU VRAM [S1, unofficial]. It builds on [Adaptive-FAM](8156-adaptive-fam.md) by utilizing its micro-models to enable multi-resolution visualization, where the level of detail is selected based on the viewer's distance to the data [S1, unofficial]. The system explicitly handles disk-to-RAM transfer latency through dedicated caching and prefetching procedures [S1, unofficial].

## How it works
The framework executes three main procedures: Caching, Prefetching, and Rendering [S1, unofficial]. The rendering procedure executes on the GPU, while Caching and Prefetching manage data loading on the CPU [S1, unofficial].

### Inputs and Outputs
*   **Input:** A sequence of Points of View (POVs) $POV_n$; a large-scale volumetric dataset stored on disk; Adaptive-FAM encoded micro-models [S1, unofficial].
*   **Output:** A rendered 2D image for each POV [S1, unofficial].
*   **Data Types:** All volumetric data uses `float32` [S1, unofficial]. Transfer functions map scalar values to Color and Opacity [S1, unofficial].

### Data Structures
*   **Micro-model Cache:** A fixed-size Least Recently Used (LRU) cache stored in system RAM. The experimental setup fixes this size at 200 micro-blocks [S1, unofficial].
*   **LOD Selection:** A bipartite strategy partitions micro-blocks into four Levels of Detail (LODs) based on the distance $d$ from the POV to the micro-block centroid [S1, unofficial]. The distance ranges are: LOD 0: $[0, 0.8]$, LOD 1: $[0.8, 1.6]$, LOD 2: $[1.6, 2.4]$, LOD 3: $[2.4, \infty]$ [S1, unofficial].

### Rendering Procedure (GPU)
The rendering uses direct volume rendering (DVR) with ray casting as an example visualization task [S1, unofficial]. It queries values and gradients directly from the Adaptive-FAM micro-models resident in GPU VRAM [S1, unofficial].

**Pseudocode:**

```python
def render(visible_micro_models, row_start, row_end, col_start, col_end, sample_first, sample_last):
    rendering_done = False
    O_max = 1.0
    for i in range(row_start, row_end + 1):
        for j in range(col_start, col_end + 1):
            color = [0.0, 0.0, 0.0, 0.0]
            O_cumulative = 0.0
            for s in range(sample_first, sample_last + 1):
                x, y, z = get_sample_location(s)
                v = value_micro_model(x, y, z)
                apply_tf(color, v)
                gx, gy, gz = gradient_micro_model(x, y, z)
                c_diffuse, c_specular = light_coefficient(gx, gy, gz)
                add_shading(color, c_diffuse, c_specular)
                O_cumulative = do_color_compositing(color, O_cumulative)
                if O_cumulative > O_max:
                    break
            set_pixel_color(i, j, color)
    rendering_done = True
```

### Caching Procedure (CPU)
Caching utilizes spatial locality to decrease micro-model movement frequency across the memory hierarchy [S1, unofficial].

**Pseudocode:**

```python
def cache_update(current_pov, cache, storage, cache_size):
    vec_vm = find_visible_micro_models(current_pov)
    for m in vec_vm:
        if m in cache:
            continue
        else:
            if len(cache) < cache_size:
                cache.load(m, storage)
            else:
                lru_micro = cache.get_lru()
                cache.replace(lru_micro, m, storage)
    cache.copy_to_gpu()
```

### Prefetching Procedure (CPU)
Prefetching predicts visible micro-models for the next POV to hide storage latency [S1, unofficial]. It runs on a separate CPU thread and is preempted when rendering finishes [S1, unofficial].

**Pseudocode:**

```python
def prefetch_next_pov(predictor, cache, storage, cache_size, rendering_done_flag):
    while not rendering_done_flag:
        next_pov = predictor.predict()
        vec_vm_next = find_visible_micro_models(next_pov)
        for m in vec_vm_next:
            if m not in cache:
                if len(cache) < cache_size:
                    cache.load(m, storage)
                else:
                    lru_micro = cache.get_lru()
                    cache.replace(lru_micro, m, storage)
```

### Parameters
*   **Cache Size:** 200 micro-blocks [S1, unofficial].
*   **LOD Ranges:** $[0, 0.8], [0.8, 1.6], [1.6, 2.4], [2.4, \infty]$ [S1, unofficial].
*   **Prefetching Algorithms:** APPA (predicts parent POV), ForeCache (predicts next POV based on user behavior), or LSTM (predicts next POV based on historical data) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Prefetch Preemption:** The prefetching thread must check for rendering completion to avoid wasting I/O bandwidth on data that will not be used [S1, unofficial].
*   **Storage Latency:** The framework is designed to handle high-latency storage, such as a 5400 RPM HDD, to simulate worst-case data movement latency [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** System RAM usage is fixed by the cache size (200 micro-blocks in experiments) [S1, unofficial]. GPU VRAM usage depends on the number of visible micro-blocks [S1, unofficial].
*   **Performance:** Tested on an NVIDIA GTX 1080 Ti (8GB VRAM) with an Intel Core i7-7700K CPU and 16GB DDR4 RAM [S1, unofficial]. The method demonstrates effectiveness in interactive visualization of large-scale datasets by mitigating the bottleneck of data movement from storage to RAM [S1, unofficial].

## Background
The framework was introduced in the paper "Adaptive Multi-Resolution Encoding for Interactive Large-Scale Volume Visualization through Functional Approximation" [S1, unofficial]. It extends the Adaptive-FAM encoding method, which uses micro-blocks and functional approximation to compress volumetric data [S1, unofficial]. The work addresses the challenge of visualizing large-scale volumes (e.g., micro-CT scans, fluid simulations) that exceed GPU memory capacity [S1, unofficial].
