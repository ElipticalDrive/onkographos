# Adaptive-FAM

Also called: Adaptive Functional Approximation Multi-resolution, Adaptive functional approximation multi-resolution encoding, Adaptive-FAM Encoding Pipeline

## Overview
Adaptive-FAM is a multi-resolution encoding pipeline designed for the interactive, out-of-core visualization of large-scale volumetric datasets [S1, unofficial]. It partitions input data into blocks, downsamples them into micro-blocks, and encodes each micro-block into a compact "micro-model" using functional approximation with dynamically optimized Normalized Control Points (NCPs) [S1, unofficial]. Unlike its sibling [Wavelet-based Volume Rendering](1052-wavelet-based-volume-rendering.md) which relies on frequency decomposition, Adaptive-FAM uses spatial partitioning and adaptive compression to minimize model size and I/O latency [S1, unofficial]. It is specifically optimized to reduce caching time and input latency in out-of-core rendering frameworks by avoiding the decompression overhead associated with traditional compressors like ZFP or SZ3 [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volumetric dataset of resolution $n^3$.
*   **Output:** A collection of micro-models, one for each micro-block across all Levels of Detail (LOD), optimized for a specified error bound.

**Data Structures:**
*   **Micro-block:** A downsampled sub-region of the original data partition.
*   **Micro-model:** A functional approximation representation of a micro-block. It is defined by a set of Normalized Control Points (NCPs). The size of the micro-model is determined by the number of NCPs used.
*   **Error Map:** A lookup structure mapping each valid NCP value to its corresponding reconstruction error for a specific micro-block.

**Parameters:**
*   **Error Bound ($e$):** The maximum allowable reconstruction error for a micro-block. [S1, unofficial]
*   **NCP Range:** Valid NCP values are integers in the range $[degree + 1, n]$, where $n$ is the resolution of the micro-block. [S1, unofficial]
*   **Sample Distance:** Used for quality evaluation (e.g., 0.000025). [S1, unofficial]
*   **Cache Size:** Fixed at 200 micro-blocks for the rendering pipeline. [S1, unofficial]

**Algorithm Steps:**

1.  **Partitioning:** Partition the input 3D dataset of resolution $n^3$ into blocks for each LOD level. To ensure C0 continuity between neighboring blocks, share exactly one sample point on the boundary in each of the x, y, and z directions. [S1, unofficial]
2.  **Downsampling:** Downsample each partitioned block into micro-blocks according to the resolution requirement of each LOD. [S1, unofficial]
3.  **Adaptive Encoding:** For each micro-block, encode it into a micro-model using the adaptive encoding pipeline. This involves two strategies:
    *   **In-level Adaptive Encoding:** Determine the optimal NCP for the micro-block.
    *   **Cross-level Adaptive Encoding:** (Details not provided in sources, but noted as part of the pipeline). [S1, unofficial]

**In-level Adaptive Encoding Procedure:**
For a specific micro-block with resolution $n^3$ and a required error bound $e$:

1.  Initialize an empty map `ErrorMap`.
2.  Iterate through all valid NCP values $k$ from $degree + 1$ to $n$:
    a. Construct a functional approximation model for the micro-block using $k$ NCPs.
    b. Calculate the reconstruction error $E_k$ between the original micro-block data and the model.
    c. Store the pair $(k, E_k)$ in `ErrorMap`.
3.  Find the optimal NCP $NCP^*$ that minimizes the NCP count while satisfying the error bound:
    $$ NCP^* = \arg \min_{k \in \text{keys}(\text{ErrorMap})} \{ k \mid \text{ErrorMap}[k] < e \} $$
4.  Encode the micro-block into a micro-model using $NCP^*$ control points. [S1, unofficial]

**Pseudocode:**

```python
def adaptive_encode_micro_block(micro_block_data, degree, error_bound):
    """
    Encodes a micro-block into a micro-model using adaptive NCP selection.
    
    Args:
        micro_block_data: 3D array of voxel values for the micro-block.
        degree: Degree of the functional approximation basis.
        error_bound: Maximum allowable reconstruction error (e).
        
    Returns:
        micro_model: The encoded micro-model (represented by NCPs).
        ncp_count: The number of NCPs used.
    """
    n = micro_block_data.shape[0] # Assuming cubic micro-block
    valid_ncp_range = range(degree + 1, n + 1)
    
    error_map = {}
    
    # In-level adaptive encoding: exhaustive search for optimal NCP
    for k in valid_ncp_range:
        # Construct model with k NCPs
        # Note: The specific functional approximation algorithm (e.g., NURBS, B-spline) 
        # is not detailed in the sources, but it maps k NCPs to the data.
        model = construct_functional_approximation(micro_block_data, k)
        
        # Calculate reconstruction error
        # This involves evaluating the model at sample points and comparing to original data
        error = calculate_reconstruction_error(micro_block_data, model)
        
        error_map[k] = error
        
    # Find optimal NCP* that satisfies error bound with minimum count
    ncp_star = None
    for k in sorted(error_map.keys()):
        if error_map[k] < error_bound:
            ncp_star = k
            break
            
    if ncp_star is None:
        # Fallback if no NCP satisfies the bound (edge case)
        # Sources do not specify fallback behavior. [G]
        ncp_star = degree + 1 
        
    # Encode final micro-model with optimal NCP
    final_model = construct_functional_approximation(micro_block_data, ncp_star)
    
    return final_model, ncp_star
```

**Edge Cases and Pitfalls:**
*   **Highly Dynamic Data:** The benefit of Adaptive-FAM's encoding time reduction is reduced when input dataset values are highly dynamic throughout the entire volumetric space. [S1, unofficial]
*   **Aggressive Compression:** When the average compression ratio exceeds 40, Adaptive-FAM's rendering accuracy falls behind traditional compressors like SZ3 and TTHRESH. [S1, unofficial]
*   **Boundary Artifacts:** Unlike traditional compressors (ZFP, SZ3), Adaptive-FAM avoids boundary artifacts because it does not rely on inaccurate reconstruction of boundary samples in the same way; it shares samples explicitly for C0 continuity. [S1, unofficial]

## Operating characteristics
**Time and Memory Complexity:**
*   **Encoding Time:** Adaptive-FAM is significantly faster than the baseline FAM method. For example, on the Branch dataset, FAM took 18.29 hours while Adaptive-FAM took 2.26 hours [S1, unofficial]. On the Rotstrat dataset, FAM took 292.68 hours while Adaptive-FAM took 172.16 hours [S1, unofficial].
*   **Model Size:** Adaptive-FAM produces much smaller models than FAM. For the ML dataset, FAM required 7.7GB while Adaptive-FAM required 232MB [S1, unofficial].
*   **Caching Time:** Due to smaller model sizes, Adaptive-FAM has significantly shorter caching times than FAM and traditional compressors, which is the primary bottleneck in out-of-core rendering. [S1, unofficial]
*   **Rendering Time:** Rendering time is faster than FAM due to fewer average NCPs. It scales sub-linearly with NCP for querying. [S1, unofficial]

**Measured Performance:**
*   **Hardware:** Tested on NVIDIA GTX 1080 Ti GPU (8GB VRAM), Intel Core i7-7700K CPU, 16GB DDR4 RAM, 4TB HDD (5400 RPM). [S1, unofficial]
*   **Compression Ratios:** Typical compression ratios range from 15.71 to 35.31 for the tested datasets. [S1, unofficial]
*   **Accuracy:** Adaptive-FAM achieves similar rendering accuracy to FAM. It produces fewer artifacts than ZFP, SZ3, and TTHRESH at similar compression ratios (~20). It provides the best rendering accuracy when the average compression ratio is less than 40. [S1, unofficial]

**Strengths and Limitations:**
*   **Strengths:**
    *   Significantly reduced input latency due to smaller model sizes and no decompression overhead. [S1, unofficial]
    *   Better cache miss rate reduction with prefetching algorithms compared to FAM. [S1, unofficial]
    *   Avoids boundary artifacts common in other compressors. [S1, unofficial]
    *   Faster than Down Sampling (DS) for large-scale datasets (except Flame). [S1, unofficial]
*   **Limitations:**
    *   Accuracy degrades compared to SZ3/TTHRESH at compression ratios > 40. [S1, unofficial]
    *   Encoding time benefits diminish for highly dynamic data. [S1, unofficial]
    *   DS is slightly faster on the Flame dataset. [S1, unofficial]

**When to Use:**
*   Use Adaptive-FAM for interactive, out-of-core visualization of large-scale volumetric datasets where input latency and caching time are critical bottlenecks. [S1, unofficial]
*   Use when compression ratios are moderate (< 40) and high rendering accuracy is required without boundary artifacts. [S1, unofficial]

**When Not to Use:**
*   Avoid if extremely high compression ratios (> 40) are required and maximum accuracy is prioritized over latency. [S1, unofficial]
*   Avoid if the dataset is highly dynamic throughout the entire volume, as encoding benefits are reduced. [S1, unofficial]

## Background
Adaptive-FAM was proposed to address the impractical encoding times of traditional Functional Approximation Multi-resolution (FAM) methods for large-scale datasets. It builds on the FAM representation but introduces adaptive encoding to dynamically compress micro-blocks based on their content. The method is designed to integrate with GPU-accelerated out-of-core rendering frameworks to improve input latency. [S1, unofficial]
