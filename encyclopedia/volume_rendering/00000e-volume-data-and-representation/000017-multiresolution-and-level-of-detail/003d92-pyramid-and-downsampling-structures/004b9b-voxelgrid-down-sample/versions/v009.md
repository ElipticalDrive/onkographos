# VoxelGrid Down Sample


## Overview
VoxelGrid Down Sample reduces the resolution of a voxel grid or point cloud by aggregating data into a coarser spatial structure. It solves the problem of managing memory and computational load in volume rendering by creating lower-resolution representations of high-density data. It differs from its siblings by offering two distinct operational modes: spatial aggregation via max-pooling for scalar fields [S1, unofficial] and point-cloud-to-voxel center extraction for geometric representations [S2, unofficial]. Unlike [Mipmap Generation](2602-mipmap-generation.md) which typically uses interpolation, this method often employs max-pooling or direct occupancy marking, preserving extreme values or geometric presence rather than averages.

## How it works
The method operates in two primary variants depending on the input data type: scalar voxel grids and point clouds.

### Inputs and Outputs
*   **Scalar Grid Variant**:
    *   Input: A 3D tensor `data` of shape $(N_x, N_y, N_z)$ and an integer downsampling `factor`.
    *   Output: A 3D tensor `new_data` of shape $(N_x/factor, N_y/factor, N_z/factor)$.
*   **Point Cloud Variant**:
    *   Input: A tensor `points` of shape $(N, D)$ containing coordinates, a `resolution` (float, voxel size), and optional `range_per_dim` (bounds).
    *   Output: A tensor `pts` containing the coordinates of the centers of occupied voxels in the downsampled grid.

### Data Structures
*   **VoxelGrid**: A sparse or dense representation defined by `resolution`, `range_per_dim` (min/max bounds per axis), and a data buffer (e.g., `torch.bool` for occupancy or float for values).
*   **Block**: A sub-volume of size $factor \times factor \times factor$ in the original grid.

### Steps: Scalar Grid (Max-Pooling)
1.  **Validate Divisibility**: Check if the input dimensions are divisible by `factor`. If `resolution % factor != 0` (referring to dimension size in source [S1, unofficial]), raise an error. [S1, unofficial]
2.  **Block Reduction**: Divide the input grid into non-overlapping blocks of size $factor \times factor \times factor$.
3.  **Aggregation**: For each block, compute the maximum value among all voxels in that block.
    $$ V_{new}(i, j, k) = \max_{u,v,w \in \text{block}} V_{old}(i \cdot factor + u, j \cdot factor + v, k \cdot factor + w) $$
4.  **Construct Output**: Assemble the aggregated values into the new, smaller grid.
5.  **Return**: Return the new `VoxelGrid` with the same logical location and scale properties as the input, but with reduced resolution. [S1, unofficial]

### Steps: Point Cloud (Occupancy Center Extraction)
1.  **Handle Empty Input**: If `points.shape[0] == 0`, return empty points. [S2, unofficial]
2.  **Determine Bounds**: Calculate `data_bounds` as:
    $$ \text{min} = \min(\text{points}) - 2 \cdot \text{resolution} $$
    $$ \text{max} = \max(\text{points}) + 2 \cdot \text{resolution} $$
    If `range_per_dim` is `None` or does not contain `data_bounds`, set `range_per_dim = data_bounds`. [S2, unofficial]
3.  **Handle Flat Dimension**: If `ignore_flat_dim` is `True` and the z-range is flat (`range_per_dim[-1][0] == range_per_dim[-1][1]`):
    *   Set `flat_z = True`.
    *   Store `flat_z_val = range_per_dim[-1][0]`.
    *   Remove the last dimension from `range_per_dim` and `points` (project to 2D).
4.  **Create Grid and Mark**:
    *   Create a `VoxelGrid` with the specified `resolution` and `range_per_dim`.
    *   Initialize the grid with `dtype=torch.bool` (or appropriate type).
    *   Map each point to its voxel index and set the corresponding voxel to `1` (occupied). [S2, unofficial]
5.  **Retrieve Centers**: Call `voxel.get_known_pos_and_values()` to extract the coordinates of the centers of all occupied voxels. Let this result be `pts`. [S2, unofficial]
6.  **Restore Flat Dimension**: If `flat_z` was `True`, append a column of ones multiplied by `flat_z_val` to `pts` along the last dimension to restore 3D coordinates. [S2, unofficial]

### Pseudocode (Point Cloud Variant)
```python
def voxel_down_sample(points, resolution, range_per_dim=None, ignore_flat_dim=False):
    # 1. Handle empty input
    if points.shape[0] == 0:
        return points

    # 2. Determine bounds if not provided
    if range_per_dim is None:
        min_pts = points.min(dim=0)[0]
        max_pts = points.max(dim=0)[0]
        data_bounds = (min_pts - 2 * resolution, max_pts + 2 * resolution)
        range_per_dim = data_bounds
    else:
        # Check if range_per_dim contains data_bounds
        # Note: Source implies a check, but exact logic for "contains" is implementation-specific.
        # We assume range_per_dim is valid if provided.
        pass

    # 3. Handle flat dimension
    flat_z = False
    flat_z_val = 0.0
    if ignore_flat_dim:
        z_min, z_max = range_per_dim[-1]
        if z_min == z_max:
            flat_z = True
            flat_z_val = z_min
            # Remove last dim from range_per_dim and points
            range_per_dim = range_per_dim[:-1]
            points = points[..., :-1]

    # 4. Create grid and mark occupied voxels
    # Assuming a helper class VoxelGrid exists which maps coordinates to indices
    grid = VoxelGrid(resolution=resolution, range_per_dim=range_per_dim, dtype=torch.bool)
    
    # Map points to voxel indices and set occupancy
    # This step assumes grid.set_occupancy(points) or similar internal logic
    # that converts continuous coordinates to discrete voxel indices based on resolution and bounds.
    grid.set_occupancy(points)

    # 5. Retrieve centers of occupied voxels
    pts = grid.get_known_pos_and_values()

    # 6. Restore flat dimension
    if flat_z:
        # Append column of ones * flat_z_val
        ones_col = torch.ones(pts.shape[0], 1, device=pts.device) * flat_z_val
        pts = torch.cat([pts, ones_col], dim=-1)

    return pts
```

### Parameters
*   **points**: $N \times D$ tensor of point cloud coordinates. [S2, unofficial]
*   **resolution**: Float, the size of a single voxel. [S2, unofficial]
*   **range_per_dim**: Optional array of bounds (min, max) per dimension. If `None`, determined by points' min/max $\pm 2 \times \text{resolution}$. [S2, unofficial]
*   **factor**: Integer, the downsampling factor (e.g., 2, 4). Used in scalar grid variant. [S1, unofficial]
*   **ignore_flat_dim**: Boolean, whether to handle degenerate 2D data embedded in 3D space. [S2, unofficial]

### Edge Cases and Pitfalls
*   **Divisibility**: The scalar grid variant requires input dimensions to be divisible by the downsampling factor. Failure to check this leads to index errors or truncated data. [S1, unofficial]
*   **Empty Input**: Point cloud variant must handle $N=0$ explicitly to avoid division by zero or empty tensor operations. [S2, unofficial]
*   **Flat Dimensions**: In 3D point clouds with constant Z, failing to handle the flat dimension can lead to incorrect voxel indexing or wasted memory. [S2, unofficial]
*   **Memory Usage**: The point cloud variant processes all points in parallel to mark the grid, which uses more memory than iterative approaches but is faster. [S2, unofficial]

## Subtopics

### [Volume Resampling and Overflow Guard](1772-volume-resampling-and-overflow-guard.md)
This method resamples a candidate volume grid to a target shape while enforcing a maximum voxel count to prevent downstream memory overflow. It differs from sibling methods by combining a strict safety cap with precise trilinear interpolation and a fallback dimension-decrement mechanism to guarantee reduction even when rounding constraints interfere.

### [Grid Deformation](5372-grid-deformation.md)
Grid Deformation is a preprocessing technique applied prior to data reduction in volume rendering compression. It transforms the input data grid according to user-defined regions to better preserve salient features during subsequent downsampling. It is an orthogonal approach to hierarchical models like wavelets, reporting improved visual results compared to pure downsampling and wavelet-based methods.

### [Optimization-based Downsampling](5825-optimization-based-downsampling.md)
Optimization-based downsampling reduces the resolution of microflake volumes by iteratively optimizing scattering parameters so that the rendered appearance of the lower-resolution level of detail matches a high-resolution reference. It solves the problem of geometric aliasing and shadowing artifacts in aggregated microgeometry, distinguishing itself from naive averaging or simple SGGX approximation by explicitly accounting for shadowing effects through image-space error minimization.

### [Pre-processing for Half Resolution](6436-pre-processing-for-half-resolution.md)
This method constructs a half-resolution volumetric representation from a full-resolution input to reduce data size while preserving visual quality and avoiding the information loss associated with direct subsampling. It operates directly in the spatial domain using a specific odd-index subsampling pattern and local median replacement to fill transparent regions.

### Max-Pooling Layer
A layer that applies a max filter to non-overlapping sub-regions of the input to downsample the input and reduce parameters in subsequent encoder layers. Contains no trainable parameters. Filter Size: 2x2. Stride: 2. Applied in layers with input channels 64, 32, and 8. [S3, unofficial]

## Operating characteristics
*   **Time Complexity**:
    *   Scalar Grid: $O(N)$ where $N$ is the number of input voxels, as each voxel is visited once.
    *   Point Cloud: $O(N)$ for marking the grid, where $N$ is the number of points. Grid creation is proportional to the volume of the bounding box.
*   **Memory Complexity**:
    *   Scalar Grid: $O(N / factor^3)$ for the output.
    *   Point Cloud: $O(V)$ where $V$ is the number of voxels in the bounding box, which can be significantly larger than $N$ if the point cloud is sparse. [S2, unofficial]
*   **Performance**: The point cloud implementation is noted to be faster than Open3D's implementation but uses more memory by processing all points in parallel. [S2, unofficial]
*   **Strengths**: Simple to implement; max-pooling preserves high-intensity features (e.g., emissive voxels); parallelizable.
*   **Limitations**: Max-pooling discards low-intensity information; point cloud variant memory usage scales with bounding box volume, not point count; requires divisibility for scalar grids.

## Background
The concept of voxel downsampling is fundamental in multiresolution volume rendering and 3D computer vision. The specific implementation using max-pooling for scalar grids is common in deep learning architectures for volumetric data, such as autoencoders for compressed volume rendering [S3, unofficial]. The point cloud to voxel center extraction method is prevalent in robotics and 3D perception libraries (e.g., PyTorch Volumetric structures) for efficient collision checking and SDF representation [S2, unofficial]. The method is often a precursor to more complex multiresolution structures like octrees or mipmaps.
