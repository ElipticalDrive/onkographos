# Volume Resampling to Isotropic Spacing

Also called: isotropic resampling, spacing normalization

## Overview
This method resamples a volume with arbitrary anisotropic voxel spacing into a new volume where all axes share a single, uniform spacing value [S1, unofficial]. It solves the problem of inconsistent physical scales across axes, which complicates downstream operations like filtering or rendering that assume uniform grid metrics [G]. Unlike [Area-Averaged Resampling](3142-area-averaged-resampling.md), which focuses on preserving integrated intensity during downsampling, this method strictly enforces geometric isotropy by calculating output dimensions based on physical extent rather than simple integer division of voxel counts [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A `VolumeData` object containing spatial dimensions, per-axis spacing, origin, direction matrix, and a voxel buffer [S1, unofficial].
*   **Output:** A new `VolumeData` object with isotropic spacing and recalculated dimensions [S1, unofficial].

**Data Structures:**
The input `VolumeData` layout contains `width`, `height`, `depth` (`size_t`), `spacingX`, `spacingY`, `spacingZ` (`float`), `voxels` (`std::vector<float>`), and `SpatialGeometry` with `origin` (`float[3]`) and `direction` (`float[9]`) [S1, unofficial].

**Parameters:**
*   `kTargetSpacing`: `float`. The desired uniform voxel spacing for the output volume, typically `1.0F` [S1, unofficial].

**Steps:**
1.  **Validation:** If any input dimension is zero, or if any spacing value is non-finite or zero, throw `std::invalid_argument` [S1, unofficial].
2.  **Physical Extent Calculation:** For each axis $i \in \{x, y, z\}$, calculate the physical extent of the volume: $\text{extent}_i = (\text{inputSize}_i - 1) \times \text{inputSpacing}_i$ [S1, unofficial].
3.  **Output Dimension Calculation:** Compute the number of voxels required to cover this extent at the target isotropic spacing: $\text{outputSize}_i = \max(1, \text{round}(\frac{\text{extent}_i}{\text{kTargetSpacing}}) + 1)$ [S1, unofficial]. The `+ 1` accounts for the fact that $N$ voxels span $N-1$ intervals [G]. The `max(1, ...)` ensures the output dimension is at least 1, even if the physical extent is zero or negative due to precision issues [S1, unofficial].
4.  **Overflow Check:** Verify that the calculated output dimensions do not cause integer overflow when used to allocate memory or index buffers, using checked multiplication [S1, unofficial].
5.  **Resampling:** Convert the input `VolumeData` to an `ITK Image<float, 3>` by setting the region, spacing, origin, direction, and copying the voxel buffer into the ITK image buffer [S1, unofficial]. Perform the resampling using the library's resampler [G]. Map the resampled `ITK Image` back to `VolumeData` by extracting size, spacing, origin, direction, and copying the buffer into a `std::vector<float>` [S1, unofficial].
6.  **Output Construction:** Create the new `VolumeData` object with the calculated `outputSize` values, `kTargetSpacing` for all axes, the original `origin` and `direction`, and the resampled voxel buffer [S1, unofficial].

**Pitfalls:**
*   Zero input dimensions or non-finite/zero spacing throws `std::invalid_argument` [S1, unofficial].
*   Voxel count mismatch between calculated dimensions and actual data throws `std::invalid_argument` [S1, unofficial].
*   Integer overflow during dimension multiplication is caught by `checkedMultiply` [S1, unofficial].

    height: int
    depth: int

    spacingY: float
    spacingZ: float

    # 1. Validation
    if volume.width == 0 or volume.height == 0 or volume.depth == 0:
        raise ValueError("Input dimensions must be non-zero")
    for s in [volume.spacingX, volume.spacingY, volume.spacingZ]:
        if not math.isfinite(s) or s == 0:
            raise ValueError("Spacing must be finite and non-zero")

    # 2. Calculate output dimensions
    output_sizes = []
    for inp_size, inp_spacing in zip([volume.width, volume.height, volume.depth],
                                     [volume.spacingX, volume.spacingY, volume.spacingZ]):
        extent = (inp_size - 1) * inp_spacing
        raw_size = round(extent / target_spacing) + 1
        output_size = max(1, raw_size)
        output_sizes.append(output_size)

    # [G] Placeholder for overflow check logic

    # 4. Resampling
    # Convert input VolumeData to ITK Image<float, 3> by setting region, spacing, origin, direction,
    # and copying the voxel buffer [S1, unofficial].
    # Perform resampling using the library's resampler [G].
    # Map the resampled ITK image back to VolumeData by extracting size, spacing, origin, direction,
    # and copying the buffer into a std::vector<float> [S1, unofficial].

## Subtopics

### Area-Averaged Resampling
Focuses on preserving the integral of the volume data during downsampling, often used for creating mipmaps [G]. Choose this when maintaining energy/intensity conservation is critical, rather than strict geometric isotropy [G]. [Link](3142-area-averaged-resampling.md)

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of input and output voxels, $O(N_{in} + N_{out})$, assuming the underlying resampling library uses linear or nearest-neighbor interpolation [G]. Higher-order interpolators increase the constant factor [G].
*   **Memory Complexity:** $O(N_{out})$ for the output buffer. The input buffer is retained during the process [G].
*   **Strengths:** Guarantees uniform voxel spacing, which simplifies subsequent processing steps like Fourier transforms or uniform grid-based rendering [G].
*   **Limitations:** The output dimensions are determined by physical extent, which may result in a significantly larger or smaller voxel count than the input, potentially leading to high memory usage or loss of detail if the target spacing is very small [G].
*   **When to use:** When downstream algorithms require isotropic voxels (e.g., certain medical imaging analyses, isotropic rendering) [G].
*   **When not to use:** When preserving the exact original voxel count or aspect ratio is more important than geometric uniformity [G].

## Background
This method is implemented in the `qt-viewer-pro` project, specifically within the `ItkVolumeConverter` and volume loading modules [S1, unofficial]. It leverages the Insight Toolkit (ITK) for robust image processing and geometry handling [S1, unofficial]. The approach reflects standard practices in medical image processing where anisotropic scans (common in MRI/CT) are resampled to isotropic grids for visualization and analysis [G].
