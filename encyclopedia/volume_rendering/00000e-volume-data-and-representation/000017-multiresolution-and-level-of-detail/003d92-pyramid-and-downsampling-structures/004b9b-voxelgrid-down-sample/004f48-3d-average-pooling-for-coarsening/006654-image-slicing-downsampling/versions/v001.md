# Image Slicing & Downsampling

Also called: 2D Slice Extraction and Coarsening, Data Downsampling and Visualization Enhancements, Slicing and Downsampling

## Overview
This method extracts 2D planar slices from 3D volumetric data and reduces spatial resolution to enable visualization on systems with limited memory or rendering capabilities [S1, S2, unofficial]. It serves as a lightweight alternative to full 3D volume rendering, allowing for the inspection of scalar fields and RGBA modalities (such as bathymetry) on commodity hardware [S2, unofficial]. Unlike the parent method [3D Average Pooling for Coarsening](13934-3d-average-pooling-for-coarsening.md), which coarsens the entire 3D dataset, this approach operates on 2D projections or subsets, significantly reducing the data volume for terminal plotting or 2D visualization tools [S1, S2, unofficial].

## How it works
**Inputs:**
- A 3D volume $V$ of dimensions $D_x \times D_y \times D_z$ with scalar or RGBA values.
- Target 2D resolution $R_{target} = (W_{target}, H_{target})$.
- Slicing axis $A \in \{x, y, z\}$ and slice index $s$.

**Outputs:**
- A 2D image $I$ of size $W_{target} \times H_{target}$.

**Data Structures:**
- The input volume is typically stored in a contiguous array or a distributed partition (e.g., `tpt::volume<3_D, T>` in TPT) [S1, unofficial].
- The output is a 2D image structure (e.g., `tpt::image<2_D, T>`) [S1, unofficial].

**Steps:**

1. **Slice Extraction:**
   Iterate over the two axes not equal to $A$. For each coordinate pair $(u, v)$ in the remaining dimensions, map the 3D index to the 2D image coordinate.
   - If slicing along $z$ (extracting $xy$ plane): $I(u, v) = V(u, v, s)$ [S1, unofficial].
   - If slicing along $y$ (extracting $xz$ plane): $I(u, v) = V(u, s, v)$ [S1, unofficial].
   - If slicing along $x$ (extracting $yz$ plane): $I(u, v) = V(s, u, v)$ [S1, unofficial].
   
   In distributed implementations, data is gathered from partitions. For a center slice at index $c_k$ along axis $k$, the local contribution is sent to the owner process [S1, unofficial]. The owner reconstructs the 2D slice by aggregating these contributions into a `tpt::image<2_D, T>` buffer [S1, unofficial].

2. **Downsampling (Coarsening):**
   If the extracted slice resolution $(W_{src}, H_{src})$ exceeds $R_{target}$, downsample the image. Two methods are cited:
   
   *Method A: Strided Sampling*
   Compute stride $S = \lfloor \frac{W_{src}}{W_{target}} \rfloor$ (and similarly for height). Sample the source image at intervals defined by the stride [S1, unofficial].
   
   *Method B: Accumulation (Box Filter)*
   Accumulate scaled values into target cells. For each target cell $(cx, cy)$, sum the source values $f(i, j)$ that map to it, weighted by a scale factor [S1, unofficial].
   $$ g(cx, cy) = \sum_{i, j \in \text{cell}(cx, cy)} f(i, j) \times \text{scale} $$
   where $\text{scale} = \frac{W_{target}}{W_{src}}$ [S1, unofficial]. Note: The source text specifies `scale = new_size[0] / f.size(0)`, which implies a normalization factor to preserve intensity or density depending on interpretation [S1, unofficial].

3. **Visualization Overlay (Optional):**
   For scientific datasets (e.g., oceanography), overlay auxiliary data onto the first slice or RGBA views [S2, unofficial]:
   - Transparent coastline maps [S2, unofficial].
   - Longitude/Latitude grids and time stamps [S2, unofficial].
   - Bathymetry as an RGBA modality [S2, unofficial].

**Pseudocode:**

```python
def extract_and_downsample(volume_3d, slice_axis, slice_idx, target_width, target_height):
    """
    Extract a 2D slice from a 3D volume and downsample it.
    volume_3d: 3D array/list of lists of lists, shape (Dx, Dy, Dz)
    slice_axis: 0 for x, 1 for y, 2 for z
    slice_idx: integer index along the slice axis
    target_width, target_height: desired output dimensions
    """
    # 1. Extract Slice
    if slice_axis == 0:
        # Extract YZ plane at x = slice_idx
        slice_2d = [[volume_3d[slice_idx][y][z] for z in range(len(volume_3d[0][0]))] 
                    for y in range(len(volume_3d[0]))]
        src_h, src_w = len(slice_2d), len(slice_2d[0])
    elif slice_axis == 1:
        # Extract XZ plane at y = slice_idx
        slice_2d = [[volume_3d[x][slice_idx][z] for z in range(len(volume_3d[0][0]))] 
                    for x in range(len(volume_3d))]
        src_h, src_w = len(slice_2d), len(slice_2d[0])
    else: # slice_axis == 2
        # Extract XY plane at z = slice_idx
        slice_2d = [[volume_3d[x][y][slice_idx] for y in range(len(volume_3d[0]))] 
                    for x in range(len(volume_3d))]
        src_h, src_w = len(slice_2d), len(slice_2d[0])

    # 2. Downsample using Accumulation (Box Filter)
    # Calculate scale factors
    scale_x = target_width / src_w
    scale_y = target_height / src_h
    
    # Initialize output image
    output_image = [[0.0 for _ in range(target_width)] for _ in range(target_height)]
    
    # Accumulate values
    for y in range(src_h):
        for x in range(src_w):
            # Map source pixel to target cell
            # Using floor to determine target cell index
            ty = int(y * scale_y)
            tx = int(x * scale_x)
            
            # Ensure bounds
            if ty < target_height and tx < target_width:
                output_image[ty][tx] += slice_2d[y][x] * scale_x * scale_y
                
    return output_image
```

**Edge Cases:**
- **Boundary Conditions:** When mapping source coordinates to target cells, ensure indices do not exceed bounds [S1, unofficial].
- **Precision:** Accumulation may lead to overflow if not scaled properly; the scale factor helps normalize [S1, unofficial].
- **Degenerate Input:** If `target_width` or `target_height` is 0, the operation is undefined.

## Operating characteristics
- **Time Complexity:** $O(W_{src} \cdot H_{src})$ for extraction and downsampling.
- **Memory Complexity:** $O(W_{src} \cdot H_{src})$ for the slice buffer, significantly less than the full 3D volume $O(D_x \cdot D_y \cdot D_z)$ [S1, S2, unofficial].
- **Performance:** Enables visualization of large datasets (e.g., year-long animations) on desktop systems that cannot load full-resolution 3D data [S2, unofficial].
- **Strengths:** Simple to implement, low memory footprint, suitable for 2D visualization tools and terminal plotting [S1, S2, unofficial].
- **Limitations:** Loses 3D context; not suitable for complex internal structures that require volume rendering [S2, unofficial].

## Background
This technique was developed to address the limitations of desktop systems in handling large scalar datasets and animations, particularly in oceanographic research [S2, unofficial]. It was used in conjunction with the VIRVO visualization system to allow researchers to view data on commodity PCs without special software installations [S2, unofficial]. The method was also implemented in the TPT (Tensor Processing Toolkit) for distributed volume processing [S1, unofficial].
