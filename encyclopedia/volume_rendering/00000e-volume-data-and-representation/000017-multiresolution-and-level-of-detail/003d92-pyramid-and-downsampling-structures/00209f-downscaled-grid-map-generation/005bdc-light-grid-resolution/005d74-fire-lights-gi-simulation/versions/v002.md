# Fire Lights (GI Simulation)
Also called: Fire Light Simulation, Light Grid Lighting, emLightsCountEnbl
## Overview
Fire Lights simulates Global Illumination (GI) by placing light sources in the bright parts of a fire simulation, allowing the fire to illuminate scene objects and the simulator's own smoke without the performance cost of full GI calculation [S1]. It serves as a faster alternative to native GI, though it creates additional light sources that persist even if GI is enabled [S1].
## How it works
**Inputs and Outputs:**
*   **Input:** Fire simulation data (emissive intensity/brightness per cell) [S1].
*   **Output:** A set of light sources positioned within the fire volume, contributing to the scene's illumination [S1].

**Data Structures:**
The method generates a collection of light objects [S1]. The position of each light corresponds to a "bright part" of the fire grid [S1]. The specific algorithm for selecting these parts is not detailed in the sources.

**Steps:**
1.  Analyze the fire simulation grid to identify bright regions [S1].
2.  Place light sources in these bright regions [S1].
3.  Adjust the color and power of these lights automatically based on the fire's properties [S1].
4.  Apply intensity multipliers: multiply intensity for illumination over the simulator's own smoke by `emLightsPowerOnSelfMult`, and multiply intensity for illumination over all other scene objects by `emLightsPowerMult` [S1].
5.  If `emLightsSelfShadow` is enabled: if `Ray-traced`, the simulator's smoke obstructs the path of light from the fire's light sources; if `Grid-based`, use grid-based approximation; if `None`, smoke will not obstruct light propagation and will be brightly lit [S1].
6.  If `emLightsCaustSubdivs` is set, use this value for caustic sampling when caustics are calculated [S1].
7.  If `emLightsPersist` is enabled, generate lights even if the fire simulator is disabled for rendering [S1].

**Parameters:**
*   `emLightsCountEnbl` (Create Fire Lights): Boolean. When enabled, activates the simulation of GI via light placement [S1].
*   `emLightsPowerOnSelfMult` (Light Power on Self): Float. Controls the light intensity over the simulator's own smoke, without changing the intensity or color of the fire itself [S1].
*   `emLightsPowerMult` (Light Power on Scene): Float. Controls the light intensity over all scene objects except the Phoenix Simulator itself [S1].
*   `emLightsSelfShadow` (Self Shadowing): Enum. Controls smoke obstruction of light. Options: `None`, `Ray-traced`, `Grid-based` [S1].
*   `emLightsCaustSubdivs` (Caustic Subdivs): Integer. Sampling control for caustic effects, used when caustics are calculated [S1].
*   `emLightsPersist` (Create Lights Even If Not Renderable): Boolean. Forces the simulator to emit light over the scene even if rendering the simulator itself is disabled [S1].

**Edge Cases and Pitfalls:**
*   **V-Ray GPU:** All Fire Lights options are ignored when rendering with V-Ray GPU; Global Illumination must be enabled in V-Ray Settings for smoke or scene illumination in this mode [S1].
*   **GI Conflict:** If `emLightsCountEnbl` is enabled while rendering with GI, additional light sources are still created by the fire at render time, which may cause double illumination or performance issues; disable `emLightsCountEnbl` if natural GI illumination is desired [S1].
*   **V-Ray Object Properties:** The `Generate GI` and `Receive GI` options from V-Ray Object Properties are ignored while `emLightsCountEnbl` is enabled [S1].
*   **Performance:** Enabling Self Shadowing decreases rendering performance; to regain speed, set Self Shadowing to Grid-based and decrease the Light Grid Resolution parameter to reduce the number of generated lights [S1].

## Subtopics

### Fire Lights
When enabled (`emLightsPersist`), this feature forces the simulator to emit light over the scene even if the simulator itself is disabled for rendering, which is primarily used for compositing scenarios where the fire simulation is rendered in a separate pass [S1].

## Operating characteristics
*   **Performance:** Rendering is much faster than using Global Illumination (GI) [S1]. However, enabling Self Shadowing decreases performance, particularly with Ray-traced shadowing [S1].
*   **Quality:** Produces similar illumination results to GI but relies on direct light placement rather than full light transport simulation [S1].
*   **Limitations:** Does not work with V-Ray GPU rendering [S1]. Can conflict with native GI if both are enabled [S1].
*   **Scaling:** Performance can be improved by reducing the Light Grid Resolution, which reduces the number of generated lights [S1].

## Background
This method is part of the Phoenix for Maya Voxel Shader, developed by Chaos Group [S1]. It provides a workaround for the high computational cost of Global Illumination in fire simulations, specifically tailored for the Phoenix Simulator environment [S1].
