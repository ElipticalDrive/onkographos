# Downscaled Grid Map Generation


## Overview
Generates a grid map for a downscaled resolution and an index map to map high-resolution coordinates to low-resolution coordinates [S1, unofficial]. It differs from sibling methods like [VoxelGrid Down Sample](1014-voxelgrid-down-sample.md) by explicitly constructing coordinate mappings rather than just aggregating values, and from [Index-Based Upsampling with Recalibration](2352-index-based-upsampling-with-recalibration.md) by focusing on the generation of the downsampled coordinate space itself [S1, unofficial].

## How it works
**Inputs:**
- Original grid map dimensions: $H_{orig}, W_{orig}$ (height and width).
- Scale factor: $s$ (downsampling ratio).
- Stride: $stride$ (spatial step size of the original grid, often 1 for normalized coordinates).

**Outputs:**
- `grid_map`: A tensor of shape $(H_{new}, W_{new}, 2)$ containing scaled coordinates.
- `index_map`: A tensor of shape $(H_{new}, W_{new})$ containing integer indices mapping to the original grid.

**Data Structures:**
- `grid_map`: Float tensor. Each element $(i, j)$ holds the scaled 2D coordinate.
- `index_map`: Integer tensor. Each element $(i, j)$ holds the index into the flattened original grid.

**Steps:**
1. Calculate the stride of the original grid map.
2. Compute new height and width by dividing original dimensions by scale and taking the ceiling:
   $$ H_{new} = \lceil H_{orig} / s \rceil $$
   $$ W_{new} = \lceil W_{orig} / s \rceil $$
3. Generate a new meshgrid for the downscaled resolution. Let $i \in [0, H_{new}-1]$ and $j \in [0, W_{new}-1]$.
4. Scale the new grid map by `scale * stride` and shift it by `((scale * stride) - 1) / 2`.
   $$ grid\_map[i, j, 0] = (i \cdot s \cdot stride + \frac{s \cdot stride - 1}{2}) $$
   $$ grid\_map[i, j, 1] = (j \cdot s \cdot stride + \frac{s \cdot stride - 1}{2}) $$
5. Compute the index map by dividing the original grid mesh coordinates by scale, adding 1, taking the ceiling, and subtracting 1.
   $$ index\_map[i, j] = \lceil \frac{grid\_map[i, j, 0]}{s} \rceil + \lceil \frac{grid\_map[i, j, 1]}{s} \rceil - 1 $$
   *Note: The source description "dividing the original grid mesh coordinates by scale" implies using the unscaled or base coordinates. However, given the context of mapping high-res to low-res, this step likely maps the low-res grid points back to high-res indices. A more standard interpretation for an index map from low to high is mapping low-res coordinates to high-res indices. The source text is ambiguous on whether "original grid mesh coordinates" refers to the input high-res coordinates or the generated low-res coordinates. Given the output is an index map to map high-resolution coordinates to low-resolution, the index map usually stores the high-res index for each low-res pixel. Let's re-read carefully: "index map to map high-resolution coordinates to low-resolution coordinates". This phrasing is tricky. Usually, an index map maps *destination* (low-res) to *source* (high-res). If it maps high to low, it would be a lookup table for high-res pixels. However, the calculation $\lceil \dots \rceil - 1$ suggests mapping a coordinate to an integer bin. Let's stick to the literal steps provided.*

    return grid_map, index_map

**Parameters:**
- `scale`: Typical value depends on the desired downsampling factor (e.g., 2 for 2x downsampling).
- `stride`: Typically 1.0 for normalized coordinates.

**Edge Cases and Pitfalls:**
- If the maximum index in the flattened index map exceeds the number of elements in the new grid map, a `ValueError` is raised [S1, unofficial]. This can happen if the ceiling operation pushes indices out of bounds due to rounding or scale factors.

## Subtopics

### [Index-Based Upsampling with Recalibration](2352-index-based-upsampling-with-recalibration.md)
Upsamples low-resolution tensors to high resolution by gathering values via an index map and scaling them with a recalibration map, specifically designed for depth values. It differs from sibling methods like Depth-Aware Upsampling by relying on explicit index and scaling tensors rather than depth-weighted interpolation.

## Operating characteristics
- **Time Complexity:** $O(H_{new} \cdot W_{new})$ for generating the grid map and index map.
- **Memory Complexity:** $O(H_{new} \cdot W_{new})$ for storing the grid map and index map.
- **Strengths:** Provides explicit coordinate mappings which can be useful for differentiable rendering or precise upsampling.
- **Limitations:** The method is specific to the coordinate generation and does not handle value aggregation. The pitfall regarding index bounds requires careful handling of scale factors and grid dimensions.
