# Streaming MIP Implementation (Basic)

Also called: Streaming MIP

## Overview
Streaming MIP is a multiresolution volume rendering technique that constructs a progressive coefficient stream from a morphological pyramid to allow interactive frame rates on large datasets that do not fit in GPU memory [S1]. It solves the problem of discrete quality jumps in level-by-level rendering by resorting detail coefficients from all pyramid levels simultaneously based on decreasing magnitude of an error measure, providing near-continuous error control [S1]. It sets itself apart from basic texture-based MIP by storing only necessary voxels and from level-by-level MMIP by offering finer granularity in approximation error control [S1].

## How it works
**Inputs:** A morphological pyramid of detail coefficients $\{d_j(x, y, z)\}$ sorted by decreasing magnitude of an error measure (typically L1-error reduction) [S1].
**Outputs:** A rendered image approximating the Maximum Intensity Projection (MIP) of the volume [S1].

**Data Structures:**
The implementation requires storing detail coefficients with specific attributes to support level-dependent dilation [S1].
*   **Position Attribute:** 4 bytes. Contains the spatial coordinates $(x, y, z)$ and the originating pyramid level $j$ encoded in the lower two bits [S1].
*   **Intensity Attribute:** 2 bytes (short) [S1]. Stores the voxel intensity value [S1].
*   **Total Size:** 6 bytes per voxel [S1].

**Algorithm Steps:**
1.  **Preprocessing:** Construct the morphological pyramid and sort all detail coefficients $\{d_j\}$ by decreasing error magnitude [S1].
2.  **Initialization:** Initialize the frame buffer (or output texture) with the minimum possible intensity value (e.g., 0 or background) [G].
3.  **Iteration:** Iterate through the sorted list of coefficients [S1]. For each coefficient $k$ with value $val$ and pyramid level $j$:
    a.  **Projection:** Project the coefficient to 2D screen coordinates $(sx, sy)$ using a standard view transformation [G].
    b.  **Local Dilation:** Determine the dilation neighborhood based on level $j$ [S1]. For a square $2 \times 2$ structuring element, the point size is $2^j$ (e.g., size 1 at level 0, size 2 at level 1, size 4 at level 2) [S1].
    c.  **Update:** For all pixels in the dilated neighborhood around $(sx, sy)$:
        i.   Compare the coefficient value $val$ with the current frame buffer value $curval$ at that pixel [S1].
        ii.  If $curval < val$, overwrite $curval$ with $val$ [S1].
    d.  **Termination:** Stop when a maximum number of coefficients is projected or a desired accuracy threshold is met [S1].

**Pseudocode:**
```python
def streaming_mip_basic(coefficients, frame_buffer):
    """
    coefficients: List of tuples (level, intensity, x, y, z), sorted by error magnitude descending.
    frame_buffer: 2D numpy array initialized to minimum value.
    """
    for level, intensity, x, y, z in coefficients:
        # Orthographic projection assumed [G]
        sx, sy = x, y
        
        # Dilation size follows the 2^j rule for a 2x2 structuring element [S1]
        dilation_size = 2 ** level
        half = dilation_size // 2
        
        # Calculate inclusive bounds for a square of side `dilation_size` centered at (sx, sy)
        min_x = max(0, int(sx) - half)
        max_x = min(frame_buffer.shape[1], int(sx) + half + 1)
        min_y = max(0, int(sy) - half)
        max_y = min(frame_buffer.shape[0], int(sy) + half + 1)
        
        # Update frame buffer with maximum operator
        for py in range(min_y, max_y):
            for px in range(min_x, max_x):
                if frame_buffer[py, px] < intensity:
                    frame_buffer[py, px] = intensity
```

**Parameters:**
*   **Structuring Element:** Typically a square $2 \times 2$ element [S1].
*   **Point Size:** Mapped to hardware point size extension (PSIZE in Cg) to implement dilation [S1].
*   **Point Sprite:** Used if the projection of the structuring element is not square [S1].

**Edge Cases and Pitfalls:**
*   **Global Dilation:** Cannot be used because the scale index varies per coefficient, unlike level-by-level projection where the scale is constant per level [S1].
*   **Performance:** Voxels are no longer ordered by intensity, requiring writes to the frame buffer to use the maximum operator (blended primitives), causing some performance loss compared to ordered alpha blending [S1].
*   **Memory:** The 6-byte overhead per voxel increases memory usage compared to standard 4-byte representations [S1].

## Subtopics

### [Streaming MIP Construction](1815-streaming-mip-construction.md)
A multiresolution volume rendering technique that constructs a progressive coefficient stream from a morphological pyramid to allow interactive frame rates on large datasets that do not fit in GPU memory. It sets itself apart from basic texture-based MIP by storing only necessary voxels and from level-by-level MMIP by offering finer granularity in approximation error control. Choose it when near-continuous error control and interactive performance on out-of-core volumes are required.

### [Block Inspection (Streamed)](6010-block-inspection-streamed.md)
Enables interactive, high-resolution inspection of a specific region within a streamed, multi-resolution volume dataset. It distinguishes itself from [Streaming MIP Construction](1815-streaming-mip-construction.md) by focusing on interactive point-picking rather than pre-computed aggregation, and from [Conical MImP](7656-conical-mimp.md) by using a standard cropped volume view rather than a conical projection. Choose it when interactive point-picking in a specific sub-region is needed.

### [Conical MImP](7656-conical-mimp.md)
A maximum importance projection technique that corrects the spatial ambiguity of cylindrical MImP by using a conical clipping frustum instead of a cylindrical one. While standard MImP renders only the object with the highest importance along a ray and hides all others, the cylindrical variant creates a "cut-away" view where the focus object appears to float in front of the context object without depth cues. Choose it when depth cues and spatial relationships between focus and context objects are required.

### [Sparse Volume Texture Mip Mapping](7955-sparse-volume-texture-mip-mapping.md)
Provides level-of-detail (LOD) management for sparse volume data by allowing sample nodes to request specific resolution levels, similar to standard 2D texture sampling. It differs from its parent [Streaming MIP Implementation (Basic)](1803-streaming-mip-implementation-basic.md) by explicitly exposing the `MipLevel` input pin on the sample node, but unlike [Conical MImP](7656-conical-mimp.md) or [Spread-space MIP chain with luminance weighting](9093-spread-space-mip-chain-with-luminance-weighting.md), it relies entirely on the engine's streaming system to load the requested level rather than computing or weighting the mip chain dynamically during sampling. Choose it for sparse volumes requiring engine-driven LOD streaming.

### [Spread-space MIP chain with luminance weighting](9093-spread-space-mip-chain-with-luminance-weighting.md)
Constructs a multi-resolution pyramid for scattering images by combining spatial blurring with a luminance-weighted auxiliary mask to prevent illumination leaking artifacts. It differs from its parent [Streaming MIP Implementation (Basic)](1803-streaming-mip-implementation-basic.md) by introducing a spreading width chain $\mathbf{W}$ and a luminance mask $\mathbf{Y}$ that modulate the Gaussian blur, ensuring that low-standard-deviation (sharp) pixels do not incorrectly propagate brightness to high MIP levels. Choose it for scattering images requiring illumination leak prevention.

### Optimized Streaming MIP
This variant avoids the drawbacks of the basic implementation (point sprites, frame buffer blending, 6-byte overhead) by using a histogram-based selection strategy [S1]. It uses only 4 bytes per voxel and avoids point sprites [S1]. The error-sorted list is used only to guide the error for speed/quality tradeoff, not strictly for rendering order [S1]. A second histogram-sorting step groups coefficients by (level, intensity) pairs, maintaining error ordering within bins [S1]. Rendering traverses the sorted list for a chosen percentage of coefficients, rendering voxels in low-to-high intensity order per level [S1].

### Advanced Algorithm with Mipmap Fallback
An approximation method where missing data at the needed resolution triggers a fallback to a higher mipmap level, resorting to iterative interrupt/resume only if no higher level is present or data is too coarse [S2, unofficial]. Fixing a budget for upload delivers a relatively stable frame rate [S2, unofficial].

### Center-Precomputed MIP Approximation
Reduces per-intersection cost compared to per-pixel Jacobian evaluation without visual loss in filtering quality [S3, unofficial]. Uses the formula $\rho_{\text{mip}}^2 = \Sigma_{uu}^{-1} u^2 + 2 \Sigma_{uv}^{-1} uv + \Sigma_{vv}^{-1} v^2$ and weight $w = n_f \cdot \exp(-0.5 \cdot \rho_{\text{mip}}^2)$ [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of coefficients projected [S1]. The method allows stopping early based on accuracy, providing variable rendering time [S1].
*   **Memory Complexity:** Requires storing the sorted list of detail coefficients [S1]. The basic implementation uses 6 bytes per voxel, while the optimized version uses 4 bytes [S1].
*   **Performance:** The basic implementation suffers from performance loss due to the need for the maximum operator in frame buffer writes and the use of point sprites [S1]. The optimized version improves performance by avoiding these drawbacks [S1].
*   **Strengths:** Provides near-continuous error control and interactive frame rates for large datasets that do not fit in GPU memory [S1].
*   **Limitations:** The basic implementation has higher memory overhead and performance costs due to blending and point sprites [S1].

## Background
Streaming MIP was introduced in the paper "Multiresolution MIP Rendering of Large Volumetric Data Accelerated on Graphics Hardware" [S1]. It builds on [Pyramid and Downsampling Structures](9527-pyramid-and-downsampling-structures.md).
