# Luminance Weighted MIP Map Filtering

Also called: Masking idea

## Overview
Luminance Weighted MIP Map Filtering is a technique to reduce illumination leaking artifacts in Gaussian MIP map blurring by using an auxiliary mask $\mathbb{M}$ to prevent low-standard-deviation pixels from propagating to high MIP levels [S1, unofficial]. It differs from its parent [Spread-space MIP chain with luminance weighting](9093-spread-space-mip-chain-with-luminance-weighting.md) by masking out low-$W$ pixels before blurring, preventing illumination leaking seen in naive MIP maps where bright low-$W$ objects leak into dark high-$W$ backgrounds [S1, unofficial].

## How it works
**Inputs:**
- $\mathbb{L}_{\text{sc}}^{[0]}$: Scattered radiance at base MIP level [S1, unofficial].
- $\mathbb{W}^{[0]}$: Spreading width at base level [S1, unofficial].
- $T$: Masking threshold distance [S1, unofficial].
- $\varepsilon$: Width control parameter for the smoothstep transition [S1, unofficial].
- $\mathcal{G}$: Discrete Gaussian filter kernel [S1, unofficial].

**Outputs:**
- $\mathbb{L}_{\text{sc}}^{[k]}$: Filtered radiance at MIP level $k$ [S1, unofficial].
- $\mathbb{M}^{[k]}$: Auxiliary mask at MIP level $k$ [S1, unofficial].

**Data Structures:**
- $\mathbb{L}_{\text{sc}}^{[k]}$, $\mathbb{W}^{[k]}$, $\mathbb{M}^{[k]}$: 2D textures/arrays of matching resolution for each MIP level $k$ [G].

**Steps:**
1. Initialize base level $k=0$ with input radiance $\mathbb{L}_{\text{sc}}^{[0]}$ and width $\mathbb{W}^{[0]}$ [G].
2. For each subsequent MIP level $k > 0$:
   a. Compute the mask $\mathbb{M}^{[k]}$ using the width from the previous level $\mathbb{W}^{[k-1]}$:
      $$ \mathbb{M}^{[k]} = \text{smoothstep}\left(T, (1 + \varepsilon) \cdot T, \mathbb{W}^{[k-1]}\right) $$
      where $\text{smoothstep}(e_1, e_2, x)$ returns $0$ for $x \le e_1$, $1$ for $x \ge e_2$, and interpolates smoothly between $e_1$ and $e_2$ otherwise [S1, unofficial].
   b. Apply the mask to the previous level's radiance:
      $$ \mathbb{L}_{\text{masked}} = \mathbb{M}^{[k]} \cdot \mathbb{L}_{\text{sc}}^{[k-1]} $$
   c. Convolve the masked radiance with the Gaussian filter $\mathcal{G}$ to produce the current level:
      $$ \mathbb{L}_{\text{sc}}^{[k]} = \mathbb{L}_{\text{masked}} * \mathcal{G} $$
      (Equation 4.19 in [S1, unofficial])

**Pseudocode:**
```python
def build_luminance_weighted_mip_chain(L_sc, W, T, epsilon, G_kernel):
    # L_sc: list of 2D arrays, L_sc[0] is base level radiance
    # W: list of 2D arrays, W[0] is base level spreading width
    # T: float, masking threshold
    # epsilon: float, transition width control
    # G_kernel: 2D array, discrete Gaussian filter
    mip_radiance = [L_sc[0]]
    mip_masks = []
    for k in range(1, len(L_sc)):
        e1 = T
        e2 = (1.0 + epsilon) * T
        M_k = smoothstep(e1, e2, W[k-1])
        mip_masks.append(M_k)
        L_masked = M_k * L_sc[k-1]

        # Implementation depends on kernel size and boundary handling. Not given in the sources.
        L_sc[k] = convolve_2d(L_masked, G_kernel)
        mip_radiance.append(L_sc[k])
    return mip_radiance, mip_masks

    return t * t * (3.0 - 2.0 * t)
```

**Parameters:**
- $T$: Masking threshold. Controls the distance/width below which pixels are suppressed [S1, unofficial].
- $\varepsilon$: Controls the width of the transition region in the smoothstep. Small positive values create a sharp cutoff; larger values create a softer transition [G].

**Edge Cases and Pitfalls:**
- If $\mathbb{W}^{[k-1]}$ is uniformly below $T$, the mask becomes zero, and the MIP level becomes black. This is intended behavior to prevent leaking [S1, unofficial].
- Precision issues may arise if $T$ is very small or $\varepsilon$ is extremely small, leading to binary masking rather than smooth weighting [G].
- The definition of $\mathbb{W}$ (spreading width) must be consistent with the parent method [Spread-space MIP chain with luminance weighting](9093-spread-space-mip-chain-with-luminance-weighting.md) [G].

## Subtopics

### [Gaussian Filtering with MIP Maps](9570-gaussian-filtering-with-mip-maps.md)
An efficient approximation for spatially varying Gaussian blurring using a MIP map pyramid, where each level is generated by convolving the previous level with a fixed Gaussian kernel, allowing logarithmic mapping of standard deviation to texture level. It differs from this method by providing the underlying blurring mechanism; this method adds a luminance-weighted mask to prevent illumination leaking artifacts that can occur when naively applying this blur to high-contrast scenes [G]. Choose this variant when the primary goal is spatially varying Gaussian blurring without explicit leakage suppression.

## Operating characteristics
- **Time Complexity:** Building each MIP level requires one mask computation (pixel-wise smoothstep) and one Gaussian convolution [G]. The convolution cost depends on kernel size [G]. Overall, linear in the number of pixels per level [G].
- **Memory Complexity:** Requires storing an additional mask texture $\mathbb{M}^{[k]}$ at each level, or recomputing it on the fly if memory is constrained [G].
- **Strengths:** Effectively prevents illumination leaking from bright, small objects (e.g., lanterns) into dark, large backgrounds, which is a common artifact in naive MIP map filtering [S1, unofficial].
- **Limitations:** Requires an auxiliary mask and an additional width/luminance texture. The choice of $T$ and $\varepsilon$ can affect visual quality and may require tuning [G].
- **When to use:** When using Gaussian MIP map blurring for real-time light transport or scattering, and illumination leaking artifacts are visible [S1, unofficial].
- **When not to use:** If the scene has uniform luminance or if the cost of maintaining the mask is prohibitive [G].

## Background
Originated in the context of real-time light transport in analytically integrable participating media [S1, unofficial]. The technique is attributed to Elek et al. [2013] and is described in the thesis "Real-Time Light Transport in Analytically Integrable Participating Media" [S1, unofficial]. It addresses the issue of sharp discontinuities and incorrect light leaking seen in naive MIP map filtering approaches [S1, unofficial].
