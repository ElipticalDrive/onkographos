# Streaming MIP Construction

Also called: Error-sorted Streaming MIP Construction, L1-error sorted Streaming MIP, MMIP, Multiresolution MIP, Streaming MIP

## Overview
Streaming MIP is a multiresolution volume rendering technique that constructs a progressive coefficient stream from a morphological pyramid to allow interactive frame rates on large datasets that do not fit in GPU memory [S1]. It solves the problem of discrete quality jumps in level-by-level rendering by resorting detail coefficients from all pyramid levels simultaneously based on decreasing magnitude of an error measure, providing near-continuous error control [S1]. It sets itself apart from basic texture-based MIP by storing only necessary voxels and from level-by-level MMIP by offering finer granularity in approximation error control [S1].

## How it works
**Inputs:** A volumetric dataset $V$ of dimensions $W \times H \times D$ [S1].
**Outputs:** A MIP image $M$ and a performance/quality trade-off determined by the number of projected coefficients [S1].

**Data Structures:**
1.  **Morphological Pyramid:** Constructed from $V$ using morphological operations [S1]. The implementation uses a three-level pyramid consisting of one approximation level $A_0$ and two detail levels $D_1, D_2$ [S1].
2.  **Coefficient Stream:** A sorted list of detail coefficients $\{d_j\}$ from all levels $D_1, D_2$ [S1].
3.  **Auxiliary Coefficients:** An intermediate set used for sorting, discarded after the stream is constructed [S1].
4.  **Render Target:** A framebuffer or image buffer initialized to the minimum intensity value (or background) for MIP accumulation [G].

**Parameters:**
*   **Pyramid Levels:** 3 levels (2 detail, 1 approximation) are used [S1].
*   **Error Measure:** L1 error. The relative L1-approximation error is defined as:
    $$ \varepsilon^{(j)} = \frac{\| \mathbf{M}^{(0)} - \mathbf{M}^{(j)} \|_1}{\| \mathbf{M}^{(0)} \|_1} $$
    where $\mathbf{M}^{(0)}$ is the original MIP image and $\mathbf{M}^{(j)}$ is the approximation after projecting $j$ coefficients [S1].
*   **Projection Type:** Parallel projection [S1].
*   **Non-axis-aligned projections:** Yield pixel-sized holes [S1].

**Steps:**

1.  **Construct Morphological Pyramid:**
    *   Apply morphological dilation and erosion operations to generate the pyramid levels [S1].
    *   Compute detail coefficients $D_k$ by subtracting the upsampled approximation of the next level from the current level (or via the specific morphological difference definition used in the source) [S1].
    *   *Note:* The exact morphological pyramid construction algorithm is referenced to [GH00] and [Roe05] but not detailed in the provided text [S1].

2.  **Construct Coefficient Stream:**
    *   Join all detail coefficients from all levels into a single set [S1].
    *   Create an **auxiliary set** of detail coefficients [S1].
    *   Sort the auxiliary set by decreasing magnitude (absolute value) of the coefficients [S1].
    *   **Resort** the original detail coefficients $\{d_j\}$ by assigning them the same order as the sorted auxiliary coefficients [S1].
    *   Discard the auxiliary coefficients [S1].
    *   *Rationale:* Directly sorting detail coefficients by magnitude is suboptimal because coefficients are not small in regions where the structuring element fits approximately but not exactly [S1]. The auxiliary sorting ensures that each successive coefficient maximally reduces the L1-error between the partial reconstruction and the original data [S1].

3.  **Rendering (Point-based Projection):**
    *   Initialize the render target [G].
    *   Iterate through the sorted coefficient stream $\{d_j\}$ [S1].
    *   For each coefficient $d_j$ at position $(x, y, z)$ with value $val$:
        *   Project the voxel at $(x, y, z)$ onto the image plane [S1].
        *   Update the pixel value at the projected location: $pixel = \max(pixel, val)$ [S1].
        *   *Implicit Empty Space Skipping:* Only non-empty voxels (those with non-zero detail coefficients or significant approximation values) are rendered [S1].
    *   Stop when a desired accuracy is reached or a maximum number of coefficients is projected [S1].

4.  **Post-processing (Optional):**
    *   For non-axis-aligned parallel projections, the voxel-based method may yield pixel-sized holes [S1].
    *   Apply a morphological closing operation using the structuring element $\tilde{A}$ used for synthesis to fill these holes [S1].

    # 1. Construct morphological pyramid via dilation/erosion [S1]
    # Note: Exact construction algorithm is not provided in the sources [S1]
    pyramid = volume  # Placeholder for pyramid structure [G]
    
    # 2. Join detail coefficients from all levels
    detail_coeffs = []
    for level in range(1, levels):
        for z in range(pyramid[level].shape[0]):
            for y in range(pyramid[level].shape[1]):
                for x in range(pyramid[level].shape[2]):
                    val = pyramid[level][z, y, x]
                    if val != 0:
                        detail_coeffs.append({'val': val, 'x': x, 'y': y, 'z': z, 'id': len(detail_coeffs)})
                        
    # 3. Create auxiliary set and sort by decreasing magnitude
    aux = list(detail_coeffs)
    aux.sort(key=lambda c: abs(c['val']), reverse=True)
    
    # 4. Resort original coefficients to match auxiliary order [S1]
    aux_order = {c['id']: i for i, c in enumerate(aux)}
    sorted_coeffs = sorted(detail_coeffs, key=lambda c: aux_order[c['id']])
    return sorted_coeffs

def streaming_mip_render(sorted_coeffs, width, height, view_matrix):
    # Initialize render target to minimum intensity [G]

**Edge Cases and Pitfalls:**
*   **Non-axis-aligned projections:** Yield pixel-sized holes. Requires post-processing morphological closing [S1].
*   **Pyramid Levels:** Using more than three levels decreases performance due to additional render, upsample, and dilation steps, and higher levels have little non-zero coefficients [S1].
*   **Precision:** The method trades image quality for performance. Median error of 7 grey levels is acceptable for preview mode [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of retained detail coefficients. Frame rate approximately doubles each time the number of detail coefficients is halved [S1].
*   **Memory Complexity:** Cache-efficient, addressing GPU memory in a linear way. Only necessary voxels are stored [S1].
*   **Performance:**
    *   **VisibleWoman (512x512x1734, 210M coeffs):**
        *   100% coeffs: 14 FPS, Median Error 0.
        *   1% coeffs: 51 FPS, Median Error 7 grey levels [S1].
    *   **XMasTree (512x512x512, 105M coeffs):**
        *   100% coeffs: 80 FPS.
        *   1% coeffs: 100 FPS, Median Error 25 grey levels [S1].
    *   **Comparison:**
        *   Streaming MIP (GPU) with L1 error 0.07 (median 4) achieves 18.4 FPS, compared to 1.1 FPS for Streaming MIP (GPU) with 0.0 error [S1].
        *   Streaming MIP (GPU) is about six times faster than the optimized software implementation given the same dataset and error bound [S1].
        *   Using two GeForce 7900GTX cards achieves a speed-up of almost a factor of two over a single card [S1].
*   **Strengths:**
    *   Interactive frame rates on large datasets [S1].
    *   Near-continuous error control.
    *   Cache-efficient memory access.
    *   Scalable to multiple GPUs [S1].
*   **Limitations:**
    *   Requires post-processing for non-axis-aligned projections [S1].
    *   Performance bound by vertex units on older GPU hardware (unified shaders improve this) [S1].
    *   Does not perform view-independent hidden voxel removal, which could theoretically yield a 2x speedup [S1].

## Background
The method is based on morphological pyramids [S1]. Reference [GH00] discusses multiresolution signal decomposition schemes including linear and morphological pyramids [S1]. The streaming MIP algorithm was introduced in [Roe05] to overcome the discrete quality jumps of level-by-level rendering [S1]. The GPU implementation and comparison with existing CPU and GPU techniques were presented in [S1].
