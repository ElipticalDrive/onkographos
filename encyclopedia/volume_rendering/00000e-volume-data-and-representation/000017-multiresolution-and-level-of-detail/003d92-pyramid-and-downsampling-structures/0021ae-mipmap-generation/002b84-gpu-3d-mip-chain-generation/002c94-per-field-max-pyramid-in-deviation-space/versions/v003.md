# Per-Field Max Pyramid in Deviation Space

Also called: deviation-space max pyramid, maxPyramidTexture

## Overview
A max-value pyramid stored in deviation space (normalized distance from contrast center) used for transfer-function-adaptive skipping during volume ray marching [S1, unofficial]. It is built from the raw volume cube, not the display mip chain, to avoid hiding thin bright filaments that might be smoothed out by box filtering [S1, unofficial]. Unlike standard mipmaps which store averaged or filtered values for display, this structure stores the maximum possible signal intensity relative to a threshold, enabling the renderer to skip empty or low-intensity regions dynamically based on live contrast settings [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Raw volume data cube ($D \times D \times D$), `contrastCenter` (scalar), `halfRange` (scalar) [S1, unofficial].
*   **Output:** A 3D texture mip chain (`maxPyramidTexture`) where each level $k$ stores the maximum deviation value for its corresponding spatial region [S1, unofficial].

**Data Structures:**
*   **FieldEntry:** Contains a new field `maxPyramidTexture` [S1, unofficial].
*   **Bind Group:** Binding 5 is added to the shared `@group(0)` bind-group layout [S1, unofficial].
*   **Texture Properties:** The texture is `textureLoad`-only, with no sampler [S1, unofficial].

**Steps:**
1.  **Initial Reduction:** The raw volume cube is reduced through three chained $2\times$ max-reductions via two upload-time scratch textures [S1, unofficial].
    *   **First Reduction:** Converts raw values to normalized deviation [S1, unofficial]. For each voxel value $v$, the deviation $d$ is calculated as:
        $$ d = \frac{|v - \text{contrastCenter}|}{\text{halfRange}} $$
        This deviation is non-negative by construction [S1, unofficial].
    *   **Subsequent Reductions:** The remaining two reductions compose via plain `max` operations on the deviation values [S1, unofficial]. Since deviation is non-negative, standard max-composition correctly propagates the maximum intensity information up the hierarchy without further normalization [S1, unofficial].
2.  **Mip Chain Generation:** After the initial reductions, the pyramid's own chain is filled via the `generateMipChain3d` primitive [S1, unofficial]. This primitive fills 3D-texture mip chains via depthSlice render passes [S1, unofficial].

**Parameters:**
*   `contrastCenter`: The center value for deviation calculation [S1, unofficial].
*   `halfRange`: The half-range used for normalization [S1, unofficial].
*   Typical values are not explicitly given in the sources, but the method supports live slider changes, implying these are dynamic uniforms [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Thin Filaments:** Building from the display mips (box-filtered) can hide thin bright filaments. The method explicitly avoids this by building from the raw cube [S1, unofficial].
*   **Precision:** The deviation formula involves division by `halfRange`. If `halfRange` is zero, the operation is undefined [S1, unofficial]. The sources do not specify a guard for this case [G: Implementers should ensure halfRange > 0 or handle division by zero explicitly].
*   **Shader Access:** No shader declares binding 5 yet in the source context, but the explicit pipeline layout allows a bind group to carry unused entries [S1, unofficial].

**Pseudocode:**
```python
def reduce_3d(src, dim_x, dim_y, dim_z, apply_deviation, contrast_center, half_range):
    """Performs a 2x max-reduction on a 3D array."""
    dst_x, dst_y, dst_z = dim_x // 2, dim_y // 2, dim_z // 2
    dst = [[[0.0] * dst_z for _ in range(dst_y)] for _ in range(dst_x)]
    for z in range(0, dim_z, 2):
        for y in range(0, dim_y, 2):
            for x in range(0, dim_x, 2):
                # Gather 8 voxels from the 2x2x2 block
                vals = [
                    src[x][y][z], src[x][y][z + 1],
                    src[x][y + 1][z], src[x][y + 1][z + 1],
                    src[x + 1][y][z], src[x + 1][y][z + 1],
                    src[x + 1][y + 1][z], src[x + 1][y + 1][z + 1]
                ]
                if apply_deviation:
                    devs = [abs(v - contrast_center) / half_range for v in vals]
                    dst[x // 2][y // 2][z // 2] = max(devs)
                else:
                    dst[x // 2][y // 2][z // 2] = max(vals)
    return dst

def generate_mip_chain_3d(base_level, base_x, base_y, base_z):
    """
    Fills the remaining 3D-texture mip chain via depthSlice render passes.
    Implemented here as a standard iterative reduction to satisfy self-containment.
    """
    current = base_level
    cx, cy, cz = base_x, base_y, base_z
    while cx > 1 or cy > 1 or cz > 1:
        nx, ny, nz = max(1, cx // 2), max(1, cy // 2), max(1, cz // 2)
        nxt = [[[0.0] * nz for _ in range(ny)] for _ in range(nx)]
        for z in range(0, cz, 2):
            for y in range(0, cy, 2):
                for x in range(0, cx, 2):
                    vals = [
                        current[x][y][z], current[x][y][z + 1],
                        current[x][y + 1][z], current[x][y + 1][z + 1],
                        current[x + 1][y][z], current[x + 1][y][z + 1],
                        current[x + 1][y + 1][z], current[x + 1][y + 1][z + 1]
                    ]
                    nxt[x // 2][y // 2][z // 2] = max(vals)
        current = nxt
        cx, cy, cz = nx, ny, nz
    return current

def build_per_field_max_pyramid(raw_volume, width, height, depth, contrast_center, half_range):
    """
    Builds the per-field max pyramid in deviation space.
    raw_volume: The input raw volume cube (D x D x D).
    contrast_center: The center value for deviation calculation.
    half_range: The half-range used for normalization.
    Returns: The base level of the maxPyramidTexture mip chain.
    """
    # Step 1: Initial Reduction through three chained 2x max-reductions
    # Using two upload-time scratch textures as intermediaries [S1, unofficial]
    
    # First reduction: Convert to deviation space
    level1 = reduce_3d(raw_volume, width, height, depth, True, contrast_center, half_range)
    
    # Second reduction: Plain max (deviation is non-negative)
    level2 = reduce_3d(level1, width // 2, height // 2, depth // 2, False, 0, 0)
    
    # Third reduction: Plain max
    level3 = reduce_3d(level2, width // 4, height // 4, depth // 4, False, 0, 0)
    
    # Step 2: Fill the pyramid's own chain via generateMipChain3d
    # The final reduced level is the base of the pyramid.
    mip_chain = generate_mip_chain_3d(level3, width // 8, height // 8, depth // 8)
    return mip_chain
```

## Subtopics

### Max-Pyramid Level of Detail (LOD)
A pre-computed hierarchy of maps for efficient calculation of maximum function values on intervals, used to estimate maximums during rendering [S2]. It starts with initial data at level $n$ (forming a $2^n \times 2^n$ array) [S2]. To generate level $n-1$, the maximum is chosen from every four adjacent values of level $n$, and the other three values are discarded [S2]. This repeats until level 0, which consists of a single value (the global maximum) [S2]. Level $k$ is a $2^k \times 2^k$ array [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial].
*   **Memory Complexity:** Not given in the sources [S1, unofficial].
*   **Measured Performance:** The method runs at 1/3 resolution with a hard 128-step cap [S1, unofficial].
*   **Scaling:** The skip cutoff is derived in-shader from live contrast/trim uniforms, so slider changes retune skipping with nothing to rebuild [S1, unofficial]. It is correct for sequential (MCPM) and divergent (CF-4) palettes [S1, unofficial].
*   **Strengths:** Avoids hiding thin bright filaments by building from the raw cube [S1, unofficial]. Enables TF-adaptive skipping [S1, unofficial].
*   **Limitations:** Requires additional upload-time scratch textures [S1, unofficial].
*   **When to use:** When dynamic, transfer-function-adaptive skipping is needed for volume ray marching [S1, unofficial].
*   **When not to use:** When thin bright filaments are not a concern and display mips are sufficient [S1, unofficial].

## Background
The concept of using max-pyramids for level-of-detail in volume rendering has roots in earlier work on GPU-based volume-oriented rendering of functionally defined objects [S2]. The specific implementation as a "Per-Field Max Pyramid in Deviation Space" is part of the volume-raymarch-acceleration plan, specifically Task 3 [S1, unofficial]. It was introduced in the `skymap` project by rulkens [S1, unofficial].
