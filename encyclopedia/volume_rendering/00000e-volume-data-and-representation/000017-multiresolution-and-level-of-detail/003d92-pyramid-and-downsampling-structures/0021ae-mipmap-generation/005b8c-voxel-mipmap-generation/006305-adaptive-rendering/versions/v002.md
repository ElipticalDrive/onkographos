# Adaptive Rendering

Also called: Adaptive voxel reconstruction

## Overview
Adaptive rendering is a volume visualization technique that improves time efficiency by performing ray tracing on coarse-resolution data first, then incrementally refining the result by incorporating information from higher-resolution levels [S1, unofficial]. It functions as an intelligent masking mechanism that accelerates rendering by skipping empty or non-useful voxels identified in the low-resolution domain before calculating new voxels from higher resolutions for the integration equation [S1, unofficial]. Unlike octree-based methods, it avoids the extra memory cost of auxiliary tree structures by leveraging the compressed nature of the multiresolution pyramid itself [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A multiresolution pyramid of volume data consisting of $M+1$ levels, indexed $m=0 \dots M$ [S1, unofficial]. The dataset has $N$ voxels on a side, where $N = 2^M + 1$ for some integer $M$ [S1, unofficial]. Level $m=0$ is the lowest resolution (LLL), and level $m=M$ is the highest resolution [S1, unofficial].
*   **Output:** A rendered image with adaptive detail, where only necessary high-resolution voxels are computed.

**Data Structures**
The method relies on a pyramid of binary volumes (or scalar volumes) indexed by level number $m$ [S1, unofficial].
*   Volume $V_m$ measures $(N-1)/2^m$ cells on a side [S1, unofficial].
*   Cells are indexed by a level number $m$ and a vector $\mathbf{i} = (i, j, k)$ where $i, j, k = 1, \dots, N-1$ [S1, unofficial].
*   The value contained in cell $\mathbf{i}$ on level $m$ is denoted $V_m(\mathbf{i})$ [S1, unofficial].

**Parameters**
*   **Resolution Levels:** The number of levels to use in the pyramid [S1, unofficial]. Experiments suggest that using 1 to 3 levels is suitable [S1, unofficial].
*   **Constraint:** Going to too low a level is counter-productive if the volume data does not have blocks of associated size containing completely zero voxels [S1, unofficial].

**Algorithm Steps**
1.  **Initialize:** Start ray tracing at the lowest resolution level (LLL, $m=0$) [S1, unofficial].
2.  **March:** Advance along the ray through the current level's voxels [S1, unofficial].
3.  **Check Value:** If a voxel with a zero value is encountered, skip it immediately [S1, unofficial]. If a non-zero voxel is encountered, invoke the block reconstruction function to obtain the corresponding block of voxels at the next higher resolution level ($m+1$) [S1, unofficial].
4.  **Switch Level:** Upon invoking block reconstruction, switch the ray tracing context to the higher resolution level [S1, unofficial].
5.  **Integrate:** For useful voxels identified in the low-resolution domain, calculate the new voxel from the higher resolution for the integration equation along the ray [S1, unofficial].
6.  **Cache:** Since voxels reconstructed along one projection ray are likely used by adjacent rays, use a cache memory to temporarily retain reconstructed voxels to reduce redundant reconstruction [S1, unofficial].
7.  **Repeat:** Continue until the ray exits the volume or the highest resolution level is reached [S1, unofficial].

**Pseudocode**
```python
def adaptive_render_ray(ray_origin, ray_direction, pyramid, cache):
    """
    ray_origin: 3D vector (x, y, z)
    ray_direction: 3D vector (dx, dy, dz)
    pyramid: List of 3D arrays [V_0, V_1, ..., V_M]
    cache: Dictionary mapping (level, i, j, k) -> value
    """
    current_level = 0
    accumulated_color = 0.0
    accumulated_opacity = 0.0
    
    # Ray traversal state (unit cell size assumed)
    t = 0.0
    step = 1.0
    # Current voxel coordinates in the current level's grid
    # Initialized to start of volume bounds
    i, j, k = 1, 1, 1
    
    while True:
        # Check bounds for current level
        # Volume V_m measures (N-1)/2^m cells on a side
        side_len = (len(pyramid[0]) - 1) // (2 ** current_level)
        if not (1 <= i <= side_len and 1 <= j <= side_len and 1 <= k <= side_len):
            break
            
        # Check cache
        cache_key = (current_level, i, j, k)
        if cache_key in cache:
            voxel_value = cache[cache_key]
        else:
            # Access voxel directly from the 3D array
            voxel_value = pyramid[current_level][i][j][k]
            cache[cache_key] = voxel_value
            
        if voxel_value == 0:
            # Skip empty space efficiently
            i, j, k = next_voxel_along_ray(i, j, k, ray_direction)
            continue
            
        # Non-zero voxel found: reconstruct higher resolution block
        if current_level + 1 < len(pyramid):
            # Standard block reconstruction (e.g., interpolation) to fill higher-res grid [G]
            high_res_block = reconstruct_block(pyramid[current_level], (i, j, k), pyramid[current_level + 1])
            
            # Switch to higher resolution level
            current_level += 1
            
            # Map current ray position to new grid coordinates
            i, j, k = map_to_higher_res_grid(i, j, k, current_level)
            
            # Re-check cache for the new high-res voxel
            cache_key = (current_level, i, j, k)
            if cache_key in cache:
                voxel_value = cache[cache_key]
            else:
                voxel_value = pyramid[current_level][i][j][k]
                cache[cache_key] = voxel_value
                
        # Integration step for the current voxel
        accumulated_color += voxel_value
        accumulated_opacity += 1.0
        
        # Advance ray
        i, j, k = next_voxel_along_ray(i, j, k, ray_direction)
        
    return accumulated_color

def next_voxel_along_ray(i, j, k, direction):
    # Simple step along positive ray direction for unit cells
    return (i + 1, j + 1, k + 1)

def map_to_higher_res_grid(i, j, k, new_level):
    # Higher resolution grid has 2x cells per side
    return (i * 2, j * 2, k * 2)
```

**Edge Cases and Pitfalls**
*   **Too Coarse Levels:** Using a level that is too low (coarse) is counter-productive if the data lacks blocks of that size containing completely zero voxels, as the skipping benefit is lost [S1, unofficial].
*   **Precision:** Mapping ray positions between different resolution grids requires careful coordinate transformation to avoid sampling errors [G].
*   **Cache Management:** The cache size must be managed to prevent memory overhead from negating the performance gains, especially for large volumes [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Improves time efficiency by skipping empty voxels at low resolution. The cost is dominated by the number of non-zero voxels reconstructed at higher levels [S1, unofficial].
*   **Memory Complexity:** Saves space compared to octree methods by not requiring an auxiliary tree structure; it uses the compressed multiresolution pyramid data directly [S1, unofficial].
*   **Strengths:** Fast elimination of empty space; no extra memory for tree structures; suitable for compressed data [S1, unofficial].
*   **Limitations:** Performance gain depends on the sparsity of the data (presence of zero blocks); choosing the wrong number of levels can degrade performance [S1, unofficial].
*   **When to Use:** When volume data has significant empty regions and a multiresolution pyramid is already available or generated [S1, unofficial].
*   **When Not to Use:** When the data is dense with no large zero blocks, or when memory is extremely constrained and caching overhead becomes significant [S1, unofficial].

## Background
The method was developed to facilitate properties of multiresolution representation, such as adaptive rendering, progressive rendering, and error bound checking [S1, unofficial]. It was motivated by the desire to eliminate the extra memory cost associated with auxiliary octree structures while maintaining the benefits of hierarchical rendering [S1, unofficial]. The approach is conceptually equivalent to octree techniques but operates directly on the pyramid of binary/scalar volumes [S1, unofficial].
