# Anisotropic Texture Atlas Packing


## Overview
Anisotropic Texture Atlas Packing is a method to pack surfel textures into a fixed-width atlas using anisotropic rectangular tiles sized according to the Nyquist rate of the hash grid, avoiding square padding on thin surfels [S1, unofficial]. It addresses the inefficiency of square padding for non-uniform surfels by aligning tile dimensions with the surfel's tangent axis scales [S1, unofficial].

## How it works
**Inputs:**
- Set of surfels $g$, each with center $\mathbf{p}_g$, tangent frame $R$, scales $s_{g,u}, s_{g,v}$, and UV half-extent $e$ [S1, unofficial].
- Hash grid finest voxel size $\delta$ [S1, unofficial].
- Atlas width constraint $W$ (default 4096) [S1, unofficial].
- Resolution bounds $r_{\min}=4, r_{\max}=64$ [S1, unofficial].

**Outputs:**
- A 2D texture atlas of dimensions $W \times H$ [S1, unofficial].
- For each surfel $g$, a rectangular tile of size $r_{g,u} \times r_{g,v}$ and its offset $(u_{off}, v_{off})$ in the atlas [S1, unofficial].
- For each texel in the tile, the pre-computed RGB value $\rho(\mathbf{x})$ [S1, unofficial].

**Data Structures:**
- **Shelf:** A contiguous horizontal band in the atlas. Defined by its starting row index $y_{start}$, current height $h$, and remaining width $w_{rem}$ [G].
- **Atlas:** A 2D array of size $W \times H$. Initialized to zero or transparent [G].

**Steps:**
1. **Calculate Anisotropic Resolution:** For each surfel $g$ and axis $a \in \{u, v\}$, compute the required resolution $r_{g,a}$:
   $$r_{g,a} = \text{clamp} \left( 2^{\lceil \log_2(4es_{g,a}/\delta) \rceil}, r_{\min}, r_{\max} \right)$$
   where $s_{g,a}$ is the surfel scale on axis $a$, $e$ is the UV half-extent in units of that scale, and $\delta$ is the finest hash voxel size [S1, unofficial]. The factor 4 combines the $2e$ span with Nyquist sampling requirements [S1, unofficial].
2. **Sort Surfels:** Sort the surfels in descending order of height $r_y$, then by width $r_x$ [S1, unofficial].
3. **Pack into Atlas (Shelf-First-Fit-Decreasing):** Initialize atlas height $H = 0$. Initialize a list of open shelves. For each surfel $g$ in sorted order, place its rectangular tile into the first available shelf [S1, unofficial].
4. **Evaluate and Bake:** For each surfel $g$ and each texel $(i, j)$ in its assigned tile ($0 \le i < r_{g,u}, 0 \le j < r_{g,v}$), compute local coordinates, lift to world space, evaluate the hash grid and MLP decoder to get RGB value $\rho(\mathbf{x})$, and write $\rho(\mathbf{x})$ to the atlas at the calculated position [S1, unofficial].
5. **Handle Atlas Limits:** Round $H$ to the next multiple of 64 after placing all surfels [S1, unofficial]. If $H$ approaches 65,536 rows (the `cudaArray` limit), increase $W$ (e.g., double it) and repack [S1, unofficial].

**Pseudocode:**
```python
import math

def clamp(val, lo, hi):
    return max(lo, min(hi, val))

def pack_anisotropic_atlas(surfels, delta, W=4096, r_min=4, r_max=64, e=4):
    # 1. Calculate anisotropic resolution per surfel
    for g in surfels:
        g.r_x = clamp(2 ** math.ceil(math.log2(4 * e * g.s_u / delta)), r_min, r_max)
        g.r_y = clamp(2 ** math.ceil(math.log2(4 * e * g.s_v / delta)), r_min, r_max)

    # 2. Sort surfels descending by height (r_y), then width (r_x)
    surfels.sort(key=lambda g: (g.r_y, g.r_x), reverse=True)

    # 3. Shelf-First-Fit-Decreasing packing
    shelves = []
    H = 0
    for g in surfels:
        w, h = g.r_x, g.r_y
        placed = False
        for shelf in shelves:
            if shelf.w_rem >= w:
                g.offset = (shelf.x_offset, shelf.y_start)
                shelf.w_rem -= w
                shelf.height = max(shelf.height, h)
                placed = True
                break
        if not placed:
            new_shelf = {'y_start': H, 'height': h, 'w_rem': W - w, 'x_offset': 0}
            shelves.append(new_shelf)
            g.offset = (0, H)
            H += h
    H = math.ceil(H / 64) * 64  # Round to multiple of 64

    # 4. Evaluate and bake
    atlas = [[None for _ in range(H)] for _ in range(W)]
    for g in surfels:
        u_off, v_off = g.offset
        for i in range(g.r_x):
            for j in range(g.r_y):
                u = (i + 0.5) / g.r_x * 2 * e - e
                v = (j + 0.5) / g.r_y * 2 * e - e
                x = g.p + u * g.s_u * g.R[:, 0] + v * g.s_v * g.R[:, 1]
                rgb = evaluate_hash_and_mlp(x)
                atlas[u_off + i][v_off + j] = rgb
    return atlas
```

**Parameters:**
- $W$: Atlas width. Default 4096 [S1, unofficial].
- $r_{\min}$: Minimum resolution. Default 4 [S1, unofficial].
- $r_{\max}$: Maximum resolution. Default 64 [S1, unofficial].
- $e$: UV half-extent. Typical value 4 [S1, unofficial].
- $\delta$: Finest hash voxel size. Scene-dependent [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Seams:** Using integer texel indices $i, j$ directly without the $+0.5$ offset and normalization in Eq. 4 causes misalignment with bilinear filtering, leading to visible seams [S1, unofficial].
- **Wasted Memory:** With $e=4$, a significant portion of texels (e.g., 50.5% in indoor scenes) may lie outside the kernel support and are never fetched, wasting memory [S1, unofficial].
