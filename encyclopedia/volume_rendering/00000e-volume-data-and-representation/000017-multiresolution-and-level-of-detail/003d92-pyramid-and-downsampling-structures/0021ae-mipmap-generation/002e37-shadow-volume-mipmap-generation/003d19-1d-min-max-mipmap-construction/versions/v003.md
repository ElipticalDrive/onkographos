# 1D Min-Max Mipmap Construction


## Overview
This method constructs a hierarchical data structure on each row of a rectified shadow map to accelerate finding the lit segments of a camera ray by storing the minimum and maximum values of the shadow heightfield [S1]. It solves the problem of quickly determining the intersection of a 1D heightfield with a camera ray, enabling volume rendering algorithms to skip fully shadowed regions [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A rectified shadow map $S$, where each row represents a 1D heightfield in an epipolar slice, and $d$ is the resolution in the $\gamma$ direction (number of light rays) [S1].
*   **Output:** A single coalesced buffer containing the min-max mipmap for all rows, laid out level by level using Ahnentafel indexing [S1].

**Data Structures**
Each row forms a complete binary tree where every node stores the minimum and maximum values of $S$ below that node [S1]. The output buffers are coalesced into a single buffer per row, arranged level by level using Ahnentafel indexing, starting with the root at index 1 [S1].

**Algorithm Steps**
1.  Initialize the leaf level with the shadow heightfield values $S[i]$ for $0 \le i < d$ [S1].
2.  Compute the tree using $\log_2 d$ ping-pong passes, where $d$ is the number of light rays [S1].
3.  In each pass, compute one level from the level below by pairing sibling nodes and storing their minimum and maximum values in the parent node [S1].
4.  Coalesce the resulting level buffers into a single buffer per row, arranging nodes level by level using Ahnentafel indexing starting at index 1 [S1].

**Pseudocode**
```python
def build_1d_min_max_mipmap(S, d):
    """
    S: 1D array of shadow heights for a single row, length d.
    d: Resolution of the shadow map in the gamma direction (number of light rays).
    Returns: Flat array of size 2*d - 1 using Ahnentafel indexing (root at index 1).
    """
    # Initialize leaves (level 0)
    current_level = [(S[i], S[i]) for i in range(d)]
    levels = [current_level]
    
    # Compute log2(d) ping-pong passes bottom-up
    while len(current_level) > 1:
        next_level = []
        for i in range(0, len(current_level), 2):
            left = current_level[i]
            right = current_level[i + 1]
            next_level.append((min(left[0], right[0]), max(left[1], right[1])))
        levels.append(next_level)
        current_level = next_level
        
    # Coalesce all levels into a single Ahnentafel-indexed buffer
    tree = [None] * (2 * d)
    idx = 1
    for level in levels:
        for node in level:
            tree[idx] = node
            idx += 1
            
    return tree[1:]
```

**Parameters**
*   $d$: Resolution of the shadow map in the $\gamma$ direction (number of light rays) [S1].

**Edge Cases and Pitfalls**
*   $d$ must be a power of 2 for the complete binary tree structure to hold without padding [G].
*   Standard precision and boundary handling apply to floating-point heightfield values [G].

## Subtopics

### [Min-Max Mipmap Traversal](9419-min-max-mipmap-traversal.md)
Min-Max Mipmap Traversal is a recursive algorithm implemented iteratively in a pixel shader to traverse a 1D min-max mipmap, identifying lit segments of a ray to integrate using prefix sums [G]. It solves the problem of efficiently determining which parts of a rectified shadow map are occluded by geometry, thereby accelerating volume rendering by skipping fully shadowed regions [G]. It sets itself apart from naive ray marching by using the hierarchical min-max bounds to skip large portions of the domain, and from standard binary tree traversal by utilizing a flat array representation with specific iterative advancement rules to avoid recursion overhead in shaders [G].

## Operating characteristics
*   **Time Complexity:** The construction requires $\log_2 d$ ping-pong passes [S1].
*   **Memory Complexity:** The memory required is proportional to the number of nodes in the complete binary tree, which is $2d - 1$ nodes per row [G].
*   **Measured Performance:** Not given in the sources. [G]
*   **Scaling:** Construction scales with the number of passes $\log_2 d$ per row [S1].
*   **Strengths:** Accelerates finding lit segments by storing min/max bounds, reducing ray marching steps in shadowed regions [S1].
*   **Limitations:** Requires $d$ to be a power of 2 for a perfect complete binary tree [G].
*   **When to use:** When rendering volumetric shadows with rectified shadow maps and needing to accelerate ray marching by skipping occluded regions [S1].
*   **When not to use:** Not given in the sources. [G]

It is part of a technique for real-time volumetric shadow rendering that uses rectified shadow maps to represent epipolar slices as 1D heightfields, enabling efficient culling of shadowed regions during volume rendering [S1].
