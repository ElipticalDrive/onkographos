# Min-Max Mipmap Traversal

Also called: Heightfield Rendering Optimization, Min-Max Mipmap Traversal Optimization, Shader Optimization for Tree Traversal, Tree Traversal for Integration

## Overview
Min-Max Mipmap Traversal is a recursive algorithm implemented iteratively in a pixel shader to traverse a 1D min-max mipmap, identifying lit segments of a ray to integrate using prefix sums [S1]. It solves the problem of efficiently determining which parts of a rectified shadow map are occluded by geometry, thereby accelerating volume rendering by skipping fully shadowed regions [S1]. It sets itself apart from naive ray marching by using hierarchical min-max bounds to skip large portions of the domain, and from standard binary tree traversal by utilizing a flat array representation with specific iterative advancement rules to avoid recursion overhead in shaders [G].

## How it works
**Inputs and Outputs:**
*   **Input:** Camera ray coordinates $(x, y)$, depth $D[x, y]$, the min-max mipmap array `min` and `max` indexed by node index and epipolar angle $\alpha$, and the prefix sum array $\Gamma_{sum}$ of the integrand $\Gamma(\gamma)$ [S1].
*   **Output:** Accumulated radiance contribution `out` for the pixel [S1].

**Data Structures:**
*   **Min-Max Mipmap:** A flat array where `min[node, α]` and `max[node, α]` store the minimum and maximum shadow heights for the range covered by `node` at angle $\alpha$ [S1].
*   **Prefix Sum Array:** $\Gamma_{sum}$ stores cumulative integrals of $\Gamma(\gamma)$ [S1].
*   **Tree Indexing:** The tree is stored in a flat array using heap-like indexing [G]. The root is index 1. For a node `n`, the left child is `2*n` and the right child is `2*n + 1` [G].

**Steps:**
1.  **Initialization:** Convert camera ray $(x, y)$ with depth $D[x, y]$ to epipolar coordinates $(\alpha, \beta, \gamma_1)$ using `TO-EPIPOLAR` [S1]. Initialize `node = 1` (root) [S1]. Get the $\gamma$-range $(\gamma_-, \gamma_+)$ for the current node using `RANGE(node)` [S1]. Initialize output accumulator `out = (0,0,0,0)` [S1].
2.  **Traversal Loop:** Iterate while `node != 1` and the ray extends into the node ($\gamma_1 > \gamma_-$) [S1].
3.  **Boundary Check:** Compare the ray height $\beta$ with the node's bounds `min[node, α]` and `max[node, α]` [S1].
    *   **Case 1: Boundary Inside ($\min[node, \alpha] \le \beta < \max[node, \alpha]$):** The node contains a shadow boundary [S1]. Recurse to the left child by setting `node = node * 2` [S1].
    *   **Case 2: Fully Lit ($\beta < \min[node, \alpha]$):** The entire range of this node is lit [S1]. Add the integral over the node's range to the output:
        $$ out = out + \Gamma_{sum}[\min(\gamma_1, \gamma_+)] - \Gamma_{sum}[\gamma_-] $$
        [S1] Then, advance to the next node [S1].
    *   **Case 3: Fully Shadowed ($\beta > \max[node, \alpha]$):** The entire range is shadowed [S1]. Skip the node [S1].
4.  **Advancement (for Cases 2 and 3):**
    *   Increment `node` by 1 (`node = node + 1`) [S1].
    *   If the new `node` is even (a left child), move up to the parent (`node = node // 2`) [S1]. The source notes an optimization where this `while` loop is replaced by a single `if` statement, limiting upward movement to at most one level [S1].
5.  **Update Range:** Get the new $\gamma$-range $(\gamma_-, \gamma_+)$ for the current `node` [S1].
6.  **Final Integration:** After the loop, compute the final radiance by dotting the accumulated `out` with the basis function $B[\beta]$:
    $$ \text{Result} = \text{dot}(B[\beta], out) $$
    [S1]

**Pseudocode:**
```python
def INTEGRATE_RAY(x, y):
    depth = D[x, y]
    alpha, beta, gamma1 = TO_EPIPOLAR(x, y, depth)  # Standard epipolar transform [G]
    
    node = 1  # Start at root
    gamma_minus, gamma_plus = RANGE(node)  # Returns γ-span for node's leaf range [G]
    out = [0.0, 0.0, 0.0, 0.0]
    
    while True:
        if min[node, alpha] <= beta < max[node, alpha]:
            # Node contains boundary, recurse to left child
            node = node * 2
        else:
            if beta < min[node, alpha]:
                # Fully lit: add integral over node range
                upper = min(gamma1, gamma_plus)
                delta = Gamma_sum[upper] - Gamma_sum[gamma_minus]
                out = [o + delta for o in out]
            
            # Advance to next node
            node = node + 1
            
            # Move up if we are a left child
            # Optimization: Source replaces while with if for single level up
            if node % 2 == 0:
                node = node // 2
        
        gamma_minus, gamma_plus = RANGE(node)
        
        if node == 1 or gamma1 <= gamma_minus:
            break
            
    return [b * o for b, o in zip(B[beta], out)]
```

**Parameters and Edge Cases:**
*   **$\gamma_1$:** The end of the ray segment in $\gamma$-space [S1].
*   **Precision:** Floating point comparisons between $\beta$ and min/max values must handle equality carefully [S1].
*   **Degenerate Input:** If the ray does not intersect the volume or the mipmap is empty, the loop condition `node != 1` handles termination [S1].

## Subtopics

### [Textured Light Integration](9425-textured-light-integration.md)
Extends the method to handle textured lights (e.g., stained-glass windows) by rectifying the light texture map $T(\alpha, \gamma)$ and multiplying it into the integrand. It requires precomputing prefix sums of $\Gamma_i(\gamma)T(\alpha, \gamma)$ per $\alpha$ using pingpong passes.

## Operating characteristics
*   **Time Complexity:** The traversal is $O(\log N)$ in the best case (fully lit or fully shadowed nodes) and $O(N)$ in the worst case (zig-zagging through boundaries), but typically much faster than linear sampling [G]. The iterative implementation avoids function call overhead [S1].
*   **Memory Complexity:** Requires storage for the min-max mipmap and the prefix sum array [S1]. For textured lights, additional storage is needed for the per-$\alpha$ prefix sums of the texture-modulated integrand [S1].
*   **Strengths:** Efficiently skips large shadowed or lit regions [S1]. Suitable for real-time rendering via pixel shaders due to iterative implementation [S1].
*   **Limitations:** Performance degrades if the shadow boundary is highly complex and intersects many nodes [G].
*   **When to use:** When rendering volumetric shadows from rectified shadow maps where the shadow boundary is sparse or smooth [S1].
*   **When not to use:** When the shadow boundary is extremely jagged or the volume is small enough that linear sampling is faster [G].

## Background
This optimization was previously used for heightfield rendering by Tevs et al. in 2008 [S1]. It was adapted for real-time volumetric shadows using 1D min-max mipmaps to accelerate the integration of light along camera rays [S1].
