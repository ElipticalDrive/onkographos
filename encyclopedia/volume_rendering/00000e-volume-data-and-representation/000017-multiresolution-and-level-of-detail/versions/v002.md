# Multiresolution and level of detail

Also called: Multiresolution representations, Hierarchical volume rendering, Multi-scale volume data

## Overview
Multiresolution and level of detail (LOD) techniques manage the trade-off between rendering fidelity and computational cost by representing volumetric data at multiple spatial resolutions [S1, S2, unofficial]. The core problem is that high-resolution volumes often exceed available GPU memory or require excessive rendering time for interactive frame rates [S2, unofficial]. This family solves the problem by allowing the renderer to select the appropriate resolution for each region of the volume based on viewer distance, screen-space error, or hardware constraints [S1, S2, unofficial]. What sets this family apart from [Dense grids and memory layout](3-dense-grids-and-memory-layout.md) is the explicit construction of a hierarchy of representations (spatial or frequency-based) rather than a single static storage format, and it differs from [Compression](4-compression.md) by focusing on the *rendering* selection logic and adaptive traversal rather than just storage reduction [S2, S3, unofficial].

## Shared principles
All methods in this family rely on the following mechanisms to enable adaptive resolution:

1.  **Hierarchical Decomposition:** The volume is decomposed into a hierarchy of representations. This is achieved either spatially (e.g., octrees, bricks, tetrahedra) or in the frequency domain (e.g., wavelets, DCT) [S1, S2, S3, unofficial].
    *   **Spatial:** Data is partitioned into blocks (bricks) or nodes (octree/tetrahedra) that can be refined or coarsened independently [S2, S3, unofficial].
    *   **Frequency:** Data is transformed into approximation and detail coefficients, where coarse levels represent low-frequency structure and fine levels represent high-frequency details [S3, unofficial].
2.  **Scaling and Resolution Mapping:** A scale factor $s$ or resolution level $l$ defines the relationship between levels. For spatial grids, the resolution $N_{new}$ is often related to $N_{prev}$ by $N_{new} = N_{prev} / s$ or $N_{new} = s \times N_{prev}$ [S1, S5, unofficial]. In mipmaps, level $k$ has dimensions reduced by a factor of $2^k$ [S2, unofficial].
3.  **Interpolation and Filtering:** Generating coarser levels requires filtering to prevent aliasing. Common kernels include:
    *   **Averaging:** Arithmetic mean of input voxels [S2, unofficial].
    *   **Max Pooling:** Selecting the maximum value in a neighborhood, preserving high-intensity features (useful for MIP) [S1, unofficial].
    *   **Splines:** Quadratic or cubic splines for smoother transitions [S2, S3, unofficial].
    *   **Wavelet Transforms:** Orthogonal basis functions that separate data into approximation and detail subbands [S3, unofficial].
4.  **Selection and Culling:** The renderer dynamically selects which resolution level to use for a given view ray or region. Selection criteria include:
    *   **Distance:** Coarser levels for distant objects [S2, unofficial].
    *   **Screen-Space Error:** Projected texel size relative to pixel size [S1, unofficial].
    *   **Error Metrics:** Quantitative measures of approximation quality (e.g., MSE, L1-error) [S1, S3, unofficial].
    *   **Memory Constraints:** Fitting the active dataset into available GPU memory [S1, unofficial].

## Subtopics

### [VoxelGrid Down Sample](1014-voxelgrid-down-sample.md)
Reduces resolution by a specified integer factor using max pooling. It differs from [Mipmap Generation](2602-mipmap-generation.md) by strictly selecting the maximum value within local neighborhoods, preserving high-intensity features and sharp boundaries, whereas mipmaps often use averaging. Choose this when generating coarse representations for Maximum Intensity Projection (MIP) or when preserving high-value features is critical.

### [Mesh Simplification](1032-mesh-simplification.md)
Reduces triangle count of a surface mesh via iterative edge collapses, typically using Quadric Error Metrics (QEM). It differs from siblings by operating on explicit polygonal meshes (surfaces extracted from volume) rather than voxel grids or textures, serving as a post-processing step for surface rendering. Choose this when rendering extracted isosurfaces rather than direct volume rendering.

### [Wavelet-based Volume Rendering](1052-wavelet-based-volume-rendering.md)
Encodes volumetric data into a multiresolution wavelet coefficient hierarchy, allowing on-demand reconstruction. It differs from [Mipmap Generation](2602-mipmap-generation.md) by using orthogonal basis functions that maintain spatial locality while separating data into approximation and detail coefficients, enabling efficient lossy/lossless compression and adaptive resolution based on error metrics rather than fixed geometric distance. Choose this for compressed streaming or when frequency-domain sparsity is high.

### [Multi-Tetra Framework](1183-multi-tetra-framework.md)
Approximates regular volume data using tetrahedra of varying levels of detail, generated through recursive subdivision and stored in a binary tree. It solves the crack problem between LODs by ensuring subdivision uses existing vertex indices without adding new points or requiring interpolation. Choose this when crack-free transitions between different LODs in a tetrahedral mesh are required.

### [Morphological Pyramid](1641-morphological-pyramid.md)
Uses morphological erosion and dilation combined with dyadic downsampling to create a hierarchy of approximations and detail signals. It enables perfect reconstruction and improves approximation accuracy. Unlike linear pyramids, it exploits the commutativity of the MIP operator with morphological dilation, allowing projections to be performed on coarse levels. Choose this for MIP rendering or when morphological properties are important.

### [Multi-Resolution Volume Visualization (Split-and-Collapse)](1692-multi-resolution-volume-visualization-split-and-collapse.md)
Dynamically adjusts spatial resolution of different volume regions to fit hardware memory constraints using a greedy algorithm for split/collapse operations. Unlike static LOD approaches, it continuously updates the representation frame-to-frame to accommodate viewpoint changes. Choose this for interactive rendering of large datasets with strict memory limits.

### [Level-of-Detail Volume Rendering via 3D Textures](1706-level-of-detail-volume-rendering-via-3d-textures.md)
Provides adaptive LOD selection using 3D texture mapping, rendering regions of interest at high resolution and distant areas at lower resolution. It guarantees consistent interpolation between levels and fixes artifacts at brick boundaries using polygon clipping and opacity correction. Choose this for GPU-accelerated rendering where texture hardware supports 3D mipmaps.

### [Streaming MIP Implementation (Basic)](1803-streaming-mip-implementation-basic.md)
Approximates MIP by projecting pre-sorted detail coefficients from a morphological pyramid directly to the frame buffer. It solves memory bandwidth issues by streaming coefficients in order of L1-error contribution, allowing progressive refinement. Choose this for real-time MIP visualization of very large datasets where full reconstruction is impossible.

### [Multiresolution Decomposed Volume Rendering](2277-multiresolution-decomposed-volume-rendering.md)
A general framework for rendering decomposed volume data (e.g., Fourier, Wavelet, DCT coefficients) without full reconstruction. It supports adaptive rendering, progressive refinement, and error bounds checking. Choose this when you need a generic pipeline for various transform-based multiresolution methods.

### [Downscaled Grid Map Generation](2338-downscaled-grid-map-generation.md)
Creates a low-resolution coordinate grid and an index map to map high-resolution coordinates to low-resolution locations. Choose this when you need to generate lookup tables for downsampling operations in shaders or CPU-side processing.

### [Level of Detail for Volumetric Terrain](2459-level-of-detail-for-volumetric-terrain.md)
A GPU-friendly LOD algorithm for real-time rendering of volumetric terrain using arbitrary volumetric models. It generates geometry on the fly, avoiding preprocessing costs and supporting infinite procedural terrain. Choose this for terrain visualization where the volume is defined by a procedural density function.

### [Mipmap Generation](2602-mipmap-generation.md)
Creates a hierarchy of downscaled volume data to enable multi-resolution rendering. It differs from [VoxelGrid Down Sample](1014-voxelgrid-down-sample.md) by organizing data into a structured mip-chain accessible via texture sampling, and from [Level-of-Detail Volume Rendering via 3D Textures](1706-level-of-detail-volume-rendering-via-3d-textures.md) by focusing on the generation pipeline itself [G]. Choose this as a standard preprocessing step for texture-based rendering.

### [Window/Level Volume Raycasting with Bricking](2775-window-level-volume-raycasting-with-bricking.md)
Combines spatial decomposition (bricking) with intensity-based transfer function mapping (window/level) to accelerate visualization. It differs from [Wavelet-based Volume Rendering](1052-wavelet-based-volume-rendering.md) by using spatial tiling rather than frequency-domain compression. Choose this for medical imaging applications where window/level adjustments are frequent.

### [Active Cut Management](3380-active-cut-management.md)
A view-dependent LOD technique that dynamically maintains a set of octree nodes (the "active cut") covering the model space. It performs frame-by-frame merges and splits based on screen-space error metrics, ensuring texel sizes remain close to one pixel. Choose this for interactive exploration where visual fidelity must be tightly coupled to screen resolution.

### [LOD Selection and Culling](5338-lod-selection-and-culling.md)
Focuses on the decision logic and data management (streaming, caching, hysteresis) required to switch between resolutions and discard invisible regions. It distinguishes itself by focusing on the *selection* and *culling* rather than the mathematical generation of the hierarchy. Choose this to implement the runtime logic for any multiresolution system.

### [Upsampling and Super-Resolution](5339-upsampling-and-super-resolution.md)
Increases spatial resolution of volumetric data or rendered images to recover fine details or correct discrete positioning errors. It is distinguished by its goal of generating higher-fidelity representations from lower-resolution inputs through geometric remapping or learning-based refinement. Choose this when enhancing low-resolution renders or correcting aliasing artifacts.

### [Wavelet-based Multiresolution](6266-wavelet-based-multiresolution.md)
Encompasses techniques that decompose volumetric data into spatial-frequency components using wavelet transforms. It differs from spatial methods like [VoxelGrid Down Sample](1014-voxelgrid-down-sample.md) by operating in the frequency domain to preserve high-frequency details at coarse resolutions. Choose this for compression-aware rendering or when frequency-domain analysis is beneficial.

### [Adaptive Resolution Data Management](8131-adaptive-resolution-data-management.md)
Not given in the sources.

### [Adaptive-FAM](8156-adaptive-fam.md)
A functional approximation multi-resolution representation that uses adaptive encoding to dynamically compress micro-blocks based on their content, designed for out-of-core interactive visualization of large-scale volumetric datasets. Choose this for out-of-core rendering where content-adaptive compression is needed.

#### Patch Merging Layer
Downsamples spatial resolution by half while doubling channels by concatenating four overlapping spatial patches [S3, unofficial].
*   **Step:** Verify input dimensions are even: `assert H % 2 == 0 and W % 2 == 0`. Reshape to spatial: `x = x.view(B, H, W, C)`. Extract four overlapping patches: `x0 = x[:, 0::2, 0::2, :]`, `x1 = x[:, 1::2, 0::2, :]`, `x2 = x[:, 0::2, 1::2, :]`, `x3 = x[:, 1::2, 1::2, :]`. Concatenate along channel dimension: `x = torch.cat([x0, x1, x2, x3], -1)`. Reshape to sequence: `x = x.view(B, -1, 4 * C)`. Apply normalization: `x = self.norm(x)`. Apply linear reduction to halve channels: `x = self.reduction(x)` [S3, unofficial].
*   **Parameter:** `input_resolution` (H, W), `dim` (input channels), `norm_layer` (default `nn.LayerNorm`) [S3, unofficial].
*   **Layout:** Input `x`: shape `(B, H*W, C)`. Output `x`: shape `(B, H/2*W/2, 2*dim)` [S3, unofficial].

#### iNGP Hierarchy Configuration
Uses 10 grid scales spaced by powers of 2 from 16 to 8192, with 4 channels per level [S4]. Grid sizes $n_l > 128$ are parameterized using a hash of size $128^3$ [S4]. This configuration (4 channels, powers of 2 spacing) works slightly better and faster than iNGP's similar approach (2 channels, spacing by $\sqrt{2}$) [S4].

#### World Dimension Constants and Hierarchy
Defines a hierarchical structure for a voxel world: `BRICK_DIM`: 4, `BRICK_VOXELS`: 64. `WORLD_BRICKS_X`: 128, `WORLD_BRICKS_Y`: 64, `WORLD_BRICKS_Z`: 128 (Total: 1,048,576 bricks). `WORLD_VOXELS_X`: 512, `WORLD_VOXELS_Y`: 256, `WORLD_VOXELS_Z`: 512. `WORLD_TILES_X`: 32, `WORLD_TILES_Y`: 16, `WORLD_TILES_Z`: 32 (Total: 16,384 tiles). `WORLD_CHUNKS_X`: 8, `WORLD_CHUNKS_Y`: 4, `WORLD_CHUNKS_Z`: 8 (Total: 256 chunks). `WORLD_L4_X`: 2, `WORLD_L4_Y`: 1, `WORLD_L4_Z`: 2 (Total: 4 L4 nodes). `PROBE_SPACING`: 8 voxels. `PROBE_DIM_X`: 64, `PROBE_DIM_Y`: 32, `PROBE_DIM_Z`: 64 (Total: 131,072 probes). `STORAGE_CHUNK_BRICKS`: 8. `STORAGE_CHUNK_VOXELS`: 32. `WORLD_STORE_CX`: 16, `WORLD_STORE_CY`: 8, `WORLD_STORE_CZ`: 16 (Total: 2,048 storage chunks) [S5, unofficial].

#### Parallel Multiresolution
A parallel multiresolution technique proposed by Gao et al. to accelerate large dataset visualization [S6].

#### Level of Detail Calculation
Calculates LOD level using: `level = MaxLevels - 1 + log2(width)`. `level0 = ceil(level)`, `plevel0 = level - level0`. `level1 = floor(level)`, `plevel1 = level1 - level` [S7].

#### Importance-based MIP Compositing
A compositing model that selects the current valid level of sparseness based on the associated volume object's importance [S8, unofficial].

## Background
Multiresolution representations in volume rendering originated from the need to handle increasingly large datasets in medical imaging and scientific visualization [S1, unofficial]. Early work focused on spatial hierarchies like octrees [S2, unofficial]. Wavelet-based methods were introduced to exploit frequency-domain sparsity for compression and adaptive rendering [S2, S3, unofficial]. The advent of GPU hardware accelerated the adoption of texture-based mipmaps and brick-based decompositions [S2, S3, unofficial]. Recent developments include neural radiance fields (NeRF) with hierarchical grid structures (e.g., iNGP) and out-of-core streaming techniques for interactive visualization of massive datasets [S4][S5, unofficial][S6].
