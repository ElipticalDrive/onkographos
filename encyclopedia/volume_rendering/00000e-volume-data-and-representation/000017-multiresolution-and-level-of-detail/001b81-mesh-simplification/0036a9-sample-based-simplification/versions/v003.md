# Sample-based Simplification
Also called: HAVS-based Simplification

## Overview
Sample-based simplification reduces geometric complexity for unstructured tetrahedral meshes during volume rendering by selectively removing triangle primitives instead of resampling the domain [S1, unofficial][S2, unofficial]. It differs from domain-based simplification, which resamples the domain via edge-collapses, by operating directly on the rendered primitives and preserving the original mesh topology [S1, unofficial][S2, unofficial]. The method is designed for interactive rendering within the HAVS volume rendering system [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh represented by its triangular faces [S1, unofficial][S2, unofficial].
*   **Output:** A subset of the original triangle indices to be rendered [S1, unofficial][S2, unofficial].

**Data Structures:**
1.  **Triangle Index List:** An array of all triangle indices from the tetrahedral mesh, sorted by importance [S1, unofficial][S2, unofficial].
2.  **Boundary Triangles:** The set of triangles on the mesh boundary, identified during preprocessing [G].
3.  **Internal Triangle Limit:** A runtime parameter controlling the maximum number of non-boundary triangles to render [S1, unofficial][S2, unofficial].

**Numbered Steps:**
1.  **Preprocessing:** Compute an importance heuristic for every triangle in the mesh [S1, unofficial][S2, unofficial].
2.  **Sorting:** Maintain a list of triangle indices sorted by importance in descending order [S1, unofficial][S2, unofficial].
3.  **Runtime Selection:** Identify all boundary triangles of the mesh [G]. Select a dynamically adjusted number of internal triangles from the sorted list, prioritizing higher importance [S1, unofficial][S2, unofficial].
4.  **Rendering:** Draw the union of the boundary triangles and the selected internal triangles [S1, unofficial][S2, unofficial].

**Pseudocode:**
```python
def preprocess(mesh):
    """
    mesh: Object with a `triangles` attribute (list of triangle objects).
    Returns:
        sorted_indices: List of triangle indices sorted by importance (descending).
        boundary_indices: Set of triangle indices on the mesh boundary.
    """
    # Mesh traversal details are not provided in the sources [G]
    all_indices = list(range(len(mesh.triangles)))
    importance_scores = [0.0] * len(all_indices)
    # Heuristic computation details are not provided in the sources [G]
    sorted_indices = sorted(all_indices, key=lambda i: importance_scores[i], reverse=True)
    boundary_indices = set()
    # Boundary detection logic is not provided in the sources [G]
    return sorted_indices, boundary_indices

def render_step(sorted_indices, boundary_indices, max_internal_triangles):
    """
    sorted_indices: Pre-sorted list of triangle indices.
    boundary_indices: Set of boundary triangle indices.
    max_internal_triangles: Dynamic limit on internal triangles to render.
    Returns:
        render_set: List of triangle indices to draw.
    """
    render_set = set(boundary_indices)
    internal_count = 0
    for idx in sorted_indices:
        if idx not in boundary_indices:
            if internal_count < max_internal_triangles:
                render_set.add(idx)
                internal_count += 1
            else:
                break
    return list(render_set)
```

**Parameters:**
*   **max_internal_triangles:** The maximum number of non-boundary triangles to include. This value is adjusted dynamically during interaction [S1, unofficial][S2, unofficial]. Typical values are not given in the sources.

**Edge Cases and Pitfalls:**
*   **Boundary Definition:** The exact topological criteria for boundary detection are not specified in the sources [G].
*   **Dynamic Adjustment:** The method relies on an unspecified heuristic to adjust `max_internal_triangles` in real-time [S1, unofficial][S2, unofficial].
*   **Heuristic Accuracy:** Selection quality depends entirely on the accuracy of the importance heuristic, which is not detailed in the sources [G].

## Subtopics

### HAVS Volume Rendering
The underlying rendering system that operates on triangle faces of tetrahedral meshes [S1, unofficial][S2, unofficial]. It provides the context for why triangle-level simplification is effective [G]. Choose it when rendering unstructured tetrahedral meshes interactively [G]. [HAVS](1000-havs-volume-rendering.md)

### Domain-based Simplification
The alternative approach that resamples the domain using edge-collapses [S1, unofficial][S2, unofficial]. Sample-based simplification is distinct because it removes primitives directly without modifying the underlying domain structure [S1, unofficial][S2, unofficial]. Choose it when domain resampling is preferred over primitive removal [G]. [Domain-based](1032-mesh-simplification.md)

## Operating characteristics
*   **Time Complexity:** Preprocessing sorting is $O(N \log N)$ where $N$ is the triangle count [G]. Runtime selection is $O(K)$ where $K$ is the number of selected triangles [G].
*   **Memory Complexity:** Requires $O(N)$ storage for importance scores and the sorted index list [G].
*   **Performance:** Optimized for interactive rendering of large datasets [S1, unofficial][S2, unofficial].
*   **Strengths:** Does not modify mesh topology; suitable for dynamic data contexts [S1, unofficial][S2, unofficial].
*   **Limitations:** Not given in the sources.
*   **When to Use:** Not given in the sources.
*   **When Not to Use:** Not given in the sources.

## Background
Sample-based simplification was introduced by Callahan et al. as an alternative to domain-based simplification for volume rendering of unstructured grids [S1, unofficial][S2, unofficial]. It is built upon the HAVS system, which operates on triangle faces of tetrahedral meshes [S1, unofficial][S2, unofficial]. The method was developed to address interactive visualization challenges for large, time-varying, and dynamic datasets [S1, unofficial][S2, unofficial].
