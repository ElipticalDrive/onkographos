# Static Level of Detail Generation via Vertex Clustering

Also called: Vertex Clustering LOD

## Overview
This method is a preprocessing technique that computes static levels of detail (LOD) for each node in an octree using vertex clustering, enabling the selection of appropriate geometric detail based on expected image contribution at runtime [S1, unofficial]. It differs from its sibling methods by prioritizing simplicity and I/O efficiency over topological complexity, specifically avoiding the need for adjacency graphs and multiple data traversals [S1, unofficial].

## How it works
**Inputs:** A pre-triangulated mesh geometry associated with an octree node [S1, unofficial].
**Outputs:** A set of $L$ simplified mesh approximations for the node, where $L$ is the number of LOD levels [S1, unofficial].

**Data Structures:**
*   **Vertex List:** Array of vertices $V$ [G].
*   **Face List:** Array of faces $F$, where each face is defined by three vertex indices [G].
*   **LOD Levels:** A list of meshes $M_0, M_1, \dots, M_{L-1}$, where $M_0$ is the original geometry [S1, unofficial].

**Parameters:**
*   $L$: Number of successive approximations per node. Typical value: 3 to 5 [S1, unofficial].
*   $R$: Target reduction ratio for each successive LOD level compared to the previous one. Typical value: $1/4$ [S1, unofficial].

**Algorithm Steps:**

1.  **Initialize:** Set $M_0$ to the original mesh geometry of the octree node [S1, unofficial].
2.  **Iterate for LOD Generation:** For $i$ from 1 to $L-1$:
    a.  **Vertex Grading:** For each vertex $v$ in the current mesh $M_{i-1}$, compute a grading weight $w(v)$ [S1, unofficial].
        *   Let $F(v)$ be the set of faces incident to vertex $v$ [G].
        *   Let $Area(f)$ be the area of face $f$ [G].
        *   Compute $w(v) = \max_{f \in F(v)} Area(f)$ [S1, unofficial].
        *   *Note:* The angle between incident edges is ignored because the dataset is pre-triangulated, making edge-angle metrics misleading [S1, unofficial].
    b.  **Vertex Clustering:** Apply the vertex clustering simplification algorithm using the weights $w(v)$ to determine which vertices to collapse or remove [S1, unofficial]. The goal is to reduce the vertex count of $M_{i-1}$ by approximately the factor $R$ to produce $M_i$ [S1, unofficial].
    c.  **Error Bound Check:** Ensure the Hausdorff distance between $M_{i-1}$ and $M_i$ remains within acceptable bounds [S1, unofficial]. The error is bounded by an intuitive, user-controlled accuracy parameter inherent to the clustering grid size [S1, unofficial].
3.  **Runtime Selection:** When rendering, for each visible octree node, calculate its expected contribution to the image quality [S1, unofficial]. Select the LOD level $M_i$ that best matches this contribution [S1, unofficial].

**Pseudocode:**

```python
def generate_lod_levels(mesh, num_lod_levels=4, reduction_ratio=0.25):
    """
    Generates static LOD levels for a mesh using vertex clustering.
    
    Args:
        mesh: The initial triangulated mesh (vertices and faces).
        num_lod_levels: Number of LOD approximations to precompute (including original).
        reduction_ratio: Target ratio of vertices in next LOD vs current.
        
    Returns:
        list of meshes: [M_0, M_1, ..., M_{num_lod_levels-1}]
    """
    lod_meshes = [mesh]
    current_mesh = mesh
    
    for i in range(1, num_lod_levels):
        # Step 1: Grade vertices by maximum incident face area
        vertex_weights = {}
        for v in current_mesh.vertices:
            incident_faces = get_incident_faces(v, current_mesh)
            if not incident_faces:
                vertex_weights[v] = 0.0
            else:
                max_area = max(face_area(f) for f in incident_faces)
                vertex_weights[v] = max_area
        
        # Step 2: Vertex Clustering Simplification
        # Implements grid-based vertex clustering with weighted priority.
        # Grid cell size is derived from the desired reduction ratio and bounding box.
        target_count = max(1, int(len(current_mesh.vertices) * reduction_ratio))
        next_mesh = vertex_clustering_simplify(current_mesh, vertex_weights, target_count)
        
        lod_meshes.append(next_mesh)
        current_mesh = next_mesh
        
    return lod_meshes

def get_incident_faces(vertex, mesh):
    """Returns list of faces containing the vertex."""
    return [f for f in mesh.faces if vertex in f.vertices]

def face_area(face):
    """Calculates area of a triangular face."""
    p1, p2, p3 = face.vertices
    return 0.5 * length(cross(p2 - p1, p3 - p1))

def vertex_clustering_simplify(mesh, vertex_weights, target_count):
    """
    Performs grid-based vertex clustering.
    Vertices are snapped to a grid; overlapping vertices are merged.
    Higher weighted vertices are preferred during merging to preserve detail.
    """
    # Compute bounding box to determine grid cell size
    min_pt = min(v.position for v in mesh.vertices)
    max_pt = max(v.position for v in mesh.vertices)
    extent = max_pt - min_pt
    num_cells = int(round(pow(target_count, 1.0/3.0)))
    cell_size = max(extent.x, extent.y, extent.z) / num_cells
    
    # Hash vertices to grid cells
    grid = {}
    for v in mesh.vertices:
        # Compute grid cell coordinates
        cx = int((v.position.x - min_pt.x) / cell_size)
        cy = int((v.position.y - min_pt.y) / cell_size)
        cz = int((v.position.z - min_pt.z) / cell_size)
        key = (cx, cy, cz)
        if key not in grid:
            grid[key] = []
        grid[key].append(v)
        
    # Merge vertices in each cell, keeping the one with highest weight
    kept_vertices = []
    for cell_verts in grid.values():
        best_v = max(cell_verts, key=lambda v: vertex_weights.get(v, 0.0))
        kept_vertices.append(best_v)
        
    # Rebuild faces using only kept vertices
    v_to_new_idx = {v: i for i, v in enumerate(kept_vertices)}
    new_faces = []
    for f in mesh.faces:
        if all(v in v_to_new_idx for v in f.vertices):
            new_faces.append(Face([v_to_new_idx[v] for v in f.vertices]))
            
    return Mesh(kept_vertices, new_faces)
```

**Edge Cases and Pitfalls:**
*   **Pre-triangulated Data:** Using the original Rossignac and Borrel factors (longest edge, max angle) on pre-triangulated data yields misleading results [S1, unofficial]. The maximum incident face area metric is required [S1, unofficial].
*   **I/O Bound Systems:** Since vertex clustering requires only one data traversal, it is preferred over methods requiring multiple passes or complex topological structures [S1, unofficial].

## Subtopics

### Comparison with Rossignac and Borrel Grading
Rossignac and Borrel's original method grades vertices by the longest incident edge length and the maximum angle between incident edges [S1, unofficial]. This method replaces those with the maximum area of incident faces [S1, unofficial]. The change is necessary because edge-angle metrics are unreliable for pre-triangulated datasets, which are common in volume rendering contexts [S1, unofficial].

### Comparison with Lindstrom's Algorithm
This method is chosen over Lindstrom's algorithm [81, 84] because vertex clustering is simpler, faster, and requires only a single data traversal, which is critical for I/O-bound systems [S1, unofficial]. It also produces bounded Hausdorff error and does not require maintaining topological adjacency graphs [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of vertices and faces in the node, as it requires only one traversal for clustering [S1, unofficial].
*   **Memory Complexity:** Proportional to the sum of the sizes of all LOD levels [G]. With a reduction ratio of $1/4$, the total memory is dominated by the original mesh, with subsequent levels adding negligible overhead [S1, unofficial].
*   **Performance:** The simplification is fast enough to be performed after the node is loaded into memory, but the single-traversal nature makes it particularly efficient for out-of-core systems where disk I/O is the bottleneck [S1, unofficial].
*   **Strengths:** Robustness (no assumptions about geometry), simplicity, bounded error, and suitability for interactive previewers [S1, unofficial].
*   **Limitations:** The quality is "good enough" but not optimal compared to more sophisticated, slower methods [S1, unofficial]. It is static, so it cannot adapt to dynamic changes in the geometry [S1, unofficial].

## Background
This method is described in the thesis "New Techniques for Out-Of-Core Visualization of Large Datasets" by Wagner Correa [S1, unofficial]. It builds upon the vertex clustering algorithm by Rossignac and Borrel [112] and adapts it for the specific needs of out-of-core volume rendering, where I/O efficiency and robustness are paramount [S1, unofficial]. The approach was selected to provide a fast, reliable way to generate LODs for large datasets that are often already triangulated [S1, unofficial].
