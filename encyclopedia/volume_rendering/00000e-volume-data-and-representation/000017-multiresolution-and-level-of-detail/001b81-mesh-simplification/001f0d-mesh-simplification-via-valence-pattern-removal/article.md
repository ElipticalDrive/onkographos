# Mesh simplification via valence pattern removal

Also called: Quad mesh post-processing, Valence-based simplification

## Overview
This method reduces the element count of quad-dominant meshes, specifically those generated by the Dual Marching Cubes (DMC) algorithm, by identifying and removing specific quadrilateral valence patterns: **3-X-3-Y** and **3-3-3-3** [S1]. It solves the problem of excessive mesh complexity and poor element quality caused by transitions between volume data layers [S1]. Unlike general decimation methods, this approach is optional, parallelized using face coloring to avoid race conditions, and specifically targets topological artifacts inherent to the DMC representation [S1]. It improves mesh quality and repositions vertices while reducing element count by approximately 10% for datasets like human skulls and skeletons [S1].

## How it works
The method operates on a mesh represented by a halfedge data structure, where faces have consistent orientation (halfedges pointing in opposite directions connect to form faces with the same orientation) [S1]. The simplification is performed in two distinct phases, one for each pattern type.

### Data Structures
*   **Halfedge Structure**: Stores connectivity. Halfedges are paired such that opposite halfedges belong to the same face boundary, ensuring consistent face orientation [S1].
*   **Face Coloring**: An implicit coloring scheme derived from the DMC method is used to assign a color ID to each element. This is critical for parallel execution to avoid race conditions when marking and removing elements [S1].
*   **Valence Buffer**: An integer buffer with one entry per vertex, storing the computed valence (number of incident edges) [S1].
*   **Removal Markers**: Boolean or integer flags indicating whether a vertex or element is marked for removal [S1].
*   **Counter Buffer**: For the 3-X-3-Y pattern, an integer buffer with one entry per vertex acts as a counter. It tracks how many quadrilaterals with the 3-X-3-Y pattern share a specific valence-3 vertex [S1].

### Pattern 3-X-3-Y Removal
This pattern consists of a quadrilateral where two non-consecutive vertices have valence 3, and the other two have valence $\ge 5$ [S1]. Removing this pattern merges the two valence-3 vertices into a single new vertex and removes the quadrilateral element [S1].

**Steps:**
1.  **Compute Vertex Valence**: A kernel iterates through all halfedges. For each halfedge, it increments the valence of its associated vertex using an atomic addition operation (`atomicAdd()`) [S1].
2.  **Mark Elements (Initial)**: A kernel processes elements. An element with the 3-X-3-Y pattern is marked for removal if no neighboring element has a lower color ID than the element itself [S1].
3.  **Remove Marked Elements**: The marked elements are removed by merging the two valence-3 vertices into a new vertex [S1].
4.  **Find Remaining Elements**: A buffer with an integer entry per vertex and a counter is used. The counter tracks how often quadrilaterals with the 3-X-3-Y pattern share a valence-3 vertex. This identifies remaining elements that share these vertices with already-processed neighbors [S1].
5.  **Remove Remaining Elements**: Elements are removed if no neighboring element has the same valence pattern (i.e., none of the valence-3 vertices is shared with another element marked for removal in this step) [S1].
6.  **Remove Vertices**: A vertex-wise kernel copies vertices to a new buffer if they are not marked for removal. It maps old vertex indices to new indices [S1].
7.  **Remove Elements**: An element-wise kernel copies quadrilaterals to a new element buffer if not marked for removal. It uses the index mapping from the previous step to connect vertices forming the new quadrilaterals [S1].
8.  **Re-build Halfedge**: The halfedge data structure is rebuilt to reflect the new connectivity [S1].

### Pattern 3-3-3-3 Removal
This pattern consists of a quadrilateral where all four vertices have valence 3 [S1]. Removing this pattern involves collapsing edges, moving the vertices of the red element toward the vertices of the blue neighbors (as described in the source's Fig. 8b), and removing the central element and its four neighbors [S1].

**Steps:**
1.  **Compute Vertex Valence**: Same as Step 1 for 3-X-3-Y [S1].
2.  **Mark Vertices and Elements**: A kernel processes the mesh element-wise. For each element, it tests if all four vertices have valence 3. If so, it reconstructs the complete neighborhood. The element and its four neighbors are marked for removal if:
    *   The element does not have a neighbor with the same valence pattern.
    *   The element does not form a non-manifold configuration (specifically, two quadrilaterals sharing the same four vertices, as shown in the source's Fig. 8c) [S1].
3.  **Remove Vertices**: Same as Step 6 for 3-X-3-Y [S1].
4.  **Remove Elements**: Same as Step 7 for 3-X-3-Y [S1].
5.  **Re-compute Halfedge**: The halfedge data structure is recomputed [S1].

### Pitfalls and Edge Cases
*   **Non-removable 3-3-3-3**: Elements with the 3-3-3-3 pattern cannot be removed if two neighboring elements also have the same valence pattern (e.g., faces of a hexahedron) [S1].
*   **Non-manifold Configuration**: Elements cannot be removed if they form a configuration where two quadrilaterals share the same four vertices, as this results in a non-manifold mesh [S1].
*   **Race Conditions**: Parallel removal requires the face coloring scheme to avoid race conditions when marking and removing elements [S1].

## Operating characteristics
*   **Complexity**: The algorithm uses CUDA kernels, indicating GPU acceleration. Complexity is linear with respect to the number of vertices, edges, and elements for each kernel pass [S1].
*   **Performance**: The simplification reduces the element count by approximately 10% for human skull and skeleton datasets [S1]. It eliminates one vertex and one element for the 3-X-3-Y pattern, and four vertices and one element for the 3-3-3-3 pattern [S1].
*   **Strengths**: Improves mesh quality, repositions vertices, and reduces element count efficiently in parallel [S1].
*   **Limitations**: Only applicable to quad-dominant meshes generated by DMC. It is an optional step [S1].
*   **When to use**: When using DMC for volume rendering and mesh quality/size is a concern.
*   **When not to use**: When the mesh is not quad-dominant or when the DMC method is not used.

## Background
The method is based on the Dual Marching Cubes (DMC) algorithm for quad-only surface reconstruction [S1]. The valence patterns 3-X-3-Y and 3-3-3-3 are well-known in quad mesh post-processing [S1]. The novelty of this approach is the efficient parallel implementation using the implicit face coloring of the DMC method [S1]. The work was published in 2021 [S1].
