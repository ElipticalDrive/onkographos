# Hoppe's Progressive Mesh Simplification

Also called: Hoppe's Simplification, Mesh Simplification for Multiresolution, Progressive Mesh Simplification

## Overview
Hoppe's Progressive Mesh Simplification is an iterative edge-collapse algorithm that generates a hierarchy of coarse meshes from a high-resolution input by removing geometric details while preserving main structural folds [S1]. It distinguishes itself from sibling methods like Quadric Error Metrics by using a simplified error metric based solely on edge length to ensure an even vertex distribution, and by collapsing edges to their geometric midpoint to minimize self-intersection risks and computational cost [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A triangular mesh $M_0 = (V_0, F_0)$ with vertex positions $V_0$ and face connectivity $F_0$.
*   **Output:** A sequence of meshes $M_0, M_1, \dots, M_k$ representing a multiresolution hierarchy, where each $M_{i+1}$ is derived from $M_i$ by a single edge collapse.

**Data Structures:**
*   **Edge List:** A collection of all edges in the current mesh. Each edge $e$ stores its two endpoint vertices $v_a, v_b$ and its computed error cost $c_e$.
*   **Priority Queue (Heap):** A min-heap ordered by error cost $c_e$, allowing efficient retrieval of the lowest-cost edge.
*   **1-Ring Neighbor Structure:** For each vertex, a list of adjacent vertices and faces, required to update connectivity after a collapse.

**Error Metric:**
The error cost for an edge is defined simply as its Euclidean length [S1]:
$$ c_e = \| v_a - v_b \|_2 $$
Unlike metrics that preserve sharp features, this metric aims to remove details uniformly, even in high-curvature regions, to create an even distribution of vertices [S1].

**Algorithm Steps:**
1.  **Initialization:** Compute the length of every edge in the input mesh $M_0$. Insert all edges into the priority queue $Q$ with their corresponding costs.
2.  **Iteration:** While $Q$ is not empty:
    a.  Pop the edge $e = (v_a, v_b)$ with the minimum cost from $Q$.
    b.  **Consistency Check:** Verify topological consistency using Hoppe's consistency checks [S1]. These checks analyze the neighborhood of the collapse to ensure the resulting mesh remains a valid manifold (e.g., no non-manifold edges, boundary issues, or self-intersections introduced by the topology change). If the check fails, discard $e$ and continue to the next iteration.
    c.  **Collapse:** If valid, collapse $e$ by merging $v_a$ and $v_b$ into a new vertex $v_{new}$.
    d.  **Position:** Set the position of $v_{new}$ to the geometric midpoint of $v_a$ and $v_b$:
        $$ p_{new} = \frac{p_a + p_b}{2} $$
        Optimization of the position is explicitly avoided to keep computation costs low and minimize self-intersection risk [S1].
    e.  **Update Connectivity:** Remove faces incident to the collapsed edge. Update the 1-ring neighbor structure for all vertices affected by the change (the 1-ring and 2-ring neighbors of the collapsed edge) [S1].
    f.  **Re-evaluate:** Recompute the costs for all edges incident to the updated vertices and update their positions in $Q$.

**Pseudocode:**
```python
def hoppe_simplification(mesh):
    # mesh.vertices: list of 3D points
    # mesh.faces: list of tuples (v1, v2, v3)
    
    # 1. Build edge list and heap
    edges = {}
    heap = []
    
    for f in mesh.faces:
        for i in range(3):
            v1 = f[i]
            v2 = f[(i + 1) % 3]
            # Ensure canonical edge representation (sorted vertices)
            edge_key = tuple(sorted([v1, v2]))
            if edge_key not in edges:
                cost = distance(mesh.vertices[v1], mesh.vertices[v2])
                edges[edge_key] = (v1, v2, cost)
                heapq.heappush(heap, (cost, edge_key))
    
    # 2. Iterative collapse
    while heap:
        cost, edge_key = heapq.heappop(heap)
        
        # Skip if edge was already removed or invalidated
        if edge_key not in edges:
            continue
            
        v1, v2, _ = edges[edge_key]
        
        # 3. Consistency Check
        if not is_topologically_consistent(mesh, v1, v2):
            continue
            
        # 4. Collapse to midpoint
        mid = (mesh.vertices[v1] + mesh.vertices[v2]) / 2.0
        
        # Update geometry
        # Note: In a real implementation, we might merge v1 and v2 into one vertex
        # For simplicity, we assume v1 remains and v2 is removed/merged
        mesh.vertices[v1] = mid
        
        # 5. Update topology and neighbors
        # Remove faces containing both v1 and v2
        # Add new faces connecting the 1-ring neighbors
        # Update 1-ring neighbor structures for affected vertices
        update_mesh_topology(mesh, v1, v2)
        
        # 6. Update costs for affected edges
        affected_edges = get_affected_edges(mesh, v1)
        for e_key in affected_edges:
            if e_key in edges:
                ev1, ev2, _ = edges[e_key]
                new_cost = distance(mesh.vertices[ev1], mesh.vertices[ev2])
                edges[e_key] = (ev1, ev2, new_cost)
                # Re-heapify or update priority (implementation dependent)
                heapq.heappush(heap, (new_cost, e_key))
                
    return mesh
```

**Edge Cases and Pitfalls:**
*   **Self-intersections:** Mitigated by using the midpoint rather than an optimized position [S1].
*   **Topological Inconsistency:** The consistency checks are critical; failing to implement them correctly can result in non-manifold meshes or holes [S1].
*   **Precision:** Floating-point precision in midpoint calculation should be handled to avoid accumulation errors in deep hierarchies [G].

## Subtopics

### Quadric Error Metrics Simplification
Introduced by Garland and Heckbert in 1997, this method uses a quadric error metric to measure the distance of vertices to the planes of adjacent faces, allowing for optimized vertex positions that minimize geometric error [S2, unofficial]. It is preferred when preserving sharp features and minimizing geometric distortion is more important than computational speed or even vertex distribution. Hoppe's method is simpler and faster but less accurate in preserving fine details [S1][S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(E \log E)$ for initial heap construction, where $E$ is the number of edges. Each collapse involves heap operations and neighbor updates, which are generally efficient but depend on the degree of the affected vertices.
*   **Memory Complexity:** $O(V + E)$ to store the mesh and the priority queue.
*   **Performance:** The use of a simple length-based metric and midpoint collapse makes it computationally inexpensive compared to quadric metrics, which require matrix operations for position optimization [S1].
*   **Strengths:** Fast execution, low risk of self-intersection, produces a smooth, even distribution of vertices [S1].
*   **Limitations:** Does not preserve sharp edges or fine geometric details as well as quadric metrics; the resulting mesh may deviate more from the original surface in high-curvature regions [S1].
*   **When to use:** When a fast, robust simplification is needed for multiresolution visualization or segmentation, and exact geometric fidelity is secondary to topological consistency and speed [S1].
*   **When not to use:** When preserving sharp features or minimizing geometric error is critical; use Quadric Error Metrics instead [S2, unofficial].

## Background
The progressive mesh representation was introduced by Hugues Hoppe in 1996 [S1]. The specific simplification algorithm described here, which uses edge collapse to the midpoint with a length-based error metric, is cited in the context of hierarchical isosurface segmentation for brain cortex models [S1]. The broader field of quadric error metrics was pioneered by Garland and Heckbert in 1997, with extensions by Hoppe in 1999 for appearance attributes [S2, unofficial].
