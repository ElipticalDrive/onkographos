# Streaming Simplification Algorithm

Also called: Buffer-based simplification, Out-of-core Tetrahedral Simplification, Out-of-core streaming simplification, Single-pass streaming simplification, Streaming Simplification of Tetrahedral Meshes, Streaming Tetrahedral Mesh Simplification

## Overview
The Streaming Simplification Algorithm simplifies large tetrahedral meshes by processing them sequentially from disk through a fixed-size in-core buffer, minimizing memory usage to handle datasets exceeding available RAM [S1]. Unlike in-core methods that require the entire connectivity graph in memory, this method performs edge collapses on localized portions using a quadric error metric while preserving the coherent stream order of the mesh for downstream processing [S1]. It distinguishes itself from other streaming approaches by ensuring the output stream remains coherent and by using a randomized edge selection strategy that avoids the "locked state" issues common in greedy priority-queue methods [S1].

## How it works
The algorithm operates in a single pass over the mesh data, converting standard indexed meshes into a streaming format, loading portions into a fixed-size buffer, simplifying them, and writing the result back to disk or a downstream module [S1].

### Inputs and Outputs
*   **Input:** A tetrahedral mesh stored in a streaming format (e.g., Breadth-First layout) on disk, containing vertex positions, scalar field values, and connectivity.
*   **Output:** A simplified tetrahedral mesh in the same streaming format, with a target reduction ratio applied.

### Data Structures
The method uses statically allocated data structures to avoid dynamic memory allocation during simplification [S1].

1.  **Streaming Mesh Format:**
    *   Tetrahedra are laid out on disk to support coherent sequential access. A Breadth-First layout is recommended to minimize the "front width" (active vertices) [S1].
    *   Vertices are marked as "finalized" once they are no longer part of the current in-core buffer's boundary [S1].

2.  **In-Core Buffer:**
    *   A fixed-size circular array or auxiliary hash table maps global vertex indices to in-core buffer indices. Due to the low-span layout, modular arithmetic is used for indexing, with collisions handled by an auxiliary hash [S1].
    *   The buffer size is $O(\text{width})$, where width is the front width of the mesh layout. In practice, 20 MB suffices for 14 million tetrahedra [S1].

3.  **Corner Table Extension:**
    *   Extends Rossignac’s corner table for tetrahedra [S1].
    *   Replaces the 'opposite' corner array $O$ with a link table $L$ of equal size. $L$ joins all corners of a given vertex in a circular linked list.
    *   Each vertex stores an index to one of its corners and quadric error information $(A, p, \epsilon)$ [S1].
    *   Memory usage: 69 bytes per vertex, 37 bytes per tetrahedron [S1].

4.  **Quadric Representation (Lindstrom):**
    *   Parameterization $(A, p, \epsilon)$ where the quadric error is:
        $$Q(x) = (x - p)^T A (x - p) + \epsilon$$
    *   $A$ is the same as the standard representation. $p$ is the minimizer, and $\epsilon$ is the minimum error.
    *   Constraints: $Ap = b$ and $p^T Ap + \epsilon = c$ [S1].
    *   Benefits: Saves memory, provides stable evaluation near $p$, and offers a lower bound $\epsilon_i + \epsilon_j$ for collapse cost [S1].

5.  **Lazy Deletion Scheme:**
    *   Vertices and tetrahedra to be deleted are marked rather than removed immediately.
    *   At the end of each WRITE phase, a linear pass removes marked elements and compacts arrays [S1].

### Algorithm Steps
The simplification follows the READ, DECIMATE, WRITE loop proposed by Wu and Kobbelt [S1].

1.  **Preprocessing:**
    *   Normalize the scalar field to the geometry range [S1].
    *   Convert the standard indexed mesh to the streaming format. If not already done, reorder using a Breadth-First approach to improve streamability [S1].

2.  **Main Loop (READ, DECIMATE, WRITE):**
    *   **READ:** Load tetrahedra from disk into the in-core buffer until the buffer is full or the target reduction is met. Introduce new elements sequentially [S1].
    *   **DECIMATE:** Simplify the in-core portion using quadric-based edge collapses until the target ratio is reached or the buffer size is halved [S1].
    *   **WRITE:** Output simplified elements to disk. To maintain coherence, elements are output in an order that preserves the input stream sequence, delaying tetrahedra with non-finalized vertices [S1].

3.  **Stream Boundary Management:**
    *   The stream boundary is the interface between tetrahedra in memory and those not yet read or already output. It consists of faces where none of the three vertices are finalized [S1].
    *   **Constraint:** Disallow collapsing any edge that has one or both vertices on the stream boundary to prevent cracks [S1].

4.  **Quadric Initialization:**
    *   When reading a new set of tetrahedra, calculate their quadrics and distribute them to the vertices [S1].
    *   For finalized vertices, compute boundary quadrics for incident boundary faces (with no other finalized vertices) and distribute them to boundary vertices [S1].

5.  **Edge Collapse Selection (Randomized):**
    *   Instead of a priority queue, use a multiple-choice randomized approach with 8 candidates per collapse [S1].
    *   Find an edge by randomly picking a tetrahedron and two of its vertices [S1].
    *   **Optimization:** Avoid minimizing $Q_i + Q_j$ if the lower bound $\epsilon_i + \epsilon_j$ exceeds the smallest quadric error found so far [S1].

6.  **Solving for Collapse Position:**
    *   Solve the linear system $Ax = b$ for the new vertex position.
    *   Use an adapted Conjugate Gradient (CG) solver for positive semidefinite systems [S1].
    *   Initialize the solver with $x = (p_i + p_j) / 2$ [S1].
    *   Preempt the solver when conjugate directions are insignificant or when the condition number exceeds $\epsilon_{max}$ [S1].

7.  **Numerical Stability:**
    *   Compute the matrix $A$ using a 4D "volume normal" to ensure positive semidefiniteness, avoiding indefinite matrices caused by roundoff errors in subtraction [S1].
    *   The 4D volume normal $n$ is computed as:
        $$n = \det \begin{bmatrix} e_2 & e_3 & e_4 & e_1 \\ v_{1x} & v_{1y} & v_{1z} & v_{1s} \\ v_{2x} & v_{2y} & v_{2z} & v_{2s} \\ v_{3x} & v_{3y} & v_{3z} & v_{3s} \end{bmatrix}$$
        where $e_i$ is the $i$-th column of the $4 \times 4$ identity matrix, and $v_1, v_2, v_3$ are vectors from one vertex to the others. $A = n n^T$ [S1].

### Parameters
*   **Target Reduction:** Ratio of output tetrahedra to original tetrahedra. Typical values: 10% for standard datasets, 1.2% for fluid dynamics [S1].
*   **Boundary Weight:** Prevents shape change. Fixed value of 100 times the maximum field value in the data [S1].
*   **Buffer Size:** $O(\text{width})$. In practice, 20 MB RAM for 14 million tetrahedra [S1].
*   **Tolerance $\epsilon_{max}$:** Set to $10^4$. Allows single-precision floating-point usage [S1].
*   **Memory Limit:** Enforced via OS (e.g., Linux bootloader). Experiments used 64 MB RAM limit [S1].

## Subtopics

### Static Allocation for Streaming Simplification
This variant emphasizes the use of statically allocated data structures instead of dynamic allocations to increase efficiency and reduce memory footprint [S1]. The buffer size is $O(\text{width})$, depending on the width of the input mesh. In practice, a 14 million tetrahedra dataset was simplified using only 20 MB RAM [S1].

## Operating characteristics
*   **Time Complexity:** The algorithm runs in a single pass over the mesh data. Performance is approximately 60,000 tetrahedra per second on a 3.2 GHz Pentium 4 [S1].
*   **Memory Complexity:** Memory usage is $O(\text{width})$, where width is the front width of the mesh layout. It can simplify 14 million tetrahedra with only 20 MB RAM [S1]. For a 1 billion tetrahedron dataset, it used 829 MB RAM [S1].
*   **Measured Performance:**
    *   Fighter dataset (1.4M tetrahedra): Simplified to 10% resolution in-core on P4 2.2GHz with 1GB RAM [S1].
    *   Fluid dynamics dataset (1 billion tetrahedra): Simplified to 12 million tetrahedra (1.2%) in 10 hours using 829 MB RAM on a Xeon 3.0GHz machine [S1].
    *   Layout time: Laying out 14 million tetrahedra using Breadth-First approach took ~40 minutes [S1].
*   **Error:** On fluid dynamics dataset, 10.85% maximum and 1.57% RMS field error on measured subregions [S1].
*   **Strengths:** Handles meshes of arbitrary size; out-of-core operation; coherent output stream; high quality approximations; fast due to optimizations in data structures and solvers [S1].
*   **Limitations:** Error-driven output can fragment the buffer; ASCII I/O is slow (binary format recommended); buffer size affects quality (larger buffer allows wider selection range for randomization) [S1].
*   **When to use:** When the mesh is too large for main memory; when downstream processing requires a coherent stream; when high simplification ratios are needed [S1].
*   **When not to use:** When in-core memory is sufficient and faster in-core methods are preferred; when the mesh layout is not optimized for streaming (e.g., high width) [S1].

## Background
The Streaming Simplification Algorithm was introduced by H.T. Vo, S.P. Callahan, P. Lindstrom, and V. Pascucci in 2007 [S1]. It builds on previous streaming simplification methods by Wu and Kobbelt [18] and Lindstrom et al. [19, 20], improving upon them by ensuring output coherence and introducing optimizations in data structures and linear solvers [S1]. It is used for simplifying large tetrahedral meshes from scientific simulations and measurements, such as fluid dynamics and partial differential equation solutions [S1].
