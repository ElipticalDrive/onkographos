# Pruning Hierarchy Construction

Also called: Pruning Hierarchy

## Overview
The pruning hierarchy is a hierarchical representation of a contour tree derived from the branch decomposition, designed to reduce the branching factor and explicitly represent features at saddles [S1, unofficial]. It addresses the problem of the branch decomposition's high branching factor, which is unsuitable for user interface purposes, by expanding the tree structure in a controlled manner that keeps the branching factor manageable [S1, unofficial]. Unlike the branch decomposition, which concatenates sequences of arcs, the pruning hierarchy splits branches at saddle points to create a ternary-like structure, ensuring that features are added in strict order of importance [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A branch decomposition of a contour tree, where each branch stores its children in a list ordered by pruning sequence [S1, unofficial].
*   **Output:** A pruning hierarchy tree and an updated vertex-to-branch mapping [S1, unofficial].

**Data Structures:**
*   **Branch:** A node containing a list of child branches and a saddle value representing the isovalue at which the branch terminates [S1, unofficial].
*   **Queue:** A FIFO structure used to traverse and process branches sequentially [S1, unofficial].
*   **Vertex Mapping:** A data structure mapping dataset vertices to their containing branch, which must be invalidated and recomputed upon every split [S1, unofficial].

**Steps:**
1. Initialize a queue with the root branch [S1, unofficial].
2. Dequeue the current branch from the queue [S1, unofficial].
3. Identify the last child added to the current branch (the final element in its child list) [S1, unofficial].
4. Split the parent branch at the saddle point associated with this last child, dividing it into an upper section and a lower section [S1, unofficial].
5. Reallocate the remaining children of the parent branch to the new upper or lower branches based on whether their saddle points are above or below the first saddle of the first child [S1, unofficial].
6. Add the two new branches as siblings to the first child of the parent branch [S1, unofficial].
7. Add all three children (the original first child and the two new branches) to the queue for further processing [S1, unofficial].
8. Update the vertex-to-branch mapping by reassigning each vertex that mapped to the parent branch to one of the new children based on whether the vertex's data value is greater or less than the split saddle value [S1, unofficial].

**Pseudocode:**
```python
class Branch:
    def __init__(self, saddle_value=0.0):
        self.saddle_value = saddle_value
        self.children = []

def construct_pruning_hierarchy(root_branch, vertex_to_branch, vertex_data_values):
    queue = [root_branch]
    while queue:
        current = queue.pop(0)
        if not current.children:
            continue
            
        last_child = current.children[-1]
        split_val = last_child.saddle_value
        first_child = current.children[0]
        first_saddle = first_child.saddle_value
        
        # Remaining children are all except the first and the last
        remaining = current.children[1:-1]
        upper_children = [c for c in remaining if c.saddle_value > first_saddle]
        lower_children = [c for c in remaining if c.saddle_value <= first_saddle]
        
        new_upper = Branch(split_val)
        new_upper.children = upper_children
        new_lower = Branch(split_val)
        new_lower.children = lower_children
        
        current.children = [first_child, new_upper, new_lower]
        queue.extend([first_child, new_upper, new_lower])
        
        # Update vertex mapping for vertices previously mapped to the split branch
        for v_idx, mapped_branch in list(vertex_to_branch.items()):
            if mapped_branch is current:
                if vertex_data_values[v_idx] > split_val:
                    vertex_to_branch[v_idx] = new_upper
                else:
                    vertex_to_branch[v_idx] = new_lower
```

**Parameters:**
*   **Symbolic Perturbation:** A technique used to guarantee unique critical isovalues during topological computation, which are later removed from the contour tree [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Vertex Mapping Invalidation:** Splitting a branch invalidates the existing vertex-to-branch mapping, requiring an explicit update step [S1, unofficial].
*   **Memory Usage:** The pruning hierarchy consumes significantly more memory than the branch decomposition [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** The number of branches grows to $3(n - 1) + 1$, where $n$ is the number of branches in the original branch decomposition [S1, unofficial].
*   **Strengths:** Reduces the branching factor to a more manageable level for user interfaces, explicitly represents all branches at each saddle to ease feature relationship interpretation, and adds features in strict order of importance to suppress small noisy features [S1, unofficial].
*   **Limitations:** High memory consumption due to the expanded ternary tree structure [S1, unofficial].
*   **When to use:** When designing a high-level user interface for topology-controlled volume rendering where a manageable branching factor and clear feature hierarchy are prioritized over memory efficiency [S1, unofficial].
*   **When not to use:** Not given in the sources.

## Background
The pruning hierarchy was introduced in the context of "Topological Galleries: A High Level User Interface for Topology Controlled Volume Rendering" by MacCarthy, Carr, and Weber [S1, unofficial]. It was implemented as part of a custom OpenCL-based topological volume renderer and a Qt-based interface, utilizing Scott Dillard’s libtourtre contour tree library [S1, unofficial]. The work was conducted on an Apple Mac Pro with specific hardware specifications [S1, unofficial]. The method builds on the branch decomposition, addressing its limitations in interface design [S1, unofficial].
