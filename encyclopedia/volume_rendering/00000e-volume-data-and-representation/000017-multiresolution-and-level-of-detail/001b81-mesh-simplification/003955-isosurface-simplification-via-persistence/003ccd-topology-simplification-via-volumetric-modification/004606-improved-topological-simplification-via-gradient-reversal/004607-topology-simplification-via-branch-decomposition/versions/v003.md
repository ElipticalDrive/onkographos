# Topology Simplification via Branch Decomposition

Also called: Branch Decomposition, Hierarchical Contour Tree Simplification, Improved Topological Simplification for Volume Rendering

## Overview
Topology Simplification via Branch Decomposition is a method for storing and traversing a hierarchy of contour tree simplifications to enable topology-controlled volume rendering [S1][S2, unofficial]. It solves the problem of "oversegmentation" by concatenating sequences of contour tree arcs into single hierarchical units, allowing users to interact with a coarse simplified tree and propagate transfer functions to the full-resolution data [S1][S2, unofficial]. Unlike methods that treat all zones with equivalent nesting depth as identical, this approach unifies topological zones based on their hierarchical relationship, avoiding unnecessary segmentation boundaries where regions do not overlap in value range [S1][S2, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** A contour tree of a scalar field, where nodes represent critical points (minima, maxima, saddles) and edges represent monotone paths between them [S1][S2, unofficial].
*   **Output:** A branch decomposition tree, where each node represents a "branch" defined by a saddle-extremum pair, and parent-child relationships indicate the hierarchical order of simplification [S1][S2, unofficial].

### Data Structures
The branch decomposition is a rooted tree structure [S1][S2, unofficial]. Each node in this tree represents a **branch** [S1][S2, unofficial].

**Branch Node Layout:**
*   `saddle`: The identifier of the saddle critical point.
*   `extremum`: The identifier of the extremum (minimum or maximum) critical point.
*   `priority`: A numeric value determining the simplification order.
*   `children`: A list of child branch nodes.
*   `parent`: A reference to the parent branch node (or null for the root).

**Root Branch Exception:**
Exactly one branch connects two leaves (the root branch) [S1][S2, unofficial]. All other branches connect one leaf (extremum) to an interior node (saddle) of another branch [S1][S2, unofficial].

### Algorithm Steps

1.  **Construct Initial Contour Tree:** Compute the contour tree of the scalar field [S1][S2, unofficial]. Identify all critical points and their connectivity [S1][S2, unofficial]. Exclude saddles corresponding to genus changes from the simplification scheme, as contours of different genus are distinguished by function value alone and do not affect segmentation complexity [S1][S2, unofficial].
2.  **Initialize Branch Tree:** Create an empty tree for the branch decomposition [S1][S2, unofficial].
3.  **Iterative Pruning:** While the contour tree contains prunable saddle-extremum pairs:
    a.  **Select Pair:** Identify a saddle-extremum pair $(s, e)$ from the contour tree [S1][S2, unofficial].
    b.  **Calculate Priority:** Compute the priority for the pair [S1][S2, unofficial].
        *   If using **Persistence**: $P(s, e) = |f(s) - f(e)|$, where $f$ is the scalar function value [S1][S2, unofficial].
        *   If using **Geometric Measures**: Compute volume or hypervolume (integral of the scalar field over the enclosed volume) [S1][S2, unofficial].
    c.  **Prune and Collapse:** Remove the pair $(s, e)$ from the contour tree [S1][S2, unofficial]. Collapse the remaining node (the saddle $s$) into an arc [S1][S2, unofficial].
    d.  **Create Branch Node:** Create a new branch node $B$ with `saddle` = $s$, `extremum` = $e$, and `priority` = $P(s, e)$ [S1][S2, unofficial].
    e.  **Link Hierarchy:** Identify the arc created by the collapse as the parent [S1][S2, unofficial]. Link branch node $B$ as a child of this parent arc [S1][S2, unofficial]. If the parent arc is itself a branch from a previous step, link $B$ to that branch node [S1][S2, unofficial]. If the parent is a new arc not yet a branch, it will be linked in a subsequent step or treated as the root if it connects two leaves [S1][S2, unofficial].
    f.  **Ordering:** Pairs with lower priority are pruned first [S1][S2, unofficial]. Consequently, they become children of branches with higher priority [S1][S2, unofficial]. The most important branches (highest priority) end up at the top of the rooted tree [S1][S2, unofficial].
4.  **Finalize:** The result is a rooted tree of branches [S1][S2, unofficial]. The root branch connects two leaves [S1][S2, unofficial]. All other branches connect an extremum to a saddle that is an interior node of a higher-priority branch [S1][S2, unofficial].

### Pseudocode

```python
def compute_branch_decomposition(contour_tree, priority_function):
    """
    Computes the branch decomposition of a contour tree.
    
    Args:
        contour_tree: Dict mapping node_id to {'type': 'min'|'max'|'saddle', 'neighbors': [node_id, ...]}
        priority_function: Callable taking (saddle_id, extremum_id) and returning a numeric priority.
                           Lower priority values are pruned first.
    
    Returns:
        root_branch: The root node of the branch decomposition tree.
    """
    # Shallow copy to avoid modifying original graph
    current_tree = {k: {'type': v['type'], 'neighbors': list(v['neighbors'])} for k, v in contour_tree.items()}
    branches = []
    collapsed_node_to_branch = {}  # Maps a collapsed saddle node to its branch

    # Iterate until no extrema remain in the contour tree
    while any(current_tree[n]['type'] in ('min', 'max') for n in current_tree):
        # 1. Find pair with lowest priority
        best_pair = None
        min_p = float('inf')
        for n in current_tree:
            if current_tree[n]['type'] == 'saddle':
                for neighbor in current_tree[n]['neighbors']:
                    if current_tree[neighbor]['type'] in ('min', 'max'):
                        p = priority_function(n, neighbor)
                        if p < min_p:
                            min_p = p
                            best_pair = (n, neighbor)
        if best_pair is None:
            break
        s, e = best_pair
        p = min_p

        # 2. Prune extremum e from contour tree
        current_tree[s]['neighbors'].remove(e)
        del current_tree[e]

        # 3. Create branch node
        branch = {'saddle': s, 'extremum': e, 'priority': p, 'children': [], 'parent': None}
        branches.append(branch)

        # 4. Link to parent arc (s)
        if s in collapsed_node_to_branch:
            parent_branch = collapsed_node_to_branch[s]
            parent_branch['children'].append(branch)
            branch['parent'] = parent_branch
        else:
            # s is not yet an extremum of a branch; it acts as the root arc
            branch['parent'] = None

        # 5. Mark s as collapsed so future pairs can link to it
        collapsed_node_to_branch[s] = branch

    # 6. Identify root branch (the one with no parent)
    root = next((b for b in branches if b['parent'] is None), branches[0] if branches else None)
    return root
```

### Parameters
*   **Priority Measure:**
    *   **Persistence:** $|f(s) - f(e)|$. Typical default [S1][S2, unofficial].
    *   **Volume:** Geometric measure of the enclosed volume [S1][S2, unofficial].
    *   **Hypervolume:** Integral of the scalar field over the enclosed volume [S1][S2, unofficial].
*   **Simplification Order:** Pairs with lower priority are pruned first [S1][S2, unofficial]. Higher priority branches are parents of lower priority branches [S1][S2, unofficial].

### Edge Cases and Pitfalls
*   **Oversegmentation:** Without branch decomposition, the volume may be oversegmented into too many topological zones [S1][S2, unofficial]. Branch decomposition avoids this by concatenating sequences of arcs into a single unit, unifying their topological zones [S1][S2, unofficial].
*   **Genus Changes:** Saddles corresponding to genus changes are not considered in the simplification scheme [S1][S2, unofficial]. Contours of different genus are distinguished by function value alone and do not contribute to contour tree complexity or segmentation [S1][S2, unofficial].
*   **Rendering Artifacts:** When canceling a branch, the transfer function for the canceled branch is set to a solid color, specifically the color of the parent branch’s transfer function at the value of the saddle connecting the branch [S1][S2, unofficial]. This avoids artifacts associated with interpolating opacities over tetrahedral meshes [S1][S2, unofficial]. The method uses hexahedral cells and looks up opacities directly in the transfer function [S2, unofficial].

## Operating characteristics

### Time and Memory Complexity
*   **Construction:** Requires computing the contour tree and then iteratively pruning pairs [S1][S2, unofficial]. The pruning step is proportional to the number of critical points [S1][S2, unofficial].
*   **Storage:** The branch decomposition stores one node per prunable saddle-extremum pair [S1][S2, unofficial]. Memory usage is linear with respect to the number of critical points [S1][S2, unofficial].

### Measured Performance
*   Not given in the sources.

### Scaling
*   The method permits user interactions on a coarse, simplified tree and propagating transfer functions down to the full resolution tree [S1][S2, unofficial]. This allows for efficient interaction regardless of the underlying data resolution [S1][S2, unofficial].

### Strengths and Limitations
*   **Strengths:**
    *   Avoids oversegmentation by unifying topological zones [S1][S2, unofficial].
    *   Provides a hierarchical representation of the contour tree, enabling multi-level interaction [S1][S2, unofficial].
    *   Reduces rendering artifacts by using hexahedral cells and direct transfer function lookups instead of tetrahedral interpolation [S2, unofficial].
*   **Limitations:**
    *   Does not consider genus changes, which may limit its ability to simplify topological features that change the genus of the isosurface [S1][S2, unofficial].
    *   The quality of simplification depends on the chosen priority measure (persistence vs. geometric) [S1][S2, unofficial].

### When to Use
*   Use when topology-controlled volume rendering is required, and the user needs to simplify the isosurface topology while maintaining visual consistency [S1][S2, unofficial].
*   Use when avoiding oversegmentation is critical for performance or visual clarity [S1][S2, unofficial].

### When Not to Use
*   Do not use if genus changes are important for the visualization, as they are ignored by this method [S1][S2, unofficial].
*   Do not use if the underlying data is not structured (e.g., unstructured tetrahedral meshes) without modification, as the method is designed for hexahedral cells and trilinear interpolants [S2, unofficial].

## Background

### Origin
The branch decomposition was originally described by Pascucci et al. [S1][S2, unofficial]. It was introduced as an efficient way for storing a hierarchy of contour tree simplifications [S1][S2, unofficial].

### History and Development
The method was applied to volume rendering in the work "Topology-Controlled Volume Rendering" [S1][S2, unofficial]. It builds upon earlier work on topological simplification, such as that by Carr et al., which used vertex prune operations [S1]. The method was extended to improve volume rendering by using hexahedral cells and direct transfer function lookups, avoiding artifacts from tetrahedral interpolation [S2, unofficial].

### Where it is Used
*   Topology-controlled volume rendering [S1][S2, unofficial].
*   Interactive visualization of scalar fields where simplification of topological features is desired [S1][S2, unofficial].
