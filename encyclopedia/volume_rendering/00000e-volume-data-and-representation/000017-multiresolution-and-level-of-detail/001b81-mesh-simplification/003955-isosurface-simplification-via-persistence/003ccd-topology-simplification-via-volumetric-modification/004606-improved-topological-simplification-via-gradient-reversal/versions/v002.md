# Improved Topological Simplification via Gradient Reversal

Also called: Gradient Reversal Simplification, Improved Topological Simplification, Tube-based Simplification

## Overview
This method modifies a scalar volume field to correspond to a simplified contour tree by reversing the gradient flow along a path from a saddle to an extremum, allowing for smoother evolution of isosurfaces compared to simple pruning [S1][S2, unofficial]. It solves the problem of visual artifacts (such as "chopping off" peaks) that occur when topological features are removed by simply deleting data or flattening regions, providing a closer approximation of the underlying scalar field [S1][S2, unofficial].

## How it works
**Inputs:** A scalar field $V$, a contour tree representing the topology of $V$, and a branch to be pruned defined by a saddle node $S$ and an extremum node $C$ (e.g., a maximum) [S1].
**Outputs:** A modified scalar field $V'$ where the topological feature corresponding to branch $SC$ is removed, and the contour tree reflects the simplification [S1].

**Data Structures:**
The method operates on the scalar grid [G]. It requires identifying the "topological zones" associated with the nodes [G]. A topological zone for a node is the set of grid points that flow to that node under the gradient ascent/descent dynamics [G]. The algorithm constructs two implicit or explicit tube structures [S1]:
1. **Child Tube:** A region starting at $S$ and extending toward $C$ [S1].
2. **Parent Tube:** A region starting at $S$ and extending into the parent zone $P$ [S1].

**Steps:**

1. **Identify Branch and Zones:**
   Identify the branch to be pruned, defined by saddle $S$ and extremum $C$. Identify the parent zone $P$ connected to $S$ (excluding the child zone $C$) [S1].

2. **Construct Child Tube:**
   Start at saddle $S$. Follow the steepest ascent path toward $C$ using a "best effort" process [S1]. Stop if a maximum/minimum is reached or if the path is obstructed by another topological zone (not $P$ or $C$) [S1]. Determine the base radius of the tube at $S$: sweep a sphere out from $S$ until it first intersects a topological zone other than $P$ or $C$ [S2, unofficial]. This distance is the base radius $R_{base}$. The tube extends from $S$ to $C$. The radius shrinks as the tube extends from $S$ toward $C$ [S1]. The child tube crosses each contour of $C$'s topological zone once [S2, unofficial].

3. **Reverse Gradient in Child Tube:**
   The original values in $C$'s zone ascend from $S$ to $C$. Define new function values in the child tube that descend from $S$ to $C$ [S1]. Specifically, at each crossing of the child tube with a contour of the topological zone, define a new function value that is lower than the previous one, effectively reversing the gradient direction within the tube [S2, unofficial].

4. **Handle New Minimum at Saddle:**
   Since $S$ is lower than all values in $C$'s zone, descending from $S$ into the child tube would create a new local minimum at $S$ [S2, unofficial]. To avoid this, construct a **Parent Tube** extending from $S$ into the parent zone $P$ [S2, unofficial]. Follow the steepest path from $S$ into $P$ using the "best effort" process. Stop if obstructed or at an extremum [S1]. Increase the values along the parent tube to elevate the function value at $S$. The gradient along the parent tube is *not* reversed; values are simply increased [S2, unofficial].

5. **Ensure Monotonicity:**
   Let $v_P$ be the value at the end of the parent tube (in zone $P$) and $v_C$ be the value at the end of the child tube (at $C$). Ideally, $v_P > v_C$. If so, a monotonically decreasing path exists from $P$, through $S$, to $C$, effecting the simplification [S1].

6. **Edge Cases and Pitfalls:**
   * **Parent Tube Insufficient Height:** If $v_P \le v_C$, a monotonically descending path cannot be constructed [S1][S2, unofficial]. *Fix:* Let $v$ be the value at the highest point on the parent tube. Uniformly scale all values in $C$'s topological zone so that they are less than $v$ [S1][S2, unofficial].
   * **Child Tube Obstruction:** If $C$ has children, the child tube may become obstructed by other zones [S1][S2, unofficial]. *Fix:* Flatten all points in $C$'s topological zone with values greater than the end of the child tube. The tip of the child tube becomes the new maximum [S1][S2, unofficial].
   * **Degenerate Case:** If no significant tubes can be constructed, the method degenerates into the "chopping-off" method (simple pruning) [S1][S2, unofficial].

**Pseudocode:**

```python
def simplify_branch_gradient_reversal(V, contour_tree, branch_to_prune):
    """
    Simplifies a scalar field V by reversing gradient flow along a branch.
    
    Args:
        V: 3D array of scalar values.
        contour_tree: Structure containing nodes (S, C, P) and their topological zones.
        branch_to_prune: Tuple (S, C) where S is saddle, C is extremum (max).
        
    Returns:
        V_prime: Modified scalar field.
    """
    # Helper: get 6-connected neighbors in a 3D grid
    def get_neighbors(p):
        x, y, z = p
        return [(x+1,y,z), (x-1,y,z), (x,y+1,z), (x,y-1,z), (x,y,z+1), (x,y,z-1)]
    
    # Helper: get points within radius r of center
    def get_sphere_points(center, r):
        cx, cy, cz = center
        pts = []
        for dx in range(-r, r+1):
            for dy in range(-r, r+1):
                for dz in range(-r, r+1):
                    if dx*dx + dy*dy + dz*dz <= r*r:
                        pts.append((cx+dx, cy+dy, cz+dz))
        return pts

    S, C = branch_to_prune
    zone_C = contour_tree.get_zone(C)
    zone_P = contour_tree.get_parent_zone(S)
    
    # Step 1: Construct Child Tube
    path_child = []
    current = S
    visited = set()
    while current != C and current not in visited:
        visited.add(current)
        path_child.append(current)
        neighbors = get_neighbors(current)
        next_point = None
        max_val = -float('inf')
        for n in neighbors:
            if n in zone_C or n in zone_P:
                if V[n] > max_val:
                    max_val = V[n]
                    next_point = n
        if next_point is None:
            break
        current = next_point
        
    # Determine base radius at S: sweep sphere from S until it hits a zone not in {zone_P, zone_C}
    R_base = 0
    for r in range(1, 100):
        sphere_pts = get_sphere_points(S, r)
        if any(V[pt] not in zone_P and V[pt] not in zone_C for pt in sphere_pts):
            R_base = r - 1
            break
            
    # Define Child Tube region and new values
    for i, point in enumerate(path_child):
        t = i / len(path_child) if len(path_child) > 1 else 0.0
        current_radius = R_base * (1.0 - t)
        tube_cross_section = get_sphere_points(point, current_radius)
        # Reverse gradient: assign descending values
        # Sources do not specify exact interpolation formula [G]
        for p in tube_cross_section:
            V[p] = V[S] - t * (V[S] - V[C])

    # Step 2: Handle Minimum at S
    path_parent = []
    current = S
    visited = set()
    while current not in visited:
        visited.add(current)
        path_parent.append(current)
        neighbors = get_neighbors(current)
        next_point = None
        max_val = -float('inf')
        for n in neighbors:
            if n in zone_P:
                if V[n] > max_val:
                    max_val = V[n]
                    next_point = n
        if next_point is None:
            break
        current = next_point
        
    # Elevate S by increasing values along parent tube
    for point in path_parent:
        V[point] = max(V[point], V[S] + 1.0)

    # Step 3: Check Monotonicity and Fix
    val_P_end = V[path_parent[-1]]
    val_C_end = V[C]
    
    if val_P_end <= val_C_end:
        v_max_parent = val_P_end
        for point in zone_C:
            if V[point] >= v_max_parent:
                V[point] = v_max_parent * 0.99
        V[S] = v_max_parent

    # Step 4: Handle Obstructed Child Tube (if C has children)
    if contour_tree.has_children(C):
        val_child_end = V[C]
        for point in zone_C:
            if V[point] > val_child_end:
                V[point] = val_child_end
        V[C] = val_child_end

    return V
```

## Subtopics

### [Topology Simplification via Branch Decomposition](11673-topology-simplification-via-branch-decomposition.md)
Topology Simplification via Branch Decomposition is a method for storing and traversing a hierarchy of contour tree simplifications to enable topology-controlled volume rendering. It solves the problem of "oversegmentation" by concatenating sequences of contour tree arcs into single hierarchical units, allowing users to interact with a coarse simplified tree and propagate transfer functions to the full-resolution data. Unlike methods that treat all zones with equivalent nesting depth as identical, this approach unifies topological zones based on their hierarchical relationship, avoiding unnecessary segmentation boundaries where regions do not overlap in value range.

### Topology Simplification via Leaf Pruning and Node Collapses
A method to suppress insignificant topological features by removing or cancelling pairs of critical points based on a specified measure. Leaf pruning removes a leaf and the arc incident to the leaf from the contour tree. For visualization methods other than isosurface extraction, data can be modified to match the simplified topology by 'flattening' the corresponding region: all points corresponding to the pruned arc are assigned the value of the saddle. Node collapses remove degree-two vertices and do not affect the contours that can be extracted or values in the data set. Pruning and collapsing are performed in an order that minimizes error based on a local geometric measure, with node collapses having priority over leaf pruning. Priority measures include hypervolume (an integral of the scalar field over the enclosed volume), volume, or persistence. A pitfall is that deleting an arc from the contour tree discards the corresponding contours from further consideration, as contours are extracted from seeds stored in the tree [S1].

## Operating characteristics
* **Time Complexity:** Not given in the sources. The "best effort" path following and sphere sweeping heuristics suggest complexity dependent on the size of the topological zones and the resolution of the grid [G].
* **Memory Complexity:** Not given in the sources. Requires storage for the scalar field and the contour tree structure [G].
* **Strengths:** Produces smoother evolution of isosurfaces compared to simple pruning. Avoids visual artifacts of "chopping off" peaks. Provides a closer approximation of the underlying scalar field [S1][S2, unofficial].
* **Limitations:** Can degenerate into "chopping-off" if tubes cannot be constructed. Requires careful handling of edge cases (monotonicity, obstruction) [S1][S2, unofficial].
* **When to use:** When smooth isosurface evolution is required and the scalar field approximation is important [S1][S2, unofficial].
* **When not to use:** When computational resources are extremely limited and the degenerate case is likely, or when topological features are not critical for the visualization [G].

## Background
The method follows the strategy of Pascucci et al. [35], which proves that one can always modify a scalar field to correspond to a simplified contour tree. The proof relies on reversing the gradient flow along a path from the saddle to the extremum of the branch to be pruned. The authors proved a stronger result, which states that the region in which the gradient flow is reversed can be made arbitrarily small. This condition is achieved by subdividing the mesh, resulting in arbitrarily thin thread-like structures connecting the former extremum to the remainder of the function. This approach, too, generates undesirable visual artifacts, and the method instead reverses the gradient flow in a tube—a region inflated from the thread to a size defined by a heuristic [S1][S2, unofficial]. The work is based on topology simplification methods introduced by Takahashi et al. [29], Carr et al. [34], and Pascucci et al. [35] [S1].
