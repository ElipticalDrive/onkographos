# Topology Simplification via Branch Decomposition

Also called: Branch Decomposition, Hierarchical Contour Tree Simplification, Improved Topological Simplification for Volume Rendering

## Overview
Topology Simplification via Branch Decomposition is an efficient method for storing a hierarchy of contour tree simplifications [S1]. It solves the problem of volume oversegmentation by concatenating sequences of arcs into single hierarchical units, unifying their topological zones [S1][S2, unofficial]. It differs from [Improved Topological Simplification via Gradient Reversal](11670-improved-topological-simplification-via-gradient-reversal.md) by operating directly on the structural hierarchy rather than modifying the scalar field, and from [Topology Simplification via Leaf Pruning and Node Collapses](11674-topology-simplification-via-leaf-pruning-and-node-collapses.md) by explicitly respecting hierarchical feature importance instead of treating all zones with the same nesting depth as equivalent [S2, unofficial]. It permits user interactions on a coarse, simplified tree and propagates transfer functions down to the full resolution tree [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A contour tree of a scalar field [S1].
*   **Output:** A branch decomposition, which is a rooted tree of branches representing topological simplifications [S1].

**Data Structures**
The branch decomposition is a hierarchical decomposition of the contour tree [S1].
*   **Branch:** Defined by a pair of critical points: a saddle and an extremum connected by a monotone path [S1].
*   **Root Branch:** Exactly one branch connects two leaves (extrema) of the original contour tree [S1].
*   **Interior Branch:** Every other branch connects one leaf (extremum) to an interior node (saddle) of another branch [S1].
*   **Hierarchy:** The decomposition forms a tree where nodes are branches; the parent of a branch is the arc or branch containing the saddle that connects to the extremum of the child branch [S1].

**Steps**
1.  **Construct the Branch Decomposition:**
    1.  Identify all saddle-extremum pairs in the contour tree [S1].
    2.  Assign a priority measure to each pair [S1][S2, unofficial].
    3.  Sort pairs by priority. Pairs with lower priority are processed first [S1][S2, unofficial].
    4.  Iterate through the sorted pairs:
        a.  Prune the saddle-extremum pair from the contour tree [S1].
        b.  Collapse the remaining node, leaving an arc [S1].
        c.  Create a branch node representing this pair [S1].
        d.  Link this branch as a child to the arc (or branch) created by the collapse, which serves as the parent [S1][S2, unofficial].
    5.  Repeat until all pairs are processed. The result is a rooted tree of branches, with the most important branches (highest priority) at the top [S1][S2, unofficial].

2.  **Apply Simplification (Rendering):**
    1.  To simplify the topology, discard branches from the decomposition. Discarding a branch is equivalent to performing a cancellation of the corresponding critical points, which is equivalent to a vertex prune operation [S1].
    2.  For each discarded branch, modify the rendering to reflect the topological change by setting the transfer function for the canceled branch to a solid color [S1].
    3.  The solid color is the color of the parent branch’s transfer function evaluated at the scalar value of the saddle that connects the child branch to the parent [S1].
    4.  This effectively "chops off" peaks and "fills in" valleys, displaying an image consistent with the pruned contour tree [S1].

**Formulas**
*   **Persistence:** $P = |f(s) - f(e)|$, where $f(s)$ is the scalar value at the saddle $s$ and $f(e)$ is the scalar value at the extremum $e$ [S1][S2, unofficial].
*   **Hypervolume:** The integral of the scalar field over the enclosed volume [S1][S2, unofficial].

**Parameters**
*   **Priority Measure:** Persistence (default) or geometric measures (volume, hypervolume) [S1][S2, unofficial].
*   **Threshold:** A cutoff value for the priority measure to determine which branches to discard [G].

**Edge Cases and Pitfalls**
*   **Genus Changes:** Saddles corresponding to genus changes are currently not considered in the simplification scheme. Contours of different genus are distinguished by function value alone and do not affect segmentation or contribute to contour tree complexity in this context [S1][S2, unofficial].
*   **Oversegmentation:** Without branch decomposition, the volume may be oversegmented into too many topological zones. Branch decomposition avoids this by concatenating sequences of arcs into a single unit, unifying their topological zones [S1][S2, unofficial].
*   **Artifact Avoidance:** Unlike methods using tetrahedral meshes and interpolated opacities, this method uses hexahedral cells and looks up opacities directly in the transfer function to avoid artifacts in cells spanning multiple topological zones [S2, unofficial].

## Subtopics

### [Pruning Hierarchy Construction](16712-pruning-hierarchy-construction.md)
A variant that expands the branch decomposition into a ternary-like structure to reduce the branching factor, making it more suitable for user interfaces while maintaining strict ordering of feature importance.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Avoids oversegmentation; allows user interaction on a coarse, simplified tree; permits propagation of transfer functions to full resolution; efficient storage of simplification hierarchy [S1].
*   **Limitations:** Does not consider genus changes; relies on the accuracy of the contour tree construction [S1][S2, unofficial].
*   **When to Use:** When efficient hierarchical storage and traversal of contour tree simplifications is required for volume rendering, particularly when avoiding oversegmentation is critical [S1].
*   **When Not to Use:** When genus changes are important for the visualization [S1].

## Background
Branch decomposition was described by Pascucci et al. [35] as an efficient way for storing a hierarchy of contour tree simplifications [S1][S2, unofficial]. It was adopted in the context of topology-controlled volume rendering and later extended by Carr et al. [34] and others [S1][S2, unofficial]. The method addresses the limitations of flat contour tree representations by providing a hierarchical structure that reflects the importance of topological features [S1].
