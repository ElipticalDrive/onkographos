# Rapid Decimation for Direct Volume Rendering

Also called: Bucket-based Decimation, Vertex Decimation

## Overview
Rapid Decimation for Direct Volume Rendering is a mesh simplification technique that reduces the polygon count of a volume dataset by removing vertices deemed unimportant based on their data values, converting a uniform grid of hexahedral or tetrahedral cells into a hybrid grid with many-sided cells and non-cell polygons [S1, unofficial]. It solves the problem of rendering large volumes efficiently by preserving visual fidelity at boundaries defined by transfer functions or data features while discarding redundant internal geometry [S1, unofficial]. Unlike its sibling [GPU-based Mesh Decimation via Edge Collapse](3505-gpu-based-mesh-decimation-via-edge-collapse.md), which relies on geometric error metrics and edge collapses, this method operates on data-value homogeneity using a bucketing strategy, making it particularly suitable for direct volume rendering where color/opacity mapping is non-linear [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** A volume dataset represented as a grid of simple hexahedral or tetrahedral cells. The dataset includes vertex positions, connectivity, and scalar data values. A transfer function (piecewise linear) may be provided.
*   **Output:** A decimated volume representation consisting of a subset of the original vertices and the polygons (faces) connecting them. The output is a hybrid grid; cells may have more than four or six faces, and some polygons may not belong to any closed cell [S1, unofficial].

### Data Structures
*   **Vertex List:** Stores position and scalar data value for each vertex.
*   **Polygon List:** Stores connectivity (vertex indices) for each polygon.
*   **Active Polygon Mask:** A boolean array indicating which polygons remain in the volume after decimation [S1, unofficial].
*   **Neighbor List:**
    *   For regular/curvilinear grids: Implicitly defined by grid indices $(z, j, k)$.
    *   For tetrahedral grids: An explicit list of neighbor vertices for each vertex [S1, unofficial].
*   **Histogram:** A smoothed histogram of the scalar data values used for bucket placement [S1, unofficial].

### Bucket Placement Strategies
The core of the method is dividing the data range into sub-ranges called "buckets." Vertices mapping to the same bucket as all their neighbors are candidates for decimation. Five strategies exist for placing bucket boundaries [S1, unofficial]:

1.  **Uniform by Range:** Places $N$ buckets at equal intervals over the data range $[min, max]$.
2.  **Uniform by Histogram:** Places buckets uniformly based on the cumulative frequency of data from a smoothed histogram, rather than the data range. This ensures roughly equal vertex counts per bucket but requires smoothing to avoid clustering in high-density regions [S1, unofficial].
3.  **Histogram Curvature:** Places boundaries where the magnitude of the second derivative of the smoothed histogram is largest. This preserves steep spikes/valleys in the data distribution [S1, unofficial].
4.  **Histogram Feature:** Identifies feature centers by finding the point with the highest curvature magnitude, then scans left and right for the next peak in curvature of opposite sign. Boundaries are placed at these outer peaks, avoiding the feature center itself [S1, unofficial].
5.  **Transfer Function:** Places a bucket boundary at each control point of the piecewise linear transfer function. This ensures that perceived visual boundaries are preserved [S1, unofficial].

**Histogram Smoothing:** All histogram-based methods (2-4) use a histogram smoothed by a Gaussian filter with standard deviation $\sigma = 2.82$ [S1, unofficial].

### Algorithm Steps

1.  **Compute Histogram:** Generate a raw histogram of the scalar data values (256 equal-width bins). Apply Gaussian smoothing with $\sigma = 2.82$ if using histogram-based strategies [S1, unofficial].
2.  **Determine Bucket Boundaries:** Select a strategy and compute the bucket boundaries $B = \{b_0, b_1, ..., b_N\}$, where $b_0$ is the minimum data value and $b_N$ is the maximum [S1, unofficial].
    *   *For Histogram Curvature:* Calculate the second derivative approximation for each bin $i$:
        $$ D_i = | -2h_i + h_{i-1} + h_{i+1} | $$
        where $h_i$ is the smoothed histogram value at bin $i$. Select the $N-1$ largest $D_i$ values as boundaries [S1, unofficial].
    *   *For Histogram Feature:* Find the bin $i_{max}$ with the maximum $D_i$. Scan left and right from $i_{max}$ to find the nearest bins $i_{left}$ and $i_{right}$ where the curvature sign changes (peaks of opposite sign). Set boundaries at the data values corresponding to $i_{left}$ and $i_{right}$. Repeat recursively, excluding found features [S1, unofficial].
3.  **Map Vertices to Buckets:** For each vertex $v$ with data value $d_v$, determine its bucket index $k$ such that $b_k \le d_v < b_{k+1}$ [S1, unofficial].
4.  **Identify Neighbors:**
    *   For regular/curvilinear grids: The 26 neighbors of vertex at $(z, j, k)$ are found by incrementing each coordinate by $d=1$ in each direction (i.e., offsets $(-1,0,0)$ to $(1,1,1)$ excluding $(0,0,0)$) [S1, unofficial].
    *   For tetrahedral grids: Use the pre-computed explicit neighbor list [S1, unofficial].
5.  **Decimation Pass:** Traverse all vertices.
    *   If a vertex $v$ is on the exterior boundary of the grid, retain it [S1, unofficial].
    *   Otherwise, check if $v$ maps to the same bucket as **all** of its neighbors.
    *   If yes, mark $v$ and all polygons incident to $v$ for decimation.
    *   If no (i.e., at least one neighbor is in a different bucket), retain $v$ and its incident polygons.
6.  **Update Geometry:** Remove decimated vertices and polygons. The remaining structure is a hybrid grid. To optimize memory, sort the polygon list so decimated vertices are listed first, keeping an offset to indicate where active vertices begin [S1, unofficial].

### Pseudocode

```python
def rapid_decimation(volume, num_buckets=10, strategy='histogram_curvature', transfer_function=None):
    """
    volume: Object containing vertices (pos, value), connectivity, and grid type.
    num_buckets: Number of sub-ranges (buckets) to divide the data range into.
    strategy: One of 'uniform_range', 'uniform_histogram', 'histogram_curvature', 
              'histogram_feature', 'transfer_function'.
    transfer_function: List of control points (data_value, opacity) if strategy is 'transfer_function'.
    """
    
    # 1. Compute Histogram
    raw_histogram = compute_histogram(volume.vertices)
    smoothed_histogram = gaussian_smooth(raw_histogram, sigma=2.82)
    
    # 2. Determine Bucket Boundaries
    boundaries = []
    min_val = volume.min_data_value
    max_val = volume.max_data_value
    
    if strategy == 'uniform_range':
        boundaries = linspace(min_val, max_val, num_buckets + 1)
        
    elif strategy == 'uniform_histogram':
        # Place boundaries uniformly based on cumulative frequency
        total_count = sum(smoothed_histogram)
        step = total_count / num_buckets
        cumulative = 0
        boundaries = [min_val]
        for i in range(len(smoothed_histogram)):
            cumulative += smoothed_histogram[i]
            if cumulative >= step and len(boundaries) < num_buckets:
                boundaries.append(get_data_value_for_bin(i, smoothed_histogram))
                cumulative = 0
        boundaries.append(max_val)
        
    elif strategy == 'histogram_curvature':
        # Calculate second derivative magnitude
        curvature = []
        for i in range(1, len(smoothed_histogram) - 1):
            h_prev = smoothed_histogram[i-1]
            h_curr = smoothed_histogram[i]
            h_next = smoothed_histogram[i+1]
            val = abs(-2 * h_curr + h_prev + h_next)
            curvature.append((val, i))
        
        # Sort by curvature magnitude descending
        curvature.sort(key=lambda x: x[0], reverse=True)
        
        # Select top num_buckets - 1 boundaries
        boundary_bins = [c[1] for c in curvature[:num_buckets - 1]]
        boundaries = [min_val]
        for b_bin in sorted(boundary_bins):
            boundaries.append(get_data_value_for_bin(b_bin, smoothed_histogram))
        boundaries.append(max_val)
        
    elif strategy == 'histogram_feature':
        # Find highest curvature magnitude
        curvature = []
        for i in range(1, len(smoothed_histogram) - 1):
            h_prev = smoothed_histogram[i-1]
            h_curr = smoothed_histogram[i]
            h_next = smoothed_histogram[i+1]
            val = abs(-2 * h_curr + h_prev + h_next)
            curvature.append((val, i))
        
        curvature.sort(key=lambda x: x[0], reverse=True)
        
        boundaries = [min_val, max_val]
        used_bins = set()
        
        for peak_val, peak_bin in curvature:
            if len(boundaries) - 1 >= num_buckets:
                break
            if peak_bin in used_bins:
                continue
                
            # Scan left for opposite sign peak
            left_bound = None
            for i in range(peak_bin - 1, 0, -1):
                h_prev = smoothed_histogram[i-1]
                h_curr = smoothed_histogram[i]
                h_next = smoothed_histogram[i+1]
                curr_curv = -2 * h_curr + h_prev + h_next
                # Check for sign change relative to peak curvature direction
                # Simplified: look for local max in opposite direction
                if is_opposite_peak(smoothed_histogram, i, peak_bin):
                    left_bound = i
                    break
            
            # Scan right for opposite sign peak
            right_bound = None
            for i in range(peak_bin + 1, len(smoothed_histogram) - 1):
                h_prev = smoothed_histogram[i-1]
                h_curr = smoothed_histogram[i]
                h_next = smoothed_histogram[i+1]
                curr_curv = -2 * h_curr + h_prev + h_next
                if is_opposite_peak(smoothed_histogram, i, peak_bin):
                    right_bound = i
                    break
            
            if left_bound is not None:
                boundaries.append(get_data_value_for_bin(left_bound, smoothed_histogram))
                used_bins.add(left_bound)
            if right_bound is not None:
                boundaries.append(get_data_value_for_bin(right_bound, smoothed_histogram))
                used_bins.add(right_bound)
                
        boundaries.sort()
        
    elif strategy == 'transfer_function':
        if transfer_function is None:
            raise ValueError("Transfer function required for this strategy")
        boundaries = [pt[0] for pt in transfer_function]
        if min_val not in boundaries:
            boundaries.insert(0, min_val)
        if max_val not in boundaries:
            boundaries.append(max_val)
        boundaries.sort()

    # 3. Map Vertices to Buckets
    vertex_buckets = {}
    for v in volume.vertices:
        val = v.value
        # Find bucket index
        bucket_idx = 0
        for i in range(len(boundaries) - 1):
            if boundaries[i] <= val < boundaries[i+1]:
                bucket_idx = i
                break
        else:
            bucket_idx = len(boundaries) - 2 # Last bucket
        vertex_buckets[v.id] = bucket_idx

    # 4. Identify Neighbors and Decimate
    active_polygons = set()
    decimated_vertices = set()
    
    # Pre-calculate exterior boundary vertices
    exterior_vertices = get_exterior_boundary_vertices(volume)
    
    for v in volume.vertices:
        if v.id in exterior_vertices:
            active_polygons.update(v.incident_polygons)
            continue
            
        neighbors = get_neighbors(volume, v)
        same_bucket = True
        for n in neighbors:
            if vertex_buckets[n.id] != vertex_buckets[v.id]:
                same_bucket = False
                break
        
        if same_bucket:
            decimated_vertices.add(v.id)
        else:
            active_polygons.update(v.incident_polygons)

    # 5. Update Geometry
    # Remove decimated vertices and polygons
    # Optimization: Sort polygon list, keep offset
    return DecimatedVolume(active_polygons, volume.vertices, decimated_vertices)

    """Check if bin i is a local peak of opposite curvature sign to center."""
    # Simplified logic: check if histogram[i] is a local max/min and 
    # the curvature sign at i is opposite to curvature sign at center
    h_prev = histogram[i-1]
    h_curr = histogram[i]
    h_next = histogram[i+1]
    
    # Local peak check
    if h_curr > h_prev and h_curr > h_next:

        if curv_i * curv_c < 0:
```

### Parameters
*   **Number of Buckets:** User-specified. More buckets lead to less decimation but higher fidelity [S1, unofficial].
*   **Histogram Smoothing Sigma:** Fixed at 2.82 for all histogram-based strategies [S1, unofficial].
*   **Neighbor Count:** 26 for regular/curvilinear grids [S1, unofficial].

### Edge Cases and Pitfalls
*   **Holes:** Strictly local decimation based on linearity can cause holes in images if a long string of vertices along a view direction are all decimated [S1, unofficial].
*   **Color Bleeding:** Strong non-linearities in the transfer function can cause color bleeding from small areas into otherwise clear portions of the volume if bucket boundaries do not align with these transitions [S1, unofficial].
*   **Boundary Retention:** Exterior boundary vertices must always be retained to define the volume's spatial extent [S1, unofficial].

## Operating characteristics

### Time and Memory Complexity
*   **Time:** Dominated by histogram computation ($O(N)$ where $N$ is number of vertices) and the decimation pass ($O(V \cdot D)$ where $V$ is vertices and $D$ is degree, typically 26). Bucket placement is $O(B \log B)$ or $O(B)$ depending on strategy, where $B$ is number of bins (256).
*   **Memory:** Requires storage for the original volume, the boolean active polygon mask, and the neighbor list (for tetrahedral grids). The boolean array optimization reduces memory overhead by sorting polygons [S1, unofficial].

### Measured Performance
*   **Decimation Rate:** Approximately 45-62% of polygons were decimated across tested datasets [S1, unofficial].
*   **Error Metric:** Image-based error metric using 32 x-ray images (500x500 resolution) with linear gray-scale transfer function. Error is the square root of the average sum-of-squares of pixel differences, discarding black pixels [S1, unofficial].

### Strengths and Limitations
*   **Strengths:** Fast, simple implementation. Preserves visual features defined by data distribution or transfer functions. Effective for CFD and medical data with distinct features [S1, unofficial].
*   **Limitations:** Can produce artifacts (holes, bleeding) if the data has strong non-linearities or if the view direction aligns with decimated regions. Not geometrically optimal (unlike quadric error metrics). The error metric is computationally expensive to compute for evaluation [S1, unofficial].

### When to Use
*   Use when rendering large volumes where performance is critical and the transfer function is known.
*   Use when the data has distinct features that can be captured by histogram boundaries or transfer function control points.
*   Avoid when geometric accuracy is more important than visual fidelity, or when the transfer function is highly non-linear and not provided [S1, unofficial].

## Background

### Origin
The method was introduced in a 1999 NASA technical report titled "Rapid Decimation for Direct Volume Rendering" [S1, unofficial]. It was developed to address the computational cost of rendering large CFD (Computational Fluid Dynamics) and medical volume datasets.

### History and Development
The authors explored five automatic strategies for bucket placement to improve upon earlier local linearity-based decimation methods that suffered from visual artifacts. The method was tested on CFD datasets (Blunt Fin, Lockheed Fighter, Space Shuttle) and medical data. The use of an image-based error metric allowed for quantitative comparison of different bucket placement strategies [S1, unofficial].

### Applications
*   Direct Volume Rendering of large scientific datasets (CFD, medical imaging).
*   Real-time visualization where pre-processing decimation is acceptable [S1, unofficial].
