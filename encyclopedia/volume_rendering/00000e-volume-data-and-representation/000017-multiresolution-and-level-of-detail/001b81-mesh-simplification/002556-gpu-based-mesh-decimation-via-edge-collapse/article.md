# GPU-based Mesh Decimation via Edge Collapse

Also called: Quadric Edge Collapse Decimation, QECD, QEM Decimation

## Overview
GPU-based Mesh Decimation via Edge Collapse is a postprocessing technique that reduces the polygon count of a triangular mesh while preserving sharp geometric features [S1]. It solves the problem of excessive face counts in meshes generated by analytic marching or other high-resolution methods, which hinder rendering and texturing efficiency [S1]. Unlike CPU-based greedy decimation which iterates until a target is reached, this method uses a limited number of parallel iterations (typically 2) combined with Thrust utilities for sorting and scanning, trading absolute optimality for significant speedups on GPU hardware [S2, unofficial]. It builds on [Mesh Simplification](1032-mesh-simplification.md) by implementing the Quadric Error Metric (QEM) specifically for GPU architectures [S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** `vertices` (Float tensor, shape `[V, 3]`), `faces` (Integer tensor, shape `[F, 3]`), `target_vertex_count` (Integer).
- **Output:** `new_vertices` (Float tensor, shape `[V', 3]`), `new_faces` (Integer tensor, shape `[F', 3]`).

**Data Structures:**
- **Tri:** Struct with fields `v0`, `v1`, `v2` (int). Represents a triangle. Invalid faces are marked by setting `v0 = -1`.
- **Edge:** Struct with fields `v0`, `v1` (int). Enforces canonical ordering `v0 < v1`.
- **Quadricf:** Struct with 10 float fields: `a00`, `a01`, `a02`, `a11`, `a12`, `a22`, `b0`, `b1`, `b2`, `c`. Represents the symmetric 4x4 quadric matrix $Q$ in compact form.
- **vertex_to_face_map:** Flat array of face indices in CSR format.
- **vertex_to_face_offsets:** Array of size `num_vertices + 1`, storing start indices for each vertex's face list in `vertex_to_face_map`.

**Parameters:**
- `MAX_ITERATIONS`: Integer, typically 2 [S2, unofficial].
- `THREADS_PER_BLOCK`: Integer, typically 256 [S2, unofficial].
- `Boundary penalty multiplier`: Float, 1000.0 [S2, unofficial].
- `Degeneracy threshold`: Float, $10^{-11}$ for one-ring area check [S2, unofficial].
- `Singular matrix threshold`: Float, $10^{-8}$ for determinant check [S2, unofficial].

**Algorithm Steps:**

1. **Initialization:** Transfer `vertices` and `faces` to GPU device vectors (`d_vertices`, `d_faces`). Initialize `num_vertices` and `num_faces`.
2. **Iteration Loop:** Repeat up to `MAX_ITERATIONS` times, while `num_vertices > target_vertex_count` and `num_faces > 0`:
    1. **Adjacency Build (Host):** Copy `d_faces` to host. Build `vertex_to_face_map` and `vertex_to_face_offsets` by iterating over all valid faces (where `v0 != -1`). Transfer these structures back to device (`d_v_to_f_map`, `d_v_to_f_offsets`).
    2. **Vertex Quadrics (Device):** Zero-initialize `d_vertex_quadrics` (size `num_vertices`). Launch `kernel_calculate_vertex_quadrics`. For each face $f$ with vertices $v_0, v_1, v_2$:
        - Compute normal $n = (v_1 - v_0) \times (v_2 - v_0)$.
        - Compute area $A = 0.5 \|n\|$. If $A \le 10^{-8}$, skip.
        - Normalize $n$. Compute distance $d = -n \cdot v_0$.
        - Construct local quadric $q$ (unweighted):
          $$
          \begin{aligned}
          q_{a00} &= n_x^2, & q_{a01} &= n_x n_y, & q_{a02} &= n_x n_z \\
          q_{a11} &= n_y^2, & q_{a12} &= n_y n_z, & q_{a22} &= n_z^2 \\
          q_{b0} &= n_x d, & q_{b1} &= n_y d, & q_{b2} &= n_z d \\
          q_c &= d^2
          \end{aligned}
          $$
        - Weight by area: $q_{ij} \leftarrow q_{ij} \times A$.
        - Atomically add $q$ to `d_vertex_quadrics[v0]`, `d_vertex_quadrics[v1]`, `d_vertex_quadrics[v2]`.
    3. **Edge Extraction (Device):** Launch `kernel_extract_face_edges`. For each face, generate 3 edges as normalized pairs `{min(v_i, v_j), max(v_i, v_j)}` into `d_all_edges`.
    4. **Edge Sorting and Uniquing (Device):** Sort `d_all_edges`. Use `thrust::unique` to identify unique edges into `d_unique_edges`.
    5. **Boundary Detection (Device):** Use `thrust::reduce_by_key` on `d_all_edges` with constant iterator `1` to count occurrences of each unique edge. If count == 1, mark as boundary in `d_is_boundary`.
    6. **Cost Calculation (Device):** Launch `kernel_calculate_edge_costs`. For each unique edge $e$ with vertices $v_0, v_1$:
        - Sum quadrics: $Q = Q_{v0} + Q_{v1}$.
        - Extract $3 \times 3$ matrix $Q_{3x3}$ from $Q$'s `a` coefficients and vector $b$ from `b` coefficients.
        - Compute determinant $det = q_{a00}(q_{a11}q_{a22} - q_{a12}^2) - q_{a01}(q_{a01}q_{a22} - q_{a12}q_{a02}) + q_{a02}(q_{a01}q_{a12} - q_{a11}q_{a02})$.
        - Compute collapse position $pos$:
          - If $|det| > 10^{-8}$, solve $Q_{3x3} pos = -b$ using Cramer's rule or inverse.
          - Else, fallback to midpoint $pos = (v_0 + v_1) / 2$.
        - **Stability Check:** Let $mid = (v_0 + v_1)/2$ and $edge\_len^2 = \|v_1 - v_0\|^2$. If $\|pos - mid\|^2 > edge\_len^2$, clamp $pos = mid$.
        - **Validity Check:** Iterate over one-ring faces of $v_0$ and $v_1$ (excluding the collapsed edge's faces). Simulate collapse by replacing $v_0, v_1$ with $pos$.
          - If any resulting face has area squared $< 10^{-11}$, mark `causes_degeneracy = true`.
          - If any resulting face normal flips (dot product with old normal $< 0$), mark `causes_flip = true`.
        - **Cost Computation:**
          $$
          cost = pos^T Q pos + 2 b^T pos + c
          $$
          Expanded:
          $$
          \begin{aligned}
          cost &= q_{a00}pos_x^2 + 2q_{a01}pos_x pos_y + 2q_{a02}pos_x pos_z + q_{a11}pos_y^2 + 2q_{a12}pos_y pos_z + q_{a22}pos_z^2 \\
          &+ 2q_{b0}pos_x + 2q_{b1}pos_y + 2q_{b2}pos_z + q_c
          \end{aligned}
          $$
          - If boundary, add $1000.0 \times edge\_len^2$.
          - If `causes_flip` or `causes_degeneracy`, add $1000.0 \times edge\_len^2$ and set $pos = mid$.
    7. **Selection (Host):** Sort edges by cost. Iterate through sorted edges. Select an edge for collapse if neither $v_0$ nor $v_1$ has been used in a previous collapse in this iteration. Store selected collapses `{v_to_remove, v_to_keep}` and `new_positions`.
    8. **Remap Table (Device):** Initialize `remap_table` where `remap_table[v_to_remove] = v_to_keep` for selected collapses, else `remap_table[i] = i`. Launch `kernel_resolve_remap_table` to perform path compression (find ultimate destination for each vertex).
    9. **Face Update (Device):** Launch `kernel_update_faces`. For each face, remap indices using `remap_table`. If any two vertices become equal, mark face as invalid `{-1, -1, -1}`.
    10. **Vertex Position Update (Device):** Launch `kernel_update_vertex_positions`. For each collapse, write the new position to the destination vertex `remap_table[v_to_remove]`.
    11. **Compaction (Device):**
        - Copy valid faces (`v0 != -1`) to `d_valid_faces`. Update `num_faces`.
        - If `num_faces == 0`, terminate.
        - Mark active vertices using `MarkActiveVertices` functor on `d_valid_faces`.
        - Compute new compact indices via `exclusive_scan` on active flags.
        - Compact vertices and faces into new contiguous buffers. Update `num_vertices`.

## Operating characteristics
- **Time Complexity:** Dominated by sorting edges ($O(E \log E)$) and adjacency building ($O(F)$) per iteration. With `MAX_ITERATIONS=2`, it is significantly faster than iterative CPU methods that run until convergence [S2, unofficial].
- **Memory Complexity:** Requires storage for vertices, faces, quadrics ($O(V)$), edges ($O(F)$), and adjacency structures ($O(F)$).
- **Performance:** Optimized for GPU memory bandwidth and parallelism using Thrust and CUDA kernels [S2, unofficial]. Typical usage targets 10,000 vertices, but performance scales with mesh size [S2, unofficial].
- **Strengths:** Fast, preserves sharp features via QEM, handles boundary preservation and topological validity checks on-device [S2, unofficial].
- **Limitations:** The actual vertex count may differ slightly from the target due to topology constraints [S2, unofficial]. Limited iterations (2) may not reach the exact target count for complex meshes [S2, unofficial]. Input tensors must be contiguous [S2, unofficial].

## Background
The method is based on Quadric Edge Collapse Decimation (QECD), originally proposed by Garland and Heckbert [S1][S3, unofficial]. It was implemented on GPU using Thrust and CUDA kernels by Hwanhuh et al. in the `spcumc` repository [S2, unofficial]. It is used as a postprocessing step in the AnalyticMesh package to simplify meshes generated by analytic marching for efficient rendering and texturing [S1].
