# Voxel Pre-integration

Also called: Color Supersampler, Linear pre-filtering, Naïve Downsampling, Volumetric Sampling Function, Voxel Mipmap Generation, Voxel Mipmap Generation and Sampling

## Overview
Voxel Pre-integration is a method to generate mipmaps for a voxelized 3D texture using bilinear filtering to create a volumetric sampling function that yields average color and occlusion for cone tracing [S1, S4, unofficial]. It solves the problem of approximating light from areas of various sizes by sampling a 4D texture (3D space + mip levels) using linear interpolation [S4, unofficial]. It differs from sibling methods like Atlas Mipmapping and GPU 3D Mip Chain Generation by specifically targeting the creation of a "volumetric sampling function" for indirect lighting approximation via cone tracing, rather than general texture compression or shadow volume optimization [S1, S4, unofficial]. Trade-offs include potential inaccuracies in appearance when input voxels are very opaque due to the loss of masking and shadowing effects [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A high-resolution 3D voxel texture (`voxelMap`) containing lighting data (e.g., Phong color values, density, or opacity) [S1, S4, unofficial].
*   **Output:** A mipmap chain of 3D textures where each level represents the average lighting over a larger spatial area [S1, S4, unofficial].
*   **Parameters:**
    *   `tex_size`: The size vector (width, height, depth) of the base 3D texture [S1, unofficial].
    *   `scene_size`: The size vector of the bounding box of the scene [S1, unofficial].
    *   `voxelizationSparsity`: Number of ticks between mipmap generation. Default: 1 [S3, unofficial].
    *   `useComputeShaderToGenMip`: Boolean flag to choose between Compute Shader and Built-in Blit Command for mipmap generation. Default: true [S3, unofficial].

**Data Structures:**
The core data structure is a 3D texture array or a 4D texture representation where the fourth dimension represents the mipmap level. Each voxel in the base level stores RGBA values (color and opacity) [S1, unofficial].

**Steps:**
1.  **Voxelization:** Rasterize scene geometry into a 3D texture. For each triangle, determine the dominant axis (largest component of the surface normal) and rasterize along that axis to maximize surface area coverage [S1, unofficial]. Assign Phong color values to the resulting voxels [S1, unofficial].
2.  **Mipmap Generation:** Generate a series of mipmaps for the resulting 3D texture using bilinear filtering methods [S1, unofficial]. This process averages the values in adjacent voxels to create lower-resolution levels. The values in the mipmaps correspond to the average direct light emitted by the surfaces in a volume specified by the given LOD level [S1, unofficial].
    *   *Note:* An alternative approach involves storing six 3D textures (anisotropic voxels) to account for directional lighting integration, averaging only on axes perpendicular to the viewing direction [S4, unofficial].
3.  **Sampling (Cone Tracing):** To approximate indirect lighting, sample the 4D texture (3D space + mip levels) using linear interpolation [S4, unofficial].
    *   Calculate the Mipmap Level of Detail (LOD) based on the cone aperture diameter:
        $$v_{level} = \log_2 \left( \frac{diameter}{tex_{size}} \right)$$
        where $diameter$ is the cone aperture diameter and $tex_{size}$ is the base texture size [S1, unofficial].
    *   Calculate the texture space position:
        $$pos_{texspace} = \frac{position}{scene_{size}} \times tex_{size}$$
        where $position$ is the world position and $scene_{size}$ is the scene bounding box size [S1, unofficial].
    *   Sample the texture using the calculated LOD and position to retrieve the pre-integrated color and occlusion [S1, unofficial].

**Pseudocode:**
The following pseudocode implements the sampling phase of Voxel Pre-integration, often referred to as the "Color Supersampler" [S1, unofficial].

```python
def sample_voxel_preintegration(position, diameter, tex_size, scene_size, voxel_map):
    """
    Samples the pre-integrated voxel mipmap chain to approximate indirect lighting.
    
    Args:
        position (vec3): World space position of the cone origin.
        diameter (float): Aperture diameter of the cone at the current step.
        tex_size (vec3): Size vector (width, height, depth) of the base 3D texture.
        scene_size (vec3): Size vector of the scene bounding box.
        voxel_map (Texture3DArray): The 3D texture containing the voxelized lighting data with mipmaps.
        
    Returns:
        vec4: Pre-integrated color and occlusion (RGBA).
    """
    # 1. Calculate Mipmap Level of Detail (LOD)
    # Formula: v_level = log2(diameter / tex_size)
    # Note: tex_size is typically treated as a scalar (e.g., width) or the method assumes isotropic voxels.
    # If tex_size is a vector, the implementation must define how to handle anisotropy in LOD calculation.
    # Based on [S1, unofficial], we use the scalar representation for the log calculation.
    base_size = tex_size.x  # Assuming isotropic or using width as reference
    v_level = log2(diameter / base_size)
    
    # 2. Calculate Texture Space Position
    # Formula: pos_texspace = position / scene_size * tex_size
    pos_texspace = (position / scene_size) * tex_size
    
    # 3. Sample the 4D texture (3D space + mip levels)
    # Using linear interpolation (bilinear/trilinear filtering)
    color_rgba = textureLod(voxel_map, pos_texspace, v_level)
    
    return color_rgba
```

**Edge Cases and Pitfalls:**
*   **Opacity and Shadowing Loss:** Linear pre-filtering does not preserve accurate transparency. Decreasing density in low-resolution voxels reduces the probability of local self-shadowing, leading to overly bright Levels of Detail (LoDs) [S2]. This is particularly problematic when input voxels are very opaque [S2].
*   **Performance Instability:** Voxelization sparsity settings can cause unstable framerates, making the method potentially unsuitable for interactive applications if not tuned correctly [S3, unofficial].
*   **Boundary Conditions:** The position calculation assumes the scene fits within `scene_size`. Out-of-bounds coordinates must be handled (e.g., clamping or returning transparent black) [S3, unofficial].

## Subtopics

### [Cone Stepping and Mip Level Selection](3515-cone-stepping-and-mip-level-selection.md)
Cone Stepping and Mip Level Selection is the sampling phase of Voxel Pre-integration, where a 3D mipmap texture is traversed along a ray to approximate indirect lighting. It solves the problem of aliasing and performance in volumetric light transport by dynamically selecting the appropriate Level of Detail (LOD) based on the projected size of the sampling cone relative to the voxel grid. It differs from sibling methods by calculating the cone diameter at each step to derive a continuous mip level, whereas alternatives like Brick LOD Selection calculate resolution bounds for entire brick volumes rather than individual samples.

## Operating characteristics
*   **Time Complexity:** Mipmap generation is $O(N)$ where $N$ is the number of voxels in the base level, assuming a fixed number of mipmap levels. Sampling is $O(1)$ per cone trace.
*   **Memory Complexity:** Requires storing the full mipmap chain, increasing memory usage by approximately 33% over the base texture (sum of geometric series $1 + 1/4 + 1/16 + \dots$).
*   **Measured Performance:** Performance depends on the mipmap generation method (Compute Shader vs. Built-in Blit Command) [S3, unofficial]. Compute Shaders may offer more control but require additional implementation overhead.
*   **Strengths:** Simple to implement; provides a good approximation of indirect lighting for diffuse surfaces; supports dynamic LOD selection based on cone size [S1, S4, unofficial].
*   **Limitations:** Inaccurate appearance for highly opaque or heterogeneous volumes due to loss of self-shadowing and masking effects [S2]. Potential framerate instability due to voxelization sparsity [S3, unofficial].
*   **When to Use:** Suitable for real-time global illumination approximations where performance is critical and visual accuracy for dense, opaque volumes is secondary [S1, S4, unofficial].
*   **When Not to Use:** Not suitable for high-fidelity rendering of dense, heterogeneous volumes where accurate transparency and self-shadowing are required [S2].

## Background
Voxel Pre-integration was introduced as part of the Voxel Cone Tracing technique for real-time global illumination. The method was described in the thesis "Real-Time Global Illumination Using OpenGL And Voxel Cone Tracing" [S1, unofficial]. It builds upon the concept of using voxelized lighting data to approximate indirect illumination. The technique was further explored in implementations such as "Voxel Cone Tracing - GitHub" [S4, unofficial] and "kakashidinho/VoxelConeTracingMetal" [S3, unofficial]. The limitations of linear pre-filtering for downsampling microflake volumes were later analyzed in "A new microflake model with microscopic self-shadowing for accurate volume downsampling" [S2], which proposed alternative methods to preserve appearance accuracy.
