# Wavelet Tree

Also called: Wavelet-based Multiresolution Tree, Hierarchical Wavelet Tree

## Overview
A Wavelet Tree is a multiresolution data representation that converts a large 3D volume into a hierarchical structure using wavelet transforms to enable level-of-detail (LOD) selection and efficient rendering [S1]. It solves the problem of managing large volumetric datasets by allowing the renderer to traverse the tree and select data blocks at appropriate resolutions based on a hierarchical error metric [S1]. Unlike standard subdivision hierarchies which may produce topological inaccuracies, this method ensures correct topological information and smaller root-mean-square errors by reorganizing data into wavelet coefficients without requiring additional memory for the hierarchy structure itself [S1]. It builds on [Wavelet-based Multiresolution](6266-wavelet-based-multiresolution.md) by providing the specific tree structure and traversal logic for 3D volumes.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset.
*   **Output:** A tree structure where leaf nodes store raw volume blocks, internal nodes store low-resolution data blocks and compressed wavelet coefficients, and the root node stores a single block representing the entire volume [S1].

**Data Structures:**
The tree is organized hierarchically. Each node $N$ contains:
1.  **Low-resolution data block:** A 3D array of voxels. For leaf nodes, this is the raw data. For internal nodes, this is the aggregated low-pass subblock from its children.
2.  **Wavelet coefficients:** A 3D array of detail coefficients. For leaf nodes, these are the high-pass coefficients from the initial transform. For internal nodes, these are the coefficients generated when transforming the parent's low-res data from the children's low-res data.
3.  **Error metric:** A scalar value representing the approximation error for the node [S1].

**Construction Algorithm:**
The construction is a bottom-up process [S1].

1.  **Leaf Initialization:** Subdivide the original 3D volume into a sequence of blocks of the same size, assuming each has $n$ voxels. These raw volume blocks form the leaf nodes of the wavelet tree [S1].
2.  **Leaf Transform:** Perform a 3D wavelet transform on each leaf block. This produces a low-pass filtered subblock of size $n/8$ and wavelet coefficients of size $7n/8$ [S1].
3.  **Parent Aggregation:** Group the low-pass filtered subblocks from eight adjacent leaf nodes into a single block of $n$ voxels. This block becomes the low-resolution data block stored in the parent node [S1].
4.  **Recursive Transform:** Recursively apply the 3D wavelet transform and subblock grouping process in a bottom-up manner until the root is reached. At the root, a single block of size $n$ represents the entire volume [S1].
5.  **Thresholding:** Compress the wavelet coefficients by setting coefficients smaller than a user-specified threshold $T$ to zero. This reduces the storage size [S1].
6.  **Compression:** Compress the thresholded wavelet coefficients using run-length encoding combined with a fixed Huffman encoder [S1].

**Hierarchical Error Metric:**
A hierarchical error metric is calculated for each node to guide LOD selection [S1]. The error $E(N)$ for a node $N$ is defined as:
$$ E(N) = \max_{C \in Children(N)} (MSE(N_{low}, C_{raw})) + \max_{C \in Children(N)} (E(C)) $$
Where:
*   $N_{low}$ is the low-resolution data block stored in node $N$.
*   $C_{raw}$ is the raw data of child node $C$ (or the reconstructed data if $C$ is internal, though the source specifies "data in its eight immediate child nodes" implying the raw or base data of the children for the MSE calculation) [S1].
*   $MSE(A, B)$ is the Mean Square Error between data block $A$ and data block $B$.
*   The metric guarantees that the error value of a parent node is greater than or equal to those of its eight child nodes [S1].

## Subtopics

### [Hierarchical Wavelet Tree Construction](6598-hierarchical-wavelet-tree-construction.md)
Hierarchical Wavelet Tree Construction is a bottom-up blockwise wavelet transform and compression scheme used to construct a multiresolution wavelet tree for 3D volume data. It solves the problem of managing large volumetric datasets by enabling parallel rendering of selected data blocks at various levels of detail. Unlike standard subdivision hierarchies which may produce topological inaccuracies, this method ensures correct topological information and smaller root-mean-square errors by reorganizing data into wavelet coefficients without requiring additional memory for the hierarchy structure itself. It builds on [Wavelet Tree](5390-wavelet-tree.md) by providing the specific algorithmic steps for generating the tree structure and coefficients.

### [Huffman-shaped Wavelet Matrix](10172-huffman-shaped-wavelet-matrix.md)
The Huffman-shaped Wavelet Matrix is a compressed index data structure used to provide random access to a stream of node operations in segmentation volume bricks. It maps symbols from a small alphabet to bit patterns using bit-wise negated Canonical Huffman Codes (CHC), stored in a level-wise concatenated bit vector acting as a wavelet matrix. It enables variable bit-length compression and random access, solving the limitation of the parent CSGV method which uses ANS stream compression and requires serial decoding. It sets itself apart from general wavelet matrices by exploiting the specific structure of the CHC to eliminate branching and interval tracking during access queries.

### Wavelet Coefficient Trees
Wavelet Coefficient Trees define parent-child relationships with respect to the slow growing refinement structure, rooted in mesh elements of the base (tier 0) mesh [S2]. Tier 2 vertices are associated with edge centers of the tier 0 mesh, and a coarse wavelet coefficient at tier 3 has only tier 3 descendants associated with that edge [S2]. Tier 1 vertices are associated with face centers of the tier 0 mesh; a tier 2 wavelet at level $l$ has two sets of child coefficients at level $l+1$: one child wavelet for each face produced by dividing the tier 0 face, and one child wavelet for each edge introduced into the tier 0 face [S2]. Tier 0 wavelets are associated with tier 0 cell centers; a tier 0 wavelet at level $l$ has three sets of children at level $l+1$: one wavelet for each subcell the tier 0 cell is divided into, one wavelet for each face inserted to produce those subcells, and one wavelet for each internal edge required to subdivide the tier 0 cell [S2].

## Operating characteristics
*   **Time Complexity:** Construction is $O(N)$ where $N$ is the number of voxels, as each voxel is processed a constant number of times in the hierarchical transform [S1]. Traversal for rendering is proportional to the number of nodes visited, which depends on the LOD selection criteria [S1].
*   **Memory Complexity:** The tree structure itself requires $O(N)$ memory for the low-resolution data blocks. The wavelet coefficients are compressed, reducing the storage overhead [S1]. The source states it does not require additional memory for the hierarchy structure itself [S1].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** The method scales well for large datasets due to the hierarchical nature and compression [S1].
*   **Strengths:** Ensures correct topological information, smaller root-mean-square errors, and efficient LOD selection via the hierarchical error metric [S1].
*   **Limitations:** Requires a user-specified threshold for compression, which can affect image quality [S1]. The exact upsampling and reconstruction methods are not specified in the sources [G].
*   **When to use:** When rendering large 3D volumes with LOD requirements and topological accuracy is critical [S1].
*   **When not to use:** When random access to specific voxels without traversal is required, or when the overhead of tree construction is prohibitive for small datasets [G].

## Background
The Wavelet Tree was introduced in the context of hierarchical navigation interfaces for large 3D steady and time-varying data sets [S1]. It is based on the work of Kindermann et al. [10] and uses a hierarchical error metric [33] to control the trade-off between image quality and rendering speed [S1]. The method is used in volume rendering to enable efficient multiresolution traversal [S1].
