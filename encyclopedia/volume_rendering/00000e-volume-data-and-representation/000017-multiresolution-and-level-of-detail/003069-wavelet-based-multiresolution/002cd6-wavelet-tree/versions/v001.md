# Wavelet Tree

Also called: Wavelet-based Multiresolution Hierarchy, Wavelet Volume Tree

## Overview
A wavelet tree is a multiresolution data representation that converts a large 3D volume into a hierarchical structure using wavelet transforms, enabling efficient level-of-detail (LOD) selection and rendering [S1]. It differs from sibling methods like [Projecting Detail Coefficients](1802-projecting-detail-coefficients.md) by organizing data into a strict parent-child tree where internal nodes store low-resolution approximations and compressed detail coefficients, rather than projecting coefficients onto a 2D plane. It complements the [Wavelet Tree Overview Map](5354-wavelet-tree-overview-map.md) by providing the underlying data structure that the overview map visualizes.

## How it works
**Inputs and Outputs**
*   **Input:** A 3D volume dataset.
*   **Output:** A hierarchical tree structure where leaf nodes contain raw volume blocks, internal nodes contain low-resolution data blocks and compressed wavelet coefficients, and the root contains a single block representing the entire volume [S1].

**Data Structures and Layout**
The tree is constructed bottom-up. Each node in the tree corresponds to a spatial block of the volume.
*   **Leaf Nodes:** Store raw volume blocks of size $n$ voxels.
*   **Internal Nodes:** Store a low-resolution data block of size $n$ voxels (derived from the low-pass subblocks of its eight children) and a set of wavelet coefficients of size $7n/8$ (the detail information discarded during the low-pass filtering) [S1].
*   **Root Node:** Stores a single block of size $n$ representing the coarsest approximation of the entire volume [S1].

**Parameters**
*   **Block Size ($n$):** The number of voxels in each leaf block. The sources assume uniform block sizes [S1].
*   **Threshold ($T$):** A user-specified threshold for wavelet coefficients. Coefficients with magnitude smaller than $T$ are set to zero to reduce storage size [S1].

**Algorithm Steps**
1.  **Subdivision:** Subdivide the original 3D volume into a sequence of non-overlapping blocks of equal size, each containing $n$ voxels. These blocks form the leaf nodes of the wavelet tree [S1].
2.  **Leaf Transform:** Perform a 3D wavelet transform on each leaf block. This produces:
    *   A low-pass filtered subblock of size $n/8$ voxels.
    *   Wavelet coefficients (detail subbands) of size $7n/8$ voxels [S1].
3.  **Parent Aggregation:** Group the low-pass filtered subblocks from eight adjacent leaf nodes (forming a $2 \times 2 \times 2$ block in the spatial hierarchy) into a single block of $n$ voxels. This aggregated block becomes the low-resolution data stored in the parent node [S1].
4.  **Coefficient Storage:** Store the wavelet coefficients generated in Step 2 within the parent node. These coefficients represent the difference between the parent's low-resolution data and the children's raw data [S1].
5.  **Thresholding:** For each internal node, compare its wavelet coefficients against the user-specified threshold $T$. If a coefficient's absolute value is less than $T$, set it to zero [S1].
6.  **Compression:** Compress the thresholded wavelet coefficients in each node using run-length encoding combined with a fixed Huffman encoder [S1].
7.  **Recursion:** Recursively apply Steps 2–6 to the parent nodes, treating the aggregated low-resolution blocks as the input for the next level of the hierarchy. Continue until the root node is reached, which contains a single block of size $n$ representing the entire volume [S1].

**Hierarchical Error Metric**
To support LOD traversal, a hierarchical error metric is calculated for each node [S1]:
1.  Compute the Mean Square Error (MSE) between the data in a parent node and the data in its eight immediate child nodes.
2.  The error value for the parent node is the maximum of the error values among its eight children [S1].
This metric guarantees that a parent node's error is greater than or equal to its children's errors, allowing for efficient error-bounded traversal [S1].

## Subtopics

### [Hierarchical Wavelet Tree Construction](6598-hierarchical-wavelet-tree-construction.md)
A bottom-up blockwise wavelet transform and compression scheme used to construct a multiresolution wavelet tree for volume data, allowing for parallel rendering of selected data blocks at various levels of detail.

## Operating characteristics
*   **Time Complexity:** Construction is $O(N \log N)$ where $N$ is the total number of voxels, due to the recursive application of the wavelet transform across $\log_2(\text{depth})$ levels. Traversal for rendering is proportional to the number of nodes visited, which depends on the error threshold and desired image quality.
*   **Memory Complexity:** The tree stores $O(N)$ data. The low-resolution data at each level sums to $N$ (since each level partitions the volume). The coefficients are compressed; with a high threshold, storage approaches $O(N)$ but with a smaller constant factor.
*   **Performance:** The hierarchical error metric allows for rapid pruning of nodes that do not contribute significantly to the image, enabling fast rendering at low resolutions or distant viewpoints [S1].
*   **Strengths:** Supports arbitrary LOD selection; efficient compression of detail coefficients; error-bounded traversal guarantees [S1].
*   **Limitations:** Requires regular block subdivision; compression artifacts may appear if the threshold is too high; 3D wavelet transform can be computationally expensive during construction [S1].

## Background
The wavelet tree was introduced as part of a hierarchical navigation interface for large 3D steady and time-varying data sets [S1]. It leverages wavelet transforms to create a multiresolution representation, building on earlier work in wavelet-based time-space partitioning trees [S1, S25]. The hierarchical error metric used for node evaluation is cited from [33] in the source [S1].
