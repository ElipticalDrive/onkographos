# Huffman-shaped Wavelet Matrix

Also called: CSGV-R Wavelet Matrix, CSGV-R compression structure, Huffman-shaped wavelet tree, Wavelet Tree Implementation for CSGV-R, Wavelet matrix

## Overview
The Huffman-shaped Wavelet Matrix is a compressed index data structure used to provide random access to a stream of node operations in segmentation volume bricks [S1]. It maps symbols from a small alphabet to bit patterns using bit-wise negated Canonical Huffman Codes (CHC), stored in a level-wise concatenated bit vector acting as a wavelet matrix [S1]. It enables variable bit-length compression and random access, solving the limitation of the parent CSGV method which uses ANS stream compression and requires serial decoding [S1]. It sets itself apart from general wavelet matrices by exploiting the specific RICE-like structure of the CHC to eliminate branching and interval tracking during access queries [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A stream of node operations $T$ derived from encoding a label multi-grid (coarsest to finest level) of a volume brick [S1]. The alphabet $\Sigma$ consists of 6 symbols: $\{ \text{copy\_parent}, \text{copy\_X}, \text{copy\_Y}, \text{copy\_Z}, \text{copy\_palette}, \text{back\_ref\_1} \}$ [S1]. The $\delta$ operation is omitted; back reference distance $\delta=1$ is encoded as a specific symbol [S1].
*   **Output:** A compressed representation consisting of the Wavelet Matrix bit vector $W$, level start indices, a flat rank structure for $W$, a separate Stop Bit vector $S$, and its rank structure [S1].

**Data Structures and Layout:**
1.  **Wavelet Matrix $W$:** A level-wise concatenated bit vector storing the CHC of the operations [S1]. The maximum CHC length is 5, resulting in 5 levels ($l=0$ to $4$) [S1].
2.  **Level Start Indices:** An array $W_0 \dots W_4$ storing the starting bit index of each level within $W$ [S1].
3.  **Flat Rank Structure:** Stored next to $W$ to support constant-time rank queries [S1]. It uses 3.51% additional space overhead [S1].
4.  **Stop Bit Vector $S$:** A separate bit vector $S[i] : i \to \{0,1\}$ indicating if a node's region is constant in all finer levels [S1]. Stored after the operation list with its own flat rank structure [S1].
5.  **Brick Header:** Contains start offsets for each LOD in the operation/stop bit lists ($T_0 \dots T_L$), palette size, and wavelet query info including $Z_1[l] = \text{rank}_1^W(W_l)$ (number of 1 bits before each level) [S1].
6.  **Storage Format:** Bit vectors and flat ranks are stored as arrays of 64-bit words [S1]. Bit index order inside a word goes from least significant bit (LSB) to most significant bit (MSB) [S1].

**Canonical Huffman Codes (CHC):**
The CHCs are bit-wise negated codes derived from operation frequencies [S1]. Shorter codes are lexicographically greater, placing shorter levels on the right-hand side of the tree [S1]. The codes follow a RICE-coding-like layout where the number of consecutive 0 bits determines the operation [S1]. Consequently, any 1 bit terminates a symbol, and no right children exist in the conceptual tree [S1].

**Construction Steps:**
1.  Encode the label multi-grid from coarsest to finest level into a list of operations $T$, omitting $\delta$ and using `back_ref_1` [S1].
2.  Compress $T$ as a Huffman-shaped wavelet tree using the hard-coded CHCs [S1].
3.  Store the result as wavelet matrix $W$ using the prefix counting algorithm [S1].
4.  Construct and store the flat rank structure next to $W$ [S1].
5.  Store stop bits $S$ separately with its own rank structure [S1].

**Formulas:**
*   Bit access: $\text{access}(i) = B[i]$ for bit vector $B$ [S1].
*   Rank query: $\text{rank}_\alpha(i) = |\{ j < i : B[j] = \alpha \}|$ for $\alpha \in \{0,1\}$, returning the number of times $\alpha$ occurred before $i$ [S1].

**Access Query:**
To access $T[i]$, the algorithm traverses the wavelet matrix [S1]. Due to the CHC structure, the direction bit $\alpha$ at level $l$ is the $l$-th bit of the code [S1]. Because any 1 bit terminates a symbol, the operation number is simply the number of zeros before the first 1 bit [S1]. This eliminates branch tracking and interval start tracking [S1].

**Rank Query:**
For rank queries, the character's CHC (e.g., `00001`) can be hardcoded to remove branching [S1]. A single interval exists per level (prefix of 0s) starting at $W_l$ [S1].

**Pseudocode:**

```python
def access_bit(W_words, i):
    """Access the i-th bit in a flat bit vector W stored as 64-bit words.
    Bit order inside a word is LSB to MSB [S1]."""
    word_idx = i // 64
    bit_off = i & 63
    return (W_words[word_idx] >> bit_off) & 1

def access_T(W_words, W_starts, i):
    """Access operation at stream index i using the Huffman-shaped wavelet matrix.
    Exploits RICE-like CHC: counts zeros until first 1 across levels [S1]."""
    symbol_len = 0
    for l in range(5):  # Levels 0 to 4
        # Level l bits are stored contiguously starting at W_starts[l]
        bit = access_bit(W_words, W_starts[l] + i)
        if bit == 1:
            return symbol_len
        symbol_len += 1
    return symbol_len  # Fallback for max-length code

def rank_1_flat(W_words, W_block_counts, W_block_size, i):
    """Compute rank_1(i) using a flat rank structure [G].
    Standard block-based implementation: precomputed counts per block + popcount."""
    block_idx = i // W_block_size
    block_start = block_idx * W_block_size
    # Count 1s in the current block up to offset i
    mask = (1 << (i % W_block_size)) - 1
    current_block_ones = bin(W_words[block_idx] & mask).count('1')
    return W_block_counts[block_idx] + current_block_ones

def idx(n, l_bar, T_offsets, S_words, S_block_counts, S_block_size):
    """Compute the operation stream index for a grid node (Morton code n, LOD l_bar).
    Handles stop bit offsets iteratively [S1]."""
    offset = 0
    current_l = l_bar
    current_n = n
    
    for l_prime in range(current_l + 1):
        # Parent node index in LOD l_prime
        exponent = 3 * (current_l - l_prime)
        n_parent = current_n >> exponent
        
        # Absolute index in stop bit stream for this parent
        stream_idx = T_offsets[l_prime] + n_parent - offset
        
        # Check if parent sets a stop bit
        if access_bit(S_words, stream_idx) == 1:
            current_l = l_prime
            current_n = n_parent
            break
        
        # Update offset: subtract stop bits in range [T[l_prime], T[l_prime] + n_parent)
        idx_end = T_offsets[l_prime] + n_parent - offset
        idx_start = T_offsets[l_prime]
        offset += rank_1_flat(S_words, S_block_counts, S_block_size, idx_end) - \
                  rank_1_flat(S_words, S_block_counts, S_block_size, idx_start)
        
        # Scale offset for next coarser level (factor of 8 per level)
        offset = 8 * offset

    return T_offsets[current_l] + current_n - offset
```

**Edge Cases and Pitfalls:**
*   **Stop Bit Offsets:** Stop bits on coarser levels in earlier Z-curve regions remove $2^d \Delta L$ node index predecessors [S1]. Nodes in removed regions must use the parent's index [S1].
*   **Negative Offset:** The offset calculation in `idx` must correctly handle the subtraction of stop bit counts to map Morton codes to stream indices [S1].
*   **Bit Order:** Bit index order inside 64-bit words is LSB to MSB [S1].

## Operating characteristics
*   **Time Complexity:** Access and rank queries take $O(\log \sigma)$ time, where $\sigma = 6$ is the alphabet size [S1]. The `idx` function takes $O(L) = O(\log_b)$ time [S1].
*   **Space Complexity:** The wavelet matrix uses $|T| \lceil H_0(T) \rceil (1+o(1))$ bits [S1]. The flat rank structure adds 3.51% overhead [S1].
*   **Performance:** Uses Vulkan buffer device addresses to pass references to brick bit vectors and headers to decoding functions [S1]. Eliminates branching and interval tracking compared to general wavelet matrices [S1].
*   **Strengths:** Enables random access to compressed segmentation volumes, unlike the serial CSGV [S1]. Efficient for GPU rendering pipelines [S1].
*   **Limitations:** Limited to the specific CHC structure of CSGV-R. Alphabet size is fixed to 6 symbols in this implementation [S1].

## Background
The Huffman-shaped Wavelet Matrix was introduced in the context of Random Access Segmentation Volume Compression for Interactive Volume Rendering [S1]. It builds on the CSGV compression method, replacing its ANS stream compression with a wavelet-based structure to enable random access [S1]. It generalizes wavelet trees [GGV03] and wavelet matrices [CNP15] to a specific application domain using bit-wise negated Canonical Huffman Codes [DEF* 21].
