# Projecting Detail Coefficients

Also called: Projecting the detail coefficients

## Overview
Projecting Detail Coefficients is a rendering technique for Multiresolution Maximum Intensity Projection (MMIP) that accelerates volume visualization by projecting wavelet detail coefficients directly to screen space [S1]. It solves the problem of high memory bandwidth consumption in large volumetric datasets by leveraging a multi-level decomposition, where lower-resolution levels are rendered to smaller viewports [S1]. Unlike standard ray-casting which processes every voxel, this method iterates over intensity thresholds and renders pre-decomposed detail levels ($d_0 \dots d_{L-1}$) and the final approximation ($f_L$) separately, allowing for efficient load balancing across multiple GPUs [S1].

## How it works
**Inputs:**
- Volumetric dataset decomposed into $L+1$ levels: detail levels $d_0, \dots, d_{L-1}$ and approximation $f_L$ [S1].
- Volume orientation (quaternion) and zoom factor (default: 1 voxel per 1 pixel) [S1].
- Lower intensity threshold (background) and optional upper intensity threshold (maximum intensity) [S1].

**Outputs:**
- A 2D projection image (Maximum Intensity Projection) [S1].

**Data Structures:**
- The volume data is stored as $L+1$ separate volumes. For an $L$-level decomposition, the structure consists of:
  - $d_i$: Detail coefficients at level $i$ (for $i = 0$ to $L-1$) [S1].
  - $f_L$: Approximation coefficients at the coarsest level $L$ [S1].
- Each level $i$ is associated with a specific viewport size: Level 0 uses the full viewport size, Level 1 uses half the size, Level 2 uses a quarter, and so on [S1].

**Steps:**
1. **Matrix Construction:** Build a model-view matrix from the volume orientation quaternion and the zoom factor. Combine this with the projection matrix to form a 4x4 modelview-projection matrix. Pass this matrix to the vertex shader [S1].
2. **Threshold Iteration:** Iterate over the intensity values present in the volume, starting from the lowest value (or user-defined lower threshold) up to the highest [S1].
3. **Upper Threshold Optimization:** If an upper intensity threshold exists above which all voxels have maximum intensity, project all these voxels in a single call to `glDrawArrays` using point primitives. This step skips rounding or anti-aliasing for these maximum-intensity regions [S1].
4. **Multi-Level Rendering:** Render each of the $L+1$ volumes ($d_0 \dots d_{L-1}$ and $f_L$) using the same projection logic.
   - Render level 0 to a quad with dimensions equal to the viewport size.
   - Render level 1 to a quad with half the viewport dimensions.
   - Render level $k$ to a quad with dimensions scaled by $1/2^k$ [S1].
5. **Compositing:** The results from the different levels are combined to form the final MMIP image. The specific compositing logic (e.g., alpha blending or max accumulation) is implied by the MMIP context but not explicitly detailed in the source beyond the projection steps [S1].

**Pseudocode:**
```python
def project_detail_coefficients(volume_decomposition, orientation_quaternion, zoom_factor, 
                                lower_threshold, upper_threshold, viewport_size):
    """
    volume_decomposition: List of volumes [d_0, d_1, ..., d_{L-1}, f_L]
    orientation_quaternion: Quaternion representing volume orientation
    zoom_factor: Float, default 1.0 (1 voxel per pixel)
    lower_threshold: Intensity value below which voxels are background
    upper_threshold: Intensity value above which voxels are max intensity (optional)
    viewport_size: Tuple (width, height)
    """
    # Step 1: Construct Model-View-Projection Matrix
    model_view_matrix = build_model_view_matrix(orientation_quaternion, zoom_factor)
    projection_matrix = build_projection_matrix() # Assumed standard projection
    mvp_matrix = multiply_matrices(projection_matrix, model_view_matrix)
    
    # Step 3: Handle upper threshold optimization if present
    if upper_threshold is not None:
        max_intensity_voxels = extract_voxels_above_threshold(volume_decomposition, upper_threshold)
        if max_intensity_voxels is not empty:
            render_point_primitives(max_intensity_voxels, mvp_matrix)
            
    # Step 4: Render multi-level decomposition
    for level_index, detail_volume in enumerate(volume_decomposition):
        # Determine viewport size for current level
        # Level 0: full size, Level 1: half, Level 2: quarter, etc.
        scale_factor = 1.0 / (2 ** level_index)
        current_viewport_width = viewport_size[0] * scale_factor
        current_viewport_height = viewport_size[1] * scale_factor
        
        # Render the current level's detail coefficients
        # The source states they are rendered "in the same fashion"
        # implying a projection pass for each level
        render_volume_to_quad(detail_volume, mvp_matrix, 
                              current_viewport_width, current_viewport_height)
                              
    # Note: The source does not specify the exact compositing shader code
    # for combining these levels into the final MMIP image [S1].
```

**Parameters:**
- Zoom factor: Default 1 voxel on 1 pixel [S1].
- $L$: Number of decomposition levels. Requires $L+1$ volumes [S1].

**Edge Cases and Pitfalls:**
- **Upper Threshold:** If an upper threshold is defined, all voxels above it are rendered as point primitives without rounding or anti-aliasing. This is an optimization but may affect visual smoothness at the boundaries of high-intensity regions [S1].
- **Viewport Scaling:** Rendering lower levels to smaller viewports requires careful handling of coordinate transformations to ensure correct spatial alignment with higher-resolution levels [S1].
- **Load Balancing:** The method supports multi-GPU rendering by switching GL contexts between X-screens per frame. This requires driver support for multiple cards on one X-server [S1].

## Operating characteristics
- **Memory Bandwidth:** The method aims to reduce memory bandwidth usage by increasing the ratio of memory bandwidth to voxel count through multiresolution representation [S1].
- **Performance:** The Multi-Resolution MIP (MMIP) algorithm allows for straightforward load spreading over multiple graphics cards, achieving almost optimal speedup for large volumes [S1].
- **Hardware Requirements:** Requires graphics hardware capable of vertex shaders and multiple GPU support (e.g., newer NVIDIA drivers supporting multiple cards for one X-server) [S1].
- **Strengths:** Efficient handling of large volumetric datasets; supports interactive adjustment of orientation and zoom; enables multi-GPU acceleration [S1].
- **Limitations:** Relies on orthogonal projection in the described examples (though generality is claimed) [S1]. The specific compositing details for combining levels are not provided in the source [S1].

## Background
The method is described in the paper "Multiresolution MIP Rendering of Large Volumetric Data Accelerated on Graphics Hardware" (EuroVis 2007) [S1]. It builds on the principles of multiresolution and level of detail, specifically utilizing wavelet-based decomposition for volume rendering [S1, S2]. The approach was developed to address the computational and memory challenges of rendering large volumetric datasets on graphics hardware [S1].
