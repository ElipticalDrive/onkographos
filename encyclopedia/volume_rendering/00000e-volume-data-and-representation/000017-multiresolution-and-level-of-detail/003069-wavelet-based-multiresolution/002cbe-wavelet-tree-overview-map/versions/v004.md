# Wavelet Tree Overview Map

Also called: Overview Map Visualization

## Overview
The Wavelet Tree Overview Map is a visualization technique designed to provide an instant, global overview of the error distribution within a wavelet-based multiresolution volume hierarchy [S1]. It solves the problem of navigating complex LOD (Level of Detail) structures by mapping the entire wavelet tree into a 2D equilateral triangle frame, allowing users to identify regions requiring refinement or coarsening [S1]. It sets itself apart from sibling methods like [Projecting Detail Coefficients](1802-projecting-detail-coefficients.md) by visualizing the full tree structure and error landscape simultaneously, rather than projecting specific frequency bands, and from [Wavelet Tree](5390-wavelet-tree.md) by providing a continuous color-filled error map rather than a discrete structural diagram.

## How it works
**Inputs and Outputs:**
*   **Input:** The complete wavelet tree hierarchy (nodes, levels, parent-child relationships) and the associated error metric for each node [S1].
*   **Output:** A 2D image where the wavelet tree is mapped to an equilateral triangle, with colors representing error magnitudes and a highlighted cut representing the current LOD [S1].

**Data Structures:**
The method relies on the existing wavelet tree data structure. Each node $N$ is defined by:
*   `level`: The depth in the tree (root is level 0).
*   `index`: The ordinal position of the node among its siblings at the same level.
*   `error`: The scalar error value associated with the node [S1].

**Steps:**

1.  **Frame Construction:** Draw an equilateral triangle frame. The apex represents the root of the wavelet tree, and the base represents all leaf nodes [S1].
2.  **Level Segmentation:** Draw horizontal line segments within the triangle frame at equal vertical distances to depict intermediate tree levels [S1].
3.  **Node Mapping:** Map each wavelet tree node to a point on the horizontal line segment corresponding to its tree level.
    *   Nodes at the same level are arranged equidistantly from left to right based on their ordinal index [S1].
    *   This mapping is performed in data space, independent of the run-time volume orientation [S1].
4.  **Error Color Mapping:** Transform the error values to colors.
    *   For hierarchies with large error ranges, transform errors $E$ into square root or logarithmic values before linearly mapping to colors to better utilize the color spectrum [S1].
    *   Typical mapping: Low errors $\rightarrow$ Violet; High errors $\rightarrow$ Red [S1].
5.  **Triangle Fan Filling:** Fill the triangle frame by drawing "triangle fans" for all parent-child branches.
    *   Each fan consists of a parent node and its children [S1].
    *   Vertices of the fan are colored according to the mapped error values [S1].
6.  **Hole Filling:** Address the "holes" (quads) left between neighboring triangle fans.
    *   A hole is formed by two neighboring parent nodes ($V_1, V_4$) and their adjacent children ($V_2, V_3$) [S1].
    *   Fill these quads with colors linearly interpolated from the four vertices to provide a continuous error distribution view and avoid a fractal appearance that hinders observation [S1].
7.  **LOD Highlighting:** Highlight the current Level of Detail (LOD).
    *   Draw a "cut" through the triangle frame corresponding to the active LOD [S1].
    *   Draw each node along the cut as a small square at its mapped point location [S1].
    *   Connect these squares following the Depth-First Search (DFS) order of the nodes [S1].

**Pitfalls:**
*   **Holes:** Filling only triangle fans leaves quads between neighboring parents empty, creating a fractal appearance that obscures error distribution [S1]. These must be filled via interpolation [S1].
*   **Color Indistinguishability:** If error values are very similar, colors may be indistinguishable. Using non-linear transformations (sqrt/log) helps mitigate this [S1].

**Pseudocode:**

```python
def draw_wavelet_tree_overview_map(tree, current_lod_nodes):
    """
    Draws the Wavelet Tree Overview Map.
    tree: Object containing all wavelet nodes with attributes: level, index, error.
    current_lod_nodes: List of nodes currently active in the LOD.
    """
    # 1. Define Frame Geometry
    # Equilateral triangle with apex at (0, H) and base at y=0
    # Height H is arbitrary, e.g., 1.0
    H = 1.0
    width_at_level = lambda level, total_levels: (level / total_levels) * 2.0 
    
    # 2. Map Nodes to Points
    # Calculate max level to determine vertical spacing
    max_level = max(node.level for node in tree.nodes)
    
    points = {} # Map node_id -> (x, y)
    
    for node in tree.nodes:
        # Vertical position based on level (apex is level 0, base is max_level)
        # Inverted y for screen coordinates if necessary, assuming y=0 is bottom
        y = H * (1.0 - node.level / max_level)
        
        # Horizontal position: equidistant among siblings at this level
        # Count nodes at this level to determine spacing
        nodes_at_level = [n for n in tree.nodes if n.level == node.level]
        total_at_level = len(nodes_at_level)
        
        # Sort by index to ensure left-to-right order
        nodes_at_level.sort(key=lambda n: n.index)
        
        # Find index of current node in sorted list
        idx = nodes_at_level.index(node)
        
        # x is normalized 0 to 1, then scaled to width at this y
        x_normalized = idx / (total_at_level - 1) if total_at_level > 1 else 0.5
        x = x_normalized * width_at_level(node.level, max_level)
        
        points[node.id] = (x, y)

    # 3. Color Mapping
    # Transform errors for better color utilization
    def map_error_to_color(error):
        # Example: Logarithmic transform
        import math
        if error <= 0:
            return (0, 0, 1) # Violet
        # Normalize error to [0, 1] range based on global min/max
        # Assuming global_min and global_max are known or computed
        normalized = math.log(error + 1) / math.log(global_max + 1)
        # Map to Red (high) to Violet (low)
        r = normalized
        b = 1.0 - normalized
        return (r, 0, b)

    # 4. Fill Triangle Fans
    # For each parent, draw triangle with children
    for parent in tree.nodes:
        children = tree.get_children(parent.id)
        if not children:
            continue
        
        p_pos = points[parent.id]
        p_color = map_error_to_color(parent.error)
        
        for child in children:
            c_pos = points[child.id]
            c_color = map_error_to_color(child.error)
            
            # Draw triangle fan segment (parent, child, next_sibling_or_edge)
            # Note: The source describes filling fans. Implementation requires 
            # handling the specific geometry of "fans" within the triangle.
            # Simplified: Draw triangle between parent and two adjacent children 
            # or parent and edge of the level segment.
            draw_triangle(p_pos, c_pos, get_adjacent_point(parent, child), p_color, c_color)

    # 5. Fill Holes (Quads)
    # Identify quads between neighboring parents
    for i in range(len(tree.nodes_at_level(level)) - 1):
        p1 = tree.nodes_at_level(level)[i]
        p2 = tree.nodes_at_level(level)[i+1]
        
        # Get children of p1 and p2
        c1_last = p1.children[-1] if p1.children else None
        c2_first = p2.children[0] if p2.children else None
        
        if c1_last and c2_first:
            # Quad vertices: p1, c1_last, c2_first, p2
            v1 = points[p1.id]
            v2 = points[c1_last.id]
            v3 = points[c2_first.id]
            v4 = points[p2.id]
            
            c1 = map_error_to_color(p1.error)
            c2 = map_error_to_color(c1_last.error)
            c3 = map_error_to_color(c2_first.error)
            c4 = map_error_to_color(p2.error)
            
            # Fill quad with interpolated colors
            fill_quad(v1, v2, v3, v4, c1, c2, c3, c4)

    # 6. Highlight LOD Cut
    # Draw squares for active nodes and connect in DFS order
    dfs_order = get_dfs_order(current_lod_nodes)
    prev_pos = None
    
    for node in dfs_order:
        pos = points[node.id]
        color = map_error_to_color(node.error)
        draw_square(pos, size=5, color=color)
        
        if prev_pos:
            draw_line(prev_pos, pos, color=(1, 1, 1)) # Highlight line
        prev_pos = pos
```

## Subtopics

### Treemap Visualization for Active Nodes
A space-filling alternative to the Overview Map that displays only the active nodes (those in the current LOD) to avoid clutter and sub-pixel resolution issues [S1].
*   **Definition:** Uses recursively subdivided display areas (alternating vertical/horizontal subdivisions) to present hierarchical information via visual attributes like color and size of bounding rectangles [S1].
*   **Steps:**
    1.  Display only nodes in the current LOD [S1].
    2.  Deduce spatial arrangement from tree level and ordinal among siblings [S1].
    3.  Color-code the error and size-code the level in the corresponding rectangular region [S1].
    4.  If colors are indistinguishable due to small error tolerance, use an alternate error metric: the difference between parent and child error values, excluding the maximum error value of the child nodes [S1].
*   **Pitfall:** Specifying a small error tolerance results in nodes with similar error values, leading to indistinguishable colors [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Provides an instant overview of the entire error distribution; independent of run-time volume orientation; guides user navigation and LOD selection [S1].
*   **Limitations:** Can suffer from "holes" if not filled; small error ranges may lead to indistinguishable colors; the Overview Map shows all nodes, which can be cluttered, whereas the Treemap variant is limited to active nodes [S1].
*   **When to use:** When a user needs a global view of the wavelet tree's error distribution to make initial LOD decisions [S1].
*   **When not to use:** When focusing on specific active regions for detailed adjustment, where the Treemap variant is preferred to avoid clutter [S1].

## Background
The Wavelet Tree Overview Map was introduced as part of a Hierarchical Navigation Interface for volume rendering [S1]. It leverages the structure of wavelet trees to visualize error distributions, serving as a starting point for local LOD adjustments [S1]. The method builds on the principles of wavelet-based multiresolution analysis [S2, unofficial].
