# Wavelet Tree Overview Map

Also called: Overview Map Visualization

## Overview
The Wavelet Tree Overview Map is a visualization technique designed to provide an instant, global overview of the error distribution within a wavelet-based multiresolution volume hierarchy [S1]. It solves the problem of navigating complex LOD (Level of Detail) structures by mapping the entire wavelet tree into a 2D equilateral triangle frame, allowing users to identify regions requiring refinement or coarsening [S1]. It sets itself apart from sibling methods like [Projecting Detail Coefficients](1802-projecting-detail-coefficients.md) by visualizing the full tree structure and error landscape simultaneously, rather than projecting specific frequency bands, and from [Wavelet Tree](5390-wavelet-tree.md) by providing a continuous color-filled error map rather than a discrete structural diagram [G].

## How it works
**Inputs and Outputs:**
*   **Input:** The complete wavelet tree hierarchy (nodes, levels, parent-child relationships) and the associated error metric for each node [S1].
*   **Output:** A 2D image where the wavelet tree is mapped to an equilateral triangle, with colors representing error magnitudes and a highlighted cut representing the current LOD [S1].

**Data Structures:**
The method operates on the existing wavelet tree data structure [S1]. Each node $N$ is defined by:
*   `level`: The depth in the tree (root is level 0).
*   `index`: The ordinal position of the node among its siblings at the same level.
*   `error`: The scalar error value associated with the node [S1].

**Steps:**

1.  **Frame Construction:** Draw an equilateral triangle frame where the apex represents the root of the wavelet tree and the base represents all leaf nodes [S1].
2.  **Level Segmentation:** Draw equal-distance horizontal line segments within the triangle frame to depict different intermediate tree levels [S1].
3.  **Node Mapping:** Map each wavelet tree node to a point on the horizontal line segment corresponding to its tree level [S1]. Nodes at the same level are arranged equidistantly from left to right based on their ordinal index [S1]. This mapping is performed in data space, independent of the run-time volume orientation [S1].
4.  **Error Color Mapping:** Transform the error values to colors [S1]. For hierarchies with large error ranges, transform errors $E$ into square root or logarithmic values before linearly mapping to colors to better utilize the color spectrum [S1]. Typical mapping assigns violet to low errors and red to high errors [S1].
5.  **Triangle Fan Filling:** Fill the triangle frame by drawing triangle fans for all parent-child branches [S1]. Each fan consists of a parent node and its children [S1]. Vertices of the fan are colored according to the mapped error values [S1].
6.  **Hole Filling:** Address the "holes" (quads) left between neighboring triangle fans [S1]. A hole is formed by two neighboring parent nodes ($V_1, V_4$) and their adjacent children ($V_2, V_3$) [S1]. Fill these quads with colors linearly interpolated from the four vertices to provide a continuous error distribution view and avoid a fractal appearance that hinders observation [S1].
7.  **LOD Highlighting:** Highlight the current Level of Detail (LOD) [S1]. Draw a "cut" through the triangle frame corresponding to the active LOD [S1]. Draw each node along the cut as a small square at its mapped point location [S1]. Connect these squares following the Depth-First Search (DFS) order of the nodes [S1].

**Pitfalls:**
*   **Holes:** Filling only triangle fans leaves quads between neighboring parents empty, creating a fractal appearance that obscures error distribution [S1]. These must be filled via interpolation [S1].
*   **Color Indistinguishability:** If error values are very similar, colors may be indistinguishable [S1]. Using non-linear transformations (sqrt/log) helps mitigate this [S1].

        nodes_by_level.setdefault(n['level'], []).append(n)

            points[node['id']] = (x, y)

            p2 = level_nodes[i+1]
            c1_last = p1.get('children', [])[-1] if p1.get('children') else None
            c2_first = p2.get('children', [])[0] if p2.get('children') else None
            if c1_last and c2_first:
                v1, v2, v3, v4 = points[p1['id']], points[c1_last['id']], points[c2_first['id']], points[p2['id']]

                fill_quad(v1, v2, v3, v4, c1, c2, c3, c4)

## Subtopics

### Treemap Visualization for Active Nodes
A space-filling alternative to the Overview Map that displays only the active nodes (those in the current LOD) to avoid clutter and sub-pixel resolution issues [S1].
*   **Definition:** Uses recursively subdivided display areas (alternating vertical/horizontal subdivisions) to present hierarchical information via visual attributes like color and size of bounding rectangles [S1].
*   **Steps:**
    1.  Display only nodes in the current LOD [S1].
    2.  Deduce spatial arrangement from tree level and ordinal among siblings [S1].
    3.  Color-code the error and size-code the level in the corresponding rectangular region [S1].
    4.  If colors are indistinguishable due to small error tolerance, use an alternate error metric: the difference between parent and child error values, excluding the maximum error value of the child nodes [S1].
*   **Pitfall:** Specifying a small error tolerance results in nodes with similar error values, leading to indistinguishable colors [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Provides an instant overview of the entire error distribution; independent of run-time volume orientation; guides user navigation and LOD selection [S1].
*   **Limitations:** Can suffer from "holes" if not filled; small error ranges may lead to indistinguishable colors; the Overview Map shows all nodes, which can be cluttered, whereas the Treemap variant is limited to active nodes [S1].
*   **When to use:** When a user needs a global view of the wavelet tree's error distribution to make initial LOD decisions [S1].
*   **When not to use:** When focusing on specific active regions for detailed adjustment, where the Treemap variant is preferred to avoid clutter [S1].

## Background
The Wavelet Tree Overview Map was introduced as part of a Hierarchical Navigation Interface for volume rendering [S1]. It leverages the structure of wavelet trees to visualize error distributions, serving as a starting point for local LOD adjustments [S1]. The method builds on the principles of wavelet-based multiresolution analysis [S2, unofficial].
