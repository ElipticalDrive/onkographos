# LOD Level Tree Traversal

Also called: LOD Raycasting with Stack Size Tracking, LODColor, LODColorTree4DRenderer, LODLevel, LODLevelTree4DRenderer, Optimized 4D Tree Rendering, Stack Depth LOD

## Overview
LOD Level Tree Traversal is a rendering technique that traverses a 4D sparse voxel octree (SVO) to locate leaf nodes containing data, then visualizes the traversal depth (Level of Detail) as a color map in a texture array [S1, unofficial]. It solves the problem of visualizing the hierarchical structure and data density of sparse volumetric data without performing full volume integration [S1, unofficial]. Unlike [Level of Detail Calculation](7836-level-of-detail-calculation.md), which computes the optimal LOD for each pixel, this method explicitly traverses the tree to a specific depth or until a leaf is found, using the stack depth as the primary visual attribute [S1, unofficial]. It differs from [Multiresolution Terrain Quantization and Prediction](9998-multiresolution-terrain-quantization-and-prediction.md) by operating on 4D sparse voxel structures rather than 2D/3D terrain grids [S1, unofficial].

## How it works
**Inputs:**
- A 4D sparse voxel octree (`tree`), containing nodes with `isLeaf()`, `hasData()`, and child pointers.
- A 3D ray for each pixel, defined by origin and direction.
- A time point (`time_point`) for 4D ray conversion.
- Render context (`rc`) providing image dimensions (`n_x`, `n_y`), frustum width, and pixel radius.
- Parameters: `max_level` (maximum tree depth to traverse), `pixel_size` (threshold for node projected size).

**Outputs:**
- A texture array (`texture_array`) of size `rc.n_y * rc.n_x * 4`, storing RGBA values per pixel.

**Data Structures:**
- `Tree4DTraverserDifferentSides`: Manages the traversal state, including a stack of `Node4D` information (`stack_TraversalInfo_about_Node4Ds`).
- `Ray4D`: 4D ray representation, derived from 3D ray and time.
- `MAP_COLOUR`: Structure with `r`, `g`, `b` double components.

**Steps:**

1.  **Initialization:**
    -   Initialize OpenMP parallelism by setting thread count to the number of processors: `omp_set_num_threads(omp_get_num_procs())` [S1, unofficial].
    -   Calculate `max_stack_size` based on tree grid dimensions:
        $$ size = \max(tree->gridsize_T, tree->gridsize_S) $$
        $$ max\_stack\_size = \lfloor \log_2(size) \rfloor + 1 $$
        [S1, unofficial].
    -   Calculate `pixel_size` threshold:
        $$ pixel\_radius = 0.5 \times \frac{frustum\_width}{rc.n\_x} $$
        $$ pixel\_size = pixel\_radius \times pixel\_radius $$
        [S1, unofficial].

2.  **Per-Pixel Loop:**
    For each pixel $(x, y)$:
    -   Compute linear index in texture array:
        $$ partial\_index = y \times (rc.n\_y \times 4) $$
        $$ index = partial\_index + x \times 4 $$
        [S1, unofficial].
    -   Generate 3D ray: `ray3D = rc.getRayForPixel_rayparam(x, y, t_pixel)` [S1, unofficial].
    -   Convert to 4D ray: `ray4D = Ray4D::convertRayTo4D(ray3D, time_point, 0.0)` [S1, unofficial].
    -   Initialize traverser: `treeTraverser = Tree4DTraverserDifferentSides(tree, ray4D)` [S1, unofficial].
    -   Initialize flags: `dataLeafNodeHasBeenFound = false`, `nodeIsToSmall = false`, `reachedMaxLevelToRender = false` [S1, unofficial].

3.  **Traversal Loop:**
    While `!treeTraverser.isTerminated()` AND `!dataLeafNodeHasBeenFound` AND `!nodeIsToSmall` AND `!reachedMaxLevelToRender`:
    -   Check for data leaf: If `treeTraverser.getCurrentNode()->isLeaf()` AND `treeTraverser.getCurrentNode()->hasData()`, set `dataLeafNodeHasBeenFound = true` [S1, unofficial].
    -   Check max level: If `treeTraverser.stack_TraversalInfo_about_Node4Ds.size() >= max_level`, set `reachedMaxLevelToRender = true` [S1, unofficial].
    -   Check node size: Calculate `projectedSizeOfCurrentNode = treeTraverser.getProjectedSizeOfCurrentNode(t_pixel)` [S1, unofficial]. If `projectedSizeOfCurrentNode <= pixel_size`, set `nodeIsToSmall = true` [S1, unofficial].
    -   Advance: If no termination condition is met, call `treeTraverser.step()` [S1, unofficial].

4.  **Color Calculation and Storage:**
    If any termination condition is met:
    -   Get current stack size: `current_stack_size = treeTraverser.stack_TraversalInfo_about_Node4Ds.size()` [S1, unofficial].
    -   Map stack depth to color:
        $$ stack\_colour = GetColour\left(\frac{current\_stack\_size}{max\_stack\_size}\right) $$
        [S1, unofficial].
    -   Extract RGB components: `R = stack_colour.r`, `G = stack_colour.g`, `B = stack_colour.b` [S1, unofficial].
    -   Store in texture array (scaled to [0, 255], alpha=1):
        $$ texture\_array[index] = \lfloor R \times 255.0 \rfloor $$
        $$ texture\_array[index+1] = \lfloor G \times 255.0 \rfloor $$
        $$ texture\_array[index+2] = \lfloor B \times 255.0 \rfloor $$
        $$ texture\_array[index+3] = 255 $$
        [S1, unofficial].

**Pseudocode:**

```python
def render_lod_level_tree(tree, rc, time_point, max_level):
    # Initialize OpenMP
    num_threads = omp_get_num_procs()
    omp_set_num_threads(num_threads)

    # Calculate max stack size
    size = max(tree.gridsize_T, tree.gridsize_S)
    max_stack_size = floor(log2(size)) + 1

    # Calculate pixel size threshold
    pixel_radius = 0.5 * (rc.frustum_width / rc.n_x)
    pixel_size = pixel_radius * pixel_radius

    # Initialize texture array
    texture_array = array of unsigned char of size rc.n_y * rc.n_x * 4

    for y in range(rc.n_y):
        for x in range(rc.n_x):
            # Calculate index
            partial_index = y * (rc.n_y * 4)
            index = partial_index + x * 4

            # Generate rays
            ray3D = rc.getRayForPixel_rayparam(x, y, time_point)
            ray4D = Ray4D.convertRayTo4D(ray3D, time_point, 0.0)

            # Initialize traverser
            treeTraverser = Tree4DTraverserDifferentSides(tree, ray4D)

            # Flags
            dataLeafNodeHasBeenFound = False
            nodeIsToSmall = False
            reachedMaxLevelToRender = False

            # Traversal loop
            while (not treeTraverser.isTerminated() and
                   not dataLeafNodeHasBeenFound and
                   not nodeIsToSmall and
                   not reachedMaxLevelToRender):

                current_node = treeTraverser.getCurrentNode()

                # Check for data leaf
                if current_node.isLeaf() and current_node.hasData():
                    dataLeafNodeHasBeenFound = True

                # Check max level
                if treeTraverser.stack_TraversalInfo_about_Node4Ds.size() >= max_level:
                    reachedMaxLevelToRender = True

                # Check node size
                projected_size = treeTraverser.getProjectedSizeOfCurrentNode(time_point)
                if projected_size <= pixel_size:
                    nodeIsToSmall = True

                # Advance if not terminated
                if not (dataLeafNodeHasBeenFound or reachedMaxLevelToRender or nodeIsToSmall):
                    treeTraverser.step()

            # Calculate and store color
            current_stack_size = treeTraverser.stack_TraversalInfo_about_Node4Ds.size()
            normalized_depth = current_stack_size / max_stack_size
            stack_colour = GetColour(normalized_depth)

            R = stack_colour.r
            G = stack_colour.g
            B = stack_colour.b

            texture_array[index] = int(R * 255.0)
            texture_array[index + 1] = int(G * 255.0)
            texture_array[index + 2] = int(B * 255.0)
            texture_array[index + 3] = 255

    return texture_array
```

## Subtopics

### LODNormalTree4DRenderer
A variant that traverses the 4D sparse voxel octree to find leaf nodes with data, then stores the normal vector of that leaf node as RGB color values in a texture array [S1, unofficial]. It differs from the base LOD Level Tree Traversal by visualizing surface orientation rather than traversal depth [S1, unofficial]. To choose it when normal visualization is required [S1, unofficial]. The normal vector is retrieved from the leaf node data, normalized, and mapped from $[-1, 1]$ to $[0, 255]$ for RGB storage:
$$ R = 255 \times \frac{normal[0] + 1.0}{2.0} $$
$$ G = 255 \times \frac{normal[1] + 1.0}{2.0} $$
$$ B = 255 \times \frac{normal[2] + 1.0}{2.0} $$
[S1, unofficial]. The parameters `pixel_size` and `max_stack_size` are calculated identically to the base method [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** Proportional to the number of pixels times the average traversal depth to the first data leaf or termination condition [S1, unofficial].
-   **Memory Complexity:** Dominated by the texture array output ($4 \times N_x \times N_y$ bytes) and the traversal stack, which is bounded by the tree depth [S1, unofficial].
-   **Performance:** Parallelized using OpenMP across pixels [S1, unofficial].
-   **Strengths:** Simple visualization of data density and hierarchical structure; efficient culling of empty space [S1, unofficial].
-   **Limitations:** Does not provide photorealistic rendering; dependent on tree structure and traversal efficiency [S1, unofficial].
-   **When to use:** For debugging sparse voxel structures, visualizing data distribution, or as a pre-pass for more complex rendering [S1, unofficial].
-   **When not to use:** When photorealistic volume rendering or normal-based shading is required [S1, unofficial].

## Background
The method originates from the 4D Sparse Voxel Octree Renderer project by joschout [S1, unofficial]. It is part of a suite of renderers for 4D SVOs, including LODNormal and LODLevel, designed to visualize different aspects of the sparse voxel data [S1, unofficial]. The implementation uses a custom `Tree4DTraverserDifferentSides` class to handle the 4D traversal logic [S1, unofficial].
