# Level of Detail Calculation

Also called: ComputeVoxelSize, LoD Level Calculation, Voxel Pre-integration, Cone Stepping and Mip Level Selection, Brick LOD Selection

## Overview
Level of Detail Calculation determines the specific resolution level within a multiresolution hierarchy required to render a voxel or brick at a given screen position, ensuring visual fidelity while minimizing computational cost. It sets itself apart from sibling methods by explicitly mapping the projected size of a volume element to a discrete hierarchy index using logarithmic scaling, rather than relying solely on distance thresholds or error metrics. This method serves as the foundational step for [LOD Selection and Culling](5338-lod-selection-and-culling.md), providing the target resolution before traversal or culling decisions are made.

## How it works
The method calculates a continuous LOD level based on the projected width of the voxel in screen space, then interpolates between the two nearest integer levels to determine the final sampling rate.

**Inputs:**
*   $M$: The maximum number of levels in the hierarchy (integer).
*   $w$: The projected width of the voxel/brick in screen space (pixels).

**Outputs:**
*   $level$: The continuous target LOD level (float).
*   $level0$: The ceiling integer level.
*   $plevel0$: The fractional weight for $level0$.
*   $level1$: The floor integer level.
*   $plevel1$: The fractional weight for $level1$.

**Data Structures:**
No complex data structures are required for the calculation itself. The hierarchy is assumed to be pre-computed with uniform scaling factors (typically powers of 2).

**Steps:**
1.  Calculate the continuous level using the logarithmic relationship between the maximum levels and the projected width.
2.  Determine the integer ceiling and floor levels.
3.  Compute the fractional weights for interpolation between the two levels.

**Formulas:**
The continuous level is calculated as [S1]:
$$ level = M - 1 + \log_2(w) $$

The ceiling level and its weight are [S1]:
$$ level0 = \lceil level \rceil $$
$$ plevel0 = level - level0 $$

The floor level and its weight are [S1]:
$$ level1 = \lfloor level \rfloor $$
$$ plevel1 = level1 - level $$

Note: $plevel0$ and $plevel1$ represent the interpolation factors. Typically, the rendering sample is taken from $level0$ with probability $plevel0$ and $level1$ with probability $plevel1$, or values are interpolated linearly if the data supports it.

**Parameters:**
*   $M$: Defined by the pre-computed hierarchy depth. Typical values depend on the volume resolution (e.g., 8–16 for large-scale scenes).

**Edge Cases and Pitfalls:**
*   **Width < 1:** If $w < 1$, $\log_2(w)$ is negative. The level may drop below 0. The implementation must clamp $level$ to the range $[0, M-1]$.
*   **Width > 2^{M-1}:** If the voxel projects to a size larger than the finest resolution allows, the level may exceed $M-1$. Clamp to $M-1$.
*   **Precision:** Floating-point precision in $\log_2$ can cause jitter at boundaries where $w$ is a power of 2. [G] Use epsilon comparisons or integer arithmetic for power-of-two widths if stability is critical.

**Pseudocode:**
```python
import math

def calculate_lod(M: int, width: float) -> dict:
    """
    Calculate LOD level based on projected width.
    
    Args:
        M: Maximum number of levels in the hierarchy.
        width: Projected width of the voxel in screen space.
        
    Returns:
        Dictionary containing level, level0, plevel0, level1, plevel1.
    """
    # Clamp width to avoid log(0) or negative logs for very small projections
    # Assuming minimum meaningful width is 0.5 pixels to prevent extreme levels
    if width <= 0:
        width = 0.5
    
    # Step 1: Calculate continuous level
    # Formula: level = M - 1 + log2(width)
    level = (M - 1) + math.log2(width)
    
    # Clamp level to valid range [0, M-1]
    level = max(0.0, min(float(M - 1), level))
    
    # Step 2: Calculate ceiling level and weight
    level0 = math.ceil(level)
    plevel0 = level - level0
    
    # Step 3: Calculate floor level and weight
    level1 = math.floor(level)
    plevel1 = level1 - level
    
    return {
        "level": level,
        "level0": level0,
        "plevel0": plevel0,
        "level1": level1,
        "plevel1": plevel1
    }
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per voxel/brick, involving a logarithm and basic arithmetic operations.
*   **Memory Complexity:** $O(1)$ auxiliary memory.
*   **Strengths:** Fast, deterministic, and suitable for real-time applications [S1]. Provides smooth transitions between levels via fractional weights.
*   **Limitations:** Assumes uniform scaling in the hierarchy. Does not account for data variance or occlusion, only projected size.
*   **When to use:** When a uniform multiresolution hierarchy (e.g., mipmaps, bricks) is available and screen-space coverage is the primary driver for LOD.
*   **When not to use:** For non-uniform hierarchies or when data-dependent error metrics are required.

## Background
The method originates from microgeometry rendering techniques, specifically in the context of fast voxelization and level of detail for rendering detailed surfaces [S1]. It is part of a broader family of techniques that map screen-space metrics to data-space resolutions to balance quality and performance.
