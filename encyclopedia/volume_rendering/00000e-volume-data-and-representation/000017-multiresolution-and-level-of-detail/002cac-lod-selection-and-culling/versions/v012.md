# LOD Selection and Culling
## Overview
LOD Selection and Culling determines which resolution level of a multiresolution volume hierarchy to render for a given view or spatial region, balancing visual fidelity against memory and performance constraints [G]. It solves the problem of rendering large volumetric datasets that exceed hardware budgets by dynamically discarding invisible subregions (culling) and selecting coarse approximations for distant or less important areas (LOD selection) [G]. It differs from sibling methods like [Mesh Simplification](1032-mesh-simplification.md) by operating on volumetric data structures (bricks, octrees, splats) rather than polygonal meshes, and from [Wavelet-based Volume Rendering](1052-wavelet-based-volume-rendering.md) by focusing on the selection logic and data management rather than the specific transform decomposition itself [G].

## Shared principles
All methods in this family share the core principles of multiresolution hierarchy generation and selection, as detailed in [Multiresolution and level of detail](7-multiresolution-and-level-of-detail.md).

## Subtopics

### [Hierarchical Culling & Multi-resolution Approximation](2010-hierarchical-culling-multi-resolution-approximation.md)
This method accelerates volume rendering by combining spatial frustum culling with multi-resolution data approximation. It solves the performance bottleneck of rendering large volumetric datasets by discarding invisible subregions and rendering visible regions at resolutions proportional to their screen importance. It explicitly couples frustum culling with hardware-assisted cell projection for exploration.

### [Streaming and Level-of-Detail (LOD) selection](3087-streaming-and-level-of-detail-lod-selection.md)
Streaming and Level-of-Detail (LOD) selection is a method for visualizing massive scenes that exceed rendering or memory budgets by dynamically selecting data resolution based on viewpoint position and screen footprint. It solves the problem of navigating arbitrarily large datasets without stalling the frame rate or exceeding memory limits by combining additive ladders (progressive detail) with substitutive levels (coarse approximations) and spatial culling. It sets itself apart from its siblings by explicitly managing the temporal aspect of data arrival and resolution selection through a "level-of-detail grammar" that prioritizes visual coverage preservation during streaming.

### [Focus Point Based Brick LOD Selection](5282-focus-point-based-brick-lod-selection.md)
Focus Point Based Brick LOD Selection is a method to determine the appropriate level-of-detail (LOD) for each brick in a multiscale volume representation based on the distance of the brick's center to a user-defined focus point. It differs from error-driven siblings because it relies exclusively on geometric proximity to the focus point, ignoring approximation error. This allows for arbitrary texture resolutions per brick, unlike methods with strict texture-to-geometry correspondence.

### [Choosing Alternative Resolutions](5314-choosing-alternative-resolutions.md)
This method selects a cache-resident resolution level for a volume rendering brick when the desired resolution is not available in memory. It leverages a bitmap of partially mapped resolutions stored in each residency-octree node to efficiently identify candidate levels without random searching. The approach prioritizes lower resolutions before attempting higher ones, iterating through candidates until a mapped page is found or all options are exhausted.

### [Finding Higher Resolution Levels](5315-finding-higher-resolution-levels.md)
This method finds the next higher resolution level in a residency octree traversal where a node is partially mapped. It returns the index of the finest available resolution level strictly higher than a given resolution index, based on a node's occupancy bitmap. It differs from sibling methods that generate data or make final rendering decisions by performing a specific bitwise lookup during hierarchical traversal.

### [Multi-resolution LOD Volume Rendering with Temporal Coherence](5717-multi-resolution-lod-volume-rendering-with-temporal-coherenc.md)
Multi-resolution LOD Volume Rendering with Temporal Coherence assigns different resolution levels to subvolumes based on visual importance metrics (projection area, gaze distance, or viewer proximity) to optimize rendering performance while maintaining visual quality. It distinguishes itself from standard LOD methods by explicitly preventing flickering during view changes through a temporal coherence mechanism that stabilizes resolution assignments across consecutive frames. Unlike strict hierarchical traversal methods, this approach allows arbitrary texture resolutions for subvolumes provided level transitions are constrained to at most one step per frame.

### [Flat blocking multi-resolution volume rendering](6428-flat-blocking-multi-resolution-volume-rendering.md)
Flat blocking multi-resolution volume rendering is a strategy for loading and rendering large volume datasets by dividing the volume into sub-blocks of equal physical size but assigning each block a different resolution (Level of Detail, LOD) based on its internal data variation. Unlike hierarchical structures that change spatial extent, this method keeps block dimensions constant while varying the voxel count within them. It is distinguished from its siblings by its explicit use of a "flat" blocking structure where LOD is determined per block via a variation heuristic, often implemented using min/max octrees.

### [Level of Detail (LoD) for Large-Scale Scenes](7325-level-of-detail-lod-for-large-scale-scenes.md)
Level of Detail (LoD) for Large-Scale Scenes regulates the amount of detail needed to represent large-scale scenes by precomputing several simplified versions of the dataset. It solves the problem of rendering massive volumes efficiently by selecting the most appropriate resolution level at runtime based on criteria such as distance to the viewer. Unlike continuous LOD methods, this approach uses discrete, static representations, which are easier to precompute and impose very little overhead at runtime, making it highly suitable for graphics hardware that favors display lists or vertex arrays.

### [Level of Detail Calculation](7836-level-of-detail-calculation.md)
Level of Detail Calculation maps a continuous spatial or view-dependent metric to a discrete resolution level within a multiresolution hierarchy. It computes a fractional level index and its bounding integer levels with associated weights to enable interpolation or selection across the hierarchy.

### [LoD Selection via Projected Width](7837-lod-selection-via-projected-width.md)
This method selects the appropriate resolution level for volume rendering by estimating the projected width of the data on the camera plane, analogous to Mipmap selection in path tracing. It solves the problem of aliasing and performance inefficiency by ensuring that the sampling rate matches the visual importance of the geometry relative to the camera. Unlike distance-based selection, which assumes uniform scaling, this approach accounts for perspective distortion and viewing angle, making it particularly effective for complex microgeometry like vegetation and hair.

### [GPU-Based Dynamic LOD Calculation](10845-gpu-based-dynamic-lod-calculation.md)
This method calculates Level-of-Detail (LOD) levels for visible tiles entirely on the GPU using compute shaders, replacing traditional CPU-side computation based on viewpoint distance and screen-space error. It distinguishes itself by integrating terrain ruggedness into the LOD decision logic and performing the calculation in parallel for thousands of tiles, thereby reducing CPU overhead.

### [Histogram Spectra for LOD Selection](11687-histogram-spectra-for-lod-selection.md)
Histogram Spectra for LOD Selection (HSPE) is a metadata-driven technique for selecting Level of Detail (LOD) in multivariate, time-varying volume rendering. It solves the problem of interactive LOD selection for large, out-of-core volumes by precomputing statistical sensitivity metrics, allowing error estimation without accessing the raw volume data. Unlike direct RMS error computation which requires reading the entire dataset, HSPE uses compact histogram spectra to pose LOD selection as an integer programming problem, maximizing quality within a working set size constraint.

### [LOD Assignment Algorithm](11688-lod-assignment-algorithm.md)
The LOD Assignment Algorithm assigns levels of detail (LOD) to subvolumes to minimize visual error density subject to a maximum working set size constraint ($S_{max}$). It solves the problem of fitting high-resolution volume datasets into limited memory by selecting resolution levels for spatial blocks.

### Mesh Level of Detail
- **Definition**: A secondary LOD system applying to meshes themselves to reduce vertex count over distance. Only applies to `VoxelInstanceLibraryMultiMeshItem` [S2].
- **Step**: Hiding Distant Instances: Instances beyond the maximum distance of the last LOD can be hidden. They are still generated but not rendered [S2]. Useful if terrain has no LOD.
- **Parameter**: Mesh LOD Properties: Three mesh properties (LOD0, LOD1, LOD2, LOD3) on `VoxelInstanceLibraryMultiMeshItem`. If only mesh is set, no LOD is used. Fewer LODs can be simulated by assigning the same mesh twice [S2]. LOD Switch Distances: Defined as ratios (usually 0 to 1) relative to the view distance of the corresponding terrain LOD (defined by `lod_index`) [S2].
- **Usage**: Impostor Meshes: Simple quads used to fake model presence at far distances (e.g., forests), allowing detailed trees when close [S2].

### LOD Actor Rendering
- **Definition**: A VTK actor that supports Level of Detail (LOD) rendering by switching between different representations of the geometry based on camera distance, using cloud points for distant views [S3, unofficial].
- **Step**: Create a `vtkLODActor` instance. Set the number of cloud points used for the distant LOD representation using `SetNumberOfCloudPoints`. Assign the mapper to the actor using `SetMapper` [S3, unofficial].
- **Parameter**: `NumberOfCloudPoints`: Integer specifying the number of points to render when the actor is viewed from a distance. Set to 1,000,000 in the example [S3, unofficial].
- **Code**: Python code snippet for configuring the LOD actor [S3, unofficial].

### Hybrid LOD (Surface-Volume Switching)
- **Definition**: A switching mechanism that provides object-level optimization by switching between surface models and their corresponding volume models to control visualization workload [S4, unofficial].
- **Step**: Threshold special indicators, specifically the distance between the viewpoint and the object, or the interaction type deployed in the simulation, to decide whether to use the volume or surface model [S4, unofficial].
- **Comparison**: Using surface models to replace volume ones at a carefully chosen threshold effectively improves the interactive rate without losing too much visual quality [S4, unofficial].

## Background
The concept of Level of Detail (LOD) in volume rendering originated from the need to handle the computational complexity of raycasting large datasets interactively [G]. Early work focused on hierarchical data structures like octrees and bricks to enable efficient traversal and culling [G]. The integration of LOD with streaming architectures allowed for the visualization of terabyte-scale datasets by dynamically loading only the necessary resolution levels [G]. Recent developments have extended LOD selection to GPU-based dynamic calculation for terrain and large-scale scenes, incorporating factors like terrain ruggedness to maintain visual quality [S1, unofficial]. Additionally, error-driven LOD assignment algorithms have been developed to optimize memory usage by minimizing visual error density per byte [S1, unofficial].
