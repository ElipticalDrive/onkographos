# Histogram Spectra for LOD Selection

Also called: Histogram Spectra Computation, Histogram Spectra Predicted Error

## Overview
Histogram Spectra for LOD Selection (HSPE) is a metadata-driven technique for selecting Level of Detail (LOD) in multivariate, time-varying volume rendering [S1]. It solves the problem of interactive LOD selection for large, out-of-core volumes by precomputing statistical sensitivity metrics, allowing error estimation without accessing the raw volume data [S1]. Unlike direct RMS error computation which requires reading the entire dataset, HSPE uses compact histogram spectra to pose LOD selection as an integer programming problem, maximizing quality within a working set size constraint [S1].

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   A multiresolution bricked volume (4D subvolumes/bricks) with $M$ levels of detail [S1].
    *   User-defined parameters:
        *   $S_{max}$: Maximum working set size constraint (bytes) [S1].
        *   Intervals of interest: User-specified bounds for variables defining the salient volume subset [S1].
*   **Outputs:**
    *   A set of LOD assignments $B$, where $B_i$ is the selected LOD index for subvolume $i$ [S1].

### Data Structures

#### Histogram Spectrum
The histogram spectrum is stored as metadata for each subvolume [S1].
*   **Layout:** Uniformly sampled 2D array of floats [S1].
*   **Dimensions:**
    *   **Columns:** Value intervals (bins). The number of columns determines the narrowest interval of interest that can be resolved [S1].
    *   **Rows:** Sampling frequencies. There are $M$ rows for $M$ LODs, excluding the ground truth row if the highest LOD matches the ground truth frequency (as its spectrum is zero) [S1].
*   **Size:** In test cases, 128 bins and 7 frequencies per subvolume were used [S1].

#### Greedy Algorithm List
A list of entries for potential LOD assignments, sorted by heuristic value [S1].
*   **Entry Structure:**
    *   `heuristic`: Error density value $A_{i,j}$ [S1].
    *   `lod_index`: The LOD index $j$ [S1].
    *   `subvolume_index`: The subvolume index $i$ [S1].

### Precomputation: Histogram Spectrum Generation
For each subvolume, a histogram spectrum is generated by sampling the subvolume at multiple levels of detail (different sampling frequencies) [S1].

1.  **Sampling:** Sample the subvolume at frequency $b$ (high resolution/ground truth) and frequency $a$ (lower resolution) [S1].
2.  **PDF Computation:** Compute the Probability Density Function (PDF) for each sampling frequency, denoted $f_b(x)$ and $f_a(x)$, where $x$ is the value parameter [S1].
3.  **Spectrum Calculation:** Compute the absolute difference between the PDFs for each bin $x$ [S1]:
    $$ h(x, a) = | f_b(x) - f_a(x) | $$
    where $a$ and $b$ are sampling frequencies [S1].
4.  **Weighting (Optional):** Apply a user-defined weighting function $w(x)$ to focus on intervals of interest [S1]:
    $$ h_w(x, a) = w(x)h(x, a) $$
    Typically, $w(x) = 1$ if $x \in Y$ (interval of interest) and $0$ otherwise [S1].

### Interactive Selection: Greedy Algorithm
The LOD selection problem is posed as an integer programming problem, solved efficiently using a greedy algorithm [S1].

**Step 1: Estimate Result Error**
Estimate the predicted error $E(a_j)$ for every LOD $j$ for every subvolume $i$ using the histogram spectra [S1]. This step has complexity $O(N)$, where $N$ is the number of subvolumes [S1].

**Step 2: Compute Heuristics and Sort**
Compute the error density (heuristic value) $A_{i,j}$ for all potential LOD assignments [S1]:
$$ A_{i,j} = \frac{E(a_j)}{S_{i,j}} $$
where $a_j$ is the sampling frequency of LOD $j$, and $S_{i,j}$ is the size in bytes loaded for LOD $j$ of subvolume $i$ [S1].
Construct a list of entries $(A_{i,j}, j, i)$ and sort in ascending order of $A_{i,j}$ [S1]. Complexity: $O(N \log N)$ [S1].

**Step 3: Assign LODs**
Iterate through the sorted list to assign LODs until the size constraint $S_{max}$ is satisfied [S1].

```python
# Pseudocode for LOD Assignment
# L: Sorted list of (heuristic, lod_index, subvolume_index)
# B: Array of LOD assignments for each subvolume, initialized to default LOD (e.g., lowest detail)
# S_max: Maximum working set size
# get_subvol_size(lod_index, subvolume_index): Returns size in bytes for specific LOD of specific subvolume

def assign_lod(L, B, S_max, get_subvol_size):
    N_subvols = len(B)
    # Initialize total size with the default LOD (assumed to be the lowest detail, index 1 or similar)
    # Note: The source assumes an initial assignment. We assume B is initialized to the coarsest LOD.
    S_total = sum(get_subvol_size(1, i) for i in range(N_subvols))
    
    # Iterate through sorted list
    for entry in L:
        if S_total > S_max:
            break
            
        heuristic, lod_idx, subvol_idx = entry
        
        # If the current LOD in the list is "better" (higher resolution) than the assigned LOD
        # The source implies checking if B[subvol] < lod_idx. 
        # Assuming lower index = coarser, higher index = finer.
        # We refine if the new LOD is finer than current.
        if B[subvol_idx] < lod_idx:
            # Remove old size
            old_size = get_subvol_size(B[subvol_idx], subvol_idx)
            S_total -= old_size
            
            # Assign new LOD
            B[subvol_idx] = lod_idx
            
            # Add new size
            new_size = get_subvol_size(lod_idx, subvol_idx)
            S_total += new_size
            
    return B
```

### Parameters
*   **Intervals of Interest:** User-specified bounds for variables [S1].
*   **$S_{max}$:** Maximum working set size [S1].
*   **Histogram Resolution:** Number of columns in the spectrum array. Should reflect the minimum width of intervals the user is likely to be interested in [S1].

### Edge Cases and Pitfalls
*   **Undersampling:** Bottom-up cut construction from the lowest level of detail may miss features at higher levels of detail if the lowest level is sufficiently undersampled [S1].
*   **Zero Rows:** If the highest sampling frequency of an LOD matches the ground truth frequency, its histogram spectrum row is zero and does not need to be stored [S1].
*   **Prediction Accuracy:** The linear relationship between histogram spectrum predicted error (HSPE) and RMS error holds for sampling frequencies $a > 0.1b$. Below this threshold, the prediction may be inaccurate [S1].
*   **Performance Bottleneck:** The computation is likely read-bound rather than compute-bound [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Precomputation:** Scales linearly with the number of data samples. Each subvolume is processed independently, making it embarrassingly parallel [S1].
*   **LOD Selection:** Total complexity is dominated by sorting: $O(N \log N)$ [S1].
    *   Error estimation: $O(N)$ [S1].
    *   Sorting: $O(N \log N)$ [S1].
    *   Assignment: $O(N)$ [S1].

### Measured Performance
*   **Platform:** Linux PC, Intel Core 2 6600, 4GiB RAM, HDD (30MiB/s) [S1].
*   **Climate QVAPOR:** HSPE selection took 0.1s vs 1782.0s for direct RMSE [S1].
*   **Combustion MIXFRAC:** HSPE selection took 0.2s vs 3900.3s for direct RMSE [S1].
*   **Metadata Size:**
    *   Climate (117GiB volume): 67MiB spectra (0.056% of volume) [S1].
    *   Combustion (69GiB volume): 60MiB spectra (0.085% of volume) [S1].

### Strengths and Limitations
*   **Strengths:** Enables interactive LOD selection for large, out-of-core volumes. Significantly faster than direct RMS error computation because it avoids reading the entire volume [S1].
*   **Limitations:** Requires precomputation of histogram spectra. The linear error prediction is only valid for $a > 0.1b$ [S1].

### When to Use
*   Use when interactive LOD selection is required for large, multivariate, time-varying volumes.
*   Use when the working set size is constrained, and maximizing quality within that constraint is the goal [S1].

### When Not to Use
*   Use direct RMSE if the volume is small enough to fit in memory and interactive speed is not critical, or if the required LODs involve extreme downsampling ($a \le 0.1b$) where HSPE accuracy degrades [S1].

## Background

### Origin
The technique was introduced in the paper "Histogram spectra for multivariate time-varying volume LOD selection" [S1].

### History and Development
The method addresses challenges in visualizing time-varying, multivariate volumes where error estimation is computationally expensive. It contrasts with error-constrained approaches by being size-constrained, maximizing importance subject to a working set size limit [S1]. It builds on previous work in multiresolution volume rendering and hierarchical culling [S1].

### Usage
Histogram spectra can be computed:
1.  **In-situ:** During data generation, requiring no additional reads [S1].
2.  **As a separate pass:** During data preparation, requiring streaming the volume once from disk [S1].
