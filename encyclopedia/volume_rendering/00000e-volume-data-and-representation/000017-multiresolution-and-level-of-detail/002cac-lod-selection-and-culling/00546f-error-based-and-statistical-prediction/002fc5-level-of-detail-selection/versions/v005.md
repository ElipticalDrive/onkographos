# Level-of-Detail Selection
Also called: Image-based LOD selection, Quality-driven LOD selection
## Overview
An algorithm using an image-based quality metric to select levels of detail for rendering large volumetric data and improving image quality [S1]. It differs from sibling methods by directly optimizing the final rendered pixel fidelity rather than relying solely on spectral histograms or static assignment rules.
## How it works
Inputs: Large volumetric dataset, camera parameters, target quality threshold or primitive budget.
Outputs: Selected LOD hierarchy for each view-dependent tile or ray.

The method operates by evaluating the error introduced by coarser LODs against the original high-resolution data using an image-based metric (e.g., PSNR, SSIM).

1.  **Preprocessing**: Compute error metrics for available LOD tiers offline or on-the-fly.
2.  **Selection**: For each view, select the coarsest LOD that satisfies the quality constraint.
3.  **Rendering**: Render using the selected LODs.

Parameters:
- Quality threshold: Not given in the sources.
- Metric: Image-based quality metric [S1].

Edge cases:
- Degenerate input: If no LOD meets the quality threshold, fall back to the highest resolution.
- Precision: Image-based metrics can be sensitive to lighting and transfer function changes.

Pseudocode:
```python
def select_lod(data, camera, quality_threshold):
    """
    Select the best LOD for a given camera view based on image quality.
    """
    best_lod = None
    min_error = infinity
    
    # Iterate through available LODs from coarsest to finest
    for lod in data.lods:
        # Render a preview or estimate error
        # Note: Full rendering is expensive; often a proxy or lower-res render is used
        rendered_image = render(lod, camera)
        reference_image = render(data.highest_lod, camera)
        
        # Calculate image-based quality metric
        error = calculate_quality_metric(rendered_image, reference_image)
        
        # Select the coarsest LOD that meets the threshold
        if error <= quality_threshold:
            best_lod = lod
            break
            
    if best_lod is None:
        best_lod = data.highest_lod
        
    return best_lod
```
## Subtopics

### Residual-Proxy Adaptive Selector
An adaptive LOD selection method using residual proxies to recover quality over fixed threshold methods at comparable primitive counts [S2, unofficial]. On the 'garden' scene, it recovers 0.49 dB over the fixed threshold at a comparable primitive count (1.05x) [S2, unofficial]. On the city-scale model, c=4 renders 68% of the primitives at -0.05 dB loss [S2, unofficial]. The aerial model (city) has a wider near-lossless window than the garden model because it is already tessellated at its training viewing distance, exhausting sub-pixel redundancy at small c, leaving surplus in super-pixel collapse [S2, unofficial].

## Operating characteristics
Time complexity: Depends on the cost of the image-based quality metric evaluation. If full rendering is used for selection, it is high. If proxies are used, it is lower.
Memory complexity: Requires storage for multiple LODs and potentially residual proxies.
Measured performance: On the city-scale model, the method achieves a 17x memory reduction (110.6 MB vs 1926 MB) at an operating point of ~20.8 dB [S2, unofficial].
Strengths: Improves image quality compared to fixed threshold methods [S2, unofficial].
Limitations: Image-based metrics can be computationally expensive to evaluate.
## Background
Origin: Proposed by Wang et al. in the context of GPU-based raycasting pipelines to render large volumetric data and improve image quality [S1].
History: Developed as part of real-time volume compression and decompression techniques based on block transformation coding [S1].
