# LOD Assignment Algorithm


## Overview
The LOD Assignment Algorithm assigns levels of detail (LOD) to subvolumes to minimize visual error density subject to a maximum working set size constraint ($S_{max}$) [S1]. It solves the problem of fitting high-resolution volume datasets into limited memory by selecting resolution levels for spatial blocks [S1].

## How it works
The algorithm operates as a greedy heuristic to solve a binary linear integer programming problem [S1]. It assumes a pre-computed list of potential LOD assignments sorted by their error density heuristic ($A_{i,j}$), which represents the error introduced per unit of memory cost [S1].

**Inputs and Outputs:**
*   **Input:**
    *   $L$: A list of potential LOD assignments sorted in ascending order of the heuristic $A_{i,j}$ [S1].
    *   $B$: An array mapping each subvolume block index to its current assigned LOD level [S1].
    *   $N_{subvols}$: The total number of subvolumes [S1].
    *   $S_{max}$: The maximum allowed working set size in bytes [S1].
*   **Output:**
    *   $B$: The updated array containing the final LOD assignment for each subvolume [S1].

**Data Structures:**
*   **List $L$**: Contains entries for potential LOD upgrades [S1]. Each entry has a `block` identifier (integer index) and a `lod` identifier (integer level index) [S1]. The list is sorted such that entries with the lowest error density appear first [S1].
*   **Array $B$**: Indexed by subvolume block ID [S1]. Stores the current LOD level for that block [S1].

**Steps:**
1.  **Initialization**: Calculate the initial total size $S_{total}$ by assuming every subvolume is at LOD 1 [S1].
    $$ S_{total} := N_{subvols} \times \text{getSubVolSizeForLOD}(1) $$
    [S1]
2.  **Iteration**: Iterate through the sorted list $L$ with index $i$ from $1$ to $L.length$ [S1]. The loop continues only if $S_{total} > S_{max}$ [S1].
3.  **Check Feasibility**: For each entry $L[i]$, check if the current LOD assigned to block $L[i].block$ (stored in $B[L[i].block]$) is strictly lower than the proposed LOD $L[i].lod$ [S1].
    *   Condition: $B[L[i].block] < L[i].lod$ [S1].
    *   If true, proceed to update [S1]. If false, skip to the next entry [S1].
4.  **Update Size**: Subtract the size of the current LOD for the block from the total size [S1].
    $$ S_{total} -= \text{getSubVolSizeForLOD}(B[L[i].block]) $$
    [S1]
5.  **Update Assignment**: Assign the new LOD to the block [S1].
    $$ B[L[i].block] := L[i].lod $$
    [S1]
6.  **Add New Size**: Add the size of the new LOD for the block to the total size [S1].
    $$ S_{total} += \text{getSubVolSizeForLOD}(B[L[i].block]) $$
    [S1]
7.  **Termination**: The algorithm terminates when $S_{total} \le S_{max}$ or the list $L$ is exhausted [S1].

**Pseudocode:**
```python
def lod_assignment_algorithm(L, B, N_subvols, S_max, getSubVolSizeForLOD):
    """
    Assign LODs to subvolumes to minimize error density subject to S_max.
    
    Args:
        L: List of entries with attributes .block and .lod, sorted by ascending error density heuristic.
        B: Array of current LOD assignments for each subvolume block.
        N_subvols: Total number of subvolumes.
        S_max: Maximum allowed working set size in bytes.
        getSubVolSizeForLOD: Function returning the byte size of a subvolume at a given LOD level.
        
    Returns:
        B: Updated array of LOD assignments.
    """
    # Initialize total size assuming all blocks are at LOD 1
    S_total = N_subvols * getSubVolSizeForLOD(1)
    
    # Iterate through sorted potential assignments
    for i in range(len(L)):
        # Stop if we are within the size constraint
        if S_total <= S_max:
            break
            
        block_idx = L[i].block
        proposed_lod = L[i].lod
        current_lod = B[block_idx]
        
        # Only upgrade if the proposed LOD is higher (coarser) than current
        if current_lod < proposed_lod:
            # Remove old size
            old_size = getSubVolSizeForLOD(current_lod)
            S_total -= old_size
            
            # Assign new LOD
            B[block_idx] = proposed_lod
            
            # Add new size
            new_size = getSubVolSizeForLOD(proposed_lod)
            S_total += new_size
            
    return B
```

**Parameters:**
*   $A_{i,j}$: The heuristic value (error density) for assigning LOD $j$ to block $i$ [S1]. Lower values are preferred [S1].
*   $S_{max}$: The memory budget [S1]. If $S_{max}$ is too low for a feasible solution, the algorithm gracefully results in the lowest detail level being specified for all blocks [S1].

**Edge Cases and Pitfalls:**
*   **Infeasible $S_{max}$**: If the constraint is too tight, the algorithm may not be able to satisfy the condition $S_{total} \le S_{max}$ even after assigning the coarsest LODs [S1]. In this case, it assigns the lowest detail level (highest LOD index) to all blocks [S1].

## Subtopics

### Greedy LOD Assignment
This is the primary implementation of the LOD Assignment Algorithm described above [S1]. It sorts potential LOD assignments by the heuristic $A_{i,j}$ (error density) and greedily assigns them [S1].
*   **Performance**: On the QVAPOR dataset, it took 0.1s compared to 7625.6s for GLPK (a general integer programming solver) [S1]. On the MIXFRAC dataset, it took 0.2s compared to 142.1s [S1].
*   **Accuracy**: The results are consistently very close to the optimal solution produced by direct integer programming [S1].
*   **Link**: [LOD Assignment Algorithm](5339-lod-assignment-algorithm.md)

### Multivariate LOD Assignment
An extension of the LOD selection optimization to handle $C$ guiding variables simultaneously [S1]. The objective function is the sum of univariate objective functions, and constraints are the logical conjunction of univariate constraint sets [S1].
*   **Definition**: Used when multiple variables (e.g., cloud density and water vapor) guide LOD selection [S1]. High LOD is required where low LOD would introduce too much error in *either* variable [S1].
*   **Formulation**:
    *   Objective: $\arg \min_H \left( \sum_{k=1}^{C} \sum_{i=1}^{N_k} \sum_{j=1}^{M} E_{k,i}(a_{k,j}) H_{k,i,j} \right)$ [S1]
    *   Constraint 1 (Size): $\sum_{k=1}^{C} \sum_{i=1}^{N_k} \sum_{j=1}^{M} H_{k,i,j} S_{k,i,j} \le S_{max}$ [S1]
    *   Constraint 2 (Selection): $\sum_{j=1}^{M} H_{k,i,j} = 1$ for all $i, k$ [S1]
    *   Constraint 3 (Bounds): $1 \le L_{k,i} \le M$; $L_{k,i} \in \mathbb{Z}$ [S1]
    *   Where $H_{k,i,j}$ is a binary variable indicating if block $i$ of variable $k$ is assigned LOD $j$, $S_{k,i,j}$ is the size, and $E_{k,i}$ is the error [S1].
*   **Pitfall**: If $S_{max}$ is too low for a feasible solution, it defaults to the lowest detail level for all blocks [S1].
*   **Link**: [LOD Assignment Algorithm](5339-lod-assignment-algorithm.md)

## Operating characteristics
*   **Time Complexity**: $O(N \lg N)$, where $N$ is linearly proportional to the number of subvolumes [S1]. This is due to the sorting step of the heuristic list [S1].
*   **Measured Performance**:
    *   QVAPOR dataset: 0.1s (Greedy) vs 7625.6s (GLPK) [S1].
    *   MIXFRAC dataset: 0.2s (Greedy) vs 142.1s (GLPK) [S1].
*   **Scaling**: The running time is unaffected by the target interval of interest, unlike general integer programming solvers (e.g., GLPK) whose performance depends on the coefficients in the linear programming problem [S1].
*   **Strengths**: Extremely fast compared to exact integer programming methods; results are very close to optimal [S1].
*   **Limitations**: It is a heuristic; while close to optimal, it is not guaranteed to be the global optimum [S1]. It requires pre-computed error densities (histogram spectra) [S1].

## Background
The LOD Assignment Algorithm was introduced in the context of multivariate time-varying volume LOD selection [S1]. It addresses the challenge of visualizing multiple variables (guiding variables) where error estimation must be performed independently for each variable using weighted histogram spectra [S1]. The method was developed to overcome the impractical computational complexity of solving the underlying NP-hard binary linear integer programming problem directly [S1].
