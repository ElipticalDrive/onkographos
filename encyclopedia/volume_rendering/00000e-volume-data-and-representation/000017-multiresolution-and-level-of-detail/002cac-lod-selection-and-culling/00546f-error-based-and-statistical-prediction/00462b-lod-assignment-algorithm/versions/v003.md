# LOD Assignment Algorithm


## Overview
The LOD Assignment Algorithm is a greedy method used to assign levels of detail (LOD) to subvolumes in order to minimize error density subject to a maximum working set size constraint ($S_{max}$) [S1]. It builds on the error estimates and heuristics produced by [Error-based and Statistical Prediction](15224-error-based-and-statistical-prediction.md). Unlike [Level-of-Detail Selection](6114-level-of-detail-selection.md), which may use simpler thresholding, or [Histogram Spectra for LOD Selection](11687-histogram-spectra-for-lod-selection.md), which focuses on generating the spectral data, this algorithm performs the final optimization step to select specific LODs for each block [S1]. It is distinguished by its $O(N \log N)$ computational complexity, making it substantially faster than exact integer programming solvers while producing results very close to the optimal solution [S1].

## How it works
The algorithm operates on a pre-sorted list of potential LOD assignments. It initializes the total memory size assuming all blocks are at the lowest detail level (LOD 1) and then iteratively upgrades blocks to higher LODs if they appear early in the sorted list, provided the total size does not exceed $S_{max}$ [S1].

### Inputs and Outputs
**Inputs:**
*   $L$: A list of tuples $(block, lod)$, sorted in ascending order of the heuristic $A_{i,j}$ (error density). This list is produced by [Error-based and Statistical Prediction](15224-error-based-and-statistical-prediction.md) [S1].
*   $B$: An array mapping each subvolume block index to its current assigned LOD level. Initially, all entries are set to 1 [S1].
*   $N_{subvols}$: The total number of subvolumes [S1].
*   $S_{max}$: The maximum allowed working set size in bytes [S1].

**Outputs:**
*   $B$: The updated array where $B[i]$ is the final assigned LOD level for block $i$ [S1].

### Data Structures
*   **List $L$**: Contains entries for potential LOD assignments. Each entry has a `block` index and a `lod` level. The list is sorted by the heuristic value $A_{i,j}$ [S1].
*   **Array $B$**: Indexed by block ID. Stores integer LOD levels. Size is $N_{subvols}$ [S1].
*   **Integer $S_{total}$**: Tracks the current total size of the working set [S1].

### Steps
1.  Initialize $S_{total}$ by assuming all subvolumes are at LOD 1:
    $$ S_{total} := N_{subvols} \times \text{getSubVolSizeForLOD}(1) $$
2.  Iterate through the sorted list $L$ with index $i$ from $0$ to $L.length - 1$.
3.  Continue the loop only if $S_{total} > S_{max}$ [S1].
4.  Inside the loop, let $current\_block = L[i].block$ and $proposed\_lod = L[i].lod$.
5.  Check if the current LOD assigned to the block is lower than the proposed LOD:
    $$ \text{if } B[current\_block] < proposed\_lod $$
6.  If the condition is met:
    a. Subtract the size of the current LOD for the block from $S_{total}$:
       $$ S_{total} -= \text{getSubVolSizeForLOD}(B[current\_block]) $$
    b. Update the assignment for the block to the new LOD:
       $$ B[current\_block] := proposed\_lod $$
    c. Add the size of the new LOD for the block to $S_{total}$:
       $$ S_{total} += \text{getSubVolSizeForLOD}(B[current\_block]) $$
7.  Repeat until the list is exhausted or $S_{total} \le S_{max}$ [S1].

### Pseudocode
```python
def lod_assignment_algorithm(L, B, N_subvols, S_max, getSubVolSizeForLOD):
    """
    Assign LODs to subvolumes to minimize error density subject to S_max.
    
    Args:
        L: List of tuples (block_index, lod_level), sorted by ascending heuristic.
        B: Array of current LOD assignments, initialized to 1.
        N_subvols: Total number of subvolumes.
        S_max: Maximum allowed working set size.
        getSubVolSizeForLOD: Function returning size in bytes for a given LOD level.
        
    Returns:
        B: Updated array of LOD assignments.
    """
    # Initialize total size assuming all blocks are at LOD 1
    S_total = N_subvols * getSubVolSizeForLOD(1)
    
    # Iterate through sorted potential assignments
    for i in range(len(L)):
        # Stop if we are within the size constraint
        if S_total <= S_max:
            break
            
        block_idx = L[i].block
        proposed_lod = L[i].lod
        
        # Only upgrade if the proposed LOD is higher than current
        if B[block_idx] < proposed_lod:
            # Remove old size
            old_size = getSubVolSizeForLOD(B[block_idx])
            S_total -= old_size
            
            # Assign new LOD
            B[block_idx] = proposed_lod
            
            # Add new size
            new_size = getSubVolSizeForLOD(B[block_idx])
            S_total += new_size
            
    return B
```

### Parameters and Edge Cases
*   **$S_{max}$**: If $S_{max}$ is too low to accommodate even the lowest detail level for all blocks, the algorithm gracefully results in the lowest detail level being specified for all blocks [S1].
*   **Precision**: The algorithm relies on the accuracy of `getSubVolSizeForLOD`. If sizes are not integers, floating-point arithmetic should be used for $S_{total}$ [G].
*   **Sorting**: The correctness of the greedy approach depends on $L$ being strictly sorted by the error density heuristic $A_{i,j}$ [S1].

## Subtopics

### Greedy LOD Assignment
This is the standard implementation of the LOD Assignment Algorithm described above. It sorts potential assignments by the heuristic and assigns LODs greedily [S1]. The running time is unaffected by the target interval of interest because it simply sorts and assigns [S1]. Its computational complexity is $O(N \log N)$, where $N$ is linearly proportional to the number of subvolumes [S1]. On the QVAPOR dataset, it took 0.1s compared to GLPK's 7625.6s. On the MIXFRAC dataset, it took 0.2s compared to GLPK's 142.1s [S1]. It substantially outperforms GLPK because general integer programming methods are exponential in the worst case, whereas this is polynomial [S1]. The results are consistently very close to the optimal solution produced by GLPK [S1].

### Multivariate LOD Assignment
This is an extension of the LOD selection optimization to handle $C$ guiding variables simultaneously [S1]. The objective function is the sum of univariate objective functions, and constraints are the logical conjunction of univariate constraint sets [S1].

**Formulation:**
The problem is to find LODs $L_{k,i}$ for variable $k$ and block $i$ that minimize:
$$ \argmin_L \sum_{k=1}^{C} \sum_{i=1}^{N_k} E_{k,i}(a_{k,L_{k,i}}) $$
Subject to:
$$ \sum_{k=1}^{C} \sum_{i=1}^{N_k} S_{k,i,L_{k,i}} \le S_{max} $$
$$ 1 \le L_{k,i} \le M; \quad L_{k,i} \in \mathbb{Z} $$
Where:
*   $C$ is the number of variables.
*   $N_k$ is the number of subvolumes in variable $k$.
*   $M$ is the number of levels of detail.
*   $a_{k,j}$ is the sampling frequency for LOD $j$ of variable $k$.
*   $S_{k,i,j}$ is the load size of LOD $j$ of block $i$ of variable $k$.
*   $E_{k,i}$ is the error function for variable $k$, block $i$.

**Binary Linear Integer Programming Formulation:**
Using binary variables $H_{k,i,j}$ (1 if LOD $j$ is chosen for block $i$ of variable $k$, 0 otherwise):
$$ \argmin_H \sum_{k=1}^{C} \sum_{i=1}^{N_k} \sum_{j=1}^{M} E_{k,i}(a_{k,j}) H_{k,i,j} $$
Subject to:
$$ \sum_{k=1}^{C} \sum_{i=1}^{N_k} \sum_{j=1}^{M} H_{k,i,j} S_{k,i,j} \le S_{max} $$
$$ \sum_{j=1}^{M} H_{k,i,j} = 1; \quad 1 \le i \le N; \quad i \in \mathbb{Z}; \quad 1 \le k \le C; \quad k \in \mathbb{Z} $$

**Pitfall:** If $S_{max}$ is too low for a feasible solution, the algorithm gracefully results in the lowest detail level being specified for all blocks [S1].

## Operating characteristics
*   **Time Complexity**: $O(N \log N)$, where $N$ is linearly proportional to the number of subvolumes [S1]. This is due to the sorting step [S1].
*   **Memory Complexity**: Not given in the sources.
*   **Performance**: On the QVAPOR dataset, the greedy algorithm took 0.1s compared to GLPK's 7625.6s. On the MIXFRAC dataset, it took 0.2s compared to GLPK's 142.1s [S1].
*   **Strengths**: Substantially faster than general integer programming methods (e.g., GLPK) because it avoids exponential worst-case complexity [S1]. Produces results very close to the optimal solution [S1].
*   **Limitations**: It is a greedy approximation and not guaranteed to be globally optimal, although empirical results show it is very close [S1].
*   **When to use**: When a fast, near-optimal LOD assignment is needed for large datasets where exact integer programming is too slow [S1].
*   **When not to use**: When the absolute optimal solution is required and computational resources allow for solving the NP-hard integer programming problem [S1].

## Background
The LOD Assignment Algorithm was introduced in the context of multivariate time-varying volume LOD selection [S1]. It addresses the problem of selecting levels of detail for volume rendering to balance visual fidelity and memory usage [S1]. The algorithm was developed to overcome the impractical computational complexity of directly solving the integer programming problem with general solvers like GLPK [S1]. It is used in visualization applications, such as weather simulations involving multiple variables like clouds and water vapor [S1].
