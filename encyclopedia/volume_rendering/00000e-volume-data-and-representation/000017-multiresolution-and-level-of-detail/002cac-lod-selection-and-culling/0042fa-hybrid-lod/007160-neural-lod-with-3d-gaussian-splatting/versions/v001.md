# Neural LOD with 3D Gaussian Splatting

Also called: NeuralLODManager, Phase 3: Neural LOD, Neural LOD with 3D Gaussian Splatting on ANE

## Overview
This method replaces voxel-based Level of Detail (LOD) for distant terrain (LOD step ≥ 4) with 3D Gaussian Splatting rendered via a neural encoder on the Apple Neural Engine (ANE) [S1, unofficial]. It eliminates the blocky appearance of distant voxel geometry while reducing memory usage by approximately 70x [S1, unofficial]. Unlike [Transvoxel Algorithm](20300-transvoxel-algorithm.md), which interpolates geometry for smooth transitions, this approach uses a learned representation to generate smooth, detailed landscape silhouettes at any distance [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A low-resolution 32×32 heightmap and biome map covering a 4×4 chunk region. This data is formatted as a tensor of shape $32 \times 32 \times 3$ representing height, biome, and normal data [S1, unofficial].
*   **Output:** A set of $N$ 3D Gaussians, where $N$ is between 64 and 256. Each Gaussian is defined by 14 floats representing position, scale, rotation, color, and opacity [S1, unofficial].

**Data Structures**
The output data structure per Gaussian consists of 14 floats [S1, unofficial]:
1.  Position (3 floats: $x, y, z$)
2.  Scale (3 floats)
3.  Rotation (4 floats: quaternion)
4.  Color (3 floats)
5.  Opacity (1 float)

**Steps**
1.  **Detection:** The `ChunkManager` detects when a terrain chunk enters the LOD ≥ 4 zone [S1, unofficial].
2.  **Data Generation (CPU):** The CPU generates a low-resolution 32×32 heightmap and biome map for the region covering 4×4 chunks [S1, unofficial].
3.  **Neural Inference (ANE):** The Apple Neural Engine (ANE) runs a Core ML model. The input tensor is $32 \times 32 \times 3$ (height, biome, normal). The model outputs an $N \times 14$ tensor containing Gaussian parameters, where $N \in [64, 256]$ [S1, unofficial].
4.  **Rendering (GPU):** The GPU performs a Gaussian Splatting render pass:
    *   Depth-sorts the splats.
    *   Rasterizes them.
    *   Performs a depth test against the existing voxel geometry [S1, unofficial].

**Pseudocode**
```python
# NeuralLODManager.swift logic
def on_chunk_lod_update(chunk):
    if chunk.lod_step >= 4:
        # CPU: Generate input data for 4x4 chunk region
        heightmap = generate_low_res_heightmap(chunk.region, resolution=32)
        biome_map = generate_biome_map(chunk.region, resolution=32)
        normals = compute_normals(heightmap)
        
        # Input tensor: 32x32x3 (height, biome, normal)
        input_tensor = stack([heightmap, biome_map, normals], axis=-1)
        
        # ANE: Core ML Inference
        # Output tensor: N x 14 (pos, scale, rotation, color, opacity)
        gaussian_params = core_ml_model.predict(input_tensor)
        
        # GPU: Render Pass
        splats = parse_gaussians(gaussian_params)
        render_gaussian_splats(splats, depth_test_against_voxels=True)

def parse_gaussians(tensor):
    """
    Tensor shape: (N, 14)
    Returns list of Gaussian objects
    """
    gaussians = []
    for i in range(tensor.shape[0]):
        g = tensor[i]
        gaussian = Gaussian(
            position=g[0:3],
            scale=g[3:6],
            rotation=g[6:10], # Quaternion
            color=g[10:13],
            opacity=g[13]
        )
        gaussians.append(gaussian)
    return gaussians
```

**Parameters**
*   **LOD Threshold:** Triggered when chunk LOD step $\ge 4$ [S1, unofficial].
*   **Input Tensor Dimensions:** $32 \times 32 \times 3$ [S1, unofficial].
*   **Output Tensor Dimensions:** $N \times 14$, where $N \in [64, 256]$ [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Hardware Requirements:** Requires macOS 15+ for Core ML and ANE support, and M1+ hardware for the Neural Engine [S1, unofficial].
*   **Memory Savings:** Memory usage for a 64-chunk region is reduced from approximately 0.5 MB (voxels) to 7 KB (128 Gaussians), a 70x savings [S1, unofficial].
*   **Visual Quality:** Compared to voxel-based LOD at step=8 (which produces $2^3=8$ effective voxels per chunk and is extremely blocky), this method provides smooth silhouettes [S1, unofficial].

## Operating characteristics
*   **Memory:** Reduces memory usage by ~70x for distant terrain (0.5 MB to 7 KB for a 64-chunk region) [S1, unofficial].
*   **Performance:** The ANE runs inference alongside the GPU, avoiding resource contention [S1, unofficial].
*   **Visual Quality:** Provides smooth, detailed landscape silhouettes at any distance, eliminating the blockiness of voxel-based LOD at high steps (e.g., step=8) [S1, unofficial].
*   **Limitations:** Restricted to Apple hardware (M1+ chips) and macOS 15+ [S1, unofficial].

## Background
This technique is part of "Phase 3" of the Metalcraft project, authored by plagness [S1, unofficial]. It addresses the limitation of the current LOD system, which at step=8 produces only 8 effective voxels per chunk, resulting in extremely blocky terrain [S1, unofficial]. The method leverages self-supervised training to render own terrain as ground truth for the Core ML model [S1, unofficial]. It integrates with `ChunkManager.swift` and uses a new render pass in `Renderer.swift` after deferred lighting, referencing the open-source MetalSplatter project for Gaussian Splatting implementation [S1, unofficial].
