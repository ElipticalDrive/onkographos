# Hybrid LoD
Also called: HybridLoD
## Overview
Hybrid LoD is a level-of-detail rendering technique that aggregates scene appearance to optimize rendering performance for large-scale volumetric or geometric datasets [S1, unofficial]. It distinguishes itself by combining high-resolution reference data with optimized low-resolution approximations, aiming to maintain visual fidelity while reducing computational cost [S1, unofficial]. Unlike pure geometric LOD methods, it focuses on appearance aggregation, potentially blending different representation strategies to handle varying detail levels [S1, unofficial].
## How it works
**Inputs and Outputs:**
*   Input: High-resolution scene data (reference), camera parameters, and a target resolution or performance constraint.
*   Output: Rendered image with aggregated appearance at the selected LOD.

**Data Structures:**
*   Not specified in the provided sources. The method likely involves storing reference high-resolution data and pre-computed or dynamically generated low-resolution approximations.

**Steps:**
1.  **Scene Analysis:** Determine the required level of detail for different parts of the scene based on distance, importance, or other criteria. [G]
2.  **Aggregation:** Combine high-resolution and low-resolution data representations. The specific aggregation mechanism (e.g., blending, switching, hierarchical blending) is not detailed in the sources. [G]
3.  **Rendering:** Render the aggregated scene data. The sources mention rendering results compared to a high-resolution reference (PT Ref. High Res.) [S1, unofficial].
4.  **Quality Assessment:** Evaluate the result using metrics like Root Mean Square Error (RMSE) against the reference [S1, unofficial].

**Formulas:**
*   RMSE calculation is implied by the results table but the formula itself is not provided. Standard RMSE is $\sqrt{\frac{1}{N}\sum_{i=1}^{N}(y_i - \hat{y}_i)^2}$, where $y_i$ is the reference value and $\hat{y}_i$ is the predicted/approximated value [G].

**Parameters:**
*   Resolution: Examples include $32^3$ and $64^3$ [S1, unofficial].
*   Samples per pixel: 1024 samples per pixel were used for the results in the source [S1, unofficial].

**Edge Cases and Pitfalls:**
*   Not specified in the provided sources. Potential issues could include artifacts at LOD boundaries or increased memory usage for storing multiple resolutions. [G]
