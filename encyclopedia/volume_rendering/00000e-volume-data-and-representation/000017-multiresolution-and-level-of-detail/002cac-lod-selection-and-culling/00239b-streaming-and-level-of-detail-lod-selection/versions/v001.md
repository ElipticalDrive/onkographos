# Streaming and Level-of-Detail (LOD) selection

Also called: additive ladders, frustum-culled streaming

## Overview
Streaming and Level-of-Detail (LOD) selection manages scenes that exceed rendering budgets by dynamically loading data based on viewpoint position, bounding memory usage to visible data and required resolution [S1, unofficial]. It sets itself apart from static multi-resolution methods by using additive ladders to paint a coarse scene from the first chunk and sharpen it as data arrives, while substitutive levels and spatial tiles reduce the cost of distant or off-screen objects [S1, unofficial]. Unlike hierarchical culling which may pre-fetch or cache entire structures, this method ensures a coarse or off-screen region is never fetched at full detail by selecting the coarsest substitutive level whose projected median splat footprint stays at or below 1.5 CSS pixels [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scene archive (e.g., `.luxar.zarr`) containing Gaussian splats with centers, Cholesky factors, amplitudes, and chunk bounds [S1, unofficial]. The archive includes LOD groups (`additive_0` ... `additive_3`) alongside base data [S1, unofficial].
*   **Output:** A stream of data chunks and rendered frames where detail adapts to screen space and network availability [S1, unofficial].

**Data Structures:**
The scene is stored in a Zarr-based archive structure [S1, unofficial]:
*   `centers`: Splat positions.
*   `cholesky`: Splat covariance (Cholesky decomposition).
*   `amplitudes`: Splat intensities.
*   `chunk_bounds`: Spatial partitioning bounds.
*   `additive_0 ... additive_3`: LOD groups representing additive ladders [S1, unofficial].

**Algorithm Steps:**
1.  **Frustum Culling:** Partition tiles are frustum-culled. Coarse or off-screen regions are never fetched at full detail [S1, unofficial].
2.  **LOD Ordering:** Additive ladders are ordered to optimize progressive loading.
    *   For $N \le 5,000$ splats: Use greedy ordering [S1, unofficial].
    *   For $N > 5,000$ splats: Use $O(N \log N)$ self-energy ordering [S1, unofficial].
3.  **Level Selection:** For each visible tile/splat group, select the coarsest substitutive level whose projected median splat footprint is $\le 1.5$ CSS pixels [S1, unofficial].
    *   If no level satisfies the condition, select the finest level [S1, unofficial].
    *   Apply a 10% hysteresis against coarsening to prevent flickering [S1, unofficial].
4.  **Fallback:** If no footprint is stamped or the stamped dimensions are not the displayed ones, fall back to the screen-area fraction the node’s bounding box projects to [S1, unofficial].
5.  **Streaming & Caching:**
    *   Fetch data in prefix order of the additive ladders [S1, unofficial].
    *   Pass fetched data through a multi-level cache:
        1.  Decoded per-slice geometry (memory).
        2.  Decoded chunks (memory).
        3.  Compressed chunks (memory).
        4.  Compressed chunks (browser origin-private file system).
        5.  HTTP range requests [S1, unofficial].
    *   Prefetching: After an on-disk hit or remote fetch, request the chunk on either side in the ordering. An idle-time prefetcher warms the adjacent slice to hide remote-fetch latency [S1, unofficial].

**Pseudocode:**
```python
def select_lod_level(splat_footprint, current_level, hysteresis_threshold=0.1):
    """
    Select the coarsest LOD level where projected median splat footprint <= 1.5 CSS pixels.
    Applies hysteresis against coarsening.
    """
    threshold = 1.5  # CSS pixels
    
    # Find coarsest level satisfying footprint constraint
    candidate_level = None
    for level in sorted_lod_levels:  # Sorted from coarsest to finest
        if level.footprint <= threshold:
            candidate_level = level
            break
            
    if candidate_level is None:
        # Finest only when none does
        return finest_level
    
    # Hysteresis against coarsening
    # If current level is finer than candidate, ensure we don't jump back too easily
    if current_level is not None and current_level.index < candidate_level.index:
        # Check if the improvement in footprint justifies the coarsening
        # Simplified: require significant change or stick to current if close
        if current_level.footprint < candidate_level.footprint * (1 - hysteresis_threshold):
            return candidate_level
        else:
            return current_level
            
    return candidate_level

def order_additive_ladder(splats):
    """
    Order splats for additive ladder construction.
    """
    n = len(splats)
    if n <= 5000:
        # Greedy ordering
        return greedy_ordering(splats)
    else:
        # O(N log N) self-energy ordering
        return self_energy_ordering(splats)

def stream_scene(scene_archive, view_params):
    """
    Main streaming loop.
    """
    # 1. Frustum cull partition tiles
    visible_tiles = frustum_cull(scene_archive.tiles, view_params)
    
    # 2. Determine LOD for each tile
    for tile in visible_tiles:
        if tile.has_footprint_stamp and tile.stamped_dims == view_params.displayed_dims:
            footprint = tile.projected_median_footprint
            lod = select_lod_level(footprint, tile.current_lod)
        else:
            # Fallback to screen-area fraction
            area_frac = tile.bounding_box.projected_area_fraction(view_params)
            lod = select_lod_by_area(area_frac, tile.current_lod)
        
        tile.target_lod = lod
        
    # 3. Fetch chunks in prefix order
    chunks_to_fetch = get_chunks_for_lods(visible_tiles)
    for chunk in chunks_to_fetch:
        data = cache_get_or_fetch(chunk)
        process_chunk(data)
        
        # Prefetch adjacent chunks
        prefetch_adjacent(chunk)
```

**Parameters:**
*   **Footprint threshold:** 1.5 CSS pixels [S1, unofficial].
*   **Hysteresis:** 10% against coarsening [S1, unofficial].
*   **LOD ordering switch:** 5,000 splats (greedy below, self-energy above) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Missing Footprint:** If no footprint is stamped or stamped dimensions do not match displayed dimensions, the fallback to screen-area fraction is used [S1, unofficial].
*   **Precision:** The 1.5 CSS pixel threshold is specific to the viewer's rendering context [S1, unofficial].
*   **Ordering Guarantee:** The $O(N \log N)$ self-energy ordering for $N > 5,000$ has no approximation guarantee claimed, though greedy lowers residual area under the loading curve by 0.2–2.6% relative to it in experiments [S1, unofficial].

## Subtopics

### [Dynamic Loading and Progressive Update](4577-dynamic-loading-and-progressive-update.md)
A strategy for visualizing massive scenes by dynamically and adaptively loading data based on viewpoint position, bounding memory usage to visible data and required resolution. It enables scalable interactive web visualization by handling scenes that outgrow a single rendering budget.

### Level-of-Detail Grammar
A system for managing scenes that exceed rendering budgets by using additive ladders, substitutive levels, and spatial tiles to adjust detail based on data arrival, distance, and screen position [S1, unofficial]. It uses additive ladders to paint a coarse scene from the first chunk and sharpen it as more data arrives, and substitutive levels and spatial tiles to reduce the cost of distant or off-screen objects [S1, unofficial]. The `.luxar.zarr` archive structure includes LOD groups: `additive_0 ... additive_3` for additive levels, alongside `centers`, `cholesky`, `amplitudes`, and `chunk_bounds` [S1, unofficial].

### Additive levels of detail for Gaussian splats
An order-optimisation framework for streaming progressive loading of Gaussian splats, building additive ladders where each rung adds detail without replacing previous data [S1, unofficial]. It computes a closed-form quadratic-assignment AUC to evaluate splat ordering, calculates a monotone-submodular utility function on the splat Gram matrix, and applies a greedy selection algorithm that guarantees a uniform $(1 - 1/e)$ approximation bound [S1, unofficial]. It is implemented using sparse-Gram storage and sparse-greedy selection to optimize memory and compute [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** LOD ordering is $O(N)$ for greedy (up to 5,000 splats) and $O(N \log N)$ for self-energy ordering (above 5,000 splats) [S1, unofficial].
*   **Memory Complexity:** Bounded by visible data and required resolution, with multi-level caching (decoded geometry, decoded chunks, compressed chunks, on-disk cache) [S1, unofficial].
*   **Measured Performance:** The Drosophila scene opens in 19.06 MB, against 5.27 MB at the compiler’s 64 KB chunks, which in turn make a step cost 266–268 requests [S1, unofficial]. Luxar scales from a handful of primitives to millions of points and splats while remaining interactive [S1, unofficial].
*   **Strengths:** Handles scenes that outgrow a single rendering budget; enables scalable interactive web visualization; hides network latency with prefetching and caching [S1, unofficial].
*   **Limitations:** The self-energy ordering for large N has no approximation guarantee; requires specific archive structure (`.luxar.zarr`) [S1, unofficial].
*   **When to use:** For massive scenes requiring interactive web visualization where network latency and rendering budget are constraints [S1, unofficial].
*   **When not to use:** For small scenes where static loading is sufficient, or when the specific `.luxar.zarr` format is not available [S1, unofficial].

## Background
The method originates from the Luxar system, described in "Luxar: Gaussian splatting for microscopy and scalable interactive web visualisation of multidimensional scientific data" [S1, unofficial]. It was developed to handle scenes that exceed rendering budgets, enabling scalable interactive web visualization [S1, unofficial]. The system uses WebGL or WebGPU rendering with HDR tone mapping and supports nD sliders for time, channel, and any hidden axis [S1, unofficial]. The compiled archive is served by any static HTTP host, and a browser viewer opens any archive from its URL [S1, unofficial].
