# Dynamic Loading Strategy


## Overview
A strategy to determine the level-of-detail (LOD) and specific data blocks to load, reducing VRAM usage by projecting block regions onto the camera plane to determine visibility [S1]. It sets itself apart from static LOD selection by dynamically culling invisible blocks and adapting resolution based on the camera's distance and the block's projected size, ensuring that only necessary data resides in memory [S1].

## How it works
**Inputs:** Camera position and orientation; 3D block definitions (center points and corner coordinates); LOD hierarchy thresholds.
**Outputs:** Set of visible blocks and their required LOD levels for the current frame.

**Data Structures:**
*   **Block Region:** Defined by four xy corner points and a single z-component.
    *   $xy$-components: Center points of the block on the xy plane [S1].
    *   $z$-component: The height of the highest part within the block [S1].
*   **Visibility Mask:** Boolean flag per block indicating if it is visible [S1].

**Steps:**
1.  **Define Block Region:** For each block, construct a region using the four xy corner points and the pre-determined z value (height of the highest part) [S1].
2.  **Project to Camera Plane:** Project the defined 3D block region onto the 2D camera plane [S1].
3.  **Visibility Check:** Determine if the projected region is visible to the camera. Blocks not visible are eliminated [S1].
4.  **LOD Selection (Threshold-based):**
    *   Start with the coarsest LOD [S1].
    *   Check the distance from the camera to all visible blocks within the finer LOD [S1].
    *   If the distance exceeds a certain threshold, render using the resources loaded at the current LOD [S1].
    *   Otherwise, progress to the subsequent, finer LOD [S1].

**Parameters:**
*   **Distance Threshold:** The maximum distance from the camera at which a finer LOD is required. "Not given in the sources." [S1].

**Pseudocode:**
```python
def dynamic_loading_strategy(camera, blocks, lod_levels, distance_threshold):
    visible_blocks = []
    
    for block in blocks:
        # Step 1 & 2: Define region and project
        # Block region is defined by 4 xy corners and max z height [S1]
        region = block.get_region() 
        projected_region = project_to_camera_plane(region, camera)
        
        # Step 3: Visibility check
        if is_visible(projected_region, camera):
            # Step 4: LOD Selection
            current_lod = lod_levels[0] # Start with coarsest [S1]
            
            for lod in lod_levels:
                if lod == lod_levels[-1]:
                    # Reached finest LOD
                    visible_blocks.append((block, lod))
                    break
                
                # Check distance to finer LOD blocks
                # Note: Logic implies checking if camera is close enough to justify finer LOD
                if distance_to_camera(camera, block) > distance_threshold:
                    # Use current LOD
                    visible_blocks.append((block, current_lod))
                    break
                else:
                    # Progress to finer LOD
                    current_lod = lod
            
            # If loop completes without break, use finest LOD
            if visible_blocks[-1][1] != lod_levels[-1] and distance_to_camera(camera, block) <= distance_threshold:
                 visible_blocks[-1] = (block, lod_levels[-1])
                 
    return visible_blocks
```

## Subtopics

### Progressive Multiscale Loading
A rendering strategy where each frame picks the appropriate resolution level per volume region, aiming for approximately one voxel per screen pixel. Coarse data fills the view first, and finer data replaces it region-by-region as it arrives, producing a complete coarse view within seconds that sharpens in place. It differs from standard dynamic loading by allowing mixed resolutions within a single frame and ensuring every cell is drawn exactly once, either from its own chunk or one resident coarser ancestor, to prevent double integration.
*   **When to choose:** When visualizing massive volumes (e.g., histotomography) where immediate coarse visibility is critical, and memory bandwidth allows for fetching specific coarser ancestors.
*   **Key Parameters:** Target resolution is coarsened to stay under 8192 cells and 60% of system memory.
*   **Link:** [Progressive Multiscale Loading](4578-progressive-multiscale-loading.md)

## Operating characteristics
*   **Time Complexity:** Depends on the number of blocks and LOD levels. Visibility checks are $O(N)$ where $N$ is the number of blocks. LOD selection involves distance checks [S1].
*   **Memory Complexity:** Reduced VRAM usage by only loading visible blocks [S1]. In progressive variants, memory is bounded by the target resolution plus a small fraction for coarser ancestors (e.g., under 1/7 of target voxels for 2x downsampling) [S2, unofficial].
*   **Strengths:** Significantly reduces VRAM usage for large scenes [S1]. Provides immediate coarse visibility in progressive variants [S2, unofficial].
*   **Limitations:** Requires efficient projection and visibility checks [S1]. Threshold-based LOD selection may cause popping if thresholds are not well-tuned [S1].
*   **When to use:** Large-scale scenes with limited VRAM [S1]. Massive volumes requiring rapid initial visibility [S2, unofficial].
*   **When not to use:** Small scenes where all data fits in memory [S1].

## Background
Originated in the context of real-time neural rendering of large-scale scenes on the web [S1]. Developed to handle the memory constraints of rendering massive 3D data sets in web browsers [S1]. Progressive multiscale loading was further developed in the context of neuroglancer for histotomography data [S2, unofficial].
