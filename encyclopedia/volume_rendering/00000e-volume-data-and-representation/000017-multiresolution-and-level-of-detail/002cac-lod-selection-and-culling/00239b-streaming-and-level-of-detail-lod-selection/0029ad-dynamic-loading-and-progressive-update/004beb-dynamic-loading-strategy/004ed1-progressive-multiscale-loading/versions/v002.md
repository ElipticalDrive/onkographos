# Progressive Multiscale Loading

Also called: Progressive LOD

## Overview
Progressive Multiscale Loading is a rendering strategy where each frame selects the appropriate resolution level per volume region, aiming for approximately one voxel per screen pixel [S1, unofficial]. Coarse data fills the view first, and finer data replaces it region-by-region as it arrives, producing a complete coarse view within seconds that sharpens in place [S1, unofficial]. It sets itself apart from static LOD systems by dynamically determining the minimum resolution required per frame based on projected size, avoiding the storage overhead of precomputed full-resolution hierarchies for extremely large 3D volumes [S1, unofficial].

## How it works
**Inputs:**
*   Current camera view (frustum, projection matrix).
*   Volume dataset with hierarchical chunk structure (axis-aligned, integer voxel ratios, aligned origins).
*   System memory limit.

**Outputs:**
*   A set of resident chunks (at various resolution levels) to be rendered for the current frame.
*   A prioritized list of chunks to fetch from storage.

**Data Structures:**
*   **Chunk:** A block of volume data at a specific resolution level.
*   **Hierarchy:** A tree where each chunk at level $L$ has a parent chunk at level $L-1$ (coarser). The hierarchy must be nested: every cell inside a parent chunk corresponds to a $2^k \times 2^k \times 2^k$ block of cells in the child chunk (for 2× downsampling).

**Steps:**

1.  **Determine Target Resolution:**
    Calculate the coarsest scale whose projected voxel size is at least 1 pixel on the screen. Let this be the *target level* $L_{target}$.
    *Constraint:* Coarsen $L_{target}$ further if necessary to ensure the total number of cells does not exceed 8192 and the memory footprint stays under 60% of system memory [S1, unofficial].

2.  **Select Resident Levels (The Single-Source Rule):**
    For every cell in the target resolution $L_{target}$ that is visible in the current view:
    *   Identify the finest resident ancestor chunk that covers this cell.
    *   If the chunk at $L_{target}$ is resident, use it.
    *   Otherwise, use exactly one resident coarser ancestor (clipped to the cell's extent).
    *   **Crucial:** Do not combine multiple levels for the same cell. A ray must integrate tissue from exactly one source per cell to prevent double integration [S1, unofficial].

3.  **Level Selection Policy:**
    *   **Floor:** The coarsest complete level is always resident and pinned above everything, ensuring a complete image exists immediately [S1, unofficial].
    *   **Interim Backing:** Typically, the target level $L_{target}$ and the next coarser level $L_{target}-1$ are considered. If $L_{target}$ is not resident, $L_{target}-1$ serves as the backing [S1, unofficial].
    *   **General Form:** The renderer takes the finest resident ancestor for each cell. Intermediate levels (between the finest resident and the floor) are not requested unless already resident [S1, unofficial].

4.  **Fetching and Warming:**
    *   Request chunks for the target level $L_{target}$ based on visibility.
    *   When idle, warm the next-finer level into system memory to prepare for future refinement [S1, unofficial].

**Pseudocode:**

```python
def get_chunks_for_frame(camera, volume_hierarchy, system_memory_limit):
    # Step 1: Determine target level
    # Calculate projected voxel size for each region
    # Find coarsest level L_target where projected_voxel >= 1 pixel
    L_target = calculate_target_level(camera, volume_hierarchy)
    
    # Apply memory constraints
    # If cells at L_target > 8192 or memory > 60% limit, coarsen L_target
    while get_cell_count(L_target) > 8192 or get_memory_usage(L_target) > 0.6 * system_memory_limit:
        L_target = L_target + 1  # Coarser level
        
    # Step 2: Identify visible cells at L_target
    visible_cells = get_visible_cells_in_frustum(L_target, camera)
    
    # Step 3: Select backing chunks for each visible cell
    resident_chunks = set()
    
    # Always include the coarsest complete level as floor
    floor_level = get_coarsest_level(volume_hierarchy)
    resident_chunks.update(get_all_chunks(floor_level))
    
    for cell in visible_cells:
        # Find the finest resident ancestor for this cell
        # Start from L_target and go up to floor_level
        current_level = L_target
        backing_chunk = None
        
        while current_level >= floor_level:
            chunk = get_chunk_at_level(cell, current_level)
            if chunk.is_resident():
                backing_chunk = chunk
                break
            current_level -= 1
            
        # If no resident ancestor found (should not happen due to floor), 
        # request the coarsest available or handle error
        if backing_chunk is None:
            backing_chunk = get_chunk_at_level(cell, floor_level)
            
        resident_chunks.add(backing_chunk)
        
        # Request non-resident chunks for L_target if not already resident
        if not chunk.is_resident():
            request_chunk(chunk)
            
    # Step 4: Warm next finer level when idle
    if is_idle():
        next_finer_level = L_target - 1
        if next_finer_level >= 0:
            warm_chunks(next_finer_level)
            
    return resident_chunks
```

**Edge Cases and Pitfalls:**
*   **Hierarchy Alignment:** Levels must nest strictly (axis-aligned, integer voxel ratios, aligned origins). Otherwise, the single-source rule fails [S1, unofficial].
*   **Double Integration:** Rendering both a fine chunk and its coarser ancestor for the same cell causes double integration of tissue along a ray [S1, unofficial].
*   **Memory Limits:** The 8192 cell and 60% memory limits are hard constraints to prevent out-of-memory errors [S1, unofficial].

## Subtopics

### [View-dependent data loading](17938-view-dependent-data-loading.md)
Combines frustum-based culling with LOD selection to reduce data requests. Unlike static LOD, it dynamically determines resolution per frame, avoiding precomputed hierarchies for massive volumes.

## Operating characteristics
*   **Time Complexity:** Depends on the number of visible cells at the target level and the cost of fetching chunks. Sorting chunks front-to-back allows early ray termination, improving effective performance [S1, unofficial].
*   **Memory Complexity:** The cost of keeping the whole chain of coarser levels resident is under 1/7 of the target's voxels for 2× downsampling levels (geometric series: $1/8 + 1/64 + \dots$) [S1, unofficial].
*   **Strengths:** Provides a complete coarse view quickly, then sharpens in place. Reduces VRAM usage by only loading necessary resolution.
*   **Limitations:** Requires a nested hierarchy. Performance may degrade if the target level is very fine and many chunks need to be fetched simultaneously.
*   **When to use:** Interactive exploration of massive volumetric datasets on limited hardware.
*   **When not to use:** When precomputed full-resolution hierarchies are feasible and memory is abundant.

## Background
Originated in the context of neuroglancer, a tool for viewing histotomography data (e.g., 2.8 TB volume @ 16bits) [S1, unofficial]. The method was developed to handle large volumes interactively without precomputing full-resolution pyramids.
