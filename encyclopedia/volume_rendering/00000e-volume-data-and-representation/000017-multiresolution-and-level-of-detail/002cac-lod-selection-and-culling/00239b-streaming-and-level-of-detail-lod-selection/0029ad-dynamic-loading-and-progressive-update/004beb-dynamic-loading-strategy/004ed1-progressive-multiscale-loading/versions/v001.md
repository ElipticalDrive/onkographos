# Progressive Multiscale Loading

Also called: Progressive LOD

## Overview
Progressive Multiscale Loading is a rendering strategy that selects the appropriate resolution level per volume region each frame, aiming for approximately one voxel per screen pixel [S1, unofficial]. It solves the problem of rendering massive volumetric datasets on limited hardware by filling the view with coarse data immediately and sharpening it in place as finer data arrives [S1, unofficial]. It differs from standard single-resolution volume rendering by dynamically mixing resolution levels per region while ensuring no voxel is integrated twice along a ray [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A multiresolution volume dataset with nested, axis-aligned, integer-voxel-ratio levels and aligned origins; current camera view; system memory constraints.
*   **Output:** A rendered image where each screen pixel is shaded using data from exactly one volume cell at the appropriate resolution.

**Data Structures:**
*   **Volume Levels:** A hierarchy of chunks where each level $L_i$ is a downsampled version of $L_{i-1}$ by a factor of 2 in each dimension [S1, unofficial].
*   **Resident Cache:** A set of chunks currently loaded in system memory.
*   **Target Resolution:** The coarsest level $L_{target}$ such that the projected voxel size is at least 1 pixel [S1, unofficial].

**Parameters:**
*   **Max Cells:** 8192 cells per dimension for the target resolution [S1, unofficial].
*   **Memory Limit:** 60% of system memory [S1, unofficial].
*   **Downsampling Factor:** 2× per level [S1, unofficial].

**Steps:**
1.  **Calculate Target Resolution:** Determine the coarsest level $L_{target}$ where the projected voxel size is $\ge 1$ pixel. If the number of cells in $L_{target}$ exceeds 8192 or the memory footprint exceeds 60% of system memory, coarsen to the next level [S1, unofficial].
2.  **Select Resident Levels:**
    *   Identify the finest resident ancestor of each target cell.
    *   Ensure the coarsest complete level is always resident as a floor [S1, unofficial].
    *   For each target cell, select exactly one backing source: either its own chunk at $L_{target}$ (if resident) or exactly one resident coarser ancestor clipped to that cell [S1, unofficial].
    *   Do not combine multiple levels for a single cell to prevent double integration [S1, unofficial].
3.  **Fetch Data:** Request missing chunks for the selected levels. Prioritize the coarsest level first, then the target level, then intermediate levels if needed [S1, unofficial].
4.  **Render:** Perform sorted front-to-back compositing using the selected chunks. Rays stop when opaque material is sufficient [S1, unofficial].

**Formulas:**
*   **Projected Voxel Size:** $s = \frac{f \cdot d}{z}$, where $f$ is focal length, $d$ is voxel size at level $L$, and $z$ is distance [G].
*   **Memory Cost of Coarser Chain:** For 2× downsampling, the total memory of all coarser levels relative to the target is $\sum_{k=1}^{\infty} \frac{1}{8^k} = \frac{1/8}{1-1/8} = \frac{1}{7}$ [S1, unofficial].

**Pseudocode:**
```python
def progressive_multiscale_render(camera, volume_levels, resident_cache, system_memory):
    # Step 1: Calculate target resolution
    target_level = None
    for level in volume_levels:
        projected_voxel = calculate_projected_voxel_size(level, camera)
        if projected_voxel >= 1.0:
            target_level = level
            break
    
    # Coarsen if necessary
    if target_level is None or count_cells(target_level) > 8192:
        target_level = find_coarsest_level_within_memory_limit(volume_levels, 0.6 * system_memory)
    
    # Step 2: Select resident levels
    # Ensure coarsest level is resident
    coarsest_level = volume_levels[-1]
    if coarsest_level not in resident_cache:
        fetch_chunk(coarsest_level)
        resident_cache.add(coarsest_level)
    
    # For each target cell, select backing source
    render_chunks = []
    for cell in target_level.cells:
        # Find finest resident ancestor
        finest_resident = find_finest_resident_ancestor(cell, resident_cache)
        if finest_resident is None:
            # Fetch target level chunk if not resident
            if cell.chunk not in resident_cache:
                fetch_chunk(cell.chunk)
                resident_cache.add(cell.chunk)
            finest_resident = cell.chunk
        
        render_chunks.append(finest_resident)
    
    # Step 3: Render
    sorted_chunks = sort_front_to_back(render_chunks, camera)
    image = empty_image()
    for chunk in sorted_chunks:
        composite_chunk(chunk, image, camera)
    
    return image
```

## Subtopics

### [View-dependent data loading](17938-view-dependent-data-loading.md)
A technique to enable interactive exploration of massive datasets on low-cost hardware by loading only the spatial extent and resolution necessary for the current camera view, reducing data requests and facilitating navigation.

## Operating characteristics
*   **Time Complexity:** Depends on the number of chunks and compositing cost. Sorting chunks adds overhead but allows early ray termination [S1, unofficial].
*   **Memory Complexity:** Under 1/7 of the target resolution's voxels for the coarser chain, plus the target resolution itself [S1, unofficial].
*   **Strengths:** Immediate visual feedback with coarse data; smooth refinement as data arrives; efficient memory usage [S1, unofficial].
*   **Limitations:** Requires nested, aligned volume levels; complex chunk management; potential for visual popping if finer data arrives late [S1, unofficial].
*   **When to Use:** Large volumetric datasets (e.g., histotomography) on limited hardware; interactive exploration [S1, unofficial].
*   **When Not to Use:** Small datasets; real-time requirements where visual popping is unacceptable; non-nested volume data [S1, unofficial].

## Background
Progressive Multiscale Loading was developed for the Neuroglancer histotomography fork to handle 2.8 TB volumes at 16-bit precision [S1, unofficial]. It addresses the limitations of single-resolution volume rendering by allowing dynamic LOD selection per region [S1, unofficial].
