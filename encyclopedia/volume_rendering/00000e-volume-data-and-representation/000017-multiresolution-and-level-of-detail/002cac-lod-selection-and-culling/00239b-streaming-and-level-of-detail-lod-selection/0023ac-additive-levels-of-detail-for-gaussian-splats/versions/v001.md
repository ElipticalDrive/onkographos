# Additive levels of detail for Gaussian splats

Also called: additive LOD streaming, order-optimised progressive loading

## Overview
This method provides an order-optimisation framework for the streaming and progressive loading of Gaussian splats [S1, unofficial]. It solves the problem of inefficient data transfer and rendering latency in large-scale scenes by constructing additive ladders where each rung adds detail without replacing previously loaded data [S1, unofficial]. Unlike substitutive LOD methods that swap coarse primitives for fine ones, this approach accumulates splats, ensuring that the viewer always renders the highest-priority subset of the scene available in the current buffer [S1, unofficial].

## How it works
The method constructs a prioritized sequence of Gaussian splats using submodular optimization to maximize a utility function derived from the splat geometry.

**Inputs and Outputs**
- **Input**: A set of $N$ Gaussian splats $\mathcal{G} = \{g_1, \dots, g_N\}$, where each splat $g_i$ is defined by position $\mathbf{t}_i$, covariance matrix $\mathbf{\Sigma}_i$ (or rotation $\mathbf{R}_i$ and scale $\mathbf{s}_i$), opacity $\alpha_i$, and spherical harmonic coefficients for color.
- **Output**: A permutation $\pi$ of indices $\{1, \dots, N\}$ defining the loading order, and a set of additive ladders (prefixes of $\pi$) for streaming.

**Data Structures**
- **Splat Gram Matrix**: A sparse matrix $\mathbf{G} \in \mathbb{R}^{N \times N}$ where entry $G_{ij}$ represents the interaction or overlap metric between splat $i$ and splat $j$. The exact formula for $G_{ij}$ is based on the quadratic-assignment approximation of the area under the curve (AUC) of the splat projection [S1, unofficial].
- **Sparse-Gram Storage**: To optimize memory, $\mathbf{G}$ is stored in a sparse format (e.g., CSR or COO), retaining only significant interactions [S1, unofficial].

**Algorithm Steps**
1. **Compute Interaction Matrix**: Calculate the pairwise interaction values $G_{ij}$ for all $i, j$. This involves a closed-form quadratic-assignment AUC evaluation to estimate the visual contribution overlap between splats [S1, unofficial].
2. **Define Utility Function**: Define a monotone-submodular utility function $f: 2^{\mathcal{G}} \to \mathbb{R}$ on the splat Gram matrix. The function measures the total visual coverage or information gain of a subset of splats [S1, unofficial].
3. **Greedy Selection**: Apply a greedy algorithm to select splats in order. At each step $k$, select the splat $g_{next}$ that maximizes the marginal gain:
   $$ g_{next} = \arg \max_{g \in \mathcal{G} \setminus S_{k-1}} f(S_{k-1} \cup \{g\}) - f(S_{k-1}) $$
   where $S_{k-1}$ is the set of splats selected in previous steps [S1, unofficial].
4. **Approximation Guarantee**: The greedy selection guarantees a uniform $(1 - 1/e)$ approximation bound for the submodular maximization problem [S1, unofficial].
5. **Streaming Ladder Construction**: Generate additive ladders by taking prefixes of the ordered set $S_k = \{g_{\pi(1)}, \dots, g_{\pi(k)}\}$. Each ladder rung contains all splats from previous rungs plus new high-priority splats [S1, unofficial].

**Edge Cases and Pitfalls**
- **Precision**: The AUC calculation must handle degenerate Gaussians (zero variance) carefully to avoid division by zero or infinite overlaps [S1, unofficial].
- **Memory**: Storing the full Gram matrix is $O(N^2)$, which is infeasible for large $N$. Sparse storage is required [S1, unofficial].
- **Order Sensitivity**: The greedy choice is myopic; while it guarantees $(1-1/e)$, it may not be globally optimal. However, this is the standard trade-off for submodular maximization [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Computing the Gram matrix is $O(N^2)$ in the worst case, but sparse storage reduces this. The greedy selection is $O(N^2)$ per step in naive implementation, but can be optimized. Overall construction is expensive, but streaming is $O(1)$ per splat.
- **Memory Complexity**: $O(N^2)$ for dense Gram, $O(K)$ for sparse Gram where $K$ is the number of significant interactions.
- **Performance**: Benchmarked on four real Luxar gsplat datasets [S1, unofficial]. The method enables efficient web visualization by reducing initial load times.
- **Strengths**: Guarantees visual quality via submodular optimization; additive nature simplifies streaming logic.
- **Limitations**: High initial computation cost for ordering; not suitable for real-time reordering of dynamic scenes.

## Background
The method originates from the Luxar project, which focuses on Gaussian splatting for microscopy and scalable interactive web visualization of multidimensional scientific data [S1, unofficial]. It was developed as a companion theory document to the main Luxar text, addressing the need for efficient streaming of large Gaussian datasets [S1, unofficial]. The approach leverages submodular optimization theory, specifically the greedy algorithm's approximation guarantee for monotone submodular functions, to solve the splat ordering problem [S1, unofficial].
