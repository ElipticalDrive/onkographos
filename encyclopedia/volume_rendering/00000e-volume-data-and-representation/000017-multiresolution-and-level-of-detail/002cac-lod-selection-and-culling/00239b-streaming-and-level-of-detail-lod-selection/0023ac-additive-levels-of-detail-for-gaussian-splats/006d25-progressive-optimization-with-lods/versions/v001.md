# Progressive Optimization with LODs

Also called: Progressive workspace optimization, Shardwise LOD optimization, PanoGS progressive refinement

## Overview
Progressive Optimization with LODs is a method for organizing and refining large-scale Gaussian splat scenes by maintaining a hierarchical workspace of three distinct detail levels: a low-resolution preview, a mid-resolution practical warm-start, and a high-resolution full-native set [S1]. It solves the problem of high GPU memory consumption and optimization instability when processing massive Gaussian datasets by allowing different stages of the pipeline to operate on subsets of the data proportional to their importance [S1]. Unlike standard single-pass optimization, this method builds additive ladders where each LOD preserves the distribution of the native seed set, enabling fast iterative previews without loading all primitives [S1]. It is distinct from [Additive levels of detail for Gaussian splats](3114-additive-levels-of-detail-for-gaussian-splats.md) by explicitly integrating ERP-aware differentiable rendering and shardwise processing into the optimization loop itself, rather than just managing static streaming assets.

## How it works
The method organizes Gaussian primitives into a progressive workspace and refines them using an ERP-aware differentiable renderer. The process involves data structure initialization, coordinate transformation, rendering, and staged parameter optimization.

### Inputs and Outputs
**Inputs:**
- Native Gaussian seed set (position, scale, rotation, color, opacity) distributed across shards.
- Camera poses for panoramic views.
- Target LOD configurations (Preview, Practical, Full-Native).

**Outputs:**
- Optimized Gaussian parameters for each LOD level.
- Packed `.splat` assets for web-based exploration.

### Data Structures
The workspace maintains three LOD tiers. Each tier stores a subset of the native Gaussians.
- **Preview LOD:** Up to 1,000,000 Gaussians [S1].
- **Practical Warm-Start LOD:** Up to 5,000,000 Gaussians [S1].
- **Full-Native LOD:** Contains all generated primitives [S1].

Sampling is performed proportionally across shards so that each LOD preserves the spatial distribution of the native seed set [S1].

### Coordinate Transformation (ERP-Aware)
The renderer maps 3D Gaussian centers to 2D Equirectangular Projection (ERP) coordinates. Given a Gaussian center $x_w$ in world coordinates and camera pose $(R_c, t_c)$:

1.  **World to Camera Frame:**
    $$ x_c = R_c (x_w - t_c) $$
    Where $x_c = [x_c, y_c, z_c]^T$ [S1].

2.  **Inverse Spherical Projection to ERP:**
    Calculate spherical coordinates from the camera-frame vector:
    $$ r = \|x_c\| $$
    $$ \theta = x_c / r $$
    $$ \phi = \arcsin(z_c / r) $$
    $$ \lambda = \text{atan2}(y_c, x_c) $$
    
    Map to normalized ERP coordinates $(u, v)$:
    $$ u = \frac{\lambda + \pi}{2\pi} - \frac{1}{2} $$
    $$ v = \frac{\phi + \pi/2}{\pi} $$
    
    **Boundary Handling:**
    - Horizontal coordinates ($u$) wrap around the panorama seam [S1].
    - Vertical coordinates ($v$) are clamped to the valid latitude range [S1].

### Rendering
Instead of hard rasterization, the renderer splats each Gaussian over a local soft footprint.
- **Footprint Size:** Proportional to the tangential scale divided by depth [S1].
- **Benefit:** Provides differentiable imagespace support and more stable gradients [S1].

### Optimization Stages
The optimization proceeds in stages, appending checkpoints to the workspace as additional LODs [S1].

1.  **Appearance Warm-Start:**
    - Geometry (centers) is fixed.
    - Only appearance-related parameters (color, opacity) are updated [S1].
    - This leverages the metrically meaningful lifted RGB-D geometry initialization [S1].

2.  **Optional Conservative Geometry Refinement:**
    - Gaussian centers are allowed to move.
    - **Constraints:**
        - Reduced learning rate.
        - Delayed activation.
        - Bounded displacement.
    - **Purpose:** Prevents photometric gradients from pulling primitives away from the high-resolution geometric initialization [S1].

3.  **Multiview Refinement:**
    - Supervision is restricted to nearby panoramas (neighbor-based strategy) [S1].
    - Avoids optimizing every view against every other view, which is crucial for sparse wide-baseline captures where distant panoramas share little valid support [S1].

4.  **Shardwise Optimization (Large Scenes):**
    - Subsets of the Gaussian scene are processed independently [S1].
    - Allows native-resolution assets to be refined under GPU memory constraints [S1].

### Pseudocode
```python
def progressive_optimization(native_gaussians, camera_poses, shards):
    """
    Organizes Gaussians into LODs and optimizes them using ERP-aware rendering.
    """
    # 1. Initialize Workspace LODs
    # Sample proportionally across shards to preserve distribution
    preview_lod = sample_gaussians(native_gaussians, shards, max_count=1_000_000)
    practical_lod = sample_gaussians(native_gaussians, shards, max_count=5_000_000)
    full_native_lod = native_gaussians
    
    workspace = {
        'preview': preview_lod,
        'practical': practical_lod,
        'full_native': full_native_lod
    }
    
    # 2. Stage 1: Appearance Warm-Start
    # Keep geometry fixed, optimize color and opacity
    for lod_name, lod_gaussians in workspace.items():
        optimize_appearance(lod_gaussians, camera_poses, renderer=erp_renderer)
        
    # 3. Stage 2: Conservative Geometry Refinement (Optional)
    # Allow centers to move with constraints
    for lod_name, lod_gaussians in workspace.items():
        optimize_geometry_conservative(
            lod_gaussians, 
            camera_poses, 
            renderer=erp_renderer,
            learning_rate=REDUCED_LR,
            activation_delay=DELAYED,
            max_displacement=BOUNDED
        )
        
    # 4. Stage 3: Multiview Refinement
    # Restrict supervision to nearby panoramas
    for lod_name, lod_gaussians in workspace.items():
        nearby_cameras = get_nearby_panoramas(camera_poses)
        optimize_multiview(lod_gaussians, nearby_cameras, renderer=erp_renderer)
        
    # 5. Stage 4: Shardwise Optimization (for Full Native if needed)
    # Process subsets independently to manage GPU memory
    for shard in shards:
        shard_gaussians = get_shard_gaussians(full_native_lod, shard)
        optimize_shard(shard_gaussians, camera_poses, renderer=erp_renderer)
        
    # 6. Export
    # Append optimized checkpoints as additional LODs
    for lod_name, lod_gaussians in workspace.items():
        export_splat(lod_gaussians, filename=f"{lod_name}.splat")
        
    return workspace

def erp_renderer(gaussian, camera_pose):
    """
    Renders a Gaussian using ERP-aware differentiable rasterization.
    """
    # Transform to camera frame
    x_c = rotate_translate(gaussian.center, camera_pose.R, camera_pose.t)
    
    # Inverse spherical projection
    r = norm(x_c)
    theta = x_c.x / r
    phi = arcsin(x_c.z / r)
    lambda_ = atan2(x_c.y, x_c.x)
    
    u = (lambda_ + PI) / (2 * PI) - 0.5
    v = (phi + PI / 2) / PI
    
    # Handle boundaries
    u = wrap_around_seam(u)
    v = clamp_latitude(v)
    
    # Soft footprint splatting
    footprint_size = gaussian.tangential_scale / depth(x_c)
    return splat_soft_footprint(u, v, footprint_size, gaussian.color, gaussian.opacity)
```

### Parameters
- **Preview LOD Limit:** 1,000,000 Gaussians [S1].
- **Practical Warm-Start LOD Limit:** 5,000,000 Gaussians [S1].
- **Learning Rate:** Reduced for geometry refinement [S1].
- **Footprint Size:** Proportional to tangential scale / depth [S1].

### Edge Cases and Pitfalls
- **Sparse Wide-Baseline Captures:** Using distant panoramas for supervision can introduce unstable visibility constraints. The method mitigates this by restricting supervision to nearby panoramas [S1].
- **Photometric Gradient Pull:** Unconstrained geometry optimization can pull primitives away from the high-resolution geometric initialization. Mitigated by bounded displacement and delayed activation [S1].
- **GPU Memory:** Full-native optimization on large scenes requires shardwise processing to avoid OOM errors [S1].

## Operating characteristics
- **Time Complexity:** Depends on the number of Gaussians in the active LOD and the number of views. Shardwise optimization allows parallel processing of subsets, reducing wall-clock time for large scenes by enabling concurrent refinement [S1].
- **Memory Complexity:** Linear with respect to the number of Gaussians in the current LOD. By using Preview (1M) and Practical (5M) LODs, memory usage is significantly lower than loading the full-native set during early optimization stages [S1].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales to large scenes via shardwise optimization, which processes subsets independently under GPU memory constraints [S1].
- **Strengths:**
    - Fast preview capabilities due to low-res LODs [S1].
    - Stable optimization by decoupling appearance and geometry refinement [S1].
    - Robust handling of sparse panoramic data via neighbor-based supervision [S1].
- **Limitations:**
    - Requires careful tuning of conservative geometry refinement parameters (learning rate, delay, bounds) [S1].
    - ERP projection introduces seam wrapping and latitude clamping artifacts if not handled correctly [S1].
- **When to use:** When optimizing large-scale Gaussian splat scenes from sparse panoramic inputs where GPU memory is limited and stable convergence is critical [S1].
- **When not to use:** For small scenes where full-native optimization fits in memory and rapid convergence is not hindered by photometric gradients [S1].

## Background
The method originates from **PanoGS** (PanoGS: Foundation-Depth-Guided High-Resolution Gaussian Splatting from Sparse Panoramic Images for Interactive Web3D Exploration), published in **2026** [S1]. It was developed to address the challenges of interactive web-based exploration of high-resolution Gaussian splats derived from sparse panoramic inputs. The key innovation is the integration of a progressive workspace with three LODs and an ERP-aware differentiable renderer, allowing for efficient optimization and export of web-friendly splat assets [S1].
