# Far Voxels


## Overview
Far Voxels is a hierarchical level-of-detail (HLOD) technique for visualizing massive 3D models, particularly CAD data with hundreds of millions of triangles, by replacing distant geometry with coarse voxel representations [S1]. It solves the performance bottleneck of rendering large-scale scenes by leveraging culling, occlusion, and out-of-core storage to maintain interactive frame rates [S1]. Unlike sibling methods that often rely on spatial partitioning of the volume domain or frequency-domain transforms, Far Voxels constructs a hierarchy based on surface-area heuristics and generates view-dependent shader models during a preprocessing phase to approximate surface appearance from a distance [S1].

## How it works
The method operates in two distinct phases: a preprocessing phase that builds the hierarchy and generates voxel shaders, and a visualization phase that traverses the hierarchy to render the model.

### Inputs and Outputs
*   **Input:** A massive triangle mesh (e.g., CAD model).
*   **Output:** A data file containing an HLOD hierarchy and voxel/triangle data, and a rendered image at interactive rates.

### Data Structures
The generated data file is divided into two parts [S1]:
1.  **HLOD Hierarchy:** Contains traversal information. Nodes are organized in a tree structure.
2.  **Model Representation Data:**
    *   **Internal Nodes:** Lists of voxels.
    *   **Leaf Nodes:** Lists of triangles or triangle-strips.

**Voxel Shader Models:**
Each voxel stores one of two shader types, selected based on surface complexity [S1]:
*   **Type 1 (Flat Surfaces):** Parameterized by a single normal vector $\mathbf{n}$ and two materials ($M_1, M_2$), one for each primary viewing direction.
*   **Type 2 (Complex Surfaces):** Composed of 6 materials ($M_{\pm x}, M_{\pm y}, M_{\pm z}$) and 6 normals ($\mathbf{n}_{\pm x}, \mathbf{n}_{\pm y}, \mathbf{n}_{\pm z}$), each associated with one of the main viewing directions ($\pm x, \pm y, \pm z$).

### Preprocessing Phase
1.  **Hierarchy Construction:**
    *   Start with all triangles of the model at the root node [S1].
    *   Recursively subdivide the node using axis-aligned planes positioned according to the surface-area heuristic [S1].
    *   Split existing triangles between the two new child nodes.
    *   Terminate subdivision when a node contains fewer than a predefined threshold of triangles; this node becomes a leaf [S1].

2.  **Voxel Generation (for Internal Nodes):**
    *   Define a sampling volume $V$ corresponding to the region of the node [S1].
    *   Define a surface $S$ surrounding $V$. The distance $d_{min}$ from $S$ to $V$ is set to the minimum distance from which the voxel representation is intended to be used [S1].
    *   Assume the viewer is always outside $S$; objects inside $S$ act as occluders for the sampling rays [S1].
    *   Use a CPU-based raytracer to shoot rays from surface $S$ into volume $V$ to sample visible surfaces [S1].
    *   **Environmental Occlusion:** Discard voxels corresponding to surfaces never hit by sampling rays, as these surfaces are assumed to be hidden from external views [S1]. This can discard 25–57% of voxels [S1].
    *   For hit voxels, analyze the radiance (color) and geometry from all sampled directions [S1].
    *   Select the appropriate shader model (Type 1 or Type 2) based on the criterion that the voxel should project to approximately one pixel at distance $d_{min}$ [S1].
    *   Store the selected materials and normals for each voxel [S1].

### Visualization Phase
1.  **Traversal:**
    *   Traverse the HLOD hierarchy starting from the root [S1].
    *   For each node, decide whether to render its voxel representation or traverse its children for higher precision [S1].
    *   The decision is based on a user-defined parameter: the maximum projected size of a voxel on the screen [S1].
    *   Descend the hierarchy until voxels are smaller than the desired projected size or a leaf node is reached [S1].

2.  **Occlusion Culling:**
    *   Test branches of the hierarchy for occlusion using Hardware Occlusion Queries [S1].
    *   Skip drawing hidden parts of the model [S1].

3.  **Rendering:**
    *   For each voxel node, bind the appropriate vertex shader (Type 1 or Type 2) [S1].
    *   Pass additional parameters (materials, normals) using VertexAttributes [S1].
    *   Draw all voxels in the node with a single call to `glDrawArrays` [S1].
    *   For leaf nodes, render the stored triangles/triangle-strips directly [S1].

### Interpolation
When viewing a Type 2 voxel from an intermediate direction, the material and normal are interpolated from the nearest viewing directions weighted by their respective direction cosines [S1].

### Pseudocode

```python
# Preprocessing Phase
def preprocess(model_triangles):
    # 1. Build HLOD Hierarchy
    root = Node(triangles=model_triangles)
    queue = [root]
    
    while queue:
        node = queue.pop(0)
        if node.triangle_count < PREDEFINED_THRESHOLD:
            node.is_leaf = True
            continue
        
        # Subdivide using surface-area heuristic
        plane = compute_surface_area_heuristic_plane(node.bounding_box)
        left_triangles, right_triangles = split_triangles(node.triangles, plane)
        
        left_child = Node(triangles=left_triangles, parent=node)
        right_child = Node(triangles=right_triangles, parent=node)
        node.children = [left_child, right_child]
        
        queue.append(left_child)
        queue.append(right_child)

    # 2. Generate Voxels for Internal Nodes
    for node in get_internal_nodes(root):
        volume_V = node.bounding_box
        # d_min is the minimum distance for which this LOD is valid
        d_min = compute_min_viewing_distance(node)
        surface_S = expand_bounding_box(volume_V, d_min)
        
        # Sample visible surfaces using CPU raytracer
        # Rays originate from surface_S into volume_V
        hit_data = raytrace_surfaces(surface_S, volume_V, model_triangles)
        
        # Environmental Occlusion: discard voxels with no hits
        hit_voxels = filter_by_hits(volume_V, hit_data)
        
        for voxel in hit_voxels:
            # Analyze radiance and geometry from all hit directions
            directions = get_hit_directions(voxel, hit_data)
            
            # Select shader model based on projected size ~ 1 pixel at d_min
            if is_flat_surface(voxel, directions):
                # Type 1: Single normal, two materials
                voxel.normal = compute_average_normal(directions)
                voxel.materials = [get_material(directions[0]), get_material(directions[1])]
                voxel.shader_type = 1
            else:
                # Type 2: 6 materials, 6 normals for +/- x, y, z
                voxel.materials = [get_material(dir) for dir in MAIN_DIRECTIONS]
                voxel.normals = [compute_normal(dir) for dir in MAIN_DIRECTIONS]
                voxel.shader_type = 2
            
            store_voxel_data(voxel)

# Visualization Phase
def visualize(camera_position, camera_frustum):
    render_queue = []
    traverse(root, camera_position, camera_frustum, render_queue)
    
    for node in render_queue:
        if node.is_leaf:
            # Render triangles directly
            draw_triangles(node.triangles)
        else:
            # Determine shader type based on dominant voxel type in node
            # Bind appropriate vertex shader
            shader = get_shader(node.voxel_type)
            
            # Pass parameters via VertexAttributes
            set_vertex_attributes(node.voxels)
            
            # Draw all voxels in a single call
            draw_arrays(node.voxels, shader)

def traverse(node, camera_pos, frustum, queue):
    # 1. Occlusion Culling
    if not is_visible(node.bounding_box, camera_pos, frustum):
        return
    
    # 2. LOD Decision
    projected_size = compute_projected_size(node.voxel_size, camera_pos)
    
    if projected_size > MAX_PROJECTED_SIZE and not node.is_leaf:
        # Traverse children for higher precision
        for child in node.children:
            traverse(child, camera_pos, frustum, queue)
    else:
        # Use current node's representation
        queue.append(node)
```

### Edge Cases and Pitfalls
*   **Aliasing:** Thin objects represented as voxels create representations larger than the original geometry, causing popping artifacts during LOD transitions [S1]. This is a severe alias problem in the original algorithm [S1].
*   **Temporal Aliasing:** The distortion caused by voxelizing thin objects is aggravated during model navigation, causing objects to seem to move between consecutive frames [S1].

## Operating characteristics
*   **Time Complexity:** Preprocessing is expensive due to CPU-based raytracing and hierarchy construction. Visualization is efficient, relying on single draw calls per node and hardware occlusion queries [S1].
*   **Memory Complexity:** Depends on the number of voxels and the hierarchy depth. Environmental occlusion reduces voxel count by 25–57% [S1].
*   **Performance:** Yields interactive rates for large datasets (hundreds of millions of triangles) by handling levels of detail, culling, and out-of-core storage [S1].
*   **Strengths:** Effective for massive models; reduces draw calls; handles occlusion well.
*   **Limitations:** Severe aliasing artifacts for thin/small objects; preprocessing time; view-dependent shader complexity [S1].
*   **When to use:** Large-scale CAD visualization where interactive frame rates are required and objects are generally not extremely thin.
*   **When not to use:** Scenes with many thin structures where visual fidelity during LOD transitions is critical without additional anti-aliasing techniques [S1].

## Background
The Far Voxels algorithm was introduced in the paper "An Anti-aliasing Technique for Voxel-Based Massive Model Visualization Strategies" [S1]. It addresses the challenges of visualizing CAD models in engineering activities, where model sizes can easily reach hundreds of millions of triangles [S1]. The method builds on the concept of using voxels to create coarse representations of sub-models to yield interactive rates [S1].
