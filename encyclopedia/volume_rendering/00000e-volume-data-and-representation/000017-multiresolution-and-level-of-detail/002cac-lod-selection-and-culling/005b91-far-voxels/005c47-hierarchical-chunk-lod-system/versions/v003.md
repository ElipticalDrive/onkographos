# Hierarchical Chunk LOD System

Also called: Octree-based Chunk LOD, Recursive Chunk LOD

## Overview
A recursive Level of Detail (LOD) system using octree-like chunk subdivision to maintain a consistent surface approximation across different distances [S1, unofficial]. It splits chunks into 8 children when close to the viewer and merges them when far away [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Viewer position ($P_{view}$), maximum LOD depth ($L_{max}$), view distance radius ($R_{view}$), base chunk size ($S_{base}$), and density data [S1, unofficial].
*   **Output:** A set of active `Chunk` objects, each containing a generated mesh and collider, forming the visible terrain [G].

**Data Structures:**
The core structure is the `Chunk` object [S1, unofficial].
*   `position`: `Vector3Int` representing the chunk's grid coordinates [S1, unofficial].
*   `mesh`: Reference to the generated `Mesh` object [S1, unofficial].
*   `dirty`: `bool`. Flag indicating if the mesh needs regeneration [S1, unofficial].
*   `densities`: `float[]`. Array of density values for the chunk's voxel grid [S1, unofficial].
*   `lod`: `int`. Current Level of Detail index [S1, unofficial].
*   `size`: `int`. The side length of the chunk in voxels [S1, unofficial].
*   `children`: `Chunk[8]`. Array of 8 child chunks (null if leaf) [S1, unofficial].
*   `transform`: Unity `Transform` component for spatial hierarchy [S1, unofficial].

**Parameters:**
*   `levelsOfDetail` ($L_{max}$): Maximum depth of the LOD hierarchy. Range: $[0, 9]$. Typical value: 4 [S1, unofficial].
*   `viewDistance` ($R_{view}$): Radius within which chunks are considered for splitting. Typical value: 500 [S1, unofficial].
*   `chunkSize` ($S_{base}$): Size of the finest detail chunk. Range: $[2, 64]$. Typical value: 2 [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    Create root chunks at positions $(x, y, z) \times (S_{base} \ll L_{max})$ [S1, unofficial].
    Set each root chunk's `lod` = $L_{max}$ and `size` = $S_{base} \ll L_{max}$ [S1, unofficial].
    Set `dirty` = true for all new chunks [S1, unofficial].

2.  **Update Loop (per frame or per viewer movement):**
    For each active chunk $C$:
    a.  **View Check:** If $C$ is outside the view distance $R_{view}$ from $P_{view}$, mark it for potential removal or ignore [S1, unofficial].
    b.  **Split Condition:** If $C$ is inside $R_{view}$ AND $C.lod > 0$:
        i.  Call `Split(C)`.
    c.  **Merge Condition:** If $C$ is outside $R_{view}$ AND $C.lod < L_{max}$ AND $C$ has children:
        i.  Call `Merge(C)`.
    d.  **Dirty Check:** If $C.dirty$ is true:
        i.  Generate mesh from `densities` using Marching Cubes or similar algorithm [G].
        ii. Set $C.dirty$ = false.

3.  **Split Operation:**
    a.  If $C.children$ is null, allocate `Chunk[8]` [S1, unofficial].
    b.  Calculate `childSize` = $C.size / 2$ [S1, unofficial].
    c.  For each of the 8 octants $i \in [0, 7]$:
        i.  Create new `Chunk` child $C_i$.
        ii. Set $C_i.size$ = `childSize` [S1, unofficial].
        iii. Set $C_i.lod$ = $C.lod - 1$ [S1, unofficial].
        iv. Set $C_i.position$ = $C.position + \text{offset}_i$, where $\text{offset}_i$ is $(\pm \text{childSize}/2, \pm \text{childSize}/2, \pm \text{childSize}/2)$ based on octant index [S1, unofficial].
        v.  Initialize $C_i$ with same material and collider settings as $C$ [S1, unofficial].
        vi. Set $C_i.dirty$ = true.
    d.  Set $C.dirty$ = false (since children will handle their own generation) [S1, unofficial].
    e.  Recursively call `RequestUpdateChunk` on all children to ensure they are processed [S1, unofficial].

4.  **Merge Operation:**
    a.  Recursively merge all children of $C$ [S1, unofficial].
    b.  Destroy child objects [S1, unofficial].
    c.  Set $C.children$ = null [S1, unofficial].
    d.  Set $C.dirty$ = true (to regenerate mesh at current LOD) [S1, unofficial].

**Pseudocode:**

```python
class Chunk:
    def __init__(self, position, lod, size, levels_of_detail):
        self.position = position
        self.lod = lod
        self.size = size
        self.levels_of_detail = levels_of_detail
        self.children = None
        self.dirty = True
        self.mesh = None
        self.densities = None
        self.material = None
        self.has_collider = False

    def split(self):
        if self.children is not None:
            return
        child_size = self.size // 2
        self.children = [None] * 8
        child_half = child_size // 2
        for i in range(8):
            ox = (i & 1) * child_half
            oy = ((i >> 1) & 1) * child_half
            oz = ((i >> 2) & 1) * child_half
            child_pos = (self.position.x + ox, self.position.y + oy, self.position.z + oz)
            child = Chunk(child_pos, self.lod - 1, child_size, self.levels_of_detail)
            child.material = self.material
            child.has_collider = self.has_collider
            self.children[i] = child
        self.dirty = False

    def merge(self):
        if self.children is None:
            return
        for child in self.children:
            if child is not None:
                child.merge()
                child.destroy()
        self.children = None
        self.dirty = True

    def update(self, viewer_pos, view_distance):
        if not self.is_within_view(viewer_pos, view_distance):
            if self.lod < self.levels_of_detail and self.children is not None:
                self.merge()
            return

        if self.lod > 0:
            self.split()
            for child in self.children:
                if child is not None:
                    child.update(viewer_pos, view_distance)
            return

        if self.dirty:
            self.generate_mesh()
            self.dirty = False

    def is_within_view(self, viewer_pos, radius):
        half_length = self.size / 2.0
        if (viewer_pos.x - radius > self.position.x + half_length or
            viewer_pos.x + radius < self.position.x - half_length or
            viewer_pos.y - radius > self.position.y + half_length or
            viewer_pos.y + radius < self.position.y - half_length or
            viewer_pos.z - radius > self.position.z + half_length or
            viewer_pos.z + radius < self.position.z - half_length):
```

**Edge Cases and Pitfalls:**
*   **Dirty Flag:** A chunk is only processed for mesh generation if `chunk.dirty` is true. Splitting or merging sets `dirty` to true. Initial creation sets `dirty` to true [S1, unofficial].
*   **Recursion Depth:** The system is described as "very recursive-based," which may lead to inefficiency or complexity compared to iterative approaches [S1, unofficial].
*   **Precision:** Floating-point precision issues may arise with large world coordinates. Using integer grid positions (`Vector3Int`) helps mitigate this [G].
*   **Boundary Conditions:** Ensure density data is available for all chunks, including those at the edge of the world [G].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of active chunks. Splitting and merging are $O(1)$ per chunk, but recursive updates can propagate [G].
*   **Memory Complexity:** $O(N)$ for active chunks. Hidden chunks consume minimal memory [G].
*   **Performance:** Interactive rates are achieved by only rendering visible chunks at appropriate LODs [S1, unofficial]. However, the CPU-based job approach is not implemented correctly in the source, leading to high CPU usage [S1, unofficial].
*   **Strengths:** Dynamic LOD, consistent surface approximation, efficient culling [S1, unofficial].
*   **Limitations:** High CPU usage due to recursion and lack of optimized job system. Lack of textures requires a triplanar shader or similar workaround [S1, unofficial].

## Background
Originated in the `tcgj/terrain-generator` project, written in Unity 2019.2.15f1 [S1, unofficial]. It builds on Marching Cubes algorithms [S1, unofficial]. The author notes potential inefficiencies in the recursive logic [S1, unofficial].
