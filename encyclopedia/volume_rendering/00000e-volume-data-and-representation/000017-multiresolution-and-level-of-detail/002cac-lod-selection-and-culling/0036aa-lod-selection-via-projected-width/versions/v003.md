# LoD Selection via Projected Width

Also called: PathTracer MipMap selection

## Overview
This method selects the appropriate resolution level for volume rendering by calculating the screen-space footprint (projected width) of the data elements, analogous to Mipmap selection in path tracing [S1]. It solves the problem of static LOD allocation by adapting resolution to view-dependent importance, ensuring that distant or small features use simplified representations while close features retain high detail [S1]. Unlike distance-based methods which rely on Euclidean distance from the camera, this approach uses the actual projected size on the image plane, providing a more accurate representation of visual significance for complex microgeometry like vegetation and hair [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A hierarchy of pre-computed volume representations (one per LOD level), camera parameters (position, orientation, field of view), and the geometric bounds of the volume data.
*   **Outputs:** A selected LOD index for each rendering sample or voxel lookup.

**Data Structures:**
The method assumes a set of $L$ volume levels, indexed $0$ (highest resolution) to $L-1$ (lowest resolution). Each level $l$ has a resolution $N_l$. The geometric extent of the volume is known in world space.

**Steps:**
1.  **Load Volumes:** Load all $L$ LOD volumes into memory simultaneously [S1].
2.  **Calculate Projected Width:** For a given voxel or sample point at world position $\mathbf{p}$, calculate its projected size on the image plane. This is typically derived from the voxel's world-space size and the camera's projection matrix. Let $w_{world}$ be the physical width of the voxel. The projected width $w_{screen}$ in pixels is:
    $$ w_{screen} = \frac{w_{world} \cdot f \cdot \text{pixel\_density}}{d} $$
    where $f$ is the focal length, $d$ is the distance from the camera to $\mathbf{p}$, and $\text{pixel\_density}$ relates to the image resolution [S1, G].
3.  **Determine LOD Level:** Compare $w_{screen}$ against predefined thresholds or a target pixel coverage. The LOD level $l$ is chosen such that the voxel's projected size matches the desired sampling rate for that level. This follows the "usual PathTracer MipMap selection" logic [S1].
4.  **Lookup Data:** Use the selected LOD level $l$ to access the corresponding volume data for the voxel value [S1].

**Pseudocode:**
```python
def select_lod_level(projected_width_pixels, target_coverage_pixels, num_levels):
    """
    Selects the LOD level based on projected width.
    :param projected_width_pixels: The size of the voxel in screen pixels.
    :param target_coverage_pixels: The desired screen coverage for the highest resolution level.
    :param num_levels: Total number of LOD levels.
    :return: Selected LOD index (0 is highest res).
    """
    # Calculate the ratio of current projected width to target coverage
    # Higher ratio means the voxel is larger on screen, requiring higher detail
    ratio = projected_width_pixels / target_coverage_pixels
    
    # Map ratio to LOD level
    # Level 0 is highest detail (largest projected size)
    # Level N is lowest detail (smallest projected size)
    # Assuming geometric progression in resolution levels
    
    if ratio < 1.0:
        return num_levels - 1
    
    # Logarithmic mapping to find the appropriate level
    # This assumes each level halves the resolution (doubles the voxel size)
    # level = log2(ratio)
    # Clamp to valid range
    import math
    level = int(math.log2(ratio))
    
    # Clamp to [0, num_levels - 1]
    level = max(0, min(level, num_levels - 1))
    
    return level

def render_voxel_with_lod(voxel_world_pos, voxel_world_size, camera, volumes):
    """
    Renders a single voxel using LOD selection via projected width.
    :param voxel_world_pos: World position of the voxel center.
    :param voxel_world_size: Physical size of the voxel.
    :param camera: Camera object with projection matrix and resolution.
    :param volumes: List of volume data structures, one per LOD level.
    :return: Rendered color/value.
    """
    # Step 1: Calculate projected width in pixels
    # Project voxel center to screen space
    screen_pos = camera.project(voxel_world_pos)
    
    # Calculate distance from camera
    dist = camera.distance_to(voxel_world_pos)
    
    # Estimate projected size based on focal length and distance
    # Simplified model: size_screen = (size_world * focal_length) / distance
    # Adjust for pixel density
    focal_length = camera.focal_length
    pixel_density = camera.resolution / camera.fov # pixels per unit angle
    
    projected_width = (voxel_world_size * focal_length * pixel_density) / dist
    
    # Step 2: Select LOD level
    # Assume target coverage for level 0 is 1 pixel (or a specific threshold)
    target_coverage = 1.0 
    lod_index = select_lod_level(projected_width, target_coverage, len(volumes))
    
    # Step 3: Lookup data from the selected volume
    volume_data = volumes[lod_index]
    voxel_value = volume_data.lookup(voxel_world_pos)
    
    return voxel_value
```

**Parameters:**
*   **Target Coverage:** The screen-space size (in pixels) that corresponds to the highest resolution level (LOD 0). Not given in the sources [S1].
*   **Number of Levels:** Determined by the user based on GPU memory and input sparsity [S1].

**Edge Cases and Pitfalls:**
*   **Out of Memory:** Combining high resolution with a high number of samples can lead to out-of-memory errors. Users must balance resolution and sample count [S1].
*   **Degenerate Input:** If the projected width is extremely small (very distant), the method should select the lowest LOD level. If extremely large (very close), it should select the highest. Clamping is necessary [G].

## Subtopics

## Operating characteristics
*   **Time Complexity:** LOD selection is $O(1)$ per voxel/sample, involving basic arithmetic and a logarithmic lookup.
*   **Memory Complexity:** Requires loading all LOD levels into memory simultaneously, which can be significant for large volumes [S1].
*   **Strengths:** View-dependent and accurate for microgeometry (vegetation, hair) where distance alone is insufficient [S1].
*   **Limitations:** Memory usage scales with the number of LOD levels. Requires pre-computation of all LODs [S1].

## Background
This method is used in the context of fast voxelization and level of detail for microgeometry rendering, specifically for rendering vegetation and hair models which are difficult to represent accurately with static LOD [S1]. It adapts the Mipmap selection strategy from path tracing to volume rendering [S1].
