# LoD Selection via Projected Width

Also called: PathTracer MipMap selection

## Overview
LoD Selection via Projected Width determines the appropriate resolution level for volume rendering by calculating the screen-space footprint of the data, analogous to Mipmap selection in path tracing [S1]. It solves the problem of static LOD allocation by adapting resolution to view-dependent importance based on geometric projection rather than Euclidean distance [S1]. Unlike [Distance-Based Level Selection](14162-distance-based-level-selection.md), which uses camera-to-voxel distance, this method relies on the projected width on the camera plane to balance rendering cost and visual fidelity [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A hierarchy of pre-computed LoD volumes (one per level), camera parameters (projection matrix, viewport dimensions), and the spatial bounds of the volume data.
*   **Outputs:** A selected LoD index for each rendering sample or voxel lookup.

**Data Structures:**
The method assumes a set of $L$ volume levels, where level $l \in [0, L-1]$ has resolution $N_l$. The volumes are loaded simultaneously into memory [S1].

**Steps:**
1.  **Compute Projected Width:** For a voxel or sample at world position $\mathbf{p}$, project it to screen space using the camera's projection matrix $\mathbf{P}$ and viewport dimensions $W, H$.
2.  **Calculate Metric:** Determine the projected width $w_{proj}$ of the voxel's extent on the screen. This is typically derived from the derivative of the screen-space coordinates with respect to world space, or the difference in screen coordinates between adjacent voxels.
3.  **Select Level:** Map the projected width $w_{proj}$ to a LoD index $l$. The selection follows the standard PathTracer MipMap selection logic [S1], where larger projected widths (closer objects) select higher resolution levels (lower indices), and smaller widths select lower resolution levels (higher indices).

**Formula:**
Let $\mathbf{p}_{screen} = \text{Project}(\mathbf{p})$. The projected width $w_{proj}$ can be approximated by the magnitude of the gradient of the screen-space position with respect to the world-space voxel size $s$:
$$ w_{proj} \approx \left\| \frac{\partial \mathbf{p}_{screen}}{\partial \mathbf{p}} \right\| \cdot s $$
The LoD index $l$ is chosen such that the texel size at level $l$ matches the projected width.

**Pseudocode:**
```python
def select_lod(projected_width, lod_levels):
    """
    Selects the LoD index based on projected width.
    projected_width: float, the screen-space size of the voxel.
    lod_levels: list of floats, the texel size (or inverse resolution) for each LoD level.
    Returns: int, the selected LoD index.
    """
    # Find the first level where the texel size is smaller than or equal to the projected width
    # This mimics standard Mipmap selection where we want the smallest texture that covers the pixel
    for l, texel_size in enumerate(lod_levels):
        if texel_size <= projected_width:
            return l
    # If no level is fine enough, return the highest resolution (index 0)
    return 0
```

**Parameters:**
*   **First level resolution:** Controls the highest detail level.
*   **Second level resolution:** Controls the next detail level.
*   **Sample number:** Number of samples per pixel.
*   *Note:* Combining high resolution with a high sample number can lead to out-of-memory problems [S1].

**Edge Cases:**
*   **Out of Memory:** Users must balance resolution and sample count to avoid GPU memory exhaustion [S1].
*   **Degenerate Input:** If the projected width is extremely small (very distant), the method selects the coarsest level. If extremely large (very close), it selects the finest.

## Subtopics

### [Distance-Based Level Selection](14162-distance-based-level-selection.md)
Uses Euclidean distance from the camera to select octree levels, providing a view-dependent hierarchy that balances rendering cost and visual fidelity.

## Operating characteristics
*   **Time Complexity:** Selection is $O(1)$ per voxel/sample after pre-computing the projected width.
*   **Memory Complexity:** Requires loading all LoD volumes simultaneously into memory [S1]. This can lead to out-of-memory issues if the number of samples and resolution are too high [S1].
*   **Strengths:** View-dependent adaptation based on screen-space footprint ensures consistent visual quality regardless of camera orientation or distance.
*   **Limitations:** Memory usage scales with the number of LoD levels and their resolutions. Requires pre-computation of all LoD levels.
*   **When to use:** When screen-space consistency is critical and sufficient GPU memory is available.
*   **When not to use:** When memory is constrained or when distance-based culling is sufficient for the scene.

## Background
This method is derived from the PathTracer MipMap selection technique [S1]. It was applied to voxelized and rendered vegetation and hair models, which are known for their difficulty in accurate Level of Detail representation [S1]. The approach exposes three main parameters to the user: first level resolution, second level resolution, and sample number [S1].
