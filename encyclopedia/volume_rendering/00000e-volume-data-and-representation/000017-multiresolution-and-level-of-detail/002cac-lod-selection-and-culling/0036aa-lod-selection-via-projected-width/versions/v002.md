# LoD Selection via Projected Width

Also called: PathTracer MipMap selection

## Overview
LoD Selection via Projected Width determines the appropriate resolution level for volume rendering by calculating the screen-space footprint of the data. It solves the problem of selecting the correct Mipmap level for sparse or microgeometry data (such as vegetation or hair) by mapping the projected width of the volume element to a discrete LoD index [S1]. Unlike distance-based selection, which relies on Euclidean camera-to-anchor distance, this method uses the actual projected size on the image plane to ensure consistent visual quality regardless of scene scale [S1, S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Camera parameters (projection matrix, view matrix, resolution), volume hierarchy metadata (bounding box or anchor position and size), and the set of available LoD volumes.
*   **Output:** An integer LoD index $L$ for each voxel or anchor point, used to select the data source.

**Data Structures:**
The method assumes a hierarchy of volumes is loaded simultaneously, one per LoD level [S1]. Each level $L$ has a specific resolution. The selection logic requires the projected width of the voxel/anchor in screen space.

**Steps:**
1.  **Compute Projected Width:** Calculate the width of the voxel or anchor point in screen space (pixels). This involves projecting the spatial extent of the volume element onto the image plane using the camera's projection matrix. Let $w_{screen}$ be this width in pixels.
2.  **Determine Required LoD:** Map $w_{screen}$ to a discrete LoD index $L$. The mapping follows the "usual PathTracer MipMap selection" logic [S1]. Typically, this involves comparing $w_{screen}$ against thresholds defined by the resolution of each LoD level. A common formulation for Mipmap selection is:
    $$ L = \max(0, \min(L_{max}, \lfloor \log_2(\frac{w_{screen}}{w_{base}}) \rfloor)) $$
    where $w_{base}$ is the reference width (e.g., 1 pixel or the width at the finest resolution) and $L_{max}$ is the maximum available LoD level [G]. The source explicitly states the metric is based on "projected width on camera" [S1].
3.  **Select Volume:** For each voxel, lookup the data from the volume corresponding to index $L$ [S1].

## Subtopics

## Operating characteristics
*   **Complexity:** The selection is $O(1)$ per voxel/anchor after projection. Loading multiple volumes increases memory usage linearly with the number of LoD levels [S1].
*   **Performance:** The method allows simultaneous loading of multiple LoD volumes [S1]. Performance is constrained by GPU memory when high resolutions and sample counts are combined [S1].
*   **Strengths:** Effective for microgeometry (vegetation, hair) where distance-based methods may fail to capture screen-space detail [S1].
*   **Limitations:** Requires careful tuning of resolution parameters to balance quality and memory [S1].

## Background
This method is used in the context of fast voxelization and level of detail for microgeometry rendering, specifically for rendering vegetation and hair models [S1]. It builds on the concept of PathTracer MipMap selection [S1].
