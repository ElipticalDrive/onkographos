# Choosing Alternative Resolutions

Also called: Choosing an alternate resolution given a node’s bitmap, Finding Lower Resolution Levels

## Overview
This method selects a cache-resident resolution level for a volume rendering brick when the desired resolution is not available in memory [S1, unofficial]. It leverages a bitmap of partially mapped resolutions stored in each residency-octree node to efficiently identify candidate levels without random searching [S1, unofficial]. The approach prioritizes lower resolutions before attempting higher ones, iterating through candidates until a mapped page is found or all options are exhausted [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** `node.bitmap` (a bitmask where each bit $i$ indicates if resolution level $i$ is partially mapped in the node) and `resolutionLevel` (the index of the desired, currently unmapped resolution) [S1, unofficial].
*   **Output:** The index of a resolution level that is both partially mapped in the node and cache-resident for the current ray, or `NONE` if no such level exists [S1, unofficial].

**Data Structures:**
*   **Resolution Ordering:** Resolution levels are indexed from $0$ (highest resolution) to $k$ (lowest resolution) [S1, unofficial].
*   **Bitmap:** An integer or bit-vector where the $i$-th bit corresponds to resolution level $i$ [S1, unofficial].

**Algorithm Steps:**
1.  **Attempt Lower Resolutions:** Compute the next candidate resolution by calling `nextLower(node.bitmap, resolutionLevel)` [S1, unofficial]. Retrieve the page for this resolution using `getPage(node, ray, resolutionLevel)` [S1, unofficial]. While the candidate resolution is valid (`!= NONE`) and the page is unmapped (`page.unmapped` is true), update the candidate to the next lower resolution and retrieve the new page [S1, unofficial]. If the loop terminates because `page.unmapped` is false, the current `nextResolution` is the result [S1, unofficial].
2.  **Attempt Higher Resolutions (if lower failed):** If the previous step resulted in an unmapped page, compute the next candidate resolution by calling `nextHigher(node.bitmap, resolutionLevel)` [S1, unofficial]. Retrieve the page for this resolution [S1, unofficial]. While the candidate resolution is valid and the page is unmapped, update the candidate to the next higher resolution and retrieve the new page [S1, unofficial]. If the loop terminates because `page.unmapped` is false, the current `nextResolution` is the result [S1, unofficial]. If no valid resolution is found, return `NONE` [S1, unofficial].

**Helper Functions:**
*   `nextLower(partiallyMapped, resolution)`: Compute a mask of all resolution levels strictly lower than `resolution` using `getLowerResolutionsMask(resolution)`, which returns a constant mask with bits set for all indices $j > resolution$ [S1, unofficial]. Compute `lower = partiallyMapped & getLowerResolutionsMask(resolution)` to isolate bits for resolutions that are both partially mapped and lower than the current level [S1, unofficial]. If `lower == 0`, return `NONE` [S1, unofficial]. Return the index of the first trailing one-bit of `lower` [S1, unofficial]. Since resolution $0$ is highest and $k$ is lowest, the least significant bit set corresponds to the next lower resolution in terms of detail (coarser) [S1, unofficial]. If `firstTrailingBit` is unavailable, compute the index as the number of consecutive trailing zero-bits from the least significant bit (LSB) [S1, unofficial].
*   `nextHigher(partiallyMapped, resolution)`: Similar to `nextLower`, but uses `getHigherResolutionsMask(resolution)` to mask bits for indices $j < resolution$ [S1, unofficial]. The result is the index of the first trailing one-bit of the masked value, which corresponds to the next higher resolution (finer) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **No Mapped Resolutions:** If the bitmap is zero or no bits correspond to valid resolutions relative to the current level, the function returns `NONE` [S1, unofficial].

## Subtopics

### Screen-Space Adaptive Resolution
Techniques that adaptively render depending on screen resolution, rendering display-aware resolutions potentially lower than data resolution to reduce computation and texture memory requirements [S2, unofficial]. Deeper level values (higher resolution) are used for areas closer to regions of interest and lower resolution for other areas [S2, unofficial].

### Multiresolution AMR Rendering for Interactivity
To render lower-resolution approximations, some of the more refined levels are ignored during grid homogenization, as coarser-resolution cells overlaid by finer-resolution cells contain valid data, gracefully decreasing image quality and rendering time [S3, unofficial]. Image resolution is reduced during interaction and enlarged using OpenGL’s pixel zoom feature [S3, unofficial]. Two user-adjustable settings control the resolution level for rendering still images and the resolution level for rendering transient images during interactive viewpoint changes [S3, unofficial]. Combining these techniques achieves interactive rendering rates of at least five frames per second for all tested data sets [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The bitmap operations (`AND`, `firstTrailingBit`) are $O(1)$ or $O(\log k)$ depending on implementation [S1, unofficial]. The iteration depends on the number of unmapped resolutions, which is typically small [S1, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space per node, as it relies on the existing bitmap [S1, unofficial].
*   **Strengths:** Efficiently finds a suitable resolution without searching all levels and uses existing residency information [S1, unofficial].
*   **Limitations:** May still fail if no resolution is mapped for the specific ray sample [S1, unofficial]. The strategy of trying lower then higher is arbitrary; other strategies (higher then lower, alternating, closest) exist [S1, unofficial].

## Background
This method is part of mixed-resolution multi-volume rendering, specifically within the context of residency-octrees and cache-aware rendering [S1, unofficial]. It was described in the work by Faludi et al. [S1, unofficial].
