# Finding Higher Resolution Levels

Also called: Choosing a higher resolution given a node’s bitmap

## Overview
This method finds the next higher resolution level for a residency octree node given its current resolution index and a bitmap of partially mapped resolutions [S1, unofficial]. It advances the traversal depth by selecting the finest available resolution from the bitmap using bitwise operations [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   `partiallyMapped`: A bitmask where the $j$-th bit is set if the node is partially mapped in resolution level $j$ [S1, unofficial].
*   `resolution`: The integer index of the resolution level last tested [S1, unofficial].
*   **Output**: The index of the next higher resolution level, or `NONE` if no higher partially mapped level exists [S1, unofficial].

**Data Structures:**
The `partiallyMapped` value is an integer where each bit corresponds to a resolution level [S1, unofficial]. Resolution levels are ordered from $0$ (highest resolution) to $k$ (lowest resolution) [S1, unofficial]. Consequently, a "higher" resolution corresponds to a lower index [S1, unofficial].

**Steps:**
1. Compute a mask `higher` that isolates bits corresponding to resolution levels that are both partially mapped and strictly higher (lower index) than the current `resolution` [S1, unofficial]. This is done by performing a bitwise AND between `partiallyMapped` and a mask generated by `getHigherResolutionsMask(resolution)` [S1, unofficial].
2. If `higher` is zero, return `NONE` [S1, unofficial].
3. Find the index of the first leading one-bit in `higher` [S1, unofficial]. This index corresponds to the next higher resolution level [S1, unofficial].

**Formulas:**
If the hardware instruction `firstLeadingBit` is unavailable, the index $i$ of the first leading one-bit of an integer $x$ is computed as [S1, unofficial]:

$$
i = \text{BIT\_WIDTH} - 1 - \text{countLeadingZeros}(x)
$$

where $\text{BIT\_WIDTH}$ is the bit-width of the integer type used for the mask [S1, unofficial].

**Pseudocode:**
```python
def find_higher_resolution(partially_mapped: int, resolution: int, bit_width: int = 32) -> int:
    """
    Finds the next higher resolution level index for a node.
    
    Args:
        partially_mapped: Bitmask of resolutions where the node is partially mapped.
        resolution: Index of the resolution level last tested.
        bit_width: Bit-width of the integer type used for the mask.
        
    Returns:
        Index of the next higher resolution, or -1 (NONE) if none exists.
    """
    # Step 1: Compute mask of resolutions strictly higher than current resolution
    # getHigherResolutionsMask returns a mask with bits 0 to resolution-1 set
    higher_mask = (1 << resolution) - 1 if resolution > 0 else 0
    higher = partially_mapped & higher_mask

    # Step 2: If mask is zero, return NONE
    if higher == 0:
        return -1  # NONE

    # Step 3: Find index of first leading one-bit
    # Fallback formula when firstLeadingBit is unavailable [S1, unofficial]
    # countLeadingZeros counts zeros from the most significant bit
    leading_zeros = bit_width - higher.bit_length()
    i = bit_width - 1 - leading_zeros
    return i
```

**Parameters:**
*   `BIT_WIDTH`: The bit-width of the integer type used for the mask (e.g., 32 or 64) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **No Higher Resolution:** If the node is not partially mapped in any resolution higher than the current one, the mask `higher` will be zero, and the function returns `NONE` [S1, unofficial].
*   **Missing Instruction:** If the `firstLeadingBit` instruction is not available on the target platform, the index must be computed using `countLeadingZeros` [S1, unofficial].
*   **Resolution Ordering:** The algorithm assumes resolution levels are ordered from $0$ (highest) to $k$ (lowest) [S1, unofficial].
