# Choosing Alternative Resolutions

Also called: Choosing an alternate resolution given a node’s bitmap, Finding Lower Resolution Levels

## Overview
This method selects a valid, cache-resident resolution level for volume rendering when the desired resolution is not available in the cache [S1, unofficial]. It operates on the principle that a node in a spatial hierarchy (such as an octree) may be partially mapped across multiple resolution levels [S1, unofficial]. By consulting a bitmap of these partially mapped resolutions, the algorithm efficiently identifies an alternative resolution to render, prioritizing lower resolutions before higher ones to minimize memory bandwidth and computation [S1, unofficial]. It differs from sibling methods like [LoD Selection via Projected Width](7837-lod-selection-via-projected-width.md) by relying on residency status rather than geometric projection, and from [Finding Higher Resolution Levels](5315-finding-higher-resolution-levels.md) by its specific fallback strategy and bit-manipulation focus.

## How it works
**Inputs and Outputs:**
*   **Input:** `node.bitmap`: A bitmask representing the resolution levels for which the node is partially mapped in the cache. `resolutionLevel`: The index of the desired resolution level (which is currently unmapped or invalid).
*   **Output:** The index of the next valid resolution level to attempt rendering, or a special value `NONE` if no valid alternative exists.

**Data Structures:**
*   **Resolution Ordering:** Resolution levels are indexed such that $0$ is the highest resolution and $k$ is the lowest resolution [S1, unofficial].
*   **Bitmap:** An integer or bit-field where the $i$-th bit is set to $1$ if the node is partially mapped at resolution level $i$, and $0$ otherwise [S1, unofficial].

**Algorithm Steps:**
The primary strategy attempts to find a lower resolution first, then a higher resolution [S1, unofficial].

1.  **Attempt Lower Resolution:**
    a.  Compute a mask of resolutions that are strictly lower than the `resolutionLevel` and are partially mapped in the node. This is done by performing a logical AND between `node.bitmap` and a precomputed constant mask `getLowerResolutionsMask(resolutionLevel)` [S1, unofficial].
    b.  If the resulting mask is zero, no lower resolution is available. Return `NONE` for this phase.
    c.  Otherwise, identify the index of the first trailing one-bit in the mask. This index corresponds to the next lower resolution level [S1, unofficial].
    d.  Attempt to retrieve the page/brick for this resolution. If the specific ray sample falls into an unmapped region within that brick (despite the node being partially mapped), iterate to the next lower resolution by repeating steps a-c with the new candidate as the reference, or until a valid page is found or `NONE` is returned.

2.  **Attempt Higher Resolution (Fallback):**
    a.  If the lower resolution search fails (returns `NONE`) or the retrieved page is still unmapped for the current ray, switch to searching for higher resolutions [S1, unofficial].
    b.  Compute a mask of resolutions that are strictly higher than the `resolutionLevel` and are partially mapped. This involves a logical AND with a `getHigherResolutionsMask` [S1, unofficial].
    c.  Identify the index of the first trailing one-bit (or appropriate bit position depending on ordering) in this mask.
    d.  Iterate through candidates, retrieving pages and checking for unmapped regions, until a valid page is found or `NONE` is returned.

**Pseudocode:**
The following pseudocode implements the logic described in [S1, unofficial], specifically Algorithms 7.2 and 7.3. It assumes helper functions `getLowerResolutionsMask`, `getHigherResolutionsMask`, `firstTrailingBit`, and `getPage` are available.

```python
def choose_alternate_resolution(node_bitmap, resolution_level):
    """
    Chooses an alternative resolution given a node's bitmap of partially 
    mapped resolutions and the index of a resolution level.
    
    Args:
        node_bitmap (int): Bitmask of partially mapped resolutions.
        resolution_level (int): The index of the desired resolution level.
        
    Returns:
        int: The index of the next valid resolution level, or -1 (NONE).
    """
    
    # Helper: Get mask of resolutions strictly lower than given level
    def get_lower_mask(res_level):
        # Returns a bitmask with 1s for all indices i where i < res_level
        # Implementation detail: (1 << res_level) - 1
        return (1 << res_level) - 1

    # Helper: Get mask of resolutions strictly higher than given level
    def get_higher_mask(res_level):
        # Returns a bitmask with 1s for all indices i where i > res_level
        # Implementation detail: Assuming max resolution is K, 
        # this would be ((1 << (K+1)) - 1) ^ get_lower_mask(res_level) ^ (1 << res_level)
        # For this example, we assume a generic high mask function exists.
        return get_higher_resolutions_mask(res_level)

    # Helper: Find index of first trailing one-bit
    def first_trailing_bit(value):
        if value == 0:
            return -1
        # Count trailing zeros. 
        # If hardware instruction not available, use loop or bit manipulation.
        # Example: value & -value gives lowest set bit. 
        # We need the index.
        index = 0
        while (value & 1) == 0:
            value >>= 1
            index += 1
        return index

    # Helper: Get page for node, ray, and resolution
    # Returns an object with attribute 'unmapped' (bool)
    def get_page(node, ray, res_level):
        # Placeholder for actual memory lookup logic
        # [G] In a real implementation, this checks if the specific voxel 
        # block for the ray's intersection is resident.
        return PageObject(unmapped=False) 

    # Step 1: Try lower resolutions first
    lower_mask = node_bitmap & get_lower_mask(resolution_level)
    
    current_resolution = first_trailing_bit(lower_mask)
    
    while current_resolution != -1:
        page = get_page(node, None, current_resolution) # Ray context implied
        if not page.unmapped:
            return current_resolution
        # If unmapped, try next lower resolution
        # Clear the current bit and find next trailing bit
        lower_mask &= ~(1 << current_resolution)
        current_resolution = first_trailing_bit(lower_mask)

    # Step 2: If lower failed, try higher resolutions
    higher_mask = node_bitmap & get_higher_mask(resolution_level)
    
    # Note: Algorithm 7.4 (not fully detailed in notes but implied) 
    # would find the next HIGHER resolution. 
    # Since resolution 0 is highest, "higher" means lower index.
    # The logic mirrors the lower search but iterates towards 0.
    
    # Simplified iteration for higher resolutions (lower indices)
    # We need to find the smallest index > resolution_level that is set.
    # This requires a different mask or iteration direction.
    # Based on [S1, unofficial] Algorithm 7.2 line 8-12:
    
    current_resolution = find_next_higher(node_bitmap, resolution_level)
    
    while current_resolution != -1:
        page = get_page(node, None, current_resolution)
        if not page.unmapped:
            return current_resolution
        # Try next higher resolution
        current_resolution = find_next_higher(node_bitmap, current_resolution)
        
    return -1 # NONE

def find_next_higher(node_bitmap, current_level):
    """
    Finds the next resolution level with a lower index (higher resolution)
    that is set in the bitmap.
    """
    # Mask out current level and all lower resolutions (higher indices)
    # We want bits > current_level (indices < current_level)
    # Mask for indices < current_level is (1 << current_level) - 1
    relevant_mask = node_bitmap & ((1 << current_level) - 1)
    
    if relevant_mask == 0:
        return -1
    
    # Find the highest set bit in relevant_mask (which is the smallest index)
    # This is equivalent to finding the first trailing bit of the reversed bits,
    # or simply the most significant bit of the relevant mask.
    # However, standard firstTrailingBit finds LSB.
    # To find MSB:
    index = 0
    temp = relevant_mask
    while temp > 1:
        temp >>= 1
        index += 1
    return index
```

**Parameters:**
*   **Resolution Indexing:** $0$ is the highest resolution, $k$ is the lowest [S1, unofficial].
*   **Fallback Strategy:** The default strategy is "Lower then Higher" [S1, unofficial]. Alternatives include "Higher then Lower" or alternating, but the cited implementation uses Lower first [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Unmapped Regions:** A node being "partially mapped" means *some* bricks are in cache, but not necessarily the specific brick intersected by the current ray [S1, unofficial]. The algorithm must iterate through candidates and check `page.unmapped` [S1, unofficial].
*   **Bit Manipulation:** If `firstTrailingBit` is not available, compute the index as the number of consecutive trailing zero-bits from the Least Significant Bit (LSB) [S1, unofficial].
*   **No Candidates:** If the mask is zero, return `NONE` [S1, unofficial].

## Subtopics

### Screen-Space Adaptive Resolution
Techniques that adaptively render depending on screen resolution, rendering display-aware resolutions potentially lower than data resolution to reduce computation and texture memory requirements [S2, unofficial]. It uses deeper level values (higher resolution) for areas closer to regions of interest and lower resolution for other areas [S2, unofficial].

### Multiresolution AMR Rendering for Interactivity
To render lower-resolution approximations, this method ignores some of the more refined levels during grid homogenization. Coarser-resolution cells overlaid by finer-resolution cells contain valid data, so ignoring finer levels gracefully decreases image quality and rendering time [S3, unofficial]. It may also reduce image resolution during interaction and enlarge the resulting image using OpenGL’s pixel zoom feature [S3, unofficial]. Two user-adjustable settings control the resolution level for still images and transient images during interactive viewpoint changes [S3, unofficial]. This approach achieved interactive rendering rates of at least five frames per second for tested datasets [S3, unofficial].

### Level-of-detail texture mapping
A method to reduce fragment shader load by rasterizing lower-resolution texture blocks when local volume detail or projected resolution allows [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** The bitmap operations (AND, bit scanning) are $O(1)$ or $O(\log k)$ depending on the bit-scan implementation, where $k$ is the number of resolution levels. The iteration depends on the number of unmapped candidates, which is typically small.
*   **Memory Complexity:** Requires storing a bitmap per node in the spatial hierarchy [S1, unofficial].
*   **Strengths:** Efficiently utilizes cache residency information without random searches through all resolution levels [S1, unofficial]. Reduces memory bandwidth by selecting the lowest valid resolution that is available [S1, unofficial].
*   **Limitations:** Does not account for geometric detail or projected size directly; relies on the assumption that lower resolutions are acceptable when the target is missing [S1, unofficial]. Performance depends on the distribution of mapped bricks.

## Background
This method originates from mixed-resolution multi-volume rendering systems, specifically those using residency-octrees to manage cache [S1, unofficial]. It addresses the problem of cache misses in hierarchical volume data structures by providing a deterministic fallback mechanism based on partial residency [S1, unofficial].
