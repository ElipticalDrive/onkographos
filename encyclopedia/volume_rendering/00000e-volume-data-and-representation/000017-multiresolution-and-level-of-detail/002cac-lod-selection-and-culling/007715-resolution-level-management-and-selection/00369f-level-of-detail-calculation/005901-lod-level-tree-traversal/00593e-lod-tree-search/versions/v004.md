# LOD Tree Search
Also called: OctTree
## Overview
LOD Tree Search is a traversal algorithm for multidimensional search trees (specifically 3D binary trees keyed by minimum value, maximum value, and Level-of-Detail) to efficiently retrieve voxel cells intersecting an isosurface at a specific resolution [S2, unofficial]. It solves the problem of finding geometric primitives for isosurface extraction without processing the entire dataset, by pruning branches that cannot contain the target isovalue or do not match the desired LOD [S2, unofficial].
## How it works
**Inputs and Outputs:**
The algorithm takes a tree branch, a target Level-of-Detail integer, an isovalue threshold, a coordinate center (default 0,0,0) [S1, unofficial], a distance range in metres for switching LOD (default 20) [S1, unofficial], and high-resolution/low-resolution geometry instances for inside/outside range rendering [S1, unofficial]. It returns a list of cells that satisfy both the LOD and isovalue intersection criteria [S2, unofficial].

**Data Structures:**
The tree is a 3D binary search tree where each node stores a minimum data value, a maximum data value, an LOD key, and pointers to left and right children [S2, unofficial].

**Numbered Steps:**
1. Check LOD Mismatch (Too High): If the current cell's LOD exceeds the target, the algorithm recurses into the left branch, which contains cells with smaller keys [S2, unofficial].
2. Check LOD Mismatch (Too Low): If the current cell's LOD is below the target, the algorithm recurses into the right branch, which contains cells with larger keys [S2, unofficial].
3. Check LOD Match: If the cell's LOD matches the target, the algorithm verifies isosurface intersection using the cell's value bounds [S2, unofficial].
4. Add Cell: If the minimum value is strictly less than the isovalue and the maximum value is strictly greater than the isovalue, the cell is added to the output list [S2, unofficial].
5. Search Children: The algorithm recursively calls the pruning function on the right child and then the left child to find other intersecting cells at the same LOD level [S2, unofficial].
6. Distance-Based LOD Switching: If the viewer distance to the coordinate center is within the specified range, the renderer draws the high-resolution children; otherwise, it draws the low-resolution object [S1, unofficial].

**Formulas:**
The isosurface intersection test uses the bounding box of scalar values in a cell:
$$ \text{min\_val} < \text{isovalue} \quad \land \quad \text{max\_val} > \text{isovalue} $$
where `min_val` and `max_val` are the minimum and maximum data values stored in the node, and `isovalue` is the scalar threshold defining the isosurface [S2, unofficial].

**Parameters:**
*   `center`: Coordinate center for distance calculation (default 0,0,0) [S1, unofficial].
*   `range`: Distance in metres from `center` for switching LOD (default 20, range [0,∞)) [S1, unofficial].
*   `highRes` / `lowRes`: Geometry instances for inside/outside range rendering [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Min Key Pruning:** If a cell's minimum value is less than the isovalue, all cells in the left branch will also satisfy this condition, allowing the algorithm to skip minimum key tests for that subtree [S2, unofficial].
*   **Max Key Pruning:** Similarly, if the maximum key condition is met, testing can stop for the right branch [S2, unofficial].
*   **LOD Boundary Optimization:** If the target LOD is the absolute maximum or minimum in the tree, and the search enters a left subtree of an already minimum LOD node, LOD key testing can stop early [S2, unofficial].
*   **Precision:** The intersection test uses strict inequalities, meaning cells where the minimum or maximum exactly equals the isovalue are excluded from the output [S2, unofficial].

**Pseudocode:**
```python
def search_lod(branch, desired_lod, isovalue, output_list):
    """Traverses the LOD tree to find cells intersecting the isosurface at the desired LOD."""
    if branch is None:
        return
    if branch.lod > desired_lod:
        search_minimum(branch.left, desired_lod, isovalue, output_list)
    elif branch.lod < desired_lod:
        search_minimum(branch.right, desired_lod, isovalue, output_list)
    else:
        if branch.min_val < isovalue and branch.max_val > isovalue:
            output_list.append(branch)
        search_minimum(branch.right, desired_lod, isovalue, output_list)
        search_minimum(branch.left, desired_lod, isovalue, output_list)

def search_minimum(branch, desired_lod, isovalue, output_list):
    """Handles traversal logic, pruning branches where min/max bounds cannot contain the isovalue."""
    if branch is None:
        return
    if branch.min_val >= isovalue or branch.max_val <= isovalue:
        return
    search_lod(branch, desired_lod, isovalue, output_list)
```
## Subtopics

### [LODTree Construction](16369-lodtree-construction.md)
A parallel divide-and-conquer algorithm that builds the multidimensional search tree used by LOD Tree Search. Unlike static hierarchical representations, it optimizes for parallel file creation and compact storage via bit-mapped vertex coordinates, specifically targeting structured grids. Choose this when you need to efficiently build the underlying data structure for structured grids.

### Hierarchical LOD Navigation and Rendering
A variant that manages a hierarchy of 3D Gaussians for navigation and rendering [S3]. It sets itself apart by using dynamic threshold-based reloading ($\tau_h = 1$) and asynchronous double buffering to avoid visual stutter during navigation [S3]. Choose this when rendering dynamic 3D Gaussian splats that require real-time hierarchy traversal and LOD switching [S3].

## Operating characteristics
*   **Time Complexity:** Depends on the distribution of data and the density of the isosurface, with pruning based on min/max bounds and LOD keys reducing traversal significantly [S2, unofficial].
*   **Memory Complexity:** Linear with respect to the number of nodes in the LOD Tree, as each cell stores min, max, and LOD keys alongside child pointers [S2, unofficial].
*   **Strengths:** Efficiently isolates cells at a specific resolution, avoiding the cost of processing higher or lower LODs, while key boundary optimizations reduce unnecessary checks [S2, unofficial].
*   **Limitations:** Performance degrades if the isosurface intersects many cells across all LODs or if the tree is unbalanced, and the algorithm assumes a pre-constructed 3D binary search tree [S2, unofficial].
*   **When to Use:** When extracting isosurfaces from large voxel datasets where only a specific level of detail is required, and the data is structured in a multikey search tree [S2, unofficial].
*   **When Not to Use:** When the isosurface is sparse and scattered across many LODs, or when the tree construction cost outweighs the search savings for a single query [S2, unofficial].
## Background
The method originates from the DYNAISOLOD system, which generates triangles on a cell-by-cell basis using the Marching Cubes algorithm for each cell found [S2, unofficial]. It was developed to handle dynamic isosurface extraction and level-of-detail in voxel space [S2, unofficial]. The X3D OctTree node provides a complementary distance-based LOD switching mechanism for volume rendering, allowing users to define high-resolution and low-resolution geometry instances based on viewer proximity to a coordinate center [S1, unofficial].
