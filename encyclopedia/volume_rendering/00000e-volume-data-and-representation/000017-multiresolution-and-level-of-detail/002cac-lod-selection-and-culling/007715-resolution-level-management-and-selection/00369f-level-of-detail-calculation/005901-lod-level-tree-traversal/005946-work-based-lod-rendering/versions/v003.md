# Work-based LOD Rendering

Also called: WorkTree4DRenderer

## Overview
Work-based LOD Rendering is a visualization technique that maps the number of tree traversal steps required to find a data leaf for each pixel to a pixel color, rather than rendering actual density or scalar values [S1, unofficial]. It visualizes traversal complexity and data sparsity distribution across a volume by treating the step count as the primary data channel [S1, unofficial]. It builds on [LOD Level Tree Traversal](16320-lod-level-tree-traversal.md) and differs from [LOD Tree Search](16352-lod-tree-search.md) by explicitly counting and coloring traversal steps instead of searching for optimal level-of-detail boundaries.

## How it works
**Inputs and Outputs:**
- **Input:** A 4D Sparse Voxel Octree (SVO) containing spatial $(x, y, z)$ and temporal $(t)$ dimensions, a camera configuration defining 3D rays, a specific time point $t$ for the 4D ray conversion, and a global maximum step counter initialized to $0$ or the previous frame's maximum [S1, unofficial].
- **Output:** A 2D texture array (RGBA) where each pixel stores a color derived from the step count required to find a data leaf for that pixel's ray [S1, unofficial].

**Data Structures:**
- **Tree:** A 4D Sparse Voxel Octree. Nodes expose `isLeaf()` and `hasData()` methods [S1, unofficial].
- **Ray4D:** A ray structure extended with time, created from a 3D ray and a scalar time point via `convertRayTo4D` [S1, unofficial].
- **TreeTraverser:** An iterator object (`Tree4DTraverserDifferentSides`) that maintains the current node, step count, and termination state [S1, unofficial].
- **Texture Array:** A buffer of unsigned char values (RGBA), indexed by `partial_index_in_texture_array + x * 4` [S1, unofficial].

**Parameters:**
- `time_point`: The temporal coordinate for the 4D ray conversion, constrained by the tree's temporal bounds $[min, max]$ [S1, unofficial].
- `max_step_count`: The global maximum step count observed across all pixels in the current frame, used for color normalization [S1, unofficial].

**Algorithm:**
The method processes pixels in parallel using OpenMP over pixel rows [S1, unofficial]. For each pixel, it performs a tree traversal to count steps until a leaf with data is found or the ray terminates [S1, unofficial].

1. Initialize an OpenMP parallel loop over pixel rows $y$: `for y in range(rc.n_y):` [S1, unofficial].
2. For each pixel $(x, y)$:
   a. Compute the 3D ray from the camera for pixel $(x, y)$ [G].
   b. Convert the 3D ray to a 4D ray using the current `time_point`: `ray4D = convertRayTo4D(ray3D, time_point, 0.0)` [S1, unofficial].
   c. Initialize the tree traverser: `traverser = Tree4DTraverserDifferentSides(tree, ray4D)` [S1, unofficial].
   d. Initialize `data_leaf_found = False` and `traverser.stepcount = 0` [S1, unofficial].
   e. Traverse the tree in a loop: `while not traverser.isTerminated() and not data_leaf_found:` [S1, unofficial].
   f. Inside the loop, check if the current node is a leaf with data: `if traverser.getCurrentNode().isLeaf() and traverser.getCurrentNode().hasData():` [S1, unofficial].
   g. If not a data leaf, advance the traversal: `traverser.step()` [S1, unofficial].
   h. After traversal, update the global maximum step count: `if traverser.stepcount > max_step_count: max_step_count = traverser.stepcount` [S1, unofficial].
   i. Map the step count to a color: `color = GetColour(traverser.stepcount, 0.0, max_step_count)` [S1, unofficial].
   j. Store the RGBA values in the texture array at index `partial_index_in_texture_array + x * 4` [S1, unofficial].

```python
for y in range(rc.n_y):
    for x in range(rc.n_x):
        ray3D = generate_ray_from_camera(x, y)  # [G] Standard camera projection
        ray4D = convertRayTo4D(ray3D, time_point, 0.0)
        traverser = Tree4DTraverserDifferentSides(tree, ray4D)
        data_leaf_found = False
        traverser.stepcount = 0
        while not traverser.isTerminated() and not data_leaf_found:
            if traverser.getCurrentNode().isLeaf() and traverser.getCurrentNode().hasData():
                data_leaf_found = True
            else:
                traverser.step()
        if traverser.stepcount > max_step_count:
            max_step_count = traverser.stepcount
        color = GetColour(traverser.stepcount, 0.0, max_step_count)
        idx = partial_index_in_texture_array + x * 4
        texture_array[idx : idx + 4] = color
```

**Edge Cases and Pitfalls:**
- **No Data Leaf:** If the ray terminates without finding a leaf with data (`isTerminated()` becomes true), the `stepcount` reflects the depth of traversal until termination [S1, unofficial].
- **Boundary Conditions:** The `time_point` must be within the tree's temporal bounds $[min, max]$ to ensure valid 4D ray generation, as enforced by the UI slider constraints [S1, unofficial].

## Operating characteristics
- **Parallelization:** The algorithm processes pixel rows in parallel using OpenMP [S1, unofficial].
- **Performance:** Performance is limited by memory access patterns in the sparse voxel octree and the branching factor of the tree [S1, unofficial].
- **Strengths:** Provides a direct visualization of data sparsity and traversal cost, useful for debugging tree construction and optimizing culling strategies [S1, unofficial].
- **Limitations:** Does not convey volumetric density or scalar values; colors represent computational work, not physical properties [S1, unofficial].
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.

## Background
Work-based LOD Rendering is implemented in the "4D-Sparse-Voxel-Octree-Renderer" project by joschout [S1, unofficial]. It is part of a suite of visualization techniques for 4D sparse voxel data, alongside depth rendering and time-point counting [S1, unofficial]. The method leverages the inherent structure of the 4D SVO to provide insight into the efficiency of ray traversal algorithms [S1, unofficial].
