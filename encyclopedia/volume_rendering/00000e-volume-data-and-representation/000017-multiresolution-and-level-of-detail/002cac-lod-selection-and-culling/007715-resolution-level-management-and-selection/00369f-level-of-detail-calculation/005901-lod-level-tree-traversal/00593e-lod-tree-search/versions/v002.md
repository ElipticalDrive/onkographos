# LOD Tree Search
## Overview
LOD Tree Search is a traversal algorithm for multidimensional search trees (specifically 3D binary trees keyed by minimum value, maximum value, and Level-of-Detail) to efficiently retrieve voxel cells intersecting an isosurface at a specific resolution [S1, unofficial]. It solves the problem of finding geometric primitives for isosurface extraction (such as Marching Cubes) without processing the entire dataset, by pruning branches that cannot contain the target isovalue or do not match the desired LOD [S1, unofficial]. It differs from sibling methods like Work-based LOD Rendering by explicitly using a multi-key tree structure to navigate spatial and resolution hierarchies simultaneously, rather than relying on workload balancing or static culling heuristics [S1, unofficial].
## How it works
**Inputs:**
*   `branch`: The root node or subtree of the LOD Tree.
*   `desired_lod`: The target Level-of-Detail integer.
*   `isovalue`: The scalar threshold defining the isosurface.

**Outputs:**
*   A list of cells (nodes) that satisfy the LOD and isovalue intersection criteria.

**Data Structures:**
The tree is a 3D binary search tree. Each node `c` stores:
*   `min_val`: The minimum data value in the cell's domain.
*   `max_val`: The maximum data value in the cell's domain.
*   `lod`: The Level-of-Detail (resolution) key for this cell.
*   `left`: Pointer to the left child (smaller keys).
*   `right`: Pointer to the right child (larger keys).

**Algorithm Steps:**
1.  **Check LOD Mismatch (Too High):** If `c.lod > desired_lod`, the current cell is too detailed. The algorithm recurses into the `left` branch, which contains cells with smaller keys (including potentially smaller LODs) [S1, unofficial].
2.  **Check LOD Mismatch (Too Low):** If `c.lod < desired_lod`, the current cell is too coarse. The algorithm recurses into the `right` branch, which contains cells with larger keys (including potentially larger LODs) [S1, unofficial].
3.  **Check LOD Match:** If `c.lod == desired_lod`:
    a.  **Check Isosurface Intersection:** Verify if the isosurface passes through the cell using the bounding box of values:
        $$ \text{min\_val} < \text{isovalue} \quad \land \quad \text{max\_val} > \text{isovalue} $$
    b.  **Add Cell:** If the condition is true, add `c` to the output list [S1, unofficial].
    c.  **Search Right:** Recursively call `search_minimum` on `c.right` to find other cells at the same LOD level [S1, unofficial].
    d.  **Search Left:** Recursively call `search_minimum` on `c.left` to find other cells at the same LOD level [S1, unofficial].

**Pseudocode:**
```python

    """
    Traverses the LOD tree to find cells intersecting the isosurface at the desired LOD.
    """
    if branch is None:
        return

    # Recurse left to find smaller LODs
    if branch.lod > desired_lod:

        return

    # Recurse right to find larger LODs
    if branch.lod < desired_lod:
        search_minimum(branch.right, desired_lod, isovalue)
        return

    # Case 3: Current LOD matches desired LOD
    # Check if the isosurface intersects this cell

        add_cell_to_output(branch)

    # Search both subtrees for other cells at the same LOD level
    search_minimum(branch.right, desired_lod, isovalue)
    search_minimum(branch.left, desired_lod, isovalue)
```

**Optimizations and Pitfalls:**
*   **Min Key Pruning:** If `branch.min_val < isovalue`, all cells in the left branch (which have smaller keys) will also have `min_val < isovalue`. The algorithm can skip testing the minimum key condition for those nodes, though it must still check LOD and max bounds [S1, unofficial].
*   **Max Key Pruning:** Similarly, if the maximum key condition is met for a branch, testing can stop for that branch's specific key checks [S1, unofficial].
*   **LOD Boundary Optimization:** If the `desired_lod` is the greatest or least possible value in the tree, and the search moves to a smaller (left) subtree of an already minimum LOD node, LOD key testing can stop. This is critical because the search is most time-consuming at the lowest level-of-detail [S1, unofficial].
*   **Precision:** The intersection test relies on strict inequalities (`<` and `>`). Edge cases where `min_val` or `max_val` exactly equals `isovalue` are not explicitly defined in the source as intersections, implying they are excluded [S1, unofficial].

## Subtopics

### [LODTree Construction](16369-lodtree-construction.md)
A parallel divide-and-conquer algorithm that builds the multidimensional search tree used by LOD Tree Search. It partitions data using three keys—minimum value, maximum value, and LOD—to create a 3D binary tree structure. Choose this when you need to efficiently build the underlying data structure for structured grids.

## Operating characteristics
*   **Time Complexity:** Depends on the distribution of data and the density of the isosurface. In the worst case, it may traverse significant portions of the tree, but pruning based on min/max bounds and LOD keys reduces this significantly [S1, unofficial].
*   **Memory Complexity:** Linear with respect to the number of nodes in the LOD Tree. The tree structure itself requires storing min, max, and LOD keys for each cell [S1, unofficial].
*   **Strengths:** Efficiently isolates cells at a specific resolution, avoiding the cost of processing higher or lower LODs. Optimizations for key boundaries reduce unnecessary checks [S1, unofficial].
*   **Limitations:** Performance degrades if the isosurface intersects many cells across all LODs or if the tree is unbalanced. The algorithm assumes a pre-constructed 3D binary search tree [S1, unofficial].
*   **When to Use:** When extracting isosurfaces from large voxel datasets where only a specific level of detail is required, and the data is structured in a multikey search tree.
*   **When Not to Use:** When the isosurface is sparse and scattered across many LODs, or when the tree construction cost outweighs the search savings for a single query.

## Background
The method originates from the DYNAISOLOD system, which generates triangles on a cell-by-cell basis using the Marching Cubes algorithm for each cell found [S1, unofficial]. It was developed to handle dynamic isosurface extraction and level-of-detail in voxel space, optimizing for parallel file creation and compact storage via bit-mapped vertex coordinates, specifically targeting structured (rectilinear) grids [S1, unofficial].
