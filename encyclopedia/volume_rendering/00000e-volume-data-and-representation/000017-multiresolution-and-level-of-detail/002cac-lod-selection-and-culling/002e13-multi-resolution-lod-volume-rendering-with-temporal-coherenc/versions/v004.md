# Multi-resolution LOD Volume Rendering with Temporal Coherence

Also called: LOD Volume Rendering with Temporal Coherence

## Overview
Multi-resolution LOD Volume Rendering with Temporal Coherence assigns different resolution levels to subvolumes based on visual importance metrics—specifically projection area, gaze distance, and view point proximity—to optimize rendering performance while maintaining visual quality [S1]. It distinguishes itself from standard LOD methods by explicitly implementing temporal coherence to prevent flickering artifacts caused by frequent LOD changes during view updates, and by using specific extensions to ensure continuous transitions and correct pixel opacities at subvolume boundaries [S1].

## How it works
The method operates on a volume dataset partitioned into subvolumes [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Volume dataset (e.g., MRI-Brain $256 \times 256 \times 109$) [S1].
    *   Current camera position and viewing direction [S1].
    *   Gaze area center (optional, for gaze-directed rendering) [S1].
    *   Previous frame's LOD assignments and importance values [S1].
    *   Texture memory budget (e.g., 100%, 54%, 33%) [S1].
*   **Outputs:**
    *   Rendered image with adaptive resolution per subvolume [S1].
    *   Updated LOD assignments for the current frame [S1].

### Data Structures
The source describes a subvolume-based approach where each subvolume has an associated resolution level [S1].
*   **Subvolume:** A spatial partition of the volume, each with a bounding box and center [S1].
*   **Importance Value:** A scalar metric calculated per subvolume to determine its rendering priority [S1].
*   **LOD Level:** An integer or discrete index representing the resolution of the texture data for that subvolume [S1].

### Parameters
*   **Projection Area:** Calculated based on the bounding box of the subvolume; higher projection area implies higher importance [S1].
*   **Gaze Distance:** The distance between the center of the gaze area and the center of the projected area of a subvolume; closer regions receive higher quality, while farther regions use lower resolution data (blur) [S1].
*   **View Point Distance:** The distance from the center of the subvolume to the view point; closer subvolumes have higher importance [S1].
*   **Level Transition Constraint:** No level transitions greater than one are allowed between adjacent subvolumes or frames to ensure smoothness [S1].
*   **Temporal Coherence Threshold:** A percentage threshold used to decide if an LOD change is necessary; if the importance value does not differ by more than this threshold from the previous frame, the LOD remains unchanged [S1].

### Algorithm Steps

1.  **Initialization (First Frame):**
    *   Calculate the importance value for each subvolume based on current view parameters (Projection Area, Gaze Distance, View Point Distance) [S1].
    *   Assign initial LOD levels based on importance and available texture memory budget [S1].

2.  **Frame Update (Subsequent Frames):**
    *   **Check for View Change:** Determine if the user has changed the viewing direction or gaze area [S1].
    *   **Recalculate Importance:** If a view change occurred, recalculate the importance value for each subvolume using the new parameters [S1].
    *   **Temporal Coherence Check:** Compare the new importance value $I_{\text{new}}$ with the previous frame's importance value $I_{\text{old}}$ for each subvolume [S1]. If $|I_{\text{new}} - I_{\text{old}}| \leq \text{Threshold} \times I_{\text{old}}$, retain the previous LOD level ($L_{\text{new}} = L_{\text{old}}$) [S1]. Otherwise, recalculate the target LOD level based on the new importance values and memory budget [S1].
    *   **Apply Transition Constraint:** Ensure that the change in LOD level for any subvolume does not exceed one level ($|L_{\text{new}} - L_{\text{old}}| \leq 1$) [S1].
    *   **Render:** Render the volume using the assigned LOD levels for each subvolume, applying extensions to handle continuous transitions and correct pixel opacities at boundaries [S1].

    # Standard projection of axis-aligned bounding box onto view plane [G]
    return bounding_box.width * bounding_box.height
