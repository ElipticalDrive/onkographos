# Cosine Projection via Upsampling

Also called: Get Cos Projection, Find Cosine Window, Generate View Alternative, Generate Views

## Overview
Cosine Projection via Upsampling generates multi-angle view projections (sinograms) from volumetric data by accounting for the viewing zenith angle (VZA) [S1, unofficial]. It solves the geometric distortion inherent in oblique viewing by upsampling the data, applying a cosine scaling factor to the grid spacing, and padding the result to maintain resolution consistency with the nadir view [S1, unofficial]. It differs from [Zero Padding for Aliasing Reduction](6382-zero-padding-for-aliasing-reduction.md) by explicitly incorporating the angular dependency of the projection path length via the cosine factor, rather than merely preventing boundary artifacts [S1, unofficial].

## How it works
The method transforms a 3D dataset (typically optical thickness or density) into a set of 2D projections corresponding to different viewing angles [S1, unofficial]. The core challenge is that an oblique view traverses a longer path through the volume than the nadir view, effectively stretching the data along the projection axis [S1, unofficial]. This method compensates by upsampling, scaling the grid, and padding [S1, unofficial].

### Inputs and Outputs
- **Input**: A 3D data array or a 2D slice projected to a Center of Mass (COM) plane [S1, unofficial]. Let the input be $D$ with spatial coordinates $x$ and $y$, and grid spacing $dx$ [S1, unofficial].
- **Output**: A multi-angle tile (sinogram) or a list of projected views, typically stacked along a new angle dimension [S1, unofficial].

### Data Structures
The implementation uses `xarray.DataArray` objects [S1, unofficial].
- **Fields**: `data` (numeric values), `coords` (spatial coordinates like `x`, `y`, `vza`), `dims` (dimension names) [S1, unofficial].
- **Layout**: The data is assumed to be on a regular grid. The `x` coordinate is a 1D array defining the boundaries or centers of the cells [S1, unofficial].

### Parameters
- **Upsampling Factor ($U$)**: The factor by which the data is upsampled before projection. Typical value: 100 [S1, unofficial].
- **Viewing Zenith Angle ($\theta$)**: The angle of view relative to the nadir (vertical). $\theta = 0^\circ$ is the nadir view [S1, unofficial].
- **Stretch ($S$)**: A small buffer factor (in units of $dx$) used to ensure the window covers the projected extent [S1, unofficial].
- **Offset**: A shift applied during interpolation to align the projected view with the nadir center [G].

### Steps
1. **Project to Center of Mass (COM)**: If the input is 3D, project it to a 2D plane to get a base view [S1, unofficial].
2. **Select Nadir View**: Extract the view at $\theta = 0^\circ$ from $D_{COM}$ (or the original data if already 2D) [S1, unofficial].
3. **Loop over VZA Angles**: For each angle $\theta$ in the desired set of angles:
    a. **Handle Nadir**: If $\theta = 0^\circ$, append $D_{nadir}$ directly to the output list [S1, unofficial].
    b. **Calculate Cosine Factor**: Compute $f = \cos(\theta_{\text{rad}})$, where $\theta_{\text{rad}} = \theta \times \frac{\pi}{180}$ [S1, unofficial].
    c. **Upsample Data**:
        - Determine the original x-range: $x_{\min} = D.x[0]$, $x_{\max} = D.x[-1]$ [S1, unofficial].
        - Create upsampled x-coordinates: $x_{\text{up}} = \text{linspace}(x_{\min}, x_{\max}, U \times \text{len}(D.x))$ [S1, unofficial].
        - Interpolate the data to $x_{\text{up}}$: $D_{\text{up}} = \text{interp}(D, x=x_{\text{up}})$ [S1, unofficial].
    d. **Calculate Projected Grid Spacing**:
        - The effective grid spacing in the projected view is scaled by the cosine factor [S1, unofficial].
        - $dx_{\text{proj}} = \frac{dx}{U} \times f$ [S1, unofficial].
    e. **Create Projected Coordinates**:
        - $x_{\text{proj}} = \text{arange}(x_{\min}, x_{\max} + dx_{\text{proj}}, dx_{\text{proj}})$ [S1, unofficial].
        - Note: The number of points $N_{\text{proj}} = \text{len}(x_{\text{proj}})$ [S1, unofficial].
    f. **Calculate Padding**:
        - The original upsampled data has $N_{\text{up}} = \text{len}(D_{\text{up}})$ [S1, unofficial].
        - Padding needed: $P = N_{\text{proj}} - N_{\text{up}}$ [S1, unofficial].
        - Split padding: $P_{\text{before}} = \lfloor P/2 \rfloor$, $P_{\text{after}} = P - P_{\text{before}}$ [S1, unofficial].
    g. **Pad Data**:
        - Pad $D_{\text{up}}$ with zeros: $D_{\text{pad}} = \text{pad}(D_{\text{up}}, \text{x}=(P_{\text{before}}, P_{\text{after}}), \text{constant\_values}=0)$ [S1, unofficial].
        - Assign new coordinates: $D_{\text{proj}} = D_{\text{pad}}.\text{assign\_coords}(\text{x}=x_{\text{proj}})$ [S1, unofficial].
    h. **Interpolate to Nadir Window**:
        - Calculate the center of the nadir view: $x_{\text{center}} = x_{\text{nadir, min}} + \frac{x_{\text{nadir, max}} - x_{\text{nadir, min}}}{2}$ [S1, unofficial].
        - Calculate the radius of the nadir view: $R = \frac{x_{\text{nadir, max}} - x_{\text{nadir, min}}}{2}$ [S1, unofficial].
        - Determine the window slice for the projected view. The projected view is wider by $1/f$ [S1, unofficial].
        - Window bounds: $x_{\text{start}} = x_{\text{center}} - \frac{R}{f} - S \cdot dx$, $x_{\text{end}} = x_{\text{center}} + \frac{R}{f} + S \cdot dx$ [S1, unofficial].
        - Interpolate $D_{\text{proj}}$ to the nadir x-grid with an offset to align the center: $D_{\text{new}} = D_{\text{proj}}.\text{interp}(\text{x}=x_{\text{nadir}} + \text{offset})$ [S1, unofficial].
    i. **Append**: Add $D_{\text{new}}$ to the list of camera views [S1, unofficial].
4. **Concatenate**: Stack all views along a new dimension (e.g., `vza` or `angles`) to form the final sinogram or multi-angle tile [S1, unofficial].

### Pseudocode

```python
import numpy as np
import xarray as xr

def cosine_projection_via_upsampling(data: xr.DataArray, angles_deg: list, dx: float, upsampling_factor: int = 100, stretch: float = 1.0) -> xr.DataArray:
    """
    Generate multi-angle projections using cosine projection via upsampling.
    
    Args:
        data: Input 2D or 3D data array. If 3D, it is assumed to be projected to 2D COM first.
              Must have 'x' and 'y' coordinates.
        angles_deg: List of viewing zenith angles in degrees.
        dx: Original grid spacing in x.
        upsampling_factor: Factor to upsample data before projection.
        stretch: Buffer factor for window calculation.
        
    Returns:
        xr.DataArray with dimensions (angles, x, y) containing the projected views.
    """
    # Source does not specify the 3D-to-2D COM projection method; assume data is pre-projected to 2D [G].
    
    # Get nadir view parameters
    x_nadir = data.coords['x'].values
    x_min_nadir = x_nadir[0]
    x_max_nadir = x_nadir[-1]
    x_center_nadir = (x_min_nadir + x_max_nadir) / 2.0
    radius_nadir = (x_max_nadir - x_min_nadir) / 2.0
    
    cameras = []
    
    for vza in angles_deg:
        if vza == 0:
            # Nadir view is the original data (or the specific nadir slice)
            cameras.append(data)
            continue
            
        # 1. Calculate cosine factor
        vza_rad = np.deg2rad(vza)
        factor = np.cos(vza_rad)
        
        # 2. Upsample x coordinates
        x_orig = data.coords['x'].values
        x_min = x_orig[0]
        x_max = x_orig[-1]
        n_orig = len(x_orig)
        n_up = int(upsampling_factor) * n_orig
        
        x_up = np.linspace(x_min, x_max, n_up)
        
        # 3. Interpolate data to upsampled x
        data_up = data.interp(x=x_up)
        
        # 4. Calculate projected grid spacing
        dx_proj = (dx / upsampling_factor) * factor
        
        # 5. Create projected x coordinates
        x_proj = np.arange(x_min, x_max + dx_proj, dx_proj)
        n_proj = len(x_proj)
        n_up_actual = len(data_up.coords['x'])
        
        # 6. Calculate padding
        pad = n_proj - n_up_actual
        pad_before = pad // 2
        pad_after = pad - pad_before
        
        # 7. Pad data with zeros
        padded_values = np.pad(data_up.values, ((pad_before, pad_after), (0, 0)), mode='constant', constant_values=0)
        
        # Create new coords for padded data
        padded_data = xr.DataArray(
            padded_values,
            dims=data_up.dims,
            coords={dim: (coord if dim != 'x' else x_proj) for dim, coord in data_up.coords.items()}
        )
        
        # 8. Interpolate to nadir x grid with offset
        # Calculate window bounds
        x_start = x_center_nadir - radius_nadir / factor - stretch * dx
        x_end = x_center_nadir + radius_nadir / factor + stretch * dx
        
        # Select the slice from the projected data
        # Source uses a wrap-around helper for boundary handling [S1, unofficial]
        # data_slice = wrap_around(x_slice, padded_data, dx)[:, sly]
        # Here we select the relevant spatial window directly
        data_slice = padded_data.sel(x=slice(x_start, x_end))
        
        # Interpolate to nadir x coordinates with shift
        offset = 0.0 # [G] Typically derived from projection geometry
        x_interp = x_nadir + offset
        
        data_new = data_slice.interp(x=x_interp)
        
        cameras.append(data_new)
        
    # Concatenate cameras
    angles_data = xr.concat(cameras, dim='angles')
    angles_data.coords['angles'] = angles_deg
    
    return angles_data
```

### Edge Cases and Pitfalls
- **VZA = 0**: The cosine factor is 1. The method should return the original data without upsampling/padding to avoid interpolation artifacts [S1, unofficial].
- **Precision**: Upsampling by a large factor (e.g., 100) increases memory usage significantly. Ensure sufficient memory [S1, unofficial].
- **Boundary Conditions**: Padding with zeros assumes the data is zero outside the domain. If the data has significant values near the boundary, this may introduce artifacts [S1, unofficial].
- **Degenerate Input**: If the input data has no x dimension, the method fails [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N \cdot U)$, where $N$ is the number of pixels and $U$ is the upsampling factor. The interpolation and padding steps dominate [S1, unofficial].
- **Memory Complexity**: $O(N \cdot U)$ for the upsampled data [S1, unofficial].
- **Strengths**: Accurately models the geometric stretching of oblique views [S1, unofficial]. Simple to implement using standard interpolation libraries [S1, unofficial].
- **Limitations**: Computationally expensive due to upsampling [S1, unofficial]. Assumes a regular grid [S1, unofficial]. Padding with zeros may introduce edge artifacts [S1, unofficial].
- **When to Use**: When generating multi-angle views for tomographic reconstruction or visualization where geometric accuracy is critical [S1, unofficial].
- **When Not to Use**: For real-time applications or when memory is constrained [S1, unofficial]. For near-nadir views where the distortion is negligible [S1, unofficial].

## Background
The method is described in the `hybridCT` repository [S1, unofficial], which focuses on hybrid cloud tomography. It is used to generate sinograms from 3D cloud fields for tomographic reconstruction [S1, unofficial]. The approach is based on the principle that an oblique view traverses a longer path through the volume, effectively scaling the data along the projection axis by the cosine of the viewing zenith angle [S1, unofficial].
