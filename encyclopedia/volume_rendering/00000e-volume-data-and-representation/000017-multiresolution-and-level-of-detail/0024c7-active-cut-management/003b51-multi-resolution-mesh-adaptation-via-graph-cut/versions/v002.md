# Multi-Resolution Mesh Adaptation via Graph Cut

Also called: Cut-based mesh refinement/coarsening, DAG-based mesh adaptation

## Overview
This method maintains a consistent, multi-resolution tetrahedral mesh by managing a "graph cut" through a Directed Acyclic Graph (DAG) of hierarchical mesh segments [S1]. It solves the problem of balancing visual fidelity and computational cost in interactive volume rendering by dynamically refining or coarsening the mesh representation [S1]. It sets itself apart from simple LOD techniques by guaranteeing a crack-free, non-overlapping mesh topology at all times through strict graph cut consistency conditions [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A DAG representing the multi-resolution mesh, where nodes are segments and edges are patches. Each segment contains precomputed error values. A user-specified maximal tetrahedra count $T_{max}$ [S1].
*   **Output:** A set of active patches forming a consistent mesh cut [S1].

**Data Structures:**
1.  **DAG:** Nodes represent segments. Each segment $S$ has:
    *   `ceiling`: The parent segment (or `None` if root).
    *   `floor`: A list of child segments.
    *   `patches_in`: List of patches connecting to the ceiling.
    *   `patches_out`: List of patches connecting to the floor.
    *   `error`: Precomputed error value associated with the segment [S1].
    *   `tet_count`: Number of tetrahedra represented by the segment's outgoing patches [G].
2.  **Cut Representation:** A list of active patches. A patch is active if it is part of the current mesh surface [S1].
3.  **Queues:**
    *   `coarsening_queue`: Contains patches that can be coarsened (all siblings active). Sorted by error ascending [S1].
    *   `refinement_queue`: Contains patches that can be refined (no preceding active patches on ceiling paths). Sorted by error descending [S1].

**Algorithm Steps:**

1.  **Initialization:**
    *   Load the root segment. Mark its outgoing patches as active.
    *   Populate `coarsening_queue` and `refinement_queue` based on initial consistency checks [S1].

2.  **Adaptation Loop:**
    *   **Step 2.1: Coarsening.**
        *   While `coarsening_queue` is not empty and current tetrahedra count $T < T_{max}$:
            *   Dequeue patch $P$ with highest priority (lowest error).
            *   Check consistency: All siblings of $P$ (other outgoing patches of $P$'s ceiling segment) must be active [S1].
            *   If consistent:
                *   Deactivate $P$.
                *   Activate all incoming patches of $P$'s ceiling segment (if not already active).
                *   Update $T$ (decrease by tetrahedra in $P$, increase by tetrahedra in incoming patches).
                *   Update queues: Add newly active patches to `refinement_queue` if they can be refined; remove $P$ from `coarsening_queue` [S1].
    *   **Step 2.2: Refinement.**
        *   While `refinement_queue` is not empty and current tetrahedra count $T < T_{max}$:
            *   Dequeue patch $P$ with highest priority (highest error).
            *   Check consistency: No active patches exist on any path from the root to the ceiling segment of $P$'s floor segments. If active preceding patches exist, they must be forced to refine first [S1].
            *   If consistent:
                *   Deactivate $P$.
                *   Activate all outgoing patches of $P$'s floor segment.
                *   Update $T$ (decrease by tetrahedra in $P$, increase by tetrahedra in outgoing patches).
                *   Update queues: Add newly active patches to `coarsening_queue` if they can be coarsened; remove $P$ from `refinement_queue` [S1].
    *   **Step 2.3: Forced Refinement (if necessary).**
        *   If a refinement is blocked by an active preceding patch, force that preceding patch to refine. This may cascade up the DAG. Recalculate $T$ and update queues [S1].

3.  **Caching:**
    *   Only load complete segments into memory.
    *   Discard a segment only if all its incoming and outgoing patches are inactive [S1].

**Pseudocode:**

```python
def adapt_mesh(dag, t_max):
    # dag contains segments. Each segment has:
    #   ceiling: parent segment or None
    #   floor: list of child segments
    #   patches_in: list of patches connecting to ceiling
    #   patches_out: list of patches connecting to floor
    # Each patch has:
    #   active: bool
    #   error: float
    #   tet_count: int
    #   ceiling_segment: reference to parent segment
    #   floor_segment: reference to child segment

    current_t = sum(p.tet_count for p in dag.active_patches())
    coarsening_q = []
    refinement_q = []

    for patch in dag.all_patches():
        if can_coarsen(patch):
            coarsening_q.append(patch)
        if can_refine(patch):
            refinement_q.append(patch)
    coarsening_q.sort(key=lambda p: p.error)
    refinement_q.sort(key=lambda p: p.error, reverse=True)

    while coarsening_q or refinement_q:
        # Step 1: Coarsen as many as possible
        while coarsening_q and current_t < t_max:
            patch = coarsening_q.pop(0)
            if not patch.active or not can_coarsen(patch):
                continue
            patch.active = False
            current_t -= patch.tet_count
            for sibling in patch.ceiling_segment.patches_out:
                if not sibling.active:
                    sibling.active = True
                    current_t += sibling.tet_count
                    if can_refine(sibling):
                        refinement_q.append(sibling)
            coarsening_q = [p for p in coarsening_q if p.active and can_coarsen(p)]
            coarsening_q.sort(key=lambda p: p.error)
            refinement_q = [p for p in refinement_q if p.active and can_refine(p)]
            refinement_q.sort(key=lambda p: p.error, reverse=True)

        # Step 2: Refine as many as necessary
        while refinement_q and current_t < t_max:
            patch = refinement_q.pop(0)
            if not patch.active or not can_refine(patch):
                continue
            preceding = get_preceding_active_patch(patch)
            if preceding is not None:
                preceding.active = False
                current_t -= preceding.tet_count
                for child in preceding.floor_segment.patches_out:
                    if not child.active:
                        child.active = True
                        current_t += child.tet_count
                        if can_coarsen(child):
                            coarsening_q.append(child)
                continue
            patch.active = False
            current_t -= patch.tet_count
            for child in patch.floor_segment.patches_out:
                if not child.active:
                    child.active = True
                    current_t += child.tet_count
                    if can_coarsen(child):
                        coarsening_q.append(child)
            coarsening_q = [p for p in coarsening_q if p.active and can_coarsen(p)]
            coarsening_q.sort(key=lambda p: p.error)
            refinement_q = [p for p in refinement_q if p.active and can_refine(p)]
            refinement_q.sort(key=lambda p: p.error, reverse=True)

        if not coarsening_q and not refinement_q:
            break

def can_coarsen(patch):
    for sibling in patch.ceiling_segment.patches_out:
        if sibling != patch and not sibling.active:
            return False
    return True

def can_refine(patch):
    current_seg = patch.ceiling_segment
    while current_seg is not None:
        for p in current_seg.patches_out:
            if p.active:
                return False
        current_seg = current_seg.ceiling
    return True

def get_preceding_active_patch(patch):
    current_seg = patch.ceiling_segment
    while current_seg is not None:
        for p in current_seg.patches_out:
            if p.active:
                return p
        current_seg = current_seg.ceiling
    return None
```

**Parameters:**
*   $T_{max}$: User-specified maximal tetrahedra count. Refinement is performed only if the resulting mesh does not exceed this number [S1].

**Edge Cases and Pitfalls:**
*   **Consistency Violation:** A patch can only be refined if all its ceiling segments do not have active patches preceding the ceiling segment on the path from roots. If they do, those preceding patches must be forced to refine to avoid overlap [S1].
*   **Precision:** Error values must be precomputed and stored with each segment. Errors increase from leaves to roots of the DAG [S1].

## Subtopics

### [Multi-triangulation](8962-multi-triangulation.md)
Multi-triangulation is a multi-resolution data structure for large unstructured tetrahedral meshes that uses a collection of hierarchical segments to enable local mesh adaptation. It solves the problem of efficiently rendering and simplifying massive meshes by allowing the mesh complexity to be adjusted at run time based on viewing parameters or attribute error, while guaranteeing a consistent mesh without cracks or intersecting tetrahedra.

### Error-Driven Direct Volume Rendering Adaptation
For direct volume rendering, all scalar attribute values of the mesh are normalized to the unit interval $[0,1]$ to support preintegration and quadric-based simplification [S1]. Each segment stores an error histogram $H$ for every attribute channel, containing the largest error within the segment for each attribute slot measured against the original tetrahedral mesh [S1]. These errors increase from the leaves of the DAG to the roots [S1]. The attribute error $E_a$ is weighted by the user-chosen classification opacity stored in a lookup table $C$ of resolution $N$, computed as:
$$E_a = V \sum_{n=1}^N H(n)C(n)$$
where each error value $H(n)$ is weighted by its classified opacity $C(n)$ [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Enables interactive direct volume rendering by dynamically adjusting mesh density [S1].
*   **Strengths:** Consistent mesh, out-of-core capability via segment caching, GPU-friendly execution [S1].
*   **Limitations:** Requires precomputed error values. Forced refinements can be costly [S1].
*   **When to use:** Interactive visualization of large unstructured tetrahedral meshes [S1].
*   **When not to use:** Static meshes where LOD is not needed, or when strict real-time performance is required without adaptive overhead [G].
