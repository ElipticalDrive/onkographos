# Multi-Resolution Mesh Adaptation via Graph Cut

Also called: Cut-based mesh refinement/coarsening, DAG-based mesh adaptation

## Overview
This method maintains a consistent, multi-resolution tetrahedral mesh by managing a "graph cut" through a Directed Acyclic Graph (DAG) of hierarchical mesh segments. It solves the problem of balancing visual fidelity and computational cost in interactive volume rendering by dynamically refining or coarsening the mesh representation. Unlike vertex-based multi-resolution models that require full mesh transfers to the GPU, this approach treats segments independently, enabling efficient out-of-core processing and direct GPU execution [S1]. It sets itself apart from simple LOD techniques by guaranteeing a crack-free, non-overlapping mesh topology at all times through strict graph cut consistency conditions [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A DAG representing the multi-resolution mesh, where nodes are segments and edges are patches. Each segment contains precomputed error values. A user-specified maximal tetrahedra count $T_{max}$.
*   **Output:** A set of active patches forming a consistent mesh cut.

**Data Structures:**
1.  **DAG:** Nodes represent segments. Each segment $S$ has:
    *   `ceiling`: The parent segment (or null if root).
    *   `floor`: A list of child segments.
    *   `patches_in`: List of patches connecting to the ceiling.
    *   `patches_out`: List of patches connecting to the floor.
    *   `error`: Precomputed error value associated with the segment.
    *   `active`: Boolean flag indicating if the segment's outgoing patches are part of the cut.
2.  **Cut Representation:** A list of active patches. A patch is active if it is part of the current mesh surface.
3.  **Queues:**
    *   `coarsening_queue`: Contains patches that can be coarsened (all siblings active). Sorted by error.
    *   `refinement_queue`: Contains patches that can be refined (no preceding active patches on ceiling paths). Sorted by error.

**Algorithm Steps:**

1.  **Initialization:**
    *   Load the root segment. Mark its outgoing patches as active.
    *   Populate `coarsening_queue` and `refinement_queue` based on initial consistency checks.

2.  **Adaptation Loop:**
    *   **Step 2.1: Coarsening.**
        *   While `coarsening_queue` is not empty and current tetrahedra count $T < T_{max}$:
            *   Dequeue patch $P$ with highest priority (lowest error).
            *   Check consistency: All siblings of $P$ (other outgoing patches of $P$'s ceiling segment) must be active.
            *   If consistent:
                *   Deactivate $P$.
                *   Activate all incoming patches of $P$'s ceiling segment (if not already active).
                *   Update $T$ (decrease by tetrahedra in $P$, increase by tetrahedra in incoming patches).
                *   Update queues: Add newly active patches to `refinement_queue` if they can be refined; remove $P$ from `coarsening_queue`.
    *   **Step 2.2: Refinement.**
        *   While `refinement_queue` is not empty and current tetrahedra count $T < T_{max}$:
            *   Dequeue patch $P$ with highest priority (highest error).
            *   Check consistency: No active patches exist on any path from the root to the ceiling segment of $P$'s floor segments. If active preceding patches exist, they must be forced to refine first [S1].
            *   If consistent:
                *   Deactivate $P$.
                *   Activate all outgoing patches of $P$'s floor segment.
                *   Update $T$ (decrease by tetrahedra in $P$, increase by tetrahedra in outgoing patches).
                *   Update queues: Add newly active patches to `coarsening_queue` if they can be coarsened; remove $P$ from `refinement_queue`.
    *   **Step 2.3: Forced Refinement (if necessary).**
        *   If a refinement is blocked by an active preceding patch, force that preceding patch to refine. This may cascade up the DAG. Recalculate $T$ and update queues.

3.  **Caching:**
    *   Only load complete segments into memory.
    *   Discard a segment only if all its incoming and outgoing patches are inactive [S1].

**Pseudocode:**

```python
def adapt_mesh(dag, t_max):
    current_t = count_tetrahedra(dag.active_patches)
    coarsening_q = PriorityQueue()
    refinement_q = PriorityQueue()
    
    # Initialize queues
    for patch in dag.active_patches:
        if can_coarsen(patch):
            coarsening_q.push(patch, patch.error)
        if can_refine(patch):
            refinement_q.push(patch, patch.error)
            
    while True:
        # Try to coarsen first
        while not coarsening_q.empty() and current_t < t_max:
            patch = coarsening_q.pop()
            if not can_coarsen(patch):
                continue # Stale entry
            
            # Coarsen
            current_t -= patch.tet_count
            patch.active = False
            for sibling in patch.ceiling.patches_out:
                if not sibling.active:
                    sibling.active = True
                    current_t += sibling.tet_count
                    if can_refine(sibling):
                        refinement_q.push(sibling, sibling.error)
            
            # Update queues for affected patches
            update_queues(patch, coarsening_q, refinement_q)
            
        # Then refine
        while not refinement_q.empty() and current_t < t_max:
            patch = refinement_q.pop()
            if not can_refine(patch):
                continue # Stale entry or blocked by preceding active patch
            
            # Check for forced refinement
            if has_preceding_active_patch(patch):
                forced_patch = get_preceding_active_patch(patch)
                # Force refine the preceding patch
                force_refine(forced_patch, dag, current_t, coarsening_q, refinement_q)
                continue # Re-evaluate current patch after forced refinement
            
            # Refine
            current_t -= patch.tet_count
            patch.active = False
            for child_patch in patch.floor.patches_out:
                child_patch.active = True
                current_t += child_patch.tet_count
                if can_coarsen(child_patch):
                    coarsening_q.push(child_patch, child_patch.error)
            
            # Update queues
            update_queues(patch, coarsening_q, refinement_q)
            
        if not coarsening_q.empty() or not refinement_q.empty():
            continue
        break

def can_coarsen(patch):
    # All siblings must be active
    for sibling in patch.ceiling.patches_out:
        if sibling != patch and not sibling.active:
            return False
    return True

def can_refine(patch):
    # No active patches on path from root to ceiling segment
    current = patch.ceiling
    while current is not None:
        if current.active: # Assuming active means the segment's outgoing patches are in cut
            # Check if any patch on the path is active
            # This requires traversing up and checking all ancestors' active status
            if has_active_ancestor(current):
                return False
        current = current.parent
    return True

def has_active_ancestor(segment):
    # Check if any segment on the path from root to this segment has active outgoing patches
    # that precede the current segment's ceiling
    current = segment
    while current is not None:
        if current.active:
            return True
        current = current.parent
    return False
```

**Parameters:**
*   $T_{max}$: User-specified maximal tetrahedra count. Refinement is performed only if the resulting mesh does not exceed this number [S1].

**Edge Cases and Pitfalls:**
*   **Consistency Violation:** A patch can only be refined if all its ceiling segments do not have active patches preceding the ceiling segment on the path from roots. If they do, those preceding patches must be forced to refine to avoid overlap [S1].
*   **Precision:** Error values must be precomputed and stored with each segment. Errors increase from leaves to roots of the DAG [S1].

## Subtopics

### [Multi-triangulation](8962-multi-triangulation.md)
Multi-triangulation is a multi-resolution data structure for large unstructured tetrahedral meshes that uses a collection of hierarchical segments to enable local mesh adaptation. It solves the problem of efficiently rendering and simplifying massive meshes by allowing the mesh complexity to be adjusted at run time based on viewing parameters or attribute error, while guaranteeing a consistent mesh without cracks or intersecting tetrahedra. Unlike vertex-based multi-resolution models that require full mesh transfer to the GPU and core memory storage, multi-triangulation treats segments independently, enabling efficient out-of-core processing and direct GPU execution.

## Operating characteristics
*   **Time Complexity:** Adaptation is $O(N \log N)$ where $N$ is the number of patches, due to queue operations. Consistency checks are $O(D)$ where $D$ is the depth of the DAG.
*   **Memory Complexity:** $O(S)$ where $S$ is the number of segments. Caching scheme ensures only active segments are loaded [S1].
*   **Performance:** Enables interactive direct volume rendering by dynamically adjusting mesh density [S1].
*   **Strengths:** Consistent mesh, out-of-core capability, GPU-friendly.
*   **Limitations:** Requires precomputed error values. Forced refinements can be costly.
*   **When to use:** Interactive visualization of large unstructured tetrahedral meshes.
*   **When not to use:** Static meshes where LOD is not needed, or when strict real-time performance is required without adaptive overhead.

## Background
Originated in the context of segment-based tetrahedral meshing and rendering [S1]. It is used in visualization systems supporting interactive direct volume rendering, isosurface extraction, and vector field visualization [S1].
