# Progressive Hierarchy with Multi-triangulation

Also called: Multi-triangulation LOD

## Overview
Progressive Hierarchy with Multi-triangulation is a dynamic Level-of-Detail (LOD) technique for volume rendering on unstructured grids that creates a progressive hierarchy of tetrahedra stored in a multi-triangulation data structure [S1, unofficial][S2, unofficial][S3, unofficial]. It solves the problem of interactive rendering performance by allowing the mesh to be dynamically updated and selectively refined to a target LOD using selection heuristics [S1, unofficial][S2, unofficial][S3, unofficial]. It differs from sibling methods by encoding all edge-collapse operations required to reduce the tetrahedral mesh to a base mesh, enabling dynamic reconstruction [S1, unofficial][S2, unofficial][S3, unofficial].

## How it works
**Inputs:** An unstructured tetrahedral grid; a target Level-of-Detail (LOD) metric or threshold; selection heuristics for determining which regions require refinement [S1, unofficial][S2, unofficial][S3, unofficial].
**Outputs:** A dynamically updated multi-triangulation mesh representation suitable for rendering [S1, unofficial][S2, unofficial][S3, unofficial].

**Data Structures:**
The core data structure is the **multi-triangulation model** [S1, unofficial][S2, unofficial][S3, unofficial]. This structure encodes the sequence of edge-collapse operations necessary to reduce the full-resolution tetrahedral mesh to a base mesh [S1, unofficial][S2, unofficial][S3, unofficial]. Specific field layouts or bit-packing details for the multi-triangulation structure are not given in the sources.

**Steps:**
1. **Model Creation:** Encode all edge-collapse operations required to reduce the number of tetrahedra in the input grid to a base mesh [S1, unofficial][S2, unofficial][S3, unofficial].
2. **LOD Selection:** Determine the desired LOD for the current frame using selection heuristics [S1, unofficial][S2, unofficial][S3, unofficial].
3. **Dynamic Update:** Selectively refine the mesh to the target LOD by applying the reverse of the recorded edge-collapse operations [S1, unofficial][S2, unofficial][S3, unofficial].
4. **Rendering:** Render the dynamically updated mesh to achieve interactive results [S1, unofficial][S2, unofficial][S3, unofficial].

**Parameters:**
*   **Selection Heuristics:** The specific criteria for choosing which edges to split or collapse are not given in the sources. [G] Typical implementations use error metrics such as camera distance or scalar value gradients.
*   **Base Mesh Resolution:** The resolution of the initial coarse mesh is not given in the sources.

**Edge Cases and Pitfalls:**
*   **Conformality:** Handling shared edges between adjacent tetrahedra during dynamic updates is not given in the sources. [G] Standard implementations track edge status globally to avoid non-manifold geometry.
*   **Precision:** Precision issues related to collapse distance relative to mesh scale are not given in the sources.
*   **Degenerate Input:** Handling of degenerate tetrahedra (zero volume) during simplification is not given in the sources.

## Subtopics

### Tetrahedral Hierarchy with Video Metaphor
A variant of the progressive hierarchy approach applied to time-varying volumetric data, proposed by Gregorski et al. [S4]. It represents the spatial component of the data as a hierarchy of tetrahedra, allowing level-of-detail control over the extracted mesh in each frame [S4]. To advance to the next frame, it refines or coarsens each node of the previous frame’s mesh [S4]. Unlike standard conformal refinement, it uses a lookup table to locally subdivide tetrahedra that do not align with their neighbors, rather than refining neighboring geometry [S4]. This approach improves run-time performance due to increased parallelizability but results in limited frame-to-frame coherence [S4].

*   **Time Complexity:** Dynamic updates allow for interactive rendering, but the exact complexity of applying edge-split operations is not given in the sources [S1, unofficial][S2, unofficial][S3, unofficial]. The video metaphor variant claims improved run-time performance due to parallelizability [S4].
*   **Memory Complexity:** The multi-triangulation structure stores all edge-collapse operations, which may require significant memory for high-resolution meshes [S1, unofficial][S2, unofficial][S3, unofficial]. Exact memory usage is not given in the sources.
*   **Measured Performance:** Specific performance metrics (FPS, memory usage) are not given in the sources [S1, unofficial][S2, unofficial][S3, unofficial][S4].
*   **Strengths:** Enables interactive rendering of unstructured grids by dynamically adjusting mesh complexity [S1, unofficial][S2, unofficial][S3, unofficial]. The video metaphor variant offers improved parallelizability [S4].
*   **Limitations:** The video metaphor variant has limited frame-to-frame coherence [S4].
*   **When to Use:** Suitable for interactive visualization of unstructured grid data where frame rates are critical [S1, unofficial][S2, unofficial][S3, unofficial]. The video metaphor variant is suitable for time-varying data where parallel processing is available [S4].

## Background
The technique was proposed by Cignoni et al. [S1, unofficial][S2, unofficial][S3, unofficial]. It builds on the multi-triangulation data structure introduced by Cignoni et al. [25] [S1, unofficial][S2, unofficial][S3, unofficial]. It appears in surveys of GPU-based volume rendering of unstructured grids [S1, unofficial][S2, unofficial][S3, unofficial]. The video metaphor variant was introduced by Gregorski et al. [S4] for time-varying data.
