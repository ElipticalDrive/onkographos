# Hierarchy of Tetrahedra (HT)
Also called: Hierarchical Tetrahedral (HT) Mesh Extraction, Regular Multi-Tessellation, nested tetrahedral meshes, regular multiresolution model

## Overview
The Hierarchy of Tetrahedra (HT) is a multiresolution representation for structured volume data that uses nested tetrahedral meshes generated by recursive bisection of a base mesh [S1]. It solves the problem of representing scalar fields on regular grids at variable levels of detail while maintaining mesh connectivity and adjacency information without explicit storage [S1]. Unlike its sibling [Multi-Tetra Framework](1183-multi-tetra-framework.md), which supports both structured and unstructured data via flexible vertex splits, HT is specific to structured datasets and relies on a fixed, regular decomposition rule, resulting in lower storage costs but potentially higher tetrahedron counts for uniform LOD [S1].

## How it works
**Inputs:** A structured volume dataset consisting of $n$ points on a regular grid, each associated with a scalar field value.
**Outputs:** A multiresolution data structure allowing extraction of tetrahedral meshes at various levels of detail (LOD) via selective refinement.

### Data Structures
The HT data structure encodes a forest of six almost full binary trees, one for each of the six initial tetrahedra of the base mesh [S1]. It does not store explicit topology (adjacency/dependency) but derives it from the tree structure [S1].

1.  **Field Table:** An array storing the scalar field values at the $n$ data points.
2.  **Error Forest:** An array representing a forest of six binary trees. Each tree corresponds to the recursive subdivision of one of the six initial tetrahedra. The nodes store the approximation error associated with the tetrahedron. The leaves correspond to the reference mesh tetrahedra, which have null error [S1].
3.  **Location Codes:** Each tetrahedron is indexed by a location code used to access the field table and error forest. A location code consists of:
    *   The level of the tetrahedron in the binary tree.
    *   The path number from the root to the tetrahedron [S1].

**Storage Cost:**
*   Error values: $12n$ bytes [S1].
*   Field table: $2n$ bytes (assuming 2 bytes per value) [S1].
*   Total: $14n$ bytes [S1].

### Base Mesh Definition
The domain is a cubic volume. The base mesh is defined by decomposing the initial cubic domain into six tetrahedra. This is achieved by decomposing the cube into six 1/8 pyramids (pyramids with a square base and height equal to 1/8 of the cube's side, meeting at the center) and then splitting each pyramid into two tetrahedra [S1].

### Refinement Rule: Tetrahedron Bisection
Refinement is performed via recursive tetrahedron bisection [S1].
1.  Identify the longest edge of the tetrahedron.
2.  Find the midpoint of this longest edge.
3.  Split the tetrahedron into two children using the plane passing through the midpoint and the opposite edge (the edge not incident to the midpoint) [S1].

This bisection rule is applied recursively. Regardless of the depth, the resulting tetrahedra fall into one of three geometric shapes, which are cyclic every three levels of decomposition [S1]:
*   **1/2 Pyramid:** Formed by splitting a pyramid with a square base in half along a diagonal plane.
*   **1/4 Pyramid:** A thinner variant.
*   **1/8 Pyramid:** The base shape.

The circumradius-to-shortest-edge ratio ($r$) characterizes the shape quality:
*   Average $r = 0.91$ [S1].
*   Minimum $r = 0.75$ (1/2 pyramid) [S1].
*   Maximum $r = 1.19$ (1/4 pyramid) [S1] [G: This ratio is calculated as $R_{circum} / L_{min}$].

### Selective Refinement and Mesh Extraction
Selective refinement extracts meshes at variable resolution by determining which tetrahedra to split based on error thresholds [S1].

**Neighbor Finding:**
To ensure continuity (avoid cracks) at transition areas between different resolution levels, the algorithm requires finding neighboring tetrahedra in constant time [S1]. This is achieved using simple arithmetic and bit-wise operations on the ordering of tetrahedra, derived from their location codes [S1].

**Cluster Updates:**
An update (splitting a tetrahedron) is defined by a cluster of tetrahedra. In HT, clusters are categorized into three types based on the orientation of the split relative to the grid axes:
1.  Axis-aligned clusters.
2.  Plane-aligned clusters.
3.  Non-aligned clusters [S1].

The number of tetrahedra in a cluster (first component of the update) and the split-set (second component, the new tetrahedra added) varies:
*   Clusters contain 4, 6, or 8 tetrahedra.
*   Split-sets contain 8, 12, or 16 tetrahedra [S1].
*   On average, an update adds 6 tetrahedra to the mesh [S1].

**Vertex Computation:**
When traversing the forest to determine spatial location, the algorithm computes the midpoint of the longest edge of the parent tetrahedron. All other vertices of the child tetrahedra are obtained directly from the vertices of the parent tetrahedron, avoiding complex geometric calculations [S1].

### Pseudocode
The following pseudocode illustrates the construction of the location code and the bisection logic. It assumes a standard indexing scheme where the root is at index 0.

```python
def compute_location_code(tet_index, level):
    """
    Computes the location code for a tetrahedron.
    tet_index: The index of the tetrahedron in the linearized tree array.
    level: The depth of the tetrahedron in the hierarchy.
    Returns: A tuple (level, path_number)
    """
    # The path number is derived from the binary representation of the index
    # or a specific labeling scheme defined in the source [S1].
    # For a binary tree stored in an array, the path is often the sequence
    # of left/right choices.
    path_number = tet_index 
    return (level, path_number)

def bisect_tetrahedron(parent_vertices, parent_tet_index):
    """
    Performs one step of tetrahedron bisection.
    parent_vertices: List of 4 vertex coordinates [v0, v1, v2, v3].
    parent_tet_index: Index used to determine the longest edge based on 
                       precomputed edge lengths or a fixed rule based on index parity.
    Returns: List of 2 child tetrahedra, each defined by 4 vertices.
    """
    # 1. Identify the longest edge.
    # In a regular grid HT, the longest edge is often determined by the 
    # orientation of the tetrahedron (axis-aligned, etc.) or by comparing 
    # squared distances between vertices.
    # Let's assume we identify indices i, j such that |vi - vj| is max.
    i, j = find_longest_edge_indices(parent_vertices)
    
    # 2. Compute midpoint of the longest edge.
    mid = (parent_vertices[i] + parent_vertices[j]) / 2.0
    
    # 3. Identify the opposite edge.
    # The opposite edge consists of the two vertices not in {i, j}.
    remaining = [k for k in range(4) if k != i and k != j]
    k, l = remaining[0], remaining[1]
    
    # 4. Form two children.
    # Child 1: vertices {i, j, k, mid}
    # Child 2: vertices {i, j, l, mid}
    # Note: The specific connectivity depends on the bisection rule 
    # ensuring the plane passes through mid and the opposite edge (k, l).
    child1 = [parent_vertices[i], parent_vertices[j], parent_vertices[k], mid]
    child2 = [parent_vertices[i], parent_vertices[j], parent_vertices[l], mid]
    
    return [child1, child2]

def extract_mesh(error_threshold, field_table, error_forest, base_mesh_tets):
    """
    Extracts a tetrahedral mesh by selectively refining the base mesh.
    error_threshold: Scalar value. Tetrahedra with error > threshold are split.
    field_table: Array of field values at grid points.
    error_forest: Array of errors for all tetrahedra in the hierarchy.
    base_mesh_tets: List of initial 6 tetrahedra.
    Returns: List of tetrahedra in the final mesh.
    """
    # Initialize mesh with base mesh tetrahedra
    mesh_tets = list(base_mesh_tets)
    
    # Queue for tetrahedra to process
    queue = list(range(len(base_mesh_tets)))
    
    while queue:
        tet_idx = queue.pop(0)
        
        # Get error for this tetrahedron
        # The error is stored in the error_forest at an index derived from 
        # the location code or linear index.
        error = get_error_from_forest(tet_idx, error_forest)
        
        if error > error_threshold:
            # Split the tetrahedron
            # We need the vertices of the current tetrahedron.
            # In a hierarchical structure, vertices are derived from parents.
            # For implementation, we might need to resolve the vertex coordinates
            # from the location code or store them.
            # Assuming we can retrieve vertices for tet_idx:
            vertices = get_vertices_for_tetrahedron(tet_idx, base_mesh_tets, error_forest)
            
            children = bisect_tetrahedron(vertices, tet_idx)
            
            # Remove parent from mesh
            mesh_tets.remove(tet_idx) # Or mark as inactive
            
            # Add children to mesh and queue
            # New indices must be assigned.
            new_idx_1 = len(mesh_tets)
            new_idx_2 = new_idx_1 + 1
            
            mesh_tets.append(new_idx_1)
            mesh_tets.append(new_idx_2)
            
            queue.append(new_idx_1)
            queue.append(new_idx_2)
        else:
            # Keep tetrahedron
            pass
            
    return mesh_tets
```

## Operating characteristics
**Time Complexity:** Selective refinement relies on constant-time neighbor finding and simple arithmetic/bit-wise operations for parent/child lookup [S1]. The complexity depends on the number of tetrahedra to be refined.
**Memory Complexity:** The storage cost is linear with respect to the number of data points $n$, specifically $14n$ bytes for the HT structure (errors and field values) [S1]. This is approximately half the cost of an edge-based Multi-Tessellation (MT), which requires $30n$ to $49n$ bytes [S1].
**Performance:**
*   **Uniform LOD:** HT produces more tetrahedra than MT for uniform LOD queries because MT offers more flexibility in choosing which tetrahedra to split, whereas HT uses a fixed decomposition rule [S1]. For example, in the Smallbucky dataset (32,768 vertices), HT uses 196,608 tetrahedra at full resolution, while MT uses 163,840 [S1].
*   **Variable LOD (Region/Field-based):** HT performs better than MT in terms of extracted mesh size (fewer tetrahedra) for variable LOD queries, such as region-based or field-value-based (isosurface) extraction [S1]. HT extracts fewer tetrahedra but more faces than MT, indicating it is better at pruning irrelevant tetrahedra from the isosurface field value [S1].
*   **Mesh Quality:** HT tetrahedra have a better shape quality (average circumradius-to-shortest-edge ratio $r=0.91$) compared to edge-based MT ($r=1.38$) [S1]. This results in better visual quality of extracted isosurfaces [S1].
**Limitations:**
*   HT is specific to structured data sets; it cannot handle unstructured data [S1].
*   Adaptive refinement can cause discontinuities (cracks) at transition areas if not handled by constant-time neighbor finding [S1].
*   Out-of-core extraction for huge datasets is an open research problem [S1].

## Background
The Hierarchy of Tetrahedra (HT) was introduced in the context of finite element analysis and scientific visualization [S1]. It is based on nested tetrahedral meshes generated by recursive decomposition, specifically tetrahedron bisection [S1]. The method was compared with the Edge-based Multi-Tessellation (MT) in the paper "Multiresolution tetrahedral meshes: an analysis and a comparison" [S1]. The HT approach leverages the regularity of structured data to avoid storing explicit topology, relying instead on the geometric properties of the recursive bisection [S1].
