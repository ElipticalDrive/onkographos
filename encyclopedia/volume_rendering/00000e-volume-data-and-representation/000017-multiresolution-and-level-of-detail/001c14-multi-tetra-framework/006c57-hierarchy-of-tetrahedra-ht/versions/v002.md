# Hierarchy of Tetrahedra (HT)
Also called: Hierarchical Tetrahedral (HT) Mesh Extraction, Regular Multi-Tessellation, nested tetrahedral meshes, regular multiresolution model

## Overview
The Hierarchy of Tetrahedra (HT) is a multiresolution representation for structured volume data that uses nested tetrahedral meshes generated by recursive bisection of a base mesh [S1]. It solves the problem of representing scalar fields on regular grids at variable levels of detail while maintaining mesh connectivity and adjacency information without explicit storage [S1]. Unlike its sibling [Multi-Tetra Framework](1183-multi-tetra-framework.md), which supports both structured and unstructured data via flexible vertex splits, HT is specific to structured datasets and relies on a fixed, regular decomposition rule, resulting in lower storage costs but potentially higher tetrahedron counts for uniform LOD [S1].

## How it works
**Inputs:** A structured volume dataset consisting of $n$ points on a regular grid, each associated with a scalar field value [S1].
**Outputs:** A multiresolution data structure allowing extraction of tetrahedral meshes at various levels of detail (LOD) via selective refinement [S1].

### Data Structures
The HT data structure encodes a forest of six almost full binary trees, one for each of the six initial tetrahedra of the base mesh [S1]. It does not store explicit topology (adjacency/dependency) but derives it from the tree structure [S1].

1.  **Field Table:** An array storing the scalar field values at the $n$ data points [S1].
2.  **Error Forest:** An array representing a forest of six binary trees [S1]. Each tree corresponds to the recursive subdivision of one of the six initial tetrahedra [S1]. The nodes store the approximation error associated with the tetrahedron [S1]. The leaves correspond to the reference mesh tetrahedra, which have null error [S1].
3.  **Location Codes:** Each tetrahedron is indexed by a location code used to access the field table and error forest [S1]. A location code consists of the level of the tetrahedron in the binary tree and the path number from the root to the tetrahedron [S1].

**Storage Cost:**
*   Error values: $12n$ bytes [S1].
*   Field table: $2n$ bytes (assuming 2 bytes per value) [S1].
*   Total: $14n$ bytes [S1].

### Base Mesh Definition
The domain is a cubic volume [S1]. The base mesh is defined by the decomposition of the initial cubic domain into six 1/8 pyramids [S1].

### Refinement Rule: Tetrahedron Bisection
Refinement is performed via recursive tetrahedron bisection [S1].
1.  Identify the longest edge of the tetrahedron [S1].
2.  Find the midpoint of this longest edge [S1].
3.  Split the tetrahedron into two children using the plane passing through the midpoint and the opposite edge (the edge not incident to the midpoint) [S1].

This bisection rule is applied recursively [S1]. Regardless of the depth, the resulting tetrahedra fall into one of three geometric shapes, which are cyclic every three levels of decomposition [S1]:
*   **1/2 Pyramid:** Formed by splitting a pyramid with a square base in half along a diagonal plane [S1].
*   **1/4 Pyramid:** A thinner variant [S1].
*   **1/8 Pyramid:** The base shape [S1].

The circumradius-to-shortest-edge ratio ($r$) characterizes the shape quality [S1]:
*   Average $r = 0.91$ [S1].
*   Minimum $r = 0.75$ (1/2 pyramid) [S1].
*   Maximum $r = 1.19$ (1/4 pyramid) [S1].

### Selective Refinement and Mesh Extraction
Selective refinement is the basic operation for extracting meshes at variable resolution [S1]. It traverses the error forest to identify tetrahedra whose associated error exceeds a threshold, triggering a split [S1].

**Neighbor Finding:**
To ensure continuity (avoid cracks) at transition areas between different resolution levels, the algorithm requires finding neighboring tetrahedra in constant time [S1]. This is achieved using simple arithmetic and bit-wise operations on the ordering of tetrahedra, derived from their location codes [S1].

**Cluster Updates:**
An update (splitting a tetrahedron) is defined by a cluster of tetrahedra [S1]. In HT, clusters are categorized into three types based on the orientation of the split relative to the grid axes: axis-aligned, plane-aligned, and non-aligned clusters [S1].

The number of tetrahedra in a cluster (first component of the update) and the split-set (second component, the new tetrahedra added) varies [S1]:
*   Clusters contain 4, 6, or 8 tetrahedra [S1].
*   Split-sets contain 8, 12, or 16 tetrahedra [S1].
*   On average, an update adds 6 tetrahedra to the mesh [S1].

**Vertex Computation:**
When traversing the forest to determine spatial location, the algorithm computes the midpoint of the longest edge of the parent tetrahedron [S1]. All other vertices of the child tetrahedra are obtained directly from the vertices of the parent tetrahedron, avoiding complex geometric calculations [S1].

### Pseudocode
The following pseudocode illustrates the construction of the location code, the bisection logic, and the selective refinement process. It assumes a standard indexing scheme where the root is at index 0.

```python
import math

def compute_location_code(tree_index, level):
    """
    Computes the location code for a tetrahedron.
    tree_index: The index of the tetrahedron in the linearized tree array.
    level: The depth of the tetrahedron in the hierarchy.
    Returns: A tuple (level, path_number)
    """
    return (level, tree_index)

def find_longest_edge_indices(vertices):
    """
    Identifies the indices of the longest edge among 4 vertices.
    vertices: List of 4 tuples (x, y, z).
    Returns: Tuple of two indices (i, j).
    """
    max_len_sq = -1.0
    edge_indices = (0, 1)
    for i in range(4):
        for j in range(i + 1, 4):
            dx = vertices[i][0] - vertices[j][0]
            dy = vertices[i][1] - vertices[j][1]
            dz = vertices[i][2] - vertices[j][2]
            len_sq = dx*dx + dy*dy + dz*dz
            if len_sq > max_len_sq:
                max_len_sq = len_sq
                edge_indices = (i, j)
    return edge_indices

def bisect_tetrahedron(vertices):
    """
    Performs one step of tetrahedron bisection.
    vertices: List of 4 vertex coordinates [v0, v1, v2, v3].
    Returns: List of 2 child tetrahedra, each defined by 4 vertices.
    """
    i, j = find_longest_edge_indices(vertices)
    mid = ((vertices[i][0] + vertices[j][0]) / 2.0,
           (vertices[i][1] + vertices[j][1]) / 2.0,
           (vertices[i][2] + vertices[j][2]) / 2.0)
    remaining = [k for k in range(4) if k != i and k != j]
    k, l = remaining[0], remaining[1]
    child1 = [vertices[i], vertices[j], vertices[k], mid]
    child2 = [vertices[i], vertices[j], vertices[l], mid]
    return [child1, child2]

def get_error_from_forest(error_forest, tree_index):
    """
    Retrieves the approximation error for a tetrahedron from the flat error forest array.
    error_forest: Array of errors indexed by tree_index.
    tree_index: Index of the tetrahedron in the linearized tree.
    Returns: Float error value.
    """
    return error_forest[tree_index]

def extract_mesh(error_threshold, field_table, error_forest, base_mesh_vertices):
    """
    Extracts a tetrahedral mesh by selectively refining the base mesh.
    error_threshold: Scalar value. Tetrahedra with error > threshold are split.
    field_table: Array of field values at grid points.
    error_forest: Array of errors for all tetrahedra in the hierarchy.
    base_mesh_vertices: List of initial 6 tetrahedra.
    Returns: List of tetrahedra in the final mesh.
    """
    mesh_tets = [list(tet) for tet in base_mesh_vertices]
    queue = [(compute_location_code(i, 0), i) for i in range(len(base_mesh_vertices))]

    while queue:
        loc_code, tet_idx = queue.pop(0)
        error = get_error_from_forest(error_forest, loc_code[1])

        if error > error_threshold:
            children = bisect_tetrahedron(mesh_tets[tet_idx])
            mesh_tets[tet_idx] = None
            idx1 = len(mesh_tets)
            idx2 = idx1 + 1
            mesh_tets.append(children[0])
            mesh_tets.append(children[1])
            queue.append((compute_location_code(idx1, loc_code[0] + 1), idx1))
            queue.append((compute_location_code(idx2, loc_code[0] + 1), idx2))

    return [tet for tet in mesh_tets if tet is not None]
```

## Operating characteristics
**Time Complexity:** Selective refinement relies on constant-time neighbor finding and simple arithmetic/bit-wise operations for parent/child lookup [S1]. The complexity depends on the number of tetrahedra to be refined [S1].
**Memory Complexity:** The storage cost is linear with respect to the number of data points $n$, specifically $14n$ bytes for the HT structure (errors and field values) [S1]. This is approximately half the cost of an edge-based Multi-Tessellation (MT), which requires $30n$ to $49n$ bytes [S1].
**Performance:**
*   **Uniform LOD:** HT produces more tetrahedra than MT for uniform LOD queries because MT offers more flexibility in choosing which tetrahedra to split, whereas HT uses a fixed decomposition rule [S1]. For example, in the Smallbucky dataset (32,768 vertices), HT uses 196,608 tetrahedra at full resolution, while MT uses 163,840 [S1].
*   **Variable LOD (Region/Field-based):** HT performs better than MT in terms of extracted mesh size (fewer tetrahedra) for variable LOD queries, such as region-based or field-value-based (isosurface) extraction [S1]. HT extracts fewer tetrahedra but more faces than MT, indicating it is better at pruning irrelevant tetrahedra from the isosurface field value [S1].
*   **Mesh Quality:** HT tetrahedra have a better shape quality (average circumradius-to-shortest-edge ratio $r=0.91$) compared to edge-based MT ($r=1.38$) [S1]. The better shape of the tetrahedra, captured by the circumradius-to-shortest-edge ratio, is reflected in the visual quality of the extracted isosurfaces [S1].
**Limitations:**
*   HT is specific to structured data sets; it cannot handle unstructured data [S1].
*   Adaptive refinement can cause discontinuities (cracks) at transition areas if not handled by constant-time neighbor finding [S1].
*   Out-of-core extraction for huge datasets is an open research problem [S1].

## Background
The Hierarchy of Tetrahedra (HT) was introduced in the context of finite element analysis and scientific visualization [S1]. It is based on nested tetrahedral meshes generated by recursive decomposition, specifically tetrahedron bisection [S1]. The method was compared with the Edge-based Multi-Tessellation (MT) in the paper "Multiresolution tetrahedral meshes: an analysis and a comparison" [S1]. The HT approach leverages the regularity of structured data to avoid storing explicit topology, relying instead on the geometric properties of the recursive bisection [S1].
