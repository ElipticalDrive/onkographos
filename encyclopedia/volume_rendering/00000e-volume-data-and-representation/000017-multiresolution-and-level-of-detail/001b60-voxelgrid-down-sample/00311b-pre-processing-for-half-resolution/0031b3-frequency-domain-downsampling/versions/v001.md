# Frequency-Domain Downsampling

Also called: 3D Downsampling Module, FFT-based Downsampling, Fourier Downsampling

## Overview
Frequency-Domain Downsampling is a non-learnable pre-processing method that reduces the resolution of volumetric data by transforming it into the frequency domain, applying a low-pass filter, and transforming it back to the spatial domain [S1]. It solves the problem of reducing data size while preserving essential low-frequency information, avoiding the aliasing artifacts associated with direct subsampling [S1]. Unlike its sibling methods that may rely on learned kernels or spatial averaging, this approach explicitly separates frequency components, allowing for controllable downsampling scales (e.g., ×1/2, ×1/4, ×1/8) without training [S1].

## How it works
**Inputs and Outputs:**
- Input: High-resolution volume $x$ of shape $(N_x, N_y, N_z)$.
- Output: Low-resolution volume $y$ of shape $(N_x/S, N_y/S, N_z/S)$, where $S$ is the downsampling scale factor.

**Data Structures:**
- The input $x$ is a 3D array of voxel intensities.
- The filter $D$ is a 3D array of complex coefficients matching the frequency domain dimensions.
- The noise term $n$ is a 3D array of the same shape as the output $y$.

**Parameters:**
- $S$: Downsampling scale factor. Typical values are 2, 4, and 8 [S1].
- $D$: Low-pass filter operator. It must be designed to pass frequencies below the Nyquist limit of the target resolution and attenuate higher frequencies [S1].
- $n$: Noise term added to the output [S1].

**Steps:**
1. **Forward Transform:** Compute the 3D Fast Fourier Transform (FFT) of the input volume $x$ to obtain the high-resolution frequency representation $F_{HR}(x)$.
2. **Filtering:** Multiply the frequency representation by the low-pass filter $D$. This operation eliminates high-frequency components that would cause aliasing upon downsampling.
3. **Inverse Transform:** Compute the inverse FFT of the filtered frequency data, but using the grid parameters of the low-resolution regime. This yields the spatial domain representation at the lower resolution.
4. **Noise Addition:** Add a noise term $n$ to the result to produce the final output $y$.

**Formula:**
The relationship between the input $x$ and output $y$ is defined as [S1]:

$$
y = F_{LR}^{-1} D F_{HR} x + n
$$

Where:
- $x$: High-resolution input volume.
- $y$: Low-resolution output volume.
- $F_{HR}$: FFT operator for the high-resolution regime (input grid size).
- $F_{LR}^{-1}$: Inverse FFT operator for the low-resolution regime (output grid size).
- $D$: Low-pass filter in the frequency domain.
- $n$: Noise term.

**Pseudocode:**
```python
import numpy as np

def frequency_domain_downsample(x, scale_factor, noise_std=0.0):
    """
    Reduces the resolution of a 3D volume using frequency-domain filtering.
    
    Args:
        x: numpy array of shape (H, W, D), high-resolution volume.
        scale_factor: int, downsampling scale (e.g., 2, 4, 8).
        noise_std: float, standard deviation of additive noise.
        
    Returns:
        y: numpy array of shape (H/scale, W/scale, D/scale), low-resolution volume.
    """
    # Step 1: Apply high-resolution FFT
    # F_HR(x) computes the 3D FFT of the input volume
    freq_domain = np.fft.fftn(x)
    
    # Step 2: Apply low-pass filter D
    # The filter D must be constructed to match the frequency grid of freq_domain.
    # It should pass low frequencies and attenuate high frequencies based on scale_factor.
    # For a scale factor S, the cutoff frequency is typically 1/(2*S) of the Nyquist frequency.
    # Implementation of D depends on specific filter design (e.g., ideal, Gaussian, Butterworth).
    # Here we assume a function create_lowpass_filter exists that generates D.
    D = create_lowpass_filter(freq_domain.shape, scale_factor)
    
    # Multiply by filter in frequency domain
    filtered_freq = freq_domain * D
    
    # Step 3: Apply inverse low-resolution FFT
    # F_LR^-1 implies transforming back to spatial domain at the lower resolution.
    # Standard practice: Crop the frequency domain to the lower resolution size 
    # before inverse transform, or resize the spatial domain after inverse transform.
    # The source formula suggests F_LR^-1 acts on the filtered data.
    # To achieve the target shape (H/S, W/S, D/S), we typically:
    # 1. Crop the frequency spectrum to the lower resolution dimensions.
    # 2. Apply inverse FFT.
    
    new_shape = (x.shape[0] // scale_factor, 
                 x.shape[1] // scale_factor, 
                 x.shape[2] // scale_factor)
    
    # Crop frequency domain to center (low frequencies)
    # Note: np.fft.fftfreq logic applies. We keep the center portion.
    # This step effectively implements the "low-resolution regime" inverse transform.
    cropped_freq = crop_frequency_spectrum(filtered_freq, new_shape)
    
    # Inverse FFT to get spatial domain
    y_spatial = np.fft.ifftn(cropped_freq).real
    
    # Step 4: Add noise term n
    if noise_std > 0:
        noise = np.random.normal(0, noise_std, y_spatial.shape)
        y = y_spatial + noise
    else:
        y = y_spatial
        
    return y

def create_lowpass_filter(shape, scale_factor):
    """
    Creates a 3D low-pass filter.
    An ideal low-pass filter is used here for simplicity, though others exist.
    """
    # Create coordinate grids
    axes = [np.fft.fftfreq(d) for d in shape]
    grid = np.meshgrid(*axes, indexing='ij')
    
    # Calculate normalized frequency distance from center
    # For ideal filter, cutoff is 1/(2*scale_factor)
    cutoff = 1.0 / (2.0 * scale_factor)
    
    # Distance from center in frequency space
    dist = np.sqrt(sum(g**2 for g in grid))
    
    # Ideal low-pass filter: 1 if dist <= cutoff, 0 otherwise
    D = (dist <= cutoff).astype(np.float32)
    
    return D

def crop_frequency_spectrum(freq_data, target_shape):
    """
    Crops the frequency domain data to the target lower resolution.
    Keeps the center low-frequency components.
    """
    # Calculate start and end indices for each dimension
    slices = []
    for i, (orig_dim, target_dim) in enumerate(zip(freq_data.shape, target_shape)):
        start = (orig_dim - target_dim) // 2
        end = start + target_dim
        slices.append(slice(start, end))
    
    return freq_data[tuple(slices)]
```

**Edge Cases and Pitfalls:**
- **Aliasing:** If the low-pass filter $D$ is not sufficiently aggressive, high-frequency components will alias into the lower resolution, causing artifacts [S1].
- **Boundary Effects:** FFT assumes periodic boundary conditions. If the volume has sharp discontinuities at the boundaries, ringing artifacts may occur. Windowing functions can mitigate this but are not specified in the source [S1].
- **Non-Standard Scales:** The source notes that non-standard scales like 1/3, 1/5, or 1/7 introduce unnecessary complexity and inconsistencies, so standard integer factors (2, 4, 8) are recommended [S1].
- **Noise:** The noise term $n$ is included in the formula but its purpose (e.g., regularization, privacy, or specific reconstruction requirements) is not detailed in the source [S1].

## Operating characteristics
- **Time Complexity:** Dominated by the FFT operations, which are $O(N \log N)$ where $N$ is the number of voxels. The filtering step is $O(N)$.
- **Memory Complexity:** Requires storage for the input volume, the frequency domain representation (complex numbers, so 2x memory for real input), the filter, and the output volume.
- **Performance:** The method is efficient and does not require training, making it suitable for real-time or pre-processing stages [S1].
- **Strengths:** Controllable downsampling scales; preserves low-frequency information; no training required [S1].
- **Limitations:** May lose high-frequency details; sensitive to filter design; assumes periodic boundaries [S1].
- **When to Use:** When reducing data size for subsequent processing (e.g., INR, SR) without the overhead of training a downsampling network [S1].
- **When Not to Use:** When high-frequency detail preservation is critical and cannot be approximated by low-pass filtering [S1].

## Background
The method originates from the work of Sheibani Fard et al. in 2026, presented in "An end-to-end implicit neural representation architecture for medical volume data" [S1]. It is part of an end-to-end architecture that includes an Implicit Neural Representation (INR) and a Super-Resolution (SR) module. The downsampling module is designed to be non-learnable, serving as a pre-processing step to reduce the computational load for the INR module [S1]. The use of Fourier Transform in medical imaging is well-established, and this method adapts it for volumetric downsampling [S1].
