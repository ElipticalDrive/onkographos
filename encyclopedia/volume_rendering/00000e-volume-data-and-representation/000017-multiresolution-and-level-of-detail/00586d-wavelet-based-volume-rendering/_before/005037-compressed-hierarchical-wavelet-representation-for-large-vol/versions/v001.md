# Compressed Hierarchical Wavelet Representation for Large Volumes

Also called: Guthe et al. wavelet rendering

## Overview
This method enables the interactive rendering of massive volume datasets (e.g., >30 GB) that exceed available video memory by storing data in a compressed hierarchical wavelet format and decompressing it on-the-fly [S1]. It differs from sibling methods by explicitly targeting out-of-core or memory-constrained hardware through software-based decompression and run-length Huffman coding, rather than relying solely on hardware texture compression or adaptive grid structures [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A large volume dataset (e.g., Visible Human data) stored in a compressed hierarchical wavelet representation.
*   **Output:** Rendered image frames using hardware texture mapping.

**Data Structures:**
The volume is represented hierarchically using wavelets. The specific bit-packing layout of the wavelet coefficients is not detailed in the sources [G]. The compression scheme uses run-length encoding followed by Huffman coding [S1].

**Steps:**
1.  **Compression:** The original volume data is transformed into a hierarchical wavelet representation and compressed using run-length Huffman coding [S1].
2.  **Level-of-Detail (LOD) Selection:** For each frame, determine the required level of detail based on the current camera view and a defined error metric [S1].
3.  **Decompression:** Decompress the selected wavelet coefficients on-the-fly in software [S1]. The decompression rate is approximately 50 MB/s [S1].
4.  **Caching:** Cache the decompressed data in memory to reuse for subsequent frames, improving performance [S1].
5.  **Rendering:** Transfer the decompressed data to video memory and render using hardware texture mapping [S1].

**Parameters:**
*   **Compression Ratio:** A ratio of 30:1 can be used without introducing visually noticeable artifacts [S1].

**Pitfalls:**
*   **Memory Limits:** For datasets larger than main memory, the technique must be generalized for out-of-core rendering [S1].
*   **Decompression Speed:** The software decompression rate (50 MB/s) is a bottleneck; caching is required to maintain interactivity [S1].

## Subtopics

### Wavelet-Based Adaptive Grid Volume Rendering
A technique that visualizes data represented by a superposition of scaling functions on a coarse regular grid and wavelets on an adaptive mesh [S2]. It capitalizes on sparse data representation and wavelet compression, specifically tailored for visualization of compressed solutions on wavelet-based adaptive computational meshes [S2]. Unlike the compressed hierarchical method which focuses on large static volumes in memory-constrained settings, this variant emphasizes adaptive meshes for time-dependent data [S2].

## Operating characteristics
*   **Performance:** Interactive rendering of the 39 GB Visible Human female dataset was achieved on a single 2 GHz Pentium 4 PC with an nVidia GeForce 4 [S1].
*   **Decompression Rate:** Approximately 50 MB/s using run-length Huffman coding [S1].
*   **Compression:** Achieves a 30:1 compression ratio with no visually noticeable artifacts [S1].
*   **Scalability:** Can be generalized for out-of-core rendering for data larger than main memory [S1].
*   **Strengths:** Enables rendering of volumes far exceeding video memory capacity; leverages hardware texture mapping for rendering efficiency [S1].
*   **Limitations:** Relies on software decompression which is slower than hardware decompression; performance is limited by decompression speed (50 MB/s) [S1].

## Background
Developed by Guthe et al., this method addresses the limitation of hardware-accelerated volume rendering, which requires loading entire volume data into texture memory [S1]. It was presented in the context of recent advances in hardware-accelerated volume rendering, citing the Visible Human dataset as a primary use case [S1].
