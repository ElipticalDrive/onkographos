# Wavelet-based Multiresolution Rendering

Also called: Wavelet-based Multresoltion Isosurface Rendering

## Overview
An interactive rendering method for isosurfaces in a voxel grid where the underlying trivariate function is represented as a spline wavelet hierarchy [S1]. It allows adaptive, view-dependent selection of level-of-detail by superimposing appropriately weighted basis functions, decreasing resolution for distant parts to improve performance with minimal visual impact [S1]. It is distinguished from its sibling [Hierarchical Wavelet Transform on Omnitrees](2216-hierarchical-wavelet-transform-on-omnitrees.md) by its specific use of polynomial spline wavelets with B-spline basis functions to guarantee continuous surfaces and its implementation of a gathering-based CUDA kernel for reconstruction rather than scattering [S1].

## How it works
**Inputs:**
*   Volumetric dataset $V$ of size up to $512^3$ voxels [S1].
*   Camera position and viewing parameters [S1].
*   Isovalue $c$ defining the surface $f(x,y,z)=c$ [S1].
*   Interpolation degree $d$ (e.g., $d=1$ for tri-linear, $d=3$ for tri-cubic) [S1].
*   Chunk size $k \times k \times k$ nodes (typically $k=8$) [S1].
*   User-defined error threshold $\epsilon$ [S1].

**Outputs:**
*   Rendered isosurface image [S1].
*   Activated octree nodes/chunks for reconstruction [S1].

**Data Structures:**
*   **Octree:** Nested vector spaces where nodes represent levels of the wavelet hierarchy [S1].
*   **Chunk:** A block of $k \times k \times k$ octree nodes processed together [S1].
*   **Wavelet Coefficients:** Low-pass (scaling) and high-pass (detail) coefficients resulting from the transform [S1].
*   **Min/Max Values:** Stored at leaf nodes, estimated using the convex combination property of B-spline basis, and propagated to the root [S1].

**Method Steps:**

1.  **Wavelet Transform:**
    Perform a 3D wavelet transform on the volume dataset using polynomial spline wavelets [S1]. The basis functions are B-splines with the least possible number of vanishing moments to minimize filter support [S1]. Due to the separability of the B-spline wavelet basis, the transformation is performed sequentially in the x-, y-, and z-directions [S1]. This reduces the computational complexity compared to a non-separable approach [S1].

2.  **Octree Construction and Min/Max Propagation:**
    Construct an octree hierarchy where each level corresponds to a resolution level in the wavelet decomposition [S1]. Calculate min/max values for leaf nodes. Propagate these min/max values towards the root using the convex combination property of the B-spline basis to enable efficient view-dependent culling [S1].

3.  **View-Dependent Chunk Activation:**
    Traverse the octree and evaluate an error metric for each chunk to determine if it needs reconstruction [S1]. A chunk is activated if:
    *   The chunk's min/max range contains the isovalue $c$ (min/max comparison with render tree entry) [S1].
    *   The geometric error metric $s/c > \epsilon$ is satisfied, where $s$ is the node diameter, $c$ is the distance from the camera, and $\epsilon$ is the user-defined threshold [S1].

4.  **Continuity Handling:**
    If a chunk is activated, check if any wavelet support extends into neighboring chunks [S1]. If so, those neighboring chunks must also be reconstructed to maintain surface continuity and avoid cracks [S1]. Chunks that are neither activated nor needed for continuity are omitted [S1].

5.  **CUDA Reconstruction:**
    Reconstruct the volume data for activated chunks using CUDA kernels [S1].
    *   **Kernel Structure:** One CUDA kernel is used for convolution along each dimension [S1].
    *   **Thread Block:** Each kernel consists of blocks of $k \times k$ threads [S1].
    *   **Thread Work:** Each thread computes a 1D convolution with the wavelet filter kernels (low-pass and high-pass) [S1].
    *   **Beam Processing:** One block is responsible for a beam of $k \times k$ voxels along the current convolution direction [S1].
    *   **Gathering Strategy:** Instead of scattering coefficients, the method traverses the octree and gathers all contributions of wavelets intersecting the current node/chunk to avoid atomic operations and bus locking penalties [S1].
    *   **Register Optimization:** At each reconstruction step, ensure all needed data resides in register space before convolution [S1]. Reuse data fetched for the reconstruction of the previous chunk [S1].
    *   **Deactivated Chunks:** Skipped entirely [S1].

6.  **Root Finding:**
    Perform root finding on the reconstructed piecewise algebraic surface defined by:
    $$f(x, y, z) = \sum_{0 \leq i, j, k \leq d} f_{ijk} x^i y^j z^k = 0$$
    where $f_{ijk}$ are the reconstructed coefficients and $d$ is the surface degree along each dimension, resulting in an overall degree of $3d$ [S1]. Different root finding techniques are compared for precision and efficiency [S1].

**Pseudocode:**

```python
def wavelet_multiresolution_rendering(volume_data, camera, isovalue, epsilon, k=8, d=3):
    # Step 1: Wavelet Transform
    # Apply separable 3D wavelet transform using polynomial spline wavelets
    # Sequentially transform in x, y, z directions
    coefficients = apply_separable_wavelet_transform(volume_data, d)
    
    # Step 2: Octree Construction
    # Build octree hierarchy from coefficients
    # Propagate min/max values from leaves to root using B-spline convex combination
    octree = build_octree(coefficients)
    propagate_min_max(octree)
    
    # Step 3: Chunk Activation
    # Traverse octree and activate chunks based on view-dependent error metric
    activated_chunks = []
    for chunk in octree.chunks:
        # Check if isovalue is within chunk's min/max range
        contains_isovalue = chunk.min_value <= isovalue <= chunk.max_value
        
        # Check geometric error metric: s/c > epsilon
        # s = node diameter, c = distance from camera
        node_diameter = get_node_diameter(chunk)
        distance_to_camera = get_distance_to_camera(chunk, camera)
        geometric_error = node_diameter / distance_to_camera
        
        if contains_isovalue and geometric_error > epsilon:
            activated_chunks.append(chunk)
            
    # Step 4: Continuity Handling
    # Add neighbors if wavelet support extends into them
    chunks_to_reconstruct = set()
    for chunk in activated_chunks:
        chunks_to_reconstruct.add(chunk)
        neighbors = get_neighbors(chunk, k)
        for neighbor in neighbors:
            if neighbor not in chunks_to_reconstruct:
                # Check if wavelet support from activated chunk overlaps neighbor
                if wavelet_support_overlaps(chunk, neighbor):
                    chunks_to_reconstruct.add(neighbor)
                    
    # Step 5: CUDA Reconstruction
    # Reconstruct data for chunks in chunks_to_reconstruct
    reconstructed_data = {}
    for chunk in chunks_to_reconstruct:
        # Skip if already processed or deactivated
        if chunk in reconstructed_data:
            continue
            
        # Gather contributions from wavelets intersecting this chunk
        # Ensure data is in register space
        data = gather_wavelet_contributions(chunk, coefficients)
        
        # Apply 1D convolution along x, y, z using CUDA kernels
        # Each block processes a beam of k*k voxels
        reconstructed_chunk = apply_cuda_convolution(data, k)
        reconstructed_data[chunk] = reconstructed_chunk
        
    # Step 6: Root Finding
    # Solve f(x,y,z) = 0 for the reconstructed piecewise algebraic surface
    isosurface = find_roots(reconstructed_data, isovalue, d)
    
    return isosurface
```

**Parameters:**
*   **Interpolation degree $d$:** Determines the surface degree along each dimension. Common choices are $d=1$ (tri-linear) and $d=3$ (tri-cubic) [S1].
*   **Chunk size $k$:** Set to $k=8$ in the source [S1].
*   **Threshold $\epsilon$:** User-defined threshold for the geometric error metric [S1].
*   **Wavelet Type:** Polynomial spline wavelets with minimal vanishing moments [S1].

**Edge Cases and Pitfalls:**
*   **Cracks:** If continuity is not maintained by reconstructing neighboring chunks where wavelet support extends, cracks may appear in the isosurface [S1].
*   **Performance:** Scattering memory access patterns (distributing coefficients into intersecting nodes) cause bus locking penalties on GPUs; the gathering approach avoids this [S1].
*   **Granularity:** Tracking activation for every single wavelet is inefficient; processing in chunks ($k \times k \times k$) is necessary for SIMD performance [S1].

## Subtopics

### Wavelet Transform
Defined by Monet Morlet to avoid the fixed resolution limit of windowed Fourier transforms [S2, unofficial]. It decomposes the signal into a family of functions that are translations and dilations of a unique mother wavelet $\psi(x)$ [S2, unofficial]. The main drawback of the alternative windowed Fourier transform (Gabor) is that its spatial and frequency resolution is constant, which is unacceptable for signals with features of very different sizes [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The separable wavelet transform reduces computation to three times the 1D case [S1]. Reconstruction is performed only on activated chunks, skipping deactivated ones [S1].
*   **Memory Complexity:** Depends on the octree structure and the number of activated chunks [S1].
*   **Measured Performance:** Tested with datasets up to $512^3$ voxels and viewport sizes up to $1024 \times 768$ pixels, demonstrating interactive frame rates [S1].
*   **Strengths:** Adaptive view-dependent level-of-detail improves performance for distant parts with little visual impact [S1]. B-spline basis guarantees continuous surfaces, avoiding cracks [S1]. GPU implementation (CUDA) utilizes high computational performance [S1].
*   **Limitations:** Requires careful handling of continuity between chunks [S1]. The number of influence coefficients grows cubically with the support of the 1D wavelet (e.g., 175 for tri-cubic) [S1].
*   **When to Use:** Interactive isosurface rendering of large volumetric datasets where view-dependent LOD is beneficial [S1].
*   **When Not to Use:** When non-isosurface rendering (e.g., direct volume rendering) is required, or when hardware does not support CUDA [S1].

## Background
Originated from work by Markus Steinberger and Markus Grabner at the Institute for Computer Graphics and Vision, Graz University of Technology, Austria [S1]. The method builds on the wavelet transformation [Chu92] which decorrelates data and allows selective removal of irrelevant data [S1]. It utilizes polynomial spline wavelets [CDF92] and GPU acceleration via CUDA [S1]. The approach is part of the broader field of wavelet-based volume rendering [S1].
