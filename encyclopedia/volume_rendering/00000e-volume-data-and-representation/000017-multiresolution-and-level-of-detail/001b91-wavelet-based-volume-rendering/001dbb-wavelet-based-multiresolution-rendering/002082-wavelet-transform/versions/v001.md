# Wavelet Transform

Also called: Discrete Wavelet Transform, Fast Wavelet Transform, Morlet Wavelet Transform

## Overview
The Wavelet Transform provides a sparse representation for highly detailed functions by decomposing signals into dilated and translated versions of a unique basis function [S2, unofficial]. It solves the limitation of windowed Fourier transforms, which suffer from fixed spatial and frequency resolution, by allowing variable resolution analysis suitable for signals with features of vastly different scales [S1, unofficial]. Unlike the Discrete Cosine Transform (DCT) used in JPEG, which requires image fragmentation due to global basis support, the Wavelet Transform has local support in both the spatial and frequency domains, eliminating the need for block-based processing [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A signal or image data array $I$ of size $N$.
*   **Output:** A set of wavelet coefficients representing the signal at multiple resolutions.

**Data Structures:**
The transform produces a hierarchical structure of sub-bands. In 2D, a single level of decomposition splits the input into four sub-bands:
*   $LL$: Low-pass in both directions (approximation).
*   $LH$: Low-pass in x, High-pass in y (horizontal details).
*   $HL$: High-pass in x, Low-pass in y (vertical details).
*   $HH$: High-pass in both directions (diagonal details).
The $LL$ sub-band is recursively decomposed in subsequent levels, creating a tree structure (e.g., $LLL$, $LLH$, etc.). The detail bands ($LH$, $HL$, $HH$) are not further decomposed in standard 2D pyramids [S2, unofficial].

**Parameters:**
*   **Compression Ratio:** Lossy compression can achieve ratios in the order of 64:1 with almost invisible artifacts [S2, unofficial].
*   **Wavelet Basis:** The specific choice of the mother wavelet $\psi(x)$ determines the filter coefficients. The sources reference linear spline wavelets and the lifting scheme for construction [S2, unofficial], but do not provide specific filter coefficients for a standard basis (e.g., Daubechies). [G] Implementers must select a standard orthogonal wavelet filter bank (e.g., Haar, Daubechies-4) or use the lifting scheme coefficients defined in the chosen library or standard.

**Algorithm Steps:**

1.  **Decomposition (Analysis):**
    The process recursively separates high-frequency details from lower frequencies.
    a. Apply low-pass filtering and high-pass filtering to the input signal in the x-direction.
    b. Downsample the results by a factor of 2 in the x-direction.
    c. Apply low-pass filtering and high-pass filtering to the results from step (b) in the y-direction.
    d. Downsample the results by a factor of 2 in the y-direction.
    e. This yields the four sub-bands: $LL$, $LH$, $HL$, $HH$.
    f. If further decomposition is required, apply steps (a) through (e) recursively to the $LL$ sub-band.

2.  **Reconstruction (Synthesis):**
    The inverse process assembles details from the coefficients.
    a. Upsample the sub-bands by a factor of 2 in the respective directions.
    b. Apply synthesis low-pass and high-pass filters.
    c. Sum the filtered results to reconstruct the signal at the current resolution.
    d. Recursively reconstruct higher-resolution levels until the original signal size is reached.

**Pseudocode:**

def wavelet_transform_2d(signal, levels, low_pass_filter, high_pass_filter):
    """
    Performs a 2D discrete wavelet transform.
    
    Args:
        signal: 2D array of input data.
        levels: Number of decomposition levels.
        low_pass_filter: 1D array representing the low-pass filter coefficients.
        high_pass_filter: 1D array representing the high-pass filter coefficients.
        
    Returns:
        A list of lists, where each inner list contains the sub-bands for that level.
        The first element is the approximation (LL) for the next level.
        The subsequent elements are detail bands (LH, HL, HH).
    """
    current_data = signal
    coefficients = []
    
    for level in range(levels):
        # 1. Filter in x-direction
        # Apply low-pass filter to each row
        low_x = apply_filter_1d(current_data, low_pass_filter, axis=1)
        # Apply high-pass filter to each row
        high_x = apply_filter_1d(current_data, high_pass_filter, axis=1)
        
        # 2. Downsample in x-direction (keep even indices)
        low_x_ds = low_x[:, ::2]
        high_x_ds = high_x[:, ::2]
        
        # 3. Filter in y-direction
        # Apply low-pass filter to each column of low_x_ds
        ll = apply_filter_1d(low_x_ds, low_pass_filter, axis=0)
        # Apply high-pass filter to each column of low_x_ds
        lh = apply_filter_1d(low_x_ds, high_pass_filter, axis=0)
        
        # Apply low-pass filter to each column of high_x_ds
        hl = apply_filter_1d(high_x_ds, low_pass_filter, axis=0)
        # Apply high-pass filter to each column of high_x_ds
        hh = apply_filter_1d(high_x_ds, high_pass_filter, axis=0)
        
        # 4. Downsample in y-direction (keep even indices)
        ll_ds = ll[::2, :]
        lh_ds = lh[::2, :]
        hl_ds = hl[::2, :]
        hh_ds = hh[::2, :]
        
        # Store the detail bands for this level
        coefficients.append({
            'LL': ll_ds,
            'LH': lh_ds,
            'HL': hl_ds,
            'HH': hh_ds
        })
        
        # Prepare for next level
        current_data = ll_ds
        
    return coefficients

**Edge Cases and Pitfalls:**
*   **Quantization Error:** In lossy compression, quantization errors are introduced during the transform range and are smoothly distributed across the image domain by the inverse transform, making them often unrecognizable to the human eye [S2, unofficial].
*   **Boundary Conditions:** The sources do not specify boundary handling for finite signals. Implementers must choose a strategy (e.g., periodic, symmetric, zero-padding) which affects the transform's energy compaction properties.
*   **Degenerate Input:** The recursive nature requires the data dimensions to be divisible by $2^L$ where $L$ is the number of levels, or appropriate boundary handling must be implemented to manage non-power-of-two sizes.

## Operating characteristics
*   **Time Complexity:** The discrete wavelet transform is computed in linear time, $O(N)$, where $N$ is the number of data points [S2, unofficial].
*   **Memory Complexity:** The transform is typically performed in-place or requires storage proportional to the input size for the coefficient tree.
*   **Performance:** Lossy compression achieves high compression rates in the order of 64:1 with almost invisible artifacts [S2, unofficial].
*   **Strengths:** Local support in both image domain and frequency space eliminates the need for image fragmentation (unlike DCT) [S2, unofficial]. It provides a sparse representation for highly detailed functions [S2, unofficial].
*   **Limitations:** The main drawback of the related windowed Fourier transform (Gabor) is constant spatial and frequency resolution, which is not acceptable for signals with features of very different sizes; the wavelet transform avoids this [S1, unofficial].

## Background
The wavelet transform was defined by Monet Morlet to avoid the fixed resolution limit of windowed Fourier transforms [S1, unofficial]. It decomposes the signal into a family of functions, which are the translation and dilation of a unique function $\psi(x)$ [S1, unofficial]. The transform has roots in signal processing and pure mathematics [S2, unofficial]. It is used in image compression, solving partial differential equations, and integrating radiosity kernels [S2, unofficial]. The lifting scheme is used to construct wavelets for efficiently modeling massive volumetric data sets [S2, unofficial].
