# Haar Wavelet Transform on Omnitrees
Also called: nodal to wavelet transform, tensor-product Haar basis
## Overview
This method transforms piecewise constant volume data stored in an omnitree structure from its nodal representation into a hierarchical wavelet coefficient representation using the tensor-product Haar basis [S1, unofficial]. It enables lossless or lossy compression by allowing insignificant coefficients to be pruned or the tree to be restructured (downsplit) [Parent]. Unlike sibling methods that may use variable-length entropy coding, this approach maintains a fixed-length code structure suitable for fast random access [Child: Haar Wavelet Compression].
## How it works
**Inputs and Outputs:**
- Input: An omnitree representing a function $f \in L^2([0,1]^d)$, where the function is defined by its values on leaf nodes.
- Output: A set of wavelet coefficients corresponding to the internal nodes and leaves of the omnitree, representing the detail and approximation components of the signal.

**Data Structures:**
The omnitree uses splitting labels $\vec{b}(v)$ for each node $v$. For a node $v$, $\vec{b}(v) = (b_1(v), \dots, b_d(v))$ where $b_j(v) \in \{0, 1\}$.
- $b_j(v) = 1$: The node is split in dimension $j$.
- $b_j(v) = 0$: The node is not split in dimension $j$ (coarse in that dimension).
The nodal representation stores $f$ as a sum over leaf nodes $v$ with $b(v)=\vec{0}$:
$$ f = \sum_{v: \vec{b}(v)=\vec{0}} s^v \phi^v $$
where $\phi^v$ is the indicator function for the hyper-rectangular region $rect(v)$ (1 if $x \in rect(v)$, 0 otherwise) [S1, unofficial].

**Steps:**
1. **Traverse the Omnitree:** Perform a depth-first traversal of the omnitree to identify all internal nodes and their children.
2. **Identify Split Dimensions:** For each internal node $v$, determine the splitting label $\vec{b}(v)$. The dimensions where $b_j(v)=1$ are the active split dimensions.
3. **Compute Haar Coefficients:** For each split dimension $j$ at node $v$:
   - Let $v_L$ and $v_R$ be the left and right children of $v$ along dimension $j$.
   - The approximation coefficient $A$ is the average of the values in $v_L$ and $v_R$.
   - The detail coefficient $D$ is half the difference between the values in $v_L$ and $v_R$.
   - Specifically, if $val(v)$ denotes the value associated with node $v$ (typically the average value over its region), then:
     $$ D_j(v) = \frac{val(v_L) - val(v_R)}{2} $$
     $$ A_j(v) = \frac{val(v_L) + val(v_R)}{2} $$
   - Note: In a tensor-product Haar basis, the transform is applied sequentially along each split dimension. The order of dimensions matters if the basis is not separable, but for Haar, the order does not affect the final set of coefficients, only the intermediate steps.
4. **Store Coefficients:** Store the detail coefficients $D_j(v)$ for all split dimensions $j$ at all internal nodes $v$. The approximation coefficients are propagated up the tree or stored at the root if no further splitting occurs.
5. **Handle Coarsening:** If a coarsening request is made for node $v$ in dimensions $C$, it is expressed as a negative marker $\vec{m}(v)$ with $m_j = -1$ for $j \in C$ and $m_j = 0$ otherwise. The new splitting label is computed as $\vec{b}(v') = \vec{b}(v) + \vec{m}(v)$ component-wise. If $b_j(v)=1$ and $m_j(v)=-1$, then $b_j(v')=0$, removing the split in that dimension [S1, unofficial].

**Parameters:**
- None explicitly defined for the transform itself. The structure of the omnitree (splitting labels) determines the transform.

**Edge Cases and Pitfalls:**
- **Precision:** Haar wavelets involve simple arithmetic (addition, subtraction, division by 2). Precision issues are minimal but should be handled consistently with floating-point standards.
- **Boundaries:** The domain is $[0,1]^d$. Boundary conditions are handled by the omnitree structure itself, as the tree adapts to the data distribution.
- **Degenerate Input:** If a node has no children (leaf), no transform is performed. If a node is split in all dimensions, the transform is applied in each dimension sequentially.

## Subtopics

### [Haar Wavelet Compression](5378-haar-wavelet-compression.md)
A lossy compression scheme for 3D volume data designed to achieve high compression ratios while supporting fast random access to individual voxels, enabling interactive visualization of large datasets. It differs from traditional wavelet coders (like SPIHT or zerotree-based methods) by using a block-based data structure with fixed-length codes and spatial coherence flags, avoiding variable-length entropy coding that hinders random access. It also differs from pure 3D wavelet methods by treating the volume as a sequence of 2D slices, applying temporal prediction to remove inter-slice correlation before performing 2D spatial wavelet decomposition, which reduces computational cost compared to full 3D transforms.

## Operating characteristics
- **Time Complexity:** Linear in the number of nodes in the omnitree, $O(N)$, where $N$ is the number of nodes. Each node is visited once, and the transform at each node is $O(d)$ where $d$ is the dimensionality.
- **Memory Complexity:** Linear in the number of nodes, $O(N)$, to store the wavelet coefficients. The omnitree structure itself also requires $O(N)$ memory.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales linearly with the number of nodes. The omnitree structure allows for adaptive resolution, so the number of nodes $N$ depends on the complexity of the volume data.
- **Strengths:** Enables efficient compression and random access. The tensor-product Haar basis is simple and fast to compute.
- **Limitations:** The Haar basis is not smooth, which may lead to artifacts in some applications. The performance depends heavily on the omnitree structure and the data distribution.
- **When to use:** When fast random access and compression are required for large volume datasets.
- **When not to use:** When smoothness of the reconstructed data is critical and the Haar basis artifacts are unacceptable.
## Background
The Haar wavelet transform on omnitrees is part of the broader field of wavelet-based volume rendering and compression. The specific implementation on omnitrees is described in the paper "Towards Fully Dynamic Omnitrees: Moment-Conserving Anisotropic Compression With Wavelets" [S1, unofficial]. The omnitree data structure allows for anisotropic refinement and coarsening, making it suitable for adaptive volume rendering.
