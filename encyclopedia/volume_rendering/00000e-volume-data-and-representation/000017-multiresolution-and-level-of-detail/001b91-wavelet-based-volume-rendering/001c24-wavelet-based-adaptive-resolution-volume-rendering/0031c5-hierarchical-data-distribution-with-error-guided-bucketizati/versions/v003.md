# Hierarchical Data Distribution with Error-Guided Bucketization

Also called: Error-Guided Load Balancing, Space-Filling Curve Distribution, tree partitioning and distribution algorithm

## Overview
Hierarchical Data Distribution with Error-Guided Bucketization is a data distribution scheme for parallel volume rendering that partitions a wavelet-based volume hierarchy among processors to minimize inter-processor communication dependencies and ensure balanced rendering workloads [S1][S2]. It solves the problem of parent-child node dependencies in wavelet reconstruction, which typically force processors to communicate during rendering, by pre-reconstructing data at specific intervals and grouping independent data into "distribution units" [S1]. Unlike standard space-filling curve distributions that only consider spatial locality, this method incorporates error-guided bucketization to ensure that nodes with similar reconstruction errors (and thus similar rendering costs) are distributed across different processors, preventing contention and load imbalance [S1][S2].

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   A pre-constructed wavelet tree of height $h$.
    *   The number of processors $P$.
    *   A parameter $k$ (where $k < h$) defining the storage interval.
    *   Error values $E_u$ for each distribution unit $u$, derived from the error of its representative node.
*   **Outputs:**
    *   A mapping of each distribution unit to a specific processor ID ($0 \dots P-1$).

### Data Structures
*   **Wavelet Tree:** A hierarchical structure where each node represents a data block. Nodes are classified as:
    *   **Representative Node:** Stores a pre-reconstructed low-resolution data block.
    *   **Associated Node:** Stores only wavelet coefficients.
*   **Distribution Unit:** The minimum unit of assignment. Defined as the data at one representative node plus the wavelet coefficients of all its descendant associated nodes that depend on that representative node. Each unit contains exactly one representative node.
*   **Bucket:** A container for distribution units, indexed by an error interval.

### Algorithm Steps

1.  **Apply EVERY-K Storage Strategy:**
    *   Identify representative nodes at every $k$-th level starting from the root (level 0).
    *   Reconstruct and store the low-resolution data block for these nodes.
    *   All other nodes (leaves and intermediate nodes not at multiples of $k$) are associated nodes storing only wavelet coefficients.
    *   By default, the root is a representative node, and all leaf nodes are associated nodes [S1][S2].

2.  **Form Distribution Units:**
    *   Partition the wavelet tree into distribution units.
    *   For each representative node $R$, its distribution unit $U_R$ consists of $R$ and all associated nodes in its subtree that do not have a closer representative node ancestor.
    *   Since reconstruction for any node in $U_R$ only requires data from $R$ (or ancestors of $R$ which are also representative), there are no data dependencies between different distribution units [S1][S2].

3.  **Calculate Error Values:**
    *   Compute an error metric $E_u$ for each distribution unit $u$. This is typically based on the reconstruction error of the representative node of that unit.
    *   Determine the global error range $[err_{min}, err_{max}]$ across all distribution units [S1][S2].

4.  **Traverse Using Hierarchical Space-Filling Curve:**
    *   Traverse the wavelet tree nodes level by level in a breadth-first search manner.
    *   Within each level, order the nodes according to a hierarchical space-filling curve (e.g., Hilbert curve) [S1][S2].
    *   This traversal generates a sequence of distribution units that preserves spatial locality [S1].

5.  **Error-Guided Bucketization:**
    *   Partition the error range $[err_{min}, err_{max}]$ into $B$ buckets (intervals).
    *   Initially, the intervals may be equal-width or equal-count.
    *   Traverse the sequence of distribution units generated in Step 4.
    *   For each unit $u$, determine its error $E_u$ and place $u$ into the bucket corresponding to the interval containing $E_u$.
    *   **Adjustment:** Adjust the bucket boundaries so that each bucket holds a similar number of distribution units. This ensures that the "cost" (error magnitude often correlates with detail/complexity) is balanced across buckets [S1][S2].

6.  **Round-Robin Distribution:**
    *   For each bucket, distribute the contained distribution units to the $P$ processors in a round-robin fashion.
    *   Because units with similar errors are in the same bucket, and they are distributed round-robin, neighboring units with similar errors are assigned to different processors. This balances the workload and minimizes cache contention [S1][S2].

### Pseudocode

```python
def distribute_wavelet_tree(wavelet_tree, num_processors, k):
    """
    Distributes wavelet tree nodes to processors using Error-Guided Bucketization.
    
    Args:
        wavelet_tree: The root of the wavelet tree.
        num_processors: Integer P, number of processors.
        k: Integer, interval for EVERY-K storage strategy.
        
    Returns:
        dict: Mapping from distribution_unit_id to processor_id.
    """
    
    # Step 1: Identify Representative Nodes and Form Units
    # Nodes at levels 0, k, 2k, ... are representative.
    # All others are associated.
    representative_nodes = []
    distribution_units = []
    
    # Helper to traverse tree and identify structure
    # Note: In a real implementation, this would traverse the tree
    # to assign parent pointers and identify descendants.
    nodes = wavelet_tree.breadth_first_search()
    
    for node in nodes:
        if node.level % k == 0:
            node.is_representative = True
            representative_nodes.append(node)
        else:
            node.is_representative = False
            
    # Form distribution units
    # Each representative node starts a unit.
    # Associated nodes belong to the nearest ancestor representative node.
    for rep_node in representative_nodes:
        unit = DistributionUnit(rep_node)
        # Assign all associated descendants to this unit
        # This requires traversing the subtree of rep_node
        # and checking if the node has a closer representative ancestor.
        # Since rep_node is at level L, and next rep is at L+k,
        # all nodes in between are associated with rep_node.
        assign_descendants_to_unit(rep_node, unit)
        distribution_units.append(unit)
        
    # Step 2: Calculate Errors
    # Error E_u is derived from the representative node's reconstruction error.
    # err_min and err_max are global bounds.
    errors = []
    for unit in distribution_units:
        e = calculate_error(unit.representative_node)
        unit.error = e
        errors.append(e)
        
    err_min = min(errors)
    err_max = max(errors)
    
    # Step 3: Define Buckets
    # Partition [err_min, err_max] into buckets.
    # The goal is to have similar number of units per bucket.
    # We can use equal-count binning or iterative adjustment.
    num_buckets = len(distribution_units) # Or a fixed number based on P?
    # The text says "several error intervals" and "adjust... so each bucket holds similar number".
    # Let's assume we create enough buckets to balance, or fixed buckets and adjust boundaries.
    # A simple approach: Sort units by error, then split into chunks.
    # However, we must preserve the SFC order for the next step.
    
    # The algorithm described:
    # 1. Partition range into intervals.
    # 2. Sort units into buckets based on SFC order.
    # 3. Adjust intervals so buckets have similar counts.
    
    # Implementation of adjustment:
    # We can start with equal-width intervals, count units, and shift boundaries.
    # Or, since we need to output a processor assignment, we can just:
    # 1. Sort units by error to find quantiles.
    # 2. Define bucket boundaries based on quantiles.
    # 3. Re-assign units to buckets based on these boundaries.
    
    sorted_units_by_error = sorted(distribution_units, key=lambda u: u.error)
    
    # Determine bucket boundaries to ensure equal count
    # If we want B buckets, we split the sorted list into B chunks.
    # But we need to map back to the SFC order.
    
    # Let's define the number of buckets. The text doesn't specify B explicitly,
    # but implies it's related to balancing. Often B >= P.
    # Let's assume we create P buckets for direct mapping, or more.
    # The text says "distributed among processors in a round-robin manner" per bucket.
    # So if we have B buckets, and P processors, each bucket distributes to P processors.
    
    # To simplify, let's assume we create P buckets.
    B = num_processors
    
    # Calculate boundaries
    chunk_size = len(sorted_units_by_error) // B
    boundaries = []
    for i in range(1, B):
        boundaries.append(sorted_units_by_error[i * chunk_size].error)
        
    # Define buckets
    buckets = [[] for _ in range(B)]
    
    # Step 4: Traverse SFC and Sort into Buckets
    # We need the SFC order of the distribution units.
    sfc_order = get_hierarchical_sfc_order(wavelet_tree, k)
    
    for unit in sfc_order:
        # Find which bucket this unit belongs to
        bucket_idx = 0
        for i, boundary in enumerate(boundaries):
            if unit.error < boundary:
                break
            bucket_idx += 1
            
        buckets[bucket_idx].append(unit)
        
    # Step 5: Round-Robin Distribution
    assignment = {}
    for bucket in buckets:
        for i, unit in enumerate(bucket):
            proc_id = i % num_processors
            assignment[unit.id] = proc_id
            
    return assignment

def get_hierarchical_sfc_order(wavelet_tree, k):
    """
    Returns distribution units in hierarchical space-filling curve order.
    Traverses level by level (BFS). Within each level, uses Hilbert curve order.
    """
    levels = wavelet_tree.get_levels()
    units_in_order = []
    
    for level in levels:
        # Get nodes at this level
        nodes_at_level = level.nodes
        # Sort nodes by their Hilbert curve index at this level
        sorted_nodes = sort_by_hilbert_index(nodes_at_level)
        
        # Add distribution units for representative nodes at this level
        # Note: Not all nodes at level L*k are necessarily the start of a unit
        # if the tree is not perfectly balanced or k doesn't divide evenly.
        # But per EVERY-K, nodes at 0, k, 2k... are reps.
        for node in sorted_nodes:
            if node.level % k == 0:
                # Find the unit this node represents
                unit = find_unit_for_representative(node)
                if unit:
                    units_in_order.append(unit)
                    
    return units_in_order

def sort_by_hilbert_index(nodes):
    """
    Sorts nodes based on their position in a Hilbert curve at their resolution level.
    """
    # Compute Hilbert index for each node's spatial position
    # This requires mapping voxel coordinates to Hilbert indices.
    hilbert_indices = []
    for node in nodes:
        idx = compute_hilbert_index(node.spatial_coordinates)
        hilbert_indices.append((idx, node))
    
    hilbert_indices.sort(key=lambda x: x[0])
    return [n for _, n in hilbert_indices]
```

### Parameters and Edge Cases
*   **Parameter $k$:** Determines the granularity of pre-reconstruction. A smaller $k$ means more representative nodes, higher memory usage for stored data blocks, but potentially faster reconstruction (fewer steps up the tree). A larger $k$ saves memory but increases reconstruction cost. Default: Root is representative, leaves are associated [S1][S2].
*   **Space-Filling Curve:** Hilbert curve is used [S1].
*   **Edge Case: $h$ not a multiple of $k$:** The text states this can be "easily handled" [S1][S2]. Typically, this means the last interval may be smaller than $k$, or the final representative nodes are placed at the deepest level $\le h$ that satisfies the modulo condition.
*   **Precision:** Error calculation can be expensive for large datasets. The MSE calculation becomes progressively more expensive as one traverses toward the root [S2].

## Operating characteristics

*   **Time Complexity:**
    *   **Tree Construction:** Approximately one hour on a 2.0GHz Intel Pentium 4 with 1GB RAM for the tested dataset [S1].
    *   **Distribution:** Linear in the number of distribution units, dominated by the SFC traversal and sorting.
*   **Memory Complexity:**
    *   **Storage:** Compressed data size was around 2.65GB for the tested dataset [S1].
    *   **Runtime:** Requires temporary disk space (256MB) and main memory (128MB) per processor for caching reconstructed data blocks [S1].
*   **Performance:**
    *   Achieves well-balanced workload among processors [S1][S2].
    *   Eliminates inter-processor communication dependencies during reconstruction [S1].
    *   Minimizes run-time communication overhead [S1].
*   **Strengths:**
    *   Scalability due to minimized dependencies.
    *   Load balancing via error-guided bucketization and SFC locality.
*   **Limitations:**
    *   Error computation can be slow for very large datasets [S2].
    *   Requires pre-reconstruction of data blocks, increasing storage requirements compared to storing only coefficients.

## Background

*   **Origin:** Proposed by C. Wang, J. Gao, and H. W. Shen.
*   **Papers:**
    *   "Parallel Multiresolution Volume Rendering of Large Data Sets with Error-Guided Load Balancing" (2004) [S2].
    *   "A Parallel Multiresolution Volume Rendering Algorithm for Large Data Sets" (2005) [S1].
*   **Context:** Developed to address the scalability issues in parallel volume rendering of large datasets using wavelet trees. Previous methods suffered from high communication overhead due to parent-child dependencies in wavelet reconstruction. This method introduces the EVERY-K storage strategy and error-guided bucketization to solve these issues [S1][S2].
