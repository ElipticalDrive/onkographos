# Hierarchical Data Distribution with Error-Guided Bucketization

Also called: Error-Guided Load Balancing, Space-Filling Curve Distribution, tree partitioning and distribution algorithm

## Overview
A data distribution scheme for parallel volume rendering that partitions a wavelet hierarchy among processors to minimize inter-processor dependency and ensure load balancing [S1][S2]. It eliminates parent-child node wavelet reconstruction dependencies by using an 'Every-K' storage strategy and balances workload by distributing data along a hierarchical space-filling curve using error-guided bucketization [S1][S2]. It sets itself apart from naive tree partitioning by guaranteeing that distribution units are independent at runtime and by actively balancing the computational load based on the error tolerance of the data blocks rather than just their count [S1].

## How it works
**Inputs:**
*   A pre-constructed wavelet tree of height $h$.
*   The number of processors $P$.
*   The error range $[err_{min}, err_{max}]$ derived from the representative nodes of all distribution units.
*   The number of error intervals (buckets) $B$.

**Outputs:**
*   An assignment of each distribution unit to a specific processor $p \in \{0, \dots, P-1\}$.

**Data Structures:**
1.  **Wavelet Tree:** Nodes contain wavelet coefficients. Some nodes are marked as `representative` (store pre-reconstructed low-resolution data blocks), others as `associated` (store only coefficients).
2.  **Distribution Unit:** A logical partition of the tree. Each unit contains exactly one `representative` node and all its descendant `associated` nodes that depend on it.
3.  **Bucket:** A container for distribution units. Defined by an error interval $[e_{start}, e_{end})$.
4.  **Processor Assignment Map:** Maps each distribution unit ID to a processor ID.

**Steps:**

1.  **Apply EVERY-K Storage Strategy:**
    *   Select a parameter $k$ such that $k < h$.
    *   Identify nodes at levels $0, k, 2k, \dots$ starting from the root (level 0) as `representative` nodes.
    *   Mark all other nodes as `associated` nodes.
    *   Pre-reconstruct and store the low-resolution data blocks for all `representative` nodes.
    *   *Note:* By default, the root is a representative node and all leaf nodes are associated nodes [S1][S2].

2.  **Define Distribution Units:**
    *   For each `representative` node $R$, create a distribution unit $U_R$.
    *   $U_R$ consists of $R$ and all descendant `associated` nodes whose reconstruction path leads to $R$ (i.e., they do not have another `representative` node as a closer ancestor).
    *   This ensures that all nodes within $U_R$ are independent of nodes in any other unit $U_{R'}$ ($R \neq R'$) [S1][S2].

3.  **Calculate Error Values:**
    *   For each distribution unit $U_R$, determine the error value $E_R$ of its representative node $R$.
    *   $err_{min} = \min_{R} (E_R)$ and $err_{max} = \max_{R} (E_R)$ [S1][S2].

4.  **Initialize Buckets:**
    *   Create $B$ empty buckets.
    *   Partition the error range $[err_{min}, err_{max}]$ into $B$ initial intervals. The exact initial interval boundaries are not specified, but they cover the full range [S1][S2].

5.  **Traverse Tree and Sort into Buckets:**
    *   Traverse the wavelet tree nodes level by level in a breadth-first search manner using a hierarchical space-filling curve (specifically the Hilbert curve) [S1][S2].
    *   For each distribution unit $U$ encountered during traversal:
        *   Determine its representative node's error $E_{rep}$.
        *   Identify the bucket $B_i$ whose error interval contains $E_{rep}$.
        *   Append $U$ to $B_i$ in the order of traversal [S1][S2].

6.  **Adjust Bucket Intervals:**
    *   Adjust the boundaries of the error intervals for the buckets so that each bucket holds a similar number of distribution units.
    *   This step ensures that the buckets are balanced in terms of the *count* of units, which correlates to load balancing when combined with the space-filling curve's locality preservation [S1][S2].

7.  **Distribute to Processors:**
    *   For each bucket $B_i$:
        *   Iterate through the distribution units in $B_i$ in the order they were added (traversal order).
        *   Assign the $j$-th unit in the bucket to processor $(j \mod P)$ in a round-robin manner [S1][S2].

**Pseudocode:**

```python
def distribute_wavelet_tree(wavelet_tree, num_processors, num_buckets, k):
    """
    Distributes wavelet tree nodes to processors using error-guided bucketization.
    
    Args:
        wavelet_tree: The root of the wavelet tree.
        num_processors: Number of processors P.
        num_buckets: Number of error buckets B.
        k: Step size for EVERY-K storage strategy.
        
    Returns:
        A dictionary mapping distribution_unit_id to processor_id.
    """
    
    # Step 1: Apply EVERY-K Storage Strategy
    # Mark nodes as representative or associated
    for node in wavelet_tree.all_nodes():
        level = node.depth
        if level % k == 0:
            node.type = 'representative'
            # Pre-reconstruct and store data block for representative nodes
            node.data_block = reconstruct_low_res(node)
        else:
            node.type = 'associated'
            
    # Step 2: Define Distribution Units
    distribution_units = []
    # A distribution unit is defined by its representative node
    for node in wavelet_tree.all_nodes():
        if node.type == 'representative':
            # Collect all associated descendants that depend on this representative
            # This implies finding all associated nodes whose closest representative ancestor is this node
            associated_descendants = find_dependent_associated_nodes(node)
            unit = {
                'id': node.id,
                'representative': node,
                'associated_nodes': associated_descendants,
                'error': node.error_value # E_R
            }
            distribution_units.append(unit)
            
    # Step 3: Calculate Error Range
    if not distribution_units:
        return {}
        
    errors = [u['error'] for u in distribution_units]
    err_min = min(errors)
    err_max = max(errors)
    
    # Step 4 & 5: Traverse and Sort into Buckets
    # Initialize buckets with empty lists
    buckets = [[] for _ in range(num_buckets)]
    
    # Define initial error intervals for buckets
    # The source says intervals are adjusted later, so initial placement is based on error value
    # We assume equal-width intervals for initial sorting
    interval_width = (err_max - err_min) / num_buckets if num_buckets > 0 else 0
    
    # Traverse using Hilbert Curve
    # The traversal order is determined by the hierarchical space-filling curve
    traversal_order = get_hilbert_traversal_order(wavelet_tree, distribution_units)
    
    for unit in traversal_order:
        e = unit['error']
        # Determine initial bucket index based on error
        if interval_width == 0:
            bucket_idx = 0
        else:
            bucket_idx = int((e - err_min) / interval_width)
            # Clamp to valid range
            if bucket_idx >= num_buckets:
                bucket_idx = num_buckets - 1
        buckets[bucket_idx].append(unit)
        
    # Step 6: Adjust Bucket Intervals
    # The goal is to have similar number of distribution units in each bucket.
    # This is typically done by re-sorting the units based on error and redistributing them
    # into buckets with equal counts.
    
    # Flatten all units and sort by error
    all_units_sorted_by_error = sorted(distribution_units, key=lambda u: u['error'])
    
    # Redistribute into buckets to balance count
    new_buckets = [[] for _ in range(num_buckets)]
    units_per_bucket = len(all_units_sorted_by_error) // num_buckets
    remainder = len(all_units_sorted_by_error) % num_buckets
    
    current_unit_idx = 0
    for i in range(num_buckets):
        # Assign units to bucket i
        count = units_per_bucket + (1 if i < remainder else 0)
        for _ in range(count):
            if current_unit_idx < len(all_units_sorted_by_error):
                new_buckets[i].append(all_units_sorted_by_error[current_unit_idx])
                current_unit_idx += 1
                
    # Note: The source mentions "sorted into a bucket... intervals adjusted... finally distributed".
    # The adjustment step effectively re-partitions the sorted list.
    # The final distribution uses the balanced buckets.
    
    # Step 7: Distribute to Processors
    assignment = {}
    for bucket in new_buckets:
        for j, unit in enumerate(bucket):
            processor_id = j % num_processors
            assignment[unit['id']] = processor_id
            
    return assignment

def find_dependent_associated_nodes(representative_node):
    """
    Finds all associated nodes that depend on the given representative node.
    These are associated nodes whose closest representative ancestor is the given node.
    """
    # This requires traversing the subtree rooted at representative_node
    # and collecting all associated nodes.
    # Since the tree structure is hierarchical, we can do a DFS/BFS from the representative node.
    dependent_nodes = []
    stack = [representative_node]
    while stack:
        current = stack.pop()
        for child in current.children:
            if child.type == 'associated':
                dependent_nodes.append(child)
                stack.append(child)
            # If a child is representative, it starts its own unit, so we don't traverse further
            # into its subtree for THIS unit.
    return dependent_nodes
```

**Parameters:**
*   $k$: The step size for the EVERY-K strategy. $k < h$ (tree height). Default: Not explicitly given, but examples use $k=2$ [S1].
*   $h$: Height of the wavelet tree [S1].
*   $P$: Number of processors [S1].
*   $B$: Number of error buckets. Not given in the sources.
*   Space-filling curve: Hilbert curve [S1].

**Edge Cases and Pitfalls:**
*   **Tree Height Not Multiple of $k$:** The source states this can be "easily handled" [S1][S2]. Implementation should ensure nodes at levels $0, k, 2k, \dots$ are marked as representative, even if the last level is not exactly a multiple of $k$.
*   **Error Range:** If all representative nodes have the same error, $err_{min} = err_{max}$, leading to a single bucket or division by zero in interval calculation. The pseudocode handles this by clamping or using a single bucket.
*   **Leaf Nodes:** By default, all leaf nodes are associated nodes [S1][S2]. This must be enforced during the EVERY-K step.

## Subtopics

### [Parallel Multiresolution Volume Rendering with Error-Guided Load Balancing](6624-parallel-multiresolution-volume-rendering-with-error-guided-.md)
A two-stage parallel algorithm for visualizing large 3D datasets that uses a wavelet tree, error-guided bucketization, and on-the-fly reconstruction to enable interactive multiresolution rendering with minimal inter-processor communication and balanced workload. It builds on [Hierarchical Data Distribution with Error-Guided Bucketization](6597-hierarchical-data-distribution-with-error-guided-bucketizati.md) by adding a run-time traversal and rendering pipeline that selects nodes based on a user-specified error tolerance, reconstructs data blocks on the fly, and composites partial images via screen-space tiling. Unlike single-machine multiresolution rendering, it explicitly partitions the wavelet tree to eliminate inter-processor data dependencies at run-time and uses space-filling curves with error-guided bucketization to maintain load balance without redistribution.

## Operating characteristics
*   **Time Complexity:** Wavelet tree construction time is approximately one hour on a 2.0GHz Intel Pentium 4 processor with 1GB main memory [S1]. The distribution algorithm itself involves a tree traversal and sorting, which is generally $O(N \log N)$ or $O(N)$ depending on the Hilbert curve generation and sorting implementation, where $N$ is the number of distribution units.
*   **Memory Complexity:** Compressed data size was around 2.65GB for the tested dataset [S1]. Each processor allocated 256MB temporary disk space and 128MB main memory for run-time caching of reconstructed data blocks [S1].
*   **Performance:** The method achieves well-balanced workload among processors [S1]. The benchmark test results show a speed of 6.542MB/s, with $T_1=0.0286s$, $T_4=0.3563s$, $T_5=0.0018s$ (Table 2 in [S1]).
*   **Strengths:** Eliminates inter-processor dependency at runtime, balances workload based on error tolerance, preserves spatial locality, and minimizes communication overhead [S1].
*   **Limitations:** Requires pre-reconstruction of data at representative nodes, which increases storage and preprocessing time. The error calculation can be slow for large datasets [S2].
*   **When to Use:** Parallel volume rendering of large 3D datasets where load balancing and minimal communication are critical.
*   **When Not to Use:** Single-processor rendering, or when memory constraints are too tight to store pre-reconstructed data blocks.
