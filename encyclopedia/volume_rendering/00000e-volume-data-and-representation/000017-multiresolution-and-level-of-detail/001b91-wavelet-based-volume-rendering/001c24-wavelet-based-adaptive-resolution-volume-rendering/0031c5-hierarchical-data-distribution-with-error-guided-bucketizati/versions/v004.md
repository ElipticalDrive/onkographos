# Hierarchical Data Distribution with Error-Guided Bucketization

Also called: Error-Guided Load Balancing, Space-Filling Curve Distribution, tree partitioning and distribution algorithm

## Overview
Hierarchical Data Distribution with Error-Guided Bucketization is a data distribution scheme for parallel volume rendering that partitions a wavelet-based volume hierarchy among processors to minimize inter-processor communication dependencies and ensure balanced rendering workloads [S1][S2]. It solves the problem of parent-child node dependencies in wavelet reconstruction, which typically force processors to communicate during rendering, by pre-reconstructing data at specific intervals and grouping independent data into "distribution units" [S1]. Unlike standard space-filling curve distributions that only consider spatial locality, this method incorporates error-guided bucketization to ensure that nodes with similar reconstruction errors (and thus similar rendering costs) are distributed across different processors, preventing contention and load imbalance [S1][S2].

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   A pre-constructed wavelet tree of height $h$ [S1][S2].
    *   The number of processors $P$ [G].
    *   A parameter $k$ (where $k < h$) defining the storage interval [S1][S2].
    *   Error values $E_u$ for each distribution unit $u$, derived from the reconstruction error of its representative node [S1][S2].
*   **Outputs:**
    *   A mapping of each distribution unit to a specific processor ID ($0 \dots P-1$) [S1][S2].

### Data Structures
*   **Wavelet Tree:** A hierarchical structure where each node represents a data block [S1][S2].
*   **Representative Node:** Stores a pre-reconstructed low-resolution data block [S1][S2].
*   **Associated Node:** Stores only wavelet coefficients [S1][S2].
*   **Distribution Unit:** The minimum unit of assignment. Defined as the data at one representative node plus the wavelet coefficients of all its descendant associated nodes that depend on that representative node. Each unit contains exactly one representative node [S1][S2].
*   **Bucket:** A container for distribution units, indexed by an error interval [S1][S2].

### Algorithm Steps

1.  **Apply EVERY-K Storage Strategy:**
    *   Identify representative nodes at every $k$-th level starting from the root (level 0) [S1][S2].
    *   Reconstruct and store the low-resolution data block for these nodes [S1][S2].
    *   All other nodes (leaves and intermediate nodes not at multiples of $k$) are associated nodes storing only wavelet coefficients [S1][S2].
    *   By default, the root is a representative node, and all leaf nodes are associated nodes [S1][S2].

2.  **Form Distribution Units:**
    *   Partition the wavelet tree into distribution units [S1][S2].
    *   For each representative node $R$, its distribution unit $U_R$ consists of $R$ and all associated nodes in its subtree that do not have a closer representative node ancestor [S1][S2].
    *   Since reconstruction for any node in $U_R$ only requires data from $R$ (or ancestors of $R$ which are also representative), there are no data dependencies between different distribution units [S1][S2].

3.  **Calculate Error Values:**
    *   Compute an error metric $E_u$ for each distribution unit $u$ [S1][S2].
    *   This is typically based on the reconstruction error (e.g., MSE) of the representative node of that unit [S2].
    *   Determine the global error range $[err_{min}, err_{max}]$ across all distribution units [S1][S2].

4.  **Traverse Using Hierarchical Space-Filling Curve:**
    *   Traverse the wavelet tree nodes level by level in a breadth-first search manner [S1][S2].
    *   Within each level, order the nodes according to a hierarchical space-filling curve (e.g., Hilbert curve) [S1][S2].
    *   This traversal generates a sequence of distribution units that preserves spatial locality [S1].

5.  **Error-Guided Bucketization:**
    *   Partition the error range $[err_{min}, err_{max}]$ into $B$ buckets (intervals) [S1][S2].
    *   Initially, the intervals may be equal-width or equal-count [S1][S2].
    *   Traverse the sequence of distribution units generated in Step 4.
    *   For each unit $u$, determine its error $E_u$ and place $u$ into the bucket corresponding to the interval containing $E_u$ [S1][S2].
    *   **Adjustment:** Adjust the bucket boundaries so that each bucket holds a similar number of distribution units [S1][S2].

6.  **Round-Robin Distribution:**
    *   For each bucket, distribute the contained distribution units to the $P$ processors in a round-robin fashion [S1][S2].
    *   Because units with similar errors are in the same bucket, and they are distributed round-robin, neighboring units with similar errors are assigned to different processors. This balances the workload and minimizes cache contention [S1][S2].

### Pseudocode

```python
def distribute_wavelet_tree(wavelet_tree, num_processors, k, num_buckets):
    # Step 1: EVERY-K storage strategy
    representative_nodes = []
    for node in wavelet_tree.breadth_first_search():
        if node.level % k == 0:
            node.is_representative = True
            representative_nodes.append(node)
        else:
            node.is_representative = False
            
    # Step 2: Form distribution units
    distribution_units = []
    for rep in representative_nodes:
        unit = {'rep': rep, 'descendants': [], 'error': 0.0}
        distribution_units.append(unit)
        
    # Assign associated nodes to their nearest ancestor representative
    for node in wavelet_tree.breadth_first_search():
        if not node.is_representative:
            ancestor = node.parent
            while ancestor is not None and not ancestor.is_representative:
                ancestor = ancestor.parent
            if ancestor is not None:
                for unit in distribution_units:
                    if unit['rep'] == ancestor:
                        unit['descendants'].append(node)
                        break
                        
    # Step 3: Compute errors
    for unit in distribution_units:
        unit['error'] = compute_reconstruction_error(unit['rep'])
    err_min = min(u['error'] for u in distribution_units)
    err_max = max(u['error'] for u in distribution_units)
    
    # Step 4: Hierarchical SFC traversal
    sfc_order = []
    for level in wavelet_tree.levels:
        nodes_at_level = sorted(level.nodes, key=lambda n: hilbert_index(n.coordinates))
        for node in nodes_at_level:
            if node.is_representative:
                for unit in distribution_units:
                    if unit['rep'] == node:
                        sfc_order.append(unit)
                        break
                        
    # Step 5: Error-guided bucketization
    buckets = [[] for _ in range(num_buckets)]
    interval_width = (err_max - err_min) / num_buckets
    for unit in sfc_order:
        idx = int((unit['error'] - err_min) / interval_width)
        if idx >= num_buckets: idx = num_buckets - 1
        buckets[idx].append(unit)
        
    # Adjust intervals so each bucket holds similar number of units
    sorted_units = sorted(distribution_units, key=lambda u: u['error'])
    chunk_size = len(sorted_units) // num_buckets
    boundaries = [sorted_units[i * chunk_size]['error'] for i in range(1, num_buckets)]
    
    buckets = [[] for _ in range(num_buckets)]
    for unit in sfc_order:
        idx = 0
        for i, bound in enumerate(boundaries):
            if unit['error'] < bound:
                break
            idx += 1
        buckets[idx].append(unit)
        
    # Step 6: Round-robin distribution
    assignment = {}
    for bucket in buckets:
        for i, unit in enumerate(bucket):
            assignment[unit['rep'].id] = i % num_processors
            
    return assignment
```

### Parameters and Edge Cases
*   **Parameter $k$:** Determines the granularity of pre-reconstruction. A smaller $k$ means more representative nodes, higher memory usage for stored data blocks, but potentially faster reconstruction (fewer steps up the tree). A larger $k$ saves memory but increases reconstruction cost. Default: Root is representative, leaves are associated [S1][S2].
*   **Space-Filling Curve:** Hilbert curve is used [S1].
*   **Edge Case: $h$ not a multiple of $k$:** The text states this can be "easily handled" [S1][S2]. Typically, this means the last interval may be smaller than $k$, or the final representative nodes are placed at the deepest level $\le h$ that satisfies the modulo condition.
*   **Precision:** Error calculation can be expensive for large datasets. The MSE calculation becomes progressively more expensive as one traverses toward the root [S2].

## Operating characteristics

*   **Time Complexity:**
    *   **Tree Construction:** Approximately one hour on a 2.0GHz Intel Pentium 4 with 1GB RAM for the tested dataset [S1].
    *   **Distribution:** Linear in the number of distribution units, dominated by the SFC traversal and sorting.
*   **Memory Complexity:**
    *   **Storage:** Compressed data size was around 2.65GB for the tested dataset [S1].
    *   **Runtime:** Requires temporary disk space (256MB) and main memory (128MB) per processor for caching reconstructed data blocks [S1].
*   **Performance:**
    *   Achieves well-balanced workload among processors [S1][S2].
    *   Eliminates inter-processor communication dependencies during reconstruction [S1].
    *   Minimizes run-time communication overhead [S1].
*   **Strengths:**
    *   Scalability due to minimized dependencies.
    *   Load balancing via error-guided bucketization and SFC locality.
*   **Limitations:**
    *   Error computation can be slow for very large datasets [S2].
    *   Requires pre-reconstruction of data blocks, increasing storage requirements compared to storing only coefficients.

## Background

*   **Origin:** Proposed by C. Wang, J. Gao, and H. W. Shen.
*   **Papers:**
    *   "Parallel Multiresolution Volume Rendering of Large Data Sets with Error-Guided Load Balancing" (2004) [S2].
    *   "A Parallel Multiresolution Volume Rendering Algorithm for Large Data Sets" (2005) [S1].
*   **Context:** Developed to address the scalability issues in parallel volume rendering of large datasets using wavelet trees. Previous methods suffered from high communication overhead due to parent-child dependencies in wavelet reconstruction. This method introduces the EVERY-K storage strategy and error-guided bucketization to solve these issues [S1][S2].
