# Multi-resolution ImageVolume and VoxelManager API

Also called: ImageVolume API, MR-API, VoxelManager API

## Overview
This method defines the application programming interface (API) for managing multi-resolution volume data within the `ImageVolume` and `VoxelManager` components, enabling adaptive resolution rendering based on GPU capabilities and memory constraints [S1, unofficial]. It distinguishes itself from sibling methods by providing a generic texture pool and a pluggable grid selection mechanism that handles both "texture too large" and "insufficient memory" errors through a unified rejection path, while maintaining backward compatibility with existing public surfaces [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** New data for a region at a stated quality (brick, sub-resolution frame, or full frame) delivered via an API [S1, unofficial].
*   **Input:** A GPU capability profile (e.g., '32gb fast', '256 edge slow') defining maximum texture edge and memory limits [S1, unofficial].
*   **Output:** A texture bound to the shader for rendering, selected from a pool based on availability and capability [S1, unofficial].
*   **Output:** Quality records (fidelity information) per viewport, reflecting the resolution actually used [S1, unofficial].

**Data Structures:**
*   **ImageVolume:** Holds a pool of textures. The public surface (`dimensions`, `spacing`, `origin`, `direction`, `imageIds`, `getImageIdIndex`) remains unchanged [S1, unofficial].
*   **Texture Pool Entry:**
    *   **Key:** A pair consisting of the grid descriptor and a statistic defined in MR-API-VM-6.2 [S1, unofficial].
    *   **Value:** The texture object and a reference count [S1, unofficial].
    *   **Lifetime Rule:** Generic over grid kind; one pool serves all texture kinds (including oblique grids) [S1, unofficial].
*   **ImageQualityStatus:** A mutable summary derived from an absolute record. Values are renumbered to fill gaps and are not a stable storage format [S1, unofficial].
*   **Grid Descriptor:** A tuple of dimensions selecting a 3D grid. The index space is three-dimensional; `getAtIJK` takes no additional arguments [S1, unofficial]. Grids admit per-level differing extents and non-uniform tiling [S1, unofficial].

**Numbered Steps:**

1.  **Profile Selection:** The application declares a GPU capability profile. The profile defines a maximum texture edge (e.g., 2048) and memory limits [S1, unofficial].
2.  **Data Acceptance:** An API accepts new data for a region at a stated quality. Loaders deliver bricks, sub-resolution frames, or full frames [S1, unofficial].
3.  **Grid Selection (Pluggable):** Before allocation, a pluggable function (parameter of the render path) compares image data dimensions against the capability profile [S1, unofficial].
    *   If the full-resolution grid exceeds the maximum edge, the function selects an alternate grid that fits [S1, unofficial].
    *   Reduction is non-uniform per axis. For example, a 2049-voxel edge exceeds a 2048 limit by one voxel; only that axis is reduced, not all three [S1, unofficial].
    *   The function is consulted at runtime, not just at setup [S1, unofficial].
4.  **Texture Allocation Check:** The pool counts the cost of the texture before allocation and compares it against the declared memory limit [S1, unofficial].
5.  **Lazy Refill:** If new data arrives, it marks the affected region of each texture as "dirty" [S1, unofficial]. The refill happens in the next render of that texture [S1, unofficial]. The dirty flag belongs to the texture pool and the region [S1, unofficial].
6.  **Rendering Claim:** A render path claims an entry from the pool and releases it after the draw [S1, unofficial]. Two viewports showing the same oblique plane share one slab [S1, unofficial].
7.  **Rejection Handling:** If the pool cannot allocate (due to size or memory):
    *   It first removes the entry with no references that is the least recently used (LRU) [S1, unofficial].
    *   If sufficient memory is not released, the pool refuses the request [S1, unofficial].
    *   The render path selects a grid it can afford (a lower resolution) [S1, unofficial].
8.  **Composite Filling:** The composite computes which sub-voxel managers fill a texture, filling the grid from the best available sources [S1, unofficial]. No strategy parameter exists in this version [S1, unofficial].
9.  **Progressive Loading:** The composite consumes existing machinery (`ProgressiveRetrieveImages`, `cachedFrames`, `ImageQualityStatus`) [S1, unofficial].
    *   **JLS Model:** Reduced data at a separate server path; no sub-resolution decode [S1, unofficial].
    *   **HTJ2K Model:** Reduction in the decoder via `decodeLevel` and byte range [S1, unofficial].
    *   The composite must take the reduced frame at its true decoded size before up-scaling to full dimensions [S1, unofficial].
10. **Quality Reporting:** Render paths (MPR and 3D) report the quality used. The MPR path clears the quality indicator where display resolution is below data resolution [S1, unofficial].

**Formulas:**
*   **Grid Selection Condition:** Let $D = (d_x, d_y, d_z)$ be the data dimensions and $E_{max}$ be the maximum texture edge from the profile.
    *   If $\max(D) > E_{max}$, select a reduced grid $D'$ such that $\max(D') \le E_{max}$ and $D'$ is non-uniformly reduced [S1, unofficial].
    *   Specifically, if $d_x = 2049$ and $E_{max} = 2048$, then $d'_x = 2048$ (or lower), while $d'_y = d_y$ and $d'_z = d_z$ (unless they also exceed limits) [S1, unofficial].

**Parameters:**
*   **Capability Profiles:** Named lists (e.g., '32gb fast', '256 edge slow') defined by GPU classes and default memory figures [S1, unofficial].
*   **Dirty Flag:** Boolean flag per texture region indicating need for refill [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Non-Uniform Reduction:** A volume with an edge of 2049 voxels exceeds a maximum edge of 2048 on one axis. The code must reduce only that one axis. A uniform reduction by factor 2 on three axes is incorrect as it reduces volume by 8x for a 1-voxel excess [S1, unofficial].
*   **Dead Flag:** The flag `multiTexturePerVolumeEnabled` in `vtkStreamingOpenGLVolumeMapper.js:104` remains dead (local const) until Part 2. Binding more than one texture in the shader is deferred [S1, unofficial].
*   **Upscaling Loss:** If a smaller decoded frame is upscaled to full dimensions before the texture sees it, the memory saving disappears. The composite must take the reduced frame at its true decoded size [S1, unofficial].
*   **Z-Dimension Meaning:** The voxel manager answers queries about the z-dimension meaning (spatial or time). A parent voxel manager can define a different meaning for z via a selector passed by the parent [S1, unofficial].
*   **Oblique Grids:** Oblique texture grids are textures at an integer offset from original integer image indices, with a view up and a view right. They are not a new kind of object [S1, unofficial].

**Pseudocode:**

```python
class TexturePool:
    def __init__(self, capability_profile):
        # capability_profile contains max_edge and max_memory
        self.max_edge = capability_profile.max_edge
        self.max_memory = capability_profile.max_memory
        self.pool = {}  # Key: (grid_descriptor, statistic), Value: {texture, ref_count, last_used}
        self.dirty_regions = {}  # Key: texture_id, Value: set of region_ids

    def get_or_create_texture(self, grid_descriptor, statistic, data_source):
        key = (grid_descriptor, statistic)
        if key in self.pool:
            entry = self.pool[key]
            entry.ref_count += 1
            entry.last_used = current_time()
            return entry.texture
        
        # Check cost before allocation
        cost = self.calculate_texture_cost(grid_descriptor)
        if cost > self.max_memory:
            # Refuse request, let render path select lower grid
            return None
        
        # Try to allocate
        if not self.has_sufficient_memory(cost):
            self.evict_lru_unreferenced()
            if not self.has_sufficient_memory(cost):
                return None
        
        # Create texture
        texture = create_texture(grid_descriptor, data_source)
        self.pool[key] = {
            'texture': texture,
            'ref_count': 1,
            'last_used': current_time()
        }
        return texture

    def mark_dirty(self, texture_id, region_id):
        if texture_id not in self.dirty_regions:
            self.dirty_regions[texture_id] = set()
        self.dirty_regions[texture_id].add(region_id)

    def refill_dirty(self, texture_id):
        if texture_id in self.dirty_regions:
            regions = self.dirty_regions[texture_id]
            for region in regions:
                update_texture_region(texture_id, region)
            self.dirty_regions[texture_id] = set()

    def evict_lru_unreferenced(self):
        unreferenced = [k for k, v in self.pool.items() if v.ref_count == 0]
        if not unreferenced:
            return
        # Sort by last_used
        unreferenced.sort(key=lambda k: self.pool[k].last_used)
        # Remove LRU
        key_to_remove = unreferenced[0]
        del self.pool[key_to_remove]

class RenderPath:
    def __init__(self, texture_pool, capability_profile):
        self.texture_pool = texture_pool
        self.grid_selector = self.default_grid_selector
        self.capability_profile = capability_profile

    def default_grid_selector(self, data_dimensions):
        # Non-uniform reduction
        max_dim = max(data_dimensions)
        if max_dim <= self.capability_profile.max_edge:
            return data_dimensions
        
        # Reduce only the axis that exceeds, or find minimal non-uniform reduction
        # Example: if x exceeds, reduce x. If multiple exceed, reduce all minimally.
        reduced_dims = list(data_dimensions)
        for i in range(3):
            if reduced_dims[i] > self.capability_profile.max_edge:
                reduced_dims[i] = self.capability_profile.max_edge
        return tuple(reduced_dims)

    def render(self, data, grid_descriptor):
        # Select grid
        selected_grid = self.grid_selector(data.dimensions)
        
        # Get texture
        texture = self.texture_pool.get_or_create_texture(selected_grid, data.statistic, data.source)
        
        if texture is None:
            # Fallback: select even lower grid or report error
            return
        
        # Claim texture
        texture.ref_count += 1
        
        # Refill if dirty
        self.texture_pool.refill_dirty(texture.id)
        
        # Bind and render
        bind_texture(texture)
        draw_volume()
        
        # Release texture
        texture.ref_count -= 1
```

## Operating characteristics
*   **Time Complexity:** Grid selection is O(1) per axis check. Texture allocation is O(N) where N is the number of textures in the pool (for LRU eviction). Refill is proportional to the number of dirty regions.
*   **Memory Complexity:** Proportional to the sum of the sizes of textures in the pool. The pool evicts unreferenced textures to stay within `max_memory`.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales with GPU memory and texture edge limits defined by the capability profile.
*   **Strengths:** Generic texture pool, unified error handling, non-uniform reduction, lazy refill, backward compatibility.
*   **Limitations:** Deferred multi-texture binding, no strategy parameter for composite filling, mutable `ImageQualityStatus` not stable for storage.
*   **When to Use:** When rendering volumes with varying GPU capabilities or when memory constraints require adaptive resolution.
*   **When Not to Use:** When fixed resolution is sufficient or when multi-texture binding is required immediately.

## Background
This method originates from a feature request for the cornerstone3D library, addressing the need for multi-resolution volume rendering and adaptive data management [S1, unofficial]. It builds on existing machinery like `ProgressiveRetrieveImages`, `cachedFrames`, and `ImageQualityStatus` [S1, unofficial]. The issue was filed on GitHub in 2026 [S1, unofficial].
