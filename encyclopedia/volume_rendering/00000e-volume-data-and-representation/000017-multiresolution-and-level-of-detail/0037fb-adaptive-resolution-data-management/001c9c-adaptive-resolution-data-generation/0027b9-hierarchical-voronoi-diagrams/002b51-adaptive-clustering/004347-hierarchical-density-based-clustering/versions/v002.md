# Hierarchical Density-based Clustering

Also called: Linsen et al. clustering, density-based hierarchical clustering

## Overview
Hierarchical Density-based Clustering is a technique for multi-dimensional feature space that generates a hierarchy of nested clusters based on density estimates, allowing for interactive exploration in cluster space rather than high-dimensional feature space [S1, unofficial]. It sets itself apart from parallel coordinates-based approaches by building on clustering to scale better to high dimensionality, and from non-visual clustering methods by providing an explicit cluster tree visualization that serves as an intuitive interaction widget [S1, unofficial].

## How it works
**Inputs:** A set of $N$ points in an $n$-dimensional feature space [S1, unofficial]. Each point represents a voxel's multi-variate data values [G].
**Outputs:** A hierarchical cluster tree and an assignment of a unique cluster ID and density value to each input point [S1, unofficial].

**Data Structures:**
1.  **Histogram:** An $n$-dimensional grid of cells [G]. Each cell stores a count of points falling within its bounds [S1, unofficial].
2.  **Cluster Tree:** A tree structure where nodes represent clusters [G]. Each node contains a list of point indices belonging to that cluster (excluding those in child clusters) [S1, unofficial].
3.  **Point Attributes:** Each point stores its assigned `cluster_id` and `density` [S1, unofficial].

**Parameters:**
*   $n$: The number of dimensions in the feature space [S1, unofficial].
*   Cell Size: The pre-defined size for the $n$-dimensional histogram bins [S1, unofficial].

**Algorithm Steps:**

1.  **Compute Densities:** Build an $n$-dimensional histogram with the specified cell size [S1, unofficial]. The density of a cell is proportional to the number of points falling into it; this count is used as the density estimate assigned to each point in that cell [S1, unofficial].
2.  **Initialize Hierarchy:** The root cluster (density 0) contains all points [S1, unofficial].
3.  **Generate First Clusters (Density 1):** Identify all connected components in the histogram where cells have density $\ge 1$ [S1, unofficial]. Two cells are connected if they share a face, edge, or vertex (i.e., they are $3^n-1$ connected in $n$ dimensions) [G]. Each connected component forms a cluster of density 1 [S1, unofficial].
4.  **Iterative Refinement:** Iteratively remove cells with the lowest remaining density values from the histogram [S1, unofficial]. If removing a cell causes a connected component to split into more than one, the respective cluster breaks into sub-clusters [S1, unofficial].
5.  **Stop Condition:** The process stops when reaching the maximum density [S1, unofficial].
6.  **Assign Cluster IDs:** Assign a unique cluster ID to each cluster [S1, unofficial]. Traverse clusters in the order of extraction and mark points with the respective cluster index [S1, unofficial]. Points contained in children overwrite the cluster ID of their parent, so each inner node contains all points of the cluster not contained in any sub-cluster [S1, unofficial].

**Pseudocode:**

```python
def hierarchical_density_clustering(points, cell_size):
    """
    points: List of n-dimensional vectors.
    cell_size: Scalar size for each dimension of the histogram bin.
    Returns: cluster_tree, point_cluster_ids, point_densities
    """
    n = len(points[0])
    
    # Step 1: Compute Densities
    histogram = {}
    point_cell_map = {}
    for idx, p in enumerate(points):
        cell_idx = tuple(int(val / cell_size) for val in p)
        point_cell_map[idx] = cell_idx
        histogram[cell_idx] = histogram.get(cell_idx, 0) + 1
        
    cell_densities = histogram
    max_density = max(cell_densities.values()) if cell_densities else 0
    
    # Step 2: Initialize Hierarchy
    root = Cluster(id=0, density=0, points=set(range(len(points))))
    clusters = [root]
    cluster_map = {0: root}
    next_id = 1
    
    # Helper: generate all 3^n - 1 neighbor offsets
    def _neighbor_diffs(n):
        diffs = []
        for i in range(1, 3**n):
            diff = []
            temp = i
            for _ in range(n):
                diff.append(temp % 3 - 1)
                temp //= 3
            diffs.append(tuple(diff))
        return diffs
        
    # Helper: find connected components for cells with density >= min_d
    def get_components(min_d):
        active = {c for c, d in cell_densities.items() if d >= min_d}
        if not active: return []
        visited = set()
        comps = []
        for start in active:
            if start in visited: continue
            comp = set()
            queue = [start]
            visited.add(start)
            while queue:
                curr = queue.pop(0)
                comp.add(curr)
                for diff in _neighbor_diffs(n):
                    nb = tuple(c + d for c, d in zip(curr, diff))
                    if nb in active and nb not in visited:
                        visited.add(nb)
                        queue.append(nb)
            comps.append(comp)
        return comps

    # Step 3 & 4: Generate clusters level by level
    # Iteratively removing lowest density cells is equivalent to 
    # computing connected components at increasing density thresholds.
    components_at_level = {}
    cluster_ids_at_level = {}
    
    for d in range(1, max_density + 1):
        comps = get_components(d)
        components_at_level[d] = comps
        current_ids = []
        
        if d == 1:
            parent_id = 0
        else:
            prev_comps = components_at_level[d-1]
            cell_to_parent_idx = {}
            for p_idx, p_comp in enumerate(prev_comps):
                for c in p_comp:
                    cell_to_parent_idx[c] = p_idx
                    
        for comp in comps:
            if d == 1:
                parent_id = 0
            else:
                parent_idx = None
                for c in comp:
                    if c in cell_to_parent_idx:
                        parent_idx = cell_to_parent_idx[c]
                        break
                parent_id = cluster_ids_at_level[d-1][parent_idx]
                
            new_cluster = Cluster(id=next_id, density=d, points=set())
            next_id += 1
            clusters.append(new_cluster)
            cluster_map[new_cluster.id] = new_cluster
            cluster_map[parent_id].children.append(new_cluster)
            current_ids.append(new_cluster.id)
            
            # Assign points to this cluster
            for c in comp:
                for idx, p_cell in point_cell_map.items():
                    if p_cell == c:
                        new_cluster.points.add(idx)
                        
        cluster_ids_at_level[d] = current_ids
        
    # Step 6: Assign final IDs to points (overwrite rule)
    point_cluster_ids = {}
    point_densities = {}
    for idx in range(len(points)):
        best_cluster = None
        best_density = -1
        for cl in clusters:
            if idx in cl.points and cl.density > best_density:
                best_density = cl.density
                best_cluster = cl
        point_cluster_ids[idx] = best_cluster.id if best_cluster else 0
        point_densities[idx] = best_cluster.density if best_cluster else 0
        
    return clusters, point_cluster_ids, point_densities

class Cluster:
    def __init__(self, id, density, points):
        self.id = id
        self.density = density
        self.points = points
        self.children = []
```

**Edge Cases and Pitfalls:**
*   **Precision:** The cell size parameter is critical. If too large, distinct clusters merge. If too small, noise creates spurious clusters [G].
*   **Boundaries:** Points on the boundary of the feature space may have artificially low densities if the histogram is not padded or handled correctly [G].
*   **Degenerate Input:** If all points have the same density, only one cluster (the root) or a single level of clusters will exist [G].
*   **Connectivity Definition:** The definition of "connected" (face, edge, vertex) must be consistent with the dimensionality $n$. In high dimensions, the number of neighbors grows exponentially ($3^n - 1$) [G].

## Operating characteristics
*   **Time Complexity:** Building the histogram is $O(N)$. Finding connected components depends on the number of cells and their connectivity. In the worst case, it can be expensive in high dimensions due to the exponential growth of neighbors [G].
*   **Memory Complexity:** Proportional to the number of points and the size of the histogram. The histogram can be sparse, so a hash map is often used [G].
*   **Strengths:** Parameter-free (no need to specify number of clusters or density levels) [S1, unofficial]. Handles arbitrary cluster shapes [S1, unofficial]. Scales better to high dimensionality than parallel coordinates [S1, unofficial].
*   **Limitations:** Sensitive to the cell size parameter [G]. Computationally expensive in high dimensions [G].
*   **When to use:** When exploring multi-variate volume data and needing an intuitive, interactive cluster hierarchy [S1, unofficial].
*   **When not to use:** When real-time performance is critical in very high dimensions, or when the data is uniformly distributed (leading to a single large cluster) [G].

## Background
The method is based on the work by Linsen et al. [LLRR08, LLR09, LL09] [S1, unofficial]. It was introduced as part of a cluster hierarchy-based user interface for interactive visual exploration of multi-variate volume data [S1, unofficial]. It combines advantages of previous approaches by Akiba et al. [AM07, AMCH07] (intuitive UI), Tzeng and Ma [TM04] (interaction with clustering results), and Linsen et al. (cluster tree visualization) [S1, unofficial].
