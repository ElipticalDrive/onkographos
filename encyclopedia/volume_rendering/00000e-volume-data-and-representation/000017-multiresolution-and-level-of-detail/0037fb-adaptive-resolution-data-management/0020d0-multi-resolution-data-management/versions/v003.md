# Multi-resolution Data Management

Also called: Flat Blocking Multi-resolution, Flat Blocking Multi-resolution Data Management, Flat Multiresolution Blocking, Multi-resolution Data Management for Light, Multiresolution Blocking for LAO, Multiresolution volume management

## Overview
Multi-resolution Data Management is a data structure and preprocessing approach that reduces computation and storage in volume rendering by avoiding superfluous sampling in empty or homogeneous spaces [S1, S2]. It divides the volume into small blocks and organizes them into a multi-resolution structure based on Level-of-Detail (LOD) rather than spatial location [S2]. This method sets itself apart from standard spatial partitioning by packing blocks of varying resolutions into a single texture and skipping calculations for non-contributing regions entirely, enabling storage reduction of at least a factor of 8 and speed-up for light computations [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A high-resolution volume dataset and a Transfer Function (TF) domain [S1, S2].
*   **Output:** A packed multi-resolution data structure consisting of a single 3D texture containing block data and an index texture specifying block locations and resolutions [S1].

**Data Structures:**
1.  **Packed Texture:** A single 3D texture containing all blocks of different resolutions, organized by LOD rather than spatial location [S1, S2].
2.  **Index Texture:** Specifies the location and resolution of each block within the packed texture [S1].
3.  **Reverse Index Map (P→V):** Maps packed coordinates to volume coordinates [S1]. It holds volume coordinates ($V$) for all non-empty blocks [S1].

**Parameters:**
*   **Block Size:** Each block consists of $16^3$ voxels [S1, S2].
*   **Highest Resolution Level ($\lambda_h$):** The maximum LOD level in the multiresolution hierarchy [S1]. In the reference implementation, $\lambda_h = 4$ [S1].
*   **Resolution Levels:** Discrete numbers in the range $[0, \lambda_h]$ [S1].
*   **Minimum Resolution:** Blocks with resolution levels corresponding to $1^3$ and $2^3$ voxels are ignored to reduce the reverse index map size by a factor of 64 [S1]. Non-empty blocks have a minimum resolution of $4^3$ voxels [S1].

**Algorithm Steps:**
1.  **Blocking:** Divide the input volume into small cubes of size $16^3$ voxels [S1, S2].
2.  **LOD Assignment:** Assign a Level-of-Detail (LOD) to each block based on its content in the TF domain to optimize image quality [S1, S2]. Empty or non-contributing blocks are assigned the lowest resolution or ignored entirely [S1, S2]. Blocks with significant content are assigned higher resolutions, up to $\lambda_h$ [S1].
3.  **Packing:** Pack all blocks into a single 3D texture, organizing them by their LOD rather than their original spatial coordinates [S1, S2].
4.  **Indexing:** Create an index texture that records the position and resolution of each block in the packed texture [S1].
5.  **Reverse Map Construction:** Create a reverse index map (P→V) for non-empty blocks [S1]. Ignore blocks with resolution levels $1^3$ and $2^3$ to reduce the map size by a factor of 64 [S1]. Store volume coordinates ($V$) for all remaining non-empty blocks (minimum resolution $4^3$) [S1].
6.  **Runtime Processing:** Perform light computations directly in the coordinates of the multi-resolution data structure [S2]. Skip calculations for empty blocks [S2]. Use the reverse index map to determine the original volume location of a voxel if needed [S1].

**Pseudocode:**
```python
def preprocess_volume(volume_data, block_size=16, lambda_h=4):
    """
    Preprocesses a volume into a multi-resolution structure.
    Args:
        volume_data: 3D array of voxel values.
        block_size: Size of each block in voxels (default 16).
        lambda_h: Highest resolution level (default 4).
    Returns:
        packed_blocks: List of flattened block data packed by LOD.
        index_data: List of (packed_index, volume_coords, resolution) tuples.
        reverse_map: Dict mapping packed_index to volume_coords.
    """
    packed_blocks = []
    index_data = []
    reverse_map = {}
    packed_idx = 0

    # Step 1 & 2: Blocking and LOD Assignment
    for x in range(0, volume_data.shape[0], block_size):
        for y in range(0, volume_data.shape[1], block_size):
            for z in range(0, volume_data.shape[2], block_size):
                # Extract block data
                block_data = volume_data[
                    x:x+block_size, y:y+block_size, z:z+block_size
                ]
                # Determine LOD based on TF content to optimize image quality [S1, S2]
                # The exact LOD metric based on TF content is not given in the sources [G].
                lod = 0 
                if lod == 0:
                    continue # Skip empty/non-contributing blocks [S1, S2]

                # Assign resolution based on LOD
                # Minimum resolution for non-empty blocks is 4^3 [S1]
                resolution = max(4, lod)

                # Step 5: Ignore blocks with resolution < 4^3 for reverse map [S1]
                if resolution < 4:
                    continue

                # Step 3 & 4: Packing and Indexing
                # Pack block data into a flat list representing the 3D texture [S1, S2]
                packed_blocks.append(block_data.flatten())
                # Record index, volume coordinates, and resolution [S1]
                index_data.append((packed_idx, (x, y, z), resolution))
                # Step 5: Build reverse map (P->V) [S1]
                reverse_map[packed_idx] = (x, y, z)
                packed_idx += 1

    return packed_blocks, index_data, reverse_map
```

**Edge Cases and Pitfalls:**
*   **Interpolation Artifacts:** Because blocks are not packed spatially, standard texture interpolation can cause artifacts at block boundaries [S2].
    *   *Solution:* Clamp sample locations to a proper distance from block borders [S2]. This is sufficient for $\alpha_{lp}$ and $I_{final}$ but not for global opacity $\alpha_g$ [S2].
*   **Reverse Map Size:** A block represented by a single voxel in the packed texture would require a reverse index map of the same size as the packed texture [S1].
    *   *Solution:* Ignore blocks with the two lowest resolution levels ($1^3$ and $2^3$) to reduce the map size by a factor of 64 [S1].

## Operating characteristics
*   **Storage Reduction:** Can reduce texture sizes by at least a factor of 8 compared to full resolution volumes [S2]. For example, a $512^3$ volume can be stored using $256 \times 256 \times 128$ voxels without significant loss of information [S2].
*   **Performance:** Provides a speed-up in LAO (Local Ambient Occlusion) processing due to data reduction from LOD selection [S1]. Skips calculations for empty regions, decreasing the number of render passes required for illumination updates [S2].
*   **Complexity:** Preprocessing involves blocking, LOD assignment, and packing [S1, S2]. Runtime involves texture lookups and clamping [S2].
*   **Strengths:** Significant storage and computation savings for large-scale volumes with large empty or homogeneous areas [S2]. Supports interactive frame rates for global lighting [S2].
*   **Limitations:** Interpolation artifacts require clamping, which may not be feasible for all computations such as global opacity [S2]. LOD selection depends on TF domain optimization, which may be complex to implement [S1].

## Background
*   **Origin:** The method was introduced in [LLYM04] and detailed in [LLY06] [S1, S2].
*   **Development:** It was applied in the context of Local Ambient Occlusion (LAO) for volume rendering [S1]. Hernell et al. used it in 2007 for efficient ambient and emissive tissue illumination [S1].
*   **Usage:** Used in medical volume rendering (e.g., $512^3$ datasets) to support interactive frame rates for global light propagation with scattering effects [S2].
