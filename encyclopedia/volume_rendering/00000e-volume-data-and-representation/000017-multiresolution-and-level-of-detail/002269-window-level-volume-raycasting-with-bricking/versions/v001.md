# Window/Level Volume Raycasting with Bricking

Also called: LQ/HQ Volume Rendering, Volume Raycasting with Window/Level and Bricking, Window/Level Volume Rendering

## Overview
Window/Level Volume Raycasting with Bricking is a direct volume rendering technique that combines spatial decomposition (bricking) with intensity-based clipping (window/level) to accelerate the raycasting of large medical datasets on standard hardware [S1, S2, unofficial]. It addresses the performance bottleneck of processing empty or irrelevant background voxels by skipping ray marching steps based on density thresholds and by organizing data into cache-friendly bricks [S1, S2, unofficial]. Unlike standard direct volume rendering which samples every voxel along the ray, this method uses a "window" (width) and "level" (center) to define the range of interest, allowing for early termination and step skipping [S1, unofficial]. It is distinct from pure bricking methods by its explicit integration of window/level transfer function mapping and from void-culling methods by its reliance on density thresholds rather than hierarchical spatial structures for culling [S1, unofficial].

## How it works
The method renders a volume by casting rays through a decomposed dataset (bricks), applying window/level transformations to voxel values, and using density-based skipping to optimize the ray march [S1, S2, unofficial].

### Inputs and Outputs
*   **Input**: 3D volume data (typically medical, e.g., DICOM), camera parameters (origin, direction), window/level parameters ($gLevel$, $gWindow$), bricking parameters ($chunkSize$, $numChunksX/Y/Z$), and rendering mode flags (LQ/HQ) [S1, unofficial].
*   **Output**: 2D image (color buffer) [S1, unofficial].

### Data Structures
The volume is decomposed into **bricks** (chunks) of fixed size $chunkSize \times chunkSize \times chunkSize$ [S1, S2, unofficial].
*   **Brick Layout**: The volume is indexed by $(chunkX, chunkY, chunkZ)$ and local element indices $(x, y, z)$ within the brick [S2, unofficial].
*   **Parameters**:
    *   $gLevel$: Window center [S1, unofficial].
    *   $gWindow$: Window width [S1, unofficial].
    *   $voxelSpacingBuffer$: Spacing in x, y, z [S1, unofficial].
    *   $volumeWidth, volumeHeight, volumeDepth$: Global dimensions [S1, unofficial].
    *   $chunkSize$: Brick dimension [S1, unofficial].
    *   $gAmbient$: Ambient lighting constant [S1, unofficial].
    *   $densityForMarchSpaceSkipping$: Threshold for skipping steps [S1, unofficial].
    *   $skipMultiplier$: Multiplier for skip distance [S1, unofficial].
    *   $subtleSurfaceThreshold$: Threshold for subtle surface detection [S1, unofficial].
    *   $surfaceThreshold$: Threshold for surface rendering [S1, unofficial].
    *   $maxSteps$: Maximum ray steps [S1, unofficial].
    *   $minGradientMagnitude$: Minimum gradient for calculation [S1, unofficial].
    *   $accumulatedThreshold$: Early termination opacity threshold [S1, unofficial].
    *   $transmittanceThreshold$: Early termination transmittance threshold [S1, unofficial].
    *   $xmin, xmax, ymin, ymax, zmin, zmax$: Cutting cube bounds [S1, unofficial].

### Algorithm Steps
1.  **Initialization**:
    *   Determine rendering mode (LQ or HQ) based on user input [S1, unofficial].
    *   Select parameters based on mode:
        *   If LQ: use $gUseGradientLQ$, $gDensityForMarchSpaceSkippingLQ$, $gSkipMultiplierLQ$, $gSubtleSurfaceThresholdLQ$, $gSurfaceThresholdLQ$, $gMaxStepsLQ$, $gMinGradientMagnitudeLQ$, $gAccumulatedThresholdLQ$, $gTransmittanceThresholdLQ$ [S1, unofficial].
        *   If HQ: use corresponding $HQ$ variants [S1, unofficial].
    *   Initialize ray origin $O$ and direction $D$ for each pixel [S1, S3, unofficial].
    *   Compute ray entry $t_{start}$ and exit $t_{end}$ within the volume bounds [S1, S3, unofficial].
    *   Apply a fixed random offset to $t$ to prevent banding [S18, unofficial].

2.  **Ray Marching Loop**:
    For each ray, iterate while $t < t_{end}$ and accumulated opacity $< accumulatedThreshold$ and step count $< maxSteps$ [S1, S2, unofficial]:
    *   **Position Calculation**: Compute current 3D position $P = O + t \cdot D$ [S1, S3, unofficial].
    *   **Brick Addressing**: Determine which brick contains $P$ and the local coordinates $(x, y, z)$ within that brick [S2, unofficial].
        *   *Refined Data Addressing*: To avoid pipeline flushes from branch prediction failures, test if the required neighborhood (e.g., for gradient or interpolation) fits within the current brick [S2, unofficial].
        *   If it fits, use a single linear offset calculation [S2, unofficial].
        *   If it does not fit, compute the brick offset plus the element offset [S2, unofficial].
    *   **Sampling**:
        *   Retrieve scalar value $d$ from the brick at $(x, y, z)$ [S1, S2, unofficial].
        *   If gradient calculation is enabled ($toggleGradient$), compute gradient $\nabla d$ using a 26-connected neighborhood or central difference with two-voxel offset to avoid discontinuities [S1, S18, unofficial].
    *   **Window/Level Transformation**:
        *   Map scalar $d$ to normalized intensity $I$ using window/level:
            $$ I = \frac{d - (gLevel - gWindow/2)}{gWindow} $$
        *   Clamp $I$ to $[0, 1]$ [S1, unofficial].
    *   **Transfer Function**:
        *   Map $I$ to color $C$ and opacity $\alpha$ [S2, S5, unofficial].
        *   Apply surface/subtle surface thresholds if in surface rendering mode [S1, unofficial].
    *   **Step Skipping (March Space Skipping)**:
        *   If $d < densityForMarchSpaceSkipping$, skip the current step by advancing $t$ by $skipMultiplier \cdot stepSize$ [S1, unofficial].
        *   This effectively treats low-density regions as transparent/empty [S1, unofficial].
    *   **Compositing**:
        *   Perform front-to-back compositing [S2, S3, S8, S9, S11, S14, S16, S20, S23, S26, unofficial]:
            $$ C'_{new} = C'_{old} + (1 - \alpha'_{old}) \alpha C $$
            $$ \alpha'_{new} = \alpha'_{old} + (1 - \alpha'_{old}) \alpha $$
    *   **Early Termination**:
        *   If $\alpha' \ge accumulatedThreshold$ or transmittance $< transmittanceThreshold$, terminate ray [S1, S2, unofficial].
    *   **Step Increment**:
        *   If not skipped, $t \leftarrow t + stepSize$ [S1, S3, unofficial].

3.  **Finalization**:
    *   Apply gamma correction (2.2) to the final color [S9, unofficial].
    *   Render the resulting image using the GPU pipeline (e.g., via WebGPU or OpenGL) [S1, unofficial].

### Pseudocode
```python
import math
import random

def vec3(x, y, z):
    return [x, y, z]

def clamp(val, min_val, max_val):
    return max(min_val, min(val, max_val))

def compute_ray_exit(origin, direction, bounds):
    # Slab intersection for axis-aligned box [G]
    t0 = max((bounds[0][i] - origin[i]) / direction[i] if direction[i] != 0 else float('inf') for i in range(3))
    t1 = min((bounds[1][i] - origin[i]) / direction[i] if direction[i] != 0 else float('inf') for i in range(3))
    return max(t0, t1)

def trilinear_interpolate(volume_data, pos, dims, chunk_size, num_chunks):
    # Determine brick and local coordinates [S2, unofficial]
    # pos is in [0,1] texture space
    # dims are global volume dimensions
    # chunk_size is brick size
    # num_chunks is global brick counts
    
    # Convert pos to global voxel coordinates
    gx = pos[0] * (dims[0] - 1)
    gy = pos[1] * (dims[1] - 1)
    gz = pos[2] * (dims[2] - 1)
    
    # Determine brick indices
    bx = int(gx // chunk_size)
    by = int(gy // chunk_size)
    bz = int(gz // chunk_size)
    
    # Local coordinates within brick
    lx = gx % chunk_size
    ly = gy % chunk_size
    lz = gz % chunk_size
    
    # Addressing optimization: check if neighborhood fits in brick [S2, unofficial]
    # For simplicity, assume we always fetch the voxel at (lx, ly, lz)
    # In a real implementation, if the gradient/interpolation neighborhood crosses brick boundaries,
    # a more complex address calculation is needed to avoid pipeline flushes [S2, unofficial].
    
    # Retrieve voxel value from the brick
    # Note: volume_data is assumed to be a flattened array of bricks
    # Brick index = bz * num_chunksY * numChunksX + by * numChunksX + bx
    # Local index = lz * chunk_size * chunk_size + ly * chunk_size + lx
    
    brick_idx = bz * num_chunks[1] * num_chunks[0] + by * num_chunks[0] + bx
    local_idx = lz * chunk_size * chunk_size + ly * chunk_size + lx
    
    # Assuming volume_data is a list of bricks, each brick is a list of voxels
    brick = volume_data[brick_idx]
    voxel_value = brick[local_idx]
    
    return voxel_value

def window_level_transform(value, level, width):
    # Map value to [0,1] using window/level [S1, unofficial]
    lower = level - width / 2.0
    normalized = (value - lower) / width
    return clamp(normalized, 0.0, 1.0)

def transfer_function(intensity, mode='LQ'):
    # Simple opacity/color mapping based on intensity [S2, S5, unofficial]
    # In practice, this is a user-defined transfer function
    # For this example, assume a simple linear mapping for demonstration
    if mode == 'LQ':
        opacity = intensity * 0.5
        color = [intensity, intensity, intensity]
    else: # HQ
        opacity = intensity
        color = [intensity, intensity * 0.8, intensity * 0.6]
    return color, opacity

def window_level_volume_raycast(volume_data, camera, volume_dims, chunk_size, num_chunks, level, width, 
                                 density_threshold, skip_multiplier, max_steps, accumulated_threshold, 
                                 mode='LQ'):
    """
    Renders a volume using Window/Level Volume Raycasting with Bricking.
    """
    h, w = camera.screen_height, camera.screen_width
    image = [[vec3(0.0, 0.0, 0.0) for _ in range(w)] for _ in range(h)]
    
    # Volume bounds [G]
    volume_bounds = [[0, 0, 0], [1, 1, 1]]
    
    for y in range(h):
        for x in range(w):
            ray_origin, ray_direction = camera.cast_ray(x, y)
            accumulated_color = vec3(0.0, 0.0, 0.0)
            accumulated_opacity = 0.0
            
            # Ray initialization: fixed random offset to prevent banding [S18, unofficial]
            t = random.uniform(0.0, 0.001) # step_size approx
            
            # Compute ray exit distance from volume bounds [G]
            t_end = compute_ray_exit(ray_origin, ray_direction, volume_bounds)
            
            step_count = 0
            while accumulated_opacity < accumulated_threshold and t < t_end and step_count < max_steps:
                # Compute current position in texture space [0,1]
                pos = [(ray_origin[i] + t * ray_direction[i]) for i in range(3)]
                
                # Sample volume at current position using bricked addressing [S1, S2, unofficial]
                scalar_value = trilinear_interpolate(volume_data, pos, volume_dims, chunk_size, num_chunks)
                
                # Window/Level Transformation [S1, unofficial]
                intensity = window_level_transform(scalar_value, level, width)
                
                # Step Skipping: if density is below threshold, skip [S1, unofficial]
                if scalar_value < density_threshold:
                    t += skip_multiplier * 0.001 # Assuming step_size ~ 0.001
                    step_count += 1
                    continue
                
                # Apply transfer function to get color and opacity [S2, S5, unofficial]
                color, opacity = transfer_function(intensity, mode)
                
                # Front-to-back compositing [S2, S5, unofficial]
                accumulated_color[0] += (1.0 - accumulated_opacity) * opacity * color[0]
                accumulated_color[1] += (1.0 - accumulated_opacity) * opacity * color[1]
                accumulated_color[2] += (1.0 - accumulated_opacity) * opacity * color[2]
                accumulated_opacity += (1.0 - accumulated_opacity) * opacity
                
                # Increment step
                t += 0.001 # step_size
                step_count += 1
                
            # Gamma correction [S9, unofficial]
            image[y][x] = [c**(1.0/2.2) for c in accumulated_color]
            
    return image
```

### Edge Cases and Pitfalls
*   **Pipeline Flushes**: Using `if-else` statements to check brick boundaries for neighborhood access can cause CPU pipeline flushes due to branch prediction failures [S2, unofficial]. The refined addressing scheme mitigates this by testing if the neighborhood fits within a single brick [S2, unofficial].
*   **Precision**: Floating-point precision in position calculations can lead to sampling errors at brick boundaries [S2, unofficial].
*   **Degenerate Input**: If the window/level range is invalid (e.g., width $\le 0$), the transformation is undefined [S1, unofficial].
*   **Empty Volumes**: If the volume contains no data above the density threshold, the ray may terminate early or return black [S1, unofficial].

## Subtopics

### Refined Data Addressing for Bricked Volumes
An addressing scheme designed to minimize the performance penalty of computing two offsets (brick offset + element offset) in a bricked volume layout, specifically avoiding pipeline flushes caused by conditional branches in if-else statements [S2, unofficial]. It tests if the needed data elements can be addressed within one brick; if true, it uses a single linear offset; if false, it performs the costly address calculations [S2, unofficial]. Choose this when rendering on CPUs with long instruction pipelines where branch prediction failures are costly [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is the average number of steps per ray. Step skipping reduces $M$ significantly for sparse volumes [S1, S2, unofficial].
*   **Memory Complexity**: $O(V)$, where $V$ is the volume size, plus overhead for brick structures [S1, S2, unofficial].
*   **Measured Performance**: Tested on Pentium 4 Xeon with 512KB L2 cache [S2, unofficial]. Bricking improves cache locality, reducing memory access latency [S2, unofficial].
*   **Scaling**: Scales well with brick size optimization; larger bricks improve cache hit rates but may increase memory usage [S2, unofficial].
*   **Strengths**: Efficient handling of large medical datasets; early termination and step skipping reduce computation; bricking improves cache performance [S1, S2, unofficial].
*   **Limitations**: Branch prediction penalties if addressing is not optimized; limited to density-based culling (no hierarchical void culling) [S1, S2, unofficial].
*   **When to Use**: Real-time rendering of large medical volumes on standard PC hardware [S2, unofficial].
*   **When Not to Use**: Volumes with complex, non-density-based structures where hierarchical culling is more effective [S1, unofficial].
