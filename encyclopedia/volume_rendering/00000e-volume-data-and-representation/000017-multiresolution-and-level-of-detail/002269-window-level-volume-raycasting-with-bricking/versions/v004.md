# Window/Level Volume Raycasting with Bricking

Also called: LQ/HQ Volume Rendering, Volume Raycasting with Window/Level and Bricking, Window/Level Volume Rendering

## Overview
Window/Level Volume Raycasting with Bricking is a direct volume rendering technique that combines spatial decomposition (bricking) with intensity-based transfer function mapping (window/level) to accelerate the visualization of large medical datasets on standard hardware [S1, S2, unofficial]. It solves the performance bottleneck of raycasting large volumes by storing data in fixed-size bricks to improve cache locality and by using a window/level transformation to map voxel intensities to optical properties [S1, S2, unofficial]. It differs from [Wavelet-based Volume Rendering](1052-wavelet-based-volume-rendering.md) by using spatial tiling rather than frequency-domain compression, and from [Level-of-Detail Volume Rendering via 3D Textures](1706-level-of-detail-volume-rendering-via-3d-textures.md) by relying on fixed-resolution bricks with dynamic transfer function parameters rather than mipmapped texture hierarchies [S1, S2, unofficial].

## How it works
The method renders a volume by casting rays through a 3D grid of bricks, applying a window/level transfer function to determine opacity and color, and accumulating contributions along the ray path [S1, S2, unofficial].

**Inputs and Outputs:**
*   **Input:** A 3D volume dataset of dimensions $W \times H \times D$ (volumeWidth, volumeHeight, volumeDepth) [S1, unofficial].
*   **Input:** Window center ($gLevel$) and window width ($gWindow$) parameters for intensity mapping [S1, unofficial].
*   **Input:** Voxel spacing buffer ($voxelSpacingBuffer$) containing spacing in x, y, z [S1, unofficial].
*   **Input:** Bricking parameters: chunk size ($chunkSize$) and number of chunks ($numChunksX, numChunksY, numChunksZ$) [S1, unofficial].
*   **Input:** Rendering mode flag (Low Quality/LQ or High Quality/HQ) which selects specific threshold constants [S1, unofficial].
*   **Input:** Cutting cube bounds ($xmin, xmax, ymin, ymax, zmin, zmax$) for clipping [S1, unofficial].
*   **Output:** A 2D image frame buffer.

**Data Structures:**
*   **Brick Layout:** The volume is decomposed into bricks of size $chunkSize \times chunkSize \times chunkSize$. The total number of bricks is $numChunksX \times numChunksY \times numChunksZ$ [S1, unofficial].
*   **Ray Marching State:** Accumulated opacity, transmittance, and color [S1, unofficial].

**Parameters:**
*   **Window/Level:** $gLevel$ (center), $gWindow$ (width) [S1, unofficial].
*   **LQ/HQ Thresholds:**
    *   $gDensityForMarchSpaceSkippingLQ/HQ$: Threshold for skipping steps [S1, unofficial].
    *   $gSkipMultiplierLQ/HQ$: Multiplier for step skipping [S1, unofficial].
    *   $gSubtleSurfaceThresholdLQ/HQ$: Threshold for subtle surface detection [S1, unofficial].
    *   $gSurfaceThresholdLQ/HQ$: Threshold for surface rendering [S1, unofficial].
    *   $gMaxStepsLQ/HQ$: Maximum ray marching steps [S1, unofficial].
    *   $gMinGradientMagnitudeLQ/HQ$: Minimum gradient magnitude for gradient calculation [S1, unofficial].
    *   $gAccumulatedThresholdLQ/HQ$: Threshold for accumulated opacity to terminate [S1, unofficial].
    *   $gTransmittanceThresholdLQ/HQ$: Threshold for transmittance to terminate [S1, unofficial].
    *   $gUseGradientLQ/HQ$: Boolean flag for gradient calculation [S1, unofficial].
*   **Bounds:** $xmin, xmax, ymin, ymax, zmin, zmax$ (defaults to -1.0, 1.0 if cutting cube is null) [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Retrieve the mesh buffer for a cube from the mesh buffer manager using the key "cube" [S1, unofficial].
    *   Initialize ray origin and direction based on camera position and screen pixel coordinates.
    *   Initialize accumulated color $C_{acc} = (0,0,0,0)$ and transmittance $T_{acc} = 1.0$ [S1, unofficial].
    *   Determine if LQ or HQ mode is active to select threshold constants [S1, unofficial].

2.  **Ray Marching Loop:**
    *   For each ray, iterate through the bricks along the ray path.
    *   For each brick, iterate through the voxels within the brick.
    *   **Step Skipping:** If the current voxel density is below $gDensityForMarchSpaceSkippingLQ/HQ$, skip $gSkipMultiplierLQ/HQ$ steps [S1, unofficial].
    *   **Gradient Calculation:** If $gUseGradientLQ/HQ$ is true and the gradient magnitude is above $gMinGradientMagnitudeLQ/HQ$, compute the gradient for shading [S1, unofficial].
    *   **Transfer Function:** Map the voxel intensity $I$ to opacity $\alpha$ and color $C$ using the window/level parameters:
        $$ \alpha = \text{WindowLevelMap}(I, gLevel, gWindow) $$
        $$ C = \text{ColorMap}(I) $$
        [S1, unofficial].
    *   **Surface Detection:** Check if the voxel meets $gSubtleSurfaceThresholdLQ/HQ$ or $gSurfaceThresholdLQ/HQ$ for enhanced surface rendering [S1, unofficial].
    *   **Blending:** Apply front-to-back blending:
        $$ C_{acc} = C_{acc} + C \cdot \alpha \cdot T_{acc} $$
        $$ T_{acc} = T_{acc} \cdot (1 - \alpha) $$
        [S1, unofficial].
    *   **Termination:** If $T_{acc} < gTransmittanceThresholdLQ/HQ$ or accumulated opacity exceeds $gAccumulatedThresholdLQ/HQ$, or if $gMaxStepsLQ/HQ$ is reached, terminate the ray [S1, unofficial].

3.  **Rendering:**
    *   Call the volume render pipeline with the offscreen render pass, vertex buffer, index buffer, and index count [S1, unofficial].

**Pseudocode:**

def window_level_opacity(intensity, center, width):
    """
    Maps intensity to opacity using window/level.
    """
    # Standard window/level mapping
    normalized = (intensity - (center - width / 2.0)) / width
    return clamp(normalized, 0.0, 1.0)

def window_level_color(intensity, center, width):
    """
    Maps intensity to color using window/level.

## Subtopics

### Refined Data Addressing for Bricked Volumes
An addressing scheme designed to minimize the performance penalty of computing two offsets (brick offset + element offset) in a bricked volume layout, specifically avoiding pipeline flushes caused by conditional branches in if-else statements [S2, unofficial]. It works by first testing if the needed data elements can be addressed within one brick; if true, it addresses data elements as fast as in a linear volume (single offset); if false, it performs the costly address calculations [S2, unofficial]. The pitfall is that using an if-else statement to check brick boundaries incurs pipeline flushes on CPUs with long instruction pipelines that use branch prediction, as the CPU may flush the pipeline if the branch outcome is false [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels traversed along the ray, but reduced by step skipping and early termination [S1, S2, unofficial].
*   **Memory Complexity:** Proportional to the volume size, but optimized by brick caching [S1, S2, unofficial].
*   **Measured Performance:** Tested on a Pentium 4 Xeon with 512KB Level-2 cache [S2, unofficial].
*   **Strengths:** Improves cache locality through bricking; allows dynamic adjustment of visualization via window/level parameters; supports step skipping for acceleration [S1, S2, unofficial].
*   **Limitations:** Branch prediction penalties in data addressing can negate performance gains; fixed brick size may not be optimal for all data distributions [S2, unofficial].
*   **When to use:** Large medical datasets where real-time interaction is required and hardware has limited cache [S1, S2, unofficial].
*   **When not to use:** When branch prediction penalties outweigh the benefits of bricking, or when higher fidelity is required than LQ/HQ modes provide [S2, unofficial].

## Background
The method originates from research on real-time mono- and multi-volume rendering of large medical datasets on standard PC hardware [S2, unofficial]. It was developed to address the performance challenges of raycasting large volumes by combining spatial decomposition (bricking) with intensity-based transfer function mapping (window/level) [S1, S2, unofficial]. The approach is implemented in web-based volume renderers using WebGPU [S1, unofficial].
