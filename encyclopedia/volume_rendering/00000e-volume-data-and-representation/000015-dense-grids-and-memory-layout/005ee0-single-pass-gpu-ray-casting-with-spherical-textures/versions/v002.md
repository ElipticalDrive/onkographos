# Single-Pass GPU Ray Casting with Spherical Textures

Also called: GPU Ray Casting (Single Pass) with Spherical 3D Textures, GPU ray casting single pass, Single-pass GPU ray casting with 3D textures in spherical coordinates, Single-pass GPU ray marching, spherical volume rendering

## Overview
This method renders a 3D volume dataset stored in spherical coordinates by mapping the data to a 3D texture and performing ray marching entirely within a fragment shader [S1, unofficial][S2, unofficial]. It casts rays from a camera position through a screen-covering quad, converting ray positions to spherical coordinates for texture lookups [S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D texture containing intensity values in spherical coordinates $(r, \theta, \phi)$, camera position `camPos`, step size `step_size`, and an MVP matrix [S1, unofficial][S2, unofficial].
*   **Output:** A 2D image where each pixel represents the alpha-composited color of the ray passing through the volume [S1, unofficial].

**Data Structures**
*   **Dimensions:** $(D_r, D_\theta, D_\phi) = (384, 15, 768)$ [S1, unofficial][S2, unofficial].
*   **Format:** `GL_R16F` (16-bit float, red channel only) with `GL_RED` format and `GL_FLOAT` type [S1, unofficial][S2, unofficial].
*   **Geometry:** A unit cube defined by 8 vertices in object space ranging from $(-0.5, -0.5, -0.5)$ to $(0.5, 0.5, 0.5)$ [S2, unofficial].

**Parameters**
*   `MAX_SAMPLES`: Integer constant, typically 200 (updated) or 300 (original) [S1, unofficial][S2, unofficial].
*   `step_size`: `vec3` uniform controlling the distance advanced per ray march step [S1, unofficial][S2, unofficial].
*   `camPos`: `vec3` uniform for camera position in object space [S1, unofficial][S2, unofficial].
*   `texMin`: `vec3(0.0)` [S1, unofficial].
*   `texMax`: `vec3(1.0)` [S1, unofficial].

**Algorithm Steps**
1.  **Vertex Shader:** Compute clip-space position `gl_Position = MVP * vec4(vVertex, 1.0)` and pass 3D texture coordinates `vUV` to the fragment shader by offsetting unit cube vertex positions from $[-0.5, 0.5]^3$ to $[0, 1]^3$ [S1, unofficial][S2, unofficial].
2.  **Fragment Shader Initialization:** Set `dataPos = vUV` and compute the ray direction by converting the object-space vertex position and camera position to spherical coordinates, subtracting them, and normalizing [S1, unofficial][S2, unofficial].
3.  **Ray Marching Loop:** Iterate up to `MAX_SAMPLES`: advance `dataPos` by `dirStep`, evaluate boundary bounds, convert to spherical texture coordinates, sample intensity, apply transfer function, composite, and check early termination [S1, unofficial][S2, unofficial].
4.  **Boundary Check:** Evaluate `dot(sign(dataPos - texMin), sign(texMax - dataPos)) < 3.0` to detect if `dataPos` has left the $[0, 1]^3$ volume bounds [S1, unofficial].
5.  **Sampling:** Fetch intensity $I$ from the red channel of the volume texture using normalized spherical coordinates [S2, unofficial].
6.  **Transfer Function:** Compute opacity $\alpha$ and color $C$ from $I$ [S1, unofficial][S2, unofficial].
7.  **Compositing:** Update accumulated color and alpha using front-to-back blending [S1, unofficial][S2, unofficial].
8.  **Early Ray Termination:** Break the loop when accumulated alpha exceeds 0.99 [S1, unofficial][S2, unofficial].

**Formulas**
*   **Spherical Conversion:** $r = \sqrt{x^2+y^2+z^2}$, $\phi = \operatorname{atan2}(y, x)$, $\theta = \operatorname{atan2}(\sqrt{x^2+y^2}, z)$ [S1, unofficial][S2, unofficial].
*   **Texture Coordinate Mapping:** $u = r / D_r$, $v = (\theta + \pi/2) / \pi$, $w = \phi / (2\pi)$ [S2, unofficial].
*   **Transfer Function:** $\alpha = \frac{e^{I} - 1}{e^{1} - 1}$, $C = I \cdot \text{vec3}(100.0, 20.0, 10.0)$ [S1, unofficial][S2, unofficial].
*   **Compositing:** $C_{acc} = C_{acc} + (1 - \alpha_{acc}) \alpha C$, $\alpha_{acc} = \alpha_{acc} + (1 - \alpha_{acc}) \alpha$ [S1, unofficial][S2, unofficial].

**Pseudocode**
```python
# Vertex Shader
def vertex_shader(vVertex, MVP):
    gl_Position = MVP * vec4(vVertex, 1.0)
    vUV = vVertex + vec3(0.5)
    return vUV

# Fragment Shader
def fragment_shader(vUV, volume_texture, camPos, step_size):
    MAX_SAMPLES = 200
    texMin = vec3(0.0)
    texMax = vec3(1.0)
    
    dataPos = vUV
    accumulated_color = vec3(0.0)
    accumulated_alpha = 0.0
    
    # Compute ray direction in spherical space
    vertex_cart = vUV - vec3(0.5)
    vertex_sph = cart2sph(vertex_cart)
    cam_sph = cart2sph(camPos)
    dir_sph = normalize(vertex_sph - cam_sph)
    dirStep = dir_sph * step_size
    
    for i in range(MAX_SAMPLES):
        dataPos = dataPos + dirStep
        
        # Boundary check before sampling to prevent out-of-bounds fetches
        if dot(sign(dataPos - texMin), sign(texMax - dataPos)) < 3.0:
            break
            
        # Convert Cartesian position to spherical, then normalize for texture lookup
        sph = cart2sph(dataPos)
        tex_coords = vec3(sph.x / 384.0, (sph.y + 3.141592653589793 / 2.0) / 3.141592653589793, sph.z / (2.0 * 3.141592653589793))
        
        # Sample volume
        intensity = texture(volume_texture, tex_coords).r
        
        # Transfer function
        alpha = (exp(intensity) - 1.0) / (exp(1.0) - 1.0)
        color = intensity * vec3(100.0, 20.0, 10.0)
        
        # Front-to-back compositing
        accumulated_color = accumulated_color + (1.0 - accumulated_alpha) * alpha * color
        accumulated_alpha = accumulated_alpha + (1.0 - accumulated_alpha) * alpha
        
        # Early ray termination
        if accumulated_alpha > 0.99:
            break
            
    return vec4(accumulated_color, accumulated_alpha)

def cart2sph(cart):
    # Cartesian to Spherical conversion using atan2 to avoid division by zero
    r = length(cart)
    phi = atan2(cart.y, cart.x)
    theta = atan2(length(cart.xy), cart.z)
    return vec3(r, theta, phi)
```

**Edge Cases and Pitfalls**
*   **Coordinate Mismatch:** The original source implementation computes spherical coordinates but samples the texture using the original Cartesian `dataPos`, ignoring the transformation for actual lookups [S1, unofficial][S2, unofficial]. This leads to incorrect visualization [S1, unofficial].
*   **Boundary Check Timing:** The original boundary check `dot(sign(dataPos-texMin),sign(texMax-dataPos)) < 3.0` is evaluated *after* advancing `dataPos` in the source code, meaning out-of-bounds texture fetches may occur before the break condition triggers [S1, unofficial].
*   **Division by Zero:** The original `cart2Sphe` function uses `atan(cart.y/cart.x)`, which divides by `cart.x` and results in infinity or NaN if `cart.x` is 0 [S2, unofficial].
*   **Spherical Distortion:** Storing spherical data in a cubic texture lattice causes significant distortion near the poles and center, which is not corrected by the standard ray marching loop [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is `MAX_SAMPLES` (typically 200–300) [S1, unofficial][S2, unofficial]. Early ray termination reduces the average number of samples per ray [S1, unofficial].
*   **Memory Complexity:** $O(D_r \cdot D_\theta \cdot D_\phi)$ for the 3D texture [S1, unofficial]. For the given dimensions $(384, 15, 768)$, `GL_R16F` mitigates VRAM usage [S1, unofficial].
*   **Strengths:** Single-pass execution allows for efficient rendering on modern GPUs [S1, unofficial][S2, unofficial]. Hardware-accelerated texture sampling avoids manual interpolation [S2, unofficial].
*   **Limitations:** The method is sensitive to the coordinate system mismatch between the spherical data layout and the cubic texture sampling [S1, unofficial][S2, unofficial]. Performance degrades with high `MAX_SAMPLES` or low early termination rates [S1, unofficial][S2, unofficial].
*   **When to Use:** Suitable for real-time visualization of spherical volume data (e.g., atmospheric models, spherical objects) where the distortion is acceptable or corrected [S2, unofficial]. Not suitable for general Cartesian volumes without modification [S2, unofficial].
