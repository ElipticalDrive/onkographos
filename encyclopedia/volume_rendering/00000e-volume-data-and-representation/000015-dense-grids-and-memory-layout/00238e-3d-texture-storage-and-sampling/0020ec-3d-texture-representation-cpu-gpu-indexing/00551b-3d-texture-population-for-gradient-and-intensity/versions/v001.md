# 3D Texture Population for Gradient and Intensity

Also called: CVolume::UpdateVolumeTexture, Gradient and Intensity Texture Population, Volume Texture Update, Voxel Gradient and Intensity Encoding

## Overview
This method encodes voxel intensity values and spatial gradients into a 3D RGBA texture to optimize GPU-based raycasting performance [S1, S2, unofficial]. By packing gradient vectors into the RGB channels and normalized intensity into the Alpha channel, it reduces memory bandwidth and allows the raycaster to sample both properties in a single texture fetch [S1, S2, unofficial]. It differs from raw intensity-only textures by providing explicit surface normal information for shading, and from separate gradient textures by co-locating data for cache efficiency [S1, S2, unofficial].

## How it works
**Inputs:**
- Raw voxel intensity array `m_pVoxelArray` of size $W \times H \times D$.
- Raw gradient array `m_pGradients` (optional), containing 3-component vectors per voxel.
- Resolution structure `res` with fields `x`, `y`, `z` (width, height, depth).
- Normalization parameters: `minInt`, `maxInt` (for linear), or histogram counters `accCounter` and `sum` (for equalized).
- Boolean flag `equalized`: if true, use histogram equalization; otherwise, use linear normalization [S1, unofficial].
- Data type size: `maxGra` is 255 for 8-bit (`UNSIGNED_CHAR`) or 65535 for 16-bit (`UNSIGNED_SHORT`) gradients [S1, unofficial].

**Outputs:**
- A 3D texture `tex3D` of size $W \times H \times D \times 4$ (RGBA), stored as a contiguous float array or platform-specific volume texture [S1, S2, unofficial].

**Data Structures:**
- `RawData_t`: Contains `intensity` array and `gradient` array.
- `Counter_t`: Contains `accCounter` array for histogram bins and `sum` total count [S1, unofficial].
- `RawInf_t`: Contains resolution `x`, `y`, `z` [S1, unofficial].

**Steps:**

1. **Iterate over all voxels** using indices $k$ (depth/z), $j$ (height/y), $i$ (width/x).
2. **Calculate linear index** in the output texture:
   $$ index = i + j \cdot res.x + k \cdot res.x \cdot res.y $$
   [S1, unofficial]
3. **Process Gradient Channels (R, G, B):**
   - If `m_pGradients` exists:
     - Retrieve gradient vector $\vec{v} = (v_x, v_y, v_z)$ at voxel $(i, j, k)$ [S2, unofficial].
     - Normalize components to $[0, 1]$ range:
       $$ R = \frac{v_x}{maxGra}, \quad G = \frac{v_y}{maxGra}, \quad B = \frac{v_z}{maxGra} $$
       [S1, unofficial]
     - Note: In the Direct3D implementation, these are cast to `BYTE` (8-bit) after scaling by 255 [S2, unofficial].
   - If `m_pGradients` does not exist:
     - Set $R = G = B = 0$ or replicate intensity depending on implementation variant. The source [S2, unofficial] sets them to the voxel value if gradients are missing, but [S1, unofficial] implies gradient channels are only populated when gradients exist. We follow [S1, unofficial] for the primary method: if no gradients, this step is skipped or channels are zeroed. However, [S2, unofficial] explicitly states: "If no gradients, stores RGBA where all channels equal the voxel value." This is a divergence. We note both.
       - Variant A (S1): Only populate RGB if gradients exist.
       - Variant B (S2): If no gradients, $R=G=B=A=$ normalized intensity.
4. **Process Intensity Channel (A):**
   - Let $I$ be the raw intensity value at the current voxel [S1, unofficial].
   - If `equalized` is true:
     - Calculate histogram-mapped value:
       $$ xpos = \frac{accCounter[I] \cdot 255.0}{sum} $$
       [S1, unofficial]
     - Normalize to $[0, 1]$:
       $$ A = \frac{xpos + 1.0}{257.0} $$
       [S1, unofficial]
   - If `equalized` is false:
     - Calculate linearly normalized value:
       $$ xpos = \frac{(I - minInt) \cdot 255.0}{maxInt - minInt} $$
       [S1, unofficial]
     - Normalize to $[0, 1]$:
       $$ A = \frac{xpos + 1.0}{257.0} $$
       [S1, unofficial]
     - Note: The formula uses `257.0` as the divisor, which maps the range $[0, 255]$ to approximately $[0, 0.996]$, avoiding exact 1.0 which might cause issues in some fixed-point or specific shader implementations [S1, unofficial].
5. **Store to Texture:**
   - For CPU-side array `tex3D`:
     $$ tex3D[index \cdot 4 + 0] = R $$
     $$ tex3D[index \cdot 4 + 1] = G $$
     $$ tex3D[index \cdot 4 + 2] = B $$
     $$ tex3D[index \cdot 4 + 3] = A $$
     [S1, unofficial]
   - For Direct3D 9 Volume Texture:
     - Lock the texture box with `D3DLOCK_DISCARD` [S2, unofficial].
     - Iterate $z$ from $0$ to $m\_iDepth$, $y$ from $0$ to $m\_iHeight$, $x$ from $0$ to $m\_iWidth$ [S2, unofficial].
     - Calculate memory offsets:
       $$ plane = lb.pBits + z \cdot lb.SlicePitch $$
       $$ scanline = plane + y \cdot lb.RowPitch $$
       [S2, unofficial]
     - Calculate voxel index in source arrays:
       $$ \_I(x, y, z) = z \cdot m\_iWidth \cdot m\_iHeight + y \cdot m\_iWidth + x $$
       [S2, unofficial]
     - If gradients exist:
       $$ \text{scanline}[x] = \text{D3DCOLOR\_ARGB}(m\_pVoxelArray[\_I], (BYTE)(v\_x \cdot 255), (BYTE)(v\_y \cdot 255), (BYTE)(v\_z \cdot 255)) $$
       [S2, unofficial]
     - If gradients do not exist:
       $$ \text{scanline}[x] = \text{D3DCOLOR\_ARGB}(m\_pVoxelArray[\_I], m\_pVoxelArray[\_I], m\_pVoxelArray[\_I], m\_pVoxelArray[\_I]) $$
       [S2, unofficial]
     - Unlock texture [S2, unofficial].

**Pseudocode:**

```python
def populate_volume_texture(voxel_array, gradient_array, resolution, equalized, min_int, max_int, acc_counter, sum_count, max_gra):
    """
    Populates a 3D RGBA texture with intensity and gradient data.
    
    Args:
        voxel_array: 1D array of raw intensity values, size W*H*D.
        gradient_array: 1D array of 3-component vectors (x,y,z), size W*H*D. Can be None.
        resolution: Tuple (W, H, D).
        equalized: Boolean, True for histogram equalization, False for linear.
        min_int: Minimum intensity for linear normalization.
        max_int: Maximum intensity for linear normalization.
        acc_counter: Histogram counter array.
        sum_count: Total sum for histogram normalization.
        max_gra: Max gradient value (255 for 8-bit, 65535 for 16-bit).
        
    Returns:
        tex3D: 1D float array of size W*H*D*4, layout [R, G, B, A] per voxel.
    """
    W, H, D = resolution
    tex3D = [0.0] * (W * H * D * 4)
    
    for k in range(D):
        for j in range(H):
            for i in range(W):
                # Linear index in the output texture
                index = i + j * W + k * W * H
                
                # 1. Gradient Channels (R, G, B)
                if gradient_array is not None:
                    grad_idx = index # Assuming gradient array is also linearized same way
                    gx = gradient_array[grad_idx * 3 + 0]
                    gy = gradient_array[grad_idx * 3 + 1]
                    gz = gradient_array[grad_idx * 3 + 2]
                    
                    # Normalize gradients to [0, 1]
                    # Note: Source [S1, unofficial] divides by max_gra. Source [S2, unofficial] casts to BYTE after *255.
                    # We follow [S1, unofficial] for float texture population.
                    tex3D[index * 4 + 0] = gx / max_gra
                    tex3D[index * 4 + 1] = gy / max_gra
                    tex3D[index * 4 + 2] = gz / max_gra
                else:
                    # If no gradients, some implementations set RGB to intensity, others to 0.
                    # Source [S2, unofficial] sets them to intensity. Source [S1, unofficial] implies they are only set if gradients exist.
                    # We set to 0.0 as a safe default for "no gradient" case in float texture,
                    # but note the divergence. [G] Setting to 0.0 to avoid mixing intensity into normal channels.
                    tex3D[index * 4 + 0] = 0.0
                    tex3D[index * 4 + 1] = 0.0
                    tex3D[index * 4 + 2] = 0.0
                
                # 2. Intensity Channel (A)
                intensity_val = voxel_array[index]
                
                if equalized:
                    # Histogram equalization
                    # Ensure intensity_val is within bounds of acc_counter
                    if 0 <= intensity_val < len(acc_counter):
                        xpos = (acc_counter[intensity_val] * 255.0) / sum_count
                    else:
                        xpos = 0.0
                    # Normalize to [0, 1] using the specific formula from [S1, unofficial]
                    tex3D[index * 4 + 3] = (xpos + 1.0) / 257.0
                else:
                    # Linear normalization
                    # Handle division by zero if max_int == min_int
                    if max_int != min_int:
                        xpos = ((intensity_val - min_int) * 255.0) / (max_int - min_int)
                    else:
                        xpos = 0.0
                    # Clamp xpos to [0, 255] to avoid out-of-range values before final normalization
                    xpos = max(0.0, min(255.0, xpos))
                    # Normalize to [0, 1] using the specific formula from [S1, unofficial]
                    tex3D[index * 4 + 3] = (xpos + 1.0) / 257.0

    return tex3D
```

**Edge Cases and Pitfalls:**
- **Gradient Data Type:** `maxGra` must match the bit-depth of the gradient data (255 for 8-bit, 65535 for 16-bit) [S1, unofficial]. Using the wrong value will scale gradients incorrectly.
- **Histogram Bounds:** If `equalized` is true, the intensity value $I$ must be a valid index into `accCounter`. If the intensity range is not contiguous or has gaps, ensure `accCounter` is sized appropriately [S1, unofficial].
- **Division by Zero:** In linear normalization, if `maxInt == minInt`, the denominator is zero. Guard against this [G].
- **Texture Locking:** When using Direct3D, `D3DLOCK_DISCARD` is used to allow the driver to optimize memory reuse. This requires careful handling of `SlicePitch` and `RowPitch` which may differ from the logical dimensions due to memory alignment [S2, unofficial].
- **Alpha Channel Precision:** The formula $(xpos + 1.0) / 257.0$ maps $[0, 255]$ to $[1/257, 256/257] \approx [0.0039, 0.9961]$. This avoids the value 1.0, which might be significant for certain blending or thresholding operations in the raycaster [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N = W \times H \times D$ is the number of voxels. Each voxel is processed once [S1, S2, unofficial].
- **Memory Complexity:** $O(N)$ for the output texture. The input arrays also require $O(N)$ memory [S1, S2, unofficial].
- **Performance:** Co-locating gradients and intensity in a single texture reduces the number of texture fetches during raycasting from two to one, improving cache utilization and reducing memory bandwidth pressure [S1, S2, unofficial].
- **Strengths:** Efficient for GPU raycasting; supports both linear and histogram-equalized intensity normalization; explicit gradient storage enables better shading [S1, S2, unofficial].
- **Limitations:** Requires pre-computation of gradients; histogram equalization requires an additional pass to compute the histogram [S1, unofficial]; Direct3D implementation requires handling of pitch/stride which can be complex [S2, unofficial].

## Background
This method is derived from implementations in scientific visualization and volume rendering libraries, specifically those using Direct3D and OpenGL for GPU-accelerated raycasting [S1, S2, unofficial]. The approach of packing gradients into RGB and intensity into Alpha is a common optimization in real-time volume rendering to minimize texture fetches [S1, S2, unofficial]. The specific normalization formula using 257.0 appears in the referenced GitHub repositories [S1, unofficial].
