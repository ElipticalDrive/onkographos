# PixelFlow Volume Rendering
Also called: PixelFlow Polygon Texturing, PixelFlow Volume Rendering Variant
## Overview
PixelFlow Volume Rendering is a polygon-based resampling method designed for the PixelFlow graphics system [S1, unofficial]. It solves the limitations of the RealityEngine by allowing pixel processors to manipulate texture values directly, enabling general lighting and scalable data sizes [S1, unofficial]. It differs from its siblings by performing trilinear interpolation and Phong shading in software on dedicated pixel processors rather than relying on hardware texture unit operations or precomputed shading coefficients [S1, unofficial].
## How it works
**Inputs:**
*   3D volume data $V(x, y, z)$ stored in texture memory.
*   Resampling polygons defining the view.
*   Light sources fixed in image space.

**Outputs:**
*   Composited frame buffer image.

**Data Structures:**
*   **Texture Memory:** 32-bit values treated as four 8-bit components: $(g_x, g_y, g_z, d)$, where $g$ represents the normalized data gradient and $d$ is the raw data value [S1, unofficial].
*   **Pixel Processor:** Each of the $128^2$ processors has an 8-bit ALU, hardware multiply, and hardware-assisted square root and divide instructions [S1, unofficial].

**Steps:**
1.  **Load:** Access eight arbitrarily-addressed 32-bit values from texture memory. This operation takes under 500 µs [S1, unofficial].
2.  **Interpolate:** Perform trilinear interpolation of all four 8-bit components ($g_x, g_y, g_z, d$) concurrently on all $128^2$ pixel processors [S1, unofficial].
3.  **Normalize:** Normalize the interpolated gradient vector $\mathbf{g} = (g_x, g_y, g_z)$ [S1, unofficial].
4.  **Shade:** Compute Phong shaded lighting coefficients using the normalized gradient and image-space light sources [S1, unofficial].
5.  **Classify:** Compute piecewise-linear transformations to translate the interpolated raw data value $d$ into color $C$ and opacity $\alpha$ [S1, unofficial].
6.  **Composite:** Multiply the color $C$ by the shading coefficient and composite the result into the frame buffer [S1, unofficial].

**Pseudocode:**
```python
# Executed concurrently on each of the 128^2 pixel processors
def process_pixel(polygon_id, texture_coords):
    # Step 1: Load 8 arbitrarily-addressed 32-bit values from texture memory
    # This is a hardware access taking < 500us
    texels = texture_memory.load_arbitrary(polygon_id, texture_coords)
    
    # Step 2: Treat 32-bit values as four 8-bit components
    # Components: [gx, gy, gz, d]
    # Perform trilinear interpolation of all four components
    gx, gy, gz, d = trilinear_interpolate(texels)
    
    # Step 3: Normalize the interpolated gradient
    gradient_magnitude = sqrt(gx*gx + gy*gy + gz*gz)
    if gradient_magnitude > 0:
        nx = gx / gradient_magnitude
        ny = gy / gradient_magnitude
        nz = gz / gradient_magnitude
    else:
        nx, ny, nz = 0, 0, 0
        
    # Step 4: Compute Phong shaded lighting coefficients
    # Light sources are fixed in image space
    shading_coeff = phong_shading(nx, ny, nz, light_sources)
    
    # Step 5: Compute piecewise-linear transformations for color and opacity
    color = piecewise_linear_color(d)
    opacity = piecewise_linear_opacity(d)
    
    # Step 6: Composite into frame buffer
    final_color = color * shading_coeff
    frame_buffer.composite(final_color, opacity)
```

**Parameters:**
*   **Pixel Processors:** $128^2$ processors per card [S1, unofficial].
*   **Memory per Card:** 0.5 million texture values [S1, unofficial].
*   **Access Time:** < 500 µs for 8 arbitrarily-addressed 32-bit values [S1, unofficial].

**Edge Cases:**
*   **Zero Gradient:** If the interpolated gradient magnitude is zero, the normal is set to $(0,0,0)$ to avoid division by zero [G].
*   **Boundary Handling:** Texture wrap modes are not explicitly detailed for PixelFlow, but standard practices for 3D textures apply to prevent sampling errors [S5, unofficial].

## Operating characteristics
*   **Performance:** Over 10 frames/second for a $256^3$ volume rendered into a 640x512 window using 400 object-space resampling polygons [S1, unofficial].
*   **Scalability:** Performance is inversely proportional to the number of screen pixels and resampling polygons used [S1, unofficial]. System scalability is achieved by adding processor cards, each with its own 0.5M texture value memory [S1, unofficial].
*   **Strengths:** Supports general lighting by sources fixed in image-space; overcomes RealityEngine limitations on data size [S1, unofficial].
*   **Limitations:** Requires specific PixelFlow hardware; software-based interpolation and shading on pixel processors [S1, unofficial].

## Background
PixelFlow Volume Rendering was proposed for the PixelFlow graphics system under development at the University of North Carolina at Chapel Hill [S1, unofficial]. It is described in the context of accelerating volume reconstruction with 3D texture hardware [S1, unofficial]. The method was presented as a variant of the polygon resampling approach, overcoming limitations of the RealityEngine [S1, unofficial].
