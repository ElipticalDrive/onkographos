# Volume Upload via Staging Buffer

Also called: GPU Memory Transfer via Staging, Staging Buffer Upload

## Overview
This method transfers dense 3D volume data from host memory to device-local GPU memory using an intermediate staging buffer. It solves the problem of moving large datasets to the GPU when direct host-to-device mapping is not supported or when the data must be prepared on the CPU before transfer. It differs from [Device Volume Snapshot](2246-device-volume-snapshot.md) by initiating the transfer from the host side rather than capturing existing device state, and from [GPU Data Layout](2469-gpu-data-layout.md) by explicitly managing the two-stage copy process (Host → Staging → Device) rather than defining the final memory layout alone.

## How it works
**Inputs:**
- `dims`: 3D dimensions $(n_x, n_y, n_z)$ of the volume.
- `field`: Host-side array of field data (e.g., `std::vector<float>` or `std::span<float>`).
- `kChannels`: Number of channels per voxel (e.g., 1 for scalar, 4 for RGBA).
- `kVolumeFormat`: GPU texture format (e.g., `R32F`, `RGBA32F`).

**Outputs:**
- A device-local 3D texture (image) ready for sampling.
- An image view for shader access.

**Data Structures:**
1.  **Device Image**:
    -   Type: `e3D`
    -   Format: `kVolumeFormat`
    -   Extent: $(n_x, n_y, n_z)$
    -   Mip Levels: 1
    -   Array Layers: 1
    -   Samples: `e1`
    -   Tiling: `eOptimal`
    -   Usage Flags: `eSampled` | `eTransferDst` | `eTransferSrc`
    -   Initial Layout: `eUndefined`
2.  **Staging Buffer**:
    -   Size: `byteSize` bytes.
    -   Usage: `eTransferSrc`
    -   Sharing Mode: `eExclusive`
    -   Memory Properties: Host-visible, Host-coherent.
3.  **Image View**:
    -   View Type: `e3D`
    -   Format: `kVolumeFormat`
    -   Subresource Range: Aspect `eColor`, Base Mip Level 0, Level Count 1, Base Array Layer 0, Layer Count 1.

**Steps:**
1.  **Validate Dimensions**: Check if $n_x$, $n_y$, or $n_z$ exceed the device's `maxImageDimension3D`. If any exceed, return error `Errc::unsupported_configuration` [S1, unofficial].
2.  **Calculate Size**: Compute the required byte size for the volume data:
    $$ \text{byteSize} = n_x \times n_y \times n_z \times kChannels \times \text{sizeof(float)} $$
3.  **Allocate Device Memory**: Allocate device-local memory for the 3D image and create the image resource with the layout defined above [S1, unofficial].
4.  **Allocate Staging Memory**: Allocate host-visible, host-coherent memory for the staging buffer with size `byteSize` [S1, unofficial].
5.  **Populate Staging Buffer**:
    -   Map the staging memory.
    -   Create a `std::span<float>` of size $n_x \times n_y \times n_z \times kChannels$.
    -   Call `deriveField<T>` to copy/populate the span with the input `field` data. This function returns `autoRange` (the data range) [S1, unofficial].
    -   Unmap the staging memory.
6.  **Copy to Device**: Record a command buffer that copies the staging buffer to the device image. The image layout transitions from `eUndefined` to `eTransferDst` during the copy, and then to `eShaderReadOnlyOptimal` (or similar sampled layout) for rendering [S1, unofficial].
7.  **Create Image View**: Create the 3D image view for shader binding [S1, unofficial].

**Pitfalls:**
-   **Destruction Order**: Memory and resources must be destroyed in reverse order of creation to avoid freeing memory bound to destroyed objects. The correct order is: `imageMem`, `image`, `view`, `stagingMem`, `staging` [S1, unofficial].
-   **Precision**: Ensure `kVolumeFormat` matches the host data type precision (e.g., `R32F` for `float`) to prevent corruption [S1, unofficial].

**Pseudocode:**
```python
def upload_volume_via_staging(field: List[float], dims: Dims3D, k_channels: int, 
                              device: Device, allocator: Allocator) -> VolumeTexture:
    # 1. Validate dimensions
    if dims.nx > device.max_image_dimension_3d or \
       dims.ny > device.max_image_dimension_3d or \
       dims.nz > device.max_image_dimension_3d:
        raise Error(Errc.unsupported_configuration, "Volume dimensions exceed device limits")

    # 2. Calculate size
    byte_size = dims.count() * k_channels * sizeof(float)

    # 3. Allocate device image
    image_info = ImageCreateInfo(
        type=ImageType.e3D,
        format=k_volume_format,
        extent=dims,
        mip_levels=1,
        array_layers=1,
        samples=SampleCount.e1,
        tiling=Tiling.eOptimal,
        usage=UsageFlagBits.eSampled | UsageFlagBits.eTransferDst | UsageFlagBits.eTransferSrc,
        initial_layout=Layout.eUndefined
    )
    image = device.create_image(image_info)
    image_mem = allocator.allocate_device_memory(image)
    image.bind_memory(image_mem, 0)

    # 4. Allocate staging buffer
    staging_info = BufferCreateInfo(
        size=byte_size,
        usage=UsageFlagBits.eTransferSrc,
        sharing_mode=SharingMode.eExclusive
    )
    staging = device.create_buffer(staging_info)
    staging_mem = allocator.allocate_host_visible_coherent_memory(staging)
    staging.bind_memory(staging_mem, 0)

    # 5. Populate staging buffer
    staging_data = staging_mem.map()
    # deriveField populates the span with field data and returns autoRange
    span = std_span_float(staging_data, dims.count() * k_channels)
    auto_range = derive_field(span, field)
    staging_mem.unmap()

    # 6. Copy to device
    command_buffer = device.begin_command_buffer()
    command_buffer.copy_buffer_to_image(staging, image, Layout.eTransferDst)
    command_buffer.pipeline_barrier(
        src_stage=PipelineStage.eTransfer,
        dst_stage=PipelineStage.eFragmentShader,
        image=image,
        old_layout=Layout.eTransferDst,
        new_layout=Layout.eShaderReadOnlyOptimal,
        src_access_mask=AccessFlagBits.eTransferWrite,
        dst_access_mask=AccessFlagBits.eShaderRead
    )
    command_buffer.end()
    device.submit_and_wait(command_buffer)

    # 7. Create image view
    view_info = ImageViewCreateInfo(
        image=image,
        view_type=ImageViewType.e3D,
        format=k_volume_format,
        subresource_range=SubresourceRange(
            aspect=ImageAspectFlagBits.eColor,
            base_mip_level=0,
            level_count=1,
            base_array_layer=0,
            layer_count=1
        )
    )
    view = device.create_image_view(view_info)

    return VolumeTexture(image=image, view=view, auto_range=auto_range)
```

## Subtopics

### Volume Readback via Staging Buffer
This variant transfers data from the device to the host. It allocates a host-visible, host-coherent staging buffer with usage `eTransferDst`. It copies `byteSize` bytes from the device image to the staging buffer, maps the staging memory into a `std::vector<float>`, unmaps it, and returns the data along with dimensions. The formula for `byteSize` is identical to upload: $n_x \times n_y \times n_z \times kChannels \times \text{sizeof(float)}$ [S1, unofficial].

## Operating characteristics
-   **Time Complexity**: $O(N)$ where $N$ is the number of voxels, dominated by the memory copy bandwidth.
-   **Memory Complexity**: $O(N)$ for the staging buffer in addition to the device texture.
-   **Performance**: Depends on PCIe bandwidth and staging buffer size. For large volumes, this is the standard method for initial upload.
-   **Strengths**: Works on all GPUs, including those without unified memory or host-coherent device memory.
-   **Limitations**: Requires extra memory for staging; not suitable for per-frame updates of large volumes due to copy overhead.

## Background
This method is a standard technique in graphics APIs like Vulkan and OpenGL for transferring large datasets to the GPU. It is implemented in the `imaginaryVolumes` library [S1, unofficial].
