# Volume Upload via Staging Buffer

Also called: GPU Memory Transfer via Staging, Staging Buffer Upload

## Overview
This method transfers dense volumetric field data from host memory to GPU device-local memory using an intermediate staging buffer. It solves the problem of populating a 3D texture with data that resides on the CPU, ensuring memory coherence and allowing the GPU to optimize access patterns for sampling. It is distinguished from direct mapping methods by explicitly decoupling the host-side data population phase from the GPU residency phase, which is necessary when the source data is not already in a host-visible, coherent memory region or when asynchronous transfer is required [S1, unofficial].

## How it works
**Inputs:**
- `dims`: A structure containing volume dimensions `nx`, `ny`, `nz`.
- `field`: A pointer or span to the source volumetric data (e.g., `std::span<const float>`).
- `kChannels`: The number of channels per voxel (e.g., 1 for scalar, 3 for RGB).
- `kVolumeFormat`: The GPU texture format (e.g., `R32F`, `RGBA32F`).

**Outputs:**
- A GPU 3D image resource handle.
- A GPU image view handle.

**Data Structures:**
1.  **Volume Dimensions (`dims`)**:
    -   `nx`: Width (uint32)
    -   `ny`: Height (uint32)
    -   `nz`: Depth (uint32)
    -   `count()`: Returns `nx * ny * nz` [S1, unofficial].
2.  **Staging Buffer**:
    -   Type: Buffer or linear memory block.
    -   Usage Flags: `TRANSFER_SRC` [S1, unofficial].
    -   Memory Properties: Host-visible, Host-coherent [S1, unofficial].
3.  **3D Image**:
    -   Type: `e3D` [S1, unofficial].
    -   Format: `kVolumeFormat` [S1, unofficial].
    -   Extent: `(dims.nx, dims.ny, dims.nz)` [S1, unofficial].
    -   Mip Levels: 1 [S1, unofficial].
    -   Array Layers: 1 [S1, unofficial].
    -   Samples: `e1` (non-multisampled) [S1, unofficial].
    -   Tiling: `eOptimal` [S1, unofficial].
    -   Usage Flags: `SAMPLED` | `TRANSFER_DST` | `TRANSFER_SRC` [S1, unofficial].
    -   Initial Layout: `eUndefined` [S1, unofficial].
4.  **Image View**:
    -   View Type: `e3D` [S1, unofficial].
    -   Format: `kVolumeFormat` [S1, unofficial].
    -   Subresource Range: Aspect `eColor`, Base Mip Level 0, Level Count 1, Base Array Layer 0, Layer Count 1 [S1, unofficial].

**Steps:**
1.  **Validation**: Check if `dims.nx`, `dims.ny`, or `dims.nz` exceed the device's `maxImageDimension3D` limit. If any dimension exceeds the limit, return error `Errc::unsupported_configuration` [S1, unofficial].
2.  **Calculate Size**: Compute the byte size of the volume data:
    $$ \text{byteSize} = \text{dims.count()} \times \text{kChannels} \times \text{sizeof(float)} $$
    [S1, unofficial].
3.  **Allocate Staging Buffer**: Allocate host-visible, host-coherent memory for the staging buffer with size `byteSize` and usage `eTransferSrc` [S1, unofficial].
4.  **Populate Staging Data**:
    -   Map the staging memory.
    -   Create a writable span of floats of size `dims.count() * kChannels`.
    -   Populate this span with the field data. The source code references a helper `deriveField<T>` which transforms the input field into the staging layout and returns an `autoRange` [S1, unofficial].
    -   Unmap the staging memory.
5.  **Allocate Device Memory**: Allocate device-local memory for the 3D image [S1, unofficial].
6.  **Create Image**: Create the 3D image resource with the parameters defined in the Data Structures section [S1, unofficial].
7.  **Transfer Data**:
    -   Record a command buffer command to copy the data from the staging buffer (`eTransferSrc`) to the 3D image (`eTransferDst`).
    -   The copy operation transfers `byteSize` bytes.
    -   Submit and wait for the command buffer to complete to ensure data coherence before the image is used for sampling [S1, unofficial].
8.  **Create Image View**: Create the 3D image view to allow the GPU shader to sample the texture [S1, unofficial].
9.  **Cleanup Staging**: Destroy the staging buffer and its associated memory to free host-visible resources [S1, unofficial].

**Pitfalls:**
-   **Destruction Order**: Memory and resources must be destroyed in reverse order of creation to avoid freeing memory bound to destroyed objects. The correct order is: image memory, image, image view, staging memory, staging buffer [S1, unofficial].
-   **Precision**: Ensure `sizeof(float)` matches the data type used in `kVolumeFormat`. Mismatches will cause corruption or alignment errors.
-   **Boundaries**: If `dims.count() * kChannels` is large, ensure the staging buffer allocation does not fail due to host memory limits.

**Pseudocode:**
```python
def upload_volume_to_gpu(field: Span[float], dims: Dims, k_channels: int, k_volume_format: Format):
    # 1. Validation
    if dims.nx > max_image_dimension_3d or dims.ny > max_image_dimension_3d or dims.nz > max_image_dimension_3d:
        raise Error(Errc::unsupported_configuration, "Volume dimensions exceed device limits")

    # 2. Calculate Size
    byte_size = (dims.nx * dims.ny * dims.nz) * k_channels * sizeof(float)

    # 3. Allocate Staging Buffer
    staging_buffer = allocate_buffer(size=byte_size, usage=Usage::TRANSFER_SRC)
    staging_memory = allocate_memory(buffer=staging_buffer, properties=MemoryProperty::HOST_VISIBLE | MemoryProperty::HOST_COHERENT)
    bind_memory(staging_buffer, staging_memory)

    # 4. Populate Staging Data
    staging_ptr = map_memory(staging_memory)
    staging_span = Span[float](staging_ptr, dims.nx * dims.ny * dims.nz * k_channels)
    
    # deriveField populates staging_span from field and returns auto_range
    auto_range = derive_field(staging_span, field)
    
    unmap_memory(staging_memory)

    # 5. Allocate Device Memory
    device_memory = allocate_memory(size=byte_size, properties=MemoryProperty::DEVICE_LOCAL)

    # 6. Create Image
    image = create_image(
        type=ImageType::e3D,
        format=k_volume_format,
        extent=(dims.nx, dims.ny, dims.nz),
        mip_levels=1,
        array_layers=1,
        samples=SampleCount::e1,
        tiling=Tiling::eOptimal,
        usage=Usage::SAMPLED | Usage::TRANSFER_DST | Usage::TRANSFER_SRC,
        initial_layout=Layout::eUndefined
    )
    bind_memory(image, device_memory)

    # 7. Transfer Data
    command_buffer = begin_command_buffer()
    copy_buffer_to_image(
        command_buffer,
        src_buffer=staging_buffer,
        dst_image=image,
        dst_layout=Layout::eTransferDstOptimal,
        regions=[BufferImageCopy(
            buffer_offset=0,
            buffer_row_length=0,
            buffer_image_height=0,
            image_subresource=ImageSubresourceLayers(
                aspect_mask=Aspect::eColor,
                mip_level=0,
                base_array_layer=0,
                layer_count=1
            ),
            image_offset=(0, 0, 0),
            image_extent=(dims.nx, dims.ny, dims.nz)
        )]
    )
    end_command_buffer(command_buffer)
    submit_and_wait(command_buffer)

    # Transition image to SHADER_READ_ONLY_OPTIMAL for sampling (implied by usage flags and typical Vulkan workflow)
    transition_image_layout(command_buffer, image, Layout::eTransferDstOptimal, Layout::eShaderReadOnlyOptimal)
    submit_and_wait(command_buffer)

    # 8. Create Image View
    image_view = create_image_view(
        image=image,
        view_type=ImageViewType::e3D,
        format=k_volume_format,
        subresource_range=ImageSubresourceRange(
            aspect_mask=Aspect::eColor,
            base_mip_level=0,
            level_count=1,
            base_array_layer=0,
            layer_count=1
        )
    )

    # 9. Cleanup Staging
    destroy_buffer(staging_buffer)
    free_memory(staging_memory)

    return image, image_view
```

## Subtopics

### Volume Readback via Staging Buffer
This variant transfers data from the GPU back to the host. It allocates a host-visible, host-coherent staging buffer with usage `eTransferDst` [S1, unofficial]. It copies `byteSize` bytes from the 3D image to the staging buffer, maps the staging memory, copies the data into a host-side `std::vector<float>`, and unmaps the memory [S1, unofficial]. The `byteSize` formula is identical to the upload method: `dims.count() * kChannels * sizeof(float)` [S1, unofficial].

## Operating characteristics
-   **Time Complexity**: $O(N)$ where $N$ is the number of voxels, dominated by the memory copy operation.
-   **Memory Complexity**: $O(N)$ for the staging buffer, which doubles the peak memory usage during upload (host staging + device storage).
-   **Performance**: The staging buffer approach is generally slower than direct mapping for small datasets due to the extra copy step, but it is necessary for large datasets or when the source data is not already in host-coherent memory. It allows for asynchronous transfers if the API supports it (e.g., Vulkan queues).
-   **Strengths**: Decouples host population from GPU residency; works with non-coherent host memory; standard pattern for bulk data upload.
-   **Limitations**: Requires additional host memory for the staging buffer; involves at least two memory copies (host to staging, staging to device).
-   **When to use**: When uploading large volumes, when the source data is not in host-visible memory, or when asynchronous transfer is required.
-   **When not to use**: For very small volumes where the overhead of buffer allocation and command submission outweighs the benefits; if direct mapping is supported and sufficient.

## Background
This method is a standard technique in GPU programming, particularly in Vulkan and OpenGL, for transferring large datasets to the GPU. It is based on the principle of using staging buffers to bridge the gap between host memory and device-local memory, ensuring optimal performance for GPU access patterns [S1, unofficial]. The specific implementation details are derived from the `imaginaryVolumes` project [S1, unofficial].
