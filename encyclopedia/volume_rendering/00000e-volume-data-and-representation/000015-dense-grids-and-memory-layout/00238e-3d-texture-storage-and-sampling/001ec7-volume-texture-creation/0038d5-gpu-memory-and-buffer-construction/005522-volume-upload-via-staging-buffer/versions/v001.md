# Volume Upload via Staging Buffer

Also called: GPU Memory Transfer via Staging, Staging Buffer Upload

## Overview
This method transfers dense volumetric scalar data from host memory to GPU device-local memory by using an intermediate host-visible, host-coherent staging buffer. It solves the problem of moving large 3D datasets to the GPU when direct mapping is not supported or when explicit asynchronous transfer control is required. It differs from direct mapping [G] by decoupling data population from GPU residency, and from pinned memory transfers [G] by using standard coherent host memory which simplifies allocation but may incur higher bandwidth costs.

## How it works
**Inputs:** Host-side volumetric field data (e.g., `std::span<const float>`), volume dimensions (`dims.nx`, `dims.ny`, `dims.nz`), and number of channels (`kChannels`, typically 1 for scalar, 4 for RGBA).
**Outputs:** A GPU-resident 3D texture (image) ready for sampling in shaders.

**Data Structures:**
1.  **Volume Dimensions:** Struct containing `nx`, `ny`, `nz` (unsigned integers).
2.  **Staging Buffer:** A device-independent memory object allocated with `VK_MEMORY_PROPERTY_HOST_VISIBLE_BIT | VK_MEMORY_PROPERTY_HOST_COHERENT_BIT`.
3.  **3D Image:** A Vulkan image object with `VK_IMAGE_TYPE_3D`, `VK_IMAGE_TILING_OPTIMAL`, and usage flags `VK_IMAGE_USAGE_SAMPLED_BIT | VK_IMAGE_USAGE_TRANSFER_DST_BIT | VK_IMAGE_USAGE_TRANSFER_SRC_BIT`.
4.  **Image View:** A handle to the 3D image for shader access.

**Steps:**
1.  **Validation:** Check if `dims.nx`, `dims.ny`, or `dims.nz` exceed `limits.maxImageDimension3D`. If so, return error `Errc::unsupported_configuration` [S1, unofficial].
2.  **Calculate Size:** Compute the byte size of the volume data:
    $$ \text{byteSize} = \text{dims.count()} \times \text{kChannels} \times \text{sizeof(float)} $$
    where $\text{dims.count()} = \text{dims.nx} \times \text{dims.ny} \times \text{dims.nz}$ [S1, unofficial].
3.  **Allocate Staging Buffer:** Allocate device-local memory for the 3D image (conceptually, the final destination) and host-visible, host-coherent memory for the staging buffer of size `byteSize` [S1, unofficial].
4.  **Populate Staging Buffer:** Map the staging memory. Create a `std::span<float>` of size `dims.count() * kChannels`. Call `deriveField<T>` (or equivalent data population routine) to copy the host field data into this span. This step may also compute the `autoRange` of the data [S1, unofficial].
5.  **Unmap Staging Buffer:** Unmap the staging memory to ensure data is visible to the GPU.
6.  **Create 3D Image:** Create the 3D image with:
    *   Type: `VK_IMAGE_TYPE_3D`
    *   Format: `kVolumeFormat` (e.g., `VK_FORMAT_R32G8B8A8_UNORM` or `VK_FORMAT_R32_SFLOAT`)
    *   Extent: `(dims.nx, dims.ny, dims.nz)`
    *   Mip Levels: 1
    *   Array Layers: 1
    *   Samples: `VK_SAMPLE_COUNT_1_BIT`
    *   Tiling: `VK_IMAGE_TILING_OPTIMAL`
    *   Usage: `VK_IMAGE_USAGE_SAMPLED_BIT | VK_IMAGE_USAGE_TRANSFER_DST_BIT | VK_IMAGE_USAGE_TRANSFER_SRC_BIT`
    *   Initial Layout: `VK_IMAGE_LAYOUT_UNDEFINED` [S1, unofficial].
7.  **Create Image View:** Create a 3D image view with:
    *   View Type: `VK_IMAGE_VIEW_TYPE_3D`
    *   Format: `kVolumeFormat`
    *   Subresource Range: Aspect `VK_IMAGE_ASPECT_COLOR`, Base Mip Level 0, Level Count 1, Base Array Layer 0, Layer Count 1 [S1, unofficial].
8.  **Record Transfer Command:** Record a command buffer that:
    *   Transitions the 3D image layout from `VK_IMAGE_LAYOUT_UNDEFINED` to `VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL`.
    *   Executes a `vkCmdCopyBufferToImage` command, copying `byteSize` bytes from the staging buffer to the 3D image. The image layout for the copy is `VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL`.
    *   Transitions the 3D image layout from `VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL` to `VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL`.
9.  **Submit and Wait:** Submit the command buffer to the graphics queue and wait for completion (or use a fence) to ensure the data is fully uploaded before the image is sampled.
10. **Cleanup:** Destroy the staging buffer and its associated memory. The 3D image and image view remain valid [S1, unofficial].

**Pitfalls:**
*   **Memory Destruction Order:** Memory must be destroyed in reverse order of binding to avoid freeing memory bound to destroyed objects. Specifically, destroy `imageMem`, then `image`, then `view`, then `stagingMem`, then `staging` [S1, unofficial].
*   **Precision:** Ensure `kChannels` and `sizeof(float)` match the shader's expectation. Mismatches cause corruption or undefined behavior.
*   **Boundaries:** If dimensions are zero or negative, the upload will fail or produce undefined results. Validate dimensions before allocation.

**Pseudocode:**
```python
def upload_volume_to_gpu(field_data: list[float], dims: Dimensions, k_channels: int, device: VulkanDevice):
    """
    Uploads volumetric data to GPU via staging buffer.
    """
    # 1. Validation
    if dims.nx > device.limits.max_image_dimension_3d or \
       dims.ny > device.limits.max_image_dimension_3d or \
       dims.nz > device.limits.max_image_dimension_3d:
        raise Error(Errc::unsupported_configuration)

    # 2. Calculate Size
    num_voxels = dims.nx * dims.ny * dims.nz
    byte_size = num_voxels * k_channels * 4  # sizeof(float) = 4

    # 3. Allocate Staging Buffer
    staging_buffer = device.allocate_buffer(byte_size, VK_BUFFER_USAGE_TRANSFER_SRC_BIT)
    staging_memory = device.allocate_memory(
        staging_buffer, 
        VK_MEMORY_PROPERTY_HOST_VISIBLE_BIT | VK_MEMORY_PROPERTY_HOST_COHERENT_BIT
    )
    device.bind_buffer_memory(staging_buffer, staging_memory)

    # 4. Populate Staging Buffer
    mapped_data = device.map_memory(staging_memory, 0, byte_size)
    # Assuming field_data is a flat list of floats
    # In C++, this would be a std::span<float>
    staging_span = mapped_data.as_span_of_floats(byte_size / 4)
    
    # deriveField<T> populates the span with field data
    # and returns autoRange. Here we simulate the copy.
    for i in range(len(field_data)):
        staging_span[i] = field_data[i]
        
    device.unmap_memory(staging_memory)

    # 5. Create 3D Image
    image_create_info = ImageCreateInfo(
        image_type=VK_IMAGE_TYPE_3D,
        format=k_volume_format,
        extent=Extent3D(dims.nx, dims.ny, dims.nz),
        mip_levels=1,
        array_layers=1,
        samples=VK_SAMPLE_COUNT_1_BIT,
        tiling=VK_IMAGE_TILING_OPTIMAL,
        usage=VK_IMAGE_USAGE_SAMPLED_BIT | VK_IMAGE_USAGE_TRANSFER_DST_BIT | VK_IMAGE_USAGE_TRANSFER_SRC_BIT,
        initial_layout=VK_IMAGE_LAYOUT_UNDEFINED
    )
    volume_image = device.create_image(image_create_info)
    image_memory = device.allocate_memory(volume_image, VK_MEMORY_PROPERTY_DEVICE_LOCAL_BIT)
    device.bind_image_memory(volume_image, image_memory)

    # 6. Create Image View
    view_create_info = ImageViewCreateInfo(
        image=volume_image,
        view_type=VK_IMAGE_VIEW_TYPE_3D,
        format=k_volume_format,
        subresource_range=SubresourceRange(
            aspect_mask=VK_IMAGE_ASPECT_COLOR,
            base_mip_level=0,
            level_count=1,
            base_array_layer=0,
            layer_count=1
        )
    )
    volume_image_view = device.create_image_view(view_create_info)

    # 7. Record Transfer Command
    command_buffer = device.begin_command_buffer()
    
    # Transition to transfer destination
    transition_image_layout(command_buffer, volume_image, VK_IMAGE_LAYOUT_UNDEFINED, VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL)
    
    # Copy buffer to image
    buffer_copy_region = BufferImageCopy(
        buffer_offset=0,
        buffer_row_length=0,
        buffer_image_height=0,
        image_subresource=ImageSubresourceLayers(
            aspect_mask=VK_IMAGE_ASPECT_COLOR,
            mip_level=0,
            base_array_layer=0,
            layer_count=1
        ),
        image_offset=Offset3D(0, 0, 0),
        image_extent=Extent3D(dims.nx, dims.ny, dims.nz)
    )
    command_buffer.copy_buffer_to_image(staging_buffer, volume_image, VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL, [buffer_copy_region])
    
    # Transition to shader read-only
    transition_image_layout(command_buffer, volume_image, VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL, VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL)
    
    device.end_command_buffer()
    device.submit_and_wait(command_buffer)

    # 8. Cleanup Staging
    device.destroy_buffer(staging_buffer)
    device.free_memory(staging_memory)

    return volume_image_view, volume_image, image_memory
```

## Subtopics

### Volume Readback via Staging Buffer
This variant transfers data from GPU device-local memory back to host memory. It allocates a host-visible, host-coherent staging buffer with `VK_BUFFER_USAGE_TRANSFER_DST_BIT`. A command buffer copies the 3D image to the staging buffer (`vkCmdCopyImageToBuffer`), then the host maps the staging buffer to read the data into a `std::vector<float>`. The byte size is calculated identically: `byteSize = dims.count() * kChannels * sizeof(float)` [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, dominated by the memory copy bandwidth.
*   **Memory Complexity:** $O(N)$ for the staging buffer, in addition to the device-local image memory.
*   **Performance:** Depends on PCIe bandwidth. For large volumes, this can be a bottleneck. Asynchronous transfers (using separate queues) can hide latency.
*   **Strengths:** Works with any GPU that supports Vulkan/OpenGL, no special pinned memory requirements, simple to implement.
*   **Limitations:** Requires extra memory (staging buffer), slower than direct mapping if supported, synchronous by default unless async queues are used.
*   **When to use:** When direct mapping is not available, or when explicit control over the transfer pipeline is needed.
*   **When not to use:** When memory is extremely constrained, or when real-time updates of small volumes are needed and direct mapping is supported.

## Background
This method is a standard technique in Vulkan and OpenGL applications for transferring large datasets to the GPU. It is widely used in scientific visualization and medical imaging applications where volumetric data is loaded from disk. The specific implementation details described here are derived from the `imaginaryVolumes` project [S1, unofficial].
