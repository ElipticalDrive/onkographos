# Device Volume Snapshot

Also called: DeviceVolume, VXL-042 Storage, Volume Immutable Storage, toDevice

## Overview
The Device Volume Snapshot creates a compact, immutable snapshot of volume metadata and GPU texture handles, optimized for passing to CUDA kernels [S1][S2, unofficial]. It differs from mutable buffer constructions by enforcing immutability once built, ensuring thread-safe sharing of internal resources across multiple snapshots [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A `Volume::Builder` containing cells (defined by value) and metadata.
*   **Output:** A `DeviceVolume` struct (or `DeviceScene` containing it) ready for device-side access.

**Data Structures:**
The core data structure is `DeviceVolume` (or embedded in `DeviceScene`). It contains:
*   `field_tex`: `cudaTextureObject_t` for the primary volume data.
*   `grad_tex`: `cudaTextureObject_t` for gradients (can be `0` if unused) [S2, unofficial].
*   `dim`: `int3` representing the voxel grid dimensions [S2, unofficial].
*   `voxel_size`: `float3` representing the physical size of a single voxel [S2, unofficial].
*   `origin`: `float3` representing the world-space origin of the volume [S2, unofficial].
*   `value_range`: `float2` representing the min/max scalar values in the volume [S2, unofficial].
*   `density_scale`: `float` for density adjustment [S2, unofficial].

**Steps:**
1.  **Builder Construction:** The `Volume::Builder` accepts `Cell` objects by value. It maintains a local table of unique `Definition` objects (sharing underlying `Data`) and a compact grid of cells that index this table, storing necessary orientation information [S1].
2.  **Immutability Enforcement:** The `Builder` produces a new `Volume` snapshot via `build()`. The resulting `Volume` is immutable; old volumes are never modified [S1].
3.  **Device Initialization:** Initialize the `DeviceVolume` struct (or `DeviceScene`) by extracting values from the `Volume::Description` and binding the GPU texture handles (`field_tex`, `grad_tex`) [S2, unofficial].
4.  **Commit:** Call `commit(cudaStream_t stream)` to finalize the snapshot and ensure data consistency on the device [S2, unofficial].

**Pitfalls:**
*   **Dangling Pointers:** The public API must not expose `std::span<const Cell>` or raw pointers/indices to the internal compact storage. Internal grid changes or memory reorganization can invalidate such references. Instead, use `cell(position)` which returns values or views reconstructed from the internal table [S1].
*   **Precision:** Ensure host-side data types are mapped to GPU-compatible texture formats (e.g., `R32F`) to prevent precision loss, adhering to the parent family's format mapping principles [S1].

**Pseudocode:**
```python
# Conceptual implementation of the snapshot creation process

class VolumeBuilder:
    def __init__(self, dim: int3):
        self.dim = dim
        self.definitions = {}  # Map: Definition -> Index
        self.grid = {}         # Map: (x,y,z) -> (def_index, orientation)

    def set_cell(self, pos: int3, cell: Cell):
        # Deduplicate definitions
        if cell.definition not in self.definitions:
            self.definitions[cell.definition] = len(self.definitions)
        
        def_idx = self.definitions[cell.definition]
        self.grid[pos] = (def_idx, cell.orientation)

    def build(self) -> Volume:
        # Create immutable Volume from builder state
        return Volume(self.dim, self.definitions, self.grid)

class Volume:
    def __init__(self, dim: int3, definitions: dict, grid: dict):
        self.dim = dim
        self.definitions = definitions
        self.grid = grid
        self.texture_handle = None # Bound later

    def cell(self, pos: int3) -> Cell:
        # Reconstruct cell by value; do not expose internal indices
        if pos in self.grid:
            def_idx, orientation = self.grid[pos]
            def_obj = list(self.definitions.keys())[def_idx]
            return Cell(def_obj, orientation)
        return Cell.empty()

class DeviceVolume:
    def __init__(self, volume: Volume, field_tex: cudaTextureObject_t, grad_tex: cudaTextureObject_t = 0):
        self.field_tex = field_tex
        self.grad_tex = grad_tex
        self.dim = volume.dim
        self.voxel_size = volume.get_voxel_size() # [G] Assumed method
        self.origin = volume.get_origin()         # [G] Assumed method
        self.value_range = volume.get_value_range() # [G] Assumed method
        self.density_scale = 1.0                  # [G] Default value

def create_snapshot(volume: Volume, stream: cudaStream_t) -> DeviceVolume:
    # 1. Bind textures to volume data (handled by parent GPU Memory methods)
    field_tex = bind_texture(volume.data, volume.dim)
    
    # 2. Initialize DeviceVolume struct
    snapshot = DeviceVolume(volume, field_tex)
    
    # 3. Commit to device memory
    commit_to_device(snapshot, stream)
    
    return snapshot
```

## Operating characteristics
*   **Memory:** Immutable storage allows lightweight copying via shared internal resources (reference counting or pointer sharing) [S1].
*   **Performance:** Access is optimized for read-only kernel execution. Gradient textures are optional, saving memory if not needed [S2, unofficial].
*   **Limitations:** Cannot be modified after creation. Updates require building a new snapshot [S1].

## Background
This method is part of the Sparkle Voxel engine design (VXL-042) and is implemented in CUDA-accelerated volume rendering engines like cuVRender [S1][S2, unofficial]. It addresses the need for efficient, thread-safe volume data transfer from host to device in modern GPU rendering pipelines.
