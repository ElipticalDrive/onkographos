# 2D Texture-Based Volume Rendering with Z-Slice Packing

Also called: 2D Texture Z-Slice Packing, Z-Slice Packing

## Overview
This method renders a 3D scalar field by storing its Z-slices in a tiled 2D texture grid, allowing 3D sampling via 2D texture lookups and trilinear interpolation [S1, unofficial]. It differs from standard 3D texture sampling by mapping 3D coordinates to a 2D atlas, requiring explicit slice indexing and offset calculation in the shader [S1, unofficial]. It builds on [Tiled 2D Texture Storage for 3D Fields](2740-tiled-2d-texture-storage-for-3d-fields.md).

## How it works
**Inputs and Outputs:**
- Input: A 3D volume of $N_z$ slices (typically 256), stored in a 2D texture of size $W \times H$.
- Input: Camera matrices (projection, model-view) and ray marching parameters.
- Output: Final color and opacity per fragment.

**Data Structures:**
- `cubeTex`: A 2D texture containing the volume data. For 256 slices arranged in a $16 \times 16$ grid within a $256 \times 256$ texture, each slice occupies a $16 \times 16$ pixel region [S1, unofficial].
- `transferTex`: A 1D or 2D texture mapping opacity (alpha) to RGB color [S1, unofficial].
- `rtTexture`: A render target texture storing world-space coordinates of the ray entry point (back face) [S1, unofficial].

**Numbered Steps:**

1. **First Pass (Back Face):** Render the back face of the volume bounding box. The fragment shader outputs the world-space coordinates of the fragment. This texture (`rtTexture`) is sampled later to determine the ray's end point [S1, unofficial].
2. **Second Pass (Front Face & Ray Marching):**
   a. **Ray Initialization:** For each fragment, determine the ray origin (front face) and direction. The back position is retrieved from `rtTexture` using `NearestFilter` to avoid interpolation artifacts at edges [S1, unofficial]. If the back position is invalid (e.g., $(0,0,0)$), discard the fragment [S1, unofficial].
   b. **Step Calculation:** Calculate the step size. The maximum distance through the volume is $\sqrt{3}$ (normalized cube diagonal). The step size in world units is derived from the total ray length and the number of steps [S1, unofficial].
   c. **Loop:** Iterate through the ray steps.
   d. **Texture Coordinate Mapping:** For the current ray position, calculate the 3D texture coordinates $(u, v, w)$.
   e. **Slice Indexing:** Determine the integer Z-slice index and the next slice index for interpolation:
      $$ z_1 = \lfloor w \cdot 255.0 \rfloor $$
      $$ z_2 = \min(z_1 + 1.0, 255.0) $$
      [S1, unofficial]
   f. **Z-Interpolation Factor:**
      $$ z_{diff} = \text{mod}(w \cdot 255.0, 1.0) $$
      [S1, unofficial]
   g. **2D Coordinate Offset:** Map the 3D coordinates to the 2D texture atlas. Divide the base UV by the grid size (16.0) and add offsets based on the slice index:
      $$ u_1 = \frac{u}{16.0} + \frac{\text{mod}(z_1, 16.0)}{16.0} $$
      $$ v_1 = \frac{v}{16.0} + \frac{\lfloor \frac{255.0 - z_1}{16.0} \rfloor}{16.0} $$
      $$ u_2 = \frac{u}{16.0} + \frac{\text{mod}(z_2, 16.0)}{16.0} $$
      $$ v_2 = \frac{v}{16.0} + \frac{\lfloor \frac{255.0 - z_2}{16.0} \rfloor}{16.0} $$
      [S1, unofficial]
   h. **Sampling:** Sample the volume texture at $(u_1, v_1)$ and $(u_2, v_2)$ using bilinear filtering to get colors/alphas $C_1$ and $C_2$ [S1, unofficial].
   i. **Z-Interpolation:** Interpolate between $C_1$ and $C_2$ using $z_{diff}$ [S1, unofficial].
   j. **Transfer Function:** Map the resulting alpha to the transfer function texture to get RGB color [S1, unofficial].
   k. **Alpha Accumulation:** Update accumulated alpha and color using front-to-back blending with a correction factor [S1, unofficial].

**Formulas:**
- **Ray Direction Increment:**
  $$ \Delta \vec{d} = \text{normalize}(\vec{d}) \cdot \delta $$
  where $\delta = 1.0 / \text{steps}$ [S1, unofficial].
- **Alpha Correction:**
  $$ \alpha_{sample} = \alpha_{raw} \cdot \alpha_{correction} \cdot (1.0 - \alpha_{accumulated}) \cdot \alpha_{scale\_factor} $$
  where $\alpha_{scale\_factor} = 25.6 \cdot \delta$ [S1, unofficial].

**Parameters:**
- `steps`: Number of ray marching steps. Default 256.0, range 0.0–512.0 [S1, unofficial].
- `MAX_STEPS`: Loop limit to prevent clipping. Set to 887 to handle diagonal viewing [S1, unofficial].
- `alphaCorrection`: User-adjustable transparency intensity. Default 1.0, range 0.01–5.0 [S1, unofficial].

**Pseudocode:**
```python
# Fragment Shader Logic (GLSL-like)

uniform sampler2D cubeTex;
uniform sampler2D transferTex;
uniform sampler2D rtTexture;
uniform float steps;
uniform float alphaCorrection;

void main() {
    // 1. Get back position from first pass
    vec3 backPos = texture2D(rtTexture, gl_TexCoord[0].xy).xyz;
    
    // Pitfall: Discard if back position is invalid
    if (backPos == vec3(0.0)) {
        gl_FragColor = vec4(0.0);
        return;
    }

    // 2. Ray setup
    vec3 frontPos = worldSpaceCoords; // From vertex shader
    vec3 dir = backPos - frontPos;
    float dist = length(dir);
    float delta = 1.0 / steps;
    vec3 stepDir = normalize(dir) * delta;

    // 3. Accumulators
    vec4 accColor = vec4(0.0);
    float accAlpha = 0.0;

    // 4. Ray Marching Loop
    // Note: MAX_STEPS is 887 to prevent diagonal clipping
    for (int i = 0; i < 887; i++) {
        if (accAlpha >= 1.0) break;

        vec3 pos = frontPos + stepDir * float(i);
        
        // Normalize pos to [0, 1] for texture lookup if needed
        // Assuming pos is already in texture space [0,1]
        
        // 5. Slice Indexing
        float zCoord = pos.z; // Assuming Z is the slice axis
        float z1 = floor(zCoord * 255.0);
        float z2 = min(z1 + 1.0, 255.0);
        float zDiff = mod(zCoord * 255.0, 1.0);

        // 6. 2D Texture Mapping
        float u = pos.x;
        float v = pos.y;
        
        vec2 uv1 = vec2(u, v) / 16.0;
        uv1.x += mod(z1, 16.0) / 16.0;
        uv1.y += floor((255.0 - z1) / 16.0) / 16.0;

        vec2 uv2 = vec2(u, v) / 16.0;
        uv2.x += mod(z2, 16.0) / 16.0;
        uv2.y += floor((255.0 - z2) / 16.0) / 16.0;

        // 7. Sampling
        vec4 color1 = texture2D(cubeTex, uv1);
        vec4 color2 = texture2D(cubeTex, uv2);

        // 8. Z-Interpolation
        vec4 colorSlice = mix(color1, color2, zDiff);

        // 9. Transfer Function
        vec4 tfColor = texture2D(transferTex, vec2(colorSlice.a, 1.0));
        vec3 finalColor = tfColor.rgb;
        float alpha = colorSlice.a;

        // 10. Alpha Accumulation
        float alphaScaleFactor = 25.6 * delta;
        float alphaSample = alpha * alphaCorrection * (1.0 - accAlpha) * alphaScaleFactor;
        
        accColor.rgb += finalColor * alphaSample;
        accAlpha += alphaSample;
    }

    gl_FragColor = vec4(accColor.rgb, accAlpha);
}
```

**Edge Cases and Pitfalls:**
- **Edge Interpolation:** Interpolated world coordinates from the first pass can produce bogus ray directions at cube edges. Use `NearestFilter` for `rtTexture` [S1, unofficial].
- **Invalid Back Position:** If the back position is $(0,0,0)$, the fragment is discarded [S1, unofficial].
- **Diagonal Clipping:** The loop limit must exceed the maximum number of steps along the diagonal ($\sqrt{3} \times \text{steps}$). 887 is used for 512 max steps [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N_{steps})$ per fragment, where $N_{steps}$ is the number of ray marching steps.
- **Memory Complexity:** $O(W \cdot H)$ for the 2D texture, where $W \cdot H = N_{slices} \cdot \text{slice\_width} \cdot \text{slice\_height}$.
- **Performance:** Efficient on GPUs due to 2D texture cache coherence and bilinear filtering. However, the overhead of calculating 2D offsets for 3D coordinates can be higher than direct 3D texture sampling.
- **Strengths:** Compatible with hardware that lacks efficient 3D texture support; leverages standard 2D texture units.
- **Limitations:** Requires two-pass rendering; manual slice indexing logic; potential precision issues at slice boundaries.

## Background
This method is demonstrated in the `web_volume_rendering` repository by Maayan-Moshe, which implements volume rendering in WebGL [S1, unofficial]. It is an adaptation of tiled 2D texture storage for 3D fields, specifically tailored for web-based rendering where 3D textures may have limited support or performance characteristics.
