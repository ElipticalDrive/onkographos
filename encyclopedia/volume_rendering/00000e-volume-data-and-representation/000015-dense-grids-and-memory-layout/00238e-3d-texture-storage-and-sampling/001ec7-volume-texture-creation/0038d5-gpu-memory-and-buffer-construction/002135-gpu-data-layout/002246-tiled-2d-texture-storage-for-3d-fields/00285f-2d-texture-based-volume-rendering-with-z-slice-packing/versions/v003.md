# 2D Texture-Based Volume Rendering with Z-Slice Packing

Also called: 2D Texture Z-Slice Packing, Z-Slice Packing

## Overview
This method renders a 3D scalar field by storing its Z-slices in a tiled 2D texture grid, allowing 3D sampling via 2D texture lookups and trilinear interpolation [S1, unofficial]. It differs from standard 3D texture sampling by mapping 3D coordinates to a 2D atlas, requiring explicit slice indexing and offset calculation in the shader [S1, unofficial]. It builds on [Tiled 2D Texture Storage for 3D Fields](2740-tiled-2d-texture-storage-for-3d-fields.md) [G].

## How it works
**Inputs and Outputs:**
- Input: A 3D volume of $N_z$ slices (typically 256), stored in a 2D texture of size $W \times H$ [S1, unofficial].
- Input: Camera matrices (projection, model-view) and ray marching parameters [S1, unofficial].
- Output: Final color and opacity per fragment [S1, unofficial].

**Data Structures:**
- `cubeTex`: A 2D texture containing the volume data. For 256 slices arranged in a $16 \times 16$ grid within a $256 \times 256$ texture, each slice occupies a $16 \times 16$ pixel region [S1, unofficial].
- `transferTex`: A 1D or 2D texture mapping opacity (alpha) to RGB color [S1, unofficial].
- `rtTexture`: A render target texture storing world-space coordinates of the ray entry point (back face) [S1, unofficial].

**Numbered Steps:**
1. **First Pass (Back Face):** Render the back face of the volume bounding box to `rtTexture` to store world-space coordinates of the ray entry point [S1, unofficial].
2. **Second Pass (Front Face & Ray Marching):**
   a. **Ray Initialization:** Determine the ray origin (front face) and direction. Retrieve the back position from `rtTexture` using `NearestFilter` to avoid interpolation artifacts at edges [S1, unofficial]. If the back position is invalid ($(0,0,0)$), discard the fragment [S1, unofficial].
   b. **Step Calculation:** Calculate the step size. The maximum distance through the volume is $\sqrt{3}$ (normalized cube diagonal) [S1, unofficial]. The step size in world units is derived from the total ray length and the number of steps [S1, unofficial].
   c. **Loop:** Iterate through the ray steps up to a fixed limit [S1, unofficial].
   d. **Texture Coordinate Mapping:** For the current ray position, calculate the 3D texture coordinates $(u, v, w)$ [S1, unofficial].
   e. **Slice Indexing:** Determine the integer Z-slice index and the next slice index for interpolation: $z_1 = \lfloor w \cdot 255.0 \rfloor$ and $z_2 = \min(z_1 + 1.0, 255.0)$ [S1, unofficial].
   f. **Z-Interpolation Factor:** Compute the fractional Z-distance: $z_{diff} = \text{mod}(w \cdot 255.0, 1.0)$ [S1, unofficial].
   g. **2D Coordinate Offset:** Map the 3D coordinates to the 2D texture atlas by dividing the base UV by the grid size (16.0) and adding offsets based on the slice index: $u_1 = \frac{u}{16.0} + \frac{\text{mod}(z_1, 16.0)}{16.0}$, $v_1 = \frac{v}{16.0} + \frac{\lfloor \frac{255.0 - z_1}{16.0} \rfloor}{16.0}$, and similarly for $(u_2, v_2)$ [S1, unofficial].
   h. **Sampling:** Sample the volume texture at $(u_1, v_1)$ and $(u_2, v_2)$ using bilinear filtering to get colors/alphas $C_1$ and $C_2$ [S1, unofficial].
   i. **Z-Interpolation:** Interpolate between $C_1$ and $C_2$ using $z_{diff}$ [S1, unofficial].
   j. **Transfer Function:** Map the resulting alpha to the transfer function texture to get RGB color [S1, unofficial].
   k. **Alpha Accumulation:** Update accumulated alpha and color using front-to-back blending with a correction factor [S1, unofficial].

**Formulas:**
- **Ray Direction Increment:** $\Delta \vec{d} = \text{normalize}(\vec{d}) \cdot \delta$, where $\delta = 1.0 / \text{steps}$ [S1, unofficial].
- **Alpha Correction:** $\alpha_{sample} = \alpha_{raw} \cdot \alpha_{correction} \cdot (1.0 - \alpha_{accumulated}) \cdot \alpha_{scale\_factor}$, where $\alpha_{scale\_factor} = 25.6 \cdot \delta$ [S1, unofficial].

**Parameters:**
- `steps`: Number of ray marching steps. Default 256.0, range 0.0–512.0 [S1, unofficial].
- `MAX_STEPS`: Loop limit to prevent clipping. Set to 887 to handle diagonal viewing [S1, unofficial].
- `alphaCorrection`: User-adjustable transparency intensity. Default 1.0, range 0.01–5.0 [S1, unofficial].

**Pseudocode:**
```python
import math

def render_fragment(front_pos, back_pos, steps, alpha_correction):
    # Pitfall: Discard if back position is invalid
    if back_pos == (0.0, 0.0, 0.0):
        return (0.0, 0.0, 0.0, 0.0)

    # Guard against division by zero
    if steps <= 0:
        steps = 1.0

    # Ray setup
    dir_vec = (back_pos[0] - front_pos[0], back_pos[1] - front_pos[1], back_pos[2] - front_pos[2])
    dist = math.sqrt(dir_vec[0]**2 + dir_vec[1]**2 + dir_vec[2]**2)
    delta = 1.0 / steps
    step_dir = (dir_vec[0] / dist * delta, dir_vec[1] / dist * delta, dir_vec[2] / dist * delta)

    acc_color = (0.0, 0.0, 0.0)
    acc_alpha = 0.0
    MAX_STEPS = 887

    for i in range(MAX_STEPS):
        if acc_alpha >= 1.0:
            break

        pos = (front_pos[0] + step_dir[0] * i,
               front_pos[1] + step_dir[1] * i,
               front_pos[2] + step_dir[2] * i)

        z_coord = pos[2]
        z1 = math.floor(z_coord * 255.0)
        z2 = min(z1 + 1.0, 255.0)
        z_diff = math.fmod(z_coord * 255.0, 1.0)

        u, v = pos[0], pos[1]
        uv1 = (u / 16.0 + math.fmod(z1, 16.0) / 16.0,
               v / 16.0 + math.floor((255.0 - z1) / 16.0) / 16.0)
        uv2 = (u / 16.0 + math.fmod(z2, 16.0) / 16.0,
               v / 16.0 + math.floor((255.0 - z2) / 16.0) / 16.0)

        # Standard 2D texture lookup with bilinear filtering [G]
        color1 = texture_lookup(cubeTex, uv1)
        color2 = texture_lookup(cubeTex, uv2)

        color_slice = (color1[0] + (color2[0] - color1[0]) * z_diff,
                       color1[1] + (color2[1] - color1[1]) * z_diff,
                       color1[2] + (color2[2] - color1[2]) * z_diff,
                       color1[3] + (color2[3] - color1[3]) * z_diff)

        tf_color = texture_lookup(transferTex, (color_slice[3], 1.0))
        final_color = (tf_color[0], tf_color[1], tf_color[2])
        alpha = color_slice[3]

        alpha_scale_factor = 25.6 * delta
        alpha_sample = alpha * alpha_correction * (1.0 - acc_alpha) * alpha_scale_factor

        acc_color = (acc_color[0] + final_color[0] * alpha_sample,
                     acc_color[1] + final_color[1] * alpha_sample,
                     acc_color[2] + final_color[2] * alpha_sample)
        acc_alpha += alpha_sample

    return (acc_color[0], acc_color[1], acc_color[2], acc_alpha)
```

**Edge Cases and Pitfalls:**
- **Edge Interpolation:** Interpolated world coordinates from the first pass can produce bogus ray directions at cube edges. Use `NearestFilter` for `rtTexture` [S1, unofficial].
- **Invalid Back Position:** If the back position is $(0,0,0)$, the fragment is discarded [S1, unofficial].
- **Diagonal Clipping:** The loop limit must exceed the maximum number of steps along the diagonal ($\sqrt{3} \times \text{steps}$). 887 is used for 512 max steps [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N_{steps})$ per fragment, where $N_{steps}$ is the number of ray marching steps [G].
- **Memory Complexity:** $O(W \cdot H)$ for the 2D texture, where $W \cdot H = N_{slices} \cdot \text{slice\_width} \cdot \text{slice\_height}$ [G].
- **Performance:** Efficient on GPUs due to 2D texture cache coherence and bilinear filtering [G]. However, the overhead of calculating 2D offsets for 3D coordinates can be higher than direct 3D texture sampling [G].
- **Strengths:** Compatible with hardware that lacks efficient 3D texture support; leverages standard 2D texture units [G].
- **Limitations:** Requires two-pass rendering; manual slice indexing logic; potential precision issues at slice boundaries [S1, unofficial].

## Background
This method is implemented in the provided codebase [S1, unofficial]. It is an adaptation of tiled 2D texture storage for 3D fields, specifically tailored for web-based rendering where 3D textures may have limited support or performance characteristics [G].
