# GPU Data Layout


## Overview
GPU Data Layout defines the host-side C++ structures and OpenGL resource bindings required to transfer volumetric scalar fields, transfer functions, and auxiliary buffers to the GPU for raycasting [S1, unofficial]. It solves the problem of mapping logical VTK data components (scalars, opacity tables, depth buffers) to specific GPU texture and framebuffer objects with strict format constraints [S1, unofficial]. It differs from [Volume Upload via Staging Buffer](15388-volume-upload-via-staging-buffer.md) by focusing on the final resource binding and layout definition rather than the transfer mechanism, and from [ClearView Unified Buffer Construction](2475-clearview-unified-buffer-construction.md) by using distinct OpenGL texture IDs for separate data types rather than a unified buffer approach [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** VTK `vtkImageData` containing scalar data (1-component or 4-component RGBA unsigned char), transfer function parameters, and rendering context (renderer, camera).
*   **Output:** Populated OpenGL resource IDs and memory layouts ready for shader sampling.

**Data Structures:**
The layout is managed via a set of host-side variables that hold OpenGL object IDs and data pointers [S1, unofficial]:

1.  **TextureObjects**: An array of 5 `unsigned int` IDs.
    *   `TextureObjects[0]`: 3D scalar texture (volume data).
    *   `TextureObjects[1]`: 1D color table (transfer function RGB).
    *   `TextureObjects[2]`: 1D opacity table (transfer function alpha).
    *   `TextureObjects[3]`: 2D grabbed depth buffer.
    *   `TextureObjects[4]`: 2D color buffer (framebuffer attachment).
2.  **MaxValueFrameBuffer** and **MaxValueFrameBuffer2**: Two `unsigned int` framebuffer IDs used for ping-pong accumulation in MIP (Maximum Intensity Projection) mode [S1, unofficial].
3.  **BoundingBox**: A `double[8][3]` array storing the world coordinates of the 8 corners of the dataset bounding box [S1, unofficial].
4.  **FrameBufferObject**: An `unsigned int` ID for the primary offscreen framebuffer object [S1, unofficial].
5.  **DepthRenderBufferObject**: An `unsigned int` ID for the depth renderbuffer attached to the framebuffer [S1, unofficial].
6.  **NoiseTexture**: A `float` array storing procedural noise data for speckle reduction [S1, unofficial].
7.  **NoiseTextureSize**: An `int` specifying the 1D dimension size of the noise texture [S1, unofficial].
8.  **NoiseTextureId**: An `unsigned int` OpenGL ID for the noise texture [S1, unofficial].
9.  **TextureCoord_1toN**: An array of `vtkTransform` pointers mapping texture coordinates from the primary volume to additional volumes [S1, unofficial].

**Validation and Constraints:**
Before layout creation, the scalar data must satisfy specific constraints [S1, unofficial]:
1.  **Component Count**: Only 1-component scalars or 4-component scalars are supported.
2.  **Data Type**: If 4-component, the data type must be `VTK_UNSIGNED_CHAR` (RGBA).
3.  **Blend Mode**: Additive blend mode (`ADDITIVE_BLEND`) is only supported with 1-component scalars.

**Steps:**
1.  **Validate Input**: Check `numberOfComponents` and `scalars->GetDataType()`. If 4 components, ensure type is `VTK_UNSIGNED_CHAR`. If `BlendMode` is `ADDITIVE_BLEND`, ensure `numberOfComponents` is 1. If validation fails, abort [S1, unofficial].
2.  **Generate Bounding Box**: Calculate the 8 corners of the dataset bounding box and store in `BoundingBox[8][3]` [S1, unofficial].
3.  **Allocate OpenGL Resources**:
    *   Generate 3D texture ID for scalar data.
    *   Generate 1D texture IDs for color and opacity tables.
    *   Generate framebuffer and renderbuffer IDs for depth and color buffers.
    *   Generate noise texture ID if speckle reduction is enabled.
4.  **Bind Resources**: Bind the generated IDs to their respective targets (e.g., `GL_TEXTURE_3D`, `GL_TEXTURE_1D`, `GL_FRAMEBUFFER`) [S1, unofficial].
5.  **Transfer Data**: Upload scalar data to the 3D texture, transfer function data to 1D textures, and noise data to the noise texture [S1, unofficial].
6.  **Setup Coordinate Mapping**: Initialize `TextureCoord_1toN` transforms for multi-volume alignment [S1, unofficial].

**Pseudocode:**
```python
def create_gpu_data_layout(vtk_image_data, blend_mode):
    # Step 1: Validate Input
    num_components = vtk_image_data.get_number_of_components()
    data_type = vtk_image_data.get_data_type()
    
    if num_components != 1 and num_components != 4:
        raise ValueError("Only 1 or 4 component scalars supported")
    
    if num_components == 4 and data_type != VTK_UNSIGNED_CHAR:
        raise ValueError("4-component scalars must be unsigned char")
        
    if blend_mode == ADDITIVE_BLEND and num_components != 1:
        raise ValueError("Additive mode only works with 1-component scalars")
        
    # Step 2: Generate Bounding Box
    bounds = vtk_image_data.get_bounds() # [xmin, xmax, ymin, ymax, zmin, zmax]
    center = vtk_image_data.get_center()
    d = bounds[1] - bounds[0] # X distance
    
    # Calculate 8 corners (simplified for illustration)
    bbox_corners = calculate_8_corners(bounds)
    BoundingBox = np.array(bbox_corners).reshape(8, 3)
    
    # Step 3: Allocate OpenGL Resources
    TextureObjects = [0] * 5
    glGenTextures(1, TextureObjects[0:1]) # 3D scalar texture
    glGenTextures(1, TextureObjects[1:2]) # 1D color table
    glGenTextures(1, TextureObjects[2:3]) # 1D opacity table
    glGenFramebuffers(1, MaxValueFrameBuffer)
    glGenFramebuffers(1, MaxValueFrameBuffer2)
    glGenFramebuffers(1, FrameBufferObject)
    glGenRenderbuffers(1, DepthRenderBufferObject)
    
    # Noise texture setup
    NoiseTextureSize = 64 # Example size
    NoiseTexture = np.random.rand(NoiseTextureSize).astype(np.float32)
    NoiseTextureId = 0
    glGenTextures(1, NoiseTextureId)
    
    # Step 4: Bind and Configure Textures
    glBindTexture(GL_TEXTURE_3D, TextureObjects[0])
    glTexImage3D(GL_TEXTURE_3D, 0, GL_RGBA, 
                 vtk_image_data.get_dimensions(), 
                 0, 0, GL_RGBA, GL_UNSIGNED_BYTE, 
                 vtk_image_data.get_pointer())
                 
    glBindTexture(GL_TEXTURE_1D, TextureObjects[1])
    glTexImage1D(GL_TEXTURE_1D, 0, GL_RGBA, color_table_size, 0, GL_RGBA, GL_FLOAT, color_table_data)
    
    glBindTexture(GL_TEXTURE_1D, TextureObjects[2])
    glTexImage1D(GL_TEXTURE_1D, 0, GL_RED, opacity_table_size, 0, GL_RED, GL_FLOAT, opacity_table_data)
    
    # Bind Framebuffer
    glBindFramebuffer(GL_FRAMEBUFFER, FrameBufferObject)
    glFramebufferRenderbuffer(GL_FRAMEBUFFER, GL_DEPTH_ATTACHMENT, GL_RENDERBUFFER, DepthRenderBufferObject)
    
    # Step 5: Setup Coordinate Mapping
    TextureCoord_1toN = [vtkTransform() for _ in range(MAX_NUMBER_OF_ADDITIONAL_VOLUMES)]
    
    return {
        "TextureObjects": TextureObjects,
        "MaxValueFrameBuffer": MaxValueFrameBuffer,
        "MaxValueFrameBuffer2": MaxValueFrameBuffer2,
        "BoundingBox": BoundingBox,
        "FrameBufferObject": FrameBufferObject,
        "DepthRenderBufferObject": DepthRenderBufferObject,
        "NoiseTexture": NoiseTexture,
        "NoiseTextureSize": NoiseTextureSize,
        "NoiseTextureId": NoiseTextureId,
        "TextureCoord_1toN": TextureCoord_1toN
    }
```

## Subtopics

### [GPU Texture Loading](2473-gpu-texture-loading.md)
Transfers volumetric scalar data from host memory or binary files into GPU-accessible 3D textures for raycasting. It solves the problem of efficiently moving dense grid data to the GPU while managing memory constraints and avoiding redundant transfers [G]. It differs from [Tiled 2D Texture Storage for 3D Fields](2740-tiled-2d-texture-storage-for-3d-fields.md) by using native 3D texture objects rather than packing 3D data into 2D tile arrays, and from [CUDA-accelerated Vector Field Reading with Magnitude](2581-cuda-accelerated-vector-field-reading-with-magnitude.md) by focusing on scalar fields rather than vector fields with magnitude pre-computation.

### [Tiled 2D Texture Storage for 3D Fields](2740-tiled-2d-texture-storage-for-3d-fields.md)
A technique to store a 3D scalar field in a 2D texture by tiling the 3D volume into 2D slices, allowing efficient GPU access via texture lookups. It maps 3D coordinates to 2D texture coordinates using a tiling scheme where the Z-coordinate determines the tile position, enabling standard 2D texture sampling hardware to access volumetric data.

## Operating characteristics
*   **Time Complexity**: Linear with respect to the volume of data for upload, $O(N)$ where $N$ is the number of voxels.
*   **Memory Complexity**: Proportional to the volume size plus overhead for auxiliary buffers (depth, color, noise).
*   **Strengths**: Explicit control over memory layout allows for optimized sampling in shaders. Supports multiple volume alignment via coordinate transforms.
*   **Limitations**: Strict input validation limits supported data types (only 1 or 4 component unsigned char). Additive blending is restricted to 1-component data.
*   **When to use**: When using OpenGL-based raycasting with VTK data structures and requiring precise control over texture and framebuffer binding.
*   **When not to use**: For vector fields or non-unsigned char scalar data without conversion. For hardware that does not support 3D textures.

## Background
This layout is derived from the `vtkGPUMultiVolumeRayCastMapper` implementation in the VTK library, specifically as adapted in the `VTKMultiVolumeRayCaster` project [S1, unofficial]. It reflects the OpenGL 2.0/3.0 era approach to volume rendering, relying on explicit texture objects and framebuffer objects rather than modern compute shaders or unified memory architectures.
