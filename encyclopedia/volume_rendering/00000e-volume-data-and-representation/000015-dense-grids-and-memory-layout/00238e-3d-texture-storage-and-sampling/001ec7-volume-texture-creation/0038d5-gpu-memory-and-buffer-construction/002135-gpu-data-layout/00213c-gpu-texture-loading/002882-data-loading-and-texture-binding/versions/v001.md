# Data Loading and Texture Binding

Also called: CUDA 3D Array and Texture Binding, GPU Texture Loading, Volume Data Loading to GPU, cudaLoadVolume

## Overview
This method transfers volumetric scalar field data and transfer function parameters from host memory to the GPU, creating a 3D CUDA array and binding it to a texture object for efficient GPU-side sampling [S1, S2, unofficial]. It differs from sibling methods by focusing specifically on the initialization phase of volume rendering: preparing the raw voxel data and associated metadata (like transfer functions) for subsequent ray-marching or slicing kernels, rather than performing the rendering itself [S1, S2, unofficial]. It builds on [GPU Texture Loading](2473-gpu-texture-loading.md) by providing the concrete CUDA API calls required to populate the 3D texture storage.

## How it works
**Inputs:**
- Host pointer to volumetric data (`texels` or `data`).
- Volume dimensions (`dims` or `dim`), typically a `cudaExtent` or struct containing `x`, `y`, `z`.
- Data type (e.g., `unsigned char`, `ushort`).
- Transfer function data (e.g., 1024 floats).

**Outputs:**
- Device-side 3D CUDA array (`devVolume` or `dataArray`).
- Bound texture reference/object (`texVolume` or `dataTex`).
- Device-side transfer function array (`devTransfer`).

**Data Structures:**
- `cudaChannelFormatDesc`: Describes the channel format (e.g., 8-bit unsigned integer or 16-bit unsigned integer).
- `cudaExtent`: Defines the 3D extent with fields `width` (x), `height` (y), `depth` (z).
- `cudaMemcpy3DParms`: Structure for 3D memory copy parameters, including source pitched pointer, destination array, extent, and copy kind.
- Texture parameters: `normalized` (boolean), `filterMode` (linear), `addressMode` (clamp for x, y, z).

**Steps:**
1. **Channel Description:** Create a channel descriptor matching the input data type. For `unsigned char`, use `cudaCreateChannelDesc<unsigned char>()` [S1, unofficial]. For `ushort`, use `cudaCreateChannelDesc<ushort>()` [S2, unofficial].
2. **Dimension Transfer:** Copy volume dimensions to a device symbol if required by the kernel interface [S2, unofficial].
3. **Memory Allocation:** Allocate a 3D CUDA array using `cudaMalloc3DArray`. The extent is defined by the volume dimensions [S1, S2, unofficial].
4. **Copy Parameters Setup:** Configure a `cudaMemcpy3DParms` structure:
   - `srcPtr`: A pitched pointer to the host data. The pitch is calculated as `width * sizeof(element_type)` [S2, unofficial]. Note: [S1, unofficial] refers to a pitched pointer of host data `texels`.
   - `dstArray`: The allocated 3D CUDA array [S1, S2, unofficial].
   - `extent`: The volume dimensions [S1, S2, unofficial].
   - `kind`: `cudaMemcpyHostToDevice` [S1, S2, unofficial].
5. **Execute Copy:** Call `cudaMemcpy3D` with the configured parameters [S1, S2, unofficial].
6. **Texture Parameters:** Set texture sampling parameters:
   - Filter mode: `cudaFilterModeLinear` [S1, S2, unofficial].
   - Address mode: `cudaAddressModeClamp` for x, y, and z axes [S1, S2, unofficial].
   - Normalized coordinates: Set to `true` in [S1, unofficial], `false` in [S2, unofficial]. This discrepancy should be resolved based on whether the kernel expects normalized [0,1] or raw coordinate access [S1, S2, unofficial].
7. **Bind Texture:** Bind the 3D array to the texture reference/object using `cudaBindTextureToArray`, passing the channel descriptor [S1, S2, unofficial].
8. **Transfer Function Loading:** Allocate device memory for the transfer function (e.g., 1024 floats) and copy host transfer function data to it [S1, unofficial].

**Pseudocode:**
```python
def load_volume_and_bind(host_data, dims, data_type, transfer_func_data):
    # 1. Channel Description
    if data_type == 'uchar':
        channel_desc = cuda_create_channel_desc_uchar()
    elif data_type == 'ushort':
        channel_desc = cuda_create_channel_desc_ushort()
    else:
        raise ValueError("Unsupported data type")

    # 2. Dimension Transfer (Optional, depends on kernel interface)
    # cuda_set_symbol(data_dim, dims)

    # 3. Memory Allocation
    extent = cuda_make_extent(dims.x, dims.y, dims.z)
    dev_array = cuda_malloc_3d_array(channel_desc, extent)

    # 4. Copy Parameters Setup
    # Calculate pitch: width in bytes
    pitch = dims.x * sizeof(data_type)
    src_ptr = cuda_make_pitched_ptr(host_data, pitch, dims.x, dims.y)
    
    copy_params = cuda_make_3d_copy_params()
    copy_params.src_ptr = src_ptr
    copy_params.dst_array = dev_array
    copy_params.extent = extent
    copy_params.kind = cudaMemcpyHostToDevice

    # 5. Execute Copy
    cuda_copy_3d(copy_params)

    # 6. Texture Parameters
    texture_ref = cuda_create_texture_reference()
    texture_ref.normalized = True  # [S1, unofficial] uses True, [S2, unofficial] uses False. Choose based on kernel needs.
    texture_ref.filter_mode = cudaFilterModeLinear
    texture_ref.address_mode[0] = cudaAddressModeClamp
    texture_ref.address_mode[1] = cudaAddressModeClamp
    texture_ref.address_mode[2] = cudaAddressModeClamp

    # 7. Bind Texture
    cuda_bind_texture_to_array(texture_ref, dev_array, channel_desc)

    # 8. Transfer Function Loading
    dev_transfer = cuda_malloc(1024 * sizeof(float))
    cuda_memcpy(dev_transfer, transfer_func_data, 1024 * sizeof(float), cudaMemcpyHostToDevice)

    return dev_array, texture_ref, dev_transfer
```

**Edge Cases and Pitfalls:**
- **Pitch Calculation:** The source pitch must be correctly calculated as `width * sizeof(element_type)` to ensure proper memory layout during `cudaMemcpy3D` [S2, unofficial].
- **Normalized Coordinates:** Disagreement exists on whether to use normalized coordinates (`true` in [S1, unofficial], `false` in [S2, unofficial]). This affects how texture coordinates are interpreted in shaders [S1, S2, unofficial].
- **Data Type Mismatch:** Ensure the channel descriptor matches the actual data type of the host array [S1, S2, unofficial].

## Operating characteristics
- **Time Complexity:** O(N) where N is the number of voxels, dominated by the memory copy operation.
- **Memory Complexity:** O(N) for the 3D CUDA array and transfer function storage.
- **Performance:** Depends on PCIe bandwidth and GPU memory bandwidth. [S1, S2, unofficial] do not provide specific performance metrics.
- **Strengths:** Efficiently prepares data for GPU-based volume rendering. [S1, S2, unofficial].
- **Limitations:** Requires explicit memory management and binding. [S1, S2, unofficial].
- **When to use:** During the initialization phase of a CUDA-based volume rendering application. [S1, S2, unofficial].
- **When not to use:** When using higher-level abstractions or when data is already on the GPU. [S1, S2, unofficial].
