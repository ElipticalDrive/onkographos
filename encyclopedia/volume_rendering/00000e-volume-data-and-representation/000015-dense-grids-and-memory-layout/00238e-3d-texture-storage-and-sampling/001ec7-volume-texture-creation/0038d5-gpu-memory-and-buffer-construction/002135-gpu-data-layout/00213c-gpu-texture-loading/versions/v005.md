# GPU Texture Loading

Also called: LoadScalarField, Raw Volumetric Data Loading (8/16-bit)

## Overview
GPU Texture Loading transfers volumetric scalar data from host memory to GPU 3D textures for subsequent raycasting or sampling [S1, S2, unofficial]. It solves the problem of preparing raw voxel data for hardware-accelerated interpolation by handling format conversion, memory allocation, and texture binding [S2, unofficial]. It differs from [Tiled 2D Texture Storage for 3D Fields](2740-tiled-2d-texture-storage-for-3d-fields.md) by using native 3D texture objects rather than packing 3D data into 2D tile arrays, and from [CUDA-accelerated Vector Field Reading with Magnitude](2581-cuda-accelerated-vector-field-reading-with-magnitude.md) by focusing on scalar field loading rather than precomputing vector magnitudes [S1, S2, unofficial].

## How it works
**Inputs:**
1.  Source data: Either a binary file path and bit-depth flag (8/16-bit) [S2, unofficial], or a `vtkImageData` pointer with scalar extraction parameters [S1, unofficial].
2.  Extent: A 6-integer array `textureExtent[6]` defining the requested subextent in dataset coordinates `[minX, maxX, minY, maxY, minZ, maxZ]` [S1, unofficial].
3.  Configuration: `is16Bits` flag (boolean) [S2, unofficial], `type` flag (integer: 0 for transformed input, 1 for raw input) [S1, unofficial], and `CellFlag` (boolean indicating point vs. cell data) [S1, unofficial].

**Outputs:**
A bound 3D texture object containing the scalar field data, ready for linear sampling [S1, S2, unofficial].

**Data Structures:**
*   **Host Buffer:** `std::vector<uint8_t>` or `std::vector<uint16_t>` sized to the exact file size for binary paths, or to the number of voxels in the extent for VTK paths [S1, S2, unofficial].
*   **GPU Texture (OpenGL):** Internal format `GL_RED`, swizzle `(R, R, R, R)`, type `GL_UNSIGNED_BYTE` or `GL_UNSIGNED_SHORT`, filter `GL_LINEAR`, wrap `GL_CLAMP_TO_BORDER` [S2, unofficial].

**Steps:**

1.  **Cache Check (VTK Path Only):** If the input pointer has not changed, the modification time is unchanged, the cell flag is unchanged, and the requested `textureExtent` is enclosed within the previously loaded `LoadedExtent`, return success immediately without reloading [S1, unofficial].
2.  **Data Extraction:**
    *   *Binary Path:* Open file in binary mode. Determine size via `file.tellg()`. Seek to the beginning. Allocate buffer of exact file size. Read entire file into buffer [S2, unofficial].
    *   *VTK Path:* Update `TransformedInput` (or `AdditionalTransformedInput` based on `type`) [S1, unofficial]. Extract scalars using `GetScalars`. Validate that scalars are point or cell data (not field data) [S1, unofficial].
3.  **Validation:** Check extent bounds. If `CellFlag` is true, use `<=` comparison for bounds; if false, use strict `<` comparison for all three axes [S1, unofficial]. If GPU memory allocation fails, return false [S1, unofficial].
4.  **Texture Creation & Upload:**
    *   *OpenGL:* Create 3D texture with `GL_RED` internal format. Set swizzle mask to `(R, R, R, R)`. Set filtering to `GL_LINEAR` and wrapping to `GL_CLAMP_TO_BORDER` for S, T, R axes [S2, unofficial]. Upload buffer data to the texture [S2, unofficial].
5.  **State Update (VTK Path Only):** Update `LoadedExtent`, `LoadedBounds`, `LoadedCellFlag`, and `LoadedTime` with current values [S1, unofficial].

**Pseudocode:**

```python
def load_gpu_texture(source_type, file_path=None, vtk_data=None, extent=None, is_16bit=False, cell_flag=False):
    # 1. Cache Check (VTK Path Only)
    if source_type == 'vtk' and vtk_data is not None:
        if (vtk_data.input_unchanged and
            vtk_data.mtime_unchanged and
            vtk_data.cell_flag_unchanged and
            extent[0] >= vtk_data.loaded_extent[0] and extent[1] <= vtk_data.loaded_extent[1] and
            extent[2] >= vtk_data.loaded_extent[2] and extent[3] <= vtk_data.loaded_extent[3] and
            extent[4] >= vtk_data.loaded_extent[4] and extent[5] <= vtk_data.loaded_extent[5]):
            return vtk_data.cached_texture

    # 2. Data Extraction
    if source_type == 'binary':
        # Open file in binary mode and determine its size using file.tellg()
        file_size = os.path.getsize(file_path)
        # Allocate a buffer of the exact file size
        buffer = bytearray(file_size)
        # Read the entire file into the buffer
        with open(file_path, 'rb') as f:
            f.readinto(buffer)
        data_type = GL_UNSIGNED_SHORT if is_16bit else GL_UNSIGNED_BYTE
    else:
        # Update TransformedInput or AdditionalTransformedInput based on type flag
        update_vtk_input(vtk_data, type_flag)
        # Extract scalars, ensuring point or cell data (not field data)
        scalars = extract_scalars(vtk_data, cell_flag)
        if scalars is None:
            raise ValueError("No scalars found or field scalars detected")
        buffer = convert_scalars_to_buffer(scalars, is_16bit)
        data_type = GL_UNSIGNED_SHORT if is_16bit else GL_UNSIGNED_BYTE

    # 3. Validation
    # Check extent bounds: if CellFlag is true, uses <= comparison; if false, requires strict < comparison for all three axes
    if cell_flag:
        if not (extent[0] <= loaded_extent[0] and extent[1] >= loaded_extent[1] and
                extent[2] <= loaded_extent[2] and extent[3] >= loaded_extent[3] and
                extent[4] <= loaded_extent[4] and extent[5] >= loaded_extent[5]):
            raise ValueError("Invalid extent bounds")
    else:
        if not (extent[0] < loaded_extent[0] and extent[1] > loaded_extent[1] and
                extent[2] < loaded_extent[2] and extent[3] > loaded_extent[3] and
                extent[4] < loaded_extent[4] and extent[5] > loaded_extent[5]):
            raise ValueError("Invalid extent bounds")
    # If GPU memory allocation fails, return false
    if not allocate_gpu_memory(extent):
        return False

    # 4. Texture Creation & Upload
    # Create a GL_RED 3D texture with GL_LINEAR filtering and GL_CLAMP_TO_BORDER wrapping
    tex_id = create_opengl_3d_texture(GL_RED, GL_LINEAR, GL_CLAMP_TO_BORDER)
    # Set the internal format to GL_RED and swizzle mask to (R, R, R, R)
    set_texture_swizzle(tex_id, (GL_RED, GL_RED, GL_RED, GL_RED))
    # Upload the buffer data to the texture
    upload_texture_3d(tex_id, buffer, data_type, extent)

    # 5. State Update (VTK Path Only)
    if source_type == 'vtk' and vtk_data is not None:
        vtk_data.loaded_extent = extent
        vtk_data.loaded_bounds = compute_bounds(extent)
        vtk_data.loaded_cell_flag = cell_flag
        vtk_data.loaded_time = get_current_time()

    return tex_id
```

## Subtopics

### [CUDA-accelerated Vector Field Reading with Magnitude](2581-cuda-accelerated-vector-field-reading-with-magnitude.md)
Enables fast, linearly interpolated reading of 3D vector field values at arbitrary positions using CUDA 3D textures. It differs from standard scalar texture loading by storing precomputed vector magnitudes in the fourth component of a `float4` structure to avoid redundant calculations during rendering. Choose this when rendering vector fields where magnitude is frequently accessed. Link: [CUDA-accelerated Vector Field Reading with Magnitude](2581-cuda-accelerated-vector-field-reading-with-magnitude.md).

### [Data Loading and Texture Binding](4283-data-loading-and-texture-binding.md)
Transfers volumetric scalar field data and transfer function parameters from host memory to the GPU, creating a 3D CUDA array and binding it to a texture object for efficient GPU-side sampling. It differs from sibling methods by focusing specifically on the initialization phase of volume rendering: preparing the raw voxel data and associated metadata for subsequent ray-marching or slicing kernels, rather than performing the rendering itself. It builds on [GPU Texture Loading](2473-gpu-texture-loading.md) by providing the concrete CUDA API calls required to populate the 3D texture storage. Choose this when concrete CUDA initialization steps are required. Link: [Data Loading and Texture Binding](4283-data-loading-and-texture-binding.md).

### [Hardware-Filtered Data Textures](13812-hardware-filtered-data-textures.md)
Enables efficient single-fetch filtered lookups by mapping volume data to specific GPU texture formats that match the sampling kernel, avoiding the high cost of manual interpolation on integer textures. This method differs from general texture loading by prioritizing the internal format's compatibility with hardware filtering units over raw transfer bandwidth, whereas sibling methods like CUDA-accelerated Vector Field Reading focus on vector magnitude computation rather than scalar field sampling optimization. Choose this when manual interpolation is a bottleneck. Link: [Hardware-Filtered Data Textures](13812-hardware-filtered-data-textures.md).

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the loaded extent, dominated by memory copy operations [S1, S2, unofficial].
*   **Memory Complexity:** $O(N)$ bytes, where $N$ is the number of voxels, with $N$ bytes for 8-bit data or $2N$ bytes for 16-bit data, plus overhead for texture object metadata [S2, unofficial].
*   **Performance:** Loading time depends on PCIe bandwidth and GPU VRAM availability. Insufficient VRAM causes allocation failure [S1, unofficial].
*   **Strengths:** Simple API, hardware-accelerated interpolation support, caching reduces redundant loads [S1, S2, unofficial].
*   **Limitations:** Limited to scalar fields (unless using variants), fixed extent loading may waste memory if subextents are small [S1, S2, unofficial].
*   **When to use:** When raw volumetric data needs to be rendered on GPU with linear interpolation [S2, unofficial].
*   **When not to use:** Not given in the sources.

## Background
Originated in VTK-based volume rendering pipelines [S1, unofficial] and standalone OpenGL/CUDA volume rendering projects [S2, unofficial]. It is used in scientific visualization where raw volumetric scalar data from binary files must be transferred to the GPU for raycasting [S2, unofficial].
