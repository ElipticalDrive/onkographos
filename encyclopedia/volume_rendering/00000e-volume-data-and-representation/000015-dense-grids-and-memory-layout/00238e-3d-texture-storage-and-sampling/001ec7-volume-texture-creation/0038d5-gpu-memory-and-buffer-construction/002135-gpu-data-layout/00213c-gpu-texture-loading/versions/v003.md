# GPU Texture Loading

Also called: LoadScalarField, Raw Volumetric Data Loading (8/16-bit)

## Overview
GPU Texture Loading transfers volumetric scalar data from host memory or binary files into GPU-accessible 3D textures for raycasting [S2, unofficial]. It solves the problem of efficiently moving dense grid data to the GPU while managing memory constraints and avoiding redundant transfers [G]. It differs from [Tiled 2D Texture Storage for 3D Fields](2740-tiled-2d-texture-storage-for-3d-fields.md) by using native 3D texture objects rather than packing 3D data into 2D tile arrays, and from [CUDA-accelerated Vector Field Reading with Magnitude](2581-cuda-accelerated-vector-field-reading-with-magnitude.md) by focusing on scalar fields rather than vector fields with magnitude pre-computation [S1, unofficial][S2, unofficial][S3, unofficial].

## How it works
**Inputs:**
1. Source data: Either a `vtkImageData` pointer containing point or cell scalars [S1, unofficial] or a raw binary file path [S2, unofficial].
2. Extent: An array of six integers `textureExtent[6]` specifying the requested subextent in dataset coordinates [S1, unofficial].
3. Bit depth: A boolean flag `is16Bits` determining if data is 8-bit (`uint8`) or 16-bit (`uint16`) [S2, unofficial].
4. Source type: An integer `type` where 0 indicates starting from `GetAdditionalTransformedInput` and 1 from `GetInput` [S1, unofficial].

**Outputs:**
A bound 3D texture object ready for sampling, with internal state variables `LoadedExtent`, `LoadedBounds`, `LoadedCellFlag`, and `LoadedTime` updated [S1, unofficial].

**Data Structures:**
* Buffer: A `std::vector<uint8_t>` or `std::vector<uint16_t>` sized to the exact file size or data volume [S2, unofficial].
* Texture (OpenGL): Internal format `GL_RED`, swizzle mask `(R, R, R, R)`, data type `GL_UNSIGNED_BYTE` or `GL_UNSIGNED_SHORT`, filter `GL_LINEAR`, wrapping `GL_CLAMP_TO_BORDER` [S2, unofficial].
* Texture (CUDA): `cudaArray` with `cudaChannelFormatDesc` for `ushort` (or appropriate type), bound to a `cudaTextureObject` [S3, unofficial].

**Steps:**
1. Cache Check: If the input pointer has not changed, the cell flag is unchanged, and the requested `textureExtent` is enclosed within the currently `LoadedExtent`, return success immediately without reloading [S1, unofficial].
2. Data Acquisition:
   * VTK Path: Retrieve scalars from the input using `GetScalars` [S1, unofficial]. Validate that scalars exist and are not field data (only point or cell scalars are supported) [S1, unofficial].
   * Binary Path: Open the file in binary mode [S2, unofficial]. Determine size using `file.tellg()` [S2, unofficial]. Allocate a buffer of that size [S2, unofficial]. Read the entire file into the buffer [S2, unofficial].
3. Texture Creation & Upload:
   * OpenGL: Create a 3D texture with `GL_RED` internal format [S2, unofficial]. Set filtering to `GL_LINEAR` and wrapping to `GL_CLAMP_TO_BORDER` [S2, unofficial]. Set the swizzle mask to `(R, R, R, R)` to ensure all components return the scalar value [S2, unofficial]. Upload the buffer data to the texture [S2, unofficial].
   * CUDA: Copy dimensions to device symbol `dataDim` [S3, unofficial]. Create a 3D array using `cudaMalloc3DArray` with the appropriate channel format (e.g., `ushort`) [S3, unofficial]. Copy host data to the 3D array using `cudaMemcpy3D` with `cudaMemcpyHostToDevice` [S3, unofficial]. Set texture parameters: `cudaFilterModeLinear`, address modes `cudaAddressModeClamp` for all axes [S3, unofficial]. Bind the array to the texture object using `cudaBindTextureToArray` [S3, unofficial].
4. State Update: Update `LoadedExtent`, `LoadedBounds`, `LoadedCellFlag`, and `LoadedTime` to reflect the new data [S1, unofficial].

**Pseudocode (OpenGL Variant):**
```python
def load_volume_texture_gl(file_path, is_16_bits, texture_extent, loaded_extent, cell_flag):
    # Cache check: if input unchanged, cell flag unchanged, and extent enclosed, succeed [S1, unofficial]
    # Sources do not specify exact caching comparison logic [G]
    if input_unchanged and cell_flag_unchanged and enclosed(texture_extent, loaded_extent, cell_flag):
        return True
    # Binary path: open file, get size, allocate buffer, read [S2, unofficial]
    file_size = os.path.getsize(file_path)
    buffer = bytearray(file_size)
    with open(file_path, 'rb') as f:
        f.readinto(buffer)
    # Texture creation
    gl_type = GL_UNSIGNED_SHORT if is_16_bits else GL_UNSIGNED_BYTE
    internal_format = GL_RED
    data_type_code = GL_RED
    tex_id = glGenTextures(1)
    glBindTexture(GL_TEXTURE_3D, tex_id)
    glTexStorage3D(GL_TEXTURE_3D, 1, internal_format,
                   texture_extent[1] - texture_extent[0] + 1,
                   texture_extent[3] - texture_extent[2] + 1,
                   texture_extent[5] - texture_extent[4] + 1)
    glTexSubImage3D(GL_TEXTURE_3D, 0,
                    texture_extent[0], texture_extent[2], texture_extent[4],
                    texture_extent[1] - texture_extent[0] + 1,
                    texture_extent[3] - texture_extent[2] + 1,
                    texture_extent[5] - texture_extent[4] + 1,
                    data_type_code, gl_type, buffer)
    glTexParameteri(GL_TEXTURE_3D, GL_TEXTURE_MIN_FILTER, GL_LINEAR)
    glTexParameteri(GL_TEXTURE_3D, GL_TEXTURE_MAG_FILTER, GL_LINEAR)
    glTexParameteri(GL_TEXTURE_3D, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_BORDER)
    glTexParameteri(GL_TEXTURE_3D, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_BORDER)
    glTexParameteri(GL_TEXTURE_3D, GL_TEXTURE_WRAP_R, GL_CLAMP_TO_BORDER)
    glTexParameterIiv(GL_TEXTURE_3D, GL_TEXTURE_SWIZZLE_RGBA,
                      [GL_RED, GL_RED, GL_RED, GL_RED])
    # Sources do not specify state update implementation [G]
    update_loaded_state(texture_extent, is_16_bits)
    return True
```

**Pseudocode (CUDA Variant):**
```python
def load_volume_texture_cuda(host_data, dim):
    # Copy dimensions to device symbol [S3, unofficial]
    cudaMemcpyToSymbol(dataDim, dim, sizeof(cudaExtent))
    # Create 3D array with ushort channel format [S3, unofficial]
    channel_desc = cudaCreateChannelDesc_ushort()
    cudaMalloc3DArray(dataArray, channel_desc, dim)
    # Copy data from host to 3D array [S3, unofficial]
    copy_params = make_cudaMemcpy3DParms()
    copy_params.srcPtr = make_cudaPitchedPtr(host_data, dim.width * sizeof(ushort), dim.width, dim.height)
    copy_params.dstArray = dataArray
    copy_params.extent = dim
    copy_params.kind = cudaMemcpyHostToDevice
    cudaMemcpy3D(copy_params)
    # Set texture parameters [S3, unofficial]
    dataTex.normalized = False
    dataTex.filterMode = cudaFilterModeLinear
    dataTex.addressMode[0] = cudaAddressModeClamp
    dataTex.addressMode[1] = cudaAddressModeClamp
    dataTex.addressMode[2] = cudaAddressModeClamp
    # Bind array to texture object [S3, unofficial]
    cudaBindTextureToArray(dataTex, dataArray, channel_desc)
```

**Edge Cases and Pitfalls:**
* VRAM Exhaustion: Returns false if GPU memory allocation fails [S1, unofficial].
* Extent Validation: If `CellFlag` is true, extent bounds use `<=` comparison; if false, strict `<` comparison is required for all three axes [S1, unofficial].
* Data Type Mismatch: Using `GL_RED` internal format requires matching swizzle and data type to avoid interpretation errors [S2, unofficial].
* Field Scalars: Field data scalars are not supported; only point or cell scalars are valid [S1, unofficial].

## Subtopics

### [CUDA-accelerated Vector Field Reading with Magnitude](2581-cuda-accelerated-vector-field-reading-with-magnitude.md)
A technique to read 3D vector field values at arbitrary positions using CUDA 3D textures with linear interpolation, storing vector magnitude in the fourth component of a float4 to avoid recomputation. It differs from standard scalar loading by encoding vector magnitude directly into the texture's alpha channel during loading, allowing shaders to access magnitude without computing `length()` at runtime. Choose this when performance-critical shaders require frequent magnitude checks. See [CUDA-accelerated Vector Field Reading with Magnitude](2581-cuda-accelerated-vector-field-reading-with-magnitude.md).

### Data Loading and Texture Binding
Loads 3D volume data into a CUDA 3D array and binds it to a texture object for GPU access [S3, unofficial]. Steps include copying data dimensions to a device symbol `dataDim`, creating a 3D array with a `ushort` channel format, copying host data to the 3D array using `cudaMemcpy3D`, setting texture parameters to linear filter and clamp address mode, and binding the 3D array to a texture object `dataTex` [S3, unofficial].

## Operating characteristics
* Time Complexity: O(N) for data transfer, where N is the number of voxels [G]. Cache hit is O(1) [G].
* Memory Complexity: O(N) for the GPU texture storage [G].
* Performance: Depends on PCIe bandwidth for host-to-device transfer [G]. CUDA `cudaMemcpy3D` may offer optimized paths for aligned data [G].
* Strengths: Simple API, direct mapping to volume raycasting shaders [G].
* Limitations: Loads entire subextents; not suitable for extremely large volumes without tiling [G]. VRAM constrained [G].
* When to use: Small to medium volumes, or when subextents are fully enclosed in memory [G].
* When not to use: Volumes exceeding available VRAM, or when dynamic streaming of sparse data is required [G].

## Background
Used in scientific visualization and medical imaging applications requiring real-time volume rendering [G]. Developed alongside VTK's multi-volume raycasting implementations [S1, unofficial], raw binary loading for custom OpenGL/Cinder-based raycasters [S2, unofficial], and CUDA-based volume rendering pipelines [S3, unofficial].
