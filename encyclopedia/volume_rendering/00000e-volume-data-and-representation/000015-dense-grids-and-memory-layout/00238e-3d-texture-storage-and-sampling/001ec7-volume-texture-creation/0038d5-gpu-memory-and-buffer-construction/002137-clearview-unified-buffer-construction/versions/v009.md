# ClearView Unified Buffer Construction

Also called: ClearView Buffer Construction

## Overview
ClearView Unified Buffer Construction is a preprocessing technique that converts a hexahedral mesh (positions, connectivity, and scalar values) into four GPU-friendly texture buffers—vertices, edges, faces, and cellScalar—optimized for the ClearView volume rendering pipeline [S1, unofficial]. It differs from standard volume texture creation by explicitly encoding topological connectivity (faces and edges) alongside geometric data to support the pipeline's specific fragment-based shading and focus-control mechanisms [S1, unofficial].

## How it works
**Inputs:**
- Hexahedral mesh geometry: `positions` (array of floats, 3 per vertex), `connectivity` (array of integers, 8 per cell).
- Scalar field: `scalars` (array of floats, 1 per vertex).

**Outputs:**
- `vertexTex`: Texture containing vertex positions.
- `edgeTex`: Texture containing edge attributes and Level-of-Detail (LOD) factors.
- `facesTex`: Texture containing face vertex and edge indices.
- `cellScalarTex`: Texture containing average scalar values per face.

**Data Structures and Layouts:**
1.  **Edges Texture (`edgeTex`)**:
    -   Format: `RG32F` (two 32-bit floats per texel).
    -   Dimensions: Width and Height determined by `texDims(edgeCount)`.
    -   Layout: Linear index `linear = c * 12 + e` for cell `c` and edge `e`.
    -   Texel Index: `ti = (row * width + col) * 2`.
    -   Values: `edgesTex[ti]` stores the maximum scalar of the two endpoints; `edgesTex[ti+1]` stores the LOD factor.
2.  **Faces Texture (`facesTex`)**:
    -   Format: `RG32UI` (four 32-bit unsigned integers per texel).
    -   Dimensions: Width = 2, Height = `faceCount`.
    -   Layout: Two texels per face.
        -   Texel 0: Vertex indices `[v0, v1, v2, v3]`.
        -   Texel 1: Edge indices `[e0, e1, e2, e3]`.
    -   Linear Texel Index: `t0linear = faceId * 2 + 0`, `t1linear = faceId * 2 + 1`.
    -   Texel Index: `ti = (row * width + col) * 4`.
3.  **Cell Scalar Texture (`cellScalarTex`)**:
    -   Format: `R32F` (one 32-bit float per texel).
    -   Dimensions: Width and Height determined by `texDims(faceCount)`.
    -   Layout: One texel per face.
    -   Value: Average scalar of the cell.
4.  **Vertex Texture (`vertexTex`)**:
    -   Standard 3D position storage (details not explicitly defined in source, assumed standard position buffer).

**Algorithm Steps:**

1.  **Compute Scalar Range:**
    Calculate the global minimum and maximum of the scalar field to normalize values.
    $$ s_{min} = \min(\text{mesh.scalars}) $$
    $$ s_{max} = \max(\text{mesh.scalars}) $$
    $$ s_{range} = \max(s_{max} - s_{min}, 10^{-9}) $$

2.  **Compute Edge LOD:**
    For each cell, calculate the average scalar of its 8 corners, normalize it, and derive the LOD factor.
    $$ \text{cellScalarAvg} = \frac{\sum_{i=0}^{7} \text{scalars}[\text{corners}_i]}{8} $$
    $$ \text{normScalar} = \frac{\text{cellScalarAvg} - s_{min}}{s_{range}} $$
    $$ \text{edgeLod} = 1 - \text{normScalar} $$

3.  **Populate Edge Texture:**
    For each cell `c` and its 12 edges `e`:
    -   Identify the two vertices `pia` and `pib` connected by the edge.
    -   Calculate linear index: `linear = c * 12 + e`.
    -   Calculate row/col: `col = linear % width`, `row = floor(linear / width)`.
    -   Calculate texel index: `ti = (row * width + col) * 2`.
    -   Store values:
        $$ \text{edgesTex}[ti] = \max(\text{scalars}[pia], \text{scalars}[pib]) $$
        $$ \text{edgesTex}[ti+1] = \text{edgeLod} $$

4.  **Populate Face Texture:**
    For each cell `c` and its 6 faces `f`:
    -   Calculate face ID: `faceId = c * 6 + f`.
    -   Get face geometry: `face = HEX_FACES[f]`.
    -   Store vertex indices in Texel 0:
        $$ \text{facesTex}[ti+0..3] = [c*8 + \text{face.corners}[0], c*8 + \text{face.corners}[1], c*8 + \text{face.corners}[2], c*8 + \text{face.corners}[3]] $$
    -   Store edge indices in Texel 1:
        $$ \text{facesTex}[ti+4..7] = [c*12 + \text{face.edges}[0], c*12 + \text{face.edges}[1], c*12 + \text{face.edges}[2], c*12 + \text{face.edges}[3]] $$
    -   Note: `ti` is calculated based on the linear texel index `t0linear` or `t1linear` as described in the layout section.

5.  **Populate Cell Scalar Texture:**
    For each face (representing a cell's scalar contribution):
    -   Calculate linear index: `faceId = c * 6 + f`.
    -   Calculate row/col: `col = faceId % width`, `row = floor(faceId / width)`.
    -   Store value:
        $$ \text{cellScalarTex}[row * width + col] = \text{cellScalarAvg} $$

**Pseudocode:**

```python
def build_clearview_buffers(mesh):
    positions = mesh.positions
    scalars = mesh.scalars
    connectivity = mesh.connectivity # List of lists, each inner list has 8 vertex indices
    
    # 1. Compute Scalar Range
    s_min = min(scalars)
    s_max = max(scalars)
    s_range = max(s_max - s_min, 1e-9)
    
    num_cells = len(connectivity)
    num_faces = num_cells * 6
    num_edges = num_cells * 12
    
    # Helper for texture dimensions (power of 2 or next multiple)
    width, height = tex_dims(num_faces)
    edge_width, edge_height = tex_dims(num_edges)
    
    # Initialize textures
    # edgeTex: RG32F -> 2 floats per texel
    edge_tex = [0.0] * (edge_width * edge_height * 2)
    # facesTex: RG32UI -> 4 uints per texel
    faces_tex = [0] * (2 * num_faces * 4) # 2 texels per face, 4 components per texel
    # cellScalarTex: R32F -> 1 float per texel
    cell_scalar_tex = [0.0] * (width * height)
    
    # Predefined hexahedron face/edge mappings (0-5 faces, 0-11 edges)
    # This is a placeholder for the actual HEX_FACES constant
    hex_faces = get_hex_face_data() 
    
    for c in range(num_cells):
        cell_verts = connectivity[c]
        
        # 2. Compute Edge LOD for this cell
        cell_scalar_avg = sum(scalars[v] for v in cell_verts) / 8.0
        norm_scalar = (cell_scalar_avg - s_min) / s_range
        edge_lod = 1.0 - norm_scalar
        
        # 3. Populate Edge Texture
        for e in range(12):
            edge_data = hex_faces[e] # Contains edge vertices or indices? 
            # Based on notes: "Get face = HEX_FACES[f]" for faces. 
            # For edges, we need the two vertices connected by edge e in cell c.
            # Assuming hex_edges maps edge index to vertex indices relative to cell start
            edge_vertices = get_hex_edge_vertices(e)
            pia = cell_verts[edge_vertices[0]]
            pib = cell_verts[edge_vertices[1]]
            
            linear = c * 12 + e
            col = linear % edge_width
            row = linear // edge_width
            ti = (row * edge_width + col) * 2
            
            edge_tex[ti] = max(scalars[pia], scalars[pib])
            edge_tex[ti+1] = edge_lod
            
        # 4. Populate Face Texture
        for f in range(6):
            face_id = c * 6 + f
            face = hex_faces[f]
            
            # Vertex indices
            v_indices = [c * 8 + face.corners[i] for i in range(4)]
            # Edge indices
            e_indices = [c * 12 + face.edges[i] for i in range(4)]
            
            # Texel 0: Vertices
            t0_linear = face_id * 2 + 0
            t0_col = t0_linear % 2
            t0_row = t0_linear // 2
            t0_ti = (t0_row * 2 + t0_col) * 4
            faces_tex[t0_ti : t0_ti+4] = v_indices
            
            # Texel 1: Edges
            t1_linear = face_id * 2 + 1
            t1_col = t1_linear % 2
            t1_row = t1_linear // 2
            t1_ti = (t1_row * 2 + t1_col) * 4
            faces_tex[t1_ti : t1_ti+4] = e_indices
            
        # 5. Populate Cell Scalar Texture
        # One texel per face, but value is cell average
        for f in range(6):
            face_id = c * 6 + f
            col = face_id % width
            row = face_id // width
            cell_scalar_tex[row * width + col] = cell_scalar_avg
            
    return {
        'edgeTex': edge_tex,
        'facesTex': faces_tex,
        'cellScalarTex': cell_scalar_tex,
        'vertexTex': positions, # Assumed direct mapping
        'sMin': s_min,
        'sMax': s_max
    }
```

**Parameters:**
-   `s_range` minimum: `1e-9` (to prevent division by zero) [S1, unofficial].
-   `edgeLod` formula: `1 - normScalar` [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Division by Zero:** If `s_max == s_min`, `s_range` is clamped to `1e-9` [S1, unofficial].
-   **Texture Dimensions:** Width and height must be calculated using `texDims` to ensure proper alignment and addressing, typically rounding up to the next power of two or a multiple of 4/8 depending on GPU requirements [S1, unofficial].
-   **Index Mapping:** Correct mapping of local hexahedron face/edge indices to global cell indices is critical. Errors here lead to corrupted connectivity [S1, unofficial].

## Subtopics

### Device Volume Snapshot
-   **What it is:** A method for capturing the current state of a volume texture on the GPU and storing it as a snapshot.
-   **Difference:** Focuses on state capture and persistence rather than initial buffer construction from mesh data.
-   **When to choose:** When you need to save or transfer volume state between frames or contexts.
-   **Link:** [Device Volume Snapshot](2246-device-volume-snapshot.md)

### GPU Data Layout
-   **What it is:** General principles for organizing volume data in GPU memory for efficient access.
-   **Difference:** Provides general guidelines, whereas ClearView constructs a specific topological structure.
-   **When to choose:** For general volume rendering optimization.
-   **Link:** [GPU Data Layout](2469-gpu-data-layout.md)

### Volume Upload via Staging Buffer
-   **What it is:** A technique for transferring large volume data from host to device memory using staging buffers.
-   **Difference:** Focuses on the transfer mechanism, not the data structure transformation.
-   **When to choose:** When uploading large datasets from CPU to GPU.
-   **Link:** [Volume Upload via Staging Buffer](15388-volume-upload-via-staging-buffer.md)

## Operating characteristics
-   **Time Complexity:** Linear with respect to the number of cells, $O(N_c)$, as it iterates through each cell to compute scalars and populate textures [S1, unofficial].
-   **Memory Complexity:** Proportional to the number of faces and edges, $O(N_f + N_e)$, where $N_f = 6 N_c$ and $N_e = 12 N_c$ [S1, unofficial].
-   **Strengths:** Optimized for the ClearView pipeline's specific shading model; encodes connectivity explicitly for efficient fragment processing [S1, unofficial].
-   **Limitations:** Specific to hexahedral meshes; requires preprocessing step before rendering [S1, unofficial].
-   **When to use:** When using the ClearView rendering pipeline with hexahedral data [S1, unofficial].
-   **When not to use:** For tetrahedral meshes or non-hexahedral volumes [S1, unofficial].

## Background
The ClearView Unified Buffer Construction method originates from the `geresim-spike` project, an unofficial implementation of the ClearView volume rendering technique [S1, unofficial]. It was developed to support the pipeline's focus-control and context visualization features by providing efficient GPU-accessible data structures for hexahedral meshes [S1, unofficial].
