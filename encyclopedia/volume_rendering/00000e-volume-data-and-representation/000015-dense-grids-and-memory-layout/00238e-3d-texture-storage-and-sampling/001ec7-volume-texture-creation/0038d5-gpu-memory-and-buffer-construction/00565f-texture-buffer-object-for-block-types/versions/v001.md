# Texture Buffer Object for Block Types

Also called: Buffer Texture, TBO color lookup, Texture Buffer Object

## Overview
Texture Buffer Object (TBO) is a technique to reinterpret a buffer object as a texture using `glTexBuffer`, allowing direct memory access via texture sampling functions [S1, unofficial]. It is primarily used to store block type colors or voxel data in a TBO and bind it as a texture to allow shaders to look up values based on indices stored in vertex or voxel data [S2, unofficial]. This method avoids the padding waste (e.g., 3 bytes per `uint8_t` element) or manual packing required when using Shader Storage Buffer Objects (SSBO) or Uniform Buffer Objects (UBO) directly with small integer types [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Host-side data array (e.g., `uint8_t` block types or `float` color values) and OpenGL context (version 3.1+).
- **Output:** A GPU-accessible texture resource bound to a texture unit, readable in shaders via `texelFetch`.

**Data Structures:**
1.  **Host Data:**
    -   For block types: A struct or array of `uint8_t` elements. Example: `uint8_t data[16][16][16]` [S1, unofficial].
    -   For colors: An array of RGBA colors. Example: 5 colors, each 4 floats (R, G, B, A) [S2, unofficial].
2.  **GPU Buffer:**
    -   Bound to `GL_TEXTURE_BUFFER` target [S1, unofficial].
    -   Internal format matches host data type: `GL_R8UI` for `uint8_t` [S1, unofficial] or `GL_R32F` for floats [S2, unofficial]. Note: If storing RGBA colors in `GL_R32F`, the shader must interpret the single channel as a packed value or the implementation must support multi-component buffer textures (standard TBOs are typically single-component; for RGBA, `GL_RGBA32F` is used if supported, or the data is laid out as 4 separate TBOs or a single `GL_RGBA32F` buffer if the driver allows [S2, unofficial]).

**Numbered Steps:**
1.  **Generate Buffer:** Create a buffer object ID using `glGenBuffers` [S1, unofficial].
2.  **Bind Buffer:** Bind the buffer to `GL_TEXTURE_BUFFER` target using `glBindBuffer(GL_TEXTURE_BUFFER, buffer_id)` [S1, unofficial].
3.  **Upload Data:** Populate the buffer with host data using `glBufferData(GL_TEXTURE_BUFFER, size, data_pointer, usage)` [S1, unofficial].
4.  **Generate Texture:** Create a texture object ID using `glGenTextures` [S1, unofficial].
5.  **Bind Texture:** Bind the texture to `GL_TEXTURE_BUFFER` target using `glBindTexture(GL_TEXTURE_BUFFER, texture_id)` [S1, unofficial].
6.  **Link Buffer to Texture:** Call `glTexBuffer(GL_TEXTURE_BUFFER, internal_format, buffer_id)` to associate the buffer's memory with the texture [S1, unofficial].
7.  **Bind to Shader:** Bind the texture to a texture unit (e.g., unit 0) using `glActiveTexture(GL_TEXTURE0)` and `glBindTexture(GL_TEXTURE_BUFFER, texture_id)` [S2, unofficial].
8.  **Set Uniform:** Set the shader uniform (defined as `uniform samplerBuffer` or `uniform usamplerBuffer`) to the texture unit index [S1, unofficial].

**Formulas:**
-   **3D to 1D Coordinate Mapping:**
    To fetch a value at voxel coordinates $(x, y, z)$ from a 1D TBO, calculate the index $i$:
    $$ i = z \times (Y \times X) + y \times X + x $$
    Where $X, Y, Z$ are the dimensions of the volume [S1, unofficial].
    *Note:* This assumes C-style array layout `data[z][y][x]`. If the host uses `data[x][y][z]`, the formula must be flipped [S1, unofficial].

-   **Shader Fetch:**
    ```glsl
    // For uint8_t block types
    uint blockType = texelFetch(terrainData, i).r;
    
    // For float colors (if stored as single channel packed or RGBA if supported)
    vec4 color = texelFetch(colorTBO, i);
    ```

**Parameters:**
-   **OpenGL Version:** 3.1 or higher [S1, unofficial].
-   **Internal Format:** `GL_R8UI` for `uint8_t` [S1, unofficial], `GL_R32F` for floats [S2, unofficial].

**Edge Cases and Pitfalls:**
-   **Coordinate Mapping:** Incorrect 3D-to-1D mapping leads to flipped or scrambled data. Ensure the host array layout matches the indexing formula [S1, unofficial].
-   **Precision:** Using `uint8_t` with `GL_R8UI` preserves exact integer values, avoiding the precision loss or padding waste of SSBO/UBO [S1, unofficial].
-   **RGBA Storage:** Standard `GL_TEXTURE_BUFFER` is typically single-component. Storing RGBA colors requires either `GL_RGBA32F` (if supported by the implementation for buffer textures) or splitting into multiple TBOs [S2, unofficial].

**Pseudocode:**
```python
# Host-side setup (C++/Python-like pseudocode)

def setup_tbo_for_block_types(data_3d, width, height, depth):
    """
    data_3d: 3D array of uint8_t (shape: [depth, height, width])
    width, height, depth: dimensions of the volume
    """
    # 1. Generate Buffer
    buffer_id = glGenBuffers(1)
    
    # 2. Bind Buffer
    glBindBuffer(GL_TEXTURE_BUFFER, buffer_id)
    
    # 3. Upload Data
    # Calculate total size: width * height * depth bytes
    size = width * height * depth
    glBufferData(GL_TEXTURE_BUFFER, size, data_3d, GL_STATIC_DRAW)
    
    # 4. Generate Texture
    texture_id = glGenTextures(1)
    
    # 5. Bind Texture
    glBindTexture(GL_TEXTURE_BUFFER, texture_id)
    
    # 6. Link Buffer to Texture
    # Format: GL_R8UI for uint8_t
    glTexBuffer(GL_TEXTURE_BUFFER, GL_R8UI, buffer_id)
    
    # 7. Bind to Shader
    glActiveTexture(GL_TEXTURE0)
    glBindTexture(GL_TEXTURE_BUFFER, texture_id)
    
    # 8. Set Uniform (assuming shader uniform 'terrainData' is bound to unit 0)

    return texture_id
```

## Subtopics

### Shader Storage Buffer Object (SSBO)
A mechanism to send large arrays of data (like voxel block types) to shaders, treating the data like texture data rather than uniform data [S1, unofficial]. It uses `layout(std430, binding = 0) buffer` in GLSL and requires OpenGL 4.3+ [S1, unofficial]. Updating data requires rebinding the SSBO and calling `glBufferData` again [S1, unofficial]. Unlike TBO, SSBO does not have the padding efficiency for `uint8_t` unless manually packed [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** Fetching a value is $O(1)$ via `texelFetch` [S1, unofficial].
-   **Memory Complexity:** Memory usage is proportional to the number of elements, with no padding waste for `uint8_t` when using `GL_R8UI` [S1, unofficial].
-   **Performance:** TBOs are efficient for read-only access patterns where data is accessed via texture coordinates or indices [S1, unofficial]. They avoid the overhead of uniform buffer limits (65KB) [S1, unofficial].
-   **Strengths:** Available since OpenGL 3.1, efficient for small integer types, no padding waste [S1, unofficial].
-   **Limitations:** Read-only access (cannot be written to from shaders), single-component limitation for standard buffer textures (requires workarounds for RGBA) [S2, unofficial].
-   **When to Use:** When storing block types or small integer data that needs to be accessed via texture sampling functions, especially on older hardware (OpenGL 3.1-4.2) [S1, unofficial].
-   **When Not to Use:** When write access from shaders is required (use SSBO) or when RGBA data is needed and the implementation does not support multi-component buffer textures [S2, unofficial].

## Background
The Texture Buffer Object (TBO) technique was introduced in OpenGL 3.1 [S1, unofficial]. It allows buffer objects to be accessed as textures, providing a way to use texture sampling functions for buffer data. This is particularly useful for volume rendering where voxel data (e.g., block types) needs to be looked up efficiently [S1, unofficial]. The method is often compared to SSBO, which was introduced in OpenGL 4.3 and offers more flexibility but requires newer hardware [S1, unofficial].
