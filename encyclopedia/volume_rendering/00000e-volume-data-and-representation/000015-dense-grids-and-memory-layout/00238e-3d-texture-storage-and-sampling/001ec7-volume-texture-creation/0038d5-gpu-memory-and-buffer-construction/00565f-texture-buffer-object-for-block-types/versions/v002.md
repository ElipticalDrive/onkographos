# Texture Buffer Object for Block Types

Also called: Buffer Texture, TBO, Texture Buffer Object, TBO color lookup

## Overview
Texture Buffer Object (TBO) is a technique to reinterpret a buffer object as a texture using `glTexBuffer`, allowing direct memory access via texture sampling functions [S1, unofficial]. It is primarily used to store block type colors or voxel data in a TBO and bind it as a texture to allow shaders to look up values based on indices stored in vertex or voxel data [S2, unofficial]. This method avoids the padding waste (e.g., 3 bytes per `uint8_t` element) or manual packing required when using Shader Storage Buffer Objects (SSBO) or Uniform Buffer Objects (UBO) directly with small integer types [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Host-side data array (e.g., `uint8_t` block types or `float` color values) and an OpenGL context (version 3.1 or higher) [S1, S2, unofficial].
- **Output:** A GPU-accessible texture resource bound to a texture unit, readable in shaders via `texelFetch` [S1, S2, unofficial].

**Data Structures:**
1.  **Host Data:**
    -   For block types: A struct or array of `uint8_t` elements, e.g., `uint8_t data[16][16][16]` [S1, unofficial].
    -   For colors: An array of RGBA colors, e.g., 5 colors each stored as 4 floats [S2, unofficial].
2.  **GPU Buffer:**
    -   Bound to the `GL_TEXTURE_BUFFER` target [S1, unofficial].
    -   Internal format matches host data type: `GL_R8UI` for `uint8_t` [S1, unofficial] or `GL_R32F` for floats [S2, unofficial]. The TBO stores colors as a single-channel `GL_R32F` buffer where the shader interprets the fetched value as a packed RGBA representation [S2, unofficial].

**Numbered Steps:**
1.  Generate a buffer object ID [S1, unofficial].
2.  Bind the buffer to the `GL_TEXTURE_BUFFER` target [S1, unofficial].
3.  Upload host data to the buffer using a buffer data allocation call [S1, unofficial].
4.  Generate a texture object ID [S1, unofficial].
5.  Bind the texture to the `GL_TEXTURE_BUFFER` target [S1, unofficial].
6.  Link the buffer to the texture using `glTexBuffer` with the appropriate internal format (e.g., `GL_R8UI` or `GL_R32F`) [S1, S2, unofficial].
7.  Bind the texture to a texture unit (e.g., unit 0) [S2, unofficial].
8.  Set the shader uniform (defined as `samplerBuffer` or `usamplerBuffer`) to the texture unit index [S1, S2, unofficial].

**Formulas:**
-   **3D to 1D Coordinate Mapping:**
    To fetch a value at voxel coordinates $(x, y, z)$ from a 1D TBO, calculate the index $i$:
    $$ i = z \times (Y \times X) + y \times X + x $$
    Where $X, Y, Z$ are the dimensions of the volume [S1, unofficial].
    This assumes C-style array layout `data[z][y][x]`. If the host uses `data[x][y][z]`, the formula must be flipped [S1, unofficial].

-   **Shader Fetch:**
    ```glsl
    // For uint8_t block types
    uint blockType = texelFetch(terrainData, i).r;
    
    // For float colors
    vec4 color = texelFetch(colorTBO, i);
    ```

**Parameters:**
-   **OpenGL Version:** 3.1 or higher [S1, unofficial].
-   **Internal Format:** `GL_R8UI` for `uint8_t` [S1, unofficial], `GL_R32F` for floats [S2, unofficial].

**Edge Cases and Pitfalls:**
-   **Coordinate Mapping:** Incorrect 3D-to-1D mapping leads to flipped or scrambled data. Ensure the host array layout matches the indexing formula [S1, unofficial].
-   **Precision:** Using `uint8_t` with `GL_R8UI` preserves exact integer values, avoiding the padding waste of SSBO/UBO [S1, unofficial].
-   **RGBA Storage:** Standard `GL_TEXTURE_BUFFER` is typically single-component. The evidence describes using `GL_R32F` to store RGBA colors in a single TBO, where the shader interprets the single channel as a packed value [S2, unofficial].

**Pseudocode:**
```python
# Standard OpenGL constants (representing standard operation values)
GL_TEXTURE_BUFFER = 0x8C2A
GL_R8UI = 0x8232
GL_STATIC_DRAW = 0x88E0
GL_TEXTURE0 = 0x84C0

def glGen_buffers(count): return [0] * count
def glBind_buffer(target, id): pass
def gl_buffer_data(target, size, data, usage): pass
def glGen_textures(count): return [0] * count
def glBind_texture(target, id): pass
def glTexBuffer(target, fmt, buffer_id): pass
def glActiveTexture(unit): pass
def glUniform1i(loc, val): pass
def glGetUniformLocation(program, name): return 0

def setup_tbo_for_block_types(data_3d, width, height, depth):
    """
    data_3d: 3D array of uint8_t (shape: [depth, height, width])
    width, height, depth: dimensions of the volume
    """
    # 1. Generate Buffer
    buffer_id = glGen_buffers(1)[0]
    
    # 2. Bind Buffer
    glBind_buffer(GL_TEXTURE_BUFFER, buffer_id)
    
    # 3. Upload Data
    size = width * height * depth
    gl_buffer_data(GL_TEXTURE_BUFFER, size, data_3d, GL_STATIC_DRAW)
    
    # 4. Generate Texture
    texture_id = glGen_textures(1)[0]
    
    # 5. Bind Texture
    glBind_texture(GL_TEXTURE_BUFFER, texture_id)
    
    # 6. Link Buffer to Texture
    glTexBuffer(GL_TEXTURE_BUFFER, GL_R8UI, buffer_id)
    
    # 7. Bind to Shader
    glActiveTexture(GL_TEXTURE0)
    glBind_texture(GL_TEXTURE_BUFFER, texture_id)
    
    # 8. Set Uniform
    glUniform1i(glGetUniformLocation(program, "terrainData"), 0)
    
    return texture_id

def fetch_block_type_index(voxel_x, voxel_y, voxel_z, width, height, depth):
    """
    Calculates the 1D index for a 3D voxel coordinate.
    Assumes C-style layout data[z][y][x].
    """
    index = voxel_z * (height * width) + voxel_y * width + voxel_x
    return index
```

## Subtopics

### Shader Storage Buffer Object (SSBO)
A mechanism to send large arrays of data (like voxel block types) to shaders, treating the data like texture data rather than uniform data [S1, unofficial]. It uses `layout(std430, binding = 0) buffer` in GLSL and requires OpenGL 4.3 or higher [S1, unofficial]. Updating data requires rebinding the SSBO and calling `glBufferData` again [S1, unofficial]. Unlike TBO, SSBO does not have the padding efficiency for `uint8_t` unless manually packed [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** Fetching a value is $O(1)$ via `texelFetch` [S1, unofficial].
-   **Memory Complexity:** Memory usage is proportional to the number of elements, with no padding waste for `uint8_t` when using `GL_R8UI` [S1, unofficial].
-   **Performance:** TBOs are efficient for read-only access patterns where data is accessed via texture coordinates or indices [S1, unofficial]. They avoid the overhead of uniform buffer limits (65KB) [S1, unofficial].
-   **Strengths:** Available since OpenGL 3.1, efficient for small integer types, no padding waste [S1, unofficial].
-   **Limitations:** Read-only access (cannot be written to from shaders) [S1, unofficial]. Standard buffer textures are typically single-component, requiring specific shader interpretation for multi-component data like RGBA [S2, unofficial].
-   **When to Use:** When storing block types or small integer data that needs to be accessed via texture sampling functions, especially on older hardware (OpenGL 3.1+) [S1, unofficial].
-   **When Not to Use:** When write access from shaders is required (use SSBO) [S1, unofficial].

## Background
The Texture Buffer Object (TBO) technique was introduced in OpenGL 3.1 [S1, unofficial]. It allows buffer objects to be accessed as textures, providing a way to use texture sampling functions for buffer data [S1, unofficial]. This is particularly useful for volume rendering where voxel data (e.g., block types) needs to be looked up efficiently [S1, unofficial]. The method is presented as an alternative to SSBO for older hardware, as SSBO requires OpenGL 4.3 or higher [S1, unofficial].
