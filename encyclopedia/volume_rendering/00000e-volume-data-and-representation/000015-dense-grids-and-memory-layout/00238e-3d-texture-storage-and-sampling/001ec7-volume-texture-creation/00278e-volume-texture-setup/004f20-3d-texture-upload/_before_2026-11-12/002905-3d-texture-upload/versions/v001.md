# 3D Texture Upload

Also called: 3D Texture Upload for Volume Data, GL_TEXTURE_3D volume upload, Volume Texture Binding

## Overview
This method transfers classified volume data from host memory to GPU memory by populating an OpenGL `GL_TEXTURE_3D` object. It solves the problem of preparing dense voxel grids for GPU-accelerated raycasting or slicing by ensuring correct memory layout, alignment, and filtering parameters. It differs from raw buffer uploads by utilizing texture hardware for interpolation and coordinate transformation, and from compression methods by storing uncompressed RGBA or single-channel data for immediate sampling [S1, S2, unofficial].

## How it works
**Inputs:**
- Classified volume data: A contiguous block of memory containing voxel values. Typically `GL_RGBA` (4 bytes per voxel) or `GL_RED` (1 byte per voxel) [S1, S2, unofficial].
- Dimensions: Width ($W$), Height ($H$), Depth ($D$) [S1, S2, unofficial].
- Source format: The native byte order of the host array [S3, unofficial].

**Outputs:**
- A bound OpenGL texture object (`GL_TEXTURE_3D`) ready for sampling in shaders [S1, S2, unofficial].

**Data Structures:**
1. **Host Buffer:**
   - If source is nested (e.g., `stack[x][y][z]`), it must be flattened into a 1D array [S3, unofficial].
   - Layout: $x$ is fastest varying, $y$ is middle, $z$ is slowest [S3, unofficial].
   - Stride: $stride_y = W$, $stride_z = W \times H$ [S3, unofficial].
   - Total size: $W \times H \times D$ bytes (for 8-bit data) [S2, S3, unofficial].
2. **GPU Texture:**
   - Target: `GL_TEXTURE_3D` [S1, S2, unofficial].
   - Internal Format: `GL_RGBA` (for classified RGBA data) [S1, unofficial] or `GL_R8` (for scalar density) [S2, unofficial].
   - Format: `GL_RGBA` [S1, unofficial] or `GL_RED` [S2, unofficial].
   - Type: `GL_UNSIGNED_BYTE` [S1, S2, unofficial].

**Steps:**
1. **Generate and Bind:** Generate a texture ID and bind it to `GL_TEXTURE_3D` [S1, unofficial].
2. **Set Wrapping:** Configure wrap modes for S, T, and R coordinates.
   - Option A: `GL_CLAMP` [S1, unofficial].
   - Option B: `GL_CLAMP_TO_EDGE` [S2, unofficial].
3. **Set Filtering:**
   - Option A: Magnification `GL_LINEAR`, Minification `GL_LINEAR_MIPMAP_LINEAR` [S1, unofficial].
   - Option B: Magnification `GL_LINEAR`, Minification `GL_LINEAR` [S2, unofficial].
4. **Set Mipmap Levels:**
   - Option A: Base level 0, Max level 4 [S1, unofficial].
   - Option B: Not explicitly set in the snippet, but implied by filter choice [S2, unofficial].
5. **Set Unpack Alignment:** Set `GL_UNPACK_ALIGNMENT` to 1 to match the host array's byte alignment (critical for non-4-byte aligned rows) [S2, unofficial].
6. **Upload Data:** Call `glTexImage3D` with the dimensions and data pointer [S1, S2, unofficial].
7. **Generate Mipmaps (Optional):** If minification filter requires mipmaps, call `glGenerateMipmap` [S1, unofficial].

**Pseudocode:**
```python
def upload_volume_texture(gl, data, width, height, depth, internal_format, format, type_enum, use_mipmaps=False):
    # 1. Generate and bind texture
    tex_id = gl.glGenTextures(1)
    gl.glBindTexture(gl.GL_TEXTURE_3D, tex_id)

    # 2. Set wrapping modes
    # Source [S1, unofficial] uses GL_CLAMP; Source [S2, unofficial] uses GL_CLAMP_TO_EDGE.
    # Implementation choice: GL_CLAMP_TO_EDGE is generally safer for volume edges.
    gl.glTexParameteri(gl.GL_TEXTURE_3D, gl.GL_TEXTURE_WRAP_S, gl.GL_CLAMP_TO_EDGE)
    gl.glTexParameteri(gl.GL_TEXTURE_3D, gl.GL_TEXTURE_WRAP_T, gl.GL_CLAMP_TO_EDGE)
    gl.glTexParameteri(gl.GL_TEXTURE_3D, gl.GL_TEXTURE_WRAP_R, gl.GL_CLAMP_TO_EDGE)

    # 3. Set filtering
    # Source [S1, unofficial] uses GL_LINEAR_MIPMAP_LINEAR; Source [S2, unofficial] uses GL_LINEAR.
    gl.glTexParameteri(gl.GL_TEXTURE_3D, gl.GL_TEXTURE_MIN_FILTER, gl.GL_LINEAR)
    gl.glTexParameteri(gl.GL_TEXTURE_3D, gl.GL_TEXTURE_MAG_FILTER, gl.GL_LINEAR)

    # 4. Set unpack alignment
    # Critical for 1-byte or non-4-byte aligned data [S2, unofficial]
    gl.glPixelStorei(gl.GL_UNPACK_ALIGNMENT, 1)

    # 5. Upload data
    # internal_format: GL_RGBA [S1, unofficial] or GL_R8 [S2, unofficial]
    # format: GL_RGBA [S1, unofficial] or GL_RED [S2, unofficial]
    # type: GL_UNSIGNED_BYTE [S1, S2, unofficial]
    gl.glTexImage3D(
        gl.GL_TEXTURE_3D,
        0,                  # level
        internal_format,    # internalformat
        width,              # width
        height,             # height
        depth,              # depth
        0,                  # border
        format,             # format
        type_enum,          # type
        data                # pixels
    )

    # 6. Generate mipmaps if required
    if use_mipmaps:
        gl.glGenerateMipmap(gl.GL_TEXTURE_3D)

    return tex_id
```

**Parameters:**
- `width`, `height`, `depth`: Dimensions of the volume grid. Typical example: $200 \times 200 \times 200$ [S1, unofficial].
- `internal_format`: `GL_RGBA` for 4-channel classified data [S1, unofficial], `GL_R8` for single-channel scalar data [S2, unofficial].
- `format`: `GL_RGBA` [S1, unofficial], `GL_RED` [S2, unofficial].
- `type`: `GL_UNSIGNED_BYTE` [S1, S2, unofficial].
- `GL_UNPACK_ALIGNMENT`: Set to 1 for byte-aligned data [S2, unofficial].

**Edge Cases:**
- **Alignment:** If `GL_UNPACK_ALIGNMENT` is not set to 1 for 1-byte or 2-byte data, OpenGL may misinterpret row strides, causing visual artifacts [S2, unofficial].
- **Mipmap Consistency:** If `GL_LINEAR_MIPMAP_LINEAR` is used, mipmaps must be generated; otherwise, sampling may fail or return undefined values [S1, unofficial].
- **Data Flattening:** If the source data is a nested array (e.g., `stack[x][y][z]`), it must be flattened to a 1D buffer before upload. The memory order must be $x$-fastest, $y$-middle, $z$-slowest [S3, unofficial].

## Subtopics

### 3D Texture Upload — 3D Texture Upload for Volume Data, GL_TEXTURE_3D volume upload, Volume Texture Binding
This variant specifically addresses the host-side data preparation when the source volume is stored as a nested array structure (e.g., `stack[x][y][z]`) rather than a flat buffer. It involves converting the nested structure into a flat `Uint8Array` (or equivalent contiguous memory) with a specific memory layout: $x$ is the fastest varying index, $y$ is the middle, and $z$ is the slowest [S3, unofficial]. The output is a `Uint8Array` of length $W \times H \times D$, where $W = \text{stack.length}$, $H = \text{stack}[0].\text{length}$, and $D = \text{stack}[0][0].\text{length}$ [S3, unofficial]. This step is a prerequisite for the actual `glTexImage3D` call if the renderer does not handle nested arrays internally [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(W \times H \times D)$ for data flattening (if required) and upload [S3, unofficial]. The upload itself is a single GPU memory copy operation.
- **Memory Complexity:** $O(W \times H \times D)$ bytes on the host for the buffer, plus $O(W \times H \times D)$ bytes on the GPU for the texture [S2, unofficial].
- **Performance:** Upload speed is limited by PCIe bandwidth. For a $200^3$ RGBA texture, this is $8$ MB, which is negligible on modern hardware [S1, unofficial].
- **Strengths:** Hardware-accelerated interpolation and coordinate transformation; simple API [S1, S2, unofficial].
- **Limitations:** Mipmaps increase memory usage by ~33%; `GL_LINEAR_MIPMAP_LINEAR` requires mipmaps to be generated [S1, unofficial].

## Background
This method is standard in OpenGL-based volume rendering applications. It builds on [Volume Texture Setup](4055-volume-texture-setup.md) by performing the actual data transfer. The specific implementation details (e.g., `GL_CLAMP` vs `GL_CLAMP_TO_EDGE`, `GL_LINEAR` vs `GL_LINEAR_MIPMAP_LINEAR`) vary between implementations [S1, S2, unofficial].
