# Texture Streaming

Also called: GPUScaledTexture management, Vispy volume texture management

## Overview
Texture streaming renders 4D volumetric data (3D spatial dimensions plus time) when the total dataset exceeds available graphics memory [S2, unofficial]. It solves the memory constraint by allocating a single 3D texture and sequentially uploading individual timesteps from main memory to the GPU for each frame [S2, unofficial]. Unlike caching all timesteps in VRAM, this method trades increased CPU-GPU bus traffic for reduced graphics memory usage [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 4D array of volume data `pData` with dimensions `[numTimesteps][dimx][dimy][dimz]`, stored in main memory [S2, unofficial].
- Output: A rendered frame using the current timestep's volume data sampled from a bound 3D texture [S2, unofficial].

**Data Structures:**
- `texID`: A single OpenGL texture ID (`GLuint`) [S2, unofficial].
- `curTimeStep`: An integer index tracking the current frame's timestep, initialized to 0 [S2, unofficial].
- `numTimesteps`: The total number of timesteps in the dataset [S2, unofficial].
- `dimx, dimy, dimz`: The spatial dimensions of the volume [S2, unofficial].

**Parameters:**
- Texture target: `GL_TEXTURE_3D` [S2, unofficial].
- Internal format: `GL_INTENSITY` [S2, unofficial].
- Pixel format: `GL_LUMINANCE` [S2, unofficial].
- Pixel type: `GL_UNSIGNED_BYTE` [S2, unofficial].
- Texture parameters (wrap, filter): Set via `glTexParameteri` [S2, unofficial].

**Steps:**
1. **Initialization:** Allocate one 3D texture ID [S2, unofficial]. Bind the texture to `GL_TEXTURE_3D` [S2, unofficial]. Set texture parameters (wrap modes, filtering) using `glTexParameteri` [S2, unofficial]. Upload the first timestep (`pData[0]`) to the GPU using `glTexImage3D` to allocate texture storage [S2, unofficial]. Initialize `curTimeStep = 0` [S2, unofficial].
2. **Rendering Loop (per frame):** Increment `curTimeStep` and wrap it around: `curTimeStep = (curTimeStep + 1) % numTimesteps` [S2, unofficial]. Bind the texture to `GL_TEXTURE_3D` [S2, unofficial]. Upload the current timestep's data (`pData[curTimeStep]`) to the existing texture storage using `glTexSubImage3D`, which overwrites the previous timestep's data in place [S2, unofficial]. Execute the drawing code (ray marching or similar) which samples from the bound texture [S2, unofficial].

**Pseudocode:**
```python
# Standard OpenGL constants defined explicitly
GL_TEXTURE_3D = 3567
GL_TEXTURE_WRAP_S = 10242
GL_CLAMP_TO_EDGE = 33071
GL_TEXTURE_WRAP_T = 10243
GL_TEXTURE_WRAP_R = 32886
GL_TEXTURE_MIN_FILTER = 10241
GL_LINEAR = 9729
GL_TEXTURE_MAG_FILTER = 10240
GL_INTENSITY = 6408
GL_LUMINANCE = 6409
GL_UNSIGNED_BYTE = 5121

# Standard OpenGL operations implemented explicitly per rules
def allocate_texture_id(): return 1  # Standard: glGenTextures(1, &id)
def bind_texture(target, texture_id): pass  # Standard: glBindTexture(target, texture_id)
def set_texture_parameter(target, param, value): pass  # Standard: glTexParameteri(target, param, value)
def upload_texture_init(target, level, internal_format, width, height, depth, border, format, type, data): pass  # Standard: glTexImage3D(...)
def upload_texture_update(target, level, xoff, yoff, zoff, width, height, depth, format, type, data): pass  # Standard: glTexSubImage3D(...)

# Initialization
texID = allocate_texture_id()
bind_texture(GL_TEXTURE_3D, texID)
set_texture_parameter(GL_TEXTURE_3D, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE)
set_texture_parameter(GL_TEXTURE_3D, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE)
set_texture_parameter(GL_TEXTURE_3D, GL_TEXTURE_WRAP_R, GL_CLAMP_TO_EDGE)
set_texture_parameter(GL_TEXTURE_3D, GL_TEXTURE_MIN_FILTER, GL_LINEAR)
set_texture_parameter(GL_TEXTURE_3D, GL_TEXTURE_MAG_FILTER, GL_LINEAR)

# Upload first timestep
upload_texture_init(
    GL_TEXTURE_3D, 0, GL_INTENSITY,
    dimx, dimy, dimz, 0,
    GL_LUMINANCE, GL_UNSIGNED_BYTE,
    pData[0]
)
curTimeStep = 0

# Per-frame rendering
def render_frame(pData, numTimesteps, dimx, dimy, dimz):
    global curTimeStep
    curTimeStep = (curTimeStep + 1) % numTimesteps
    bind_texture(GL_TEXTURE_3D, texID)
    upload_texture_update(
        GL_TEXTURE_3D, 0, 0, 0, 0,
        dimx, dimy, dimz,
        GL_LUMINANCE, GL_UNSIGNED_BYTE,
        pData[curTimeStep]
    )
    draw_volume()
```

**Edge Cases and Pitfalls:**
- **Precision:** The example uses `GL_UNSIGNED_BYTE` and `GL_INTENSITY`, limiting data to 8-bit single-channel [S2, unofficial]. For higher precision or multi-channel data, formats must be adjusted, though multi-channel support requires shader modifications to expose multiple channels [S1, unofficial].
- **Performance:** The method involves a CPU `memcpy` and a `glTexSubImage3D` call per frame, creating a potential download bottleneck [S2, unofficial].
- **Multi-channel Data:** Precomputing results for custom functions across channel dimensions (e.g., for brainbow images with high color variability) is slow and inconvenient, requiring near-continuous precomputation [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per frame for texture upload, but dependent on the bandwidth of the CPU-GPU bus [S2, unofficial]. The cost is proportional to the size of one timestep's volume data [S2, unofficial].
- **Memory Complexity:** $O(V)$ where $V$ is the size of a single 3D volume, regardless of the number of timesteps [S2, unofficial]. This is significantly lower than caching all timesteps ($O(T \times V)$) [S2, unofficial].
- **Measured Performance:** Involves CPU `memcpy` and `glTexSubImage3D` calls for each frame, causing a download bottleneck [S2, unofficial].
- **Strengths:** Minimal graphics memory usage; suitable for large 4D datasets that do not fit in VRAM [S2, unofficial].
- **Limitations:** High CPU-GPU bus traffic; potential frame rate reduction due to data transfer latency; not suitable for real-time interaction if the transfer time exceeds the frame budget [S2, unofficial].
- **When to use:** When graphics memory is insufficient to hold all timesteps simultaneously, but the dataset fits in main RAM [S2, unofficial].
- **When not to use:** When low latency and high frame rates are critical, or when the dataset fits entirely in VRAM (caching is preferred) [S2, unofficial].

## Background
The technique is described in NVIDIA GTC 2009 slides as a method for handling 4D data when graphics memory is limited [S2, unofficial]. It is also referenced in the context of Vispy volume visual management, where `GPUScaledTexture` is used to manage single-channel 3D textures for volume rendering [S1, unofficial].
