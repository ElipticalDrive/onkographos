# CPU-GPU Hybrid Pipeline with Post-Packing Optimization

Also called: Greedy-based approach, Hybrid CPU-GPU Approach, Hybrid CPU-GPU Volume Rendering with Greedy Packing and Post-Packing Optimization, Proposed Greedy-based approach

## Overview
This method mitigates GPU memory bottlenecks in 3D texture mapping by using CPU pre-processing to pack non-empty voxels into memory-optimized 2D slices, followed by GPU rendering [S1][S2, unofficial]. It addresses the specific problem that directly applying 2D greedy packing to 3D textures causes memory inflation due to hardware constraints requiring uniform texture dimensions for all slices [S1][S2, unofficial]. Unlike linked-list sparse storage methods which suffer from pointer bloat at higher densities, this approach compacts isolated non-empty voxels into 2D texture slices, bypassing the severe padding waste of AMR structures and the decoding overheads of out-of-core streaming [S1][S2, unofficial].

## How it works
The pipeline consists of CPU-side preprocessing to identify, partition, and pack voxels, followed by GPU-side rendering with hardware-accelerated interpolation and LOD [S1][S2, unofficial].

### Inputs and Outputs
*   **Input:** Raw volume data (e.g., CT/MRI scalar fields), density threshold ($T_{density}$), sparsity threshold ($T_{sparsity}$) [S1][S2, unofficial].
*   **Output:** A packed 3D texture object uploaded to GPU memory, ready for rendering [S1][S2, unofficial].

### Data Structures
1.  **Seed Map:** A binary mask or list identifying "important" voxels based on the density threshold [S1][S2, unofficial].
2.  **Partitioned Sub-volumes (Bricks):** Groups of voxels generated by greedy partitioning [S1][S2, unofficial].
3.  **2D Texture Slices:** 2D arrays containing packed pixels from sub-volumes [S1][S2, unofficial].
4.  **3D Texture Object:** The final GPU resource formed by stacking uniform 2D slices [S1][S2, unofficial].

### Numbered Steps

1.  **Thresholding and Sparsity Evaluation:**
    *   Apply the density threshold $T_{density}$ to the input volume data to identify important voxels [S1][S2, unofficial].
    *   Generate a seed map defining these important voxels [S1][S2, unofficial].
    *   Evaluate dataset sparsity ($S$) based on the seed map [S1][S2, unofficial].

2.  **Strategy Selection (Sparse Check):**
    *   Compare sparsity $S$ against the defined sparsity threshold $T_{sparsity}$ [S1][S2, unofficial].
    *   **If $S > T_{sparsity}$:** Select the **Regular 2D packing** approach [S1][S2, unofficial]. Proceed to Step 5.
    *   **If $S \le T_{sparsity}$:** Select the **Greedy-based approach** [S1][S2, unofficial]. Proceed to Step 3.

3.  **Greedy Partitioning (Greedy-based only):**
    *   Perform greedy partitioning of the volume into sub-volumes or bricks [S1][S2, unofficial].
    *   The partitioning logic defines "profit" as the number of new seed voxels encompassed by an expansion versus the number of empty voxels [S1].
    *   Expansion continues until no further expansion yields positive profit [S1].

4.  **2D Packing and Post-Packing Optimization (Greedy-based only):**
    *   Apply 2D greedy packing to pack the partitioned sub-volumes into 2D texture slices [S1][S2, unofficial].
    *   **Post-Packing Optimization:** Analyze the initial greedy packing layout [S2, unofficial].
    *   Reorganize the partitioned textures into uniform size to satisfy 3D texture hardware constraints [S1][S2, unofficial].
    *   This step minimizes memory waste caused by irregular gaps that would otherwise require padding [S1][S2, unofficial].
    *   Stack the uniform slices [S1][S2, unofficial].

5.  **Regular 2D Packing (Regular approach only):**
    *   Apply standard 2D packing to pack the identified voxels into 2D slices [S1][S2, unofficial].
    *   Stack the slices [S1][S2, unofficial].

6.  **Mipmapping:**
    *   Apply a standard mipmapping strategy to the final retained textures [S1][S2, unofficial].
    *   Create a discrete Level of Detail (LOD) system using pre-computed, down-sampled versions of the texture atlas [S1][S2, unofficial].

7.  **Upload and Rendering:**
    *   Upload the packed 3D texture object to the GPU [S1][S2, unofficial].
    *   Offload interpolation and rendering tasks to the GPU [S1][S2, unofficial].
    *   During rendering, hardware automatically selects the appropriate resolution level based on the object's distance from the camera [S1][S2, unofficial].

### Parameters
*   **Density Threshold ($T_{density}$):** A configured value used to define important voxels and determine sparsity for strategy selection [S1][S2, unofficial].
*   **Sparsity Threshold ($T_{sparsity}$):** The threshold value compared against dataset sparsity to decide between Greedy-based and Regular 2D packing approaches [S1][S2, unofficial].
*   **Uniform Texture Dimensions:** Hardware constraint requiring all texture slices to match in size to form a valid 3D texture object [S1][S2, unofficial].

### Edge Cases and Pitfalls
*   **Memory Inflation:** Directly applying greedy packing to 3D textures introduces memory inflation due to hardware constraints requiring uniform texture dimensions [S1][S2, unofficial].
*   **Sparse Data Degradation:** The Greedy-based approach suffers from noticeable memory performance degradation when applied to sparse datasets [S1][S2, unofficial]. This is mitigated by the sparse check which bypasses greedy packing for such cases [S1][S2, unofficial].
*   **Pointer Bloat:** Unlike linked-list sparse storage (e.g., Kauker et al.), this method avoids pointer bloat and ~43% memory overhead that occurs at higher dataset densities (e.g., 34.6%) [S2, unofficial].

## Subtopics

### Regular 2D Packing
A simpler packing strategy used when dataset sparsity is high [S1][S2, unofficial]. It safeguards memory performance by detecting potential overhead early and bypassing the greedy pipeline [S1][S2, unofficial]. Choose it when sparsity exceeds the defined threshold to avoid greedy packing degradation [S1]. See [Regular 2D Packing](regular-2d-packing.md).

### Greedy Partitioning
The process of dividing the volume into sub-volumes based on seed voxels and profit metrics (new seed voxels vs. empty voxels) [S1]. Choose it for dense datasets where sparsity is below the threshold [S1]. See [Greedy Partitioning](greedy-partitioning.md).

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Scales with the number of packed 2D slices and the uniform 3D texture dimensions required by hardware [S1][S2, unofficial].
*   **Measured Performance:** Achieves an average 30.9% reduction in memory usage compared to the default 3D texture mapping baseline on medical imaging datasets (CT/MRI) [S1][S2, unofficial].
*   **Scaling:** Avoids the performance degradation seen in linked-list methods, which drop to 1.9 fps at 34.6% occupancy [S2, unofficial].
*   **Strengths:** Bypasses severe 3D texture padding waste of AMR structures and complex decoding overheads of out-of-core streaming [S1][S2, unofficial].
*   **Limitations:** Greedy approach is less effective on sparse datasets and requires CPU pre-processing time [S1][S2, unofficial].
*   **When to Use:** Dense CT/MRI medical imaging volume rendering where GPU memory is constrained [S1][S2, unofficial].
*   **When Not to Use:** Highly sparse datasets where the sparsity check triggers the Regular 2D packing fallback [S1][S2, unofficial].

## Background
This method was proposed by Wei-Ming Yang and Robert Sadleir from Dublin City University [S1][S2, unofficial]. It addresses limitations in existing volume rendering techniques, such as Shear-Warp (software-based, requires multiple volume copies) and empty-space skipping with linked lists (pointer bloat) [S1][S2, unofficial]. The approach builds on prior work in 2D greedy packing and adapts it for 3D texture mapping via a hybrid CPU-GPU pipeline [S1][S2, unofficial]. It is primarily used in CT/MRI medical imaging volume rendering [S1][S2, unofficial].
