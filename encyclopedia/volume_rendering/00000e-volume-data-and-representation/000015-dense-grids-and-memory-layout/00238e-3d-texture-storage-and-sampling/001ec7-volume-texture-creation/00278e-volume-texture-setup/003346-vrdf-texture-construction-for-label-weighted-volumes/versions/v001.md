# VRDF Texture Construction for Label-Weighted Volumes

Also called: BuildUnityTextures, Fused mode export, Labelmap Weighted 4D Export Strategy, Split mode export, anatomy_label_weighted texture setup

## Overview
This method constructs GPU-accessible 3D textures for Unity volume rendering when the input data is in 'anatomy_label_weighted' mode with 2 channels [S1, unofficial]. It separates discrete labels and continuous weights into distinct 3D textures with specific filtering modes to support weighted raymarching [S1, unofficial]. It serves as the runtime counterpart to the VRDF file export logic, ensuring that the label and weight data are sampled correctly for opacity modulation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A data structure `data` containing:
    *   `data.meta.mode`: String, must be `"anatomy_label_weighted"`.
    *   `data.meta.channels`: Integer, must be `2`.
    *   `data.meta.channel_meaning`: Array of strings `["labelmap", "weight01"]`.
    *   `data.labelData`: Raw label data (integers or floats representing discrete classes).
    *   `data.weightData`: Raw weight data (floats, normalized 0-1).
    *   `data.tf.type`: String, either `"labelmap"` or `"continuous"`.
    *   `data.tf`: Transfer function definition (if type is continuous).
    *   `dimX, dimY, dimZ`: Volume dimensions.
*   **Output:** Two Unity `Texture3D` objects (`_VolumeTexLabels`, `_VolumeTexWeights`) and optional LUT textures (`data.tfLUTTextureSoft`, `data.tfLUTTextureHard`).

**Data Structures:**
1.  **Label Texture:** `Texture3D` with format `RFloat`, dimensions `(dimX, dimY, dimZ)`, mipmaps `false`.
2.  **Weight Texture:** `Texture3D` with format `RFloat`, dimensions `(dimX, dimY, dimZ)`, mipmaps `false`.
3.  **LUT Textures:** `Texture3D` or `Texture2D` (implementation dependent for LUTs) generated by helper functions.

**Steps:**
1.  **Mode Check:** Verify `data.meta.mode == "anatomy_label_weighted"` and `data.meta.channels == 2`. If false, the method falls back to the legacy single-volume path (see [3D Texture Upload](4419-3d-texture-upload.md) for legacy details) [S1, unofficial].
2.  **Label Texture Creation:**
    *   Create a `Texture3D` object.
    *   Set dimensions to `(dimX, dimY, dimZ)`.
    *   Set format to `RFloat` (32-bit float, single channel) [S1, unofficial].
    *   Set `wrapMode` to `Clamp` [S1, unofficial].
    *   Set `filterMode` to `Point` (nearest neighbor) [S1, unofficial].
    *   Assign pixel data from `data.labelData`.
    *   Apply changes to the GPU [S1, unofficial].
3.  **Weight Texture Creation:**
    *   Create a `Texture3D` object.
    *   Set dimensions to `(dimX, dimY, dimZ)`.
    *   Set format to `RFloat` [S1, unofficial].
    *   Set `wrapMode` to `Clamp` [S1, unofficial].
    *   Set `filterMode` to `Bilinear` [S1, unofficial].
    *   Assign pixel data from `data.weightData`.
    *   Apply changes to the GPU [S1, unofficial].
4.  **Transfer Function LUT Generation:**
    *   If `data.tf.type == "labelmap"`: Call `BuildLabelmapLUTs(data)` to generate transfer function LUTs [S1, unofficial].
    *   If `data.tf.type == "continuous"`: Call `BuildContinuousLUT(data.tf)` and assign the result to `data.tfLUTTextureSoft`. Set `data.tfLUTTextureHard` to `null` [S1, unofficial].
    *   Otherwise: Set `data.tfLUTTextureSoft` and `data.tfLUTTextureHard` to `null` [S1, unofficial].

**Pseudocode:**
```python
def build_label_weighted_textures(data):
    # 1. Mode Check
    if data.meta.mode != "anatomy_label_weighted" or data.meta.channels != 2:
        # Fallback to legacy single-volume path
        return build_legacy_texture(data)

    dimX, dimY, dimZ = data.dimX, data.dimY, data.dimZ

    # 2. Label Texture Creation
    # Create Texture3D for labels
    label_tex = create_texture3d(
        width=dimX,
        height=dimY,
        depth=dimZ,
        format="RFloat",
        mipmaps=False
    )
    label_tex.wrap_mode = "Clamp"
    label_tex.filter_mode = "Point" # Nearest neighbor
    label_tex.set_pixel_data(data.labelData)
    label_tex.apply()

    # 3. Weight Texture Creation
    # Create Texture3D for weights
    weight_tex = create_texture3d(
        width=dimX,
        height=dimY,
        depth=dimZ,
        format="RFloat",
        mipmaps=False
    )
    weight_tex.wrap_mode = "Clamp"
    weight_tex.filter_mode = "Bilinear"
    weight_tex.set_pixel_data(data.weightData)
    weight_tex.apply()

    # 4. Transfer Function LUT Generation
    if data.tf.type == "labelmap":
        data.tfLUTTextureSoft, data.tfLUTTextureHard = build_labelmap_luts(data)
    elif data.tf.type == "continuous":
        data.tfLUTTextureSoft = build_continuous_lut(data.tf)
        data.tfLUTTextureHard = None
    else:
        data.tfLUTTextureSoft = None
        data.tfLUTTextureHard = None

    return label_tex, weight_tex
```

**Parameters:**
*   `meta.mode`: `"anatomy_label_weighted"` [S1, unofficial].
*   `meta.channels`: `2` [S1, unofficial].
*   `meta.channel_meaning`: `["labelmap", "weight01"]` [S1, unofficial].
*   `TF type`: `"labelmap"` or `"continuous"` [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Labels are stored in `RFloat` but represent discrete integers. Using `Point` filtering prevents interpolation artifacts between label classes [S1, unofficial].
*   **Weight Normalization:** Weights are expected to be in the range [0, 1]. If raw data is not normalized, bilinear sampling may produce values outside this range, affecting opacity modulation [S1, unofficial].
*   **Legacy Mode:** If the mode check fails, the method must correctly delegate to the legacy path to avoid rendering errors [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** O(N) where N is the number of voxels, for texture upload. LUT generation is O(C) where C is the number of classes or curve points.
*   **Memory Complexity:** O(N) for the two 3D textures (labels and weights). Additional memory for LUTs.
*   **Performance:** Point sampling for labels is fast and avoids interpolation artifacts. Bilinear sampling for weights allows smooth opacity transitions.
*   **Strengths:** Separates discrete and continuous data for optimal sampling. Supports weighted tumor rendering via opacity modulation [S1, unofficial].
*   **Limitations:** Requires specific input format (`anatomy_label_weighted`). Not suitable for general 4D volumes without modification.

## Background
This method is part of the VRDF SDK ecosystem for Unity volume rendering [S1, unofficial]. It addresses the need to handle label-weighted volumes, where discrete anatomical labels are modulated by continuous weight values (e.g., tumor confidence) [S1, unofficial]. The approach is derived from the VRDF file format specification, which supports fused and split modes for label-weighted data [S1, unofficial].
