# VRDF Texture Construction for Label-Weighted Volumes

Also called: BuildUnityTextures, Fused mode export, Labelmap Weighted 4D Export Strategy, Split mode export, anatomy_label_weighted texture setup

## Overview
This method constructs GPU-accessible 3D textures for Unity volume rendering when the input data is in 'anatomy_label_weighted' mode with 2 channels [S1, unofficial]. It separates discrete labels and continuous weights into distinct 3D textures with specific filtering modes to support weighted raymarching [S1, unofficial]. It serves as the runtime counterpart to the VRDF file export logic, ensuring that the label and weight data are sampled correctly for opacity modulation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A data structure `data` containing `meta.mode` (string `"anatomy_label_weighted"`), `meta.channels` (integer `2`), `meta.channel_meaning` (array `["labelmap", "weight01"]`), `labelData` (raw discrete class values), `weightData` (raw continuous values), `tf.type` (string `"labelmap"` or `"continuous"`), `tf` (transfer function definition), and volume dimensions `dimX`, `dimY`, `dimZ` [S1, unofficial].
*   **Output:** Two Unity `Texture3D` objects (`_VolumeTexLabels`, `_VolumeTexWeights`) and optional LUT textures (`data.tfLUTTextureSoft`, `data.tfLUTTextureHard`) [S1, unofficial].

**Data Structures:**
1.  **Label Texture:** `Texture3D` with format `RFloat`, dimensions `(dimX, dimY, dimZ)`, and `mipmaps=false` [S1, unofficial].
2.  **Weight Texture:** `Texture3D` with format `RFloat`, dimensions `(dimX, dimY, dimZ)`, and `mipmaps=false` [S1, unofficial].
3.  **LUT Textures:** `Texture3D` or `Texture2D` objects generated by helper functions based on the transfer function type [S1, unofficial].

**Steps:**
1.  **Mode Check:** Verify `data.meta.mode == "anatomy_label_weighted"` and `data.meta.channels == 2` [S1, unofficial]. If false, the method falls back to the legacy single-volume path [S1, unofficial].
2.  **Label Texture Creation:** Create a `Texture3D` object with dimensions `(dimX, dimY, dimZ)` and format `RFloat` [S1, unofficial]. Set `wrapMode` to `Clamp` and `filterMode` to `Point` (nearest neighbor) [S1, unofficial]. Assign pixel data from `data.labelData` and apply the texture [S1, unofficial].
3.  **Weight Texture Creation:** Create a `Texture3D` object with dimensions `(dimX, dimY, dimZ)` and format `RFloat` [S1, unofficial]. Set `wrapMode` to `Clamp` and `filterMode` to `Bilinear` [S1, unofficial]. Assign pixel data from `data.weightData` and apply the texture [S1, unofficial].
4.  **Transfer Function LUT Generation:** If `data.tf.type == "labelmap"`, call `BuildLabelmapLUTs(data)` to generate transfer function LUTs [S1, unofficial]. If `data.tf.type == "continuous"`, call `BuildContinuousLUT(data.tf)` and assign the result to `data.tfLUTTextureSoft` while setting `data.tfLUTTextureHard` to `null` [S1, unofficial]. Otherwise, set both LUT textures to `null` [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Labels are stored in `RFloat` format but represent discrete integers [S1, unofficial]. Using `Point` filtering prevents interpolation artifacts between label classes [S1, unofficial].
*   **Weight Normalization:** Weights are normalized to the range [0, 1] [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** O(N) where N is the number of voxels for texture upload, and O(C) where C is the number of classes or curve points for LUT generation [S1, unofficial].
*   **Memory Complexity:** O(N) for the two 3D textures (labels and weights), plus additional memory for LUTs [S1, unofficial].
*   **Performance:** Point sampling for labels is fast and avoids interpolation artifacts, while bilinear sampling for weights allows smooth opacity transitions [S1, unofficial].
*   **Strengths:** Separates discrete and continuous data for optimal sampling and supports weighted tumor rendering via opacity modulation [S1, unofficial].
*   **Limitations:** Requires the specific `anatomy_label_weighted` input format and is not suitable for general 4D volumes without modification [S1, unofficial].

## Background
This method is part of the VRDF SDK ecosystem for Unity volume rendering [S1, unofficial]. It addresses the need to handle label-weighted volumes where discrete anatomical labels are modulated by continuous weight values such as tumor confidence [S1, unofficial]. The approach is derived from the VRDF file format specification which supports fused and split modes for label-weighted data [S1, unofficial].
