# Voxel Volume Initialization & Binding

Also called: VoxelVolume Setup

## Overview
Voxel Volume Initialization & Binding allocates GPU memory for a dense 3D texture, configures sampling parameters, and establishes read/write bindings for compute shaders [S1, unofficial]. It prepares a structured, mipmapped voxel grid for subsequent lighting passes [G]. Unlike [3D Texture Upload](4419-3d-texture-upload.md), which focuses on data transfer, this method manages the OpenGL resource lifecycle and binding state [G]. It differs from [Sparse Volume Texture Setup](7432-sparse-volume-texture-setup.md) by using a dense `GL_TEXTURE_3D` with fixed dimensions rather than sparse binding extensions [G].

## How it works
**Inputs:**
- `volumeSize`: Integer defining the cubic resolution (N × N × N) [S1, unofficial].
- `volumeMipmapLevel`: Integer specifying the target mip level for subsequent operations [S1, unofficial].
- `minVertex`, `maxVertex`: Bounding box coordinates passed as shader attributes [S1, unofficial].

**Outputs:**
- Bound 3D texture resource (`_volumeTexture`) [S1, unofficial].
- Framebuffer Object (FBO) with the texture attached [S1, unofficial].
- Image load/store binding for write access [S1, unofficial].
- Texture unit binding for read access [S1, unofficial].

**Data Structures:**
- `_volumeTexture`: OpenGL handle for `GL_TEXTURE_3D` [S1, unofficial].
- Internal format: `GL_RGBA8` (8-bit unsigned integer per channel, normalized) [S1, unofficial].
- Dimensions: `volumeSize` × `volumeSize` × `volumeSize` [S1, unofficial].
- Border: 0 [S1, unofficial].

**Steps:**
1. Clear existing volume data and store the new `_volumeSize` [S1, unofficial].
2. Generate and bind a 3D texture (`GL_TEXTURE_3D`) with internal format `GL_RGBA8`, dimensions `volumeSize` × `volumeSize` × `volumeSize`, and no border [S1, unofficial].
3. Set texture parameters: min filter `GL_LINEAR_MIPMAP_LINEAR`, mag filter `GL_LINEAR`, and wrap modes `GL_CLAMP_TO_BORDER` for S, T, and R axes [S1, unofficial].
4. Generate mipmaps for the 3D texture [S1, unofficial].
5. Create an FBO, bind it, and attach the 3D texture to `GL_COLOR_ATTACHMENT0` [S1, unofficial].
6. Bind for writing using image load/store: `GL::BindImageTexture(0, _volumeTexture, 0, GL_FALSE, 0, GL_WRITE_ONLY, GL_RGBA8)` [S1, unofficial].
7. Bind for reading by activating texture unit 10 and binding the 3D texture [S1, unofficial].
8. Pass pipeline attributes to shaders: `volumeTexture` (ATTR_1I, value 10), `minVertex` (ATTR_3F), `maxVertex` (ATTR_3F), `volumeSize` (ATTR_3I), `volumeMipmapLevel` (ATTR_1I, read from settings) [S1, unofficial].

**Pseudocode:**
```python
def initialize_voxel_volume(volume_size, volume_mipmap_level, min_vertex, max_vertex):
    # 1. Clear existing data
    clear_existing_volume_data()
    _volume_size = volume_size

    # 2. Generate 3D Texture
    _volume_texture = create_texture_3d()
    bind_texture_3d(_volume_texture)
    allocate_texture_3d(
        internal_format="GL_RGBA8",
        width=volume_size,
        height=volume_size,
        depth=volume_size,
        border=0,
        data=None
    )

    # 3. Set Parameters
    set_texture_parameter(_volume_texture, "GL_TEXTURE_MIN_FILTER", "GL_LINEAR_MIPMAP_LINEAR")
    set_texture_parameter(_volume_texture, "GL_TEXTURE_MAG_FILTER", "GL_LINEAR")
    set_texture_parameter(_volume_texture, "GL_TEXTURE_WRAP_S", "GL_CLAMP_TO_BORDER")
    set_texture_parameter(_volume_texture, "GL_TEXTURE_WRAP_T", "GL_CLAMP_TO_BORDER")
    set_texture_parameter(_volume_texture, "GL_TEXTURE_WRAP_R", "GL_CLAMP_TO_BORDER")

    # 4. Generate Mipmaps
    generate_mipmaps(_volume_texture)

    # 5. FBO Setup
    fbo = create_framebuffer_object()
    bind_framebuffer_object(fbo)
    attach_texture_to_fbo(
        framebuffer=fbo,
        attachment_point="GL_COLOR_ATTACHMENT0",
        texture=_volume_texture,
        mipmap_level=0
    )

    # 6. Bind for Writing (Image Load/Store)
    bind_image_texture(
        binding_point=0,
        texture=_volume_texture,
        mipmap_level=0,
        layered=False,
        layer=0,
        access="GL_WRITE_ONLY",
        format="GL_RGBA8"
    )

    # 7. Bind for Reading
    activate_texture_unit(10)
    bind_texture_3d(_volume_texture)

    # 8. Set Shader Uniforms
    set_shader_uniform_1i("volumeTexture", 10)
    set_shader_uniform_3f("minVertex", min_vertex.x, min_vertex.y, min_vertex.z)
    set_shader_uniform_3f("maxVertex", max_vertex.x, max_vertex.y, max_vertex.z)
    set_shader_uniform_3i("volumeSize", volume_size, volume_size, volume_size)
    set_shader_uniform_1i("volumeMipmapLevel", volume_mipmap_level)

    unbind_framebuffer_object()
```

**Edge Cases and Pitfalls:**
- **Precision:** `GL_RGBA8` limits color precision to 256 levels per channel [G]. For high-dynamic-range lighting, this may cause banding [G]. Ensure the consumer shaders interpret the values correctly (normalized vs. raw) [G].
- **Boundaries:** `GL_CLAMP_TO_BORDER` requires a border color to be set if sampling outside the volume [G]. Set border color to `(0,0,0,0)` to ensure out-of-bounds samples return black/transparent [G].
- **Mipmap Levels:** If `volumeMipmapLevel` is requested but mipmaps are not generated, sampling may fail or return undefined data [G].

## Subtopics

### Voxel Border Pass
A compute-shader-based post-processing step that refines the voxel volume boundaries across mip levels [S1, unofficial]. It iterates through mip levels from 0 to `MIPMAP_LEVELS - 1` [S1, unofficial]. For each level, it retrieves the compute shader named `VOXEL_BORDER_PASS_COMPUTE_SHADER` and binds the VoxelVolume render volume for reading [S1, unofficial]. It sends custom attributes for the current shader and render volume, sets the source mip level uniform to the current loop index, and sets the destination mip resolution uniform to `dstMipRes` [S1, unofficial]. It binds the voxel volume for writing at the current mip level, calculates the number of work groups by dividing `dstMipRes` by 4.0 and taking the ceiling, and dispatches the compute shader with the calculated number of work groups for X, Y, and Z dimensions [S1, unofficial]. It inserts a memory barrier for texture fetch and shader image access, then halves the destination mip resolution for the next iteration [S1, unofficial]. After the loop, it inserts a memory barrier to ensure writing to the image has finished before reading [S1, unofficial].

## Operating characteristics
- **Time Complexity:** O(N^3) for texture allocation and mipmap generation, where N is `volumeSize` [G]. The border pass adds O(N^3) work across all mip levels [G].
- **Memory Complexity:** O(N^3) for the dense 3D texture storage [G]. `GL_RGBA8` uses 1 byte per channel, 4 bytes per voxel [G].
- **Performance:** Dependent on GPU memory bandwidth for texture allocation [G]. Mipmap generation is typically hardware-accelerated [G].
- **Strengths:** Simple API usage; standard OpenGL compatibility; efficient for dense volumes [G].
- **Limitations:** High memory usage for large N; no support for sparse data structures; fixed resolution [G].
- **When to use:** When the scene fits within memory limits and dense voxelization is required for cone tracing [G].
- **When not to use:** For very large scenes where memory is constrained; consider [Sparse Volume Texture Setup](7432-sparse-volume-texture-setup.md) instead [G].

## Background
Originated in the context of real-time voxel cone tracing implementations, specifically within the Voxel-Cone-Tracing project [S1, unofficial]. It provides the foundational GPU resource management for voxel-based global illumination [G].
