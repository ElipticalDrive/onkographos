# Dynamic Volume Texture Slice Rendering
Also called: Depth slice rendering, Rendering to Volume Texture Slices, Slice rendering
## Overview
Dynamic Volume Texture Slice Rendering is a technique for updating specific depth slices of a 3D volume texture by rendering into them individually using slice-specific render targets [S1, unofficial]. It solves the problem of dynamically updating volumetric data (such as fog or smoke) on the GPU by allowing fragment shaders to write directly into a chosen slice of a volume texture [S1, unofficial]. It differs from standard volume rendering by treating the volume texture as a collection of 2D slices that can be updated independently, rather than as a monolithic 3D buffer [S1, unofficial].
## How it works
### Inputs and Outputs
- **Input**: A 3D volume texture (created with `volume: true`) and a set of slice indices to update.
- **Output**: Updated color data in the specified depth slices of the volume texture.

### Data Structures
The method relies on the `RenderTarget` object with specific constructor options:
- `colorBuffer`: The 3D volume texture to render into.
- `slice`: A number specifying the depth slice index (0-based). Defaults to 0.
- `depth`: A boolean indicating whether to create a depth buffer. For volume textures, this must be a separate 2D texture.
- `mipLevel`: A number or `undefined`. If `undefined`, it triggers mipmap regeneration for the entire volume after the last slice is rendered.

### Steps
1. **Create Render Targets**: For each depth slice that needs updating, create a `RenderTarget` instance. All render targets must share the same `colorBuffer` (the volume texture) but specify a unique `slice` index [S1, unofficial].
2. **Configure Depth Buffer**: Since a volume texture cannot serve as a depth buffer, create a separate 2D texture to act as the depth buffer. This 2D depth buffer can be shared across all slice render targets [S1, unofficial].
3. **Render to Slices**: For each slice, bind the corresponding `RenderTarget` and execute the rendering pass. The fragment shader writes to the current depth slice [S1, unofficial].
4. **Handle Mipmaps**: If the volume texture has mipmaps enabled, they are regenerated for the entire volume after rendering to a slice because each mip level is filtered from multiple depth slices [S1, unofficial]. Set the `mipLevel` option to `undefined` for the last slice to trigger this regeneration [S1, unofficial].

### Pseudocode
```python
# Create a 3D volume texture with mipmaps enabled
volume_texture = Texture(
    device=device,
    width=128,
    height=128,
    depth=32,
    volume=True,
    mipmaps=True
)

# Create a shared 2D depth buffer
depth_buffer = Texture(
    device=device,
    width=128,
    height=128,
    format=FORMAT_DEPTH
)

render_targets = []
num_slices = 32

for slice_index in range(num_slices):
    # Determine if this is the last slice to trigger mipmap regeneration
    is_last_slice = (slice_index == num_slices - 1)
    
    # Create render target for the current slice
    rt = RenderTarget(
        colorBuffer=volume_texture,
        slice=slice_index,
        depthBuffer=depth_buffer,
        depth=True,
        mipLevel=0 if not is_last_slice else None  # None triggers regeneration
    )
    render_targets.append(rt)

# Render to each slice
for rt in render_targets:
    bind_render_target(rt)
    execute_render_pass()  # Shader writes to rt.slice

# Mipmaps are automatically regenerated after the last slice if mipLevel was None
```

### Parameters
- `RenderTarget.options.slice`: The depth slice index of the volume texture to render to. Defaults to 0 [S1, unofficial].
- `RenderTarget.options.mipLevel`: Set to `undefined` (or `None` in Python-like pseudocode) for the last slice to trigger mipmap regeneration [S1, unofficial].

### Edge Cases and Pitfalls
- **Multisampling**: Multisampling is not supported for volume textures because multisampled rendering cannot be resolved into a single depth slice on WebGPU. The `samples` option is ignored with a warning [S1, unofficial].
- **Depth Buffer**: A volume texture cannot serve as a depth buffer. A separate 2D texture must be used for depth testing [S1, unofficial].
- **Mipmap Regeneration**: Mipmaps are regenerated for the entire volume after rendering to a slice, not per-slice. This is because each mip level is filtered from multiple depth slices [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Not given in the sources.
- **Memory Complexity**: Not given in the sources.
- **Performance**: Not given in the sources.
- **Strengths**: Allows dynamic updates to volumetric data on the GPU for both WebGL2 and WebGPU backends [S1, unofficial].
- **Limitations**: Multisampling is not supported. Mipmap regeneration affects the entire volume, which may be costly for large textures [S1, unofficial].
- **When to use**: When dynamic volumetric effects (e.g., fog, smoke) need to be updated on the GPU.
- **When not to use**: When multisampling is required for the volume texture.

## Background
This method was introduced in the PlayCanvas engine via pull request #9697, which added support for rendering to depth slices of volume textures on both WebGL2 and WebGPU [S1, unofficial]. It also added mipmap generation for volume textures on WebGPU, which was previously unsupported [S1, unofficial]. The feature was developed to enable dynamic volumetric effects, such as fog, to be rendered on the GPU [S1, unofficial].
