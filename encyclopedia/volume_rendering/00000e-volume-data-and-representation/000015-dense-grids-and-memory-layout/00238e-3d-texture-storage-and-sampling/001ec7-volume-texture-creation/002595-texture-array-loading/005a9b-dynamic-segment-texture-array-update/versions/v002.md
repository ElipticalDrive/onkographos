# Dynamic Segment Texture Array Update

Also called: Segment Texture Array Update

## Overview
Dynamic Segment Texture Array Update is a method that rebuilds a GPU texture array from a directory of voxel segments and binds it to shader uniforms [S1, unofficial]. It solves the problem of mapping discrete, sparse voxel segments to a contiguous texture array for rendering [S1, unofficial]. It differs from standard volume rendering by treating the volume as a collection of independent segments assembled from a directory structure rather than a monolithic 3D buffer [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A directory texture containing segment metadata (X, Y, Z coordinates) and a collection of existing voxel textures indexed by segment ID [S1, unofficial].
*   **Output:** A rebuilt texture array bound to the shader uniform `segment_bricks`, along with updated uniforms for `active_segment_count` and `segment_directory` [S1, unofficial].

**Data Structures:**
*   **Directory Entry:** A structure containing three components (X, Y, Z) representing segment coordinates [S1, unofficial].
*   **Segment ID:** A 32-bit integer computed from the directory entry components using bit-shifting [S1, unofficial].
*   **Texture Array:** A GPU resource holding the voxel textures, bound to the `segment_bricks` uniform [S1, unofficial].

**Numbered Steps:**
1.  **Update Active Segment Count:** Set the shader uniform `active_segment_count` to the current active segment count [S1, unofficial].
2.  **Update Directory Texture:** If the directory texture exists, set the shader uniform `segment_directory` to it [S1, unofficial].
3.  **Rebuild Texture Array:** Iterate through the directory entries [S1, unofficial]. For each entry, compute the segment ID as `((uint)entry.X << 18) | ((uint)entry.Y << 9) | (uint)entry.Z` [S1, unofficial]. If a texture exists for this ID, add it to the texture array [S1, unofficial].
4.  **Bind Texture Array:** Set the shader uniform `segment_bricks` to the rebuilt texture array [S1, unofficial].

```python
def dynamic_segment_texture_array_update(directory_texture, active_segment_count, texture_pool):
    # Step 1: Update active segment count
    set_shader_uniform("active_segment_count", active_segment_count)
    
    # Step 2: Update directory texture
    if directory_texture is not None:
        set_shader_uniform("segment_directory", directory_texture)
    
    # Step 3: Rebuild texture array
    new_texture_array = []
    for entry in directory_texture.entries:
        segment_id = ((entry.X << 18) | (entry.Y << 9) | entry.Z)
        if segment_id in texture_pool:
            new_texture_array.append(texture_pool[segment_id])
    
    # Step 4: Bind texture array
    rebuilt_array = create_texture_array(new_texture_array)
    set_shader_uniform("segment_bricks", rebuilt_array)
```

**Parameters:**
*   `active_segment_count`: Integer, set to the current number of active segments [S1, unofficial].
*   `segment_directory`: Texture reference, contains directory entries [S1, unofficial].
*   `segment_bricks`: Texture array reference, holds the rebuilt voxel textures [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The bit-shifting formula `((uint)entry.X << 18) | ((uint)entry.Y << 9) | (uint)entry.Z` implies `entry.X` uses 14 bits (range 0–16383), `entry.Y` uses 9 bits (range 0–511), and `entry.Z` uses 9 bits (range 0–511) [S1, unofficial].
*   **Directory Format:** The directory texture must store entries in the exact order expected by the iteration loop, as the texture array is built sequentially from directory order [S1, unofficial].
*   **Missing Textures:** If a computed `segment_id` has no corresponding texture in the pool, it is skipped during the rebuild [S1, unofficial].

## Subtopics

### [Dynamic Volume Texture Slice Rendering](18557-dynamic-volume-texture-slice-rendering.md)
Updates specific depth slices of a 3D volume texture individually using slice-specific render targets. It differs from standard volume rendering by treating the volume texture as a collection of 2D slices that can be updated independently, rather than as a monolithic 3D buffer. Choose it when dynamically updating volumetric data like fog or smoke on the GPU by allowing fragment shaders to write directly into a chosen slice.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of directory entries, as the method iterates through each entry once to rebuild the array [S1, unofficial].
*   **Memory Complexity:** $O(M)$ where $M$ is the number of active segments, as the texture array stores one texture per segment [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales linearly with the number of segments [S1, unofficial]. The texture array holds at most `MaxSegments` textures, imposing a temporary limit on active segments [S1, unofficial].
*   **Strengths:** Efficiently handles sparse volumes by only including active segments in the texture array and allows dynamic updates without rebuilding the entire volume texture [S1, unofficial].
*   **Limitations:** Requires CPU-side iteration to rebuild the texture array, which can be a bottleneck if done frequently [S1, unofficial]. The bit-packing formula limits the coordinate space [S1, unofficial].
*   **When to use:** When rendering sparse voxel volumes with dynamic updates [S1, unofficial].
*   **When not to use:** For dense volumes where most segments are active, or when the coordinate space exceeds the bit-packing limits [S1, unofficial].
