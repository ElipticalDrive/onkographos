# Dynamic Volume Texture Slice Rendering
Also called: Depth slice rendering, Rendering to Volume Texture Slices
## Overview
Dynamic Volume Texture Slice Rendering is a technique for updating specific depth slices of a 3D volume texture by rendering into them individually using slice-specific render targets [S1, unofficial]. It solves the problem of dynamically updating volumetric data (such as fog or smoke) on the GPU by allowing fragment shaders to write directly into a chosen slice of a volume texture [S1, unofficial]. It differs from standard volume rendering by treating the volume texture as a collection of 2D slices that can be updated independently, rather than as a monolithic 3D buffer [S1, unofficial].
## How it works
### Inputs and Outputs
- **Input**: A 3D volume texture (created with `volume: true`) and a set of slice indices to update [S1, unofficial].
- **Output**: Updated color data in the specified depth slices of the volume texture [S1, unofficial].

### Data Structures
The method relies on the `RenderTarget` object with specific constructor options:
- `colorBuffer`: The 3D volume texture to render into [S1, unofficial].
- `slice`: A number specifying the depth slice index (0-based). Defaults to 0 [S1, unofficial].
- `depth`: A boolean indicating whether to use a depth buffer [S1, unofficial].
- `mipLevel`: A number or `undefined`. Set to `undefined` for the last slice to trigger mipmap regeneration for the entire volume [S1, unofficial].

### Steps
1. **Create Render Targets**: For each depth slice that needs updating, create a `RenderTarget` instance [S1, unofficial]. All render targets must share the same `colorBuffer` (the volume texture) but specify a unique `slice` index [S1, unofficial].
2. **Configure Depth Buffer**: If depth testing is required, create a separate 2D texture to act as the depth buffer, as a volume texture cannot serve as a depth buffer [S1, unofficial]. This 2D depth buffer can be shared across all slice render targets [S1, unofficial].
3. **Render to Slices**: For each slice, bind the corresponding `RenderTarget` and execute the rendering pass [S1, unofficial]. The fragment shader writes to the current depth slice [S1, unofficial].
4. **Handle Mipmaps**: If the volume texture has mipmaps enabled, they are regenerated for the entire volume after rendering to a slice because each mip level is filtered from multiple depth slices [S1, unofficial]. Set the `mipLevel` option to `undefined` for the last slice to trigger this regeneration [S1, unofficial].

### Parameters
- `RenderTarget.options.slice`: The depth slice index of the volume texture to render to. Defaults to 0 [S1, unofficial].
- `RenderTarget.options.mipLevel`: Set to `undefined` (or `None` in Python-like pseudocode) for the last slice to trigger mipmap regeneration [S1, unofficial].

### Edge Cases and Pitfalls
- **Multisampling**: Multisampling is not supported for volume textures because multisampled rendering cannot be resolved into a single depth slice on WebGPU [S1, unofficial]. The `samples` option is ignored with a warning [S1, unofficial].
- **Depth Buffer**: A volume texture cannot serve as a depth buffer [S1, unofficial]. A separate 2D texture must be used for depth testing [S1, unofficial].
- **Mipmap Regeneration**: Mipmaps are regenerated for the entire volume after rendering to a slice, not per-slice [S1, unofficial]. This is because each mip level is filtered from multiple depth slices [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Not given in the sources.
- **Memory Complexity**: Not given in the sources.
- **Performance**: Not given in the sources.
- **Strengths**: Allows dynamic updates to volumetric data on the GPU for both WebGL2 and WebGPU backends [S1, unofficial].
- **Limitations**: Multisampling is not supported [S1, unofficial]. Mipmap regeneration affects the entire volume, which may be costly for large textures [S1, unofficial].
- **When to use**: When dynamic volumetric effects (e.g., fog, smoke) need to be updated on the GPU [S1, unofficial].
- **When not to use**: When multisampling is required for the volume texture [S1, unofficial].

## Background
This method was introduced in the PlayCanvas engine via pull request #9697, which added support for rendering to depth slices of volume textures on both WebGL2 and WebGPU [S1, unofficial]. It also added mipmap generation for volume textures on WebGPU, which was previously unsupported [S1, unofficial]. The feature was developed to enable dynamic volumetric effects, such as fog, to be rendered on the GPU [S1, unofficial].
