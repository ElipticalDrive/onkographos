# Volume Context and Configuration

Also called: Context and Volume Configuration, Volume Setup

## Overview
Volume Context and Configuration establishes the rendering state and data layout metadata required by a volume rendering engine to interpret raw voxel data [S1]. It configures the logical description of the volume, including dimensions, voxel structure, and field offsets, so that the renderer can correctly traverse and shade the data [S1].

## How it works
The method involves creating a context object, defining the volume's geometric dimensions, and declaring the internal structure of each voxel, including the number and layout of fields used for shading and classification [S1].

### Inputs and Outputs
- **Input**: Raw voxel data layout, volume dimensions ($X, Y, Z$), and field metadata [S1].
- **Output**: A configured context object (`vpContext`) containing all necessary state for rendering [S1].

### Data Structures
The primary data structure is the context pointer (`vpContext`), which holds default values for rendering parameters and can be instantiated multiple times [S1]. A voxel is a contiguous block of memory containing fields such as scalar density or normal vectors [S1]. Field offsets are byte positions from the start of the voxel, calculated using a macro or function [S1].

### Steps
1. **Create Context**: Initialize a new context with default values using `vpCreateContext()` [S1].
2. **Set Volume Dimensions**: Define the number of elements in each dimension using `vpSetVolumeSize(vpc, xlen, ylen, zlen)`, which returns `VP_OK` on success [S1].
3. **Set Voxel Size and Field Counts**: Declare the total byte size of a voxel and the number of fields for general storage, shading, and classification using `vpSetVoxelSize()` [S1].
4. **Declare Field Properties**: For each field, determine its byte offset and register its size, offset, and maximum value using `vpFieldOffset()` and `vpSetVoxelField()` [S1].
5. **Render**: Use the configured context for rendering [S1].
6. **Destroy Context**: Free the context resources using `vpDestroyContext(vpc)` [S1].

### Pseudocode
```python
VP_OK = 0

class vpContext:
    def __init__(self): pass
    def set_volume_size(self, x, y, z): return VP_OK
    def set_voxel_size(self, bpv, nvf, nsf, ncf): return VP_OK
    def set_voxel_field(self, fnum, fsize, foffset, fmax): return VP_OK

def vpCreateContext(): return vpContext()
def vpDestroyContext(vpc): pass
def vpSetVolumeSize(vpc, xlen, ylen, zlen): return vpc.set_volume_size(xlen, ylen, zlen)
def vpSetVoxelSize(vpc, bytes_per_voxel, num_voxel_fields, num_shade_fields, num_classify_fields):
    return vpc.set_voxel_size(bytes_per_voxel, num_voxel_fields, num_shade_fields, num_classify_fields)
def vpSetVoxelField(vpc, field_num, field_size, field_offset, field_max):
    return vpc.set_voxel_field(field_num, field_size, field_offset, field_max)
def vpFieldOffset(voxel_ptr, field_name):
    # Simulates macro returning byte offset based on struct layout
    offsets = {"scalar": 0, "normal": 1, "gradient": 3}
    return offsets.get(field_name, 0)

# 1. Create context
vpc = vpCreateContext()

# 2. Set dimensions (e.g., 64x64x64)
xlen, ylen, zlen = 64, 64, 64
result = vpSetVolumeSize(vpc, xlen, ylen, zlen)
assert result == VP_OK

# 3. Define voxel structure
bytes_per_voxel = 4
num_voxel_fields = 1
num_shade_fields = 2
num_classify_fields = 2
result = vpSetVoxelSize(vpc, bytes_per_voxel, num_voxel_fields, num_shade_fields, num_classify_fields)

# 4. Declare fields
dummy_voxel = object()
field_offset_0 = vpFieldOffset(dummy_voxel, "scalar")
vpSetVoxelField(vpc, 0, 1, field_offset_0, 255)

field_offset_1 = vpFieldOffset(dummy_voxel, "normal")
vpSetVoxelField(vpc, 1, 2, field_offset_1, 65535)

field_offset_2 = vpFieldOffset(dummy_voxel, "gradient")
vpSetVoxelField(vpc, 2, 1, field_offset_2, 255)

# 5. Rendering loop would use vpc here

# 6. Cleanup
vpDestroyContext(vpc)
```

### Parameters and Typical Values
- **`bytes_per_voxel`**: Total size of the voxel in bytes [S1].
- **`num_voxel_fields`**: Total number of fields in the voxel [S1].
- **`num_shade_fields`**: Number of fields required for shading [S1].
- **`num_classify_fields`**: Number of fields required for classification [S1].
- **`field_max`**: Maximum representable value for the field [S1].

### Edge Cases and Pitfalls
- **Memory Alignment**: `vpFieldOffset` must correctly calculate byte offsets based on the user's voxel struct layout [S1].
- **Context Management**: A program can maintain multiple active contexts simultaneously to render different volumes or parameters [S1].

## Subtopics

### 3D Texture Volume Rendering Setup
This variant configures OpenGL state specifically for 3D texture volume rendering [S2, unofficial].
- **Definition**: Initializes OpenGL state by enabling 3D textures, disabling depth testing, setting up front-face culling, and configuring alpha blending to correctly composite semi-transparent volume data [S2, unofficial].
- **Step**: Generates two texture objects, binds the first to `GL_TEXTURE0_ARB`, sets minification and magnification filters to `GL_LINEAR`, and sets S, T, R wrap modes to `GL_CLAMP` [S2, unofficial].
- **Parameter**: `_RES` is the grid resolution dimension. `_N` is derived as `_RES - 2`. `_SIZE` is the total number of voxels, calculated as `_RES * _RES * _RES` [S2, unofficial].
- **Layout**: `_volumeData` is a flat `float*` array of size `_SIZE` storing voxel densities, accessed via macro `_I(i,j,k)` [S2, unofficial].
- **Pitfall**: Depth testing must be explicitly disabled before rendering volume data to prevent occlusion artifacts from interfering with alpha blending [S2, unofficial].

## Operating characteristics
- **Time Complexity**: Context creation and configuration are $O(1)$ relative to the number of voxels, as they only set metadata [S1]. Field offset calculation is $O(1)$ per field [S1].
- **Memory Complexity**: The context object stores only metadata (dimensions, field counts, offsets) and does not hold the voxel data itself [S1].
- **Strengths**: Decouples data layout from rendering logic. Allows multiple contexts for different volumes or parameters [S1].
- **Limitations**: The primary definition is specific to the VolPack API [S1]. The OpenGL variant is tightly coupled to legacy OpenGL state management [S2, unofficial].
- **When to use**: When using a library like VolPack that requires explicit metadata declaration, or when setting up legacy OpenGL for 3D textures [S1][S2, unofficial].

## Background
The primary definition originates from VolPack, a volume rendering library [S1]. The OpenGL variant is derived from the `nevermoe/SmokeSimulation` repository [S2, unofficial].
