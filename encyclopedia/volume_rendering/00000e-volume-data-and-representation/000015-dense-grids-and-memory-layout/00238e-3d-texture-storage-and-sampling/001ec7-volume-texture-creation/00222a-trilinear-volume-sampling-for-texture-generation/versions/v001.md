# Trilinear Volume Sampling for Texture Generation

Also called: Trilinear Texture Sampling, Trilinear Volume Sampling

## Overview
Trilinear volume sampling retrieves attribute values (such as color or material properties) from a 3D texture by interpolating between the eight nearest grid points using normalized coordinates [S1, S2, unofficial]. It solves the problem of mapping continuous world-space positions to discrete volumetric data, enabling the generation of smooth attribute volumes from mesh or point cloud inputs [S2, unofficial]. Unlike nearest-neighbor sampling, it reduces aliasing artifacts at the cost of increased computational overhead [S1, unofficial].

## How it works
**Inputs:**
- `dataTex`: A 3D CUDA texture object storing volume data. The underlying storage type is `ushort` (unsigned 16-bit integer), but the read mode is configured as `cudaReadModeNormalizedFloat`, mapping values to the $[0, 1]$ range [S1, unofficial].
- `coords`: A tensor of 3D positions in world space or grid space, depending on the implementation context [S2, unofficial].
- `attr_volume`: The source 3D attribute data (e.g., color, density) to be sampled [S2, unofficial].
- `grid_size`: The dimensions of the target volume grid $(W, H, D)$ [S2, unofficial].
- `aabb`: The axis-aligned bounding box of the volume, defined by minimum and maximum corners [S2, unofficial].
- `voxel_size`: The physical size of a single voxel [S2, unofficial].

**Outputs:**
- `attrs`: A tensor containing the interpolated attribute values at the specified coordinates [S2, unofficial].

**Data Structures:**
- `cudaArray *dataArray`: The CUDA array backing the 3D texture `dataTex` [S1, unofficial].
- `texture<ushort, 3, cudaReadModeNormalizedFloat> dataTex`: The texture reference object [S1, unofficial].
- `torch.Tensor attrs`: Initialized as `torch.zeros(texture_size, texture_size, attr_volume.shape[1], device='cuda')` [S2, unofficial].

**Steps:**
1. **Coordinate Normalization (CUDA Context):** If using the CUDA texture API, convert world-space or grid-space coordinates $(x, y, z)$ to normalized texture coordinates in the range $[0, 1]$. This is typically done by dividing the integer grid coordinates by the texture dimensions $(W, H, D)$ [S1, unofficial].
2. **Coordinate Transformation (PyTorch Context):** If mapping from world space, transform coordinates to grid space using the bounding box and voxel size:
   $$
   \text{grid\_coords} = \frac{\text{valid\_pos} - \text{aabb}[0]}{\text{voxel\_size}}
   $$
   where `valid_pos` are the world-space positions [S2, unofficial].
3. **Interpolation:** Perform trilinear interpolation.
   - In CUDA, call the built-in texture fetch function:
     $$
     \text{value} = \text{tex3D}(\text{dataTex}, x, y, z)
     $$
     where $x, y, z \in [0, 1]$ [S1, unofficial].
   - In PyTorch, use `grid_sample_3d` with `mode='trilinear'`. The input grid tensor is constructed by concatenating a batch dimension of zeros with the normalized coordinates [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample, as trilinear interpolation involves a fixed number of arithmetic operations (24 multiplications, 16 additions in the worst case) [S1, S2, unofficial].
- **Memory Complexity:** $O(N)$ where $N$ is the number of voxels, determined by the texture size [S1, unofficial].
- **Performance:** Hardware-accelerated in CUDA via `tex3D`, which is efficient for random access patterns [S1, unofficial]. Software implementations (PyTorch) are slower due to kernel launch overhead and lack of dedicated hardware interpolation units for arbitrary grid sizes [S2, unofficial].
- **Strengths:** Smooth interpolation reduces aliasing; hardware acceleration in CUDA [S1, unofficial].
- **Limitations:** 16-bit storage may limit dynamic range; requires careful coordinate normalization [S1, S2, unofficial].

## Background
The method originates from CUDA volume rendering techniques, where 3D textures are used to store volumetric data for ray casting [S1, unofficial]. The PyTorch implementation extends this to attribute volume generation from meshes, leveraging `grid_sample_3d` for differentiable sampling [S2, unofficial].
