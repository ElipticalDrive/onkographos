# Tiled 2D Texture Storage for 3D Fields

Also called: 2D Texture Tiling for 3D Fields, Tiled 2D Texture Storage

## Overview
A technique to store a 3D scalar field in a 2D texture by tiling the 3D volume into 2D slices, allowing efficient GPU access via texture lookups [S1, unofficial]. It maps 3D coordinates to 2D texture coordinates using a tiling scheme where the Z-coordinate determines the tile position, enabling standard 2D texture sampling hardware to access volumetric data.

## How it works
**Inputs and Outputs**
- Input: A 3D scalar field of dimensions $N_x \times N_y \times N_z$.
- Input: `tilesX`, the number of tiles along the X-axis of the 2D texture.
- Output: A 2D texture of dimensions $W \times H$ containing the tiled volume data.

**Data Structures**
The 2D texture is organized as a grid of tiles. Each tile corresponds to a slice or group of slices of the 3D volume. The layout is determined by `tilesX`.

**Parameters**
- `tilesX`: The number of tiles along the X-axis of the 2D texture. It determines the tiling layout [S1, unofficial].
- `gridSize`: The spatial resolution of the volume in the X and Y dimensions (assumed square for the formula provided) [S1, unofficial].

**Mapping Formula**
To map a 3D coordinate $(x, y, z)$ to 2D texture coordinates $(u, v)$:
1. Calculate the tile indices for the Z-coordinate:
   $$tileX = z \pmod{tilesX}$$
   $$tileY = \lfloor z / tilesX \rfloor$$
2. Calculate the texture coordinates:
   $$u = tileX \cdot gridSize + x$$
   $$v = tileY \cdot gridSize + y$$

**Pseudocode**
```python
def map_3d_to_2d_texture(x, y, z, tilesX, gridSize):
    """
    Maps 3D volume coordinates to 2D texture coordinates.
    
    Args:
        x: X coordinate in volume (0 <= x < gridSize)
        y: Y coordinate in volume (0 <= y < gridSize)
        z: Z coordinate in volume (0 <= z < N_z)
        tilesX: Number of tiles along X-axis of the 2D texture
        gridSize: Spatial resolution of the volume in X and Y dimensions
        
    Returns:
        (u, v): 2D texture coordinates
    """
    tileX = z % tilesX
    tileY = z // tilesX
    u = tileX * gridSize + x
    v = tileY * gridSize + y
    return u, v
```

**Edge Cases and Pitfalls**
- The formula assumes `gridSize` is constant for X and Y. If the volume is not square in XY, the mapping may need adjustment.
- The Z-coordinate must be within the bounds of the volume.
- The tiling layout must be consistent between the storage phase and the sampling phase.

## Subtopics

## Operating characteristics
- **Time Complexity**: Mapping 3D to 2D coordinates is $O(1)$.
- **Memory Complexity**: The 2D texture size is $W \times H$, where $W$ and $H$ depend on `tilesX`, `gridSize`, and $N_z$. Specifically, $W = tilesX \cdot gridSize$ and $H = \lceil N_z / tilesX \rceil \cdot gridSize$.
- **Strengths**: Allows use of standard 2D texture sampling hardware for 3D data.
- **Limitations**: The tiling scheme may lead to discontinuities at tile boundaries if not handled carefully. The choice of `tilesX` affects the aspect ratio of the 2D texture and potentially cache efficiency.

## Background
This technique is used in GPU-based volume rendering and marching cubes implementations to leverage 2D texture hardware for 3D data access [S1, unofficial].
