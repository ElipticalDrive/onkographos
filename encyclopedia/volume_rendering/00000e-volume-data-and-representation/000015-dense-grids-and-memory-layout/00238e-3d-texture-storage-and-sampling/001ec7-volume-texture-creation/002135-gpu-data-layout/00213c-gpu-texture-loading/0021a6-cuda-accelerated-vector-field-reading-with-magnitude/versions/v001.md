# CUDA-accelerated Vector Field Reading with Magnitude

Also called: Float4 Vector Texture Binding, Vector Field Texture Loading

## Overview
This method enables fast, linearly interpolated reading of 3D vector field values at arbitrary positions using CUDA 3D textures [S1, unofficial]. It solves the problem of efficient vector field sampling in real-time visualization by precomputing vector magnitudes and storing them in the fourth component of a `float4` structure, thereby avoiding redundant magnitude calculations during rendering [S1, unofficial]. It differs from standard scalar texture loading by handling multi-component vector data and leveraging the hardware interpolation capabilities of CUDA textures for both direction and magnitude [S1, unofficial].

## How it works
**Inputs:** A host-side 3D vector field dataset (typically from an NRRD or similar format) where each grid point has $(x, y, z)$ components, and the grid dimensions $(width, height, depth)$.
**Outputs:** A bound CUDA texture object (`vectorFieldTex`) ready for sampling in device kernels.

**Data Structures:**
1.  **Host Data Buffer:** A 1D array of `float4` with size $N = width \times height \times depth$. Each element stores $(v_x, v_y, v_z, |v|)$, where $|v|$ is the precomputed magnitude.
2.  **Device Array:** A `cudaArray` allocated with `cudaChannelFormatDesc` for `float4`.
3.  **Texture Object:** A `texture<float4, cudaTextureType3D, cudaReadModeElementType>` object.

**Steps:**

1.  **Precompute Magnitude:** Iterate through the raw vector data. For each vector $\mathbf{v} = (v_x, v_y, v_z)$, compute the magnitude $m = \|\mathbf{v}\|$ and store it in the $w$ component of a `float4` structure.
    $$ m = \sqrt{v_x^2 + v_y^2 + v_z^2} $$
    The host buffer element becomes $(v_x, v_y, v_z, m)$ [S1, unofficial].

2.  **Allocate Device Memory:** Create a channel descriptor for `float4` and allocate a 3D array on the GPU.
    $$ \text{channelDesc} = \text{cudaCreateChannelDesc<float4>}() $$
    $$ \text{cudaMalloc3DArray}(\&d\_volumeArray, \&channelDesc, volumeSize) $$
    where `volumeSize` is a `cudaExtent` struct containing width, height, and depth [S1, unofficial].

3.  **Copy Data to GPU:** Use `cudaMemcpy3D` with a pitched source pointer to copy the host `float4` array to the device 3D array. The pitch is calculated as `width * sizeof(float4)` [S1, unofficial].

4.  **Configure Texture Object:** Set the texture parameters:
    *   `normalized = false`: Coordinates are in texel space (not normalized 0-1).
    *   `filterMode = cudaFilterModeLinear`: Enables trilinear interpolation.
    *   `addressMode[0..2] = cudaAddressModeClamp`: Clamps coordinates to the grid boundaries [S1, unofficial].

5.  **Bind Texture:** Bind the device array to the texture object.
    $$ \text{cudaBindTextureToArray}(vectorFieldTex, d\_volumeArray, channelDesc) $$

**Pseudocode:**

```python
import math
import ctypes
import numpy as np

# Assume cuda module is available and initialized
# This pseudocode represents the logic described in [S1, unofficial]

def prepare_vector_field(host_vectors_3d, width, height, depth):
    """
    host_vectors_3d: numpy array of shape (width, height, depth, 3) or flat list of (x,y,z)
    Returns: float4 array ready for CUDA upload
    """
    total_size = width * height * depth
    # Allocate host memory for float4
    # Structure: x, y, z, magnitude
    host_data = np.empty(total_size, dtype=np.float32) # Simplified view
    
    # In reality, we need a structured dtype or interleaved array
    # Let's assume a flat interleaved array of floats: [x0, y0, z0, m0, x1, y1, z1, m1, ...]
    host_float4_array = np.zeros(total_size * 4, dtype=np.float32)
    
    idx = 0
    for i in range(total_size):
        # Read x, y, z from input source (e.g., NRRD)
        # input_stream.read(...)
        vx = host_vectors_3d.flat[i * 3]
        vy = host_vectors_3d.flat[i * 3 + 1]
        vz = host_vectors_3d.flat[i * 3 + 2]
        
        # Compute magnitude
        mag = math.sqrt(vx*vx + vy*vy + vz*vz)
        
        # Store in float4 layout
        host_float4_array[idx] = vx
        host_float4_array[idx+1] = vy
        host_float4_array[idx+2] = vz
        host_float4_array[idx+3] = mag
        idx += 4
        
    return host_float4_array

def init_cuda_texture(host_float4_array, width, height, depth):
    """
    Simulates the CUDA setup steps from [S1, unofficial]
    """
    # 1. Channel Descriptor
    channel_desc = cuda_create_channel_desc_float4()
    
    # 2. Allocate 3D Array
    volume_size = cuda_extent(width, height, depth)
    d_volume_array = cuda_malloc3d_array(channel_desc, volume_size)
    
    # 3. Copy Data
    # Pitch is width * sizeof(float4)
    pitch = width * 16 # sizeof(float4) is 16 bytes
    src_ptr = cuda_pitched_ptr(host_float4_array, pitch, width, height)
    
    copy_params = {
        'srcPtr': src_ptr,
        'dstArray': d_volume_array,
        'extent': volume_size,
        'kind': cudaMemcpyHostToDevice
    }
    cuda_memcpy3d(copy_params)
    
    # 4. Configure Texture
    vector_field_tex = cuda_texture_object()
    vector_field_tex.normalized = False
    vector_field_tex.filter_mode = cuda_filter_mode_linear
    vector_field_tex.address_mode = [cuda_address_mode_clamp, cuda_address_mode_clamp, cuda_address_mode_clamp]
    
    # 5. Bind
    cuda_bind_texture_to_array(vector_field_tex, d_volume_array, channel_desc)
    
    return vector_field_tex

def sample_vector_field(tex, x, y, z):
    """
    Kernel-side or host-side sampling using the bound texture
    Returns float4 (x, y, z, magnitude)
    """
    # tex3D performs trilinear interpolation
    vector = cuda_tex3d(tex, x, y, z)
    return vector
```

**Parameters:**
*   **Memory Overhead:** Increases memory consumption by 1/3 compared to storing only `float3` vectors, because `float4` is used instead of `float3` [S1, unofficial].
*   **Interpolation:** Linear (trilinear) [S1, unofficial].
*   **Boundary Handling:** Clamp [S1, unofficial].

**Pitfalls:**
*   **CUDA Texture Type Limitations:** CUDA 3D textures do not support `float3` channel formats directly; only `float1`, `float2`, or `float4` are supported [S1, unofficial]. This necessitates the use of `float4` with the fourth component used for magnitude (or padding).
*   **Memory Constraints:** The 1/3 memory increase can be significant for large datasets on GPUs with limited memory [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Reading a vector is $O(1)$ per query, involving a single texture fetch with hardware-accelerated trilinear interpolation [S1, unofficial].
*   **Memory Complexity:** $O(N)$ where $N$ is the number of grid points, but with a constant factor of 4 floats per point instead of 3 [S1, unofficial].
*   **Performance:** Significantly speeds up visualization compared to CPU-side interpolation or magnitude computation per sample [S1, unofficial].
*   **Strengths:** Hardware-accelerated interpolation; precomputed magnitude avoids redundant square root calculations in the rendering loop [S1, unofficial].
*   **Limitations:** Increased memory footprint; requires pre-processing step to compute magnitudes [S1, unofficial].
*   **When to use:** Real-time visualization of 3D vector fields where performance is critical and GPU memory is sufficient [S1, unofficial].
*   **When not to use:** When GPU memory is extremely constrained and magnitude is not needed for visualization [S1, unofficial].

## Background
This technique was described by Marek Fiser in the context of real-time visualization of 3D vector fields using CUDA [S1, unofficial]. It leverages the CUDA runtime API's support for 3D textures to handle the discrete nature of volumetric data, which requires interpolation for arbitrary query points [S1, unofficial]. The approach of storing magnitude in the fourth component is a workaround for the lack of `float3` texture support in CUDA at the time of writing [S1, unofficial].
