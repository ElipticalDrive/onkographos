# Coarsest-Level Lerp

Also called: coarsest-level interpolation, min-level lerp

## Overview
Coarsest-Level Lerp is a method for computing the value of a coarser-side vertex in an Adaptive Mesh Refinement (AMR) volume by performing trilinear interpolation on the coarsest refinement level involved in the input data. It ensures continuity and local rectilinearity by selecting the lowest common refinement level for the query point. Unlike [Current-Level Lerp](913-tri-linear-interpolation-via-lrp.md#current-level-lerp), which adapts to the finest leaf cell, or [Finest Level Lerp](913-tri-linear-interpolation-via-lrp.md#finest-level-lerp), which averages all touching leaf cells, Coarsest-Level Lerp restricts interpolation to the minimal necessary resolution, potentially reducing computational overhead at the cost of lower fidelity at boundaries compared to finest-level averaging [S1, unofficial].

## How it works
**Inputs:**
- `D[0]`: The primary dual cell (or data structure) containing the query point.
- `D[X]`: The secondary dual cell (or data structure) containing the query point.
- `oct`: The target octant structure where the vertex value is stored.
- `oct.l`: The current level of the octant.
- `oct[X].p`: The logical position of the vertex within the octant.

**Outputs:**
- `oct[X].v`: The computed value for the coarser-side vertex.

**Data Structures:**
- `D[l].l`: The refinement level of dual cell `D` at index `l`.
- `D[l].v`: The value associated with dual cell `D` at index `l`.
- `lerpOnLevel(level, position)`: A helper function that performs trilinear interpolation on the specified refinement level using the logical position.

**Steps:**
1. Calculate the logical coordinate index level:
   $$ lX' = \min(D[0].l, D[X].l) $$
2. Check if the calculated level matches the current octant level:
   - If $ lX' == oct.l $:
     The vertex lies on a boundary where both inputs are at the current level. Set the value to the average of the inputs:
     $$ oct[X].v = \text{avg}(D[0].v, D[X].v) $$
   - Otherwise ($ lX' < oct.l $):
     Perform trilinear interpolation on the coarsest level identified:
     $$ oct[X].v = \text{lerpOnLevel}(lX', oct[X].p) $$

**Pitfalls:**
- In many cases, multiple calls to `lerpOnLevel` may resolve to the same dual cell $ D $. A performance-optimized implementation should detect this redundancy and replace the interpolation with direct averaging of the respective inputs [S1, unofficial].
- Precision issues may arise if the logical position `oct[X].p` is not correctly normalized to the grid of level $ lX' $.

## Subtopics

### Current-Level Lerp
A method that performs interpolation on the leaf cell (current level) rather than the coarsest level, making the interpolant adaptive. It calculates $ lX' = \min(D[0].l, D[X].l) $. If $ lX' == oct.l $, it averages the inputs. Otherwise, it finds the leaf cell level using `findLeafCell(oct[X].p).l` and interpolates on that level. This strategy allows the interpolant to adapt to the finest available data at the query point [S1, unofficial].

### Finest Level Lerp
A method that computes the weighted average of all leaf cells touching the vertex, which lies on at least one boundary and in the center of a finest level logical dual cell. It calculates $ lX'_{min} = \min(D[0].l, D[X].l) $ and $ lX'_{max} = \max(D[0].l, D[X].l) $. If $ lX'_{min} == lX'_{max} $ (not a boundary), it averages the inputs. Otherwise, it finds the finest level dual cell `D'` and averages all its vertex values. This method is fast, simple, and qualitatively one of the best, often used by default [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the cost of `lerpOnLevel`. In the worst case, it requires traversing the AMR hierarchy to find the coarsest cell, but typically it is $ O(1) $ if the cell containing the point is cached or indexed.
- **Memory Complexity:** $ O(1) $ auxiliary memory, as it only requires access to the specific dual cells involved.
- **Performance:** Generally faster than Finest Level Lerp because it avoids averaging multiple leaf cells. However, it may be slower than Current-Level Lerp if the coarsest level is significantly deeper than the leaf level, requiring more interpolation steps or larger grid lookups.
- **Strengths:** Ensures continuity and local rectilinearity. Simple to implement. Avoids ghost artifacts by using actual leaf cells only on the boundary.
- **Limitations:** May produce lower accuracy at boundaries compared to Finest Level Lerp, as it does not incorporate information from finer levels. Not suitable for ray-isosurface intersections if the interpolant does not preserve monotonicity or smoothness required by the intersection algorithm [S1, unofficial].
- **When to use:** When computational efficiency is prioritized over boundary accuracy, or when the coarsest level provides sufficient resolution for the application.
- **When not to use:** When high-fidelity boundary representation is critical, or when ray-isosurface intersection accuracy is required and the interpolant's properties are insufficient [S1, unofficial].

## Background
Coarsest-Level Lerp was introduced in the context of CPU-based isosurface ray tracing of Adaptive Mesh Refinement (AMR) data. It is one of four options presented to guarantee that the interpolant is continuous, adaptive, accurate, and locally rectilinear. The method leverages the logical grid abstraction of AMR data, treating each refinement level as a structured grid. It was developed to address the challenges of sampling AMR data for isosurface extraction, specifically ensuring that boundary vertices are computed consistently with the underlying grid structure [S1, unofficial].
