# Parametric Texturing with Lightmap and Reference Map

Also called: shader-based landscape texturing, terraform-style texturing

## Overview
A texturing scheme for voxel landscapes that uses a single shader script for the entire landscape while storing varying parameters in separate arrays to avoid the memory overhead of per-voxel textures [S1, unofficial]. It solves the problem of tiling and memory exhaustion in large voxel worlds by decoupling texture selection from the rendering loop, using a reference map to blend between two textures and a lightmap for shading [S1, unofficial]. It is distinguished from per-voxel shader storage by its extreme inner-loop speed, despite offering limited blending ranges compared to more complex multi-texture approaches [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Heightmap (implicit geometry), Lightmap (greyscale array), Reference Map (greyscale bitmap), a sorted list of available textures ($tex_0, tex_1, \dots$), and camera/screen coordinates.
*   **Output:** Rendered pixel color for each screen coordinate.

**Data Structures:**
1.  **Lightmap:** An array of colors (typically greyscale values to reduce cache thrashing) with the same dimensions as the heightmap [S1, unofficial].
2.  **Reference Map (ref-map):** A bitmap of greyscale values, same format as the lightmap, used to determine texture selection and blending [S1, unofficial].
3.  **Texture List:** An ordered array of textures sorted by index [S1, unofficial].

**Offline Lightmap Update:**
The lightmap is computed prior to runtime to save performance [S1, unofficial]. For each point in the map:
1.  Interpolate along a ray towards the sun.
2.  Stop if mountains are hit to determine shadow status [S1, unofficial].
3.  Associate a color based on the slope at that point and a random coefficient of small magnitude [S1, unofficial].

**Realtime Partial Update (Optional):**
Lightmap blocks of $32 \times 32$ pixels can be updated each frame [S1, unofficial]. Applying this only to blocks within the view frustum produces artifacts when the view rotates suddenly [S1, unofficial].

**Rendering Steps (Span Renderer):**
The renderer iterates over screen spans. For each span from $y_1$ to $y_2$:
1.  Compute world space deltas $(dwx, dwz)$ for the span endpoints $(wx_1, wz_1)$ to $(wx_2, wz_2)$ [S1, unofficial].
2.  Initialize current world coordinates $(wx, wz)$ and screen coordinates $(x, wy)$ [G].
3.  For each screen $y$ from $y_1$ to $y_2$:
    a.  Look up $Rval$ from the Reference Map and $Lval$ from the Lightmap at the current world position $(wx, wz)$ [S1, unofficial].
    b.  Select two textures, $tex_1$ and $tex_2$, from the sorted texture list based on $Rval$ [S1, unofficial].
    c.  Compute an alpha coefficient $A$ based on $Rval$ [S1, unofficial].
    d.  Determine texture coordinates $(tx, ty)$ from current world coordinates $(wx, wy)$ [S1, unofficial].
    e.  Load texels from $tex_1$ and $tex_2$ and blend them using $A$ [S1, unofficial].
    f.  Modulate the blended result with $Lval$ [S1, unofficial].
    g.  Plot the pixel [S1, unofficial].
    h.  Interpolate $(wx, wz)$ for the next step [S1, unofficial].

**Pseudocode:**
```python
def render_span(y1, y2, x1, wx1, wz1, wx2, wz2, textures, ref_map, light_map, framebuffer):
    # Compute deltas for linear interpolation across the span
    dx = wx2 - wx1
    dz = wz2 - wz1
    dy = y2 - y1
    
    # Initialize current world and screen coordinates
    wx = wx1
    wz = wz1
    x = x1
    wy = y1
    
    for y in range(y1, y2 + 1):
        # Get parameters from maps using current world coordinates
        # Greyscale values are sampled directly from the bitmap arrays [G]
        Rval = ref_map[wy][wx]
        Lval = light_map[wy][wx]
        
        # Select two textures and alpha based on reference map value
        # The ref-map value maps to an index in the sorted texture list
        # to pick two adjacent textures for blending [G]
        n = len(textures)
        idx = int(Rval * (n - 1))
        idx = min(idx, n - 2)
        tex1 = textures[idx]
        tex2 = textures[idx + 1]
        A = Rval * (n - 1) - idx
        
        # Compute texture coordinates from world coordinates [G]
        tx = wx % tex1.width
        ty = wz % tex1.height
        
        # Load texels and blend given A
        # If A is 0, the texture is skipped (black areas not needed) [S1, unofficial]
        if A > 0:
            c1 = tex1.sample(tx, ty)
            c2 = tex2.sample(tx, ty)
            blended = c1 * (1.0 - A) + c2 * A
        else:
            blended = tex1.sample(tx, ty)
            
        # Modulate result with Lval
        final_color = blended * Lval
        
        # Plot pixel
        framebuffer[y][x] = final_color
        
        # Interpolate (wx, wz)
        wx += dx / dy
        wz += dz / dy
        x += 1
        wy += 1
```

**Edge Cases and Pitfalls:**
*   **Blending Limitation:** The method cannot blend directly from $tex_1$ to $tex_4$; it only blends between the two selected textures based on the ref-map index [S1, unofficial].
*   **Zero Alpha:** Areas where the alpha coefficient is zero are skipped because black areas of alpha-blended textures are not needed [S1, unofficial].
*   **View Rotation Artifacts:** Partially updating the lightmap only within the view frustum causes visible artifacts when the camera rotates suddenly [S1, unofficial].

## Operating characteristics
*   **Memory:** Avoids the memory overhead of per-voxel textures. Storing a $32 \times 32$ texture per column for a $1024 \times 1024$ map would require over 1 GB of memory [S1, unofficial]. This method uses a sorted list of textures plus two scalar maps (Lightmap and Ref-map) [S1, unofficial].
*   **Performance:** Provides an extremely fast inner loop due to the simplicity of the shader script and the limited number of texture lookups (two per pixel) [S1, unofficial].
*   **Quality:** Minimizes visible tiling by using parametric variation (slope, random coefficients, ref-map) [S1, unofficial].
*   **Limitations:** Limited texture blending ranges; cannot smoothly transition between arbitrary non-adjacent textures in the list [S1, unofficial].

## Background
This method was described in the context of the "terraVox" engine, a realtime voxel landscape engine [S1, unofficial]. It was chosen over storing $256 \times 256$ shader scripts because it provides an extremely fast inner loop, despite the disadvantage of limited texture blending ranges [S1, unofficial].
