# Texture Uniting (Multi-Channel Packing)


## Overview
Texture Uniting is a data preparation technique that combines multiple separate 3D textures (representing distinct attributes such as noise, detail, light, or mask) into a single RGBA 3D texture. It solves the problem of excessive GPU memory bandwidth consumption and sampling overhead when rendering volumes with multiple independent attribute channels by allowing simultaneous access to all attributes in a single texture fetch. Unlike [Texture Packing Strategy](3196-texture-packing-strategy.md), which separates attributes into individual scalar textures to minimize bandwidth when accessed independently, Texture Uniting packs them together to optimize for simultaneous access patterns [S1, unofficial].

## How it works
**Inputs:**
- Four source 3D textures: `noise_texture`, `detail_texture`, `light_texture`, and `mask_texture`.
- Source dimensions: $N_{noise}, N_{detail}, N_{light}, N_{mask}$ (integers).
- Target unified texture dimension: $N_{united}$ (integer, assumed cubic).

**Outputs:**
- A single unified 3D texture `united_texture` with dimensions $(N_{united}, N_{united}, N_{united})$ and RGBA format.

**Data Structures:**
- `united_texture`: A 3D texture object where each texel stores a `float4` $(x, y, z, w)$.
- `sampler_linear_clamp`: A texture sampler state configured with linear filtering (`GL_LINEAR` or equivalent) and clamping address mode (`GL_CLAMP_TO_EDGE` or equivalent) to handle resolution mismatches between source and target textures [S1, unofficial].

**Steps:**
1.  **Initialize Unified Texture:** Allocate a 3D texture `united_texture` of size $N_{united}^3$.
2.  **Iterate Voxels:** For each voxel coordinate $(i, j, k)$ in the unified texture, where $0 \le i, j, k < N_{united}$:
    a.  **Normalize Coordinates:** Compute normalized texture coordinates $(s, t, r)$ for the current voxel:
        $$
        s = \frac{i}{N_{united}}, \quad t = \frac{j}{N_{united}}, \quad r = \frac{k}{N_{united}}
        $$
        [S1, unofficial]
    b.  **Sample Noise Channel:** Sample the red channel from `noise_texture` using the normalized coordinates:
        $$
        x = \text{noise\_texture.SampleLevel}(sampler\_linear\_clamp, (s, t, r), 0).r
        $$
        [S1, unofficial]
    c.  **Sample Detail Channel:** Sample the red channel from `detail_texture`:
        $$
        y = \text{detail\_texture.SampleLevel}(sampler\_linear\_clamp, (s, t, r), 0).r
        $$
        [S1, unofficial]
    d.  **Sample Light Channel:** Sample the red channel from `light_texture`:
        $$
        z = \text{light\_texture.SampleLevel}(sampler\_linear\_clamp, (s, t, r), 0).r
        $$
        [S1, unofficial]
    e.  **Sample and Normalize Mask Channel:** Sample the red channel from `mask_texture` and normalize by dividing by 32.0:
        $$
        w = \frac{\text{mask\_texture.SampleLevel}(sampler\_linear\_clamp, (s, t, r), 0).r}{32.0}
        $$
        [S1, unofficial]
    f.  **Write to Unified Texture:** Store the combined vector in the unified texture:
        $$
        \text{united\_texture}[i, j, k] = (x, y, z, w)
        $$
        [S1, unofficial]

**Parameters:**
- $N_{united}$: The dimension of the output unified texture. [S1, unofficial]
- $N_{noise}, N_{detail}, N_{light}, N_{mask}$: The dimensions of the source textures. [S1, unofficial]

**Edge Cases and Pitfalls:**
- **Resolution Mismatch:** The method uses normalized coordinates with linear filtering (`SampleLevel` with linear sampler) rather than integer indexing. This allows for bilinear filtering across resolution boundaries between source textures of different sizes, preventing aliasing or hard edges when source resolutions differ from $N_{united}$ [S1, unofficial].
- **Mask Normalization:** The mask channel is explicitly divided by 32.0. If the source mask values are not in the expected range, this normalization may produce incorrect results. [S1, unofficial]

**Pseudocode:**
```python
def unite_textures(noise_tex, detail_tex, light_tex, mask_tex, united_size):
    """
    Combines four 3D textures into a single RGBA 3D texture.
    
    Args:
        noise_tex: 3D texture object for noise channel
        detail_tex: 3D texture object for detail channel
        light_tex: 3D texture object for light channel
        mask_tex: 3D texture object for mask channel
        united_size: int, dimension of the output cubic texture
        
    Returns:
        united_tex: 3D texture object with RGBA format
    """
    # Initialize unified texture
    united_tex = create_3d_texture(united_size, united_size, united_size, format=RGBA32F)
    
    # Create sampler with linear filtering and clamp to edge
    sampler = create_sampler(filter=LINEAR, address_mode=CLAMP_TO_EDGE)
    
    # Iterate over all voxels in the unified texture
    for i in range(united_size):
        for j in range(united_size):
            for k in range(united_size):
                # Normalize coordinates to [0, 1]
                s = i / united_size
                t = j / united_size
                r = k / united_size
                
                # Sample each channel using normalized coordinates
                # Note: SampleLevel typically takes mip level 0 for base level
                x = noise_tex.sample_level(sampler, (s, t, r), 0).r
                y = detail_tex.sample_level(sampler, (s, t, r), 0).r
                z = light_tex.sample_level(sampler, (s, t, r), 0).r
                w_raw = mask_tex.sample_level(sampler, (s, t, r), 0).r
                w = w_raw / 32.0
                
                # Write to unified texture
                united_tex.set_texel(i, j, k, (x, y, z, w))
                
    return united_tex
```

## Subtopics

### PBR Material Channel Packing
PBR Material Channel Packing is a specific application of multi-channel packing for physically based rendering material properties. It packs BaseColor and Alpha into an RGBA texture, and Metallic and Roughness into an RGB texture (with R=0, G=Roughness, B=Metallic). It is chosen when rendering PBR materials where these attributes need to be sampled simultaneously. Parameters include `alphaMode` (typically 'OPAQUE') and `doubleSided` (True if not remeshed, else False) [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N_{united}^3)$, as each voxel in the unified texture requires four texture samples and one write operation.
- **Memory Complexity:** $O(N_{united}^3 \times 4 \times \text{bytes\_per\_channel})$. For 32-bit floats, this is $16 \times N_{united}^3$ bytes.
- **Performance:** Reduces memory bandwidth pressure during rendering by combining four separate texture fetches into one. However, the packing process itself incurs an upfront cost.
- **Strengths:** Optimizes for simultaneous access to multiple attributes; handles resolution differences via linear filtering.
- **Limitations:** Requires all attributes to be sampled together; if attributes are accessed independently, separate textures may be more efficient.
- **When to Use:** When rendering volumes or materials where multiple attributes (e.g., density, color, emission) are needed per voxel and accessed in the same shader pass.
- **When Not to Use:** When attributes are accessed sparsely or independently, as the unified texture forces all channels to be loaded.

## Background
Texture Uniting was introduced in the context of volumetric smoke rendering to optimize memory bandwidth. The technique was documented in the `VolumetricSmoke` repository by furkanunsal42 [S1, unofficial]. It leverages standard 3D texture sampling capabilities available in modern graphics APIs (OpenGL, DirectX, Vulkan) to combine multiple data channels into a single texture resource.
