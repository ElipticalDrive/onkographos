# Texture Uniting (Multi-Channel Packing)

Also called: multi-channel packing, texture merging

## Overview
Texture Uniting is a technique to combine four separate 3D textures (e.g., noise, detail, light, mask) into a single RGBA 3D texture to optimize memory bandwidth and sampling [S1, unofficial]. It differs from simple storage by actively aggregating distinct logical channels into one hardware resource, whereas [3D Texture Storage and Sampling](3064-3d-texture-storage-and-sampling.md) describes the underlying mechanism of storing and accessing individual volumes.

## How it works
**Inputs:**
- Source 3D textures: $T_{noise}, T_{detail}, T_{light}, T_{mask}$ with dimensions $(N_{noise}, N_{detail}, N_{light}, N_{mask})$.
- Target unified texture: $T_{united}$ with cubic dimension $N_{united}$.

**Data Structures:**
- $T_{united}$: A 3D texture object (e.g., `GL_TEXTURE_3D`) with format `RGBA32F` or equivalent, dimensions $(N_{united}, N_{united}, N_{united})$.

**Steps:**
1.  **Normalize Coordinates:** For each voxel index $(i, j, k)$ in the unified texture, compute normalized coordinates $u, v, w \in [0, 1]$:
    $$
    u = \frac{i}{N_{united}}, \quad v = \frac{j}{N_{united}}, \quad w = \frac{k}{N_{united}}
    $$
2.  **Sample Noise Channel:** Sample the noise texture at normalized coordinates. Assuming the noise texture is also normalized to $[0,1]$ or scaled appropriately:
    $$
    x = T_{noise}.SampleLevel(sampler_{linear}, (u, v, w), 0).r
    $$
    [S1, unofficial].
3.  **Sample Detail Channel:**
    $$
    y = T_{detail}.SampleLevel(sampler_{linear}, (u, v, w), 0).r
    $$
    [S1, unofficial].
4.  **Sample Light Channel:**
    $$
    z = T_{light}.SampleLevel(sampler_{linear}, (u, v, w), 0).r
    $$
    [S1, unofficial].
5.  **Sample and Normalize Mask Channel:**
    $$
    w = \frac{T_{mask}.SampleLevel(sampler_{linear}, (u, v, w), 0).r}{32.0}
    $$
    [S1, unofficial].
6.  **Write to Unified Texture:**
    $$
    T_{united}[i, j, k] = (x, y, z, w)
    $$
    [S1, unofficial].

**Parameters:**
- $N_{united}$: Integer dimension of the output unified texture (assumed cubic) [S1, unofficial].
- $N_{noise}, N_{detail}, N_{light}, N_{mask}$: Integer dimensions of the source textures [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Resolution Mismatch:** The method uses normalized coordinates (`id / united_texture_size`) rather than integer scaling (`id * source_size / united_texture_size`). This allows for bilinear/trilinear filtering across resolution boundaries between source textures, smoothing out discrepancies in grid resolution [S1, unofficial].
- **Precision:** Arithmetic operations are performed in 32-bit floating point, but results are truncated when written to destination textures if lower precision formats (e.g., 16-bit) are used [S3, unofficial].

**Pseudocode:**
```python
def unite_textures(noise_tex, detail_tex, light_tex, mask_tex, united_size):
    """
    Combines four 3D textures into a single RGBA 3D texture.
    
    Args:
        noise_tex: 3D texture object for noise channel
        detail_tex: 3D texture object for detail channel
        light_tex: 3D texture object for light channel
        mask_tex: 3D texture object for mask channel
        united_size: int, dimension of the cubic output texture
        
    Returns:
        united_tex: 3D texture object with RGBA channels
    """
    # Initialize unified texture with RGBA32F format
    united_tex = create_3d_texture(width=united_size, height=united_size, depth=united_size, format='RGBA32F')
    
    # Define linear clamp sampler
    sampler = create_sampler(filter_mode='linear', address_mode='clamp_to_edge')
    
    for i in range(united_size):
        for j in range(united_size):
            for k in range(united_size):
                # Normalize coordinates to [0, 1]
                u = i / united_size
                v = j / united_size
                w = k / united_size
                
                # Sample each channel
                # Note: SampleLevel assumes normalized coordinates for the sampler
                x = noise_tex.sample_level(sampler, (u, v, w), mip_level=0).r
                y = detail_tex.sample_level(sampler, (u, v, w), mip_level=0).r
                z = light_tex.sample_level(sampler, (u, v, w), mip_level=0).r
                
                # Sample mask and normalize
                mask_val = mask_tex.sample_level(sampler, (u, v, w), mip_level=0).r
                w_channel = mask_val / 32.0
                
                # Write to unified texture
                united_tex.set_value(i, j, k, (x, y, z, w_channel))
                
    return united_tex
```

## Subtopics

### PBR Material Channel Packing
Packs PBR material properties into standard texture formats: BaseColor and Alpha into RGBA, Metallic and Roughness into RGB (R=0, G=Roughness, B=Metallic) [S2, unofficial]. Steps: 1. Pack BaseColor/Alpha: `np.concatenate([base_color, alpha], axis=-1)`. 2. Pack Metallic/Roughness: `np.concatenate([np.zeros_like(metallic), roughness, metallic], axis=-1)` [S2, unofficial]. Parameters: `alphaMode: 'OPAQUE'`, `doubleSided: True` if not remesh else `False` [S2, unofficial].

### Texture Packing Strategy
Avoids packing multiple cell attributes into a single texture if it increases memory bandwidth usage unnecessarily [S3, unofficial]. Steps: Keep frequently accessed attributes (like inside-outside for pressure solve) in their own scalar textures to minimize bandwidth [S3, unofficial]. Pitfall: Packing inside-outside and velocity into a single RGBA texture increases memory transfer by 4x, which is inefficient if velocity is unused during pressure solving [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N^3)$ where $N$ is the unified texture dimension, as each voxel requires four samples and one write.
- **Memory Complexity:** Reduces overhead from four separate texture objects to one, but increases per-voxel memory usage from 1 channel to 4 channels.
- **Performance:** Optimizes memory bandwidth by reducing the number of texture fetches during rendering if the unified texture is sampled once per ray step instead of four times [S1, unofficial]. However, if only a subset of channels is needed, unpacking or separate textures may be more efficient [S3, unofficial].
- **Strengths:** Reduces texture object overhead, simplifies shader code for multi-channel data, and leverages hardware filtering for resolution mismatches [S1, unofficial].
- **Limitations:** Increases memory bandwidth if all channels are not used simultaneously; potential precision loss if using lower-bit formats [S3, unofficial].

## Background
Originated in real-time volumetric rendering and fluid simulation to manage memory bandwidth and simplify multi-channel data access [S1, S3, unofficial]. The technique is commonly used in GPU-based smoke and fluid simulations where multiple physical properties (density, velocity, temperature) need to be sampled efficiently [S1, unofficial].
