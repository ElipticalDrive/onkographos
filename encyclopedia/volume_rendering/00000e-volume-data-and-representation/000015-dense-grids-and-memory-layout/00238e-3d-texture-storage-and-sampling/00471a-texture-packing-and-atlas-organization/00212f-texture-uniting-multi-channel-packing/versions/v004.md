# Texture Uniting (Multi-Channel Packing)

Also called: multi-channel packing, texture merging

## Overview
Texture Uniting is a technique to combine four separate 3D textures (noise, detail, light, mask) into a single RGBA 3D texture to optimize memory bandwidth and sampling [S1, unofficial]. It solves the problem of excessive GPU memory consumption and redundant sampling overhead when rendering high-resolution volumes with multiple attribute channels by avoiding the duplication of raw voxel data and enabling simultaneous access to related attributes [S1, unofficial]. Unlike [3D Volume Atlas Packing](7158-3d-volume-atlas-packing.md), which arranges distinct datasets in a spatial atlas to minimize texture binding switches, this method interleaves attributes into a single volume's color channels to optimize bandwidth for simultaneous access [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Four source 3D textures: `noise_texture`, `detail_texture`, `light_texture`, and `mask_texture`. Each has an integer dimension (`noise_texture_size`, `detail_texture_size`, `light_texture_size`, `mask_texture_size`).
*   **Output:** A single unified 3D texture (`united_texture`) with integer dimension `united_texture_size` (assumed cubic).

**Data Structures:**
*   `united_texture`: A 3D texture resource with format supporting RGBA components (e.g., `RGBA32F` or `RGBA16F`).
*   Source textures: 3D textures with single-channel (R) or RGBA formats, typically normalized to [0, 1].

**Steps:**
1.  Initialize the `united_texture` with dimensions `united_texture_size`.
2.  For each voxel coordinate `id.xyz` in the output volume:
    a.  Compute normalized coordinates for sampling: `uv = id.xyz / united_texture_size`.
    b.  Sample the noise channel: `x = noise_texture.SampleLevel(sampler_linear_clamp, uv, 0).r`.
    c.  Sample the detail channel: `y = detail_texture.SampleLevel(sampler_linear_clamp, uv, 0).r`.
    d.  Sample the light channel: `z = light_texture.SampleLevel(sampler_linear_clamp, uv, 0).r`.
    e.  Sample the mask channel and normalize: `w = mask_texture.SampleLevel(sampler_linear_clamp, uv, 0).r / 32.0f`.
    f.  Write the packed value: `united_texture[id.xyz] = float4(x, y, z, w)`.

**Formulas:**
*   Normalized coordinate: $uv = \frac{id}{S_{united}}$
*   Noise value: $x = T_{noise}(uv)$
*   Detail value: $y = T_{detail}(uv)$
*   Light value: $z = T_{light}(uv)$
*   Mask value: $w = \frac{T_{mask}(uv)}{32.0}$

Where $S_{united}$ is `united_texture_size`, and $T_{channel}$ denotes the sampling function for the respective source texture.

**Parameters:**
*   `united_texture_size`: int dimension of the output unified texture (assumed cubic).
*   `noise_texture_size`, `detail_texture_size`, `light_texture_size`, `mask_texture_size`: int dimensions of the source textures.

**Edge Cases and Pitfalls:**
*   **Resolution Mismatch:** Source textures may have different resolutions. Using normalized coordinates with `SampleLevel` and linear clamping allows for bilinear filtering across resolution boundaries, preventing aliasing artifacts [S1, unofficial].
*   **Mask Normalization:** The mask value is divided by 32.0f. This implies the source mask texture values are in the range [0, 32] or that a specific scaling factor is required for downstream shading calculations [S1, unofficial].
*   **Precision:** Using floating-point formats (e.g., `RGBA32F`) is recommended to preserve precision during the packing and unpacking process, especially if the source textures have high dynamic range.

**Pseudocode:**
```python
def unite_textures(noise_tex, detail_tex, light_tex, mask_tex, united_size):
    """
    Combines four 3D textures into a single RGBA 3D texture.
    
    Args:
        noise_tex: 3D texture object for noise channel
        detail_tex: 3D texture object for detail channel
        light_tex: 3D texture object for light channel
        mask_tex: 3D texture object for mask channel
        united_size: int, dimension of the output cubic texture
        
    Returns:
        united_tex: 3D texture object with RGBA format
    """
    # Initialize output texture
    united_tex = create_3d_texture(width=united_size, height=united_size, depth=united_size, format='RGBA32F')
    
    # Define sampler with linear clamping
    sampler = create_sampler(filter='linear', address_mode='clamp_to_edge')
    
    # Pre-calculate inverse size for normalized coordinates
    inv_united_size = 1.0 / united_size
    
    # Iterate over all voxels in the output texture
    for z in range(united_size):
        for y in range(united_size):
            for x in range(united_size):
                # Compute normalized coordinates
                uv = float3(x * inv_united_size, y * inv_united_size, z * inv_united_size)
                
                # Sample each channel
                # Note: SampleLevel uses mip level 0
                x_val = noise_tex.sample_level(sampler, uv, 0).r
                y_val = detail_tex.sample_level(sampler, uv, 0).r
                z_val = light_tex.sample_level(sampler, uv, 0).r
                w_val = mask_tex.sample_level(sampler, uv, 0).r / 32.0f
                
                # Write to unified texture
                united_tex.set_value(x, y, z, float4(x_val, y_val, z_val, w_val))
                
    return united_tex
```

## Subtopics

### [Texture Packing Strategy](3196-texture-packing-strategy.md)
Texture Packing Strategy is a memory optimization technique that maps a single underlying volume dataset to multiple distinct GPU textures, each scaled by a specific scalar multiplier. It solves the problem of excessive GPU memory consumption when rendering high-resolution volumes with multiple attribute channels (e.g., emission, absorption, reflection) by avoiding the duplication of raw voxel data. Unlike [Texture Uniting (Multi-Channel Packing)](2470-texture-uniting-multi-channel-packing.md), which combines attributes into a single RGBA texture to optimize bandwidth for simultaneous access, this strategy separates attributes into individual scalar textures to minimize bandwidth usage when attributes are accessed independently or with different scaling factors.

### PBR Material Channel Packing
Packs PBR material properties into standard texture formats: BaseColor and Alpha into RGBA, Metallic and Roughness into RGB (R=0, G=Roughness, B=Metallic) [S2, unofficial]. Steps: Pack BaseColor/Alpha by concatenating `[base_color, alpha]` along the last axis; Pack Metallic/Roughness by concatenating `[zeros_like(metallic), roughness, metallic]` along the last axis [S2, unofficial]. Parameters: `alphaMode` is 'OPAQUE', `doubleSided` is True if not remesh else False [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels in the output texture. Each voxel requires four texture samples and one write operation.
*   **Memory Complexity:** $O(N)$, where $N$ is the number of voxels. The output texture uses 4 components per voxel, while the input textures use 1 component per voxel each. Total input memory is $4N$, output is $4N$, so there is no net memory reduction in terms of raw data volume, but bandwidth is optimized by reducing the number of texture bindings and sampling calls during rendering.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales linearly with resolution. The use of normalized coordinates and linear filtering ensures consistent quality across different resolutions.
*   **Strengths:** Reduces texture binding overhead, enables simultaneous access to multiple attributes, handles resolution mismatches via filtering.
*   **Limitations:** Requires all attributes to be sampled simultaneously; if attributes are accessed independently, separate textures may be more efficient. The mask normalization factor (32.0) is specific to the source implementation and may need adjustment for other use cases.
*   **When to use:** When rendering volumes where multiple attributes (noise, detail, light, mask) are needed per voxel and are accessed together.
*   **When not to use:** When attributes are accessed independently or have vastly different access patterns.

## Background
Origin: This technique is described in the context of volumetric smoke rendering, specifically in the `VolumetricSmoke` project by furkanunsal42 [S1, unofficial]. It is used to optimize the rendering pipeline by combining multiple texture lookups into a single unified texture, reducing the overhead associated with multiple texture bindings and sampling operations.
