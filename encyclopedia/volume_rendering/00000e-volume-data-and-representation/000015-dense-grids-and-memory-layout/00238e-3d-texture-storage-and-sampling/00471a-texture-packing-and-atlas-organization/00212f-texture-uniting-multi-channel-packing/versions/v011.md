# Texture Uniting (Multi-Channel Packing)

Also called: Multi-Channel Packing, Multi-Channel Volume Texture Optimization, Texture Packing/Unpacking Scheme

## Overview
Texture Uniting combines multiple separate 3D textures (e.g., noise, detail, light, mask) into a single RGBA 3D texture to optimize memory bandwidth and sampling efficiency [S1, unofficial]. It solves the problem of excessive texture unit usage and redundant sampling operations when rendering volumes with multiple attribute channels [S2, unofficial]. Unlike [Texture Packing Strategy](3196-texture-packing-strategy.md), which separates attributes into individual scalar textures to minimize memory bandwidth when accessed independently, this method combines attributes into a single RGBA texture for simultaneous access at a single coordinate [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** $N$ source 3D textures ($T_1, T_2, \dots, T_N$), where $N \le 4$. Each source texture $T_i$ has dimensions $D_{i,x} \times D_{i,y} \times D_{i,z}$ and stores a single scalar value per voxel [S1, unofficial].
- **Outputs:** A single unified 3D texture $T_{united}$ with dimensions $D_{u,x} \times D_{u,y} \times D_{u,z}$ and RGBA32 format (8 bits per channel) [S1, unofficial][S2, unofficial][S3].

**Data Structures:**
- $T_{united}$: A 3D texture resource. Each voxel stores a `float4` vector [S1, unofficial].
- Coordinate mapping: The unified texture uses normalized coordinates $[0, 1]$ for sampling [S1, unofficial].

**Steps:**
1. **Determine Unified Dimensions:** Choose $D_{u,x}, D_{u,y}, D_{u,z}$ such that they are large enough to hold the highest-resolution source texture [S1, unofficial].
2. **Initialize:** Clear $T_{united}$ to zero [G].
3. **Pack Channels:** For each voxel $(x, y, z)$ in $T_{united}$:
   a. For each source texture $T_i$ mapped to channel $c_i \in \{R, G, B, A\}$:
      i. Calculate normalized source coordinate: $u = \frac{x}{D_{u,x}}$, $v = \frac{y}{D_{u,y}}$, $w = \frac{z}{D_{u,z}}$ [S1, unofficial].
      ii. Sample $T_i$ at $(u, v, w)$ using linear clamping to handle resolution mismatches [S1, unofficial].
      iii. Extract the scalar value (e.g., red channel `.r`) [S1, unofficial].
      iv. Apply required normalization (e.g., dividing by a constant $K$) [S1, unofficial].
      v. Store the result in channel $c_i$ of $T_{united}[x, y, z]$ [S1, unofficial].
4. **Shader Unpacking:** In the rendering shader, sample $T_{united}$ at normalized coordinate $(u, v, w)$ to retrieve all attributes simultaneously [S1, unofficial].

**Formulas:**
- Sampling a channel $c$ (mapped from source $T_c$) at unified coordinate $(x, y, z)$:
  $$
  \text{value}_c = T_c.\text{SampleLevel}(\text{sampler}, \left( \frac{x}{D_{u,x}}, \frac{y}{D_{u,y}}, \frac{z}{D_{u,z}} \right), 0).\text{channel}_c
  $$
  Where $\text{sampler}$ uses linear filtering and clamp addressing [S1, unofficial].
- Normalization (example for mask):
  $$
  w = \frac{\text{mask\_sample}}{32.0}
  $$
  [S1, unofficial]

**Parameters:**
- $D_{u,x}, D_{u,y}, D_{u,z}$: Dimensions of the unified texture. Must be $\ge$ max dimension of any source texture [S1, unofficial].
- Texture Format: RGBA32 (8-bit per channel) is typical [S2, unofficial][S3].
- Sampling Mode: Linear clamping is recommended to handle resolution differences between source textures [S1, unofficial].

**Edge Cases and Pitfalls:**
- **2-Channel Performance:** A 2-channel volume texture is usually much slower on multiple vendors' GPUs and should be avoided. Pack into a 3-channel texture with a zero-padded extra channel, or use two 1-channel textures if the padded channel requires too much texture RAM [S2, unofficial].
- **Channel Limit:** Only 4 channels are available in standard RGBA. For more attributes, separate textures or a different packing strategy is required [S2, unofficial].
- **Precision Loss:** Storing data in 8-bit channels causes quantization [S3].
- **Resolution Mismatch:** Linear sampling across normalized coordinates handles different resolutions but may blur high-frequency details if the unified texture is significantly larger than a source [S1, unofficial].

**Pseudocode:**
```python
def pack_textures_to_united(source_textures, unified_size):
    """
    Packs multiple 3D textures into a single RGBA 3D texture.
    source_textures: List of 4 or fewer 3D textures supporting standard sampling.
    unified_size: Tuple (x, y, z) dimensions of the output texture.
    """
    # Initialize output texture as a 3D array of zeros
    united_texture = [[[ [0.0, 0.0, 0.0, 0.0] for _ in range(unified_size[2])] 
                       for _ in range(unified_size[1])] 
                      for _ in range(unified_size[0])]
    
    for x in range(unified_size[0]):
        for y in range(unified_size[1]):
            for z in range(unified_size[2]):
                result = [0.0, 0.0, 0.0, 0.0]
                
                for i, src in enumerate(source_textures):
                    if i >= 4:
                        break  # Only 4 channels available
                    
                    # Calculate normalized coordinates
                    u = x / unified_size[0]
                    v = y / unified_size[1]
                    w = z / unified_size[2]
                    
                    # Standard graphics operation: linear interpolation with clamp addressing [G]
                    # sample = texture_sample_linear_clamp(src, u, v, w, mip_level=0)
                    val = src.sample_linear_clamp(u, v, w, 0)  # [G]
                    
                    # Apply normalization if needed (e.g., mask channel)
                    if i == 3:
                        val /= 32.0
                    
                    result[i] = val
                
                united_texture[x][y][z] = result
                
    return united_texture
```

## Subtopics

### [Texture Packing Strategy](3196-texture-packing-strategy.md)
Maps a single underlying volume dataset to multiple distinct GPU textures, each scaled by a specific scalar multiplier to reduce GPU memory consumption. It solves excessive memory usage when rendering high-resolution volumes with multiple attribute channels by avoiding raw voxel data duplication. Unlike [Texture Uniting (Multi-Channel Packing)](2470-texture-uniting-multi-channel-packing.md), which combines attributes into a single RGBA texture for simultaneous access, this strategy separates attributes into individual scalar textures to minimize memory bandwidth when attributes are accessed independently.

### PBR Material Channel Packing
Packs PBR material properties into standard texture formats: BaseColor and Alpha into RGBA, Metallic and Roughness into RGB (R=0, G=Roughness, B=Metallic) [S4, unofficial]. Packing BaseColor/Alpha: `np.concatenate([base_color, alpha], axis=-1)` [S4, unofficial]. Packing Metallic/Roughness: `np.concatenate([np.zeros_like(metallic), roughness, metallic], axis=-1)` [S4, unofficial]. Parameters include `alphaMode: 'OPAQUE'` and `doubleSided: True` if not remesh else False [S4, unofficial].

## Operating characteristics
- **Time Complexity:** Packing is $O(N \cdot D_u^3)$ where $N$ is the number of source textures and $D_u$ is the unified dimension [G]. Sampling is $O(1)$ per voxel, retrieving 4 values instead of 1, reducing memory bandwidth for multi-attribute access [S1, unofficial][S2, unofficial].
- **Memory Complexity:** Reduces memory overhead by eliminating redundant texture headers and allowing tighter packing [G]. However, if source textures have vastly different resolutions, the unified texture may waste space on lower-resolution channels [S2, unofficial].
- **Performance:** Improves performance when multiple attributes are accessed per voxel (e.g., density + noise + light) by reducing texture unit switches and sampling calls [S1, unofficial]. Texture sampling a single multi-channel texture is faster than sampling multiple independent textures due to better cache locality [S2, unofficial].
- **Scaling:** Linearly scales with unified volume resolution. GPU performance degrades if 2-channel formats are used; padding to 3 channels or splitting into 1-channel textures restores performance [S2, unofficial].
- **Strengths and Limitations:** Best when attributes are tightly coupled and accessed simultaneously per voxel [S1, unofficial][S2, unofficial]. Limited to 4 channels per texture, and 8-bit formats introduce quantization [S3]. Linear filtering across resolution boundaries may blur high-frequency details [S1, unofficial].
- **When to use:** Use when rendering volumes with multiple coincident attributes (noise, masks, densities) and cache locality is critical [S2, unofficial]. Avoid when attributes require different storage precisions, resolutions, or exceed 4 channels [S2, unofficial].

## Background
Used in volumetric rendering for smoke and clouds, where multiple noise functions (Perlin, Worley) and masks are required per voxel [S1, unofficial][S3]. Also used in custom volume apps (e.g., gloo-based fluorescence data with float16, and voxel-to-object ID maps with uint8 RGB) [S2, unofficial]. Applied in PBR material pipelines for packing material properties [S4, unofficial].
