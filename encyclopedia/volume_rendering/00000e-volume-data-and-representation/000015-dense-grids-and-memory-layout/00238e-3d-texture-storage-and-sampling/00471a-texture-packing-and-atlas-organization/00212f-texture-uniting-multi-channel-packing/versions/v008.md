# Texture Uniting (Multi-Channel Packing)

Also called: Multi-Channel Packing, Multi-Channel Volume Texture Optimization, Texture Packing/Unpacking Scheme

## Overview
Texture Uniting combines multiple separate 3D textures (e.g., noise, detail, light, mask) into a single RGBA 3D texture to optimize memory bandwidth and sampling efficiency [S1, unofficial]. It solves the problem of excessive texture unit usage and redundant sampling operations when rendering volumes with multiple attribute channels [S2, unofficial]. Unlike [Texture Packing Strategy](3196-texture-packing-strategy.md), which separates attributes into individual scalar textures to minimize memory bandwidth when accessed independently, this method packs semantic attributes into color channels of a single volume, allowing simultaneous access to all attributes at a single coordinate [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** $N$ source 3D textures ($T_1, T_2, \dots, T_N$), where $N \le 4$. Each source texture stores a single scalar value per voxel [S1, unofficial].
- **Outputs:** A single unified 3D texture $T_{united}$ with dimensions $D_{u,x} \times D_{u,y} \times D_{u,z}$ (assumed cubic) and format RGBA32 (8 bits per channel) [S1, unofficial][S3].

**Data Structures:**
- $T_{united}$: A 3D texture resource. Each voxel stores a `float4` vector [S1, unofficial].
- Coordinate mapping: The unified texture uses normalized coordinates $[0, 1]$ for sampling [S1, unofficial].

**Steps:**
1. **Determine Unified Dimensions:** Choose $D_{u,x}, D_{u,y}, D_{u,z}$ such that they are large enough to hold the highest-resolution source texture. The sources assume a cubic dimension $D_u$ [S1, unofficial].
2. **Initialize:** Clear $T_{united}$ to zero.
3. **Pack Channels:** For each voxel $(x, y, z)$ in $T_{united}$:
   a. Calculate normalized coordinates: $u = x / D_{u,x}$, $v = y / D_{u,y}$, $w = z / D_{u,z}$ [S1, unofficial].
   b. For each source texture $T_i$ (mapped to channel $c_i \in \{R, G, B, A\}$):
      i. Sample $T_i$ at $(u, v, w)$ using linear clamping sampling to handle resolution differences [S1, unofficial].
      ii. Extract the scalar value (e.g., red channel `.r`) [S1, unofficial].
      iii. Apply normalization if required (e.g., divide mask channel by 32.0) [S1, unofficial].
      iv. Store the result in channel $c_i$ of $T_{united}[x, y, z]$ [S1, unofficial].
4. **Shader Unpacking:** In the rendering shader, sample $T_{united}$ at normalized coordinate $(u, v, w)$ to retrieve all attributes simultaneously [S1, unofficial].

**Formulas:**
- Sampling a channel $c$ (mapped from source $T_c$) at unified coordinate $(x, y, z)$:
  $$ \text{value}_c = T_c.\text{SampleLevel}(\text{sampler\_linear\_clamp}, (u, v, w), 0).\text{channel}_c $$
  Where $u = x/D_{u,x}$, $v = y/D_{u,y}$, $w = z/D_{u,z}$, and the sampler uses linear filtering with clamp addressing [S1, unofficial].
- Normalization (example for mask):
  $$ w = \frac{\text{mask\_sample}}{32.0} $$
  [S1, unofficial]

**Parameters:**
- $D_{u,x}, D_{u,y}, D_{u,z}$: Dimensions of the unified texture. Must be $\ge$ max dimension of any source texture. Sources assume a cubic layout [S1, unofficial].
- Texture Format: RGBA32 (8 bits per channel) is standard [S3].
- Sampling Mode: Linear clamping is recommended to handle resolution differences between source textures [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Channel Performance:** A 2-channel volume texture is usually much slower on multiple vendors' GPUs and should be avoided. It is faster to pack into a 3-channel texture with a zero-padded extra channel, or use two 1-channel textures if the padded channel requires too much texture RAM [S2, unofficial].
- **Resolution Mismatch:** Linear sampling across normalized coordinates allows filtering across resolution boundaries, but may blur high-frequency details if the unified texture is significantly larger than a source texture [S1, unofficial].
- **Precision Loss:** Storing floating-point values in 8-bit channels causes quantization [S3].
- **Channel Limit:** Standard RGBA provides only 4 channels. Separate textures are required for more than 4 channels or different storage types/precisions [S2, unofficial].

**Pseudocode:**
```python
# Self-contained definitions for texture operations
class Texture3D:
    def __init__(self, width, height, depth):
        self.width = width
        self.height = height
        self.depth = depth
        self.data = [[[0.0 for _ in range(depth)] for _ in range(height)] for _ in range(width)]
    def sample(self, u, v, w):
        # Standard trilinear interpolation with clamp addressing on normalized coordinates [0,1] [G]
        ix = int(min(max(u * self.width, 0), self.width - 1))
        iy = int(min(max(v * self.height, 0), self.height - 1))
        iz = int(min(max(w * self.depth, 0), self.depth - 1))
        return Vector3D(self.data[ix][iy][iz])
    def set_pixel(self, x, y, z, value):
        self.data[x][y][z] = value

class Vector3D:
    def __init__(self, val):
        self.r = val
        self.g = 0.0
        self.b = 0.0
        self.a = 0.0

RGBA32 = "RGBA32" # 8 bits per channel format

def pack_textures_to_united(source_textures, unified_size):
    united_texture = Texture3D(unified_size[0], unified_size[1], unified_size[2])
    channels = ['R', 'G', 'B', 'A']

    for x in range(unified_size[0]):
        for y in range(unified_size[1]):
            for z in range(unified_size[2]):
                result = [0.0, 0.0, 0.0, 0.0]
                for i, src_tex in enumerate(source_textures):
                    if i >= 4:
                        break
                    u = x / unified_size[0]
                    v = y / unified_size[1]
                    w = z / unified_size[2]
                    sample_val = src_tex.sample(u, v, w)
                    val = sample_val.r
                    if i == 3:
                        val = val / 32.0
                    result[i] = val
                united_texture.set_pixel(x, y, z, result)
    return united_texture

def sample_united_texture(united_texture, u, v, w):
    sample = united_texture.sample(u, v, w)
    return sample.r, sample.g, sample.b, sample.a
```

## Subtopics

### [Texture Packing Strategy](3196-texture-packing-strategy.md)
Maps a single underlying volume dataset to multiple distinct GPU textures, each scaled by a specific scalar multiplier to reduce GPU memory consumption. It solves excessive memory usage when rendering high-resolution volumes with multiple attribute channels by avoiding raw voxel data duplication. Unlike Texture Uniting, which combines attributes into a single RGBA texture for simultaneous access, this strategy separates attributes into individual scalar textures to minimize memory bandwidth when attributes are accessed independently.

### PBR Material Channel Packing
Packs PBR material properties into standard texture formats: BaseColor and Alpha into RGBA, Metallic and Roughness into RGB (R=0, G=Roughness, B=Metallic) [S4, unofficial]. Packing BaseColor/Alpha: `np.concatenate([base_color, alpha], axis=-1)`. Packing Metallic/Roughness: `np.concatenate([np.zeros_like(metallic), roughness, metallic], axis=-1)` [S4, unofficial]. Parameters include `alphaMode: 'OPAQUE'` and `doubleSided: True` if not remesh else False [S4, unofficial].

## Operating characteristics
- **Sampling Performance:** Sampling a single multi-channel texture is faster than sampling multiple independent textures due to better cache locality [S2, unofficial].
- **Memory Overhead:** Reduces memory overhead by eliminating redundant texture headers and allowing tighter packing. However, if source textures have vastly different resolutions, the unified texture may waste space on lower-resolution channels [S2, unofficial].
- **Limitations:** Limited to 4 channels per texture. Linear filtering across resolution boundaries can cause blurring if not managed. Precision loss occurs with 8-bit channels [S3]. 2-channel textures are notably slower on many GPUs [S2, unofficial].

## Background
Used in custom volume applications (e.g., gloo) for fluorescence data and voxel-to-object ID maps [S2, unofficial]. Popularized in Unity-based volumetric tutorials for efficient noise generation and sampling, where techniques like horizontal packing of 128x128x128 3D textures into 16384x128 2D images are employed [S3]. Also applied in PBR material pipelines for packing material properties [S4, unofficial].
