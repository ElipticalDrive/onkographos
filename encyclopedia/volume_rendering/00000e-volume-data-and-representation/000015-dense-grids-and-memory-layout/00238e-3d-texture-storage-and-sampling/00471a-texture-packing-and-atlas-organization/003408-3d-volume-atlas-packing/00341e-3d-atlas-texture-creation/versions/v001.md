# 3D Atlas Texture Creation

Also called: createAtlasTexture

## Overview
Creates a half-precision 3D atlas texture and updates shader uniforms based on volume parameters [S1, unofficial]. It packs multiple volumes or timesteps into a single 3D texture, building on [3D Volume Atlas Packing](7158-3d-volume-atlas-packing.md) which handles the initial grid resolution calculation and buffer allocation.

## How it works
**Inputs:**
- `volumeResolution`: `THREE.Vector3` representing the 3D resolution (voxel count) of one volume [S1, unofficial].
- `volumeOrigin`: `THREE.Vector3` representing the 3D world-space origin of the volume [S1, unofficial].
- `voxelSize`: `THREE.Vector3` representing the physical 3D size of one voxel [S1, unofficial].
- `timeCount`: `number` representing the total number of timesteps [S1, unofficial].
- `textureFilter`: `number` (default: `THREE.LinearFilter`) representing the texture interpolation mode [S1, unofficial].

**Data Structures:**
The method relies on the flat `Uint16Array` buffer allocated by the parent packing step. The shader uniforms are updated as follows:
- `atlasResolution`: `vec3` storing the number of volumes in X, Y, Z dimensions of the atlas [S1, unofficial].
- `volumeResolution`: `vec3` storing the voxel count per volume [S1, unofficial].
- `voxelSize`: `vec3` storing the physical size of a single voxel [S1, unofficial].
- `timeCount`: `float` storing the number of timesteps/volumes stored in the atlas [S1, unofficial].

**Steps:**
1. Allocate a half-precision (16-bit float) 3D texture using the resolution derived from the parent packing step [S1, unofficial].
2. Upload the packed volume data from the `Uint16Array` buffer into the texture [S1, unofficial].
3. Set the texture filtering mode to `textureFilter` [S1, unofficial].
4. Update the following shader uniforms:
   - `atlasResolution`: Set to the 3D grid dimensions of the atlas [S1, unofficial].
   - `volumeResolution`: Set to the input `volumeResolution` [S1, unofficial].
   - `voxelSize`: Set to the input `voxelSize` [S1, unofficial].
   - `timeCount`: Set to the input `timeCount` [S1, unofficial].

**Sampling Formula:**
The shader uses the following logic to sample values, assuming the origin is centered on the first voxel [S1, unofficial]:

$$
\text{volumeVoxel} = \frac{\text{position} - \text{volumeOrigin}}{\text{voxelSize}}
$$

$$
\text{volumeUv} = \frac{\text{volumeVoxel} + 0.5}{\text{volumeResolution}}
$$

$$
\text{uv0} = \text{volumeUvOffset0} + \frac{\text{volumeUv}}{\text{atlasResolution}}
$$

$$
\text{uv1} = \text{volumeUvOffset1} + \frac{\text{volumeUv}}{\text{atlasResolution}}
$$

$$
\text{value0} = \text{texture}(\text{volumeAtlas}, \text{uv0}).r
$$

$$
\text{value1} = \text{texture}(\text{volumeAtlas}, \text{uv1}).r
$$

$$
\text{return} \text{mix}(\text{value0}, \text{value1}, \text{volumeT})
$$

**Edge Cases:**
- Precision: Uses half-precision (16-bit) storage, which may limit dynamic range compared to 32-bit floats [S1, unofficial].
- Boundary: The sampling assumes the volume origin is centered on the first voxel [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Uses half-precision (16-bit) per voxel [S1, unofficial].
- **Strengths:** Efficiently packs multiple volumes into a single texture object [S1, unofficial].
- **Limitations:** Half-precision may introduce quantization artifacts [S1, unofficial].
