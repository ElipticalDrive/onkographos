# Volume Interleaving

Also called: Bit Interleaving, Coordinate Bit Interleaving

## Overview
Volume Interleaving is a memory layout optimization technique designed to reduce cache misses during ray-casting volume rendering [S1]. It solves the problem of poor spatial locality in standard row-major or column-major storage by reordering voxel addresses so that spatially adjacent voxels are stored contiguously in linear memory [S1]. Unlike sibling methods that focus on bank allocation or miniblock organization, Volume Interleaving achieves this through a deterministic bit-permutation of coordinates, specifically mapping 3D indices to a linear address via bit interleaving [S1].

## How it works
**Inputs:**
- 3D voxel coordinates $(X, Y, Z)$, where each coordinate is an integer [G].
- Block size parameter $B=32$ [S1].

**Outputs:**
- Linear memory address $A$ corresponding to the voxel at $(X, Y, Z)$ [G].

**Data Structures:**
- A 32-entry lookup table $T$, indexed by 5-bit values ($0 \dots 31$) [S1].

**Method:**
The volume is decomposed into small blocks of $32^3$ samples (32×32×32 voxels) [S1]. The memory address is generated by treating the block index and the intra-block offset separately, then combining them [G].

1.  **Block Index Calculation:**
    The coordinates are divided by the block size $B=32$ [G]. The integer quotients form the block index [G]. Let $X_{block} = \lfloor X / 32 \rfloor$, $Y_{block} = \lfloor Y / 32 \rfloor$, $Z_{block} = \lfloor Z / 32 \rfloor$ [G]. These higher-order bits are grouped by dimension in the final address [S1].

2.  **Lower Bit Interleaving:**
    The lower 5 bits of each coordinate ($X_{4\dots0}, Y_{4\dots0}, Z_{4\dots0}$) are interleaved to form the intra-block offset [S1]. The specific interleaving pattern maps the bits such that the least significant bits of the address come from the least significant bits of the coordinates, alternating across dimensions [G].

3.  **Address Construction:**
    The final linear address $A$ is constructed by concatenating the higher-order block bits (grouped by dimension) with the interleaved lower bits [S1]. The mapping formula is:
    $$ (X_{n \dots 0}, Y_{n \dots 0}, Z_{n \dots 0}) \implies Z_{n \dots 5} Y_{n \dots 5} X_{n \dots 5} Z_4 Y_4 X_4 \dots Z_0 Y_0 X_0 $$
    [S1]. Here, $X_{n \dots 5}$ denotes the bits of $X$ from bit $n$ down to bit 5 [G]. The lower 5 bits ($4 \dots 0$) are interleaved as $Z_k Y_k X_k$ for $k=0 \dots 4$ [S1].

4.  **Implementation via Lookup Table:**
    A 32-entry lookup table is used to perform the interleaving of the five lower bits efficiently using binary operators [S1]. This avoids iterative bit-shifting for the lower portion [G].

**Pseudocode:**
```python
def volume_interleaving_address(x, y, z):
    """
    Computes the linear memory address for a voxel at (x, y, z)
    using Volume Interleaving with block size 32 [S1].
    """
    B = 32
    
    # Extract block indices (higher bits) and lower 5 bits [G]
    x_block, x_low = divmod(x, B)
    y_block, y_low = divmod(y, B)
    z_block, z_low = divmod(z, B)
    
    # Interleave lower 5 bits: pattern Z_k Y_k X_k for k=0..4 [S1]
    # LSB (bit 0) is X_0, bit 1 is Y_0, bit 2 is Z_0, etc. [G]
    offset = 0
    for k in range(5):
        offset |= ((x_low >> k) & 1) << (2 * k)
        offset |= ((y_low >> k) & 1) << (2 * k + 1)
        offset |= ((z_low >> k) & 1) << (2 * k + 2)
        
    # Combine block indices (higher bits grouped by dimension: Z, then Y, then X) [S1]
    # Each block index is shifted by 15 bits (5 bits per dimension * 3 dimensions) [G]
    address = (z_block << 15) | (y_block << 15) | (x_block << 15) | offset
    return address
```

**Parameters:**
- Block size: $32^3$ samples (32×32×32 voxels) [S1].

**Edge Cases:**
- Coordinates must be non-negative integers [G].
- The number of bits $n$ must be sufficient to cover the volume dimensions [G].

## Subtopics

### [Parallel Reordering of Interleaved Voxel Bits](3361-parallel-reordering-of-interleaved-voxel-bits.md)
This method reorders two integers containing interleaved 4-bit groups representing voxel indices into contiguous blocks, specifically separating even-indexed voxels (0, 2, 4, 6) from odd-indexed voxels (1, 3, 5, 7). The technique shifts groups of information simultaneously in parallel whenever possible to achieve the reordering.

## Operating characteristics
- **Time Complexity:** The address calculation is $O(1)$ per voxel, involving bitwise operations and table lookups [S1].
- **Memory Complexity:** The method requires a small 32-entry lookup table [S1]. The memory layout itself does not change the total storage size of the volume [G].
- **Performance:** The primary benefit is reduced cache misses during ray-casting [S1].
- **Strengths:** Improves spatial locality for 3D data access patterns typical in ray-casting [S1].
