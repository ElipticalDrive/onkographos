# Parallel Reordering of Interleaved Voxel Bits

Also called: Parallel Reordering of Interleaved 4-bit Groups, Parallel Reordering of Interleaved Voxel Groups

## Overview
This method reorders two integers containing interleaved 4-bit groups representing voxel indices into contiguous blocks, specifically separating even-indexed voxels (0, 2, 4, 6) from odd-indexed voxels (1, 3, 5, 7) [S1, unofficial][S2, unofficial]. The technique shifts groups of information simultaneously in parallel whenever possible to achieve the reordering [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** Two integers containing interleaved 4-bit groups. The first integer holds even-indexed voxels in a permuted order `[0, 2, 6, 4]`, and the second holds odd-indexed voxels `[1, 3, 5, 7]` [S1, unofficial][S2, unofficial].
*   **Output:** Two integers with contiguous 4-bit groups. The first contains even voxels in natural order `[0, 2, 4, 6]`, and the second contains odd voxels in natural order `[1, 3, 5, 7]` [S1, unofficial][S2, unofficial].

**Data Structures**
The method operates on fixed-width integer registers packing 4-bit groups [S1, unofficial][S2, unofficial]. The 32nd bit is reserved for other purposes and must be excluded or handled separately [S1, unofficial][S2, unofficial].

**Numbered Steps**
1.  Pack voxel indices into 4-bit groups within integer registers [S1, unofficial][S2, unofficial].
2.  Apply parallel bitwise shifts to align the interleaved groups simultaneously [S1, unofficial][S2, unofficial].
3.  Merge the shifted groups into their target contiguous positions using bitwise masks [G].

**Formulas**
Not given in the sources. The permutation is defined explicitly as `[0, 2, 6, 4] → [0, 2, 4, 6]` for even voxels and `[1, 3, 5, 7] → [1, 3, 5, 7]` for odd voxels [S1, unofficial][S2, unofficial].

**Pseudocode**
```python
def reorder_interleaved_voxels(even_voxels, odd_voxels):
    """
    Reorders interleaved 4-bit groups.
    Input: even_voxels contains 4-bit groups [0, 2, 6, 4]
           odd_voxels contains 4-bit groups [1, 3, 5, 7]
    Output: even_voxels contains [0, 2, 4, 6]
            odd_voxels contains [1, 3, 5, 7]
    The source specifies shifting groups simultaneously in parallel [S1, unofficial][S2, unofficial].
    The permutation requires swapping the 3rd and 4th 4-bit groups.
    Exact shift counts and masks are not given in the sources [G].
    """
    # Assume groups are packed in the lower 16 bits: [g3, g2, g1, g0]
    # Input: g3=0, g2=2, g1=6, g0=4. Target: g3=0, g2=2, g1=4, g0=6.
    # Swap g1 and g0 using parallel shifts and masks.
    MASK_G1 = 0x00000F00
    MASK_G0 = 0x000000F0

    g1 = (even_voxels & MASK_G1) >> 4
    g0 = (even_voxels & MASK_G0) >> 0

    # Clear original positions and place swapped values
    even_voxels = (even_voxels & ~(MASK_G1 | MASK_G0)) | (g1 << 0) | (g0 << 4)

    # Odd voxels are already in order [1, 3, 5, 7] per the source [S1, unofficial][S2, unofficial]
    return even_voxels, odd_voxels
```

**Parameters and Edge Cases**
*   **Bit Width:** The method operates on 4-bit groups [S1, unofficial][S2, unofficial]. For density computation, 28 bits per color channel are used (the largest multiple of four below 32), resulting in 960 slices instead of 1024 [S1, unofficial][S2, unofficial].
*   **32nd Bit:** The highest bit (32nd bit) is reserved and should be excluded [S1, unofficial][S2, unofficial]. For solid voxelization, the 1D texture is modified to exclude it, allowing 992 slices in a single pass instead of 1024 [S1, unofficial][S2, unofficial].
*   **Precision:** The method uses exact integer bit manipulation, so no floating-point precision issues occur [G].

## Operating characteristics
*   **Performance:** The reordering is effectively free in DX9 implementations due to cache behavior, while DX10 implementations incur a minor cost, causing approximately a 10% variation in overall results [S2, unofficial].
*   **Complexity:** The operation runs in $O(1)$ time per pair of integers, relying on constant-time bitwise shifts and masks [G].
*   **Strengths:** Executes in parallel on GPU hardware with minimal overhead relative to the voxelization pipeline [G].
*   **Limitations:** Specific to 4-bit groups and requires explicit handling of the 32nd bit when using 32-bit integers [S1, unofficial][S2, unofficial].

## Background
This technique is part of the Single-Pass GPU Solid Voxelization method introduced by Laine and Karras at SIGGRAPH 2005 [S1, unofficial][S2, unofficial].
