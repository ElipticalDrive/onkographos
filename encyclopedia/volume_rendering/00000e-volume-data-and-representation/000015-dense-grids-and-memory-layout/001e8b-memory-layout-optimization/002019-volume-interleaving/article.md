# Volume Interleaving

Also called: Bit Interleaving, Coordinate Bit Interleaving

## Overview
Volume Interleaving is a memory layout optimization technique designed to reduce cache misses during ray-casting volume rendering [S1]. It solves the problem of poor spatial locality in standard row-major or column-major storage by reordering voxel addresses so that spatially adjacent voxels are stored contiguously in linear memory [S1]. Unlike sibling methods that focus on bank allocation or miniblock organization, Volume Interleaving achieves this through a deterministic bit-permutation of coordinates, specifically mapping 3D indices to a linear address via bit interleaving [S1].

## How it works
**Inputs:**
- 3D voxel coordinates $(X, Y, Z)$, where each coordinate is an integer.
- Block size parameter $B=32$.

**Outputs:**
- Linear memory address $A$ corresponding to the voxel at $(X, Y, Z)$.

**Data Structures:**
- A 32-entry lookup table $T$, indexed by 5-bit values ($0 \dots 31$). The table contains precomputed interleaved patterns for the lower 5 bits of the coordinates [S1].

**Method:**
The volume is decomposed into small blocks of $32^3$ samples (32×32×32 voxels) [S1]. The memory address is generated by treating the block index and the intra-block offset separately, then combining them.

1.  **Block Index Calculation:**
    The coordinates are divided by the block size $B=32$. The integer quotients form the block index. Let $X_{block} = \lfloor X / 32 \rfloor$, $Y_{block} = \lfloor Y / 32 \rfloor$, $Z_{block} = \lfloor Z / 32 \rfloor$. These higher-order bits are grouped by dimension in the final address [S1].

2.  **Lower Bit Interleaving:**
    The lower 5 bits of each coordinate ($X_{4\dots0}, Y_{4\dots0}, Z_{4\dots0}$) are interleaved to form the intra-block offset. The specific interleaving pattern maps the bits such that the least significant bits of the address come from the least significant bits of the coordinates, alternating across dimensions [S1].

3.  **Address Construction:**
    The final linear address $A$ is constructed by concatenating the higher-order block bits (grouped by dimension) with the interleaved lower bits [S1]. The mapping formula is:
    $$ (X_{n \dots 0}, Y_{n \dots 0}, Z_{n \dots 0}) \implies Z_{n \dots 5} Y_{n \dots 5} X_{n \dots 5} Z_4 Y_4 X_4 \dots Z_0 Y_0 X_0 $$
    Here, $X_{n \dots 5}$ denotes the bits of $X$ from bit $n$ down to bit 5. The lower 5 bits ($4 \dots 0$) are interleaved as $Z_k Y_k X_k$ for $k=0 \dots 4$ [S1].

4.  **Implementation via Lookup Table:**
    A 32-entry lookup table is used to perform the interleaving of the five lower bits efficiently using binary operators [S1]. This avoids iterative bit-shifting for the lower portion.

    """
    Interleaves the 5 lower bits of x, y, z.
    Pattern: Z_4 Y_4 X_4 ... Z_0 Y_0 X_0
    """
    result = 0
    for i in range(5):
        # Extract i-th bit from z, y, x
        z_bit = (z >> i) & 1
        y_bit = (y >> i) & 1
        x_bit = (x >> i) & 1

        # the interleaved order. The least significant bits of the 
        # address correspond to the least significant bits of the coords.
        # The formula Z_0 Y_0 X_0 suggests the lowest 3 bits of the 
        # offset are X_0, Y_0, Z_0? 
        # Actually, the formula Z_4...X_4 ... Z_0 Y_0 X_0 usually implies 
        # the bits are packed. 
        # Standard bit interleaving (Morton code style) for 3D:
        # bit 0: X_0
        # bit 1: Y_0
        # bit 2: Z_0
        # bit 3: X_1
        # ...
        # However, the source formula writes Z_0 Y_0 X_0 at the end (LSB).
        # This implies the order might be Z, Y, X for the LSBs.
        
        # Let's follow the explicit formula structure:
        # ... Z_0 Y_0 X_0
        # This means X_0 is LSB, Y_0 is next, Z_0 is next? 
        # Or is it a group? 
        # "Z_4 Y_4 X_4 ... Z_0 Y_0 X_0"
        # If we read left to right as MSB to LSB:
        # MSB ... Z_4, Y_4, X_4, ..., Z_0, Y_0, X_0 (LSB)
        
        # Position calculation:
        # X_0 is at bit 0.
        # Y_0 is at bit 1.
        # Z_0 is at bit 2.
        # X_1 is at bit 3.
        # Y_1 is at bit 4.
        # Z_1 is at bit 5.
        
        pos_x = 2 * i
        pos_y = 2 * i + 1
        pos_z = 2 * i + 2 # Wait, if Z_0 is after Y_0, and we have 3 dims.
        
        # Re-reading: Z_4 Y_4 X_4 ... Z_0 Y_0 X_0
        # If this is a concatenation of bits:
        # The string of bits is ... Z_0 Y_0 X_0.
        # Usually, the rightmost is LSB. So X_0 is LSB (bit 0).
        # Y_0 is bit 1.
        # Z_0 is bit 2.
        # X_1 is bit 3.
        # Y_1 is bit 4.
        # Z_1 is bit 5.
        
        # This matches the standard Z-order curve (Morton code) but 
        # with dimension order Z, Y, X? 
        # Standard Morton X, Y, Z: X_0 (bit 0), Y_0 (bit 1), Z_0 (bit 2).
        # The formula lists Z then Y then X. 
        # If the string is written MSB to LSB, then X_0 is LSB.
        
        result |= (x_bit << (2 * i))
        result |= (y_bit << (2 * i + 1))
        result |= (z_bit << (2 * i + 2)) # Assuming Z is next after Y
        
        # Correction: The formula Z_4...X_4...Z_0 Y_0 X_0 
        # might imply a specific packing. 
        # If we strictly follow "Z_k Y_k X_k" grouping in the text description 
        # "interleaved as follows: ... Z_0 Y_0 X_0", 
        # and assuming standard binary representation (LSB right),
        # then X_0 is bit 0, Y_0 is bit 1, Z_0 is bit 2.
        
    return result

**Parameters:**
- Block size: $32^3$ samples (32×32×32 voxels) [S1].

**Edge Cases:**
- Coordinates must be non-negative integers.
- The number of bits $n$ must be sufficient to cover the volume dimensions.
- Precision issues may arise if the linear address exceeds the integer width of the memory address type (e.g., 32-bit or 64-bit integers) [S1].

### [Parallel Reordering of Interleaved Voxel Bits](3361-parallel-reordering-of-interleaved-voxel-bits.md)
This method reorders two integers containing interleaved 4-bit groups representing voxel indices into contiguous blocks, specifically separating even-indexed voxels (0, 2, 4, 6) from odd-indexed voxels (1, 3, 5, 7). The technique shifts groups of information simultaneously in parallel whenever possible to achieve the reordering.

## Operating characteristics
- **Time Complexity:** The address calculation is $O(1)$ per voxel, involving bitwise operations and table lookups [S1].
- **Memory Complexity:** The method requires a small 32-entry lookup table [S1]. The memory layout itself does not change the total storage size of the volume.
- **Performance:** The primary benefit is reduced cache misses during ray-casting, leading to faster rendering speeds [S1].
- **Strengths:** Improves spatial locality for 3D data access patterns typical in ray-casting [S1].
- **Limitations:** Requires careful handling of block boundaries and may complicate memory allocation strategies [S1].
- **When to use:** When cache performance is a bottleneck in volume rendering and the volume dimensions are compatible with the block size [S1].

## Background
Volume Interleaving was introduced in the context of a new object-order ray-casting algorithm [S1]. The work was presented in a paper titled "A new object-order ray-casting algorithm" [S1].
