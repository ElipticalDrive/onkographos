# Memory-Insensitive Rendering


## Overview
Memory-Insensitive Rendering (MIR) is a completely disk-based technique for rendering arbitrarily large unstructured volumetric grids on machines with limited main memory [S1, unofficial]. It solves the problem of rendering datasets that exceed available RAM by avoiding random access to the dataset, requiring only a small, constant amount of main memory [S1, unofficial]. Unlike its siblings which optimize memory layout for in-core processing, MIR relies on external sorting and sequential disk I/O to achieve scalability [S1, unofficial].

## How it works
**Inputs:**
*   Normalized tetrahedron file (containing vertex positions and scalar values for each tetrahedron).
*   Transformation matrix.
*   Screen resolution (defining pixel IDs $\rho_i$).
*   Transfer functions for lighting and compositing.

**Outputs:**
*   Rendered image.

**Data Structures:**
1.  **Vertex File:** Binary file containing vertex records. Each record holds the 3D position $(x, y, z)$ and scalar field value.
2.  **Tetrahedra File (Normalized):** Binary file containing $t$ records. Each record holds the actual vertex values (positions and scalars) for the 4 vertices of a tetrahedron, rather than indices.
3.  **Intersection File:** Binary file containing records generated during Step 1. Each record contains:
    *   Pixel ID $\rho_i$ (integer).
    *   Entry depth $z_0$ (float).
    *   Exit depth $z_1$ (float).
    *   Interpolated scalar field value (float, for lighting).

**Preprocessing: Normalization**
If the input data uses an indexed mesh format (vertices with coordinates/scalars; tetrahedra with 4 integer indices), it must be normalized to dereference pointers [S1, unofficial].
1.  Create two binary files: one for vertices, one for tetrahedra.
2.  For each of the 4 vertex indices in the tetrahedra file, externally sort the tetrahedra file by that index using external mergesort. This takes time $O(t \log t)$ [S1, unofficial].
3.  Perform a synchronous scan of the vertex file and the sorted tetrahedra file, reading one record at a time to output the dereferenced position and scalar field values. This takes time $O(v + t)$ because references are sorted [S1, unofficial].
4.  Repeat steps 2-3 for all 4 vertex indices. The final tetrahedra file contains $t$ records with actual vertex values [S1, unofficial].

**Rendering Steps:**

1.  **Ray Intersection Generation:**
    Read each tetrahedron from the normalized file. Transform it with the specified transformation matrix. Compute all ray intersections for the screen resolution. For each pixel $\rho_i$ intersecting the cell in the interval $[z_0, z_1]$, output two records: $(\rho_i, z_0)$ and $(\rho_i, z_1)$. Also save an interpolated scalar field value for lighting. Memory usage is minimal, holding only the cell description and temporary storage for one intersection [S1, unofficial].

2.  **External Sort:**
    Sort the intersection file using an external sort. The compare function sorts primarily on pixel ID $\rho_i$, and secondarily on the depth of intersection $z$. This ensures records for a particular pixel are sequential and ordered by increasing depth [S1, unofficial].

3.  **Compositing:**
    Traverse the sorted file. Use the transfer functions to light and composite the samples, which are already in the correct front-to-back order [S1, unofficial].

**Pseudocode:**

```python
def memory_insensitive_rendering(normalized_tetra_file, transform_matrix, screen_resolution, transfer_functions):
    """
    Renders a large unstructured grid using disk-based processing.
    
    Args:
        normalized_tetra_file: Path to the normalized tetrahedron file.
        transform_matrix: 4x4 transformation matrix.
        screen_resolution: Tuple (width, height) defining pixel grid.
        transfer_functions: Functions for lighting and compositing.
        
    Returns:
        Rendered image buffer.
    """
    
    # Step 1: Generate Ray Intersections
    # Output file for intersections
    intersection_file = open("intersections.bin", "wb")
    
    # Open normalized tetrahedron file
    with open(normalized_tetra_file, "rb") as tetra_f:
        while True:
            tetra_record = read_tetra_record(tetra_f)
            if not tetra_record:
                break
            
            # Transform tetrahedron vertices
            transformed_vertices = [transform(v, transform_matrix) for v in tetra_record.vertices]
            
            # Compute ray intersections for all pixels
            # For each pixel rho_i intersecting the tetrahedron in [z0, z1]:
            intersections = compute_tetra_ray_intersections(transformed_vertices, screen_resolution)
            
            for inter in intersections:
                rho_i = inter.pixel_id
                z0 = inter.entry_depth
                z1 = inter.exit_depth
                scalar_val = inter.interpolated_scalar
                
                # Write record: (rho_i, z0, z1, scalar_val)
                write_intersection_record(intersection_file, rho_i, z0, z1, scalar_val)
    
    intersection_file.close()
    
    # Step 2: External Sort
    # Sort primarily by pixel ID, secondarily by depth z
    sorted_intersection_file = external_sort("intersections.bin", 
                                             key=lambda rec: (rec.rho_i, rec.z0))
    
    # Step 3: Compositing
    image = initialize_image(screen_resolution)
    
    with open(sorted_intersection_file, "rb") as sorted_f:
        current_pixel = -1
        front_to_back_samples = []
        
        while True:
            record = read_intersection_record(sorted_f)
            if not record:
                break
            
            # Handle pixel boundary
            if record.rho_i != current_pixel:
                # Composite previous pixel if exists
                if current_pixel != -1:
                    composite_pixel(image, current_pixel, front_to_back_samples, transfer_functions)
                
                current_pixel = record.rho_i
                front_to_back_samples = []
            
            # Add sample to current pixel's list (already sorted by depth)
            front_to_back_samples.append({
                'z': record.z0,
                'scalar': record.scalar_val
            })
        
        # Composite last pixel
        if current_pixel != -1:
            composite_pixel(image, current_pixel, front_to_back_samples, transfer_functions)
            
    return image

def compute_tetra_ray_intersections(vertices, screen_resolution):
    """
    Computes ray-tetrahedron intersections for all pixels.
    Returns list of intersection objects with pixel_id, entry_depth, exit_depth, scalar.
    """
    intersections = []
    width, height = screen_resolution
    
    # Iterate over all pixels
    for y in range(height):
        for x in range(width):
            pixel_id = y * width + x
            ray = generate_ray_from_pixel(x, y, screen_resolution)
            
            # Compute intersection interval [z0, z1]
            hit = ray_tetra_intersection(ray, vertices)
            
            if hit:
                z0, z1 = hit.entry, hit.exit
                # Interpolate scalar field value at midpoint or appropriate point
                scalar_val = interpolate_scalar(vertices, hit.point)
                
                intersections.append({
                    'pixel_id': pixel_id,
                    'entry_depth': z0,
                    'exit_depth': z1,
                    'interpolated_scalar': scalar_val
                })
                
    return intersections

def composite_pixel(image, pixel_id, samples, transfer_functions):
    """
    Composites samples for a single pixel using front-to-back alpha compositing.
    """
    color = [0.0, 0.0, 0.0]
    alpha = 0.0
    
    for sample in samples:
        # Apply transfer function to get color and opacity
        c, a = transfer_functions(sample['scalar'])
        
        # Front-to-back compositing
        # C_out = C_in + C_s * a_s * (1 - alpha_in)
        # alpha_out = alpha_in + a_s * (1 - alpha_in)
        
        color = [
            color[i] + c[i] * a * (1 - alpha) for i in range(3)
        ]
        alpha = alpha + a * (1 - alpha)
        
    # Write to image buffer
    image[pixel_id] = color
```

## Operating characteristics
*   **Time Complexity:** Normalization sorting takes $O(t \log t)$ using external mergesort. Synchronous scan takes $O(v + t)$ [S1, unofficial]. The rendering phase involves one scan over the grid, one external-memory sort, and a final accumulation scan [S1, unofficial].
*   **Memory Complexity:** Requires a small, constant amount of main memory [S1, unofficial].
*   **Disk Space:** Proportional to the number of actual ray stabbings between rays and cells [S1, unofficial].
*   **Strengths:** Can render arbitrarily large datasets on machines with very little memory [S1, unofficial]. Good load balancing characteristics [S1, unofficial].
*   **Limitations:** Substantially slower than in-core techniques like ZSWEEP, which can be up to an order of magnitude faster [S1, unofficial]. The external sort is generally the most time-consuming step [S1, unofficial].
*   **When to use:** When rendering unstructured grids that exceed available RAM and speed is not the primary constraint.
*   **When not to use:** When high performance is required and sufficient memory is available.

## Background
Memory-Insensitive Rendering was introduced as part of out-of-core rendering techniques for large, unstructured grids [S1, unofficial]. It is essentially an external memory version of techniques previously considered by [9, 6] [S1, unofficial]. While [9] discarded the technique as too inefficient due to lack of coherency between rays, [6] used it for its good load balancing characteristics, optimizing it to save space [S1, unofficial]. The method was implemented and tested on large datasets under different conditions [S1, unofficial].
