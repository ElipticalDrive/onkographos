# Double-buffered Voxel Storage and Routing

Also called: Double-buffered Voxel Storage, Graphics Memory Management and Voxel Routing, Read-Modify-Write Voxel Operations

## Overview
This method manages volumetric data for continuous display by dividing DDR SDRAM into color-specific (Red, Green, Blue) double buffers, allowing simultaneous scanning of an active buffer and modification of an inactive one [S1]. It distinguishes itself from sibling methods like [Skewed Memory Organization](2351-skewed-memory-organization-for-conflict-free-ray-access.md) by prioritizing logical compositing operations (AND, OR, XOR) via hardware-accelerated read-modify-write paths in voxel routers, rather than solely focusing on spatial conflict avoidance [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric or geometry-based 3-D data from a host PC (e.g., via SCSI) [S1].
*   **Output:** LVTTL data and control signals for Digital Micromirror Devices (DMDs) [S1].

**Data Structures and Layout:**
The graphics memory module consists of 6 Gbits of DDR SDRAM [S1].
*   **Total Capacity:** 6 Gbits (768 MB).
*   **Division:** Split into 3 colors $\times$ 2 buffers = 6 SDRAM buffers [S1].
*   **Buffer Size:** 128 MB per buffer [S1].
*   **Components:**
    *   3 Voxel Routers (one per color: Red, Green, Blue) [S1].
    *   1 Graphics Memory Manager [S1].
    *   All controllers implemented in FPGA [S1].

**Numbered Steps:**
1.  **Data Ingestion:** The Raster Engine accepts 3-D data from the host PC, converts it to the 3-D-display-specific coordinate system, and writes it into the graphics memory [S1].
2.  **Buffer Scheduling:** The Graphics Memory Manager schedules scanning of the "active" buffer for display while allowing random reads and writes to the "inactive" buffer [S1].
3.  **Routing:** Data is routed between the CPU, graphics memory, and DMDs via the three color-specific voxel routers [S1].
4.  **Read-Modify-Write (RMW):** To handle logic operations between new data and data already being displayed, the voxel routers perform automatic RMW operations [S1].
    *   The Raster Engine initiates each RMW with a single write instruction [S1].
    *   Supported operations: AND, OR, XOR, and masking [S1].
5.  **Instruction Buffering:** All RMW instructions are buffered in a FIFO within the FPGA and executed when scheduling allows, minimizing Raster Engine overhead [S1].
6.  **Display Formatting:** The DMD formatter electronics convert the LVTTL data and control signals into non-standard voltages required to operate the DMDs [S1].
7.  **Synchronization:** Screen speed and position are locked to volume scanning signals by the motor controller [S1].

**Pseudocode:**
```python
# Simplified representation of the hardware flow described in [S1]

class GraphicsMemoryManager:
    def __init__(self):
        # 6 buffers: 3 colors * 2 buffers
        # Buffer 0,1: Red (Active, Inactive)
        # Buffer 2,3: Green (Active, Inactive)
        # Buffer 4,5: Blue (Active, Inactive)
        self.buffers = [SDRAMBuffer(128 * 1024 * 1024) for _ in range(6)]
        self.active_color_idx = 0 # Index into [0, 2, 4]
        self.fifo = InstructionFIFO()

    def schedule_scan(self, color_idx):
        """Start scanning the active buffer for a specific color."""
        active_buf_idx = color_idx
        self.buffers[active_buf_idx].scan_out()

    def schedule_update(self, color_idx, new_data, operation):
        """Queue a read-modify-write operation on the inactive buffer."""
        inactive_buf_idx = color_idx + 1
        # The Raster Engine sends one write instruction
        self.fifo.enqueue({
            'buffer_idx': inactive_buf_idx,
            'data': new_data,
            'op': operation # AND, OR, XOR, MASK
        })

    def process_fifo(self):
        """FPGA executes queued instructions when scheduling allows."""
        while not self.fifo.is_empty():
            cmd = self.fifo.dequeue()
            active_buf = self.buffers[cmd['buffer_idx']]
            current_voxels = active_buf.read()
            
            # Perform hardware-accelerated logic
            if cmd['op'] == 'AND':
                new_voxels = current_voxels & cmd['data']
            elif cmd['op'] == 'OR':
                new_voxels = current_voxels | cmd['data']
            elif cmd['op'] == 'XOR':
                new_voxels = current_voxels ^ cmd['data']
            elif cmd['op'] == 'MASK':
                new_voxels = current_voxels & cmd['data']
            else:
                new_voxels = cmd['data'] # Default write
            
            active_buf.write(new_voxels)

class VoxelRouter:
    def __init__(self, color):
        self.color = color
        self.manager = GraphicsMemoryManager()

    def route_to_dmd(self):
        """Read from active buffer and send to formatter."""
        buf_idx = self.manager.get_active_buffer_index(self.color)
        data = self.manager.buffers[buf_idx].read_scan_line()
        return data

class RasterEngine:
    def __init__(self, host_data):
        self.host_data = host_data
        self.router_red = VoxelRouter('Red')
        self.router_green = VoxelRouter('Green')
        self.router_blue = VoxelRouter('Blue')
        self.manager = GraphicsMemoryManager()

    def process_frame(self):
        # Convert host data to voxel format
        voxel_data = self.convert_to_voxel(self.host_data)
        
        # Initiate RMW with single write instruction
        # Example: OR new voxels into the inactive buffer
        self.manager.schedule_update(
            color_idx=0, # Red
            new_data=voxel_data['red'],
            operation='OR'
        )
        
        # Trigger scheduling
        self.manager.process_fifo()
```

**Parameters:**
*   **SDRAM Type:** DDR SDRAM [S1].
*   **Buffer Size:** 128 MB [S1].
*   **Total Memory:** 6 Gbits [S1].
*   **Interface:** SCSI (from Host PC) [S1].

**Edge Cases and Pitfalls:**
*   **Scheduling Conflicts:** Instructions are buffered in a FIFO and performed "when scheduling allows" [S1]. If the FIFO fills up or scheduling is tight, updates may be delayed, potentially causing visual artifacts if the active buffer is swapped before all pending RMW operations complete.
*   **Precision:** Not given in the sources.
*   **Boundaries:** Screen speed and position are locked to volume scanning signals [S1]. Mismatch between motor controller and graphics memory manager timing can cause display errors.

## Subtopics

### Shared Memory Voxel Buffer Pipeline
A two-part architecture where a driver creates a voxel buffer in shared memory and scans it out in sync with rotation, while client code generates content and writes to the same buffer [S2, unofficial]. The driver initializes the shared memory voxel buffer, the client writes voxel data, and the driver reads the buffer and scans it out to LED panels synchronized to rotation [S2, unofficial]. Designed as a self-contained gadget (like a Vectrex) rather than a PC-peripheral, though a Python demo streams point clouds over WiFi [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Fixed at 6 Gbits (768 MB) total, divided into 6 x 128 MB buffers [S1].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths:** Very low overhead for the Raster Engine software due to hardware-accelerated RMW and FIFO buffering [S1]. Supports complex compositing (AND, OR, XOR) directly in the memory path [S1].
*   **Limitations:** Requires specific FPGA implementation for the memory manager and routers [S1]. Dependent on DMD formatter electronics for voltage conversion [S1].
*   **When to use:** When continuous display of volumetric data with frequent logical updates (compositing) is required, and hardware resources (FPGA) are available.
*   **When not:** When memory is strictly limited to less than 6 Gbits or when logical compositing is not needed.

## Background
Originated in a system described in SPIE Vol. 4297A, "Stereoscopic Displays and Virtual Reality Systems VIII" [S1]. The system uses a Raster Engine, Graphics Memory Module, and DMDs to render 3-D data. The graphics memory manager and voxel routers are implemented in FPGAs, with code stored in flash ROM for field upgrades [S1].
