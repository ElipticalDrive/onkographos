# Parallel Memory Access with Cubic Addressing
Also called: Memory Access Buffering (FIFO)

## Overview
Parallel Memory Access with Cubic Addressing is a hardware-aware memory layout and access strategy for interactive ray casting that distributes voxel data across eight parallel memory modules (banks) to maximize bandwidth and minimize pipeline stalls [S1]. It builds on [Cubic Addressing Scheme](7285-cubic-addressing-scheme.md) by ensuring that each trilinear interpolation neighborhood is served by distinct memory banks, allowing simultaneous access to all eight corner voxels [S1]. Unlike unbuffered approaches where frame time depends on the cumulative latency of all memory accesses, this method decouples memory retrieval from the rendering pipeline using FIFO buffers, making performance dependent only on the slowest individual SDRAM bank [S1].

## How it works
**Inputs:**
- Ray sample coordinates $(V_z, V_y, V_x)$ in the volume grid [S1].
- Sub-cube size $s$ (Not given in the sources for this specific method, but implied by the parent article).
- Eight parallel memory modules $M_0$ through $M_7$ [S1].

**Outputs:**
- Eight voxel values retrieved from the eight memory modules for trilinear interpolation [S1].
- Updated memory addresses for the next sample point [S1].

**Data Structures:**
- **Memory Layout:** The volume is partitioned into $s^3$ sub-cubes [S1]. Each sub-cube is distributed across the eight memory banks [S1]. Within each bank, voxels are stored such that each bank holds every second voxel along specific axes to facilitate the addressing scheme [S1].
- **FIFO Buffers:** For each of the eight memory modules, there are two FIFO buffers: one for addresses and one for voxel values [S1].

**Address Calculation:**
The core of the method is calculating the address for each of the eight memory modules $M_i$ based on the sample point $(V_z, V_y, V_x)$ [S1]. Since each memory module stores only every second voxel, the base coordinates are divided by two (implemented as a bitwise shift) [S1].

Let $A$ be the address for a specific memory module. The address is calculated as:
$$ A = s^3 AC + A_v $$
where $AC$ is the sub-cube address and $A_v$ is the voxel address within the sub-cube [S1].

The voxel address components $A_v$ depend on the memory module index $i$ and the sample coordinates [S1]. The coordinates used for address calculation are derived from $V_x, V_y, V_z$ [S1]. If the sample point coordinates are divisible by two, the coordinates used are the original coordinates divided by two [S1].

For a sample point $S$, the modified coordinates for each memory module are calculated as follows [S1]:

$$
\begin{aligned}
M_0 &: (M_x, M_y, M_z) \\
M_1 &: (M_x, M_y, M_z) \\
M_2 &: (M_x, M_y, M_z) \\
M_3 &: (M_x, M_y, M_z) \\
M_4 &: (M_x, M_y, M_z) \\
M_5 &: (M_x, M_y, M_z) \\
M_6 &: (M_x, M_y, M_z) \\
M_7 &: (M_x, M_y, M_z)
\end{aligned}
$$

*Note: The source text provides a fragmented formula for $M_0$ and $M_1$ and states "where..." but does not provide the complete explicit formulas for all eight modules in the provided excerpts [S1]. It states that for $M_0$, the x-coordinate is divided by two and the modulus by two of the x-coordinate is added, and for $M_1$, only the division by two is needed [S1]. The general pattern involves an address modification unit (incrementer) when the sample point is between two neighborhoods [S1].*

To complete the addressing scheme for implementation [G], each bank $M_i$ corresponds to a specific parity triplet $(p_x, p_y, p_z)$ derived from the binary representation of $i$: $p_x = i \bmod 2$, $p_y = (i \gg 1) \bmod 2$, $p_z = (i \gg 2) \bmod 2$. The adjusted coordinates for bank $i$ are:
$$ M_{x,i} = \lfloor V_x / 2 \rfloor + p_x, \quad M_{y,i} = \lfloor V_y / 2 \rfloor + p_y, \quad M_{z,i} = \lfloor V_z / 2 \rfloor + p_z $$

**Pipeline Operation:**
1. **Address Generation:** Calculate the eight memory addresses for the current sample point. This involves dividing the sample address by two and applying modulus operations to determine the specific voxel within the sub-cube for each bank [S1].
2. **FIFO Enqueue:** Push the calculated addresses into the address FIFO buffers for each of the eight memory modules [S1].
3. **Memory Access:** The memory controllers read from the SDRAMs. The voxel values are pushed into the voxel value FIFO buffers [S1].
4. **Interpolation:** The ray casting pipeline consumes voxel values from the voxel FIFO buffers to perform trilinear interpolation [S1].

**Edge Cases and Pitfalls:**
- **Cache Misses and Pipeline Stalls:** The pipeline stalls only when the voxel FIFO of a particular memory is empty at the same time that this memory requires a cache refill [S1].
- **Sub-cube Boundary Crossing:** When a ray crosses the y-z plane of the next $s^3$ sub-cube, memories $M_0, M_2, M_4, M_6$ change coordinates and refresh their cache, while $M_1, M_3, M_5, M_7$ remain in the current sub-cube [S1]. If cache refreshes happen in separate pipeline cycles, the pipeline stalls twice [S1].
- **Consecutive Cache Misses:** Depending on the ray direction, a particular memory can have up to 2 cache misses consecutively [S1].

**Pseudocode:**
```python
class FIFO:
    """Simple bounded FIFO buffer for addresses or voxel values."""
    def __init__(self, capacity):
        self.capacity = capacity
        self.buffer = []
    def enqueue(self, item):
        if len(self.buffer) < self.capacity:
            self.buffer.append(item)
    def dequeue(self):
        return self.buffer.pop(0) if self.buffer else None
    def is_empty(self):
        return len(self.buffer) == 0

def trilinear_interpolate(v000, v100, v010, v110, v001, v101, v011, v111, t):
    """Standard trilinear interpolation using fractional coordinates t=(tx,ty,tz)."""
    def lerp(a, b, f): return a + f * (b - a)
    c00 = lerp(v000, v100, t[0])
    c10 = lerp(v010, v110, t[0])
    c01 = lerp(v001, v101, t[0])
    c11 = lerp(v011, v111, t[0])
    c0 = lerp(c00, c10, t[1])
    c1 = lerp(c01, c11, t[1])
    return lerp(c0, c1, t[2])

def calculate_memory_addresses(vz, vy, vx, s):
    """
    Calculates the eight memory addresses for the parallel banks
    for a given sample point (vz, vy, vx) and sub-cube size s.
    """
    addresses = []
    # Base division by 2 (shift operation) [S1]
    base_x = vx >> 1
    base_y = vy >> 1
    base_z = vz >> 1

    for i in range(8):
        # Parity mapping for 8 banks [G]
        px = i & 1
        py = (i >> 1) & 1
        pz = (i >> 2) & 1

        # Adjusted coordinates: base + parity offset [S1, G]
        ax = base_x + px
        ay = base_y + py
        az = base_z + pz

        # Sub-cube address calculation
        subcube_x = vx // s
        subcube_y = vy // s
        subcube_z = vz // s
        subcube_addr = subcube_z * s * s + subcube_y * s + subcube_x

        # Voxel address within sub-cube (row-major layout) [G]
        voxel_addr = az * s * s + ay * s + ax
        
        # Final address: A = s^3 * AC + Av [S1]
        addresses.append(subcube_addr * (s * s * s) + voxel_addr)
    return addresses

def ray_cast_pipeline(rays, volume_data, s, fifo_capacity=4):
    """
    Simulates the ray casting pipeline with FIFO buffering and cubic addressing.
    """
    address_fifos = [FIFO(fifo_capacity) for _ in range(8)]
    value_fifos = [FIFO(fifo_capacity) for _ in range(8)]
    results = []

    for ray in rays:
        o, d, step = ray.origin, ray.direction, ray.step
        t = 0.0
        while t < ray.max_distance:
            # Compute integer grid coordinates [G]
            gx = int(o[0] + d[0] * t)
            gy = int(o[1] + d[1] * t)
            gz = int(o[2] + d[2] * t)

            # Boundary check [G]
            if not (0 <= gx < volume_data.width and 0 <= gy < volume_data.height and 0 <= gz < volume_data.depth):
                break

            # 1. Address Generation [S1]
            mem_addrs = calculate_memory_addresses(gz, gy, gx, s)

            # 2. FIFO Enqueue [S1]
            for i in range(8):
                address_fifos[i].enqueue(mem_addrs[i])

            # 3. Memory Access & Refill [S1]
            voxels = []
            for i in range(8):
                if value_fifos[i].is_empty():
                    if not address_fifos[i].is_empty():
                        addr = address_fifos[i].dequeue()
                        voxel = volume_data.read(addr)
                        value_fifos[i].enqueue(voxel)
                    else:
                        # Pipeline stall condition: FIFO empty and no address to fetch [S1]
                        voxel = 0.0
                else:
                    voxel = value_fifos[i].dequeue()
                voxels.append(voxel)

            # 4. Interpolation [S1]
            # Compute fractional part for interpolation weights [G]
            fx = (o[0] + d[0] * t) - gx
            fy = (o[1] + d[1] * t) - gy
            fz = (o[2] + d[2] * t) - gz
            t_weights = (fx, fy, fz)

            color = trilinear_interpolate(*voxels, t_weights)
            results.append(color)

            t += step
    return results
```

## Operating characteristics
- **Time Complexity:** The frame time is dependent on the performance of the slowest SDRAM bank, rather than the sum of all access times [S1]. This is a significant improvement over unbuffered memory access [S1].
- **Memory Complexity:** Requires eight parallel memory modules (or logical banks) and FIFO buffers for addresses and voxel values for each module [S1].
- **Performance:** Provides optimal performance with poor feasibility in terms of board space if 64 independent addresses are calculated (as in a 64-SDRAM solution) [S1]. The 8-bank solution is more practical and fits on a PC1 board, though it may suffer from unbalanced access times if not carefully designed [S1].
- **Strengths:** Minimizes pipeline stalling due to cache misses by buffering [S1]. Allows for high bandwidth utilization by accessing 8 voxels in parallel [S1].
- **Limitations:** Pipeline stalls can still occur if the FIFOs are empty and a cache refill is needed [S1]. Stalls can be compounded if cache refreshes happen in separate pipeline cycles (e.g., when crossing sub-cube boundaries) [S1].

## Background
This method was introduced in the context of low-cost memory architectures for PCI-based interactive ray casting [S1]. It addresses the limitations of traditional memory addressing and unbuffered parallel access by combining cubic addressing with parallel memory access and FIFO buffering [S1]. The work highlights the trade-off between optimal performance (requiring many memory modules) and practical feasibility (using fewer modules with banking) [S1].
