# Ghost Data Exchange for Interpolation and Gradients

Also called: Boundary Voxel Replication for Distributed Memory, Ghost Cell Stitching for Distributed Memory, Ghost Data (Halo) Exchange

## Overview
Ghost Data Exchange is a communication protocol used in distributed-memory volume rendering to maintain data consistency across node boundaries. It solves the problem of accessing neighboring voxels required for local resampling (trilinear interpolation) and gradient estimation (central differences) without incurring frequent inter-node fetches during the raycasting phase. It is chosen when the rendering algorithm requires spatial derivatives or multi-voxel sampling that extends beyond the local node's data partition.

## How it works
**Inputs and Outputs:**
- Input: Local volume data block (macro), neighbor volume data blocks (macros), communication topology.
- Output: Extended local volume data block including ghost layers, ready for raycasting.

**Data Structures:**
The local data structure is extended by adding a halo region around the boundary of the local macro.
- **Local Data:** $V_{local}$ of size $D_x \times D_y \times D_z$.
- **Ghost Layers:** Two layers of voxels are added to each face of the local block.
- **Total Extended Size:** $(D_x + 4) \times (D_y + 4) \times (D_z + 4)$ assuming 1-voxel wide ghost layers on all sides.

**Numbered Steps:**
1. **Identify Neighbors:** Determine which adjacent macros share a boundary with the local macro. This is based on the grid decomposition topology (e.g., 3D torus or grid).
2. **Prepare Send Buffers:** For each neighbor, identify the voxels in the local macro that are adjacent to the shared boundary. These are the "source" voxels for the neighbor's ghost layer.
3. **Prepare Receive Buffers:** Allocate space in the local ghost layers for data coming from each neighbor.
4. **Execute Exchange:** Perform a non-blocking or blocking MPI communication (e.g., `MPI_Sendrecv` or `MPI_Isend`/`MPI_Irecv`) to swap boundary voxels between neighbors.
   - Local boundary voxels are sent to the neighbor.
   - Neighbor's boundary voxels are received into the local ghost layers.
5. **Fill Ghost Layers:** The received data is placed into the appropriate ghost layer positions.
   - Layer 1 (Inner Ghost): Adjacent to the local data boundary.
   - Layer 2 (Outer Ghost): Adjacent to Layer 1.

**Formulas:**
- **Trilinear Interpolation:** Requires access to 8 neighboring voxels. If a ray samples a voxel at the boundary of the local macro, it may need voxels from the ghost layer.
  $$ V_{sample} = \sum_{i=0}^{1} \sum_{j=0}^{1} \sum_{k=0}^{1} w_{ijk} V_{x+i, y+j, z+k} $$
  where $V_{x+i, y+j, z+k}$ can reside in the local data or the ghost layers.
- **Central Difference Gradient:** Requires access to voxels at $x \pm 1, y \pm 1, z \pm 1$.
  $$ \frac{\partial V}{\partial x} \approx \frac{V_{x+1, y, z} - V_{x-1, y, z}}{2\Delta x} $$
  For a voxel at the local boundary, $V_{x+1, y, z}$ or $V_{x-1, y, z}$ may reside in the ghost layers.

**Parameters:**
- **Number of Ghost Layers:** 2 [S1, S2].
  - Layer 1: Supports trilinear interpolation of sampled values [S1, S2].
  - Layer 2: Supports computing the gradient field using central differences [S1, S2].
  - Note: Gradients are not precomputed for the dataset in the reference implementation [S2].

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** The outermost ghost layers (Layer 2) do not have neighbors to exchange with. They must be filled with a default value (e.g., zero, or replicated boundary values) [G].
- **Precision:** Ensure that the data type used for ghost layers matches the local data type to avoid precision loss during exchange.
- **Deadlock:** Use non-blocking communication or careful ordering of send/receive operations to avoid deadlock in distributed systems.

**Pseudocode:**
```python
def exchange_ghost_data(local_macro, neighbors, ghost_layers=2):
    """
    Exchanges ghost data between local macro and its neighbors.
    
    Args:
        local_macro: 3D array of shape (Dx, Dy, Dz)
        neighbors: List of tuples (neighbor_id, direction)
                   direction is a tuple (dx, dy, dz) indicating the relative position
        ghost_layers: Number of ghost layers (default 2)
        
    Returns:
        extended_macro: 3D array with ghost layers added
    """
    Dx, Dy, Dz = local_macro.shape
    
    # Create extended macro with ghost layers
    # Add 2 layers on each side: total size + 4 in each dimension
    extended_macro = np.zeros((Dx + 4, Dy + 4, Dz + 4), dtype=local_macro.dtype)
    
    # Copy local data to the center
    extended_macro[2:Dx+2, 2:Dy+2, 2:Dz+2] = local_macro
    
    # Initialize ghost layers with a default value (e.g., 0)
    # This handles the outermost ghost layers which have no neighbors
    extended_macro[:2, :, :] = 0
    extended_macro[Dx+2:, :, :] = 0
    extended_macro[:, :2, :] = 0
    extended_macro[:, Dy+2:, :] = 0
    extended_macro[:, :, :2] = 0
    extended_macro[:, :, Dz+2:] = 0
    
    # Exchange data with neighbors
    for neighbor_id, direction in neighbors:
        dx, dy, dz = direction
        
        # Determine which face of the local macro is shared with the neighbor
        # and which part of the ghost layer will receive the data
        
        # Example: if neighbor is in +x direction (dx=1, dy=0, dz=0)
        # Local macro's +x boundary is at index Dx+1 (in extended_macro)
        # Neighbor's -x boundary is at index 0 (in neighbor's extended_macro)
        
        if dx == 1:
            # Send local +x boundary to neighbor
            send_data = extended_macro[Dx+1, :, :]
            # Receive from neighbor's -x boundary into local -x ghost layer (Layer 2)
            # The neighbor's data will be placed in extended_macro[0, :, :]
            # This requires a communication call
            receive_data = mpi_comm.recv(source=neighbor_id, tag=0)
            extended_macro[0, :, :] = receive_data
            
        elif dx == -1:
            # Send local -x boundary to neighbor
            send_data = extended_macro[1, :, :]
            # Receive from neighbor's +x boundary into local +x ghost layer (Layer 2)
            receive_data = mpi_comm.recv(source=neighbor_id, tag=0)
            extended_macro[Dx+3, :, :] = receive_data
            
        # Similar logic for dy and dz directions...
        
    return extended_macro
```

## Subtopics

### [Data Replication for Adjacent Macros](14149-data-replication-for-adjacent-macros.md)
A data distribution strategy for adjacent macro groups where nodes replicate boundary voxels from neighbors to allow local resampling without inter-node fetches at data boundaries.

## Operating characteristics
- **Time Complexity:** The time complexity of the ghost data exchange is proportional to the surface area of the local macro, i.e., $O(D_y D_z + D_x D_z + D_x D_y)$ per neighbor.
- **Memory Complexity:** The memory overhead is proportional to the surface area of the local macro times the number of ghost layers. For 2 layers, the overhead is approximately $2 \times (D_y D_z + D_x D_z + D_x D_y)$ voxels.
- **Measured Performance:** The MPI-hybrid approach requires less exchange and storage of ghost data by roughly 40% across all concurrencies compared to MPI-only, because it uses fewer, larger blocks in its decomposition [S1, S2].
- **Strengths:** Reduces the frequency of inter-node communication during raycasting by providing necessary neighbor data locally.
- **Limitations:** Increases memory usage per node. The communication overhead can become significant if the local blocks are too small (high surface-to-volume ratio).
- **When to Use:** When the rendering algorithm requires trilinear interpolation or central difference gradients, and the data is distributed across multiple nodes.
- **When Not to Use:** When the rendering algorithm uses nearest-neighbor interpolation and does not require gradients, or when the data fits entirely within a single node's memory.

## Background
The concept of ghost data exchange in volume rendering was discussed in the context of MPI-hybrid parallelism for large, multi-core systems. The specific requirement of two layers of ghost data for trilinear interpolation and central difference gradients was detailed in research by M. Howison, E.W. Bethel, & H. Childs [S1, S2]. The comparison between MPI-hybrid and MPI-only approaches highlighted the efficiency gains from using fewer, larger blocks.
