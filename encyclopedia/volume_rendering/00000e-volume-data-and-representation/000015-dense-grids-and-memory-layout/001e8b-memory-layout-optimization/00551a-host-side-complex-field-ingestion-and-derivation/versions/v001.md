# Host-side Complex Field Ingestion and Derivation

Also called: ADR-0008/0010 ingestion contract, Complex Field Packing, Host-side volume data model & complex field derivation, deriveField

## Overview
This method defines the host-side ingestion contract for complex-valued volume data, packing a complex field into a flat interleaved array of floats and computing magnitude statistics [S1, unofficial]. It solves the problem of preparing complex scalar fields for GPU rendering by separating the host-side data transformation from the GPU-side derivation of magnitude and phase, which are computed in-shader at render time rather than stored on the host [S1, unofficial]. It sets itself apart from sibling methods by focusing on the specific data layout and statistical derivation required for complex fields, whereas siblings like [Voxel Buffer Memory Layout and Loop Optimization](1598-voxel-buffer-memory-layout-and-loop-optimization.md) focus on general voxel buffer access patterns and [Volume Interleaving](2174-volume-interleaving.md) focuses on general channel interleaving strategies.

## How it works
**Inputs and Outputs:**
- Input: A contiguous array of complex numbers of template precision $T$ (e.g., `std::complex<double>`), with size $N$.
- Input: `GridDims` structure defining the volume dimensions.
- Output: A flat interleaved array of floats `out` of size $2N$, where each complex number is split into real and imaginary components.
- Output: `MagnitudeRange` struct containing `minPositive` and `max` magnitude values.

**Data Structures:**
- `GridDims`:
  - Fields: `std::uint32_t nx, ny, nz`.
  - Indexing: 0-based, x-fastest. Index calculation: $idx = x + nx \times (y + ny \times z)$.
  - Helper: `dims.count()` returns $nx \times ny \times nz$.
- `MagnitudeRange`:
  - Fields: `float minPositive`, `float max`.
  - `minPositive`: The least strictly positive magnitude $|z|$ found in the input. If the field is all-zero, this is $0$.
  - `max`: The greatest magnitude $|z|$ found in the input. If the field is all-zero, this is $0$.

**Algorithm Steps:**
1. Validate that the input complex array size equals `dims.count()` and the output float array size equals $2 \times$ `dims.count()` [S1, unofficial].
2. Initialize `maxMag` to $0$ and `minPos` to $0$. Initialize a boolean flag `anyPositive` to `false` [S1, unofficial].
3. Loop over each element $i$ from $0$ to $N-1$:
   a. Let $z = \text{in}[i]$ be the complex number at index $i$ [S1, unofficial].
   b. Store the real part of $z$ in `out[2*i]` as a float [S1, unofficial].
   c. Store the imaginary part of $z$ in `out[2*i+1]` as a float [S1, unofficial].
   d. Compute the magnitude $mag = |z|$ using precision $T$ [S1, unofficial].
   e. Update `maxMag`: if $mag > \text{maxMag}$, set $\text{maxMag} = mag$ [S1, unofficial].
   f. Update `minPos`: if $mag > 0$:
      i. Set `anyPositive` to `true` [S1, unofficial].
      ii. If `anyPositive` was previously `false` or $mag < \text{minPos}$, set $\text{minPos} = mag$ [S1, unofficial].
4. Return `MagnitudeRange` with `minPositive` cast to float (or $0$ if `anyPositive` is false) and `max` cast to float [S1, unofficial].

**Pseudocode:**
```python
from typing import NamedTuple
import math

class GridDims:
    def __init__(self, nx: int, ny: int, nz: int):
        self.nx = nx
        self.ny = ny
        self.nz = nz

    def count(self) -> int:
        return self.nx * self.ny * self.nz

class MagnitudeRange(NamedTuple):
    minPositive: float
    max: float

def derive_field(in_complex, dims, out_float):
    """
    Derives magnitude statistics and packs complex field into interleaved floats.
    
    Args:
        in_complex: List of complex numbers (T).
        dims: GridDims object.
        out_float: List of floats (size 2 * dims.count()).
        
    Returns:
        MagnitudeRange object.
    """
    n = dims.count()
    
    # Validation [S1, unofficial]
    if len(in_complex) != n:
        raise ValueError("deriveField: input size != count")
    if len(out_float) != 2 * n:
        raise ValueError("deriveField: output size != 2*count")
        
    max_mag = 0.0
    min_pos = 0.0
    any_positive = False
    
    for i in range(n):
        z = in_complex[i]
        
        # Pack real and imaginary parts [S1, unofficial]
        out_float[2 * i] = float(z.real())
        out_float[2 * i + 1] = float(z.imag())
        
        # Compute magnitude in input precision T [S1, unofficial]
        mag = abs(z)
        
        # Update max magnitude [S1, unofficial]
        if mag > max_mag:
            max_mag = mag
            
        # Update min positive magnitude [S1, unofficial]
        if mag > 0:
            any_positive = True
            if not any_positive or mag < min_pos:
                min_pos = mag
                
    # Return results, casting to float [S1, unofficial]
    min_pos_out = float(min_pos) if any_positive else 0.0
    max_mag_out = float(max_mag)
    
    return MagnitudeRange(minPositive=min_pos_out, max=max_mag_out)
```

**Parameters:**
- $T$: Template parameter for input precision (e.g., `double`). The magnitude range is computed in precision $T$ before narrowing to float to preserve input-precision accuracy [S1, unofficial].

**Edge Cases and Pitfalls:**
- Input size must equal `dims.count()` and output size must equal $2 \times$ `dims.count()`. This is enforced via runtime assertions [S1, unofficial].
- If the field is all-zero, `minPositive` is $0$ [S1, unofficial].
- Precision loss can occur if $T$ is significantly larger than float, but the algorithm computes statistics in $T$ before casting to mitigate this [S1, unofficial].

## Subtopics

### Complex Field Packing
- **What it is:** The process of converting a complex-valued array into a flat, interleaved float array (real, imag, real, imag...) for GPU consumption.
- **What sets it apart:** It specifically handles the real/imaginary split and interleaving required for complex fields, unlike general interleaving methods.
- **When to choose it:** When rendering complex-valued volume data where magnitude and phase are derived on the GPU.
- **Link:** [Host-side Complex Field Ingestion and Derivation](2892-host-side-complex-field-ingestion-and-derivation.md)

### Magnitude Range Derivation
- **What it is:** Computing the minimum strictly positive and maximum magnitude values from the complex field.
- **What sets it apart:** It computes these statistics in the input precision $T$ before casting to float, ensuring accuracy for the rendering pipeline.
- **When to choose it:** When the rendering pipeline requires normalized or scaled magnitude values for transfer functions or lighting calculations.
- **Link:** [Host-side Complex Field Ingestion and Derivation](2892-host-side-complex-field-ingestion-and-derivation.md)

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of voxels. Each voxel is processed once to compute magnitude and pack data.
- **Memory Complexity:** $O(N)$ for the output interleaved array. The input array is read-only.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Linear scaling with the number of voxels.
- **Strengths:** Preserves input precision for statistics; separates host-side data preparation from GPU-side derivation; simple and deterministic.
- **Limitations:** Requires host-side memory for the full interleaved array; magnitude and phase are not pre-computed, requiring GPU computation at render time.
- **When to use it:** When rendering complex-valued volume data and the rendering pipeline supports in-shader derivation of magnitude and phase.
- **When not to use it:** When memory bandwidth is extremely constrained and pre-computing magnitude on the host is preferred, or when the data is not complex-valued.

## Background
This method originates from the `imaginaryVolumes` project, specifically associated with ADR-0008/0010 ingestion contracts [S1, unofficial]. It is part of the host-side data preparation pipeline for complex volume rendering, ensuring that complex fields are correctly formatted and statistically characterized before being uploaded to the GPU.
