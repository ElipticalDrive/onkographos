# Voxel Data Layout

Also called: Input Data Format, Node Data Layout, Voxel Cube, Voxel Data Structure (Naive), World Tensor

## Overview
Voxel Data Layout refers to the fundamental memory organization of voxel data in a dense 3D grid, typically implemented as a contiguous array or tensor indexed by world coordinates $[x, y, z]$ [S4, unofficial][S6, unofficial]. It solves the problem of mapping 3D spatial positions to linear memory addresses for efficient access during rendering or processing [G]. Unlike hierarchical structures (e.g., [Voxel Data Structure](3982-voxel-data-structure.md)) which use pointers or bitmasks to skip empty space, this layout stores every voxel in a fixed-size slot, making it simple to implement but potentially memory-inefficient for sparse scenes [G]. It serves as the base layer for optimizations like [Voxel Material Packing](4907-voxel-material-packing.md) and [Voxel Renderer with Top-Level Grid and Bricks](8114-voxel-renderer-with-top-level-grid-and-bricks.md) [G].

## How it works
### Inputs and Outputs
- **Input**: 3D dimensions ($W, H, D$) defining the volume bounds, and a stream of voxel data (type, color, opacity, etc.) [S6, unofficial].
- **Output**: A linear memory buffer (array) where each voxel is stored at a specific index calculated from its $(x, y, z)$ coordinates [S6, unofficial].

### Data Structures
The layout is a contiguous 1D array. The specific field composition varies by implementation:

1. **Naive Tensor Layout [S4, unofficial]**:
   - Structure: A 3D tensor indexed by `world[x, y, z]` [S4, unofficial].
   - Entry: A tensor containing 4 numbers: opacity $\sigma$ followed by an RGB triplet $(R, G, B)$ [S4, unofficial].

2. **Fixed-Width Bit-Packed Layout [S1, unofficial]**:
   - Storage: 32-bit storage buffer per voxel [S1, unofficial].
   - Layout: Bits 0-7: Voxel type (8 bits). Bits 8-23: Color (16 bits). Bits 24-31: Auxiliary data (8 bits) [S1, unofficial].
   - Scaling: Voxels are scaled such that edges are $1/8$ unit in length [S1, unofficial].

3. **Binary Index Layout [S2, unofficial]**:
   - Format: Binary file composed of 8-bit or 16-bit indices [S2, unofficial].
   - Order: Left-to-right, bottom-to-top, back-to-front [S2, unofficial].

4. **Gaussian Lobe Layout [S5]**:
   - Fields per voxel: 1. Average vector $D$ (direction). 2. Standard deviation $\sigma$ (encoded via $|D|$). 3. Visibility/Occlusion (single average value). 4. Material color (opacity-weighted, alpha pre-multiplied). 5. Normal (pre-multiplied by opacity) [S5].

### Index Calculation
For a contiguous 1D array `_voxelData` of generic type `T`, 3D coordinates $(x, y, z)$ are mapped to a 1D index using row-major ordering [S6, unofficial][S8, unofficial]:

$$ \text{Index}(x, y, z) = x + y \cdot W + z \cdot W \cdot H $$

Where:
- $W$ is Width.
- $H$ is Height.
- $D$ is Depth [S6, unofficial].

### Steps for Access
1. **Compute Index**: Calculate the linear index from $(x, y, z)$ using the formula above [S6, unofficial].
2. **Bounds Check**: Verify $0 \le \text{Index} < W \cdot H \cdot D$ [S6, unofficial].
3. **Retrieve Data**:
   - If valid, return `_voxelData[Index]` [S6, unofficial].
   - If invalid, return a default value (e.g., $[0,0,0,0]$ for RGBA [S4, unofficial] or `default(T)` [S6, unofficial]).

### Pseudocode
```python
class VoxelGrid:
    def __init__(self, width, height, depth, default_value=0):
        self.width = width
        self.height = height
        self.depth = depth
        self.volume_size = width * height * depth
        self._voxel_data = [default_value] * self.volume_size
        self.default_value = default_value

    def set_voxel(self, x, y, z, value):
        index = self._xyz_to_index(x, y, z)
        if 0 <= index < self.volume_size:
            self._voxel_data[index] = value
        else:
            raise IndexError(f"Voxel ({x}, {y}, {z}) out of bounds")

    def get_voxel(self, x, y, z):
        index = self._xyz_to_index(x, y, z)
        if 0 <= index < self.volume_size:
            return self._voxel_data[index]
        else:
            return self.default_value

    def try_get_voxel(self, x, y, z):
        index = self._xyz_to_index(x, y, z)
        if 0 <= index < self.volume_size:
            return True, self._voxel_data[index]
        else:
            return False, self.default_value

    def _xyz_to_index(self, x, y, z):
        return x + y * self.width + z * self.width * self.height
```

### Parameters and Edge Cases
- **Invalid Node/Out-of-Bounds**: Addressing a voxel position not in the world returns $[0,0,0,0]$ [S4, unofficial]. Direct access via raw index without bounds checking throws `IndexOutOfRangeException` [S6, unofficial].
- **Root Node**: In hierarchical variants, `ROOT_NODE` is 0 [S3, unofficial].
- **Invalid Node Ref**: `INVALID_NODE` is `0xFFFFFFFF` [S3, unofficial].

## Subtopics

### [Voxel Material Packing](4907-voxel-material-packing.md)
Voxel Material Packing is a data layout for storing material properties and color within a single 32-bit voxel value. It allows up to 256 distinct materials to be managed by a MaterialManager. It builds on [Voxel Data Layout](4076-voxel-data-layout.md).

### [Voxel Renderer with Top-Level Grid and Bricks](8114-voxel-renderer-with-top-level-grid-and-bricks.md)
This method renders voxel data using a two-level grid structure (top-level grid containing 8x8x8 voxel bricks) to optimize memory transfer and cache locality. It solves the bottleneck of transferring large voxel datasets to the GPU by synchronizing only changed bricks and leveraging high internal GPU bandwidth for staging. It differs from flat dense grid renderers by introducing spatial tiling for cache efficiency and dynamic update budgets.

### Voxel Representation with Gaussian Lobes
This variant stores directional information using isotropic Gaussian lobes characterized by an average vector $D$ and standard deviation $\sigma$ [S5]. The variance is encoded via the norm $|D|$ such that $\sigma^2 = \frac{1 - |D|}{|D|}$ to ease interpolation [S5]. Fields include $D$, $\sigma$, visibility/occlusion, pre-multiplied material color, and opacity-pre-multiplied normal [S5]. This representation is more accurate than single values for describing light behavior but requires complex interpolation logic [S5].

## Operating characteristics
- **Time Complexity**: Access is $O(1)$ given coordinates, requiring only arithmetic for index calculation [G].
- **Memory Complexity**: $O(W \cdot H \cdot D)$ [G]. Memory usage is proportional to the volume of the bounding box, regardless of sparsity [G].
- **Strengths**: Simple implementation, no pointer chasing, predictable memory access patterns [G].
- **Limitations**: Poor scalability for large, sparse volumes. Fixed resolution requires full grid allocation [G].
- **When to Use**: Dense volumes, small scenes, or as a base for hierarchical structures [G].
- **When Not to Use**: Large open-world scenes with sparse objects, where hierarchical methods like [Voxel Data Structure](3982-voxel-data-structure.md) are preferred [G].

## Background
The naive tensor layout is a foundational concept in voxel rendering, often used in initial implementations and educational contexts. It appears in early voxel simulation projects [S1, unofficial] and tutorials on neural radiance fields (NeRF) and plenoxels, where it serves as a baseline before introducing spherical harmonics or hierarchical structures [S4, unofficial]. The binary index format with specific ordering (left-to-right, bottom-to-top, back-to-front) is used in surface reconstruction tools like SurfaceNets [S2, unofficial]. The Gaussian lobe representation was introduced in the context of voxel cone tracing for indirect illumination [S5].
