# Voxel Format Handling

Also called: Voxel Format Support, Voxel Format Transformation

## Overview
Voxel format handling provides flexible support for varying bit-depths and field compositions in volume rendering, distinguishing between data stored in system memory ("memory voxels") and data processed in rendering pipelines ("pipeline voxels") [S1, S2, unofficial]. It solves the problem of hardware and API incompatibility with diverse voxel layouts by allowing simple transformations (e.g., table lookups) to convert memory formats into pipeline-ready formats [S1, S2, unofficial]. This approach sets it apart from rigid, fixed-format renderers by enabling user-defined field sequences and modular shader binding, though it introduces complexity in managing multiple format definitions [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Memory voxel data with arbitrary field configurations (intensity, index, gradient, opacity, user fields) [S1, unofficial].
*   **Output:** Pipeline voxel data optimized for the rendering hardware or ray-tracing pipeline [S1, S2, unofficial].

**Data Structures:**
A memory voxel is composed of a sequence of fields. The total size must be padded to a multiple of 16 bits [S1, unofficial].
*   **Intensity Field:** 8, 12, or 16 bits. Indicates intensity or indexes an RGB table [S1, unofficial].
*   **Index Field:** 4, 8, 12, or 16 bits. Used for color lookup and material type indication [S1, unofficial].
*   **Gradient Coefficient:** 8 bits (potential for future expansion) [S1, unofficial].
*   **Opacity Field:** 8 bits or an index to an opacity table [S1, unofficial].
*   **User Fields:** Arbitrary size, unrestricted, but must pad the total voxel size to a 16-bit multiple [S1, unofficial].
*   **Constraints:** Not all fields are required; fields may overlap or be absent [S1, unofficial].

**Steps:**
1.  **Define Memory Voxel:** Construct the memory voxel by assigning bit-widths to the required fields (Intensity, Index, Gradient, Opacity, User) according to the application's needs [S1, unofficial].
2.  **Pad to 16-bit Boundary:** Ensure the total bit-width of the memory voxel is a multiple of 16 bits by adding padding to user fields if necessary [S1, unofficial].
3.  **Transform to Pipeline Voxel:** Apply a transformation to convert the memory voxel into the pipeline voxel format. This is typically a simple operation, such as a table lookup, applied to some or all fields [S1, unofficial]. In the simplest case, the pipeline voxel is identical to the memory voxel [S1, unofficial].
4.  **Handle Larger Voxels:** If the voxel size exceeds 16 bits, treat it as a sequence of 16-bit values. Note that this results in a proportional reduction in frame rate [S1, unofficial].

    Creates a memory voxel structure definition.
    Returns total_bits and field_layout.
    """

    if intensity_bits not in [8, 12, 16]:
        raise ValueError("Intensity must be 8, 12, or 16 bits")
    if index_bits not in [4, 8, 12, 16]:
        raise ValueError("Index must be 4, 8, 12, or 16 bits")
    if gradient_bits != 8:
        raise ValueError("Gradient is currently fixed at 8 bits")
    if opacity_bits != 8:
        raise ValueError("Opacity is currently fixed at 8 bits")

    total_bits = intensity_bits + index_bits + gradient_bits + opacity_bits + user_bits
    
    # Pad to 16-bit multiple [S1, unofficial]
    if total_bits % 16 != 0:
        padding_bits = 16 - (total_bits % 16)
        total_bits += padding_bits
    else:
        padding_bits = 0
        
    return {

        "index_bits": index_bits,
        "gradient_bits": gradient_bits,
        "opacity_bits": opacity_bits,
        "user_bits": user_bits,

    }

*   **Larger Voxels:** Voxels larger than 16 bits are treated as a sequence of 16-bit values, leading to a proportional reduction in frame rate [S1, unofficial].

*   **Padding:** Failure to pad to a 16-bit multiple may cause alignment issues in hardware pipelines [S1, unofficial].

## Subtopics

### Vulkan Ray Tracing Pipeline Setup for Voxel Formats
A method for handling different voxel formats in a Vulkan ray tracing pipeline by building a Shader Binding Table (SBT) with specific intersection shaders tailored to the format design, and binding callable shaders to decode attributes [S2, unofficial]. It sets itself apart by linking formats directly to shaders, allowing the engine to handle SBT construction while the user only links formats [S2, unofficial]. Choose this when using Vulkan for ray-traced volume rendering with diverse voxel formats [S2, unofficial]. The pipeline execution depends on four things: the geometry configuration in the Bottom-Level Acceleration Structure (BLAS), the SBT offset in the top-level instance, the SBT’s data, and the geometry that was potentially hit [S2, unofficial]. Steps include tracking voxel formats in BLAS geometries, building the SBT with tailored intersection shaders, binding callable shaders for attribute decoding, and linking formats to their corresponding shaders [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Processing time increases proportionally for voxels larger than 16 bits, as they are treated as sequences of 16-bit values [S1, unofficial].
*   **Memory Complexity:** Memory usage is determined by the voxel size, padded to 16-bit multiples [S1, unofficial].
*   **Performance:** On EM-Cube hardware, 16-bit voxels are processed at 125 MHz with 4 pipelines per chip [S1, unofficial]. Larger voxels result in proportional frame rate reduction [S1, unofficial].
*   **Strengths:** Flexibility in defining voxel fields (intensity, index, gradient, opacity, user fields) [S1, unofficial]. Modular handling of formats in ray-tracing pipelines via SBT [S2, unofficial].
*   **Limitations:** Performance degradation for non-16-bit voxel sizes [S1, unofficial]. Complexity in managing multiple format definitions and transformations [S1, S2, unofficial].
*   **When to Use:** When hardware supports 16-bit voxel processing and flexibility in voxel field definition is required [S1, unofficial]. When using Vulkan ray tracing with diverse voxel formats [S2, unofficial].
*   **When Not to Use:** When maximum performance is critical and voxel sizes are significantly larger than 16 bits [S1, unofficial]. When the rendering pipeline does not support flexible format transformation [S1, unofficial].

## Background
The concept of flexible voxel format handling originated with the EM-Cube architecture, proposed in 1997 for low-cost real-time volume rendering [S1, unofficial]. EM-Cube introduced the distinction between memory and pipeline voxels and the use of 16-bit processing units [S1, unofficial]. More recently, the approach has been adapted for modern ray-tracing APIs like Vulkan, where format handling is integrated into the Shader Binding Table (SBT) mechanism [S2, unofficial].
