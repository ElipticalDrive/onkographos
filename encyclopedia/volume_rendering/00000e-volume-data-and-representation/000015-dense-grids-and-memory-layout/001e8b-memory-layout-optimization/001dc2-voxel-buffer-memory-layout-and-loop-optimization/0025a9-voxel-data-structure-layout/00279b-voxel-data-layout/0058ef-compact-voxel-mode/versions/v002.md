# Compact Voxel Mode

Also called: 1-byte voxel mode

## Overview
Compact Voxel Mode is a compile-time optional storage format that reduces voxel memory usage by 4x compared to the default mode by packing voxel data into a single byte per voxel [S1, unofficial]. It solves the problem of excessive memory consumption in large-scale voxel scenes, enabling the loading of models that would otherwise exceed available RAM or hit volume limits [S1, unofficial]. Unlike the default mode, which preserves full feature support, this mode sacrifices color depth, transparency, normals, and bone indices to achieve its memory efficiency [S1, unofficial].

## How it works
**Inputs and Outputs:**
The method is activated via the CMake boolean flag `USE_COMPACT_VOXEL` [S1, unofficial]. When enabled, it changes the internal memory layout of voxel data structures to a single-byte format [S1, unofficial]. When disabled (default), the system preserves the original byte-for-byte behavior [S1, unofficial].

**Data Structures:**
In compact mode, each voxel is stored as a single `uint8_t` (1 byte) [S1, unofficial]. The bit layout is defined as follows:
- **Bit 7:** Outline flag [S1, unofficial].
- **Bit 6:** Solid flag [S1, unofficial].
- **Bits 0–5:** Color index, supporting a maximum of 64 distinct colors [S1, unofficial].
In default mode, the layout is not explicitly defined in the sources but is implied to be larger, resulting in 4x the memory usage of the compact mode [S1, unofficial].

**Bulk Operations:**
Bulk flag operations (`hasFlags`, `removeFlags`, `toggleFlags`, `setFlags`) utilize `uint64_t` processing for both default and compact modes to handle multiple voxels efficiently [S1, unofficial]. Memory allocations for voxel data are padded to 8-byte boundaries via an `allocSize()` function to support safe bulk reads [S1, unofficial].

**Pseudocode:**
The following pseudocode illustrates the compact voxel storage and bulk flag processing logic [S1, unofficial]. It assumes a standard vector-based storage for voxels [G].

```python
def alloc_size(num_voxels: int) -> int:
    """Pads voxel count to 8-byte boundaries for safe uint64_t bulk reads."""
    raw_bytes = num_voxels * 1  # 1 byte per voxel in compact mode
    return (raw_bytes + 7) & ~7

def pack_voxel(outline: bool, solid: bool, color_index: int) -> int:
    """Packs voxel attributes into a single uint8_t."""
    if not (0 <= color_index <= 63):
        raise ValueError("Color index must be between 0 and 63")
    byte_val = 0
    if outline:
        byte_val |= 1 << 7
    if solid:
        byte_val |= 1 << 6
    byte_val |= color_index & 0x3F
    return byte_val

def bulk_set_flags(voxels: list, start_idx: int, num_voxels: int, outline: bool, solid: bool, color_index: int):
    """Sets flags for a bulk range. Uses uint64_t processing (8 voxels per word)."""
    packed = pack_voxel(outline, solid, color_index)
    # In C++, this value is cast to uint64_t and written to memory in 8-byte chunks
    for i in range(start_idx, start_idx + num_voxels):
        if i < len(voxels):
            voxels[i] = packed
```

**Edge Cases and Pitfalls:**
- **Unsupported Features:** Normals, bone indices, and `VoxelType::Transparent` are not supported in compact mode [S1, unofficial]. Attempting to use these features is not supported [S1, unofficial].
- **Color Limit:** The color index is limited to 6 bits, allowing only 64 colors [S1, unofficial].
- **Memory Padding:** Allocations are padded to 8-byte boundaries to ensure safe bulk reads using `uint64_t` [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- **Memory:** Reduces memory usage by 4x compared to the default mode [S1, unofficial].
- **Time:** Rendering performance remains stable and is not noticeably impacted by the compact mode [S1, unofficial].

**Measured Performance:**
- In a test case with a 5500x5500x5500 model containing 89 million solid voxels, memory requirements dropped from 160GB to 40GB [S1, unofficial].
- Rendering performance remained stable at 60 fps for the 89 million voxel model in compact mode, identical to other models [S1, unofficial].

**Strengths and Limitations:**
- **Strengths:** Significant memory reduction, enabling larger scenes to be loaded and rendered [S1, unofficial].
- **Limitations:** Loss of color depth (max 64 colors), transparency, normals, and bone indices [S1, unofficial].

**When to Use:**
- Use when memory is a bottleneck and the scene does not require transparency, normals, bone indices, or more than 64 colors [S1, unofficial].

**When Not to Use:**
- Do not use when full feature support (transparency, normals, etc.) is required [S1, unofficial].

## Background
Compact Voxel Mode was introduced as a compile-time option (`USE_COMPACT_VOXEL`) to address memory starvation issues in large voxel scenes [S1, unofficial]. The motivation stemmed from loading models with thousands of nodes and tens of gigabytes of voxel data, where the default mode caused excessive memory allocation and silent merging of volumes [S1, unofficial]. The feature was developed as part of a pull request to support large scenes and increase the `MAX_VOLUMES` limit [S1, unofficial].
