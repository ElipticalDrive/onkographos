# Voxel Data Packing and Mapping

Also called: Voxel Buffer Memory Layout, Memory-to-Pipeline Voxel Transformation

## Overview
Voxel Data Packing and Mapping is a method for optimizing the storage and transfer of volume data by converting floating-point datasets into compact integer formats for graphics memory. It solves the problem of bandwidth and memory constraints during data loading by packing up to four data values into a single 32-bit voxel. It differs from [Voxel Material Packing](4907-voxel-material-packing.md) by focusing on the initial data ingestion and format conversion from host memory to graphics memory, whereas the parent method focuses on material indexing within a fixed 32-bit structure. It differs from [Voxel Block Data Layout](7171-voxel-block-data-layout.md) by operating on a per-voxel packing basis rather than a hierarchical block structure.

## How it works
The method involves two distinct phases: the initial packing for graphics memory (based on [S1, unofficial]) and the flexible format handling for pipeline processing (based on [S2, unofficial]).

### Inputs and Outputs
*   **Input:** Floating-point volume dataset on disk/host memory.
*   **Output:** Packed voxel data in graphics memory (32-bit integers) or pipeline-ready voxels (8/16-bit fields).

### Data Structures
**Graphics Memory Voxel (32-bit):**
*   Layout: 4 bytes total.
*   Content: Up to four 8-bit integer values.
*   Source: [S1, unofficial]

**Memory Voxel (Conceptual/Host):**
*   Fields (variable bit depths, padded to 16-bit multiples):
    1.  **Intensity:** 8, 12, or 16 bits. Indicates intensity or indexes an RGB table. [S2, unofficial]
    2.  **Index:** 4, 8, 12, or 16 bits. Used for color lookup and material type indication. [S2, unofficial]
    3.  **Gradient Coefficient:** 8 bits. [S2, unofficial]
    4.  **Opacity:** 8 bits or an index to an opacity table. [S2, unofficial]
    5.  **Arbitrary User Fields:** Unrestricted size, padded to maintain 16-bit alignment. [S2, unofficial]
*   Note: Fields may overlap or be absent. [S2, unofficial]

**Pipeline Voxel:**
*   Format: 8-bit or a sequence of 16-bit fields.
*   Relationship: Can be identical to memory voxels or a transformation thereof. [S2, unofficial]

### Steps
1.  **Load Data:** Load the floating-point dataset from disk. [S1, unofficial]
2.  **Map and Pack (Graphics Memory):**
    *   Apply a user-specified mapping function to convert floating-point values to 8-bit integers. [S1, unofficial]
    *   Pack up to four such values into a single 32-bit voxel. [S1, unofficial]
    *   Transfer the packed data to graphics memory. [S1, unofficial]
3.  **Transform to Pipeline Format (Optional/Advanced):**
    *   If the pipeline requires a different format than the memory voxel, apply a transformation (e.g., table lookup) to specific fields. [S2, unofficial]
    *   This creates the "pipeline voxel" from the "memory voxel." [S2, unofficial]

### Formulas and Parameters
*   **Mapping:** $V_{int} = \text{Map}(V_{float})$, where $V_{int} \in [0, 255]$. The mapping function is user-specified. [S1, unofficial]
*   **Memory Size:** $Size_{voxel} = 32 \text{ bits} = 4 \text{ bytes}$. [S1, unofficial]
*   **Alignment:** Total voxel size must be a multiple of 16 bits. [S2, unofficial]

### Parameters
*   **Mapping Function:** User-specified. Can be changed dynamically within the Cave environment. [S1, unofficial]
*   **Bit Depths:** Intensity (8/12/16), Index (4/8/12/16), Gradient (8), Opacity (8). [S2, unofficial]

### Edge Cases and Pitfalls
*   **Mapping Updates:** Changing the floating-point-to-integer mapping requires updating the entire dataset in graphics memory, which may take a few seconds. [S1, unofficial]
*   **Larger Voxels:** If voxels exceed 16 bits (treated as sequences of 16-bit values), the frame rate reduces proportionally. [S2, unofficial]
*   **Precision:** Converting to 8-bit integers may lose precision compared to the original floating-point data. [S1, unofficial]

    """
    Loads a floating-point volume and packs it into 32-bit integers for graphics memory.
    
    Args:
        filepath: Path to the floating-point dataset.
        mapping_func: A callable that maps a float to an 8-bit integer (0-255).
        
    Returns:
        packed_data: A numpy array or buffer of 32-bit integers ready for GPU upload.
    """
    # 1. Load floating point data
    # [G] Assuming a standard library like numpy or a custom loader
    float_data = load_floating_point_data(filepath) 
    
    # 2. Convert and pack
    # Each voxel holds up to 4 values. 
    # [G] Assuming the data is structured such that 4 consecutive floats map to one 32-bit voxel.
    # If the data is 3D, we iterate through voxels.
    
    num_voxels = float_data.size // 4
    packed_data = np.zeros(num_voxels, dtype=np.uint32)
    
    for i in range(num_voxels):
        voxel_32bit = 0
        for j in range(4):
            idx = i * 4 + j
            if idx < float_data.size:
                # Apply user-specified mapping
                val_8bit = mapping_func(float_data[idx])
                # Pack into 8-bit slots
                voxel_32bit |= (val_8bit << (8 * j))
        
        packed_data[i] = voxel_32bit
        
    return packed_data

## Subtopics

### Voxel Format Handling
This variant, associated with the EM-Cube architecture, emphasizes flexibility in voxel formats for pipeline processing. It distinguishes between "memory voxels" (in host memory) and "pipeline voxels" (in the rendering pipeline). It allows for 8-bit or 16-bit field sequences, where pipeline voxels are derived from memory voxels via simple transformations like table lookups. It is chosen when the rendering hardware requires specific field widths (e.g., 16-bit) that differ from the storage format. Larger voxels (sequences of 16-bit values) result in a proportional reduction in frame rate. [S2, unofficial]

## Operating characteristics
*   **Memory:** Each voxel occupies 32 bits (4 bytes) in graphics memory when using the 4-value 8-bit packing scheme. [S1, unofficial]
*   **Performance:** Loading a full 500x500x100 voxel dataset is possible. Animation of 48 time steps required downsampling to 128x128x100. [S1, unofficial]
*   **Scaling:** Frame rate is proportional to voxel size; larger voxels (treated as sequences of 16-bit values) reduce frame rate proportionally. [S2, unofficial]
*   **Latency:** Updating the floating-point-to-integer mapping requires a full dataset update in graphics memory, taking a few seconds. [S1, unofficial]
*   **Strengths:** Reduces memory bandwidth requirements by converting to 8-bit integers; allows flexible field definitions. [S1, S2, unofficial]
*   **Limitations:** Loss of precision due to 8-bit conversion; potential frame rate reduction with larger voxel formats. [S1, S2, unofficial]

## Background
The method originated in the context of the IEEE Visualization 2004 Contest and the EM-Cube architecture. The 32-bit packing approach was used in the Cave environment for exploring large datasets like hurricane simulations. The flexible format handling was developed for the EM-Cube, an architecture for low-cost real-time volume rendering, which processed 16-bit voxels at 125 MHz. [S1, S2, unofficial]
