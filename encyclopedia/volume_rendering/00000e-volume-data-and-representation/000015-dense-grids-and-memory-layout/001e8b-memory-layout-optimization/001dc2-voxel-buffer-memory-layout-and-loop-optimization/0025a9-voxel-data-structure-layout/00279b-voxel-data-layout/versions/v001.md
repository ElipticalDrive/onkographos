# Voxel Data Layout

Also called: Input Data Format, Voxel Cube, Voxel Data Structure (Naive), World Tensor

## Overview
Voxel Data Layout refers to the fundamental memory organization of a dense 3D grid where each cell (voxel) stores discrete properties such as material type, color, or radiance. It solves the problem of mapping 3D spatial coordinates $(x, y, z)$ to a linear memory address for efficient access during ray marching or volume rendering. Unlike sparse structures (e.g., [Voxel Data Structure](3982-voxel-data-structure.md)) which use pointers or hash maps to skip empty space, this layout allocates contiguous memory for every possible voxel in the defined bounding box, prioritizing predictable access patterns and cache locality over memory efficiency for sparse scenes.

## How it works
### Inputs and Outputs
- **Input**: 3D integer coordinates $(x, y, z)$ within bounds $[0, \text{Width}-1] \times [0, \text{Height}-1] \times [0, \text{Depth}-1]$.
- **Output**: A voxel data structure (e.g., a 32-bit integer, a struct, or a tensor) containing material/color/opacity information.

### Data Structures and Layout
The layout varies by implementation goal, but common patterns include:

1.  **Naive Tensor (World Tensor)**: A 3D array or flattened 1D array where each voxel stores opacity $\sigma$ and an RGB triplet.
    -   **Fields**: $\sigma$ (float), $R$ (float), $G$ (float), $B$ (float).
    -   **Size**: 4 numbers per voxel [S3, unofficial].
    -   **Indexing**: $Index = x + y \cdot \text{Width} + z \cdot \text{Width} \cdot \text{Height}$ [S5, unofficial].

2.  **Packed 32-bit Integer**: Used for performance-critical or limited-memory contexts (e.g., raytracing demos).
    -   **Bits [31..24]**: 8-bit Material ID (max 256 materials) [S6, unofficial].
    -   **Bits [23..16]**: Red channel [S6, unofficial].
    -   **Bits [15..8]**: Green channel [S6, unofficial].
    -   **Bits [7..0]**: Blue channel [S6, unofficial].
    -   *Alternative Packing*: 8 bits Type, 16 bits Color, 8 bits Auxiliary [S1, unofficial].

3.  **Binary Index Format**: Stored in files or buffers.
    -   **Order**: Left-to-right, bottom-to-top, back-to-front [S2, unofficial].
    -   **Precision**: 8-bit or 16-bit indices [S2, unofficial].

### Numbered Steps for Access
1.  **Validate Bounds**: Check if $0 \le x < \text{Width}$, $0 \le y < \text{Height}$, and $0 \le z < \text{Depth}$ [S5, unofficial].
2.  **Compute Linear Index**:
    $$ \text{index} = x + y \cdot \text{Width} + z \cdot \text{Width} \cdot \text{Height} $$
    [S5, unofficial]
3.  **Retrieve Data**:
    -   If using a contiguous array `_voxelData` of type `T`:
        ```python
        voxel_data = _voxelData[index]
        ```
    -   If using a packed 32-bit integer `val`:
        ```python
        material_id = (val >> 24) & 0xFF
        r = (val >> 16) & 0xFF
        g = (val >> 8) & 0xFF
        b = val & 0xFF
        ```
    [S6, unofficial]
4.  **Handle Out-of-Bounds**: If the coordinate is invalid, return a default value.
    -   For the Naive Tensor: Return $[0, 0, 0, 0]$ (zero opacity, black color) [S3, unofficial].
    -   For Safe Access Methods: Return `false` and set output to `default` (e.g., 0 for bytes) [S5, unofficial].

### Formulas
-   **Index Calculation**:
    $$ I(x, y, z) = x + y \cdot W + z \cdot W \cdot H $$
    Where $W$ is Width, $H$ is Height [S5, unofficial].

-   **Variance Encoding (for Gaussian Lobes)**:
    $$ \sigma^2 = \frac{1 - |D|}{|D|} $$
    Where $|D|$ is the norm of the average direction vector $D$. This encoding eases interpolation [S4].

### Parameters
-   **Width, Height, Depth**: Integer dimensions defining the volume bounds [S5, unofficial].
-   **Voxel Scale**: In some implementations, voxel edges are scaled to $1/8$ unit length to increase geometric detail [S1, unofficial].
-   **Max Materials**: 256 (determined by 8-bit material ID) [S6, unofficial].

### Edge Cases and Pitfalls
-   **Out-of-Bounds Access**: Direct array access without bounds checking throws an `IndexOutOfRangeException` (or equivalent segfault) [S5, unofficial]. Always use a safe accessor (e.g., `TryGetVoxelData`) that checks $0 \le \text{index} < \text{Length}$ [S5, unofficial].
-   **Default Return Value**: Addressing a non-existent voxel position must consistently return a defined default (e.g., $[0,0,0,0]$) to prevent rendering artifacts or crashes [S3, unofficial].
-   **Memory Contiguity**: The layout assumes a single contiguous native array. Strided or interleaved layouts require different indexing logic [S5, unofficial].

### Pseudocode
```python
class VoxelGrid:
    def __init__(self, width, height, depth, voxel_data_array):
        self.width = width
        self.height = height
        self.depth = depth
        self.voxel_data = voxel_data_array  # 1D contiguous array of type T

    def get_voxel(self, x, y, z):
        """
        Returns voxel data. If out of bounds, returns default value.
        For packed 32-bit integers, returns a dict with material, r, g, b.
        For tensors, returns the raw tensor.
        """
        # 1. Validate bounds
        if not (0 <= x < self.width and 
                0 <= y < self.height and 
                0 <= z < self.depth):
            return self._get_default_voxel()

        # 2. Compute linear index
        index = x + y * self.width + z * self.width * self.height

        # 3. Retrieve data
        raw_data = self.voxel_data[index]

        # 4. Unpack if necessary (example for 32-bit packed layout)
        # If raw_data is a 32-bit int:
        if isinstance(raw_data, int):
            material_id = (raw_data >> 24) & 0xFF
            r = (raw_data >> 16) & 0xFF
            g = (raw_data >> 8) & 0xFF
            b = raw_data & 0xFF
            return {"material": material_id, "r": r, "g": g, "b": b}
        
        # If raw_data is a tensor/struct (e.g., [sigma, r, g, b]):
        return raw_data

    def _get_default_voxel(self):
        """
        Returns default value for out-of-bounds access.
        For naive tensor: [0, 0, 0, 0] (sigma=0, RGB=0) [S3, unofficial].
        For packed int: 0 (all channels 0) [S5, unofficial].
        """
        return 0 # Or [0, 0, 0, 0] depending on type T
```

## Subtopics

### Voxel Representation with Gaussian Lobes
A variant where each voxel stores directional light information rather than just static color. It uses an average direction vector $D$ and a standard deviation $\sigma$ (encoded via $|D|$) to model isotropic Gaussian lobes [S4]. Fields include: 1. Average vector $D$, 2. Standard deviation $\sigma$, 3. Visibility/Occlusion (single average value), 4. Material color (opacity-weighted, alpha pre-multiplied), 5. Normal (pre-multiplied by opacity) [S4]. Chosen for compactness compared to storing arbitrary distributions, though it lacks view-dependency for thin objects [S4].

### Voxel Data Volume Storage and Access
Focuses on the software interface for accessing the contiguous array. It emphasizes safe access methods (`TryGetVoxelData`) that prevent `IndexOutOfRangeException` by validating indices against `Width`, `Height`, and `Depth` before accessing `_voxelData` [S5, unofficial]. This is a critical implementation detail for robustness in C#/C++ environments [S5, unofficial].

### Voxel Material Packing
A specific 32-bit integer layout optimization that packs Material ID (8 bits), Red (8 bits), Green (8 bits), and Blue (8 bits) into a single integer [S6, unofficial]. This allows managing up to 256 distinct materials via a `MaterialManager` while minimizing memory bandwidth during ray traversal [S6, unofficial].

## Operating characteristics
-   **Time Complexity**: $O(1)$ for voxel access given coordinates, assuming contiguous memory and no hashing [S5, unofficial].
-   **Memory Complexity**: $O(W \cdot H \cdot D)$, where $W, H, D$ are dimensions. Memory usage is high for sparse scenes as empty space is allocated [S3, unofficial].
-   **Performance**: High cache locality due to contiguous storage [S5, unofficial]. Access patterns in ray marching (linear traversal) benefit from sequential memory reads [S1, unofficial].
-   **Limitations**: Inefficient for sparse volumes; out-of-bounds checks are mandatory to prevent crashes [S5, unofficial]. The naive tensor layout (RGB + $\sigma$) is less expressive than spherical harmonic variants (28 numbers/voxel) but faster to compute [S3, unofficial].

## Background
The concept of a dense voxel grid is foundational in volume rendering. Early implementations used simple 3D tensors indexed by world coordinates, storing opacity and RGB triplets for demonstration purposes before evolving to more complex representations like spherical harmonics [S3, unofficial]. The "naive" structure is often the starting point for implementing ray marchers, where equidistant steps sample the grid [S1, unofficial]. Binary formats for storage often use specific scan orders (left-to-right, bottom-to-top, back-to-front) to facilitate file I/O [S2, unofficial].
