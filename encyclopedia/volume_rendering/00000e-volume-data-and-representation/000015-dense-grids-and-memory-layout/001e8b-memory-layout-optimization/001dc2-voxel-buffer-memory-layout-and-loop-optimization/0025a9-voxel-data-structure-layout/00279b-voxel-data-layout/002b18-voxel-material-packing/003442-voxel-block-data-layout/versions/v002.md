# Voxel Block Data Layout

Also called: Block int32 packing, Coordinate bit-packing

## Overview
This layout stores 3D voxel coordinates within a single 32-bit integer to optimize memory access and indexing in voxel-based rendering engines [S1, unofficial]. It packs spatial position into a dense integer key while storing material or color data separately as an 8-bit palette index [S1, unofficial].

## How it works
**Inputs:** Voxel coordinates $(x, y, z)$ and an optional material or color index [S1, unofficial].
**Outputs:** A packed 32-bit integer representing the voxel position, with material properties stored separately [S1, unofficial].

**Data Structures:**
1. **Packed Coordinate:** A 32-bit unsigned integer [S1, unofficial]. Bits 24–31 hold the $x$ coordinate, bits 16–23 hold $y$, and bits 8–15 hold $z$ [S1, unofficial].
2. **Block Object:** Contains the packed coordinate and a separate 8-bit palette index for color or material [S1, unofficial].
3. **Voxel Struct:** In some implementations, voxels are stored as structs containing `flags` (uint8), `color` (uint32), and `blockType` (uint8), indexed in a 3D map using `V3_Vec3i16` coordinates [S2, unofficial].
4. **Chunk Storage:** Chunks store voxels in a map keyed by `V3_Vec3i16`, alongside a 2D heightmap `maxY` of type `[chunkSize][chunkSize]uint8` and a `flag` byte [S2, unofficial].

**Packing Formula:**
The coordinate $P$ is calculated as:
$$ P = (x \ll 24) \mid (y \ll 16) \mid (z \ll 8) $$
[S1, unofficial].

**Unpacking Formula:**
Given packed integer $P$:
$$ x = (P \gg 24) \ \& \ 0xFF $$
$$ y = (P \gg 16) \ \& \ 0xFF $$
$$ z = (P \gg 8) \ \& \ 0xFF $$
[S1, unofficial].

**Pseudocode:**
```python
def pack_voxel(x: int, y: int, z: int) -> int:
    """Packs x, y, z coordinates into a single 32-bit integer."""
    if not (0 <= x <= 255 and 0 <= y <= 255 and 0 <= z <= 255):
        raise ValueError("Coordinates must fit in 8 bits")
    return (x << 24) | (y << 16) | (z << 8)

def unpack_voxel(packed: int) -> tuple:
    """Unpacks x, y, z from a 32-bit integer."""
    return ((packed >> 24) & 0xFF, (packed >> 16) & 0xFF, (packed >> 8) & 0xFF)

class Block:
    def __init__(self, x: int, y: int, z: int, color_index: int):
        self.packed_coord = pack_voxel(x, y, z)
        self.color = color_index  # Stored separately as 8-bit palette index

class Chunk:
    def __init__(self, chunk_size: int):
        self.voxels = {}  # Map keyed by V3_Vec3i16 coordinates
        self.maxY = [[0] * chunk_size for _ in range(chunk_size)]  # 2D heightmap
        self.flag = 0
```

**Parameters:**
* Coordinate precision: 8 bits per axis, supporting a range of 0–255 [S1, unofficial].
* Color/Material storage: Separate 8-bit palette index [S1, unofficial].

**Edge Cases and Pitfalls:**
* Byte order confusion: Inline comments in some implementations suggest a byte order of color, x, y, z, but the actual implementation packs x, y, z into the integer with $x$ as the most significant byte, and color is not packed into this integer [S1, unofficial].

## Operating characteristics
Memory usage is reduced compared to storing three separate integers or floats per voxel, as coordinates are packed into a single 32-bit integer [S1, unofficial]. Access speed relies on fast bitwise operations for packing and unpacking, making it efficient for hash map keys when coordinates are the primary lookup key [S1, unofficial]. The 8-bit limit restricts world coordinates to 256 units per axis per block or chunk context [S1, unofficial]. Not given in the sources: time complexity, measured performance on specific hardware, scaling behavior, and suitability for high-precision scientific volume rendering.

## Background
This layout originates from a 2015 JavaScript-based WebGL voxel engine implementation designed to minimize memory footprint and simplify spatial indexing [S1, unofficial]. It has also been applied in C++ voxel projects for similar structural organization [S2, unofficial].
