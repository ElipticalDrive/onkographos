# Voxel Data Structure Layout

Also called: Array2, Array2<T>, Structure Field Alignment, Voxel Field Ordering

## Overview
Voxel Data Structure Layout defines the memory organization of per-voxel attributes in dense volume rendering, solving memory bandwidth and capacity constraints by packing essential state into a minimal footprint [S2]. It differs from [Voxel Data Layout](4076-voxel-data-layout.md) by focusing on the internal struct definition and field ordering to optimize for specific rendering algorithms (e.g., shading vs. classification), whereas Voxel Data Layout focuses on the global 3D-to-1D grid mapping [S2]. It builds on [Voxel Buffer Memory Layout and Loop Optimization](1598-voxel-buffer-memory-layout-and-loop-optimization.md) by defining the atomic unit stored within that buffer [S2].

## How it works
**Inputs:** Voxel attribute types (e.g., scalar, normal, gradient) and rendering requirements (shading-only vs. classification).
**Outputs:** A contiguous memory layout for a voxel structure and the corresponding access logic.

**Data Structures:**
The core unit is a C-style struct containing fields for voxel properties. A typical example includes:
- `Normal`: 16-bit unsigned integer (`unsigned short`), encoding surface normal.
- `Scalar`: 8-bit unsigned integer (`unsigned char`), encoding density or intensity.
- `Gradient`: 8-bit unsigned integer (`unsigned char`), encoding gradient magnitude.

The layout of the struct `Voxel` is defined as:
```cpp
typedef unsigned char Scalar;
typedef unsigned short Normal;
typedef unsigned char Gradient;
typedef struct {
    Normal normal;
    Scalar scalar;
    Gradient gradient;
} Voxel;
```

**Numbered Steps:**
1. **Identify Field Requirements:** Determine which fields are required for the primary rendering pass (e.g., shading) and which are secondary (e.g., classification) [S2].
2. **Order Fields by Priority:** Place shading-critical fields first in the struct, followed by classification-only fields. This allows the creation of a "shading-only" subset of the data, reducing memory footprint and improving cache performance for fast rendering algorithms [S2].
3. **Check Alignment Constraints:** Verify that field ordering satisfies machine alignment restrictions. For example, 16-bit quantities must be aligned to 2-byte boundaries. If fields are ordered poorly, the compiler may insert padding bytes, increasing the struct size. Use `sizeof()` to verify the total size matches expectations [S2].
4. **Define Accessor Logic:** Map 2D logical coordinates $(i, j)$ to a 1D index in the underlying array using row-major ordering: $index = i + ni \times j$, where $ni$ is the width (number of columns) and $j$ is the row index [S1, unofficial].
5. **Implement Bounds Checking:** Ensure access operators assert that $0 \le i < ni$ and $0 \le j < nj$ to prevent out-of-bounds access [S1, unofficial].

**Formulas:**
- 1D Index from 2D coordinates:
  $$ idx = i + ni \cdot j $$
  Where:
  - $i$: Column index ($0 \le i < ni$)
  - $j$: Row index ($0 \le j < nj$)
  - $ni$: Number of columns (width)

**Parameters:**
- `ni`: Width of the 2D slice or grid dimension.
- `nj`: Height of the 2D slice or grid dimension.
- `sizeof(Voxel)`: Must be verified to be 4 bytes in the example layout (2 + 1 + 1) with no padding, or adjusted if padding is introduced by the compiler [S2].

**Edge Cases and Pitfalls:**
- **Alignment Padding:** If fields are not ordered to satisfy alignment (e.g., placing an 8-bit field before a 16-bit field on some architectures), the compiler may insert padding. This increases memory usage and breaks the assumption of tight packing [S2].
- **Out-of-Bounds Access:** Accessing $i \ge ni$ or $j \ge nj$ triggers an assertion failure if bounds checking is enabled [S1, unofficial].
- **Shading vs. Classification Mismatch:** If classification fields are placed before shading fields, the fast rendering algorithm cannot skip the classification data, negating the memory and cache benefits [S2].

**Pseudocode:**
```python
# Definition of Voxel struct fields
# Normal: 2 bytes, Scalar: 1 byte, Gradient: 1 byte
# Total size: 4 bytes (assuming no padding)

class Voxel:
    def __init__(self, normal: int, scalar: int, gradient: int):
        self.normal = normal      # 16-bit unsigned
        self.scalar = scalar      # 8-bit unsigned
        self.gradient = gradient  # 8-bit unsigned

class Array2:
    def __init__(self, ni: int, nj: int, data: list = None):
        assert ni >= 0 and nj >= 0, "Dimensions must be non-negative"
        self.ni = ni
        self.nj = nj
        # Underlying 1D array storing Voxel objects or raw bytes
        if data is None:
            self.a = [None] * (ni * nj)
        else:
            self.a = data

    def resize(self, ni: int, nj: int):
        """Updates dimensions and resizes the underlying array."""
        assert ni >= 0 and nj >= 0
        self.ni = ni
        self.nj = nj
        self.a = [None] * (ni * nj)

    def clear(self):
        """Empties the array and resets dimensions."""
        self.a = []
        self.ni = 0
        self.nj = 0

    def swap(self, other: 'Array2'):
        """Exchanges ni, nj, and a with another Array2 instance."""
        self.ni, other.ni = other.ni, self.ni
        self.nj, other.nj = other.nj, self.nj
        self.a, other.a = other.a, self.a

    def get(self, i: int, j: int) -> Voxel:
        """Accesses element at (i, j) with bounds checking."""
        assert 0 <= i < self.ni, f"i={i} out of bounds [0, {self.ni})"
        assert 0 <= j < self.nj, f"j={j} out of bounds [0, {self.nj})"
        index = i + self.ni * j
        return self.a[index]

    def set(self, i: int, j: int, value: Voxel):
        """Sets element at (i, j) with bounds checking."""
        assert 0 <= i < self.ni, f"i={i} out of bounds [0, {self.ni})"
        assert 0 <= j < self.nj, f"j={j} out of bounds [0, {self.nj})"
        index = i + self.ni * j
        self.a[index] = value

# Typedefs for common types (conceptual)
# Array2d = Array2[float]
# Array2f = Array2[float]
# Array2i = Array2[int]
# Array2ui = Array2[unsigned int]
# Array2s = Array2[short]
# Array2us = Array2[unsigned short]
# Array2c = Array2[char]
# Array2uc = Array2[unsigned char]
# Array2ll = Array2[long long]
# Array2ull = Array2[unsigned long long]
```

## Subtopics

### SerializedArray Binary Layout
A binary serialization format for voxel data structures, including name, data type, shape, and raw data. It consists of: 8 bytes for `name_size` (uint64), N bytes for `name` (char, N=name_size), 4 bytes for `dtype` (uint32), 8 bytes for `shape_dim_count` (uint64), M*8 bytes for shape dimensions (uint64, M=shape_dim_count), 8 bytes for `data_byte_count` (uint64), and K bytes for `data` (uint8, K=data_byte_count) [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Access is $O(1)$ given valid coordinates, involving a single multiplication and addition for index calculation [S1, unofficial].
- **Memory Complexity:** $O(ni \times nj \times sizeof(Voxel))$. The layout is dense, allocating memory for every voxel in the defined bounding box [S2].
- **Performance:** Placing shading fields first improves cache locality for rendering passes that do not require classification data, reducing memory bandwidth usage [S2].
- **Strengths:** Predictable access patterns, high cache efficiency for dense volumes, and flexibility to subset data for specific rendering algorithms [S2].
- **Limitations:** Inefficient for sparse scenes due to contiguous allocation of empty space; alignment padding can increase memory usage if not carefully managed [S2].
- **When to Use:** Dense volume rendering where cache locality is critical and the volume is fully occupied or nearly fully occupied.
- **When Not to Use:** Highly sparse volumes where sparse structures (e.g., hash maps, pointers) would save significant memory [S2].

## Background
The concept of struct field alignment and ordering for voxel data originates from the VolPack library, which emphasized the importance of field ordering to support both shading and classification algorithms efficiently [S2]. The `Array2` template structure is documented in the NMC repository, providing a generic 2D array implementation with bounds checking and resizing capabilities [S1, unofficial]. The SerializedArray binary layout is described in the sparse-voxels repository, detailing a specific serialization format for voxel data [S3, unofficial].
