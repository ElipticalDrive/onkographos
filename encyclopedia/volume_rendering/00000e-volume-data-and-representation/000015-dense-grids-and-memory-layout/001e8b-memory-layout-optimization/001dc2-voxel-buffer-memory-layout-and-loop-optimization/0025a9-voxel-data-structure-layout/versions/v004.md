# Voxel Data Structure Layout

Also called: Array2, Array2<T>, Structure Field Alignment, Voxel Field Ordering

## Overview
Voxel Data Structure Layout defines the memory organization of a dense 3D grid where each cell (voxel) stores scalar or vector properties such as opacity, color, or material type. It solves the problem of mapping 3D spatial coordinates to contiguous memory addresses for efficient ray-marching or surface extraction. It differs from hierarchical structures like [Voxel Data Structure](3982-voxel-data-structure.md) by using a flat, fixed-size array without internal node pointers or occupancy masks, making it suitable for dense volumes or as a base representation before compression.

## How it works
### Inputs and Outputs
- **Inputs**: Dimensions of the grid ($n_i, n_j$) and a contiguous memory buffer for the data.
- **Outputs**: A data structure providing $O(1)$ access to any voxel at coordinates $(i, j)$ via a 1D index.

### Data Structures
The core layout is a 2D array abstraction `Array2<T>` which wraps a 1D container.

**Layout of `Array2<T>`:**
```cpp
template <typename T, typename ArrayT = std::vector<T>>
struct Array2 {
    int ni; // Width (dimension i)
    int nj; // Height (dimension j)
    ArrayT a; // Contiguous storage of size ni * nj
};
```
- `ni` and `nj` are integers representing the grid dimensions.
- `a` is a contiguous array (e.g., `std::vector<T>`) storing the voxel data.
- Total capacity is $n_i \times n_j$ elements of type $T$.

**Voxel Field Layout (Structure of Arrays vs Array of Structures):**
When storing multiple attributes per voxel (e.g., Normal, Scalar, Gradient), the layout within the element $T$ (if $T$ is a struct) or the planar arrays must respect alignment.

**Example Voxel Struct (Array of Structures):**
```cpp
typedef unsigned char Scalar;
typedef unsigned short Normal;
typedef unsigned char Gradient;

typedef struct {
    Normal normal;   // 16-bit
    Scalar scalar;   // 8-bit
    Gradient gradient; // 8-bit
} Voxel;
```
- **Field Ordering**: Fields required for shading (e.g., `normal`) should be placed first, followed by fields used only for classification (e.g., `gradient`). This allows storing just the shading fields for fast rendering algorithms, saving memory and improving cache performance [S2].
- **Alignment**: Fields must be ordered to satisfy machine alignment restrictions (e.g., 16-bit quantities aligned to 2-byte boundaries). The compiler may insert padding if fields are not ordered carefully. Use `sizeof()` to verify the struct size matches expectations [S2].

### Numbered Steps

1. **Initialization**:
   - Construct `Array2<T>` with dimensions $n_i, n_j$.
   - Assert $n_i \ge 0$ and $n_j \ge 0$ [S1, unofficial].
   - Allocate underlying array `a` of size $n_i \times n_j$.

2. **Coordinate Mapping**:
   - To access the element at 2D coordinates $(i, j)$, compute the 1D index:
     $$ \text{index} = i + n_i \times j $$
   - This assumes row-major ordering where $i$ is the innermost dimension (column-major in matrix terms, but row-major in memory if $j$ is the row index) [S1, unofficial]. Note: The parent article [Voxel Buffer Memory Layout and Loop Optimization] specifies row-major ordering where $x$ is innermost. For a 2D slice or the `Array2` abstraction, $i$ corresponds to the innermost stride.

3. **Access**:
   - Retrieve value: `val = a[index]`.
   - Bounds checking: Assert $0 \le i < n_i$ and $0 \le j < n_j$. Accessing outside these ranges triggers an assertion failure [S1, unofficial][S2].

4. **Resizing**:
   - Call `resize(ni_new, nj_new)`.
   - Update `ni` and `nj`.
   - Resize `a` to size $n_i \times n_j$. Existing data is preserved if dimensions allow, otherwise truncated or padded (implementation dependent, but typically reallocated) [S1, unofficial].

5. **Clearing**:
   - Call `clear()`.
   - Empty array `a`.
   - Set $n_i = 0, n_j = 0$ [S1, unofficial].

6. **Swapping**:
   - Call `swap(Array2<T>& x)`.
   - Exchange `ni`, `nj`, and `a` with another instance $x$ [S1, unofficial].

### Pseudocode

```python
class Array2:
    def __init__(self, ni: int, nj: int, data: list = None):
        """
        Initialize Array2 with dimensions ni, nj.
        If data is provided, it must have length ni * nj.
        """
        assert ni >= 0 and nj >= 0, "Dimensions must be non-negative"
        self.ni = ni
        self.nj = nj
        if data is not None:
            assert len(data) == ni * nj, "Data length must match dimensions"
            self.a = data
        else:
            self.a = [None] * (ni * nj)

    def resize(self, ni: int, nj: int):
        """Update dimensions and resize underlying array."""
        assert ni >= 0 and nj >= 0
        self.ni = ni
        self.nj = nj
        self.a = [None] * (ni * nj)

    def clear(self):
        """Empty the array and reset dimensions."""
        self.a = []
        self.ni = 0
        self.nj = 0

    def swap(self, other: 'Array2'):
        """Exchange state with another Array2 instance."""
        self.ni, other.ni = other.ni, self.ni
        self.nj, other.nj = other.nj, self.nj
        self.a, other.a = other.a, self.a

    def get(self, i: int, j: int):
        """
        Get element at (i, j).
        Index formula: i + ni * j
        """
        assert 0 <= i < self.ni, f"i out of bounds: {i} not in [0, {self.ni})"
        assert 0 <= j < self.nj, f"j out of bounds: {j} not in [0, {self.nj})"
        index = i + self.ni * j
        return self.a[index]

    def set(self, i: int, j: int, value):
        """Set element at (i, j)."""
        assert 0 <= i < self.ni, f"i out of bounds: {i} not in [0, {self.ni})"
        assert 0 <= j < self.nj, f"j out of bounds: {j} not in [0, {self.nj})"
        index = i + self.ni * j
        self.a[index] = value

    def sizeof_voxel(self, voxel_type_size: int) -> int:
        """
        Helper to verify voxel struct size.
        In C++, sizeof(Voxel) should be checked against expected alignment.
        """
        return voxel_type_size
```

### Parameters and Typical Values
- **Data Types**: Common typedefs include `Array2d` (double), `Array2f` (float), `Array2i` (int), `Array2ui` (unsigned int), `Array2s` (short), `Array2us` (unsigned short), `Array2c` (char), `Array2uc` (unsigned char), `Array2ll` (long long), `Array2ull` (unsigned long long) [S1, unofficial].
- **Voxel Size**: In the VolPack example, a Voxel struct is 32 bits (4 bytes) if packed tightly, but may be larger due to alignment padding depending on the platform [S2].

### Edge Cases and Pitfalls
- **Alignment Padding**: If fields are not ordered correctly, the compiler may insert padding bytes. For example, a struct with `unsigned short` (2 bytes) followed by `unsigned char` (1 byte) might be padded to 4 bytes total on some architectures. Always verify `sizeof(Voxel)` [S2].
- **Bounds Checking**: Accessing $i \ge n_i$ or $j \ge n_j$ causes assertion failure. In performance-critical paths, bounds checks should be handled by the caller or disabled with explicit guarantees [S1, unofficial].
- **Memory Contiguity**: The underlying array `a` must be contiguous. Non-contiguous storage breaks the 1D index mapping formula.

### SerializedArray Binary Layout
The binary layout for SerializedArray structures, including name, dtype, shape, and data.
- **Layout**:
  1. 8 bytes: `uint64` `name_size`
  2. N bytes: `char` `name` (where $N = \text{name\_size}$)
  3. 4 bytes: `uint32` `dtype`
  4. 8 bytes: `uint64` `shape_dim_count`
  5. $M \times 8$ bytes: `uint64` `shape` dimensions (where $M = \text{shape\_dim\_count}$)
  6. 8 bytes: `uint64` `data_byte_count`
  7. K bytes: `uint8` `data` (where $K = \text{data\_byte\_count}$) [S3, unofficial]

### Voxel Data Planar De-interleaving
Converts an Array of Structures (AoS) of `FVoxelData` into a Structure of Arrays (SoA) planar format for compression, and vice versa [S4, unofficial].
- **AoS to SoA (De-interleaving)**:
  - Input: `TArray<FVoxelData> Data` of size $N$.
  - Output: `TArray<uint8> OutPlanes` of size $N \times 4$.
  - Layout: First $N$ bytes are MaterialID, next $N$ are Density, next $N$ are BiomeID, last $N$ are Metadata.
  - Steps:
    1. Set $N = \text{Data.Num()}$.
    2. Reinterpret `Data` as `uint8* Src`.
    3. Set pointers `Mat`, `Den`, `Bio`, `Meta` in `OutPlanes` to the start of each plane.
    4. Loop $i$ from $0$ to $N-1$:
       - `Mat[i] = Src[i*4 + 0]`
       - `Den[i] = Src[i*4 + 1]`
       - `Bio[i] = Src[i*4 + 2]`
       - `Meta[i] = Src[i*4 + 3]` [S4, unofficial]
- **SoA to AoS (Interleaving)**:
  - Input: `uint8* Planes` (Mat, Den, Bio, Meta contiguous blocks of `NumVoxels` size).
  - Output: `TArray<FVoxelData> OutData`.
  - Steps:
    1. Set `Mat`, `Den`, `Bio`, `Meta` pointers.
    2. Reinterpret `OutData` as `uint8* Dst`.
    3. Loop $i$ from $0$ to `NumVoxels-1`:
       - `Dst[i*4 + 0] = Mat[i]`
       - `Dst[i*4 + 1] = Den[i]`
       - `Dst[i*4 + 2] = Bio[i]`
       - `Dst[i*4 + 3] = Meta[i]` [S4, unofficial]

## Operating characteristics
- **Time Complexity**: Access is $O(1)$ given valid coordinates. Resizing is $O(n_i \times n_j)$ due to reallocation.
- **Memory Complexity**: $O(n_i \times n_j \times \text{sizeof}(T))$. For the VolPack Voxel example, this is 4 bytes per voxel if tightly packed, but potentially more with alignment padding [S2].
- **Performance**: Cache performance is improved by ordering fields for shading first, allowing smaller subsets of data to be loaded for rendering [S2]. Planar de-interleaving (SoA) improves compression efficiency and vectorization potential compared to AoS [S4, unofficial].
- **Strengths**: Simple implementation, low overhead, predictable memory usage, efficient for dense volumes.
- **Limitations**: Not suitable for sparse volumes (wastes memory on empty space). Alignment padding can increase memory usage. Bounds checking overhead if not optimized out.

## Background
The `Array2` abstraction and its variants are commonly used in graphics programming for 2D slices of 3D data or 2D textures. The VolPack User's Guide provides specific recommendations for voxel field ordering to optimize shading and classification performance [S2]. The SerializedArray binary layout is used in sparse voxel serialization contexts [S3, unofficial]. Planar de-interleaving is used in voxel engines like VoxelWorlds to optimize data for compression and processing [S4, unofficial].
