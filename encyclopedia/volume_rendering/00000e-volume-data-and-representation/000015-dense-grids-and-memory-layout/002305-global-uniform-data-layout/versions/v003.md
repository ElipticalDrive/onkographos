# Global Uniform Data Layout

Also called: App State Buffer, GlobalUniformData

## Overview
Global Uniform Data Layout is a GPU buffer structure that aggregates camera matrices, lighting parameters, and rendering state flags into a single contiguous memory block for efficient transfer from CPU to GPU shaders [S1, unofficial]. It solves the problem of fragmented uniform updates by grouping frequently accessed, frame-varying data into one cache-friendly resource, distinct from instance-specific or texture-based data [S1, unofficial]. It is distinguished from generic camera matrices by its inclusion of explicit previous-frame basis vectors and world-voxel origin offsets to support reprojection history for temporal anti-aliasing (TAA) and lighting caches [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** CPU-side rendering parameters including camera pose, projection matrices, lighting configurations, and rendering toggles.
*   **Output:** A GPU-visible uniform buffer (e.g., `UniformBuffer` in Metal/Vulkan, `cbv` in DirectX) bound to a shader stage.

**Data Structures:**
The primary layout is defined by the `GlobalUniformData` struct [S1, unofficial]. It inherits from a `Settings` struct and follows with specific fields [S1, unofficial].

**Settings Sub-structure:**
The `Settings` struct contains boolean flags for lighting modes [S1, unofficial]:
*   `indirectSpecularLight`: Enable indirect specular lighting.
*   `indirectDiffuseLight`: Enable indirect diffuse lighting.
*   `directLight`: Enable direct lighting.
*   `shadows`: Enable shadow rendering.

**GlobalUniformData Layout:**
The layout follows the `Settings` struct [S1, unofficial]:
1.  `pointLights`: Array of `PointLight` structures.
    *   `MAX_LIGHTS`: Maximum number of point lights. Default value is 1 [S1, unofficial].
    *   `PointLight` structure:
        *   `position`: `packed_float3` (3 floats, 12 bytes).
        *   `color`: `packed_float3` (3 floats, 12 bytes).
2.  `numberOfLights`: `int` (4 bytes).
3.  `V`: View matrix (`glm::mat4`, 16 floats, 64 bytes) [S1, unofficial].
4.  `P`: Projection matrix (`glm::mat4`, 16 floats, 64 bytes) [S1, unofficial].
5.  `cameraPosition`: `vec3` (3 floats, 12 bytes) [S1, unofficial].
6.  `voxelTextureSize`: `uint32_t` (4 bytes) [S1, unofficial].
7.  `state`: `int32_t` (4 bytes) [S1, unofficial].
8.  `padding`: `uint32_t[3]` (12 bytes) [S1, unofficial].

**Pitfalls:**
*   **Alignment:** The `padding` field ensures the struct ends on a 16-byte boundary, which is often required for uniform buffer alignment in graphics APIs [S1, unofficial].
*   **Light Count:** The `numberOfLights` field must be synchronized with the actual number of lights in the `pointLights` array to prevent out-of-bounds access in shaders [S1, unofficial].

**Pseudocode:**
```python
# Define the GlobalUniformData structure for CPU-side population
class GlobalUniformData:
    def __init__(self):
        self.settings = Settings()
        self.pointLights = [PointLight() for _ in range(1)] # MAX_LIGHTS = 1
        self.numberOfLights = 0
        self.V = [[1.0]*4 for _ in range(4)] # Identity matrix placeholder
        self.P = [[1.0]*4 for _ in range(4)] # Identity matrix placeholder
        self.cameraPosition = [0.0, 0.0, 0.0]
        self.voxelTextureSize = 0
        self.state = 0
        self.padding = [0, 0, 0]

class Settings:
    def __init__(self):
        self.indirectSpecularLight = False
        self.indirectDiffuseLight = False
        self.directLight = True
        self.shadows = True

class PointLight:
    def __init__(self):
        self.position = [0.0, 0.0, 0.0]
        self.color = [1.0, 1.0, 1.0]

# Function to update the buffer before rendering
def update_global_uniform_buffer(camera, lights, scene):
    global_uniform = GlobalUniformData()
    
    # Update settings
    global_uniform.settings.indirectSpecularLight = scene.indirect_specular
    global_uniform.settings.indirectDiffuseLight = scene.indirect_diffuse
    global_uniform.settings.directLight = scene.direct_light
    global_uniform.settings.shadows = scene.shadows
    
    # Update lights
    for i, light in enumerate(lights[:1]): # Limit to MAX_LIGHTS
        global_uniform.pointLights[i].position = light.position
        global_uniform.pointLights[i].color = light.color
    global_uniform.numberOfLights = min(len(lights), 1)
    
    # Update camera matrices
    global_uniform.V = camera.view_matrix
    global_uniform.P = camera.projection_matrix
    global_uniform.cameraPosition = camera.position
    
    # Update scene parameters
    global_uniform.voxelTextureSize = scene.voxel_texture_size
    global_uniform.state = scene.state
    
    # Send to GPU
    gpu_buffer.update_data(global_uniform)
```

## Subtopics

### Instance Data Layout
A tightly packed data structure used to pass instance data (position, texture, tint, shape ID, orientation) to the GPU for instanced rendering of voxel shapes [S2, unofficial]. It is distinguished from global uniforms by being per-instance rather than per-frame [S2, unofficial]. Choose it when rendering multiple distinct voxel objects with unique properties [S2, unofficial].
*   **Definition:** Struct `ShapeInstance` with `LayoutKind.Explicit, Pack = 1` [S2, unofficial].
*   **Layout:** Total size 32 bytes [S2, unofficial].
    *   `position`: `Vector3` (float[3], 12 bytes, offset 0) [S2, unofficial].
    *   `texture`: `int` (4 bytes, offset 12) [S2, unofficial].
    *   `shape`: `ushort` (2 bytes, offset 16) [S2, unofficial].
    *   `rotation`: `ushort` (2 bytes, offset 18) [S2, unofficial].
    *   `tint`: `Vector3` (float[3], 12 bytes, offset 20) [S2, unofficial].
*   **Parameters:**
    *   `rotation` encoding: Calculated as `(int)up * 4 + forward` [S2, unofficial]. `up` is a `Direction` enum, `forward` is an integer range 0-3 representing clockwise rotation perpendicular to up [S2, unofficial].
*   **Pitfalls:** The `shape` field is truncated to `ushort` (2 bytes) despite the constructor accepting an `int`, limiting unique shapes to 65535 [S2, unofficial].

### WebGPU Uniform Buffer Packing
A specific linear memory layout for volumetric cloud rendering parameters in WebGPU [S3, unofficial]. It is distinguished by its use of a `Float32Array` with explicit indices for various parameters, including some packed into `Uint32View` [S3, unofficial]. Choose it for WebGPU-based volumetric rendering implementations [S3, unofficial].
*   **Layout:** `Float32Array` of size 64 (256 bytes) [S3, unofficial].
    *   Indices 0-7: `width`, `height`, `time`, `coverage`, `cloudBottom`, `cloudTop`, `densityMultiplier`, `maxSteps` (via `Uint32View`) [S3, unofficial].
    *   Indices 8-11: `lightSteps` (via `Uint32View`), `stepSize`, padding [S3, unofficial].
    *   Indices 12-15: `sunDirection`, padding [S3, unofficial].
    *   Indices 16-19: `camPos`, padding [S3, unofficial].
    *   Indices 20-35: `invProj` matrix [S3, unofficial].
    *   Indices 36-51: `invView` matrix [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ for buffer update, as it involves copying a fixed-size structure [S1, unofficial].
*   **Memory Complexity:** $O(1)$, with a fixed size determined by the maximum number of lights and matrix dimensions [S1, unofficial].
*   **Performance:** High cache efficiency due to contiguous memory layout [S1, unofficial].
*   **Strengths:** Simplifies shader code by providing a single access point for global state [S1, unofficial].
*   **Limitations:** Limited scalability for large numbers of lights due to fixed `MAX_LIGHTS` [S1, unofficial].

## Background
The Global Uniform Data Layout originated in the VoxelConeTracingMetal project [S1, unofficial]. It was developed to optimize the rendering pipeline for voxel-based cone tracing by reducing the number of uniform buffer bindings [S1, unofficial].
