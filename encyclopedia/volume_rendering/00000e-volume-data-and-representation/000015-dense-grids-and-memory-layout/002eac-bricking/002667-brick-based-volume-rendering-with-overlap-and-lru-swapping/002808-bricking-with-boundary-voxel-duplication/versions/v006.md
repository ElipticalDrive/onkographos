# Bricking with Boundary Voxel Duplication

Also called: Boundary layer correction, Clipping with pre-integrated volume rendering, Texture Bricking, Volume Boundary Replication

## Overview
Bricking with Boundary Voxel Duplication is a technique to solve incorrect interpolation at texture tile boundaries in 3D volume rendering by duplicating a plane of voxels at each brick boundary [S1, unofficial]. It prevents black strips at cut boundaries in composited images by ensuring features at the cut are not dropped [S2, unofficial]. It focuses on spatial continuity of the scalar field at fixed brick boundaries rather than hierarchical level-of-detail transitions, and addresses hardware texture interpolation artifacts rather than geometric surface representation [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D volume grid divided into subvolumes (bricks).
- Output: A composited image where ray samples across brick boundaries are consistent, avoiding artifacts.

**Data Structures:**
- **Brick Structure:** Neighboring bricks share a common plane of voxels at their boundary to enable consistent trilinear interpolation [S1, unofficial].
- **Boundary Replication:** One layer of the boundary grid is replicated at each subvolume [S2, unofficial].

**Steps:**
1. Divide the volume grid into subvolumes.
2. For each subvolume, replicate the voxel layer at the boundary into the adjacent subvolume's data structure. For example, if Subvolume 1 includes layer 1 to layer $k$, and Subvolume 2 includes layer $k$ to layer $n$, layer $k$ is replicated in Subvolume 2 [S2, unofficial].
3. Load each brick into GPU texture memory.
4. Perform ray casting. When a ray crosses a brick boundary, the texture unit uses the duplicated voxels to perform correct trilinear interpolation across the boundary [S1, unofficial].

**Formulas:**
- Not given in the sources.

**Parameters:**
- Replication depth: 1 layer of voxels [S2, unofficial].

**Edge Cases and Pitfalls:**
- If the view vector is parallel to the cut plane and boundary replication is not used, a black strip will appear at each cut boundary in the composited image [S2, unofficial].
- At the boundary between texture tiles, interpolation is incorrect because the texture unit does not have enough information to consistently interpolate across texture boundaries [S1, unofficial].

**Pseudocode:**
```python
def brick_with_boundary_voxel_duplication(volume_grid, brick_size):
    """
    Divides volume_grid into bricks and duplicates boundary voxels.
    volume_grid: 3D array of voxel values.
    brick_size: tuple (dx, dy, dz) defining brick dimensions.
    """
    bricks = {}
    nx, ny, nz = volume_grid.shape
    bx, by, bz = brick_size
    
    for i in range(0, nx, bx):
        for j in range(0, ny, by):
            for k in range(0, nz, bz):
                x_end = min(i + bx, nx)
                y_end = min(j + by, ny)
                z_end = min(k + bz, nz)
                
                # Allocate brick with 1-voxel overlap on each face
                brick_data = [[[0] * (bz + 2) for _ in range(by + 2)] for _ in range(bx + 2)]
                
                # Copy core data into the center
                for x in range(bx):
                    for y in range(by):
                        for z in range(bz):
                            brick_data[x + 1][y + 1][z + 1] = volume_grid[i + x][j + y][k + z]
                
                # Duplicate boundary planes into overlaps
                # x-faces
                for y in range(by):
                    for z in range(bz):
                        brick_data[0][y + 1][z + 1] = volume_grid[i][j + y][k + z]
                        brick_data[-1][y + 1][z + 1] = volume_grid[x_end - 1][j + y][k + z]
                # y-faces
                for x in range(bx):
                    for z in range(bz):
                        brick_data[x + 1][0][z + 1] = volume_grid[i + x][j][k + z]
                        brick_data[x + 1][-1][z + 1] = volume_grid[i + x][y_end - 1][k + z]
                # z-faces
                for x in range(bx):
                    for y in range(by):
                        brick_data[x + 1][y + 1][0] = volume_grid[i + x][j + y][k]
                        brick_data[x + 1][y + 1][-1] = volume_grid[i + x][j + y][z_end - 1]
                        
                bricks[(i, j, k)] = brick_data
    return bricks
```

## Subtopics

### [Continuous Level Transitions](5275-continuous-level-transitions.md)
Maintains continuity of the 3D scalar field at boundaries where adjacent bricks are rendered at different levels of detail (LOD). It adapts the textures of finer-level bricks to interpolate correctly from the coarser level, restricting transitions to a difference of at most one level.

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Increases memory usage due to duplicated boundary voxels. Not given in the sources.
- **Measured Performance:** For large volume data sets, the bricking strategy is extremely inefficient, resulting in significantly lower frame rates compared to 2D-textures [S1, unofficial].
- **Strengths:** Superior image quality compared to 2D-texture based solutions; removes significant drawbacks of 2D approaches; hardware support for trilinear interpolation provides a natural means of increasing the sampling rate to obtain images of high quality [S1, unofficial].
- **Limitations:** Extremely inefficient for large volume data sets; significantly lower frame rates for large data compared to 2D-textures [S1, unofficial].

## Background
Described in research on volume rendering techniques for graphics hardware [S1, unofficial] and in parallel ray-traced volume rendering algorithms [S2, unofficial]. The 3D-texture based approach has proven superior in terms of image quality, removing some of the significant drawbacks while preserving almost all the benefits [S1, unofficial].
