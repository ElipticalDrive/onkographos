# Dual Grid Traversal


## Overview
Dual Grid Traversal traverses over cubes in a dual grid formed by placing a vertex in the center of each cube in a primal grid and connecting adjacent vertices into cubes [S1, unofficial]. Each 2×2×2 cube in the dual grid spans a 3×3×3 region in the primal grid [S1, unofficial]. It provides a cell-centered representation for volumetric data traversal and isosurface generation.

## How it works
**Inputs and Outputs:**
- Input: A primal grid of dimensions $N \times N \times N$ containing scalar values.
- Output: A dual grid structure containing vertices, values, and connectivity (cells).

**Data Structures:**
The `DualGrid<D>` structure contains `size` (usize), `primal_grid` (PrimalGrid<D>), and `duals` (array of two vectors) [S1, unofficial]. Each vector in `duals` has length $(N-1)^2$ and stores tuples of `(Vec3, D)` representing position and value [S1, unofficial].

**Steps:**
1. Initialize `DualGrid` with size $N$.
2. Calculate `size_minus_one = N - 1`.
3. Initialize `primal_grid` with size $N$.
4. Initialize `duals` with two vectors, each of length `size_minus_one * size_minus_one`, filled with `(Vec3::zero(), D::zero())` [S1, unofficial].

**Formulas:**
- Dual Grid Dimensions: $(N-1) \times (N-1) \times (N-1)$ along each axis [S1, unofficial].
- Dual Vertex Position: $\mathbf{p}_{ijk}$ corresponds to the center of primal cell $(i,j,k)$.

**Parameters:**
- $N$: The dimension of the primal grid. The dual grid dimension is $(N-1)$ along each axis [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** The dual grid cells are defined for $i,j,k \in \{0, \dots, N-2\}$ to avoid out-of-bounds indexing when accessing neighbors [G].
- **Precision:** Mapping continuous coordinates to discrete dual vertices requires careful handling of floating-point rounding near domain boundaries [G].

**Pseudocode:**
```python
def dual_grid_traversal(primal_grid, N):
    # primal_grid: nested list of size N x N x N
    size_minus_one = N - 1
    
    # Initialize duals: two vectors of length (N-1)^2, each element is (position, value)
    duals = [
        [((0.0, 0.0, 0.0), 0.0) for _ in range(size_minus_one * size_minus_one)]
        for _ in range(2)
    ]
    
    # Flatten primal grid values for direct access
    dual_values = [val for row in primal_grid for col in row for val in col]
    
    # Construct dual grid cells (cubes)
    dual_cells = []
    for k in range(size_minus_one):
        for j in range(size_minus_one):
            for i in range(size_minus_one):
                v0 = i + j * N + k * N * N
                v1 = (i + 1) + j * N + k * N * N
                v2 = i + (j + 1) * N + k * N * N
                v3 = (i + 1) + (j + 1) * N + k * N * N
                v4 = i + j * N + (k + 1) * N * N
                v5 = (i + 1) + j * N + (k + 1) * N * N
                v6 = i + (j + 1) * N + (k + 1) * N * N
                v7 = (i + 1) + (j + 1) * N + (k + 1) * N * N
                dual_cells.append([v0, v1, v2, v3, v4, v5, v6, v7])
                
    return duals, dual_values, dual_cells
```

## Subtopics

### [Dual Grid Traversal for Adaptive Octree](4043-dual-grid-traversal-for-adaptive-octree.md)
This method recursively traverses an adaptive octree to generate the vertices, edges, and faces of a dual grid structure. It solves the problem of creating a manifold traversal mesh from non-uniform voxel data by explicitly handling boundaries between octree nodes of different refinement levels. It differs from uniform grid duals by using a set of 2–8 surrounding octree nodes to define each dual vertex, allowing it to bridge gaps where large nodes abut smaller ones. It builds on [Dual Grid Traversal](1233-dual-grid-traversal.md) by adapting the dual grid construction to the hierarchical nature of an octree [G].

### Dual-cell method
A standard approach to bridging cracks across AMR levels by constructing a grid by connecting cell centers instead of re-sampling, using original data values [S2]. It constructs the grid by connecting cell centers using the original data values, mitigating conflicts like dangling nodes [S2]. However, it introduces gaps between hierarchy levels [S2]. It also amplifies compression artifacts, especially block-wise artifacts from SZ-L/R, when the error bound is relatively large [S2].

## Operating characteristics
- **Time Complexity:** $O(N^3)$ for uniform grids, where $N$ is the grid dimension. For adaptive octrees, it depends on the number of nodes [G].
- **Memory Complexity:** $O(N^3)$ for storing dual vertices and values [G].
- **Strengths:** Uses original data values to mitigate conflicts like dangling nodes across AMR levels [S2].
- **Limitations:** Introduces gaps between hierarchy levels in AMR data [S2]; amplifies compression artifacts [S2].

## Background
The dual grid method is a standard approach in volume visualization for bridging cracks across AMR levels [S2]. It was discussed in the context of the WarpX framework and patch-based AMR data reduction techniques [S2]. Implementation details for uniform grids are provided in [S1, unofficial].
