# Dual Grid Construction

Also called: Dual Cell Generation, Adaptive Octree Dual Grid

## Overview
Dual Grid Construction generates a topological structure from an adaptive octree, where each vertex in the dual grid corresponds to a point in the octree, represented as a set of 2–8 surrounding octree nodes to handle adaptive boundaries [S1, unofficial]. It bridges gaps where large nodes abut smaller ones by explicitly tracking node references at interfaces [S1, unofficial].

## How it works
**Inputs:** An adaptive octree root node [S1, unofficial].
**Outputs:** A collection of `DualCell` objects [S1, unofficial].

**Data Structures:**
* `OctreeNode`: Contains `Bounds` (axis-aligned bounding box), `Depth`, and `Children` (array of 8 `OctreeNode` references or `null` if leaf) [S1, unofficial].
* `DualCell`: Contains 8 `OctreeNode` references (`n0` to `n7`) ordered identically to octree children [S1, unofficial]. The `Vertex` property returns `n0.Bounds.max` [S1, unofficial]. The array may contain duplicate references when adjacent nodes have different sizes [S1, unofficial].

**Algorithm Steps:**
1. **Recursive Traversal:** Start at the root. If the current node is a leaf (`Children == null`), yield break or return [S1, unofficial].
2. **Child Traversal:** Recursively traverse all 8 children [S1, unofficial].
3. **Face Processing:** Traverse shared faces between child pairs:
   * X-faces: (0,1), (3,2), (4,5), (7,6) [S1, unofficial].
   * Y-faces: (0,4), (1,5), (3,7), (2,6) [S1, unofficial].
   * Z-faces: (0,3), (1,2), (4,7), (5,6) [S1, unofficial].
4. **Edge Processing:** Traverse shared edges between child quartets:
   * X-edges: (0,3,7,4), (1,2,6,5) [S1, unofficial].
   * Y-edges: (0,1,2,3), (4,5,6,7) [S1, unofficial].
   * Z-edges: (3,2,6,7), (1,0,4,5) [S1, S2, unofficial].
5. **Vertex Processing:** Implicit in the face and edge traversal; each interface generates a `DualCell` containing the participating nodes [S1, unofficial].

**Pseudocode:**
```python
class OctreeNode:
    def __init__(self, bounds, depth, children):
        self.bounds = bounds
        self.depth = depth
        self.children = children

class DualCell:
    def __init__(self, nodes):
        self.nodes = nodes
    @property
    def vertex(self):
        return self.nodes[0].bounds.max

def build_dual_grid(node):
    cells = []
    if node.children is None:
        return cells
    for child in node.children:
        cells.extend(build_dual_grid(child))
    children = node.children
    # X faces
    for i, j in [(0, 1), (3, 2), (4, 5), (7, 6)]:
        cells.append(DualCell([children[i], children[j]]))
    # Y faces
    for i, j in [(0, 4), (1, 5), (3, 7), (2, 6)]:
        cells.append(DualCell([children[i], children[j]]))
    # Z faces
    for i, j in [(0, 3), (1, 2), (4, 7), (5, 6)]:
        cells.append(DualCell([children[i], children[j]]))
    # X edges
    for q in [(0, 3, 7, 4), (1, 2, 6, 5)]:
        cells.append(DualCell([children[i] for i in q]))
    # Y edges
    for q in [(0, 1, 2, 3), (4, 5, 6, 7)]:
        cells.append(DualCell([children[i] for i in q]))
    # Z edges
    for q in [(3, 2, 6, 7), (1, 0, 4, 5)]:
        cells.append(DualCell([children[i] for i in q]))
    return cells
```

**Parameters:**
* Recursion depth: Determined by octree construction [S1, unofficial].
* Thresholds: Not given in the sources.

**Edge Cases and Pitfalls:**
* **Duplicate References:** Large nodes adjacent to smaller nodes cause the same `OctreeNode` reference to appear multiple times in a `DualCell`'s 8-node array [S1, unofficial]. The algorithm explicitly allows these duplicates [S1, unofficial].
* **Boundary Conditions:** Nodes at the boundary of the octree root may have missing children (conceptually null or outside bounds) [S2, unofficial]. These must be handled, often by treating them as leaves or skipping interface generation for missing sides [S2, unofficial].
* **Vertex Consistency:** The `Vertex` property is defined as `n0.Bounds.max` [S1, unofficial].

## Subtopics

### Octree Mesh Generation
This variant focuses on generating the final triangle mesh indices rather than just the dual cells [S2, unofficial]. It calls `GenerateVertexIndices` with the root node and a vertex buffer to populate vertex positions, then calls `CellProc` with an index buffer to populate triangle primitives [S2, unofficial]. It relies on the dual grid construction to identify the topology but adds the step of converting that topology into renderable geometry [S2, unofficial].

## Background
The concept of dual grids in the context of adaptive octrees originates from the need to apply marching cubes-like algorithms to non-uniform voxel data [S1, S2, unofficial]. The specific implementation details are derived from open-source implementations of Dual Marching Cubes [S1, S2, unofficial]. The approach allows for the generation of smooth surfaces from hierarchical data structures commonly used in procedural generation and scientific visualization [S1, S2, unofficial].
