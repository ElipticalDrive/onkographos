# Top Voxel Retrieval


## Overview
Top Voxel Retrieval finds the highest solid voxel at a given $(x,y)$ column and returns its color and $z$-coordinate [S1, unofficial]. It serves as a fast, column-based alternative to full ray marching for determining surface visibility and occlusion [S2, unofficial]. Unlike the parent [Voxel Map Lookup](4226-voxel-map-lookup.md), which retrieves a specific voxel's color, this method searches for the maximum $z$ value within a chunk's sorted block list [S1, unofficial].

## How it works
**Inputs:** A pointer to the `libvxl_map` structure, and integer coordinates $(x, y)$ representing the column to query.
**Outputs:** The color (integer) and $z$-coordinate (short) of the topmost solid voxel. If no solid voxel exists, the behavior is undefined or triggers an assertion [S1, unofficial].

**Data Structures:**
The method relies on the `libvxl_map` structure [S1, unofficial]:
```c
struct libvxl_map {
    size_t* chunk_offsets; // Offsets into the buffer for each chunk
    size_t chunk_size;     // Size of a single chunk in bytes
    void* buffer;          // Raw memory buffer containing chunk data
    size_t buffer_offset;  // Offset of the current chunk's data within buffer
    size_t pos;            // Current position in the buffer
};
```
Each chunk contains a sorted array of blocks (`blocks_sorted`) and a geometry bitfield (`geometry`) [S1, unofficial]. The block structure is:
```c
struct __attribute__((packed)) libvxl_kv6_block {
    int color;           // Voxel color
    short z;             // Z-coordinate
    unsigned char visfaces; // Visibility flags
    unsigned char normal; // Normal vector index
};
```

**Steps:**
1.  **Calculate Chunk Index:** Determine which chunk contains the column $(x, y)$. This is typically derived from the global coordinates divided by the chunk dimensions.
2.  **Access Chunk Data:** Use `chunk_offsets` to find the start of the chunk data in `buffer`. Cast the data to a `libvxl_chunk_copy` structure [S1, unofficial].
3.  **Check Geometry Bitfield:** The parent [Voxel Map Lookup](4226-voxel-map-lookup.md) uses a global geometry bitfield to quickly check if a voxel exists. For top retrieval, the chunk's `geometry` bitfield (or equivalent) should be checked to see if the column $(x, y)$ has any solid voxels. If the bit is unset, no solid voxel exists [S1, unofficial].
4.  **Binary Search for Top Voxel:** The chunk's `blocks_sorted` array is sorted by $z$ coordinate. Perform a binary search (specifically a lower-bound search for $z \ge 0$ or the maximum $z$) to find the highest block [S1, unofficial]. The function `libvxl_chunk_gequal_block` is likely used for this comparison [S1, unofficial].
5.  **Return Result:** Return the `color` and `z` fields of the found block.

**Pitfalls:**
*   **Assertion Failure:** If no block exists at the queried column, `libvxl_chunk_gequal_block` may trigger an assertion because it expects a valid lower-bound match [S1, unofficial]. Always check the geometry bitfield first.
*   **Precision:** The $z$ coordinate is stored as a `short`. Ensure that the world coordinates fit within the range of a signed 16-bit integer [-32768, 32767] [S1, unofficial].

## Subtopics

### 2D Voxel Shadow Map
A 2D shadow map storing the highest occupied voxel Y-coordinate per $(X, Z)$ column to determine occlusion for lighting without ray marching [S2, unofficial]. It is chosen when real-time lighting occlusion is needed and full ray marching is too expensive [S2, unofficial].
*   **Definition:** Stores max Y height for each $(X, Z)$ column [S2, unofficial].
*   **Layout:** `uint16_t*` array of size `shadow_map_size[0] * shadow_map_size[1]` [S2, unofficial].
*   **Index Calculation:** `index = (ws[0] + ws[1]) + (SH_MAX_X * ws[2])`, where `ws[0]` is X, `ws[1]` is Y, `ws[2]` is Z, and `SH_MAX_X` is the shadow map width [S2, unofficial].
*   **Occlusion Test:** A voxel at world space `ws` is in shadow if `shadow_map[index] >= ws[1]+1` OR `shadow_map[index+1] >= ws[1]+1` [S2, unofficial].
*   **Parameter:** `root_bitw` is the log2 scaling factor for world to shadow map coordinates. Typical value: 3 (scaling factor of 8) [S2, unofficial].
*   **Pitfall:** The index calculation adds `ws[1]` to `ws[0]`, shearing the coordinate space. Careful alignment of world bounds and shadow map dimensions is required to avoid out-of-bounds access [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ where $N$ is the number of blocks in the chunk, due to the binary search [S1, unofficial].
*   **Memory Complexity:** $O(1)$ additional memory, as it operates on the existing chunk data [S1, unofficial].
*   **Strengths:** Extremely fast for column-based queries; avoids ray marching overhead [S2, unofficial].
*   **Limitations:** Only provides the top voxel; does not handle internal structures or multiple surfaces per column [S1, unofficial].
*   **When to Use:** For shadow mapping, sky visibility checks, or fast surface culling [S2, unofficial].
*   **When Not to Use:** When internal voxel properties or multiple hits are required [S1, unofficial].

## Background
Top Voxel Retrieval is part of the `libvxl` library, an unofficial voxel engine implementation [S1, unofficial]. It was developed to provide efficient access to voxel data for rendering and game logic [S1, unofficial]. The 2D Voxel Shadow Map variant is part of the `voxplat` project, which focuses on voxel platformer mechanics [S2, unofficial].
