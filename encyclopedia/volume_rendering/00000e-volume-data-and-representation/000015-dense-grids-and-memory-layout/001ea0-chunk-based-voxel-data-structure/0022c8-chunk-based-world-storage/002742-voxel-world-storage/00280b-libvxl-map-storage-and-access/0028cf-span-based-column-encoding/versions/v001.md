# Span-based Column Encoding

Also called: VXL span serialization

## Overview
Span-based Column Encoding compresses a single $(x,y)$ column of a sparse voxel map into a linear sequence of runs, separating air, top-surface color, and bottom-surface color. It solves the problem of efficiently serializing sparse voxel data by reducing the storage of empty space and surface boundaries to compact run-length encoded structures. It differs from [Chunked Voxel Map Serialization with Visfaces](4201-chunked-voxel-map-serialization-with-visfaces.md) by focusing on vertical column integrity and explicit air/run separation rather than face-based mesh generation or horizontal chunking.

## How it works
**Inputs:** A `libvxl_map` structure containing width, height, depth, and a sparse block storage; coordinates $(x,y)$ defining the column to encode.
**Outputs:** A sequence of `libvxl_span` structures written to a buffer.

**Data Structures:**
*   `libvxl_span`: Contains fields `color_start`, `color_end`, `air_start`, `length`, and `offset`. The exact bit layout is not specified in the sources, but it represents a run of voxels.
*   `libvxl_block`: Contains `position` (packed key) and `color` (uint32_t).
*   `position` key: Packed integer where $z$ is extracted via `key_getz()` and the rest via `key_discardz()`.

**Steps:**
1.  **Initialization:** Set `first_run = true`. Determine the starting $z$ coordinate from the first block in the chunk at $(x,y)$. If no blocks exist, the column is empty.
2.  **Determine Top Start:** Query the map geometry at $(x,y,z)$. If a block exists (`libvxl_geometry_get` returns true), set `top_start = z`. Otherwise, set `top_start` to the $z$-coordinate of the first block in the chunk (the lowest occupied voxel). [S1, unofficial]
3.  **Find Top End:** Call `find_successive_surface` to identify `top_end` (the $z$ coordinate immediately above the top surface) and `last_surface_block`. [S1, unofficial]
4.  **Determine Bottom Start:**
    *   If `top_end` equals `map->depth` (column height) OR the voxel at `top_end` is not solid (`!libvxl_geometry_get`), then `bottom_start = top_end`.
    *   Else, if `last_surface_block` points to a block at $z=0$, set `bottom_start` to the $z$-coordinate of that block. [S1, unofficial]
5.  **Write Top Run:**
    *   Set `desc->color_start = top_start`.
    *   Set `desc->color_end = top_end - 1`.
    *   Set `desc->air_start = 0` if `first_run` is true; otherwise `desc->air_start = z` (current $z$).
    *   Advance the buffer offset.
    *   Write top colors: Loop $k$ from `top_start` to `top_end`. For each block, write `(block->color & 0xFFFFFF) | 0x7F000000`. The alpha channel is set to `0x7F` (127), indicating semi-transparency or surface status. Advance offset. [S1, unofficial]
6.  **Write Bottom Run:**
    *   Determine `bottom_end` (implied by context as the end of the bottom color run).
    *   If `bottom_end < map->depth`:
        *   Set `desc->length = 1 + (top_end - top_start) + (bottom_end - bottom_start)`.
        *   Write bottom colors.
        *   Set $z = bottom_end$.
    *   Else (column ends at surface or depth):
        *   Set `desc->length = 1 + (top_end - top_start)`.
        *   Set $z = bottom_start$. [S1, unofficial]

**Pseudocode:**
```python
def encode_column(map, x, y):
    # 1. Initialization
    first_run = True
    # Get starting z from first block in chunk
    chunk = chunk_fposition(map, x, y)
    if chunk.index == 0:
        return [] # Empty column
    
    # Find first block
    first_block = libvxl_chunk_gequal_block(chunk, pos_key(x, y, 0))
    z = key_getz(first_block.position)
    
    # 2. Determine Top Start
    if libvxl_geometry_get(map, x, y, z):
        top_start = z
    else:
        top_start = key_getz(first_block.position)
        
    # 3. Find Top End
    top_end, last_surface_block = find_successive_surface(map, x, y, top_start)
    
    # 4. Determine Bottom Start
    if top_end == map.depth or not libvxl_geometry_get(map, x, y, top_end):
        bottom_start = top_end
    elif last_surface_block and key_getz(last_surface_block.position) == 0:
        bottom_start = key_getz(last_surface_block.position)
    else:
        bottom_start = top_end # Fallback if condition not met
        
    # 5. Write Top Run
    spans = []
    desc = libvxl_span()
    desc.color_start = top_start
    desc.color_end = top_end - 1
    desc.air_start = 0 if first_run else z
    desc.offset = 0 # Placeholder for buffer offset logic
    spans.append(desc)
    
    # Write top colors
    for k in range(top_start, top_end):
        block = get_block_at(map, x, y, k)
        if block:
            color = (block.color & 0xFFFFFF) | 0x7F000000
            write_color(color) # To buffer
            
    # 6. Write Bottom Run
    # Note: bottom_end is not explicitly defined in the snippet, 
    # assumed to be derived from geometry or block data below top_end.
    # Assuming bottom_end is found similarly to top_end or via geometry check.
    bottom_end = find_bottom_end(map, x, y, bottom_start)
    
    if bottom_end < map.depth:
        desc.length = 1 + (top_end - top_start) + (bottom_end - bottom_start)
        # Write bottom colors
        for k in range(bottom_start, bottom_end):
            block = get_block_at(map, x, y, k)
            if block:
                write_color(block.color)
        z = bottom_end
    else:
        desc.length = 1 + (top_end - top_start)
        z = bottom_start
        
    return spans
```

**Parameters:**
*   `map->depth`: Total height of the voxel map.
*   `0x7F000000`: Alpha mask for surface blocks.

**Edge Cases:**
*   **Empty Column:** If no blocks exist in the chunk, the function should return early or handle the absence of `first_block`.
*   **Boundary Conditions:** `top_end` can equal `map->depth`. `bottom_start` logic depends on whether the surface touches the bottom ($z=0$) or ends at the top.
*   **Precision:** Color packing uses bitwise AND with `0xFFFFFF` to mask RGB, preserving only the lower 24 bits.

## Subtopics

### [Voxel Map Streaming](4946-voxel-map-streaming.md)
Voxel Map Streaming is a sequential I/O method for dense voxel maps that outputs fixed-size binary chunks by iterating over $(x,y)$ columns. It solves the problem of efficient bulk transfer of voxel data by buffering encoded columns into a sliding window, allowing consumers to read data in predictable, fixed-size blocks without managing individual column boundaries. It differs from direct column access by abstracting the underlying [Span-based Column Encoding](4365-span-based-column-encoding.md) into a continuous byte stream with internal buffering and chunking logic.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of blocks in the column, as it iterates through surface blocks to determine runs.
*   **Memory Complexity:** Proportional to the number of runs in the column.
*   **Strengths:** Efficiently compresses sparse columns by ignoring large air gaps. Explicitly handles surface colors with alpha masking.
*   **Limitations:** Requires random access to blocks within a column to determine geometry and colors. Not suitable for horizontal traversal without re-encoding.
*   **When to Use:** When serializing voxel maps for storage or network transmission where column-wise access is natural.
*   **When Not to Use:** When horizontal slicing or face-based mesh generation is required (use [Chunked Voxel Map Serialization with Visfaces](4201-chunked-voxel-map-serialization-with-visfaces.md) instead).

## Background
Span-based Column Encoding is part of the `libvxl` library, an implementation of the Voxel Space map format used in the game *Ace of Spades*. It was developed by xtreme8000 to provide an efficient internal representation for sparse voxel data. The method derives from the `.vxl` file format specifications, focusing on compact serialization of columnar data.
