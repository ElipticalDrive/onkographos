# Voxel World Storage

Also called: VoxelWorld
## Overview
Voxel World Storage is a dense grid data structure that maintains block types for each chunk in world coordinates, enabling direct ray querying of the voxel space [S1, unofficial]. It solves the problem of selecting or interacting with specific voxels in a scene that lacks traditional mesh colliders by providing a coordinate-mapped lookup of block types [S1, unofficial].
## How it works
**Inputs and Outputs:**
- Input: Ray origin, ray direction, and a `VoxelWorld` containing chunk data and bounds [S1, unofficial].
- Output: A `VoxelRayHit` structure containing the solid voxel coordinates, its block type, the face normal and identifier of the crossing boundary, the empty voxel preceding the hit, and the distance to the hit [S1, unofficial].
**Data Structures:**
1. `VoxelWorld`: Stores `Min` and `Max` vectors defining the world limits box, and a collection of chunks [S1, unofficial]. Positions outside this box are treated as empty [S1, unofficial].
2. `Chunk`: Contains a dense `BlockTypes` array [S1, unofficial]. The sample scene allocates 2 bytes per voxel, totaling 32 MiB across 1,024 chunks [S1, unofficial].
**Algorithm (Voxel Ray Traversal):**
The traversal follows the Amanatides and Woo algorithm [S1, unofficial].
1. Initialize current voxel $v = \lfloor origin \rfloor$ [G].
2. Determine step direction per axis: $step = \text{sign}(direction)$ [G].
3. Calculate $t_{max}$ and $t_{delta}$ for boundary crossings per axis [G].
4. Loop while distance $\le$ max distance (default: 64 voxels) [S1, unofficial] and $Min \le v \le Max$ [S1, unofficial]:
   a. Identify axis with smallest $t_{max}$ [G].
   b. Update $t_{max}$ for that axis by adding $t_{delta}$ [G].
   c. Advance $v$ by $step$ in that axis [G].
   d. Retrieve block type at $v$ via world-to-chunk translation [S1, unofficial].
   e. If empty, continue [S1, unofficial].
   f. If solid, record hit (solid voxel, block type, normal, face, empty voxel, distance) and return [S1, unofficial].
**Pseudocode:**
```python
def VoxelRay(origin, direction, voxel_world, max_distance=64.0):
    # Amanatides & Woo initialization [G]
    v = floor(origin)
    step = sign(direction)
    t_delta = abs(1.0 / direction)
    next_boundary = v + step
    t_max = (next_boundary - origin) * t_delta
    prev_v = v
    distance = 0.0
    while distance <= max_distance and all(voxel_world.Min <= v <= voxel_world.Max):
        # Tie-breaking: X first, then Y, then Z [S1, unofficial]
        if t_max[0] <= t_max[1] and t_max[0] <= t_max[2]:
            axis = 0
        elif t_max[1] <= t_max[2]:
            axis = 1
        else:
            axis = 2
        prev_v = v
        v[axis] += step[axis]
        t_max[axis] += t_delta[axis]
        distance = t_max[axis]
        if not all(voxel_world.Min <= v <= voxel_world.Max):
            break
        block_type = voxel_world.GetBlockType(v)
        if block_type != EMPTY:
            return VoxelRayHit(solid_voxel=v, block_type=block_type, normal=axis_to_normal(axis, step[axis]), face=axis, empty_voxel=prev_v, distance=distance)
    return None
```
**Edge Cases:**
- World limits: The ray stops if it exits the box defined by `Min` and `Max` [S1, unofficial].
- Max distance: The ray stops if the distance exceeds the default 64 voxels [S1, unofficial].
- Edges/Corners: At simultaneous boundaries, the ray crosses X first, then Y, then Z [S1, unofficial].
- Outside world: A position outside all chunks is treated as empty [S1, unofficial].
**Pitfalls:**
- Changing a chunk array after `AddChunk` is permitted to allow in-place updates [S1, unofficial].
- Precision and depth offset handling notes were previously too strong and were relaxed [S1, unofficial].

## Operating characteristics
- Time Complexity: Ray traversal is $O(d)$ where $d$ is the distance to the hit or max distance, as it visits each voxel along the ray path [S1, unofficial].
- Memory Complexity: $O(N)$ where $N$ is the total number of voxels, with the sample scene using 32 MiB for 1,024 chunks at 2 bytes per voxel [S1, unofficial].
- Strengths: Direct access to block types without mesh colliders, enabling efficient ray-based selection [S1, unofficial].
- Limitations: Dense storage requires significant memory for large worlds, and traversal depth is limited by the maximum distance parameter [S1, unofficial].
## Background
Voxel World Storage was introduced in a legacy project to enable voxel ray querying for selecting voxels at the screen center, replacing the legacy Physics.Raycast on mesh colliders [S1, unofficial]. It was part of the M1 milestone port, adding features like the voxel ray and selection box pipeline [S1, unofficial].
