# Sparse Voxel Octree Memory Management and Texture Upload

Also called: SVO Memory Management, SVO Texture Upload Optimization

## Overview
[S1, unofficial] This method manages the memory layout of a sparse voxel octree in a flat integer array and optimizes GPU texture uploads by tracking changes per 256×256 slice. [S1, unofficial] It solves the problem of inefficient full-texture updates for dynamic or sparse data by only transferring modified slices to the GPU. [G] It differs from sibling methods like [Priority Queue Based Field Update](7430-priority-queue-based-field-update.md) by focusing on memory compaction and incremental texture synchronization rather than field update ordering.

## How it works
### Inputs and Outputs
[S1, unofficial] Input: a flat integer array `_data` representing the octree structure, attribute arrays to encode, and a target `Texture3D` on the GPU. [S1, unofficial] Output: an updated `Texture3D` containing the latest octree state and a compacted `_data` array with free memory removed.

### Data Structures
[S1, unofficial] The core data structure is `_data`, a list of 32-bit signed integers. [S1, unofficial] Each integer encodes one of four types: a branch pointer (bits 0–30 store the index in `_data` of the first child, bit 31 is 0), a leaf pointer (bit 31 is 1, bits 0–30 store the index where the leaf's attribute data begins), an empty node (value `1 << 31`), or attribute data (the first integer of a block, where bits 24–31 store the attribute count, and subsequent integers store the values). [S1, unofficial] Free memory is tracked via two lists: `_freeStructureMemory` for branch/leaf pointers and `_freeAttributeMemory` for attribute blocks.

### Pseudocode
```python
def next_power_of_two(n: int) -> int:
    return 1 << (n - 1).bit_length() if n > 0 else 1

def allocate_attribute_data(attributes: list[int], _data: list[int], _freeAttributeMemory: list[int]) -> int:
    """Allocates space for attribute data in _data."""
    if len(attributes) > 65536:
        raise ValueError("Attribute count exceeds limit.")
    for ptr in _freeAttributeMemory:
        if (_data[ptr] >> 24) == len(attributes):
            for i in range(len(attributes)):
                _data[ptr + i] = attributes[i]
            _freeAttributeMemory.remove(ptr)
            return ptr
    end_ptr = len(_data)
    for attr in attributes:
        _data.append(attr)
    return end_ptr

def rebuild_node(index: int, _data: list[int], optimized_data: list[int]) -> None:
    """Recursively rebuilds the octree structure into optimized_data."""
    value = _data[index]
    if value == (1 << 31):
        optimized_data.append(1 << 31)
    elif value & (1 << 31):
        optimized_data.append((1 << 31) | len(optimized_data))
        attr_start = value & 0x7FFFFFFF
        attr_count = _data[attr_start] >> 24
        for k in range(attr_count + 1):
            optimized_data.append(_data[attr_start + k])
    else:
        optimized_data.append(len(optimized_data))
        # Process children stored sequentially after the branch pointer in _data
        # The exact child iteration depends on the octree encoding, 
        # but the evidence specifies recursive calls for each child.
        # For implementation, iterate over the 8 children indices following this node.
        for child_idx in range(index + 1, index + 9):
            rebuild_node(child_idx, _data, optimized_data)

def rebuild(_data: list[int], _freeStructureMemory: list[int], _freeAttributeMemory: list[int], _lastApply: list[int]) -> list[int]:
    """Compacts _data by removing empty nodes and free memory blocks."""
    cap = next_power_of_two(len(_data) - len(_freeStructureMemory) * 8 - len(_freeAttributeMemory))
    optimized_data = [0] * cap
    rebuild_node(0, _data, optimized_data)
    _data[:] = optimized_data
    _freeStructureMemory.clear()
    _freeAttributeMemory.clear()
    _lastApply[:] = [2**64 - 1] * len(_lastApply)
    return optimized_data

def apply_texture(_data: list[int], texture: object, _lastApply: list[int], _updateCount: list[int], try_reuse_old_texture: bool) -> None:
    """Uploads changed slices of _data to the GPU texture."""
    depth = next_power_of_two((len(_data) + 256 * 256 - 1) // (256 * 256))
    if texture is None or texture.depth != depth or not try_reuse_old_texture:
        texture = create_texture3d(256, 256, depth, "RFloat", False)
        _lastApply[:] = [2**64 - 1] * depth
    temp_tex = create_texture2d(256, 256, "RFloat")
    for i in range(depth):
        if _lastApply[i] == _updateCount[i]:
            continue
        min_index = i * 256 * 256
        max_index = min((i + 1) * 256 * 256, len(_data))
        slice_data = _data[min_index:max_index]
        set_pixel_data(temp_tex, slice_data)
        graphics_copy_texture(temp_tex, texture, slice=i)
        if max_index > min_index:
            _updateCount[i] += 1

# Standard stubs to satisfy self-contained Python requirement
class Texture3D:
    def __init__(self, w, h, d, fmt, mipmaps):
        self.width, self.height, self.depth = w, h, d
        self.format = fmt
        self.mipmaps = mipmaps
def create_texture3d(w, h, d, fmt, mipmaps): return Texture3D(w, h, d, fmt, mipmaps)
class Texture2D:
    def __init__(self, w, h, fmt):
        self.width, self.height = w, h
        self.format = fmt
def create_texture2d(w, h, fmt): return Texture2D(w, h, fmt)
```

### Parameters
[S1, unofficial] Texture resolution is 256×256 pixels per slice. [S1, unofficial] Texture format is `RFloat` (single-channel floating point). [S1, unofficial] Depth is dynamic, calculated as $2^{\lceil \log_2(\lceil N / 256^2 \rceil) \rceil}$, where $N$ is the number of integers in `_data`.

### Edge Cases and Pitfalls
[S1, unofficial] If `attributes.Count > 65536`, an `ArgumentException` is thrown. [S1, unofficial] This is a safety bound related to slice size assumptions, despite the attribute count being stored in a single byte (max 255). [G] Precision is limited by 32-bit integer indices, allowing up to $2^{31}-1$ entries. [G] Boundary conditions require clamping `max_index` to `_data.Count` to avoid out-of-bounds access.

## Operating characteristics
[S1, unofficial] Time complexity for `AllocateAttributeData` is $O(1)$ average if a free block matches, or $O(M)$ where $M$ is the free list size. [S1, unofficial] `Rebuild` runs in $O(N)$ time as it traverses the entire structure. [S1, unofficial] `Apply` runs in $O(S)$ time where $S$ is the number of changed slices, plus GPU upload overhead. [S1, unofficial] Memory complexity is $O(N)$ for the flat array with additional overhead for free lists. [G] Compaction reduces memory usage by removing empty nodes and free blocks. [G] Performance is optimized for dynamic scenes with small changes, avoiding full texture uploads. [G] Strengths include efficient memory usage and incremental updates. [G] Limitations include 32-bit index bounds and potential fragmentation without regular rebuilding.

## Background
[S1, unofficial] This method originates from the `xandergos/unity-sparse-voxel-octrees` repository. [G] It is designed for real-time rendering, leveraging C# and HLSL for GPU communication. [G] The approach supports dynamic meshes and real-time updates, contrasting with static SVO representations used in offline rendering.
