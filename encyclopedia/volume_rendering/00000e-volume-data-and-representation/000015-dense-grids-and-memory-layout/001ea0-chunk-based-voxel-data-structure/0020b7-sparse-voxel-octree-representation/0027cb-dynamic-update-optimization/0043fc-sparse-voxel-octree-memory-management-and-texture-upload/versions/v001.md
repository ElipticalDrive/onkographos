# Sparse Voxel Octree Memory Management and Texture Upload

Also called: SVO Memory Management, SVO Texture Upload Optimization

## Overview
This method manages the memory layout of a Sparse Voxel Octree (SVO) in a flat integer array and optimizes GPU texture uploads by tracking changes per 256x256 slice. It solves the problem of inefficient full-texture updates for dynamic or sparse data by only transferring modified slices to the GPU. It differs from sibling methods like [Priority Queue Based Field Update](7430-priority-queue-based-field-update.md) by focusing on memory compaction and incremental texture synchronization rather than field update ordering.

## How it works
### Inputs and Outputs
- **Input**: A list of integers `_data` representing the SVO structure; a list of attribute arrays to be encoded; a target `Texture3D` on the GPU.
- **Output**: An updated `Texture3D` containing the latest SVO state; a compacted `_data` array with free memory removed.

### Data Structures
The core data structure is `_data`, a `List<int>` (32-bit signed integers). Each integer encodes one of the following:
1.  **Branch Pointer**: Bits 0–30 store the index in `_data` of the first child. Bit 31 is 0.
2.  **Leaf Pointer**: Bit 31 is 1. Bits 0–30 store the index in `_data` where the leaf's attribute data begins.
3.  **Empty Node**: Value is `1 << 31` (0x80000000). Indicates a null or empty voxel.
4.  **Attribute Data**: The first integer of an attribute block. Bits 24–31 (the most significant byte) store the count of attributes in that block. The remaining 31 bits (or subsequent integers) store the attribute values.

Free memory is tracked via two lists: `_freeStructureMemory` (for branch/leaf pointers) and `_freeAttributeMemory` (for attribute blocks).

### Pseudocode

```python
def allocate_attribute_data(attributes: List[int], _data: List[int], _freeAttributeMemory: List[int], attributes_count: int) -> int:
    """
    Allocates space for attribute data in _data.
    attributes: List of integer attribute values.
    attributes_count: Expected number of attributes (stored in first byte of first int).
    Returns: Index in _data where attributes start.
    """
    if len(attributes) > 65536:
        raise ArgumentException("Attribute count exceeds limit.")

    # Check for free block with matching attribute count
    for ptr in _freeAttributeMemory:
        # Check if the first byte of the free block matches the expected attribute count
        # In C#, _data[ptr] >> 24 extracts the most significant byte
        if (_data[ptr] >> 24) == attributes_count:
            # Copy attributes into the free block
            for i in range(len(attributes)):
                _data[ptr + i] = attributes[i]
            
            # Record updates for texture upload
            update_ptr = ptr
            update_end_ptr = ptr + len(attributes) - 1
            _freeAttributeMemory.remove(ptr)
            return update_ptr

    # No free block found; append to end
    end_ptr = len(_data)
    for attr in attributes:
        _data.append(attr)
    
    update_ptr = end_ptr
    update_end_ptr = end_ptr + len(attributes) - 1
    return update_ptr

def rebuild(_data: List[int]) -> List[int]:
    """
    Compacts _data by removing empty nodes and free memory blocks.
    Returns: New compacted list of integers.
    """
    optimized_data = []
    # Estimate capacity to avoid reallocations
    # Note: This formula assumes specific memory layout details from source
    estimated_capacity = next_power_of_two(len(_data) - len(_free_structure_memory) * 8 - len(_free_attribute_memory))
    optimized_data = [0] * estimated_capacity
    
    # Recursive rebuild logic (simplified for flat list representation)
    # In practice, this requires traversing the octree structure encoded in _data
    # and rebuilding the flat array.
    
    # Placeholder for recursive traversal logic based on source description:
    # For each child of a branch:
    #   if value == (1 << 31): add (1 << 31)
    #   elif bit 31 is set (leaf): add (1 << 31 | optimized_data.count), then append attributes
    #   else (branch): add optimized_data.count, recursively rebuild
    
    # Since full recursive implementation depends on tree traversal not fully detailed in flat list ops,
    # we describe the transformation:
    # 1. Iterate through _data.
    # 2. If node is empty (1<<31), add to optimized_data.
    # 3. If node is leaf, add pointer with offset, then append attribute data.
    # 4. If node is branch, add pointer to new location, then recursively process children.
    
    # Clear free lists
    _free_structure_memory.clear()
    _free_attribute_memory.clear()
    
    return optimized_data

def apply_texture(_data: List[int], texture: Texture3D, _last_apply: List[int], _update_count: List[int]) -> None:
    """
    Uploads changed slices of _data to the GPU texture.
    """
    # Calculate depth based on data size
    # Mathf.NextPowerOfTwo(Mathf.CeilToInt((float) _data.Count / 256 / 256))
    depth = next_power_of_two(ceil(len(_data) / 256.0 / 256.0))
    
    # Check if texture needs recreation
    if texture is None or texture.depth != depth or not try_reuse_old_texture:
        destroy_old_texture(texture)
        texture = create_texture3d(256, 256, depth, TextureFormat.RFloat, mipmaps=False)
        _last_apply = [max_int64] * depth
    
    temp_tex = create_texture2d(256, 256, TextureFormat.RFloat)
    
    for i in range(depth):
        if _last_apply[i] == _update_count[i]:
            continue  # Skip unchanged slices
        
        min_index = i * 256 * 256
        max_index = min((i + 1) * 256 * 256, len(_data))
        
        # Copy slice data to temp texture
        set_pixel_data(temp_tex, _data[min_index:max_index])
        
        # Copy from temp texture to main texture slice
        graphics_copy_texture(temp_tex, texture, slice=i)
        
        # Increment update count if changes occurred
        if max_index > min_index:
            _update_count[i] += 1
    
    _last_apply = _update_count.copy()
```

### Parameters
- **Texture Resolution**: 256x256 pixels per slice.
- **Texture Format**: `RFloat` (single-channel floating point).
- **Depth**: Dynamic, calculated as $2^{\lceil \log_2(\lceil N / 256^2 \rceil) \rceil}$, where $N$ is the number of integers in `_data`.

### Edge Cases and Pitfalls
- **Attribute Count Limit**: If `attributes.Count > 65536`, an `ArgumentException` is thrown. This is a safety bound related to slice size assumptions, despite the attribute count being stored in a single byte (max 255). The source notes a discrepancy between the byte limit and the code check [S1, unofficial].
- **Precision**: The use of 32-bit integers for pointers and attributes may limit the maximum size of the octree. Bit 31 is used as a type flag, leaving 31 bits for indices, allowing up to $2^{31}-1$ entries.
- **Boundary Conditions**: When calculating `max_index` for texture slices, ensure it is clamped to `_data.Count` to avoid out-of-bounds access.

## Operating characteristics
- **Time Complexity**: 
  - `AllocateAttributeData`: $O(1)$ average case if free block found, $O(N)$ worst case if scanning free list.
  - `Rebuild`: $O(N)$ where $N$ is the number of nodes, as it traverses the entire structure.
  - `Apply`: $O(S)$ where $S$ is the number of changed slices, plus GPU upload time.
- **Memory Complexity**: $O(N)$ for the flat array, with additional overhead for free lists. Compaction reduces memory usage by removing empty nodes.
- **Performance**: Optimized for dynamic scenes where only small portions of the octree change. Avoids full texture uploads, reducing bandwidth usage.
- **Strengths**: Efficient memory usage, incremental updates, simple data structure.
- **Limitations**: Limited by 32-bit integer indices, potential fragmentation if not rebuilt regularly.

## Background
This method is part of the Unity Sparse Voxel Octrees project by xandergos [S1, unofficial]. It is designed for real-time rendering in Unity, leveraging C# and HLSL for GPU communication. The approach is tailored for dynamic meshes and real-time updates, contrasting with static SVO representations used in offline rendering.
