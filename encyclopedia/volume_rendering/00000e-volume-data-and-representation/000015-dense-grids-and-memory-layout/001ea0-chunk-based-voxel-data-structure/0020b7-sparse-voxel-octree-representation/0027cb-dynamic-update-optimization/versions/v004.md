# Dynamic Update Optimization

Also called: Dynamic Voxel Cone Tracing Optimization, Dynamic SVO Update Pipeline

## Overview
Dynamic Update Optimization is a set of heuristics and data management strategies designed to accelerate indirect illumination calculations in real-time voxel cone tracing by separating static and dynamic scene components [S1, unofficial]. It solves the performance bottleneck of re-voxelizing and re-filtering the entire Sparse Voxel Octree (SVO) every frame when only a subset of objects are moving [S1, unofficial]. Unlike static-only approaches, it maintains a persistent octree for static geometry while appending dynamic voxel fragments to the end of the node buffer, allowing for incremental updates [S1, unofficial]. It differs from sibling methods like [Sparse Voxel Octree with Bricks](2354-sparse-voxel-octree-with-bricks.md) by focusing on temporal update scheduling and atomic accumulation rather than spatial data compaction, and from [SVRaster](2464-svraster.md) by retaining the hierarchical cone tracing pipeline rather than rasterizing voxels directly.

## How it works
The method operates on a Sparse Voxel Octree (SVO) where each node stores voxel data. The core innovation is the separation of static and dynamic data within the same buffer structure and the optimization of the voxelization and filtering passes.

### Inputs and Outputs
*   **Input:** Scene geometry (static and dynamic), camera position, camera frustum, maximum cone tracing distance.
*   **Output:** Updated SVO node buffer containing static data (unchanged) and dynamic fragments (new/updated), filtered indirect illumination values.

### Data Structures
The SVO node buffer is a flat array. Each node contains:
*   **Static Flag:** A bit flag indicating if the node is static [S1, unofficial].
*   **Normal:** A vector representing the voxel normal [S1, unofficial].
*   **Counter:** A 1-byte integer counter used to track the number of contributions for dynamic voxels [S1, unofficial].
*   **Neighbor Offset:** An offset pointing to neighbor nodes, which must be reset if dynamic nodes are appended [S1, unofficial].
*   **Diffuse Color:** The accumulated diffuse color [S1, unofficial].

*Note: The counter is stored only for normals to facilitate the `InterlockedMax` optimization for dynamic geometry, not for other attributes [S1, unofficial].*

### Algorithm Steps

1.  **Initialization (Static Geometry):**
    *   Perform the standard 4 steps of voxel cone tracing (voxelization, filtering, etc.) for all static geometry [S1, unofficial].
    *   Mark all resulting octree nodes as static using the bit flag [S1, unofficial].
    *   Store these nodes in the octree buffer [S1, unofficial].

2.  **Dynamic Voxelization (Per Frame):**
    *   Identify dynamic objects in the scene [S1, unofficial].
    *   Voxelize dynamic geometry into the octree.
    *   **Accumulation Strategy:** Use `InterlockedMax()` to compute both diffuse color and normal for the octree voxel [S1, unofficial].
        *   *Reasoning:* `InterlockedMax()` is faster than atomic average [S1, unofficial].
        *   *Trade-off:* Using `InterlockedMax()` for normals decreases lighting quality for small voxel volumes (e.g., $256 \times 256 \times 256$) due to artifacts where light reflects off the max normal instead of the average [S1, unofficial].
        *   *Implementation Detail:* For dynamic geometry, use `InterlockedMax()` for normals. For static geometry, compute average normals [S1, unofficial]. The 1-byte counter tracks contributions for this purpose [S1, unofficial].
    *   Append dynamic voxel fragments to the **end** of the octree node buffer [S1, unofficial].
    *   Reset the static octree node neighbor offsets that point to the newly appended dynamic nodes [S1, unofficial].

3.  **Affected Node Identification:**
    *   Dispatch threads for all nodes to find those affected by dynamic voxels from the previous and current frames [S1, unofficial].
    *   Queue the indices of these affected nodes into a buffer [S1, unofficial].
    *   Only recalculate values for nodes in this buffer [S1, unofficial].

4.  **Direct Lighting Injection with Frustum Culling:**
    *   Perform view-frustum culling when injecting direct lighting into the octree [S1, unofficial].
    *   **Extended Frustum:** Calculate an extended frustum from the current camera by moving the camera backward and increasing the far plane using the same field of view [S1, unofficial].
    *   **Extended Distance:** Calculated as:
        $$ D_{ext} = D_{max\_cone} + D_{voxel\_size} $$
        Where $D_{max\_cone}$ is the maximum cone tracing distance (limited in the demo, potentially losing far objects like sky) and $D_{voxel\_size}$ is the filtered voxel size [S1, unofficial].
    *   Only voxels within this extended frustum are filtered [S1, unofficial].

5.  **Cone Tracing Pass Optimization:**
    *   Perform the cone tracing pass at **half resolution** of the screen resolution [S1, unofficial].
    *   **Artifact Handling:** Upscaling to full resolution causes visible artifacts, especially at geometry edges [S1, unofficial].
    *   **Correction Method:**
        1.  Perform an edge detection filter using the depth buffer to identify problematic pixels [S1, unofficial].
        2.  **Option A (High Quality):** Re-perform cone tracing at full resolution for these edge pixels. This removes artifacts but significantly drops frame rate [S1, unofficial].
        3.  **Option B (High Performance):** Blur the identified edge pixels by averaging with neighbor pixels. This is much faster but results in lower quality than Option A [S1, unofficial].

### Pseudocode

```python
def dynamic_update_optimization(scene, camera, frame_count):
    # Step 1: Initialization (Only once)
    if frame_count == 0:
        static_nodes = voxelize_static_geometry(scene.static_objects)
        for node in static_nodes:
            node.is_static = True
            node.normal = compute_average_normal(node.contributions) # Average for static
        octree_buffer = static_nodes
        octree_buffer.append_dynamic_marker() # Mark end of static section

    # Step 2: Dynamic Voxelization (Every frame)
    dynamic_fragments = []
    for obj in scene.dynamic_objects:
        voxels = voxelize_geometry(obj)
        for voxel in voxels:
            # Use InterlockedMax for dynamic normals (faster, lower quality)
            # Counter tracks contributions for this voxel
            existing_node = find_or_create_node_in_octree(voxel.position)
            if existing_node:
                existing_node.diffuse = max(existing_node.diffuse, voxel.diffuse)
                existing_node.normal = max(existing_node.normal, voxel.normal) # InterlockedMax
                existing_node.counter += 1
            else:
                new_node = Node()
                new_node.diffuse = voxel.diffuse
                new_node.normal = voxel.normal
                new_node.counter = 1
                new_node.is_static = False
                dynamic_fragments.append(new_node)
    
    # Append dynamic fragments to end of buffer
    octree_buffer.extend(dynamic_fragments)
    
    # Reset neighbor offsets for static nodes pointing to new dynamic nodes
    reset_neighbor_offsets(octree_buffer, len(dynamic_fragments))

    # Step 3: Identify Affected Nodes
    affected_node_indices = []
    for node_index in range(len(octree_buffer)):
        node = octree_buffer[node_index]
        if is_affected_by_dynamic_voxels(node, dynamic_fragments):
            affected_node_indices.append(node_index)
            
    # Step 4: Filter Affected Nodes
    for idx in affected_node_indices:
        node = octree_buffer[idx]
        if not node.is_static:
            # Re-filter dynamic nodes
            filter_node(node)
        else:
            # Re-filter static nodes affected by dynamic changes
            filter_node(node)

    # Step 5: Direct Lighting Injection with Extended Frustum
    camera_pos = camera.position
    fov = camera.fov
    max_cone_dist = get_max_cone_tracing_distance()
    voxel_size = get_filtered_voxel_size()
    
    # Calculate extended distance
    extended_dist = max_cone_dist + voxel_size
    
    # Create extended frustum
    extended_frustum = create_extended_frustum(camera_pos, fov, extended_dist)
    
    for node in octree_buffer:
        if is_inside_frustum(node, extended_frustum):
            inject_direct_lighting(node, scene.lights)

    # Step 6: Cone Tracing Pass
    # Render at half resolution
    half_res_buffer = render_cone_tracing(octree_buffer, camera, resolution=screen_resolution / 2)
    
    # Upscale and fix artifacts
    full_res_buffer = upscale(half_res_buffer, method='bilinear')
    
    # Detect edges using depth buffer
    edge_mask = detect_edges(full_res_buffer.depth_buffer)
    
    # Option B: Blur edge pixels (Faster)
    blurred_edges = blur_pixels(full_res_buffer, edge_mask, neighbor_count=8)
    final_image = blend(full_res_buffer, blurred_edges, edge_mask)
    
    # Note: Option A (Re-trace edges) is omitted for performance in this implementation
    # if performance_critical:
    #     edge_pixels = get_pixel_coords(edge_mask)
    #     edge_tracing = render_cone_tracing(octree_buffer, camera, resolution=screen_resolution, pixels=edge_pixels)
    #     final_image = replace_pixels(full_res_buffer, edge_tracing, edge_pixels)
    
    return final_image
```

### Parameters and Typical Values
*   **Voxel Resolution:** $256 \times 256 \times 256$ is cited as a size where `InterlockedMax()` artifacts become visible [S1, unofficial].
*   **Cone Tracing Resolution:** Half of screen resolution [S1, unofficial].
*   **Extended Frustum Distance:** Sum of maximum cone tracing distance and filtered voxel size [S1, unofficial].
*   **Dynamic Object Voxelization:** Only dynamic objects are voxelized every frame [S1, unofficial].

### Edge Cases and Pitfalls
*   **Normal Artifacts:** Using `InterlockedMax()` for normals in small voxels causes incorrect lighting reflections [S1, unofficial]. Solution: Use average normals for static geometry, `InterlockedMax` only for dynamic [S1, unofficial].
*   **Far Object Sampling:** Limiting cone tracing distance may lose ability to sample far objects like sky [S1, unofficial].
*   **Upscaling Artifacts:** Bilinear upscaling of half-resolution cone tracing creates visible artifacts at geometry edges [S1, unofficial].
*   **Performance Drop:** Re-tracing edge pixels at full resolution significantly drops frame rate [S1, unofficial].

## Subtopics

### [Priority Queue Based Field Update](7430-priority-queue-based-field-update.md)
A scheduling mechanism for hierarchical volume data structures that ensures field modifications are applied from coarser levels to finer levels. It solves the problem of visual artifacts and inconsistency in interactive volume sculpting, where a depth-first recursive update would modify fine details before their coarser parents are adjusted, violating the hierarchical dependency required for correct resolution-adaptive rendering. Unlike sibling methods that may handle memory or texture uploads, this method specifically manages the temporal and spatial order of geometric updates using a priority queue of cell queues.

### [Sparse Voxel Octree Memory Management and Texture Upload](11147-sparse-voxel-octree-memory-management-and-texture-upload.md)
This method manages the memory layout of a Sparse Voxel Octree (SVO) in a flat integer array and optimizes GPU texture uploads by tracking changes per 256x256 slice. It solves the problem of inefficient full-texture updates for dynamic or sparse data by only transferring modified slices to the GPU. It differs from sibling methods like [Priority Queue Based Field Update](7430-priority-queue-based-field-update.md) by focusing on memory compaction and incremental texture synchronization rather than field update ordering.

## Operating characteristics
*   **Time Complexity:** Reduced per-frame cost for dynamic scenes. Static geometry is processed once. Dynamic geometry processing is $O(N_{dynamic})$ for voxelization and $O(N_{affected})$ for filtering, where $N_{affected}$ is the number of nodes impacted by dynamic changes [S1, unofficial].
*   **Memory Complexity:** The octree buffer grows with dynamic fragments. Since dynamic fragments are appended to the end, the buffer size increases over time unless cleared [S1, unofficial].
*   **Measured Performance:** Using `InterlockedMax()` is faster than atomic average [S1, unofficial]. Half-resolution cone tracing with blurring is much faster than full-resolution re-tracing of edge pixels [S1, unofficial].
*   **Strengths:** Significant speedup for scenes with dynamic objects. Efficient use of GPU parallelism via atomic operations and frustum culling.
*   **Limitations:** Visual artifacts from `InterlockedMax()` normals in small voxels. Artifacts from half-resolution upscaling. Potential loss of far-field lighting due to cone tracing distance limits. Frame rate drops if high-quality edge correction is chosen [S1, unofficial].
*   **When to Use:** Real-time applications with dynamic objects where performance is critical and some visual degradation is acceptable.
*   **When Not to Use:** Applications requiring high-fidelity lighting on small dynamic objects or where far-field indirect illumination is critical.

## Background
Dynamic Update Optimization was introduced by Simon Green in his blog post "Implementing Voxel Cone Tracing" in January 2013 [S1, unofficial]. It was developed as part of an unofficial implementation of voxel cone tracing to address the performance challenges of real-time indirect illumination in dynamic scenes [S1, unofficial]. The method builds on the Sparse Voxel Octree Representation [2340-sparse-voxel-octree-representation.md] and introduces specific optimizations for dynamic content handling [S1, unofficial].
