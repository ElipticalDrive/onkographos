# Dynamic Update Optimization

Also called: Dynamic Voxel Cone Tracing Optimization

## Overview
Dynamic Update Optimization is a set of heuristic techniques for accelerating indirect illumination calculation in sparse voxel octrees by separating static and dynamic scene components and optimizing the voxelization and cone tracing passes. It solves the performance bottleneck of recalculating global illumination for every frame in scenes with moving geometry. It differs from static-only voxelization by maintaining a persistent octree for static geometry while appending dynamic voxel fragments, and from naive full-resolution cone tracing by employing half-resolution passes with targeted re-computation.

## How it works
The method operates on a sparse voxel octree where each node contains voxel data. The core logic separates the scene into static and dynamic parts to minimize per-frame computation.

### Inputs and Outputs
*   **Input**: Scene geometry (static and dynamic), camera position and orientation, octree data structure.
*   **Output**: Indirect illumination values for the current frame.

### Data Structures
The octree node buffer stores voxel attributes. For dynamic geometry, the structure includes:
*   **Normal**: Stored as a vector.
*   **Counter**: A 1-byte integer used to track the number of contributions to the voxel [S1, unofficial].
*   **Flag**: A bit flag to identify if a node is static or dynamic [S1, unofficial].
*   **Neighbor Offset**: Points to neighbor nodes, requiring reset when dynamic nodes are appended [S1, unofficial].

### Steps
1.  **Initialization (Static Geometry)**:
    *   Perform the standard 5-step indirect illumination calculation pipeline for all static geometry [S1, unofficial].
    *   Store the resulting voxels in the octree. Mark these nodes with a static bit flag [S1, unofficial].

2.  **Per-Frame Dynamic Update**:
    *   **Voxelization**: Voxelize only the dynamic geometry for the current frame [S1, unofficial].
        *   Use `InterlockedMax()` to compute diffuse color and normal for each voxel. This is faster than atomic averaging [S1, unofficial].
        *   Append these dynamic voxel fragments to the end of the octree node buffer [S1, unofficial].
        *   Reset the neighbor offsets of static octree nodes that point to the newly appended dynamic nodes [S1, unofficial].
    *   **Affected Node Identification**:
        *   Dispatch threads for all octree nodes.
        *   Queue the indices of nodes affected by dynamic voxels (from previous and current frames) into a buffer [S1, unofficial].
        *   Only recalculate values for these queued nodes [S1, unofficial].
    *   **Re-filtering**: Re-filter the static nodes identified in the previous step to account for lighting changes from dynamic voxels [S1, unofficial].

3.  **Direct Lighting Injection (View-Frustum Culling)**:
    *   Calculate an extended view frustum from the current camera.
    *   The extended frustum is defined by moving the camera backward and increasing the far plane while maintaining the same field of view [S1, unofficial].
    *   The extended distance is calculated as:
        $$ D_{ext} = D_{max\_cone} + S_{voxel} $$
        Where $D_{max\_cone}$ is the maximum cone tracing distance and $S_{voxel}$ is the filtered voxel size [S1, unofficial].
    *   Cull light injection to voxels within this extended frustum, skipping distant voxels that will not be sampled [S1, unofficial].

4.  **Cone Tracing Pass (Half Resolution)**:
    *   Perform the cone tracing pass at half the screen resolution [S1, unofficial].
    *   This introduces up-scaling artifacts, particularly at geometry edges [S1, unofficial].

5.  **Artifact Correction (Edge Detection)**:
    *   Detect edge pixels using an edge detection filter on the depth buffer [S1, unofficial].
    *   Perform cone tracing at full resolution *only* for these detected edge pixels [S1, unofficial].
    *   For non-edge pixels, use the half-resolution results (potentially blurred if re-computation is too slow, though the primary method described is re-computation at edges) [S1, unofficial].

### Pseudocode

```python
def dynamic_update_optimization(scene, camera, octree):
    # Step 1: Initialization (One-time or when static geometry changes)
    if octree.is_empty_or_static_changed():
        static_voxels = voxelize(scene.static_geometry)
        octree.insert(static_voxels, is_static=True)
        octree.compute_indirect_illumination_pipeline(octree.static_nodes)
        octree.mark_static_nodes()

    # Step 2: Per-Frame Dynamic Update
    dynamic_voxels = voxelize(scene.dynamic_geometry)
    
    # Use InterlockedMax for faster accumulation
    for voxel in dynamic_voxels:
        octree.append_dynamic_voxel(voxel, is_static=False)
        
    # Reset neighbor offsets for static nodes pointing to new dynamic nodes
    affected_static_nodes = octree.find_nodes_pointing_to_dynamic_buffer()
    for node in affected_static_nodes:
        node.reset_neighbor_offset()

    # Identify nodes affected by dynamic changes
    affected_nodes_buffer = []
    for node in octree.all_nodes:
        if node.is_affected_by_dynamic_voxels():
            affected_nodes_buffer.append(node.index)

    # Re-calculate only for affected nodes
    for idx in affected_nodes_buffer:
        node = octree.get_node(idx)
        node.re_filter_and_recalculate()

    # Step 3: Direct Lighting Injection with Frustum Culling
    extended_frustum = calculate_extended_frustum(camera)
    # D_ext = D_max_cone + S_voxel
    extended_frustum.far_plane = camera.far_plane + (max_cone_distance + voxel_size)
    
    for light in scene.lights:
        inject_direct_light(light, octree, extended_frustum)

    # Step 4: Cone Tracing at Half Resolution
    half_res_image = cone_trace(octree, camera, resolution=screen_resolution / 2)
    
    # Step 5: Edge Detection and Full Resolution Correction
    edge_pixels = detect_edges(depth_buffer)
    
    full_res_image = half_res_image.copy()
    for pixel in edge_pixels:
        full_res_image[pixel] = cone_trace_single_pixel(octree, camera, pixel)
        
    return full_res_image
```

### Parameters and Edge Cases
*   **InterlockedMax vs. Average**: Using `InterlockedMax()` for normals decreases lighting quality if the voxel volume is small (e.g., $256 \times 256 \times 256$). It causes artifacts where light reflects incorrectly compared to an average normal. Therefore, `InterlockedMax()` is used for normals in dynamic geometry, but average normals are kept for static geometry [S1, unofficial].
*   **Cone Tracing Distance**: Limiting the cone tracing distance may result in the loss of ability to sample far objects like the sky [S1, unofficial].
*   **Artifacts**: Half-resolution cone tracing causes visible artifacts when up-scaled, especially at geometry edges. Blurring is a faster alternative to re-computation but yields lower quality [S1, unofficial].

## Subtopics

## Operating characteristics
*   **Performance**: Significantly faster than recalculating the entire octree every frame by isolating dynamic updates [S1, unofficial].
*   **Quality Trade-offs**: Using `InterlockedMax()` for normals reduces lighting quality for small voxel volumes [S1, unofficial]. Half-resolution cone tracing introduces up-scaling artifacts [S1, unofficial].
*   **Limitations**: Limited cone tracing distance prevents sampling of distant objects (e.g., sky) [S1, unofficial]. The edge detection re-computation approach can still cause frame rate drops if the number of edge pixels is high [S1, unofficial].
