# Naive Octree Node Representation

Also called: Branch Tree Node, Direct Memory Octree Node, Pointer-based Octree Node

## Overview
The Naive Octree Node Representation is a direct memory layout for hierarchical voxel data structures where each node explicitly stores pointers to its eight children and metadata for leaf status or voxel values [S1, S3, unofficial]. It solves the problem of implementing a standard octree with minimal abstraction overhead, serving as the baseline for more complex sparse voxel representations [S1, S3, unofficial]. Unlike compressed variants like [Bitmask Leaf Compression](3603-bitmask-leaf-compression.md) or layout-optimized structures like [Octree Data Structure Layout](4518-octree-data-structure-layout.md), this method prioritizes implementation simplicity and direct pointer access over memory efficiency [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel grid (implicitly defined by the root node's bounds and depth) and voxel values (color/intensity) to be inserted.
*   **Output:** A tree of `OctreeNode` structures representing the sparse volume.

**Data Structures:**
The core structure is the `OctreeNode`. Sources provide two slightly different field layouts, but both follow the same logical grouping:

1.  **Pointer-based Layout (S1, S3):**
    *   `children`: An array of 8 pointers (`Node*` or `OctreeNode*`) to child nodes.
    *   `isLeaf`: A boolean flag indicating if the node is a leaf.
    *   `value` / `voxelColorIndex`: If `isLeaf` is true, this stores the voxel data (e.g., `uint32_t` color or `int8_t` index). If `isLeaf` is false, this field is often unused or repurposed in specific implementations, though S3 implies `value` is only valid for leaves.
    *   `centerX`, `centerY`, `centerZ`: Coordinates defining the spatial center of the node's bounding box.
    *   `depth`: The current depth in the octree hierarchy.

    *Memory Cost:* 72 Bytes on a 64-bit processor (8 pointers × 8 bytes + 1 bool + 1 int8_t + 1 uint32_t + 3 uint8_t + 1 uint8_t + padding) and 40 Bytes on a 32-bit processor (8 pointers × 4 bytes) [S1, unofficial].

2.  **Template-based Layout (S2):**
    *   Inherits from a base `tree_node`.
    *   `children_`: `std::array<base_type*, 8>` storing child pointers.
    *   This structure is part of a larger template system (`branch_tree_node<Scalar>`) but retains the core 8-pointer child structure.

**Numbered Steps:**

1.  **Root Initialization:**
    *   Set `depth = 0`.
    *   Set `isLeaf = true`.
    *   Set `value = 0` (or default color).
    *   Set `centerX = centerY = centerZ = 0` (or root bounds center) [S3, unofficial].

2.  **Non-Root Initialization (for new nodes):**
    *   Set `depth` based on parent + 1.
    *   Set `isLeaf = true`.
    *   Set `value = 0`.
    *   Calculate `childDepth = depth - 1`.
    *   Calculate `childSize = 1 << childDepth` (power of 2).
    *   Set `centerX`, `centerY`, `centerZ` based on the node's spatial position [S3, unofficial].

3.  **Insert Voxel (`SetVoxel`):**
    *   **Base Case:** If `depth == 0`, set `this->value = value` and return [S3, unofficial].
    *   **Leaf Optimization:** If `isLeaf` is true and `this->value == value`, return (no change needed) [S3, unofficial].
    *   **Split Leaf:** If `isLeaf` is true but `this->value != value`:
        *   Call `initChildren()` to allocate and initialize 8 child nodes.
        *   Copy `this->value` to all 8 children (to preserve existing data).
        *   Set `isLeaf = false`.
    *   **Recurse:**
        *   Compute `childIndex` using `GetChildIndex(x, y, z)` based on the voxel's position relative to the node's center [S3, unofficial].
        *   Recursively call `children[childIndex].SetVoxel(x, y, z, value)` [S3, unofficial].
    *   **Collapse Check:** Call `TryCollapse()` to merge children if they are identical leaves (implementation detail not fully specified in sources) [S3, unofficial].

4.  **Retrieve Voxel (`GetValue`):**
    *   If `isLeaf` is true, return `value` [S3, unofficial].
    *   Else, compute `childIndex` using `GetChildIndex(x, y, z)`.
    *   Return `children[childIndex].GetValue(x, y, z)` [S3, unofficial].

5.  **Initialize Children (`initChildren`):**
    *   Set `childDepth = depth - 1`.
    *   Set `childSize = 1 << childDepth`.
    *   Allocate `children = new OctreeNode[8]` (or equivalent dynamic array) [S3, unofficial].
    *   Calculate base coordinates: `baseX = centerX - childSize`, `baseY = centerY - childSize`, `baseZ = centerZ - childSize` [S3, unofficial].
    *   Initialize each of the 8 children with offsets corresponding to the 8 octants:
        *   Indices 0-7 correspond to combinations of `(±childSize, ±childSize, ±childSize)` added to the base coordinates [S3, unofficial].

**Pseudocode:**

```python
class OctreeNode:
    def __init__(self, depth=0, centerX=0, centerY=0, centerZ=0):
        self.depth = depth
        self.centerX = centerX
        self.centerY = centerY
        self.centerZ = centerZ
        self.isLeaf = True
        self.value = 0  # uint32_t or similar
        self.children = [None] * 8  # Array of 8 pointers

    def init_children(self):
        """Allocates and initializes 8 child nodes."""
        child_depth = self.depth - 1
        child_size = 1 << child_depth  # 2^child_depth
        
        # Base coordinates for the children's bounding boxes
        base_x = self.centerX - child_size
        base_y = self.centerY - child_size
        base_z = self.centerZ - child_size
        
        # Initialize 8 children with appropriate offsets
        for i in range(8):
            # Determine offset based on bit representation of i
            # Bit 0: X, Bit 1: Y, Bit 2: Z
            offset_x = (i & 1) * child_size
            offset_y = (i & 2) * child_size
            offset_z = (i & 4) * child_size
            
            child = OctreeNode(
                depth=child_depth,
                centerX=base_x + offset_x + child_size,
                centerY=base_y + offset_y + child_size,
                centerZ=base_z + offset_z + child_size
            )
            child.value = self.value  # Copy current leaf value to children
            self.children[i] = child

    def get_child_index(self, x, y, z):
        """Computes the index (0-7) of the child containing (x, y, z)."""
        # Implementation depends on coordinate system relative to centerX/Y/Z
        # Assuming x, y, z are absolute coordinates and children are split by center
        idx = 0
        if x >= self.centerX: idx |= 1
        if y >= self.centerY: idx |= 2
        if z >= self.centerZ: idx |= 4
        return idx

    def set_voxel(self, x, y, z, value):
        """Inserts a voxel value at (x, y, z)."""
        # Base case: depth 0
        if self.depth == 0:
            self.value = value
            return

        # If leaf and value is same, do nothing
        if self.isLeaf and self.value == value:
            return

        # If leaf but value differs, split
        if self.isLeaf:
            self.init_children()
            self.isLeaf = False

        # Recurse into child
        child_idx = self.get_child_index(x, y, z)
        if self.children[child_idx] is None:
            # This case should be handled by init_children if we came from a leaf split,
            # or by explicit allocation if this is a new branch.
            # For naive representation, we assume children are allocated when needed.
            # If this node was not a leaf before, children should exist.
            # If this node was a leaf, init_children allocated them.
            # However, if we are traversing a sparse tree, we might need to allocate.
            # Based on S3, init_children is called only when splitting a leaf.
            # If we are in a non-leaf node, children must exist.
            pass 
        
        self.children[child_idx].set_voxel(x, y, z, value)
        
        # Try to collapse children if they are identical (not fully specified in S3)
        # self.try_collapse()

    def get_value(self, x, y, z):
        """Retrieves the voxel value at (x, y, z)."""
        if self.isLeaf:
            return self.value
        
        child_idx = self.get_child_index(x, y, z)
        return self.children[child_idx].get_value(x, y, z)
```

**Parameters:**
*   **Memory Cost:** 72 Bytes per node on 64-bit systems, 40 Bytes on 32-bit systems [S1, unofficial].
*   **Depth:** Starts at 0 for the root [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Depth 0 Base Case:** Recursion must stop at `depth == 0` to prevent underflow or invalid memory access [S3, unofficial].
*   **Undefined Helpers:** `GetChildIndex` and `TryCollapse` are referenced but not fully defined in the source snippets. Implementers must define the coordinate mapping logic and the collapse condition (e.g., all 8 children are identical leaves) [S3, unofficial].
*   **Memory Allocation:** The naive representation allocates memory for all 8 children when a leaf splits, even if only one child will be used. This leads to significant memory overhead in sparse scenes [S1, unofficial].

## Subtopics

### [Bitmask Leaf Compression](3603-bitmask-leaf-compression.md)
Eliminates leaf nodes by packing 8 voxels into a 64-bit integer in the parent, reducing memory usage for dense leaf regions.

### [Octree Data Structure Layout](4518-octree-data-structure-layout.md)
Encapsulates global tree state (bounds, node list) in a root class, separating management from individual node representation.

## Operating characteristics
*   **Time Complexity:** Insertion and retrieval are $O(d)$ where $d$ is the depth of the octree, as each operation traverses one node per level [S3, unofficial].
*   **Memory Complexity:** $O(8^d)$ in the worst case (full octree), but significantly higher overhead for sparse data due to the allocation of 8 pointers per non-leaf node [S1, unofficial]. The memory cost per node is fixed at 72/40 bytes [S1, unofficial].
*   **Strengths:** Simple implementation, direct pointer access, no complex bit-packing logic required for basic operations [S1, S3, unofficial].
*   **Limitations:** High memory overhead for sparse voxels due to pointer arrays and separate leaf nodes. Not suitable for large-scale scenes without compression or alternative layouts [S1, unofficial].
*   **When to Use:** Prototyping, small-scale volumes, or as a baseline for comparison with optimized structures [S1, S3, unofficial].
*   **When Not to Use:** Large-scale sparse voxel rendering, real-time applications with memory constraints, or scenes with high sparsity [S1, unofficial].

## Background
The naive octree node representation is a fundamental concept in spatial data structures, originating from standard computer science literature on octrees [S1, S2, S3, unofficial]. It is widely used in early implementations of sparse voxel octrees for global illumination and terrain generation [S1, S3, unofficial]. The specific memory cost figures (72/40 bytes) are cited from a thesis on SVO compression [S1, unofficial]. The template-based variant is seen in C++ libraries like `planaria/dmc` [S2, unofficial].
