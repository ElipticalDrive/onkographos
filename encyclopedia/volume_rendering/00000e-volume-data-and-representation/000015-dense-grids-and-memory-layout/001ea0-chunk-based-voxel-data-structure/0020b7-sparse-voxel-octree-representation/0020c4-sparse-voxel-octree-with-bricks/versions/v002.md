# Sparse Voxel Octree with Bricks

Also called: SVO with Bricks, SVOC, Sparse Voxel Octree with 3x3x3 Bricks, Voxel Cone Tracing Octree

## Overview
Sparse Voxel Octree with Bricks is a hierarchical scene representation that stores filtered lighting information (energy intensity, direction, occlusion, and Normal Distribution Functions) in small 3x3x3 voxel volumes, called bricks, attached to octree nodes [S1]. It solves the memory inefficiency of inter-brick interpolation in sparse octrees by positioning voxel centers at node corners, allowing hardware trilinear interpolation to cover 2x2x2 nodes without expensive one-voxel borders [S1]. This method enables smooth, geometry-independent indirect illumination at real-time frame rates, differing from naive node representations by using texture volumes per node rather than single values [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scene mesh or volume data; viewing and lighting configuration [S1].
*   **Output:** A sparse voxel octree structure stored in linear GPU memory, with bricks stored in texture memory, enabling filtered scene queries with increasing precision [S1].

**Data Structures:**
1.  **Octree Node:**
    *   Stored in linear GPU memory [S1].
    *   Nodes are grouped into 2x2x2 tiles [S1].
    *   Each tile shares a single pointer to its 2x2x2 children [S1].
    *   Contains a pointer to a 3x3x3 brick in texture memory [S1].
    *   Contains neighbor pointers (to spatially neighboring nodes and parent) [S1].
    *   Empty nodes are collapsed to save memory [S1].
2.  **Brick:**
    *   A 3x3x3 voxel volume stored in texture memory [S1].
    *   Voxel centers are located at the corners of the node's bounding box, not the center [S1].
    *   Approximates the scene section represented by the node [S1].
    *   Allocated in a shared brick buffer [S1].

**Numbered Steps:**
1.  **Tree Construction:** The root node represents the entire scene [S1]. Children represent an eighth of the parent's volume [S1]. This hierarchy allows querying filtered scene information (energy intensity, direction, occlusion, NDFs) with increasing precision by descending the tree [S1].
2.  **Brick Assignment:** Each non-empty node is assigned a 3x3x3 brick [S1]. The brick stores the filtered scene information for that spatial region [S1].
3.  **Voxel Center Placement:** To enable correct inter-brick interpolation using hardware trilinear filtering, the 3x3x3 brick is configured such that its voxel centers align with the corners of the node's bounding box [S1]. This ensures that interpolated values for any point within a 2x2x2 node group are computed entirely within a single brick covering those nodes [S1].
4.  **Memory Optimization:** Empty nodes are collapsed [S1]. This reduces memory occupancy but requires pointer-based traversal logic to handle the sparse nature of the tree [S1].
5.  **Neighbor Pointers:** Due to memory savings from the 3x3x3 brick design (using less than half the memory of border-based approaches), neighbor pointers are added to nodes [S1]. These pointers enable quick visits to spatially neighboring nodes and the parent [S1].
6.  **Grouping:** Nodes are grouped into 2x2x2 tiles [S1]. A single pointer stores the children for all 2x2x2 nodes in the tile, optimizing memory layout [S1].

**Formulas:**
*   **Memory Reduction:** The 3x3x3 brick approach uses less than half the memory compared to adding a one-voxel boundary for the same sampling precision [S1].
*   **Precision:** Filtered scene information is queried with increasing precision by descending the tree hierarchy [S1].

**Parameters:**
*   **Brick Size:** 3x3x3 voxels [S1].
*   **Node Tile Size:** 2x2x2 nodes [S1].
*   **Max Octree Resolution:** Typically 512x512 pixels for a 512^3 octree [S1].

**Edge Cases and Pitfalls:**
*   **Inter-brick Interpolation Continuity:** The original approach [CNLE09] used a one-voxel border duplicating neighbors to ensure correct interpolation [S1]. This is expensive for small bricks [S1]. The 3x3x3 brick with corner-aligned voxel centers solves this by ensuring interpolated values are computed inside a brick covering 2x2x2 nodes [S1].
*   **Empty Nodes:** Collapsing empty nodes reduces memory but requires careful pointer-based traversal logic to avoid accessing invalid memory [S1].

**Pseudocode:**
```python
def trilinear_interpolate(brick, point):
    """Standard trilinear interpolation over a 3x3x3 brick."""
    x, y, z = point
    ix, fx = int(x), x - int(x)
    iy, fy = y - int(y)
    iz, fz = z - int(z)
    # Clamp indices to valid brick range [0, 2]
    ix = max(0, min(2, ix))
    iy = max(0, min(2, iy))
    iz = max(0, min(2, iz))
    v000 = brick[iz][iy][ix]
    v100 = brick[iz][iy][min(ix+1, 2)]
    v010 = brick[iz][min(iy+1, 2)][ix]
    v110 = brick[iz][min(iy+1, 2)][min(ix+1, 2)]
    v001 = brick[min(iz+1, 2)][iy][ix]
    v101 = brick[min(iz+1, 2)][iy][min(ix+1, 2)]
    v011 = brick[min(iz+1, 2)][min(iy+1, 2)][ix]
    v111 = brick[min(iz+1, 2)][min(iy+1, 2)][min(ix+1, 2)]
    v00 = v000 * (1-fx) + v100 * fx
    v01 = v010 * (1-fx) + v110 * fx
    v10 = v001 * (1-fx) + v101 * fx
    v11 = v011 * (1-fx) + v111 * fx
    v0 = v00 * (1-fy) + v01 * fy
    v1 = v10 * (1-fy) + v11 * fy
    return v0 * (1-fz) + v1 * fz

class Node:
    def __init__(self):
        self.brick_ptr = None
        self.children_ptr = None
        self.parent_ptr = None
        self.neighbor_ptrs = []

class Brick:
    def __init__(self):
        self.voxels = [[[0.0 for _ in range(3)] for _ in range(3)] for _ in range(3)]

def is_empty_region(scene_data, bbox):
    """Checks if a spatial region contains no geometry or light [G]."""
    return not scene_data.intersects(bbox)

def allocate_brick():
    """Allocates a 3x3x3 brick in the shared texture buffer [G]."""
    return Brick()

def allocate_tile():
    """Allocates a 2x2x2 array of node pointers [G]."""
    return [[None for _ in range(2)] for _ in range(2)]

def add_neighbor_pointers(node, parent):
    """Assigns parent pointer and links to spatial neighbors [G]."""
    node.parent_ptr = parent

def add_to_tile(tile, i, j, k, child):
    """Places a child node into its 2x2x2 tile slot [G]."""
    tile[i][j][k] = child

def query_scene(node, point):
    """Queries filtered scene information at a point using brick interpolation."""
    if node is None:
        return None
    brick = node.brick_ptr
    if brick is None:
        return None
    return trilinear_interpolate(brick.voxels, point)

def build_octree(scene_data, max_depth=8):
    """Builds the sparse voxel octree with bricks."""
    root = Node()
    root.brick_ptr = allocate_brick()
    build_recursive(root, scene_data, 0, max_depth)
    return root

def build_recursive(node, scene_data, depth, max_depth):
    """Recursively constructs the octree hierarchy."""
    if depth >= max_depth:
        return
    if is_empty_region(scene_data, node.bounding_box):
        node.children_ptr = None
        return
    node.children_ptr = allocate_tile()
    for i in range(2):
        for j in range(2):
            for k in range(2):
                child = Node()
                child.parent_ptr = node
                child.brick_ptr = allocate_brick()
                add_neighbor_pointers(child, node)
                build_recursive(child, scene_data, depth + 1, max_depth)
                add_to_tile(node.children_ptr, i, j, k, child)
```

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Uses less than half the memory of border-based approaches for the same sampling precision [S1]. Empty nodes are collapsed to save memory [S1].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Handles large and complex scenes through adaptivity [S1].
*   **Strengths:** Smooth results without light undersampling or geometric LOD issues [S1]. Efficient memory usage for small bricks [S1].
*   **Limitations:** Requires pointer-based traversal logic due to collapsed empty nodes [S1].
*   **When to Use:** When smooth, geometry-independent indirect illumination is required at real-time frame rates [S1].
*   **When Not to Use:** When memory is extremely constrained and interpolation is not needed (use Naive Octree Node Representation) [S1].

## Background
The method originates from the paper "Interactive Indirect Illumination Using Voxel Cone Tracing" by [CNLE09] and subsequent work [S1]. It was developed to provide smooth results without missing information like light undersampling or geometric LOD, which are issues in path-tracing or photon mapping [Jen96] [S1]. The specific 3x3x3 brick design with corner-aligned voxel centers was proposed to solve the memory inefficiency of inter-brick interpolation in sparse octrees [S1].
