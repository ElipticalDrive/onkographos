# Clustered Grid Cell (CGC) Data Structure
## Overview
The Clustered Grid Cell (CGC) data structure is a memory-efficient representation for isosurface rendering that stores active grid cells directly as rendering primitives, eliminating the need for the original volume scalar data during the rendering phase [S1]. It sets itself apart from previous cell rasterization approaches, such as Liu et al.'s method, by storing eight corner scalar values with each cell, allowing full rendering without GPU-resident volume textures, while achieving approximately 37% of the memory usage of typical efficient mesh-based representations [S1].
## How it works
**Inputs:**
- A 3D scalar volume dataset [S1].
- Block dimensions: $16 \times 16 \times 16$ voxels [S1].
- Grid position precision: 16 bits per component (X, Y, Z) [S1].
- Maximum grid size: $128\text{K} \times 128\text{K} \times 128\text{K}$ voxels [S1].

**Outputs:**
- A linear buffer of blocks (16 bytes each) [S1].
- A linear buffer of metacells (12 bytes each) [S1].
- A buffer texture storing corner scalar values (two RGBA values per active cell) [S1].

**Data Structures:**

1.  **Block:** Represents a $16 \times 16 \times 16$ region of the volume [S1].
    -   Layout: 16 bytes [S1].
    -   Content: Metadata linking to the metacell buffer for this block [S1].

2.  **Metacell:** Groups up to 8 neighboring active grid cells into a $2 \times 2 \times 2$ unit [S1].
    -   Layout: 12 bytes [S1].
    -   Fields:
        -   Pointer: Index to the cluster or cell data [S1].
        -   Cell Mask: Bitmask indicating which of the 8 potential cell positions are active [S1].
        -   Cell Pointer: Index to the specific cell data within the cluster or global buffer [S1].
    -   Note: The last metacell in a cluster stores a cluster bound (Axis-Aligned Bounding Box) instead of standard cell metadata [S1].

3.  **Cluster:** A group of 16 consecutive metacells [S1].
    -   Size: Exactly 16 metacells [S1].
    -   Padding: The last cluster of each block is padded with empty metacells to ensure it contains exactly 16 metacells, preventing spillover into the next block [S1].

4.  **Corner Scalar Buffer:**
    -   Stores 8 corner scalar values per active grid cell [S1].
    -   Format: Two RGBA values [S1].
    -   Precision: Component type matches the scalar precision of the original volume data [S1].

**Algorithm Steps:**

1.  **Block Division:** Divide the volume data into non-overlapping $16 \times 16 \times 16$ blocks [S1].
2.  **Active Cell Extraction:** For each block, identify active grid cells (cells intersecting the isosurface or meeting activity criteria) [S1].
3.  **Morton Ordering:** Sort the active grid cells within each block using Morton order (Z-order curve) [S1].
4.  **Metacell Grouping:** Group up to 8 neighboring cells into $2 \times 2 \times 2$ metacells [S1].
    -   Determine the $2 \times 2 \times 2$ grid position for each group.
    -   Set the cell mask bits for active cells within the group.
    -   Assign pointers to the metacell structure [S1].
5.  **Cluster Formation:** Group 16 consecutive metacells into a cluster [S1].
    -   If a block's metacells do not fill the last cluster completely, pad with empty metacells until the count reaches 16 [S1].
    -   In the last metacell of each cluster, store the cluster's Axis-Aligned Bounding Box (AABB) instead of cell metadata [S1].
6.  **Scalar Storage:** For each active grid cell, extract the 8 corner scalar values from the original volume data [S1].
7.  **Buffer Population:**
    -   Write block metadata to the block buffer [S1].
    -   Write metacell data (pointer, mask, cell pointer, or bound) to the metacell buffer [S1].
    -   Write the two RGBA values representing the 8 corner scalars to the corner scalar buffer texture [S1].
8.  **Upload:** Upload the extracted metacells and grid cell data to separate GPU buffer textures [S1].

**Pseudocode:**

```python
def build_cgc(volume_data, block_size=16):
    blocks_buffer = []
    metacells_buffer = []
    corner_scalars_buffer = []
    metacell_offset = 0

    dim_x, dim_y, dim_z = volume_data.shape
    for z in range(0, dim_z, block_size):
        for y in range(0, dim_y, block_size):
            for x in range(0, dim_x, block_size):
                # 1. Extract active cells in block
                active_cells = []
                for cz in range(z, min(z + block_size, dim_z)):
                    for cy in range(y, min(y + block_size, dim_y)):
                        for cx in range(x, min(x + block_size, dim_x)):
                            if is_active(volume_data, cx, cy, cz):
                                active_cells.append((cx, cy, cz))

                # 2. Sort active cells in Morton order
                active_cells.sort(key=lambda c: morton_encode(c[0], c[1], c[2]))

                # 3. Group into metacells (2x2x2)
                block_metacells = []
                for i in range(0, len(active_cells), 8):
                    group = active_cells[i:i+8]
                    mask = 0
                    for j, cell in enumerate(group):
                        if cell is not None:
                            mask |= (1 << j)
                    mc = {'pointer': metacell_offset + len(block_metacells), 'mask': mask, 'cell_pointer': 0, 'cells': group}
                    block_metacells.append(mc)

                # 4. Group into clusters of 16 metacells
                num_clusters = (len(block_metacells) + 15) // 16
                for c in range(num_clusters):
                    start = c * 16
                    end = min(start + 16, len(block_metacells))
                    cluster = block_metacells[start:end]

                    # Pad last cluster of block to exactly 16 metacells
                    if c == num_clusters - 1 and len(cluster) < 16:
                        for _ in range(16 - len(cluster)):
                            cluster.append({'pointer': 0, 'mask': 0, 'cell_pointer': 0, 'cells': []})

                    # Last metacell stores cluster bound (AABB) instead of cell metadata
                    last_mc = cluster[-1]
                    last_mc['pointer'] = compute_cluster_aabb(cluster)
                    last_mc['mask'] = 0
                    last_mc['cell_pointer'] = 0

                    metacells_buffer.extend(cluster)

                    # Store corner scalars for active cells
                    for mc in cluster:
                        if mc['cells']:
                            for cell in mc['cells']:
                                scalars = extract_8_corner_scalars(volume_data, cell)
                                corner_scalars_buffer.append(pack_scalars_to_rgba(scalars))

                # 5. Create block entry (16 bytes)
                blocks_buffer.append({'metacell_offset': metacell_offset, 'aabb': compute_block_aabb(x, y, z, block_size)})
                metacell_offset += len(block_metacells)

    return blocks_buffer, metacells_buffer, corner_scalars_buffer

def morton_encode(x, y, z): return (x | (y << 1) | (z << 2))
def is_active(vol, x, y, z): return vol[x, y, z] != 0
def extract_8_corner_scalars(vol, cell): return [vol[c] for c in get_cell_corners(cell)]
def pack_scalars_to_rgba(scalars): return (scalars[0:4], scalars[4:8])
def compute_cluster_aabb(cluster): return min_max_aabb([c['cells'] for c in cluster])
def compute_block_aabb(x, y, z, size): return (x, y, z, x+size, y+size, z+size)
def get_cell_corners(cell): return [(cell[0]+dx, cell[1]+dy, cell[2]+dz) for dx in (0,1) for dy in (0,1) for dz in (0,1)]
def min_max_aabb(cells): return min(c for cell in cells for c in cell), max(c for cell in cells for c in cell)
```

**Edge Cases and Pitfalls:**
-   **Spillover:** Metacells from one block must not spill into the next block's cluster [S1]. This is handled by padding the last cluster of each block to exactly 16 metacells [S1].
-   **Precision:** Grid positions are stored with 16 bits per component, limiting the maximum grid size to $128\text{K} \times 128\text{K} \times 128\text{K}$ voxels [S1].
-   **Scalar Storage:** The corner scalar buffer must match the precision of the original volume data to avoid interpolation errors during rendering [S1].

## Operating characteristics
-   **Memory Usage:** Approximately 37% of a typical efficient mesh-based representation [S1].
-   **Block Size:** 16 bytes per block [S1].
-   **Metacell Size:** 12 bytes per metacell [S1].
-   **Grid Position Precision:** 16 bits per component (X, Y, Z) [S1].
-   **Maximum Grid Size:** $128\text{K} \times 128\text{K} \times 128\text{K}$ voxels [S1].
-   **Strengths:**
    -   Eliminates the need for the original volume data during rendering [S1].
    -   Supports large grid sizes [S1].
    -   Memory efficient compared to mesh-based representations [S1].
    -   Suitable for hybrid ray tracing or path tracing for global illumination [S1].
-   **Limitations:**
    -   Requires CPU-side extraction of active cells and upload to GPU [S1].
    -   Grid size is limited by 16-bit position precision [S1].
-   **When to Use:** Isosurface rendering where memory bandwidth is a bottleneck and the original volume data cannot be kept in GPU memory [S1].
-   **When Not to Use:** When the original volume data is already resident in GPU memory and can be accessed efficiently, or when grid sizes exceed $128\text{K}^3$ [S1].

## Background
The Clustered Grid Cell data structure was proposed in a paper by [S1] to address the limitations of existing isosurface rendering methods that require extracting another representation of the data or relying on the original volume data during rendering [S1]. It builds on the concept of cell rasterization using billboard splatting, as introduced in previous work [13] (referenced in [S1]), but improves upon it by storing corner scalar values with each cell and organizing them into a clustered hierarchy for efficient culling and rendering [S1]. The method supports visibility buffer culling and EWA-based interpolation of attributes like normals [S1].
