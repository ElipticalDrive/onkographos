# Bricked Volume Hierarchy
## Overview
The Bricked Volume Hierarchy is a data organization scheme where a volume dataset is partitioned into chunks called bricks across multiple resolution levels [S1, unofficial]. It solves the problem of managing multi-resolution volume data by decoupling the logical resolution levels from the geometric subdivision of the space [S1, unofficial]. What sets it apart from its siblings, such as the [N³-tree with Brick Pool and Node Pool](3407-n-tree-with-brick-pool-and-node-pool.md), is that the downsampling ratio between resolution levels is flexible, whereas the geometric subdivision in residency octrees is fixed [S1, unofficial].

## Subtopics

### [Brick Caching with LRU Replacement](879-brick-caching-with-lru-replacement.md)
Manages the residency of bricks in the GPU cache using Least Recently Used replacement. Sets itself apart by enforcing a strict eviction policy based on access recency. Choose it when deterministic cache behavior is prioritized.

### [Brick-based Volume Raycasting](3341-brick-based-volume-raycasting.md)
The rendering algorithm that traverses the hierarchy to sample bricks. Sets itself apart by directly mapping ray traversal steps to brick boundaries. Choose it when direct hardware-accelerated ray traversal of the brick hierarchy is required for rendering.

### [N³-tree with Brick Pool and Node Pool](3407-n-tree-with-brick-pool-and-node-pool.md)
A specific implementation using an N³-tree structure for managing the hierarchy. Sets itself apart by explicitly separating node and brick memory pools for efficient allocation. Choose it when hierarchical spatial indexing with explicit memory pooling is needed.

### [Multi-Level Cache and Prefetching](4631-multi-level-cache-and-prefetching.md)
Optimizes data transfer by prefetching bricks into multi-level caches. Sets itself apart by overlapping computation with data movement across cache tiers. Choose it when memory bandwidth bottlenecks require aggressive prefetching strategies.

### [Raymarching with LOD-based Brick Caching](5776-raymarching-with-lod-based-brick-caching.md)
Combines raymarching with Level-of-Detail selection for brick caching. Sets itself apart by dynamically switching resolution levels during traversal. Choose it when adaptive resolution selection during traversal improves performance.

## Background
The bricked volume hierarchy distinguishes the resolution levels of a volume from the spatial, purely geometric subdivision determined by a residency octree [S1, unofficial]. This separation allows for flexible downsampling ratios between resolution levels, contrasting with the fixed halving subdivision of octree nodes [S1, unofficial].
