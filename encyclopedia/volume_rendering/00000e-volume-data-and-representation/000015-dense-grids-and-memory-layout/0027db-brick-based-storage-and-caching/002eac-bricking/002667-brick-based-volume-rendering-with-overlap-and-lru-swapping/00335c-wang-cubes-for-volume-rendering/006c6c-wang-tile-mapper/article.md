# Wang Tile Mapper

Also called: Nanomatrix Wang tile mapper, Wang tilling algorithm

## Overview
The Wang Tile Mapper is a spatial indexing and mapping technique used to place molecular instances (Wang squares and cubes) onto proxy geometry meshes for volume rendering [S1]. It solves the problem of efficiently determining which pre-computed Wang tiles correspond to specific regions of a 3D mesh during rendering, linking the abstract tiling space to the physical mesh coordinates [S1]. It sets itself apart from direct texture lookups by using a pre-generated "tiling recipe" and a sliding window approach to handle arbitrary triangle projections, enabling parallel processing of molecular instancing [S1].

## How it works
**Inputs:**
1.  A proxy geometry mesh defined in 3D space.
2.  A set of Wang squares (2D) and Wang cubes (3D) with associated indices.
3.  The tiling recipes generated by the Wang tilling algorithm.

**Outputs:**
1.  A mapping from mesh triangle texture coordinates (uv) to Wang square indices.
2.  A mapping from mesh box coordinates (ijk) to Wang cube indices.

**Data Structures:**
*   **Tiling Recipe (2D):** A 2D array containing indices of Wang squares. The dimensions are large enough to cover the full texture coordinate space $[0, 1] \times [0, 1]$ [S1].
*   **Tiling Recipe (3D):** A 3D array containing indices of Wang cubes. The dimensions are large enough to cover the full core grid coordinates, ensuring any box has a corresponding Wang cube [S1].
*   **Replication Area:** A 2D region (window) within the 2D tiling recipe. Its size is fixed and determined by the largest triangle in the mesh [S1].

**Steps:**

1.  **Preprocessing (2D Tiling):** Run the Wang tilling algorithm to generate the 2D tiling recipe. This array must be sufficiently large to cover the entire texture coordinate space $[0, 1]$ [S1].
2.  **Preprocessing (3D Tiling):** Extend the algorithm to 3D to generate the 3D tiling recipe. This array must be large enough to cover the full core grid coordinates [S1].
3.  **Preprocessing (Replication Area):** Identify the largest triangle in the proxy geometry mesh. Compute the size of the replication area based on this triangle. The replication area represents the maximum number of tiles from the tiling recipe that might be projected onto any single triangle [S1].
4.  **Rendering (Origin Determination):** For a given triangle, calculate its minimum texture coordinates, denoted as $min_{uv}$ [S1]. Use these coordinates to define the origin of the replication area within the 2D tiling recipe [S1].
5.  **Rendering (Projection):** Determine the subset of tiles from the replication area that are projected onto the specific triangle. This involves mapping the triangle's spatial extent to the corresponding indices in the tiling recipe [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The mapping relies on texture coordinates falling within $[0, 1]$. Precision errors at boundaries may require careful handling of tile indices [S1].
*   **Mesh Complexity:** The replication area size is determined by the *largest* triangle. If the mesh contains triangles of vastly different sizes, this may lead to inefficient memory usage for smaller triangles [S1].
*   **Boundary Conditions:** The tiling recipes must be large enough to cover the entire coordinate space. If the mesh extends beyond the pre-computed recipe bounds, the mapping will fail [S1].

## Subtopics

### Wang Cubes for Volume Rendering
*   **What it is:** A technique using non-periodic 3D Wang Cubes to store volume rendering data and segmentation masks.
*   **Difference:** Focuses on 3D data storage and memory reduction compared to full volumetric textures.
*   **When to choose:** When memory footprint is critical for large-scale volume data.
*   **Link:** [Wang Cubes for Volume Rendering](6980-wang-cubes-for-volume-rendering.md)

## Operating characteristics
*   **Time Complexity:** Preprocessing is dominated by the Wang tilling algorithm, which is not detailed in the sources [S1]. Rendering involves a constant-time lookup of the replication area based on triangle coordinates, followed by projection calculations [S1].
*   **Memory Complexity:** Requires storing two tiling recipes (2D and 3D) and the replication area. The size of the recipes depends on the resolution of the texture/core grid space [S1].
*   **Strengths:** Enables parallel processing of molecular instancing via the sliding window approach [S1]. Efficiently maps abstract tiling spaces to physical mesh geometry [S1].
*   **Limitations:** The replication area size is fixed by the largest triangle, potentially wasting resources for smaller triangles [S1]. The method relies on pre-computed tiling recipes, which may be large for high-resolution scenes [S1].
*   **When to use:** For visualizing large scenes with trillions of atoms where memory footprint must be minimized [S1].
*   **When not to use:** If the mesh has extreme variations in triangle size, leading to inefficient replication areas [S1].

## Background
The Wang Tile Mapper was introduced in the Nanomatrix paper [3] (cited as [S1] in the provided text) for the placement and visualization of molecular structures at correct spatial locations [S1]. It is a crucial part of the Nanouniverse renderer, which aims to visualize large scenes with trillions of atoms at interactive rates while keeping the memory footprint low [S1]. The method links the µLAS and mLAS levels in a three-level AS tree [S1].
