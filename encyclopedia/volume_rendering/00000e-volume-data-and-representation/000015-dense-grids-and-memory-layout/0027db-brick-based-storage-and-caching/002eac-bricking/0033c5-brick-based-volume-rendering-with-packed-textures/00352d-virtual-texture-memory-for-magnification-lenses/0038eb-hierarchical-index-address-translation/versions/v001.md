# Hierarchical Index/Address Translation

Also called: Address translation texture, Layout/index texture

## Overview
Hierarchical Index/Address Translation is a method that maps virtual volume coordinates to physical texture coordinates, supporting multi-resolution rendering and memory management [S1, unofficial]. It solves the problem of addressing anisotropic down-sampled volume data by packing multiple resolution levels into a single 3D texture, enabling efficient memory management for petascale microscopy data streams [S1, unofficial]. It builds on [Virtual Texture Memory for Magnification Lenses](7444-virtual-texture-memory-for-magnification-lenses.md) by providing the specific translation logic and data layout for multi-resolution page directories.

## How it works
The method uses an index texture (also called a layout or address translation texture) to store metadata for bricks, allowing the renderer to locate physical data in a packed 3D texture buffer based on virtual coordinates.

**Inputs and Outputs**
*   **Input:** Virtual volume coordinates $(v_x, v_y, v_z)$, typically derived from ray-casting or sampling logic.
*   **Output:** Physical texture coordinates $(p_x, p_y, p_z)$ and brick identifiers within the packed 3D texture.

**Data Structures**
The index texture stores metadata for each brick. The specific fields defined in the source are:
1.  Number of bricks
2.  Texture size of brick
3.  Physical extent of brick

The exact bit-packing, field sizes, and total layout of this metadata structure are not given in the sources.

**Steps**
1.  **Sample Index Texture:** At the current virtual coordinate, sample the index texture to retrieve the metadata for the corresponding brick.
2.  **Retrieve Metadata:** Extract the "Number of bricks", "Texture size of brick", and "Physical extent of brick" from the sampled data [S1, unofficial].
3.  **Calculate Offset:** Use the metadata to calculate the offset within the packed 3D texture. The "Physical extent of brick" defines the spatial bounds, while the "Texture size of brick" defines the sampling resolution [S1, unofficial].
4.  **Map Coordinates:** Transform the virtual coordinate into the local coordinate space of the physical brick using the retrieved extent and size information.
5.  **Sample Data:** Sample the packed 3D texture at the calculated physical coordinate to retrieve the voxel data [S1, unofficial].

**Formulas**
Not given in the sources. The specific mathematical relationship between the virtual coordinates, the metadata fields, and the final physical texture coordinates is not provided.

**Parameters**
*   **Brick Packing:** Bricks are packed into a single 3D texture. For filtering, neighbor voxels are duplicated, resulting in an overhead of 10% with $32^3$ bricks (storing $(n+1)^3$ bricks instead of $n^3$) [S1, unofficial].
*   **Resolution Levels:** The method supports hierarchical levels (e.g., Level 0 to Level 3) for adaptive volume sampling [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Boundary Conditions:** The source mentions duplicate neighbor voxels for filtering, implying boundary handling is managed by this duplication strategy [S1, unofficial].
*   **Precision:** Not given in the sources.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** The method packs bricks into a single 3D texture. There is a 10% overhead for filtering with $32^3$ bricks due to duplicate neighbor voxels [S1, unofficial].
*   **Measured Performance:** Adaptive volume sampling using this method achieved a speed-up of 2.6-2.8x compared to full density rendering [S1, unofficial].
*   **Strengths:** Supports multi-resolution rendering; allows arbitrary coordinate transformations without rebinding textures; efficient memory management for large datasets.
*   **Limitations:** Requires an additional index texture; specific performance characteristics depend on the hardware and resolution.
*   **When to use:** When rendering large, multi-resolution volume datasets (e.g., petascale microscopy) where memory efficiency and adaptive sampling are critical.
*   **When not to use:** For simple, single-resolution volumes where the overhead of the index texture is not justified.
