# Rolling 3-Row Slab Cache
Also called: VxlSlabCache
## Overview
The Rolling 3-Row Slab Cache is a memory structure designed to store voxel column data across a rolling window of three Y-rows to support incremental updates and neighbor-dependent recompilation in dense voxel grids [S1, unofficial]. It sets itself apart from sibling caches by maintaining a fixed-size sliding window of Y-indices rather than a priority-based or full-grid storage, optimizing for locality during column-wise edits [S1, unofficial].
## How it works
### Inputs and Outputs
- **Inputs**: X and Y coordinates within the voxel grid dimensions ($VSID$); base Y coordinate defining the window position.
- **Outputs**: A cache slot index for a specific voxel column, or `None` if the coordinate is out of bounds or outside the rolling window.

### Data Structures
The cache maintains a flat array of optional column slots.
- **`columns`**: `Box<[Option<VxlSlabColumn>; Self::COLUMN_COUNT]>`
- **`WIDTH`**: Constant `3`, representing the number of rolling rows (Stale, Flush, Edit).
- **`COLUMN_COUNT`**: Constant `VSID * 3`, where $VSID$ is the voxel grid dimension in X and Y.
- **`VxlSlabColumn`**: A collection of `VxlSlab` structs, where each slab represents a contiguous range of Z-values (solid start to exclusive end).

### Constants and Mapping
The three rows are mapped to Y-offsets relative to the `base_y`:
- **`STALE_ROW`**: Index `0`, Y-offset `-2`.
- **`FLUSH_ROW`**: Index `1`, Y-offset `-1`.
- **`EDIT_ROW`**: Index `2`, Y-offset `0`.

The slot index for a given X and Y is calculated as:
$$ \text{slot} = x \times \text{WIDTH} + \text{row\_index} $$
where `row_index` is derived from the Y-offset.

### Steps
1. **Initialization (`start_edits`)**:
   - Clamp input coordinates to $[0, VSID-1]$.
   - Calculate `flush_x_start/end` and `support_x_start/end` with $\pm 1$ padding to ensure neighbor access.
   - Initialize `VxlSlabCacheCtx` with the base slot and bounds.
   - Call `ctx.init()` to nullify columns in the support range.

2. **Index Calculation (`get_index_y`)**:
   - Validate that $y$ is within $[0, VSID)$.
   - Compute $y_{\text{offset}} = y - \text{base\_y}$.
   - Check if $y_{\text{offset}} \in \{-2, -1, 0\}$. If not, return `None`.
   - Map $y_{\text{offset}}$ to a slot index: $\text{slot} = y_{\text{offset}} + 2$.
   - Call `get_index_slot(base_slot, x, slot)` to return the final linear index.

### Pseudocode
```python
# Constants
WIDTH = 3
# VSID is the grid dimension in X and Y
# MAXZDIM is the grid dimension in Z

def get_index_y(base_slot: int, base_y: int, x: int, y: int) -> Optional[int]:
    """
    Computes the cache slot index for a voxel at (x, y) relative to base_y.
    Returns None if y is out of grid bounds or outside the 3-row window.
    """
    # Check global Y bounds
    if not (0 <= y < VSID):
        return None
    
    # Calculate offset from the base of the rolling window
    y_offset = y - base_y
    
    # Check if within the 3-row window (-2, -1, 0)
    if not (-2 <= y_offset <= 0):
        return None
    
    # Map offset to slot index 0, 1, or 2
    slot = y_offset + 2
    
    # Compute linear index: x * WIDTH + slot
    # Note: base_slot is typically x * WIDTH for the current column group
    return base_slot + slot

def start_edits(ctx: VxlSlabCacheCtx, x: int, y: int, vsid: int):
    """
    Initializes the cache context for edits at (x, y).
    """
    # Clamp coordinates to [0, VSID-1]
    x = max(0, min(x, vsid - 1))
    y = max(0, min(y, vsid - 1))
    
    # Calculate support range with +/- 1 padding
    flush_x_start = x - 1
    flush_x_end = x + 1
    support_x_start = x - 1
    support_x_end = x + 1
    
    # Initialize context with base slot and bounds
    # Assuming base_slot corresponds to the column group for x
    base_slot = x * WIDTH
    ctx.init(base_slot, flush_x_start, flush_x_end, support_x_start, support_x_end)
    
    # Nullify columns in the support range
    for sx in range(support_x_start, support_x_end + 1):
        for sy in range(-2, 1): # -2, -1, 0
            slot_idx = get_index_y(base_slot, ctx.base_y, sx, ctx.base_y + sy)
            if slot_idx is not None:
                ctx.columns[slot_idx] = None

def get_voxel(x: int, y: int, z: int, ctx: VxlSlabCacheCtx) -> VxlState:
    """
    Retrieves the voxel state at (x, y, z).
    """
    if not (0 <= x < VSID) or not (0 <= y < VSID):
        return VxlState.Air
    
    slot_idx = get_index_y(ctx.base_slot, ctx.base_y, x, y)
    if slot_idx is None:
        return VxlState.Air # Or handle out-of-window appropriately
        
    column = ctx.columns[slot_idx]
    if column is None:
        return VxlState.Air
        
    return get_voxel_inner(column, z)

def get_voxel_inner(column: List[VxlData], z: int) -> VxlState:
    """
    Traverses the RLE column to find the state at Z.
    """
    if z >= MAXZDIM:
        return VxlState.Unexposed
        
    cursor = 0
    while cursor < len(column):
        span = VxlCompiledSpan(column[cursor:])
        
        if z <= span.solid_start():
            return span.solid_start() # Or appropriate state
            
        if span.header.is_last_span():
            break
            
        if span.solid_start() <= z <= span.solid_end():
            break
            
        cursor += span.header.len
        
    return VxlState.Air # Default if not found in spans
```

### Parameters
- **`WIDTH`**: `3` [S1, unofficial].
- **`STALE_ROW`**: `0` [S1, unofficial].
- **`FLUSH_ROW`**: `1` [S1, unofficial].
- **`EDIT_ROW`**: `2` [S1, unofficial].

### Edge Cases and Pitfalls
- **Out-of-bounds coordinates**: `get_index_y` and `get_index_slot` return `None` instead of panicking when X or Y are outside $[0, VSID)$ or the Y-offset is outside $[-2, 0]$ [S1, unofficial].
- **Empty Columns**: Recompilation asserts that the slab column is not empty and that the last slab ends at `MAXZDIM` [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Index lookup is $O(1)$. Voxel access is $O(S)$ where $S$ is the number of spans in the column.
- **Memory Complexity**: $O(VSID \times 3)$ slots, each holding an optional column.
- **Strengths**: Efficient for incremental updates where only a small vertical strip of columns changes. The rolling window reduces cache pressure by keeping only relevant Y-rows active.
- **Limitations**: Not suitable for random access across large Y ranges without updating the base Y. Requires careful management of the rolling window position.
- **When to use**: When performing voxel edits or recompilations on a per-column basis with strong Y-locality.
- **When not to use**: For global grid queries or when Y-coordinates are widely scattered.

## Background
The Rolling 3-Row Slab Cache is part of the VxlSlabCache implementation in the `rust-voxlap-vxl` project [S1, unofficial]. It is designed to optimize voxel data structures for real-time editing and rendering by minimizing memory allocations and maximizing cache locality for column-based operations.
