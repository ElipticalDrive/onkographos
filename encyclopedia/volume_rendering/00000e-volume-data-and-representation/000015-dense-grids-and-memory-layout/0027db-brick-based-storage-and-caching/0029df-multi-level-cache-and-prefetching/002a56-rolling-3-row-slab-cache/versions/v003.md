# Rolling 3-Row Slab Cache
Also called: VxlSlabCache
## Overview
The Rolling 3-Row Slab Cache is a memory structure that stores voxel column data across a rolling window of three Y-rows to support incremental updates and neighbor-dependent recompilation in dense voxel grids [S1, unofficial]. It sets itself apart from sibling caches like the [VxlSlabColumn Priority Cache](4742-vxlslabcolumn-priority-cache.md) by maintaining a fixed-size sliding window of Y-indices rather than priority-based or full-grid storage, optimizing for locality during column-wise edits [S1, unofficial]. It builds on the principles of [Multi-Level Cache and Prefetching](4631-multi-level-cache-and-prefetching.md) by restricting active memory to a narrow spatial band [S1, unofficial].
## How it works
### Inputs and Outputs
- **Inputs**: X and Y coordinates within the voxel grid dimensions ($VSID$); a base Y coordinate defining the window position; a cache context object [S1, unofficial].
- **Outputs**: A cache slot index for a specific voxel column, or `None` if the coordinate is out of bounds or outside the rolling window [S1, unofficial].

### Data Structures
The cache maintains a flat array of optional column slots [S1, unofficial].
- **`columns`**: `Box<[Option<VxlSlabColumn>; Self::COLUMN_COUNT]>` where each slot holds an optional column [S1, unofficial].
- **`WIDTH`**: Constant `3`, representing the number of rolling rows (Stale, Flush, Edit) [S1, unofficial].
- **`COLUMN_COUNT`**: Constant `VSID * 3`, where $VSID$ is the voxel grid dimension in X and Y [S1, unofficial].
- **`VxlSlabColumn`**: A collection of `VxlSlab` structs, where each slab represents a contiguous range of Z-values (solid start to exclusive end) [S1, unofficial].

### Constants and Mapping
The three rows are mapped to Y-offsets relative to the `base_y` [S1, unofficial]:
- **`STALE_ROW`**: Index `0`, Y-offset `-2` [S1, unofficial].
- **`FLUSH_ROW`**: Index `1`, Y-offset `-1` [S1, unofficial].
- **`EDIT_ROW`**: Index `2`, Y-offset `0` [S1, unofficial].

The slot index for a given X and Y is calculated as:
$$ \text{slot\_index} = x \times \text{WIDTH} + \text{row\_index} $$
where `row_index` is derived from the Y-offset [S1, unofficial].

### Steps
1. **Initialization (`start_edits`)**:
   - Clamp input coordinates to $[0, VSID-1]$ [S1, unofficial].
   - Calculate `flush_x_start/end` and `support_x_start/end` with $\pm 1$ padding to ensure neighbor access [S1, unofficial].
   - Initialize `VxlSlabCacheCtx` with the base slot and bounds [S1, unofficial].
   - Call `ctx.init()` to nullify columns in the support range [S1, unofficial].

2. **Index Calculation (`get_index_y`)**:
   - Validate that $y$ is within $[0, VSID)$ [S1, unofficial].
   - Compute $y_{\text{offset}} = y - \text{base\_y}$ [S1, unofficial].
   - Check if $y_{\text{offset}} \in \{-2, -1, 0\}$ [S1, unofficial].
   - Map $y_{\text{offset}}$ to a slot index: $\text{slot} = y_{\text{offset}} + 2$ [S1, unofficial].
   - Call `get_index_slot(base_slot, x, slot)` to return the final linear index [S1, unofficial].

### Pseudocode
```python
WIDTH = 3
VSID = 256  # Grid dimension in X and Y

def get_index_slot(base_slot: int, x: int, slot: int) -> int:
    """Computes the linear cache index from x, slot, and base offset."""
    return x * WIDTH + slot

def get_index_y(base_slot: int, base_y: int, x: int, y: int) -> int | None:
    """Computes the cache slot index for a voxel at (x, y) relative to base_y."""
    if not (0 <= y < VSID):
        return None
    y_offset = y - base_y
    if not (-2 <= y_offset <= 0):
        return None
    slot = y_offset + 2
    return get_index_slot(base_slot, x, slot)

def start_edits(ctx: dict, x: int, y: int, vsid: int) -> None:
    """Initializes the cache context for edits at (x, y)."""
    # Clamp coordinates to [0, VSID-1]
    x = max(0, min(x, vsid - 1))
    y = max(0, min(y, vsid - 1))
    
    # Calculate flush and support ranges with ±1 padding
    flush_x_start = x - 1
    flush_x_end = x + 1
    support_x_start = x - 1
    support_x_end = x + 1
    
    # Initialize context with base slot and bounds
    base_slot = x * WIDTH
    ctx['base_slot'] = base_slot
    ctx['base_y'] = y
    ctx['flush_x_start'] = flush_x_start
    ctx['flush_x_end'] = flush_x_end
    ctx['support_x_start'] = support_x_start
    ctx['support_x_end'] = support_x_end
    
    # Nullify columns in the support range
    ctx.init()
```

### Parameters
- **`WIDTH`**: `3` [S1, unofficial].
- **`STALE_ROW`**: `0` [S1, unofficial].
- **`FLUSH_ROW`**: `1` [S1, unofficial].
- **`EDIT_ROW`**: `2` [S1, unofficial].

### Edge Cases and Pitfalls
- **Out-of-bounds coordinates**: `get_index_y` and `get_index_slot` return `None` instead of panicking when X or Y are outside $[0, VSID)$ or the Y-offset is outside $[-2, 0]$ [S1, unofficial].
- **Empty Columns**: Recompilation asserts that the slab column is not empty and that the last slab ends at `MAXZDIM` [S1, unofficial].
- **Precision/Boundaries**: The $\pm 1$ padding in `start_edits` guarantees neighbor columns are accessible during recompilation without index underflow or overflow [S1, unofficial].

It is designed to optimize voxel data structures for real-time editing and rendering by minimizing memory allocations and maximizing cache locality for column-based operations [S1, unofficial].
