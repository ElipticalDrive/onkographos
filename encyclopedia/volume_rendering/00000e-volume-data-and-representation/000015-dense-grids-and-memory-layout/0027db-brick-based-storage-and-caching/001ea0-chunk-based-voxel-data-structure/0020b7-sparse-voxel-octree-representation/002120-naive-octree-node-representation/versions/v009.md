# Naive Octree Node Representation

Also called: Branch Tree Node, Direct Memory Octree Node, Pointer-based Octree Node

## Overview
The Naive Octree Node Representation is a direct memory layout for hierarchical spatial partitioning where each non-leaf node explicitly stores pointers to its eight children, and leaf nodes store a single data value [S1, S3, unofficial]. It provides a straightforward recursive structure for storing and querying voxel values, where each non-leaf node divides space into 8 children and leaf nodes store a single `uint32_t` value [S3, unofficial]. Unlike compressed variants such as [Bitmask Leaf Compression](3603-bitmask-leaf-compression.md) or layout-optimized structures like [Octree Data Structure Layout](4518-octree-data-structure-layout.md), this method incurs significant memory overhead for dense scenes, as storing explicit leaf nodes causes memory usage to approach 8 times that of a full octree of depth $d-1$ [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel value $v$ with position $p=(x,y,z)$ and an octree $o$ with root node $r$ and depth $d$ [S1, S3, unofficial].
*   **Output:** The modified octree $o$ with the voxel inserted, or the value retrieved at position $p$ [S1, S3, unofficial].

**Data Structures:**
The core structure is the `Node`, with two common layouts cited in the literature:

1.  **Compact Layout (S3):**
    ```cpp
    struct OctreeNode {
        bool isLeaf;          // 1 byte
        uint32_t value;       // 4 bytes (stores color/index if leaf, or acts as marker) [S3, unofficial]
        OctreeNode* children; // 4 or 8 bytes (pointer to array of 8 children if not leaf) [S3, unofficial]
        uint8_t centerX;      // 1 byte
        uint8_t centerY;      // 1 byte
        uint8_t centerZ;      // 1 byte
        uint8_t depth;        // 1 byte
    };
    ```
    S3 specifies that `value` stores the voxel data for leaves, while `children` is allocated for non-leaves, and memory order matches declaration [S3, unofficial].

2.  **Explicit Index Layout (S1):**
    ```cpp
    struct Node {
        Node * children[8];
        int8_t voxelColorIndex;
        bool isLeaf;
    };
    ```
    S1 cites this specific struct layout with explicit memory costs [S1, unofficial].

**Numbered Steps:**

1.  **Root Initialization:**
    *   Set `depth = 0` [S3, unofficial].
    *   Set `isLeaf = true` [S3, unofficial].
    *   Set `value = 0` [S3, unofficial].
    *   Set `centerX = centerY = centerZ = 0` [S3, unofficial].

2.  **Non-Root Initialization (for child creation):**
    *   Set `depth` to parent's depth + 1 [S3, unofficial].
    *   Set `isLeaf = true` initially [S3, unofficial].
    *   Set `value = 0` [S3, unofficial].
    *   Calculate `childDepth = depth - 1` [S3, unofficial].
    *   Calculate `childSize = 1 << childDepth` (i.e., $2^{childDepth}$) [S3, unofficial].
    *   Set `centerX = x + childSize`, `centerY = y + childSize`, `centerZ = z + childSize`, where $(x,y,z)$ is the node's base coordinate [S3, unofficial].

3.  **Insert Voxel (`SetVoxel`):**
    *   **Base Case:** If `depth == 0`, set `this->value = value` and return [S3, unofficial].
    *   **Leaf Optimization:** If `isLeaf` is true and `this->value == value`, return (no change needed) [S3, unofficial].
    *   **Split Leaf:** If `isLeaf` is true but `this->value != value`:
        *   Call `initChildren()` to allocate and initialize 8 child nodes [S3, unofficial].
        *   Copy `this->value` to all 8 children (propagate current value) [S3, unofficial].
        *   Set `isLeaf = false`.
    *   **Recurse:**
        *   Compute `childIndex` using `GetChildIndex(x, y, z)` [S3, unofficial].
        *   Recurse: `children[childIndex].SetVoxel(x, y, z, value)` [S3, unofficial].
    *   **Collapse:** Call `TryCollapse()` to check if all 8 children are identical leaves; if so, merge them back into this node [S3, unofficial].

4.  **Retrieve Voxel (`GetValue`):**
    *   If `isLeaf` is true, return `value` [S3, unofficial].
    *   Else, compute `childIndex` via `GetChildIndex(x, y, z)` [S3, unofficial].
    *   Return `children[childIndex].GetValue(x, y, z)` [S3, unofficial].

5.  **Initialize Children (`initChildren`):**
    *   Set `childDepth = depth - 1` [S3, unofficial].
    *   Set `childSize = 1 << childDepth` [S3, unofficial].
    *   Allocate `children = new OctreeNode[8]` [S3, unofficial].
    *   Compute base coordinates: `baseX = centerX - childSize`, `baseY = centerY - childSize`, `baseZ = centerZ - childSize` [S3, unofficial].
    *   Initialize 8 children with offsets relative to the base:
        *   Indices 0-7 correspond to binary representations of $0..7$ mapping to $(dx, dy, dz)$ where $dx, dy, dz \in \{0, childSize\}$ [S3, unofficial].
        *   Example: Child 0 at $(baseX, baseY, baseZ)$, Child 1 at $(baseX+childSize, baseY, baseZ)$, etc. [S3, unofficial].

**Pseudocode:**

```python
class OctreeNode:
    def __init__(self, depth, centerX, centerY, centerZ):
        self.depth = depth
        self.centerX = centerX
        self.centerY = centerY
        self.centerZ = centerZ
        self.isLeaf = True
        self.value = 0
        self.children = None

    def init_children(self):
        """Allocates 8 child nodes and propagates current leaf value."""
        child_depth = self.depth - 1
        child_size = 1 << child_depth
        
        base_x = self.centerX - child_size
        base_y = self.centerY - child_size
        base_z = self.centerZ - child_size
        
        self.children = []
        for i in range(8):
            dx = (i & 1) * child_size
            dy = (i & 2) * child_size
            dz = (i & 4) * child_size
            
            child = OctreeNode(child_depth, base_x + dx, base_y + dy, base_z + dz)
            child.value = self.value
            self.children.append(child)
        
        self.isLeaf = False

    def get_child_index(self, x, y, z):
        """Maps global coordinates to one of 8 children based on center split."""
        idx = 0
        if x >= self.centerX: idx |= 1
        if y >= self.centerY: idx |= 2
        if z >= self.centerZ: idx |= 4
        return idx

    def set_voxel(self, x, y, z, value):
        if self.depth == 0:
            self.value = value
            return
        
        if self.isLeaf:
            if self.value == value:
                return
            self.init_children()
        
        child_idx = self.get_child_index(x, y, z)
        self.children[child_idx].set_voxel(x, y, z, value)
        
        self.try_collapse()

    def get_value(self, x, y, z):
        if self.isLeaf:
            return self.value
        child_idx = self.get_child_index(x, y, z)
        return self.children[child_idx].get_value(x, y, z)

    def try_collapse(self):
        """Merges 8 identical leaf children back into this node."""
        if self.isLeaf:
            return
        
        first_child = self.children[0]
        if not first_child.isLeaf:
            return
        
        same_value = first_child.value
        for child in self.children[1:]:
            if not child.isLeaf or child.value != same_value:
                return
        
        self.isLeaf = True
        self.value = same_value
        self.children = None
```

**Parameters:**
*   **Memory Cost:** 72 Bytes per node on a 64-bit processor; 40 Bytes on a 32-bit processor [S1, unofficial].
*   **Depth:** The maximum recursion depth $d$. Depth 0 is the base case (single voxel) [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Depth 0 Base Case:** Recursion must stop at `depth == 0` [S3, unofficial].
*   **Undefined Helpers:** `GetChildIndex` and `TryCollapse` are referenced in S3 but not defined [S3, unofficial].
*   **Memory Overhead:** For a full octree of depth $d$, the memory cost factor $mc$ approaches 8 times that of a full octree of depth $d-1$ due to explicit leaf nodes [S1, unofficial].

## Subtopics

### [Bitmask Leaf Compression](3603-bitmask-leaf-compression.md)
Bitmask Leaf Compression is a memory optimization technique for Sparse Voxel Octrees that eliminates leaf nodes at the deepest level by packing their voxel data into a single integer field within their parent node. It solves the excessive memory overhead of naive octree representations, where storing explicit leaf nodes causes memory usage to approach 8 times that of a full octree of depth $d-1$. By removing the leaf node structure entirely, it reduces the memory cost factor $mc$ from 8 to 1 for the deepest level.

### [Octree Data Structure Layout](4518-octree-data-structure-layout.md)
This article defines the memory layout and class structure for a naive octree representation, serving as the foundational implementation for sparse voxel octrees. It solves the problem of organizing hierarchical volumetric data in contiguous memory while maintaining access to bounding box metadata and voxel attributes. It differs from its parent [Naive Octree Node Representation](2445-naive-octree-node-representation.md) by explicitly defining the container class fields (`min`, `max`, `size`, `gridlength`) and the storage mechanism (`std::vector<Node>`), and it differs from its sibling [Bitmask Leaf Compression](3603-bitmask-leaf-compression.md) by storing full node structures rather than compressing leaf status into bitmasks.

### Discriminated Union Node Storage
A method using a union to store either leaf data or child pointers in the same memory space, distinguished by a boolean flag [S4, unofficial]. Size overhead is one byte for the boolean flag, plus typically 7 bytes of padding on a 64-bit platform [S4, unofficial]. Speed overhead requires a boolean check to determine which union member is active [S4, unofficial]. Layout: `class Node<T>` contains a `bool isLeaf`, followed by an anonymous union. If `isLeaf` is true, the union member `T value` is valid [S4, unofficial]. If `isLeaf` is false, the union member `Node<T> *children[8]` is valid [S4, unofficial]. Pitfall: If `sizeof(value)` is less than `sizeof(children)` by at least `sizeof(Node<T>*)`, the `isLeaf` flag can be omitted by prepending a null pointer to the value and checking if `children[0] == nullptr` [S4, unofficial].

### Inheritance-based Octree Node Storage
A method of storing octree nodes using C++ inheritance, where a base Node class is inherited by specific Internal (branch) and Leaf classes to distinguish node types [S4, unofficial]. Size overhead is one vtable pointer, typically 8 bytes on a 64-bit platform [S4, unofficial]. Layout: Base class `Node<T>` is empty or minimal. `Internal<T>` inherits `Node<T>` and contains `Node<T> *children[8]`. `Leaf<T>` inherits `Node<T>` and contains `T value` [S4, unofficial]. Pitfall: Performance overhead exists due to either virtual function calls or `dynamic_cast` operations required to access specific node data [S4, unofficial].

### Single Type Node Storage
A method where a single node type contains both data and child pointers, deducing leaf status by checking if the first child pointer is null [S4, unofficial]. Layout: `class Node<T>` contains a `bool isLeaf`, `T value` (valid if leaf), and `Node<T> *children[8]` (valid if not leaf) [S4, unofficial]. Pitfall: Either the value or the child pointers are redundant, resulting in wasted memory compared to the discriminated union approach [S4, unofficial]. There is no advantage compared to the discriminated union method [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Insertion and retrieval are $O(d)$ where $d$ is the depth of the octree, as each step traverses one level [G].
*   **Memory Complexity:** $O(N)$ where $N$ is the number of nodes [G]. Due to the naive structure, $N$ can be up to 8 times larger than necessary for dense scenes compared to compressed variants [S1, unofficial].
*   **Performance:** Fast to implement and debug due to direct pointer access. Slow for dense data due to high memory allocation and poor cache locality (scattered nodes) [S1, unofficial].
*   **Strengths:** Simple logic, direct traversal, no complex bit-packing logic required for basic operations [S1, unofficial].
*   **Limitations:** High memory usage, especially for deep trees or dense volumes. Not suitable for real-time applications with large scenes without compression [S1, unofficial].

## Background
The specific struct layout with 72/40 byte costs is cited in a thesis on global illumination efficiency [S1, unofficial]. It is described in academic studies on Sparse Voxel Octree compression [S1, unofficial].
