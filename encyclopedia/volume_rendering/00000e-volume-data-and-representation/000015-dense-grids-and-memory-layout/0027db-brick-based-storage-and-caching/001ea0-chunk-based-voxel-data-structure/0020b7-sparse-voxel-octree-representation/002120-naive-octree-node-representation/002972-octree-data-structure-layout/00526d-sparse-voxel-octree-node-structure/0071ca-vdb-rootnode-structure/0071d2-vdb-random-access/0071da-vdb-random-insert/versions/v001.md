# VDB Random Insert

Also called: VDB Insert, Sparse Voxel Octree Insert

## Overview
VDB Random Insert is the algorithm for inserting values into a VDB (Sparse Voxel Octree) data structure, primarily used for initialization or dynamic data updates such as rebuilding a narrow band of a level set [S1, unofficial]. It differs from [VDB Random Access](22363-vdb-random-access.md) by allocating child nodes dynamically when bits are off in the `mChildMask`, ensuring a low memory footprint for sparse data, whereas random access only traverses existing nodes [S1, unofficial].

## How it works
**Inputs:** A VDB RootNode, a voxel position (defined by a perfect key or coordinate), and a value to insert.
**Outputs:** The VDB structure updated with the new value and necessary node allocations.

**Data Structures:**
*   **RootNode:** Contains a map of child nodes and a `mChildMask` (bitmask indicating presence of children) and `mValueMask` (bitmask indicating active voxels in leaf nodes).
*   **Child Nodes:** Octree nodes (Tile, Internal, or Leaf) indexed by bits in the mask.
*   **LeafNode:** Contains the actual voxel data buffer.

**Steps:**
1.  **Traverse:** Start at the RootNode. Use fast bit operations to determine the path to the target voxel based on its key [S1, unofficial].
2.  **Allocate:** For each level of the octree, check the corresponding bit in the current node's `mChildMask`. If the bit is off (0), allocate a new child node and set the bit to 1 [S1, unofficial].
3.  **Terminate:** Continue traversal until a LeafNode is reached (which may have been newly constructed in step 2) [S1, unofficial].
4.  **Set Value:** Write the input value into the desired temporal buffer within the LeafNode at the specific voxel index [S1, unofficial].
5.  **Update Mask:** Set the corresponding bit in the LeafNode's `mValueMask` to indicate the voxel is active [S1, unofficial].

**Pseudocode:**
```python
def vdb_random_insert(root_node, key, value):
    """
    Inserts a value into the VDB structure at the given key.
    key: integer perfect key representing the voxel position.
    value: the data to store.
    """
    current_node = root_node
    
    # Traverse from root to leaf, allocating nodes as needed
    # Assuming 8 levels of octree for a standard VDB resolution block
    for level in range(0, 8):
        # Extract 3 bits from the key for this level (x, y, z)
        # This assumes a standard perfect key layout where bits are interleaved
        # or pre-extracted. The source refers to "fast bit operations" [S1, unofficial].
        child_index = get_child_index_from_key(key, level)
        
        # Check if child exists using mChildMask
        if not (current_node.mChildMask & (1 << child_index)):
            # Allocate new child node
            new_child = allocate_octree_node()
            current_node.children[child_index] = new_child
            # Set the bit in mChildMask to mark existence
            current_node.mChildMask |= (1 << child_index)
        
        # Move to the child
        current_node = current_node.children[child_index]
        
        # If we reached a LeafNode, stop traversing
        if isinstance(current_node, LeafNode):
            break
    
    # current_node is now the LeafNode
    # Set the voxel value in the temporal buffer
    # The specific index within the leaf is derived from the final bits of the key
    leaf_index = get_leaf_index_from_key(key)
    current_node.data_buffer[leaf_index] = value
    
    # Set the corresponding bit in mValueMask
    current_node.mValueMask |= (1 << leaf_index)
```

**Edge Cases and Pitfalls:**
*   **Dynamic Allocation Overhead:** Random insert is slower than random lookup because it involves dynamic memory allocation for child nodes [S1, unofficial].
*   **Amortization:** The overhead is amortized over multiple coherent insert operations, resulting in average constant-time complexity [S1, unofficial].
*   **Precision:** Ensure the perfect key generation is collision-free for the root map [S1, unofficial].

## Subtopics

### VDB Random Deletion
Algorithm for deleting values from VDB, requiring efficiency for dynamic data [S1, unofficial]. It unsets bits in `mChildMask` and `mValueMask` and prunes empty nodes bottom-up [S1, unofficial]. Steps: 1. Traverse similarly to random insert [S1, unofficial]. 2. Unset bits in `mChildMask` and `mValueMask` [S1, unofficial]. 3. Prune nodes bottom-up if they contain no child nodes or active voxels [S1, unofficial]. 4. Implement pruning efficiently by checking multiple bits (e.g., 64 entries) using 64-bit arithmetic [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Average O(1) due to amortization over coherent insert operations [S1, unofficial].
*   **Memory Footprint:** Low for sparse volumetric data because nodes below the RootNode are allocated only on insert [S1, unofficial].
*   **Performance:** Slower than random lookup due to dynamic allocation overhead, but efficient for dynamic data updates [S1, unofficial].
*   **Strengths:** Supports constant-time random access operations independent of topology or resolution [S1, unofficial].
*   **Limitations:** Dynamic allocation can cause latency spikes if not amortized; not suitable for static data where lookup-only is sufficient.

## Background
Originated in the VDB (Sparse Voxel Octree) framework by Ken Museth, presented in the paper "VDB: High-Resolution Sparse Volumes with Dynamic Topology" (TOG 2013) [S1, unofficial]. It is used in high-resolution volume rendering and dynamic topology simulations, such as narrow band level set rebuilding [S1, unofficial].
