# World Function / Neighbor Query

Also called: Querying neighboring chunks, World block access

## Overview
The World Function / Neighbor Query is a method for accessing voxel data across chunk boundaries by abstracting local chunk bounds into a global coordinate system. It solves the problem of boundary checks during mesh generation and block updates by allowing any voxel coordinate to be queried regardless of which chunk owns it, eliminating the need to duplicate or pad voxel data at chunk edges. It differs from direct chunk access by centralizing boundary logic into a single query function that handles out-of-bounds and unloaded regions, whereas sibling methods like [Chunk Neighbor Retrieval](6783-chunk-neighbor-retrieval.md) explicitly fetch neighbor chunk coordinates for face-adjacent access.

## How it works
The method defines a global function that accepts world block coordinates, determines the owning chunk, and returns the block ID or a sentinel value.

**Inputs and Outputs:**
- Input: World block coordinates $(x, y, z)$.
- Output: Block ID (integer).

**Data Structures:**
- Chunk storage: A map or array mapping chunk coordinates $(cx, cy, cz)$ to chunk data structures.
- Chunk data: Contains a 3D array of block IDs of size $S \times S \times S$, where $S$ is the chunk size.
- Sentinel values:
  - $0$: Air (empty block).
  - $-2$: Out-of-bounds or unloaded chunk.

**Steps:**
1. Define a world function `get_block(x, y, z)` that accepts world block coordinates.
2. Compute the chunk coordinates $(cx, cy, cz)$ from the world block coordinates using integer division:
   $$ cx = \lfloor x / S \rfloor, \quad cy = \lfloor y / S \rfloor, \quad cz = \lfloor z / S \rfloor $$
   where $S$ is the chunk size.
3. Check if the chunk at $(cx, cy, cz)$ exists and is loaded. If not, return $-2$.
4. Compute the local block coordinates $(lx, ly, lz)$ within the chunk:
   $$ lx = x \pmod S, \quad ly = y \pmod S, \quad lz = z \pmod S $$
   Handle negative modulo results if the language does not support mathematical modulo (e.g., in C++/Python, ensure $lx \ge 0$).
5. Retrieve the block ID from the chunk's data array at $(lx, ly, lz)$.
6. Return the block ID. If the block is air, return $0$.

**Parameters:**
- $S$: Chunk size. Typical values are $16$ or $32$ blocks per dimension.
- Return value for air: $0$.
- Return value for out-of-bounds/unloaded: $-2$.

**Pitfalls:**
- Requires adding conditional checks to the meshing logic to handle the $-2$ sentinel, which prevents meshing sides of unloaded chunks.
- Avoids duplicating voxel data across chunk boundaries, but requires careful handling of negative coordinates in modulo operations.
- Precision issues may arise if chunk coordinates are computed incorrectly for negative world coordinates.

**Pseudocode:**
```python
def get_block(world_x, world_y, world_z, chunk_size, chunk_map):
    # Step 2: Compute chunk coordinates
    chunk_x = floor(world_x / chunk_size)
    chunk_y = floor(world_y / chunk_size)
    chunk_z = floor(world_z / chunk_size)

    # Step 3: Check if chunk exists and is loaded
    chunk_key = (chunk_x, chunk_y, chunk_z)
    if chunk_key not in chunk_map:
        return -2  # Out-of-bounds or unloaded

    chunk_data = chunk_map[chunk_key]

    # Step 4: Compute local block coordinates
    local_x = world_x % chunk_size
    local_y = world_y % chunk_size
    local_z = world_z % chunk_size

    # Handle negative modulo results for languages where % can return negative
    if local_x < 0:
        local_x += chunk_size
    if local_y < 0:
        local_y += chunk_size
    if local_z < 0:
        local_z += chunk_size

    # Step 5: Retrieve block ID
    block_id = chunk_data[local_x][local_y][local_z]

    # Step 6: Return block ID (0 for air is implicit if stored as 0)
    return block_id
```

## Subtopics

### Cross-Chunk Boundary Block Retrieval
Retrieves the block type at a voxel coordinate that lies outside the current chunk's bounds by checking adjacent loaded chunks. If the coordinate along axis $d$ is negative ($<0$), it checks `nearbyChunks[0]`. If null, it returns `UNKNOW_BLOCK`. If not null, it adjusts the coordinate by adding the chunk size $S$ and returns the block data. If the coordinate is within bounds, it returns the block from the current chunk's data array. This variant is useful when the world function is not available or when optimizing for specific boundary cases in a voxel engine.

## Operating characteristics
- **Time Complexity:** $O(1)$ for chunk lookup and block access, assuming hash map or array access for chunk storage.
- **Memory Complexity:** $O(1)$ additional memory per query, as no extra data structures are created.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales well with world size as long as chunk loading/unloading is efficient.
- **Strengths:** Simplifies boundary checks, avoids data duplication, and centralizes boundary logic.
- **Limitations:** Requires handling of sentinel values and potential negative modulo issues.
- **When to use:** When simplifying chunk updates and boundary checks without padding overhead is desired.
- **When not to use:** When direct chunk access is sufficient and boundary checks are rare.

## Background
The method originates from community discussions on voxel game development, specifically addressing inner face culling and chunk boundary management. It was proposed as a simpler alternative to padding chunks with duplicate data, leveraging a global world function to abstract chunk boundaries. The approach is used in voxel engines to streamline mesh generation and block updates.
