# Chunk State Machine

Also called: Chunk Processing State Flags

## Overview
Chunks use bitwise flags to track processing state [S1, unofficial]. It operates alongside the parent [Chunk Data Modification & Queue Management](4427-chunk-data-modification-queue-management.md) to track chunk modifications and queue affected chunks for processing [G].

## How it works
**Inputs and Outputs:** Not given in the sources.
**Data Structures:** The state is stored in a single byte (`uint8`) using specific bitwise flags [S1, unofficial]:
- `V3_C_NONE (0x00)`: Initial or reset state.
- `V3_C_WAITING (0x01)`: Chunk is queued for processing.
- `V3_C_BUILT (0x02)`: Voxel data structure is built.
- `V3_C_READY (0x04)`: Chunk is ready for meshing.
- `V3_C_MESHED (0x08)`: Mesh geometry has been generated.
- `V3_C_IN_VIEW (0x10)`: Chunk is currently within the camera frustum.
- `V3_C_GLOBY (0x20)`: Chunk is marked for global update.
- `V3_C_MESHING (0x40)`: Mesh generation is in progress.
- `V3_C_REMESH (0x80)`: Chunk requires remeshing due to data changes.

**Steps:**
1. Initialize chunk state to `V3_C_NONE` [G].
2. Apply bitwise operations to set or clear flags based on processing events [G].
3. State transition logic is not given in the sources.

**Formulas:** Not given in the sources.

**Parameters:** Not given in the sources.

**Edge Cases:** Not given in the sources.

**Pseudocode:**
```python
# Bitmask constants for chunk state tracking [S1, unofficial]
V3_C_NONE = 0x00
V3_C_WAITING = 0x01
V3_C_BUILT = 0x02
V3_C_READY = 0x04
V3_C_MESHED = 0x08
V3_C_IN_VIEW = 0x10
V3_C_GLOBY = 0x20
V3_C_MESHING = 0x40
V3_C_REMESH = 0x80

def update_chunk_state(chunk_state: int, event: str) -> int:
    """
    Updates the chunk state byte based on an event.
    Transition logic between states is not specified in the sources [G].
    """
    if event == "START_MESHING":
        # Set meshing flag [G]
        return chunk_state | V3_C_MESHING
    elif event == "FINISH_MESHING":
        # Clear meshing flag [G]
        return chunk_state & ~V3_C_MESHING
    elif event == "DATA_CHANGED":
        # Mark for remeshing [G]
        return chunk_state | V3_C_REMESH
    elif event == "VISIBILITY_UPDATE":
        # Update view flag based on frustum check [G]
        return chunk_state | V3_C_IN_VIEW
    elif event == "GLOBAL_UPDATE":
        # Mark for global processing [G]
        return chunk_state | V3_C_GLOBY
    return chunk_state
```

## Subtopics

### Volume State Management
Manages the global state of the entire volume rather than individual chunks [S2, unofficial]. Each volume has a state: idle, loading, updating, or complete [S2, unofficial]. The `completeUpdate()` function reduces and uploads all pending slices, then renders [S2, unofficial]. The `restart()` function clears the queue, resets the cursor, marks all slices dirty, and increments a generation number; it is called by `cancelLoading` followed by `load`, a change of grid, and a new texture allocation [S2, unofficial]. A batch or worker result with an old generation number has no effect [S2, unofficial]. A viewport gives its focal reduced slice to the volume, which gets the highest priority; an oblique view uses all slices, so the round-robin cursor stays as the fallback [S2, unofficial].
