# Raymarching with LOD-based Brick Caching

Also called: Brick Caching and Decoding, Compressed Segmentation Volume (CSV) Visualization

## Overview
This method renders Compressed Segmentation Volumes (CSVs) by raymarching with one ray per pixel, decompressing bricks on-demand at the required Level of Detail (LOD) and storing them in a GPU cache [S1]. It exploits temporal coherency by allowing a one-frame lag for decompression requests, falling back to the coarsest LOD if the target LOD is not yet available [S1]. Unlike Shading Atlas Streaming (SAS), it tests bricks for empty space using palettes before requesting cache locations, omits superblock/column concepts in favor of contiguous base elements, and performs decompression during cache assignment [S1].

## How it works
**Inputs:** Compressed Segmentation Volume (CSV) data (palette and compressed voxel data), Transfer Function (TF) mapping labels to opacity/color, camera position and orientation, screen resolution.
**Outputs:** Rendered image.

**Data Structures:**
1.  **CSV Data:** Stored as palettes (label-to-color/opacity maps) and compressed voxel blocks. For large datasets, coarse LOD palettes/data reside in GPU memory, while fine LOD data resides in CPU memory [S1].
2.  **Cache Structure:**
    *   Pool of base elements, each holding $2^3$ voxels [S1].
    *   Blocks of size $2^{3 \cdot l}$ (where $l=1..N$) are formed from contiguous base elements to store decompressed bricks of LOD $l$ [S1].
    *   One stack $S_l$ per LOD level stores indices of free blocks [S1].
    *   A shared atomic cache top pointer to allocate new base elements if stacks are empty [S1].
3.  **Request Buffer:** Stores brick indices requiring fine detail data from CPU memory [S1].

**Parameters:**
*   **LOD Selection:** Target approximately one voxel per pixel on screen, based on the distance of the brick's center to the camera [S1].
*   **Opacity Threshold:** User-defined threshold for sending shadow rays [S1].
*   **Upload Buffer Size:** 8 MB buffer for transferring requested detail level data from CPU to GPU [S1].

**Steps:**

1.  **Raymarching:**
    *   Perform straightforward raymarching with one ray per pixel [S1].
    *   For each intersected brick, determine the required LOD based on the distance from the brick's center to the camera [S1].
    *   **Empty-Space Skipping:** Check the brick's palette. If no palette entry is mapped to an opacity $> 0$ by the current TF, skip the entire brick (do not request decompression) [S1].
    *   **Cache Lookup:** If the desired LOD is in the cache, sample it. If not, mark the brick/LOD as requested for the next frame [S1].
    *   **Fallback:** If a requested LOD is not yet decompressed in the current frame, fall back to the coarsest LOD (stored as the first palette entry, directly accessible) [S1].
    *   **Shading:** For hit voxels with opacity above the user-defined threshold, send an additional shadow ray. Optionally approximate ambient occlusion by accumulating shadow rays over time [S1].

2.  **Cache Assignment (Post-Frame):**
    *   Determine required bricks and LODs for the next frame [S1].
    *   Test visibility against the TF. Mark visible bricks with ascending indices (one sequence per block size) [S1].
    *   Count bricks per LOD level [S1].
    *   **Eviction:** Bricks already in the cache that became invisible are evicted. Their blocks are pushed onto the respective stack $S_l$ [S1].
    *   **Allocation:** For each LOD level $l$, check if stack $S_l$ has enough free blocks.
        *   If yes, assign blocks from $S_l$.
        *   If no, atomically advance the shared cache top pointer by $l$ to allocate new base elements forming a block of size $2^{3 \cdot l}$ [S1].
        *   If insufficient base elements exist (cache full/fragmented), rebuild the cache: clear all blocks/stacks and re-decompress all visible bricks [S1].
    *   **Detail Separation Check:** Determine if fine detail levels (stored in CPU memory) are needed for any requested brick [S1].
        *   If yes, add the brick index to the request buffer [S1].
        *   Transfer the request buffer to CPU memory [S1].
        *   Generate a buffer of requested detail levels in parallel to rendering the next frame and asynchronously upload to GPU memory [S1].
        *   If the upload buffer (e.g., 8 MB) is insufficient for the requested data, distribute the upload across several frames [S1].

3.  **Decompression:**
    *   Decompress requested bricks in parallel on the GPU [S1].
    *   Store results in the assigned cache locations [S1].
    *   If a brick requires fine detail from CPU memory and it has not arrived, decompress only up to the finest available level in GPU memory, or use predictive upload for bricks close to the camera [S1].

def render_frame(camera, tf, csv_data):
    image = empty_image()
    next_frame_requests = [] # List of (brick_index, lod_level)
    
    # 1. Raymarching
    for pixel in pixels:
        ray = cast_ray(pixel, camera)
        while ray_traverse(ray, csv_data):
            brick = get_intersected_brick(ray)
            
            # Empty-Space Skipping
            if not is_visible_in_tf(brick.palette, tf):
                continue
                
            lod = determine_lod(brick.center, camera)
            
            # Cache Lookup
            cached_block = cache_lookup(brick.index, lod)
            
            if cached_block is not None:
                sample = sample_voxel(cached_block, ray)
                image[pixel] = composite(image[pixel], sample)
                
                # Shadow Ray
                if sample.opacity > opacity_threshold:
                    shadow_color = cast_shadow_ray(ray, brick)
                    image[pixel] = apply_shading(image[pixel], shadow_color)
            else:
                # Request for next frame
                next_frame_requests.append((brick.index, lod))
                # Fallback to coarsest LOD if not yet decompressed
                coarsest_lod = 0
                cached_block = cache_lookup(brick.index, coarsest_lod)
                if cached_block is not None:
                    sample = sample_voxel(cached_block, ray)
                    image[pixel] = composite(image[pixel], sample)
    
    # 2. Cache Assignment (for next frame)
    process_cache_assignment(next_frame_requests, tf, csv_data)
    
    return image

def process_cache_assignment(requests, tf, csv_data):
    visible_bricks = []
    counts = [0] * MAX_LOD
    
    # Mark visible bricks and count
    for brick_index, lod in requests:
        # Re-check visibility (TF might have changed or brick might be occluded)
        if is_visible_in_tf(csv_data[brick_index].palette, tf):
            visible_bricks.append((brick_index, lod))
            counts[lod] += 1
            
    # Evict invisible bricks from cache
    evicted_blocks = evict_invisible_bricks(visible_bricks)
    for block in evicted_blocks:
        lod = block.lod
        stacks[lod].push(block.index)
        
    # Allocate blocks
    allocated_blocks = []
    for lod in range(MAX_LOD):
        needed = counts[lod]
        available = stacks[lod].size()
        
        if available >= needed:
            # Use existing free blocks
            for _ in range(needed):
                block_idx = stacks[lod].pop()
                allocated_blocks.append((block_idx, lod))
        else:
            # Allocate new blocks
            deficit = needed - available
            for _ in range(deficit):
                # Atomically advance cache top
                base_idx = atomic_add(&cache_top, lod)
                # Form block from contiguous base elements
                block_idx = base_idx
                allocated_blocks.append((block_idx, lod))
                
            # Check for cache rebuild if allocation failed (not enough base elements)
            if cache_top > MAX_BASE_ELEMENTS:
                rebuild_cache(visible_bricks, csv_data)
                return # Rebuild handles decompression

    # 3. Detail Separation & Upload
    detail_requests = []
    for brick_index, lod in allocated_blocks:
        # Check if fine detail is needed (e.g., lod > coarsest_available_in_gpu)
        if needs_fine_detail(brick_index, lod, csv_data):
            detail_requests.append(brick_index)
            
    if detail_requests:

## Operating characteristics
*   **Time Complexity:** Raymarching is $O(P \cdot D)$ where $P$ is pixels and $D$ is depth. Decompression is parallelized on GPU. Cache assignment is $O(B)$ where $B$ is number of bricks.
*   **Memory Complexity:** Cache size depends on visible bricks and LODs. For the CORTEX dataset (6144x9216x4096), L0 (finest) consumes 9.2 GB, while all other levels take 4.3 GB [S1].
*   **Performance:** Exploits temporal coherency with a one-frame lag, reducing stalls [S1]. Empty-space skipping via palettes reduces unnecessary decompression [S1].
*   **Strengths:** Efficient handling of large CSVs via detail separation; fast access via cache; low latency for LOD changes due to fallback mechanism [S1].
*   **Limitations:** One-frame lag may cause visible artifacts during rapid camera movement; cache rebuilds can cause stuttering if fragmentation is high [S1].
*   **When to use:** Large segmentation volumes with temporal coherence; when GPU memory is insufficient for full resolution [S1].
*   **When not to use:** Scenes with rapid, non-coherent camera movement; when strict zero-latency LOD switching is required [S1].

## Background
Originated in the context of Compressed Segmentation Volumes (CSVs) for scientific visualization [S1]. The method builds on Shading Atlas Streaming (SAS) but simplifies the cache structure by omitting superblocks and columns, using contiguous base elements instead [S1]. It addresses the challenge of rendering very large CSVs that exceed GPU memory by streaming fine detail levels from CPU memory on demand [S1].
