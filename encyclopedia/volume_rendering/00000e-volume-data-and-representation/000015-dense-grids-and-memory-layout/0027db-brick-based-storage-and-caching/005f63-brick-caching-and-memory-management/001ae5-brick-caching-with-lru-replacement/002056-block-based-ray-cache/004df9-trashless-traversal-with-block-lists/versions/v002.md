# Trashless Traversal with Block Lists

Also called: Trashless Distribution Scheme

## Overview
Trashless Traversal with Block Lists is a cache optimization strategy for volume rendering that prevents cache trashing by ensuring evicted data is never accessed again [S1, unofficial]. It subdivides the volume into blocks, sorts them front-to-back, and organizes them into disjoint block lists so that no ray intersects more than one block per list [S1, unofficial]. This distinguishes it from standard traversal by decoupling block processing order from ray order, allowing parallel processing within lists while maintaining cache locality [S1, unofficial].

## How it works
**Inputs:** Volume dataset subdivided into blocks; viewing direction; ray origins and directions [S1, unofficial].
**Outputs:** Rendered image; updated ray states [G].

**Data Structures:**
1. **Block List:** A sequence of blocks sorted front-to-back [S1, unofficial].
2. **Ray List:** Associated with each block, containing rays whose current resample position lies within the brick [S1, unofficial].
3. **Global Address Lookup Table:** Shared by all blocks to map block IDs to memory addresses [S1, unofficial].

**Algorithm Steps:**
1. Subdivide the volume into blocks [S1, unofficial].
2. Sort blocks in front-to-back order based on the viewing direction [S1, unofficial].
3. Place blocks into block lists such that no ray intersecting one block in a list intersects another block in the same list [S1, unofficial].
4. For each ray, identify the first block it intersects and add it to that block's ray list [S1, unofficial].
5. Traverse blocks in front-to-back order by sequentially processing block lists [S1, unofficial].
6. Process blocks within a list in any order, including in parallel [S1, unofficial].
7. For each block, process all rays in its ray list [S1, unofficial].
8. If a ray leaves a block, remove it from the current ray list and add it to the new block's list [S1, unofficial].
9. Continue to the next block when the current block's ray list is empty [S1, unofficial].

**Pseudocode:**
```python
def trashless_traversal(blocks, rays, viewing_direction):
    # 1. Subdivide volume into blocks (assumed preprocessed)
    # 2. Sort blocks front-to-back based on viewing direction
    blocks.sort(key=lambda b: project_center(b, viewing_direction))
    # 3. Place blocks into block lists ensuring no ray intersects multiple blocks in the same list
    block_lists = distribute_blocks_to_lists(blocks)
    # 4. Initialize ray lists: each block holds a list of rays whose current resample position lies within the brick
    for block in blocks:
        block.ray_list = []
    for ray in rays:
        first_block = find_first_intersecting_block(ray, blocks)
        first_block.ray_list.append(ray)
    # 5. Traverse blocks in front-to-back order by sequentially processing block lists
    for block_list in block_lists:
        # 6. Blocks within one list can be processed in any order (e.g., parallel)
        for block in block_list:
            # 7. For each block, process all rays in its ray list
            current_rays = block.ray_list
            block.ray_list = []
            for ray in current_rays:
                # Perform volume sampling/raycasting for ray within block bounds
                sample_volume(ray, block)
                # 8. If a ray leaves a block, remove it from the current ray list and add it to the new block's list
                if ray.has_exited_block(block):
                    next_block = find_next_intersecting_block(ray, blocks)
                    next_block.ray_list.append(ray)
                # 9. Continue to next block when current block's ray list is empty
```

**Parameters:**
- **Brick Size:** Must be chosen appropriately to ensure a block entirely remains in a fast cache while its rays are being processed [S1, unofficial]. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Cache Trashing:** Avoided by ensuring data once replaced in cache is not required again, achieved by the specific construction of block lists where rays do not jump between blocks within the same list [S1, unofficial]. Not given in the sources.

## Operating characteristics
- **Time Complexity:** Not given in the sources.

- **Performance:** The approach significantly reduces cache misses by ensuring that a block entirely remains in a fast cache while its rays are being processed [S1, unofficial]. Not given in the sources.
- **Strengths:** Eliminates cache trashing; allows parallel processing of blocks within a list; practically requires no additional memory as all blocks share one global address lookup table [S1, unofficial].
- **Limitations:** Requires precomputation or per-frame sorting for the block lists [S1, unofficial]. Not given in the sources.

## Background
The method is based on the "trashless distribution scheme" presented by Law and Yagel [S1, unofficial]. Originally developed in the context of parallelization to avoid redundant distribution of data blocks over a network, it was adapted for single-processor cache optimization [S1, unofficial]. The approach is described in the context of efficient volume visualization of large medical datasets [S1, unofficial].
