# Spatial Coherence Ray Grouping

Also called: Package Ray Grouping, Pattern Attribution of Node Sets

## Overview
Spatial Coherence Ray Grouping exploits spatial coherence by grouping rays in packages in the image plane to collect node traversal information, reducing the amount of data sent to the CPU [S1, unofficial]. It unifies frustum containment, visibility, and Level-of-Detail (LOD) selection within the rendering kernel, taking all workload off the CPU [S1, unofficial]. It is a specific application of Ray Aggregation, which traces groups of rays as single units to leverage register SIMD capabilities [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Rays grouped into packages based on image plane coordinates [S1, unofficial].
*   **Output:** Rendered color for each ray, plus supplementary traversal data (node indices) required for cache updates [S1, unofficial].

**Data Structures:**
The core data structure is the **Ray Package** [S1, unofficial]. For a standard 2x2 package:
*   Contains 4 rays [S1, unofficial].
*   Each ray outputs a fixed-size list of 12 traversed node indices [S1, unofficial].
*   Total capacity per package: $4 \times 12 = 48$ node indices [S1, unofficial].

**Algorithm Steps:**
1.  **Grouping:** Divide the image plane into packages of size $P \times P$ (commonly $2 \times 2$) [S1, unofficial].
2.  **Traversal:** Trace all rays within a package [S1, unofficial]. Neighboring rays visit mostly similar nodes because a brick in a node projects onto several pixels [S1, unofficial].
3.  **Attribution:** Assign specific slots in the package's output buffer to specific rays based on their position within the package [S1, unofficial]. For a 2x2 package:
    *   Upper-left ray stores the first 12 node indices.
    *   Upper-right ray stores the second 12 node indices.
    *   Lower-left ray stores the third 12 node indices.
    *   Lower-right ray stores the fourth 12 node indices [S1, unofficial].
4.  **Supplementary Output:** Alongside the final color, each ray outputs its assigned node indices [S1, unofficial].
5.  **Aggregation:** The package outputs the combined traversal data (e.g., 48 indices) to be processed by the CPU for cache updates [S1, unofficial].

    """
    num_rays = len(rays)
    nodes_per_ray = 12  # Typical value from [S1, unofficial]
    total_nodes = num_rays * nodes_per_ray
    
    colors = []
    all_node_indices = []
    
    for i, ray in enumerate(rays):
        # Step 2: Traverse the volume structure for this ray

**Edge Cases and Pitfalls:**
*   **Transparency:** In transparent volumes, rays traverse many nodes, but the framebuffer can only output a limited amount of information per fragment, even with MRTs [S1, unofficial]. The fixed output size (e.g., 48 indices) is a constraint imposed by this framebuffer capacity limit [S1, unofficial].
*   **Precision:** Node indices must be packed efficiently to fit within the framebuffer limits [S1, unofficial].

## Subtopics

### Ray Aggregation (Packet Traversal)
A general strategy where a group of rays is traced as a single unit (a packet) to exploit spatial coherence [S2]. It is the most used strategy in current interactive systems [S2]. It allows the use of register SIMD to process four rays in a bundle and can be combined with frustum- and interval-arithmetic techniques to avoid traversal steps by exploiting conservative bounds of the ray group [S2]. It is used with k-dtrees and for primary eye rays, hard/soft shadow rays, and secondary rays [S2]. Spatial Coherence Ray Grouping is a specific application of this strategy tailored for volume data streaming [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Reduces CPU overhead by batching traversal data [S1, unofficial]. The GPU handles traversal and data collection, offloading workload from the CPU [S1, unofficial].
*   **Memory Complexity:** Requires additional buffer space for supplementary node indices per ray [S1, unofficial]. For a 2x2 package with 12 nodes/ray, this is 48 indices per package [S1, unofficial].
*   **Strengths:** Unifies visibility, frustum culling, and LOD selection in the kernel [S1, unofficial]. Significantly reduces data transfer between GPU and CPU for cache management [S1, unofficial].
*   **Limitations:** Fixed buffer sizes may truncate traversal history in highly transparent scenes due to framebuffer output limits [S1, unofficial].
*   **When to use:** When using GPU-Steered LRU Cache Management for brick-based volume rendering [S1, unofficial].

## Background
Originated in the context of "Ray-Guided Streaming" for efficient voxel rendering [S1, unofficial]. The key insight is that neighboring rays visit mostly similar nodes because a brick in a node projects onto several pixels [S1, unofficial]. This method was proposed to combine the rendering and visibility update phases, taking workload off the CPU [S1, unofficial]. It builds on the general concept of Ray Aggregation, which has been used in interactive systems with k-dtrees [S2].
