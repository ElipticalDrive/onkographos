# Ray Aggregation (Packet Traversal)
Also called: Packet Traversal, Ray Packet Traversal, Ray Packets

## Overview
Ray aggregation (packet traversal) is a traversal strategy that exploits spatial coherence by grouping neighboring rays into packets to be processed as a single unit, reducing redundant traversal and intersection tests [S2]. It distinguishes itself from beam tracing by maintaining explicit ray representations throughout the process, and from single-ray traversal by batching rays to leverage register-level SIMD execution [S2]. Trade-offs are detailed in Operating characteristics.

## How it works
**Inputs and Outputs**
- Input: A group of spatially coherent rays (a packet) and a scene hierarchy (e.g., k-dtree or grid) [S2].
- Output: Intersection points or traversal status for each ray in the packet.

**Data Structures**
Each packet stores the state of multiple rays, including origin coordinates, direction vectors, and current traversal state (e.g., current node index) [G]. The packet is processed as a single unit with conservative boundary checks [S1, unofficial].

**Steps**
1. Group rays into a spatial grid, typically 4x4, 8x8, or 16x16 pixel blocks [S1, unofficial].
2. Compute a conservative bounding volume (e.g., frustum or interval-arithmetic bounds) that encloses all rays in the packet [S2].
3. Traverse the scene hierarchy using the packet's bounding volume to skip nodes that do not intersect the entire packet [S2].
4. Process the rays within the packet using register-level SIMD instructions (e.g., processing four rays in a 128-bit bundle) [S2].
5. Perform intersection tests against primitives for the active rays [S2].
6. When rays in the packet diverge and intersect different nodes, fork the packet, compute exit points for individual rays, and trace each ray individually [S1, unofficial].

**Formulas**
Not given in the sources.

**Parameters**
- Packet grid sizes: 4x4, 8x8, or 16x16 [S1, unofficial].

**Edge Cases and Pitfalls**
- The speedup achieved depends strongly on the specific volume dataset being rendered [S1, unofficial].
- High ray divergence within a packet reduces SIMD efficiency and requires packet forking [S1, unofficial].

**Pseudocode**
```python
def trace_packet(packet, scene):
    while packet:
        bounds = compute_conservative_bounds(packet)  # [G]
        nodes = scene.traverse(bounds)                # [G]
        for node in nodes:
            if not node.intersects(bounds):
                continue
            hits = []
            for ray in packet:
                hit = ray.intersect(node)
                if hit:
                    hits.append((ray, hit))
            if len(hits) != len(packet):
                # Rays diverged into different nodes
                for ray, hit in hits:
                    ray.t_min = hit.t  # Compute exit point / update state
                trace_packet(hits, scene)
                remaining = [r for r in packet if r not in hits]
                trace_packet(remaining, scene)
                return
            packet = hits
```

## Operating characteristics
- **Time Complexity**: Reduces the number of intersection tests and traversal steps by exploiting spatial coherence [S2].
- **Memory Complexity**: Not given in the sources.
- **Performance**: Highly effective for primary eye rays, hard shadow rays, soft shadow rays, and secondary rays in interactive systems [S2].
- **Strengths**: Enables register-level SIMD optimization (e.g., four rays in a bundle), reduces traversal overhead, and is the most widely used coherence strategy in current interactive systems [S2].
- **Limitations**: Performance degrades with high ray divergence; speedup depends strongly on the specific volume dataset [S1, unofficial].

## Background
Ray aggregation was introduced by Ingo Wald in 2004 in the work 'Interactive Distributed Ray Tracing' as a first step into realtime parallelization of ray tracing [S1, unofficial]. It is particularly effective in grid-based and k-dtree-based rendering systems, and is widely adopted in interactive ray tracing due to its compatibility with SIMD hardware and its ability to handle various ray types efficiently [S2].
