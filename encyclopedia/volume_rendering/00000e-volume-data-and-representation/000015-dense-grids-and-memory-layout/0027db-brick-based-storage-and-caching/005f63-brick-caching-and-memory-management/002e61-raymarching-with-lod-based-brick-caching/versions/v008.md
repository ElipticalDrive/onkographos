# Raymarching with LOD-based Brick Caching

Also called: Brick Caching and Decoding, Compressed Segmentation Volume (CSV) Visualization

## Overview
This method renders Compressed Segmentation Volumes (CSVs) by raymarching with one ray per pixel, decompressing bricks on-demand at the required Level of Detail (LOD), and storing them in a GPU cache [S1]. It differs from its siblings by exploiting temporal coherency with a one-frame decompression lag, using palette-based empty-space skipping before cache allocation, and employing a contiguous base-element cache structure that omits the superblock and column concepts found in Shading Atlas Streaming (SAS) [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Compressed Segmentation Volume (CSV) data, Transfer Function (TF), camera parameters, and a user-defined opacity threshold for shadow rays [S1].
*   **Output:** Rendered image frame [S1].

**Data Structures:**
1.  **CSV Data:** Partitioned into uniform 3D bricks [S1]. Each brick has a compressed representation consisting of a palette and data [S1]. The palette contains labels with associated opacity values [S1].
2.  **Cache Pool:** A pool of base elements, each of size $2^3$ voxels [S1].
3.  **Cache Stacks:** One stack $S_l$ per LOD level $l$ ($l=0..N$) [S1]. Each stack stores indices of free blocks of size $2^{3l}$ [S1].
4.  **Cache Top Pointer:** A shared atomic pointer to the next available base element in the pool [S1].
5.  **Request Buffer:** A buffer storing brick indices requiring fine detail data for CPU-to-GPU upload [S1].

**Parameters:**
*   **LOD Selection:** The LOD for a brick is determined by the distance of the brick's center to the camera, targeting approximately one voxel per pixel on the screen [S1].
*   **Upload Buffer Size:** 8 MB buffer for uploading requested detail level data to the GPU [S1].

**Algorithm Steps:**

1.  **Raymarching and LOD Determination:** For each pixel, cast a ray [S1]. For every visible brick intersected by the ray, determine the required LOD based on the distance from the brick's center to the camera [S1].
2.  **Empty-Space Skipping:** Check the brick's palette [S1]. If none of the palette entries are mapped to an opacity greater than 0, skip the entire brick [S1].
3.  **Cache Request (One-Frame Lag):** If the required LOD is not in the cache, request it for the *next* frame [S1]. Allow a one-frame lag [S1]. If the brick is not yet decompressed in the next frame, fall back to the coarsest LOD (stored as the first palette entry, directly accessible) [S1].
4.  **Shadow Rays:** For hit voxels above the user-defined opacity threshold, send an additional shadow ray [S1]. Optionally, approximate ambient occlusion by accumulating shadow rays over time [S1].
5.  **Cache Assignment (Post-Frame):** After rendering a frame, determine the required bricks and LODs for the next frame [S1]. Test visibility against the TF [S1]. Mark visible bricks with ascending indices (one sequence per block size) [S1]. Count the number of bricks needed per LOD level [S1]. Evict invisible bricks from the cache [S1]. Push their blocks onto the respective stacks $S_l$ [S1]. Check if each stack $S_l$ has enough free blocks to fulfill the requests for level $l$ [S1]. If stacks are insufficient, allocate new blocks by atomically advancing the shared cache top pointer by $l$ (forming a block of size $2^{3l}$ from contiguous base elements) [S1]. If no free base elements are available, rebuild the cache: clear all blocks and stacks, and re-decompress all visible bricks [S1].
6.  **Decompression:** Decompress the requested bricks in parallel on the GPU and store the results in the assigned cache locations [S1].
7.  **Detail Separation (Optional):** If the CSV is too large for GPU memory, store coarse LOD data (palette and data) on the GPU and fine LOD data in CPU memory [S1]. During cache assignment, identify bricks needing fine detail levels [S1]. Add their indices to a request buffer [S1]. Transfer the buffer to CPU memory after assignment [S1]. Generate a buffer of requested detail levels in parallel to rendering the next frame and asynchronously upload it to GPU memory [S1]. Handle the one-frame lag for detail upload by either decompressing only up to the finest available GPU level or predictively uploading data for bricks close to the camera [S1]. Discard fine detail data once the brick is decompressed and cached [S1].

# Global State

cache_stacks = [[] for _ in range(N + 1)]
gpu_csv = {}
cpu_csv = {}

next_frame_requests = []

def render_frame(camera, tf, opacity_threshold):
    # 1. Raymarching & LOD Determination
    for pixel in range(num_pixels):
        ray = compute_ray_from_pixel(pixel, camera)
        for brick in intersect_bricks(ray):
            # 2. Empty-Space Skipping
            if not any(tf.get_opacity(label) > 0 for label in brick.palette):
                continue
            # 3. LOD Determination
            lod = compute_lod_from_distance(brick.center_to(camera.position))
            # 4. Cache Check & One-Frame Lag
            if lod not in brick.cached_lods:
                next_frame_requests.append((brick, lod))
                lod = 0 # Fall back to coarsest LOD (first palette entry)
            render_voxel(brick.cached_lods[lod], ray)
            # 5. Shadow Rays
            if get_voxel_opacity() > opacity_threshold:
                shadow_ray = compute_shadow_ray(ray)
                accumulate_ambient_occlusion(shadow_ray)
    # 6. Cache Assignment for Next Frame
    assign_cache(tf)

def assign_cache(tf):
    global cache_pool_top
    visible_bricks = [b for b, _ in next_frame_requests if is_visible(b, tf)]
    # Evict invisible bricks
    for brick in current_cache_bricks:
        if brick not in visible_bricks:
            cache_stacks[brick.lod].append(brick.block_index)
            brick.block_index = None
    # Count bricks per LOD
    lod_counts = count_bricks_per_lod(visible_bricks)
    # Allocate cache blocks
    for lod, count in lod_counts.items():
        free_blocks = len(cache_stacks[lod])
        needed = count - free_blocks
        if needed > 0:
            allocated = allocate_from_pool(lod, needed)
            if allocated < needed:
                rebuild_cache(visible_bricks)
                return
    # Decompress in parallel
    decompress_bricks_in_parallel(visible_bricks)
    # Detail Separation
    if use_detail_separation:
        upload_fine_details(visible_bricks)

def allocate_from_pool(lod, count):
    global cache_pool_top
    base_elements_per_block = 2**(3 * (lod - 1)) if lod > 0 else 1
    allocated = 0
    for _ in range(count):
        start = atomic_add(cache_pool_top, base_elements_per_block)
        if start + base_elements_per_block > cache_pool_size:
            break
        allocated += 1
    return allocated

def rebuild_cache(visible_bricks):
    global cache_pool_top, cache_stacks
    cache_stacks = [[] for _ in range(N + 1)]
    cache_pool_top = 0
    decompress_bricks_in_parallel(visible_bricks)

def upload_fine_details(visible_bricks):
    global request_buffer
    request_buffer = [b.index for b in visible_bricks if needs_fine_detail(b)]
    cpu_buffer = transfer_to_cpu(request_buffer)
    async_upload_to_gpu(cpu_buffer)

## Operating characteristics
*   The one-frame lag for decompression and detail upload can cause artifacts if the frame rate is low, but is typically small at reasonable frame rates [S1].
*   The 8 MB upload buffer is sufficient in most frames; if insufficient, upload is distributed across several frames, trading LOD adaptation for responsivity [S1].
*   For the CORTEX dataset (6144x9216x4096), the finest LOD (L0) consumes 9.2 GB, while all other levels take 4.3 GB [S1].
*   The method allows storing coarse LODs on GPU and fine LODs on CPU, reducing GPU memory pressure [S1].
*   Empty-space skipping reduces unnecessary decompression [S1].
*   Cache rebuilds are expensive but rare [S1].

## Background
This method was introduced in the context of Fast Compressed Segmentation Volumes for Scientific Visualization [S1]. It builds on the principles of Shading Atlas Streaming (SAS) but simplifies the cache structure by omitting superblocks and columns, using contiguous base elements instead [S1]. It is designed for large-scale scientific visualization where memory bandwidth and capacity are bottlenecks [S1].
