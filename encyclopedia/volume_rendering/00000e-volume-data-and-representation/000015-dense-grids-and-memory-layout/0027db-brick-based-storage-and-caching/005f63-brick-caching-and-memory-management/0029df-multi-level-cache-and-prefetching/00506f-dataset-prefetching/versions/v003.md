# Dataset Prefetching

Also called: Asynchronous Data Loading, Dataset.run

## Overview
Dataset Prefetching runs a background thread to prefetch batches into a queue for asynchronous data loading [S1, unofficial]. It decouples data retrieval from the rendering loop, differing from sibling methods that focus on spatial caching hierarchies (e.g., [VxlSlabColumn Priority Cache](4742-vxlslabcolumn-priority-cache.md) or [Rolling 3-Row Slab Cache](4747-rolling-3-row-slab-cache.md)) by focusing on temporal overlap of I/O and computation [S1, unofficial].

## How it works
**Inputs:** A dataset object providing iteration methods (`_next_train` or `_next_test`) [S1, unofficial].
**Outputs:** A queue containing pre-fetched data batches [S1, unofficial].

**Data Structures:**
1. **Prefetch Queue:** A thread-safe FIFO queue with a fixed capacity of 3 [S1, unofficial].

**Steps:**
1. Initialize the prefetch queue with a capacity of 3 [S1, unofficial].
2. Start a background thread in daemon mode [S1, unofficial].
3. Enter an infinite loop that calls the appropriate next function (`_next_train` or `_next_test`) and puts the result into the queue [S1, unofficial].

**Pseudocode:**
```python
import queue
import threading

class DatasetPrefetcher:
    def __init__(self, dataset, next_fn):
        self.dataset = dataset
        self.next_fn = next_fn
        self.queue = queue.Queue(maxsize=3)  # [S1, unofficial]
        self.thread = None
        self.running = False

    def _prefetch_loop(self):
        while self.running:
            # [S1, unofficial] Call appropriate next function
            batch = self.next_fn()
            self.queue.put(batch)  # [S1, unofficial]

    def start(self):
        self.running = True
        self.thread = threading.Thread(target=self._prefetch_loop, daemon=True)  # [S1, unofficial]
        self.thread.start()

    def get_batch(self):
        return self.queue.get()  # [G]
```

**Parameters:**
* **Queue Size:** 3 [S1, unofficial].
* **Thread Mode:** Daemon [S1, unofficial].

## Subtopics

### DHCS (Distributed Hierarchical Cache System) Asynchronous Overlap
This variant extends asynchronous prefetching to distributed volume rendering [S2]. It launches all asynchronous data loads for the current frame [S2]. It determines the local memory state at the end of the current frame (when data loads are achieved) [S2]. It launches binary all-to-all communication overlapped with the rendering of the volume renderer [S2]. It renders the first bricks even if all requests are not yet satisfied [S2]. A sequential implementation with synchronous (blocking) requests decreases performance because data loading, cache state update, volume slicing, and rendering are executed serially [S2].

## Background
The method is documented in the CaSE-NeRF project [S1, unofficial]. The principle of overlapping data loading with rendering to avoid serial execution penalties is also described in the context of distributed shared memory systems for large volumes, such as DHCS [S2].
