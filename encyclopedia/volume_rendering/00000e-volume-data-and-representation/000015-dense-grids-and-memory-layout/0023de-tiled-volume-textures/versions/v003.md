# Tiled Volume Textures

Also called: 3D Tiled Resources, 3D Tiled Textures, D3D11.3 Tiled Resource APIs, Volume (3D) textures as tiled resources, Volume Tiled Resources

## Overview
Tiled Volume Textures are a Direct3D 11.3/12 hardware feature that decouples a 3D texture resource object from its backing memory, enabling virtual addressing for high-resolution volume data [S1, unofficial][S2][S3]. This allows the GPU to stream texture data and maintain performance by loading only a subset of the volume onto the GPU at any given time, addressing memory capacity limits while preserving the filtering and sampling capabilities of 3D textures [S1, unofficial][S2][S3]. Unlike software-managed virtual texturing (e.g., id Tech 5), which requires the CPU to manage all page mappings and incur significant overhead, tiled resources offload the virtual-to-physical mapping to the hardware, reducing CPU workload [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A logical 3D texture resource (defined by dimensions, format, and mip levels) and a backing memory heap [S2][S3].
*   **Output:** A mapped resource where specific 3D tiles within the logical texture are bound to physical memory locations in the heap, or marked as NULL (unmapped) [S2][S3].

**Data Structures:**
The method relies on specific Direct3D structures to define the mapping [S2][S3]. The exact layouts are:

1.  **`D3D12_TILED_RESOURCE_COORDINATE`** (or `D3D11_TILED_RESOURCE_COORDINATE`): Holds the $x$, $y$, and $z$ coordinates and subresource reference [S2][S3].
    *   `UINT X`: X-coordinate of the tile in the resource.
    *   `UINT Y`: Y-coordinate of the tile in the resource.
    *   `UINT Z`: Z-coordinate of the tile in the resource.
    *   `UINT Subresource`: Index of the mip level or array slice.
2.  **`D3D12_TILE_REGION_SIZE`** (or `D3D11_TILE_REGION_SIZE`): Specifies the size and number of tiles of the tiled region [S2][S3].
    *   `UINT NumTiles`: Total number of tiles in the region.
    *   `UINT Width`: Width of the region in tiles (used if `bUseBox` is true).
    *   `UINT Height`: Height of the region in tiles (used if `bUseBox` is true).
    *   `UINT Depth`: Depth of the region in tiles (used if `bUseBox` is true).
    *   `BOOL bUseBox`: If true, `Width`, `Height`, and `Depth` define a rectangular box of tiles; if false, `NumTiles` defines a linear sequence of tiles starting from the coordinate [S2][S3].
3.  **`D3D12_TILE_SHAPE`** (or `D3D11_TILE_SHAPE`): Defines the tile shape as width, height, and depth in texels [S2][S3].
    *   `UINT WidthInTexels`: Width of the tile.
    *   `UINT HeightInTexels`: Height of the tile.
    *   `UINT DepthInTexels`: Depth of the tile.

**Tile Dimensions:**
The physical size of a tile (in texels) depends on the texture's bits-per-pixel (bpp) for 1 sample/pixel formats [S2][S3]. The standard tile dimensions are:

| Bits/pixel | Tile Dimensions (w x h x d) |
| :--- | :--- |
| 8 | 64 x 32 x 32 |
| 16 | 32 x 32 x 32 |
| 32 | 32 x 32 x 16 |
| 64 | 32 x 16 x 16 |
| 128 | 16 x 16 x 16 |
| BC1, BC4 | 128 x 64 x 16 |
| BC2, BC3, BC5, BC6, BC7 | 64 x 64 x 16 |

**Numbered Steps:**

1.  **Check Feature Support:** Query the device to determine if volume tiled resources are supported [S2][S3]. Call `ID3D12Device::CheckFeatureSupport` with `D3D12_FEATURE_DATA_D3D12_OPTIONS` to determine the supported tile resource tier level and whether `VolumeTiledResourcesSupported` is true [S3]. (For Direct3D 11, use `D3D11_FEATURE_DATA_D3D11_OPTIONS1` and `D3D11_TILED_RESOURCES_TIER` [S2]).
2.  **Create Resource and Heap:** Create a 3D texture resource and a backing memory heap [S2][S3]. The resource is decoupled from the heap, allowing memory reuse and streaming [S2][S3].
3.  **Map Tiles to Memory:** Construct a list of tile mappings specifying the tiled resource, the coordinate structure, the backing heap, the heap offset, the number of tiles, and mapping flags [S3]. Call `ID3D12CommandQueue::UpdateTileMappings` to update the mappings of tile locations in the tiled resource to memory locations in the resource heap [S3].
4.  **Copy Data to Tiles:** Prepare a source buffer containing the volume data [S3]. Call `ID3D12GraphicsCommandList::CopyTiles` to copy tiles from the buffer to the tiled resource or vice versa [S3].
5.  **Handle NULL Tiles:** Mark blocks of the texture as unused to maintain sparseness similar to Sparse Voxel Octrees (SVOs) [S1, unofficial]. To mark a tile as unused, call `UpdateTileMappings` with the appropriate flags indicating no backing memory reservation [S3].

**Pseudocode:**

```python
def setup_volume_tiled_resource(device, command_queue, command_list, texture_desc, heap_desc, source_buffer, active_tile_indices):
    """
    Sets up a 3D tiled resource and maps active tiles to the backing heap.
    """
    # 1. Check feature support
    feature_data = check_feature_support(device, "D3D12_FEATURE_D3D12_OPTIONS")
    if not feature_data.VolumeTiledResourcesSupported:
        raise RuntimeError("Volume Tiled Resources not supported")
    
    # 2. Create the 3D texture resource and backing heap
    texture = create_resource(device, texture_desc)
    heap = create_heap(device, heap_desc)
    
    # 3. Get tile shape and size
    tiling_info = get_resource_tiling(device, texture)
    tile_shape = tiling_info.TileShape
    bytes_per_texel = get_bytes_per_texel(texture_desc.Format)
    tile_size_bytes = tile_shape.WidthInTexels * tile_shape.HeightInTexels * tile_shape.DepthInTexels * bytes_per_texel
    
    # 4. Prepare and update tile mappings
    num_active_tiles = len(active_tile_indices)
    if num_active_tiles == 0:
        return

    mapping = {
        "TiledResource": texture,
        "TiledResourceCoordinate": {"X": 0, "Y": 0, "Z": 0, "Subresource": 0},
        "Heap": heap,
        "HeapOffset": 0,
        "NumTiles": num_active_tiles,
        "Flags": "D3D12_TILE_MAPPING_NO_HOLE"
    }
    
    update_tile_mappings(command_queue, [mapping], None)
    
    # 5. Copy data to the tiled resource
    copy_desc = {
        "SourceBuffer": source_buffer,
        "SourceOffset": 0,
        "TiledResource": texture,
        "TiledResourceCoordinate": {"X": 0, "Y": 0, "Z": 0, "Subresource": 0},
        "TileRegionSize": {"NumTiles": num_active_tiles, "bUseBox": False},
        "Flags": "D3D12_TILE_COPY_NONE"
    }
    
    copy_tiles(command_list, copy_desc)
    command_list.close()
    command_queue.execute_command_lists([command_list])
```

**Edge Cases and Pitfalls:**
*   **Dynamic Object Latency:** Dynamic objects must flag bricks to the CPU, which takes a few frames to process, meaning dynamic objects may not be fully voxelized across brick bounds immediately [S1, unofficial].
*   **Unsupported Formats:** Tiled resources do not support 96bpp formats, video formats, `R1_UNORM`, `R8G8_B8G8_UNORM`, or `R8R8_G8B8_UNORM` [S2][S3].
*   **CPU Overhead:** While hardware-managed, the CPU must still manage the mapping of tiles in the volume texture, including marking blocks as unused to maintain sparseness [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Mapping tiles is an API call ($O(1)$ per call, but $O(N)$ for $N$ tiles). Copying data is $O(N)$ where $N$ is the number of texels. Sampling is $O(1)$ per sample, with hardware handling the virtual-to-physical translation [G].
*   **Memory Complexity:** Memory usage is proportional to the number of *active* tiles, not the total volume size. This allows for high-resolution volumes to be stored with low GPU memory footprint [S1, unofficial][S2].
*   **Performance:** Maintains high performance by leveraging hardware virtual addressing, avoiding the CPU overhead of software-managed virtual texturing [S1, unofficial].
*   **Strengths:** Efficient memory usage for sparse or large volumes; hardware-accelerated sampling and filtering; reduced CPU overhead compared to software solutions [S1, unofficial][S2].
*   **Limitations:** Requires Direct3D 11.3/12 hardware support; CPU still manages tile mappings; dynamic updates have latency due to CPU-GPU synchronization [S1, unofficial][S2].
*   **When to use:** When rendering large, sparse 3D volumes on Direct3D 11.3/12 hardware where memory is a constraint, and some latency in dynamic updates is acceptable [S1, unofficial][S2].
*   **When not to use:** On hardware without tiled resource support; when real-time, frame-accurate dynamic updates are critical without latency; when using unsupported formats [S2][S3].

## Background
Tiled resources were first introduced in DirectX 11.2 (Windows 8.1) for 2D textures [S2][S3]. Volume (3D) tiled resources were added in Direct3D 11.3 and Direct3D 12 [S1, unofficial][S2][S3]. The feature targets memory issues in high-resolution 3D texture rendering by allowing only part of the texture to be loaded onto the GPU at any given time [S1, unofficial]. It is similar to the virtual texturing used in id Tech 5 (Rage), but leverages hardware virtual addressing to reduce the CPU overhead associated with manual page management [S1, unofficial]. It is used in voxel-based rendering techniques, such as Voxel Cone Traced Global Illumination, to manage large voxel grids efficiently [S1, unofficial].
