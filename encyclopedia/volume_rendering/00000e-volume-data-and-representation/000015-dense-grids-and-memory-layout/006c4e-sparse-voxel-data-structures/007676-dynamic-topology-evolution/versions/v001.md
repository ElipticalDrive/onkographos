# Dynamic Topology Evolution

Also called: Bulk-Synchronous Topological Evolution, Bulk-synchronous topology evolution, Dynamic GPU Sparse Grids, NanoVDB dynamic topology updates, NanoVDB Dynamic Topology Operators

## Overview
Dynamic Topology Evolution is a suite of bulk-synchronous operators that enable topological changes (morphological dilation, grid merging, pruning, and cross-resolution coarsening/refinement) on NanoVDB's linearized index-grids, eliminating the static, read-only constraint of prior NanoVDB versions [S1, unofficial]. Unlike [OpenVDB](21071-sparse-voxel-data-structures.md) which relies on fine-grained heap allocation and pointer-heavy nodes for dynamic topology, this method uses a linearized memory layout with relative addressing and bit-parallel algorithms for GPU throughput [S1, unofficial]. It solves the problem of efficiently evolving the topological domain of active voxels in sparse grids for simulation and dynamic geometric processes, targeting reconstruction of trees with hundreds of millions of voxels in a few milliseconds [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** One or more source NanoVDB Index-Grids (topology-only structures). For merging, two grids. For pruning/dilation, one grid plus an optional mask.
*   **Output:** A new NanoVDB Index-Grid with updated topology. The data payload (sidecar) is handled separately by [Injection and Sidecar Operators](#injection-and-sidecar-operators).

**Data Structures:**
*   **Index-Grid:** Stores only topology. Root tiles span $4096^3$ voxels. Upper tree nodes (children of root) span $128^3$ voxels. Leaf nodes span $8$ voxels [S1, unofficial].
*   **Scratchpad Structures (Bit-encoded):**
    *   `upperMasks`: Array of `Mask<5>` bitmaps ($32^3$ bits each) for upper level nodes. Footprint: 4 KB per candidate root tile [S1, unofficial].
    *   `lowerMasks`: 2D array of $32^3$ `Mask<4>` entries per root tile, indexed by parent tile ID and local linear offset of child node. Footprint: 16 MB per candidate root tile [S1, unofficial].
*   **Count Arrays (for Prefix Sums):**
    *   `upperCounts`: Size $N_{tiles}$. Value is 1 if $i$-th upper node has any active lower node children, else 0 [S1, unofficial].
    *   `lowerCounts`: Size $N_{tiles} \times 32K$. Value is 1 if $i$-th lower node has any active leaf node children, else 0 [S1, unofficial].
    *   `leafCounts`: Size $N_{tiles} \times 32K$. Value is the number of leaf node children of the $i$-th lower node (popcount of the lower node's childMask) [S1, unofficial].

**Parameters:**
*   **Operators:**
    1.  **Morphological Dilation:** Expands active voxel set into immediate neighborhood [S1, unofficial].
    2.  **Pruning:** Removes voxels based on input mask [S1, unofficial].
    3.  **Merging:** Boolean union of two Index-Grids [S1, unofficial].
    4.  **Coarsening:** Downsamples by 2:1 ratio per axis (8:1 volumetric reduction) [S1, unofficial].
    5.  **Refinement:** Adjoint of coarsening, upsamples by 2:1 ratio [S1, unofficial].
*   **Performance Target:** Reconstruct trees with hundreds of millions of voxels in a few milliseconds [S1, unofficial].

**Algorithm Steps:**
The method adopts a bulk-synchronous manipulation paradigm where topological changes are enacted collectively in discrete epochs [S1, unofficial].

1.  **Root Tile Pre-processing (Op-specific, CPU):** Construct a conservative envelope of candidate root tiles.
    *   For **Merging**: Take union of all input root tiles.
    *   For **Pruning**: Retain existing set.
    *   For **Dilation/Coarsening/Refinement**: Analyze index-space bounding box of existing tiles and instantiate candidate neighbors where operation may trigger spatial expansion.
    *   *Note:* These operations run on CPU as the root table is a minuscule fraction of total memory [S1, unofficial].

2.  **Scratchpad Allocation (Generic, GPU):** Allocate `upperMasks` and `lowerMasks` to enumerate result tree nodes precisely. These store sequentially all `childMask` bitmaps at the two internal levels of the tree [S1, unofficial].

3.  **Hierarchical Mask Marking (Op-specific, GPU):** Evaluate input topology in parallel to determine which leaf nodes must exist in the output epoch.
    *   For **Merging**: Active leaf in either input mandates inclusion.
    *   For **Pruning**: Leaf persists if any of its active voxels remain after mask application.
    *   Mark necessary leaf nodes and lower node parents in scratchpad bitmaps using `atomicOr` reductions [S1, unofficial].

4.  **Prefix Sums and Allocation (Generic, GPU):** Resolve final hierarchical counts through parallel prefix sums (using NVIDIA CUB library) on `upperCounts`, `lowerCounts`, and `leafCounts`. Compute inclusive prefix sums. Use terminal element of each offset array to get total number of nodes at that level. Perform single monolithic allocation for entire tree structure [S1, unofficial].

5.  **Structural Reconnection (Generic, GPU):** Each thread for a node in scratchpad uses corresponding prefix sum from offsets arrays to resolve absolute address in destination buffer. Perform final pruning at root level: candidate tile is written to final `tileTable` only if its entry in offset array indicates it is non-empty. Update relative child pointers by sampling starting offset of children's range from next level's offset array [S1, unofficial].

6.  **Operator-Specific Voxel Population (Op-specific, GPU):** Populate leaf-level voxel masks (`valueMask`).
    *   For **Merging/Pruning**: Threads perform bitwise OR or AND operations between input grids and masks, writing directly to new leaf nodes.
    *   For **Coarsening/Refinement**: Perform structured 2:1 bit-permutations to downsample/upsample occupancy patterns.
    *   *Note:* Dilation logic is more complex and involves bit-parallel neighborhood expansion [S1, unofficial].

7.  **Topological Post-Processing (Generic, GPU):** Compute final prefix sum across newly populated leaf bit-masks to assign unique voxel offset to every leaf node. This count provides total active voxel population and defines size of linearized data sidecar. Parallel reduction updates index-space bounding boxes and computes grid checksum [S1, unofficial].

**Pseudocode:**
```python
def dynamic_topology_evolution(source_grids, operation, mask=None):
    """
    Evolves NanoVDB topology using bulk-synchronous operators.
    source_grids: List of Index-Grids.
    operation: 'dilation', 'pruning', 'merging', 'coarsening', 'refinement'.
    mask: Optional mask grid for pruning.
    """
    # Step 1: Root Tile Pre-processing (CPU)
    candidate_tiles = []
    if operation == 'merging':
        candidate_tiles = union(source_grids[0].root_tiles, source_grids[1].root_tiles)
    elif operation == 'pruning':
        candidate_tiles = source_grids[0].root_tiles
    elif operation in ['dilation', 'coarsening', 'refinement']:
        for tile in source_grids[0].root_tiles:
            bbox = tile.bounding_box
            # Instantiate candidate neighbors where operation may trigger expansion
            candidate_tiles.extend(instantiate_candidate_neighbors(bbox, operation))
    
    # Step 2: Scratchpad Allocation (GPU)
    # Allocate upperMasks (Mask<5>) and lowerMasks (Mask<4>)
    upper_masks = allocate_scratchpad_upper(candidate_tiles)
    lower_masks = allocate_scratchpad_lower(candidate_tiles)
    
    # Step 3: Hierarchical Mask Marking (GPU)
    # Parallel evaluation of input topology
    for tile in candidate_tiles:
        # Determine which leaf nodes must exist
        if operation == 'merging':
            # Active leaf in either input mandates inclusion
            mark_leaves_merging(tile, source_grids[0], source_grids[1], upper_masks, lower_masks)
        elif operation == 'pruning':
            # Leaf persists if any active voxels remain after mask application
            mark_leaves_pruning(tile, source_grids[0], mask, upper_masks, lower_masks)
        elif operation == 'dilation':
            # Complex bit-parallel neighborhood expansion
            mark_leaves_dilation(tile, source_grids[0], upper_masks, lower_masks)
        # Coarsening/Refinement follow similar marking logic based on resolution change
        
    # Step 4: Prefix Sums and Allocation (GPU)
    # Compute counts
    upper_counts = compute_upper_counts(upper_masks)
    lower_counts = compute_lower_counts(lower_masks)
    leaf_counts = compute_leaf_counts(lower_masks)
    
    # Parallel prefix sums (e.g., using CUB)
    upper_offsets = inclusive_prefix_sum(upper_counts)
    lower_offsets = inclusive_prefix_sum(lower_counts)
    leaf_offsets = inclusive_prefix_sum(leaf_counts)
    
    # Monolithic allocation
    total_upper = upper_offsets[-1]
    total_lower = lower_offsets[-1]
    total_leaves = leaf_offsets[-1]
    dest_buffer = allocate_monolithic_tree(total_upper, total_lower, total_leaves)
    
    # Step 5: Structural Reconnection (GPU)
    # Wire parent-child relationships
    for node in scratchpad_nodes:
        abs_addr = resolve_address(node, upper_offsets, lower_offsets, leaf_offsets)
        dest_buffer[node.id] = abs_addr
        
    # Final root pruning
    final_tile_table = []
    for i, tile in enumerate(candidate_tiles):
        if upper_offsets[i] != upper_offsets[i+1] if i+1 < len(upper_offsets) else True:
            final_tile_table.append(tile)
            
    # Update relative child pointers
    for node in dest_buffer.internal_nodes:
        node.child_ptr = sample_offset_from_next_level(node, lower_offsets, leaf_offsets)
        
    # Step 6: Operator-Specific Voxel Population (GPU)
    for leaf in dest_buffer.leaves:
        if operation in ['merging', 'pruning']:
            # Bitwise OR/AND between input grids and masks
            leaf.value_mask = apply_bitwise_op(source_grids, mask, operation)
        elif operation in ['coarsening', 'refinement']:
            # Structured 2:1 bit-permutations
            leaf.value_mask = apply_bit_permutation(source_grids, operation)
        elif operation == 'dilation':
            leaf.value_mask = apply_dilation_mask(source_grids[0])
            
    # Step 7: Topological Post-Processing (GPU)
    # Final prefix sum for voxel offsets
    voxel_offsets = inclusive_prefix_sum(leaf.value_masks)
    total_active_voxels = voxel_offsets[-1]
    
    # Update bounding boxes and checksum
    bounding_box = parallel_reduce_bounding_box(dest_buffer)
    checksum = compute_checksum(dest_buffer, voxel_offsets)
    
    return IndexGrid(final_tile_table, dest_buffer, voxel_offsets, bounding_box, checksum)
```

## Subtopics

### Injection and Sidecar Operators
A suite of operators for the efficient integration and evolution of auxiliary sidecar payloads alongside the primary topology [S1, unofficial]. Used in MeshToGrid implementation to store UDF values in a sidecar alongside a sparse index grid [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Reconstructs trees with hundreds of millions of voxels in a few milliseconds [S1, unofficial].
*   **Memory Complexity:** Scratchpad footprint is modest: 4 KB for `upperMasks` and 16 MB for `lowerMasks` per candidate root tile [S1, unofficial]. Since a single root tile covers $4096^3$ voxels, practical grids rarely exceed a few dozen tiles. Once a tile's occupancy exceeds 0.01%, the footprint of a single scalar float channel already outweighs these temporary bookkeeping structures [S1, unofficial].
*   **Strengths:** High throughput on GPU via bit-parallel algorithms and linearized memory layout. Eliminates heap allocation overhead. Suitable for simulation and dynamic geometric processes [S1, unofficial].
*   **Limitations:** Bulk-synchronous model requires discrete epochs; not suitable for fine-grained, per-voxel dynamic updates without restructuring. Root tile pre-processing runs on CPU, which may be a bottleneck for extremely large tile counts (though rare) [S1, unofficial].
*   **When to use:** When dynamic topology changes (dilation, pruning, merging) are required in GPU-accelerated volume rendering or simulation using NanoVDB.
*   **When not to use:** When static topology is sufficient (use standard NanoVDB) or when fine-grained, pointer-based dynamic updates are preferred over bulk rewrites (use OpenVDB) [S1, unofficial].

## Background
Dynamic Topology Evolution was introduced by Eftychios Sifakis, Francis Williams, Christopher Horvath, Rohan Sawhney, and Mark Harris at NVIDIA [S1, unofficial]. It addresses the limitation of prior NanoVDB versions which assumed a static topology, precluding use in simulation and dynamic geometric processes [S1, unofficial]. The method builds on the linearized memory layout of NanoVDB [Museth 2021] and Index-Grids [Williams et al. 2024] [S1, unofficial].
