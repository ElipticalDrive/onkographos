# Redshift Volume Object

Also called: Redshift VDB Loader, Redshift Volume Rendering Objects

## Overview
The Redshift Volume Object is a scene container that loads heterogeneous volumetric data (varying density such as clouds, smoke, fire, or explosions) from VDB files or animated VDB sequences [S1, unofficial][S2]. It serves as the geometric proxy for sparse voxel data, distinct from homogeneous media handled by the Redshift Environment object or procedural skies generated by the Clouds object [S1, unofficial][S2]. While the parent article [VDB Data Loading & 3D Texture Setup](4880-vdb-data-loading-3d-texture-setup.md) details the low-level parsing of VDB binary formats and 3D texture uploads, the Redshift Volume Object provides the high-level scene integration, viewport preview, and material binding interface.

## How it works
**Inputs and Outputs:**
*   **Input:** A VDB file path (static) or a sequence of VDB files (animated).
*   **Output:** A scene node containing the volumetric bounds and data reference, rendered using the attached Standard Volume material.

**Data Structures:**
The object relies on the sparse voxel structure parsed by the parent method. It does not store dense grids itself but references the loaded VDB data. The viewport preview is rendered as either a bounding box or a point cloud representation of the loaded data [S1, unofficial][S2].

**Steps:**
1.  **Load Data:** The object reads the VDB file header and sparse voxel coordinates. If an animated sequence is provided, it loads the frame sequence [S1, unofficial][S2].
2.  **Compute Bounds:** The object calculates the bounding box enclosing all non-empty voxels in the loaded data [S1, unofficial][S2].
3.  **Viewport Preview:** The viewport displays either the computed bounding box or a point cloud preview of the voxel centers to aid in scene composition [S1, unofficial][S2].
4.  **Material Binding:** The visual appearance (scattering, absorption, emission) is defined by assigning a Standard Volume material to the object [S1, unofficial].
5.  **Rendering:** During ray traversal, the renderer samples the VDB data referenced by the object, modulated by the Standard Volume material's parameters [S1, unofficial].

**Parameters:**
*   **File Path:** String path to the VDB file or sequence.
*   **Preview Mode:** Enum selecting between "Bounding Box" and "Point Cloud" for viewport display [S1, unofficial][S2].
*   **Material:** Reference to a Standard Volume material instance [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Homogeneous Volumes:** This object is not suitable for uniform media like atmospheric haze or fog, which require the Redshift Environment object instead [S1, unofficial].
*   **Procedural Skies:** For sky simulations, the Clouds object is the appropriate tool, offering specific modes for background rendering or fully volumetric interaction with scene geometry [S1, unofficial].

## Operating characteristics
*   **Memory:** Memory usage is proportional to the size of the VDB file and the number of active tiles/voxels loaded into the 3D texture or sparse structure.
*   **Performance:** Rendering speed depends on the density of the VDB data and the complexity of the Standard Volume material. Heterogeneous volumes generally require more samples than homogeneous ones to converge.
*   **Strengths:** Supports complex, non-uniform density distributions; supports animation via VDB sequences; integrates seamlessly with Redshift's material system.
*   **Limitations:** Requires pre-computed VDB data; not suitable for simple, uniform atmospheric effects (use Environment object); not suitable for procedural sky generation (use Clouds object).

## Background
The Redshift Volume Object was introduced as part of Maxon's Redshift renderer suite to support heterogeneous volumetric rendering. It enables artists to load external VDB data sets, such as those from animation studios or providers like JangaFX and The Pixel Lab [S1, unofficial][S2]. It is part of a broader workflow where Redshift splits volume rendering into distinct tools: the Volume Object for heterogeneous data, the Environment Object for homogeneous media and god rays, and the Clouds Object for procedural skies [S1, unofficial][S2].
