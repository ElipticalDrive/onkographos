# Redshift Volume Object

Also called: Heterogeneous Volume, Non-uniform Volume, Redshift VDB Loader, Redshift Volume Rendering Objects

## Overview
The Redshift Volume Object loads heterogeneous volumetric data (varying density such as clouds, smoke, fire, or explosions) from VDB files or animated VDB sequences [S1, unofficial][S2]. It serves as the geometric proxy for sparse voxel data, distinct from homogeneous media handled by the Redshift Environment object or procedural skies generated by the Clouds object [S1, unofficial][S2]. Builds on [VDB Data Loading & 3D Texture Setup](4880-vdb-data-loading-3d-texture-setup.md) for low-level VDB parsing and 3D texture uploads [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A VDB file or an animated VDB sequence [S1, unofficial][S2].
*   **Output:** A scene node containing the volumetric data, rendered using an attached Standard Volume material [S1, unofficial][S2].

**Data Structures:**
The object references the sparse voxel structure parsed by the parent method [G]. It does not store dense grids itself but relies on the loaded VDB data [G]. The viewport preview is rendered as either a bounding box or a point cloud representation of the loaded data [S1, unofficial][S2]. Exact field layouts, sizes, and bit packing details are not given in the sources. [G]

**Steps:**
1.  **Load Data:** The object reads the VDB file or animated sequence [S1, unofficial][S2].
2.  **Viewport Preview:** The viewport displays either a bounding box or a point cloud preview of the loaded data to aid in scene composition [S1, unofficial][S2].
3.  **Material Binding:** The visual appearance (scattering, absorption, emission) is defined by assigning a Standard Volume material to the object [S1, unofficial].
4.  **Rendering:** During ray traversal, the renderer samples the VDB data referenced by the object, modulated by the Standard Volume material's parameters [G].

**Formulas:** Not given in the sources. [G]

**Parameters:** Not given in the sources. [G]

**Edge Cases and Pitfalls:**
*   **Homogeneous Volumes:** This object is not suitable for uniform media like atmospheric haze or fog, which require the Redshift Environment object instead [S1, unofficial].
*   **Procedural Skies:** For sky simulations, the Clouds object is the appropriate tool, offering specific modes for background rendering or fully volumetric interaction with scene geometry [S1, unofficial].
*   **GPU Memory:** Volumes must fit entirely in GPU memory, as they are the only asset type excluded from Redshift's Out-of-Core system [S3, unofficial].

## Background
The Redshift Volume Object is part of Maxon's Redshift renderer suite workflow for volume rendering [S1, unofficial][S2]. It enables artists to load external VDB datasets, such as those from animation studios or providers like JangaFX and The Pixel Lab [S1, unofficial][S2]. It operates within a broader workflow where Redshift splits volume rendering into distinct tools: the Volume Object for heterogeneous data, the Environment Object for homogeneous media and god rays, and the Clouds Object for procedural skies [S1, unofficial][S2].
