# Evaluation Cache

Also called: CachedEval, EvalCache

## Overview
Evaluation Cache eliminates redundant computation by storing previously computed field values and their derivatives at shared grid locations [S1, unofficial]. It differs from sibling methods that optimize spatial data layout or hardware texture sampling by caching the results of expensive algorithmic evaluations rather than optimizing data access patterns [G].

## How it works
**Inputs and Outputs**
- Input: Grid origin $\mathbf{o}$, cell size $s$, and an evaluation function $f(\mathbf{x})$ returning a scalar and optionally a gradient vector [G].
- Output: A cache mapping quantized grid positions to computed values and gradients [S1, unofficial].

**Data Structures**
The method uses two structures [S1, unofficial]:
- `GridPos`: A quantized key representing a unique corner in the global grid.
- `CachedEval`: Fields `value` (f64) and `gradient` (Option<[f64; 3]>) [S1, unofficial].
- `EvalCache`: Field `entries` (HashMap<GridPos, CachedEval>), using quantized grid positions as keys to ensure shared corners are evaluated only once [S1, unofficial].

**Algorithm Steps**
1. **Quantize Grid Position**: For a cell corner, compute a unique integer key [S1, unofficial]. Let $\mathbf{c} = (c_x, c_y, c_z)$ be the cell's integer coordinates and $corner\_idx \in \{0, \dots, 7\}$ be the local corner index [G]. The quantized grid position components are $g_x = c_x + (corner\_idx \ \& \ 1)$, $g_y = c_y + ((corner\_idx \gg 1) \ \& \ 1)$, and $g_z = c_z + ((corner\_idx \gg 2) \ \& \ 1)$ [S1, unofficial].
2. **Check Cache**: Look up the quantized position in `EvalCache.entries` [S1, unofficial]. If present, return `entry.value` and `entry.gradient` [S1, unofficial].
3. **Evaluate**: Convert the grid position to world space [S1, unofficial]. Let $\mathbf{P}_{grid} = (g_x, g_y, g_z)$ be the continuous grid position derived from $\mathbf{c}$ and $corner\_idx$ [S1, unofficial]. Compute $\mathbf{x} = \mathbf{o} + \mathbf{P}_{grid} \cdot s$ [S1, unofficial]. Evaluate $v = f(\mathbf{x})$ and $\mathbf{g} = \nabla f(\mathbf{x})$ [G].
4. **Store**: Insert $(\mathbf{P}_{grid}, \text{CachedEval}(v, \mathbf{g}))$ into `EvalCache.entries` [S1, unofficial].
5. **Return**: Return $v$ and $\mathbf{g}$ [S1, unofficial].

**Pseudocode**
```python
from typing import Tuple, Optional, Dict, Callable

class CachedEval:
    def __init__(self, value: float, gradient: Optional[Tuple[float, float, float]]):
        self.value = value
        self.gradient = gradient

class EvalCache:
    def __init__(self):
        self.entries: Dict[Tuple[int, int, int], CachedEval] = {}

    def quantize_grid_pos(self, cell_coords: Tuple[int, int, int], corner_idx: int) -> Tuple[int, int, int]:
        cx, cy, cz = cell_coords
        gx = cx + (corner_idx & 1)
        gy = cy + ((corner_idx >> 1) & 1)
        gz = cz + ((corner_idx >> 2) & 1)
        return (gx, gy, gz)

    def get_or_eval(self, origin: Tuple[float, float, float], 
                    cell_size: float, cell_coords: Tuple[int, int, int], 
                    corner_idx: int, 
                    eval_func: Callable[[float, float, float], Tuple[float, Optional[Tuple[float, float, float]]]]) -> Tuple[float, Optional[Tuple[float, float, float]]]:
        key = self.quantize_grid_pos(cell_coords, corner_idx)
        if key in self.entries:
            entry = self.entries[key]
            return entry.value, entry.gradient
        
        world_x = origin[0] + key[0] * cell_size
        world_y = origin[1] + key[1] * cell_size
        world_z = origin[2] + key[2] * cell_size
        
        value, gradient = eval_func(world_x, world_y, world_z)
        self.entries[key] = CachedEval(value, gradient)
        
        return value, gradient
```

**Parameters**
- `cell_size`: The physical size of a single grid cell [G].
- `origin`: The world-space coordinate of the grid's $(0,0,0)$ corner [G].

**Edge Cases and Pitfalls**
- **Key Collisions**: The additive quantization scheme may produce collisions if cell coordinates are large [G].
- **Memory Usage**: The cache grows with the number of unique corners, potentially exceeding available memory for large volumes [G].
- **Gradient Storage**: Storing gradients doubles the memory footprint per entry; omit it when derivatives are unnecessary [G].

## Subtopics

### [Edge Point Caching](891-edge-point-caching.md)
Eliminates redundant linear interpolation calculations for isosurface intersection points on cube edges shared between adjacent voxels in the Marching Cubes algorithm. It differs from standard Marching Cubes by maintaining a lookup structure that ensures each geometric edge is interpolated only once, regardless of how many adjacent cubes share it. Choose it when extracting manifolds with high edge-sharing density to reduce interpolation overhead [G]. [Edge Point Caching](891-edge-point-caching.md)

### Volume Access Caching
A variant where the cache stores the result of texture sampling operations in iterative volume rendering [S2]. The back sample of one iteration is cached and reused as the front sample of the next, ensuring the number of texture accesses remains $N$ regardless of the integration order [S2]. Choose it for second-order pre-integrated rendering to minimize computational cost and branching penalties [S2].

## Operating characteristics
- **Time Complexity**: Not given in the sources [G].
- **Memory Complexity**: Not given in the sources [G].
- **Strengths**: Eliminates redundant mathematical evaluations at shared grid vertices [G].
- **Limitations**: Requires additional memory for the hash map and suffers from hash overhead on very large grids [G].
- **When to use**: When the evaluation function is expensive and corners are shared across multiple cells [G].

## Background
The method is used in isosurface extraction algorithms, specifically Manifold Dual Contouring, to optimize the computation of corner values and gradients [S1, unofficial]. It is also applied in volume rendering to cache texture samples across iterations [S2].
