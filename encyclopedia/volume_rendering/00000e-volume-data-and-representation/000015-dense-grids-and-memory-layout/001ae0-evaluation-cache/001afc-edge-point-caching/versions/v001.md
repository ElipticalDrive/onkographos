# Edge Point Caching

Also called: GetEdgePoint, X/Y/ZEdgePoint

## Overview
Edge Point Caching is a memory optimization technique used in the Marching Cubes algorithm to eliminate redundant linear interpolation calculations for isosurface intersection points on cube edges shared between adjacent voxels [S1, unofficial]. It differs from standard Marching Cubes by maintaining a lookup table of computed edge points, ensuring that each geometric edge in the grid is interpolated only once, regardless of how many adjacent cubes share it [S1, unofficial].

## How it works
**Inputs:** A 3D scalar field grid, an isovalue threshold, and a voxel processing loop iterating over $i, j, k$ indices.
**Outputs:** A list of triangles defining the isosurface.
**Data Structures:**
The cache is a 3D array of integers, `EdgeCache[X][Y][Z][EdgeIndex]`, where dimensions correspond to the voxel grid size plus one (to cover vertices/edges at boundaries). `EdgeIndex` ranges from 0 to 11, representing the 12 edges of a cube. The cache stores the computed 3D coordinate (or an index into a global point list) for each edge. If an edge has not been computed, the cache value is initialized to -1 [S1, unofficial].

**Steps:**
1. Initialize `EdgeCache` with -1 for all entries.
2. For each voxel $(i, j, k)$:
   a. Determine the cube case based on scalar values at the 8 corners.
   b. For each active edge in the case:
      i. Identify the edge uniquely by its global coordinates.
      ii. Map the local edge index to a specific cache access function (`GetXEdgePoint`, `GetYEdgePoint`, or `GetZEdgePoint`) based on the orientation of the edge [S1, unofficial].
      iii. Check if `EdgeCache` contains a valid value (not -1) for this edge.
      iv. If valid, retrieve the cached point.
      v. If invalid, compute the intersection point using linear interpolation between the two corner scalar values and the isovalue. Store the result in `EdgeCache` and return it.
   c. Construct triangles using the retrieved edge points.

## Operating characteristics
- **Time Complexity:** Reduces the number of linear interpolation operations from $12 \times N$ (where $N$ is the number of voxels) to approximately $12 \times N / 3 = 4 \times N$ on average, as each internal edge is shared by 3 voxels (in 3D, edges are shared by 4 voxels, but the caching logic ensures each is computed once). The lookup is $O(1)$.
- **Memory Complexity:** Requires $O(X \times Y \times Z \times 12)$ storage for the cache. This can be significant for large volumes.
- **Strengths:** Eliminates redundant calculations, improving performance for large datasets.
- **Limitations:** Increased memory usage. Cache invalidation or reuse requires careful management if the volume changes.

## Background
Originated in implementations of the Marching Cubes algorithm to optimize performance. The specific implementation details are found in open-source C code for 3D model extraction [S1, unofficial].
