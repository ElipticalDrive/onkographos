# Node Caching for Random Access

Also called: Accessor Class Caching, Cached Tree Traversal

## Overview
Node Caching for Random Access accelerates coordinate-based value queries in VDB structures by buffering recently visited nodes in a small cache list, thereby avoiding full tree traversals for repeated or nearby accesses [S1, unofficial]. It sets itself apart from sibling methods like [Stencil Access](22361-stencil-access.md) by focusing on arbitrary random access patterns rather than local neighborhood evaluation, and from [VDB Value Accessor Caching](8756-vdb-value-accessor-caching.md) by explicitly detailing the inverted traversal mechanism and perfect keying strategy that enables average constant-time performance [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Global voxel coordinates $(x, y, z)$ to query.
*   **Output:** The value at the specified coordinate, accessed via the cached or newly traversed path.

**Data Structures:**
The method uses a compile-time-fixed linked list within the `Accessor` class. Each entry in the list stores:
1.  A pointer to a tree node (`InternalNode` or `LeafNode`).
2.  A perfect key array `int cacheKey[3]`.

The `Accessor` instances are registered in the `RootNode`'s `mAccessors` member [S1, unofficial].

**Parameters:**
*   **Cache Size:** Equal to the depth of the tree (e.g., 3 for a 4-level tree including root) [S1, unofficial].

**Steps:**
1.  **Cache Initialization (First Access):** If the cache is empty or invalid, perform a standard top-down tree traversal from the `RootNode` to the target leaf. During this traversal, record every visited node and its associated global coordinate range into the cache list. The list is ordered leaf-to-root (i.e., the last element is the `RootNode`, the first is the `LeafNode`) [S1, unofficial].
2.  **Key Computation:** For the target global coordinates $(x, y, z)$, compute the perfect key for each level of the tree. The key for a specific axis is derived using bitwise operations:
    $$ \text{cacheKey}[i] = x \ \& \ \sim((1 \ll s\text{Log2X}) - 1) $$
    where $s\text{Log2X}$ is the compile-time constant for the logarithm of the branching factor along the X-axis. The same applies to Y and Z axes. This operation effectively masks out the lower bits, identifying the node's global position [S1, unofficial].
3.  **Cache Lookup:** Traverse the cache list from the leaf end (bottom-up) towards the root. For each cached entry, compute the `cacheKey` for the target $(x, y, z)$ and compare it with the entry's stored key.
    *   **Match Found:** A match indicates that the target coordinate lies within the spatial bounds of the cached node. Terminate the search and initiate a **shortened tree traversal** starting from this cached node.
    *   **No Match:** If the list is exhausted without a match, proceed to Step 5.
4.  **Shortened Traversal & Cache Update:**
    *   From the matched cached node, derive an offset into the node's direct access table (e.g., `mInternalDAT`) using fast bitwise operations on the local coordinates relative to the node's origin.
    *   Traverse down the tree from this node until a `LeafNode` or a `Tile` (compressed node) is reached.
    *   As new nodes are visited during this shortened traversal, update the cache list. The new nodes replace the old entries, maintaining the leaf-to-root order. This effectively "slides" the cache window down the tree [S1, unofficial].
5.  **Full Traversal (Cache Miss):** If no match is found in the cache list (worst case), perform a regular top-down tree traversal from the `RootNode`. Rebuild the entire cache list with the nodes visited during this traversal [S1, unofficial].

**Pseudocode:**
```python
def query_value(accessor, root, x, y, z):
    # Step 1: Compute perfect keys for the target coordinates
    # sLog2X, sLog2Y, sLog2Z are compile-time constants for branching factor logs
    key_x = x & ~((1 << sLog2X) - 1)
    key_y = y & ~((1 << sLog2Y) - 1)
    key_z = z & ~((1 << sLog2Z) - 1)
    target_key = (key_x, key_y, key_z)

    # Step 2: Search cache list (ordered leaf-to-root)
    # cache_list is a linked list of (node, key) pairs
    cached_node = None
    for entry in accessor.cache_list:
        if entry.key == target_key:
            cached_node = entry.node
            break

    # Step 3: Determine traversal start point
    if cached_node is not None:
        # Cache hit: start shortened traversal from cached node
        current_node = cached_node
        new_cache_entries = []
        
        # Derive offset into current_node's direct access table
        # This uses local coordinates relative to current_node's origin
        local_coords = get_local_coords(current_node, x, y, z)
        offset = compute_dat_offset(local_coords, current_node.branching_factor)
        
        # Traverse down from current_node to leaf/tile
        # Note: In a real implementation, this follows child pointers based on offset
        while not is_leaf_or_tile(current_node):
            child_index = get_child_index(offset, current_node.branching_factor)
            current_node = current_node.children[child_index]
            # Recompute key for the new node's level to store in cache
            # The key logic depends on the specific level's sLog2 values
            level_key = compute_key_for_level(x, y, z, current_node.level)
            new_cache_entries.append((current_node, level_key))
            
        # Update cache: prepend new entries (leaf first)
        # The old cache is replaced by the path from cached_node to leaf
        accessor.cache_list = new_cache_entries
        
        # Return value from the final leaf/tile
        return current_node.get_value(offset)
    else:
        # Cache miss: full traversal from root
        current_node = root
        new_cache_entries = []
        
        while not is_leaf_or_tile(current_node):
            # Compute global key for this level to store in cache
            level_key = compute_key_for_level(x, y, z, current_node.level)
            new_cache_entries.append((current_node, level_key))
            
            # Traverse down
            offset = compute_dat_offset_for_root(x, y, z, current_node)
            child_index = get_child_index(offset, current_node.branching_factor)
            current_node = current_node.children[child_index]
            
        # Update cache with full path
        accessor.cache_list = new_cache_entries
        
        # Return value
        return current_node.get_value(compute_dat_offset_for_leaf(x, y, z, current_node))
```

**Edge Cases and Pitfalls:**
*   **Coordinate Transformation:** The method requires nodes to be accessible directly via global coordinates without expensive local coordinate transformations. This is enabled by VDB's height-balanced structure, fixed tree depth, and compile-time known power-of-two branching factors [S1, unofficial].
*   **Hash Table Overhead:** Standard hash tables are precluded because random access operations are already fast, leaving little room for computational overhead. The fixed-size linked list with bitwise keys is significantly lighter [S1, unofficial].
*   **Worst Case:** If accesses are completely random with no spatial coherence, the cache is invalidated on every access, resulting in a full tree traversal every time. However, due to the fixed depth, this remains effectively constant time [S1, unofficial].

## Subtopics

### [Stencil Access](22361-stencil-access.md)
Stencil Access provides efficient evaluation of a local neighborhood (support stencil) of grid points for Finite Difference computations, interpolation, or filtering. It sets itself apart from sibling methods like DT-Grid and H-RLE by combining a single sequential iterator for the center point with accelerated random access via an `Accessor` (see [Node Caching for Random Access](22341-node-caching-for-random-access.md)), rather than grouping multiple sequential iterators. This approach avoids the linear overhead scaling with stencil size found in those alternatives, amortizing retrieval costs through cache reuse.

### VDB Inverted Tree Traversal Caching
VDB Inverted Tree Traversal Caching is a technique to improve random access performance by caching previous access patterns and traversing the tree from bottom up until a common parent node is reached, exploiting spatial coherence [S1, unofficial]. It caches the sequence of nodes visited during a previous root-to-leaf traversal in a small cache list (size = tree depth, e.g., 3), ordered leaf-to-root [S1, unofficial]. For subsequent access, it traverses from bottom up using cached nodes until a common parent is reached [S1, unofficial]. The perfect key is computed as `int cacheKey[3] = {x&~((1<<sLog2X)-1), y&~((1<<sLog2Y)-1), z&~((1<<sLog2Z)-1);}` where `&` is bitwise AND, `~` is bitwise NOT, and `sLog2X/Y/Z` are compile-time constants [S1, unofficial]. Standard hash tables are precluded for caching because random access operations are already fast, leaving little room for computational overhead; the cache list size equals tree depth to ensure efficient storage and retrieval [S1, unofficial]. It is analogous to the CPU's Translation Look-aside Buffer (TLB), with `RootNode` ~ main memory, `InternalNodes` ~ L3/L2 cache, and `LeafNodes` ~ L1 cache [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Average constant time access. Worst-case linear in tree depth, which is fixed, so effectively constant [S1, unofficial].
*   **Memory Complexity:** $O(D)$, where $D$ is the tree depth (e.g., 3 nodes). The cache size is fixed and small [S1, unofficial].
*   **Measured Performance:** The technique amortizes the slower access time of the `RootNode` if its child nodes are large enough to introduce average spatial coherence for all practical access patterns [S1, unofficial].
*   **Strengths:** Extremely low overhead; leverages spatial coherence in random access patterns; no dynamic memory allocation for cache entries.
*   **Limitations:** Requires height-balanced trees with fixed depth and power-of-two branching factors; ineffective for completely random, non-coherent access patterns (though still bounded by tree depth).
*   **When to Use:** When accessing VDB data with spatial coherence (e.g., ray marching, volume rendering, physics simulations).
*   **When Not to Use:** When access patterns are entirely random with no locality, or when using non-VDB data structures that do not support direct global coordinate mapping.

## Background
Originating from the VDB (OpenVDB) paper by Ken Museth (2013), this technique was designed to address the performance bottleneck of random access in sparse volumetric data structures [S1, unofficial]. The core idea draws an analogy to CPU memory hierarchies, specifically the Translation Look-aside Buffer (TLB), treating the VDB tree levels as analogous to L1/L2/L3 caches and main memory [S1, unofficial]. It is a fundamental component of the VDB `Accessor` class, enabling efficient rendering and simulation workflows that rely on frequent, spatially coherent voxel queries [S1, unofficial].
