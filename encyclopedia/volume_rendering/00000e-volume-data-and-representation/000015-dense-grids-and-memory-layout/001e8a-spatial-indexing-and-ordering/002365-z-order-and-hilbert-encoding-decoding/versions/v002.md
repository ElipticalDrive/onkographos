# Z-Order and Hilbert Encoding/Decoding


## Overview
Z-order and Hilbert encoding map $N$-dimensional spatial coordinates to a 1D linear index to optimize cache locality in volume rendering and spatial indexing [S1, S8, unofficial]. Unlike arithmetic strides which suffer from poor locality across slices, these space-filling curves ensure that points close in Euclidean distance have close linear indices [S1, S8, unofficial]. Z-order uses bit-interleaving for simplicity, while Hilbert curves provide superior locality at the cost of higher computational complexity [S1, unofficial].

## How it works
### Inputs and Outputs
- **Inputs**: $N$-dimensional integer coordinates $(x_0, x_1, \dots, x_{N-1})$ and the bit-width $B$ of the coordinate space (typically 32 or 64 bits).
- **Outputs**: A 1D linear index $I$ (encoded) or the original coordinates (decoded).

### Data Structures
- **Encoded Index**: A single integer of width $N \times B$ bits.
- **Decoded Coordinates**: An array of $N$ integers, each of width $B$ bits.

### Algorithm: Z-Order (Morton Code) Encoding
Z-order encoding interleaves the bits of the input coordinates.

1. Initialize $I = 0$.
2. For each dimension $d$ from $0$ to $N-1$:
   - Extract the $b$-th bit of $x_d$: $bit = (x_d \gg b) \& 1$.
   - Set the bit at position $d + N \times b$ in $I$: $I |= (bit \ll (d + N \times b))$.
3. Return $I$.

**Pseudocode (3D, 32-bit):**
```python
def z_order_encode(x, y, z):
    # Interleave bits of x, y, z
    # Assume x, y, z are 32-bit integers
    i = 0
    for b in range(32):
        i |= ((x & (1 << b)) << (2 * b))
        i |= ((y & (1 << b)) << (2 * b + 1))
        i |= ((z & (1 << b)) << (2 * b + 2))
    return i
```
*Note: The above pseudocode is a simplified bit-interleaving logic. Efficient implementations use parallel bit manipulation instructions or lookup tables [S1, unofficial].*

### Algorithm: Hilbert Curve Encoding
Hilbert encoding maps coordinates by traversing a recursive space-filling curve. The mapping depends on the dimension and the orientation of the curve at each recursive step.

1. Initialize $I = 0$.
2. For each bit position $b$ from $B-1$ down to $0$:
   - Determine the quadrant $q$ containing the point $(x_b, y_b, z_b)$ based on the current orientation.
   - Update $I$ by adding the offset corresponding to quadrant $q$.
   - Update the coordinates $(x, y, z)$ and the orientation matrix to reflect the recursive step into the selected quadrant.
3. Return $I$.

**Pseudocode (3D, simplified conceptual):**
```python
def hilbert_encode(x, y, z):
    n = 1 << 32  # Assuming 32-bit coordinates
    d = 0
    # Recursive logic implemented iteratively
    for b in range(31, -1, -1):
        rx = 1 & (x >> b)
        ry = 1 & (y >> b)
        rz = 1 & (z >> b)
        
        # Determine quadrant and update orientation
        # This involves rotating/reflection matrices based on current orientation
        # and the bits rx, ry, rz
        # ... (complex bit manipulation logic) ...

        d = (d << 2) | quadrant_index

    return d
```
*Note: Exact bit-manipulation formulas for Hilbert curves are complex and dimension-dependent [S1, unofficial].*

### Decoding
Decoding reverses the encoding process.
- **Z-Order Decoding**: Extract bits from $I$ at intervals of $N$ and distribute them to the respective coordinate dimensions.
- **Hilbert Decoding**: Traverse the curve in reverse, using the linear index to determine the quadrant at each step and updating the coordinates accordingly.

### Parameters
- **Bit-width ($B$)**: Typically 32 or 64 bits, matching the coordinate precision.
- **Dimension ($N$)**: Typically 3 for volume rendering.

### Edge Cases and Pitfalls
- **Precision**: Bit-interleaving requires sufficient integer width to avoid overflow. For 3D 32-bit coordinates, the Z-order code requires 96 bits, which may exceed standard integer types.
- **Boundaries**: Coordinates must be within the defined range $[0, 2^B - 1]$.
- **Degenerate Input**: Zero coordinates are handled correctly by both methods.

## Subtopics

### Morton Code Sorting for Brick Layout
Morton code sorting is used to organize sub-bricks within a parent brick structure to ensure spatial coherence in the output buffer [S2, unofficial]. Sub-bricks are sorted by their Morton codes within each group during construction, guaranteeing that the global buffer remains spatially coherent as bricks are added level by level [S2, unofficial]. An enumeration sort is employed, leveraging a 1:1 mapping between threads and sub-bricks, with a maximum of 64 sub-bricks per parent [S2, unofficial]. This approach optimizes cache performance during rendering by ensuring nearby threads access adjacent bricks [S2, unofficial].

### Serialized-Morton/ASTC
Serialized-Morton/ASTC is a variant that rearranges voxel attributes into correlations to enable the reuse of the ASTC codec for compression [S3, unofficial]. While it removes 2D layouts and reduces addressing overhead, it requires mapping voxel locations to serialized attributes for random access [S3, unofficial]. This rearrangement can weaken the spatial correlations available to UV mapping alone, potentially impacting compression efficiency compared to standard 3D layouts [S3, unofficial]. It is used in mesh texture compression where GPU-resident low-latency random-access decoding is required [S3, unofficial].

## Operating characteristics
- **Time Complexity**: Z-order encoding/decoding is $O(B)$ where $B$ is the bit-width, often optimized to $O(1)$ with parallel bit manipulation instructions. Hilbert encoding/decoding is also $O(B)$ but with a higher constant factor due to orientation updates.
- **Memory Complexity**: $O(1)$ for the index itself.
- **Performance**: Z-order is faster to compute but has lower locality than Hilbert. Hilbert provides better cache locality, which can lead to significant performance gains in rendering and spatial queries despite higher encoding/decoding costs [S1, S2, unofficial].
- **Strengths**: Excellent spatial locality, compact representation, efficient for sorting and indexing.
- **Limitations**: Z-order locality degrades at larger distances compared to Hilbert. Hilbert computation is more complex. Both require integer coordinates.

## Background
Z-order (Morton code) was introduced by G. M. Morton in 1966 [S1, unofficial]. Hilbert curves were introduced by David Hilbert in 1891 [S1, unofficial]. These methods are widely used in volume rendering, spatial databases, and image processing to optimize data layout and access patterns [S1, S8, unofficial]. The provided sources highlight their use in GPU-based voxel rendering and texture compression [S1, S2, S3, unofficial].
