# OpenVDB Volume Grid Storage

Also called: OpenVDB Grid, VDB Grid

## Overview
OpenVDB Volume Grid Storage is a data structure for efficiently storing dense and sparse volume grids as groups of voxels, where each voxel is indexed by a 3D integer coordinate [S1, unofficial]. It solves the memory inefficiency of storing individual values for every voxel in large grids by using tiling and active status flags to compress uniform regions and empty space [S1, unofficial]. It sets itself apart from sibling methods by combining a hierarchical tiling system with a binary active/inactive status per tile and voxel, allowing for efficient storage of both dense data with uniform areas and sparse data with large empty regions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of voxel values at 3D integer coordinates, a grid transform, and a background value.
*   **Output:** A compressed grid structure containing tiles, active status flags, and data pointers.

**Data Structures:**
The grid consists of the following components:
1.  **Grid Transform:** A 4x4 matrix (or equivalent) mapping index-space to object-space. It includes location, rotation, and scale [S1, unofficial].
2.  **Background Value:** A single scalar value (e.g., float) representing the value of all inactive voxels [S1, unofficial].
3.  **Tiles:** Hierarchical blocks of voxels.
    *   **Small Tile:** A block of $8 \times 8 \times 8 = 512$ voxels [S1, unofficial].
    *   **Large Tile:** A block of $16 \times 16 \times 16$ small tiles (less common) [S1, unofficial].
    *   Each tile stores a pointer to data if active, or a flag if inactive.
4.  **Active Status:** A binary flag associated with each tile and voxel.
    *   **Active:** The tile/voxel stores a specific value.
    *   **Inactive:** The tile/voxel uses the grid’s background value [S1, unofficial].

**Coordinate System:**
*   Voxels are indexed by 3D integer coordinates $(x, y, z)$ [S1, unofficial].
*   The coordinate $(0, 0, 0)$ is the center voxel [S1, unofficial].
*   The coordinate $(1, 0, 0)$ is the voxel to the right of the center [S1, unofficial].

**Transform Mapping:**
The grid transform maps index-space to object-space. For a grid with scale $s$, the object-space position $\mathbf{p}_{obj}$ for index $\mathbf{i} = (x, y, z)$ is calculated as:
$$ \mathbf{p}_{obj} = \mathbf{T} \cdot (\mathbf{i} \cdot s) $$
Where $\mathbf{T}$ is the transformation matrix (rotation and translation) and $s$ is the uniform scale factor [S1, unofficial]. For example, if scale is $0.1$, voxel $(5, 0, 0)$ corresponds to object space position $(0.5, 0, 0)$ [S1, unofficial].

**Numbered Steps for Storage:**
1.  **Initialize Grid:** Create an empty grid with a specified background value and transform [S1, unofficial].
2.  **Assign Voxels:** For each input voxel at index $\mathbf{i}$ with value $v$:
    a. Determine the small tile containing $\mathbf{i}$.
    b. Check if all voxels in the small tile have the same value $v$.
    c. If yes, mark the small tile as active and store $v$ once for the entire tile [S1, unofficial].
    d. If no, mark the small tile as active and store individual values for each voxel in the tile [S1, unofficial].
    e. Check if all small tiles in a large tile are identical and active. If so, store the large tile as a single unit [S1, unofficial].
3.  **Handle Inactive Voxels:** Any voxel not explicitly set to active remains inactive and returns the background value [S1, unofficial].

**Pseudocode:**
```python
class OpenVDBGrid:
    def __init__(self, background_value, transform_matrix, scale):
        self.background_value = background_value
        self.transform = transform_matrix
        self.scale = scale
        self.tiles = {}  # Map from tile_key to Tile object

    def set_voxel(self, index, value):
        """Set a single voxel's value."""
        tile_key = self._get_tile_key(index)
        if tile_key not in self.tiles:
            self.tiles[tile_key] = Tile()
        self.tiles[tile_key].set_voxel(index, value)

    def get_voxel(self, index):
        """Get a single voxel's value."""
        tile_key = self._get_tile_key(index)
        if tile_key in self.tiles:
            tile = self.tiles[tile_key]
            if tile.is_active:
                return tile.get_voxel(index)
            else:
                return self.background_value
        else:
            return self.background_value

    def _get_tile_key(self, index):
        """Calculate the key for the small tile containing the index."""
        # Assuming 8x8x8 small tiles
        tile_size = 8
        return (index[0] // tile_size, index[1] // tile_size, index[2] // tile_size)

class Tile:
    def __init__(self):
        self.is_active = False
        self.uniform_value = None
        self.voxel_data = {}  # Map from local_index to value

    def set_voxel(self, index, value):
        self.is_active = True
        # Check if this is the first voxel or if it matches the uniform value
        if not self.voxel_data:
            self.uniform_value = value
            self.voxel_data = {}
        elif self.uniform_value is not None and self.uniform_value != value:
            # Transition from uniform to individual storage
            self.uniform_value = None
            # Copy existing uniform value to all voxels in tile
            for i in range(8):
                for j in range(8):
                    for k in range(8):
                        self.voxel_data[(i, j, k)] = self.uniform_value
        if self.uniform_value is None:
            local_index = (index[0] % 8, index[1] % 8, index[2] % 8)
            self.voxel_data[local_index] = value

    def get_voxel(self, index):
        if self.uniform_value is not None:
            return self.uniform_value
        local_index = (index[0] % 8, index[1] % 8, index[2] % 8)
        return self.voxel_data.get(local_index, self.uniform_value) # Fallback to uniform if not found (should not happen if active)
```

**Parameters:**
*   **Small Tile Size:** $8 \times 8 \times 8$ voxels [S1, unofficial].
*   **Large Tile Size:** $16 \times 16 \times 16$ small tiles (less common) [S1, unofficial].
*   **Background Value:** User-defined, typically 0.0 for SDFs [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Efficiency:** Storing every voxel individually is impractical for large grids (e.g., $100^3$ voxels = 1,000,000 values) [S1, unofficial]. Tiling and active status are required for efficiency [S1, unofficial].
*   **Topology Merging:** When combining grids (e.g., addition), topologies are generally merged, which may increase memory usage if the resulting grid has less uniformity [S1, unofficial].
*   **Inactive Voxels:** Most operations ignore inactive voxels, which use the background value [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Lookup is $O(1)$ for tile access plus $O(1)$ for voxel access within a tile, assuming hash-based tile lookup. Pruning and voxelization operations depend on the number of tiles and voxels [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of active tiles and active voxels within those tiles, not the total volume of the grid [S1, unofficial].
*   **Strengths:** Efficient storage of sparse data and dense data with large uniform regions. Supports efficient boolean operations with smooth transitions for SDFs [S1, unofficial].
*   **Limitations:** SDF grids are generally less efficient for storing detailed shapes compared to meshes [S1, unofficial].
*   **When to Use:** When dealing with volume grids that have significant empty space or uniform regions, or when performing boolean operations on SDFs [S1, unofficial].
*   **When Not to Use:** When the grid is fully dense with no uniform regions, the overhead of tiling may not be justified [S1, unofficial].

## Background
OpenVDB is an industry-standard library for storing and processing volumetric data [S1, unofficial]. It was developed to address the memory challenges of storing large volume grids, such as those used in visual effects and scientific visualization [S1, unofficial]. The structure is widely used in software like Blender (via Geometry Nodes), Houdini, and other VFX tools [S1, unofficial].
