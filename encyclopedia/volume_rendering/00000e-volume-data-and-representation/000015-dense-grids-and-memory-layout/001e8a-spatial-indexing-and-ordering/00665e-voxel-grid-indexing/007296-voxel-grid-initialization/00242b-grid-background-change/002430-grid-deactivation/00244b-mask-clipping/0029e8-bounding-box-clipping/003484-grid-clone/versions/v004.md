# Grid Clone

Also called: PixelGrid2D Clone

## Overview
Grid Clone creates a deep copy of a source voxel grid, preserving its bounding box, pixel dimensions, and all voxel data values. It solves the problem of duplicating grid state for independent modification or serialization. Unlike [Bounding Box Clipping](4643-bounding-box-clipping.md), which filters voxels by spatial containment, Grid Clone retains the entire logical extent of the source grid. It differs from [Voxel Body Copying with Sub-Voxel Clipping](7181-voxel-body-copying-with-sub-oxel-clipping.md) by performing a direct value assignment without geometric clipping or sub-voxel interpolation.

## How it works
**Inputs and Outputs:**
- Input: A source grid object (e.g., `PixelGrid2D` or `ScalarGrid3D`) containing a bounding box, pixel size, and an array of voxel values.
- Output: A new grid instance with identical metadata and a deep copy of the voxel data array.

**Data Structures:**
The source grid typically contains:
- `_BBox`: A bounding box object defining the spatial extent (min/max coordinates).
- `_PixelSize`: A point/vector object defining the physical size of a single voxel/pixel in x, y, and z dimensions.
- `Count`: An integer representing the total number of voxels/pixels.
- `Values`: A contiguous array (e.g., `float[]`) storing the scalar or color data for each voxel.

**Steps:**
1. **Initialize Metadata:** Create a new grid instance. Extract the source grid's `_BBox` and `_PixelSize` and assign them to the new instance. This ensures the new grid occupies the same logical space.
2. **Allocate Data:** Allocate a new array for the voxel values with size equal to the source grid's `Count`.
3. **Copy Values:** Iterate through the source grid's value array from index $0$ to `Count` (exclusive). Assign each value at index $i$ to the corresponding index $i$ in the new grid's value array.
   $$ V_{new}[i] = V_{source}[i] \quad \forall i \in [0, \text{Count}) $$
4. **Return:** Return the new grid instance.

**Pseudocode:**
```python
def GridClone(source_grid):
    # Step 1: Initialize new grid with source metadata
    new_grid = PixelGrid2D()
    new_grid._BBox = source_grid._BBox
    new_grid._PixelSize = source_grid._PixelSize
    
    # Step 2: Allocate new value array
    count = source_grid.Count
    new_grid.Values = new array of floats of size count
    
    # Step 3: Copy values
    for i from 0 to count - 1:
        new_grid.Values[i] = source_grid.Values[i]
        
    # Step 4: Return result
    return new_grid
```

**Edge Cases and Pitfalls:**
- **Memory Allocation:** If `Count` is large, ensure sufficient memory is available for the new array. Failure to allocate may cause runtime errors.
- **Reference vs. Value:** The copy must be deep. Copying the reference to the `Values` array would result in both grids sharing the same data, leading to unintended side effects when one grid is modified.
- **Metadata Consistency:** The bounding box and pixel size must be copied exactly. Any discrepancy in `_PixelSize` will cause spatial misalignment when the cloned grid is used in rendering or further processing.

## Subtopics

### [PixelGrid2D CloneEmpty](7356-pixelgrid2d-cloneempty.md)
Creates a new `PixelGrid2D` instance initialized with the current bounding box and pixel size, effectively producing an empty grid structure ready for population. It differs from `Grid Reinitialization` by preserving the existing grid topology and memory layout without reallocating underlying segmentation tensors or updating object counts.

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(N)$, where $N$ is the number of voxels (`Count`), due to the linear iteration required to copy values.
- Memory: $O(N)$ additional memory is required for the new value array. The metadata overhead is $O(1)$.

**Measured Performance:**
Performance depends on the size of the grid and the efficiency of the underlying array copy mechanism. For small grids, the overhead of object creation dominates. For large grids, the linear copy is the primary cost.

**Strengths and Limitations:**
- Strengths: Simple, fast, and preserves exact data integrity. No geometric calculations are needed.
- Limitations: Does not reduce memory usage. If the goal is to save space, [Bounding Box Clipping](4643-bounding-box-clipping.md) or sparse representations should be considered.

**When to Use:**
- When an independent copy of the grid is needed for simulation or editing.
- When serializing the grid state.
- When passing the grid to a function that might modify it.

**When Not to Use:**
- When memory is constrained and a subset of the grid is sufficient.
- When only the structure (empty grid) is needed, not the data.

## Background
The `Grid Clone` method is part of the voxel tools ecosystem, specifically associated with the `voxeltools` repository by arendvw [S1, unofficial]. It is implemented in C# within the `StudioAvw.Voxels.Geometry` namespace, often in conjunction with classes like `ScalarGrid3D` and `PixelGrid2D`. The method provides a basic utility for grid manipulation, allowing developers to duplicate grid states without complex geometric operations.
