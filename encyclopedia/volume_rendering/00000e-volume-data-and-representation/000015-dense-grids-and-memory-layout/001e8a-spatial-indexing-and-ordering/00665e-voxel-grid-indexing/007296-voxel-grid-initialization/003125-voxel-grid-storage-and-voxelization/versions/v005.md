# Voxel Grid Storage and Voxelization

Also called: Voxel Grid Storage

## Overview
Voxel Grid Storage and Voxelization is the process of converting continuous geometric representations (such as meshes or implicit shapes) into a discrete, dense 3D grid of scalar values or occupancy flags [S1, S2, unofficial]. It solves the problem of spatial discretization required for volume rendering, collision detection, and mesh processing by mapping world-space coordinates to array indices [S1, S2, unofficial]. It differs from [Voxel Grid Construction](3085-voxel-grid-construction.md) by focusing on the fundamental storage layout and the core voxelization algorithm (SDF evaluation or ray casting) rather than higher-level construction pipelines, and from [Instanced Voxel Rendering](10592-instanced-voxel-rendering.md) by providing the raw data structure rather than the rendering optimization [S1, S2, S3, unofficial].

## How it works
**Inputs:**
- A geometric primitive (mesh or implicit shape) defined in world space.
- A target voxel size (physical units per voxel).
- Optional: An existing grid structure to share with other meshes.

**Outputs:**
- A voxel grid data structure containing scalar distances or boolean occupancy values.
- Grid metadata: origin, dimensions (width, height, depth), and voxel size.

**Data Structures:**
Two primary storage layouts are documented:

1.  **1D Float Array (SDF Storage):**
    -   `voxels`: A 1D array of `float`.
    -   Dimensions: `width`, `height`, `depth`.
    -   Indexing: `index = (z * width * height) + (y * width) + x`.
    -   Memory: $W \times H \times D$ floats.
    -   Padding: If the required size exceeds the current array length, the array is resized to the nearest power of 2 greater than or equal to the required size using bitwise operations [S1, unofficial].

2.  **3D Boolean Array (Occupancy Storage):**
    -   `data`: A 3D array of `bool` (`bool *** data`).
    -   Dimensions: `x.count`, `y.count`, `z.count`.
    -   Memory: $X \times Y \times Z$ bytes (inefficient, as `bool` typically occupies a full byte) [S2, unofficial].

**Algorithm Steps:**

1.  **Grid Initialization (Fitting):**
    -   Calculate the world-space bounding box of the input shape: $[min_x, min_y, min_z]$ to $[max_x, max_y, max_z]$ [S1, unofficial].
    -   Compute the grid origin $(posX, posY, posZ)$ by flooring the minimum coordinates scaled by the reciprocal of the voxel size, then subtracting one voxel size:
        $$ posX = \lfloor \frac{min_x}{voxel\_size} \rfloor - 1 $$
        (Similarly for $posY, posZ$) [S1, unofficial].
    -   Compute the grid dimensions by ceiling the extents scaled by the reciprocal of the voxel size, then adding 2 voxels to each dimension for padding:
        $$ width = \lceil \frac{max_x - min_x}{voxel\_size} \rceil + 2 $$
        (Similarly for $height, depth$) [S1, unofficial].

2.  **Allocation:**
    -   If using 1D float storage, check if `width * height * depth` exceeds the current array length. If so, resize to the next power of 2 [S1, unofficial].
    -   If using 3D boolean storage, allocate `data[x][y][z]` for all dimensions [S2, unofficial].

3.  **Voxelization Loop:**
    -   Iterate through all voxel coordinates $(x, y, z)$ where $x \in [0, width)$, $y \in [0, height)$, $z \in [0, depth)$ [S1, unofficial].
    -   Compute the world-space center position of the voxel:
        $$ pos = (posX + (x + 0.5) \cdot voxel\_size, posY + (y + 0.5) \cdot voxel\_size, posZ + (z + 0.5) \cdot voxel\_size) $$
        (Implemented via `getVoxelCenterPos(x, y, z)` in [S1, unofficial])
    -   Transform $pos$ to the shape's local coordinate system.
    -   Evaluate the shape's Signed Distance Function (SDF) at the local point: $d = SDF(local\_pos)$ [S1, unofficial].
    -   Store $d$ in the voxel array at index corresponding to $(x, y, z)$ [S1, unofficial].
    -   *Alternative for Occupancy:* If using boolean storage, set `data[x][y][z] = true` if the point is inside the shape, `false` otherwise [S2, unofficial].

**Parameters:**
-   `DEFAULT_VOXEL_SIZE`: Static float constant, typically `0.1f` (world units) [S1, unofficial].
-   `OUT_OF_BOUNDS_VALUE`: Large default value (e.g., `10_000.0f`) returned when accessing coordinates outside grid bounds [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Out-of-Bounds Access:** Accessing a voxel coordinate outside the grid bounds does not throw an error; it returns a large default value (e.g., `10_000.0f`) to indicate invalid access [S1, unofficial].
-   **Memory Efficiency:** Using `bool` for voxel storage is memory inefficient because each boolean typically occupies a full byte rather than a single bit [S2, unofficial].
-   **Precision:** Floating-point precision in SDF evaluation and coordinate transformation can affect boundary accuracy [S1, unofficial].

**Pseudocode:**

```python
import math
import numpy as np

class VoxelGrid:
    def __init__(self, voxel_size=0.1):
        self.voxel_size = voxel_size
        self.width = 0
        self.height = 0
        self.depth = 0
        self.origin_x = 0.0
        self.origin_y = 0.0
        self.origin_z = 0.0
        self.voxels = None  # 1D float array or 3D bool array

    def fit_to_shape(self, shape):
        """
        Calculate grid dimensions and origin based on shape's bounding box.
        shape.get_bounding_box() returns (min_xyz, max_xyz) in world space.
        """
        min_xyz, max_xyz = shape.get_bounding_box()
        min_x, min_y, min_z = min_xyz
        max_x, max_y, max_z = max_xyz

        # Compute origin
        self.origin_x = math.floor(min_x / self.voxel_size) - 1
        self.origin_y = math.floor(min_y / self.voxel_size) - 1
        self.origin_z = math.floor(min_z / self.voxel_size) - 1

        # Compute dimensions with padding
        self.width = math.ceil((max_x - min_x) / self.voxel_size) + 2
        self.height = math.ceil((max_y - min_y) / self.voxel_size) + 2
        self.depth = math.ceil((max_z - min_z) / self.voxel_size) + 2

        # Allocate memory (1D float array example)
        required_size = self.width * self.height * self.depth
        # Resize to nearest power of 2 if needed
        if self.voxels is not None and len(self.voxels) >= required_size:
            pass # Keep existing buffer if large enough
        else:
            # Bitwise rounding up to power of 2
            power = 1
            while power < required_size:
                power <<= 1
            self.voxels = np.zeros(power, dtype=np.float32)

    def get_voxel_center_pos(self, x, y, z):
        """Compute world-space center of voxel (x, y, z)."""
        px = self.origin_x + (x + 0.5) * self.voxel_size
        py = self.origin_y + (y + 0.5) * self.voxel_size
        pz = self.origin_z + (z + 0.5) * self.voxel_size
        return np.array([px, py, pz], dtype=np.float32)

    def voxelize(self, shape):
        """
        Iterate through all voxels and evaluate SDF.
        shape.local_sdf(point) returns signed distance in local space.
        shape.world_to_local(point) transforms world point to local space.
        """
        for z in range(self.depth):
            for y in range(self.height):
                for x in range(self.width):
                    # Get world center
                    world_pos = self.get_voxel_center_pos(x, y, z)
                    # Transform to local space
                    local_pos = shape.world_to_local(world_pos)
                    # Evaluate SDF
                    distance = shape.local_sdf(local_pos)
                    # Store in 1D array
                    index = (z * self.width * self.height) + (y * self.width) + x
                    self.voxels[index] = distance

    def get_voxel(self, x, y, z):
        """
        Retrieve voxel value. Returns large default if out of bounds.
        """
        if x < 0 or x >= self.width or \
           y < 0 or y >= self.height or \
           z < 0 or z >= self.depth:
            return 10000.0f  # Out-of-bounds indicator
        index = (z * self.width * self.height) + (y * self.width) + x
        return self.voxels[index]
```

## Subtopics

### [VoxelizationGrid](6601-voxelizationgrid.md)
`VoxelizationGrid` is a data structure that represents an explicit voxelization grid, defining spatial bounds, grid dimensions, and voxel sizes in 3D space. It serves as a base class for managing a 3D voxel grid in world space, providing utilities for coordinate conversion, ray intersection, and mesh generation. It is distinct from sibling methods like [Instanced Voxel Rendering](10592-instanced-voxel-rendering.md) by focusing on the foundational storage and indexing logic rather than the rendering pipeline itself.

### [Instanced Voxel Rendering](10592-instanced-voxel-rendering.md)
Instanced Voxel Rendering is a technique for visualizing sparse voxel grids by generating a single unit cube mesh and drawing it multiple times at different positions using OpenGL instanced rendering, thereby reducing memory overhead compared to storing full geometry for every voxel. It differs from [VoxelizationGrid](6601-voxelizationgrid.md) by explicitly leveraging GPU instancing (`glDrawElementsInstanced`) to render discrete voxel positions, whereas VoxelizationGrid may imply a denser or differently structured grid representation without necessarily optimizing for instance count reduction via this specific API call pattern.

### Shared-grid Voxelization
**Definition:** Workflow where multiple meshes are voxelized onto a single, explicitly defined voxel grid, typically defined by the largest or outer mesh [S3, unofficial].

**Steps:**
1.  **Build Shared Grid:** Load the outer mesh. Call `build_voxelization_grid(outer_mesh, voxel_size=voxel_size, pixel_size=pixel_size)` to create `shared_grid`. Calculate the translation vector `translation_xyz = (outer_mesh.center - inner_mesh.center).astype(np.float32)` [S3, unofficial].
2.  **Voxelize Outer Mesh:** Call `voxelize_on_grid(outer_mesh, grid=shared_grid, mode="solid")` to produce `outer_grid` [S3, unofficial].
3.  **Voxelize Inner Mesh:** Call `voxelize_on_grid(inner_mesh, grid=shared_grid, mode="solid", translation_xyz=translation_xyz)` to produce `inner_grid`, applying the translation to align it with the outer mesh's coordinate system [S3, unofficial].

**Parameters:**
-   `mode` (str, default "solid"): Passed to `voxelize_on_grid`, specifies solid voxelization [S3, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(W \times H \times D)$, where $W, H, D$ are grid dimensions. Each voxel requires a constant number of operations (coordinate transformation, SDF evaluation, storage) [S1, unofficial].
-   **Memory Complexity:** $O(W \times H \times D)$ for storage. Using `bool` arrays is memory inefficient (1 byte per voxel) compared to bit-packed representations [S2, unofficial].
-   **Performance:** Performance is heavily dependent on the cost of the SDF evaluation or ray-casting per voxel. For complex meshes, BVH acceleration structures can speed up ray intersection during voxelization [S3, unofficial].
-   **Strengths:** Simple data structure, easy to implement, supports arbitrary shapes via SDFs [S1, unofficial].
-   **Limitations:** Memory usage grows cubically with resolution. Out-of-bounds access handling requires explicit checks or large default values [S1, unofficial]. Boolean storage is inefficient [S2, unofficial].
-   **When to Use:** When a dense, regular grid representation is required for volume rendering or collision detection.
-   **When Not to Use:** For highly sparse scenes where sparse voxel octrees or instanced rendering are more efficient [S1, S3, unofficial].

## Background
Voxelization is a fundamental technique in computer graphics, originating from the need to rasterize 3D geometry into a volume representation. Early implementations used simple ray casting or bounding box checks. Modern implementations often leverage Signed Distance Functions (SDFs) for smooth representation and BVH acceleration for efficient mesh intersection [S1, S3, unofficial]. The specific implementations cited here are from open-source projects: IsosurfaceExtraction [S1, unofficial], OBJ-Solidizer-And-Voxelizer [S2, unofficial], and Voxelerate [S3, unofficial].
