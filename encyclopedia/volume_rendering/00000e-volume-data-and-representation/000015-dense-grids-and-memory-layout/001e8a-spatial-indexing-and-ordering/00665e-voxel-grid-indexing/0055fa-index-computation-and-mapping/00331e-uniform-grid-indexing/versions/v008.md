# Uniform Grid Indexing

Also called: 3D Grid Index Calculation, 3D to 1D Grid Mapping, Froxel Index Calculation, Position Index Calculation, getPositionIndex

## Overview
Uniform Grid Indexing maps a continuous 3D world position $\mathbf{p}$ to a discrete linear array index $I$ within a uniform voxel grid. It solves the problem of spatial lookup in dense volume representations by converting geometric coordinates into memory offsets. It sets itself apart from [Voxel Index Computation](13870-voxel-index-computation.md) by assuming a strictly regular, axis-aligned bounding box (AABB) with uniform cell sizes, and from [Uniform Grid Adjacent Cell Indexing](2992-uniform-grid-adjacent-cell-indexing.md) by focusing on the primary lookup rather than neighborhood traversal.

## How it works
**Inputs:**
- $\mathbf{p} = (p_x, p_y, p_z)$: Continuous world position.
- $\mathbf{b}_{min} = (b_{min,x}, b_{min,y}, b_{min,z})$: Minimum bound of the grid's AABB.
- $\mathbf{b}_{max} = (b_{max,x}, b_{max,y}, b_{max,z})$: Maximum bound of the grid's AABB.
- $N_x, N_y, N_z$: Number of divisions (cells) along each axis.
- $\mathbf{s} = (s_x, s_y, s_z)$: Voxel size (cell dimensions). Note: $\mathbf{s}$ is often derived from $\mathbf{b}_{max} - \mathbf{b}_{min}$ and $N$.

**Outputs:**
- $I$: Linear 1D index into the voxel array.

**Data Structures:**
- The grid is stored as a 1D array of size $N_x \cdot N_y \cdot N_z$.
- Memory layout is row-major (Z-major or Y-major depending on convention, but standard row-major in 3D usually implies $I = i \cdot N_y N_z + j \cdot N_z + k$ where $i,j,k$ correspond to $x,y,z$). The sources indicate a specific mapping where $X$ is the fastest varying index (inner loop), $Y$ is middle, and $Z$ is slowest (outer loop).

**Steps:**
1.  **Boundary Check**: If the grid has only one cell ($N_x=N_y=N_z=1$), return 0 [S3, unofficial].
2.  **Coordinate Transformation**: Calculate the relative position of $\mathbf{p}$ with respect to $\mathbf{b}_{min}$:
    $$ \mathbf{p}_{rel} = \mathbf{p} - \mathbf{b}_{min} $$
3.  **Normalization**: Normalize $\mathbf{p}_{rel}$ to the range $[0, 1]$ by dividing by the total extent $\mathbf{E} = \mathbf{b}_{max} - \mathbf{b}_{min}$. Handle division by zero if any extent component is negligible (e.g., using a small epsilon `KINDA_SMALL_NUMBER`) [S3, unofficial].
    $$ \mathbf{p}_{norm} = \frac{\mathbf{p}_{rel}}{\mathbf{E}} $$
4.  **Scaling**: Scale the normalized coordinates by the number of divisions to get floating-point cell coordinates:
    $$ \mathbf{c}_{float} = \mathbf{p}_{norm} \cdot (N_x, N_y, N_z) $$
5.  **Discretization**: Apply the floor operation to obtain integer grid coordinates $(i, j, k)$:
    $$ i = \lfloor c_{float,x} \rfloor, \quad j = \lfloor c_{float,y} \rfloor, \quad k = \lfloor c_{float,z} \rfloor $$
6.  **Clamping**: Clamp $(i, j, k)$ to the valid range $[0, N_x-1] \times [0, N_y-1] \times [0, N_z-1]$ to handle points outside the AABB [S1, S3, unofficial].
7.  **Linearization**: Compute the linear index using row-major ordering. Based on [S2, unofficial] and [S1, unofficial], the formula is:
    $$ I = i \cdot (N_y \cdot N_z) + j \cdot N_z + k $$
    *Note: [S1, unofficial] defines the formula as $x \cdot N_y N_z + y \cdot N_z + z$, where $x,y,z$ are the clamped integer indices. [S2, unofficial] uses $X + Y \cdot GridX + Z \cdot GridX \cdot GridY$. These are transposes of each other depending on whether X or Z is the fastest varying dimension. The code in [S3, unofficial] implies $Z$ is the slowest (outermost) dimension because it is multiplied by the largest stride ($N_x^2$ if cubic).*

**Pseudocode:**
```python
def uniform_grid_indexing(position, bounds_min, bounds_max, num_divs):
    """
    Maps a 3D position to a linear index in a uniform grid.
    
    Args:
        position: tuple (x, y, z)
        bounds_min: tuple (min_x, min_y, min_z)
        bounds_max: tuple (max_x, max_y, max_z)
        num_divs: tuple (Nx, Ny, Nz)
        
    Returns:
        int: Linear index
    """
    Nx, Ny, Nz = num_divs
    
    # Handle single cell case
    if Nx == 1 and Ny == 1 and Nz == 1:
        return 0

    # Calculate extents
    extent_x = bounds_max[0] - bounds_min[0]
    extent_y = bounds_max[1] - bounds_min[1]
    extent_z = bounds_max[2] - bounds_min[2]
    
    # Small epsilon to prevent division by zero
    EPS = 1e-9
    
    # Relative position
    rel_x = position[0] - bounds_min[0]
    rel_y = position[1] - bounds_min[1]
    rel_z = position[2] - bounds_min[2]
    
    # Normalize to [0, 1]
    # Note: If extent is 0, clamp relative to 0 to avoid NaN/Inf, 
    # though typically bounds_min != bounds_max.
    norm_x = rel_x / extent_x if extent_x > EPS else 0.0
    norm_y = rel_y / extent_y if extent_y > EPS else 0.0
    norm_z = rel_z / extent_z if extent_z > EPS else 0.0
    
    # Scale to grid coordinates
    float_i = norm_x * Nx
    float_j = norm_y * Ny
    float_k = norm_z * Nz
    
    # Floor to integer indices
    i = int(float_i)
    j = int(float_j)
    k = int(float_k)
    
    # Clamp to valid range [0, N-1]
    i = max(0, min(i, Nx - 1))
    j = max(0, min(j, Ny - 1))
    k = max(0, min(k, Nz - 1))
    
    # Linearize (Row-major: X is fastest, Z is slowest)
    # Formula from [S1, unofficial]: index = x * Ny * Nz + y * Nz + z
    linear_index = i * (Ny * Nz) + j * Nz + k
    
    return linear_index
```

**Parameters:**
- `KINDA_SMALL_NUMBER`: A small epsilon value (e.g., $10^{-9}$) used to avoid division by zero when grid extents are zero [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Division by Zero**: If any dimension of the bounding box has zero size, the normalization step fails. Guard against this with an epsilon check [S3, unofficial].
- **Out-of-Bounds**: Points outside the AABB must be clamped, not rejected, to ensure valid memory access [S1, S3, unofficial].
- **Precision**: Floating-point inaccuracies near cell boundaries can cause jitter. Using `floor` is standard, but `round` might be used in specific variants. The sources specify `floor` [S3, unofficial].

## Subtopics

### [Regular Grid Decomposition](7659-regular-grid-decomposition.md)
Regular Grid Decomposition is a spatial partitioning strategy for neural volume rendering where the global scene domain is divided into a uniform 3D grid of independent neural network models, each responsible for a specific sub-region. It solves the problem of representing large-scale or complex scenes by distributing the modeling capacity across multiple smaller networks rather than relying on a single global model. Unlike [Compact Grid Method](9891-compact-grid-method.md), which adapts grid density to data sparsity, Regular Grid Decomposition uses a fixed, homogeneous grid structure, which simplifies the inference pipeline but requires significantly more regions to achieve comparable accuracy in non-homogeneous scenes.

### [Compact Grid Method](9891-compact-grid-method.md)
The Compact Grid Method is a static data structure for representing a uniform grid acceleration structure with minimal memory requirements: exactly one index per grid cell and exactly one index per object reference, built in linear time. It solves the problem of efficiently mapping objects to grid cells for ray tracing without the memory overhead of linked lists or dynamic arrays. It sets itself apart from its siblings by using a two-pass counting-sort-like algorithm to pack object indices into a single contiguous array, managed by a cell offset array that defines list boundaries implicitly, avoiding null pointers or extra tracking arrays.

### [MAP Grid Sampling and Filtering](15864-map-grid-sampling-and-filtering.md)
MAP is a program that constructs a rectangular grid from irregular input data and samples it using either Z-Buffer or A-Buffer techniques, applying optional filtering. It differs from its siblings by explicitly supporting variable plane spacing and specific filtering modes (Gaussian or density weighting) within the A-Buffer framework, whereas Z-Buffer sampling does not specify filtering in this context.

## Operating characteristics
- **Time Complexity**: $O(1)$ arithmetic operations. The mapping involves a constant number of subtractions, divisions, multiplications, and comparisons.
- **Memory Complexity**: $O(1)$ auxiliary space. No additional data structures are required beyond the grid bounds and dimensions.
- **Strengths**: Extremely fast lookup; simple implementation; cache-friendly if the grid is accessed sequentially or with spatial locality.
- **Limitations**: Memory usage scales with the cube of the resolution ($N^3$), making it inefficient for sparse data or very large domains. It cannot represent non-uniform voxel sizes.
- **When to use**: Dense volume rendering, collision detection in uniform spaces, or when the scene fits within a reasonable bounding box with uniform detail.
- **When not to use**: Sparse scenes (use [Compact Grid Method](9891-compact-grid-method.md) or octrees), or scenes with highly varying feature scales (use adaptive grids).

## Background
Uniform grid indexing is a fundamental technique in computer graphics and computational geometry, dating back to the early days of voxel-based rendering and spatial partitioning. It is widely used in ray tracing acceleration structures, volume visualization, and physics simulations. The specific implementation details involving "froxels" and Unreal Engine contexts are popularized in modern real-time rendering techniques for global illumination and light propagation volumes [S2, S3, unofficial]. The method is standard in libraries like VoxelFragmentML for efficient voxel data management [S1, unofficial].
