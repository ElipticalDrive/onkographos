# Uniform Grid Indexing

Also called: 3D Grid Index Calculation, 3D to 1D Grid Mapping, Froxel Index Calculation, Position Index Calculation, getPositionIndex

## Overview
Uniform Grid Indexing maps a continuous 3D world position $\mathbf{p}$ to a discrete 1D linear array index $I$ within a fixed-resolution volumetric grid. It solves the problem of spatial lookup in dense voxel representations by converting geometric coordinates into memory offsets. It sets itself apart from [Voxel Index Computation](13870-voxel-index-computation.md) by assuming a strictly uniform, axis-aligned bounding box (AABB) with constant voxel dimensions, whereas [Voxel Index Computation] may handle irregular or sparse structures. It differs from [Uniform Grid Adjacent Cell Indexing](2992-uniform-grid-adjacent-cell-indexing.md) by computing the primary cell index rather than neighbor offsets.

## How it works
**Inputs:**
- $\mathbf{p} = (p_x, p_y, p_z)$: Continuous world position.
- $\mathbf{b}_{min} = (b_{min,x}, b_{min,y}, b_{min,z})$: Minimum corner of the grid's AABB.
- $\mathbf{b}_{max} = (b_{max,x}, b_{max,y}, b_{max,z})$: Maximum corner of the grid's AABB.
- $N_x, N_y, N_z$: Integer number of divisions (voxels) along each axis.

**Outputs:**
- $I$: Linear 1D index into the voxel array.

**Data Structures:**
The grid is stored as a 1D array of size $N_x \cdot N_y \cdot N_z$. The memory layout is row-major (Z-major in some contexts, but consistent with the formula $I = i \cdot S_y S_z + j \cdot S_z + k$ where $i,j,k$ correspond to X,Y,Z).

**Steps:**
1.  **Validate Bounds**: Check if the position is within the grid bounds. If $p_x < b_{min,x}$ or $p_x \ge b_{max,x}$ (and similarly for $y, z$), the position is outside. Handle via clamping or error return [S2, S3, unofficial].
2.  **Handle Single Cell**: If $N_x = N_y = N_z = 1$, return $0$ immediately [S3, unofficial].
3.  **Translate**: Compute relative position $\mathbf{r} = \mathbf{p} - \mathbf{b}_{min}$ [S3, unofficial].
4.  **Normalize**: Normalize $\mathbf{r}$ to the range $[0, 1]$ per axis. To avoid division by zero, use a small epsilon $\epsilon$ if $\mathbf{b}_{max} - \mathbf{b}_{min}$ is near zero [S3, unofficial].
    $$ \hat{r}_x = \frac{r_x}{b_{max,x} - b_{min,x}}, \quad \hat{r}_y = \frac{r_y}{b_{max,y} - b_{min,y}}, \quad \hat{r}_z = \frac{r_z}{b_{max,z} - b_{min,z}} $$
5.  **Scale**: Multiply normalized coordinates by the number of divisions to get floating-point cell coordinates [S3, unofficial]:
    $$ c_x = \hat{r}_x \cdot N_x, \quad c_y = \hat{r}_y \cdot N_y, \quad c_z = \hat{r}_z \cdot N_z $$
6.  **Discretize**: Apply floor operation to get integer grid coordinates $(i, j, k)$ [S3, unofficial]:
    $$ i = \lfloor c_x \rfloor, \quad j = \lfloor c_y \rfloor, \quad k = \lfloor c_z \rfloor $$
7.  **Clamp**: Clamp indices to valid range $[0, N-1]$ to handle boundary cases where $\mathbf{p}$ is exactly at $\mathbf{b}_{max}$ or slightly outside due to precision [S1, S3, unofficial]:
    $$ i = \text{clamp}(i, 0, N_x - 1) $$
    $$ j = \text{clamp}(j, 0, N_y - 1) $$
    $$ k = \text{clamp}(k, 0, N_z - 1) $$
8.  **Linearize**: Compute the 1D index using row-major ordering (X varies fastest, Z slowest, or as defined by the stride formula) [S1, S2, S3, unofficial]:
    $$ I = i \cdot (N_y \cdot N_z) + j \cdot N_z + k $$

**Formula:**
Combining the steps, the direct formula for the index $I$ given position $\mathbf{p}$ is [S1, S3, unofficial]:
$$ I = \text{clamp}\left(\left\lfloor \frac{\mathbf{p} - \mathbf{b}_{min}}{\mathbf{b}_{max} - \mathbf{b}_{min}} \cdot \mathbf{N} \right\rfloor, 0, \mathbf{N} - 1\right) \cdot \text{Strides} $$
Explicitly for each axis $x,y,z$ with $N_x, N_y, N_z$:
$$ i = \text{clamp}\left(\left\lfloor \frac{p_x - b_{min,x}}{b_{max,x} - b_{min,x}} \cdot N_x \right\rfloor, 0, N_x - 1\right) $$
$$ j = \text{clamp}\left(\left\lfloor \frac{p_y - b_{min,y}}{b_{max,y} - b_{min,y}} \cdot N_y \right\rfloor, 0, N_y - 1\right) $$
$$ k = \text{clamp}\left(\left\lfloor \frac{p_z - b_{min,z}}{b_{max,z} - b_{min,z}} \cdot N_z \right\rfloor, 0, N_z - 1\right) $$
$$ I = i \cdot N_y \cdot N_z + j \cdot N_z + k $$

**Pseudocode:**
```python
def uniform_grid_index(p_x, p_y, p_z, b_min_x, b_min_y, b_min_z, 
                       b_max_x, b_max_y, b_max_z, N_x, N_y, N_z):
    # Handle single cell case
    if N_x == 1 and N_y == 1 and N_z == 1:
        return 0

    # Calculate box sizes
    size_x = b_max_x - b_min_x
    size_y = b_max_y - b_min_y
    size_z = b_max_z - b_min_z

    # Handle division by zero with epsilon
    EPSILON = 1e-9
    if size_x < EPSILON: size_x = EPSILON
    if size_y < EPSILON: size_y = EPSILON
    if size_z < EPSILON: size_z = EPSILON

    # Translate and normalize
    rel_x = (p_x - b_min_x) / size_x
    rel_y = (p_y - b_min_y) / size_y
    rel_z = (p_z - b_min_z) / size_z

    # Scale to grid coordinates
    c_x = rel_x * N_x
    c_y = rel_y * N_y
    c_z = rel_z * N_z

    # Floor to integer indices
    i = int(c_x)
    j = int(c_y)
    k = int(c_z)

    # Clamp to valid range [0, N-1]
    if i < 0: i = 0
    elif i >= N_x: i = N_x - 1
    
    if j < 0: j = 0
    elif j >= N_y: j = N_y - 1
    
    if k < 0: k = 0
    elif k >= N_z: k = N_z - 1

    # Linearize (Row-major: X varies fastest, then Y, then Z)
    # Formula: I = i * (Ny * Nz) + j * Nz + k
    linear_index = i * (N_y * N_z) + j * N_z + k
    
    return linear_index
```

**Parameters:**
- $N_x, N_y, N_z$: Grid resolution. Typical values depend on scene scale and required detail (e.g., $64^3$ to $256^3$).
- $\epsilon$: Small constant for numerical stability (e.g., $10^{-9}$) [S3, unofficial].

**Edge Cases:**
- **Position at $\mathbf{b}_{max}$**: Without clamping, the normalized coordinate becomes $1.0$, scaling to $N$, and flooring to $N$, which is out of bounds. Clamping fixes this [S1, S3, unofficial].
- **Zero-sized Box**: Division by zero if $\mathbf{b}_{min} = \mathbf{b}_{max}$. Handled by epsilon check [S3, unofficial].
- **Outside Bounds**: Positions outside the AABB are clamped to the nearest valid cell [S1, S3, unofficial].

## Subtopics

### [Regular Grid Decomposition](7659-regular-grid-decomposition.md)
Regular Grid Decomposition is a spatial partitioning strategy for neural volume rendering where the global scene domain is divided into a uniform 3D grid of independent neural network models, each responsible for a specific sub-region. It solves the problem of representing large-scale or complex scenes by distributing the modeling capacity across multiple smaller networks rather than relying on a single global model. Unlike [Compact Grid Method](9891-compact-grid-method.md), which adapts grid density to data sparsity, Regular Grid Decomposition uses a fixed, homogeneous grid structure, which simplifies the inference pipeline but requires significantly more regions to achieve comparable accuracy in non-homogeneous scenes.

### [Compact Grid Method](9891-compact-grid-method.md)
The Compact Grid Method is a static data structure for representing a uniform grid acceleration structure with minimal memory requirements: exactly one index per grid cell and exactly one index per object reference, built in linear time. It solves the problem of efficiently mapping objects to grid cells for ray tracing without the memory overhead of linked lists or dynamic arrays. It sets itself apart from its siblings by using a two-pass counting-sort-like algorithm to pack object indices into a single contiguous array, managed by a cell offset array that defines list boundaries implicitly, avoiding null pointers or extra tracking arrays.

## Operating characteristics
- **Time Complexity**: $O(1)$ for index calculation. It involves a constant number of arithmetic operations (subtractions, divisions, multiplications, floor, clamp).
- **Memory Complexity**: $O(1)$ auxiliary space. The grid itself requires $O(N_x N_y N_z)$ memory, but the indexing method does not add overhead.
- **Performance**: Extremely fast, suitable for real-time ray marching or voxel traversal. The primary cost is the floating-point division and clamp operations.
- **Strengths**: Simple implementation, cache-friendly linear access pattern (row-major), no pointer chasing.
- **Limitations**: Memory usage grows cubically with resolution. Not suitable for highly sparse data where most cells are empty. Boundary handling requires explicit clamping.
- **When to use**: Dense volumetric data, uniform voxel grids, real-time rendering.
- **When not to use**: Sparse data (use [Voxel Index Computation](13870-voxel-index-computation.md) or sparse structures), non-uniform voxel sizes.

## Background
Uniform Grid Indexing is a fundamental technique in volume rendering and spatial data structures. It originates from the need to efficiently access voxel data in computer graphics, medical imaging, and scientific visualization. The method is widely used in ray marching algorithms, where a ray's position is continuously mapped to voxel indices to sample density or color. The specific implementation details, such as clamping and epsilon handling, are common in game engine implementations (e.g., Unreal Engine's Froxel system) and voxel-based ML frameworks [S1, S2, S3, unofficial].
