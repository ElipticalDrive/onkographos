# Uniform Grid Indexing

Also called: 3D Grid Index Calculation, 3D to 1D Grid Mapping, Froxel Index Calculation, Position Index Calculation, getPositionIndex

## Overview
Uniform Grid Indexing converts a continuous 3D world position into a discrete 1D linear array index within a uniform voxel grid, enabling efficient memory access for dense volume data [S1, S2, unofficial]. It solves the problem of mapping spatial coordinates to a flat memory layout by combining coordinate transformation (translation, scaling, discretization) with row-major linearization [S1, S2, unofficial]. Unlike [Voxel Index Computation](13870-voxel-index-computation.md), which may handle sparse or irregular structures, this method assumes a fixed, homogeneous grid where strides are derived directly from grid dimensions [S1, S2, unofficial].

## How it works
**Inputs:**
- `position`: A 3D vector $(p_x, p_y, p_z)$ representing the world coordinate.
- `boundsMin`: A 3D vector $(b_{min,x}, b_{min,y}, b_{min,z})$ defining the minimum corner of the grid's axis-aligned bounding box (AABB).
- `boundsMax`: A 3D vector $(b_{max,x}, b_{max,y}, b_{max,z})$ defining the maximum corner of the AABB.
- `cellsPerEdge`: An integer $N$ representing the number of divisions along each axis (assuming a cubic grid where $N_x = N_y = N_z = N$) [S3, unofficial]. Alternatively, separate dimensions $N_x, N_y, N_z$ may be provided [S1, unofficial].

**Outputs:**
- `linearIndex`: A single integer representing the position in the 1D array.

**Data Structures:**
- The grid is stored as a 1D array of size $N_x \times N_y \times N_z$ (or $N^3$ for cubic grids).
- Indices are 0-based integers.

**Steps:**
1.  **Validate Bounds**: Ensure the input position is within or near the grid bounds. If the grid has only one cell ($N=1$), return index 0 immediately [S3, unofficial].
2.  **Calculate Grid Dimensions**: Determine the number of divisions per axis. If `cellsPerEdge` is used, $N_x = N_y = N_z = \text{cellsPerEdge}$ [S3, unofficial]. Otherwise, use explicit $N_x, N_y, N_z$ [S1, unofficial].
3.  **Translate**: Compute the relative position of the point with respect to the grid's minimum bound:
    $$ \mathbf{p}_{rel} = \mathbf{p} - \mathbf{b}_{min} $$
4.  **Scale**: Normalize the relative position to the range $[0, 1]$ by dividing by the grid dimensions (or voxel size). If using `cellsPerEdge`, the voxel size is derived from the bounding box size:
    $$ \mathbf{s} = \frac{\mathbf{b}_{max} - \mathbf{b}_{min}}{N} $$
    $$ \mathbf{c}_{float} = \frac{\mathbf{p}_{rel}}{\mathbf{s}} $$
    *Note*: Handle division by zero if any dimension of the bounding box is zero, typically by treating it as a small epsilon or returning a default index [S3, unofficial].
5.  **Discretize**: Convert floating-point coordinates to integer grid indices using the floor operation:
    $$ i = \lfloor c_{float,x} \rfloor, \quad j = \lfloor c_{float,y} \rfloor, \quad k = \lfloor c_{float,z} \rfloor $$
6.  **Clamp**: Clamp the integer indices to the valid range $[0, N-1]$ to prevent out-of-bounds access for points outside the AABB [S1, S3, unofficial]:
    $$ i = \text{clamp}(i, 0, N_x - 1) $$
    $$ j = \text{clamp}(j, 0, N_y - 1) $$
    $$ k = \text{clamp}(k, 0, N_z - 1) $$
7.  **Linearize**: Compute the 1D index using row-major ordering (X is fastest, Z is slowest):
    $$ I = i \cdot N_y \cdot N_z + j \cdot N_z + k $$
    For a cubic grid with $N_x=N_y=N_z=N$:
    $$ I = k \cdot N^2 + j \cdot N + i $$

**Pseudocode:**
```python
def uniform_grid_indexing(position, bounds_min, bounds_max, cells_per_edge):
    """
    Computes the 1D linear index for a 3D position in a uniform grid.
    
    Args:
        position: tuple (x, y, z) of floats
        bounds_min: tuple (x, y, z) of floats
        bounds_max: tuple (x, y, z) of floats
        cells_per_edge: int, number of divisions per axis (assumes cubic grid)
        
    Returns:
        int: linear index in the 1D array
    """
    # Handle single cell case
    if cells_per_edge == 1:
        return 0
    
    # Calculate grid dimensions
    nx = cells_per_edge
    ny = cells_per_edge
    nz = cells_per_edge
    
    # Calculate bounding box size
    box_size_x = bounds_max[0] - bounds_min[0]
    box_size_y = bounds_max[1] - bounds_min[1]
    box_size_z = bounds_max[2] - bounds_min[2]
    
    # Handle division by zero (e.g., zero-sized dimension)
    # Using a small epsilon to avoid division by zero
    epsilon = 1e-9
    if box_size_x < epsilon: box_size_x = epsilon
    if box_size_y < epsilon: box_size_y = epsilon
    if box_size_z < epsilon: box_size_z = epsilon
    
    # Translate position relative to boundsMin
    rel_x = position[0] - bounds_min[0]
    rel_y = position[1] - bounds_min[1]
    rel_z = position[2] - bounds_min[2]
    
    # Normalize relative position to [0, 1] range per axis
    norm_x = rel_x / box_size_x
    norm_y = rel_y / box_size_y
    norm_z = rel_z / box_size_z
    
    # Scale normalized position by cellsPerEdge to get floating-point cell coordinates
    scaled_x = norm_x * cells_per_edge
    scaled_y = norm_y * cells_per_edge
    scaled_z = norm_z * cells_per_edge
    
    # Floor the scaled position to get integer 3D grid cell indices
    cell_x = int(scaled_x)
    cell_y = int(scaled_y)
    cell_z = int(scaled_z)
    
    # Clamp cell indices to valid range [0, cellsPerEdge - 1]
    cell_x = max(0, min(cell_x, cells_per_edge - 1))
    cell_y = max(0, min(cell_y, cells_per_edge - 1))
    cell_z = max(0, min(cell_z, cells_per_edge - 1))
    
    # Calculate linear index using row-major order
    # I = Z * (X * Y) + Y * X + X
    # For cubic grid: I = Z * N^2 + Y * N + X
    linear_index = cell_z * (cells_per_edge * cells_per_edge) + cell_y * cells_per_edge + cell_x
    
    return linear_index
```

**Parameters:**
- `cellsPerEdge`: Typical values depend on the scene scale and required resolution. Common values range from 16 to 1024 for real-time applications [S3, unofficial].
- `boundsMin/Max`: Defined by the scene's spatial extent.

**Edge Cases and Pitfalls:**
- **Out-of-Bounds**: Points outside the AABB must be clamped, not rejected, to avoid crashes [S1, S3, unofficial].
- **Zero-Dimension Bounds**: If any dimension of the bounding box is zero, division by zero occurs. A small epsilon should be used [S3, unofficial].
- **Precision**: Floating-point precision errors may cause points exactly on grid boundaries to flip between cells. Clamping after flooring mitigates this [S1, S3, unofficial].

## Subtopics

### [Regular Grid Decomposition](7659-regular-grid-decomposition.md)
Regular Grid Decomposition is a spatial partitioning strategy for neural volume rendering where the global scene domain is divided into a uniform 3D grid of independent neural network models, each responsible for a specific sub-region. It solves the problem of representing large-scale or complex scenes by distributing the modeling capacity across multiple smaller networks rather than relying on a single global model. Unlike [Compact Grid Method](9891-compact-grid-method.md), which adapts grid density to data sparsity, Regular Grid Decomposition uses a fixed, homogeneous grid structure, which simplifies the inference pipeline but requires significantly more regions to achieve comparable accuracy in non-homogeneous scenes.

### [Compact Grid Method](9891-compact-grid-method.md)
The Compact Grid Method is a static data structure for representing a uniform grid acceleration structure with minimal memory requirements: exactly one index per grid cell and exactly one index per object reference, built in linear time. It solves the problem of efficiently mapping objects to grid cells for ray tracing without the memory overhead of linked lists or dynamic arrays. It sets itself apart from its siblings by using a two-pass counting-sort-like algorithm to pack object indices into a single contiguous array, managed by a cell offset array that defines list boundaries implicitly, avoiding null pointers or extra tracking arrays.

### [MAP Grid Sampling and Filtering](15864-map-grid-sampling-and-filtering.md)
MAP is a program that constructs a rectangular grid from irregular input data and samples it using either Z-Buffer or A-Buffer techniques, applying optional filtering. It differs from its siblings by explicitly supporting variable plane spacing and specific filtering modes (Gaussian or density weighting) within the A-Buffer framework, whereas Z-Buffer sampling does not specify filtering in this context.

## Operating characteristics
- **Time Complexity**: $O(1)$ for index calculation, as it involves a fixed number of arithmetic operations [S1, S2, unofficial].
- **Memory Complexity**: $O(N^3)$ for storing the grid data, where $N$ is the number of divisions per axis [S1, S2, unofficial].
- **Performance**: Extremely fast due to simple arithmetic and no branching (except for clamping) [S1, S2, unofficial].
- **Strengths**: Simple implementation, cache-friendly for sequential access, efficient for dense data [S1, S2, unofficial].
- **Limitations**: Memory usage grows cubically with resolution, making it inefficient for sparse data or very high resolutions [S1, S2, unofficial].
- **When to Use**: Dense volume rendering, real-time applications with moderate resolution, uniform data distribution [S1, S2, unofficial].
- **When Not to Use**: Sparse data, very high resolution requirements, scenes with large empty spaces [S1, S2, unofficial].

## Background
Uniform Grid Indexing is a fundamental technique in volume rendering and computer graphics, originating from the need to efficiently access 3D data stored in 1D memory arrays. It is widely used in voxel-based rendering, ray marching, and spatial partitioning [S1, S2, unofficial]. The method is often associated with early voxel graphics and has been adopted in modern real-time rendering engines for its simplicity and performance [S1, S2, unofficial].
