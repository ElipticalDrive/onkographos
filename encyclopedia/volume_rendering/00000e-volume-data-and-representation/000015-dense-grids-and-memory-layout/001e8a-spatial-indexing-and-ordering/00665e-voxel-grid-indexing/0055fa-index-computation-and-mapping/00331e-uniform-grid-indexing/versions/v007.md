# Uniform Grid Indexing

Also called: 3D Grid Index Calculation, 3D to 1D Grid Mapping, Froxel Index Calculation, Position Index Calculation, getPositionIndex

## Overview
Uniform Grid Indexing maps a continuous 3D world position $\mathbf{p}$ to a discrete 1D linear index $I$ within a fixed-size, axis-aligned voxel grid. It solves the problem of spatial lookup in dense volumetric data by converting geometric coordinates into array offsets using affine transformation and row-major linearization. It sets itself apart from its siblings by relying on a strictly uniform grid structure with fixed cell dimensions, unlike [Voxel Index Computation](13870-voxel-index-computation.md) which may handle variable or sparse structures, and [Uniform Grid Adjacent Cell Indexing](2992-uniform-grid-adjacent-cell-indexing.md) which focuses on neighbor traversal rather than primary position mapping.

## How it works
**Inputs:**
- $\mathbf{p} = (p_x, p_y, p_z)$: The 3D world position to map.
- $\mathbf{b}_{min} = (b_{min,x}, b_{min,y}, b_{min,z})$: The minimum corner of the grid's bounding box (AABB).
- $\mathbf{b}_{max} = (b_{max,x}, b_{max,y}, b_{max,z})$: The maximum corner of the grid's bounding box.
- $N_x, N_y, N_z$: The number of divisions (cells) along the X, Y, and Z axes. Alternatively, a single scalar $N$ if the grid is cubic ($N_x=N_y=N_z=N$).
- $\epsilon$: A small constant to prevent division by zero (e.g., `KINDA_SMALL_NUMBER` or machine epsilon) [S3, unofficial].

**Outputs:**
- $I$: A single integer representing the linear index in the 1D array.

**Data Structures:**
- The grid is stored as a 1D array of size $N_x \cdot N_y \cdot N_z$.
- Memory layout is row-major (Z-major in some contexts, see formula below).

**Steps:**
1.  **Handle Degenerate Grid:** If any dimension has size 1 (e.g., $N_x=1, N_y=1, N_z=1$), return index 0 immediately [S3, unofficial].
2.  **Calculate Bounding Box Size:** Compute the physical size of the grid along each axis:
    $$ \mathbf{S} = \mathbf{b}_{max} - \mathbf{b}_{min} $$
    $$ S_x = b_{max,x} - b_{min,x}, \quad S_y = b_{max,y} - b_{min,y}, \quad S_z = b_{max,z} - b_{min,z} $$
3.  **Translate Position:** Compute the relative position of $\mathbf{p}$ with respect to the minimum bound:
    $$ \mathbf{p}_{rel} = \mathbf{p} - \mathbf{b}_{min} $$
    $$ p_{rel,x} = p_x - b_{min,x}, \quad \text{etc.} $$
4.  **Normalize:** Convert relative position to a $[0, 1]$ range. Guard against division by zero using $\epsilon$:
    $$ n_x = \frac{p_{rel,x}}{S_x + \epsilon}, \quad n_y = \frac{p_{rel,y}}{S_y + \epsilon}, \quad n_z = \frac{p_{rel,z}}{S_z + \epsilon} $$
    *Note: Some implementations clamp $n$ to $[0, 1]$ before scaling, or clamp the final integer index [S1, unofficial].*
5.  **Scale to Grid Coordinates:** Multiply normalized coordinates by the number of divisions to get floating-point cell coordinates:
    $$ c_x = n_x \cdot N_x, \quad c_y = n_y \cdot N_y, \quad c_z = n_z \cdot N_z $$
6.  **Discretize (Floor):** Convert to integer grid coordinates $(i, j, k)$ by flooring:
    $$ i = \lfloor c_x \rfloor, \quad j = \lfloor c_y \rfloor, \quad k = \lfloor c_z \rfloor $$
7.  **Clamp:** Ensure indices are within valid bounds $[0, N-1]$ to handle points outside the AABB:
    $$ i = \text{clamp}(i, 0, N_x - 1) $$
    $$ j = \text{clamp}(j, 0, N_y - 1) $$
    $$ k = \text{clamp}(k, 0, N_z - 1) $$
8.  **Linearize:** Compute the 1D index using row-major ordering. The specific stride order depends on the implementation's memory layout convention. Two common variants found in sources are:
    -   **Variant A (X-fastest, Z-slowest):** $I = i \cdot N_y \cdot N_z + j \cdot N_z + k$ [S1, unofficial].
    -   **Variant B (Z-fastest, X-slowest):** $I = k \cdot N_x \cdot N_y + j \cdot N_x + i$ [S2, unofficial].
    *Implementers must verify the stride order of their target grid storage. Variant A is explicitly cited in [S1, unofficial], Variant B in [S2, unofficial].*

**Pseudocode:**
```python
def uniform_grid_index(p, b_min, b_max, n_dims, epsilon=1e-9):
    """
    Maps a 3D position to a linear index in a uniform grid.
    
    Args:
        p: tuple (x, y, z) world position
        b_min: tuple (x, y, z) minimum bound
        b_max: tuple (x, y, z) maximum bound
        n_dims: tuple (Nx, Ny, Nz) number of cells per axis
        epsilon: float to prevent division by zero
        
    Returns:
        int: linear index
    """
    Nx, Ny, Nz = n_dims
    
    # Step 1: Handle single cell case
    if Nx == 1 and Ny == 1 and Nz == 1:
        return 0
        
    # Step 2: Calculate bounding box size
    Sx = b_max[0] - b_min[0]
    Sy = b_max[1] - b_min[1]
    Sz = b_max[2] - b_min[2]
    
    # Step 3 & 4: Translate and Normalize
    # Guard against zero size dimensions
    rx = (p[0] - b_min[0]) / (Sx + epsilon)
    ry = (p[1] - b_min[1]) / (Sy + epsilon)
    rz = (p[2] - b_min[2]) / (Sz + epsilon)
    
    # Step 5: Scale
    cx = rx * Nx
    cy = ry * Ny
    cz = rz * Nz
    
    # Step 6: Floor
    ix = int(cx) # floor
    iy = int(cy)
    iz = int(cz)
    
    # Step 7: Clamp
    ix = max(0, min(ix, Nx - 1))
    iy = max(0, min(iy, Ny - 1))
    iz = max(0, min(iz, Nz - 1))
    
    # Step 8: Linearize (Variant A from [S1, unofficial])
    # I = i * Ny * Nz + j * Nz + k
    index = ix * Ny * Nz + iy * Nz + iz
    
    return index
```

**Edge Cases and Pitfalls:**
-   **Division by Zero:** If the bounding box has zero extent in any dimension, division by $S_x, S_y, S_z$ will fail. The $\epsilon$ guard or explicit check is required [S3, unofficial].
-   **Out-of-Bounds:** Points outside the AABB must be clamped to the nearest valid cell index to avoid array out-of-bounds errors [S1, unofficial].
-   **Precision:** Floating-point inaccuracies near cell boundaries can cause jitter. Using `floor` is standard, but `round` may be used for center-based sampling.
-   **Stride Order:** The linearization formula is not universal. [S1, unofficial] uses $x \cdot N_y N_z + y \cdot N_z + z$, while [S2, unofficial] uses $z \cdot N_x N_y + y \cdot N_x + x$. The implementer must match the memory layout of the underlying array.

## Subtopics

### [Regular Grid Decomposition](7659-regular-grid-decomposition.md)
Regular Grid Decomposition is a spatial partitioning strategy for neural volume rendering where the global scene domain is divided into a uniform 3D grid of independent neural network models, each responsible for a specific sub-region. It solves the problem of representing large-scale or complex scenes by distributing the modeling capacity across multiple smaller networks rather than relying on a single global model. Unlike [Compact Grid Method](9891-compact-grid-method.md), which adapts grid density to data sparsity, Regular Grid Decomposition uses a fixed, homogeneous grid structure, which simplifies the inference pipeline but requires significantly more regions to achieve comparable accuracy in non-homogeneous scenes.

### [Compact Grid Method](9891-compact-grid-method.md)
The Compact Grid Method is a static data structure for representing a uniform grid acceleration structure with minimal memory requirements: exactly one index per grid cell and exactly one index per object reference, built in linear time. It solves the problem of efficiently mapping objects to grid cells for ray tracing without the memory overhead of linked lists or dynamic arrays. It sets itself apart from its siblings by using a two-pass counting-sort-like algorithm to pack object indices into a single contiguous array, managed by a cell offset array that defines list boundaries implicitly, avoiding null pointers or extra tracking arrays.

### [MAP Grid Sampling and Filtering](15864-map-grid-sampling-and-filtering.md)
MAP is a program that constructs a rectangular grid from irregular input data and samples it using either Z-Buffer or A-Buffer techniques, applying optional filtering. It differs from its siblings by explicitly supporting variable plane spacing and specific filtering modes (Gaussian or density weighting) within the A-Buffer framework, whereas Z-Buffer sampling does not specify filtering in this context.

## Operating characteristics
-   **Time Complexity:** $O(1)$ arithmetic operations. The mapping involves a constant number of subtractions, divisions, multiplications, and comparisons.
-   **Memory Complexity:** $O(1)$ auxiliary memory. No additional data structures are required for the indexing calculation itself.
-   **Strengths:** Extremely fast lookup; cache-friendly if the grid is accessed sequentially; simple implementation.
-   **Limitations:** Memory usage scales with $N_x N_y N_z$, leading to high memory consumption for high-resolution grids even if the scene is sparse. Not suitable for highly anisotropic or non-uniform data distributions without significant waste.
-   **When to Use:** Dense volumetric data with uniform distribution; real-time rendering where latency is critical; scenes with uniform resolution requirements.
-   **When Not to Use:** Sparse data (use sparse grids or octrees); highly anisotropic features (use adaptive grids).

## Background
Uniform grid indexing is a fundamental technique in computer graphics, originating from the need to accelerate ray tracing and volume rendering. The concept of mapping 3D coordinates to 1D arrays via row-major ordering is standard in linear algebra and memory management. Specific implementations like the "Froxel" indexing method are used in modern real-time rendering engines (e.g., Unreal Engine) for light propagation volumes and voxel-based lighting [S2, unofficial]. The method is closely related to the "Voxel Fragment" techniques used in neural rendering pipelines [S1, unofficial].
