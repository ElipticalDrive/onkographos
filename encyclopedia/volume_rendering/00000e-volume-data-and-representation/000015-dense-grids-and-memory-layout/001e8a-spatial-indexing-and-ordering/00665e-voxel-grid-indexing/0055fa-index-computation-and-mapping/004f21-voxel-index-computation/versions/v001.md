# Voxel Index Computation

Also called: ComputeIndex3, Index Computation (3-bit)

## Overview
Voxel Index Computation maps continuous 3D coordinates to discrete voxel grid indices, solving the problem of spatial localization for ray marching and point cloud queries in neural rendering. It differs from generic grid indexing by supporting batched bounding box constraints and optional coordinate shifts for half-voxel alignment [S1, unofficial], while a specialized variant computes compact 3-bit indices for texture coordinate interpolation [S2, unofficial].

## How it works
**Inputs:**
- `points`: Tensor of shape $(N, 3)$ containing 3D coordinates.
- `batch_ids`: Tensor of shape $(N)$ containing integer batch identifiers.
- `bounding_boxes`: Tensor of shape $(B, 1, 3)$ or $(B, 3)$, where $B$ is the number of batches. Represents the minimum corner of the voxel grid for each batch.
- `voxel_size`: Scalar or Tensor of shape $(B)$ or $(B, 3)$ representing the side length of a voxel.
- `shift`: Boolean flag. If true, applies a half-voxel offset to the bounding box minimums.
- `cat_batch_ids`: Boolean flag. If true, appends the batch ID to the output.

**Outputs:**
- `voxel_indices`: Tensor of shape $(N, 3)$ if `cat_batch_ids` is false, or $(N, 4)$ if true. Contains the integer voxel coordinates $(i, j, k)$.

**Data Structures:**
- Standard floating-point tensors for coordinates and sizes.
- Integer tensors for indices and batch IDs.

**Steps:**
1. **Select Bounding Box Minimums:** Retrieve the bounding box minimum for each point based on its batch ID.
   $$ \text{bb\_mins} = \text{bounding\_boxes}[\text{batch\_ids}][:, 0] $$
   [S1, unofficial]

2. **Retrieve Voxel Size:** Get the voxel size for each point. Handle scalar vs. tensor inputs.
   $$ \text{voxel\_size\_b} = \begin{cases} \text{voxel\_size}[\text{batch\_ids}] & \text{if voxel\_size is Tensor} \\ \text{voxel\_size} & \text{otherwise} \end{cases} $$
   [S1, unofficial]

3. **Broadcasting Expansion:** If the voxel size tensor is 1D (shape $(B)$), expand it to 2D (shape $(B, 1)$) to allow broadcasting against the 3D point coordinates.
   [S1, unofficial]

4. **Apply Shift (Optional):** If the `shift` flag is true, subtract half the voxel size from the bounding box minimums. This aligns the grid such that the center of the voxel at index 0 is at the bounding box corner.
   $$ \text{bb\_mins} = \text{bb\_mins} - 0.5 \times \text{voxel\_size\_b} $$
   [S1, unofficial]

5. **Compute Indices:** Calculate the integer voxel indices using floor division.
   $$ \text{voxel\_indices} = \lfloor (\text{points} - \text{bb\_mins}) / \text{voxel\_size\_b} \rfloor $$
   Cast the result to long integers.
   [S1, unofficial]

6. **Concatenate Batch ID (Optional):** If `cat_batch_ids` is true, concatenate the `batch_ids` tensor to `voxel_indices` along dimension 1.
   $$ \text{output} = \text{concat}(\text{voxel\_indices}, \text{batch\_ids}, \text{dim}=1) $$
   [S1, unofficial]

**Pseudocode:**
```python
import torch

def compute_voxel_indices(points, batch_ids, bounding_boxes, voxel_size, shift=False, cat_batch_ids=False):
    """
    Compute voxel indices for a batch of 3D points.
    
    Args:
        points: Tensor (N, 3)
        batch_ids: Tensor (N,)
        bounding_boxes: Tensor (B, 1, 3) or (B, 3)
        voxel_size: Scalar or Tensor (B,) or (B, 3)
        shift: bool
        cat_batch_ids: bool
        
    Returns:
        Tensor (N, 3) or (N, 4)
    """
    # Step 1: Select bounding box mins
    # Assuming bounding_boxes shape is (B, 1, 3) or (B, 3)
    # If (B, 3), we might need to unsqueeze to (B, 1, 3) for consistent indexing
    if bounding_boxes.dim() == 2:
        bb_mins = bounding_boxes[batch_ids]
    else:
        bb_mins = bounding_boxes[batch_ids][:, 0]
        
    # Step 2: Retrieve voxel size
    if isinstance(voxel_size, torch.Tensor):
        voxel_size_b = voxel_size[batch_ids]
    else:
        voxel_size_b = torch.full_like(points, voxel_size)
        
    # Step 3: Expand for broadcasting if 1D
    if isinstance(voxel_size_b, torch.Tensor) and voxel_size_b.dim() == 1:
        voxel_size_b = voxel_size_b.unsqueeze(-1)
        
    # Step 4: Apply shift
    if shift:
        bb_mins = bb_mins - 0.5 * voxel_size_b
        
    # Step 5: Compute indices
    # Ensure float division before floor
    voxel_indices = torch.floor((points - bb_mins) / voxel_size_b).long()
    
    # Step 6: Concatenate batch IDs
    if cat_batch_ids:
        batch_ids_expanded = batch_ids.unsqueeze(-1).long()
        output = torch.cat([voxel_indices, batch_ids_expanded], dim=1)
        return output
    else:
        return voxel_indices
```

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point errors in `points - bb_mins` can cause `floor` to snap to the wrong integer if the point is extremely close to a voxel boundary. [G] Use a small epsilon tolerance if boundary precision is critical.
- **Out of Bounds:** The method does not clamp indices to the grid dimensions. Points outside the bounding box will produce negative or excessively large indices. [G] Clamping should be applied if the grid has fixed dimensions.
- **Voxel Size Zero:** Division by zero if `voxel_size` is 0. [G] Validate input.

**3-Bit Index Variant:**
A separate computation exists for mapping a texel position relative to two endpoints (`end0`, `end1`) to a 3-bit index (0-7).
Formula:
$$ \text{index} = \text{clamp}\left(\text{round}\left(\frac{\text{texelPos} - \text{end0}}{\text{end1} - \text{end0}} \times 6.98182 + 0.00909 + 0.5\right), 0, 7\right) $$
[S2, unofficial]
This is used for compact encoding in texture compression contexts, not general voxel grid traversal.

## Operating characteristics
- **Time Complexity:** $O(N)$ for $N$ points, involving basic arithmetic operations per point.
- **Memory Complexity:** $O(N)$ to store the output indices.
- **Performance:** Highly efficient on GPU due to vectorized tensor operations. [S1, unofficial]
- **Strengths:** Supports batched bounding boxes and flexible voxel sizes. [S1, unofficial]
- **Limitations:** Does not handle out-of-bounds clamping internally. [G] The 3-bit variant is specific to texture coordinate interpolation and not general spatial indexing. [S2, unofficial]

## Background
The general voxel index computation method is implemented in the VGVGGT repository, associated with 2D/3D Gaussian Splatting frameworks. [S1, unofficial] The 3-bit index computation originates from real-time BC6H compression implementations on GPU. [S2, unofficial]
