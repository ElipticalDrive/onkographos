# Voxel Index Computation

Also called: ComputeIndex3, Index Computation (3-bit)

## Overview
Voxel Index Computation maps continuous 3D coordinates to discrete integer indices within a voxel grid, serving as the fundamental lookup mechanism for dense volume representations. It differs from sibling methods by supporting both standard batched point-to-grid mapping with configurable bounding boxes and specialized 3-bit texel indexing for compressed texture formats. While [Uniform Grid Indexing](6941-uniform-grid-indexing.md) handles general spatial hashing, this method provides specific implementations for Gaussian Splatting pipelines and BC6H compression contexts.

## How it works
The method operates in two distinct modes based on the input context: general batched voxel indexing for 3D Gaussians and 3-bit texel indexing for block compression.

### Inputs and Outputs
**Mode 1: Batched Voxel Indexing**
*   **Inputs**:
    *   `points`: Tensor of shape $(N, 3)$ containing 3D coordinates $(x, y, z)$.
    *   `bounding_boxes`: Tensor of shape $(B, 2, 3)$ or $(B, 3)$ defining min/max bounds per batch ID.
    *   `batch_ids`: Tensor of shape $(N,)$ mapping each point to a bounding box.
    *   `voxel_size`: Scalar or Tensor defining the grid resolution.
    *   `shift` (bool): If true, applies a half-voxel offset to the bounding box minimum.
    *   `cat_batch_ids` (bool): If true, appends the batch ID to the output.
*   **Outputs**:
    *   `voxel_indices`: Tensor of shape $(N, 3)$ if `cat_batch_ids` is false, or $(N, 4)$ if true.

**Mode 2: 3-bit Texel Indexing**
*   **Inputs**:
    *   `texelPos`: Continuous position relative to block endpoints.
    *   `end0`, `end1`: Two endpoints defining the local coordinate space.
*   **Outputs**:
    *   `index`: Integer in range $[0, 7]$.

### Data Structures
*   **Voxel Grid**: Implicitly defined by `bounding_boxes` and `voxel_size`. No explicit storage is required for the index computation itself, only for the subsequent data lookup.
*   **Index Format**:
    *   Standard: 32-bit integer per dimension $(i, j, k)$.
    *   3-bit: 3-bit integer representing one of 8 sub-blocks.

### Steps and Formulas

#### Mode 1: Batched Voxel Indexing [S1, unofficial]

1.  **Select Bounding Box Minimums**:
    Retrieve the minimum coordinate for each point's bounding box.
    $$ \mathbf{bb}_{min}[n] = \text{bounding\_boxes}[\text{batch\_ids}[n]][0] $$
    Where $\mathbf{bb}_{min}$ has shape $(N, 3)$.

2.  **Retrieve Voxel Size**:
    Handle scalar or tensor voxel sizes.
    $$ \mathbf{v}_s = \begin{cases} \text{voxel\_size}[\text{batch\_ids}] & \text{if tensor} \\ \text{voxel\_size} & \text{if scalar} \end{cases} $$
    If $\mathbf{v}_s$ is 1D (shape $(3,)$), expand to 2D for broadcasting:
    $$ \mathbf{v}_s \leftarrow \mathbf{v}_s.unsqueeze(-1) \quad (\text{shape } (N, 3)) $$

3.  **Apply Shift (Optional)**:
    If `shift` is true, adjust the bounding box minimums to center the voxel grid.
    $$ \mathbf{bb}_{min} \leftarrow \mathbf{bb}_{min} - 0.5 \cdot \mathbf{v}_s $$

4.  **Compute Integer Indices**:
    Map continuous points to discrete grid coordinates using floor division.
    $$ \mathbf{i} = \lfloor (\mathbf{points} - \mathbf{bb}_{min}) / \mathbf{v}_s \rfloor $$
    Cast to long integer type.

5.  **Concatenate Batch IDs (Optional)**:
    If `cat_batch_ids` is true, append the batch ID to the index tensor.
    $$ \mathbf{output} = \text{concat}(\mathbf{i}, \text{batch\_ids}[:, \text{None}]) $$
    Result shape: $(N, 4)$. Otherwise, return $\mathbf{i}$ with shape $(N, 3)$.

#### Mode 2: 3-bit Texel Indexing [S2, unofficial]

1.  **Normalize Position**:
    Compute the relative position of `texelPos` between `end0` and `end1`.
    $$ \text{ratio} = \frac{\text{texelPos} - \text{end0}}{\text{end1} - \text{end0}} $$

2.  **Scale and Offset**:
    Apply specific scaling and bias factors derived for BC6H compression.
    $$ \text{scaled} = \text{ratio} \cdot 6.98182 + 0.00909 + 0.5 $$

3.  **Round and Clamp**:
    Round to nearest integer and clamp to the valid 3-bit range.
    $$ \text{index} = \text{clamp}(\text{round}(\text{scaled}), 0, 7) $$

### Pseudocode

```python
import torch
import math

def compute_voxel_indices(points, bounding_boxes, batch_ids, voxel_size, shift=False, cat_batch_ids=False):
    """
    Computes voxel indices for a batch of 3D points.
    
    Args:
        points: Tensor (N, 3)
        bounding_boxes: Tensor (B, 2, 3) or (B, 3)
        batch_ids: Tensor (N,)
        voxel_size: Scalar or Tensor
        shift: Boolean
        cat_batch_ids: Boolean
        
    Returns:
        Tensor (N, 3) or (N, 4)
    """
    # Step 1: Select min bounding box
    # Assuming bounding_boxes is (B, 2, 3) where dim 1 is [min, max]
    if bounding_boxes.dim() == 3:
        bb_mins = bounding_boxes[batch_ids][:, 0]
    else:
        # If (B, 3), treat as min only or handle appropriately [G]
        bb_mins = bounding_boxes[batch_ids]

    # Step 2: Retrieve voxel size
    if isinstance(voxel_size, torch.Tensor):
        voxel_size_b = voxel_size[batch_ids]
        if voxel_size_b.dim() == 1:
            voxel_size_b = voxel_size_b.unsqueeze(-1)
    else:
        voxel_size_b = voxel_size

    # Step 3: Shift
    if shift:
        bb_mins = bb_mins - 0.5 * voxel_size_b

    # Step 4: Compute indices
    voxel_indices = torch.floor((points - bb_mins) / voxel_size_b).long()

    # Step 5: Concatenate batch IDs
    if cat_batch_ids:
        batch_ids_expanded = batch_ids.unsqueeze(-1).long()
        output = torch.cat([voxel_indices, batch_ids_expanded], dim=1)
        return output
    else:
        return voxel_indices

def compute_3bit_index(texel_pos, end0, end1):
    """
    Computes a 3-bit index for BC6H compression.
    
    Args:
        texel_pos: Float
        end0: Float
        end1: Float
        
    Returns:
        Integer 0-7
    """
    ratio = (texel_pos - end0) / (end1 - end0)
    scaled = ratio * 6.98182 + 0.00909 + 0.5
    rounded = round(scaled)
    index = max(0, min(7, rounded))
    return index
```

### Edge Cases and Pitfalls
*   **Division by Zero**: If `end1 == end0` in Mode 2, the ratio is undefined. The source does not specify a guard; implementers should clamp or return a sentinel value [G].
*   **Precision**: Floating-point errors in `floor` operations can cause off-by-one errors at exact grid boundaries. Using `torch.floor` is standard, but careful handling of negative coordinates is required as floor behaves differently than truncation [G].
*   **Batch ID Mismatch**: If `batch_ids` contains indices out of bounds for `bounding_boxes`, an index error will occur. Input validation is required [G].

## Operating characteristics
*   **Time Complexity**: $O(N)$ for batched indexing, where $N$ is the number of points. The 3-bit computation is $O(1)$ per texel.
*   **Memory Complexity**: $O(N)$ to store the output indices. No additional memory for the grid structure is required during index computation.
*   **Performance**: Highly efficient on GPU due to vectorized tensor operations. The 3-bit method is extremely fast but limited to specific compression contexts.
*   **Limitations**: Does not handle non-uniform voxel sizes within a single batch without tensor expansion. Boundary handling is implicit via the bounding box definition; points outside bounds result in negative indices or values > grid size, requiring post-processing [G].

## Background
The batched voxel indexing method originates from the 2D/3D Gaussian Splatting literature, specifically implemented in the VGVGGT framework for efficient point cloud to grid mapping [S1, unofficial]. The 3-bit indexing method is derived from real-time BC6H texture compression algorithms, where efficient mapping of texel positions to 8 sub-blocks is critical for compression speed [S2, unofficial].
