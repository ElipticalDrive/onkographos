# Uniform Grid Adjacent Cell Indexing

Also called: Adjacent Cell Indexing, Edge Neighbor Indexing

## Overview
Uniform Grid Adjacent Cell Indexing computes the linear indices of the four cells sharing a specific edge in a uniform voxel grid [S1, unofficial]. It solves the problem of identifying neighboring volumes for edge-based surface reconstruction algorithms by mapping an edge position to its surrounding cell indices [S1, unofficial]. It is distinct from [Uniform Grid Indexing](6941-uniform-grid-indexing.md), which maps a single point to one cell, and [Voxel Index Computation](13870-voxel-index-computation.md), which refers to the base linearization strategy [G]. This method specifically handles the topology of edge-sharing cells and returns a sentinel value for out-of-bounds neighbors [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The edge position $\mathbf{e}$ (integer grid coordinates), the grid dimensions $N_x, N_y, N_z$, and the edge orientation type (0: parallel to X, 1: parallel to Y, 2: parallel to Z) [S1, unofficial].
*   **Output:** An array `cells` of four linear indices corresponding to the cells adjacent to the edge [S1, unofficial]. If a neighbor does not exist, the index is set to a sentinel value `kBadIndex` [S1, unofficial].

**Data Structures:**
*   `cells`: An integer array of size 4 [S1, unofficial].
*   `kBadIndex`: A sentinel integer (e.g., $-1$) indicating an invalid or non-existent cell [S1, unofficial].
*   `m_size`: The base grid dimension parameter used in the source formulas [S1, unofficial].
*   `m_halfSize`: Half the grid size, used for boundary coordinate checks [S1, unofficial].

**Strides and Formulas:**
The method uses row-major linearization where $X$ is the fastest axis [G]. For a uniform grid with side length $N = m\_size + 1$, the strides are $S_x = N^2$, $S_y = N$, and $S_z = 1$ [G]. The source defines relative offsets for each edge type [S1, unofficial]:
*   **Edge Type 0 (Parallel to X-axis):** $dy = N^2$, $dz = 1$ [S1, unofficial].
    $$ \text{cells}[2] = \text{pointToIndex}(\mathbf{e}) $$
    $$ \text{cells}[0] = \text{cells}[2] - dy - dz $$
    $$ \text{cells}[1] = \text{cells}[2] - dz $$
    $$ \text{cells}[3] = \text{cells}[2] - dy $$
*   **Edge Type 1 (Parallel to Y-axis):** $dx = N$, $dz = 1$ [S1, unofficial].
    $$ \text{cells}[2] = \text{pointToIndex}(\mathbf{e}) $$
    $$ \text{cells}[0] = \text{cells}[2] - dx - dz $$
    $$ \text{cells}[1] = \text{cells}[2] - dx $$
    $$ \text{cells}[3] = \text{cells}[2] - dz $$
*   **Edge Type 2 (Parallel to Z-axis):** $dx = N$, $dy = N^2$ [S1, unofficial].
    $$ \text{cells}[2] = \text{pointToIndex}(\mathbf{e}) $$
    $$ \text{cells}[0] = \text{cells}[2] - dx - dy $$
    $$ \text{cells}[1] = \text{cells}[2] - dy $$
    $$ \text{cells}[3] = \text{cells}[2] - dx $$

**Algorithm Steps:**
1.  **Compute Reference Cell:** Calculate the linear index of the primary cell containing the edge position using coordinate transformation, scaling, discretization, and clamping to $[0, N-1]$ [G]. Assign this to `cells[2]` [S1, unofficial].
2.  **Compute Neighbors:** Apply the offset formulas for the given edge type to calculate `cells[0]`, `cells[1]`, and `cells[3]` [S1, unofficial].
3.  **Boundary Check:** Validate each computed index against the grid bounds $[0, N^3 - 1]$ [G]. If an index falls outside these bounds, set it to `kBadIndex` [S1, unofficial].

**Pitfalls and Edge Cases:**
*   **Boundary Conditions:** If the edge lies on the grid boundary, some adjacent cells do not exist [S1, unofficial]. For Edge Type 0, specific coordinate conditions trigger invalid neighbors: if $\mathbf{e}_y = -m\_halfSize$, `cells[0]` and `cells[3]` are invalid; if $\mathbf{e}_y = m\_halfSize$, `cells[1]` and `cells[2]` are invalid; if $\mathbf{e}_z = -m\_halfSize$, `cells[0]` and `cells[1]` are invalid; if $\mathbf{e}_z = m\_halfSize$, `cells[2]` and `cells[3]` are invalid [S1, unofficial]. Analogous coordinate checks apply to other edge types based on their perpendicular axes [S1, unofficial].
*   **Sentinel Value:** Always check for `kBadIndex` before accessing cell data to prevent out-of-bounds memory access [S1, unofficial].

**Pseudocode:**
```python
def compute_adjacent_cells(edge_pos, m_size, edge_type):
    """
    Computes linear indices of 4 cells adjacent to an edge in a uniform grid.
    Args:
        edge_pos: Tuple (x, y, z) of integer grid coordinates.
        m_size: Integer base dimension of the grid.
        edge_type: Integer 0 (X-parallel), 1 (Y-parallel), 2 (Z-parallel).
    Returns:
        List of 4 integers. kBadIndex (-1) for out-of-bounds neighbors.
    """
    kBadIndex = -1
    N = m_size + 1
    total_cells = N * N * N
    
    # Clamp coordinates to valid grid range [0, N-1]
    ix = max(0, min(N - 1, edge_pos[0]))
    iy = max(0, min(N - 1, edge_pos[1]))
    iz = max(0, min(N - 1, edge_pos[2]))
    
    # Row-major linear index: I = i * (N*N) + j * N + k
    cells_2 = ix * (N * N) + iy * N + iz
    cells = [0, 0, 0, 0]
    cells[2] = cells_2
    
    if edge_type == 0:  # Parallel to X
        dy = N * N
        dz = 1
        cells[0] = cells_2 - dy - dz
        cells[1] = cells_2 - dz
        cells[3] = cells_2 - dy
    elif edge_type == 1:  # Parallel to Y
        dx = N
        dz = 1
        cells[0] = cells_2 - dx - dz
        cells[1] = cells_2 - dx
        cells[3] = cells_2 - dz
    elif edge_type == 2:  # Parallel to Z
        dx = N
        dy = N * N
        cells[0] = cells_2 - dx - dy
        cells[1] = cells_2 - dy
        cells[3] = cells_2 - dx
        
    # Boundary validation
    for i in range(4):
        if cells[i] < 0 or cells[i] >= total_cells:
            cells[i] = kBadIndex
            
    return cells
```

## Subtopics

### [Uniform Grid Boundary Checks](4380-uniform-grid-boundary-checks.md)
Determines whether a coordinate lies within valid grid bounds or on the boundary. It is distinct from this method, which computes neighbor indices and returns a sentinel value for out-of-bounds neighbors [G]. Choose it when explicit coordinate validation is required before indexing [G].

### [Multi-Material Quad Vertex Index Mapping](4910-multi-material-quad-vertex-index-mapping.md)
Maps a cell edge type to a four-element vertex index array defining a quadrilateral primitive. It is distinct from this method, which computes adjacent cell linear indices for edge topology [G]. Choose it when resolving vertex connectivity for quad faces in multi-material grids [G].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per edge [S1, unofficial]. The computation involves a fixed number of arithmetic operations and boundary checks [S1, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space [S1, unofficial]. Requires storage for 4 indices and a few temporary variables [S1, unofficial].
*   **Strengths:** Fast, deterministic, and efficient for edge-based surface extraction [S1, unofficial].
*   **Limitations:** Requires careful boundary handling [S1, unofficial]. The specific stride formulas depend on the uniform grid dimension parameter $m\_size$ [S1, unofficial].
*   **When to use:** When implementing Marching Cubes or similar algorithms that require access to all cells sharing an edge [S1, unofficial].
*   **When not to use:** When only a single cell lookup is needed (use [Uniform Grid Indexing](6941-uniform-grid-indexing.md)) [S1, unofficial].

## Background
The method originates from implementations in isosurface extraction libraries, specifically noted in the unofficial source [S1, unofficial]. It addresses the topological requirement of identifying all volumes surrounding an edge, which is necessary for constructing consistent surface meshes from voxel data [S1, unofficial].
