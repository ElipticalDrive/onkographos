# Uniform Grid Adjacent Cell Indexing

Also called: Adjacent Cell Indexing, Edge Neighbor Indexing

## Overview
Computes the linear indices of the four cells adjacent to a specific edge in a uniform voxel grid. It solves the problem of identifying the spatial neighbors of an edge for operations such as multi-material quad vertex mapping or edge-based interpolation. It differs from [Uniform Grid Indexing](6941-uniform-grid-indexing.md) by returning a set of four indices rather than a single cell index, and from [Voxel Index Computation](13870-voxel-index-computation.md) by focusing on edge-adjacency relationships rather than point-to-cell mapping.

## How it works
**Inputs and Outputs:**
*   **Input:** `edgePos` (the grid coordinate of the edge, typically integer or floating-point), `edgeType` (0, 1, or 2, indicating the axis parallel to the edge), `m_size` (the dimension of the grid, assumed cubic $N \times N \times N$), `m_halfSize` (half the grid dimension, used for boundary checks).
*   **Output:** An array `cells[4]` containing the linear indices of the four cells sharing the edge. Invalid indices are replaced with `kBadIndex` if the edge lies on a grid boundary.

**Data Structures:**
*   `cells`: Array of 4 integers.
*   `kBadIndex`: Sentinel value (e.g., -1) indicating no neighbor exists.

**Formulas:**
The linear index $I$ for a 3D coordinate $(i, j, k)$ in a row-major layout is:
$$ I = i \cdot S_y S_z + j \cdot S_z + k $$
Where $S_z = m\_size + 1$ and $S_y = m\_size + 1$ (assuming a cubic grid where dimensions are equal). Let $dy = (m\_size + 1)^2$ and $dz = 1$.

The base index `cells[2]` is computed using `pointToIndex(edgePos)`. The other three indices are derived by subtracting strides corresponding to the axes perpendicular to the edge.

**Steps:**
1.  Determine the strides based on `edgeType`.
2.  Compute `cells[2]` from `edgePos`.
3.  Compute `cells[0]`, `cells[1]`, and `cells[3]` using the strides.
4.  Apply boundary checks to replace invalid indices with `kBadIndex`.

**Pseudocode:**
```python
def compute_adjacent_cells(edgePos, edgeType, m_size, m_halfSize):
    # edgePos is assumed to be a tuple (x, y, z)
    # m_size is the grid dimension N
    # m_halfSize is N / 2 (assuming centered grid)
    
    cells = [0] * 4
    kBadIndex = -1
    
    # Helper to compute linear index from 3D coordinates
    def point_to_index(pos):
        i, j, k = pos
        # Assuming row-major layout: I = i * (N+1)^2 + j * (N+1) + k
        # Note: The source uses (m_size + 1) as the stride base
        stride_yz = (m_size + 1) * (m_size + 1)
        stride_z = 1
        return i * stride_yz + j * stride_z + k

    # Compute base index
    cells[2] = point_to_index(edgePos)
    
    if edgeType == 0:
        # Edge parallel to X axis
        # Strides: dy = (N+1)^2, dz = 1
        dy = (m_size + 1) * (m_size + 1)
        dz = 1
        cells[0] = cells[2] - dy - dz
        cells[1] = cells[2] - dz
        cells[3] = cells[2] - dy
        
        # Boundary checks for edge parallel to X
        # If edgePos.y == -m_halfSize, cells[0] and cells[3] are invalid
        if edgePos[1] == -m_halfSize:
            cells[0] = kBadIndex
            cells[3] = kBadIndex
        # If edgePos.y == m_halfSize, cells[1] and cells[2] are invalid
        if edgePos[1] == m_halfSize:
            cells[1] = kBadIndex
            cells[2] = kBadIndex
        # If edgePos.z == -m_halfSize, cells[0] and cells[1] are invalid
        if edgePos[2] == -m_halfSize:
            cells[0] = kBadIndex
            cells[1] = kBadIndex
        # If edgePos.z == m_halfSize, cells[2] and cells[3] are invalid
        if edgePos[2] == m_halfSize:
            cells[2] = kBadIndex
            cells[3] = kBadIndex

    elif edgeType == 1:
        # Edge parallel to Y axis
        # Strides: dx = (N+1), dz = 1
        dx = (m_size + 1)
        dz = 1
        cells[0] = cells[2] - dx - dz
        cells[1] = cells[2] - dx
        cells[3] = cells[2] - dz
        
        # Boundary checks for edge parallel to Y
        # (Specific boundary conditions for Y-parallel edges are not explicitly detailed in the source notes,
        # but follow the pattern of checking x and z bounds)
        # Note: The source notes only detail boundary checks for edgeType 0.
        # For implementation completeness, one would check x and z boundaries here.
        # However, adhering strictly to the source: "Not given in the sources." for specific Y-boundary logic.
        # [G] Assuming symmetric logic: check x and z bounds.
        if edgePos[0] == -m_halfSize:
            cells[0] = kBadIndex
            cells[1] = kBadIndex
        if edgePos[0] == m_halfSize:
            cells[2] = kBadIndex
            cells[3] = kBadIndex
        if edgePos[2] == -m_halfSize:
            cells[0] = kBadIndex
            cells[2] = kBadIndex
        if edgePos[2] == m_halfSize:
            cells[1] = kBadIndex
            cells[3] = kBadIndex

    elif edgeType == 2:
        # Edge parallel to Z axis
        # Strides: dx = (N+1), dy = (N+1)^2
        dx = (m_size + 1)
        dy = (m_size + 1) * (m_size + 1)
        cells[0] = cells[2] - dx - dy
        cells[1] = cells[2] - dy
        cells[3] = cells[2] - dx
        
        # Boundary checks for edge parallel to Z
        # (Specific boundary conditions for Z-parallel edges are not explicitly detailed in the source notes)
        # [G] Assuming symmetric logic: check x and y bounds.
        if edgePos[0] == -m_halfSize:
            cells[0] = kBadIndex
            cells[1] = kBadIndex
        if edgePos[0] == m_halfSize:
            cells[2] = kBadIndex
            cells[3] = kBadIndex
        if edgePos[1] == -m_halfSize:
            cells[0] = kBadIndex
            cells[2] = kBadIndex
        if edgePos[1] == m_halfSize:
            cells[1] = kBadIndex
            cells[3] = kBadIndex

    return cells
```

Multi-Material Quad Vertex Index Mapping maps a cell edge type to a four-element vertex index array defining a quadrilateral primitive. It resolves vertex connectivity for a quad face using pointer arithmetic on a cell array, building on [Uniform Grid Adjacent Cell Indexing](2992-uniform-grid-adjacent-cell-indexing.md) which computes adjacent cell linear indices.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per edge, as it involves a constant number of arithmetic operations and comparisons.
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Strengths:** Fast, deterministic, and simple to implement. Suitable for real-time applications where edge-based operations are frequent.
*   **Limitations:** Requires careful boundary handling. The logic is specific to uniform grids and may not generalize to non-uniform or hierarchical grids without modification.
*   **When to use:** When performing operations that require knowledge of all cells sharing an edge, such as multi-material mesh generation or edge-based smoothing.
*   **When not to use:** For simple point-to-cell lookups, use [Uniform Grid Indexing](6941-uniform-grid-indexing.md). For non-uniform grids, other indexing schemes are required.

## Background
The method originates from the `isomesh` library by Svenny [S1, unofficial]. It is used in the context of generating meshes from volumetric data, specifically for handling multi-material interfaces where edge connectivity is crucial.
