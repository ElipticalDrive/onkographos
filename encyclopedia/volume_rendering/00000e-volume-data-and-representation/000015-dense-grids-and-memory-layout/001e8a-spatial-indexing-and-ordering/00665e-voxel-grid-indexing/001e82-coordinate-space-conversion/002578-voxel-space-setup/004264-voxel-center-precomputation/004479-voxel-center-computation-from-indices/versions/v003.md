# Voxel Center Computation from Indices

Also called: Voxel Center Coordinate Generation, Voxel-to-World Coordinate Mapping for Crosshair

## Overview
Computes the 3D world-space coordinates of voxel centers given their discrete indices, bounding box origins, and voxel sizes [S3, unofficial]. It solves the problem of mapping discrete grid positions to continuous physical space for ray casting, shading, or crosshair placement [G]. It is distinguished from [Voxel Grid Coordinate Mapping](15198-voxel-grid-coordinate-mapping.md) by focusing specifically on center point calculation rather than handling linear buffer indexing schemes or geometry-based vertex generation.

## How it works
**Inputs and Outputs:**
- `voxel_indices`: Array of shape $[N, 3]$ or $[N, 4]$ containing discrete voxel indices $(i, j, k)$ [S3, unofficial]. If `cat_batch_ids` is true, the first column is a batch ID, and indices are in columns 1-3 [S3, unofficial].
- `voxel_size`: Voxel dimensions $(s_x, s_y, s_z)$ as a scalar or vector [S3, unofficial].
- `bb_mins`: Minimum bounding box coordinates for each voxel/batch, shape $[N, 3]$ or broadcastable [S3, unofficial].
- `shift`: Boolean flag determining if an offset of half-voxel size is applied [S3, unofficial].
- `cat_batch_ids`: Boolean flag indicating if batch IDs are present in the input indices [S3, unofficial].
- `centers`: Output array of shape $[N, 3]$ containing world-space coordinates $(x, y, z)$ for each voxel center [S3, unofficial].

**Data Structures:**
- `voxel_indices`: Integer array.
- `voxel_size`: Float scalar or vector.
- `bb_mins`: Float vector or array.
- `centers`: Float array $[N, 3]$.

**Numbered Steps:**
1. **Validate Batch IDs:** If `cat_batch_ids` is false, raise `NotImplementedError`, as only cases with batch IDs concatenated are supported [S3, unofficial].
2. **Extract Indices:** If `cat_batch_ids` is true, extract indices from `voxel_indices[:, 1:]` [S3, unofficial].
3. **Retrieve Parameters:** Get `voxel_size` and `bb_mins` [S3, unofficial]. If `voxel_size` is a scalar, treat it as $(s, s, s)$ [G].
4. **Compute Centers:** Apply the formula based on `shift`:
   - If `shift` is true: $\text{centers} = \text{indices} \cdot \text{voxel\_size} + \text{bb\_mins}$ [S3, unofficial].
   - If `shift` is false: $\text{centers} = \text{indices} \cdot \text{voxel\_size} + \text{bb\_mins} + 0.5 \cdot \text{voxel\_size}$ [S3, unofficial].

**Formulas:**
- $\text{centers} = \text{indices} \cdot \text{voxel\_size} + \text{bb\_mins}$ (when `shift` is true) [S3, unofficial].
- $\text{centers} = \text{indices} \cdot \text{voxel\_size} + \text{bb\_mins} + 0.5 \cdot \text{voxel\_size}$ (when `shift` is false) [S3, unofficial].
- Where $\text{indices}$ is the extracted $[N, 3]$ integer array, $\text{voxel\_size}$ is the $[3]$ float vector, and $\text{bb\_mins}$ is the $[N, 3]$ float array of bounding box origins [S3, unofficial].

**Parameters:**
- `shift`: Boolean. Controls the half-voxel offset. `True` applies no offset; `False` applies $0.5 \cdot \text{voxel\_size}$ [S3, unofficial].
- `cat_batch_ids`: Boolean. Must be `True` for execution [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Batch ID Handling:** The function strictly requires `cat_batch_ids` to be true. Passing indices without batch IDs raises `NotImplementedError` [S3, unofficial].
- **Shift Logic:** `shift=True` implies indices map directly to the voxel start or a specific alignment, while `shift=False` adds a standard half-voxel offset to reach the center [S3, unofficial].
- **Precision:** Inputs should be cast to floating-point types before arithmetic to avoid integer truncation [G].

**Pseudocode:**
```python
def compute_voxel_centers(voxel_indices, voxel_size, bb_mins, shift, cat_batch_ids):
    """
    Compute world-space centers of voxels from discrete indices.
    
    Args:
        voxel_indices: List of lists or array of shape [N, 3] or [N, 4]. 
                       If cat_batch_ids is True, column 0 is batch ID, columns 1-3 are indices.
        voxel_size: Scalar or list of 3 floats representing (sx, sy, sz).
        bb_mins: List of lists or array of shape [N, 3] or broadcastable minimum bounding box coordinates.
        shift: Boolean. If True, no half-voxel offset is added. If False, 0.5 * voxel_size is added.
        cat_batch_ids: Boolean. If True, batch IDs are present in voxel_indices.
        
    Returns:
        centers: List of lists of shape [N, 3] with world-space coordinates.
        
    Raises:
        NotImplementedError: If cat_batch_ids is False.
    """
    if not cat_batch_ids:
        raise NotImplementedError("Only cases with batch IDs concatenated are supported.")
    
    # Extract indices (skip batch ID column)
    indices = [row[1:] for row in voxel_indices]
    
    # Ensure voxel_size is a list of 3 floats
    if isinstance(voxel_size, (int, float)):
        voxel_size = [float(voxel_size), float(voxel_size), float(voxel_size)]
    else:
        voxel_size = [float(v) for v in voxel_size]
        
    centers = []
    for i in range(len(indices)):
        idx = indices[i]
        bb = bb_mins[i] if len(bb_mins) > 1 else bb_mins
        offset = [0.0, 0.0, 0.0] if shift else [0.5 * voxel_size[j] for j in range(3)]
        center = [float(idx[j]) * voxel_size[j] + float(bb[j]) + offset[j] for j in range(3)]
        centers.append(center)
    return centers
```

## Subtopics

### [Voxel Grid Coordinate Mapping](15198-voxel-grid-coordinate-mapping.md)
Handles bijective transformations between discrete indices, linear buffer positions, and world coordinates, including row-major flattening and vertex generation for geometry-based rendering. Choose this when you need to map linear buffer indices or generate geometry vertices rather than just center points [G].

### Non-1 Indexing for Volume Centering
Uses non-standard array indexing (e.g., negative ranges) to define the spatial origin and center of a volume, ensuring camera rotation pivots around the true geometric center [S4, unofficial]. Example implementations use functions like `ImageFiltering.centered` to create arrays with indices centered around zero [S4, unofficial]. Standard 1-based indexing causes rotation pivots to be relative to a corner of the image rather than the center [S4, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of voxels. The computation involves element-wise multiplication and addition [G].
- **Memory Complexity:** $O(N)$ for the output array [G].
- **Strengths:** Simple, efficient, and directly maps indices to world space. Suitable for real-time applications like crosshair placement or ray casting origins [G].
- **Limitations:** Limited to regular grids. Does not handle irregular voxel sizes or non-axis-aligned bounding boxes [G]. The requirement for batch IDs restricts its use in single-batch scenarios without modification [S3, unofficial].
- **When to Use:** When you have discrete voxel indices and need their corresponding world-space centers for shading or ray casting [G].
- **When Not to Use:** When you need to map linear buffer indices to world space (use [Voxel Grid Coordinate Mapping](15198-voxel-grid-coordinate-mapping.md)) or when dealing with irregular voxel structures [G].

## Background
The method is derived from implementations in volumetric rendering and 3D Gaussian Splatting frameworks, specifically those involving depth estimation and scene reconstruction [S3, unofficial]. It is used in systems like VGVGGT for computing voxel centers for Gaussian scene decoding [S3, unofficial].
