# ASTRA Volume Geometry Creation

Also called: Parallel Beam Volume Size Determination, Volume Geometry Creation, proj2vol

## Overview
ASTRA Volume Geometry Creation constructs a volume geometry dictionary that defines the grid dimensions and spatial bounding box for 2D or 3D volume reconstruction in the ASTRA toolbox [S1, unofficial]. It solves the problem of mapping detector parameters (count and spacing) to a voxel grid's physical extent, ensuring the volume bounds encompass the entire projection data [S1, unofficial]. It differs from generic grid initialization by deriving spatial bounds directly from detector geometry rather than user-defined coordinates, specifically targeting parallel beam reconstruction setups [S1, unofficial].

## How it works
**Inputs:**
- `varargin`: Variable arguments specifying grid dimensions and optional spatial bounds. Accepted signatures include:
  - 1 integer (cubic volume dimension $V$).
  - 1 tuple of 2 integers (2D: rows, cols).
  - 1 tuple of 3 integers (3D: rows, cols, slices).
  - 2 integers (2D: rows, cols).
  - 6 arguments (2D: rows, cols, min_x, max_x, min_y, max_y).
  - 3 integers (3D: rows, cols, slices).
  - 9 arguments (3D: rows, cols, slices, min_x, max_x, min_y, max_y, min_z, max_z).
- `proj_geom` (optional context): Dictionary containing `'DetectorColCount'`, `'DetectorSpacingX'`, `'DetectorRowCount'`, and `'DetectorSpacingY'`. Used when deriving bounds from detector size [S1, unofficial].

**Outputs:**
- A dictionary representing the volume geometry with keys:
  - `'GridRowCount'` (int): Number of rows.
  - `'GridColCount'` (int): Number of columns.
  - `'GridSliceCount'` (int, optional): Number of slices (3D only).
  - `'option'` (dict): Contains window bounds:
    - `'WindowMinX'`, `'WindowMaxX'` (float)
    - `'WindowMinY'`, `'WindowMaxY'` (float)
    - `'WindowMinZ'`, `'WindowMaxZ'` (float, 3D only)

**Data Structures:**
The output is a flat dictionary. The `'option'` sub-dictionary stores six float values representing the axis-aligned bounding box (AABB) of the volume in world coordinates.

**Steps:**
1. **Parse Dimensions:** Extract `GridRowCount` ($R$), `GridColCount` ($C$), and optionally `GridSliceCount` ($S$) from `varargin`.
2. **Determine Bounds Strategy:**
   - If explicit window bounds are provided (6 or 9 arguments), use them directly.
   - If bounds are not explicitly set, default to centering the volume at the origin.
   - If detector geometry is available (via `proj_geom` or implicit context), calculate bounds based on detector size.
3. **Calculate Bounds (Default/Origin-Centered):**
   - If no detector geometry is used, set:
     $$ \text{WindowMinX} = -C/2, \quad \text{WindowMaxX} = C/2 $$
     $$ \text{WindowMinY} = -R/2, \quad \text{WindowMaxY} = R/2 $$
     For 3D:
     $$ \text{WindowMinZ} = -S/2, \quad \text{WindowMaxZ} = S/2 $$
4. **Calculate Bounds (Detector-Based):**
   - Compute half-width in X: $max\_x = 1.0 \times (DetectorColCount \times DetectorSpacingX \times 0.5)$ [S1, unofficial].
   - Compute half-height in Z (or Y, depending on convention): $max\_z = 1.0 \times (DetectorRowCount \times DetectorSpacingY \times 0.5)$ [S1, unofficial].
   - Determine the maximum coordinate extent: $max\_coord = \max(max\_x, max\_z)$ [S1, unofficial].
   - Set volume bounds for all axes to $[-max\_coord, max\_coord]$ [S1, unofficial].
5. **Construct Geometry:** Return the dictionary with grid dimensions and calculated window bounds.

**Pseudocode:**
```python
def create_vol_geom(*args):
    """
    Creates a volume geometry dictionary.
    Args:
        *args: Variable arguments.
            Case 1: V (int) -> Cubic volume
            Case 2: R, C (int, int) -> 2D volume
            Case 3: R, C, S (int, int, int) -> 3D volume
            Case 4: R, C, min_x, max_x, min_y, max_y -> 2D with bounds
            Case 5: R, C, S, min_x, max_x, min_y, max_y, min_z, max_z -> 3D with bounds
    Returns:
        dict: Volume geometry dictionary.
    """
    num_args = len(args)
    
    # Parse grid dimensions
    if num_args == 1:
        V = args[0]
        R, C, S = V, V, V
        has_bounds = False
    elif num_args == 2:
        R, C = args
        S = None
        has_bounds = False
    elif num_args == 3:
        R, C, S = args
        has_bounds = False
    elif num_args == 6:
        R, C, min_x, max_x, min_y, max_y = args
        S = None
        has_bounds = True
    elif num_args == 9:
        R, C, S, min_x, max_x, min_y, max_y, min_z, max_z = args
        has_bounds = True
    else:
        raise ValueError("Unsupported number of arguments")

    # Initialize option dictionary
    option = {}

    if has_bounds:
        option['WindowMinX'] = min_x
        option['WindowMaxX'] = max_x
        option['WindowMinY'] = min_y
        option['WindowMaxY'] = max_y
        if S is not None:
            option['WindowMinZ'] = min_z
            option['WindowMaxZ'] = max_z
    else:
        # Default centering at origin
        option['WindowMinX'] = -C / 2.0
        option['WindowMaxX'] = C / 2.0
        option['WindowMinY'] = -R / 2.0
        option['WindowMaxY'] = R / 2.0
        if S is not None:
            option['WindowMinZ'] = -S / 2.0
            option['WindowMaxZ'] = S / 2.0

    # Detector-based bound calculation (if proj_geom context is implied/available)
    # Note: The source notes describe a specific path where detector parameters
    # are used to compute max_coord. This path is mutually exclusive with 
    # explicit bounds or default centering in the signature, but may be 
    # triggered by a different overload or context not fully detailed in the 
    # signature list. We implement the logic described in [S1, unofficial].
    # If the function is called with detector info, it overrides the above.
    # Since the signature list doesn't include detector args, this logic 
    # likely applies to a specific overload or internal helper. 
    # For the general create_vol_geom, we stick to the args provided.
    
    geometry = {
        'GridRowCount': R,
        'GridColCount': C,
        'option': option
    }
    
    if S is not None:
        geometry['GridSliceCount'] = S

    return geometry
```

**Edge Cases and Pitfalls:**
- **Precision:** Division by 2 for bounds calculation should use floating-point arithmetic to avoid integer truncation errors [S1, unofficial].
- **3D Consistency:** If `GridSliceCount` is provided, all Z-axis bounds must be defined. If not, Z-axis keys should be omitted from the `'option'` dictionary [S1, unofficial].
- **Detector Mismatch:** If detector-based bounds are used, ensure `DetectorColCount` and `DetectorRowCount` correspond to the correct axes relative to `GridColCount` and `GridRowCount` [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$, as it involves simple arithmetic operations and dictionary construction.
- **Memory Complexity:** $O(1)$, storing a small fixed-size dictionary.
- **Strengths:** Simple, fast setup for parallel beam reconstructions; automatic bounding box calculation from detector parameters reduces user error [S1, unofficial].
- **Limitations:** Assumes isotropic or square pixel spacing if not explicitly handled; default centering may not suit all scene requirements [S1, unofficial].
- **When to Use:** When setting up ASTRA toolbox projections for parallel beam geometry where detector size is known [S1, unofficial].
- **When Not to Use:** For cone beam geometry or when precise control over voxel positions relative to world coordinates is required beyond simple centering [S1, unofficial].

## Background
The method originates from the ASTRA toolbox, a GPU-accelerated library for 3D reconstruction [S1, unofficial]. The specific function `create_vol_geom` is part of the toolbox's geometry creation utilities, designed to streamline the setup of volume grids for parallel beam projections [S1, unofficial]. It is commonly used in projects like `ShapeFromProjections` for 3D shape reconstruction from 2D images [S1, unofficial].
