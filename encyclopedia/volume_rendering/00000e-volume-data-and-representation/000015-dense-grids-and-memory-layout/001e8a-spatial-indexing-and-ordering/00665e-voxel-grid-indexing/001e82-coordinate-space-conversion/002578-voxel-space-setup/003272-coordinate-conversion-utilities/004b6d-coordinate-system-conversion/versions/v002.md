# Coordinate System Conversion
Also called: Swept-Volume Coordinate Transformation, Cartesian-to-Cylindrical-to-System Conversion

## Overview
This method converts normalized Cartesian voxel data into system-specific coordinates for swept-volume displays, mapping 3D spatial positions to 2D panel coordinates and an angular sweep parameter [S1]. It differs from [Metric Coordinate Conversion](12960-metric-coordinate-conversion.md) by targeting cylindrical projection displays rather than general metric scaling, and from [Sliced Volume Coordinate Mapping](8287-sliced-volume-coordinate-mapping.md) by transforming full volumetric data prior to slicing [G].

## How it works
**Inputs:** Normalized Cartesian data points in Descartes coordinates $(x, y, z)$ with color attributes $(r, g, b)$ [S1].
**Outputs:** System coordinates $(h, w, \theta)$ with color attributes $(r, g, b)$ [S1].

**Data Structures:**
The input is a list or grid of tuples $(x, y, z, r, g, b)$ [S1].
The output is a list or grid of tuples $(h, w, \theta, r, g, b)$ [S1].

**Parameters:**
- $x_{center}, y_{center}, z_{center}$: The center of the display coordinate system origin [S1].
- Screen resolution scaling factors: Applied to adjust object data scaling to the actual display screen resolution [S1].

**Steps:**
1.  **Centering:** Subtract center coordinates from input Cartesian coordinates to normalize position relative to the display center [S1].
    $$x' = x - x_{center}$$
    $$y' = y - y_{center}$$
    $$z' = z - z_{center}$$
2.  **Cartesian to Cylindrical:** Convert centered coordinates to cylindrical form $(\theta, \rho, z, r, g, b)$ [S1].
    $$\theta = \arctan2(y', x')$$
    $$\rho = \sqrt{x'^2 + y'^2}$$
    Color attributes $(r, g, b)$ are preserved [S1].
3.  **Cylindrical to System:** Map cylindrical coordinates to system coordinates $(h, w, \theta, r, g, b)$ [S1].
    - $h$ (Height): Corresponds to the vertical position, derived from $z'$ [S1].
    - $w$ (Width): Corresponds to the horizontal panel coordinate, derived from $\rho$ [S1].
    - $\theta$ (Angle): The angular sweep parameter [S1].
    Color attributes $(r, g, b)$ are preserved [S1].
4.  **Data Reduction:** After transformation, save only voxels activated on the display panel [S1]. Query memory by panel coordinates $(h, w)$; if a match is found, return the color data, otherwise return 0 [S1].

**Pseudocode:**
```python
import math

def convert_coordinate_system(points, x_center, y_center, z_center, 
                              max_radius, screen_width):
    """
    Convert normalized Cartesian data to swept-volume system coordinates.
    
    Args:
        points: List of tuples (x, y, z, r, g, b)
        x_center, y_center, z_center: Center of the display coordinate system
        max_radius: Maximum physical radius of the swept volume for scaling
        screen_width: Resolution of the display panel
        
    Returns:
        List of tuples (h, w, theta, r, g, b)
    """
    output = []
    scale = screen_width / max_radius if max_radius > 0 else 1.0
    
    for x, y, z, r, g, b in points:
        # Step 1: Centering
        x_prime = x - x_center
        y_prime = y - y_center
        z_prime = z - z_center
        
        # Step 2: Cartesian to Cylindrical
        theta = math.atan2(y_prime, x_prime)
        rho = math.sqrt(x_prime**2 + y_prime**2)
        
        # Step 3: Cylindrical to System Coordinates
        h = z_prime
        w = rho * scale
        
        output.append((h, w, theta, r, g, b))
        
    return output
```
[G] The source specifies scaling to screen resolution but does not provide the exact formula; the implementer must determine `max_radius` and apply a linear scale to fit $\rho$ to $[0, \text{screen\_width}]$.

## Operating characteristics
**Time Complexity:** $O(N)$ for $N$ input voxels, as each point undergoes constant arithmetic operations [G].
**Memory Complexity:** $O(N)$ to store transformed coordinates and attributes [G].
**Strengths:** Directly maps 3D data to swept-volume display geometric requirements [S1].
**Limitations:** Requires precise display center and resolution knowledge; data reduction is hardware-dependent [S1].
**When to use:** When rendering volumetric data on swept-volume displays or cylindrical projection systems [S1].
**When not to use:** For standard orthogonal or perspective volume rendering on flat screens, or when metric spatial relationships are required without angular projection [G].

## Background
The method originates from the design of 3D swept-volume volumetric displays, where data must be transformed from standard Cartesian coordinates to a cylindrical coordinate system matching the physical layout of the display panel and sweep mechanism [S1].
