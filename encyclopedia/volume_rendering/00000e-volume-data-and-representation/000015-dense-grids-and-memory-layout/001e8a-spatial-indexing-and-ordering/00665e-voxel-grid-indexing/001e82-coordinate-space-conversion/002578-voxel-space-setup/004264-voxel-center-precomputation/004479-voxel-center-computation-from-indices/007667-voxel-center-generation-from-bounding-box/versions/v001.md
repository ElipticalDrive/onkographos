# Voxel Center Generation from Bounding Box

Also called: BboxToVoxels, Bounding Box to Voxels

## Overview
This method generates a list of 3D coordinates representing the centers of voxels that fill a specified axis-aligned bounding box (AABB) at a given resolution. It solves the problem of discretizing a continuous spatial volume into a regular grid of sample points for subsequent volume rendering or ray-casting operations. It differs from [Voxel Center Computation from Indices](11239-voxel-center-computation-from-indices.md) by accepting a bounding box and voxel size directly, rather than pre-computed indices, and differs from [Voxel Grid Coordinate Mapping](15198-voxel-grid-coordinate-mapping.md) by explicitly ensuring 6-connectivity for the resulting raster structure [S1, S2].

## How it works
**Inputs:**
*   `ZBbox`: An axis-aligned bounding box object containing `Min` (3D vector) and `Diagonal` (3D vector, where `Diagonal = Max - Min`).
*   `vSize`: A 3D vector representing the side length of a single voxel along each axis $(v_x, v_y, v_z)$.

**Outputs:**
*   `VoxelPoints`: A list of 3D points, where each point is the center of a voxel within the bounding box.

**Data Structures:**
*   `Point3d`: A structure with fields `x`, `y`, `z` of type float or double.
*   `Vector3d`: A structure with fields `x`, `y`, `z` of type float or double, supporting addition and scalar multiplication.
*   `List`: A dynamic array or linked list storing `Point3d` objects.

**Parameters:**
*   `vSize`: Typical values depend on the scene scale and desired resolution. Must be positive.
*   `ZBbox`: Defined by the extent of the volume data or camera frustum.

**Steps:**
1.  **Initialize:**
    *   Set integer counters $i=0, j=0, k=0$.
    *   Calculate the maximum index for each dimension using floor division of the bounding box diagonal by the voxel size:
        $$ I_{max} = \left\lfloor \frac{ZBbox.Diagonal.x}{vSize.x} \right\rfloor $$
        $$ J_{max} = \left\lfloor \frac{ZBbox.Diagonal.y}{vSize.y} \right\rfloor $$
        $$ K_{max} = \left\lfloor \frac{ZBbox.Diagonal.z}{vSize.z} \right\rfloor $$
    *   Create an empty list `VoxelPoints`.

2.  **Iterate and Compute Centers:**
    *   Loop $k$ from $0$ to $K_{max} - 1$.
    *   Loop $j$ from $0$ to $J_{max} - 1$.
    *   Loop $i$ from $0$ to $I_{max} - 1$.
    *   For each triplet $(i, j, k)$:
        *   Compute the relative offset from the bounding box minimum:
            $$ P_{rel} = (i \cdot vSize.x, \ j \cdot vSize.y, \ k \cdot vSize.z) $$
        *   Compute the absolute center by adding the bounding box minimum and half the voxel size:
            $$ P_{center} = P_{rel} + ZBbox.Min + (0.5 \cdot vSize.x, \ 0.5 \cdot vSize.y, \ 0.5 \cdot vSize.z) $$
        *   Append $P_{center}$ to `VoxelPoints`.

3.  **Return:**
    *   Return `VoxelPoints`.

**Pseudocode:**
```python
def BboxToVoxels(ZBbox, vSize):
    # ZBbox is an object with attributes Min (Vector3) and Diagonal (Vector3)
    # vSize is a Vector3 with attributes x, y, z
    
    # 1. Initialize
    Imax = floor(ZBbox.Diagonal.x / vSize.x)
    Jmax = floor(ZBbox.Diagonal.y / vSize.y)
    Kmax = floor(ZBbox.Diagonal.z / vSize.z)
    
    VoxelPoints = []
    
    # 2. Create voxels
    for k in range(Kmax):
        for j in range(Jmax):
            for i in range(Imax):
                # Relative point based on index and voxel size
                rel_x = i * vSize.x
                rel_y = j * vSize.y
                rel_z = k * vSize.z
                
                # Absolute center: Min + relative_offset + half_voxel_size
                center_x = ZBbox.Min.x + rel_x + 0.5 * vSize.x
                center_y = ZBbox.Min.y + rel_y + 0.5 * vSize.y
                center_z = ZBbox.Min.z + rel_z + 0.5 * vSize.z
                
                VoxelPoints.append((center_x, center_y, center_z))
                
    # 3. Return
    return VoxelPoints
```

**Edge Cases and Pitfalls:**
*   **Zero or Negative Voxel Size:** If any component of `vSize` is zero or negative, division by zero or incorrect floor calculations occur. The method assumes strictly positive voxel sizes [S1, S2].
*   **Empty Bounding Box:** If `ZBbox.Diagonal` has any zero component, the corresponding `Imax`, `Jmax`, or `Kmax` will be 0, resulting in an empty list. This is correct behavior for degenerate volumes.
*   **Precision:** Using floating-point arithmetic for `Diagonal / vSize` before flooring may introduce small errors if the bounding box dimensions are not exact multiples of the voxel size. The sources use floor, which truncates towards zero for positive numbers, effectively ignoring partial voxels at the boundary [S1, S2].

## Operating characteristics
*   **Time Complexity:** $O(I_{max} \cdot J_{max} \cdot K_{max})$, which is linear with respect to the number of voxels generated.
*   **Memory Complexity:** $O(I_{max} \cdot J_{max} \cdot K_{max})$ to store the list of voxel centers.
*   **Strengths:** Simple to implement; guarantees 6-connectivity for the resulting raster, which is critical for certain ray-casting intersection algorithms [S1, S2].
*   **Limitations:** Does not handle non-axis-aligned bounding boxes. Ignores partial voxels at the boundaries due to floor operation.
*   **When to use:** When a regular grid of sample points is needed for volume rendering or ray tracing within a known AABB.
*   **When not to use:** When sparse data structures are preferred, or when the bounding box is not axis-aligned.

## Background
The method is defined as Algorithm 6 in the paper "Voxelization algorithms for geospatial applications" [S1, S2]. It was applied to datasets such as street centerlines from Istanbul (Tarlabasi) and the Rotterdam AHN-2 dataset to generate voxelized representations for geospatial analysis [S1, S2]. The approach ensures 6-connectivity, which is noted as equally effective as other targets for connectivity but distinct in its mesh composition if extended to full voxel geometry [S1, S2].
