# Coordinate Alignment


## Overview
Coordinate alignment shifts a set of 3D points so that a specific statistical property of their coordinates matches a target location. It solves the problem of positioning voxel-based objects relative to a reference frame by adjusting their spatial offset. Unlike [Sliced Volume Coordinate Mapping](8287-sliced-volume-coordinate-mapping.md) which handles chunking, or [Metric Coordinate Conversion](12960-metric-coordinate-mapping.md) which handles unit scaling, this method performs pure translation based on coordinate statistics. It differs from [Coordinate System Conversion](12990-coordinate-system-conversion.md) by preserving the coordinate system orientation while altering the object's position.

## How it works
**Inputs and Outputs:**
- Input: `coords`, a data frame containing columns `x`, `y`, and `z` representing point coordinates [S1, unofficial].
- Input: `loc`, a vector of three values specifying the target location for the alignment [S1, unofficial]. Default is `c(0, 0, 0)`.
- Input: `x`, `y`, `z`, strings specifying the alignment method for each axis [S1, unofficial]. Default is `"mean"`. Valid values are `"min"`, `"mean"`, `"max"`, `"identity"`, and `"median"` [S1, unofficial].
- Output: A data frame with the same structure as `coords`, containing the transformed coordinates [S1, unofficial].

**Data Structures:**
The input and output are standard data frames (tables) with three columns: `x`, `y`, `z`. Each row represents a point in 3D space. No bit-packing or specialized memory layout is specified; standard tabular storage is used [S1, unofficial].

**Algorithm:**
For each axis $a \in \{x, y, z\}$:
1. Calculate the statistic $S_a$ of the current coordinates along axis $a$ using the method specified by the parameter $a$ (e.g., mean, min, max, median). If the method is `"identity"`, $S_a$ is effectively 0 relative to the shift, or the operation is skipped for that axis [S1, unofficial].
2. Calculate the shift amount $\Delta_a = \text{loc}_a - S_a$.
3. Update each coordinate $p_a$ in the column: $p'_a = p_a + \Delta_a$.

**Formulas:**
Let $C_a$ be the vector of coordinates for axis $a$. Let $M(C_a, \text{method})$ be the function computing the statistic.
$$ \Delta_a = \text{loc}_a - M(C_a, \text{method}_a) $$
$$ C'_a = C_a + \Delta_a $$

**Pseudocode:**
```python
def coord_align(coords, loc=(0, 0, 0), x_method="mean", y_method="mean", z_method="mean"):
    """
    Aligns coordinates to a target location based on statistical properties.
    
    Args:
        coords: List of tuples or array-like of shape (N, 3) with columns x, y, z.
        loc: Tuple of 3 floats (target_x, target_y, target_z).
        x_method, y_method, z_method: String, one of 'min', 'mean', 'max', 'identity', 'median'.
        
    Returns:
        List of tuples or array-like of shape (N, 3) with transformed coordinates.
    """
    xs = [p[0] for p in coords]
    ys = [p[1] for p in coords]
    zs = [p[2] for p in coords]
    
    # Helper to calculate statistic
    def get_statistic(values, method):
        if method == "min":
            return min(values)
        elif method == "max":
            return max(values)
        elif method == "mean":
            return sum(values) / len(values)
        elif method == "median":
            sorted_vals = sorted(values)
            n = len(sorted_vals)
            if n % 2 == 0:
                return (sorted_vals[n//2 - 1] + sorted_vals[n//2]) / 2
            else:
                return sorted_vals[n//2]
        elif method == "identity":
            return 0
        else:
            raise ValueError(f"Unknown method: {method}")

    # Calculate shifts
    shift_x = loc[0] - get_statistic(xs, x_method)
    shift_y = loc[1] - get_statistic(ys, y_method)
    shift_z = loc[2] - get_statistic(zs, z_method)
    
    # Apply shifts
    transformed = []
    for p in coords:
        new_x = p[0] + shift_x
        new_y = p[1] + shift_y
        new_z = p[2] + shift_z
        transformed.append((new_x, new_y, new_z))
        
    return transformed
```

**Edge Cases and Pitfalls:**
- If the coordinate list is empty, the statistic calculation may fail or return undefined values. The source does not specify behavior for empty inputs [S1, unofficial].
- The `"identity"` method implies no shift is calculated for that axis relative to the statistic, effectively leaving the axis unchanged if `loc` is 0, or shifting by `loc` if interpreted as a direct offset. The source lists it as a valid method alongside statistical measures [S1, unofficial].

## Operating characteristics
Time complexity is $O(N)$ where $N$ is the number of points, as it requires a single pass to compute statistics and a second pass to apply shifts. Memory complexity is $O(N)$ to store the output coordinates. Performance is limited by the cost of sorting for median calculation if that method is chosen, making it $O(N \log N)$ in that specific case. Strengths include simplicity and flexibility in positioning. Limitations include the lack of rotation or scaling capabilities, which are handled by sibling methods like [Coordinate System Conversion](12990-coordinate-system-conversion.md).

## Background
The method originates from the `isocubes` package for voxel data visualization, which provides utilities for manipulating isometric cube representations. It is part of a suite of coordinate transformation functions including `coord_translate` and `coord_rotate` [S1, unofficial].
