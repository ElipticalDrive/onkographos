# Coordinate Conversion Utilities

Also called: Voxel to World Transform, World-to-Voxel Coordinate Conversion, Voxel Coordinate Conversion, LocalToVoxel, VoxelToLocal

## Overview
Coordinate Conversion Utilities provide bidirectional mapping between discrete voxel grid indices and continuous world-space coordinates [S1, unofficial][S2, unofficial][S3, unofficial]. They solve the spatial indexing problem by translating between the logical structure of a voxel grid and the physical or application coordinate system [S1, unofficial][S2, unofficial]. What sets this method apart from siblings like [Sliced Volume Coordinate Mapping](8287-sliced-volume-coordinate-mapping.md) or [Metric Coordinate Conversion](12960-metric-coordinate-conversion.md) is its focus on fundamental grid-to-world and world-to-grid transformations without adding domain-specific constraints like 2D texture flattening or metric decomposition [S2, unofficial][S3, unofficial].

## How it works
### Inputs and Outputs
*   **World-to-Voxel Input:** A 3D world-space position vector $\mathbf{p}_{world} = (x, y, z)$ [S2, unofficial][S3, unofficial].
*   **World-to-Voxel Output:** A 3D voxel coordinate vector $\mathbf{v}_{voxel} = (i, j, k)$, representing either global indices or local indices within a chunk [S2, unofficial][S3, unofficial].
*   **Voxel-to-World Input:** A 3D voxel coordinate vector $\mathbf{v}_{voxel}$ (global or local) [S1, unofficial][S3, unofficial].
*   **Voxel-to-World Output:** A 3D world-space position vector $\mathbf{p}_{world}$, typically representing the center of the voxel [S1, unofficial][S3, unofficial].

### Data Structures
*   **Transformation Parameters:**
    *   `world_scale`: A scalar defining the size of one voxel in world units [S1, unofficial].
    *   `world_position`: The world-space origin or offset of the voxel grid [S1, unofficial].
    *   `center`: The center offset of the voxel grid, used to align the grid center with the world origin [S1, unofficial].
    *   `chunk_size`: The dimensions of a chunk in voxels for chunked grids [S3, unofficial].
    *   `chunk_coord`: The integer coordinates of the chunk containing the voxel [S3, unofficial].
*   **Coordinate System Enum:** A `uint32_t` enum representing axis directions for coordinate system alignment, used in formats like SPZ [S4, unofficial].

### Steps
1.  **World-to-Voxel (Grid-Centered):** Subtract the grid origin, scale by `world_scale`, and add the `center` offset to obtain voxel indices [S1, unofficial].
2.  **World-to-Voxel (Chunked):** Convert world position to chunk coordinates using floor division, then compute local voxel coordinates within the chunk [S3, unofficial].
3.  **Voxel-to-World (Grid-Centered):** Subtract the `center` offset, divide by `world_scale`, and add the `world_position` offset to obtain world coordinates [S1, unofficial].
4.  **Voxel-to-World (Chunked):** Convert local voxel coordinates to global coordinates by adding `chunk_coord * chunk_size`, then compute world position by scaling and adding the chunk origin plus half-voxel offset [S3, unofficial].
5.  **Coordinate System Alignment:** Compare axis direction bitmasks to determine alignment and required rotation [S4, unofficial].

### Formulas
#### 1. Standard Voxel-to-World (Grid-Centered)
$$ \mathbf{p}_{world}[i] = \left( \frac{\mathbf{v}_{voxel}[i] - \mathbf{center}[i]}{\mathbf{world\_scale}} \right) + \mathbf{world\_position}[i] $$
Where:
*   $i \in \{0, 1, 2\}$ corresponds to $x, y, z$ [S1, unofficial].
*   $\mathbf{center}[0] = \text{VOXELS\_X} / 2$, $\mathbf{center}[1] = \text{VOXELS\_Y} / 2$, $\mathbf{center}[2] = 0$ [S1, unofficial].
*   $\mathbf{world\_position}$ is the world-space location of the grid's reference point [S1, unofficial].

#### 2. Chunked Global/Local Conversion
For chunked voxel worlds, global voxel coordinates $\mathbf{v}_{global}$ are decomposed into chunk coordinates $\mathbf{c}$ and local voxel coordinates $\mathbf{v}_{local}$ [S3, unofficial].
**Global to Local:**
$$ \mathbf{v}_{local}[i] = \mathbf{v}_{global}[i] \pmod{\text{chunk\_size}} $$
If $\mathbf{v}_{local}[i] < 0$, then $\mathbf{v}_{local}[i] \leftarrow \mathbf{v}_{local}[i] + \text{chunk\_size}$ [S3, unofficial].
**Local to Global:**
$$ \mathbf{v}_{global}[i] = \mathbf{c}[i] \times \text{chunk\_size} + \mathbf{v}_{local}[i] $$
Where $\mathbf{c}[i]$ is the chunk coordinate index [S3, unofficial].

#### 3. Coordinate System Bit Encoding
Used to determine axis alignment and rotation requirements between two coordinate systems represented as bitmasks [S4, unofficial].
*   **Axes Match:**
    $$ \text{axesMatch}(a, b) = \{ \text{match}_0, \text{match}_1, \text{match}_2 \} $$
    Where $\text{match}_k = ((a_{num} \gg k) \& 1) == ((b_{num} \gg k) \& 1)$ for $k \in \{0, 1, 2\}$ [S4, unofficial].
    If either system is `UNSPECIFIED` (<0), returns $\{ \text{true}, \text{true}, \text{true} \}$ [S4, unofficial].
*   **Need Rotation:**
    $$ \text{needRotation}(a, b) = ((a_{num} \gg 3) \& 1) \neq ((b_{num} \gg 3) \& 1) $$
    If either is `UNSPECIFIED`, returns `false` [S4, unofficial].

### Pseudocode
```python
def voxel_to_world(voxel_pos, world_scale, world_position, center=None):
    """Converts voxel coordinates to world-space position [S1, unofficial][S3, unofficial]."""
    if center is not None:
        return tuple(
            ((voxel_pos[i] - center[i]) / world_scale) + world_position[i]
            for i in range(3)
        )
    else:
        return tuple(
            world_position[i] + (voxel_pos[i] + 0.5) * world_scale
            for i in range(3)
        )

def world_to_voxel(world_pos, world_scale, world_position, center=None):
    """Converts world-space position to voxel coordinates [S1, unofficial][S3, unofficial]."""
    if center is not None:
        return tuple(
            (world_pos[i] - world_position[i]) * world_scale + center[i]
            for i in range(3)
        )
    else:
        return tuple(
            (world_pos[i] - world_position[i]) / world_scale
            for i in range(3)
        )

def global_to_local_voxel(global_voxel, chunk_size):
    """Converts global voxel coordinates to local chunk coordinates [S3, unofficial]."""
    local = [g % chunk_size for g in global_voxel]
    for i in range(3):
        if local[i] < 0:
            local[i] += chunk_size
    return tuple(local)

def local_to_global_voxel(local_voxel, chunk_coord, chunk_size):
    """Converts local chunk voxel coordinates to global voxel coordinates [S3, unofficial]."""
    return tuple(
        chunk_coord[i] * chunk_size + local_voxel[i]
        for i in range(3)
    )

def axes_match(coord_sys_a, coord_sys_b):
    """Determines if axes align between two coordinate systems [S4, unofficial]."""
    UNSPECIFIED = -1
    if coord_sys_a < UNSPECIFIED or coord_sys_b < UNSPECIFIED:
        return (True, True, True)
    a_num = coord_sys_a - 1
    b_num = coord_sys_b - 1
    return tuple(
        ((a_num >> k) & 1) == ((b_num >> k) & 1)
        for k in range(3)
    )

def need_rotation(coord_sys_a, coord_sys_b):
    """Checks if a pi/2 rotation is required between coordinate systems [S4, unofficial]."""
    UNSPECIFIED = -1
    if coord_sys_a < UNSPECIFIED or coord_sys_b < UNSPECIFIED:
        return False
    a_num = coord_sys_a - 1
    b_num = coord_sys_b - 1
    return ((a_num >> 3) & 1) != ((b_num >> 3) & 1)
```

### Parameters and Typical Values
*   `world_scale`: Typically 1.0 for unit voxels, or the physical size of a voxel (e.g., 0.01 for 1cm voxels) [S1, unofficial].
*   `chunk_size`: Commonly $16 \times 16 \times 16$ or $32 \times 32 \times 32$ in chunked voxel engines [S3, unofficial].
*   `ground`: In heightmap conversion, typically `'xy'` or `'xz'` [S5, unofficial].

### Edge Cases and Pitfalls
*   **Negative Coordinates:** Modulo operations with negative numbers vary by language; the standard approach is to add the chunk size if the result is negative to ensure positive local indices [S3, unofficial].
*   **Matrix Indexing vs. Isometric Space:** When converting heightmaps, matrices are indexed top-down, while isometric space often increases bottom-up, requiring a vertical flip (`flipy=TRUE`) [S5, unofficial].
*   **Solid Operation Cost:** Making a heightmap "solid" (filling gaps) is computationally expensive in memory and CPU; it should be disabled (`solid=FALSE`) for large or complex heightmaps if performance is critical [S5, unofficial].
*   **Visibility Removal:** Removing non-visible voxels (`check_visibility=TRUE`) can cause issues if the rendering viewpoint changes, as hidden voxels are permanently removed from the coordinate list [S5, unofficial].

## Subtopics

### [Sliced Volume Coordinate Mapping](8287-sliced-volume-coordinate-mapping.md)
Converts 3D voxel coordinates to 2D texture coordinates for tiled 2D slice storage, enabling GPU sampling of 3D data without 3D texture support.

### [Metric Coordinate Conversion](12960-metric-coordinate-conversion.md)
Decomposes world positions into integer meter and fractional meter components for large-scale spatial indexing and high-precision local sampling.

### [Coordinate System Conversion](12990-coordinate-system-conversion.md)
Maps 3D spatial positions to 2D panel coordinates and angular sweep parameters for swept-volume displays.

### [Coordinate Alignment](14251-coordinate-alignment.md)
Shifts voxel coordinates to align statistical properties (min, mean, median, max) with a target location without altering topology [G].

### [Adaptive Coordinate Conversion](6876-adaptive-coordinate-conversion.md)
A technique for visualizing 3D ultrasound datasets by dynamically transforming points from their native pyramidal coordinate system into a Cartesian grid during rendering. Unlike methods that rely on pre-interpolation or iterative mapping, this approach leverages a direct one-to-one correspondence between grid rings to perform bilinear mapping. It is primarily used in GPU-accelerated raycasting to enable real-time visualization of volumetric data acquired in non-Cartesian geometries.

### Coordinate System Bit Encoding
A method for determining axis alignment and rotation requirements between coordinate systems using bitmasks [S4, unofficial]. The `CoordinateSystem` enum is a `uint32_t` with 16 valid values (1-16) representing axis directions [S4, unofficial]. Bit 0: Left(0)/Right(1). Bit 1: Down(0)/Up(1). Bit 2: Back(0)/Front(1). Value 0 is UNSPECIFIED [S4, unofficial]. Examples: LDB=1, RDB=2, LUB=3, RUB=4, LDF=5, RDF=6, LUF=7, RUF=8, LFD=9, RFD=10, LFU=11, RFU=12, LBD=13, RBD=14, LBU=15, RBU=16 [S4, unofficial].

### Heightmap Coordinate Calculation
Calculates voxel coordinates from a matrix where values indicate height above the ground [S5, unofficial]. Parameters include `mat` (integer matrix), `fill` (color matrix, optional), `scale` (default 1), `flipx` (default FALSE), `flipy` (default TRUE), `ground` (default 'xy'), `solid` (default TRUE, expensive), and `check_visibility` (default FALSE) [S5, unofficial]. Returns a data.frame of voxel coordinates [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ for standard coordinate conversions [S1, unofficial][S3, unofficial]. Chunked conversions involve modulo and division, still $O(1)$ per coordinate [S3, unofficial].
*   **Memory Complexity:** $O(1)$ for the conversion logic itself [S3, unofficial].
*   **Strengths:** Simple, fast, and deterministic [S3, unofficial].
*   **Limitations:** Standard conversions assume a uniform grid [S4, unofficial].
*   **When to Use:** Whenever voxel indices need to be mapped to world positions or vice versa [S1, unofficial][S2, unofficial].

## Background
Coordinate conversion utilities originated alongside early voxel-based graphics systems to bridge discrete grid indexing and continuous rendering spaces [S1, unofficial]. With the adoption of chunked voxel engines, global-to-local coordinate conversion became necessary to manage memory and world boundaries [S3, unofficial]. In medical imaging, adaptive conversion was developed to handle non-Cartesian data sources like ultrasound [S4, unofficial]. In file formats like SPZ, coordinate system encoding was introduced to handle axis alignment and rotation between different software vendors [S4, unofficial]. Heightmap conversion utilities emerged in the R ecosystem for visualizing isometric voxel data [S5, unofficial].
