# Incremental Back-Rotation for Voxel Mapping

Also called: Back rotation, Brute force rotation, Destination-to-source rotation, Discrete Tool Rotation (Inverse Method with Optimization), Optimised rotation method

## Overview
Incremental back-rotation is a voxel mapping algorithm that determines the source voxel position for each destination voxel during a 3D rotation, thereby eradicating the holes produced by forward (direct) rotation [S1][S2, unofficial]. While forward rotation maps source voxels to destination positions and suffers from truncation errors that leave gaps in the final image, back-rotation maps every destination voxel back to the source space to ensure complete coverage [S2, unofficial]. It sets itself apart from naive inverse rotation by employing an incremental scanning procedure that updates coordinates using constant increments of sine and cosine, reducing computational cost [S1].

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   Source voxel grid (initial image) with dimensions $D_{src}$.
    *   Destination voxel grid (final image) with dimensions $D_{dst}$.
    *   Rotation angle $\theta$ (typically about a single axis, e.g., Z-axis) [S1].
    *   Rotation matrix $R$ and its inverse $R^{-1}$ [S2, unofficial].
*   **Outputs:**
    *   Destination voxel grid populated with values sampled from the source grid.

### Data Structures
*   **Voxel Grids:** 3D arrays of values. Indices are integer coordinates $(x, y, z)$.
*   **Basis Vectors:** The orthogonal axes of the destination grid expressed in the source basis, computed via inverse rotation [S2, unofficial].
*   **Incremental State:** Current source coordinate $(X_{src}, Y_{src})$ and accumulated increments for $X$ and $Y$ directions [S1].

### Steps

1.  **Compute Destination Bounding Box:**
    Rotate the eight corners of the source voxel grid using the rotation matrix. Compute the axis-aligned bounding box (AABB) of these eight rotated corners. This defines the dimensions and extent of the destination grid [S2, unofficial].

2.  **Initialize Back-Rotation Origin:**
    Identify the minimum coordinates of the destination bounding box. Back-rotate these minimum coordinates to find the corresponding starting position in the source space. This is done by applying the inverse rotation (replacing $\theta$ with $-\theta$) to the destination minimums [S1].

3.  **Compute Basis Increments (Optimization):**
    Instead of computing the inverse rotation for every voxel, compute the inverse transformation for only four voxels that define three orthogonal axes of the destination grid. These define the basis vectors $\mathbf{I}, \mathbf{J}, \mathbf{K}$ in the source space [S2, unofficial].
    *   Let $\mathbf{K}$ be the increment vector for moving along the Z-axis of the destination grid.
    *   Let $\mathbf{J}$ be the increment vector for moving along the Y-axis of the destination grid.
    *   Let $\mathbf{I}$ be the increment vector for moving along the X-axis of the destination grid.
    These vectors allow the position in the source grid to be updated via vector addition rather than matrix multiplication for each voxel [S2, unofficial].

4.  **Incremental Scan:**
    Iterate through the destination grid. For each voxel, calculate the corresponding source coordinate using the pre-computed basis vectors. This avoids heavy trigonometric computations per voxel [S1].

### Formulas

For a rotation about the Z-axis, the standard forward rotation is:
$$ X_{dest} = X_{src} \cos \theta - Y_{src} \sin \theta $$
$$ Y_{dest} = X_{src} \sin \theta + Y_{src} \cos \theta $$

The back-rotation (inverse) equations map a destination coordinate $(X_{dest}, Y_{dest})$ to the source $(X_{src}, Y_{src})$. The incremental updates for adjacent destination voxels are derived from the derivatives of the inverse rotation.

The source coordinates for the voxel at $(X_{dest}+1, Y_{dest})$ are:
$$ X_{src}^{(X+1)} = X_{src}^{(0)} + X_{dest} \cos \theta + (Y_{dest} + 1) \sin \theta $$
$$ Y_{src}^{(X+1)} = Y_{src}^{(0)} - X_{dest} \sin \theta + (Y_{dest} + 1) \cos \theta $$

The source coordinates for the voxel at $(X_{dest}, Y_{dest}+1)$ are:
$$ X_{src}^{(Y+1)} = X_{src}^{(0)} + (X_{dest} + 1) \cos \theta + Y_{dest} \sin \theta $$
$$ Y_{src}^{(Y+1)} = Y_{src}^{(0)} - (X_{dest} + 1) \sin \theta + Y_{dest} \cos \theta $$

*Note: The source text provides specific incremental forms (Equations 11-14 in [S1]) which effectively compute the new source position by adding constant increments of $\sin \theta$ and $\cos \theta$ to the previous position. Specifically, moving in the destination X-direction adds $\cos \theta$ to $X_{src}$ and $-\sin \theta$ to $Y_{src}$ (scaled appropriately). Moving in the destination Y-direction adds $\sin \theta$ to $X_{src}$ and $\cos \theta$ to $Y_{src}$ [S1].*

The incremental update for the basis vectors (Optimization 1) allows the position $M$ in the source image to be updated as:
$$ M_{next} = M_{current} + \mathbf{V} $$
where $\mathbf{V}$ is the appropriate basis vector ($\mathbf{I}, \mathbf{J},$ or $\mathbf{K}$) [S2, unofficial].

### Parameters and Typical Values
*   **Theta ($\theta$):** Rotation angle in radians.
*   **Grid Size:** Typically powers of 2 (e.g., $8^3, 16^3, 32^3, 64^3$) for efficient memory access [S2, unofficial].

### Edge Cases and Pitfalls
*   **Holes:** Forward rotation causes holes because multiple source voxels project to the same destination voxel due to truncation. Back-rotation solves this by ensuring every destination voxel is filled [S1][S2, unofficial].
*   **Aliasing:** Direct inverse rotation can produce significant aliasing. Antialiasing techniques (e.g., trilinear interpolation) are recommended [S2, unofficial].
*   **Performance:** Brute force inverse rotation (computing matrix multiplication for every voxel) is computationally expensive. The incremental method reduces this by using fixed-point additions [S1].
*   **Cache:** Storing already rotated voxels in a cache can improve performance if the contact area between the tool and object changes incrementally [S2, unofficial].

## Subtopics

### Incremental Rotation Algorithm
This variant emphasizes the use of parallel memory and barrel shifters to move entire beams of voxels in a single operation, leveraging the fact that voxels along beams parallel to the rotation axis are identically rotated [S1]. It specifically addresses the Z-axis rotation where the incremental updates for $X$ and $Y$ are constant for all $Z$ [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Time Complexity:** The incremental method reduces the per-voxel cost from a full matrix multiplication to a few fixed-point additions. The complexity is linear with respect to the number of voxels in the destination grid, $O(N)$, where $N$ is the total voxel count [S1][S2, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the source and destination grids. Additional $O(1)$ for basis vectors and cache [S2, unofficial].

### Measured Performance
Performance data from [S2, unofficial] on a PC with AMD 3GHz, 1GB RAM, NVIDIA Geforce FX 5200:

| Grid Size | Brute Force (ms) | Optimised (ms) |
| :--- | :--- | :--- |
| 8x8x8 | 0.1826 | 0.0456 |
| 16x16x16 | 1.321 | 0.322 |
| 32x32x32 | 10.17 | 2.49 |
| 64x64x64 | 82.3 | 18.1 |

The optimised method reduces rotation time by approximately 75% compared to the brute force method for a $16^3$ tool [S2, unofficial]. Computation times depend on the rotation angle because the number of voxels needed to store the rotated tool changes with the angle [S2, unofficial]. Worst-case times assume all voxels are rotated; practical times are lower due to caching and sparse contact areas [S2, unofficial].

### Strengths and Limitations
*   **Strengths:** Eliminates holes in the rotated image; computationally efficient compared to brute force inverse rotation; suitable for real-time applications when optimized [S2, unofficial].
*   **Limitations:** Still subject to aliasing if interpolation is not used; performance degrades with larger grid sizes; requires pre-computation of bounding boxes and basis vectors [S2, unofficial].

## Background

The method originated in the context of voxel frame buffer processors and discrete tools for virtual sculpture. The "voxblt Engine" described in [S1] introduced the incremental back-rotation technique to handle room rotation in voxel graphics, addressing the hole problem inherent in forward rotation. Later, [S2, unofficial] refined this for discrete tools in virtual sculpture, proposing an optimized inverse method with basis vector interpolation and caching to achieve real-time performance.
