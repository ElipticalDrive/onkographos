# Voxel Grid Initialization & Clamping

Also called: Voxel Grid Construction with Capacity Limits

## Overview
This method initializes the dimensions and vertex counts of a uniform voxel grid while enforcing hardware vertex limits to prevent GPU buffer overflows [S1, unofficial]. It differs from its parent, [Voxel Grid Construction from AABB](12627-voxel-grid-construction-from-aabb.md), by focusing on numerical stability and resource constraints rather than spatial mapping; it takes the target resolution and clamps it to fit within a maximum vertex budget [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Target voxel dimensions ($N_x, N_y, N_z$), maximum allowed vertex count ($V_{max}$), and physical voxel size ($s$) [S1, unofficial].
- **Output:** Clamped voxel dimensions ($N'_x, N'_y, N'_z$), vertex counts ($V'_x, V'_y, V'_z$), total voxel count ($T_V$), and total vertex count ($T_{Vtx}$) [S1, unofficial].

**Data Structures:**
The source defines a `Voxel` class with the following fields [S1, unofficial]:
- `voxelPosition`: `Vector3` (world position of the grid origin).
- `voxelGrid`: `Vector3Int` (physical grid dimensions).
- `boundaryCenter`: `Vector3` (center of the bounding box).
- `boundaryWorldPos`: `Vector3` (world position of the boundary).
- `numVoxel`: `Vector3Int` (number of voxels per axis, $N_x, N_y, N_z$).
- `numVertex`: `Vector3Int` (number of vertices per axis, $N_x+1, N_y+1, N_z+1$).
- `totalVoxel`: `long` (total number of voxels, $N_x \times N_y \times N_z$).
- `totalVertex`: `int` (total number of vertices, $(N_x+1)(N_y+1)(N_z+1)$).
- `voxelNodes`: `Node[8]` (array of 8 neighbor nodes).

**Parameters:**
- $V_{max}$: Maximum allowed vertex count. Default value is 858,993,459 [S1, unofficial]. This limit prevents integer overflow and GPU buffer exhaustion [S1, unofficial].
- $s$: Physical size of a single voxel unit [S1, unofficial].

**Steps:**
1. **Store Previous Dimensions:** Save the current target voxel dimensions $(N_x, N_y, N_z)$ as $(N^{old}_x, N^{old}_y, N^{old}_z)$ [S1, unofficial].
2. **Clamp Dimensions:** Clamp each dimension to a minimum of 1 and a maximum derived from $V_{max}$ and the other two dimensions. The maximum for a dimension is calculated as $\lfloor \frac{V_{max}}{N^{old}_j \times N^{old}_k} \rfloor - 2$, where $j, k$ are the other two axes. This ensures that the resulting vertex count $(N_x+1)(N_y+1)(N_z+1)$ does not exceed $V_{max}$ [S1, unofficial].
   $$ N'_i = \text{clamp}(N^{old}_i, 1, \lfloor \frac{V_{max}}{N^{old}_j \times N^{old}_k} \rfloor - 2) $$
   where $i \in \{x, y, z\}$ and $\{i, j, k\} = \{x, y, z\}$ [S1, unofficial].
3. **Clamp Coordinates:** Ensure voxel grid coordinates are within valid ranges [S1, unofficial].
4. **Calculate Vertex Counts:** Compute the number of vertices per axis as $V'_i = N'_i + 1$. Clamp each component of `numVertex` between 2 and 65,535 [S1, unofficial].
5. **Compute Totals:** Calculate total voxels $T_V = N'_x \times N'_y \times N'_z$ and total vertices $T_{Vtx} = V'_x \times V'_y \times V'_z$ [S1, unofficial].
6. **Final Validation:** If $T_{Vtx} > V_{max}$, log an error and adjust the Y-dimension ($N'_y$) downwards until the constraint is satisfied [S1, unofficial].

**Pseudocode:**
```python
def clamp(val, min_val, max_val):
    return max(min_val, min(val, max_val))

def initialize_voxel_grid(num_voxel: tuple, max_vertex: int = 858993459) -> dict:
    # Step 1: Store previous dimensions
    old_num_voxel = num_voxel

    # Guard against division by zero if old dimensions are zero or negative [G]
    old_x = max(old_num_voxel[0], 1)
    old_y = max(old_num_voxel[1], 1)
    old_z = max(old_num_voxel[2], 1)

    # Step 2: Clamp dimensions based on vertex limit
    # Max for X: max_vertex / (old_Y * old_Z) - 2
    max_x = max_vertex // (old_y * old_z) - 2
    new_x = clamp(old_num_voxel[0], 1, max_x)

    # Max for Y: max_vertex / (old_X * old_Z) - 2
    max_y = max_vertex // (old_x * old_z) - 2
    new_y = clamp(old_num_voxel[1], 1, max_y)

    # Max for Z: max_vertex / (old_Y * old_X) - 2
    max_z = max_vertex // (old_y * old_x) - 2
    new_z = clamp(old_num_voxel[2], 1, max_z)

    # Step 3: Clamp voxel grid coordinates to valid ranges [G]
    # (Assumed handled by dimension clamping or specific coordinate logic)

    # Step 4: Calculate numVertex as numVoxel + 1, clamped between 2 and 65535
    num_vertex = (
        clamp(new_x + 1, 2, 65535),
        clamp(new_y + 1, 2, 65535),
        clamp(new_z + 1, 2, 65535)
    )

    # Step 5: Compute totalVoxel and totalVertex
    total_voxel = new_x * new_y * new_z
    total_vertex = num_vertex[0] * num_vertex[1] * num_vertex[2]

    # Step 6: If totalVertex exceeds maxVertex, adjust Y-dimension
    if total_vertex > max_vertex:
        print("Error: Total vertices exceed maxVertex. Adjusting Y-dimension.")
        while total_vertex > max_vertex and new_y > 1:
            new_y -= 1
            num_vertex = (
                num_vertex[0],
                clamp(new_y + 1, 2, 65535),
                num_vertex[2]
            )
            total_vertex = num_vertex[0] * num_vertex[1] * num_vertex[2]

    return {
        "num_voxel": (new_x, new_y, new_z),
        "num_vertex": num_vertex,
        "total_voxel": total_voxel,
        "total_vertex": total_vertex
    }
```

**Edge Cases and Pitfalls:**
- **Zero or Negative Input:** If initial dimensions are $\le 0$, the clamp to 1 ensures valid grid creation [S1, unofficial].
- **Integer Overflow:** Using 32-bit integers for vertex counts can overflow for large grids; $V_{max}$ is set to prevent this [S1, unofficial].
- **Degenerate Grids:** Clamping to minimum 1 voxel ensures the grid is never empty [S1, unofficial].
- **Division by Zero:** The clamping formula uses previous dimensions in the denominator; if previous dimensions are zero, a guard is required before division [G].

## Operating characteristics
- **Time Complexity:** $O(1)$, as it involves a fixed number of arithmetic operations and clamps [S1, unofficial].
- **Memory Complexity:** $O(1)$, storing only a few integer vectors [S1, unofficial].
- **Strengths:** Prevents GPU crashes due to buffer overflows; ensures numerical stability for downstream rendering algorithms [S1, unofficial].
- **Limitations:** May reduce resolution significantly if the target grid is too large for the hardware limit [S1, unofficial].
- **When to Use:** Always before initializing voxel grids for GPU-based rendering or reconstruction to ensure safety [S1, unofficial].
- **When Not to Use:** Not applicable; this is a safety step required for robust implementation [S1, unofficial].
