# Voxel Grid Coordinate Mapping

Also called: Grid Index to World Coordinate Mapping, Linear Buffer Index to World Coordinate Mapping

## Overview
Voxel Grid Coordinate Mapping provides the transformations between discrete voxel indices, linear buffer positions, and continuous world-space coordinates [S1, unofficial]. It handles the row-major flattening of a cubic grid into a 1D buffer and maps grid indices to world-space vertex coordinates for geometry-based volume rendering [S1, unofficial][S2]. It is distinguished from [Voxel Center Computation from Indices](11239-voxel-center-computation-from-indices.md) by explicitly computing vertex positions for rendering primitives rather than just center points [S1, unofficial][S2].

## How it works
**Inputs:**
- `SamplesPerSide`: Integer, the number of voxels along one axis of the cubic grid.
- `CellSize`: Float, the physical width/height/depth of a single voxel.
- `index`: Integer, the linear buffer index.
- `(x, y, z)`: Integers, the 3D grid coordinates.

**Outputs:**
- `(x, y, z)`: 3D grid coordinates.
- `index`: Linear buffer index.
- `(xPos, yPos, zPos)`: World-space vertex coordinates.

**Data Structures:**
The linear buffer is a 1D array of size `SamplesPerSide^3` [S1, unofficial]. The mapping assumes a row-major layout where the Z-axis is the slowest varying dimension, Y is intermediate, and X is the fastest [S1, unofficial].

**Steps:**

1. **Linear Index to 3D Grid Coordinates:**
   Given a linear `index`, compute the 3D grid coordinates `(x, y, z)` using integer division and modulo operations [S1, unofficial]:
   $$
   \begin{aligned}
   z &= \text{index} / (\text{SamplesPerSide} \times \text{SamplesPerSide}) \\
   y &= (\text{index} \pmod{\text{SamplesPerSide} \times \text{SamplesPerSide}}) / \text{SamplesPerSide} \\
   x &= \text{index} \pmod{\text{SamplesPerSide}}
   \end{aligned}
   $$

2. **3D Grid Coordinates to Linear Index:**
   Given `(x, y, z)`, compute the linear `index` [S1, unofficial]:
   $$
   \text{index} = x + y \times \text{SamplesPerSide} + z \times \text{SamplesPerSide} \times \text{SamplesPerSide}
   $$

3. **3D Grid Coordinates to World Space Vertex Coordinates:**
   Map the discrete grid indices to continuous world coordinates [S1, unofficial]. First, calculate the bounding half-extent `bound` based on the number of intervals (`gridSize = SamplesPerSide - 1`) [S1, unofficial]:
   $$
   \text{gridSize} = \text{SamplesPerSide} - 1
   $$
   $$
   \text{bound} = (\text{gridSize} / 2) \times \text{CellSize}
   $$
   Then, compute the world coordinates using linear interpolation from `-bound` to `bound` [S1, unofficial]:
   $$
   \begin{aligned}
   x_{\text{Pos}} &= \text{Lerp}(-\text{bound}, \text{bound}, x / \text{gridSize}) \\
   y_{\text{Pos}} &= \text{Lerp}(-\text{bound}, \text{bound}, y / \text{gridSize}) \\
   z_{\text{Pos}} &= \text{Lerp}(-\text{bound}, \text{bound}, z / \text{gridSize})
   \end{aligned}
   $$
   Where $\text{Lerp}(a, b, t) = a + t(b - a)$.

**Pseudocode:**
```python
def linear_to_grid(index: int, samples_per_side: int) -> tuple[int, int, int]:
    """Converts a linear buffer index to 3D grid coordinates (x, y, z)."""
    z = index // (samples_per_side * samples_per_side)
    y = (index % (samples_per_side * samples_per_side)) // samples_per_side
    x = index % samples_per_side
    return (x, y, z)

def grid_to_linear(x: int, y: int, z: int, samples_per_side: int) -> int:
    """Converts 3D grid coordinates to a linear buffer index."""
    return x + y * samples_per_side + z * samples_per_side * samples_per_side

def grid_to_world(x: int, y: int, z: int, cell_size: float, samples_per_side: int) -> tuple[float, float, float]:
    """Maps 3D grid indices to world-space vertex coordinates."""
    grid_size = samples_per_side - 1
    bound = (grid_size / 2.0) * cell_size
    
    t_x = x / grid_size
    t_y = y / grid_size
    t_z = z / grid_size
    
    x_pos = -bound + t_x * (2.0 * bound)
    y_pos = -bound + t_y * (2.0 * bound)
    z_pos = -bound + t_z * (2.0 * bound)
    
    return (x_pos, y_pos, z_pos)
```

**Edge Cases and Pitfalls:**
- **Division by Zero:** If `SamplesPerSide` is 1, `gridSize` becomes 0, causing division by zero in the world coordinate mapping [G].
- **Identity Transformation:** If the mapping between vertex coordinates and voxel coordinates is not an identity transformation, the rendered volume will appear warped [S2].

## Subtopics

### Per-Vertex Coordinate Mapping
This variant replaces standard geometry initialization functions (e.g., `my_InitGeometry`) to explicitly specify voxel coordinates on a per-vertex basis [S2]. If the mapping between the vertex coordinates and the underlying voxel grid coordinates is not an identity transformation, the rendered volume will appear warped [S2].

## Background
The specific world coordinate mapping formula, which centers the grid around the origin using `SamplesPerSide - 1` as the divisor, is documented in the IsoMesh project [S1, unofficial]. The concept of per-vertex coordinate mapping and the warning regarding warping due to non-identity transformations originates from the SGI Volumizer documentation [S2].
