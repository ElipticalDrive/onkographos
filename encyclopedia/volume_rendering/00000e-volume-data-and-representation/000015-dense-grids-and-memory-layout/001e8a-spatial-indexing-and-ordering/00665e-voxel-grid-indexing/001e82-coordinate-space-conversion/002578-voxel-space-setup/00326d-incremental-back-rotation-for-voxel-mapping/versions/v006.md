# Incremental Back-Rotation for Voxel Mapping

Also called: Back rotation, Brute force rotation, Destination-to-source rotation, Discrete Tool Rotation (Inverse Method with Optimization), Optimised rotation method

## Overview
Incremental back-rotation is a voxel mapping algorithm that determines the source voxel position for each destination voxel during a 3D rotation, thereby eradicating the holes produced by forward (direct) rotation [S1][S2, unofficial]. While forward rotation maps source voxels to destination positions and suffers from truncation errors that leave gaps in the final image, back-rotation maps every destination voxel back to the source space to ensure complete coverage [S2, unofficial]. It sets itself apart from naive inverse rotation by employing an incremental scanning procedure that updates coordinates using constant increments of sine and cosine, reducing computational cost [S1].

## How it works

### Inputs and Outputs
*   **Inputs:** Source voxel grid (initial image), destination voxel grid (final image), rotation angle $\theta$ (typically about a single axis, e.g., Z-axis) [S1], and the inverse rotation matrix $R^{-1}$ [S2, unofficial].
*   **Outputs:** Destination voxel grid populated with values sampled from the source grid [S2, unofficial].

### Data Structures
*   **Voxel Grids:** 3D arrays of values indexed by integer coordinates $(x, y, z)$ [S1][S2, unofficial].
*   **Basis Vectors:** The orthogonal axes of the destination grid expressed in the source basis, computed via inverse rotation of the destination basis vectors [S2, unofficial].
*   **Incremental State:** Current source coordinate $(X_{src}, Y_{src})$ and accumulated increments for $X$ and $Y$ directions [S1].

### Steps
1.  **Compute Destination Bounding Box:** Rotate the eight corners of the source voxel grid using the rotation matrix. Compute the axis-aligned bounding box of these eight rotated corners to determine the final dimensions of the destination grid [S2, unofficial].
2.  **Initialize Back-Rotation Origin:** Identify the minimum coordinates of the destination bounding box. Back-rotate these minimum coordinates to find the corresponding starting position in the source space by applying the inverse rotation (replacing $\theta$ with $-\theta$) [S1].
3.  **Compute Basis Increments (Optimization):** Instead of computing the inverse rotation for every voxel, compute the inverse transformation for only four voxels that define three orthogonal axes of the destination grid. These define the basis vectors $\mathbf{I}, \mathbf{J}, \mathbf{K}$ in the source space [S2, unofficial]. Additionally, only voxels in contact with the object are rotated for internal operations, while display uses OpenGL rotation capabilities [S2, unofficial].
4.  **Incremental Scan:** Iterate through the destination grid. For each voxel, calculate the corresponding source coordinate using the pre-computed basis vectors. This avoids heavy trigonometric computations per voxel [S1].

### Formulas
For a rotation about the Z-axis, the standard forward rotation is:
$$ X_{dest} = X_{src} \cos \theta - Y_{src} \sin \theta $$
$$ Y_{dest} = X_{src} \sin \theta + Y_{src} \cos \theta $$
The back-rotation (inverse) equations map a destination coordinate $(X_{dest}, Y_{dest})$ to the source $(X_{src}, Y_{src})$ [S1]. The incremental updates for adjacent destination voxels are derived from the inverse rotation derivatives [S1].
The source coordinates for the voxel at $(X_{dest}+1, Y_{dest})$ are:
$$ X_{src} = (X_{dest} + 1) \cos \theta + Y_{dest} \sin \theta $$
$$ Y_{src} = -(X_{dest} + 1) \sin \theta + Y_{dest} \cos \theta $$
The source coordinates for the voxel at $(X_{dest}, Y_{dest}+1)$ are:
$$ X_{src} = X_{dest} \cos \theta + (Y_{dest} + 1) \sin \theta $$
$$ Y_{src} = -X_{dest} \sin \theta + (Y_{dest} + 1) \cos \theta $$
Moving in the destination X-direction adds $\cos \theta$ to $X_{src}$ and $-\sin \theta$ to $Y_{src}$ [S1]. Moving in the destination Y-direction adds $\sin \theta$ to $X_{src}$ and $\cos \theta$ to $Y_{src}$ [S1]. Either set employs only two fixed-point additions that can be performed in parallel [S1].

### Pseudocode
```python
import math

def incremental_back_rotation(source_grid, dest_dims, theta, dest_min):
    # 1. Compute inverse rotation components for Z-axis rotation [S1]
    cos_theta = math.cos(theta)
    sin_theta = math.sin(theta)

    # 2. Compute basis vectors in source space (inverse rotation of destination axes) [S2, unofficial]
    # I vector (step in dest X): adds cos_theta to X_src, sin_theta to Y_src
    vec_i = (cos_theta, sin_theta, 0.0)
    # J vector (step in dest Y): adds sin_theta to X_src, cos_theta to Y_src
    vec_j = (sin_theta, cos_theta, 0.0)
    # K vector (step in dest Z): unchanged for Z-rotation
    vec_k = (0.0, 0.0, 1.0)

    dim_x, dim_y, dim_z = dest_dims

    # 3. Initialize source coordinate at back-rotated destination minimum [S1]
    # M_start = Inverse_Rotation(dest_min)
    M = (dest_min[0] * cos_theta + dest_min[1] * sin_theta,
         -dest_min[0] * sin_theta + dest_min[1] * cos_theta,
         dest_min[2])

    # Allocate destination grid
    dest_grid = [[[] for _ in range(dim_z)] for _ in range(dim_y)]

    for x_dest in range(dim_x):
        for y_dest in range(dim_y):
            for z_dest in range(dim_z):
                dest_grid[y_dest][z_dest].append(sample_grid(source_grid, M))
                # Increment along Z (K vector) [S2, unofficial]
                M = (M[0] + vec_k[0], M[1] + vec_k[1], M[2] + vec_k[2])

            # Roll back Z increments and add one Y step (J vector) [S2, unofficial]
            M = (M[0] - dim_z * vec_k[0] + vec_j[0],
                 M[1] - dim_z * vec_k[1] + vec_j[1],
                 M[2] - dim_z * vec_k[2] + vec_j[2])

        # Roll back Y increments and add one X step (I vector) [S2, unofficial]
        M = (M[0] - dim_y * vec_j[0] + vec_i[0],
             M[1] - dim_y * vec_j[1] + vec_i[1],
             M[2] - dim_y * vec_j[2] + vec_i[2])

    return dest_grid

def sample_grid(grid, point):
    # Nearest-neighbor sampling; trilinear interpolation reduces aliasing [S2, unofficial]
    x, y, z = point
    ix, iy, iz = int(round(x)), int(round(y)), int(round(z))
    ix = max(0, min(ix, grid.width - 1))
    iy = max(0, min(iy, grid.height - 1))
    iz = max(0, min(iz, grid.depth - 1))
    return grid[ix, iy, iz]
```

### Parameters and Typical Values
*   **Theta ($\theta$):** Rotation angle in radians [S1].
*   **Grid Sizes:** Benchmarked at $8^3$, $16^3$, $32^3$, and $64^3$ resolutions [S2, unofficial].

### Edge Cases and Pitfalls
*   **Holes:** Forward rotation causes holes because multiple source voxels project to the same destination voxel due to truncation. Back-rotation solves this by mapping destination voxels to source voxels [S1][S2, unofficial].
*   **Aliasing:** Direct inverse rotation produces significant aliasing. Antialiasing techniques such as trilinear interpolation are recommended [S2, unofficial].
*   **Performance:** Brute force inverse rotation has high computation time increasing with the number of voxels. The incremental method reduces this by using fixed-point additions [S1][S2, unofficial].
*   **Caching:** Storing already rotated voxels in a cache improves performance when the contact area between the tool and object changes incrementally [S2, unofficial].

## Subtopics

### Incremental Rotation Algorithm
This variant emphasizes the use of parallel memory and barrel shifters to move entire beams of voxels in a single operation, leveraging the fact that voxels along beams parallel to the rotation axis are identically rotated [S1]. It specifically addresses the Z-axis rotation where the incremental updates for $X$ and $Y$ are constant for all $Z$ [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Time Complexity:** The incremental method reduces the per-voxel cost from a full matrix multiplication to a few fixed-point additions. The complexity is linear with respect to the number of voxels in the destination grid, $O(N)$, where $N$ is the total voxel count [S1][S2, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the source and destination grids. Additional $O(1)$ for basis vectors and cache [S2, unofficial].

### Measured Performance
Performance data from [S2, unofficial] on a PC with AMD 3GHz, 1GB RAM, NVIDIA Geforce FX 5200:

| Grid Size | Brute Force (ms) | Optimised (ms) |
| :--- | :--- | :--- |
| 8x8x8 | 0.1826 | 0.0456 |
| 16x16x16 | 1.321 | 0.322 |
| 32x32x32 | 10.17 | 2.49 |
| 64x64x64 | 82.3 | 18.1 |

The optimised method reduces rotation time by approximately 75% compared to the brute force method for a $16^3$ tool [S2, unofficial]. Computation times depend on the rotation angle because the number of voxels needed to store the rotated tool changes with the angle [S2, unofficial]. Worst-case times assume all voxels are rotated; practical times are lower due to caching and sparse contact areas [S2, unofficial].

### Strengths and Limitations
*   **Strengths:** Eliminates holes in the rotated image; computationally efficient compared to brute force inverse rotation; suitable for real-time applications when optimized [S2, unofficial].
*   **Limitations:** Still subject to aliasing if interpolation is not used; performance degrades with larger grid sizes; requires pre-computation of bounding boxes and basis vectors [S2, unofficial].

## Background
The method originated in the context of voxel frame buffer processors and discrete tools for virtual sculpture [S1][S2, unofficial]. The "voxblt Engine" described in [S1] introduced the incremental back-rotation technique to handle room rotation in voxel graphics, addressing the hole problem inherent in forward rotation. Later, [S2, unofficial] refined this for discrete tools in virtual sculpture, proposing an optimized inverse method with basis vector interpolation and caching to achieve real-time performance.
