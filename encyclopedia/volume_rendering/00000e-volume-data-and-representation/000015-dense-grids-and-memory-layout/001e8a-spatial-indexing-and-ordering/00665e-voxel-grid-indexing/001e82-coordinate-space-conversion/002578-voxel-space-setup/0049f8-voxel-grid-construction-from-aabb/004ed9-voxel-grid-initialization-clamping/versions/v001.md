# Voxel Grid Initialization & Clamping

Also called: Voxel Grid Construction with Capacity Limits

## Overview
This method initializes the dimensional parameters of a uniform voxel grid while enforcing strict hardware vertex limits to prevent GPU buffer overflows. It differs from its parent [Voxel Grid Construction from AABB](12627-voxel-grid-construction-from-aabb.md) by adding a dynamic clamping step that adjusts voxel counts based on a maximum vertex budget, ensuring the resulting grid fits within memory constraints.

## How it works
**Inputs and Outputs:**
*   **Input:** Target voxel dimensions ($N_x, N_y, N_z$), maximum allowed vertex count ($V_{max}$), and physical voxel size ($s$).
*   **Output:** Clamped voxel dimensions ($N'_x, N'_y, N'_z$), vertex counts ($V'_x, V'_y, V'_z$), and total counts ($T_V, T_{Ver}$).

**Data Structures:**
The `Voxel` class maintains the following fields [S1, unofficial]:
*   `voxelPosition`: `Vector3` (world position of the grid origin).
*   `voxelGrid`: `Vector3Int` (physical bounds or grid orientation).
*   `boundaryCenter`: `Vector3` (center of the volume).
*   `boundaryWorldPos`: `Vector3` (world position of the boundary).
*   `numVoxel`: `Vector3Int` (clamped number of voxels per axis).
*   `numVertex`: `Vector3Int` (number of vertices per axis, derived from `numVoxel`).
*   `totalVoxel`: `long` (total number of voxels, $N'_x \times N'_y \times N'_z$).
*   `totalVertex`: `int` (total number of vertices, $V'_x \times V'_y \times V'_z$).
*   `voxelNodes`: `Node[8]` (array of 8 neighbor nodes).

**Parameters:**
*   $V_{max}$: Maximum allowed vertex count. Default value is 858,993,459 [S1, unofficial]. This limit prevents GPU buffer overflow.
*   $s$: Physical size of a single voxel unit [S1, unofficial].

**Steps:**
1.  **Store Previous Dimensions:** Save the initial target voxel dimensions $(N_x, N_y, N_z)$ as $(N^{old}_x, N^{old}_y, N^{old}_z)$ [S1, unofficial].
2.  **Clamp Voxel Dimensions:** Adjust each axis dimension to ensure the total vertex count does not exceed $V_{max}$. The number of vertices per axis is $N + 1$. The constraint is $(N'_x + 1)(N'_y + 1)(N'_z + 1) \le V_{max}$.
    The clamping formula for each axis $i$ uses the *other two* original dimensions to calculate the maximum allowable value for axis $i$ [S1, unofficial]:
    $$ N'_x = \text{Clamp}(N_x, 1, \lfloor \frac{V_{max}}{N^{old}_y \cdot N^{old}_z} \rfloor - 2) $$
    $$ N'_y = \text{Clamp}(N_y, 1, \lfloor \frac{V_{max}}{N^{old}_x \cdot N^{old}_z} \rfloor - 2) $$
    $$ N'_z = \text{Clamp}(N_z, 1, \lfloor \frac{V_{max}}{N^{old}_x \cdot N^{old}_y} \rfloor - 2) $$
    Note: The subtraction of 2 accounts for the $+1$ vertex per axis in the product expansion approximation or specific buffer layout requirements [S1, unofficial].
3.  **Clamp Coordinates:** Ensure voxel grid coordinates are within valid ranges [S1, unofficial].
4.  **Calculate Vertex Counts:** Compute the number of vertices per axis:
    $$ V'_i = N'_i + 1 $$
    Clamp $V'_i$ to the range $[2, 65535]$ to ensure valid grid topology and fit within 16-bit index buffers if used [S1, unofficial].
5.  **Compute Totals:**
    $$ T_V = N'_x \times N'_y \times N'_z $$
    $$ T_{Ver} = V'_x \times V'_y \times V'_z $$
6.  **Final Verification and Adjustment:** If $T_{Ver} > V_{max}$, log an error and adjust the Y-dimension ($N'_y$) downwards until the constraint is satisfied [S1, unofficial].

**Pseudocode:**
```python
def initialize_voxel_grid(num_voxel: Vector3Int, max_vertex: int = 858993459) -> Voxel:
    # Step 1: Store previous dimensions
    old_num_voxel = num_voxel
    
    # Step 2: Clamp voxel dimensions based on vertex limit
    # Formula: N'_i = Clamp(N_i, 1, floor(max_vertex / (N_old_j * N_old_k)) - 2)
    # Using integer division for floor
    
    max_x = max_vertex // (old_num_voxel.y * old_num_voxel.z) - 2
    num_voxel.x = clamp(num_voxel.x, 1, max_x)
    
    max_y = max_vertex // (old_num_voxel.x * old_num_voxel.z) - 2
    num_voxel.y = clamp(num_voxel.y, 1, max_y)
    
    max_z = max_vertex // (old_num_voxel.y * old_num_voxel.x) - 2
    num_voxel.z = clamp(num_voxel.z, 1, max_z)
    
    # Step 3: Clamp voxel grid coordinates to valid ranges
    # [G] Implementation detail: Ensure coordinates are within the defined AABB bounds.
    
    # Step 4: Calculate numVertex as numVoxel + 1, clamped between 2 and 65535
    num_vertex = Vector3Int(
        clamp(num_voxel.x + 1, 2, 65535),
        clamp(num_voxel.y + 1, 2, 65535),
        clamp(num_voxel.z + 1, 2, 65535)
    )
    
    # Step 5: Compute totalVoxel and totalVertex
    total_voxel = num_voxel.x * num_voxel.y * num_voxel.z
    total_vertex = num_vertex.x * num_vertex.y * num_vertex.z
    
    # Step 6: If totalVertex exceeds maxVertex, log an error and adjust the Y-dimension
    if total_vertex > max_vertex:
        print("Error: Total vertices exceed maxVertex. Adjusting Y-dimension.")
        # [G] Iteratively reduce Y until constraint is met
        while total_vertex > max_vertex and num_vertex.y > 2:
            num_vertex.y -= 1
            num_voxel.y = num_vertex.y - 1
            total_vertex = num_vertex.x * num_vertex.y * num_vertex.z
            
    return Voxel(
        numVoxel=num_voxel,
        numVertex=num_vertex,
        totalVoxel=total_voxel,
        totalVertex=total_vertex
    )
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If any of the original dimensions ($N^{old}_y, N^{old}_z$, etc.) are zero, the clamping calculation will fail. The parent method [Voxel Grid Construction from AABB](12627-voxel-grid-construction-from-aabb.md) should ensure non-zero extents before this step.
*   **Negative Limits:** If $V_{max}$ is too small relative to the other dimensions, the calculated maximum for an axis may be less than 1. The `Clamp` function handles this by setting the dimension to 1.
*   **16-bit Index Overflow:** The clamp to 65535 ensures that vertex indices fit in a 16-bit unsigned integer, which is common in graphics APIs.

## Operating characteristics
*   **Time Complexity:** $O(1)$ arithmetic operations. The clamping and calculation steps are constant time relative to the grid size.
*   **Memory Complexity:** $O(1)$ additional memory for temporary variables. The method modifies the `Voxel` structure in place or returns a new instance with minimal overhead.
*   **Strengths:** Prevents GPU crashes due to buffer overflow; ensures compatibility with 16-bit indexing.
*   **Limitations:** May significantly reduce resolution if the target grid is too large for the hardware limit; the Y-axis adjustment in Step 6 is a heuristic fallback that may not be optimal for all aspect ratios.
*   **When to Use:** When generating voxel grids for GPU-based rendering or simulation where memory limits are strict.
*   **When Not to Use:** When exact resolution is critical and the hardware limit cannot be relaxed.

## Background
This method originates from the `lineBasedCave_Simplex` project, specifically within the `DensityGenerator.cs` script [S1, unofficial]. It was developed to handle the initialization of voxel grids for density generation and marching cubes algorithms in Unity, ensuring that the generated meshes do not exceed GPU buffer capacities.
