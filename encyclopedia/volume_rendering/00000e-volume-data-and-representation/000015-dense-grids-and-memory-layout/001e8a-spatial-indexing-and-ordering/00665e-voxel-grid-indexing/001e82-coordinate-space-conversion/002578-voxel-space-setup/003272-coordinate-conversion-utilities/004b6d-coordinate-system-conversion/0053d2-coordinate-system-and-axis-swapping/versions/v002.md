# Coordinate System and Axis Swapping

Also called: Axis Swapping, OFF File Coordinate Conversion

## Overview
This method converts input mesh data from a right-handed Cartesian coordinate system (where $x$ is right, $y$ is up, and $z$ is forward) into a voxel grid layout where the first dimension corresponds to height ($y$), the second to width ($x$), and the third to depth ($z$) [S1, unofficial]. It solves the misalignment between standard geometric modeling conventions and the memory layout requirements of specific voxelization engines [S1, unofficial]. It differs from general coordinate system conversion by performing a specific axis swap ($x \leftrightarrow y$) during the voxelization process rather than a post-hoc metadata adjustment [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A triangular mesh file in OFF format (or a directory of consecutively numbered OFF files) where meshes must be watertight and scaled to fit the target volume dimensions [S1, unofficial].
*   **Output:** A voxel grid stored in an HDF5 file [S1, unofficial].

**Data Structures:**
The output is a 3D array with dimensions $(H, W, D)$ corresponding to $(y, x, z)$ respectively [S1, unofficial]. Optional color channels are stored if the `--color` flag is enabled [S1, unofficial].

**Parameters:**
*   `--height` ($H$): Default 32. Corresponds to the Y-axis (up) [S1, unofficial].
*   `--width` ($W$): Default 32. Corresponds to the X-axis (right) [S1, unofficial].
*   `--depth` ($D$): Default 32. Corresponds to the Z-axis (forward) [S1, unofficial].
*   `--mode`: 'occ' (occupancy) or 'sdf' (signed distance field). Default 'occ' [S1, unofficial].
*   `--center`: Boolean flag. Default False. If set, SDF computation uses voxel centers; otherwise, it uses the top-left-front corner [S1, unofficial].
*   `--color`: Boolean flag. Default False. If set, color information is kept after voxelization [S1, unofficial].

**Steps:**
1.  **Load Mesh:** Read the triangular mesh from the OFF file. The mesh must be watertight and scaled to fit the target volume dimensions [S1, unofficial].
2.  **Axis Swap Mapping:** Define the mapping from input mesh coordinates $(x_{in}, y_{in}, z_{in})$ to voxel grid indices $(i, j, k)$: $i = y_{in}$, $j = x_{in}$, $k = z_{in}$. This effectively swaps the $x$ and $y$ axes during voxelization so the first dimension corresponds to height [S1, unofficial].
3.  **Voxelization:** If `--mode` is 'occ', mark voxels intersected by the mesh triangles as occupied. If 'sdf', compute the signed distance to the mesh for each voxel corner (default) or center (if `--center` is set) [S1, unofficial].
4.  **Color Assignment:** If `--color` is set, use face IDs to map to color files and assign colors to the 12 triangular faces of each voxel [S1, unofficial].
5.  **Store:** Write the resulting grid to an HDF5 file [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Non-watertight meshes:** The tool requires watertight meshes. Use simplification algorithms (e.g., semi-convex hull) if necessary [S1, unofficial].
*   **Scaling:** Meshes must be scaled to fit the volume; incorrect scaling leads to empty or clipped volumes [S1, unofficial].
*   **SDF Reference:** The choice between voxel centers and corners affects SDF computation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Depends heavily on resolution ($H, W, D$) and mesh complexity [S1, unofficial].
*   **Strengths:** Simple axis swap handles common OFF file coordinate mismatches. Supports both occupancy and SDF [S1, unofficial].
*   **Limitations:** Requires watertight meshes. Axis swap is fixed ($x \leftrightarrow y$) and not configurable for other systems [S1, unofficial].

## Background
This method originates from the `mesh-voxelization` tool, designed to convert OFF format triangular meshes into voxel grids for machine learning and graphics applications [S1, unofficial]. It addresses the specific convention where OFF files use $x$=right, $y$=up, $z$=forward, while the target voxel grid prioritizes height as the first dimension [S1, unofficial].
