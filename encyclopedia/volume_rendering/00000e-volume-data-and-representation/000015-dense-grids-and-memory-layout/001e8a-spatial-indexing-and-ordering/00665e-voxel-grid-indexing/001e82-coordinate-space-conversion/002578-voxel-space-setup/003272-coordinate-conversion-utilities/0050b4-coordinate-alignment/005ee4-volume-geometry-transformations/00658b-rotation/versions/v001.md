# Rotation
Also called: Rotate
## Overview
Rotation modifies the spatial orientation of a 3D volume geometry by applying angular transformations to voxel coordinates. It solves the problem of reorienting volumetric data for alignment, animation, or geometric manipulation while preserving the underlying voxel grid topology. Unlike translation or scaling, rotation requires coordinate remapping and interpolation to determine new voxel values, distinguishing it from simple positional shifts [S2, unofficial]. It is a core component of Volume Geometry Transformations [17760-volume-geometry-transformations.md].

## How it works
**Inputs and Outputs:**
- Input: A voxel grid (dense or sparse), rotation parameters (axis, angle/turns, optional center).
- Output: A transformed voxel grid with updated coordinates and interpolated values.

**Data Structures:**
The voxel grid is typically represented as a 3D array or hash map where each entry contains:
- `x, y, z`: Integer or floating-point coordinates.
- `value`: Scalar or vector data (density, color, etc.).
- `active`: Boolean flag indicating if the voxel is occupied (for sparse grids).

**Steps:**
1. **Define Rotation Parameters:** Specify the axis of rotation (x, y, or z), the magnitude (angle $\theta$ in radians or integer `turns` for 90-degree increments), and an optional center of rotation $C = (c_x, c_y, c_z)$ [S1, S2, unofficial].
2. **Translate to Origin:** If a center $C$ is specified, translate all voxel coordinates $(x, y, z)$ by $-C$ to move the rotation center to the origin [S2, unofficial].
   $$ x_{temp} = x - c_x $$
   $$ y_{temp} = y - c_y $$
   $$ z_{temp} = z - c_z $$
3. **Apply Rotation Matrix:** Apply the rotation matrix $R$ corresponding to the axis and angle to the translated coordinates [S2, unofficial].
   - For rotation around the z-axis by angle $\theta$:
     $$ x' = x_{temp} \cos \theta - y_{temp} \sin \theta $$
     $$ y' = x_{temp} \sin \theta + y_{temp} \cos \theta $$
     $$ z' = z_{temp} $$
   - For 90-degree increments (integer `turns`), use discrete permutations:
     - `turns = 1` (90°): $(x, y, z) \to (-y, x, z)$
     - `turns = 2` (180°): $(x, y, z) \to (-x, -y, z)$
     - `turns = 3` (270°): $(x, y, z) \to (y, -x, z)$
     [S1, unofficial]
4. **Translate Back:** If a center $C$ was used, translate the rotated coordinates back by $+C$ [S2, unofficial].
   $$ x_{final} = x' + c_x $$
   $$ y_{final} = y' + c_y $$
   $$ z_{final} = z' + c_z $$
5. **Interpolation and Resampling:** Since rotated coordinates are often non-integer, interpolate the voxel values from the original grid to the new positions. Common methods include nearest-neighbor, trilinear, or higher-order interpolation [S2, unofficial].
6. **Update Grid:** Place the interpolated values into the new grid structure. For sparse grids, update the hash map keys.

**Pseudocode:**
```python
import math

def rotate_voxel_grid(grid, axis='z', turns=1, center=None):
    """
    Rotate a voxel grid.
    grid: dict or 3D array of voxel values.
    axis: 'x', 'y', or 'z'.
    turns: integer number of 90-degree rotations.
    center: tuple (cx, cy, cz) or None for origin.
    """
    new_grid = {}
    
    # Determine rotation matrix or permutation based on axis and turns
    # For simplicity, handling 90-degree increments as per [S1, unofficial]
    # General angle rotation would require trigonometric interpolation [S2, unofficial]
    
    for coords, value in grid.items():
        x, y, z = coords
        
        # Step 2: Translate to center
        if center:
            cx, cy, cz = center
            x -= cx
            y -= cy
            z -= cz
        
        # Step 3: Apply rotation
        # Normalize turns to 0-3
        t = turns % 4
        
        if axis == 'z':
            if t == 0:
                nx, ny, nz = x, y, z
            elif t == 1:
                nx, ny, nz = -y, x, z
            elif t == 2:
                nx, ny, nz = -x, -y, z
            elif t == 3:
                nx, ny, nz = y, -x, z
        elif axis == 'x':
            if t == 0:
                nx, ny, nz = x, y, z
            elif t == 1:
                nx, ny, nz = x, -z, y
            elif t == 2:
                nx, ny, nz = x, -y, -z
            elif t == 3:
                nx, ny, nz = x, z, -y
        elif axis == 'y':
            if t == 0:
                nx, ny, nz = x, y, z
            elif t == 1:
                nx, ny, nz = z, y, -x
            elif t == 2:
                nx, ny, nz = -x, y, -z
            elif t == 3:
                nx, ny, nz = -z, y, x
        else:
            raise ValueError("Axis must be 'x', 'y', or 'z'")
        
        # Step 4: Translate back
        if center:
            nx += cx
            ny += cy
            nz += cz
        
        # Step 5: Interpolation is required for non-integer results
        # For 90-degree increments on integer grids, coordinates remain integer
        # For arbitrary angles, use trilinear interpolation from original grid
        # Here we assume integer coordinates for 90-degree increments [S1, unofficial]
        new_grid[(nx, ny, nz)] = value
        
    return new_grid
```

**Parameters:**
- `axis`: String, one of 'x', 'y', 'z'.
- `turns`: Integer, number of 90-degree rotations.
- `center`: Optional tuple of floats, default is origin (0,0,0).

**Edge Cases:**
- Non-integer coordinates: If arbitrary angles are used, interpolation is mandatory [S2, unofficial].
- Boundary conditions: Rotated voxels may fall outside the original grid bounds; clipping or padding may be required.
- Precision: Floating-point errors in arbitrary angle rotations can cause misalignment.

## Subtopics

### Geometric Transformations
Rotation is a subset of geometric transformations, which also include translation and scaling. These operations involve remapping voxel coordinates and require interpolation to determine new values [S2, unofficial]. Unlike rotation, translation and scaling do not change the orientation of the voxel grid but alter position or size. Choose rotation when reorienting the volume is necessary, such as aligning data with a coordinate system or preparing for animation.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of active voxels, assuming constant-time coordinate transformation. Interpolation adds overhead proportional to the number of neighbors sampled.
- **Memory Complexity:** $O(N)$ for storing the transformed grid.
- **Performance:** Fast for 90-degree increments on integer grids as no interpolation is needed [S1, unofficial]. Slower for arbitrary angles due to interpolation [S2, unofficial].
- **Strengths:** Simple implementation for discrete rotations; preserves topology.
- **Limitations:** Interpolation artifacts (blurring) for arbitrary angles; potential loss of detail if not handled carefully.
- **When to use:** Aligning volumes, creating animations, or preparing data for rendering.
- **When not to use:** When preserving exact voxel values without interpolation is critical (use nearest-neighbor or avoid rotation).

## Background
Rotation in voxel grids originates from basic 3D computer graphics and geometric modeling. The concept of rotating coordinates using rotation matrices is fundamental in linear algebra and has been adapted for voxel-based representations in applications like medical imaging, computational fluid dynamics, and 3D modeling [S2, unofficial]. The specific implementation of 90-degree increments is common in discrete grid-based systems for efficiency [S1, unofficial].
