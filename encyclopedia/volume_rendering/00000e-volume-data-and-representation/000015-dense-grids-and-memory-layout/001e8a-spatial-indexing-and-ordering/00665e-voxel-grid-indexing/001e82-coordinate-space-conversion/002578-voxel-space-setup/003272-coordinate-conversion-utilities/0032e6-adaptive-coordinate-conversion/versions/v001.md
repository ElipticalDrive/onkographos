# Adaptive Coordinate Conversion

Also called: On-the-fly pyramidal-to-Cartesian conversion, USPG to Cartesian Grid Mapping

## Overview
Adaptive Coordinate Conversion is a technique for visualizing 3D ultrasound datasets by dynamically transforming points from their native pyramidal (or polar) coordinate system into a Cartesian grid during rendering [S1]. Unlike methods that rely on pre-interpolation or iterative mapping where one polar pixel maps to many Cartesian pixels, this approach leverages a direct one-to-one correspondence between grid rings to perform bilinear mapping [S2]. It is primarily used in GPU-accelerated raycasting to enable real-time visualization of volumetric data acquired in non-Cartesian geometries [S1, S2].

## How it works
The method addresses the mismatch between the acquisition geometry of ultrasound probes (typically pyramidal or polar) and the standard Cartesian grid required for efficient texture sampling and raycasting.

### Inputs and Outputs
- **Input**: 3D ultrasound dataset defined in a native pyramidal/polar grid (USPG).
- **Output**: Rendered image on a Cartesian grid (CG).

### Data Structures
The method relies on the structural equivalence between the USPG and the target Cartesian Grid (CG).
- **USPG Structure**: Composed of concentric rings $R_n$.
- **Ring Indexing**: Each ring $R_n$ has a head ($H_n$) and a tail meeting on the positive X-axis. Numbering starts at the head and proceeds anti-clockwise [S2].
- **Grid Count**: Ring $R_n$ contains $n_g = 4(2^n - 1)$ grids [S2].
- **Head Recurrence**: The head element index $H_n$ is determined by:
  $$ H_{n+1} = H_n + 4(2^n - 1) $$
  where $H_1 = 0$ and $n = 1, 2, \dots, N/2$ [S2].

### Steps
1. **Identify Ring Correspondence**: Determine the ring index $n$ for the current sample point in the USPG. The total number of grids in ring $R_n$ of the USPG is identical to the number of grids in the corresponding square ring of the Cartesian Grid [S2].
2. **Calculate Local Offset**: Determine the position of the sample point within ring $R_n$ relative to the head $H_n$.
3. **Map to Cartesian**: Use the one-to-one correspondence to map the USPG grid index directly to the Cartesian grid index. Since the grid counts are identical, no interpolation between multiple Cartesian pixels is required for the ring structure itself [S2].
4. **Bilinear Interpolation**: Apply bilinear interpolation within the mapped Cartesian cell to retrieve the final color and opacity values for raycasting [S2].

### Edge Cases and Pitfalls
- **Boundary Conditions**: The head and tail of the ring meet on the positive X-axis. Care must be taken to ensure continuity across this boundary [S2].
- **Precision**: The recurrence relation for $H_n$ grows exponentially. For large $N$, ensure integer overflow is handled if using fixed-size integers [S2].
- **Degenerate Input**: The method assumes a valid USPG structure where rings are well-defined. Invalid ring indices will cause incorrect mapping [S2].

## Subtopics

### USPG to Cartesian Grid Mapping
A specific implementation of adaptive coordinate conversion for 2D/3D image reconstruction using algebraic algorithms. It differs from other variants by explicitly leveraging the one-to-one correspondence between USPG rings and Cartesian square rings, which have the same number of grids. This allows for a direct bilinear mapping without the need for interpolation or iterative techniques where one polar pixel maps to many Cartesian pixels [S2]. It is chosen when the acquisition geometry is strictly polar/pyramidal and the target display is Cartesian, and when computational efficiency is prioritized over pre-processing interpolation [S2].

## Operating characteristics
- **Time Complexity**: $O(1)$ per sample point for the mapping calculation, assuming precomputed ring heads or efficient bit-shift operations for $2^n$. The overall complexity is dominated by the raycasting traversal.
- **Memory Complexity**: Requires storage for the Cartesian grid, which has the same number of elements as the USPG grid, so memory usage is comparable to the native dataset size [S2].
- **Performance**: Enables real-time visualization on GPU by avoiding expensive pre-interpolation steps [S1]. The direct mapping reduces computational overhead compared to iterative methods [S2].
- **Strengths**: Simple, straightforward, and efficient. Eliminates artifacts associated with interpolation or iterative mapping [S2].
- **Limitations**: Limited to cases where the USPG and CG grid structures have a one-to-one correspondence. Not applicable if the grid densities differ significantly [S2].

## Background
The technique was introduced by Lim et al. in the context of GPU-based raycasting for visualizing 3D ultrasound datasets [S1]. It was developed to address the challenge of rendering data acquired in a native pyramidal coordinate system, which is common in ultrasound imaging, onto a standard Cartesian grid for display [S1]. The specific USPG to Cartesian mapping variant was further detailed in work on uniformly sampled polar and cylindrical grids for algebraic reconstruction [S2].
