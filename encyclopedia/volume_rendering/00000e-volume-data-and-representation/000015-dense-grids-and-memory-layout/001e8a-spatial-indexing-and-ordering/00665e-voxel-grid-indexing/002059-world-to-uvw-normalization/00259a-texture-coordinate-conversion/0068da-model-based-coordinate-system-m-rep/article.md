# Model-based Coordinate System (M-rep)
Also called: X2U map, medial representation coordinates

## Overview
The Model-based Coordinate System (M-rep) provides a parameterization $(u, v, \tau)$ for volumetric data that establishes semantic correspondence between different instances of an anatomical model, such as structures from different patients [S1, unofficial]. Unlike standard geometric parameterizations, it defines coordinates based on a medial sheet (skeletal surface midway between opposing boundaries) and spokes extending to the boundary, enabling guided solid texture synthesis and consistent orientation fields [S1, unofficial]. It is distinct from sibling methods like [Voxel Texture Atlas UV Mapping](4162-voxel-texture-atlas-uv-mapping.md) by encoding intrinsic anatomical topology rather than just surface projection.

## How it works
**Inputs:**
1. A segmented 3D surface model of an anatomical object.
2. A medial representation (M-rep) of the object, consisting of a continuous medial sheet $M$ parameterized by $(u, v)$ and a set of spokes extending from the sheet to the object boundary [S1, unofficial].

**Outputs:**
1. An X2U map: a lookup table storing object coordinates $(u, v, \tau)$ for every world-space $(x, y, z)$ triplet inside the model [S1, unofficial].
2. Orientation fields: gradients $d_u = \nabla u$, $d_v = \nabla v$, $d_\tau = \nabla \tau$ [S1, unofficial].
3. Region classification masks based on $\tau$ thresholds [S1, unofficial].

**Data Structures:**
*   **X2U Map:** A 3D grid (lookup table) aligned with the world-space voxel grid. Each voxel $(x, y, z)$ contains a tuple $(u, v, \tau)$.
    *   $u$: Along-object coordinate (index along the medial sheet).
    *   $v$: Around-object coordinate (index across the medial sheet).
    *   $\tau$: Through-object coordinate, defined as the fraction of the spoke distance from the medial sheet to the boundary. $\tau=0$ at the medial sheet, $\tau=1$ at the boundary [S1, unofficial].

**Algorithm: X2U Map Computation**
The X2U map is precomputed using a fast coordinate scan-conversion algorithm [S1, unofficial].

1.  **Onion Skin Generation:** Generate a large number of "onion skins" (thin volumetric slices or shells) from the medial representation. Each onion skin is color-coded with its corresponding $(u, v, \tau)$ coordinates.
2.  **Rasterization and Clipping:** Rasterize these onion skins. Clip the rasterized data to individual planes defined by the model's geometry.
3.  **Volume Combination:** Combine these clipped planes into a single volume.
4.  **Lookup Table Population:** For every voxel $(x, y, z)$ inside the model, store the interpolated $(u, v, \tau)$ values obtained from the combined volume. Voxels outside the model are marked as invalid [S1, unofficial].

**Orientation Field Computation:**
Once the X2U map is established, the orientation fields are computed as the spatial gradients of the coordinates:
$$ d_u = \nabla u, \quad d_v = \nabla v, \quad d_\tau = \nabla \tau $$
These vectors define the local orientation at each voxel. Note that $d_u, d_v, d_\tau$ are not necessarily orthogonal in the world $(x, y, z)$ space [S1, unofficial].

**Region Classification:**
Threshold values for $\tau$ are used to classify material regions within the model. Typical values for bone structures are:
*   $0 < \tau < 0.5$: Marrow region
*   $0.5 < \tau < 0.7$: Interior bone region
*   $0.7 < \tau < 1$: Exterior bone region [S1, unofficial]

These regions are used to compute a smooth transition field $st$ for texture synthesis [S1, unofficial].

```python
def compute_x2u_map(model_surface, medial_sheet, spokes):
    """
    Computes the X2U map using scan-conversion.
    model_surface: 3D mesh defining the object boundary.
    medial_sheet: Parameterized surface M(u,v).
    spokes: List of spokes, each defined by a point on M(u,v) and a direction/length to the boundary.
    """
    # Initialize output volume with invalid values
    volume_size = get_world_bounds(model_surface)
    x2u_map = create_3d_array(volume_size, dtype=float32, fill_value=INVALID)

    # Step 1 & 2: Rasterize onion skins and clip to planes
    # Onion skins are generated by sampling the medial sheet and expanding along spokes
    onion_skins = generate_onion_skins(medial_sheet, spokes, resolution=HIGH)
    
    for skin in onion_skins:
        # skin contains (u, v, tau) values and geometric position
        # Rasterize skin into a temporary plane buffer
        plane_buffer = rasterize(skin, model_surface)
        
        # Clip plane_buffer to the model's interior planes
        clipped_plane = clip_to_planes(plane_buffer, model_surface)
        
        # Step 3 & 4: Combine into volume
        # Update the x2u_map with values from the clipped plane
        # Interpolation may be needed if planes are sparse
        update_volume(x2u_map, clipped_plane)

    return x2u_map

def compute_orientation_fields(x2u_map):
    """
    Computes gradient fields du, dv, d_tau from the X2U map.
    """
    du = gradient(x2u_map[:, :, :, 0])
    dv = gradient(x2u_map[:, :, :, 1])
    d_tau = gradient(x2u_map[:, :, :, 2])
    return du, dv, d_tau

def classify_regions(x2u_map):
    """
    Classifies voxels based on tau thresholds.
    """
    tau = x2u_map[:, :, :, 2]
    marrow_mask = (tau > 0) & (tau < 0.5)
    interior_mask = (tau >= 0.5) & (tau < 0.7)
    exterior_mask = (tau >= 0.7) & (tau < 1.0)
    return marrow_mask, interior_mask, exterior_mask
```

## Operating characteristics
*   **Precomputation Cost:** High. Requires generating and rasterizing a large number of onion skins and clipping them to planes. The complexity depends on the resolution of the medial representation and the number of onion skins [S1, unofficial].
*   **Memory Usage:** High. The X2U map stores three floating-point values per voxel inside the model. For high-resolution volumes, this lookup table can be significant [S1, unofficial].
*   **Runtime Performance:** Fast sampling. Once the X2U map is computed, texture synthesis and region classification are $O(1)$ lookups per voxel [S1, unofficial].
*   **Strengths:** Provides semantic correspondence between different anatomical instances (patients), enabling consistent texture synthesis and orientation fields. Automatically computes 3D model-based orientation information [S1, unofficial].
*   **Limitations:** Requires a valid medial representation (M-rep) as input, which can be difficult to compute for complex or noisy anatomical structures. The non-orthogonality of the gradient fields in world space can complicate certain texture synthesis algorithms [S1, unofficial].
*   **When to use:** When synthesizing solid textures for anatomical volumes where consistency across different patient models is required.
*   **When not to use:** For generic procedural textures or when medial representations are unavailable or unreliable.

## Background
The Model-based Coordinate System was introduced by Kabul, Merck, Rosenman, and Pizer in their work on "Model-based Solid Texture Synthesis for Anatomic Volume Illustration" [S1, unofficial]. It builds upon the concept of Medial Representations (M-reps), specifically "single figure slabular" M-reps, which represent 3D objects by a single continuous medial sheet and a set of spokes [S1, unofficial]. The method was developed to address the problem of guided solid texture synthesis for anatomic structures, ensuring that corresponding points in different instances of anatomic objects have the same $(u, v, \tau)$ values [S1, unofficial]. The X2U map computation method references details found in [Mer09] [S1, unofficial].
