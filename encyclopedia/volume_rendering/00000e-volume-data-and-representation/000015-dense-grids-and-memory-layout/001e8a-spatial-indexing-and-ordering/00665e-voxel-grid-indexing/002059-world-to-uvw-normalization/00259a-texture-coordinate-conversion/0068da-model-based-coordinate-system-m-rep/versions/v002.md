# Model-based Coordinate System (M-rep)
Also called: X2U map, medial representation coordinates

## Overview
The Model-based Coordinate System (M-rep) provides a parameterization $(u, v, \tau)$ for volumetric data that establishes semantic correspondence between different instances of an anatomical model [S1, unofficial]. It defines coordinates based on a medial sheet (skeletal surface midway between opposing boundaries) and spokes extending to the boundary, enabling guided solid texture synthesis and consistent orientation fields [S1, unofficial].

## How it works
**Inputs:**
1. A segmented 3D surface model of an anatomical object [S1, unofficial].
2. A medial representation (M-rep) of the object, consisting of a continuous medial sheet $M$ parameterized by $(u, v)$ and a set of spokes extending from the sheet to the object boundary [S1, unofficial].

**Outputs:**
1. An X2U map: a lookup table storing object coordinates $(u, v, \tau)$ for every world-space $(x, y, z)$ triplet inside the model [S1, unofficial].
2. Orientation fields: gradients $d_u = \nabla u$, $d_v = \nabla v$, $d_\tau = \nabla \tau$ [S1, unofficial].
3. Region classification masks based on $\tau$ thresholds [S1, unofficial].

**Data Structures:**
*   **X2U Map:** A 3D grid (lookup table) aligned with the world-space voxel grid [S1, unofficial]. Each voxel $(x, y, z)$ contains a tuple $(u, v, \tau)$ [S1, unofficial].
    *   $u$: Along-object coordinate (index along the medial sheet) [S1, unofficial].
    *   $v$: Around-object coordinate (index across the medial sheet) [S1, unofficial].
    *   $\tau$: Through-object coordinate, defined as the fraction of the spoke distance from the medial sheet to the boundary, where $\tau=0$ at the medial sheet and $\tau=1$ at the boundary [S1, unofficial].

**Algorithm: X2U Map Computation**
The X2U map is precomputed using a fast coordinate scan-conversion algorithm [S1, unofficial].
1. Generate a large number of onion skins (thin volumetric shells) from the medial representation, color-coded with $(u, v, \tau)$ coordinates [S1, unofficial].
2. Rasterize each onion skin and clip the rasterized data to individual planes defined by the model's geometry [S1, unofficial].
3. Combine the clipped planes into a single volume [S1, unofficial].
4. Store the resulting $(u, v, \tau)$ values at every voxel inside the model as a lookup table [S1, unofficial].

**Orientation Field Computation:**
Once the X2U map is established, the orientation fields are computed as the spatial gradients of the coordinates:
$$ d_u = \nabla u, \quad d_v = \nabla v, \quad d_\tau = \nabla \tau $$
These vectors define the local orientation at each voxel [S1, unofficial]. Note that $d_u, d_v, d_\tau$ are not necessarily orthogonal in the world $(x, y, z)$ space [S1, unofficial].

**Region Classification:**
Threshold values for $\tau$ classify material regions within the model [S1, unofficial]. Typical values for bone structures are:
*   $0 < \tau < 0.5$: Marrow region
*   $0.5 < \tau < 0.7$: Interior bone region
*   $0.7 < \tau < 1$: Exterior bone region [S1, unofficial]
These regions are used to compute a smooth transition field $st$ for texture synthesis [S1, unofficial].

**Pseudocode:**
```python
def compute_x2u_map(model_bounds, medial_sheet, spokes, voxel_size):
    # Initialize volume with invalid marker
    volume = [[[None for _ in range(model_bounds[2])] for _ in range(model_bounds[1])] for _ in range(model_bounds[0])]
    
    # Generate onion skins from medial sheet and spokes [G]
    onion_skins = []
    for u in range(medial_sheet.u_resolution):
        for v in range(medial_sheet.v_resolution):
            skin = generate_skin_from_spokes(medial_sheet, spokes, u, v)
            onion_skins.append(skin)
    
    for skin in onion_skins:
        # Rasterize skin to a 2D plane buffer
        plane_buffer = rasterize_skin_to_plane(skin, voxel_size)
        # Clip plane to model interior planes
        clipped_plane = clip_plane_to_model(plane_buffer, model_bounds)
        # Combine into volume
        update_volume_from_plane(volume, clipped_plane)
    
    return volume

def generate_skin_from_spokes(sheet, spokes, u, v):
    # Extract spoke geometry for parameter (u, v) [G]
    return {"u": u, "v": v, "points": spokes[u][v]}

def rasterize_skin_to_plane(skin, voxel_size):
    # Map skin points to 2D grid coordinates [G]
    return [[(skin["u"], skin["v"], 0.5) for _ in range(10)] for _ in range(10)]

def clip_plane_to_model(plane, bounds):
    # Filter points inside model bounds [G]
    return [p for p in plane if all(0 <= p[i] < bounds[i] for i in range(3))]

def update_volume_from_plane(volume, plane):
    # Write clipped points to volume array [G]
    for p in plane:
        x, y, z = int(p[0]), int(p[1]), int(p[2])
        if 0 <= x < len(volume) and 0 <= y < len(volume[0]) and 0 <= z < len(volume[0][0]):
            volume[x][y][z] = (p[0], p[1], p[2])

def compute_orientation_fields(x2u_map):
    # Compute gradients using finite differences [G]
    du = compute_gradient(x2u_map, axis=0)
    dv = compute_gradient(x2u_map, axis=1)
    d_tau = compute_gradient(x2u_map, axis=2)
    return du, dv, d_tau

def classify_regions(x2u_map):
    tau = extract_channel(x2u_map, axis=2)
    marrow = (tau > 0) & (tau < 0.5)
    interior = (tau >= 0.5) & (tau < 0.7)
    exterior = (tau >= 0.7) & (tau < 1.0)
    return marrow, interior, exterior
```

## Operating characteristics
*   **Precomputation Cost:** High. Requires generating and rasterizing a large number of onion skins and clipping them to planes [S1, unofficial].
*   **Memory Usage:** High. The X2U map stores three floating-point values per voxel inside the model [S1, unofficial].
*   **Runtime Performance:** Fast sampling. Once the X2U map is computed, texture synthesis and region classification are $O(1)$ lookups per voxel [S1, unofficial].
*   **Strengths:** Provides semantic correspondence between different anatomical instances (patients), enabling consistent texture synthesis and orientation fields [S1, unofficial]. Automatically computes 3D model-based orientation information [S1, unofficial].
*   **Limitations:** Requires a valid medial representation (M-rep) as input, which can be difficult to compute for complex or noisy anatomical structures [S1, unofficial]. The non-orthogonality of the gradient fields in world space can complicate certain texture synthesis algorithms [S1, unofficial].
*   **When to use:** When synthesizing solid textures for anatomical volumes where consistency across different patient models is required [S1, unofficial].
*   **When not to use:** For generic procedural textures or when medial representations are unavailable or unreliable [S1, unofficial].

## Background
The Model-based Coordinate System was introduced by Kabul, Merck, Rosenman, and Pizer in their work on "Model-based Solid Texture Synthesis for Anatomic Volume Illustration" [S1, unofficial]. It builds upon the concept of Medial Representations (M-reps), specifically "single figure slabular" M-reps, which represent 3D objects by a single continuous medial sheet and a set of spokes [S1, unofficial]. The method was developed to address the problem of guided solid texture synthesis for anatomic structures, ensuring that corresponding points in different instances of anatomic objects have the same $(u, v, \tau)$ values [S1, unofficial]. The X2U map computation method references details found in [Mer09] [S1, unofficial].
