# UV Contraction for Z-fighting Prevention

Also called: Half-pixel UV contraction, Trim sheet UV contraction, UV Contraction (Half-Pixel), UV padding, UV scaling, UV shrinkage

## Overview
UV Contraction is a mesh preprocessing technique that scales the UV coordinates of mesh vertices inward toward the center of their texture space to prevent sampling errors, such as seams, sparkly dots, or z-fighting artifacts, at texture boundaries [S1, unofficial]. It specifically addresses issues arising in voxel rendering or when using texture atlases (trim sheets) where texture sampling bleed occurs at the edges of individual atlas tiles [S1, unofficial]. Unlike [Texture Coordinate Margin Adjustment](17488-texture-coordinate-margin-adjustment.md), which adds a margin to prevent lookups outside bounds, UV Contraction actively shrinks the UV footprint to stay safely within the valid texel region of the atlas.

## How it works
**Inputs and Outputs:**
- **Input:** A mesh resource (e.g., `ArrayMesh`) with UV coordinates, a texture atlas size (typically 256x256), and the assumption that the mesh consists of a single surface composed of quads (2 triangles per face, 6 vertices total) [S1, unofficial].
- **Output:** The same mesh resource with modified UV coordinates, saved back to disk [S1, unofficial].

**Data Structures:**
- **Mesh Data:** The mesh is accessed via a tool (e.g., `MeshDataTool`) that provides vertex and face indices. The mesh is assumed to have exactly one surface [S1, unofficial].
- **UV Coordinates:** 2D vectors $(u, v)$ in normalized texture space $[0, 1]$ [S1, unofficial].

**Parameters:**
- **TEXTURE_SIZE:** The width/height of the square texture atlas in pixels. Typical value: 256 [S1, unofficial].
- **TEXEL:** The size of one texel in normalized UV space. Formula: $TEXEL = 1.0 / TEXTURE_SIZE$ [S1, unofficial].
- **factor:** The scaling multiplier for contraction. Formula: $factor = 1.0 - (TEXEL \times 0.5)$ [S1, unofficial]. This represents a contraction of exactly half a texel [S1, unofficial].

**Steps:**
1.  Iterate through all faces of the mesh. The algorithm assumes faces are processed in pairs representing quads (6 vertices total per quad) [S1, unofficial].
2.  For each quad, calculate the center of the UV quad. Sum the UV coordinates of all 6 vertices and multiply by $1/6$.
    $$center = \sum_{i=1}^{6} uv_i \times \frac{1}{6}$$
3.  Compute the contraction factor using the texture size:
    $$factor = 1.0 - \left(\frac{1.0}{TEXTURE_SIZE} \times 0.5\right)$$
4.  For each of the 6 vertices in the quad, compute the new UV coordinate by scaling the distance from the center by the factor and adding the center back:
    $$new\_uv = (old\_uv - center) \times factor + center$$
5.  Update the mesh's vertex UVs with the new values [S1, unofficial].
6.  Commit the modified mesh data and save the resource [S1, unofficial].

**Pseudocode:**
```python
def uv_contraction(mesh, texture_size=256.0):
    """
    Contracts UV coordinates of a mesh to prevent z-fighting/seams.
    Assumes mesh has 1 surface, composed of quads (2 triangles per face).
    """
    texel = 1.0 / texture_size
    factor = 1.0 - (texel * 0.5)
    
    # Access mesh data via a tool (implementation-specific, e.g., MeshDataTool)
    mesh_tool = create_mesh_data_tool(mesh)
    mesh_tool.create_from_surface(mesh, surface_index=0)
    
    face_count = mesh_tool.get_face_count()
    
    # Iterate over faces in pairs (quads)
    for face_idx in range(0, face_count - 1, 2):
        uvs = {}
        center = Vector2(0.0, 0.0)
        
        # Process 6 vertices of the quad (2 triangles)
        for idx in range(6):
            # Determine triangle index (0 or 1) and vertex index within triangle (0, 1, 2)
            tri_idx = idx // 3
            vert_idx_in_tri = idx % 3
            
            # Get global vertex index for this face
            vertex_idx = mesh_tool.get_face_vertex(face_idx + tri_idx, vert_idx_in_tri)
            uv = mesh_tool.get_vertex_uv(vertex_idx)
            
            # Accumulate center
            center += uv * (1.0 / 6.0)
            uvs[vertex_idx] = uv
            
        # Contract UVs
        for vertex_idx, old_uv in uvs.items():
            new_uv = (old_uv - center) * factor + center
            mesh_tool.set_vertex_uv(vertex_idx, new_uv)
            
    # Commit changes back to mesh
    mesh.clear_surfaces()
    mesh_tool.commit_to_surface(mesh, surface_index=0)
    
    # Save mesh resource (implementation-specific)
    save_mesh_resource(mesh)
```

**Edge Cases and Pitfalls:**
- The method assumes UVs are snapped to pixels [S1, unofficial].
- It requires the mesh to be composed of exactly one surface [S1, unofficial].
- It assumes UVs are structured as quads (2 triangles per face, 6 vertices) [S1, unofficial].
- It assumes the texture atlas size is fixed (e.g., 256x256) [S1, unofficial].
- It assumes individual mesh resource files rather than inherited scenes [S1, unofficial].
- If antialiasing or multisampling is enabled, the method still works but was originally noted in the context of projects not requiring them [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Time complexity is linear with respect to the number of vertices/faces, as each vertex is processed once per quad [S1, unofficial].
- Memory complexity is minimal, requiring storage for temporary UV arrays per quad [S1, unofficial].

**Measured Performance:**
- Specific performance metrics are not provided in the sources [S1, unofficial].

**Scaling:**
- The method scales with the number of meshes and faces. It is a preprocessing step, so runtime performance is unaffected, but import time increases [S1, unofficial].

**Strengths and Limitations:**
- **Strengths:** Effectively prevents seams and sparkly dots in voxel rendering and trim sheet usage [S1, unofficial]. Works even with MSAA enabled [S1, unofficial].
- **Limitations:** Highly restrictive assumptions about mesh structure (single surface, quads, pixel-snapped UVs) and texture atlas size [S1, unofficial]. Not suitable for meshes with arbitrary topology or multiple surfaces [S1, unofficial].

**When to Use:**
- Use when rendering voxel-based meshes or using texture atlases (trim sheets) where z-fighting or sampling bleed at tile boundaries is observed [S1, unofficial].
- Use when mesh structure is known to be simple quads and UVs are pixel-snapped [S1, unofficial].

**When Not to Use:**
- Do not use for meshes with complex topology, multiple surfaces, or non-quad faces [S1, unofficial].
- Do not use if UVs are not snapped to pixels or if the texture atlas size is dynamic [S1, unofficial].

## Background
UV Contraction was proposed as a solution to z-fighting and sampling artifacts in voxel rendering using texture atlases (trim sheets) [S1, unofficial]. The technique was discussed in the context of the Godot Engine, specifically addressing issues reported in GitHub issue #79081 [S1, unofficial]. It was implemented as a preprocessing script (EditorScenePostImport) to modify mesh UVs during scene import [S1, unofficial].
