# Texture Coordinate Generation for Volume

Also called: Half-texel offset coordinate generation, Texture Coordinate Generation for Display Region

## Overview
Generates normalized texture coordinates for the 8 corners of a 3D volume box (or a sub-region thereof) to map the 3D texture correctly, accounting for half-texel offsets [S1, unofficial].

## How it works
**Inputs:**
1. `size`: A 3D integer vector $(W, H, D)$ representing the dimensions of the 3D texture image [S1, unofficial].
2. `img_size`: A 3D integer vector representing the total dimensions of the texture space [S1, unofficial].
3. `min_corner`, `max_corner`: 3D integer vectors defining the sub-region bounds within `img_size` [S1, unofficial].

**Outputs:**
An array of 8 normalized 3D texture coordinate vectors $(u, v, w)$ corresponding to the 8 vertices of the volume box [S1, unofficial].

**Data Structures:**
- `fvec3`: A 3-component floating-point vector $(x, y, z)$ [S1, unofficial].
- `ivec3`: A 3-component integer vector [S1, unofficial].
- `texc`: An array of 8 `fvec3` elements [S1, unofficial].

**Steps:**

1. **Validate Input:** Check if any dimension of `size` or `img_size` is zero. If so, abort and log an error [S1, unofficial].
2. **Compute Half-Texel Offsets:** Calculate the offset for each axis based on the inverse of the image dimensions [S1, unofficial]:
   $$
   dx = \frac{0.5}{W}, \quad dy = \frac{0.5}{H}, \quad dz = \frac{0.5}{D}
   $$
   Where $W, H, D$ are `img_size.x()`, `img_size.y()`, `img_size.z()` respectively [S1, unofficial].
3. **Compute Corner Coordinates:**
   - **For full volume:**
     $$
     x_0 = 0.0 + dx, \quad x_1 = 1.0 - dx
     $$
     $$
     y_0 = 0.0 + dy, \quad y_1 = 1.0 - dy
     $$
     $$
     z_0 = 0.0 + dz, \quad z_1 = 1.0 - dz
     $$
     [S1, unofficial]
   - **For sub-region (display region):**
     $$
     x_0 = \frac{\min\_corner.x}{W} + dx, \quad x_1 = \frac{\max\_corner.x}{W} - dx
     $$
     $$
     y_0 = \frac{\min\_corner.y}{H} + dy, \quad y_1 = \frac{\max\_corner.y}{H} - dy
     $$
     $$
     z_0 = \frac{\min\_corner.z}{D} + dz, \quad z_1 = \frac{\max\_corner.z}{D} - dz
     $$
     [S1, unofficial]
4. **Assign Texture Coordinates:** Populate the `texc` array with the 8 vertices in the following specific order [S1, unofficial]:
   1. $(x_0, y_0, z_1)$
   2. $(x_1, y_0, z_1)$
   3. $(x_1, y_1, z_1)$
   4. $(x_0, y_1, z_1)$
   5. $(x_0, y_0, z_0)$
   6. $(x_1, y_0, z_0)$
   7. $(x_1, y_1, z_0)$
   8. $(x_0, y_1, z_0)$

**Pseudocode:**
```python
def generate_texture_coordinates(size, img_size=None, min_corner=None, max_corner=None):
    if img_size is None:
        img_size = size
        min_corner = (0, 0, 0)
        max_corner = (size.x - 1, size.y - 1, size.z - 1)
        
    W, H, D = img_size.x, img_size.y, img_size.z
    if W == 0 or H == 0 or D == 0:
        raise ValueError("Image size cannot contain zero dimensions.")
        
    dx = 0.5 / W
    dy = 0.5 / H
    dz = 0.5 / D
    
    if min_corner is None:
        x0, x1 = 0.0 + dx, 1.0 - dx
        y0, y1 = 0.0 + dy, 1.0 - dy
        z0, z1 = 0.0 + dz, 1.0 - dz
    else:
        x0 = (min_corner.x / W) + dx
        x1 = (max_corner.x / W) - dx
        y0 = (min_corner.y / H) + dy
        y1 = (max_corner.y / H) - dy
        z0 = (min_corner.z / D) + dz
        z1 = (max_corner.z / D) - dz
        
    texc = [
        (x0, y0, z1), (x1, y0, z1), (x1, y1, z1), (x0, y1, z1),
        (x0, y0, z0), (x1, y0, z0), (x1, y1, z0), (x0, y1, z0)
    ]
    return texc
```

**Edge Cases and Pitfalls:**
- The source code contains a comment expressing uncertainty about why $z_1$ is used for the first four vertices and $z_0$ for the last four, suggesting the specific winding order or face culling requirements driving this arrangement are not well-documented [S1, unofficial].

## Subtopics

### [Texture Coordinate Margin Adjustment](17488-texture-coordinate-margin-adjustment.md)
A technique to fix white artifacts (empty texture spots) caused by rounding errors in shader texture lookups by modifying texture coordinates to add a small margin, preventing lookups outside the texture bounds. It addresses the issue where floating-point precision errors cause sampled coordinates to fall just outside the valid $[0, 1]$ range, resulting in sampling from empty or undefined regions, particularly in voxel engines using large texture atlases. Unlike [UV Contraction for Z-fighting Prevention](22185-uv-contraction-for-z-fighting-prevention.md), which shrinks the UV footprint to prevent bleed between atlas tiles, this method expands the valid lookup region slightly inward to tolerate boundary errors without altering the visual footprint of the texture.

## Background
Originated in the Visualization Library's `RaycastVolume` implementation, specifically in the `generateTextureCoordinates` method [S1, unofficial]. The method is used to bind geometry to 3D textures for raycasting volume rendering [S1, unofficial].
