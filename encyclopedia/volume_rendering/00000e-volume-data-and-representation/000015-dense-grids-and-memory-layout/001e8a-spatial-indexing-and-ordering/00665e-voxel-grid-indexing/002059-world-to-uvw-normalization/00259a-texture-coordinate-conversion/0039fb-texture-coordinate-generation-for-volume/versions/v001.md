# Texture Coordinate Generation for Volume

Also called: Half-texel offset coordinate generation, Texture Coordinate Generation for Display Region

## Overview
Generates normalized texture coordinates for the 8 corners of a 3D volume box (or a sub-region thereof) to ensure correct 3D texture sampling, specifically accounting for half-texel offsets to align texel centers with geometric vertices [S1, unofficial]. It differs from its parent [Texture Coordinate Conversion](3581-texture-coordinate-conversion.md) by explicitly computing the corner vertices for a bounding box geometry rather than providing a general-purpose shader function for arbitrary point sampling, and from siblings like [Voxel Texture Atlas UV Mapping](4162-voxel-texture-atlas-uv-mapping.md) by focusing on single-volume alignment rather than atlas packing [S1, S2, unofficial].

## How it works
**Inputs:**
1. `size`: A 3D integer vector $(W, H, D)$ representing the dimensions of the 3D texture image [S1, unofficial].
2. `img_size`: A 3D integer vector representing the total dimensions of the texture space [S1, unofficial].
3. `min_corner`, `max_corner`: 3D integer vectors defining the sub-region bounds within `img_size` [S1, unofficial].

**Outputs:**
An array of 8 normalized 3D texture coordinate vectors $(u, v, w)$ corresponding to the 8 vertices of the volume box [S1, unofficial].

**Data Structures:**
- `fvec3`: A 3-component floating-point vector $(x, y, z)$ [S1, unofficial].
- `ivec3`: A 3-component integer vector [S1, unofficial].
- `texc`: An array of 8 `fvec3` elements [S1, unofficial].

**Steps:**

1. **Validate Input:** Check if any dimension of `size` or `img_size` is zero. If so, abort and log an error [S1, unofficial].
2. **Compute Half-Texel Offsets:** Calculate the offset for each axis based on the inverse of the image dimensions [S1, unofficial]:
   $$
   dx = \frac{0.5}{W}, \quad dy = \frac{0.5}{H}, \quad dz = \frac{0.5}{D}
   $$
   Where $W, H, D$ are `img_size.x()`, `img_size.y()`, `img_size.z()` respectively [S1, unofficial].
3. **Compute Corner Coordinates:**
   - **For full volume:**
     $$
     x_0 = 0.0 + dx, \quad x_1 = 1.0 - dx
     $$
     $$
     y_0 = 0.0 + dy, \quad y_1 = 1.0 - dy
     $$
     $$
     z_0 = 0.0 + dz, \quad z_1 = 1.0 - dz
     $$
     [S1, unofficial]
   - **For sub-region (display region):**
     $$
     x_0 = \frac{\min\_corner.x}{W} + dx, \quad x_1 = \frac{\max\_corner.x}{W} - dx
     $$
     $$
     y_0 = \frac{\min\_corner.y}{H} + dy, \quad y_1 = \frac{\max\_corner.y}{H} - dy
     $$
     $$
     z_0 = \frac{\min\_corner.z}{D} + dz, \quad z_1 = \frac{\max\_corner.z}{D} - dz
     $$
     [S1, unofficial]
4. **Assign Texture Coordinates:** Populate the `texc` array with the 8 vertices in the following specific order [S1, unofficial]:
   1. $(x_0, y_0, z_1)$
   2. $(x_1, y_0, z_1)$
   3. $(x_1, y_1, z_1)$
   4. $(x_0, y_1, z_1)$
   5. $(x_0, y_0, z_0)$
   6. $(x_1, y_0, z_0)$
   7. $(x_1, y_1, z_0)$
   8. $(x_0, y_1, z_0)$

**Pseudocode:**
```python
def generate_texture_coordinates(size, img_size=None, min_corner=None, max_corner=None):
    # Determine dimensions
    if img_size is None:
        img_size = size
        min_corner = (0, 0, 0)
        max_corner = (size.x - 1, size.y - 1, size.z - 1)
    
    W, H, D = img_size.x, img_size.y, img_size.z
    
    # Validate input
    if W == 0 or H == 0 or D == 0:
        raise ValueError("Image size cannot contain zero dimensions.")
        
    # Compute half-texel offsets
    dx = 0.5 / W
    dy = 0.5 / H
    dz = 0.5 / D
    
    # Compute normalized corner coordinates
    # Note: Source uses max_corner directly in division, implying max_corner 
    # is the exclusive upper bound or the source code logic assumes specific 
    # indexing. Based on S1: x1 = max_corner.x / W - dx.
    # If max_corner is inclusive index, this formula might need adjustment,
    # but we follow the source exactly [S1, unofficial].
    x0 = (min_corner.x / W) + dx
    x1 = (max_corner.x / W) - dx
    y0 = (min_corner.y / H) + dy
    y1 = (max_corner.y / H) - dy
    z0 = (min_corner.z / D) + dz
    z1 = (max_corner.z / D) - dz
    
    # Assign to 8 vertices in specific order
    texc = [
        (x0, y0, z1),
        (x1, y0, z1),
        (x1, y1, z1),
        (x0, y1, z1),
        (x0, y0, z0),
        (x1, y0, z0),
        (x1, y1, z0),
        (x0, y1, z0)
    ]
    
    return texc
```

**Edge Cases and Pitfalls:**
- The source code contains a comment expressing uncertainty about why $z_1$ is used for the first four vertices and $z_0$ for the last four, suggesting the specific winding order or face culling requirements driving this arrangement are not well-documented [S1, unofficial].
- Floating-point rounding errors in shader texture lookups can cause coordinates to map to "empty" spots outside the valid texture area, resulting in white artifacts [S2, unofficial].

## Subtopics

### Texture Coordinate Margin Adjustment
A technique to fix white artifacts (empty texture spots) caused by rounding errors in shader texture lookups by modifying texture coordinates to add a small margin, preventing lookups outside the texture bounds [S2, unofficial]. It is chosen when using single large textures with multiple block textures (e.g., voxel engines) where floating-point precision issues lead to sampling errors [S2, unofficial]. An alternative fix is using recent GLSL versions with integer-based texture lookup methods to avoid floating-point rounding issues entirely [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$, as it computes a fixed number of 8 vertices regardless of volume size.
- **Memory Complexity:** $O(1)$, storing only 8 vectors.
- **Strengths:** Ensures precise alignment of texture centers with geometry vertices, reducing interpolation artifacts at the volume boundaries [S1, unofficial].
- **Limitations:** Does not inherently solve floating-point rounding errors in the shader stage; requires additional margin adjustment or integer-based lookups for robustness in complex atlases [S2, unofficial].
- **When to use:** When rendering a 3D volume using a single texture object and precise vertex-to-texel alignment is required [S1, unofficial].
- **When not to use:** When using integer-based texture sampling functions that are immune to floating-point rounding errors [S2, unofficial].

## Background
Originated in the Visualization Library's `RaycastVolume` implementation, specifically in the `generateTextureCoordinates` method [S1, unofficial]. The method is used to bind geometry to 3D textures for raycasting volume rendering [S1, unofficial]. The associated pitfall regarding white artifacts in voxel engines is discussed in community forums regarding texture atlas usage [S2, unofficial].
