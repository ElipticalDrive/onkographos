# Bonxai

Also called: BonxaiGrid

## Overview
Bonxai is a header-only C++ sparse voxel grid library designed to represent 3D space, specifically intended to replace simple hash table maps in LiDAR odometry pipelines [S1, unofficial]. It addresses the performance bottlenecks of nearest neighbor searches and point removal operations found in previous implementations like `VoxelHashMap` [S1, unofficial]. Unlike flat hash tables, Bonxai uses a hierarchical structure with dense leaf nodes, which significantly accelerates query operations at the cost of increased memory consumption proportional to data sparsity [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D point cloud data (coordinates) [S1, unofficial].
*   **Output:** A hierarchical grid structure supporting insertion, nearest neighbor search, and point removal [S1, unofficial].

**Data Structures:**
The grid is hierarchical, consisting of inner grids and leaf nodes [S1, unofficial].
*   **Inner Grid:** A sparse index layer that maps inner coordinates to active leaf nodes [G].
*   **Leaf Node:** A dense allocation of voxels [S1, unofficial]. The dimensions are controlled by `leaf_grid_log2_dim` [S1, unofficial].
    *   Number of voxels per leaf: $2^{\text{leaf\_grid\_log2\_dim} \times 3}$ [S1, unofficial].
    *   Default `leaf_grid_log2_dim` is 3, resulting in $2^9 = 512$ voxels per leaf [S1, unofficial].
    *   Alternative "small leaf" configuration uses `leaf_grid_log2_dim` = 2, resulting in $2^6 = 64$ voxels per leaf [S1, unofficial].
*   **Voxel Content:** Each voxel stores a `std::vector` of points [S1, unofficial].

**Parameters:**
*   `inner_grid_log2_dim`: Log2 of the inner grid dimension. Default: 2 [S1, unofficial].
*   `leaf_grid_log2_dim`: Log2 of the leaf grid dimension. Default: 3 [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Create the grid with specified `inner_grid_log2_dim` and `leaf_grid_log2_dim` [G].
2.  **Insertion:**
    a. Map the input 3D point to its corresponding leaf node and local voxel index within that leaf [G].
    b. If the leaf node does not exist, allocate it [G].
    c. Access the `std::vector` of points in the target voxel [G].
    d. Reserve memory for the vector if it is empty or small, using `max_points_per_voxel_` [S1, unofficial].
    e. Append the point to the vector [G].
3.  **Nearest Neighbor Search:**
    a. Identify the leaf node containing the query point [G].
    b. Iterate through the voxels in the vicinity (typically the same leaf or adjacent leaves) [G].
    c. Compute distances to points stored in the voxel vectors [G].
    d. Return the closest point [G].
4.  **Point Removal:**
    a. Locate the voxel containing the point [G].
    b. Remove the point from the `std::vector` [G].

**Pseudocode:**
```python
import math

class BonxaiGrid:
    def __init__(self, inner_grid_log2_dim=2, leaf_grid_log2_dim=3):
        self.inner_grid_log2_dim = inner_grid_log2_dim
        self.leaf_grid_log2_dim = leaf_grid_log2_dim
        self.leaf_size = 2 ** leaf_grid_log2_dim
        self.inner_size = 2 ** inner_grid_log2_dim
        self.inner_grid = {}  # Sparse map from inner coordinate to LeafNode [G]
        self.max_points_per_voxel = 100  # [G] Typical default, not specified in sources

    class LeafNode:
        def __init__(self, leaf_size):
            self.leaf_size = leaf_size
            num_voxels = leaf_size ** 3
            self.voxels = [[] for _ in range(num_voxels)]  # Dense array of point vectors [G]

    def insert_point(self, point):
        # Map point to leaf coordinate and local voxel index [G]
        leaf_coord = tuple(p // self.leaf_size for p in point)
        voxel_local_index = tuple(p % self.leaf_size for p in point)
        voxel_idx = voxel_local_index[0] * self.leaf_size**2 + voxel_local_index[1] * self.leaf_size + voxel_local_index[2]

        if leaf_coord not in self.inner_grid:
            self.inner_grid[leaf_coord] = self.LeafNode(self.leaf_size)

        leaf = self.inner_grid[leaf_coord]
        voxel_vec = leaf.voxels[voxel_idx]
        if len(voxel_vec) == 0:
            voxel_vec.extend([None] * self.max_points_per_voxel)  # [G] Simulates std::vector::reserve

        voxel_vec.append(point)

    def nearest_neighbor(self, query_point, radius=None):
        leaf_coord = tuple(p // self.leaf_size for p in query_point)
        if leaf_coord not in self.inner_grid:
            return None

        leaf = self.inner_grid[leaf_coord]
        min_dist = float('inf')
        closest_point = None

        # Determine search bounds within the leaf [G]
        local_query = tuple(p % self.leaf_size for p in query_point)
        search_radius = radius if radius is not None else self.leaf_size
        start_x = max(0, local_query[0] - search_radius)
        end_x = min(self.leaf_size, local_query[0] + search_radius + 1)
        start_y = max(0, local_query[1] - search_radius)
        end_y = min(self.leaf_size, local_query[1] + search_radius + 1)
        start_z = max(0, local_query[2] - search_radius)
        end_z = min(self.leaf_size, local_query[2] + search_radius + 1)

        for x in range(start_x, end_x):
            for y in range(start_y, end_y):
                for z in range(start_z, end_z):
                    voxel_idx = x * self.leaf_size**2 + y * self.leaf_size + z
                    for pt in leaf.voxels[voxel_idx]:
                        if pt is None: continue
                        dist = math.sqrt(sum((a-b)**2 for a, b in zip(query_point, pt)))
                        if dist < min_dist:
                            min_dist = dist
                            closest_point = pt
        return closest_point
```

**Edge Cases and Pitfalls:**
*   **Memory Overhead:** Dense leaf allocation causes memory overhead proportional to data sparsity. If a leaf node is mostly empty, the memory for the `std::vector` array is still allocated [S1, unofficial].
*   **Performance Degradation:** Performance degrades in scenarios with random point measurements (reflections, occlusions) or sparse structures, as the dense leaf structure is less efficient than hash tables for highly sparse data [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Nearest neighbor search and point removal are faster than `VoxelHashMap` [S1, unofficial]. Point insertion is slower than `VoxelHashMap` [S1, unofficial].
*   **Memory Complexity:** Higher memory consumption than hash tables due to dense leaf allocation. The overhead is proportional to the sparsity of the data [S1, unofficial].
*   **Measured Performance:**
    *   On a benchmark of 6,000,000 points sampled from a 100m cube surface, Bonxai halves the runtime of the nearest neighbor search compared to `VoxelHashMap` [S1, unofficial].
    *   On 60,000 points, memory and runtime trends remain consistent [S1, unofficial].
    *   The speedup is particularly notable for single-threaded nearest neighbor searches [S1, unofficial].
*   **Strengths:** Fast nearest neighbor queries, fast point removal, header-only, no additional dependencies [S1, unofficial].
*   **Limitations:** Higher memory usage, slower point insertion, performance issues with highly sparse or random data [S1, unofficial].
*   **When to use:** When nearest neighbor search is a bottleneck and memory is not the primary constraint, especially in structured environments [S1, unofficial].
*   **When not to use:** When memory is extremely constrained or data is highly sparse and random [S1, unofficial].

## Background
Bonxai was introduced as a replacement for the `VoxelHashMap` in the KISS-ICP project by the PRBonn group [S1, unofficial]. The motivation was to move away from simple hash tables to a more appropriate and flexible data structure for representing 3D space, enabling future extensions like TSDF registration [S1, unofficial]. The library was chosen for being well-maintained, header-only, and having no additional dependencies [S1, unofficial]. Benchmarks were conducted using `heaptrack` for memory analysis and comparing against `VoxelHashMap` [S1, unofficial].
