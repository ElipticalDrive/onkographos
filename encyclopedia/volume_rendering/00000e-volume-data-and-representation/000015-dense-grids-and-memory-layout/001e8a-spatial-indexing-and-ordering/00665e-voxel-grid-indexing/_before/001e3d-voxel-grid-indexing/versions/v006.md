# Voxel Grid Indexing

Also called: Dense Voxel Grid, Voxel Grids, Voxel Indexing, VoxelGridDesc

## Overview
Voxel Grid Indexing maps 3D voxel coordinates $(i, j, k)$ to a 1D linear array index and vice versa, enabling efficient storage and retrieval of volumetric data in contiguous memory buffers [S1, S4, S8, unofficial]. It solves the problem of spatial lookup in volume rendering by converting continuous or discrete spatial positions into deterministic, collision-free array offsets [S1, S2, unofficial]. Unlike sparse representations that require tree traversal or hashing, this method provides $O(1)$ access via a simple "ravel" operation (series of products and sums), offering the fastest possible query time for dense grids [S8, unofficial]. However, it suffers from $O(N^3)$ memory complexity, making it prohibitive for high-resolution grids without sparsity optimizations [S7, S8, unofficial].

## How it works
**Inputs:**
- Grid dimensions: $size_x, size_y, size_z$ (number of voxels along each axis) [S2, S4, unofficial].
- Optional padding: $padding$ (e.g., 1 voxel border) to handle boundary checks and neighbor lookups without wrapping [S1, S3, unofficial].
- Optional world bounds: $min\_points$ (bounding box minimum) and $grid\_cell\_size$ for mapping continuous points to indices [S6, unofficial].

**Outputs:**
- Linear index $I$ for a given $(i, j, k)$ [S1, S4, unofficial].
- Coordinates $(i, j, k)$ for a given linear index $I$ [S1, S2, unofficial].

**Data Structures:**
- A 1D array (e.g., `TArray<BlockType>` or `float[]`) of size $size_x \times size_y \times size_z$ (or padded equivalent) [S1, S4, unofficial].
- Row-major layout: X dimension varies fastest, then Y, then Z [S5, S8, unofficial].

**Steps:**

1. **Calculate Strides:**
   Compute the strides for the Y and Z dimensions. If padding is applied, use padded dimensions $size'_x = size_x + padding$, etc.
   $$size_z' = size_z'$$
   $$size_yz' = size_y' \times size_z'$$
   $$size_x' = size_x'$$ (implicit in the first term) [S1, S2, S4, unofficial].

2. **Forward Mapping (3D to 1D):**
   Convert coordinates $(i, j, k)$ to linear index $I$:
   $$I = i \cdot size_yz' + j \cdot size_z' + k$$
   If padding is used (e.g., to access neighbors), coordinates are often shifted or the buffer is sized larger:
   $$I = (i + 1) \cdot kPaddedArea + (j + 1) \cdot kPaddedSize + (k + 1)$$
   where $kPaddedArea = size_x' \times size_y'$ and $kPaddedSize = size_x'$ [S1, S3, unofficial].
   Alternatively, for a grid with dimensions reduced by 1 (as in some specific implementations):
   $$offset = (k \times (dims[1] - 1) + j) \times (dims[0] - 1) + i$$ [S4, unofficial].

3. **Inverse Mapping (1D to 3D):**
   Convert linear index $I$ back to $(i, j, k)$:
   $$i = I / (size_y' \times size_z')$$
   $$j = (I \pmod{size_y' \times size_z'}) / size_z'$$
   $$k = (I \pmod{size_y' \times size_z'}) \pmod{size_z'}$$
   [S1, S2, unofficial].

4. **Continuous to Discrete Mapping (Optional):**
   For ray marching or point cloud queries, map continuous world coordinates $P$ to voxel indices:
   $$points\_index = \lfloor (P - min\_points) / grid\_cell\_size \rfloor$$
   Clamp indices to $[0, size_x'-1] \times [0, size_y'-1] \times [0, size_z'-1]$ [S6, unofficial].

**Pseudocode:**

```python
def voxel_index(i, j, k, size_x, size_y, size_z, padding=0):
    """
    Maps 3D voxel coordinates to a 1D linear index.
    Uses row-major order: x varies fastest, then y, then z.
    """
    # Apply padding if necessary for boundary checks
    sx = size_x + padding
    sy = size_y + padding
    sz = size_z + padding
    
    # Calculate strides
    stride_z = sz
    stride_yz = sy * sz
    
    # Compute linear index
    index = i * stride_yz + j * stride_z + k
    return index

def voxel_coords(index, size_x, size_y, size_z, padding=0):
    """
    Maps a 1D linear index back to 3D voxel coordinates.
    """
    sx = size_x + padding
    sy = size_y + padding
    sz = size_z + padding
    
    stride_z = sz
    stride_yz = sy * sz
    
    # Inverse mapping
    i = index // stride_yz
    remainder = index % stride_yz
    j = remainder // stride_z
    k = remainder % stride_z
    
    return (i, j, k)

def point_to_voxel_index(point, min_points, grid_cell_size, size_x, size_y, size_z, padding=0):
    """
    Maps a continuous 3D point to a voxel index.
    """
    # Calculate relative position
    rel_x = point[0] - min_points[0]
    rel_y = point[1] - min_points[1]
    rel_z = point[2] - min_points[2]
    
    # Calculate index
    idx_x = int(rel_x / grid_cell_size[0])
    idx_y = int(rel_y / grid_cell_size[1])
    idx_z = int(rel_z / grid_cell_size[2])
    
    # Clamp to grid bounds
    sx = size_x + padding
    sy = size_y + padding
    sz = size_z + padding
    
    idx_x = max(0, min(idx_x, sx - 1))
    idx_y = max(0, min(idx_y, sy - 1))
    idx_z = max(0, min(idx_z, sz - 1))
    
    return voxel_index(idx_x, idx_y, idx_z, size_x, size_y, size_z, padding)
```

**Parameters:**
- `size_x, size_y, size_z`: Grid dimensions in voxels [S2, unofficial].
- `padding`: Number of voxels to add to each dimension for boundary safety (e.g., 1) [S1, S3, unofficial].
- `grid_cell_size`: Size of each voxel in world units (e.g., 1.0) [S6, unofficial].
- `min_points`: Minimum corner of the bounding box [S6, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Access:** Without padding, accessing neighbors at grid boundaries (e.g., $i-1$ when $i=0$) causes out-of-bounds memory access. Padding solves this by expanding the buffer [S1, unofficial].
- **Precision:** Floating-point to integer conversion for continuous points must use floor or truncation consistently to avoid off-by-one errors [S6, unofficial].
- **Memory Usage:** Memory grows cubically with resolution. A $1024^3$ grid requires significant memory, often exceeding GPU limits [S8, unofficial].

## Subtopics

### [Coordinate Space Conversion](1785-coordinate-space-conversion.md)
Coordinate Space Conversion defines the deterministic arithmetic for mapping between continuous world coordinates, continuous voxel coordinates, discrete integer voxel indices, and block indices in a sparse voxel grid. It solves the problem of accurately locating which voxel contains a given point and converting that voxel back to world space, ensuring consistency across host (CPU), device (GPU), and shader (GLSL) execution paths. It differs from Voxel Grid Initialization by performing the per-point arithmetic rather than static bounding box setup, and from World to UVW Normalization by operating in physical units and integer indices rather than normalized $[0, 1]$ texture coordinates [1785-coordinate-space-conversion.md].

### [Voxel Grid Initialization](2168-voxel-grid-initialization.md)
Voxel Grid Initialization is the process of populating a sparse voxel data structure with active voxels based on specific criteria, typically by activating all voxels that match a target value (such as a background or level-set threshold). It differs from Voxel Grid Construction by focusing on the logical activation of existing or newly allocated grid cells rather than the geometric generation of the grid topology from primitives. It serves as the foundational step for Voxel Grid Indexing by ensuring the underlying data structures are correctly sized and populated before rendering or traversal [2168-voxel-grid-initialization.md].

### [World to UVW Normalization](2229-world-to-uvw-normalization.md)
World to UVW Normalization maps arbitrary 3D world coordinates into the normalized $[0, 1]$ range of a voxel grid, enabling consistent indexing and texture sampling regardless of the scene's physical scale or origin. It differs from Coordinate Space Conversion by explicitly handling discrete voxel grid boundaries and dimensionality, and from Texture Coordinate Conversion by operating at the grid indexing level rather than applying shader-specific offsets like Y-flips or centering adjustments [2229-world-to-uvw-normalization.md].

### [Bitstream Voxel Position Encoding](2371-bitstream-voxel-position-encoding.md)
Bitstream Voxel Position Encoding is a method to encode the 3D position of a voxel into a linear bitstream for tree traversal, where each child index is determined by 3 bits. It solves the problem of mapping spatial coordinates to a hierarchical structure (such as an Octree) by creating a deterministic bit sequence that guides navigation from the root to the leaf node representing the voxel [2371-bitstream-voxel-position-encoding.md].

### [Uniform Grid Adjacent Cell Indexing](2992-uniform-grid-adjacent-cell-indexing.md)
Computes the linear indices of the four cells sharing a specific grid edge in a uniform voxel grid, returning a sentinel value (`kBadIndex`) for neighbors that lie outside the grid boundaries. It differs from general Voxel Grid Indexing by specializing in edge-adjacency relationships required for constructing quad primitives in isosurface extraction, rather than arbitrary point-to-cell mapping [2992-uniform-grid-adjacent-cell-indexing.md].

### [Grid Embedding](4454-grid-embedding.md)
Grid Embedding is a method for storing shape-specific latent codes in a dense, learnable 4D tensor lookup table indexed by model ID. It solves the problem of efficiently retrieving and optimizing per-model geometric or feature representations by structuring them as a dense grid rather than a sparse or unstructured collection. It differs from sibling methods like Spatial Hashing or Sparse Voxel Grid by enforcing a fixed, dense memory layout for model-level indexing, whereas siblings typically focus on spatial coordinate hashing or sparse occupancy [4454-grid-embedding.md].

### [Spatial Hashing](5002-spatial-hashing.md)
Spatial Hashing maps 3D world positions to hierarchical string-based spatial hashes (keys) and vice versa, enabling efficient traversal of a voxel hierarchy without storing explicit grid structures. It differs from flat spatial hashing by using a fixed-depth 12-level octal encoding where each character represents a 2x2x2 voxel block, allowing direct conversion between coordinates and region boundaries. Unlike Bitstream Voxel Position Encoding which stores raw bits, this method compresses position into a human-readable string for hierarchical queries [5002-spatial-hashing.md].

### [Uniform Grid Indexing](6941-uniform-grid-indexing.md)
Uniform Grid Indexing converts a 3D world position into a linear array index within a dense, axis-aligned voxel grid. It solves the problem of spatial lookup in volume rendering by mapping continuous coordinates to discrete storage locations using an axis-aligned bounding box (AABB) and fixed grid resolution. It sets itself apart from Spatial Hashing by guaranteeing deterministic, collision-free indexing for all points within the grid bounds, and from Sparse Voxel Grid by using a fixed memory footprint regardless of data sparsity [6941-uniform-grid-indexing.md].

### [Sparse Voxel Grid](8021-sparse-voxel-grid.md)
A sparse voxel grid is a volume representation that stores only non-zero elements as a list of coordinates and corresponding data, reducing memory usage compared to dense grids. It differs from its sibling Uniform Grid Indexing by avoiding storage of empty space, but requires accelerated data structures for efficient querying, unlike the direct indexing of uniform grids [8021-sparse-voxel-grid.md].

### [Memory Layout and Data Mapping](8133-memory-layout-and-data-mapping.md)
Memory Layout and Data Mapping defines the mechanism for storing 3D voxel grids in contiguous 1D memory buffers and computing the bidirectional mapping between logical voxel coordinates (IJK) and linear array indices. It solves the problem of efficient random access and cache-friendly traversal of dense volumetric data by establishing a consistent row-major ordering where the X-dimension varies fastest, followed by Y, then Z. It differs from sparse representations by assuming a fixed, dense grid where memory is allocated for the entire bounding box, making it suitable for regular datasets [8133-memory-layout-and-data-mapping.md].

### [Sparse Voxel Chunk Indexing](8606-sparse-voxel-chunk-indexing.md)
Sparse Voxel Chunk Indexing maps a linear map index to a specific voxel within a sparse 8x8x8 chunk structure using bitmask arithmetic and cumulative counts, enabling efficient traversal of sparse volumetric data. It distinguishes itself from hash-based spatial indexing by preserving strict spatial coherence and from octrees by using a fixed-depth shallow tree structure that avoids logarithmic access overhead [8606-sparse-voxel-chunk-indexing.md].

### [Voxel Index Computation](13870-voxel-index-computation.md)
Voxel Index Computation maps continuous 3D coordinates to discrete voxel grid indices, solving the problem of spatial localization for ray marching and point cloud queries in neural rendering. It differs from generic grid indexing by supporting batched bounding box constraints and optional coordinate shifts for half-voxel alignment, while a specialized variant computes compact 3-bit indices for texture coordinate interpolation [13870-voxel-index-computation.md].

### [OpenVDB Volume Grid Storage](14574-openvdb-volume-grid-storage.md)
A data structure for efficiently storing dense and sparse volume grids as groups of voxels, where each voxel is indexed by a 3D integer coordinate [14574-openvdb-volume-grid-storage.md].

### Data Collection from Indices
Extracts data from a tensor given a list of indices, handling both 2D and 3D data tensors. It reshapes data to 2D (flatten first two dimensions) if it is 3D, or keeps as 2D if it is 2D, then calculates point_index by combining index and count_index to flatten the indexing [S9, unofficial].

### Coarse Geometry Searching
A two-stage optimization process where the first stage efficiently finds the coarse 3D areas of interest (geometry) using a low-resolution voxel grid with view-invariant color, reducing queried points for the fine stage. It initializes all grid values in the coarse density voxel grid to 0 and sets a bias term to ensure accumulated transmittance is close to 1 at the start of training. It also scales the learning rate for each grid point based on the number of training views visible to it [S10].

## Operating characteristics
- **Time Complexity:** $O(1)$ for index computation and lookup [S8, unofficial].
- **Memory Complexity:** $O(N^3)$ where $N$ is the resolution per dimension. This cubic growth makes high-resolution dense grids memory-prohibitive [S7, S8, unofficial].
- **Performance:** Provides the fastest query time among spatial indexing methods due to direct arithmetic mapping [S8, unofficial].
- **Strengths:** Simple implementation, cache-friendly for dense data, no overhead for tree traversal or hash collisions [S8, unofficial].
- **Limitations:** High memory consumption for large volumes, inefficient for sparse scenes [S7, S8, unofficial].
- **When to Use:** Small to medium-sized dense volumes, or as a coarse approximation in multi-stage rendering (e.g., coarse geometry search in NeRF) [S10].
- **When Not to Use:** Large-scale sparse scenes, high-resolution volumes where memory is constrained [S7, S8, unofficial].

## Background
Voxel grids are a fundamental representation in computer graphics and volume rendering, dating back to the early days of 3D graphics. They provide an explicit discretization of 3D space into cubes, storing metadata in an array [S7, unofficial]. The method has been widely used in various forms, from simple occupancy grids to complex neural rendering optimizations like Direct Voxel Grid Optimization [S10]. The shift towards sparse and hierarchical representations (like Octrees and Sparse Voxel Grids) has been driven by the memory limitations of dense voxel grids [S8, unofficial].
