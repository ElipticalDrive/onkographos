# Spherical Voxel Grid Setup

Also called: SVR grid setup, Spherical voxel grid, SphericalVoxelGrid Initialization

## Overview
Spherical Voxel Grid Setup initializes the data structures required for efficient ray casting traversal in a spherical coordinate system, specifically designed for egocentric omnidirectional view synthesis [S1, unofficial]. It differs from Cartesian voxel grids by aligning the grid topology with the radial nature of egocentric rays, thereby reducing wasted memory on distant objects and avoiding the non-uniform ray-grid hit distribution inherent in uniform Cartesian resolutions [S1, unofficial]. It builds on [Voxel Space Setup](3520-voxel-space-setup.md) by defining a spherical bounding volume and precomputing geometric constants for traversal.

## How it works
**Inputs:**
- `min_bound`, `max_bound`: `SphereBound` structs defining the lower and upper limits for radial ($r$), polar ($\theta$), and azimuthal ($\phi$) coordinates.
- `num_radial_sections`, `num_polar_sections`, `num_azimuthal_sections`: Integer counts defining the number of voxels along the radial, polar, and azimuthal axes, respectively.
- `sphere_center`: 3D Cartesian coordinates $(x, y, z)$ of the sphere's center.

**Outputs:**
- A `SphericalVoxelGrid` object containing precomputed deltas, trigonometric lookup tables, line segment arrays, and bound vectors.

**Data Structures:**
1.  `SphereBound`:
    -   `radial`: `double`
    -   `polar`: `double`
    -   `azimuthal`: `double`
2.  `LineSegment`:
    -   `P1`: `double`
    -   `P2`: `double`
3.  `TrigonometricValues`:
    -   `cosine`: `double`
    -   `sine`: `double`
4.  `SphericalVoxelGrid` (internal fields):
    -   `num_radial_sections_`, `num_polar_sections_`, `num_azimuthal_sections_`: `std::size_t`

    -   `sphere_max_radius_`: `double`
    -   `sphere_max_diameter_`: `double`
    -   `delta_radius_`, `delta_theta_`, `delta_phi_`: `double`
    -   `delta_radii_sq_`: `std::vector<double>` of size $N_r + 1$
    -   `polar_trig_values_`: `std::vector<TrigonometricValues>` of size $N_p + 1$
    -   `azimuthal_trig_values_`: `std::vector<TrigonometricValues>` of size $N_a + 1$
    -   `P_max_polar_`: `std::vector<LineSegment>` of size $N_p + 1$
    -   `P_max_azimuthal_`: `std::vector<LineSegment>` of size $N_a + 1$
    -   `center_to_polar_bound_vectors_`: `std::vector<Vec3>` of size $N_p + 1$
    -   `center_to_azimuthal_bound_vectors_`: `std::vector<Vec3>` of size $N_a + 1$

**Steps:**

1.  **Compute Deltas:**
    Calculate the step size for each spherical dimension using the bounds and section counts [S1, unofficial]:
    $$ \Delta r = \frac{r_{max} - r_{min}}{N_r} $$
    $$ \Delta \theta = \frac{\theta_{max} - \theta_{min}}{N_p} $$
    $$ \Delta \phi = \frac{\phi_{max} - \phi_{min}}{N_a} $$
    Where $r_{max}, r_{min}$ are `max_bound.radial`, `min_bound.radial`, etc., and $N_r, N_p, N_a$ are the respective section counts [S1, unofficial].

2.  **Initialize Delta Radii Squared:**
    Create `delta_radii_sq_` of size $N_r + 1$. This array stores the squared radial distances from the center, starting from the maximum radius down to zero [S1, unofficial].
    -   Let $R_{max} = r_{max} - r_{min}$ (referred to as `max_radius` in source logic, effectively the radial span or absolute max depending on implementation context; source implies `max_bound.radial` is used as `sphere_max_radius_` and `delta_radius` is computed from the span).
    -   Initialize `current_delta_radius` = $R_{max}$ (or `max_bound.radial` as per source TODO note, but formula uses span). *Correction based on source code:* The source code sets `sphere_max_radius_` to `max_bound.radial` and computes `delta_radius_` from the span. The `initializeDeltaRadiiSquared` function takes `max_radius` (which is `max_bound.radial` in the constructor call context) and `delta_radius_`.
    -   For $i$ from 0 to $N_r$:
        -   `delta_radii_sq_[i]` = `current_delta_radius`$^2$
        -   `current_delta_radius` -= $\Delta r$
    -   *Note:* The source example shows `max_radius=6, delta=2, N=3` yielding `{36, 16, 4, 0}`. This implies the starting value is the absolute max radius, not the span.

3.  **Initialize Trigonometric Values:**
    Create `polar_trig_values_` (size $N_p + 1$) and `azimuthal_trig_values_` (size $N_a + 1$) [S1, unofficial].
    -   For polar: Start with $\theta = \theta_{min}$. For $i$ from 0 to $N_p$:
        -   `polar_trig_values_[i].cosine` = $\cos(\theta)$
        -   `polar_trig_values_[i].sine` = $\sin(\theta)$
        -   $\theta$ += $\Delta \theta$
    -   For azimuthal: Start with $\phi = \phi_{min}$. For $i$ from 0 to $N_a$:
        -   `azimuthal_trig_values_[i].cosine` = $\cos(\phi)$
        -   `azimuthal_trig_values_[i].sine` = $\sin(\phi)$
        -   $\phi$ += $\Delta \phi$

4.  **Initialize Max Radius Line Segments:**
    Create `P_max_polar_` (size $N_p + 1$) and `P_max_azimuthal_` (size $N_a + 1$) [S1, unofficial]. These represent intersection points between voxel boundary lines and the radial voxel.
    -   The source code snippet cuts off the implementation of `initializeMaxRadiusLineSegments`, but the description states it uses section counts, `sphere_center`, `sphere_max_radius_`, and the respective trig values.
    -   *Inference:* These likely compute the Cartesian coordinates of the boundary points on the sphere surface or within the voxel grid to facilitate ray-box intersection tests. Specifically, they map the angular bounds to Cartesian vectors scaled by the max radius.

5.  **Compute Bound Vectors:**
    Calculate `center_to_polar_bound_vectors_` and `center_to_azimuthal_bound_vectors_` [S1, unofficial].
    -   For each index $i$:
        -   `center_to_polar_bound_vectors_[i]` = `sphere_center` - `P_max_polar_[i]`
        -   `center_to_azimuthal_bound_vectors_[i]` = `sphere_center` - `P_max_azimuthal_[i]`
    -   These vectors represent the direction from the sphere center to the voxel boundary points.

**Edge Cases and Pitfalls:**

## Operating characteristics
- **Time Complexity:** Initialization is $O(N_r + N_p + N_a)$ due to the linear precomputation of deltas, trigonometric values, and line segments [S1, unofficial].
- **Memory Complexity:** $O(N_r + N_p + N_a)$ to store the precomputed arrays [S1, unofficial].
- **Strengths:** Aligns with egocentric rays, reducing wasted memory on distant objects compared to Cartesian grids. Enables factorization for performance enhancement [S1, unofficial].
- **Limitations:** Non-standard angular bounds ($[0, 2\pi]$ for polar) may require careful handling in downstream algorithms. The exact implementation of `initializeMaxRadiusLineSegments` is not fully detailed in the provided source, potentially obscuring the complexity of the line segment calculations [S1, unofficial].
- **Usage:** Instantiated and passed to `walkSphericalVolume` for ray casting traversal [S1, unofficial].

## Background
The Spherical Voxel Grid Setup is part of the Spherical Volume Rendering (SVR) algorithm, designed for egocentric omnidirectional view synthesis [S1, unofficial]. It addresses the inefficiency of uniform resolution in large-scale unbounded scenes by replacing Cartesian grids with a spherical topology that avoids polar singularities through the use of offset quasi-uniform grids (though the specific "Balanced Spherical Grid" variant is a child topic) [S1, unofficial]. The method was developed as part of the `spherical-volume-rendering` project [S1, unofficial].
