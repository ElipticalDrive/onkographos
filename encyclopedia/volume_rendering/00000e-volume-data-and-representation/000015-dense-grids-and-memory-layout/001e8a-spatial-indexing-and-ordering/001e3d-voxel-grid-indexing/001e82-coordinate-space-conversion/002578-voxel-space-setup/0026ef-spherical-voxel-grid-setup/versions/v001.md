# Spherical Voxel Grid Setup

Also called: SVR grid setup, Spherical voxel grid, SphericalVoxelGrid Initialization

## Overview
Spherical Voxel Grid Setup initializes the data structures required for efficient ray casting traversal within a spherical coordinate volume. It computes the discretization steps, precomputes trigonometric values, and constructs geometric primitives (line segments) that define voxel boundaries, enabling the `walkSphericalVolume` algorithm to determine ray-voxel intersections without repeated expensive trigonometric calculations or square roots during the rendering pass. It differs from Cartesian voxel grid setups by operating in a $(r, \theta, \phi)$ coordinate system tailored for egocentric view synthesis, where resolution requirements are anisotropic and radial distances vary significantly.

## How it works
**Inputs:**
- `num_radial_sections` ($N_r$): Integer count of voxels along the radial axis.
- `num_polar_sections` ($N_p$): Integer count of voxels along the polar axis.
- `num_azimuthal_sections` ($N_a$): Integer count of voxels along the azimuthal axis.
- `min_bound`: `SphereBound` struct containing `radial` ($r_{min}$), `polar` ($\theta_{min}$), and `azimuthal` ($\phi_{min}$) lower bounds.
- `max_bound`: `SphereBound` struct containing `radial` ($r_{max}$), `polar` ($\theta_{max}$), and `azimuthal` ($\phi_{max}$) upper bounds.
- `sphere_center`: 3D Cartesian vector $(x_c, y_c, z_c)$ representing the center of the spherical volume.

**Outputs:**
- A `SphericalVoxelGrid` object containing:
  - Discretization deltas: `delta_radius_`, `delta_theta_`, `delta_phi_`.
  - Precomputed squared radial deltas: `delta_radii_sq_` (array of size $N_r + 1$).
  - Precomputed trigonometric values: `polar_trig_values_` (size $N_p + 1$), `azimuthal_trig_values_` (size $N_a + 1$).
  - Line segment arrays: `P_max_polar_` (size $N_p + 1$), `P_max_azimuthal_` (size $N_a + 1$).
  - Bound vectors: `center_to_polar_bound_vectors_`, `center_to_azimuthal_bound_vectors_`.

**Data Structures:**
- `SphereBound`:
  ```cpp
  struct SphereBound {
      double radial;
      double polar;
      double azimuthal;
  };
  ```
- `LineSegment`:
  ```cpp
  struct LineSegment {
      double P1;
      double P2;
  };
  ```
- `TrigonometricValues`:
  ```cpp
  struct TrigonometricValues {
      double cosine;
      double sine;
  };
  ```

**Steps:**

1.  **Compute Discretization Deltas:**
    Calculate the step size for each dimension based on the bounds and section counts [S1, unofficial].
    $$ \Delta r = \frac{r_{max} - r_{min}}{N_r} $$
    $$ \Delta \theta = \frac{\theta_{max} - \theta_{min}}{N_p} $$
    $$ \Delta \phi = \frac{\phi_{max} - \phi_{min}}{N_a} $$
    Store these as `delta_radius_`, `delta_theta_`, and `delta_phi_` respectively.

2.  **Precompute Squared Radial Deltas:**
    Initialize `delta_radii_sq_` as a vector of size $N_r + 1$. This array stores the squared distance from the sphere center to the radial voxel boundaries. The values are computed starting from `max_radius` ($r_{max}$) and subtracting `delta_radius_` at each step [S1, unofficial].
    $$ \text{delta\_radii\_sq\_}[i] = (r_{max} - i \cdot \Delta r)^2 \quad \text{for } i = 0 \dots N_r $$
    Note: The implementation iterates such that the first element is $r_{max}^2$ and the last is $r_{min}^2$ (effectively $0^2$ if $r_{min}=0$) [S1, unofficial].

3.  **Precompute Trigonometric Values:**
    Initialize `polar_trig_values_` (size $N_p + 1$) and `azimuthal_trig_values_` (size $N_a + 1$). These arrays store the sine and cosine of the angular boundaries [S1, unofficial].
    For polar angles $\theta$:
    $$ \theta_i = \theta_{min} + i \cdot \Delta \theta \quad \text{for } i = 0 \dots N_p $$
    $$ \text{polar\_trig\_values\_}[i] = \{ \cos(\theta_i), \sin(\theta_i) \} $$
    For azimuthal angles $\phi$:
    $$ \phi_i = \phi_{min} + i \cdot \Delta \phi \quad \text{for } i = 0 \dots N_a $$
    $$ \text{azimuthal\_trig\_values\_}[i] = \{ \cos(\phi_i), \sin(\phi_i) \} $$

4.  **Compute Max Radius Line Segments:**
    Initialize `P_max_polar_` and `P_max_azimuthal_` arrays using `initializeMaxRadiusLineSegments` [S1, unofficial]. These line segments represent the intersection points of the radial voxel boundaries with the maximum radius sphere in the polar and azimuthal planes, respectively.
    For each section $i$, the line segment endpoints $P1$ and $P2$ are derived from the sphere center and the precomputed trigonometric values scaled by `sphere_max_radius_` ($r_{max}$) [S1, unofficial]. Specifically, the code notes that `sphere_max_radius_` is set to `max_bound.radial` [S1, unofficial].

5.  **Compute Bound Vectors:**
    Calculate `center_to_polar_bound_vectors_` and `center_to_azimuthal_bound_vectors_` by subtracting the $P_{max}$ coordinates from `sphere_center` [S1, unofficial]. These vectors are used to translate the line segment calculations relative to the sphere's center in Cartesian space.

**Edge Cases and Pitfalls:**
- The grid coordinate system uses polar and azimuthal angles within the range $[0, 2\pi]$. A TODO in the source indicates a potential future update to change the polar grid range to $[0, \pi]$ [S1, unofficial]. Implementers should be aware of this current convention.
- `sphere_max_radius_` is currently set to `max_bound.radial` [S1, unofficial]. If the volume is not centered at the origin or if `min_bound.radial` is not 0, the radial deltas still span the full range $[r_{min}, r_{max}]$, but the trigonometric and line segment calculations rely on `sphere_max_radius_` for the outer boundary geometry.

## Operating characteristics
- **Time Complexity:** The setup phase is $O(N_r + N_p + N_a)$ due to the linear precomputation of deltas, trigonometric values, and line segments.
- **Memory Complexity:** $O(N_r + N_p + N_a)$ to store the precomputed arrays.
- **Strengths:** Precomputing trigonometric values and squared radial deltas significantly accelerates the ray casting traversal (`walkSphericalVolume`) by avoiding repeated expensive function calls during rendering.
- **Limitations:** The current implementation uses a fixed angular range of $[0, 2\pi]$ for polar angles, which may not align with standard spherical coordinate conventions ($[0, \pi]$) and may require updates [S1, unofficial].
- **Usage:** Designed for egocentric view synthesis where the camera is at the center of the spherical volume.

## Background
The Spherical Voxel Grid Setup is part of the Spherical Volume Rendering (SVR) algorithm, developed for efficient rendering of radiance fields in egocentric view synthesis. It addresses the inefficiencies of Cartesian grids when dealing with panoramic imagery, where resolution requirements vary with distance and angle. The method was introduced in the `spherical-volume-rendering/svr-algorithm` repository [S1, unofficial].
