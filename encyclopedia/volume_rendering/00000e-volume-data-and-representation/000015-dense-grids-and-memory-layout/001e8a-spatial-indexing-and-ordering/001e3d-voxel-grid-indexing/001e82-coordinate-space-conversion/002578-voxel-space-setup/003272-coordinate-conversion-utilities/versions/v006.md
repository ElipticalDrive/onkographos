# Coordinate Conversion Utilities

Also called: Voxel to World Transform, World-to-Voxel Coordinate Conversion, Voxel Coordinate Conversion, LocalToVoxel, VoxelToLocal

## Overview
Coordinate Conversion Utilities provide the bidirectional mapping between continuous world-space positions and discrete voxel grid indices, serving as the fundamental interface between geometric reasoning and volumetric data access [S1, S2, S3, unofficial]. While [Voxel Space Setup](3520-voxel-space-setup.md) establishes the bounding box and transformation matrices, these utilities perform the actual arithmetic to translate a point in space into a specific cell index and vice versa [S1, S2, S3, unofficial]. They differ from [Spherical Voxel Grid Setup](3883-spherical-voxel-grid-setup.md) by operating on Cartesian grids rather than spherical shells, and from [Incremental Back-Rotation for Voxel Mapping](6759-incremental-back-rotation-for-voxel-mapping.md) by handling static linear transformations rather than iterative rotational adjustments.

## How it works
The method encompasses several distinct conversion paths depending on the coordinate system (global vs. local, chunked vs. flat) and the target representation (Cartesian vs. cylindrical).

### Inputs and Outputs
*   **World-to-Voxel:** Input is a continuous 3D vector $(x, y, z)$ in world units. Output is a discrete integer voxel index $(i, j, k)$ or a local position within a chunk.
*   **Voxel-to-World:** Input is a discrete integer voxel index $(i, j, k)$ or a local chunk-relative position. Output is a continuous 3D vector $(x, y, z)$ representing the world-space center or corner of the voxel.

### Data Structures
*   **Voxel Grid Parameters:**
    *   `world_scale`: The size of one voxel in world units (e.g., meters per voxel).
    *   `world_position`: The world-space origin or center offset of the voxel grid.
    *   `center`: The grid center offset, often defined as $(VOXELS_X/2, VOXELS_Y/2, 0)$ for specific display setups [S1, unofficial].
*   **Chunked Grid Parameters (if applicable):**
    *   `ChunkSize`: The dimension of a chunk in voxels (e.g., $16 \times 16 \times 16$).
    *   `ChunkCoord`: The integer coordinates of the chunk in the global chunk grid.
    *   `LocalPos`: The integer coordinates of the voxel within the chunk $(0 \dots ChunkSize-1)$.

### Formulas and Steps

#### 1. Global Voxel to World (Cartesian)
Converts a global voxel index to its world-space center.
$$
position[i] = \left( \frac{voxel[i] - center[i]}{world\_scale} \right) + world\_position[i]
$$
Where:
*   $voxel[i]$ is the voxel index along axis $i$ ($x, y, z$).
*   $center[i]$ is the grid center offset. For some implementations, $center[0] = VOXELS\_X/2$, $center[1] = VOXELS\_Y/2$, $center[2] = 0$ [S1, unofficial].
*   $world\_scale$ is the voxel size in world units.
*   $world\_position[i]$ is the world-space origin offset [S1, unofficial].

#### 2. World to Global Voxel
Converts a world-space position to a global voxel index.
$$
voxel[i] = \lfloor (world\_position[i] - world\_origin[i]) \times world\_scale \rfloor
$$
*Note: The exact formula depends on whether `world_position` represents the origin or the center. If it represents the center, the offset must be adjusted accordingly [S3, S1, unofficial].*

#### 3. Chunked Coordinate Conversion
For large worlds divided into chunks, conversion involves two stages: determining the chunk and the local position within it.

**World to Chunk/Local:**
1.  Calculate global voxel coordinates:
    $$
    VoxelCoord = \lfloor (WorldPos - WorldOrigin) \times WorldScale \rfloor
    $$
2.  Calculate Chunk Coordinates:
    $$
    ChunkCoord = \lfloor VoxelCoord / ChunkSize \rfloor
    $$
3.  Calculate Local Voxel Coordinates:
    $$
    Local.X = VoxelCoord.X \pmod{ChunkSize}
    $$
    $$
    Local.Y = VoxelCoord.Y \pmod{ChunkSize}
    $$
    $$
    Local.Z = VoxelCoord.Z \pmod{ChunkSize}
    $$
4.  Handle Negative Coordinates:
    If $Local.X < 0$, add $ChunkSize$ to $Local.X$. Repeat for $Y$ and $Z$ [S3, unofficial].

**Local/Chunk to World:**
1.  Calculate Global Voxel Coordinate:
    $$
    GlobalVoxel = ChunkCoord \times ChunkSize + LocalPos
    $$
2.  Calculate World Position (Voxel Center):
    $$
    WorldPos = (ChunkOrigin + LocalPos + 0.5) \times VoxelSize
    $$
    Where $ChunkOrigin$ is the world-space minimum corner of the chunk [S3, unofficial].

### Pseudocode

```python
def world_to_voxel(world_pos, world_origin, world_scale):
    """
    Converts a world-space position to a global voxel index.
    world_pos: tuple (x, y, z)
    world_origin: tuple (x, y, z)
    world_scale: float (voxels per world unit)
    """
    # Calculate relative position
    rel_x = (world_pos[0] - world_origin[0]) * world_scale
    rel_y = (world_pos[1] - world_origin[1]) * world_scale
    rel_z = (world_pos[2] - world_origin[2]) * world_scale
    
    # Floor to get integer voxel index
    voxel_x = int(rel_x) if rel_x >= 0 else int(rel_x) - 1
    voxel_y = int(rel_y) if rel_y >= 0 else int(rel_y) - 1
    voxel_z = int(rel_z) if rel_z >= 0 else int(rel_z) - 1
    
    return (voxel_x, voxel_y, voxel_z)

def voxel_to_world(voxel_pos, world_origin, world_scale, center_offset=None):
    """
    Converts a global voxel index to a world-space position.
    voxel_pos: tuple (x, y, z)
    world_origin: tuple (x, y, z)
    world_scale: float (voxels per world unit)
    center_offset: tuple (x, y, z) or None. If provided, adjusts for grid centering [S1, unofficial].
    """
    if center_offset is None:
        center_offset = (0, 0, 0)
        
    # Apply center offset and scale
    # Formula: pos = ((voxel - center) / scale) + world_position
    # Note: world_scale in sources is often "voxels per unit" or "unit per voxel".
    # If world_scale is "unit per voxel" (size), we divide by it.
    # If world_scale is "voxels per unit" (density), we multiply by it.
    # Based on S1: position = ((voxel - center) / world_scale) + world_position
    # This implies world_scale is a divisor, likely "voxels per unit" or a scaling factor.
    # However, standard practice is VoxelSize. Let's assume world_scale is VoxelSize for clarity,
    # but adhere to S1's structure.
    
    # Re-interpreting S1: "world_scale" acts as a divisor.
    # If world_scale is 1.0 (1 unit = 1 voxel), then pos = voxel - center + origin.
    
    x = ((voxel_pos[0] - center_offset[0]) / world_scale) + world_origin[0]
    y = ((voxel_pos[1] - center_offset[1]) / world_scale) + world_origin[1]
    z = ((voxel_pos[2] - center_offset[2]) / world_scale) + world_origin[2]
    
    return (x, y, z)

def world_to_chunk(world_pos, world_origin, world_scale, chunk_size):
    """
    Converts world position to chunk coordinates and local voxel position.
    """
    # 1. Get global voxel
    voxel = world_to_voxel(world_pos, world_origin, world_scale)
    
    # 2. Get chunk coord
    chunk_x = voxel[0] // chunk_size
    chunk_y = voxel[1] // chunk_size
    chunk_z = voxel[2] // chunk_size
    
    # 3. Get local voxel
    local_x = voxel[0] % chunk_size
    local_y = voxel[1] % chunk_size
    local_z = voxel[2] % chunk_size
    
    # 4. Handle negative modulo
    if local_x < 0: local_x += chunk_size
    if local_y < 0: local_y += chunk_size
    if local_z < 0: local_z += chunk_size
    
    return (chunk_x, chunk_y, chunk_z), (local_x, local_y, local_z)

def chunk_local_to_world(chunk_coord, local_pos, world_origin, world_scale, chunk_size, center_offset=None):
    """
    Converts chunk coordinate and local voxel position to world space.
    """
    # 1. Reconstruct global voxel
    global_x = chunk_coord[0] * chunk_size + local_pos[0]
    global_y = chunk_coord[1] * chunk_size + local_pos[1]
    global_z = chunk_coord[2] * chunk_size + local_pos[2]
    
    # 2. Convert to world
    return voxel_to_world((global_x, global_y, global_z), world_origin, world_scale, center_offset)
```

### Edge Cases and Pitfalls
*   **Negative Coordinates:** Modulo operations on negative numbers vary by language. In C++/Python, `%` can return negative results. The algorithm must explicitly add `ChunkSize` if the result is negative [S3, unofficial].
*   **Precision Loss:** Converting large world coordinates to voxel indices and back can lose sub-voxel precision. Use floating-point arithmetic for intermediate steps [S3, unofficial].
*   **Boundary Conditions:** Voxels on the edge of the grid may map to world positions outside the intended bounding box if `world_position` is not carefully defined as the origin or center [S1, unofficial].

## Subtopics

### [Sliced Volume Coordinate Mapping](8287-sliced-volume-coordinate-mapping.md)
Sliced Volume Coordinate Mapping converts 3D voxel coordinates into 2D texture coordinates for volumetric data stored as a tiled grid of 2D slices within a single 2D image. This technique enables GPU texture sampling of 3D data using standard 2D texture units, which is necessary when hardware 3D texture support is unavailable or inefficient. It differs from standard 3D texture sampling by flattening the volume into a 2D grid of slices, requiring specific coordinate mapping logic to resolve 3D coordinates to 2D image pixels.

### [Metric Coordinate Conversion](12960-metric-coordinate-conversion.md)
Metric Coordinate Conversion decomposes a continuous world-space position into a discrete integer meter component and a continuous fractional meter component. This method solves the problem of separating large-scale spatial indexing (handled by whole meters) from high-precision local sampling (handled by fractional meters). It differs from [Sliced Volume Coordinate Mapping](8287-sliced-volume-coordinate-mapping.md) by operating on absolute world coordinates rather than slice-relative indices, and from [Voxel Index Computation](11238-voxel-index-computation.md) by preserving sub-meter precision rather than truncating to voxel indices.

### Adaptive Coordinate Conversion
A technique used by Lim et al. to visualize 3D ultrasound datasets, where points within the native pyramidal ultrasound coordinate system were adaptively converted on the fly to a Cartesian grid [S4].

### Coordinate System Bit Encoding
A method for determining axis alignment and rotation requirements between two coordinate systems using bit manipulation.
*   **Layout:** `CoordinateSystem` is a `uint32_t` enum with 16 valid values (1-16) representing axis directions. Bit 0: Left(0)/Right(1). Bit 1: Down(0)/Up(1). Bit 2: Back(0)/Front(1). Value 0 is UNSPECIFIED. Examples: LDB=1, RDB=2, LUB=3, RUB=4, LDF=5, RDF=6, LUF=7, RUF=8, LFD=9, RFD=10, LFU=11, RFU=12, LBD=13, RBD=14, LBU=15, RBU=16 [S5, unofficial].
*   **Steps:**
    1.  `axesMatch(a, b)`: Converts enums to 0-based indices ($aNum = a-1, bNum = b-1$). If either is UNSPECIFIED (<0), returns `{true, true, true}`. Otherwise, compares bit $i$ of $aNum$ and $bNum$ for $i=0,1,2$. Returns a 3-element bool array indicating match per axis [S5, unofficial].
    2.  `needRotation(a, b)`: Checks if a $\pm \pi/2$ rotation is required by comparing bit 3 of the 0-based indices. If either is UNSPECIFIED, returns false. Otherwise, returns true if bit 3 differs [S5, unofficial].

### Coordinate System Conversion
Conversion of normalized Cartesian data $(x, y, z, r, g, b)$ to system coordinates $(h, w, \theta, r, g, b)$ for swept-volume display [S6].
*   **Step 1:** Convert data from Descartes coordinates to cylindrical coordinates with the form $(\theta, \rho, z, r, g, b)$.
*   **Step 2:** Convert data from cylindrical coordinates to system coordinates with the form $(h, w, \theta, r, g, b)$ [S6].

## Operating characteristics
*   **Time Complexity:** $O(1)$ for basic voxel-to-world and world-to-voxel conversions. Chunked conversions are also $O(1)$ but involve additional arithmetic operations.
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Performance:** These operations are extremely fast and are typically executed per-vertex or per-ray step in volume rendering. They are not a bottleneck compared to texture sampling or ray marching.
*   **Strengths:** Simple arithmetic, no complex data structures required.
*   **Limitations:** Does not handle non-linear transformations (e.g., spherical, cylindrical) without additional steps. Precision issues may arise with very large world coordinates.

## Background
Coordinate conversion is a fundamental operation in computer graphics, originating from the need to map between different coordinate spaces (world, view, projection, texture). In the context of voxel grids, it became critical with the rise of voxel-based games and volumetric displays. The specific chunked implementation described in [S3, unofficial] is common in large-scale voxel worlds to manage memory and loading. The adaptive conversion for ultrasound [S4] highlights its use in medical visualization. The bit-encoding method [S5, unofficial] is used in 3D file formats (like SPZ) to handle diverse coordinate system conventions.
