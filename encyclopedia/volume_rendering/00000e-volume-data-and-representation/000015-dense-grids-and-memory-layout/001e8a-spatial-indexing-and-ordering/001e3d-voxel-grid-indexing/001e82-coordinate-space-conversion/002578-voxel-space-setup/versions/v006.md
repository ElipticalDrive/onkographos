# Voxel Space Setup

Also called: AABB to Voxel Grid Mapping, SetupVoxelization

## Overview
Voxel Space Setup computes the bounding box and transformation matrices required to map world-space coordinates to discrete voxel grid indices, handling padding and uniform voxel normalization [S1, unofficial]. It solves the problem of establishing a consistent coordinate system for volume rendering by defining the spatial extent and resolution of the voxel grid relative to the scene's geometry [S1, unofficial]. It differs from [Spherical Voxel Grid Setup](3883-spherical-voxel-grid-setup.md) by operating in a Cartesian coordinate system and from [Incremental Back-Rotation for Voxel Mapping](6759-incremental-back-rotation-for-voxel-mapping.md) by performing static initialization rather than dynamic coordinate transformation.

## How it works
**Inputs:**
- Axis-Aligned Bounding Box (AABB) of the model in world space, defined by `min` and `max` vectors.
- Target grid resolution dimensions: `gridSizeX`, `gridSizeY`, `gridSizeZ` (integers).
- Boolean flag `g_useCubeVoxels`: if true, enforces uniform voxel dimensions across all axes.

**Outputs:**
- `voxelSpace`: Array of two 3D vectors representing the minimum and maximum bounds in voxel space.
- `g_matWorldToVoxel`: 4x4 transformation matrix mapping world coordinates to voxel indices.
- `g_matWorldToVoxelProj`: 4x4 transformation matrix mapping world coordinates to Normalized Device Coordinates (NDC) for projection.
- Stride values for memory layout: `g_strideX`, `g_strideY`, `g_dataSize`.

**Data Structures:**
- `g_aabbModel`: Array of two `float3` vectors, `[0]` is min, `[1]` is max.
- `g_voxelSpace`: Array of two `float3` vectors, `[0]` is min, `[1]` is max.
- `g_matWorldToVoxel`: 4x4 matrix stored as `float4x4`.
- `g_matWorldToVoxelProj`: 4x4 matrix stored as `float4x4`.

**Steps:**

1. **Calculate Memory Strides:**
   Compute the stride for the Z-axis padded to 32-bit words to ensure proper alignment for GPU access.
   $$ g\_strideX = \lceil \frac{g\_gridSizeZ + 31}{32} \rceil $$
   $$ g\_strideY = g\_strideX \times g\_gridSizeX $$
   $$ g\_dataSize = g\_strideY \times g\_gridSizeY $$

2. **Compute Model Extent:**
   Calculate the raw extent of the AABB.
   $$ extent = max - min $$
   Add padding to the extent to prevent edge cases where triangles exactly on the boundary are missed. The padding is 2 units distributed across the grid size.
   $$ extent = extent \times \frac{gridSize + 2}{gridSize} $$
   Where $gridSize$ is a vector $(g\_gridSizeX, g\_gridSizeY, g\_gridSizeZ)$.

3. **Normalize Voxel Dimensions (Optional):**
   If `g_useCubeVoxels` is true, enforce uniform voxel size by taking the maximum component of the extent vector and replicating it to all axes.
   $$ maxDim = \max(extent.x, extent.y, extent.z) $$
   $$ extent = (maxDim, maxDim, maxDim) $$

4. **Compute Center and Voxel Space Bounds:**
   Calculate the center of the original AABB.
   $$ center = \frac{min + max}{2} $$
   Compute the minimum bound in voxel space.
   $$ voxelSpaceMin = center - 0.5 \times extent $$
   Store the min and max bounds in `g_voxelSpace`.
   $$ g\_voxelSpace[0] = voxelSpaceMin $$
   $$ g\_voxelSpace[1] = voxelSpaceMin + extent $$

5. **Compute World-to-Voxel Transformation:**
   Construct the matrix that translates the voxel space minimum to the origin and scales the extent to the grid size.
   $$ g\_matWorldToVoxel = Translate(-voxelSpaceMin) \times Scale(\frac{gridSize}{extent}) $$
   Note: The matrix is typically transposed for column-major storage or specific shader expectations.

6. **Compute World-to-Voxel Projection Transformation:**
   Construct the matrix for NDC projection. This translates the center of the volume to the origin (except Z, which uses `voxelSpaceMin`) and scales to NDC range $[-1, 1]$ for X and Y, and $[0, 1]$ for Z.
   $$ g\_matWorldToVoxelProj = Translate(-center.x, -center.y, -voxelSpaceMin.z) \times Scale(\frac{2.0}{extent.x}, \frac{2.0}{extent.y}, \frac{1.0}{extent.z}, 0.0) $$

**Pseudocode:**

```python
def setup_voxelization(aabb_min, aabb_max, grid_size_x, grid_size_y, grid_size_z, use_cube_voxels):
    # 1. Calculate Memory Strides
    # Pad Z stride to 32-bit words (4 bytes)
    stride_x = (grid_size_z + 31) // 32
    stride_y = stride_x * grid_size_x
    data_size = stride_y * grid_size_y

    # 2. Compute Model Extent
    extent = aabb_max - aabb_min
    
    # Add padding: scale extent by (gridSize + 2) / gridSize
    # This adds 2 units of padding distributed over the grid size
    grid_size_vec = Vector3(grid_size_x, grid_size_y, grid_size_z)
    extent = extent * ((grid_size_vec + 2.0) / grid_size_vec)

    # 3. Normalize Voxel Dimensions
    if use_cube_voxels:
        max_dim = max(extent.x, max(extent.y, extent.z))
        extent = Vector3(max_dim, max_dim, max_dim)

    # 4. Compute Center and Voxel Space Bounds
    center = 0.5 * (aabb_min + aabb_max)
    voxel_space_min = center - 0.5 * extent
    
    voxel_space = [voxel_space_min, voxel_space_min + extent]

    # 5. Compute World-to-Voxel Transformation
    # Translate by -voxelSpaceMin, then Scale by gridSize / extent
    # Matrix multiplication order: Translate * Scale
    mat_world_to_voxel = translate_matrix(-voxel_space_min) * scale_matrix(grid_size_vec / extent)
    
    # 6. Compute World-to-Voxel Projection Transformation
    # Translate by (-center.x, -center.y, -voxelSpaceMin.z)
    # Scale by (2.0/extent.x, 2.0/extent.y, 1.0/extent.z)
    proj_translate = Vector3(-center.x, -center.y, -voxel_space_min.z)
    proj_scale = Vector3(2.0 / extent.x, 2.0 / extent.y, 1.0 / extent.z)
    
    mat_world_to_voxel_proj = translate_matrix(proj_translate) * scale_matrix(proj_scale)

    return {
        'stride_x': stride_x,
        'stride_y': stride_y,
        'data_size': data_size,
        'voxel_space': voxel_space,
        'mat_world_to_voxel': mat_world_to_voxel,
        'mat_world_to_voxel_proj': mat_world_to_voxel_proj
    }
```

**Parameters:**
- `g_useCubeVoxels`: Boolean flag to enforce uniform voxel dimensions across all axes [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Misses:** Grid padding of 2 units is added to the extent to prevent edge cases where triangles exactly on the boundary are missed [S1, unofficial].
- **Zero Extent:** If an axis has zero extent, division by zero may occur during scaling. The source [S5, unofficial] notes that non-positive resolution values or inverted AABBs should be rejected.

## Subtopics

### [Spherical Voxel Grid Setup](3883-spherical-voxel-grid-setup.md)
Spherical Voxel Grid Setup initializes the data structures required for efficient ray casting traversal within a spherical coordinate volume. It computes discretization steps, precomputes trigonometric values, and constructs geometric primitives (line segments) that define voxel boundaries, enabling the `walkSphericalVolume` algorithm to determine ray-voxel intersections. It differs from Cartesian voxel grid setups by operating in an $(r, \theta, \phi)$ coordinate system tailored for egocentric view synthesis, where resolution requirements are anisotropic and radial distances vary significantly.

### [Incremental Back-Rotation for Voxel Mapping](6759-incremental-back-rotation-for-voxel-mapping.md)
Incremental back-rotation is an algorithm used to map destination voxel coordinates to their corresponding source voxel positions during a room rotation operation, specifically to eradicate holes produced by forward rotation. It sets itself apart from forward mapping by iterating over the destination grid and computing source locations, ensuring every destination voxel is filled. This method builds on [Voxel Space Setup](3520-voxel-space-setup.md) by utilizing the established transformation matrices to perform efficient, incremental coordinate calculations.

### [Coordinate Conversion Utilities](6766-coordinate-conversion-utilities.md)
Coordinate Conversion Utilities provide the mathematical primitives for mapping between world-space positions, global voxel indices, and local chunk-relative coordinates in a voxel grid. They solve the problem of addressing data stored in spatially partitioned chunks by translating continuous world coordinates into discrete integer grid indices. Unlike [Spherical Voxel Grid Setup](3883-spherical-voxel-grid-setup.md) which handles angular domains, or [Incremental Back-Rotation for Voxel Mapping](6759-incremental-back-rotation-for-voxel-mapping.md) which handles orientation, these utilities assume an axis-aligned Cartesian grid. They differ from [Voxel Center Precomputation](10731-voxel-center-precomputation.md) by operating on indices rather than pre-calculated floating-point centers, and from [PixelGrid2D Construction](9430-pixelgrid2d-construction.md) by maintaining 3D spatial hierarchy rather than flattening to 2D.

### [PixelGrid2D Construction](9430-pixelgrid2d-construction.md)
PixelGrid2D Construction initializes a 2D grid structure (`Grid2D<BitArray, bool>`) to store voxel occupancy or scalar data projected onto a 2D plane. It solves the problem of mapping a 3D voxel space's bounding box and resolution into a compact 2D memory layout suitable for rendering or processing. It differs from its sibling [Spherical Voxel Grid Setup](3883-spherical-voxel-grid-setup.md) by using a Cartesian bounding box rather than spherical coordinates, and from [Incremental Back-Rotation for Voxel Mapping](6759-incremental-back-rotation-for-voxel-mapping.md) by performing a static initialization rather than dynamic coordinate transformation.

### [Voxel Center Precomputation](10731-voxel-center-precomputation.md)
Precomputes the 3D coordinates of voxel centers for a regular grid defined by origin, size, and dimensions.

### OpenVDB Density Grid Loading
Loads a heterogeneous density field from an OpenVDB file to provide spatial density queries for participating media [S2, unofficial]. It computes the AABB from the active voxel bounding box using `gridPtr->evalActiveVoxelBoundingBox()` and converts indices to world coordinates [S2, unofficial]. Density at a given world position is interpolated using `openvdb::tools::GridSampler` with `openvdb::tools::BoxSampler` [S2, unofficial]. The maximum density is retrieved via `gridPtr->evalMinMax(minValue, maxValue)` [S2, unofficial].

### Ray Tracing Volume Data Setup
Typical simplifications include an integral mapping of voxel address space to pixel address space (1-1 is easiest; usually projection of a voxel map to $k \times k$ pixels); arbitrary mapping requires interpolation [S3, unofficial]. The sampling lattice is rectilinear and uniformly spaced [S3, unofficial]. Pixel spacing must be less than voxel spacing [S3, unofficial]. The method typically uses one ray per pixel (no supersampling) and parallel projection [S3, unofficial].

### Volume Normalization to Unit Cube
Computes the bounding box (bb_min, bb_max) of the volume grid by transforming the grid's corner points (0,0,0) and (index_extent, index_extent, index_extent) using the grid's transform matrix [S4, unofficial]. It calculates the extent vector (bb_max - bb_min) and the maximum dimension size [S4, unofficial]. If size is not 1.0, it constructs a transformation matrix that scales the volume by 1/size and translates it so its center is at the origin (subtracting bb_min + 0.5 * extent) [S4, unofficial]. The density_scale parameter is multiplied by the original size to compensate for the spatial scaling [S4, unofficial].

### Voxel Grid Construction from AABB
Constructs a uniform voxel grid from an Axis-Aligned Bounding Box (AABB) and a target resolution [S5, unofficial]. It ensures uniform voxel size by scaling based on the longest axis and clamping zero-extent axes [S5, unofficial]. Voxel size is calculated as `max(AABB dimensions) / resolution` [S5, unofficial]. Voxel counts for each axis are calculated as `ceil(AABB dimension / voxelSize)` [S5, unofficial]. Non-positive or non-integer resolution values are rejected and throw an error [S5, unofficial]. Inverted AABBs (min > max) are rejected and throw an error [S5, unofficial].

## Operating characteristics
**Time Complexity:**
The setup process is $O(1)$ with respect to the scene complexity, as it only involves arithmetic operations on the AABB and grid dimensions. The memory stride calculation is also $O(1)$.

**Memory Complexity:**
The memory required for the grid is $O(N_x \times N_y \times N_z)$, where $N_x, N_y, N_z$ are the grid dimensions. The padding adds a small constant overhead. The transformation matrices require a fixed amount of memory (2x 4x4 matrices).

**Performance:**
Performance depends on the grid resolution and the hardware capabilities for matrix operations. The padding ensures robustness at the cost of slightly increased memory usage.

**Strengths:**
- Provides a consistent coordinate system for volume rendering.
- Handles padding to prevent boundary artifacts.
- Supports uniform voxel sizes for simpler interpolation.

**Limitations:**
- Cartesian grids may not be optimal for all scene geometries (e.g., spherical objects).
- Fixed resolution may lead to aliasing or excessive memory usage if not chosen carefully.

**When to Use:**
- When rendering volumes with Cartesian symmetry.
- When simplicity and speed of coordinate conversion are prioritized.

**When Not to Use:**
- For scenes with strong spherical symmetry (use [Spherical Voxel Grid Setup](3883-spherical-voxel-grid-setup.md)).
- When memory is extremely constrained and the scene is sparse (consider sparse voxel octrees).

## Background
Voxel Space Setup is a fundamental technique in computer graphics for preparing volume data for rendering. It originates from the need to map continuous world coordinates to discrete voxel indices for efficient access and processing. The method described here, including padding and cube voxel normalization, is commonly found in GPU-based voxelization pipelines [S1, unofficial]. It builds on the principles of coordinate space conversion [1785-coordinate-space-conversion.md] and is a prerequisite for many volume rendering algorithms.
