# Voxel Center Precomputation


## Overview
Precomputes the 3D world coordinates of voxel centers for a regular, axis-aligned voxel grid defined by an origin, dimensions, and physical voxel size. It solves the problem of mapping discrete grid indices to continuous world space coordinates efficiently, avoiding per-lookup computation during rendering or training. It differs from [Incremental Back-Rotation for Voxel Mapping](6759-incremental-back-rotation-for-voxel-mapping.md) by assuming a fixed, non-rotated grid, and from [Coordinate Conversion Utilities](6766-coordinate-conversion-utilities.md) by providing the full 3D tensor of centers rather than generic conversion functions.

## How it works
**Inputs:**
- `grid_origin`: 3D vector `[x_min, y_min, z_min]` representing the scene origin or bounding box minimum [S1, unofficial].
- `voxel_size`: 3D vector `[sx, sy, sz]` representing the physical dimensions of a single voxel [S1, unofficial].
- `grid_dims`: 3D vector `[depth, height, width]` or `[D, H, W]` representing the number of voxels in each dimension [S1, unofficial].

**Outputs:**
- A tensor of shape `(D, H, W, 3)` containing the world coordinates of each voxel center [S1, unofficial].

**Data Structures:**
- The output is a dense 4D tensor where the last dimension holds the `(x, y, z)` coordinates. The first three dimensions correspond to the grid indices `(i, j, k)` for depth, height, and width respectively.

**Steps:**
1. Extract dimensions $D, H, W$ from `grid_dims` [S1, unofficial].
2. Compute the x-coordinates for each column index $w \in [0, W-1]$:
   $$ x_w = \text{grid\_origin}[0] + w \times \text{voxel\_size}[0] + \frac{\text{voxel\_size}[0]}{2} $$
   This creates an array of length $W$ [S1, unofficial].
3. Compute the y-coordinates for each row index $h \in [0, H-1]$:
   $$ y_h = \text{grid\_origin}[1] + h \times \text{voxel\_size}[1] + \frac{\text{voxel\_size}[1]}{2} $$
   This creates an array of length $H$ [S1, unofficial].
4. Compute the z-coordinates for each depth index $d \in [0, D-1]$:
   $$ z_d = \text{grid\_origin}[2] + d \times \text{voxel\_size}[2] + \frac{\text{voxel\_size}[2]}{2} $$
   This creates an array of length $D$ [S1, unofficial].
5. Stack the coordinate arrays into a 3D grid using `meshgrid` with `'ij'` indexing (Cartesian indexing) to produce arrays of shape `(D, H, W)` for x, y, and z respectively [S1, unofficial].
6. Concatenate the x, y, and z arrays along the last dimension to form the final tensor of shape `(D, H, W, 3)` [S1, unofficial].

**Pseudocode:**
```python
import numpy as np

def precompute_voxel_centers(grid_origin, voxel_size, grid_dims):
    """
    Precomputes the 3D coordinates of voxel centers for a regular grid.
    
    Args:
        grid_origin (array-like): [x_min, y_min, z_min]
        voxel_size (array-like): [sx, sy, sz]
        grid_dims (array-like): [depth, height, width]
        
    Returns:
        numpy.ndarray: Tensor of shape (D, H, W, 3) with voxel center coordinates.
    """
    # Extract dimensions
    D, H, W = grid_dims
    
    # Extract origin and size components
    ox, oy, oz = grid_origin
    sx, sy, sz = voxel_size
    
    # Compute coordinate arrays
    # x coordinates: origin[0] + index * size[0] + size[0]/2
    x_coords = ox + np.arange(W) * sx + sx / 2.0
    
    # y coordinates: origin[1] + index * size[1] + size[1]/2
    y_coords = oy + np.arange(H) * sy + sy / 2.0
    
    # z coordinates: origin[2] + index * size[2] + size[2]/2
    z_coords = oz + np.arange(D) * sz + sz / 2.0
    
    # Create meshgrid with 'ij' indexing (Cartesian)
    # This produces arrays of shape (D, H, W)
    X, Y, Z = np.meshgrid(x_coords, y_coords, z_coords, indexing='ij')
    
    # Stack into (D, H, W, 3)
    voxel_centers = np.stack((X, Y, Z), axis=-1)
    
    return voxel_centers
```

**Parameters:**
- `grid_origin`: Scene origin coordinates. Typical values depend on the scene normalization (e.g., centered at 0 or aligned to dataset bounds) [S1, unofficial].
- `voxel_size`: Physical size of a single voxel. Determined by the desired resolution and bounding box size [S1, unofficial].
- `grid_dims`: Voxel grid dimensions `[depth, height, width]`. Must match the resolution of the volume grid used for rendering [S1, unofficial].

**Edge Cases and Pitfalls:**
- The formula assumes the voxel center is offset by half the voxel size from the grid origin. If the grid origin represents the center of the first voxel, the offset should be 0. The sources specify the `+ voxel_size/2` offset, implying `grid_origin` is the corner of the first voxel [S1, unofficial].
- Precision issues may arise if `grid_origin` and `voxel_size` have vastly different magnitudes. Using floating-point arithmetic (float32 or float64) is recommended [S1, unofficial].
- The order of dimensions in `grid_dims` is `[depth, height, width]`, which corresponds to `[z, y, x]` in standard Cartesian coordinates if `grid_origin` is `[x_min, y_min, z_min]`. This must be consistent with the meshgrid indexing [S1, unofficial].

## Subtopics

### Voxel Center Computation from Indices
Computes the 3D coordinates of voxel centers given their discrete indices, bounding boxes, and voxel sizes, primarily used in batched or sparse contexts [S2, unofficial]. It differs from the standard precomputation by operating on specific indices rather than the full grid and supporting batched bounding boxes [S2, unofficial]. Choose this when working with sparse voxel representations or batched inference where only a subset of voxels are active [S2, unofficial].

**Definition:** Computes the 3D coordinates of voxel centers given their discrete indices, bounding boxes, and voxel sizes [S2, unofficial].

**Steps:**
1. Select the minimum bounding box coordinate for each voxel: `bb_mins = bounding_boxes[batch_ids][:, 0]` [S2, unofficial].
2. Retrieve the voxel size for each voxel, handling scalar/tensor inputs similarly to index computation [S2, unofficial].
3. If `shift` is true and `cat_batch_ids` is true, compute centers as:
   $$ \text{centers} = \text{voxel\_indices}[:, 1:] \times \text{voxel\_size\_b} + \text{bb\_mins} $$
   [S2, unofficial].
4. If `shift` is false and `cat_batch_ids` is true, compute centers as:
   $$ \text{centers} = \text{voxel\_indices}[:, 1:] \times \text{voxel\_size\_b} + \text{bb\_mins} + 0.5 \times \text{voxel\_size\_b} $$
   [S2, unofficial].

**Pitfalls:**
- The function raises `NotImplementedError` if `cat_batch_ids` is false, as only cases with batch IDs concatenated are supported [S2, unofficial].
- The `shift` parameter controls whether the 0.5 voxel offset is applied. This must be consistent with the coordinate system definition (corner vs. center origin) [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(D \times H \times W)$ to generate the full grid. The computation is vectorized and efficient on modern hardware [S1, unofficial].
- **Memory Complexity:** $O(D \times H \times W \times 3)$ to store the center coordinates. For high-resolution grids, this can be significant. Precomputing avoids repeated calculation during rendering [S1, unofficial].
- **Performance:** The operation is typically performed once during initialization. The cost is negligible compared to the rendering loop [S1, unofficial].
- **Strengths:** Simple, deterministic, and fast for regular grids. Provides direct access to world coordinates for any grid index [S1, unofficial].
- **Limitations:** Only applicable to regular, axis-aligned grids. Does not support rotated or irregular voxel structures [S1, unofficial].
- **When to use:** When rendering or training on a fixed, dense voxel grid where world coordinates are needed for each voxel [S1, unofficial].
- **When not to use:** For sparse voxels, rotated grids, or when memory is constrained and on-the-fly computation is preferred [S1, unofficial].

## Background
Originated in the context of 3D Gaussian Splatting and volume rendering implementations, specifically within the AVM-GS framework [S1, unofficial]. It is a fundamental utility for mapping between discrete grid indices and continuous world space, enabling efficient ray-voxel intersection and attribute lookup [S1, unofficial]. The method is standard in dense grid-based volume representations [S1, unofficial].
