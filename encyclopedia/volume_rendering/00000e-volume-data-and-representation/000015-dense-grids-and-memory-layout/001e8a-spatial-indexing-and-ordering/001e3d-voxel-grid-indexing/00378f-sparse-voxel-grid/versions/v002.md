# Sparse Voxel Grid


## Overview
A sparse voxel grid is a volume representation that stores only non-zero elements as a list of coordinates and corresponding data to reduce memory usage compared to dense grids [S1, unofficial]. It differs from its sibling [Uniform Grid Indexing](6941-uniform-grid-indexing.md) by avoiding storage of empty space, but requires accelerated data structures for efficient querying [S1, unofficial].

## How it works
**Inputs:** A list of non-zero voxel entries, where each entry contains a 3D coordinate $(x, y, z)$ and associated attribute data [S1, unofficial].
**Outputs:** The attribute data for a queried coordinate, or a signal indicating the voxel is empty [G].
**Data Structures:** The core representation is a list of coordinate-data tuples. Query acceleration uses either a hierarchical tree (e.g., a KD-tree or an octree with 8 children per node) or a hash table mapping coordinates to data values [S1, unofficial].
**Querying Steps:**
1. Given a target coordinate $P = (x, y, z)$, initiate a search.
2. If using a linear list, iterate through all elements and compare coordinates to $P$ [S1, unofficial].
3. If using a tree, traverse from the root to the appropriate leaf based on spatial subdivision [S1, unofficial].
4. If using a hash table, compute the hash of $P$ and retrieve the stored value [S1, unofficial].
5. If a matching coordinate is found, return its data; otherwise, the voxel is empty [S1, unofficial].

**Parameters:** Resolution is not explicitly defined for the sparse grid itself, as it adapts to the data distribution [S1, unofficial]. Data types depend on the application (e.g., float for SDF, uint8 for material indices) [G].
**Edge Cases and Pitfalls:** Naive iteration over the list has $O(N)$ time complexity, which is inefficient for large datasets [S1, unofficial]. Accelerated structures are required for practical use [S1, unofficial].

## Subtopics

### Sparse Volume Data Storage
A storage strategy for volume data that keeps sampled data in separate cells and discards SDFs after Hermite data construction to allow parallel modifications, extractions, and culling [S2]. Material indices are stored in a one-dimensional typed array of 8-bit unsigned integers (`uint8`) [S2]. Edge data is stored in typed arrays simulating a hash map, split into three groups (edges, zero crossings, normals), each further split into three arrays for the X, Y, and Z axes [S2]. Edges are stored as starting grid point indices in ascending order [S2]. Zero crossing values are stored in order corresponding to the edges [S2]. Normal vectors are stored as $(x, y, z)$ floating point triples, also corresponding to the edge order [S2]. The flattened index for a grid point at coordinates $(x, y, z)$ with resolution $n$ is calculated as $index = z \times (n+1)^2 + y \times (n+1) + x$ [S2]. Given a starting point index $a$, the ending point index $b$ is $a+1$ for the X-axis, $a+(n+1)$ for the Y-axis, and $a+(n+1)^2$ for the Z-axis [S2]. The grid resolution $n$ is an integer from 1 to 256 [S2].

### Weight-sharing Voxel Representation
A voxel representation where weights are shared across different spatial scales to reduce memory usage and enhance performance [S3]. It reduces model size compared to maintaining independent voxels for each scale [S3].

## Operating characteristics
Query time depends on the acceleration structure: $O(1)$ average for hash tables, $O(\log N)$ for trees, and $O(N)$ for linear lists [S1, unofficial]. Memory complexity is proportional to the number of non-zero voxels, significantly less than dense grids for sparse scenes [S1, unofficial]. Strengths include efficient memory usage for sparse data and support for high resolution without proportional memory cost [S1, unofficial]. Limitations include more complex querying than dense grids and the requirement for additional acceleration data structures [S1, unofficial]. It should be used when volume data is sparse or contains large empty regions [S1, unofficial]. It should not be used when the volume is dense, as the overhead of the acceleration structure may outweigh memory savings [G].

## Background
The concept is used to increase the resolution of voxel grids by harnessing the sparsity of 3D space [S1, unofficial]. It is a fundamental component in methods like Neural Sparse Voxel Fields, which propose learning sparse voxel grids in a progressive manner [S1, unofficial]. The term is often associated with octrees, which serve as a variant using a tree structure for search [S1, unofficial].
