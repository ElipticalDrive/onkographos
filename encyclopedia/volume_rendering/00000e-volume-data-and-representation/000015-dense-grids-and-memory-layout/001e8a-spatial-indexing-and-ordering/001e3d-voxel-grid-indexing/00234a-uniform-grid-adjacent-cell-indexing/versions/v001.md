# Uniform Grid Adjacent Cell Indexing

Also called: Adjacent Cell Indexing, Edge Neighbor Indexing

## Overview
Uniform Grid Adjacent Cell Indexing computes the linear memory indices of the four cells sharing a specific grid edge in a uniform voxel grid. It solves the problem of efficiently locating neighboring cells for operations such as multi-material interface definition or gradient estimation without traversing a graph structure. It differs from its parent, [Voxel Grid Indexing](1719-voxel-grid-indexing.md), which provides general coordinate-to-index mapping, by specifically resolving the topology of edge-adjacent neighbors using pointer arithmetic based on edge orientation [S1, unofficial]. It differs from [Multi-Material Cell Map Indexing & Access](4886-multi-material-cell-map-indexing-access.md) by computing raw linear indices rather than material-specific pointers.

## How it works
**Inputs:**
- `edgePos`: A 3D integer coordinate representing the position of the edge center or a reference point on the edge.
- `edgeType`: An integer identifier (0, 1, or 2) indicating the axis parallel to the edge.
- `m_size`: The dimension of the grid (assumed cubic, $N \times N \times N$).
- `m_halfSize`: Half the grid dimension, used for boundary checks.
- `kBadIndex`: A sentinel value (e.g., -1) indicating a non-existent neighbor.

**Outputs:**
- `cells`: An array of 4 integers containing the linear indices of the adjacent cells.

**Data Structures:**
- Linear indexing assumes row-major order (Z is fastest changing, then Y, then X). The stride for Y is $S_y = (m\_size + 1)$ and for Z is $S_z = 1$. Note: The source formulas use $(m\_size + 1)$ as the Y-stride, implying the grid includes boundary faces or a specific padding scheme where the dimension is effectively $m\_size + 1$ in the indexing space [S1, unofficial].

**Formulas:**
Let $dy = (m\_size + 1) \times (m\_size + 1)$ and $dz = 1$.
The base index is $idx = \text{pointToIndex}(edgePos)$.

For **Edge Type 0** (parallel to X axis):
$$
\begin{aligned}
cells[2] &= idx \\
cells[0] &= idx - dy - dz \\
cells[1] &= idx - dz \\
cells[3] &= idx - dy
\end{aligned}
$$

For **Edge Type 1** (parallel to Y axis):
Let $dx = (m\_size + 1)$ and $dz = 1$.
$$
\begin{aligned}
cells[2] &= idx \\
cells[0] &= idx - dx - dz \\
cells[1] &= idx - dx \\
cells[3] &= idx - dz
\end{aligned}
$$

For **Edge Type 2** (parallel to Z axis):
Let $dx = (m\_size + 1)$ and $dy = (m\_size + 1) \times (m\_size + 1)$.
$$
\begin{aligned}
cells[2] &= idx \\
cells[0] &= idx - dx - dy \\
cells[1] &= idx - dy \\
cells[3] &= idx - dx
\end{aligned}
$$

**Steps:**
1. Determine the stride constants ($dx, dy, dz$) based on `edgeType`.
2. Compute the linear index of the reference point on the edge using `pointToIndex`.
3. Apply the subtraction offsets defined by the edge type to compute the four neighbor indices.
4. Validate each computed index against the grid boundaries. If an index falls outside the valid range, replace it with `kBadIndex`.

**Pitfalls:**
- **Boundary Conditions:** Accessing cells outside the grid must return `kBadIndex`. For Edge Type 0 (X-parallel), invalid neighbors occur at specific Y and Z boundaries:
    - If $edgePos.y == -m\_halfSize$, `cells[0]` and `cells[3]` are invalid.
    - If $edgePos.y == m\_halfSize$, `cells[1]` and `cells[2]` are invalid.
    - If $edgePos.z == -m\_halfSize$, `cells[0]` and `cells[1]` are invalid.
    - If $edgePos.z == m\_halfSize$, `cells[2]` and `cells[3]` are invalid [S1, unofficial].
- **Indexing Assumption:** The use of $(m\_size + 1)$ as a stride suggests the grid indexing space includes boundary nodes or faces, distinct from standard $0 \dots N-1$ cell indexing. Implementers must ensure `pointToIndex` uses the same stride convention.

**Pseudocode:**
```python
def get_adjacent_cells(edge_pos, edge_type, m_size, m_half_size, k_bad_index):
    """
    Computes linear indices of 4 cells adjacent to an edge in a uniform grid.
    edge_pos: tuple (x, y, z)
    edge_type: 0 (X-parallel), 1 (Y-parallel), 2 (Z-parallel)
    """
    # Helper to convert 3D pos to linear index
    # Based on source formulas, stride_y = (m_size + 1)^2, stride_z = 1
    # This implies a grid dimension of (m_size + 1) in each axis for indexing purposes
    def point_to_index(pos):
        x, y, z = pos
        stride_y = (m_size + 1) * (m_size + 1)
        stride_z = 1
        return x * stride_y + y * stride_z + z

    idx = point_to_index(edge_pos)
    cells = [0, 0, 0, 0]

    if edge_type == 0:  # Parallel to X
        dy = (m_size + 1) * (m_size + 1)
        dz = 1
        cells[2] = idx
        cells[0] = idx - dy - dz
        cells[1] = idx - dz
        cells[3] = idx - dy
        
        # Boundary checks for Type 0
        if edge_pos[1] == -m_half_size:
            cells[0] = k_bad_index
            cells[3] = k_bad_index
        if edge_pos[1] == m_half_size:
            cells[1] = k_bad_index
            cells[2] = k_bad_index
        if edge_pos[2] == -m_half_size:
            cells[0] = k_bad_index
            cells[1] = k_bad_index
        if edge_pos[2] == m_half_size:
            cells[2] = k_bad_index
            cells[3] = k_bad_index

    elif edge_type == 1:  # Parallel to Y
        dx = (m_size + 1)
        dz = 1
        cells[2] = idx
        cells[0] = idx - dx - dz
        cells[1] = idx - dx
        cells[3] = idx - dz
        
        # Boundary checks for Type 1 (inferred from symmetry and source structure)
        # Source explicitly lists Type 0 checks. Type 1/2 checks follow similar logic
        # relative to their perpendicular axes.
        # For Y-parallel edge at (x, y, z):
        # Neighbors are offset in X and Z.
        # Invalid if x or z is on boundary.
        if edge_pos[0] == -m_half_size:
            cells[0] = k_bad_index
            cells[3] = k_bad_index
        if edge_pos[0] == m_half_size:
            cells[1] = k_bad_index
            cells[2] = k_bad_index
        if edge_pos[2] == -m_half_size:
            cells[0] = k_bad_index
            cells[1] = k_bad_index
        if edge_pos[2] == m_half_size:
            cells[2] = k_bad_index
            cells[3] = k_bad_index

    elif edge_type == 2:  # Parallel to Z
        dx = (m_size + 1)
        dy = (m_size + 1) * (m_size + 1)
        cells[2] = idx
        cells[0] = idx - dx - dy
        cells[1] = idx - dy
        cells[3] = idx - dx
        
        # Boundary checks for Type 2
        if edge_pos[0] == -m_half_size:
            cells[0] = k_bad_index
            cells[3] = k_bad_index
        if edge_pos[0] == m_half_size:
            cells[1] = k_bad_index
            cells[2] = k_bad_index
        if edge_pos[1] == -m_half_size:
            cells[0] = k_bad_index
            cells[1] = k_bad_index
        if edge_pos[1] == m_half_size:
            cells[2] = k_bad_index
            cells[3] = k_bad_index

    return cells
```

## Subtopics

### [Multi-Material Quad Vertex Index Mapping](4910-multi-material-quad-vertex-index-mapping.md)
Multi-Material Quad Vertex Index Mapping (MMQVIM) is a method for generating quadrilateral primitives from voxel data by mapping specific cell edge configurations to vertex indices. It solves the problem of defining the geometry of multi-material interfaces in a uniform grid by determining the four vertices of a quad based on the material flags at the corners of a cell edge. It differs from its parent, [Uniform Grid Adjacent Cell Indexing](2992-uniform-grid-adjacent-cell-indexing.md), which computes linear indices for adjacent cells, by specifically resolving the vertex connectivity for a quadrilateral face using pointer arithmetic on a cell array [4910-multi-material-quad-vertex-index-mapping.md].

### Uniform Grid Boundary Checks
Uniform Grid Boundary Checks provide utility functions to validate whether a face or cell position lies within the grid bounds or on the boundary. `isFaceInGrid` checks if a face is inside the grid; for face type 0 (normal X), this requires $|facePos.x| \le m\_halfSize$ and $-m\_halfSize \le facePos.y < m\_halfSize$, $-m\_halfSize \le facePos.z < m\_halfSize$. `isFaceOnBorder` checks if a face is on the boundary; for face type 0, true if $|facePos.x| == m\_halfSize$. `isCellInGrid` returns false if any coordinate is $< -m\_halfSize$ or $\ge m\_halfSize$. `isCellOnBorder` returns true if any coordinate is $-m\_halfSize$ or $m\_halfSize - 1$ [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ for index computation. Boundary checks are also $O(1)$.
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Performance:** Extremely fast due to simple arithmetic. No memory allocation or traversal required.
- **Strengths:** Deterministic, branch-predictable (if boundary checks are optimized), suitable for GPU shaders or tight loops.
- **Limitations:** Requires careful handling of boundary conditions to avoid out-of-bounds memory access. Relies on a specific grid indexing convention (stride of $m\_size+1$).

## Background
This method originates from the `isomesh` project by Svenny, which implements efficient isosurface extraction and multi-material mesh generation from voxel data [S1, unofficial]. It is designed for uniform grids where topological relationships are implicit in the memory layout.
