# Multi-Material Quad Vertex Index Mapping

Also called: Edge-based Quad Indexing, MMCellFlag Edge Mapping

## Overview
Multi-Material Quad Vertex Index Mapping (MMQVIM) is a method for generating quadrilateral primitives from voxel data by mapping specific cell edge configurations to vertex indices. It solves the problem of defining the geometry of multi-material interfaces in a uniform grid by determining the four vertices of a quad based on the material flags at the corners of a cell edge. It differs from its parent, [Uniform Grid Adjacent Cell Indexing](2992-uniform-grid-adjacent-cell-indexing.md), which computes linear indices for adjacent cells, by specifically resolving the vertex connectivity for a quadrilateral face using pointer arithmetic on a cell array.

## How it works
**Inputs and Outputs:**
*   **Input:** A pointer to the current cell (`pCell`), the current cell's vertex index, the grid dimensions (`length`, `area`), and an edge type identifier (one of 12 defined edge types).
*   **Output:** A 4-element array `quadVtxIndices` containing the vertex indices for the quadrilateral.

**Data Structures:**
*   `pCell`: A pointer to a cell structure containing at least a `vertexIndex` field.
*   `length`: The number of cells along the X-axis (or primary stride).
*   `area`: The number of cells along the Y-axis (or secondary stride), typically `length * height` or similar grid dimension product.
*   `quadVtxIndices`: An array of 4 integers representing vertex indices.

**Edge Types:**
The method handles 12 specific edge types:
1.  `LeftBottomEdge`
2.  `RightBottomEdge`
3.  `BackBottomEdge`
4.  `FrontBottomEdge`
5.  `LeftTopEdge`
6.  `RightTopEdge`
7.  `BackTopEdge`
8.  `FrontTopEdge`
9.  `LeftBackEdge`
10. `RightBackEdge`
11. `LeftFrontEdge`
12. `RightFrontEdge`

**Algorithm:**
The core logic uses pointer arithmetic to compute the indices of the three adjacent vertices based on the current cell's position and the specific edge type. The first vertex index is always the current cell's vertex index. The remaining three are computed by adding or subtracting offsets (`1`, `area`, `length`) to the current cell's base index or pointer.

```python
        quad_vtx_indices[2] = p_cell_vertex_index - area

        quad_vtx_indices[1] = p_cell_vertex_index - length

        quad_vtx_indices[3] = p_cell_vertex_index + length - area

        quad_vtx_indices[1] = p_cell_vertex_index + length
        quad_vtx_indices[2] = p_cell_vertex_index + area
        quad_vtx_indices[3] = p_cell_vertex_index + length + area
        
    elif edge_type == "LeftBackEdge":
        quad_vtx_indices[1] = p_cell_vertex_index - 1
        quad_vtx_indices[2] = p_cell_vertex_index - area
        quad_vtx_indices[3] = p_cell_vertex_index - 1 - area
        
    elif edge_type == "RightBackEdge":
        quad_vtx_indices[1] = p_cell_vertex_index + 1
        quad_vtx_indices[2] = p_cell_vertex_index - area
        quad_vtx_indices[3] = p_cell_vertex_index + 1 - area

        quad_vtx_indices[1] = p_cell_vertex_index - 1
        quad_vtx_indices[2] = p_cell_vertex_index + area
        quad_vtx_indices[3] = p_cell_vertex_index - 1 + area

        quad_vtx_indices[1] = p_cell_vertex_index + 1
        quad_vtx_indices[2] = p_cell_vertex_index + area
        quad_vtx_indices[3] = p_cell_vertex_index + 1 + area
        
    else:
        # Pitfall: Unrecognized edge type degenerates to zero-area quad
        quad_vtx_indices[1] = p_cell_vertex_index

```

**Parameters:**
*   `length`: Grid width in cells.
*   `area`: Grid depth * width (or similar 2D stride) in cells.
*   Typical values depend on the grid resolution.

**Edge Cases and Pitfalls:**
*   **Unrecognized Edge Type:** If an edge type not in the 12 defined types is passed, the method degenerates to a zero-area quad by setting all four indices to the current cell's vertex index [S1, unofficial].
*   **Boundary Conditions:** The source notes that the parent method handles boundaries by returning `kBadIndex`. This method relies on pointer arithmetic, so boundary checks must be performed before calling this mapping or the offsets must account for wrapping/clamping, though the source does not explicitly detail boundary handling within this specific function [S1, unofficial].

## Subtopics

### Chunkless Indexing
Eliminates per-chunk index data by using one shared quad buffer for the entire world mesh, reducing index data per chunk to zero [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** O(1) per edge type lookup.
*   **Memory Complexity:** O(1) additional memory for the output array.
*   **Performance:** The source does not provide specific performance metrics for this method in isolation. However, related techniques in the same ecosystem (e.g., greedy meshing with chunkless indexing) show significant reductions in triangle count (5.3x fewer) and memory usage (126.7 MB to 10.9 MB) [S2, unofficial].
*   **Strengths:** Simple pointer arithmetic, no complex lookups.
*   **Limitations:** Requires careful handling of edge types and boundary conditions. Degenerates silently on invalid input.

## Background
The method is part of the SurfaceNets multi-material implementation, which generates surfaces from voxel data. It is used in applications requiring efficient rendering of multi-material voxel worlds, such as the one described in the source repository [S1, unofficial].
