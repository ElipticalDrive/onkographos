# Grid Embedding

Also called: Learnable 4D Tensor Lookup Table, Shape-specific latent codes grid

## Overview
Grid Embedding is a method for storing shape-specific latent codes in a dense, learnable 4D tensor lookup table indexed by model ID [S1, unofficial]. It solves the problem of efficiently retrieving and optimizing per-model geometric or feature representations by structuring them as a dense grid rather than a sparse or unstructured collection. It differs from sibling methods like [Spatial Hashing](5002-spatial-hashing.md) or [Sparse Voxel Grid](8021-sparse-voxel-grid.md) by enforcing a fixed, dense memory layout for model-level indexing, whereas siblings typically focus on spatial coordinate hashing or sparse occupancy [S1, unofficial].

## How it works
**Inputs:** A tensor of model indices with shape $(n_{models})$.
**Outputs:** A tensor of shape $(n_{models}, grid\_size+1, grid\_size+1, grid\_size+1, latent\_dim)$ containing the retrieved latent codes.

**Data Structure:**
The embedding is stored as a learnable parameter tensor $E$ with shape $(n, grid\_size+1, grid\_size+1, grid\_size+1, latent\_dim)$, where $n$ is the number of models, $grid\_size$ defines the spatial resolution of the latent code volume, and $latent\_dim$ is the feature dimensionality. The tensor is stored as `nn.Parameter` to enable gradient tracking during backpropagation [S1, unofficial].

**Steps:**
1.  **Gather:** Given an input tensor of model indices $I$ of shape $(n_{models})$, retrieve the corresponding embeddings from the lookup table: $E_{gathered} = E[I]$. This operation maps each model ID to its associated 4D latent volume.
2.  **Reshape:** Reshape the gathered tensor to preserve the 4D grid structure across the batch dimension. The output shape is $(n_{models}, grid\_size+1, grid\_size+1, grid\_size+1, latent\_dim)$ [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn

class GridEmbedding(nn.Module):
    def __init__(self, n_models, grid_size, latent_dim):
        super().__init__()
        # Shape: (n_models, grid_size+1, grid_size+1, grid_size+1, latent_dim)
        # Stored as nn.Parameter for gradient tracking [S1, unofficial]
        self.embeddings = nn.Parameter(
            torch.randn(n_models, grid_size + 1, grid_size + 1, grid_size + 1, latent_dim)
        )

    def forward(self, indices):
        """
        Args:
            indices: Tensor of shape (n_models,) containing model IDs.
        Returns:
            Tensor of shape (n_models, grid_size+1, grid_size+1, grid_size+1, latent_dim)
        """
        # Gather embeddings via self.embeddings[indices] [S1, unofficial]
        gathered = self.embeddings[indices]
        
        # Reshape to (n_models, grid_size+1, grid_size+1, grid_size+1, -1)
        # to preserve the 4D grid structure across the batch dimension [S1, unofficial]
        # Note: If indices is 1D, gathered already has the correct leading dimension.
        # The reshape ensures the last dimension is latent_dim and the middle three are grid_size+1.
        n = indices.shape[0]
        output = gathered.view(n, self.embeddings.shape[1], 
                               self.embeddings.shape[2], 
                               self.embeddings.shape[3], 
                               self.embeddings.shape[4])
        return output
```

**Parameters:**
*   $n_{models}$: Number of distinct models/shapes.
*   $grid\_size$: Spatial resolution of the latent code volume. Typical values are not given in the sources.
*   $latent\_dim$: Dimensionality of the feature vector per voxel.

**Edge Cases and Pitfalls:**
*   **Index Out of Bounds:** If an index in $I$ exceeds $n_{models}-1$, the gather operation will fail. Input validation is required [G].
*   **Memory Usage:** The memory cost is $O(n_{models} \cdot grid\_size^3 \cdot latent\_dim)$. For large $grid\_size$ or $n_{models}$, this dense layout may exceed GPU memory limits compared to sparse alternatives [S1, unofficial].

## Subtopics

### Trainable 3D Saliency Grid
A trainable 3D tensor data structure $G$ with resolution $T \times T \times T$ that stores trainable values representing the saliency of features near each grid voxel, used to guide feature pruning [S2]. It differs from the standard Grid Embedding by operating on spatial coordinates to modulate feature importance (saliency) rather than storing shape-specific latent codes [S2]. Choose this when aiming to reduce space complexity and improve accuracy by pruning internal occluded regions in hashgrid-based NeRFs [S2].

**Definition:** A 3D tensor $G$ of size $T \times T \times T$ initialized as an all-ones tensor, storing trainable floats [S2].
**Steps:**
1.  Split space coarsely into $T \times T \times T$ uniform grids [S2].
2.  For input coordinate $x$, locate the 8 voxels $(x_1 \dots x_8)$ surrounding $x$ in grid $G$ [S2].
3.  Quantize coordinates $x_i$ to $(\hat{x}_i, \hat{y}_i, \hat{z}_i)$ between $0$ and $T-1$ to index saliency values $g_i$ [S2].
4.  Interpolate values associated with the 8 surrounding voxels to get smoothed saliency distribution $P$ [S2].
**Formulas:**
*   Saliency value: $g_i = G(\hat{x}_i, \hat{y}_i, \hat{z}_i)$ [S2].
*   Saliency weight $p$ at coordinate $x$ is calculated by trilinear interpolation of $g_i$ followed by a sigmoid operator, ensuring $0 < p < 1$ [S2].
*   Final weighted feature vector: $v = p \cdot f$, where $f$ is the feature vector fetched from the hashgrid [S2].
**Parameters:**
*   $T$: Resolution of the saliency grid. Typically much smaller than the resolution of the dense feature grid [S2].
**Pitfalls:**
*   Precision in quantization and interpolation affects the smoothness of the saliency distribution [S2].

## Operating characteristics
*   **Time Complexity:** Lookup is $O(1)$ per model index via direct tensor indexing [S1, unofficial].
*   **Memory Complexity:** $O(n_{models} \cdot grid\_size^3 \cdot latent\_dim)$ [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Enables end-to-end gradient-based optimization of shape-specific latent codes; simple implementation via standard tensor operations [S1, unofficial].
*   **Limitations:** High memory consumption for large grids or many models; dense layout does not adapt to sparsity of the underlying shape [S1, unofficial].
*   **When to use:** When the number of models is manageable and dense, differentiable access to per-model latent volumes is required [S1, unofficial].
*   **When not to use:** For very large-scale scenes or sparse geometries where memory efficiency is critical; use [Sparse Voxel Grid](8021-sparse-voxel-grid.md) or [Spatial Hashing](5002-spatial-hashing.md) instead.

## Background
The Grid Embedding method is described in the context of VC-SDFGen, an unofficial implementation or repository [S1, unofficial]. It is used to store and optimize shape-specific latent codes for 3D models, likely within a neural implicit representation framework. The Trainable 3D Saliency Grid variant originates from HollowNeRF, which proposes pruning hashgrid-based NeRFs by learning sparsity patterns to reclaim capacity spent on internal occluded regions [S2].
