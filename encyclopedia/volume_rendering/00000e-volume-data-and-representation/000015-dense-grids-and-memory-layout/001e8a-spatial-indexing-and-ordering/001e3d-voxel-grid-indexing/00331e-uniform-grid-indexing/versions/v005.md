# Uniform Grid Indexing

Also called: 3D Grid Index Calculation, 3D to 1D Grid Mapping, Froxel Index Calculation, Position Index Calculation, getPositionIndex

## Overview
Uniform Grid Indexing converts a 3D world position into a linear array index within a dense, axis-aligned voxel grid [S1, unofficial]. It solves the problem of spatial lookup in volume rendering by mapping continuous coordinates to discrete storage locations using an axis-aligned bounding box (AABB) and fixed grid resolution [S2, unofficial]. It sets itself apart from [Spatial Hashing](5002-spatial-hashing.md) by guaranteeing deterministic, collision-free indexing for all points within the grid bounds, and from [Sparse Voxel Grid](8021-sparse-voxel-grid.md) by using a fixed memory footprint regardless of data sparsity [G].

## How it works
**Inputs:**
- `position`: A 3D vector $(x, y, z)$ in world space [S3, unofficial].
- `boundsMin`: The minimum corner of the grid's AABB $(min_x, min_y, min_z)$ [S3, unofficial].
- `boundsMax`: The maximum corner of the grid's AABB $(max_x, max_y, max_z)$ [S3, unofficial].
- `cellsPerEdge`: The number of voxels along one edge of the cubic grid (integer $N$) [S3, unofficial].

**Outputs:**
- `linearIndex`: A single integer representing the position in a 1D array storing the grid data [S2, unofficial].

**Data Structures:**
- The grid is stored as a 1D array of size $N^3$ using row-major ordering [G].
- Row-major layout implies that the $z$-axis is the most significant dimension, followed by $y$, then $x$ [G].

**Steps:**
1. **Edge Case Handling:** If `cellsPerEdge` is 1, the grid contains only one voxel [S3, unofficial].
2. **Bounding Box Validation:** Calculate the bounding box size vector: $\text{BoxSize} = \text{boundsMax} - \text{boundsMin}$ [S3, unofficial].
3. **Relative Position:** Translate the input position relative to the minimum bound: $\text{RelativePosition} = \text{position} - \text{boundsMin}$ [S3, unofficial].
4. **Normalization:** Normalize the relative position to the $[0, 1]$ range per axis [S3, unofficial].
5. **Scaling:** Scale the normalized coordinates by the grid resolution to get floating-point cell coordinates: $\text{ScaledPosition} = \text{NormalizedPosition} \times \text{cellsPerEdge}$ [S3, unofficial].
6. **Integer Conversion:** Floor the scaled positions to obtain integer grid indices $(CellX, CellY, CellZ)$ [S3, unofficial].
7. **Clamping:** Clamp the integer indices to the valid range $[0, \text{cellsPerEdge} - 1]$ to handle boundary cases [S3, unofficial].
8. **Linear Index Calculation:** Compute the linear index using row-major order: $\text{LinearIndex} = CellZ \cdot (\text{cellsPerEdge}^2) + CellY \cdot \text{cellsPerEdge} + CellX$ [S3, unofficial].

**Formulas:**
The conversion can be expressed compactly using clamp operations on the normalized coordinates scaled by the number of divisions $\text{_numDivs}$ (where $\text{_numDivs} = \text{cellsPerEdge}$) [S1, unofficial]:

$$ x = \text{clamp}\left(\frac{\text{position}.x - \text{_aabb.min}.x}{\text{_cellSize}.x}, 0, \text{_numDivs}.x - 1\right) $$
$$ y = \text{clamp}\left(\frac{\text{position}.y - \text{_aabb.min}.y}{\text{_cellSize}.y}, 0, \text{_numDivs}.y - 1\right) $$
$$ z = \text{clamp}\left(\frac{\text{position}.z - \text{_aabb.min}.z}{\text{_cellSize}.z}, 0, \text{_numDivs}.z - 1\right) $$

$$ \text{index} = x \cdot \text{_numDivs}.y \cdot \text{_numDivs}.z + y \cdot \text{_numDivs}.z + z $$

Note that $\text{_cellSize}$ is equivalent to $\text{BoxSize} / \text{cellsPerEdge}$ [G]. The terms $\text{_numDivs}.y \cdot \text{_numDivs}.z$ and $\text{_numDivs}.z$ correspond to the stride for the $y$ and $z$ dimensions respectively in a non-cubic grid, but for a uniform cubic grid where $\text{cellsPerEdge}$ is constant, this simplifies to the row-major formula in Step 8 [S1, unofficial]. An equivalent formulation maps 3D grid coordinates $(X, Y, Z)$ to a 1D array index as $\text{Index} = X + Y \cdot \text{GridX} + Z \cdot \text{GridX} \cdot \text{GridY}$ [S2, unofficial].

**Pseudocode:**
```python
import math

def uniform_grid_indexing(position, bounds_min, bounds_max, cells_per_edge):
    """
    Converts a 3D world position to a linear index in a uniform voxel grid.
    """
    if cells_per_edge == 1:
        return 0

    box_size_x = bounds_max[0] - bounds_min[0]
    box_size_y = bounds_max[1] - bounds_min[1]
    box_size_z = bounds_max[2] - bounds_min[2]

    if box_size_x <= 0 or box_size_y <= 0 or box_size_z <= 0:
        return 0

    rel_x = position[0] - bounds_min[0]
    rel_y = position[1] - bounds_min[1]
    rel_z = position[2] - bounds_min[2]

    eps = 1e-9
    norm_x = rel_x / max(box_size_x, eps)
    norm_y = rel_y / max(box_size_y, eps)
    norm_z = rel_z / max(box_size_z, eps)

    scaled_x = norm_x * cells_per_edge
    scaled_y = norm_y * cells_per_edge
    scaled_z = norm_z * cells_per_edge

    cell_x = math.floor(scaled_x)
    cell_y = math.floor(scaled_y)
    cell_z = math.floor(scaled_z)

    max_idx = cells_per_edge - 1
    cell_x = max(0, min(cell_x, max_idx))
    cell_y = max(0, min(cell_y, max_idx))
    cell_z = max(0, min(cell_z, max_idx))

    linear_index = cell_z * (cells_per_edge ** 2) + cell_y * cells_per_edge + cell_x
    return linear_index
```

**Parameters:**
- `cells_per_edge`: Typically a power of 2 (e.g., 64, 128, 256) for efficient bit-shifting in optimized implementations, though the algorithm works for any integer [S2, unofficial].
- `boundsMin`, `boundsMax`: Define the spatial extent of the volume [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Division by Zero:** If `boundsMin` equals `boundsMax` in any dimension, `BoxSize` is zero [G].
- **Boundary Precision:** Points exactly on the boundary may suffer from floating-point inaccuracies [G].
- **Out-of-Bounds:** Points outside the AABB are clamped to the nearest edge voxel, which may cause multiple distinct world positions to map to the same voxel [S1, unofficial].

## Subtopics

### [Regular Grid Decomposition](7659-regular-grid-decomposition.md)
Regular Grid Decomposition is a spatial partitioning strategy for neural volume rendering where the global scene domain is divided into a uniform 3D grid of independent neural network models, each responsible for a specific sub-region. It solves the problem of representing large-scale or complex scenes by distributing the modeling capacity across multiple smaller networks rather than relying on a single global model. Unlike [Compact Grid Method](9891-compact-grid-method.md), which adapts grid density to data sparsity, Regular Grid Decomposition uses a fixed, homogeneous grid structure, which simplifies the inference pipeline but requires significantly more regions to achieve comparable accuracy in non-homogeneous scenes.

### [Compact Grid Method](9891-compact-grid-method.md)
The Compact Grid Method is a static data structure for representing a uniform grid acceleration structure with minimal memory requirements: exactly one index per grid cell and exactly one index per object reference, built in linear time. It solves the problem of efficiently mapping objects to grid cells for ray tracing without the memory overhead of linked lists or dynamic arrays. It sets itself apart from its siblings by using a two-pass counting-sort-like algorithm to pack object indices into a single contiguous array, managed by a cell offset array that defines list boundaries implicitly, avoiding null pointers or extra tracking arrays.
