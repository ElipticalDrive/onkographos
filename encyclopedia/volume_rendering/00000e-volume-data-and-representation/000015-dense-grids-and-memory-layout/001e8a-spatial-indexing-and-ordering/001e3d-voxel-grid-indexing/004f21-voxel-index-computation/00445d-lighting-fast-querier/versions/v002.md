# Lighting Fast Querier

Also called: PointNeRF Voxel Querier, World-to-Grid Point Indexer

## Overview
The Lighting Fast Querier is a class that manages the querying of 3D points from a point cloud for ray marching, handling coordinate transformations, grid indexing via CUDA, and ray generation [S1, unofficial]. It solves the problem of efficiently determining which voxels contain point cloud data for a given set of camera rays, handling coordinate transformations, bounding box clamping, and super-resolution scaling [S1, unofficial]. It differs from generic voxel indexing by integrating ray generation, jittered sampling for training, and specific kernel-based query logic optimized for point cloud density [S1, unofficial].

## How it works
**Inputs:**
- `point_xyz_w_tensor`: Tensor of 3D point coordinates in world space [S1, unofficial].
- `pixel_idx`: Tensor of pixel coordinates (u, v) for ray origins [S1, unofficial].
- `raydir`: Tensor of ray directions [S1, unofficial].
- `opt`: Configuration object containing hyperparameters (`vsize`, `vscale`, `kernel_size`, `query_size`, `radius_limit_scale`, `inverse`, `SR`, `random_sample`, `training`) [S1, unofficial].
- `ranges`: Optional bounding box constraints `[min_x, min_y, min_z, max_x, max_y, max_z]` [S1, unofficial].
- `w2pers`: World-to-perspective transformation matrix [S1, unofficial].

**Outputs:**
- `sample_point_indices`: Indices of the queried voxels [S1, unofficial].
- `sample_locations`: World coordinates of the sampled points [S1, unofficial].
- `ray_mask`: Boolean mask indicating valid rays [S1, unofficial].
- `ray_directions`: Expanded ray directions for the sampled points [S1, unofficial].

**Data Structures:**
- `min_xyz`, `max_xyz`: 3D vectors defining the voxel grid bounds [S1, unofficial].
- `vdim_np`, `scaled_vdim_np`: Integer dimensions of the voxel grid [S1, unofficial].
- `radius_limit_np`: Float scalar for query radius [S1, unofficial].

**Steps:**
1. **Compute Bounding Box:** Calculate the initial bounding box from the point cloud: `min_xyz = min(point_xyz_w_tensor, axis=0)`, `max_xyz = max(point_xyz_w_tensor, axis=0)` [S1, unofficial]. If `ranges` is provided, clamp the bounds: `min_xyz = max(min_xyz, ranges[:3])`, `max_xyz = min(max_xyz, ranges[3:])` [S1, unofficial].
2. **Expand Bounds:** Expand the bounding box by half the scaled voxel size times the kernel size to ensure coverage: `min_xyz -= scaled_vsize_np * opt.kernel_size / 2`, `max_xyz += scaled_vsize_np * opt.kernel_size / 2` [S1, unofficial]. [G] `scaled_vsize_np` is derived from `opt.vsize` and `opt.vscale`.
3. **Calculate Grid Dimensions:** Compute the voxel dimensions in world units and scale them: `vdim_np = (max_xyz - min_xyz) / vsize_np`, `scaled_vdim_np = ceil(vdim_np / vscale_np)` converted to `int32` [S1, unofficial].
4. **Generate Rays:** Determine ray positions using `near_far_disparity_linear_ray_generation` if `opt.inverse > 0`, otherwise `near_far_linear_ray_generation`, with jitter if training [S1, unofficial].
5. **Query Grid Indices (CUDA):** Call the CUDA extension `query_worldcoords_cuda.woord_query_grid_point_index` with pixel indices, ray positions, world coordinates, point counts, kernel/query sizes, scaling factors, and ranges to get sample point indices, locations, and ray masks [S1, unofficial].
6. **Extract and Reshape Directions:** Extract and reshape ray directions for the sampled points using `ray_mask_tensor` to filter valid rays, expanding them for super-resolution (`opt.SR`) [S1, unofficial].
7. **Perspective Transformation:** Transform world coordinates to perspective coordinates using `w2pers`, which shifts by camera position, rotates by camera rotation transpose, and divides x/y by z [S1, unofficial].

**Parameters:**
- `radius_limit_np`: The radius limit for querying, calculated as `opt.radius_limit_scale * max(opt.vsize[0], opt.vsize[1])` converted to float32 [S1, unofficial].
- `vscale_np`: A vector of integers from `opt.vscale` used to scale voxel dimensions [S1, unofficial].
- `kernel_size`: The size of the kernel used in querying, from `opt.kernel_size` [S1, unofficial].
- `query_size`: The size of the query, from `opt.query_size` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Empty Point Cloud:** If `point_xyz_w_tensor` is empty, `min_xyz` and `max_xyz` will be undefined [S1, unofficial]. Handle this by returning empty tensors or a default grid [G].
- **Degenerate Input:** If `opt.vsize` is zero, division by zero occurs [G]. Ensure `opt.vsize` is positive.
- **Boundary Clamping:** If `ranges` are tighter than the point cloud bounds, the expanded bounds may still exclude points [G]. Ensure `ranges` are consistent with the point cloud distribution [G].

## Operating characteristics
- **Time Complexity:** $O(N)$ for bounding box computation, where $N$ is the number of points [G]. The CUDA query is $O(R \times K)$, where $R$ is the number of rays and $K$ is the kernel size [G].
- **Memory Complexity:** $O(V)$ for the voxel grid, where $V$ is the number of voxels [G].
- **Performance:** Optimized for GPU execution via CUDA. Performance scales with the number of rays and the density of the point cloud [G].
- **Strengths:** Fast querying of point cloud data for ray marching; handles super-resolution; integrates jitter for training stability [G].
- **Limitations:** Requires CUDA; dependent on specific configuration parameters; may suffer from precision issues with large bounding boxes [G].

## Background
The Lighting Fast Querier is part of the PointNeRF framework, which combines point clouds with neural radiance fields for efficient 3D reconstruction. It was introduced in the PointNeRF project by Xharlie [S1, unofficial].
