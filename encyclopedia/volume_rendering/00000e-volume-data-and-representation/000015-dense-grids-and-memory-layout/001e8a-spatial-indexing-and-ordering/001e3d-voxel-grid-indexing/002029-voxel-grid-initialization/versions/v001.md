# Voxel Grid Initialization

Also called: Grid Activation, Grid Initialization, activate, vTable1 initialization

## Overview
Voxel Grid Initialization prepares a sparse voxel data structure for rendering by activating voxels that match a specific background or threshold value, effectively expanding the active set of the grid [S1, unofficial]. It differs from sibling methods like [Coordinate Space Conversion](1785-coordinate-space-conversion.md) by focusing on data population and memory allocation rather than coordinate transformation, and from [Spatial Hashing](5002-spatial-hashing.md) by operating on a dense grid structure before potential sparsification. The method ensures that the underlying voxel table (`vTable1`) is correctly sized and initialized to zero before populating active voxel coordinates [S2, unofficial].

## How it works
**Inputs:**
- `tree`: The sparse voxel tree structure containing leaf nodes and a `background` value.
- `value`: The specific scalar value to activate (typically equal to `tree.background`) [S1, unofficial].
- `linearGridDim`: The linear dimension of the grid, used to calculate the voxel table size [S2, unofficial].

**Outputs:**
- A new grid structure with an initialized `vTable1` containing active voxel coordinates.
- The `vTable1` array itself, containing indices or coordinates of active voxels.

**Data Structures:**
- **Grid Structure**: Contains the following fields [S2, unofficial]:
  - `vTable1`: `unsigned int*` pointer to the voxel table.
  - `gridSize`: `int` representing the grid dimensions.
  - `gridVoxelSize`: `float` representing the size of a single voxel.
- **Voxel Table (`vTable1`)**: A 1D array of unsigned integers. The dimension is calculated via `vTableDimension(linearGridDim)` [S2, unofficial]. The specific formula for `vTableDimension` is not provided in the sources [S2, unofficial].

**Steps:**
1. **Initialize Active Set**: Create a temporary data structure `data` initialized with all currently active voxels from `active_voxels(tree)` [S1, unofficial].
2. **Allocate Voxel Table**: Allocate memory for `vTable1` using `vTableMalloc`. The size is determined by `linearGridDim` [S2, unofficial].
3. **Iterate Leaves**: For each leaf in the tree:
   - Iterate through offsets defined by `off_indices(leaf.value_mask)` [S1, unofficial].
   - Check if `leaf.values[offset + 1] == value` [S1, unofficial].
   - If true, decode the 3D coordinate `c` from the leaf and offset.
   - Add the coordinate to the data structure: `data[c] = value` [S1, unofficial].
4. **Initialize Voxel Table**: Set all entries in the allocated `vTable1` to zero using `vTableInitialEmpty` [S2, unofficial].
5. **Build Grid**: Construct the final grid using `build_grid(data, tree.background; ...)` [S1, unofficial].
6. **GPU Initialization**: On the GPU, set `vTable1` to `NULL`, and initialize `gridSize` and `gridVoxelSize` [S2, unofficial].

**Pseudocode:**
```python
def voxel_grid_initialization(tree, value, linearGridDim):
    # Step 1: Initialize active set with existing active voxels
    data = {}
    for c in active_voxels(tree):
        data[c] = tree.background

    # Step 2: Allocate memory for voxel table
    # vTableMalloc calculates dimension based on linearGridDim
    vTable1 = vTableMalloc(linearGridDim)

    # Step 3: Iterate all leaves and activate matching voxels
    for leaf in tree.leaves:
        # Get offsets from the value mask
        offsets = off_indices(leaf.value_mask)
        for offset in offsets:
            # Check if the value at this offset matches the target value
            # Note: Source uses offset + 1, likely due to 1-based indexing or specific layout
            if leaf.values[offset + 1] == value:
                # Decode the 3D coordinate c from the leaf and offset
                c = decode_coordinate(leaf, offset)
                # Add to data structure
                data[c] = value

    # Step 4: Initialize the allocated voxel table to all zeros
    vTableInitialEmpty(vTable1)

    # Step 5: Build the new grid
    grid = build_grid(data, tree.background)

    # Step 6: Initialize grid structure on GPU
    grid.vTable1 = NULL
    grid.gridSize = linearGridDim
    grid.gridVoxelSize = tree.voxel_size

    return grid
```

**Parameters:**
- `value`: Typically set to `tree.background` to activate the background volume [S1, unofficial].
- `linearGridDim`: The linear dimension of the grid, used for memory allocation [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Precision**: Floating-point inaccuracies in coordinate decoding may lead to duplicate or missing voxels if not handled by integer quantization (see [Voxel Grid Construction](3085-voxel-grid-construction.md)) [G].
- **Boundaries**: Ensure `offset + 1` does not exceed the bounds of `leaf.values` [S1, unofficial].
- **Degenerate Input**: If `tree` has no leaves, the grid will be empty but still allocated [G].

## Subtopics

### [Voxel Grid Construction](3085-voxel-grid-construction.md)
Constructs a 3D voxel grid where each cube has 8 corner vertices, deduplicating shared corners to store them only once. The grid is centered at the origin with unit length along each dimension. It differs from naive grid generation by using integer quantization for vertex deduplication to handle floating-point inaccuracies, reducing memory usage and ensuring consistent topology for subsequent marching cubes or similar extraction algorithms.

### [Grid Background Change](3210-grid-background-change.md)
Updates the background value of inactive voxels in a volume grid while preserving the values of active voxels. It returns a new grid where inactive voxels holding the old background value are updated to a new background value, while active voxels remain unchanged.

### Dense Copy Ingestion
Builds a VDB grid from a dense 3D array. Only values differing from `background` are stored as active voxels [S1, unofficial].
- **Steps**:
  1. Iterate array indices `ix, iy, iz`.
  2. If `array[ix, iy, iz] != background`, compute world coordinate `c` using `bbox_min` and add to `data` [S1, unofficial].
  3. Build grid using `build_grid(data, background; ...)` [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of leaves and their active voxels. The iteration over leaves and offsets dominates the runtime [S1, unofficial].
- **Memory Complexity**: Proportional to the number of active voxels plus the overhead of the voxel table allocation [S2, unofficial].
- **Measured Performance**: Benchmarks in [S1, unofficial] show that warmup renders are necessary to defeat JIT first-call effects, indicating significant initial allocation overhead.
- **Strengths**: Efficiently activates background voxels, which is crucial for volume rendering where the background contributes to the final color.
- **Limitations**: Requires full iteration over leaves, which can be slow for very large grids. The specific formula for `vTableDimension` is not provided, making optimization difficult [S2, unofficial].
- **When to Use**: When preparing a sparse voxel grid for rendering, especially when the background needs to be explicitly activated.
- **When Not to Use**: When memory is extremely constrained and the background can be handled implicitly by the renderer.

## Background
The method originates from the Lyr.jl library [S1, unofficial] and is used in the context of GPU-accelerated volume rendering. It is part of the pipeline that converts level set data into fog for volume rendering [S1, unofficial]. The voxel table initialization is a critical step in preparing the data structure for the rendering kernel [S2, unofficial].
