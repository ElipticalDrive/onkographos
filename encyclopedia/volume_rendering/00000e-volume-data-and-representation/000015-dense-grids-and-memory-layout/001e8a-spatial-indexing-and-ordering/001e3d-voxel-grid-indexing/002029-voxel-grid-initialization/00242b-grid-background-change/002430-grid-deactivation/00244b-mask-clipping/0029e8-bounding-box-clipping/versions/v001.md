# Bounding Box Clipping

Also called: clip (bbox)

## Overview
Bounding Box Clipping returns a new grid containing only the active voxels of a source grid that lie within a specified axis-aligned bounding box (AABB) [S1, unofficial]. It serves as a spatial filter to isolate a region of interest or reduce memory footprint by discarding voxels outside the target volume [S1, unofficial]. Unlike [Mask Clipping](3229-mask-clipping.md), which uses a secondary binary grid to define the active region, Bounding Box Clipping uses geometric coordinates, making it suitable for rectangular sub-volumes without requiring a pre-computed mask grid.

## How it works
**Inputs:**
- `source_grid`: The input voxel grid containing active/inactive voxels.
- `bbox`: An axis-aligned bounding box defined by minimum and maximum coordinates $(x_{min}, y_{min}, z_{min})$ and $(x_{max}, y_{max}, z_{max})$.

**Outputs:**
- `clipped_grid`: A new grid containing only the voxels from `source_grid` where the voxel center (or representative coordinate) lies within `bbox`.

**Data Structures:**
- The output grid typically maintains the same internal data structure as the source (e.g., a dense array, sparse hash map, or linked list of blocks), but initialized with a smaller extent or a subset of the original data.
- If the source is sparse, the output may be a new sparse structure containing only the relevant entries.

**Steps:**
1. Initialize an empty container for the output grid data.
2. Iterate through all active voxels in the `source_grid`.
3. For each active voxel at coordinate $c = (x, y, z)$:
   - Check if $c$ is contained within `bbox`.
   - The containment test is defined as:
     $$x_{min} \le x \le x_{max} \land y_{min} \le y \le y_{max} \land z_{min} \le z \le z_{max}$$
   - If the condition is true, add the voxel (and its associated data) to the output container.
4. Construct the `clipped_grid` from the output container.
5. Return `clipped_grid`.

**Pseudocode:**
```python
def bounding_box_clip(source_grid, bbox):
    """
    Clips a voxel grid to a bounding box.
    
    Args:
        source_grid: Object with method `get_active_voxels()` returning an iterable of (coord, data).
        bbox: Tuple (x_min, y_min, z_min, x_max, y_max, z_max).
        
    Returns:
        A new grid object containing only voxels inside the bbox.
    """
    x_min, y_min, z_min, x_max, y_max, z_max = bbox
    clipped_data = []
    
    # Iterate over all active voxels in the source
    for coord, data in source_grid.get_active_voxels():
        x, y, z = coord
        
        # Check containment in AABB
        if (x_min <= x <= x_max and
            y_min <= y <= y_max and
            z_min <= z <= z_max):
            clipped_data.append((coord, data))
            
    # Construct and return the new grid
    # Implementation detail: The specific constructor depends on the grid type.
    # [G] Assuming a generic Grid constructor that accepts a list of active voxels.
    return Grid.from_active_voxels(clipped_data)
```

**Edge Cases and Pitfalls:**
- **Empty Result:** If no active voxels lie within the bounding box, the result is an empty grid. The implementation must handle this gracefully (e.g., returning a valid empty grid rather than null, unless specified otherwise).
- **Boundary Precision:** Coordinate comparisons should be inclusive ($\le$) to ensure voxels on the boundary are included, consistent with standard voxel grid indexing.
- **Degenerate BBox:** If $x_{min} > x_{max}$ or similar for other axes, the bbox is invalid. The method should either return an empty grid or raise an error. [G] Raising an error is safer to prevent silent data loss.

## Subtopics

### Voxel Body Copying with Sub-Voxel Clipping
This variant handles clipping at a finer granularity, potentially operating on "solid blocks" or "voxel bodies" rather than individual voxels. It calculates the integer bounding box of the volume within the world grid using a function like `TryGetRange` [S2, unofficial]. If no solid range exists, it returns null [S2, unofficial]. It iterates over all solid blocks in the volume using `ForEachSolidIn` [S2, unofficial]. For each block, if it is not fully inside the target bbox, it calls `ClipBlock` with `keepInside: true` to get the clipped field [S2, unofficial]. If the resulting field is empty, it is skipped; if it is full, the field is set to null [S2, unofficial]. Otherwise, a new `VoxelBody.Voxel` with the clipped field is added to a `kept` list [S2, unofficial]. If the `kept` list is empty, it returns null; otherwise, it creates a `VoxelBody` using `VoxelBody.Cropped` with the name and the list of voxels [S2, unofficial]. This approach is useful when the underlying data is organized in larger, immutable blocks that need to be partially retained.

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of active voxels in the source grid. Each active voxel is visited once and checked against the bbox.
- **Memory Complexity:** $O(K)$, where $K$ is the number of active voxels inside the bounding box. The output grid stores only these voxels.
- **Performance:** The operation is generally fast and memory-bound if the grid is sparse, as it avoids iterating over inactive voxels. If the grid is dense, iterating over the entire volume may be costly, but the clipping itself is a simple comparison.
- **Strengths:** Simple to implement, efficient for sparse grids, no need for auxiliary mask data.
- **Limitations:** Only supports axis-aligned rectangular regions. Not suitable for irregular or non-rectangular sub-volumes.

## Background
Bounding Box Clipping is a fundamental operation in voxel-based graphics and simulation, often used for level-of-detail management, culling, or preparing data for specific rendering passes. It is implemented in various voxel engines and libraries, such as Lyr.jl [S1, unofficial] and VoxelTerraformer [S2, unofficial].
