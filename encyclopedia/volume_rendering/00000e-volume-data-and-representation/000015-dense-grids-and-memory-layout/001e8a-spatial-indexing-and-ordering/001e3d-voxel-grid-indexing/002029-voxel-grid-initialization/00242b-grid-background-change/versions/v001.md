# Grid Background Change

## Overview
Grid Background Change updates the background value of inactive voxels in a volume grid while preserving the values of active voxels. It solves the problem of isolating background noise or changing the default background representation in a volume dataset. Unlike [Voxel Grid Construction](3085-voxel-grid-construction.md), which builds a grid from scratch, this method modifies an existing grid's background state. It differs from [Grid Deactivation](3214-grid-deactivation.md), which removes active voxels based on scalar criteria, by explicitly updating the values of previously inactive (background) voxels.
## How it works
**Inputs:**
- `grid`: The source volume grid containing active and inactive voxels.
- `new_bg`: The new background value (scalar type `T`) to assign to inactive voxels.

**Outputs:**
- A new grid instance with the same structure (tree, voxel size, name) but with inactive voxels set to `new_bg`.

**Data Structures:**
- The grid uses a tree structure (e.g., VDB tree) where each leaf node contains a `value_mask` indicating active voxels and a `values` array storing scalar data.
- `on_indices(mask)`: Returns a list of offsets corresponding to set bits in `value_mask`.
- `Dict{Coord, T}`: A dictionary mapping 3D coordinates to scalar values for active voxels.

**Steps:**
1. **Extract Active Voxels:** Iterate through all leaf nodes in the grid's tree. For each leaf, iterate through the offsets returned by `on_indices(leaf.value_mask)`.
2. **Decode Coordinates:** For each offset, decode the 3D coordinate `c` using the leaf's `origin` and the offset bits.
3. **Store Active Data:** Store the value `leaf.values[offset + 1]` in a dictionary `active_data` at key `c`. The `+1` accounts for potential header or padding bytes in the leaf's value storage layout [S1, unofficial].
4. **Build New Grid:** Construct a new grid using the extracted `active_data` and the `new_bg` value. The new grid retains the original grid's `name`, `grid_class`, and `voxel_size` (`vs`). The construction function `build_grid` handles assigning `new_bg` to all coordinates not present in `active_data` [S1, unofficial].

**Pseudocode:**
```python
def grid_background_change(grid, new_bg):
    active_data = {}
    for leaf in grid.tree.leaves():
        # Get offsets of active voxels in this leaf
        offsets = on_indices(leaf.value_mask)
        for offset in offsets:
            # Decode coordinate from leaf origin and offset
            c = decode_coordinate(leaf.origin, offset)
            # Store value; offset + 1 accounts for leaf data layout
            active_data[c] = leaf.values[offset + 1]
    
    # Build new grid with active data and new background value
    new_grid = build_grid(
        data=active_data,
        new_bg=new_bg,
        name=grid.name,
        grid_class=grid.grid_class,
        voxel_size=grid.voxel_size
    )
    return new_grid
```

**Parameters:**
- `new_bg`: The new background scalar value. Typical values depend on the data type (e.g., 0.0 for density, 1.0 for opacity). Not given in the sources.

**Edge Cases:**
- **Empty Active Set:** If no voxels are active, the new grid will consist entirely of `new_bg`.
- **Precision:** Coordinate decoding must handle floating-point precision if the grid uses continuous coordinates. Not given in the sources.
- **Boundary Conditions:** The `decode_coordinate` function must correctly map leaf-local offsets to global coordinates. Not given in the sources.

## Subtopics

### [Grid Deactivation](3214-grid-deactivation.md)
Removes active voxels based on scalar value. Choose when isolating foreground objects by removing background noise is required.

## Operating characteristics
- **Time Complexity:** Linear in the number of active voxels, as it iterates only through active leaves and offsets. Not given in the sources.
- **Memory Complexity:** Proportional to the number of active voxels for the temporary dictionary, plus the size of the new grid. Not given in the sources.
- **Strengths:** Efficiently updates background without modifying active data. Preserves grid structure.
- **Limitations:** Requires iterating all leaves. Not suitable for sparse grids with very large inactive regions if memory is constrained.
- **When to Use:** When the background value needs to be changed for rendering or analysis purposes without altering active data.
- **When Not to Use:** When active voxels also need modification; use [Grid Deactivation](3214-grid-deactivation.md) or other methods.
## Background
Originated in the Lyr.jl library by Tobias Osborne [S1, unofficial]. It is used in volume rendering pipelines to manage background values in VDB-based volume grids.
