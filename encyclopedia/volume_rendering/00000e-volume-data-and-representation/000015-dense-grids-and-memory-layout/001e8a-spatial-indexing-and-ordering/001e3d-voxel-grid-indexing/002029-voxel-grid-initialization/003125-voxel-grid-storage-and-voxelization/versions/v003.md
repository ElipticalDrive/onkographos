# Voxel Grid Storage and Voxelization

Also called: Voxel Grid Storage

## Overview
Voxel Grid Storage and Voxelization is the process of converting continuous geometric primitives (typically meshes) into a discrete, dense 3D grid representation suitable for volume rendering or signed distance field (SDF) computation [S1, S2, unofficial]. It solves the problem of spatial discretization by mapping world-space coordinates to integer grid indices and evaluating geometric predicates (such as SDFs) at voxel centers [S1, unofficial]. It differs from [Voxel Grid Construction](3085-voxel-grid-construction.md) by focusing on the specific memory layout (1D array vs. multi-dimensional pointers) and the explicit initialization of grid bounds and dimensions, whereas Construction may imply a broader pipeline including sparse structures. It differs from [Grid Background Change](3210-grid-background-change.md) by handling the initial population of the grid with geometric data rather than modifying existing background values.

## How it works
**Inputs:**
- A geometric shape (e.g., a mesh or implicit function) [S1, S2, unofficial].
- A target voxel size (physical units per voxel) [S1, unofficial].
- Optional: An existing grid structure to fit into (for shared-grid variants) [S3, unofficial].

**Outputs:**
- A voxel grid data structure containing the discretized geometric representation (SDF values or occupancy) [S1, S2, unofficial].

**Data Structures:**
Two primary storage layouts are documented in the sources:

1.  **1D Float Array (SDF Storage):**
    -   `voxels`: A single 1D array of `float`.
    -   Dimensions: `width`, `height`, `depth` (integers).
    -   Indexing formula: `index = (z * width * height) + (y * width) + x` [S1, unofficial].
    -   Memory layout: Z is the slowest-varying dimension, Y is middle, X is fastest [S1, unofficial].
    -   Allocation: If `width * height * depth` exceeds current capacity, resize to the nearest power of 2 greater than or equal to the required size using bitwise rounding-up [S1, unofficial].

2.  **3D Boolean Pointer Array (Occupancy Storage):**
    -   `data`: A 3D array of `bool` implemented as `bool ***` [S2, unofficial].
    -   Allocation: Dynamically allocated as `new bool ** [dimensions.x.count]`, with nested loops allocating `dimensions.y.count` pointers per X, and `dimensions.z.count` bools per Y [S2, unofficial].

**Algorithm Steps:**

1.  **Calculate Bounding Box:** Determine the world-space bounding box of the input shape [S1, unofficial].
2.  **Compute Grid Origin:**
    -   Let $B_{min}$ be the minimum coordinates of the bounding box.
    -   Let $v$ be the voxel size.
    -   Compute origin $O = (\lfloor B_{min,x} / v \rfloor - 1) \cdot v, (\lfloor B_{min,y} / v \rfloor - 1) \cdot v, (\lfloor B_{min,z} / v \rfloor - 1) \cdot v$ [S1, unofficial].
    -   *Note:* The source describes this as "flooring the bounding box minimum coordinates scaled by the voxel size reciprocal, then subtracting one voxel size" [S1, unofficial].
3.  **Compute Grid Dimensions:**
    -   Let $E$ be the extents (max - min) of the bounding box.
    -   Compute base dimensions $D_{base} = \lceil E / v \rceil$ [S1, unofficial].
    -   Add padding: $D_{final} = D_{base} + 2$ for each dimension (width, height, depth) [S1, unofficial].
4.  **Allocate Storage:**
    -   Calculate total voxels $N = width \times height \times depth$.
    -   If using 1D float array, ensure capacity $\ge N$. If not, resize to next power of 2 [S1, unofficial].
    -   If using 3D bool array, allocate the pointer structure [S2, unofficial].
5.  **Voxelize (SDF Method):**
    -   Iterate $z$ from 0 to $depth-1$, $y$ from 0 to $height-1$, $x$ from 0 to $width-1$ [S1, unofficial].
    -   Compute world-space center: $P_{world} = O + (x + 0.5) \cdot v, (y + 0.5) \cdot v, (z + 0.5) \cdot v$ [S1, unofficial].
    -   Transform $P_{world}$ to the shape's local coordinate system [S1, unofficial].
    -   Evaluate the shape's Signed Distance Function (SDF) at the local point [S1, unofficial].
    -   Store the result in `voxels[index]` [S1, unofficial].
6.  **Voxelize (Occupancy Method):**
    -   Iterate through all voxel coordinates [S2, unofficial].
    -   Determine if the voxel center (or sample) lies inside the shape.
    -   Set `data[x][y][z]` to `true` if inside, `false` otherwise [S2, unofficial].

**Parameters:**
-   `DEFAULT_VOXEL_SIZE`: Static float constant, typically `0.1f` [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Out-of-Bounds Access:** Accessing a voxel coordinate outside the grid bounds does not throw an error. Instead, the `getVoxel` method returns a large default value of `10_000.0f` to indicate out-of-bounds access [S1, unofficial].
-   **Memory Efficiency:** Using `bool` for voxel storage is memory inefficient because each boolean typically occupies a full byte rather than a single bit [S2, unofficial].
-   **Precision:** The bitwise rounding-up for power-of-2 allocation may result in significant memory overallocation for non-power-of-2 grid sizes [S1, unofficial].

**Pseudocode (1D Float Array SDF Voxelization):**

```python
import math

def voxelize_sdf(shape, voxel_size=0.1):
    """
    Voxelize a shape into a 1D float array representing an SDF grid.
    
    Args:
        shape: Object with method get_bounding_box() and evaluate_sdf(local_point).
        voxel_size: Physical size of each voxel.
        
    Returns:
        dict with 'voxels' (list), 'width', 'height', 'depth', 'origin'.
    """
    # 1. Calculate Bounding Box
    bbox_min, bbox_max = shape.get_bounding_box()
    
    # 2. Compute Grid Origin
    # Floor(min / voxel_size) - 1, then multiply by voxel_size
    origin_x = (math.floor(bbox_min[0] / voxel_size) - 1) * voxel_size
    origin_y = (math.floor(bbox_min[1] / voxel_size) - 1) * voxel_size
    origin_z = (math.floor(bbox_min[2] / voxel_size) - 1) * voxel_size
    origin = (origin_x, origin_y, origin_z)
    
    # 3. Compute Grid Dimensions
    extents = (
        bbox_max[0] - bbox_min[0],
        bbox_max[1] - bbox_min[1],
        bbox_max[2] - bbox_min[2]
    )
    
    # Ceiling(extent / voxel_size) + 2 for padding
    width = math.ceil(extents[0] / voxel_size) + 2
    height = math.ceil(extents[1] / voxel_size) + 2
    depth = math.ceil(extents[2] / voxel_size) + 2
    
    # 4. Allocate Storage
    num_voxels = width * height * depth
    # Resize to nearest power of 2 >= num_voxels
    # Bitwise rounding up: 1 << (num_voxels - 1).bit_length() if num_voxels > 0 else 1
    if num_voxels > 0:
        capacity = 1 << (num_voxels - 1).bit_length()
    else:
        capacity = 1
    voxels = [0.0] * capacity
    
    # 5. Voxelize
    for z in range(depth):
        for y in range(height):
            for x in range(width):
                # Compute world-space center
                center_x = origin_x + (x + 0.5) * voxel_size
                center_y = origin_y + (y + 0.5) * voxel_size
                center_z = origin_z + (z + 0.5) * voxel_size
                world_pos = (center_x, center_y, center_z)
                
                # Transform to local space
                local_pos = shape.world_to_local(world_pos)
                
                # Evaluate SDF
                sdf_value = shape.evaluate_sdf(local_pos)
                
                # Store
                index = (z * width * height) + (y * width) + x
                voxels[index] = sdf_value
                
    return {
        'voxels': voxels,
        'width': width,
        'height': height,
        'depth': depth,
        'origin': origin
    }
```

## Subtopics

### [VoxelizationGrid](6601-voxelizationgrid.md)
`VoxelizationGrid` is a data structure representing an explicit voxelization grid, defining bounds, grid dimensions, and voxel sizes in 3D space. It solves the problem of converting arbitrary mesh bounding boxes into a discrete, aligned 3D grid suitable for dense volume storage, ensuring that grid indices map consistently to world coordinates. It is chosen when a reusable grid structure with explicit coordinate mapping is needed, distinct from simple array storage. Link: [VoxelizationGrid](6601-voxelizationgrid.md).

### [Instanced Voxel Rendering](10592-instanced-voxel-rendering.md)
Instanced Voxel Rendering is a technique for visualizing sparse voxel grids by generating a single unit cube mesh and drawing it multiple times at different positions using OpenGL instanced rendering, thereby reducing memory overhead compared to storing full geometry for every voxel. It differs from [VoxelizationGrid](6601-voxelizationgrid.md) by explicitly leveraging GPU instancing (`glDrawElementsInstanced`) to render discrete voxel positions, whereas VoxelizationGrid may imply a denser or differently structured grid representation without necessarily optimizing for instance count reduction via this specific API call pattern. Link: [Instanced Voxel Rendering](10592-instanced-voxel-rendering.md).

### Shared-grid Voxelization
Shared-grid Voxelization is a workflow where multiple meshes are voxelized onto a single, explicitly defined voxel grid, typically defined by the largest or outer mesh [S3, unofficial]. It is chosen when aligning multiple geometric components (e.g., inner and outer shells) into a common coordinate system for unified processing.
-   **Steps:**
    1.  Build shared grid: Load outer mesh. Call `build_voxelization_grid(outer_mesh, voxel_size=voxel_size, pixel_size=pixel_size)` to create `shared_grid` [S3, unofficial].
    2.  Calculate translation vector `translation_xyz = (outer_mesh.center - inner_mesh.center).astype(np.float32)` [S3, unofficial].
    3.  Voxelize outer mesh: Call `voxelize_on_grid(outer_mesh, grid=shared_grid, mode="solid")` to produce `outer_grid` [S3, unofficial].
    4.  Voxelize inner mesh: Call `voxelize_on_grid(inner_mesh, grid=shared_grid, mode="solid", translation_xyz=translation_xyz)` to produce `inner_grid`, applying the translation to align it with the outer mesh's coordinate system [S3, unofficial].
-   **Parameters:** `mode` (str, default "solid"): Passed to `voxelize_on_grid`, specifies solid voxelization [S3, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the grid, as each voxel requires one SDF evaluation or occupancy test [S1, S2, unofficial].
-   **Memory Complexity:** $O(N)$ for the voxel array. For 1D float arrays, this is $4N$ bytes. For 3D bool arrays, this is $N$ bytes (inefficient due to byte-per-bool storage) [S1, S2, unofficial].
-   **Measured Performance:** Not given in the sources.
-   **Scaling:** Linear with grid resolution. Power-of-2 allocation may cause memory spikes for grid sizes just above a power of 2 [S1, unofficial].
-   **Strengths:** Simple indexing, fast random access, compatible with standard volume rendering pipelines [S1, unofficial].
-   **Limitations:** Memory inefficient for sparse data (uses dense storage) [S2, unofficial]. Out-of-bounds access returns a sentinel value rather than failing, which may hide bugs if not checked [S1, unofficial].
-   **When to use:** Dense volume representation, SDF computation, when grid dimensions are known and manageable.
-   **When not to use:** Highly sparse scenes where sparse voxel octrees or hash grids would be more memory efficient.

## Background
The method originates from implementations in Java-based isosurface extraction tools [S1, unofficial] and C++ voxelization utilities [S2, unofficial], as well as Python-based voxelization workflows [S3, unofficial]. It is used in applications requiring the conversion of mesh data into volume data for rendering, solid modeling, or physics simulation. The specific SDF voxelization approach with power-of-2 allocation and sentinel values for out-of-bounds access is documented in the Chickenkeeper/IsosurfaceExtraction repository [S1, unofficial]. The 3D boolean pointer array approach is documented in the antonmartynov/OBJ-Solidizer-And-Voxelizer repository [S2, unofficial]. The shared-grid workflow is documented in the hsafari68/Voxelerate repository [S3, unofficial].
