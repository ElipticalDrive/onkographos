# Packed Voxel Cell Encoding


## Overview
Packed Voxel Cell Encoding is a bitstream method that compresses a voxel's 3D integer coordinate and the axis along which a ray exited that voxel into a single 32-bit unsigned integer. It solves the problem of efficiently returning hit voxel data from a ray marcher while preserving the geometric context required for normal estimation and subsequent traversal. It differs from its parent [Bitstream Voxel Position Encoding](2371-bitstream-voxel-position-encoding.md) by explicitly storing the crossing axis alongside the coordinate, enabling direct reconstruction of the intersection point and surface normal without additional ray-marching steps.

## How it works
**Inputs:** A voxel coordinate $(x, y, z)$ where each component is a signed 16-bit integer, and a crossing axis index $a \in \{0, 1, 2\}$ representing the X, Y, or Z axis respectively.
**Output:** A single 32-bit unsigned integer (`uint`).

**Data Structure Layout:**
The 32-bit integer is divided into four fields:
- Bits 0–9 (10 bits): X coordinate.
- Bits 10–19 (10 bits): Y coordinate.
- Bits 20–29 (10 bits): Z coordinate.
- Bits 30–31 (2 bits): Crossing axis index.

**Constraints:**
The coordinate components must fit within 10 bits. Since 10 bits can represent values from $-512$ to $511$ (if interpreted as signed) or $0$ to $1023$ (if unsigned), the implementation must handle the sign extension or offset appropriately. The source code implies the coordinates are stored as signed values within these bits, likely using two's complement representation for the lower 10 bits, or the grid is constrained to a specific range. The axis index is limited to 0, 1, or 2.

**Pseudocode:**
The following Python-like pseudocode demonstrates packing and unpacking, including the reconstruction of the intersection point and normal as described in the source.

```python
import numpy as np

def pack_voxel_cell(coord: tuple[int, int, int], axis: int) -> int:
    """
    Pack voxel coordinate and crossing axis into a 32-bit uint.
    
    Args:
        coord: Tuple (x, y, z) of signed 16-bit integers.
        axis: Integer 0, 1, or 2 indicating the crossing axis.
        
    Returns:
        32-bit unsigned integer.
    """
    x, y, z = coord
    
    # Mask to 10 bits. Assuming two's complement for signed values.
    # In C/C++, casting to uint16_t and then shifting handles this naturally.
    # Here we simulate the bit layout: bits 0-9 for x, 10-19 for y, 20-29 for z.
    # We assume the input coordinates are already within the representable range.
    
    packed = 0
    packed |= (x & 0x3FF) << 0   # Bits 0-9
    packed |= (y & 0x3FF) << 10  # Bits 10-19
    packed |= (z & 0x3FF) << 20  # Bits 20-29
    packed |= (axis & 0x3) << 30 # Bits 30-31
    
    return packed

def unpack_voxel_cell(packed_cell: int) -> tuple[tuple[int, int, int], int]:
    """
    Unpack voxel coordinate and crossing axis from a 32-bit uint.
    
    Args:
        packed_cell: 32-bit unsigned integer.
        
    Returns:
        Tuple of (coord: (x, y, z), axis: int).
    """
    # Extract axis
    axis = (packed_cell >> 30) & 0x3
    
    # Extract coordinates
    x = (packed_cell >> 0) & 0x3FF
    y = (packed_cell >> 10) & 0x3FF
    z = (packed_cell >> 20) & 0x3FF
    
    # Convert back to signed 16-bit integers if necessary
    # If the 10th bit is set, it's negative in two's complement
    if x & 0x200: x -= 0x400
    if y & 0x200: y -= 0x400
    if z & 0x200: z -= 0x400
    
    return ((x, y, z), axis)

def reconstruct_intersection(ray_origin: np.ndarray, ray_dir: np.ndarray, packed_cell: int) -> tuple[np.ndarray, np.ndarray]:
    """
    Reconstruct the intersection point and normal from the packed cell.
    Based on [S1, unofficial].
    """
    coord, axis = unpack_voxel_cell(packed_cell)
    cell = np.array(coord, dtype=np.float32)
    axis_index = axis
    
    # Axis mask: vector with 1.0 at the crossing axis, 0.0 elsewhere
    axis_mask = np.array([
        1.0 if axis_index == 0 else 0.0,
        1.0 if axis_index == 1 else 0.0,
        1.0 if axis_index == 2 else 0.0
    ], dtype=np.float32)
    
    # Normal is opposite to the ray direction component along the crossing axis
    # sign() returns -1, 0, or 1
    normal = -np.sign(ray_dir) * axis_mask
    
    # Entry plane: the face of the voxel the ray entered
    # If ray_dir component is negative, the entry plane is at cell + 1
    # If positive, entry plane is at cell
    entry_plane = cell + (ray_dir < 0.0).astype(np.float32)
    
    # Distance to the entry plane along the ray
    # dot(entry_plane - ray_origin, axis_mask) / dot(ray_dir, axis_mask)
    # Note: dot(ray_dir, axis_mask) is simply the component of ray_dir along the axis
    distance = np.dot(entry_plane - ray_origin, axis_mask) / np.dot(ray_dir, axis_mask)
    
    position = ray_origin + distance * ray_dir
    
    return position, normal
```

**Edge Cases and Pitfalls:**
- **Coordinate Range:** The 10-bit storage limits the coordinate range. If coordinates exceed $\pm 511$, overflow occurs. The implementation must ensure the voxel grid fits within this range or use a different encoding for larger grids.
- **Axis Index:** The axis index must be strictly 0, 1, or 2. Invalid values will corrupt the normal calculation.
- **Ray Direction Zero:** If `ray_dir` has a zero component along the crossing axis, the distance calculation involves division by zero. This should not happen in a valid ray-marching step where a voxel exit is detected.

## Subtopics

## Operating characteristics
**Time Complexity:** $O(1)$ for packing and unpacking. The reconstruction of the intersection point is also $O(1)$ with a few arithmetic operations.
**Memory Complexity:** $O(1)$ per voxel hit. The packed cell uses exactly 32 bits.
**Performance:** This method is highly efficient for GPU ray marching, as it minimizes memory bandwidth by storing both position and geometric context in a single register. The reconstruction of the normal and intersection point avoids additional ray-marching steps, reducing latency.
**Strengths:** Compact representation, fast reconstruction of geometric data, simple bitwise operations.
**Limitations:** Limited coordinate range (10 bits per axis). Not suitable for very large voxel grids without hierarchical indexing or offsetting.

## Background
Packed Voxel Cell Encoding is used in the vxray renderer [S1, unofficial]. It is part of a family of bitstream voxel position encoding methods designed for efficient voxel terrain rendering. The method allows the ray marcher to return a compact representation of the hit voxel, which can then be used for shading, normal estimation, and further traversal.
