# Volume Data Structure and Indexing

Also called: IJK to RAS coordinate mapping, Volume class

## Overview
The Volume data structure stores 3D scalar data in a contiguous linear array (TypedArray) and manages the bidirectional mapping between voxel indices (IJK) and physical coordinates (RAS) [S1, unofficial]. It differs from sparse representations by assuming a fixed, dense grid where memory is allocated for the entire bounding box, making it suitable for regular medical or scientific datasets [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A buffer of scalar values (e.g., `ArrayBuffer`), dimensions $N_x, N_y, N_z$ (denoted `xLength`, `yLength`, `zLength`), and optional physical transformation parameters (spacing, offset, rotation matrix).
*   **Output:** A `Volume` object providing methods to access voxel data by IJK or linear index, and to transform coordinates between voxel space and physical space.

**Data Structures:**
The `Volume` object maintains the following fields [S1, unofficial]:
*   `this.data`: A `TypedArray` (e.g., `Float32Array`, `Uint8Array`) storing the voxel values.
*   `this.xLength`, `this.yLength`, `this.zLength`: Integer dimensions of the grid.
*   `this.spacing`: An array of 3 numbers $[s_x, s_y, s_z]$, default $[1, 1, 1]$.
*   `this.offset`: An array of 3 numbers $[o_x, o_y, o_z]$, default $[0, 0, 0]$.
*   `this.matrix`: A $3 \times 3$ rotation matrix $M$, default identity.
*   `this.inverseMatrix`: The inverse of `this.matrix`.
*   `this.segmentation`: Boolean flag, default `false`.
*   `this.sliceList`: Array of `VolumeSlice` objects associated with this volume.
*   `this.min`, `this.max`: Scalar values representing the minimum and maximum data values in the volume.
*   `lowerThreshold`, `upperThreshold`: Values defining the range of voxels included in slices. Default `lowerThreshold` is $-\infty$, `upperThreshold` is $+\infty$. Changing these triggers a geometry update on all associated slices [S1, unofficial].

**Indexing Formulas:**
The storage layout is row-major, where the I dimension (x-axis) varies fastest, followed by J (y-axis), then K (z-axis) [S1, unofficial].

1.  **Forward Indexing (IJK to Linear):**
    Given voxel coordinates $(i, j, k)$, the linear index $idx$ in `this.data` is:
    $$
    idx = k \cdot N_x \cdot N_y + j \cdot N_x + i
    $$
    Where $i \in [0, N_x - 1]$, $j \in [0, N_y - 1]$, $k \in [0, N_z - 1]$ [S1, unofficial].

2.  **Reverse Indexing (Linear to IJK):**
    Given a linear index $idx$, the coordinates are:
    $$
    k = \lfloor idx / (N_y \cdot N_x) \rfloor
    $$
    $$
    j = \lfloor (idx - k \cdot N_y \cdot N_x) / N_x \rfloor
    $$
    $$
    i = idx - k \cdot N_y \cdot N_x - j \cdot N_x
    $$
    Note: The source formula for $j$ uses subtraction of the z-component contribution before division, which is equivalent to modulo arithmetic [S1, unofficial].

**Physical Coordinate Transformation:**
To map a voxel index to physical space (RAS):
1.  Convert linear index to $(i, j, k)$ using reverse indexing.
2.  Apply spacing to get scaled voxel coordinates:
    $$
    v_x = i \cdot s_x, \quad v_y = j \cdot s_y, \quad v_z = k \cdot s_z
    $$
3.  Apply rotation matrix $M$:
    $$
    \begin{bmatrix} x' \\ y' \\ z' \end{bmatrix} = M \begin{bmatrix} v_x \\ v_y \\ v_z \end{bmatrix}
    $$
4.  Apply offset $O$:
    $$
    P = \begin{bmatrix} x' \\ y' \\ z' \end{bmatrix} + \begin{bmatrix} o_x \\ o_y \\ o_z \end{bmatrix}
    $$
    If no rotation is needed, $M$ is the identity matrix [S1, unofficial].

**Pseudocode:**
```python
class Volume:
    def __init__(self, data_buffer, x_length, y_length, z_length, 
                 spacing=None, offset=None, matrix=None):
        # Validate buffer size
        expected_size = x_length * y_length * z_length
        if len(data_buffer) != expected_size:
            raise Error("Error in Volume constructor, lengths are not matching arrayBuffer size")
        
        # Check for unsupported 64-bit types
        if data_buffer.dtype in [int64, uint64]:
            raise Error("Error in Volume constructor : this type is not supported in JavaScript")

        self.data = data_buffer
        self.xLength = x_length
        self.yLength = y_length
        self.zLength = z_length
        
        # Defaults
        self.spacing = spacing if spacing else [1, 1, 1]
        self.offset = offset if offset else [0, 0, 0]
        self.matrix = matrix if matrix else IdentityMatrix3()
        self.inverseMatrix = self.matrix.inverse()
        self.segmentation = False
        self.sliceList = []
        self.lowerThreshold = -Infinity
        self.upperThreshold = Infinity
        
        # Compute min/max, ignoring NaN
        self.min, self.max = self._compute_min_max()

    def _compute_min_max(self):
        min_val = Infinity
        max_val = -Infinity
        for val in self.data:
            if not isnan(val):
                if val < min_val: min_val = val
                if val > max_val: max_val = val
        return min_val, max_val

    def index_from_ijk(self, i, j, k):
        return k * self.xLength * self.yLength + j * self.xLength + i

    def ijk_from_index(self, idx):
        k = floor(idx / (self.yLength * self.xLength))
        remainder = idx - k * self.yLength * self.xLength
        j = floor(remainder / self.xLength)
        i = remainder - j * self.xLength
        return (i, j, k)

    def get_voxel(self, i, j, k):
        idx = self.index_from_ijk(i, j, k)
        return self.data[idx]

    def set_voxel(self, i, j, k, value):
        idx = self.index_from_ijk(i, j, k)
        self.data[idx] = value

    def ijk_to_ras(self, i, j, k):
        # 1. Scale by spacing
        vx = i * self.spacing[0]
        vy = j * self.spacing[1]
        vz = k * self.spacing[2]
        
        # 2. Apply rotation matrix M
        # Assuming M is a 3x3 matrix represented as a flat list or nested list
        # x' = M[0][0]*vx + M[0][1]*vy + M[0][2]*vz
        # y' = M[1][0]*vx + M[1][1]*vy + M[1][2]*vz
        # z' = M[2][0]*vx + M[2][1]*vy + M[2][2]*vz
        x_prime = dot(self.matrix.row(0), [vx, vy, vz])
        y_prime = dot(self.matrix.row(1), [vx, vy, vz])
        z_prime = dot(self.matrix.row(2), [vx, vy, vz])
        
        # 3. Apply offset
        return [x_prime + self.offset[0], 
                y_prime + self.offset[1], 
                z_prime + self.offset[2]]

    def map(self, callback):
        """Applies a callback function to every voxel in place."""
        for idx in range(len(self.data)):
            self.data[idx] = callback(self.data[idx], idx)
```

**Edge Cases and Pitfalls:**
*   **Buffer Size Mismatch:** If the input `arrayBuffer` size does not equal $N_x \cdot N_y \cdot N_z$, an error is thrown [S1, unofficial].
*   **Data Type Limitations:** JavaScript TypedArrays do not support 64-bit integers. Attempting to construct a Volume with `int64` or `uint64` data throws an error [S1, unofficial].
*   **NaN Handling:** Min/Max calculations must explicitly ignore NaN values [S1, unofficial].

## Operating characteristics
*   **Memory Complexity:** $O(N_x \cdot N_y \cdot N_z)$, as the entire grid is stored in a contiguous array.
*   **Time Complexity:** Indexing operations (IJK to linear, linear to IJK) are $O(1)$. Physical coordinate transformation is $O(1)$ (constant number of arithmetic operations).
*   **Strengths:** Fast random access to any voxel; simple memory layout; efficient for dense data where most voxels are occupied.
*   **Limitations:** High memory consumption for large volumes with sparse data; fixed grid dimensions require padding or cropping for irregular shapes.
*   **When to use:** Regular, dense volumetric data (e.g., CT/MRI scans) where fast voxel access and simple indexing are required.
*   **When not to use:** Sparse volumes where most voxels are empty/background; highly irregular geometries.

## Background
The `Volume` class is part of the `webgl_volume_demo` project by PeterC-DLS [S1, unofficial]. It implements a standard dense grid representation common in medical imaging and scientific visualization, utilizing the IJK-to-RAS coordinate transformation paradigm prevalent in DICOM and NIfTI data handling.
