# Texture Coordinate Conversion

Also called: local2tex

## Overview
Texture Coordinate Conversion is a utility function that transforms local or world space coordinates ($P$) into normalized texture coordinates ($uv$) suitable for volume sampling. It solves the problem of mapping discrete voxel grid indices to the continuous $[0, 1]$ range expected by 3D texture samplers. It differs from its parent, World to UVW Normalization, by applying specific shader-space adjustments: an inverse volume size scaling, a 0.5 offset to center the sampling in the voxel, and a Y-axis flip to align with texture coordinate conventions [S1, unofficial].

## How it works
**Inputs:**
- $P$: Input position vector (float3), typically in local or world space depending on the caller's context.
- $g\_cf3InvVolSize$: Pre-computed inverse dimensions of the volume grid (float3), where each component is $1 / \text{dimension}$.

**Outputs:**
- $uv$: Normalized texture coordinates (float3) in the range $[0, 1]$.

**Data Structures:**
- No complex data structures are required. The operation relies on vector arithmetic.

**Steps:**
1. **Scale and Offset:** Multiply the input position $P$ by the inverse volume size $g\_cf3InvVolSize$ and add a constant offset of $0.5$. This maps the integer voxel indices to the center of each voxel cell in normalized space.
   $$ uv = P \times g\_cf3InvVolSize + 0.5 $$
2. **Flip Y-Axis:** Invert the Y component of the resulting vector to match the texture coordinate system where Y increases downwards (or upwards, depending on the specific graphics API convention, but here explicitly flipped).
   $$ uv.y = 1 - uv.y $$

**Formulas:**
Let $P = (P_x, P_y, P_z)$ and $g\_cf3InvVolSize = (S_x, S_y, S_z)$.
$$ uv_x = P_x \cdot S_x + 0.5 $$
$$ uv_y = 1 - (P_y \cdot S_y + 0.5) $$
$$ uv_z = P_z \cdot S_z + 0.5 $$

**Parameters:**
- $g\_cf3InvVolSize$: Inverse dimensions of the volume. For a volume of size $N_x \times N_y \times N_z$, $S_x = 1/N_x$, $S_y = 1/N_y$, $S_z = 1/N_z$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Precision:** If $P$ is exactly at the boundary of the volume, the resulting $uv$ may be slightly outside $[0, 1]$ due to floating-point precision. Texture samplers usually clamp or wrap, but explicit clamping may be required for correctness [G].
- **Coordinate System Mismatch:** The Y-flip assumes a specific relationship between the voxel grid's Y-axis and the texture's Y-axis. If the volume data is stored with a different orientation, this flip may need to be removed or applied to a different axis [G].

**Pseudocode:**
```python
def texture_coordinate_conversion(P: Vector3, g_cf3InvVolSize: Vector3) -> Vector3:
    """
    Converts local/world space coordinates P to texture coordinates uv.
    
    Args:
        P: Input position vector (float3).
        g_cf3InvVolSize: Inverse dimensions of the volume (float3).
        
    Returns:
        uv: Normalized texture coordinates (float3).
    """
    # Step 1: Scale by inverse volume size and add 0.5 offset
    uv = P * g_cf3InvVolSize + 0.5
    
    # Step 2: Flip the Y coordinate
    uv.y = 1.0 - uv.y
    
    return uv
```

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(1)$ per coordinate conversion. It involves a few vector multiplications and additions.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Performance:** Extremely fast, suitable for execution in pixel/fragment shaders or compute kernels for every sample point.
- **Strengths:** Simple, deterministic, and directly compatible with standard 3D texture sampling hardware.
- **Limitations:** Only handles uniform scaling based on the inverse volume size. Does not account for non-uniform scaling or anisotropic voxels unless $g\_cf3InvVolSize$ is pre-computed to include those factors [G].

## Background
This method is derived from the Dynamic Volume Raycasting implementation by pengliu916, which uses a fixed-size voxel grid (e.g., $256 \times 256 \times 256$) and requires mapping ray intersection points to texture coordinates for trilinear interpolation [S1, unofficial]. The specific formula with the 0.5 offset and Y-flip is a common convention in voxel-based rendering to ensure samples are taken from the center of the voxel cells.
