# Texture Coordinate Conversion
Also called: local2tex
## Overview
Texture Coordinate Conversion is a utility function that transforms local or world space coordinates ($P$) into normalized texture coordinates ($uv$) suitable for 3D volume sampling. It solves the problem of mapping continuous spatial positions to the discrete $[0, 1]$ range of a 3D texture unit. It differs from its parent, World to UVW Normalization, by explicitly handling the coordinate system conventions required by graphics APIs, specifically the inversion of the Y-axis and the application of a half-voxel offset to align with texture center sampling [S1, unofficial].
## How it works
**Inputs and Outputs:**
- Input: A 3D position vector $P$ (typically in local or object space) and the inverse dimensions of the volume grid $g_{cf3InvVolSize}$.
- Output: A 3D texture coordinate vector $uv$ in the range $[0, 1]$.

**Data Structures:**
- $g_{cf3InvVolSize}$: A `float3` containing the inverse of the volume dimensions $(1/N_x, 1/N_y, 1/N_z)$. This pre-computed value avoids division during runtime [S1, unofficial].

**Steps:**
1.  **Scale and Offset:** Multiply the input position $P$ by the inverse volume size and add a constant offset of $0.5$. This maps the integer voxel indices (assuming $0 \dots N-1$) to the center of the texels in the $[0, 1]$ range.
    $$ uv = P \times g_{cf3InvVolSize} + 0.5 $$
2.  **Flip Y-Axis:** Invert the Y component of the resulting texture coordinate. This accounts for the difference between the typical 3D graphics coordinate system (where Y is up) and the texture coordinate system (where V is often down or inverted relative to image space).
    $$ uv.y = 1 - uv.y $$

**Pseudocode:**
```python
def texture_coordinate_conversion(P: Vector3, inv_vol_size: Vector3) -> Vector3:
    """
    Converts a local/world space position P to texture coordinates.
    
    Args:
        P: Input position vector (float3).
        inv_vol_size: Inverse volume dimensions (float3), precomputed as (1/Nx, 1/Ny, 1/Nz).
        
    Returns:
        uv: Texture coordinates in [0, 1] range.
    """
    # Step 1: Scale by inverse volume size and add 0.5 offset
    uv = P * inv_vol_size + Vector3(0.5, 0.5, 0.5)
    
    # Step 2: Flip the Y coordinate
    uv.y = 1.0 - uv.y
    
    return uv
```

**Parameters:**
- $g_{cf3InvVolSize}$: Inverse dimensions of the volume. Typical values depend on the volume resolution (e.g., for a $256^3$ volume, this is $1/256 \approx 0.00390625$) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Precision:** If $P$ is exactly at the boundary of the volume (e.g., $N-1$), the scaling and offset should result in $1.0$. Floating-point precision errors might cause values slightly outside $[0, 1]$, requiring clamping if the texture sampler does not handle out-of-bounds coordinates gracefully [G].
- **Coordinate System Mismatch:** Failing to flip the Y-axis results in vertically inverted textures, which is a common pitfall when porting between different graphics APIs or data formats [S1, unofficial].

## Subtopics

### Voxel Center Alignment Offset
A variant that offsets the camera position in texture space by half a unit to align ray origins with voxel centers. It assumes texture coordinates range from $0$ to $1$. The camera position is computed in object space using the inverse model-view matrix, and then the offset $(0.5, 0.5, 0.5)$ is added. Formula: $\mathbf{p}_{\text{tex}} = \mathbf{p}_{\text{obj}} + (0.5, 0.5, 0.5)$ [S2, unofficial].

### Texture Coordinate Generation for Volume
Generates texture coordinates for the 8 corners of a volume box to map a 3D texture correctly, accounting for half-texel offsets. For a full volume of size $(S_x, S_y, S_z)$, half-texel offsets are $dx = 0.5/S_x$, $dy = 0.5/S_y$, $dz = 0.5/S_z$. The corner coordinates are $x_0 = dx, x_1 = 1-dx$, etc. The 8 vertices are assigned in the order: $(x_0,y_0,z_1), (x_1,y_0,z_1), (x_1,y_1,z_1), (x_0,y_1,z_1), (x_0,y_0,z_0), (x_1,y_0,z_0), (x_1,y_1,z_0), (x_0,y_1,z_0)$. For a sub-region defined by min/max corners and image size, the coordinates are normalized and shifted by the half-texel offsets similarly. A known pitfall is uncertainty regarding the specific assignment of $z_1$ vs $z_0$ for the front/back faces in some implementations [S3, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(1)$ per coordinate conversion.
- Memory: $O(1)$ for the pre-computed inverse volume size vector.

**Measured Performance:**
- The operation is extremely lightweight, consisting of a few floating-point multiplications and additions. It is typically executed per-vertex or per-ray-step in shaders.

**Scaling:**
- Scales linearly with the number of conversions required. The pre-computation of $g_{cf3InvVolSize}$ ensures that the conversion cost is independent of the volume resolution.

**Strengths and Limitations:**
- Strengths: Simple, fast, and corrects for common coordinate system discrepancies (Y-flip, center alignment).
- Limitations: Assumes a specific voxel indexing scheme (integer indices mapped to texture centers). Does not handle non-uniform scaling or non-axis-aligned volumes without additional transformation matrices.

**When to Use:**
- Use when sampling 3D textures from ray-casting or volume rendering shaders where the input coordinates are in local/object space and need to be mapped to the texture's normalized coordinate system.

## Background
Originating from early dynamic volume raycasting implementations, this method is a standard utility in 3D graphics programming for interfacing between geometric space and texture space. It addresses the historical differences between how 3D engines represent world coordinates and how texture hardware expects normalized coordinates. The specific Y-flip and 0.5 offset pattern is documented in early GPU-based volume rendering tutorials and source code [S1, unofficial].
