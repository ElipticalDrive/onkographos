# Spatial Sorting Layout

Also called: Directional sort, Spatial layout

## Overview
Spatial sorting is a data layout technique for tetrahedral meshes that reorders vertices and cells to maximize spatial coherence along a dominant principal direction [S1]. It solves the problem of poor cache locality and streaming efficiency in large meshes by ensuring that geometrically adjacent elements are stored contiguously in memory [S1]. Unlike general-purpose spatial indexing, it relies on a single global sorting direction, making it distinct from bricking or space-filling curve methods [S1].

## How it works
The method transforms a tetrahedral mesh into a streamable format through a sequence of file-based sorts and reindexing operations [S1].

**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh defined by a vertex list $V$ and a cell list $C$, where each cell $c \in C$ references four vertex indices.
*   **Output:** A new interleaved file containing vertices and cells in a spatially sorted order, along with a mapping file for reindexing [S1].

**Data Structures:**
1.  **Vertex File:** Stores vertex attributes. Initially indexed by original position $i$.
2.  **Mapping File:** A list of integers mapping new index $j$ to old index $i$ (or vice versa, as required for reindexing).
3.  **Cell File:** Stores the four vertex indices for each tetrahedron.
4.  **Interleaved File:** The final output where each cell is written immediately after the vertex with the largest index within that cell [S1].

**Steps:**
1.  **Identify Sorting Direction:** Determine a spatial direction vector $\vec{d}$ that crosses the maximum number of tetrahedra [S1].
2.  **Sort Vertices:** Perform an out-of-core sort of the vertices based on their projection onto $\vec{d}$ [S1].
    *   Let the sorted vertices be $v'_0, v'_1, \dots, v'_{N-1}$.
    *   Create a mapping file that records the permutation from the original ordering to this new ordering [S1].
3.  **Reindex Cells:** Read the original cell file and update all vertex indices using the mapping file created in Step 2. Write the reindexed cells to a new cell file [S1].
4.  **Sort Cells:** Sort the cell file based on the largest vertex index contained within each cell [S1].
    *   For a cell $c$ with vertex indices $\{i_1, i_2, i_3, i_4\}$, the sort key is $k_c = \max(i_1, i_2, i_3, i_4)$ [S1].
5.  **Interleave:** Read the sorted vertex file and the sorted cell file simultaneously.
    *   For each cell $c$ in the sorted cell file, write the cell data to the output file immediately after writing the vertex corresponding to $k_c$ [S1].

**Pseudocode:**
```python
def spatial_sort_layout(vertices, cells, direction):
    # Step 1 & 2: Sort vertices and create mapping
    # Project vertices onto direction
    projections = [dot(v.position, direction) for v in vertices]
    
    # Create index list and sort by projection
    indices = list(range(len(vertices)))
    indices.sort(key=lambda i: projections[i])
    
    # Create mapping: new_index -> old_index
    # If we want to map old index i to new position j:
    mapping = [0] * len(vertices)
    for new_idx, old_idx in enumerate(indices):
        mapping[old_idx] = new_idx
        
    # Step 3: Reindex cells
    reindexed_cells = []
    for cell in cells:
        new_cell = [mapping[v_idx] for v_idx in cell]
        reindexed_cells.append(new_cell)
        
    # Step 4: Sort cells by max vertex index
    # Key is the maximum index in the cell
    reindexed_cells.sort(key=lambda cell: max(cell))
    
    # Step 5: Interleave
    output_file = []
    
    # We need to write vertices in the sorted order (indices)
    # And cells in the sorted order (reindexed_cells)
    
    # To interleave correctly, we iterate through the sorted cells.
    # For each cell, we must ensure the vertex with the max index has been written.
    # Since cells are sorted by max index, and vertices are sorted by projection,
    # we can maintain a pointer to the next vertex to write.
    
    vertex_ptr = 0
    for cell in reindexed_cells:
        max_idx = max(cell)
        
        # Write all vertices up to and including the max_idx of the current cell
        while vertex_ptr <= max_idx:
            output_file.append(vertices[indices[vertex_ptr]])
            vertex_ptr += 1
            
        output_file.append(cell)
        
    return output_file
```

**Edge Cases and Pitfalls:**
*   **Dominant Direction:** The method works especially well only for meshes with a dominant principal direction [S1].
*   **Non-Dominant Meshes:** For meshes lacking a dominant direction (e.g., spheres), this layout is inefficient [S1].

## Subtopics

### Density-sorted point storage
Storing points sorted by density results in the least spatial coherence among point-based layouts [S2, book]. Points are sorted by their density value, allowing irrelevant points (assigned transparent values in transfer functions) to be quickly culled from the rendering pipeline [S2, book]. This approach requires storing $(x,y,z)$ coordinates and possibly gradient vectors alongside the points because neighborhood relations are completely lost [S2, book]. All points must be transformed to view space before culling for occlusion or viewing pyramid exclusion [S2, book]. During rendering, points must be depth-sorted or tossed into depth bins [S2, book]. A compromise involves sorting points by density within volume slices only, providing implicit depth-ordering when used with an axis-aligned sheet-buffer method [S2, book].

## Operating characteristics
*   **Time Complexity:** Dominated by the out-of-core sorts. Sorting $N$ vertices and $M$ cells takes $O(N \log N + M \log M)$ [S1].
*   **Memory Complexity:** Requires storage for the vertex file, cell file, mapping file, and the interleaved output file. Out-of-core sorting minimizes RAM usage [S1].
*   **Performance:** Highly efficient for streaming and cache coherence on meshes with a strong principal direction [S1].
*   **Limitations:** Poor performance on isotropic or complex topologies without a dominant direction [S1].

## Background
The technique was analyzed for streaming simplification of tetrahedral meshes, building on work by Wu and Kobbelt for triangle mesh simplification [S1]. It is cited in the context of optimizing memory access patterns for large volumetric datasets [S1].
