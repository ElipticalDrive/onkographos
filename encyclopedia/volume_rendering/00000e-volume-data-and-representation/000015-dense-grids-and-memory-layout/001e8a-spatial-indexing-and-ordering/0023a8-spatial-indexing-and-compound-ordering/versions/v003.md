# Spatial Indexing and Compound Ordering

Also called: Compound Ordering Index, Space-Filling Curve Indexing

## Overview
Spatial Indexing and Compound Ordering maps multidimensional data elements, each defined by discrete non-spatial coordinates (e.g., time, channel) and spatial coordinates, into a 1D linear array to optimize data access [S1, unofficial]. It solves the problem of efficiently fetching subsets of multidimensional volumetric data by ensuring that points sharing discrete attributes or close in spatial distance are stored contiguously [S1, unofficial]. It differs from simple [Arithmetic Strides](1797-spatial-indexing-and-ordering.md) by using space-filling curves for spatial locality, and from pure [Morton Code Encoding](1700-morton-code-encoding-decoding.md) by hierarchically sorting discrete dimensions as the most significant keys before applying spatial ordering within slices [S1, unofficial].

## How it works
**Inputs:**
- A set of data elements, each defined by a discrete non-spatial coordinate $d$ (e.g., time step, channel) and a spatial coordinate vector $\mathbf{x}$ [S1, unofficial].
- A chunking strategy defining the spatial extent of each chunk [S1, unofficial].

**Outputs:**
- A linear array of chunks, sorted according to the compound ordering [S1, unofficial].
- Metadata containing precomputed Axis-Aligned Bounding Boxes (AABBs) for each chunk [S1, unofficial].

**Data Structures:**
- **Chunk:** A contiguous block of data elements [S1, unofficial].
- **Metadata:** For each chunk, stores an AABB representing the extent of the data it contains across all dimensions (spatial $\pm$ tolerance, and discrete slice positions) [S1, unofficial].

**Algorithm Steps:**

1.  **Sort by Discrete Dimensions:**
    Group elements by their discrete non-spatial coordinates $d$ and sort the groups such that elements with the same $d$ are contiguous in memory [S1, unofficial].

2.  **Apply Space-Filling Curve (SFC) within Slices:**
    Within each group of identical discrete coordinate $d$, sort the elements based on their spatial coordinates $\mathbf{x}$ using a space-filling curve [S1, unofficial]. Hilbert curves are used as the default for serialization due to superior spatial locality, while Morton (Z-order) curves are used for in-memory reordering during fitting due to lower computational cost [S1, unofficial].

3.  **Chunking:**
    Partition the sorted linear array into chunks of fixed size (e.g., 1 MB) [S1, unofficial]. Because the non-displayed dimensions lead the ordering, rows of one value of a discrete axis are contiguous, so a time step fetches chunks of the new timepoint plus prefetched first chunks of neighbors [S1, unofficial]. A chunk that spans several timepoints brings its neighbors along, and a level-of-detail ladder built per timepoint keeps the property rung by rung [S1, unofficial].

4.  **Precompute Metadata (AABBs):**
    Precompute chunk-level axis-aligned bounding boxes (AABBs) as metadata [S1, unofficial].

5.  **Query and Fetch:**
    At load and on every view change, perform a fast AABB test against each chunk’s precomputed nD extent (slice position $\pm$ tolerance per dimension) to select only overlapping chunks for fetching [S1, unofficial]. The prefetcher adds the adjacent slice to the fetch list [S1, unofficial].

**Parameters:**
- **SFC Type:** Hilbert (default for serialization, superior spatial locality) and Morton (Z-order, used for in-memory reordering during fitting due to lower computational cost) [S1, unofficial].
- **Chunk Size:** 1 MB [S1, unofficial].

**Edge Cases and Pitfalls:**

## Subtopics

### Multi-Resolution Tetrahedral Region Indicator
A spatial indexing scheme for multi-resolution tetrahedral grids where a unique index encodes the intersection of tetrahedra containing a point $\mathbf{x}$ across all resolution levels [S2]. It is chosen when working with hierarchical tetrahedral meshes for spatial indexing and identifying neighboring cells [S2].

**Definition:**
At each resolution level $\ell$, the grid cube is subdivided into six congruent tetrahedra [S2]. The tetra offset $t^{(\ell)}(\mathbf{x}) \in \{0, 1, 2, 3, 4, 5\}$ indicates which of these tetrahedra anchored at $a^{(\ell)}(\mathbf{x})$ contains $\mathbf{x}$ [S2]. The region indicator at level $\ell$ is defined as:
$$ \mathbf{r}^{(\ell)}(\mathbf{x}) := [ a^{(\ell)}(\mathbf{x}), t^{(\ell)}(\mathbf{x}) ] \in \mathbb{Z}^4 $$
The full region indicator is obtained by concatenating all levelwise tetra indices:
$$ \mathbf{r}(\mathbf{x}) := \bigoplus_{\ell=0}^{L-1} \mathbf{r}^{(\ell)}(\mathbf{x}) \in \mathbb{Z}^{4L} $$
where $\bigoplus$ denotes concatenation [S2].

**Parameters:**
- $L$: Number of resolution levels in the multi-resolution grid. Typical value: 4 [S2].
- $d$: Feature dimension per level. Typical value: 2 [S2].

**Usage:**
This index allows for efficient identification of neighboring cells when a point lies on a boundary by perturbing the tetrahedron index according to a barycentric mask [S2].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Performance:** Coalesces chunks selected by the slice-intersection query into a small number of HTTP range requests, and tighter chunk extents make the intersection test more selective [S1, unofficial].
- **Strengths:** Optimizes for multidimensional data with discrete axes; ensures spatially proximate splats lie in adjacent chunks [S1, unofficial].
- **Limitations:** Hilbert curve computation has a higher computational cost than Morton [S1, unofficial].

## Background
The method originates from the requirements of scalable web visualization of multidimensional scientific data, specifically in the Luxar viewer for microscopy data [S1, unofficial]. It combines principles of space-filling curves (Morton, Hilbert) with hierarchical sorting of discrete dimensions to enable efficient chunk-based loading over HTTP [S1, unofficial].
