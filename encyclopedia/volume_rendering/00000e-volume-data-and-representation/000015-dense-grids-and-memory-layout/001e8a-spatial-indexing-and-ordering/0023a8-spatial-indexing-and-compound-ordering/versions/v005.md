# Spatial Indexing and Compound Ordering
Also called: Compound Ordering Index, Space-Filling Curve Indexing

## Overview
Spatial Indexing and Compound Ordering maps multidimensional data, combining spatial coordinates with discrete non-spatial dimensions (e.g., time, channel), into a 1D linear array to optimize cache locality and network fetching [S1, unofficial]. It solves the problem of poor spatial coherence in multidimensional datasets by hierarchically sorting elements: first by discrete non-spatial coordinates, and then by a space-filling curve (SFC) index within each discrete slice [S1, unofficial]. Unlike standard Morton or Hilbert encoding that only handles spatial coordinates, this method structures data so that contiguous memory blocks correspond to both spatial proximity and discrete slice membership, enabling efficient range queries for specific time steps or channels [S1, unofficial].

## How it works
**Inputs:**
- A set of data elements, each defined by spatial coordinates $\mathbf{x} \in \mathbb{R}^d$ (typically $d=3$) and discrete non-spatial coordinates $\mathbf{c} \in \mathbb{Z}^k$ (e.g., time $t$, channel $ch$) [S1, unofficial].
- A chosen space-filling curve type (Hilbert or Morton) [S1, unofficial].
- Chunk size (implementation-dependent; the demo site uses 1 MB chunks) [S1, unofficial].

**Outputs:**
- A sorted array of elements.
- Metadata: Chunk-level Axis-Aligned Bounding Boxes (AABBs) for each chunk [S1, unofficial].

**Data Structures:**
1. **Element Record:** Contains spatial coordinates $\mathbf{x}$, discrete coordinates $\mathbf{c}$, and the computed linear index $I$ [G].
2. **Chunk Metadata:** For each chunk $j$, stores an AABB defined by min/max bounds in all dimensions (spatial and discrete) [S1, unofficial].

**Steps:**
1. **Primary Sort (Discrete):** Sort all elements by their discrete non-spatial coordinates $\mathbf{c}$ (e.g., time, channel) [S1, unofficial]. This ensures that all elements belonging to a specific discrete slice are contiguous in memory [S1, unofficial].
2. **Secondary Sort (Spatial):** Within each discrete slice, sort elements based on their linear index generated by the chosen SFC over the spatial coordinates $\mathbf{x}$ [S1, unofficial].
   - If using **Morton (Z-order)**: Interleave the bits of the spatial coordinates [G].
   - If using **Hilbert**: Map spatial coordinates to the Hilbert curve index using a standard bitwise/recursive algorithm [G].
3. **Chunking:** Partition the sorted array into contiguous chunks [S1, unofficial].
4. **Metadata Precomputation:** For each chunk, compute the AABB that encloses all elements within that chunk. The AABB spans the range of spatial coordinates and discrete coordinates present in the chunk [S1, unofficial].

**Parameters:**
- **SFC Type:** Hilbert is the default for serialization due to superior spatial locality [S1, unofficial]. Morton (Z-order) is used for in-memory reordering during fitting due to lower computational cost [S1, unofficial].
- **Chunk Size:** Determined by storage constraints and network request efficiency (e.g., 1 MB chunks in the demo layout) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Chunk Spanning Multiple Discrete Slices:** A chunk may span multiple timepoints or channels. This is handled by the AABB test, which checks for overlap with the query range [S1, unofficial].
- **Prefetching:** When fetching a new time step, the system may prefetch the first chunks of neighboring time steps to mitigate latency [S1, unofficial].

**Pseudocode:**
```python
def compute_compound_order(elements, sfc_type='hilbert', chunk_size=1024):
    """
    Sorts elements by discrete coordinates, then by SFC index within each slice.
    Returns sorted elements and chunk AABBs.
    """
    # Step 1: Compute SFC index for each element
    for elem in elements:
        if sfc_type == 'hilbert':
            # Standard Hilbert curve encoding algorithm [G]
            elem.sfc_index = hilbert_encode(elem.spatial_coords)
        elif sfc_type == 'morton':
            # Interleave bits of spatial coordinates [G]
            elem.sfc_index = morton_encode(elem.spatial_coords)
        else:
            raise ValueError("Unsupported SFC type")

    # Step 2: Primary sort by discrete coordinates
    elements.sort(key=lambda e: e.discrete_coords)

    # Step 3: Secondary sort by SFC index within each discrete slice
    slices = {}
    for elem in elements:
        key = elem.discrete_coords
        if key not in slices:
            slices[key] = []
        slices[key].append(elem)

    sorted_elements = []
    for key in sorted(slices.keys()):
        slice_elems = slices[key]
        slice_elems.sort(key=lambda e: e.sfc_index)
        sorted_elements.extend(slice_elems)

    # Step 4: Chunking and AABB computation
    chunks = []
    for i in range(0, len(sorted_elements), chunk_size):
        chunk_elems = sorted_elements[i:i+chunk_size]
        if not chunk_elems:
            break
        
        # Initialize bounds with first element
        min_spatial = list(chunk_elems[0].spatial_coords)
        max_spatial = list(chunk_elems[0].spatial_coords)
        min_discrete = list(chunk_elems[0].discrete_coords)
        max_discrete = list(chunk_elems[0].discrete_coords)

        for elem in chunk_elems:
            for d in range(len(elem.spatial_coords)):
                if elem.spatial_coords[d] < min_spatial[d]: min_spatial[d] = elem.spatial_coords[d]
                if elem.spatial_coords[d] > max_spatial[d]: max_spatial[d] = elem.spatial_coords[d]
            for d in range(len(elem.discrete_coords)):
                if elem.discrete_coords[d] < min_discrete[d]: min_discrete[d] = elem.discrete_coords[d]
                if elem.discrete_coords[d] > max_discrete[d]: max_discrete[d] = elem.discrete_coords[d]
        
        chunks.append({
            'elements': chunk_elems,
            'aabb': {
                'min_spatial': min_spatial,
                'max_spatial': max_spatial,
                'min_discrete': min_discrete,
                'max_discrete': max_discrete
            }
        })

    return sorted_elements, chunks

def query_chunks(chunks, query_discrete_range, query_spatial_bounds):
    """
    Selects chunks overlapping the query range using AABB test.
    """
    selected_chunks = []
    for chunk in chunks:
        aabb = chunk['aabb']
        
        # Check discrete overlap
        discrete_overlap = not (
            aabb['max_discrete'] < query_discrete_range[0] or
            aabb['min_discrete'] > query_discrete_range[1]
        )
        
        # Check spatial overlap
        spatial_overlap = not (
            aabb['max_spatial'] < query_spatial_bounds[0] or
            aabb['min_spatial'] > query_spatial_bounds[1]
        )
        
        if discrete_overlap and spatial_overlap:
            selected_chunks.append(chunk)
            
    return selected_chunks
```

## Subtopics

### [Spatial Sorting Layout](14435-spatial-sorting-layout.md)
Spatial sorting is a memory layout technique for tetrahedral meshes that reorders vertices and cells to maximize spatial coherence along a dominant principal direction. It solves the problem of poor cache locality in large meshes by ensuring that cells sharing vertices are stored contiguously in memory. Unlike general spatial indexing methods that handle arbitrary geometries, this approach is specifically optimized for meshes with a strong linear orientation, sacrificing performance on isotropic data like spheres.

### Multi-Resolution Tetrahedral Region Indicator
A unique spatial index encoding the intersection of tetrahedra containing a point $\mathbf{x}$ across all resolution levels of a multi-resolution tetrahedral grid [S2]. The region indicator at level $\ell$ is defined as $\mathbf{r}^{(\ell)}(\mathbf{x}) := [ a^{(\ell)}(\mathbf{x}), t^{(\ell)}(\mathbf{x}) ] \in \mathbb{Z}^4$, where $a^{(\ell)}(\mathbf{x})$ is the anchor displacement and $t^{(\ell)}(\mathbf{x}) \in \{0, 1, 2, 3, 4, 5\}$ is the tetrahedron index containing $\mathbf{x}$ [S2]. The full region indicator is obtained by concatenating all levelwise indices: $\mathbf{r}(\mathbf{x}) := \bigoplus_{\ell=0}^{L-1} \mathbf{r}^{(\ell)}(\mathbf{x}) \in \mathbb{Z}^{4L}$ [S2]. Typical parameters are $L=4$ resolution levels and $d=2$ feature dimensions per level [S2].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Performance:** Hilbert curves provide superior spatial locality compared to Morton curves, leading to better cache performance and fewer chunk fetches for spatially coherent queries [S1, unofficial]. However, Hilbert encoding is computationally more expensive than Morton encoding [S1, unofficial].
- **Strengths:** Efficient range queries for multidimensional data; reduces network requests by coalescing chunks; supports prefetching for temporal data [S1, unofficial].
- **Limitations:** Requires precomputation of SFC indices and AABBs [S1, unofficial].

## Background
Spatial Indexing and Compound Ordering is used in scalable interactive web visualization of multidimensional scientific data, such as microscopy data [S1, unofficial]. It enables efficient loading and rendering of large datasets by leveraging space-filling curves and hierarchical sorting [S1, unofficial]. The method is implemented in the Luxar viewer, which supports both WebGL and WebGPU backends [S1, unofficial].
