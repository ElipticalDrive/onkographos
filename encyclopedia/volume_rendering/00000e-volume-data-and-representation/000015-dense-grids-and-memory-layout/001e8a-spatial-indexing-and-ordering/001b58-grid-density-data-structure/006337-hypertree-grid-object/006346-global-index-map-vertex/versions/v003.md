# Global Index Map (Vertex)
## Overview
The Global Index Map (Vertex) maps a local vertex identifier within a single hypertree to a unique global integer index across the entire hypertree grid object [S1, unofficial]. It aggregates sparse, variable-size hypertree structures into a single contiguous addressing space for visualization and property storage [S1, unofficial]. It is distinguished from the Hypertree Global Index Map, which identifies hypertrees themselves, by operating at the vertex level within a hypertree [S1, unofficial]. It builds on [Hypertree Grid Object](18823-hypertree-grid-object.md).
## How it works
**Inputs:**
- $n_{HT}$: The index of the constituting hypertree within the grid [S1, unofficial].
- $n_l$: The local vertex index within that hypertree [S1, unofficial].
**Outputs:**
- $n_g$: The global vertex index [S1, unofficial].
**Data Structures:**
- An array or map storing the cumulative count of vertices for each hypertree in the grid [S1, unofficial]. If implicit, this is computed on the fly [S1, unofficial].
**Formulas:**
The global index $n_g$ is defined as an injective function:
$$ n_g = n_l + \sum_{i=0}^{n_{HT}-1} C_i $$
Where:
- $n_l \in [0, C_{n_{HT}}[$ is the local vertex index, with $C_{n_{HT}}$ being the number of cells in the hypertree identified by $n_{HT}$ [S1, unofficial].
- $C_i$ is the number of cells in the hypertree identified by index $i$ [S1, unofficial].
- $n_g \in [0, C[$ where $C$ is the total number of nodes in the whole hypertree grid [S1, unofficial].
**Steps:**
1. Identify the hypertree index $n_{HT}$ for the target vertex [S1, unofficial].
2. Retrieve the local vertex index $n_l$ within that hypertree [S1, unofficial].
3. Calculate the sum of cell counts $C_i$ for all hypertrees with index $i < n_{HT}$ [S1, unofficial].
4. Add the sum to $n_l$ to obtain $n_g$ [S1, unofficial].
**Pitfalls:**
- **Implicit Ordering Assumption:** The formula $n_g = n_l + \sum_{i=0}^{n_{HT}-1} C_i$ assumes that the simulation properties follow the same indexing order as the visualization needs [S1, unofficial].
- **Mandatory Explicit Map:** In practice, simulation properties are often not ordered the same way as visualization requirements, making an explicit Global Index Map mandatory if implicit ordering cannot be guaranteed [S1, unofficial].
- **Consistency:** The indexing scheme applies to all properties; consequently, all properties must be ordered in the same way [S1, unofficial].
**Pseudocode:**
```python
def compute_global_index(n_ht, n_l, hypertree_cell_counts):
    """
    Compute the global vertex index ng.
    
    Args:
        n_ht (int): Index of the hypertree.
        n_l (int): Local vertex index within the hypertree.
        hypertree_cell_counts (list[int]): List where index i contains C_i, 
                                           the number of cells in hypertree i.
                                           Must be sorted by hypertree index.
    
    Returns:
        int: The global vertex index ng.
    """
    preceding_cells = sum(hypertree_cell_counts[:n_ht])
    n_g = n_l + preceding_cells
    return n_g
```
## Subtopics

### Hypertree Global Index Map
The Hypertree Global Index Map ($n_{HT}$) is an injective function that returns values in $[0, \Pi_E]$ for a hypertree identified by coordinates $(i, j, k) \in \mathbb{N}^3$ [S1, unofficial]. It identifies the constituting hypertree object itself within the grid, rather than a vertex within it [S1, unofficial]. It is used to map spatial coordinates of hypertrees to a linear index for grid-level operations [S1, unofficial].

## Background
The concept originates from the paper "Efficient visualization and analysis of large-scale, tree-based, adaptive mesh refinement simulations with rectilinear geometry" [S1, unofficial]. It is part of the Hypertree Grid Object data structure, which supports dimensions $d \in \{1, 2, 3\}$ and branching factor $f \in \mathbb{N}^*$ [S1, unofficial]. The global indexing allows for a compact description of vertex coordinates based on bounding box information [S1, unofficial].
