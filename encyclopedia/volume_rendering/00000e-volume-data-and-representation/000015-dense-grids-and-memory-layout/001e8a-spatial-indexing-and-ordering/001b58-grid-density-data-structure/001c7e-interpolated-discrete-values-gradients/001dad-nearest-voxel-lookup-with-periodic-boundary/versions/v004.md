# Nearest Voxel Lookup with Periodic Boundary

Also called: Grid Probing, Nearest Voxel Lookup, Nearest-Neighbor Density Lookup, Periodic Boundary Voxel Lookup, Wrapped Nearest Neighbor Sampling

## Overview
Nearest Voxel Lookup retrieves the scalar value of the single voxel containing a sample point without interpolating neighboring values [S1, unofficial]. It maps continuous sample coordinates to discrete grid indices, applying periodic boundary conditions (modulo arithmetic) to handle out-of-bounds access [S2, unofficial]. Unlike [Interpolated Discrete Values & Gradients](1268-interpolated-discrete-values-gradients.md), which blends adjacent voxels, this method provides a discontinuous, blocky approximation that is computationally cheaper but less smooth [S5].

## How it works
**Inputs:**
- Sample point $p$ in world space.
- Grid bounding box defined by minimum corner $B_{min}$ and maximum corner $B_{max}$ [S1, unofficial].
- Grid resolution $R$ (assumed uniform cubic grid with $R$ voxels per axis) [S1, unofficial].
- 1D density array `grid.density` of size $R^3$ [S1, unofficial].

**Outputs:**
- Scalar density value $d$ at the nearest voxel.
- Boolean flag `out_of_bounds` indicating if the sample was outside the grid bounds before wrapping [S2, unofficial].

**Data Structures:**
- `Grid`: Struct containing `bounds[2]` (Vec3), `baseResolution` (int), and `density` (float array).
- `Point`: Vec3 structure for coordinates.

**Steps:**
1. **Transform to Local Space:** Compute the vector from the grid minimum to the sample point:
   $$ p_{local} = p - B_{min} $$
2. **Normalize:** Divide by the grid physical size to get coordinates in $[0, 1]$:
   $$ gridSize = B_{max} - B_{min} $$
   $$ p_{norm} = \frac{p_{local}}{gridSize} $$
3. **Convert to Voxel Space:** Scale by resolution to get floating-point voxel coordinates:
   $$ p_{voxel} = p_{norm} \times R $$
4. **Quantize to Integer Indices:** Compute floor of each component to get the voxel index. Using `floor` is critical to ensure indices are $\ge 0$ for negative local coordinates, avoiding invalid memory access that `static_cast<int>` (truncation) would cause for negative values [S1, unofficial].
   $$ i = \lfloor p_{voxel.x} \rfloor $$
   $$ j = \lfloor p_{voxel.y} \rfloor $$
   $$ k = \lfloor p_{voxel.z} \rfloor $$
5. **Handle Boundaries:**
   - Check if indices are within $[0, R-1]$. If $p_{norm}$ is exactly 1.0, $p_{voxel}$ is $R$, leading to index $R$, which is out of bounds.
   - Apply periodic boundary conditions using modulo arithmetic for out-of-bounds indices:
     $$ i_{final} = i \pmod R $$
     $$ j_{final} = j \pmod R $$
     $$ k_{final} = k \pmod R $$
   - Note: In languages where modulo can return negative values for negative operands, adjust by adding $R$ before modulo or using a dedicated wrap function [S2, unofficial].
6. **Lookup:** Compute linear memory index and return value:
   $$ idx = (k_{final} \times R + j_{final}) \times R + i_{final} $$
   $$ d = grid.density[idx] $$

**Pseudocode:**
```python
def nearest_voxel_lookup_periodic(grid, p):
    # 1. Transform to local space
    p_local = p - grid.bounds[0]
    
    # 2. Normalize to [0, 1]
    grid_size = grid.bounds[1] - grid.bounds[0]
    p_norm = p_local / grid_size
    
    # 3. Convert to voxel space
    p_voxel = p_norm * grid.baseResolution
    
    # 4. Floor to integer indices
    # Using floor ensures 0 for negative coordinates, preventing -1 index
    i = floor(p_voxel.x)
    j = floor(p_voxel.y)
    k = floor(p_voxel.z)
    
    # 5. Handle out-of-bounds with periodic boundary (modulo)
    # Check if originally out of bounds for reporting
    out_of_bounds = (i < 0) or (i >= grid.baseResolution) or \
                    (j < 0) or (j >= grid.baseResolution) or \
                    (k < 0) or (k >= grid.baseResolution)
    
    # Apply modulo for periodic wrapping
    # Ensure positive modulo result
    i = ((i % grid.baseResolution) + grid.baseResolution) % grid.baseResolution
    j = ((j % grid.baseResolution) + grid.baseResolution) % grid.baseResolution
    k = ((k % grid.baseResolution) + grid.baseResolution) % grid.baseResolution
    
    # 6. Linear index calculation
    R = grid.baseResolution
    idx = (k * R + j) * R + i
    
    return grid.density[idx], out_of_bounds
```

**Parameters:**
- `grid.baseResolution`: Integer, typical values $64^3$ to $256^3$ [S1, unofficial].
- `grid.bounds`: Vec3, defines physical extent [S1, unofficial].

**Edge Cases:**
- **Exact Boundary:** If $p_{norm}$ is exactly 1.0, $p_{voxel}$ equals $R$. `floor(R)` is $R$, which is out of bounds $[0, R-1]$. Modulo handles this by wrapping to 0 [S1, unofficial].
- **Negative Coordinates:** If $p_{local}$ is negative, `floor` returns negative integers. Modulo wraps them to the end of the grid [S1, S2, unofficial].
- **Precision:** Floating-point errors in normalization might cause coordinates slightly outside $[0,1]$ to be misclassified. Modulo arithmetic is robust to this [S2, unofficial].

## Subtopics

### Nearest Integer Rounding (Floor)
Converts continuous floating-point coordinates into discrete integer grid indices by rounding to the closest integer value [4233-nearest-integer-rounding.md]. It minimizes spatial quantization error compared to floor-based indexing, which is critical for accurate gradient estimation. It differs from [Ceil](1574-ceil.md) and [Floor](1575-floor.md) by balancing bias in both directions.

### Nearest Neighbor Search Interpolation
A variant that uses a KD-tree to find constraint points within a radius $w$ for each grid vertex, then solves for coefficients using LLT/LDLT decomposition to compute implicit function values [S3, unofficial]. It is more complex than simple lookup, involving weight matrix generation and basis matrix solving.

### Nearest Integer Rounding (Floor)
Rounds a 3D vector down to the nearest integer coordinates [S4]. This is the specific quantization step used in the primary method to ensure non-negative indices for negative local coordinates.

### Nearest Neighbor Interpolation
Estimates the sample value as the value at the nearest grid point [S5]. It gives a rough estimate compared to trilinear interpolation and is the conceptual basis for the lookup method described here.

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample. Involves constant number of arithmetic operations and one array lookup [S1, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space. Requires storage for the grid data $O(R^3)$ [S1, unofficial].
- **Performance:** Significantly faster than interpolation methods due to lack of blending calculations [S5].
- **Strengths:** Simple implementation, low computational cost, periodic boundaries allow seamless tiling [S2, unofficial].
- **Limitations:** Discontinuous output (blocky artifacts), no smoothing, aliasing at high frequencies [S5].
- **When to Use:** Low-resolution volumes, performance-critical applications, or when periodicity is required [S1, S2, unofficial].
- **When Not to Use:** High-fidelity rendering requiring smooth gradients or continuous derivatives [S5].

## Background
Originated from basic voxel grid rendering techniques where density is probed directly from memory [S1, unofficial]. The term "probing" is used in OpenVDB for this operation [S1, unofficial]. Periodic boundary conditions are common in procedural noise and texture synthesis, adapted here for volume data to handle out-of-bounds rays [S2, unofficial]. The method is foundational for more complex interpolation schemes like trilinear or Hermite interpolation, which build upon this coordinate mapping step [S1, unofficial].
