# Nearest Voxel Lookup with Periodic Boundary

Also called: Grid Probing, Nearest Voxel Lookup, Nearest-Neighbor Density Lookup, Nearest-Neighbor Search Interpolation, Periodic Boundary Voxel Lookup, Wrapped Nearest Neighbor Sampling

## Overview
This method retrieves the scalar density value of the single voxel containing a sample point, without interpolating neighboring values [S1, unofficial]. It differs from bilinear or trilinear interpolation by selecting only the nearest grid vertex, offering lower computational cost at the expense of visual continuity [S1, unofficial]. The "Periodic Boundary" variant explicitly handles out-of-bounds coordinates by wrapping them via modulo arithmetic, allowing seamless tiling or handling of rays that stray outside the defined grid volume [S2, unofficial].

## How it works
**Inputs:**
*   `grid`: A structure containing:
    *   `bounds`: A 3D vector pair `[min, max]` defining the world-space axis-aligned bounding box (AABB) of the grid.
    *   `baseResolution`: An integer scalar (or 3D vector) representing the number of voxels along each axis (assumed cubic for simplicity in basic implementations, but generally $N_x, N_y, N_z$).
    *   `density`: A 1D array or flattened 3D tensor storing voxel values.
*   `p`: A 3D point in world space.

**Outputs:**
*   `value`: The scalar density at the nearest voxel.
*   `valid`: A boolean indicating if the point was within the primary grid bounds (optional, depending on implementation).

**Data Structures:**
The density array is stored in row-major order (Z-major, Y-major, X-minor) or similar contiguous layout. The index $I$ for coordinates $(x, y, z)$ is calculated as:
$$ I = (z \cdot N_y + y) \cdot N_x + x $$
where $N_x, N_y, N_z$ are the resolutions along each axis [S1, unofficial].

**Steps:**
1.  **Transform to Local Space:** Subtract the grid's minimum bound from the sample point to shift the coordinate system so the grid origin is at $(0,0,0)$ [S1, unofficial].
    $$ p_{local} = p - grid.bounds[0] $$
2.  **Normalize:** Divide by the grid's physical size to map the point to the $[0, 1]$ range [S1, unofficial].
    $$ gridSize = grid.bounds[1] - grid.bounds[0] $$
    $$ p_{norm} = p_{local} / gridSize $$
3.  **Convert to Voxel Space:** Multiply normalized coordinates by the grid resolution to get floating-point voxel coordinates [S1, unofficial].
    $$ p_{voxel} = p_{norm} \cdot grid.baseResolution $$
4.  **Compute Integer Indices:** Apply the floor function to the voxel coordinates to determine the integer grid indices [S1, unofficial].
    $$ x_i = \lfloor p_{voxel}.x \rfloor $$
    $$ y_i = \lfloor p_{voxel}.y \rfloor $$
    $$ z_i = \lfloor p_{voxel}.z \rfloor $$
5.  **Apply Periodic Boundary Conditions:** If the indices fall outside the valid range $[0, N-1]$, wrap them using modulo arithmetic [S2, unofficial].
    $$ x_i = x_i \pmod{N_x} $$
    $$ y_i = y_i \pmod{N_y} $$
    $$ z_i = z_i \pmod{N_z} $$
    *Note: Ensure the modulo operation handles negative numbers correctly (e.g., returning positive remainders).*
6.  **Clamp Check (Pre-Wrap Guard):** Before wrapping, or if periodic boundaries are not desired for all cases, check if coordinates exceed $N-1$. This occurs if normalized coordinates are exactly $1.0$ due to floating-point precision or ray endpoints [S1, unofficial]. If periodic boundaries are active, the modulo step in Step 5 handles this. If not, clamp to $N-1$.
7.  **Lookup:** Calculate the linear memory index and retrieve the value [S1, unofficial].
    $$ index = (z_i \cdot N_y + y_i) \cdot N_x + x_i $$
    $$ value = grid.density[index] $$

**Pseudocode:**
```python
def nearest_voxel_lookup_periodic(grid, p):
    # 1. Transform to local space
    p_local = p - grid.bounds[0]
    
    # 2. Normalize to [0, 1]
    grid_size = grid.bounds[1] - grid.bounds[0]
    p_norm = p_local / grid_size
    
    # 3. Convert to voxel space
    p_voxel = p_norm * grid.baseResolution
    
    # 4. Compute integer indices using floor
    # floor is critical to handle negative coordinates correctly (returns 0 for -0.5, not -1)
    xi = floor(p_voxel.x)
    yi = floor(p_voxel.y)
    zi = floor(p_voxel.z)
    
    # 5. Apply periodic boundary conditions (modulo)
    # Ensure modulo returns positive results for negative inputs
    nx, ny, nz = grid.baseResolution
    xi = xi % nx
    yi = yi % ny
    zi = zi % nz
    
    # 6. Calculate linear index (Row-major: Z, Y, X)
    index = (zi * ny + yi) * nx + xi
    
    # 7. Return value
    return grid.density[index]
```

**Parameters:**
*   `grid.baseResolution`: Typically $64^3, 128^3, 256^3$ depending on desired detail and memory constraints [S1, unofficial].
*   `grid.bounds`: Defined by the scene geometry or asset origin [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Negative Coordinates:** Using truncation (e.g., `static_cast<int>` in C++) instead of `floor` for negative voxel coordinates results in indices like $-1$, causing invalid memory access or incorrect wrapping if not handled [S1, unofficial]. `floor` ensures that coordinates $< 0$ map to $0$ before modulo or clamping.
*   **Boundary Exceedance:** If a normalized coordinate is exactly $1.0$ (e.g., at the max bound), `floor` yields $N-1$. If it slightly exceeds $1.0$ due to precision, `floor` yields $N$, which is out of bounds. Periodic boundary conditions (modulo) handle this by wrapping $N$ to $0$ [S1, unofficial][S2, unofficial].
*   **Memory Layout:** The index calculation assumes a specific memory layout (row-major). If the grid is stored in column-major or Z-major without the correct stride, the lookup will return incorrect data.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. Requires a few arithmetic operations and one memory access.
*   **Memory Complexity:** $O(1)$ auxiliary space. The grid itself is $O(N^3)$ but is considered input data.
*   **Performance:** Significantly faster than trilinear interpolation as it avoids 8 memory accesses and 7 multiplications/additions per sample [S1, unofficial].
*   **Strengths:** Minimal computational overhead; suitable for real-time applications or when visual smoothness is not critical (e.g., coarse volume visualization, collision detection).
*   **Limitations:** Produces blocky, aliased visuals due to lack of interpolation. Discontinuities at voxel boundaries are visible [S1, unofficial].
*   **When to use:** When performance is paramount and visual quality is secondary, or when the voxel resolution is sufficiently high that artifacts are negligible.
*   **When not to use:** When smooth gradients or high-fidelity volume rendering is required.

## Background
This technique is a fundamental component of voxel-based volume rendering. It is referred to as "probing" in libraries like OpenVDB [S1, unofficial]. The concept of mapping continuous space to discrete grid indices dates back to early computer graphics and scientific visualization. The specific handling of periodic boundaries is common in procedural generation and texture mapping, applied here to volume data to allow seamless tiling or robust handling of out-of-bounds rays [S2, unofficial].
