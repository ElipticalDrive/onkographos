# Interpolated Discrete Values & Gradients

Also called: Cubic Spline Interpolation, CubicSpline, Discrete Field Interpolation, Interpolated Grid Fields, Tri-Cubic Interpolation

## Overview
Interpolated Discrete Values & Gradients computes a continuous scalar field and its spatial gradient from discrete data stored at grid vertices using tri-cubic interpolation [S1, unofficial][S2]. It solves the problem of mapping arbitrary continuous world-space coordinates to a smooth, differentiable representation suitable for isosurfacing and volume rendering, unlike [Nearest Voxel Lookup with Periodic Boundary](1573-nearest-voxel-lookup-with-periodic-boundary.md) which produces piecewise-constant fields [S2]. It differs from [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md) by performing the full 3D blending operation rather than just retrieving corner indices, and from [Piecewise Quadratic Hermite Interpolation](4001-piecewise-quadratic-hermite-interpolation.md) by using a single cubic polynomial per axis instead of piecewise quadratics [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A query point $p$ in world space, a grid structure providing access to discrete values at vertices, and optionally precomputed or analytically known gradients at vertices.
- Output: A scalar value $f(p)$ and a gradient vector $\nabla f(p)$.

**Data Structures:**
The method relies on a dense grid structure (e.g., `CGAL::Isosurfacing::Cartesian_grid_3`) that maps integer indices $(i, j, k)$ to world coordinates and provides access to scalar values $V_{i,j,k}$ and gradient vectors $G_{i,j,k}$ at each vertex [S2].

**Algorithm Steps:**
1. **Voxel Coordinate Calculation:** Determine the integer coordinates of the voxel containing the query point $p$. For each axis $a \in \{x, y, z\}$, compute $v_i[a] = \lfloor (p[a] - \text{bounds}[0][a]) / \text{voxel\_dim}[a] \rfloor$ [S1, unofficial].
2. **Minimum Corner and Offset:** Compute the world coordinates of the minimum corner of the voxel: $v_{\min} = \text{bounds}[0] + v_i \cdot \text{voxel\_dim}$ [S1, unofficial]. Compute the fractional offset $t$ in the range $[0, 1]$: $t = (p - v_{\min}) / \text{voxel\_dim}$ [S1, unofficial].
3. **Tri-Cubic Interpolation (Scalar):** Perform cubic interpolation along each axis using a 4x4x4 neighborhood of voxels centered around $v_i$ [S1, unofficial].
    - **Z-Interpolation:** For each $j \in [-1, 2]$ and $i \in [-1, 2]$, interpolate along the z-axis using four values:
      $$ z_{\text{interp}}[j+1][i+1] = \text{CINT\_CR}(t.z, V_{v_i.x+i, v_i.y+j, v_i.z-1}, V_{v_i.x+i, v_i.y+j, v_i.z}, V_{v_i.x+i, v_i.y+j, v_i.z+1}, V_{v_i.x+i, v_i.y+j, v_i.z+2}) $$
      [S1, unofficial].
    - **Y-Interpolation:** For each $i \in [0, 3]$, interpolate the z-interpolated values along the y-axis:
      $$ y_{\text{interp}}[i] = \text{CINT\_CR}(t.y, z_{\text{interp}}[0][i], z_{\text{interp}}[1][i], z_{\text{interp}}[2][i], z_{\text{interp}}[3][i]) $$
      [S1, unofficial].
    - **X-Interpolation:** Interpolate the y-interpolated values along the x-axis to get the final result:
      $$ f(p) = \text{CINT\_CR}(t.x, y_{\text{interp}}[0], y_{\text{interp}}[1], y_{\text{interp}}[2], y_{\text{interp}}[3]) $$
      [S1, unofficial].
4. **Gradient Computation:** The gradient can be computed analytically if vertex gradients are known, or computed via discrete differences [S2]. If using discrete gradients, the method `gradients.compute_discrete_gradients(values)` can be used to populate gradient fields from the scalar values [S2].

**Cubic Spline Basis Function:**
The core interpolation function $\text{CINT\_CR}(t, p_k, p_{k-1}, p_{k+1}, p_{k+2})$ (or generally $p_k, p_{k+1}$ with derivatives $m_k, m_{k+1}$) uses cubic Hermite basis functions [S1, unofficial]. For an interval $[x_k, x_{k+1}]$ with length $\Delta = x_{k+1} - x_k$ and normalized parameter $t = \max(x - x_k, 0) / \Delta$ [S1, unofficial]:
- Compute powers: $t_2 = t^2$, $t_3 = t^3$ [S1, unofficial].
- Compute basis functions:
  $$ h_{00} = 2t^3 - 3t^2 + 1 $$
  $$ h_{10} = t^3 - 2t^2 + t $$
  $$ h_{01} = -2t^3 + 3t^2 $$
  $$ h_{11} = t^3 - t^2 $$
  [S1, unofficial].
- Return result:
  $$ \text{result} = h_{00} p_k + h_{10} \Delta m_k + h_{01} p_{k+1} + h_{11} \Delta m_{k+1} $$
  [S1, unofficial].

**Pseudocode:**
```python
def cubic_hermite(p_k, m_k, p_k1, m_k1, t, delta):
    """
    Performs 1D cubic Hermite interpolation.
    p_k, p_k1: Scalar values at endpoints.
    m_k, m_k1: Derivatives at endpoints.
    t: Normalized parameter in [0, 1].
    delta: Length of the interval.
    """
    t2 = t * t
    t3 = t2 * t
    h00 = 2 * t3 - 3 * t2 + 1
    h10 = t3 - 2 * t2 + t
    h01 = -2 * t3 + 3 * t2
    h11 = t3 - t2
    return h00 * p_k + h10 * delta * m_k + h01 * p_k1 + h11 * delta * m_k1

def interpolate_tricubic(p, grid):
    """
    Computes scalar value at point p using tri-cubic interpolation.
    grid: Object providing bounds, voxel_dim, and get_value(i, j, k).
    """
    # 1. Compute voxel integer coordinates
    v_i = [0, 0, 0]
    for axis in range(3):
        v_i[axis] = floor((p[axis] - grid.bounds[0][axis]) / grid.voxel_dim[axis])

    # 2. Compute minimum corner and local offset
    v_min = [grid.bounds[0][axis] + v_i[axis] * grid.voxel_dim[axis] for axis in range(3)]
    t = [(p[axis] - v_min[axis]) / grid.voxel_dim[axis] for axis in range(3)]

    # 3. Z-interpolation
    # z_interp[j+1][i+1] stores interpolated value for fixed y, z neighbors
    z_interp = [[0.0 for _ in range(4)] for _ in range(4)]
    for j in range(-1, 3):
        for i in range(-1, 3):
            # Get 4 z-neighbors
            v_z0 = grid.get_value(v_i[0] + i, v_i[1] + j, v_i[2] - 1)
            v_z1 = grid.get_value(v_i[0] + i, v_i[1] + j, v_i[2])
            v_z2 = grid.get_value(v_i[0] + i, v_i[1] + j, v_i[2] + 1)
            v_z3 = grid.get_value(v_i[0] + i, v_i[1] + j, v_i[2] + 2)
            
            # Assuming derivatives are zero or computed separately for standard tri-cubic
            # If derivatives are available, use cubic_hermite with m_k, m_k1
            # Here we assume standard Catmull-Rom or similar if derivatives not provided
            # The source [S1, unofficial] uses CINT_CR which implies Hermite with derivatives.
            # If derivatives are not available, this step requires a variant or approximation.
            # For strict adherence to [S1, unofficial], we assume derivatives m are available.
            m_z0 = grid.get_gradient(v_i[0] + i, v_i[1] + j, v_i[2] - 1)[2]
            m_z1 = grid.get_gradient(v_i[0] + i, v_i[1] + j, v_i[2])[2]
            m_z2 = grid.get_gradient(v_i[0] + i, v_i[1] + j, v_i[2] + 1)[2]
            m_z3 = grid.get_gradient(v_i[0] + i, v_i[1] + j, v_i[2] + 2)[2]
            
            # Interpolate between z1 and z2 using z0 and z3 as neighbors for derivative estimation
            # Standard Catmull-Rom uses neighbors to estimate derivatives:
            # m_k = 0.5 * (p_{k+1} - p_{k-1})
            # However, [S1, unofficial] explicitly mentions derivatives mk, mk_1.
            # We will use the provided derivatives if available, otherwise estimate.
            # Let's assume derivatives are provided by grid.get_gradient.
            
            # Interpolate between v_z1 and v_z2
            # Note: CINT_CR in [S1, unofficial] takes 4 values. This suggests Catmull-Rom spline
            # which is a specific cubic Hermite spline where derivatives are estimated from neighbors.
            # Formula for Catmull-Rom between p1 and p2 using p0 and p3:
            # result = 0.5 * ((2*p1) + (-p0+p2)*t + (2*p0 - 5*p1 + 4*p2 - p3)*t^2 + (-p0 + 3*p1 - 3*p2 + p3)*t^3)
            # But [S1, unofficial] formula uses h00, h10 etc with explicit derivatives.
            # We will stick to the Hermite form if derivatives are known.
            
            # If using Catmull-Rom (common for "Cubic Spline" in this context without explicit gradients):
            # t_z = t[2]
            # z_interp[j+1][i+1] = catmull_rom(v_z0, v_z1, v_z2, v_z3, t_z)
            
            # Using the Hermite form from [S1, unofficial] with estimated derivatives:
            m_k = 0.5 * (v_z2 - v_z0)
            m_k1 = 0.5 * (v_z3 - v_z1)
            delta_z = grid.voxel_dim[2]
            z_interp[j+1][i+1] = cubic_hermite(v_z1, m_k, v_z2, m_k1, t[2], delta_z)

    # 4. Y-interpolation
    y_interp = [0.0 for _ in range(4)]
    for i in range(4):
        # Get 4 y-neighbors from z_interp
        v_y0 = z_interp[0][i]
        v_y1 = z_interp[1][i]
        v_y2 = z_interp[2][i]
        v_y3 = z_interp[3][i]
        
        m_k = 0.5 * (v_y2 - v_y0)
        m_k1 = 0.5 * (v_y3 - v_y1)
        delta_y = grid.voxel_dim[1]
        y_interp[i] = cubic_hermite(v_y1, m_k, v_y2, m_k1, t[1], delta_y)

    # 5. X-interpolation
    # Get 4 x-neighbors from y_interp
    v_x0 = y_interp[0]
    v_x1 = y_interp[1]
    v_x2 = y_interp[2]
    v_x3 = y_interp[3]
    
    m_k = 0.5 * (v_x2 - v_x0)
    m_k1 = 0.5 * (v_x3 - v_x1)
    delta_x = grid.voxel_dim[0]
    return cubic_hermite(v_x1, m_k, v_x2, m_k1, t[0], delta_x)
```

## Subtopics

### [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md)
Extracts the 8 vertices of the enclosing grid cell. Chosen when higher-order reconstruction requires explicit access to corner data rather than a black-box interpolation function.

### [Nearest Voxel Lookup with Periodic Boundary](1573-nearest-voxel-lookup-with-periodic-boundary.md)
Retrieves a single voxel value. Chosen for piecewise-constant fields or when sharp discontinuities must be preserved without smoothing.

### [Piecewise Quadratic Hermite Interpolation](4001-piecewise-quadratic-hermite-interpolation.md)
Uses two quadratic Bézier curves per interval. Chosen for better stability with small subdivision counts compared to cubic interpolation.

### [Mipmap Grid Query](4154-mipmap-grid-query.md)
Selects resolution based on distance from center. Chosen for adaptive resolution sampling in hierarchical grids.

### [Cylindrical Coordinate Interpolation](4282-cylindrical-coordinate-interpolation.md)
Maps to cylindrical space before sampling. Chosen for geometries with cylindrical symmetry to reduce sampling artifacts.

### Dense Copy Extraction
Extracts a bounding box region into a dense array. Chosen for preprocessing or exporting grid data.

### Uncertain Gradient Field Interpolation
Reconstructs gradient as a random vector. Chosen when data uncertainty must be propagated to the gradient field.

### Backprojection via Shepard's Interpolation
Fits a scale field from discrete extrema. Chosen for size-based transfer functions.

### Kriging Interpolation
Constructs a regular grid from sparse borehole data. Chosen for geospatial data with limited sampling points.

### Data Interpolation
Converts irregular grids to regular grids. Chosen for preprocessing non-uniform data for texture generation.

## Operating characteristics
- **Time Complexity:** $O(1)$ per query, as it accesses a fixed 4x4x4 neighborhood (64 values) regardless of grid size [S1, unofficial].
- **Memory Complexity:** $O(N)$ for the grid storage, where $N$ is the number of voxels. The interpolation itself uses constant auxiliary memory [S1, unofficial].
- **Performance:** Efficient for ray marching and isosurfacing due to low per-sample cost [S1, unofficial].
- **Strengths:** Provides smooth, continuous fields with continuous first derivatives (C1 continuity), reducing aliasing artifacts compared to nearest-neighbor [S2].
- **Limitations:** Requires access to a 4x4x4 neighborhood, which can cause boundary issues if not handled [S1, unofficial]. Computationally more expensive than linear or nearest-neighbor interpolation [S1, unofficial].
- **When to use:** When smooth surfaces and accurate gradients are required for isosurfacing (e.g., Dual Contouring) or high-quality volume rendering [S2].
- **When not to use:** When memory bandwidth is the primary bottleneck and smoothness is not critical, or when the grid is extremely large and cache locality of the 64-sample neighborhood is problematic.

## Background
The method originates from the use of cubic spline interpolation for scalar field reconstruction in volume rendering and isosurfacing [S1, unofficial]. It is implemented in libraries such as CGAL's Isosurfacing module for dual contouring and marching cubes [S2]. The technique is widely used in computer graphics for generating smooth implicit surfaces from discrete data [S2].
