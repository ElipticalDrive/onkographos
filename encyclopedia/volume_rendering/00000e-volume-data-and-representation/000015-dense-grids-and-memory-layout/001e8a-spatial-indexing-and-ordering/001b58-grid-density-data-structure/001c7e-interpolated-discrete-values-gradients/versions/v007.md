# Interpolated Discrete Values & Gradients

Also called: Cubic Spline Interpolation, CubicSpline, Discrete Field Interpolation, Interpolated Grid Fields, Tri-Cubic Interpolation

## Overview
Interpolated Discrete Values & Gradients computes a continuous scalar field and its spatial gradient from discrete grid data using tri-cubic interpolation, requiring a 4x4x4 neighborhood of voxels to estimate values and derivatives at arbitrary 3D points [S1, unofficial][S2]. It solves the problem of mapping continuous world-space coordinates to discrete memory indices while providing $C^1$ continuity for smooth shading and accurate gradient estimation, unlike [Nearest Voxel Lookup with Periodic Boundary](1573-nearest-voxel-lookup-with-periodic-boundary.md) which yields piecewise-constant fields, or [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md) which computes gradients only at grid vertices [S1, unofficial][S2]. It builds on [Grid Density Data Structure](998-grid-density-data-structure.md) by providing the sampling primitives necessary for ray marching and isosurfacing.

## How it works
**Inputs:**
- A dense 3D grid of scalar values $V$ with dimensions $D_x \times D_y \times D_z$.
- A query point $p = (p_x, p_y, p_z)$ in world space.
- Grid bounding box bounds $[b_{min}, b_{max}]$ and voxel dimensions $voxel\_dim = (dx, dy, dz)$.

**Outputs:**
- Scalar value $f(p)$ at the query point.
- Gradient vector $\nabla f(p) = (\frac{\partial f}{\partial x}, \frac{\partial f}{\partial y}, \frac{\partial f}{\partial z})$ at the query point.

**Data Structures:**
- The grid is stored as a 1D array or 3D tensor. Access to a voxel at integer indices $(i, j, k)$ is denoted $V[i, j, k]$.
- Temporary storage for interpolation: a 4x4x4 array of values is conceptually accessed, but computed layer-by-layer to save memory.

**Steps:**

1. **Compute Voxel Coordinates:**
   Determine the integer coordinates of the voxel containing the query point $p$.
   $$ v_i[axis] = \lfloor \frac{p[axis] - b_{min}[axis]}{voxel\_dim[axis]} \rfloor $$
   where $axis \in \{x, y, z\}$. Let $v_i = (v_x, v_y, v_z)$.

2. **Compute Local Offset:**
   Calculate the fractional offset $t$ of the point within the voxel, normalized to $[0, 1]$.
   $$ v_{min} = b_{min} + v_i \cdot voxel\_dim $$
   $$ t[axis] = \frac{p[axis] - v_{min}[axis]}{voxel\_dim[axis]} $$

3. **Tri-Cubic Interpolation (Value):**
   The method uses cubic Hermite spline interpolation along each axis. The 1D cubic interpolation function $CINT\_CR(val, p_0, p_1, p_2, p_3, t)$ computes the interpolated value using four points and their implied derivatives. However, standard tri-cubic interpolation typically requires derivative information or uses a Catmull-Rom spline formulation which approximates derivatives from neighboring points. Based on [S1, unofficial], the implementation uses a function `CINT_CR` which takes 4 values along an axis. This implies a Catmull-Rom spline where the derivative at a point is estimated from its neighbors.

   The interpolation proceeds in three passes (Z, then Y, then X):

   **Pass 1: Z-interpolation**
   For each $j \in [-1, 2]$ and $i \in [-1, 2]$:
   $$ z\_interp[j+1][i+1] = CINT\_CR(t_z, V[v_x+i, v_y+j, v_z-1], V[v_x+i, v_y+j, v_z], V[v_x+i, v_y+j, v_z+1], V[v_x+i, v_y+j, v_z+2]) $$
   Here, $CINT\_CR$ performs 1D cubic interpolation along the Z-axis using the four neighboring voxels.

   **Pass 2: Y-interpolation**
   For each $i \in [-1, 2]$:
   $$ y\_interp[i] = CINT\_CR(t_y, z\_interp[0][i], z\_interp[1][i], z\_interp[2][i], z\_interp[3][i]) $$
   This interpolates the previously computed Z-interpolated values along the Y-axis.

   **Pass 3: X-interpolation**
   $$ result = CINT\_CR(t_x, y\_interp[0], y\_interp[1], y\_interp[2], y\_interp[3]) $$
   This yields the final scalar value $f(p)$.

   **1D Cubic Hermite/Catmull-Rom Basis:**
   The function $CINT\_CR(t, p_0, p_1, p_2, p_3)$ can be implemented using cubic Hermite basis functions if derivatives are known, or Catmull-Rom if they are derived from points. [S1, unofficial] provides the Hermite basis functions $h_{00}, h_{10}, h_{01}, h_{11}$ for an interval $[x_k, x_{k+1}]$ with values $p_k, p_{k+1}$ and derivatives $m_k, m_{k+1}$:
   $$ t = \frac{x - x_k}{x_{k+1} - x_k} $$
   $$ h_{00} = 2t^3 - 3t^2 + 1 $$
   $$ h_{10} = t^3 - 2t^2 + t $$
   $$ h_{01} = -2t^3 + 3t^2 $$
   $$ h_{11} = t^3 - t^2 $$
   $$ result = h_{00} p_k + h_{10} \Delta x m_k + h_{01} p_{k+1} + h_{11} \Delta x m_{k+1} $$
   In a standard tri-cubic grid interpolation without explicit derivative storage, Catmull-Rom splines are often used, where the derivative $m_k$ is approximated as $\frac{p_{k+1} - p_{k-1}}{2}$. [S1, unofficial] references `CINT_CR` which likely encapsulates this logic.

4. **Gradient Computation:**
   The gradient $\nabla f(p)$ is computed by differentiating the interpolation basis functions.
   - **Analytical:** If the underlying field is defined by analytic functions at vertices, gradients are computed per vertex [S2].
   - **Discrete:** If only values are known, gradients can be computed using finite differences on the interpolated field or by using the derivatives inherent in the spline basis. [S2] provides `gradients.compute_discrete_gradients(values)` which likely computes vertex gradients using finite differences and then interpolates them similarly to the values.
   
   For a Catmull-Rom spline, the derivative with respect to $t$ is:
   $$ \frac{d}{dt} CINT\_CR(t, p_0, p_1, p_2, p_3) = \frac{1}{2} \begin{bmatrix} -1 & 2 & -1 & 0 \\ -3 & 0 & 3 & 0 \\ 3 & -6 & 3 & 0 \\ -1 & 3 & -3 & 1 \end{bmatrix} \begin{bmatrix} p_0 \\ p_1 \\ p_2 \\ p_3 \end{bmatrix} $$
   The total gradient components are obtained by applying the chain rule through the three interpolation passes.

**Parameters:**
- Grid resolution: Not given in the sources.
- Voxel dimensions: Defined by the grid bounding box and resolution.
- Boundary conditions: Not given in the sources. [G] Typically, clamping or reflection is used for points outside the grid bounds.

**Edge Cases and Pitfalls:**
- **Boundary Handling:** Points outside the grid bounds require clamping of indices or extrapolation. [S1, unofficial] does not specify, but standard practice is to clamp $v_i$ to $[0, D-1]$.
- **Precision:** Cubic interpolation is sensitive to floating-point precision in derivative calculations. [S1, unofficial] uses `float` in CUDA, suggesting single-precision is supported.
- **Degenerate Input:** If voxel dimensions are zero, division by zero occurs in $t$ calculation.

**Pseudocode:**

```python
def cubic_hermite_basis(t, p0, p1, m0, m1, delta):
    """
    Computes the value of a cubic Hermite spline at parameter t in [0, 1].
    p0, p1: values at endpoints.
    m0, m1: derivatives at endpoints.
    delta: length of the interval (x1 - x0).
    """
    t2 = t * t
    t3 = t2 * t
    h00 = 2 * t3 - 3 * t2 + 1
    h10 = t3 - 2 * t2 + t
    h01 = -2 * t3 + 3 * t2
    h11 = t3 - t2
    return h00 * p0 + h10 * delta * m0 + h01 * p1 + h11 * delta * m1

def catmull_rom_interpolate(t, p0, p1, p2, p3):
    """
    Catmull-Rom interpolation using 4 points.
    Derivatives are approximated as m0 = (p1 - p-1)/2, m1 = (p2 - p0)/2.
    Here p-1 is p0, p1 is p1, p2 is p2, p3 is p3? 
    Standard Catmull-Rom for segment p1-p2 uses p0, p1, p2, p3.
    Derivative at p1: (p2 - p0) / 2
    Derivative at p2: (p3 - p1) / 2
    """
    m0 = (p2 - p0) / 2.0
    m1 = (p3 - p1) / 2.0
    # delta is 1.0 for normalized t
    return cubic_hermite_basis(t, p1, p2, m0, m1, 1.0)

def interpolate_1d(t, p0, p1, p2, p3):
    return catmull_rom_interpolate(t, p0, p1, p2, p3)

def tri_cubic_interpolate(grid, p, bounds, voxel_dim):
    # 1. Compute voxel coordinates
    vx = int((p.x - bounds.min.x) / voxel_dim.x)
    vy = int((p.y - bounds.min.y) / voxel_dim.y)
    vz = int((p.z - bounds.min.z) / voxel_dim.z)
    
    # 2. Compute local offset
    v_min_x = bounds.min.x + vx * voxel_dim.x
    v_min_y = bounds.min.y + vy * voxel_dim.y
    v_min_z = bounds.min.z + vz * voxel_dim.z
    
    tx = (p.x - v_min_x) / voxel_dim.x
    ty = (p.y - v_min_y) / voxel_dim.y
    tz = (p.z - v_min_z) / voxel_dim.z
    
    # 3. Z-interpolation (4x4 grid of values)
    # z_interp[j+1][i+1] corresponds to j in [-1, 2], i in [-1, 2]
    z_interp = [[0.0 for _ in range(4)] for _ in range(4)]
    
    for j in range(-1, 3):
        for i in range(-1, 3):
            # Access grid with boundary clamping
            val_0 = grid.get(vx + i, vy + j, vz - 1)
            val_1 = grid.get(vx + i, vy + j, vz)
            val_2 = grid.get(vx + i, vy + j, vz + 1)
            val_3 = grid.get(vx + i, vy + j, vz + 2)
            z_interp[j+1][i+1] = interpolate_1d(tz, val_0, val_1, val_2, val_3)
            
    # 4. Y-interpolation
    y_interp = [0.0 for _ in range(4)]
    for i in range(-1, 3):
        val_0 = z_interp[0][i+1]
        val_1 = z_interp[1][i+1]
        val_2 = z_interp[2][i+1]
        val_3 = z_interp[3][i+1]
        y_interp[i+1] = interpolate_1d(ty, val_0, val_1, val_2, val_3)
        
    # 5. X-interpolation
    val_0 = y_interp[0]
    val_1 = y_interp[1]
    val_2 = y_interp[2]
    val_3 = y_interp[3]
    result = interpolate_1d(tx, val_0, val_1, val_2, val_3)
    
    return result
```

## Subtopics

### [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md)
Extracts the 8 vertices of the enclosing grid cell. It is the foundational data retrieval step for trilinear interpolation, solving the mapping of continuous coordinates to discrete tensor indices. Unlike this method which uses a 4x4x4 neighborhood for cubic accuracy, it gathers only the 8 corners for linear blending.

### [Nearest Voxel Lookup with Periodic Boundary](1573-nearest-voxel-lookup-with-periodic-boundary.md)
Retrieves the single voxel value nearest to the query point. It produces a piecewise-constant field, preserving sharp discontinuities but introducing aliasing. It differs from this method by using zero-order approximation instead of higher-order continuity.

### [Mipmap Grid Query](4154-mipmap-grid-query.md)
Selects a mip level based on spatial distance from the center. It solves adaptive resolution sampling, using coarser grids for distant points. It differs from this method by dynamically selecting resolution rather than fixed high-resolution cubic interpolation.

### [Cylindrical Coordinate Interpolation](4282-cylindrical-coordinate-interpolation.md)
Maps Cartesian points to cylindrical space before sampling. It reduces sampling artifacts for radially symmetric data by aligning the coordinate system with the geometry's principal axis.

### [Polynomial and Spline Interpolation](11104-polynomial-and-spline-interpolation.md)
A family of methods using higher-order polynomials (cubic) over wider support regions to guarantee $C^1$ or $C^2$ continuity. This method is a specific instance of this family, using tri-cubic splines.

## Operating characteristics
- **Time Complexity:** $O(1)$ per query, but with a high constant factor due to the 4x4x4 = 64 voxel accesses and multiple interpolation steps [S1, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary memory per query, as the 4x4x4 neighborhood is temporary.
- **Measured Performance:** Not given in the sources. [G] On modern GPUs, this can be optimized using texture units with hardware cubic filtering, which is often faster than software tri-cubic interpolation.
- **Strengths:** Provides smooth, differentiable fields suitable for high-quality rendering and gradient-based surface extraction (e.g., Dual Contouring) [S2].
- **Limitations:** Computationally expensive compared to trilinear or nearest-neighbor interpolation. Requires a 4x4x4 neighborhood, which can be problematic near boundaries without padding.
- **When to use:** When smooth gradients are required for isosurfacing or high-quality volume rendering.
- **When not to use:** When performance is critical and visual smoothness is less important, or when the data is inherently discrete and sharp edges are desired.

## Background
The method originates from the use of cubic spline interpolation in volume rendering and isosurfacing. [S1, unofficial] describes its use in CUDA-based volume rendering with ray marching. [S2] details its implementation in CGAL's Isosurfacing module for dual contouring and marching cubes, where `Interpolated_discrete_values_3` and `Interpolated_discrete_gradients_3` are used to provide smooth fields for surface extraction from discrete data. The technique is widely used in scientific visualization to convert discrete voxel data into continuous fields for transfer functions and gradient estimation.
