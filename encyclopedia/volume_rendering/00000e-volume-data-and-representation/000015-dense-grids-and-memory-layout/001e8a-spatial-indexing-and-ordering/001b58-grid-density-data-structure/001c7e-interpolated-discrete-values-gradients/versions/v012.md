# Interpolated Discrete Values & Gradients

Also called: Cubic Spline Interpolation, CubicSpline, Discrete Field Interpolation, Interpolated Grid Fields, Tri-Cubic Interpolation

## Overview
Interpolated Discrete Values & Gradients computes a continuous scalar field and its spatial gradient from discrete grid data using tri-cubic interpolation [S1, unofficial][S2]. It solves the problem of mapping continuous world-space coordinates to discrete memory indices while providing smooth, differentiable values essential for ray marching and gradient-based shading [S1, unofficial][S2]. Unlike [Nearest Voxel Lookup with Periodic Boundary](1573-nearest-voxel-lookup-with-periodic-boundary.md), which produces a piecewise-constant field, this method blends adjacent voxels to ensure $C^0$ continuity of the scalar field and $C^0$ continuity of the gradient (assuming the gradient is also interpolated) [S1, unofficial][S2]. It differs from [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md) by providing the value and gradient simultaneously through a unified interpolation basis rather than post-processing discrete differences [S2].

## How it works
**Inputs:**
- A query point $\mathbf{p} = (p_x, p_y, p_z)$ in world space.
- A dense 3D grid of scalar values (voxels) with known bounding box $\mathbf{B}_{min}$ and voxel dimensions $\mathbf{d} = (d_x, d_y, d_z)$.
- Optionally, pre-computed gradients at grid vertices, or a method to compute them from the scalar values.

**Outputs:**
- A scalar value $V(\mathbf{p})$.
- A gradient vector $\nabla V(\mathbf{p}) = (\frac{\partial V}{\partial x}, \frac{\partial V}{\partial y}, \frac{\partial V}{\partial z})$.

**Data Structures:**
- The grid is stored as a 3D array `data[x][y][z]` of size $N_x \times N_y \times N_z$.
- Indices are integer coordinates $v_i = (v_x, v_y, v_z)$ representing the voxel containing the query point.

**Algorithm Steps:**

1.  **Coordinate Mapping:**
    Compute the integer voxel coordinates $v_i$ containing $\mathbf{p}$:
    $$ v_i[axis] = \lfloor \frac{p_{axis} - B_{min, axis}}{d_{axis}} \rfloor $$
    Compute the minimum corner of the voxel:
    $$ \mathbf{v}_{min} = \mathbf{B}_{min} + v_i \cdot \mathbf{d} $$
    Compute the local fractional offset $\mathbf{t}$ in range $[0, 1]$:
    $$ \mathbf{t} = \frac{\mathbf{p} - \mathbf{v}_{min}}{\mathbf{d}} $$
    *Note: $\mathbf{t}$ components $t_x, t_y, t_z$ are used for interpolation along each axis.*

2.  **Neighborhood Selection:**
    Tri-cubic interpolation requires a $4 \times 4 \times 4$ neighborhood of voxels. The indices relative to $v_i$ are $i \in [-1, 2]$ and $j \in [-1, 2]$ for the y and z axes, and similarly for x. The global indices accessed are:
    $$ \text{idx}(x, y, z) = (v_x + i, v_y + j, v_z + k) $$
    for $i, j, k \in \{-1, 0, 1, 2\}$. Boundary checks must be applied if the query point is near the grid edge.

3.  **1D Cubic Interpolation (Hermite Basis):**
    The core interpolation function `CINT_CR` (Cubic Interpolation with Continuous Derivatives) computes the value at parameter $t \in [0, 1]$ given two values $p_k, p_{k+1}$ and their derivatives $m_k, m_{k+1}$ (scaled by interval length).
    
    Let $\Delta = 1$ (since $t$ is normalized to $[0,1]$). The basis functions are:
    $$ h_{00} = 2t^3 - 3t^2 + 1 $$
    $$ h_{10} = t^3 - 2t^2 + t $$
    $$ h_{01} = -2t^3 + 3t^2 $$
    $$ h_{11} = t^3 - t^2 $$
    
    The interpolated value is:
    $$ \text{CINT\_CR}(t, p_k, p_{k+1}, m_k, m_{k+1}) = h_{00} p_k + h_{10} m_k + h_{01} p_{k+1} + h_{11} m_{k+1} $$
    
    *Note: In standard tri-cubic interpolation of scalar fields without pre-computed vertex gradients, the derivatives $m$ are often approximated using finite differences of the scalar values, or the method defaults to trilinear if gradients are unavailable. However, the source [S1, unofficial] explicitly defines `CINT_CR` using derivatives, implying the availability of gradient data or a specific spline formulation.*

4.  **Tri-Cubic Interpolation:**
    Perform interpolation along the z-axis first, then y, then x.
    
    a. **Z-interpolation:** For each $j \in [-1, 2]$ and $i \in [-1, 2]$, compute 4 values along the z-axis using the 4 voxels at $z$-indices $v_z-1$ to $v_z+2$.
    $$ z\_interp[j+1][i+1] = \text{CINT\_CR}(t_z, \text{data}[v_x+i][v_y+j][v_z-1], \text{data}[v_x+i][v_y+j][v_z], \text{data}[v_x+i][v_y+j][v_z+1], \text{data}[v_x+i][v_y+j][v_z+2]) $$
    *Note: The source [S1, unofficial] code snippet shows `CINT_CR` taking 4 arguments for values, but the formula definition takes 4 arguments including derivatives. If derivatives are not provided, standard cubic spline coefficients or finite difference approximations for $m$ must be used. The source [S1, unofficial] pseudocode implies `CINT_CR` handles the basis evaluation.*

    b. **Y-interpolation:** For each $i \in [-1, 2]$, interpolate the results from step (a) along the y-axis.
    $$ y\_interp[i] = \text{CINT\_CR}(t_y, z\_interp[0][i], z\_interp[1][i], z\_interp[2][i], z\_interp[3][i]) $$

    c. **X-interpolation:** Interpolate the results from step (b) along the x-axis.
    $$ V(\mathbf{p}) = \text{CINT\_CR}(t_x, y\_interp[0], y\_interp[1], y\_interp[2], y\_interp[3]) $$

5.  **Gradient Computation:**
    The gradient $\nabla V(\mathbf{p})$ can be computed analytically if the basis functions' derivatives are used, or by interpolating pre-computed vertex gradients.
    
    If using pre-computed vertex gradients $\mathbf{g}_{ijk}$ at each voxel corner:
    Apply the same tri-cubic interpolation structure to each component of the gradient vector independently.
    $$ \nabla V(\mathbf{p}) = (\text{TriCubic}(t, \mathbf{g}_x), \text{TriCubic}(t, \mathbf{g}_y), \text{TriCubic}(t, \mathbf{g}_z)) $$
    
    If gradients are not pre-computed, they can be estimated using finite differences on the interpolated field or by computing the derivative of the basis functions directly if the scalar values are treated as samples of a cubic spline. The source [S2] mentions `gradients.compute_discrete_gradients(values)` as an alternative to analytical gradients.

**Pseudocode:**

```python
def tri_cubic_interpolate(data, bounds_min, voxel_dim, p):
    """
    data: 3D array [nx, ny, nz]
    bounds_min: (bx, by, bz)
    voxel_dim: (dx, dy, dz)
    p: (px, py, pz)
    """
    # 1. Compute voxel coordinates and offset
    vx = int((p[0] - bounds_min[0]) / voxel_dim[0])
    vy = int((p[1] - bounds_min[1]) / voxel_dim[1])
    vz = int((p[2] - bounds_min[2]) / voxel_dim[2])
    
    tx = (p[0] - (bounds_min[0] + vx * voxel_dim[0])) / voxel_dim[0]
    ty = (p[1] - (bounds_min[1] + vy * voxel_dim[1])) / voxel_dim[1]
    tz = (p[2] - (bounds_min[2] + vz * voxel_dim[2])) / voxel_dim[2]
    
    # 2. Define cubic basis functions
    def h00(t): return 2*t**3 - 3*t**2 + 1
    def h10(t): return t**3 - 2*t**2 + t
    def h01(t): return -2*t**3 + 3*t**2
    def h11(t): return t**3 - t**2
    
    # 3. Helper for 1D cubic interpolation with derivatives
    # Note: If derivatives are not available, this function needs to approximate them
    # or use a standard cubic spline solver. Here we assume derivatives are passed.
    def cint_cr(t, p0, p1, m0, m1):
        t2 = t * t
        t3 = t2 * t
        return h00(t)*p0 + h10(t)*m0 + h01(t)*p1 + h11(t)*m1

    # 4. Z-interpolation
    # We need 4x4x4 neighborhood. Indices relative to vx, vy, vz are -1, 0, 1, 2
    z_interp = [[0.0]*4 for _ in range(4)]
    for j in range(-1, 3): # y offset
        for i in range(-1, 3): # x offset
            # Get 4 z-values and their derivatives
            # Assuming we have a function get_derivs that returns (val, deriv)
            # For simplicity, if only values are known, m0, m1 must be estimated.
            # Source [S1, unofficial] implies CINT_CR takes values and derivatives.
            # If derivatives are not stored, one might use finite differences:
            # m0 = (data[vx+i][vy+j][vz+1] - data[vx+i][vy+j][vz-1]) / 2
            # But strictly following [S1, unofficial], we assume derivatives are inputs or computed.
            
            # Placeholder for derivative retrieval
            # In a real implementation, `data` might be a struct containing value and gradient
            # or gradients are computed separately.
            
            # For this pseudocode, we assume `get_val` and `get_grad` access the grid
            # and return the scalar value and its partial derivative at the grid vertex.
            
            vals_z = [get_val(data, vx+i, vy+j, vz+k) for k in range(-1, 3)]
            grads_z = [get_grad(data, vx+i, vy+j, vz+k) for k in range(-1, 3)] # Assuming gradient is stored or computed
            
            # Interpolate along Z using Hermite basis
            # CINT_CR(t, p_k, p_{k+1}, m_k, m_{k+1})
            # Here m_k is the derivative along Z.
            
            # Note: The source [S1, unofficial] code snippet uses CINT_CR with 4 arguments for values.
            # This contradicts the formula definition. 
            # Re-reading [S1, unofficial]: "CINT_CR(t.z, field(data, ...), ...)"
            # It seems [S1, unofficial] might be using a cubic interpolation that only takes values 
            # (like Catmull-Rom or cubic spline with computed slopes).
            # However, the formula explicitly uses derivatives.
            # We will stick to the formula definition which requires derivatives.
            
            # If derivatives are not available, we cannot use the exact formula from [S1, unofficial] 
            # without approximation. We assume derivatives are available via `get_grad`.
            
            # Interpolate Z
            # We need to interpolate 4 lines (for each i, j) along Z
            # The result is a 4x4 grid of values at the Z-interpolated plane
            
            # Let's assume `cint_cr` handles the basis evaluation
            # We need 4 values for the interpolation segment? 
            # No, Hermite interpolation uses 2 points and 2 slopes.
            # The source [S1, unofficial] loop: `CINT_CR(t.z, field(data, v_i[0]+i, v_i[1]+j, v_i[2]-1), ...)`
            # It passes 4 values. This suggests a Catmull-Rom spline or similar 
            # which converts 4 points to slopes internally.
            
            # Catmull-Rom to Hermite conversion:
            # m0 = 0.5 * (p1 - p-1)
            # m1 = 0.5 * (p2 - p0)
            # Then use Hermite.
            
            p_m1 = vals_z[0]
            p_0 = vals_z[1]
            p_1 = vals_z[2]
            p_2 = vals_z[3]
            
            m0 = 0.5 * (p_1 - p_m1)
            m1 = 0.5 * (p_2 - p_0)
            
            z_interp[j+1][i+1] = cint_cr(tz, p_0, p_1, m0, m1)

    # 5. Y-interpolation
    y_interp = [0.0]*4
    for i in range(-1, 3):
        # Get 4 Z-interpolated values for this X slice
        vals_y = [z_interp[j+1][i+1] for j in range(-1, 3)]
        
        p_m1 = vals_y[0]
        p_0 = vals_y[1]
        p_1 = vals_y[2]
        p_2 = vals_y[3]
        
        m0 = 0.5 * (p_1 - p_m1)
        m1 = 0.5 * (p_2 - p_0)
        
        y_interp[i] = cint_cr(ty, p_0, p_1, m0, m1)

    # 6. X-interpolation
    vals_x = y_interp
    p_m1 = vals_x[0]
    p_0 = vals_x[1]
    p_1 = vals_x[2]
    p_2 = vals_x[3]
    
    m0 = 0.5 * (p_1 - p_m1)
    m1 = 0.5 * (p_2 - p_0)
    
    result = cint_cr(tx, p_0, p_1, m0, m1)
    
    return result
```

## Subtopics

### [Nearest Voxel Lookup with Periodic Boundary](1573-nearest-voxel-lookup-with-periodic-boundary.md)
Nearest Voxel Lookup retrieves the scalar value of the single grid voxel containing or nearest to a continuous sample point, without interpolating neighboring values. It solves the problem of mapping continuous world-space coordinates to discrete memory indices in a dense volume grid. Unlike [Interpolated Discrete Values & Gradients](1268-interpolated-discrete-values-gradients.md), which blends adjacent voxels for smoothness, this method produces a piecewise-constant field that preserves sharp discontinuities but introduces aliasing artifacts. It differs from [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md) by returning a single value rather than a set of corner indices, and from [Piecewise Quadratic Hermite Interpolation](4001-piecewise-quadratic-hermite-interpolation.md) by using zero-order approximation instead of higher-order continuity [G].

### [Dense Copy Extraction](3215-dense-copy-extraction.md)
Dense Copy Extraction extracts a spatial region defined by a bounding box from a sparse grid representation into a contiguous dense 3D array. It solves the problem of converting sparse, hierarchical data structures (like OpenVDB) into uniform grids suitable for dense rendering, machine learning inputs, or standard image processing. Unlike sibling methods that query individual points or gradients, this method performs a bulk conversion, initializing the output with a background value and overwriting it with interpolated values for all coordinates within the specified bounds.

### [Mipmap Grid Query](4154-mipmap-grid-query.md)
Mipmap Grid Query retrieves scalar values from a multi-resolution grid hierarchy by selecting a mip level based on the spatial distance of the query point from the center of the base bounding box. It solves the problem of aliasing and resolution mismatch in dense volume rendering by automatically downscaling the query resolution as the point moves further from the center, assuming a geometric scaling relationship between mip levels. It differs from standard trilinear interpolation by dynamically adjusting the grid resolution used for the lookup based on spatial context rather than a fixed user-defined level.

### [Cylindrical Coordinate Interpolation](4282-cylindrical-coordinate-interpolation.md)
Cylindrical Coordinate Interpolation maps Cartesian query points to cylindrical space before sampling the volume data, enabling efficient texture-based lookup for geometries with cylindrical symmetry. It differs from standard Cartesian interpolation by remapping the coordinate system to align with the geometry's principal axis.

### [Data Interpolation](7180-data-interpolation.md)
Data Interpolation is a preprocessing technique that maps arbitrarily shaped or scattered 3D data grids into rectangular grids suitable for visualization software and volume texture generation. It solves the problem of uneven data structures by converting non-uniform or scattered inputs into regular grids, enabling shader programming and standard volume rendering pipelines. It differs from sibling methods like [Nearest Voxel Lookup](1573-nearest-voxel-lookup-with-periodic-boundary.md) by actively reconstructing values via filtering rather than simple lookup, and from [Polynomial and Spline Interpolation](11104-polynomial-and-spline-interpolation.md) by focusing on the global grid construction and filtering strategy rather than local basis functions alone.

### [Polynomial and Spline Interpolation](11104-polynomial-and-spline-interpolation.md)
Polynomial and Spline Interpolation provides a continuous, differentiable scalar or vector field $u(\mathbf{p})$ from discrete grid data, enabling smooth volume rendering and gradient-based shading. It is distinguished from nearest-neighbor or simple linear methods by its higher-order continuity ($C^1$ or $C^2$) and from global basis methods by its local support, ensuring that the value at any query point depends only on a finite neighborhood of grid indices.

### [Interpolated SDF Gradient Calculation](12389-interpolated-sdf-gradient-calculation.md)
Calculates the gradient of a Signed Distance Field (SDF) at a continuous position within a 4x4x4 voxel block by interpolating gradients computed at the 8 corners of the block. It differs from nearest-neighbor gradient lookup by providing smooth, continuous derivatives essential for stable ray marching and normal estimation, while operating on a fixed local block size rather than a single voxel.

### Uncertain Gradient Field Interpolation
Reconstruction of the gradient field from an uncertain scalar field, resulting in a trivariate random vector $\mathbf{Y}$ representing the uncertainties of partial derivatives along x, y, and z [S3]. For voxels falling out of the support of the basis function $\rho$, zero weights are assigned [S3]. The uncertain gradient is obtained from linear combinations of random variables at neighboring voxels:
$$ \begin{bmatrix} Y_x \\ Y_y \\ Y_z \end{bmatrix} = \sum_i \begin{bmatrix} \alpha_i \\ \beta_i \\ \gamma_i \end{bmatrix} X_i $$
with weights $\begin{bmatrix} \alpha_i \\ \beta_i \\ \gamma_i \end{bmatrix} = \rho(\mathbf{v} - \mathbf{v}_i)$, where $\rho$ is the basis function (derivative reconstruction filter) and $X_i$ are random variables at neighboring voxels [S3]. When data uncertainties are modeled as (scaled) uniform distributions, the distribution of each partial derivative is a box spline [S3].

### Backprojection via Shepard's Interpolation
A technique to fit a continuous scale field $S(\mathbf{x})$ from a discrete set of LoG extrema $N=\{(\mathbf{x}_i, t_i)\}$ by interpolating the representative scales $t_i$ using basis functions, allowing for a smooth transfer function [S4, unofficial]. The basis function $\Theta(d)$ uses the fourth-degree Wendland polynomial with compact support:
$$ \Theta(d) = \left[ \left[ 1 - \frac{d}{h} \right]_0^1 \right]^4 \left( 4\frac{d}{h} + 1 \right) $$
where $[\cdot]_0^1$ is a clamping function between 0 and 1, and $h$ is a parameter controlling the local support (typically $h = k \cdot t_i$ with $k \approx 1$) [S4, unofficial]. Alternatively, the maximum operator can be used: $S(\mathbf{x}) = \max_{\mathbf{x}_i \in N} \{\Theta(||\mathbf{x} - \mathbf{x}_i||) t_i\}$ to give priority to larger features [S4, unofficial]. A pitfall is "bleeding," where a small feature inherits the scale of a large feature, handled by a visibility test [S4, unofficial].

### Kriging Interpolation
An interpolation algorithm used to construct a regular grid data model from limited and discrete 3D borehole data [S5]. The process involves gridding, selecting reference points, calculating coefficients using a variation function, and solving an equation set (e.g., via LU decomposition) to get weight coefficients $\lambda_i$. The estimated value is $R'(p_0) = \sum_{i=1}^n \lambda_i R(p_i)$ [S5].

### Zero Set Initialization of Isosurfaces
Initialization of closest points for isosurfaces defined on regularly sampled scalar fields using local gradient estimates instead of trilinear interpolation [S6]. The scalar field gradient $\nabla f(\mathbf{s})$ is estimated using central differencing. The closest point is computed by solving the linear approximation $f(\mathbf{s}') = f(\mathbf{s}) + \nabla f(\mathbf{s}) \cdot (\mathbf{s}' - \mathbf{s}) = f_0$ for $\mathbf{s}'$ [S6]. This approximation is inaccurate for high curvature regions [S6].

### Constant Filter Radius Mapping
Maps curvilinear grid data to a rectangular grid using a user-set constant filter radius for spatial interpolation [S7, unofficial]. A pitfall is that it violates the Nyquist criteria when input data has a wide range of scales and spatial densities, as a single radius cannot adequately sample all parts of the input grid [S7, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per query, but with a high constant factor due to the $4 \times 4 \times 4 = 64$ voxel accesses and cubic basis function evaluations [S1, unofficial].
- **Memory Complexity:** $O(N)$ for the grid storage, where $N$ is the number of voxels. If gradients are stored, memory usage doubles [S2].
- **Measured Performance:** Performance depends heavily on cache locality. Accessing a $4 \times 4 \times 4$ block may cause cache misses if the grid is large. [S1, unofficial] reports successful ray marching with this method in CUDA.
- **Strengths:** Provides smooth, continuous values and gradients, reducing aliasing artifacts compared to nearest-neighbor or trilinear interpolation. Essential for gradient-based shading and isosurfacing (e.g., Dual Contouring) [S2].
- **Limitations:** Computationally expensive compared to trilinear or nearest-neighbor. Requires boundary handling for voxels near the grid edges. If gradients are not pre-computed, computing them adds overhead [S2].
- **When to use:** When smooth shading, accurate normals, or high-quality isosurfaces are required.
- **When not to use:** When performance is critical and visual quality can tolerate lower-order interpolation (e.g., simple volume rendering with transfer functions that don't rely on gradients).

## Background
The method originates from the use of cubic spline interpolation in volume rendering and isosurfacing. It is implemented in libraries such as CGAL's Isosurfacing module (`CGAL::Isosurfacing::Interpolated_discrete_values_3` and `CGAL::Isosurfacing::Interpolated_discrete_gradients_3`) for dual contouring and marching cubes [S2]. The specific tri-cubic formulation with Hermite basis functions is detailed in custom volume rendering implementations [S1, unofficial]. The handling of uncertain gradients extends this to probabilistic volume rendering [S3].
