# Cylindrical Coordinate Interpolation
Also called: Interpolation in cylindrical coordinates
## Overview
Cylindrical Coordinate Interpolation maps Cartesian query points to cylindrical space before sampling the volume data, enabling efficient texture-based lookup for geometries with cylindrical symmetry [S1, unofficial]. It differs from standard Cartesian interpolation by remapping the coordinate system to align with the geometry's principal axis, reducing sampling artifacts for radially symmetric data [S1, unofficial].
## How it works
**Inputs:**
- `point`: Cartesian coordinates $(x, y, z)$ of the query location.
- `outVal`: Default output value if sampling fails.
- `triCubic`: Boolean flag selecting interpolation kernel (linear vs. trilinear/tricubic).
- `geomSize`: Dimensions of the bounding geometry $(G_x, G_y, G_z)$.
- `dataDim`: Dimensions of the volume texture $(D_x, D_y, D_z)$.
- `dataTex`: 3D texture object containing the volume data.

**Data Structures:**
- `float3`: A vector type with fields `x`, `y`, `z`.
- `cartToCyl(point)`: Helper function converting Cartesian $(x, y, z)$ to cylindrical $(r, \theta, z)$. Standard definition: $r = \sqrt{x^2 + y^2}$, $\theta = \operatorname{atan2}(y, x)$, $z = z$.

**Steps:**
1. Calculate step sizes (voxel sizes in the cylindrical domain):
   $$ L_{step} = \frac{G_x}{D_x} $$
   $$ \Theta_{step} = \frac{G_y}{D_y} $$
   $$ Z_{step} = \frac{G_z}{D_z} $$
   Note: The source code maps geometry width $G_x$ to data width $D_x$ for the radial/length dimension, geometry height $G_y$ to data height $D_y$ for the angle dimension, and geometry depth $G_z$ to data depth $D_z$ for the vertical dimension [S1, unofficial].

2. Convert the Cartesian point to cylindrical coordinates:
   $$ \mathbf{c} = \text{cartToCyl}(\text{point}) $$
   Let $\mathbf{c} = (c_x, c_y, c_z)$, where $c_x$ is radius, $c_y$ is angle, and $c_z$ is height.

3. Normalize cylindrical coordinates to texture coordinates $\mathbf{t} = (t_x, t_y, t_z)$:
   $$ t_x = \frac{c_x}{L_{step}} $$
   $$ t_y = \frac{c_y}{\Theta_{step}} $$
   $$ t_z = \frac{c_z}{Z_{step}} $$

4. Boundary Check:
   If any component of $\mathbf{t}$ is outside the valid range $[0, D_i - 1]$ for its respective dimension $i \in \{x, y, z\}$, return `outVal` immediately [S1, unofficial].

5. Sampling:
   - If `triCubic` is true, call `cubicInterpolate(t)`. This function performs tricubic interpolation using the 8 surrounding voxels and their gradients (or differences) to compute a smooth value [S1, unofficial].
   - Otherwise, perform linear texture sampling:
     $$ \text{value} = \text{tex3D}(\text{dataTex}, t_x, t_y, t_z) $$
     This performs trilinear interpolation using hardware texture units [S1, unofficial].

**Pseudocode:**
```python
def interpolate_cyl(point, out_val, tri_cubic, geom_size, data_dim, data_tex):
    # 1. Calculate step sizes
    length_step = geom_size.x / data_dim.width
    angle_step = geom_size.y / data_dim.height
    height_step = geom_size.z / data_dim.depth

    # 2. Convert to cylindrical coordinates
    # cartToCyl returns (radius, angle, height)
    cyl_coord = cart_to_cyl(point)

    # 3. Normalize to texture coordinates
    tex_coord_x = cyl_coord.x / length_step
    tex_coord_y = cyl_coord.y / angle_step
    tex_coord_z = cyl_coord.z / height_step

    # 4. Boundary check
    if (tex_coord_x < 0 or tex_coord_x > data_dim.width - 1 or
        tex_coord_y < 0 or tex_coord_y > data_dim.height - 1 or
        tex_coord_z < 0 or tex_coord_z > data_dim.depth - 1):
        return out_val

    # 5. Sampling
    if tri_cubic:
        return cubic_interpolate(tex_coord_x, tex_coord_y, tex_coord_z)
    else:
        # Linear texture sampling
        return tex3d_sample(data_tex, tex_coord_x, tex_coord_y, tex_coord_z)
```

## Subtopics

### Spherical Coordinate Interpolation
Interpolation in spherical coordinates, mapping Cartesian points to spherical space before sampling [S1, unofficial]. It calculates step sizes for length, longitude, and latitude, converts the point, adds a Z-offset (`geomSize.z`) to the spherical coordinates, and maps them to texture coordinates: $X = \text{longitude}/\text{longStep}$, $Y = \text{latitude}/\text{latStep}$, $Z = \text{length}/\text{lengthStep}$ [S1, unofficial]. It uses the same linear or cubic sampling logic as the cylindrical variant and returns the output value if texture coordinates are out of bounds [S1, unofficial]. Choose this for geometries with spherical symmetry.

## Operating characteristics
**Time Complexity:** $O(1)$ per sample. The conversion and normalization are constant-time arithmetic operations. The sampling cost depends on the kernel: linear is typically faster due to hardware acceleration, while cubic requires more arithmetic operations [S1, unofficial].
**Memory Complexity:** $O(1)$ auxiliary memory. The method relies on the pre-allocated 3D texture `dataTex` [S1, unofficial].
**Strengths:** Efficiently handles cylindrical geometries by aligning the sampling grid with the data structure, reducing aliasing and improving cache coherence for radially symmetric volumes [S1, unofficial].
**Limitations:** Only suitable for data with cylindrical symmetry. Requires careful handling of the angle discontinuity at $\pm \pi$ if the data wraps around, though the source implementation assumes a direct mapping [S1, unofficial]. Out-of-bounds checks are explicit, which may branch unpredictably [S1, unofficial].

## Background
This method originates from a CUDA-based volume rendering implementation for the DTU dataset, specifically designed to handle different geometric types (cylindrical and spherical) within a unified framework [S1, unofficial]. It was part of an unofficial repository (`ojaisnielsen/dtu-2010-cuda-volume-rendering`) demonstrating GPU-accelerated ray casting with flexible coordinate transformations [S1, unofficial].
