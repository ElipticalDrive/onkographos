# SDF Grid Sampling

Also called: GridSampler, wsSample

## Overview
SDF Grid Sampling evaluates a Signed Distance Field (SDF) at arbitrary query points using various interpolation strategies, typically within a sparse voxel grid structure [S1, unofficial]. It solves the problem of retrieving continuous geometric values from discrete voxel representations for ray marching or volume rendering. It differs from its parent [Voxel Interpolation (Nearest, Trilinear, Triquadratic, Tricubic)](6486-voxel-interpolation-nearest-trilinear-triquadratic-tricubic.md) by specifically wrapping the interpolation logic for SDF-based rendering pipelines, often integrating with transform matrices and parallel execution frameworks like TBB [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A set of 3D query points $P = \{p_0, p_1, \dots, p_n\}$, a grid accessor providing access to the underlying voxel data, and a spatial transform mapping world coordinates to voxel space.
- Output: A vector of SDF values corresponding to the query points.

**Data Structures:**
The implementation relies on a `GridSampler` class (e.g., `openvdb::tools::GridSampler`) which encapsulates:
1.  **Grid Accessor:** A handle to the grid's value type (e.g., `openvdb::FloatGrid::ConstAccessor`) allowing efficient lookup of voxel values.
2.  **Transform:** A spatial transform object (e.g., `grid->transform()`) used to convert world-space query points into the grid's local coordinate system.
3.  **Interpolation Mode:** An integer or enum specifying the interpolation strategy.

**Steps:**
1.  Initialize the `GridSampler` with the grid accessor and the grid's spatial transform.
2.  Iterate over the input query points. In high-performance implementations, this iteration is parallelized using thread-based parallelism (e.g., `tbb::parallel_for`) to distribute the workload across CPU cores [S1, unofficial].
3.  For each query point $p_i$:
    a.  Convert $p_i$ from world space to voxel space using the transform.
    b.  Invoke the sampling method (e.g., `wsSample`) on the sampler instance.
    c.  The sampler determines the surrounding voxel corners based on the interpolation mode.
    d.  Interpolate the SDF values from the corners to produce the final scalar value.
4.  Store the result in the output array.

**Parameters:**
-   **Mode:** Determines the interpolation type.
    -   `1`: BoxSampler (Trilinear interpolation) [S1, unofficial].
    -   `2`: QuadraticSampler (Triquadratic interpolation) [S1, unofficial].
    -   Else: PointSampler (Nearest neighbor) [S1, unofficial].
    -   Default: `1` (Trilinear) [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Out-of-Bounds:** If a query point falls outside the active voxel bounds of the grid, the behavior depends on the accessor's boundary handling (e.g., returning 0, infinity, or clamping).
-   **Precision:** Floating-point precision in the transform and interpolation steps can introduce artifacts, especially at large scales or near the zero-crossing surface [S1, unofficial].

## Subtopics

### Naive SVRaster-SDF Extension
A baseline approach that repurposes SVRaster's voxel-corner storage to store SDF values instead of densities, using trilinear interpolation for point queries and NeuS-style alpha blending for rendering [S2, unofficial].
-   **Definition:** Stores SDF values in the voxel corner geometry `geov` (previously used for density) [S2, unofficial].
-   **Method:**
    1.  Evaluate the SDF field $f(\cdot)$ at the ray-voxel entry and exit points $t_i$ and $t_{i+1}$ [S2, unofficial].
    2.  Compute opacity $\alpha_i$ using the NeuS SDF-based alpha-blending formulation using the logistic cumulative density function $\Phi_s(f)$ [S2, unofficial].
-   **Formula:** The SDF value $f(p)$ at a continuous 3D point $p$ inside voxel $v$ is obtained by trilinear interpolation over its corners `geov`:
    $$ f(p) = \text{interp}(\text{geov}, q) $$
    where $q = \frac{p - v_{\min}}{v_l}$, with $v_{\min}$ being the voxel corner closest to the world origin and $v_l$ the voxel side length [S2, unofficial].
-   **Pitfalls:** This naive approach exhibits high-frequency noise, fragmented surfaces, and inconsistent level-set structures due to the independent parameterization of sparse voxels lacking spatial coupling [S2, unofficial].

## Operating characteristics
-   **Time Complexity:** Linear with respect to the number of query points $O(N)$, where each point requires a constant number of lookups and interpolation operations. Parallelization reduces wall-clock time proportionally to the number of cores [S1, unofficial].
-   **Memory Complexity:** Depends on the underlying grid storage (sparse vs. dense). The sampler itself has minimal overhead [S1, unofficial].
-   **Strengths:** Efficient evaluation of SDFs for ray marching; flexible interpolation modes [S1, unofficial].
-   **Limitations:** Naive extensions on sparse voxel structures (like SVRaster) suffer from noise and fragmentation due to lack of spatial coupling between independent voxels [S2, unofficial].

## Background
The `GridSampler` tool is part of the OpenVDB library ecosystem, specifically within its tools module for interpolation [S1, unofficial]. It is used in pipelines that convert mesh data to volume data (e.g., `mesh2volume`) and subsequently sample that data for visualization or further processing [S1, unofficial]. The specific integration with TBB for parallel sampling highlights its use in high-performance computing contexts [S1, unofficial]. The naive SVRaster-SDF extension represents an early attempt to combine sparse voxel rasterization with neural implicit surface representations (NeuS) before more advanced voxel association mechanisms were developed [S2, unofficial].
