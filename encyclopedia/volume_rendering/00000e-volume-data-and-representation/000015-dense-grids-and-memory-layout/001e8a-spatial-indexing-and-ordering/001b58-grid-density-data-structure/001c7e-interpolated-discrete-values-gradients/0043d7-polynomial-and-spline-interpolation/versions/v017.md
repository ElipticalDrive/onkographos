# Polynomial and Spline Interpolation

Also called: Continuous Field Reconstruction from Discrete Samples, Basis Function Interpolation

## Overview
Polynomial and Spline Interpolation provides scalar value and gradient fields computed from discrete data at grid vertices using continuous basis functions, enabling smooth reconstruction of volume data for ray casting and feature extraction. It sets itself apart from nearest-neighbor or simple copy methods by ensuring $C^0$ or higher continuity across cell boundaries, reducing aliasing and artifacts in gradient-sensitive tasks such as normal estimation and density smoothing [S1][S2, S3, unofficial].

## Shared principles
All methods in this family operate on a dense grid tensor $\mathbf{G}$ of shape $(D_x, D_y, D_z, C)$, where $D$ are dimensions and $C$ is the channel count (e.g., density, color, or derivatives) [S1][S2, S3, unofficial]. The core mechanism involves:
1.  **Locating the Support:** Mapping a query point $\mathbf{p} \in \mathbb{R}^3$ to a local coordinate system within a specific grid cell or support region. This typically involves computing floor/ceil indices to identify the enclosing voxel(s) or the range of control points influencing the query [S1][S2, S3, unofficial].
2.  **Gathering Data:** Retrieving the relevant discrete values (and optionally derivatives) from the grid vertices or control points that define the local basis functions. For standard voxel grids, this is the 8 corners of the enclosing cell; for B-splines, it is a 4x4x4 support kernel [S1][S2, S3, unofficial].
3.  **Basis Evaluation:** Computing weights using polynomial basis functions defined on the normalized local coordinates $(u, v, w) \in [0, 1]^3$ (or a similar local domain). These basis functions determine the contribution of each gathered data point to the final interpolated value [S1][S2, S3, unofficial].
4.  **Weighted Summation:** Combining the gathered data with the computed basis weights to produce the final interpolated scalar or vector value [S1][S2, S3, unofficial].

Boundary conditions (clamping, periodic, or constant) are applied to indices that fall outside the valid grid domain $[0, D_d-1]$ during the gathering step [S1][S2, S3, unofficial].

## Subtopics

### [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md)
Grid Cell Collection via Corner Indices is a method for retrieving the eight vertex values of the grid cell enclosing a query point, serving as the foundational data gathering step for trilinear interpolation in dense voxel grids. It solves the problem of efficiently mapping arbitrary floating-point coordinates to the discrete tensor indices required for volume rendering or feature extraction, handling boundary conditions and batched queries. It sets itself apart from higher-order methods like [B-spline Field Interpolation](11066-b-spline-field-interpolation.md) by strictly limiting the support to the immediate 8 neighbors of the enclosing cell, and from [VoxelGrid](2159-voxelgrid.md) by focusing on the index computation and gathering logic rather than the storage structure itself.

### [Piecewise Quadratic Hermite Interpolation](4001-piecewise-quadratic-hermite-interpolation.md)
A method for interpolating scalar fields within a 1D subinterval using two piecewise quadratic Bézier curves to satisfy Hermite data (value and derivative) at both endpoints. It solves the incompatibility of single quadratic interpolation with four constraints (two values, two derivatives) by splitting the interval, providing exact interpolation for normalized fields and better stability for small subdivisions compared to cubic methods.

### [Hermite Interpolation of Scalar Fields](9450-hermite-interpolation-of-scalar-fields.md)
Hermite interpolation of scalar fields renders scalar-valued functions (such as height fields or signed distance fields) by storing partial derivatives alongside function values on a regular grid, using these derivatives to construct a globally $C^1$-continuous interpolation between samples. Unlike standard trilinear interpolation which yields only $C^0$ continuity, this method guarantees smooth gradients, allowing the exact normals of the reconstructed cubic Hermite surface to be used as shading normals, providing a storage-efficient replacement for normal mapping when normals are already derived from the field.

### [B-spline Field Interpolation](11066-b-spline-field-interpolation.md)
B-spline Field Interpolation is a method for function interpolation using cubic B-splines, defined by a grid of control points and weights, where shape functions have local influence. It solves the problem of evaluating a continuous, smooth scalar or vector field from discrete control points, ensuring $C^2$ continuity across cell boundaries. It sets itself apart from its siblings by using a fixed 4x4x4 support kernel with specific cubic polynomial basis functions that sum to 1, rather than interpolating directly through control points (which would require higher degrees of freedom or different basis definitions).

### [Voxel Data Interpolation and Sampling](12781-voxel-data-interpolation-and-sampling.md)
Voxel Data Interpolation and Sampling retrieves scalar values, gradients, and transformed colors at arbitrary 3D positions within a volume grid. It supports configurable interpolation modes (trilinear or nearest neighbor) and transfer function input modes, enabling the evaluation of density, color, and opacity during ray casting. Unlike the parent [Polynomial and Spline Interpolation](11104-polynomial-and-spline-interpolation.md) which defines the general basis function framework, this method specifically implements the discrete grid access and boundary handling required for standard voxel-based volume rendering.

### [Third Order Elimination (Scaling)](13712-third-order-elimination-scaling.md)
Third Order Elimination (Scaling) is a quadratic interpolation method that derives a second-order polynomial from a cubic Hermite basis by scaling the input derivatives to force the third-order coefficient to zero. It solves the problem of approximating a smooth implicit function with reduced computational complexity while maintaining continuity, specifically distinguishing itself from [B-spline Field Interpolation](11066-b-spline-field-interpolation.md) and [Piecewise Quadratic Hermite Interpolation](4001-piecewise-quadratic-hermite-interpolation.md) by using a multiplicative scaling factor rather than a least-squares fit or additive offset.

### [Tricubic Interpolation](14963-tricubic-interpolation.md)
Tricubic interpolation is a higher-order method that employs cubic polynomials over a 4x4x4 neighborhood of 64 points to approximate smooth underlying functions with an accuracy of $O(h^4)$, where $h$ is the grid spacing. Unlike trilinear interpolation which provides only $C^0$ continuity, tricubic interpolation yields $C^1$ continuity, significantly reducing artifacts in gradient-sensitive tasks such as volume rendering and medical imaging upsampling. It is chosen when differentiable outputs are required, despite the increased computational expense compared to lower-order methods.

### [NURBS Spline Representation for Measurement Coordinates](16136-nurbs-spline-representation-for-measurement-coordinates.md)
This method represents uncertain measurement coordinates (such as view angles and detector locations) as a NURBS surface, where control points and weights are optimized jointly with volume reconstruction. It differs from standard grid interpolation by learning the geometric parameters of the coordinate system itself, rather than interpolating values within a fixed grid.

#### Box Spline Interpolation
**Definition:** A piecewise polynomial interpolation function with finite support, uniquely defined by a direction matrix, used for reconstructing continuous splines from discrete datasets [S1].
**Steps:** Construct the box-spline by taking consecutive directional convolutions along each column direction of the direction matrix $\Xi$. For non-Cartesian lattices, apply a change-of-variables to the Cartesian lattice theory [S1].
**Formula:** Recursive definition: $M_{\Xi \cup \{\mathbf{d}\}}(\mathbf{x}) = \int_0^1 M_\Xi(\mathbf{x} - t\mathbf{d}) dt, \mathbf{x} \in \mathbb{R}^n$ (Eq 6) [S1].
**Comparison:** Provides higher quality and reasonable performance compared to trilinear or tricubic interpolations commonly used on mobile devices [S1].
**Usage:** Mobile volume rendering, FCC datasets, GPU ray casting [S1].

#### Distance Weighting Filter
**Definition:** A spatial interpolation filter that assigns weights based on distance to preserve data structure during grid mapping [S2, unofficial].
**Parameter:** Filter radius determines the spatial extent of the weighting; must be shortened to increase sampling rate [S2, unofficial].
**Pitfall:** Assumes a constant, second-order distribution of weighting terms based on the filter radius; under-samples areas with high data frequency, causing inner and outer shells to disappear where data density varies [S2, unofficial].
**Comparison:** Performs worse than the Gaussian filter for preserving accuracy because it lacks a degree of freedom for adjusting sampling frequency independently of radius [S2, unofficial].

#### Multi-scale Feature Interpolation
**Definition:** Multi-scale feature interpolation using HexPlane grids. It interpolates features from multiple resolution levels and combines them [S3, unofficial].
**Steps:** Coordinate Combinations: Generate all combinations of coordinates of size grid_dimensions from the input point dimensions (range(pts.shape[-1])). Loop over Scales: Iterate through ms_grids up to num_levels. For each scale, initialize interp_space to 1.0. Combine Scales: If concat_features is True, append interp_space to multi_scale_interp list. Else, add interp_space to the accumulated multi_scale_interp tensor. Final Concatenation: If concat_features is True, concatenate all multi_scale_interp tensors along the last dimension (dim=-1) [S3, unofficial].

## Background
The use of polynomial and spline interpolation in volume rendering has evolved to address the limitations of discrete voxel sampling, particularly on resource-constrained platforms. Early mobile volume visualization techniques leveraged tensor-based methods like trilinear and tricubic interpolation but sought higher quality with lower computational cost [S1]. Box splines, introduced by de Boor et al. as multivariate generalizations of uniform B-splines, were adopted for real-time rendering on mobile devices using FCC (Face-Centered Cubic) datasets due to their high quality and reasonable performance [S1]. The recursive construction of box splines via directional convolutions allows for efficient evaluation on non-Cartesian lattices through change-of-variables [S1].

In parallel, Hermite interpolation has been utilized to preserve gradient information, enabling $C^1$-continuous surfaces for accurate shading without storing explicit normal maps [S1]. B-spline field interpolation provides $C^2$ continuity and local control, making it suitable for smooth field reconstruction from control points [S1]. Distance weighting filters were explored for mapping scattered data to rectangular grids, though they were found to be less accurate than Gaussian filters for preserving high-frequency data structures [S2, unofficial]. More recently, multi-scale feature interpolation using HexPlane grids has been applied in dynamic neural rendering contexts to combine features from different resolutions [S3, unofficial].
