# B-spline Volume Representation with Subdivision

Also called: B-spline tensor, Chaikin subdivision

## Overview
This method represents medical image datasets using B-spline basis functions to enable smooth interpolation and multi-resolution rendering, avoiding the quality loss of linear interpolation while maintaining interactive rates [S1]. It sets itself apart from standard trilinear interpolation by providing superior image quality through subdivision algorithms that are faster than direct basis function evaluation, and it differs from simple hierarchical mipmaps by explicitly maintaining a high-resolution super-resolution representation for Regions of Interest (ROI) alongside a low-resolution approximation for global context [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A discrete 3D volume dataset $V$ with dimensions $p \times q \times r$ containing intensity values $V_{ijk}$ [S1].
*   **Outputs:**
    1.  A low-resolution approximation image of size $(N/2)^3$ (where $N$ is the original dimension) explicitly stored in memory [S1].
    2.  A super-resolution representation of the original resolution (or higher) generated via forward subdivision [S1].
    3.  A continuous representation $L(u, v, w)$ for any point within the volume [S1].

**Data Structures:**
*   **Original Volume:** A 3D array of size $p \times q \times r$ [S1].
*   **Low-Resolution Approximation:** A 3D array of size $(p/2) \times (q/2) \times (r/2)$ [S1].
*   **Super-Resolution Volume:** A 3D array of size $2p \times 2q \times 2r$ (assuming one subdivision step) [S1].
*   **ROI Definition:** A box-shaped sub-volume defined by a 3D center position and a size [S1].

**Formulas:**
The full B-spline representation of a trivariate dataset is defined as [S1]:
$$L(u, v, w) = \sum_{i=0}^{p-1} \sum_{j=0}^{q-1} \sum_{k=0}^{r-1} V_{ijk} B$$
where $B = B^m_i(u)B^m_j(v)B^m_k(w)$ are the B-spline basis functions, and $u, v, w$ are parameters for the x, y, and z axes respectively [S1].

**Forward Subdivision (Chaikin) for Quadratic B-Spline:**
To generate the super-resolution representation, the following scheme is applied independently over all main directions (x, y, z) [S1]:
$$c_{2i}^{k+1} = \frac{1}{4}c_{i-1}^k + \frac{3}{4}c_i^k$$
$$c_{2i+1}^{k+1} = \frac{3}{4}c_i^k + \frac{1}{4}c_{i+1}^k$$
where $k$ and $k+1$ refer to the coarse and fine datasets, and $c_{i-1}, c_i, c_{i+1}$ are consecutive voxel values along one of the main directions [S1].

**Reverse Subdivision:**
To obtain the low-resolution approximation explicitly stored in memory, the reverse Chaikin scheme is applied in all three main directions [S1]:
$$c_i^k = -\frac{1}{4}c_{2i-1}^{k+1} + \frac{3}{4}c_{2i}^{k+1} + \frac{3}{4}c_{2i+1}^{k+1} - \frac{1}{4}c_{2i+2}^{k+1}$$
where $k+1$ refers to the higher-resolution image and $k$ to the low-resolution approximation [S1].

**Parameters:**
*   **ROI (Region of Interest):** A box-shaped sub-volume defined by a 3D position (center) and size, used to define the area for super-resolution rendering [S1].

**Pseudocode:**

```python
def forward_subdivision_1d(coarse_data):
    """
    Applies Chaikin subdivision to a 1D array of voxel values.
    Returns a 1D array with double the length.
    """
    n = len(coarse_data)
    fine_data = [0.0] * (2 * n)
    
    # Boundary handling: The source implies access to c_{i-1} and c_{i+1}.
    # For implementation, boundary conditions must be defined.
    # Standard practice for such subdivision often assumes zero-padding 
    # or replication, but the source does not specify. [G]
    # We assume a guard for indices.
    
    for i in range(n):
        # Access neighbors with boundary checks
        c_prev = coarse_data[i-1] if i > 0 else coarse_data[0] # [G] Default to clamp
        c_curr = coarse_data[i]
        c_next = coarse_data[i+1] if i < n-1 else coarse_data[-1] # [G] Default to clamp
        
        # Even index
        fine_data[2*i] = 0.25 * c_prev + 0.75 * c_curr
        # Odd index
        fine_data[2*i+1] = 0.75 * c_curr + 0.25 * c_next
        
    return fine_data

def apply_forward_subdivision_3d(volume):
    """
    Applies forward subdivision independently over x, y, and z axes.
    """
    # Apply along X
    # Note: This requires iterating and applying 1D subdivision to each line.
    # The source states: "Applying this scheme independently over all main directions x, y and z"
    # This implies a tensor product approach.
    
    # Step 1: Subdivide along X
    # volume shape: (Z, Y, X)
    new_x = 2 * volume.shape[2]
    temp_volume = zeros((volume.shape[0], volume.shape[1], new_x))
    
    for z in range(volume.shape[0]):
        for y in range(volume.shape[1]):
            line = volume[z, y, :]
            subdivided_line = forward_subdivision_1d(line)
            temp_volume[z, y, :] = subdivided_line
            
    # Step 2: Subdivide along Y
    new_y = 2 * temp_volume.shape[1]
    temp_volume_2 = zeros((temp_volume.shape[0], new_y, temp_volume.shape[2]))
    
    for z in range(temp_volume.shape[0]):
        for x in range(temp_volume.shape[2]):
            line = temp_volume[z, :, x]
            subdivided_line = forward_subdivision_1d(line)
            temp_volume_2[z, :, x] = subdivided_line
            
    # Step 3: Subdivide along Z
    new_z = 2 * temp_volume_2.shape[0]
    final_volume = zeros((new_z, temp_volume_2.shape[1], temp_volume_2.shape[2]))
    
    for y in range(temp_volume_2.shape[1]):
        for x in range(temp_volume_2.shape[2]):
            line = temp_volume_2[:, y, x]
            subdivided_line = forward_subdivision_1d(line)
            final_volume[:, y, x] = subdivided_line
            
    return final_volume

def reverse_subdivision_1d(fine_data):
    """
    Applies reverse Chaikin subdivision to a 1D array.
    Returns a 1D array with half the length.
    """
    n_fine = len(fine_data)
    n_coarse = n_fine // 2
    coarse_data = [0.0] * n_coarse
    
    for i in range(n_coarse):
        # Indices in fine_data corresponding to the formula
        # c_{2i-1}, c_{2i}, c_{2i+1}, c_{2i+2}
        idx_2i_minus_1 = 2*i - 1
        idx_2i = 2*i
        idx_2i_plus_1 = 2*i + 1
        idx_2i_plus_2 = 2*i + 2
        
        # Boundary handling: The source does not specify boundary conditions 
        # for reverse subdivision. [G]
        # We assume a guard for indices.
        
        c_2i_minus_1 = fine_data[idx_2i_minus_1] if idx_2i_minus_1 >= 0 else 0.0 # [G] Default to 0
        c_2i = fine_data[idx_2i]
        c_2i_plus_1 = fine_data[idx_2i_plus_1] if idx_2i_plus_1 < n_fine else 0.0 # [G] Default to 0
        c_2i_plus_2 = fine_data[idx_2i_plus_2] if idx_2i_plus_2 < n_fine else 0.0 # [G] Default to 0
        
        coarse_data[i] = -0.25 * c_2i_minus_1 + 0.75 * c_2i + 0.75 * c_2i_plus_1 - 0.25 * c_2i_plus_2
        
    return coarse_data

def apply_reverse_subdivision_3d(volume):
    """
    Applies reverse subdivision independently over x, y, and z axes.
    """
    # Similar to forward, but in reverse order of dimensions and using reverse_subdivision_1d
    
    # Step 1: Reverse along X
    new_x = volume.shape[2] // 2
    temp_volume = zeros((volume.shape[0], volume.shape[1], new_x))
    
    for z in range(volume.shape[0]):
        for y in range(volume.shape[1]):
            line = volume[z, y, :]
            subdivided_line = reverse_subdivision_1d(line)
            temp_volume[z, y, :] = subdivided_line
            
    # Step 2: Reverse along Y
    new_y = temp_volume.shape[1] // 2
    temp_volume_2 = zeros((temp_volume.shape[0], new_y, temp_volume.shape[2]))
    
    for z in range(temp_volume.shape[0]):
        for x in range(temp_volume.shape[2]):
            line = temp_volume[z, :, x]
            subdivided_line = reverse_subdivision_1d(line)
            temp_volume_2[z, :, x] = subdivided_line
            
    # Step 3: Reverse along Z
    new_z = temp_volume_2.shape[0] // 2
    final_volume = zeros((new_z, temp_volume_2.shape[1], temp_volume_2.shape[2]))
    
    for y in range(temp_volume_2.shape[1]):
        for x in range(temp_volume_2.shape[2]):
            line = temp_volume_2[:, y, x]
            subdivided_line = reverse_subdivision_1d(line)
            final_volume[:, y, x] = subdivided_line
            
    return final_volume
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The source formulas reference indices $i-1$ and $i+1$ (forward) and $2i-1, 2i+1, 2i+2$ (reverse). The source does not specify how to handle boundaries at the edges of the volume. Implementers must define boundary conditions (e.g., zero-padding, replication, or periodic) [G].
*   **Explicit Storage:** The low-resolution image is explicitly stored in memory rather than evaluated on the fly to ensure fast transitions between interaction and non-interaction states [S1].

## Subtopics

### ROI-Based Super-Resolution
*   **What it is:** A technique where a user-defined 3D box (ROI) is rendered at super-resolution while the rest of the volume is rendered at low resolution.
*   **What sets it apart:** It combines global context (low-res) with local detail (super-res) to mimic medical illustrators' focus of attention.
*   **When to choose it:** When interactive exploration of large medical datasets requires both overview and detailed inspection of specific features.
*   **Link:** [ROI-Based Super-Resolution](52-roi-based-super-resolution.md)

## Operating characteristics
*   **Time Complexity:** The subdivision schemes are linear in the number of voxels processed per step. Forward subdivision doubles the resolution, increasing data size by $8\times$ for 3D. Reverse subdivision halves the resolution.
*   **Memory Complexity:** Requires storing the original volume, the low-resolution approximation, and the super-resolution volume (if generated). The low-resolution image is explicitly stored to allow fast switching [S1].
*   **Measured Performance:** The method allows for interactive rates by rendering the low-resolution approximation during user interaction and switching to the original or super-resolution representation upon cessation of interaction [S1].
*   **Strengths:** Superior image quality compared to trilinear interpolation; fast evaluation via subdivision algorithms; efficient hierarchical multi-resolution structure [S1].
*   **Limitations:** Requires explicit storage of multiple resolution levels; boundary conditions are not specified in the source [S1].
*   **When to use it:** When high-quality visualization of medical volumetric data is required at interactive frame rates, particularly for close-up views [S1].
*   **When not to use it:** When memory is extremely constrained and storing multiple resolution levels is not feasible, or when lower quality interpolation is acceptable [S1].

## Background
The method originates from the work of Unser [Uns97, Uns02] regarding the cost-benefit advantages of using splines to model images [S1]. It was applied to real-time super-resolution contextual close-up of clinical volumetric data in a paper presented at EuroVis 2006 [S1]. The subdivision algorithm used is the Chaikin subdivision algorithm, which rapidly generates quadratic B-splines [S1]. The reverse subdivision rules are based on [BS00] [S1].
