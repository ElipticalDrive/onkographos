# Voxel Data Interpolation and Sampling

Also called: getNextIntersectColor, getNextIntersectionGradient, getNextIntersectionScalar

## Overview
This method retrieves scalar values, gradients, and transformed colors at arbitrary 3D positions within a volume grid, supporting configurable interpolation and transfer function input modes [S1, unofficial]. It differs from sibling methods by explicitly exposing the gradient magnitude as a secondary input to the transfer function transformer, allowing for gradient-based opacity or color mapping, whereas siblings like [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md) focus primarily on index calculation and [B-spline Field Interpolation](11066-b-spline-field-interpolation.md) focuses on higher-order continuity without necessarily exposing raw gradient vectors for transfer functions.

## How it works
**Inputs and Outputs:**
*   **Input:** Query point $\mathbf{p} = (x, y, z)$ in voxel coordinates; Volume grid dimensions $X_{DIM}, Y_{DIM}, Z_{DIM}$; Interpolation mode $INTER\_MODE$; Transfer function input mode $TRN\_MODE$.
*   **Outputs:** Transformed color (RGBA) and optionally gradient information.

**Data Structures:**
The volume data is stored in two contiguous vectors:
1.  `scalars`: `std::vector<float>` containing scalar values $W_i$.
2.  `gradients`: `std::vector<glm::vec3>` containing 3D gradient vectors $\nabla W_i$.

The index for a voxel at integer coordinates $(x, y, z)$ is calculated as:
$$ idx(x, y, z) = x + y \cdot X_{DIM} + z \cdot X_{DIM} \cdot Y_{DIM} $$

**Parameters:**
*   $INTER\_MODE$: Integer. `1` for trilinear interpolation, `2` for nearest neighbor. [S1, unofficial]
*   $TRN\_MODE$: Integer. `1` for transfer function input $(V, V)$, `2` for $(V, |\nabla V|)$. [S1, unofficial]

**Steps:**
1.  **Boundary Check:** Determine the integer coordinates $\mathbf{c} = (\lfloor x \rfloor, \lfloor y \rfloor, \lfloor z \rfloor)$. If $\mathbf{c}$ is outside the bounds $[0, X_{DIM}-1] \times [0, Y_{DIM}-1] \times [0, Z_{DIM}-1]$, return $(0, 0, 0, 0)$ [S1, unofficial].
2.  **Value Retrieval:**
    *   If $INTER\_MODE = 2$ (Nearest Neighbor): Retrieve scalar $V$ and gradient $\mathbf{g}$ at $\mathbf{c}$ using $idx(\mathbf{c})$.
    *   If $INTER\_MODE = 1$ (Trilinear): Retrieve the 8 neighboring scalar values $W_i$ and gradient vectors $\mathbf{g}_i$ at the corners of the voxel containing $\mathbf{p}$. Compute weights based on the fractional part of $\mathbf{p}$ and interpolate to get $V$ and $\mathbf{g}$ [S1, unofficial]. *Note: The source implementation currently defaults to nearest neighbor, stating "needs to implement voxel intersection" for full trilinear support, but the structure supports it via $INTER\_MODE$* [S1, unofficial].
3.  **Transfer Function Input Preparation:**
    *   If $TRN\_MODE = 1$: Prepare input pair $(V, V)$.
    *   If $TRN\_MODE = 2$: Compute gradient magnitude $M = |\mathbf{g}| = \sqrt{g_x^2 + g_y^2 + g_z^2}$. Clamp $M$ to $[0, 1]$. Scale by 256: $M' = M \cdot 256$. Prepare input pair $(V, M')$.
4.  **Transformation:** Pass the prepared pair to the transfer function transformer (e.g., a 1D lookup or spline evaluation) to produce the final RGBA color [S1, unofficial].

**Pseudocode:**
```python
def get_voxel_color(p_x, p_y, p_z, scalars, gradients, x_dim, y_dim, z_dim, inter_mode, trn_mode):
    # 1. Boundary Check
    ix = int(p_x)
    iy = int(p_y)
    iz = int(p_z)
    
    if not (0 <= ix < x_dim and 0 <= iy < y_dim and 0 <= iz < z_dim):
        return (0.0, 0.0, 0.0, 0.0)

    # 2. Value Retrieval
    # Note: Full trilinear interpolation requires 8 neighbors and fractional weights.
    # The source implementation currently uses nearest neighbor only.
    # [G] Assuming nearest neighbor for the provided implementation details.
    
    idx = ix + iy * x_dim + iz * x_dim * y_dim
    
    if idx < len(scalars):
        V = scalars[idx]
    else:
        V = 0.0
        
    if idx < len(gradients):
        g_vec = gradients[idx]
    else:
        g_vec = (0.0, 0.0, 0.0)

    # 3. Transfer Function Input Preparation
    if trn_mode == 1:
        input_val_1 = V
        input_val_2 = V
    elif trn_mode == 2:
        input_val_1 = V
        mag = (g_vec[0]**2 + g_vec[1]**2 + g_vec[2]**2)**0.5
        # Clamp to [0, 1]
        mag = max(0.0, min(1.0, mag))
        input_val_2 = mag * 256.0
    else:
        # Default fallback
        input_val_1 = V
        input_val_2 = V

    # 4. Transformation
    # [G] The specific transfer function logic (e.g., 1D lookup) is not detailed in the source snippet.
    # This step calls the user-defined transformer with the prepared inputs.
    color = transform_transfer_function(input_val_1, input_val_2)
    
    return color
```

## Subtopics

### Trilinear Interpolation
Linear interpolation across 8 neighbors. Chosen when smoothness is required over performance. Link to [Polynomial and Spline Interpolation](11104-polynomial-and-spline-interpolation.md).

### Nearest Neighbor
Sampling the closest voxel. Chosen for speed or when discrete voxel values are preferred. Link to [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md).

## Operating characteristics
*   **Time Complexity**: $O(1)$ per query, as it accesses a fixed number of neighbors (1 for nearest, 8 for trilinear) regardless of grid size.
*   **Memory Complexity**: $O(N)$ where $N$ is the number of voxels, storing both scalars and gradients.
*   **Strengths**: Simple implementation; supports gradient-based transfer functions which are crucial for surface-like rendering in volume visualization.
*   **Limitations**: The source implementation notes that full trilinear interpolation was not fully implemented at the time of the report ("currently do the nearest neighbour only"), potentially leading to aliasing artifacts if trilinear mode is selected but not correctly coded [S1, unofficial].
*   **When to use**: When gradient information is needed for opacity control and performance is critical, or when the volume is low-resolution enough that nearest neighbor artifacts are acceptable.

## Background
This method originates from a student project for CSE-333 Computer Graphics (2020) involving volume ray casting [S1, unofficial]. It was designed to support 1D transfer functions and optional gradient-based opacity, addressing the need for flexible volume rendering parameters in an educational ray casting context.
