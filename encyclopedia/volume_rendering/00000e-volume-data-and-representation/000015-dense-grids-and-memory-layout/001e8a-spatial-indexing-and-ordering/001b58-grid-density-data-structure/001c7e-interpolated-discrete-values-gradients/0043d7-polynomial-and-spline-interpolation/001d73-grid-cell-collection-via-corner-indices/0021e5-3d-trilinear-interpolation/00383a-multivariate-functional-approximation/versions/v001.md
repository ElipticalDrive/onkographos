# Multivariate Functional Approximation

Also called: Functional approximation

## Overview
Multivariate Functional Approximation (MFA) is a continuous volume representation method that evaluates off-grid sample locations using control points and polynomial degrees to achieve higher accuracy than trilinear interpolation [S1, unofficial]. It distinguishes itself by approximating C1 continuity across partition boundaries without requiring ghost voxels, thereby reducing data size overhead while preserving shading smoothness [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D dataset of resolution $n^3$, partitioned into micro-blocks.
*   **Output:** A "micro-model" containing control points and knot information for a fitted B-spline, plus metadata (NCP, degree).

**Data Structures:**
The micro-model storage layout is defined by the following formula for its size in bytes [S1, unofficial]:
$$Size(Micro-model) = 1 + ((NCP + degree) \times 3 + NCP^3) \times 4$$
Where:
*   $NCP$: Number of Control Points.
*   $degree$: Polynomial order of the fitted B-spline.
*   The constant `1` likely represents a header or type identifier.
*   The term `((NCP + degree) * 3 + NCP^3) * 4` suggests the storage of knot vectors and control point coordinates (assuming 32-bit floats). Specifically, it implies storage for $(NCP + degree)$ knots in 3 dimensions and $NCP^3$ control points in 3 dimensions.

**Parameters:**
*   **NCP (Number of Control Points):** The primary determinant of encoded micro-model size and fitting accuracy. Valid range for a micro-block of resolution $n^3$ is $[degree+1, n]$ [S1, unofficial]. A larger NCP yields higher fitting accuracy, but the optimal NCP for a given error bound is data-dependent [S1, unofficial].
*   **Degree:** The polynomial order of the fitted B-spline [S1, unofficial].

**Algorithm Steps:**
1.  **Partitioning:** Divide the input 3D dataset into micro-blocks. For a multi-resolution framework with $m$ Levels of Detail (LODs), the number of micro-blocks increases twofold along each $x, y, z$ direction from the $i$-th LOD to the $i+1$-th LOD [S1, unofficial].
2.  **Selection:** For each micro-block, select the $NCP$ and $degree$ parameters. Finding the minimal $NCP$ under a specific error bound involves an exhaustive search, as the optimal value is data-dependent [S1, unofficial].
3.  **Fitting:** Fit a multivariate B-spline to the data within the micro-block using the selected $NCP$ and $degree$. This involves determining the knot vector and control points that minimize the global error [S1, unofficial].
4.  **Encoding:** Store the resulting control points and knot information in the micro-model format defined by the size formula [S1, unofficial].

    # This implies the sum over k=1 to m of (2^k)^3 * O((n/k)^4).
    
    micro_models = []
    
    # Iterate through all micro-blocks in the current LOD
    # The exact iteration logic depends on the partitioning scheme,
    # but generally involves dividing the volume into sub-cubes.
    for block in partition_volume(dataset, lod_level):
        # Determine optimal NCP and degree
        # This is data-dependent and may require exhaustive search
        ncp, degree = find_optimal_parameters(block)
        
        # Fit B-spline to block data
        # This step computes the control points and knots
        control_points, knots = fit_bspline(block, ncp, degree)
        
        # Create micro-model
        # Size = 1 + ((NCP + degree) * 3 + NCP^3) * 4 bytes

def query_mfa(micro_model, point):
    """
    Evaluates the MFA model at a specific 3D point.
    
    Args:
        micro_model: The encoded micro-model.
        point: 3D coordinate (x, y, z).
        
    Returns:
        Scalar value at the point.
    """
    # Evaluate the B-spline at the given point using the control points and knots
    # This provides high-order accuracy and random access to value and derivative
    value = evaluate_bspline(micro_model['control_points'], 
                             micro_model['knots'],

**Edge Cases and Pitfalls:**
*   **Encoding Time:** For large-scale datasets (large $n$) with multiple LODs (large $m$), the encoding time can become impractical [S1, unofficial].
*   **Query Time:** Query time is the main performance bottleneck for visualizing large-scale datasets [S1, unofficial].
*   **Parameter Selection:** The optimal NCP is data-dependent. Using a fixed NCP may lead to suboptimal accuracy or unnecessary data size [S1, unofficial].

### C3 Data Approximation
A method for approximating volume data using C3 data. The (1,1,1) approximation yields a C0 smooth approximation. The (3,3,3) approximation yields at least C1 smooth approximation and takes longer to calculate [S2, unofficial].
*   **Parameters:** Approximation type: (1,1,1) or (3,3,3). The (3,3,3) calculation takes much longer than (1,1,1) for the same image size [S2, unofficial]. Polygon structure: Each polygon has three to six vertices with XYZ coordinate values and a normal associated with each vertex [S2, unofficial].
*   **Performance:** Output size for (1,1,1) approximation: 121,486 polygons for a sphere test data. Output size for (3,3,3) approximation: 78,741 polygons for the same sphere test data [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Encoding time for a 3D dataset of resolution $n^3$ across all possible NCP values is $O(n^4)$ [S1, unofficial]. Total encoding time for a multi-resolution framework with $m$ LODs is $O(8^m \cdot n^4)$ [S1, unofficial].
*   **Memory Complexity:** The storage size of a micro-model is determined by the formula $Size(Micro-model) = 1 + ((NCP + degree) \times 3 + NCP^3) \times 4$ bytes [S1, unofficial].
*   **Strengths:** Higher accuracy than trilinear interpolation for off-grid sample locations; approximates C1 continuity without ghost areas; reduces data size overhead [S1, unofficial].
*   **Limitations:** High encoding time for large datasets; query time is a performance bottleneck [S1, unofficial].
*   **When to Use:** When high accuracy and smooth shading are required, and encoding time is not a critical constraint. Suitable for interactive visualization of large-scale datasets if adaptive multi-resolution encoding is used [S1, unofficial].
*   **When Not to Use:** When real-time encoding is required for very large datasets, or when memory bandwidth is severely constrained and the overhead of storing control points is prohibitive.

## Background
Multivariate Functional Approximation was introduced as a method for continuous representation of volume data, providing more accurate evaluation of off-grid sample locations than traditional trilinear interpolation for scientific datasets [S1, unofficial]. It leverages the strong spatial correlation property of general scientific datasets to avoid the need for ghost areas [S1, unofficial]. The method is suitable for modeling data segments considering both data size and modeling accuracy [S1, unofficial].
