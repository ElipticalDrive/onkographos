# B-spline Field Interpolation

Also called: B-spline deformation field, Cubic B-spline field

## Overview
B-spline Field Interpolation is a method for evaluating a continuous scalar or vector field from a discrete grid of control points using cubic B-spline basis functions [S1, unofficial]. It solves the problem of smooth, local interpolation where the value at any query point depends only on a fixed $4 \times 4 \times 4$ neighborhood of control points, ensuring constant-time query complexity relative to the total grid size [S1, unofficial]. It is distinguished from linear or nearest-neighbor voxel sampling by its $C^1$ continuity and from global polynomial interpolation by its local support, making it suitable for deformation fields and density representations in neural rendering [S1, unofficial].

## How it works
**Inputs:**
*   Query point coordinates $\mathbf{p} = (x, y, z)$.
*   Grid origin $\mathbf{p}_0 = (x_0, y_0, z_0)$.
*   Grid spacing $\mathbf{s} = (dx, dy, dz)$.
*   Control point weights $W$, a 3D array of shape $(N_x, N_y, N_z)$, where $N_x, N_y, N_z \ge 4$.

**Outputs:**
*   Interpolated scalar value $u(\mathbf{p})$. For vector fields (e.g., displacement), this is computed independently for each component.

**Data Structures:**
*   The weights $W$ are stored in a dense 3D array. In memory, this is typically row-major or column-major linearized array. The minimum valid grid size is $4 \times 4 \times 4$ [S1, unofficial].
*   For a 3D vector field (e.g., displacement $\mathbf{u} = (u_x, u_y, u_z)$), three separate weight grids are required, totaling 192 degrees of freedom for the minimum grid size [S1, unofficial].

**Algorithm Steps:**

1.  **Calculate Integer Indices:** Determine the base index $(i_x, i_y, i_z)$ of the $4 \times 4 \times 4$ support grid that contains the query point. The indices are calculated using floor operations:
    $$
    i_x = \left\lfloor \frac{x - x_0}{dx} - 1 \right\rfloor, \quad
    i_y = \left\lfloor \frac{y - y_0}{dy} - 1 \right\rfloor, \quad
    i_z = \left\lfloor \frac{z - z_0}{dz} - 1 \right\rfloor
    $$
    [S1, unofficial]

2.  **Calculate Normalized Coordinates:** Compute the local coordinates $(\tilde{x}, \tilde{y}, \tilde{z})$ within the support cell. These coordinates lie in the range $[0, 1]$ and represent the position of $\mathbf{p}$ relative to the grid structure:
    $$
    \tilde{x} = \frac{x - x_0}{dx} - 1 - i_x, \quad
    \tilde{y} = \frac{y - y_0}{dy} - 1 - i_y, \quad
    \tilde{z} = \frac{z - z_0}{dz} - 1 - i_z
    $$
    [S1, unofficial]

3.  **Evaluate Basis Functions:** Compute the cubic B-spline basis weights for each dimension. The basis functions $B_0, B_1, B_2, B_3$ are defined for $\tilde{x} \in [0, 1]$ as:
    $$
    B_0(\tilde{x}) = \frac{(1 - \tilde{x})^3}{6}
    $$
    $$
    B_1(\tilde{x}) = \frac{3\tilde{x}^3 - 6\tilde{x}^2 + 4}{6}
    $$
    $$
    B_2(\tilde{x}) = \frac{-3\tilde{x}^3 + 3\tilde{x}^2 + 3\tilde{x} + 1}{6}
    $$
    $$
    B_3(\tilde{x}) = \frac{\tilde{x}^3}{6}
    $$
    [S1, unofficial]
    *Note: These functions sum to 1 for any $\tilde{x} \in [0, 1]$ [S1, unofficial].*

4.  **Compute Interpolated Value:** Sum the weighted contributions of the 64 control points in the support region:
    $$
    u(\mathbf{p}) = \sum_{l=0}^{3} \sum_{m=0}^{3} \sum_{n=0}^{3} B_l(\tilde{x}) B_m(\tilde{y}) B_n(\tilde{z}) W_{i_x+l, i_y+m, i_z+n}
    $$
    [S1, unofficial]

**Pseudocode:**
```python
def cubic_b_spline_3d(x, y, z, x0, y0, z0, dx, dy, dz, weights):
    """
    Interpolate a value at (x, y, z) using a 3D grid of control points.
    
    Args:
        x, y, z: Query point coordinates.
        x0, y0, z0: Grid origin.
        dx, dy, dz: Grid spacing.
        weights: 3D numpy array or list of lists of lists of shape (Nx, Ny, Nz).
        
    Returns:
        Interpolated scalar value.
    """
    # Step 1: Calculate integer indices
    ix = int((x - x0) / dx - 1)
    iy = int((y - y0) / dy - 1)
    iz = int((z - z0) / dz - 1)
    
    # Step 2: Calculate normalized coordinates
    x_tilde = (x - x0) / dx - 1 - ix
    y_tilde = (y - y0) / dy - 1 - iy
    z_tilde = (z - z0) / dz - 1 - iz
    
    # Step 3: Evaluate basis functions
    def b0(t): return (1 - t)**3 / 6.0
    def b1(t): return (3 * t**3 - 6 * t**2 + 4) / 6.0
    def b2(t): return (-3 * t**3 + 3 * t**2 + 3 * t + 1) / 6.0
    def b3(t): return t**3 / 6.0
    
    bx = [b0(x_tilde), b1(x_tilde), b2(x_tilde), b3(x_tilde)]
    by = [b0(y_tilde), b1(y_tilde), b2(y_tilde), b3(y_tilde)]
    bz = [b0(z_tilde), b1(z_tilde), b2(z_tilde), b3(z_tilde)]
    
    # Step 4: Compute weighted sum
    value = 0.0
    for l in range(4):
        for m in range(4):
            for n in range(4):
                # Access weight W[ix+l, iy+m, iz+n]
                # Note: In a real implementation, bounds checking for ix+l, etc.
                # is required if the query point is near the grid boundary.
                w = weights[ix + l][iy + m][iz + n]
                value += bx[l] * by[m] * bz[n] * w
                
    return value
```

**Edge Cases and Pitfalls:**
*   **Non-Interpolatory Nature:** The value of the field at a control point (where $\tilde{x}=0, \tilde{y}=0, \tilde{z}=0$) is not equal to the weight of that control point. For example, if a single control point has weight 1 and all others 0, the field value at that point is $2/3$ due to the blending of neighboring basis functions [S1, unofficial].
*   **Boundary Conditions:** The algorithm assumes the query point falls within the valid support range. If $i_x, i_y,$ or $i_z$ result in indices outside the allocated weight array bounds, explicit clamping or padding logic is required [G].
*   **Precision:** The basis functions are cubic polynomials. Standard floating-point precision is sufficient, but care should be taken with very large coordinate values relative to grid spacing to avoid loss of significance in the subtraction steps [G].

## Subtopics

### Time-varying B-spline Deformation Field
A variant where the displacement field $\mathbf{u}(\mathbf{x}, t)$ is parametrized by cubic B-splines on a fixed 3D spatial grid, but the control point weights $w(t)$ vary with time [S1, unofficial]. Unlike discrete timestep approaches, this method defines weights implicitly as a function of time $w(t)$, often generated by a Multi-Layer Perceptron (MLP) $\phi(t) \rightarrow w(t)$ [S1, unofficial]. This ensures implicit time continuity and allows queries at arbitrary continuous time and position [S1, unofficial]. The spatial interpolation formula remains identical, but the weights $w_{i_x+l, i_y+m, i_z+n}$ are replaced by $w(t)_{i_x+l, i_y+m, i_z+n}$ [S1, unofficial]. The grid of control points remains fixed in space, while the weights evolve [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query, as it always accesses exactly 64 control points ($4 \times 4 \times 4$) regardless of the total grid size [S1, unofficial].
*   **Memory Complexity:** $O(N_x N_y N_z)$ to store the control point weights. For a 3D vector field, memory usage is triple that of a scalar field [S1, unofficial].
*   **Strengths:** Provides $C^1$ continuous derivatives, which is beneficial for gradient-based optimization in neural rendering and deformation tasks. Local support ensures stability and efficiency [S1, unofficial].
*   **Limitations:** The field is not interpolatory (does not pass through control points), which may require higher grid density to capture sharp features compared to linear interpolation. Boundary handling requires explicit logic [S1, unofficial].
*   **When to Use:** Suitable for representing smooth deformation fields, density fields in neural volume rendering, and scenarios requiring continuous derivatives [S1, unofficial].
*   **When Not to Use:** When exact interpolation of control points is required, or when the field contains sharp discontinuities that would require an impractically fine grid to resolve [S1, unofficial].

## Background
The method is based on cubic B-splines introduced by Rueckert et al. [S1, unofficial]. It was adapted for neural rendering in the context of dynamic tomography, where it is used to represent time-varying deformation fields and density fields as continuous functions rather than discrete voxel grids [S1, unofficial]. The approach was compared against discrete timestep fitting and cumulative weight summation, with the implicit time-varying weight approach yielding the best results for efficiency and continuity [S1, unofficial].
