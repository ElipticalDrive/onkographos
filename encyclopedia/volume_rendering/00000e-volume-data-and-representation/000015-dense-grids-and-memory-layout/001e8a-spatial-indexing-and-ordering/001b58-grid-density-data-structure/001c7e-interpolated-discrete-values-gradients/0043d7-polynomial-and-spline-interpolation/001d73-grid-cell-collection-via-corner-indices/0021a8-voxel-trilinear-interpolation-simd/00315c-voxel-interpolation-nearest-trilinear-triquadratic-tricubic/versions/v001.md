# Voxel Interpolation (Nearest, Trilinear, Triquadratic, Tricubic)
Also called: Nearest Neighbor Sampler, SampleFromVoxels, Tricubic Sampler, Trilinear Sampler, Triquadratic Sampler

## Overview
This method provides a unified interface for sampling values from a dense or sparse voxel grid at arbitrary floating-point coordinates using interpolation orders 0 (nearest), 1 (trilinear), 2 (triquadratic), and 3 (tricubic) [S1, unofficial]. It differs from sibling methods by exposing a templated API that abstracts the underlying tree structure (e.g., OpenVDB/NanoVDB) while supporting multiple precision levels and interpolation kernels, whereas [Voxel Trilinear Interpolation (SIMD)](2564-voxel-trilinear-interpolation-simd.md) is hardcoded to trilinear with AVX optimizations.

## How it works
**Inputs and Outputs:**
- Input: A voxel grid (represented as a tree structure, e.g., `TreeT`) and a sampling coordinate (`Vec3f` or `Vec3d`).
- Output: The interpolated scalar value at the coordinate.

**Data Structures:**
The implementation relies on the underlying tree's node layout (e.g., `cnanovdb_node` structures with child masks, value masks, and offsets) as defined in the parent [Voxel Trilinear Interpolation (SIMD)](2564-voxel-trilinear-interpolation-simd.md) article. The sampler maintains a read accessor (`cnanovdb_readaccessor`) to cache node lookups [S1, unofficial].

**Parameters:**
- `Order`: Integer specifying interpolation degree. 0=Nearest, 1=Trilinear, 2=Triquadratic, 3=Tricubic [S1, unofficial].
- `TreeT`: The specific tree type (e.g., NanoVDB tree) [S1, unofficial].

**Steps:**
1. **Initialization:** Create a sampler instance using the factory function `math::createSampler<Order, TreeT, false>(grid.tree())` [S1, unofficial].
2. **Coordinate Handling:** The sampler accepts integer coordinates (`CoordT ijk`) or floating-point coordinates (`Vec3f xyz` / `Vec3d xyz`) [S1, unofficial].
3. **Lookup:** For floating-point coordinates, the integer base indices are computed. The underlying tree traversal logic (as detailed in the parent article) locates the active leaf or internal node containing the coordinate [S1, unofficial].
4. **Interpolation:**
   - **Order 0 (Nearest):** Returns the value of the voxel at the nearest integer coordinate.
   - **Order 1 (Trilinear):** Computes the weighted average of the 8 surrounding voxels based on the fractional distance in x, y, and z [G].
   - **Order 2 (Triquadratic):** Uses 27 surrounding voxels (3x3x3 grid) to fit a quadratic surface [G].
   - **Order 3 (Tricubic):** Uses 64 surrounding voxels (4x4x4 grid) to fit a cubic surface [G].
   *Note: The specific interpolation weights and formulas are not provided in the source notes; they are assumed to be standard polynomial kernels implemented within the sampler class.*
5. **Return:** The computed value is returned. If the coordinate is outside the valid grid bounds, the behavior is typically to return 0 or handle boundary checks as per the tree's configuration [G].

            # Get 8 neighbors: (i,j,k) to (i+1,j+1,k+1)
            v000 = self.tree.get_value(ijk_base)
            v100 = self.tree.get_value(ijk_base + Vec3i(1,0,0))
            v010 = self.tree.get_value(ijk_base + Vec3i(0,1,0))
            v001 = self.tree.get_value(ijk_base + Vec3i(0,0,1))
            v110 = self.tree.get_value(ijk_base + Vec3i(1,1,0))

            v011 = self.tree.get_value(ijk_base + Vec3i(0,1,1))
            v111 = self.tree.get_value(ijk_base + Vec3i(1,1,1))
            
            # Fractional distances
            fx = xyz.x - ijk_base.x
            fy = xyz.y - ijk_base.y
            fz = xyz.z - ijk_base.z
            
            # Interpolate
            ix00 = lerp(v000, v100, fx)
            ix01 = lerp(v001, v101, fx)
            ix10 = lerp(v010, v110, fx)
            ix11 = lerp(v011, v111, fx)

            iy1 = lerp(ix10, ix11, fz)

        elif self.order == 2:

## Subtopics

### Nearest Neighbor (Order 0)
Fastest, blocky artifacts. Use for low-res or binary masks.

### Trilinear (Order 1)
Standard balance of speed and smoothness. Use for general volume rendering.

### Triquadratic (Order 2)
Higher continuity (C1). Use when smooth gradients are critical.

### Tricubic (Order 3)
Highest continuity (C2). Computationally expensive. Use for high-fidelity scientific visualization.

## Operating characteristics
- **Time Complexity:** O(1) for lookup (assuming tree depth is fixed/small), but interpolation cost grows with order. Nearest is O(1). Trilinear is O(1) with ~8 lookups. Triquadratic requires 27 lookups. Tricubic requires 64 lookups [G].
- **Memory:** Depends on the underlying tree structure (see parent article). The sampler itself has minimal overhead [S1, unofficial].
- **Strengths:** Unified API for multiple interpolation orders; supports both integer and floating-point coordinates [S1, unofficial].
- **Limitations:** Higher orders require more memory bandwidth and computation. Boundary conditions for higher-order interpolations are not specified in the source [G].

## Background
The method is implemented in the `HNanoSolver` project, which provides a C++ templated class for sampling voxel grid values [S1, unofficial]. It is designed to work with NanoVDB/OpenVDB tree structures, leveraging their internal node layout for efficient traversal [S1, unofficial].
