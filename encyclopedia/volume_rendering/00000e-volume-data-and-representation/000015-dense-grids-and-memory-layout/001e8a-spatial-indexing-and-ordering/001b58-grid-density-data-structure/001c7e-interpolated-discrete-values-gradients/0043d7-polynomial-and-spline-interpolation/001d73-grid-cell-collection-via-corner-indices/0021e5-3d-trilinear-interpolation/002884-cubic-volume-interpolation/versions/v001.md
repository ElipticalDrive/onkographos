# Cubic Volume Interpolation
Also called: Cubic Trilinear Interpolation, Trilinear Interpolation with Cubic Weights

## Overview
Cubic Volume Interpolation extends standard trilinear interpolation by using cubic mixture weights for each axis to sample a 3D texture at 8 corners defined by those weights [S1, unofficial]. It provides higher-order continuity and smoother gradients compared to linear methods, at the cost of increased computational complexity and memory bandwidth usage [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D coordinate `texCoord` (float3) within the texture space, and a 3D texture `dataTex` containing the volume data.
- Output: A single interpolated float value representing the density or color at `texCoord`.

**Data Structures:**
- `dataTex`: A 3D texture object. The specific implementation uses CUDA's `tex3D` function for sampling [S1, unofficial].
- `mixX`, `mixY`, `mixZ`: Temporary `float3` variables storing the fractional offsets and weight sums for each axis.

**Steps:**
1. **Calculate Cubic Mixture Weights:** For each axis (X, Y, Z), compute the cubic interpolation weights and fractional offsets using the `cubicInterpMixture` function. This function takes the coordinate component, computes the integer part `i` and fractional part `a`, then derives weights `w0` through `w3` [S1, unofficial].
2. **Sample Texture Corners:** Sample the 3D texture at the 8 corners defined by the mixture weights. The coordinates for these samples are derived from `mixX`, `mixY`, and `mixZ`. Specifically, the texture is sampled at combinations of `mixX.x`/`mixX.y`, `mixY.x`/`mixY.y`, and `mixZ.x`/`mixZ.y` [S1, unofficial].
3. **Interpolate along X Axis:** For each of the two Z-slices (defined by `mixZ.x` and `mixZ.y`), interpolate along the X axis between the corresponding Y-slices.
   - For the first Z-slice (`mixZ.x`):
     - `vY0Z0 = lerp(vX0Y0Z0, vX1Y0Z0, mixX.z)`
     - `vY1Z0 = lerp(vX0Y1Z0, vX1Y1Z0, mixX.z)`
   - For the second Z-slice (`mixZ.y`):
     - `vY0Z1 = lerp(vX0Y0Z1, vX1Y0Z1, mixX.z)`
     - `vY1Z1 = lerp(vX0Y1Z1, vX1Y1Z1, mixX.z)`
4. **Interpolate along Y Axis:** For each Z-slice, interpolate along the Y axis between the results of the X interpolation.
   - `vZ0 = lerp(vY0Z0, vY1Z0, mixY.z)`
   - `vZ1 = lerp(vY0Z1, vY1Z1, mixY.z)`
5. **Interpolate along Z Axis:** Finally, interpolate along the Z axis between `vZ0` and `vZ1` using `mixZ.z` to produce the final value [S1, unofficial].

**Formulas:**
The cubic weights are calculated as follows, where `a` is the fractional part of the coordinate:
$$ a2 = a \times a $$
$$ a3 = a \times a2 $$
$$ w0 = -a3 + (2 \times a2) - a $$
$$ w1 = a3 - (2 \times a2) + 1 $$
$$ w2 = -a3 + a2 + a $$
$$ w3 = a3 - a2 $$

The `cubicInterpMixture` function returns a `float3` containing:
- First component: `i - (w0 / (w0 + w1))` (fractional offset for the first texel)
- Second component: `i + 1 + (w3 / (w2 + w3))` (fractional offset for the second texel)
- Third component: `w2 + w3` (sum of weights for normalization) [S1, unofficial]

**Parameters:**
- `triCubic`: A boolean flag that determines whether to use cubic interpolation (`true`) or trilinear interpolation (`false`) [S1, unofficial].

**Edge Cases and Pitfalls:**
- Boundary conditions: The implementation checks if the texture coordinates are within the valid range `[0, dataDim - 1]`. If out of bounds, it returns a default `outVal` [S1, unofficial].
- Precision: The use of cubic weights involves higher-order polynomial calculations, which may introduce numerical instability if not handled carefully, though the specific implementation does not detail error correction [S1, unofficial].

**Pseudocode:**
```python
def cubic_interpolate(tex_coord, data_tex):
    mix_x = cubic_interp_mixture(tex_coord.x)
    mix_y = cubic_interp_mixture(tex_coord.y)
    mix_z = cubic_interp_mixture(tex_coord.z)

    # Sample the 8 corners
    v_x0_y0_z0 = tex3d(data_tex, mix_x.x, mix_y.x, mix_z.x)
    v_x0_y1_z0 = tex3d(data_tex, mix_x.x, mix_y.y, mix_z.x)
    v_x0_y0_z1 = tex3d(data_tex, mix_x.x, mix_y.x, mix_z.y)
    v_x0_y1_z1 = tex3d(data_tex, mix_x.x, mix_y.y, mix_z.y)
    v_x1_y0_z0 = tex3d(data_tex, mix_x.y, mix_y.x, mix_z.x)
    v_x1_y1_z0 = tex3d(data_tex, mix_x.y, mix_y.y, mix_z.x)
    v_x1_y0_z1 = tex3d(data_tex, mix_x.y, mix_y.x, mix_z.y)
    v_x1_y1_z1 = tex3d(data_tex, mix_x.y, mix_y.y, mix_z.y)

    # Interpolate along X
    v_y0_z0 = lerp(v_x0_y0_z0, v_x1_y0_z0, mix_x.z)
    v_y1_z0 = lerp(v_x0_y1_z0, v_x1_y1_z0, mix_x.z)
    v_y0_z1 = lerp(v_x0_y0_z1, v_x1_y0_z1, mix_x.z)
    v_y1_z1 = lerp(v_x0_y1_z1, v_x1_y1_z1, mix_x.z)

    # Interpolate along Y
    v_z0 = lerp(v_y0_z0, v_y1_z0, mix_y.z)
    v_z1 = lerp(v_y0_z1, v_y1_z1, mix_y.z)

    # Interpolate along Z
    return lerp(v_z0, v_z1, mix_z.z)

def cubic_interp_mixture(coord):
    i = floor(coord)
    a = coord - i
    a2 = a * a
    a3 = a * a2
    w0 = -a3 + (2 * a2) - a
    w1 = a3 - (2 * a2) + 1
    w2 = -a3 + a2 + a
    w3 = a3 - a2
    offset1 = i - (w0 / (w0 + w1))
    offset2 = i + 1 + (w3 / (w2 + w3))
    weight_sum = w2 + w3
    return (offset1, offset2, weight_sum)
```

## Subtopics

### Cubic Interpolation Weights
Computes cubic interpolation weights and fractional offsets for a 1D coordinate, used for higher-order volume interpolation [S1, unofficial]. It calculates the integer part `i` and fractional part `a` of the coordinate, then derives weights `w0` through `w3` using cubic polynomials. The function returns a `float3` containing the fractional offsets for the two texels involved in the interpolation and the sum of weights for normalization [S1, unofficial]. This is a helper function for the main cubic interpolation method [S1, unofficial].

## Operating characteristics
- **Time Complexity:** O(1) per sample, but with a higher constant factor than trilinear interpolation due to the additional polynomial calculations and 8 texture samples [S1, unofficial].
- **Memory Complexity:** O(1) auxiliary space, but requires 8 texture samples per interpolated value [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Performance scales linearly with the number of samples, but the increased computational load per sample may reduce throughput compared to linear methods [S1, unofficial].
- **Strengths:** Smoother gradients and higher-order continuity compared to trilinear interpolation [S1, unofficial].
- **Limitations:** Higher computational cost and memory bandwidth usage [S1, unofficial].
- **When to use:** When smooth gradients are critical and computational resources are sufficient [S1, unofficial].
- **When not to use:** When performance is a primary concern or when lower-order continuity is acceptable [S1, unofficial].

## Background
Originating from a CUDA volume rendering implementation, this method extends standard trilinear interpolation to provide smoother results in 3D texture sampling [S1, unofficial]. It is used in contexts where visual quality is prioritized over raw performance, such as high-fidelity volume rendering [S1, unofficial].
