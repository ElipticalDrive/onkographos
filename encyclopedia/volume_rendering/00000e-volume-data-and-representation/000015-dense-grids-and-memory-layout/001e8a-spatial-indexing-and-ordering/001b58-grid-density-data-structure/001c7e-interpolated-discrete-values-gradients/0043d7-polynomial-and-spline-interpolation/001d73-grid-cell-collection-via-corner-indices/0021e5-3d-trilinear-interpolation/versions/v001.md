# 3D Trilinear Interpolation

Also called: Trilinear Interpolation (Standard), Trilinear Voxel Interpolation, Voxel Trilinear Interpolation

## Overview
3D Trilinear Interpolation retrieves the value of a scalar or vector field at arbitrary floating-point coordinates $(x, y, z)$ by interpolating the values at the 8 integer corners of the enclosing voxel grid cell [S1, unofficial]. It is used in volume rendering and raycasting to achieve higher sampling resolution than nearest-neighbor sampling, providing smooth transitions between discrete voxel values [S1, unofficial]. It differs from its sibling [Voxel Trilinear Interpolation (SIMD)](2564-voxel-trilinear-interpolation-simd.md) by focusing on the standard algorithmic definition rather than vectorized hardware optimizations, and from [Trilinear Interpolation (Compressed/Linked)](2629-trilinear-interpolation-compressed-linked.md) by operating on dense, contiguous memory layouts without link indirection [S2, unofficial].

## How it works
**Inputs:**
- A dense 3D grid of values $V$ with dimensions $D_x \times D_y \times D_z$ [S1, S2, unofficial].
- A query point $P = (x, y, z)$ in the same coordinate system as the grid [S1, S2, unofficial].
- Optional: Grid origin $O = (o_x, o_y, o_z)$ and voxel spacings $S = (dx, dy, dz)$ if the query coordinates are in world space [S2, unofficial].

**Outputs:**
- The interpolated value $val$ at $P$ [S1, unofficial].
- If batched, an array of values corresponding to a list of query points [S2, unofficial].

**Data Structures:**
- The grid $V$ is typically stored as a 3D array (e.g., NumPy or JAX array) with shape $(D_x, D_y, D_z)$ [S1, S2, unofficial].
- Corner values are retrieved as scalars or vectors depending on the data type (e.g., density, color, SH coefficients) [S2, unofficial].

**Steps:**

1. **Coordinate Normalization (if applicable):**
   If the input coordinates are in world space, normalize them to voxel space:
   $$
   xyz = \frac{P - O}{S}
   $$
   where $xyz = (x', y', z')$ [S2, unofficial].

2. **Boundary Check:**
   If $x' < 0$ or $y' < 0$ or $z' < 0$ or $x' \ge D_x$ or $y' \ge D_y$ or $z' \ge D_z$, return 0 (or a designated out-of-bounds value) [S1, unofficial].

3. **Floor and Ceiling Coordinates:**
   Compute the integer floor coordinates:
   $$
   x_0 = \lfloor x' \rfloor, \quad y_0 = \lfloor y' \rfloor, \quad z_0 = \lfloor z' \rfloor
   $$
   Compute the integer ceiling coordinates:
   $$
   x_1 = x_0 + 1, \quad y_1 = y_0 + 1, \quad z_1 = z_0 + 1
   $$
   [S1, S2, unofficial].

4. **Fractional Differences:**
   Compute the fractional parts (weights) for each axis:
   $$
   \alpha = x' - x_0, \quad \beta = y' - y_0, \quad \gamma = z' - z_0
   $$
   Alternatively, using $1-\alpha$ notation:
   $$
   tmpX = 1 - \alpha, \quad tmpY = 1 - \beta, \quad tmpZ = 1 - \gamma
   $$
   [S1, S2, unofficial].

5. **Corner Value Retrieval:**
   Retrieve the 8 corner values from the grid $V$:
   $$
   \begin{aligned}
   v_{000} &= V(x_0, y_0, z_0) \\
   v_{100} &= V(x_1, y_0, z_0) \\
   v_{010} &= V(x_0, y_1, z_0) \\
   v_{110} &= V(x_1, y_1, z_0) \\
   v_{001} &= V(x_0, y_0, z_1) \\
   v_{101} &= V(x_1, y_0, z_1) \\
   v_{011} &= V(x_0, y_1, z_1) \\
   v_{111} &= V(x_1, y_1, z_1)
   \end{aligned}
   $$
   [S1, S2, unofficial].

6. **Weight Calculation:**
   Compute the 8 trilinear weights. The weight for corner $(i, j, k)$ where $i,j,k \in \{0,1\}$ is:
   $$
   w_{ijk} = (i \cdot \alpha + (1-i) \cdot tmpX) \cdot (j \cdot \beta + (1-j) \cdot tmpY) \cdot (k \cdot \gamma + (1-k) \cdot tmpZ)
   $$
   Explicitly:
   $$
   \begin{aligned}
   w_{000} &= tmpX \cdot tmpY \cdot tmpZ \\
   w_{100} &= \alpha \cdot tmpY \cdot tmpZ \\
   w_{010} &= tmpX \cdot \beta \cdot tmpZ \\
   w_{110} &= \alpha \cdot \beta \cdot tmpZ \\
   w_{001} &= tmpX \cdot tmpY \cdot \gamma \\
   w_{101} &= \alpha \cdot tmpY \cdot \gamma \\
   w_{011} &= tmpX \cdot \beta \cdot \gamma \\
   w_{111} &= \alpha \cdot \beta \cdot \gamma
   \end{aligned}
   $$
   [S1, S2, unofficial].

7. **Final Interpolation:**
   Sum the products of weights and corner values:
   $$
   val = \sum_{i,j,k \in \{0,1\}} w_{ijk} \cdot v_{ijk}
   $$
   [S1, S2, unofficial].

**Pseudocode:**

```python
import numpy as np

def trilinear_interpolation(volume, x, y, z):
    """
    Perform 3D trilinear interpolation on a dense volume.
    
    Args:
        volume: 3D numpy array of shape (Dx, Dy, Dz)
        x, y, z: float coordinates in voxel space
        
    Returns:
        Interpolated value at (x, y, z)
    """
    # 1. Boundary Check
    if x < 0 or y < 0 or z < 0 or x >= volume.shape[0] or y >= volume.shape[1] or z >= volume.shape[2]:
        return 0.0

    # 2. Floor and Ceiling Coordinates
    x0 = int(np.floor(x))
    y0 = int(np.floor(y))
    z0 = int(np.floor(z))
    
    x1 = x0 + 1
    y1 = y0 + 1
    z1 = z0 + 1

    # 3. Fractional Differences
    # Note: Source [S1, unofficial] has a precedence bug in alpha = x - x0 / (x1 - x0).
    # Since x1 - x0 is always 1, this simplifies to x - x0.
    # Standard trilinear uses the fractional part directly.
    alpha = x - x0
    beta = y - y0
    gamma = z - z0
    
    tmpX = 1.0 - alpha
    tmpY = 1.0 - beta
    tmpZ = 1.0 - gamma

    # 4. Retrieve Corner Values
    # Using clamping for safety if indices might be out of bounds due to float precision,
    # though boundary check above should handle strict bounds.
    # Accessing directly as per source [S1, S2, unofficial]
    v000 = volume[x0, y0, z0]
    v100 = volume[x1, y0, z0]
    v010 = volume[x0, y1, z0]
    v110 = volume[x1, y1, z0]
    v001 = volume[x0, y0, z1]
    v101 = volume[x1, y0, z1]
    v011 = volume[x0, y1, z1]
    v111 = volume[x1, y1, z1]

    # 5. Final Interpolation
    val = (tmpX * tmpY * tmpZ * v000 +
           alpha * tmpY * tmpZ * v100 +
           tmpX * beta * tmpZ * v010 +
           alpha * beta * tmpZ * v110 +
           tmpX * tmpY * gamma * v001 +
           alpha * tmpY * gamma * v101 +
           tmpX * beta * gamma * v011 +
           alpha * beta * gamma * v111)

    return val

def trilinear_interpolation_batch(vecs, volume):
    """
    Batched trilinear interpolation.
    
    Args:
        vecs: numpy array of shape (N, 3) containing (x, y, z) coordinates
        volume: 3D numpy array of shape (Dx, Dy, Dz)
        
    Returns:
        numpy array of shape (N,) with interpolated values
    """
    results = np.zeros(vecs.shape[0])
    for i in range(vecs.shape[0]):
        results[i] = trilinear_interpolation(volume, vecs[i, 0], vecs[i, 1], vecs[i, 2])
    return results
```

**Parameters:**
- `volume`: The 3D grid data [S1, S2, unofficial].
- `x, y, z`: Query coordinates [S1, unofficial].
- `origin`: Grid origin in world space, default $(0,0,0)$ [S2, unofficial].
- `dx, dy, dz`: Voxel spacings, default $1.0$ [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** If the query point lies outside the grid bounds, the value is typically clamped to 0 or the nearest edge value. Source [S1, unofficial] returns 0 [S1, unofficial].
- **Precision:** Floating-point errors near integer boundaries can cause $x_0$ and $x_1$ to be incorrect if not handled carefully. Using `np.floor` is standard [S1, S2, unofficial].
- **Operator Precedence:** Source [S1, unofficial] contains a bug in the weight calculation: `alpha = x - x0 / (x1 - x0)`. Due to operator precedence, this evaluates to `x - (x0 / 1)`, which is correct only if `x1 - x0 == 1`. However, the intent is clearly the fractional part. The pseudocode above corrects this to `alpha = x - x0` [S1, unofficial].
- **Vector Data:** If the grid stores vectors (e.g., RGB, SH coefficients), the interpolation is performed component-wise [S2, unofficial].

## Subtopics

### [Trilinear Interpolation (Compressed/Linked)](2629-trilinear-interpolation-compressed-linked.md)
This method performs trilinear interpolation on a sparse, compressed voxel grid by mapping logical voxel coordinates to a dense array of compressed values via a link array. It solves the problem of efficiently accessing non-contiguous data in sparse volume representations while maintaining the continuity of trilinear sampling. It differs from standard dense trilinear interpolation by introducing a lookup step that translates grid indices to compressed indices, and it differs from unstructured sparse interpolation by retaining the regular 8-corner neighborhood structure of the grid. It builds on [3D Trilinear Interpolation](2613-3d-trilinear-interpolation.md).

## Operating characteristics
- **Time Complexity:** $O(1)$ per query point, as it involves a fixed number of arithmetic operations and memory accesses (8 reads) [S1, S2, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space per query, assuming the grid is already in memory [S1, S2, unofficial].
- **Measured Performance:** In JAX-accelerated implementations, batched trilinear interpolation can be highly efficient using `vmap` and `jit`, allowing for parallel processing of many sample points along rays [S2, unofficial].
- **Strengths:** Smooth interpolation, simple implementation, low computational cost per sample [S1, unofficial].
- **Limitations:** Requires dense memory layout, which can be inefficient for sparse volumes [S2, unofficial]. Aliasing artifacts may occur if sampling rate is too low [S1, unofficial].
- **When to Use:** When smooth interpolation is required and the volume is dense or can be efficiently accessed [S1, unofficial].
- **When Not to Use:** For very sparse volumes where compressed representations are more memory-efficient [S2, unofficial].

## Background
3D Trilinear Interpolation is a standard technique in computer graphics and scientific visualization for sampling dense grid data. It is widely used in volume rendering, particularly in raycasting, to sample voxel values at sub-voxel precision [S1, unofficial]. The method is fundamental to many volume rendering pipelines, including those using spherical harmonics for view-dependent effects [S2, unofficial].
