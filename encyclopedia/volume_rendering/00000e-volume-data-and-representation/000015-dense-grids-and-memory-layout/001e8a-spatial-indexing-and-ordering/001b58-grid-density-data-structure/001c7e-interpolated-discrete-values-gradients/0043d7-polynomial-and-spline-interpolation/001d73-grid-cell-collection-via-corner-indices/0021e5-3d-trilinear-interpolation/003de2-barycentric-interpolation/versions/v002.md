# Barycentric Interpolation

Also called: Barycentric weight calculation, Simplex interpolation

## Overview
Barycentric interpolation is a method for interpolating learnable feature vectors at the $n+1$ vertices of a simplex cell using barycentric coordinates derived from sorted, skewed coordinates [S1, unofficial]. It serves as an efficient alternative to computationally expensive $n$-linear interpolation by maintaining similarity to standard interpolation schemes while avoiding the kernel summation overhead found in simplex noise algorithms [S1, unofficial]. It is specifically designed for simplex-based structures where points are mapped to vertices via coordinate skewing and simplicial subdivision [S1, unofficial].

## How it works
**Inputs:**
- A query point $x \in \mathbb{R}^n$ representing the skewed coordinates [S1, unofficial].
- A set of $n+1$ learnable feature vectors $g_1, g_2, \dots, g_{n+1}$, one for each vertex of the simplex [S1, unofficial].
- Dimension parameter $n$ [S1, unofficial].

**Outputs:**
- A single interpolated feature vector for point $x$ [S1, unofficial].

**Data Structures:**
- Weights $w$ are stored as an array of size $n+1$ [S1, unofficial].
- Features $f$ are stored as an array of size $n+1$ and sorted to align with the sorted coordinate indices [S1, unofficial].
- Bit packing details are not given in the sources.

**Steps:**
1. **Coordinate Skewing:** Transform the input point $x$ into skewed coordinates using an affine transformation [S1, unofficial]. The exact algebraic coefficient for the skewing transformation is garbled in the source text and not fully recoverable [S1, unofficial]. The transformation preserves barycentric coordinates [S1, unofficial].
2. **Sort Coordinates:** Sort the skewed coordinates of $x$ in descending order to obtain $x_1 \ge x_2 \ge \dots \ge x_n$ [S1, unofficial].
3. **Sort Features:** Sort the feature vectors $f$ using bubble sort to align with the sorted coordinate indices [S1, unofficial].
4. **Compute Weights:** Calculate the barycentric weights using the closed-form formula derived from simplicial subdivision [S1, unofficial]:
   $$w_1 = 1 - x_1$$
   $$w_i = x_{i-1} - x_i \quad \text{for } i = 2, \dots, n$$
   $$w_{n+1} = x_n$$
   where $x_1, \dots, x_n$ are the sorted entries of the skewed point $x$ in descending order [S1, unofficial].
5. **Interpolate:** Compute the dot product of the weights and the sorted features to obtain the final feature vector [S1, unofficial].

**Pseudocode:**
```python
def barycentric_interpolation(x, features):
    """
    Interpolate features using barycentric coordinates on a simplex.
    
    Args:
        x: List of n floats, the skewed coordinates of the query point.
        features: List of n+1 feature vectors (or scalars), one for each vertex.
        
    Returns:
        The interpolated feature vector (or scalar).
    """
    n = len(x)
    
    # Step 1: Coordinate Skewing
    # The exact skewing formula is garbled in the source [S1, unofficial].
    # We assume x is already skewed as per the paper's definition.
    skewed_x = x
    
    # Step 2: Sort coordinates in descending order
    coords_with_idx = [(skewed_x[i], i) for i in range(n)]
    coords_with_idx.sort(key=lambda p: p[0], reverse=True)
    sorted_coords = [p[0] for p in coords_with_idx]
    sorted_indices = [p[1] for p in coords_with_idx]
    
    # Step 3: Sort features to align with sorted coordinates
    # The source specifies sorting features to match the sorted coordinate order [S1, unofficial].
    sorted_features = [features[sorted_indices[i]] for i in range(n)]
    # The source lists n features in the algorithm but n+1 weights in the formula.
    # We append the remaining feature to match the n+1 weights.
    if len(features) > n:
        sorted_features.append(features[n])
        
    # Step 4: Compute weights using the closed-form formula [S1, unofficial]
    w = [1.0 - sorted_coords[0]]
    for i in range(1, n):
        w.append(sorted_coords[i-1] - sorted_coords[i])
    w.append(sorted_coords[n-1])
    
    # Step 5: Interpolate
    result = 0.0
    for i in range(n + 1):
        result += w[i] * sorted_features[i]
        
    return result
```

**Parameters:**
- $n$: The dimension parameter, where the algorithm operates in $n+1$ dimensions (i.e., $n$-dimensional space, simplex with $n+1$ vertices) [S1, unofficial].
- Typical values are not given in the sources.

**Edge Cases and Pitfalls:**
- The barycentric coordinates are preserved under the affine skewing transformation [S1, unofficial].
- The source text for the coordinate skewing formula is garbled, making exact implementation of the skewing step difficult without external knowledge or the full paper [S1, unofficial].
- The source mentions "Sort features f using bubble sort" but does not specify the sorting key or how features map to vertices in a grid structure [S1, unofficial].
- The source lists $n$ features in the algorithm description but $n+1$ weights in the formula, which is a discrepancy [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The dominant operations are sorting the coordinates and features, which is $O(n \log n)$ or $O(n^2)$ with bubble sort as mentioned in the source [S1, unofficial]. The weight calculation and dot product are $O(n)$ [S1, unofficial].
- **Memory Complexity:** $O(n)$ for storing coordinates and weights [S1, unofficial].
- **Performance:** Compared to $n$-linear interpolation, this method is more efficient due to the simpler formula for weights [S1, unofficial].
- **Strengths:** Efficient, maintains similarity to trilinear interpolation, avoids kernel summation overhead of simplex noise [S1, unofficial].
- **Limitations:** Garbled source text for skewing formula, ambiguity in feature sorting and mapping [S1, unofficial].
- **When to use it:** Use when interpolating learnable feature vectors on simplex-based structures for graphics primitives encoding [S1, unofficial].
- **When not to use it:** Avoid when exact skewing coefficients are required or when standard grid-aligned interpolation suffices [S1, unofficial].

## Background
- **Origin:** The method is described in "Efficient Encoding of Graphics Primitives with Simplex-based Structures" [S1, unofficial].
- **History:** It is proposed as an efficient alternative to trilinear interpolation for learning mappings for graphics primitives using simplex-based structures [S1, unofficial].
- **Usage:** Used in graphics primitives encoding, specifically for interpolating learnable feature vectors at simplex vertices [S1, unofficial].
