# 3D Trilinear Interpolation

Also called: 3D Linear Interpolation, Trilinear Interpolant, Trilinear Sampling, Trilinear Voxel Interpolation, Voxel Trilinear Interpolation

## Overview
3D Trilinear Interpolation reconstructs the value of a scalar or vector field at an arbitrary point $P=(x,y,z)$ within a regular grid by computing a weighted sum of the values at the eight corners of the enclosing voxel [S1, S2][S13, unofficial]. It assumes the underlying function varies linearly along axes parallel to the grid, providing $C^0$ continuity for properly-oriented rectangular grids [S2][S20, unofficial]. It is the standard reconstruction filter for ray casting in direct volume rendering, offering a balance between the smoothness of higher-order methods and the computational efficiency of nearest-neighbor sampling [S3, S10, unofficial].

## How it works
**Inputs:**
- Query point $P = (x, y, z)$ in world or grid coordinates.
- Volume grid data $V$ with dimensions $D_x \times D_y \times D_z$.
- Grid origin $O = (x_{min}, y_{min}, z_{min})$ and voxel spacing (step size) $S = (s_x, s_y, s_z)$. If the grid is unit-spaced and aligned at the origin, $O=(0,0,0)$ and $S=(1,1,1)$.

**Outputs:**
- Interpolated value $V(P)$ (scalar) or $\vec{G}(P)$ (vector/gradient).

**Data Structures:**
- The grid is typically stored as a 1D array or 3D array with row-major or column-major layout. For a 3D array `grid[z][y][x]`, the memory offset for corner $(x_i, y_j, z_k)$ is $k \cdot (D_x D_y) + j \cdot D_x + i$ [S7, S18, unofficial].
- Corner values are accessed using integer indices derived from the floor of the normalized coordinates.

**Steps:**

1. **Coordinate Normalization and Indexing:**
   Determine the integer indices of the minimum corner of the enclosing voxel. For unit-spaced grids aligned at 0:
   $$
   x_0 = \lfloor x \rfloor, \quad y_0 = \lfloor y \rfloor, \quad z_0 = \lfloor z \rfloor
   $$
   The maximum corner indices are:
   $$
   x_1 = x_0 + 1, \quad y_1 = y_0 + 1, \quad z_1 = z_0 + 1
   $$
   For non-unit spacing or arbitrary origin, normalize first:
   $$
   x_{norm} = \frac{x - x_{min}}{s_x}, \quad y_{norm} = \frac{y - y_{min}}{s_y}, \quad z_{norm} = \frac{z - z_{min}}{s_z}
   $$
   Then apply floor to the normalized coordinates [S13, S16, S21, unofficial].

2. **Fractional Offset Calculation:**
   Compute the fractional distances (weights) within the voxel for each axis. These values lie in $[0, 1)$:
   $$
   u = x_{norm} - x_0, \quad v = y_{norm} - y_0, \quad w = z_{norm} - z_0
   $$
   Alternatively denoted as $t_x, t_y, t_z$ or $xd, yd, zd$ [S8, S13, S21, unofficial].

3. **Boundary Handling:**
   If the query point lies outside the grid bounds ($x < 0$ or $x \ge D_x$, etc.), the method typically returns a default value (often 0) or clamps the indices to the nearest valid corner [S11, S18, unofficial]. Note: Clamping indices changes the interpolation behavior at boundaries compared to returning a default.

4. **Corner Value Retrieval:**
   Fetch the values from the 8 corners of the voxel defined by $(x_0, y_0, z_0)$ and $(x_1, y_1, z_1)$. Let $V_{ijk}$ denote the value at corner $(x_i, y_j, z_k)$ where $i,j,k \in \{0,1\}$:
   - $V_{000}$ at $(x_0, y_0, z_0)$
   - $V_{100}$ at $(x_1, y_0, z_0)$
   - $V_{010}$ at $(x_0, y_1, z_0)$
   - $V_{110}$ at $(x_1, y_1, z_0)$
   - $V_{001}$ at $(x_0, y_0, z_1)$
   - $V_{101}$ at $(x_1, y_0, z_1)$
   - $V_{011}$ at $(x_0, y_1, z_1)$
   - $V_{111}$ at $(x_1, y_1, z_1)$

5. **Interpolation:**
   Perform linear interpolation along the x-axis, then y-axis, then z-axis (separable interpolation). This requires 7 additions and 7 multiplications [S6, S19, unofficial].

   **X-interpolation (4 steps):**
   $$
   \begin{aligned}
   C_{00} &= V_{000}(1 - u) + V_{100}u \\
   C_{10} &= V_{010}(1 - u) + V_{110}u \\
   C_{01} &= V_{001}(1 - u) + V_{101}u \\
   C_{11} &= V_{011}(1 - u) + V_{111}u
   \end{aligned}
   $$
   *(Note: Notation $C_{ab}$ here represents the result of x-interpolation for the face at y-level $a$ and z-level $b$. Some sources use different indexing, e.g., $c01$ for $y=0, z=1$ face. The logic is consistent: interpolate pairs along X.)*

   **Y-interpolation (2 steps):**
   $$
   \begin{aligned}
   C_0 &= C_{00}(1 - v) + C_{10}v \\
   C_1 &= C_{01}(1 - v) + C_{11}v
   \end{aligned}
   $$

   **Z-interpolation (1 step):**
   $$
   V(P) = C_0(1 - w) + C_1 w
   $$

   **Expanded Formula:**
   The result can also be written as a single weighted sum of the 8 corners:
   $$
   \begin{aligned}
   V(P) = & \ V_{000}(1-u)(1-v)(1-w) + V_{100}u(1-v)(1-w) \\
   & + V_{010}(1-u)v(1-w) + V_{110}uv(1-w) \\
   & + V_{001}(1-u)(1-v)w + V_{101}u(1-v)w \\
   & + V_{011}(1-u)vw + V_{111}uvw
   \end{aligned}
   $$
   [S8, S13, S20, unofficial][S25]

**Pseudocode:**

```python
def trilinear_interpolate(grid, x, y, z, dims, origin=(0,0,0), spacing=(1,1,1)):
    """
    grid: 3D array or flattened array with shape (Dz, Dy, Dx) or (Dx, Dy, Dz) depending on layout.
          Assuming standard numpy-like indexing grid[z, y, x] for clarity, 
          but memory layout must be respected in implementation.
    dims: tuple (Dx, Dy, Dz)
    origin: tuple (x_min, y_min, z_min)
    spacing: tuple (sx, sy, sz)
    """
    # 1. Normalize coordinates
    nx = (x - origin[0]) / spacing[0]
    ny = (y - origin[1]) / spacing[1]
    nz = (z - origin[2]) / spacing[2]
    
    # 2. Boundary check and clamping (or return 0)
    # Here we clamp to valid range [0, dims-1] for indices
    x0 = int(np.floor(nx))
    y0 = int(np.floor(ny))
    z0 = int(np.floor(nz))
    
    x1 = min(x0 + 1, dims[0] - 1)
    y1 = min(y0 + 1, dims[1] - 1)
    z1 = min(z0 + 1, dims[2] - 1)
    
    # If point is strictly outside, handle appropriately (e.g., return 0 or clamp)
    if x < origin[0] or x >= origin[0] + dims[0]*spacing[0] or \
       y < origin[1] or y >= origin[1] + dims[1]*spacing[1] or \
       z < origin[2] or z >= origin[2] + dims[2]*spacing[2]:
        return 0.0 # [G] Default boundary behavior

    # 3. Fractional offsets
    u = nx - x0
    v = ny - y0
    w = nz - z0
    
    # 4. Fetch corner values
    # Note: Accessing grid[z, y, x]
    v000 = grid[z0, y0, x0]
    v100 = grid[z0, y0, x1]
    v010 = grid[z0, y1, x0]
    v110 = grid[z0, y1, x1]
    v001 = grid[z1, y0, x0]
    v101 = grid[z1, y0, x1]
    v011 = grid[z1, y1, x0]
    v111 = grid[z1, y1, x1]
    
    # 5. Interpolate
    # X-axis
    c00 = v000 * (1 - u) + v100 * u
    c10 = v010 * (1 - u) + v110 * u
    c01 = v001 * (1 - u) + v101 * u
    c11 = v011 * (1 - u) + v111 * u
    
    # Y-axis
    c0 = c00 * (1 - v) + c10 * v
    c1 = c01 * (1 - v) + c11 * v
    
    # Z-axis
    result = c0 * (1 - w) + c1 * w
    
    return result
```

**Gradient Interpolation:**
If the grid stores gradients (vectors) at each corner, the same weights $(u,v,w)$ are applied to the gradient vectors independently to obtain the interpolated gradient $\vec{G}(P)$ [S21, unofficial].

## Subtopics

### [Trilinear Interpolation (Compressed/Linked)](2629-trilinear-interpolation-compressed-linked.md)
Performs trilinear interpolation on a compressed sparse grid using a links array to map voxel indices to compressed value indices, handling boundary checks via masking or a zero-value hack. It builds on 3D Trilinear Interpolation by adding a link lookup step that translates grid coordinates to compressed indices while retaining the regular 8-corner neighborhood structure.

### [Trilinear Gradient Interpolation](3470-trilinear-gradient-interpolation.md)
Computes the gradient or surface normal at an arbitrary point by interpolating pre-computed vector values stored at the eight corners. It differs from standard 3D Trilinear Interpolation by operating on vector fields rather than scalar values.

### [Cubic Volume Interpolation](4278-cubic-volume-interpolation.md)
Extends standard 3D trilinear interpolation by replacing linear mixture weights with cubic polynomial weights for each spatial axis.

### [Quantile Interpolation for Uncertain Data](5008-quantile-interpolation-for-uncertain-data.md)
Interpolates nonparametric probability distributions (PDFs) represented as histograms or KDEs by breaking them into quantiles and interpolating the quantile widths linearly. It builds on 3D Trilinear Interpolation by applying the trilinear logic to the widths of quantile intervals.

### [Analytic Derivative of Tri-linear Interpolation](6919-analytic-derivative-of-tri-linear-interpolation.md)
Computes the exact partial derivatives of a tri-linearly interpolated grid function with respect to the sample location. It is used for gradient-based optimization in neural implicit representations.

### [Ghost Cell Stitching for Node-Centered AMR](8949-ghost-cell-stitching-for-node-centered-amr.md)
Handles data continuity between different Adaptive Mesh Refinement (AMR) levels by introducing ghost cells at level boundaries, ensuring consistent trilinear interpolation across coarse-fine interfaces.

### [Smoothstep Trilinear Interpolation](9344-smoothstep-trilinear-interpolation.md)
Achieves $C^1$-smooth interpolation in multiresolution hash encodings by modifying the interpolation weights (using smoothstep functions) rather than the data structure, avoiding derivative discontinuities at grid boundaries.

### [Barycentric Interpolation](9603-barycentric-interpolation.md)
Interpolates learnable feature vectors at the vertices of a simplex cell using barycentric coordinates derived from sorted, skewed coordinates. It serves as an efficient alternative to n-linear interpolation for simplex-based structures.

### [Semi-Lagrangian Fluid Advection](12285-semi-lagrangian-fluid-advection.md)
Advection of scalar fluid properties using a semi-Lagrangian scheme that traces back from the current cell center along the velocity field and samples the scalar value using trilinear interpolation.

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample point. It involves a fixed number of arithmetic operations (7 multiplications and 7 additions for the efficient separable form) regardless of grid size [S19, S20, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary memory per sample, plus the storage for the grid itself.
- **Performance:** It is significantly faster than cubic interpolation (which uses 64 points) but slower than nearest-neighbor [S5, S10, unofficial]. On modern hardware, it is often memory-bandwidth bound rather than compute-bound due to the random access pattern of fetching 8 corners [S14, unofficial].
- **Strengths:** Provides smooth, continuous variation between sample points, avoiding the blocky artifacts of nearest-neighbor interpolation [S20, unofficial]. It is the standard filter for ray casting in direct volume rendering [S3, unofficial].
- **Limitations:** It is only $C^0$ continuous; derivatives are discontinuous at voxel boundaries, which can cause shading artifacts [S2][S20, unofficial]. It suffers from "diamond" or cross-shaped artifacts at large magnification factors [S10, unofficial]. Continuity cannot be assumed for irregular, rotated, or curvilinear grids [S2].
- **When to use:** Standard volume rendering, texture sampling, and fluid simulation where moderate smoothness is required and performance is critical.
- **When not to use:** When high-order continuity ($C^1$ or higher) is required for shading (use Cubic or Smoothstep variants), or when the grid is highly irregular/curvilinear without precomputed coefficients [S2].

## Background
Trilinear interpolation was introduced as a standard method for reconstructing values in regular, rectilinear, and curvilinear data sets for volume rendering [S1]. It is widely used in direct volume rendering (DVR) ray casting pipelines, where it serves as the primary reconstruction filter [S3, S13, unofficial]. The method assumes the underlying function varies linearly along axes parallel to the grid, which corresponds to a piecewise trilinear polynomial form [S2]. It is often compared with nearest-neighbor (box) and cubic spline filters, with trilinear being the most common choice for its balance of quality and speed [S3, S10, unofficial].
