# Bilinear Sampler


## Overview
The Bilinear Sampler is a differentiable operation that samples values from a spatial tensor (2D or 3D) at arbitrary floating-point coordinates using bilinear interpolation. It solves the problem of extracting feature maps or voxel data at non-integer locations, which is essential for spatial transformer networks and 3D reconstruction pipelines. It differs from its parent [Voxel Interpolation](6486-voxel-interpolation-nearest-trilinear-triquadratic-tricubic.md) by specifically implementing the 2D/3D bilinear case with a coordinate transformation pipeline (scaling and shifting) defined by the `align_corners` convention, rather than a generic templated interpolation order.

## How it works
**Inputs and Outputs:**
- **Input:** A tensor $I$ of shape $(B, C, H, W)$ for 2D or $(B, C, T, H, W)$ for 3D, where $B$ is batch size, $C$ is channels, and $H, W, T$ are spatial dimensions.
- **Coordinates:** A tensor $C_{grid}$ of shape $(B, H_o, W_o, 2)$ for 2D or $(B, T_o, H_o, W_o, 3)$ for 3D, containing normalized coordinates in the range $[-1, 1]$.
- **Output:** A tensor $O$ of shape $(B, C, H_o, W_o)$ for 2D or $(B, C, T_o, H_o, W_o)$ for 3D.

**Parameters:**
- **align_corners:** Boolean. If `True`, the coordinate range $[-1, 1]$ maps to the centers of the edge pixels (range $[0, \text{size}-1]$). If `False`, it maps to the edges (range $[0, \text{size}]$).
- **padding_mode:** String. Determines behavior for coordinates outside $[-1, 1]$. Defaults to `'border'` [S1, unofficial].

**Data Structures:**
The implementation relies on standard tensor operations. No custom memory layouts are required beyond the input and coordinate tensors.

**Steps:**
1.  **Preprocessing:** Clone and detach the coordinate tensor $C_{grid}$. Convert it to the same device and data type as the input tensor $I$ [S1, unofficial].
2.  **Dimension Validation:** Extract spatial sizes from $I$. Assert that the number of spatial dimensions is either 2 or 3 [S1, unofficial].
3.  **3D Reordering:** If the input is 3D (shape $(B, C, T, H, W)$), the coordinate tensor is expected in $(B, T, H, W, 3)$ format. Reorder the coordinate dimensions from $(t, x, y)$ to $(x, y, t)$ using index mapping $[1, 2, 0]$ on the last three dimensions [S1, unofficial].
4.  **Coordinate Transformation:** Compute a scaling factor $s$ for each spatial dimension $d \in \{H, W\}$ or $\{T, H, W\}$:
    - If `align_corners` is `True`:
      $$ s_d = \frac{2}{\max(\text{size}_d - 1, 1)} $$
    - If `align_corners` is `False`:
      $$ s_d = \frac{2}{\text{size}_d} $$
    Transform the coordinates $c$ by multiplying by $s$ and subtracting 1:
    $$ c' = c \cdot s - 1 $$
    This maps the grid coordinates to the pixel/voxel center space [S1, unofficial].
5.  **Sampling:** Perform bilinear interpolation using the transformed coordinates. For a 2D point $(x, y)$, the value is computed as:
    $$ V = (1-w_x)(1-w_y)I_{i,j} + w_x(1-w_y)I_{i+1,j} + (1-w_x)w_y I_{i,j+1} + w_x w_y I_{i+1,j+1} $$
    where $i = \lfloor x \rfloor, j = \lfloor y \rfloor$, and $w_x, w_y$ are the fractional parts. The operation handles boundary conditions according to `padding_mode` [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def bilinear_sampler(input: torch.Tensor, coords: torch.Tensor, align_corners: bool = True, padding_mode: str = 'border') -> torch.Tensor:
    """
    Samples input tensor at coordinates using bilinear interpolation.
    input: (B, C, H, W) or (B, C, T, H, W)
    coords: (B, H_o, W_o, 2) or (B, T_o, H_o, W_o, 3)
    """
    # 1. Clone, detach, and convert device/dtype
    coords = coords.clone().detach().to(device=input.device, dtype=input.dtype)
    
    # 2. Get spatial sizes
    sizes = input.shape[2:]
    assert len(sizes) in (2, 3), f"Expected 2 or 3 spatial dimensions, got {len(sizes)}"
    
    # 3. Reorder 3D coords from (t, x, y) to (x, y, t)
    if len(sizes) == 3:
        # coords shape: (B, T, H, W, 3) -> (B, H, W, T, 3) is not quite right, 
        # the note says reorder from (t, x, y) to (x, y, t) using indices [1, 2, 0] on the last dim.
        # Assuming coords[..., [1, 2, 0]] implies the last dim is the coordinate vector (t,x,y)
        # and we want (x,y,t).
        coords = coords[..., [1, 2, 0]]
        
    # 4. Compute scale and transform
    # Note: The source says "reversed(sizes)". 
    # If sizes is (H, W), reversed is (W, H).
    # If sizes is (T, H, W), reversed is (W, H, T).
    # We need to apply the scale to the corresponding coordinate dimensions.
    
    scale_factors = []
    for size in reversed(sizes):
        if align_corners:
            s = 2.0 / max(size - 1, 1)
        else:
            s = 2.0 / size
        scale_factors.append(s)
    
    # scale_factors is now [s_last, ..., s_first]
    # We need to broadcast this to the coordinate tensor.
    # coords shape: (B, ..., D) where D is 2 or 3.
    # The last dimension of coords corresponds to the spatial dimensions.
    # If we reversed sizes, the last coord dim corresponds to the first size dim?
    # Let's look at the mapping.
    # Input: (B, C, H, W). Sizes: (H, W). Reversed: (W, H).
    # Coords: (B, H_o, W_o, 2). Last dim: [x, y].
    # Usually x corresponds to W (width) and y to H (height) in image coordinates?
    # Or x is column (W) and y is row (H).
    # The source code snippet doesn't show the broadcasting logic explicitly, 
    # but standard grid_sample expects coords in [-1, 1].
    
    # Reshape scale_factors to broadcast correctly over the last dimension of coords.
    # scale_factors has length len(sizes).
    # coords[..., -1] is the last coord dim.
    # We need to map scale_factors[i] to the corresponding coord dimension.
    
    # If sizes = (H, W), reversed = (W, H).
    # Coords last dim is [x, y]. x is usually associated with W, y with H.
    # So scale_factors[0] (for W) goes to x, scale_factors[1] (for H) goes to y.
    
    # Construct the scale tensor for broadcasting
    # shape of scale_tensor should be (1, 1, ..., 1, D) where D is 2 or 3
    scale_shape = [1] * coords.dim()
    scale_shape[-1] = len(scale_factors)
    scale_tensor = torch.tensor(scale_factors, dtype=coords.dtype, device=coords.device).view(scale_shape)
    
    # Apply transformation: coords * scale - 1
    coords = coords * scale_tensor - 1.0
    
    # 5. Call grid_sample
    # Note: F.grid_sample expects input (B, C, H, W) and grid (B, H_o, W_o, 2)
    # The input to F.grid_sample must match the spatial order.
    # If we modified coords, we must ensure F.grid_sample interprets them correctly.
    # PyTorch's grid_sample expects grid coordinates to correspond to the input dimensions.
    # If input is (B, C, H, W), grid is (B, H_o, W_o, 2) where grid[..., 0] is x (W) and grid[..., 1] is y (H).
    # Our scale_factors were derived from reversed(sizes) = (W, H).
    # So scale_factors[0] is for W, scale_factors[1] is for H.
    # coords[..., 0] is x (W), coords[..., 1] is y (H).
    # The multiplication coords * scale_tensor works if scale_tensor aligns with the last dim.
    
    output = F.grid_sample(input, coords, align_corners=align_corners, padding_mode=padding_mode)
    
    return output
```

## Subtopics

### Sample Features 4D
A variant that samples spatial features from a 4D tensor $(B, C, H, W)$ at a set of $R$ points. It calls the standard bilinear sampler and reshapes the output from $(B, C, R, 1)$ to $(B, R, C)$ by permuting and viewing the tensor. It is used when extracting feature vectors for specific points rather than a full grid [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(B \cdot C \cdot H_o \cdot W_o)$ for 2D, as each output pixel requires a constant number of arithmetic operations (4 multiplications, 3 additions for bilinear).
- **Memory Complexity:** $O(B \cdot C \cdot H_o \cdot W_o)$ for the output tensor. The coordinate tensor requires $O(B \cdot H_o \cdot W_o \cdot 2)$ or $O(B \cdot T_o \cdot H_o \cdot W_o \cdot 3)$ memory.
- **Performance:** Highly optimized in modern deep learning frameworks (e.g., PyTorch's `F.grid_sample`) using SIMD instructions and GPU kernels.
- **Strengths:** Differentiable, allowing gradient flow to both the input features and the coordinates. Efficient for dense sampling.
- **Limitations:** Bilinear interpolation is only first-order accurate. It may introduce blurring compared to higher-order methods like [Tricubic B-Spline Interpolation](8246-tricubic-b-spline-interpolation.md). Boundary handling depends on `padding_mode`, which can introduce artifacts if not chosen carefully.

## Background
The bilinear sampler is a fundamental component in Spatial Transformer Networks (STNs) and various 3D vision architectures. It is implemented as `F.grid_sample` in PyTorch. The specific coordinate transformation logic involving `align_corners` and the handling of 3D tensor reordering are detailed in the implementation of the AnySplat project [S1, unofficial].
