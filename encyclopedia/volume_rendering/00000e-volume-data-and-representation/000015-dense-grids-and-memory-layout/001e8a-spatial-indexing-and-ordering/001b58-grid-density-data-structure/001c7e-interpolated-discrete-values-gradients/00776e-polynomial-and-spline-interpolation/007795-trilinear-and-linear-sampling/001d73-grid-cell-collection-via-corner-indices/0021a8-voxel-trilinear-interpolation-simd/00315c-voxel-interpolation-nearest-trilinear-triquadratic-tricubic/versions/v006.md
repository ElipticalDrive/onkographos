# Voxel Interpolation (Nearest, Trilinear, Triquadratic, Tricubic)
## Overview
Voxel interpolation samples values from a dense or sparse 3D volume grid at arbitrary floating-point coordinates using polynomial interpolation of varying orders (nearest, trilinear, triquadratic, tricubic) [S1, unofficial][S2, unofficial]. It solves the problem of extracting continuous scalar or vector fields from discrete voxel representations, which is essential for volume rendering and signed distance field (SDF) evaluation [S1, unofficial][S2, unofficial]. It sets itself apart from its parent [Voxel Trilinear Interpolation (SIMD)](2564-voxel-trilinear-interpolation-simd.md) by supporting multiple interpolation orders (0–3) and integrating with high-level tensor frameworks like PyTorch or low-level tree structures like OpenVDB/NanoVDB [S1, unofficial][S2, unofficial][S3].
## How it works
### Inputs and Outputs
**Inputs:**
1.  **Volume Grid:** A 3D array of values. In PyTorch, this is a tensor of shape `(D, H, W)` or `(1, 1, D, H, W)` [S1, unofficial]. In OpenVDB/NanoVDB, this is a `Tree` or `Accessor` object [S2, unofficial][S3].
2.  **Query Points:** A set of 3D coordinates. In PyTorch, a grid tensor of shape `(N, 3)` or `(1, N, 3)` containing normalized coordinates in `[-1, 1]` [S1, unofficial]. In OpenVDB, a `Vec3f` or `Vec3d` coordinate [S2, unofficial].
3.  **Interpolation Order:** An integer specifying the method: 0 = Nearest Neighbor, 1 = Trilinear, 2 = Triquadratic, 3 = Tricubic [S1, unofficial][S2, unofficial].

**Outputs:**
*   Sampled values at the query points. For PyTorch, a tensor of shape `(N,)` or `(1, N)` [S1, unofficial]. For OpenVDB, a scalar or vector value [S2, unofficial].

### Data Structures
**PyTorch Grid Tensor:**
*   Shape: `(1, N, 3)` where `N` is the number of query points.
*   Values: Normalized coordinates in the range `[-1, 1]`. The axes are ordered `(X, Y, Z)` [S1, unofficial].

**OpenVDB/NanoVDB Sampler:**
*   Created via a factory function `createSampler<Order, TreeT, UseCache>(acc)` [S3].
*   `Order`: Integer template parameter (0–3) [S2, unofficial][S3].
*   `TreeT`: The tree or accessor type (e.g., `openvdb::FloatGrid::ConstAccessor`) [S2, unofficial][S3].
*   `UseCache`: Boolean flag, default `true`, for caching node lookups [S3].

### Steps
1.  **Coordinate Normalization (PyTorch Context):** Normalize the bounding box or query points to `[-1, 1]` using `bbox_norm = (bbox - center) / extent`, where `center = bbox.sum(-1)/2` and `extent = (bbox[:,1]-bbox[:,0])/2` [S1, unofficial].
2.  **Sampler Creation (OpenVDB/NanoVDB Context):** Obtain an accessor for the grid via `grid.getAccessor()`, then instantiate the sampler with `nanovdb::math::createSampler<Order>(acc)` [S3].
3.  **Sampling Execution:**
    *   **PyTorch:** Reshape input volume to `(1, 1, D, H, W)` and grid to `(1, N, 3)`, call the sampling routine, and squeeze output to remove batch/channel dimensions [S1, unofficial].
    *   **OpenVDB/NanoVDB:** Iterate over query points (e.g., using `tbb::parallel_for`) and call the sampler with the coordinate, or use `wsSample` for world-space SDF evaluation [S1, unofficial][S2, unofficial].

### Formulas
**Trilinear Interpolation (Order 1):**
For a query point $(x, y, z)$ within a voxel defined by integer corners $(i, j, k)$ to $(i+1, j+1, k+1)$, let $u, v, w$ be the fractional parts of $x, y, z$:
$$ u = x - i, \quad v = y - j, \quad w = z - k $$
The value $V$ is computed as:
$$ V = (1-u)(1-v)(1-w)V_{000} + u(1-v)(1-w)V_{100} + (1-u)v(1-w)V_{010} + u v (1-w)V_{110} + (1-u)(1-v)w V_{001} + u(1-v)w V_{101} + (1-u)v w V_{011} + u v w V_{111} $$
[G]

**Nearest Neighbor (Order 0):**
$$ V = V_{\lfloor x \rfloor, \lfloor y \rfloor, \lfloor z \rfloor} $$
[G]

### Parameters
*   **Order:** 0 (Nearest), 1 (Trilinear), 2 (Triquadratic), 3 (Tricubic) [S2, unofficial].
*   **Mode:** 'nearest' or 'trilinear' [S1, unofficial].
*   **UseCache:** Boolean, default `true` (NanoVDB) [S3].

### Edge Cases and Pitfalls
*   **Out-of-Bounds:** Queries outside the volume bounds must be clamped or return a default value (typically 0) [S1, unofficial].
*   **Precision:** Use `Vec3d` for high-precision SDF sampling to avoid coordinate jitter [S1, unofficial].
*   **Axis Ordering:** PyTorch's grid generation may require axis reversal (XZY to ZXY to XYZ) depending on the source data layout [S1, unofficial].
*   **Sparse Volumes:** For sparse grids, interpolation traverses the tree hierarchy; empty space is handled efficiently by skipping inactive nodes [S2, unofficial][S3].

### Pseudocode
```python
import math

def sample_volume(volume, query_points, bbox, order=1):
    """
    Samples a 3D volume at query points using nearest or trilinear interpolation.
    volume: list of lists of lists (D, H, W)
    query_points: list of (x, y, z) tuples in physical/voxel coordinates
    bbox: list of two tuples [(min_x, min_y, min_z), (max_x, max_y, max_z)]
    order: 0 for nearest, 1 for trilinear
    """
    # 1. Normalize query points to [-1, 1]
    bbox = list(bbox)
    center = [(bbox[0][i] + bbox[1][i]) / 2.0 for i in range(3)]
    extent = [(bbox[1][i] - bbox[0][i]) / 2.0 for i in range(3)]
    extent = [1.0 if e == 0 else e for e in extent]
    
    results = []
    for p in query_points:
        normalized = [((p[i] - center[i]) / extent[i]) for i in range(3)]
        
        # 2. Map normalized [-1, 1] to voxel indices [0, D/H/W-1]
        min_idx = [0, 0, 0]
        max_idx = [len(volume) - 1, len(volume[0]) - 1, len(volume[0][0]) - 1]
        
        idx = [int(math.floor((normalized[i] + 1.0) / 2.0 * (max_idx[i] - min_idx[i]) + min_idx[i])) for i in range(3)]
        idx = [max(min_idx[i], min(max_idx[i], idx[i])) for i in range(3)]
        
        frac = [(normalized[i] + 1.0) / 2.0 * (max_idx[i] - min_idx[i]) + min_idx[i] - idx[i] for i in range(3)]
        
        # 3. Interpolate
        if order == 0:
            results.append(volume[idx[0]][idx[1]][idx[2]])
        elif order == 1:
            u, v, w = frac
            def get_val(x, y, z):
                x = max(min_idx[0], min(max_idx[0], x))
                y = max(min_idx[1], min(max_idx[1], y))
                z = max(min_idx[2], min(max_idx[2], z))
                return volume[x][y][z]
                
            v000 = get_val(idx[0], idx[1], idx[2])
            v100 = get_val(idx[0]+1, idx[1], idx[2])
            v010 = get_val(idx[0], idx[1]+1, idx[2])
            v110 = get_val(idx[0]+1, idx[1]+1, idx[2])
            v001 = get_val(idx[0], idx[1], idx[2]+1)
            v101 = get_val(idx[0]+1, idx[1], idx[2]+1)
            v011 = get_val(idx[0], idx[1]+1, idx[2]+1)
            v111 = get_val(idx[0]+1, idx[1]+1, idx[2]+1)
            
            val = ((1-u)*(1-v)*(1-w)*v000 + u*(1-v)*(1-w)*v100 +
                   (1-u)*v*(1-w)*v010 + u*v*(1-w)*v110 +
                   (1-u)*(1-v)*w*v001 + u*(1-v)*w*v101 +
                   (1-u)*v*w*v011 + u*v*w*v111)
            results.append(val)
    return results
```
*Note: The OpenVDB/NanoVDB C++ factory pattern `createSampler<Order>(acc)` is a templated compile-time construct not directly translatable to Python; the Python implementation above provides the equivalent runtime logic.*
## Subtopics

### [Tricubic B-Spline Interpolation](8246-tricubic-b-spline-interpolation.md)
A GPU-accelerated method for sampling 3D volume textures using uniform cubic B-splines, providing smoother results than linear interpolation while being faster than full tricubic convolution. It sets itself apart from standard tricubic convolution by reducing the number of texture fetches through grouped weight calculations and optimized coordinate mapping, making it suitable for real-time volume rendering where visual fidelity is prioritized over the absolute minimal computational cost of trilinear interpolation.

### [Bilinear Sampler](12826-bilinear-sampler.md)
The Bilinear Sampler is a differentiable operation that samples values from a dense grid (tensor) at arbitrary floating-point coordinates using bilinear interpolation. It solves the problem of extracting feature maps or voxel data at non-integer locations, which is essential for spatial transformer networks, deformable convolutions, and neural rendering pipelines. It distinguishes itself from nearest-neighbor sampling by providing smooth gradients and from higher-order splines by its computational efficiency and local support over a single cell. It builds on [Voxel Interpolation (Nearest, Trilinear, Triquadratic, Tricubic)](6486-voxel-interpolation-nearest-trilinear-triquadratic-tricubic.md) but is specialized for 2D spatial grids (and 3D spatiotemporal grids) with specific coordinate normalization conventions (`align_corners`) and padding modes.

### Voxel Sampler Factory
Factory function that creates a voxel sampler of a specific polynomial order [S3]. It allows for compact syntax in C++ code [S3]. Parameters include `Order` (polynomial order) and `UseCache` (boolean, default true) [S3]. Example: `auto smp = nanovdb::math::createSampler<1>(acc)` [S3].

### SDF Grid Sampling
Evaluates the signed distance field at arbitrary query points using different interpolation strategies [S1, unofficial]. It uses `openvdb::tools::GridSampler` with modes: 1 (BoxSampler/trilinear), 2 (QuadraticSampler), or default (PointSampler/nearest) [S1, unofficial]. It supports parallel iteration over query points using TBB [S1, unofficial].

### Multi-resolution Interpolation
An algorithm to interpolate values at boundaries of voxel blocks with different resolutions by searching for the common finest grid between neighbours [S4]. Initialisation of uninitialised fine voxels interpolates values from parent grids using extrapolation at block boundaries to avoid synchronisation issues [S4]. Given a 3D sampling point and scale, it converts to voxel coordinates, fetches 8-neighbour points at the finest resolution, checks resolution constraints, and repeats the search at a coarser scale if violated [S4]. If uniform, it performs interpolation at the target scale [S4].

## Operating characteristics
Time and memory complexity are not given in the sources. PyTorch's `F.grid_sample` natively supports nearest and trilinear modes, while higher orders require custom implementations [S1, unofficial]. Multi-resolution interpolation handles scale changes by falling back to coarser grids at block boundaries [S4]. Trilinear interpolation is the most common trade-off between speed and smoothness [S1, unofficial].
## Background
The PyTorch implementation (`F.grid_sample`) is used for sampling dense volume grids at arbitrary query points [S1, unofficial]. The OpenVDB/NanoVDB implementations provide templated samplers for sparse voxel trees [S2, unofficial][S3]. SDF evaluation leverages these samplers with world-space coordinate transforms [S1, unofficial]. Multi-resolution rendering strategies handle adaptive voxel hierarchies by interpolating across scale boundaries [S4].
