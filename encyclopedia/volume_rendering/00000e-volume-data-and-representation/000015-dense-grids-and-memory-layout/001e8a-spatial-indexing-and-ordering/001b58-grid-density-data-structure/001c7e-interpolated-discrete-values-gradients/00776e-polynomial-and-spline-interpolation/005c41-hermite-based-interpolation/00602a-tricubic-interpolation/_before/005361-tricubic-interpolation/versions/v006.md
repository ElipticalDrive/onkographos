# Tricubic Interpolation
Also called: Tricubic Hermite Interpolation

## Overview
Tricubic interpolation is a higher-order method that employs cubic polynomials over a $4 \times 4 \times 4$ neighborhood of 64 points to approximate a continuous 3D field [S1]. It provides $C^1$ continuity and fourth-order accuracy $O(h^4)$, making it superior to trilinear interpolation for smooth functions and gradient-sensitive tasks like volume rendering, at the cost of increased computational expense [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A dense grid tensor $\mathbf{G}$ of shape $(D_x, D_y, D_z, C)$ containing scalar values and their spatial gradients (or derivatives) [S2, unofficial]. Query point $\mathbf{p} \in \mathbb{R}^3$.
*   **Output:** Interpolated value $\mathbf{v} \in \mathbb{R}^C$ and optionally its gradient $\nabla \mathbf{v}$ at $\mathbf{p}$ [S2, unofficial].

**Data Structures:**
The method requires access to the 64 control points surrounding the query voxel. For each control point $(i, j, k)$, the data structure must store:
1.  The scalar value $V_{i,j,k}$.
2.  The three partial derivatives $\frac{\partial V}{\partial x}, \frac{\partial V}{\partial y}, \frac{\partial V}{\partial z}$ at that point [S2, unofficial].
*Note: If gradients are not pre-computed in the grid, they must be estimated from neighboring voxel values, which is not part of the core interpolation definition but a prerequisite [G].*

**Numbered Steps:**
1.  **Locate Support:** Compute the integer indices $(i, j, k) = (\lfloor p_x \rfloor, \lfloor p_y \rfloor, \lfloor p_z \rfloor)$ and normalized local coordinates $(u, v, w) = (p_x - i, p_y - j, p_z - k)$ where $u, v, w \in [0, 1]$ [S1][S2, unofficial].
2.  **Gather Data:** Retrieve the 64 values and 192 gradients from the $4 \times 4 \times 4$ neighborhood centered on the voxel defined by $(i, j, k)$. Specifically, access points $(i+\delta_x, j+\delta_y, k+\delta_z)$ for $\delta_x, \delta_y, \delta_z \in \{-1, 0, 1\}$ [S1].
3.  **Construct Basis:** Define the 1D cubic Hermite basis functions for each axis. For a local coordinate $t \in [0, 1]$, the basis functions $H_0(t), H_1(t), H_2(t), H_3(t)$ are:
    $$
    \begin{aligned}
    H_0(t) &= 2t^3 - 3t^2 + 1 \\
    H_1(t) &= -2t^3 + 3t^2 \\
    H_2(t) &= t^3 - 2t^2 + t \\
    H_3(t) &= t^3 - t^2
    \end{aligned}
    $$
    These functions ensure that $H_0(0)=1, H_0(1)=0, H_0'(0)=0, H_0'(1)=0$, etc., mapping values and tangents correctly [S2, unofficial].
4.  **Evaluate:** Compute the interpolated value using the tensor product of the basis functions and the gathered data. For a single channel:
    $$
    V(\mathbf{p}) = \sum_{\delta_x=-1}^{1} \sum_{\delta_y=-1}^{1} \sum_{\delta_z=-1}^{1} \left( H_0(u) V_{i+\delta_x,j+\delta_y,k+\delta_z} + H_1(u) \frac{\partial V}{\partial x}_{i+\delta_x,j+\delta_y,k+\delta_z} + H_2(u) V_{i+\delta_x,j+\delta_y,k+\delta_z} + H_3(u) \frac{\partial V}{\partial x}_{i+\delta_x,j+\delta_y,k+\delta_z} \right) \dots
    $$
    *Correction:* The standard 3D Hermite formulation separates the axes. The value is computed as:
    $$
    V(\mathbf{p}) = \mathbf{H}(u)^T \mathbf{V}_{block} \mathbf{H}(v) \mathbf{H}(w)^T \text{ (conceptual tensor contraction)}
    $$
    More explicitly, for each of the 64 points, the contribution is weighted by the product of the 1D basis functions corresponding to the value or derivative type. Let $\mathbf{h}(t) = [H_0(t), H_1(t), H_2(t), H_3(t)]^T$. The interpolation is:
    $$
    V(\mathbf{p}) = \sum_{\delta_x=-1}^{1} \sum_{\delta_y=-1}^{1} \sum_{\delta_z=-1}^{1} \mathbf{h}(u)^T \mathbf{M}_{\delta_x} \mathbf{G}_{i+\delta_x,j+\delta_y,k+\delta_z} \mathbf{M}_{\delta_y}^T \mathbf{h}(v) \mathbf{M}_{\delta_z}^T \mathbf{h}(w)
    $$
    Where $\mathbf{G}$ contains the value and derivatives, and $\mathbf{M}$ selects the appropriate basis function component. A simpler implementation often computes the 1D interpolation along X, then Y, then Z, using the Hermite basis for both value and derivative inputs at each step [S2, unofficial].

**Parameters:**
*   Grid spacing $h$: Determines the accuracy order $O(h^4)$ [S1].
*   Boundary handling: Out-of-bounds indices are clamped to $[0, D_d-1]$ [S1][S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query, but with a high constant factor due to 64 point accesses and cubic polynomial evaluations. Significantly slower than trilinear [S1].
*   **Memory Complexity:** Requires storing gradients alongside values, increasing memory footprint by 4x (1 value + 3 derivatives) [S2, unofficial].
*   **Accuracy:** $O(h^4)$ for smooth functions, superior to trilinear's $O(h^2)$ [S1].
*   **Continuity:** $C^1$ continuous, reducing artifacts in gradient-sensitive visualization [S1].
*   **Strengths:** High accuracy, smooth gradients, differentiable outputs [S1].
*   **Limitations:** High computational cost, requires gradient data (pre-computation or estimation needed) [S1][S2, unofficial].
*   **When to use:** When $C^1$ continuity is critical for visualization quality and performance allows [S1].
*   **When not to use:** For real-time applications with limited GPU memory or compute, or when data is not smooth [S1].

## Background
Tricubic Hermite interpolation was discussed in the context of Irradiance Volumes for games, highlighting its efficiency in GPU constant stores when using lower-order spherical harmonics [S2, unofficial]. It is a standard higher-order alternative to trilinear interpolation in medical imaging and volume rendering for upsampling 3D volumes [S1].
