# Multi-scale Feature Interpolation

Also called: HexPlaneField Interpolation

## Overview
Multi-scale feature interpolation combines feature representations from multiple resolution levels of a HexPlane grid to reconstruct dense 3D features at query points [S1, unofficial]. It addresses the limitation of single-resolution grids by aggregating coarse structural information with fine-grained details, improving reconstruction quality for dynamic scenes [S1, unofficial]. Unlike standard linear or B-spline interpolation which operates on a single fixed grid, this method explicitly manages a hierarchy of grid scales, concatenating or accumulating interpolated results across these levels [S1, unofficial].

## How it works
**Inputs:**
- `pts`: Query points tensor of shape $(N, 3)$, where $N$ is the number of points and 3 represents $(x, y, z)$ coordinates [S1, unofficial].
- `ms_grids`: A list of grid tensors, one for each scale level. Each grid $\mathbf{G}_l$ has shape $(D_{x,l}, D_{y,l}, D_{z,l}, C_l)$ [S1, unofficial].
- `num_levels`: The number of scales in `ms_grids` [S1, unofficial].
- `concat_features`: Boolean flag. If `True`, features from different scales are concatenated along the channel dimension. If `False`, they are summed [S1, unofficial].

**Outputs:**
- `multi_scale_interp`: Interpolated feature tensor. Shape depends on `concat_features`. If `True`, shape is $(N, \sum C_l)$. If `False`, shape is $(N, C_{base})$ assuming compatible channel counts or accumulation logic [S1, unofficial].

**Data Structures:**
- The HexPlane grid representation decomposes the 3D volume into six 2D planes (XY, YZ, XZ, and their inverses). However, the provided source notes describe a generic multi-scale grid interpolation loop without detailing the specific HexPlane projection mechanics, focusing instead on the aggregation logic [S1, unofficial]. The implementation assumes a helper function `interpolate_grid(grid, pts)` exists which performs the underlying spatial interpolation (e.g., trilinear or bilinear on planes) for a single scale [S1, unofficial].

**Steps:**
1.  Initialize an empty list `multi_scale_interp` to store results from each scale.
2.  Iterate through each scale level $l$ from $0$ to `num_levels` - 1:
    a.  Retrieve the grid $\mathbf{G}_l$ from `ms_grids`.
    b.  Compute the interpolated features for the query points `pts` using the grid $\mathbf{G}_l$. Let this result be $I_l$.
    c.  If `concat_features` is `True`, append $I_l$ to `multi_scale_interp`.
    d.  If `concat_features` is `False`, add $I_l$ to the accumulated tensor (initializing the accumulator if it is the first scale).
3.  If `concat_features` is `True`, concatenate all tensors in `multi_scale_interp` along the last dimension (dim=-1).
4.  Return the final tensor.

**Pseudocode:**
```python
def interpolate_ms_features(pts, ms_grids, num_levels, concat_features=True):
    """
    Interpolates features from multiple grid scales.
    
    Args:
        pts: Tensor of shape (N, 3) containing query coordinates.
        ms_grids: List of grid tensors, one per scale level.
        num_levels: Integer, number of scales.
        concat_features: Boolean, whether to concatenate or sum features.
        
    Returns:
        Tensor of interpolated features.
    """
    multi_scale_interp = []
    accumulated_features = None
    
    for l in range(num_levels):
        # Retrieve grid for current scale
        grid = ms_grids[l]
        
        # Interpolate features for this scale
        # Note: The specific interpolation kernel (e.g., HexPlane bilinear) 
        # is assumed to be implemented in interpolate_grid.
        interp_space = interpolate_grid(grid, pts)
        
        if concat_features:
            multi_scale_interp.append(interp_space)
        else:
            if accumulated_features is None:
                accumulated_features = interp_space
            else:
                accumulated_features = accumulated_features + interp_space
                
    if concat_features:
        # Concatenate along the feature dimension (last dim)
        result = torch.cat(multi_scale_interp, dim=-1)
    else:
        result = accumulated_features
        
    return result
```

**Parameters:**
- `concat_features`: Default `True`. Determines the fusion strategy [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Channel Mismatch:** If `concat_features` is `False`, the channel dimensions of all scales must be identical to allow addition. If they differ, the operation is undefined or requires padding/alignment not described in the sources [S1, unofficial].
- **Grid Resolution:** Coarse grids may lack high-frequency detail, while fine grids may be noisy. The multi-scale approach mitigates this, but extreme resolution gaps may lead to artifacts if not balanced [S1, unofficial].
- **Coordinate Normalization:** The `pts` coordinates must be normalized to the grid's indexing space (typically $[0, 1]$ or $[-1, 1]$) consistent with how the grids were constructed [S1, unofficial].

## Subtopics

### 3D Gaussian Feature Interpolation
This variant interpolates features using pre-computed 3D Gaussian parameters rather than a dense grid. It computes Gaussian weights based on the distance between query points and Gaussian centers, weighted by the inverse covariance matrix, and performs a weighted sum of features [S2, unofficial]. The data structure includes feature tensors `feats` of shape $(B, C, K)$, offsets `offsets` of shape $(B, K, 3)$, determinants `det` of shape $(B, K)$, and inverse covariance matrices `inv` of shape $(B, K, 3, 3)$ [S2, unofficial]. It is chosen when explicit geometric primitives are preferred over voxel-based representations, particularly in dynamic scene rendering where Gaussian splats offer efficient memory usage and differentiability [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot L \cdot K)$, where $N$ is the number of query points, $L$ is the number of scales, and $K$ is the cost of interpolation per scale (dependent on grid resolution and interpolation kernel) [S1, unofficial]. For HexPlane grids, $K$ is typically low due to the 2D nature of the planes.
- **Memory Complexity:** $O(\sum_{l=0}^{L-1} D_{x,l} D_{y,l} D_{z,l} C_l)$ to store all grid levels [S1, unofficial]. Concatenation increases output memory by a factor of $L$ if `concat_features` is `True`.
- **Performance:** In synthetic scenes (D-NeRF), training time is reported as ~8 minutes, and in real dynamic scenes (HyperNeRF) as ~30 minutes, indicating efficient convergence [S1, unofficial].
- **Strengths:** Captures multi-resolution details; effective for dynamic scenes; compatible with HexPlane representations for memory efficiency.
- **Limitations:** Requires careful tuning of scale levels; concatenation increases feature dimensionality, potentially impacting downstream decoder complexity.

## Background
Multi-scale feature interpolation using HexPlane grids was introduced in the context of 4D Gaussian Splatting for dynamic scene representation. The method was part of the 4DGaussians framework, accepted at CVPR 2024 [S1, unofficial]. It builds upon the HexPlane representation to handle temporal dynamics by interpolating features across multiple spatial resolutions, improving reconstruction quality for both synthetic and real-world dynamic videos [S1, unofficial].
