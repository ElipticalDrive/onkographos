# Grid Cell Collection via Corner Indices

Also called: 8-Corner Grid Sampling, Trilinear Corner Indexing, GatherGeoParams, GatherFeatParams, Gather Tri-Interpolated Feature Parameters, Gather Tri-Interpolated Geometry Parameters

## Overview
Grid Cell Collection via Corner Indices is a method to sample a 3D volume at a continuous coordinate by interpolating the 8 surrounding voxel corners using linear weights [S1, S2, S3, S4, unofficial]. It serves as the fundamental indexing and gathering primitive for trilinear interpolation, extracting geometry and feature parameters from a dense grid based on voxel keys and care indices [S3, unofficial]. Unlike [Voxel Data Interpolation and Sampling](12781-voxel-data-interpolation-and-sampling.md) which may describe broader interpolation strategies, this method specifically focuses on the efficient collection of the 8 corner values required for the subsequent weighted combination [S4, unofficial].

## How it works
**Inputs:**
- `point`: A continuous 3D coordinate $(x, y, z)$ or a batch of such coordinates.
- `grid`: A 3D tensor or structured volume containing the data to be sampled.
- `boundary_mode`: A string or enum defining behavior for out-of-bounds coordinates (e.g., 'fill', 'clamp', 'periodic').
- `outsideValue`: The value to return if the point is out of bounds or if interpolation fails due to NaN/Inf [S1, unofficial].

**Outputs:**
- `result`: The interpolated scalar or vector value at `point`.

**Data Structures:**
- **VoxSample** (used in brick-based implementations): A struct containing two arrays of size 8:
  - `values`: Array of 8 floats.
  - `positions`: Array of 8 `vec3` coordinates.
  - Index mapping: Indices 0–3 correspond to the lowest Z-plane corners (sw, se, ne, nw). Indices 4–7 correspond to the highest Z-plane corners (sw, se, ne, nw) [S4, unofficial].

**Numbered Steps:**

1. **Boundary Check:** Resolve input coordinates $(x, y, z)$. If the coordinate is out of bounds and `boundary_mode` is 'fill', return `outsideValue` immediately [S1, unofficial].
2. **Compute Integer Indices:** Calculate the floor indices for each dimension:
   $$x_0 = \lfloor x \rfloor, \quad y_0 = \lfloor y \rfloor, \quad z_0 = \lfloor z \rfloor$$ [S1, unofficial].
3. **Compute Ceiling Indices:** Calculate the ceiling indices, clamped to the volume bounds $(W-1, H-1, D-1)$:
   $$x_1 = \min(x_0 + 1, W - 1)$$
   $$y_1 = \min(y_0 + 1, H - 1)$$
   $$z_1 = \min(z_0 + 1, D - 1)$$ [S1, unofficial].
   *Note: In periodic boundary modes, indices are wrapped using modulo arithmetic instead of clamping [S2, unofficial].*
4. **Generate Corner Indices:** Form all 8 combinations of $(x_0/x_1, y_0/y_1, z_0/z_1)$. This results in a list of 8 integer coordinate triplets representing the corners of the enclosing voxel [S2, unofficial].
5. **Compute Fractional Offsets:** Calculate the fractional part of the coordinate within the voxel:
   $$f_x = x - x_0, \quad f_y = y - y_0, \quad f_z = z - z_0$$ [S1, unofficial].
6. **Compute Weights:** Define the linear interpolation weights for each dimension:
   $$w_x = [1 - f_x, f_x]$$
   $$w_y = [1 - f_y, f_y]$$
   $$w_z = [1 - f_z, f_z]$$ [S1, unofficial].
7. **Gather Values:** Iterate through the 8 corners (indices $i_z \in \{0,1\}, i_y \in \{0,1\}, i_x \in \{0,1\}$):
   a. Calculate the combined weight: $w = w_x[i_x] \cdot w_y[i_y] \cdot w_z[i_z]$ [S1, unofficial].
   b. If $w == 0$, skip this corner (optimization to avoid multiplying by NaN) [S1, unofficial].
   c. Retrieve the value $v$ from the grid at the corresponding corner index [S1, unofficial].
   d. If $v$ is not finite (NaN or Infinity), discard the entire result and return `outsideValue` [S1, unofficial].
   e. Accumulate the result: $result \leftarrow result + w \cdot v$ [S1, unofficial].
8. **Final Validation:** If the accumulated `result` is not finite, return `outsideValue`; otherwise, return `result` [S1, unofficial].

**Pseudocode:**

```python
def grid_cell_collection_via_corner_indices(point, grid, grid_dims, boundary_mode='clamp', outside_value=0.0):
    """
    Samples a 3D volume at a continuous coordinate using trilinear interpolation.
    
    Args:
        point (tuple): (x, y, z) continuous coordinates.
        grid (tensor/list): The 3D volume data.
        grid_dims (tuple): (W, H, D) dimensions of the grid.
        boundary_mode (str): 'clamp', 'periodic', or 'fill'.
        outside_value (float): Value to return for out-of-bounds or invalid data.
        
    Returns:
        float: Interpolated value.
    """
    x, y, z = point
    W, H, D = grid_dims
    
    # Step 1: Boundary Check
    if boundary_mode == 'fill':
        if x < 0 or x >= W or y < 0 or y >= H or z < 0 or z >= D:
            return outside_value
            
    # Step 2: Compute Floor Indices
    x0 = int(x) # floor for positive, but generally floor(x)
    y0 = int(y)
    z0 = int(z)
    
    # Ensure floor behavior for negative numbers if necessary, 
    # though typical volume coords are positive. 
    # Using math.floor for correctness.
    import math
    x0 = math.floor(x)
    y0 = math.floor(y)
    z0 = math.floor(z)

    # Step 3: Compute Ceiling Indices (Clamped)
    if boundary_mode == 'clamp':
        x1 = min(x0 + 1, W - 1)
        y1 = min(y0 + 1, H - 1)
        z1 = min(z0 + 1, D - 1)
        
        # Clamp floor indices too if point is slightly out of bounds but mode is clamp
        x0 = max(x0, 0)
        y0 = max(y0, 0)
        z0 = max(z0, 0)
        
    elif boundary_mode == 'periodic':
        x1 = (x0 + 1) % W
        y1 = (y0 + 1) % H
        z1 = (z0 + 1) % D
        x0 = x0 % W
        y0 = y0 % H
        z0 = z0 % D
    else:
        # Default to clamp if not specified
        x1 = min(x0 + 1, W - 1)
        y1 = min(y0 + 1, H - 1)
        z1 = min(z0 + 1, D - 1)
        x0 = max(x0, 0)
        y0 = max(y0, 0)
        z0 = max(z0, 0)

    # Step 4 & 5: Compute Fractional Offsets
    # Note: x0 is the floor. The offset is x - floor(x).
    fx = x - x0
    fy = y - y0
    fz = z - z0
    
    # Step 6: Compute Weights
    wx = [1.0 - fx, fx]
    wy = [1.0 - fy, fy]
    wz = [1.0 - fz, fz]
    
    # Step 7: Gather and Interpolate
    result = 0.0
    
    # Iterate iz, iy, ix from 0 to 1
    for iz in range(2):
        for iy in range(2):
            for ix in range(2):
                weight = wx[ix] * wy[iy] * wz[iz]
                
                # Skip if weight is 0 to avoid NaN multiplication issues
                if weight == 0.0:
                    continue
                
                # Determine corner coordinates
                cx = x0 if ix == 0 else x1
                cy = y0 if iy == 0 else y1
                cz = z0 if iz == 0 else z1
                
                # Retrieve value
                # Assuming grid is accessed as grid[z][y][x] or similar flat indexing
                # This depends on the specific memory layout of `grid`
                try:
                    value = grid[cz][cy][cx]
                except IndexError:
                    # Fallback for safety if indices are slightly off due to float precision
                    return outside_value
                    
                # Check for finite value
                if not (math.isfinite(value)):
                    return outside_value
                    
                result += weight * value
                
    # Step 8: Final Validation
    if not math.isfinite(result):
        return outside_value
        
    return result
```

**Parameters:**
- `interpolation`: Set to "linear" to use this method [S1, unofficial].
- `cval`: Constant value to fill past edges, default 0 (used in variants like `Grid2`) [S5, unofficial].

**Edge Cases and Pitfalls:**
- **NaN/Infinity Contamination:** If any neighbor value is NaN or Infinity, the entire interpolation result is discarded and replaced with `outsideValue` to prevent contamination [S1, unofficial].
- **Zero Weight:** If the interpolation weight is exactly 0 (e.g., at integer coordinates), the corresponding neighbor is skipped to avoid multiplying by NaN [S1, unofficial].
- **Out-of-Bounds:** Coordinates outside the grid volume must be handled explicitly via boundary modes (clamp, periodic, or fill) [S1, S2, unofficial].

## Subtopics

### [VoxelGrid](2159-voxelgrid.md)
VoxelGrid is a dense, fixed-resolution 3D data structure that stores scene properties (such as density, color, or signed distance) at grid vertices to support efficient feature queries via trilinear interpolation. It serves as a differentiable, learnable replacement for implicit neural networks (MLPs) in neural rendering, enabling direct optimization of volumetric attributes. Unlike sparse structures like octrees, which are difficult to update on the fly in learning frameworks, VoxelGrid offers fast, memory-accessible queries at the cost of high memory consumption for large volumes.

### [Curvilinear to Rectilinear Resampling](2248-curvilinear-to-rectilinear-resampling.md)
This method converts a curvilinear input grid into a rectilinear output grid by estimating function values at new sample points.

### [Voxel Trilinear Interpolation (SIMD)](2564-voxel-trilinear-interpolation-simd.md)
Voxel Trilinear Interpolation (SIMD) retrieves scalar or vector values from a 3D volume grid at arbitrary floating-point coordinates by interpolating the eight corner values of the enclosing voxel cell using Single Instruction, Multiple Data (SIMD) instructions. It builds on [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md) by fetching the eight surrounding voxel values and combining them with fractional weights.

### [3D Trilinear Interpolation](2613-3d-trilinear-interpolation.md)
3D Trilinear Interpolation estimates the value of a scalar field at an arbitrary point within a voxel by computing a weighted average of the values at the voxel's eight corners. It solves the problem of sampling discrete volume data at non-integer coordinates, which is essential for ray casting where sample points rarely align with grid vertices. Unlike nearest-neighbor interpolation, which produces blocky artifacts, trilinear interpolation provides $C^0$ continuity and smoother gradients, though it is less accurate than higher-order splines for data with high curvature.

### [iso_corners_list_f1v4](2627-iso-corners-list-f1v4.md)
`iso_corners_list_f1v4` is a GPU kernel variant that computes the values of one function at the eight corners of the grid cells enclosing a list of input points, enabling trilinear interpolation or surface extraction. It differs from its siblings by processing 256 consecutive lattice points per thread group across 2–4 neighboring bricks, sharing shell setup overhead among all points in the group rather than per-brick, which improves occupancy and reduces redundant memory accesses.

### [Brick Volume Addressing with If-Else](3340-brick-volume-addressing-with-if-else.md)
Brick Volume Addressing with If-Else computes memory offsets for accessing neighboring samples in a brick-structured volume for resampling or gradient computation. It determines whether adjacent samples lie within the current brick or in a neighboring brick by using explicit conditional checks. Unlike sibling methods that assume a uniform linear layout, this method uses an `if-else` statement to test if needed data elements are within one brick; if true, it uses fast linear addressing, otherwise it falls back to address calculations. It differs from its sibling [Lookup Table Addressing for Resampling](3535-lookup-table-addressing-for-resampling.md) by using runtime `if-else` branches instead of precomputed lookup tables, which incurs pipeline flush penalties but avoids table memory overhead.

### Grid Interpolation with Boundary Handling
A linearly interpolated grid structure used for voxel interpolation (interp5) and image plane interpolation (interp4), handling boundary conditions via constant value filling [S5, unofficial]. It wraps a 2D/3D grid of values into a callable interpolation function, supporting 4th-order (bicubic) and 5th-order interpolation with a specified constant value for out-of-bounds queries [S5, unofficial].
- **Steps:**
  - `interp4`: Map coordinates $x \in [0,1]$ to grid indices: $coords = (x \cdot grid\_res) - 0.5$. Flip coords along last axis. Use `jax.scipy.ndimage.map_coordinates` with order=1 and `cval` [S5, unofficial].
  - `interp5`: Map coordinates $x$ to grid indices: $coords = (x \cdot (grid\_res+1)) - 1$. Permute x and y axes using matrix $\begin{bmatrix} 0 & 1 & 0 \\ 1 & 0 & 0 \\ 0 & 0 & 1 \end{bmatrix}$. Use `jax.scipy.ndimage.map_coordinates` with order=1 and `cval` [S5, unofficial].
  - Initialize `Grid2` with `grid_vals` and `cval`. Return lambda function calling `interp4` or `interp5` [S5, unofficial].
- **Parameters:** `grid_vals`: `jnp.ndarray`, the voxel points to interpolate between. `cval`: float, constant value to fill past edges, default 0 [S5, unofficial].
- **Code:**
  ```python
  grid_obj = Grid2(grid_vals = grid, cval=cval)
  predict_interp = lambda x: grid_obj.interp5(x)
  return predict_interp
  ```

### VIPER Cell Sampling with Extrapolation Flag Invalidation
A cell sampling technique that uses tri-linear interpolation at ray entry and exit points to check if target values lie within the cell range, combined with vertex flags to invalidate cells containing extrapolated data [S7, unofficial].
- **Steps:**
  1. Interpolate data values at the exact points where a ray enters and exits a grid cell [S7, unofficial].
  2. Compare target values to the interpolated entry and exit values to determine if they lie within the cell [S7, unofficial].
  3. Check the eight vertices of the cell for a flag value (positive or negative) [S7, unofficial].
  4. If any vertex contains the flag value, ignore the cell and continue rendering [S7, unofficial].
  5. During data placement, set a flag at each grid node that receives data [S7, unofficial].
  6. After placement completes, assign a value equal to twice the largest data value found to all nodes with an unset flag [S7, unofficial].
  7. Write the twice-maximum value to the data file so VIPER can read it during rendering [S7, unofficial].
- **Pitfalls:**
  - Tri-linear interpolation across cells containing extrapolated data (unset flags) may produce a range that falsely contains a target value [S7, unofficial].
  - A-buffering delays knowledge of the largest data value until all points are processed, whereas Z-buffering finds it during placement [S7, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample, as it involves a fixed number of 8 memory accesses and arithmetic operations regardless of grid size.
- **Memory Complexity:** $O(1)$ auxiliary memory per sample, plus the storage for the grid itself.
- **Performance:** Highly efficient on modern GPUs due to coalesced memory access patterns when sampling batches of points, especially when optimized with SIMD instructions [S3, unofficial].
- **Strengths:** Simple to implement, differentiable (enabling gradient-based optimization in neural rendering), and provides smooth $C^0$ continuity [S1, S2, S5, unofficial].
- **Limitations:** Memory consumption scales cubically with resolution for dense grids, making it unsuitable for very large volumes without sparse structures like bricks or octrees [S1, S4, unofficial]. Accuracy is limited to linear interpolation, which may blur high-frequency details compared to higher-order splines [S6, unofficial].
- **When to Use:** When sampling dense, fixed-resolution voxel grids for neural rendering, medical imaging, or real-time volume visualization where performance and differentiability are prioritized over extreme memory efficiency [S1, S2, S4, S5, unofficial].
- **When Not to Use:** For very large scenes where memory bandwidth is a bottleneck and sparse representations (like Octrees or VDB) are more appropriate, or when higher-order continuity is required [S1, S6, unofficial].

## Background
The method originates from the fundamental requirements of volume rendering and voxel-based data visualization, where continuous ray casting requires sampling discrete grid data [S1, S3, S4, unofficial]. It is widely used in modern neural rendering frameworks (such as Plenoxels and RTNF) as a differentiable layer for optimizing voxel grids [S2, S5, unofficial]. Variants like `iso_corners_list_f1v4` and VIPER cell sampling extend the core concept to handle specific GPU kernel optimizations and extrapolation safety checks in scientific visualization [S1, S7, unofficial].
