# Ghost Cell Stitching for Node-Centered AMR

Also called: Ghost Cell Stitching

## Overview
Ghost Cell Stitching is a technique for handling Adaptive Mesh Refinement (AMR) data in visualization frameworks by marking coarse cells that are refined at a lower level as "ghost" cells [S1, S3, unofficial]. This method allows structured grids to retain their native form, enabling proper trilinear interpolation at patch boundaries and hanging nodes without converting the data into an unstructured grid [S1, S3, unofficial]. It is specifically designed for node-centered AMR data, where both sides of a level boundary form structured node-centered grids that naturally lend to trilinear interpolation [S2, unofficial]. By preserving the structured layout, it avoids the memory overhead and interpolation artifacts associated with removing refined cells or creating unstructured meshes [S1, S3, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
- AMR dataset consisting of multiple patches (boxes) at various refinement levels.
- Simulation-derived abutment information describing how boxes connect [S4].
- Scalar field values associated with grid nodes or cells.

**Outputs:**
- A structured grid representation where boundary cells are augmented with "ghost" cells.
- A ghost flag array marking each cell as non-ghost, boundary ghost, or invalidation ghost [S4].
- Stitch cells (in the context of isosurface extraction) that bridge coarse and fine levels [S4].

### Data Structures
1.  **Ghost Flag Array**: An array of flags, one per grid cell, specifying whether the cell is a ghost cell. If flagged as ghost, the flag also specifies the type:
    -   **Boundary Ghost**: Cells added to provide surrounding data for interpolation or stitch cell generation [S4].
    -   **Invalidation Ghost**: Cells marked as invalid because a more accurate data representation (finer level) is available [S4].
2.  **BoxAbutment**: A data structure where `BoxAbutment[B]` lists the boxes $B_0, B_1, \dots, B_{n-1}$ that box $B$ abuts with, along with the locations of those abutments. This includes abutment for boxes at the same refinement level and nesting for boxes at different refinement levels [S4].
3.  **BoxToProcessingElement**: A map indicating which processing element (PE) each box resides on, used for parallel communication [S4].

### Steps
The method involves generating ghost data to fill boundaries between patches and levels, followed by visualization processing, and finally cleanup.

1.  **Initialize (Parallel Setup)**:
    -   Each processing element identifies which boxes it has loaded.
    -   Processing elements exchange information to create the `BoxToProcessingElement` map [S4].

2.  **Pack (Message Construction)**:
    -   Every processing element iterates over the boxes it owns.
    -   For each box $B$, determine its abutting patches $B_i$ using `BoxAbutment[B]`.
    -   For each $B_i$, extract one layer of cells in the abutment region.
    -   Convert this layer into a message containing the destination box, the data, and the location of that data on the destination patch.
    -   Append this message to the overall message buffer for the processing element designated by `BoxToProcessingElement[B_i]` [S4].

3.  **Exchange (Communication)**:
    -   Each processing element sends its messages to others.
    -   This is typically implemented using an MPI `Alltoallv` command [S4].

4.  **Unpack (Ghost Cell Population)**:
    -   Every processing element extends its boxes with ghost cells using the incoming messages.
    -   The values in these ghost cells must satisfy specific conditions to ensure consistent stitch cell generation [S4]:
        -   **Domain Boundaries**: If a ghost cell coincides with the boundary of the domain, no ghost data is needed [S4].
        -   **Adjacent Box Values**: If a ghost cell coincides with the cell of an adjacent box in the same level, the ghost cell is filled with the value from that adjacent box [S4].
        -   **Coarse Parent Values**: If no neighboring box overlapping the ghost cell exists in the same level, the ghost cell is filled with the value from the cell it refines in the parent level ($i-1$). Since a level is always completely contained in its parent level, such a cell always exists [S4].
        -   **Level Dependency**: When generating ghost data for a box in level $i$, only data from level $i$ and parent level $i-1$ are considered. Data from finer levels ($>i$) is ignored [S4].
    -   A single layer of ghost cells around a box is always sufficient to determine appropriate stitch cell vertex values [S4].

5.  **Visualization Processing**:
    -   Most algorithms operate identically on ghost and non-ghost cells, ignoring the ghost markings during processing [S1, S3, unofficial].
    -   The ghost flag array is used by visualization algorithms (e.g., Marching Cubes) to blank out ghost cells, preventing artifacts like cracked isosurfaces at hanging nodes [S1, unofficial][S4].

6.  **Cleanup**:
    -   After all algorithms have been applied, a module walks the data set and removes all cells or geometry resulting from a ghost cell [S1, S3, unofficial].

### Pseudocode
```python
def generate_ghost_cells(boxes, BoxAbutment, BoxToProcessingElement, my_pe):
    """
    Generates ghost cells for AMR data in a parallel environment.
    """
    # Phase 1: Initialize
    # BoxToProcessingElement is assumed to be pre-computed or exchanged
    
    # Phase 2: Pack
    messages = {} # Map: dest_pe -> list of messages
    
    for box in boxes_owned_by(my_pe):
        abutting_patches = BoxAbutment[box]
        for patch in abutting_patches:
            dest_pe = BoxToProcessingElement[patch]
            if dest_pe not in messages:
                messages[dest_pe] = []
            
            # Extract one layer of cells in the abutment region
            ghost_data = extract_boundary_layer(box, patch)
            
            # Create message
            msg = {
                'dest_box': patch,
                'data': ghost_data,
                'location': get_abutment_location(box, patch)
            }
            messages[dest_pe].append(msg)

    # Phase 3: Exchange
    # In MPI, this would be Alltoallv. Here we simulate the receipt.
    received_messages = exchange_alltoallv(messages)

    # Phase 4: Unpack
    for box in boxes_owned_by(my_pe):
        for msg in received_messages.get(my_pe, []):
            if msg['dest_box'] == box:
                fill_ghost_cells(box, msg['data'], msg['location'])

def fill_ghost_cells(box, data, location):
    """
    Fills ghost cells in a box based on specific rules.
    """
    for cell in location:
        if is_domain_boundary(cell):
            continue # No ghost data needed for domain boundaries
        
        if is_adjacent_box_cell(cell):
            # Fill with value from adjacent box
            value = get_value_from_adjacent_box(cell)
        else:
            # Fill with value from parent level
            parent_cell = get_parent_cell(cell)
            value = get_value(parent_cell)
        
        set_value(cell, value)
        mark_as_ghost(cell, type='boundary_ghost')

def process_visualization(grid, ghost_flags):
    """
    Runs visualization algorithms, ignoring ghost cells.
    """
    for cell in grid:
        if ghost_flags[cell] == 'non_ghost':
            process_cell(cell)
        # Ghost cells are processed identically but results are ignored/blanked

def cleanup(grid, ghost_flags):
    """
    Removes ghost cells after processing.
    """
    for cell in grid:
        if ghost_flags[cell] != 'non_ghost':
            remove_cell(cell)
```

### Parameters
-   **Ghost Cell Count**: A single layer of ghost cells around a box is always sufficient [S4].
-   **BoxAbutment**: Requires simulation-derived abutment information [S4].

### Edge Cases and Pitfalls
-   **Hanging Nodes**: Without ghost cells, hanging nodes at patch boundaries with different refinement levels cause incorrect interpolation and cracked isosurfaces in algorithms like Marching Cubes [S1, S3, unofficial].
-   **Memory Footprint**: Removing ghost cells before applying visualization algorithms creates an unstructured grid with a memory footprint an order of magnitude larger [S1, S3, unofficial].
-   **Domain Boundaries**: Ghost cells coinciding with the domain boundary do not require data exchange [S4].
-   **Parallel Communication**: The approach requires collective communication (e.g., MPI Alltoallv) and cannot work in an out-of-core setting [S4].

## Operating characteristics
-   **Time Complexity**: The ghost generation phase involves communication proportional to the surface area of the patches. The visualization phase operates in linear time with respect to the number of cells, as most algorithms ignore ghost markings [S1, S3, unofficial].
-   **Memory Complexity**: Maintains the native structured grid memory footprint. Avoids the order-of-magnitude increase associated with unstructured grids [S1, S3, unofficial].
-   **Strengths**: Preserves structured grid efficiency; enables correct trilinear interpolation at hanging nodes; avoids cracked isosurfaces; compatible with existing visualization modules that ignore ghost flags [S1, S3, unofficial][S4].
-   **Limitations**: Requires collective communication (not suitable for out-of-core); depends on simulation code providing abutment information; only works for node-centered AMR where boundaries form structured grids [S2, unofficial][S4].
-   **When to Use**: Node-centered AMR data where crack-free isosurfaces or correct interpolation at patch boundaries is required, and simulation data includes abutment information [S1, unofficial][S4].
-   **When Not to Use**: Cell-centered AMR (requires unstructured mesh geometry for stitching) [S2, unofficial]; out-of-core processing [S4]; when abutment information is unavailable [S4].

## Background
Ghost Cell Stitching was developed as part of the VisIt visualization framework to handle AMR data efficiently [S1, S3, unofficial]. It addresses the challenge of interpolating data at hanging nodes in AMR grids, which previously led to artifacts like cracked isosurfaces in Marching Cubes implementations [S1, S3, unofficial]. The method leverages the fact that for node-centered AMR, both sides of a level boundary form structured node-centered grids, allowing trilinear interpolation to work correctly when ghost cells are introduced [S2, unofficial]. The parallel implementation, described in [S4], uses abutment information from simulation codes to re-create ghost data, incurring lower costs than redistributing the entire dataset [S4].
