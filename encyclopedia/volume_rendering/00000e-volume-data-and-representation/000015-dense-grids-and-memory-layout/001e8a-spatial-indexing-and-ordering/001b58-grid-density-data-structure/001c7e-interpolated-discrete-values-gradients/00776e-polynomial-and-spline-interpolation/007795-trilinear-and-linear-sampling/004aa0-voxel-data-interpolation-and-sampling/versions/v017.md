# Voxel Data Interpolation and Sampling

Also called: Sample Grid, Sample Grid Index, getNextIntersectColor, getNextIntersectionGradient, getNextIntersectionScalar

## Overview
Voxel Data Interpolation and Sampling retrieves scalar values, gradients, and transformed colors at arbitrary 3D positions within a dense volume grid [S1, unofficial]. It solves the problem of converting discrete grid data into continuous fields for ray casting or field evaluation [S2, unofficial]. It differs from its siblings by explicitly supporting both interpolation modes (trilinear, nearest neighbor) and specific transfer function input modes (scalar-only vs. scalar-plus-gradient magnitude) within a unified sampling interface [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Query position $\mathbf{p} = (x, y, z)$ in grid coordinates; grid dimensions $X_{DIM}, Y_{DIM}, Z_{DIM}$; grid data vectors (scalars, gradients); interpolation mode $INTER\_MODE$; transfer function mode $TRN\_MODE$.
*   **Output:** Interpolated scalar value, gradient vector (optional), and transformed color/alpha.

**Data Structures:**
The volume data is stored in two vectors [S1, unofficial]:
1.  `scalars`: `vector<float>` containing density or scalar field values.
2.  `gradients`: `vector<glm::vec3>` containing pre-computed gradient vectors.

The index for a voxel at integer coordinates $(x, y, z)$ is calculated as [S1, unofficial]:
$$ idx = x + (y \cdot X_{DIM}) + (z \cdot X_{DIM} \cdot Y_{DIM}) $$

**Parameters:**
*   $INTER\_MODE$: Controls interpolation. $1$ for trilinear interpolation, $2$ for nearest neighbor [S1, unofficial].
*   $TRN\_MODE$: Controls transfer function input. $1$ for input $(Voxel Value, Voxel Value)$, $2$ for input $(Voxel Value, Gradient Magnitude)$ [S1, unofficial].

**Steps:**
1.  **Boundary Check:** Check if integer coordinates $(x, y, z)$ are within bounds $[0, X_{DIM}-1] \times [0, Y_{DIM}-1] \times [0, Z_{DIM}-1]$. If not, return default value $(0,0,0,0)$ [S1, unofficial].
2.  **Gather Data:**
    *   If $INTER\_MODE = 2$ (Nearest Neighbor): Retrieve scalar $S$ and gradient $\mathbf{G}$ at $(x, y, z)$ using the index formula.
    *   If $INTER\_MODE = 1$ (Trilinear): Retrieve the 8 corner values and gradients of the enclosing voxel. Compute weights based on fractional coordinates $(u, v, w)$ and interpolate $S$ and $\mathbf{G}$ [S1, unofficial]. Note: Some implementations may default to nearest neighbor if trilinear is not fully implemented [S1, unofficial].
3.  **Compute Transfer Function Input:**
    *   If $TRN\_MODE = 1$: Pass $(S, S)$ to the transfer function transformer.
    *   If $TRN\_MODE = 2$: Compute gradient magnitude $M = \|\mathbf{G}\|$. Clamp $M$ to $[0, 1]$. Scale by 256. Pass $(S, M \cdot 256)$ to the transformer [S1, unofficial].
4.  **Transform:** Apply the 1D transfer function to the inputs to obtain color and alpha [S1, unofficial].

## Subtopics

### Sample Grid
High-level node that computes interpolated value at a position [S2, unofficial].

### Sample Grid Index
Low-level access to actual values at integer coordinates [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ for nearest neighbor. $O(1)$ for trilinear (constant 8 samples).
*   **Memory Complexity:** $O(N)$ where $N$ is the number of voxels, storing both scalars and gradients.
*   **Strengths:** Simple implementation; supports gradient-based transfer functions for better material appearance [S1, unofficial].
*   **Limitations:** Pre-computing gradients increases memory usage by 3x (assuming float scalars and vec3 gradients) [S1, unofficial]. Trilinear interpolation may not be fully implemented in all versions [S1, unofficial].
*   **When to use:** When ray casting requires smooth scalar fields and gradient-based opacity control.

## Background
This method originates from a student project for CSE-333 Computer Graphics (2020) implementing volume ray casting [S1, unofficial]. It was designed to support 1D transfer functions and optional gradient-based opacity. The concepts of "Sample Grid" and "Sample Grid Index" are also present in modern geometry node systems like Blender's, where they facilitate field evaluation on voxel grids [S2, unofficial].
