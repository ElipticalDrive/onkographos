# Hermite Interpolation of Scalar Fields

Also called: C1-continuous Hermite Interpolation, Hermite Interpolation

## Overview
Hermite interpolation of scalar fields reconstructs a globally $C^1$-continuous scalar function from discrete samples by storing both function values and their partial derivatives at grid vertices [S1, unofficial]. Unlike linear or bilinear interpolation which yields $C^0$ continuity, this method uses cubic basis functions to ensure smooth gradients across cell boundaries [S1, unofficial]. It serves as a storage-efficient replacement for normal mapping in rendering, as the stored derivatives can directly provide shading normals without additional texture memory [S1, unofficial].

## How it works
**Inputs:**
- A regular grid of scalar values $f(\mathbf{x})$.
- Partial derivatives $\frac{\partial f}{\partial x}, \frac{\partial f}{\partial y}, \frac{\partial f}{\partial z}$ at each grid vertex. In rendering applications, these derivatives often correspond to surface normals already computed for the discrete field [S1, unofficial].
- A query point $\mathbf{p}$ within a grid cell.

**Outputs:**
- The interpolated scalar value $V(\mathbf{p})$.
- The gradient $\nabla V(\mathbf{p})$, which provides the exact surface normal for shading [S1, unofficial].

**Data Structures:**
Each grid vertex stores a tuple $(f, \partial_x f, \partial_y f, \partial_z f)$. For 3D fields, mixed partial derivatives ($\partial_{xy}f, \partial_{xz}f, \partial_{yz}f$) may be approximated if higher-order continuity or specific surface patch requirements are needed, akin to Adini's method for parametric surface patches [S1, unofficial].

**Algorithm:**
1.  **Locate Cell:** Identify the grid cell containing $\mathbf{p}$. Let the cell corners be indexed $i,j,k \in \{0,1\}$ along axes $x,y,z$.
2.  **Normalize Coordinates:** Compute local coordinates $u, v, w \in [0,1]$ representing the position of $\mathbf{p}$ within the cell relative to the corner $(0,0,0)$.
3.  **Compute Basis Functions:** For each dimension, compute the cubic Hermite basis functions. For a local coordinate $t \in [0,1]$:
    $$ H_0(t) = 2t^3 - 3t^2 + 1 $$
    $$ H_1(t) = t^3 - 2t^2 + t $$
    $$ H_2(t) = -2t^3 + 3t^2 $$
    $$ H_3(t) = t^3 - t^2 $$
    These correspond to value, derivative at start, value at end, and derivative at end, respectively.
4.  **Interpolate Value:** The interpolated value $V(\mathbf{p})$ is the tensor product of the 1D Hermite interpolants along each axis. For a 3D cell, this involves summing over all 8 corners and 24 derivative terms (3 per corner):
    $$ V(\mathbf{p}) = \sum_{i=0}^1 \sum_{j=0}^1 \sum_{k=0}^1 \left( H_{0,i}(u) H_{0,j}(v) H_{0,k}(w) f_{ijk} + H_{1,i}(u) H_{0,j}(v) H_{0,k}(w) \partial_x f_{ijk} + \dots \right) $$
    Where $H_{0,i}(u)$ is $H_0(u)$ if $i=0$ else $H_2(u)$, and $H_{1,i}(u)$ is $H_1(u)$ if $i=0$ else $H_3(u)$.
5.  **Compute Gradient (Optional):** The gradient $\nabla V(\mathbf{p})$ is computed by differentiating the basis functions with respect to $u,v,w$ and scaling by the grid spacing. These exact normals are used for shading [S1, unofficial].

**Parameters:**
- Grid spacing: Determines the scaling of derivative values if they are not normalized.
- Order: Typically cubic (3rd order) for $C^1$ continuity [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Mixed Derivatives:** For 3D first-order fields, mixed partial derivatives are not naturally stored in basic Hermite interpolation. An approximation akin to Adini's method is required if these are needed for higher fidelity [S1, unofficial].
- **Boundary Conditions:** Derivatives at domain boundaries must be consistent with the interior to maintain global $C^1$ continuity.
- **Precision:** Cubic evaluation is more sensitive to floating-point precision than linear interpolation, though generally stable [S1, unofficial].

```python
def hermite_basis(t):
    """
    Returns (H0, H1, H2, H3) for cubic Hermite interpolation.
    H0: value at 0
    H1: derivative at 0
    H2: value at 1
    H3: derivative at 1
    """
    t2 = t * t
    t3 = t2 * t
    h0 = 2 * t3 - 3 * t2 + 1
    h1 = t3 - 2 * t2 + t
    h2 = -2 * t3 + 3 * t2
    h3 = t3 - t2
    return h0, h1, h2, h3

def interpolate_hermite_3d(p, grid_data, grid_spacing):
    """
    Interpolate scalar field at point p using Hermite interpolation.
    grid_data: dict or array storing (value, dx, dy, dz) at each vertex.
    grid_spacing: float, distance between grid vertices.
    """
    # 1. Locate cell
    # Assuming p is within bounds and grid is regular
    x, y, z = p
    ix = int(x / grid_spacing)
    iy = int(y / grid_spacing)
    iz = int(z / grid_spacing)
    
    # Local coordinates u, v, w in [0, 1]
    u = (x - ix * grid_spacing) / grid_spacing
    v = (y - iy * grid_spacing) / grid_spacing
    w = (z - iz * grid_spacing) / grid_spacing
    
    # 2. Compute basis functions
    h0_u, h1_u, h2_u, h3_u = hermite_basis(u)
    h0_v, h1_v, h2_v, h3_v = hermite_basis(v)
    h0_w, h1_w, h2_w, h3_w = hermite_basis(w)
    
    value = 0.0
    
    # 3. Sum over 8 corners
    for i in range(2):
        for j in range(2):
            for k in range(2):
                # Select basis functions for this corner
                # For i=0: use h0_u for value, h1_u for dx
                # For i=1: use h2_u for value, h3_u for dx
                val_u = h0_u if i == 0 else h2_u
                dx_u = h1_u if i == 0 else h3_u
                val_v = h0_v if j == 0 else h2_v
                dy_v = h1_v if j == 0 else h3_v
                val_w = h0_w if k == 0 else h2_w
                dz_w = h1_w if k == 0 else h3_w
                
                # Get data at corner (ix+i, iy+j, iz+k)
                # Data structure: (f, df_dx, df_dy, df_dz)
                # Note: Mixed derivatives are not included in basic 3D Hermite
                # as per standard implementation, though Adini's method approximates them [S1, unofficial]
                data = grid_data[ix+i, iy+j, iz+k]
                f = data[0]
                df_dx = data[1]
                df_dy = data[2]
                df_dz = data[3]
                
                # Tensor product expansion
                # Term for value
                term_val = val_u * val_v * val_w * f
                
                # Term for dx derivative
                # The derivative df_dx is scaled by grid_spacing if stored as raw derivative
                # Assuming df_dx is d/dx, so no scaling needed for the basis weight
                term_dx = dx_u * val_v * val_w * df_dx
                
                # Term for dy derivative
                term_dy = val_u * dy_v * val_w * df_dy
                
                # Term for dz derivative
                term_dz = val_u * val_v * dz_w * df_dz
                
                value += term_val + term_dx + term_dy + term_dz
                
    return value
```

## Subtopics

### Floating Scale Surface Reconstruction (FSSR) Integration
In the context of Floating Scale Surface Reconstruction (FSSR), Hermite interpolation is used to improve the continuity of the reconstructed surface. The original FSSR weighting function is not $C^1$-continuous. To fix this, the weighting function is replaced with $w(r) = \frac{1}{12} (r - 3)^{12} (r + 1)^4$, which ensures $C^1$ continuity [S2]. This integration improves mean and RMS error and visual appearance compared to quadratic methods, although maximum error can remain large [S2].

## Operating characteristics
- **Continuity:** Guarantees global $C^1$ continuity, unlike linear interpolation which is $C^0$ [S1, unofficial].
- **Storage:** Requires storing 4 values (1 scalar + 3 derivatives) per vertex instead of 1. However, in rendering, if normals are already stored, the storage cost is effectively zero for the derivatives, merely changing the basis [S1, unofficial].
- **Performance:** Cubic evaluation is more computationally expensive than linear interpolation but provides smoother shading and geometry [S1, unofficial].
- **Accuracy:** Provides richer visual appearance and better geometric fidelity than linear or bilinear methods [S1, unofficial]. In FSSR, cubic interpolation improves mean and RMS error [S2].

## Background
Hermite interpolation of scalar fields was proposed as a technique for real-time computer graphics, specifically for rendering height fields and signed distance fields [S1, unofficial]. It generalizes the concept of storing derivatives with function values to arbitrary orders and dimensions [S1, unofficial]. The method is particularly useful in sphere tracing and implicit volume rendering where smooth normals are critical for shading [S1, unofficial]. It has also been applied in surface reconstruction algorithms like Poisson Surface Reconstruction (PSR) and FSSR to improve the quality of reconstructed surfaces from point clouds and scanner data [S2].
