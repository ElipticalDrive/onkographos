# Voxel Trilinear Interpolation (SIMD)

Also called: SIMD Trilinear Sampling, Trilinear Interpolation with AVX, Trilinear Volume Interpolation, Trilinear Voxel Interpolation

## Overview
Voxel Trilinear Interpolation (SIMD) retrieves scalar or vector values from a 3D volume grid at arbitrary floating-point coordinates by interpolating the eight corner values of the enclosing voxel cell using Single Instruction, Multiple Data (SIMD) instructions [S1, S3, S5, unofficial]. It sets itself apart from standard scalar trilinear interpolation by processing multiple volume samples or vector components in parallel within a single CPU instruction cycle, significantly increasing throughput for dense volume rendering or marching cubes applications [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume data array (dense grid or brick), query coordinates $(u, v, w)$, and volume dimensions.
*   **Output:** The interpolated value (scalar or vector) at the query point.

**Data Structures:**
*   **Volume Data:** Stored in a 1D array in row-major order. For a brick of size $(B_x, B_y, B_z)$, the data size is $(B_x+1) \times (B_x+1) \times (B_z+1)$ elements [S3, unofficial].
*   **Strides:** Linear indexing uses strides: $x_{next} = B_x + 1$, $y_{next} = B_x + 1$, $z_{next} = (B_x + 1) \times (B_y + 1)$ [S3, unofficial].
*   **SIMD Registers:** 128-bit registers (e.g., AVX `__m128`) used to hold multiple float components or bytes for parallel arithmetic [S3, unofficial].

**Numbered Steps:**
1.  **Coordinate Normalization:** Convert world or normalized coordinates to relative positions within the brick or grid. If using normalized coordinates $(u,v,w) \in [0,1]$, scale by grid dimensions to get physical indices [S1, S3, unofficial].
2.  **Index Calculation:** Compute the integer grid indices $(i_x, i_y, i_z)$ and fractional offsets $(f_x, f_y, f_z)$:
    $$ i_x = \lfloor u \cdot (N_x - 1) \rfloor, \quad f_x = u \cdot (N_x - 1) - i_x $$
    (Similarly for $y$ and $z$) [S1, S2, S3, unofficial].
3.  **Boundary Clamping:** Clamp indices to valid ranges $[0, N-1]$ to prevent out-of-bounds access. If the query point is outside the volume bounds, return 0 or a default value [S2, S3, unofficial].
4.  **Corner Fetching:** Calculate the linear base index for the lower corner $(i_x, i_y, i_z)$ and fetch the 8 corner values:
    $$ \text{idx} = i_z \cdot z_{next} + i_y \cdot y_{next} + i_x \cdot x_{next} $$
    Values: $v_{000}, v_{100}, v_{010}, v_{110}, v_{001}, v_{101}, v_{011}, v_{111}$ [S3, S4, unofficial].
5.  **SIMD Weight Preparation:** Broadcast fractional coordinates into SIMD registers.
    *   $w_x = f_x$
    *   $w_y = f_y$
    *   $w_z = f_z$
    *   Compute complementary weights: $1-w_x, 1-w_y, 1-w_z$ [S3, unofficial].
6.  **Parallel Interpolation:**
    *   Load corner values into SIMD registers.
    *   Perform bilinear interpolation on the bottom face ($z=0$) and top face ($z=1$) using X and Y weights.
    *   Interpolate between the bottom and top results using the Z weight.
    *   *Optimization:* Use horizontal adds and shuffles to minimize register moves [S3, unofficial].
7.  **Final Value:** Return the interpolated scalar or vector component.

**Formulas:**
The standard trilinear interpolation formula for a scalar value $V$ is:
$$ V = \sum_{i,j,k \in \{0,1\}} v_{ijk} \cdot (1-f_x)^{1-i} f_x^i \cdot (1-f_y)^{1-j} f_y^j \cdot (1-f_z)^{1-k} f_z^k $$
Where $v_{ijk}$ are the 8 corner values and $f_x, f_y, f_z$ are the fractional coordinates [S3, unofficial].

**Pseudocode:**
```python
import math

def voxel_trilinear_simd(volume_data, dims, brick_size, u, v, w):
    """
    Performs SIMD-optimized trilinear interpolation.
    volume_data: 1D list/array of floats.
    dims: (Nx, Ny, Nz) grid dimensions.
    brick_size: (Bx, By, Bz) brick dimensions.
    u, v, w: Query coordinates in [0, 1].
    """
    # 1. Normalize and scale to grid indices
    # Note: dims might differ from brick_size if sub-sampling. 
    # Assuming u,v,w are normalized to the full grid dims.
    scale_x = dims[0] - 1
    scale_y = dims[1] - 1
    scale_z = dims[2] - 1
    
    pos_x = u * scale_x
    pos_y = v * scale_y
    pos_z = w * scale_z
    
    # 2. Integer indices and fractional parts
    ix = int(math.floor(pos_x))
    iy = int(math.floor(pos_y))
    iz = int(math.floor(pos_z))
    
    fx = pos_x - ix
    fy = pos_y - iy
    fz = pos_z - iz
    
    # 3. Boundary Clamping
    # Clamp to [0, N-1] for indices, but for interpolation we need neighbors up to N-1
    # If point is outside, return 0.0
    if ix < 0 or iy < 0 or iz < 0 or ix >= dims[0] or iy >= dims[1] or iz >= dims[2]:
        return 0.0
    
    # Clamp indices for fetching. 
    # For trilinear, we need indices up to N-1. 
    # If ix == N-1, we clamp ix+1 to N-1 (repeating edge) or handle as boundary.
    # Standard clamping for volume rendering often repeats edge or clamps to N-2 for valid cell.
    # Here we follow [S2, unofficial] clamping to [0, N-1].
    x0 = max(0, min(ix, dims[0] - 1))
    x1 = max(0, min(ix + 1, dims[0] - 1))
    y0 = max(0, min(iy, dims[1] - 1))
    y1 = max(0, min(iy + 1, dims[1] - 1))
    z0 = max(0, min(iz, dims[2] - 1))
    z1 = max(0, min(iz + 1, dims[2] - 1))
    
    # 4. Calculate Strides and Base Index
    # Assuming row-major: x is fastest, then y, then z
    stride_x = 1
    stride_y = dims[0]
    stride_z = dims[0] * dims[1]
    
    base_idx = z0 * stride_z + y0 * stride_y + x0 * stride_x
    
    # 5. Fetch 8 Corners
    # v000: (x0, y0, z0)
    # v100: (x1, y0, z0)
    # v010: (x0, y1, z0)
    # v110: (x1, y1, z0)
    # v001: (x0, y0, z1)
    # v101: (x1, y0, z1)
    # v011: (x0, y1, z1)
    # v111: (x1, y1, z1)
    
    v000 = volume_data[base_idx]
    v100 = volume_data[base_idx + stride_x]
    v010 = volume_data[base_idx + stride_y]
    v110 = volume_data[base_idx + stride_y + stride_x]
    v001 = volume_data[base_idx + stride_z]
    v101 = volume_data[base_idx + stride_z + stride_x]
    v011 = volume_data[base_idx + stride_z + stride_y]
    v111 = volume_data[base_idx + stride_z + stride_y + stride_x]
    
    # 6. SIMD-style Interpolation (Simulated with scalar ops for clarity, 
    # but structured to show parallel weight application)
    # Weights
    w_x = fx
    w_y = fy
    w_z = fz
    w_x_inv = 1.0 - w_x
    w_y_inv = 1.0 - w_y
    w_z_inv = 1.0 - w_z
    
    # Interpolate along X for bottom face (z0)
    # v00 = (1-fx)*v000 + fx*v100
    # v10 = (1-fx)*v010 + fx*v110
    v00 = w_x_inv * v000 + w_x * v100
    v10 = w_x_inv * v010 + w_x * v110
    
    # Interpolate along X for top face (z1)
    # v01 = (1-fx)*v001 + fx*v101
    # v11 = (1-fx)*v011 + fx*v111
    v01 = w_x_inv * v001 + w_x * v101
    v11 = w_x_inv * v011 + w_x * v111
    
    # Interpolate along Y for bottom and top
    # v0 = (1-fy)*v00 + fy*v10
    # v1 = (1-fy)*v01 + fy*v11
    v0 = w_y_inv * v00 + w_y * v10
    v1 = w_y_inv * v01 + w_y * v11
    
    # Interpolate along Z
    # final = (1-fz)*v0 + fz*v1
    final = w_z_inv * v0 + w_z * v1
    
    return final
```

**Parameters:**
*   **Block Dimensions:** In GPU implementations (CUDA), block dimensions are often fixed, e.g., `BLOCK_SIZE = 8`, resulting in `threads = {8, 8, 8}` (512 threads per block) [S2, unofficial].
*   **Grid Dimensions:** Calculated based on the number of points $N_p$ and maximum threads per axis (e.g., `MAX_THREADS_AXIS = 128`) [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Indices must be clamped to `[0, nGrids.dim - 1]` to prevent out-of-bounds memory access [S2, unofficial]. If any index component is less than 0 or greater than or equal to dimensions, return 0.0f [S3, unofficial].
*   **Precision:** Using `float` (32-bit) is standard. For higher precision, `double` may be used, but SIMD throughput decreases.
*   **Degenerate Input:** If the volume data is empty or dimensions are zero, handle gracefully by returning 0 or raising an error.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query point, as it involves a fixed number of arithmetic operations and memory accesses regardless of grid size.
*   **Memory Complexity:** $O(N)$ for the volume data, where $N$ is the number of voxels.
*   **Measured Performance:** SIMD implementations (e.g., AVX) can process multiple samples or vector components in parallel, significantly reducing latency compared to scalar implementations. Specific throughput depends on CPU architecture and data alignment [S3, unofficial].
*   **Scaling:** Scales linearly with the number of query points. Parallelization (SIMD, GPU) is highly effective.
*   **Strengths:** Smooth interpolation, efficient memory access patterns (coalesced in GPU, cache-friendly in CPU), high throughput with SIMD.
*   **Limitations:** Limited to linear continuity (G0). Artifacts may appear at low resolutions. Boundary handling requires care.
*   **When to Use:** Dense volume rendering, marching cubes, real-time visualization where smoothness is required.
*   **When Not to Use:** Sparse data (use SVO), high-frequency details requiring higher-order interpolation (use tricubic).

## Background
Voxel trilinear interpolation is a fundamental technique in volume rendering and computer graphics for sampling dense 3D grids. The SIMD optimization leverages CPU vector instructions (like AVX) to accelerate the interpolation process, which is a bottleneck in real-time applications. The method is widely used in tools like `torchmcubes` for marching cubes on GPU [S2, unofficial], and in parallel volume renderers [S3, unofficial].
