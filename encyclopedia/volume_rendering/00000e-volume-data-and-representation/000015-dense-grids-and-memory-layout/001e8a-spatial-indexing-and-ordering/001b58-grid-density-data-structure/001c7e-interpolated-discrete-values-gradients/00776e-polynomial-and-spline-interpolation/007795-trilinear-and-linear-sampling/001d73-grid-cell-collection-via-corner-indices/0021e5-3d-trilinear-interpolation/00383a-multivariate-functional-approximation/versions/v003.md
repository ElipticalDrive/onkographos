# Multivariate Functional Approximation

Also called: Functional approximation

## Overview
Multivariate Functional Approximation (MFA) is a continuous volume representation method that models 3D scalar fields using polynomial functions, specifically B-splines, defined over micro-blocks of the data grid [S1, unofficial]. It solves the problem of accurate off-grid sample evaluation and smooth shading in volume rendering by providing higher-order continuity than trilinear interpolation without requiring ghost voxels or boundary padding [S1, unofficial]. Unlike its sibling [3D Trilinear Interpolation](2613-3d-trilinear-interpolation.md), which is limited to C0 continuity and linear accuracy, MFA approximates C1 continuity across partition boundaries, reducing Mach ringing artifacts and polygon counts in isosurface extraction while maintaining a compact data footprint [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field dataset of resolution $n^3$, partitioned into micro-blocks [S1, unofficial].
*   **Output:** A set of micro-models, each containing control points and knot vectors defining a trivariate polynomial function for its respective micro-block [S1, unofficial].

**Data Structures:**
The core data structure is the **Micro-model** [S1, unofficial]. It stores the parameters required to evaluate the B-spline function [S1, unofficial].
*   **Fields:**
    *   `degree` (integer): The polynomial order of the fitted B-spline [S1, unofficial].
    *   `NCP` (integer): The Number of Control Points [S1, unofficial].
    *   `ControlPoints` (array): A 3D array of control point values [S1, unofficial].
    *   `Knots` (tuple): Three knot vectors (one per axis) defining the B-spline basis functions [S1, unofficial].
*   **Storage Size:** The file size of a single micro-model in bytes is calculated as [S1, unofficial]:
    $$Size(Micro\text{-}model) = 1 + ((NCP + degree) \times 3 + NCP^3) \times 4$$

**Parameters:**
*   **NCP (Number of Control Points):** The primary determinant of encoded model size and fitting accuracy [S1, unofficial]. The valid range for a micro-block of resolution $n^3$ is $[degree+1, n]$ [S1, unofficial]. A larger NCP yields higher fitting accuracy but increases storage and query time [S1, unofficial]. The optimal NCP for a given error bound is data-dependent and may require exhaustive search [S1, unofficial].
*   **Degree:** The polynomial order of the fitted B-spline [S1, unofficial]. Higher degrees increase continuity and accuracy but also computational cost [S1, unofficial].

**Algorithm Steps:**
1.  **Partitioning:** Divide the input 3D dataset into micro-blocks [S1, unofficial]. For multi-resolution frameworks, this may involve $m$ Levels of Detail (LODs), where the number of micro-blocks increases twofold along each axis ($x, y, z$) from LOD $i$ to $i+1$ [S1, unofficial].
2.  **Fitting:** For each micro-block, fit a multivariate polynomial (B-spline) to the scalar values within the block [S1, unofficial]. Select `degree` and `NCP` based on desired accuracy and size constraints [S1, unofficial]. Solve for control points and knots to minimize global error [G]. This step has a time complexity of $O(n^4)$ for a 3D dataset of resolution $n^3$ across all possible NCP values [S1, unofficial].
3.  **Encoding:** Store the resulting `degree`, `NCP`, control points, and knots in the Micro-model structure [S1, unofficial].
4.  **Querying (Rendering):** To evaluate a sample point $P$ within a micro-block: identify the micro-block containing $P$ [S1, unofficial]. Evaluate the trivariate B-spline function using the stored control points, knots, and degree at $P$ [S1, unofficial]. Return the interpolated value [S1, unofficial]. This allows random access to both value and derivative with high-order accuracy [S1, unofficial].

**Pseudocode:**
```python
def bspline_basis_1d(i, k, t, x):
    """Standard Cox-de Boor recursion for B-spline basis function [G]."""
    if k == 0:
        return 1.0 if t[i] <= x < t[i+1] else 0.0
    left = (x - t[i]) / (t[i+k-1] - t[i]) if t[i+k-1] != t[i] else 0.0
    right = (t[i+k] - x) / (t[i+k] - t[i+1]) if t[i+k] != t[i+1] else 0.0
    return left * bspline_basis_1d(i, k-1, t, x) + right * bspline_basis_1d(i+1, k-1, t, x)

def evaluate_mfa_micro_model(point, micro_model):
    """Evaluates the scalar value at a given 3D point using a pre-fitted MFA micro-model [S1, unofficial]."""
    x, y, z = point
    degree = micro_model['degree']
    ncp = micro_model['NCP']
    cp = micro_model['control_points']
    knots_x, knots_y, knots_z = micro_model['knots']
    val = 0.0
    for i in range(ncp):
        for j in range(ncp):
            for l in range(ncp):
                val += cp[i][j][l] * bspline_basis_1d(i, degree+1, knots_x, x) * \
                             bspline_basis_1d(j, degree+1, knots_y, y) * \
                             bspline_basis_1d(l, degree+1, knots_z, z)
    return val
```

**Edge Cases and Pitfalls:**
*   **Encoding Time:** For large-scale datasets ($n$ large) with multiple LODs ($m$ large), the total encoding time $O(8^m \cdot n^4)$ can become impractical [S1, unofficial]. Adaptive encoding methods are required to mitigate this [S1, unofficial].
*   **Query Bottleneck:** Query time is the main performance bottleneck for visualizing large-scale datasets using MFA [S1, unofficial].
*   **Boundary Continuity:** While MFA approximates C1 continuity, it does not guarantee it strictly without careful knot placement and control point selection [S1, unofficial].

## Subtopics

### [Trivariate Cubic Polynomial Approximation for Scalar Fields](14573-trivariate-cubic-polynomial-approximation-for-scalar-fields.md)
This variant models 3D scalar field data (e.g., CT/MRI) by approximating subcubes of a cuberille volume with trivariate cubic polynomial functions that achieve C1 continuity on shared faces. It provides a compact analytic representation for isosurface generation, distinguishing itself from lower-order approximations by avoiding polygon shading artifacts like Mach ringing.

### C3 Data Approximation
A method for approximating volume data using C3 data, yielding polygonal isosurfaces [S2, unofficial]. It offers two approximation types: (1,1,1) and (3,3,3) [S2, unofficial].
*   **(1,1,1) Approximation:** Yields a C0 smooth approximation [S2, unofficial]. It is faster to calculate but produces more polygons (e.g., 121,486 polygons for a sphere test data) [S2, unofficial].
*   **(3,3,3) Approximation:** Yields at least C1 smooth approximation [S2, unofficial]. It takes much longer to calculate but produces fewer polygons (e.g., 78,741 polygons for the same sphere test data) [S2, unofficial].
*   **Output Structure:** Each polygon has three to six vertices with XYZ coordinate values and a normal associated with each vertex [S2, unofficial].

## Operating characteristics
*   **Time Complexity:**
    *   Encoding: $O(n^4)$ for a 3D dataset of resolution $n^3$ across all possible NCP values [S1, unofficial].
    *   Multi-resolution Encoding: Total time for $m$ LODs is $O(8^m \cdot n^4)$ [S1, unofficial].
    *   Querying: Not explicitly given, but noted as the main performance bottleneck [S1, unofficial].
*   **Memory Complexity:** Determined by the Micro-model size: $1 + ((NCP + degree) \times 3 + NCP^3) \times 4$ bytes per micro-block [S1, unofficial].
*   **Measured Performance:**
    *   In isosurface extraction, (3,3,3) C3 approximation reduced polygon count from 121,486 to 78,741 for a sphere test data compared to (1,1,1) [S2, unofficial].
    *   (3,3,3) calculation takes much longer than (1,1,1) for the same image size [S2, unofficial].
*   **Strengths:**
    *   Higher accuracy for off-grid sample evaluation than trilinear interpolation [S1, unofficial].
    *   Approximates C1 continuity without ghost voxels, reducing data size overhead [S1, unofficial].
    *   Reduces Mach ringing artifacts in rendering [S1, unofficial].
    *   Compact analytic representation [S1, unofficial].
*   **Limitations:**
    *   High encoding time for large datasets [S1, unofficial].
    *   Query time is a bottleneck [S1, unofficial].
    *   Optimal NCP is data-dependent and may require exhaustive search [S1, unofficial].
*   **When to Use:** Suitable for interactive visualization of large-scale scientific datasets where rendering quality (smoothness, accuracy) is critical and encoding can be done offline or adaptively [S1, unofficial].
*   **When Not to Use:** When real-time encoding is required for very large datasets, or when memory bandwidth is severely constrained and the overhead of storing control points is prohibitive [S1, unofficial].

## Background
MFA was introduced as a method for in situ modeling of scientific data, providing random access to value and derivative with high-order accuracy [S1, unofficial]. It addresses the limitations of traditional local filters like trilinear interpolation in distributed visualization pipelines [S1, unofficial]. The method is particularly relevant for structured or unstructured grids with non-linear spatial correlations [S1, unofficial]. The C3 data approximation variant was explored in the context of scalar field modeling and visualization on parallel architectures like the Intel Delta [S2, unofficial].
