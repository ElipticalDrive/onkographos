# Mipmap Grid Query

Also called: Distance-based Mipmap Selection, AABB-relative Mipmap Query

## Overview
Mipmap Grid Query retrieves values from a hierarchical grid structure by selecting a mip level based on the spatial distance of the query point from the center of the base axis-aligned bounding box (AABB). It solves the problem of adaptive resolution sampling in dense grids, ensuring that points far from the center use coarser representations while points near the center use the finest resolution. It differs from [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md) by dynamically selecting the grid resolution based on distance rather than fixed cell geometry, and from [Nearest Voxel Lookup with Periodic Boundary](1573-nearest-voxel-lookup-with-periodic-boundary.md) by using a hierarchical mip-chain rather than a single periodic grid.

## How it works
**Inputs:**
- `x`: Tensor of shape $[N, 3]$ containing $N$ query points in world space [S1, unofficial].
- `data`: Tensor of shape $[m, R_x, R_y, R_z]$ containing the mip-chain of grid values, where $m$ is the number of mip levels and $R_x, R_y, R_z$ are the resolutions of the base level [S1, unofficial].
- `base_aabb`: Tensor of shape $[6]$ defining the bounding box $[min_x, min_y, min_z, max_x, max_y, max_z]$ of the base level grid [S1, unofficial].

**Data Structures:**
- The `data` tensor is assumed to be a mip-chain where each subsequent level is a 2x downsampled version of the previous one. The source assumes the AABBs of multiple grids are 2x scaled relative to the base [S1, unofficial].

**Steps:**
1.  **Normalize Coordinates:** Transform query points `x` from world space to normalized space $[0, 1]$ relative to `base_aabb`.
    $$ x_{norm} = \frac{x - base\_aabb[0:3]}{base\_aabb[3:6] - base\_aabb[0:3]} $$
2.  **Compute Distance Metric:** Calculate the maximum absolute distance from the center $(0.5, 0.5, 0.5)$ in the normalized coordinates.
    $$ maxval = \max(|x_{norm} - 0.5|) $$
    Clamp `maxval` to a minimum of $0.1$ to avoid numerical issues with the exponent calculation (specifically to prevent `frexpf` from returning an exponent of 0 for very small values) [S1, unofficial].
3.  **Determine Mip Level:** Compute the mip level index using the floating-point exponent of `maxval`.
    $$ level = \lfloor \log_2(maxval) \rfloor + 1 $$
    In implementation, this is often done using `frexp` or bit manipulation on the exponent. The level is clamped to a minimum of $0$ [S1, unofficial].
4.  **Select Valid Mip:** Create a boolean selector for mips where $level < data.shape[0]$. If the computed level exceeds the available mip levels, the query should return zero or handle the out-of-bounds case [S1, unofficial].
5.  **Re-normalize for Selected Mip:** Adjust the normalized coordinates to match the resolution of the selected mip level. Since each mip level is 2x smaller, the coordinates must be scaled.
    $$ x_{mip} = x_{norm} \times 2^{level} $$
    Note: The source describes re-normalizing to $[0, 1]$ using a scale factor of $2^{level}$. This implies the coordinates are effectively expanded to cover the larger domain of the coarser grid, or the grid indices are computed directly from this scaled value.
6.  **Map to Grid Indices:** Convert the scaled coordinates to integer grid indices using the base resolution $R$.
    $$ idx = \lfloor x_{mip} \times R \rfloor $$
    Clamp indices to the range $[0, R - 1]$ [S1, unofficial].
7.  **Query and Return:** Retrieve the value from `data[level]` at `idx`. If the mip level was invalid (out of bounds), return 0. Otherwise, return the queried value [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Precision:** Clamping `maxval` to 0.1 is critical to prevent `log2` or `frexp` from producing extreme exponents for points very close to the center, which could result in negative mip levels or underflow [S1, unofficial].
-   **Boundaries:** Points outside the `base_aabb` will have normalized coordinates $> 1$ or $< 0$. The re-normalization step $x_{mip} = x_{norm} \times 2^{level}$ can push indices far outside the grid bounds. Clamping indices to $[0, R-1]$ is required [S1, unofficial].
-   **Degenerate Input:** If `base_aabb` has zero extent, division by zero occurs. This is not handled in the source notes [G].

## Subtopics

### Ripmap Encoding with Tetra-Linear Interpolation
A 4D interpolation method used in Rip-NeRF to query feature values from Ripmaps (R) based on position $(p_x, p_y)$ and level $(l_x, l_y)$. It uses tetra-linear interpolation over 16 neighboring vertices in the 4D space to handle the anisotropic nature of the Gaussian footprint [S2]. Given a query point $(p_x, p_y, l_x, l_y)$, it identifies 16 neighboring vertices $(p_{xi}, p_{yj}, l_{xk}, l_{ym})$ where $i,j,k,m \in \{0,1\}$. The feature value $f$ is computed as a weighted sum: $f = \sum_{i,j,k,m} w_{ijklm} f_{ijklm}$, where $f_{ijklm} = R_{l_x^k, l_y^m}(p_{xi}, p_{yj})$ and the weight $w_{ijklm} = \prod_{d \in \{x,y\}} \prod_{t \in \{p,l\}} (1 - |t_d - t_{d,i,j}|)$ [S2]. The Ripmap R has a shape of $512 \times 512 \times 16$, corresponding to 10 unparalleled icosahedron faces [S2]. This method allows efficient querying while considering anisotropic Gaussian footprints [S2].

## Operating characteristics
-   **Time Complexity:** $O(1)$ per query point, assuming constant-time arithmetic and array access. The computation involves normalization, log/exp operations, and a single grid lookup.
-   **Memory Complexity:** $O(m \cdot R_x R_y R_z)$ to store the mip-chain.
-   **Performance:** Efficient for large scenes where adaptive resolution is needed. The use of `frexp` or bit manipulation for level selection is fast [S1, unofficial].
-   **Strengths:** Provides smooth transitions between resolutions based on spatial distance. Simple to implement.
-   **Limitations:** The distance-based selection may not align perfectly with view-dependent aliasing requirements compared to more complex anti-aliasing methods. It assumes a regular 2x downsampling hierarchy [S1, unofficial].
-   **When to use:** When querying dense grids with a known hierarchical structure and where distance from the center is a good proxy for required resolution.
-   **When not to use:** When the grid does not have a regular 2x mip-chain structure or when view-dependent sampling is required (e.g., use [Ripmap Encoding with Tetra-Linear Interpolation](#ripmap-encoding-with-tetra-linear-interpolation) for 4D anisotropic cases).

## Background
Mipmap Grid Query is a technique used in volume rendering and neural radiance fields to manage memory and computational cost by adapting the resolution of grid queries based on the query point's location. It is implemented in libraries such as `nerfacc` [S1, unofficial]. The method relies on the assumption that mip levels are 2x scaled relative to the base AABB [S1, unofficial].
