# Mipmap Grid Query

Also called: Grid Value Query with Mip-Mapping, Mipmap Level Selection via Frexp, _query mip selection

## Overview
Mipmap Grid Query retrieves scalar values from a multi-resolution grid hierarchy by selecting a mip level based on the spatial distance of the query point from the center of the base bounding box [S2, S3, unofficial]. It solves the problem of aliasing and resolution mismatch in dense volume rendering by automatically downscaling the query resolution as the point moves further from the center, assuming a geometric scaling relationship between mip levels [S2, S3, unofficial]. It differs from standard trilinear interpolation by dynamically adjusting the grid resolution used for the lookup based on spatial context rather than a fixed user-defined level [G]. Builds on [Interpolated Discrete Values & Gradients](1268-interpolated-discrete-values-gradients.md).

## How it works
**Inputs and Outputs:**
- Input `x`: A tensor of shape $[N, 3]$ containing $N$ query points [S2, S3, unofficial].
- Input `data`: A tensor of shape $[m, res_x, res_y, res_z]$ containing the grid values for $m$ mip levels [S2, S3, unofficial].
- Input `base_aabb`: A tensor of shape $[6]$ representing the axis-aligned bounding box of the base level grid, formatted as $[min_x, min_y, min_z, max_x, max_y, max_z]$ [S2, S3, unofficial].
- Output: A tensor of shape $[N]$ containing the queried values [S2, S3, unofficial].

**Data Structures:**
The method assumes the `data` tensor is organized such that the first dimension indexes the mip level [S2, S3, unofficial]. The spatial dimensions correspond to the resolution of that specific mip level [G]. The relationship between mip level $l$ and resolution is typically $res_{x,l} = res_x / 2^l$, though the implementation handles this via coordinate scaling [S2, S3, unofficial].

**Algorithm Steps:**
1. **Normalize Coordinates:** Transform the query points `x` from world coordinates to the normalized range $[0, 1]$ relative to the `base_aabb` [S2, S3, unofficial].
   $$ x_{norm} = \frac{x - aabb_{min}}{aabb_{max} - aabb_{min}} $$
   where $aabb_{min} = [min_x, min_y, min_z]$ and $aabb_{max} = [max_x, max_y, max_z]$ [S2, S3, unofficial].

2. **Compute Distance Metric:** Calculate the maximum absolute deviation of the normalized coordinates from the center $(0.5, 0.5, 0.5)$ [S1, S2, S3, unofficial].
   $$ maxval = \max(|x_{norm} - 0.5|) $$
   Clamp $maxval$ to a minimum value of $0.1$ to prevent numerical instability in the subsequent floating-point decomposition (specifically, to avoid an exponent of $0$ in `frexp`) [S1, S2, S3, unofficial].

3. **Determine Mip Level:** Compute the mip level index $l$ using the exponent of the floating-point representation of $maxval$ [S1, S2, S3, unofficial].
   $$ l = \text{exponent}(maxval) + 1 $$
   Clamp $l$ to a minimum of $0$ [S1, S2, S3, unofficial].

4. **Re-normalize for Selected Mip:** Adjust the normalized coordinates to align with the resolution of the selected mip level $l$ [S3, unofficial].
   $$ scale = 2^l $$
   $$ x_{unit} = \frac{x_{norm} - 0.5}{scale} + 0.5 $$
   This maps the query point into the coordinate space of the lower-resolution grid [S3, unofficial].

5. **Map to Grid Indices:** Convert the re-normalized coordinates $x_{unit}$ to integer grid indices $i_x, i_y, i_z$ using the base resolution scaled by the mip level [S3, unofficial].
   $$ resolution = \text{shape}(data)[1:] $$
   $$ i = \lfloor x_{unit} \cdot resolution \rfloor $$
   Clamp the indices $i$ to the valid range $[0, resolution - 1]$ [S3, unofficial].

6. **Query and Return:** Retrieve the value from the `data` tensor at the computed mip level and indices [S2, S3, unofficial]. A selector mask handles out-of-bounds mip levels [S2, S3, unofficial].
   $$ selector = (l < m) $$
   $$ result = data[l, i_x, i_y, i_z] \cdot selector $$

**Pseudocode:**
```python
import torch

def mipmap_grid_query(x: torch.Tensor, data: torch.Tensor, base_aabb: torch.Tensor) -> torch.Tensor:
    """Query values from a mipmap grid hierarchy.
    
    Args:
        x: Tensor of shape [N, 3], query points.
        data: Tensor of shape [m, res_x, res_y, res_z], grid values.
        base_aabb: Tensor of shape [6], [min_x, min_y, min_z, max_x, max_y, max_z].
        
    Returns:
        Tensor of shape [N], queried values.
    """
    # 1. Normalize coordinates to [0, 1]
    aabb_min = base_aabb[:3]
    aabb_max = base_aabb[3:]
    x_norm = (x - aabb_min) / (aabb_max - aabb_min)
    
    # 2. Compute maxval: max absolute distance from center (0.5)
    maxval = torch.max(torch.abs(x_norm - 0.5), dim=1).values
    
    # Clamp to avoid frexp exponent 0
    maxval = torch.clamp(maxval, min=0.1)
    
    # 3. Compute mip level using frexp exponent + 1, clamped to min 0
    mantissa, exponent = torch.frexp(maxval)
    mip = torch.clamp(exponent + 1, min=0)
    
    # 4. Create selector for valid mips
    num_mips = data.shape[0]
    selector = (mip < num_mips)
    
    # Clamp mip to max available index for safe indexing
    mip = torch.clamp(mip, max=num_mips - 1)
    
    # 5. Re-normalize points to [0, 1] using scale factor 2^mip
    scale = 2.0 ** mip[:, None]  # Shape [N, 1]
    x_unit = (x_norm - 0.5) / scale + 0.5
    
    # 6. Map normalized points to grid indices
    base_res = torch.tensor(data.shape[1:], device=x.device, dtype=torch.float32)
    res_current = base_res / scale.squeeze(1)  # Shape [N, 3]
    
    ix = (x_unit * res_current).long()
    
    # Clamp indices to valid range [0, res - 1]
    ix = torch.clamp(ix, min=0, max=res_current.long() - 1)
    
    # 7. Query values
    ix_x = ix[:, 0]
    ix_y = ix[:, 1]
    ix_z = ix[:, 2]
    
    values = data[mip, ix_x, ix_y, ix_z]
    
    # Apply selector
    result = values * selector.float()
    
    return result
```

**Parameters:**
- `x`: Tensor of shape $[N, 3]$ [S2, S3, unofficial].
- `data`: Tensor of shape $[m, res_x, res_y, res_z]$ [S2, S3, unofficial].
- `base_aabb`: Tensor of shape $[6]$ [S2, S3, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** The use of `frexp` and floating-point division can introduce precision errors for points very close to the boundaries or the center [G]. Clamping `maxval` to $0.1$ prevents `frexp` from returning an exponent that would lead to an invalid mip level calculation for points near the center [S1, S2, S3, unofficial].
- **Boundaries:** Points outside the `base_aabb` will have normalized coordinates outside $[0, 1]$. The re-normalization step may map these to invalid grid indices [G]. Clamping indices to $[0, res-1]$ handles this, but the semantic meaning of the query is undefined for out-of-bounds points [G].
- **Degenerate Input:** If `base_aabb` has zero volume (min equals max), division by zero occurs [G]. This must be checked and handled before normalization [G].

## Subtopics

### Ripmap Encoding with Tetra-Linear Interpolation
A 4D interpolation method used in Rip-NeRF to query feature values from Ripmaps (R) based on position $(p_x, p_y)$ and level $(l_x, l_y)$ [S4]. It uses tetra-linear interpolation over 16 neighboring vertices in the 4D space [S4]. Given a query point $(p_x, p_y, l_x, l_y)$, the 16 neighboring vertices are identified with binary indices $i, j, k, m \in \{0, 1\}$ [S4]. The feature value $f$ is computed as a weighted sum: $f = \sum_{i=0}^1 \sum_{j=0}^1 \sum_{k=0}^1 \sum_{m=0}^1 w_{ijklm} f_{ijklm}$, where $f_{ijklm} = R_{l_x^k, l_y^m}(p_x^i, p_y^j)$ is the feature value at the neighboring vertex, and $w_{ijklm} = \prod_{d \in \{x,y\}} \prod_{t \in \{p,l\}} (1 - |t_d - t_{d,i,j}|)$ is the interpolation weight [S4]. The Ripmap R has a shape of $512 \times 512 \times 16$, corresponding to 10 unparalleled icosahedron faces [S4]. This method allows for efficient querying while considering the anisotropic nature of the Gaussian footprint [S4].

## Operating characteristics
- **Time Complexity:** $O(N)$ for $N$ query points, with constant overhead per point for coordinate transformations and indexing [G].
- **Memory Complexity:** $O(m \cdot res_x \cdot res_y \cdot res_z)$ to store the mipmap grid [G].
- **Performance:** Efficient for large-scale volume rendering as it reduces the number of active voxels queried for distant points [G]. The use of integer indexing and simple arithmetic operations makes it fast on GPU hardware [G].
- **Strengths:** Automatic level-of-detail selection based on spatial context; reduces aliasing; simple implementation [G].
- **Limitations:** Assumes a strict 2x scaling relationship between mip levels; may not be optimal for scenes with non-uniform detail distribution; boundary handling requires careful clamping [G].
- **When to use:** Dense volume rendering with hierarchical grid data where spatial coherence is high and detail varies with distance from the center [G].
- **When not to use:** Scenes with highly anisotropic or non-uniform detail distribution that does not follow the 2x scaling assumption; when precise control over the level of detail is required independent of spatial position [G].

## Background
Mipmap Grid Query is a technique used in modern neural radiance field (NeRF) implementations, particularly those involving dense grid representations and anti-aliasing [S2, S3, unofficial]. It is closely related to the mipmapping strategies used in computer graphics to manage texture resolution [G]. The specific implementation described here is found in the `nerfacc` library [S2, unofficial] and the `CNC` repository [S3, unofficial].
