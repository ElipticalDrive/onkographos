# Mipmap Grid Query
## Overview
Mipmap Grid Query retrieves values from a hierarchical grid structure by selecting a mip level based on the spatial distance of the query point from the center of the base axis-aligned bounding box (AABB) [S1, unofficial]. It solves the problem of adaptive resolution sampling in dense grids, ensuring that points far from the center use coarser representations while points near the center use the finest resolution [S1, unofficial].

## How it works
**Inputs:**
- `x`: Tensor of shape $[N, 3]$ containing $N$ query points in world space [S1, unofficial].
- `data`: Tensor of shape $[m, R_x, R_y, R_z]$ containing the mip-chain of grid values, where $m$ is the number of mip levels and $R_x, R_y, R_z$ are the resolutions of the base level [S1, unofficial].
- `base_aabb`: Tensor of shape $[6]$ defining the bounding box $[min_x, min_y, min_z, max_x, max_y, max_z]$ of the base level grid [S1, unofficial].

**Data Structures:**
- The `data` tensor is assumed to be a mip-chain where each subsequent level is a 2x downsampled version of the previous one [S1, unofficial]. The source assumes the AABBs of multiple grids are 2x scaled relative to the base [S1, unofficial].

**Steps:**
1. **Normalize Coordinates:** Transform query points `x` from world space to normalized space $[0, 1]$ relative to `base_aabb` [S1, unofficial].
   $$ x_{norm} = \frac{x - base\_aabb[0:3]}{base\_aabb[3:6] - base\_aabb[0:3]} $$
2. **Compute Distance Metric:** Calculate the maximum absolute distance from the center $(0.5, 0.5, 0.5)$ in the normalized coordinates [S1, unofficial].
   $$ maxval = \max(|x_{norm} - 0.5|) $$
   Clamp `maxval` to a minimum of $0.1$ to avoid numerical issues with the exponent calculation (specifically to prevent `frexpf` from returning an exponent of 0 for very small values) [S1, unofficial].
3. **Determine Mip Level:** Compute the mip level index using the floating-point exponent of `maxval` plus 1 [S1, unofficial].
   $$ level = \lfloor \log_2(maxval) \rfloor + 1 $$
   In implementation, this is done using `frexp` or bit manipulation on the exponent [S1, unofficial]. The level is clamped to a minimum of $0$ [S1, unofficial].
4. **Select Valid Mip:** Create a boolean selector for mips where $level < data.shape[0]$ [S1, unofficial].
5. **Re-normalize for Selected Mip:** Adjust the normalized coordinates to match the resolution of the selected mip level [S1, unofficial]. Since each mip level is 2x smaller, the coordinates must be scaled [S1, unofficial].
   $$ x_{mip} = x_{norm} \times 2^{level} $$
   This implies the coordinates are effectively expanded to cover the larger domain of the coarser grid, or the grid indices are computed directly from this scaled value [S1, unofficial].
6. **Map to Grid Indices:** Convert the scaled coordinates to integer grid indices using the base resolution $R$ [S1, unofficial].
   $$ idx = \lfloor x_{mip} \times R \rfloor $$
   Clamp indices to the range $[0, R - 1]$ [S1, unofficial].
7. **Query and Return:** Retrieve the value from `data[level]` at `idx` [S1, unofficial]. If the mip level was invalid (out of bounds), return 0 [S1, unofficial].

**Pseudocode:**
```python
import torch

def mipmap_grid_query(x: torch.Tensor, data: torch.Tensor, base_aabb: torch.Tensor) -> torch.Tensor:
    # x: [N, 3], data: [m, Rx, Ry, Rz], base_aabb: [6]
    # 1. Normalize points x to [0, 1] range relative to base_aabb
    min_vals = base_aabb[:3]
    max_vals = base_aabb[3:]
    extents = max_vals - min_vals
    x_norm = (x - min_vals) / extents

    # 2. Compute maxval as the maximum absolute distance from 0.5 in normalized coordinates
    dist_from_center = torch.abs(x_norm - 0.5)
    maxval = torch.max(dist_from_center, dim=1, keepdim=True).values
    # Clamp to min 0.1 to avoid frexpf exponent 0
    maxval = torch.clamp(maxval, min=0.1)

    # 3. Compute mip level using frexp exponent plus 1, clamped to min 0
    _, exp = torch.frexp(maxval)
    mip = exp + 1
    mip = torch.clamp(mip, min=0)

    # 4. Create selector for valid mips (mip < data.shape[0])
    num_mips = data.shape[0]
    selector = (mip < num_mips)

    # 5. Re-normalize points to [0, 1] using scale factor 2^mip
    scale = 2.0 ** mip.float()
    x_mip = x_norm * scale

    # 6. Map normalized points to grid indices using resolution, clamping to max resolution - 1
    res = data.shape[1:]  # [resx, resy, resz]
    # Corrected index mapping: scale coordinates by 2^mip, then divide by 2^mip to get base grid indices
    indices = torch.floor(x_norm * torch.tensor(res) / (2 ** mip)).long()
    indices = torch.clamp(indices, min=0, max=torch.tensor(res) - 1)

    # 7. Clamp mip to max data.shape[0] - 1 and return queried values multiplied by selector
    mip_clamped = torch.clamp(mip, max=num_mips - 1)
    values = data[mip_clamped.squeeze(-1), indices[:, 0], indices[:, 1], indices[:, 2]]
    return values * selector.float()
```

**Edge Cases and Pitfalls:**
- **Precision:** Clamping `maxval` to 0.1 is critical to prevent `log2` or `frexp` from producing extreme exponents for points very close to the center, which could result in negative mip levels or underflow [S1, unofficial].
- **Boundaries:** Points outside the `base_aabb` will have normalized coordinates $> 1$ or $< 0$ [S1, unofficial]. The re-normalization step $x_{mip} = x_{norm} \times 2^{level}$ can push indices far outside the grid bounds [S1, unofficial]. Clamping indices to $[0, R-1]$ is required [S1, unofficial].
- **Degenerate Input:** If `base_aabb` has zero extent, division by zero occurs [G].

## Subtopics

### Ripmap Encoding with Tetra-Linear Interpolation
A 4D interpolation method used in Rip-NeRF to query feature values from Ripmaps (R) based on position $(p_x, p_y)$ and level $(l_x, l_y)$ [S2]. It uses tetra-linear interpolation over 16 neighboring vertices in the 4D space to handle the anisotropic nature of the Gaussian footprint [S2]. Given a query point $(p_x, p_y, l_x, l_y)$, it identifies 16 neighboring vertices $(p_{xi}, p_{yj}, l_{xk}, l_{ym})$ where $i,j,k,m \in \{0,1\}$ [S2]. The feature value $f$ is computed as a weighted sum: $f = \sum_{i,j,k,m} w_{ijklm} f_{ijklm}$, where $f_{ijklm} = R_{l_x^k, l_y^m}(p_{xi}, p_{yj})$ and the weight $w_{ijklm} = \prod_{d \in \{x,y\}} \prod_{t \in \{p,l\}} (1 - |t_d - t_{d,i,j}|)$ [S2]. The Ripmap R has a shape of $512 \times 512 \times 16$, corresponding to 10 unparalleled icosahedron faces [S2]. This method allows efficient querying while considering anisotropic Gaussian footprints [S2].
