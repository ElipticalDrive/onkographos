# 3D Trilinear Interpolation

Also called: 3D Linear Interpolation, Trilinear Interpolant, Trilinear Interpolation (General), Trilinear Sampling, Trilinear Voxel Interpolation, Voxel Trilinear Interpolation

## Overview
3D Trilinear Interpolation estimates the value of a scalar field at an arbitrary point $P=(x,y,z)$ within a voxel by linearly interpolating the values at the eight corners of the enclosing grid cell [S1][S2, unofficial][S3, unofficial][S4, unofficial][S5, unofficial][S6, unofficial][S7, unofficial][S8, unofficial]. It solves the problem of sampling dense volume data at sub-voxel resolution, providing smoother results than nearest-neighbor sampling while remaining computationally cheaper than higher-order methods like tricubic interpolation [S2, unofficial][S4, unofficial]. It differs from [VoxelGrid](2159-voxelgrid.md) by providing continuous value estimation rather than discrete cell access, and from [Cubic Volume Interpolation](4278-cubic-volume-interpolation.md) by using only the 8 immediate corner values rather than a larger stencil [S2, unofficial][S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A query point $P = (x, y, z)$ in continuous coordinates; a dense 3D grid of values $V$ with dimensions $N_x \times N_y \times N_z$ (or extent $E$ and origin) [S1][S3, unofficial][S5, unofficial][S6, unofficial][S7, unofficial][S9, unofficial].
*   **Output:** A single interpolated scalar value $F(P)$ [S1][S5, unofficial][S7, unofficial].

**Data Structures:**
The grid is typically stored as a contiguous array or multi-dimensional array [G]. For a rectilinear grid with uniform spacing, the layout is often `data[z][y][x]` or `data[x][y][z]` depending on memory layout conventions (row-major vs column-major) [S3, unofficial]. The values at the eight corners are accessed via integer indices derived from the floor of the query coordinates [S5, unofficial][S6, unofficial][S7, unofficial].

**Numbered Steps:**
1.  **Boundary Check:** If the query point $P$ lies outside the grid bounds ($x < 0$ or $x \ge N_x$, etc.), return a default value (typically 0 or clamped) [S9, unofficial].
2.  **Floor Coordinates:** Compute the integer indices of the minimum corner of the enclosing voxel:
    $$x_0 = \lfloor x \rfloor, \quad y_0 = \lfloor y \rfloor, \quad z_0 = \lfloor z \rfloor$$
    [S5, unofficial][S6, unofficial][S7, unofficial][S8, unofficial].
3.  **Ceiling Coordinates:** Compute the integer indices of the maximum corner:
    $$x_1 = x_0 + 1, \quad y_1 = y_0 + 1, \quad z_1 = z_0 + 1$$
    [S5, unofficial][S6, unofficial].
4.  **Fractional Distances:** Compute the normalized distances (weights) within the voxel for each axis [S8, unofficial]. For uniform grids with unit spacing, this is simply the fractional part of the coordinate [S5, unofficial][S6, unofficial][S8, unofficial]:
    $$t_x = x - x_0, \quad t_y = y - y_0, \quad t_z = z - z_0$$
    If the grid has non-uniform spacing or physical extents, normalize by the voxel size or cell dimensions:
    $$t_x = \frac{x - x_0}{x_1 - x_0}, \quad t_y = \frac{y - y_0}{y_1 - y_0}, \quad t_z = \frac{z - z_0}{z_1 - z_0}$$
    [S7, unofficial][S8, unofficial][S9, unofficial]. Note: $t_x, t_y, t_z \in [0, 1)$.
5.  **Corner Retrieval:** Retrieve the values at the eight corners of the voxel:
    *   $V_{000} = V(x_0, y_0, z_0)$
    *   $V_{100} = V(x_1, y_0, z_0)$
    *   $V_{010} = V(x_0, y_1, z_0)$
    *   $V_{110} = V(x_1, y_1, z_0)$
    *   $V_{001} = V(x_0, y_0, z_1)$
    *   $V_{101} = V(x_1, y_0, z_1)$
    *   $V_{011} = V(x_0, y_1, z_1)$
    *   $V_{111} = V(x_1, y_1, z_1)$
    [S5, unofficial][S6, unofficial][S7, unofficial][S8, unofficial].
6.  **Interpolation:** Perform linear interpolation along the x-axis, then y-axis, then z-axis (or any order, as the operation is commutative) [S3, unofficial][S7, unofficial][S8, unofficial][S9, unofficial].
    *   **X-interpolation:**
        $$C_{00} = V_{000}(1 - t_x) + V_{100}t_x$$
        $$C_{01} = V_{001}(1 - t_x) + V_{101}t_x$$
        $$C_{10} = V_{010}(1 - t_x) + V_{110}t_x$$
        $$C_{11} = V_{011}(1 - t_x) + V_{111}t_x$$
        [S8, unofficial]. Alternatively, grouped by z-level:
        $$V_{y1z0} = V_{010}(1 - t_x) + V_{110}t_x, \quad V_{y0z0} = V_{000}(1 - t_x) + V_{100}t_x$$
        [S3, unofficial].
    *   **Y-interpolation:**
        $$C_0 = C_{00}(1 - t_y) + C_{10}t_y$$
        $$C_1 = C_{01}(1 - t_y) + C_{11}t_y$$
        [S8, unofficial]. Alternatively:
        $$V_{z0} = V_{y0z0}(1 - t_y) + V_{y1z0}t_y$$
        $$V_{z1} = V_{y0z1}(1 - t_y) + V_{y1z1}t_y$$
        [S3, unofficial].
    *   **Z-interpolation (Final Result):**
        $$F(P) = C_0(1 - t_z) + C_1t_z$$
        [S8, unofficial]. Alternatively:
        $$F(P) = V_{z0}(1 - t_z) + V_{z1}t_z$$
        [S3, unofficial].

**Formula:**
The expanded form of the trilinear interpolant is:
$$F(P) = (1-t_z)(1-t_y)(1-t_x)V_{000} + (1-t_z)(1-t_y)t_x V_{100} + (1-t_z)t_y(1-t_x)V_{010} + (1-t_z)t_y t_x V_{110} + t_z(1-t_y)(1-t_x)V_{001} + t_z(1-t_y)t_x V_{101} + t_z t_y(1-t_x)V_{011} + t_z t_y t_x V_{111}$$
[S5, unofficial][S7, unofficial].

This can also be viewed as solving for constants $a \dots h$ in the polynomial $F(P) = a + bx + cy + dz + exy + fxz + gyz + hxyz$ such that it matches the 8 corner values [S1]. However, the recursive linear interpolation method above is the standard implementation [S3, unofficial][S7, unofficial][S8, unofficial].

**Parameters:**
*   **Grid Dimensions:** $N_x, N_y, N_z$ [S1][S9, unofficial].
*   **Voxel Spacing:** $dx, dy, dz$ (often 1.0 for normalized grids) [S6, unofficial][S9, unofficial].
*   **Origin:** The coordinate of the $(0,0,0)$ voxel corner [S6, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Points outside the grid must be handled. Common strategies include clamping to the nearest edge, returning 0, or using periodic boundary conditions [S9, unofficial].
*   **Continuity:** Trilinear interpolation provides $C^0$ continuity along interior faces for properly-oriented rectangular grids [S1]. However, continuity is not guaranteed for curvilinear or arbitrarily oriented cells, and the function may vary depending on which adjacent cell the point is assumed to belong to [S1].
*   **Artifacts:** At large magnification factors, trilinear interpolation can produce "three-dimensional crosses" or diamond-shaped artifacts due to the nature of the kernel [S4, unofficial].
*   **Precision:** When computing fractional parts, ensure that $t_x, t_y, t_z$ are correctly calculated as $x - \lfloor x \rfloor$ to avoid precision errors near integer boundaries [S6, unofficial][S8, unofficial].

**Pseudocode:**
```python
def trilinear_interpolation(grid, x, y, z):
    """
    Performs 3D trilinear interpolation on a dense grid.
    
    Args:
        grid: 3D array-like object with shape (Nx, Ny, Nz).
              Assumed to be indexed as grid[x, y, z] for logical clarity.
        x, y, z: Float coordinates of the query point.
        
    Returns:
        Interpolated scalar value.
    """
    # 1. Boundary Check
    Nx, Ny, Nz = grid.shape
    
    if x < 0 or x >= Nx or y < 0 or y >= Ny or z < 0 or z >= Nz:
        return 0.0  # Default boundary condition [S9, unofficial]

    # 2. Floor Coordinates
    x0 = floor(x)
    y0 = floor(y)
    z0 = floor(z)

    # 3. Ceiling Coordinates
    x1 = x0 + 1
    y1 = y0 + 1
    z1 = z0 + 1

    # 4. Fractional Distances (Weights)
    # For uniform grids with unit spacing, this is simply the fractional part
    tx = x - x0
    ty = y - y0
    tz = z - z0
    
    # If non-uniform, normalize:
    # tx = (x - x0) / (x1 - x0)
    # ty = (y - y0) / (y1 - y0)
    # tz = (z - z0) / (z1 - z0)

    # 5. Corner Retrieval
    # Accessing the 8 corners. Note: Array indexing order depends on memory layout.
    v000 = grid[x0, y0, z0]
    v100 = grid[x1, y0, z0]
    v010 = grid[x0, y1, z0]
    v110 = grid[x1, y1, z0]
    v001 = grid[x0, y0, z1]
    v101 = grid[x1, y0, z1]
    v011 = grid[x0, y1, z1]
    v111 = grid[x1, y1, z1]

    # 6. Interpolation
    
    # X-interpolation
    c00 = v000 * (1 - tx) + v100 * tx
    c01 = v001 * (1 - tx) + v101 * tx
    c10 = v010 * (1 - tx) + v110 * tx
    c11 = v011 * (1 - tx) + v111 * tx

    # Y-interpolation
    c0 = c00 * (1 - ty) + c10 * ty
    c1 = c01 * (1 - ty) + c11 * ty

    # Z-interpolation
    result = c0 * (1 - tz) + c1 * tz

    return result
```

## Subtopics

### [Trilinear Interpolation (Compressed/Linked)](2629-trilinear-interpolation-compressed-linked.md)
This method performs trilinear interpolation on a compressed sparse grid using a links array to map voxel indices to compressed value indices, handling boundary checks via masking or a zero-value hack. It builds on [3D Trilinear Interpolation](2613-3d-trilinear-interpolation.md) by adding a link lookup step that translates grid coordinates to compressed indices while retaining the regular 8-corner neighborhood structure.

### [Trilinear Gradient Interpolation](3470-trilinear-gradient-interpolation.md)
Trilinear Gradient Interpolation computes the gradient or surface normal at an arbitrary point within a voxel by interpolating pre-computed vector values stored at the eight corners of the surrounding unit cube. It solves the problem of obtaining smooth, continuous directional derivatives from discrete grid data, which is essential for shading and ray marching in volume rendering. It differs from standard [3D Trilinear Interpolation](2613-3d-trilinear-interpolation.md) by operating on vector fields rather than scalar values, and from [Cubic Volume Interpolation](4278-cubic-volume-interpolation.md) by using only corner data without higher-order derivative constraints. Trilinear Gradient Interpolation extends standard trilinear interpolation to vector fields.

### [Cubic Volume Interpolation](4278-cubic-volume-interpolation.md)
Cubic Volume Interpolation extends standard 3D trilinear interpolation by replacing linear mixture weights with cubic polynomial weights for each spatial axis. It differs from its parent [3D Trilinear Interpolation](2613-3d-trilinear-interpolation.md) by using cubic mixture weights to determine texture sampling coordinates and interpolation factors.

### [Quantile Interpolation for Uncertain Data](5008-quantile-interpolation-for-uncertain-data.md)
Quantile Interpolation is a technique for interpolating nonparametric probability distributions (PDFs) represented as histograms or Kernel Density Estimates (KDEs) by breaking them into a fixed number of quantiles and interpolating the quantile widths linearly, resulting in a closed-form PDF at the interpolated point with linear time complexity relative to the number of quantiles. It solves the problem of reconstructing uncertain volume data where each grid vertex holds a distribution rather than a scalar, enabling Direct Volume Rendering (DVR) that preserves statistical properties like modality and variance. Unlike convolution-based nonparametric approaches which have exponential time complexity, this method is feasible for real-time DVR reconstruction because its complexity scales linearly with the number of quantiles. It builds on [3D Trilinear Interpolation](2613-3d-trilinear-interpolation.md) by applying the trilinear logic to the widths of quantile intervals rather than scalar values.

### Grid Querying with Interpolation
Querying volume density sigma and color c from feature grids along camera rays using interpolation operators [S19]. It reduces computational burden by replacing trilinear interpolation with linear/bilinear interpolation of vector/matrix factors [S19].

### Majorant Fix for Interpolation
Adjusts the stored maximum density value in each leaf node to account for interpolation artifacts [S20, unofficial]. When interpolating near leaf boundaries, the stencil may sample neighboring leaves with higher values, causing the leaf's stored max to be an underestimate [S20, unofficial]. This function ensures the majorant is a valid upper bound for any interpolated value within the leaf [S20, unofficial]. It iterates over all leaves, computes the interpolation Area of Effect (AoE) bounding box, and updates the leaf's max density based on neighbors [S20, unofficial]. The parameter `order` is 1 for trilinear interpolation [S20, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query point, involving a constant number of arithmetic operations (18 multiplications and 14 additions in the expanded form, or fewer in the recursive form) [S4, unofficial][S6, unofficial][S8, unofficial].
*   **Memory Complexity:** $O(N_x N_y N_z)$ for the dense grid storage [S1][S3, unofficial].
*   **Measured Performance:** Rendering rectilinear grids with trilinear interpolation is faster than curvilinear volumes, where precalculation of coefficients can take ~110 seconds and intersection testing dominates [S1]. Trilinear interpolation uses 8 neighbor points, whereas tricubic interpolation uses 64 points [S4, unofficial].
*   **Strengths:** Simple to implement, computationally efficient, provides smoother results than nearest-neighbor [S4, unofficial][S5, unofficial].
*   **Limitations:** $C^0$ continuity only; artifacts (diamonds) at high magnification [S4, unofficial]; not suitable for irregular or rotated grids without modification [S1].
*   **When to Use:** Standard volume rendering where performance is critical and high-frequency detail is not required [G].
*   **When Not to Use:** When $C^1$ continuity is required (use cubic or higher-order methods) or when dealing with highly irregular/curvilinear grids [S1][S4, unofficial].

## Background
Trilinear interpolation was developed as a standard method for volume rendering of rectilinear and curvilinear grids [S1]. It is a fundamental technique in computer graphics for sampling 3D textures and volume data [S2, unofficial][S3, unofficial][S4, unofficial][S5, unofficial][S6, unofficial][S7, unofficial][S8, unofficial][S9, unofficial]. The method assumes the underlying function varies linearly along lines parallel to the cartesian axes [S1]. It is widely used in direct volume rendering (DVR) and is a component of more complex methods like [Trilinear Gradient Interpolation](3470-trilinear-gradient-interpolation.md) and [Cubic Volume Interpolation](4278-cubic-volume-interpolation.md) [S1][S3, unofficial][S4, unofficial][S11, unofficial].
