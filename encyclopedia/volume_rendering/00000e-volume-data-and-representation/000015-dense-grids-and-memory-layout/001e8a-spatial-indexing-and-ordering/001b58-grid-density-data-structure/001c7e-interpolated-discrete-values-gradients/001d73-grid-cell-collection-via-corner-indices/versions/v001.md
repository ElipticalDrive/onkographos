# Grid Cell Collection via Corner Indices

Also called: 8-Corner Grid Sampling, Trilinear Corner Indexing

## Overview
This method collects the values at the 8 vertices of the grid cell enclosing each input point, providing the raw data required for trilinear interpolation or similar operations [S1, unofficial]. It differs from [Nearest Voxel Lookup with Periodic Boundary](1573-nearest-voxel-lookup-with-periodic-boundary.md) by retrieving all 8 neighbors rather than a single nearest neighbor, enabling smooth gradient-based reconstruction.

## How it works
**Inputs:** A tensor of normalized sample coordinates (shape $[N, 3]$) and a dense grid tensor.
**Outputs:** A tensor of collected corner values (shape $[N, 8, C]$) or indices ready for indexing.

**Data Structures:**
- `normalized_samples`: Float tensor of shape $[N, 3]$ containing $(x, y, z)$ coordinates.
- `grid`: Tensor storing values at grid vertices.

**Steps:**
1. **Compute Bounds:** For each dimension $d \in \{x, y, z\}$, calculate the floor and ceiling indices of the sample coordinates. Let $p_d$ be the coordinate. The indices are $i_{floor} = \lfloor p_d \rfloor$ and $i_{ceil} = \lceil p_d \rceil$.
2. **Generate Combinations:** Form the Cartesian product of the floor/ceil indices for all three dimensions. This yields 8 index tuples $(i_x, i_y, i_z)$ representing the corners of the enclosing voxel.
3. **Reshape:** Flatten the list of corner indices to align with the input points. The resulting tensor has shape $[N \times 8, 3]$.
4. **Boundary Handling:** Apply periodic boundary conditions to any indices that fall outside the valid grid range $[0, D-1]$. The index $i$ is mapped to $i \mod D$.
5. **Indexing:** Use the fixed indices to gather values from the grid tensor.

**Pseudocode:**
```python
import torch

def collect_corner_indices(normalized_samples):
    """
    Collects corner indices for trilinear interpolation.
    Args:
        normalized_samples: Tensor of shape [N, 3] with coordinates in [0, 1] or similar range.
                            Assumes grid dimensions are known or handled in a wrapper.
    Returns:
        indices: Tensor of shape [N*8, 3] containing integer corner indices.
    """
    # 1. Compute floor and ceil for each dimension
    # Note: In practice, coordinates must be scaled by grid dimensions before floor/ceil
    # to get actual vertex indices. Assuming normalized_samples are already scaled 
    # to [0, Dim-1] or the function handles scaling externally.
    # Here we assume inputs are already in index space or we scale them.
    # For strict implementation based on [S1]:
    
    # Extract components
    x = normalized_samples[:, 0]
    y = normalized_samples[:, 1]
    z = normalized_samples[:, 2]
    
    # Compute floor and ceil
    floor_x = torch.floor(x)
    ceil_x = torch.ceil(x)
    floor_y = torch.floor(y)
    ceil_y = torch.ceil(y)
    floor_z = torch.floor(z)
    ceil_z = torch.ceil(z)
    
    # 2. Generate all 8 combinations
    # Create lists for each dimension
    x_components = [floor_x, ceil_x]
    y_components = [floor_y, ceil_y]
    z_components = [floor_z, ceil_z]
    
    relevant_points = []
    for xc in x_components:
        for yc in y_components:
            for zc in z_components:
                # Concatenate along the last dimension
                point = torch.stack([xc, yc, zc], dim=1)
                relevant_points.append(point)
    
    # 3. Reshape to flat list
    # Stack all 8 tensors: shape [8, N, 3] -> [N*8, 3]
    all_corners = torch.cat(relevant_points, dim=0)
    
    # 4. Fix out-of-bounds indices (Periodic Boundary)
    # Assuming grid dimensions are passed or known. 
    # If not provided, this step is marked [G].
    # For demonstration, assume grid_size is a tuple (Dx, Dy, Dz)
    # indices = all_corners % torch.tensor(grid_size, device=all_corners.device)
    
    return all_corners.long()
```

**Parameters:**
- Grid dimensions: Not given in the sources.
- Boundary condition: Periodic [S1, unofficial].

**Edge Cases:**
- **Precision:** Floating point errors in coordinate calculation may cause `floor` and `ceil` to be equal for integer coordinates. This is handled naturally by the Cartesian product (duplicate corners will have identical indices).
- **Boundaries:** Indices outside the grid must be wrapped. The source specifies periodic boundary conditions [S1, unofficial].

## Subtopics

### [VoxelGrid](2159-voxelgrid.md)
VoxelGrid is a dense, learnable 3D data structure that represents a parameterized function (such as density and color in neural radiance fields) by storing values at the corners of a regular grid, enabling differentiable trilinear interpolation. It differs from its parent, [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md), by providing a concrete, trainable tensor implementation with automatic boundary clamping, and from [Curvilinear to Rectilinear Resampling](2248-curvilinear-to-rectilinear-resampling.md) by maintaining a fixed, axis-aligned topology rather than mapping irregular coordinates.

### [Curvilinear to Rectilinear Resampling](2248-curvilinear-to-rectilinear-resampling.md)
This method converts a curvilinear input grid (composed of hexahedral cells) into a rectilinear output grid by estimating function values at new sample points. It differs from sibling methods like [VoxelGrid](2159-voxelgrid.md) by explicitly handling the geometric distortion of the input domain, requiring a cell-localization step before interpolation, whereas rectilinear grids assume a fixed, orthogonal topology.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of sample points, as it involves constant-time arithmetic and indexing per point.
- **Memory Complexity:** $O(N)$ to store the 8 indices per point.
- **Strengths:** Simple to implement; provides all necessary data for trilinear interpolation.
- **Limitations:** Requires boundary handling logic; periodic boundaries may introduce artifacts if the grid is not periodic.

## Background
This method is used in implementations of neural radiance fields and dense voxel representations, such as Plenoxels [S1, unofficial]. It serves as the foundational step for sampling values from a grid for subsequent interpolation.
