# Grid Cell Collection via Corner Indices

Also called: 8-Corner Grid Sampling, Trilinear Corner Indexing

## Overview
This method collects the values at the 8 vertices of the grid cell enclosing each input point, providing the necessary data for trilinear interpolation or similar operations. It differs from [Nearest Voxel Lookup with Periodic Boundary](1573-nearest-voxel-lookup-with-periodic-boundary.md) by retrieving all 8 surrounding corners rather than a single nearest neighbor, enabling smooth field evaluation. It serves as the foundational indexing step for [3D Trilinear Interpolation](2613-3d-trilinear-interpolation.md) and its SIMD variant.

## How it works
**Inputs:**
- `samples`: A tensor of shape $[N, 3]$ containing $N$ input points with floating-point coordinates $(x, y, z)$.
- `grid_shape`: A tuple or tensor defining the dimensions of the target grid $(D_x, D_y, D_z)$.
- `periodic`: A boolean flag indicating whether to apply periodic boundary conditions for out-of-bounds indices.

**Outputs:**
- `corner_indices`: A tensor of shape $[N, 8, 3]$ containing the integer indices of the 8 corners for each point.
- `corner_values`: A tensor of shape $[N, 8, C]$ (where $C$ is the channel count) containing the values at those corners, retrieved from the grid.

**Data Structures:**
- The grid is stored as a dense tensor. Indices are 0-based integers.
- Corner indices are stored in a fixed order corresponding to the binary representation of the corner offset: $(i, j, k)$ where $i,j,k \in \{0,1\}$ correspond to floor/ceil respectively.

**Steps:**
1. **Compute Floor and Ceil Coordinates:** For each point $(x, y, z)$, compute the floor and ceil coordinates for each dimension.
   $$
   x_{floor} = \lfloor x \rfloor, \quad x_{ceil} = \lceil x \rceil
   $$
   Repeat for $y$ and $z$.

2. **Generate Corner Combinations:** Create all 8 combinations of $(x_{floor}/x_{ceil}, y_{floor}/y_{ceil}, z_{floor}/z_{ceil})$. This results in a tensor of shape $[N, 8, 3]$.

3. **Reshape and Flatten:** The indices are typically generated as a list of 8 tensors (one per corner) and concatenated along the last dimension to form the $[N, 8, 3]$ structure.

4. **Handle Out-of-Bounds Indices:** If `periodic` is true, apply modulo arithmetic to wrap indices to the grid boundaries. If false, clamp indices to $[0, D-1]$ or handle as an error depending on implementation requirements.
   $$
   idx_{wrapped} = idx \mod D
   $$

5. **Index into Grid:** Use the corrected integer indices to gather values from the grid tensor.

**Pseudocode:**
```python
def collect_corner_indices(samples, grid_shape, periodic=True):
    """
    Collects corner indices for trilinear interpolation.
    
    Args:
        samples: Tensor of shape [N, 3] with float coordinates.
        grid_shape: Tuple (Dx, Dy, Dz) of grid dimensions.
        periodic: Boolean, if True, wrap indices; else clamp.
        
    Returns:
        corner_indices: Tensor of shape [N, 8, 3] with integer indices.
    """
    # Step 1: Compute floor and ceil for each dimension
    # samples shape: [N, 3]
    floor_coords = torch.floor(samples).long()
    ceil_coords = torch.ceil(samples).long()
    
    # Split into x, y, z components
    x_floor = floor_coords[:, 0:1]
    x_ceil = ceil_coords[:, 0:1]
    y_floor = floor_coords[:, 1:2]
    y_ceil = ceil_coords[:, 1:2]
    z_floor = floor_coords[:, 2:3]
    z_ceil = ceil_coords[:, 2:3]
    
    # Step 2: Generate all 8 combinations
    # Order: (floor, floor, floor), (floor, floor, ceil), ..., (ceil, ceil, ceil)
    corners = []
    for x in [x_floor, x_ceil]:
        for y in [y_floor, y_ceil]:
            for z in [z_floor, z_ceil]:
                corners.append(torch.cat([x, y, z], dim=1))
    
    # Stack into [N, 8, 3]
    corner_indices = torch.stack(corners, dim=1)
    
    # Step 3: Handle boundaries
    if periodic:
        # Modulo with grid dimensions
        dims = torch.tensor(grid_shape, device=samples.device).unsqueeze(0).unsqueeze(0) # [1, 1, 3]
        corner_indices = corner_indices % dims
    else:
        # Clamp to [0, D-1]
        corner_indices = torch.clamp(corner_indices, 0, torch.tensor(grid_shape, device=samples.device).long().unsqueeze(0).unsqueeze(0) - 1)
        
    return corner_indices
```

**Parameters:**
- `periodic`: Default `True` in many neural rendering contexts (e.g., Plenoxels) to handle edge cases gracefully [S1, unofficial].

**Edge Cases:**
- **Precision:** Floating-point coordinates exactly on integer boundaries may result in `floor == ceil`. The algorithm handles this naturally as the corner indices will be identical, and interpolation weights will handle the zero-width interval.
- **Out-of-Bounds:** If `periodic` is false and points lie outside the grid, clamping is required to prevent memory access errors [G].

## Subtopics

### [VoxelGrid](2159-voxelgrid.md)
A dense, learnable 3D structure storing values at voxel centers but using corner indices for differentiable trilinear interpolation. It replaces MLPs with a fixed tensor layout.

### [Curvilinear to Rectilinear Resampling](2248-curvilinear-to-rectilinear-resampling.md)
Converts curilinear grids to rectilinear ones. It requires cell localization before interpolation, unlike the fixed topology assumed here.

### [Voxel Trilinear Interpolation (SIMD)](2564-voxel-trilinear-interpolation-simd.md)
Optimizes the sampling kernel using AVX/AVX2 to process two voxel samples in parallel, doubling throughput. It consumes the corner indices produced by this method.

### [3D Trilinear Interpolation](2613-3d-trilinear-interpolation.md)
The standard algorithmic definition of interpolating scalar/vector fields using the 8 corners. It operates on dense memory layouts without link indirection.

### [iso_corners_list_f1v4](2627-iso-corners-list-f1v4.md)
A GPU kernel variant that processes 256 consecutive lattice points per group to maximize thread occupancy, sharing shell setup overhead across neighboring bricks.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of input points. The constant factor is small (8 lookups per point).
- **Memory Complexity:** $O(N)$ to store the corner indices and values.
- **Performance:** Highly efficient on GPUs due to coalesced memory access patterns when points are batched. The SIMD variant [Voxel Trilinear Interpolation (SIMD)](2564-voxel-trilinear-interpolation-simd.md) further accelerates this by packing samples into 128-bit registers.
- **Strengths:** Simple, differentiable, and compatible with dense grid layouts.
- **Limitations:** Requires dense memory allocation for the grid. Not suitable for sparse data without significant overhead.

## Background
This method is fundamental to grid-based neural rendering, particularly in systems like Plenoxels [S1, unofficial]. It enables the replacement of coordinate-based MLPs with fixed, axis-aligned tensor layouts, allowing for efficient differentiable rendering. The approach is widely used in volume rendering and raycasting to achieve smooth transitions between discrete voxel values.
