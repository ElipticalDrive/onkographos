# Voxel Grid Density Estimation with Trilinear Interpolation

Also called: VoxelGrid.density

## Overview
This method estimates the accumulated density and color along a ray by sampling a 3D voxel grid using trilinear interpolation to retrieve values at arbitrary positions, then aggregating these values using a transmittance-based opacity formula. It builds on [Voxel Trilinear Interpolation (SIMD)](2564-voxel-trilinear-interpolation-simd.md) by providing the higher-level logic for ray marching, boundary handling, and final density accumulation. It is distinguished from simpler discrete sampling by producing smooth, "proper cube" boundaries without the lumpy artifacts associated with lower-resolution or non-interpolated representations.

## How it works
**Inputs:**
- `ray_samples_with_distances`: A list or tensor of ray sample positions $(x, y, z)$ and associated distances. In the reference implementation, each sample is a vector containing at least position coordinates, distance to the next sample, density, and color components. Specifically, the code accesses indices 0, 1, 2 for position, 3 for distance ($\delta_i$), 4 for density ($\sigma_i$), and 5 for color ($C_i$).
- `VoxelGrid`: A data structure containing the 3D grid dimensions and stored voxel data.

**Outputs:**
- `density`: A scalar value representing the accumulated color/density contribution along the ray.

**Data Structures:**
The `VoxelGrid` structure contains the following fields [S1, unofficial]:
- `grid_x`, `grid_y`, `grid_z`: Integers defining the dimensions of the voxel grid.
- `default_voxel`: A tensor of shape $[4]$, typically initialized to $[0.005, 0.5, 0.6, 0.7]$. The indices correspond to $[density, R, G, B]$.
- `voxel_grid`: A tensor of shape $[grid\_x, grid\_y, grid\_z, 4]$. The 4 channels correspond to $[density, color\_r, color\_g, color\_b]$. Note: The source code accesses density at index 4 and color at index 5 in the flattened ray sample vector, but the voxel grid itself stores these in indices 0-3.

**Algorithm Steps:**

1.  **Initialization**: Initialize an empty list `collected_voxels` to store interpolated voxel values for each ray sample. Initialize `density = 0`.

2.  **Ray Sampling Loop**: For each ray sample in `ray_samples_with_distances`:
    a.  Extract position $(x, y, z)$ from the sample.
    b.  **Grid Coordinate Calculation**: Determine the integer grid coordinates and their neighbors:
        $$x_0 = \lfloor x \rfloor, \quad x_1 = x_0 + 1$$
        $$y_0 = \lfloor y \rfloor, \quad y_1 = y_0 + 1$$
        $$z_0 = \lfloor z \rfloor, \quad z_1 = z_0 + 1$$
    c.  **Fractional Offset Calculation**: Compute the interpolation weights:
        $$x_d = \frac{x - x_0}{x_1 - x_0}$$
        $$y_d = \frac{y - y_0}{y_1 - y_0}$$
        $$z_d = \frac{z - z_0}{z_1 - z_0}$$
        *Note: If $x_1 - x_0 = 0$ (i.e., $x$ is an integer), the division is undefined. In practice, if $x$ is an integer, $x_d=0$ is used, or the sample is treated as being at the corner. The source code uses `int(x)` which truncates, so for integer inputs, $x_d=0$.*
    d.  **Corner Retrieval**: Retrieve the 8 corner voxel values using `self.at(x, y, z)`. The `at` method checks boundary conditions:
        - If $(x, y, z)$ is outside the grid bounds ($0 \le x < grid\_x$, etc.), return `torch.tensor([0., 0., 0., 0.])`.
        - Otherwise, return `voxel_grid[int(x), int(y), int(z)]`.
        
        Let the retrieved values be $c_{000}$ through $c_{111}$, where the subscripts correspond to $(x_i, y_j, z_k)$ indices.
    e.  **Trilinear Interpolation**:
        - Interpolate along X:
          $$c_{00} = c_{000}(1 - x_d) + c_{100}x_d$$
          $$c_{01} = c_{001}(1 - x_d) + c_{101}x_d$$
          $$c_{10} = c_{010}(1 - x_d) + c_{110}x_d$$
          $$c_{11} = c_{011}(1 - x_d) + c_{111}x_d$$
        - Interpolate along Y:
          $$c_{0} = c_{00}(1 - y_d) + c_{10}y_d$$
          $$c_{1} = c_{01}(1 - y_d) + c_{11}y_d$$
        - Interpolate along Z:
          $$c = c_{0}(1 - z_d) + c_{1}z_d$$
    f.  **Collection**: Append the interpolated vector $c$ to `collected_voxels`.

3.  **Density Accumulation**:
    The source code implements a specific variation of volume rendering integration. It calculates cumulative transmittances and then sums the contribution of each sample.
    
    Let $N$ be the number of samples.
    Let $v_i$ be the voxel vector for sample $i$, where:
    - $v_i[3]$ is the distance to the next sample $\delta_i$.
    - $v_i[4]$ is the density $\sigma_i$.
    - $v_i[5]$ is the color $C_i$.
    
    The code calculates a list of `transmittances` where each entry $T_i$ is the sum of exponentials of previous samples:
    $$T_i = \sum_{j=0}^{i-1} \exp(-\sigma_j \delta_j)$$
    *(Note: This is an additive accumulation of transmittance factors, not the standard multiplicative $T_i = \prod_{j=0}^{i-1} \exp(-\sigma_j \delta_j)$. This appears to be a specific implementation detail or potential bug in the source, but is reproduced here as the defined method.)*
    
    The final density is computed as:
    $$density = \sum_{i=0}^{N-1} T_i \cdot (1 - \exp(-\sigma_i \delta_i)) \cdot C_i$$

**Edge Cases and Pitfalls:**
- **Boundary Handling**: If a sample position is outside the grid bounds, `self.at()` returns a zero tensor `[0., 0., 0., 0.]` [S1, unofficial].
- **Precision**: Integer truncation is used for grid coordinates. If $x$ is an integer, $x_d=0$.
- **Artifacts**: Low sampling rates (e.g., 100 samples) produce banding artifacts known as "onion rings". Increasing the sampling rate (e.g., to 200) resolves this [S1, unofficial].
- **Implementation Discrepancy**: The source code's `channel_opacity` function accesses index 5 for color, but the voxel grid stores color at indices 1-3. The aggregation logic in the source code is inconsistent with the voxel collection logic. The pseudocode above resolves this by using the collected voxel data directly.

## Operating characteristics
- **Time Complexity**: $O(N \cdot M)$ where $N$ is the number of ray samples and $M$ is the number of samples per ray (if marching is included). The interpolation is constant time per sample. The accumulation is linear in the number of samples.
- **Memory Complexity**: $O(grid\_x \cdot grid\_y \cdot grid\_z)$ to store the voxel grid.
- **Performance**: The method produces smooth results ("proper cube") compared to discrete sampling. However, it is sensitive to sampling rate; insufficient samples lead to visible artifacts.
- **Strengths**: Smooth interpolation, simple implementation, handles boundaries gracefully.
- **Limitations**: Memory intensive for high-resolution grids. Artifacts at low sampling rates.
