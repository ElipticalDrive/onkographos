# Grid Cell Collection via Corner Indices

Also called: 8-Corner Grid Sampling, Trilinear Corner Indexing

## Overview
This method collects the values at the 8 vertices of the grid cell enclosing each input point, providing the raw data required for trilinear interpolation or similar operations [S1, unofficial].

## How it works
**Inputs:** A tensor of sample coordinates (shape $[N, 3]$) and a dense grid tensor [S1, unofficial].
**Outputs:** A tensor of collected corner indices (shape $[N \times 8, 3]$) or gathered values [S1, unofficial].

**Data Structures:**
- `samples`: Float tensor of shape $[N, 3]$ containing $(x, y, z)$ coordinates.
- `grid`: Tensor storing values at grid vertices.

**Steps:**
1. For each input point, compute `ceil` and `floor` coordinates for $x$, $y$, $z$ dimensions [S1, unofficial].
2. Generate all 8 combinations of $(\text{ceil}/\text{floor}) \times (\text{ceil}/\text{floor}) \times (\text{ceil}/\text{floor})$ to form the corner indices [S1, unofficial].
3. Reshape the corner indices tensor to a flat list of points [S1, unofficial].
4. Fix out-of-bounds indices using periodic boundary conditions [S1, unofficial].
5. Index into the grid tensor using the fixed indices [S1, unofficial].

**Pseudocode:**
```python
import torch

def collect_corner_indices(samples, grid_size):
    """
    Collects corner indices for trilinear interpolation.
    Args:
        samples: Tensor of shape [N, 3] with coordinates.
        grid_size: Tuple or tensor of grid dimensions [Dx, Dy, Dz].
    Returns:
        indices: Tensor of shape [N*8, 3] containing integer corner indices.
    """
    # 1. Compute floor and ceil for each dimension
    floor_x = torch.floor(samples[:, 0])
    ceil_x = torch.ceil(samples[:, 0])
    floor_y = torch.floor(samples[:, 1])
    ceil_y = torch.ceil(samples[:, 1])
    floor_z = torch.floor(samples[:, 2])
    ceil_z = torch.ceil(samples[:, 2])

    # 2. Generate all 8 combinations
    x_components = [floor_x, ceil_x]
    y_components = [floor_y, ceil_y]
    z_components = [floor_z, ceil_z]

    corners = []
    for xc in x_components:
        for yc in y_components:
            for zc in z_components:
                corners.append(torch.stack([xc, yc, zc], dim=1))

    # 3. Reshape to flat list
    indices = torch.cat(corners, dim=0).type(torch.long)

    # 4. Fix out-of-bounds indices using periodic boundary conditions
    grid_size_tensor = torch.tensor(grid_size, device=indices.device, dtype=torch.long)
    indices = indices % grid_size_tensor

    return indices
```

**Parameters:**
- Grid dimensions: Not given in the sources.
- Boundary condition: Periodic [S1, unofficial].

**Edge Cases:**
- **Precision:** Floating point errors may cause `floor` and `ceil` to be equal for integer coordinates. This is handled naturally by the Cartesian product, as duplicate corners will have identical indices [G].
- **Boundaries:** Indices outside the grid must be wrapped. The source specifies periodic boundary conditions [S1, unofficial].

## Subtopics

### [VoxelGrid](2159-voxelgrid.md)
VoxelGrid is a dense, learnable 3D data structure that represents a parameterized function (such as density and color in neural radiance fields) by storing values at the corners of a regular grid, enabling differentiable trilinear interpolation. It differs from its parent, [Grid Cell Collection via Corner Indices](1518-grid-cell-collection-via-corner-indices.md), by providing a concrete, trainable tensor implementation with automatic boundary clamping, and from [Curvilinear to Rectilinear Resampling](2248-curvilinear-to-rectilinear-resampling.md) by maintaining a fixed, axis-aligned topology rather than mapping irregular coordinates.

### [Curvilinear to Rectilinear Resampling](2248-curvilinear-to-rectilinear-resampling.md)
This method converts a curvilinear input grid (composed of hexahedral cells) into a rectilinear output grid by estimating function values at new sample points. It differs from sibling methods like [VoxelGrid](2159-voxelgrid.md) by explicitly handling the geometric distortion of the input domain, requiring a cell-localization step before interpolation, whereas rectilinear grids assume a fixed, orthogonal topology.
