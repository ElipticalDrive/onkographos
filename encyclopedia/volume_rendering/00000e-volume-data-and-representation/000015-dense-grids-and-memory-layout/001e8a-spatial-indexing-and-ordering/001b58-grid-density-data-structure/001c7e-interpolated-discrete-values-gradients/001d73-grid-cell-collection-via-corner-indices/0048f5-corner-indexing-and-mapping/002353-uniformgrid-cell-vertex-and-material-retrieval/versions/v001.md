# UniformGrid Cell Vertex and Material Retrieval
## Overview
Retrieves the linear indices and associated material values of the 8 vertices defining a specific cell in a uniform 3D grid, given the cell's linear index. It serves as the foundational lookup step for surface extraction algorithms (such as Marching Cubes or FlexiCubes) and trilinear interpolation by mapping topological vertex definitions to the grid's spatial data structure. It differs from its sibling [VoxelGrid](2159-voxelgrid.md) by focusing on the specific arithmetic of linear index derivation for a uniform topology, and from [Cube Edge Vertex Retrieval](3217-cube-edge-vertex-retrieval.md) by returning the 8 corner vertices rather than the 12 edge pairs.
## How it works
**Inputs and Outputs:**
- Input: `cellIdx` (linear index of the cell, integer), `m_size` (grid dimension size, integer).
- Output: `v` (array of 8 linear vertex indices), `materials` (array of 8 material values).

**Data Structures:**
- `v`: Array of 8 integers representing linear indices.
- `materials`: Array of 8 values (type depends on material storage, e.g., float, int).

**Formulas:**
The linear indices of the 8 vertices are derived using stride constants based on the grid size `m_size`. Let $N = m\_size + 1$.
$$
\begin{aligned}
dx &= N \\
dy &= N \times N \\
dz &= 1
\end{aligned}
$$
The vertex indices $v[0]$ through $v[7]$ are calculated as:
$$
\begin{aligned}
v[0] &= cellIdx \\
v[1] &= cellIdx + dz \\
v[2] &= cellIdx + dx \\
v[3] &= cellIdx + dx + dz \\
v[4] &= cellIdx + dy \\
v[5] &= cellIdx + dy + dz \\
v[6] &= cellIdx + dx + dy \\
v[7] &= cellIdx + dx + dy + dz
\end{aligned}
$$
Material retrieval follows the same indexing pattern as vertices, accessing the material array at the computed linear indices.

**Pseudocode:**
```python
def uniform_grid_cell_vertex_and_material_retrieval(cellIdx, m_size, vertex_array, material_array):
    """
    Retrieves linear indices of 8 vertices and their materials for a given cell.
    
    Args:
        cellIdx (int): Linear index of the cell.
        m_size (int): Grid dimension size (assumed cubic, N x N x N).
        vertex_array (list): Pre-allocated list/array of size 8 for output indices.
        material_array (list): Array containing material values indexed by linear vertex index.
        
    Returns:
        tuple: (vertex_array, material_values) where material_values is a list of 8 materials.
    """
    # Calculate stride constants
    # N is the number of vertices along one dimension
    N = m_size + 1
    
    dx = N
    dy = N * N
    dz = 1
    
    # Calculate linear indices for the 8 vertices
    # Order corresponds to standard voxel corner ordering (e.g., LSB to MSB in x,y,z)
    # v[0] = (0,0,0) relative to cell
    # v[1] = (0,0,1) relative to cell -> +dz
    # v[2] = (0,1,0) relative to cell -> +dx
    # v[3] = (0,1,1) relative to cell -> +dx+dz
    # v[4] = (1,0,0) relative to cell -> +dy
    # v[5] = (1,0,1) relative to cell -> +dy+dz
    # v[6] = (1,1,0) relative to cell -> +dx+dy
    # v[7] = (1,1,1) relative to cell -> +dx+dy+dz
    
    vertex_array[0] = cellIdx
    vertex_array[1] = cellIdx + dz
    vertex_array[2] = cellIdx + dx
    vertex_array[3] = cellIdx + dx + dz
    vertex_array[4] = cellIdx + dy
    vertex_array[5] = cellIdx + dy + dz
    vertex_array[6] = cellIdx + dx + dy
    vertex_array[7] = cellIdx + dx + dy + dz
    
    # Retrieve materials using the same indices
    material_values = []
    for i in range(8):
        idx = vertex_array[i]
        # Guard against out-of-bounds if cellIdx is near grid boundary
        # [G] Implementation note: Ensure idx < len(material_array)
        if 0 <= idx < len(material_array):
            material_values.append(material_array[idx])
        else:
            # Handle boundary case: return default or raise error
            # [G] Assuming boundary vertices are valid or handled by caller
            material_values.append(None) 
            
    return vertex_array, material_values
```

**Parameters:**
- `m_size`: The number of cells along one axis. Typical values depend on resolution (e.g., 64, 128, 256).
- `cellIdx`: Must be within the range $[0, m\_size^3 - 1]$.

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** If `cellIdx` refers to a cell on the grid boundary, the calculated vertex indices may exceed the valid range of the vertex/material arrays if the arrays are sized only for internal cells. The vertex array size is $(m\_size+1)^3$. Ensure `cellIdx` is valid for the cell count, not the vertex count.
- **Precision:** Linear indices are integers. No floating-point precision issues in index calculation.
- **Degenerate Input:** `m_size` must be positive. `cellIdx` must be non-negative.

## Subtopics

### [Cube Edge Vertex Retrieval](3217-cube-edge-vertex-retrieval.md)
Retrieves the linear indices of the 12 vertex pairs that define the edges of a specific voxel cube in a uniform grid. It serves as the foundational lookup step for surface extraction algorithms (such as Marching Cubes or FlexiCubes) by mapping topological edge definitions to the grid's spatial data structure. It differs from its parent [UniformGrid Cell Vertex and Material Retrieval](2999-uniformgrid-cell-vertex-and-material-retrieval.md) by focusing specifically on the 12 edges rather than the 8 corner vertices, providing the connectivity required to determine surface intersections.

## Operating characteristics
- **Time Complexity:** $O(1)$ per cell, involving a constant number of arithmetic operations and array accesses.
- **Memory Complexity:** $O(1)$ auxiliary space for the 8 vertex indices and materials.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales linearly with the number of cells processed, but each cell lookup is independent and constant time.
- **Strengths:** Simple arithmetic, no branching for index calculation, cache-friendly if cells are processed sequentially.
- **Limitations:** Requires uniform grid topology. Not applicable to non-uniform or hierarchical grids without modification.
- **When to use:** Surface extraction (Marching Cubes), trilinear interpolation, gradient computation in uniform grids.
- **When not to use:** Non-uniform grids, sparse grids, or when only edge connectivity is needed (use [Cube Edge Vertex Retrieval](3217-cube-edge-vertex-retrieval.md)).

## Background
Originated in the context of isosurface extraction from uniform volumetric data. The method is implemented in the `isomesh` library by Svenny [S1, unofficial]. It provides a direct mapping from cell topology to vertex indices in a linearized memory layout.
