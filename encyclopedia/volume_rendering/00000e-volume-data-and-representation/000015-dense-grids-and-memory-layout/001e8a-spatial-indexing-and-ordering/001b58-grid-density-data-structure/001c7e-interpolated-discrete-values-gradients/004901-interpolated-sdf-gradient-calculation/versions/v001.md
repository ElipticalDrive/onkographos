# Interpolated SDF Gradient Calculation


## Overview
Calculates the gradient of a Signed Distance Field (SDF) at a continuous position within a 4x4x4 voxel block by interpolating gradients computed at the 8 corners of the block. It differs from nearest-neighbor gradient lookup by providing smooth, continuous derivatives essential for stable ray marching and normal estimation, while operating on a fixed local block size rather than a single voxel.

## How it works
**Inputs and Outputs:**
- Input: A `VoxelBuffer` containing SDF data, and a continuous 3D position `p`.
- Output: A 3D gradient vector $\nabla f(p)$.

**Data Structures:**
- `VoxelBuffer`: A 1D span of SDF values. The SDF channel supports 8-bit (`int8_t`), 16-bit (`int16_t`), or 32-bit (`float`) depths.
- Block Size: Fixed at $4 \times 4 \times 4$ voxels.
- Strides: To access adjacent voxels in the 1D span, the jump strides are defined as:
  - $j_x = 1$
  - $j_y = 4$
  - $j_z = 16$

**Steps:**
1. **Block Selection:** Determine the 4x4x4 block centered at `floor(p) - 1`. This block covers the range from `floor(p)` to `floor(p) + 2` in all dimensions. Extract the SDF channel data as a `Span<const TSd>`.
2. **Fractional Position:** Compute the fractional part of the position within the block:
   $$ pf = p - \lfloor p \rfloor $$
   where $pf \in [0, 1)^3$.
3. **Corner Gradient Calculation:** Compute the raw gradient at each of the 8 corners of the 4x4x4 block. The corners are indexed by binary triples $(c_x, c_y, c_z)$ where $c_i \in \{0, 1\}$.
   - For each corner, identify the voxel indices in the 1D span using the strides $j_x, j_y, j_z$ and the corner offset.
   - Compute the gradient at the corner using central differences. The source code computes `sd_px - sd_nx`, which implies a gradient component calculation. Specifically, for a corner at index $i$, the gradient is derived from the SDF values at adjacent voxels. The standard central difference for the x-component at a voxel is $(SDF(x+1) - SDF(x-1))/2$. However, the source notes specify `gradient = (pos+ - pos-) / 2` implicitly via `sd_px - sd_nx`. We interpret this as computing the gradient vector at the corner using the immediate neighbors in the grid.
   - Let $G_{c_x, c_y, c_z}$ be the gradient vector at corner $(c_x, c_y, c_z)$.
4. **Trilinear Interpolation:** Interpolate the 8 corner gradients $G_{c_x, c_y, c_z}$ using the fractional position $pf$ to obtain the final gradient $\nabla f(p)$.
   $$ \nabla f(p) = \sum_{c_x=0}^{1} \sum_{c_y=0}^{1} \sum_{c_z=0}^{1} G_{c_x, c_y, c_z} \cdot w_{c_x}(pf_x) \cdot w_{c_y}(pf_y) \cdot w_{c_z}(pf_z) $$
   where $w_i(t) = t$ if $i=1$ and $1-t$ if $i=0$.

**Pseudocode:**
```python
def get_interpolated_raw_sdf_gradient(buffer, position):
    # Check for compression
    if buffer.compression == COMPRESSION_UNIFORM:
        return Vector3(0, 0, 0)

    # Block selection: center at floor(position) - 1
    # The block covers floor(position) to floor(position) + 2
    base_idx = compute_1d_index(floor(position) - 1, buffer.stride_x, buffer.stride_y, buffer.stride_z)
    
    # Fractional position
    pf = position - floor(position)
    
    # Strides for 4x4x4 block
    jump_x = 1
    jump_y = 4
    jump_z = 16
    
    # Compute gradients at 8 corners
    corner_gradients = []
    for cx in [0, 1]:
        for cy in [0, 1]:
            for cz in [0, 1]:
                # Calculate corner index in the 1D buffer
                # The corner is relative to the block start
                # Note: The exact indexing depends on how the block is stored.
                # Assuming the block is stored contiguously or with specific strides.
                # Based on jump strides, the corner at (cx, cy, cz) relative to block start:
                corner_offset = cx * jump_x + cy * jump_y + cz * jump_z
                corner_idx = base_idx + corner_offset
                
                # Get SDF value at corner
                sdf_val = buffer[corner_idx]
                
                # Compute raw gradient at corner using central differences
                # This requires accessing neighbors. The source says "get_raw_sdf_gradient"
                # which uses central differences: (pos+ - pos-) / 2
                # We need to implement get_raw_sdf_gradient here or assume it's available.
                # Since pseudocode must be self-contained, we inline the logic.
                # However, accessing neighbors for central difference requires boundary checks.
                # The source notes do not specify boundary handling for the corner gradient calculation itself,
                # only that it uses central differences.
                
                # For the purpose of this article, we assume get_raw_sdf_gradient is a helper
                # that computes the gradient at a specific voxel index using its neighbors.
                # If we must inline it, we need the buffer's total size and boundary logic.
                # Given the constraint "no placeholders", and the complexity of boundary checks
                # not being detailed in the notes, we will call a helper function defined below.
                grad = get_raw_sdf_gradient(buffer, corner_idx, jump_x, jump_y, jump_z)
                corner_gradients.append(grad)
    
    # Trilinear interpolation of gradients
    result = Vector3(0, 0, 0)
    for i, cx in enumerate([0, 1]):
        for j, cy in enumerate([0, 1]):
            for k, cz in enumerate([0, 1]):
                weight = (pf.x if cx else 1 - pf.x) * \
                         (pf.y if cy else 1 - pf.y) * \
                         (pf.z if cz else 1 - pf.z)
                result += corner_gradients[i * 4 + j * 2 + k] * weight
                
    return result

def get_raw_sdf_gradient(buffer, idx, jump_x, jump_y, jump_z):
    # Central difference gradient
    # Gradient = (SDF(pos + step) - SDF(pos - step)) / 2
    # We need to handle boundaries. The source does not specify.
    # We assume valid neighbors exist for the corners of the 4x4x4 block
    # within the larger buffer context.
    
    # X component
    sdf_pos_x = buffer[idx + jump_x]
    sdf_neg_x = buffer[idx - jump_x]
    grad_x = (sdf_pos_x - sdf_neg_x) / 2.0
    
    # Y component
    sdf_pos_y = buffer[idx + jump_y]
    sdf_neg_y = buffer[idx - jump_y]
    grad_y = (sdf_pos_y - sdf_neg_y) / 2.0
    
    # Z component
    sdf_pos_z = buffer[idx + jump_z]
    sdf_neg_z = buffer[idx - jump_z]
    grad_z = (sdf_pos_z - sdf_neg_z) / 2.0
    
    return Vector3(grad_x, grad_y, grad_z)
```

**Parameters:**
- Block Size: $4 \times 4 \times 4$ (fixed).
- Strides: $j_x=1, j_y=4, j_z=16$ (fixed for 4x4x4 block in 1D span).

**Edge Cases and Pitfalls:**
- **Compression:** If the SDF channel is compressed (`COMPRESSION_UNIFORM`), the gradient returns a zero vector because gradients cannot be accurately computed from compressed data [S1, unofficial].
- **Boundary Conditions:** The central difference calculation at corners requires valid neighbors. If the queried position is near the buffer boundary, accessing `idx - jump` may be out of bounds. The source notes do not specify how this is handled (e.g., clamping, reflection, or error). Implementers must ensure boundary checks are in place or that the query position is guaranteed to be within a valid region with sufficient padding.

## Operating characteristics
- **Time Complexity:** Constant time $O(1)$ per query, as it always accesses a fixed 4x4x4 block (64 voxels) and performs a fixed number of arithmetic operations.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Strengths:** Provides smooth gradients for ray marching; efficient due to fixed block size and simple interpolation.
- **Limitations:** Gradient accuracy depends on the underlying SDF resolution and the validity of central differences (requires smooth data); compressed data yields zero gradients.

## Background
This method is part of the Godot Voxel module, specifically designed for efficient SDF queries in voxel-based terrain and mesh generation. It is used in the `voxel_mesh_sdf` feature set.
