# Edge ID Calculation

Also called: Edge Vertex ID Calculation

## Overview
Edge ID Calculation determines the unique global identifier for a vertex located on a specific edge of a voxel cell. It solves the problem of mapping local geometric primitives (edges of a voxel) to a global vertex buffer index, enabling the construction of a coherent mesh from discrete voxel data. It differs from standard Cartesian indexing by relying on a specific vertex layout formula that accounts for the 3D grid topology, ensuring consistent adjacency across voxel boundaries.

## How it works
**Inputs:**
- Voxel corner coordinates $(x, y, z)$, where $x, y, z$ are integer indices of the voxel corner.
- Grid dimensions $xWidth$ and $yWidth$, representing the number of voxels in the x and y directions respectively.

**Outputs:**
- A unique global vertex ID (integer) corresponding to the vertex at the specified edge of the voxel.

**Data Structures:**
- No complex data structures are required for the calculation itself; it is a direct arithmetic computation. The result is typically used as an index into a global vertex array.

**Formulas:**
The base vertex ID for a voxel corner is calculated as:
$$
vertexId(x, y, z) = 3 \times (z \times (yWidth + 1) \times (xWidth + 1) + y \times (xWidth + 1) + x)
$$
This formula assumes a specific vertex packing scheme where each voxel corner contributes 3 potential vertex slots (likely for normal or color data, or simply a stride of 3), or it maps to a specific interleaved layout. The factor of 3 suggests that the vertex buffer might store 3 vertices per grid point, or it is a stride multiplier. However, looking at the edge offsets, they are added to the base ID.

**Edge Mapping:**
The 12 edges of a voxel are mapped to offsets from the base vertex ID or adjacent vertex IDs. Let $B = vertexId(x, y, z)$. The global ID for edge $e$ is:

- Edge 0: $B + 1$
- Edge 1: $vertexId(x, y+1, z)$
- Edge 2: $vertexId(x+1, y, z) + 1$
- Edge 3: $B$
- Edge 4: $vertexId(x, y, z+1) + 1$
- Edge 5: $vertexId(x, y+1, z+1)$
- Edge 6: $vertexId(x+1, y, z+1) + 1$
- Edge 7: $vertexId(x, y, z+1)$
- Edge 8: $B + 2$
- Edge 9: $vertexId(x, y+1, z) + 2$
- Edge 10: $vertexId(x+1, y+1, z) + 2$
- Edge 11: $vertexId(x+1, y, z) + 2$

**Pseudocode:**
```python
def calculate_vertex_id(x: int, y: int, z: int, x_width: int, y_width: int) -> int:
    """
    Calculates the base vertex ID for a voxel corner.
    """
    return 3 * (z * (y_width + 1) * (x_width + 1) + y * (x_width + 1) + x)

def get_edge_vertex_id(edge_index: int, x: int, y: int, z: int, x_width: int, y_width: int) -> int:
    """
    Returns the global vertex ID for a specific edge of a voxel.
    Edge indices 0-11 correspond to the standard DualMC edge numbering.
    """
    base_id = calculate_vertex_id(x, y, z, x_width, y_width)
    
    # Helper to get vertex ID for a specific coordinate
    def get_vid(cx, cy, cz):
        return calculate_vertex_id(cx, cy, cz, x_width, y_width)

    if edge_index == 0:
        return base_id + 1
    elif edge_index == 1:
        return get_vid(x, y + 1, z)
    elif edge_index == 2:
        return get_vid(x + 1, y, z) + 1
    elif edge_index == 3:
        return base_id
    elif edge_index == 4:
        return get_vid(x, y, z + 1) + 1
    elif edge_index == 5:
        return get_vid(x, y + 1, z + 1)
    elif edge_index == 6:
        return get_vid(x + 1, y, z + 1) + 1
    elif edge_index == 7:
        return get_vid(x, y, z + 1)
    elif edge_index == 8:
        return base_id + 2
    elif edge_index == 9:
        return get_vid(x, y + 1, z) + 2
    elif edge_index == 10:
        return get_vid(x + 1, y + 1, z) + 2
    elif edge_index == 11:
        return get_vid(x + 1, y, z) + 2
    else:
        raise ValueError("Edge index must be between 0 and 11")
```

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** The calculation assumes that the coordinates $(x, y, z)$ and their neighbors (e.g., $x+1, y+1, z+1$) are within the valid grid bounds. Accessing vertices outside the grid will result in invalid IDs or out-of-bounds memory access if used directly.
- **Vertex Buffer Layout:** The formula includes a multiplier of 3. This implies that the vertex buffer is not a simple 1:1 mapping of grid points to vertices. It suggests that each grid point might have 3 associated vertices (e.g., for different normals or colors) or that the stride is 3. Implementers must ensure the vertex buffer is allocated with this stride in mind.
- **Consistency:** The edge numbering must match the DualMC algorithm's expected edge indices. Mismatched edge numbering will result in incorrect triangle connectivity.

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(1)$ per edge ID calculation. It involves a constant number of arithmetic operations.
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Performance:** Extremely fast, suitable for real-time applications. The calculation is purely arithmetic and does not require memory lookups beyond the input parameters.
- **Strengths:** Simple, deterministic, and efficient.
- **Limitations:** Requires careful handling of grid boundaries. The specific vertex layout (stride of 3) is non-standard and must be understood by the rest of the pipeline.

## Background
The method originates from the ilastik marching cubes implementation, which uses a specific vertex layout for its mesh generation. The edge numbering and vertex ID calculation are designed to work with the DualMC (Dual Marching Cubes) algorithm, which relies on a canonical spatial layout for voxel corners and edges.
