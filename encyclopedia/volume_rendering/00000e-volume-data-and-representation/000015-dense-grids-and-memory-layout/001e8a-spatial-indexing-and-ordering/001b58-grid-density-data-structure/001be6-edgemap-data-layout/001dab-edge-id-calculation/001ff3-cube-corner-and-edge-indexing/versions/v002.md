# Cube Corner and Edge Indexing

Also called: DualMC corner/edge mapping, Morton code corner indexing

## Overview
Cube Corner and Edge Indexing defines the coordinate system and indexing scheme for the vertices and edges of a voxel cell used in DualMC table generation [S1, unofficial]. It maps the 8 cube corners to indices 0–7 via Morton codes and assigns unique indices 0–11 to the 12 edges [S1, unofficial].

## How it works
### Inputs and Outputs
- **Input**: None (static definition).
- **Output**: Three static mappings:
  1. `cornerIndex`: Maps a corner's spatial position to an integer 0–7 [S1, unofficial].
  2. `edgeIndex`: Maps an edge's spatial position to an integer 0–11 [S1, unofficial].
  3. `cornerEdges`: A lookup table mapping each corner to its three incident edges [S1, unofficial].

### Data Structures
The indexing relies on a fixed-size cube geometry [S1, unofficial].

**Corner Layout**:
The 8 corners are indexed 0 through 7 based on Morton codes [S1, unofficial]. The index corresponds to the Morton code of the corner's local coordinates $(x, y, z)$, where $x, y, z \in \{0, 1\}$ [S1, unofficial]. The mapping from local coordinates to corner index $C$ is $C = 4z + 2y + x$ [S1, unofficial]. The explicit coordinate mapping is:
- Corner 0: $(0, 0, 0)$
- Corner 1: $(1, 0, 0)$
- Corner 2: $(0, 1, 0)$
- Corner 3: $(1, 1, 0)$
- Corner 4: $(0, 0, 1)$
- Corner 5: $(1, 0, 1)$
- Corner 6: $(0, 1, 1)$
- Corner 7: $(1, 1, 1)$ [S1, unofficial].

**Edge Layout**:
The 12 edges are indexed 0 through 11 [S1, unofficial]. Each edge connects two corners according to the fixed mapping:
| Edge Index | Connects Corner A | Connects Corner B |
| :--- | :--- | :--- |
| 0 | 0 | 1 |
| 1 | 1 | 5 |
| 2 | 0 | 4 |
| 3 | 4 | 5 |
| 4 | 2 | 3 |
| 5 | 3 | 7 |
| 6 | 2 | 6 |
| 7 | 6 | 7 |
| 8 | 0 | 2 |
| 9 | 1 | 3 |
| 10 | 4 | 6 |
| 11 | 5 | 7 | [S1, unofficial].

**cornerEdges Table**:
The table maps each corner $C \in [0, 7]$ to the indices of its three adjacent edges [S1, unofficial].

### Step-by-Step Construction
1. **Define Corner Coordinates**: Assign local coordinates $(x, y, z) \in \{0, 1\}^3$ to each of the 8 corners [S1, unofficial].
2. **Calculate Corner Indices**: Compute the corner index $C = 4z + 2y + x$ for each corner [S1, unofficial].
3. **Define Edges**: Enumerate the 12 edges of the cube, each defined by its two endpoint corners [S1, unofficial].
4. **Assign Edge Indices**: Assign indices 0–11 to the edges according to the fixed mapping [S1, unofficial].
5. **Build `cornerEdges` Table**: For each corner $C \in [0, 7]$, identify the three edges incident to it and store their indices in `cornerEdges[8][3]` [S1, unofficial].

### Pseudocode
The following Python-like pseudocode defines the static mappings.

```python
def calculate_corner_index(x, y, z):
    """Calculates corner index C = 4z + 2y + x for binary coordinates."""
    return (z << 2) | (y << 1) | x

def build_corner_edges_table():
    """Returns corner_edges[8][3] mapping each corner to its 3 incident edge indices."""
    edges = [
        (0, 1), (1, 5), (0, 4), (4, 5),
        (2, 3), (3, 7), (2, 6), (6, 7),
        (0, 2), (1, 3), (4, 6), (5, 7)
    ]
    corner_edges = [[] for _ in range(8)]
    for edge_idx, (c1, c2) in enumerate(edges):
        corner_edges[c1].append(edge_idx)
        corner_edges[c2].append(edge_idx)
    for c in range(8):
        corner_edges[c].sort()
    return corner_edges

corner_edges_table = build_corner_edges_table()
```

### Parameters and Edge Cases
- **Bit Packing**: The Morton code formula $C = 4z + 2y + x$ assumes binary local coordinates $(x, y, z) \in \{0, 1\}^3$ [S1, unofficial].
- **Coordinate System**: The source defines a right-handed system with $x$ right, $y$ up, and $z$ depth [S1, unofficial].
- **Degenerate Input**: Not applicable, as this is a static topological definition [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(1)$ for all lookups, as the tables are static and precomputed [S1, unofficial].
- **Memory Complexity**: $O(1)$, requiring only 8 corner indices, 12 edge indices, and an $8 \times 3$ edge list [S1, unofficial].
- **Strengths**: Provides a deterministic, hardware-independent mapping for voxel topology, essential for generating DualMC lookup tables [S1, unofficial].
- **Limitations**: Tied to the specific Morton code ordering; remapping is required if a different global grid ordering is used [G].

## Background
This indexing scheme originates from the DualMC implementation by Dominik Wodniok [S1, unofficial]. It is used in the `gentables` utility to generate static lookup tables that map voxel occupancy masks to extracted surface primitives [S1, unofficial]. The method ensures topological consistency between corners and edges, facilitating efficient traversal and neighbor lookup in dense volume data [S1, unofficial].
