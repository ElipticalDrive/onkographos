# Edge ID Calculation


## Overview
Edge ID Calculation determines the unique global identifier for a vertex located on a specific edge of a voxel cell [S1, unofficial]. It maps local geometric primitives (edges of a voxel) to a global vertex buffer index, enabling the construction of a coherent mesh from discrete voxel data [S1, unofficial]. It differs from standard Cartesian indexing by relying on a specific vertex layout formula that accounts for the 3D grid topology, ensuring consistent adjacency across voxel boundaries [S1, unofficial].

## How it works
**Inputs:**
- Voxel corner coordinates $(x, y, z)$, where $x, y, z$ are integer indices of the voxel corner [S1, unofficial].
- Grid dimensions $xWidth$ and $yWidth$, representing the number of voxels in the x and y directions respectively [S1, unofficial].

**Outputs:**
- A unique global vertex ID (integer) corresponding to the vertex at the specified edge of the voxel [S1, unofficial].

**Data Structures:**
- No complex data structures are required for the calculation itself; it is a direct arithmetic computation [S1, unofficial]. The result is typically used as an index into a global vertex array [G].

**Formulas:**
The base vertex ID for a voxel corner is calculated as:
$$
vertexId(x, y, z) = 3 \times (z \times (yWidth + 1) \times (xWidth + 1) + y \times (xWidth + 1) + x)
$$
The formula uses a stride multiplier of 3 for the vertex buffer layout [S1, unofficial].

**Edge Mapping:**
The 12 edges of a voxel are mapped to offsets from the base vertex ID or adjacent vertex IDs [S1, unofficial]. Let $B = vertexId(x, y, z)$. The global ID for edge $e$ is:
- Edge 0: $B + 1$
- Edge 1: $vertexId(x, y+1, z)$
- Edge 2: $vertexId(x+1, y, z) + 1$
- Edge 3: $B$
- Edge 4: $vertexId(x, y, z+1) + 1$
- Edge 5: $vertexId(x, y+1, z+1)$
- Edge 6: $vertexId(x+1, y, z+1) + 1$
- Edge 7: $vertexId(x, y, z+1)$
- Edge 8: $B + 2$
- Edge 9: $vertexId(x, y+1, z) + 2$
- Edge 10: $vertexId(x+1, y+1, z) + 2$
- Edge 11: $vertexId(x+1, y, z) + 2$

**Pseudocode:**
```python
def calculate_vertex_id(x: int, y: int, z: int, x_width: int, y_width: int) -> int:
    """Calculates the base vertex ID for a voxel corner."""
    return 3 * (z * (y_width + 1) * (x_width + 1) + y * (x_width + 1) + x)

def get_edge_vertex_id(edge_index: int, x: int, y: int, z: int, x_width: int, y_width: int) -> int:
    """Returns the global vertex ID for a specific edge of a voxel."""
    base_id = calculate_vertex_id(x, y, z, x_width, y_width)
    
    def get_vid(cx, cy, cz):
        return calculate_vertex_id(cx, cy, cz, x_width, y_width)

    if edge_index == 0:
        return base_id + 1
    elif edge_index == 1:
        return get_vid(x, y + 1, z)
    elif edge_index == 2:
        return get_vid(x + 1, y, z) + 1
    elif edge_index == 3:
        return base_id
    elif edge_index == 4:
        return get_vid(x, y, z + 1) + 1
    elif edge_index == 5:
        return get_vid(x, y + 1, z + 1)
    elif edge_index == 6:
        return get_vid(x + 1, y, z + 1) + 1
    elif edge_index == 7:
        return get_vid(x, y, z + 1)
    elif edge_index == 8:
        return base_id + 2
    elif edge_index == 9:
        return get_vid(x, y + 1, z) + 2
    elif edge_index == 10:
        return get_vid(x + 1, y + 1, z) + 2
    elif edge_index == 11:
        return get_vid(x + 1, y, z) + 2
    else:
        raise ValueError("Edge index must be between 0 and 11")
```

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** The calculation assumes that the coordinates $(x, y, z)$ and their neighbors (e.g., $x+1, y+1, z+1$) are within the valid grid bounds [G]. Accessing vertices outside the grid will result in invalid IDs or out-of-bounds memory access if used directly [G].
- **Consistency:** The edge numbering must match the DualMC algorithm's expected edge indices [G]. Mismatched edge numbering will result in incorrect triangle connectivity [G].

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(1)$ per edge ID calculation [G].
- **Memory Complexity:** $O(1)$ auxiliary space [G].
- **Performance:** Not given in the sources.
- **Strengths:** Simple, deterministic, and efficient [G].
- **Limitations:** Requires careful handling of grid boundaries [G]. The specific vertex layout (stride of 3) is non-standard and must be understood by the rest of the pipeline [G].

## Background
The method originates from the ilastik marching cubes implementation, which uses a specific vertex layout for its mesh generation [S1, unofficial]. The edge numbering and vertex ID calculation are designed to work with the DualMC (Dual Marching Cubes) algorithm, which relies on a canonical spatial layout for voxel corners and edges [S1, unofficial].
