# EdgeMap Data Layout


## Overview
The EdgeMap data layout organizes geometric primitives for volumetric data processing by storing parallel arrays of indices, intersection points, normals, traversal directions, and offsets [S1, unofficial]. It differs from sibling methods by explicitly decoupling geometric attributes from scalar values into a unified edge-indexed structure [S1, unofficial].

## How it works
**Inputs and Outputs:**

**Data Structures:**
The core layout is defined by the `EdgeMap` struct containing the following fields, all sized to `Index.TotalSize` [S1, unofficial]:
1. `Index`: An `IndexMap` object managing the mapping of local geometric primitives to global indices.
2. `Intersections`: A `unique_ptr<glm::vec3[]>` storing the 3D coordinates of intersection points.
3. `Normals`: A `unique_ptr<glm::vec3[]>` storing the surface normal vectors at each intersection.
4. `Directions`: A `unique_ptr<float[]>` storing traversal direction information.
5. `IndexOffset`: A `unique_ptr<int[]>` storing offset values for indexing into the global buffers.

## Subtopics

### [Edge ID Calculation](1570-edge-id-calculation.md)
Determines the unique global identifier for a vertex on a specific edge of a voxel cell, mapping local primitives to a global vertex buffer index. It differs from standard Cartesian indexing by using a specific vertex layout formula for 3D grid topology consistency. When to choose: Not given in the sources.

### [Enhanced Volume Data Set (EVDS)](11040-enhanced-volume-data-set-evds.md)
Augments standard voxel grids with Boolean edge labels to encode local connectivity between vertices, solving the problem of separating segmentation from geometric modeling by providing a topological map. Unlike standard dense grids, EVDS explicitly tracks whether two adjacent vertices share an active connection, enabling efficient topological analysis and hierarchical compression via L-blocks. When to choose: Not given in the sources.

### [Geodesic Grid Connectivity Setup](17621-geodesic-grid-connectivity-setup.md)
Constructs adjacency and incidence data structures for rendering on a geodesic unstructured grid, transforming raw topology into GPU-accessible formats via Texture Buffer Objects (TBOs). It differs from sibling methods by focusing on bidirectional mapping between grid primitives and uploading relationships as TBOs, whereas [Edge ID Calculation](1570-edge-id-calculation.md) focuses on local indexing and [Enhanced Volume Data Set (EVDS)](11040-enhanced-volume-data-set-evds.md) focuses on the volumetric data container. When to choose: Not given in the sources.
