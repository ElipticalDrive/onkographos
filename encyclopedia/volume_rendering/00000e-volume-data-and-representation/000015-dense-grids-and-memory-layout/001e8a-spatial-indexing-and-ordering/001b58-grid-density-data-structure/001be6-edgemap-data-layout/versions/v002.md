# EdgeMap Data Layout

Also called: EdgeMap

## Overview
The EdgeMap data layout is a memory structure within the Grid Density Data Structure that stores geometric intersection data for isosurface extraction [S1, unofficial]. It organizes intersection points, surface normals, ray directions, and indexing offsets into contiguous arrays [S1, unofficial]. It differs from sibling methods like Gradient Computation via Finite Differences by storing pre-computed geometric primitives rather than derivative values, and from Interpolated Discrete Values & Gradients by focusing on explicit intersection coordinates rather than field values [G].

## How it works
The EdgeMap struct aggregates five primary data fields, all dynamically sized to `Index.TotalSize`, which represents the total number of active edges or intersection entries [S1, unofficial]. The layout is defined as follows:

1. **Index (IndexMap)**: A mapping structure for edge-to-voxel relationships or sorting keys [S1, unofficial]. The exact internal layout of `IndexMap` is not specified in the sources [S1, unofficial].
2. **Intersections**: An array of `glm::vec3` objects storing the 3D coordinates of intersection points on the edges [S1, unofficial].
3. **Normals**: An array of `glm::vec3` objects storing the surface normal vectors at each intersection point [S1, unofficial].
4. **Directions**: An array of `float` values storing scalar direction information [S1, unofficial].
5. **IndexOffset**: An array of `int` values storing offset indices [S1, unofficial].

The data is managed using `std::unique_ptr` for automatic memory management of the dynamic arrays [S1, unofficial]. Implementation requires initializing the arrays to `Index.TotalSize` and populating them during the isosurface extraction pass. Input consists of voxel grid data and ray traversal results; output is the populated EdgeMap ready for mesh assembly. Formulas, specific parameters, and edge case handling are not given in the sources.

```python
class EdgeMap:
    def __init__(self, total_size: int):
        self.total_size = total_size
        self.index_map = None  # Layout not specified in sources [S1, unofficial]
        self.intersections = [None] * total_size
        self.normals = [None] * total_size
        self.directions = [0.0] * total_size
        self.index_offset = [0] * total_size

    def set_intersection(self, index: int, point: tuple) -> None:
        if 0 <= index < self.total_size:
            self.intersections[index] = point

    def set_normal(self, index: int, normal: tuple) -> None:
        if 0 <= index < self.total_size:
            self.normals[index] = normal

    def set_direction(self, index: int, direction: float) -> None:
        if 0 <= index < self.total_size:
            self.directions[index] = direction

    def set_offset(self, index: int, offset: int) -> None:
        if 0 <= index < self.total_size:
            self.index_offset[index] = offset
```

## Operating characteristics
Memory complexity is linear with respect to `Index.TotalSize`, requiring storage for four dynamic arrays of that size [S1, unofficial]. The use of `glm::vec3` implies 12 bytes per intersection and normal entry, while `float` and `int` occupy 4 bytes each, yielding approximately 32 bytes per entry plus the `IndexMap` overhead [S1, unofficial]. Performance characteristics, scaling behavior, and measured performance on specific hardware are not given in the sources [S1, unofficial]. Strengths include compact, contiguous storage for GPU-friendly traversal; limitations include dependency on the unspecified `IndexMap` implementation and lack of documented degenerate input handling [S1, unofficial].

## Background
