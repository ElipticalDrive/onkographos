# EdgeMap Data Layout

Also called: EdgeMap

## Overview
The EdgeMap data layout is a memory structure used in volume rendering to store geometric intersection data for isosurface extraction, specifically within the context of the Grid Density Data Structure. It organizes intersection points, surface normals, ray directions, and indexing offsets into contiguous arrays. It differs from sibling methods like Gradient Computation via Finite Differences by storing pre-computed geometric primitives rather than derivative values, and from Interpolated Discrete Values & Gradients by focusing on explicit intersection coordinates rather than field values.

## How it works
The EdgeMap struct aggregates four primary data arrays, all sized to `Index.TotalSize`, which represents the total number of active edges or intersection entries. The layout is defined as follows:

1.  **Index (IndexMap)**: A mapping structure that likely provides lookup capabilities for edge-to-voxel relationships or sorting keys. The exact internal layout of `IndexMap` is not specified in the source, but it is a required component of the struct.
2.  **Intersections**: An array of `glm::vec3` objects storing the 3D coordinates of intersection points on the edges.
3.  **Normals**: An array of `glm::vec3` objects storing the surface normal vectors at each intersection point.
4.  **Directions**: An array of `float` values storing scalar direction information, possibly related to ray traversal or edge orientation.
5.  **IndexOffset**: An array of `int` values storing offset indices, likely used to group intersections by voxel or cell.

The data is managed using `std::unique_ptr` for automatic memory management of the dynamic arrays.

```python
class EdgeMap:
    def __init__(self, total_size):
        self.total_size = total_size
        # IndexMap layout is not specified in sources [S1, unofficial]
        self.index_map = None 
        
        # Intersections: Array of 3D vectors
        self.intersections = [None] * total_size
        
        # Normals: Array of 3D vectors
        self.normals = [None] * total_size
        
        # Directions: Array of floats
        self.directions = [0.0] * total_size
        
        # IndexOffset: Array of integers
        self.index_offset = [0] * total_size

    def set_intersection(self, index, point):
        """Set the intersection point at a specific index."""
        if 0 <= index < self.total_size:
            self.intersections[index] = point

    def set_normal(self, index, normal):
        """Set the normal vector at a specific index."""
        if 0 <= index < self.total_size:
            self.normals[index] = normal

    def set_direction(self, index, direction):
        """Set the direction scalar at a specific index."""
        if 0 <= index < self.total_size:
            self.directions[index] = direction

    def set_offset(self, index, offset):
        """Set the index offset at a specific index."""
        if 0 <= index < self.total_size:
            self.index_offset[index] = offset
```

## Operating characteristics
The memory complexity is linear with respect to `Index.TotalSize`, requiring storage for four arrays of size `N`. The use of `glm::vec3` implies 12 bytes per intersection and normal, while `float` and `int` typically occupy 4 bytes each. Total memory per entry is approximately 32 bytes plus the overhead of the `IndexMap`. Performance characteristics depend on the implementation of `IndexMap` and the population of these arrays, which is not detailed in the sources.

## Background
The EdgeMap data layout is part of the `Isosurface` project by HeartofTheForce. It is used in conjunction with shader programs for graphics rendering, as indicated by the surrounding code context involving GLSL shaders and OpenGL state management.
