# Gradient Computation via Finite Differences

Also called: Central Difference Gradient, Central-Difference Gradient Operator, FD Gradient, Finite Difference Gradient, Gradient Computation Using Central Differences

## Overview
Gradient Computation via Finite Differences estimates the spatial gradient vector of a scalar volume field at each voxel or sample point to provide surface normals for local illumination (e.g., Phong shading) and opacity modulation [S1, S2, unofficial][S3, book]. It sets itself apart from [Sobel Operator](1416-sobel-operator.md) by using a minimal 6-neighbor stencil which is computationally cheaper but less smooth, and from [Analytic Gradient Computation](2167-analytic-gradient-computation.md) by requiring explicit neighbor lookups rather than deriving derivatives from the reconstruction basis [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume grid $V$ of resolution $R_x \times R_y \times R_z$.
*   **Output:** A gradient vector field $G$, where each voxel $(x,y,z)$ has a 3D vector $\nabla V = (\frac{\partial V}{\partial x}, \frac{\partial V}{\partial y}, \frac{\partial V}{\partial z})$.

**Data Structures:**
*   **Volume Data:** Stored as a 1D array or texture. If 1D, layout is interleaved RGB (x, y, z components) per voxel for the gradient output, size $N \times 3$ floats, where $N = R_x R_y R_z$ [S5, unofficial].
*   **Gradient Storage:** Can be a separate float array [S5, unofficial], a signed normalized texture (e.g., `RGBA8_SNORM`) for GPU sampling [S8, unofficial], or encoded into 8-bit integers [S8, unofficial].

**Parameters:**
*   $h$: The physical distance between voxels along the axis of differentiation [S3, book][S14]. In index space, this is often normalized to 1.0, making the denominator 2 [S9, unofficial].
*   `grad_magnitude_modifier`: A scalar multiplier applied to the gradient magnitude before clamping [S4, unofficial].
*   `scale`: A multiplier (typically 2.0) used to map gradient magnitudes to the [0,1] range for quantization [S8, unofficial].

**Steps:**
1.  **Iterate** over every voxel $(x, y, z)$ in the volume grid.
2.  **Compute Components:** Calculate the partial derivatives using central differences.
    *   $g_x = \frac{V(x+1, y, z) - V(x-1, y, z)}{2h}$
    *   $g_y = \frac{V(x, y+1, z) - V(x, y-1, z)}{2h}$
    *   $g_z = \frac{V(x, y, z+1) - V(x, y, z-1)}{2h}$
    *   If working in index space where $h=1$, the division by $2h$ becomes multiplication by $0.5$ [S8, S9, unofficial].
3.  **Handle Boundaries:** At data boundaries, neighbors may be out of bounds. The standard approach is to pad the volume by repeating boundary values (clamping coordinates to $[0, R_i-1]$) [S3, book][S8, unofficial][S14]. Alternatively, return zero or use one-sided differences [S18, unofficial].
4.  **Normalize:** Compute the magnitude $len = \sqrt{g_x^2 + g_y^2 + g_z^2}$. If $len > \epsilon$ (e.g., $10^{-6}$), normalize the vector $\mathbf{n} = \frac{(g_x, g_y, g_z)}{len}$. Otherwise, set $\mathbf{n} = (0,0,0)$ [S2, S8, unofficial].
5.  **Encode (Optional):** If storing in fixed-point formats, map the signed normal $\mathbf{n} \in [-1, 1]$ to unsigned $[0, 1]$ via $enc = \mathbf{n} \cdot 0.5 + 0.5$, then quantize to 8-bit integers [S8, unofficial].

**Pseudocode:**
```python
def compute_central_difference_gradients(volume, resolution):
    """
    Computes the gradient vector field for a scalar volume using central differences.
    
    Args:
        volume: 1D array or 3D array of scalar values.
        resolution: Tuple (rx, ry, rz) of the volume dimensions.
        
    Returns:
        gradients: 1D array of floats of size N*3, interleaved (gx, gy, gz).
    """
    rx, ry, rz = resolution
    n_voxels = rx * ry * rz
    gradients = [0.0] * (n_voxels * 3)
    
    # Helper to safely fetch voxel value with clamping
    def get_voxel(x, y, z):
        # Clamp coordinates to valid range
        x = max(0, min(x, rx - 1))
        y = max(0, min(y, ry - 1))
        z = max(0, min(z, rz - 1))
        
        # Calculate linear index assuming row-major order (x varies fastest)
        idx = x + y * rx + z * rx * ry
        return volume[idx]

    for z in range(rz):
        for y in range(ry):
            for x in range(rx):
                # Central differences
                # Note: h=1 in index space. If physical spacing is needed, divide by 2*h_phys
                gx = (get_voxel(x + 1, y, z) - get_voxel(x - 1, y, z)) * 0.5
                gy = (get_voxel(x, y + 1, z) - get_voxel(x, y - 1, z)) * 0.5
                gz = (get_voxel(x, y, z + 1) - get_voxel(x, y, z - 1)) * 0.5
                
                # Normalize
                length_sq = gx*gx + gy*gy + gz*gz
                if length_sq > 1e-12:
                    length = length_sq ** 0.5
                    gx /= length
                    gy /= length
                    gz /= length
                else:
                    gx = 0.0
                    gy = 0.0
                    gz = 0.0
                
                # Store interleaved
                idx = (x + y * rx + z * rx * ry) * 3
                gradients[idx] = gx
                gradients[idx + 1] = gy
                gradients[idx + 2] = gz
                
    return gradients
```

## Subtopics

### Gradient Map Generation
A GPU compute shader pass that calculates gradients for all voxels and stores them in a gradient map image, including magnitude and direction. It uses a 3D image buffer with `rgba8_snorm` layout, storing normalized gradient direction in x, y, z and magnitude in w. The magnitude is clamped to [0, 1] after being multiplied by a `grad_magnitude_modifier` [S4, unofficial].

### Voxel Gradient Calculation
A pre-processing step using the Sobel operator (a variant of finite differences) to detect edges. Gradient magnitude modulates voxel opacity to hide homogeneous regions, and gradient direction is used for shading [S16, unofficial].

### Clamped Central Differences
A variant for adaptive mesh refinement (AMR) or structured grids where offset positions are clamped to the current region to avoid additional ray traversals. It computes six additional basis reconstruction samples at positions offset by the region's sample rate. Gradients are not necessarily continuous at level boundaries because the offset size can change [S17].

### Precomputed Gradient Volume
A method where gradients are precomputed and stored alongside scalar values in a `VoxelVertex` union. It uses `m_safe_get` to handle out-of-bounds access by returning 0.0f, effectively zero-padding boundaries. The gradient is normalized and stored as a vec3, with the scalar value stored in the w component [S18, unofficial].

### Gradient-based Surface Projection
Visualizes interfaces between regions of different density by projecting through a matrix of gradient magnitude values. The surface normal $N$ is approximated by finite differences, and surface strength $|N|$ is the L2-norm. This allows visualization of diffuse transitions at sub-voxel accuracy [S19, unofficial].

### Curl Grid Computation
Computes the curl $\nabla \times \mathbf{F}$ of a vector grid using central differences. It uses a 6-point stencil in index space with a scalar multiplier of 0.5 (representing $1/(2 \cdot \text{voxel\_size})$). Components are computed as:
*   $curl_x = (v[4][3] - v[5][3] - v[6][2] + v[7][2]) \cdot 0.5$
*   $curl_y = (v[6][1] - v[7][1] - v[2][3] + v[3][3]) \cdot 0.5$
*   $curl_z = (v[2][2] - v[3][2] - v[4][1] + v[5][1]) \cdot 0.5$
[S7, unofficial].

### Laplacian Grid Computation
Computes the Laplacian $\nabla^2 f$ at every active voxel using a 6-point stencil in index space. It builds on the gradient stencil infrastructure but sums the second derivatives [S7, unofficial].

### Gradient Magnitude Computation
Computes the Euclidean norm $|\mathbf{v}|$ at every active voxel of a vector grid. It iterates over active voxels, computes the norm, and builds a result grid with a zero background [S7, unofficial].

### Forward Difference Gradient
A simpler gradient estimation taking four neighboring voxels. For voxel $V$ at $(x,y,z)$:
*   $\nabla_x = V_{x+1,y,z} - V_{x,y,z}$
*   $\nabla_y = V_{x,y+1,z} - V_{x,y,z}$
*   $\nabla_z = V_{x,y,z+1} - V_{x,y,z}$
[S6, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels, as each voxel requires a constant number of lookups and arithmetic operations [S5, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the gradient field separately [S5, unofficial].
*   **Performance:** Very fast due to minimal stencil size (6 neighbors) compared to Sobel (26 neighbors) or Neumann (26+ neighbors) [S2, unofficial].
*   **Strengths:** Low computational cost, simple implementation, suitable for real-time rendering when precomputed gradients are not feasible or when on-the-fly estimation is required [S1, S2, unofficial].
*   **Limitations:** Less smooth gradients compared to operators using more voxels (e.g., Sobel3D, Neumann), resulting in a worse description of local surface structure [S2, unofficial]. Visual artifacts similar to trilinear interpolation resampling can occur [S3, book][S14].
*   **When to use:** Real-time volume rendering where performance is critical, or when implementing on-the-fly shading without precomputed gradient textures.
*   **When not to use:** High-fidelity offline rendering where smooth shading is required, or when noise reduction is needed (use Sobel or Neumann instead).

## Background
The method originates from standard numerical analysis techniques for approximating derivatives. In volume rendering, it was popularized for real-time raycasting to enable local illumination effects like Phong shading without the cost of explicit surface extraction [S1, S2, unofficial]. It is widely used in GPU-based volume renderers, often implemented as compute shaders or fragment shaders for on-the-fly gradient estimation [S4, S8, S10, unofficial]. The technique is documented in standard graphics references such as the NVIDIA GPU Gems [S3, book] and various academic dissertations on real-time volume rendering [S6, unofficial].
