# Gradient Computation via Finite Differences

Also called: Central Difference Gradient, Finite Difference Gradient, Central Difference Gradient Estimation, Central Difference Gradient Calculation, Gradient Computation Using Central Differences

## Overview
Gradient Computation via Finite Differences estimates the spatial gradient vector of a scalar volume field at discrete voxel locations to provide surface normals for local illumination (e.g., Phong shading) and opacity modulation in direct volume rendering [S1, S2, unofficial][S3, book]. It sets itself apart from [Analytic Gradient Computation](2167-analytic-gradient-computation.md) by relying on discrete neighbor sampling rather than basis function derivatives, and from [Sobel Operator](1109-edgemap-data-layout.md) by using a minimal 6-neighbor stencil, trading computational simplicity and speed for higher noise sensitivity and boundary artifacts [S2, unofficial][S17].

## How it works
**Inputs:** A 3D scalar volume grid $V$ of dimensions $N_x \times N_y \times N_z$, where $V(x,y,z)$ is the scalar value at voxel indices $(x,y,z)$. Physical voxel spacing $(h_x, h_y, h_z)$ is required if physical units are needed; otherwise, index-space differences are used [S3, book][S19, unofficial].

**Outputs:** A 3D vector grid $G$ of the same dimensions, where $G(x,y,z) = \nabla V(x,y,z)$, or a normalized normal vector $N(x,y,z)$ [S5, S10, unofficial].

**Data Structures:**
*   **Input Volume:** 1D array of size $N_x N_y N_z$ in row-major order (x fastest, y middle, z slowest) [S6, S8, unofficial].
*   **Output Gradient:** 1D array of size $N_x N_y N_z \times 3$ with interleaved components $(g_x, g_y, g_z)$ per voxel [S5, unofficial]. Alternatively, stored in a 3D texture (e.g., `RGBA8_SNORM`) where R, G, B store the signed normal components [S4, S12, unofficial].

**Algorithm Steps:**
1.  Iterate through every voxel $(x, y, z)$ in the volume.
2.  For each axis $a \in \{x, y, z\}$, compute the central difference approximation of the derivative:
    $$ \frac{\partial V}{\partial a} \approx \frac{V(pos + \mathbf{h}_a) - V(pos - \mathbf{h}_a)}{2 h_a} $$
    where $\mathbf{h}_x = (h_x, 0, 0)$, $\mathbf{h}_y = (0, h_y, 0)$, $\mathbf{h}_z = (0, 0, h_z)$ [S3, book][S19, unofficial].
    In index space (assuming unit spacing $h_a=1$), this simplifies to:
    $$ g_x = V(x+1, y, z) - V(x-1, y, z) $$
    $$ g_y = V(x, y+1, z) - V(x, y-1, z) $$
    $$ g_z = V(x, y, z+1) - V(x, y, z-1) $$
    [S2, S7, unofficial][S17].
3.  **Boundary Handling:** At grid boundaries, neighbors may be out of bounds. Common strategies include:
    *   Clamping coordinates to the valid range $[0, N-1]$ (repeating edge values) [S12, S21, unofficial].
    *   Using one-sided differences if only one neighbor is available [S22, unofficial].
    *   Padding the volume with repeated boundary values before computation [S3, book][S23].
4.  **Normalization (Optional):** If normals are required for shading, normalize the gradient vector:
    $$ \mathbf{n} = \frac{\mathbf{g}}{|\mathbf{g}|} = \frac{(g_x, g_y, g_z)}{\sqrt{g_x^2 + g_y^2 + g_z^2}} $$
    If $|\mathbf{g}| < \epsilon$ (e.g., $10^{-6}$), set $\mathbf{n} = (0,0,0)$ to avoid division by zero [S2, S12, unofficial].
5.  **Storage/Encoding:** If storing in 8-bit textures, encode signed normals $n \in [-1, 1]$ to unsigned $[0, 1]$ via $c = n \cdot 0.5 + 0.5$, then quantize to integers [S12, unofficial].

**Pseudocode:**
```python
def compute_central_difference_gradients(volume, resolution, physical_spacing=None):
    """
    volume: 1D array of size Nx*Ny*Nz, row-major.
    resolution: tuple (Nx, Ny, Nz).
    physical_spacing: tuple (hx, hy, hz) or None for index-space.
    Returns: 1D array of size Nx*Ny*Nz*3, interleaved (gx, gy, gz).
    """
    Nx, Ny, Nz = resolution
    hx, hy, hz = physical_spacing if physical_spacing else (1.0, 1.0, 1.0)
    
    # Output buffer: interleaved RGB
    gradients = [0.0] * (Nx * Ny * Nz * 3)
    
    # Precompute reciprocal of 2*h for division
    inv_2hx = 1.0 / (2.0 * hx)
    inv_2hy = 1.0 / (2.0 * hy)
    inv_2hz = 1.0 / (2.0 * hz)
    
    for z in range(Nz):
        for y in range(Ny):
            for x in range(Nx):
                # Linear index for current voxel
                idx = x + y * Nx + z * Nx * Ny
                
                # Helper to get voxel value with clamping
                def get_voxel(ix, iy, iz):
                    # Clamp to [0, N-1]
                    ix = max(0, min(Nx - 1, ix))
                    iy = max(0, min(Ny - 1, iy))
                    iz = max(0, min(Nz - 1, iz))
                    return volume[ix + iy * Nx + iz * Nx * Ny]
                
                # Central differences
                # X component
                val_pos = get_voxel(x + 1, y, z)
                val_neg = get_voxel(x - 1, y, z)
                gx = (val_pos - val_neg) * inv_2hx
                
                # Y component
                val_pos = get_voxel(x, y + 1, z)
                val_neg = get_voxel(x, y - 1, z)
                gy = (val_pos - val_neg) * inv_2hy
                
                # Z component
                val_pos = get_voxel(x, y, z + 1)
                val_neg = get_voxel(x, y, z - 1)
                gz = (val_pos - val_neg) * inv_2hz
                
                # Store
                gradients[idx * 3] = gx
                gradients[idx * 3 + 1] = gy
                gradients[idx * 3 + 2] = gz
                
    return gradients

def normalize_gradients(gradients, resolution):
    Nx, Ny, Nz = resolution
    N = Nx * Ny * Nz
    for i in range(N):
        gx = gradients[i * 3]
        gy = gradients[i * 3 + 1]
        gz = gradients[i * 3 + 2]
        
        length_sq = gx*gx + gy*gy + gz*gz
        if length_sq > 1e-12:
            length = length_sq ** 0.5
            gradients[i * 3] = gx / length
            gradients[i * 3 + 1] = gy / length
            gradients[i * 3 + 2] = gz / length
        else:
            gradients[i * 3] = 0.0
            gradients[i * 3 + 1] = 0.0
            gradients[i * 3 + 2] = 0.0
```

**Parameters:**
*   **Step Size ($h$):** The physical distance between voxels along the axis of differentiation [S3, book][S23]. If using index space, $h=1$.
*   **Epsilon ($\epsilon$):** Threshold for zero-length gradient check, typically $10^{-6}$ [S9, S12, unofficial].
*   **Boundary Mode:** Clamping (repeat edge) is most common [S12, S21, unofficial]; padding is also used [S3, book].

**Edge Cases and Pitfalls:**
*   **Boundary Artifacts:** The gradient is undefined at the exact boundary without padding/clamping. Clamping introduces discontinuities in the derivative, causing visual artifacts similar to trilinear interpolation resampling [S3, book][S23].
*   **Noise Sensitivity:** The central difference operator uses only 6 neighboring voxels, resulting in less smooth gradients compared to operators using more voxels (e.g., Sobel3D or Neumann) [S2, unofficial][S17]. It displays substantial voxel artifacts from coarse data resolution [S17].
*   **Zero Gradient:** Flat regions yield zero vectors. Normalization must handle this to avoid NaNs [S12, unofficial][S24].
*   **Out-of-Bounds Access:** Direct array access without clamping or padding causes memory errors [S6, S8, unofficial].

## Subtopics

### [Gradient-based Diffuse Lighting with Alpha Blending](1257-gradient-based-diffuse-lighting-with-alpha-blending.md)

### [Analytic Gradient Computation](2167-analytic-gradient-computation.md)
Computes gradient vectors for local shading using analytic derivatives of the basis reconstruction function, avoiding additional samples or ray traversals.

### [Gradient Estimation from Samples](2180-gradient-estimation-from-samples.md)
Computes gradient vectors by sampling the 3D texture at positions offset from the current reconstruction sample, performing finite difference approximation implicitly during the ray-casting shading pass.

### [Per-Region Gradient Averaging](2715-per-region-gradient-averaging.md)
Computes the 3D gradient vector for each voxel by averaging directional gradients across multiple discrete scalar regions, using a binary neighbor check to detect region boundaries.

### [Gradient Magnitude Computation](3184-gradient-magnitude-computation.md)
Computes the Euclidean norm $|\mathbf{v}|$ at every active voxel of a vector grid, producing a scalar magnitude grid.

### [Neumann Gradient](3342-neumann-gradient.md)
A 3D gradient estimation method using a 3×3×3 neighborhood of 26 surrounding voxels and linear regression to produce nearly isotropic gradients with reduced fringing artifacts.

### [Scanline Gradient Computation](3582-scanline-gradient-computation.md)
A memory-efficient method for computing 3D gradient vectors by processing one scanline at a time, maintaining only a sliding window of three slices in memory.

### [Finite Difference Stencils (Central/Forward/Backward)](3858-finite-difference-stencils-central-forward-backward.md)
A family of methods computing spatial gradients using finite difference approximations, trading computational simplicity for potential noise sensitivity.

### [Second Derivative Computation](6353-second-derivative-computation.md)
Computes second-order spatial derivatives (curvature, Laplacian) from discrete grid data.

### Voxel Gradient Calculation
A pre-processing step using the Sobel operator to detect edges within the volume and compute gradients. Gradient magnitude modulates voxel opacity to hide homogeneous regions, and gradient direction is used for shading [S25, unofficial].

### Linearly Separable Piecewise Polynomial Interpolation Gradient
A gradient estimation method using optimized piecewise polynomial interpolation filters designed for specific accuracy and continuity characteristics, proposed by Möller et al. It uses coefficients $-1/12, 2/3, -2/3, 1/12$ for offsets $-2, -1, +1, +2$ respectively along each axis. It has slightly softer edges in regions of rapid change compared to central differences [S17].

### Gradient Selection
Selects between Central Difference and Sobel gradient estimation based on the `gradientMode` uniform. If `gradientMode == GRADIENT_SOBEL`, returns `gradientSobel(textureCoord)`, else returns `gradientCentral(textureCoord)` [S14, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels, as each voxel requires a constant number of reads and arithmetic operations [S5, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the gradient field (3 floats per voxel) [S5, unofficial]. If computed on-the-fly during raycasting, memory overhead is $O(1)$ per sample, but bandwidth increases by 6 texture fetches per gradient calculation [S18, unofficial].
*   **Performance:** The central difference operator is computationally inexpensive, requiring only 6 sampling points per calculation [S2, unofficial]. It is significantly faster than complex operators like the Zucker-Hummel operator (54 points) [S2, unofficial].
*   **Strengths:** Simple to implement, low computational cost, suitable for real-time rendering when precomputed [S17].
*   **Limitations:** Poor description of local surface structure compared to Sobel3D [S2, unofficial]. Sensitive to noise and produces voxel artifacts on coarse data [S17]. Boundary artifacts require careful handling [S3, book].
*   **When to Use:** When performance is critical, data is smooth, or as a baseline for shading. When high-quality normals are needed for noisy data, consider [Neumann Gradient](3342-neumann-gradient.md) or [Sobel](1109-edgemap-data-layout.md).

## Background
Gradient computation via finite differences is a standard technique in scientific visualization and computer graphics for estimating surface normals from discrete scalar fields. It is widely used in volume rendering to enhance visual quality through local illumination models like Phong shading [S1, unofficial][S3, book]. The method is implemented in various libraries, such as CGAL's `Finite_difference_gradient_3` for isosurfacing [S24], and is a foundational component in many GPU-based volume rendering pipelines [S12, S20, unofficial].
