# Gradient Computation via Finite Differences

Also called: Central Difference Gradient, FD Gradient, Finite Difference Gradient, Finite Difference Gradient Computation, Gradient Estimation

## Overview
Gradient Computation via Finite Differences calculates the 3D gradient vector for each voxel in a scalar volume by approximating spatial derivatives using neighboring voxel values [S2, unofficial, S4]. This method provides the gradient data required for illumination and opacity modulation in volume rendering, and for isosurfacing algorithms when analytical gradients are unavailable [S4, S5]. It relies on discrete sampling of the scalar field, distinguishing it from analytical differentiation, and typically uses axis-aligned neighbor differences, though tetrahedron-based variants also exist [S1, unofficial, S3, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   A scalar volume texture or array $V$ of resolution $R = (R_x, R_y, R_z)$ [S2, unofficial, S3, unofficial].
*   A uniform buffer parameter `grad_magnitude_modifier` (float, 4 bytes at offset 0, binding 0) for GPU implementations [S1, unofficial].

**Outputs:**
*   A gradient array $G$ containing the 3D gradient vector $\nabla V$ for each voxel [S2, unofficial].
*   Alternatively, an encoded texture storing normalized direction and magnitude [S1, unofficial, S3, unofficial].

### Data Structures
1.  **Gradient Array (CPU/General):** A 1D float array of size $N \times 3$, where $N = R_x \times R_y \times R_z$. The layout is interleaved RGB: indices $3k, 3k+1, 3k+2$ store $g_x, g_y, g_z$ for voxel $k$ [S2, unofficial].
2.  **Gradient Texture (GPU):**
    *   **RGBA8_SNORM:** Stores normalized direction $(n_x, n_y, n_z)$ in RGB and magnitude in A [S1, unofficial].
    *   **RGBA8:** Stores direction in RGB and clamped density/magnitude in A [S3, unofficial].
    *   **RG8:** Stores clamped density in R and clamped magnitude in G [S3, unofficial].

### Algorithm Steps

#### 1. Boundary Handling
To prevent out-of-bounds reads, sampling coordinates are clamped to the valid voxel range $[0, R_i-1]$ for each axis $i \in \{x, y, z\}$ [S3, unofficial]. Alternatively, boundary neighbors are determined explicitly:
*   If index $i=0$: $x_0=i, x_1=i+1, dx=1.0$ [S2, unofficial].
*   If index $i=R_x-1$: $x_0=i-1, x_1=i, dx=1.0$ [S2, unofficial].
*   Otherwise: $x_0=i-1, x_1=i+1, dx=2.0$ [S2, unofficial].

#### 2. Gradient Calculation
The gradient components are computed using central differences [S3, unofficial].

**Standard Central Difference (Unit Spacing):**
$$ g_x = \frac{V(x+1, y, z) - V(x-1, y, z)}{2} $$
$$ g_y = \frac{V(x, y+1, z) - V(x, y-1, z)}{2} $$
$$ g_z = \frac{V(x, y, z+1) - V(x, y, z-1)}{2} $$
[S3, unofficial]

**Physical Spacing:**
If grid spacing is known, the step size $s$ is computed as $s = 0.01 \sqrt{\text{spacing}^2}$ [S5]. The components are divided by the respective distances $dx, dy, dz$ [S2, unofficial].

**Tetrahedron-Based Variant:**
Some implementations sum contributions from four tetrahedron neighbors defined by offset vectors $k$ [S1, unofficial]:
1.  Offset $(-1, -1, 1)$ with weight $(-1, -1, 1)$ [S1, unofficial].
2.  Offset $(1, -1, 1)$ with weight $(1, -1, 1)$ [S1, unofficial].
3.  Offset $(1, 1, -1)$ with weight $(1, 1, -1)$ [S1, unofficial].
4.  Offset $(1, 1, 1)$ with weight $(1, 1, 1)$ [S1, unofficial].
The sum is multiplied by $0.25$ to yield the final vector [S1, unofficial].

#### 3. Normalization and Encoding
1.  Compute magnitude: $L = \sqrt{g_x^2 + g_y^2 + g_z^2}$ [S3, unofficial].
2.  If $L > 10^{-6}$, normalize: $\mathbf{n} = \mathbf{g} / L$ [S3, unofficial]. Else, $\mathbf{n} = (0,0,0)$ [S3, unofficial].
3.  **Direction Encoding:** Map $\mathbf{n} \in [-1, 1]$ to $[0, 1]$ via $\mathbf{e} = \mathbf{n} \times 0.5 + 0.5$ [S3, unofficial]. Quantize to 8-bit integers: $out = \text{round}(\mathbf{e} \times 255)$ [S3, unofficial].
4.  **Magnitude Encoding:** Multiply magnitude by `grad_magnitude_modifier` and clamp to $[0, 1]$ [S1, unofficial]. For RG8 layout, scale typical max magnitude ($\sqrt{3}/2$) by $2.0$ to fit range [S3, unofficial].

### Pseudocode
```python
def compute_gradients(volume, resolution, magnitude_modifier=1.0):
    """
    Computes voxel gradients using central differences with explicit boundary handling.
    volume: 3D array of shape (Rx, Ry, Rz)
    resolution: tuple (Rx, Ry, Rz)
    returns: gradient_array of shape (Rx, Ry, Rz, 3) and magnitude_array of shape (Rx, Ry, Rz)
    """
    Rx, Ry, Rz = resolution
    gradients = [[[None for _ in range(Rz)] for _ in range(Ry)] for _ in range(Rx)]
    magnitudes = [[[None for _ in range(Rz)] for _ in range(Ry)] for _ in range(Rx)]
    
    for z in range(Rz):
        for y in range(Ry):
            for x in range(Rx):
                # Boundary handling for X
                if x == 0:
                    x0, x1, dx = 0, 1, 1.0
                elif x == Rx - 1:
                    x0, x1, dx = Rx - 2, Rx - 1, 1.0
                else:
                    x0, x1, dx = x - 1, x + 1, 2.0
                
                # Boundary handling for Y
                if y == 0:
                    y0, y1, dy = 0, 1, 1.0
                elif y == Ry - 1:
                    y0, y1, dy = Ry - 2, Ry - 1, 1.0
                else:
                    y0, y1, dy = y - 1, y + 1, 2.0

                # Boundary handling for Z
                if z == 0:
                    z0, z1, dz = 0, 1, 1.0
                elif z == Rz - 1:
                    z0, z1, dz = Rz - 2, Rz - 1, 1.0
                else:
                    z0, z1, dz = z - 1, z + 1, 2.0

                # Fetch values
                v_x0 = volume[x0][y][z]
                v_x1 = volume[x1][y][z]
                v_y0 = volume[x][y0][z]
                v_y1 = volume[x][y1][z]
                v_z0 = volume[x][y][z0]
                v_z1 = volume[x][y][z1]

                # Compute components
                gx = (v_x1 - v_x0) / dx
                gy = (v_y1 - v_y0) / dy
                gz = (v_z1 - v_z0) / dz

                # Normalize
                length = (gx*gx + gy*gy + gz*gz) ** 0.5
                if length > 1e-6:
                    nx, ny, nz = gx/length, gy/length, gz/length
                else:
                    nx, ny, nz = 0.0, 0.0, 0.0

                gradients[x][y][z] = (nx, ny, nz)
                magnitudes[x][y][z] = min(length * magnitude_modifier, 1.0)

    return gradients, magnitudes
```

### Parameters
*   **grad_magnitude_modifier:** Scalar multiplier applied to gradient magnitude before clamping, stored in a uniform buffer (binding 0, offset 0, 4 bytes) for GPU implementations [S1, unofficial].
*   **scale:** Factor (e.g., $2.0$) used to map gradient magnitudes to the $[0,1]$ range for specific texture formats [S3, unofficial].
*   **step:** Finite difference step size, computed as $0.01 \times \sqrt{\text{grid\_spacing}^2}$ in CGAL implementations [S5].

### Edge Cases and Pitfalls
*   **Zero Distance:** If the distance $d$ between points is exactly $0$, the gradient direction is undefined; assign a null vector [S5].
*   **Boundary Conditions:** Clamping coordinates prevents out-of-bounds reads but may introduce discontinuities at volume edges; repeating edge voxels is an alternative boundary strategy [S3, unofficial].
*   **Precision:** Central difference gradient components are often stored with signed 8-bit precision, representing values in the range $[-127, 127]$ [S4].

## Subtopics

### Gradient Map Generation
A specific GPU compute shader implementation that calculates gradients for all voxels and stores them in a 3D image buffer [S1, unofficial]. It uses the global invocation ID to map threads to voxels, computes the gradient vector, normalizes it, and stores the direction in RGB and the clamped magnitude (multiplied by `grad_magnitude_modifier`) in the Alpha channel of an `rgba8_snorm` texture [S1, unofficial].

### [Sobel Operator](1416-sobel-operator.md)
An efficient edge detecting operator used for gradient measurement in volume rendering, specifically for opacity function generation and shading. It is an isotropic operator with good localization and signal-to-noise characteristics.

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels, as each voxel requires a constant number of reads and arithmetic operations [S2, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the gradient array (3 floats per voxel) or texture [S2, unofficial].
*   **Performance:** On GPU, dispatching compute shaders with workgroups of size 8x8x8 allows efficient parallelization [S1, unofficial].
*   **Strengths:** Simple to implement; works on any discrete scalar field; provides necessary gradient data for lighting and isosurfacing [S3, unofficial, S4, S5].
*   **Limitations:** Boundary conditions require explicit handling to avoid out-of-bounds reads; hardware implementations may pipeline gradient estimation one voxel, one beam, and one slice behind the interpolation unit to access necessary data from previous and next slices [S4].

## Background
The method originates from standard numerical analysis techniques for approximating derivatives [S4]. In computer graphics, it is widely used in volume rendering for illumination and opacity modulation [S3, unofficial, S4], and in isosurfacing algorithms like Dual Contouring, where CGAL's `Finite_difference_gradient_3` class provides a robust implementation for computing gradients from discrete values [S5]. The tetrahedron-based variant is attributed to Iñaki Ñiguez [S1, unofficial].
