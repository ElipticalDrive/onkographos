# Gradient Computation via Finite Differences

Also called: Finite Difference Gradient, Central Difference Gradient, FD Gradient

## Overview
Gradient Computation via Finite Differences estimates the spatial gradient vector of a scalar volume at each voxel or sample position to provide surface normals for shading and opacity modulation [S1, S3]. It solves the problem of lacking analytical derivatives for discrete voxel data by approximating the gradient using neighboring sample values [S1]. Unlike the [Sobel Operator](1416-sobel-operator.md) which uses separable smoothing kernels to reduce noise, this method uses direct central differences, offering higher spatial accuracy at the cost of increased sensitivity to high-frequency noise [S1, S2].

## How it works
**Inputs:** A scalar volume texture or array $V$ with resolution $R = (R_x, R_y, R_z)$ and optional physical spacing $h_{phys} = (h_x, h_y, h_z)$.
**Outputs:** A gradient array $G$ storing 3D vectors, or a normalized normal map texture.

**Data Structures:**
1.  **Input Volume:** 3D texture or 1D array of size $N = R_x R_y R_z$. Layout is typically interleaved or planar. Access $V(x,y,z)$ returns a scalar.
2.  **Gradient Buffer:**
    *   *Float Array:* Size $N \times 3$, interleaved $(g_x, g_y, g_z)$ per voxel [S3].
    *   *Normalized Texture:* `RGBA8_SNORM` or `RG8` texture. `RGBA8_SNORM` stores normalized direction $(n_x, n_y, n_z)$ in RGB and magnitude in A or R/G [S2, S4].

**Parameters:**
*   `step_size`: The distance between sample points. If physical spacing is unknown, a unit step or small epsilon (e.g., $0.01 \times \text{diagonal}$) is used [S8].
*   `grad_magnitude_modifier`: Scalar multiplier for gradient magnitude before clamping [S2].
*   `scale`: Mapping factor for magnitude encoding (e.g., $2.0$ to map max magnitude $\sqrt{3}/2$ to $[0,1]$) [S4].

**Steps:**
1.  **Initialize:** Allocate output buffer $G$ of size $N \times 3$ or bind output image.
2.  **Iterate Voxels:** For each voxel $(i, j, k)$ where $0 \le i < R_x, 0 \le j < R_y, 0 \le k < R_z$:
    a.  **Determine Neighbors:** Identify indices for left/right, up/down, front/back neighbors. Handle boundaries by clamping coordinates to $[0, R-1]$ or repeating edge voxels [S4, S7].
    b.  **Fetch Values:** Retrieve scalar values $v_{pos}$ and $v_{neg}$ for each axis.
    c.  **Compute Components:** Calculate central differences.
        $$g_x = \frac{V(i+1, j, k) - V(i-1, j, k)}{2 \cdot h_x}$$
        $$g_y = \frac{V(i, j+1, k) - V(i, j-1, k)}{2 \cdot h_y}$$
        $$g_z = \frac{V(i, j, k+1) - V(i, j, k-1)}{2 \cdot h_z}$$
        If physical spacing is uniform and normalized to $[0,1]$, $h_x=h_y=h_z=1$ (or $1/(R-1)$ depending on coordinate system) [S4, S7].
    d.  **Store/Encode:**
        *   *Float:* Store $(g_x, g_y, g_z)$ in $G$.
        *   *Normalized:* Compute length $L = \sqrt{g_x^2 + g_y^2 + g_z^2}$. If $L > \epsilon$, normalize $\mathbf{n} = \mathbf{g}/L$. Encode $\mathbf{n}$ to $[0,1]$ via $c = \mathbf{n} \cdot 0.5 + 0.5$ and quantize to 8-bit integers [S4]. Store magnitude separately if required [S2].

**Pseudocode (CPU/General):**
```python
def compute_gradients(volume, resolution, spacing=(1.0, 1.0, 1.0)):
    """
    volume: 3D array or function V(x,y,z)
    resolution: tuple (Rx, Ry, Rz)
    spacing: tuple (hx, hy, hz)
    """
    Rx, Ry, Rz = resolution
    hx, hy, hz = spacing
    gradients = [] # List of vec3
    
    for z in range(Rz):
        for y in range(Ry):
            for x in range(Rx):
                # Clamp neighbors to valid range
                x_prev = max(x - 1, 0)
                x_next = min(x + 1, Rx - 1)
                y_prev = max(y - 1, 0)
                y_next = min(y + 1, Ry - 1)
                z_prev = max(z - 1, 0)
                z_next = min(z + 1, Rz - 1)
                
                # Fetch values
                v_left = volume[x_prev, y, z]
                v_right = volume[x_next, y, z]
                v_down = volume[x, y_prev, z]
                v_up = volume[x, y_next, z]
                v_back = volume[x, y, z_prev]
                v_front = volume[x, y, z_next]
                
                # Compute central differences
                gx = (v_right - v_left) / (2.0 * hx)
                gy = (v_up - v_down) / (2.0 * hy)
                gz = (v_front - v_back) / (2.0 * hz)
                
                gradients.append((gx, gy, gz))
                
    return gradients
```

**Pseudocode (GPU Compute Shader):**
```glsl
#version 450
layout(local_size_x = 8, local_size_y = 8, local_size_z = 8) in;

layout(binding = 0, r8) uniform readonly image3D uVolume;
layout(binding = 1, rgba8_snorm) uniform writeonly image3D uGradientMap;
layout(binding = 2, r32f) uniform readonly image3D uSpacing; // Or uniform float

void main() {
    ivec3 texSize = imageSize(uVolume);
    ivec3 pos = ivec3(gl_GlobalInvocationID);
    
    // Check bounds
    if (any(greaterThan(pos, texSize - 1))) return;
    
    vec3 spacing = texelFetch(uSpacing, pos, 0).xyz;
    if (spacing.x == 0.0) spacing.x = 1.0; // Fallback
    if (spacing.y == 0.0) spacing.y = 1.0;
    if (spacing.z == 0.0) spacing.z = 1.0;
    
    // Neighbor coordinates with clamping
    ivec3 p_prev = max(pos - 1, 0);
    ivec3 p_next = min(pos + 1, texSize - 1);
    
    // Fetch scalar values
    float v_left = float(imageLoad(uVolume, p_prev).r);
    float v_right = float(imageLoad(uVolume, p_next).r);
    
    ivec3 p_down = ivec3(pos.x, max(pos.y - 1, 0), pos.z);
    ivec3 p_up = ivec3(pos.x, min(pos.y + 1, texSize.y - 1), pos.z);
    float v_down = float(imageLoad(uVolume, p_down).r);
    float v_up = float(imageLoad(uVolume, p_up).r);
    
    ivec3 p_back = ivec3(pos.x, pos.y, max(pos.z - 1, 0));
    ivec3 p_front = ivec3(pos.x, pos.y, min(pos.z + 1, texSize.z - 1));
    float v_back = float(imageLoad(uVolume, p_back).r);
    float v_front = float(imageLoad(uVolume, p_front).r);
    
    // Compute gradient components
    vec3 grad;
    grad.x = (v_right - v_left) / (2.0 * spacing.x);
    grad.y = (v_up - v_down) / (2.0 * spacing.y);
    grad.z = (v_front - v_back) / (2.0 * spacing.z);
    
    // Normalize and encode
    float len = length(grad);
    vec3 normal = vec3(0.0);
    if (len > 1e-6) {
        normal = grad / len;
    }
    
    // Encode to [0, 1] for SNORM texture
    vec4 enc = vec4(normal * 0.5 + 0.5, 0.0);
    imageStore(uGradientMap, pos, enc);
}
```

## Subtopics

### [Gradient-based Diffuse Lighting with Alpha Blending](1257-gradient-based-diffuse-lighting-with-alpha-blending.md)
This method applies diffuse lighting to a scalar volume by estimating surface normals from voxel gradients and compositing the lit color into a framebuffer using front-to-back alpha blending. It differs from its parent, [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md), by integrating the lighting calculation and compositing step directly into the rendering loop, rather than just storing precomputed gradients. It is distinct from the [Sobel Operator](1416-sobel-operator.md) sibling, which is a specific kernel-based gradient estimation technique, whereas this method uses central differences for gradient estimation within the lighting context.

### [Sobel Operator](1416-sobel-operator.md)
The Sobel Operator is a gradient estimation method used in volume rendering to compute the spatial gradient vector for each voxel in a scalar volume. It solves the problem of determining the rate of change of data values to generate opacity functions and shading normals, emphasizing regions of high spatial frequency corresponding to edges. Unlike general edge detection where spatial location is critical, in volume rendering opacity functions are applied uniformly regardless of position, so the goal is to locate boundaries in the data value domain rather than the spatial domain. It is distinguished from its sibling [Gradient-based Diffuse Lighting with Alpha Blending](1257-gradient-based-diffuse-lighting-with-alpha-blending.md) by being a fundamental gradient computation primitive rather than a lighting model, and from [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md) by using separable smoothing weights that make it less sensitive to noise than simple central differences.

### Gradient Map Generation
A compute shader pass that calculates gradients for all voxels in the volume and stores them in a gradient map image, including magnitude and direction [S2]. It computes the gradient vector for each voxel, normalizes the direction, calculates the magnitude (optionally scaled by `grad_magnitude_modifier` and clamped to $[0,1]$), and stores the normalized direction in the RGB components and magnitude in the W component of a `rgba8_snorm` image buffer [S2].

### Voxel Gradient Calculation
A pre-processing step using the Sobel operator to detect edges within the volume and compute gradients [S9]. The gradient magnitude is used to modulate voxel opacity (making homogeneous regions invisible), and the gradient direction is used for shading [S9].

### Analytic Gradient Computation
A method to compute gradient vectors for local shading (BRDF) using analytic derivatives of the basis reconstruction function, avoiding additional samples or ray traversals [S10]. The gradient is computed as the first-order partial derivatives of the basis reconstruction equation. For example, the x-derivative involves the basis function component $\hat{h}$, cell width $C_w$, and a sign function $\chi(x)$ [S10]. Unlike central differencing, which requires 6 additional basis reconstruction samples and ray traversals, analytic gradients use only existing data values [S10]. However, analytic gradients are not continuously differentiable, leading to shading artifacts at cell and level boundaries, whereas central differences are continuous but expensive [S10].

### Clamped Central Differences
A variant of central differencing for gradient computation that clamps offset positions to the current region to avoid additional ray traversals [S10]. It computes six additional basis reconstruction samples at positions offset from the current sample by a distance proportional to the region's sample rate, then clamps these offsets to the current region before evaluation [S10]. While this removes the cost of additional ray traversals, gradients are not necessarily continuous at level boundaries because the offset size can change [S10]. Accurate central differencing requires tracing 6 additional rays per sample via infinitesimal rays to find containing regions, which is expensive; the clamped version reduces quality but improves performance [S10].

### Gradient Estimation from Samples
A method to compute gradient vectors for volume shading using only the samples taken for reconstruction, avoiding additional expensive computations [S10].

## Operating characteristics
**Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel requires a constant number of reads (6 neighbors) and arithmetic operations [S3].
**Memory Complexity:** $O(N)$ for storing the gradient array, typically 3 floats (12 bytes) or 4 bytes (normalized) per voxel [S3, S4].
**Performance:** On GPU, this is highly parallelizable and fits well into compute shaders or fragment shaders during ray marching [S2]. VolumePro implements this in hardware, operating one voxel behind the interpolation unit to buffer necessary data from previous/next slices, using signed 8-bit precision for components [S6].
**Strengths:** Simple to implement; provides accurate normals for smooth regions; compatible with standard ray marching pipelines [S1, S6].
**Limitations:** Sensitive to noise in the volume data; boundary handling requires care (clamping vs. reflection) [S1, S4]. Analytic alternatives are faster for specific basis functions but lack continuity [S10].

## Background
The method originates from standard numerical analysis techniques for approximating derivatives. In volume rendering, it was popularized for adding visual cues like directional light and Phong shading to scalar fields [S1]. It is widely used in real-time ray casting systems like VolumePro, which hardware-accelerates the estimation using buffering units [S6]. It is also a core component in isosurfacing libraries like CGAL, where `Finite_difference_gradient_3` computes gradients from discrete values for dual contouring [S8].
