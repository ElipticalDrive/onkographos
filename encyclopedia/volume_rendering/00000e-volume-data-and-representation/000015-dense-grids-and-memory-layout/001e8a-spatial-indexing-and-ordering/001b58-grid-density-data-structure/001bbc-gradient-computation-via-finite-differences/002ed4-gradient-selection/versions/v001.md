# Gradient Selection

Also called: Gradient Mode Selection

## Overview
Gradient Selection determines which finite difference stencil is used to compute the 3D gradient vector for each voxel in a scalar volume. It acts as a runtime switch between Central Difference and Sobel gradient estimation methods, allowing the renderer to choose between higher accuracy and noise robustness. It builds on [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md) by abstracting the specific stencil choice behind a uniform parameter.

## How it works
**Inputs:**
- `textureCoord`: The normalized 3D texture coordinate $(u, v, w)$ for the current voxel.
- `gradientMode`: An integer uniform specifying the desired estimation mode.

**Outputs:**
- `gradient`: A 3D vector $(g_x, g_y, g_z)$ representing the gradient at the given coordinate.

**Data Structures:**
- `gradientMode`: Integer constant.
  - `GRADIENT_CENTRAL`: Selects Central Difference.
  - `GRADIENT_SOBEL`: Selects Sobel.

**Steps:**
1. Evaluate the `gradientMode` uniform.
2. If `gradientMode == GRADIENT_SOBEL`, compute the gradient using the Sobel operator.
3. Otherwise, compute the gradient using the Central Difference operator.

**Formulas:**
The underlying formulas for the sub-methods are defined in their respective articles:
- Central Difference: $g_i = \frac{V(x_i + h) - V(x_i - h)}{2h}$ [S1, 1077-gradient-computation-via-finite-differences.md, unofficial].
- Sobel: Weighted average of neighbors in a 3x3x3 kernel [S1, 1204-gradient-map-generation.md, unofficial].

    """
    Selects and computes the gradient based on the specified mode.
    
    Args:
        texture_coord: vec3, normalized coordinates [0, 1]
        gradient_mode: int, GRADIENT_CENTRAL or GRADIENT_SOBEL
        
    Returns:
        vec3, the computed gradient vector
    """
    if gradient_mode == GRADIENT_SOBEL:
        return gradient_sobel(texture_coord)
    else:
        return gradient_central(texture_coord)

**Parameters:**
- `gradientMode`: Controls the trade-off. Central Difference is generally more accurate for smooth data; Sobel is more robust to noise [S1, unofficial].

**Edge Cases:**
- Boundary conditions: Both underlying methods require handling voxels near the volume boundaries where neighbors fall outside the grid. This is typically handled by clamping, reflection, or periodic extension in the underlying sampling functions.

## Subtopics

### [Cubic Shading](9681-cubic-shading.md)
An extension that uses all 26 neighbors in a 3x3x3 window for gradient calculation, offering higher accuracy than the 6-neighbor orthogonal approach. Choose when high-fidelity shading is required and performance allows.

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel, as it involves a fixed number of texture lookups (9 for Sobel, 7 for Central Difference including center).
- **Memory Complexity:** $O(1)$ additional memory, as it does not store intermediate gradient data structures beyond the output vector.
- **Strengths:** Simple runtime switch; no preprocessing required for the selection itself.
- **Limitations:** The quality of the gradient depends entirely on the chosen stencil. Sobel may introduce directional bias; Central Difference may amplify noise.
- **When to use:** Use Central Difference for smooth, high-resolution volumes. Use Sobel for noisy or lower-resolution data where edge preservation is critical.

## Background
Gradient Selection is a common pattern in GPU-based volume rendering shaders, particularly in WebGL implementations. It allows developers to toggle between accuracy and robustness without recompiling shaders. The specific implementation cited here is from an unofficial GitHub repository [S1, unofficial].
