# Gradient Magnitude Computation

Also called: Magnitude Grid Computation

## Overview
Computes the Euclidean norm of the gradient vector at every active voxel of a vector grid, producing a scalar magnitude grid. It differs from [Gradient Map Generation](1204-gradient-map-generation.md) by outputting a scalar field rather than a texture, and from [Sobel Operator](1416-sobel-operator.md) by operating on pre-computed gradient vectors rather than deriving them from scalar data. It serves as a foundational step for [Gradient-based Diffuse Lighting with Alpha Blending](1257-gradient-based-diffuse-lighting-with-alpha-blending.md) and [Analytic Gradient Computation](2167-analytic-gradient-computation.md) where scalar intensity of change is required.

## How it works
**Inputs:** A vector grid where each active voxel stores a 3D gradient vector $\mathbf{v} = (v_x, v_y, v_z)$.
**Outputs:** A scalar grid where each active voxel stores the magnitude $|\mathbf{v}|$.

**Data Structures:**
The input is typically a hierarchical data structure (e.g., a tree of tiles or blocks) containing active voxels. Each active voxel holds a vector type. The output is a scalar grid with the same topology (active voxel locations, voxel size, background value).

**Steps:**
1. Iterate over all active voxels in the input grid. Let the coordinate of a voxel be $c$ and its gradient vector be $\mathbf{v}_c$.
2. For each active voxel, compute the Euclidean norm:
   $$ |\mathbf{v}_c| = \sqrt{v_{c,x}^2 + v_{c,y}^2 + v_{c,z}^2} $$
3. Store the computed magnitude in a result structure keyed by coordinate $c$.
4. Construct the output scalar grid using the computed magnitudes, a background value of zero, and the original grid's voxel size and topology.

**Pseudocode:**
```python
def compute_gradient_magnitude(input_vector_grid):
    """
    Computes the Euclidean norm of gradient vectors for all active voxels.
    
    Args:
        input_vector_grid: A structure supporting iteration over active voxels.
                           Each voxel yields a coordinate and a Vec3 gradient.
                           
    Returns:
        output_scalar_grid: A scalar grid with magnitudes at active voxels,
                            zero background, and same topology as input.
    """
    # Initialize result storage
    # In a dense implementation, this might be a pre-allocated array.
    # In a sparse implementation, a dictionary or sparse list.
    magnitudes = {}

    # Iterate over all active voxels
    for coord, gradient_vector in input_vector_grid.active_voxels():
        # Extract components
        vx = gradient_vector.x
        vy = gradient_vector.y
        vz = gradient_vector.z
        
        # Compute Euclidean norm
        magnitude = sqrt(vx*vx + vy*vy + vz*vz)
        
        # Store result
        magnitudes[coord] = magnitude

    # Build the output grid
    # Assumes a constructor that takes a map of active values, background, and metadata
    output_grid = ScalarGrid(
        active_values=magnitudes,
        background_value=0.0,
        voxel_size=input_vector_grid.voxel_size,
        topology=input_vector_grid.topology
    )
    
    return output_grid
```

**Edge Cases and Pitfalls:**
- **Zero Vectors:** If $\mathbf{v} = (0,0,0)$, the magnitude is 0. This is handled correctly by the formula.
- **NaN/Inf:** If input gradients contain NaN or Inf, the output will propagate these values. Input validation is not part of this method but should be considered upstream.
- **Background Voxels:** Inactive/background voxels are explicitly set to 0.0 in the output grid, not computed from neighbors.

## Subtopics

### Godunov Norm Squared Computation
Computes the squared Godunov norm for gradient components, used in high-resolution shock-capturing schemes. It distinguishes itself by handling negative and positive gradient components separately to ensure monotonicity. It is chosen when solving hyperbolic conservation laws on grids. It takes a boolean `isOutside` flag, gradient vectors for negative and positive sides (`gradient_m`, `gradient_p`), or individual scalar components (`dP_xm`, `dP_xp`, etc.). The implementation checks if the point is outside the domain; if so, it may return zero or a boundary value. Otherwise, it combines the components using a Godunov-style scheme that considers the sign of the gradients to prevent oscillations. The squared norm is computed to avoid square roots for efficiency in some solvers.

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of active voxels. Each voxel requires a constant number of arithmetic operations (3 multiplications, 2 additions, 1 square root).
- **Memory Complexity:** $O(N)$ for the output grid. The input grid is read-only.
- **Performance:** The operation is memory-bandwidth bound if the input and output grids are large and do not fit in cache. The square root operation is relatively expensive compared to basic arithmetic, but modern CPUs/GPUs have hardware-accelerated `sqrt`.
- **Strengths:** Simple, parallelizable, numerically stable for non-zero vectors.
- **Limitations:** Does not handle inactive voxels (they are zeroed). Sensitive to noise in gradient vectors if the gradients are noisy.
- **When to use:** When scalar intensity of gradient is needed for lighting, compositing, or further scalar field analysis.
- **When not to use:** When vector direction is needed (use [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md) directly) or when robustness to noise is critical (consider smoothing first).

## Background
The computation of gradient magnitude is a standard operation in image and volume processing. In the context of sparse grid data structures like OpenVDB, it is often used in conjunction with [Scanline Gradient Computation](3582-scanline-gradient-computation.md) or [Gradient Estimation from Samples](2180-gradient-estimation-from-samples.md) to derive scalar fields from vector fields. The Godunov variant is specific to computational fluid dynamics and high-resolution schemes, as seen in OpenVDB's math utilities.
