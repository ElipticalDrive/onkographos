# Depth and Image Gradient Regularization

Also called: Curvature Regularization with Gradient Masking, Depth Regularization with Image Gradient Weighting

## Overview
This method applies a regularization loss to predicted depth maps by penalizing second-order spatial derivatives (curvature) of the depth, weighted exponentially by the local image gradient magnitude. It solves the problem of noisy or jagged depth predictions in differentiable rendering pipelines by enforcing smoothness in textureless regions while preserving sharp discontinuities at object boundaries. It differs from sibling methods like [Laplacian Grid Computation](3160-laplacian-grid-computation.md) by explicitly incorporating image gradient information to create a spatially adaptive smoothing mask, rather than applying uniform or purely geometric smoothing.

## How it works
**Inputs and Outputs**
- **Input**: A predicted depth map $D$ of size $H \times W$, where $D[\mathbf{u}]$ is the depth value at pixel coordinate $\mathbf{u} = (x, y)$. An input image $\mathbf{I}$ of size $H \times W$, where $\mathbf{I}[\mathbf{u}]$ is the pixel intensity (scalar or per-channel) at $\mathbf{u}$.
- **Output**: A scalar regularization loss value $\mathcal{L}_{\text{reg. depth}}$.

**Data Structures**
- $D$: 2D array of floats, shape $(H, W)$.
- $\mathbf{I}$: 2D array of floats, shape $(H, W)$ or $(H, W, C)$. If multi-channel, the gradient magnitude is computed per channel and aggregated (typically max or mean, though the source implies a scalar intensity context or per-pixel max).

**Definitions**
- $\mathbf{u}_{x-1} = (x-1, y)$, $\mathbf{u}_{x+1} = (x+1, y)$, $\mathbf{u}_{y-1} = (x, y-1)$, $\mathbf{u}_{y+1} = (x, y+1)$.
- Boundary conditions: For pixels on the image border, neighbors outside the image are assumed to have the same depth/intensity as the boundary pixel (clamp-to-edge) or the term is omitted. The source does not explicitly specify boundary handling, but standard finite difference implementations clamp. [G] We assume clamp-to-edge padding for robustness.

**Formulas**
1. **Horizontal Depth Second Derivative**:
   $$ D_x^{\Delta}[\mathbf{u}] = D[\mathbf{u}_{x-1}, \mathbf{u}_y] - 2D[\mathbf{u}_x, \mathbf{u}_y] + D[\mathbf{u}_{x+1}, \mathbf{u}_y] $$
2. **Vertical Depth Second Derivative**:
   $$ D_y^{\Delta}[\mathbf{u}] = D[\mathbf{u}_x, \mathbf{u}_{y-1}] - 2D[\mathbf{u}_x, \mathbf{u}_y] + D[\mathbf{u}_x, \mathbf{u}_{y+1}] $$
3. **Horizontal Image Gradient Magnitude (L-infinity norm)**:
   $$ \mathbf{I}_x^{\Delta}[\mathbf{u}] = \max\left( |\mathbf{I}[\mathbf{u}_{x-1}, \mathbf{u}_y] - \mathbf{I}[\mathbf{u}_x, \mathbf{u}_y]|, |\mathbf{I}[\mathbf{u}_{x+1}, \mathbf{u}_y] - \mathbf{I}[\mathbf{u}_x, \mathbf{u}_y]| \right) $$
4. **Vertical Image Gradient Magnitude (L-infinity norm)**:
   $$ \mathbf{I}_y^{\Delta}[\mathbf{u}] = \max\left( |\mathbf{I}[\mathbf{u}_x, \mathbf{u}_{y-1}] - \mathbf{I}[\mathbf{u}_x, \mathbf{u}_y]|, |\mathbf{I}[\mathbf{u}_x, \mathbf{u}_{y+1}] - \mathbf{I}[\mathbf{u}_x, \mathbf{u}_y]| \right) $$
5. **Regularization Loss**:
   $$ \mathcal{L}_{\text{reg. depth}}[\mathbf{u}] = D_x^{\Delta}[\mathbf{u}] \exp\left(8 \cdot \mathbf{I}_x^{\Delta}[\mathbf{u}]\right) + D_y^{\Delta}[\mathbf{u}] \exp\left(8 \cdot \mathbf{I}_y^{\Delta}[\mathbf{u}]\right) $$
   The total loss is the sum (or mean) of $\mathcal{L}_{\text{reg. depth}}[\mathbf{u}]$ over all valid pixels $\mathbf{u}$.

**Parameters**
- Weighting factor in exponential: $8$ [S1].

**Pseudocode**
```python
import numpy as np

def depth_gradient_regularization(D: np.ndarray, I: np.ndarray) -> float:
    """
    Compute depth regularization loss weighted by image gradients.
    
    Args:
        D: Depth map of shape (H, W).
        I: Image intensity of shape (H, W) or (H, W, C).
        
    Returns:
        Scalar regularization loss.
    """
    H, W = D.shape
    
    # Pad inputs with clamp-to-edge to handle boundaries
    D_pad = np.pad(D, pad_width=1, mode='edge')
    I_pad = np.pad(I, pad_width=1, mode='edge')
    
    # Extract neighbors for horizontal differences
    D_left = D_pad[1:-1, :-2]
    D_right = D_pad[1:-1, 2:]
    D_center = D_pad[1:-1, 1:-1]
    
    I_left = I_pad[1:-1, :-2]
    I_right = I_pad[1:-1, 2:]
    I_center = I_pad[1:-1, 1:-1]
    
    # Horizontal depth second derivative
    Dx = D_left - 2 * D_center + D_right
    
    # Horizontal image gradient magnitude (L-infinity)
    # Handle multi-channel I by taking max over channels if needed, 
    # but source implies scalar or per-pixel max. Assuming I is scalar or 
    # we compute magnitude per channel and take max.
    if I_pad.ndim == 3:
        # Compute abs diff for each channel
        diff_left = np.abs(I_left - I_center)
        diff_right = np.abs(I_right - I_center)
        # Max over spatial neighbors, then max over channels if necessary?
        # Source says max(|I[x-1]-I[x]|, |I[x+1]-I[x]|). 
        # If I is multi-channel, we assume scalar intensity or max over channels.
        # Let's assume I is converted to scalar intensity (e.g. luminance) or 
        # the formula applies to each channel and we aggregate. 
        # Given "I[ux, uy]" notation, let's assume scalar for simplicity or 
        # that I is already a single channel intensity map.
        pass
    
    # Compute horizontal gradient magnitude
    diff_left = np.abs(I_left - I_center)
    diff_right = np.abs(I_right - I_center)
    Ix = np.maximum(diff_left, diff_right)
    
    # Extract neighbors for vertical differences
    D_up = D_pad[:-2, 1:-1]
    D_down = D_pad[2:, 1:-1]
    
    I_up = I_pad[:-2, 1:-1]
    I_down = I_pad[2:, 1:-1]
    
    # Vertical depth second derivative
    Dy = D_up - 2 * D_center + D_down
    
    # Vertical image gradient magnitude
    diff_up = np.abs(I_up - I_center)
    diff_down = np.abs(I_down - I_center)
    Iy = np.maximum(diff_up, diff_down)
    
    # Compute exponential weights
    # Note: Source uses exp(8 * I). If I is large, this can overflow.
    # In practice, I might be normalized.
    weight_x = np.exp(8 * Ix)
    weight_y = np.exp(8 * Iy)
    
    # Compute loss per pixel
    loss_x = Dx * weight_x
    loss_y = Dy * weight_y
    
    total_loss = np.sum(loss_x + loss_y)
    
    return total_loss
```

**Edge Cases and Pitfalls**
- **Overflow**: The term $\exp(8 \cdot \mathbf{I}^{\Delta})$ can overflow if image gradients are large. Ensure $\mathbf{I}$ is normalized to a small range (e.g., [0, 1]) before computation.
- **Boundary Pixels**: The finite difference stencil requires neighbors. Clamp-to-edge padding is a standard choice [G].
- **Sign of Loss**: The depth second derivative $D_x^{\Delta}$ can be positive or negative. The loss is not an absolute value, so it penalizes curvature in a signed manner. This may encourage specific curvature directions. The source does not specify taking the absolute value of the depth derivative.

## Operating characteristics
- **Time Complexity**: $O(H \cdot W)$ for computing derivatives and the loss. The exponential and multiplication are element-wise.
- **Memory Complexity**: $O(H \cdot W)$ for storing intermediate gradient maps and padded inputs.
- **Strengths**: Preserves sharp depth edges where image gradients are high (object boundaries), while smoothing depth in textureless regions.
- **Limitations**: Sensitive to noise in the image $\mathbf{I}$; noisy images may lead to incorrect gradient masks. The exponential weighting can be aggressive if not normalized.
- **When to use**: Differentiable rendering pipelines where depth consistency with image edges is critical, such as in [PixelSplat](https://doi.org/10.1109/cvpr52733.2024.01840).
- **When not to use**: When the image is noisy or lacks texture, as the gradient mask may fail to preserve true depth discontinuities.

## Background
This method was introduced in the context of 3D Gaussian Splatting from image pairs, specifically in the [PixelSplat](https://doi.org/10.1109/cvpr52733.2024.01840) paper [S1]. It is used to regularize the predicted depth maps during the training of generalizable 3D reconstruction models, ensuring that the depth predictions are smooth but respect the edges present in the input images.
