# Eikonal Omega Term Computation

Also called: Double backprop for Eikonal term, Second-order dOmega

## Overview
Computes the gradient of the Eikonal constraint term with respect to the hash grid encoding features, enabling training of neural implicit surfaces via second-order derivative backpropagation [S1, unofficial]. It differs from standard first-order gradient methods by explicitly handling the chain rule through the alpha scaling factor and optional second-order derivative tensors, supporting both "double backprop" and "second-order dOmega" implementations [S1, unofficial].

## How it works
**Inputs:**
- `x_pre`: Input coordinates tensor of shape $(N, 3)$, where $N$ is the number of points [S1, unofficial].
- `feature_table`: Hash grid feature tensor of shape $(L, F)$, where $L$ is the total number of features across all levels and $F$ is the feature dimension [S1, unofficial].
- `resolutions`: Array of integer grid resolutions for each level [S1, unofficial].
- `cube_vertices`: Array defining the 8 vertices of a cube, used for tetrahedron selection [S1, unofficial].
- `tetrahedra_index`: Array mapping cube vertices to tetrahedra indices [S1, unofficial].
- `prime_factors`: Array of three prime numbers used for hashing grid coordinates to table indices [S1, unofficial].
- `g_de`: Gradient tensor related to the encoding output [S1, unofficial].
- `alpha_dn`: Scaling factor tensor for the Eikonal term [S1, unofficial].
- `z_dalpha_dx_de`: Optional tensor for second-order derivative information [S1, unofficial].
- `table_size`: Size of the hash table [S1, unofficial].

**Outputs:**
- `g_feature_table`: Gradient tensor with respect to `feature_table`, same shape as `feature_table` [S1, unofficial].
- `grad_x_pre`, `grad_resolutions`, etc.: Other gradients are returned as `None` or not computed in this specific backward pass implementation [S1, unofficial].

**Data Structures:**
- The hash grid uses a sparse hash table of size `table_size`. Coordinates $(x, y, z)$ are hashed using prime factors to determine the table index [S1, unofficial].
- Tetrahedral interpolation is performed within a cube defined by `cube_vertices`. The cube is split into 6 tetrahedra based on the fractional coordinates $(f_x, f_y, f_z)$ [S1, unofficial].

**Steps:**
1. **Forward Pass (Context Saving):**
   - Save all input tensors (`x_pre`, `feature_table`, `resolutions`, `cube_vertices`, `tetrahedra_index`, `prime_factors`, `g_de`, `alpha_dn`, `z_dalpha_dx_de`, `F_tensor`, `table_size_tensor`) to the autograd context [S1, unofficial].
   - Return a scalar zero tensor of the same device and dtype as `x_pre` [S1, unofficial].

2. **Backward Pass:**
   - Retrieve saved tensors from context [S1, unofficial].
   - Compute `scale` as the value of the incoming gradient `grad_out` [S1, unofficial].
   - Extract dimensions $N$ (number of points), $L$ (number of levels/features), $F$ (feature dimension), and `table_size` [S1, unofficial].
   - Initialize `g_feature_table` as a zero tensor of the same shape as `feature_table` [S1, unofficial].
   - Determine the implementation mode:
     - If `_tetra_db_double` is available:
       - If `z_dalpha_dx_de` is empty (numel == 0), set $z$ to a zero tensor of shape $(N, L \times F)$ [S1, unofficial].
       - Otherwise, set $z = (z\_dalpha\_dx\_de \times scale).contiguous().float()$ [S1, unofficial].
       - Call `_tetra_db_double` with inputs: `x_pre`, `feature_table`, $z$, `g_de`, `(alpha_dn * scale)`, `resolutions`, `g_feature_table`, $N$, $L$, $F$, `table_size`, `cube_vertices`, `tetrahedra_index`, `prime_factors` [S1, unofficial].
     - Else if `_tetra_db_second` is available:
       - Call `_tetra_db_second` with inputs: `x_pre`, `g_de`, `(alpha_dn * scale)`, `resolutions`, `g_feature_table`, $N$, $L$, $F$, `table_size`, `cube_vertices`, `tetrahedra_index`, `prime_factors` [S1, unofficial].
     - Else raise `RuntimeError` [S1, unofficial].
   - Return gradients: `grad_x_pre=None`, `grad_feature_table=g_feature_table`, `grad_resolutions=None`, `grad_cv=None`, `grad_ti=None`, `grad_pf=None`, `grad_g_de=None`, `grad_alpha_dn=None`, `grad_z=None`, `grad_F=None`, `grad_table_size=None` [S1, unofficial].

**Pseudocode:**
```python
import torch

def eikonal_omega_backward(grad_out, x_pre, feature_table, resolutions, cube_vertices, 
                           tetrahedra_index, prime_factors, g_de, alpha_dn, z_dalpha_dx_de, 
                           table_size, N, L, F):
    """
    Backward pass for Eikonal Omega Term Computation.
    """
    scale = float(grad_out.item())
    
    # Initialize gradient tensor for features
    g_feature_table = torch.zeros_like(feature_table)
    
    # Prepare z tensor based on second-order derivative info
    if z_dalpha_dx_de is not None and z_dalpha_dx_de.numel() > 0:
        z = (z_dalpha_dx_de * scale).contiguous().float()
    else:
        z = torch.zeros((N, L * F), device=x_pre.device, dtype=torch.float32)
        
    # Prepare scaled alpha_dn
    alpha_dn_scaled = (alpha_dn * scale).contiguous().float()
    
    # Prepare other inputs
    x_pre_cont = x_pre.contiguous().float()
    feature_table_cont = feature_table.contiguous().float()
    g_de_cont = g_de.contiguous().float()
    resolutions_cont = resolutions.contiguous()
    cube_vertices_cont = cube_vertices.contiguous()
    tetrahedra_index_cont = tetrahedra_index.contiguous()
    prime_factors_cont = prime_factors.contiguous()
    
    # Choose implementation
    if _tetra_db_double_available:
        _tetra_db_double(
            x_pre_cont, feature_table_cont, z, g_de_cont, alpha_dn_scaled,
            resolutions_cont, g_feature_table, N, L, F, table_size,
            cube_vertices_cont, tetrahedra_index_cont, prime_factors_cont
        )
    elif _tetra_db_second_available:
        _tetra_db_second(
            x_pre_cont, g_de_cont, alpha_dn_scaled, resolutions_cont,
            g_feature_table, N, L, F, table_size,
            cube_vertices_cont, tetrahedra_index_cont, prime_factors_cont
        )
    else:
        raise RuntimeError("No Eikonal Omega backward implementation available")
        
    return None, g_feature_table, None, None, None, None, None, None, None, None, None
```

**Parameters:**
- `x_pre`: Input coordinates tensor [S1, unofficial].
- `g_de`: Gradient tensor related to the encoding [S1, unofficial].
- `alpha_dn`: Scaling factor tensor for the Eikonal term [S1, unofficial].
- `z_dalpha_dx_de`: Optional tensor for second-order derivative information [S1, unofficial].

**Edge Cases and Pitfalls:**
- If `z_dalpha_dx_de` is None or empty, it is treated as a zero tensor [S1, unofficial].
- Boundary handling for grid coordinates is managed by `pos_fract_resm1` which clamps grid indices to $[0, res-1]$ [S1, unofficial].
- Hash collisions are handled by the prime factor-based hashing scheme [S1, unofficial].

## Background
This method is part of the TetraSDF framework, which uses tetrahedral interpolation for neural implicit surface representation [S1, unofficial]. The Eikonal term is crucial for enforcing the unit gradient magnitude constraint on the signed distance function [S1, unofficial].
