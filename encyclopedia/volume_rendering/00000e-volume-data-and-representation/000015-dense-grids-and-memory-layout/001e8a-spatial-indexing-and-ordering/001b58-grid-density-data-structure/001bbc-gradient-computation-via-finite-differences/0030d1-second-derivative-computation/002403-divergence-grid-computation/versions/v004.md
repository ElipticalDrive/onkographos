# Divergence Grid Computation

Also called: Divergence Calculation with Obstacle Velocity Boundary Conditions, Divergence Computation, Finite Difference Divergence

## Overview
Computes the divergence $\nabla \cdot \mathbf{F}$ of a vector field grid (typically velocity) at every active voxel using central differences [S1, S2, unofficial]. It is distinguished from sibling methods like [Laplacian Grid Computation](3160-laplacian-grid-computation.md) by operating on vector fields rather than scalar fields, and specifically handles solid boundaries by substituting obstacle velocities for fluid velocities at cell interfaces [S2, unofficial].

## How it works
**Inputs:** A 3D vector grid $\mathbf{V}$ where each active voxel stores a velocity vector $(v_x, v_y, v_z)$. A boundary mask or function `IsBoundaryCell` identifying solid/obstacle voxels. An obstacle velocity field $\mathbf{V}_{obs}$ providing the velocity at solid boundaries (often zero or rigid body motion).

**Outputs:** A scalar grid $D$ storing the divergence value at each active voxel.

**Data Structures:**
- **Input Grid:** Sparse or dense 3D grid. Each voxel at index $(i,j,k)$ holds a vector $\mathbf{v}_{i,j,k} = (v_x, v_y, v_z)$.
- **Stencil:** A local access pattern retrieving the 6 face-neighbors of the current voxel: Left ($L$), Right ($R$), Bottom ($B$), Top ($T$), Down ($D$), Up ($U$).
- **Result Grid:** Sparse or dense 3D grid with the same topology as the input, storing scalar values. Background value is 0.

**Steps:**
1. Initialize a stencil context with the grid topology and voxel size $\Delta x$ [S1, unofficial].
2. Iterate over all active voxels $c$ in the grid [S1, unofficial].
3. For each active voxel $c$, identify its 6 face-neighbors:
   - Left: $c + (-1, 0, 0)$
   - Right: $c + (1, 0, 0)$
   - Bottom: $c + (0, -1, 0)$
   - Top: $c + (0, 1, 0)$
   - Down: $c + (0, 0, -1)$
   - Up: $c + (0, 0, 1)$
4. For each neighbor, retrieve its velocity vector. If the neighbor is a boundary cell (solid/obstacle), replace the retrieved velocity with the obstacle velocity at that location [S2, unofficial].
5. Compute the divergence using the central difference formula:
   $$ D_c = \frac{1}{2\Delta x} \left[ (v_{R,x} - v_{L,x}) + (v_{T,y} - v_{B,y}) + (v_{U,z} - v_{D,z}) \right] $$
   where $v_{R,x}$ is the x-component of the velocity at the Right neighbor, etc. [S1, S2, unofficial].
   Note: In index space with unit voxel spacing ($\Delta x = 1$), the factor is $0.5$ [S1, unofficial].
6. Store $D_c$ in the result grid at coordinate $c$ [S1, unofficial].
7. Build the final result grid using the computed values, a background value of 0, and the original grid's voxel size [S1, unofficial].

**Pseudocode:**
```python
def compute_divergence_grid(velocity_grid, is_boundary_cell, obstacle_velocity_func, voxel_size):
    """
    Computes divergence of a vector field grid.
    
    Args:
        velocity_grid: Dict mapping (i,j,k) -> (vx, vy, vz) for active voxels.
        is_boundary_cell: Function taking (i,j,k) -> bool.
        obstacle_velocity_func: Function taking (i,j,k) -> (vx, vy, vz).
        voxel_size: Float, physical size of one voxel.
        
    Returns:
        Dict mapping (i,j,k) -> divergence scalar.
    """
    divergence_grid = {}
    factor = 0.5 / voxel_size
    
    # Iterate over all active voxels in the velocity grid
    for coord, velocity in velocity_grid.items():
        i, j, k = coord
        
        # Define neighbor offsets
        neighbors = {
            'L': (i-1, j, k), 'R': (i+1, j, k),
            'B': (i, j-1, k), 'T': (i, j+1, k),
            'D': (i, j, k-1), 'U': (i, j, k+1)
        }
        
        # Retrieve velocities, handling boundaries
        v_L = get_velocity_with_boundary(neighbors['L'], velocity_grid, is_boundary_cell, obstacle_velocity_func)
        v_R = get_velocity_with_boundary(neighbors['R'], velocity_grid, is_boundary_cell, obstacle_velocity_func)
        v_B = get_velocity_with_boundary(neighbors['B'], velocity_grid, is_boundary_cell, obstacle_velocity_func)
        v_T = get_velocity_with_boundary(neighbors['T'], velocity_grid, is_boundary_cell, obstacle_velocity_func)
        v_D = get_velocity_with_boundary(neighbors['D'], velocity_grid, is_boundary_cell, obstacle_velocity_func)
        v_U = get_velocity_with_boundary(neighbors['U'], velocity_grid, is_boundary_cell, obstacle_velocity_func)
        
        # Compute divergence
        # Formula: 0.5 * ((v_R.x - v_L.x) + (v_T.y - v_B.y) + (v_U.z - v_D.z)) / voxel_size
        div = factor * (
            (v_R[0] - v_L[0]) +  # x-component difference
            (v_T[1] - v_B[1]) +  # y-component difference
            (v_U[2] - v_D[2])    # z-component difference
        )
        
        divergence_grid[coord] = div
        
    return divergence_grid

def get_velocity_with_boundary(coord, velocity_grid, is_boundary_cell, obstacle_velocity_func):
    """Helper to get velocity, substituting obstacle velocity if boundary."""
    if is_boundary_cell(coord):
        return obstacle_velocity_func(coord)
    elif coord in velocity_grid:
        return velocity_grid[coord]
    else:
        # Not given in the sources. Typically returns zero or extrapolates.
        # For divergence in fluid simulation, inactive neighbors outside the domain
        # are often treated as boundaries or zero. We assume zero for inactive non-boundary.
        return (0.0, 0.0, 0.0)
```

**Parameters:**
- `voxel_size`: Physical size of a voxel. Default 1.0 if using index space directly [S1, unofficial].
- `obstacle_velocity_func`: Returns velocity at solid cells. Often $(0,0,0)$ for static obstacles [S2, unofficial].

**Edge Cases:**
- **Boundary Cells:** The method explicitly checks if neighbors are boundaries. If a neighbor is solid, its velocity is replaced by the obstacle velocity [S2, unofficial].
- **Inactive Neighbors:** If a neighbor is not active and not a boundary, the behavior is not explicitly defined in the sources [G]. Standard practice is to treat as zero or boundary.
- **Precision:** Using `Float64` is recommended for stability in simulation contexts [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of active voxels. Each voxel requires 6 neighbor lookups and a constant number of arithmetic operations.
- **Memory Complexity:** $O(N)$ for the output grid. Input grid is read-only.
- **Performance:** On GPU, this maps well to parallel execution per voxel. The boundary check adds a conditional branch, which may cause divergence in SIMD/SIMT units if boundaries are irregular [S2, unofficial].
- **Strengths:** Simple, stable, and physically meaningful for incompressibility constraints ($\nabla \cdot \mathbf{v} = 0$).
- **Limitations:** Only first-order accurate in space if not using higher-order stencils (though central difference is second-order for the derivative itself, the grid representation may limit accuracy). Sensitive to boundary condition implementation.

## Background
The method is derived from standard finite difference approximations of the divergence operator in computational fluid dynamics (CFD). The specific handling of obstacle velocities for boundary conditions is detailed in GPU Gems 3 for real-time fluid simulation [S2, unofficial]. The Julia implementation in Lyr.jl provides a sparse grid-based reference for this computation [S1, unofficial].
