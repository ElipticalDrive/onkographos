# Second-order Grid Sampler

Also called: Double back-propagation for grid sampler, Hessian computation for SDF, Hessian computation for SDF via double backprop, Second-order derivative computation for SDF regularization, Second-order derivatives via double backpropagation

## Overview
The Second-order Grid Sampler is a method for computing the Hessian matrix of a Signed Distance Field (SDF) with respect to 3D query coordinates and feature grid parameters, specifically within a differentiable rendering or reconstruction pipeline using trilinear interpolation. It solves the problem that standard automatic differentiation frameworks (e.g., PyTorch) do not support second-order gradients (double back-propagation) through the grid sampling operation [S1]. By manually implementing the second-order derivative terms, it enables regularization of the gradient term in SDF learning, avoiding the memory overhead of higher-order tensors [S1]. It is distinct from finite difference methods (like [Laplacian Grid Computation](3160-laplacian-grid-computation.md)) because it computes exact analytical derivatives of the interpolation function itself, rather than approximating derivatives of the sampled values on a discrete grid.

## How it works
The method computes the second-order derivatives of the SDF value $\phi$ with respect to the query position $x$, the feature grid parameters $\theta$, and the geometry network parameters $\omega$. The SDF is defined as $\phi(x, \theta, \omega) = f_\omega(z(\theta, x))$, where $z = V_\theta(x)$ is the tri-linearly interpolated feature vector at query point $x$ [S1].

### Inputs and Outputs
**Inputs:**
1.  Query point coordinates $x = [x, y, z]^T \in \mathbb{R}^3$, normalized to $[0, 1]$ within the voxel containing the point.
2.  Feature vector $\theta \in \mathbb{R}^8$ containing the feature values at the 8 vertices of the enclosing voxel, ordered as $[\theta_{000}, \theta_{001}, \theta_{010}, \theta_{011}, \theta_{100}, \theta_{101}, \theta_{110}, \theta_{111}]^T$ [S1].
3.  (Optional) Geometry network parameters $\omega$ and the function $f_\omega$ if mixed derivatives with respect to $\omega$ are required. For the core Hessian blocks involving $x$ and $\theta$, only $\theta$ and $x$ are needed.

**Outputs:**
1.  The Hessian block $\frac{\partial^2 \phi}{\partial x^2}$ (3x3 matrix).
2.  The mixed Hessian block $\frac{\partial^2 \phi}{\partial x \partial \theta}$ (3x8 matrix).
3.  (Optional) The mixed Hessian block $\frac{\partial^2 \phi}{\partial x \partial \omega}$ (3xN matrix, where N is the number of parameters in $\omega$).

### Data Structures
*   **Query Point:** 3-element vector $[x, y, z]$.
*   **Feature Vector:** 8-element vector $\theta$.
*   **Coefficient Vector:** 8-element vector $w(x)$ representing trilinear interpolation weights.
*   **Jacobian Matrix:** $8 \times 3$ matrix $J = \frac{\partial w}{\partial x}$.
*   **Hessian Matrix:** $3 \times 3$ matrix for $\frac{\partial^2 f}{\partial x^2}$.

### Numbered Steps

1.  **Compute Interpolation Weights:**
    Calculate the coefficient vector $w(x) \in \mathbb{R}^8$ for the query point $x=[x,y,z]$:
    $$
    w(x) = \begin{bmatrix}
    (1-x)(1-y)(1-z) \\
    (1-x)(1-y)z \\
    (1-x)y(1-z) \\
    (1-x)yz \\
    x(1-y)(1-z) \\
    x(1-y)z \\
    xy(1-z) \\
    xyz
    \end{bmatrix}
    $$
    [S1]

2.  **Compute Jacobian of Weights:**
    Calculate the $8 \times 3$ Jacobian matrix $J = \frac{\partial w}{\partial x}$. The columns $J_1, J_2, J_3$ correspond to derivatives with respect to $x, y, z$:
    $$
    J_1 = \begin{bmatrix} -(1-y)(1-z) \\ -(1-y)z \\ -y(1-z) \\ -yz \\ (1-y)(1-z) \\ (1-y)z \\ y(1-z) \\ yz \end{bmatrix}, \quad
    J_2 = \begin{bmatrix} -(1-x)(1-z) \\ -(1-x)z \\ (1-x)(1-z) \\ (1-x)z \\ -x(1-z) \\ -xz \\ x(1-z) \\ xz \end{bmatrix}, \quad
    J_3 = \begin{bmatrix} -(1-x)(1-y) \\ (1-x)(1-y) \\ -(1-x)y \\ (1-x)y \\ -x(1-y) \\ x(1-y) \\ -xy \\ xy \end{bmatrix}
    $$
    [S1]

3.  **Compute Mixed Hessian Block $\frac{\partial^2 f}{\partial x \partial \theta}$:**
    This block is the transpose of the Jacobian of the weights with respect to $x$:
    $$
    \frac{\partial^2 f}{\partial x \partial \theta} = \left( \frac{\partial w}{\partial x} \right)^T = J^T
    $$
    This results in a $3 \times 8$ matrix. Note that this derivation assumes 1-D features; for multi-dimensional features, this operation is performed per feature dimension [S1].

4.  **Compute Pure Second Hessian Block $\frac{\partial^2 f}{\partial x^2}$:**
    Compute the $3 \times 3$ Hessian matrix $H = \frac{\partial^2 f}{\partial x^2}$.
    
    *   **Diagonal Elements:** The diagonal elements $h_{11}, h_{22}, h_{33}$ are zero. This is because each column $J_i$ of the Jacobian only contains variables from the other two dimensions, making the derivative of $J_i$ with respect to the corresponding coordinate zero [S1].
    
    *   **Off-Diagonal Elements:** The matrix is symmetric ($h_{ij} = h_{ji}$). The non-zero off-diagonal elements are computed as follows:
        $$
        h_{12} = h_{21} = (1-z)(\theta_{000} + \theta_{110} - \theta_{010} - \theta_{100}) + z(\theta_{001} + \theta_{111} - \theta_{011} - \theta_{101})
        $$
        $$
        h_{13} = h_{31} = (1-y)(\theta_{000} + \theta_{101} - \theta_{001} - \theta_{100}) + y(\theta_{010} + \theta_{111} - \theta_{011} - \theta_{110})
        $$
        $$
        h_{23} = h_{32} = (1-x)(\theta_{000} + \theta_{011} - \theta_{001} - \theta_{010}) + x(\theta_{100} + \theta_{111} - \theta_{101} - \theta_{110})
        $$
        [S1]

5.  **Assemble Full Hessian Blocks for SDF:**
    If the SDF is defined as $\phi(x) = f_\omega(z)$, the full second-order derivatives required for regularization are:
    
    *   **$\frac{\partial^2 \phi}{\partial x^2}$:**
        $$
        \frac{\partial^2 \phi}{\partial x^2} = \sum_{i=1}^C \left( \frac{\partial^2 f_\omega(z)}{\partial z_i^2} \left(\frac{\partial z_i}{\partial x}\right)^2 + \frac{\partial f_\omega(z)}{\partial z_i} \frac{\partial^2 z_i}{\partial x^2} \right)
        $$
        Here, $\frac{\partial z_i}{\partial x}$ is the $i$-th row of $J^T$ (scaled by feature dimension if necessary), and $\frac{\partial^2 z_i}{\partial x^2}$ is the $i$-th row of the Hessian $H$ computed in Step 4. The term $\frac{\partial^2 f_\omega(z)}{\partial z_i^2}$ and $\frac{\partial f_\omega(z)}{\partial z_i}$ are obtained via standard backpropagation through the network $f_\omega$ (which supports double backprop) [S1].
        
    *   **$\frac{\partial^2 \phi}{\partial x \partial \theta}$:**
        $$
        \frac{\partial^2 \phi}{\partial x \partial \theta} = \sum_{i=1}^C \frac{\partial^2 f_\omega(z)}{\partial z_i^2} \frac{\partial z_i}{\partial \theta} \frac{\partial z_i}{\partial x}
        $$
        Since $\frac{\partial z_i}{\partial \theta}$ is the $i$-th column of the identity matrix (for the specific feature index) and $\frac{\partial z_i}{\partial x}$ is the $i$-th row of $J^T$, this simplifies to combining the network's second derivative w.r.t features with the spatial Jacobian [S1].

### Pseudocode

```python
import torch

def compute_trilinear_hessian(x, theta):
    """
    Computes the Hessian blocks for the SDF with respect to x and theta
    for a single query point and its enclosing voxel features.
    
    Args:
        x: Tensor of shape (3,), query coordinates [x, y, z] in [0, 1].
        theta: Tensor of shape (8,), feature values at voxel corners.
               Order: [000, 001, 010, 011, 100, 101, 110, 111].
               
    Returns:
        hessian_xx: Tensor of shape (3, 3), second derivative w.r.t x.
        hessian_xtheta: Tensor of shape (3, 8), mixed derivative w.r.t x and theta.
    """
    x_val, y_val, z_val = x[0], x[1], x[2]
    
    # Step 1: Compute Jacobian of weights J (8x3)
    # J1: d/dx, J2: d/dy, J3: d/dz
    # Using the explicit formulas from [S1]
    
    # Column 1 (d/dx)
    j1 = torch.tensor([
        -(1-y_val)*(1-z_val),
        -(1-y_val)*z_val,
        -y_val*(1-z_val),
        -y_val*z_val,
        (1-y_val)*(1-z_val),
        (1-y_val)*z_val,
        y_val*(1-z_val),
        y_val*z_val
    ], dtype=x.dtype, device=x.device)
    
    # Column 2 (d/dy)
    j2 = torch.tensor([
        -(1-x_val)*(1-z_val),
        -(1-x_val)*z_val,
        (1-x_val)*(1-z_val),
        (1-x_val)*z_val,
        -x_val*(1-z_val),
        -x_val*z_val,
        x_val*(1-z_val),
        x_val*z_val
    ], dtype=x.dtype, device=x.device)
    
    # Column 3 (d/dz)
    j3 = torch.tensor([
        -(1-x_val)*(1-y_val),
        (1-x_val)*(1-y_val),
        -(1-x_val)*y_val,
        (1-x_val)*y_val,
        -x_val*(1-y_val),
        x_val*(1-y_val),
        -x_val*y_val,
        x_val*y_val
    ], dtype=x.dtype, device=x.device)
    
    J = torch.stack([j1, j2, j3], dim=1) # Shape (8, 3)
    
    # Step 2: Compute Mixed Hessian Block d^2f / dx dtheta
    # This is simply J^T (3x8)
    hessian_xtheta = J.T
    
    # Step 3: Compute Pure Second Hessian Block d^2f / dx^2
    # Diagonal elements are 0
    hessian_xx = torch.zeros(3, 3, dtype=x.dtype, device=x.device)
    
    # Off-diagonal elements
    # h12 = h21
    h12 = (1-z_val)*(theta[0] + theta[6] - theta[2] - theta[4]) + \
          z_val*(theta[1] + theta[7] - theta[3] - theta[5])
          
    # h13 = h31
    h13 = (1-y_val)*(theta[0] + theta[5] - theta[1] - theta[4]) + \
          y_val*(theta[2] + theta[7] - theta[3] - theta[6])
          
    # h23 = h32
    h23 = (1-x_val)*(theta[0] + theta[3] - theta[1] - theta[2]) + \
          x_val*(theta[4] + theta[7] - theta[5] - theta[6])
          
    hessian_xx[0, 1] = h12
    hessian_xx[1, 0] = h12
    hessian_xx[0, 2] = h13
    hessian_xx[2, 0] = h13
    hessian_xx[1, 2] = h23
    hessian_xx[2, 1] = h23
    
    return hessian_xx, hessian_xtheta
```

### Parameters
*   **Feature Dimension:** The derivation assumes 1-D features for simplicity but generalizes to any feature dimension $C$ [S1]. In implementation, the Hessian blocks are computed for each feature dimension and summed/combined according to the network $f_\omega$'s structure.
*   **Coordinate System:** Coordinates $x, y, z$ are assumed to be normalized to $[0, 1]$ within the voxel. If physical coordinates are used, scaling factors must be applied [S1].

### Edge Cases and Pitfalls
*   **Boundary Conditions:** The method assumes the query point $x$ lies within a valid voxel with 8 neighbors. If $x$ is outside the grid, the interpolation weights and derivatives are undefined or require extrapolation strategies not covered by this specific analytical derivation [S1].
*   **Zero Diagonal:** A common implementation pitfall is attempting to compute non-zero diagonal elements for $\frac{\partial^2 f}{\partial x^2}$. The analytical derivation proves these are exactly zero for trilinear interpolation [S1].
*   **Tensor Order:** The feature vector $\theta$ must follow the specific vertex ordering $[000, 001, 010, 011, 100, 101, 110, 111]$ corresponding to the binary representation of the corner indices. Mismatched ordering will produce incorrect Hessian values [S1].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query point, as it involves a fixed number of arithmetic operations (constant size vectors and matrices).
*   **Memory Complexity:** $O(1)$ auxiliary memory per query point.
*   **Strengths:** Provides exact analytical second-order derivatives for trilinear interpolation, enabling precise gradient regularization in SDF learning without the noise or approximation errors of finite differences. It avoids the memory explosion of higher-order tensors by decomposing the problem [S1].
*   **Limitations:** Only applicable to trilinear interpolation. Does not handle non-uniform voxel spacing or higher-order interpolation schemes without modification. Requires the query point to be inside a voxel [S1].
*   **When to use:** When training neural fields (like SDFs) that require Hessian-based regularization (e.g., enforcing flatness or specific curvature properties) and using PyTorch's grid sampler.
*   **When not to use:** When using finite difference methods on discrete grids (use [Laplacian Grid Computation](3160-laplacian-grid-computation.md)) or when higher-order interpolation is used.

## Background
The method was introduced in the context of "GO-Surf: Neural Feature Grid Optimization for Fast, High-Fidelity RGB-D Surface Reconstruction" by Jingwen Wang, Tymoteusz Bleja, and Lourdes Agapito (2022) [S1]. It addresses the limitation of PyTorch's automatic differentiation engine, which does not support double back-propagation through the `grid_sampler` operation. By manually deriving and implementing the second-order derivatives of the trilinear interpolation function, the authors enabled the regularization of the SDF gradient term, which is crucial for learning accurate geometry priors [S1].
