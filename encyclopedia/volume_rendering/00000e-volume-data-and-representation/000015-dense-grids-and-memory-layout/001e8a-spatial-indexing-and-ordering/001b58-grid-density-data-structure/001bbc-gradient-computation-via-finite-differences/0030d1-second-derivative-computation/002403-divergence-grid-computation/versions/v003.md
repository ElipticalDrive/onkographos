# Divergence Grid Computation

Also called: Divergence Calculation with Obstacle Velocity Boundary Conditions, Divergence Computation, Finite Difference Divergence

## Overview
Computes the divergence $\nabla \cdot \mathbf{v}$ of a vector field grid using central differences [S1, S2, unofficial]. It differs from sibling methods like [Laplacian Grid Computation](3160-laplacian-grid-computation.md) by operating on a vector input rather than a scalar one, and specifically handles fluid-solid boundaries by substituting obstacle velocities for inactive cells [S2, unofficial].

## How it works
**Inputs**: A 3D vector grid $\mathbf{v}$ containing velocity components $(v_x, v_y, v_z)$ at active voxels; a boundary mask or function `IsBoundaryCell` identifying solid/obstacle cells; and obstacle velocity values `GetObstacleVelocity` for boundary cells [S2, unofficial].
**Outputs**: A scalar grid of divergence values with the same topology as the input, background initialized to zero [S1, S2, unofficial].

**Data Structures**:
- `GradStencil`: A helper structure that manages access to a voxel and its 6 immediate neighbors (Left, Right, Bottom, Top, Down, Up) [S1, unofficial].
- Neighbor indices relative to center $c$:
  - Left: $c + (-1, 0, 0)$
  - Right: $c + (1, 0, 0)$
  - Bottom: $c + (0, -1, 0)$
  - Top: $c + (0, 1, 0)$
  - Down: $c + (0, 0, -1)$
  - Up: $c + (0, 0, 1)$

**Steps**:
1. Initialize a `GradStencil` with the input grid tree [S1, unofficial].
2. Iterate over all active voxels $c$ in the grid [S1, unofficial].
3. For each active voxel, sample the velocity vectors from the six neighboring cells [S1, S2, unofficial].
4. **Boundary Handling**: If a neighbor is a boundary cell (solid/obstacle), replace its sampled velocity with the specific obstacle velocity at that location [S2, unofficial]. If not a boundary, use the standard grid value [S2, unofficial].
5. Compute the divergence using the central difference formula [S1, S2, unofficial]:
   $$ \text{div} = 0.5 \times \left( (v_R.x - v_L.x) + (v_T.y - v_B.y) + (v_U.z - v_D.z) \right) $$
   Where $v_R, v_L, v_T, v_B, v_U, v_D$ are the velocity vectors of the Right, Left, Top, Bottom, Up, and Down neighbors respectively [S2, unofficial].
   *Note*: The source [S1, unofficial] provides an alternative indexing formula `div = (v[2][1] - v[3][1] + v[4][2] - v[5][2] + v[6][3] - v[7][3]) * 0.5`. This maps to the same central difference logic where indices 2/3, 4/5, 6/7 correspond to opposing axis pairs, but the explicit component formula [S2, unofficial] is preferred for clarity [S1, S2, unofficial].
6. Store the result in a dictionary keyed by coordinate $c$ [S1, unofficial].
7. Build the result grid from the dictionary, using the original grid's voxel size and a background value of zero [S1, unofficial].

**Pseudocode**:
```python
def compute_divergence_grid(grid, is_boundary, get_obstacle_velocity):
    """
    grid: Dict[(x,y,z), (vx, vy, vz)] representing active voxels.
    is_boundary: Function(coord) -> bool
    get_obstacle_velocity: Function(coord) -> (vx, vy, vz)
    Returns: Dict[(x,y,z), float] divergence values.
    """
    divergence_grid = {}
    
    # Define neighbor offsets: (dx, dy, dz)
    neighbors = {
        'L': (-1, 0, 0), 'R': (1, 0, 0),
        'B': (0, -1, 0), 'T': (0, 1, 0),
        'D': (0, 0, -1), 'U': (0, 0, 1)
    }
    
    for c, v_center in grid.items():
        # Sample neighbors
        v_neighbors = {}
        for name, offset in neighbors.items():
            nc = (c[0] + offset[0], c[1] + offset[1], c[2] + offset[2])
            
            # Check if neighbor is boundary or outside grid
            # Note: If nc is not in grid, it is treated as boundary/inactive
            if nc not in grid or is_boundary(nc):
                if nc in grid:
                    v_neighbors[name] = get_obstacle_velocity(nc)
                else:
                    # [G] If neighbor is outside the defined grid bounds, 
                    # standard practice is to clamp or use zero. 
                    # The source [S2, unofficial] implies boundary handling via 
                    # GetObstacleVelocity. We assume outside cells are 
                    # handled by the boundary logic or treated as zero 
                    # if no obstacle velocity is defined. 
                    # For robustness, we use zero if no obstacle velocity is available.
                    v_neighbors[name] = (0.0, 0.0, 0.0)
            else:
                v_neighbors[name] = grid[nc]
        
        v_L = v_neighbors['L']
        v_R = v_neighbors['R']
        v_B = v_neighbors['B']
        v_T = v_neighbors['T']
        v_D = v_neighbors['D']
        v_U = v_neighbors['U']
        
        # Compute divergence
        # Formula: 0.5 * ((v_R.x - v_L.x) + (v_T.y - v_B.y) + (v_U.z - v_D.z))
        div_x = v_R[0] - v_L[0]
        div_y = v_T[1] - v_B[1]
        div_z = v_U[2] - v_D[2]
        
        divergence = 0.5 * (div_x + div_y + div_z)
        divergence_grid[c] = divergence
        
    return divergence_grid
```

**Parameters**:
- `0.5`: The scalar multiplier representing $\frac{1}{2\Delta x}$ in index space [S1, unofficial].

**Edge Cases**:
- **Boundary Cells**: The method explicitly checks if neighbors are boundary cells. If so, it substitutes the obstacle velocity [S2, unofficial].
- **Inactive Voxels**: The iteration is over active voxels only. Neighbors that are inactive (not in the grid) are treated as boundaries [S1, S2, unofficial].
- **Precision**: Standard floating-point arithmetic is used. No specific precision requirements are noted beyond standard grid computations [S1, S2, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N)$ where $N$ is the number of active voxels, as each active voxel requires 6 neighbor lookups and constant-time arithmetic [S1, S2, unofficial].
- **Memory Complexity**: $O(N)$ for the output grid [S1, unofficial].
- **Performance**: Not given in the sources.
- **Strengths**: Handles complex fluid-solid interactions via obstacle velocity boundary conditions [S2, unofficial]. Simple and efficient stencil-based computation [S1, unofficial].
- **Limitations**: Only computes divergence; does not solve the projection step itself (which is a separate kernel [S2, unofficial]). Accuracy is limited to first-order central differences [S1, unofficial].

## Background
The method is part of the GPU Gems 3 chapter on Real-Time Simulation and Rendering of 3D Fluids, which details GPU-based fluid simulation techniques [S2, unofficial]. It is also implemented in the Lyr.jl Julia library for volume rendering and simulation [S1, unofficial]. The approach builds on the shared principles of finite difference stencils used in [Second Derivative Computation](6353-second-derivative-computation.md) [S1, S2, unofficial].
