# Eikonal Omega Term Computation

Also called: Double backprop for Eikonal term, Second-order dOmega

## Overview
Computes the gradient of the Eikonal constraint term with respect to the hash grid encoding features, enabling the enforcement of the unit-norm gradient property in neural implicit representations. It differs from standard first-order gradient computation by propagating second-order derivative information through the tetrahedral interpolation kernel, specifically supporting two backpropagation strategies: double backpropagation and second-order dOmega.

## How it works
The method implements a custom CUDA autograd function that computes the forward pass as a zero tensor (since the Eikonal term is a loss, not a feature output) and performs the backward pass to compute gradients for the feature table.

**Inputs and Outputs:**
*   **Inputs:**
    *   `x_pre`: Input coordinates tensor of shape $(N, 3)$, where $N$ is the number of points.
    *   `feature_table`: The hash grid feature tensor of shape $(L, F)$, where $L$ is the table size and $F$ is the feature dimension.
    *   `resolutions`: Array of grid resolutions for each level.
    *   `cube_vertices`: Cube vertex indices mapping.
    *   `tetrahedra_index`: Tetrahedron vertex indices mapping.
    *   `prime_factors`: Hash prime factors for coordinate hashing.
    *   `g_de`: Gradient tensor related to the encoding output (from upstream loss).
    *   `alpha_dn`: Scaling factor tensor for the Eikonal term.
    *   `z_dalpha_dx_de`: Optional tensor containing second-order derivative information. If empty or None, treated as zero.
*   **Outputs:**
    *   `grad_feature_table`: Gradient tensor with respect to `feature_table`.
    *   Other gradients (`grad_x_pre`, etc.) are returned as `None` or zero, as only feature table gradients are typically required for optimization in this context.

**Data Structures:**
The implementation relies on the tetrahedral decomposition of the cube. Each cube is split into 6 tetrahedra. The `tetrahedra_index` maps a tetrahedron ID to 4 vertex indices. The `cube_vertices` map defines the 8 vertices of a cube. The hash grid uses a sparse hash table of size `table_size` with resolution `resolutions[level]` for each level $L$.

**Numbered Steps:**

1.  **Forward Pass:**
    *   Save all input tensors (`x_pre`, `feature_table`, `resolutions`, `cube_vertices`, `tetrahedra_index`, `prime_factors`, `g_de`, `alpha_dn`, `z_dalpha_dx_de`, `F_tensor`, `table_size_tensor`) to the autograd context.
    *   Return a scalar zero tensor of the same device and dtype as `x_pre`. This represents the forward value of the Eikonal constraint term (which is 0 for the purpose of gradient propagation in this specific implementation structure, or rather, the function computes the gradient of the term, not the term itself).

2.  **Backward Pass:**
    *   Retrieve saved tensors from context.
    *   Compute `scale` as the value of `grad_out.item()` (the upstream gradient).
    *   Extract dimensions: $N$ (number of points), $L$ (number of levels), $F$ (feature dimension), and `table_size`.
    *   Initialize `g_feature_table` as a zero tensor of the same shape as `feature_table`.
    *   Determine the backpropagation mode based on the availability of `_tetra_db_double` or `_tetra_db_second` kernels.
    *   **Mode 1: Double Backprop (`_tetra_db_double`):**
        *   If `z_dalpha_dx_de` is empty (numel == 0), set $z = \text{zeros}(N, L \times F)$.
        *   Otherwise, set $z = (z\_dalpha\_dx\_de \times \text{scale}).\text{contiguous}().\text{float}()$.
        *   Call `_tetra_db_double` with arguments: `x_pre`, `feature_table`, $z$, `g_de`, `(alpha_dn * scale)`, `resolutions`, `g_feature_table`, $N$, $L$, $F$, `table_size`, `cube_vertices`, `tetrahedra_index`, `prime_factors`.
    *   **Mode 2: Second-order dOmega (`_tetra_db_second`):**
        *   Call `_tetra_db_second` with arguments: `x_pre`, `g_de`, `(alpha_dn * scale)`, `resolutions`, `g_feature_table`, $N$, $L$, $F$, `table_size`, `cube_vertices`, `tetrahedra_index`, `prime_factors`.
    *   If neither kernel is available, raise a `RuntimeError`.

3.  **Return Gradients:**
    *   Return `grad_x_pre=None`, `grad_feature_table=g_feature_table`, and `None` for all other inputs.

**Pseudocode:**

```python
import torch

def eikonal_omega_backward(grad_out, x_pre, feature_table, resolutions, 
                           cube_vertices, tetrahedra_index, prime_factors,
                           g_de, alpha_dn, z_dalpha_dx_de, F, table_size):
    """
    Computes the gradient of the Eikonal Omega term w.r.t. feature_table.
    """
    scale = float(grad_out.item())
    N = x_pre.shape[0]
    L = feature_table.shape[0] // F # Assuming feature_table is flattened or structured by level
    
    # Initialize gradient tensor
    g_feature_table = torch.zeros_like(feature_table)
    
    # Prepare z tensor for double backprop
    if z_dalpha_dx_de is not None and z_dalpha_dx_de.numel() > 0:
        z = (z_dalpha_dx_de * scale).contiguous().float()
    else:
        z = torch.zeros(N, L * F, device=x_pre.device, dtype=torch.float32)
        
    # Prepare scaled alpha_dn
    alpha_dn_scaled = (alpha_dn * scale).contiguous().float()
    
    # Select kernel based on availability
    if _tetra_db_double_available:
        _tetra_db_double(
            x_pre.contiguous().float(),
            feature_table.contiguous().float(),
            z,
            g_de.contiguous().float(),
            alpha_dn_scaled,
            resolutions,
            g_feature_table,
            N, L, F, table_size,
            cube_vertices.contiguous(),
            tetrahedra_index.contiguous(),
            prime_factors.contiguous()
        )
    elif _tetra_db_second_available:
        _tetra_db_second(
            x_pre.contiguous().float(),
            g_de.contiguous().float(),
            alpha_dn_scaled,
            resolutions,
            g_feature_table,
            N, L, F, table_size,
            cube_vertices.contiguous(),
            tetrahedra_index.contiguous(),
            prime_factors.contiguous()
        )
    else:
        raise RuntimeError("No Eikonal Omega backprop kernel available")
        
    return g_feature_table
```

**Parameters:**
*   `x_pre`: Input coordinates tensor. Shape: $(N, 3)$.
*   `g_de`: Gradient tensor related to the encoding. Shape: $(N, L \times F)$ or similar, depending on the specific encoding layout.
*   `alpha_dn`: Scaling factor tensor for the Eikonal term. Shape: $(N,)$.
*   `z_dalpha_dx_de`: Optional tensor for second-order derivative information. Shape: $(N, L \times F)$.

**Edge Cases and Pitfalls:**
*   **Empty `z_dalpha_dx_de`:** If the tensor is empty or None, it must be explicitly replaced with a zero tensor of the correct shape to avoid undefined behavior in the kernel.
*   **Kernel Availability:** The method relies on specific CUDA kernels (`_tetra_db_double` or `_tetra_db_second`). If neither is compiled or available, the operation fails.
*   **Precision:** All tensors are cast to `float32` before kernel invocation to ensure consistency, as the kernels expect `float` inputs.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of points $N$ and levels $L$, i.e., $O(N \cdot L)$. The constant factor depends on the tetrahedral interpolation and hash lookup overhead.
*   **Memory Complexity:** $O(N \cdot L \cdot F)$ for storing intermediate gradients and $O(L \cdot F)$ for the feature table gradient.
*   **Performance:** Highly optimized for GPU execution via custom CUDA kernels. Performance scales with the number of threads and blocks launched.
*   **Strengths:** Enables efficient computation of second-order derivatives required for Eikonal regularization in neural implicit fields.
*   **Limitations:** Requires specific CUDA kernel implementations. Not suitable for CPU-only environments without fallback implementations.

## Background
The method is part of the TetraSDF framework, which uses tetrahedral decomposition for efficient and accurate gradient computation in neural implicit representations. The Eikonal term is crucial for enforcing the unit-norm gradient property, which helps in stabilizing training and improving reconstruction quality. The double backprop and second-order dOmega approaches are specific techniques to handle the second-order derivatives required for this term.
