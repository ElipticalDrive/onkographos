# Second-order Grid Sampler

Also called: Double back-propagation for grid sampler, Hessian computation for SDF, Hessian computation for SDF via double backprop, Second-order derivative computation for SDF regularization, Second-order derivatives via double backpropagation

## Overview
The Second-order Grid Sampler is a method for computing the Hessian matrix of a Signed Distance Field (SDF) with respect to 3D query coordinates and feature grid parameters, specifically within a differentiable rendering or reconstruction pipeline that uses tri-linearly interpolated feature grids [S1]. It solves the problem that standard automatic differentiation frameworks (e.g., PyTorch) do not support second-order gradients (double back-propagation) through the `grid_sampler` operation [S1]. By analytically deriving the second-order derivatives of the tri-linear interpolation function, the method allows for the regularization of the SDF gradient term without resorting to finite differences or higher-order tensor manipulations [S1]. It sets itself apart from sibling methods like [Laplacian Grid Computation](3160-laplacian-grid-computation.md) by operating in the continuous parameter space of learned feature grids rather than on discrete voxel values, and from [Mean Curvature Grid Computation](3126-mean-curvature-grid-computation.md) by providing the full Hessian blocks required for gradient regularization rather than just curvature scalars.

## How it works
The method computes the second-order derivatives of the SDF $\phi$ with respect to the query position $x$, feature grid parameters $\theta$, and geometry network parameters $\omega$. The SDF is defined as $\phi(x, \theta, \omega) = f_\omega(z(\theta, x))$, where $z = V_\theta(x) \in \mathbb{R}^C$ is the tri-linearly interpolated feature vector at query point $x$ [S1].

### Inputs and Outputs
**Inputs:**
1.  Query point $x = [x, y, z]^T \in \mathbb{R}^3$, normalized to $[0, 1]^3$ relative to the voxel containing the point.
2.  Feature grid parameters $\theta \in \mathbb{R}^{8 \times C}$, representing the feature vectors at the 8 vertices of the enclosing voxel. The vertices are indexed by binary coordinates $(v_x, v_y, v_z) \in \{0,1\}^3$.
3.  Geometry network parameters $\omega$ (implicit in $f_\omega$).
4.  Feature dimension $C$.

**Outputs:**
1.  Hessian block $\frac{\partial^2 \phi}{\partial x^2}$ (3x3 matrix).
2.  Hessian block $\frac{\partial^2 \phi}{\partial x \partial \theta}$ (3x8C matrix, or 3x8 for C=1).
3.  Hessian block $\frac{\partial^2 \phi}{\partial x \partial \omega}$ (3xN matrix, where N is size of $\omega$).

### Data Structures
*   **Coefficient Vector $w(x)$**: An 8-dimensional vector containing the tri-linear interpolation weights for the 8 vertices of the voxel enclosing $x$. The order of vertices corresponds to the binary representation of the vertex indices $(v_x, v_y, v_z)$ mapped to indices $0..7$:
    *   Index 0: $(0,0,0)$
    *   Index 1: $(0,0,1)$
    *   Index 2: $(0,1,0)$
    *   Index 3: $(0,1,1)$
    *   Index 4: $(1,0,0)$
    *   Index 5: $(1,0,1)$
    *   Index 6: $(1,1,0)$
    *   Index 7: $(1,1,1)$
*   **Jacobian Matrix $\frac{\partial w}{\partial x}$**: An $8 \times 3$ matrix where column $j$ contains the partial derivatives of $w$ with respect to coordinate $j \in \{x, y, z\}$.

### Formulas
The first-order gradient of the SDF w.r.t. $x$ is computed via the chain rule [S1]:
$$ \frac{\partial \phi}{\partial x} = \sum_{i=1}^C \frac{\partial f_\omega(z)}{\partial z_i} \frac{\partial z_i}{\partial x} $$
To avoid higher-order tensors, the second-order derivatives are derived for each feature dimension $z_i$ independently [S1].

**1. Second derivative w.r.t. $x$ ($\frac{\partial^2 \phi}{\partial x^2}$):**
$$ \frac{\partial^2 \phi}{\partial x^2} = \sum_{i=1}^C \left( \frac{\partial^2 f_\omega(z)}{\partial z_i^2} \left(\frac{\partial z_i}{\partial x}\right)^2 + \frac{\partial f_\omega(z)}{\partial z_i} \frac{\partial^2 z_i}{\partial x^2} \right) $$
The term $\frac{\partial^2 z_i}{\partial x^2}$ corresponds to the Hessian of the interpolation function $f$ w.r.t $x$. For tri-linear interpolation, the Hessian matrix $H_x = \frac{\partial^2 f}{\partial x^2}$ has zero diagonal elements and specific off-diagonal elements [S1]:
$$ H_x = \begin{bmatrix} 0 & h_{12} & h_{13} \\ h_{21} & 0 & h_{23} \\ h_{31} & h_{32} & 0 \end{bmatrix} $$
Where (assuming 1-D features for derivation, generalized to $C$ dimensions):
$$ h_{12} = h_{21} = (1 - z)(\theta_{000} + \theta_{110} - \theta_{010} - \theta_{100}) + z(\theta_{001} + \theta_{111} - \theta_{011} - \theta_{101}) $$
$$ h_{13} = h_{31} = (1 - y)(\theta_{000} + \theta_{101} - \theta_{001} - \theta_{100}) + y(\theta_{010} + \theta_{111} - \theta_{011} - \theta_{110}) $$
$$ h_{23} = h_{32} = (1 - x)(\theta_{000} + \theta_{011} - \theta_{001} - \theta_{010}) + x(\theta_{100} + \theta_{111} - \theta_{101} - \theta_{110}) $$
Note: $\theta_{v_x v_y v_z}$ denotes the scalar feature value at vertex $(v_x, v_y, v_z)$. For multi-dimensional features, this applies to each channel $i$ independently.

**2. Mixed derivative w.r.t. $x$ and $\theta$ ($\frac{\partial^2 \phi}{\partial x \partial \theta}$):**
$$ \frac{\partial^2 \phi}{\partial x \partial \theta} = \sum_{i=1}^C \frac{\partial^2 f_\omega(z)}{\partial z_i^2} \frac{\partial z_i}{\partial \theta} \frac{\partial z_i}{\partial x} $$
The term $\frac{\partial^2 f}{\partial x \partial \theta}$ is the transpose of the Jacobian of $w$ w.r.t $x$ [S1]:
$$ \frac{\partial^2 f}{\partial x \partial \theta} = \left( \frac{\partial w}{\partial x} \right)^T $$
The Jacobian $\frac{\partial w}{\partial x}$ is an $8 \times 3$ matrix. Its columns $J_1, J_2, J_3$ are:
$$ J_1 = \begin{bmatrix} -(1-y)(1-z) \\ -(1-y)z \\ -y(1-z) \\ -yz \\ (1-y)(1-z) \\ (1-y)z \\ y(1-z) \\ yz \end{bmatrix}, \quad J_2 = \begin{bmatrix} -(1-x)(1-z) \\ -(1-x)z \\ (1-x)(1-z) \\ (1-x)z \\ -x(1-z) \\ -xz \\ x(1-z) \\ xz \end{bmatrix}, \quad J_3 = \begin{bmatrix} -(1-x)(1-y) \\ (1-x)(1-y) \\ -(1-x)y \\ (1-x)y \\ -x(1-y) \\ x(1-y) \\ -xy \\ xy \end{bmatrix} $$

**3. Mixed derivative w.r.t. $x$ and $\omega$ ($\frac{\partial^2 \phi}{\partial x \partial \omega}$):**
$$ \frac{\partial^2 \phi}{\partial x \partial \omega} = \sum_{i=1}^C \left( \frac{\partial^2 f_\omega(z)}{\partial z_i^2} \frac{\partial z_i}{\partial \omega} \frac{\partial z_i}{\partial x} + \frac{\partial f_\omega(z)}{\partial z_i} \frac{\partial^2 z_i}{\partial x \partial \omega} \right) $$
This term is computed using standard automatic differentiation (single back-prop) through the geometry network $f_\omega$ and the grid sampler, as PyTorch supports first-order gradients through these operations [S1].

### Pseudocode
```python
import torch

def compute_second_order_grid_sampler(x, theta, f_omega, df_dz, d2f_dz2):
    """
    Computes the Hessian blocks for the SDF regularization.
    
    Args:
        x: Tensor of shape (..., 3), query points [x, y, z] in [0, 1].
        theta: Tensor of shape (..., 8, C), feature values at voxel vertices.
               Vertices ordered: 000, 001, 010, 011, 100, 101, 110, 111.
        f_omega: The geometry network function f_omega(z).
        df_dz: Gradient of f_omega w.r.t z, shape (..., C). Computed via standard backprop.
        d2f_dz2: Hessian of f_omega w.r.t z (diagonal), shape (..., C). 
                 Computed via standard backprop if f_omega is differentiable twice, 
                 or assumed zero if f_omega is linear/MLP with specific activation handling.
                 Note: The source [S1] implies d2f_dz2 is needed. If f_omega is a standard MLP, 
                 this requires double backprop through f_omega, which is supported.
    
    Returns:
        hessian_xx: Tensor of shape (..., 3, 3)
        hessian_x_theta: Tensor of shape (..., 3, 8*C)
        hessian_x_omega: Tensor of shape (..., 3, N_omega)
    """
    # 1. Compute first order gradients of interpolation w.r.t x
    # w is shape (..., 8)
    x_val, y_val, z_val = x[..., 0:1], x[..., 1:2], x[..., 2:3]
    
    # Coefficients w(x)
    w = torch.stack([
        (1-x_val)*(1-y_val)*(1-z_val),
        (1-x_val)*(1-y_val)*z_val,
        (1-x_val)*y_val*(1-z_val),
        (1-x_val)*y_val*z_val,
        x_val*(1-y_val)*(1-z_val),
        x_val*(1-y_val)*z_val,
        x_val*y_val*(1-z_val),
        x_val*y_val*z_val
    ], dim=-1) # Shape (..., 8)
    
    # Jacobian of w w.r.t x: J is (..., 8, 3)
    # Column 0: dw/dx
    dw_dx = torch.stack([
        -(1-y_val)*(1-z_val),
        -(1-y_val)*z_val,
        -y_val*(1-z_val),
        -y_val*z_val,
        (1-y_val)*(1-z_val),
        (1-y_val)*z_val,
        y_val*(1-z_val),
        y_val*z_val
    ], dim=-1)
    
    # Column 1: dw/dy
    dw_dy = torch.stack([
        -(1-x_val)*(1-z_val),
        -(1-x_val)*z_val,
        (1-x_val)*(1-z_val),
        (1-x_val)*z_val,
        -x_val*(1-z_val),
        -x_val*z_val,
        x_val*(1-z_val),
        x_val*z_val
    ], dim=-1)
    
    # Column 2: dw/dz
    dw_dz = torch.stack([
        -(1-x_val)*(1-y_val),
        (1-x_val)*(1-y_val),
        -(1-x_val)*y_val,
        (1-x_val)*y_val,
        -x_val*(1-y_val),
        x_val*(1-y_val),
        -x_val*y_val,
        x_val*y_val
    ], dim=-1)
    
    J = torch.stack([dw_dx, dw_dy, dw_dz], dim=-1) # (..., 8, 3)
    
    # 2. Compute Hessian_xx block
    # H_xx is 3x3. Diagonal is 0. Off-diagonals depend on theta.
    # We compute the scalar Hessian of the interpolation function for each channel.
    # For a single channel, H_interp_xx is 3x3.
    # Generalizing to C channels: we need to sum over channels weighted by d2f_dz2 and df_dz.
    
    # Calculate off-diagonal terms for the interpolation Hessian
    # h12 (x-y)
    h12 = (1-z_val)*(theta[..., 0] + theta[..., 6] - theta[..., 2] - theta[..., 4]) + \
          z_val*(theta[..., 1] + theta[..., 7] - theta[..., 3] - theta[..., 5])
          
    # h13 (x-z)
    h13 = (1-y_val)*(theta[..., 0] + theta[..., 5] - theta[..., 1] - theta[..., 4]) + \
          y_val*(theta[..., 2] + theta[..., 7] - theta[..., 3] - theta[..., 6])
          
    # h23 (y-z)
    h23 = (1-x_val)*(theta[..., 0] + theta[..., 3] - theta[..., 1] - theta[..., 2]) + \
          x_val*(theta[..., 4] + theta[..., 7] - theta[..., 5] - theta[..., 6])
          
    # Reshape for broadcasting: h12 is (..., 1), needs to fill H_xx[0,1] and H_xx[1,0]
    # H_xx shape (..., 3, 3)
    H_xx = torch.zeros(*x.shape[:-1], 3, 3, device=x.device)
    
    # Diagonals are 0
    # Off-diagonals
    # Note: The formula in [S1] is for 1-D features. For C-D features, we sum over i.
    # Term 1: sum_i ( d2f_dz2_i * (dz_i/dx)^2 ) -> This is the "curvature" of f_omega part
    # Term 2: sum_i ( df_dz_i * d2z_i/dx^2 ) -> This is the interpolation Hessian part
    
    # Let's compute the interpolation Hessian part first: H_interp_xx
    # H_interp_xx[i,j] = h_ij from above if i!=j else 0
    # But wait, the formula in [S1] Eq 3 is:
    # d2phi/dx2 = sum_i ( d2f/dzi2 * (dzi/dx)^2 + df/dzi * d2zi/dx2 )
    
    # dzi/dx is the gradient of the interpolated feature z_i w.r.t x.
    # z_i = theta_i . w(x)
    # dzi/dx = theta_i^T * dw/dx = theta_i^T * J[:, :, k] for k-th dim
    
    # Let's compute dzi/dx for all channels
    # theta shape (..., 8, C), J shape (..., 8, 3)
    # dzi/dx shape (..., C, 3)
    dz_dx = torch.einsum('...ic,...ic->...ic', theta, J) # This is wrong, J is (8,3), theta is (8,C)
    # Correct: dz_dx = theta @ J.T ? No.
    # z = theta^T w. dz/dx = theta^T dw/dx.
    # theta is (8, C). dw/dx is (8, 3).
    # dz/dx is (C, 3).
    # Using einsum: theta[i, c] * J[i, k] -> sum over i.
    dz_dx = torch.einsum('...ic,...ik->...kc', theta, J) # Shape (..., C, 3)
    
    # Term 1: sum_i ( d2f_dz2_i * (dzi/dx)^2 )
    # d2f_dz2 is (..., C). dz_dx is (..., C, 3).
    # (dzi/dx)^2 is (..., C, 3).
    # Product is (..., C, 3). Sum over C -> (..., 3).
    term1 = torch.sum(d2f_dz2.unsqueeze(-1) * (dz_dx ** 2), dim=-2) # (..., 3)
    
    # Term 2: sum_i ( df_dz_i * d2zi/dx2 )
    # d2zi/dx2 is the Hessian of the interpolation for channel i.
    # H_interp_xx is 3x3.
    # We need to construct H_interp_xx for each channel.
    # Since the off-diagonals h12, h13, h23 depend on theta, they are channel-specific.
    
    # Let's build H_interp_xx channel by channel or using broadcasting
    # h12, h13, h23 are (..., 1) or (..., C) depending on theta.
    # theta is (..., 8, C).
    # h12 calculation:
    h12_c = (1-z_val)*(theta[..., 0, :] + theta[..., 6, :] - theta[..., 2, :] - theta[..., 4, :]) + \
            z_val*(theta[..., 1, :] + theta[..., 7, :] - theta[..., 3, :] - theta[..., 5, :])
    h13_c = (1-y_val)*(theta[..., 0, :] + theta[..., 5, :] - theta[..., 1, :] - theta[..., 4, :]) + \
            y_val*(theta[..., 2, :] + theta[..., 7, :] - theta[..., 3, :] - theta[..., 6, :])
    h23_c = (1-x_val)*(theta[..., 0, :] + theta[..., 3, :] - theta[..., 1, :] - theta[..., 2, :]) + \
            x_val*(theta[..., 4, :] + theta[..., 7, :] - theta[..., 5, :] - theta[..., 6, :])
            
    # H_interp_xx shape (..., 3, 3, C)
    H_interp_xx = torch.zeros(*x.shape[:-1], 3, 3, theta.shape[-1], device=x.device)
    H_interp_xx[..., 0, 1, :] = h12_c
    H_interp_xx[..., 1, 0, :] = h12_c
    H_interp_xx[..., 0, 2, :] = h13_c
    H_interp_xx[..., 2, 0, :] = h13_c
    H_interp_xx[..., 1, 2, :] = h23_c
    H_interp_xx[..., 2, 1, :] = h23_c
    
    # df_dz is (..., C). Expand to (..., 1, 1, C)
    df_dz_exp = df_dz.unsqueeze(-2).unsqueeze(-2) # (..., 1, 1, C)
    term2 = torch.sum(df_dz_exp * H_interp_xx, dim=-1) # (..., 3, 3)
    
    H_xx = term1.unsqueeze(-1) + term2 # term1 is (..., 3), broadcast to (..., 3, 3)
    
    # 3. Compute Hessian_x_theta
    # d2phi/dx dtheta = sum_i ( d2f_dz2_i * (dzi/dtheta) (dzi/dx) )
    # dzi/dtheta = dw/dx (since z_i = theta_i . w). So dzi/dtheta is J (..., 8, 3) transposed?
    # z_i = sum_j theta_ij w_j. dz_i/dtheta_ik = w_j if k=j else 0.
    # So dz/dtheta is a block diagonal matrix of w?
    # Actually, the formula in [S1] says d2f/dx dtheta = (dw/dx)^T.
    # This is for the interpolation part.
    # The full term is sum_i d2f_dz2_i * (dzi/dtheta) (dzi/dx).
    # dzi/dtheta is a vector of size 8C? Or 8?
    # If theta is (8, C), then dtheta is (8, C).
    # dzi/dtheta_ij = w_j if i==j else 0.
    # So dzi/dtheta is a sparse matrix.
    # However, [S1] Eq 4: d2phi/dx dtheta = sum_i d2f_dz2_i * (dzi/dtheta) (dzi/dx).
    # And it states d2f/dx dtheta = (dw/dx)^T.
    # This implies that for the regularization, they might assume d2f_dz2 is identity or handled separately?
    # No, Eq 4 has d2f_dz2.
    # Let's look at Eq 13: d2f/dx dtheta = (dw/dx)^T. This is for f = theta^T w.
    # So d2f/dx dtheta is (3, 8).
    # The full Hessian block is sum_i d2f_dz2_i * (dzi/dtheta) (dzi/dx).
    # dzi/dx is (C, 3). dzi/dtheta is (C, 8C)?
    # Let's stick to the source's explicit statement: "The second-order derivative block d2f/dx dtheta is given by the transpose of the Jacobian of w w.r.t x".
    # This applies to the interpolation function f.
    # For the SDF phi, we have the chain rule factor d2f_dz2.
    
    # H_x_theta shape (..., 3, 8*C)
    # We can compute this by expanding the result for each channel.
    # For channel i, the contribution is d2f_dz2_i * (dzi/dtheta) (dzi/dx).
    # dzi/dtheta for channel i is a vector of size 8C with w at positions corresponding to theta_i.
    # dzi/dx is a vector of size 3.
    # This results in a 3x8C matrix.
    
    # Simplified approach:
    # H_x_theta = sum_i d2f_dz2_i * (J^T expanded)
    # J is (..., 8, 3). J^T is (..., 3, 8).
    # We need to expand J^T to (..., 3, 8*C) by inserting zeros for other channels.
    
    # Let's construct H_x_theta directly.
    # H_x_theta[..., k, :] where k is 3x1 block.
    # For each channel c, we have a 3x8 block.
    # The block is d2f_dz2_c * J^T.
    
    J_T = J.transpose(-1, -2) # (..., 3, 8)
    
    # Expand J_T to (..., 3, 8*C)
    # H_x_theta = torch.zeros(..., 3, 8*C)
    # for c in range(C):
    #    H_x_theta[..., :, c*8:(c+1)*8] = d2f_dz2[..., c] * J_T
    
    # Vectorized:
    # d2f_dz2 is (..., C). J_T is (..., 3, 8).
    # Reshape d2f_dz2 to (..., C, 1, 1)
    # Reshape J_T to (..., 1, 3, 8)
    # Product is (..., C, 3, 8).
    # Sum over C? No, we need to scatter.
    
    # Actually, the source [S1] Eq 4 is:
    # d2phi/dx dtheta = sum_i d2f_dz2_i * (dzi/dtheta) (dzi/dx)
    # If we assume the regularization term is just the Hessian of the interpolation,
    # then we use (dw/dx)^T.
    
    # Let's provide the implementation for the interpolation Hessian block as per [S1] Eq 13.
    # H_interp_x_theta = J_T # (..., 3, 8)
    # For C dimensions, we stack them.
    
    H_x_theta = torch.zeros(*x.shape[:-1], 3, 8 * theta.shape[-1], device=x.device)
    for c in range(theta.shape[-1]):
        H_x_theta[..., :, c*8:(c+1)*8] = d2f_dz2[..., c:c+1] * J_T
        
    # 4. Compute Hessian_x_omega
    # This is computed via standard backprop.
    # We need to compute dphi/dx and then backprop w.r.t omega.
    # But we need the second derivative.
    # PyTorch supports double backprop through f_omega.
    # We can compute dphi/dx, then .backward(retain_graph=True) w.r.t omega?
    # No, we need d/dx (dphi/domega).
    # This is equivalent to d/domega (dphi/dx).
    # So we compute dphi/dx, then backprop w.r.t omega.
    
    # dphi/dx is (..., 3).
    # We need to sum over batch dimensions if any.
    # Let's assume x is (N, 3).
    
    # This part is framework-dependent. The source [S1] says "Pytorch's automatic differentiation package supports double back-propagation through an MLP".
    # So we can compute:
    # grad_phi_x = dphi/dx
    # grad_phi_x.backward(gradient=torch.ones_like(grad_phi_x), inputs=omega, retain_graph=True)
    # This gives d/domega (dphi/dx).
    
    # However, we must ensure that the computation graph for dphi/dx is preserved.
    
    return H_xx, H_x_theta, None # H_x_omega requires specific backprop logic
```

### Parameters
*   **Feature Dimension $C$**: The derivation assumes 1-D features for simplicity but generalizes to any feature dimension [S1].
*   **Voxel Spacing**: The derivation assumes unit spacing or normalized coordinates $[0,1]$ [S1]. For non-unit spacing, results must be scaled by $1/\Delta x^2$ etc. [G].

### Edge Cases and Pitfalls
*   **PyTorch Limitations**: PyTorch's `grid_sampler` does not support second-order gradients (double back-propagation) through the sampling operation itself [S1]. This method is necessary to bypass this limitation.
*   **Higher-Order Tensors**: The method avoids constructing higher-order tensors by summing over individual feature dimensions $z_i$ [S1].
*   **Boundary Handling**: The method assumes the query point $x$ is within the voxel $[0,1]^3$. Points outside the grid require boundary handling strategies (e.g., clamping, zero-padding) before interpolation, which vary by application [G, unofficial].
*   **Precision**: The analytical derivatives are exact for tri-linear interpolation, avoiding numerical errors from finite differences.

## Operating characteristics
*   **Time Complexity**: The analytical computation of the Hessian blocks is $O(1)$ per query point (constant number of arithmetic operations for the 8 vertices). The dominant cost is the forward and backward passes through the geometry network $f_\omega$ and the grid sampler, which are $O(C)$ and $O(N_{\omega})$ respectively.
*   **Memory Complexity**: $O(C)$ for storing feature gradients and Hessians per query point. No higher-order tensors are stored [S1].
*   **Measured Performance**: The method enables efficient regularization of SDFs in large-scale reconstruction tasks (e.g., GO-Surf) by avoiding the overhead of finite difference stencils or numerical Hessian estimation [S1].
*   **Strengths**: Exact derivatives for tri-linear interpolation; avoids numerical instability of finite differences; compatible with standard deep learning frameworks (with manual implementation of the grid sampler's second derivative).
*   **Limitations**: Requires manual implementation of the second-order grid sampler derivatives; limited to tri-linear interpolation; assumes smooth feature grids.
*   **When to use**: When regularizing the gradient of an SDF defined by a tri-linearly interpolated feature grid in a differentiable rendering pipeline.
*   **When not to use**: When using other interpolation methods (e.g., bilinear, nearest-neighbor) or when the feature grid is not differentiable.

## Background
The Second-order Grid Sampler was introduced by Jingwen Wang, Tymoteusz Bleja, and Lourdes Agapito in the paper "GO-Surf: Neural Feature Grid Optimization for Fast, High-Fidelity RGB-D Surface Reconstruction" (CVPR 2022) [S1]. It was developed to address the challenge of regularizing the gradient of the predicted SDF in neural RGB-D surface reconstruction. The method allows for the computation of the Hessian of the SDF with respect to query coordinates and feature parameters, which is used to enforce the Eikonal equation ($|\nabla \phi| = 1$) and its derivatives, improving the accuracy and completion of the reconstructed meshes. The work was supported by the UCL Centre for Doctoral Training in Foundational AI and Cisco Research [S1].
