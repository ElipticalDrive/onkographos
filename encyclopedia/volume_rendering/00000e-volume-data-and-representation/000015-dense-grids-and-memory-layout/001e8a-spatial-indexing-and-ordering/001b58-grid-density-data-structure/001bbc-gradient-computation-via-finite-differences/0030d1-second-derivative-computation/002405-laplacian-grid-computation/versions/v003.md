# Laplacian Grid Computation
Also called: Divergence of Gradient, Laplacian Field Transformation, Laplacian of Gaussian (LoG) Scale Detection, Normalized Laplacian Detection, Second Derivative Field

## Overview
Laplacian Grid Computation transforms a scalar input field $f(x,y,z)$ into a new scalar field representing the Laplacian $\nabla^2 f$, which is the divergence of the gradient. This operation highlights boundaries and structural features while suppressing homogeneous interiors where the gradient change is constant [S1]. It differs from its sibling [Mean Curvature Grid Computation](3126-mean-curvature-grid-computation.md) by computing the trace of the Hessian (sum of second derivatives) rather than the mean curvature, and from [Divergence Grid Computation](3151-divergence-grid-computation.md) by operating on the gradient field derived from the scalar input rather than an arbitrary vector field.

## How it works
**Inputs and Outputs**
*   **Input**: A scalar grid $f$ with active voxels defined by a grid tree.
*   **Output**: A scalar grid of the same topology, containing $\nabla^2 f$, with background values initialized to zero.

**Data Structures**
*   **Grid Tree**: Defines the spatial extent and active voxels.
*   **Stencil**: A `GradStencil` or neighbor iterator that accesses $f$ at coordinates $c + (\delta_x, \delta_y, \delta_z)$ where $\delta \in \{-1, 0, 1\}$.

**Formulas**
The Laplacian is defined as the sum of second partial derivatives [S1]:
$$ \nabla^2 f(x, y, z) = \frac{\partial^2 f}{\partial x^2} + \frac{\partial^2 f}{\partial y^2} + \frac{\partial^2 f}{\partial z^2} $$
In discrete index space, using central differences, the second derivative along an axis is approximated as $f(x+1) - 2f(x) + f(x-1)$. The divergence of a vector field $F$ is formally defined as the limit of the surface integral over a volume element $V$ [S1]:
$$ \nabla \cdot F \equiv \lim_{V \to 0} \frac{\oint_S F \cdot ds}{V} $$

**Steps**
1.  Initialize a `GradStencil` with the input grid tree.
2.  Iterate over all active voxels $(c, \_)$ in the grid tree.
3.  Move the stencil to the current coordinate $c$.
4.  Compute the Laplacian scalar using the 6-point stencil (accessing immediate neighbors along each axis) [S2, unofficial].
5.  Store the computed value in a dictionary keyed by coordinate.
6.  Build the result grid using the computed data, a background value of zero, and the original grid's voxel size.

**Pseudocode**
```python
def compute_laplacian_grid(input_grid):
    # Initialize output grid with background zero
    output_grid = Grid(topology=input_grid.topology, background=0.0)
    
    # Initialize stencil for neighbor access
    stencil = GradStencil(input_grid)
    
    # Iterate over all active voxels
    for coord in input_grid.active_voxels():
        # Move stencil to current coordinate
        stencil.set_position(coord)
        
        # Access center and neighbors
        # f_center is f(coord)
        # f_x_plus is f(coord + (1,0,0))
        # f_x_minus is f(coord + (-1,0,0))
        # etc.
        
        # Compute second derivatives using central differences
        # d2f_dx2 = f(x+1) - 2f(x) + f(x-1)
        d2f_dx2 = stencil.get(1, 0, 0) - 2.0 * stencil.get(0, 0, 0) + stencil.get(-1, 0, 0)
        d2f_dy2 = stencil.get(0, 1, 0) - 2.0 * stencil.get(0, 0, 0) + stencil.get(0, -1, 0)
        d2f_dz2 = stencil.get(0, 0, 1) - 2.0 * stencil.get(0, 0, 0) + stencil.get(0, 0, -1)
        
        # Sum for Laplacian
        laplacian = d2f_dx2 + d2f_dy2 + d2f_dz2
        
        # Store in output
        output_grid.set_value(coord, laplacian)
        
    return output_grid
```

**Parameters and Edge Cases**
*   **Normalization**: First derivatives are typically scaled by $0.5$ in index space, but the pure Laplacian second derivative uses an implicit multiplier of $1.0$ for the stencil weights [Parent].
*   **Boundary Handling**: Inactive voxels or grid boundaries require specific handling. Common strategies include clamping to the center value or setting the output to zero [Parent].
*   **Pitfall**: Using the first derivative field as input to standard deviation operations is less appropriate for general cases because extrema are not clear boundary indicators and it fails to distinguish objects with similar intensities [S1].

## Subtopics

### [GPU Laplacian Scale-Space Maxima Detection](5852-gpu-laplacian-scale-space-maxima-detection.md)
Detects local maxima of the Laplacian across a scale space to identify blob-like structures. It differs from siblings by merging scale-space diffusion and maxima detection into a single per-iteration pass, avoiding the storage of the full scale-space pyramid in GPU memory.

### [Scale Field Computation](6538-scale-field-computation.md)
Estimates a 3D scalar field $S$ encoding local feature size using iterative non-linear diffusion. It differs from pyramid-based approaches by allowing sub-voxel scale detection and better localization without subsampling granularity limitations.

## Operating characteristics
*   **Complexity**: Time complexity is linear with respect to the number of active voxels, as each voxel requires a constant number of neighbor accesses (6-point stencil). Memory complexity is linear for the output grid.
*   **Performance**: Performance depends on the efficiency of the stencil access and grid traversal. On GPU, coalesced memory access for neighbor reads is critical.
*   **Strengths**: Effectively highlights boundaries and suppresses homogeneous regions. Simple to implement using standard finite difference stencils.
*   **Limitations**: Sensitive to noise, as second derivatives amplify high-frequency components. Linear diffusion can cause nearby objects to merge into a single blob before detection, leading to inaccurate scale maxima localization [S3, unofficial].
*   **When to use**: When boundary detection or feature size estimation (via scale space) is required.
*   **When not to use**: When noise robustness is critical without pre-smoothing, or when first-order gradient information is sufficient.

## Background
The Laplacian operator is a fundamental differential operator in vector calculus, defined as the divergence of the gradient [S1]. In volume rendering, it is used for feature detection and transfer function design. The concept of using the Laplacian for blob detection in scale space was formalized in the context of the Laplacian of Gaussian (LoG) [S3, unofficial]. The specific application to volume data and scale-based transfer functions has been explored in recent research [S1][S3, unofficial].
