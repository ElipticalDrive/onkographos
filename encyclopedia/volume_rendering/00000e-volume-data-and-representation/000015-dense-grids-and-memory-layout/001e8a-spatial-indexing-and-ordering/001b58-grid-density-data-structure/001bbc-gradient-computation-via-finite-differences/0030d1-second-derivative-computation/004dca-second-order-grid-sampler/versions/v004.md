# Second-order Grid Sampler

Also called: Double back-propagation for grid sampler, Hessian computation for SDF, Hessian computation for SDF via double backprop, Second-order derivative computation for SDF regularization, Second-order derivatives via double backpropagation

## Overview
The Second-order Grid Sampler computes the Hessian matrix of a Signed Distance Field (SDF) with respect to 3D query coordinates and feature grid parameters by manually implementing second-order gradients through trilinear interpolation. It solves the problem that standard automatic differentiation frameworks (e.g., PyTorch) do not support double back-propagation through the `grid_sampler` operation, which is required to regularize gradient terms in neural surface reconstruction [S1]. It is distinguished from finite difference methods (see [Second Derivative Computation](6353-second-derivative-computation.md)) by computing exact analytical derivatives of the learned interpolation function rather than approximating them from sampled voxel values, thereby avoiding noise amplification and stencil boundary issues [S1].

## How it works
The method computes the second-order derivatives of the SDF $\phi$ with respect to the query position $x$, feature grid parameters $\theta$, and geometry network parameters $\omega$. The SDF is defined as $\phi(x, \theta, \omega) = f_\omega(z(\theta, x))$, where $z = V_\theta(x)$ is the tri-linearly interpolated feature vector at query point $x$ [S1].

### Inputs and Outputs
**Inputs:**
1.  Query position $x = [x, y, z]^T \in \mathbb{R}^3$, normalized to $[0, 1]$ within the voxel containing the point [S1].
2.  Feature vector $\theta \in \mathbb{R}^8$ containing the values at the 8 vertices of the enclosing voxel, ordered as $[\theta_{000}, \theta_{001}, \theta_{010}, \theta_{011}, \theta_{100}, \theta_{101}, \theta_{110}, \theta_{111}]^T$ [S1].
3.  (Optional) Geometry network parameters $\omega$ and the function $f_\omega$ if mixed derivatives with $\omega$ are required [S1].

**Outputs:**
1.  Hessian block $\frac{\partial^2 \phi}{\partial x^2}$ (3x3 matrix) [S1].
2.  Mixed Hessian block $\frac{\partial^2 \phi}{\partial x \partial \theta}$ (3x8 matrix) [S1].
3.  Mixed Hessian block $\frac{\partial^2 \phi}{\partial x \partial \omega}$ (if $\omega$ is used) [S1].

### Data Structures
*   **Coefficient Vector $w(x)$**: An 8-dimensional vector representing the trilinear interpolation weights for the 8 voxel corners [S1].
*   **Jacobian Matrix $\frac{\partial w}{\partial x}$**: An $8 \times 3$ matrix where each column $J_i$ is the derivative of $w$ with respect to coordinate $i$ ($x, y, z$) [S1].

### Formulas
The first-order gradient of the SDF with respect to $x$ is computed as [S1]:
$$ \frac{\partial \phi}{\partial x} = \sum_{i=1}^C \frac{\partial f_\omega(z)}{\partial z_i} \frac{\partial z_i}{\partial x} $$
where $C$ is the feature dimension (typically 1 for scalar SDF, or higher for multi-channel features) [S1].

The second-order derivatives required for regularization are [S1]:

1.  **Hessian w.r.t. position $x$**:
    $$ \frac{\partial^2 \phi}{\partial x^2} = \sum_{i=1}^C \left( \frac{\partial^2 f_\omega(z)}{\partial z_i^2} \left(\frac{\partial z_i}{\partial x}\right)^2 + \frac{\partial f_\omega(z)}{\partial z_i} \frac{\partial^2 z_i}{\partial x^2} \right) $$
    For the specific case where $f_\omega$ is linear or identity (common in simple grid samplers), the term $\frac{\partial^2 f_\omega}{\partial z_i^2}$ vanishes, leaving the computation dependent on $\frac{\partial^2 z_i}{\partial x^2}$ [S1].

2.  **Mixed Hessian w.r.t. $x$ and $\theta$**:
    $$ \frac{\partial^2 \phi}{\partial x \partial \theta} = \sum_{i=1}^C \frac{\partial^2 f_\omega(z)}{\partial z_i^2} \frac{\partial z_i}{\partial \theta} \frac{\partial z_i}{\partial x} $$
    If $f_\omega$ is linear, this simplifies to the transpose of the Jacobian of the weights [S1]:
    $$ \frac{\partial^2 f}{\partial x \partial \theta} = \left(\frac{\partial w}{\partial x}\right)^T $$

3.  **Mixed Hessian w.r.t. $x$ and $\omega$**:
    $$ \frac{\partial^2 \phi}{\partial x \partial \omega} = \sum_{i=1}^C \left( \frac{\partial^2 f_\omega(z)}{\partial z_i^2} \frac{\partial z_i}{\partial \omega} \frac{\partial z_i}{\partial x} + \frac{\partial f_\omega(z)}{\partial z_i} \frac{\partial^2 z_i}{\partial x \partial \omega} \right) $$
    Note: PyTorch supports double back-propagation through MLPs ($f_\omega$), so this term can often be computed via standard autograd if $f_\omega$ is differentiable, whereas the grid sampler part requires manual implementation [S1].

### Trilinear Interpolation Derivatives
The coefficient vector $w(x)$ for $x=[x,y,z]$ is [S1]:
$$ w(x) = \begin{bmatrix} (1-x)(1-y)(1-z) \\ (1-x)(1-y)z \\ (1-x)y(1-z) \\ (1-x)yz \\ x(1-y)(1-z) \\ x(1-y)z \\ xy(1-z) \\ xyz \end{bmatrix} $$

The Jacobian $\frac{\partial w}{\partial x}$ is an $8 \times 3$ matrix with columns $J_1, J_2, J_3$ [S1]:
$$ J_1 = \frac{\partial w}{\partial x} = \begin{bmatrix} -(1-y)(1-z) \\ -(1-y)z \\ -y(1-z) \\ -yz \\ (1-y)(1-z) \\ (1-y)z \\ y(1-z) \\ yz \end{bmatrix}, \quad J_2 = \frac{\partial w}{\partial y} = \begin{bmatrix} -(1-x)(1-z) \\ -(1-x)z \\ (1-x)(1-z) \\ (1-x)z \\ -x(1-z) \\ -xz \\ x(1-z) \\ xz \end{bmatrix}, \quad J_3 = \frac{\partial w}{\partial z} = \begin{bmatrix} -(1-x)(1-y) \\ (1-x)(1-y) \\ -(1-x)y \\ (1-x)y \\ -x(1-y) \\ x(1-y) \\ -xy \\ xy \end{bmatrix} $$

The Hessian block $\frac{\partial^2 f}{\partial x^2}$ is a $3 \times 3$ matrix $H$ where $H_{ij} = J_i^T \theta J_j$ (for linear $f$) or more generally derived from differentiating $J_i \theta$ [S1].
The diagonal elements $h_{11}, h_{22}, h_{33}$ are zero because each column $J_i$ depends only on the other two dimensions [S1].
The off-diagonal elements are [S1]:
$$ h_{12} = h_{21} = (1-z)(\theta_{000} + \theta_{110} - \theta_{010} - \theta_{100}) + z(\theta_{001} + \theta_{111} - \theta_{011} - \theta_{101}) $$
$$ h_{13} = h_{31} = (1-y)(\theta_{000} + \theta_{101} - \theta_{001} - \theta_{100}) + y(\theta_{010} + \theta_{111} - \theta_{011} - \theta_{110}) $$
$$ h_{23} = h_{32} = (1-x)(\theta_{000} + \theta_{011} - \theta_{001} - \theta_{010}) + x(\theta_{100} + \theta_{111} - \theta_{101} - \theta_{110}) $$

### Pseudocode
```python
import torch

def second_order_grid_sampler(x, theta):
    """
    Computes the Hessian of the SDF with respect to x and theta for a single query point.
    
    Args:
        x: Tensor of shape (3,), query coordinates [x, y, z] in [0, 1].
        theta: Tensor of shape (8,), feature values at voxel corners.
               Order: [000, 001, 010, 011, 100, 101, 110, 111].
               
    Returns:
        hessian_x: Tensor of shape (3, 3), second derivative w.r.t. x.
        hessian_x_theta: Tensor of shape (3, 8), mixed derivative w.r.t. x and theta.
    """
    x_val, y_val, z_val = x[0], x[1], x[2]
    
    # Precompute terms to avoid redundant calculations
    one_minus_x = 1.0 - x_val
    one_minus_y = 1.0 - y_val
    one_minus_z = 1.0 - z_val
    
    # Compute off-diagonal elements of the Hessian w.r.t. x
    # h12 = h21
    term1_12 = one_minus_z * (theta[0] + theta[6] - theta[2] - theta[4])
    term2_12 = z_val * (theta[1] + theta[7] - theta[3] - theta[5])
    h12 = term1_12 + term2_12
    
    # h13 = h31
    term1_13 = one_minus_y * (theta[0] + theta[5] - theta[1] - theta[4])
    term2_13 = y_val * (theta[2] + theta[7] - theta[3] - theta[6])
    h13 = term1_13 + term2_13
    
    # h23 = h32
    term1_23 = one_minus_x * (theta[0] + theta[3] - theta[1] - theta[2])
    term2_23 = x_val * (theta[4] + theta[7] - theta[5] - theta[6])
    h23 = term1_23 + term2_23
    
    # Construct the 3x3 Hessian matrix
    # Diagonal elements are zero
    hessian_x = torch.zeros(3, 3)
    hessian_x[0, 1] = h12
    hessian_x[1, 0] = h12
    hessian_x[0, 2] = h13
    hessian_x[2, 0] = h13
    hessian_x[1, 2] = h23
    hessian_x[2, 1] = h23
    
    # Compute mixed Hessian w.r.t. x and theta
    # This is the transpose of the Jacobian of w w.r.t. x
    # J1 (d/dx)
    j1 = torch.tensor([
        -one_minus_y * one_minus_z,
        -one_minus_y * z_val,
        -y_val * one_minus_z,
        -y_val * z_val,
        one_minus_y * one_minus_z,
        one_minus_y * z_val,
        y_val * one_minus_z,
        y_val * z_val
    ], dtype=theta.dtype, device=theta.device)
    
    # J2 (d/dy)
    j2 = torch.tensor([
        -one_minus_x * one_minus_z,
        -one_minus_x * z_val,
        one_minus_x * one_minus_z,
        one_minus_x * z_val,
        -x_val * one_minus_z,
        -x_val * z_val,
        x_val * one_minus_z,
        x_val * z_val
    ], dtype=theta.dtype, device=theta.device)
    
    # J3 (d/dz)
    j3 = torch.tensor([
        -one_minus_x * one_minus_y,
        one_minus_x * one_minus_y,
        -one_minus_x * y_val,
        one_minus_x * y_val,
        -x_val * one_minus_y,
        x_val * one_minus_y,
        -x_val * y_val,
        x_val * y_val
    ], dtype=theta.dtype, device=theta.device)
    
    # Stack Jacobian columns to form 8x3 matrix, then transpose to get 3x8
    J = torch.stack([j1, j2, j3], dim=1) # Shape (8, 3)
    hessian_x_theta = J.T # Shape (3, 8)
    
    return hessian_x, hessian_x_theta
```

### Parameters and Edge Cases
*   **Feature Dimension**: The derivation assumes 1-D features for simplicity but generalizes to any feature dimension $C$ by summing over dimensions $i=1 \dots C$ [S1].
*   **Coordinate Normalization**: The formulas assume query coordinates $x, y, z$ are normalized to $[0, 1]$ within the voxel. If using world coordinates, they must be converted to local voxel coordinates [S1].
*   **Voxel Boundary**: The method is defined strictly within the voxel enclosing the query point. If the query point lies exactly on a boundary, the interpolation weights are still well-defined, but numerical stability may depend on the specific implementation of the surrounding grid sampler [S1].
*   **Zero Diagonal**: The diagonal elements of the Hessian w.r.t. $x$ are analytically zero for trilinear interpolation. This is a specific property of the linear basis functions used [S1].

## Operating characteristics
*   **Time Complexity**: $O(1)$ per query point, as it involves a fixed number of arithmetic operations (constant number of multiplications and additions) regardless of grid size.
*   **Memory Complexity**: $O(1)$ auxiliary memory per query point.
*   **Strengths**: Provides exact analytical derivatives, avoiding the noise amplification associated with finite difference methods. Integrates seamlessly into gradient-based optimization pipelines (e.g., PyTorch) when implemented as a custom autograd function.
*   **Limitations**: Only applicable to trilinear interpolation. Does not handle non-linear interpolation schemes without re-derivation. Requires manual implementation of the backward pass for the grid sampler component in frameworks that do not support double back-propagation through the sampling operation natively [S1].
*   **When to use**: When regularizing the gradient of an SDF learned via neural feature grids (e.g., in GO-Surf, NeuralRGBD) and exact Hessian information is needed for optimization stability [S1].
*   **When not to use**: When the interpolation is not trilinear, or when approximate derivatives are sufficient and finite differences are preferred for simplicity [S1].

## Background
The method was introduced in the context of "GO-Surf: Neural Feature Grid Optimization for Fast, High-Fidelity RGB-D Surface Reconstruction" by Jingwen Wang, Tymoteusz Bleja, and Lourdes Agapito (2022) [S1]. It addresses the limitation of PyTorch's `grid_sampler` which lacks support for second-order gradients (double back-propagation) through the sampling operation, a requirement for regularizing the gradient term of the SDF in their learning framework [S1]. The approach builds on the analytical derivatives of trilinear interpolation, allowing the computation of Hessian blocks with respect to query positions and feature parameters without resorting to finite differences [S1].
