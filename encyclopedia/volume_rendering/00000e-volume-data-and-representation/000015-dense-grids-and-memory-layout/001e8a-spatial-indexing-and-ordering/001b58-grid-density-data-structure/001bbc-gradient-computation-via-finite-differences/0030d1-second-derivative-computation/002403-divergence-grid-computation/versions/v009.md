# Divergence Grid Computation

Also called: Divergence Calculation with Obstacle Velocity Boundary Conditions, Divergence Computation, Finite Difference Divergence

## Overview
Computes the divergence $\nabla \cdot \mathbf{F}$ of a vector field grid at every active voxel using central differences [S1, S2, unofficial]. It is distinct from sibling methods like [Laplacian Grid Computation](3160-laplacian-grid-computation.md) because it operates on a vector field rather than a scalar field, summing the partial derivatives of each component along its respective axis [S1, S2, unofficial]. It is primarily used in fluid simulation to enforce incompressibility constraints via projection steps [S2, unofficial].

## How it works
**Inputs:**
- A vector grid $\mathbf{V}$ where each active voxel stores a 3D vector $(v_x, v_y, v_z)$ [S1, unofficial].
- A boundary mask or obstacle grid indicating solid cells [G].
- Obstacle velocity data for solid cells [G].
- A list of active voxel coordinates from the grid tree [S1, unofficial].

**Outputs:**
- A scalar grid $\Phi$ where each active voxel stores the divergence value [S1, unofficial].

**Data Structures:**
- The grid stores active voxel coordinates in a tree structure [S1, unofficial].
- Neighbors are accessed via a 6-point cross stencil: Left ($-x$), Right ($+x$), Bottom ($-y$), Top ($+y$), Down ($-z$), Up ($+z$) [G].

**Steps:**
1. Initialize a GradStencil with the grid tree [S1, unofficial].
2. Iterate over all active voxels $(c_x, c_y, c_z)$ in the grid [S1, unofficial].
3. Sample velocity vectors from the six neighboring cells (Left, Right, Bottom, Top, Down, Up) [S2, unofficial].
4. If a neighboring cell is a boundary cell, replace its velocity with the obstacle velocity at that location [S2, unofficial].
5. Move the stencil to the current coordinate $c$ [S1, unofficial].
6. Compute the divergence using the formula and store it in a dictionary keyed by coordinate [S1, unofficial].
7. Build the result grid using the computed data, a background value of zero, and the original grid's voxel size [S1, unofficial].
8. Return the computed divergence [S1, unofficial].

**Formula:**
$$ \text{div} = 0.5 \times \left( (v_{R,x} - v_{L,x}) + (v_{T,y} - v_{B,y}) + (v_{U,z} - v_{D,z}) \right) $$
where $v_{R,x}$ is the x-component of the right neighbor's velocity, etc. [S2, unofficial]. The scalar $0.5$ represents $1/(2 \cdot \text{voxel\_size})$ in index space [S1, unofficial].

**Pseudocode:**
```python
def compute_divergence_grid(active_voxels, velocity_grid, obstacle_mask, obstacle_velocity, voxel_size):
    """
    Computes divergence of a velocity grid with obstacle boundary conditions.
    """
    div_results = {}
    for c in active_voxels:
        # Sample six neighbors
        v_L = velocity_grid[c + (-1, 0, 0)]
        v_R = velocity_grid[c + (1, 0, 0)]
        v_B = velocity_grid[c + (0, -1, 0)]
        v_T = velocity_grid[c + (0, 1, 0)]
        v_D = velocity_grid[c + (0, 0, -1)]
        v_U = velocity_grid[c + (0, 0, 1)]
        
        # Apply obstacle boundary conditions
        if obstacle_mask[c + (-1, 0, 0)]: v_L = obstacle_velocity[c + (-1, 0, 0)]
        if obstacle_mask[c + (1, 0, 0)]: v_R = obstacle_velocity[c + (1, 0, 0)]
        if obstacle_mask[c + (0, -1, 0)]: v_B = obstacle_velocity[c + (0, -1, 0)]
        if obstacle_mask[c + (0, 1, 0)]: v_T = obstacle_velocity[c + (0, 1, 0)]
        if obstacle_mask[c + (0, 0, -1)]: v_D = obstacle_velocity[c + (0, 0, -1)]
        if obstacle_mask[c + (0, 0, 1)]: v_U = obstacle_velocity[c + (0, 0, 1)]
        
        # Compute divergence
        div = 0.5 * ((v_R[0] - v_L[0]) + (v_T[1] - v_B[1]) + (v_U[2] - v_D[2]))
        div_results[c] = div
        
    # Build result grid using computed data, background 0, and original voxel size
    return div_results
```

**Parameters:**
- `half`: The scalar multiplier $0.5$, representing $1/(2 \cdot \text{voxel\_size})$ in index space [S1, unofficial].

**Edge Cases:**
- **Boundary Cells:** The method explicitly checks if neighbors are boundary cells. If a neighbor is solid, its velocity is replaced by the obstacle velocity [S2, unofficial].
- **Out of Bounds:** Standard implementations assume zero-padding for neighbors outside the active domain [G].

## Subtopics

### Projection Step with Free-Slip Boundary Conditions
A variant used in the pressure projection step of fluid simulation. It computes the pressure gradient $\nabla p$ and subtracts it from the old velocity to enforce divergence-free flow, while explicitly handling free-slip boundary conditions [S2, unofficial].
- **Mechanism:** If the center cell is solid, return the obstacle velocity immediately. Otherwise, sample pressure from the center and six neighbors. If a neighbor is solid, set its pressure to the center pressure and accumulate its obstacle velocity component into an accumulator `obstV` with a corresponding mask component set to 0 [S2, unofficial].
- **Formula:**
  $$ \nabla p = 0.5 \times (p_R - p_L, p_T - p_B, p_U - p_D) $$
  $$ \mathbf{v}_{new} = \mathbf{v}_{old} - \nabla p $$
  $$ \mathbf{v}_{final} = (\mathbf{v}_{new} \odot \mathbf{v}_{mask}) + \mathbf{v}_{obst} $$
  where $\odot$ is component-wise multiplication [S2, unofficial].
- **When to choose:** Use this when simulating fluids with solid obstacles where the fluid can slide along the surface (free-slip) rather than sticking to it (no-slip) [S2, unofficial].

## Operating characteristics
- **Performance:** Real-time performance is achievable on GPU using fragment shaders or compute shaders, as demonstrated in GPU Gems 3 [S2, unofficial]. The operation is memory-bandwidth bound due to the 6 neighbor samples per voxel [S2, unofficial].
- **Complexity:** Time complexity is $O(N)$ where $N$ is the number of active voxels, and memory complexity is $O(N)$ for the result dictionary and grid [G].
- **Strengths:** Handles obstacles explicitly by injecting boundary velocities into the stencil [S2, unofficial].
- **Limitations:** Accuracy is limited by the discrete central difference approximation [G].

## Background
The method originates from real-time fluid simulation techniques, specifically those described in *GPU Gems 3* for simulating 3D fluids on the GPU [S2, unofficial]. It is a fundamental component of the projection method for solving the Navier-Stokes equations in a discrete grid setting [S2, unofficial]. The specific handling of obstacle velocities for divergence calculation ensures that the pressure projection step correctly enforces boundary conditions [S2, unofficial].
