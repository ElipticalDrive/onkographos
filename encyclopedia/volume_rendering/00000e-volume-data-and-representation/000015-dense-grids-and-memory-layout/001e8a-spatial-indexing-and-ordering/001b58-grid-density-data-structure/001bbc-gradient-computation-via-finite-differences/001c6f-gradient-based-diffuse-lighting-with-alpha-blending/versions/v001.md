# Gradient-based Diffuse Lighting with Alpha Blending

Also called: Gradient-based Diffuse Lighting

## Overview
This method applies diffuse lighting to a scalar volume by estimating surface normals from voxel gradients and compositing the lit color into a framebuffer using front-to-back alpha blending. It differs from its parent, [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md), by integrating the lighting calculation and compositing step directly into the rendering loop, rather than just storing precomputed gradients. It is distinct from the [Sobel Operator](1416-sobel-operator.md) sibling, which is a specific kernel-based gradient estimation technique, whereas this method uses central differences for gradient estimation within the lighting context.

## How it works
**Inputs:**
- `parent`: The volume data structure containing:
  - `width`: Integer width of the volume grid.
  - `zSize`: Integer depth (z-dimension) of the volume grid.
  - `v2`: 1D array of voxel values (integers, typically 0-255).
  - `transfer_a`: 1D array of 32-bit integers storing alpha values indexed by voxel value.
  - `transfer_rgb`: 1D array of 32-bit integers storing RGB values indexed by voxel value.
- `light`: A 3D vector $(light[0], light[1], light[2])$ representing the light direction.
- `out_a`: Accumulated alpha (float, initialized to 0.0).
- `rgb`: Accumulated color (array of 3 floats, initialized to 0.0).

**Outputs:**
- Updated `out_a`: Accumulated alpha.
- Updated `rgb`: Accumulated color.

**Data Structures:**
- Voxel values are accessed via linear indexing. The source code implies a specific memory layout where the index calculation involves `id_a`, `id_b`, and `id_c`. Based on the formula `v(id_c, id_a + id_b*width)`, the layout appears to be:
  - `id_b` is the row index (0 to `width-1`? No, `width` is used as stride for `id_a`). Let's analyze the index formula carefully.
  - Formula: `v(id_c, id_a + id_b*width)`.
  - This suggests a 3D array `v[z][x + y*width]`.
  - `id_a` corresponds to `x`.
  - `id_b` corresponds to `y`.
  - `id_c` corresponds to `z`.
  - The linear index into `v2` is `id_c * (width * height) + id_a + id_b * width`. However, the source code snippet `v(id_c, id_a + id_b*width)` suggests `v` is treated as a 2D array in the formula description, but `v2` is 1D. The linear index $I$ for voxel $(x, y, z)$ is $z \cdot W \cdot H + y \cdot W + x$.
  - The source code uses `id_a`, `id_b`, `id_c` as coordinates.
  - Neighbor indices are calculated relative to `id_a`, `id_b`, `id_c`.

**Steps:**

1.  **Gradient Estimation:**
    Calculate the 3D gradient vector $\mathbf{g} = (g_x, g_y, g_z)$ using central differences on the least significant byte (0-255) of the voxel values, normalized by 255.0.
    
    Let $V(x, y, z)$ be the voxel value at coordinates $(x, y, z)$.
    
    $$g_x = \frac{V(x+1, y, z) \ \& \ 0xFF}{255.0} - \frac{V(x-1, y, z) \ \& \ 0xFF}{255.0}$$
    
    $$g_y = \frac{V(x, y+1, z) \ \& \ 0xFF}{255.0} - \frac{V(x, y-1, z) \ \& \ 0xFF}{255.0}$$
    
    $$g_z = \frac{V(x, y, z+1) \ \& \ 0xFF}{255.0} - \frac{V(x, y, z-1) \ \& \ 0xFF}{255.0}$$
    
    *Note: Boundary conditions must be handled by clamping neighbor indices to the valid range $[0, \text{dim}-1]$.*

2.  **Gradient Normalization:**
    Calculate the magnitude of the gradient:
    $$|\mathbf{g}| = \sqrt{g_x^2 + g_y^2 + g_z^2}$$
    
    If $|\mathbf{g}| > 0$:
    $$\mathbf{n} = \left( \frac{g_x}{|\mathbf{g}|}, \frac{g_y}{|\mathbf{g}|}, \frac{g_z}{|\mathbf{g}|} \right)$$
    Else:
    $$\mathbf{n} = (0, 0, 0)$$

3.  **Diffuse Lighting Factor:**
    Calculate the diffuse lighting factor $D$ using the dot product of the normalized gradient $\mathbf{n}$ and the light vector $\mathbf{l}$:
    $$D = \max(n_x l_x + n_y l_y + n_z l_z, 0)$$

4.  **Transfer Function Lookup:**
    Extract the color and alpha for the current voxel value $v$.
    
    Alpha:
    $$\alpha_{src} = \frac{\text{parent.transfer\_a}[v] \ \& \ 0x000000FF}{255}$$
    
    RGB:
    Let $rgb\_val = \text{parent.transfer\_rgb}[v]$.
    $$R_{src} = \frac{(rgb\_val \ \& \ 0x00FF0000) \gg 16}{255.0}$$
    $$G_{src} = \frac{(rgb\_val \ \& \ 0x0000FF00) \gg 8}{255.0}$$
    $$B_{src} = \frac{rgb\_val \ \& \ 0x000000FF}{255.0}$$

5.  **Lighting Application:**
    Apply diffuse lighting to the source color components with an ambient term of 0.25. The result is clamped to 1.0.
    
    $$R_{lit} = \min(D \cdot R_{src} + 0.25 \cdot R_{src}, 1.0)$$
    $$G_{lit} = \min(D \cdot G_{src} + 0.25 \cdot G_{src}, 1.0)$$
    $$B_{lit} = \min(D \cdot B_{src} + 0.25 \cdot B_{src}, 1.0)$$

6.  **Alpha Blending (Front-to-Back):**
    Composite the lit color into the accumulated framebuffer.
    
    $$R_{out} = (1.0 - \alpha_{out}) \cdot R_{lit} \cdot \alpha_{src} + R_{out}$$
    $$G_{out} = (1.0 - \alpha_{out}) \cdot G_{lit} \cdot \alpha_{src} + G_{out}$$
    $$B_{out} = (1.0 - \alpha_{out}) \cdot B_{lit} \cdot \alpha_{src} + B_{out}$$
    
    Update accumulated alpha:
    $$\alpha_{out} = (1.0 - \alpha_{out}) \cdot \alpha_{src} + \alpha_{out}$$

7.  **Output Packing (Optional/Contextual):**
    If the final pixel color needs to be stored as a 32-bit integer with opaque alpha (as suggested by the source's final packing step, though this step seems to describe a final pixel write rather than the accumulation step itself):
    $$R_{final} = \lfloor R_{out} \cdot 255 \rfloor$$
    $$G_{final} = \lfloor G_{out} \cdot 255 \rfloor$$
    $$B_{final} = \lfloor B_{out} \cdot 255 \rfloor$$
    $$Pixel = (255 \ll 24) \ | \ (R_{final} \ll 16) \ | \ (G_{final} \ll 8) \ | \ B_{final}$$

**Pseudocode:**

```python
def gradient_based_diffuse_lighting_with_alpha_blending(
    parent, light, out_a, rgb, x, y, z
):
    # 1. Gradient Estimation with Boundary Clamping
    # Dimensions
    width = parent.width
    z_size = parent.zSize
    # Assuming height is derived or part of parent, but source only mentions width and zSize.
    # The index formula v(id_c, id_a + id_b*width) implies a 2D slice structure.
    # We need height to calculate full linear index. 
    # However, the source code uses v2 as a 1D array.
    # Let's assume parent has 'height' or we calculate linear index directly.
    # The source formula: v(id_c, id_a + id_b*width)
    # This implies the inner loop is 'a' (x), middle is 'b' (y), outer is 'c' (z).
    # Linear index I = c * (width * height) + b * width + a.
    # We need 'height'. If not given, we assume it's available in parent or derived.
    # For the sake of implementation, let's assume parent.height exists.
    height = parent.height if hasattr(parent, 'height') else None
    
    if height is None:
        raise ValueError("Height is required to compute linear indices.")

    def get_voxel_val(a, b, c):
        # Clamp indices
        a = max(0, min(a, width - 1))
        b = max(0, min(b, height - 1))
        c = max(0, min(c, z_size - 1))
        
        # Linear index
        idx = c * (width * height) + b * width + a
        val = parent.v2[idx]
        return (val & 0xFF) / 255.0

    # Central differences
    gx = get_voxel_val(x + 1, y, z) - get_voxel_val(x - 1, y, z)
    gy = get_voxel_val(x, y + 1, z) - get_voxel_val(x, y - 1, z)
    gz = get_voxel_val(x, y, z + 1) - get_voxel_val(x, y, z - 1)

    # 2. Gradient Normalization
    grad_l = (gx**2 + gy**2 + gz**2)**0.5
    if grad_l > 0:
        nx = gx / grad_l
        ny = gy / grad_l
        nz = gz / grad_l
    else:
        nx, ny, nz = 0.0, 0.0, 0.0

    # 3. Diffuse Lighting Factor
    diffuse = max(nx * light[0] + ny * light[1] + nz * light[2], 0)

    # 4. Transfer Function Lookup
    val = parent.v2[c * (width * height) + b * width + a] # Use current x,y,z
    # Note: The source uses 'value' from the loop context.
    # We need the linear index for the current voxel to lookup transfer function.
    current_idx = z * (width * height) + y * width + x
    current_val = parent.v2[current_idx]
    
    transfer_a_val = parent.transfer_a[current_val]
    transfer_rgb_val = parent.transfer_rgb[current_val]
    
    aa = (transfer_a_val & 0x000000FF) / 255.0
    
    vv_alpha = (transfer_rgb_val >> 24) / 255.0 # Unused in blending formula? Source extracts it.
    vv_red = ((transfer_rgb_val & 0x00FF0000) >> 16) / 255.0
    vv_green = ((transfer_rgb_val & 0x0000FF00) >> 8) / 255.0
    vv_blue = (transfer_rgb_val & 0x000000FF) / 255.0

    # 5. Lighting Application
    # Ambient term 0.25
    vv_red = min(diffuse * vv_red + 0.25 * vv_red, 1.0)
    vv_green = min(diffuse * vv_green + 0.25 * vv_green, 1.0)
    vv_blue = min(diffuse * vv_blue + 0.25 * vv_blue, 1.0)

    # 6. Alpha Blending
    rgb[0] = (1.0 - out_a) * vv_red * aa + rgb[0]
    rgb[1] = (1.0 - out_a) * vv_green * aa + rgb[1]
    rgb[2] = (1.0 - out_a) * vv_blue * aa + rgb[2]
    
    out_a = (1.0 - out_a) * aa + out_a
    
    return out_a, rgb
```

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel for the lighting and blending step, assuming constant-time transfer function lookup and gradient computation. The gradient computation requires 6 neighbor lookups.
- **Memory Complexity:** $O(1)$ additional memory per voxel for the current step, plus the storage for the transfer functions and volume data.
- **Performance:** The method is computationally lightweight per voxel, suitable for CPU-based direct volume rendering as indicated by the source repository name. However, the 6 neighbor lookups for gradient estimation and the transfer function lookups add overhead compared to simple alpha blending.
- **Strengths:** Provides surface-like shading effects without explicit surface extraction. Simple to implement.
- **Limitations:** Gradient estimation via central differences can be noisy in low-resolution volumes. Boundary handling requires clamping, which may distort normals at edges. The method assumes a specific memory layout and transfer function format.

## Background
The method is derived from a direct volume rendering implementation on the CPU, as seen in the `browarsoftware/directvolumerenderingcpu` repository. It combines gradient-based normal estimation with standard front-to-back alpha compositing.
