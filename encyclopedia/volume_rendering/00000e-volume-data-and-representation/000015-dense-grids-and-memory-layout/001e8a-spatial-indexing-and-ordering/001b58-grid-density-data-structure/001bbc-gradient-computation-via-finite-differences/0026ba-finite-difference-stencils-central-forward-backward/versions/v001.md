# Finite Difference Stencils (Central/Forward/Backward)

Also called: Finite Difference Gradients, FD Stencils

## Overview
Finite difference stencils compute the spatial gradient of a scalar volume by approximating partial derivatives using discrete samples from neighboring voxels. This method solves the problem of estimating surface normals or density rates of change for ray marching and shading without requiring analytic derivatives of the underlying basis functions. It differs from [Analytic Gradient Computation](2167-analytic-gradient-computation.md) by relying on numerical approximation rather than closed-form differentiation, and from [Gradient Estimation from Samples](2180-gradient-estimation-from-samples.md) by using fixed geometric offsets rather than statistical sampling of ray hits.

## Shared principles
All finite difference stencils approximate the first derivative of a function $f(\mathbf{x})$ at a point $\mathbf{x}$ using a weighted sum of function values at discrete grid points. The general form for a partial derivative with respect to coordinate $i$ is:

$$ \frac{\partial f}{\partial x_i} \approx \sum_{k} w_k f(\mathbf{x} + \delta_k \mathbf{e}_i) $$

where $w_k$ are weights and $\delta_k$ are offsets along the axis $\mathbf{e}_i$. The accuracy of the stencil is determined by the order of the Taylor series expansion it matches. Lower-order stencils (like forward/backward) use fewer samples but suffer from bias or lower accuracy, while higher-order stencils (like central or 4th-order) use more samples to reduce truncation error. The choice of stencil dictates the number of memory accesses (samples) required per gradient component.

## Subtopics

### Central Differences
Central differences approximate the derivative using points on both sides of the target voxel. For a 1D function $f$, the first-order central difference is:

$$ f'(x) \approx \frac{f(x + h) - f(x - h)}{2h} $$

In 3D, this requires 2 samples per axis (6 total for the full gradient vector). It is second-order accurate ($O(h^2)$) and unbiased for interior points. It is the standard choice for smooth volumes where boundary effects are minimal or handled separately.

### Forward Differences
Forward differences approximate the derivative using the current voxel and the next voxel in the positive direction:

$$ f'(x) \approx \frac{f(x + h) - f(x)}{h} $$

This requires 2 samples per axis (6 total). It is first-order accurate ($O(h)$) and introduces a directional bias. It is typically used when memory bandwidth is constrained or when computing gradients at boundaries where backward points are unavailable, though [Neumann Gradient](3342-neumann-gradient.md) offers a more robust boundary handling strategy.

### Backward Differences
Backward differences approximate the derivative using the current voxel and the previous voxel in the negative direction:

$$ f'(x) \approx \frac{f(x) - f(x - h)}{h} $$

This requires 2 samples per axis (6 total). Like forward differences, it is first-order accurate and biased. It is the mirror counterpart to forward differences and is rarely used in isolation for volume rendering unless specific directional constraints exist.

### Clamped Central Differences
#### definition
- [S1] A variant of central differencing for gradient computation that clamps offset positions to the current region to avoid additional ray traversals.
#### step
- [S1] Compute six additional basis reconstruction samples at positions offset from the current sample by a distance proportional to the region's sample rate.
- [S1] Clamp the offset positions to the current region before evaluating them.
#### pitfall
- [S1] Gradients are not necessarily continuous at level boundaries because the offset size can change.
#### comparison
- [S1] Accurate central differencing requires tracing 6 additional rays per sample via infinitesimal rays to find containing regions, which is expensive. Clamped version removes ray traversals but reduces quality.

### Curl Grid Computation
#### definition
- [S2, unofficial] Computes the curl ∇×F at every active voxel of a vector grid using central differences.
#### step
- [S2, unofficial] Initialize a GradStencil with the grid tree.
- [S2, unofficial] Iterate over all active voxels (c, _) in the grid tree.
- [S2, unofficial] Move the stencil to the current coordinate c.
- [S2, unofficial] Compute the x, y, and z components of the curl using the formulas and store the tuple (cx, cy, cz) in a dictionary keyed by coordinate.
- [S2, unofficial] Build the result grid using the computed data, a background value of zero vector (0,0,0), and the original grid's voxel size.
#### formula
- [S2, unofficial] curl_x = (v[4][3] - v[5][3] - v[6][2] + v[7][2]) * 0.5
- [S2, unofficial] curl_y = (v[6][1] - v[7][1] - v[2][3] + v[3][3]) * 0.5
- [S2, unofficial] curl_z = (v[2][2] - v[3][2] - v[4][1] + v[5][1]) * 0.5
#### parameter
- [S2, unofficial] half: The scalar multiplier 0.5, representing 1/(2*voxel_size) in index space.

### WENO5 Interpolation
#### definition
- [S3] Implementation of nominally fifth-order finite-difference WENO that returns the numerical flux for interpolation.
- [S3] Implementation of nominally fifth-order finite-difference WENO.
#### formula
- [S3] Given $v_1 = f(x-2dx)$, $v_2 = f(x-dx)$, $v_3 = f(x)$, $v_4 = f(x+dx)$ and $v_5 = f(x+2dx)$, return an interpolated value $f(x+dx/2)$ with the special property that $( f(x+dx/2) - f(x-dx/2) ) / dx = df/dx (x) + error$, where the error is fifth-order in smooth regions: $O(dx) \le error \le O(dx^5)$
#### parameter
- [S3] scale2: A scaling factor for the weights, default value is 1.0.
- [S3] v1, v2, v3, v4, v5: Five input values for the stencil.
- [S3] scale2: Scaling factor, defaults to 1.0.
- [S3] RealT: Type for scale2, defaults to ValueType.
#### history
- [S3] Introduced by Chi-Wang Shu. Referenced in 'High Order Finite Difference and Finite Volume WENO Schemes and Discontinuous Galerkin Methods for CFD' (ICASE Report No 2001-11, page 6) and ICASE No 97-65 (Shu, 1997).

## Background
Finite difference methods are a cornerstone of numerical analysis, dating back to the early 20th century. In the context of volume rendering, they were popularized as a practical alternative to analytic gradients for complex basis functions or sparse data structures like AMR (Adaptive Mesh Refinement). The specific implementation details for ray-traced AMR data, such as handling region boundaries and infinitesimal ray tracing for accurate offsets, are documented in the ExaBricks framework [S1]. The use of higher-order schemes like WENO for smoothness in CFD-derived volumes is standard practice [S3]. The trade-off between computational cost and visual quality, particularly regarding the number of samples required (e.g., 6 for central vs. 54 for Zucker-Hummel), is a key consideration in real-time rendering systems [S4, unofficial].
