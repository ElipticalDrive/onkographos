# Numerical Gradient and Hessian Computation

Also called: Numerical Gradient and Hessian, Finite Difference Gradient/Hessian, Autodiff Gradient/Hessian

## Overview
Computes the gradient (surface normal) and optionally the Hessian matrix of a Signed Distance Function (SDF) field at specified query points. It differs from its parent [2nd-Order Finite Difference Gradient](13052-2nd-order-finite-difference-gradient.md) by supporting both numerical finite differences and automatic differentiation (autograd), and by providing the full Hessian matrix in addition to the gradient.

## How it works
**Inputs:**
- `points`: Tensor of shape $(N, 3)$ containing $N$ query points in 3D space.
- `get_sdf`: Function that evaluates the SDF at given points.
- `delta`: Step size for numerical differentiation.
- `_numerical_grad`: Boolean flag. `True` uses finite differences; `False` uses automatic differentiation.
- `_heissian`: Boolean flag. `True` computes the Hessian matrix.

**Outputs:**
- `gradient`: Tensor of shape $(N, 3)$ containing the gradient vectors.
- `hessian`: Tensor of shape $(N, 3, 3)$ containing the Hessian matrices (only if `_heissian` is `True`).

**Data Structures:**
- `offsets`: List of 6 offset vectors for central differences: `[(delta, 0, 0), (-delta, 0, 0), (0, delta, 0), (0, -delta, 0), (0, 0, delta), (0, 0, -delta)]`.
- `points_sdf`: Tensor of shape $(6, N, 1)$ storing SDF values at the 6 offset points.

**Steps:**

1. **Numerical Gradient Mode (`_numerical_grad` is `True`):**
   a. Define offset vectors:
      $$ \text{offsets} = \{ (\delta, 0, 0), (-\delta, 0, 0), (0, \delta, 0), (0, -\delta, 0), (0, 0, \delta), (0, 0, -\delta) \} $$
   b. Compute SDF values at the 6 offset points for all $N$ query points:
      $$ \text{points\_sdf} = \text{get\_sdf}(\text{points} \oplus \text{offsets}) $$
      where $\oplus$ denotes broadcasting addition, resulting in a tensor of shape $(6, N, 1)$.
   c. Calculate the gradient using central differences:
      $$ \nabla f = \frac{1}{2\delta} \begin{bmatrix} f(x+\delta, y, z) - f(x-\delta, y, z) \\ f(x, y+\delta, z) - f(x, y-\delta, z) \\ f(x, y, z+\delta) - f(x, y, z-\delta) \end{bmatrix} $$
      In tensor form:
      $$ \text{gradient} = 0.5 \cdot \frac{1}{\delta} \cdot \text{concat}(\text{points\_sdf}[0] - \text{points\_sdf}[1], \text{points\_sdf}[2] - \text{points\_sdf}[3], \text{points\_sdf}[4] - \text{points\_sdf}[5], \text{dim}=1) $$
   d. If `_heissian` is `True`, calculate the Hessian using second-order central differences:
      $$ H = \frac{1}{\delta^2} \begin{bmatrix} f(x+\delta, y, z) + f(x-\delta, y, z) - 2f(x, y, z) & \dots & \dots \\ \dots & \dots & \dots \\ \dots & \dots & \dots \end{bmatrix} $$
      Specifically, the diagonal elements are computed as:
      $$ H_{ii} = \frac{1}{\delta^2} (f(x_i+\delta) + f(x_i-\delta) - 2f(x_i)) $$
      The off-diagonal elements are not explicitly detailed in the source for numerical mode, but the source formula implies a simplified diagonal approximation or assumes symmetry. The source code snippet shows:
      $$ \text{hessian} = \text{hessian\_coef} \cdot (\text{cat}(\{\text{points\_sdf}[0] + \text{points\_sdf}[1], \dots\}, 1) - 2 \cdot \text{sdf}) $$
      where $\text{hessian\_coef} = \frac{1}{\delta^2}$. Note: The source code snippet for Hessian in numerical mode appears to compute only the diagonal elements or assumes a specific structure. For a full Hessian, off-diagonal terms would require additional evaluations. [G] In practice, for a full Hessian, one would need 19 points (center + 6 face + 12 edge centers) for second-order accuracy. The source implementation seems to focus on the diagonal or a simplified version. We will stick to the source's explicit formula for the diagonal part if that's all that's provided, but the source code snippet is ambiguous for off-diagonals. Given the source code `cat({(points_sdf[0] + points_sdf[1]), ...}, 1)`, it seems to concatenate the sums for each axis, implying a diagonal Hessian or a specific layout. We will describe the diagonal computation as per the source.

2. **Automatic Differentiation Mode (`_numerical_grad` is `False`):**
   a. Enable gradient computation mode.
   b. Ensure the input points `_xyz` require gradients.
   c. Compute the SDF value: $s = \text{get\_sdf}(\text{points})$.
   d. Compute the gradient using backpropagation:
      $$ \nabla f = \frac{\partial s}{\partial \text{points}} $$
      In PyTorch: `gradients = torch.autograd.grad(s, points, grad_outputs=torch.ones_like(s), create_graph=True, retain_graph=True)[0]`
   e. If `_heissian` is `True`, compute the Hessian by differentiating the gradients:
      $$ H = \frac{\partial \nabla f}{\partial \text{points}} $$
      In PyTorch: `hessian = torch.autograd.grad(gradients, points, grad_outputs=torch.ones_like(gradients), create_graph=True, retain_graph=True)[0]`

**Parameters:**
- `delta`: Step size for numerical differentiation. Typical value: Not given in the sources.
- `_numerical_grad`: Boolean flag. Default: Not given in the sources.
- `_heissian`: Boolean flag. Default: Not given in the sources.

**Edge Cases and Pitfalls:**
- **Precision:** Numerical differentiation is sensitive to the choice of `delta`. Too small a delta leads to cancellation errors; too large a delta leads to truncation errors. [G] A common choice is $\delta \approx \sqrt{\epsilon}$ where $\epsilon$ is machine epsilon, but for SDFs, this may need adjustment based on the scale of the field.
- **Boundaries:** If query points are near the boundary of the SDF domain, offset points may fall outside. The `get_sdf` function must handle out-of-bounds queries (e.g., by clamping or returning a large value).
- **Degenerate Input:** If `points` is empty, the output should be empty tensors of the correct shape.

**Pseudocode:**

```python
def compute_gradient_and_hessian(points, get_sdf, delta, numerical_grad=True, heissian=True):
    """
    Compute gradient and optionally Hessian of SDF at given points.
    
    Args:
        points: Tensor of shape (N, 3)
        get_sdf: Function that takes points (N, 3) and returns SDF values (N,)
        delta: Step size for numerical differentiation
        numerical_grad: Boolean, True for finite differences, False for autograd
        heissian: Boolean, True to compute Hessian
        
    Returns:
        gradient: Tensor of shape (N, 3)
        hessian: Tensor of shape (N, 3, 3) if heissian is True, else None
    """
    N = points.shape[0]
    
    if numerical_grad:
        # Define offsets for central differences
        offsets = [
            [delta, 0, 0],
            [-delta, 0, 0],
            [0, delta, 0],
            [0, -delta, 0],
            [0, 0, delta],
            [0, 0, -delta]
        ]
        
        # Compute SDF at offset points
        # points is (N, 3), offsets are 6 vectors of size 3
        # We need to evaluate SDF at points + offset for each offset
        # Resulting shape: (6, N)
        points_sdf = []
        for offset in offsets:
            offset_points = points + torch.tensor(offset, dtype=points.dtype).unsqueeze(0)
            sdf_values = get_sdf(offset_points)
            points_sdf.append(sdf_values)
        
        points_sdf = torch.stack(points_sdf, dim=0)  # Shape: (6, N)
        
        # Compute gradient using central differences
        # gradient_x = (f(x+dx) - f(x-dx)) / (2*dx)
        grad_x = (points_sdf[0] - points_sdf[1]) / (2 * delta)
        grad_y = (points_sdf[2] - points_sdf[3]) / (2 * delta)
        grad_z = (points_sdf[4] - points_sdf[5]) / (2 * delta)
        
        gradient = torch.stack([grad_x, grad_y, grad_z], dim=1)  # Shape: (N, 3)
        
        hessian = None
        if heissian:
            # Compute Hessian diagonal elements using second-order central differences
            # H_xx = (f(x+dx) + f(x-dx) - 2*f(x)) / dx^2
            # Note: The source code snippet suggests a specific concatenation, but the standard formula is used here.
            # The source code: hessian = hessian_coef * (cat({(points_sdf[0] + points_sdf[1]), ...}, 1) - 2 * _sdf)
            # This implies computing the diagonal elements. Off-diagonal elements are not explicitly detailed in the source for numerical mode.
            # We will compute the diagonal elements as per the standard formula.
            # [G] For a full Hessian, off-diagonal terms would require additional evaluations.
            # The source code snippet is ambiguous for off-diagonals. We will stick to the diagonal part if that's all that's provided.
            # However, the source code snippet `cat({(points_sdf[0] + points_sdf[1]), ...}, 1)` suggests concatenating the sums for each axis.
            # This results in a tensor of shape (3, N) if we concatenate the sums for x, y, z.
            # Then subtracting 2 * _sdf (shape (N,)) would require broadcasting.
            # Let's assume the source code computes the diagonal elements of the Hessian.
            
            sdf_at_center = get_sdf(points)  # Shape: (N,)
            hessian_coef = 1.0 / (delta * delta)
            
            # Diagonal elements
            h_xx = (points_sdf[0] + points_sdf[1] - 2 * sdf_at_center) * hessian_coef
            h_yy = (points_sdf[2] + points_sdf[3] - 2 * sdf_at_center) * hessian_coef
            h_zz = (points_sdf[4] + points_sdf[5] - 2 * sdf_at_center) * hessian_coef
            
            # Construct Hessian matrix (assuming off-diagonals are zero or not computed)
            # [G] The source code does not specify off-diagonal elements for numerical mode.
            # We will set them to zero as a placeholder, but this is an implementation detail not in the source.
            hessian = torch.zeros(N, 3, 3, dtype=points.dtype)
            hessian[:, 0, 0] = h_xx
            hessian[:, 1, 1] = h_yy
            hessian[:, 2, 2] = h_zz
            
    else:
        # Automatic differentiation mode
        points.requires_grad_(True)
        sdf = get_sdf(points)
        
        # Compute gradient
        gradients = torch.autograd.grad(sdf, points, grad_outputs=torch.ones_like(sdf), create_graph=True, retain_graph=True)[0]
        
        hessian = None
        if heissian:
            # Compute Hessian by differentiating gradients
            # gradients is (N, 3), points is (N, 3)
            # We need to compute d(gradients_i) / d(points_j) for all i, j
            # This results in a tensor of shape (N, 3, 3)
            hessian_list = []
            for i in range(3):
                # Compute gradient of gradients[:, i] with respect to points
                grad_of_grad = torch.autograd.grad(gradients[:, i], points, grad_outputs=torch.ones_like(gradients[:, i]), create_graph=True, retain_graph=True)[0]
                hessian_list.append(grad_of_grad)
            
            hessian = torch.stack(hessian_list, dim=1)  # Shape: (N, 3, 3)
            
    return gradient, hessian
```

## Subtopics

### [2nd-Order Finite Difference Gradient](13052-2nd-order-finite-difference-gradient.md)
Computes surface normals using a second-order central difference gradient. Simpler, only computes gradient.

### [4th-Order Finite Difference Gradient](13053-4th-order-finite-difference-gradient.md)
Uses a higher-order stencil for more accurate gradients. More computationally expensive.

## Operating characteristics
- **Time Complexity:** 
  - Numerical: $O(N)$ SDF evaluations, where $N$ is the number of query points. Each point requires 6 SDF evaluations for the gradient and potentially more for the Hessian (if off-diagonals are computed).
  - Autograd: $O(N)$ SDF evaluations for the gradient, and $O(N)$ additional evaluations for the Hessian (if computed).
- **Memory Complexity:** $O(N)$ for storing SDF values and gradients.
- **Strengths:** 
  - Numerical mode is simple to implement and does not require the SDF function to be differentiable.
  - Autograd mode provides exact gradients (up to machine precision) and can compute the Hessian efficiently.
- **Limitations:** 
  - Numerical mode is sensitive to the choice of `delta`.
  - Autograd mode requires the SDF function to be implemented using a framework that supports automatic differentiation (e.g., PyTorch).
  - Computing the Hessian via autograd can be memory-intensive for large $N$.

## Background
This method is implemented in the [GS-SDF](https://github.com/hku-mars/GS-SDF) repository [S1, unofficial]. It is used in the context of Gaussian Splatting with Signed Distance Functions, where accurate gradient and Hessian information is needed for optimization and rendering.
