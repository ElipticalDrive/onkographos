# Gradient Selection

Also called: Finite Difference Stencils, Gradient Mode Selection, Gradient estimation via finite differences

## Overview
Gradient Selection is a runtime dispatch mechanism that chooses between finite difference stencil implementations to estimate the gradient vector of a scalar volume field for shading purposes [S1, unofficial]. It adapts gradient estimation to a `gradientMode` parameter, allowing a trade-off between the accuracy of central differences and the noise-robustness of Sobel operators [G]. It distinguishes itself from precomputed gradient storage by computing derivatives on-the-fly [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: `textureCoord` (3D coordinate in volume space), `gradientMode` (integer flag) [S1, unofficial].
*   Output: Normalized gradient vector $\mathbf{g} = \nabla V / \|\nabla V\|$ [S2, unofficial].

**Data Structures:**
*   `gradientMode`: An integer flag controlling selection. Typical values are not explicitly defined in the sources [G].

**Steps:**
1.  Check the value of `gradientMode`.
2.  If `gradientMode` selects Sobel, invoke the Sobel gradient estimation routine [S1, unofficial].
3.  Otherwise, invoke the Central Difference gradient estimation routine [S1, unofficial].
4.  Normalize the resulting gradient vector to substitute for surface normals in shading models [S2, unofficial].

**Pseudocode:**
```python
def compute_gradient_selection(field, coord, gradient_mode):
    """Dispatches gradient estimation based on the selected mode."""
    x, y, z = coord
    if gradient_mode == 1:
        grad = gradient_sobel(field, x, y, z)
    else:
        grad = gradient_central(field, x, y, z)
    magnitude = (grad[0]**2 + grad[1]**2 + grad[2]**2)**0.5
    if magnitude > 1e-6:
        return (grad[0]/magnitude, grad[1]/magnitude, grad[2]/magnitude)
    return (0.0, 0.0, 0.0)

def gradient_central(field, x, y, z):
    """Estimates gradient using central differences [S2, unofficial]."""
    h = 1.0
    dx = (field[x+1, y, z] - field[x-1, y, z]) / (2.0 * h)
    dy = (field[x, y+1, z] - field[x, y-1, z]) / (2.0 * h)
    dz = (field[x, y, z+1] - field[x, y, z-1]) / (2.0 * h)
    return (dx, dy, dz)

def gradient_sobel(field, x, y, z):
    """Estimates gradient using a standard 3x3x3 Sobel kernel [G]."""
    sx, sy, sz = 0.0, 0.0, 0.0
    for i in range(-1, 2):
        for j in range(-1, 2):
            for k in range(-1, 2):
                wx = i * (j**2 + 1) * (k**2 + 1)
                wy = j * (i**2 + 1) * (k**2 + 1)
                wz = k * (i**2 + 1) * (j**2 + 1)
                sx += wx * field[x+i, y+j, z+k]
                sy += wy * field[x+i, y+j, z+k]
                sz += wz * field[x+i, y+j, z+k]
    return (sx, sy, sz)
```

**Parameters:**
*   `gradientMode`: Controls the selection. Typical values are not explicitly defined in the sources [G].

**Edge Cases and Pitfalls:**
*   **Noisy Data:** Simple central differences may produce inaccurate normals in noisy data; more complex estimation schemes are recommended in such cases [S2, unofficial].
*   **Boundaries:** Boundary handling (clamping, zero-padding) is required when stencil neighbors fall outside the volume domain [G].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per voxel, as it involves a constant number of texture lookups and arithmetic operations [G].
*   **Memory Complexity:** $O(1)$ auxiliary memory, as gradients are computed on-the-fly [G].
*   **Strengths:** Flexible runtime switching between accuracy and noise robustness. No precomputation storage required [G].
*   **Limitations:** Central differences are sensitive to noise. Boundary effects can distort normals if not handled correctly [G].
*   **When to use:** When shading quality needs to be tuned per-frame or per-volume, and precomputed gradients are too expensive [G].
*   **When not to use:** For very noisy data without Sobel fallback, or when hardware acceleration for specific gradient operations is unavailable [G].

## Background
Gradient estimation via finite differences is a fundamental technique in volume rendering to approximate surface normals for shading [S2, unofficial]. The selection between different stencil types allows renderers to balance visual fidelity and noise sensitivity [G]. The specific implementation described here appears in WebGL-based volume rendering contexts [G].
