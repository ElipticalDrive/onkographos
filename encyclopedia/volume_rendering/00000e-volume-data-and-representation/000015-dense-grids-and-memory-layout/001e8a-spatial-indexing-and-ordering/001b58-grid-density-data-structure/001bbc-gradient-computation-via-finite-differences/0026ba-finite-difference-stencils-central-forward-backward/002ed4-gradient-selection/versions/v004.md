# Gradient Selection

Also called: Central differences, Finite Difference Stencils, Gradient Mode Selection, Gradient estimation via finite differences

## Overview
Gradient Selection is a runtime decision mechanism that chooses between specific finite difference gradient estimation algorithms, primarily Central Difference and Sobel, based on a configuration uniform [S1, unofficial]. It solves the problem of adapting gradient accuracy to data characteristics or performance constraints by selecting the appropriate stencil [S2, unofficial]. It differs from sibling methods like [Neumann Gradient](3342-neumann-gradient.md) or [Forward Difference Gradient](3362-forward-difference-gradient.md) by acting as a dispatcher rather than a standalone estimator, allowing dynamic switching between first-order central differences and higher-order Sobel operators [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A scalar volume texture $V$, a sampling coordinate $\mathbf{t}$ (texture coordinate), and a mode selector `gradientMode`.
- Output: A normalized gradient vector $\mathbf{g}$ at $\mathbf{t}$.

**Data Structures:**
- `gradientMode`: An integer or enum uniform.
  - `GRADIENT_CENTRAL`: Selects central difference.
  - `GRADIENT_SOBEL`: Selects Sobel operator.

**Steps:**
1. Evaluate the mode selector `gradientMode`.
2. If `gradientMode == GRADIENT_SOBEL`:
   - Compute the gradient using the Sobel operator [S1, unofficial].
   - Return the normalized result.
3. Else (default to `GRADIENT_CENTRAL`):
   - Compute the gradient using central differences [S1, unofficial].
   - Return the normalized result.

**Formulas:**
For Central Difference [S2, unofficial]:
The partial derivatives are computed as:
$$ G_x = \frac{V(x+1, y, z) - V(x-1, y, z)}{2h} $$
$$ G_y = \frac{V(x, y+1, z) - V(x, y-1, z)}{2h} $$
$$ G_z = \frac{V(x, y, z+1) - V(x, y, z-1)}{2h} $$
where $h$ is the voxel spacing. The gradient vector is $\mathbf{G} = (G_x, G_y, G_z)$.

For Sobel [S1, unofficial]:
The Sobel operator uses a $3 \times 3$ (or $3 \times 3 \times 3$) kernel to estimate derivatives, providing smoother results than simple central differences in noisy data [S1, unofficial]. The exact kernel weights are not specified in the provided sources, but it is invoked via `gradientSobel(textureCoord)` [S1, unofficial].

**Pseudocode:**
```python
def select_gradient(volume, texture_coord, gradient_mode):
    """
    Selects and computes the gradient based on the mode.
    volume: 3D array of scalar values.
    texture_coord: tuple (x, y, z) in normalized [0,1] or voxel indices.
    gradient_mode: int, GRADIENT_CENTRAL or GRADIENT_SOBEL.
    Returns: normalized gradient vector (gx, gy, gz).
    """
    # Assume texture_coord is converted to voxel indices (ix, iy, iz)
    ix, iy, iz = texture_coord_to_voxel(texture_coord)
    
    if gradient_mode == GRADIENT_SOBEL:
        return gradient_sobel(volume, ix, iy, iz)
    else:
        return gradient_central(volume, ix, iy, iz)

def gradient_central(volume, ix, iy, iz):
    """
    Computes central difference gradient.
    """
    # Boundary handling: clamp indices [G]
    def get_val(x, y, z):
        x = clamp(x, 0, volume.shape[0] - 1)
        y = clamp(y, 0, volume.shape[1] - 1)
        z = clamp(z, 0, volume.shape[2] - 1)
        return volume[x, y, z]

    # Central differences
    gx = (get_val(ix + 1, iy, iz) - get_val(ix - 1, iy, iz)) / 2.0
    gy = (get_val(ix, iy + 1, iz) - get_val(ix, iy - 1, iz)) / 2.0
    gz = (get_val(ix, iy, iz + 1) - get_val(ix, iy, iz - 1)) / 2.0
    
    # Normalize
    mag = sqrt(gx**2 + gy**2 + gz**2)
    if mag > 0:
        return (gx / mag, gy / mag, gz / mag)
    return (0.0, 0.0, 0.0)

def gradient_sobel(volume, ix, iy, iz):
    """
    Computes Sobel gradient.
    Note: Exact kernel implementation details are not provided in sources [S1, unofficial].
    This is a placeholder for the Sobel operator logic.
    """
    # Sobel typically involves weighted sums of neighbors.
    # For example, for x-direction:
    # Gx = (V(x+1,y-1,z) + 2*V(x+1,y,z) + V(x+1,y+1,z)) 
    #    - (V(x-1,y-1,z) + 2*V(x-1,y,z) + V(x-1,y+1,z))
    # Similar for Gy and Gz.
    # Since exact weights are not in [S1, unofficial], we return central as fallback [G].
    return gradient_central(volume, ix, iy, iz)
```

**Parameters:**
- `gradientMode`: Controls selection. Typical values are `GRADIENT_CENTRAL` (default) and `GRADIENT_SOBEL` [S1, unofficial].

**Edge Cases and Pitfalls:**
- Noisy data may produce inaccurate gradients with simple central differences, necessitating the use of Sobel or other complex schemes [S2, unofficial].
- Boundary conditions must be handled via clamping, zero-padding, or extrapolation when neighbors fall outside the volume bounds [G].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel for both Central and Sobel, as they use fixed-size stencils. Sobel is slightly more expensive due to more multiplications/additions.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Strengths:** Simple to implement; Sobel provides better noise robustness [S2, unofficial].
- **Limitations:** Central differences are sensitive to noise [S2, unofficial]. Sobel may blur fine details compared to central differences.
- **When to use:** Use Central for clean, high-resolution data; use Sobel for noisy data [S2, unofficial].

## Background
Gradient selection is a common pattern in volume rendering shaders to allow users to trade off between performance and gradient accuracy [S1, S2, unofficial]. It builds on the principles of finite difference stencils [Parent](3858-finite-difference-stencils-central-forward-backward.md).
