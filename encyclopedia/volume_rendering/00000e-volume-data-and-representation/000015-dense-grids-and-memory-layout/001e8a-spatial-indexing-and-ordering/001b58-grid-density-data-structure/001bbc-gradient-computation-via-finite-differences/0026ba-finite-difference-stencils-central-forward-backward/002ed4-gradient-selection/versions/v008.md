# Gradient Selection
Also called: Central differences, Finite Difference Stencils, Gradient Mode Selection, Gradient estimation via finite differences

## Overview
Gradient Selection is a runtime dispatch mechanism that chooses between specific finite difference schemes—primarily Central Difference and Sobel estimation—to compute the normalized gradient vector of a scalar volume field [S1, unofficial]. This gradient substitutes for surface normals in shading models, enabling shaded volume rendering [S2, unofficial]. It distinguishes itself from sibling methods by explicitly exposing the choice of estimator as a configurable mode, allowing the application to trade off between the isotropic accuracy of central differences and the noise-robustness of Sobel filters [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A scalar volume texture $V$, a sampling coordinate $\mathbf{c}$ (normalized or voxel-space), and a configuration parameter `gradientMode`.
- Output: A normalized 3D gradient vector $\mathbf{n} = \nabla V / \|\nabla V\|$.

**Data Structures:**
- `gradientMode`: An integer or enum identifier. Typical values: `GRADIENT_CENTRAL` (default), `GRADIENT_SOBEL`.

**Steps:**
1. Evaluate the selected estimator function based on `gradientMode`.
2. If `gradientMode` specifies Sobel, compute the gradient using the Sobel kernel [S1, unofficial].
3. Otherwise, compute the gradient using Central Differences [S1, unofficial].
4. Normalize the resulting vector $\mathbf{g} = (g_x, g_y, g_z)$ to obtain the normal $\mathbf{n}$ [S2, unofficial].

**Formulas:**
For Central Differences on an isotropic grid with spacing $h=1$:
$$ g_x = \frac{V(x+1, y, z) - V(x-1, y, z)}{2} $$
$$ g_y = \frac{V(x, y+1, z) - V(x, y-1, z)}{2} $$
$$ g_z = \frac{V(x, y, z+1) - V(x, y, z-1)}{2} $$
$$ \mathbf{n} = \frac{(g_x, g_y, g_z)}{\sqrt{g_x^2 + g_y^2 + g_z^2}} $$

For Sobel estimation, the gradient is computed using $3 \times 3 \times 3$ or $3 \times 3$ cross-sectional kernels that weigh neighbors to reduce noise [S1, S2, unofficial]. The exact kernel weights are not specified in the provided sources, but the method is distinct from simple central differencing [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Noisy Data:** Simple central differences may produce noisy gradients. In such cases, more complex estimation schemes like Sobel are required [S2, unofficial].
- **Boundaries:** When stencil neighbors fall outside the volume domain, boundary handling (clamping, zero-padding) is required [G].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel, as it involves a fixed number of memory accesses and arithmetic operations.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Strengths:** Central differences provide high accuracy for smooth fields. Sobel estimation offers better noise robustness. The selection mechanism allows runtime adaptation.
- **Limitations:** Central differences are sensitive to noise. Sobel kernels are more expensive than central differences due to larger stencils.
- **When to use:** Use Central Differences for clean, high-resolution data. Use Sobel for noisy data or when smoother normals are desired [S1, S2, unofficial].
