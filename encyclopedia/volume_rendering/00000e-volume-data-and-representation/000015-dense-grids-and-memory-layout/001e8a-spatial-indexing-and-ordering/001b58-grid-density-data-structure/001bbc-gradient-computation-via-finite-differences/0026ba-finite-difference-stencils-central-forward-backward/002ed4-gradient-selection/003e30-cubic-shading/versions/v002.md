# Cubic Shading

Also called: 26 neighbour grey-level gradient shading, Cubic window shading, Neighbourhood grey-level gradient shading

## Overview
Cubic shading is a gradient estimation technique for volume rendering that calculates surface normals using all 26 neighbors of a center voxel within a 3x3x3 cubic window, rather than relying solely on the 6 immediate orthogonal neighbors [S1]. It produces images with smoother shading and normals closer to those of analytically defined spheres compared to standard grey-level gradient shading [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A stream of voxel data from a 3D volume grid [S1].
*   **Output:** A screen value (intensity) for each voxel, derived from lighting calculations indexed by the computed gradient [S1].

**Data Structures:**
*   **Cubic Window:** A buffered set of 27 registers representing a 3x3x3 neighborhood [S1]. The registers are laid out in a horizontal line, subdivided into groups of 3 registers representing columns [S1].
*   **Look-Up Table (LUT):** Stores precalculated shading values [S1]. The index size is typically 15 bits, requiring 32KB of memory ($2^{15}$ bytes) [S1].

**Algorithm Steps:**
1.  **Stream Data:** Volume data passes into the start of a column in the cubic window, through the column, and leaves at the other end [S1].
2.  **Calculate Gradient:** Compute the gradient components ($G_x, G_y, G_z$) for the voxel at the center of the 26-connected neighborhood [S1].
3.  **Index LUT:** Use the calculated gradient components to form an index for the LUT [S1]. Typically, the 5 most significant bits of each component are used [S1].
4.  **Generate Value:** Retrieve the shading value from the LUT and output it as the final screen value [S1].

**Gradient Calculation Details:**
The gradient is calculated using a pipeline architecture involving Triple Input Adders (TIAs) and registers [S1]. The calculation involves summing voxels in 3x3 two-dimensional windows situated adjacent to the center surface voxel [S1]. There are six such windows representing the six sides of the 3D cubic window [S1].
Let $S_{xyz}$ denote the summation of a side [S1]. The summation equations for the sides are derived from the voxel values $g_{ijz}$ at coordinates $(i,j,z)$ within the cubic window [S1]. For example, one side summation is defined as:
$$ S_{xyz} = C_{20z} + C_{10z} + C_{00z} + C_{12z} + C_{02z} $$
where $C_{ijz}$ represents the column where $z=i, y=j$ [S1]. Similar equations apply to the other sides [S1].
The components of the modified gradient equation are calculated as follows [S1]:
$$ G_x = S_{21z} - S_{01z} $$
$$ G_y = S_{x2z} - S_{0rz} $$
$$ G_z = S_{r12} - S_{r10} $$
*Note: The source text contains garbled symbols in the gradient formulas (e.g., $8_{21}/z$, $8_{roz}$, $8_{r1/2}$) [S1]. The variables $S$ represent the side totals described above [S1]. The subscripts correspond to the coordinate values in the axis for the cubic window [S1].*

**Pipeline Stages (Y-Gradient Example):**
1.  **Column Total:** Values from the cubic window pass through a TIA, generating a result placed in a column total register [S1].
2.  **Side Total:** Values from the column total registers are inputs to a second TIA, passing output to a side total register [S1].
3.  **Component Calculation:** The difference between values from side total registers is taken and stored in the component register [S1].

**Z-Component Specifics:**
Because the Z-axis direction aligns with data movement through columns, the sum of the side where data enters equals the sum of the side where data leaves after processing two center voxels [S1]. This side total is buffered twice [S1]. The Z gradient component is the difference between the current side total and the buffered side total [S1].

**Normalization:**
The calculated gradient value is normalized and used as the surface normal in lighting calculations stored in the LUT [S1].

**Pseudocode:**
```python
def cubic_shading_gradient(voxel_grid):
    """
    Computes the gradient for the center voxel of a 3x3x3 cubic window.
    voxel_grid: 3D list/array of shape (3, 3, 3) containing voxel intensities.
    Returns: (Gx, Gy, Gz) gradient components as integers.
    """
    # Compute side totals: sum of 3x3 faces perpendicular to each axis
    # X-axis faces (sum over y, z for fixed x)
    S_x0 = sum(voxel_grid[0][y][z] for y in range(3) for z in range(3))
    S_x2 = sum(voxel_grid[2][y][z] for y in range(3) for z in range(3))
    # Y-axis faces (sum over x, z for fixed y)
    S_y0 = sum(voxel_grid[x][0][z] for x in range(3) for z in range(3))
    S_y2 = sum(voxel_grid[x][2][z] for x in range(3) for z in range(3))
    # Z-axis faces (sum over x, y for fixed z)
    S_z0 = sum(voxel_grid[x][y][0] for x in range(3) for y in range(3))
    S_z2 = sum(voxel_grid[x][y][2] for x in range(3) for y in range(3))

    # Gradient components are differences of opposite side totals
    # Matches the hardware pipeline: difference of side total registers [S1]
    Gx = S_x2 - S_x0
    Gy = S_y2 - S_y0
    Gz = S_z2 - S_z0
    return Gx, Gy, Gz

def cubic_shading_pipeline(voxel_stream):
    """
    Simulates the hardware pipeline for cubic shading.
    voxel_stream: iterator yielding voxel values in column-major order.
    Yields: screen intensity values.
    """
    # Buffer 27 voxels to form the 3x3x3 cubic window [S1]
    window = [0] * 27
    idx = 0
    for val in voxel_stream:
        window[idx % 27] = val
        idx += 1
        if idx >= 27:
            # Extract 3x3x3 grid from flat buffer
            grid = [[[window[i*9 + j*3 + k] for k in range(3)] for j in range(3)] for i in range(3)]
            Gx, Gy, Gz = cubic_shading_gradient(grid)
            # Form 15-bit LUT index from 5 MSBs of each component [S1]
            lut_index = ((Gx >> 3) & 0x1F) << 10 | ((Gy >> 3) & 0x1F) << 5 | ((Gz >> 3) & 0x1F)
            # Retrieve shading value from LUT [S1]
            # LUT is an external 32KB table mapping 15-bit indices to shading values [G]
            screen_value = LUT[lut_index]
            yield screen_value
```

## Operating characteristics
*   **Complexity:** The method requires accessing 27 voxels per center voxel and performing multiple additions and subtractions [S1]. The hardware implementation uses a pipeline with Triple Input Adders (TIAs) [S1].
*   **Memory:** Requires a 32KB LUT for a 15-bit index (5 bits per gradient component) [S1].
*   **Strengths:** Produces images closer to the expected look of rendered spheres; reduces mean, variance, and mean square of pixel differences compared to standard gradient shading [S1].
*   **Limitations:** Using an LUT reduces shading accuracy; the improvement from cubic shading is less significant with an LUT compared to without [S1].

## Background
Cubic shading was introduced as an extension of grey-level gradient shading to improve the visual quality of volume rendered spheres [S1]. It was described in a paper detailing a hardware architecture for video-rate smooth shading of volume data [S1]. The technique uses a 3x3x3 neighborhood of voxels, similar to biquadratic surface interpolation described in other works [S1].
