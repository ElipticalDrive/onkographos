# Forward Difference Gradient

Also called: Gradient Estimation for Lighting, Intermediate Difference Gradient, Simple Forward Differencing Gradient

## Overview
The Forward Difference Gradient is a first-order finite difference method that estimates the spatial gradient of a scalar volume field using the current voxel and its three immediate neighbors in the positive axis directions [S1, S2, unofficial]. It is primarily used to compute surface normals for lighting models in direct volume rendering, where the gradient direction determines the angle of reflection relative to light sources [S2, unofficial]. Unlike the Central Difference Gradient, which is second-order accurate and unbiased, the Forward Difference Gradient is biased toward the positive axis direction but requires fewer memory accesses and is computationally simpler [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A 3D scalar volume $V$ of dimensions $W \times H \times D$, where $V_{x,y,z}$ is the scalar value at integer coordinates $(x, y, z)$.
- **Output:** A 3D vector field $N$ representing the unnormalized gradient, and optionally the normalized gradient $n$ and gradient magnitude $||N||$.

**Data Structures:**
- $V$: Array of scalar values (e.g., `float` or `uint16`).
- $N$: Array of 3-component vectors (e.g., `vec3` or three separate arrays).
- $n$: Array of 3-component unit vectors.

**Parameters:**
- Voxel spacing $h$: For isotropic grids, a single scalar $h$. For anisotropic grids, spacings $h_x, h_y, h_z$ [G].

**Steps:**
1. Iterate over all valid voxel coordinates $(x, y, z)$ within the volume bounds.
2. For each voxel, retrieve the value $V_{x,y,z}$ and its neighbors $V_{x+1,y,z}$, $V_{x,y+1,z}$, and $V_{x,y,z+1}$.
3. Compute the unnormalized gradient components using forward differences:
   $$ \nabla_x = V_{x+1,y,z} - V_{x,y,z} $$
   $$ \nabla_y = V_{x,y+1,z} - V_{x,y,z} $$
   $$ \nabla_z = V_{x,y,z+1} - V_{x,y,z} $$
   [S1, unofficial]
4. If physical units are required, scale each component by the inverse of the corresponding voxel spacing ($1/h_x, 1/h_y, 1/h_z$) [G].
5. Compute the gradient magnitude:
   $$ ||N(x,y,z)|| = \sqrt{\nabla_x^2 + \nabla_y^2 + \nabla_z^2} $$
   [S2, unofficial]
6. Compute the normalized gradient vector:
   $$ n(x,y,z) = \frac{N(x,y,z)}{||N(x,y,z)||} $$
   [S2, unofficial]
   This normalized vector is used in the lighting model for reflected light [S2, unofficial].

**Pseudocode:**
```python
def compute_forward_difference_gradient(volume, spacing):
    """
    Computes the forward difference gradient for a 3D volume.
    
    Args:
        volume: 3D array of shape (W, H, D) containing scalar values.
        spacing: Tuple (hx, hy, hz) of voxel spacings.
        
    Returns:
        normals: 3D array of shape (W, H, D, 3) containing normalized gradient vectors.
        magnitudes: 3D array of shape (W, H, D) containing gradient magnitudes.
    """
    W, H, D = volume.shape
    hx, hy, hz = spacing
    
    normals = np.zeros((W, H, D, 3))
    magnitudes = np.zeros((W, H, D))
    
    # Precompute inverse spacings for anisotropic scaling [G]
    inv_hx = 1.0 / hx
    inv_hy = 1.0 / hy
    inv_hz = 1.0 / hz
    
    for z in range(D):
        for y in range(H):
            for x in range(W):
                # Boundary handling: Clamp to nearest boundary if neighbor is out of bounds
                # Note: Forward difference requires x+1, y+1, z+1. 
                # If at the last index, we clamp to the last valid neighbor.
                
                # Get current value
                v_curr = volume[x, y, z]
                
                # Get neighbors with clamping [G]
                v_x_next = volume[min(x + 1, W - 1), y, z]
                v_y_next = volume[x, min(y + 1, H - 1), z]
                v_z_next = volume[x, y, min(z + 1, D - 1)]
                
                # Compute differences
                dx = v_x_next - v_curr
                dy = v_y_next - v_curr
                dz = v_z_next - v_curr
                
                # Scale by inverse spacing for physical gradient [G]
                grad_x = dx * inv_hx
                grad_y = dy * inv_hy
                grad_z = dz * inv_hz
                
                # Compute magnitude
                mag = np.sqrt(grad_x**2 + grad_y**2 + grad_z**2)
                magnitudes[x, y, z] = mag
                
                # Normalize
                if mag > 1e-8: # Avoid division by zero
                    normals[x, y, z, 0] = grad_x / mag
                    normals[x, y, z, 1] = grad_y / mag
                    normals[x, y, z, 2] = grad_z / mag
                else:
                    normals[x, y, z, :] = [0.0, 0.0, 0.0]
                    
    return normals, magnitudes
```

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** The stencil requires neighbors at $x+1, y+1, z+1$. Voxels on the maximum extent of any axis lack these neighbors. Clamping (using the value of the nearest boundary voxel) is a common strategy [G]. Zero-padding or reflection are alternatives but may introduce artifacts at the volume edge [G].
- **Precision:** For very small gradients, normalization may suffer from floating-point precision issues. A small epsilon threshold should be used before division [G].
- **Bias:** The gradient is biased toward the positive axis direction. This can cause lighting artifacts if the volume orientation is not consistent or if high-frequency details are present [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(W \times H \times D)$, as each voxel is processed once with a constant number of operations.
- **Memory Complexity:** $O(W \times H \times D)$ for storing the gradient field.
- **Performance:** Faster than Central Difference Gradient due to fewer memory accesses (4 reads vs. 7 reads) and simpler arithmetic. However, it is less accurate [S1, unofficial].
- **Strengths:** Simple implementation, low computational cost, minimal memory overhead.
- **Limitations:** First-order accuracy ($O(h)$), biased results, boundary artifacts if not handled carefully.
- **When to use:** Real-time rendering where performance is critical and high accuracy is not required. Suitable for smooth volumes or when combined with other techniques to mitigate bias.
- **When not to use:** When high-fidelity surface reconstruction or accurate lighting is required; use Central Difference or higher-order methods instead.

## Background
The Forward Difference Gradient is one of the earliest and simplest gradient estimation methods used in volume rendering. It was described in foundational works such as Drebin et al.'s "Volume Rendering" (Siggraph 88) and Sabella's "A Rendering Algorithm for Visualizing 3D Scalar Fields" (Siggraph 88) [S2, unofficial]. It is often referred to as the "Intermediate Difference Gradient" in some literature due to its position between simple nearest-neighbor and more complex central difference schemes [S1, unofficial]. The method is widely used in educational contexts and real-time applications due to its simplicity [S1, S2, unofficial].
