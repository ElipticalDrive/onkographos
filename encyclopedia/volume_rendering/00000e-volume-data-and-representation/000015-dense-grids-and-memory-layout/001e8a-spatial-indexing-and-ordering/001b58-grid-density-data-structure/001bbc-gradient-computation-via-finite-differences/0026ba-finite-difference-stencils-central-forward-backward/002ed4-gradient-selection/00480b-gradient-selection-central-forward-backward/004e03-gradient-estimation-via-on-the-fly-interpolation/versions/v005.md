# Gradient Estimation via On-the-Fly Interpolation

Also called: Gradient Estimation via Central Differencing, Interpolated Gradient Estimation, On-the-Fly Gradient Computation

## Overview
This method estimates the gradient vector at an arbitrary sample point $(x,y,z)$ during ray integration by computing central differences of the underlying scalar volume data on demand, rather than precomputing and storing gradients at grid nodes [S2, unofficial][S3, book]. It trades increased computational load for reduced memory footprint, avoiding the storage overhead of a separate gradient field [S2, unofficial]. Unlike precomputed gradient approaches, it exploits the spatial and temporal locality of the scalar values required for the stencil, which can yield performance gains on both CPU and GPU architectures [S2, unofficial].

## How it works
**Inputs and Outputs**
- Input: A scalar volume dataset $V$ defined on a regular 3D grid, and a sample position $\mathbf{p} = (x, y, z)$ within the volume bounds [S2, unofficial][S3, book].
- Output: The gradient vector $\mathbf{g} = [g_x, g_y, g_z]^T$ at $\mathbf{p}$ [S3, book].

**Data Structures**
- $V$: A 3D array of scalar values. The implementation assumes standard grid indexing where $V(i, j, k)$ accesses the value at grid coordinates $(i, j, k)$ [G].

**Steps**
1.  **Interpolate Support Samples**: Since the sample point $\mathbf{p}$ is generally not aligned with grid nodes, the six scalar values required for the central difference stencil must be interpolated from the volume data [S3, book]. Let $V_{\text{interp}}(x, y, z)$ denote the interpolated value at arbitrary coordinates [G]. Any standard interpolation filter may be used [S1, unofficial][S3, book].
2.  **Compute Central Differences**: Calculate the gradient components using the central difference formula [S3, book]:
    $$
    \begin{bmatrix} g_x \\ g_y \\ g_z \end{bmatrix} = \begin{bmatrix} V_{\text{interp}}(x-1, y, z) \\ V_{\text{interp}}(x, y-1, z) \\ V_{\text{interp}}(x, y, z-1) \end{bmatrix} - \begin{bmatrix} V_{\text{interp}}(x+1, y, z) \\ V_{\text{interp}}(x, y+1, z) \\ V_{\text{interp}}(x, y, z+1) \end{bmatrix}
    $$
3.  **Return Gradient**: Return $\mathbf{g}$ for use in illumination calculations (e.g., normal vector normalization) [S3, book].

**Pseudocode**
```python
def compute_gradient_on_the_fly(V, x, y, z):
    """
    Computes the gradient at (x, y, z) using on-the-fly central differencing.
    
    Args:
        V: 3D numpy array of volume data.
        x, y, z: Float coordinates of the sample point.
        
    Returns:
        g: Tuple (gx, gy, gz) representing the gradient vector.
    """
    def trilinear(V, px, py, pz):
        # Trilinear interpolation at arbitrary coordinates [G]
        ix, iy, iz = int(px), int(py), int(pz)
        fx, fy, fz = px - ix, py - iy, pz - iz
        # Clamp indices to grid bounds [G]
        ix = max(0, min(ix, V.shape[0] - 1))
        iy = max(0, min(iy, V.shape[1] - 1))
        iz = max(0, min(iz, V.shape[2] - 1))
        # Fetch corner values with boundary clamping [G]
        c000 = V[ix, iy, iz]
        c100 = V[min(ix+1, V.shape[0]-1), iy, iz]
        c010 = V[ix, min(iy+1, V.shape[1]-1), iz]
        c001 = V[ix, iy, min(iz+1, V.shape[2]-1)]
        c110 = V[min(ix+1, V.shape[0]-1), min(iy+1, V.shape[1]-1), iz]
        c101 = V[min(ix+1, V.shape[0]-1), iy, min(iz+1, V.shape[2]-1)]
        c011 = V[ix, min(iy+1, V.shape[1]-1), min(iz+1, V.shape[2]-1)]
        c111 = V[min(ix+1, V.shape[0]-1), min(iy+1, V.shape[1]-1), min(iz+1, V.shape[2]-1)]
        return (c000*(1-fx)*(1-fy)*(1-fz) + c100*fx*(1-fy)*(1-fz) +
                c010*(1-fx)*fy*(1-fz) + c110*fx*fy*(1-fz) +
                c001*(1-fx)*(1-fy)*fz + c101*fx*(1-fy)*fz +
                c011*(1-fx)*fy*fz + c111*fx*fy*fz)

    # Interpolate the six support points for the central difference stencil
    v_left_x = trilinear(V, x - 1, y, z)
    v_left_y = trilinear(V, x, y - 1, z)
    v_left_z = trilinear(V, x, y, z - 1)
    v_right_x = trilinear(V, x + 1, y, z)
    v_right_y = trilinear(V, x, y + 1, z)
    v_right_z = trilinear(V, x, y, z + 1)

    # Compute central differences
    gx = v_left_x - v_right_x
    gy = v_left_y - v_right_y
    gz = v_left_z - v_right_z
    
    return (gx, gy, gz)
```

**Parameters**
- Interpolation Filter: The quality of the interpolation filter significantly impacts gradient accuracy [S3, book].

**Edge Cases and Pitfalls**
- **Boundary Conditions**: When sample points are near volume boundaries, the stencil requires values outside the grid [G].
- **Interpolation Sensitivity**: Gradients are more sensitive to interpolation filter quality than the scalar values themselves because they are used in illumination calculations involving normalization of normal vectors [S1, unofficial][S3, book].
- **Precision**: The subtraction of nearby interpolated values can amplify noise if the volume data is noisy [G].

## Subtopics

### Precomputed Gradients
Computes gradients at all grid nodes beforehand and stores them [S3, book]. Uses more memory but reduces per-sample compute cost [S2, unofficial]. Choose when memory/cache capacity is sufficient and compute throughput is the primary bottleneck [G]. [Gradient Selection — Central/Forward/Backward](12132-gradient-selection-central-forward-backward.md)

### Gradient Filtering
Applies optimized gradient filters directly to the volume data [S3, book]. Often provides the best visual results but has higher complexity [S1, unofficial][S3, book]. Choose when interpolation quality and shading accuracy are prioritized over memory footprint [G]. ## Operating characteristics
- **Time Complexity**: $O(1)$ per sample, but with a higher constant factor due to six interpolation calls and six arithmetic operations per sample [G].
- **Memory Complexity**: $O(1)$ additional memory per sample [G]. No storage for a gradient field is required, reducing the total memory footprint by a factor of three compared to precomputed gradients [S2, unofficial].
- **Performance**: On-the-fly computation was found to be faster than precomputed gradients by an average of 8.2% on Intel/Nehalem, 19.4% on AMD/MagnyCours, and 80.7% on NVIDIA/Fermi [S2, unofficial]. This is attributed to the spatial and temporal locality of the scalar values needed for the stencil, which are either nearby in memory (especially with Z-ordering) or loaded recently, whereas precomputed gradients cause additional cache pressure from a separate memory buffer [S2, unofficial].
- **Strengths**: Lower memory usage; avoids cache misses associated with separate gradient buffers; simple to implement [S2, unofficial].
- **Limitations**: Higher computational cost per sample; sensitive to interpolation quality [S3, book].

## Background
The method was analyzed in the context of shared-memory parallel raycasting volume rendering [S2, unofficial]. It is one of three popular methods to estimate gradients from volume data, alongside precomputed central differencing and gradient filtering [S3, book]. The approach leverages the observation that the six-point stencil operation has significant locality, making it efficient despite the repeated computation [S2, unofficial].
