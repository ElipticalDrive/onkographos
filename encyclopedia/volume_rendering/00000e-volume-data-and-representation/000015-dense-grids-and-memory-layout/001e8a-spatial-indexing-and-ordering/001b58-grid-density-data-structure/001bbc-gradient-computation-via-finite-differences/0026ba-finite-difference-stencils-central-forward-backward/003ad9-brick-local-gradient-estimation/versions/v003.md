# Brick-local Gradient Estimation
Also called: Central Differences within a Brick, Clamped Central Differences for Bricks

## Overview
Brick-local gradient estimation computes volume gradients using central differences restricted to the spatial bounds of a single data brick, eliminating the need for cross-brick memory indirection during ray casting [S1, unofficial]. It differs from standard central difference stencils by clamping sample coordinates to the brick's valid sample range and dynamically adjusting the denominator based on the actual span of the sampled voxels, ensuring correct slope magnitudes near brick boundaries [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A scalar volume value $V$ at a specific voxel position $\mathbf{p}$ within a brick, the brick's local coordinate system, the brick's LOD scale factor $h$ (voxel spacing), and the brick's metadata defining the valid sample range $[\mathbf{min}, \mathbf{max}]$.
- Output: A 3D gradient vector $\mathbf{G} = (G_x, G_y, G_z)$.

**Data Structures:**
The method operates on a single brick's data slot. The brick metadata includes:
- `sampleMin`: The minimum valid voxel index (or coordinate) for sampling within the brick.
- `sampleMax`: The maximum valid voxel index (or coordinate) for sampling within the brick.
- `lodScale`: The scaling factor $h$ for the current Level of Detail (LOD).

**Steps:**
1. For each axis $i \in \{x, y, z\}$, compute the gradient component $G_i$ using a helper function `brickSlope`.
2. In `brickSlope`, determine the high and low sample positions:
   $$ \mathbf{p}_{hi} = \text{clamp}(\mathbf{p} + \mathbf{e}_i \cdot h, \mathbf{min}, \mathbf{max}) $$
   $$ \mathbf{p}_{lo} = \text{clamp}(\mathbf{p} - \mathbf{e}_i \cdot h, \mathbf{min}, \mathbf{max}) $$
   where $\mathbf{e}_i$ is the unit vector for axis $i$, and $\text{clamp}(\mathbf{v}, \mathbf{min}, \mathbf{max})$ clamps each component of $\mathbf{v}$ to the range $[\mathbf{min}, \mathbf{max}]$.
3. Calculate the effective span in finest-level voxels:
   $$ \text{span} = \max\left( \frac{(\mathbf{p}_{hi} - \mathbf{p}_{lo}) \cdot \mathbf{e}_i}{h}, 0.001 \right) $$
   This step ensures the denominator is non-zero and corrects the slope magnitude when the clamped positions span less than two level voxels (e.g., at brick faces where one neighbor is clamped to the boundary).
4. Sample the volume at the clamped positions using affine interpolation (if sub-voxel precision is required) or direct lookup:
   $$ V_{hi} = \text{sample}(\mathbf{p}_{hi}) $$
   $$ V_{lo} = \text{sample}(\mathbf{p}_{lo}) $$
5. Compute the gradient component:
   $$ G_i = \frac{V_{hi} - V_{lo}}{\text{span}} $$

**Pseudocode:**
```python
def compute_brick_local_gradient(volume_brick, voxel_pos, brick_min, brick_max, h):
    """
    Computes the gradient at voxel_pos using brick-local central differences.
    
    Args:
        volume_brick: 3D array of scalar values for the current brick.
        voxel_pos: Tuple (x, y, z) of the current voxel's integer coordinates within the brick.
        brick_min: Tuple (min_x, min_y, min_z) of the minimum valid sample coordinates.
        brick_max: Tuple (max_x, max_y, max_z) of the maximum valid sample coordinates.
        h: Float, the voxel spacing (lodScale).
        
    Returns:
        Tuple (gx, gy, gz) of gradient components.
    """
    def clamp(val, min_val, max_val):
        return max(min_val, min(val, max_val))

    def sample_at(pos):
        # Clamp position to brick bounds for array indexing
        ix = clamp(pos[0], brick_min[0], brick_max[0])
        iy = clamp(pos[1], brick_min[1], brick_max[1])
        iz = clamp(pos[2], brick_min[2], brick_max[2])
        # Return scalar value. Assuming integer indices for simplicity.
        # If sub-voxel, use affine interpolation here.
        return volume_brick[ix, iy, iz]

    def brick_slope(axis_idx):
        # Unit vector for the axis
        offset = [0.0, 0.0, 0.0]
        offset[axis_idx] = h
        
        # Calculate high and low positions
        hi = [
            clamp(voxel_pos[0] + offset[0], brick_min[0], brick_max[0]),
            clamp(voxel_pos[1] + offset[1], brick_min[1], brick_max[1]),
            clamp(voxel_pos[2] + offset[2], brick_min[2], brick_max[2])
        ]
        lo = [
            clamp(voxel_pos[0] - offset[0], brick_min[0], brick_max[0]),
            clamp(voxel_pos[1] - offset[1], brick_min[1], brick_max[1]),
            clamp(voxel_pos[2] - offset[2], brick_min[2], brick_max[2])
        ]
        
        # Calculate span
        # Dot product of (hi - lo) with the axis unit vector
        diff = [hi[0] - lo[0], hi[1] - lo[1], hi[2] - lo[2]]
        span = diff[axis_idx] / h
        if span < 0.001:
            span = 0.001
            
        # Sample and compute slope
        val_hi = sample_at(hi)
        val_lo = sample_at(lo)
        return (val_hi - val_lo) / span

    gx = brick_slope(0)
    gy = brick_slope(1)
    gz = brick_slope(2)
    
    return (gx, gy, gz)
```

**Parameters:**
- $h$ (voxel spacing): Typically derived from the brick's LOD level.
- `brick_min`, `brick_max`: Defined by the brick's geometry and LOD.

**Edge Cases:**
- **Brick Boundaries:** If a neighbor falls outside the brick, it is clamped to the boundary voxel. This reduces the effective step size, so the denominator `span` is adjusted to reflect the actual distance between samples, preventing artificially large gradients [S1, unofficial].
- **Zero Span:** If `voxel_pos` is at the boundary and both neighbors are clamped to the same value (e.g., at a corner of the brick), the span would be zero. The minimum span of 0.001 prevents division by zero [S1, unofficial].

## Subtopics

### [Gradient Cache](10335-gradient-cache.md)
Stores computed gradients per brick to avoid redundant calculations. It offers higher speedups than cell-local caching by reusing gradients across multiple cells within a brick, while requiring only modest, volume-size-independent memory.

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel gradient computation, as it involves a fixed number of clamping, sampling, and arithmetic operations.
- **Memory Complexity:** $O(1)$ auxiliary memory per gradient computation, as it does not require storing a global gradient field.
- **Performance:** Faster than global gradient computation because it avoids cross-brick lookups and indirection in the hot loop [S1, unofficial].
- **Strengths:** Efficient for out-of-core rendering where loading global gradient data is prohibitive; handles brick boundaries gracefully without artifacts from unclamped indices.
- **Limitations:** Gradients may be discontinuous across brick boundaries if the clamping behavior differs between adjacent bricks or if the volume is not perfectly aligned with brick grids. Accuracy may degrade near brick faces due to the adaptive span calculation.

## Background
Brick-local gradient estimation is used in out-of-core volume rendering systems, such as Kiln, to enable efficient rendering of multi-GB datasets on the web using WebGPU [S1, unofficial]. It was developed to address the performance bottleneck of computing gradients on-the-fly without incurring the memory overhead of storing precomputed gradients for the entire volume.
