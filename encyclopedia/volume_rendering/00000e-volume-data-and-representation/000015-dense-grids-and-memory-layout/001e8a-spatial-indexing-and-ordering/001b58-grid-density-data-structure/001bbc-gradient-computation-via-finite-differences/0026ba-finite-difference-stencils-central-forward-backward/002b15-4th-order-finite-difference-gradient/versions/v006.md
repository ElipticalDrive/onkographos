# 4th-Order Finite Difference Gradient

Also called: 4th-Order Accurate Finite Difference Scheme, Grid Normal Computation via 4th-Order Finite Differences

## Overview
Computes the gradient (normal vector) of a Signed Distance Function (SDF) grid at every voxel center using a 4th-order accurate finite difference scheme [S1, unofficial]. This method provides smooth normals for ray marching and shading, distinguishing itself from the 2nd-order central difference method by using larger stencils and boundary extrapolation to achieve $O(h^4)$ accuracy [S1, unofficial]. It builds on [Finite Difference Stencils (Central/Forward/Backward)](3858-finite-difference-stencils-central-forward-backward.md).

## How it works
**Inputs:**
- `grid`: A 3D tensor of shape $(N_x, N_y, N_z)$ containing scalar values (e.g., SDF values) at voxel centers.
- `voxel_size`: A scalar representing the physical spacing $h$ between voxels (assumed isotropic).
- `grid_res_x`, `grid_res_y`, `grid_res_z`: Integers $N_x, N_y, N_z$ representing the grid dimensions.

**Outputs:**
- A list of three 3D tensors `[grid_normal_x, grid_normal_y, grid_normal_z]`, each of shape $(N_x, N_y, N_z)$, representing the partial derivatives $\frac{\partial V}{\partial x}$, $\frac{\partial V}{\partial y}$, and $\frac{\partial V}{\partial z}$.

**Data Structures:**
- The grid is stored as a dense 3D array. No auxiliary structures are required.

**Steps:**
1.  Define the largest indices for each dimension: $n_x = N_x - 1$, $n_y = N_y - 1$, $n_z = N_z - 1$.
2.  Compute the x-axis gradient components:
    -   Calculate the forward-shifted term $X_1$ by concatenating the interior slice `grid[1:,:,:]` with an extrapolated boundary value at the upper end. The extrapolated value is $3 \cdot V_{n_x} - 3 \cdot V_{n_x-1} + V_{n_x-2}$.
    -   Calculate the backward-shifted term $X_2$ by concatenating an extrapolated boundary value at the lower end with the interior slice `grid[:n_x,:,:]`. The extrapolated value is $-3 \cdot V_1 + 3 \cdot V_0 + V_2$.
    -   Compute `grid_normal_x` as $(X_1 - X_2) / (2 \cdot \text{voxel\_size})$.
3.  Repeat step 2 for the y-axis (using dimensions 1 and indices $n_y$) and z-axis (using dimensions 2 and indices $n_z$).

**Formulas:**
The central difference approximation for the x-component is:
$$ G_x = \frac{X_1 - X_2}{2h} $$
where $X_1$ and $X_2$ are shifted versions of the grid. For interior points, this reduces to the standard 2nd-order central difference. At boundaries, the extrapolation ensures 4th-order accuracy. The boundary extrapolation formula for the last element in a dimension with index $n$ is [S1, unofficial]:
$$ V_{n+1} = 3V_n - 3V_{n-1} + V_{n-2} $$
Similarly, for the first element (index 0), the extrapolated value for index $-1$ is:
$$ V_{-1} = -3V_1 + 3V_0 + V_2 $$

**Parameters:**
- `voxel_size`: The physical size of a single voxel. Typical values depend on the scene scale.

**Pseudocode:**
```python
def compute_4th_order_gradient(grid, voxel_size, nx, ny, nz):
    """
    Computes the 4th-order gradient of a 3D grid.
    
    Args:
        grid: 3D numpy array of shape (nx, ny, nz).
        voxel_size: Scalar float, the spacing h.
        nx, ny, nz: Integers, grid dimensions.
        
    Returns:
        List of 3 numpy arrays [gx, gy, gz] of shape (nx, ny, nz).
    """
    # Initialize output arrays
    gx = np.zeros_like(grid)
    gy = np.zeros_like(grid)
    gz = np.zeros_like(grid)
    
    # Precompute boundary extrapolations for x-axis
    # Upper boundary extrapolation: V_{nx} = 3*V_{nx-1} - 3*V_{nx-2} + V_{nx-3} ? 
    # Note: The source uses indices relative to the end. 
    # Source: 3 * grid[n_x,:,:] - 3 * grid[n_x-1,:,:] + grid[n_x-2,:,:]
    # This corresponds to estimating V_{nx+1} based on V_{nx}, V_{nx-1}, V_{nx-2}
    # Wait, the source code says:
    # X_1 = cat(grid[1:,:,:], (3 * grid[n_x,:,:] - 3 * grid[n_x-1,:,:] + grid[n_x-2,:,:]))
    # This implies the last element of X_1 is an extrapolated value for the position nx+1?
    # No, X_1 has shape (nx, ny, nz). 
    # grid[1:,:,:] has shape (nx-1, ny, nz).
    # The concatenated term has shape (1, ny, nz).
    # So X_1[i] for i < nx-1 is grid[i+1].
    # X_1[nx-1] is the extrapolated value.
    # Similarly X_2[0] is the extrapolated value.
    
    # X_1: Forward shift. X_1[i] approx V(i+1)
    # Interior: X_1[i] = grid[i+1] for i in 0..nx-2
    # Boundary (i = nx-1): X_1[nx-1] = 3*grid[nx-1] - 3*grid[nx-2] + grid[nx-3]
    # Wait, source uses n_x = nx - 1.
    # grid[n_x] is the last element.
    # So X_1[nx-1] = 3*grid[nx-1] - 3*grid[nx-2] + grid[nx-3]
    
    # X_2: Backward shift. X_2[i] approx V(i-1)
    # Interior: X_2[i] = grid[i-1] for i in 1..nx-1
    # Boundary (i = 0): X_2[0] = -3*grid[1] + 3*grid[0] + grid[2]
    
    # Let's implement exactly as source
    
    # X_1 construction
    interior_x1 = grid[1:, :, :] # Shape (nx-1, ny, nz)
    # Extrapolated value at the end (index nx-1 in X_1)
    # Source: 3 * grid[n_x,:,:] - 3 * grid[n_x-1,:,:] + grid[n_x-2,:,:]
    # n_x = nx - 1
    ext_x1_end = 3 * grid[nx-1, :, :] - 3 * grid[nx-2, :, :] + grid[nx-3, :, :]
    ext_x1_end = ext_x1_end[np.newaxis, :, :] # Shape (1, ny, nz)
    X1 = np.concatenate((interior_x1, ext_x1_end), axis=0)
    
    # X_2 construction
    # Extrapolated value at the start (index 0 in X_2)
    # Source: -3 * grid[1,:,:] + 3 * grid[0,:,:] + grid[2,:,:]
    ext_x2_start = -3 * grid[1, :, :] + 3 * grid[0, :, :] + grid[2, :, :]
    ext_x2_start = ext_x2_start[np.newaxis, :, :] # Shape (1, ny, nz)
    interior_x2 = grid[:nx-1, :, :] # Shape (nx-1, ny, nz)
    X2 = np.concatenate((ext_x2_start, interior_x2), axis=0)
    
    gx = (X1 - X2) / (2 * voxel_size)
    
    # Y-axis
    interior_y1 = grid[:, 1:, :]
    ext_y1_end = 3 * grid[:, ny-1, :] - 3 * grid[:, ny-2, :] + grid[:, ny-3, :]
    ext_y1_end = ext_y1_end[:, np.newaxis, :]
    Y1 = np.concatenate((interior_y1, ext_y1_end), axis=1)
    
    ext_y2_start = -3 * grid[:, 1, :] + 3 * grid[:, 0, :] + grid[:, 2, :]
    ext_y2_start = ext_y2_start[:, np.newaxis, :]
    interior_y2 = grid[:, :ny-1, :]
    Y2 = np.concatenate((ext_y2_start, interior_y2), axis=1)
    
    gy = (Y1 - Y2) / (2 * voxel_size)
    
    # Z-axis
    interior_z1 = grid[:, :, 1:]
    ext_z1_end = 3 * grid[:, :, nz-1] - 3 * grid[:, :, nz-2] + grid[:, :, nz-3]
    ext_z1_end = ext_z1_end[:, :, np.newaxis]
    Z1 = np.concatenate((interior_z1, ext_z1_end), axis=2)
    
    ext_z2_start = -3 * grid[:, :, 1] + 3 * grid[:, :, 0] + grid[:, :, 2]
    ext_z2_start = ext_z2_start[:, :, np.newaxis]
    interior_z2 = grid[:, :, :nz-1]
    Z2 = np.concatenate((ext_z2_start, interior_z2), axis=2)
    
    gz = (Z1 - Z2) / (2 * voxel_size)
    
    return [gx, gy, gz]
```

**Edge Cases and Pitfalls:**
-   **Grid Size:** The stencil requires at least 3 voxels in each dimension to compute the boundary extrapolation terms ($V_{n-2}$, $V_2$, etc.). If $N < 3$, the method fails [G].
-   **Precision:** Using floating-point arithmetic, ensure that the extrapolation does not introduce significant noise if the grid values are noisy.
-   **Anisotropic Grids:** The current implementation assumes isotropic `voxel_size`. For anisotropic grids, the divisor should be adjusted per axis ($2h_x, 2h_y, 2h_z$) [G].

## Subtopics

### Sobel Operator
Uses 3x3x3 kernels for gradient estimation, often with smoothing. Less accurate than 4th-order FD but faster and more robust to noise. [Sobel Operator](1416-sobel-operator.md)

### Jacobian Estimation via Central Differences
Computes the full Jacobian matrix, not just the gradient. Uses 2nd-order central differences. [Jacobian Estimation via Central Differences](2650-jacobian-estimation-via-central-differences.md)

### Forward Difference Gradient
Uses forward differences, biased and 1st-order accurate. Simpler but less smooth. [Forward Difference Gradient](3362-forward-difference-gradient.md)

### Gauss-Seidel with Successive Over-Relaxation (SOR)
An iterative solver for Poisson equations, not a direct gradient estimator. [Gauss-Seidel with Successive Over-Relaxation (SOR)](6904-gauss-seidel-with-successive-over-relaxation-sor.md)

## Operating characteristics
-   **Time Complexity**: $O(N_x N_y N_z)$, as each voxel is processed once with a constant number of operations.
-   **Memory Complexity**: $O(N_x N_y N_z)$ for the input grid and output gradients. No significant auxiliary memory.
-   **Performance**: Faster than iterative methods but slower than 1st-order differences due to larger stencil and boundary handling.
-   **Strengths**: High accuracy ($O(h^4)$) for smooth fields like SDFs. Smooth normals reduce artifacts in ray marching.
-   **Limitations**: Requires boundary extrapolation, which can be sensitive to noise at boundaries. Not suitable for non-smooth or noisy data without pre-filtering.
-   **When to Use**: When high-quality normals are required for SDF-based rendering or physics, and the grid is smooth.
-   **When Not to Use**: For noisy data, or when computational resources are extremely limited.

## Background
The method is implemented in the SDFDiff repository, associated with CVPR 2020 work on differentiable rendering of SDFs [S1, unofficial]. It leverages finite difference schemes to compute gradients for backpropagation in neural rendering pipelines.
