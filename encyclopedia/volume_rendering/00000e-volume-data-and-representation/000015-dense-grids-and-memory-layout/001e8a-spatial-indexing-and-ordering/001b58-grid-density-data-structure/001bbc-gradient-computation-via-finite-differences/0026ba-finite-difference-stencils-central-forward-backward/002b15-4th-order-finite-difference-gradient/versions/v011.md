# 4th-Order Finite Difference Gradient
Also called: 4th-Order Accurate Finite Difference Scheme, Grid Normal Computation via 4th-Order Finite Differences

## Overview
The 4th-Order Finite Difference Gradient computes the gradient (normal vector) of a scalar field, typically a Signed Distance Function (SDF) grid, at every voxel center using a 4th-order accurate finite difference scheme [S1, unofficial]. This method provides smooth normals essential for ray marching and shading in volume rendering. It distinguishes itself from lower-order siblings like the [2nd-Order Finite Difference Gradient](13052-2nd-order-finite-difference-gradient.md) by employing a wider stencil and boundary extrapolation to maintain high accuracy even at domain edges, whereas the 2nd-order method uses only immediate neighbors .

## How it works
**Inputs and Outputs:**
- Input: A 3D scalar grid $V$ of dimensions $N_x \times N_y \times N_z$, where $V_{i,j,k}$ is the value at voxel $(i,j,k)$.
- Input: `voxel_size` $h$, the physical spacing between voxels (assumed isotropic).
- Output: Three 3D grids $G_x, G_y, G_z$ representing the partial derivatives $\frac{\partial V}{\partial x}, \frac{\partial V}{\partial y}, \frac{\partial V}{\partial z}$.

**Data Structures:**
- The grid $V$ is stored as a dense 3D array or tensor.
- Boundary handling requires accessing indices outside $[0, N-1]$.

**Algorithm:**
The gradient is computed by approximating the central difference using forward and backward approximations that are extended to the boundaries using a 4th-order extrapolation formula.

1.  **Define Boundary Indices:**
    Let $n_x = N_x - 1$, $n_y = N_y - 1$, $n_z = N_z - 1$.

2.  **Compute X-Axis Gradient:**
    -   Compute forward approximation $X_1$:
        -   Interior: $V_{i+1, j, k}$ for $i \in [0, n_x-1]$.
        -   Boundary ($i=n_x$): Extrapolate $V_{n_x+1, j, k}$ using the 4th-order formula:
            $$ V_{n_x+1} = 3V_{n_x} - 3V_{n_x-1} + V_{n_x-2} $$
        -   Concatenate: $X_1 = [V_{1,\cdot,\cdot}, \dots, V_{n_x,\cdot,\cdot}, V_{n_x+1,\cdot,\cdot}]$.
    -   Compute backward approximation $X_2$:
        -   Boundary ($i=0$): Extrapolate $V_{-1, j, k}$ using the 4th-order formula:
            $$ V_{-1} = -3V_{0} + 3V_{1} + V_{2} $$
        -   Interior: $V_{i-1, j, k}$ for $i \in [1, n_x]$.
        -   Concatenate: $X_2 = [V_{-1,\cdot,\cdot}, V_{0,\cdot,\cdot}, \dots, V_{n_x-1,\cdot,\cdot}]$.
    -   Calculate $G_x$:
        $$ G_x = \frac{X_1 - X_2}{2h} $$

3.  **Compute Y-Axis Gradient:**
    -   Repeat logic for $Y_1$ and $Y_2$ along the $y$-dimension.
    -   $Y_1$ interior: $V_{i, j+1, k}$. Boundary $j=n_y$: $V_{i, n_y+1, k} = 3V_{i, n_y, k} - 3V_{i, n_y-1, k} + V_{i, n_y-2, k}$.
    -   $Y_2$ interior: $V_{i, j-1, k}$. Boundary $j=0$: $V_{i, -1, k} = -3V_{i, 0, k} + 3V_{i, 1, k} + V_{i, 2, k}$.
    -   Calculate $G_y = \frac{Y_1 - Y_2}{2h}$.

4.  **Compute Z-Axis Gradient:**
    -   Repeat logic for $Z_1$ and $Z_2$ along the $z$-dimension.
    -   $Z_1$ interior: $V_{i, j, k+1}$. Boundary $k=n_z$: $V_{i, j, n_z+1} = 3V_{i, j, n_z} - 3V_{i, j, n_z-1} + V_{i, j, n_z-2}$.
    -   $Z_2$ interior: $V_{i, j, k-1}$. Boundary $k=0$: $V_{i, j, -1} = -3V_{i, j, 0} + 3V_{i, j, 1} + V_{i, j, 2}$.
    -   Calculate $G_z = \frac{Z_1 - Z_2}{2h}$.

**Pseudocode:**
```python
def compute_4th_order_gradient(grid, voxel_size):
    """
    Computes the 4th-order finite difference gradient of a 3D grid.
    
    Args:
        grid: 3D numpy array or tensor of shape (Nx, Ny, Nz)
        voxel_size: float, physical spacing h
        
    Returns:
        gx, gy, gz: 3D arrays of shape (Nx, Ny, Nz)
    """
    Nx, Ny, Nz = grid.shape
    gx = np.zeros_like(grid)
    gy = np.zeros_like(grid)
    gz = np.zeros_like(grid)
    
    # Helper for 4th-order extrapolation at the end of a dimension
    def extrapolate_end(grid_slice, axis_idx, n):
        # grid_slice is the grid sliced along the other two axes
        # Returns the value at index n+1 based on n, n-1, n-2
        return 3 * grid_slice[n] - 3 * grid_slice[n-1] + grid_slice[n-2]

    # Helper for 4th-order extrapolation at the start of a dimension
    def extrapolate_start(grid_slice, axis_idx, n):
        # Returns the value at index -1 based on 0, 1, 2
        return -3 * grid_slice[0] + 3 * grid_slice[1] + grid_slice[2]

    # X-axis gradient
    # X1: forward difference shifted left (uses i+1)
    # Interior: grid[1:, :, :]
    # Boundary at Nx-1: extrapolate_end along axis 0
    x1_interior = grid[1:, :, :]
    x1_boundary = extrapolate_end(grid[:, :, :], 0, Nx - 1)
    x1_boundary = x1_boundary.reshape(1, Ny, Nz)
    X1 = np.concatenate([x1_interior, x1_boundary], axis=0)
    
    # X2: backward difference shifted right (uses i-1)
    # Interior: grid[:-1, :, :]
    # Boundary at 0: extrapolate_start along axis 0
    x2_interior = grid[:-1, :, :]
    x2_boundary = extrapolate_start(grid[:, :, :], 0, 0)
    x2_boundary = x2_boundary.reshape(1, Ny, Nz)
    X2 = np.concatenate([x2_boundary, x2_interior], axis=0)
    
    gx = (X1 - X2) / (2 * voxel_size)
    
    # Y-axis gradient
    # Y1: forward difference along axis 1
    y1_interior = grid[:, 1:, :]
    y1_boundary = extrapolate_end(grid[:, :, :], 1, Ny - 1)
    y1_boundary = y1_boundary.reshape(Nx, 1, Nz)
    Y1 = np.concatenate([y1_interior, y1_boundary], axis=1)
    
    # Y2: backward difference along axis 1
    y2_interior = grid[:, :-1, :]
    y2_boundary = extrapolate_start(grid[:, :, :], 1, 0)
    y2_boundary = y2_boundary.reshape(Nx, 1, Nz)
    Y2 = np.concatenate([y2_boundary, y2_interior], axis=1)
    
    gy = (Y1 - Y2) / (2 * voxel_size)
    
    # Z-axis gradient
    # Z1: forward difference along axis 2
    z1_interior = grid[:, :, 1:]
    z1_boundary = extrapolate_end(grid[:, :, :], 2, Nz - 1)
    z1_boundary = z1_boundary.reshape(Nx, Ny, 1)
    Z1 = np.concatenate([z1_interior, z1_boundary], axis=2)
    
    # Z2: backward difference along axis 2
    z2_interior = grid[:, :, :-1]
    z2_boundary = extrapolate_start(grid[:, :, :], 2, 0)
    z2_boundary = z2_boundary.reshape(Nx, Ny, 1)
    Z2 = np.concatenate([z2_boundary, z2_interior], axis=2)
    
    gz = (Z1 - Z2) / (2 * voxel_size)
    
    return gx, gy, gz
```

**Parameters:**
- `voxel_size`: The physical size of a single voxel. Used to normalize the finite difference result to physical units [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Small Grids:** If any dimension has fewer than 3 voxels, the extrapolation formula $V_{-1} = -3V_0 + 3V_1 + V_2$ or $V_{n+1} = 3V_n - 3V_{n-1} + V_{n-2}$ requires indices that do not exist. The method assumes $N \ge 3$ for all dimensions [G].
- **Precision:** The extrapolation coefficients (3, -3, 1) can amplify noise in the grid values, particularly near boundaries. This is a trade-off for maintaining 4th-order accuracy [S1, unofficial].

## Subtopics

### [2nd-Order Finite Difference Gradient](13052-2nd-order-finite-difference-gradient.md)
Uses only immediate neighbors for gradient estimation. Choose this when computational cost is critical and high-frequency noise is not a concern, as it offers a trade-off between cost and smoothness compared to the 4th-order method.

## Operating characteristics
- **Time Complexity:** $O(N_x N_y N_z)$, as each voxel is processed a constant number of times. The constant factor is higher than 2nd-order due to the larger stencil and boundary handling logic.
- **Memory Complexity:** $O(N_x N_y N_z)$ for storing the input grid and three output gradient grids.
- **Performance:** Provides significantly smoother normals than 2nd-order methods, which is beneficial for ray marching stability and shading quality [S1, unofficial].
- **Strengths:** High accuracy (4th-order) even at boundaries; smooth gradients.
- **Limitations:** Requires at least 3 voxels per dimension; sensitive to noise due to extrapolation coefficients; higher computational overhead than 2nd-order.
- **When to use:** When high-quality normals are required for SDF rendering and the grid resolution is sufficient ($N \ge 3$).
- **When not to use:** For very low-resolution grids or when noise robustness is prioritized over accuracy.

## Background
The method is implemented in the context of differentiable rendering of Signed Distance Functions, specifically in the SDFDiff framework [S1, unofficial]. It was presented in a 2020 paper (CVPR 2020) by Yue Jiang et al., aiming to provide accurate gradients for optimizing SDFs from images. The 4th-order finite difference scheme is a standard numerical analysis technique adapted here for grid-based volume data.
