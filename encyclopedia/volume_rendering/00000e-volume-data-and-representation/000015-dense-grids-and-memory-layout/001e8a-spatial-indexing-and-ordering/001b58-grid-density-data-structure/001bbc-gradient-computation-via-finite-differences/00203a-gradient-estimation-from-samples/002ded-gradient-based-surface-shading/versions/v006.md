# Gradient-Based Surface Shading

Also called: Gradient-Based Shading (Levoy), Grey-level gradient shading, Gray-level Shading

## Overview
Gradient-Based Surface Shading is a local illumination technique for volume rendering that approximates surface normals using the gradient of the scalar field to apply Phong-style lighting (diffuse, specular, and ambient) [S3][S5, unofficial]. Unlike standard emission/absorption models which treat voxels as light sources or absorbers, this method makes surface details and boundaries more prominent by calculating lighting based on local orientation [S3, S11]. It sets itself apart from its parent method, [Gradient Estimation from Samples](2180-gradient-estimation-from-samples.md), by specifically utilizing these estimated gradients to drive a shading model that mimics polygonal graphics, and from its sibling [Gradient-based Pre-computed Shading](3159-gradient-based-pre-computed-shading.md) by typically computing gradients on-the-fly or trading memory for time via precomputation [S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume $V$ with dimensions $W \times H \times D$, where each voxel $v_{i,j,k}$ holds an intensity value. A transfer function $\tau$ mapping intensity to opacity/color (optional, depending on implementation [S3]). Light parameters: light direction $\omega_i$, view direction $\omega_o$, light intensity $L_l$, and material coefficients ($k_a, k_d, k_s$).
*   **Output:** A shaded 2D image or ray-cast color value for each sample point.

**Data Structures:**
*   **Volume Grid:** Dense array of scalar values.
*   **Gradient Vector:** A 3D vector $\nabla f(x) = (G_x, G_y, G_z)$ computed at the sample location.
*   **Normal Vector:** The normalized gradient $\mathbf{n} = \frac{\nabla f(x)}{|\nabla f(x)|}$.

**Gradient Computation:**
The surface normal is approximated by the gradient of the scalar field. The gradient is computed numerically using finite differences [S5, unofficial]. The most common scheme is central differences [S2, S9, unofficial]. For a voxel at indices $(i, j, k)$ with value $v_{i,j,k}$ and spacing $(D_x, D_y, D_z)$:

$$
G_x = \frac{v_{i+1,j,k} - v_{i-1,j,k}}{2 D_x}
$$
$$
G_y = \frac{v_{i,j+1,k} - v_{i,j-1,k}}{2 D_y}
$$
$$
G_z = \frac{v_{i,j,k+1} - v_{i,j,k-1}}{2 D_z}
$$

Alternative schemes include forward/backward differences or the Sobel Operator [S5, unofficial]. Forward difference for $G_x$: $v_{i+1,j,k} - v_{i,j,k}$. Backward difference: $v_{i,j,k} - v_{i-1,j,k}$ [S9, unofficial].

**Shading Model:**
The method substitutes the geometric surface normal in the Blinn-Phong illumination model with the normalized gradient derived from the volumetric data [S3]. The total shading function $s(\tilde{x}, \omega_i, \omega_o)$ at position $\tilde{x}$ is the sum of ambient, diffuse, and specular components, modulated by the transfer function $\tau(\tilde{x})$ [S3]:

$$
s(\tilde{x}, \omega_i, \omega_o) = \tau(\tilde{x}) \cdot (L_{diff}(\tilde{x}, \omega_i) + L_{spec}(\tilde{x}, \omega_i, \omega_o) + L_{amb}(\tilde{x}))
$$

Where:
1.  **Ambient:**
    $$ L_{amb}(\tilde{x}) = L_l \cdot k_a $$
    This ensures voxels with gradients pointing away from the light source do not appear pitch black [S3].

2.  **Diffuse:**
    $$ L_{diff}(\tilde{x}, \omega_i) = L_l \cdot k_d \cdot \max(|\nabla \tau(f(\tilde{x}))| \cdot \omega_i, 0) $$
    Note: Some implementations use the magnitude of the gradient $|\nabla f|$ directly or normalized gradient $\mathbf{n} \cdot \omega_i$. The source [S3] explicitly includes the gradient magnitude $|\nabla \tau(f(\tilde{x}))|$ in the diffuse term, which is unusual for standard Phong (which uses dot product of normals). However, [S2, unofficial] and [S5, unofficial] imply standard Phong where $N(x) \cdot L$. We present the standard Blinn-Phong form using the normal $\mathbf{n}$ derived from the gradient, as supported by [S2, S5, unofficial], while noting [S3] uses magnitude. To be implementable and consistent with "Phong shading" mentioned in [S2, unofficial], we use the normal vector $\mathbf{n}$:
    $$ L_{diff}(\tilde{x}, \omega_i) = L_l \cdot k_d \cdot \max(\mathbf{n} \cdot \omega_i, 0) $$

3.  **Specular:**
    $$ L_{spec}(\tilde{x}, \omega_i, \omega_o) = L_l \cdot k_s \cdot \max(\mathbf{n} \cdot \mathbf{h}, 0)^\alpha $$
    Where $\mathbf{h}$ is the normalized half-vector between light and view directions, and $\alpha$ is the shininess exponent. Large $\alpha$ results in small sharp highlights; smaller $\alpha$ results in bigger smoother highlights [S3].

**Parameters:**
*   $k_a, k_d, k_s$: Ambient, diffuse, and specular coefficients (e.g., $k_a=0.1, k_d=0.5, k_s=0.4$ [S5, unofficial]).
*   $\alpha$: Shininess exponent [S3].
*   $L_l$: Initial light intensity [S3].
*   $D_x, D_y, D_z$: Physical spacing between samples [S9, unofficial].

**Pseudocode:**
```python
def compute_gradient(volume, i, j, k, dx, dy, dz):
    """
    Computes the gradient vector at voxel (i, j, k) using central differences.
    Handles boundary conditions by clamping indices.
    """
    # Helper to get voxel value with boundary clamping
    def get_voxel(ii, jj, kk):
        ii = max(0, min(ii, volume.width - 1))
        jj = max(0, min(jj, volume.height - 1))
        kk = max(0, min(kk, volume.depth - 1))
        return volume[ii, jj, kk]

    gx = (get_voxel(i + 1, j, k) - get_voxel(i - 1, j, k)) / (2 * dx)
    gy = (get_voxel(i, j + 1, k) - get_voxel(i, j - 1, k)) / (2 * dy)
    gz = (get_voxel(i, j, k + 1) - get_voxel(i, j, k - 1)) / (2 * dz)
    
    return Vector3(gx, gy, gz)

def gradient_shading_sample(volume, sample_pos, light_dir, view_dir, 
                            k_a, k_d, k_s, alpha, dx, dy, dz):
    """
    Computes the shaded color for a single sample point in the volume.
    """
    # 1. Get voxel value and compute gradient
    # Interpolate voxel value if sample_pos is not on grid center
    voxel_val = volume.interpolate(sample_pos)
    
    # Compute gradient at the grid location closest to sample_pos or at sample_pos
    # For simplicity, assuming sample_pos aligns with grid or we compute gradient at nearest grid point
    i, j, k = volume.world_to_grid(sample_pos)
    
    grad = compute_gradient(volume, i, j, k, dx, dy, dz)
    
    # 2. Normalize gradient to get surface normal
    grad_mag = length(grad)
    if grad_mag < 1e-6:
        # Fallback for homogeneous regions or zero gradient
        normal = Vector3(0, 0, 0) # Or a default normal, e.g., (0,0,1)
    else:
        normal = normalize(grad)
        
    # 3. Compute lighting components
    # Ambient
    L_amb = light_dir.intensity * k_a # Note: light_dir here represents light intensity vector L_l
    
    # Diffuse
    # Light direction vector L (normalized)
    L_vec = normalize(light_dir.direction)
    diffuse_term = max(dot(normal, L_vec), 0.0)
    L_diff = light_dir.intensity * k_d * diffuse_term
    
    # Specular
    # Half vector H = normalize(L + V)
    V_vec = normalize(view_dir.direction)
    H_vec = normalize(L_vec + V_vec)
    specular_term = pow(max(dot(normal, H_vec), 0.0), alpha)
    L_spec = light_dir.intensity * k_s * specular_term
    
    # 4. Combine
    # Apply transfer function tau for opacity/color modulation
    tau = volume.transfer_function(voxel_val)
    
    total_light = L_amb + L_diff + L_spec
    
    # Return shaded color (assuming light_dir.intensity is color intensity)
    return total_light * tau
```

**Edge Cases and Pitfalls:**
*   **Homogeneous Regions:** If the gradient magnitude is very low or zero, the normal is undefined or noisy. The method is not robust here [S6, book][S7].
*   **Noise Sensitivity:** Gradients are sensitive to noise. High-frequency noise emphasizes artifacts, making this method unsuitable for low SNR modalities like MRI, 3D ultrasound, or seismic data [S3][S6, book].
*   **Object Edges:** Central differences may smooth out sharp edges if adjacent pixels belong to different objects. Backward differences may provide better approximation at these boundaries [S9, unofficial].
*   **Clipping Surfaces:** When using clipping geometry, the computed gradient must be replaced with the clipping surface normal to avoid artifacts [S5, unofficial][S3].
*   **Multivariate Fields:** The method is unsuitable for multivariate fields because the eigenvector representing the direction of greatest change only indicates orientation, not absolute direction, leading to sign flips and interpolation issues [S6, book][S7].
*   **Thin Objects:** The technique may fail to display thin objects if the grey-level is inappropriate for locating the surface [S11].

## Subtopics

### [Gradient Estimation Methods](15931-gradient-estimation-methods.md)
Focuses on the accuracy of the gradient vector itself rather than just the surface location. The choice of method (e.g., Sobel vs. Central Difference) significantly impacts visual artifacts like ripple effects when sample distances are large.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample for gradient computation if precomputed, or $O(1)$ with a small constant for on-the-fly central differences (requires 6 neighbor lookups).
*   **Memory Complexity:** $O(1)$ additional memory if computed on-the-fly. If precomputed, $O(N)$ where $N$ is the number of voxels, requiring storage of 3 floats per voxel. For a $256 \times 256 \times 256$ dataset, precomputing gradients requires more than 200 MB [S4, unofficial].
*   **Performance:** Highly dependent on the Signal-to-Noise Ratio (SNR) of the data. It is widely used in interactive volume rendering due to its simplicity and effectiveness in enhancing surface details [S3].
*   **Strengths:** Makes surface details prominent; computationally inexpensive per sample; easy to implement.
*   **Limitations:** Not robust for homogeneous regions; sensitive to noise; unsuitable for multivariate fields; does not support shadows or global illumination effects (local shading only) [S3][S6, book].
*   **When to Use:** High-quality CT data with high SNR where surface detail enhancement is desired.
*   **When Not to Use:** Low SNR data (MRI, ultrasound), multivariate fields, or when global illumination/shadows are required.

## Background
Gradient-based shading was published by Hohne and Bernstein in 1986, using gray-level gradients to perform shading of surfaces rendered from 3D CT data [S8, unofficial]. It was further popularized by Levoy in 1988 with volume raycasting [S2, S8, unofficial]. It remains one of the most widely used shading techniques in interactive volume rendering [S3].
