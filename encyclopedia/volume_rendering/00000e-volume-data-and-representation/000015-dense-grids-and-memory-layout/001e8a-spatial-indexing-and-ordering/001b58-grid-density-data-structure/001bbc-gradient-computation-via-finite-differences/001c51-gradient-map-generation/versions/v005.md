# Gradient Map Generation
Also called: Gradient Map Compute Shader

## Overview
Gradient Map Generation is a GPU-based compute shader pass that calculates the 3D gradient vector for every voxel in a scalar volume and stores the results in a dedicated 3D image buffer [S1, unofficial]. It solves the problem of efficiently precomputing spatial derivative information for subsequent volume rendering or lighting passes. It differs from its parent [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md) by explicitly handling the storage layout (magnitude and direction in a single RGBA8_SNORM buffer) and post-processing steps (magnitude clamping and normalization) within the same kernel invocation [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D scalar volume texture (read-only), typically 8-bit or 16-bit unsigned normalized [S1, unofficial].
- Output: A 3D image buffer `gradient_map` with layout `rgba8_snorm` [S1, unofficial].
- Parameters: `grad_magnitude_modifier` (float), `reductionBlockSize` (unsigned int), `partition_intensity_min` (float, default 0), `partition_intensity_max` (float, default 255) [S1, unofficial].

**Data Structures:**
- `gradient_map`: 3D image buffer.
  - Format: `GL_RGBA8_SNORM` [S1, unofficial].
  - Layout:
    - `x, y, z`: Normalized gradient direction vector components.
    - `w`: Gradient magnitude, clamped to [0, 1].

**Steps:**
1. Determine the dimensions of the `gradient_map` image.
2. Dispatch a compute shader where each work group corresponds to a block of voxels. The global invocation ID $(i, j, k)$ maps to a specific voxel coordinate.
3. For each voxel at $(i, j, k)$, compute the gradient vector $\mathbf{g}$ using finite differences (as defined in [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md)).
4. Calculate the gradient magnitude $m = \|\mathbf{g}\|$.
5. Apply a modifier and clamp the magnitude: $m' = \text{clamp}(m \times \text{grad\_magnitude\_modifier}, 0.0, 1.0)$.
6. Normalize the gradient direction: $\mathbf{d} = \frac{\mathbf{g}}{\|\mathbf{g}\|}$. If $\|\mathbf{g}\| = 0$, $\mathbf{d}$ is undefined or set to $(0,0,0)$ [G].
7. Store $\mathbf{d}$ in the `x, y, z` components and $m'$ in the `w` component of `gradient_map[i][j][k]`.

**Pseudocode:**
```python
# Pseudocode for the compute shader invocation
# Inputs: textureVolume (3D texture), gradient_map (3D image buffer)
# Uniforms: grad_magnitude_modifier (float)

def compute_gradient_map(global_invocation_id):
    # 1. Get voxel coordinates from global invocation ID
    x, y, z = global_invocation_id
    
    # 2. Get volume dimensions
    vol_width, vol_height, vol_depth = get_volume_dimensions()
    
    # 3. Compute gradient vector using finite differences
    # This calls the logic from Gradient Computation via Finite Differences
    gradient_vector = get_gradient(x, y, z, vol_width, vol_height, vol_depth)
    
    # 4. Calculate magnitude
    magnitude = length(gradient_vector)
    
    # 5. Apply modifier and clamp
    modified_magnitude = magnitude * grad_magnitude_modifier
    clamped_magnitude = clamp(modified_magnitude, 0.0, 1.0)
    
    # 6. Normalize direction
    if magnitude > 0.0:
        direction = normalize(gradient_vector)
    else:
        direction = vec3(0.0, 0.0, 0.0) # [G] Default for zero gradient
        
    # 7. Store in gradient map
    # gradient_map is rgba8_snorm
    gradient_map[x][y][z] = vec4(direction.x, direction.y, direction.z, clamped_magnitude)
```

**Edge Cases and Pitfalls:**
- **Zero Gradient:** If the gradient vector is zero (e.g., in uniform regions), normalization is undefined. The implementation must handle this, typically by storing a zero vector [G].
- **Boundary Conditions:** Finite difference calculations at volume boundaries require special handling (e.g., one-sided differences or padding) to avoid accessing out-of-bounds memory [G].
- **Precision:** The `rgba8_snorm` format provides 8-bit signed normalized precision. This may introduce quantization artifacts in the gradient direction and magnitude, especially for subtle gradients.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed once in parallel.
- **Memory Complexity:** $O(N)$ for the output gradient map, requiring 4 bytes per voxel (RGBA8).
- **Performance:** Highly parallelizable on GPU. Performance is limited by memory bandwidth for large volumes due to the read of the volume texture and write to the gradient map.
- **Strengths:** Efficient GPU implementation; decouples gradient computation from rendering; provides both direction and magnitude in a single pass.
- **Limitations:** Quantization errors from 8-bit storage; requires additional memory for the gradient map; sensitive to noise in the input volume.

## Background
This method is implemented in the DVR_ESS_PDM project [S1, unofficial]. It is a common technique in volume rendering pipelines to precompute gradient information for lighting models, such as Phong shading or normal-based shading, to enhance the visual quality of the rendered volume.
