# Grid Density Data Structure

Also called: 1D Array Density Layout, 3D Grid, 3D Voxel Grid Density Field, Dense Voxel Grid Storage, Dense structure, Linearized 3D Grid, Volume Grid Data Structure

## Overview
The Grid Density Data Structure is a dense, axis-aligned 3D grid representation used to store scalar density values (or coupled fields like temperature) for volume rendering [S1, unofficial][S2, unofficial]. It solves the problem of efficiently storing and sampling volumetric data by mapping continuous world-space coordinates to discrete voxel indices, enabling direct access without the indirection overhead of sparse structures [S4, unofficial]. It sets itself apart from sparse representations like [Octree](../octree.md) or [BitGrid3D](../bitgrid3d.md) by guaranteeing $O(1)$ access time at the cost of memory proportional to the bounding box volume, and from [Spatial Indexing and Ordering](1797-spatial-indexing-and-ordering.md) variants by using a fixed, uniform resolution rather than adaptive subdivision [S1, unofficial][S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Grid resolution $N$ (assumed equal in all dimensions, typically a power of 2), world-space bounding box defined by minimum and maximum extents $B_{min}$ and $B_{max}$, and density values for each voxel [S1, unofficial].
*   **Output:** A contiguous 1D array of floating-point density values, accessible via linearized 3D indices, along with metadata for coordinate transformation [S1, unofficial][S3, unofficial].

**Data Structures:**
The grid is defined by a structure containing:
1.  `density`: A contiguous 1D array of `float` values with size $N^3$ [S1, unofficial].
2.  `dimension`: An integer representing the resolution $N$ in each dimension (e.g., 32, 64, 128) [S1, unofficial].
3.  `bounds`: An array of two 3D points representing the world-space minimum and maximum extents $[B_{min}, B_{max}]$ [S1, unofficial].
4.  `transformation`: A matrix $D$ that transforms world coordinates to local grid coordinates [S3, unofficial].

**Numbered Steps:**

1.  **Initialization:** Allocate a 1D array of size $N_x \cdot N_y \cdot N_z$ and initialize all values to 0 [S3, unofficial].
2.  **Coordinate Transformation Setup:** Define the world-space bounding box $[B_{min}, B_{max}]$ where the size is equal in all dimensions [S1, unofficial]. Compute the transformation matrix $D$ that maps world coordinates to local grid coordinates. This involves a translation $T(p_0)$ to the grid origin and a scaling $S(p_1 - p_0)$ to normalize the grid to unit size, combined with the world-to-local matrix $W$ [S3, unofficial]:
    $$ M = T(p_0) \times S(p_1 - p_0) $$
    $$ D = (W \times M)^{-1} $$
    where $p_0$ and $p_1$ are the local-coordinate points defining the grid bounds [S3, unofficial].
3.  **Density Population:** Iterate through the grid indices. For each voxel $(x, y, z)$, compute the local density value. For example, to generate a spherical smoke density:
    $$ dist = \sqrt{\left(x - \frac{n_x-1}{2}\right)^2 + \left(y - \frac{n_y-1}{2}\right)^2 + \left(z - \frac{n_z-1}{2}\right)^2} $$
    $$ density[index] = \frac{1}{2^{dist+2}} $$
    where the index is computed using row-major ordering [S3, unofficial].
4.  **Indexing:** Map 3D coordinates $(x, y, z)$ to a 1D index $I$ using row-major strides:
    $$ I = (z \cdot n_y + y) \cdot n_x + x $$
    where $n_x, n_y, n_z$ are the grid dimensions [S3, unofficial].

**Pseudocode:**

```python
import math

class GridDensity:
    def __init__(self, dimension: int, bounds_min: tuple, bounds_max: tuple):
        """
        Initialize a dense 3D grid density structure.
        
        Args:
            dimension: Resolution N (assumed equal for x, y, z).
            bounds_min: World-space minimum extent (x, y, z).
            bounds_max: World-space maximum extent (x, y, z).
        """
        self.dimension = dimension
        self.bounds_min = bounds_min
        self.bounds_max = bounds_max
        self.nx = dimension
        self.ny = dimension
        self.nz = dimension
        
        # Allocate contiguous 1D array for density
        self.density = [0.0] * (self.nx * self.ny * self.nz)
        
        # Compute transformation matrix D (world to local)
        # Note: In a real implementation, this would involve matrix inversion.
        # Here we assume a simple scaling/translation for demonstration.
        self.transform_matrix = self._compute_transform(bounds_min, bounds_max)

    def _compute_transform(self, b_min, b_max):
        """
        Compute the transformation matrix D from world to local coordinates.
        Simplified for demonstration: assumes axis-aligned and equal scaling.
        """
        # In practice, this uses the formula from [S3, unofficial]:
        # D = (W * M)^-1 where M involves translation and scaling.
        # For a simple AABB aligned with world axes:
        size_x = b_max[0] - b_min[0]
        size_y = b_max[1] - b_min[1]
        size_z = b_max[2] - b_min[2]
        
        # Return a placeholder for the actual matrix object
        return {"scale": (1.0/size_x, 1.0/size_y, 1.0/size_z), "offset": b_min}

    def set_density_sphere(self, center_local: tuple, radius: float):
        """
        Populate the grid with a spherical density field.
        """
        for z in range(1, self.nz - 1):
            for y in range(1, self.ny - 1):
                for x in range(1, self.nx - 1):
                    # Compute distance from center in local grid coordinates
                    dist = math.sqrt(
                        (x - (self.nx - 1) / 2)**2 +
                        (y - (self.ny - 1) / 2)**2 +
                        (z - (self.nz - 1) / 2)**2
                    )
                    # Apply density function
                    density_val = 1.0 / (2**(dist + 2))
                    
                    # Compute 1D index
                    index = (z * self.ny + y) * self.nx + x
                    self.density[index] = density_val

    def get_density(self, x: int, y: int, z: int) -> float:
        """
        Retrieve density value at grid coordinates.
        """
        index = (z * self.ny + y) * self.nx + x
        return self.density[index]

    def world_to_local(self, world_point: tuple) -> tuple:
        """
        Transform a world-space point to local grid coordinates.
        """
        # Apply inverse transformation
        # Simplified: subtract offset and divide by scale
        offset = self.transform_matrix["offset"]
        scale = self.transform_matrix["scale"]
        
        local_x = (world_point[0] - offset[0]) * scale[0]
        local_y = (world_point[1] - offset[1]) * scale[1]
        local_z = (world_point[2] - offset[2]) * scale[2]
        
        return (local_x, local_y, local_z)

    def save_to_binary(self, filename: str):
        """
        Save the grid density to a binary file.
        """
        with open(filename, 'wb') as f:
            for z in range(self.nz):
                for y in range(self.ny):
                    for x in range(self.nx):
                        density = self.density[(z * self.ny + y) * self.nx + x]
                        f.write(density.to_bytes(4, byteorder='little'))
```

**Parameters:**
*   **Resolution ($N$):** Number of voxels per dimension. Typically a power of 2 (8, 16, 32, 64, 128) for simplicity and hardware optimization [S1, unofficial].
*   **World-Space Bounds:** Minimum and maximum extents $(B_{min}, B_{max})$. The size must be equal in all dimensions for a cubic grid [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Usage:** Dense grids require memory proportional to $N^3$. High resolutions quickly exhaust available memory, limiting the detail compared to sparse structures [S4, unofficial].
*   **Boundary Conditions:** Harsh edges at the grid boundary can cause artifacts. It is recommended to enforce zero density at the edges (e.g., restricting the sphere radius to $9/2$ in an 11x11x11 grid) [S3, unofficial].
*   **Precision:** Floating-point precision in the density array affects the smoothness of the volume. [S1, unofficial]

## Operating characteristics
*   **Time Complexity:** Sampling is $O(1)$ per voxel access, as it involves simple arithmetic for index calculation and array lookup [S4, unofficial].
*   **Memory Complexity:** $O(N^3)$, where $N$ is the resolution. This is the primary limitation, as memory usage grows cubically with resolution [S4, unofficial].
*   **Measured Performance:** Dense grids are faster to sample than sparse grids because they avoid indirection overhead (e.g., tree traversal or pointer chasing) [S4, unofficial]. However, they require lower resolutions due to memory constraints, which can reduce visual detail [S4, unofficial].
*   **Strengths:** Fast sampling, simple implementation, supports precomputed data (like lighting) easily, and is compatible with 3D texture hardware acceleration [S4, unofficial].
*   **Limitations:** High memory consumption limits resolution; inefficient for sparse scenes with large empty regions [S4, unofficial].
*   **When to Use:** Suitable for scenes with high density or when sampling speed is critical and memory is sufficient [S4, unofficial].
*   **When Not to Use:** Unsuitable for very large, sparse scenes where memory efficiency is paramount [S4, unofficial].

## Background
The Grid Density Data Structure originates from the need to store and render volumetric data from fluid simulations (smoke, water, etc.) [S1, unofficial]. It is a fundamental concept in volume rendering, often referred to as a "3D bitmap" [S1, unofficial]. The approach is detailed in educational resources on volume rendering, such as those by Scratchapixel [S1, unofficial], and is used in implementations like the volume path tracer by Shibodd [S2, unofficial] and the volumetric path tracing project by Jugoodma [S3, unofficial]. It is often loaded from sparse formats like OpenVDB and converted to dense grids for rendering [S4, unofficial].
