# Grid Density Data Structure

Also called: 3D Grid, 3D Scalar Grid, Dense Voxel Grid Storage, Volume Grid Data Structure

## Overview
The Grid Density Data Structure stores scalar density values in a fixed-resolution, axis-aligned 3D grid for volume rendering [S1, S5, unofficial]. It discretizes a continuous volumetric field into a contiguous memory layout, enabling fast direct sampling without the indirection overhead of sparse structures [S5, unofficial]. Unlike sparse alternatives that trade memory efficiency for traversal speed, the dense grid guarantees $O(1)$ coordinate-to-index mapping [S5, unofficial]. It provides the base storage for downstream methods like [Interpolated Discrete Values & Gradients](1268-interpolated-discrete-values-gradients.md) and [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md) [G].

## How it works
**Inputs:**
- Grid resolution $N$ (equal in all dimensions, typically a power of 2) [S1, unofficial].
- World-space bounds: minimum point $\mathbf{p}_{min}$ and maximum point $\mathbf{p}_{max}$, forming an axis-aligned bounding box (AABB) with equal physical size in all three dimensions [S1, unofficial].
- Optional: A transformation matrix $\mathbf{W}$ mapping local grid coordinates to world coordinates, and its inverse $\mathbf{D}$ for ray intersection [S3, unofficial].

**Outputs:**
- A dense 3D scalar field accessible via 3D integer indices $(x, y, z)$ or 1D linear index $I$ [S3, unofficial].

**Data Structures:**
The grid is stored as a contiguous 1D array of floating-point values [S1, unofficial]. Implementations vary in field naming, but core components include:
1. **`density`**: A 1D array of `float` values of size $N_x \cdot N_y \cdot N_z$ [S1, S3, unofficial].
2. **`nx`, `ny`, `nz`** (or `dimension`): Integer resolutions per axis [S4, unofficial]. For cubic grids, $N_x = N_y = N_z = N$ [S1, unofficial].
3. **`bounds`**: An array of two 3D points `bounds[0]` ($\mathbf{p}_{min}$) and `bounds[1]` ($\mathbf{p}_{max}$) defining the world-space extent [S1, unofficial].
4. **`voxel_size`**: The physical spacing between grid points, present in some implementations but not given as a direct input parameter for the basic structure [S4, unofficial].

*Note: Some implementations extend this structure to store additional fields like temperature or majorant values in parallel arrays or handles, but the core density structure remains a single contiguous float array [S2, unofficial].*

**Indexing Formula:**
Coordinates $(x, y, z)$ are mapped to a 1D linear index $I$ using row-major ordering (Z-major, Y-major, X-minor) [S3, unofficial]:
$$ I = (z \cdot N_y + y) \cdot N_x + x $$
where $0 \le x < N_x$, $0 \le y < N_y$, and $0 \le z < N_z$ [S3, unofficial].

**Algorithm: Grid Initialization and Population** [S3, unofficial].
The following pseudocode demonstrates initializing a grid and populating it with a radial density profile, as described in [S3, unofficial].

```python
import math

def create_grid(nx, ny, nz):
    """
    Creates a dense 3D grid structure.
    Returns a dictionary containing the density array and dimensions.
    """
    # Initialize density array of size nx * ny * nz to 0.0 [S3, unofficial]
    density = [0.0] * (nx * ny * nz)
    
    # Store dimensions and bounds [S1, unofficial]
    bounds_min = (-1.0, -1.0, -1.0)
    bounds_max = (1.0, 1.0, 1.0)
    
    return {
        "density": density,
        "nx": nx,
        "ny": ny,
        "nz": nz,
        "bounds": [bounds_min, bounds_max]
    }

def populate_radial_density(grid):
    """
    Populates the grid with a radial density falloff.
    Based on the formula from [S3, unofficial].
    """
    nx = grid["nx"]
    ny = grid["ny"]
    nz = grid["nz"]
    density = grid["density"]
    
    # Iterate through interior voxels to avoid boundary artifacts [S3, unofficial]
    for z in range(1, nz - 1):
        for y in range(1, ny - 1):
            for x in range(1, nx - 1):
                # Calculate distance from center of grid [S3, unofficial]
                dist_sq = (x - (nx - 1) / 2)**2 + \
                          (y - (ny - 1) / 2)**2 + \
                          (z - (nz - 1) / 2)**2
                dist = math.sqrt(dist_sq)
                
                # Compute density value [S3, unofficial]
                val = 1.0 / (2**(dist + 2))
                
                # Map 3D coordinates to 1D index [S3, unofficial]
                index = (z * ny + y) * nx + x
                density[index] = val

def sample_grid(grid, world_point):
    """
    Samples the grid density at a specific world coordinate.
    """
    bounds_min = grid["bounds"][0]
    bounds_max = grid["bounds"][1]
    nx = grid["nx"]
    ny = grid["ny"]
    nz = grid["nz"]
    
    # World-to-local conversion not given in sources [G]
    local_x = (world_point[0] - bounds_min[0]) / (bounds_max[0] - bounds_min[0]) * (nx - 1)
    local_y = (world_point[1] - bounds_min[1]) / (bounds_max[1] - bounds_min[1]) * (ny - 1)
    local_z = (world_point[2] - bounds_min[2]) / (bounds_max[2] - bounds_min[2]) * (nz - 1)
    
    # Clamp to valid range [0, N-1] to handle boundary cases [G]
    local_x = max(0, min(nx - 1, local_x))
    local_y = max(0, min(ny - 1, local_y))
    local_z = max(0, min(nz - 1, local_z))
    
    # For nearest-neighbor sampling (dense grid default without interpolation)
    ix = int(round(local_x))
    iy = int(round(local_y))
    iz = int(round(local_z))
    
    # Ensure indices are within bounds [G]
    ix = max(0, min(nx - 1, ix))
    iy = max(0, min(ny - 1, iy))
    iz = max(0, min(nz - 1, iz))
    
    # Calculate 1D index [S3, unofficial]
    index = (iz * ny + iy) * nx + ix
    
    return grid["density"][index]
```

**Parameters:**
- **Resolution ($N$)**: Number of voxels per dimension [S1, unofficial]. Common values are powers of 2 (8, 16, 32, 64, 128) to facilitate texture mapping and memory alignment [S1, unofficial].
- **Bounds**: Defined by $\mathbf{p}_{min}$ and $\mathbf{p}_{max}$. The physical size must be identical in all three dimensions for cubic voxels [S1, unofficial].
- **Voxel Size**: Implicitly determined by bounds and resolution [S4, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Artifacts**: Hard edges at the grid boundary can cause visual artifacts [S3, unofficial]. It is recommended to enforce zero density at the outermost voxels (indices 0 and $N-1$) to smooth the falloff [S3, unofficial].
- **Memory Usage**: Dense grids require memory proportional to $N^3$ [S1, S5, unofficial]. High resolutions quickly exhaust available memory, limiting the detail that can be stored compared to sparse structures [S5, unofficial].
- **Indirection Overhead**: While dense grids avoid the pointer chasing of sparse trees, they suffer from poor cache locality if the ray traversal jumps between distant parts of the grid without spatial coherence [S5, unofficial].

## Subtopics

### [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md)
Gradient Computation via Finite Differences estimates the spatial derivative vector (surface normal) of a scalar volume field at discrete voxel positions to enable local illumination models such as Phong shading or directional lighting. It differs from [Analytic Gradient Computation](2167-analytic-gradient-computation.md) by relying on discrete sampling rather than closed-form differentiation, and from [Gradient Estimation from Samples](2180-gradient-estimation-from-samples.md) by using a deterministic, grid-aligned stencil structure rather than stochastic or ray-based estimation.

### [EdgeMap Data Layout](1109-edgemap-data-layout.md)
The EdgeMap data layout is a dense grid structure that stores geometric primitives (intersections, normals, and traversal directions) for isosurface extraction, specifically designed to support efficient mesh generation from volumetric data. It differs from sibling methods like the [VoxelGrid Data Structure](1216-voxelgrid-data-structure.md) by explicitly decoupling geometric attributes from scalar values, storing them in parallel arrays indexed by a global edge map, which enables coherent mesh construction without repeated lookups.

### [VoxelGrid Data Structure](1216-voxelgrid-data-structure.md)
The VoxelGrid Data Structure is a dense 3D grid representation that maps continuous world coordinates to discrete voxel indices within a defined bounding box. It stores per-voxel data such as occupancy bits or label histograms, differing from sparse alternatives by guaranteeing $O(1)$ index-based access at the cost of memory proportional to the bounding box volume.

### [Interpolated Discrete Values & Gradients](1268-interpolated-discrete-values-gradients.md)
Interpolated Discrete Values & Gradients computes a continuous scalar field and its spatial gradient from discrete grid data using tri-cubic interpolation. It solves the problem of mapping continuous world-space coordinates to discrete memory indices while providing smooth, differentiable field values essential for ray marching and isosurface extraction. Unlike [Nearest Voxel Lookup with Periodic Boundary](1573-nearest-voxel-lookup-with-periodic-boundary.md), which produces a piecewise-constant field with sharp discontinuities, this method blends adjacent voxels to ensure $C^0$ continuity and provides explicit gradient estimates for stable normal estimation. It differs from [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md) by deriving gradients analytically from the interpolation basis functions rather than approximating them via discrete differences, resulting in smoother derivatives.

### [Euclidean Distance Field (EDF) Data Structure](3220-euclidean-distance-field-edf-data-structure.md)
The Euclidean Distance Field (EDF) is a dense grid data structure used in volume rendering to accelerate ray traversal by storing the distance to the nearest occupied voxel. It solves the problem of slow, voxel-by-ray stepping in dense or complex geometries by allowing rays to skip empty space in large increments proportional to the stored distance. It is distinguished from its siblings, such as the [VoxelGrid Data Structure](1216-voxelgrid-data-structure.md) which steps one voxel at a time, and the [EdgeMap Data Layout](1109-edgemap-data-layout.md) which uses boundary representations, by providing a continuous metric of proximity that trades higher memory bandwidth and pre-processing costs for only modest traversal length reductions (~8% shorter than space-partitioning methods).

### [Grid Resolution Heuristic](4871-grid-resolution-heuristic.md)
The Grid Resolution Heuristic is a method for computing optimal grid densities ($\lambda$) for leaf levels in spatial acceleration structures to minimize expected ray traversal cost. It addresses the problem of determining the appropriate granularity of a uniform grid by balancing the cost of traversing empty space against the cost of intersecting primitives within occupied cells. Unlike static resolution choices, this heuristic uses the Surface Area Metric to derive scene-specific density values that optimize the trade-off between traversal and intersection overhead. It differs from sibling methods like [Euclidean Distance Field (EDF) Data Structure](3220-euclidean-distance-field-edf-data-structure.md) by focusing on global density parameters rather than local geometric distance fields, and from [Gradient Computation via Finite Differences](1077-gradient-computation-via-finite-differences.md) by operating on discrete cell occupancy rather than continuous field derivatives.

### [Hypertree Grid Object](18823-hypertree-grid-object.md)
The Hypertree Grid Object (GE) is a data structure for representing Adaptive Mesh Refinement (AMR) simulations with rectilinear geometry, combining multiple hypertrees into a single, consecutively ordered grid. It solves the problem of efficiently storing and visualizing large-scale, sparse, tree-based AMR data by reducing memory footprint by nearly an order of magnitude compared to explicit unstructured meshes, while maintaining rectilinear connectivity for optimized traversal. It is distinguished from its siblings by its specific constraint to rectilinear, implicit geometric definitions and its global indexing scheme, unlike the [VoxelGrid Data Structure](1216-voxelgrid-data-structure.md) which uses uniform dense grids, or the [Euclidean Distance Field (EDF) Data Structure](3220-euclidean-distance-field-edf-data-structure.md) which focuses on distance metrics rather than topological refinement.

## Operating characteristics
- **Time Complexity**: Access and update are $O(1)$ with respect to the number of voxels, as indexing is a direct arithmetic calculation [S1, S5, unofficial].
- **Memory Complexity**: $O(N^3)$, where $N$ is the resolution per dimension [S1, S5, unofficial]. Memory usage grows cubically, making high-resolution grids expensive [S5, unofficial].
- **Performance**: Dense grids are significantly faster to sample than sparse grids because they avoid indirection overhead (pointer chasing) [S5, unofficial]. However, the maximum achievable resolution is lower than sparse methods due to memory constraints [S5, unofficial].
- **Strengths**: Simple implementation, fast sampling, compatibility with 3D texture hardware, ability to store precomputed data (e.g., lighting) [S5, unofficial].
- **Limitations**: High memory consumption, fixed resolution (cannot adapt to local detail), poor spatial locality for non-adjacent slices if not using space-filling curves [S1, S5, unofficial].
- **When to Use**: Suitable for scenes with moderate resolution requirements, or when the overhead of sparse structures is unacceptable [S5, unofficial]. Often used as a target format for data loaded from sparse formats like OpenVDB [S5, unofficial].
- **When Not to Use**: When memory is severely constrained, or when the volume has large empty regions where sparse structures (like [VoxelGrid Data Structure](1216-voxelgrid-data-structure.md)) would be more efficient [S5, unofficial].

## Background
The 3D grid density structure discretizes fluid simulation results and volumetric data for rendering [S1, unofficial]. It is analogous to how bitmaps represent 2D images [S1, unofficial]. Early ray tracer implementations used simple 1D arrays mapped to 3D coordinates, often assuming axis-aligned bounding boxes for efficient ray intersection [S1, unofficial]. The structure is widely used in educational implementations demonstrating heterogeneous media, such as the radial density formula for smoke spheres [S3, unofficial]. Industry tools like OpenVDB load sparse voxel data and convert it to dense grids for rendering [S5, unofficial].
