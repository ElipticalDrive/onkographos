# Grid Density Data Structure

Also called: 3D Grid, 3D Scalar Grid, Dense Voxel Grid Storage, Volume Grid Data Structure

## Overview
The Grid Density Data Structure is a dense, axis-aligned 3D grid representation used to store scalar density values for volume rendering [S1, unofficial]. It solves the problem of discretizing a continuous volumetric field into a fixed-resolution lattice, enabling fast, direct memory access during ray marching [S1, unofficial][S5, unofficial]. Unlike sparse alternatives like [Sparse Voxel Octrees](1705-sparse-voxel-octrees.md) or [KD-Tree Volume Rendering](1706-kd-tree-volume-rendering.md), which offer memory efficiency at the cost of traversal indirection, the dense grid guarantees $O(1)$ sampling time by storing data in a contiguous 1D array, making it ideal for high-performance rendering where resolution is constrained by memory rather than scene complexity [S5, unofficial].

## How it works
The method maps a 3D world-space bounding box to a fixed-resolution cubic lattice. Each voxel stores a single scalar density value. The grid is assumed to be an axis-aligned bounding box (AABB) with equal resolution in all three dimensions [S1, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   `resolution` ($N$): Integer number of voxels per dimension (e.g., 32, 64, 128). Sources suggest powers of 2 are common for this structure, though not strictly required by the data layout itself [S1, unofficial].
    *   `bounds`: Two 3D points defining the minimum ($p_{min}$) and maximum ($p_{max}$) extents of the grid in world space. The physical size must be identical in all three dimensions (i.e., $p_{max} - p_{min}$ is a scalar vector) [S1, unofficial].
    *   `density_data`: A sequence of floating-point values representing the density at each voxel.
*   **Outputs:**
    *   A `Grid` object containing the density array, resolution, and bounds, ready for ray-box intersection and ray-marching sampling.

### Data Structures
The core structure is a flat 1D array of floats, indexed using row-major (or equivalent contiguous) ordering.

**Struct Layout:**
```cpp
struct Grid {
    float *density;       // Contiguous memory block of size resolution^3
    size_t dimension;     // Resolution N (e.g., 128)
    Point bounds[2];      // World-space min and max extents
};
```
*   `density`: Array of size $N^3$.
*   `dimension`: The integer resolution $N$.
*   `bounds`: Array of two 3D points. `bounds[0]` is the minimum corner, `bounds[1]` is the maximum corner [S1, unofficial].

**Indexing Formula:**
Given voxel coordinates $(x, y, z)$ where $0 \le x, y, z < N$, the linear index $I$ in the 1D array is:
$$ I = (z \cdot N + y) \cdot N + x $$
This corresponds to iterating $z$ (depth), then $y$ (row), then $x$ (column) [S3, unofficial].

### Parameters
*   **Resolution ($N$):** Number of voxels along any axis. Typical values are powers of 2 (8, 16, 32, 64, 128) to simplify texture mapping or hardware acceleration, though the data structure itself supports any integer $N \ge 1$ [S1, unofficial].
*   **World Bounds:** Defined by $p_{min}$ and $p_{max}$. The size $S = p_{max} - p_{min}$ must satisfy $S_x = S_y = S_z$ [S1, unofficial].
*   **Voxel Size ($\Delta$):** The physical size of one voxel is $\Delta = S / N$.

### Numbered Steps

1.  **Initialize Grid:**
    Allocate a 1D array `density` of size $N^3$. Initialize all values to 0.0.
2.  **Define Bounds:**
    Set `bounds[0]` and `bounds[1]` to define the AABB in world space. Ensure the box is cubic (equal side lengths) [S1, unofficial].
3.  **Populate Density (Example: Spherical Source):**
    To generate a simple density field (e.g., a smoke sphere centered in the grid):
    a. Iterate $z$ from $1$ to $N-2$.
    b. Iterate $y$ from $1$ to $N-2$.
    c. Iterate $x$ from $1$ to $N-2$.
    d. Calculate the normalized distance from the center:
       $$ dist = \sqrt{ \left(x - \frac{N-1}{2}\right)^2 + \left(y - \frac{N-1}{2}\right)^2 + \left(z - \frac{N-1}{2}\right)^2 } $$
    e. Compute density using an exponential falloff:
       $$ density[index] = \frac{1}{2^{dist + 2}} $$
    f. Store at index $I = (z \cdot N + y) \cdot N + x$ [S3, unofficial].
    *Note: Edges are often left at 0 to reduce harsh artifacts at the boundary [S3, unofficial].*
4.  **Coordinate Transformation (Optional but Recommended):**
    To sample the grid from a world-space ray, compute a transformation matrix $D$ that maps world coordinates to local grid coordinates $(0 \dots N-1)$.
    a. Let $p_0$ and $p_1$ be the local bounds $(0,0,0)$ and $(N-1, N-1, N-1)$.
    b. Compute scaling matrix $S$ and translation $T$ to map world bounds to local bounds.
    c. If $W$ is the world-to-local transformation matrix for the grid object, the inverse $D = (W \times M)^{-1}$ maps world points to grid indices [S3, unofficial].

### Pseudocode

```python
import math

class Grid:
    def __init__(self, resolution, bounds_min, bounds_max):
        """
        Initialize a dense 3D grid.
        
        Args:
            resolution (int): Number of voxels per dimension (N).
            bounds_min (tuple): (x, y, z) minimum world coordinates.
            bounds_max (tuple): (x, y, z) maximum world coordinates.
        """
        self.N = resolution
        self.bounds_min = bounds_min
        self.bounds_max = bounds_max
        
        # Validate cubic bounds
        size_x = bounds_max[0] - bounds_min[0]
        size_y = bounds_max[1] - bounds_min[1]
        size_z = bounds_max[2] - bounds_min[2]
        if not (math.isclose(size_x, size_y) and math.isclose(size_y, size_z)):
            raise ValueError("Grid bounds must form a cube (equal dimensions in all axes)")
        
        self.size = size_x
        self.voxel_size = self.size / self.N
        
        # Allocate contiguous 1D array
        self.density = [0.0] * (self.N ** 3)

    def set_density_sphere(self, center_x, center_y, center_z, falloff_base=2.0, falloff_offset=2.0):
        """
        Populate grid with a spherical density field.
        Iterates from 1 to N-2 to keep edges at 0.
        """
        half_N = (self.N - 1) / 2.0
        
        for z in range(1, self.N - 1):
            for y in range(1, self.N - 1):
                for x in range(1, self.N - 1):
                    # Calculate distance from center in voxel units
                    dx = x - half_N
                    dy = y - half_N
                    dz = z - half_N
                    dist = math.sqrt(dx*dx + dy*dy + dz*dz)
                    
                    # Compute density
                    val = 1.0 / (falloff_base ** (dist + falloff_offset))
                    
                    # Linear index: row-major (z, y, x)
                    idx = (z * self.N + y) * self.N + x
                    self.density[idx] = val

    def sample(self, world_x, world_y, world_z):
        """
        Sample density at a world-space coordinate.
        Returns 0.0 if outside bounds.
        """
        # Transform world to local grid coordinates
        # Local coord = (World - Min) / VoxelSize
        lx = (world_x - self.bounds_min[0]) / self.voxel_size
        ly = (world_y - self.bounds_min[1]) / self.voxel_size
        lz = (world_z - self.bounds_min[2]) / self.voxel_size
        
        # Check bounds
        if not (0 <= lx < self.N and 0 <= ly < self.N and 0 <= lz < self.N):
            return 0.0
            
        # For nearest-neighbor sampling, truncate to integer indices
        ix = int(lx)
        iy = int(ly)
        iz = int(lz)
        
        # Clamp to valid range (handles floating point errors near N)
        ix = max(0, min(ix, self.N - 1))
        iy = max(0, min(iy, self.N - 1))
        iz = max(0, min(iz, self.N - 1))
        
        idx = (iz * self.N + iy) * self.N + ix
        return self.density[idx]
```

### Edge Cases and Pitfalls
*   **Memory Usage:** The memory cost is $O(N^3)$. For high resolutions (e.g., $1024^3$), this requires significant RAM (8GB for 32-bit floats), limiting the maximum resolution compared to sparse structures [S5, unofficial].
*   **Boundary Artifacts:** If density values at the grid edges are non-zero, ray marching may produce artifacts as rays exit the volume. It is common practice to force the outermost layer of voxels (index 0 and $N-1$) to 0 [S3, unofficial].
*   **Coordinate Transformation:** Failing to correctly invert the world-to-local transformation matrix will result in sampling the wrong part of the grid or out-of-bounds access [S3, unofficial].
*   **Interpolation:** The basic structure stores discrete values. For smooth rendering, interpolation (e.g., tri-linear) must be implemented on top of this structure, as the raw array only provides nearest-neighbor access [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Sampling is $O(1)$ because it involves direct array indexing and simple arithmetic [S5, unofficial]. Ray-box intersection is also $O(1)$ [S1, unofficial].
*   **Memory Complexity:** $O(N^3)$, where $N$ is the resolution per dimension. Memory usage grows cubically with resolution [S5, unofficial].
*   **Performance:** Dense grids are significantly faster to sample than sparse grids (like [Sparse Voxel Octrees](1705-sparse-voxel-octrees.md)) because they avoid pointer indirection and cache misses associated with tree traversal [S5, unofficial]. However, the maximum achievable resolution is lower due to memory constraints [S5, unofficial].
*   **Strengths:** Simple implementation, excellent cache locality for contiguous traversal, fast sampling, easy integration with 3D textures in GPUs [S5, unofficial].
*   **Limitations:** High memory consumption limits resolution; inefficient for sparse scenes where most of the grid is empty [S5, unofficial].
*   **When to Use:** When the volume is dense, the resolution required is moderate (e.g., < 256^3), and sampling speed is prioritized over memory footprint. Common in real-time cloud rendering or fluid visualization [S5, unofficial].
*   **When Not to Use:** For large, sparse scenes (e.g., vast atmospheric volumes with small clouds) where memory efficiency is paramount; use [Sparse Voxel Octrees](1705-sparse-voxel-octrees.md) or [KD-Tree Volume Rendering](1706-kd-tree-volume-rendering.md) instead.

## Background
The 3D grid density structure is a fundamental representation in volume rendering, originating from the discretization of continuous scalar fields. It is widely used in fluid simulation visualization (smoke, fire) and atmospheric rendering. The approach of storing density in a 3D grid is analogous to storing pixel values in a 2D bitmap [S1, unofficial]. Early implementations relied on simple array indexing, while modern implementations often load data from sparse formats like OpenVDB and convert them to dense grids for faster sampling [S5, unofficial]. The structure is a key component in many ray marching algorithms, where it serves as the primary data source for opacity and color accumulation [S1, unofficial].
