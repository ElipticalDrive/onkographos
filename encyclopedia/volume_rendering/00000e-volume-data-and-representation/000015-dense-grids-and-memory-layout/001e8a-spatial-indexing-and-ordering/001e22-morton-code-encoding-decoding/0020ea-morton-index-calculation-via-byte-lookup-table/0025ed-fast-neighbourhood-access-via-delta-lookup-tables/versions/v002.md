# Fast Neighbourhood Access via Delta Lookup Tables

Also called: Morton neighbour peeking, deltaX/Y/Z lookup

## Overview
A method to access immediate neighbours of a voxel in Morton-ordered memory without re-encoding coordinates, using precomputed offset tables that map a coordinate component to the memory stride required to reach its neighbour [S1, unofficial]. It solves the performance bottleneck of decoding a Morton index to $(x,y,z)$, modifying coordinates, and re-encoding, which involves expensive bitwise operations [S1, unofficial]. It is significantly faster than the naive decode-modify-encode approach and offers a simpler implementation alternative to bitwise manipulation methods like Fabian Giesen’s [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Current voxel pointer in Morton-ordered memory, current chunk-local coordinates $(x, y, z)$, and precomputed delta lookup tables [S1, unofficial].
- Output: Pointer to the neighbour voxel (e.g., at $x+1, y, z$) or a fallback mechanism if the neighbour is outside the current chunk [S1, unofficial].

**Data Structures:**
Three lookup tables: `deltaX`, `deltaY`, and `deltaZ` [S1, unofficial].
- Size: 256 elements each (for 8-bit coordinate components, supporting chunks up to $256^3$ voxels) [S1, unofficial].
- Type: Integer offsets (e.g., `int32_t`) representing the stride in memory [S1, unofficial].
- Layout: The value at index $i$ is the Morton index difference between a voxel at coordinate $i$ and its neighbour at $i+1$ along that axis, assuming the other two coordinates are constant [S1, unofficial].

**Numbered Steps:**
1. Initialize three lookup tables (`deltaX`, `deltaY`, `deltaZ`) of size 256 [S1, unofficial].
2. Populate `deltaX[i]` with the difference between the Morton index of $(i+1, 0, 0)$ and $(i, 0, 0)$ for $i \in [0, 255]$ [S1, unofficial].
3. Populate `deltaY[i]` with the difference between the Morton index of $(0, i+1, 0)$ and $(0, i, 0)$ for $i \in [0, 255]$ [S1, unofficial].
4. Populate `deltaZ[i]` with the difference between the Morton index of $(0, 0, i+1)$ and $(0, 0, i)$ for $i \in [0, 255]$ [S1, unofficial].
5. To access the neighbour at $(x+1, y, z)$:
   - Check if $x+1$ is within the current chunk boundaries [S1, unofficial].
   - If yes, compute `new_ptr = current_ptr + deltaX[x]` [S1, unofficial].
   - If no, fallback to global coordinate calculation [S1, unofficial].
6. To access the neighbour at $(x+1, y+1, z+1)$:
   - Check if $x+1, y+1, z+1$ are within current chunk boundaries [S1, unofficial].
   - If yes, compute `new_ptr = current_ptr + deltaX[x] + deltaY[y] + deltaZ[z]` [S1, unofficial].
   - If no, fallback to global coordinate calculation [S1, unofficial].

**Formulas:**
Let $M(x, y, z)$ be the Morton index of voxel $(x, y, z)$ [S1, unofficial].
The delta for the x-axis is defined as:
$$ \Delta X_x = M(x+1, 0, 0) - M(x, 0, 0) $$
The delta for the y-axis is defined as:
$$ \Delta Y_y = M(0, y+1, 0) - M(0, y, 0) $$
The delta for the z-axis is defined as:
$$ \Delta Z_z = M(0, 0, z+1) - M(0, 0, z) $$
The new pointer for a neighbour at $(x+\delta_x, y+\delta_y, z+\delta_z)$ is:
$$ P_{new} = P_{current} + \sum_{axis \in \{x,y,z\}, \delta_{axis}=1} \Delta_{axis}[coord_{axis}] $$

**Parameters:**
- Table size: 256 (supports chunks up to $256^3$) [S1, unofficial].
- Coordinate bit-width: 8 bits per axis (implied by table size) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Chunk Boundaries:** If the neighbour lies outside the current chunk, the delta lookup is invalid for the global volume. The implementation must check chunk boundaries using macros (e.g., `CAN_GO_POS_X`) before using the delta [S1, unofficial].
- **Fallback:** If the boundary check fails, the method must fall back to decoding the Morton index to global coordinates, modifying them, and re-encoding or using a global lookup [S1, unofficial].

**Pseudocode:**
```python
# Precomputed tables (size 256)
deltaX = [0] * 256
deltaY = [0] * 256
deltaZ = [0] * 256

def morton_encode(x, y, z):
    """Standard 3D Morton (Z-order) encoding [G]."""
    x = (x | (x << 16)) & 0x0000FFFF0000FFFF
    x = (x | (x << 8)) & 0x00FF00FF00FF00FF
    x = (x | (x << 4)) & 0x0F0F0F0F0F0F0F0F
    x = (x | (x << 2)) & 0x3333333333333333
    x = (x | (x << 1)) & 0x5555555555555555
    y = (y | (y << 16)) & 0x0000FFFF0000FFFF
    y = (y | (y << 8)) & 0x00FF00FF00FF00FF
    y = (y | (y << 4)) & 0x0F0F0F0F0F0F0F0F
    y = (y | (y << 2)) & 0x3333333333333333
    y = (y | (y << 1)) & 0x5555555555555555
    z = (z | (z << 16)) & 0x0000FFFF0000FFFF
    z = (z | (z << 8)) & 0x00FF00FF00FF00FF
    z = (z | (z << 4)) & 0x0F0F0F0F0F0F0F0F
    z = (z | (z << 2)) & 0x3333333333333333
    z = (z | (z << 1)) & 0x5555555555555555
    return x | (y << 1) | (z << 2)

def morton_decode(index):
    """Standard 3D Morton decoding [G]."""
    index = index & 0x5555555555555555
    index = (index ^ (index >> 1)) & 0x3333333333333333
    index = (index ^ (index >> 2)) & 0x0F0F0F0F0F0F0F0F
    index = (index ^ (index >> 4)) & 0x00FF00FF00FF00FF
    index = (index ^ (index >> 8)) & 0x0000FFFF0000FFFF
    index = (index ^ (index >> 16)) & 0x00000000FFFFFFFF
    x = index
    index = (index >> 1) & 0x5555555555555555
    index = (index ^ (index >> 1)) & 0x3333333333333333
    index = (index ^ (index >> 2)) & 0x0F0F0F0F0F0F0F0F
    index = (index ^ (index >> 4)) & 0x00FF00FF00FF00FF
    index = (index ^ (index >> 8)) & 0x0000FFFF0000FFFF
    index = (index ^ (index >> 16)) & 0x00000000FFFFFFFF
    y = index
    index = (index >> 1) & 0x5555555555555555
    index = (index ^ (index >> 1)) & 0x3333333333333333
    index = (index ^ (index >> 2)) & 0x0F0F0F0F0F0F0F0F
    index = (index ^ (index >> 4)) & 0x00FF00FF00FF00FF
    index = (index ^ (index >> 8)) & 0x0000FFFF0000FFFF
    index = (index ^ (index >> 16)) & 0x00000000FFFFFFFF
    z = index
    return x, y, z

def init_delta_tables():
    """Initialize delta lookup tables by computing adjacent Morton index differences [S1, unofficial]."""
    for i in range(256):
        deltaX[i] = morton_encode(i + 1, 0, 0) - morton_encode(i, 0, 0)
        deltaY[i] = morton_encode(0, i + 1, 0) - morton_encode(0, i, 0)
        deltaZ[i] = morton_encode(0, 0, i + 1) - morton_encode(0, 0, i)

def peek_voxel_x_plus_one(current_ptr, x_pos_in_chunk, base_morton_index):
    """Access voxel at (x+1, y, z) relative to current voxel [S1, unofficial]."""
    if x_pos_in_chunk < 255:
        return current_ptr + deltaX[x_pos_in_chunk]
    else:
        # Fallback: decode Morton index to global coordinates, modify, and re-encode [S1, unofficial]
        gx, gy, gz = morton_decode(base_morton_index)
        new_morton = morton_encode(gx + 1, gy, gz)
        return base_ptr_to_index_map(new_morton)  # Standard global lookup mapping [G]

def peek_voxel_all_plus_one(current_ptr, x_pos_in_chunk, y_pos_in_chunk, z_pos_in_chunk, base_morton_index):
    """Access voxel at (x+1, y+1, z+1) relative to current voxel [S1, unofficial]."""
    if x_pos_in_chunk < 255 and y_pos_in_chunk < 255 and z_pos_in_chunk < 255:
        return current_ptr + deltaX[x_pos_in_chunk] + deltaY[y_pos_in_chunk] + deltaZ[z_pos_in_chunk]
    else:
        # Fallback: decode Morton index to global coordinates, modify, and re-encode [S1, unofficial]
        gx, gy, gz = morton_decode(base_morton_index)
        new_morton = morton_encode(gx + 1, gy + 1, gz + 1)
        return base_ptr_to_index_map(new_morton)  # Standard global lookup mapping [G]
```

## Operating characteristics
- **Time Complexity:** $O(1)$ for neighbour access within the same chunk, as it involves only array lookups and addition [S1, unofficial].
- **Memory Complexity:** $O(1)$ extra memory for the three lookup tables (3 * 256 * 4 bytes = 3 KB for `int32_t`) [S1, unofficial].
- **Measured Performance:** Significantly faster than the naive decode-modify-encode approach [S1, unofficial].
- **Scaling:** Supports chunks up to $256^3$ voxels with fixed table size [S1, unofficial].
- **Strengths:** Simple implementation, fast access, no bitwise operations during runtime [S1, unofficial].
- **Limitations:** Requires boundary checks; fallback to global lookup is needed for cross-chunk neighbours [S1, unofficial].

## Background
Originated in the PolyVox project, as described in a blog post by Matt and contributors [S1, unofficial]. The method was developed to efficiently handle voxel data stored in Morton-ordered chunks, addressing the complexity of neighbour access in such a layout [S1, unofficial].
