# Block-level Charting

Also called: Block-based UV Parameterization

## Overview
Block-level charting is a deterministic UV parametrization method for texture compression that generates one 2D chart per occupied 3D block, ensuring UV coordinates can be inferred on the receiver side without transmitting them [S1]. It differs from traditional UV mapping by partitioning the surface into fixed-size blocks matching the geometry compression structure, rather than using few large charts like UVAtlas or one chart per triangle like PTEX [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A reconstructed 3D volume mesh (identical on sender and receiver), block size (fixed), and block occupancy status.
*   **Output:** A global UV atlas and per-vertex UV coordinates relative to that atlas.

**Data Structures:**
*   **Block:** A fixed-size 3D voxel grid cell.
*   **Chart:** A 2D texture region containing projected vertices from one block.
*   **Atlas:** A 2D texture containing all charts.

**Steps:**
1.  **Reconstruction Sync:** Decompress the signal on the sender side so the sender and receiver have identical reconstructed volumes [S1].
2.  **Block Processing:** For each occupied 3D block:
    a. Extract triangles belonging to the block.
    b. Group triangles by their normals. Most blocks have one group; complex areas may have more [S1].
    c. For each group:
        i. Calculate the average normal $\mathbf{n}_{avg}$ of the group.
        ii. Determine a tangent space from $\mathbf{n}_{avg}$.
        iii. Project vertices of the group onto this tangent space.
        iv. Rotate the projections using rotating calipers [63] to fit into an axis-aligned rectangle with minimum area.
        v. Compute the bounding box of the rotated projections.
    d. Sort the bounding boxes of all groups in the block by size.
    e. Pack the bounding boxes into a 2D chart using a quadtree-like algorithm [S1].
    f. Offset vertex UV coordinates to be relative to the chart [S1].
3.  **Atlas Packing:** Pack all block charts into a global atlas. Offset vertex UV coordinates again to be relative to the atlas [S1].

**Pseudocode:**
```python
def block_level_charting(reconstructed_volume, block_size):
    atlas = EmptyAtlas()
    for block in reconstructed_volume.occupied_blocks:
        triangles = extract_triangles(block)
        groups = group_by_normals(triangles)
        chart = EmptyChart()
        
        for group in groups:
            avg_normal = average_normal(group.vertices)
            tangent_space = create_tangent_space(avg_normal)
            projections = project_onto_tangent_space(group.vertices, tangent_space)
            rotated_projections = rotate_to_min_area_rect(projections)
            bbox = compute_bounding_box(rotated_projections)
            chart.add_bbox(bbox)
            
        # Quadtree-like packing happens inside chart.add_bbox or a separate packer
        chart.pack()
        
        # Offset vertices relative to chart
        for vertex in block.vertices:
            vertex.uv = chart.local_uv(vertex)
            
        atlas.add_chart(chart)
        
    # Offset vertices relative to atlas
    for vertex in reconstructed_volume.all_vertices:
        vertex.uv = atlas.global_uv(vertex)
        
    return atlas
```

**Parameters:**
*   Block size: Fixed, determined by geometry compression structure [S1].
*   Rotating calipers: Used for minimum area rectangle fitting [S1].

**Edge Cases:**
*   Complex areas (e.g., fingers) may have multiple normal groups per block [S1].
*   Deterministic process ensures no UV transmission needed [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Deterministic, no UV transmission, matches geometry compression structure, encourages global spatial coherence [S1].
*   **Limitations:** Non-trivial packing due to varying block positions across frames [S1].
*   **When to use:** When combined with block-level geometry compression [S1].

## Background
Originated in "Deep Implicit Volume Compression" (2020) [S1]. It addresses the need for efficient texture compression in dynamic volumes by leveraging the block-based structure of the geometry representation [S1].
