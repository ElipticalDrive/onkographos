# Morton Packing for Texture Atlases

Also called: Morton-based atlas packing, Z-order curve packing

## Overview
Morton Packing is a strategy to pack block-level texture charts into a 2D texture atlas using Morton ordering to maximize spatio-temporal coherence, thereby preserving 3D spatial structure in the 2D layout [S1]. It solves the problem of generating high-quality, compressible texture maps for sparse volume data (e.g., reconstructed TSDF blocks) without the computational cost of tracking features over time or compressing UV coordinates [S1]. Unlike methods that map triangles arbitrarily (sacrificing spatial coherence) or track features for temporal consistency (expensive), this method inherently encourages spatio-temporal coherence by mapping 3D block positions to 2D atlas positions via rank-based Morton codes [S1].

## How it works
**Inputs:** A set of occupied 3D blocks, each identified by integer coordinates $(x, y, z)$ on a regular 3D grid.
**Outputs:** A 2D texture atlas where each block's chart is placed at integer coordinates $(u, v)$.

**Data Structures:**
*   **Block Coordinates:** List of tuples $(x, y, z)$ for all occupied blocks.
*   **3D Morton Code:** A 64-bit integer (or sufficient width) representing the interleaved bits of $x, y, z$.
*   **2D Morton Code:** A 32-bit integer (or sufficient width) representing the interleaved bits of $u, v$.
*   **Sorted List:** A list of 3D Morton codes sorted in ascending order.

**Parameters:**
*   $B$: Number of bits per coordinate dimension. Typical values depend on the resolution of the volume grid.
*   Priority: The bit interleaving order prioritizes the $y$-axis (vertical) over $x$ and $z$ to accommodate standing human figures [S1].

**Steps:**
1.  **Compute 3D Morton Codes:** For each occupied block at $(x, y, z)$, compute its 3D Morton code $M_3(x, y, z)$.
2.  **Sort and Rank:** Create a list of all computed $M_3$ codes. Sort this list in ascending order. Determine the rank of each block's $M_3$ code within this sorted list. Let $rank(M_3(x, y, z))$ be this rank (0-indexed).
3.  **Compute 2D Atlas Position:** Map the rank to a 2D position $(u, v)$ using the inverse 2D Morton function $M_2^{-1}$. The atlas position is $(u, v) = M_2^{-1}(rank(M_3(x, y, z)))$.
4.  **Pack Charts:** Place the texture chart for the block at the computed $(u, v)$ position in the atlas.

**Formulas:**
The 3D Morton code for a block at $(x, y, z)$ is defined as [S1]:
$$ M_3(x, y, z) = \sum_{b=0}^{B-1} (4y_b + 2x_b + z_b)2^{3b} $$
where $x_b, y_b, z_b$ are the $b$-th bits of $x, y, z$ respectively. The binary representation consists of interleaved bits $y_{B-1} x_{B-1} z_{B-1} \dots y_0 x_0 z_0$. Note the priority of $y$ over $x$ and $z$ [S1].

The 2D Morton code for a chart at $(u, v)$ is defined as [S1]:
$$ M_2(u, v) = \sum_{b=0}^{B-1} (2u_b + v_b)2^{2b} $$
where $u_b, v_b$ are the $b$-th bits of $u, v$. The binary representation consists of interleaved bits $u_{B-1} v_{B-1} \dots u_0 v_0$.

The mapping uses the inverse of $M_2$, which is obtained by demultiplexing the bits of the rank into $u$ and $v$ [S1].

**Pseudocode:**
```python
def interleave_bits(x, y, z, num_bits):
    """
    Interleaves bits of x, y, z into a single integer.
    Priority: y, then x, then z.
    Returns the 3D Morton code.
    """
    m3 = 0
    for b in range(num_bits):
        yb = (y >> b) & 1
        xb = (x >> b) & 1
        zb = (z >> b) & 1
        # 4*y + 2*x + z corresponds to bit positions 3b+2, 3b+1, 3b
        m3 |= (yb << (3 * b + 2)) | (xb << (3 * b + 1)) | (zb << (3 * b))
    return m3

def deinterleave_bits(m2, num_bits):
    """
    Demultiplexes bits of a 2D Morton code into u and v.
    Returns tuple (u, v).
    """
    u = 0
    v = 0
    for b in range(num_bits):
        # Bit 2b is u, bit 2b+1 is v
        u |= ((m2 >> (2 * b)) & 1) << b
        v |= ((m2 >> (2 * b + 1)) & 1) << b
    return u, v

def morton_packing(block_coords, num_bits):
    """
    block_coords: List of (x, y, z) tuples for occupied blocks.
    num_bits: Number of bits per coordinate dimension.
    Returns: List of (x, y, z, u, v) tuples.
    """
    # Step 1: Compute 3D Morton Codes
    morton_codes = []
    for x, y, z in block_coords:
        m3 = interleave_bits(x, y, z, num_bits)
        morton_codes.append((m3, x, y, z))
    
    # Step 2: Sort and Rank
    # Sort by Morton code
    morton_codes.sort(key=lambda item: item[0])
    
    # Assign ranks
    ranked_blocks = []
    for rank, (m3, x, y, z) in enumerate(morton_codes):
        # Step 3: Compute 2D Atlas Position
        # The rank is treated as a 2D Morton code index
        u, v = deinterleave_bits(rank, num_bits)
        ranked_blocks.append((x, y, z, u, v))
        
    return ranked_blocks
```

**Edge Cases and Pitfalls:**
*   **Smooth Movement:** The method assumes smooth movement of blocks in 3D space. If blocks move erratically, spatio-temporal coherence in the atlas will be poor [S1].
*   **Coordinate Priority:** Prioritizing the $y$-axis is crucial for standing human figures. Using a different priority (e.g., $x, y, z$) may reduce compression efficacy for typical use cases [S1].
*   **Precision:** Ensure the integer types used for Morton codes have sufficient bit width to avoid overflow for the given resolution $B$ [S1].

## Subtopics

### Block-based UV Parameterization
A fast parametrization method based on block-based charting that generates coherent texture maps for efficient compression using existing video compression algorithms, without tracking or UV coordinate compression [S1]. It generates a Morton packed chart $M_x$ from the mesh extracted using marching cubes on the reconstructed TSDF block [S1]. The chart $M_x$ is then coded separately using texture encoder and decoder blocks [S1]. Unlike methods that track features over time (expensive) or map triangles arbitrarily (Motion2Fusion, sacrifices spatial coherence), this method encourages spatio-temporal coherence without tracking [S1].

## Operating characteristics
*   **Time Complexity:** Dominated by sorting the 3D Morton codes, $O(N \log N)$ where $N$ is the number of occupied blocks. Morton code computation is $O(N \cdot B)$.
*   **Memory Complexity:** $O(N)$ to store the block coordinates and Morton codes.
*   **Strengths:** High spatio-temporal coherence for smooth motion; no need for UV coordinate compression or streaming; compatible with existing video codecs; faster than feature-tracking methods [S1].
*   **Limitations:** Relies on smooth motion assumption; performance degrades with erratic movement; requires block-based representation [S1].
*   **When to Use:** When compressing dynamic 3D scenes (e.g., human avatars) where spatial and temporal coherence is important for video compression, and real-time or low-latency processing is needed [S1].
*   **When Not to Use:** For static scenes where simpler UV mapping suffices, or for scenes with highly erratic motion where coherence is not preserved [S1].

## Background
Morton Packing was proposed as part of a deep 3D compression method for implicit volumes, specifically to complement TSDF compression [S1]. It leverages Morton ordering (Z-order curve), which has been widely used in 3D graphics for spatial representations [S1]. The method was introduced to address the computational intensity of enforcing spatial and temporal consistency in UV parametrization, offering a middle ground between arbitrary mapping and expensive feature tracking [S1].
