# Morton Packing for Texture Atlases

Also called: Morton Packing, Morton-based atlas packing, Z-order curve packing

## Overview
Morton Packing for Texture Atlases is a strategy to pack block-level charts into a 2D atlas using Morton ordering to maximize spatio-temporal coherence [S1]. It solves the problem of efficiently encoding high-quality textures alongside compressed geometry in sparse volume data structures where the set of occupied blocks varies per frame [S1]. Unlike methods that sacrifice spatial coherence for efficiency or require expensive temporal tracking, this approach preserves 3D spatial structure in the 2D atlas by mapping sorted 3D Morton codes to 2D Morton coordinates [S1].

## How it works
**Inputs:**
- A set of occupied 3D blocks, each identified by integer coordinates $(x, y, z)$ on a regular 3D grid [S1].
- The bit-width $B$ for coordinate representation, implied by the summation limits in the Morton code definitions [S1].

**Outputs:**
- A 2D texture atlas where each occupied block is assigned a unique chart at 2D coordinates $(u, v)$ [S1].
- The mapping function that associates each 3D block $(x, y, z)$ to its 2D atlas position $(u, v)$ [S1].

**Data Structures:**
- A list of 3D Morton codes, one for each occupied block [S1].
- A sorted version of this list to determine ranks [S1].

**Formulas:**
The 3D Morton code $M_3(x, y, z)$ for a block at $(x, y, z)$ is defined as [S1]:
$$ M_3(x, y, z) = \sum_{b=0}^{B-1} (4y_b + 2x_b + z_b)2^{3b} $$
where $x_b, y_b, z_b$ are the $b$-th bits of the coordinates $x, y, z$ [S1]. The binary representation of $M_3$ consists of interleaved bits $y_{B-1} x_{B-1} z_{B-1} \dots y_0 x_0 z_0$ [S1]. Note that the $y$-axis is prioritized in the interleaving order (placed in the most significant positions for each triplet) to accommodate standing human figures [S1].

The 2D Morton code $M_2(u, v)$ for a chart at $(u, v)$ is defined as [S1]:
$$ M_2(u, v) = \sum_{b=0}^{B-1} (2u_b + v_b)2^{2b} $$
where $u_b, v_b$ are the $b$-th bits of $u, v$ [S1]. The binary representation is interleaved bits $u_{B-1} v_{B-1} \dots u_0 v_0$ [S1].

**Steps:**
1. For each occupied block at $(x, y, z)$, compute its 3D Morton code $M_3(x, y, z)$ using the bit-interleaving formula above, prioritizing $y$ over $x$ and $z$ [S1].
2. Collect all computed 3D Morton codes into a list [S1].
3. Sort the list of 3D Morton codes in ascending order [S1].
4. For each block, determine its rank in the sorted list. Let $rank(M_3(x, y, z))$ be the index (0-based) of the block's Morton code in the sorted list [S1].
5. Compute the 2D atlas coordinates $(u, v)$ by applying the inverse 2D Morton function to the rank:
   $$ (u, v) = M_2^{-1}(rank(M_3(x, y, z))) $$
   This involves demultiplexing the bits of the rank into $u$ and $v$ [S1].
6. Assign the texture chart for the block at $(x, y, z)$ to the position $(u, v)$ in the 2D atlas [S1].

**Pseudocode:**
```python
def compute_3d_morton(x, y, z, B):
    """
    Compute 3D Morton code prioritizing y-axis.
    Interleaving order: y, x, z.
    """
    code = 0
    for b in range(B):
        xb = (x >> b) & 1
        yb = (y >> b) & 1
        zb = (z >> b) & 1
        # Interleave as ... y_b x_b z_b ...
        # Position in code: 3*b + 2 for y, 3*b + 1 for x, 3*b for z
        code |= (yb << (3 * b + 2))
        code |= (xb << (3 * b + 1))
        code |= (zb << (3 * b))
    return code

def compute_2d_morton(u, v, B):
    """
    Compute 2D Morton code.
    Interleaving order: u, v.
    """
    code = 0
    for b in range(B):
        ub = (u >> b) & 1
        vb = (v >> b) & 1
        # Interleave as ... u_b v_b ...
        code |= (ub << (2 * b + 1))
        code |= (vb << (2 * b))
    return code

def inverse_2d_morton(code, B):
    """
    Inverse of compute_2d_morton.
    Extracts u and v from the Morton code.
    """
    u = 0
    v = 0
    for b in range(B):
        # Extract bits at even and odd positions
        # Bit 2b is v_b, Bit 2b+1 is u_b
        vb = (code >> (2 * b)) & 1
        ub = (code >> (2 * b + 1)) & 1
        u |= (ub << b)
        v |= (vb << b)
    return u, v

def morton_packing(occupied_blocks, B):
    """
    occupied_blocks: list of tuples (x, y, z)
    B: bit-width for coordinates
    Returns: dict mapping (x, y, z) to (u, v)
    """
    # Step 1: Compute 3D Morton codes
    morton_codes = []
    for (x, y, z) in occupied_blocks:
        m3 = compute_3d_morton(x, y, z, B)
        morton_codes.append((m3, (x, y, z)))
    
    # Step 2 & 3: Sort by Morton code
    morton_codes.sort(key=lambda item: item[0])
    
    # Step 4, 5, 6: Map rank to 2D Morton coordinates
    mapping = {}
    for rank, (m3, block) in enumerate(morton_codes):
        u, v = inverse_2d_morton(rank, B)
        mapping[block] = (u, v)
        
    return mapping
```

**Parameters:**
- $B$: Bit-width for coordinate representation. Typical values depend on the resolution of the volume grid. Not given in the sources.
- Coordinate priority: $y$ is prioritized over $x$ and $z$ in the 3D Morton code interleaving [S1].

**Edge cases and pitfalls:**
- If blocks move smoothly in 3D space, corresponding patches move smoothly in the atlas, leading to approximate spatio-temporal coherence and better video compression [S1].
- Prioritizing the $y$-axis accommodates typically standing human figures [S1].
- The method assumes the movement of the subject is smooth to preserve spatio-temporal coherence [S1].

## Subtopics

### [Block-based UV Parameterization](6997-block-based-uv-parameterization.md)
A fast parametrization method based on block-based charting that generates coherent texture maps for efficient compression using existing video compression algorithms, without tracking or UV coordinate compression. It solves the problem of efficiently encoding high-quality textures alongside compressed geometry without the computational overhead of tracking features over time or transmitting UV coordinates. Unlike methods that sacrifice spatial coherence for efficiency or require expensive temporal tracking for consistency, this approach inherently encourages spatio-temporal coherence by deriving UVs deterministically from the local block structure.

## Operating characteristics
- Time and memory complexity are not given in the sources.
- Performance depends on the efficiency of Morton code computation and sorting [S1].
- Strengths include maximizing spatio-temporal coherence for video compression by preserving 3D spatial structure in the 2D atlas [S1].
- Limitations include reliance on smooth block movement to maintain coherence [S1].
- When to use: compressing textures for dynamic sparse volume data where spatio-temporal coherence improves video compression [S1].
- When not to use: when blocks move erratically, as spatial coherence may not translate to temporal coherence [S1].

## Background
The specific strategy of packing block-level charts into a texture atlas using Morton ordering was proposed within the context of deep implicit volume compression [S1]. It builds on Morton ordering (Z-order curve), which has been widely used in 3D graphics to create spatial representations [S1]. The application to texture atlas packing for block-level charts in sparse volume data structures was introduced to optimize compression by maximizing spatio-temporal coherence [S1].
