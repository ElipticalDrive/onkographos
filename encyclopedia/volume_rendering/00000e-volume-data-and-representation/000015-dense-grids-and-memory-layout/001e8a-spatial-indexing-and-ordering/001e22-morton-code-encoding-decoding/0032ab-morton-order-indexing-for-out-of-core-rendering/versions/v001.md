# Morton Order Indexing for Out-of-Core Rendering

Also called: Morton indexing, Z-order curve traversal

## Overview
Morton Order Indexing for Out-of-Core Rendering is a data organization scheme that sorts voxel indices based on spatial locality using a recursive Z-shaped curve traversal, reducing disk seek operations by storing similar color/function values contiguously [S1, unofficial]. It differs from standard Morton Code Encoding by integrating the spatial index with a histogram-based look-up table to manage variable-sized voxelsets on disk, enabling efficient out-of-core retrieval [S1, unofficial].

## How it works
**Inputs:**
- A 3D grid of voxels with dimensions $2^n \times 2^n \times 2^n$ [S1, unofficial].
- Voxel data including position (3x 4-byte values) and normalized gradient (3 bytes) [S1, unofficial].
- Background images used to identify noise colors [S1, unofficial].

**Outputs:**
- A disk file containing voxelsets stored in Morton order.
- A look-up table $l$ mapping Morton indices to file offsets [S1, unofficial].

**Data Structures:**
- **Histogram $h$:** An array where $h(r,g,b)$ stores the number of occurrences (voxels) for a specific color/value $(r,g,b)$ [S1, unofficial].
- **Look-up Table $l$:** Stores starting offsets $s_V$ for each voxelset $V$ [S1, unofficial].

**Steps:**

1.  **Morton Index Calculation:** Compute the Morton index $M(r,g,b)$ for each voxel's color/value using bit-interleaving of its coordinates or value components [S1, unofficial].
2.  **Histogram Generation (Pass 1):** Iterate through all voxels. For each voxel, increment the histogram entry corresponding to its color/value: $h(r,g,b) \leftarrow h(r,g,b) + 1$ [S1, unofficial].
3.  **Noise Cleaning:** Identify colors present in the background images. Set $h(r,g,b) = 0$ for all such colors to exclude background noise from storage [S1, unofficial].
4.  **Look-up Table Construction:** Calculate the starting offset $s_V$ for each unique Morton index $M$ using the cumulative sum of the histogram:
    $$ s_V = \sum_{i=0}^{M(r,g,b)-1} h(M^{-1}(i)) $$
    where $M^{-1}(i)$ is the inverse Morton index mapping the integer $i$ back to the color/value tuple, and $h$ is the cleaned histogram [S1, unofficial]. Store these offsets in the look-up table $l$ [S1, unofficial].
5.  **Data Encoding (Pass 2):** Iterate through the voxels in Morton order (sorted by $M(r,g,b)$). For each voxel, write its data (position and gradient) to the disk file at the offset $s_V$ retrieved from the look-up table $l$ [S1, unofficial]. Increment the offset for the next voxel of the same color/value if necessary, or manage offsets per voxelset [S1, unofficial].
6.  **Data Retrieval:** To render, calculate the Morton index for selected colors. Sort these indices in ascending order. Access the file consecutively using the offsets in $l$ [S1, unofficial].

**Pseudocode:**

```python
def morton_index(x, y, z):
    """Interleave bits of x, y, z to form a Morton code."""
    # Implementation details of bit interleaving are assumed from Morton Code Encoding
    # [G] Standard bit interleaving algorithm
    code = 0
    for i in range(16): # Assuming 16-bit coordinates
        code |= (x & (1 << i)) << (2 * i)
        code |= (y & (1 << i)) << (2 * i + 1)
        code |= (z & (1 << i)) << (2 * i + 2)
    return code

def preprocess_voxels(voxels, background_colors):
    """
    Pass 1: Generate histogram and clean noise.
    Pass 2: Build look-up table and write to disk.
    """
    # Step 1: Histogram Generation
    histogram = {} # Maps (r,g,b) -> count
    
    for voxel in voxels:
        color = voxel.color
        if color not in histogram:
            histogram[color] = 0
        histogram[color] += 1
        
    # Step 2: Noise Cleaning
    for bg_color in background_colors:
        if bg_color in histogram:
            histogram[bg_color] = 0
            
    # Step 3: Look-up Table Construction
    # Sort unique colors by their Morton index
    unique_colors = list(histogram.keys())
    unique_colors.sort(key=lambda c: morton_index(*c))
    
    look_up_table = {} # Maps Morton_index -> start_offset
    current_offset = 0
    
    for color in unique_colors:
        m_index = morton_index(*color)
        look_up_table[m_index] = current_offset
        # The size of the voxelset is the count in the histogram
        # Note: The formula in source sums occurrences, implying contiguous storage
        # of all voxels of that color.
        voxel_size = 15 # 12 bytes position + 3 bytes normal [S1, unofficial]
        count = histogram[color]
        current_offset += count * voxel_size
        
    return look_up_table

def write_voxelset_to_disk(voxels, look_up_table, output_file):
    """
    Pass 2: Write data to disk in Morton order.
    """
    # Sort voxels by Morton index of their color
    sorted_voxels = sorted(voxels, key=lambda v: morton_index(*v.color))
    
    # Group voxels by color to write contiguous blocks
    # [G] Grouping logic to match the "voxelset" concept
    from itertools import groupby
    
    for color, group in groupby(sorted_voxels, key=lambda v: v.color):
        m_index = morton_index(*color)
        start_offset = look_up_table[m_index]
        
        # Write all voxels of this color to the calculated offset
        for voxel in group:
            output_file.seek(start_offset)
            output_file.write(voxel.encode()) # 15 bytes per voxel
            start_offset += 15 # Increment for next voxel in set

def retrieve_voxelset(selected_colors, look_up_table, input_file):
    """
    Retrieve voxelsets for rendering.
    """
    # Calculate Morton indices and sort
    indices = [morton_index(*c) for c in selected_colors]
    indices.sort()
    
    data = []
    for m_index in indices:
        if m_index in look_up_table:
            offset = look_up_table[m_index]
            input_file.seek(offset)
            # Read the voxelset (size determined by histogram count)
            # [G] Need count from histogram or store it in LUT
            # Assuming we read until next offset or stored count
            voxelset = input_file.read(15 * histogram[selected_colors[0]]) # Placeholder for actual count retrieval
            data.append(voxelset)
    return data
```

**Parameters:**
- Voxel data size: 15 bytes per voxel (12 bytes position, 3 bytes normal) [S1, unofficial].
- Grid dimensions: $2^n \times 2^n \times 2^n$ [S1, unofficial].

**Edge Cases:**
- Background noise: Must be cleaned from the histogram to avoid storing unnecessary data [S1, unofficial].
- Degenerate input: If a color has zero occurrences after cleaning, it is excluded [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Pre-processing requires $O(N)$ to build the histogram and $O(N \log N)$ or $O(N)$ to sort voxels by Morton index, where $N$ is the number of voxels [S1, unofficial]. Retrieval is $O(K \log K)$ for sorting $K$ selected colors, followed by $O(1)$ seek per voxelset [S1, unofficial].
- **Memory Complexity:** Requires storing the histogram and look-up table in memory. The size depends on the number of unique colors/values [S1, unofficial].
- **Performance:** Reduces disk seek operations by accessing datasets consecutively, allowing real-time reading from disk [S1, unofficial].
- **Strengths:** Exploits spatial locality for similar colors; reduces unnecessary disk rotations [S1, unofficial].
- **Limitations:** Requires two-pass pre-processing; variable-sized voxelsets require careful offset management [S1, unofficial].

## Background
This method was proposed in "Interactive Visualization of Very Large Datasets Using an Out-of-Core Point-based Approach" [S1, unofficial]. It addresses the challenge of rendering large volumetric datasets that do not fit in main memory by organizing data on disk to minimize I/O latency.
