# Octree Construction via Morton Codes

Also called: Morton-based Octree Building

## Overview
This method constructs a sparse octree from a list of active level-0 nodes sorted by Morton code in a bottom-up, breadth-first manner [S1]. It links hierarchical parent-child relationships and establishes x-neighbor pointers without requiring global sorting or complex tree traversal algorithms [S1]. It differs from Zhou et al. [2010] by storing volumetric payload rather than point clouds and maintaining only x-neighbor adjacency instead of all 26 neighbors [S1].

## How it works
**Inputs:** A list of active level-0 nodes (`ActNodes1`), sorted by Morton code [S1].
**Outputs:** A fully linked octree structure with parent-child pointers and x-neighbor pointers up to a specified top level $n$ [S1].

**Data Structures:**
*   `ActNodes1`: Array of active nodes at the current level, each containing a `morton_code` (integer) and `payload` [S1].
*   `Nodes0`: Array of child nodes allocated for the current level. Size is $8 \times \text{length}(ActNodes1)$ [S1].
*   `Flag1`: Boolean buffer of size $\text{length}(ActNodes1)$ [S1].
*   `ParentIndex1`: Integer buffer of size $\text{length}(ActNodes1)$, result of an exclusive scan on `Flag1` [S1].
*   `Nodes1`: Array of parent nodes at the next level up. Size is $8 \times N_{a2}$, where $N_{a2}$ is the number of active nodes at the next level [S1].

**Algorithm Steps:**

1.  **Initialize Level 0 Children:** Allocate `Nodes0` with size $8 \times \text{length}(ActNodes1)$ and initialize it. Set x-neighbor pointers between adjacent nodes within `Nodes0` that share the same parent [S1].
2.  **Determine Parent Boundaries:** For each index $i$ from $0$ to $\text{length}(ActNodes1) - 2$, check if `ActNodes1[i+1]` has a different level-2 parent than `ActNodes1[i]` by comparing the higher-order bits of their Morton codes. Write `1` to `Flag1[i]` if the parent is different, `0` otherwise. Set `Flag1[last] = 1` to mark the final boundary [S1].
3.  **Compute Parent Indices:** Perform an exclusive scan on `Flag1` to yield `ParentIndex1`. The last entry of `ParentIndex1` plus one equals $N_{a2}$, the number of active nodes at the next level [S1].
4.  **Allocate Level 1 Parents:** Allocate and initialize `Nodes1` with size $8 \times N_{a2}$ [S1].
5.  **Link Children to Parents:** For each index $i$ in `ActNodes1`, calculate the index $j$ in `Nodes1` as $j = 8 \times \text{ParentIndex1}[i] + (\text{ActNodes1}[i] \pmod 8)$. Set the parent pointer of `Nodes0[8 \times i]` (the first child of the $i$-th active node) to `Nodes1[j]`, and establish child pointers in `Nodes1[j]` pointing to the 8 children in `Nodes0` starting at index $8 \times i$ [S1].
6.  **Derive Next Level Active List:** Create `ActNodes2` from `ActNodes1` by stripping the three least significant bits from each Morton code and performing compaction using `Flag1` and `ParentIndex1` to retain only unique parent codes [S1].
7.  **Iterate Upwards:** Process `ActNodes2` analogously to `ActNodes1` to establish level-2 nodes [S1].
8.  **Termination Condition:** Repeat the process for remaining levels, stopping two levels below the root node where the tree becomes dense enough that all nodes at the top level $n$ are created explicitly [S1].
9.  **Finalize Top Level:** Create all nodes at level $n$ and establish x-neighbor pointers for all adjacent nodes at this level [S1].
10. **Propagate X-Neighbor Pointers:** Starting from level $n$ down to level 1, propagate x-neighbor pointers from nodes in level $i$ to their child nodes in level $i-1$, linking adjacent level-$(i-1)$ nodes that have different parent nodes [S1].

**Pseudocode:**

```python
def construct_octree(ActNodes1):
    # ActNodes1: list of dicts with 'morton_code' and 'payload', sorted by morton_code
    current_act_nodes = ActNodes1
    level_nodes = []  # Stores Nodes0, Nodes1, etc.
    
    while True:
        num_active = len(current_act_nodes)
        if num_active == 0:
            break
            
        # Step 1: Allocate children (Nodes0)
        nodes0 = [None] * (8 * num_active)
        for i in range(num_active):
            base = 8 * i
            for k in range(8):
                nodes0[base + k] = {'morton_code': current_act_nodes[i]['morton_code'] | k, 'payload': None}
            # Set x-neighbor pointers between adjacent nodes with same parent
            for k in range(0, 8, 2):
                nodes0[base + k]['x_neighbor'] = nodes0[base + k + 1]
                nodes0[base + k + 1]['x_neighbor'] = nodes0[base + k]
        level_nodes.append(nodes0)
        
        # Step 2: Determine parent boundaries
        flag1 = [0] * num_active
        for i in range(num_active - 1):
            if (current_act_nodes[i]['morton_code'] >> 3) != (current_act_nodes[i+1]['morton_code'] >> 3):
                flag1[i] = 1
        flag1[num_active - 1] = 1
        
        # Step 3: Exclusive scan
        parent_index1 = exclusive_scan(flag1)
        num_active_next = parent_index1[num_active - 1] + 1
        
        # Step 4: Allocate parents (Nodes1)
        nodes1 = [None] * (8 * num_active_next)
        
        # Step 5: Link children to parents
        for i in range(num_active):
            base = 8 * i
            j = 8 * parent_index1[i] + (current_act_nodes[i]['morton_code'] % 8)
            nodes1[j] = {'morton_code': current_act_nodes[i]['morton_code'] >> 3, 'payload': None}
            nodes1[j]['children'] = nodes0[base : base + 8]
            nodes0[base]['parent'] = nodes1[j]
            
        # Step 6: Derive next level active list (compaction using Flag1)
        act_nodes_next = []
        for i in range(num_active):
            if flag1[i] == 1:
                act_nodes_next.append({
                    'morton_code': current_act_nodes[i]['morton_code'] >> 3,
                    'payload': None
                })
                
        current_act_nodes = act_nodes_next
        
        # Step 8: Termination check (stop two levels below root)
        if len(current_act_nodes) <= 1:
            break
            
    # Step 9 & 10: Finalize top level and propagate x-neighbors
    # If loop terminated early, create remaining levels explicitly
    # Propagate x-neighbor pointers from level i to i-1
    for l in range(len(level_nodes) - 1, 0, -1):
        nodes_upper = level_nodes[l]
        nodes_lower = level_nodes[l-1]
        propagate_x_neighbors(nodes_upper, nodes_lower)
        
    return level_nodes

def exclusive_scan(arr):
    result = [0] * len(arr)
    for i in range(1, len(arr)):
        result[i] = result[i-1] + arr[i-1]
    return result

def propagate_x_neighbors(nodes_upper, nodes_lower):
    # Propagate from parent to children, then link adjacent lower nodes with different parents
    for i in range(len(nodes_upper)):
        parent = nodes_upper[i]
        children = parent['children']
        # Propagate parent's x-neighbor to children (simplified: link leftmost to rightmost of neighbor's children)
        if 'x_neighbor' in parent and parent['x_neighbor'] is not None:
            neighbor = parent['x_neighbor']
            neighbor_children = neighbor['children']
            children[0]['x_neighbor'] = neighbor_children[7]
            neighbor_children[7]['x_neighbor'] = children[0]
            children[1]['x_neighbor'] = neighbor_children[6]
            neighbor_children[6]['x_neighbor'] = children[1]
            children[2]['x_neighbor'] = neighbor_children[5]
            neighbor_children[5]['x_neighbor'] = children[2]
            children[3]['x_neighbor'] = neighbor_children[4]
            neighbor_children[4]['x_neighbor'] = children[3]
            
    # Link adjacent level-(i-1) nodes with different parent nodes
    for i in range(len(nodes_lower) - 1):
        curr = nodes_lower[i]
        next_node = nodes_lower[i+1]
        if curr['parent'] is not next_node['parent']:
            curr['x_neighbor'] = next_node
            next_node['x_neighbor'] = curr
```

## Subtopics

### Parallel Tree Construction using Morton Codes
An efficient parallel tree construction algorithm for spatial data suited for GPU, utilizing spatially coherent properties of Morton codes to construct all nodes simultaneously [S2, unofficial]. Morton codes describe the path to take through an octree to reach a leaf. Each interior node calculates the split position of all its children in-place based on the depth of the first difference in the bit representations of the Morton codes. All interior nodes are processed independently and simultaneously [S2, unofficial]. Requires a complete set of leaf nodes to be in sorted order of their Morton codes. Not applicable for constructing new spatial data where the next level depends on preceding level properties, as interior nodes can no longer be evaluated independently [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of active nodes per level, dominated by the exclusive scan and pointer assignment steps [G].
*   **Memory Complexity:** $O(N)$ for storing tree nodes and temporary buffers (`Flag1`, `ParentIndex1`) proportional to active nodes at each level [G].
*   **Strengths:** Efficient parallelization potential on GPUs; avoids complex tree balancing or recursive descent [S1, G].
*   **Limitations:** Requires pre-sorted Morton codes; maintains only x-neighbor adjacency, which may be insufficient for algorithms requiring full 26-neighbor connectivity [S1, G].
*   **When to use:** Constructing sparse octrees from voxelized data or point clouds where x-neighbor traversal is sufficient [S1, G].
*   **When not to use:** When full spatial adjacency is required or when dynamically generating spatial data where tree levels depend on preceding level properties [S2, G, unofficial].

## Background
This method was described in the context of fast parallel surface and solid voxelization on GPUs [S1]. It shares similarities with the approach by Zhou et al. [2010], proceeding bottom-up in a breadth-first fashion using Morton ordering [S1]. The main differences are in the stored payload (volumetric vs. point cloud) and the adjacency information maintained (x-neighbor vs. all 26 neighbors) [S1]. Parallel variants exploit the spatial coherence of Morton codes to construct all interior nodes simultaneously by calculating split positions based on the depth of the first difference in bit representations [S2, unofficial].
