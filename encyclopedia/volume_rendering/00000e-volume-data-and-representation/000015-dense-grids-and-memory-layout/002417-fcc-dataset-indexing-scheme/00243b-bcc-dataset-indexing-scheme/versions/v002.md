# BCC Dataset Indexing Scheme

Also called: BCC to 2-channel 3D texture mapping

## Overview
The BCC Dataset Indexing Scheme stores a Body-Centered Cubic (BCC) volume dataset in a standard two-channel 3D texture to enable hardware-accelerated raycasting without custom memory layouts [S1]. It maps non-Cartesian BCC lattice points to a Cartesian texture grid using bitwise operations [S1].

## How it works
**Inputs:** A BCC dataset defined on a grid with coordinates $(j_x, j_y, j_z)$, and a 3D texture `texid` with two channels [S1].
**Outputs:** The value of the BCC voxel at index $(j_x, j_y, j_z)$ retrieved from the texture [S1].

**Data Structures:**
The BCC lattice points are mapped to a Cartesian grid and packed into a 3D texture with two channels [S1].

**Access Pattern:**
The core operation is a bitwise mapping from the BCC coordinate $(j_x, j_y, j_z)$ to the texture coordinates $(u, v, w)$ and channel index $c$ [S1].
1. Compute the texture coordinates by right-shifting the BCC coordinates by 1:
   $$ u = j_x \gg 1 $$
   $$ v = j_y \gg 1 $$
   $$ w = j_z \gg 1 $$
2. Determine the channel index $c$ based on the least significant bit of $j_x$:
   $$ c = j_x \& 1 $$
   The source specifies the access pattern as `texelFetch(texid, j.x >> 1, j.y >> 1, j.z >> 1)[x & 1]` [S1], where $u, v, w$ are the texture coordinates, $c$ is the channel index, and $x$ refers to $j_x$.

**Pseudocode:**
```python
def get_bcc_value(tex, jx, jy, jz):
    """
    Retrieves the value of a BCC voxel at integer coordinates (jx, jy, jz).
    tex: A 3D array of shape (W, H, D) where each element is a 2-element list/array.
    jx, jy, jz: Integer coordinates of the BCC lattice point.
    Returns: The scalar value stored in the texture.
    """
    # Map BCC coordinates to texture coordinates using bitwise right shift
    u = jx >> 1
    v = jy >> 1
    w = jz >> 1
    
    # Determine channel index based on the least significant bit of jx
    channel_index = jx & 1
    
    # Fetch the texel and return the value from the selected channel
    texel = tex[u][v][w]
    return texel[channel_index]
```

**Parameters:**
- Texture channels: 2 [S1].
- Bitwise operations: Supported in GLSL 1.30 and later [S1].

**Edge Cases and Pitfalls:**
- **Negative Coordinates:** The behavior of bitwise right shift and AND operators for negative integers depends on the language and hardware representation [G]. The source assumes positive indices or two's complement behavior consistent with GLSL [S1].
- **Boundary Conditions:** Texture dimensions must be sufficient to hold the mapped coordinates. Not given in the sources.

## Subtopics

### BCC Grid Extension for 4D
An extension of BCC grids for 4D volume rendering by Neophytou and Mueller [S2, unofficial]. It uses a 3D hyperslicer to extract 3D volumes from the 4D dataset for shaded and semi-transparent visualization, followed by occlusion ordering on the extracted volumes [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Memory: Uses 2 channels per voxel in the texture [S1].
- Time: Access is $O(1)$ using bitwise operations [S1].

**Strengths and Limitations:**
- **Strengths:** Efficient hardware support via standard 3D textures; fast bitwise indexing [S1].
- **Limitations:** Requires coordinate mapping to a 2-channel texture; limited to 2 channels of data per voxel in this scheme [S1].

**When to Use:**
Use when rendering BCC datasets and efficient hardware texture access is required [S1].

## Background
The scheme is described in the context of GPU isosurface raycasting of FCC and BCC datasets [S1]. It leverages the efficiency of bitwise operations available in GLSL 1.30+ to map non-Cartesian grids to Cartesian textures [S1]. The BCC extension for 4D rendering was introduced by Neophytou and Mueller [S2, unofficial].
