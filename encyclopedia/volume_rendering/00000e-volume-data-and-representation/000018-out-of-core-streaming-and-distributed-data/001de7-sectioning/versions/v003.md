# Sectioning
Also called: Section Memory, External FIFO, VolumePro Sectioning

## Overview
Sectioning partitions a volume dataset into smaller segments to constrain the on-chip memory usage of First-In-First-Out (FIFO) buffers within hardware pipelines [S1, unofficial]. It solves the problem of limited on-chip storage for intermediate values required for ray-casting by off-loading these values to external memory between processing sections [S1, unofficial]. Unlike sibling methods that focus on network distribution or bandwidth scheduling, Sectioning manages data recirculation within a single rendering pass to maintain exact numerical precision without approximation [S1, unofficial][G].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume dataset partitioned into sections along the x-direction [S1, unofficial].
*   **Output:** A rendered image identical to a non-sectioned render, with no visual artifacts at section boundaries [S1, unofficial].

**Data Structures:**
*   **Section Memory:** An external memory block acting as a large FIFO [S1, unofficial]. It stores intermediate values (accumulated color and opacity) that would normally be passed between pipeline stages [S1, unofficial].
    *   **Layout:** The memory organization corresponds to the width of a section. In the VolumePro implementation, each section is 32 voxels wide [S1, unofficial].
    *   **Content:** Intermediate values needed for rendering near the right boundary of a section [S1, unofficial].

**Numbered Steps:**
1.  **Partitioning:** The volume dataset is partitioned into sections. In the VolumePro implementation, this is done only in the x-direction, with each section being 32 voxels wide [S1, unofficial].
2.  **Traversal Order Modification:** Voxels are read in slice-by-slice order within a single section [S1, unofficial]. Within slices, voxels are read in beam-by-beam order, but beams span only the width of the current section (32 voxels) [S1, unofficial].
3.  **Section Processing (Right-Hand Pipeline):** The full section is processed front-to-back [S1, unofficial]. Shift registers in the right-hand pipeline are modified to optionally write intermediate values to Section Memory at the end of a section [S1, unofficial]. These values are the ones that would have been passed to the next pipeline stage in a continuous stream [S1, unofficial].
4.  **Section Boundary Handling:** At the start of a new section, the left-hand pipeline reads values from Section Memory [S1, unofficial]. If not reading from Section Memory (e.g., first section), it accepts values from the right-hand pipeline [S1, unofficial]. Values are passed through multiplexers to the left pipeline [S1, unofficial].
5.  **Recirculation:** Values are read from Section Memory in the exact same order they were written [S1, unofficial]. This ensures that the left-hand pipeline receives the same data it would have received if the sections were processed as one continuous block [S1, unofficial].
6.  **Iteration:** The next section is processed, repeating steps 2-5 until the entire volume is rendered [S1, unofficial].

**Formulas:**
*   Let $V$ be the volume dataset.
*   Let $W$ be the section width in voxels ($W=32$ in VolumePro) [S1, unofficial].
*   Let $(C, \alpha)$ be the accumulated color and opacity state passed between pipeline stages [S1, unofficial].
*   Let $S_{mem}$ be the Section Memory buffer [S1, unofficial].
*   At the end of section $s_i$, the right-hand pipeline writes $(C, \alpha)$ to $S_{mem}$ [S1, unofficial].
*   At the beginning of section $s_{i+1}$, the left-hand pipeline reads $(C, \alpha)$ from $S_{mem}$ [S1, unofficial].
*   Correctness condition: The state read by the left pipeline equals the state written by the right pipeline of the previous section, ensuring $I_{left}(s_{i+1}) = I_{right}(s_i)$ with no approximation [S1, unofficial].

**Parameters:**
*   **Section Width:** 32 voxels (VolumePro specific) [S1, unofficial].
*   **Direction:** X-direction (VolumePro specific; theoretically possible in y- and/or z-directions) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** No approximation is made; the method guarantees no visual artifacts at section boundaries because the exact same values are written and read [S1, unofficial].
*   **Memory Organization:** The section width must align with the underlying memory organization (e.g., 32 voxels for VolumePro) [S1, unofficial].
*   **Ordering:** The read order from Section Memory must exactly match the write order to ensure correct pipeline state [S1, unofficial].

**Pseudocode:**
```python
def sectioned_volume_render(volume, section_width=32):
    """
    Simulates the VolumePro sectioning pipeline.
    Traversal: sections in x, then x within section, then y (beam), then z (front-to-back).
    State: accumulated color (C) and opacity (alpha).
    """
    X, Y, Z = volume.shape
    # Initialize pipeline state [G]
    acc_color = [0.0, 0.0, 0.0]
    acc_alpha = 0.0
    section_memory = None

    for sec_start in range(0, X, section_width):
        sec_end = min(sec_start + section_width, X)

        # At start of section, left pipeline reads from Section Memory if available [S1, unofficial]
        if section_memory is not None:
            acc_color, acc_alpha = section_memory

        for x in range(sec_start, sec_end):
            for y in range(Y):
                for z in range(Z):
                    # Sample volume and update state using standard over-attenuation compositing [G]
                    sample_color, sample_alpha = volume[x, y, z]
                    alpha_contribution = (1.0 - acc_alpha) * sample_alpha
                    acc_color[0] += alpha_contribution * sample_color
                    acc_color[1] += alpha_contribution * sample_color
                    acc_color[2] += alpha_contribution * sample_color
                    acc_alpha += alpha_contribution

                # Right-hand pipeline shift registers hold current state [S1, unofficial]
                current_state = (acc_color.copy(), acc_alpha)

            # At end of section, write state to Section Memory [S1, unofficial]
            if x == sec_end - 1:
                section_memory = current_state

    return acc_color, acc_alpha
```

## Operating characteristics
*   **Time Complexity:** No additional computational complexity; the same values are calculated, just in a different order [S1, unofficial].
*   **Memory Complexity:** Reduces on-chip FIFO memory requirements by off-loading intermediate values to external memory [S1, unofficial].
*   **Measured Performance:** Implemented in VolumePro with 32-voxel sections [S1, unofficial].
*   **Strengths:** Exact numerical precision; no visual artifacts at section boundaries [S1, unofficial].
*   **Limitations:** Requires external memory access; limited to x-direction in VolumePro [S1, unofficial].
*   **When to use:** When on-chip FIFO memory is insufficient for the full volume width [S1, unofficial].
*   **When not to use:** When external memory bandwidth is a bottleneck or when hardware supports sufficient on-chip memory [S1, unofficial].

## Background
Sectioning was introduced in the VolumePro real-time ray-casting system [S1, unofficial]. It was developed to address the limitations of semiconductor processes regarding on-chip memory size [S1, unofficial]. The method is detailed in the VolumePro technical report [S1, unofficial].
