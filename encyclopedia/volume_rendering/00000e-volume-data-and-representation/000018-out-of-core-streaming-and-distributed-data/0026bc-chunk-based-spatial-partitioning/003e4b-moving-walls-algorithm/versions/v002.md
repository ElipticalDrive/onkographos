# Moving Walls Algorithm


## Overview
The Moving Walls Algorithm partitions a volume dataset into cells containing closely cropped blocks of data, optimizing for a target memory size and a specific viewpoint [S1, unofficial]. It differs from static chunking by using a kd-tree space partition driven by tightly cropped subvolumes to follow natural volume boundaries, and employs dynamic programming to solve a relaxed version of the Load-Balanced Node Distribution (LBND) problem [S1, unofficial].

## How it works
**Inputs:**
1. Raw volume data (e.g., slices).
2. A mask volume defining regions of interest.
3. Target memory size per cell.
4. Viewpoint information (for view-dependent optimization).

**Outputs:**
1. A flex-block partition (view-independent cells containing empty space and cropped subvolumes).
2. A kd-tree structure extracted from the partition.
3. A dependency graph (look-up table) of flex-blocks for ray-task scheduling.

**Data Structures:**
- **Flex-block:** A cell in the partition containing one or more cropped data blocks.
- **kd-tree:** A spatial partitioning tree where each node represents a cell.
- **Dependency Graph:** A look-up table mapping view directions to an ordered list of flex-blocks, representing the priority order for ray traversal.

**Steps:**
1. **Cropping:** Crop slices to one or more bounding rectangles of regions of interest using the mask volume. Store cropped slices on disk [S1, unofficial].
2. **Partitioning:** Use the bounding rectangle parameters of cropped slices as input to the Moving Walls algorithm. Partition the scene into cells such that the total size of each group of data blocks is closely matched to the target memory size [S1, unofficial].
3. **Dynamic Programming (Optional Variant):** Apply dynamic programming to slab-projection slices to find a solution to a relaxed LBND problem, creating a flex-block partition [S1, unofficial].
4. **kd-tree Extraction:** Extract the kd-tree from the output of the moving walls procedure [S1, unofficial].
5. **Dependency Graph Generation:** For each of eight quantized view directions, extract the image priority order from the kd-tree. Store this as a look-up table representing the dependency graph of flex-blocks [S1, unofficial].
6. **Distribution:** Distribute flex-block parameters (including the dependency graph) and cropped slices across the cluster [S1, unofficial].

**Pseudocode:**
```python
def moving_walls_algorithm(raw_data, mask, target_memory, viewpoint):
    # Step 1: Crop slices based on mask
    cropped_slices = crop_slices(raw_data, mask)
    
    # Step 2: Partition scene into cells
    # The algorithm uses bounding rectangle parameters of cropped slices
    # to partition the scene into cells matching target_memory
    cells = partition_scene(cropped_slices, target_memory, viewpoint)
    
    # Step 3: Extract kd-tree
    kd_tree = extract_kd_tree(cells)
    
    # Step 4: Generate dependency graph
    # Quantize view directions into 8 directions
    view_directions = get_quantized_view_directions(8)
    dependency_graph = {}
    
    for direction in view_directions:
        # Extract priority order of flex-blocks for this direction
        priority_order = get_priority_order(kd_tree, direction)
        dependency_graph[direction] = priority_order
        
    return cells, kd_tree, dependency_graph
```

**Edge Cases:**
- The depth of the search tree is limited to prevent intractability, which limits the size of data bricks relative to the whole dataset [S1, unofficial].
- Blocks are never created until the end of preprocessing to avoid memory restrictions on volume block sizes [S1, unofficial].

## Subtopics

### Moving Walls DP
A dynamic programming algorithm that finds a solution to a relaxed version of the LBND problem [S1, unofficial]. It applies dynamic programming to slab-projection slices to create a flex-block partition, which is a view-independent partition of cells containing a combination of empty space and cropped subvolumes [S1, unofficial]. This variant gives the user control over the tradeoff between distribution quality and algorithm run time [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The dynamic programming approach allows user control over the tradeoff between distribution quality and algorithm run time [S1, unofficial]. The search tree depth is limited to prevent intractability [S1, unofficial].
- **Memory:** The total size of each group of data blocks is closely matched to the target memory size [S1, unofficial].
- **Strengths:** Scene partitioning is driven by tightly cropped subvolumes, allowing volume boundaries to be followed in a natural manner [S1, unofficial]. It supports dynamic task scheduling via a dependency graph [S1, unofficial].
- **Limitations:** The partition is optimized with respect to a single viewpoint in the base algorithm [S1, unofficial].

## Background
The Moving Walls Algorithm was introduced in the context of massive data management for distributed volume visualization [S1, unofficial]. It is used in conjunction with cell-tree peeling algorithms for efficient cell-processing schedules [S1, unofficial]. The algorithm is part of a broader framework that includes dependency graph acceleration and dynamic task scheduling for distributed ray tracing [S1, unofficial].
