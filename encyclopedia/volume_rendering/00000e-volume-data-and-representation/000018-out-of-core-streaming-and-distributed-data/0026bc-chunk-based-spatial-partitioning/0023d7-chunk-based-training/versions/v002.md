# Chunk-based Training

Also called: Parallel chunk-based training

## Overview
Chunk-based Training is a distributed optimization strategy for training large-scale neural volume representations, where the input volume is partitioned into spatial chunks to enable parallel processing across multiple GPUs [S1, unofficial]. It differs from single-GPU training by scaling the coordinate space and training units according to the number of chunks, allowing datasets like Hemibrain to be trained on 4–5 GPUs instead of a single device [S1, unofficial].

## How it works
**Inputs:** Large-scale 3D volume dataset; number of chunks $n_{chunk}$.
**Outputs:** Trained neural volume model parameters.

**Data Structures:**
The volume is represented in a normalized coordinate space. For large volumes, the global coordinate space $[-1, 1]^3$ is subdivided into $n_{chunk}$ sub-spaces. Each chunk $i$ occupies a specific region within this scaled space.

**Steps:**
1.  **Coordinate Space Scaling:** Determine the bounding box for each chunk. If the full volume is optimized in $[-1, 1]^3$, the space for $n_{chunk}$ chunks is scaled such that each chunk covers a sub-region. For example:
    *   $n_{chunk} = 8$: Each chunk covers a region of size $1.0$ in each dimension (e.g., $[-0.5, 0.5]^3$ for the central chunk, or partitioned octants).
    *   $n_{chunk} = 64$: Each chunk covers a region of size $0.5$ in each dimension (e.g., $[-0.25, 0.25]^3$).
    *   $n_{chunk} = 125$: Each chunk covers a region of size $0.4$ in each dimension (e.g., $[-0.2, 0.2]^3$) [S1, unofficial].
2.  **Chunk Assignment:** Assign each chunk to a distinct GPU. The number of GPUs used matches $n_{chunk}$ or is a divisor thereof if multiple chunks are processed per GPU [S1, unofficial].
3.  **Subvolume Partitioning:** Within each training unit (chunk or full volume), partition the data into voxelized cubic subvolumes for optimization [S1, unofficial].
4.  **Parallel Optimization:** Each GPU optimizes its assigned chunk(s) independently using the subvolume partitioning. The subvolume side length is set to approximately half the longest axis of the training unit. For flat volumes (e.g., Neuron), the smallest axis is used instead [S1, unofficial].

**Parameters:**
*   $n_{chunk}$: Number of chunks. Typical values: 8 (BigBrain, Woodbranch), 64 (Hemibrain vDeltaA), 125 (Hemibrain lLN2P) [S1, unofficial].
*   Subvolume side length: $\approx \frac{1}{2} \times \max(\text{axis lengths})$ of the training unit. For flat volumes, $\approx \frac{1}{2} \times \min(\text{axis lengths})$ [S1, unofficial].

**Pseudocode:**
```python
def chunk_based_training(volume_data, n_chunk, gpu_ids):
    # Step 1: Scale coordinate space
    # The global space is [-1, 1]^3.
    # Each chunk i gets a sub-region.
    # Example for 8 chunks (octants):
    # Chunk 0: [-1, 0] x [-1, 0] x [-1, 0]
    # ...
    # For 64 chunks, the step size is 0.5.
    # For 125 chunks, the step size is 0.4.
    chunk_size = 2.0 / n_chunk ** (1/3) # Approximate linear scaling factor
    
    # Step 2: Assign chunks to GPUs
    # Each GPU handles one or more chunks
    gpu_assignments = assign_chunks_to_gpus(n_chunk, gpu_ids)
    
    # Step 3: Parallel optimization
    results = []
    for gpu_id, chunks in gpu_assignments.items():
        # For each chunk in this GPU's assignment
        for chunk in chunks:
            # Determine subvolume size based on chunk dimensions
            chunk_dims = get_chunk_dimensions(chunk)
            if is_flat_volume(chunk_dims):
                subvolume_side = 0.5 * min(chunk_dims)
            else:
                subvolume_side = 0.5 * max(chunk_dims)
            
            # Optimize chunk using subvolumes
            model_params = optimize_chunk(
                volume_data, 
                chunk, 
                subvolume_side, 
                gpu_id
            )
            results.append(model_params)
            
    return merge_model_params(results)
```

## Subtopics

### Subvolume Configuration
A variant where the training unit (full volume or individual chunk) is further partitioned into voxelized cubic subvolumes during optimization. The subvolume side length is set to approximately half the longest axis of the training unit. For flat volumes (e.g., Neuron), the smallest axis is used instead [S1, unofficial]. This reduces memory pressure and improves cache locality during gradient computation.

## Operating characteristics
*   **Hardware:** Tested on NVIDIA RTX A6000 GPUs [S1, unofficial].
*   **Scaling:** BigBrain and Woodbranch trained sequentially on a single A6000 ($n_{chunk}=8$ or $4$). Hemibrain (vDeltaA) uses 4 GPUs ($n_{chunk}=64$). Hemibrain (lLN2P) uses 5 GPUs ($n_{chunk}=125$) [S1, unofficial].
*   **Memory:** Subvolume partitioning reduces per-GPU memory requirements by processing smaller voxelized blocks [S1, unofficial].
*   **Performance:** Enables training of datasets that exceed single-GPU memory capacity (e.g., Hemibrain) [S1, unofficial].

## Background
Chunk-based Training was introduced in the context of 3D Ellipsoid-based Sparse Volume Rendering (ESVR) to handle large-scale volumetric datasets like BigBrain and Hemibrain [S1, unofficial]. It builds on the principles of chunk-based spatial partitioning, extending them to the training phase rather than just rendering [S1, unofficial].
