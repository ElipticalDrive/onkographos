# Chunk-based Training

Also called: Parallel chunk-based training

## Overview
Chunk-based Training is a strategy for optimizing large-scale volumetric datasets by partitioning the global volume into non-overlapping spatial chunks, allowing parallel optimization across multiple GPUs [S1, unofficial]. It sets itself apart from sequential training by enabling the processing of datasets that exceed single-GPU memory capacity, while differing from distributed rendering by focusing on the training phase of neural volume representations rather than inference [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A large-scale 3D dataset (e.g., histology, microscopy) and a target number of chunks $n_{chunk}$.
- Output: Trained neural network weights (or implicit field parameters) for each chunk.

**Data Structures:**
The global domain $\Omega$ is decomposed into $n_{chunk}$ chunks. Each chunk $C_i$ is associated with a fixed spatial extent. The specific data structure for the neural network weights is not detailed in the sources, but the spatial partitioning follows the parent's AABB definition [Parent].

**Coordinate Mapping and Scaling:**
1. The full volume is initially optimized in a normalized coordinate space of $[-1, 1]^3$ [S1, unofficial].
2. For large volumes, the training space is scaled according to the number of chunks. If the volume is divided into $n_{chunk}$ chunks, the coordinate space for each chunk is scaled to $[-0.5, 0.5]^3$ for 8 chunks, $[-0.25, 0.25]^3$ for 64 chunks, and $[-0.2, 0.2]^3$ for 125 chunks [S1, unofficial].
3. Global voxel coordinates $\mathbf{p}$ are mapped to chunk indices $\mathbf{k}$ and local offsets $\mathbf{p}_{local}$ using the parent's formulas [Parent].

**Subvolume Configuration:**
During optimization, the training unit (full volume or individual chunk) is partitioned into voxelized cubic subvolumes [S1, unofficial].
- The subvolume side length is set to approximately half the longest axis of the training unit [S1, unofficial].
- For flat volumes (e.g., Neuron), the smallest axis is used instead [S1, unofficial].

**Pseudocode:**
```python
def chunk_based_training(dataset, n_chunk, gpu_ids):
    # 1. Determine coordinate scaling based on chunk count
    # Source provides specific examples: 8->[-0.5,0.5], 64->[-0.25,0.25], 125->[-0.2,0.2]
    # General formula for scaling factor s: s = 1 / (n_chunk^(1/3))
    # Coordinate range becomes [-s, s]^3
    scale = 1.0 / (n_chunk ** (1.0/3.0))
    coord_min = -scale
    coord_max = scale
    
    # 2. Partition dataset into n_chunk chunks
    chunks = partition_volume(dataset, n_chunk)
    
    # 3. Configure subvolumes for each chunk
    for chunk in chunks:
        # Determine subvolume size based on chunk dimensions
        longest_axis = max(chunk.width, chunk.height, chunk.depth)
        subvolume_size = longest_axis / 2.0
        
        # For flat volumes, use smallest axis (heuristic check needed)
        if is_flat_volume(chunk):
            smallest_axis = min(chunk.width, chunk.height, chunk.depth)
            subvolume_size = smallest_axis / 2.0
            
        chunk.subvolume_size = subvolume_size
        
    # 4. Parallel optimization across GPUs
    # Assign chunks to GPUs
    gpu_assignments = assign_chunks_to_gpus(chunks, gpu_ids)
    
    # Launch parallel training processes
    for gpu_id, chunk_list in gpu_assignments.items():
        for chunk in chunk_list:
            train_chunk(chunk, coord_min, coord_max, subvolume_size)
            
    return trained_chunks
```

**Parameters:**
- $n_{chunk}$: Number of chunks. Typical values: 8 for BigBrain and Woodbranch, 64 for Hemibrain (vDeltaA), and 125 for Hemibrain (lLN2P) [S1, unofficial].
- Subvolume side length: Approximately half the longest axis of the training unit [S1, unofficial].

**Edge Cases:**
- Flat volumes: The subvolume size calculation must use the smallest axis instead of the longest to avoid excessively large subvolumes [S1, unofficial].

## Subtopics

### Subvolume Configuration
A variant where the training unit is further partitioned into voxelized cubic subvolumes during optimization. It is chosen to manage memory usage during the gradient computation phase. The subvolume size is dynamically determined based on the aspect ratio of the training unit (half the longest axis, or smallest for flat volumes) [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Memory: Scales linearly with the number of chunks and GPUs, as each GPU processes a subset of the volume [S1, unofficial].
- Time: Parallelizable across GPUs, reducing total training time for large datasets [S1, unofficial].

**Measured Performance:**
- Hardware: NVIDIA RTX A6000 GPUs [S1, unofficial].
- BigBrain and Woodbranch: Trained sequentially on a single A6000 with 8 chunks [S1, unofficial].
- Hemibrain (vDeltaA): Trained on 4 GPUs with 64 chunks [S1, unofficial].
- Hemibrain (lLN2P): Trained on 5 GPUs with 125 chunks [S1, unofficial].

**Strengths and Limitations:**
- Strengths: Enables training on datasets that exceed single-GPU memory limits [S1, unofficial].
- Limitations: Requires careful handling of chunk boundaries to avoid artifacts (see Parent) [Parent].

## Background
Originated in the context of large-scale 3D volume rendering, specifically for datasets like BigBrain, Woodbranch, and Hemibrain [S1, unofficial]. The method was developed to address the memory constraints of training neural volume representations on high-resolution histological and microscopy data [S1, unofficial].
