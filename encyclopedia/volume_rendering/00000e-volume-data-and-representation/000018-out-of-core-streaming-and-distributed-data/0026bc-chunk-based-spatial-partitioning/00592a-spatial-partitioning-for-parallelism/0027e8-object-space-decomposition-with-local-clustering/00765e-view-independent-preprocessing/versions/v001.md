# View Independent Preprocessing

Also called: Clusterization Preprocessing, Graph Partitioning Preprocessing

## Overview
View Independent Preprocessing is the initial phase of a parallel volume rendering pipeline that performs all setup work independent of visualization parameters, executed once at program startup [S1, unofficial]. It solves the problem of distributing unstructured tetrahedral volume data across multiple processors and establishing the cluster-based spatial partitioning required for subsequent rendering phases [S1, unofficial]. It sets apart from its siblings by handling the initial data ingestion, connectivity completion, and static graph partitioning, whereas the [Remapping Phase](4250-remapping-phase.md) handles dynamic load balancing and the [Graph Partitioning for Cell Clusterization](23477-graph-partitioning-for-cell-clusterization.md) describes the specific algorithmic technique used within this phase.

## How it works
**Inputs and Outputs:**
*   **Input:** 3D volume data stored in $P$ chunks on disk, where $P$ is the number of processors. Each chunk contains an equal amount of tetrahedral cell information [S1, unofficial].
*   **Output:** Local clusterization partitions on each processor, connectivity data structures, and (for SCA) a mapping of clusters to processors [S1, unofficial].

**Data Structures:**
*   **Local Connectivity Graph:** A graph representation of tetrahedral cells and their shared faces within a processor's local chunk. Nodes represent cells; edges represent shared faces [S1, unofficial].
*   **Cluster List:** A list of clusters sorted by total face area [S1, unofficial].

**Steps:**
1.  **Data Distribution:** A master processor reads the entire dataset from disk and sends one chunk to each of the $P$ processors. Each processor treats its received chunk as local data [S1, unofficial].
2.  **Connectivity Completion:** Each processor concurrently constructs local data structures. For external faces shared by cells stored in different processors, inter-processor communication is performed to complete the connectivity information [S1, unofficial].
3.  **Graph Construction:** Using the completed connectivity data, each processor creates a local clusterization graph [S1, unofficial].
4.  **Graph Partitioning:** The local graphs are input into the METIS graph partitioning tool. METIS uses the Greedy Graph Growing algorithm to output partitions representing the clusterization of the data [S1, unofficial].
5.  **Disconnected Cluster Elimination:** Processors inspect the returned partitions. A breadth-first search (BFS) is performed on every cluster to check for connectivity. If a cluster is disconnected, it is separated into its connected components. All smaller components are merged into a single, newly created cluster to limit workload assignment error [S1, unofficial].
6.  **Cluster Mapping (SCA Scheme Only):** For the Scatter-Cluster-Assignment (SCA) scheme, clusters are scattered among processors using a bin-packing-like method:
    *   Calculate the sum of face areas for every cluster [S1, unofficial].
    *   Sort clusters in decreasing order of their area sums [S1, unofficial].
    *   Distribute clusters to the least heavily loaded processor (in terms of face area sum) [S1, unofficial].
    *   Apply a limit on the number of clusters per processor to balance cell counts [S1, unofficial].
    *   *Note:* For the Neighbor-Cluster-Assignment (NCA) scheme, no scattering is needed as data chunks already consist of neighbor clusters [S1, unofficial].

**Pseudocode:**
```python
def view_independent_preprocessing(master_processor, processors, num_processors):
    # Step 1: Data Distribution
    if master_processor:
        dataset = read_from_disk()
        chunks = split_into_equal_chunks(dataset, num_processors)
        for i, proc in enumerate(processors):
            send_chunk(proc, chunks[i])
    else:
        local_chunk = receive_chunk()
        local_cells = parse_tetrahedral_cells(local_chunk)
        
        # Step 2: Connectivity Completion
        # Construct local adjacency list for cells
        local_graph = build_local_connectivity_graph(local_cells)
        
        # Identify external faces and communicate
        external_faces = identify_external_faces(local_graph)
        shared_faces = communicate_external_faces(external_faces, processors)
        complete_connectivity(local_graph, shared_faces)
        
        # Step 3: Graph Construction
        clusterization_graph = local_graph
        
        # Step 4: Graph Partitioning
        # METIS is called externally; assume it returns partition IDs
        partitions = metis_partition(clusterization_graph)
        
        # Step 5: Disconnected Cluster Elimination
        final_clusters = []
        for cluster_id in unique(partitions):
            cells_in_cluster = get_cells_with_partition(partitions, cluster_id)
            connected_components = find_connected_components(cells_in_cluster, local_graph)
            
            if len(connected_components) == 1:
                final_clusters.append(connected_components[0])
            else:
                # Merge smaller components into a new single cluster
                # Keep the largest component as the primary, merge others
                largest = max(connected_components, key=len)
                merged = largest
                for comp in connected_components:
                    if comp != largest:
                        merged.extend(comp)
                final_clusters.append(merged)
        
        # Step 6: Cluster Mapping (SCA)
        if scheme == "SCA":
            cluster_areas = []
            for cluster in final_clusters:
                area = sum_face_areas(cluster, local_graph)
                cluster_areas.append((cluster, area))
            
            # Sort by area descending
            cluster_areas.sort(key=lambda x: x[1], reverse=True)
            
            # Bin-packing distribution
            processor_loads = {p: 0.0 for p in processors}
            processor_cluster_counts = {p: 0 for p in processors}
            max_clusters_per_proc = calculate_limit(num_processors, len(final_clusters))
            
            for cluster, area in cluster_areas:
                # Find least loaded processor
                least_loaded_proc = min(processors, key=lambda p: processor_loads[p])
                
                # Check cluster count limit
                if processor_cluster_counts[least_loaded_proc] < max_clusters_per_proc:
                    assign_cluster_to_processor(least_loaded_proc, cluster)
                    processor_loads[least_loaded_proc] += area
                    processor_cluster_counts[least_loaded_proc] += 1
                else:
                    # Fallback to next least loaded if limit hit
                    next_proc = min([p for p in processors if p != least_loaded_proc], 
                                    key=lambda p: processor_loads[p])
                    assign_cluster_to_processor(next_proc, cluster)
                    processor_loads[next_proc] += area
                    processor_cluster_counts[next_proc] += 1
        else:
            # NCA: No mapping needed
            pass
```

**Parameters:**
*   **METIS Tool:** Uses the Greedy Graph Growing algorithm [S1, unofficial].
*   **Workload Metric:** Sum of face areas for SCA [S1, unofficial].
*   **Cluster Limit:** A limit on the number of clusters per processor is applied to balance cell counts [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Disconnected Clusters:** METIS may produce disconnected clusters, especially for workload assignment schemes using bounding boxes. These must be eliminated to avoid increased hypergraph partitioning duration [S1, unofficial].
*   **Precision:** Not given in the sources.
*   **Boundaries:** External faces shared between processors require communication to complete connectivity [S1, unofficial].

## Subtopics

### Remapping Phase
Handles dynamic load balancing after the initial static partitioning. Chosen when workload varies significantly during rendering. [Remapping Phase](4250-remapping-phase.md)

### Graph Partitioning for Cell Clusterization
Describes the specific graph partitioning technique (METIS with Greedy Graph Growing) used within View Independent Preprocessing. Chosen for its efficiency in creating balanced clusters. [Graph Partitioning for Cell Clusterization](23477-graph-partitioning-for-cell-clusterization.md)

## Operating characteristics
*   **Time Complexity:** Dominated by graph partitioning (METIS) and connectivity completion. The elimination of disconnected clusters adds BFS overhead [S1, unofficial].
*   **Memory Complexity:** Requires storing local connectivity graphs and cluster data structures on each processor [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Assumes the number of data chunks equals the number of processors [S1, unofficial].
*   **Strengths:** Reduces view-dependent preprocessing time by pre-computing static partitions; handles disconnected clusters to ensure workload balance [S1, unofficial].
*   **Limitations:** Requires inter-processor communication for connectivity completion; SCA scheme requires additional bin-packing logic [S1, unofficial].
*   **When to Use:** When the volume data is static and visualization parameters change frequently, allowing the preprocessing to be amortized [S1, unofficial].
*   **When Not to Use:** When the data distribution is already optimal (NCA scheme) or when dynamic remapping is preferred over static clustering [S1, unofficial].

## Background
This method originates from a hypergraph-partitioning based remapping model for image-space parallel volume rendering [S1, unofficial]. It is part of a four-phase implementation: View Independent Preprocessing, View Dependent Preprocessing, Cluster Migration, and Local Rendering [S1, unofficial]. The approach assumes 3D volume data is produced by simulations on parallel machines, stored in chunks corresponding to processors [S1, unofficial].
