# Object-space decomposition with local clustering

Also called: Graph-based clustering for unstructured grids, Local clustering via MeTiS

## Overview
Object-space decomposition with local clustering is a view-independent preprocessing method for parallel volume rendering on unstructured grids that partitions the domain into cell-clusters to minimize communication and load imbalance during rendering [S1, unofficial]. It differs from sibling methods like [MPI-based Volume Partitioning](1093-mpi-based-volume-partitioning.md) by performing k-way partitioning locally on each processor using MeTiS before global synchronization, and from [ShardedVolume](12593-shardedvolume.md) by explicitly constructing a contracted visualization graph to support the subsequent [Remapping Phase](4250-remapping-phase.md) for dynamic view adaptation [S1, unofficial].

## How it works
**Inputs:**
- Global visualization graph $Q_v = (N_v, E_v)$ representing the unstructured grid connectivity.
- Number of processors $A$.
- Viewing parameter $v$ (used later for remapping, but the graph topology is view-independent).

**Outputs:**
- Global clustering solution $C = [C_1, C_2, ..., C_K]$, where $K$ is the total number of clusters.
- Global mapping function $M_e$ mapping each cluster to a processor.
- Local data structures: `ClusterData` and `ClusterMapArray` on each processor.
- Contracted visualization graph $Q_c = (N_c, E_c)$ and migration cost function $T_c$.

**Data Structures:**

1.  **`ClusterData`**: Maintained by each processor for its local cell-clusters.
    -   `VertexArray`: List of vertices belonging to the cluster, using local indexing.
    -   `CellArray`: List of tetrahedral cells belonging to the cluster, using local indexing.
    -   **Connectivity**: For each cell in `CellArray`, the four global neighbor-cell identifiers are replaced by a tuple: `(global_cluster_id, local_index_of_neighbor_cell)`. This maintains connectivity between cell-clusters within the local indexing scheme [S1, unofficial].
    -   `TotalVolume`: The sum of the volumes (in WSC) of all constituent cells in the cluster [S1, unofficial].

2.  **`ClusterMapArray`**: Maintained by each processor for *all* clusters in the global environment.
    -   For each global cluster $C_i$:
        -   `Mapping`: The current processor assignment $M_e(C_i)$.
        -   `Pointer`: A pointer to the `ClusterData` structure if $C_i$ is local to this processor; otherwise null [S1, unofficial].

**Numbered Steps:**

1.  **Local Graph Construction**: Each processor $P_k$ ($k=1 \dots A$) constructs its local view-independent visualization graph $Q_k$. This graph is the subgraph of the global graph $Q_v$ induced by the node subset corresponding to the local cells owned by $P_k$ [S1, unofficial].

2.  **Local Clustering**: Each processor $P_k$ concurrently performs a $q_k$-way clustering of its local graph $Q_k$ using MeTiS [S1, unofficial].
    -   **Parameter Selection**: The local number of resulting clusters $q_k$ is selected to be proportional to the total node weight in its local graph such that:
        $$ \sum_{k=1}^{A} q_k = c \cdot a $$
        where $c$ and $a$ are constants defined by the system configuration. This scheme reduces variations in cluster weights to improve the efficiency of the subsequent graph-partitioning based remapping [S1, unofficial].
    -   The local $q_k$-way partitioning performed in each processor $P_k$ effectively constitutes a $K$-way global clustering solution $C = [C_1, C_2, ..., C_K]$ [S1, unofficial].

3.  **Global Identifier Assignment**: Each cluster in the overall environment is assigned a unique global cluster identifier. The global mapping function $M_e$ for these clusters is determined [S1, unofficial].

4.  **Connectivity Update**: In the `CellArray` structure of each local `ClusterData`, the four global neighbor-cell identifiers of each cell are replaced by the global-cluster identifiers and local indices of the respective neighbor cells. This ensures connectivity information between cell-clusters is maintained within the local indexing scheme [S1, unofficial].

5.  **Contracted Graph Construction ($Q_c$)**:
    -   The contracted visualization graph $Q_c = (N_c, E_c)$ is the contraction of the global graph according to the global clustering solution $C$ for a given viewing parameter $v$.
    -   There exists an edge $C_{ij}$ between clusters $C_i$ and $C_j$ if these clusters share at least one face through two neighbor cells in these two clusters [S1, unofficial].
    -   Note: The topology of the view-dependent visualization graph does not change with changing viewing parameter $v$, and is identical to the topology of the view-independent contracted visualization graph $Q_c$. All contracted graphs differ only in node and edge weights [S1, unofficial].
    -   Each processor constructs its local portion of $Q_c$ [S1, unofficial].

6.  **Global Graph Replication**: A copy of the global graph $Q_c$ is replicated in each processor by performing an all-to-all-broadcast operation. This allows the construction of the view-dependent contracted graph to involve only the computation of node and edge weights according to $v$ [S1, unofficial].

7.  **Migration Cost Calculation ($T_c$)**:
    -   $T_c$ denotes the cluster-migration-cost function.
    -   The migration cost of a cell-cluster is taken to be equal to the ratio of the size of its associated `ClusterData` structure to the size of an individual ray-segment information [S1, unofficial].
    -   Since each processor only knows the migration costs of its local clusters, an all-to-all broadcast operation is performed to let each processor become aware of the migration costs of all clusters [S1, unofficial].

def estimate_q_k(total_cells, num_processors):
    """
    Estimates q_k proportional to total node weight.
    Not given in sources: specific formula for c and a.
    """
    # Placeholder for proportional distribution
    return max(1, total_cells // num_processors)

def update_cell_connectivity(cell_array, local_partition, global_graph):
    """
    Replaces global neighbor-cell identifiers with (global_cluster_id, local_index).
    """
    for cell in cell_array.cells:
        for neighbor_cell_idx in range(4):
            neighbor_global_id = cell.get_neighbor_global_id(neighbor_cell_idx)
            if neighbor_global_id is not None:
                # Find which cluster the neighbor belongs to
                neighbor_cluster_id = get_cluster_id_for_cell(neighbor_global_id, local_partition)
                # Find local index of neighbor in its cluster
                neighbor_local_index = get_local_index_in_cluster(neighbor_global_id, neighbor_cluster_id)
                cell.set_neighbor_info(neighbor_cell_idx, neighbor_cluster_id, neighbor_local_index)

def build_local_contracted_graph(global_clustering_C, global_mapping_Me, proc_id):
    """
    Constructs the local portion of the contracted visualization graph Qc.
    """
    local_clusters = [c for c in global_clustering_C if global_mapping_Me[get_global_id(c)] == proc_id]
    local_edges = []
    
    # Check for shared faces between local clusters and all other clusters
    # Note: Source says topology is identical to view-independent graph.
    # We need to find edges between any two clusters that share a face.
    for i, cluster_i in enumerate(global_clustering_C):
        for j, cluster_j in enumerate(global_clustering_C):
            if i >= j: continue
            if share_face(cluster_i, cluster_j):
                local_edges.append((get_global_id(cluster_i), get_global_id(cluster_j)))
                
    return {
        'nodes': [get_global_id(c) for c in local_clusters],
        'edges': local_edges
    }

def share_face(cluster_i, cluster_j):
    """
    Checks if two clusters share at least one face through two neighbor cells.
    """
    # Iterate through cells in cluster_i and check if any neighbor is in cluster_j
    for cell in cluster_i.cells:
        for neighbor_global_id in cell.get_neighbor_global_ids():
            if get_cluster_id_for_cell(neighbor_global_id, global_clustering_C) == get_global_id(cluster_j):
                return True
    return False

## Subtopics

### [Remapping Phase](4250-remapping-phase.md)
The Remapping Phase is a view-dependent preprocessing step in chunk-based spatial partitioning for parallel volume rendering, designed to reassign data clusters to processors based on the current viewing parameters. It solves load imbalance and communication overhead when the camera changes, ensuring clusters with high interaction remain co-located. It adapts the static clustering solution from Object-space decomposition with local clustering to the current view via a dynamic graph-partitioning loop.

## Operating characteristics
- **Time Complexity**: The local clustering step uses MeTiS, which is generally efficient for graph partitioning. The global synchronization steps (all-to-all broadcasts) dominate communication time. The construction of the contracted graph $Q_c$ is view-independent, so its topology is computed once. View-dependent weight updates are lightweight [S1, unofficial].
- **Memory Complexity**: Requires storing `ClusterData` for local clusters, `ClusterMapArray` for all global clusters, and a full copy of the contracted graph $Q_c$ on each processor. The `ClusterMapArray` scales with the total number of clusters $K$ [S1, unofficial].
- **Measured Performance**: Not given in the sources.
- **Strengths**: Minimizes view-independent preprocessing overhead by performing clustering locally. The contracted graph topology is view-independent, reducing recomputation during view changes. The migration cost function is also view-independent [S1, unofficial].
- **Limitations**: Requires significant communication (all-to-all broadcasts) to synchronize cluster mappings and migration costs. The local clustering may not produce a globally optimal partition without further refinement (handled in the Remapping Phase) [S1, unofficial].
- **When to use**: Suitable for unstructured grid volume rendering where view-dependent load balancing is critical, and the overhead of global graph partitioning is too high. Best used in conjunction with the Remapping Phase [S1, unofficial].
- **When not**: Not suitable for static views where a single global partition would suffice, or for systems with very high communication latency where all-to-all broadcasts are prohibitive.

## Background
Originated in the context of parallel direct volume rendering of unstructured grids. The method was proposed to address the limitations of global partitioning approaches by leveraging local clustering with MeTiS to reduce preprocessing overhead [S1, unofficial]. It is part of a broader framework that includes a Remapping Phase for dynamic adaptation to viewing parameters [S1, unofficial].
