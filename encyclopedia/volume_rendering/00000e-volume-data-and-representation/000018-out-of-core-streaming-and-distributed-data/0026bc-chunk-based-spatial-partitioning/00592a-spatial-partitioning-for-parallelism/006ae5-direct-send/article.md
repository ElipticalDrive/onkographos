# Direct Send

Also called: Envoi direct

## Overview
Direct Send is a parallel volume rendering composition technique for object partitioning where partial images generated by different processors are sent directly to a specific target processor for final composition [S1, unofficial]. It builds on [Chunk-based spatial partitioning](3862-chunk-based-spatial-partitioning.md) and is distinguished from sibling methods like [MPI-based Volume Partitioning](1093-mpi-based-volume-partitioning.md), which relies on iterative pairwise exchanges, and [Parallel Pipeline](12593-shardedvolume.md), which arranges processors in a linear sequence [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: $P$ processors, each holding a partition of the volume data and having rendered a partial image of size $W \times H$ [G].
*   Output: A single composed image on the target processor [G].

**Data Structures:**
*   Partial Image: A 2D array of color and opacity values $(c_i, \alpha_i)$ for each pixel $i \in [0, W \times H - 1]$ [G].
*   Communication Buffer: A contiguous memory block of size $W \times H \times B$ bytes, where $B$ is bytes per pixel (e.g., 4 for RGBA) [G].

**Steps:**
1.  **Partitioning:** The global volume domain is divided into $P$ chunks. Each processor $p \in [0, P-1]$ renders its assigned chunk independently [G].
2.  **Target Assignment:** A target processor $T$ is selected (typically processor 0 or a dedicated node) [G].
3.  **Transmission:** Each processor $p \neq T$ sends its entire partial image directly to processor $T$ via point-to-point communication [S1, unofficial].
4.  **Composition:** Processor $T$ receives partial images from all other processors and composites them into the final image using front-to-back alpha compositing [G].
    *   Front-to-back formula for pixel $i$:
        $$C_{final} = \sum_{j=1}^{N} c_j \alpha_j \prod_{k=1}^{j-1} (1 - \alpha_k)$$
        $$\alpha_{final} = 1 - \prod_{j=1}^{N} (1 - \alpha_j)$$
        where $N$ is the number of partial images, and $c_j, \alpha_j$ are the color and opacity from the $j$-th received partial image [G].
5.  **Distribution (Optional):** If the final image is needed on all processors, processor $T$ broadcasts the result [G].

**Parameters:**
*   $P$: Number of processors.
*   $W, H$: Image dimensions.

**Edge Cases and Pitfalls:**
*   **Communication Bottleneck:** Processor $T$ becomes a bottleneck as it must receive $P-1$ large messages simultaneously [G].
*   **Memory Pressure:** Processor $T$ must store $P$ partial images in memory during composition [G].
*   **Synchronization:** All processors must complete rendering before transmission begins to ensure data consistency [G].

## Subtopics

### Parallel Pipeline
A composition technique where processors are arranged in a pipeline to compose partial images [S1, unofficial]. Unlike Direct Send, which sends partial images directly to a single target for composition, data flows sequentially through the pipeline, reducing peak memory usage on any single node but increasing latency due to sequential processing [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. Standard implementations scale as $O(P \cdot W \cdot H)$ for communication and composition on the target node [G].
*   **Memory Complexity:** Not given in the sources. The target processor requires $O(P \cdot W \cdot H)$ to store partial images, while others use $O(W \cdot H)$ [G].
*   **Strengths:** Simple implementation; low latency for small $P$; no iterative communication rounds [G].
*   **Limitations:** Poor scalability for large $P$ due to the single-point bottleneck on the target processor; high memory requirement on the target node [G].
*   **When to Use:** Not given in the sources. Typically suited for small-scale clusters or when implementation simplicity is prioritized [G].
*   **When Not to Use:** Not given in the sources. Generally avoided for large-scale distributed systems or when target node memory/bandwidth is constrained [G].

## Background
Direct Send was proposed in the early 1990s as one of the foundational parallel volume rendering composition techniques, alongside Binary Swap and Parallel Pipeline [S1, unofficial].
