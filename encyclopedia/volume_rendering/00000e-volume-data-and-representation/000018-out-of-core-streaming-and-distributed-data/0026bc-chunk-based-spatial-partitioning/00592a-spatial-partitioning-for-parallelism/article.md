# Spatial Partitioning for Parallelism

Also called: Chunk-based Parallelism, Distributed Volume Rendering

## Overview
Spatial Partitioning for Parallelism divides a volumetric dataset into independent chunks to distribute I/O and computation across multiple processing units, solving the memory and throughput bottlenecks of large-scale volume rendering [G]. It differs from tree-based methods by using fixed or pre-computed spatial divisions rather than hierarchical traversal, and from streaming methods by focusing on static or semi-static data distribution for parallel execution rather than temporal or view-dependent chunk loading [G].

## Shared principles
Builds on the chunk-based spatial partitioning family [Chunk-based spatial partitioning](3862-chunk-based-spatial-partitioning.md).

## Subtopics

### [MPI-based Volume Partitioning](1093-mpi-based-volume-partitioning.md)
A data-parallel strategy partitioning a volumetric dataset into contiguous chunks of slices assigned to distinct MPI processes. It partitions the data grid directly rather than clustering geometric primitives, and relies on static process assignment rather than dynamic sharding. Choose it for efficient I/O and parallel rendering of uniform-resolution volumes where contiguous memory access minimizes seek overhead.

### [Object-space decomposition with local clustering](4156-object-space-decomposition-with-local-clustering.md)
A view-independent preprocessing method for parallel volume rendering on unstructured grids that partitions the domain into cell-clusters to minimize communication and load imbalance. It performs k-way partitioning locally using MeTiS before global synchronization and explicitly constructs a contracted visualization graph for dynamic view adaptation. Choose it for unstructured grids requiring load-balanced, view-dependent rendering with minimal inter-processor communication.

### [ShardedVolume](12593-shardedvolume.md)
A data structure representing a 3D volume partitioned into multiple shards (sub-arrays) to allow parallel processing or memory management across devices. It treats each shard as an autonomous unit for arithmetic operations and data access. Choose it for managing large volumetric datasets that exceed single-device memory or require distributed computation with high-level API abstractions.

### [One-Phase Remapping Model](16393-one-phase-remapping-model.md)
A method for solving the remapping problem in parallel direct volume rendering by constructing a single augmented graph and performing a single K-way partition, rather than separating partitioning and assignment into two phases. It integrates current mapping and migration costs into the graph structure to simultaneously optimize load balance and communication overhead. Choose it when two-phase approaches restrict task-to-processor assignment quality and dynamic remapping is required.

### [Graph-Based Distributed Partitioning](19155-graph-based-distributed-partitioning.md)
An offline strategy for assigning 3D points (such as 3D Gaussian splats) to distributed GPUs or machines by modeling data access patterns as a bipartite graph and partitioning it to minimize cross-partition communication edges while balancing memory usage. It explicitly accounts for camera view dependency rather than relying on geometric proximity. Choose it for large-scale distributed rendering of point-based data where view-dependent locality reduces inter-GPU communication.

### [Slice-Based Data-Space Parallel Distribution](20355-slice-based-data-space-parallel-distribution.md)
Partitions a 3D voxel dataset into contiguous 2D slices and assigns them to parallel processors to enable local processing while minimizing communication overhead. It distributes the source data itself rather than rendering tasks across the image plane, leveraging typically higher X-Y resolution for efficient loop execution. Choose it for medical imaging workloads where data is naturally recorded on a slice basis and memory per node must be minimized.

### [Direct Send](20759-direct-send.md)
A parallel volume rendering composition technique for object partitioning where partial images generated by different processors are sent directly to a specific target processor for final composition. It is distinguished from iterative pairwise exchanges or linear processor sequences. Choose it for straightforward, low-latency composition when a dedicated compositing node is available and network bandwidth can handle bulk transfers.

#### Binary Swap

### definition
- A composition technique for object partitioning on clusters where partial images are exchanged and merged between processors in a binary swap fashion to produce the final image [S1, unofficial].

### pitfall
- Transparent pixels can be eliminated in communications using compression techniques and bounding box structures [S1, unofficial].

### usage
- Implemented in the DViz library developed at INRIA Lorraine, which provides a particularly performant implementation [S1, unofficial].

## Background
The concept of spatial partitioning for parallel volume rendering originated with the need to scale ray-casting and isosurface extraction to datasets exceeding single-node memory [G]. Early implementations used simple slice-based decomposition across MPI processes [MPI-based Volume Partitioning](1093-mpi-based-volume-partitioning.md). Subsequent research introduced graph-partitioning techniques for unstructured grids to minimize communication during rendering [Object-space decomposition with local clustering](4156-object-space-decomposition-with-local-clustering.md). More recently, high-level abstractions like ShardedVolume have been developed to manage distributed volumetric data for scientific computing and machine learning workloads [ShardedVolume](12593-shardedvolume.md).
