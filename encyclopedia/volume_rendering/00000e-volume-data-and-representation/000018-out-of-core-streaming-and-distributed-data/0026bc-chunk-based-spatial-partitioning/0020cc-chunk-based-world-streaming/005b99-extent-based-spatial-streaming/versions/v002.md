# Extent-based Spatial Streaming

Also called: Extent-based Streaming

## Overview
Extent-based spatial streaming is a technique for processing large datasets by dividing the spatial domain into multiple chunks, where each pipeline execution processes a specific spatial subset (extent) of the data [S1, unofficial]. It differs from piece-based streaming by explicitly calculating and requesting the spatial bounds (`UPDATE_EXTENT`) via an extent translator, rather than relying on the executive to map piece indices to extents [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A dataset with a defined spatial extent (e.g., `vtkImageData`) [S1, unofficial].
*   **Output:** A multi-block dataset (`vtkMultiBlockDataSet`) containing the processed results for each spatial chunk [S1, unofficial].

**Data Structures:**
*   **vtkExtentTranslator:** A utility class that computes spatial extents for a given piece index [S1, unofficial].
    *   **Fields/Methods:**
        *   `SetWholeExtent(xmin, xmax, ymin, ymax, zmin, zmax)`: Sets the total spatial bounds [S1, unofficial].
        *   `SetNumberOfPieces(n)`: Sets the total number of chunks [S1, unofficial].
        *   `SetPiece(index)`: Sets the current piece index (0 to n-1) [S1, unofficial].
        *   `PieceToExtent()`: Computes the extent for the current piece [S1, unofficial].
        *   `GetExtent()`: Returns the computed extent as an array of 6 integers `[xmin, xmax, ymin, ymax, zmin, zmax]` [S1, unofficial].
*   **UPDATE_EXTENT:** A pipeline information key storing an array of 6 integers representing the spatial bounds requested for the current execution [S1, unofficial].

**Parameters:**
*   **NumberOfBlocks:** The total number of spatial chunks (pieces) to divide the whole extent into. Typical value: 20 [S1, unofficial].
*   **WholeExtent:** The spatial bounds of the entire dataset, defined as `(xmin, xmax, ymin, ymax, zmin, zmax)`. Typical value: `(-100, 100, -100, 100, -100, 100)` [S1, unofficial].

**Algorithm Steps:**
1.  **RequestInformation:** Retrieve the `WHOLE_EXTENT` from the input information object and pass it to the `vtkExtentTranslator` using `SetWholeExtent` [S1, unofficial].
2.  **RequestUpdateExtent:** Set the current piece index on the translator using `SetPiece(self.UpdateIndex)` [S1, unofficial]. Compute the corresponding spatial bounds using `PieceToExtent()` [S1, unofficial]. Retrieve the result using `GetExtent()` [S1, unofficial]. Set the `UPDATE_EXTENT` key on the input information object with the computed extent array of size 6 [S1, unofficial].
3.  **RequestData:** Retrieve the input data object [S1, unofficial]. Initialize the output multi-block dataset to have `NumberOfBlocks` if it is currently empty [S1, unofficial]. Process the input data restricted to the `UPDATE_EXTENT` (e.g., pass to a contour filter) [S1, unofficial]. If the processing output contains cells, create a `vtkPolyData` block, shallow copy the output, and set it in the multi-block dataset at the current `UpdateIndex` [S1, unofficial]. Check if `UpdateIndex` is less than `NumberOfBlocks - 1` [S1, unofficial]. If true, increment `UpdateIndex` and set the `CONTINUE_EXECUTING` flag to 1 to trigger re-execution for the next chunk [S1, unofficial]. If false, remove the `CONTINUE_EXECUTING` flag and reset `UpdateIndex` to 0 [S1, unofficial].

**Pseudocode:**
```python
class ExtentTranslator:
    def __init__(self):
        self.whole_extent = None
        self.num_pieces = 0
        self.current_piece = 0
        self.computed_extent = None

    def set_whole_extent(self, extent):
        self.whole_extent = list(extent)

    def set_number_of_pieces(self, n):
        self.num_pieces = n

    def set_piece(self, index):
        self.current_piece = index

    def piece_to_extent(self):
        if self.whole_extent is None or self.num_pieces == 0:
            self.computed_extent = self.whole_extent
            return
        xmin, xmax, ymin, ymax, zmin, zmax = self.whole_extent
        dx = (xmax - xmin) / self.num_pieces
        ix = self.current_piece
        start = xmin + int(ix * dx)
        end = xmin + int((ix + 1) * dx)
        self.computed_extent = [start, end, ymin, ymax, zmin, zmax]

    def get_extent(self):
        return self.computed_extent

class PipelineRequest:
    def __init__(self):
        self.continue_flag = False

    def set_continue_executing(self, val):
        self.continue_flag = bool(val)

    def remove_continue_executing(self):
        self.continue_flag = False

class MultiBlockDataset:
    def __init__(self):
        self.blocks = []

    def get_number_of_blocks(self):
        return len(self.blocks)

    def set_number_of_blocks(self, n):
        self.blocks = [None] * n

    def set_block(self, index, block):
        self.blocks[index] = block

class DataObject:
    def __init__(self, cells):
        self.cells = cells

    def get_number_of_cells(self):
        return len(self.cells)

    def shallow_copy(self):
        return DataObject(list(self.cells))

class ContourProcessor:
    def __init__(self, value):
        self.value = value
        self.input_data = None
        self.output_cells = []

    def set_input_data(self, data):
        self.input_data = data

    def update(self):
        # The actual filtering logic depends on the specific filter implementation.
        # This step processes the input data restricted to the UPDATE_EXTENT.
        self.output_cells = [c for c in self.input_data.cells if True]
        return self

    def get_output(self):
        return DataObject(self.output_cells)

class ExtentBasedStreamer:
    def __init__(self):
        self.update_index = 0
        self.number_of_blocks = 20
        self.extent_translator = ExtentTranslator()
        self.extent_translator.set_number_of_pieces(self.number_of_blocks)
        self.processor = ContourProcessor(180)

    def request_information(self, in_info):
        whole_extent = in_info.get_whole_extent()
        self.extent_translator.set_whole_extent(whole_extent)
        return 1

    def request_update_extent(self, request, in_info):
        self.extent_translator.set_piece(self.update_index)
        self.extent_translator.piece_to_extent()
        extent = self.extent_translator.get_extent()
        in_info.set_update_extent(extent)
        return 1

    def request_data(self, request, in_info, out_info):
        input_data = in_info.get_data_object()
        output = out_info.get_multi_block_dataset()

        if output.get_number_of_blocks() == 0:
            output.set_number_of_blocks(self.number_of_blocks)

        self.processor.set_input_data(input_data)
        self.processor.update()
        contour_output = self.processor.get_output()

        if contour_output.get_number_of_cells() > 0:
            block = contour_output.shallow_copy()
            output.set_block(self.update_index, block)

        if self.update_index < self.number_of_blocks - 1:
            self.update_index += 1
            request.set_continue_executing(1)
        else:
            request.remove_continue_executing()
            self.update_index = 0
        return 1
```

**Edge Cases and Pitfalls:**
*   **Memory Usage:** The output of processing filters (e.g., contouring) can be significantly larger than the input image data, potentially causing memory issues if all blocks are kept in memory [S1, unofficial].
*   **Empty Blocks:** Some spatial chunks may not contain data relevant to the processing filter (e.g., no isosurface intersection), resulting in empty blocks. The algorithm conditionally adds blocks only when the processing output contains cells, as shown in the source check `if contour.GetNumberOfCells() > 0` [S1, unofficial].

## Subtopics

### Piece-based Spatial Streaming
A spatial streaming technique where the pipeline requests data subsets using piece indices rather than explicit extents, allowing the executive to handle extent calculation [S1, unofficial]. It sets `UPDATE_NUMBER_OF_PIECES` and `UPDATE_PIECE_NUMBER` keys instead of `UPDATE_EXTENT` [S1, unofficial]. Unlike extent-based streaming, which explicitly calculates extents via `vtkExtentTranslator`, piece-based streaming relies on the executive to use the extent translator under the hood [S1, unofficial]. It is the only viable choice for unstructured data sources where explicit extent calculation may not be applicable or supported [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of blocks, as each block is processed in a separate pipeline execution [G]. Total time is proportional to the sum of processing times for all chunks [G].
*   **Memory Complexity:** Bounded by the memory required for a single chunk plus the memory for the output multi-block dataset [G]. This allows processing datasets larger than available RAM [G].
*   **Strengths:** Enables processing of datasets that do not fit in memory by breaking them into manageable spatial chunks [S1, unofficial].
*   **Limitations:** The output data structure (multi-block) may be more complex to consume than a single contiguous dataset. Processing filters may generate output larger than input, risking memory issues if not managed [S1, unofficial].
*   **When to use:** When the input dataset is too large to fit in memory and the processing algorithm can operate on spatial subsets independently [G].
*   **When not to use:** When the processing algorithm requires global context or communication between spatial regions that cannot be easily decomposed [G].

## Background
Originated in the Visualization Toolkit (VTK) as part of the Streaming Demand Driven Pipeline model. Introduced by Berk Geveci in 2014 to address the need for processing large spatial datasets that exceed memory capacity [S1, unofficial].
