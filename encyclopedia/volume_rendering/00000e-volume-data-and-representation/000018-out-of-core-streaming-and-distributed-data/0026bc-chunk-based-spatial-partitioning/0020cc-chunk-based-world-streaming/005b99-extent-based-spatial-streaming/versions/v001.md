# Extent-based Spatial Streaming

Also called: Extent-based Streaming

## Overview
Extent-based spatial streaming is a technique for processing large datasets by dividing the spatial domain into multiple chunks, where each pipeline execution processes a specific spatial subset (extent) of the data [S1, unofficial]. It differs from piece-based streaming by explicitly calculating and requesting the spatial bounds (UPDATE_EXTENT) via an extent translator, rather than relying on the executive to map piece indices to extents [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A dataset with a defined spatial extent (e.g., `vtkImageData`).
*   **Output:** A multi-block dataset (`vtkMultiBlockDataSet`) containing the processed results for each spatial chunk.

**Data Structures:**
*   **vtkExtentTranslator:** A utility class that computes spatial extents for a given piece index.
    *   **Fields/Methods:**
        *   `SetWholeExtent(xmin, xmax, ymin, ymax, zmin, zmax)`: Sets the total spatial bounds.
        *   `SetNumberOfPieces(n)`: Sets the total number of chunks.
        *   `SetPiece(index)`: Sets the current piece index (0 to n-1).
        *   `PieceToExtent()`: Computes the extent for the current piece.
        *   `GetExtent()`: Returns the computed extent as an array of 6 integers `[xmin, xmax, ymin, ymax, zmin, zmax]`.
*   **UPDATE_EXTENT:** A pipeline information key storing an array of 6 integers representing the spatial bounds requested for the current execution.

**Parameters:**
*   **NumberOfBlocks:** The total number of spatial chunks (pieces) to divide the whole extent into. Typical value: 20 [S1, unofficial].
*   **WholeExtent:** The spatial bounds of the entire dataset, defined as `(xmin, xmax, ymin, ymax, zmin, zmax)`. Typical value: `(-100, 100, -100, 100, -100, 100)` [S1, unofficial].

**Algorithm Steps:**
1.  **RequestInformation:** Retrieve the `WHOLE_EXTENT` from the input information object. Pass this extent to the `vtkExtentTranslator` using `SetWholeExtent`.
2.  **RequestUpdateExtent:**
    *   Set the current piece index on the translator using `SetPiece(self.UpdateIndex)`.
    *   Compute the corresponding spatial bounds using `PieceToExtent()`.
    *   Retrieve the result using `GetExtent()`.
    *   Set the `UPDATE_EXTENT` key on the input information object with the computed extent array of size 6.
3.  **RequestData:**
    *   Retrieve the input data object.
    *   Initialize the output multi-block dataset to have `NumberOfBlocks` if it is currently empty.
    *   Process the input data restricted to the `UPDATE_EXTENT` (e.g., pass to a contour filter).
    *   If the processing output contains cells, create a `vtkPolyData` block, shallow copy the output, and set it in the multi-block dataset at the current `UpdateIndex`.
    *   Check if `UpdateIndex` is less than `NumberOfBlocks - 1`.
        *   If true: Increment `UpdateIndex` and set the `CONTINUE_EXECUTING` flag to 1 to trigger re-execution for the next chunk.
        *   If false: Remove the `CONTINUE_EXECUTING` flag and reset `UpdateIndex` to 0.

**Pseudocode:**
```python
class ExtentBasedStreamer:
    def __init__(self):
        self.UpdateIndex = 0
        self.NumberOfBlocks = 20
        self.ExtentTranslator = vtkExtentTranslator()
        # Initialize processing filter (e.g., ContourFilter)
        self.Processor = vtkContourFilter()
        self.Processor.SetValue(0, 180)

    def RequestInformation(self, request, inInfo, outInfo):
        # Get the whole extent from the input
        wholeExtent = inInfo[0].GetInformationObject(0).Get(WHOLE_EXTENT)
        # Configure the translator with the total bounds
        self.ExtentTranslator.SetWholeExtent(wholeExtent)
        self.ExtentTranslator.SetNumberOfPieces(self.NumberOfBlocks)
        return 1

    def RequestUpdateExtent(self, request, inInfo, outInfo):
        # Set the current piece index
        self.ExtentTranslator.SetPiece(self.UpdateIndex)
        # Compute the extent for this piece
        self.ExtentTranslator.PieceToExtent()
        # Get the computed extent array [xmin, xmax, ymin, ymax, zmin, zmax]
        extent = self.ExtentTranslator.GetExtent()
        # Request this specific extent from the input source
        inInfo[0].GetInformationObject(0).Set(UPDATE_EXTENT, extent, 6)
        return 1

    def RequestData(self, request, inInfo, outInfo):
        # Get input data
        inputData = inInfo[0].GetInformationObject(0).Get(DATA_OBJECT())
        # Get output multi-block dataset
        output = outInfo[0].GetInformationObject(0).Get(DATA_OBJECT())
        
        # Initialize output blocks if empty
        if output.GetNumberOfBlocks() == 0:
            output.SetNumberOfBlocks(self.NumberOfBlocks)
            
        # Configure processor with current input piece
        self.Processor.SetInputData(inputData)
        self.Processor.Update()
        
        # Get contour output
        contourOutput = self.Processor.GetOutput()
        
        # If there are cells, add to the multi-block dataset
        if contourOutput.GetNumberOfCells() > 0:
            block = vtkPolyData()
            block.ShallowCopy(contourOutput)
            output.SetBlock(self.UpdateIndex, block)
            
        # Handle streaming control
        if self.UpdateIndex < self.NumberOfBlocks - 1:
            self.UpdateIndex += 1
            request.Set(CONTINUE_EXECUTING, 1)
        else:
            request.Remove(CONTINUE_EXECUTING)
            self.UpdateIndex = 0
        return 1
```

**Edge Cases and Pitfalls:**
*   **Memory Usage:** The output of processing filters (e.g., contouring) can be significantly larger than the input image data. If all blocks are retained in memory simultaneously, this can cause memory exhaustion [S1, unofficial].
*   **Empty Blocks:** Some spatial chunks may not contain data relevant to the processing filter (e.g., no isosurface intersection), resulting in empty blocks. The algorithm must handle cases where `GetNumberOfCells() == 0` gracefully [S1, unofficial].

## Subtopics

### Piece-based Spatial Streaming
A spatial streaming technique where the pipeline requests data subsets using piece indices rather than explicit extents, allowing the executive to handle extent calculation [S1, unofficial]. It sets `UPDATE_NUMBER_OF_PIECES` and `UPDATE_PIECE_NUMBER` keys instead of `UPDATE_EXTENT` [S1, unofficial]. Unlike extent-based streaming, which explicitly calculates extents via `vtkExtentTranslator`, piece-based streaming relies on the executive to use the extent translator under the hood [S1, unofficial]. It is the only viable choice for unstructured data sources where explicit extent calculation may not be applicable or supported [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of blocks, as each block is processed in a separate pipeline execution. Total time is proportional to the sum of processing times for all chunks.
*   **Memory Complexity:** Bounded by the memory required for a single chunk plus the memory for the output multi-block dataset. This allows processing datasets larger than available RAM.
*   **Strengths:** Enables processing of datasets that do not fit in memory by breaking them into manageable spatial chunks.
*   **Limitations:** The output data structure (multi-block) may be more complex to consume than a single contiguous dataset. Processing filters may generate output larger than input, risking memory issues if not managed [S1, unofficial].
*   **When to use:** When the input dataset is too large to fit in memory and the processing algorithm can operate on spatial subsets independently.
*   **When not to use:** When the processing algorithm requires global context or communication between spatial regions that cannot be easily decomposed.

## Background
Originated in the Visualization Toolkit (VTK) as part of the Streaming Demand Driven Pipeline model. Introduced by Berk Geveci in 2014 to address the need for processing large spatial datasets that exceed memory capacity [S1, unofficial]. It builds on the concepts of temporal streaming previously covered in VTK documentation [S1, unofficial].
