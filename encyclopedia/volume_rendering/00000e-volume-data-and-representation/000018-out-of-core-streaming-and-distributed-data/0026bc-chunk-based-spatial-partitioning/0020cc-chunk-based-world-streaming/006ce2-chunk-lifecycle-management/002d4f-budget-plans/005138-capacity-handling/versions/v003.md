# Capacity Handling

Also called: Block Quota Rounding, Budget Assignment, Integer Budget Allocation

## Overview
Capacity Handling is the procedure that converts continuous block retention quotas into integer budgets $K_b$ that sum exactly to a global target $K$, while respecting individual block capacities $n_b$ [S1, unofficial]. It solves the problem of discretizing soft allocation scores into hard chunk limits for out-of-core streaming, ensuring the total retained Gaussian count matches the budget without exceeding per-block storage limits [S1, unofficial].

## How it works
**Inputs:** $N$ total Gaussians, $B$ disjoint blocks $C_b$, block capacities $n_b$, target retained count $K$, diagonal importance scores $D_i$, smoothing parameter $\beta > 0$, and pseudocount $\epsilon_a > 0$ [S1, unofficial].

**Outputs:** Integer budget $K_b$ for each block $b$, satisfying $0 \le K_b \le n_b$ and $\sum_b K_b = K$ [S1, unofficial].

**Data Structures:** Block list as an array of blocks indexed $b=1 \dots B$, Gaussian list as an array of Gaussians indexed $i=1 \dots N$, and a scores array $D$ of size $N$ [S1, unofficial].

**Steps:**

1.  **Initial Top-K Counting:** Rank all $N$ Gaussians by $D_i$ descending, resolving ties by global Gaussian index [S1, unofficial]. Identify the global Top-$K$ indices and count how many fall into each block: $K'_b = |C_b \cap \text{Top-}K \{D_i\}_{i=1}^N|$ [S1, unofficial]. This satisfies $\sum_b K'_b = K$ [S1, unofficial].
2.  **Logarithmic Smoothing:** Compute smoothed continuous quotas $\tilde{K}_b$ to reduce retention disparity across blocks [S1, unofficial]. Calculate $r_b = \frac{K'_b}{(K/N)n_b + \epsilon_a}$, which compares the initial quota to the proportional quota $(K/N)n_b$ [S1, unofficial]. Then compute $\tilde{K}_b = K \frac{n_b \log(1 + \beta r_b)}{\sum_{b'=1}^B n_{b'} \log(1 + \beta r_{b'})}$ [S1, unofficial]. Increasing $\beta$ reduces disparities among block retention ratios [S1, unofficial].
3.  **Clipping and Initialization:** Clip continuous quotas to valid bounds and initialize integer budgets by flooring: $\hat{K}_b = \min\{n_b, \max(0, \tilde{K}_b)\}$ and $K_b \leftarrow \lfloor \hat{K}_b \rfloor$ [S1, unofficial].
4.  **Residual Allocation:** Calculate remaining budget $H = K - \sum_b K_b$ and fractional residuals $f_b = \hat{K}_b - K_b$ [S1, unofficial]. While $H > 0$, identify eligible blocks where $K_b < n_b$, sort them by descending $f_b$ with ties broken by block index, and assign one unit to the first $\min(H, \text{number of eligible blocks})$ blocks [S1, unofficial]. Update $H$ and $f_b$ for affected blocks and repeat until $H = 0$ [S1, unofficial]. If no quota is clipped, one pass reduces to standard largest-remainder rounding; clipping can create a larger deficit requiring multiple passes [S1, unofficial].

**Pseudocode:**

```python
import math

def capacity_handling(gaussians, blocks, K, beta, epsilon_a):
    """
    gaussians: list of dicts/objects with keys 'id', 'D', 'block_id'
    blocks: list of dicts/objects with keys 'id', 'capacity'
    K: int, target total retained count
    beta: float, smoothing parameter > 0
    epsilon_a: float, pseudocount > 0
    Returns: dict mapping block_id to integer budget K_b
    """
    N = len(gaussians)
    B = len(blocks)
    
    # Step 1: Initial Top-K Counting
    sorted_gaussians = sorted(gaussians, key=lambda g: (-g['D'], g['id']))
    top_k_ids = set(g['id'] for g in sorted_gaussians[:K])
    
    initial_quotas = {b['id']: 0 for b in blocks}
    for g in gaussians:
        if g['id'] in top_k_ids:
            initial_quotas[g['block_id']] += 1
            
    # Step 2: Logarithmic Smoothing
    proportional_base = K / N
    denom_sum = 0.0
    r_values = {}
    
    for b in blocks:
        n_b = b['capacity']
        K_prime = initial_quotas[b['id']]
        r_b = K_prime / (proportional_base * n_b + epsilon_a)
        r_values[b['id']] = r_b
        denom_sum += n_b * math.log(1 + beta * r_b)
        
    continuous_quotas = {}
    for b in blocks:
        n_b = b['capacity']
        r_b = r_values[b['id']]
        continuous_quotas[b['id']] = K * (n_b * math.log(1 + beta * r_b)) / denom_sum
        
    # Step 3: Clipping and Initialization
    integer_budgets = {}
    clipped_quotas = {}
    
    for b in blocks:
        b_id = b['id']
        n_b = b['capacity']
        k_tilde = continuous_quotas[b_id]
        k_hat = min(n_b, max(0.0, k_tilde))
        clipped_quotas[b_id] = k_hat
        integer_budgets[b_id] = int(math.floor(k_hat))
        
    # Step 4: Residual Allocation
    current_sum = sum(integer_budgets.values())
    H = K - current_sum
    
    while H > 0:
        eligible = []
        for idx, b in enumerate(blocks):
            b_id = b['id']
            if integer_budgets[b_id] < b['capacity']:
                f_b = clipped_quotas[b_id] - integer_budgets[b_id]
                eligible.append((b_id, f_b, idx))
                
        if not eligible:
            break
            
        eligible.sort(key=lambda x: (-x[1], x[2]))
        num_assign = min(H, len(eligible))
        
        for i in range(num_assign):
            b_id = eligible[i][0]
            integer_budgets[b_id] += 1
            H -= 1
            
    return integer_budgets
```

**Edge Cases and Pitfalls:**
- **Zero Initial Quotas:** Blocks with no Top-$K$ members get $K'_b=0$, which is handled by $\epsilon_a$ to prevent division by zero or $\log(0)$ in the smoothing step [S1, unofficial].
- **Capacity Overflow:** If smoothing assigns a quota $> n_b$, it is clipped, creating a deficit $H$ that must be redistributed across multiple passes [S1, unofficial].
- **Tie Breaking:** Global index is used for Gaussian ranking ties, while block index is used for residual allocation ties [S1, unofficial].

## Subtopics

### Deterministic Integer Allocation
A deterministic method to convert expected Gaussian counts $B p_n$ into integer allocations $k_n^\bullet$ for $N$ anchors, ensuring the total count sums exactly to budget $B$ without sorting or ties [S2, unofficial]. It uses systematic rounding with a fixed phase $\phi = 1/2$ [S2, unofficial].
- **Definition:** Converts probabilities $p_n$ to integers $k_n^\bullet$ such that $\sum k_n^\bullet = B$ [S2, unofficial].
- **Method:** Compute cumulative probabilities $P_n = \sum_{m \le n} p_m$ with $P_0=0$. Calculate $k_n^\bullet = \lfloor B P_n - \phi \rfloor - \lfloor B P_{n-1} - \phi \rfloor$ using double precision [S2, unofficial].
- **Properties:** Counts sum exactly to $B$ due to telescoping sum; each count is either $\lfloor B p_n \rfloor$ or $\lceil B p_n \rceil$; anchors with $p_n=0$ receive 0 [S2, unofficial].
- **Complexity:** $O(N)$ time, no sorting required [S2, unofficial].
- **Parameters:** Budget floor $B/N$ is floored at $1/64$ to keep log-ratio $u$ finite [S2, unofficial].

## Operating characteristics
- **Time Complexity:** The primary Capacity Handling method involves sorting Gaussians ($O(N \log N)$) and potentially multiple passes over blocks for residual allocation [S1, unofficial]. The Deterministic Integer Allocation variant is $O(N)$ [S2, unofficial].
- **Memory Complexity:** Requires storage for scores, quotas, and block capacities, totaling $O(N + B)$ [S1, unofficial][S2, unofficial].
- **Strengths:** Ensures strict adherence to global budget $K$ and per-block capacities $n_b$ [S1, unofficial]. Smoothing reduces imbalance caused by global Top-K selection [S1, unofficial]. Deterministic variant avoids non-determinism from sorting ties [S2, unofficial].
- **Limitations:** Clipping can necessitate multiple passes in the primary method [S1, unofficial]. Smoothing parameters $\beta$ and $\epsilon_a$ require tuning [S1, unofficial].
- **When to use:** Use when chunk-based streaming requires strict integer budgets per block to manage memory limits [S1, unofficial]. Use Deterministic Integer Allocation when a fast, tie-free, deterministic conversion from probabilities to counts is needed [S2, unofficial].

## Background
Capacity Handling originates from the SplatQ method for pruning 3D Gaussian Splatting, where it serves as the final step in budget assignment after similarity-guided partitioning and quadratic selection [S1, unofficial]. It addresses the impracticality of global quadratic optimization for millions of Gaussians by partitioning the problem into blocks [S1, unofficial]. The Deterministic Integer Allocation variant appears in RLSplat for resource-linear budget control in feed-forward 3D Gaussian Splatting [S2, unofficial].
