# Distance-based Chunk Culling

Also called: Chunk Update & Render Culling, Distance-based Culling for Chunk Updates, HiddeRemoveChunk, HideRemoveChunk

## Overview
Distance-based Chunk Culling manages memory and rendering load by deactivating or destroying chunks based on their distance from the player [S1, S2, unofficial]. It complements Frustum Culling & Distance Sorting by handling the lifecycle of chunks that are outside the view frustum but still within the world bounds, specifically optimizing update costs for distant geometry [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Player position ($P$), chunk dictionary ($ChunkDict$), chunk geometry parameters ($CHUNK\_SIDE$), view distance parameter ($chunkViewDistance$), and modification state flags.
- Output: Updated chunk states (Active, Deactivated, Destroyed) and modified mesh update flags.

**Data Structures:**
- `ChunkDict`: A map or dictionary storing active chunks. Key: Chunk identifier (e.g., coordinates). Value: Chunk object containing `transform.position` (world position), `isModified` flag, and `meshUpdated` flag.
- `Chunk Object`:
  - `transform.position`: Vector3 $(x, y, z)$ representing the chunk's center or origin in world space.
  - `isModified`: Boolean indicating if the chunk's data has changed since the last render/update.
  - `meshUpdated`: Boolean indicating if the mesh has been regenerated.

**Parameters:**
- $CHUNK\_SIDE$: The physical side length of a chunk in world units.
- $chunkViewDistance$: A multiplier defining the visible range in chunks.
- $hideDistance$: Threshold for deactivating chunks. Calculated as:
  $$hideDistance = CHUNK\_SIDE \times chunkViewDistance$$
- $removeDistance$: Threshold for destroying chunks. Calculated as:
  $$removeDistance = hideDistance + (hideDistance \times chunkMantainDistance)$$
  Note: $chunkMantainDistance$ is a multiplier for the removal buffer. If not specified, the exact formula for the buffer is not given in the sources [S1, unofficial].
- $minRenderUpdate$: Border ignore threshold for update culling. Default 0. Increases to 1 or 2 if the chunk is on a map border [S2, unofficial].
- $renderDist$: The rendering distance in chunks (implied by context in S2).
- $CHUNK\_SZ\_X$: The chunk size in the X dimension (often equal to $CHUNK\_SIDE$) [S2, unofficial].

**Steps:**
1. **Calculate Distance:** For each chunk $C$ in $ChunkDict$, calculate the Euclidean distance in the XZ plane from the player position $P_{xz}$ to the chunk position $C_{pos.xz}$:
   $$d = \sqrt{(P_x - C_{pos.x})^2 + (P_z - C_{pos.z})^2}$$
   [S1, unofficial]

2. **Update Logic (if chunk is modified):**
   - Check if the chunk's data is modified (`_data.isModified`).
   - If not modified, skip update processing [S2, unofficial].
   - If modified:
     - Set `_data.isModified` to false.
     - Regenerate the mesh (e.g., `calcGreedyChunk()`) [S2, unofficial].
     - Set `_meshUpdated` to true [S2, unofficial].

3. **Culling Logic:**
   - If $d > hideDistance$ and the chunk is currently active:
     - Deactivate the chunk [S1, unofficial].
   - If $d > removeDistance$:
     - Destroy the chunk (remove from memory and dictionary) [S1, unofficial].

4. **Render Update Culling (Optimization):**
   - Determine if a chunk needs a render update based on its position relative to the camera's view range [S2, unofficial].
   - Calculate `minRenderUpdate` (default 0) [S2, unofficial].
   - Check if the chunk's X position is outside the camera's effective render range:
     $$RangeX = [startX, startX + ((renderDist - 1) \times 2) \times CHUNK\_SZ\_X]$$
     If outside, increment `minRenderUpdate` [S2, unofficial].
   - Apply the same logic for the Z position [S2, unofficial].
   - If the chunk's `_needRenderUpdate` count exceeds `minRenderUpdate`:
     - Set `_data.isModified` to true to trigger a mesh regeneration in the next frame [S2, unofficial].

**Pseudocode:**
```python
def process_chunk_culling(player_pos, chunk_dict, chunk_side, chunk_view_distance, chunk_maintain_distance, render_dist, chunk_sz_x, start_x):
    hide_distance = chunk_side * chunk_view_distance
    remove_distance = hide_distance + (hide_distance * chunk_maintain_distance)
    
    chunks_to_remove = []
    
    for chunk_id, chunk in chunk_dict.items():
        # 1. Calculate XZ distance
        dx = player_pos.x - chunk.transform.position.x
        dz = player_pos.z - chunk.transform.position.z
        distance_xz = sqrt(dx*dx + dz*dz)
        
        # 2. Handle modification and mesh update
        if chunk.data.is_modified:
            chunk.data.is_modified = False
            chunk.calc_greedy_chunk() # Regenerate mesh
            chunk.mesh_updated = True
            
            # 4. Render Update Culling Logic
            min_render_update = 0
            # Check X bounds
            x_min = start_x
            x_max = start_x + ((render_dist - 1) * 2 * chunk_sz_x)
            if not (x_min <= chunk.transform.position.x <= x_max):
                min_render_update += 1
            
            # Check Z bounds (assuming similar structure for Z)
            # Note: Source S2 implies similar logic for Z but does not explicitly define Z start/max variables.
            # Assuming symmetric or similar bounds for demonstration.
            # In a real implementation, Z bounds would be defined.
            # [G] Placeholder for Z bounds logic as per S2 description
            z_min = start_x # Placeholder, should be Z start
            z_max = start_x + ((render_dist - 1) * 2 * chunk_sz_x) # Placeholder
            if not (z_min <= chunk.transform.position.z <= z_max):
                min_render_update += 1
                
            if chunk.need_render_update > min_render_update:
                chunk.data.is_modified = True
        else:
            # Skip update if not modified
            pass
            
        # 3. Culling based on distance
        if distance_xz > hide_distance and chunk.is_active:
            chunk.deactivate()
            
        if distance_xz > remove_distance:
            chunks_to_remove.append(chunk_id)
            
    for chunk_id in chunks_to_remove:
        del chunk_dict[chunk_id]
```

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point errors in distance calculations may cause jittering at the boundary of $hideDistance$ or $removeDistance$. [G] Consider using a small epsilon or hysteresis.
- **Boundary Conditions:** The render update culling relies on `startX` and `renderDist`. If these are not correctly aligned with the chunk grid, chunks may be incorrectly marked as needing updates or skipped. [S2, unofficial]
- **Degenerate Input:** If $chunkViewDistance$ is 0, $hideDistance$ is 0, and all chunks are deactivated immediately. [G]
- **Missing Z Bounds:** Source S2 describes X and Z logic for `minRenderUpdate` but does not explicitly provide the Z start and max variables. The pseudocode assumes symmetry or requires external definition. [S2, unofficial]

## Operating characteristics
- **Time Complexity:** $O(N)$ per frame, where $N$ is the number of active chunks, as each chunk must be iterated to check distance and modification state.
- **Memory Complexity:** $O(N)$ for storing active chunks. Deactivation and destruction reduce memory usage over time as the player moves away from generated areas.
- **Performance:** Significantly reduces rendering and update load by skipping distant chunks. The optimization of skipping updates for chunks outside the render range (S2) further reduces CPU cost for mesh regeneration.
- **Strengths:** Effective memory management in large open worlds. Prevents unnecessary computation for invisible geometry.
- **Limitations:** Requires careful tuning of $hideDistance$ and $removeDistance$ to avoid pop-in or excessive memory churn. The XZ-only distance calculation ignores Y, which may be insufficient for verticality in some scenes. [S1, unofficial]

## Background
Distance-based culling is a standard technique in game engines and voxel-based applications to manage large datasets. In the context of voxel rendering, it is often paired with frustum culling to handle chunks that are outside the view but still within the world. The specific implementation details provided here are derived from community-driven projects using Unity and C++.
