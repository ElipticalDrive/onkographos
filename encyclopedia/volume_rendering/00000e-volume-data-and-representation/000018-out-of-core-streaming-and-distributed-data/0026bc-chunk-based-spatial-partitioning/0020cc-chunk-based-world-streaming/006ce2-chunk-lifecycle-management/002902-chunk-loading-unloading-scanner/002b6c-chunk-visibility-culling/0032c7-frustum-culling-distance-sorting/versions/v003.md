# Frustum Culling & Distance Sorting

Also called: Chunk Visibility Culling with Distance Sorting

## Overview
This method filters visible chunks and sorts them by distance for rendering order [S1, unofficial]. It determines which chunks intersect the view frustum and orders them to support depth-sorted compositing or nearest-first data streaming [S1, S2, unofficial]. It differs from [Octree Frustum Culling & LOD Selection](5771-octree-frustum-culling-lod-selection.md) by operating on a flat list of chunks rather than a hierarchical tree, and from [Out-of-Core Frustum Clipping](6688-out-of-core-frustum-clipping.md) by focusing on discrete chunk visibility and sorting rather than continuous geometric clipping [S1, S2, unofficial].

## How it works
**Inputs:** Camera view and projection matrices; list of active chunks with world positions; camera position.
**Outputs:** Sorted list of visible chunks.

**Data Structures:**
- `Chunk`: Contains world position fields `GetXWorldPos()` and `GetZWorldPos()` [S1, unofficial].
- `Frustum`: Constructed from view and projection matrices [S1, unofficial].
- `m_LastCamChunkPos`: Tracks the camera's current chunk position to avoid unnecessary sorting [S1, unofficial].

**Steps:**
1. **Construct Frustum:** Create the view frustum from the current projection and view matrices [S1, unofficial].
2. **Check Chunk Change:** Compute the camera's current chunk position. If `m_LastCamChunkPos` differs from the current position, proceed to rebuild the ordered list; otherwise, skip sorting [S1, unofficial].
3. **Filter Visible Chunks:** Iterate through all chunks. For each chunk, check if it is ready (`IsMeshReady()`) and if it intersects the frustum (`frustum.IsChunkInFrustum(wx, wz)`) [S1, unofficial].
4. **Sort Chunks:** Sort the visible chunks using a distance comparison [S1, unofficial]. The sorting logic uses squared Euclidean distance in the XZ plane [S1, unofficial]:
   - Calculate squared distance for chunk A: $d_A = \text{glm::vec2}(a \to \text{GetXWorldPos}(), a \to \text{GetZWorldPos}()) - \text{CamPos}$, then $\text{distSq}_A = \text{glm::dot}(d_A, d_A)$ [S1, unofficial].
   - Calculate squared distance for chunk B: $d_B = \text{glm::vec2}(b \to \text{GetXWorldPos}(), b \to \text{GetZWorldPos}()) - \text{CamPos}$, then $\text{distSq}_B = \text{glm::dot}(d_B, d_B)$ [S1, unofficial].
   - Compare: Return true if $\text{distSq}_A > \text{distSq}_B$ to sort in descending order (farthest first) [S1, unofficial].

**Pitfalls:**
- **2D Distance:** The sorting uses only X and Z coordinates, ignoring Y. This assumes chunks are sorted on the horizontal plane [S1, unofficial].
- **Precision:** Using squared distance avoids square root computation but requires consistent coordinate scaling [S1, unofficial].

**Pseudocode:**
```python
def update_chunk_visibility(camera, chunks, last_cam_chunk_pos):
    # 1. Construct frustum from view and projection matrices [S1, unofficial]
    frustum = create_frustum(camera.view_matrix, camera.projection_matrix)
    
    # 2. Compute camera chunk position [S1, unofficial]
    current_cam_chunk_pos = get_camera_chunk_position(camera.position)
    
    # 3. If camera chunk changed, rebuild ordered list [S1, unofficial]
    if current_cam_chunk_pos != last_cam_chunk_pos:
        visible_chunks = []
        
        # 4. Iterate chunks, check IsMeshReady() and frustum.IsChunkInFrustum(wx, wz) [S1, unofficial]
        for chunk in chunks:
            if chunk.is_mesh_ready() and frustum.is_chunk_in_frustum(chunk.wx, chunk.wz):
                visible_chunks.append(chunk)
        
        # 5. Sort chunks using std::sort with distance comparison [S1, unofficial]
        # Sorting logic: Descending order by squared XZ distance [S1, unofficial]
        visible_chunks.sort(key=lambda c: squared_xz_distance(c, camera.position), reverse=True)
        
        last_cam_chunk_pos = current_cam_chunk_pos
        
    return visible_chunks, last_cam_chunk_pos

def squared_xz_distance(chunk, camera_pos):
    # 1. Calculate squared distance from camera to chunk A: dA = glm::vec2(a->GetXWorldPos(), a->GetZWorldPos()) - CamPos, then distSqA = glm::dot(dA, dA) [S1, unofficial]
    dx = chunk.get_x_world_pos() - camera_pos.x
    dz = chunk.get_z_world_pos() - camera_pos.z
    return dx * dx + dz * dz
```

## Subtopics

### Chunk Sorting by Distance
Sorts chunks based on their distance to the camera, likely for depth sorting or LOD selection [S1, unofficial]. It uses squared XZ distance for efficiency [S1, unofficial]. Choose this when horizontal plane sorting is sufficient and Y-axis variation is negligible [S1, unofficial].

### Nearest-First Downloads and Empty-Space Skipping
A data streaming strategy where chunks are requested in order of distance from the camera, and chunks whose brightest voxel is below a threshold are skipped entirely [S2, unofficial]. Choose this for out-of-core streaming to prioritize visible data and skip empty regions [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ for sorting $N$ visible chunks [S1, unofficial]. Frustum culling is $O(N)$ [S1, unofficial].
- **Memory Complexity:** $O(N)$ to store visible chunk references [S1, unofficial].
- **Performance:** Avoids unnecessary sorting by tracking camera chunk position [S1, unofficial].
- **Strengths:** Simple to implement; efficient for flat chunk lists [S1, unofficial].
- **Limitations:** Ignores Y-axis for distance sorting [S1, unofficial]; does not handle hierarchical culling [S1, unofficial].
- **When to use:** When chunks are flat and horizontal sorting is sufficient [S1, unofficial].
- **When not to use:** When Y-axis depth is critical or chunks are hierarchical [S1, unofficial].
