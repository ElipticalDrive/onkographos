# Synchronous Chunk Loading

Also called: ForceLoadChunksAt

## Overview
Synchronous Chunk Loading is a method for ensuring that a specific region of a voxel world is fully generated and rendered before the calling thread proceeds. It solves the problem of visual popping or missing geometry when a player or camera enters a previously unloaded area by forcing the immediate generation of a 3x3 grid of chunks centered on a target world position [S1, unofficial]. Unlike asynchronous approaches, this method blocks execution until all required data is processed, guaranteeing consistency at the cost of potential frame stalls [S1, unofficial].

## How it works
**Inputs:**
- `WorldPos`: The 3D world coordinate to center the loading grid on [S1, unofficial].
- `WorldMesh`: The actor or object responsible for rendering and managing chunk meshes [S1, unofficial].
- `ActiveChunks`: A set or map tracking currently active/loaded chunk indices [S1, unofficial].
- `ChunkCache`: A storage structure holding generated chunk data [S1, unofficial].
- `ModifiedBlocks`: A collection of pending modifications to apply to generated data [S1, unofficial].
- `GenParams`: Parameters passed to the world generator [S1, unofficial].

**Data Structures:**
- `ActiveChunks`: Stores chunk indices (e.g., `FIntPoint` or `Vector2i`) that are currently rendered and have collision enabled [S1, unofficial].
- `ChunkCache`: Maps chunk indices to their generated data structures [S1, unofficial].
- `ModifiedBlocks`: Stores modifications keyed by chunk or block coordinates [S1, unofficial].

**Steps:**
1. **Validate World Mesh:** Check if `WorldMesh` exists. If it is null or invalid, terminate the function immediately [S1, unofficial].
2. **Calculate Center Index:** Convert the input `WorldPos` to a chunk index using the world-to-chunk conversion function:
   $$ Center = \text{WorldToChunkIndex}(WorldPos) $$
   [S1, unofficial]
3. **Iterate Grid:** Loop through a 3x3 grid relative to the center. Let $DX$ range from $-1$ to $1$ and $DY$ range from $-1$ to $1$ [S1, unofficial].
4. **Check Activity:** Calculate the current index:
   $$ Index = (Center.X + DX, Center.Y + DY) $$
   [S1, unofficial]
   If `Index` is already present in `ActiveChunks`, skip to the next iteration [S1, unofficial].
5. **Generate Data:** If `Index` is not in `ChunkCache`, generate the chunk data:
   $$ Data = \text{FWorldGenerator::GenerateChunk}(GenParams, Index) $$
   [S1, unofficial]
6. **Apply Modifications:** Apply any pending changes from `ModifiedBlocks` to the newly generated `Data` [S1, unofficial].
7. **Cache Data:** Store the processed `Data` in `ChunkCache` keyed by `Index` [S1, unofficial].
8. **Prepare Mesh:** Retrieve the data from `ChunkCache` and prepare the mesh:
   $$ Mesh = \text{AWorldMeshActor::PrepareChunkMesh}(Data) $$
   [S1, unofficial]
9. **Apply and Enable:**
   - Apply the mesh to the world: `WorldMesh->ApplyChunk(Index, Mesh)` [S1, unofficial].
   - Enable collision for the chunk: `WorldMesh->EnableCollision(Index)` [S1, unofficial].
   - Add `Index` to `ActiveChunks` [S1, unofficial].

**Pseudocode:**
```python
def SynchronousChunkLoading(WorldPos, WorldMesh, ActiveChunks, ChunkCache, ModifiedBlocks, GenParams):
    # Step 1: Validate World Mesh
    if WorldMesh is None:
        return

    # Step 2: Calculate Center Index
    Center = WorldToChunkIndex(WorldPos)

    # Step 3: Iterate Grid
    for DX in range(-1, 2):
        for DY in range(-1, 2):
            # Step 4: Calculate Index and Check Activity
            Index = (Center.X + DX, Center.Y + DY)
            if Index in ActiveChunks:
                continue

            # Step 5: Generate Data if not in Cache
            if Index not in ChunkCache:
                Data = FWorldGenerator_GenerateChunk(GenParams, Index)
                
                # Step 6: Apply Modifications
                Data = ApplyModifiedBlocks(Data, ModifiedBlocks)
                
                # Step 7: Cache Data
                ChunkCache[Index] = Data
            
            # Step 8: Prepare Mesh
            Data = ChunkCache[Index]
            Mesh = AWorldMeshActor_PrepareChunkMesh(Data)
            
            # Step 9: Apply and Enable
            WorldMesh_ApplyChunk(WorldMesh, Index, Mesh)
            WorldMesh_EnableCollision(WorldMesh, Index)
            ActiveChunks.add(Index)
```

**Parameters:**
- `GenParams`: Configuration for the voxel generator (e.g., noise seeds, density thresholds). Typical values depend on the specific world generation algorithm [S1, unofficial].
- `WorldPos`: Player or camera position. Typically updated every frame or when significant movement occurs [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Null World Mesh:** If `WorldMesh` is not initialized, the function returns early to prevent crashes [S1, unofficial].
- **Already Active:** Checking `ActiveChunks` prevents redundant generation and mesh creation [S1, unofficial].
- **Blocking:** Since this is synchronous, large generation times or heavy mesh preparation can cause frame drops or stuttering [S1, unofficial].

## Subtopics

### Progressive Splat Loading (Direct to Uncompressed Array)
This variant loads chunk data directly into an uncompressed array structure rather than generating meshes immediately. It initializes an `UncompressedSplatArray` and copies incoming chunks into a `directLoadBufferIn`. Once a sufficient number of bytes are loaded, it parses the splats into a `standardLoadUncompressedSplatArray` [S2, unofficial]. This approach is suitable for point-based rendering (e.g., Gaussian Splatting) where raw data processing precedes visualization [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per chunk in terms of grid size (always 9 chunks), but the constant factor depends on the cost of `GenerateChunk` and `PrepareChunkMesh`. In the worst case, all 9 chunks must be generated from scratch.
- **Memory Complexity:** $O(1)$ additional memory per chunk for the cache and mesh structures.
- **Performance:** Guarantees that the 3x3 area is visible and collidable immediately after the call returns. However, it introduces latency spikes if chunk generation is expensive [S1, unofficial].
- **Strengths:** Simple to implement; ensures no visual gaps during rapid movement or teleportation; deterministic state [S1, unofficial].
- **Limitations:** Blocks the main thread; not suitable for very large worlds or high-frequency updates without causing stutter [S1, unofficial].
- **When to use:** When immediate visual consistency is critical and the chunk generation cost is low enough to fit within a frame budget [S1, unofficial].
- **When not to use:** When the world is vast, chunk generation is complex, or smooth streaming is required without blocking [S1, unofficial].

## Background
This method is derived from the `VoxelWorld` implementation by HawkDev15, which uses a synchronous approach to load chunks around the player position in a voxel-based game environment [S1, unofficial]. It is commonly used in Unreal Engine-based voxel projects where simplicity and immediate feedback are prioritized over streaming performance [S1, unofficial].
