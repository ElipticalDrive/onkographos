# Synchronous Chunk Loading

Also called: ForceLoadChunksAt

## Overview
Synchronous Chunk Loading is a method for ensuring that the 3x3 grid of chunks surrounding a specific world position is generated, cached, and rendered immediately. It solves the problem of missing or incomplete geometry when a player or camera moves into an ungenerated area by blocking execution until the local data is ready. It differs from asynchronous variants by performing all generation and mesh preparation on the calling thread, guaranteeing visual consistency at the cost of potential frame stalls during initial generation.

## How it works
**Inputs:**
- `WorldPos`: The 3D world coordinate to center the loading grid on.
- `WorldMesh`: A reference to the actor or manager responsible for rendering chunk meshes.
- `ChunkCache`: A data structure mapping chunk indices to generated chunk data.
- `ActiveChunks`: A set or list of chunk indices currently rendered and enabled.
- `ModifiedBlocks`: A collection of pending block modifications to apply to generated data.
- `GenParams`: Parameters passed to the chunk generator (e.g., seed, noise settings).

**Data Structures:**
- `ChunkIndex`: A 2D coordinate pair `(X, Y)` representing the chunk grid position.
- `ChunkData`: The raw voxel or geometry data generated for a chunk.
- `ChunkMesh`: The prepared renderable mesh for a single chunk.

**Steps:**
1. **Validation:** Check if `WorldMesh` exists. If not, terminate the function. [S1, unofficial]
2. **Center Calculation:** Compute the center chunk index for the given world position:
   $$ \text{Center} = \text{WorldToChunkIndex}(\text{WorldPos}) $$
   [S1, unofficial]
3. **Iteration:** Loop through a 3x3 grid relative to the center. Let $DX$ range from $-1$ to $1$ and $DY$ range from $-1$ to $1$.
4. **Index Calculation:** For each iteration, calculate the target chunk index:
   $$ \text{Index} = (\text{Center}.X + DX, \text{Center}.Y + DY) $$
   [S1, unofficial]
5. **Skip Active:** If `Index` is present in `ActiveChunks`, continue to the next iteration. [S1, unofficial]
6. **Generation:** If `Index` is not in `ChunkCache`, generate the chunk data:
   $$ \text{Data} = \text{FWorldGenerator::GenerateChunk}(\text{GenParams}, \text{Index}) $$
   [S1, unofficial]
7. **Modification:** Apply any pending changes from `ModifiedBlocks` to the generated `Data`. [S1, unofficial]
8. **Caching:** Store the processed `Data` in `ChunkCache` under `Index`. [S1, unofficial]
9. **Mesh Preparation:** Retrieve `Data` from `ChunkCache` and prepare the mesh:
   $$ \text{Mesh} = \text{AWorldMeshActor::PrepareChunkMesh}(\text{Data}) $$
   [S1, unofficial]
10. **Application:** Apply the mesh to the world:
    $$ \text{WorldMesh} \rightarrow \text{ApplyChunk}(\text{Index}, \text{Mesh}) $$
    [S1, unofficial]
11. **Collision:** Enable collision for the chunk:
    $$ \text{WorldMesh} \rightarrow \text{EnableCollision}(\text{Index}) $$
    [S1, unofficial]
12. **Activation:** Add `Index` to `ActiveChunks`. [S1, unofficial]

**Pseudocode:**
```python
def SynchronousChunkLoading(WorldPos, WorldMesh, ChunkCache, ActiveChunks, ModifiedBlocks, GenParams):
    # Step 1: Validation
    if WorldMesh is None:
        return

    # Step 2: Center Calculation
    Center = WorldToChunkIndex(WorldPos)

    # Step 3-4: Iteration and Index Calculation
    for DX in range(-1, 2):
        for DY in range(-1, 2):
            Index = (Center.X + DX, Center.Y + DY)

            # Step 5: Skip Active
            if Index in ActiveChunks:
                continue

            # Step 6: Generation
            if Index not in ChunkCache:
                Data = FWorldGenerator.GenerateChunk(GenParams, Index)

                # Step 7: Modification
                Data = ApplyModifications(Data, ModifiedBlocks)

                # Step 8: Caching
                ChunkCache[Index] = Data
            else:
                Data = ChunkCache[Index]

            # Step 9: Mesh Preparation
            Mesh = AWorldMeshActor.PrepareChunkMesh(Data)

            # Step 10: Application
            WorldMesh.ApplyChunk(Index, Mesh)

            # Step 11: Collision
            WorldMesh.EnableCollision(Index)

            # Step 12: Activation
            ActiveChunks.add(Index)
```

**Parameters:**
- `WorldPos`: The player or camera position.
- `GenParams`: Generator configuration. Typical values depend on the specific world generator implementation. [S1, unofficial]

**Edge Cases:**
- **Missing WorldMesh:** The function returns immediately if the mesh actor is not initialized. [S1, unofficial]
- **Degenerate Input:** If `WorldPos` is invalid, `WorldToChunkIndex` behavior is undefined. [G]

## Subtopics

### [Progressive Splat Loading (Direct to Uncompressed Array)](7122-progressive-splat-loading-direct-to-uncompressed-array.md)
Progressive Splat Loading is a method for ingesting chunk-based splat data into an uncompressed array during synchronous chunk loading, enabling immediate rendering of available data without waiting for full chunk assembly. It differs from standard chunk loading by parsing splats directly from a streaming buffer into a global array as bytes arrive, rather than holding them in a temporary structure until the entire chunk is received. This reduces latency for initial visibility but requires careful management of partial data and memory layout.

## Operating characteristics
- **Time Complexity:** $O(1)$ relative to the world size, but $O(N)$ relative to the chunk generation cost, where $N$ is the number of ungenerated chunks in the 3x3 grid. Since it is synchronous, the calling thread blocks until all chunks are generated and meshed.
- **Memory Complexity:** $O(1)$ additional memory per chunk generated, stored in `ChunkCache`.
- **Performance:** Measured performance depends on the cost of `FWorldGenerator::GenerateChunk` and `PrepareChunkMesh`. On typical hardware, this may cause frame drops if generation is heavy. [S1, unofficial]
- **Strengths:** Guarantees that the local area is fully rendered and collision-enabled before returning. Simple to implement and debug.
- **Limitations:** Can cause stuttering or frame pauses if chunks are not pre-cached. Not suitable for real-time streaming in large worlds without asynchronous support.
- **When to use:** When immediate visual consistency is required for a small area, or during level initialization.
- **When not to use:** When streaming large worlds with high-latency storage or heavy generation costs.

## Background
This method is derived from the `VoxelWorld` project by HawkDev15, which implements a voxel-based world generation system in Unreal Engine. The specific function `ForceLoadChunksAt` is used to ensure chunks around the player are loaded synchronously. [S1, unofficial]
