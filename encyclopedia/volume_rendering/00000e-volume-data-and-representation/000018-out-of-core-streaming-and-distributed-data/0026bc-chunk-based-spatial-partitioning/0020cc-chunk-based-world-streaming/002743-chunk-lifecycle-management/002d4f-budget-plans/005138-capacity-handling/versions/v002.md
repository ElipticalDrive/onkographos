# Capacity Handling

Also called: Block Quota Rounding, Budget Assignment, Integer Budget Allocation

## Overview
Capacity Handling is the procedure that converts continuous block retention quotas into integer budgets $K_b$ that sum exactly to a global target $K$, while respecting individual block capacities $n_b$ [S1, unofficial]. It solves the problem of discretizing soft allocation scores into hard chunk limits for out-of-core streaming, ensuring the total retained Gaussian count matches the budget without exceeding per-block storage limits [S1, unofficial]. It differs from sibling methods like [Block Loading Badges](6011-block-loading-badges.md) by focusing on the mathematical conversion of smoothed diagonal scores into strict integer counts rather than dynamic loading flags [S1, S2, unofficial].

## How it works
**Inputs:**
- $N$: Total number of Gaussians.
- $B$: Number of disjoint blocks $C_b$.
- $n_b$: Capacity (maximum number of Gaussians) of block $b$.
- $K$: Target global retained count.
- $D_i$: Diagonal importance scores for each Gaussian $i$ [S1, unofficial].
- $\beta$: Smoothing parameter ($\beta > 0$) [S1, unofficial].
- $\epsilon_a$: Pseudocount for zero initial quotas ($\epsilon_a > 0$) [S1, unofficial].

**Outputs:**
- $K_b$: Integer budget for each block $b$, such that $0 \le K_b \le n_b$ and $\sum_b K_b = K$ [S1, unofficial].

**Data Structures:**
- Block list: Array of blocks indexed $b=1 \dots B$.
- Gaussian list: Array of Gaussians indexed $i=1 \dots N$.
- Scores: Array $D$ of size $N$.

**Steps:**

1.  **Initial Top-K Counting:**
    Rank all $N$ Gaussians by their diagonal scores $D_i$ in descending order. Resolve ties using the global Gaussian index. Identify the set of indices for the global Top-$K$ members. For each block $b$, count the number of these Top-$K$ members contained within the block:
    $$ K'_b = |C_b \cap \text{Top-}K \{D_i\}_{i=1}^N| $$
    This initial count satisfies $\sum_b K'_b = K$ [S1, unofficial].

2.  **Logarithmic Smoothing:**
    Compute the smoothed continuous quota $\tilde{K}_b$ to reduce disparity between blocks, particularly handling blocks with zero initial quotas via $\epsilon_a$ [S1, unofficial]:
    $$ r_b = \frac{K'_b}{(K/N)n_b + \epsilon_a} $$
    $$ \tilde{K}_b = K \frac{n_b \log(1 + \beta r_b)}{\sum_{b'=1}^B n_{b'} \log(1 + \beta r_{b'})} $$
    Here, $r_b$ compares the initial quota to the proportional quota $(K/N)n_b$ [S1, unofficial]. Increasing $\beta$ reduces disparities among block retention ratios [S1, unofficial].

3.  **Clipping and Initialization:**
    Clip the continuous quotas to the valid range $[0, n_b]$ and initialize the integer budgets by flooring:
    $$ \hat{K}_b = \min\{n_b, \max(0, \tilde{K}_b)\} $$
    $$ K_b \leftarrow \lfloor \hat{K}_b \rfloor $$
    [S1, unofficial]

4.  **Residual Allocation (Largest Remainder with Capacity Check):**
    Calculate the remaining budget $H$ and the fractional residuals $f_b$:
    $$ H = K - \sum_b K_b $$
    $$ f_b = \hat{K}_b - K_b $$
    While $H > 0$:
    a. Identify eligible blocks where $K_b < n_b$.
    b. Sort eligible blocks by descending $f_b$. Break ties by ascending block index [S1, unofficial].
    c. Assign one unit of budget to the first $\min(H, \text{number of eligible blocks})$ blocks in the sorted list.
    d. Update $H$ and $f_b$ for the affected blocks.
    e. Repeat until $H = 0$ [S1, unofficial].

    *Note:* If no quota is clipped, this reduces to standard largest-remainder rounding. Clipping can create a larger deficit, requiring multiple passes [S1, unofficial].

**Pseudocode:**

```python
def capacity_handling(Gaussians, Blocks, K, beta, epsilon_a):
    """
    Gaussians: list of objects with attributes .id, .D (score), .block_id
    Blocks: list of objects with attributes .id, .capacity (n_b)
    K: int, target total retained count
    beta: float, smoothing parameter > 0
    epsilon_a: float, pseudocount > 0
    Returns: dict mapping block_id to integer budget K_b
    """
    N = len(Gaussians)
    B = len(Blocks)
    
    # Step 1: Initial Top-K Counting
    # Sort Gaussians by D descending, then by id ascending for tie-breaking
    sorted_gaussians = sorted(Gaussians, key=lambda g: (-g.D, g.id))
    top_k_indices = set(g.id for g in sorted_gaussians[:K])
    
    # Count initial quotas K'_b
    initial_quotas = {}
    for b in Blocks:
        count = 0
        for g in Gaussians:
            if g.block_id == b.id and g.id in top_k_indices:
                count += 1
        initial_quotas[b.id] = count
        
    # Step 2: Logarithmic Smoothing
    # Calculate r_b
    proportional_quota = (K / N)
    
    # Precompute denominator terms
    denom_sum = 0.0
    r_values = {}
    for b in Blocks:
        n_b = b.capacity
        K_prime_b = initial_quotas[b.id]
        # r_b = K'_b / ((K/N)*n_b + epsilon_a)
        r_b = K_prime_b / (proportional_quota * n_b + epsilon_a)
        r_values[b.id] = r_b
        
        # Term for denominator: n_b * log(1 + beta * r_b)
        term = n_b * math.log(1 + beta * r_b)
        denom_sum += term
        
    # Calculate continuous quotas K_tilde_b
    continuous_quotas = {}
    for b in Blocks:
        n_b = b.capacity
        r_b = r_values[b.id]
        # K_tilde_b = K * (n_b * log(1 + beta * r_b)) / denom_sum
        numerator = n_b * math.log(1 + beta * r_b)
        continuous_quotas[b.id] = K * (numerator / denom_sum)
        
    # Step 3: Clipping and Initialization
    integer_budgets = {}
    clipped_quotas = {}
    
    for b in Blocks:
        b_id = b.id
        n_b = b.capacity
        k_tilde = continuous_quotas[b_id]
        
        # Clip to [0, n_b]
        k_hat = min(n_b, max(0.0, k_tilde))
        clipped_quotas[b_id] = k_hat
        
        # Floor
        integer_budgets[b_id] = int(math.floor(k_hat))
        
    # Step 4: Residual Allocation
    current_sum = sum(integer_budgets.values())
    H = K - current_sum
    
    while H > 0:
        # Identify eligible blocks: K_b < n_b
        eligible_blocks = []
        for b in Blocks:
            b_id = b.id
            if integer_budgets[b_id] < b.capacity:
                k_hat = clipped_quotas[b_id]
                k_int = integer_budgets[b_id]
                f_b = k_hat - k_int
                eligible_blocks.append((b_id, f_b))
                
        if not eligible_blocks:
            # Should not happen if logic is correct and H > 0 implies capacity exists
            break
            
        # Sort by descending f_b, then ascending block_id (tie-break)
        # Python's sort is stable, so we sort by f_b desc, then id asc
        eligible_blocks.sort(key=lambda x: (-x[1], x[0]))
        
        # Assign to first min(H, len) blocks
        num_to_assign = min(H, len(eligible_blocks))
        
        for i in range(num_to_assign):
            b_id = eligible_blocks[i][0]
            integer_budgets[b_id] += 1
            H -= 1
            
            # Update residual for next pass if needed
            # Note: The source says "Update H and fb". 
            # If we increment K_b, the residual f_b effectively decreases 
            # because K_hat is fixed. 
            # However, the loop condition is H > 0. 
            # We just need to ensure we don't re-assign to the same block 
            # in the same pass if H is large? 
            # The source says "Each of the first ... blocks receives one unit."
            # It implies a single pass over the sorted list for one unit per block?
            # "While H > 0 ... Each of the first ... blocks receives one unit."
            # This phrasing suggests that in one iteration of the while loop,
            # we give 1 unit to multiple blocks.
            # But if H is large, we might need multiple passes.
            # The update of fb is implicit: f_b_new = k_hat - (k_int + 1) = f_b - 1.
            # So the block drops to the bottom of the sorted list for the next pass.
            
    return integer_budgets
```

**Edge Cases and Pitfalls:**
- **Zero Initial Quotas:** Blocks with no Top-$K$ members get $K'_b=0$. The pseudocount $\epsilon_a$ prevents division by zero or log(0) issues in the smoothing step [S1, unofficial].
- **Capacity Overflow:** If smoothing assigns a quota $> n_b$, it is clipped. This creates a deficit $H$ that must be redistributed, potentially requiring multiple passes through the eligible blocks [S1, unofficial].
- **Tie Breaking:** Global index is used for Gaussian ranking ties; block index is used for residual allocation ties [S1, unofficial].

## Subtopics

### Deterministic Integer Allocation
A deterministic method to convert expected Gaussian counts $B p_n$ into integer allocations $k_n^\bullet$ for $N$ anchors, ensuring the total count sums exactly to budget $B$ without sorting or ties [S2, unofficial]. It uses systematic rounding with a fixed phase $\phi = 1/2$ [S2, unofficial].
- **Definition:** Converts probabilities $p_n$ to integers $k_n^\bullet$ such that $\sum k_n^\bullet = B$ [S2, unofficial].
- **Method:** Compute cumulative probabilities $P_n = \sum_{m \le n} p_m$ with $P_0=0$. Calculate $k_n^\bullet = \lfloor B P_n - \phi \rfloor - \lfloor B P_{n-1} - \phi \rfloor$ using double precision [S2, unofficial].
- **Properties:** Counts sum exactly to $B$ due to telescoping sum; each count is either $\lfloor B p_n \rfloor$ or $\lceil B p_n \rceil$; anchors with $p_n=0$ receive 0 [S2, unofficial].
- **Complexity:** $O(N)$ time, no sorting required [S2, unofficial].
- **Parameters:** Budget floor $B/N$ is floored at $1/64$ to keep log-ratio $u$ finite [S2, unofficial].

## Operating characteristics
- **Time Complexity:** The primary Capacity Handling method involves sorting Gaussians ($O(N \log N)$) and potentially multiple passes over blocks for residual allocation. The Deterministic Integer Allocation variant is $O(N)$ [S1, S2, unofficial].
- **Memory Complexity:** Requires storage for scores, quotas, and block capacities. $O(N + B)$ [S1, S2, unofficial].
- **Strengths:** Ensures strict adherence to global budget $K$ and per-block capacities $n_b$ [S1, unofficial]. Smoothing reduces imbalance caused by global Top-K selection [S1, unofficial]. Deterministic variant avoids non-determinism from sorting ties [S2, unofficial].
- **Limitations:** Clipping can necessitate multiple passes in the primary method [S1, unofficial]. Smoothing parameters $\beta$ and $\epsilon_a$ require tuning [S1, unofficial].
- **When to use:** Use when chunk-based streaming requires strict integer budgets per block to manage memory limits [S1, unofficial]. Use Deterministic Integer Allocation when a fast, tie-free, deterministic conversion from probabilities to counts is needed [S2, unofficial].

## Background
Capacity Handling originates from the SplatQ method for pruning 3D Gaussian Splatting, where it serves as the final step in budget assignment after similarity-guided partitioning and quadratic selection [S1, unofficial]. It addresses the impracticality of global quadratic optimization for millions of Gaussians by partitioning the problem into blocks [S1, unofficial]. The Deterministic Integer Allocation variant appears in RLSplat for resource-linear budget control in feed-forward 3D Gaussian Splatting [S2, unofficial].
