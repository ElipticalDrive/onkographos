# Chunk Loading/Unloading Scanner

Also called: Chunk Load/Unload Distance Culling, Render Distance Chunk Management, Scanner, ScannerPlugin, Spatial Chunk Culling

## Overview
The Chunk Loading/Unloading Scanner is a spatial management technique that determines which chunks of a volume dataset need to be loaded into memory or unloaded based on the camera's current and previous positions [S1, S2, unofficial]. It solves the problem of efficiently streaming large voxel worlds by identifying a "load area" and an "unload area" using offset grids, then computing the symmetric difference between these areas to generate precise queue updates [S1, S2, unofficial]. Unlike [Dynamic Chunk Generation with Radius](4002-dynamic-chunk-generation-with-radius.md), which focuses on procedural generation triggers, or [Budget Plans](5497-budget-plans.md), which manage resource limits, the Scanner focuses on the geometric transition logic between camera states [S1, S2, unofficial]. It differs from [Chunk Visibility Culling](5031-chunk-visibility-culling.md) by operating on a flat list of chunks and performing binary load/unload decisions based on distance thresholds rather than frustum intersection tests [S1, S2, unofficial].

## How it works
**Inputs:** Camera world position, camera transform (optional, depending on implementation), previous camera chunk position, chunk grid dimensions, render distance radius, and data/mesh sampling offsets.
**Outputs:** Four queues of chunk coordinates: `unresolved_data_load`, `unresolved_mesh_load`, `unresolved_data_unload`, `unresolved_mesh_unload`.

**Data Structures:**
The core state is held in a `Scanner` struct (or equivalent class) containing:
- `prev_chunk_pos`: `IVec3` (32-bit signed integer vector), storing the chunk coordinates of the camera in the previous frame.
- `checks_per_frame`: `usize`, limiting the number of chunks processed per frame to smooth out spikes. Default value: $32 \times 32 \times 32$ [S1, unofficial].
- `data_offset`: `usize`, radius for data loading offsets. Calculated as `distance + 1` [S1, unofficial].
- `mesh_offset`: `usize`, radius for mesh loading offsets. Calculated as `distance` [S1, unofficial].
- `data_sampling_offsets`: `Vec<IVec3>`, precomputed list of relative chunk offsets within the data loading radius.
- `mesh_sampling_offsets`: `Vec<IVec3>`, precomputed list of relative chunk offsets within the mesh loading radius.
- `unresolved_data_load`: `Vec<IVec3>`, chunks to load data for.
- `unresolved_mesh_load`: `Vec<IVec3>`, chunks to load mesh geometry for.
- `unresolved_data_unload`: `VecDeque<IVec3>`, chunks to unload data from.
- `unresolved_mesh_unload`: `VecDeque<IVec3>`, chunks to unload mesh from.

**Parameters:**
- `CHUNK_RENDER_DISTANCE` (or `distance`): The number of chunks to load around the player. This defines the base radius for the load area [S2, unofficial].
- Unloading Threshold Multiplier: A scalar (typically 8) applied to `CHUNK_RENDER_DISTANCE` to determine when chunks are aggressively unloaded [S2, unofficial].

**Algorithm Steps:**

1.  **Calculate Current Chunk Position:**
    Determine the chunk index containing the camera.
    *Method A (from [S1, unofficial]):*
    $$ \text{chunk\_pos} = \lfloor (\text{camera\_transform.translation} - \text{Vec3}(16.0)) \times \frac{1}{32.0} \rfloor $$
    *Method B (from [S2, unofficial]):*
    $$ \text{current\_chunk\_index} = \left( \lfloor \frac{\text{camera\_position}.x}{\text{Chunk::CHUNK\_LENGTH}} \rfloor, \lfloor \frac{\text{camera\_position}.y}{\text{Chunk::CHUNK\_LENGTH}} \rfloor, \lfloor \frac{\text{camera\_position}.z}{\text{Chunk::CHUNK\_LENGTH}} \rfloor \right) $$
    [S1, S2, unofficial]

2.  **Check for Movement:**
    Compare `current_chunk_pos` with `prev_chunk_pos`. If they are identical, skip processing for this frame [S1, unofficial].

3.  **Generate Sampling Offsets:**
    Precompute or generate the list of relative offsets for the load/unload areas.
    *For Data/Mesh Load Areas:* Iterate $x, y, z$ from $-\text{offset}$ to $+\text{offset}$. Collect offsets where at least one coordinate is at the boundary of the offset radius (to optimize for surface area) [S2, unofficial].
    *For Unload Area:* Use a larger radius defined by `CHUNK_RENDER_DISTANCE * Unloading Threshold Multiplier` (e.g., 8) [S2, unofficial].

4.  **Define Load and Unload Areas:**
    Create two sets of chunk coordinates:
    - `load_data_area` = `current_chunk_pos` + `data_sampling_offsets`
    - `unload_data_area` = `prev_chunk_pos` + `data_sampling_offsets` (or the larger unload radius)
    [S1, unofficial]

5.  **Compute Differences:**
    Calculate the symmetric difference between the current load area and the previous unload area to find chunks that need state changes.
    $$ \text{data\_load} = \text{load\_data\_area} \setminus \text{unload\_data\_area} $$
    $$ \text{data\_unload} = \text{unload\_data\_area} \setminus \text{load\_data\_area} $$
    Repeat for mesh areas using `mesh_sampling_offsets` [S1, unofficial].

6.  **Update Queues:**
    - Add chunks in `data_load` to `unresolved_data_load`.
    - Add chunks in `mesh_load` to `unresolved_mesh_load`.
    - Add chunks in `data_unload` to `unresolved_data_unload`.
    - Add chunks in `mesh_unload` to `unresolved_mesh_unload`.
    - Remove any chunks that are already loaded from the unload queues.
    - Remove any chunks that are already queued for loading from the load queues (to prevent duplicates) [S1, unofficial].

7.  **Sort Load Queues:**
    Sort `unresolved_data_load` and `unresolved_mesh_load` by squared Euclidean distance from the `current_chunk_pos` to prioritize loading nearby chunks first.
    $$ \text{dist}^2 = (x - x_c)^2 + (y - y_c)^2 + (z - z_c)^2 $$
    [S1, unofficial]

8.  **Limit Processing (Optional):**
    If `checks_per_frame` is set, only process the first $N$ chunks from the sorted load queues and the first $N$ chunks from the unload queues [S1, unofficial].

**Pseudocode:**

```python
import math
from collections import deque
from typing import List, Tuple

class IVec3:
    def __init__(self, x: int, y: int, z: int):
        self.x = x
        self.y = y
        self.z = z

    def __add__(self, other):
        return IVec3(self.x + other.x, self.y + other.y, self.z + other.z)

    def __sub__(self, other):
        return IVec3(self.x - other.x, self.y - other.y, self.z - other.z)

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y and self.z == other.z

    def __hash__(self):
        return hash((self.x, self.y, self.z))

    def squared_dist(self, other):
        dx = self.x - other.x
        dy = self.y - other.y
        dz = self.z - other.z
        return dx*dx + dy*dy + dz*dz

def generate_offsets(radius: int) -> List[IVec3]:
    """
    Generates offsets within a radius.
    From [S2, unofficial]: iterate x,y,z from -radius to radius, collect where at least one coord is at boundary.
    """
    offsets = []
    for x in range(-radius, radius + 1):
        for y in range(-radius, radius + 1):
            for z in range(-radius, radius + 1):
                # Check if at least one coordinate is at the boundary
                if abs(x) == radius or abs(y) == radius or abs(z) == radius:
                    offsets.append(IVec3(x, y, z))
    return offsets

def chunk_position_from_camera(camera_pos: IVec3, chunk_length: int) -> IVec3:
    """
    From [S2, unofficial]: floor division.
    """
    return IVec3(
        int(math.floor(camera_pos.x / chunk_length)),
        int(math.floor(camera_pos.y / chunk_length)),
        int(math.floor(camera_pos.z / chunk_length))
    )

class ChunkScanner:
    def __init__(self, chunk_length: int, render_distance: int):
        self.chunk_length = chunk_length
        self.render_distance = render_distance
        self.prev_chunk_pos = None
        
        # Parameters from [S1, unofficial]
        self.data_offset = render_distance + 1
        self.mesh_offset = render_distance
        
        # Precompute offsets
        self.data_sampling_offsets = generate_offsets(self.data_offset)
        self.mesh_sampling_offsets = generate_offsets(self.mesh_offset)
        
        # Unload radius multiplier from [S2, unofficial]
        self.unload_multiplier = 8
        self.unload_radius = render_distance * self.unload_multiplier
        self.unload_sampling_offsets = generate_offsets(self.unload_radius)
        
        # Queues
        self.unresolved_data_load: List[IVec3] = []
        self.unresolved_mesh_load: List[IVec3] = []
        self.unresolved_data_unload: deque = deque()
        self.unresolved_mesh_unload: deque = deque()
        
        # Limit from [S1, unofficial]
        self.checks_per_frame = 32 * 32 * 32

    def update(self, camera_pos: IVec3, loaded_chunks: set):
        current_chunk_pos = chunk_position_from_camera(camera_pos, self.chunk_length)
        
        # Step 2: Check for movement
        if self.prev_chunk_pos is not None and current_chunk_pos == self.prev_chunk_pos:
            return
            
        # Step 4: Define Areas
        # Load Area based on current position
        load_data_area = set()
        for offset in self.data_sampling_offsets:
            load_data_area.add(current_chunk_pos + offset)
            
        load_mesh_area = set()
        for offset in self.mesh_sampling_offsets:
            load_mesh_area.add(current_chunk_pos + offset)
            
        # Unload Area based on previous position (or current if prev is None)
        prev_pos = self.prev_chunk_pos if self.prev_chunk_pos else current_chunk_pos
        unload_data_area = set()
        for offset in self.unload_sampling_offsets:
            unload_data_area.add(prev_pos + offset)
            
        unload_mesh_area = set()
        for offset in self.unload_sampling_offsets: # Assuming same radius for mesh unload for simplicity, or specific mesh unload radius
            unload_mesh_area.add(prev_pos + offset)

        # Step 5: Compute Differences
        data_load = load_data_area - unload_data_area
        data_unload = unload_data_area - load_data_area
        mesh_load = load_mesh_area - unload_mesh_area
        mesh_unload = unload_mesh_area - load_mesh_area

        # Step 6: Update Queues
        # Add to load queues
        for chunk in data_load:
            if chunk not in loaded_chunks: # [G] Guard against loading already loaded chunks
                self.unresolved_data_load.append(chunk)
        
        for chunk in mesh_load:
            if chunk not in loaded_chunks:
                self.unresolved_mesh_load.append(chunk)
                
        # Add to unload queues
        for chunk in data_unload:
            if chunk in loaded_chunks: # [G] Only unload if currently loaded
                self.unresolved_data_unload.append(chunk)
                
        for chunk in mesh_unload:
            if chunk in loaded_chunks:
                self.unresolved_mesh_unload.append(chunk)
                
        # Remove already loaded from unload queues
        # Note: In a real implementation, we might need to scan the deque to remove, 
        # or use a set for active unload requests. Here we assume the deque is processed 
        # and cleared by the consumer, or we filter here.
        # Simplified: The consumer should check if chunk is still in loaded_chunks before unloading.
        
        # Step 7: Sort Load Queues
        self.unresolved_data_load.sort(key=lambda c: c.squared_dist(current_chunk_pos))
        self.unresolved_mesh_load.sort(key=lambda c: c.squared_dist(current_chunk_pos))
        
        # Step 8: Limit Processing
        # The scanner generates the lists. The consumer (renderer/engine) should limit 
        # how many it actually processes per frame based on checks_per_frame.
        # The scanner itself just prepares the sorted lists.
        
        self.prev_chunk_pos = current_chunk_pos
```

**Edge Cases and Pitfalls:**
- **Unloading Overhead:** Unloading freed resources (e.g., `ID3D12Resource`) has high overhead. The implementation may queue indices for later processing rather than unloading immediately every frame [S2, unofficial].
- **Precision:** Chunk position calculation must handle negative coordinates correctly (floor division vs truncation) [S2, unofficial].
- **Degenerate Input:** If the camera does not move, the scanner skips processing, which is correct but requires careful handling of the initial frame where `prev_chunk_pos` is null [S1, unofficial].

## Subtopics

### [Chunk Visibility Culling](5031-chunk-visibility-culling.md)
Determines visibility via frustum tests on a flat list of chunks. Choose this when you need to exclude chunks outside the view volume before distance-based loading. It is a binary filter, unlike the distance-based loading of the Scanner.

## Operating characteristics
- **Time Complexity:** $O(R^2)$ per axis for offset generation, where $R$ is the render distance. The difference calculation is $O(N)$ where $N$ is the number of chunks in the load/unload shells. Sorting is $O(N \log N)$.
- **Memory Complexity:** $O(R^2)$ to store the offset lists and queues.
- **Performance:** The method is efficient for large worlds because it only processes the boundary chunks between the old and new camera positions. The `checks_per_frame` parameter allows smoothing out CPU spikes [S1, unofficial].
- **Strengths:** Simple logic, low overhead for small camera movements, easy to implement.
- **Limitations:** Does not account for occlusion (chunks might be loaded but not visible). The large unload radius (8x render distance) can lead to loading chunks far away if the camera moves quickly, potentially causing memory spikes [S2, unofficial].

## Background
The Chunk Loading/Unloading Scanner is a technique used in voxel engines and out-of-core volume rendering systems to manage memory for large spatial datasets. It is implemented in projects such as the Binary Greedy Voxel Meshing Algorithm demo [S1, unofficial] and the rtarun9 voxel engine [S2, unofficial]. The method relies on the principle that only chunks near the camera boundary need to be updated when the camera moves, reducing the need to scan the entire world grid every frame.
