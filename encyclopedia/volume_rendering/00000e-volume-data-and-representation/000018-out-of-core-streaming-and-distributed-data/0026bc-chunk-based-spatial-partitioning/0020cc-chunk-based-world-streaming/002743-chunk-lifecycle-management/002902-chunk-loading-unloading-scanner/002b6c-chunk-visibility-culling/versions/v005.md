# Chunk Visibility Culling

Also called: Chunk Frustum Culling, Frustum Culling for Chunk Rendering, Frustum Culling for Chunk Visibility

## Overview
Chunk Visibility Culling determines which spatial chunks of a volume dataset are visible to the camera by testing if their world-space bounding boxes intersect the view frustum [S1, S3, S4, unofficial]. It sets itself apart from sibling methods by operating on a flat list of loaded chunks rather than traversing a hierarchy (like [Octree Frustum Culling & LOD Selection](5771-octree-frustum-culling-lod-selection.md)) or performing geometric clipping for resolution selection (like [Out-of-Core Frustum Clipping](6688-out-of-core-frustum-clipping.md)) [S1, S3, S4, unofficial]. It builds on [Chunk Loading/Unloading Scanner](4404-chunk-loading-unloading-scanner.md) by filtering the set of loaded chunks for rendering eligibility [S2, unofficial].

## How it works
**Inputs:**
- Camera object containing projection matrix and world inverse matrix [S3, unofficial].
- List of currently loaded chunks, each providing world-space position and bounding volume data [S2, S3, S4, unofficial].
- `renderRadius`: Optional radius in chunk coordinates around the center chunk to limit the search space [S3, unofficial].

**Outputs:**
- `_chunkVisibleSet`: A set of chunks determined to be inside the frustum [S2, unofficial].
- `_chunkRenderSet`: A subset of visible chunks, sorted by distance, ready for the renderer queue [S2, S3, unofficial].

**Data Structures:**
- `Chunk`: Stores world-space position and bounding volume parameters [S2, S4, unofficial].
- `Frustum`: An object holding the six view frustum planes derived from the camera matrices [S3, unofficial].
- `ChunkManager`: Maintains `_chunkVisibleSet` (`std::set<Chunk*>`) and `_chunkRenderSet` (`std::set<Chunk*>`) [S2, unofficial].

**Steps:**
1. **Extract Frustum Planes:** Compute the view frustum from the camera's projection matrix and world inverse matrix [S3, unofficial].
   $$ \text{projScreenMatrix} = \text{camera.projectionMatrix} \times \text{camera.matrixWorldInverse} $$
   $$ \text{frustum} = \text{Frustum.setFromProjectionMatrix}(\text{projScreenMatrix}) $$
2. **Calculate Center Chunk:** Determine the chunk coordinates containing the camera to optimize the search radius [S3, unofficial].
   $$ \text{center\_chunk\_coords} = (\lfloor \text{camera.position.x} / \text{CHUNK\_WORLD\_SIZE} \rfloor, \lfloor \text{camera.position.y} / \text{CHUNK\_WORLD\_SIZE} \rfloor, \lfloor \text{camera.position.z} / \text{CHUNK\_WORLD\_SIZE} \rfloor) $$
3. **Iterate Loaded Chunks:** Loop through all chunks currently loaded by the `ChunkManager` [S1, S2, unofficial].
4. **Check Bounding Volume Validity:** If the chunk's bounding volume may be out of date due to transformations, rebuild or validate it [S2, unofficial].
   $$ \text{if } \text{boundingVolumeOutOfDate}(): \text{rebuildBounds}() $$
5. **Frustum Intersection Test:**
   - **Method A (Explicit World Pos):** Calculate the chunk's world position and call the frustum's specific intersection test [S4, unofficial].
     $$ wx = \text{chunk.GetXWorldPos}() \times \text{Chunk.m\_XSize} $$
     $$ wz = \text{chunk.GetZWorldPos}() \times \text{Chunk.m\_ZSize} $$
     $$ \text{visible} = \text{frustum.IsChunkInFrustum}(wx, wz) $$
   - **Method B (AABB Intersection):** Use the chunk's full bounding box [S3, unofficial].
     $$ \text{visible} = \text{frustum.intersectsBox}(\text{chunk.bounds}) $$
6. **Update Visible Set:** If `visible` is true, add the chunk to `_chunkVisibleSet` [S3, unofficial].
7. **Sort by Distance:** Sort the chunks in `_chunkVisibleSet` by squared distance from `center_chunk_coords` to populate `_chunkRenderSet` for correct rendering order (e.g., for transparency or LOD) [S3, unofficial].
   $$ \text{dist}^2 = (\text{chunk.pos} - \text{center\_chunk\_coords})^2 $$
8. **Render Queue Submission:** Submit the model, transform, and render layer of chunks in `_chunkRenderSet` to the renderer [S1, S2, unofficial].

**Pseudocode:**
```python
def update_visibility_list(camera, chunk_manager, render_radius=None):
    # 1. Extract Frustum Planes [G]
    proj_screen_matrix = camera.projection_matrix * camera.matrix_world_inverse
    frustum_planes = extract_frustum_planes_from_matrix(proj_screen_matrix)
    
    # 2. Calculate Center Chunk [S3, unofficial]
    chunk_world_size = chunk_manager.chunk_world_size
    center_chunk_coords = (
        int(camera.position.x // chunk_world_size),
        int(camera.position.y // chunk_world_size),
        int(camera.position.z // chunk_world_size)
    )
    
    visible_chunks = []
    
    # 3. Iterate Loaded Chunks [S1, S2, unofficial]
    for chunk in chunk_manager.loaded_chunks:
        # 4. Check Bounding Volume Validity [S2, unofficial]
        if chunk.bounding_volume_out_of_date():
            chunk.calculate_bounds(chunk_manager.world_transform)
            
        # 5. Frustum Intersection Test [S3, S4, unofficial]
        aabb_min = chunk.bounds.min
        aabb_max = chunk.bounds.max
        if aabb_frustum_intersect(aabb_min, aabb_max, frustum_planes):
            visible_chunks.append(chunk)
            
    # 7. Sort by Distance [S3, unofficial]
    visible_chunks.sort(key=lambda c: 
        (c.position.x - center_chunk_coords[0])**2 + 
        (c.position.y - center_chunk_coords[1])**2 + 
        (c.position.z - center_chunk_coords[2])**2
    )
    
    # Update Manager Sets [S2, unofficial]
    chunk_manager.chunk_visible_set = set(visible_chunks)
    chunk_manager.chunk_render_set = visible_chunks
    
    return visible_chunks

def extract_frustum_planes_from_matrix(matrix):
    # Standard extraction of 6 frustum planes from a 4x4 projection*view matrix [G]
    planes = []
    for i in range(6):
        plane = [matrix[3][i] + matrix[0][i],
                 matrix[3][i] + matrix[1][i],
                 matrix[3][i] + matrix[2][i],
                 matrix[3][i]]
        planes.append(plane)
    return planes

def aabb_frustum_intersect(min_pt, max_pt, planes):
    # Standard AABB vs Frustum plane intersection test [G]
    for plane in planes:
        # Check if the corner maximizing the dot product is outside the plane
        x = max_pt.x if plane[0] > 0 else min_pt.x
        y = max_pt.y if plane[1] > 0 else min_pt.y
        z = max_pt.z if plane[2] > 0 else min_pt.z
        if plane[0]*x + plane[1]*y + plane[2]*z + plane[3] > 0:
            return False
    return True
```

## Subtopics

### [Octree Frustum Culling & LOD Selection](5771-octree-frustum-culling-lod-selection.md)
Recursively traverses a chunk-based octree to determine visibility and assign LOD in a single pass [5771-octree-frustum-culling-lod-selection.md]. It differs by deferring geometry queueing until a node is fully visible or fully outside, combining culling and LOD logic [5771-octree-frustum-culling-lod-selection.md]. Choose when hierarchical detail is required [5771-octree-frustum-culling-lod-selection.md].

### [Out-of-Core Frustum Clipping](6688-out-of-core-frustum-clipping.md)
Couples geometric frustum tests with a resolution selection algorithm to ensure loaded data fits texture memory limits [6688-out-of-core-frustum-clipping.md]. It differs by explicitly clipping geometry for resolution constraints, enabling out-of-core streaming [6688-out-of-core-frustum-clipping.md]. Choose when memory bandwidth is the primary bottleneck [6688-out-of-core-frustum-clipping.md].

### [Frustum Culling & Distance Sorting](6849-frustum-culling-distance-sorting.md)
Filters visible chunks and sorts them by distance for rendering order [6849-frustum-culling-distance-sorting.md]. It differs by operating on flat chunk lists without hierarchical traversal or geometric clipping [6849-frustum-culling-distance-sorting.md]. Choose when simple depth sorting is sufficient for transparent blending [6849-frustum-culling-distance-sorting.md].

### Streaming via Visibility Buffer
Transfers data (e.g., Gaussians) to the GPU on-demand based on visibility determined by a visibility buffer, rather than just view frustum culling [S5]. It differs by using a tiled compute-based software rasterizer or KD-Tree voxel tests to determine overlap before transfer [S5]. Choose for advanced streaming where GPU-side visibility determination is preferred [S5].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of loaded chunks, as each chunk's bounding box is tested against the frustum [S1, S3, S4, unofficial]. Sorting adds $O(V \log V)$ where $V$ is the number of visible chunks [S3, unofficial].
- **Memory Complexity:** Not given in the sources [S1, S3, S4, unofficial].
- **Performance:** Highly efficient for large scenes with sparse loading, as it avoids rendering off-screen geometry [S1, S4, unofficial]. Performance degrades if the number of loaded chunks $N$ is very high, as the linear scan becomes costly [S2, unofficial].
- **Strengths:** Simple to implement; effective at reducing off-screen rendering work [S1, S4, unofficial].
- **Limitations:** Does not handle occlusion (chunks behind other opaque chunks are still tested and potentially rendered) [S3, S4, unofficial]. Bounding volumes must be kept up-to-date with transformations [S2, unofficial].
- **When to Use:** Standard chunk-based rendering where occlusion culling is handled separately or not needed [S1, S3, unofficial].
- **When Not to Use:** Scenes with extreme occlusion where overdraw is high, or when hierarchical culling (Octree) can skip large empty regions more efficiently [5771-octree-frustum-culling-lod-selection.md] [S1, S3, S4, unofficial].

## Background
Chunk Visibility Culling is a technique adapted from standard view frustum culling for discrete spatial partitions (chunks) rather than individual meshes [S1, S3, S4, unofficial]. It is used in chunk-based volume rendering and voxel terrain systems to manage rendering eligibility [S2, S3, S4, unofficial].
