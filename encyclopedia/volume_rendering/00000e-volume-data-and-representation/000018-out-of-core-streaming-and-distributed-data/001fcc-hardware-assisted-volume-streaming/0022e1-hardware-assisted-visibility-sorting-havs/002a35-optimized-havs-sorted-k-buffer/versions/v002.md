# Optimized HAVS (Sorted k-buffer)

Also called: Optimization of HAVS, Sorted k-buffer HAVS

## Overview
Optimized HAVS is a refinement of Hardware Assisted Visibility Sorting [Hardware Assisted Visibility Sorting (HAVS)](2918-hardware-assisted-visibility-sorting-havs.md) that maintains the k-buffer in a strictly sorted state (ascending order of fragment distance) to reduce the computational cost of fragment-level visibility sorting [S1]. While standard HAVS requires $2k-1$ comparisons to identify the two nearest fragments for compositing, this optimization reduces that requirement to $k$ comparisons per fragment processing step after the buffer is full, thereby improving rendering efficiency for large unstructured grid datasets [S1].

## How it works
**Inputs:**
- A stream of volume fragments projected to screen space [S1].
- A k-buffer of fixed capacity $k$ per pixel, storing the nearest fragments [S1].
- A 3D pre-integrated lookup table for color and opacity retrieval [S1].
- Image dimensions $m \times n$ [S1].

**Outputs:**
- A composited color and opacity value for each pixel in the framebuffer [S1].
- The k-buffer state updated for the next frame or fragment batch [S1].

**Data Structures:**
- **k-buffer:** An array of size $k$ per pixel [S1]. Each element stores fragment properties (distance, color, opacity, etc.) [S1]. The buffer is maintained in ascending order of distance from the camera [S1].
- **3D Pre-integrated Table:** A texture or lookup table mapping distance intervals and optical properties to color/opacity values [S1].

**Parameters:**
- $k$: The number of nearest fragments to retain [S1]. The source notes that existing HAVS restricts $k$ to 6, but this optimization allows for analysis of $k$ ranges to balance precision and efficiency [S1]. Typical values are small integers (e.g., $k \le 6$ or slightly higher depending on implementation constraints) [S1].

**Algorithm Steps:**
For each pixel $j$ in the image ($1 \le j \le m \times n$), let $s_j$ be the total number of fragments projected to that pixel [S1]. The k-buffer is processed as follows [S1]:

1. **Buffer Not Full ($current\_size < k$):** Insert the new fragment into the k-buffer at the correct position to maintain ascending order of distance by comparing it with existing fragments [S1].
2. **Buffer Full ($current\_size == k$):** Let the fragments in the buffer be $f_1, f_2, \dots, f_k$, where $f_1$ is the nearest (smallest distance) and $f_k$ is the farthest [S1].
3. Select $f_1$ as the first nearest fragment candidate [S1].
4. Select the nearest fragment $f_i$ from the remaining $k-1$ fragments ($f_2, \dots, f_k$) [S1]. Since the buffer is sorted, $f_i$ is simply $f_2$ [S1].
5. Compare $f_1$ and $f_i$, and get the smaller one $f_j$ [S1].
6. Use $(v_i, v_1)$ and the distance difference to get color and opacity from the 3D pre-integrated table [S1].
7. Composite the resulting color and opacity to the framebuffer [S1].
8. Discard $f_j$ and write the remaining $k$ fragments back to the k-buffer (the new fragment is inserted to restore size $k$) [S1].

**Formulas:**
Let $N_2$ be the total number of comparisons for the sorted k-buffer across all pixels [S1].
Let $t_1$ be comparisons during insertion (buffer not full) [S1].
Let $t_2$ be comparisons when the buffer is full [S1].

The total comparisons $N_2$ are given by [S1]:
$$ N_2 = \sum_{j=1}^{m \times n} (t_1 + t_2) = \sum_{j=1}^{m \times n} \left( \sum_{l=1}^{k-1} l + (1 + k - 1) \times (s_j - k) \right) $$

Where:
- $\sum_{l=1}^{k-1} l$ represents the comparisons needed to insert fragments into the buffer while it is filling up (sum of $1$ to $k-1$) [S1].
- $(1 + k - 1) \times (s_j - k)$ represents the comparisons for the remaining $s_j - k$ fragments after the buffer is full [S1]. The term $(1 + k - 1)$ simplifies to $k$, which is the number of comparisons per fragment when the buffer is full [S1].

The average comparisons per pixel $e_2$ are [S1]:
$$ e_2 = \frac{N_2}{m \times n} = \frac{\sum_{j=1}^{m \times n} (\sum_{l=1}^{k-1} l + k \times (s_j - k))}{m \times n} $$

The difference in average comparisons between the original HAVS ($e_1$) and the optimized HAVS ($e_2$) is [S1]:
$$ \Delta e = e_1 - e_2 = \frac{\sum_{j=1}^{m \times n} ((k-1) \times (s_j - \frac{k}{2} - 1))}{m \times n} $$

**Pseudocode:**
```python
def optimized_havs(fragments, k, pre_integrated_table, m, n):
    """
    Process fragments using Optimized HAVS with a sorted k-buffer.
    Args:
        fragments: List of fragment objects with attributes .pixel_index, .distance, .volume_interval
        k: Buffer capacity per pixel
        pre_integrated_table: Callable returning (color, opacity) given (vi, v1, distance_diff)
        m: Image width
        n: Image height
    Returns:
        framebuffer: List of (color, opacity) tuples per pixel
    """
    k_buffers = [[] for _ in range(m * n)]
    framebuffer = [None] * (m * n)
    pixel_fragments = [[] for _ in range(m * n)]
    
    for frag in fragments:
        pixel_fragments[frag.pixel_index].append(frag)
        
    for p in range(m * n):
        buffer = k_buffers[p]
        for frag in pixel_fragments[p]:
            current_size = len(buffer)
            
            if current_size < k:
                # Step 1: Insert new fragment into correct position by comparing with existing fragments
                insert_idx = 0
                while insert_idx < current_size and buffer[insert_idx].distance < frag.distance:
                    insert_idx += 1
                buffer.insert(insert_idx, frag)
            else:
                # Step 2: Select first fragment f1 as nearest
                f1 = buffer[0]
                # Step 3: Select nearest fragment fi in the rest k-1 fragments
                fi = buffer[1]
                # Step 4: Compare f1 and fi, get smaller one fj
                fj = f1 if f1.distance < fi.distance else fi
                # Step 5: Use (vi, v1) and distance difference to get color/opacity from 3D pre-integrated table
                color, opacity = pre_integrated_table(fi.volume_interval, f1.volume_interval, fi.distance - f1.distance)
                # Step 6: Composite to framebuffer
                if framebuffer[p] is None:
                    framebuffer[p] = (color, opacity)
                else:
                    prev_c, prev_o = framebuffer[p]
                    framebuffer[p] = (color * opacity + prev_c * (1 - opacity), opacity + prev_o * (1 - opacity))
                # Step 7: Discard fj and write remaining k fragments back
                buffer.pop(0)  # fj is always f1 in a sorted buffer
                # Insert the new fragment to restore size k
                insert_idx = 0
                while insert_idx < k - 1 and buffer[insert_idx].distance < frag.distance:
                    insert_idx += 1
                buffer.insert(insert_idx, frag)
                
    return framebuffer
```

## Operating characteristics
- **Time Complexity:** The number of comparisons per fragment after the buffer is full is $k$, compared to $2k-1$ in the original HAVS [S1]. The total comparisons $N_2$ are reduced, leading to improved efficiency [S1]. The improvement ratio $\frac{\Delta e}{e_1}$ increases as the dataset size ($s_j$) increases [S1].
- **Memory Complexity:** Requires storing $k$ fragments per pixel in the k-buffer [S1].
- **Strengths:** Reduces comparison overhead, especially for large datasets with many fragments per pixel [S1]. Allows for larger $k$ values without proportional performance loss, potentially improving rendering precision [S1].
- **Limitations:** Requires maintaining the sorted order of the k-buffer, which involves insertion operations [S1]. The benefit is most pronounced when $s_j$ is significantly larger than $k$ [S1].

## Background
This optimization was proposed in a paper on volume rendering of unstructured grids [S1]. It addresses the inefficiency of the original HAVS algorithm, which requires $2k-1$ comparisons to find the two nearest fragments [S1]. By keeping the k-buffer sorted, the algorithm reduces this to $k$ comparisons [S1]. The paper also investigates the optimal range for $k$ to balance precision and efficiency, noting that standard HAVS often restricts $k$ to 6 [S1].
