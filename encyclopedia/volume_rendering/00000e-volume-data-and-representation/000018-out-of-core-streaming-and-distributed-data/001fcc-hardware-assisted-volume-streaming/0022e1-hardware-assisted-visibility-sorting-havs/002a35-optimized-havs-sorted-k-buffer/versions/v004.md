# Optimized HAVS (Sorted k-buffer)

Also called: HAVS k-buffer, Hardware-accelerated k-buffer algorithm, Optimization of HAVS, Sorted k-buffer HAVS

## Overview
Optimized HAVS (Sorted k-buffer) is an optimization of the Hardware Assisted Visibility Sorting (HAVS) algorithm that maintains the k-buffer in ascending order of fragment distance to reduce the computational cost of fragment-level visibility sorting [S1]. While standard HAVS requires $2k-1$ comparisons to identify the two nearest fragments for compositing, this method reduces that requirement to $k$ comparisons per fragment after the buffer is full [S1]. It is primarily used for simulating accurate radiographs involving attenuation and attenuation-emission cases, leveraging modern graphics hardware capabilities [S2, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   A 3D dataset partitioned into tetrahedra [S2, unofficial].
*   The dataset is preprocessed by extending it about an axial coordinate, partitioning into hexahedra, and then into tetrahedra [S2, unofficial].
*   An initial sort of the tetrahedra data is performed [S2, unofficial].
*   Image dimensions ($m \times n$) [S1].
*   Buffer size $k$ [S1].

**Outputs:**
*   A rendered image (simulated radiograph) with photon intensity information [S2, unofficial].

### Data Structures
*   **k-buffer:** A fixed-size array of length $k$ storing fragments [S1]. Each fragment contains distance, color, and opacity data [S1]. The buffer is maintained in strictly ascending order of fragment distance from the viewer [S1].
*   **3D Pre-integrated Table:** A texture or lookup table used to retrieve color and opacity values based on the optical depth difference between fragments [S1].

### Algorithm Steps
1.  **Preprocessing:** Extend the 2D or 3D data set about the axial coordinate, partition into hexahedra, and then into tetrahedra [S2, unofficial]. Perform an initial sort on the tetrahedra [S2, unofficial].
2.  **Fragment Processing (Per Pixel):** For each pixel, process incoming fragments from the sorted tetrahedra list:
    1.  **Buffer Not Full:** If the number of fragments currently in the k-buffer is less than $k$, insert the new fragment into the correct position to maintain ascending order by comparing it with existing fragments [S1].
    2.  **Buffer Full:** If the buffer contains $k$ fragments:
        a.  Select the first fragment $f_1$ (the nearest, as the buffer is sorted) [S1].
        b.  Select the nearest fragment $f_i$ in the rest $k$ fragments [S1].
        c.  Compare $f_1$ and $f_i$ to determine the smaller (nearest) one, denoted as $f_j$ [S1].
        d.  Use the optical path $(v_i, v_1)$ and the distance difference between the fragments to retrieve color and opacity from the 3D pre-integrated table [S1].
        e.  Composite the resulting color and opacity to the framebuffer [S1].
        f.  Discard $f_j$ and write the remaining $k$ fragments back to the k-buffer [S1].
3.  **Post-processing:** Apply image processing techniques to the resulting photon intensity information [S2, unofficial]. This includes computing effects of low Z windows, pinholes (modeled via Gaussian blur), and adding noise in a single pass [S2, unofficial].

### Formulas
Let $m \times n$ be the image size, $k$ be the buffer size, and $s_j$ be the number of fragments processed for pixel $j$ [S1].

**Total comparisons for sorted k-buffer per pixel $j$ ($N_2$):**
The total comparisons consist of insertion comparisons ($t_1$) when the buffer is filling, and selection comparisons ($t_2$) when the buffer is full [S1].
$$ N_2 = \sum_{j=1}^{m \times n} (t_1 + t_2) = \sum_{j=1}^{m \times n} \left( \sum_{l=1}^{k-1} l + k \times (s_j - k) \right) $$
*Note: The source text contains a typographical error in the summation limit $\sum_{l=1}^{k \times l}$ which is corrected to $\sum_{l=1}^{k-1} l$ based on the context of insertion steps and the subsequent average formula [S1].*

**Average comparisons per pixel ($e_2$):**
$$ e_2 = \frac{N_2}{m \times n} = \frac{\sum_{j=1}^{m \times n} (\sum_{l=1}^{k-1} l + k \times (s_j - k))}{m \times n} $$

**Difference in average comparisons ($\Delta e$) between original HAVS ($e_1$) and Optimized HAVS ($e_2$):**
$$ \Delta e = e_1 - e_2 = \frac{\sum_{j=1}^{m \times n} ((k-1) \times (s_j - \frac{k}{2} - 1))}{m \times n} $$

**Improved Efficiency:**
As the dataset size increases, the term involving $s_j$ dominates, and the improved efficiency increases [S1].

### Parameters
*   **k:** The buffer size. The original HAVS restricted $k$ to 6 [S1]. The optimized algorithm allows analysis of $k$ to balance precision and efficiency [S1].
*   **Image Size:** In the cited fill-tube simulation, the image size was $160 \times 160$ pixels [S2, unofficial].
*   **Energy Groups:** The simulation handled 57 energy groups [S2, unofficial].

### Edge Cases and Pitfalls
*   **Banding Artifacts:** If the original simulated data is two-dimensional and features not on the axis are rotated about the axial coordinate to create a 3D stand-in, banding artifacts are created [S2, unofficial].
*   **Hardware Requirements:** The algorithm requires recent graphics cards and drivers due to the need for floating-point accuracy and advanced texture capabilities [S2, unofficial].
*   **Precision vs. Efficiency:** Larger $k$ values increase precision but decrease efficiency [S1].

### Pseudocode
```python
def optimized_havs_render(tetrahedra, image_width, image_height, k, pre_integrated_table):
    """
    Renders a volume using the Optimized HAVS (Sorted k-buffer) method.
    
    Args:
        tetrahedra: List of tetrahedra, pre-sorted by distance/depth.
        image_width: Width of the output image (m).
        image_height: Height of the output image (n).
        k: Size of the k-buffer.
        pre_integrated_table: 3D texture/LUT for color/opacity lookup.
        
    Returns:
        framebuffer: The rendered image.
    """
    # Initialize framebuffer with zero intensity
    framebuffer = [[0.0, 0.0, 0.0, 0.0] for _ in range(image_width * image_height)]
    
    # Initialize k-buffers for each pixel
    k_buffers = [[] for _ in range(image_width * image_height)]
    
    # Process each tetrahedron
    for tet in tetrahedra:
        # Standard rasterization: project tetrahedron to screen space
        affected_pixels = rasterize_tetrahedron(tet, image_width, image_height)
        
        for pixel in affected_pixels:
            idx = pixel.y * image_width + pixel.x
            buffer = k_buffers[idx]
            
            # Standard ray-tetrahedron intersection to get fragment properties
            fragment = intersect_tetrahedron(tet, pixel, image_width, image_height)
            
            if len(buffer) < k:
                # Buffer not full: Insert into correct position to maintain sort
                insert_sorted(buffer, fragment)
            else:
                # Buffer full: k comparisons needed
                # 1. Select first fragment f1 (nearest, since sorted)
                f1 = buffer[0]
                
                # 2. Select nearest fragment fi in the rest k fragments
                fi = buffer[1]
                
                # 3. Compare f1 and fi, get smaller one fj
                if f1.distance < fi.distance:
                    fj = f1
                    other = fi
                else:
                    fj = fi
                    other = f1
                
                # 4. Use (vi, v1) and distance difference to get color/opacity
                color, opacity = pre_integrated_table.lookup(fj.distance, other.distance)
                
                # 5. Composite to framebuffer
                framebuffer[pixel] = composite_front_to_back(framebuffer[pixel], color, opacity)
                
                # 6. Discard fj and write remaining k fragments back
                buffer.remove(fj)
                insert_sorted(buffer, fragment)
                
    # Post-processing: Apply Gaussian blur for pinholes, add noise, low Z window
    framebuffer = apply_post_processing(framebuffer)
    
    return framebuffer

def rasterize_tetrahedron(tet, w, h):
    """Standard screen-space projection returning list of pixel coordinates."""
    return [pixel for pixel in standard_rasterization(tet, w, h)]

def intersect_tetrahedron(tet, pixel, w, h):
    """Standard ray-tetrahedron intersection returning distance, color, opacity."""
    return standard_intersection(tet, pixel, w, h)

def insert_sorted(buffer, fragment):
    """Insert fragment into buffer maintaining ascending order of distance."""
    for i in range(len(buffer)):
        if fragment.distance < buffer[i].distance:
            buffer.insert(i, fragment)
            return
    buffer.append(fragment)

def composite_front_to_back(current, color, opacity):
    """Standard front-to-back compositing."""
    return [current[0] + color[0] * opacity * (1 - current[3]),
            current[1] + color[1] * opacity * (1 - current[3]),
            current[2] + color[2] * opacity * (1 - current[3]),
            current[3] + opacity * (1 - current[3])]

def apply_post_processing(framebuffer):
    """Apply Gaussian blur, noise addition, and low Z window filtering."""
    return standard_image_processing(framebuffer)
```

## Operating characteristics
*   **Time Complexity:** The number of comparisons per fragment after the buffer is full is $k$, compared to $2k-1$ in the original HAVS [S1]. The total comparisons are given by the formula $N_2$ in the How it works section [S1].
*   **Memory Complexity:** Requires storage for the k-buffer ($k$ fragments per pixel) and the 3D pre-integrated table [S1].
*   **Measured Performance:** In a fill-tube simulation with 1,719,000 tetrahedra and 57 energy groups:
    *   Software raytracing: 2 minutes on a 2.2 GHz Pentium with 896 MB RAM [S2, unofficial].
    *   Hardware-accelerated k-buffer: 0.656 seconds for initial sort and 57.7 seconds for solution on a 3.2 GHz Pentium 4 with 2 GB RAM and ATI X800 Pro (256 MB RAM) [S2, unofficial].
    *   Image processing operations (blur, noise) accounted for less than 5% of total processing time [S2, unofficial].
*   **Strengths:** Significantly reduces comparison time in fragment-level sorting; suitable for accurate simulated radiographs; leverages GPU hardware acceleration [S1][S2, unofficial].
*   **Limitations:** Requires recent graphics hardware with advanced texture capabilities and floating-point accuracy; banding artifacts can occur with 2D data rotated for 3D simulation; large $k$ reduces efficiency [S1][S2, unofficial].
*   **When to use:** When simulating radiographs with attenuation and attenuation-emission, and when hardware acceleration is available [S2, unofficial].

## Background
Optimized HAVS was proposed as an improvement to the Hardware-Assisted Visibility Sorting (HAVS) algorithm, which is a key volume rendering technique for unstructured grids [S1]. The optimization specifically addresses the efficiency bottleneck of fragment-level sorting by maintaining a sorted k-buffer [S1]. It has been applied in scientific visualization contexts, such as simulating radiographs for fill-tube experiments in high-energy density physics [S2, unofficial]. The method relies on the capabilities of modern GPUs, reflecting the shift towards hardware-accelerated volume rendering in the mid-2000s [S2, unofficial].
