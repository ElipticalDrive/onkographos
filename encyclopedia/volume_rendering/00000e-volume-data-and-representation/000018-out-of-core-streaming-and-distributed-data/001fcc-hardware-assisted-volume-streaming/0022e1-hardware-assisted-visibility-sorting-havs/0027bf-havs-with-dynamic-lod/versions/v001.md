# HAVS with Dynamic LOD

Also called: Hardware-Assisted Visibility Sorting with Dynamic Level of Detail

## Overview
This method extends Hardware-Assisted Visibility Sorting (HAVS) by dynamically adjusting the number of internal mesh faces rendered to maintain a target frame rate during interactive exploration. It separates boundary and internal faces, sorts internal faces by importance, and selectively discards less important faces to reduce rasterization load. Unlike [Optimized HAVS (Sorted k-buffer)](4735-optimized-havs-sorted-k-buffer.md), which optimizes the sorting mechanism, this approach focuses on adaptive sampling of the geometry itself to balance interactivity and visual quality.

## How it works
**Inputs:**
- A tetrahedral mesh (or similar cell-based volume data).
- A target frame rate (typically 10 fps) [S1, unofficial].
- A pre-integrated lookup table (LUT) for standard resolution [S1, unofficial].

**Outputs:**
- A rendered image with opacity and color.
- A dynamic count of internal faces $|I|$ to be rasterized.

**Data Structures:**
1.  **Boundary Face List:** Faces on the exterior of the mesh.
2.  **Internal Face List:** Faces shared between adjacent cells, sorted by importance (most to least).
3.  **k-Buffer:** A fixed-size buffer per pixel storing the $k$ fragments closest to the viewpoint.
4.  **Primary LUT:** 3D texture mapping front scalar, back scalar, and distance to pre-integrated color/opacity. Valid for intervals $\le$ max edge length.
5.  **Secondary LUT:** Scaled 3D texture mapping front scalar, back scalar, and normalized distance (spanning the entire bounding box) to handle large gaps caused by LOD.

**Steps:**

1.  **Preprocessing:**
    1.  Separate all mesh faces into boundary and internal lists.
    2.  Identify duplicate internal faces (neighboring faces with identical vertices and scalar values). Remove these duplicates to prevent zero-length integration intervals [S1, unofficial].
    3.  Sort the remaining internal faces from most important to least important using a sampling strategy (e.g., Field, Area, Topology, or View-aligned) [S1, unofficial].
    4.  Generate the Primary LUT based on the maximum edge length of the original mesh [S1, unofficial].
    5.  Generate the Secondary LUT scaled to handle rays spanning the entire bounding box of the mesh [S1, unofficial].

2.  **Frame Loop (Dynamic LOD Adjustment):**
    1.  Measure the render time of the previous frame.
    2.  Adjust the number of internal faces $|I|$ to be drawn in the current frame to maintain the target frame rate. If the frame was too slow, decrease $|I|$; if too fast, increase $|I|$ [S1, unofficial].
    3.  Select the first $|I|$ faces from the sorted internal list.
    4.  Combine the selected internal faces with all boundary faces.

3.  **Rasterization and Compositing (HAVS Core):**
    1.  **CPU Sort:** Sort the combined face list by their centroids in object space to provide a partial front-to-back order [S1, unofficial].
    2.  **GPU Rasterization:** For each face:
        a.  Rasterize the face to generate fragments.
        b.  **k-Buffer Update:** For each pixel, compare the new fragment with the $k$ entries in the k-buffer. Keep the $k$ fragments closest to the viewpoint [S1, unofficial].
        c.  **Compositing:** Use the two k-buffer entries closest to the viewpoint (front and back) to look up color and opacity.
            *   If using the **Secondary LUT** (during dynamic LOD), use the scaled table to handle the potentially large distance between fragments caused by skipped faces [S1, unofficial].
            *   If using the **Primary LUT** (full quality), use the standard table.
        d.  Composite the result into the framebuffer.
        e.  Write the remaining $k-2$ fragments back to the k-buffer [S1, unofficial].
    3.  **Quality Switch:** When rendering full-quality images (non-interactive), replace the Secondary LUT with the Primary LUT and use the full internal face list [S1, unofficial].

**Pitfalls:**
-   **Gaps:** Removing internal faces creates intervals larger than the maximum edge length used to build the Primary LUT. Using the Primary LUT in this state causes visual artifacts. The Secondary LUT is required during dynamic LOD to handle these large spans [S1, unofficial].
-   **Precision:** The k-buffer size $k$ must be sufficient to capture the necessary depth information for accurate compositing, but large $k$ increases memory bandwidth [S1, unofficial].

**Pseudocode:**

```python
# Preprocessing
boundary_faces = get_boundary_faces(mesh)
internal_faces = get_internal_faces(mesh)
remove_duplicates(internal_faces) # Remove faces with same vertices/scalars
sort_internal_faces_by_importance(internal_faces) # e.g., by area or field value
primary_lut = create_lut(max_edge_length(mesh))
secondary_lut = create_lut_scaled_to_bounding_box(mesh)

# Runtime
target_fps = 10.0
current_internal_face_count = len(internal_faces)

while rendering:
    # 1. Adjust LOD based on previous frame time
    if previous_frame_time > 1.0 / target_fps:
        current_internal_face_count = max(0, current_internal_face_count - step)
    else:
        current_internal_face_count = min(len(internal_faces), current_internal_face_count + step)
    
    # 2. Select faces
    selected_internal = internal_faces[:current_internal_face_count]
    all_faces = boundary_faces + selected_internal
    
    # 3. CPU Sort
    sort_faces_by_centroid(all_faces)
    
    # 4. GPU Rasterization & Compositing
    clear_k_buffer()
    clear_framebuffer()
    
    # Choose LUT based on mode
    if interactive_mode:
        lut = secondary_lut
    else:
        lut = primary_lut
        current_internal_face_count = len(internal_faces) # Full quality override
        
    for face in all_faces:
        fragments = rasterize(face)
        for frag in fragments:
            # Update k-buffer: keep k closest to viewpoint
            update_k_buffer(frag, k)
            
            # Get front and back fragments from k-buffer
            front_frag, back_frag = get_k_closest_fragments(k_buffer, k=2)
            
            # Lookup pre-integrated color/opacity
            # Distance is normalized in secondary LUT, absolute in primary
            color, opacity = lookup(lut, front_frag.scalar, back_frag.scalar, front_frag.dist, back_frag.dist)
            
            # Composite into framebuffer
            composite(framebuffer, color, opacity)
            
            # Write remaining k-2 fragments back
            write_remaining_to_k_buffer(k_buffer, k)
            
    previous_frame_time = measure_render_time()
```

## Operating characteristics
-   **Time Complexity:** Depends on the number of faces rasterized. Dynamic LOD reduces the number of faces $|I|$ to maintain a constant frame rate, effectively capping the rendering time per frame [S1, unofficial].
-   **Memory Complexity:** Requires storage for the mesh faces, the k-buffer (size $k$ per pixel), and two LUTs. The mesh faces can remain on the GPU [S1, unofficial].
-   **Performance:** On an ATI Radeon X800 Pro, the method maintains interactivity by adjusting LOD. The bottleneck is rasterization, which is reduced by drawing fewer faces [S1, unofficial].
-   **Strengths:** Operates on mesh faces rather than cells, resulting in fewer rasterizations ($2n$ triangles for $n$ tetrahedra) compared to projected tetrahedra ($3.4n$). Avoids empty space accumulation errors when dropping primitives [S1, unofficial].
-   **Limitations:** Visual quality degrades as more faces are dropped. The use of the Secondary LUT introduces approximation errors for large intervals [S1, unofficial].

## Background
This method was developed by Steve Callahan as part of his Master's thesis research on the k-buffer and its applications to volume rendering. It builds directly on the Hardware-Assisted Visibility Sorting (HAVS) algorithm described in Chapter 4 of the same work. The work was conducted around 2006-2007, utilizing hardware available at the time (ATI Radeon X800 Pro) [S1, unofficial].
