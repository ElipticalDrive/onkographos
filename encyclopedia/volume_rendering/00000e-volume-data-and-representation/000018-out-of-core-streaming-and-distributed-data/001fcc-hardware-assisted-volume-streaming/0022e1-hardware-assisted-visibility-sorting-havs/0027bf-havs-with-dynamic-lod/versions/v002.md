# HAVS with Dynamic LOD

Also called: Hardware-Assisted Visibility Sorting with Dynamic Level of Detail

## Overview
This method extends Hardware-Assisted Visibility Sorting (HAVS) by dynamically adjusting the number of internal mesh faces rendered to maintain a target frame rate during interactive exploration [S1, unofficial]. It separates boundary and internal faces, sorts internal faces by importance, and selectively discards less important faces to reduce rasterization load [S1, unofficial]. Unlike [Optimized HAVS (Sorted k-buffer)](4735-optimized-havs-sorted-k-buffer.md), which optimizes the sorting mechanism, this approach focuses on adaptive sampling of the geometry itself to balance interactivity and visual quality [S1, unofficial].

## How it works
**Inputs:**
- A tetrahedral mesh (or similar cell-based volume data) [S1, unofficial].
- A target frame rate (typically 10 fps) [S1, unofficial].
- A pre-integrated lookup table (LUT) for standard resolution [S1, unofficial].

**Outputs:**
- A rendered image with opacity and color [S1, unofficial].
- A dynamic count of internal faces $|I|$ to be rasterized [S1, unofficial].

**Data Structures:**
1. **Boundary Face List:** Faces on the exterior of the mesh [S1, unofficial].
2. **Internal Face List:** Faces shared between adjacent cells, sorted by importance (most to least) [S1, unofficial].
3. **k-Buffer:** A fixed-size buffer per pixel storing $k$ fragments [S1, unofficial].
4. **Primary LUT:** 3D texture mapping front scalar, back scalar, and distance to pre-integrated color/opacity. Valid for intervals $\le$ max edge length [S1, unofficial].
5. **Secondary LUT:** Scaled 3D texture mapping front scalar, back scalar, and normalized distance (spanning the entire bounding box) to handle large gaps caused by LOD [S1, unofficial].

**Steps:**

1. **Preprocessing:**
    1. Separate all mesh faces into boundary and internal lists [S1, unofficial].
    2. Identify duplicate internal faces (neighboring faces with identical vertices and scalar values) and remove them to prevent zero-length integration intervals [S1, unofficial].
    3. Sort the remaining internal faces from most important to least important using a sampling strategy (e.g., Field, Area, Topology, or View-aligned) [S1, unofficial].
    4. Generate the Primary LUT based on the maximum edge length of the original mesh [S1, unofficial].
    5. Generate the Secondary LUT scaled to handle rays spanning the entire bounding box of the mesh [S1, unofficial].

2. **Frame Loop (Dynamic LOD Adjustment):**
    1. Measure the render time of the previous frame [S1, unofficial].
    2. Adjust the number of internal faces $|I|$ to be drawn in the current frame to maintain the target frame rate. If the frame was too slow, decrease $|I|$; if too fast, increase $|I|$ [S1, unofficial].
    3. Select the first $|I|$ faces from the sorted internal list [S1, unofficial].
    4. Combine the selected internal faces with all boundary faces [S1, unofficial].

3. **Rasterization and Compositing (HAVS Core):**
    1. **CPU Sort:** Sort the combined face list by their centroids in object space to provide a partial front-to-back order [S1, unofficial].
    2. **GPU Rasterization:** For each face:
        a. Rasterize the face to generate fragments [S1, unofficial].
        b. **k-Buffer Update:** For each pixel, compare the new fragment with the $k$ entries in the k-buffer [S1, unofficial].
        c. **Compositing:** Use the two k-buffer entries closest to the viewpoint (front and back) to look up color and opacity [S1, unofficial].
            * If using the **Secondary LUT** (during dynamic LOD), use the scaled table to handle the potentially large distance between fragments caused by skipped faces [S1, unofficial].
            * If using the **Primary LUT** (full quality), use the standard table [S1, unofficial].
        d. Composite the result into the framebuffer [S1, unofficial].
        e. Write the remaining fragments back to the k-buffer [S1, unofficial].
    3. **Quality Switch:** When rendering full-quality images (non-interactive), use the Primary LUT and the full internal face list [S1, unofficial].

**Pitfalls:**
- **Gaps:** Removing internal faces creates intervals larger than the maximum edge length used to build the Primary LUT. Using the Primary LUT in this state causes visual artifacts. The Secondary LUT is required during dynamic LOD to handle these large spans [S1, unofficial].

**Pseudocode:**

```python
# Preprocessing
boundary_faces = [f for f in mesh.faces if f.is_boundary]
internal_faces = [f for f in mesh.faces if not f.is_boundary]
# Remove duplicates: neighboring faces with same vertices and scalar values
unique_internal = []
seen_keys = set()
for f in internal_faces:
    key = (tuple(sorted(f.vertices)), f.scalar)
    if key not in seen_keys:
        seen_keys.add(key)
        unique_internal.append(f)
# Sort internal faces from most important to least important
unique_internal.sort(key=lambda f: importance_score(f), reverse=True)
primary_lut = create_3d_texture(front_scalar, back_scalar, distance, max_edge_length(mesh))
secondary_lut = create_3d_texture_scaled(front_scalar, back_scalar, normalized_distance, mesh.bounding_box)

# Runtime
target_fps = 10.0
current_i = len(unique_internal)
previous_frame_time = 0.0
k = 4  # Not given in the sources.
k_buffer = {}  # pixel_id -> list of fragments

while True:
    # 1. Adjust LOD based on previous frame time
    if previous_frame_time > 1.0 / target_fps:
        current_i = max(0, current_i - 1)
    else:
        current_i = min(len(unique_internal), current_i + 1)

    # 2. Select faces
    selected_internal = unique_internal[:current_i]
    all_faces = boundary_faces + selected_internal

    # 3. CPU Sort by centroid
    all_faces.sort(key=lambda f: centroid(f))

    # 4. GPU Rasterization & Compositing
    # k_buffer and framebuffer are managed by GPU fragment shaders
    use_secondary = current_i < len(unique_internal)
    lut = secondary_lut if use_secondary else primary_lut

    for face in all_faces:
        fragments = rasterize(face)
        for frag in fragments:
            pixel_id = frag.screen_coords
            if pixel_id not in k_buffer:
                k_buffer[pixel_id] = []
            entries = k_buffer[pixel_id]

            # Compare with k-buffer entries, keep k fragments
            entries.append(frag)
            entries.sort(key=lambda e: e.distance_to_viewpoint)
            if len(entries) > k:
                entries.pop() # Replacement policy not specified in sources [G]

            # Compositing: use two entries closest to viewpoint
            if len(entries) >= 2:
                front_frag = entries[-1]
                back_frag = entries[-2]
                color, opacity = lookup(lut, front_frag.scalar, back_frag.scalar, front_frag.distance, back_frag.distance)
                composite(framebuffer, color, opacity)
                # Write remaining k-2 fragments back
                k_buffer[pixel_id] = entries[:-2]
            elif len(entries) == 1:
                k_buffer[pixel_id] = entries

    previous_frame_time = measure_render_time()
```

## Operating characteristics
- **Time Complexity:** Depends on the number of faces rasterized. Dynamic LOD reduces the number of faces $|I|$ to maintain a constant frame rate, effectively capping the rendering time per frame [S1, unofficial].
- **Memory Complexity:** Requires storage for the mesh faces, the k-buffer (size $k$ per pixel), and two LUTs. The mesh faces can remain on the GPU [S1, unofficial].
- **Performance:** On an ATI Radeon X800 Pro, the method maintains interactivity by adjusting LOD. The bottleneck is rasterization, which is reduced by drawing fewer faces [S1, unofficial].
- **Strengths:** Operates on mesh faces rather than cells, resulting in fewer rasterizations ($2n$ triangles for $n$ tetrahedra) compared to projected tetrahedra ($3.4n$). Avoids empty space accumulation errors when dropping primitives [S1, unofficial].
- **Limitations:** Visual quality degrades as more faces are dropped. The use of the Secondary LUT introduces approximation errors for large intervals [S1, unofficial].

## Background
This method was developed by Steve Callahan as part of his Master's thesis research on the k-buffer and its applications to volume rendering. It builds directly on the Hardware-Assisted Visibility Sorting (HAVS) algorithm described in Chapter 4 of the same work. The work was conducted around 2006-2007, utilizing hardware available at the time (ATI Radeon X800 Pro) [S1, unofficial].
