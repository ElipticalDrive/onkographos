# HAVS-based Progressive Rendering

Also called: Progressive Volume Rendering, Progressive Volume Rendering of Unstructured Grids

## Overview
HAVS-based Progressive Rendering is a level-of-detail framework for the interactive exploration of large unstructured tetrahedral datasets that exceed the memory or rendering capacity of conventional direct volume rendering techniques [S1]. It solves the problem of visualizing massive meshes (e.g., ~14 million tetrahedra) by incrementally streaming portions of the mesh geometry to a hardware-assisted renderer, displaying approximations that increase in quality until a full-quality image is achieved [S1]. Unlike full-volume streaming methods that transmit all geometry, this approach processes the triangles that compose the tetrahedral mesh and relies on Hardware-Assisted Visibility Sorting (HAVS) to manage surface composition in both object-space and image-space, allowing the client to accumulate and refine the image progressively [S1]. It builds on [HAVS with Dynamic LOD](4110-havs-with-dynamic-lod.md) by providing a reduced representation during interaction and refining the image during idle frames [S1].

## How it works
The method combines object-space sorting, GPU-based image-space sorting via a k-buffer, and iterative compositing to generate a progressive image [S1].

**Inputs and Outputs**
*   **Input:** A large tetrahedral mesh (unstructured grid) defined by vertices and tetrahedra [S1].
*   **Output:** A sequence of increasingly accurate 2D image approximations displayed to the user [S1].

**Data Structures**
1.  **Sorted Triangle List:** The triangles composing the tetrahedral mesh are pre-sorted by their centroid in object-space [S1].
2.  **K-buffer:** A fixed-size A-buffer implemented using GPU textures. It stores fragments sorted by depth in image-space [S1].
3.  **Off-screen Framebuffer:** A texture buffer storing the composited result of the two closest fragments (scalar values and distance) for generating the current approximation [S1].
4.  **3D Pre-integrated Table:** A 3D texture containing volume integral data used to composite fragments into the framebuffer based on scalar values and distances [S1].

**Parameters**
*   **Batch Size:** The number of internal triangles streamed and rasterized in each iteration [S1]. Not given in the sources.
*   **K-buffer Size:** The fixed capacity of the A-buffer [S1]. Not given in the sources.

**Algorithm Steps**

1.  **Initialization:**
    *   Clear the off-screen framebuffer and the k-buffer [S1].
    *   Sort all triangles of the tetrahedral mesh by centroid [S1].

2.  **Boundary Rendering (Initial State):**
    *   Identify the boundary triangles of the mesh [S1].
    *   Rasterize the boundary triangles [S1].
    *   Insert the front and back fragments of the boundary triangles into the k-buffer [S1].

3.  **Iterative Refinement Loop:**
    *   While the full-quality image is not achieved and the user is not interacting:
        a.  **Stream Geometry:** Select the next batch of internal triangles from the sorted list [S1].
        b.  **Rasterization:** Rasterize the batch of internal triangles [S1].
        c.  **Image-Space Sorting:** Insert the resulting fragments into the k-buffer, maintaining the sorted order [S1].
        d.  **Fragment Selection:** Retrieve the two fragments closest to the viewpoint from the k-buffer (front-most and second-front-most) [S1].
        e.  **Compositing to Off-screen Buffer:**
            *   Let $F_1$ be the front-most fragment and $F_2$ be the second-front-most fragment [S1].
            *   Let $s_1, s_2$ be their scalar values and $d_1, d_2$ be their distances from the viewpoint [S1].
            *   Use the 3D pre-integrated table to composite $F_1$ and $F_2$ into the off-screen framebuffer [S1]. The compositing accounts for the scalar values and the distance between them ($d_2 - d_1$) [S1].
        f.  **K-buffer Update:**
            *   Discard the front-most fragment ($F_1$) from the k-buffer [S1].
            *   Store the remaining fragments (including $F_2$ and any new fragments) back into the k-buffer [S1].
        g.  **Approximation Generation:**
            *   Create an approximation for the current rasterized portion by compositing the off-screen framebuffer with the contribution of the gap between the front and back fragments still residing in the k-buffer [S1].
        h.  **Display:** Display the generated approximation [S1].
        i.  **State Maintenance:** Keep the off-screen framebuffer and the updated k-buffer for the subsequent iteration [S1].

4.  **Interaction Reset:**
    *   If the user changes the view or interacts with the scene:
        *   Clear the off-screen framebuffer and the k-buffer [S1].
        *   Reset the triangle stream to the beginning [S1].
        *   Restart the process from the boundary rendering phase [S1].

**Pseudocode**

```python
from dataclasses import dataclass
from typing import List, Tuple, Dict

@dataclass
class Fragment:
    depth: float
    scalar: float
    pixel: Tuple[int, int]

class KBuffer:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.fragments: List[Fragment] = []

    def insert_sorted(self, new_fragments: List[Fragment]):
        self.fragments.extend(new_fragments)
        self.fragments.sort(key=lambda f: f.depth)
        if len(self.fragments) > self.capacity:
            self.fragments = self.fragments[:self.capacity]

    def get_front_two(self) -> Tuple[Fragment, Fragment]:
        if len(self.fragments) < 2:
            return None, None
        return self.fragments[0], self.fragments[1]

    def remove_front(self):
        if self.fragments:
            self.fragments.pop(0)

    def clear(self):
        self.fragments.clear()

def rasterize(triangles: List, viewpoint: Tuple[float, float, float]) -> List[Fragment]:
    fragments = []
    for tri in triangles:
        # Standard triangle rasterization: project to screen, interpolate scalar, compute depth [G]
        fragments.append(Fragment(depth=0.0, scalar=0.0, pixel=(0, 0)))
    return fragments

def composite_fragments(f1: Fragment, f2: Fragment, table: Dict) -> Tuple[float, float]:
    distance = f2.depth - f1.depth
    # Lookup in 3D pre-integrated table using scalar values and distance [S1]
    return table.get((f1.scalar, f2.scalar, distance), (0.0, 0.0))

def generate_approximation(offscreen_fb: List[Tuple[float, float]], k_buffer: KBuffer, table: Dict) -> List[Tuple[float, float]]:
    # Composite off-screen framebuffer with the contribution of the gap
    # between the front and back fragments still in the k-buffer [S1]
    result = offscreen_fb.copy()
    # Standard volume compositing for remaining fragments to fill the gap [G]
    for frag in k_buffer.fragments:
        result.append((frag.scalar, frag.depth))
    return result

def havs_progressive_render(mesh: List, viewpoint: Tuple[float, float, float], k_buffer_capacity: int, pre_integrated_table: Dict):
    k_buffer = KBuffer(capacity=k_buffer_capacity)
    offscreen_fb = []

    all_triangles = mesh.get_all_triangles()
    sorted_triangles = sorted(all_triangles, key=lambda t: t.centroid)

    boundary_triangles = [t for t in all_triangles if mesh.is_boundary(t)]
    boundary_fragments = rasterize(boundary_triangles, viewpoint)
    k_buffer.insert_sorted(boundary_fragments)

    internal_stream_index = 0
    batch_size = 1000  # Not given in the sources.

    while not mesh.is_full_quality() and not mesh.user_interacted():
        batch = sorted_triangles[internal_stream_index : internal_stream_index + batch_size]
        internal_stream_index += batch_size

        new_fragments = rasterize(batch, viewpoint)
        k_buffer.insert_sorted(new_fragments)

        f1, f2 = k_buffer.get_front_two()
        if f1 is None or f2 is None:
            continue

        composite_result = composite_fragments(f1, f2, pre_integrated_table)
        offscreen_fb.append(composite_result)

        k_buffer.remove_front()

        approximation = generate_approximation(offscreen_fb, k_buffer, pre_integrated_table)
        # Display approximation
        # State maintenance: buffers kept for next iteration

    if mesh.user_interacted():
        k_buffer.clear()
        offscreen_fb.clear()
        internal_stream_index = 0
        boundary_fragments = rasterize(boundary_triangles, viewpoint)
        k_buffer.insert_sorted(boundary_fragments)
```

## Subtopics

### [Hardware-Assisted Progressive Volume Rendering](8241-hardware-assisted-progressive-volume-rendering.md)
A client-server architecture that minimizes client-side storage by transmitting only necessary mesh triangles in progressive depth ranges. It differs by focusing on network transmission and client accumulation, whereas HAVS-based Progressive Rendering focuses on GPU-side incremental refinement and state maintenance.

## Operating characteristics
*   **Time Complexity:** The algorithm renders each triangle in the mesh only once per viewpoint, leading to an efficient LOD algorithm that quickly converges to a full-quality image [S1].
*   **Memory Complexity:** The method maintains only a light-weight image representation of the volume between rendering steps, storing state in the k-buffer and off-screen framebuffer [S1].
*   **Measured Performance:** Demonstrated on the SF1 dataset consisting of about 14 million tetrahedra [S1].
*   **Strengths:** Provides a reduced representation during interaction and incrementally refines the progressive image during idle frames, allowing for interactive exploration of datasets too large for conventional approaches [S1].
*   **Limitations:** The incremental state is invalid upon user interaction; the view change requires clearing buffers and restarting, which may cause a temporary drop in frame rate or quality until the new view is re-established [S1].
*   **When to use:** Interactive exploration of large tetrahedral datasets in scientific computing domains like computational fluid dynamics and structural mechanics [S1].
*   **When not to use:** When the dataset is small enough to be rendered conventionally or when immediate full-quality rendering without progressive refinement is required [S1].

## Background
The method was developed by S. P. Callahan, L. Bavov, V. Pascucci, and C. T. Silva [S1]. It is based on the Hardware-Assisted Visibility Sorting (HAVS) algorithm [Callahan et al. 2005] and extends it to handle larger datasets through progressive rendering [Callahan et al. 2006] [S1]. The work was performed under the auspices of the U.S. DOE by LLNL and supported by NSF, DOE, IBM, and ARO [S1].
