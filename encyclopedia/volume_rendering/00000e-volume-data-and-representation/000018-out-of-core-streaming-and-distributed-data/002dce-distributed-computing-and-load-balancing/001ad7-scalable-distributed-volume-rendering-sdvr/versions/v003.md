# Scalable Distributed Volume Rendering (SDVR)

Also called: Cluster-based Distributed Volume Rendering, Distributed Volume Rendering System, Distributed rendering system for unstructured data, Distributed slicing rendering, MPI-based distributed volume rendering

## Overview
Scalable Distributed Volume Rendering (SDVR) is a distributed rendering method for unstructured data targeting large PC clusters, using OpenGL and MPI, designed for scalability where rendering time remains constant as data size and node count increase [S1][S2, unofficial]. It solves the problem of rendering massive unstructured grids by partitioning the dataset into load-balanced chunks and accumulating subimages over the network [S1][S2, unofficial]. Unlike sibling methods like [MPI Volume Rendering (1D/2D Decomposition)](2249-mpi-volume-rendering-1d-2d-decomposition.md) which may rely on structured grid decomposition, SDVR uses an out-of-core modified k-d decomposition to handle arbitrary unstructured data, and unlike [Distributed Volume Ray Tracing with Global Kd-Tree](1774-distributed-volume-ray-tracing-with-global-kd-tree.md) which scatters adjacent cells for load balance, SDVR clusters them into brick-shaped chunks for efficient local slicing [S1][S2, unofficial].

## How it works
**Inputs:** Unstructured volume dataset (e.g., curvilinear or unstructured grid); cluster configuration (number of nodes).
**Outputs:** Final composite image.

**Data Structures:**
1.  **Dataset Partition:** The input is partitioned into "brick-shaped chunks." These are spatially contiguous subsets of the unstructured grid.
2.  **Distribution Map:** A mapping of chunks to cluster nodes (MPI ranks).
3.  **Subimages:** Per-node rendered images (typically RGBA buffers).

**Steps:**
1.  **Preprocessing (Partitioning):** Partition the dataset into small, load-balanced chunks. This is done using an out-of-core algorithm based on a modified k-d decomposition [S1][S2, unofficial]. The goal is to ensure each chunk has approximately equal computational cost (e.g., similar number of cells or volume).
2.  **Distribution:** Distribute the brick-shaped chunks to the nodes of the cluster via MPI [S1][S2, unofficial]. Each node receives a subset of chunks.
3.  **Local Rendering:** Each node independently slices, clips, and renders its assigned chunks. This step typically uses OpenGL for hardware acceleration if available, or software rendering otherwise [S1][S2, unofficial]. The slicing method projects cells onto the view plane [S1].
4.  **Compositing:** Gather and accumulate the resulting subimages from all nodes over the interconnect system [S1][S2, unofficial]. This is typically done via pixel-based accumulation (e.g., using MPI_Reduce or similar collective operations) to form the final image.

**Edge Cases and Pitfalls:**
*   **Communication Overhead:** The speed-up curve levels out after a certain number of threads (e.g., 5 for slicing, 18 for projection) due to communications overhead [S1].
*   **Load Imbalance:** If the k-d decomposition is not effective, some nodes may have significantly more work, leading to idle time [S1][S2, unofficial].
*   **Memory Constraints:** The out-of-core algorithm is necessary because the dataset may exceed the memory of individual nodes [S1][S2, unofficial].

## Subtopics

### [Distributed Volume Ray Tracing with Global Kd-Tree](1774-distributed-volume-ray-tracing-with-global-kd-tree.md)
A distributed rendering method for load balancing where adjacent tetrahedra are scattered across nodes rather than clustered, using a global kd-tree to restore ordering during rendering. Unlike SDVR which clusters adjacent tetrahedra into brick-shaped chunks, this method scatters them to maintain load balance for close views, at the cost of requiring a global kd-tree.

### [Distributed Shared Virtual Memory Volume Rendering](1916-distributed-shared-virtual-memory-volume-rendering.md)
Distributed Shared Virtual Memory (DSVM) Volume Rendering is a method for rendering tera-scale volumes on GPU clusters by mapping the entire volume into a single shared 3D virtual memory space accessible by all nodes. It solves the problem of managing massive datasets that exceed the physical memory of individual GPUs by using on-demand paging of small voxel blocks, allowing multiple nodes to render disjoint parts of the volume simultaneously without explicit data partitioning or load balancing. It differs from SDVR by relying on a flat virtual memory address space with hardware-assisted page fault handling rather than a distributed spatial index, and by targeting small GPU clusters where implicit load balancing via interleaved distribution units suffices.

## Operating characteristics
*   **Scalability:** The primary goal is scalability: as the data set size increases, if additional computational nodes are provided, rendering time remains constant [S1][S2, unofficial].
*   **Performance:** A prototype ran successfully at interactive rates on up to 32 nodes of a PC cluster with Nvidia GeForce-3 graphics cards [S1][S2, unofficial].
*   **Hardware Requirements:** Can run on any platform with or without graphics hardware, though peak performance requires hardware [S1][S2, unofficial].
*   **Limitations:** Performance may be limited by communication overhead, especially as the number of nodes increases [S1]. The system is designed for large PC clusters (16-1000+ nodes) [S1][S2, unofficial].
*   **When to Use:** Suitable for large unstructured datasets that cannot fit in a single node's memory, and when a cluster with MPI support is available.
*   **When Not to Use:** For small datasets that fit in memory, or when high-performance graphics hardware is not available and software rendering is too slow.

## Background
SDVR was developed for the visualization of large unstructured grids, such as those found in scientific simulations. It was presented in the context of volume rendering for curvilinear and unstructured grids [S1][S2, unofficial]. The work was performed under the auspices of the U.S. Department of Energy by Lawrence Livermore National Laboratory [S1][S2, unofficial]. The system targets large PC clusters, leveraging MPI for communication and OpenGL for rendering [S1][S2, unofficial].
