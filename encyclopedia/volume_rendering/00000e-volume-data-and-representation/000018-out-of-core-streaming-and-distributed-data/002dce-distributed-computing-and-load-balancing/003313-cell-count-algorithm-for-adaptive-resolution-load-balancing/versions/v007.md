# Cell Count Algorithm for Adaptive-Resolution Load Balancing

Also called: Adaptive-resolution data decomposition, Shuttle algorithm for block assignment, Spatial Division of Adaptive-Resolution Data

## Overview
The Cell Count Algorithm is a load-balancing strategy for distributed volume rendering of adaptive-resolution datasets, where data is partitioned into blocks of varying resolutions [S1, unofficial]. Unlike spatial decomposition which divides the volume by geometric extent, this method assigns blocks to processors based on their cell counts to ensure that each processor handles a roughly equal computational workload, preventing idle time caused by low-resolution blocks finishing early [S1, unofficial].

## How it works
The algorithm distributes blocks of varying resolutions among processors to balance workload [S1, unofficial]. It assumes that rendering time is proportional to the number of cells in a block, and that each block has a consistent resolution [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** A list of $n$ blocks $B_1, B_2, \dots, B_n$. Each block $B_x$ has an associated cell count $C_x$ representing its resolution [S1, unofficial]. A list of $p$ available processors $P_1, \dots, P_p$ [S1, unofficial].
*   **Output:** An assignment mapping each block $B_x$ to a processor $P_y$ such that the total cell count assigned to each processor is approximately equal [S1, unofficial].

**Data Structures:**
*   **Block List:** A list of objects containing at least the field `cell_count` (integer) [S1, unofficial].
*   **Processor List:** A list of objects containing at least the field `accumulated_cell_count` (integer) [S1, unofficial].
*   **Sorted Blocks:** A list of block references, sorted by `cell_count` in descending order [S1, unofficial].

**Parameters:**
*   $n$: Total number of blocks [S1, unofficial].
*   $p$: Total number of processors [S1, unofficial].
*   $C_x$: Cell count of block $x$ [S1, unofficial].

**Steps:**
1.  **Calculate Total Cells:** Compute the total number of cells in the dataset by summing the cell counts of all blocks:
    $$ C_{total} = \sum_{x=1}^{n} C_x $$
    [S1, unofficial]
2.  **Calculate Optimal Load:** Determine the optimal number of cells per processor by dividing the total cell count by the number of processors, rounded up to the nearest integer:
    $$ C_{optimal} = \lceil C_{total} / p \rceil $$
    [S1, unofficial]
3.  **Sort Blocks:** Sort all blocks in descending order based on their cell count $C_x$ [S1, unofficial].
4.  **Initialize Processors:** Initialize the list of available processors with `accumulated_cell_count` set to 0 [S1, unofficial].
5.  **Assign Blocks (Shuttle Algorithm):** Iterate through the sorted blocks and assign them to processors using a cycling strategy [S1, unofficial]:
    *   Maintain a pointer to the current processor in the active list (initially the first processor) [S1, unofficial].
    *   Maintain a pointer to the next unassigned block in the sorted list (initially the first block) [S1, unofficial].
    *   While there are unassigned blocks:
        1.  Select the `current_processor` from the active list [S1, unofficial].
        2.  Select the `current_block` from the sorted blocks list [S1, unofficial].
        3.  Assign `current_block` to `current_processor` [S1, unofficial].
        4.  Update `current_processor.accumulated_cell_count` by adding `current_block.cell_count` [S1, unofficial].
        5.  Check if `current_processor.accumulated_cell_count` $\ge C_{optimal}$ [S1, unofficial].
        6.  If the condition is met, mark `current_processor` as full and remove it from the active list [S1, unofficial].
        7.  Advance the block pointer to the next block [S1, unofficial].
        8.  Advance the processor pointer to the next processor in the active list (cycling if necessary) [S1, unofficial].

**Pseudocode:**
```python
def cell_count_algorithm(blocks, num_processors):
    """
    blocks: List of dicts/objects with 'cell_count'
    num_processors: Integer, number of processors
    Returns: List of processor indices for each block in original order
    """
    n = len(blocks)
    if n == 0:
        return []

    # Step 1: Calculate total cells
    total_cells = sum(b['cell_count'] for b in blocks)

    # Step 2: Calculate optimal cells per processor (round up)
    optimal_cells = (total_cells + num_processors - 1) // num_processors

    # Step 3: Sort blocks by cell count descending, keep original indices
    sorted_blocks = sorted(enumerate(blocks), key=lambda x: x[1]['cell_count'], reverse=True)

    # Step 4: Initialize processors
    processors = [{'id': i, 'accumulated': 0} for i in range(num_processors)]
    active_procs = list(range(num_processors)) # Indices into processors list
    proc_ptr = 0

    assignments = [None] * n

    # Step 5: Assign blocks (Shuttle Algorithm)
    for orig_idx, block in sorted_blocks:
        # Cycle through active processors
        current_proc_idx = active_procs[proc_ptr % len(active_procs)]
        current_proc = processors[current_proc_idx]

        # Assign block
        assignments[orig_idx] = current_proc['id']
        current_proc['accumulated'] += block['cell_count']

        # Check if processor is full
        if current_proc['accumulated'] >= optimal_cells:
            # Remove from active list
            active_procs.pop(proc_ptr % len(active_procs))
            # If pointer exceeded new list length, reset to 0
            if proc_ptr >= len(active_procs):
                proc_ptr = 0
        else:
            proc_ptr += 1

    return assignments
```

**Edge Cases and Pitfalls:**
*   **Large Blocks:** If a single block's cell count exceeds $C_{optimal}$, the assigned processor will exceed the optimal threshold immediately and be removed from the active list [S1, unofficial]. Subsequent blocks are distributed among the remaining processors [S1, unofficial].
*   **Precision:** Cell counts are integers, and rounding $C_{optimal}$ up ensures the sum of assigned cells meets or exceeds $C_{total}$, though individual processors may deviate slightly from the exact average [S1, unofficial].
*   **Consistent Resolution:** The algorithm assumes each block has a consistent resolution [S1, unofficial]. If a block contains mixed resolutions, the cell count might not accurately reflect the rendering cost [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Sorting the blocks takes $O(n \log n)$ where $n$ is the number of blocks [S1, unofficial]. The assignment loop runs in $O(n)$ time [S1, unofficial]. Total time complexity is $O(n \log n)$ [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** It effectively balances computational load by accounting for varying block resolutions [S1, unofficial]. It prevents idle time that would occur with equal spatial division [S1, unofficial].
*   **Limitations:** It does not guarantee spatial locality [S1, unofficial]. Processors may receive blocks that are far apart in the volume, potentially increasing communication overhead for compositing if the rendering algorithm requires neighbor data or if compositing is done in a spatial order [S1, unofficial]. The source contrasts this with equal data division, noting that equal division assigns equal numbers of blocks regardless of resolution, leading to imbalance [S1, unofficial].
*   **When to Use:** Use when the dataset has significant variation in resolution (adaptive resolution) and computational cost is dominated by the number of cells rather than communication [S1, unofficial]. Use when the number of processors is comparable to or less than the number of blocks [S1, unofficial].
*   **When Not to Use:** Avoid if spatial locality is critical for performance (e.g., cache coherence, minimal communication) and the resolution variation is low [S1, unofficial]. Avoid if the number of processors is much larger than the number of blocks, as many processors will remain idle [S1, unofficial].

## Background
The Cell Count Algorithm was described in the context of volume visualization of time-varying data using parallel, multiresolution and adaptive-resolution techniques [S1, unofficial]. It addresses the inefficiency of dividing adaptive-resolution data equally by spatial extent, which causes processors handling low-resolution portions to finish early and sit idle [S1, unofficial]. The algorithm is also referred to as the "shuttle algorithm" for block assignment in the source [S1, unofficial]. It is part of a broader effort to optimize distributed processing for adaptive-resolution datasets, where blocks have consistent resolutions represented by their cell counts [S1, unofficial].
