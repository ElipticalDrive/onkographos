# Dynamic load balancing using kd-trees

Also called: kd-tree based load balancing, hierarchical load balancing

## Overview
This method uses a kd-tree to hierarchically decompose the volume data space, enabling dynamic redistribution of computational work among processors to minimize load imbalance across frames [S1, unofficial]. It sets itself apart from static decomposition methods by allowing runtime adjustment of partition boundaries based on load statistics stored in inner nodes, and from queue-based methods by structuring work distribution spatially rather than as a flat list of tasks [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume dataset, a current load balance state (statistics), and a target number of processors $P$.
*   **Output:** An assignment of data partitions (leaf nodes) to processors.

**Data Structures:**
*   **kd-tree:** A binary tree encoding the decomposition of the data space.
    *   **Inner Nodes:** Store load statistics (e.g., estimated cost, occlusion information, or voxel count) for the subtree rooted at that node [S1, unofficial].
    *   **Leaf Nodes:** Contain the effective partitions of work (e.g., bricks or subvolumes) assigned to specific processors [S1, unofficial].
    *   **Splitting:** At each level, the data space is split alternating along orthogonal axes (x, y, z) [S1, unofficial].

**Steps:**
1.  **Estimate Costs:** Calculate load statistics for each partition. This may involve estimated rendering costs or occlusion information [S1, unofficial].
2.  **Build/Update Tree:** Populate the kd-tree. Leaf nodes hold the current work partitions. Inner nodes aggregate the load statistics from their children [S1, unofficial].
3.  **Traverse for Balance:** Traverse the kd-tree in a specific order to redistribute partitions. The traversal strategy aims to balance the load statistics across the $P$ processors [S1, unofficial].
4.  **Assign Partitions:** Assign the leaf node partitions to processors based on the balanced traversal [S1, unofficial].

**Parameters:**
*   **Splitting Axis:** Alternates between x, y, and z axes at each tree level [S1, unofficial].
*   **Load Statistic:** Can be estimated cost, occlusion info, or simple voxel count [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Replication:** When using the kd-tree to determine the compositing order of partial rays, replication of boundary data is necessary to ensure correct blending across processor boundaries [S1, unofficial].

### [Incremental Load Balancing with Brick Caching](9862-incremental-load-balancing-with-brick-caching.md)
A dynamic load balancing technique for distributed volume rendering that incrementally moves bricks between cluster nodes to correct imbalance, using a caching mechanism to reduce transfer costs when reversing moves. It sets itself apart from full-tree balancing methods by processing only one node per frame to respect limited computation time, and from naive incremental methods by employing a brick cache to mitigate oscillation and stagnation caused by high network transfer costs.
