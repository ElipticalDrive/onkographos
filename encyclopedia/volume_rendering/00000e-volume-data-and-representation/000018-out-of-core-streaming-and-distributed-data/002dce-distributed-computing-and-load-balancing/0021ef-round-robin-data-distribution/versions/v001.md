# Round-Robin Data Distribution

Also called: Round-Robin Cell Distribution, Round-Robin Static Load Balancing, Round-robin distribution, Static Load Balancing via Round Robin

## Overview
Round-Robin Data Distribution is a static load balancing strategy for parallel volume rendering where mesh cells are assigned to processors in a cyclic order [S1, unofficial][S2]. It solves the problem of load imbalance caused by variations in cell size, shape, and opacity by dispersing connected cells widely among processors, thereby averaging out computational requirements [S1, unofficial]. Unlike methods that group connected cells to exploit spatial coherence, this approach scatters them to avoid exacerbating imbalances, as connected cells often share similar rendering costs [S1, unofficial]. It is distinct from [Scalable Distributed Volume Rendering (SDVR)](863-scalable-distributed-volume-rendering-sdvr.md) and [MPI Volume Rendering (1D/2D Decomposition)](2249-mpi-volume-rendering-1d-2d-decomposition.md) by prioritizing load averaging over spatial locality [S1, unofficial][S2].

## How it works
**Inputs:** A set of $N$ mesh cells (e.g., tetrahedra) and $P$ processors.
**Outputs:** An assignment map mapping each cell index to a processor ID.

**Data Structures:**
*   **Cell:** Stores 4 node indices. Size: 16 bytes [S1, unofficial][S2].
*   **Node:** Stores 3 coordinates and 1 scalar value. Size: 16 bytes [S1, unofficial][S2].
*   **Assignment Array:** An array of size $N$ storing processor IDs.

**Steps:**
1.  Iterate through all mesh cells $i$ from $0$ to $N-1$.
2.  Assign cell $i$ to processor $p$ using the formula:
    $$ p = i \mod P $$
    where $P$ is the total number of processors [S1, unofficial].
3.  Store the assignment in the assignment array.
4.  Distribute the cell data and necessary node data to the assigned processors [S1, unofficial].

**Parameters:**
*   $P$: Number of processors.
*   $N$: Number of cells.

**Edge Cases and Pitfalls:**
*   **Data Transfer Volume:** The round-robin distribution discourages data sharing. In the worst case, where no node information is shared between cells assigned to a processor, the maximum data transferred is $80n$ bytes for distributing $n$ cells to a single processor [S1, unofficial][S2]. This is derived from:
    $$ 16 \text{ bytes/cell} \times n \text{ cells} + 16 \text{ bytes/node} \times 4 \text{ nodes/cell} \times n \text{ cells} = 80n \text{ bytes} $$
    [S1, unofficial][S2].
*   **Spatial Coherence:** The method destroys spatial relationships between cells, making the dataset appear more regular but complicating optimizations that rely on locality [S2].
*   **Connectivity:** No connectivity data is needed for the distribution itself, only cell and node information [S1, unofficial][S2].

**Pseudocode:**
```python
def round_robin_distribution(cells, num_processors):
    """
    Assigns cells to processors in a round-robin fashion.
    
    Args:
        cells: List of cell objects, each having a unique index and 4 node indices.
        num_processors: Total number of processors P.
        
    Returns:
        assignments: List of processor IDs for each cell.
    """
    num_cells = len(cells)
    assignments = [0] * num_cells
    
    for i in range(num_cells):
        # Assign cell i to processor (i mod P)
        processor_id = i % num_processors
        assignments[i] = processor_id
        
    return assignments
```

## Subtopics

### Static Round-Robin Partitioning
A variant where the data volume is partitioned into $n-p$ subvolumes (where $n$ is a "magic number" determined by 1-2 test runs) and these subvolumes are distributed round-robin across $p$ processors [S3, unofficial]. Each processor renders its assigned disjointed subvolumes [S3, unofficial]. It differs from dynamic load balancing by being fixed after initial test runs [S3, unofficial]. Pitfalls include increased image compositing cost due to more ray segments, no consistent improvement in ray casting cost, and failure for zoom-in views on adaptive grids [S3, unofficial].

### Scattered Assignment
A scheme where mesh cells are assigned to processors in a scattered fashion for load balancing in the Local Preprocessing/Mesh (LPM) step [S4, unofficial]. Each processor concurrently determines the mesh-cell to processor assignment without communication [S4, unofficial]. It lacks explicit minimization of communication overhead for the Ray Segment Migration (RSM) step [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** The assignment computation is $O(N)$, where $N$ is the number of cells, as it involves a simple modulo operation per cell [S1, S4, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the assignment map and cell data [S1, unofficial].
*   **Data Transfer:** Worst-case transfer volume is $80n$ bytes per processor for $n$ cells [S1, unofficial][S2]. Example: Distributing 1 million cells across 128 processors requires an average of 640,000 bytes transferred to and stored at each processor [S1, unofficial][S2].
*   **Strengths:** Flexibility; trivial computation for any number of processors without expensive partitioning; approximates static load balance by averaging out computational requirements [S1, unofficial][S2].
*   **Limitations:** Destroys spatial relationships; increases compositing cost in some variants; does not minimize communication overhead explicitly [S2][S3, S4, unofficial].
*   **When to Use:** When load imbalance due to cell size/opacity variations is significant and spatial coherence is not critical for the rendering algorithm (e.g., cell-projection) [S1, unofficial].
*   **When Not to Use:** For zoom-in views on adaptive grids or when communication overhead for ray segment migration is a bottleneck [S3, S4, unofficial].

## Background
The method was developed for scalable parallel cell-projection volume rendering of three-dimensional unstructured data on massively parallel distributed-memory supercomputers, such as the IBM SP2 [S1, unofficial]. It was introduced to address load imbalances that occur when connected cells are grouped together, as connected cells often have similar size and opacity, leading to uneven workloads [S1, unofficial]. The approach uses a spatial partitioning tree to guide rendering, optimize compositing, and reduce memory consumption, while round-robin distribution handles the data load balancing [S1, unofficial].
