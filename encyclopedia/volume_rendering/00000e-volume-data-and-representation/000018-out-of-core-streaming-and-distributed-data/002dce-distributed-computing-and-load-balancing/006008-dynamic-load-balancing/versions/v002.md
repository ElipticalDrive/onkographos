# Dynamic Load Balancing
Also called: DLB, Re-load Balancing Scheme
## Overview
Dynamic Load Balancing (DLB) is a distributed work-stealing scheme used to handle load imbalance in volume rendering caused by initial data distribution, view-dependent scan conversion time, and the run-time dynamic behavior of Early Ray Termination (ERT) [S1, unofficial]. It differs from preprocessing-based static load balancing, which cannot handle dynamic ERT behavior, and self-scheduling schemes, which perform poorly on non-shared memory systems like PC clusters [S1, unofficial].
## How it works
### Inputs and outputs
**Inputs:**
*   A volume dataset partitioned across multiple processors [S1, unofficial].
*   A view direction [S1, unofficial].
*   An Early Ray Termination (ERT) scheme, specifically Conservative Early Ray Termination (CERT) [S1, unofficial].

**Outputs:**
*   A redistributed workload for subsequent frames or views [S2, unofficial].

### Steps
1.  **Initial Execution:** Perform initial rendering runs on the dataset [S2, unofficial].
2.  **Re-balancing:** Apply a re-load balancing scheme to redistribute work for subsequent visualizations [S2, unofficial].
3.  **Work Stealing:** Utilize a distributed work-stealing mechanism to redistribute tasks from overloaded processors to idle ones [S1, unofficial].

### Pseudocode
```python
def dynamic_load_balancing(dataset, view, processors):
    # Step 1: Initial execution
    # Sources state: "make some initial runs for the data set introduced" [S2, unofficial]
    measured_workloads = []
    for p in processors:
        work = 0
        for ray in generate_rays(dataset, view, p.partition):
            if conservative_early_ray_termination(ray, dataset):
                work += 1
        measured_workloads.append(work)

    # Step 2: Re-load balancing
    # Sources state: "doing some re-load balancing scheme for further visualizations" [S2, unofficial]
    # Redistribute partitions to balance measured_workloads across processors
    balanced_partitions = balance_partitions(processors, measured_workloads)

    # Step 3: Distributed work-stealing execution
    # Sources state: "we choose the distributed work-stealing scheme as the dynamic load balancing(DLB) scheme" [S1, unofficial]
    for p in processors:
        render_partition(p, balanced_partitions[p])
        # Work-stealing: idle processors take tasks from busy processors
        while p.is_idle():
            stolen_task = steal_from_busy_processor(processors)
            if stolen_task is not None:
                render_partition(p, stolen_task)

    # Compositing preserves relative depth order of rendered partitions [G]
    return alpha_composite_all_partitions(processors)

def conservative_early_ray_termination(ray, dataset):
    # Standard operation: check partially accumulated opacity and subscreen comparison [S1, unofficial]
    return ray.opacity > threshold

def balance_partitions(processors, workloads):
    # Not given in the sources; standard load-balancing redistribution assumed [G]
    return redistribute_evenly(workloads)

def steal_from_busy_processor(processors):
    # Not given in the sources; standard work-stealing queue selection assumed [G]
    return pick_heaviest_queue(processors)
```

### Edge cases and pitfalls
*   **Single View Limitation:** The method can only be applied if multiple runs from a single view are needed, such as in time-varying data sets [S2, unofficial].
*   **Dynamic ERT Behavior:** Standard static balancing fails to account for the run-time dynamic behavior of ERT, which varies per view and dataset density [S1, unofficial].

### Strengths and limitations
*   **Strengths:** Handles three sources of imbalance: initial distribution, view dependency, and dynamic ERT behavior [S1, unofficial]. Works on non-shared memory systems like PC clusters where self-scheduling fails [S1, unofficial].
*   **Limitations:** Requires multiple runs from a single view (e.g., time-varying data) to be effective [S2, unofficial].

### When to use it and when not
*   **Use:** When rendering time-varying data or multiple views where ERT behavior changes dynamically on a distributed cluster [S1, unofficial][S2, unofficial].
*   **Do not use:** For single-view static rendering, or when relying on self-scheduling schemes on non-shared memory systems [S1, unofficial].

## Background
### Origin
The method is described in the context of Cell-projection Parallel Volume Rendering [S1, unofficial].

### History and development
The authors selected distributed work-stealing over preprocessing-based static load balancing (which cannot handle dynamic ERT behavior) and self-scheduling dynamic load balancing (which performs poorly on non-shared memory systems like PC clusters) [S1, unofficial].

### Where it is used
Distributed volume rendering systems on PC clusters [S1, unofficial].
