# MPI Volume Rendering (1D/2D Decomposition)

Also called: Parallel Volume Rendering with MPI, MPI-based Parallel Volume Rendering with Domain Decomposition

## Overview
MPI Volume Rendering (1D/2D Decomposition) is a distributed-memory parallel volume rendering technique that partitions a 3D scalar dataset into 1D (slices) or 2D (blocks) spatial subdomains, assigning each to an MPI process for independent ray casting [S2, S3, S5, unofficial]. It solves the scalability problem of rendering large volumetric datasets that exceed the memory or compute capacity of a single node by distributing both data and computation across a cluster [S1][S4, unofficial]. Unlike its sibling [MPI Volume Rendering (3D Decomposition)](2254-mpi-volume-rendering-3d-decomposition.md), which splits the volume along all three axes, this method restricts decomposition to the X and/or Y axes, keeping the full depth (Z-axis) intact for each process to simplify ray casting and compositing [S2, S3, unofficial]. It differs from [Parallel Volume Ray Casting (PVR) Library Interface](3206-parallel-volume-ray-casting-pvr-library-interface.md) by using fixed-axis aligned subdomains rather than generic partitioning, prioritizing direct compositing performance over abstract applicability [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset (typically `float32`), opacity and color transfer functions (TFs), rendering parameters (step size, bounding box), and MPI communicator [S3, S5, unofficial].
*   **Output:** A final 2D RGBA image assembled by the root process, along with performance metrics (timing, early termination counts) [S3, unofficial].

**Data Structures:**
*   **Volume Data:** Stored as a contiguous array. In C/C++, it is a `std::vector<float>` with index calculation $I = z \cdot Y \cdot X + y \cdot X + x$ (assuming X is the fastest varying dimension) [S2, unofficial]. In Python, it is a `numpy` array of shape $(X, Y, Z)$ or $(Z, Y, X)$ depending on loading order, converted to C-contiguous memory [S3, S5, unofficial].
*   **Transfer Functions:** Precomputed dictionaries or arrays mapping scalar values to opacity and RGB color. For efficiency, these are loaded once per process into local lookup structures (e.g., sorted key-value pairs for binary search) to avoid repeated file I/O or complex interpolation during the ray loop [S3, unofficial].
*   **Local Image Buffer:** Each process maintains a local buffer for its assigned sub-image region. In C++, this is often a 3D array `eachImage[eachYlen][eachXlen][4]` storing RGBA floats [S4, unofficial]. In Python, it is a numpy array of shape $(rows, cols, 4)$ [S3, unofficial].

**Numbered Steps:**

1.  **Initialization:** Initialize MPI communicator [S5, unofficial]. Rank 0 reads command-line arguments (filename, partitioning type, step size, bounding box) and global volume dimensions [S3, S5, unofficial].
2.  **Transfer Function Loading:** All processes load opacity and color transfer functions from text files [S3, unofficial]. These are parsed into local dictionaries or arrays [S3, unofficial]. For opacity, keys are scalar values and values are opacities [S3, unofficial]. For color, keys are scalar values and values are RGB triplets [S3, unofficial].
3.  **Domain Decomposition:**
    *   **1D Decomposition:** The volume is split along the X-axis (or Y-axis) [S3, unofficial]. If $N$ processes are used, the X-dimension $X_{dim}$ is divided into chunks [S3, unofficial]. Process $p$ receives X-range $[p \cdot chunk\_size, (p+1) \cdot chunk\_size)$ [S3, unofficial]. The last process receives the remainder to cover the full width [S3, unofficial]. The Y and Z dimensions remain full [S3, S5, unofficial].
    *   **2D Decomposition:** The volume is split along X and Y axes [S3, unofficial]. The number of processes $N$ is factorized into $N_x \times N_y$ such that $N_x \ge N_y$ and $N_x \approx N_y$ (square-ish grid) [S3, S5, unofficial]. Process $(p_x, p_y)$ receives a block defined by $[p_x \cdot chunk\_x, (p_x+1) \cdot chunk\_x)$ and $[p_y \cdot chunk\_y, (p_y+1) \cdot chunk\_y)$ [S3, unofficial]. The last blocks in each dimension receive the remainder [S3, unofficial]. (Note: [S5, unofficial] distributes the remainder to the first extra processes instead).
4.  **Data Distribution:** Rank 0 distributes the relevant sub-domains to all other processes [S3, unofficial]. In C++, this involves iterating through the global data indices corresponding to the process's bounds and sending the flattened subset via `MPI_Send` [S4, unofficial]. In Python, `mpi4py` scatter or send operations are used [S3, S5, unofficial].
5.  **Ray Casting (Local Rendering):** Each process renders its assigned sub-domain independently:
    *   Iterate over each pixel $(x, y)$ in the local sub-image bounds [S3, unofficial].
    *   Initialize accumulated color $C' = (0,0,0)$ and accumulated opacity $A' = 0$ [S3, unofficial].
    *   March along the Z-axis (depth) with step size $s$ [S3, unofficial].
    *   For each sample point $z_{sample}$:
        *   Interpolate the scalar value $V$ from the local volume data using linear interpolation between adjacent slices [S3, unofficial].
        *   Interpolate opacity $A$ and color $C$ from the local transfer function dictionaries using the scalar value $V$ [S3, unofficial].
        *   Update accumulated values using front-to-back compositing:
            $$ C' = C' + (1 - A') C A $$
            $$ A' = A' + (1 - A') A $$
        *   **Early Termination:** If $A'$ exceeds a threshold (e.g., 0.97 [S2, unofficial] or 1.0 [S3, unofficial]), terminate the ray for this pixel, increment the early termination counter, and break the Z-loop.
6.  **Result Assembly:**
    *   **Global Reduction (Simple):** Each process sends its local sub-image and early termination count to Rank 0 [S3, unofficial]. Rank 0 assembles the final image by placing each sub-image in its correct spatial position based on the decomposition grid [S3, S5, unofficial].
    *   **Binary Swap (Optimized):** To avoid bottlenecking Rank 0, processes may use a binary swap reduction [S4, unofficial]. Processes exchange partial images with partners in a tree-like structure ($\log_2 N$ steps), compositing received images onto their own [S4, unofficial].
7.  **Finalization:** Rank 0 saves the assembled image to a file (e.g., PNG) and reports timing statistics [S3, unofficial].

**Pseudocode:**

```python
import numpy as np
from mpi4py import MPI
import bisect

def find_best_split(num_processes):
    best_split = (1, num_processes)
    for i in range(1, int(np.sqrt(num_processes)) + 1):
        if num_processes % i == 0:
            j = num_processes // i
            if i <= j:
                best_split = (j, i)
    return best_split

def calculate_bounds(rank, size, x_dim, y_dim, z_dim, partitioning):
    if partitioning == 1:
        chunk_size = x_dim // size
        start_x = rank * chunk_size
        end_x = x_dim if rank == size - 1 else start_x + chunk_size
        return start_x, x_dim, 0, y_dim
    else:
        num_splits_x, num_splits_y = find_best_split(size)
        chunk_x = x_dim // num_splits_x
        chunk_y = y_dim // num_splits_y
        proc_x = rank % num_splits_x
        proc_y = rank // num_splits_x
        start_x = proc_x * chunk_x
        end_x = x_dim if proc_x == num_splits_x - 1 else start_x + chunk_x
        start_y = proc_y * chunk_y
        end_y = y_dim if proc_y == num_splits_y - 1 else start_y + chunk_y
        return start_x, end_x, start_y, end_y

def interpolate_volume(data, x, y, z, z_dim):
    z_idx = int(np.floor(z))
    z_next = min(z_idx + 1, z_dim - 1)
    alpha = z - z_idx
    val1 = data[x, y, z_idx]
    val2 = data[x, y, z_next]
    return (1 - alpha) * val1 + alpha * val2

def interpolate_tf(tf_keys, tf_values, scalar_val):
    idx = bisect.bisect(tf_keys, scalar_val)
    if idx == 0: return tf_values[0]
    if idx >= len(tf_keys): idx = len(tf_keys) - 1
    k1, k2 = tf_keys[idx-1], tf_keys[idx]
    v1, v2 = tf_values[idx-1], tf_values[idx]
    if k2 == k1: return v1
    alpha = (scalar_val - k1) / (k2 - k1)
    return (1 - alpha) * v1 + alpha * v2

def render_subdomain(local_data, x_start, x_end, y_start, y_end, z_dim, step_size, 
                     color_keys, color_values, opacity_keys, opacity_values):
    h = y_end - y_start
    w = x_end - x_start
    sub_image = np.zeros((h, w, 3), dtype=np.float32)
    sub_opacity = np.zeros((h, w), dtype=np.float32)
    early_terminations = 0
    
    for i in range(h):
        for j in range(w):
            acc_r, acc_g, acc_b = 0.0, 0.0, 0.0
            acc_a = 0.0
            z = 0.0
            while z < z_dim:
                scalar_val = interpolate_volume(local_data, j, i, z, z_dim)
                
                # Interpolate Color
                c_idx = bisect.bisect(color_keys, scalar_val)
                if c_idx == len(color_keys): c_idx = len(color_keys) - 1
                if c_idx == 0: c_idx = 1
                k1_c, k2_c = color_keys[c_idx-1], color_keys[c_idx]
                v1_c, v2_c = color_values[c_idx-1], color_values[c_idx]
                if k2_c == k1_c:
                    r, g, b = v1_c
                else:
                    alpha_c = (scalar_val - k1_c) / (k2_c - k1_c)
                    r = (1 - alpha_c) * v1_c[0] + alpha_c * v2_c[0]
                    g = (1 - alpha_c) * v1_c[1] + alpha_c * v2_c[1]
                    b = (1 - alpha_c) * v1_c[2] + alpha_c * v2_c[2]
                    
                # Interpolate Opacity
                o_idx = bisect.bisect(opacity_keys, scalar_val)
                if o_idx == len(opacity_keys): o_idx = len(opacity_keys) - 1
                if o_idx == 0: o_idx = 1
                k1_o, k2_o = opacity_keys[o_idx-1], opacity_keys[o_idx]
                v1_o, v2_o = opacity_values[o_idx-1], opacity_values[o_idx]
                if k2_o == k1_o:
                    op = v1_o
                else:
                    alpha_o = (scalar_val - k1_o) / (k2_o - k1_o)
                    op = (1 - alpha_o) * v1_o + alpha_o * v2_o
                    
                # Front-to-Back Compositing
                factor = (1.0 - acc_a) * op
                acc_r += factor * r
                acc_g += factor * g
                acc_b += factor * b
                acc_a += factor
                
                if acc_a >= 0.97:
                    early_terminations += 1
                    break
                z += step_size
            
            sub_image[i, j] = [acc_r, acc_g, acc_b]
            sub_opacity[i, j] = acc_a
    return sub_image, sub_opacity, early_terminations

def main():
    comm = MPI.COMM_WORLD
    rank = comm.Get_rank()
    size = comm.Get_size()
    
    # Load transfer functions (all ranks)
    # File I/O omitted; sources [S3, S5, unofficial] describe parsing text files into sorted key arrays.
    color_keys = np.array([...])
    color_values = np.array([...])
    opacity_keys = np.array([...])
    opacity_values = np.array([...])
    
    if rank == 0:
        # Load volume data from file (omitted for brevity)
        volume_data = np.zeros((x_dim, y_dim, z_dim)) 
        bounds_list = []
        for r in range(size):
            bounds_list.append(calculate_bounds(r, size, x_dim, y_dim, z_dim, partitioning))
        
        # Scatter data and bounds
        for r in range(size):
            xb, xe, yb, ye = bounds_list[r]
            local_data = volume_data[xb:xe, yb:ye, :]
            comm.Send(local_data, dest=r, tag=0)
            comm.Send(np.array([xb, xe, yb, ye]), dest=r, tag=1)
            
        # Render own subdomain
        sub_img, sub_op, early_term = render_subdomain(volume_data, 0, x_dim, 0, y_dim, z_dim, step_size, 
                                                       color_keys, color_values, opacity_keys, opacity_values)
        all_sub_imgs = [None] * size
        all_sub_imgs[0] = sub_img
        for r in range(1, size):
            recv_buf = np.empty((ye-yb, xe-xb, 3), dtype=np.float32)
            comm.Recv(recv_buf, source=r, tag=2)
            all_sub_imgs[r] = recv_buf
        # Assemble final image
        final_image = assemble_image(all_sub_imgs, bounds_list)
        save_image(final_image)
    else:
        local_data = np.empty((1, 1, 1), dtype=np.float32)
        comm.Recv(local_data, source=0, tag=0)
        bounds = np.empty(4, dtype=int)
        comm.Recv(bounds, source=0, tag=1)
        x_start, x_end, y_start, y_end = bounds
        
        sub_img, sub_op, early_term = render_subdomain(local_data, x_start, x_end, y_start, y_end, z_dim, step_size, 
                                                       color_keys, color_values, opacity_keys, opacity_values)
        comm.Send(sub_img, dest=0, tag=2)
```

**Parameters:**
*   **Step Size:** Distance between sample points along the ray. Typical value: 0.5 [S3, S5, unofficial].
*   **Partitioning Type:** 1 for 1D (X-axis split), 2 for 2D (X and Y split) [S3, S5, unofficial].
*   **Early Termination Threshold:** Opacity value at which ray casting stops. Thresholds of 0.97 [S2, unofficial] or 1.0 [S3, unofficial] are used.
*   **Volume Dimensions:** Examples include 1000x1000x200 [S2, unofficial] or 2000x2000x400 [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Index Clamping:** When interpolating transfer functions, if the scalar value exceeds the max key, the index must be clamped to the last valid index to prevent out-of-bounds access [S3, unofficial].
*   **Non-Divisible Dimensions:** When splitting dimensions among processes, the last process in a dimension receives the remainder of the division to ensure all data is covered [S3, S5, unofficial].
*   **Load Imbalance:** If opacity reaches 1.0 quickly at isosurfaces, rays terminate early, causing uneven computation times across partitions [S1].
*   **RGB Clamping:** RGB values exceeding 1.0 should be clamped to 1.0 to prevent invalid colors [S4, unofficial].
*   **Axis-Aligned Restriction:** This method only supports rays cast along the Z-axis. General ray directions are not supported by the decomposition strategy [S3, unofficial].

## Subtopics

### [MPI Volume Rendering (3D Decomposition)](2254-mpi-volume-rendering-3d-decomposition.md)
MPI Volume Rendering (3D Decomposition) partitions the volume into a 3D grid of subdomains, assigning each to a distinct MPI process. It allows splitting along X, Y, and Z axes simultaneously to better match data aspect ratios and process grids. Unlike 1D/2D decomposition, it requires more complex communication for compositing if not axis-aligned, or handles depth slices locally. Choose this when the volume is large in all dimensions and 1D/2D splits result in overly large local datasets or poor load balance. Link: [MPI Volume Rendering (3D Decomposition)](2254-mpi-volume-rendering-3d-decomposition.md).

### [Parallel Volume Rendering with Static Load Balancing](2547-parallel-volume-rendering-with-static-load-balancing.md)
This method combines spatial partitioning with static load balancing for unstructured meshes, minimizing synchronization overhead. It uses a fully distributed, view-independent static partitioning scheme. Choose this for unstructured grids where regular decomposition is not feasible. Link: [Parallel Volume Rendering with Static Load Balancing](2547-parallel-volume-rendering-with-static-load-balancing.md).

### [MPI Master Node Parallel Rendering Workflow](2625-mpi-master-node-parallel-rendering-workflow.md)
A master-slave architecture where a master node coordinates spawning, distributes parameters, and assembles the final image from per-slice fragments. It explicitly handles domain decomposition and image concatenation within a workflow abstraction. Choose this for simpler implementation where a single node has sufficient memory to assemble the final image. Link: [MPI Master Node Parallel Rendering Workflow](2625-mpi-master-node-parallel-rendering-workflow.md).

### [Parallel Volume Ray Casting (PVR) Library Interface](3206-parallel-volume-ray-casting-pvr-library-interface.md)
A software design for distributed-memory systems enabling in-place rendering of rectilinear grid data without transferring large datasets to a host. It separates local resampling from global compositing and uses direct compositing to remain independent of partitioning schemes. Choose this for generic applicability across different data partitioning strategies. Link: [Parallel Volume Ray Casting (PVR) Library Interface](3206-parallel-volume-ray-casting-pvr-library-interface.md).

### [Parallel Distributed Axis-aligned Volume Rendering using MPI](3804-parallel-distributed-axis-aligned-volume-rendering-using-mpi.md)
Performs axis-aligned rendering by decomposing the dataset across MPI processes, casting rays along the Z-axis and compositing front-to-back. It distributes data spatially along the view axis, eliminating per-ray communication overhead. Supports 1D and 2D decomposition. This is the core method described in the main article. Link: [Parallel Distributed Axis-aligned Volume Rendering using MPI](3804-parallel-distributed-axis-aligned-volume-rendering-using-mpi.md).

### [Parallel DVR Algorithm (Object-Space Decomposition)](4258-parallel-dvr-algorithm-object-space-decomposition.md)
Also known as OS-DVR, this method decomposes the volume into clusters to minimize communication and redundant rays. It employs a view-dependent remapping phase to dynamically reassign clusters based on viewing parameters. Choose this when the view changes frequently and static decomposition leads to poor load balance. Link: [Parallel DVR Algorithm (Object-Space Decomposition)](4258-parallel-dvr-algorithm-object-space-decomposition.md).

### Distributed INR Volume Rendering
A deep learning-based method that trains one independent Implicit Neural Representation (INR) per MPI rank on its local data partition. It uses ghost cells and half-Gaussian sampling for continuity without inter-process communication. Validated at HPC scale (up to 512 ranks) with near-ideal weak scaling. Choose this for massive datasets where traditional voxel-based rendering is too memory-intensive or slow, and neural representations are acceptable. Link: [Distributed INR Volume Rendering](2250-distributed-inr-volume-rendering.md).

## Operating characteristics
*   **Time Complexity:** $O(N \cdot R \cdot S)$, where $N$ is the number of pixels in the sub-image, $R$ is the number of rays per pixel (usually 1), and $S$ is the number of samples per ray. With early termination, $S$ is effectively reduced.
*   **Memory Complexity:** $O(V_{local})$, where $V_{local}$ is the size of the sub-domain assigned to each process. This allows rendering volumes much larger than the memory of a single node.
*   **Measured Performance:** On a 512-node cluster, render times for a 128x128x128 head dataset were 0.0593s (render) and 0.3782s (composite) [S1]. For a 256x256x128 vessel dataset, 0.0453s (render) and 0.2167s (composite) [S1].
*   **Scaling:** Near-linear speedup is observed for datasets with uniform opacity distribution (e.g., vorticity dataset) [S1]. Load imbalance occurs for datasets with sharp isosurfaces (e.g., head dataset) where early termination varies significantly across partitions [S1].
*   **Strengths:** Early termination optimization reduces execution time by 15% on tested systems [S2, unofficial].
*   **Limitations:** Load imbalance due to non-uniform data density, communication bottleneck if using global reduction (mitigated by binary swap) [S4, unofficial].
*   **When to Use:** Large volumetric datasets that fit in distributed memory, static viewing angles, uniform or predictable opacity distribution.
*   **When Not to Use:** Highly dynamic views requiring frequent remapping (use OS-DVR), unstructured meshes (use Static Load Balancing), or when inter-process communication overhead dominates (use 3D decomposition if depth is large).

## Background
*   **Origin:** The method is based on distributed memory parallel volume rendering techniques using MPI [S1][S2, S3, unofficial]. Early implementations used PVM on CM-5 and IBM RS/6000 workstations [S1].
*   **History:** Developed to address the scalability limits of single-node volume rendering as dataset sizes increased [S1][S4, unofficial].
*   **Usage:** Used in scientific visualization projects for large datasets (e.g., 2000x2000x400 float32) on MPI clusters [S3, unofficial]. Also validated at HPC scale with INR variants [S6, unofficial].
