# Parallel Distributed Axis-aligned Volume Rendering using MPI

Also called: Distributed Front-to-Back Volume Rendering, Distributed Ray Casting, MPI Ray Casting Volume Rendering, MPI Volume Rendering, MPI-based Ray Casting with Data Decomposition, Parallel Front-to-Back Volume Rendering, Parallel Volume Rendering via MPI, Slice-based Compositing

## Overview
This method performs axis-aligned volume rendering by decomposing a 3D scalar dataset across multiple MPI processes, where each process renders a spatial subdomain by casting rays along the Z-axis and compositing front-to-back [S1, S3, unofficial]. It differs from global ray casting by distributing data spatially along the view axis rather than distributing rays, which eliminates per-ray communication overhead and enables independent compositing per process [S2, unofficial]. The method supports 1D (x-axis) and 2D (x and y axes) data decomposition to balance load and memory usage [S3, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A 3D scalar volume dataset (e.g., `.raw` or `.vti`), color and opacity transfer function definitions, decomposition parameters ($p_x, p_y$ or $p_z$), and rendering parameters (step size, view axis) [S1, S3, unofficial].
- **Output:** A final 2D RGB image assembled from partial images generated by each MPI rank [S1, S3, unofficial].

**Data Structures:**
- **Volume Data:** Stored as a NumPy array. For `.raw` files, dimensions are extracted from the filename pattern `_NxNxM.raw`, reshaped to $(z, x, y)$, and axes $x, y$ are reversed [S3, unofficial]. For `.vti` files, data is loaded via VTK and transposed to align the view axis with the last dimension (e.g., `transpose(data, (2, 1, 0))` for Z-view) [S2, unofficial].
- **Transfer Functions:**
    - **Color TF:** Parsed from text files into triplets $(scalar, r, g, b)$ [S3, unofficial] or VTK `vtkColorTransferFunction` objects [S2, unofficial].
    - **Opacity TF:** Parsed into pairs $(scalar, opacity)$ [S3, unofficial] or VTK `vtkPiecewiseFunction` objects [S3, unofficial].
- **Local Image Buffers:**
    - `sub_image`: 2D array of shape $(rows, cols, 3)$ with dtype `float32`, storing accumulated RGB color [S1, unofficial].
    - `sub_opacity`: 2D array of shape $(rows, cols)$ with dtype `float32`, storing accumulated opacity [S1, unofficial].

**Numbered Steps:**

1.  **Data Decomposition:**
    The volume grid is decomposed into chunks based on the partition type [S1, S3, unofficial].
    - **1D Decomposition (X-axis):** Calculate chunk size $x_{chunk} = \lceil x_{size} / p_x \rceil$. Rank $i$ receives data slice `data[:, x_start:x_end, :]` where $x_{start} = i \cdot x_{chunk}$ and $x_{end} = \min((i+1) \cdot x_{chunk}, x_{size})$ [S3, unofficial].
    - **2D Decomposition (X-Y Plane):** Determine grid dimensions $x_{num}$ and $y_{num}$ such that $x_{num} \cdot y_{num} = p_x$ and $y_{num}$ is the largest factor of $p_x$ less than or equal to $\sqrt{p_x}$ [S3, unofficial]. Calculate $x_{chunk} = \lceil x_{size} / x_{num} \rceil$ and $y_{chunk} = \lceil y_{size} / y_{num} \rceil$. Rank $(i, j)$ receives `data[:, x_start:x_end, y_start:y_end]` [S3, unofficial].
    - **3D Decomposition (Alternative):** Compute chunk indices: $proc_z = rank // (p_x p_y)$, $proc_y = (rank \% (p_x p_y)) // p_x$, $proc_x = rank \% p_x$. Calculate chunk dimensions as $x_{dim}//p_x$, etc. Determine start/end indices for each axis [S1, unofficial].

2.  **Data Distribution:**
    Root rank (0) prepares the data chunks. Global parameters (step size, chunk shapes, counts, displacements) are broadcast to all ranks using `comm.bcast` [S3, unofficial]. The flattened volume data is scattered to each rank using `comm.Scatterv` with calculated counts and displacements, then reshaped into `sub_data_chunk` [S3, unofficial].

3.  **Ray Casting and Compositing:**
    For each pixel $(i, j)$ in the local chunk's spatial dimensions:
    - Initialize `color_accum = [0, 0, 0]` and `opacity_accum = 0` [S3, unofficial].
    - Iterate along the projection axis (Z) with step size $s$ [S1, S3, unofficial]. Samples are generated at $z = 0, s, 2s, \dots$ up to depth [S1, unofficial].
    - **Interpolation:** If $s=1$, sample $V = data[z, i, j]$. If $s>1$, perform linear interpolation between grid points $z_1 = \lfloor z \rfloor$ and $z_2 = \min(z_1+1, z_{size}-1)$ [S3, unofficial].
      $$V_p = (1 - \alpha) V_1 + \alpha V_2$$
      where $\alpha = z - z_1$, $V_1$ is the value at $z_1$, and $V_2$ is the value at $z_2$ [S1, S3, unofficial].
    - **Transfer Function Lookup:** Map $V_p$ to color $C$ and opacity $A$ using the transfer functions.
        - **Linear Interpolation (Text-based TFs):** Find bracketing index $k$ via `searchsorted`. Clamp to $len(keys)-2$. Compute interpolation factor $\alpha_{tf} = (V_p - keys[k]) / (keys[k+1] - keys[k])$. Interpolate values [S1, S3, unofficial].
        - **VTK TFs:** Use `vtkPiecewiseFunction` or `vtkColorTransferFunction` to evaluate $C$ and $A$ [S2, S3, unofficial].
        - **Gaussian TFs (Alternative):** Model color as $C(x) = \sum w_i \exp\left(-\frac{(x - \mu_i)^2}{\sigma_i^2}\right)$ applied to log-transformed values [S2, unofficial].
    - **Front-to-Back Compositing:** Update accumulated color and opacity [S1, S3, unofficial]:
      $$C_{out} = C_{in} + (1 - A_{in}) C_{sample} A_{sample}$$
      $$A_{out} = A_{in} + (1 - A_{in}) A_{sample}$$
      where $C_{in}, A_{in}$ are previous accumulations, and $C_{sample}, A_{sample}$ are the current sample's color and opacity [S1, S3, unofficial].
    - **Early Ray Termination:** If $A_{out} \ge 1.0$, increment termination counter and break the ray loop [S1, S3, unofficial].

4.  **Image Assembly:**
    Each rank sends its `sub_image` and `sub_opacity` (combined into RGBA) to rank 0 [S1, unofficial]. Rank 0 gathers these images using `comm.gather` [S3, unofficial].
    - **Stitching:** For 1D decomposition, concatenate images along the x-axis. For 2D decomposition, reconstruct the grid using $x_{num}$ and $y_{num}$, placing each sub-image at its corresponding spatial location [S3, unofficial].
    - **Normalization:** Convert final float32 image to uint8 by normalizing by `max()` and multiplying by 255 [S3, unofficial].

```python
import numpy as np
from mpi4py import MPI

def parse_tf_file(filename, is_color=False):
    """Parse TF file into keys and values arrays."""
    with open(filename, 'r') as f:
        content = f.read().replace(',', '').split()
    keys = []
    values = []
    if is_color:
        for i in range(0, len(content), 4):
            keys.append(float(content[i]))
            values.append([float(content[i+1]), float(content[i+2]), float(content[i+3])])
    else:
        for i in range(0, len(content), 2):
            keys.append(float(content[i]))
            values.append(float(content[i+1]))
    return np.array(keys), np.array(values)

def evaluate_tf(keys, values, x):
    """Linearly interpolate value from sorted keys/values array."""
    idx = np.searchsorted(keys, x) - 1
    if idx >= len(keys) - 2:
        idx = len(keys) - 2
    if idx < 0:
        idx = 0
    alpha = (x - keys[idx]) / (keys[idx + 1] - keys[idx])
    return (1 - alpha) * values[idx] + alpha * values[idx + 1]

def ray_cast_chunk(sub_data, step_size, color_keys, colors, opacity_keys, opacities):
    """
    Perform front-to-back ray casting on a local volume chunk.
    sub_data: numpy array of shape (depth, height, width).
    """
    depth, height, width = sub_data.shape
    sub_image = np.zeros((height, width, 3), dtype=np.float32)
    sub_opacity = np.zeros((height, width), dtype=np.float32)
    early_terminations = 0

    samples = np.arange(0.0, depth - 1, step_size)
    int_samples = np.floor(samples).astype(int)
    alphas = samples - int_samples

    for i in range(height):
        for j in range(width):
            c_acc = np.zeros(3, dtype=np.float32)
            a_acc = 0.0
            
            for k in range(len(samples)):
                z_idx = int_samples[k]
                frac = alphas[k]
                z_next = min(z_idx + 1, depth - 1)
                
                v1 = sub_data[z_idx, i, j]
                v2 = sub_data[z_next, i, j]
                v_p = (1 - frac) * v1 + frac * v2
                
                color = np.array([
                    evaluate_tf(color_keys, colors[:, 0], v_p),
                    evaluate_tf(color_keys, colors[:, 1], v_p),
                    evaluate_tf(color_keys, colors[:, 2], v_p)
                ])
                opacity = evaluate_tf(opacity_keys, opacities, v_p)
                
                c_acc += (1 - a_acc) * color * opacity
                a_acc += (1 - a_acc) * opacity
                
                if a_acc >= 1.0:
                    early_terminations += 1
                    break
            
            sub_image[i, j] = c_acc
            sub_opacity[i, j] = a_acc

    return sub_image, sub_opacity, early_terminations

    rank = comm.Get_rank()
    size = comm.Get_size()

    counts = []
    displacements = []
    step_size = comm.bcast(step_size, root=0)
    chunk_shapes = comm.bcast(chunk_shapes, root=0)
    counts = comm.bcast(counts, root=0)
    displacements = comm.bcast(displacements, root=0)
    
    recv_count = counts[rank]
    recv_buffer = np.empty(recv_count, dtype=np.float32)
    comm.Scatterv([recv_buffer, counts, displacements, MPI.FLOAT], root=0)
    sub_data_chunk = recv_buffer.reshape(chunk_shapes[rank])
```

## Operating characteristics
- **Time Complexity:** $O(N_{pixels} \cdot N_{samples})$ per process, where $N_{samples} = depth / step\_size$. Early ray termination reduces the average sample count [S1, unofficial].
- **Communication Overhead:** $O(N_{processes})$ for gathering sub-images and timing data to the root rank [S1, unofficial].
- **Memory:** Each process stores only its assigned volume chunk and local image buffer, scaling linearly with $1/N_{processes}$ for volume data [S1, S3, unofficial].
- **Strengths:** Eliminates per-ray communication overhead by distributing data; supports load balancing via 1D/2D decomposition; early ray termination optimizes performance for opaque regions [S1, S2, S3, unofficial].
- **Limitations:** Uneven data division if dimensions are not divisible by process count; requires root rank to assemble final image, which can be a bottleneck for very large images [S2, S3, unofficial].
- **When to Use:** Large 3D scalar datasets that fit in aggregate memory but not in a single node's memory; axis-aligned views along the Z-axis [S1, S3, unofficial].
- **When Not to Use:** Arbitrary view directions (requires more complex decomposition or ray distribution); interactive rendering with frequent view changes (decomposition overhead) [S2, unofficial].

## Background
This method is implemented in academic research projects using Python, `mpi4py`, and VTK [S1, S2, S3, unofficial]. It is designed for parallel volume rendering workflows on HPC clusters, leveraging MPI for distributed memory communication [S1, S2, unofficial]. The approach builds on the principles of distributed computing and load balancing in volume rendering, specifically focusing on spatial decomposition [Parent].
