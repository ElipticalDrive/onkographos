# MPI Master Node Parallel Rendering Workflow

Also called: MPI Image Assembly, Master-Slave Volume Rendering

## Overview
This method implements a master-slave parallel volume rendering workflow where a single master process coordinates multiple slave processes to render a 3D volume dataset [S1, unofficial]. The master distributes volume metadata and transfer functions, while slaves perform independent ray casting or slice-based compositing on assigned spatial regions [S1, unofficial]. The master assembles the resulting partial image buffers into a final image, encoding it to JPEG for transmission over TCP or storage to disk [S1, unofficial]. It differs from pure MPI-only approaches by introducing a TCP-based communication layer for image data transfer, allowing slaves to operate as independent server processes [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Command-line arguments specifying image dimensions (`width`, `height`), number of slave processes (`slave_size`), thread counts, volume file path, and rendering parameters [S1, unofficial].
- **Outputs:** A final assembled image file (e.g., JPEG) and timing statistics [S1, unofficial].

**Data Structures:**
- `vifo`: A structure containing volume metadata:
  - `dims` (Vector3i): Volume dimensions [S1, unofficial].
  - `blk_size` (Vector3i): Brick/block sizes [S1, unofficial].
  - `bmin`, `bmax` (Vector3f): Bounding box coordinates [S1, unofficial].
  - `mmu_ratio` (float): Memory management unit ratio or scaling factor [S1, unofficial].
  - `volume_file` (string): Path to the volume data file [S1, unofficial].
- `tf1d_buf`: A buffer of size `TF1D_BUF_SIZE` (10240 bytes) storing the 1D transfer function data [S1, unofficial].
- `ibuf`: A 2D array `char ibuf[slave_size][ibuf_size]` storing partial image buffers from each slave [S1, unofficial].
  - `ibuf_size` is calculated as $\lceil \text{height} / \text{slave\_size} \rceil \times \text{width} \times 3$ bytes [S1, unofficial].
- `slave_request` and `slave_status`: Arrays of size `slave_size` for MPI asynchronous receive requests and status [S1, unofficial].
- `msg_buf`: A buffer of size `MSG_BUF_SIZE` (1024 bytes) for broadcasting control messages [S1, unofficial].

**Steps:**
1. **Initialization:**
   - Parse command-line arguments to extract `width`, `height`, `slave_size`, `thread_nums`, and `vifo_path` [S1, unofficial].
   - Load volume metadata into a `vifo` structure [S1, unofficial].
   - Construct a message string containing dimensions, brick sizes, bounding box, `mmu_ratio`, and file path [S1, unofficial].
   - Spawn `slave_size` slave processes using `MPI_Comm_spawn` with the constructed message as arguments [S1, unofficial].
   - Send the transfer function data to all slaves using `send_tf1d` (broadcasting `tf1d_buf` over `slave_comm`) [S1, unofficial].

2. **Communication Setup:**
   - Set up a TCP acceptor on `PORT` (9523) for receiving the final assembled image if required by the specific implementation variant, though the primary assembly happens in memory before disk write [S1, unofficial].
   - Calculate `lines_per_slave` as $\lceil \text{height} / \text{slave\_size} \rceil$ [S1, unofficial].
   - Allocate `ibuf` and request/status arrays [S1, unofficial].

3. **Rendering Loop (for `image_nums` iterations):**
   - Accept TCP connections from slaves (if using TCP for image transfer) or rely on MPI for image data [S1, unofficial].
   - Broadcast a control message (`msg_buf`) to all slaves via `MPI_Send` (or `MPI_Bcast` if implemented as such) [S1, unofficial].
   - Record start time `t1` [S1, unofficial].
   - Issue non-blocking receives for each slave: `MPI_Irecv` into `ibuf[slave_id]` for `ibuf_size` bytes, tag `slave_id`, from rank `slave_id` on `slave_comm` [S1, unofficial].
   - Wait for all receives to complete using `MPI_Waitall` [S1, unofficial].
   - Record end time `t2` [S1, unofficial].
   - Calculate and print rendering time [S1, unofficial].

4. **Image Assembly:**
   - Iterate through each row `r` from 0 to `height - 1` [S1, unofficial].
   - Determine the slave responsible for this row: `slave_no = r % slave_size` [S1, unofficial].
   - Determine the row index within that slave's buffer: `slave_row = r / slave_size` [S1, unofficial].
   - Copy `width * 3` bytes from `ibuf[slave_no] + slave_row * width * 3` to the destination buffer `dst_base` [S1, unofficial].
   - Advance `dst_base` by `width * 3` [S1, unofficial].
   - *Pitfall:* This round-robin distribution assumes `height` is divisible by `slave_size` for perfect uniformity, but the integer division handles uneven distribution by assigning extra rows to earlier slaves [S1, unofficial].

5. **Output:**
   - Encode the assembled image buffer (`ibuf_dst`) to JPEG format [S1, unofficial].
   - Write the JPEG size and buffer to a socket (if TCP transmission is used) or save to disk [S1, unofficial].
   - Close connections and finalize MPI [S1, unofficial].

**Pseudocode:**

```python
import math
import time
import mpi4py.MPI as MPI

# Constants from source
TF1D_BUF_SIZE = 10240
MSG_BUF_SIZE = 1024
PORT = 9523

def send_tf1d(tf1d_buf, comm):
    """Broadcast transfer function data to all slaves."""
    comm.Bcast(tf1d_buf, root=0)

def main():
    comm = MPI.COMM_WORLD
    rank = comm.Get_rank()
    
    if rank == 0:
        # 1. Initialization
        width = 512
        height = 512
        slave_size = 4
        vifo_path = "volume.vifo"
        image_nums = 5
        
        # Load volume metadata into vifo structure
        vifo = {
            'dims': (512, 512, 512),
            'blk_size': (64, 64, 64),
            'bmin': (0.0, 0.0, 0.0),
            'bmax': (1.0, 1.0, 1.0),
            'mmu_ratio': 1.0,
            'volume_file': vifo_path
        }
        
        # Construct message string with dimensions, brick sizes, bounding box, mmu_ratio, and file path
        msg = f"{vifo['dims']} {vifo['blk_size']} {vifo['bmin']} {vifo['bmax']} {vifo['mmu_ratio']} {vifo['volume_file']}"
        
        # Spawn slave_size processes with this message
        slave_comm = comm.Spawn("./VolumeRendererServer_slave", args=[msg], count=slave_size)
        
        # Send transfer function data to slaves
        tf1d_buf = bytearray(TF1D_BUF_SIZE)
        send_tf1d(tf1d_buf, slave_comm)
        
        # Calculate lines per slave and allocate buffers
        ibuf_size = math.ceil(height / slave_size) * width * 3
        ibuf = [bytearray(ibuf_size) for _ in range(slave_size)]
        slave_request = [slave_comm.Irecv(ibuf[i], source=i, tag=i) for i in range(slave_size)]
        slave_status = [slave_comm.Status() for _ in range(slave_size)]
        
        t_sum = 0.0
        
        # 3. Rendering Loop
        for j in range(image_nums):
            # Broadcast control message to all slaves
            msg_buf = bytearray(MSG_BUF_SIZE)
            msg_buf[:len(msg)] = msg.encode('ascii')
            slave_comm.Bcast(msg_buf, root=0)
            
            t1 = MPI.Wtime()
            
            # Issue non-blocking receives for each slave
            for i in range(slave_size):
                slave_request[i] = slave_comm.Irecv(ibuf[i], source=i, tag=i)
            
            # Wait for all receives to complete
            MPI.Waitall(slave_request, slave_status)
            
            t2 = MPI.Wtime()
            if j >= 2:
                render_time = t2 - t1
                t_sum += render_time
                print(f"Render time for image {j}: {render_time}")
        
        print(f"Average Rendering time cost: {t_sum / (image_nums - 2)}")
        
        # 4. Image Assembly
        dst_base = bytearray(height * width * 3)
        for r in range(height):
            slave_no = r % slave_size
            slave_row = r // slave_size
            src_offset = slave_row * width * 3
            dst_offset = r * width * 3
            dst_base[dst_offset:dst_offset + width * 3] = ibuf[slave_no][src_offset:src_offset + width * 3]
            
        # 5. Output
        # Encode ibuf_dst to JPEG, write size and buffer to socket, close connections
        # write_image_disk(dst_base, width, height, "test.jpg")
        
        slave_comm.Free()
        MPI.Finalize()

if __name__ == "__main__":
    main()
```

**Parameters:**
- `slave_size`: Number of slave processes [S1, unofficial].
- `width`, `height`: Image resolution [S1, unofficial].
- `image_nums`: Number of frames to render for timing averaging [S1, unofficial].
- `PORT`: TCP port (9523) for potential image transmission [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Uneven Height Distribution:** If `height` is not divisible by `slave_size`, the last rows are distributed unevenly [S1, unofficial]. The formula `slave_row = r // slave_size` correctly maps rows to slave buffers, but the buffer size `ibuf_size` must be large enough to hold the maximum number of rows any single slave might contribute, which is $\lceil \text{height} / \text{slave\_size} \rceil$ [S1, unofficial].
- **MPI Spawn:** `MPI_Comm_spawn` requires the slave executable to be in the PATH or specified with a full path [S1, unofficial].

## Subtopics

### MPI Master-Slave Octree Volume Rendering
A variant where slaves traverse an Octree (OTree) structure to find empty/non-empty blocks, computing ray segments only for non-empty blocks to optimize rendering [S1, unofficial]. The master sends volume metadata (bmin, bmax, mmu_ratio, file path) and transfer function data [S1, unofficial]. Slaves perform ray casting on these optimized segments [S1, unofficial]. This differs from standard voxel-based ray casting by leveraging hierarchical data structures for early ray termination and empty space skipping [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Dominated by ray casting on slaves and MPI communication [S1, unofficial]. Image assembly is $O(\text{height} \times \text{width})$ [S1, unofficial].
- **Memory Complexity:** $O(\text{slave\_size} \times \text{height} \times \text{width} \times 3)$ for image buffers on the master [S1, unofficial]. Slaves store volume data and transfer functions [S1, unofficial].
- **Performance:** Timing is measured over multiple frames, averaging out startup costs [S1, unofficial]. The use of non-blocking MPI receives allows for potential overlap, though the example waits for all before assembly [S1, unofficial].
- **Strengths:** Simple master-slave model, leverages MPI for process management, TCP for flexible image transfer [S1, unofficial].
- **Limitations:** Master becomes a bottleneck for image assembly and control [S1, unofficial]. Round-robin row distribution may lead to load imbalance if ray casting cost varies significantly per row (e.g., due to opacity variations) [S1, unofficial]. Fixed buffer sizes for TF and messages limit flexibility [S1, unofficial].
- **When to Use:** Suitable for static volumes where load balancing is not critical or where the volume is uniform [S1, unofficial]. Not ideal for highly heterogeneous volumes without additional load balancing strategies [S1, unofficial].
