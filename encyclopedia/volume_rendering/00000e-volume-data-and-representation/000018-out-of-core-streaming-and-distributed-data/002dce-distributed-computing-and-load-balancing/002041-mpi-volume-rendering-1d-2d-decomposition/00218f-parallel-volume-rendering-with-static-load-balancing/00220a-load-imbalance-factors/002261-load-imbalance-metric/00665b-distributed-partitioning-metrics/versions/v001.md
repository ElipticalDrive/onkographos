# Distributed Partitioning Metrics

Also called: Communication and Load Metrics for Distributed Volume Rendering

## Overview
Distributed Partitioning Metrics quantify the efficiency of a spatial decomposition in parallel volume rendering by evaluating communication overhead and workload balance. Unlike [Load Imbalance Metric](2763-load-imbalance-metric.md), which focuses solely on computational weight distribution, this method aggregates communication volume, message count, and boundary regularity to provide a holistic view of distributed rendering performance.

## How it works
The method evaluates a partitioning scheme defined over $p$ processors. It requires the set of rays cast for the volume, the voxel data structure, and the partition assignment for each voxel.

**Inputs:**
- $R$: Set of rays.
- $V$: Volume grid with dimensions $X \times Y \times Z$.
- $P$: Set of $p$ partitions (processors).
- $\text{owner}(v)$: Function returning the partition ID owning voxel $v$.
- $\text{weight}(v)$: Scalar weight of voxel $v$ (e.g., opacity or density).

**Outputs:**
- Communication Volume ($C_{vol}$)
- Message Count ($C_{msg}$)
- Load Imbalance ($L_{imb}$)
- Boundary Regularizer ($B_{reg}$)

**Steps:**

1.  **Communication Volume**:
    For each ray $r \in R$:
    - Identify the set of unique partition owners for all voxels sampled by $r$: $O_r = \{ \text{owner}(v) \mid v \in \text{sampled}(r) \}$.
    - Calculate the communication cost for this ray: $c_r = \max(0, |O_r| - 1)$.
    - Sum across all rays: $C_{vol} = \sum_{r \in R} c_r$.

2.  **Message Count**:
    For each ray $r \in R$:
    - Construct a complete graph where nodes are the unique owners $O_r$.
    - For each owner $o \in O_r$, determine its partner set $P_o$ (other owners in $O_r$).
    - Sum the size of each owner's partner set: $m_r = \sum_{o \in O_r} |P_o|$.
    - Subtract the number of partitions involved to avoid double-counting or self-loops depending on graph definition.     - $S_{partners} = \sum_{r \in R} \sum_{o \in O_r} |O_r \setminus \{o\}|$.
    - $C_{msg} = S_{partners} - p$. [G: This subtraction of global $p$ from a ray-summed value is unusual; it may imply a global graph or a specific normalization factor not fully detailed. Implemented as stated.]

3.  **Load Imbalance**:
    - Compute total weight $W_{total} = \sum_{v \in V} \text{weight}(v)$.
    - Compute average weight per partition: $W_{avg} = W_{total} / p$.
    - For each partition $i \in \{0, \dots, p-1\}$, compute its weight sum $W_i = \sum_{v \in \text{partition } i} \text{weight}(v)$.
    - $L_{imb} = \max_{i} \left( \frac{W_i}{W_{avg}} - 1 \right)$.

4.  **Boundary Regularizer**:
    - For each partition $i$, determine its bounding box dimensions $x_s^{(i)} = [xs_0, xs_1, xs_2]$.
    - Calculate the surface area of the bounding box: $A_i = 2 \cdot (xs_0 \cdot xs_1 + xs_0 \cdot xs_2 + xs_1 \cdot xs_2)$. *Note*: The source formula is $2 \cdot (xs[0]*xs[1] + (xs[0]-1)*xs[2] + (xs[1]-1)*(xs[2]-1))$. This looks like a specific voxel-boundary count. We use the source formula exactly.
    - $B_i = 2 \cdot (xs_0 \cdot xs_1 + (xs_0 - 1) \cdot xs_2 + (xs_1 - 1) \cdot (xs_2 - 1))$.
    - Sum boundary voxels: $B_{total} = \sum_{i} B_i$.
    - Subtract global boundary voxels $B_{global}$ (calculated similarly for the entire volume $X \times Y \times Z$).
    - $B_{reg} = B_{total} - B_{global}$.

**Pseudocode:**

```python
def compute_distributed_partitioning_metrics(rays, volume, partitions, p):
    """
    rays: list of ray objects, each having a method get_sampled_voxels()
    volume: object with dimensions (X, Y, Z) and method get_weight(v)
    partitions: list of partition objects, each having a method get_voxels()
    p: int, number of partitions
    """
    
    # Precompute voxel to partition mapping for speed
    voxel_to_partition = {}
    for pid, part in enumerate(partitions):
        for v in part.get_voxels():
            voxel_to_partition[v] = pid
            
    # 1. Communication Volume
    comm_vol = 0
    for ray in rays:
        owners = set()
        for v in ray.get_sampled_voxels():
            owners.add(voxel_to_partition[v])
        comm_vol += max(0, len(owners) - 1)
        
    # 2. Message Count
    # Sum of partner set sizes across all rays
    partner_sum = 0
    for ray in rays:
        owners = set()
        for v in ray.get_sampled_voxels():
            owners.add(voxel_to_partition[v])
        # Complete graph edges: for each owner, partners are other owners
        for o in owners:
            partner_sum += (len(owners) - 1)
            
    msg_count = partner_sum - p
    
    # 3. Load Imbalance
    total_weight = 0
    for v in volume.get_all_voxels():
        total_weight += volume.get_weight(v)
        
    avg_weight = total_weight / p
    
    max_imbalance = 0
    for part in partitions:
        part_weight = 0
        for v in part.get_voxels():
            part_weight += volume.get_weight(v)
        imbalance = (part_weight / avg_weight) - 1
        if imbalance > max_imbalance:
            max_imbalance = imbalance
            
    load_imbalance = max_imbalance
    
    # 4. Boundary Regularizer
    def calc_boundary_metric(dim_x, dim_y, dim_z):
        # Formula from source: 2 * (xs[0]*xs[1] + (xs[0]-1)*xs[2] + (xs[1]-1)*(xs[2]-1))
        # Assuming xs[0]=x, xs[1]=y, xs[2]=z
        return 2 * (dim_x * dim_y + (dim_x - 1) * dim_z + (dim_y - 1) * (dim_z - 1))
        
    global_boundary = calc_boundary_metric(volume.X, volume.Y, volume.Z)
    
    total_partition_boundary = 0
    for part in partitions:
        bbox = part.get_bounding_box() # Returns (xs, ys, zs)
        total_partition_boundary += calc_boundary_metric(bbox.x, bbox.y, bbox.z)
        
    boundary_reg = total_partition_boundary - global_boundary
    
    return {
        "communication_volume": comm_vol,
        "message_count": msg_count,
        "load_imbalance": load_imbalance,
        "boundary_regularizer": boundary_reg
    }
```

## Subtopics

## Operating characteristics
- **Time Complexity**: $O(R \cdot V_{avg} + V)$, where $R$ is the number of rays, $V_{avg}$ is the average number of voxels per ray, and $V$ is the total number of voxels. The dominant cost is iterating over rays and voxels to build owner sets and weight sums.
- **Memory Complexity**: $O(V + R \cdot p)$ in the worst case for storing owner sets if not optimized, but typically $O(V)$ for voxel-partition mapping and $O(R)$ for ray processing buffers.
- **Strengths**: Provides a multi-dimensional view of partition quality, combining communication, load, and geometric regularity.
- **Limitations**: The message count formula's subtraction of global $p$ is non-standard and may require verification against specific implementation details. The boundary regularizer formula is heuristic and may not correlate linearly with actual communication latency.

## Background
The metrics are derived from the TPT (Tree-based Parallel Volume Rendering) library implementation, specifically focusing on MPI-based distributed rendering load balancing. The approach is used to evaluate and optimize spatial decompositions for large-scale volume rendering tasks.
