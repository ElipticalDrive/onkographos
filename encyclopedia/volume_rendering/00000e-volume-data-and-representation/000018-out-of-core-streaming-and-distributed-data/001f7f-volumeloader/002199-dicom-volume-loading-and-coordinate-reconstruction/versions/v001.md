# DICOM Volume Loading and Coordinate Reconstruction

Also called: DICOM File Loading and Stacking, DICOM Loader, DICOM Volume Reconstruction Loading & Density Conversion, DICOM to Density Conversion, Volume DICOM Loading and Rescaling

## Overview
This method loads a 3D volumetric dataset from a series of DICOM image files, reconstructs the physical voxel grid by resolving coordinate system conventions, and converts raw pixel values into physical density. It specifically addresses the discrepancy between DICOM's pixel-center coordinate convention and the corner-point convention required by downstream volume rendering engines, while handling the non-cubic nature of medical voxels [S1, S2, S3, unofficial]. It differs from generic volume loaders by explicitly managing DICOM-specific metadata (Rescale Slope/Intercept, Pixel Spacing, Slice Thickness) and orientation flips (rot90) necessary for correct anatomical alignment [S2, S3, unofficial].

## How it works
**Inputs:** A directory of DICOM files (typically `.dcm` or `.IMA`), sorted by filename.
**Outputs:** A 3D density array (float), a physical bounding box (min/max points), and voxel dimensions (scale).

### Data Structures
1.  **DICOM Metadata Object:** Extracted per file.
    *   `rows`: Integer (image height in pixels).
    *   `cols`: Integer (image width in pixels).
    *   `pixelSpacing`: Array of 2 floats `[spacing_y, spacing_x]` in mm.
    *   `sliceThickness`: Float in mm.
    *   `bitsAllocated`: Integer (usually 16).
    *   `pixelRepresentation`: Integer (0 for unsigned, 1 for signed).
    *   `rescaleSlope`: Float (default 1.0).
    *   `rescaleIntercept`: Float (default -1000.0).
    *   `dataCollectionCenterPatient`: Array of 3 floats `[x, y, z]` in mm.
    *   `reconstructionTargetCenterPatient`: Array of 3 floats `[x, y, z]` in mm.
2.  **Volume Data Buffer:**
    *   Type: `Uint16Array` or `Float32Array` depending on intermediate processing.
    *   Size: `rows * cols * num_slices`.
3.  **Physical Bounds:**
    *   `min_pt`: Array of 3 floats `[x, y, z]`.
    *   `max_pt`: Array of 3 floats `[x, y, z]`.

### Steps

1.  **File Selection and Sorting:**
    *   Scan the input directory for DICOM files.
    *   Filter by suffix (e.g., `.IMA` or `.dcm`) [S2, unofficial].
    *   Sort files alphabetically by filename to ensure correct slice ordering [S2, unofficial].

2.  **Metadata Extraction and Validation:**
    *   For each file, decode the DICOM header.
    *   Extract `rows`, `cols`, `pixelSpacing`, `sliceThickness`, `bitsAllocated`, `pixelRepresentation`, `rescaleSlope`, `rescaleIntercept`, `dataCollectionCenterPatient`, and `reconstructionTargetCenterPatient` [S2, S3, unofficial].
    *   Calculate `bytesPerVoxel = bitsAllocated / 8` [S3, unofficial].
    *   **Pitfall:** If `bytesPerVoxel != 2`, throw an error. Unsupported byte depths are not handled [S3, unofficial].

3.  **Pixel Data Loading and Orientation Correction:**
    *   Read raw pixel data as unsigned short (`'H'`) [S2, unofficial].
    *   Reshape raw data to `[cols, rows]` in C-order [S2, unofficial].
    *   Apply rotation to correct DICOM orientation: `data_array = np.rot90(data_array, k=-1)` (equivalent to 270-degree counter-clockwise or -90-degree rotation) [S2, unofficial].
    *   *Note:* This rotation accounts for the standard DICOM display convention where the image is flipped horizontally relative to the patient's left-right axis [S2, unofficial].

4.  **Hounsfield Unit (HU) to Density Conversion:**
    *   Convert raw pixel values to Hounsfield Units:
        $$ \text{HU} = \text{RescaleSlope} \cdot \text{data\_array} + \text{RescaleIntercept} $$
    *   Convert HU to normalized density (where water = 1.0):
        $$ \text{density} = \frac{\text{HU} + 1000}{1000} $$
        $$ \text{density} = \frac{\text{RescaleSlope} \cdot \text{data\_array} + \text{RescaleIntercept} + 1000}{1000} $$ [S2, unofficial].
    *   *Note:* Some implementations store intermediate values as signed integers by adding $2^{15}$ (32768) to handle negative HU values before conversion [S3, unofficial].

5.  **Volume Stacking:**
    *   Initialize a 3D buffer `volumeData` of size `rows * cols * num_slices` [S3, unofficial].
    *   Iterate through sorted slices $i$ from $0$ to $N-1$:
        *   Calculate `sliceOffset = i * (rows * cols)`.
        *   Copy converted density values into `volumeData[sliceOffset : sliceOffset + (rows*cols)]` [S3, unofficial].

6.  **Coordinate Reconstruction and Bounding Box Calculation:**
    *   **Voxel Size:**
        $$ \text{voxel\_size} = [\text{pixelSpacing}[0], \text{pixelSpacing}[1], \text{sliceThickness}] $$ [S2, unofficial].
        *   Note: `pixelSpacing[0]` corresponds to Y (rows) and `pixelSpacing[1]` to X (cols) in DICOM, but after rotation, the array dimensions map to physical axes. The scale vector is typically `[pixelSpacing[0], pixelSpacing[1], sliceThickness]` [S3, unofficial].
    *   **Slice Distance Calculation:**
        *   If `num_slices > 1`:
            $$ \text{slice\_distance} = | \text{DataCollectionCenterPatient}_{\text{slice1}}[2] - \text{DataCollectionCenterPatient}_{\text{slice0}}[2] | $$
        *   If `num_slices == 1`:
            $$ \text{slice\_distance} = \text{sliceThickness} $$ [S2, unofficial].
    *   **Center Point Calculation:**
        *   Use `ReconstructionTargetCenterPatient` or `DataCollectionCenterPatient` of the first slice as the reference center `mid_pt` [S2, unofficial].
    *   **Bounds Calculation (Corner-Point Convention):**
        *   Volume rendering engines often require corner-point coordinates, whereas DICOM stores pixel centers.
        *   Calculate `min_pt` and `max_pt` based on `voxel_size` and `shape` (`[rows, cols, num_slices]`) [S2, unofficial].
        *   **Z-Axis Bounds:**
            *   Compute raw bounds using the Z-component of `DataCollectionCenterPatient` for the first and last slices.
            *   Adjust for corner-point convention by subtracting/adding half the `slice_distance` [S2, unofficial].
            *   **Pitfall:** If the calculation of Z-bounds fails (e.g., min > max due to sorting or convention errors), reverse the order: use the last slice for `min_pt[2]` and the first for `max_pt[2]`, and log an error [S2, unofficial].
        *   **Y-Axis (Axis 1) Convention:**
            *   DICOM Y-axis convention is often reversed relative to standard Cartesian coordinates used in rendering. Swap `min_pt[1]` and `max_pt[1]` to correct this [S2, unofficial].
        *   **X-Axis (Axis 0):**
            *   Typically follows standard left-to-right or right-to-left depending on the specific DICOM orientation tags (PatientLeft/Right). The rotation in Step 3 handles the in-plane flip, but the bounding box must align with the final array layout.

7.  **Final Volume Layout:**
    *   The resulting volume data is often transposed or rearranged to match the renderer's expected memory layout (e.g., from `[rows, cols, slices]` to `[slices, rows, cols]` or similar, depending on the specific engine's `VolumeLoader` interface) [S2, unofficial].
    *   The physical size in millimeters is stored separately from the texture dimensions to allow for anisotropic scaling during rendering [S1, unofficial].

### Pseudocode

```python
import numpy as np
import os
import glob

def load_dicom_volume(folder_path, suffix='.dcm'):
    """
    Loads a DICOM series from a folder, converts to density, and computes physical bounds.
    """
    # 1. File Selection and Sorting
    files = sorted(glob.glob(os.path.join(folder_path, f'*{suffix}')))
    if not files:
        raise ValueError("No DICOM files found.")

    num_slices = len(files)
    slices_data = []
    metadata_list = []

    # 2. Metadata Extraction and Pixel Loading
    for f in files:
        # Assume bacaDicom or pydicom loads the dataset
        ds = bacaDicom(f) 
        
        rows = ds.rows
        cols = ds.cols
        pixel_spacing = ds.pixel_spacing # [spacing_y, spacing_x]
        slice_thickness = ds.slice_thickness
        rescale_slope = ds.rescale_slope
        rescale_intercept = ds.rescale_intercept
        data_collection_center = ds.data_collection_center_patient
        reconstruction_center = ds.reconstruction_target_center_patient
        
        # Extract raw pixel data
        raw_pixels = ds.pixel_array
        
        # Validate bytes per voxel
        bits_allocated = ds.bits_allocated
        bytes_per_voxel = bits_allocated // 8
        if bytes_per_voxel != 2:
            raise Error(f"Unsupported bytes per voxel: {bytes_per_voxel}")

        # Reshape to [cols, rows] C-order
        data_array = raw_pixels.reshape((cols, rows))
        
        # Rotate -90 degrees to correct orientation
        data_array = np.rot90(data_array, k=-1)
        
        slices_data.append(data_array)
        metadata_list.append({
            'pixel_spacing': pixel_spacing,
            'slice_thickness': slice_thickness,
            'data_collection_center': data_collection_center,
            'reconstruction_center': reconstruction_center
        })

    # 3. HU to Density Conversion
    densities = []
    for i, data_array in enumerate(slices_data):
        # HU = Slope * Pixel + Intercept
        hu_values = rescale_slope * data_array + rescale_intercept
        # Density = (HU + 1000) / 1000
        density_slice = (hu_values + 1000) / 1000.0
        densities.append(density_slice)

    # Stack into 3D volume [rows, cols, num_slices]
    volume_data = np.stack(densities, axis=-1)

    # 4. Coordinate Reconstruction
    first_meta = metadata_list[0]
    last_meta = metadata_list[-1]
    
    # Voxel Size [x, y, z] in mm
    # Note: pixel_spacing[0] is Y (rows), pixel_spacing[1] is X (cols)
    # After rot90, the array dimensions are [rows, cols].
    # We map physical dimensions to array dimensions.
    voxel_size = [first_meta['pixel_spacing'][1], first_meta['pixel_spacing'][0], first_meta['slice_thickness']]
    
    shape = volume_data.shape # (rows, cols, num_slices)
    
    # Slice Distance
    if num_slices > 1:
        z1 = metadata_list[0]['data_collection_center'][2]
        z2 = metadata_list[1]['data_collection_center'][2]
        slice_distance = abs(z2 - z1)
    else:
        slice_distance = first_meta['slice_thickness']

    # Center Point
    mid_pt = first_meta['reconstruction_center'] # or data_collection_center
    
    # Calculate Bounds
    # Physical extent of the volume
    extent_x = shape[0] * voxel_size[0] # rows * pixel_spacing_y
    extent_y = shape[1] * voxel_size[1] # cols * pixel_spacing_x
    extent_z = shape[2] * slice_distance # num_slices * slice_thickness
    
    # Initial min/max based on center and extent
    min_pt = [mid_pt[0] - extent_x/2, mid_pt[1] - extent_y/2, mid_pt[2] - extent_z/2]
    max_pt = [mid_pt[0] + extent_x/2, mid_pt[1] + extent_y/2, mid_pt[2] + extent_z/2]
    
    # Adjust Z for corner-point convention using actual slice centers
    # DICOM stores center. Corner is center - half_thickness.
    # First slice center is z1. First corner is z1 - slice_distance/2.
    # Last slice center is z_last. Last corner is z_last + slice_distance/2.
    try:
        z_first_center = metadata_list[0]['data_collection_center'][2]
        z_last_center = metadata_list[-1]['data_collection_center'][2]
        
        min_pt[2] = z_first_center - slice_distance / 2
        max_pt[2] = z_last_center + slice_distance / 2
    except Exception:
        # Fallback if calculation fails
        min_pt[2], max_pt[2] = max_pt[2], min_pt[2]
        print("Error: Z-axis bounds calculation failed, reversed min/max.")

    # Adjust Y-axis convention (swap min/max)
    min_pt[1], max_pt[1] = max_pt[1], min_pt[1]

    return volume_data, min_pt, max_pt, voxel_size
```

## Subtopics

### DICOM Volume Texture Preparation
This variant prepares the loaded volume for GPU rendering by quantizing the continuous density values into a discrete window range (defined by lower and upper Hounsfield unit thresholds) and integer-downsampling the texture if any axis exceeds 256 voxels. It stores the physical size of the volume in millimeters separately from the texture dimensions to preserve anisotropic scaling information during the downsampling process [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot R \cdot C)$, where $N$ is the number of slices, and $R, C$ are rows and columns. The dominant cost is reading and decoding DICOM headers and pixel data.
*   **Memory Complexity:** $O(N \cdot R \cdot C)$ for the volume data buffer. Additional memory is required for DICOM header parsing.
*   **Performance:** Loading speed depends heavily on I/O throughput and the efficiency of the DICOM parsing library (`bacaDicom` or similar). Conversion to density is a fast element-wise operation.
*   **Strengths:** Handles the complex coordinate transformations required for medical imaging (corner-point vs. center-point, axis flips). Correctly maps HU to physical density.
*   **Limitations:** Assumes all slices have the same dimensions and orientation. Does not handle missing slices or irregular spacing automatically without explicit `slice_distance` calculation. Unsupported bit depths (e.g., 8-bit or 32-bit) are rejected [S3, unofficial].
*   **When to use:** When loading CT or MRI series for volume rendering where anatomical accuracy and correct physical scaling are critical.
*   **When not to use:** For non-medical volumetric data, or when real-time streaming of irregularly spaced slices is required without pre-processing.

## Background
This method originates from implementations in medical imaging visualization libraries, specifically those integrating DICOM loading with WebGL/WebGPU volume rendering engines. It addresses the specific challenges of rendering DICOM series in web-based environments, where standard image viewers often fail to represent the 3D nature of the data correctly (e.g., treating slices as cubes) [S1, unofficial]. The approach is documented in unofficial repositories such as `Panacea` (for the texture preparation and rendering pipeline) [S1, unofficial], `DGR` (for the DICOM loading and gradient-based processing) [S2, unofficial], and `ossium` (for the WebGPU-based DICOM loader and coordinate handling) [S3, unofficial].
