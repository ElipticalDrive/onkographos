# AMR Basis Reconstruction Filter

Also called: AMR Basis Function Interpolation, Basis Function Reconstruction, Basis function interpolation, Basis interpolation method, Reconstruction via Basis Functions, basis function approach, basis method

## Overview
The AMR Basis Reconstruction Filter is a volume rendering interpolation strategy for Block-Structured Adaptive Mesh Refinement (BC AMR) data that computes a continuous, smooth scalar field by blending values from all contributing AMR levels using hat-shaped basis functions [S1, unofficial]. It solves the "stitching" problem at boundaries between cells of different resolutions without subdividing coarse cells into smaller elements or using virtual/inner nodes, thereby avoiding the ghosting artifacts common in other methods [S1, unofficial]. Unlike the "Finest" method, which produces high-frequency transition artifacts at coarse boundaries, or methods by Weber et al. and Moran and Ellsworth that rely on simplicial subdivision, the basis method provides a globally continuous interpolant that is smooth and continuous, though it is more computationally expensive and no longer strictly interpolating [S1, unofficial].

## How it works
The method treats the cell-centered values of leaf cells as scattered data points and reconstructs the value at a query point $\vec{P}$ using a weighted, renormalized sum of hat-shaped basis functions centered at the corners of the "dual cell" containing $\vec{P}$ [S1, unofficial].

### Inputs and Outputs
*   **Input:** A query point $\vec{P}$ in 3D space; the AMR dataset consisting of bricks, levels, and cell values [S1, unofficial].
*   **Output:** A single scalar value $V(\vec{P})$ representing the interpolated value at $\vec{P}$ [S1, unofficial].

### Data Structures
The method relies on the standard BC AMR structure:
*   **Bricks:** Rectangular blocks of cells, typically around $16 \times 16 \times 16$ data cells each [S1, unofficial].
*   **Levels:** Hierarchical refinement levels where bricks on the same level do not overlap, but overlap coarser levels [S1, unofficial].
*   **Refinement Factor ($R$):** Determines the grid alignment, typically $R=2$, where each coarse cell is covered by $R \times R \times R$ finer cells [S1, unofficial].
*   **Leaf vs. Inner Nodes:** Cells are classified as "leaf" (finest resolution in that region) or "inner" (coarser cells covered by finer ones) [S1, unofficial].
*   **Dual Cell:** For a point $\vec{P}$ at a specific level $l$, the dual cell $D$ is the coarse cell at level $l$ that contains $\vec{P}$ [S1, unofficial].

### Formulas
The hat-shaped basis function $\hat{h}(t)$ is defined as:
$$ \hat{h}(t) = \max(1 - t, 0) $$

The basis function $\hat{H}_C(\vec{P})$ for a corner cell $C$ is the product of 1D hat functions along each axis:
$$ \hat{H}_C(\vec{P}) = \hat{h}\left(\frac{|\vec{C}_p.x - \vec{P}_x|}{\vec{C}_w}\right) \hat{h}\left(\frac{|\vec{C}_p.y - \vec{P}_y|}{\vec{C}_w}\right) \hat{h}\left(\frac{|\vec{C}_p.z - \vec{P}_z|}{\vec{C}_w}\right) $$
where $\vec{C}_p$ is the position of the corner of cell $C$ and $\vec{C}_w$ is the width of cell $C$ [S1, unofficial].

The final interpolated value is:
$$ \text{AMR}_{\text{basis}}(\vec{P}) = \frac{\sum_{C_i} \hat{H}_{C_i}(\vec{P}) C_{v_i}}{\sum_{C_i} \hat{H}_{C_i}(\vec{P})} $$
where the sum is over all leaf cells $C_i$ that are corners of the dual cells found during the traversal [S1, unofficial].

### Parameters
*   **Refinement Factor ($R$):** Determines the grid alignment. Typically 2 [S1, unofficial].
*   **Basis Function Support:** The support is not truncated at the first sample on the neighboring side, leading to larger overlap between cells from neighboring blocks compared to methods like Ljung et al. [S2].

### Algorithm Steps
1.  Initialize `sum_weights = 0` and `sum_weightedValues = 0` [S1, unofficial].
2.  Iterate through levels $l$ starting from level 0 upwards [S1, unofficial].
3.  For each level $l$, find the dual cell $D$ of point $\vec{P}$ at that level [S1, unofficial].
4.  For each corner cell $C$ of the dual cell $D$:
    a.  Check if $C$ is a leaf cell [S1, unofficial].
    b.  If $C$ is a leaf cell, calculate $\hat{H}_C(\vec{P})$ [S1, unofficial].
    c.  Add $\hat{H}_C(\vec{P})$ to `sum_weights` [S1, unofficial].
    d.  Add $\hat{H}_C(\vec{P}) \times C.v$ to `sum_weightedValues` [S1, unofficial].
5.  Check if any of the corner cells $C$ in the current dual cell $D$ are inner nodes [S1, unofficial].
    a.  If **none** of the cells are inner nodes, break the loop (coarser levels will not contribute unique leaf information or are fully covered) [S1, unofficial].
    b.  If there are inner nodes, continue to the next level [S1, unofficial].
6.  Return `sum_weightedValues / sum_weights` [S1, unofficial].

        if not has_inner_node:

### Edge Cases and Pitfalls
*   **Non-Interpolating:** The method is not strictly interpolating (values at cell centers may not be exactly reproduced if surrounded by other levels), which makes implicit ray-isosurface intersection difficult [S1, unofficial].
*   **Performance in Deep Refinement:** In deeply refined regions, it is costly to determine the coarsest level that contributes, potentially requiring many dual-cell look-ups [S1, unofficial].
*   **Support Overlap:** The non-truncated support results in larger support overlap between cells from neighboring blocks compared to truncated methods [S2].
*   **Ghosting:** Unlike methods using virtual/inner cells, this method avoids ghosting artifacts [S1, unofficial].

## Subtopics

### AMR Blend Method
A reconstruction strategy for AMR data used to render different AMR levels (e.g., Level 0-1, 0-2) by blending them, as shown in OSPRay implementations [S1, unofficial]. It is used to visualize data at varying levels of refinement but is distinct from the basis function approach which blends across all levels simultaneously via basis functions [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Higher than the "Finest" method [S1, unofficial]. In deeply refined regions, performance degrades because determining the coarsest contributing level is non-trivial, leading to many dual-cell look-ups [S1, unofficial].
*   **Memory Complexity:** Standard AMR storage; no additional subdivision structures required (unlike Weber et al.) [S1, unofficial].
*   **Quality:** Produces smooth, continuous images without high-frequency transition artifacts at coarse cell boundaries, which are present in the "Finest" method [S1, unofficial]. It avoids ghosting artifacts associated with virtual cells [S1, unofficial].
*   **Strengths:** Simple implementation, smooth continuity, no ghosting, no need for cell subdivision [S1, unofficial].
*   **Limitations:** More expensive than "Finest"; not strictly interpolating (harder for isosurface extraction); potential performance hit in deep refinement due to level traversal [S1, unofficial].
*   **When to Use:** Use when smooth continuity across level boundaries is required and ghosting artifacts must be avoided, accepting higher computational cost [S1, unofficial].

## Background
The method was introduced by Ingo Wald, Carson Brownlee, Will Usher, and Aaron Knoll in 2017 as part of their work on CPU volume rendering of Adaptive Mesh Refinement data in the OSPRay framework [S1, unofficial]. It was presented as a novel reconstruction option compared to existing methods like those by Weber et al. and Moran and Ellsworth, which required subdividing cells [S1, unofficial]. The method is implemented in OSPRay and integrated into ParaView [S1, unofficial].
