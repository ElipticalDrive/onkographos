# AMR Basis Reconstruction Filter

Also called: AMR Basis Function Interpolation, Basis Function Reconstruction, Basis function interpolation, Basis interpolation method, Reconstruction via Basis Functions, basis function approach, basis method

## Overview
The AMR Basis Reconstruction Filter is a volume rendering interpolation strategy for Berger-Colella (BC) Adaptive Mesh Refinement (AMR) data that computes a continuous, smooth sample value by performing a weighted and renormalized sum of hat-shaped basis functions centered at leaf cell corners [S1, unofficial]. It solves the "stitching" problem at AMR level boundaries by interpolating across all contributing AMR levels simultaneously, thereby avoiding the high-frequency transition artifacts and ghosting associated with methods that rely on virtual cells, inner nodes, or non-rectilinear subdivision [S1, unofficial][S2]. Unlike sibling methods that subdivide coarse cells into stitch elements or truncate basis support, this approach ensures continuity without introducing topological complexity, though it sacrifices strict interpolation properties [S1, unofficial][S2].

## How it works
**Inputs and Outputs**
*   **Input:** A query point $\vec{P}$ in 3D space; the AMR dataset consisting of bricks on multiple levels, where each cell $C$ has a center $\vec{C}_p$, a width $C_w$, and a scalar value $C.v$. The dataset is traversed using a kd-tree structure to locate cells [S1, unofficial].
*   **Output:** A single interpolated scalar value $AMR_{basis}(\vec{P})$.

**Data Structures**
The method operates on the standard Berger-Colella AMR representation: a set of bricks $B^{(i)}$ containing $16 \times 16 \times 16$ (typically) data cells. Cells are organized by level $L$, with finer levels covering coarser cells in multiples of the refinement factor $R$ [S1, unofficial]. The implementation relies on a kd-tree to efficiently find the "dual cell" for any query point [S1, unofficial].

**Formulas**
The reconstruction uses a 1D hat function $\hat{h}(t)$ defined as:
$$ \hat{h}(t) = \max(1 - t, 0) $$
The 3D basis function $\hat{H}_C(\vec{P})$ for a cell $C$ centered at $\vec{C}_p$ with width $C_w$ is the product of three 1D hat functions along each axis:
$$ \hat{H}_C(\vec{P}) = \hat{h}\left(\frac{|\vec{C}_{p,x} - \vec{P}_x|}{C_w}\right) \hat{h}\left(\frac{|\vec{C}_{p,y} - \vec{P}_y|}{C_w}\right) \hat{h}\left(\frac{|\vec{C}_{p,z} - \vec{P}_z|}{C_w}\right) $$
The final interpolated value is a weighted average:
$$ AMR_{basis}(\vec{P}) = \frac{\sum_{C_i} \hat{H}_{C_i}(\vec{P}) C_{v_i}}{\sum_{C_i} \hat{H}_{C_i}(\vec{P})} $$
where the sum is over all leaf cells $C_i$ that contribute to the query point [S1, unofficial].

**Algorithm Steps**
1.  Initialize `sum_weights` = 0 and `sum_weightedValues` = 0.
2.  Iterate through AMR levels $l$ starting from level 0 (coarsest) upwards.
3.  Find the dual cell $D$ for point $\vec{P}$ at the current level $l$. The dual cell is the coarse cell at level $l$ that contains $\vec{P}$ [S1, unofficial].
4.  For each of the 8 corner cells $C$ of the dual cell $D$:
    a. Check if $C$ is a leaf cell (i.e., it has no finer children).
    b. If $C$ is a leaf cell, compute $\hat{H}_C(\vec{P})$.
    c. Add $\hat{H}_C(\vec{P})$ to `sum_weights`.
    d. Add $\hat{H}_C(\vec{P}) \times C.v$ to `sum_weightedValues`.
5.  Check if any of the corner cells $C$ in the current dual cell $D$ are inner nodes (non-leaf cells).
    a. If **none** of the corner cells are inner nodes, break the loop. This indicates that the finest level contributing to $\vec{P}$ has been processed, and no coarser levels will add new leaf contributions [S1, unofficial].
    b. If any corner cell is an inner node, continue to the next level $l+1$.
6.  Return `sum_weightedValues` / `sum_weights`.

**Pseudocode**
```python
def AMR_basis(P, amr_data):
    sum_weights = 0.0
    sum_weighted_values = 0.0
    
    # Iterate levels from coarsest (0) to finest
    for level in amr_data.levels:
        # Find the dual cell D at this level containing P
        D = find_dual_cell(P, level, amr_data)
        
        # Check if we should stop: if all corners of D are leaves,
        # no finer level will contribute new leaf cells for P.
        # Note: The source logic implies checking if corners are inner nodes.
        # If none are inner nodes, we have reached the finest contributing level.
        all_corners_are_leaves = True
        for corner_cell in D.corners:
            if not corner_cell.is_leaf:
                all_corners_are_leaves = False
                break
        
        for corner_cell in D.corners:
            if corner_cell.is_leaf:
                # Compute hat function value
                # h_hat(t) = max(1 - t, 0)
                # H_hat(P, C) = h_hat(dx/Cw) * h_hat(dy/Cw) * h_hat(dz/Cw)
                h_hat_val = compute_h_hat(P, corner_cell)
                
                sum_weights += h_hat_val
                sum_weighted_values += h_hat_val * corner_cell.value
        
        if all_corners_are_leaves:
            break
            
    if sum_weights == 0:
        return 0.0 # Or handle as error/undefined
        
    return sum_weighted_values / sum_weights

def compute_h_hat(P, cell):
    # cell.center is (cx, cy, cz)
    # cell.width is w
    dx = abs(cell.center.x - P.x) / cell.width
    dy = abs(cell.center.y - P.y) / cell.width
    dz = abs(cell.center.z - P.z) / cell.width
    
    h_x = max(1.0 - dx, 0.0)
    h_y = max(1.0 - dy, 0.0)
    h_z = max(1.0 - dz, 0.0)
    
    return h_x * h_y * h_z
```

**Parameters and Edge Cases**
*   **Refinement Factor ($R$):** Typically an integer (e.g., 2), determining how many fine cells cover one coarse cell [S1, unofficial].
*   **Brick Size:** Typically $16 \times 16 \times 16$ cells, but can vary [S1, unofficial].
*   **Precision:** The method is not strictly interpolating; values at cell centers are not guaranteed to be exactly $C.v$ if other levels contribute [S1, unofficial].
*   **Deeply Refined Regions:** In regions with high refinement levels, determining the coarsest contributing level is non-trivial. The algorithm may perform many dual-cell look-ups up to the coarsest level before the "all leaves" condition is met, which is costly [S1, unofficial].
*   **Boundary Support:** The basis function support is not truncated at the first sample on the neighboring side. This leads to larger support overlap between cells from neighboring blocks compared to methods like Leaf et al. or Ljung et al. [S2].

## Subtopics

### AMR Blend Method
A reconstruction strategy for AMR data used to render different AMR levels (e.g., Level 0-1, 0-2) as distinct visual layers or blended results [S1, unofficial]. It is used in the OSPRay implementation for rendering AMR data at varying levels, allowing users to inspect specific resolution ranges [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity**
*   **Time:** The cost depends on the number of levels traversed. In deeply refined regions, the algorithm may iterate through many coarse levels before stopping, making it potentially costly due to repeated dual-cell look-ups [S1, unofficial].
*   **Memory:** Requires storage for the AMR kd-tree and cell data. No additional large temporary structures are needed beyond the accumulator variables [S1, unofficial].

**Measured Performance**
*   In benchmarks on a KNL node and dual-Xeon systems, the Basis method is the most expensive of the four reconstruction strategies (Finest, Blend, Inner, Basis) [S1, unofficial].
*   The "Finest" method achieves the highest performance but worst quality; the Basis method offers the best quality but lowest performance [S1, unofficial].
*   Performance is largely oblivious to the maximum refinement level if the finer levels only affect a small portion of the rays (e.g., waves at the dataset center) [S1, unofficial].

**Strengths and Limitations**
*   **Strengths:** Produces smooth, continuous images without high-frequency transition artifacts at coarse cell boundaries. Avoids ghosting artifacts by not using virtual or inner cells. Easy to implement [S1, unofficial].
*   **Limitations:** Not strictly interpolating, which makes implicit ray-isosurface intersection non-obvious. Higher computational cost than "Finest" or "Inner" methods. Large support overlap can lead to unnecessary computations in sparse regions [S1, unofficial][S2].

**When to Use**
*   Use when image quality and smoothness across AMR boundaries are prioritized over performance.
*   Avoid when strict interpolation is required for isosurface extraction or when performance is critical and artifacts are acceptable.

## Background
The AMR Basis Reconstruction Filter was introduced by Ingo Wald, Carson Brownlee, Will Usher, and Aaron Knoll in 2017 as part of their work on CPU volume rendering of Adaptive Mesh Refinement data [S1, unofficial]. It was implemented in the OSPRay interactive CPU ray tracing framework and integrated into ParaView [S1, unofficial]. The method is novel compared to existing approaches by Weber et al. and Moran and Ellsworth, which rely on subdividing lower-resolution cells into stitch cells or simplicial elements to handle boundaries [S1, unofficial]. It also differs from Leaf et al. and Ljung et al. by not truncating the basis function support [S2].
