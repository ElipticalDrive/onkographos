# Redundant coarse data bridging

Also called: Redundant data bridging, Redundant coarse data gap filling

## Overview
Redundant coarse data bridging is a method for eliminating geometric cracks and holes that occur at the boundaries between different refinement levels in Adaptive Mesh Refinement (AMR) volume rendering. It solves the problem of discontinuous geometry by utilizing data points stored at coarser levels—specifically those that are redundant due to the overlapping nature of patch-based AMR—to fill the voids between coarse and fine meshes [S1]. Unlike stitching cells, which constructs new unstructured geometry to bridge gaps, this method capitalizes on existing overlap in the data structure to seamlessly connect iso-surfaces or scalar fields across level boundaries [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A patch-based AMR dataset containing hierarchical levels of refinement, where coarser levels contain data points that overlap with the spatial domain of finer levels.
*   **Output:** A continuous, gap-free geometric representation (e.g., iso-surface) across all AMR levels.

**Data Structures:**
The method relies on the inherent redundancy in patch-based AMR structures. In such structures, a cell at level $L$ may be subdivided into children at level $L+1$. The parent cell's data point (e.g., a 0D scalar value) remains stored even if the children are active. This parent data point is considered "redundant" for the fine-scale analysis but is available for bridging [S1].

**Steps:**
1.  **Identify Redundant Data:** Locate data points at coarser levels that correspond to spatial regions covered by finer levels. In patch-based AMR, these points are naturally present due to the hierarchical storage scheme [S1].
2.  **Gap Detection:** Identify boundaries where a coarse cell abuts a finer mesh, creating a geometric discontinuity or "crack" in the rendered iso-surface [S1].
3.  **Bridging:** Use the redundant coarse data points to interpolate or define the geometry within the gap. The coarse data point acts as a bridge, ensuring that the scalar field or surface is continuous across the level transition [S1].
4.  **Rendering:** Render the unified geometry. The presence of the redundant coarse data ensures that the iso-surface does not exhibit holes at the level interfaces [S1].

**Formulas:**
Not given in the sources. The method is described conceptually as utilizing existing overlap rather than a specific mathematical interpolation formula.

**Parameters:**
*   **Overlap Threshold:** Not given in the sources. The method assumes the existence of overlap inherent to patch-based AMR.

**Edge Cases and Pitfalls:**
*   **Non-Patch-Based AMR:** The method specifically relies on the "existing overlap in patch-based AMR" [S1]. It may not be directly applicable to non-overlapping AMR structures without modification.
*   **Data Availability:** Requires that the coarse data points are preserved in memory even when finer levels are active. If the coarse data is discarded to save memory, bridging cannot occur.

**Pseudocode:**
```python
def bridge_gaps_with_redundant_data(amr_dataset):
    """
    Bridges gaps between AMR levels using redundant coarse data.
    
    Args:
        amr_dataset: A patch-based AMR dataset structure.
        
    Returns:
        A continuous geometric representation (e.g., iso-surface mesh).
    """
    # Step 1: Identify redundant coarse data points
    # In patch-based AMR, coarse cells overlap with fine children.
    # These coarse data points are redundant for fine-scale analysis
    # but available for bridging.
    redundant_points = []
    for level in amr_dataset.levels:
        if level.is_coarser_than_next_level():
            for cell in level.cells:
                # Check if this cell's data point is spatially covered by finer levels
                if cell.has_fine_children():
                    redundant_points.append(cell.data_point)
    
    # Step 2: Identify gaps at level boundaries
    # Gaps occur where coarse cells meet finer meshes
    gaps = identify_level_boundary_gaps(amr_dataset)
    
    # Step 3: Bridge gaps using redundant data
    for gap in gaps:
        # Find the redundant coarse data point associated with the gap
        # The coarse data point lies within the spatial domain of the gap
        coarse_point = find_redundant_point_for_gap(gap, redundant_points)
        
        # Use the coarse point to define the geometry in the gap
        # This ensures continuity of the iso-surface
        fill_gap_with_coarse_data(gap, coarse_point)
        
    # Step 4: Render the unified geometry
    mesh = generate_unified_mesh(amr_dataset)
    return mesh
```

## Subtopics

### AMR Grid Completion
A preprocessing technique that converts an adaptive wavelet grid into a traditional node-centered AMR grid by adding supplementary nodes, allowing the use of existing AMR visualization software [S2]. Unlike direct summation in wavelet space, this approach deals with actual function values on a traditional node-centered AMR grid, requiring additional storage and potentially significant preprocessing time [S2]. It is chosen when compatibility with standard AMR visualization tools (e.g., Paraview, VisIt) is required, rather than rendering directly from the wavelet basis [S2].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Requires additional storage for redundant coarse data points, which are already present in patch-based AMR structures, so no extra storage is needed for the bridging itself [S1]. In contrast, AMR Grid Completion requires additional storage for supplementary nodes [S2].
*   **Time:** The bridging process is described as utilizing existing data, implying low computational overhead during rendering [S1]. However, AMR Grid Completion may take significant preprocessing time depending on the complexity of the wavelet grid [S2].

**Strengths and Limitations:**
*   **Strengths:** Eliminates cracks and holes in iso-surfaces at AMR level boundaries without requiring new geometry construction (unlike stitching cells) [S1]. Leverages existing data redundancy.
*   **Limitations:** Specific to patch-based AMR structures with overlapping levels [S1]. Not applicable to non-overlapping AMR grids.

**When to use it and when not:**
*   **Use:** When rendering patch-based AMR data and encountering visual artifacts (cracks/holes) at level boundaries, and when coarse data is preserved.
*   **Do not use:** When using non-patch-based AMR structures, or when coarse data has been discarded to save memory.

## Background
The method was proposed as an alternative to the "stitching cells" algorithm for filling gaps between AMR levels [S1]. It was demonstrated in the context of the AMReX framework, highlighting the benefits of patch-based AMR structures where overlap is inherent [S1]. The technique addresses the visual discontinuities that arise when re-sampling or rendering iso-surfaces across different refinement levels [S1].
