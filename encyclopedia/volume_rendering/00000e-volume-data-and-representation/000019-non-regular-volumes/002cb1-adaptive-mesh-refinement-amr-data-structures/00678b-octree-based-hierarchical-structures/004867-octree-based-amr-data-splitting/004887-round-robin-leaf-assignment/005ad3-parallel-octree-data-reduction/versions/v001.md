# Parallel Octree Data Reduction

Also called: Adaptive multiresolution visualization using parallel octrees

## Overview
Parallel Octree Data Reduction is a technique for the interactive visualization of large scientific data sets by combining hierarchical data reduction with parallel computing [S1, unofficial]. It distributes data across Message Passing Interface (MPI) processors to build a distributed-memory octree, allowing users to interactively adapt resolution (refine or prune) on a local graphics workstation while retaining access to full-resolution data [S1, unofficial]. It sets itself apart from sibling methods by explicitly coupling the data reduction phase with the parallel distribution infrastructure, using statistical error indicators to guide both the visualization fidelity and the potential for future adaptive refinement.

## How it works
**Inputs and Outputs**
*   **Input:** A large field data set consisting of spatial locations and their corresponding field data values.
*   **Output:** A distributed octree structure where each leaf node contains aggregated field data and statistical error indicators, distributed across $M$ processors.

**Data Structures**
The core data structure is a distributed octree. Each node in the octree contains:
*   Spatial bounds of the octant.
*   Aggregated field data value (e.g., mean).
*   Statistical error indicators:
    *   Standard deviation ($\sigma$).
    *   Maximum deviation from the mean ($\epsilon$).
*   Interoctant links:
    *   Local links to children and siblings.
    *   Off-processor parent links: Represented by a local root structure containing spatial information to enable local point searches without communication [S1, unofficial].

**Parameters**
*   **Maximum elements per octant ($N_{max}$):** A user-defined threshold for subdividing an octant leaf. The current implementation divides an octant leaf when this number of elements has been inserted [S1, unofficial]. Typical value: Not specified in sources, but used to maintain uniform fidelity for h-adaptive meshes [S1, unofficial].

**Algorithm Steps**
1.  **Insertion:** Loop through the field data. For each data point with spatial location $\mathbf{x}$ and value $v$, insert $v$ into the appropriate leaf octant of the octree based on $\mathbf{x}$ [S1, unofficial].
2.  **Refinement Check:** After insertion, determine if the current leaf octant should divide. If the number of elements in the leaf exceeds $N_{max}$, divide the octant to create eight new leaf octants [S1, unofficial].
    *   *Note:* For uniform meshes or p-adaptive methods, the current criterion is insufficient. Future plans include using error indicator techniques such as energy norms or gradient bounds to determine subdivision [S1, unofficial].
3.  **Aggregation:** After all data points are inserted and the tree structure is finalized, aggregate the field data values for each leaf octant. The values are averaged or otherwise agglomerated [S1, unofficial].
4.  **Error Computation:** For each leaf octant, compute statistical values to indicate error:
    *   Standard deviation ($\sigma$).
    *   Maximum deviation from the mean ($\epsilon$) [S1, unofficial].
5.  **Normalization:** Normalize the standard deviation and maximum deviation by the mean ($\mu$) of the leaf octant to yield normalized error indicators $a_n$ and $e_n$:
    $$ a_n = \frac{\sigma}{\mu} $$
    $$ e_n = \frac{\epsilon}{\mu} $$
    These are included as additional scalar fields to be visualized, providing an indication of the fidelity of the reduced data set to the original data set [S1, unofficial].
6.  **Distribution:** Distribute the octree across the processors of the MPP using an octree partitioning algorithm and arbitrary octant migration for load balancing [S1, unofficial].
7.  **Traversal:** Form the reduced data set by traversing each local octree and computing the values on each leaf. This is done on each processor in linear time with respect to the local number of data points [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Insufficient Refinement Criterion:** For uniform meshes or p-adaptive methods, the "max elements" criterion is insufficient to capture fine-scale structure. Error indicator techniques such as energy norms or gradient bounds are required [S1, unofficial].
*   **Complex Algorithms:** Algorithms requiring fat-neighbor links or a guarantee of maximum level-difference between adjacent octants complicate octree insertion [S1, unofficial].
*   **Communication:** Most insertion, refinement, and coarsening operations can be performed without interprocessor communication. However, off-processor parent links require local root structures to avoid communication during point searches [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Forming the reduced data set is linear time with respect to the local number of data points on each processor [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** The system allows for interactive exploration of large data sets while retaining full-resolution capability [S1, unofficial].
*   **Strengths:**
    *   Enables interactive adaptation of resolution on local workstations.
    *   Provides error indicators ($a_n, e_n$) to highlight regions of interest and potential fine-scale structure [S1, unofficial].
    *   Efficient traversal enabled by interoctant links and local root structures for off-processor parents [S1, unofficial].
*   **Limitations:**
    *   The current refinement criterion is limited to h-adaptive meshes with roughly constant error per data point [S1, unofficial].
    *   Complex algorithms may require additional links that complicate insertion [S1, unofficial].

## Background
Parallel Octree Data Reduction was developed to address the challenge of visualizing and exploring large scientific data sets whose size often exceeds the performance and memory capacity of even the most powerful graphics workstations [S1, unofficial]. The technique combines hierarchical data reduction methods with parallel computing to allow interactive exploration while retaining full-resolution capability [S1, unofficial].
