# Parallel Octree Data Reduction

Also called: Adaptive Multiresolution Subsampling, Adaptive Subsampling, Adaptive multiresolution visualization using parallel octrees, Parallel Octree Subsampling

## Overview
Parallel Octree Data Reduction is a technique for the interactive visualization of large scientific datasets by combining hierarchical data reduction with parallel computing [S1, unofficial]. It distributes data across Massively Parallel Processing (MPP) processors to build a distributed-memory octree, allowing users to interactively adapt resolution (refine or prune) on a local graphics workstation while retaining access to full-resolution data [S1, unofficial]. Unlike uniform grid subsampling, which uses a fixed grid and allows more grid points but higher approximation error in complex regions, this method places more points where data changes rapidly to minimize approximation error [S2]. It builds on [Round-robin Leaf Assignment](12287-round-robin-leaf-assignment.md) for the initial distribution of octree leaves, but adds the logic for adaptive refinement based on data error metrics.

## How it works
**Inputs and Outputs**
*   **Input:** File-based scalar field data requiring only spatial coordinate information; no connectivity information is necessary [S2]. The input format supports unstructured tetrahedral and hexahedral, block adaptive, and uniform meshes [S2].
*   **Output:** A reduced multiresolution dataset represented by a distributed octree. Each leaf octant stores the agglomerated field value, statistical error indicators, and links to parent/children [S1, unofficial][S2]. The normalized statistical values are communicated as additional scalar fields to the visualization client [S2].

**Data Structures**
The core structure is a distributed octree.
*   **Octant Node:** Contains spatial information (bounding box), a list of associated data points (or their aggregated statistics), and links to children.
*   **Inter-octant Links:** Enable efficient traversal. Links may be local or off-processor [S1, unofficial].
*   **Local Root Structure:** Off-processor parent links are represented by a local root structure containing spatial information. This enables local point searches without communication [S1, unofficial].
*   **Statistical Fields:** For each leaf, the following are stored:
    *   Mean value ($\mu$)
    *   Standard deviation ($\sigma$)
    *   Maximum deviation from the mean ($\epsilon$)
    *   Normalized standard deviation ($a_n = \sigma / \mu$)
    *   Normalized maximum deviation ($e_n = \epsilon / \mu$) [S1, unofficial]

**Parameters**
*   **Refinement Criterion:** A threshold controlling refinement. This can be:
    *   A user-specified bound on standard deviation or maximum deviation [S2].
    *   An automatically determined error bound given a performance constraint (maximum target number of leaf octants) [S2].
    *   A user-defined maximum number of elements per octant (used for h-adaptive meshes where error is roughly constant) [S1, unofficial].
*   **Aggregation Method:** Field data values are averaged or otherwise agglomerated after insertion [S1, unofficial].

**Algorithm Steps**
1.  **Insertion:** Loop through the input field data. For each data point with spatial location $(x, y, z)$ and value $v$, insert $v$ into the appropriate leaf octant of the octree based on spatial coordinates [S1, unofficial][S2].
2.  **Evaluation:** Evaluate each leaf octant according to the specified criterion [S2].
3.  **Refinement:** If the criterion indicates refinement is necessary (e.g., element count exceeds threshold, or error metrics exceed bounds):
    *   Split the leaf octant into eight new child octants [S1, unofficial][S2].
    *   Reassign the associated data points from the parent leaf to the new child leaf octants [S2].
    *   *Note:* For uniform meshes or p-adaptive methods, the max-element criterion is insufficient; error indicator techniques such as energy norms or gradient bounds should be used to determine subdivision [S1, unofficial].
4.  **Aggregation and Statistics:** For each leaf octant (after all insertions and refinements):
    *   Compute the mean ($\mu$) of the aggregated field values.
    *   Compute the standard deviation ($\sigma$).
    *   Compute the maximum deviation from the mean ($\epsilon$).
    *   Compute normalized error indicators: $a_n = \sigma / \mu$ and $e_n = \epsilon / \mu$ [S1, unofficial].
5.  **Distribution:** Distribute the octree across the processors of the MPP using an octree partitioning algorithm and arbitrary octant migration for load balancing [S1, unofficial].
6.  **Traversal and Output:** Traverse each local octree and compute the final values on each leaf. This is done on each processor in linear time with respect to the local number of data points [S1, unofficial]. The reduced data set and error fields are communicated to the client [S2].

**Pseudocode**
```python
def parallel_octree_reduction(data_points, criterion, num_processors):
    """
    data_points: List of tuples (x, y, z, value)
    criterion: Function or threshold determining refinement
    num_processors: Number of MPP processors
    """
    # 1. Parallel Insertion
    # Each processor handles a subset of data points or uses a distributed hash
    # The octree is built in parallel.
    octree = DistributedOctree()
    
    for (x, y, z, value) in data_points:
        leaf = octree.find_leaf(x, y, z)
        leaf.insert(value)
        
        # 2. Evaluation and Refinement
        if criterion.should_refine(leaf):
            children = octree.split_leaf(leaf)
            # 3. Reassign points to children
            for child in children:
                child.insert(leaf.values) # Re-distribute points to new children
            leaf.clear() # Parent is no longer a leaf

    # 4. Aggregation and Statistics
    for leaf in octree.get_all_leaves():
        if leaf.is_empty():
            continue
        
        values = leaf.get_values()
        mu = mean(values)
        sigma = standard_deviation(values)
        epsilon = max_deviation_from_mean(values, mu)
        
        # Avoid division by zero if mean is zero
        if mu == 0:
            a_n = 0
            e_n = 0
        else:
            a_n = sigma / mu
            e_n = epsilon / mu
            
        leaf.set_mean(mu)
        leaf.set_normalized_error(a_n, e_n)

    # 5. Distribution and Load Balancing
    # Partition the octree across num_processors
    # Use octree partitioning algorithm and arbitrary octant migration
    distributed_octree = partition_octree(octree, num_processors)

    # 6. Output Generation
    # Traverse local octree on each processor
    reduced_data = []
    for leaf in distributed_octree.local_leaves():
        reduced_data.append({
            'center': leaf.center,
            'value': leaf.mean,
            'error_a': leaf.a_n,
            'error_e': leaf.e_n
        })
        
    return reduced_data
```

**Edge Cases and Pitfalls**
*   **Uniform/P-Adaptive Meshes:** The default criterion (max elements) is insufficient for uniform meshes or p-adaptive methods. Using it may lead to poor fidelity. Error indicator techniques (energy norms, gradient bounds) are required [S1, unofficial].
*   **Memory Limits:** Approximation errors increase as the original problem size increases because a smaller percentage of points can be used in the reduced dataset due to local workstation memory limits [S2]. This is mitigated by adaptive refinement at the cost of increased communication [S2].
*   **Complex Algorithms:** Algorithms like streamlines or isosurface generation may require fat-neighbor links or a guarantee of maximum level-difference between adjacent octants. Providing this functionality complicates octree insertion [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Forming the reduced data set is done in linear time with respect to the local number of data points on each processor [S1, unofficial].
*   **Memory Complexity:** Limited by the memory size and speed of the local graphics workstation for the reduced dataset [S2]. The distributed octree structure requires memory for inter-octant links and local root structures [S1, unofficial].
*   **Performance:** The method is designed for interactive exploration on desktop workstations connected via high-speed networks [S2].
*   **Strengths:** Minimizes approximation error by placing more points where data changes rapidly [S2]. Allows interactive adaptation of resolution (zooming in on regions of interest) without sacrificing local graphics performance [S1, unofficial][S2].
*   **Limitations:** Approximation errors can be high for very large datasets if workstation memory is constrained [S2]. Communication overhead increases with adaptive refinement [S2].
*   **When to use:** Interactive remote exploration of large terabyte/petabyte scalar field datasets [S2].
*   **When not to use:** When uniform grid subsampling is sufficient and the overhead of octree management is unjustified, or when the dataset is small enough to fit entirely in local memory.

## Background
*   **Origin:** Developed by Lori A. Freitag and Raymond M. Loy at Argonne National Laboratory [S2].
*   **History:** The technique was presented in the mid-1990s as a solution to the challenge of exploring terabyte and petabyte-scale datasets on desktop workstations [S2]. It was part of a broader effort to compare remote visualization strategies, including image-based rendering and parallel visualization servers [S2].
*   **Implementation:** The system uses a client/server model based on TCP/IP and Unix sockets, implemented via the ALICE Memory Snooper (AMS) from Argonne National Laboratory [S2]. The GUI uses Java Swing components with VTK classes [S2].
*   **Usage:** Used for interactive remote exploration of large scientific data sets [S1, unofficial][S2].
