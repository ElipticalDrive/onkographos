# Round-robin Leaf Assignment

Also called: Round-robin distribution

## Overview
Round-robin Leaf Assignment is a parallel distribution strategy for Adaptive Mesh Refinement (AMR) volume rendering where octree leaves are assigned to processing nodes based on their index in a deterministic octree traversal, independent of the viewing direction [S1, unofficial]. It sets itself apart from sibling methods like Back-to-front Cell Assignment by using a static, view-independent assignment, which reduces I/O overhead during viewpoint animation, whereas alternatives often require dynamic re-traversal or cell-level decomposition based on camera position [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: An octree structure generated by the AMR splitting stage, containing a list of leaves with varying sizes (data volumes).
- Input: $N$, the total number of processing nodes.
- Output: A mapping from each processing node $i$ (where $0 \le i < N$) to a subset of octree leaves.

**Data structures:**
- The octree leaves are accessed via a linearized list generated by a specific traversal order (e.g., depth-first or breadth-first). The exact traversal algorithm is not specified in the sources, but it must be deterministic to ensure consistent indexing [S1, unofficial].
- Each leaf has an implicit or explicit index $k$ in this traversal list, where $k = 0, 1, 2, \dots, L-1$ and $L$ is the total number of leaves.

**Steps:**
1. Perform a deterministic octree traversal to generate an ordered list of all leaves.
2. For each leaf in the list, determine its zero-based index $k$.
3. Assign leaf $k$ to processing node $i$, where $i = k \pmod N$.

**Formula:**
Node $i$ is assigned all leaves with index $k$ such that:
$$ k = N \cdot j + i $$
where $j = 0, 1, 2, \dots$ and $N$ is the total number of processing nodes.

**Parameters:**
- $N$: Total number of processing nodes. Typical values depend on the cluster size.

**Edge cases and pitfalls:**
- **Load balancing:** Octree leaves can vary vastly in size (number of cells or data volume). Since assignment is based on count rather than size, load balancing problems are expected [S1, unofficial].
- **Compositing complexity:** The compositing stage is complicated and involves significant communication because nodes render multiple non-contiguous leaves scattered across the octree [S1, unofficial].
- **Communication overhead:** Increased communication is required to gather partial images from non-contiguous leaves, though this can be overlapped with rendering [S1, unofficial].

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def assign_leaves_robin(octree_leaves, num_nodes):
    """
    Assign octree leaves to processing nodes using round-robin distribution.
    
    Args:
        octree_leaves: A list of leaf objects, ordered by a deterministic octree traversal.
        num_nodes: Total number of processing nodes (N).
        
    Returns:
        A dictionary mapping node_id to a list of assigned leaves.
    """
    assignments = {i: [] for i in range(num_nodes)}
    
    for index, leaf in enumerate(octree_leaves):
        node_id = index % num_nodes
        assignments[node_id].append(leaf)
        
    return assignments
```

## Subtopics

## Operating characteristics
- **Time complexity:** Assignment is $O(L)$, where $L$ is the number of leaves, assuming constant-time modulo and list append operations.
- **Memory complexity:** $O(L)$ to store the assignment map.
- **Measured performance:** Not given in the sources.
- **Scaling:** Scales with the number of leaves and nodes, but load imbalance may degrade efficiency as $N$ increases or as leaf size variance grows.
- **Strengths:** Static assignment reduces I/O overhead during viewpoint animation; no need to re-traverse or re-assign based on camera position [S1, unofficial].
- **Limitations:** Poor load balancing due to varying leaf sizes; high communication overhead during compositing due to non-contiguous leaf distribution [S1, unofficial].
- **When to use:** When viewpoint animation is frequent and I/O reduction is prioritized over perfect load balance.
- **When not:** When leaf sizes are highly variable and load balance is critical, or when communication bandwidth is severely limited.

## Background
Origin: Developed in the context of parallel volume visualization of AMR data, as described in research by Okreylos et al. [S1, unofficial]. The method is part of a suite of distribution strategies investigated for parallel renderers handling hierarchical AMR data structures.
