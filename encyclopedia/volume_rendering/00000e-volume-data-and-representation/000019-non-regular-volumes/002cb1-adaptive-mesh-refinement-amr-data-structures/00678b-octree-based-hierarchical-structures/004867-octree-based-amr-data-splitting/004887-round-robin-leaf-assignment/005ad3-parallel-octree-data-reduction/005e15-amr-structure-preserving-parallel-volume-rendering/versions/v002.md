# AMR Structure-Preserving Parallel Volume Rendering


## Overview
A parallel volume rendering method that preserves the Adaptive Mesh Refinement (AMR) block structure, distributing leaves of the octree among processors and using raycasting with adaptive sampling [S1, unofficial]. It sets itself apart from its parent method [Parallel Octree Data Reduction](16751-parallel-octree-data-reduction.md) by explicitly maintaining the hierarchical block topology for rendering rather than reducing data for interactive preview, and from its child [VisIt Data Parallel Volume Rendering](17553-visit-data-parallel-volume-rendering.md) by not treating patches as atomic units with ghost-cell filtering, but rather distributing individual octree leaves [S1, unofficial].

## How it works
**Inputs:** AMR dataset organized as a hierarchy of grids; number of processors $P$.
**Outputs:** Composite volume-rendered image.

**Data Structures:**
The AMR hierarchy is organized as a quadtree (2D) or octree (3D) [S1, unofficial].
*   **Inner Nodes:** Indicate regions requiring further refinement.
*   **Leaf Nodes:** Specify a grid block with resolution determined by the current hierarchy level.

**Steps:**
1.  **Tree Construction:** Organize the input AMR grids into the quadtree/octree structure. Inner nodes represent refinement regions; leaf nodes represent the finest available grid blocks at that location [S1, unofficial].
2.  **Load Balancing:** Distribute individual blocks (leaf nodes of the octree) among the $P$ processors in a round-robin fashion to achieve static load balancing [S1, unofficial].
3.  **Communication Buffering:** Render individual blocks using raycasting. The block structure generates many small ray-segments. These segments are buffered into larger messages to decrease communication overhead [S1, unofficial].
4.  **Rendering:** Perform raycasting on each block. Two sampling schemes are available:
    *   **Simple Approach:** Uses a fixed, constant sample distance for all blocks [S1, unofficial].
    *   **Adaptive Approach:** Decreases the sample distance in finer resolution blocks to maintain visual fidelity proportional to the data resolution [S1, unofficial].

**Pseudocode:**
```python
def amr_structure_preserving_rendering(amr_hierarchy, num_processors):
    """
    Renders AMR data preserving block structure.
    amr_hierarchy: Object containing the octree/quadtree structure.
    num_processors: Integer P.
    """
    # Step 1: Identify leaves
    leaves = amr_hierarchy.get_leaves()
    
    # Step 2: Round-robin distribution
    # Assign each leaf to a processor index 0..P-1
    processor_assignments = []
    for i, leaf in enumerate(leaves):
        proc_id = i % num_processors
        processor_assignments.append((proc_id, leaf))
    
    # Group leaves by processor
    processor_blocks = {}
    for proc_id, leaf in processor_assignments:
        if proc_id not in processor_blocks:
            processor_blocks[proc_id] = []
        processor_blocks[proc_id].append(leaf)
    
    # Step 3 & 4: Render and Buffer
    # Each processor renders its assigned blocks
    # Raycasting is performed on each block
    # Small ray-segments are buffered into larger messages
    
    rendered_images = {}
    for proc_id, blocks in processor_blocks.items():
        local_image = empty_image()
        for block in blocks:
            # Determine sampling scheme
            # If adaptive: sample_distance decreases as block resolution increases
            # If simple: sample_distance is constant
            sample_distance = get_sample_distance(block, scheme='adaptive')
            
            # Raycast the block
            block_image = raycast_block(block, sample_distance)
            
            # Compose into local image
            local_image = compose(local_image, block_image)
        
        rendered_images[proc_id] = local_image
    
    # Composite results from all processors
    final_image = composite_all(rendered_images)
    return final_image
```

**Parameters:**
*   **Sampling Scheme:** 'simple' or 'adaptive' [S1, unofficial].
*   **Sample Distance:** Constant for simple; variable based on resolution for adaptive [S1, unofficial].

**Edge Cases:**
*   **Communication Overhead:** The block structure can lead to many small ray-segments. Buffering is required to mitigate overhead [S1, unofficial].
*   **Load Imbalance:** Static round-robin distribution assumes uniform block sizes or computational cost. Uneven block sizes may lead to imbalance [S1, unofficial].

## Subtopics

### [VisIt Data Parallel Volume Rendering](17553-visit-data-parallel-volume-rendering.md)
A scheme in VisIt that treats AMR patches as atomic units and ignores ghost cells for correct sampling at boundaries. Choose this when using VisIt and needing explicit ghost-cell handling; otherwise, use the base method for general octree leaf distribution.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of leaf blocks and rays cast. Communication overhead is reduced by buffering small ray-segments into larger messages [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of leaf blocks distributed across processors. Each processor stores only its assigned blocks [S1, unofficial].
*   **Strengths:** Preserves AMR structure; static load balancing via round-robin; reduced communication overhead via buffering [S1, unofficial].
*   **Limitations:** Static load balancing may not adapt to dynamic scene complexity; small ray-segments require careful buffering management [S1, unofficial].
*   **When to Use:** Interactive visualization of large AMR datasets where preserving block structure is beneficial and static load balancing is sufficient [S1, unofficial].
*   **When Not to Use:** When dynamic load balancing is required or when ghost-cell handling is critical for boundary accuracy (use [VisIt Data Parallel Volume Rendering](17553-visit-data-parallel-volume-rendering.md) instead) [S1, unofficial].

## Background
Described by Ma in 1999 using the PARAMESH framework [S1, unofficial]. Ma compared two approaches: resampling to a uniform grid (binary-swap composition) and preserving the AMR structure (the method described here) [S1, unofficial]. The structure-preserving method was developed to avoid the cost of resampling and to leverage the hierarchical nature of AMR data directly [S1, unofficial].
