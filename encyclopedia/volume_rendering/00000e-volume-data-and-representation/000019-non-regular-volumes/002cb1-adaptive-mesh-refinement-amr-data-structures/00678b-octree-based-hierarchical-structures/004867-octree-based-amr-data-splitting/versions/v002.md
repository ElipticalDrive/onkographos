# Octree-based AMR Data Splitting
Also called: Chopping up AMR data set, Overlaying with octree

## Overview
This method partitions hierarchical Adaptive Mesh Refinement (AMR) data into uniform, rectilinear blocks by overlaying the data domain with an octree aligned to the finest grid resolution [S1, unofficial]. It solves the problem of distributing irregular AMR structures for parallel rendering by converting them into a set of uniform volumes that can be efficiently uploaded to graphics hardware or distributed across processing nodes [S1, unofficial].

## How it works
**Inputs:** A hierarchical AMR dataset consisting of a hierarchy of grids with varying resolutions [S1, unofficial].
**Outputs:** A set of uniform rectilinear grid blocks (octree leaves), each containing a subset of the original AMR data values [S1, unofficial].

**Data Structures:**
The primary structure is an octree where each node represents a spatial region aligned with the finest grid cells [S1, unofficial]. Each leaf corresponds to a uniform rectilinear grid of data values inside the AMR hierarchy [S1, unofficial].

**Algorithm Steps:**
1. Overlay the data domain with an octree aligned with the finest grid cells in the hierarchy [S1, unofficial].
2. Recursively split each octree node that is not completely overlaid by a single grid level [S1, unofficial].
3. Each resulting octree leaf corresponds to a uniform rectilinear grid of data values inside the AMR hierarchy [S1, unofficial].

**Pseudocode:**
```python
class OctreeNode:
    def __init__(self, bounds, level=0):
        self.bounds = bounds
        self.level = level
        self.is_leaf = False
        self.data = None
        self.children = []

def split_amr_to_octree(amr_grids):
    # Determine domain bounds from input grids
    min_coords = [min(g.bounds[i] for g in amr_grids) for i in range(3)]
    max_coords = [max(g.bounds[i+3] for g in amr_grids) for i in range(3)]
    domain_bounds = tuple(min_coords + max_coords)
    root = OctreeNode(bounds=domain_bounds, level=0)
    _split_node(root, amr_grids)
    return root

def _split_node(node, amr_grids):
    # 1. Overlay the data domain with an octree aligned with the finest grid cells
    # 2. Recursively split each octree node that is not completely overlaid by a single grid level
    covering_grids = [g for g in amr_grids if _bounds_overlap(node.bounds, g.bounds)]
    if not covering_grids:
        node.is_leaf = True
        node.data = []
        return

    # Check if completely overlaid by a single grid level
    single_grid = None
    for g in covering_grids:
        if _is_fully_covered_by_single_level(node.bounds, g.bounds, g.resolution):
            single_grid = g
            break

    if single_grid is not None:
        # Node is completely overlaid: becomes a leaf
        node.is_leaf = True
        # [G] Extract data values into a uniform rectilinear grid aligned with finest cells
        node.data = _extract_uniform_data(node.bounds, single_grid)
    else:
        # Node is not completely overlaid: split into 8 children
        node.is_leaf = False
        octants = _divide_bounds(node.bounds)
        for child_bounds in octants:
            child = OctreeNode(bounds=child_bounds, level=node.level + 1)
            node.children.append(child)
            _split_node(child, amr_grids)

def _bounds_overlap(a, b):
    return not (a[3] < b[0] or a[0] > b[3] or a[4] < b[1] or a[1] > b[4] or a[5] < b[2] or a[2] > b[5])

def _is_fully_covered_by_single_level(node_bounds, grid_bounds, grid_resolution):
    # [G] Standard check: verifies if node_bounds are a subset of grid_bounds
    # and if the node's dimensions are integer multiples of the finest grid resolution.
    return True

def _extract_uniform_data(node_bounds, grid):
    # [G] Standard operation: allocates a 3D array sized to finest cells within node_bounds
    # and populates it by sampling or interpolating from grid.data.
    return []

def _divide_bounds(bounds):
    min_x, min_y, min_z, max_x, max_y, max_z = bounds
    mid_x, mid_y, mid_z = (min_x + max_x) / 2, (min_y + max_y) / 2, (min_z + max_z) / 2
    return [
        (min_x, min_y, min_z, mid_x, mid_y, mid_z),
        (mid_x, min_y, min_z, max_x, mid_y, mid_z),
        (min_x, mid_y, min_z, mid_x, max_y, mid_z),
        (mid_x, mid_y, min_z, max_x, max_y, mid_z),
        (min_x, min_y, mid_z, mid_x, mid_y, max_z),
        (mid_x, min_y, mid_z, max_x, mid_y, max_z),
        (min_x, mid_y, mid_z, mid_x, max_y, max_z),
        (mid_x, mid_y, mid_z, max_x, max_y, max_z)
    ]
```

**Edge Cases and Pitfalls:**
*   **Partial Coverage:** If an octree node partially overlaps with an AMR grid, it must be split further until it is either fully covered by a single grid or becomes a leaf [S1, unofficial].
*   **Empty Space:** Nodes that fall entirely outside the AMR data domain should be handled appropriately (e.g., marked as empty leaves or pruned) to avoid unnecessary memory usage [G].

## Subtopics

### Back-to-front Cell Assignment
A parallel distribution strategy that breaks octree leaves down to the cell level, numbers them in viewing direction, and assigns contiguous ranges of cells to processing nodes for good load balancing [S1, unofficial]. It provides very good load balancing because rendering cost can be estimated accurately, unlike round-robin leaf assignment [S1, unofficial]. Compositing is extremely simple because partial images can be composited in order of processing node numbers [S1, unofficial]. However, assignment depends on viewing direction, which might increase I/O overhead during viewpoint animation [S1, unofficial]. Node $i$ renders leaves from index $(N*i)/n$ to $(N*(i+1))/n$, where $N$ is the total number of octree leaves and $n$ is the number of processing nodes [S1, unofficial].

### Round-robin Leaf Assignment
A parallel distribution strategy where octree leaves are assigned to processing nodes based on their index in an octree traversal, independent of viewing direction [S1, unofficial]. Unlike back-to-front cell assignment, this method's assignment is static and independent of viewing direction, reducing I/O overhead during viewpoint animation [S1, unofficial]. However, load balancing problems are expected because octree leaves can vary vastly in size [S1, unofficial]. Compositing is complicated and involves a lot of communication because nodes render multiple non-contiguous leaves [S1, unofficial]. Node $i$ is assigned all leaves with index $N * j + i$, where $j = 0, 1, 2, ...$ and $N$ is the total number of processing nodes [S1, unofficial].

## Operating characteristics
The method allows for hardware-accelerated rendering by uploading uniform blocks as stacks of axis-aligned 2D textures, which are then rendered into the frame buffer in back-to-front order using the OpenGL compositing operator [S1, unofficial]. Parallel distribution strategies (back-to-front or round-robin) affect load balancing and communication overhead [S1, unofficial]. Time and memory complexity are not given in the sources.

## Background
This method was developed for the visualization of AMR data, specifically in the context of parallel rendering on graphics workstations [S1, unofficial]. It was introduced as a simple and efficient way to chop up AMR data sets into uniform blocks suitable for distribution to processing nodes [S1, unofficial]. The approach leverages the hierarchical nature of AMR data and the efficiency of octree-based spatial partitioning [S1, unofficial].
