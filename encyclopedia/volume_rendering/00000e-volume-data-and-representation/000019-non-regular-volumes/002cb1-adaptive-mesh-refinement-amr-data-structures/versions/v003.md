# Adaptive Mesh Refinement (AMR) Data Structures
## Overview
Adaptive Mesh Refinement (AMR) data structures organize volumetric data with non-uniform resolution to efficiently store and render sparse or high-gradient fields [S1][S2, unofficial]. This family solves the problem of managing hierarchical grids where refinement levels vary spatially, enabling efficient traversal and rendering without processing uniform high-resolution data everywhere [S1][S2, unofficial]. It sets itself apart from sibling methods like [Tetrahedral Regularization](834-tetrahedral-regularization.md) and [Bezier Tetrahedra Evaluation](1422-bezier-tetrahedra-evaluation.md) by focusing on the hierarchical organization of the data (typically box-based or tetrahedral forests) rather than the specific geometric interpolation or basis function evaluation techniques used during the rendering pass [S1][S2, unofficial].

## Shared principles
This family inherits the unstructured topology, adaptive resolution, basis function evaluation, ray-element intersection, and continuity requirements defined in [Non-regular volumes](9-non-regular-volumes.md) [G].

## Subtopics

### [TET-AMR Data Structure](1094-tet-amr-data-structure.md)
A forest of tetrahedral refinement trees designed to store volumetric data for elements across all refinement levels, including child counts, direct face neighbors, and associated scalars. It solves the problem of efficiently identifying which refinement trees to sample during volume rendering by storing a coarse mesh alongside the refined data, enabling the construction of a bounding volume hierarchy (BVH) over the coarse elements. It sets itself apart from general AMR structures by explicitly storing direct face neighbors and child counts within the element data to facilitate fast traversal and neighbor lookups without runtime index resolution. Choose it when tetrahedral mesh traversal and neighbor lookups are prioritized over box-based structures.

### [Scene Geometry and Scalar Range Initialization](1679-scene-geometry-and-scalar-range-initialization.md)
Constructs the scene geometry and scalar ranges for volume rendering by aggregating AMR box data, computing global bounding boxes via MPI, applying normalization scaling, and determining scalar value ranges including optional logarithmic scaling. It differs from sibling methods by explicitly handling the aggregation of distributed AMR level data into a unified scene representation with normalized coordinates and robust scalar range detection, whereas [Exact AMR Rendering](4399-exact-amr-rendering.md) focuses on the ray-casting traversal and [TET-AMR Data Structure](1094-tet-amr-data-structure.md) focuses on tetrahedral mesh construction. Choose it when initializing distributed AMR scenes with normalized coordinates and scalar transforms.

### [Exact AMR Rendering](4399-exact-amr-rendering.md)
Exact AMR Rendering treats AMR gas cells as piecewise-constant geometric cubes rather than smoothing them as SPH particles. It solves the problem of geometric fidelity in synthetic observations by ensuring mass conservation to round-off and eliminating the bias and smoothing inherent in kernel-based SPH rendering. It differs from its sibling [Approximate perspective projection of AMR cells](4400-approximate-perspective-projection-of-amr-cells.md) by avoiding orthographic approximations for large or perspective-distorted cells, ensuring geometric fidelity where perspective effects are significant. Choose it when exact mass conservation and geometric fidelity are required over particle-based smoothing.

### [AMR Basis Reconstruction Filter](5581-amr-basis-reconstruction-filter.md)
A method to provide a continuous interpolant across AMR level boundaries using basis functions, allowing smooth sample reconstruction without costly cell location kernels. The non-truncated support of the basis function results in larger support overlap between cells from neighboring blocks. Choose it when continuity across level boundaries is critical and computational cost of support overlap is acceptable.

### AMR with 3DTM
A technique rendering AMR data using 3DTM, partitioning the volume into axis-aligned bricks of the same level of resolution [S1]. It extends the AMR tree-based 3DTM to render large and sparse data sets [S1]. Choose it when rendering large, sparse AMR datasets using brick-based traversal.

### Subdivision for Cell-Centered AMR Boundaries
A challenge in cell-centered AMR where stitching across boundaries requires unstructured mesh geometry because dual grids do not align across levels [S2, unofficial]. This approach (subdividing into tets/hexes) is contrasted with the paper's basis function method which avoids subdivision [S2, unofficial]. Choose it when unstructured mesh subdivision is preferred over basis function reconstruction for boundary stitching.

### Nearest-Neighbor Lookup
The simplest reconstruction strategy for AMR data, returning the scalar value of the leaf cell containing the query point [S2, unofficial]. It is fast and simple but not continuous, even within same-level regions [S2, unofficial]. Choose it when performance is prioritized over continuity and artifacts are tolerable.

## Background
Adaptive Mesh Refinement (AMR) originated in computational fluid dynamics to efficiently resolve multi-scale phenomena [S2, unofficial]. Early visualization approaches relied on uniform grids or simple hierarchical box structures [G]. The integration of AMR with ray tracing evolved to handle hierarchical data traversal, utilizing sparse octrees for traversal [S1] and extending tree-based techniques like 3DTM to handle large, sparse AMR datasets [S1]. Maintaining continuity across level boundaries led to various interpolation strategies, including basis function reconstruction and unstructured element stitching [S2, unofficial].
