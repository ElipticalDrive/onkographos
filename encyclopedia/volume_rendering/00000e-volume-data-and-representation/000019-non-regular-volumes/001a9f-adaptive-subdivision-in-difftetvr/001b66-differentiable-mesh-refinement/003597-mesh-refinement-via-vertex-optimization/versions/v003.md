# Mesh Refinement via Vertex Optimization

Also called: Mesh Optimization

## Overview
Mesh Refinement via Vertex Optimization adjusts the vertex positions and colors of a template mesh to match input photographs, using multi-layer splatting for stability [S1]. It solves the problem of fitting a parametric surface to multi-view imagery where single-layer splatting is unstable due to the flexibility of the optimization and the sensitivity of image derivatives [S1]. It differs from pose estimation because each vertex depends on fewer pixels, making derivative errors more significant, and from grid-based methods by operating directly on mesh topology rather than occupancy fields [S1][S2, unofficial].

## How it works
**Inputs:**
- A template mesh with initial vertex positions $V_0$ and uniform gray colors.
- Input photographs from $N$ camera views (typically 3) [S1].
- A background rectangle placed behind the subject to reveal multiple geometry layers [S1].

**Outputs:**
- Optimized vertex positions $V$ and colors $C$.

**Data Structures:**
- Vertex parameters: $v = \text{torch.nn.Parameter}(v_0.\text{clone}())$ [S2, unofficial].
- Face batch: A subset of mesh faces for efficient processing.

**Steps:**
1. **Initialization**: Roughly align the hand template mesh to the input images and assign a uniform gray color [S1]. Initialize vertex parameters $v$ from the mesh vertices [S2, unofficial].
2. **Optimizer Setup**: Initialize the optimizer. Sources suggest Adam [S1] or RMSprop with learning rate $1e-5$ [S2, unofficial].
3. **Batching**: Create a DataLoader for faces with batch size `refine_max_faces` (default 10000) and `shuffle=True` [S2, unofficial].
4. **Optimization Loop**: Iterate for `refinement_step` iterations (default 0) [S2, unofficial].
   - Sample a batch of faces.
   - Detach latent codes $c$ to prevent graph retention: $c = c.\text{detach}()$ [S2, unofficial].
   - Render the mesh using multi-layer splatting to match input photographs [S1].
   - Compute loss against input images.
   - Apply regularization using As-Rigid-As-Possible (ARAP) deformation energy [S1].
   - Update vertex positions using the optimizer.

**Formulas:**
- ARAP Regularization: Minimizes the deviation from rigid transformations of local neighborhoods [S1].
- Multi-layer Splatting: Renders multiple layers of geometry to handle transparency and occlusion, crucial for convergence [S1].

**Parameters:**
- `refinement_step`: Number of optimization iterations. Default: 0 [S2, unofficial].
- `refine_max_faces`: Max number of faces used as batch size. Default: 10000 [S2, unofficial].
- Learning Rate: $1e-5$ (RMSprop) [S2, unofficial].

**Edge Cases and Pitfalls:**
- Single-layer splatting is unstable at higher learning rates and leads to slower convergence [S1].
- Errors in image derivatives are more significant because each vertex depends on fewer pixels compared to pose estimation [S1].

## Subtopics

### [TetWeave Late-Stage Optimization](2583-tetweave-late-stage-optimization.md)
TetWeave Late-Stage Optimization is a differentiable refinement phase that adjusts the Signed Distance Field (SDF) values, point positions, and spherical harmonics (SH) coefficients of an existing tetrahedral mesh without modifying its topological structure. It distinguishes itself from earlier stages by decoupling geometry optimization from grid updates, relying instead on multi-view rendering losses (mask, depth, normal) and SDF regularization to polish the reconstruction. This method builds on [Mesh Refinement via Vertex Optimization](989-mesh-refinement-via-vertex-optimization.md) by operating on the final mesh representation derived from the optimized points and SDF.

## Operating characteristics
- **Time Complexity**: Not given in the sources.
- **Memory Complexity**: Not given in the sources.
- **Measured Performance**: Total runtimes of approximately 4 seconds to convergence, similar between Adam and LM (Levenberg-Marquardt) despite LM's extra cost [S1].
- **Scaling**: Not given in the sources.
- **Strengths**: Robust convergence with multi-layer splatting; handles complex geometry via template deformation [S1].
- **Limitations**: Single-layer splatting is unstable; sensitive to image derivative errors due to low pixel-to-vertex ratio [S1].
- **When to use**: When fitting a parametric mesh to multi-view images with stable convergence requirements.
- **When not**: When single-layer rendering is sufficient or when computational resources are extremely limited.

## Background
Originated in the context of differentiable surface rendering, specifically for optimizing parametric surfaces like hand templates [S1]. The method leverages ARAP deformation energy for regularization [S1]. It is used in applications requiring high-fidelity mesh reconstruction from photographs, such as hand modeling [S1].
