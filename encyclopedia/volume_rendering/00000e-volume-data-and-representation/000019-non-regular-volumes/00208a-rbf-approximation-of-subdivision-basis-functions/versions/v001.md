# RBF Approximation of Subdivision Basis Functions

Also called: RBF-based Subdivision, RBF-based splatting for subdivision volumes, RBF-driven Subdivision Volume Visualization, Subdivision Volume Splatting, Volumetric Subdivision (VS) with RBF approximation

## Overview
This method replaces the computationally expensive recursive subdivision of volumetric meshes with the efficient evaluation of Radial Basis Functions (RBFs) that mimic the subdivision algorithm's behavior, enabling interactive GPU-based volume splatting [S1, unofficial]. It solves the problem of high memory and rendering costs associated with explicit tessellation of complex polyhedra (hexahedra, octahedra) into tetrahedra, which introduces interpolation errors and exponential growth in cell count [S1, unofficial]. Unlike sibling methods like [Adaptive Subdivision in DiffTetVR](807-adaptive-subdivision-in-difftetvr.md) which rely on explicit mesh refinement, this approach approximates the continuous volumetric basis function using radially symmetric kernels, avoiding explicit connectivity storage and allowing adaptive refinement only in undersampled regions [S1, unofficial].

## How it works
**Inputs:**
- A control mesh defining the initial volumetric domain (e.g., a 7x7x7 grid of vertices).
- A subdivision scheme (e.g., MCQ) defining the refinement rules [S1, unofficial].
- Original data values assigned to the control vertices [S1, unofficial].

**Outputs:**
- A rendered volume image using GPU splatting.
- A set of RBF parameters (kernel type, radius, coefficients) approximating the subdivision basis function [S1, unofficial].

**Data Structures:**
- **Control Mesh:** A 3D grid of vertices. For fitting, a 7x7x7 mesh is used where the center vertex has weight 1.0 and all others 0.0 [S1, unofficial].
- **Discretized Basis Function:** A 3D volume of point samples (e.g., 19^3 resolution) generated by subdividing the control mesh to a limit level (practically level 5) [S1, unofficial].
- **RBF Kernel Parameters:** Type (Gaussian, BC-spline, Cardinal), radius $r$, and coefficients (e.g., $\sigma$, $B$, $C$, $a$) [S1, unofficial].

**Steps:**

1.  **Identify Subdivision Rules:** Determine the weighted sums of vertices for the chosen subdivision scheme (e.g., MCQ) to understand the basis function behavior [S1, unofficial].
2.  **Generate Discretized Basis Function:**
    - Create a control mesh of size $7 \times 7 \times 7$ with unit interval spacing.
    - Assign a value of 1.0 to the center vertex and 0.0 to all other vertices [S1, unofficial].
    - Apply the subdivision rules recursively up to level 5.
    - Sample the resulting volume at a resolution of $19^3$ to obtain discrete point samples of the continuous basis function [S1, unofficial].
3.  **Fit RBF Kernel:**
    - Select a radially symmetric kernel type: Gaussian, Cubic BC-spline, or Cubic Cardinal spline [S1, unofficial].
    - Perform least-squares fitting to match the kernel to the discretized basis function samples over the spatial domain $[-3, 3] \times [-3, 3] \times [-3, 3]$ [S1, unofficial].
    - Test radii $r \in \{1, 2, 3\}$ for spline filters. For Gaussian, radius is effectively infinite/large [S1, unofficial].
    - Select the kernel with the lowest Mean Squared Error (MSE) [S1, unofficial].
4.  **Render with Adaptive RBF Splatting:**
    - For each cell (hexahedron) in the coarse control mesh:
        - Check if the cell's image-plane projection covers many pixels or if the region is undersampled [S1, unofficial].
        - If refinement is needed, generate new sample points within the cell using trilinear interpolation until the maximum inter-sample distance is approximately 1.5 units (where 1 unit is the voxel length) [S1, unofficial].
        - For each sample point, calculate its density value by centering the fitted RBF reconstruction kernel over the sample and taking a weighted sum of the original data values (control vertex weights) within the kernel's extent [S1, unofficial].
        - The extent of the kernel is set to include all vertices of the cell containing the sample point [S1, unofficial].
        - Weights are determined by the distance from the sample point to the control vertices, using the fitted kernel function [S1, unofficial].
    - Render the resulting point cloud using an image-aligned RBF-centric rasterization pipeline (inverse method) on the GPU [S1, unofficial].

**Formulas:**

**Gaussian Distribution:**
$$g(x) = \frac{1}{\sigma\sqrt{2\pi}} e^{-(x-\mu)^2/(2\sigma^2)}$$
Where $\mu$ is the mean and $\sigma$ is the standard deviation [S1, unofficial].

**Cubic BC-spline Filter:**
$$h_{BC}(x) = \begin{cases} (2 - \frac{3}{2}B - C)|x|^3 + (-3 + 2B + C)|x|^2 + (1 - \frac{1}{3}B) & \text{if } |x| < r \\ (-\frac{1}{6}B - C)|x|^3 + (B + 5C)|x|^2 + (-2B - 8C)|x| + (\frac{4}{3}B + 4C) & \text{if } r \leq |x| < 2r \\ 0 & \text{otherwise} \end{cases}$$
Where $B$ and $C$ are parameters and $r$ is the radius [S1, unofficial].

**Cubic Cardinal Spline Filter:**
$$h_a(x) = \begin{cases} (a+2)|x|^3 - (a+3)|x|^2 + 1 & \text{if } |x| < r \\ a|x|^3 - 5a|x|^2 + 8a|x| - 4a & \text{if } r \leq |x| < 2r \\ 0 & \text{otherwise} \end{cases}$$
Where $a$ is the parameter and $r$ is the radius [S1, unofficial].

**Parameters:**
- **Subdivision Level $n$:** Number of recursive steps. In MCQ, cell count grows as $8^n$ [S1, unofficial].
- **MCQ Scheme:** Interpolatory subdivision scheme, reproduces cubic polynomials for regular topology, $C^1$ continuous for irregular [S1, unofficial].
- **Gaussian Mean $\mu$:** Fixed at 0 [S1, unofficial].
- **Gaussian Standard Deviation $\sigma$:** 0.43 (determined via Bisection Method) [S1, unofficial].
- **Spatial Domain:** $[-3, 3] \times [-3, 3] \times [-3, 3]$ for 7x7x7 control mesh [S1, unofficial].
- **Inter-sample Distance:** Refine until max distance is ~1.5 units [S1, unofficial].
- **Kernel Extent:** Sufficiently large to include all vertices of the containing cell [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Approximation Error:** Highest in regions outside a radius of 1.0 unit, where the true basis function has square-like density distributions due to tensor-product derivation, which radially symmetric kernels cannot perfectly capture [S1, unofficial].
- **Ray Tracing Unsuitability:** Ray tracing is unsatisfactory for subdivision volumes because the irregular spatial distribution of voxels interferes with fundamental computations like trilinear interpolation [S1, unofficial].
- **Tessellation Errors:** Tessellating complex polyhedra into tetrahedra introduces linear interpolation errors; minimizing these requires further subdivision, increasing cell count [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Reduced compared to explicit subdivision. Avoids traversing cell structures or constructing next-level subdivisions [S1, unofficial].
- **Memory Complexity:** Reduced. Does not store connectivity information for exponentially growing cell decompositions [S1, unofficial].
- **Measured Performance:** Rendering RMSE ranges from 0.003 to 0.011 compared to explicit subdivision results [S1, unofficial]. Best fit error for Gaussian kernel: MSE 0.000041, RMSE 0.006395, MAE 0.002079 [S1, unofficial].
- **Scaling:** Adaptive refinement avoids oversampling. Global subdivision to achieve 5x5x5 resolution requires level 3 (8^3 vertices), wasting 448 superfluous samples per hexahedron compared to the needed 4^3 samples [S1, unofficial].
- **Strengths:** Interactive GPU rendering, low memory footprint, adaptive refinement.
- **Limitations:** Approximation error in regions far from center (square-like distributions), requires fitting process for each subdivision scheme.

## Background
- **Origin:** Developed by researchers at Stony Brook University, presented at EuroVis 2007 [S1, unofficial].
- **History:** Volumetric Subdivision (VS) enables volumetric sculpting and realistic deformations ("virtual clay"). Previous methods like Projected Tetrahedra (PT) required depth-sorting and tessellation, which were computationally expensive [S1, unofficial]. The MCQ scheme [MCQ04] was used for proof-of-concept experiments [S1, unofficial].
- **Usage:** Visualization of procedural subdivision volume schemes, particularly those with irregular topologies where octrees are not suitable [S1, unofficial].
