# Homogeneity-Based KD-Tree Construction

Also called: AMR Mesh Construction via Homogeneity-Based KD-Tree

## Overview
This method constructs a hierarchical KD-tree for Adaptive Mesh Refinement (AMR) datasets to enable efficient ray traversal and rendering without replicating cells into a voxel grid [S1]. It solves the memory waste and performance penalties of homogeneous page tables by grouping same-level cells into axis-aligned patches [S1].

## How it works
**Inputs:** An AMR dataset consisting of cells with associated refinement levels and spatial positions [S1].
**Outputs:** A KD-tree where leaf nodes contain homogeneous patches (axis-aligned boxes of same-level cells) and internal nodes contain split information [S1].

**Data Structures:**
*   **Box:** An axis-aligned bounding box defined by minimum and maximum coordinates, containing a list of cells.
*   **Node:** Represents a region in the KD-tree.
    *   `is_leaf`: Boolean flag indicating if the node is a leaf.
    *   `data`: List of cells if the node is a leaf.
    *   `children`: Tuple of two child nodes if the node is internal.

**Parameters:**
*   `homogeneity(box)`: A function returning the ratio of homogeneity of cell levels inside the box; returns $1.0$ if all cells share the same level, $0.0$ if all have different levels [S1].

**Algorithm:**
The construction is recursive, starting from the root box containing the entire dataset.

1.  **Check Homogeneity:** Calculate $H = \text{homogeneity}(b)$ for the current box $b$.
2.  **Base Case (Leaf):** If $H == 1.0$, the box is homogeneous.
    *   Mark node $n$ as a leaf.
    *   Copy all cells from box $b$ to node $n$.
    *   Return.
3.  **Recursive Step (Split):** If $H < 1.0$:
    *   Initialize `best_score` to $0$ and `best_cut` to `None`.
    *   For each axis direction $d \in \{x, y, z\}$:
        *   For each possible cut plane $p$ in direction $d$ (typically at cell boundaries):
            *   Split box $b$ by $p$ into $b_{left}$ and $b_{right}$.
            *   Calculate `current_score` = $\text{homogeneity}(b_{left}) + \text{homogeneity}(b_{right})$ [S1].
            *   If `current_score` > `best_score`:
                *   `best_score` = `current_score`
                *   `best_cut` = $p$
    *   Split box $b$ using `best_cut` to create `child_box_1` and `child_box_2`.
    *   Create two child nodes `child_node_1` and `child_node_2`.
    *   Set $n.children = (\text{child\_node\_1}, \text{child\_node\_2})$.
    *   Recursively call `build_mesh(child_box_1, child_node_1)`.
    *   Recursively call `build_mesh(child_box_2, child_node_2)`.

**Pseudocode:**

```python
class Node:
    def __init__(self):
        self.is_leaf = False
        self.data = None
        self.children = None

class Box:
    def __init__(self, min_coords, max_coords, cells):
        self.min = min_coords
        self.max = max_coords
        self.cells = cells

    def split(self, cut_plane, axis):
        # Standard AABB split: returns two new boxes
        left_min = list(self.min)
        left_max = list(self.max)
        right_min = list(self.min)
        right_max = list(self.max)
        left_max[axis] = cut_plane
        right_min[axis] = cut_plane
        left_cells = [c for c in self.cells if c.center[axis] <= cut_plane]
        right_cells = [c for c in self.cells if c.center[axis] > cut_plane]
        return Box(left_min, left_max, left_cells), Box(right_min, right_max, right_cells)

def homogeneity(box):
    """Returns ratio of homogeneity of cell levels inside the box.
    Returns 1.0 if all cells share the same level, 0.0 if all have different levels [S1]."""
    if not box.cells:
        return 1.0 # Empty box is trivially homogeneous [G]
    levels = [cell.level for cell in box.cells]
    unique_levels = set(levels)
    if len(unique_levels) == 1:
        return 1.0
    # Intermediate ratios are implementation-defined; return 0.0 for non-homogeneous [G]
    return 0.0

def get_possible_cuts(box, axis):
    """Returns sorted unique cell boundary coordinates along the axis [G]."""
    cuts = set()
    for cell in box.cells:
        cuts.add(cell.min[axis])
        cuts.add(cell.max[axis])
    return sorted(c for c in cuts if c > box.min[axis] and c < box.max[axis])

def split_box(box):
    best_score = 0.0
    best_cut = None
    
    for axis in ['x', 'y', 'z']:
        cuts = get_possible_cuts(box, axis)
        for p in cuts:
            b_left, b_right = box.split(p, axis)
            # Source specifies: current score = homogeneity(b cut by p) [S1]
            score = homogeneity(b_left) + homogeneity(b_right)
            
            if score > best_score:
                best_score = score
                best_cut = (p, axis)
                
    if best_cut is None:
        return box, box # Fallback if no valid cuts exist [G]
        
    p, axis = best_cut
    b_left, b_right = box.split(p, axis)
    return b_left, b_right

def build_mesh(box, node):
    if homogeneity(box) == 1.0:
        node.is_leaf = True
        node.data = box.cells
        return
    
    node.is_leaf = False
    child_node_1 = Node()
    child_node_2 = Node()
    
    b_left, b_right = split_box(box)
    
    node.children = (child_node_1, child_node_2)
    
    build_mesh(b_left, child_node_1)
    build_mesh(b_right, child_node_2)
```

**Edge Cases and Pitfalls:**
*   **Empty Boxes:** If a box contains no cells, `homogeneity` should return $1.0$ to prevent infinite recursion or unnecessary splits [G].
*   **Cut Plane Selection:** The number of possible cut planes can be large; optimization is required to avoid $O(N^2)$ complexity in splitting [G].
*   **Traversal Order:** The resulting tree is traversed on the CPU in back-to-front order, and each patch is sent to the GPU for rendering [S1].

## Subtopics

### [AMR KD-Tree Construction](6768-amr-kd-tree-construction.md)
A general method for representing and traversing block-structured (Berger-Colella) Adaptive Mesh Refinement (AMR) data using a kd-tree structure to enable efficient query, sampling, and direct rendering. It sets itself apart by grouping same-level cells into patches and building a KD-tree based on level homogeneity, avoiding the memory waste and performance penalty associated with flat hierarchical structures.

## Operating characteristics
*   **Time Complexity:** Construction time depends on the number of cells and the cost of evaluating homogeneity for each potential split [G].
*   **Memory Complexity:** The structure stores cells only once in leaf nodes, avoiding the memory waste of voxel replication [S1].
*   **Performance:** Rendering is accelerated by sending homogeneous patches to the GPU, where traversal is trivial, while the CPU handles the hierarchical traversal [S1].
*   **Strengths:** No additional cells are added; memory efficient; leverages GPU regularity [S1].
*   **Limitations:** CPU-GPU synchronization overhead [G].

## Background
This method was presented in the context of high-quality, semi-analytical volume rendering for AMR datasets [S1]. It addresses the limitations of previous multi-octree approaches that required data reformatting or voxel replication [S1]. The technique was developed to handle hierarchical structures efficiently on the GPU by using a hybrid CPU-GPU sorting approach [S1].
