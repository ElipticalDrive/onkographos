# AMR KD-Tree Construction

Also called: kd-tree build, kd-tree builder, kd-tree structure for AMR, kd-tree traversal for AMR, median-split kd-tree

## Overview
A general method for representing and traversing block-structured (Berger-Colella) Adaptive Mesh Refinement (AMR) data using a kd-tree structure to enable efficient query, sampling, and direct rendering [S1, unofficial]. It solves the problem of efficiently locating cells in native AMR datasets without requiring data reformatting or voxel replication, which was necessary in previous multi-octree approaches [S1, unofficial]. It builds on the parent method by grouping same-level cells into patches and building a KD-tree based on level homogeneity [Parent].

## How it works
**Inputs and Outputs**
*   **Input:** A `vtkHierarchicalBoxDataSet` structure containing block-structured AMR data (bricks) across multiple levels [S1, unofficial].
*   **Output:** A kd-tree data structure where leaves cover spatial regions, enabling efficient cell location and dual-cell queries [S1, unofficial].

**Data Structures**
*   **kd-tree Nodes:** Internal nodes store a partitioning plane (axis-aligned) and pointers to left/right children [S1, unofficial].
*   **kd-tree Leaves:** Each leaf refers to a spatial region that contains exactly one brick per level it covers [S1, unofficial]. Any brick may be referenced by multiple leaves [S1, unofficial]. Leaves typically cover many cells [S1, unofficial].
*   **Block Representation:** Blocks are defined by their spatial boundaries [S1, unofficial]. The tree is built over unique block regions [S1, unofficial].

**Algorithm Steps**
1.  **Compute Global Bounds:** Calculate the world-space bounding box encompassing all bricks across all AMR levels [S1, unofficial].
2.  **Recursive Partitioning:** Define a function `BuildKDTree(current_region, blocks_in_region)`:
    a.  **Identify Boundaries:** Determine the list of all block boundaries that intersect `current_region`. Each boundary defines an axis-aligned plane [S1, unofficial].
    b.  **Select Partition Plane:** Pick one boundary plane as the partitioning plane. The current implementation uses the plane closest to the spatial median of the current region [S1, unofficial].
    c.  **Partition Blocks:** Sort the `blocks_in_region` into those overlapping the left half and those overlapping the right; blocks overlapping both go into both halves [S1, unofficial].
    d.  **Recurse:** Recurse on the left and right halves until no more boundary plane overlaps the current region, in which case a leaf is created [S1, unofficial].

**Pseudocode**
```python
from dataclasses import dataclass
from typing import List, Tuple

@dataclass
class BoundingBox:
    min: Tuple[float, float, float]
    max: Tuple[float, float, float]

@dataclass
class Plane:
    axis: int
    position: float

@dataclass
class LeafNode:
    bricks: List[object]

@dataclass
class InternalNode:
    plane: Plane
    left: object
    right: object

def build_amr_kd_tree(blocks: List[object], current_bounds: BoundingBox) -> object:
    # Step 2a: Determine list of all block boundaries intersecting current_bounds
    intersecting_planes = []
    for block in blocks:
        for axis in range(3):
            if current_bounds.min[axis] < block.bbox.min[axis] < current_bounds.max[axis]:
                intersecting_planes.append(Plane(axis, block.bbox.min[axis]))
            if current_bounds.min[axis] < block.bbox.max[axis] < current_bounds.max[axis]:
                intersecting_planes.append(Plane(axis, block.bbox.max[axis]))

    # Base case: No more boundary plane overlaps the current region
    if not intersecting_planes:
        return LeafNode(bricks=blocks)

    # Step 2b: Pick one boundary plane as partitioning plane (closest to spatial median)
    center = (
        (current_bounds.min[0] + current_bounds.max[0]) / 2.0,
        (current_bounds.min[1] + current_bounds.max[1]) / 2.0,
        (current_bounds.min[2] + current_bounds.max[2]) / 2.0
    )
    best_plane = None
    min_dist = float('inf')
    for p in intersecting_planes:
        dist = abs(p.position - center[p.axis])
        if dist < min_dist:
            min_dist = dist
            best_plane = p

    # Step 2c: Sort blocks into left and right halves; overlapping both go into both
    left_blocks = []
    right_blocks = []
    for block in blocks:
        if block.bbox.max[best_plane.axis] <= best_plane.position:
            left_blocks.append(block)
        if block.bbox.min[best_plane.axis] >= best_plane.position:
            right_blocks.append(block)

    # Step 2d: Recurse on left and right halves
    def update_bounds(bounds, plane, side):
        new_min = list(bounds.min)
        new_max = list(bounds.max)
        if side == 'left':
            new_max[plane.axis] = plane.position
        else:
            new_min[plane.axis] = plane.position
        return BoundingBox(tuple(new_min), tuple(new_max))

    left_child = build_amr_kd_tree(left_blocks, update_bounds(current_bounds, best_plane, 'left'))
    right_child = build_amr_kd_tree(right_blocks, update_bounds(current_bounds, best_plane, 'right'))

    return InternalNode(plane=best_plane, left=left_child, right=right_child)
```

**Parameters**
*   **Split Strategy:** Median-closest boundary plane [S1, unofficial].
*   **Data Structure:** `vtkHierarchicalBoxDataSet` [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Block Overlap:** In Berger-Colella AMR, blocks at different levels can overlap spatially. The algorithm explicitly handles blocks overlapping both partition halves by including them in both child lists [S1, unofficial].
*   **Precision:** Using floating-point coordinates for cell centers and widths minimizes register pressure and avoids int-to-float conversions during traversal [S1, unofficial].

## Subtopics

### Packetized Cell/Dual-Cell Query
An optimized query method implemented in ISPC that performs $N$ reconstructions and cell/dual-cell queries in parallel using a packet paradigm to traverse the KD-tree [S1, unofficial]. It is a special variant of the dual-cell query that performs all 8 corner queries in a single traversal by viewing the 8 vertex locations as the intersection of three sets of parallel planes [S1, unofficial]. It references cells by their (float) center point and levels by their (float) center width to utilize floating point units, minimize register pressure, avoid int-to-float conversions, and allow multiply-add capabilities [S1, unofficial]. It realizes recursion with a software-maintained stack [S1, unofficial]. At each kd-tree node, it checks on which side of the node's partitioning plane the respective query planes lie [S1, unofficial]. It tracks, with only 6 state variables, which of the planes are active in a given subtree [S1, unofficial]. Once a leaf is reached, the 6 active planes define which of the 8 corner values are active, and those are filled from the brick stored in the leaf [S1, unofficial]. $N$ is the vector width of the underlying CPU architecture [S1, unofficial]. These optimized kernels are an order of magnitude faster than the scalar reference code [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not explicitly given in the sources [S1, unofficial]. However, the packetized query variant is reported to be an order of magnitude faster than scalar reference code [S1, unofficial].
*   **Memory Complexity:** The structure avoids replicating voxels, storing data in the original `vtkHierarchicalBoxDataSet` format [S1, unofficial]. Any brick may be referenced by multiple leaves [S1, unofficial].
*   **Performance:** Demonstrated on a dual-Xeon workstation and a KNL node on Stampede 2 [S1, unofficial]. Performance varies with reconstruction filters and maximum AMR levels [S1, unofficial].
*   **Strengths:** Enables direct volume rendering of BC AMR data without reformatting or resampling [S1, unofficial]. Efficient cell location via packetized traversal [S1, unofficial].
*   **Limitations:** Relies on CPU ray tracing (OSPRay) [S1, unofficial]. Performance depends on vector width $N$ [S1, unofficial].
*   **When to use:** Interactive CPU-based volume rendering of block-structured AMR data where direct access to native VTK data is required [S1, unofficial].

## Background
Originated in work by Ingo Wald et al. for the OSPRay interactive CPU ray tracing framework [S1, unofficial]. It was developed to address the limitations of previous multi-octree structures that required data reformatting and copying [S1, unofficial]. The method was integrated into VTK 7.1 and ParaView 5.0, replacing the previous approach of loading AMR data into a `vtkAMR` structure and resampling it into a structured volume for rendering [S1, unofficial]. It supports Berger-Colella AMR layouts as used by ParaView’s and VitIt’s Chombo readers [S1, unofficial].
