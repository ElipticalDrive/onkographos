# Quadratic Super Splines

Also called: Pseudo C1 continuity iso-surface, RZNS04 method, Rössel et al

## Overview
Quadratic Super Splines is a technique for reconstructing iso-surfaces from volumetric data with pseudo C1 continuity along cell boundaries, producing smooth contours by partitioning cells into tetrahedra and using Bernstein-Bézier coefficients [S1]. It differs from standard linear or cubic tetrahedral methods by employing a univariate piecewise quadratic polynomial that allows for efficient ray-iso-surface intersection via quadratic equation solving, balancing smoothness against the high memory cost of storing 65 coefficients per cell [S1][S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A regular volumetric dataset (scalar field) defined on a grid of cells.
*   **Output:** A set of Bernstein-Bézier coefficients for each cell, enabling ray-tetrahedron intersection tests for iso-surface rendering.

**Data Structures**
Each cell in the volumetric grid is partitioned into 24 congruent tetrahedra [S1][S2, unofficial].
*   **Coefficients per Cell:** 65 Bernstein-Bézier coefficients are calculated per cell [S1][S2, unofficial].
    *   Distribution: 50 on the cell faces, 14 on the midpoints of the tetrahedra edges, and 1 at the center position [S1][S2, unofficial].
*   **Coefficients per Tetrahedron:** Each of the 24 tetrahedra uses 10 coefficients [S1][S2, unofficial].
    *   Layout: 4 coefficients at the vertices and 6 coefficients at the middle of the edges [S1][S2, unofficial].

**Algorithm Steps**

1.  **Coefficient Computation:**
    Compute the 65 Bernstein-Bézier coefficients for each cell using a repeated averaging pattern on 27 data values located at the centers of the surrounding cells [S1][S2, unofficial]. This process creates a quasi-interpolating spline [S1][S2, unofficial].

2.  **Ray-Tetrahedron Intersection:**
    To find the intersection of a ray with the iso-surface within a specific tetrahedron:
    a. Determine the entry distance $t_{min}$ and exit distance $t_{max}$ of the ray intersecting the tetrahedron boundaries [S1][S2, unofficial].
    b. Compute the entry point $q_1 = O + t_{min}D$ and exit point $q_2 = O + t_{max}D$ [S1][S2, unofficial].
    c. Calculate the midpoint $m = (q_1 + q_2) / 2$ [S1][S2, unofficial].
    d. Apply de Casteljau's algorithm (or direct quadratic Bézier evaluation) using the 10 Bézier coefficients of the tetrahedron to evaluate the scalar field at $q_1$, $q_2$, and $m$ [S1][S2, unofficial]. Let these values be $w_1$, $w_2$, and $w$ respectively [S1][S2, unofficial].
    e. Solve the quadratic equation for the intersection parameter $\tau$:
       $$ \alpha\tau^2 + \delta\beta\tau + \delta^2 w_1 = 0 $$
       where:
       *   $\tau \in [0, \delta]$
       *   $\delta = t_{max} - t_{min}$ denotes the length of the hit interval [S1][S2, unofficial].
       *   $\alpha = 2(w_1 + w_2 - 2w)$
       *   $\beta = 4w - 3w_1 - w_2$ [S1][S2, unofficial]
    f. The intersection point $p$ is found using the valid root $\tau$ as $p = q_1 + \tau D$ [S1][S2, unofficial].

import math

def ray_tet_intersection(o, d, v0, v1, v2, v3):
    """
    Intersects ray (origin o, direction d) with tetrahedron (v0..v3).
    Returns (t_min, t_max) along the ray, or None if no intersection.
    """
    t_min = -math.inf
    t_max = math.inf
    faces = [(v0, v1, v2), (v0, v2, v3), (v0, v3, v1), (v1, v2, v3)]
    for a, b, c in faces:
        e1 = (b[0]-a[0], b[1]-a[1], b[2]-a[2])
        e2 = (c[0]-a[0], c[1]-a[1], c[2]-a[2])
        n = (e1[1]*e2[2]-e1[2]*e2[1], e1[2]*e2[0]-e1[0]*e2[2], e1[0]*e2[1]-e1[1]*e2[0])
        nd = n[0]*d[0] + n[1]*d[1] + n[2]*d[2]
        no = n[0]*o[0] + n[1]*o[1] + n[2]*o[2]
        na = n[0]*a[0] + n[1]*a[1] + n[2]*a[2]
        if abs(nd) < 1e-12:
            if no - na > 0:
                return None
            continue
        t = (na - no) / nd
        if nd > 0:
            t_max = min(t_max, t)
        else:
            t_min = max(t_min, t)
    if t_min > t_max:
        return None
    return t_min, t_max

def barycentric_coords(p, v0, v1, v2, v3):
    """
    Computes barycentric coordinates (u, v, w, z) for point p relative to tetrahedron.
    """
    e1 = (v1[0]-v0[0], v1[1]-v0[1], v1[2]-v0[2])
    e2 = (v2[0]-v0[0], v2[1]-v0[1], v2[2]-v0[2])
    e3 = (v3[0]-v0[0], v3[1]-v0[1], v3[2]-v0[2])
    dp = (p[0]-v0[0], p[1]-v0[1], p[2]-v0[2])
    det = e1[0]*(e2[1]*e3[2]-e2[2]*e3[1]) - e1[1]*(e2[0]*e3[2]-e2[2]*e3[0]) + e1[2]*(e2[0]*e3[1]-e2[1]*e3[0])
    if abs(det) < 1e-12:
        return (0.0, 0.0, 0.0, 1.0)
    u = (dp[0]*(e2[1]*e3[2]-e2[2]*e3[1]) - e1[0]*(dp[1]*e3[2]-dp[2]*e3[1]) + e1[0]*(dp[1]*e2[2]-dp[2]*e2[1])) / det
    v = (e1[0]*(dp[1]*e3[2]-dp[2]*e3[1]) - dp[0]*(e1[1]*e3[2]-e1[2]*e3[1]) + e1[0]*(dp[1]*e2[2]-dp[2]*e2[1])) / det
    w = (e1[0]*(e2[1]*dp[2]-e2[2]*dp[1]) - e1[1]*(e2[0]*dp[2]-e2[2]*dp[0]) + dp[0]*(e1[1]*e2[2]-e1[2]*e2[1])) / det
    z = 1.0 - u - v - w
    return (u, v, w, z)

def eval_quadratic_tet(b_coeffs, v0, v1, v2, v3, p):
    """
    Evaluates quadratic Bézier tetrahedron at point p using 10 coefficients.
    b_coeffs layout: [c_v0, c_v1, c_v2, c_v3, c_e01, c_e02, c_e03, c_e12, c_e13, c_e23]
    """
    u, v, w, z = barycentric_coords(p, v0, v1, v2, v3)
    # Quadratic Bernstein basis evaluation
    val = (b_coeffs[0]*u*u + b_coeffs[1]*v*v + b_coeffs[2]*w*w + b_coeffs[3]*z*z +
           2.0*(b_coeffs[4]*u*v + b_coeffs[5]*u*w + b_coeffs[6]*u*z +
                b_coeffs[7]*v*w + b_coeffs[8]*v*z + b_coeffs[9]*w*z))
    return val

def ray_tet_intersection_iso(ray_origin, ray_direction, tet_vertices, tet_b_coeffs):
    """
    Finds intersection of ray with iso-surface inside a tetrahedron.
    """
    # 1. Intersect ray with tetrahedron to get t_min and t_max
    t_vals = ray_tet_intersection(ray_origin, ray_direction, *tet_vertices)
    if t_vals is None:
        return None
    t_min, t_max = t_vals

    # 2. Compute q1, q2, and midpoint
    q1 = (ray_origin[0] + t_min*ray_direction[0], ray_origin[1] + t_min*ray_direction[1], ray_origin[2] + t_min*ray_direction[2])
    q2 = (ray_origin[0] + t_max*ray_direction[0], ray_origin[1] + t_max*ray_direction[1], ray_origin[2] + t_max*ray_direction[2])
    midpoint = ((q1[0]+q2[0])/2.0, (q1[1]+q2[1])/2.0, (q1[2]+q2[2])/2.0)

    # 3. Evaluate scalar field at q1, q2, and midpoint using de Casteljau
    w1 = eval_quadratic_tet(tet_b_coeffs, *tet_vertices, q1)
    w2 = eval_quadratic_tet(tet_b_coeffs, *tet_vertices, q2)
    w  = eval_quadratic_tet(tet_b_coeffs, *tet_vertices, midpoint)

    # 4. Compute quadratic coefficients
    delta = t_max - t_min
    if delta < 1e-12:
        return None
    
    alpha = 2.0 * (w1 + w2 - 2.0 * w)
    beta  = 4.0 * w - 3.0 * w1 - w2

    # 5. Solve quadratic equation: alpha*tau^2 + delta*beta*tau + delta^2*w1 = 0
    A = alpha
    B = delta * beta
    C = delta * delta * w1

    if abs(A) < 1e-12:
        # Linear case: B*tau + C = 0
        if abs(B) < 1e-12:
            return None
        tau = -C / B
    else:
        discriminant = B*B - 4*A*C
        if discriminant < 0:
            return None
        sqrt_disc = math.sqrt(discriminant)
        tau1 = (-B + sqrt_disc) / (2.0 * A)
        tau2 = (-B - sqrt_disc) / (2.0 * A)
        tau = tau1 if 0 <= tau1 <= delta else (tau2 if 0 <= tau2 <= delta else None)

    if tau is None:
        return None

    # 6. Return intersection point
    return (ray_origin[0] + tau*ray_direction[0], ray_origin[1] + tau*ray_direction[1], ray_origin[2] + tau*ray_direction[2])

**Edge Cases and Pitfalls**
*   **Memory Requirements:** The method requires storing 65 coefficients per cell, leading to high memory usage [S2, unofficial]. A careful trade-off must be made between pre-processing all values and on-the-fly computation [S2, unofficial].
*   **Cache Thrashing:** A naïve ray casting algorithm stepping along a ray and testing all pierced cells causes cache thrashing due to high memory requests for voxels [S2, unofficial]. Acceleration structures (e.g., Implicit Min/Max KD-Trees) are required for efficient traversal [S2, unofficial].
*   **Boundary Cell Detection:** Determining if a cell is a boundary cell is computationally expensive in naïve approaches [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The intersection test is described as "quite efficient in terms of computational requirements" because it reduces the intersection problem to solving a quadratic equation per tetrahedron [S1]. However, the coefficient computation is non-trivial due to the 27-value averaging pattern [S1][S2, unofficial].
*   **Memory Complexity:** High. 65 coefficients per cell are stored [S1][S2, unofficial]. This is significantly more than linear or standard cubic tetrahedral representations.
*   **Performance:** Allows for rendering high-quality iso-surfaces with pseudo C1 continuity [S1]. Efficiency is enhanced when combined with SIMD-optimized packet traversal using kd-trees [S2, unofficial].
*   **Strengths:** Produces smooth iso-surface contours with pseudo C1 continuity along cell boundaries [S1][S2, unofficial]. Efficient ray-tetrahedron intersection via quadratic solving [S1].
*   **Limitations:** High memory footprint [S2, unofficial]. Requires acceleration structures to avoid cache thrashing and expensive boundary checks [S2, unofficial].

## Background
The method was introduced by Rössel et al. in [RZNS04] to exploit quadratic super splines for iso-surface reconstruction [S1]. It is cited in "Interactive Volume Rendering with Ray Tracing" (Eurographics 2006) by Marmitt, Friedrich, and Slusallek [S1]. The technique is part of the broader field of non-regular volume representations using tetrahedral meshes and Bézier evaluation.
