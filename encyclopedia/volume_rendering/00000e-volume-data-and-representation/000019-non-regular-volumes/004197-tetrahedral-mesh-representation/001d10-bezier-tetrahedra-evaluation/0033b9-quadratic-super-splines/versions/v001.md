# Quadratic Super Splines

Also called: Pseudo C1 continuity iso-surface, RZNS04 method, Rössel et al

## Overview
Quadratic Super Splines is a technique for reconstructing iso-surfaces from volumetric data with pseudo C1 continuity along cell boundaries, producing smooth contours by partitioning cells into tetrahedra and using Bernstein-Bézier coefficients [S1]. It differs from standard linear or cubic tetrahedral methods by employing a univariate piecewise quadratic polynomial that allows for efficient ray-iso-surface intersection via quadratic equation solving, balancing smoothness against the high memory cost of storing 65 coefficients per cell [S1][S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A regular volumetric dataset (scalar field) defined on a grid of cells.
*   **Output:** A set of Bernstein-Bézier coefficients for each cell, enabling ray-tetrahedron intersection tests for iso-surface rendering.

**Data Structures**
Each cell in the volumetric grid is partitioned into 24 congruent tetrahedra [S1][S2, unofficial].
*   **Coefficients per Cell:** 65 Bernstein-Bézier coefficients are calculated per cell [S1][S2, unofficial].
    *   Distribution: 50 on the cell faces, 14 on the midpoints of the tetrahedra edges, and 1 at the center position [S1][S2, unofficial].
*   **Coefficients per Tetrahedron:** Each of the 24 tetrahedra uses 10 coefficients [S1][S2, unofficial].
    *   Layout: 4 coefficients at the vertices and 6 coefficients at the middle of the edges [S1][S2, unofficial].

**Algorithm Steps**

1.  **Coefficient Computation:**
    Compute the 65 Bernstein-Bézier coefficients for each cell using a repeated averaging pattern on 27 data values located at the centers of the surrounding cells [S1][S2, unofficial]. This process creates a quasi-interpolating spline [S1][S2, unofficial].

2.  **Ray-Tetrahedron Intersection:**
    To find the intersection of a ray with the iso-surface within a specific tetrahedron:
    a. Determine the entry point $q_1$ and exit point $q_2$ of the ray intersecting the tetrahedron boundaries [S1][S2, unofficial].
    b. Calculate the midpoint $m = (q_1 + q_2) / 2$ [S1][S2, unofficial].
    c. Apply de Casteljau's algorithm using the 10 Bézier coefficients of the tetrahedron to evaluate the scalar field at $q_1$, $q_2$, and $m$ [S1][S2, unofficial]. Let these values be $w_1$, $w_2$, and $w$ respectively [S1][S2, unofficial].
    d. Solve the quadratic equation for the intersection parameter $\tau$:
       $$ \alpha\tau^2 + \delta\beta\tau + \delta^2 w_1 = 0 $$
       where:
       *   $\tau \in [0, \delta]$
       *   $\delta$ denotes the maximum in the hit interval (distance from $q_1$ to $q_2$) [S1][S2, unofficial].
       *   $\alpha = 2(w_1 + w_2 - 2w)$
       *   $\beta = 4w - 3w_1 - w_2$ [S1][S2, unofficial]
    e. The intersection point $p$ is found using the valid root $\tau$ [S1][S2, unofficial].

    return ray_origin + ray_direction * valid_tau

**Edge Cases and Pitfalls**
*   **Memory Requirements:** The method requires storing 65 coefficients per cell, leading to high memory usage [S2, unofficial]. A careful trade-off must be made between pre-processing all values and on-the-fly computation [S2, unofficial].
*   **Cache Thrashing:** A naïve ray casting algorithm stepping along a ray and testing all pierced cells causes cache thrashing due to high memory requests for voxels [S2, unofficial]. Acceleration structures (e.g., Implicit Min/Max KD-Trees) are required for efficient traversal [S2, unofficial].
*   **Boundary Cell Detection:** Determining if a cell is a boundary cell is computationally expensive in naïve approaches [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The intersection test is described as "quite efficient in terms of computational requirements" because it reduces the intersection problem to solving a quadratic equation per tetrahedron [S1]. However, the coefficient computation is non-trivial due to the 27-value averaging pattern [S1][S2, unofficial].
*   **Memory Complexity:** High. 65 coefficients per cell are stored [S1][S2, unofficial]. This is significantly more than linear or standard cubic tetrahedral representations.
*   **Performance:** Allows for rendering high-quality iso-surfaces with pseudo C1 continuity [S1]. Efficiency is enhanced when combined with SIMD-optimized packet traversal using kd-trees [S2, unofficial].
*   **Strengths:** Produces smooth iso-surface contours with pseudo C1 continuity along cell boundaries [S1][S2, unofficial]. Efficient ray-tetrahedron intersection via quadratic solving [S1].
*   **Limitations:** High memory footprint [S2, unofficial]. Requires acceleration structures to avoid cache thrashing and expensive boundary checks [S2, unofficial].

## Background
The method was introduced by Rössel et al. in [RZNS04] to exploit quadratic super splines for iso-surface reconstruction [S1]. It is cited in "Interactive Volume Rendering with Ray Tracing" (Eurographics 2006) by Marmitt, Friedrich, and Slusallek [S1]. The technique is part of the broader field of non-regular volume representations using tetrahedral meshes and Bézier evaluation.
