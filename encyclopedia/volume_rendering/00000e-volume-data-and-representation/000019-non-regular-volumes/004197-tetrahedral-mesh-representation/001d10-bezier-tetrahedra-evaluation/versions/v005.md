# Bezier Tetrahedra Evaluation

Also called: Bezier Tetrahedron, Cubic BT

## Overview
Bezier Tetrahedra (BT) evaluation computes scalar field values within a tetrahedral element using cubic Bernstein polynomials defined by 20 control weights and a bounding tetrahedron [S1]. It solves the problem of representing volumetric data on unstructured grids and enables efficient ray-tracing of isosurfaces by reducing intersection to univariate polynomial root finding [S1].

## How it works
**Inputs:**
- A query point $P = (x, y, z, 1)$ in projective space [S1].
- A bounding tetrahedron defined by four vertices $T = (T_1, T_2, T_3, T_4)$, where each $T_i$ is a 3D point [S1].
- A set of 20 scalar weights $\{w_{ijkl}\}$ for $i+j+k+l=3$ [S1].

**Outputs:**
- A scalar value $b(P)$ representing the function value at $P$ [S1].

**Data Structures:**
- **Weights:** Stored as a flat array of 20 floats. The tensor form (64 values) is never stored; implementations expand from the tetrahedral form to compute transformations and encode back to tetrahedral form [S1].
- **Tetrahedron Vertices:** Stored as four 3D vectors [S1].

**Steps:**
1. **Compute Barycentric Coordinates:** Construct a $4 \times 4$ matrix $\mathbf{T}$ where the rows are the homogeneous coordinates of the vertices $T_1, T_2, T_3, T_4$. Compute the inverse matrix $\mathbf{T}^{-1}$. Compute the barycentric coordinate vector $\mathbf{r} = (r, s, t, u)$ by multiplying the query point $P$ by $\mathbf{T}^{-1}$: $\mathbf{r} = P \cdot \mathbf{T}^{-1}$ [S1].
2. **Evaluate Bernstein Polynomial:** Compute the value $b(P)$ using the sum over all non-negative integers $i, j, k, l$ such that $i+j+k+l=3$: $b(P) = \sum_{i+j+k+l=3} w_{ijkl} \binom{3}{i,j,k,l} r^i s^j t^k u^l$, where $\binom{3}{i,j,k,l} = \frac{3!}{i!j!k!l!}$ is the multinomial coefficient [S1].

**Parameters:**
- **Degree:** 3 (Cubic). This determines the number of weights (20) and the power of the barycentric coordinates [S1].
- **Weights:** 20 scalar values. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Degenerate Tetrahedra:** If the determinant of $\mathbf{T}$ is zero (volume is zero), $\mathbf{T}^{-1}$ does not exist. The implementation must check for this condition [G].
- **Precision:** Barycentric coordinate computation involves matrix inversion. For nearly flat tetrahedra, numerical instability may occur [G].
- **Tensor Form:** The tensor form of BT weights (64 values) is less compact than the tetrahedral form (20 values). Implementations should never store the tensor form; they must expand from the tetrahedral form for transformations and encode back to tetrahedral form [S1].

**Pseudocode:**
```python
def evaluate_bezier_tetrahedron(P, T, weights):
    """
    Evaluate a cubic Bezier Tetrahedron at point P.
    
    Args:
        P: tuple (x, y, z, 1) - Point in projective space.
        T: list of 4 tuples - Vertices (x, y, z) of the bounding tetrahedron.
        weights: list of 20 floats - Control weights w_ijkl for i+j+k+l=3.
                 Must be ordered consistently with the iteration order below.
        
    Returns:
        float: The scalar value at P.
    """
    # Step 1: Compute Barycentric Coordinates
    # Construct 4x4 matrix T_mat from vertices (homogeneous coordinates)
    T_mat = [[T[i][0], T[i][1], T[i][2], 1.0] for i in range(4)]
    
    # Compute inverse of T_mat [G]
    T_inv = invert_4x4(T_mat)
    
    # Multiply P by T_inv to get barycentric coords (r, s, t, u)
    # P is a row vector (x, y, z, 1)
    r = sum(P[k] * T_inv[k][0] for k in range(4))
    s = sum(P[k] * T_inv[k][1] for k in range(4))
    t = sum(P[k] * T_inv[k][2] for k in range(4))
    u = sum(P[k] * T_inv[k][3] for k in range(4))
    
    # Step 2: Evaluate Bernstein Polynomial
    # Precompute powers of barycentric coordinates
    r_p = [1.0, r, r*r, r*r*r]
    s_p = [1.0, s, s*s, s*s*s]
    t_p = [1.0, t, t*t, t*t*t]
    u_p = [1.0, u, u*u, u*u*u]
    
    # Factorials for multinomial coefficient 3!/(i!j!k!l!)
    fact = [1, 1, 2, 6]
    
    value = 0.0
    # Generate all (i,j,k,l) with i+j+k+l=3
    combos = []
    for i in range(4):
        for j in range(4):
            for k in range(4):
                l = 3 - i - j - k
                if l >= 0:
                    combos.append((i, j, k, l))
                    
    # Sum over the 20 combinations
    for idx, (i, j, k, l) in enumerate(combos):
        coeff = 6.0 / (fact[i] * fact[j] * fact[k] * fact[l])
        value += weights[idx] * coeff * r_p[i] * s_p[j] * t_p[k] * u_p[l]
        
    return value

def invert_4x4(M):
    """Computes the inverse of a 4x4 matrix using cofactors [G]."""
    def minor(m, r, c):
        return [[m[i][j] for j in range(4) if j != c] for i in range(4) if i != r]
    
    def det_3x3(m):
        return (m[0][0]*(m[1][1]*m[2][2]-m[1][2]*m[2][1]) -
                m[0][1]*(m[1][0]*m[2][2]-m[1][2]*m[2][0]) +
                m[0][2]*(m[1][0]*m[2][1]-m[1][1]*m[2][0]))
                
    det = 0.0
    for c in range(4):
        det += M[0][c] * ((-1)**c) * det_3x3(minor(M, 0, c))
    if det == 0:
        raise ValueError("Singular matrix: tetrahedron volume is zero.")
        
    inv_det = 1.0 / det
    inv = [[0.0]*4 for _ in range(4)]
    for i in range(4):
        for j in range(4):
            cof = ((-1)**(i+j)) * det_3x3(minor(M, j, i))
            inv[i][j] = cof * inv_det
    return inv
```

## Subtopics

### [Quadratic Super Splines](7082-quadratic-super-splines.md)
Quadratic Super Splines is a technique for reconstructing iso-surfaces from volumetric data with pseudo $C^1$ continuity along cell boundaries, producing smooth contours by partitioning cells into tetrahedra and using Bernstein-Bézier coefficients. It differs from standard linear or cubic tetrahedral methods by employing a univariate piecewise quadratic polynomial that allows for efficient ray-iso-surface intersection via quadratic equation solving, balancing smoothness against the high memory cost of storing 65 coefficients per cell.

### BT Ray Tracing in Screen Space
An extension of Loop and Blinn [2006] for ray-tracing BTs [S1]. It transforms the BT weights and bounding tetrahedra into screen space to solve for ray-BT intersections [S1]. The process substitutes the viewing ray equation (constant x, y; varying z) into the zero-isosurface equation, collapsing the polynomial from four variables to a univariate polynomial in z [S1]. The transformed weight tensor is computed as $\tilde{B}_{\beta_1, \beta_2, \beta_3} = W_{\beta_1}^{\alpha_1} W_{\beta_2}^{\alpha_2} W_{\beta_3}^{\alpha_3} B_{\alpha_1, \alpha_2, \alpha_3}$, where $W$ is the inverse composite transform and $B$ is the original weight tensor [S1]. The zero-isosurface is defined by $P_s^{\beta_1} P_s^{\beta_2} P_s^{\beta_3} \tilde{B}_{\beta_1, \beta_2, \beta_3} = 0$ [S1]. Solving for the roots of this univariate polynomial yields the intersection points [S1].

### BT Bounding Property Culling
A culling technique using the bounding property of BTs [S1]. The value of a BT at any point $P$ is bounded by the minimum and maximum of its weights [S1]. This allows early culling of tetrahedra that cannot contain a specific isosurface level [S1]. The step computes the minimum and maximum values of the weight set $\{w_{i,j,k,l}\}$ for a given BT, and if the target isosurface level is outside the range $[\min\_weight, \max\_weight]$, the tetrahedron is culled [S1].

## Operating characteristics
- **Time Complexity:** Evaluation is $O(1)$ per tetrahedron, involving a constant-time $4 \times 4$ matrix inversion and a fixed number of arithmetic operations for the 20 weights [G]. Ray tracing requires solving a univariate polynomial, which is also constant time but involves root-finding algorithms [S1].
- **Memory Complexity:** 20 scalar weights per tetrahedron plus 4 vertices [S1].
- **Measured Performance:** Loop and Blinn [2006] implemented this on graphics hardware, suggesting efficient rasterization or ray-tracing performance [S1]. Not given in the sources.
- **Strengths:** Smooth representation, efficient ray-tracing via univariate polynomial reduction, hardware-friendly [S1].
- **Limitations:** Higher memory cost than linear methods, potential numerical instability with degenerate tetrahedra [G].
- **When to Use:** When smooth iso-surfaces are required on unstructured grids and memory allows for higher-order coefficients [S1].
- **When Not to Use:** Not given in the sources.

## Background
Bezier Tetrahedra were developed by Charles Loop and James Blinn in 2006 for interactive volume isosurface rendering on graphics hardware [S1]. The method extends the concept of Bezier curves and surfaces to 3D tetrahedral elements, allowing for efficient ray-tracing by transforming the problem into screen space [S1].
