# Supercube

Also called: Supercube Clustering

## Overview
A supercube is a spatial and hierarchical structure that tiles each level of resolution in a Longest Edge Bisection (LEB) tetrahedral hierarchy, defined by a set of 98 edges arranged in a cubic domain [S1]. It clusters diamonds to exploit spatial and hierarchical coherence for representing partial Diamond Multivolumes (DMVs) and active fronts [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A cubic domain in 3D space, defined by its origin coordinates and scale (resolution level) [S1].
*   **Output:** A data structure representing the 56 valid edges (diamonds) contained within that supercube, along with bitflags indicating which tetrahedra are present in the active front [S1].

**Data Structures:**
A supercube is defined by a set of 98 potential edges [S1].
*   **Edge Set:** The supercube $\sigma$ is constructed from an empty cubic domain. The edges are formed by: 1) 8 edges joining the cube center to its 8 corners; 2) 30 edges joining each of the 6 face centers to the 4 face corners and the cube center; 3) 60 edges joining each of the 12 edge midpoints to the 2 closest cube corners, the 2 closest face centers, and the cube center [S1].
*   **Diamond Classification:** The 56 valid edges correspond to diamonds of three types: 8 zero-diamonds (scale 0), each containing 6 tetrahedra; 24 one-diamonds (scale 1), each containing 4 tetrahedra; and 24 two-diamonds (scale 2), each containing 8 tetrahedra [S1].
*   **Tetrahedron Count:** The total potential tetrahedra indexed by a supercube is $8 \times 6 + 24 \times 4 + 24 \times 8 = 336$ [S1].
*   **Active Front Bookkeeping:** Since tetrahedra in a conforming mesh cannot overlap, the presence of a tetrahedron $t$ precludes its parent and children [S1]. Tetrahedra contribute to diamonds in pairs [S1]. Therefore, the active front state for a supercube is tracked using $336 / 2 = 168$ bits (21 bytes) [S1].
*   **Indexing:** Supercubes at each level are indexed by the coordinates of their origin [S1].

**Boundary Rule:**
To ensure unique association of edges to supercubes, half-open intervals are used [S1].
*   A supercube contains all internal edges and edges on its lower boundaries, but excludes edges on its upper boundaries [S1].
*   Any edge whose endpoints are both on an upper boundary belongs to a neighboring supercube [S1].
*   Under this rule, the 98 potential edges reduce to 56 valid edges: 8 cube diagonals, 24 face diagonals, and 24 cube edges [S1].

**Pseudocode:**
The following Python-like pseudocode defines the construction, filtering, and bookkeeping logic.

```python
def construct_supercube_edges(cube_origin, cube_size):
    """Constructs the 98 potential edges of a supercube."""
    cx, cy, cz = cube_origin
    s = cube_size
    center = (cx + s/2, cy + s/2, cz + s/2)
    corners = [
        (cx, cy, cz), (cx+s, cy, cz), (cx, cy+s, cz), (cx+s, cy+s, cz),
        (cx, cy, cz+s), (cx+s, cy, cz+s), (cx, cy+s, cz+s), (cx+s, cy+s, cz+s)
    ]
    face_centers = [
        (cx + s/2, cy + s/2, cz), (cx + s/2, cy + s/2, cz + s),
        (cx + s/2, cy, cz + s/2), (cx + s/2, cy + s, cz + s/2),
        (cx, cy + s/2, cz + s/2), (cx + s, cy + s/2, cz + s/2)
    ]
    edge_midpoints = [
        (cx + s/2, cy, cz), (cx + s/2, cy + s, cz),
        (cx, cy + s/2, cz), (cx + s, cy + s/2, cz),
        (cx, cy, cz + s/2), (cx + s, cy, cz + s/2),
        (cx, cy + s, cz + s/2), (cx + s, cy + s, cz + s/2),
        (cx + s/2, cy, cz + s), (cx + s/2, cy + s, cz + s),
        (cx, cy + s/2, cz + s), (cx + s, cy + s/2, cz + s)
    ]
    edges = []
    for corner in corners:
        edges.append((center, corner))
    for fc in face_centers:
        edges.append((fc, center))
    for i, fc in enumerate(face_centers):
        if i < 2:
            face_corners = corners[0:4] if i == 0 else corners[4:8]
        elif i < 4:
            face_corners = [corners[0], corners[1], corners[4], corners[5]] if i == 2 else [corners[2], corners[3], corners[6], corners[7]]
        else:
            face_corners = [corners[0], corners[2], corners[4], corners[6]] if i == 4 else [corners[1], corners[3], corners[5], corners[7]]
        for corner in face_corners:
            edges.append((fc, corner))
    for mid in edge_midpoints:
        edges.append((mid, center))
        if mid[0] == cx + s/2 and mid[1] == cy and mid[2] == cz:
            neighbors = (corners[0], corners[1], face_centers[0], face_centers[2])
        elif mid[0] == cx + s/2 and mid[1] == cy + s and mid[2] == cz:
            neighbors = (corners[1], corners[3], face_centers[0], face_centers[3])
        elif mid[0] == cx and mid[1] == cy + s/2 and mid[2] == cz:
            neighbors = (corners[0], corners[2], face_centers[0], face_centers[4])
        elif mid[0] == cx + s and mid[1] == cy + s/2 and mid[2] == cz:
            neighbors = (corners[1], corners[3], face_centers[0], face_centers[5])
        elif mid[0] == cx and mid[1] == cy and mid[2] == cz + s/2:
            neighbors = (corners[0], corners[4], face_centers[2], face_centers[4])
        elif mid[0] == cx + s and mid[1] == cy and mid[2] == cz + s/2:
            neighbors = (corners[1], corners[5], face_centers[2], face_centers[5])
        elif mid[0] == cx and mid[1] == cy + s and mid[2] == cz + s/2:
            neighbors = (corners[2], corners[6], face_centers[3], face_centers[4])
        elif mid[0] == cx + s and mid[1] == cy + s and mid[2] == cz + s/2:
            neighbors = (corners[3], corners[7], face_centers[3], face_centers[5])
        elif mid[0] == cx + s/2 and mid[1] == cy and mid[2] == cz + s:
            neighbors = (corners[4], corners[5], face_centers[1], face_centers[2])
        elif mid[0] == cx + s/2 and mid[1] == cy + s and mid[2] == cz + s:
            neighbors = (corners[5], corners[7], face_centers[1], face_centers[3])
        elif mid[0] == cx and mid[1] == cy + s/2 and mid[2] == cz + s:
            neighbors = (corners[4], corners[6], face_centers[1], face_centers[4])
        elif mid[0] == cx + s and mid[1] == cy + s/2 and mid[2] == cz + s:
            neighbors = (corners[5], corners[7], face_centers[1], face_centers[5])
        for n in neighbors:
            edges.append((mid, n))
    return edges

def filter_supercube_edges(edges, cube_origin, cube_size):
    """Applies the half-open interval rule to select the 56 valid edges."""
    min_x, min_y, min_z = cube_origin
    max_x, max_y, max_z = (cube_origin[0] + cube_size, cube_origin[1] + cube_size, cube_origin[2] + cube_size)
    valid_edges = []
    for v1, v2 in edges:
        is_upper_x = (v1[0] == max_x and v2[0] == max_x)
        is_upper_y = (v1[1] == max_y and v2[1] == max_y)
        is_upper_z = (v1[2] == max_z and v2[2] == max_z)
        if not (is_upper_x or is_upper_y or is_upper_z):
            valid_edges.append((v1, v2))
    return valid_edges

def encode_active_front(tetrahedra_indices):
    """Encodes the presence of tetrahedra in the active front using 168 bits."""
    bits = bytearray(21)
    for t in tetrahedra_indices:
        bit_idx = t % 168
        byte_idx = bit_idx // 8
        bit_offset = bit_idx % 8
        bits[byte_idx] |= (1 << bit_offset)
    return bits
```

**Parameters:**
*   **Origin Coordinates:** Integer or floating-point coordinates defining the lower-left-back corner of the cubic domain [S1].
*   **Scale/Resolution:** The level in the LEB hierarchy, determining the granularity of the diamonds [S1].

**Edge Cases and Pitfalls:**
*   **Overlap vs. Conformity:** Tetrahedra indexed by a supercube overlap in the full DMV hierarchy [S1]. However, in a conforming active front mesh, tetrahedra cannot overlap [S1]. The presence of a tetrahedron $t$ precludes the presence of its parent and children [S1]. Implementers must ensure the active front logic respects this containment relation to avoid double-counting or invalid geometry [G].
*   **Boundary Association:** The half-open interval rule is critical for unique association [S1]. Failure to exclude upper-boundary edges results in edges being assigned to multiple supercubes, breaking the hierarchical indexing [G].

## Operating characteristics
*   **Memory Complexity:** Each supercube requires 27 bytes of overhead: 6 bytes for the origin index and 21 bytes (168 bits) for the active front bookkeeping [S1].
*   **Scalability:** Supercubes tile the domain at each resolution level, allowing efficient representation of large datasets [S1].
*   **Limitations:** The method is specific to the LEB tetrahedral hierarchy and diamond multivolumes [S1].

## Background
The supercube was introduced in the context of Diamond Multivolumes (DMVs) and selective refinement for volume rendering [S1]. It was proposed to address the inefficiency of representing sparse active fronts using raw diamond lists [S1]. By analyzing the symmetry in the LEB hierarchy, the authors identified a repeating cubic pattern of edges that could be used to cluster diamonds, leading to the supercube primitive [S1].
