# Piecewise-Linear Topology Representation

Also called: Cell Complexes, Simplicial Complexes

## Overview
Piecewise-Linear Topology Representation models geometric data as a tuple $(K, V)$, where $K$ is a combinatorial simplicial complex defining connectivity and $V$ is a set of vertex positions in $\mathbb{R}^n$ [S1, unofficial]. It solves the problem of representing arbitrary, unstructured topologies with precise boundary definitions, distinguishing itself from regular grids by supporting complex genus and non-manifold features through explicit combinatorial rules [S1, unofficial]. It serves as the foundational topological abstraction for tetrahedral mesh representations, providing the rigorous mathematical structure upon which adaptive refinement and basis function evaluation are built.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ vertices $V = \{v_0, \dots, v_{N-1}\}$ where each $v_i \in \mathbb{R}^n$, and a combinatorial structure $K$ defining the connectivity.
*   **Output:** A geometric model realizing the topology specified by $K$ with the geometry specified by $V$.

**Data Structures:**
The representation consists of two distinct components:
1.  **Combinatorial Complex ($K$):** A finite collection of cells (simplices) satisfying specific closure and intersection properties. It stores the incidence relations between vertices, edges, triangles, and tetrahedra.
2.  **Vertex Position Set ($V$):** An array or list of coordinate vectors.

**Definitions:**
*   An **$n$-simplex** is defined by $n+1$ linearly independent points $v_0, \dots, v_n$ [S1, unofficial].
*   A **face** of a simplex $A$ is a simplex spanned by a subset of its vertices. The set of all faces is denoted $faces(A)$ [S1, unofficial].
*   The **star** of a simplex $A$, denoted $star(A)$, is the set of all simplices in $K$ for which $A$ is a face [S1, unofficial].

**Cell Complex Rules:**
A cell complex $K$ is a finite collection of cells satisfying:
1.  **Downward Closure:** If $B, C \notin K$ and $B < C$ (B is a face of C), then $B \notin K$ is false; i.e., if a cell is in $K$, all its faces are in $K$. Formally: If $C \in K$ and $B \subset C$, then $B \in K$ [S1, unofficial].
2.  **Intersection Property:** If $B, C \in K$ and $B \neq C$, then $B \cap C$ is either empty or a common face of both $B$ and $C$ [S1, unofficial].

**Simplicial Complex Specifics:**
A cell complex is a **simplicial complex** if every cell is a simplex [S1, unofficial].
*   **Principal Simplex:** A simplex with no parents (no higher-dimensional simplex in $K$ has it as a proper face).
*   **Boundary Simplex:** A simplex with exactly one parent.
*   **Regular Complex:** A simplicial complex where all principal simplices are of the same dimension [S1, unofficial].

**Manifold Properties:**
*   **$n$-Manifold:** A polyhedron where each point has a neighborhood homeomorphic to an open set in $\mathbb{R}^n$ [S1, unofficial].
*   **Pseudo-Manifold:** A regular complex satisfying:
    1.  Every $(n-1)$-face is a face of some $n$-cell.
    2.  Every $n$-cell is a face of exactly two $n$-cells.
    3.  Any two $n$-cells can be connected by a sequence of $n$-cells sharing $(n-1)$-faces [S1, unofficial].

**Pseudocode for Topological Validation:**
```python
def is_valid_simplicial_complex(K, V):
    """
    Validates that K is a valid simplicial complex given vertices V.
    K is a set of tuples, where each tuple represents a simplex 
    as a sorted list of vertex indices.
    """
    # 1. Check that all vertices in K exist in V
    all_vertices_in_K = set()
    for simplex in K:
        for vertex_idx in simplex:
            if vertex_idx < 0 or vertex_idx >= len(V):
                return False
            all_vertices_in_K.add(vertex_idx)

    # 2. Check Downward Closure: Every face of a simplex in K must be in K
    for simplex in K:
        # Generate all subsets of the simplex
        for i in range(1, len(simplex) + 1):
            for face in combinations(simplex, i):
                # Sort face to ensure canonical representation
                sorted_face = tuple(sorted(face))
                if sorted_face not in K:
                    return False

    # 3. Check Intersection Property: Intersection of any two simplices 
    # must be a face of both.
    for simplex_A in K:
        for simplex_B in K:
            if simplex_A == simplex_B:
                continue
            
            # Calculate intersection of vertex sets
            intersection = set(simplex_A).intersection(set(simplex_B))
            
            # If intersection is empty, it's valid
            if not intersection:
                continue
            
            # If intersection is not empty, it must be a face of A and B
            intersection_tuple = tuple(sorted(intersection))
            
            # Check if intersection is a face of A
            is_face_of_A = False
            for face in faces(simplex_A): # Helper to get all faces of A
                if tuple(sorted(face)) == intersection_tuple:
                    is_face_of_A = True
                    break
            
            if not is_face_of_A:
                return False

            # Check if intersection is a face of B
            is_face_of_B = False
            for face in faces(simplex_B): # Helper to get all faces of B
                if tuple(sorted(face)) == intersection_tuple:
                    is_face_of_B = True
                    break
            
            if not is_face_of_B:
                return False

    return True

def faces(simplex):
    """Returns all subsets of a simplex (its faces)."""
    result = []
    for i in range(len(simplex) + 1):
        for subset in combinations(simplex, i):
            result.append(subset)
    return result
```

**Edge Cases and Pitfalls:**
*   **Non-Manifold Geometry:** The general cell complex definition allows non-manifold configurations (e.g., two tetrahedra sharing only an edge). If manifold properties are required, strict validation against the pseudo-manifold rules must be applied [S1, unofficial].
*   **Degenerate Simplices:** Simplices with linearly dependent vertices (volume zero) are technically allowed in the combinatorial definition but cause numerical issues in rendering. The source notes that linear independence is required for the definition of an $n$-simplex [S1, unofficial].
*   **Orientation:** The combinatorial complex $K$ does not inherently store orientation. Orientation must be derived from the vertex ordering in $V$ or stored explicitly if required for normal calculation.

### [Cell-Definition-Shape Geometry Model](16078-cell-definition-shape-geometry-model.md)
A Cell is a lightweight value type containing a Definition by value and an orientation. It shares immutable data via std::shared_ptr<const Data> within the Definition, allowing multiple cells to share the same geometry and material bindings without a global registry.

## Operating characteristics
*   **Time Complexity:** Topological queries (e.g., finding neighbors via `star()`) depend on the degree of the simplex. In a well-formed mesh, this is bounded by the average valence. Intersection tests for rendering require ray-tetrahedron intersection, which is $O(1)$ per element but requires traversal of the complex.
*   **Memory Complexity:** $O(N + E + F + T)$ where $N, E, F, T$ are the number of vertices, edges, faces, and tetrahedra. The combinatorial structure $K$ stores indices, while $V$ stores coordinates.
*   **Strengths:** Exact topological representation; supports arbitrary genus and non-manifold features; basis for adaptive refinement.
*   **Limitations:** Complex data structures for connectivity; no inherent spatial acceleration (requires external BVH or grid for ray traversal); validation is computationally expensive.
*   **When to use:** When topological correctness and arbitrary connectivity are critical, such as in scientific visualization of complex domains or differentiable geometry optimization.
*   **When not to use:** For simple, regular domains where structured grids are more efficient; when hardware rasterization of regular meshes is preferred without custom shaders.

## Background
The piecewise-linear topology representation originates from discrete geometry and computational topology. It is formally introduced in the context of multiresolution representation and compression of surfaces and volumes. The concepts of simplicial complexes, manifolds, and cell complexes are foundational to the field, providing the mathematical rigor necessary for unstructured mesh processing. The specific definitions and properties cited are derived from academic work on multiresolution surface and volume representations [S1, unofficial].
