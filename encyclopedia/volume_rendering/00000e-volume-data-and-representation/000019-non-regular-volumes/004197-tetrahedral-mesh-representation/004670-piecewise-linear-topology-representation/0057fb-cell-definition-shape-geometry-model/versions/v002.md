# Cell-Definition-Shape Geometry Model

Also called: VXL-042, VXL-043, VXL-044, VXL-045

## Overview
The Cell-Definition-Shape geometry model is a lightweight, immutable data structure for representing non-regular volumes within a voxel rendering system [S1]. It solves the problem of efficiently storing and sharing complex geometric definitions without requiring a global registry or heavy reference counting overhead [S1]. It sets itself apart from sibling methods by decoupling the geometric definition (`Shape`) from its instance placement (`Cell`) via an intermediate immutable `Definition` object, allowing multiple cells to share geometry and material bindings through value semantics and shared pointers [S1].

## How it works

### Inputs and Outputs
*   **Input:** A set of polygons defining a `Shape`, vertex positions, normals, UVs, and material slots [S1].
*   **Output:** A `Volume` containing a local table of `Definition` objects and a compact array of `Cell` indices, with a public API exposing reconstructed `Cell` values [S1].

### Data Structures

#### MeshVertex
The fundamental vertex structure for shapes [S1].
*   `position`: `spk::Vector3Int` (Integer coordinates, quantized to 1/1000 grid, range 0–1000) [S1].
*   `normal`: `spk::Vector3` (Float) [S1].
*   `uv`: `spk::Vector2` (Float) [S1].
*   `materialIndex`: `std::uint32_t` (Local index to `Model`) [S1].

#### Shape
A collection of polygons [S1].
*   **Polygon Constraints:** Each polygon must be planar, convex, and have at least three vertices [S1]. Globally concave shapes are represented as a union of multiple convex polygons, not a single concave polygon [S1].
*   **Shell Classification:** Polygons are classified into `outerShell` or `innerShell` at construction [S1].
    *   `outerShell`: All vertices lie on the same unit cube boundary plane (coordinate X, Y, or Z is constant and equal to 0 or 1000) [S1].
    *   `innerShell`: All other polygons [S1].
*   **Boundary Coverage:** Six 2D boundary coverages are calculated exclusively from `outerShell` polygons [S1]. These coverages must be decomposable into unions of axis-aligned 2D rectangles on the 1000×1000 grid, not a single bounding box, to avoid false occlusions [S1]. `innerShell` polygons retain their 3D data, UVs, and material slots independently of these coverages [S1].

#### Definition
An immutable object that associates a `Shape` with semantic material slots of a `Model` [S1].
*   **Layout:** Contains a `std::shared_ptr<const Data>` pointing to the immutable geometry data [S1].
*   **Properties:** Does not contain concrete palette materials [S1]. Copying a `Definition` is lightweight because it shares the underlying `Data` pointer [S1].

#### Cell
A lightweight value type stored in the `Volume` [S1].
*   **Layout:** Contains a `Definition` by value (light copy) and an `orientation` [S1].
*   **Orientation:** Discrete set of 8 variants: 4 rotations of 90 degrees around the Y-axis and one vertical flip [S1].
*   **Storage:** Stored compactly in the `Volume` using indices [S1]. The `Volume` maintains a local table of definitions and reconstructs `Cell` values on public reads [S1].

### Steps

1.  **Shape Construction:**
    *   Validate that all polygons are planar, convex, and have $\ge 3$ vertices [S1].
    *   Classify each polygon:
        *   If all vertices share a constant coordinate (0 or 1000) on X, Y, or Z, assign to `outerShell` [S1].
        *   Otherwise, assign to `innerShell` [S1].
    *   Calculate 2D boundary coverages for the six faces of the unit cube using only `outerShell` polygons [S1].
    *   Store `innerShell` polygons with their 3D data, UVs, and material slots [S1].

2.  **Definition Creation:**
    *   Create an immutable `Definition` object [S1].
    *   Associate the `Shape` with the `Definition` [S1].
    *   Bind semantic material slots from the `Model` to the `Definition` [S1].
    *   Encapsulate the geometry data in a `std::shared_ptr<const Data>` [S1].

3.  **Cell Creation:**
    *   Instantiate a `Cell` by value [S1].
    *   Assign the `Definition` to the `Cell` [S1].
    *   Assign an `orientation` from the 8 discrete variants (4 rotations $\times$ 2 flips) [S1].

4.  **Volume Population:**
    *   Store `Definition` objects in a local table within the `Volume` [S1].
    *   Store `Cell` indices compactly in the `Volume` [S1].
    *   On public read, reconstruct the `Cell` value from the stored index and the local definition table [S1].

### Parameters
*   **Vertex Quantization:** Coordinates are quantized to a 1/1000 integer grid (`spk::Vector3Int`) ranging from 0 to 1000 [S1]. This applies to both `Shape` definition and visible fragments after occlusion culling [S1].
*   **Boundary Grid Resolution:** 2D boundary coverages are evaluated on integer grids of resolution 1000 $\times$ 1000 [S1].
*   **Orientation Variants:** 8 total (4 rotations $\times$ 2 flips) [S1].

### Edge Cases and Pitfalls
*   **Empty Boundary Coverages:** Shapes with no boundary polygons (e.g., vegetation, small centered shapes) may have six empty coverages while retaining a non-empty `innerShell` [S1]. The Mesher must handle emitting or discarding interior faces based on occlusion, not just geometric presence [S1].
*   **False Occlusions:** Filled boundary coverages must be decomposable into unions of axis-aligned 2D rectangles on the grid, not a single bounding box, to avoid false occlusions [S1].
*   **No Global Registry:** No global Catalog is mandatory for resolving Shapes and bindings [S1].
*   **Degenerate Input:** Exact conventions for vertex winding, UV indexing, and handling degenerate inputs are not fully defined in the sources [S1].

class Volume:

        self.definitions: list[Definition] = []
        self.cells: list[int] = []

def classify_polygon(polygon: Polygon) -> str:
    coords = polygon.vertices
    for axis in ('x', 'y', 'z'):
        constant_val = getattr(coords[0], axis)
        if all(getattr(v, axis) == constant_val for v in coords) and constant_val in (0, 1000):
            return 'outerShell'
    return 'innerShell'

def build_shape(polygons: list[Polygon]) -> Shape:
    shape = Shape(polygons)
    for polygon in polygons:
        polygon.shell_type = classify_polygon(polygon)
    shape.boundary_coverages = calculate_boundary_coverages(shape.polygons)
    return shape

def calculate_boundary_coverages(polygons: list[Polygon]) -> dict[str, list[tuple[int, int, int, int]]]:
    coverages = {face: [] for face in ['px', 'nx', 'py', 'ny', 'pz', 'nz']}
    for polygon in polygons:
        if polygon.shell_type == 'outerShell':
            face = get_face_from_constant_coord(polygon)
            rects = decompose_to_rectangles(polygon)
            coverages[face].extend(rects)
    return coverages

def get_face_from_constant_coord(polygon: Polygon) -> str:
    for v in polygon.vertices:
        if v.x == 0: return 'nx'
        if v.x == 1000: return 'px'
        if v.y == 0: return 'ny'
        if v.y == 1000: return 'py'
        if v.z == 0: return 'nz'
        if v.z == 1000: return 'pz'
    return 'unknown'

## Operating characteristics

*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Not given in the sources.
*   **Strengths:** Lightweight value semantics for Cells. No global registry required. Geometry and materials are shared via `std::shared_ptr<const Data>` [S1].
*   **Limitations:** Limited to convex polygons. Global concavity requires decomposition into multiple convex polygons [S1]. Boundary coverage calculation is restricted to axis-aligned planes [S1].
*   **When to Use:** Suitable for voxel-based rendering systems requiring efficient storage and sharing of complex, non-regular geometric shapes [S1].
*   **When Not to Use:** Not suitable for scenes requiring global concave shapes without decomposition or non-axis-aligned boundary coverage [S1].

## Background

The Cell-Definition-Shape geometry model is part of the Voxel Rendering System design, specifically defined in the VXL-042, VXL-043, VXL-044, and VXL-045 specifications [S1]. It was developed as part of the Sparkle voxel engine project [S1]. The model emphasizes immutability and value semantics to simplify resource management and improve performance in voxel-based rendering [S1].
