# Normal Estimation with KdTree and OMP

Also called: PCL NormalEstimationOMP, Parallel KdTree Normal Estimation

## Overview
This method estimates surface normal vectors for a point cloud by performing parallel least-squares plane fitting within local neighborhoods defined by a KdTree search structure [S1, unofficial]. It builds on [Least Squares Plane Fitting for Point Cloud Normals](12472-least-squares-plane-fitting-for-point-cloud-normals.md) by introducing OpenMP-based parallelization to accelerate the neighbor search and eigenvalue decomposition steps [S1, unofficial]. Unlike sequential implementations, it scales effectively with the number of CPU cores, making it suitable for large-scale point clouds where computational efficiency is critical [S1, unofficial].

## How it works
**Inputs:**
- `input_cloud`: A point cloud containing 3D coordinates ($x, y, z$).
- `kSearch`: The number of nearest neighbors to consider for each point (default: 20) [S1, unofficial].

**Outputs:**
- `output_normals`: A point cloud where each point has an associated normal vector ($n_x, n_y, n_z$) and optionally curvature [S1, unofficial].

**Data Structures:**
- `KdTree`: A spatial indexing structure storing the `input_cloud` to enable efficient $k$-nearest neighbor queries [S1, unofficial].
- `NormalEstimationOMP`: The processing object that manages the parallel execution context and stores the resulting normals [S1, unofficial].

**Steps:**
1. **Preprocessing**: Remove NaN values from the input cloud if present [S1, unofficial].
2. **KdTree Construction**: Initialize a KdTree with the cleaned input cloud. This allows $O(\log N)$ average-case search time for neighbors [S1, unofficial].
3. **Parallel Loop Initialization**: Instantiate `NormalEstimationOMP` and set the input cloud and search method (KdTree) [S1, unofficial].
4. **Neighbor Search**: For each point $P_i$ in the cloud, query the KdTree to find the $k$-nearest neighbors (including $P_i$ itself) [S1, unofficial].
5. **Plane Fitting**: For each point $P_i$ and its neighbor set $N_i$:
   - Compute the centroid $\mu$ of $N_i$.
   - Construct the covariance matrix $C$ of the points in $N_i$ relative to $\mu$:
     $$ C = \sum_{P_j \in N_i} (P_j - \mu)(P_j - \mu)^T $$
   - Perform eigenvalue decomposition on $C$. The eigenvector corresponding to the smallest eigenvalue is the normal vector $n_i$ [S1, unofficial].
6. **Parallel Execution**: Steps 4 and 5 are executed in parallel using OpenMP pragmas, distributing the workload across available CPU threads [S1, unofficial].
7. **Output**: Store the computed normal vectors in the output cloud [S1, unofficial].

**Parameters:**
- `kSearch`: Number of neighbors. Typical value: 20 [S1, unofficial].
- `thread_count`: Number of OpenMP threads. Defaults to system-available cores [S1, unofficial].

**Edge Cases:**
- **Sparse Regions**: If fewer than $k$ neighbors are found (e.g., at boundaries), the method may fail or produce inaccurate normals. A fallback to a larger radius or fewer neighbors is not explicitly detailed in the source [S1, unofficial].
- **Degenerate Geometry**: If points are collinear or coplanar, the covariance matrix may be singular. The source does not specify a regularization term for this case [S1, unofficial].

```python
import numpy as np
import open3d as o3d  # Assuming a standard library for KdTree and OMP-like parallelism, as PCL is C++
# Note: The source uses PCL's NormalEstimationOMP. This pseudocode mimics the logic.

def estimate_normals_kdtree_omp(point_cloud, k_search=20):
    """
    Estimate normals using KdTree and parallel processing.
    """
    # 1. Preprocessing: Remove NaNs
    cloud = remove_nan(point_cloud)
    
    # 2. Build KdTree
    kdtree = build_kdtree(cloud)
    
    # 3. Initialize output
    normals = np.zeros((len(cloud), 3))
    
    # 4. Parallel Loop (simulated with list comprehension for clarity, 
    # but in C++ PCL, this is #pragma omp parallel for)
    # Each thread processes a subset of points
    def process_point(i):
        point = cloud[i]
        # Query k-nearest neighbors
        indices, distances = kdtree.query(point, k=k_search)
        neighbors = cloud[indices]
        
        # Compute centroid
        centroid = np.mean(neighbors, axis=0)
        
        # Compute covariance matrix
        diff = neighbors - centroid
        cov_matrix = np.dot(diff.T, diff)
        
        # Eigenvalue decomposition
        eigenvalues, eigenvectors = np.linalg.eigh(cov_matrix)
        
        # Normal is eigenvector with smallest eigenvalue
        normal = eigenvectors[:, np.argmin(eigenvalues)]
        
        # Ensure consistent orientation (optional, not in source)
        # if np.dot(normal, point - centroid) < 0:
        #     normal = -normal
        
        return normal

    # Parallel execution
    import concurrent.futures
    with concurrent.futures.ThreadPoolExecutor() as executor:
        results = executor.map(process_point, range(len(cloud)))
        normals = np.array(list(results))
        
    return normals
```

## Subtopics

### Planar Filter
A variant that estimates normals from a depth map rather than a point cloud [S2, unofficial]. It solves for local plane gradients ($Z_x, Z_y, Z_z$) using a filter function to weight neighbors and regularization to enforce fronto-parallelism [S2, unofficial]. It is chosen when working with dense depth maps from stereo or structured light sensors, where point cloud extraction is not the primary input [S2, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N \log N)$ for KdTree construction and $O(N \cdot k)$ for neighbor search and fitting, where $N$ is the number of points and $k$ is `kSearch` [S1, unofficial].
- **Memory Complexity**: $O(N)$ for storing the cloud and KdTree structure [S1, unofficial].
- **Performance**: Scales linearly with the number of CPU cores due to OpenMP parallelization [S1, unofficial].
- **Strengths**: High speed for large point clouds; robust to moderate noise due to local plane fitting [S1, unofficial].
- **Limitations**: Sensitive to the choice of `kSearch`; small $k$ leads to noisy normals, large $k$ blurs sharp features [S1, unofficial]. Not suitable for GPU acceleration without modification [S1, unofficial].

## Background
The method is part of the Point Cloud Library (PCL) ecosystem, specifically the `pcl::NormalEstimationOMP` class [S1, unofficial]. It was developed to provide a fast, multi-threaded alternative to sequential normal estimation algorithms, leveraging OpenMP for parallel execution [S1, unofficial]. It is widely used in robotics, 3D reconstruction, and mesh processing pipelines where real-time or near-real-time normal estimation is required [S1, unofficial].
