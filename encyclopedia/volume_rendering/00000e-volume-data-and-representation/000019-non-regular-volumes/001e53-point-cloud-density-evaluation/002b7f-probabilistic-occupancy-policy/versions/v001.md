# Probabilistic Occupancy Policy

Also called: Intensity-based Occupancy Thresholding, Signed Intensity Occupancy Policy

## Overview
The Probabilistic Occupancy Policy determines the occupancy status of a point cloud point based on its intensity field value, using a probabilistic interpretation where values near 0.0 indicate free space and values near 1.0 indicate occupied space [S1, unofficial]. It sets itself apart from the Signed Intensity Occupancy Policy by using a symmetric tolerance range around both 0 and 1, rather than a single threshold near zero [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A point $p$ from a point cloud, which may contain an 'intensity' field.
- Output: An `OccupancyStatus` enum value: `FREE`, `OCCUPIED`, or `UNKNOWN`.

**Data Structures:**
The method uses a simple enumeration for status:
```cpp
enum OccupancyStatus { FREE = 0, OCCUPIED = 1, UNKNOWN = 2 };
```
The point $p$ is assumed to have a method or field access `p.intensity` returning a `float`. If the field does not exist, the method returns `UNKNOWN` [S1, unofficial].

**Parameters:**
- `TOLLERANCE`: A static constant float with value `0.2`. This defines the tolerance range for determining if an intensity value is close to 0 (free) or 1 (occupied) [S1, unofficial].

**Steps:**
1. Check if the point $p$ has an 'intensity' field. If not, return `UNKNOWN` [S1, unofficial].
2. Let $v$ be the value of the intensity field.
3. If $|v| < \text{TOLLERANCE}$, return `FREE` [S1, unofficial].
4. If $v > (1.0 - \text{TOLLERANCE})$, return `OCCUPIED` [S1, unofficial].
5. Otherwise, return `UNKNOWN` [S1, unofficial].

**Pseudocode:**
```python
def get_occupancy_status(p):
    # Check if intensity field exists
    if not hasattr(p, 'intensity'):
        return OccupancyStatus.UNKNOWN
    
    v = p.intensity
    TOLLERANCE = 0.2
    
    # Check for free space (intensity near 0)
    if abs(v) < TOLLERANCE:
        return OccupancyStatus.FREE
    
    # Check for occupied space (intensity near 1)
    if v > (1.0 - TOLLERANCE):
        return OccupancyStatus.OCCUPIED
    
    # Otherwise unknown
    return OccupancyStatus.UNKNOWN
```

**Edge Cases and Pitfalls:**
- The term "Probabilistic" is used in the name, but the implementation is a deterministic thresholding scheme [S1, unofficial].
- The tolerance is symmetric for the "free" check ($|v| < 0.2$) but asymmetric for the "occupied" check ($v > 0.8$), effectively covering the range $[0, 0.2)$ as free and $(0.8, 1.0]$ as occupied [S1, unofficial].
- Values in $[0.2, 0.8]$ are considered unknown [S1, unofficial].
- The source code uses the spelling `TOLLERANCE` (double L) [S1, unofficial].

## Operating characteristics
- Time Complexity: $O(1)$ per point, as it involves a constant number of comparisons.
- Memory Complexity: $O(1)$, no additional data structures required.
- Strengths: Simple to implement, fast, and robust to noise if the tolerance is chosen appropriately.
- Limitations: The "probabilistic" name is misleading as it is deterministic. It assumes intensity values are normalized to $[0, 1]$ or close to it. It does not account for spatial context or point density.
- When to use: When point clouds have reliable intensity fields that correlate with occupancy (e.g., from range sensors or segmentation).
- When not to use: When intensity values are not normalized or when spatial context is needed to resolve ambiguity.

## Background
The Probabilistic Occupancy Policy is part of the `basic_next_best_view` package, developed by R. Monica [S1, unofficial]. It is used in robotics for next-best-view planning, where occupancy information from point clouds is needed to evaluate potential viewpoints. The policy is one of several occupancy policies available in the package, alongside the Signed Intensity Occupancy Policy [S1, unofficial].
