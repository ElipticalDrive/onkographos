# Barnes-Hut Fast Summation

Also called: Accelerated primal queries, Barnes-Hut Fast Summation for Primal Queries, Barnes-Hut approximation

## Overview
Barnes-Hut Fast Summation is an algorithm that accelerates the evaluation of dipole sums for geometry and radiance fields by approximating the contribution of distant clusters of points using a single centroid, reducing complexity from $O(N)$ to $O(\log N)$ [S1]. It sets itself apart from naive summation by replacing individual point interactions with hierarchical cluster approximations, enabling efficient inverse rendering on dense point clouds [S1].

## How it works
**Inputs:** A point cloud $P$ with $N$ points, where each point $m$ has a location $p_m$, area weight $A_m$, normal $n_m$, and moment attribute $b_m$; a query point $x$; a regularization parameter $\varepsilon$; and a separation criterion $\beta$.
**Outputs:** The approximated dipole sum value and, for adjoint queries, the gradient contribution.

**Data Structures:**
The method uses a tree data structure (e.g., an octree) [S1].
*   **Leaf Nodes:** Correspond to individual points in $P$.
*   **Internal Nodes:** Represent clusters of points.
*   **Node Attributes:** Each node $t$ stores:
    *   $\widehat{A}_t$: Total area weight of the cluster.
    *   $\widehat{p}_t$: Centroid location of the cluster.
    *   $\widehat{r}_t$: Maximum distance from the centroid to any point in the cluster.
    *   $\widehat{b}_t$: Weighted average moment attribute of the cluster.

**Formulas:**
Node attributes are computed recursively from children or directly from leaf points [S1]:
$$ \widehat{A}_t \equiv \sum_{m \in \mathcal{L}(t)} A_m $$
$$ \widehat{p}_t \equiv \frac{1}{\widehat{A}_t} \sum_{m \in \mathcal{L}(t)} A_m \, p_m $$
$$ \widehat{r}_t \equiv \max_{m \in \mathcal{L}(t)} \|p_m - \widehat{p}_t\| $$
$$ \widehat{b}_t \equiv \frac{1}{\widehat{A}_t} \sum_{m \in \mathcal{L}(t)} A_m n_m b_m $$
Here $\mathcal{L}(t)$ is the set of leaf nodes that are successors of node $t$.

The dipole sum contribution of a distant cluster is approximated by [S1]:
$$ \sum_{m \in \mathcal{L}(t)} A_m P_\varepsilon(x, p_m) b_m \approx \widehat{A}_t S \left( \frac{\|\widehat{p}_t - x\|}{\varepsilon} \right) \frac{\widehat{b}_t \cdot (\widehat{p}_t - x)}{\|\widehat{p}_t - x\|^3} $$
Here $P_\varepsilon$ is the dipole kernel, $S$ is a scaling function, and $\widehat{b}_t$ is treated as a vector derived from the normal and moment attributes.

**Algorithm Steps:**
1.  **Build Tree:** Construct the hierarchical tree structure where leaf nodes correspond to individual points and internal nodes subdivide the point cloud $P$ into clusters [S1].
2.  **Compute Attributes:** Calculate $\widehat{A}_t, \widehat{p}_t, \widehat{r}_t, \widehat{b}_t$ for all nodes, starting from leaves and moving up to the root [S1].
3.  **Query (Primal/Adjoint):** For a query point $x$, traverse the tree starting from the root.
    *   For each node $t$, check if it is "far" from $x$. The condition for termination/approximation is [S1]:
        $$ \|x - \widehat{p}_t\| > \beta \cdot \widehat{r}_t $$
    *   If the condition is true, apply the approximation formula using the node's aggregated attributes and return the result for this branch [S1].
    *   If the condition is false (node is "close"), recursively visit the children of node $t$ [S1].
    *   If the node is a leaf, compute the exact contribution of the single point [S1].

**Pseudocode:**
```python
def compute_dipole_sum_approximation(node, x, epsilon, beta):
    """
    Computes the dipole sum contribution of a node and its descendants.
    node: Tree node with attributes A_hat, p_hat, r_hat, b_hat, and children list.
    x: Query point (vector).
    epsilon: Regularization parameter.
    beta: Separation criterion.
    """
    # Calculate distance from query point to cluster centroid
    dist_vec = node.p_hat - x
    dist_norm = norm(dist_vec)
    
    # Check separation criterion
    # If the cluster is far enough, use the Barnes-Hut approximation
    if dist_norm > beta * node.r_hat:
        # Approximation formula
        # S is a scaling function dependent on dist_norm / epsilon
        # b_hat is treated as a vector for the dot product
        # Note: Exact implementation of S() depends on the specific dipole kernel definition
        scaling_factor = S(dist_norm / epsilon)
        term = scaling_factor * (node.b_hat dot dist_vec) / (dist_norm ** 3)
        return node.A_hat * term
    else:
        # Cluster is close, must visit children
        total_sum = 0.0
        if node.is_leaf():
            # Exact calculation for single point
            # This requires access to the specific point's attributes (A_m, p_m, b_m)
            # stored in the leaf node
            point = node.point_data
            dist_vec_exact = point.p - x
            dist_norm_exact = norm(dist_vec_exact)
            # Exact kernel evaluation P_epsilon(x, p_m) * b_m
            exact_term = evaluate_dipole_kernel(point, x, epsilon) * point.b
            return point.A * exact_term
        else:
            # Recursively sum contributions from children
            for child in node.children:
                total_sum += compute_dipole_sum_approximation(child, x, epsilon, beta)
            return total_sum
```

**Parameters:**
*   $\beta$: Separation criterion. Typical values are not explicitly given in the sources, but it controls the trade-off between accuracy and speed [S1].
*   $\varepsilon$: Regularization parameter [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The approximation relies on the distance being significantly larger than the cluster radius. If $\beta$ is too small, accuracy degrades; if too large, performance gains are lost [S1].
*   **Boundaries:** The method assumes a hierarchical subdivision. Degenerate cases (e.g., all points at the same location) may require special handling in tree construction [S1].
*   **Adjoint Queries:** The adjoint query (gradient computation) follows a similar traversal logic, terminating early for distant clusters and backpropagating through the approximation formula [S1].

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ relative to point cloud size $N$, compared to $O(N)$ for naive summation [S1].
*   **Memory Complexity:** $O(N)$ to store the tree structure and point attributes [S1].
*   **Performance:** Enables inverse rendering at speeds competitive with rasterization methods, particularly beneficial for dense point clouds from structure-from-motion [S1].
*   **Strengths:** Dramatic acceleration of both primal and adjoint queries, making large-scale point cloud rendering feasible [S1].
*   **Limitations:** Approximation error depends on $\beta$ and the distribution of points. Not suitable for high-accuracy requirements where exact summation is mandatory [S1].

## Background
The method is based on the classical Barnes-Hut fast summation algorithm, originally applied to the winding number by Barill et al. [2018] [S1]. It was adapted for dipole sums in the context of 3D reconstruction with fast dipole sums [S1]. The approach allows for efficient evaluation of geometry and radiance fields in point-based representations, facilitating inverse rendering [S1].
