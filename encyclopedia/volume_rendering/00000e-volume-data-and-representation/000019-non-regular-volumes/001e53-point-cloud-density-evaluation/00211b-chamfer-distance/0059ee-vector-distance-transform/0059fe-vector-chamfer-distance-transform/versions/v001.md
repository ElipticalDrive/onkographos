# Vector Chamfer Distance Transform

Also called: VCVDT

## Overview
The Vector Chamfer Distance Transform (VCVDT) is a method for generating volume data from triangle models by computing distance values to identify part design characteristics, such as heavy and thin sections [S1, S2, unofficial]. It distinguishes itself from standard scalar Chamfer Distance Transforms by utilizing vector information within masks to achieve more precise distance estimation results [Parent]. It is one of the algorithms used in programs for creating volume data from triangle models, alongside Brute Force, CDTs, and EVDT [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A stereolithography (SLA) file or polygon model [S2, unofficial].
- Output: A voxel model with distance values assigned to voxels, identifying local maximum distance values for thin section analysis [S2, unofficial].

**Data Structures:**
- The volume is represented as a 3D grid of voxels [S2, unofficial].
- Each voxel stores a distance value [S2, unofficial].
- The computation requires access to neighboring voxels: 26 neighbors for the 3-4-5 chamfer metric and 6 direct orthogonal neighbors for the city-block metric [S2, unofficial].

**Steps:**
1. **Voxelization:** Convert the input triangle model into a voxel grid at a user-specified resolution and accuracy [S1, S2, unofficial].
2. **Distance Computation:** Compute distance values for each voxel using a chosen metric:
   - **Quantitative Analysis (3-4-5 Chamfer):** For each voxel, check all 26 neighboring voxels to compute the distance [S2, unofficial].
   - **Qualitative Analysis (City-Block):** For each voxel, check only the 6 direct orthogonal neighbors to compute the distance [S2, unofficial].
3. **Thin Section Analysis:** Scan the volume once to identify voxels with a local maximum distance value, which indicates thin sections [S2, unofficial].

**Parameters:**
- **Metric:** 3-4-5 chamfer metric for quantitative analysis or city-block metric for qualitative analysis [S2, unofficial].
- **Resolution:** User-specified resolution and accuracy for voxelization [S1, unofficial].

**Edge Cases and Pitfalls:**
- The time required for voxelization depends on the number and size of polygons, volume size, and shape complexity [S2, unofficial].
- The distance transformation time is approximately proportional to the volume size (number of voxels) [S2, unofficial].

def vector_chamfer_distance_transform(volume, metric='3-4-5'):
    """
    Compute distance transform for a voxel volume.
    
    Args:
        volume: 3D array of voxels (1 for inside, 0 for outside).
        metric: '3-4-5' for quantitative analysis, 'city-block' for qualitative.
        
    Returns:
        distance_volume: 3D array of distance values.
    """
    # Initialize distance volume with infinity
    distance_volume = np.full(volume.shape, np.inf)
    
    # Identify boundary voxels (inside voxels adjacent to outside)
    # Note: Exact boundary detection logic is not provided in sources [G]
    boundary_voxels = find_boundary_voxels(volume)
    
    # Set initial distance for boundary voxels to 0
    for voxel in boundary_voxels:
        distance_volume[voxel] = 0
        
    # Propagate distances
    if metric == '3-4-5':
        # Check all 26 neighbors
        neighbors = get_26_neighbors()
    elif metric == 'city-block':
        # Check 6 direct orthogonal neighbors
        neighbors = get_6_neighbors()
    else:
        raise ValueError("Unknown metric")
        
    # Iterative propagation until convergence
    # Note: Specific iteration scheme (e.g., forward-backward) is not provided in sources [G]
    while not_converged(distance_volume, neighbors):
        for voxel in volume.nonzero():
            min_dist = np.inf
            for neighbor in neighbors(voxel):
                if volume[neighbor]:
                    dist = compute_distance(voxel, neighbor, metric) + distance_volume[neighbor]
                    if dist < min_dist:
                        min_dist = dist
            if min_dist < distance_volume[voxel]:
                distance_volume[voxel] = min_dist
                
    return distance_volume

def find_local_maxima(distance_volume):
    """
    Identify voxels with local maximum distance values.
    """
    local_maxima = []
    for voxel in distance_volume.nonzero():
        if is_local_maximum(voxel, distance_volume):
            local_maxima.append(voxel)
    return local_maxima

## Subtopics

### Distance Transform for Wall Thickness Evaluation
This variant uses distance transforms to evaluate part design by computing distance values for voxels to identify heavy and thin sections [S2, unofficial]. It employs two metrics: the 3-4-5 chamfer metric for quantitative analysis (checking all 26 neighboring voxels) and the city-block metric for qualitative analysis (checking only 6 direct orthogonal voxels) [S2, unofficial]. The qualitative analysis is 2-3 times faster than the quantitative analysis due to the reduced number of neighbors checked [S2, unofficial].

## Operating characteristics
- **Time Complexity:** The distance transformation time is approximately proportional to the volume size (number of voxels) [S2, unofficial].
- **Performance:** Qualitative analysis (city-block) is 2-3 times faster than quantitative analysis (3-4-5 chamfer) because it uses fewer neighbors (6 vs 26) [S2, unofficial].
- **Voxelization Time:** Depends on the number and size of polygons, volume size, and shape complexity [S2, unofficial].
- **Strengths:** Extremely efficient for distance transformation; suitable for identifying thin sections in die casting parts [S2, unofficial].
- **Limitations:** Voxelization time can be significant for complex shapes with large volumes and many polygons [S2, unofficial].

## Background
The Vector Chamfer Distance Transform was used in a prototype system for evaluating die casting part and die design, which accepts stereolithography (SLA) files as input and generates voxel models [S2, unofficial]. The system was implemented on an IBM R6000 37" workstation with 128 MB memory and Power Gt4e Graphics Adapter [S2, unofficial]. It is also mentioned in the context of volume data generation from triangle meshes, where it is one of several algorithms used [S1, unofficial].
