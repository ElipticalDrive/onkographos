# Chamfer Distance
Also called: Bidirectional Chamfer Distance

## Overview
Chamfer Distance (CD) is a symmetric geometric metric that evaluates the reconstruction accuracy of 3D surfaces by measuring the average closest-point distance between two point clouds: a predicted set and a ground-truth set [S1, unofficial][S2, S3, S4]. It solves the problem of quantifying geometric fidelity in implicit surface representations (such as SDFs and UDFs) and explicit mesh reconstructions, where traditional pixel-wise errors are insufficient [S1, S6, unofficial]. Unlike its siblings in Point Cloud Density Evaluation, which may focus on local density or probabilistic occupancy, CD assesses global surface alignment by computing bidirectional nearest-neighbor distances [S3].

## How it works
**Inputs and Outputs:**
- **Input:** Two point clouds, $P_{pred}$ (predicted) and $P_{GT}$ (ground truth), or $\chi_1$ and $\chi_2$. Each point is a 3D coordinate vector $\mathbf{p} \in \mathbb{R}^3$ [S2, S3, S4].
- **Output:** A scalar value representing the bidirectional Chamfer Distance [S1, unofficial][S2].

**Data Structures:**
- Point clouds are typically stored as arrays of shape $(N, 3)$, where $N$ is the number of points [S8, S11, unofficial].
- For efficient nearest-neighbor search, a spatial index such as a KD-Tree is built from the ground-truth point cloud [S8, unofficial].

**Formula:**
The standard bidirectional Chamfer Distance is defined as [S1, unofficial][S2, S3, S4, S5]:

$$
CD(P_{pred}, P_{GT}) = \frac{1}{|P_{pred}|} \sum_{p \in P_{pred}} \min_{q \in P_{GT}} \|p - q\|_2 + \frac{1}{|P_{GT}|} \sum_{q \in P_{GT}} \min_{p \in P_{pred}} \|q - p\|_2
$$

Where:
- $|P|$ denotes the cardinality (number of points) of the set $P$ [S3, S4].
- $\|\cdot\|_2$ is the Euclidean norm [S3, S4].
- The first term computes the average distance from each predicted point to its nearest neighbor in the ground-truth set.
- The second term computes the average distance from each ground-truth point to its nearest neighbor in the predicted set.

**Parameters:**
- **Sampling Count:** The number of points used for evaluation significantly impacts the metric. Standard evaluations often use 300,000 uniformly sampled points from the reconstructed and ground-truth meshes [S3]. Other implementations may use 3,000 points [S7].
- **Threshold (for F-Score):** While CD itself is a distance, it is often paired with F-Score, which uses a distance threshold $t$. A typical value for $t$ is 0.01 [S7].

**Edge Cases and Pitfalls:**
- **Unequal Point Counts:** The formula normalizes by the cardinality of each set independently, so $|P_{pred}|$ does not need to equal $|P_{GT}|$ [S1, unofficial][S2].
- **Precision:** The metric is sensitive to outliers. A single distant point can significantly increase the average distance [S3].
- **Sampling Bias:** Uniform sampling on meshes with varying curvature can lead to biased evaluations if not handled carefully (e.g., area-weighted sampling) [S3].

**Pseudocode:**
The following Python-like pseudocode implements the standard bidirectional Chamfer Distance using a KD-Tree for efficient nearest-neighbor queries.

```python
import numpy as np
from scipy.spatial import KDTree

def chamfer_distance(points_pred, points_gt):
    """
    Compute the bidirectional Chamfer Distance between two point clouds.
    
    Args:
        points_pred: numpy array of shape (N, 3), predicted points.
        points_gt: numpy array of shape (M, 3), ground truth points.
        
    Returns:
        cd: float, the bidirectional Chamfer Distance.
    """
    # Build KD-Tree from ground truth points for efficient nearest neighbor search
    tree_gt = KDTree(points_gt)
    
    # Compute distance from each predicted point to its nearest ground truth point
    # k=1 returns the nearest neighbor
    distances_pred_to_gt, _ = tree_gt.query(points_pred, k=1)
    
    # Build KD-Tree from predicted points for the reverse direction
    tree_pred = KDTree(points_pred)
    
    # Compute distance from each ground truth point to its nearest predicted point
    distances_gt_to_pred, _ = tree_pred.query(points_gt, k=1)
    
    # Calculate mean distances
    mean_dist_pred = np.mean(distances_pred_to_gt)
    mean_dist_gt = np.mean(distances_gt_to_pred)
    
    # Sum the bidirectional averages
    cd = mean_dist_pred + mean_dist_gt
    
    return cd
```

## Subtopics

### [Edge Chamfer Distance](6089-edge-chamfer-distance.md)
Edge Chamfer Distance (ECD) is a variant that calculates the symmetric distance between two point clouds sampled specifically from the edges of meshes, rather than their surfaces. It solves the problem of evaluating edge reconstruction quality and geometric sharpness, which standard surface-based Chamfer Distance fails to capture adequately. Unlike the parent method [Chamfer Distance](2446-chamfer-distance.md) which assesses global surface fidelity, ECD isolates the structural integrity of sharp features and boundaries.

### [Pairwise Chamfer Distance via Relative Transform](13046-pairwise-chamfer-distance-via-relative-transform.md)
Computes the symmetric Chamfer distance between two sets of world-to-link transforms by evaluating the geometric error of sampled mesh points under the relative transformation between each pair of transforms. It differs from standard point-cloud Chamfer distance by operating in transform space, using relative rigid-body motions to align sampled surface points for distance evaluation.

### Mean Distance Computation
A variant step described in [S8, unofficial] where points are converted to a numpy array and a KD-Tree is built. The mean squared distance to the 3 nearest neighbors (excluding self, hence indices 1:4) is computed and returned as a tensor. This differs from the standard CD by using squared distances and a fixed number of neighbors (3) rather than the single nearest neighbor.

### Global Chamfer Distance
Measures global geometric accuracy by computing bidirectional CD between uniformly sampled point sets from the reconstructed mesh surface ($\mathbf{S}_r$) and ground truth surface ($\mathbf{S}_{\text{gt}}$) [S3]. The formula is $\text{CD}_{\text{glo}} = \mathcal{L}_{\text{CD}}(\mathbf{S}_r, \mathbf{S}_{\text{gt}})$ [S3]. It is typically computed using 300K sampled points [S3].

### DCCVT Loss Functions
In the context of Differentiable Clipped Centroidal Voronoi Tessellation (DCCVT), a specific Chamfer-based loss is used [S9]. The loss $\mathcal{L}_{\text{CD}}$ is defined as $\min_{\text{dist}} \left( \{\|\mathbf{p} - \mathbf{v}_i\|^2, \|\mathbf{p} - \mathbf{b}_{ij}\|^2\} \right)$, where $\mathbf{p}$ are points from the input point cloud, $\mathbf{v}_i$ are projected Voronoi vertices, and $\mathbf{b}_{ij}$ are projected edge midpoints [S9]. This encourages Voronoi vertices and edges to lie close to the input point cloud.

### Batched Unidirectional Chamfer Distance
Computes the batched unidirectional chamfer distance between observed world-frame surface points and the surface points of an object transformed by a set of 4x4 rigid transform matrices [S10, unofficial]. The steps involve:
1. Getting batch size $B$ and number of evaluation points [S10, unofficial].
2. Creating a `Transform3d` object from world-to-object matrices [S10, unofficial].
3. Transforming model points from world frame to object frame [S10, unofficial].
4. Querying an SDF or object factory for distance $d$ [S10, unofficial].
5. Computing chamfer distance as $(\text{scale} \times d)^2$ [S10, unofficial].
6. Averaging the chamfer distance across evaluation points [S10, unofficial].
The parameter `scale` defaults to 1000, converting distance to mm if input is in meters [S10, unofficial].

### Chamfer Distance with Color
Extends CD to include color information [S11, unofficial]. The steps are:
1. Split input tensors into coordinates (first 3 channels) and colors (last 3 channels) [S11, unofficial].
2. Compute normalization factor as the maximum L2 norm of coordinates across the batch [S11, unofficial].
3. Compute pairwise geometric distance matrix, find minimum geometric distance and indices for both directions [S11, unofficial].
4. Retrieve nearest neighbor colors using gathered indices [S11, unofficial].
5. Compute color distances as L2 norms between original and nearest neighbor colors [S11, unofficial].
6. Calculate final loss as $\alpha \cdot \text{mean}(\text{geo}_{x \to y}) + \alpha \cdot \text{mean}(\text{geo}_{y \to x}) + (1 - \alpha) \cdot \text{mean}(\text{color}_{1}) + \text{mean}(\text{color}_{2})$ [S11, unofficial].
The parameter `alpha` balances geometric and color distances, defaulting to 0.5 [S11, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Building a KD-Tree takes $O(N \log N)$ time and $O(N)$ space [S8, unofficial].
- Querying nearest neighbors for $M$ points takes $O(M \log N)$ time [S8, unofficial].
- Total time complexity for bidirectional CD is $O((N+M) \log (\max(N,M)))$ [S8, unofficial].
- Memory complexity is dominated by the storage of the point clouds and the KD-Tree structure, $O(N+M)$ [S8, unofficial].

**Measured Performance:**
- On the 'chair' scene, AugNeRF achieved a CD of $1.04 \times 10^{-2}$, which is 29.25% lower than vanilla NeRF ($1.47 \times 10^{-2}$) [S5].
- On the ABC dataset, a method achieved a CD of 3.15 [S4].

**Scaling:**
- The metric scales linearly with the number of points if the KD-Tree construction is amortized or if the number of points is fixed [S3].
- Higher resolution meshes require more points for accurate sampling, increasing computational cost [S4].

**Strengths and Limitations:**
- **Strengths:** Simple to compute, differentiable (useful for training), and provides a global measure of surface accuracy [S1, unofficial][S3].
- **Limitations:** Sensitive to outliers and noise; does not account for surface normals or texture directly (unless extended) [S3][S6, unofficial]. It may not capture local geometric details as effectively as normal consistency or depth error metrics [S6, unofficial].

**When to Use:**
- Use CD for evaluating the overall geometric accuracy of reconstructed meshes or point clouds from implicit fields [S1, unofficial][S3].
- Use it when a single scalar metric is needed to compare different reconstruction methods [S4].

**When Not to Use:**
- Do not use CD alone if sharp edges or boundaries are critical; use Edge Chamfer Distance instead [S1, unofficial][S3].
- Do not use CD if normal accuracy is the primary concern; use Normal Consistency (NC) [S2, S4].

## Background
Chamfer Distance originated as a metric for comparing point sets and has become a standard evaluation tool in 3D reconstruction, particularly for Neural Radiance Fields (NeRFs) and Signed Distance Fields (SDFs) [S1, unofficial][S5]. It was formally adopted in the context of SDF-based NeRFs to measure the average closest-point distance between predicted and ground-truth point clouds [S1, unofficial]. The metric is widely used in benchmarks such as ABC, Thingi10k, DTU, and Tanks & Temples [S4][S6, unofficial]. Variants like Global CD, Non-manifold CD, and Boundary CD were derived to evaluate specific aspects of reconstruction quality, such as global accuracy and edge continuity [S3].
