# KDTree-based Neighbor Counting

Also called: KDTree Density Evaluation, Per-Voxel Point Density Calculation via KDTree

## Overview
This method calculates the density of mesh vertices within each voxel of a volume grid by querying neighboring points using a KDTree and normalizing the resulting counts [S1, unofficial]. It solves the problem of converting discrete point cloud or mesh data into a volumetric density field suitable for visualization or further processing [S1, unofficial]. It distinguishes itself from its siblings by using a spatial index (KDTree) for efficient neighbor retrieval rather than grid-based binning [11706-grid-based-dbscan.md] or kernel smoothing [13917-kernel-density-estimation-kde.md], and from [5598-clusterability-check.md] by focusing on scalar density estimation rather than cluster validity.

## How it works
**Inputs:**
- A set of mesh vertices (points) $P = \{p_1, ..., p_N\}$.
- A voxel grid definition with side length $x$.
- The number of voxels or grid dimensions.

**Outputs:**
- A voxel grid where each voxel contains a normalized density field value in the range $[0, 1]$.

**Data Structures:**
- **KDTree**: A spatial data structure built from the input points $P$. In SciPy, this is typically a `KDTree` object.
- **Voxel Grid**: A 3D array or list of voxel objects, each storing a center coordinate and a density value.

**Steps:**
1. **Calculate Equivalent Sphere Radius**: Determine the radius $r$ of a sphere that has the same volume as a single voxel cube with side length $x$. The volume of the cube is $V_{cube} = x^3$. The volume of a sphere is $V_{sphere} = \frac{4}{3}\pi r^3$. Equating them:
   $$ x^3 = \frac{4}{3}\pi r^3 $$
   Solving for $r$:
   $$ r = x \left( \frac{3}{4\pi} \right)^{1/3} $$
   [S1, unofficial]

2. **Build KDTree**: Construct a KDTree from the input mesh vertices $P$. [S1, unofficial]

3. **Query Neighbors**: For each voxel center $c_i$ in the grid:
   - Use the KDTree to find all points within distance $r$ from $c_i$. This is typically done using a function like `query_ball_point`. [S1, unofficial]
   - Let $N_i$ be the count of points found in this neighborhood.

4. **Normalize Counts**: Find the maximum count $N_{max} = \max_i(N_i)$ across all voxels. Normalize each voxel's count:
   $$ d_i = \frac{N_i}{N_{max}} $$
   [S1, unofficial]

5. **Attach Field**: Store $d_i$ as a field value associated with voxel $i$. [S1, unofficial]

**Parameters:**
- $x$: Voxel side length. Typical values depend on the scene scale and desired resolution.
- $r$: Calculated radius. Not a free parameter, but derived from $x$.

**Edge Cases and Pitfalls:**
- **Boundary Imperfection**: Using a spherical query for cubic voxels yields imperfect boundary results, as the sphere extends beyond the cube faces. This is a known simplification. [S1, unofficial]
- **Empty Voxels**: Voxels with no neighbors will have a count of 0.
- **Max Count Zero**: If no points exist, $N_{max}$ is 0, leading to division by zero. This should be handled by checking if $N_{max} > 0$. [G]

**Pseudocode:**
```python
import numpy as np
from scipy.spatial import KDTree

def kd_tree_neighbor_counting(points, voxel_side_length):
    """
    Calculate per-voxel density using KDTree neighbor counting.
    
    Args:
        points: Array of shape (N, 3) containing mesh vertices.
        voxel_side_length: Float, side length x of the voxel cubes.
        
    Returns:
        voxel_centers: Array of shape (M, 3) with voxel centers.
        densities: Array of shape (M,) with normalized density values.
    """
    # Step 1: Calculate equivalent sphere radius
    # r = x * (3 / (4 * pi))^(1/3)
    r = voxel_side_length * (3.0 / (4.0 * np.pi)) ** (1.0 / 3.0)
    
    # Step 2: Build KDTree
    tree = KDTree(points)
    
    # Step 3: Define voxel grid centers (example: uniform grid over bounding box)
    # Note: In a real implementation, voxel_centers would be generated based on 
    # the scene bounds and resolution. Here we assume they are provided or computed.
    # For this self-contained example, we assume a simple grid over the point bounds.
    bounds = np.array([points.min(axis=0), points.max(axis=0)])
    # Generate a coarse grid for demonstration; in practice, this is defined by the user.
    # We'll use a fixed number of voxels per dimension for simplicity.
    n_voxels_per_dim = 10
    voxel_centers = np.array(np.meshgrid(
        np.linspace(bounds[0,0], bounds[1,0], n_voxels_per_dim),
        np.linspace(bounds[0,1], bounds[1,1], n_voxels_per_dim),
        np.linspace(bounds[0,2], bounds[1,2], n_voxels_per_dim)
    )).T.reshape(-1, 3)
    
    # Step 4: Query neighbors and count
    counts = np.zeros(len(voxel_centers), dtype=int)
    for i, center in enumerate(voxel_centers):
        # query_ball_point returns indices of points within radius r
        neighbors = tree.query_ball_point(center, r)
        counts[i] = len(neighbors)
        
    # Step 5: Normalize
    max_count = np.max(counts)
    if max_count == 0:
        densities = np.zeros_like(counts, dtype=float)
    else:
        densities = counts / max_count
        
    return voxel_centers, densities
```

## Operating characteristics
- **Time Complexity**: Building the KDTree is $O(N \log N)$. Querying neighbors for $M$ voxels is $O(M \cdot K)$ where $K$ is the average number of neighbors found, but worst-case can be higher depending on data distribution. [S1, unofficial]
- **Memory Complexity**: $O(N)$ for storing the KDTree and points. [S1, unofficial]
- **Strengths**: Simple to implement using standard libraries (e.g., SciPy). Efficient for moderate-sized datasets. [S1, unofficial]
- **Limitations**: Spherical query approximation for cubic voxels introduces boundary errors. [S1, unofficial] Performance may degrade for very large point clouds without optimizations like those in [10966-efficient-knn-implementation.md].
- **When to Use**: When a quick density estimate is needed for visualization or thresholding, and the dataset size is manageable. [S1, unofficial]
- **When Not to Use**: For real-time rendering of massive point clouds where $O(N^2)$ or high query costs are prohibitive. [S1, unofficial]
