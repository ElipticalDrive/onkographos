# KDTree-based Neighbor Counting

Also called: KDTree Density Evaluation, Per-Voxel Point Density Calculation via KDTree

## Overview
This method calculates the density of mesh vertices within each voxel of a volume grid by querying neighboring points using a KDTree and normalizing the counts. It solves the problem of quantifying point cloud density in a voxelized representation, which is a useful analysis step not always present in standard visualization libraries. It distinguishes itself from siblings like [Grid-based DBSCAN](11706-grid-based-dbscan.md) by using a fixed spherical radius query rather than density-based clustering, and from [Parzen Density Estimation](11796-parzen-density-estimation.md) by using discrete vertex counts rather than continuous kernel weighting.

## How it works
**Inputs and Outputs:**
- Input: A set of mesh vertices (points) and a voxel grid defined by side length $x$.
- Output: A voxel grid where each voxel has an attached field containing a normalized density value between 0 and 1.

**Data Structures:**
- **Voxel Grid:** A 3D array or hash map mapping voxel coordinates to a density value.
- **KDTree:** A spatial data structure built from the input mesh vertices to enable efficient nearest-neighbor queries.

**Steps:**
1.  **Calculate Sphere Radius:** Determine the radius $r$ of a sphere that has the same volume as the voxel cube with side length $x$. The formula is:
    $$ r = x \cdot \left( \frac{3}{4 \pi} \right)^{1/3} $$
    where $x$ is the voxel cube side length and $r$ is the equivalent-volume sphere radius [S1, unofficial].
2.  **Build KDTree:** Construct a KDTree from the input mesh vertices.
3.  **Query Neighbors:** For each voxel center, use the KDTree to find all mesh vertices within the spherical radius $r$. This is typically done using a function like `query_ball_point` [S1, unofficial].
4.  **Count Vertices:** Count the number of vertices found in the neighborhood of each voxel center.
5.  **Normalize Counts:** Find the maximum count across all voxels. Divide each voxel's count by this maximum to scale the values between 0 and 1.
6.  **Attach Field:** Assign the normalized density value to the corresponding voxel.

**Pseudocode:**
```python
import numpy as np
from scipy.spatial import KDTree
import math

def kd_tree_neighbor_counting(vertices, voxel_centers, voxel_side_length):
    """
    Calculate normalized point density for each voxel using KDTree.
    
    Args:
        vertices: Array of shape (N, 3) containing mesh vertex coordinates.
        voxel_centers: Array of shape (M, 3) containing the center coordinates of each voxel.
        voxel_side_length: Float, the side length x of the cubic voxels.
        
    Returns:
        densities: Array of shape (M,) containing normalized density values for each voxel.
    """
    # Step 1: Calculate sphere radius r with volume equal to voxel cube volume
    # Volume of cube = x^3
    # Volume of sphere = (4/3) * pi * r^3
    # Equating: x^3 = (4/3) * pi * r^3 => r = x * (3 / (4 * pi))^(1/3)
    r = voxel_side_length * (3.0 / (4.0 * math.pi)) ** (1.0 / 3.0)
    
    # Step 2: Build KDTree from vertices
    tree = KDTree(vertices)
    
    # Step 3: Query neighbors for each voxel center
    # query_ball_point returns a list of indices for each query point
    neighbor_indices_list = tree.query_ball_point(voxel_centers, r)
    
    # Step 4: Count vertices in each neighborhood
    counts = np.array([len(indices) for indices in neighbor_indices_list])
    
    # Step 5: Normalize counts by dividing by the maximum count
    max_count = np.max(counts)
    if max_count == 0:
        densities = np.zeros_like(counts, dtype=float)
    else:
        densities = counts / max_count
        
    # Step 6: Return densities (to be attached as a field to voxels)
    return densities
```

**Edge Cases and Pitfalls:**
- **Boundary Imperfection:** Using a spherical query for cubic voxels yields imperfect boundary results, as the sphere extends beyond the cube faces [S1, unofficial]. This is a known simplification.
- **Empty Voxels:** If no vertices are found within the radius, the count is 0. Normalization handles this correctly if the maximum count is non-zero.
- **Precision:** Ensure floating-point precision is sufficient for radius calculation, especially for very small or large voxel sizes.

## Operating characteristics
- **Time Complexity:** Building the KDTree is $O(N \log N)$ where $N$ is the number of vertices. Querying all $M$ voxel centers is $O(M \log N)$ on average, but worst-case can be $O(M \cdot N)$ if the radius is large relative to the point distribution.
- **Memory Complexity:** $O(N)$ to store the KDTree and vertex data. $O(M)$ to store the results.
- **Strengths:** Simple to implement using standard libraries (e.g., SciPy). Provides a direct count of points in a local neighborhood.
- **Limitations:** The spherical query approximation for cubic voxels introduces boundary errors. Performance degrades with very large datasets if not optimized (see [Efficient kNN Implementation](10966-efficient-knn-implementation.md)).
- **When to Use:** When a quick, approximate density estimate is needed for visualization or analysis, and the dataset size is manageable.
- **When Not to Use:** When high precision at voxel boundaries is required, or when dealing with extremely large point clouds where $O(M \log N)$ is too slow.
