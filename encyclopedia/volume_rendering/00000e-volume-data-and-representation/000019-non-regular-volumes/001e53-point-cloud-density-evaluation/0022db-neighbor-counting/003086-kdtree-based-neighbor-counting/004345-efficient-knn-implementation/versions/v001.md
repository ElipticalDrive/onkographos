# Efficient kNN Implementation

Also called: Customized CUDA kNN, Local kNN with Camera Parameters

## Overview
Efficient kNN Implementation provides scalable nearest-neighbor search for point cloud density evaluation in volume rendering, specifically addressing the computational bottleneck of global kNN at high resolutions. It distinguishes itself by switching between a brute-force CUDA implementation for small datasets and a camera-aware local search for large datasets, reducing complexity from $O(N^2)$ to $O(N \cdot C)$ by leveraging multi-view geometric constraints [S1].

## How it works
The method selects an algorithm based on the total point count $N$ and the number of views. It constructs a candidate set of size $C$ using camera parameters to restrict the search space, then computes exact 3D distances within this set to select the top-$k$ neighbors [S1].

**Inputs:**
- Point cloud $P$ with $N$ points.
- Number of nearest neighbors $k$.
- Camera parameters (poses and intrinsics) for $V$ views.
- Threshold $T$ for switching modes (e.g., $T = 300,000$) [S1].

**Outputs:**
- For each point $p_i \in P$, a list of $k$ nearest neighbor indices.

**Data Structures:**
- **Candidate Set $C_{set}$**: A list of point indices. Size is $C$.
- **Distance Array**: Stores squared Euclidean distances between $p_i$ and points in $C_{set}$.

**Steps:**
1. **Mode Selection**: If $N < T$, use Customized CUDA Global kNN [S1]. Else, use Efficient Local kNN [S1].
2. **Candidate Construction (Local Mode)**:
   - For each point $p_i$, identify its source view $v_i$.
   - **Spatial Neighbors**: Query points in $P$ that belong to the same view $v_i$ and are spatially close (e.g., within a bounding box or radius) [S1].
   - **Cross-View Neighbors**: Identify nearby cameras $v_j$ (based on camera pose proximity). Project points from $v_j$ into the coordinate system of $v_i$ or use 3D positions if available. Aggregate these points into the candidate set [S1].
   - Limit the total candidate set size to $C$ [S1].
3. **Distance Computation**:
   - Compute squared Euclidean distance $d^2(p_i, p_j) = \|p_i - p_j\|^2$ for all $p_j \in C_{set}$ [S1].
4. **Top-k Selection**:
   - Sort the candidate distances.
   - Select the indices of the $k$ smallest distances [S1].

**Pseudocode:**
```python
def efficient_knn(points, k, camera_params, threshold=300000):
    """
    points: List of 3D coordinates (N, 3)
    k: Number of neighbors
    camera_params: Dict or list containing camera poses and view indices for each point
    threshold: Point count threshold for switching methods
    """
    N = len(points)
    
    # Step 1: Mode Selection
    if N < threshold:
        # Use customized CUDA implementation [S1]
        # Note: Specific CUDA kernel details are not provided in sources [G]
        return cuda_global_knn(points, k)
    
    # Step 2: Efficient Local kNN
    candidates = []
    neighbors = []
    
    # Pre-calculate camera proximity if needed [S1]
    # For each point, build candidate set C using camera parameters [S1]
    for i in range(N):
        p_i = points[i]
        view_i = camera_params[i].view_id
        pose_i = camera_params[i].pose
        
        # Aggregate spatial neighbors from same view [S1]
        same_view_indices = get_spatial_neighbors_same_view(points, view_i, p_i)
        
        # Aggregate cross-view neighbors from nearby cameras [S1]
        nearby_cameras = get_nearby_cameras(camera_params, pose_i)
        cross_view_indices = []
        for cam in nearby_cameras:
            # Project or retrieve points from nearby view
            cross_view_indices.extend(get_points_from_view(points, cam.view_id))
            
        # Combine and limit to constant size C [S1]
        candidate_indices = list(set(same_view_indices + cross_view_indices))
        # Truncate to C if necessary [S1]
        candidate_indices = candidate_indices[:C]
        
        # Step 3: Compute exact 3D distances within this set [S1]
        dists = []
        for idx in candidate_indices:
            p_j = points[idx]
            dist_sq = sum((p_i[d] - p_j[d])**2 for d in range(3))
            dists.append((dist_sq, idx))
            
        # Step 4: Top-k selection [S1]
        dists.sort(key=lambda x: x[0])
        top_k_indices = [idx for _, idx in dists[:k]]
        neighbors.append(top_k_indices)
        
    return neighbors
```

**Parameters:**
- $T$: Threshold for switching to local kNN. Typical value: 300,000 points [S1].
- $C$: Size of candidate set. Not given in the sources.
- $k$: Number of neighbors. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Precision**: Using squared Euclidean distance avoids square root computation but requires careful handling of large coordinate values to avoid overflow [G].
- **Boundary Conditions**: If a point has fewer than $k$ valid candidates in the local set, the result will contain fewer than $k$ neighbors [G].
- **Degenerate Input**: If camera parameters are missing or invalid, cross-view neighbor aggregation fails [G].

## Subtopics

### [Efficient Local kNN](10975-efficient-local-knn.md)
A drop-in $O(N)$ local k-nearest neighbors module that exploits the known multi-view grid structure to replace global brute-force search, reducing complexity from $O(N^2)$ to $O(N)$. It constructs a candidate set using camera parameters to aggregate spatial neighbors from the same view and cross-view neighbors projected from nearby cameras. Choose this method when point counts exceed 300K or when high-resolution rendering requires scalability. See [Efficient Local kNN](10975-efficient-local-knn.md).

### Reciprocal Nearest Neighbor Matching
Finds mutual nearest neighbors between two point sets $P_1$ and $P_2$ using KDTree to identify reciprocal matches [S2, unofficial]. It builds KDTree for both sets, queries each tree for the other's nearest neighbors, and computes the intersection of mutual matches [S2, unofficial]. Use this for matching points across different views or datasets where bidirectional consistency is required [S2, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N^2)$ for the customized CUDA global kNN [S1]. $O(N \cdot C)$ for the efficient local kNN, where $C$ is the constant candidate set size [S1].
- **Memory Complexity**: Not given in the sources.
- **Measured Performance**: The global kNN becomes a computational bottleneck at higher resolutions or view counts [S1]. The local kNN ensures scalability for massive point clouds [S1].
- **Strengths**: Scalability to high-resolution images and large point clouds via the local kNN alternative [S1].
- **Limitations**: The global kNN is limited to point counts < 300K [S1]. The local kNN depends on the accuracy of camera parameters and the definition of "nearby" cameras [S1].
- **When to Use**: Use global kNN for small point clouds (< 300K) [S1]. Use local kNN for larger datasets or high-resolution rendering [S1].

## Background
The method originates from ReSplat: Learning Recurrent Gaussian Splatting [S1]. It was developed to address the scalability issues of global kNN in Gaussian Splatting applications, where point counts can be very large. The efficient local kNN variant was introduced to reduce computational complexity by leveraging multi-view geometry [S1].
