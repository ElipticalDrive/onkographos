# K-Nearest Neighbors Query

Also called: KNNQuery

## Overview
A method to find the $k$ nearest neighbors for each point in a target set (new\_xyz) within a source set (xyz), returning indices and squared distances [S1, unofficial]. It performs K-Nearest Neighbors search on 3D points using a CUDA kernel, handling batched inputs with offsets [S1, unofficial]. It builds on [Efficient kNN Implementation](10966-efficient-knn-implementation.md) and differs from [Efficient Local kNN](10975-efficient-local-knn.md) by focusing on global batched queries with explicit offset management, and from [PointOps2 CUDA Kernels](13912-pointops2-cuda-kernels.md) by being a specific high-level API wrapper rather than a low-level kernel library [G].

## How it works
**Inputs:**
- `src`: Source point cloud coordinates, shape $(B, M, 3)$ or $(B, 3, M)$ depending on `transpose` [S1, unofficial].
- `x`: Query point cloud coordinates, shape $(B, N, 3)$ or $(B, 3, N)$ depending on `transpose` [S1, unofficial].
- `src_offset`: Cumulative offsets for the source set, shape $(B+1)$ [S1, unofficial].
- `x_offset`: Cumulative offsets for the query set, shape $(B+1)$ [S1, unofficial].
- `k`: Number of neighbors to find [S1, unofficial].
- `transpose`: Boolean flag indicating if input tensors are in $(B, 3, N)$ format [S1, unofficial].

**Outputs:**
- `idx`: Indices of the $k$ nearest neighbors in the source set, shape $(B, N, k)$, type `long` [S1, unofficial].
- `dist`: Euclidean distances to the neighbors, shape $(B, N, k)$ [S1, unofficial].

**Data Structures:**
- The offsets arrays `src_offset` and `x_offset` are 1D tensors of size $B+1$ storing cumulative batch start indices. For batch $b$, the points are located in the range `[offset[b], offset[b+1])` [S1, unofficial].

**Steps:**
1. If the query set `x` is `None`, default to using `src` as the query set [S1, unofficial].
2. If `transpose` is true, transpose `x` and `src` from $(B, N, 3)$ to $(B, 3, N)$ and make them contiguous [S1, unofficial].
3. Extract batch size $B$, query count $N$, and source count $M$ [S1, unofficial].
4. Reshape `x` to $(B \times N, 3)$ and `src` to $(B \times M, 3)$ [S1, unofficial].
5. Compute cumulative offsets `x_offset` and `src_offset` for the batched CUDA kernel call [S1, unofficial].
6. Call the CUDA kernel `knnquery(k, src, x, src_offset, x_offset)` to get indices `idx_raw` and squared distances `dist2` [S1, unofficial].
7. Adjust indices by subtracting `(src_offset - M)` to correct for batch offsets [S1, unofficial].
8. Reshape `idx` to $(B, N, k)$ and return as long integers [S1, unofficial].
9. Return `idx` and the square root of `dist2` [S1, unofficial].

**Pseudocode:**
```python
import torch

def knnquery(k, src, x, src_offset, x_offset, transpose=False):
    """
    k: int, number of neighbors
    src: Tensor (B, M, 3) or (B, 3, M)
    x: Tensor (B, N, 3) or (B, 3, N)
    src_offset: Tensor (B+1), cumulative offsets for src
    x_offset: Tensor (B+1), cumulative offsets for x
    transpose: bool, if True inputs are (B, 3, N)
    """
    if x is None:
        x = src.clone()
        
    if transpose:
        src = src.transpose(1, 2).contiguous()
        x = x.transpose(1, 2).contiguous()
        
    B, N, _ = x.shape
    _, M, _ = src.shape
    
    # Reshape to 2D for CUDA kernel
    src_flat = src.view(-1, 3) # (B*M, 3)
    x_flat = x.view(-1, 3)     # (B*N, 3)
    
    # External CUDA kernel call: idx_raw, dist2 = pointops_cuda.knnquery_cuda(k, src_flat, x_flat, src_offset, x_offset)
    idx_raw, dist2 = knnquery_cuda(k, src_flat, x_flat, src_offset, x_offset)
    
    # Adjust indices: subtract the base offset of the source for each batch
    # idx_raw is in the flattened space [0, B*M)
    # Reshape idx_raw to (B, N, k)
    idx_raw = idx_raw.view(B, N, k)
    
    # Create a tensor of batch indices for each query point
    batch_indices = torch.arange(B).view(B, 1, 1).expand(B, N, k).to(idx_raw.device)
    
    # Get the source offset for each query point's batch
    src_offsets_for_queries = src_offset[batch_indices]
    
    # Adjust indices (sources note: subtract (src_offset - m))
    idx_local = idx_raw - src_offsets_for_queries
    
    # Return indices and distances
    dist = torch.sqrt(dist2)
    
    return idx_local.long(), dist
```

**Parameters:**
- `k`: Typical values depend on the application density, e.g., 16, 32, 64 [G].
- `transpose`: False for standard $(B, N, 3)$ layout [G].

**Edge Cases:**
- If `x` is `None`, it defaults to `src` [S1, unofficial].
- Boundary conditions: Ensure `src_offset` and `x_offset` are correctly computed to avoid out-of-bounds access in the CUDA kernel [S1, unofficial].
- Precision issues may arise in squared distance calculations for very large coordinates; use double precision if necessary [G].

## Subtopics

### N-th Closest (Worley/Hart)
A basis function introduced by Worley and Hart [S2, book] that places 'feature points' at random locations in $\mathbb{R}^3$ and calculates the distance from a surface point to each of the $n$ closest feature points. It is used to index a color spline, adding a flagstone style texture to the surface of the object. It is chosen when procedural texturing with cellular noise patterns is required [S2, book].

### Point-to-Point Distance with Normals
Computes minimum distances from source points to target points, optionally incorporating normal alignment via dot products [S3, unofficial]. It builds a KDTree from target points, queries nearest neighbors for source points, and if normals are provided, normalizes both sets, computes the dot product between target normals at nearest indices and source normals, and takes the absolute value to handle flipped normals gracefully [S3, unofficial]. Implementation: `dist, idx = kdtree.query(points_src); normals_dot_product = np.abs((normals_tgt[idx] * normals_src).sum(axis=-1))` [S3, unofficial]. It is chosen when geometric alignment and surface normal consistency are required alongside distance metrics [S3, unofficial].

### Spatial Evaluation of Spectral Properties
Approximates continuous spatial evaluation of vertex-based spectral quantity $A$ at arbitrary point $p$ via barycentric interpolation $b_p(A)$ [S4]. It computes spectral embeddings at vertices $Z = \Phi_{iso} (\Lambda_{iso})^{-1}$, constructs a K-Nearest Neighbours (KNN) graph in the embedded space to dynamically restrict evaluation of each point $p$ to its $K_s$ nearest sources $N(p)$, and estimates mass $m^*$ at continuous source points, typically assigning a uniform unit mass $m^*=1$ for speed without performance deterioration [S4]. Computational complexity is strictly bounded to $O(P \times K_s)$, where $P$ is number of points and $K_s$ is number of nearest sources [S4]. It is chosen when evaluating spectral properties on manifolds with strictly bounded computational complexity is required [S4].

### Nearest Neighbor Correspondence with Truncation
Finds the nearest neighbor in a reference point set for each query point, applying distance truncation and optional outlier filtering [S5, unofficial]. It constructs an Open3D KDTree from `verts1`, computes `truncation_dist_square = truncation_dist^2`, performs a $k=1$ KNN search on the KDTree for each query vertex, and if `dist_square < truncation_dist_square` appends the neighbor index and $\sqrt{\text{dist\_square}}$ to results; otherwise, if `ignore_outlier` is false, appends the index and `truncation_dist`, or skips if true [S5, unofficial]. Parameters: `verts1`, `verts2` are $N \times 3$ numpy arrays of reference and query vertices; `truncation_dist` is a scalar distance threshold; `ignore_outlier` is a boolean flag [S5, unofficial]. It is chosen when robust point cloud registration or surface matching with tolerance bounds is required [S5, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot M \cdot \log M)$ or $O(N \cdot M)$ depending on the underlying spatial data structure (e.g., KD-Tree vs. brute force) [G]. The CUDA implementation optimizes this for parallel execution [G].
- **Memory Complexity:** $O(N \cdot k)$ for storing indices and distances [G].
- **Measured Performance:** High performance on GPU due to parallelization. Specific metrics depend on hardware and resolution [G].
- **Strengths:** Efficient batched processing, GPU acceleration [G].
- **Limitations:** Requires CUDA-capable hardware. Memory usage scales with batch size and query count [G].
- **When to use:** When fast neighbor search is needed for large point clouds in a batched manner [G].
- **When not to use:** On CPU-only systems or when memory is extremely constrained [G].

## Background
Originated from the need for efficient neighbor search in point cloud processing, particularly in the context of 4D Gaussian Splatting and other neural rendering techniques [S1, unofficial]. The implementation relies on CUDA kernels for batched queries and offset management [S1, unofficial].
