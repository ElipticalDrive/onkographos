# Efficient kNN Implementation

Also called: Customized CUDA kNN, Local kNN with Camera Parameters

## Overview
Efficient kNN Implementation provides scalable k-nearest neighbor (kNN) search for point cloud density evaluation in volume rendering, specifically addressing the computational bottleneck of global search in large-scale scenes [S1]. It distinguishes itself from global brute-force methods by offering two modes: a customized CUDA implementation for smaller datasets and an efficient local kNN alternative that exploits camera parameters to restrict the search space, reducing complexity from $O(N^2)$ to $O(N \cdot C)$ [S1]. This approach enables real-time processing for high-resolution images and massive point clouds where standard global kNN becomes prohibitive [S1].

## How it works
The method selects between two implementation strategies based on the total point count $N$ and the number of views, leveraging CUDA for hardware acceleration [S1][S3, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   Point cloud coordinates: $P \in \mathbb{R}^{N \times 3}$ (or batched $P \in \mathbb{R}^{B \times N \times 3}$) [S3, unofficial].
    *   Query points: $Q \in \mathbb{R}^{M \times 3}$ (optional; if None, $Q=P$) [S3, unofficial].
    *   Camera parameters: Intrinsics and extrinsics for all views, used to construct candidate sets in local mode [S1].
    *   Hyperparameters: $k$ (number of neighbors), $C$ (candidate set size) [S1].
*   **Outputs**:
    *   Indices: $idx \in \mathbb{Z}^{M \times k}$ (or $\mathbb{Z}^{B \times M \times k}$) [S3, unofficial].
    *   Distances: $dist \in \mathbb{R}^{M \times k}$ (or $\mathbb{R}^{B \times M \times k}$), representing Euclidean distances to the $k$ nearest neighbors [S3, unofficial].

### Data Structures
*   **Candidate Set (Local Mode)**: A subset of points $S \subset P$ with size $|S| = C$. Constructed by aggregating spatial neighbors from the current view and cross-view neighbors projected from nearby cameras using camera parameters [S1].
*   **Batch Offsets**: For batched inputs, cumulative offsets $x\_offset$ and $src\_offset$ are computed to map global indices to local batch indices for the CUDA kernel [S3, unofficial].

### Steps
1.  **Mode Selection**: If $N < 300,000$, use the **Customized CUDA Global kNN**. Otherwise, use the **Efficient Local kNN** [S1].
2.  **Candidate Construction (Local Mode Only)**:
    *   For each query point, identify spatial neighbors in the same view.
    *   Project points from nearby cameras into the current view using camera parameters.
    *   Aggregate these into a candidate set $S$ of size $C$ [S1].
3.  **Distance Computation**:
    *   Compute exact 3D Euclidean distances between query points and points in $S$ (or the full set $P$ in global mode) [S1][S3, unofficial].
    *   Formula: $d_{ij} = \| p_i - q_j \|_2 = \sqrt{\sum_{c=1}^3 (p_{i,c} - q_{j,c})^2}$ [S3, unofficial].
4.  **Top-k Selection**:
    *   Select the $k$ points with the smallest distances from the computed distances [S1][S3, unofficial].
    *   Return indices and distances [S3, unofficial].

### Pseudocode
```python
def efficient_knn(points, queries, k, camera_params=None, max_points=300000):
    """
    Efficient kNN implementation for volume rendering.
    
    Args:
        points: Source points, shape (N, 3) or (B, N, 3).
        queries: Query points, shape (M, 3) or (B, M, 3). If None, queries = points.
        k: Number of neighbors.
        camera_params: Camera parameters for local kNN construction.
        max_points: Threshold for switching between global and local kNN.
        
    Returns:
        idx: Indices of nearest neighbors, shape (M, k) or (B, M, k).
        dist: Distances to nearest neighbors, shape (M, k) or (B, M, k).
    """
    if queries is None:
        queries = points
        
    N = points.shape[0] if points.dim() == 2 else points.shape[1]
    
    # Step 1: Mode Selection
    if N < max_points:
        # Customized CUDA Global kNN
        # Reshape to 2D if batched: (B*N, 3) and (B*M, 3)
        if points.dim() == 3:
            points = points.view(-1, 3)
            queries = queries.view(-1, 3)
            # Compute batch offsets
            b = points.shape[0] // N
            src_offset = torch.arange(0, b+1, dtype=torch.long) * N
            x_offset = torch.arange(0, b+1, dtype=torch.long) * queries.shape[0] // b
            # Call CUDA kernel
            idx, dist2 = knnquery_cuda(k, points, queries, src_offset, x_offset)
            # Adjust indices for batch offsets
            idx = idx - (src_offset[1:] - N) # Simplified adjustment
            idx = idx.view(-1, k)
            dist = torch.sqrt(dist2)
        else:
            # Single batch
            idx, dist2 = knnquery_cuda(k, points, queries)
            dist = torch.sqrt(dist2)
    else:
        # Efficient Local kNN
        # Step 2: Candidate Construction
        candidate_set = construct_candidate_set(points, queries, camera_params)
        C = candidate_set.shape[0]
        
        # Step 3: Distance Computation
        # Compute distances between queries and candidate set
        # dist_matrix shape: (M, C)
        dist_matrix = torch.cdist(queries, candidate_set)
        
        # Step 4: Top-k Selection
        # Get top-k indices and distances
        dist, idx_local = torch.topk(dist_matrix, k, largest=False)
        
        # Map local indices to global indices in points
        # Note: candidate_set contains references or indices to original points
        idx = map_to_global_indices(idx_local, candidate_set)
        
    return idx, dist

def construct_candidate_set(points, queries, camera_params):
    """
    Construct candidate set using camera parameters.
    Aggregates spatial neighbors from same view and cross-view neighbors.
    """
    candidates = []
    for i, q in enumerate(queries):
        # Get spatial neighbors in same view
        spatial_neighbors = get_spatial_neighbors(q, points, camera_params)
        # Get cross-view neighbors projected from nearby cameras
        cross_view_neighbors = get_cross_view_neighbors(q, points, camera_params)
        # Aggregate and limit to size C
        combined = torch.cat([spatial_neighbors, cross_view_neighbors])
        # Select top C based on some heuristic (e.g., projected distance)
        # [G] Specific heuristic for selecting C from combined set is not detailed in sources
        candidates.append(combined[:C])
    return torch.stack(candidates)

def knnquery_cuda(k, src, x, src_offset=None, x_offset=None):
    """
    Wrapper for CUDA kernel pointops_cuda.knnquery_cuda.
    Returns indices and squared distances.
    """
    # Implementation details depend on specific CUDA library (e.g., PointOps2)
    # [G] This function calls a CUDA kernel, exact implementation varies by library
    idx, dist2 = pointops_cuda.knnquery_cuda(k, src, x, src_offset, x_offset)
    return idx, dist2
```

### Parameters
*   $k$: Number of neighbors. Typical values depend on density estimation requirements [S3, unofficial].
*   $C$: Candidate set size. Chosen to balance accuracy and performance [S1].
*   $max\_points$: Threshold for mode switching. Default 300,000 [S1].

### Edge Cases and Pitfalls
*   **Precision**: Use squared distances for comparison to avoid square root operations, then take square root only for final output [S3, unofficial].
*   **Boundaries**: Handle edge points where fewer than $k$ neighbors exist in the candidate set [S1].
*   **Degenerate Input**: If $N=0$ or $M=0$, return empty arrays [G].

## Subtopics

### [Efficient Local kNN](10975-efficient-local-knn.md)
Efficient Local kNN is a drop-in replacement for global brute-force k-nearest neighbors (kNN) search in point cloud or Gaussian splatting rendering pipelines. It solves the $O(N^2)$ complexity bottleneck of global search by exploiting the multi-view grid structure of the scene, reducing complexity to $O(N)$. It sets itself apart from global kNN by constraining the search space to spatially adjacent pixels in the source view and corresponding projected pixels in other views, achieving significant speedups with negligible quality loss.

### [PointOps2 CUDA Kernels](13912-pointops2-cuda-kernels.md)
PointOps2 is a collection of CUDA kernels for point cloud operations, including KNN query, furthest point sampling, grouping, interpolation, subtraction, aggregation, attention mechanisms, and relative position encoding, exposed via PyTorch C++ extension. It serves as the computational backend for efficient local neighborhood processing in point cloud deep learning, specifically within frameworks like 4D Gaussian Splatting. It differs from its parent [Efficient kNN Implementation](10966-efficient-knn-implementation.md) by providing a comprehensive suite of operations beyond just neighbor counting, and from its sibling [Efficient Local kNN](10975-efficient-local-knn.md) by including higher-level operations like aggregation and attention.

### Reciprocal Nearest Neighbor Matching
Reciprocal Nearest Neighbor Matching finds mutual nearest neighbors between two point sets P1 and P2 using KDTree to identify reciprocal matches [S2, unofficial]. It builds KDTree for P1 and P2, queries tree2 for P1 to get nn1_in_P2, and tree1 for P2 to get nn2_in_P1, then computes reciprocal matches by checking if nn2_in_P1[nn1_in_P2] == np.arange(len(nn1_in_P2)) and vice versa [S2, unofficial].

### K-Nearest Neighbors Query
K-Nearest Neighbors Query is a method to find the k nearest neighbors for each point in a target set (new_xyz) within a source set (xyz), returning indices and squared distances [S3, unofficial]. It performs K-Nearest Neighbors search on 3D points using a CUDA kernel, handling batched inputs with offsets [S3, unofficial]. If new_xyz is None, it defaults to using xyz as the query set [S3, unofficial]. It calls the CUDA kernel `pointops_cuda.knnquery_cuda` to compute indices (idx) and squared distances (dist2), then returns indices and the square root of squared distances [S3, unofficial]. If `transpose` is true, it transposes `x` and `src` from (B, N, 3) to (B, 3, N) and makes contiguous [S3, unofficial]. It extracts batch size `b`, query count `n`, and source count `m`, reshapes `x` and `src` to 2D tensors (B*N, 3) and (B*M, 3), computes cumulative offsets `x_offset` and `src_offset`, calls `knnquery(k, src, x, src_offset, x_offset)` to get indices and distances, adjusts indices by subtracting `(src_offset - m)` to correct for batch offsets, reshapes to (B, N, K), and returns as long integers [S3, unofficial]. Input: xyz (n, 3), new_xyz (m, 3), offset (b), new_offset (b). Output: idx (m, nsample), dist2 (m, nsample) [S3, unofficial].

## Operating characteristics
*   **Time Complexity**: Global kNN is $O(N^2)$ [S1]. Efficient Local kNN is $O(N \cdot C)$, where $C$ is the candidate set size, effectively $O(N)$ for constant $C$ [S1].
*   **Memory Complexity**: Global kNN requires $O(N^2)$ space for distance matrix if not optimized [S1]. Local kNN requires $O(N \cdot C)$ space for candidate set [S1].
*   **Measured Performance**: For point counts < 300K, customized CUDA global kNN is efficient [S1]. For higher resolutions/view counts, efficient local kNN provides significant speedups [S1].
*   **Strengths**: Scalability to large point clouds, real-time performance, negligible quality loss [S1].
*   **Limitations**: Local kNN depends on camera parameters and may miss distant neighbors if $C$ is too small [S1]. Global kNN becomes prohibitive for $N > 300K$ [S1].
*   **When to Use**: Use global kNN for small datasets ($N < 300K$) [S1]. Use local kNN for large datasets or high-resolution scenes [S1].

## Background
Efficient kNN Implementation originated in the context of Gaussian Splatting and point cloud rendering, where scalability is critical [S1]. The customized CUDA implementation builds on existing GPU-accelerated kNN libraries [S1]. The efficient local kNN variant was introduced to address the $O(N^2)$ bottleneck in large-scale multi-view scenes [S1]. It is used in frameworks like ReSplat and 4D Gaussian Splatting [S1][S3, unofficial].
