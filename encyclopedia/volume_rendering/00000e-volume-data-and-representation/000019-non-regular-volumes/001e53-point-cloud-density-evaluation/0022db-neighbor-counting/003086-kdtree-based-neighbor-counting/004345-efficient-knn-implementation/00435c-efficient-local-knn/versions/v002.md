# Efficient Local kNN

Also called: Local k-nearest neighbors, O(N) local kNN

## Overview
Efficient Local kNN is a drop-in replacement for global brute-force k-nearest neighbors (kNN) search in point cloud or Gaussian splatting rendering pipelines [S1]. It solves the $O(N^2)$ complexity bottleneck of global search by exploiting the multi-view grid structure of the scene, reducing complexity to $O(N)$ [S1]. It sets itself apart from global kNN by constraining the search space to spatially adjacent pixels in the source view and corresponding projected pixels in other views, achieving significant speedups with negligible quality loss [S1].

## How it works
**Inputs:**
- A set of $N$ 3D points (e.g., Gaussian centers) with positions $\mathbf{p}_i \in \mathbb{R}^3$.
- $V$ camera views, each defined by an intrinsic matrix $\mathbf{K}_v$ and extrinsic pose $\mathbf{T}_v$ (world-to-camera transformation).
- Integer parameters: $k$ (number of neighbors), $r_s$ (same-view spatial radius), $r_c$ (cross-view spatial radius).
- Optional: Depth maps or point cloud projections for efficient spatial indexing.

**Outputs:**
- For each query point $\mathbf{p}_q$, a list of $k$ nearest neighbor indices from the candidate set.

**Data Structures:**
- **Point Cloud:** Array of $N$ points, each storing 3D coordinates.
- **Camera Info:** Array of $V$ cameras, each storing $\mathbf{K}_v$ and $\mathbf{T}_v$.
- **Spatial Index (Implicit):** The method relies on the assumption that nearby pixels in 2D image space correspond to nearby 3D points. Candidates are identified by 2D pixel coordinates within a square window.

**Parameters:**
- $r_s = 3$: Spatial radius for the same-view window.
- $r_c = 3$: Spatial radius for the cross-view window.
- $k$: Number of neighbors to retrieve.
- Compression Factor: Default 16×, using depth maps at 1/4 resolution [S1].

**Steps:**
1. **Same-View Candidate Generation:** For each query point $\mathbf{p}_q$ in the current view, project it to 2D pixel coordinates $(u, v)$. Define a square window of size $(2r_s + 1) \times (2r_s + 1)$ centered at $(u, v)$. Collect all 3D points whose 2D projections fall within this window in the same view.
2. **Cross-View Candidate Gathering:** For each other view $v' \neq v$:
   a. Project the 3D query point $\mathbf{p}_q$ into the 2D image plane of view $v'$ using $\mathbf{K}_{v'}$ and $\mathbf{T}_{v'}$. Let the projected pixel be $(u', v')$.
   b. Define a square window of size $(2r_c + 1) \times (2r_c + 1)$ centered at $(u', v')$.
   c. Collect all 3D points from view $v'$ whose 2D projections fall within this window.
3. **Candidate Aggregation:** Combine the same-view candidates and all cross-view candidates into a single candidate set $\mathcal{C}$.
4. **Neighbor Selection:** Compute the 3D Euclidean distance between $\mathbf{p}_q$ and every point in $\mathcal{C}$. Select the $k$ points with the smallest distances.

import numpy as np

def efficient_local_knn(points, cameras, k, rs=3, rc=3):
    """
    Efficient Local kNN implementation.
    
    Args:
        points: Nx3 array of 3D point coordinates.
        cameras: List of V dictionaries, each containing 'K' (3x3 intrinsic) 
                 and 'T' (4x4 extrinsic world-to-camera matrix).
        k: Number of neighbors to find.
        rs: Same-view spatial radius.
        rc: Cross-view spatial radius.
        
    Returns:
        neighbors: Nxk array of neighbor indices.
    """
    N = points.shape[0]
    V = len(cameras)
    neighbors = np.zeros((N, k), dtype=np.int32)
    
    # Precompute 2D projections for all points in all views to enable fast window lookup

    # For the sake of this self-contained pseudocode, we assume a helper function 
    # `get_points_in_window` that returns indices of points within a 2D window.
    
    for i in range(N):
        query_point = points[i]
        candidates = []
        
        # Step 1: Same-view candidates (View 0 is assumed as the source view for simplicity,
        # or the view corresponding to the query point's origin)
        # Project query point to view 0
        u, v = project_2d(query_point, cameras[0]['K'], cameras[0]['T'])

        same_view_indices = get_points_in_window(points, cameras[0], u, v, rs)
        candidates.extend(same_view_indices)
        
        # Step 2: Cross-view candidates
        for v_idx in range(1, V):
            # Project query point to view v_idx
            u_cross, v_cross = project_2d(query_point, cameras[v_idx]['K'], cameras[v_idx]['T'])
            
            # Get cross-view candidates within (2*rc + 1)^2 window
            cross_view_indices = get_points_in_window(points, cameras[v_idx], u_cross, v_cross, rc)
            candidates.extend(cross_view_indices)
        
        # Step 3 & 4: Select top-k neighbors
        if len(candidates) == 0:
            # Fallback if no candidates found (e.g., point out of bounds)
            # [G] Default to self or nearest available, though sources don't specify.
            neighbors[i] = [i] * k
            continue
            
        # Compute distances to all candidates
        candidate_points = points[candidates]
        distances = np.linalg.norm(candidate_points - query_point, axis=1)
        
        # Get indices of k smallest distances
        top_k_indices = np.argpartition(distances, k)[:k]
        
        # Map back to original point indices
        neighbors[i] = np.array(candidates)[top_k_indices]
        
    return neighbors

def project_2d(point_3d, K, T):
    """
    Projects a 3D point to 2D pixel coordinates.
    point_3d: (3,) or (1,3)
    K: 3x3 intrinsic matrix
    T: 4x4 extrinsic matrix (world to camera)
    Returns: (u, v) pixel coordinates
    """
    # Homogeneous coordinates
    point_h = np.append(point_3d, 1.0)
    
    # World to Camera transformation
    point_cam = T @ point_h
    
    # Project to 2D
    point_2d_h = K @ point_cam[:3]
    
    # Normalize by depth
    u = point_2d_h[0] / point_2d_h[2]
    v = point_2d_h[1] / point_2d_h[2]
    
    return u, v

**Edge Cases and Pitfalls:**
- **Out-of-bounds projections:** If a point projects outside the image plane of a camera, it should be excluded from candidates [S1].
- **Precision:** Floating-point precision in projection calculations may affect window boundary checks.
- **Degenerate Input:** If $N$ is small or points are sparse, the candidate set may be empty. The pseudocode includes a fallback [G].
- **Compression:** Using compressed depth maps (e.g., 1/4 resolution) may introduce quantization errors in 2D coordinate estimation [S1].

## Subtopics

### Morton-order approximation for KNN/LD scoring
Replaces exact kNN distance computation with a Morton-order (Z-order curve) spatial approximation to compute Local Distinctiveness (LD) scores for Gaussian pruning [S2]. It sorts all Gaussians by their Morton code index and uses the resulting spatial ordering to approximate nearest-neighbor relationships for LD scoring instead of computing pairwise Euclidean distances [S2]. This achieves a 146× speedup over exact KNN while maintaining nearly identical accuracy, making it suitable for scalability in complex or large-scale scenes where KNN's $O(N^2)$ complexity becomes impractical [S2]. On the Mip-NeRF 360 dataset (OMG-XS variant), Morton order yields PSNR 27.06, SSIM 0.807, LPIPS 0.243, and Time 4100 ms, compared to KNN's PSNR 27.07, SSIM 0.808, LPIPS 0.241, and Time 28 ms [S2].

## Operating characteristics
**Time and Memory Complexity:**
- Reduces complexity from $O(N^2)$ for global brute-force search to $O(N)$ by vectorizing cross-view reprojections and limiting the search space [S1].
- Morton-order approximation reduces time complexity from $O(N^2)$ to effectively $O(N \log N)$ or $O(N)$ depending on sorting, with significantly lower memory usage than KNN [S2].

**Measured Performance:**
- On 8 views at 512x960 resolution with 246K Gaussians, Local kNN takes 0.591s compared to Global kNN's 0.816s [S1].
- Morton-order approximation achieves a 146× speedup over KNN [S2].

**Scaling:**
- Local kNN scales linearly with the number of points $N$ [S1].
- Morton-order approximation scales better with the number of primitives, making it suitable for large-scale scenes [S2].

**Strengths and Limitations:**
- **Strengths:** Significant speedup with negligible quality loss (PSNR 27.65 vs 27.70 for Local kNN) [S1]. Morton order provides scalability and generalizability [S2].
- **Limitations:** Relies on the assumption that nearby pixels in 2D correspond to nearby 3D points, which may not hold for all scene geometries [S1]. Morton order is an approximation and may not be as accurate as exact KNN in highly non-uniform distributions [S2].

**When to Use:**
- Use Local kNN when inference speed is critical and the scene has a multi-view grid structure [S1].
- Use Morton-order approximation when the number of Gaussians is large and KNN becomes computationally prohibitive [S2].

## Background
Efficient Local kNN was introduced in ReSplat: Learning Recurrent Gaussian Splatting [S1]. It addresses the computational bottleneck of global kNN search in high-resolution point clouds. Morton-order approximation for KNN/LD scoring was introduced in Optimized Minimal 3D Gaussian Splatting [S2] to improve scalability during training.
