# Neighbor Counting


## Overview
Neighbor Counting is a method for evaluating local point cloud density by determining the number of neighboring points within a specified radius for each point in the dataset [S1, unofficial]. It serves as a fundamental primitive for non-regular volume representations, enabling density estimation, clustering validation, and noise filtering [S1, unofficial]. Unlike global density metrics, it provides a per-point local statistic, distinguishing it from sibling methods like Chamfer Distance which measure pairwise set distances, or BrickDensityRegion Point Splatting which aggregates density into fixed spatial bricks [S3956-brickdensityregion-point-splatting.md].

## How it works
**Inputs:**
- A set of $N$ points $P = \{p_1, p_2, \dots, p_N\}$ in $\mathbb{R}^d$ (typically $d=3$).
- A distance threshold $r$ (radius) defining the neighborhood scope.

**Outputs:**
- An array `neighbor_counts` of size $N$, where `neighbor_counts[i]` is the number of points $p_j$ ($j \neq i$) such that $\|p_i - p_j\| \le r$.

**Data Structures:**
- **KDTree**: A spatial partitioning data structure built from $P$ to enable efficient range queries. The tree nodes store point indices and bounding boxes.
- **neighbor_counts**: A 1D integer array of length $N$.

**Steps:**
1. **Build Index**: Construct a KDTree from the input point set $P$ [S1, unofficial].
2. **Query Radius**: For each point $p_i \in P$:
   - Query the KDTree for all points within distance $r$ of $p_i$ [S1, unofficial].
   - Let $S_i$ be the set of returned point indices.
   - Calculate the count: $c_i = |S_i| - 1$. The subtraction of 1 excludes the point $p_i$ itself, which is always returned by a standard radius query [S1, unofficial].
3. **Store**: Assign $c_i$ to `neighbor_counts[i]`.

**Pseudocode:**
```python
import numpy as np
from sklearn.neighbors import KDTree

def neighbor_counting(points: np.ndarray, radius: float) -> np.ndarray:
    """
    Calculate the number of neighbors within a given radius for each point.
    
    Args:
        points: Array of shape (N, D) containing point coordinates.
        radius: The distance threshold for neighborhood definition.
        
    Returns:
        Array of shape (N,) containing neighbor counts (excluding self).
    """
    # Step 1: Build KDTree
    tree = KDTree(points)
    
    # Step 2: Query neighbors
    # query_radius returns a list of arrays, where each array contains indices
    # of points within 'radius' of the corresponding query point.
    indices_list = tree.query_radius(points, r=radius)
    
    # Step 3: Calculate counts excluding self
    # The query includes the point itself, so we subtract 1.
    neighbor_counts = np.array([len(indices) - 1 for indices in indices_list])
    
    return neighbor_counts
```

**Parameters:**
- `radius` ($r$): The Euclidean distance threshold. Typical values depend on the scale of the input data; for normalized unit cubes, $r \in [0.01, 0.1]$ is common for sparse clouds [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Self-Inclusion**: Standard KDTree radius queries include the query point itself. Failing to subtract 1 results in a count inflated by 1 [S1, unofficial].
- **Precision**: Floating-point comparison errors near the boundary $r$ may cause inconsistent inclusion/exclusion if not handled consistently (e.g., using $\le$ vs $<$).
- **Empty Neighborhoods**: Points with no neighbors (other than self) will have a count of 0.

## Subtopics

### [Clusterability Check](5598-clusterability-check.md)
Clusterability Check determines if a K-D tree node's grid can be clustered (optimized for rendering) by verifying if the combined QEF point count matches the sum of component point counts. It serves as a binary gate in the Neighbor Counting pipeline, preventing invalid aggregation of geometric primitives that would violate conservation laws or introduce rendering artifacts.

### [KDTree-based Neighbor Counting](6285-kdtree-based-neighbor-counting.md)
Calculates the density of mesh vertices within each voxel by querying neighboring points using a KDTree and normalizing counts. This variant adapts the basic neighbor counting logic to voxel-based density estimation, often used in conjunction with point splatting or volume rasterization.

### Range Weight
#### definition
A statistical neighborhood analysis attribute derived from intensity values that describes the neighborhood footprint in a given partial intensity range, acting as a proxy for material characteristics like homogeneity and size [S2, unofficial].

#### formula
$$w_r(\boldsymbol{\Phi}, N) = \frac{|N \cap V_{\boldsymbol{\Phi}}|}{|N|}$$
where $N$ is an arbitrary voxel neighborhood, $V_{\boldsymbol{\Phi}}$ is the set of voxels within range $\boldsymbol{\Phi}$, and $|V|$ is the cardinality of a set $V$ [S2, unofficial].

#### usage
Used in forensic visualizations to highlight metal fragments and their neighborhood, and in MR bile duct examination to isolate liver tumors [S2, unofficial].

## Operating characteristics
- **Time Complexity**: Building the KDTree takes $O(N \log N)$ on average. Querying all points takes $O(N \log N)$ on average for uniform distributions, but can degrade to $O(N^2)$ in worst-case high-dimensional or clustered scenarios [S1, unofficial].
- **Memory Complexity**: $O(N)$ to store the points and the KDTree structure, plus $O(N)$ for the output array.
- **Strengths**: Simple to implement; provides immediate local density estimates; effective for noise detection and outlier removal.
- **Limitations**: Sensitive to the choice of radius $r$; computationally expensive for very large datasets without spatial indexing; does not account for point orientation or surface normal information.
- **When to use**: When local density is required for clustering, noise filtering, or as a preprocessing step for more complex volume representations.
- **When not to use**: When global density metrics are sufficient, or when computational resources are extremely limited and approximate methods are acceptable.

## Background
Neighbor Counting is a fundamental technique in spatial data analysis and point cloud processing. Its implementation using KDTree-based radius queries is widely documented in computational geometry libraries and graphics research [S1, unofficial]. The concept is closely related to local density estimation in statistics and is a precursor to more complex neighborhood-based attributes like Range Weight in volume visualization [S2, unofficial].
