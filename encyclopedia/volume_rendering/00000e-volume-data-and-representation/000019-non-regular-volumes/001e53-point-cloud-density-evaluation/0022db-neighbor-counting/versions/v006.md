# Neighbor Counting


## Overview
Neighbor Counting is a fundamental technique in Point Cloud Density Evaluation that estimates the local density of points by counting the number of neighbors within a specified radius for each point in a dataset [S1, unofficial]. It serves as a core primitive for assessing spatial distribution, identifying outliers, and initializing density-based clustering or rendering parameters. Unlike global metrics, it provides a per-point local density estimate, distinguishing it from sibling methods like Chamfer Distance which measure set-to-set error, or BrickDensityRegion Point Splatting which aggregates density into voxel bricks [3956-brickdensityregion-point-splatting.md].

## How it works
**Inputs:**
- A set of $N$ points $P = \{p_1, p_2, \dots, p_N\}$, where each $p_i \in \mathbb{R}^3$.
- A distance threshold (radius) $r$.

**Outputs:**
- An array `neighbor_counts` of size $N$, where `neighbor_counts[i]` is the number of points in $P$ within distance $r$ of $p_i$, excluding $p_i$ itself.

**Data Structures:**
- **KDTree**: A spatial indexing structure built from $P$ to enable efficient range queries. The tree is typically balanced, with each node representing a bounding volume (e.g., AABB) containing a subset of points. Leaf nodes contain a small number of points (e.g., 1-10) [S1, unofficial].

**Steps:**
1. **Build KDTree**: Construct a KDTree from the input point set $P$. This involves recursively splitting the space along the axis with the largest variance until a stopping criterion (e.g., max points per leaf) is met [S1, unofficial].
2. **Query Neighbors**: For each point $p_i \in P$:
   a. Perform a range query on the KDTree with center $p_i$ and radius $r$.
   b. Retrieve all points $p_j$ such that $\|p_i - p_j\|_2 \le r$.
   c. Count the number of retrieved points.
   d. Subtract 1 from the count to exclude the query point $p_i$ itself (since the distance to itself is 0, it is always included in the range query unless explicitly excluded) [S1, unofficial].
   e. Store the result in `neighbor_counts[i]`.

**Formula:**
For a point $p_i$, the neighbor count $C_i$ is:
$$ C_i = |\{ p_j \in P : \|p_i - p_j\|_2 \le r \}| - 1 $$
where $\| \cdot \|_2$ is the Euclidean distance.

**Parameters:**
- $r$ (distance_threshold): The radius for neighbor search. Typical values depend on the scale of the data; e.g., in point cloud processing, it might be a fraction of the bounding box diagonal or a fixed world unit [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Self-Inclusion**: The range query typically includes the query point itself. Failing to subtract 1 results in an overcount of 1 for every point [S1, unofficial].
- **Boundary Effects**: Points near the boundary of the point cloud may have fewer neighbors simply due to lack of data, not lower density. This should be considered when interpreting density [G].
- **Precision**: Floating-point precision in distance calculations can affect inclusion/exclusion at the exact boundary $r$. Using squared distances ($\|p_i - p_j\|_2^2 \le r^2$) avoids square roots and improves performance and precision [G].

**Pseudocode:**
```python
import numpy as np
from scipy.spatial import KDTree

def neighbor_counting(points: np.ndarray, radius: float) -> np.ndarray:
    """
    Calculate the number of neighbors within a given radius for each point.
    
    Args:
        points: Array of shape (N, 3) containing 3D coordinates.
        radius: Distance threshold for neighbor search.
        
    Returns:
        Array of shape (N,) containing neighbor counts (excluding self).
    """
    # Build KDTree from input points
    tree = KDTree(points)
    
    # Initialize array for neighbor counts
    counts = np.zeros(len(points), dtype=np.int32)
    
    # Query neighbors for each point
    # query_radius returns indices of points within radius
    # Note: scipy's query_radius includes the point itself if distance is 0
    for i in range(len(points)):
        # Get indices of neighbors within radius
        neighbor_indices = tree.query_radius(points[i], r=radius)
        
        # Count neighbors, excluding self
        # The point itself is always at distance 0, so it is in neighbor_indices
        # We subtract 1 to exclude self
        counts[i] = len(neighbor_indices) - 1
        
    return counts
```

### [Clusterability Check](5598-clusterability-check.md)
Clusterability Check determines if a K-D tree node's grid can be clustered (optimized for rendering) by verifying if the combined QEF point count matches the sum of component point counts. It serves as a binary gate in the Neighbor Counting pipeline, preventing invalid aggregation of geometric primitives that would violate conservation laws or introduce rendering artifacts.

### [KDTree-based Neighbor Counting](6285-kdtree-based-neighbor-counting.md)
Calculates the density of mesh vertices within each voxel by querying neighboring points using a KDTree and normalizing counts. This variant extends basic neighbor counting by mapping points to a voxel grid and aggregating counts per voxel, enabling density estimation for rendering purposes [6285-kdtree-based-neighbor-counting.md].

### Range Weight
#### definition
A statistical neighborhood analysis attribute derived from intensity values that describes the neighborhood footprint in a given partial intensity range, acting as a proxy for material characteristics like homogeneity and size [S2, unofficial].

#### formula
$$ w_r(\boldsymbol{\Phi}, N) = \frac{|N \cap V_{\boldsymbol{\Phi}}|}{|N|} $$
where $N$ is an arbitrary voxel neighborhood, $V_{\boldsymbol{\Phi}}$ is the set of voxels within range $\boldsymbol{\Phi}$, and $|V|$ is the cardinality of a set $V$ [S2, unofficial].

#### usage
Used in forensic visualizations to highlight metal fragments and their neighborhood, and in MR bile duct examination to isolate liver tumors [S2, unofficial].

## Operating characteristics
- **Time Complexity**: Building the KDTree takes $O(N \log N)$ on average. Querying neighbors for all points takes $O(N \log N)$ on average with a balanced KDTree, but can degrade to $O(N^2)$ in worst-case scenarios (e.g., highly clustered data or poor tree balance) [S1, unofficial].
- **Memory Complexity**: $O(N)$ to store the points and the KDTree structure [S1, unofficial].
- **Measured Performance**: Performance depends heavily on the data distribution and the choice of $r$. For uniform distributions, KDTree queries are efficient. For clustered data, performance may degrade [G].
- **Strengths**: Simple to implement, efficient for moderate-sized datasets, provides local density information.
- **Limitations**: Sensitive to the choice of $r$, can be slow for very large datasets or high-dimensional data, suffers from the curse of dimensionality [G].
- **When to use**: When local density estimation is needed for outlier detection, clustering initialization, or rendering parameter adjustment.
- **When not to use**: For very large datasets where approximate methods (e.g., grid-based hashing) are preferred, or in high-dimensional spaces where KDTree performance degrades [G].

## Background
Neighbor Counting is a basic spatial analysis technique widely used in point cloud processing, computer graphics, and scientific visualization. The use of KDTree for efficient neighbor search was popularized by Bentley in 1975 [G]. In the context of volume rendering and point cloud density evaluation, it serves as a foundational step for more complex operations like density-based clustering or adaptive sampling [S1, unofficial]. The specific implementation details cited here are from an unofficial source [S1, unofficial], which describes a practical implementation using `scipy.spatial.KDTree`.
