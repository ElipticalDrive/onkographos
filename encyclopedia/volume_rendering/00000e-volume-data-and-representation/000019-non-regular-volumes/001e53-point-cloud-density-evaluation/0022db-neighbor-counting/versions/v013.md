# Neighbor Counting
## Overview
Neighbor Counting quantifies the local density of points in a point cloud or mesh by determining how many other points reside within a specified proximity of a query point [S1, unofficial]. It provides discrete, integer-based counts rather than smoothed kernel sums, distinguishing it from continuous density estimators like [Parzen Density Estimation](11796-parzen-density-estimation.md) [S1, unofficial]. Unlike connectivity-based clustering methods such as [Grid-based DBSCAN](11706-grid-based-dbscan.md), it focuses on local neighborhood statistics to inform voxelization or surface reconstruction filtering [S1, unofficial].

## How it works
The method operates on a set of input points $P = \{p_1, p_2, \dots, p_n\}$ in $\mathbb{R}^3$ and a distance threshold $\tau$ [S1, unofficial]. The output is a set of neighbor counts $C = \{c_1, c_2, \dots, c_n\}$, where $c_i$ represents the number of neighbors of point $p_i$ within distance $\tau$ [S1, unofficial].

### Data Structures
1. **Input Points**: An array of 3D coordinates $(x, y, z)$ [G].
2. **KDTree**: A spatial index structure built from the input points to enable efficient range queries [G].
3. **Neighbor Counts**: An integer array of size $n$, initialized to zero [G].

### Parameters
* $\tau$ (distance_threshold): The maximum Euclidean distance to consider a point a neighbor. Not given in the sources.

### Steps
1. **Build Index**: Construct a KDTree from the input point set $P$ [S1, unofficial].
2. **Query**: For each point $p_i \in P$: Query the KDTree for all points within Euclidean distance $\tau$ of $p_i$ using `query_radius` [S1, unofficial]. Let $N_i$ be the set of returned points [S1, unofficial]. Calculate the count $c_i = |N_i| - 1$ [S1, unofficial].
3. **Store**: Save $c_i$ to the output array at index $i$ [S1, unofficial].

### Edge Cases and Pitfalls
* **Self-Inclusion**: The query radius typically includes the query point itself, requiring an explicit subtraction of 1 from the raw count to reflect other neighbors [S1, unofficial].
* **Boundary Conditions**: Points near the boundary of the point cloud may have artificially low counts due to the absence of points outside the dataset [G].
* **Precision**: Floating-point precision in distance calculations can affect which points are included if they lie exactly on the boundary $\tau$; standard Euclidean distance comparison `dist <= tau` is recommended [G].

### Pseudocode
```python
import math
from typing import List, Tuple

def neighbor_counting(points: List[Tuple[float, float, float]], distance_threshold: float) -> List[int]:
    """
    Calculate the number of neighbors for each point within the given distance threshold.
    Implements the steps: Build Index, Query, Subtract Self, Store.
    """
    n = len(points)
    counts = [0] * n
    
    # Step 1: Build Index (simplified as direct storage for self-contained validity)
    # In practice, a KDTree structure is used for efficient range queries [G].
    
    # Step 2: Query for each point
    for i, p in enumerate(points):
        neighbor_indices = []
        for j, q in enumerate(points):
            dist = math.sqrt((p[0] - q[0])**2 + (p[1] - q[1])**2 + (p[2] - q[2])**2)
            if dist <= distance_threshold:
                neighbor_indices.append(j)
        
        # Step 3: Subtract 1 to exclude self
        count = len(neighbor_indices) - 1
        
        # Handle case where no other points are within range
        if count < 0:
            count = 0
            
        # Step 4: Store
        counts[i] = count
        
    return counts
```

## Subtopics

### [Clusterability Check](5598-clusterability-check.md)
Determines if a K-D tree node's grid can be clustered by checking if the combined QEF point count matches the sum of component point counts.

### [KDTree-based Neighbor Counting](6285-kdtree-based-neighbor-counting.md)
Calculates density by querying neighboring points using a KDTree and normalizing counts. It uses a fixed spherical radius, differing from [Grid-based DBSCAN](11706-grid-based-dbscan.md) which uses connectivity, and from [Parzen Density Estimation](11796-parzen-density-estimation.md) which provides smoothed sums.

### [Predictor Definitions](11644-predictor-definitions.md)
Provides heuristic spatial interpolation methods for estimating a target voxel's value using immediate neighbors, used in adaptive wavelet-based volume compression to construct prediction residuals. Differs from density estimation by focusing on spatial correlation for signal prediction rather than local point density.

### [Grid-based DBSCAN](11706-grid-based-dbscan.md)
Optimized DBSCAN variant for 2D spaces mapping data to a grid and using graph connectivity to guarantee $O(n \log n)$ time complexity. Differs from tree-based methods by avoiding VP-tree/KD-tree limitations.

### [DBSCAN](11722-dbscan.md)
Density-based clustering identifying arbitrary-shaped clusters, robust to noise, distinguishing itself from centroid-based methods by handling non-convex shapes and outliers. Builds on Neighbor Counting by using range-queries to evaluate local point density.

### [Parzen Density Estimation](11796-parzen-density-estimation.md)
Estimates the probability density function using continuous Gaussian kernel interpolation to define cluster boundaries, allowing smoother decision boundaries than discrete neighbor counts.

### Range Weight
A statistical neighborhood analysis attribute derived from intensity values describing the neighborhood footprint in a partial intensity range $\Phi$, acting as a proxy for material characteristics like homogeneity and size [S2, unofficial]. It is defined as:
$$ w_r(\Phi, N) = \frac{|N \cap V_\Phi|}{|N|} $$
where $N$ is an arbitrary voxel neighborhood, $V_\Phi$ is the set of voxels within range $\Phi$, and $|V|$ is the cardinality of set $V$ [S2, unofficial]. It is used in forensic visualizations to highlight metal fragments and in MR bile duct examinations to isolate liver tumors [S2, unofficial].

### Angle Criterion for Neighbor Filtering
Filters neighborhood $N(c)$ to remove neighbors producing inaccurate isopoints due to large angles between edges [S3]. Steps: Sort all points in $N(c)$ by distance to $x$. Delete neighbors where the angle $\beta$ between the edge to that neighbor and the edge to any closer neighbor is less than threshold $\alpha$ [S3]. The choice for $\alpha$ is motivated by 3D optimal sphere packing, typically including diagonal neighbors in gridded data [S3]. This filtering breaks symmetry, potentially requiring duplicate isopoint computations [S3].

### Cluster Compactness Metric
Evaluates cluster quality by calculating the Mean Squared Error (MSE) of points relative to their cluster centroid [S4, unofficial]. Steps:
1. Initialize `compactness` dict, `total_weighted=0.0`, `total_points=0` [S4, unofficial].
2. Identify valid mask where labels >= 0 [S4, unofficial].
3. If no valid clusters, return empty dict and `float('nan')` [S4, unofficial].
4. Iterate over unique cluster IDs in valid mask [S4, unofficial].
5. Get indices `idx` for current cluster ID [S4, unofficial].
6. Extract points `pts` from features using `idx`; skip if empty [S4, unofficial].
7. Calculate centroid as mean of `pts` along axis=0 [S4, unofficial].
8. Calculate MSE as mean of sum of squared differences between `pts` and centroid [S4, unofficial].
9. Store MSE in `compactness` dict for `int(cid)` [S4, unofficial].
10. Update `total_weighted` by adding `mse * len(pts)` [S4, unofficial].
11. Update `total_points` by adding `len(pts)` [S4, unofficial].
12. Calculate `avg_compactness` as `total_weighted / total_points` if `total_points > 0`, else `float('nan')` [S4, unofficial].
13. Return `compactness` dict and `avg_compactness` [S4, unofficial].
