# Neighbor Counting


## Overview
Neighbor Counting is a fundamental technique in point cloud density evaluation that estimates the local density of points by counting the number of neighbors within a specified radius for each point in the dataset [S1, unofficial]. It serves as the primary mechanism for determining point distribution characteristics, which is critical for downstream tasks such as adaptive voxelization, noise filtering, and density-based clustering in volume rendering pipelines [S1, unofficial]. Unlike global metrics, it provides a per-point density estimate, allowing for localized analysis of geometric features [S1, unofficial]. It differs from [Chamfer Distance](2446-chamfer-distance.md) by measuring local neighborhood cardinality rather than pairwise distances to a target surface, and from [BrickDensityRegion Point Splatting](3956-brickdensityregion-point-splatting.md) by operating on discrete point queries rather than continuous splatted contributions [S1, unofficial].

## How it works
The method relies on spatial indexing to efficiently query neighbors. The core implementation uses a KDTree to organize input points, enabling logarithmic time complexity for range queries [S1, unofficial].

### Inputs and Outputs
- **Input**: A set of $N$ points $P = \{p_1, p_2, \dots, p_N\}$, where each point $p_i$ has coordinates $(x_i, y_i, z_i)$. A scalar `distance_threshold` (often denoted as $\epsilon$) defining the maximum radius for neighbor inclusion.
- **Output**: An array `neighbor_count` of size $N$, where `neighbor_count[i]` stores the number of neighbors of point $p_i$ within `distance_threshold`.

### Data Structures
1.  **KDTree**: A binary tree structure where each node represents a point in $N$-dimensional space. The tree is built recursively by splitting the space along the axis with the largest variance [S1, unofficial].
2.  **Neighbor Count Array**: A 1D array of integers (or floats) of length $N$.

### Steps
1.  **Build KDTree**: Construct a KDTree from the input point set $P$.
2.  **Query Neighbors**: For each point $p_i \in P$:
    a. Perform a range query on the KDTree with center $p_i$ and radius `distance_threshold`.
    b. Retrieve the set of points $N_i$ returned by the query.
    c. Calculate the count: $C_i = |N_i| - 1$. The subtraction of 1 excludes the point $p_i$ itself, which is always included in the query result [S1, unofficial].
3.  **Store Result**: Assign $C_i$ to `neighbor_count[i]`.

### Formula
The neighbor count for point $p_i$ is defined as:
$$
\text{count}(p_i) = \left| \{ p_j \in P \mid \| p_i - p_j \|_2 \le \text{distance\_threshold} \} \right| - 1
$$
Where:
- $\| \cdot \|_2$ is the Euclidean distance.
- The set includes all points $p_j$ (including $p_i$) within the radius.
- $-1$ removes the self-match.

### Parameters
- **distance_threshold**: The radius $\epsilon$ for the neighborhood query. Typical values depend on the scale of the data; it must be chosen relative to the average point spacing to capture meaningful local structure [S1, unofficial].

### Edge Cases and Pitfalls
- **Self-Inclusion**: The KDTree range query typically returns the query point itself if it exists in the tree. Failing to subtract 1 results in a count inflated by 1 for every point [S1, unofficial].
- **Boundary Conditions**: Points near the boundary of the dataset may have fewer neighbors simply due to lack of data, not lower density. This is an inherent property of the method and not an error, but must be considered in interpretation.
- **Precision**: Floating-point precision in distance calculations can affect neighbor inclusion for points exactly at the threshold boundary. Using a small epsilon tolerance in comparisons may be necessary depending on the implementation [G].

### Pseudocode
```python
import numpy as np
from scipy.spatial import KDTree

def neighbor_counting(points, distance_threshold):
    """
    Calculate the number of neighbors for each point within a given radius.
    
    Args:
        points (np.ndarray): Array of shape (N, 3) containing point coordinates.
        distance_threshold (float): Maximum distance to consider a neighbor.
        
    Returns:
        np.ndarray: Array of shape (N,) containing neighbor counts (excluding self).
    """
    # Step 1: Build KDTree
    tree = KDTree(points)
    
    # Initialize output array
    counts = np.zeros(len(points), dtype=np.int32)
    
    # Step 2: Query neighbors for each point
    for i, point in enumerate(points):
        # query_radius returns indices of points within distance_threshold
        # It includes the point itself if it is in the tree
        neighbor_indices = tree.query_radius(point, r=distance_threshold)
        
        # Step 3: Count neighbors, excluding self
        # The count includes the point itself, so subtract 1
        counts[i] = len(neighbor_indices) - 1
        
    return counts
```

## Subtopics

### [Clusterability Check](5598-clusterability-check.md)
Clusterability Check determines if a K-D tree node's grid can be clustered (optimized for rendering) by verifying if the combined QEF point count matches the sum of component point counts. It serves as a binary gate in the Neighbor Counting pipeline, preventing invalid aggregation of geometric primitives that would violate conservation laws or introduce rendering artifacts.

### [KDTree-based Neighbor Counting](6285-kdtree-based-neighbor-counting.md)
Calculates the density of mesh vertices within each voxel by querying neighboring points using a KDTree and normalizing counts. This variant extends the basic point-wise count to voxel-based density estimation by aggregating neighbor counts or point densities within voxel boundaries.

### [Grid-based DBSCAN](11706-grid-based-dbscan.md)
Grid-based DBSCAN is an optimized variant of the DBSCAN clustering algorithm designed specifically for 2D spaces. It solves the problem that standard DBSCAN implementations often fail to achieve optimal time complexity or produce discrepant results compared to the original algorithm due to the limitations of general index structures like VP-trees and KD-trees. It sets itself apart from its siblings by mapping the dataset to a 2D grid and using graph connectivity to identify clusters, guaranteeing $O(n \log n)$ time complexity for 2D data, whereas [KDTree-based Neighbor Counting](6285-kdtree-based-neighbor-counting.md) relies on tree structures that may not guarantee this complexity or consistency.

#### DBSCAN
**Definition**: A density-based clustering algorithm that identifies arbitrary-shaped clusters and is robust to noise and data heterogeneity [S4, unofficial].
- **Core-point**: A point $p$ is a core-point if the number of points in its $\epsilon$-neighborhood $V_\epsilon(p)$ is greater than or equal to `minPts` [S4, unofficial].
- **Border-point**: A point $p_a$ is a border-point if it is reachable from a core-point $p_b$ but $|V_\epsilon(p_a)| < \text{minPts}$ [S4, unofficial].
- **Noise**: Points that are neither core-points nor border-points [S4, unofficial].

**Step**:
1. Initialize `clusterID` to 0. Iterate through all points $p$ in $P$ and label them as UNCLASSIFIED [S4, unofficial].
2. Iterate through all points $p$ in $P$. If $p$ is UNCLASSIFIED, call `ExpandCluster(p, \epsilon, minPts, P, clusterID)`. If `ExpandCluster` returns true, increment `clusterID` [S4, unofficial].
3. If expansion proceeds, add all unclassified points retrieved from the range-query (except the initial point $p$) to a list of expandable points $S$. Iterate through $S$ until empty. Assign all reached points to the current cluster [S4, unofficial].

**Parameter**:
- $\epsilon$ (eps): The search radius for range-queries [S4, unofficial].
- `minPts`: The minimum number of points required to form a dense region (core point) [S4, unofficial].

## Operating characteristics
- **Time Complexity**: Building the KDTree takes $O(N \log N)$ on average. Querying neighbors for all points takes $O(N \log N)$ on average, but can degrade to $O(N^2)$ in worst-case scenarios (e.g., high-dimensional data or specific point distributions) [S1, unofficial].
- **Memory Complexity**: $O(N)$ to store the points and the KDTree structure, plus $O(N)$ for the output count array.
- **Measured Performance**: Performance depends heavily on the dimensionality of the data and the distribution of points. For 3D point clouds, KDTree-based neighbor counting is generally efficient for $N < 10^6$ points. For larger datasets, grid-based approximations (like Grid-based DBSCAN) may be preferred for their guaranteed $O(N \log N)$ complexity in 2D/3D grid mappings [S1, unofficial].
- **Strengths**: Simple to implement, provides direct local density estimates, works well with KDTree libraries.
- **Limitations**: Sensitive to the choice of `distance_threshold`. Does not handle varying densities well without adaptive thresholds. Performance degrades in high dimensions.
- **When to use**: When local density estimation is required for point cloud processing, such as in normal estimation, noise removal, or as a preprocessing step for clustering.
- **When not to use**: When global density metrics are sufficient, or when dealing with very high-dimensional data where KDTree performance degrades significantly.

## Background
Neighbor Counting is a foundational technique in computational geometry and point cloud processing. Its use in volume rendering pipelines, particularly for density evaluation and clustering, has been documented in recent research on dynamic geometry rendering and volume exploration [S1, unofficial][S4, unofficial]. The method is often a precursor to more complex algorithms like DBSCAN, which relies on neighbor counts to identify core points [S4, unofficial].
