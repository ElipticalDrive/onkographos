# Neighbor Counting
## Overview
Neighbor Counting estimates local point cloud density by counting the number of input points within a specified radius of each query point [S1, S3, unofficial]. It serves as a fundamental primitive for density evaluation in non-regular volumes, providing the scalar field data required by higher-level techniques like [BrickDensityRegion Point Splatting](3956-brickdensityregion-point-splatting.md) [S3, unofficial].

## How it works
**Inputs:**
- `points`: An array of shape $(N, 3)$ containing 3D coordinates [S1, S3, unofficial].
- `radius`: The search radius $r$ for neighbor identification [S1, S3, unofficial].

**Outputs:**
- `counts`: An array of shape $(N,)$ where `counts[i]` is the number of neighbors of `points[i]` within `radius` [S1, unofficial].

**Data Structures:**
- **KDTree**: A spatial index structure built from `points` to enable efficient range queries [S1, S3, unofficial].

**Steps:**
1. **Build Index**: Construct a KDTree from the input `points` [S1, unofficial].
2. **Query Neighbors**: For each point $p_i$ in `points`, query the KDTree for all points within distance `radius` of $p_i$ [S1, S3, unofficial].
3. **Calculate Count**: Let $S_i$ be the set of returned indices. Calculate the count $c_i = |S_i| - 1$ to exclude the point $p_i$ itself, which is always within distance 0 [S1, unofficial].
4. **Store Result**: Store $c_i$ in the output array at index $i$ [S1, unofficial].

**Pitfalls:**
- **Self-Inclusion**: Failing to subtract 1 from the query result leads to a count inflated by 1 for every point [S1, unofficial].
- **Boundary Effects**: In voxel-based variants, using a spherical query for cubic voxels yields imperfect boundary results, as the sphere extends beyond the cube faces [S3, unofficial].

**Pseudocode:**
```python
import numpy as np
from scipy.spatial import KDTree

def neighbor_counting(points: np.ndarray, radius: float) -> np.ndarray:
    # Step 1: Build KDTree from input points
    tree = KDTree(points)
    
    # Step 2: Query neighbors for each point within radius
    neighbor_indices = tree.query_ball_point(points, r=radius)
    
    # Step 3: Calculate counts excluding self (subtract 1)
    counts = np.array([len(indices) - 1 for indices in neighbor_indices])
    
    return counts
```

## Subtopics

### Clusterability Check
Determines if a K-D tree node's grid can be clustered (optimized for rendering) by checking if the combined QEF point count matches the sum of component point counts [S2, unofficial]. It calls `RectilinearGrid::calClusterability` with children grids, plane direction, min/max codes, and scalar field $t$ [S2, unofficial]. If `selfClusterable` is false, it sets `clusterable = false` and returns [S2, unofficial]. It iterates over all children; if any child is not clusterable, it sets `clusterable = false` and returns [S2, unofficial]. Otherwise, it sets `clusterable = true` [S2, unofficial].

### KDTree-based Neighbor Counting
Calculates the density of mesh vertices within each voxel by querying neighboring points using a KDTree and normalizing counts [S3, unofficial]. It uses `query_ball_point` to find all mesh vertices within a spherical radius around each voxel center [S3, unofficial]. The sphere radius $r$ is calculated to match the voxel cube volume: $r = x \cdot \sqrt[3]{\frac{3}{4\pi}}$, where $x$ is the cube side length [S3, unofficial]. Vertices are counted in each neighborhood, and counts are normalized by dividing by the maximum count to scale between 0 and 1 [S3, unofficial]. These normalized values are attached as a field to the voxels [S3, unofficial]. A key pitfall is that using a spherical query for cubic voxels yields imperfect boundary results, as the sphere extends beyond the cube faces [S3, unofficial].

## Operating characteristics
- **Time Complexity**: Not given in the sources [S1, S2, S3, unofficial].
- **Memory Complexity**: Not given in the sources [S1, S2, S3, unofficial].
- **Strengths**: Simple to implement; provides a direct measure of local density [S3, unofficial].
- **Limitations**: Sensitive to the choice of radius; spherical queries on cubic voxels introduce boundary artifacts [S3, unofficial].
- **When to use**: When a quick estimate of local point density is needed for density-based rendering techniques [S3, unofficial].
- **When not to use**: When precise volumetric occupancy within cubic boundaries is required without boundary artifacts [S3, unofficial].

## Background
Neighbor Counting is implemented using KDTree or similar spatial indexing structures [S1, S3, unofficial]. The specific implementation details for voxel-based density evaluation using KDTree and spherical queries are documented in tutorials on mesh and point cloud voxelization [S3, unofficial]. The clusterability check variant is part of the KdtreeISO project for efficient mesh representation [S2, unofficial].
