# Predictor Definitions

Also called: Candidate Predictors

## Overview
Predictor Definitions provide a set of heuristic spatial interpolation methods for estimating the value of a target voxel in a 3D volume using its immediate neighbors. This method is primarily used in adaptive wavelet-based volume compression (specifically RDLS-SS-DWT+Pred) to construct prediction residuals, thereby improving compression efficiency by reducing the entropy of the data [S1]. It differs from density estimation methods (like [Parzen Density Estimation](11796-parzen-density- estimation.md) or [DBSCAN](11722-dbscan.md)) by focusing on spatial correlation for signal prediction rather than local point density for data representation or clustering.

## How it works
### Inputs and outputs
*   **Input:** The scalar value of the target voxel $X$ at coordinates $(i, r, c)$ (slice $i$, row $r$, column $c$) and the values of its 7 immediate neighbors.
*   **Output:** A predicted scalar value $\hat{V}_X$ for voxel $X$.

### Data structures and neighbor layout
The method relies on 7 specific neighboring voxels relative to the target $X$. Let the values of these neighbors be denoted by variables $A$ through $H$. The spatial layout is defined as follows [S1]:

*   **Slice $i$ (same slice as $X$):**
    *   $A$: $(i, r, c-1)$ — Left neighbor
    *   $B$: $(i, r-1, c)$ — Top neighbor
    *   $C$: $(i, r-1, c-1)$ — Top-Left neighbor
    *   $H$: $(i, r-1, c+1)$ — Top-Right neighbor (Note: Source Figure 2 labels this position $H$, but Table 1 predictors only utilize $A, B, C, D, E, F$. $H$ is defined in the figure but not used in the standard predictor formulas listed in Table 1 [S1]).
*   **Slice $i-1$ (previous slice):**
    *   $D$: $(i-1, r, c)$ — Direct predecessor in depth
    *   $E$: $(i-1, r, c-1)$ — Predecessor, Left
    *   $F$: $(i-1, r-1, c)$ — Predecessor, Top
    *   $G$: $(i-1, r-1, c-1)$ — Predecessor, Top-Left

*Note: The sources define neighbors $A, B, C, D, E, F$ explicitly in Table 1 and Figure 2. Neighbor $H$ is shown in Figure 2 but is not referenced in the predictor formulas in Table 1 [S1].*

### Numbered steps
1.  **Neighbor Retrieval:** Retrieve the values of neighbors $A, B, C, D, E, F$ for the target voxel $X$.
2.  **Boundary Check:** If any required neighbor is outside the volume bounds, the predictor is considered invalid. The algorithm falls back to a simpler predictor (e.g., NOP) or handles the missing value according to a fallback hierarchy [S1].
3.  **Prediction Calculation:** Compute the predicted value using one of the defined candidate predictors based on the available neighbor values.
4.  **Residual Calculation (Contextual):** In the compression context, the residual is calculated as $R = V_X - \hat{V}_X$, where $V_X$ is the actual value. This residual is then transformed and encoded [S1].

### Formulas
The following predictors are defined in Table 1 of [S1]. Let $V_X$ be the predicted value.

1.  **NOP (No Prediction):**
    $$ V_X = 0 $$
2.  **P_X (Planar X):**
    $$ V_X = A $$
3.  **P_Y (Planar Y):**
    $$ V_X = B $$
4.  **P_Z (Planar Z):**
    $$ V_X = D $$
5.  **AVG_XY (Average X-Y):**
    $$ V_X = \frac{A + B}{2} $$
6.  **AVG_XZ (Average X-Z):**
    $$ V_X = \frac{A + D}{2} $$
7.  **AVG_YZ (Average Y-Z):**
    $$ V_X = \frac{B + D}{2} $$
8.  **MED_XY (Median X-Y):**
    $$ V_X = \text{median}(A, B, A + B - C) $$
9.  **MED_XZ (Median X-Z):**
    $$ V_X = \text{median}(A, D, A + D - E) $$
10. **MED_YZ (Median Y-Z):**
    $$ V_X = \text{median}(B, D, B + D - F) $$
11. **AVG3D (3D Average):**
    $$ V_X = \frac{A + B + D}{3} $$

*Note: The term $A+B-C$ in MED_XY represents a planar extrapolation from the top-left corner. Similarly for others [S1].*

### Parameters
*   **Predictor Selection:** The choice of predictor is adaptive. The method uses a greedy heuristic to select the most recently employed filter for a specific subband to minimize complexity, rather than performing a full search of all 14 filters for each transform level [S1].
*   **Fallback:** If a predictor cannot be computed due to boundary conditions, a simpler predictor is used (e.g., NOP) [S1].

### Edge cases and pitfalls
*   **Boundary Conditions:** Voxels on the edges or corners of the volume lack some neighbors. The method must handle these by falling back to simpler predictors that require fewer neighbors (e.g., using NOP if no neighbors are available, or P_X if only the left neighbor exists) [S1].
*   **Precision:** The median operation requires handling integer or floating-point comparisons. Standard median logic applies.
*   **Degenerate Input:** If the volume is empty or single-voxel, NOP is the only valid predictor.

### Pseudocode
```python
def predict_voxel(target_voxel, neighbors):
    """
    Predicts the value of a voxel based on its neighbors.
    
    Args:
        target_voxel: The actual value of the voxel at (i, r, c).
        neighbors: A dictionary or object containing values for A, B, C, D, E, F.
                   Keys: 'A', 'B', 'C', 'D', 'E', 'F'.
                   Values: Scalar values of the respective neighbors.
                   If a neighbor is out of bounds, its value is None.
    
    Returns:
        predicted_value: The predicted scalar value.
        predictor_name: String identifier of the predictor used.
    """
    A = neighbors.get('A')
    B = neighbors.get('B')
    C = neighbors.get('C')
    D = neighbors.get('D')
    E = neighbors.get('E')
    F = neighbors.get('F')
    
    # Helper to check if a predictor is valid (all required neighbors exist)
    def is_valid(required_vars):
        for var in required_vars:
            if var not in neighbors or neighbors[var] is None:
                return False
        return True

    # Helper for median of three values
    def median3(v1, v2, v3):
        if v1 > v2:
            if v2 > v3:
                return v2
            elif v1 > v3:
                return v3
            else:
                return v1
        else:
            if v1 > v3:
                return v1
            elif v2 > v3:
                return v3
            else:
                return v2

    # Try predictors in order of complexity/availability? 
    # The source says "if a given predictor cannot be computed, a simpler one is used instead".
    # We attempt to use the most complex valid predictor, or fall back.
    # However, the source doesn't specify the exact fallback hierarchy order, 
    # only that a simpler one is used. We will implement a standard fallback chain.
    
    # 1. AVG3D requires A, B, D
    if is_valid(['A', 'B', 'D']):
        return (A + B + D) / 3.0, "AVG3D"
    
    # 2. MED_XY requires A, B, C
    if is_valid(['A', 'B', 'C']):
        return median3(A, B, A + B - C), "MED_XY"
    
    # 3. MED_XZ requires A, D, E
    if is_valid(['A', 'D', 'E']):
        return median3(A, D, A + D - E), "MED_XZ"
    
    # 4. MED_YZ requires B, D, F
    if is_valid(['B', 'D', 'F']):
        return median3(B, D, B + D - F), "MED_YZ"
    
    # 5. AVG_XY requires A, B
    if is_valid(['A', 'B']):
        return (A + B) / 2.0, "AVG_XY"
    
    # 6. AVG_XZ requires A, D
    if is_valid(['A', 'D']):
        return (A + D) / 2.0, "AVG_XZ"
    
    # 7. AVG_YZ requires B, D
    if is_valid(['B', 'D']):
        return (B + D) / 2.0, "AVG_YZ"
    
    # 8. P_X requires A
    if is_valid(['A']):
        return A, "P_X"
    
    # 9. P_Y requires B
    if is_valid(['B']):
        return B, "P_Y"
    
    # 10. P_Z requires D
    if is_valid(['D']):
        return D, "P_Z"
    
    # 11. NOP requires no neighbors
    return 0.0, "NOP"
```

## Subtopics

### Linear De-biasing
A post-processing step applied to the predictions (specifically in the context of muon tomography detector optimization, not directly part of the wavelet compression predictors but cited in the same source context for prediction refinement) [S2]. It corrects systematic bias in predicted values using a linear transformation.
*   **What it is:** A parametric correction function $h_{pred} = a \times z_{pred} + b$ applied to raw predictions $z_{pred}$ to produce de-biased heights $h_{pred}$ [S2].
*   **What sets it apart:** Unlike the spatial predictors which estimate values from neighbors, this method adjusts the global scale and offset of predictions based on statistical calibration against known targets [S2].
*   **When to choose it:** When using a neural network or inference model for volume height prediction where systematic bias exists, and computational cost of re-scanning large datasets for calibration is prohibitive [S2].
*   **Parameters:** Typical values from tested examples are $a = 2$ and $b = -0.2$ [S2].
*   **Link:** [TomOpt: Differential optimisation...](https://doi.org/10.1088/2632-2153/ad52e7)

## Operating characteristics
*   **Time Complexity:** $O(1)$ per voxel, as it involves a fixed number of arithmetic operations and neighbor lookups.
*   **Memory Complexity:** $O(1)$ auxiliary memory per voxel prediction.
*   **Strengths:** Low computational overhead; adaptive nature allows it to handle varying local smoothness in volumetric data; effective for reducing residual entropy in wavelet transforms [S1].
*   **Limitations:** Performance depends heavily on the spatial correlation of the data; boundary conditions require careful handling; the greedy heuristic for filter selection may not find the globally optimal predictor for every subband [S1].
*   **When to use:** In lossless or near-lossless volume compression where spatial redundancy is high, such as in medical imaging (JP3D) [S1].
*   **When not to use:** In highly noisy or uncorrelated data where spatial prediction provides little benefit; when global statistical properties are more relevant than local spatial ones.

## Background
The Predictor Definitions were introduced in the context of improving JP3D compression of volumetric medical images using a hybrid adaptive wavelet-based transform (RDLS-SS-DWT+Pred) [S1]. The method was developed to reduce the complexity of full filter search in adaptive transforms by using a greedy heuristic that reuses recently employed filters for specific subbands [S1]. The specific neighbor layout and predictor formulas are detailed in Table 1 and Figure 2 of the source paper [S1].
