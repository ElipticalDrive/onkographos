# Mesh/Point Cloud Evaluation Metrics

Also called: F-score, F1 score, Mesh Quality Evaluation Metrics

## Overview
Mesh/Point Cloud Evaluation Metrics provides a comprehensive suite of geometric and topological measures to assess the fidelity and quality of reconstructed 3D surfaces against ground truth data [S2, S3, unofficial]. It addresses the problem of objectively quantifying reconstruction errors by combining point-wise proximity (Chamfer Distance), surface alignment (Normal Consistency), and threshold-based correctness (F-score), while also penalizing poor mesh topology (aspect ratios, self-intersections) [S2, S3, unofficial]. Unlike [Chamfer Distance](2446-chamfer-distance.md), which only measures average displacement, this method integrates precision/recall trade-offs and mesh regularity checks to provide a holistic quality assessment [S2, unofficial]. It differs from [Cloud-to-Mesh Accuracy Metrics](10560-cloud-to-mesh-accuracy-metrics.md) by evaluating symmetric point-cloud distances rather than orthogonal point-to-facet displacements [S1, S3, unofficial].

## How it works
The method evaluates a predicted mesh (or point cloud sampled from it) against a ground truth mesh by computing geometric accuracy, completeness, normal consistency, and topological regularity [S2, unofficial][S4].

### Inputs and Outputs
*   **Inputs**:
    *   Predicted mesh $M_{pred}$ (or point cloud $P_{pred}$).
    *   Ground truth mesh $M_{gt}$ (or point cloud $P_{gt}$).
    *   Optional: Camera parameters for visibility culling (in specific pipelines [S1, unofficial]).
*   **Outputs**:
    *   Chamfer Distance (L1 and L2).
    *   Normal Consistency (NC).
    *   F-score (F1).
    *   Edge Chamfer Distance (ECD) and Edge F1 (EF1).
    *   Mesh quality metrics: Aspect Ratio (triAR, tetAR), Radius Ratio, Angle Regularity, Flipped Triangles/Tetrahedra, Self-intersection percentage [S2, S3, unofficial].

### Data Structures
*   **Point Clouds**: Arrays of shape $(N, 3)$ containing vertex coordinates.
*   **Normals**: Arrays of shape $(N, 3)$ containing unit normal vectors.
*   **KDTree**: Spatial index for nearest neighbor queries.
*   **Mesh Topology**: Triangle indices (for surface) or Tetrahedron indices (for volume) [S3, unofficial].

### Parameters
*   `num_points`: Number of points to sample from each mesh for evaluation. Default: 100,000 [S2, unofficial].
*   `f1_threshold`: Distance threshold for computing Precision and Recall in F-score. Default: 0.001 [S2, unofficial].
*   `ef1_radius`: Radius for detecting edge points. Default: 0.004 [S2, unofficial].
*   `ef1_dotproduct_threshold`: Dot product threshold for edge classification. Default: 0.2 [S2, unofficial].
*   `ef1_threshold`: Distance threshold for Edge F-score. Default: 0.005 [S2, unofficial] [G: inferred from context of edge metrics].

### Steps
1.  **Sampling**: Sample $N$ points uniformly from the surface of $M_{pred}$ and $M_{gt}$ to obtain $P_{pred}$ and $P_{gt}$ [S2, unofficial][S4]. If the input is already a point cloud, use it directly.
2.  **KDTree Construction**: Build a KDTree for $P_{gt}$ and another for $P_{pred}$ to enable efficient nearest neighbor queries [S2, unofficial].
3.  **Chamfer Distance (CD)**:
    *   For each point $p \in P_{pred}$, find the nearest neighbor $q \in P_{gt}$ and compute distance $d(p, q) = \|p - q\|$.
    *   For each point $q \in P_{gt}$, find the nearest neighbor $p \in P_{pred}$ and compute distance $d(q, p) = \|q - p\|$.
    *   Compute $CD_{L1} = \frac{1}{|P_{pred}|} \sum_{p \in P_{pred}} \min_{q \in P_{gt}} \|p - q\|_1 + \frac{1}{|P_{gt}|} \sum_{q \in P_{gt}} \min_{p \in P_{pred}} \|q - p\|_1$ [S4].
    *   Compute $CD_{L2}$ similarly using Euclidean norm $\|\cdot\|_2$ [S2, unofficial].
4.  **Normal Consistency (NC)**:
    *   For each point $p \in P_{pred}$, find its nearest neighbor $q \in P_{gt}$.
    *   Compute the dot product of their normals: $dot = \frac{n_p \cdot n_q}{\|n_p\| \|n_q\|}$ [S2, unofficial].
    *   NC is typically the mean of these dot products (or 1 - mean absolute difference) [S4].
5.  **F-score (F1)**:
    *   Compute Precision: fraction of $P_{pred}$ points within `f1_threshold` of any point in $P_{gt}$.
    *   Compute Recall: fraction of $P_{gt}$ points within `f1_threshold` of any point in $P_{pred}$.
    *   $F1 = \frac{2 \cdot Precision \cdot Recall}{Precision + Recall}$ [S1, S2, unofficial].
6.  **Edge Metrics (ECD, EF1)**:
    *   Identify "edge points" in $P_{pred}$ and $P_{gt}$ using `query_radius` with `ef1_radius` and `ef1_dotproduct_threshold` to detect points on sharp features [S2, unofficial].
    *   Compute Chamfer Distance and F-score specifically on these edge points using `ef1_threshold` [S2, unofficial].
7.  **Mesh Quality Metrics**:
    *   **Aspect Ratio**: Compute triangle/tetrahedron aspect ratios. Report mean, min, and max [S3, unofficial].
    *   **Flipped Elements**: Count triangles/tetrahedra with negative volume or inverted normals [S3, unofficial].
    *   **Self-intersection**: Detect and count self-intersecting triangles/tetrahedra [S3, unofficial].
    *   **Angle Regularity**: Compute via geometric libraries (e.g., `trimesh`) [S2, unofficial].
8.  **Aggregation**: Return all computed metrics. For datasets, report average of mean aspect ratios and median of min/max aspect ratios to reduce outlier impact [S3, unofficial].

import numpy as np
from scipy.spatial import KDTree

def compute_mesh_metrics(pred_mesh, gt_mesh, num_points=100000, f1_threshold=0.001, ef1_radius=0.004, ef1_dot_threshold=0.2, ef1_threshold=0.005):
    """
    Compute comprehensive mesh evaluation metrics.
    """
    # 1. Sampling
    P_pred = sample_points(pred_mesh, num_points)
    P_gt = sample_points(gt_mesh, num_points)
    
    # 2. KDTree Construction
    tree_pred = KDTree(P_pred)
    tree_gt = KDTree(P_gt)
    
    # 3. Chamfer Distance
    dist_pred_to_gt, idx_pred_to_gt = tree_gt.query(P_pred, k=1)
    dist_gt_to_pred, idx_gt_to_pred = tree_pred.query(P_gt, k=1)
    
    cd_l1 = np.mean(dist_pred_to_gt) + np.mean(dist_gt_to_pred) # Assuming L1 if dists are L1, else L2
    cd_l2 = np.mean(dist_pred_to_gt**2)**0.5 + np.mean(dist_gt_to_pred**2)**0.5 # L2
    
    # 4. Normal Consistency
    N_pred = get_normals(pred_mesh, P_pred)
    N_gt = get_normals(gt_mesh, P_gt)
    
    # Match normals based on nearest points
    dot_products = np.sum(N_pred * N_gt[idx_pred_to_gt], axis=1)
    normal_consistency = np.mean(dot_products)
    
    # 5. F-score
    precision = np.mean(dist_pred_to_gt < f1_threshold)
    recall = np.mean(dist_gt_to_pred < f1_threshold)
    f1_score = 2 * precision * recall / (precision + recall + 1e-8)

    edge_idx_gt = detect_edge_points(P_gt, N_gt, ef1_radius, ef1_dot_threshold)
    
    P_pred_edge = P_pred[edge_idx_pred]
    P_gt_edge = P_gt[edge_idx_gt]

    recall_edge = np.mean(dist_edge_gt_to_pred < ef1_threshold)
    ef1 = 2 * prec_edge * recall_edge / (prec_edge + recall_edge + 1e-8)

        'cd_l2': cd_l2,

        'ef1': ef1,

## Subtopics

### [Mesh Quality Evaluation](8534-mesh-quality-evaluation.md)
Mesh Quality Evaluation assesses the geometric regularity of triangular meshes, specifically penalizing long, skinny, or degenerate triangles in favor of well-shaped ones. It differs from accuracy metrics like Chamfer Distance by focusing on topological and shape integrity rather than point-wise proximity to a ground truth.

### [Evaluation Pipeline](9358-evaluation-pipeline.md)
This pipeline computes Chamfer distance ($C_{\ell1}$), intersection-over-union (IoU), normal consistency (NC), and F-score on reconstructed surfaces visible in the input color/depth streams. It differs from standard mesh evaluation by explicitly culling occluded or unseen geometry to prevent error inflation from regions where the network output is unpredictable or where ground truth contains hidden surfaces. It builds on [Mesh/Point Cloud Evaluation Metrics](4797-mesh-point-cloud-evaluation-metrics.md) but restricts the comparison domain to the viewing frusta of the input cameras.

### [Evaluation Metrics](9899-evaluation-metrics.md)
Evaluation Metrics computes quantitative assessments of rendering and reconstruction quality by comparing generated outputs against ground truth data. It addresses the problem of objectively measuring fidelity in 3D graphics, covering data-level, image-level, and geometric-level errors. Unlike its sibling [Evaluation Pipeline](9358-evaluation-pipeline.md), which orchestrates the workflow, this method defines the specific mathematical functions for quality calculation. It differs from [Cloud-to-Mesh Accuracy Metrics](10560-cloud-to-mesh-accuracy-metrics.md) by focusing on image and volume data metrics (PSNR, LPIPS) rather than purely geometric point-cloud distances, though it shares the Chamfer Distance metric for isosurface evaluation.

### [Cloud-to-Mesh Accuracy Metrics](10560-cloud-to-mesh-accuracy-metrics.md)
Cloud-to-Mesh Accuracy Metrics quantify how closely a reconstructed point cloud reflects ground truth locations by computing the Euclidean displacements from each point in the compared cloud to the nearest facet of a reference mesh. Unlike symmetric metrics that average errors in both directions, this method specifically evaluates the precision of the reconstruction by measuring the orthogonal distance to the reference surface, handling cases where the projection falls outside the triangle boundaries by measuring to the nearest edge.

### [SDF Consistency Metrics](13280-sdf-consistency-metrics.md)
SDF Consistency Metrics evaluate how closely a reconstructed mesh matches the trained Signed Distance Function (SDF) field by measuring the network's SDF output at points on the mesh surface and at its vertices. Unlike geometric metrics that compare two meshes, this method assesses the internal consistency of the implicit representation, ensuring the extracted geometry aligns with the learned field. It is distinct from [Cloud-to-Mesh Accuracy Metrics](10560-cloud-to-mesh-accuracy-metrics.md) which measure distance to ground truth, and [Evaluation Metrics](9899-evaluation-metrics.md) which provide a broader suite of quality indicators.

### Shape Novelty Verification
To verify generated models are new shapes and not memorized training data, given a generated mesh, retrieve the most similar mesh in the training set by computing the Chamfer distance of point cloud samples from the generated mesh against all meshes in the training set [S3, unofficial].

### Evaluation Metrics for 3D Reconstruction
Computes geometric accuracy, completeness, photometric precision/recall, F-score, normal consistency, and PSNR to evaluate neural scene reconstruction quality [S4].
*   **PSNR Formula**: $PSNR = \frac{1}{N_I} \sum_{n=1}^{N_I} 20 \cdot \log_{10} \left( \frac{1}{\sqrt{MSE(C^n_{pred}, C^n_{gt})}} \right)$ [S4].
*   **Parameters**: $P$: Sampled point cloud from the predicted mesh; $n_p, n_{\bar{p}}$: Normal vectors computed from the prediction and ground truth point clouds respectively; $N_I$: Number of images used for evaluation [S4].

## Operating characteristics
*   **Time Complexity**: Dominated by nearest neighbor queries, $O(N \log N)$ for KDTree construction and $O(N \log N)$ for queries, where $N$ is the number of sampled points [S2, unofficial]. Topological checks (self-intersection) can be $O(T^2)$ or $O(T \log T)$ depending on implementation, where $T$ is the number of triangles [S3, unofficial].
*   **Memory Complexity**: $O(N)$ for storing point clouds and trees [S2, unofficial].
*   **Performance**: Metrics are sensitive to sampling density; `num_points` should be high enough to capture details but low enough for runtime feasibility (default 100k) [S2, unofficial].
*   **Strengths**: Provides a multi-faceted view of quality (geometric, normal, topological) [S2, unofficial]. F-score handles threshold-based correctness well [S1, unofficial].
*   **Limitations**: Chamfer Distance is sensitive to outliers and sampling bias [S4]. F-score depends heavily on the choice of `f1_threshold` [S2, unofficial]. Topological metrics require valid mesh structures, not just point clouds [S3, unofficial].
*   **When to use**: When evaluating neural reconstruction methods (NeRF, SDF) where both geometric accuracy and mesh regularity matter [S2, unofficial][S4].
*   **When not to use**: When only point-wise accuracy is needed (use [Chamfer Distance](2446-chamfer-distance.md)) or when evaluating purely volumetric data without surface extraction [S3, unofficial].

## Background
The method originates from the need to comprehensively evaluate 3D reconstruction quality in neural rendering and generative models [S1, S2, S3, unofficial]. F-score and Chamfer Distance are standard in point cloud completion and reconstruction benchmarks [S1, unofficial][S4]. Mesh quality metrics (aspect ratio, flipped triangles) are adapted from computer graphics mesh validation tools [S3, unofficial]. The integration of edge-specific metrics (ECD, EF1) addresses the limitation of global metrics in capturing sharp feature preservation [S2, unofficial]. The pipeline approach (culling occluded geometry) was introduced to handle the ambiguity of hidden surfaces in unbounded scenes [S1, unofficial].
