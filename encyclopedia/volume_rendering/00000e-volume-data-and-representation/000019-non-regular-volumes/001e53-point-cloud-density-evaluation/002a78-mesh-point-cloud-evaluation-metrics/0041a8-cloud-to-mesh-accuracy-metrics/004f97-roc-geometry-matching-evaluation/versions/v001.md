# ROC Geometry Matching Evaluation

Also called: Point cloud matching for ROC curves

## Overview
ROC Geometry Matching Evaluation quantifies the geometric accuracy of a reconstructed point cloud $B$ against a reference point cloud $A$ by computing the True Positive Rate (TPR) and False Positive Rate (FPR) at a specific distance threshold [S1]. Unlike symmetric metrics such as D1/D2 that average errors in both directions and assume similar point counts, this asymmetric method handles cases where the predicted cloud $B$ contains significantly more points than the reference $A$, preventing artificially inflated accuracy scores in the $A \rightarrow B$ direction [S1].

## How it works
**Inputs:**
- Reference point cloud $A = \{a_1, \dots, a_P\}$ in World Coordinate System (WCS).
- Predicted point cloud $B = \{b_1, \dots, b_M\}$ in World Coordinate System (WCS).
- Voxel grid resolution $R$ (e.g., $512^3$) used to define the search space for negative samples [S1].

**Outputs:**
- True Positive Rate (TPR).
- False Positive Rate (FPR).

**Data Structures:**
- Point clouds $A$ and $B$ are stored as lists of 3D coordinates $(x, y, z)$.
- A voxel grid of size $R \times R \times R$ is implicitly or explicitly used to determine the total number of negative samples $N$ [S1].

**Parameters:**
- $\delta$: Distance threshold for a match. Set to the diagonal of a voxel in $B$ scaled to world coordinates. If the voxel size in world units is $s$, then $\delta = s\sqrt{3}$ [S1].
- $P$: Total number of points in reference cloud $A$ [S1].
- $N$: Total number of negative samples, calculated as the total number of points in the voxelized grid minus $P$ [S1].

**Steps:**
1.  **Calculate Threshold $\delta$**: Determine the voxel size in world coordinates based on the scene bounds and grid resolution $R$. Compute $\delta = \text{voxel\_size} \times \sqrt{3}$ [S1].
2.  **Compute Distances**: For each point $b_i \in B$, calculate the minimum Euclidean distance to any point $a_j \in A$:
    $$ d(b_i, A) = \min_{a_j \in A} \| b_i - a_j \|_2 $$
3.  **Classify Points**:
    -   A point $b_i$ is a **True Positive (TP)** if $d(b_i, A) \le \delta$.
    -   A point $b_i$ is a **False Positive (FP)** if $d(b_i, A) > \delta$.
4.  **Count Positives and Negatives**:
    -   $TP = \sum_{b_i \in B} \mathbb{1}(d(b_i, A) \le \delta)$
    -   $FP = \sum_{b_i \in B} \mathbb{1}(d(b_i, A) > \delta)$
    -   $P = |A|$ (Total points in reference cloud) [S1].
    -   $N = R^3 - P$ (Total grid points minus reference points) [S1].
5.  **Compute Rates**:
    -   $TPR = \frac{TP}{P}$
    -   $FPR = \frac{FP}{N}$

**Pseudocode:**
```python
import math
import numpy as np

def roc_geometry_matching_evaluation(A, B, grid_resolution):
    """
    Computes TPR and FPR for point cloud matching.
    
    Args:
        A: numpy array of shape (P, 3), reference point cloud in WCS.
        B: numpy array of shape (M, 3), predicted point cloud in WCS.
        grid_resolution: int, resolution of the voxel grid (e.g., 512).
        
    Returns:
        tpr: float, True Positive Rate.
        fpr: float, False Positive Rate.
    """
    P = A.shape[0]
    total_grid_points = grid_resolution ** 3
    N = total_grid_points - P
    
    # Calculate voxel size in world coordinates.
    # Note: The source assumes the scene bounds are normalized or known.
    # If bounds are [-1, 1], the world size is 2.
    # This implementation assumes a standard normalized world size of 2.0.
    world_size = 2.0
    voxel_size = world_size / grid_resolution
    delta = voxel_size * math.sqrt(3)
    
    # Calculate minimum distance from each point in B to any point in A.
    # Using broadcasting for efficiency: (M, 1, 3) - (1, P, 3) -> (M, P, 3)
    # This step is computationally expensive for large P and M.
    # [G] In practice, a KD-tree or voxel-based search is used for A to speed up min distance calculation.
    diff = B[:, np.newaxis, :] - A[np.newaxis, :, :]
    distances = np.linalg.norm(diff, axis=2)
    min_distances = np.min(distances, axis=1)
    
    # Classify points
    tp_mask = min_distances <= delta
    fp_mask = min_distances > delta
    
    TP = np.sum(tp_mask)
    FP = np.sum(fp_mask)
    
    # Compute rates
    # Guard against division by zero if P or N is 0
    if P == 0:
        tpr = 0.0
    else:
        tpr = TP / P
        
    if N == 0:
        fpr = 0.0
    else:
        fpr = FP / N
        
    return tpr, fpr
```

**Edge Cases and Pitfalls:**
-   **Grid Resolution Dependency**: The value of $N$ depends heavily on the chosen voxel grid resolution. A higher resolution increases $N$, potentially lowering the FPR if the number of false positives remains constant. The source cites $512^3$ for "resolution 9" [S1].
-   **Asymmetry**: This metric is asymmetric. It evaluates how well $B$ covers $A$ (via TPR) and how much $B$ deviates from $A$ (via FPR). It does not penalize $A$ for missing parts of $B$ [S1].
-   **Threshold Sensitivity**: The choice of $\delta$ is critical. Using the voxel diagonal provides a scale-invariant threshold relative to the grid, but it may not reflect perceptual accuracy for all applications [S1].

## Operating characteristics
-   **Time Complexity**: The naive calculation of minimum distances is $O(M \cdot P)$, where $M$ is the number of points in $B$ and $P$ is the number of points in $A$. Spatial indexing structures (e.g., KD-trees) can reduce this to approximately $O(M \log P)$ [G].
-   **Memory Complexity**: $O(M + P)$ to store the point clouds and distance arrays.
-   **Strengths**: Effective for evaluating pruning methods where the predicted cloud $B$ has a significantly different number of points than the reference $A$. It avoids the bias of symmetric metrics like D1/D2 which assume similar point counts [S1].
-   **Limitations**: The metric is sensitive to the voxel grid resolution used to calculate $N$. It does not provide a single scalar score but rather a curve (ROC) when evaluated at multiple thresholds [S1].

## Background
This method was introduced in the context of evaluating visibility-based geometry pruning for neural plenoptic scene representations, specifically PlenOctrees [S1]. It was developed to address the limitations of symmetric Chamfer Distance variants (D1/D2) when comparing point clouds of vastly different densities, which is common in neural rendering compression and pruning tasks [S1].
