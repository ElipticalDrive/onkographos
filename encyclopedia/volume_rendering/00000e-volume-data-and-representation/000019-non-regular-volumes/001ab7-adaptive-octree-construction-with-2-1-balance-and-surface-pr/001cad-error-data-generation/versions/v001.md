# Error Data Generation
Also called: Adaptive Resolution Error Measure
## Overview
Error Data Generation computes a quantitative measure of the approximation error introduced by the Adaptive Resolution (AR) data reduction process [S1, unofficial]. It solves the problem of quantifying data loss during the transition from fine-grained volume data to a coarser, adaptive representation, enabling the inclusion of error metrics in subsequent isosurface rendering pipelines [S1, unofficial]. It differs from sibling methods like [Octree Balance Subdivision](847-octree-balance-subdivision.md) or [Constrained Octree Refinement](2426-constrained-octree-refinement.md) by focusing specifically on the numerical fidelity of the data values themselves rather than topological constraints or balance rules.
## How it works
**Inputs and Outputs:**
- Input: A set of coarse data values $V_c$ and their corresponding fine-resolution child values $V_f$.
- Output: A set of error values $E$ associated with each coarse node.

**Data Structures:**
The error data is stored alongside the adaptive resolution data. For each coarse node $i$, an error value $E_i$ is computed. The layout is typically a scalar field aligned with the coarse grid nodes.

**Steps:**
1.  **Identify Child Nodes:** For each coarse data point (parent node) in the adaptive resolution representation, identify the 8 child nodes in the next finer resolution level of the octree [S1, unofficial].
2.  **Compute Individual Errors:** For each of the 8 child nodes $j$, calculate the difference between the child's original value $v_{f,j}$ and the parent's coarse value $v_c$. The error for a single child is typically the squared difference or absolute difference, though the source specifies "average error" implying a mean squared error approach is standard for such metrics [S1, unofficial]. Let $e_j = (v_{f,j} - v_c)^2$.
3.  **Aggregate Error:** Compute the error for the coarse point $E_i$ as the average of the errors of its 8 children:
    $$ E_i = \frac{1}{8} \sum_{j=1}^{8} (v_{f,j} - v_c)^2 $$
    This represents the mean square error of representing the 8 original fine values with the single coarse value [S1, unofficial].
4.  **Store Error:** Associate $E_i$ with the coarse node for use in rendering.

**Parameters:**
- The factor 8 is fixed by the octree structure (binary subdivision in 3D) [S1, unofficial].

**Edge Cases and Pitfalls:**
- If a coarse node has no children (leaf in the fine grid or boundary condition), the error is undefined or zero depending on implementation. The source assumes a regular octree structure where coarse points map to 8 children [S1, unofficial].
- Precision issues may arise if the range of values is large; normalization might be required for rendering [G].

**Pseudocode:**
```python
def compute_error_data(coarse_values, fine_values, octree_structure):
    """
    coarse_values: dict mapping node_id to value v_c
    fine_values: dict mapping node_id to value v_f
    octree_structure: function get_children(node_id) returning list of 8 child node IDs
    
    Returns: dict mapping node_id to error E
    """
    error_data = {}
    
    for node_id, v_c in coarse_values.items():
        children_ids = get_children(node_id)
        
        # Ensure all 8 children exist
        if len(children_ids) != 8:
            # Handle boundary or incomplete nodes [G]
            error_data[node_id] = 0.0
            continue
            
        sum_squared_diff = 0.0
        for child_id in children_ids:
            v_f = fine_values[child_id]
            diff = v_f - v_c
            sum_squared_diff += diff * diff
            
        # Average error (Mean Squared Error)
        error_data[node_id] = sum_squared_diff / 8.0
        
    return error_data
```
## Subtopics

### [Hierarchical Error Metric Calculation](6607-hierarchical-error-metric-calculation.md)
A fast method to calculate error values at every tree node based on the mean square error (MSE) between a parent node's low-resolution data and its eight immediate child nodes, taking the maximum error of the children into account. This avoids the high I/O and computational cost of comparing against raw data.

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(N)$ where $N$ is the number of coarse nodes, as each node requires a constant number of operations (8 subtractions, 8 squares, 1 sum, 1 division) [S1, unofficial].
- Memory: $O(N)$ for storing the error values alongside the coarse data [S1, unofficial].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Scales linearly with the number of adaptive resolution nodes [S1, unofficial].

**Strengths and Limitations:**
- Strength: Simple to compute and provides a direct measure of data fidelity [S1, unofficial].
- Limitation: Does not account for geometric features or topological changes, only value approximation [S1, unofficial].

**When to Use:**
- When isosurface rendering quality needs to be improved by incorporating error metrics [S1, unofficial].
- When data reduction is performed and the impact on visual fidelity needs to be quantified [S1, unofficial].

**When Not to Use:**
- When computational resources are extremely limited and error metrics are not needed for rendering [S1, unofficial].
- When the focus is on topological correctness rather than value approximation [S1, unofficial].
## Background
**Origin:**
- The method was introduced by Shu, Zhou, and Kankanhalli in their work on IsoSurface Rendering of Adaptive Resolution Data [S1, unofficial].

**History and Development:**
- The method is part of the Adaptive Resolution (AR) data representation framework, which aims to reduce memory space and computation time during rendering by eliminating redundant cubes from the data set [S1, unofficial].
- It builds on prior research in adaptive marching cubes, such as the work by Shu, Zhou, and Kankanhalli [9] (cited in [S1, unofficial]), who used a static uniform resolution representation with dynamic MR traversal to speed up the marching cubes algorithm.

**Where it is used:**
- IsoSurface Rendering of Adaptive Resolution Data [S1, unofficial].
