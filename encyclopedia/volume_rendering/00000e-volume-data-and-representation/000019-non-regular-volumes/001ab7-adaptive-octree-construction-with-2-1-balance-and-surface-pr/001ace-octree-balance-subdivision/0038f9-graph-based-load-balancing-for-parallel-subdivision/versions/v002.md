# Graph-based Load Balancing for Parallel Subdivision

Also called: Bajaj’s Parallel Algorithm, Octree-based Partitioning with Metis Merging, Static and random subdivision with graph-based balancing

## Overview
This method balances parallel workloads for isosurface extraction by distributing volumetric blocks such that each process holds an equal number of active cells for any isovalue [S1]. It differs from spatial-only partitioning by analyzing the distribution of active cells across isovalue thresholds, ensuring uniform computational load across parallel processes regardless of the specific isosurface threshold [S1].

## How it works
**Inputs:** A volumetric dataset and a target number of parallel processes $P$ [G].
**Outputs:** A partitioning of the volume into $P$ segments, where each segment contains a subset of the data [G].

**Data Structures:**
1. **Octree:** A space-partitioning structure where leaves are cubic boxes [G].
2. **Adjacency Graph:** An undirected graph $G=(V, E)$ where $V$ is the set of octree leaves and $E$ represents valid merge connections [G].
3. **Segment Map:** A mapping from each leaf to a segment ID $s \in \{0, \dots, P-1\}$ [G].

**Steps:**

1. **Initial Subdivision:** Subdivide the volume into fine-grain blocks using static and random subdivision among the $P$ nodes [S1]. Alternatively, construct an octree where leaves are subdivided at their center if the number of vertices exceeds a maximal limit $N_{\text{max}}$, reflecting point density [S2].

2. **Graph Construction:** Create an undirected graph where nodes are the octree leaves [S2]. Add an edge between two leaves $u$ and $v$ if they are spatial neighbors in the octree and their volumes do not differ by a factor of more than 2 [S2]. In the static/random approach, blocks are examined to extract a graph representing the range of values assumed by cell points and the number of active cells intersected for each value [S1].

3. **Graph Partitioning:** Run a graph partitioning algorithm (specifically Metis 4.0) on the constructed graph to merge leaves into $P$ balanced segments [S2]. The goal is to ensure each parallel process has the same amount of active cells for any isovalue [S1].

4. **Assignment:** For tetrahedral meshes, iterate over all tetrahedra, determine the segment indices of all four vertices, and assign the tetrahedron to the segment with the smallest index [S2]. For volumetric blocks, distribute blocks having similar graph characteristics among the nodes [S1].

**Parameters:**
* $N_{\text{max}}$: Maximum vertices per octree leaf. Not given in the sources.
* Partitioning Tool: Metis 4.0 [S2].

**Edge Cases and Pitfalls:**
* **Data Duplication:** The main drawback is the production of a large number of duplicated data [S1].
* **Boundary Shape:** The method creates well-shaped boundaries between segments sufficient for multi-triangulations, avoiding the need to compute tetrahedron centers [S2].

**Pseudocode:**
```python
def graph_based_load_balancing(volume, P, max_vertices_per_leaf):
    # Step 1: Initial Subdivision
    # Build octree by recursively subdividing leaves at center if vertex count > max_vertices_per_leaf [S2]
    # Alternative for static/random variant: leaves = static_random_subdivide(volume, P) [S1]
    leaves = build_octree(volume, max_vertices_per_leaf)

    # Step 2: Graph Construction
    graph_nodes = list(range(len(leaves)))
    graph_edges = []
    for i, u in enumerate(leaves):
        for j, v in enumerate(leaves):
            if i < j and are_octree_neighbors(u, v):
                vol_u, vol_v = compute_volume(u), compute_volume(v)
                if max(vol_u, vol_v) / min(vol_u, vol_v) <= 2:  # [S2]
                    graph_edges.append((i, j))
                # Alternative graph construction: encode value ranges and active cell counts per isovalue [S1]

    # Step 3: Graph Partitioning
    # Call Metis 4.0 to partition graph_nodes and graph_edges into P segments [S2]
    # Alternative: distribute blocks with similar graph characteristics to P processes [S1]
    segments = metis_partition(graph_nodes, graph_edges, P)

    # Step 4: Assignment
    segment_map = {leaf: seg for leaf, seg in zip(leaves, segments)}
    if tetrahedral_mesh:
        for tet in tetrahedra:
            seg_indices = [segment_map[v] for v in tet.vertices]
            tet.segment = min(seg_indices)  # [S2]
    else:
        for block in leaves:
            assign_block_to_process(block, segments[block])  # [S1]
    return segments
```

## Subtopics

## Operating characteristics
* **Time Complexity:** Preprocessing analysis is executed mostly in parallel [S1]. Graph partitioning is performed using Metis 4.0 to merge leaves into balanced segments [S2].
* **Memory Complexity:** High memory overhead due to data duplication [S1].
* **Strengths:** Ensures uniform load for any isovalue; suitable for interactive environments [S1].
* **Limitations:** Significant data duplication; requires preprocessing [S1].
* **When to use:** Used when interactive environments require uniform active cell counts across varying isovalue thresholds [S1].
* **When not to use:** Used when memory bandwidth is constrained due to duplication [S1].

## Background
Originating from work by Bajaj et al. (referenced as [44] in [S1]), this algorithm was designed for parallel isosurface extraction in distributed environments [S1]. It was evaluated against pure data parallel and dynamic distribution algorithms [S1]. The octree-based variant was developed for segment-based tetrahedral meshing, particularly for CFD simulations [S2].
