# Topological Octree Construction

Also called: Adaptive Octree Refinement, Lobello et al. 2012 Method, Lobello et al. 2014 Method, Regular Octree Construction

## Overview
Topological Octree Construction is an adaptive subdivision strategy that refines a 3D grid based on topological complexity to ensure the extracted implicit surface is manifold, meaning it contains no non-manifold edges or vertices [S1, unofficial]. It differs from sibling methods by explicitly defining "complex" cells via edge and face intersection analysis rather than relying solely on scalar value heterogeneity or error bounds [S1, unofficial]. It builds on [Adaptive Octree Construction with 2:1 Balance and Surface Propagation](830-adaptive-octree-construction-with-2-1-balance-and-surface-pr.md) by providing the specific topological criteria for refinement and the balancing mechanism.

## How it works
**Inputs:**
- Binary volume data $V$ where $V(x,y,z) \in \{0, 1\}$, representing the interior ($1$) and exterior ($0$) of the object.
- Minimum tree level $L_{min}$ and maximum tree level $L_{max}$.
- Construction mode: "Regular" (Lobello et al. 2012) or "Adaptive" (Lobello et al. 2014) [S1, unofficial].

**Outputs:**
- An octree data structure where leaf cells satisfy topological safety constraints.
- A 2:1 balanced tree where leaf depths differ by at most one level [S1, unofficial].

**Data Structures:**
- **Octree Node:** Contains a Morton key (integer) for spatial/hierarchical indexing, a depth level, a boolean flag `is_leaf`, and a list of 8 child pointers (null if leaf) [S1, unofficial].
- **Face Voxels:** For a given face, a 2D grid of voxel values corresponding to the intersection of the implicit surface boundary $\partial V$ with that face.

**Definitions:**
- **Complex Edge:** An edge of a cell is complex if it is intercepted by $\partial V$ more than once [S1, unofficial].
- **Complex Face:** A face is complex if it is intercepted by $\partial V$ but contains no complex edges, yet possesses an isolated connected component crossing it [S1, unofficial].
- **Complex Cell:** A leaf cell $C$ is complex if at least one of its edges or faces is complex [S1, unofficial].
- **Non-homogeneous Cell:** A cell where at least one corner has a different scalar value than the others (applies only to Regular Construction) [S1, unofficial].

**Algorithm Steps:**

1. **Initialization:** Create a root node at level $L_{min}$. Subdivide the volume into a regular grid of cells at level $L_{min}$ [S1, unofficial].

2. **Complexity Detection (Iterative):**
   For each leaf cell $C$ in the current octree:
   
   a. **Check Edges:** Iterate through the 12 edges of $C$. For each edge, traverse the voxels along the edge. If the number of sign changes (transitions between 0 and 1) is greater than 1, the edge is complex. If any edge is complex, mark $C$ as complex [S1, unofficial].
   
   b. **Check Faces:** If $C$ is not yet marked complex, iterate through the 6 faces. For each face:
      i. Extract the 2D grid of voxel values on the face.
      ii. Apply the **Hoshen-Kopelman algorithm** to identify connected components of internal voxels (voxels with value 1, assuming 1 is interior) [S1, unofficial].
      iii. **Hoshen-Kopelman Implementation:**
          - Initialize a label counter $L = 0$.
          - Create a label map for the face voxels, initialized to 0.
          - Traverse face voxels in raster order.
          - If a voxel $v$ has value 1 (internal):
            - If $v$ has no label and no labeled neighbors, increment $L$ and assign label $L$ to $v$.
            - If $v$ has labeled neighbors, assign the label of the first labeled neighbor to $v$.
            - If $v$ has multiple labeled neighbors with different labels, union the sets of these labels (standard union-find operation) and update all voxels in the affected sets to the representative label.
      iv. After labeling, check each connected component. If a component exists such that none of its voxels belong to the boundary edges of the face, the face is complex. If any face is complex, mark $C$ as complex [S1, unofficial].

   c. **Check Non-homogeneity (Regular Construction Only):**
      If the construction mode is "Regular", check if $C$ is non-homogeneous. If the 8 corners of $C$ do not all have the same value, mark $C$ as complex [S1, unofficial].

3. **Subdivision:**
   If $C$ is marked complex and its current depth $d < L_{max}$:
   - Subdivide $C$ into 8 children at depth $d+1$.
   - Remove $C$ from the leaf list.
   - Add the 8 new children to the leaf list.
   - If $d = L_{max}$, the cell remains a leaf (maximum refinement reached) [S1, unofficial].

4. **Balancing:**
   After all complex cells are subdivided, enforce 2:1 balance. If any two face-adjacent leaf cells differ in depth by more than 1 level, subdivide the shallower cell until the constraint is satisfied. This ensures surface quality by preventing large jumps in resolution [S1, unofficial].

5. **Termination:**
   Repeat steps 2-4 until no leaf cells require subdivision or all complex cells are at $L_{max}$ and the tree is balanced.

## Subtopics

### Octree Face Connection Strategy
A strategy to connect vertices on octree faces to ensure that further subdivision does not change the isotopy of the surface, assuming a vertical parametrizable direction [S2]. For top and bottom faces (perpendicular to the parametrizable direction), vertices can be connected arbitrarily because changing connections corresponds to moving a saddle point through the surface, which does not affect isotopy in the union of adjacent cubes [S2]. For side faces, the gradient bound does not hold, and the intersection curve can pierce opposite edges, preventing unique topology determination. However, topology changes on side faces correspond to moving the surface sideways, which does not affect the global surface topology. To construct an isotopic approximation, newly created vertices on the boundary of an octree face are examined. If the configuration could correspond to a parametrizable intersection curve, vertices are connected to maintain parametrizability. For other configurations, vertices are connected pairwise starting from an arbitrary vertex [S2].

## Operating characteristics
- **Time Complexity:** Depends on the number of complex cells and the cost of Hoshen-Kopelman labeling on faces. In the worst case, every cell is complex, leading to $O(N)$ subdivisions where $N$ is the number of voxels, but typically much less due to adaptivity.
- **Memory Complexity:** Proportional to the number of nodes in the octree. The 2:1 balance constraint increases memory usage compared to a purely topological octree but improves surface quality [S1, unofficial].
- **Performance:** Regular Construction (Lobello et al. 2012) results in all surface-intersecting cells being at the maximum refinement level, leading to higher memory usage but potentially simpler connectivity [S1, unofficial]. Adaptive Construction (Lobello et al. 2014) allows surface-intersecting cells at various levels, reducing memory but requiring more complex balancing [S1, unofficial].
- **Strengths:** Guarantees manifold surfaces by construction. Efficiently refines only where necessary.
- **Limitations:** Requires careful implementation of Hoshen-Kopelman and balancing. Sensitive to the choice of $L_{min}$ and $L_{max}$.

## Background
The method was introduced by Lobello et al. in 2012 and 2014 [S1, unofficial]. The 2012 paper proposed a "Regular Construction" using both complex cell and non-homogeneous cell rules. The 2014 paper refined this to an "Adaptive Construction" using only the complex cell rule, allowing for variable refinement levels. The method is used in the extraction of isosurfaces from massive binary volumes, such as salt domes [S1, unofficial]. The face connection strategy is described in the context of isotopic approximation of implicit curves and surfaces [S2].
