# NeX (Neural Basis Expansion)
Also called: Neural Basis Expansion for MPI

## Overview
NeX is a novel view synthesis method that extends the Multiplane Image (MPI) representation with neural basis expansion to capture complex view-dependent effects efficiently [S1]. Unlike standard MPIs which assume view-independent colors, NeX models the angular variation of radiance using learned basis functions, allowing it to reproduce sharp highlights and specular reflections that fixed-basis methods (like Spherical Harmonics) or sparse-input methods (like DeepView) struggle with [S1]. It builds on [Neural and primitive-based representations](10-neural-and-primitive-based-representations.md) by combining the structural efficiency of MPIs with the expressive power of implicit neural fields for specific parameter groups.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N_{in}$ input images (typically 12) with known camera poses and intrinsics.
*   **Output:** A rendered image for a target view (held-out camera pose) by compositing planes along the viewing ray.

**Data Structures:**
The scene is represented as a stack of $P$ planes. Each plane $p$ at depth $z_p$ contains:
1.  **Alpha Transparency ($A_p$):** Stored implicitly via a neural network $f_A(\mathbf{x})$ [S1].
2.  **Base Color ($K_{0,p}$):** Stored explicitly as a 2D texture (RGB) [S1].
3.  **View-Dependent Coefficients ($K_{1,p}, \dots, K_{N,p}$):** Stored implicitly via a neural network $f_K(\mathbf{x})$ [S1].

The optimal configuration identified in ablation studies is **Im-Ex-Im**: Implicit Alpha, Explicit Base Color, Implicit View-Dependent Coefficients [S1].

**Basis Functions:**
The view-dependent color at a point $\mathbf{x}$ on plane $p$ for viewing direction $\mathbf{d}$ is computed as:
$$ C(\mathbf{x}, \mathbf{d}) = K_{0,p}(\mathbf{x}) + \sum_{i=1}^{N} K_{i,p}(\mathbf{x}) \cdot B_i(\mathbf{d}) $$
Where:
*   $K_{0,p}(\mathbf{x})$ is the base color (view-independent).
*   $K_{i,p}(\mathbf{x})$ are the learned coefficients for the $i$-th basis function.
*   $B_i(\mathbf{d})$ are the basis functions of the viewing direction $\mathbf{d}$. In NeX, these are **learned** via a small neural network, outperforming fixed bases like Taylor Series (TS), Spherical Harmonics (SH), Hemispherical Harmonics (HSH), Jacobi Spherical Harmonics (JH), and Fourier Series (FS) [S1].

**Rendering (Alpha Compositing):**
For a ray $\mathbf{r}$, the color $C_{out}$ and opacity $\alpha_{out}$ are computed by standard volume rendering integration over the planes:
$$ \alpha_{out} = 1 - \prod_{p=1}^{P} (1 - \alpha_p) $$
$$ C_{out} = \sum_{p=1}^{P} C_p \cdot \alpha_p \cdot \prod_{j=1}^{p-1} (1 - \alpha_j) $$
Where $\alpha_p$ is the alpha value sampled from the implicit network $f_A$ at the intersection of the ray and plane $p$, and $C_p$ is the view-dependent color computed using the basis expansion.

**Training:**
1.  Initialize $P$ planes.
2.  Define implicit networks for $A$ and $K_{1..N}$, and explicit textures for $K_0$.
3.  Render images for training views.
4.  Minimize reconstruction loss (e.g., MSE) between rendered images and ground truth input views.
5.  Optimize parameters using gradient descent.

import torch
import torch.nn as nn
import torch.nn.functional as F

class NeXModel:
    def __init__(self, num_planes, num_basis_coeffs, image_height, image_width):
        self.num_planes = num_planes
        self.num_basis = num_basis_coeffs
        self.height = image_height
        self.width = image_width
        
        # Explicit storage for Base Color K0
        # Shape: (num_planes, 3, height, width)
        self.K0 = nn.Parameter(torch.randn(num_planes, 3, height, width))
        
        # Implicit storage for Alpha A and View-Dependent Coeffs K1..KN
        # Using a simple MLP as placeholder for the implicit function f_theta
        # Input: 2D coordinate (u, v) normalized to [-1, 1]
        # Output: 1 + num_basis coefficients
        self.implicit_net = nn.Sequential(
            nn.Linear(2, 64),
            nn.ReLU(),
            nn.Linear(64, 64),
            nn.ReLU(),
            nn.Linear(64, 1 + num_basis) # First output is Alpha, rest are K1..KN
        )
        
        # Learned basis functions network
        # Input: viewing direction (3D vector)
        # Output: num_basis coefficients
        self.basis_net = nn.Sequential(
            nn.Linear(3, 64),
            nn.ReLU(),
            nn.Linear(64, num_basis)
        )
        
        # Plane depths (z-coordinates)
        # Initialized to span the scene depth range
        self.plane_depths = nn.Parameter(torch.linspace(0.1, 1.0, num_planes))

    def get_basis_coeffs(self, view_direction):
        """
        Computes the basis function values B_i(d) for a given view direction.
        In NeX, these are learned.
        """
        # view_direction: (batch, 3)
        return self.basis_net(view_direction)

    def get_implicit_params(self, coords):
        """
        Samples implicit network for Alpha and K1..KN at 2D coordinates.
        coords: (batch, 2) normalized [-1, 1]
        Returns: alpha (batch, 1), K_coeffs (batch, num_basis)
        """
        output = self.implicit_net(coords)
        alpha = torch.sigmoid(output[:, 0:1]) # Alpha must be in [0, 1]
        k_coeffs = output[:, 1:]
        return alpha, k_coeffs

    def render_ray(self, ray_origin, ray_direction, plane_depths):
        """
        Renders a single ray through the MPI.
        """
        # Calculate intersection of ray with each plane
        # z = plane_depth
        # ray_origin + t * ray_direction = (x, y, plane_depth)
        # t = (plane_depth - ray_origin.z) / ray_direction.z
        t = (plane_depths - ray_origin[2]) / ray_direction[2]
        
        # Intersection points in 3D
        points_3d = ray_origin.unsqueeze(1) + t.unsqueeze(1) * ray_direction.unsqueeze(1)
        
        # Project to 2D texture coordinates (u, v)
        # Assuming standard pinhole camera projection logic here
        # This part depends on specific camera intrinsics not detailed in source
        # Placeholder for coordinate sampling logic
        coords_2d = self.project_to_uv(points_3d) 
        
        # Get basis coefficients for this view direction
        basis_vals = self.get_basis_coeffs(ray_direction) # (num_basis,)
        
        alpha_accum = 0.0
        color_accum = 0.0
        
        for p in range(self.num_planes):
            # Sample implicit network for this plane's alpha and K coeffs
            # Note: In implementation, coords_2d would be indexed per plane
            # or the network takes plane index as input. 
            # Source implies separate implicit nets or shared net with plane context.
            # We assume shared net for simplicity, but source suggests 
            # "implicit function" for parameters.
            
            # For correctness with source "Im-Ex-Im":
            # K0 is explicit texture lookup
            k0 = F.grid_sample(self.K0[p:p+1], coords_2d[p:p+1].unsqueeze(0).unsqueeze(0), 
                               align_corners=True).squeeze() # (3,)
            
            # Implicit for Alpha and K1..KN
            # Assuming coords_2d is normalized for the plane's local space
            alpha_p, k_coeffs_p = self.get_implicit_params(coords_2d[p]) # (1,), (num_basis,)
            
            # Compute view-dependent color
            # C = K0 + sum(Ki * Bi)
            # k_coeffs_p is (num_basis,), basis_vals is (num_basis,)
            view_dep_color = torch.sum(k_coeffs_p * basis_vals, dim=0) # (num_basis,) dot product
            color_p = k0 + view_dep_color
            
            # Alpha compositing
            alpha_p = alpha_p.item()
            color_p = color_p.cpu().numpy() # Simplified for pseudocode flow
            
            transmittance = 1.0 - alpha_accum
            color_accum += transmittance * alpha_p * color_p
            alpha_accum += transmittance * alpha_p
            
            if alpha_accum > 0.99:
                break
                
        return color_accum, alpha_accum

**Parameters:**
*   **Number of basis coefficients ($N$):** Varies from 0 to 20. Performance peaks at 6-9 coefficients; beyond this, overfitting occurs [S1].
*   **Number of planes ($P$):** Not explicitly fixed in the summary, but DeepView comparison uses 80 planes [S1].
*   **Resolution:** 800x480 (Spaces dataset), 1008x756 (Shiny dataset) [S1].

**Edge Cases and Pitfalls:**
*   **Stack of Cards Artifacts:** Viewing the MPI from angles far from the center reveals individual planes [S1].
*   **Extreme Highlights:** Cannot reproduce light sparkles, extremely sharp highlights, or refraction through test tubes [S1].
*   **Exposure Differences:** Uncompensated exposure differences in training images cause flickering [S1].
*   **Training Time:** Requires long training times and may need more input views to replicate complex view-dependent effects [S1].

## Operating characteristics
*   **Time Complexity:** Rendering is real-time on standard graphics hardware due to the explicit storage of base color and the low rank of the basis expansion [S1]. Training time is long [S1].
*   **Memory Complexity:** Constant with respect to spatial resolution (implicit representation for A and K), but scales with the number of planes and basis coefficients [S1].
*   **Performance:** On the Spaces dataset (12-view training, 4-view test), NeX achieves higher average PSNR (35.84 vs 31.60 for DeepView), SSIM (0.985 vs 0.978), and LPIPS (0.083 vs 0.085) than DeepView [S1].
*   **Strengths:** Captures complex view-dependent effects better than fixed bases (SH, Taylor, etc.) with the same number of coefficients [S1]. Efficient rendering.
*   **Limitations:** Inherits MPI limitations (stack of cards). Struggles with extreme specularities and refraction. Sensitive to exposure mismatches in input data [S1].

## Background
NeX was introduced in the paper "NeX: Real-time View Synthesis with Neural Basis Expansion" [S1]. It extends the Multiplane Image (MPI) representation by incorporating neural basis expansion to model view-dependent effects. The method was tested on the Spaces dataset (16 forward-facing cameras, 800x480) and the Shiny dataset (1008x756) [S1]. It compares favorably against DeepView and Soft3D [S1].
