# TriPlane NeRF

Also called: Tri-Plane representation, Tri-Planes, Tri-plane factorization, Tri-planes and K-planes, Triplane Features

## Overview
TriPlane NeRF is an explicit-implicit scene representation that models a 3D scene using three axis-aligned orthogonal feature planes [S1][S3]. It solves the scaling problems of voxel-based representations by maintaining efficiency and expressiveness while allowing for a small decoder network [S1]. Unlike Voxel NeRF, which requires large memory for high-resolution grids, TriPlane NeRF keeps the decoder small and uses explicit feature representation, enabling planes to be calculated with gradient-based optimization or produced by CNNs like StyleGAN or diffusion models [S1]. It builds on the planar factorization concept of [K-planes](3317-k-planes.md) by restricting the factorization to the three primary coordinate planes ($XY, XZ, YZ$) for static scenes [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D position $x \in \mathbb{R}^3$ and a viewing direction $d \in \mathbb{R}^3$.
*   **Output:** Color $c$ and density $\sigma$.
*   **Parameters:** $\Theta$ (decoder MLP weights), $P$ (feature planes).

**Data Structures:**
The representation consists of three feature planes $P = (P_{xy}, P_{xz}, P_{yz})$ [S1][S3].
*   Each plane $P_{ij}$ is a 2D feature map with spatial resolution $N \times N$ and $C$ channels [S1, S2].
*   Typical values: $N=128$ or $512$, $C=8$ or $32$ [S2, S6].
*   Initialization: Random or values drawn from a normal distribution with standard deviation $0.1$ [S2, S6].
*   Optimization: Updated via gradient descent during reconstruction [S2, S6].

**Steps:**
1.  **Projection:** Project the 3D position $x = (x, y, z)$ orthogonally onto the three feature planes [S2, S6].
    *   $x$ projects to $(x, y)$ on $P_{xy}$.
    *   $x$ projects to $(x, z)$ on $P_{xz}$.
    *   $x$ projects to $(y, z)$ on $P_{yz}$.
2.  **Sampling:** Identify the four nearest grid points on each plane [S6]. Retrieve the corresponding feature vectors $F_{xy}, F_{xz}, F_{yz}$ via bilinear interpolation from each plane [S1, S2, S6].
3.  **Aggregation:** Aggregate the three feature vectors. Sources specify two primary methods:
    *   Summation: $F_{agg} = F_{xy} + F_{xz} + F_{yz}$ [S1, S2].
    *   Concatenation: $f_{tri} = \text{concat}(f_{XY}, f_{YZ}, f_{ZX})$ [S6].
4.  **Decoding:** Pass the aggregated feature vector into a lightweight MLP [S1, S2]. The MLP interprets the aggregated 3D features, optionally combines them with the viewing direction $d$ (often encoded via spherical harmonics), and predicts the final color $c$ and density $\sigma$ [S2, S6].
5.  **Rendering:** Use the predicted color $c$ and density $\sigma$ for volume rendering via alpha compositing [S4].

**Formula:**
The query function is defined as [S5]:
$$ F_{\text{TriPlaneNeRF}}(x, d; \Theta, P) = (c, \sigma) $$
For sum aggregation, the neural field output is formulated as [S2]:
$$ NF(x) = \text{MLP}_\phi(f_{xy}(x) + f_{yz}(x) + f_{xz}(x)) $$

**Pseudocode:**
```python
def triplane_query(x, planes, decoder, d):
    """
    Query TriPlane NeRF for color and density at position x.
    
    Args:
        x: 3D position (x, y, z)
        planes: Dictionary containing P_xy, P_xz, P_yz. 
                Each is a tensor of shape [N, N, C].
        decoder: Function or MLP that takes aggregated features and direction d.
                 Returns (color, density).
        d: Viewing direction vector.
    
    Returns:
        color: RGB color
        density: Volume density
    """
    x_val, y_val, z_val = x
    
    # Step 1 & 2: Project and sample via bilinear interpolation
    # Coordinates are assumed normalized to [0, 1] for grid indexing.
    f_xy = bilinear_interpolate(planes['P_xy'], x_val, y_val)
    f_xz = bilinear_interpolate(planes['P_xz'], x_val, z_val)
    f_yz = bilinear_interpolate(planes['P_yz'], y_val, z_val)
    
    # Step 3: Aggregate features (Summation variant [S1, S2])
    f_agg = f_xy + f_xz + f_yz
    
    # Step 4: Decode
    color, density = decoder(f_agg, d)
    
    return color, density

def bilinear_interpolate(grid, u, v):
    """
    Perform bilinear interpolation on a 2D grid.
    
    Args:
        grid: Tensor [H, W, C]
        u, v: Normalized coordinates in [0, 1]
        
    Returns:
        Feature vector of shape [C]
    """
    h, w, c = grid.shape
    u_idx = u * (w - 1)
    v_idx = v * (h - 1)
    
    u0 = int(u_idx)
    v0 = int(v_idx)
    u1 = min(u0 + 1, w - 1)
    v1 = min(v0 + 1, h - 1)
    
    du = u_idx - u0
    dv = v_idx - v0
    
    q00 = grid[v0, u0, :]
    q01 = grid[v0, u1, :]
    q10 = grid[v1, u0, :]
    q11 = grid[v1, u1, :]
    
    top = lerp(q00, q01, du)
    bottom = lerp(q10, q11, du)
    
    return lerp(top, bottom, dv)

def lerp(a, b, t):
    return a + t * (b - a)
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Coordinates outside the $[0, 1]$ range must be clamped or handled via padding to avoid out-of-bounds interpolation errors [G].
*   **Aggregation Choice:** The choice between summation and concatenation affects the decoder's input dimension and capacity; summation keeps the channel dimension constant ($C$), while concatenation increases it ($3C$) [S1, S2].
*   **Occlusion and Hallucination:** Using only global features can lead to hallucinations, while using only local features leads to ineffective performance for occlusions and faraway views; variants combine both to mitigate these issues [S9].

## Subtopics

### [MultiPlaneGAN](7441-multiplanegan.md)
MultiPlaneGAN is a GAN-based 3D generation framework that synthesizes 3D objects by replacing the tri-plane representation of EG3D with a MultiPlane 3D representation consisting of 32 planes posed on a sphere. It differs from its parent [TriPlane NeRF](6932-triplane-nerf.md) and the baseline EG3D by using a spherical distribution of feature planes rather than axis-aligned orthogonal planes, while retaining the EG3D decoder, super-resolution module, and discriminator architecture.

### [Platonic Solid Projection](8518-platonic-solid-projection.md)
Platonic Solid Projection is a 3D space factorization method that projects 3D areas onto the faces of a Platonic solid, allowing anisotropic 3D areas to be represented on 2D planes with distinguishable characterization. It reduces memory consumption from $O(n^3)$ to $O(n^2)$ by replacing 3D volumes with 2D feature grids. Unlike the orthogonal tri-plane representation (derived from a regular hexahedron/cube), this method uses various Platonic solids to provide a flexible trade-off between rendering quality and efficiency by selecting solids with different numbers of faces.

### [Spatial Planes](9808-spatial-planes.md)
Spatial Planes is a static 3D representation that extends [TriPlane NeRF](6932-triplane-nerf.md) by utilizing three axis-aligned feature planes ($P_{XY}, P_{XZ}, P_{YZ}$) to encode volumetric information. It serves as an ablation variant of HexPlane, designed to evaluate the impact of breaking symmetry in feature plane configurations. Unlike TriPlane NeRF, which typically uses $XY, XZ, YZ$ planes for static scenes, Spatial Planes explicitly isolates these three spatial projections without temporal components, making it incapable of representing dynamic scenes on its own.

### [Tri-Mip Encoding](11551-tri-mip-encoding.md)
Tri-Mip Encoding is a method to model the pre-filtered 3D feature space by factorizing it into three orthogonal 2D mipmaps, enabling efficient area sampling for anti-aliased rendering. It decomposes 3D space into three axis-aligned planes (XY, XZ, YZ) and represents each with a mipmap structure, allowing queries to adaptively select resolution based on the sampling area size. Unlike [TriPlane NeRF](6932-triplane-nerf.md), which uses static feature planes, Tri-Mip Encoding uses mipmaps to explicitly model pre-filtered features, ensuring coherence across different viewing distances and resolutions.

### [Tri-plane Spatial Encoding with Sigma/Color MLPs](15264-tri-plane-spatial-encoding-with-sigma-color-mlps.md)
This method is the spatial representation component of the KFD-NeRF pipeline, designed to encode canonical 3D points for dynamic neural radiance fields. It solves the problem of balancing high-fidelity 3D reconstruction with computational efficiency and model size, which are critical for dynamic scenes. It sets itself apart from pure MLPs by avoiding convergence difficulties and from multi-scale voxel grids by achieving significantly smaller memory footprints while maintaining comparable or superior rendering quality. It builds on the TriPlane NeRF representation by adding a specific multi-scale feature aggregation strategy and a two-MLP decoding architecture (Sigma and Color).

### [Tri-Plane NeuS](17499-tri-plane-neus.md)
Tri-Plane NeuS is a neural surface reconstruction method that combines the TriPlane NeRF representation with the NeuS implicit surface formulation. It models the Signed Distance Function (SDF) using tri-plane features and an MLP, solving the problem of high-fidelity 3D surface recovery from multi-view images. It differs from its parent [TriPlane NeRF](6932-triplane-nerf.md) by optimizing for an SDF rather than volume density, and from [NeuS](link-to-neus) by using explicit tri-plane features instead of a purely implicit MLP for spatial encoding.

### [TK-Planes](20850-tk-planes.md)
TK-Planes is a neural rendering architecture for dynamic scenes that extends K-Planes by storing tiered abstract feature vectors in explicit grids rather than direct RGB or density values. It solves the fidelity issue of high-interest dynamic objects (e.g., people) across varying poses and time-slices by decoupling volumetric feature accumulation from image synthesis. Unlike its siblings which typically output RGB directly or use complex proposal sampling, TK-Planes outputs low-resolution feature maps that are decoded into final RGB images via a multi-stage convolutional neural network, allowing for significant reductions in ray casting and sampling requirements while improving training and inference speed.

### HexPlane-Swap
HexPlane-Swap is a variant that groups planes with repeated axes like $P_{XY}, P_{XT}$ [S8]. It achieves inferior results because its axes are not complementary, losing features from the particular axis [S8]. On the D-NeRF dataset, HexPlane-Swap achieves PSNR 28.562, SSIM 0.954, LPIPS 0.056, and Training Time 11m 44s [S8].

### HexPlane-SH
HexPlane-SH is a pure explicit model without MLPs on the D-NeRF dataset [S8]. It stores spherical harmonics (SH) as appearance features and directly regresses RGB from it rather than using MLPs [S8]. On the D-NeRF dataset, HexPlane-SH achieves PSNR 29.284, SSIM 0.952, LPIPS 0.056, and Training Time 10m 42s [S8].

### Deep Residual Local Features
Deep Residual Local Features use local features $f_r$ as a residual connection into the rendering MLP [S9]. These features are obtained by projecting the world point $x$ into source views using camera parameters $\gamma_i, K_i$ and extracting features via bilinear interpolation [S9]. Using only local features leads to ineffective performance for occlusions and faraway 360° views, while using only global features leads to hallucinations; the method combines both to mitigate these issues [S9].

### SDF-based 3D GAN with Spatially-Varying Surface Tightness
This method uses an implicit surface representation based on VolSDF, leveraging a spatially-varying parameter similar to Adaptive Shells to control the softness of the surface [S10]. The network uses a StyleGAN-like architecture to map from a Gaussian prior noise vector $z$ (dimension $R^{512}$) to a triplane representation $T$ [S10]. The triplane $T$ is conditioned by $w = \text{Mapping}(z)$ and has dimensions $T(w) \in R^{3 \times 32 \times 512 \times 512}$, corresponding to three axis-aligned 2D feature grids ($f_{xy}, f_{xz}, f_{yz}$) [S10]. Previous radiance field representations lack a concrete definition for surface geometry, resulting in bumpy surfaces; SDFs resolve this by providing an implicit surface definition [S10]. Unlike StyleSDF which lacks spatial-variance and leads to over-smoothed geometry, this method uses spatially-varying surface tightness to handle both hard boundaries (skin, eyes) and soft volumetric representations (hair) [S10].

### Triplane renderer
The Triplane renderer renders a triplane representation into images using explicit volumetric rendering [S11]. It samples points along the ray, queries a 2-layer fully-connected neural network to output color and density at each sample point, computes 32-dimensional sum-pooled interpolations of triplane features at the sample location, and concatenates or combines the sum-pooled features with a positional embedding of the 3D sample position [S11]. Ground plane geometry extending beyond the triplane boundaries is handled by the positional embedding, allowing the network to output a single constant feature for out-of-bounds regions [S11]. It differs from EG3D by using explicit volumetric ray sampling and a 2-layer FC network instead of EG3D's rendering approach [S11].

## Operating characteristics
*   **Time Complexity:** Querying scales as $O(1)$ per plane, making it efficient for rendering [G].
*   **Memory Complexity:** Memory usage scales as $O(N^2)$ per plane, which is significantly lower than the $O(N^3)$ of dense voxel grids [S1].
*   **Measured Performance:** TriPlane NeRF (referred to as MultiPlaneNeRF in [S1]) shows competitive performance; for example, on the Chair scene it achieves PSNR 32.81 and SSIM 0.972, outperforming SRN and NV, and comparable to NeRF and NSFV [S1].
*   **Strengths:** Efficient scaling to higher resolutions compared to voxels; small decoder size; compatibility with GANs and diffusion models [S1].
*   **Limitations:** Static representation unless extended with temporal planes; potential for hallucinations if global features are used without local context [S9]; bumpy surfaces if not combined with SDFs [S10].

## Background
TriPlane NeRF was introduced as a solution to the scaling problems of voxel representations in neural radiance fields [S1]. It aligns explicit features along three axis-aligned orthogonal feature planes, enabling efficient querying of 3D points by projecting them onto these planes and aggregating features [S1][S3]. The method allows for gradient-based optimization of the planes or their generation by CNNs like StyleGAN or diffusion models [S1]. It is a specific case of planar factorization, related to [K-planes](3317-k-planes.md), but restricted to the three primary coordinate planes for static scene representation [S1][S3].
