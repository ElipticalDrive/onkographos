# TriPlane NeRF

Also called: TriPlane(x, Triplane Feature Sampling

## Overview
TriPlane NeRF is a hybrid 3D representation that aligns explicit features along three axis-aligned orthogonal feature planes to solve the scaling problems of voxel-based representations while maintaining efficiency and expressiveness [S1]. It differs from its parent [K-planes](3317-k-planes.md) by restricting the factorization to the three primary spatial coordinate planes ($XY, XZ, YZ$) rather than all $d$-choose-2 pairs, and from [Voxel NeRF](52-name.md) by using explicit feature planes instead of a dense 3D grid, which allows the decoder to remain small and enables the planes to be optimized via gradients or generated by CNNs [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D position $x \in \mathbb{R}^3$ and a viewing direction $d$ [S1].
*   **Output:** A tuple $(c, \sigma)$ representing color and density, computed by a decoder network [S1].

**Data Structures:**
The representation consists of three feature planes $P = (P_{xy}, P_{xz}, P_{yz})$ [S1].
*   **Layout:** Each plane $P_{ij}$ is a 2D grid with resolution $N \times N$ and $C$ channels [S1].
*   **Initialization:** Random [S2].
*   **Optimization:** Optimized during reconstruction [S2].

**Algorithm:**
1.  **Projection:** Project the 3D position $x = (x, y, z)$ orthogonally onto each of the three feature planes to obtain 2D coordinates [S2].
    *   For $P_{xy}$, use coordinates $(x, y)$ [S2].
    *   For $P_{xz}$, use coordinates $(x, z)$ [S2].
    *   For $P_{yz}$, use coordinates $(y, z)$ [S2].
2.  **Interpolation:** Identify the four nearest grid points on each plane and apply bilinear interpolation to compute the feature vectors $F_{xy}$, $F_{xz}$, and $F_{yz}$ [S2].
3.  **Aggregation:** Aggregate the three feature vectors via summation to form the combined feature vector $F_{agg}$ [S1]:
    $$ F_{agg} = F_{xy} + F_{xz} + F_{yz} $$
4.  **Decoding:** Pass the aggregated feature $F_{agg}$ and the viewing direction $d$ into a lightweight decoder network (implemented as a small MLP) with parameters $\Theta$ to predict color $c$ and density $\sigma$ [S1].

**Formula:**
The final output is defined as [S1]:
$$ F_{TriPlaneNeRF}(x, d; \Theta, P) = (c, \sigma) $$
Where:
*   $x$ is the 3D position.
*   $d$ is the viewing direction.
*   $\Theta$ are the decoder parameters.
*   $P$ are the feature planes.

**Parameters:**
*   $N$: Spatial resolution of each plane. Not given in the sources.
*   $C$: Number of channels per plane. Not given in the sources.
*   *Note:* Specific implementations use fixed resolutions such as $512 \times 512$ with $8$ channels per plane [S2].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Bilinear interpolation requires handling coordinates outside the $[0, N-1]$ range [G].
*   **Degenerate Input:** If $x$ lies on an axis where two coordinates are identical (e.g., $x=y$), the projections remain valid, but the feature contribution from the corresponding plane may be redundant [G].
*   **Memory Complexity:** $O(N^2 C)$, where $N$ is the spatial resolution and $C$ is the channel count [G].

**Pseudocode:**
```python
def TriPlaneNeRF_Query(x, P, N, C):
    # x: (3,) float32, P: list of 3 planes, each (N, N, C)
    # Project x onto each plane
    coords_xy = (x[0], x[1])
    coords_xz = (x[0], x[2])
    coords_yz = (x[1], x[2])

    # Bilinear interpolation for each plane
    F_xy = BilinearInterpolate(P[0], coords_xy, N)
    F_xz = BilinearInterpolate(P[1], coords_xz, N)
    F_yz = BilinearInterpolate(P[2], coords_yz, N)

    # Aggregate via summation
    F_agg = F_xy + F_xz + F_yz
    return F_agg

def BilinearInterpolate(plane, coords, N):
    # coords: (u, v) in [0, N-1]
    u, v = coords
    # Clamp to valid range [0, N-1]
    u = max(0.0, min(float(N - 1), u))
    v = max(0.0, min(float(N - 1), v))
    # Grid indices
    u0, v0 = int(u), int(v)
    u1, v1 = u0 + 1, v0 + 1
    # Fractional parts
    du, dv = u - u0, v - v0
    # Fetch corners
    q00 = plane[u0, v0, :]
    q10 = plane[u1, v0, :]
    q01 = plane[u0, v1, :]
    q11 = plane[u1, v1, :]
    # Interpolate
    top = q00 * (1 - du) + q10 * du
    bottom = q01 * (1 - du) + q11 * du
    return top * (1 - dv) + bottom * dv
```

## Subtopics

### HexPlane-Swap
HexPlane-Swap is a variant that groups planes with repeated axes, such as $P_{XY}$ and $P_{XT}$ [S3]. It achieves inferior results because its axes are not complementary, causing the loss of features from the particular axis [S3]. On the D-NeRF dataset, it achieves PSNR 28.562, SSIM 0.954, LPIPS 0.056, and Training Time 11m 44s [S3].

### HexPlane-SH
HexPlane-SH is a pure explicit model without MLPs, designed for the D-NeRF dataset [S3]. It stores spherical harmonics (SH) as appearance features and directly regresses RGB from them rather than using an MLP decoder [S3]. On the D-NeRF dataset, it achieves PSNR 29.284, SSIM 0.952, LPIPS 0.056, and Training Time 10m 42s [S3].

## Operating characteristics
*   **Memory Complexity:** $O(N^2 C)$, where $N$ is the spatial resolution and $C$ is the channel count [G].
*   **Strengths:** Keeps the decoder small and uses explicit feature representation, allowing planes to be calculated with gradient-based optimization or produced by CNNs like StyleGAN or diffusion models [S1]. Solves the scaling problems of voxel representations while maintaining efficiency and expressiveness [S1].
*   **Limitations:** Restricted to three axis-aligned planes, which may lack the symmetry and completeness of methods using all coordinate pairs (like HexPlane) or spherical distributions (like MultiPlaneGAN) [S1, S2].
*   **Performance:** In comparisons on the D-NeRF dataset, variants derived from this concept (like HexPlane) show high efficiency, but specific metrics for the base TriPlane NeRF are not provided in the sources [S1, S2].

## Background
TriPlane NeRF was introduced as a solution to the scaling problems of voxel representations in neural radiance fields [S1]. It leverages the TriPlane representation, which aligns explicit features along three axis-aligned orthogonal planes [S1]. The method retains the vanilla NeRF cost function and rendering procedure [S1]. It is closely related to MultiPlaneNeRF, which uses a similar non-trainable representation structure [S1].
