# TK-Planes

Also called: Tiered K-Planes

## Overview
TK-Planes is a neural rendering architecture for dynamic scenes that extends K-Planes by storing tiered abstract feature vectors in explicit grids rather than direct RGB or density values [S1]. It solves the fidelity issue of high-interest dynamic objects (e.g., people) across varying poses and time-slices by decoupling volumetric feature accumulation from image synthesis [S1]. Unlike its siblings which typically output RGB directly or use complex proposal sampling, TK-Planes outputs low-resolution feature maps that are decoded into final RGB images via a multi-stage convolutional neural network, allowing for significant reductions in ray casting and sampling requirements while improving training and inference speed [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of camera poses (estimated via pix-sfm [S1]).
*   Input images (e.g., from UAV datasets like Okutama-Action or UG2) [S1].
*   Hyperparameters: Feature vector dimension $D$, number of tiers $n$ (typically 1 or 2) [S1].

**Outputs:**
*   Final rendered RGB images [S1].
*   Intermediate feature maps at each tier scale [S1].

### Data Structures

**1. Tiered Feature Grids**
The representation consists of $n$ tiers of feature grids. Each tier contains 9 grids total:
*   3 Static Spatial grids (axis-aligned planes) [S1].
*   3 Dynamic Spatial grids (axis-aligned planes) [S1].
*   3 Dynamic Spatio-Temporal grids (axis-aligned planes) [S1].

Each grid stores feature vectors of dimension $D$. The grids are initialized similarly to Extended K-Planes [S1].

**2. Image Decoder**
A multi-stage convolutional neural network. Each stage (except the final one) consists of:
*   **Skip Connection (`up1x1`)**: Bilinear upsampling (doubling spatial dimensions) followed by a $1 \times 1$ convolution (halving channel dimensions) [S1].
*   **Processed Input (`up5x5`)**: Bilinear upsampling (doubling spatial dimensions) followed by a $5 \times 5$ convolution (reducing channel dimensions to half of the *original* input channel dimension to the stage) [S1].
*   **Processing Block**: Two convolutional layers [S1].

The **Final Stage** consists of $x$ $3 \times 3$ convolutional layers, followed by a final convolutional layer reducing channels to 3, and a Sigmoid activation [S1].

### Numbered Steps

1.  **Grid Initialization**: Initialize $n$ tiers of feature grids. Each tier has 9 grids: $C_s$ (3 static spatial), $C_d$ (3 dynamic spatial), and $C_{dt}$ (3 dynamic spatio-temporal). Each grid contains learnable feature vectors of dimension $D$ [S1].
2.  **Ray Casting**: For each pixel in the target image, cast a ray through the scene. Use uniform sampling (not proposal sampling) to select sample points $q$ along the ray [S1].
3.  **Feature Query**: For each sample point $q$:
    *   Compute static feature vector $f_s(q)$ by projecting $q$ onto the 3 static spatial planes in $C_s$ and taking the Hadamard product of the retrieved features [S1].
    *   Compute dynamic feature vector $f_d(q)$ by projecting $q$ onto the 3 dynamic spatial and 3 dynamic spatio-temporal planes in $C_d$ and taking the Hadamard product [S1].
    *   Concatenate $f_s(q)$ and $f_d(q)$ along the batch dimension to form $f(q) = f_s(q) \oplus f_d(q)$ [S1].
4.  **MLP Processing**: Pass $f(q)$ through MLP networks to output a density value $\sigma$ and a refined feature vector $f_{out}(q)$ [S1].
5.  **Volumetric Rendering**: Accumulate the feature vectors along the ray using standard volumetric rendering to produce a final feature map $F_{tier}$ for the current tier scale $d_s$. The feature map dimensions are significantly smaller than the final image (e.g., $45 \times 80$ for a $720 \times 1280$ image, a reduction factor of 256) [S1].
6.  **Decoder Processing**:
    *   Input the feature map $F_{tier}$ into the corresponding stage of the Image Decoder [S1].
    *   Process static and dynamic feature maps independently through the same decoder layers to maintain robustness and avoid complexity [S1].
    *   If multiple tiers are used, feed the feature map from the current tier into the appropriate stage of the decoder, while passing the output from the previous stage as the other input [S1].
7.  **Final Synthesis**: In the final decoder stage, concatenate the processed static and dynamic feature maps along the channel dimension. Pass through $x$ $3 \times 3$ convolutions, a final $3 \times 3$ convolution to 3 channels, and a Sigmoid activation to produce the final RGB image [S1].
8.  **Training**:
    *   Process rays in patches (or entire images if using 1-2 tiers) [S1].
    *   Optimize grid features and decoder weights with a learning rate of $1e-3$ for 100,000 iterations on an NVIDIA RTX 3090 [S1].
    *   For dynamic PSNR calculation, use ground truth bounding boxes for dynamic regions (e.g., people) or generate them using YOLOv8 if not available [S1].

### Formulas

**Static Feature Vector:**
$$ f_s(q) = \prod_{c \in C_s} f_s(q)_c $$
Where $C_s$ is the set of 3 static spatial planes, $q$ is the query point, and $\prod$ denotes the Hadamard product [S1].

**Dynamic Feature Vector:**
$$ f_d(q) = \prod_{c \in C_d} f_d(q)_c $$
Where $C_d$ is the set of 3 dynamic spatial and 3 dynamic spatio-temporal planes, and $\prod$ denotes the Hadamard product [S1].

**Combined Feature Vector:**
$$ f(q) = f_s(q) \oplus f_d(q) $$
Where $\oplus$ denotes concatenation in the batch dimension [S1].

### Parameters

*   **Feature Vector Dimension ($D$)**: Hyperparameter defining the size of each feature vector $f_*(q)_c$ [S1].
*   **Number of Tiers ($n$)**: Typically 1 or 2 to balance speed, accuracy, and memory [S1].
*   **Feature Map Resolution**: Can be much smaller than final image resolution. Example: $45 \times 80$ for $720 \times 1280$ input (reduction factor 256) [S1].
*   **Learning Rate**: $1e-3$ for both feature grids and image decoder [S1].
*   **Training Iterations**: 100,000 [S1].
*   **Hardware**: NVIDIA RTX 3090 GPU [S1].
*   **Camera Pose Estimation**: Uses pix-sfm with SuperPoint features, SuperGlue matcher, and hloc tool [S1].

### Edge Cases and Pitfalls

*   **Dynamic Region Bounding**: Calculating dynamic PSNR requires bounding boxes for dynamic objects. If ground truth is unavailable (e.g., UG2 dataset), YOLOv8 must be used to extract them [S1].
*   **Sampling Method**: TK-Planes uses uniform sampling, which is simpler than the proposal sampling used in K-Planes but may require careful tuning of sample points to avoid aliasing in low-resolution feature maps [S1].
*   **Patch vs. Full Image**: Rays must be processed in patches during training to accommodate the image decoder's spatial constraints, though 1-2 tiers allow full-image processing in one pass [S1].

## Operating characteristics

**Time and Memory Complexity:**
*   **Speed**: TK-Planes with two tiers runs 10x faster than previous K-Planes versions. A one-tier version runs 25x faster [S1].
*   **Bottleneck**: Ray casting and sampling remain a bottleneck, but the number of rays and points sampled is significantly reduced due to the low-resolution feature map output [S1].
*   **Memory**: Uses explicit grids, which consume memory proportional to the grid resolution and feature dimension $D$. The use of tiered grids (up to 2 tiers) balances memory usage with accuracy [S1].

**Measured Performance:**
*   **Hardware**: NVIDIA RTX 3090 GPU [S1].
*   **Training**: 100,000 iterations, learning rate $1e-3$ [S1].
*   **Accuracy (Okutama)**: Up to 1.8 PSNR improvement over stock/extended K-Planes. Up to 4.1 DPSNR improvement. 0.93 PSNR improvement over 4D Gaussians. 3.61 DPSNR improvement over 4D Gaussians [S1].
*   **Accuracy (UG2)**: Up to 3.96 PSNR improvement over stock/extended K-Planes. Up to 3.51 DPSNR improvement. 1.05 PSNR improvement over 4D Gaussians. 4.58 DPSNR improvement over 4D Gaussians [S1].

**Strengths and Limitations:**
*   **Strengths**: High fidelity for dynamic objects (people) in UAV scenes. Faster training and inference compared to implicit NeRFs. Reduced ray casting requirements.
*   **Limitations**: Relies on uniform sampling, which may be less efficient than proposal sampling. Requires bounding boxes for dynamic PSNR evaluation (can be generated with YOLOv8 if not available). Performance is tied to the quality of camera pose estimation (pix-sfm) [S1].

**When to Use:**
*   Dynamic scene rendering, particularly for UAV or aerial videos with small moving objects.
*   Applications requiring high fidelity of dynamic objects for downstream tasks like object detection or pose recognition [S1].

**When Not to Use:**
*   Static scenes where simpler methods like TriPlane NeRF may suffice.
*   Scenes where proposal sampling is critical for high-frequency detail without the overhead of tiered grids [S1].

## Background

TK-Planes was introduced in 2025 by researchers extending the K-Planes architecture to handle dynamic UAV-based scenes [S1]. It builds on the explicit factored representations of K-Planes [9] and Extended K-Planes [21], which use axis-aligned planes to store features. The method was developed to address the domain gap between synthetic and real-world data for UAV perception, specifically targeting high-altitude videos with dynamic human actions [S1]. It was evaluated on the Okutama-Action and UG2 datasets [S1].
