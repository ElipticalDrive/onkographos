# K-planes

Also called: Explicit Radiance Fields in Space, Time, and Appearance, hex-planes, k-planes factorization, tri-planes

## Overview
K-planes is a white-box, interpretable radiance field representation that factorizes a $d$-dimensional scene into $k = \binom{d}{2}$ orthogonal 2D feature planes [S2]. It solves the scalability and memory bottlenecks of implicit neural representations and high-dimensional voxel grids by using planar factorization to represent spatial and temporal interactions compactly [S2]. Unlike sibling methods such as [Forplane](5177-forplane.md) or [Feature Grid as Radiance Field](5508-feature-grid-as-radiance-field.md) which often rely on additive feature combination or complex hashing, K-planes uniquely employs element-wise multiplication (Hadamard product) of plane features to enforce spatial localization, enabling the use of a linear decoder for view-dependent color while maintaining competitive reconstruction quality [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A query point $\mathbf{q} \in \mathbb{R}^d$ representing spatial coordinates, viewing direction, or time [S2].
*   **Output:** A signal vector containing density $\sigma$ and color $\mathbf{c}$ [G].

**Data Structures:**
The core data structure is a set of $k$ 2D feature planes $\mathbf{P} = \{\mathbf{P}_c\}_{c \in C}$ [S2].
*   **Plane Layout:** Each plane $\mathbf{P}_c$ is a 2D grid of shape $N \times N \times M$ [S2].
    *   $N$: Symmetric spatial (and temporal, for space-time planes) resolution.
    *   $M$: Feature dimension size, capturing density and view-dependent color information.
*   **Plane Selection:** For a scene of dimensionality $d$, the number of planes is $k = \binom{d}{2}$ [S2].
    *   For $d=3$ (static 3D), $k=3$ (tri-planes: $xy, xz, yz$) [S2].
    *   For $d=4$ (dynamic 4D), $k=6$ (hex-planes: $xy, xz, yz, xt, yt, zt$) [S2].
*   **Multiscale Support:** The representation supports multiple scales $S$ [S2].

**Parameters:**
*   $d$: Dimensionality of the scene space. Typical values: $d=3$ for static, $d=4$ for dynamic [S2].
*   $N$: Resolution of the planes.
*   $M$: Feature vector size.
*   $S$: Number of scales.

**Algorithm Steps:**

1.  **Coordinate Normalization and Projection:**
    Normalize the query point $\mathbf{q}$ entries to the range $[0, N)$ [S2]. For each plane $c \in C$, project $\mathbf{q}$ onto the 2D axes defining that plane to obtain 2D coordinates $\pi_c(\mathbf{q})$ [S2].
    *   For static 3D ($d=3$), $\mathbf{q}=(x,y,z)$ [S2]. Projections are $(x,y)$ for $P_{xy}$, $(x,z)$ for $P_{xz}$, and $(y,z)$ for $P_{yz}$ [S2].
    *   For dynamic 4D ($d=4$), $\mathbf{q}=(x,y,z,t)$ [S2]. Projections include space-space pairs and space-time pairs (e.g., $(x,t)$ for $P_{xt}$) [S2].

2.  **Multiscale Feature Retrieval:**
    For each scale $s$ and each plane $c$, perform bilinear interpolation $\psi$ on the plane grid $\mathbf{P}_c^{(s)}$ at the projected coordinates:
    $$ \mathbf{f}(\mathbf{q})_{c,s} = \psi(\mathbf{P}_c^{(s)}, \pi_c(\mathbf{q})) $$
    where $\psi$ denotes bilinear interpolation of a point into a regularly spaced 2D grid [S2].

3.  **Feature Fusion (Hadamard Product):**
    Combine the features from all $k$ planes for a specific scale $s$ using element-wise multiplication (Hadamard product) [S2]. This produces a localized feature vector $\mathbf{f}(\mathbf{q})_s$ of length $M$:
    $$ \mathbf{f}(\mathbf{q})_s = \prod_{c \in C} \mathbf{f}(\mathbf{q})_{c,s} $$
    The product ensures the feature is non-zero only if the point lies within active regions of all constituent planes, providing spatial localization [S2].

4.  **Scale Concatenation:**
    Concatenate the feature vectors from all $S$ scales to form the final input feature vector $\mathbf{f}(\mathbf{q})$ for the decoder:
    $$ \mathbf{f}(\mathbf{q}) = [\mathbf{f}(\mathbf{q})_1; \mathbf{f}(\mathbf{q})_2; \dots; \mathbf{f}(\mathbf{q})_S] $$
    The resulting vector has length $M \times S$ [S2].

5.  **Decoding:**
    Decode $\mathbf{f}(\mathbf{q})$ into density $\sigma$ and color $\mathbf{c}$ using one of two methods (see Subtopics):
    *   **Linear Decoder:** $\sigma(\mathbf{q}) = \mathbf{f}(\mathbf{q}) \cdot \mathbf{b}_\sigma$ and $\mathbf{c}(\mathbf{q}, \mathbf{d}) = \mathbf{f}(\mathbf{q}) \cdot \mathbf{B}_{RGB}(\mathbf{d})$, where $\mathbf{b}_\sigma$ is a learned basis vector and $\mathbf{B}_{RGB}$ is a learned color basis dependent on view direction $\mathbf{d}$ [S2].
    *   **MLP Decoder:** Use small MLPs $g_\sigma$ and $g_{RGB}$ to map features to density and color [S2].

6.  **Output Normalization:**
    Apply exponential to density $\sigma$ and sigmoid to color $\mathbf{c}$ to constrain values to valid ranges $(0, \infty)$ and $[0, 1]$ respectively [S2].

7.  **Volume Rendering:**
    Render the ray color and density using the standard volumetric rendering formula [S2].

**Pseudocode:**

```python
import numpy as np

def kplanes_forward(q, planes, view_dir, b_sigma, B_rgb, mlp_sigma, mlp_rgb, embed_view, decoder_type='linear'):
    """
    Forward pass for K-planes representation.
    
    Args:
        q: Query point, shape (d,) or (batch_size, d). Coordinates normalized to [0, N).
        planes: List of 2D arrays. planes[s] is the feature grid for scale s.
                Shape of each grid: (N_s, N_s, M).
        view_dir: Viewing direction, shape (3,) or (batch_size, 3).
        b_sigma: Learned basis vector for density, shape (M_total,).
        B_rgb: Learned color basis for view-dependent color, shape (M_total, 3).
        mlp_sigma: MLP for density and intermediate features.
        mlp_rgb: MLP for color prediction.
        embed_view: Function to embed view direction.
        decoder_type: 'linear' or 'mlp'.
        
    Returns:
        sigma: Density, shape (batch_size,) or ().
        color: RGB color, shape (3,) or (batch_size, 3).
    """
    # 1. Determine dimensions
    d = q.shape[-1]
    k = d * (d - 1) // 2  # Number of planes
    scales = len(planes)
    
    # 2. Define plane axes for dimension d
    plane_axes = []
    for i in range(d):
        for j in range(i + 1, d):
            plane_axes.append((i, j))
            
    # 3. Retrieve and multiply features across scales
    all_scale_features = []
    
    for s in range(scales):
        # Initialize combined feature vector for this scale with multiplicative identity
        combined_features = np.ones(planes[s].shape[-1])
        
        for c in range(k):
            axis_i, axis_j = plane_axes[c]
            # Project q onto the c-th plane
            coords = np.array([q[axis_i], q[axis_j]])
            
            # Bilinear interpolation
            feat = interp2d(planes[s], coords)
            
            # Element-wise multiplication
            combined_features = combined_features * feat
            
        all_scale_features.append(combined_features)
        
    # 4. Concatenate features from all scales
    final_features = np.concatenate(all_scale_features, axis=-1)
    
    # 5. Decode
    if decoder_type == 'linear':
        sigma = np.dot(final_features, b_sigma)
        color = np.dot(final_features, B_rgb)
    elif decoder_type == 'mlp':
        intermediate = mlp_sigma(final_features)
        view_embed = embed_view(view_dir)
        color = mlp_rgb(np.concatenate([intermediate, view_embed], axis=-1))
        
    # 6. Normalize
    sigma = np.exp(sigma)
    color = 1.0 / (1.0 + np.exp(-color)) # Sigmoid
    
    return sigma, color

def interp2d(grid, coords):
    """
    Bilinear interpolation of a 2D grid at given coordinates.
    grid: (N, N, M)
    coords: (2,) float, [x, y] in [0, N-1]
    Returns: (M,)
    """
    x, y = coords
    x0, y0 = np.floor(x).astype(int), np.floor(y).astype(int)
    x1, y1 = x0 + 1, y0 + 1
    
    # Handle boundaries
    x0 = np.clip(x0, 0, grid.shape[0] - 1)
    y0 = np.clip(y0, 0, grid.shape[1] - 1)
    x1 = np.clip(x1, 0, grid.shape[0] - 1)
    y1 = np.clip(y1, 0, grid.shape[1] - 1)
    
    # Interpolation weights
    wx = x - x0
    wy = y - y0
    
    # Get corner values
    v00 = grid[x0, y0, :]
    v10 = grid[x1, y0, :]
    v01 = grid[x0, y1, :]
    v11 = grid[x1, y1, :]
    
    # Bilinear interpolation
    top = v00 * (1 - wx) + v10 * wx
    bottom = v01 * (1 - wx) + v11 * wx
    result = top * (1 - wy) + bottom * wy
    
    return result
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Coordinates must be normalized to $[0, N)$ before projection [S2]. Interpolation must handle boundary clamping to avoid out-of-bounds access [S2].
*   **Static/Dynamic Separation:** For 4D scenes, space-time planes ($xt, yt, zt$) should be initialized to 1 (multiplicative identity) and regularized with $\mathcal{L}_{sep}$ to ensure static regions remain at 1, allowing the space-only planes to model the static background [S2].
*   **Coordinate Systems:** For forward-facing scenes, use Normalized Device Coordinates (NDC) [S2]. For unbounded scenes, apply $\ell_\infty$ scene contraction [S2].

## Subtopics

### [TriPlane NeRF](6932-triplane-nerf.md)
TriPlane NeRF is an explicit-implicit scene representation that models a 3D scene using three axis-aligned orthogonal feature planes. It solves the scaling problems of voxel-based representations by maintaining efficiency and expressiveness while allowing for a small decoder network. Unlike Voxel NeRF, which requires large memory for high-resolution grids, TriPlane NeRF keeps the decoder small and uses explicit feature representation, enabling planes to be calculated with gradient-based optimization or produced by CNNs like StyleGAN or diffusion models. It builds on the planar factorization concept of [K-planes](3317-k-planes.md) by restricting the factorization to the three primary coordinate planes ($XY, XZ, YZ$) for static scenes.

### K-planes MLP Decoder
A hybrid model where k-planes features are decoded by small MLPs, similar to Instant-NGP and DVGO [S2]. Features are decoded by two small MLPs: $g_\sigma$ maps features $\mathbf{f}(\mathbf{q})$ into density $\sigma$ and additional features $\hat{\mathbf{f}}$; $g_{RGB}$ maps $\hat{\mathbf{f}}$ and embedded view direction $\gamma(\mathbf{d})$ into RGB color [S2]. Predicted density and color values are normalized via exponential and sigmoid, respectively [S2]. Formulas: $\sigma(\mathbf{q}, \hat{\mathbf{f}}(\mathbf{q})) = g_\sigma(\mathbf{f}(\mathbf{q}))$ and $\mathbf{c}(\mathbf{q}, \mathbf{d}) = g_{RGB}(\hat{\mathbf{f}}(\mathbf{q}), \gamma(\mathbf{d}))$ [S2].

### Appearance Code Augmentation
An extension to handle scenes with varying appearance (e.g., changing illumination) by adding a global appearance code per frame to disentangle global appearance from scene geometry [S2]. Augment the K-planes model (either the linear decoder or the MLP decoder) with a learned global appearance code for each frame [S2]. This code is passed as an additional input to the decoder (e.g., to the learned color basis or MLP color decoder) so that it can affect color but not geometry [S2].

### MK-Planes
An extension of K-Planes from $\mathbb{C}^2$ planes to $\mathbb{C}^{2+\alpha}$ planes, where $\alpha$ is the number of interactable objects in dynamic scenes [S5, unofficial]. By leveraging the fact that each instance occupies a distinct region, the model can be further compressed to $3 + 3\alpha$ planes (MK-Planes*) [S5, unofficial].

## Operating characteristics
*   **Memory Complexity:** Achieves approximately 1000x compression over a full 4D grid [S2]. A 4D volume represented by K-planes uses ~200 MB, whereas a direct representation at the same resolution requires >300 GB [S2].
*   **Time Complexity:** Trains orders of magnitude faster than prior implicit models and on par with concurrent hybrid models [S2]. Training time for dynamic scenes reduces from 1 week on 8 GPUs to 4 hours on 1 GPU [S2][S4, unofficial].
*   **Strengths:** White-box and interpretable; scales gracefully to arbitrary dimensions $d$; supports multiscale representations; linear decoder is possible due to Hadamard product localization; efficient compression [S2].
*   **Limitations:** Requires careful initialization of space-time planes for dynamic scenes; may need proposal sampling for efficient rendering in complex scenes [S2].
*   **When to use:** Static 3D volumes, 3D photo collections with varying appearances, and 4D dynamic videos [S2].
*   **When not to use:** Scenes requiring highly complex, non-local view-dependent effects that a linear decoder cannot capture (though MLP decoder mitigates this); extremely high-frequency details that require very large $N$ or $M$ [S2].

## Background
K-planes was introduced in January 2023 [S2]. It was developed to address the black-box nature of MLP-based radiance fields and the memory inefficiency of voxel-based methods [S2]. The method builds on the planar factorization concept, extending tri-plane representations to arbitrary dimensions by using $k = \binom{d}{2}$ planes [S2]. It distinguishes itself from prior additive methods by using element-wise multiplication, which enables spatial localization and the use of a linear decoder [S2]. The method has been used for static 3D volumes, 3D photo collections with varying appearances, and 4D dynamic videos [S2].
