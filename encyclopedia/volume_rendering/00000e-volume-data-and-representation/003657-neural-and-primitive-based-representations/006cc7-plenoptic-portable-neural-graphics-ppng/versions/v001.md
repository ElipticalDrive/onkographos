# Plenoptic Portable Neural Graphics (PPNG)

Also called: Fourier-indexed volume, Plenoptic PNG

## Overview
Plenoptic Portable Neural Graphics (PPNG) is a volumetric neural feature representation that maps 3D spatial coordinates to color and opacity using a sinusoidal function-encoded feature volume [S1]. It solves the problem of compact, real-time neural rendering by leveraging feature sharing in the Fourier domain, which reduces parameter count compared to spatial coordinate-indexed volumes [S1]. Unlike spatial hashing or dense voxel grids, PPNG uses low-resolution 3D textures indexed by positional encoding slices, allowing it to fit on low-cost GPUs with limited memory while maintaining competitive rendering quality [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D query point $\mathbf{p} = (x, y, z)$ and a viewing direction $\mathbf{d}$.
*   **Output:** Opacity $\sigma$ and color $\mathbf{c} \in \mathbb{R}^3$.

**Data Structures:**
1.  **Feature Volumes:** A set of $L \times 2$ 3D volume cubes $\{V_{\sin_i}, V_{\cos_i} \in \mathbb{R}^{Q^3 \times D}\}_{i=0}^{L-1}$.
    *   $Q$: Volume quantization size (resolution).
    *   $D$: Feature dimension per entry.
    *   Storage: Stored as 3D textures (e.g., RGBA format in GLSL where $D=4$).
2.  **MLP ($g_\theta$):** A shallow multi-layer perceptron.
    *   Input size: $F = 2 \times L \times D$.
    *   Structure: Single linear layer producing density (1 value) and a 15-length feature vector. These, combined with degree-3 spherical harmonics of $\mathbf{d}$ (length 16), feed a 2-layer MLP with a 16-hidden unit layer, outputting RGB color.
    *   Total parameters: 1,072 [S1].
3.  **Occupancy Grid (Optional for optimization):** A voxel-based density cache encoded with Run-Length Encoding (RLE) and stored as a single-channel 3D texture for empty-space skipping [S1].

**Parameters:**
*   $Q = 80$ (Typical resolution) [S1].
*   $L = 4$ (Number of frequency levels) [S1].
*   $D = 4$ (Feature dimension) [S1].
*   $F = 32$ (Feature vector length, calculated as $2 \times L \times D$) [S1].

**Algorithm Steps:**

1.  **Positional Encoding:**
    Apply positional encoding to the input point $\mathbf{p} = (x, y, z)$. For each axis $w \in \{x, y, z\}$ and frequency level $i \in \{0, \dots, L-1\}$, compute:
    $$ \gamma(w) = [(\sin(f_i \pi w), \cos(f_i \pi w))]_{i=0}^{L-1} \in \mathbb{R}^{L \times 2} $$
    where $f_i$ are frequency levels. Concatenate results for all axes:
    $$ \gamma(\mathbf{p}) = \text{concat}([\gamma(x), \gamma(y), \gamma(z)]) \in \mathbb{R}^{3 \times L \times 2} $$
    [S1]

2.  **Feature Volume Indexing:**
    For each frequency level $i$, extract the 3D slice of the positional encoding:
    $$ \gamma_{\sin_i} = [\sin(f_i \pi x), \sin(f_i \pi y), \sin(f_i \pi z)] $$
    $$ \gamma_{\cos_i} = [\cos(f_i \pi x), \cos(f_i \pi y), \cos(f_i \pi z)] $$
    [S1]

3.  **Tri-linear Interpolation:**
    Query the feature vectors $z_{\sin_i}$ and $z_{\cos_i}$ from the corresponding volumes $V_{\sin_i}$ and $V_{\cos_i}$ using tri-linear interpolation $\pi_{tri}$:
    $$ z_{\sin_i} = \pi_{tri}(\gamma_{\sin_i}, V_{\sin_i}) $$
    $$ z_{\cos_i} = \pi_{tri}(\gamma_{\cos_i}, V_{\cos_i}) $$
    [S1]

4.  **Feature Concatenation:**
    Concatenate features from all frequency levels to form the final feature vector $\mathbf{z}(\mathbf{p})$:
    $$ \mathbf{z}(\mathbf{p}) = \text{concat}[\dots, z_{\sin_i}, z_{\cos_i}, \dots]_{i=0}^{L-1} $$
    The length of $\mathbf{z}(\mathbf{p})$ is $F = 2 \times L \times D$ [S1].

5.  **MLP Regression:**
    Pass $\mathbf{z}(\mathbf{p})$ and viewing direction $\mathbf{d}$ into the MLP $g_\theta$ to regress opacity $\sigma$ and color $\mathbf{c}$:
    $$ (\mathbf{c}, \sigma) = g_\theta(\mathbf{z}(\mathbf{p}), \mathbf{d}) $$
    [S1]

**Pseudocode:**

```python
import numpy as np

def ppng_query(p: np.ndarray, d: np.ndarray, volumes: list, mlp: object) -> tuple:
    """
    Query PPNG representation for a single point.
    
    Args:
        p: 3D coordinate (x, y, z)
        d: Viewing direction vector
        volumes: List of L*2 3D arrays (Q^3 x D), ordered [V_sin_0, V_cos_0, ..., V_sin_L-1, V_cos_L-1]
        mlp: MLP object with forward pass accepting feature vector and direction
        
    Returns:
        (color, opacity)
    """
    L = 4  # Number of frequency levels
    D = 4  # Feature dimension
    Q = 80 # Volume resolution (used for interpolation bounds)
    
    # Frequencies f_i. The paper uses f_i in sin(f_i * pi * w).
    # Standard positional encoding usually implies f_i = 2^i or similar.
    # The paper cites [36, 49] for positional encoding. 
    # Assuming standard NeRF frequencies for implementation context [G].
    frequencies = np.array([2**i for i in range(L)])
    
    features = []
    
    for i in range(L):
        f_i = frequencies[i]
        
        # Step 1 & 2: Compute sinusoidal coordinates for this frequency
        # gamma_sin_i = [sin(f_i * pi * x), sin(f_i * pi * y), sin(f_i * pi * z)]
        # gamma_cos_i = [cos(f_i * pi * x), cos(f_i * pi * y), cos(f_i * pi * z)]
        
        x, y, z = p
        sin_coords = np.array([np.sin(f_i * np.pi * x), 
                               np.sin(f_i * np.pi * y), 
                               np.sin(f_i * np.pi * z)])
        cos_coords = np.array([np.cos(f_i * np.pi * x), 
                               np.cos(f_i * np.pi * y), 
                               np.cos(f_i * np.pi * z)])
        
        # Step 3: Tri-linear interpolation
        # Note: In a real implementation, pi_tri handles boundary conditions 
        # and interpolation weights. Here we assume a helper function exists 
        # or use standard trilinear interpolation logic.
        # Volumes are stored as [V_sin_0, V_cos_0, ...]
        v_sin_idx = i * 2
        v_cos_idx = i * 2 + 1
        
        z_sin_i = trilinear_interpolate(sin_coords, volumes[v_sin_idx], Q)
        z_cos_i = trilinear_interpolate(cos_coords, volumes[v_cos_idx], Q)
        
        features.append(z_sin_i)
        features.append(z_cos_i)
        
    # Step 4: Concatenate features
    # Shape: (F,) where F = 2 * L * D
    z_p = np.concatenate(features)
    
    # Step 5: MLP Regression
    # The MLP takes z(p) and d. 
    # Internal MLP structure:
    # 1. Linear layer on z_p -> density (1) + feature (15)
    # 2. SH of d (degree 3) -> length 16
    # 3. Concat feature + SH -> 2-layer MLP (hidden 16) -> RGB (3)
    
    color, opacity = mlp.forward(z_p, d)
    
    return color, opacity

def trilinear_interpolate(coords: np.ndarray, volume: np.ndarray, Q: int) -> np.ndarray:
    """
    Perform tri-linear interpolation on a 3D volume.
    coords: [x, y, z] in range [0, 1] or [0, Q-1] depending on implementation.
    Assuming coords are normalized [0, 1] for standard texture sampling.
    """
    # Scale to voxel indices
    # Note: Exact boundary handling (clamp, wrap, mirror) depends on GLSL settings.
    # GLSL 'linear' filtering usually implies clamping or wrapping.
    # We assume standard clamping to [0, Q-1] for this implementation [G].
    
    idx = coords * (Q - 1)
    
    # Get floor and ceil indices
    x0, y0, z0 = np.floor(idx).astype(int)
    x1, y1, z1 = np.ceil(idx).astype(int)
    
    # Clamp to volume bounds
    x0 = np.clip(x0, 0, Q - 1)
    y0 = np.clip(y0, 0, Q - 1)
    z0 = np.clip(z0, 0, Q - 1)
    x1 = np.clip(x1, 0, Q - 1)
    y1 = np.clip(y1, 0, Q - 1)
    z1 = np.clip(z1, 0, Q - 1)
    
    # Interpolation weights
    wx = idx[0] - x0
    wy = idx[1] - y0
    wz = idx[2] - z0
    
    # Get values at 8 corners
    # Volume shape: (Q, Q, Q, D)
    v000 = volume[x0, y0, z0]
    v100 = volume[x1, y0, z0]
    v010 = volume[x0, y1, z0]
    v110 = volume[x1, y1, z0]
    v001 = volume[x0, y0, z1]
    v101 = volume[x1, y0, z1]
    v011 = volume[x0, y1, z1]
    v111 = volume[x1, y1, z1]
    
    # Interpolate
    # Lerp along x
    v00 = v000 * (1 - wx) + v100 * wx
    v01 = v001 * (1 - wx) + v101 * wx
    v10 = v010 * (1 - wx) + v110 * wx
    v11 = v011 * (1 - wx) + v111 * wx
    
    # Lerp along y
    v0 = v00 * (1 - wy) + v10 * wy
    v1 = v01 * (1 - wy) + v11 * wy
    
    # Lerp along z
    result = v0 * (1 - wz) + v1 * wz
    
    return result
```

## Subtopics

### PPNG GLSL Renderer
A real-time, interactive, and portable viewing implementation using WebGL2 and GLSL to render PPNG representations on low-cost GPUs [S1]. It decodes binary PPNG files (types 1, 2, or 3) and converts PPNG-1/2 to PPNG-3 via parallelized GLSL code if necessary [S1]. It loads volumetric Fourier features as RGBA 3D textures with linear filtering for tri-linear interpolation, and an RLE-encoded voxel-based density cache as a single-channel 3D texture for empty-space skipping [S1]. The MLP is chunked into 4x4 matrices (Mat4) for faster inference [S1]. Rendering is performed in a fragment shader by casting rays, checking occupancy, and integrating color/opacity using the volume rendering equation, terminating when accumulated transmittance falls below a threshold [S1].

### PPNG-3 (Vanilla PPNG)
The vanilla representation storing dense 3D volumes for each frequency without factorization [S1]. It has a memory complexity of $Q^3 \times D$ per volume [S1]. With typical parameters ($Q=80, D=4, L=4$), the model size is 32.7MB using half-precision floating points, including the shallow MLP weights [S1].

### PPNG-1
A factorized version of PPNG inspired by CP-decomposition, decomposing 3D volumes into a set of triplets of 1D vectors $(v_{rx}, v_{rz}, v_{ry})$ [S1]. It uses $R=8$ factorized components [S1]. The model size is 125KB using half-precision floating points [S1].

### PPNG-2
A factorized version of PPNG using a different tensor decomposition scheme than PPNG-1 [S1]. It uses $R=2$ factorized components [S1]. The model size is 2.45MB using half-precision floating points [S1].

## Operating characteristics
*   **Memory Complexity:** For vanilla PPNG (PPNG-3), the memory complexity is $Q^3 \times D$ per volume [S1]. The total model size for PPNG-3 is 32.7MB (half-precision), PPNG-2 is 2.45MB, and PPNG-1 is 125KB [S1].
*   **Performance:** PPNG is 2-3 orders of magnitude smaller than baseline NeRF models in terms of model size and over 10x-100x faster in training speed [S1]. The GLSL renderer enables real-time rendering on low-cost GPUs and mobile devices [S1].
*   **Decoding Time:** Less than 20 ms for combined RLE and CBOR decodings [S1].
*   **Strengths:** Compactness, feature sharing in Fourier domain, real-time capability on limited hardware, portable binary format (CBOR) [S1].
*   **Limitations:** Requires factorization (PPNG-1/2) for extreme compactness; vanilla PPNG-3 is larger than factorized variants [S1].

## Background
Plenoptic Portable Neural Graphics (PPNG) was introduced in the paper "Plenoptic PNG: Real-Time Neural Radiance Fields in 150 KB" [S1]. It builds on the principles of neural fields and positional encoding [S1]. The method leverages the redundancy and multi-scale nature of Fourier features to allow significantly smaller volume resolutions ($Q=80$) compared to typical spatial volumes ($S=512$) [S1].
