# L2 Norm Sphere Contraction

Also called: L2 Contraction, Space Contraction, contract

## Overview
L2 Norm Sphere Contraction is a coordinate transformation method used in neural radiance fields to handle unbounded scenes by mapping infinite 3D space into a bounded sphere of radius 2 [S2, unofficial]. It solves the problem of representing distant background geometry in datasets like Mip-NeRF 360 by ensuring that points at infinity map to the sphere's surface [S1][S2, unofficial]. It differs from other contraction methods by using a specific L2-norm-based scaling factor that preserves angular direction while compressing radial distance non-linearly [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D coordinate vector $\mathbf{x} \in \mathbb{R}^3$.
- Output: A contracted 3D coordinate vector $\mathbf{x}' \in \mathbb{R}^3$ within the bounded sphere.

**Data Structures:**
- No persistent data structures are required. The transformation is stateless and computed per-point.

**Steps:**
1. Compute the L2 norm of the input vector: $r = \|\mathbf{x}\|_2 = \sqrt{x^2 + y^2 + z^2}$.
2. Handle the degenerate case where $\mathbf{x} = \mathbf{0}$. If $r = 0$, the output is $\mathbf{0}$ [G].
3. Compute the scaling factor $s$ based on the norm $r$:
   $$ s = 2 - \frac{1}{r} $$
   This formula ensures that as $r \to \infty$, $s \to 2$, mapping infinity to the sphere boundary [S2, unofficial].
4. Normalize the input vector to get the direction: $\hat{\mathbf{x}} = \frac{\mathbf{x}}{r}$.
5. Multiply the direction by the scaling factor to get the output:
   $$ \mathbf{x}' = s \cdot \hat{\mathbf{x}} = \left(2 - \frac{1}{r}\right) \frac{\mathbf{x}}{r} $$

**Formula:**
For $\|\mathbf{x}\| > 0$:
$$ \mathbf{x}' = \left(2 - \frac{1}{\|\mathbf{x}\|}\right) \frac{\mathbf{x}}{\|\mathbf{x}\|} $$

**Parameters:**
- The method implicitly assumes a bounding sphere of radius 2 [S2, unofficial].
- Scene normalization may precede this step. According to [S1], the scene of interest is modeled with a sphere whose diameter is the maximum distance between any two camera positions in the training log plus 50 meters. This normalization ensures the scene fits within the contraction domain.

**Edge Cases and Pitfalls:**
- **Zero Vector:** Division by zero occurs if $\mathbf{x} = \mathbf{0}$. The implementation must check for $r=0$ and return $\mathbf{0}$ [G].
- **Precision:** For very large $r$, $1/r$ becomes small, and the scaling factor approaches 2. Floating-point precision issues may arise if $r$ is extremely large, though typically coordinates are normalized beforehand.
- **Boundary:** Points exactly on the sphere boundary ($r=2$) map to themselves? Let's check: if $r=2$, $s = 2 - 0.5 = 1.5$. $\mathbf{x}' = 1.5 \frac{\mathbf{x}}{2} = 0.75 \mathbf{x}$. The norm becomes $0.75 \times 2 = 1.5$. The sphere of radius 2 is the *target* domain, but the mapping is not identity at $r=2$. The mapping is continuous and monotonic. The maximum output norm is 2 (as $r \to \infty$).

**Pseudocode:**
```python
import numpy as np

def l2_norm_sphere_contraction(x: np.ndarray) -> np.ndarray:
    """
    Contracts unbounded 3D space into a sphere of radius 2 using L2 norm.
    
    Args:
        x: Input 3D coordinate array of shape (..., 3).
        
    Returns:
        Contracted 3D coordinate array of the same shape.
    """
    # Compute L2 norm along the last axis
    norm = np.linalg.norm(x, axis=-1, keepdims=True)
    
    # Handle zero vector to avoid division by zero
    # [G] Guard against NaN propagation from 0/0
    safe_norm = np.where(norm == 0, 1.0, norm)
    
    # Compute scaling factor: 2 - 1/norm
    scale = 2.0 - (1.0 / safe_norm)
    
    # Normalize direction
    direction = x / safe_norm
    
    # Scale direction
    x_prime = scale * direction
    
    # Restore zero vector output
    x_prime = np.where(norm == 0, 0.0, x_prime)
    
    return x_prime
```

## Subtopics

### Contract Coordinates (Modified)
A variant that maps unbounded scenes into a $[-1, 1]$ cube rather than a sphere, introducing a scale parameter $a$ to control the foreground/background ratio [S3]. It converts X, Y, Z axes independently [S3]. The formula is:
$$ \operatorname{CC}(\mathbf{x}) = 0.5 \times \begin{cases} a \mathbf{x} & \|\mathbf{x}\| \leq 1 \\ \left((2-a)\left(1 - \frac{1}{\|\mathbf{x}\|}\right) + a\right) \frac{\mathbf{x}}{\|\mathbf{x}\|} & \|\mathbf{x}\| > 1 \end{cases} $$
where $a$ controls the foreground mapping range $[-a/2, a/2]$ [S3]. When $a=1$, it reduces to the standard contract coordinates [S3]. Typical value for $a$ is 1 [S3]. This variant is used in methods like Lightplane to better utilize explicit 3D hash grids by expanding foreground regions [S3].

## Operating characteristics
- **Time Complexity:** $O(1)$ per point, involving a few arithmetic operations and a square root.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Strengths:** Simple to implement; effectively bounds unbounded scenes for neural network training; preserves angular information [S2, unofficial].
- **Limitations:** The mapping is non-linear, which may distort local geometry near the origin compared to linear scaling [S2, unofficial]. The choice of bounding sphere radius (implicitly 2) requires proper scene normalization [S1].
- **When to use:** When training NeRF-like models on unbounded datasets (e.g., Mip-NeRF 360) where background geometry needs to be represented within a bounded domain [S1][S2, unofficial].
- **When not to use:** For bounded scenes where explicit bounding boxes are sufficient, or when preserving linear metric properties in the far field is critical without distortion.

## Background
The method originates from the need to handle unbounded backgrounds in the Mip-NeRF 360 dataset [S1]. It was introduced as a "scene contraction" strategy [S1][S2, unofficial]. The specific L2 norm formulation is detailed in [S2, unofficial] (unofficial implementation notes) and cited in [S1] as referencing prior work [5] (likely the original Mip-NeRF 360 paper or related contraction techniques). The variant with parameter $a$ was introduced in Lightplane [S3] to improve performance with hash-based encodings.
