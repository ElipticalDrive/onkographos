# Scene Parameterization Radius

Also called: S-NeRF radius parameterization, improved scene parameterization function

## Overview
Constrains large-scale unbounded street-view scenes into a bounded unit sphere volume to enable efficient voxel grid allocation and position encoding, avoiding the heavy range compression of close objects inherent in standard Normalized Device Coordinates (NDC) or basic contraction methods. It sets apart from its siblings by using a piecewise mapping function controlled by a radius parameter $r$ to preserve high-frequency details for nearby objects while mapping distant geometry, specifically tailored for ego-vehicle scenarios where camera motion complicates standard NDC assumptions.

## How it works
**Inputs and outputs:**
- Input: 3D point coordinates $\mathbf{x} \in \mathbb{R}^3$ in world space.
- Output: Parameterized coordinates $\mathbf{x}' \in \mathbb{R}^3$ mapped into a bounded range suitable for position encoding.

**Data structures:**
- The parameterization is a mathematical function applied per-vertex; no persistent data structure is required beyond the scalar radius parameter $r$.

**Parameters:**
- $r$: Scene parameterization radius. Determines the boundary between the linear and non-linear mapping regimes.
- Typical values: $3$ to $10$ meters. A value of $3$ is commonly used for background street scenes [S1, unofficial]. Street views typically span $>200$m, making this bounded range necessary [S1, unofficial].

**Steps:**
1. Compute the Euclidean norm of the input point: $d = \|\mathbf{x}\|$.
2. Apply the piecewise mapping function $f(\mathbf{x})$ based on $d$ relative to $r$:
   - If $d \le r$: Apply linear scaling.
   - If $d > r$: Apply non-linear contraction.
3. The mapping function is defined as [S1, unofficial]:
   $$
   f(\mathbf{x}) = 
   \begin{cases} 
   \frac{\mathbf{x}}{r}, & \text{if } \|\mathbf{x}\| \le r \\
   \left(2 - \frac{r}{\|\mathbf{x}\|}\right) \frac{\mathbf{x}}{\|\mathbf{x}\|}, & \text{otherwise}
   \end{cases}
   $$

**Pseudocode:**
```python
import math

def scene_parameterization_radius(x, r):
    """
    Maps 3D point x into a bounded range using radius r.
    
    Args:
        x: numpy array of shape (3,) representing the 3D point.
        r: float, the scene parameterization radius (e.g., 3.0).
        
    Returns:
        numpy array of shape (3,) representing the parameterized point.
    """
    norm_x = math.sqrt(x[0]**2 + x[1]**2 + x[2]**2)
    
    if norm_x <= r:
        # Linear scaling for close objects
        return x / r
    else:
        # Non-linear contraction for far objects
        # Formula: (2 - r / norm_x) * (x / norm_x)
        # This ensures continuity at norm_x == r
        scale = (2.0 - r / norm_x) / norm_x
        return x * scale
```

**Edge cases and pitfalls:**
- **Precision at boundary:** The function is continuous at $\|\mathbf{x}\| = r$. Ensure floating-point comparisons handle the boundary correctly to avoid jitter.
- **Zero vector:** If $\mathbf{x} = \mathbf{0}$, the norm is 0. The linear branch handles this (returns $\mathbf{0}$). The non-linear branch involves division by norm, so it must be guarded by the `if` condition.
- **Large coordinates:** For very large $\|\mathbf{x}\|$, the term $r/\|\mathbf{x}\|$ approaches 0, and the mapping approaches $2 \frac{\mathbf{x}}{\|\mathbf{x}\|}$, effectively projecting distant points to the surface of a sphere of radius 2. This bounds the scene.

## Subtopics

### Improved Scene Parameterization Function
An improvement over NDC and basic contraction (Barron et al., 2022) designed to constrain long-range street view sequences into a bounded range before position encoding. It avoids the heavy range compression of close objects that occurs in standard NDC, which fails in scenes with complicated ego-car motions and challenging camera settings. It provides more details for close object rendering by decoupling the near-field resolution from the far-field bound via the radius parameter $r$. It is chosen when rendering street views with significant depth variation and ego-motion, where standard NDC artifacts are prominent. It links to [Unbounded inward-facing scene parameterization](957-unbounded-inward-facing-scene-parameterization.md).

## Operating characteristics
- **Time complexity:** $O(1)$ per point for the parameterization function.
- **Memory complexity:** $O(1)$ auxiliary memory.
- **Measured performance:** In S-NeRF experiments on nuScenes and Waymo datasets (street views spanning $>200$m), using $r \in [3, 10]$ produced better rendering results than the original Mip-NeRF 360 setting which lacks this adjustable radius [S1, unofficial].
- **Strengths:** Preserves high-frequency details for nearby objects (controlled by $r$) while bounding the entire scene. Independent of far bounds.
- **Limitations:** Requires tuning of $r$. NDC fails in these specific ego-vehicle scenarios due to complex motion, making this parameterization necessary.
- **When to use:** Unbounded inward-facing street scenes with ego-motion.
- **When not to use:** Bounded indoor scenes or scenes where NDC is sufficient and stable.

## Background
Originated in S-NeRF (2023) for neural radiance fields in street views. It addresses the failure of Normalized Device Coordinates (NDC) in scenes with complicated ego-car motions and challenging camera settings. It improves upon the scene parameterization function used in Mip-NeRF 360 (Barron et al., 2022) by introducing the radius parameter $r$. It is used in conjunction with frustum sampling from Mip-NeRF (Barron et al., 2021), sampling along rays evenly in a log scale to get more points close to the near plane, further enhancing close-object detail.
