# Scene Parameterization Radius


## Overview
Constrains large-scale unbounded street-view scenes into a bounded range using a piecewise distance mapping function controlled by a radius parameter $r$ to preserve details for close objects [S1, unofficial]. It differs from standard Normalized Device Coordinates (NDC) by decoupling near-field resolution from far-field bounds, which is necessary for ego-vehicle scenarios with complex camera motion [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: 3D point coordinates $\mathbf{x} \in \mathbb{R}^3$ in world space [G].
- Output: Parameterized coordinates $\mathbf{x}' \in \mathbb{R}^3$ mapped into a bounded range suitable for position encoding [G].

**Data structures:**
- The parameterization is a per-vertex mathematical function requiring only the scalar radius parameter $r$ [G].

**Steps:**
1. Compute the Euclidean norm of the input point: $d = \|\mathbf{x}\|$ [G].
2. Evaluate the piecewise mapping function $f(\mathbf{x})$ by comparing $d$ to the radius parameter $r$ [S1, unofficial].
3. Return the transformed coordinates $\mathbf{x}' = f(\mathbf{x})$ [G].

**Formulas:**
The mapping function is defined as [S1, unofficial]:
$$
f(\mathbf{x}) = 
\begin{cases} 
\frac{\mathbf{x}}{r}, & \text{if } \|\mathbf{x}\| \le r \\
\left(2 - \frac{r}{\|\mathbf{x}\|}\right) \frac{\mathbf{x}}{\|\mathbf{x}\|}, & \text{otherwise}
\end{cases}
$$
The source text contains a transcription error in Equation (2) writing `(2 - r) x / kxk`; the mathematically continuous form at $\|\mathbf{x}\|=r$ requires the term $(2 - r/\|\mathbf{x}\|)$ [S1, unofficial][G].

**Parameters:**
- $r$: Scene parameterization radius defining the boundary between linear and non-linear mapping regimes [S1, unofficial].
- Typical values: $3$ to $10$ meters [S1, unofficial]. Street views typically span $>200$ meters, necessitating this bounded range [S1, unofficial].

**Edge cases and pitfalls:**
- **Precision at boundary:** The function is continuous at $\|\mathbf{x}\| = r$ [G]. Ensure floating-point comparisons handle the boundary correctly to avoid jitter [G].
- **Zero vector:** If $\mathbf{x} = \mathbf{0}$, the norm is $0$ and the linear branch returns $\mathbf{0}$ safely [G].
- **Large coordinates:** For very large $\|\mathbf{x}\|$, the term $r/\|\mathbf{x}\|$ approaches $0$, and the mapping approaches $2 \frac{\mathbf{x}}{\|\mathbf{x}\|}$, effectively projecting distant points to the surface of a sphere of radius $2$ [G].

**Pseudocode:**
```python
import math

def scene_parameterization_radius(x, r):
    """
    Maps 3D point x into a bounded range using radius r.
    
    Args:
        x: numpy array of shape (3,) representing the 3D point.
        r: float, the scene parameterization radius (e.g., 3.0).
        
    Returns:
        numpy array of shape (3,) representing the parameterized point.
    """
    norm_x = math.sqrt(x[0]**2 + x[1]**2 + x[2]**2)
    
    if norm_x <= r:
        return x / r
    else:
        scale = (2.0 - r / norm_x) / norm_x
        return x * scale
```

## Subtopics

### [Improved Scene Parameterization Function](15179-improved-scene-parameterization-function.md)
An improvement over NDC and basic contraction (Barron et al., 2022) designed to constrain long-range street view sequences into a bounded range before position encoding. It avoids the heavy range compression of close objects that occurs in standard NDC, which fails in scenes with complicated ego-car motions and challenging camera settings. It provides more details for close object rendering by decoupling the near-field resolution from the far-field bound via the radius parameter $r$. It is chosen when rendering street views with significant depth variation and ego-motion, where standard NDC artifacts are prominent. It links to [Unbounded inward-facing scene parameterization](957-unbounded-inward-facing-scene-parameterization.md).

## Operating characteristics
- **Time complexity:** $O(1)$ per point for the parameterization function [G].
- **Memory complexity:** $O(1)$ auxiliary memory [G].
- **Measured performance:** In S-NeRF experiments on nuScenes and Waymo datasets (street views spanning $>200$m), using $r \in [3, 10]$ produced better rendering results than the original Mip-NeRF 360 setting which lacks this adjustable radius [S1, unofficial].
- **Strengths:** Preserves high-frequency details for nearby objects (controlled by $r$) while bounding the entire scene [S1, unofficial]. Independent of far bounds [S1, unofficial].
- **Limitations:** Requires tuning of $r$ [S1, unofficial]. NDC fails in these specific ego-vehicle scenarios due to complex motion, making this parameterization necessary [S1, unofficial].
- **When to use:** Unbounded inward-facing street scenes with ego-motion [S1, unofficial].
- **When not to use:** Bounded indoor scenes or scenes where NDC is sufficient and stable [G].

## Background
Originated in S-NeRF (2023) for neural radiance fields in street views [S1, unofficial]. It addresses the failure of Normalized Device Coordinates (NDC) in scenes with complicated ego-car motions and challenging camera settings [S1, unofficial]. It improves upon the scene parameterization function used in Mip-NeRF 360 (Barron et al., 2022) by introducing the radius parameter $r$ [S1, unofficial]. It is used in conjunction with frustum sampling from Mip-NeRF (Barron et al., 2021), sampling along rays evenly in a log scale to get more points close to the near plane, further enhancing close-object detail [S1, unofficial].
