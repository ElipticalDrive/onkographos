# Output Activation & Time Encoding

Also called: Output Activation, Time Encoding

## Overview
This module applies dataset-specific output constraints to neural features and encodes temporal inputs for dynamic scene representation [S1, S2]. It maps latent feature vectors to valid RGB color ranges and handles time-varying scene appearance using either linear or sinusoidal time encoding [S1, S2].

## How it works
**Inputs:**
- Feature vector $\mathbf{f}$ from the preceding network [S1, S2].
- Time variable $t$, normalized to a specific range [S1, S2].

**Outputs:**
- RGB color vector $\mathbf{c} \in [0, 1]^3$ [S1].

**Data Structures:**
- No specific complex data structures are defined for this module itself; it operates on scalar or vector inputs [G].

**Steps:**
1. **Time Encoding:** The time variable $t$ is processed using a linear form without positional encoding [S1], or sinusoidal functions for implicit approaches [S2].
2. **Feature Combination:** The encoded time representation is combined with the input feature vector $\mathbf{f}$ for the final prediction stage [S1, S2].
3. **Output Activation:** The predicted raw color values are constrained to the valid display range $[0, 1]$ using a dataset-specific function [S1].

**Formulas:**
- **Linear Time Encoding:** $\mathbf{e}_t = t$ [S1].
- **Sinusoidal Time Encoding:** $\mathbf{e}_t = [\sin(\omega_1 t), \cos(\omega_1 t), \dots, \sin(\omega_L t), \cos(\omega_L t)]$, where $L$ is the number of sinusoidal functions [S2].
- **Sigmoid Activation:** $\mathbf{c} = \sigma(\mathbf{c}_{raw}) = \frac{1}{1 + e^{-\mathbf{c}_{raw}}}$, applied when training on the Neural 3D dataset [S1].
- **Clamp Activation:** $\mathbf{c} = \text{clamp}(\mathbf{c}_{raw}, 0, 1)$, applied for other datasets (e.g., Google Immersive, Technicolor) [S1].

**Parameters:**
- $L$: Number of sinusoidal functions for time encoding. Default is 10 [S2].
- Time normalization range: Typically $[-1.0, 1.0]$, but can be reduced to $[-0.8, 0.8]$ for K-Planes experiments without harming performance [S2].

**Edge Cases and Pitfalls:**
- If $L=0$ in sinusoidal encoding, the model fails to represent dynamic scenes [S2].
- Using $L=5$ yields lower quality in dynamic regions compared to $L=10$ [S2].

## Subtopics

### Sinusoidal Time Encoding
A variant where the normalized time input is encoded using a set of sinusoidal functions to better represent scene movement in implicit function-based approaches [S2]. The number of functions $L$ defaults to 10, as $L=0$ fails to represent dynamics and $L=5$ offers lower quality than $L=10$ [S2].

## Operating characteristics
- **Time Complexity:** Not given in the sources [G].
- **Memory Complexity:** Not given in the sources [G].
- **Strengths:** Sinusoidal encoding allows the network to better represent the movement of the scene [S2].
- **Limitations:** Sinusoidal encoding requires selecting $L$; $L=0$ fails to represent dynamic scenes and $L=5$ yields lower quality than the default $L=10$ [S2].
- **When to use:** Use sinusoidal encoding for dynamic scenes in implicit representations [S2]. Use linear encoding with dataset-specific activation (sigmoid/clamp) for explicit feature splatting methods [S1].

## Background
The use of sigmoid activation for Neural 3D dataset and clamp for others originates from Spacetime Gaussian Feature Splatting [S1]. The sinusoidal time encoding for implicit dynamic NeRFs was introduced in Sync-NeRF [S2].
