# Neural BRDF and Geometry Decoding

Also called: Appearance Feature Decoding

## Overview
This method decodes scene appearance features into physically interpretable outputs—specifically BRDF values, surface normals, and RGB colors—using distinct neural networks [S1, unofficial]. It solves the problem of separating geometric and radiometric properties from a shared feature representation, allowing for explicit control over shading and geometry during rendering [S1, unofficial]. It differs from sibling methods like [MLPRender_Fea](2414-mlprender-fea.md) by explicitly predicting BRDF parameters and normals rather than just RGB, and from [Neural Surface Rendering](9960-neural-surface-rendering.md) by being a component of a volumetric/radiance field pipeline rather than a pure mesh shader.

## How it works
**Inputs and Outputs:**
*   **Input:** Appearance feature vector $a(x)$, 3D coordinate $x$, view direction $d$, and optional physical parameters $p^*$ (e.g., albedo, roughness) [S1, unofficial].
*   **Outputs:**
    *   $bval$: 3-channel BRDF value [S1, unofficial].
    *   $rgb$: 3-channel color value [S1, unofficial].
    *   $nval$: 3-channel surface normal vector [S1, unofficial].

**Data Structures:**
The appearance feature $a(x)$ is a vector of length $L$ [S1, unofficial].
$$ a(x) = F[1, L] $$
where $F$ represents the feature extraction process [S1, unofficial].

**Network Architectures:**
Three distinct Multi-Layer Perceptrons (MLPs) are employed:
1.  **BRDF Decoder ($B_{dec}$):** Maps $\{ a(x), x, d, p^* \}$ to $bval$ [S1, unofficial].
2.  **Color Decoder ($C_{fuc}$):** Maps $\{ a(x), x, d \}$ to $rgb$ [S1, unofficial].
3.  **Normal Decoder ($n_{fuc}$):** Maps $\{ a(x), x \}$ to $nval$ [S1, unofficial].

**Parameters:**
*   $p^*$: Optional physical parameters such as albedo and roughness. If available, these are included in the input to $B_{dec}$ [S1, unofficial].

**Algorithm:**
1.  Extract the appearance feature vector $a(x)$ from the scene representation at point $x$ [S1, unofficial].
2.  Normalize the view direction $d$ if not already normalized [G].
3.  Pass $a(x)$, $x$, $d$, and $p^*$ (if present) to $B_{dec}$ to compute the BRDF value $bval$ [S1, unofficial].
4.  Pass $a(x)$, $x$, and $d$ to $C_{fuc}$ to compute the RGB color [S1, unofficial].
5.  Pass $a(x)$ and $x$ to $n_{fuc}$ to compute the surface normal $nval$ [S1, unofficial].

**Pseudocode:**
```python
def neural_brdf_geometry_decoding(a_x, x, d, p_star=None):
    """
    Decodes appearance features into BRDF, Color, and Normal.
    
    Args:
        a_x: Appearance feature vector of length L.
        x: 3D coordinate (3,).
        d: View direction (3,).
        p_star: Optional physical parameters (e.g., albedo, roughness).
        
    Returns:
        bval: BRDF value (3,).
        rgb: Color value (3,).
        nval: Surface normal (3,).
    """
    # Normalize view direction
    d = d / np.linalg.norm(d)
    
    # BRDF Decoder: B_dec({a(x), x, d, p*}) -> bval
    # Inputs: a_x, x, d, and p_star if available
    brdf_input = np.concatenate([a_x, x, d])
    if p_star is not None:
        brdf_input = np.concatenate([brdf_input, p_star])
    bval = B_dec_MLP(brdf_input)
    
    # Color Decoder: C_fuc({a(x), x, d}) -> rgb
    # Inputs: a_x, x, d
    color_input = np.concatenate([a_x, x, d])
    rgb = C_fuc_MLP(color_input)
    
    # Normal Decoder: n_fuc({a(x), x}) -> nval
    # Inputs: a_x, x
    normal_input = np.concatenate([a_x, x])
    nval = n_fuc_MLP(normal_input)
    
    # Normalize normal vector to ensure unit length
    nval = nval / np.linalg.norm(nval)
    
    return bval, rgb, nval
```

## Subtopics

### [TensoRF Feature Decoding Architecture](8181-tensorf-feature-decoding-architecture.md)
The TensoRF Feature Decoding Architecture maps compressed feature tensors to radiance and density. It is distinguished by ablation-tested linear layer configurations optimized for speed and PSNR on synthetic datasets, rather than explicit BRDF parameterization.

### [Neural Surface Rendering](9960-neural-surface-rendering.md)
Neural Surface Rendering renders explicit meshes using a neural shader to approximate PBR. It builds on Neural BRDF and Geometry Decoding by explicitly handling intersection points and normals as primary inputs for the appearance model, allowing learned shading effects like subsurface scattering.

### [Neural SDF and Material MLPs](10268-neural-sdf-and-material-mlps.md)
This method defines separate MLPs for SDF and material properties (diffuse/specular albedo, roughness) within the IRON pipeline. It differs from TensoRF by using explicit separate MLPs rather than tensor-decoded features, and from Neural Surface Rendering by focusing on architectural hyperparameters for inverse rendering optimization.

### Volumetric Appearance Architectures
This variant models RGB and transparency as two identical neural network architectures with different output dimensions (3 for RGB, 1 for transparency) [S2]. It encodes 3D points using trainable positional encoding, followed by an MLP with three layers of 128, 128, and 64 features [S2]. Inputs include encoded position, spherical harmonics encoding (degree 3) of view direction, normal vector, and geometric feature vector [S2].

## Operating characteristics
**Time and Memory Complexity:**
Not given in the sources. The method uses multiple MLPs, implying higher computational cost than single-output decoders, but the exact complexity depends on the MLP depth and width [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Explicitly decodes physically meaningful parameters (BRDF, normals), enabling relighting and material analysis [S1, unofficial].
*   **Limitations:** Requires training multiple distinct networks, increasing model complexity [S1, unofficial]. Performance depends on the quality of the appearance feature vector $a(x)$ [S1, unofficial].

**When to Use:**
Use when explicit material and geometric parameters are required for downstream tasks like relighting or material editing [S1, unofficial].

**When Not to Use:**
Avoid when computational efficiency is paramount and only RGB output is needed [S1, unofficial].

## Background
Originated in the context of tensorial relighting radiance fields [S1, unofficial]. The method is part of a pipeline that approximates incident light fields using environment maps parameterized by multi-spherical Gaussians [S1, unofficial].
