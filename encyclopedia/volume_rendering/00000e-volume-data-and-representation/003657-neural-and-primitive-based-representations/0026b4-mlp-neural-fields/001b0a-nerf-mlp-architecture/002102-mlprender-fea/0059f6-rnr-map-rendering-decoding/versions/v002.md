# RNR-Map Rendering (Decoding)

Also called: Decoding and Rendering (Fdec), Locally Conditioned Radiance Fields Rendering

## Overview
RNR-Map Rendering (Decoding) reconstructs an RGBD image from a 2D latent map by sampling latent codes along camera rays and converting them into locally conditioned radiance fields using modulation linear layers [S1]. It solves the problem of generalizable neural rendering by enabling image synthesis from arbitrary, unseen environments without per-scene optimization, distinguishing it from standard NeRF which requires continuous field optimization for each specific scene [S1].

## How it works
**Inputs:**
*   Query pose $P_q$ (camera parameters) [S1].
*   RNR-Map $m$ (2D latent map of size $U \times V$) [S1].
*   Decoder parameters $\theta_{dec}$ (pretrained) [S1].

**Outputs:**
*   Reconstructed RGBD image $I$ [S1].

**Data Structures:**
*   **RNR-Map ($m$):** A 2D grid of latent codes [S1].
    *   Dimensions: $U \times V$ (height and width) [S1].
    *   Element $m(u, v)$: A latent code vector of dimension $D$ ($m(u, v) \in \mathbb{R}^D$) [S1].
    *   Mask ($n$): A parallel grid of integers recording the number of averaged features at each position, $n(u, v) = |X_{(u,v)}|$ [S1].

**Steps:**
1.  **Ray Definition:** For each pixel in the target image, define a camera ray corresponding to the query pose $P_q$ [S1].
2.  **Latent Code Sampling:** Sample latent codes from the RNR-Map $m$ along each camera ray [S1].
3.  **Modulation:** Convert the sampled latent codes into modulation linear layer-based locally conditioned radiance fields [S1].
4.  **Rendering:** Pass the sampled latent codes through the pretrained decoder $\theta_{dec}$ to reconstruct the pixel color/intensity [S1].

**Formulas:**
The training loss for the encoder and decoder is defined as the L1 norm between the original observation $I_i$ and the rendered image [S1]:

$$
\mathrm{Loss}(\theta_{enc}, \theta_{dec}) = \frac{1}{N} \sum_{i=1}^N ||I_i - F_{dec}(m_N^g, p_i; \theta_{dec})||_1
$$

Where:
*   $N$ is the number of images [S1].
*   $I_i$ are the original observations [S1].
*   $m_N^g$ is the final global map [S1].
*   $p_i$ are the poses [S1].
*   $F_{dec}$ is the decoding function [S1].

**Pseudocode:**

```python
import math

def render_rnr_map(query_pose, rnr_map, decoder):
    """
    Renders an RGBD image from an RNR-Map given a query pose.
    
    Args:
        query_pose: Dictionary containing 'intrinsics' (3x3 K) and 'extrinsics' (4x4 T).
        rnr_map: 2D grid of latent codes m of shape (U, V, D).
        decoder: Pretrained decoder network theta_dec.
        
    Returns:
        rendered_image: Reconstructed RGBD image of shape (U, V, 4).
    """
    U, V, D = rnr_map.shape
    rendered_image = [[None for _ in range(V)] for _ in range(U)]
    
    for h in range(U):
        for w in range(V):
            # 1. Define camera ray for pixel (h, w)
            # [G] Standard pinhole camera model: ray origin is camera center, direction is back-projected pixel.
            ray_origin = [query_pose['extrinsics'][i][3] for i in range(3)]
            pixel_vec = [w, h, 1.0]
            ray_direction = [sum(query_pose['intrinsics'][i][j] * pixel_vec[j] for j in range(3)) for i in range(3)]
            norm = math.sqrt(sum(c*c for c in ray_direction))
            ray_direction = [c/norm for c in ray_direction]
            
            # 2. Sample latent code from map along ray
            # [G] The source states sampling occurs at points along the ray corresponding to pixel location.
            # We project the ray to 2D map coordinates (u, v).
            u, v = ray_to_map_coords(ray_origin, ray_direction, query_pose, U, V)
            u, v = max(0, min(u, U - 1)), max(0, min(v, V - 1))
            latent_code = bilinear_interpolate(rnr_map, u, v)
            
            # 3 & 4. Convert to locally conditioned radiance fields and render
            # [G] The decoder uses the latent code to modulate its internal linear layers.
            pixel_value = decoder.decode(latent_code, ray_origin, ray_direction)
            rendered_image[h][w] = pixel_value
            
    return rendered_image

def ray_to_map_coords(ray_origin, ray_direction, query_pose, height, width):
    """
    Projects a 3D ray to 2D map coordinates (u, v).
    [G] The source does not specify the exact projection math. 
    We assume a direct correspondence between pixel grid and map grid for decoding.
    """
    # Simplified projection: map ray direction components to grid coordinates
    # In practice, this involves inverse camera projection through intrinsics.
    u = int(ray_direction[0] * height)
    v = int(ray_direction[1] * width)
    return u, v

def bilinear_interpolate(grid, u, v):
    """
    Performs bilinear interpolation on a 2D grid of vectors.
    """
    u0, v0 = int(u), int(v)
    u1, v1 = u0 + 1, v0 + 1
    du, dv = u - u0, v - v0
    
    # Clamp boundary indices
    u0, u1 = max(0, min(u0, len(grid)-1)), max(0, min(u1, len(grid)-1))
    v0, v1 = max(0, min(v0, len(grid[0])-1)), max(0, min(v1, len(grid[0])-1))
    
    # Interpolate along u
    vec_u0 = [grid[u0][v0][d] * (1-du) + grid[u1][v0][d] * du for d in range(len(grid[0][0]))]
    vec_u1 = [grid[u0][v1][d] * (1-du) + grid[u1][v1][d] * du for d in range(len(grid[0][0]))]
    
    # Interpolate along v
    result = [vec_u0[d] * (1-dv) + vec_u1[d] * dv for d in range(len(vec_u0))]
    return result
```

**Edge Cases and Pitfalls:**
*   **Unseen Environments:** The method is designed to handle unseen environments by embedding useful information from images into the map, but performance depends on the encoder's ability to generalize [S1].
*   **Precision:** The text does not specify precision issues, but standard floating-point precision applies to the L1 loss and interpolation [S1].
*   **Boundary Handling:** Sampling near map edges requires clamping or padding to avoid out-of-bounds latent code retrieval [G].

## Operating characteristics
*   **Time Complexity:** Real-time capable [S1].
*   **Memory Complexity:** Depends on the size of the RNR-Map ($U \times V \times D$) [S1].
*   **Strengths:** Generalizable to arbitrary scenes without additional optimization; real-time rendering capability; handles unseen environments [S1].
*   **Limitations:** Requires a pretrained encoder and decoder; relies on the quality of the latent map construction [S1].
*   **When to use:** Visual navigation tasks in unseen environments where real-time rendering is required [S1].
*   **When not to use:** Not given in the sources.

## Background
RNR-Map was introduced in the paper "Renderable Neural Radiance Map for Visual Navigation" [S1]. It addresses the limitation of standard NeRF, which optimizes a continuous field and is not generalizable to various scenes, a serious problem for visual navigation tasks in unseen environments [S1]. The method uses a pair of encoder and decoder networks to embed visual information from images into a latent map and reconstruct images using neural radiance fields conditioned on these latent codes [S1].
