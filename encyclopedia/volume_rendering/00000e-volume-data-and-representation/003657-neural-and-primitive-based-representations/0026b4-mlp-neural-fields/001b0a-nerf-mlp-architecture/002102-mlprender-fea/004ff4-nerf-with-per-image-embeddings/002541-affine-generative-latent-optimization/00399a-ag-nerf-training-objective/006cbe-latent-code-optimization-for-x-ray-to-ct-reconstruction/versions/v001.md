# Latent Code Optimization for X-ray to CT Reconstruction

Also called: DeepScan3D Reconstruction, Single-X-ray-to-3D-CT-Reconstruction

## Overview
This method reconstructs a 3D Computed Tomography (CT) volume from a single 2D X-ray projection by optimizing the latent code $z$ of a pre-trained conditional Neural Radiance Field (NeRF) generator, rather than optimizing the network weights [S1, unofficial]. It solves the ill-posed inverse problem of single-view tomography by leveraging a learned generative prior to constrain the solution space [S1, unofficial]. Unlike standard NeRF training which optimizes network weights, this approach keeps the generator weights fixed and treats the latent vector as the trainable parameter, enabling reconstruction from a single view without retraining the network [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A single 2D X-ray projection image $I_{target}$ of shape $(H, W)$, and a pre-trained conditional NeRF generator $G$ with fixed weights.
- **Output:** A reconstructed 3D volume represented by the optimized latent code $z$ and the corresponding rendered projections.

**Data Structures:**
- **Latent Code $z$:** A tensor of shape $(N_{samples}, z_{dim})$ initially, where $N_{samples}$ is the number of candidate reconstructions and $z_{dim}$ is the dimension of the latent space defined in the configuration. During rendering, this is expanded to $(N_{samples} \times N_{poses}, z_{dim})$ [S1, unofficial].
- **Rays Tensor:** A tensor of shape $(2, B \times H \times W, 3)$ after permutation and flattening, representing the origin and direction for each pixel in the batch [S1, unofficial].
- **Camera Poses:** A set of $N_{poses}$ camera poses generated based on angular ranges. Each pose is a $3 \times 4$ matrix [S1, unofficial].

**Parameters:**
- **Learning Rate:** 0.0005 for the latent code optimizer [S1, unofficial].
- **Optimizer:** RMSprop with $\alpha=0.99$ and $\epsilon=1e-8$ [S1, unofficial].
- **Maximum Iterations:** 5000 [S1, unofficial].
- **PSNR Stopping Threshold:** 25. Optimization breaks if the Peak Signal-to-Noise Ratio (PSNR) exceeds this value [S1, unofficial].
- **Image Resolution:** 64x64 pixels (default, configurable via `--img_size`) [S1, unofficial].
- **Loss Weights:** Perceptual loss weight $\lambda_{perc} = 0.3$, MSE loss weight $\lambda_{mse} = 0.1$ [S1, unofficial].
- **Save Frequency:** Every 50 iterations [S1, unofficial].

**Steps:**
1. **Initialization:** Load the generator model from a checkpoint and set it to evaluation mode (`eval()`) to disable dropout and batch normalization updates [S1, unofficial]. Create a copy of the generator weights for testing to preserve the original trained model [S1, unofficial].
2. **Latent Sampling:** Sample initial latent codes $z$ from the learned latent distribution $z_{dist}$ with dimension $z_{dim}$. The shape is $(N_{samples}, z_{dim})$ [S1, unofficial]. If a real X-ray image is provided, it can be encoded into a latent code using a noisy image transformation function; otherwise, codes are sampled from the distribution [S1, unofficial].
3. **Pose Generation:** Define camera poses for rendering. Calculate theta and phi ranges from the configuration data. Generate $N_{phi}$ poses using a pose generation function with a fixed theta mean and varying phi. The radius is taken from the configuration data radius [S1, unofficial].
4. **Expansion:** Expand the latent codes and poses to match the number of frames. $z$ is expanded to $(N_{samples} \times N_{poses}, z_{dim})$ and poses to $(N_{samples} \times N_{poses}, 3, 4)$ [S1, unofficial].
5. **Optimization Loop:** For each optimization iteration:
    a. Zero gradients of the latent code optimizer [S1, unofficial].
    b. Generate rays for each sample/pose pair using a ray generation function. Rays are batched by `batch_size`. The shape is transformed from `Bx2x(HxW)xC` to `2x(BxHxW)x3` via permute and flatten [S1, unofficial].
    c. Query the generator network with latent code $z_i$ and rays $rays_i$. The generator returns RGB, Depth, Accumulation, and potentially other outputs. The output shape is transformed from `(NxHxW)xC` to `NxCxHxW` [S1, unofficial].
    d. Concatenate results and reshape to $(N_{samples}, N_{frames}, C, H, W)$ to form the reconstructed X-ray volume projections [S1, unofficial].
    e. Compute reconstruction loss. The loss is a weighted sum of perceptual loss and MSE loss between the first frame of the first sample's reconstruction and the target X-ray image:
       $$ L = \lambda_{perc} L_{perc} + \lambda_{mse} L_{mse} $$
       where $L_{perc}$ is the perceptual loss and $L_{mse}$ is the Mean Squared Error [S1, unofficial].
    f. Backpropagate the reconstruction loss and step the optimizer to update the latent code $z$ [S1, unofficial].
    g. Check stopping condition: if accumulated PSNR exceeds the threshold (default 25), break the loop [S1, unofficial].
    h. Periodically save generated videos of the reconstructed volume projections every `args.save_every` iterations (default 50) [S1, unofficial].

**Edge Cases and Pitfalls:**
- The generator must be in evaluation mode (`eval()`) during inference to disable dropout and batch normalization updates, but the latent code $z$ is treated as a trainable parameter (optimizer target) rather than the network weights [S1, unofficial].
- Precision issues may arise if the generator output scaling does not match the target X-ray image scaling. Proper normalization (e.g., dividing by 2 and adding 0.5) is required [S1, unofficial].
- Degenerate input (e.g., a very low-quality or noisy X-ray) may lead to suboptimal latent codes. The perceptual loss helps mitigate this by guiding the reconstruction towards realistic textures [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The optimization loop runs for up to 5000 iterations. Each iteration involves forward passes through the generator for $N_{samples} \times N_{poses}$ rays. The complexity is dominated by the generator query, which is $O(N_{samples} \times N_{poses} \times H \times W)$ per iteration [S1, unofficial].
- **Memory Complexity:** The memory usage is proportional to the number of samples, poses, and the generator's internal state. The latent code tensor is small, but the intermediate tensors for rays and generator outputs can be large [S1, unofficial].
- **Measured Performance:** The method uses a resolution of 64x64 pixels and 400 poses for reconstruction [S1, unofficial]. The stopping condition is based on PSNR, with a default threshold of 25 [S1, unofficial].
- **Strengths:** It allows reconstruction from a single view without retraining the network, leveraging a strong generative prior [S1, unofficial].
- **Limitations:** The quality of reconstruction depends heavily on the pre-trained generator's ability to model the data distribution. It may struggle with out-of-distribution inputs [S1, unofficial].

## Background
This method is part of the DeepScan3D project, which aims to reconstruct 3D CT volumes from single 2D X-ray projections using Neural Radiance Fields [S1, unofficial]. It builds on the AG-NeRF framework, which uses affine generative latent optimization for NeRF training [S1, unofficial]. The approach was developed to address the challenges of single-view tomography, where traditional methods require multiple projections [S1, unofficial].
