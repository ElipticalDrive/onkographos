# NeRF with Global Animation Code

Also called: NeRF extended with global animation code, temporal conditioned NeRF

## Overview
This method extends the static NeRF MLP architecture to handle dynamic sequences by conditioning the radiance field on a global animation code [S1]. While standard NeRF learns a continuous function of scene radiance (RGB and opacity) conditioned only on 3D coordinates and viewing direction, it is not directly applicable to dynamic scenes [S1]. By introducing a global animation code generated from an encoder (such as the one in NV), the model can render novel views of dynamic content by varying this code [S1]. It builds on [AG-NeRF Training Objective](8502-ag-nerf-training-objective.md) by providing the specific architectural integration of the animation code into the NeRF MLP.

## How it works
**Inputs:**
1.  3D scene coordinates $\mathbf{x} \in \mathbb{R}^3$.
2.  Viewing direction $\mathbf{d} \in \mathbb{R}^3$.
3.  Global animation code $\mathbf{z} \in \mathbb{R}^{256}$ [S1].

**Outputs:**
1.  Color $\mathbf{c} \in \mathbb{R}^3$.
2.  Density $\sigma \in \mathbb{R}$.

**Data Structures:**
*   **Global Animation Code:** A feature vector of 256 entries [S1]. This code is generated by an encoder network (e.g., from NV) which processes input frames or modalities [S1].
*   **NeRF MLP:** A fully connected neural network that takes positional encoding of coordinates, viewing direction, and the global animation code as input [S1].

**Steps:**
1.  **Positional Encoding:** Apply positional encoding to the 3D coordinates $\mathbf{x}$ to capture high-frequency information [S1].
2.  **Code Generation:** Generate the global animation code $\mathbf{z}$ using an encoder network conditioned on the input dynamic data (e.g., RGB images) [S1]. The encoder in NV produces this code [S1].
3.  **NeRF Conditioning:** Concatenate or combine the positional encoding of $\mathbf{x}$, the viewing direction $\mathbf{d}$, and the global animation code $\mathbf{z}$ [S1].
4.  **Radiance Prediction:** Pass the combined input through the NeRF MLP to predict density $\sigma$ and color $\mathbf{c}$ [S1].
5.  **Raymarching:** Perform raymarching using the predicted density and color, conditioned on the global animation code, to render novel views [S1].

**Pseudocode:**
```python
def render_dynamic_neRF(ray_origin, ray_direction, global_animation_code):
    """
    Renders a single ray for a dynamic NeRF.
    
    Args:
        ray_origin: 3D vector, origin of the ray.
        ray_direction: 3D vector, direction of the ray.
        global_animation_code: 256-dim vector, conditioning the dynamic appearance.
        
    Returns:
        color: 3D vector, rendered color.
        depth: float, accumulated depth.
    """
    # Number of samples along the ray
    N_samples = 128
    
    # Sample points along the ray
    # t values are sampled between near and far bounds
    t_vals = sample_t_vals(N_samples)
    
    # Compute 3D coordinates for each sample
    # x_i = ray_origin + t_i * ray_direction
    points = ray_origin + t_vals[:, None] * ray_direction
    
    # Apply positional encoding to 3D coordinates
    # This captures high frequency information [S1]
    encoded_points = positional_encoding(points)
    
    # Concatenate encoded points, viewing direction, and global animation code
    # The MLP is conditioned on these three inputs [S1]
    input_vector = concatenate([encoded_points, ray_direction, global_animation_code])
    
    # Pass through the NeRF MLP
    # The MLP predicts density and color for each point
    # Note: The specific MLP architecture details (layers, activations) are not
    # provided in the sources, so we assume a standard MLP forward pass [S1]
    density, color = mlp_forward(input_vector)
    
    # Perform raymarching to accumulate color and depth
    # Using standard volume rendering integral approximation
    weights = compute_weights(density, t_vals)
    color = sum(weights[:, None] * color, axis=0)
    depth = sum(weights * t_vals, axis=0)
    
    return color, depth

def compute_weights(density, t_vals):
    """
    Computes raymarching weights from density and sample distances.
    """
    # Compute distances between samples
    dists = t_vals[1:] - t_vals[:-1]
    # Append a zero for the last segment
    dists = concatenate([dists, torch.tensor([0.0])])
    
    # Compute alpha from density
    # alpha = 1 - exp(-sigma * delta)
    alpha = 1.0 - torch.exp(-density * dists)
    
    # Compute transmittance
    # T_i = exp(-sum_{j=0}^{i-1} sigma_j * delta_j)
    transmittance = torch.cumprod(1.0 - alpha + 1e-10, dim=0)
    transmittance = torch.roll(transmittance, 1)
    transmittance[0] = 1.0
    
    # Weights = alpha * transmittance
    weights = alpha * transmittance
    
    return weights
```

**Parameters:**
*   **Global Animation Code Size:** 256 entries [S1].
*   **Volume Size:** $128^3$ (mentioned in context of NV encoder/decoder, likely referring to the latent space or voxel grid size in the NV component, not necessarily the NeRF sampling grid) [S1].
*   **Warp Field Size:** $32^3$ (mentioned in context of NV) [S1].

**Edge Cases and Pitfalls:**
*   **Dynamic Sequences:** Original NeRF is not directly applicable to dynamic sequences; it requires this extension with an animation code [S1].
*   **Encoder Dependency:** The quality of the animation code depends on the encoder (e.g., NV). If the encoder fails to capture the dynamic features, the rendering will be inaccurate [S1].

## Subtopics

### Landmark Driven Animation
A method to drive the dynamic field using 2D landmarks instead of images [S1]. It trains a simplified PointNet-like encoder to regress the global code from 2D landmarks [S1]. The encoder is trained by minimizing the L2 distance between the global code from keypoints ($z_{kps}$) and the corresponding global code from images ($z_{img}$) [S1]. Keypoint encoders provide less information than image encoders, resulting in lower performance, but still allow reasonable avatar driving [S1]. This allows for controllable animation where the user can manipulate landmarks to drive the NeRF [S1].

*   **Strengths:** Capable of rendering dynamic scenes by conditioning on a global animation code [S1]. Can be driven by various modalities, including 2D landmarks [S1].
*   **Limitations:** Performance with landmark-driven animation is lower than image-driven due to less information in keypoints [S1].
*   **When to use:** When rendering dynamic scenes (e.g., human heads) from a set of input images and needing to generate novel views or animate the scene [S1].
*   **When not to use:** For static scenes, where standard NeRF is sufficient [S1].

## Background
This method extends the original NeRF approach, which learns a continuous function of scene radiance conditioned on scene coordinates and viewing direction [S1]. The original NeRF is not directly applicable to dynamic sequences [S1]. The extension introduces a global animation code generated from an encoder in NV (Neural Volumes) to handle dynamic sequences [S1]. The NV encoder-decoder network is used to regress the global code from three images [S1]. The global animation code is a feature vector of 256 entries [S1]. The method allows for novel view synthesis of dynamic human heads [S1].
