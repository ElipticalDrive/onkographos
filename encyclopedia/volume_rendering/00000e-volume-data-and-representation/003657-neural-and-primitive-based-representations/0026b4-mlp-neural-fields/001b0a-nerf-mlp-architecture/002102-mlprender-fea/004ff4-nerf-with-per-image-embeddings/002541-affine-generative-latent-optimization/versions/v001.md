# Affine Generative Latent Optimization

Also called: Affine GLO, Affine transformation of bottleneck vector

## Overview
Affine Generative Latent Optimization (Affine GLO) is a technique for modeling per-image appearance variation in neural radiance fields by applying an affine transformation to a latent bottleneck vector. It solves the problem of capturing style and appearance changes across a sequence of images (video) without introducing artifacts like floaters. It sets itself apart from standard per-image embeddings by learning a generative mapping (an MLP) that produces scale and shift parameters, rather than using the embedding directly as a static input feature. It builds on [NeRF with Per-Image Embeddings](2484-nerf-with-per-image-embeddings.md).

## How it works
**Inputs:**
- A set of training images.
- A bottleneck vector $z$ (latent representation) for each image.

**Outputs:**
- A scale vector $s$ and a shift vector $t$, both of the same length as $z$.
- The transformed vector $z'$ used as input to the view-dependent MLP.

**Data Structures:**
- **Bottleneck Vector ($z$):** A 1D vector of length 128. One vector is allocated per image in the training set.
- **Affine MLP:** A two-layer Multi-Layer Perceptron.
    - Input size: 128 (length of $z$).
    - Hidden layer size: 128 units.
    - Output size: 256 (two vectors of length 128: scale $s$ and shift $t$).
    - Activations: ReLU for the hidden layer; Exponential ($\exp$) for the scale output; linear (identity) for the shift output.

**Parameters:**
- Latent vector length: 128 [S1].
- MLP hidden units: 128 [S1].

**Steps:**
1. For each image in the training set, allocate a 128-length vector $z$ [S1].
2. Pass $z$ through the two-layer Affine MLP:
   - Compute hidden representation $h = \text{ReLU}(W_1 z + b_1)$, where $W_1 \in \mathbb{R}^{128 \times 128}$ and $b_1 \in \mathbb{R}^{128}$ [S1].
   - Compute raw output $y = W_2 h + b_2$, where $W_2 \in \mathbb{R}^{256 \times 128}$ and $b_2 \in \mathbb{R}^{256}$ [S1].
   - Split $y$ into two 128-length vectors: $y_{scale}$ and $y_{shift}$ [S1].
   - Compute scale $s = \exp(y_{scale})$ [S1].
   - Compute shift $t = y_{shift}$ [S1].
3. Transform the bottleneck vector: $z' = s \odot z + t$, where $\odot$ denotes element-wise multiplication [S1].
4. Use $z'$ as the input to the view-dependent MLP for color prediction [S1].

**Pseudocode:**
```python
import numpy as np

class AffineGLP:
    def __init__(self, latent_dim=128, hidden_dim=128):
        self.latent_dim = latent_dim
        self.hidden_dim = hidden_dim
        # Initialize weights and biases for the two-layer MLP
        # Layer 1: latent_dim -> hidden_dim
        self.W1 = np.random.randn(hidden_dim, latent_dim) * 0.01
        self.b1 = np.zeros(hidden_dim)
        # Layer 2: hidden_dim -> 2 * latent_dim (scale and shift)
        self.W2 = np.random.randn(2 * latent_dim, hidden_dim) * 0.01
        self.b2 = np.zeros(2 * latent_dim)

    def forward(self, z):
        """
        z: numpy array of shape (N, latent_dim)
        Returns: transformed_z of shape (N, latent_dim)
        """
        # Layer 1 with ReLU activation
        h = np.maximum(0, np.dot(z, self.W1.T) + self.b1)
        
        # Layer 2 output
        y = np.dot(h, self.W2.T) + self.b2
        
        # Split into scale and shift components
        y_scale = y[:, :self.latent_dim]
        y_shift = y[:, self.latent_dim:]
        
        # Apply final activations
        # Scale uses exp, shift uses identity
        s = np.exp(y_scale)
        t = y_shift
        
        # Affine transformation: z' = s * z + t
        transformed_z = s * z + t
        
        return transformed_z
```

**Edge Cases and Pitfalls:**
- The technique is specifically noted to be used only for video results and does not improve quantitative performance on standard metrics [S1].
- The exponential activation on the scale ensures positive scaling factors, which is critical for stability.

## Subtopics

## Operating characteristics
- **Performance:** The method allows the model to more easily explain per-image appearance variation without placing floaters in front of training cameras [S1].
- **Training Speed:** It results in faster training than the GLO baseline [S1].
- **Limitations:** It does not improve quantitative performance on metrics [S1].
- **Use Case:** Specifically designed for video results where appearance variation is significant [S1].

## Background
The technique resembles prior techniques in the literature for modulating activations to control “style” and appearance [S1]. It is cited in the context of Zip-NeRF, which discusses anti-aliased grid-based neural radiance fields [S1].
