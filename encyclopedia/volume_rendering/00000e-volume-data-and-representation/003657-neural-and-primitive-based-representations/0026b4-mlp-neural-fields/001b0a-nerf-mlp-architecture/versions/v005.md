# NeRF MLP Architecture

Also called: NeRF MLP, NeRF Network, NeRF Architecture, NeRF Model Architecture, NeRF Network Architecture, Neural Radiance Field MLP, Neural Radiance Field Network

## Overview

The NeRF MLP Architecture is a multi-layer perceptron (MLP) that maps a 5D coordinate—comprising a 3D spatial location $\mathbf{x}$ and a 2D viewing direction $\mathbf{d}$—to volume density $\sigma$ and view-dependent emitted color $\mathbf{c}$. It solves the problem of representing complex 3D scenes as continuous volumetric functions for novel view synthesis. It sets itself apart from its siblings by enforcing a specific two-branch structure: density is predicted as a function of position only (enforcing multiview consistency), while color is predicted from position features concatenated with the viewing direction (enabling specular reflections and view-dependent effects) [S1][S9, unofficial].

## How it works

**Inputs and Outputs:**
*   **Input:** A batch of 5D coordinates. The spatial position $\mathbf{x} = (x, y, z)$ and viewing direction $\mathbf{d} = (d_x, d_y, d_z)$ (a 3D Cartesian unit vector derived from spherical coordinates $\theta, \phi$) [S1][S9, unofficial].
*   **Output:** Volume density $\sigma \in [0, \infty)$ and RGB color $\mathbf{c} \in [0, 1]$ [S1][S13, unofficial].

**Data Structures and Layout:**
The network consists of two main components: a position MLP (density backbone) and a color head [S10, unofficial].

1.  **Positional Encoding:** Inputs are expanded using a deterministic positional encoding function $\gamma(\cdot)$ [S1][S13, unofficial].
    *   For position $\mathbf{x}$: $\gamma(\mathbf{x}) \in \mathbb{R}^{D_{pos}}$.
    *   For direction $\mathbf{d}$: $\gamma(\mathbf{d}) \in \mathbb{R}^{D_{dir}}$.
2.  **Position MLP:** A sequence of fully connected layers with ReLU activations.
    *   Input dimension: $D_{pos}$.
    *   Hidden layers: $L_{pos}$ layers of width $W$.
    *   Skip connections: The original encoded position $\gamma(\mathbf{x})$ is concatenated to the output of specific layers (typically layer index 4, 0-indexed) [S1][S10, unofficial].
    *   Output: A scalar $\sigma$ and a feature vector $\mathbf{f} \in \mathbb{R}^{W}$.
3.  **Color Head:**
    *   Input: Concatenation of feature vector $\mathbf{f}$ and encoded direction $\gamma(\mathbf{d})$.
    *   Hidden layers: $L_{dir}$ layers of width $W_{dir}$.
    *   Output: RGB color $\mathbf{c}$.

**Parameters (Default Values from [S1]):**
*   Positional Encoding Depth for Position ($L_{pos}$): 10.
*   Positional Encoding Depth for Direction ($L_{dir}$): 4.
*   Position MLP Layers ($L_{pos}$): 8.
*   Hidden Dimension ($W$): 256.
*   Skip Layer Index: 4.
*   Color Head Layers ($L_{dir}$): 1.
*   Color Head Hidden Dimension ($W_{dir}$): 128.

**Formulas:**

1.  **Positional Encoding:**
    For an input coordinate $v \in \{x, y, z, d_x, d_y, d_z\}$ and frequency band $i \in [0, L-1]$:
    $$ \gamma(v)_i = [\sin(2^i \pi v), \cos(2^i \pi v)] $$
    The full encoding for a vector $\mathbf{v}$ is the concatenation of these components and the original values:
    $$ \gamma(\mathbf{v}) = [\mathbf{v}, \sin(2^0 \pi \mathbf{v}), \cos(2^0 \pi \mathbf{v}), \dots, \sin(2^{L-1} \pi \mathbf{v}), \cos(2^{L-1} \pi \mathbf{v})] $$
    This results in input dimensions $D_{pos} = 3(1 + 2L_{pos}) = 63$ and $D_{dir} = 3(1 + 2L_{dir}) = 27$ [S10, S13, unofficial].

2.  **Position MLP Forward Pass:**
    Let $h_0 = \gamma(\mathbf{x})$. For layer $l = 1 \dots 8$:
    $$ h_l = \text{ReLU}(W_l h_{l-1} + b_l) $$
    If $l = 5$ (corresponding to skip index 4 in 0-indexed layer list after the first layer, or explicitly defined as the skip point in the original paper's diagram description where the input is concatenated to the 5th layer's activation [S1, A]):
    $$ h_l = \text{ReLU}(W_l [h_{l-1}, \gamma(\mathbf{x})] + b_l) $$
    *Note: The original paper states the skip connects to the 5th layer. In a 0-indexed list of 8 layers, this is index 4. The input to layer 0 is $\gamma(\mathbf{x})$. The output of layer 0 is $h_0'$. The skip usually concatenates to the input of a subsequent layer. The standard implementation [S1][S7, unofficial] concatenates $\gamma(\mathbf{x})$ to the hidden state before applying the linear transform at the skip layer.*
    
    Corrected Step-by-Step for Position MLP (based on [S1][S7, unofficial]):
    Let $x = \gamma(\mathbf{x})$.
    For $i = 0$ to $7$:
    1. $x = \text{ReLU}(\text{Linear}_i(x))$
    2. If $i == 4$: $x = \text{ReLU}(\text{Linear}_{i+1}([x, \gamma(\mathbf{x})]))$
    
    *Clarification on Layer Count:* The paper describes 8 layers for the position network. The skip connection is at the 5th layer.
    Let's define the layers $l_0 \dots l_7$.
    $h = \gamma(\mathbf{x})$
    For $i = 0 \dots 7$:
      $h = \text{ReLU}(l_i(h))$
      If $i == 4$:
        $h = \text{ReLU}(l_{i+1}([h, \gamma(\mathbf{x})]))$
    
    Output of Position MLP:
    $$ \sigma = \text{ReLU}(l_\sigma(h)) $$
    $$ \mathbf{f} = l_f(h) $$
    Where $l_\sigma$ is a linear layer mapping $W \to 1$ and $l_f$ maps $W \to W$ [S1][S10, unofficial].

3.  **Color Head Forward Pass:**
    $$ \mathbf{c} = \text{Sigmoid}(\text{Linear}_{color}([ \mathbf{f}, \gamma(\mathbf{d}) ])) $$
    The color head takes the 256-dim feature vector $\mathbf{f}$ and the 27-dim encoded direction $\gamma(\mathbf{d})$, concatenates them, passes through a 128-unit ReLU layer, and then a 3-unit Sigmoid layer [S1].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class PositionalEncoding(nn.Module):
    def __init__(self, num_frequencies):
        super().__init__()
        self.num_frequencies = num_frequencies

    def forward(self, x):
        # x shape: (..., 3)
        # Output shape: (..., 3 * (1 + 2 * num_frequencies))
        freq_bands = 2.0 ** torch.arange(self.num_frequencies, device=x.device).float()
        # Create sin/cos components
        # x[..., None] * freq_bands -> (..., 3, num_freqs)
        # sin/cos -> (..., 3, num_freqs, 2)
        # reshape to (..., 3 * 2 * num_freqs)
        x_expanded = x[..., None] * freq_bands
        s = torch.sin(x_expanded)
        c = torch.cos(x_expanded)
        encoded = torch.cat([x, s.flatten(start_dim=-2), c.flatten(start_dim=-2)], dim=-1)
        return encoded

class NeRFMLP(nn.Module):
    def __init__(self, pos_freqs=10, dir_freqs=4, hidden_dim=256, skip_layer=4):
        super().__init__()
        self.pos_enc = PositionalEncoding(pos_freqs)
        self.dir_enc = PositionalEncoding(dir_freqs)
        
        # Position MLP: 8 layers
        # Layer 0: input_dim -> hidden_dim
        # Layers 1-3: hidden_dim -> hidden_dim
        # Layer 4: (hidden_dim + input_dim) -> hidden_dim (skip connection)
        # Layers 5-7: hidden_dim -> hidden_dim
        self.pos_layers = nn.ModuleList()
        
        input_dim_pos = 3 * (1 + 2 * pos_freqs)
        
        # First layer
        self.pos_layers.append(nn.Linear(input_dim_pos, hidden_dim))
        
        # Layers 1 to 3
        for _ in range(3):
            self.pos_layers.append(nn.Linear(hidden_dim, hidden_dim))
            
        # Skip layer (index 4)
        self.pos_layers.append(nn.Linear(hidden_dim + input_dim_pos, hidden_dim))
        
        # Layers 5 to 7
        for _ in range(3):
            self.pos_layers.append(nn.Linear(hidden_dim, hidden_dim))
            
        # Output heads
        self.sigma_head = nn.Linear(hidden_dim, 1)
        self.feature_head = nn.Linear(hidden_dim, hidden_dim)
        
        # Color Head
        input_dim_dir = 3 * (1 + 2 * dir_freqs)
        self.color_layers = nn.Sequential(
            nn.Linear(hidden_dim + input_dim_dir, hidden_dim // 2),
            nn.ReLU(),
            nn.Linear(hidden_dim // 2, 3)
        )

    def forward(self, positions, directions):
        # positions: (N, 3)
        # directions: (N, 3)
        
        pos_emb = self.pos_enc(positions)
        dir_emb = self.dir_enc(directions)
        
        x = pos_emb
        for i, layer in enumerate(self.pos_layers):
            if i == self.skip_layer:
                # Concatenate original positional encoding
                x = torch.cat([x, pos_emb], dim=-1)
            x = F.relu(layer(x))
            
        # Density (view-independent)
        # Using softplus with shift -1 as per [S7, unofficial] or ReLU as per [S1]
        # S1 uses ReLU. S7 uses softplus(h - 1). We follow S1 for standard NeRF.
        sigma = F.relu(self.sigma_head(x))
        
        # Feature vector
        feat = self.feature_head(x)
        
        # Color (view-dependent)
        feat_dir = torch.cat([feat, dir_emb], dim=-1)
        rgb = torch.sigmoid(self.color_layers(feat_dir))
        
        return sigma, rgb
```

## Subtopics

### [Unbounded inward-facing scene parameterization](957-unbounded-inward-facing-scene-parameterization.md)
This method parameterizes unbounded 360-degree scenes by mapping coordinates from $\mathbb{R}^3$ into a bounded domain (typically $[-2, 2]^3$ or a unit sphere), enabling the use of bounded acceleration structures like voxel grids for efficient rendering. It allocates model capacity proportional to disparity (inverse distance), ensuring distant content is represented with lower resolution while preserving detail near the origin. Unlike standard NeRF fields that assume bounded volumes, this technique extends bounded data structures to unbounded scenes. It differs from forward-facing parameterization by handling full spherical coverage rather than a viewing frustum.

### [Position-Only NeRF Field](1253-position-only-nerf-field.md)
A position-only NeRF field is an implicit volume representation that maps a 3D spatial coordinate directly to volume density and emitted color, omitting the viewing direction input to reduce model size and training time. Unlike the full NeRF architecture which models view-dependent effects, this variant assumes isotropic appearance, making it suitable for scenes where lighting is uniform or view dependence is negligible. It serves as a simplified baseline for neural radiance fields, trading view-dependent accuracy for computational efficiency.

### [Tiny NeRF](1275-tiny-nerf.md)
Tiny NeRF is a compression pipeline for voxel-based neural radiance fields that transforms voxel grids into the frequency domain via block-wise Discrete Cosine Transformation (DCT), then prunes and quantizes the resulting coefficients to reduce storage by over 100x with minimal quality loss. Unlike sibling methods that prune empty spatial voxels (e.g., [Unbounded inward-facing scene parameterization](957-unbounded-inward-facing-scene-parameterization.md), [Position-Only NeRF Field](1253-position-only-nerf-field.md)), Tiny NeRF operates on frequency coefficients, allowing higher pruning rates by overcoming foreground-background ratio limitations. It differs from [MLPRender_Fea](2414-mlprender-fea.md) and [View-Dependent MLP](2444-view-dependent-mlp.md) by compressing the explicit voxel grid representation rather than optimizing the MLP architecture itself.

### [MLPRender_Fea](2414-mlprender-fea.md)
MLPRender_Fea is a neural rendering module that predicts RGB color from input features and view directions using a Multi-Layer Perceptron (MLP). Unlike the parent [NeRF MLP Architecture](910-nerf-mlp-architecture.md) which maps 5D coordinates (3D location and viewing direction) directly to density and color, MLPRender_Fea explicitly excludes the 3D position from its input, relying on pre-computed spatial features instead. This design separates spatial structure handling from view-dependent appearance modeling.

### [View-Dependent MLP](2444-view-dependent-mlp.md)
This method replaces the small bottleneck in Instant Neural Graphics Primitives (iNGP) with a larger view-dependent MLP to better express complex view-dependent effects and reduce the formation of "floaters" (spurious geometry). It builds on [NeRF MLP Architecture](910-nerf-mlp-architecture.md) by expanding the capacity of the view-dependent color decoding stage.

### [InstantNGP Network Architecture](5049-instantngp-network-architecture.md)
This article describes the specific Multi-Layer Perceptron (MLP) configuration and feature encoding strategy used in the InstantNGP framework, as adapted by subsequent methods like MonoSDF and Point-NeuS. It solves the bottleneck of evaluating high-dimensional neural fields by combining sparse voxel grids with multi-resolution hash encoding. It sets itself apart from the parent [NeRF MLP Architecture](910-nerf-mlp-architecture.md) by replacing the raw positional encoding with a learnable, sparse hash-based feature storage system, and from [Tiny NeRF](1275-tiny-nerf.md) by maintaining larger hidden dimensions for higher fidelity.

### Recursive Neural Field
A sub-network $F_{\Phi_i}$ that takes its parent branch's output $y_{p_i}$ and viewing direction $d$ as inputs, and predicts color $c_i$, density $\sigma_i$, uncertainty $\delta_i$, and a latent vector $y_i$ [S16]. The sub-network consists of an MLP module, a Branch module, and an Out module. The Branch module predicts uncertainty $\delta_i$, forwards low uncertainty points to the Out module, and distributes high uncertainty points to different sub-networks based on distances to $k_i$ cluster centers [S16]. The function is defined as $F_{\Phi_i} : (y_{p_i}, d) \rightarrow (c_i, \sigma_i, y_i, \delta_i)$, where $F_{\Phi_1}$ is the root taking query coordinates $(x, y, z)$ [S16].

### NeUDF Network Architecture
Two separate MLP networks: one for the Unsigned Distance Field (UDF) and one for color, similar to IDR and NeuS [S17]. The UDF Network ($\Psi(x)$) has 8 hidden layers of size 256, takes spatial location $p(t)$ as input, outputs UDF value and 256-dim feature vector, uses Softplus activation ($\beta=100$), and has a skip connection from input to the 4th layer's output [S17]. The Color Network ($c(x, v)$) has 4 hidden layers of size 256, takes spatial location $p(t)$, view direction $v$, gradient $n$ of the UDF network, and the 256-dim feature vector as inputs, using positional encoding and weight normalization [S17]. Normal regularization is applied to the gradient $n$ before use [S17].

## Operating characteristics

*   **Time Complexity:** The network evaluates $O(N)$ rays, each with $N_s$ samples. Each sample requires a forward pass through the MLP. The MLP has $L$ layers of width $W$. Complexity per sample is $O(L \cdot W^2)$. Total complexity is $O(N \cdot N_s \cdot L \cdot W^2)$ [S1].
*   **Memory Complexity:** The model weights are stored in memory. With default parameters ($L=8, W=256$), the model size is approximately 5 MB [S1]. This is significantly smaller than voxel-based representations (e.g., LLFF requires >15 GB) [S1].
*   **Performance:** On an NVIDIA V100, rendering a single frame (requiring ~150-200 million network queries) takes approximately 30 seconds [S1]. Training a separate network for each scene takes at least 12 hours [S1].
*   **Strengths:** High-quality novel view synthesis with view-dependent effects; compact storage; continuous representation allows arbitrary resolution rendering [S1].
*   **Limitations:** Slow training and inference compared to grid-based methods; spectral bias requires positional encoding; limited to single-scene optimization (not generalizable across scenes without training) [S1].
*   **When to use:** When high-fidelity novel view synthesis is required for a single scene and computational resources for training are available.
*   **When not to use:** For real-time applications requiring fast inference without pre-training, or for generalizable scene representation across many scenes [S1].

## Background

The NeRF MLP Architecture was introduced by Mildenhall et al. in the paper "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" (ECCV 2020) [S1][S7, unofficial]. It addresses the long-standing problem of view synthesis by optimizing a continuous 5D scene representation using a sparse set of input views [S1]. The architecture leverages positional encoding to overcome spectral bias in standard MLPs [S1]. It outperforms prior methods like Neural Volumes (NV), Scene Representation Networks (SRN), and Local Light Field Fusion (LLFF) in both quantitative and qualitative metrics for complex scenes [S1].
