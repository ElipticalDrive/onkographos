# NeRF MLP Architecture

Also called: NeRF MLP, NeRF Network Architecture, Neural Radiance Field MLP, Two-layer MLP for NeRF

## Overview
The NeRF MLP Architecture is a multi-layer perceptron (MLP) that maps 3D spatial coordinates and viewing directions to volume density and view-dependent emitted color, serving as the core implicit representation for Neural Radiance Fields [S1, S2, S3]. It solves the problem of representing complex 3D scenes with high-frequency geometry and appearance using a continuous function that is differentiable with respect to its inputs, enabling optimization via gradient descent on rendered images [S2]. What sets it apart from its siblings, such as [Scene Representation Networks (SRN)](1150-scene-representation-networks-srn.md) which uses a single network for all outputs, and [SIREN Neural Field](1250-siren-neural-field.md) which uses periodic activations, is its specific two-stage hierarchical design: a deeper "density backbone" processes position to output density and an intermediate feature vector, while a shallower "color head" combines this feature with the viewing direction to predict color [S2][S12, unofficial]. This decoupling enforces multiview consistency for density while allowing view-dependent shading for color [S2, S13].

## How it works

### Inputs and Outputs
*   **Inputs**: A batch of 5D coordinates. Each coordinate consists of a 3D spatial position $\mathbf{x} = (x, y, z)$ and a 3D Cartesian unit viewing direction $\mathbf{d} = (d_x, d_y, d_z)$ derived from spherical coordinates $(\theta, \phi)$ [S2][S11, unofficial].
*   **Outputs**: For each input, the network outputs a scalar volume density $\sigma \in [0, \infty)$ and a 3D RGB color vector $\mathbf{c} = (r, g, b) \in [0, 1]$ [S2][S17, unofficial].

### Data Structures and Layout
The architecture is implemented as two sequential MLP blocks with skip connections.

**1. Positional Encoding**
Raw inputs are expanded using Fourier features (positional encoding) to help the network learn high-frequency functions [S2][S17, unofficial].
*   **Position Encoding $\gamma(\mathbf{x})$**: Concatenation of $\mathbf{x}$, $\sin(2^i \pi \mathbf{x})$, and $\cos(2^i \pi \mathbf{x})$ for $i \in [0, L_{pos}-1]$.
    *   Default $L_{pos} = 10$.
    *   Input dimension: $3 \times (1 + 2 \times 10) = 63$ [S11, S17, unofficial].
*   **Direction Encoding $\gamma(\mathbf{d})$**: Same formula as above.
    *   Default $L_{dir} = 4$ (some implementations use 6) [S11, S17, unofficial].
    *   Input dimension: $3 \times (1 + 2 \times 4) = 27$ (or 39 if $L_{dir}=6$) [S11, S17, unofficial].

**2. Density Backbone (Position MLP)**
This block processes $\gamma(\mathbf{x})$ to predict density and an intermediate feature vector.
*   **Layers**: 8 fully connected (linear) layers.
*   **Width**: 256 hidden units per layer [S2][S12, unofficial].
*   **Activation**: ReLU for all layers except the final output projection [S2][S12, unofficial].
*   **Skip Connection**: The original encoded position $\gamma(\mathbf{x})$ is concatenated to the output of the 5th layer (index 4, 0-based) [S2][S12, unofficial].
    *   Layer 0: Input 63 $\to$ 256.
    *   Layers 1-3: Input 256 $\to$ 256.
    *   Layer 4: Input $256 + 63 = 319$ $\to$ 256.
    *   Layers 5-7: Input 256 $\to$ 256.
*   **Output Heads**:
    *   **Density Head**: A linear layer mapping 256 $\to$ 1. Output $\sigma$ is rectified using ReLU (or softplus with shift -1 for sparser initialization) [S2][S9, S17, unofficial].
    *   **Feature Head**: A linear layer mapping 256 $\to$ 256. This outputs the 256-dimensional intermediate feature vector $\mathbf{e}$ [S2][S12, unofficial].

**3. Color Head (Direction MLP)**
This block processes the feature vector $\mathbf{e}$ and direction encoding $\gamma(\mathbf{d})$ to predict color.
*   **Concatenation**: $\mathbf{e}$ (256) is concatenated with $\gamma(\mathbf{d})$ (27 or 39) [S2][S12, unofficial].
*   **Layers**: 1 fully connected layer with ReLU activation, followed by a final linear layer with no activation (or Sigmoid for clamping) [S2][S12, S17, unofficial].
    *   Layer 1: Input $256 + D_{dir}$ $\to$ 128. Activation: ReLU.
    *   Layer 2: Input 128 $\to$ 3. Activation: Sigmoid [S2][S17, unofficial].
*   **Output**: RGB color $\mathbf{c}$ [S2].

### Pseudocode
```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class NeRFMLP(nn.Module):
    def __init__(self, L_pos=10, L_dir=4, hidden_dim=256, skip_layer=4):
        super().__init__()
        self.L_pos = L_pos
        self.L_dir = L_dir
        
        # Calculate input dimensions
        # Input is [x, sin(2^0 pi x), cos(2^0 pi x), ...]
        self.input_ch = 3 * (1 + 2 * L_pos)
        self.input_ch_views = 3 * (1 + 2 * L_dir)
        
        # Density Backbone: 8 layers of 256 units
        # Layer 0
        self.fc0 = nn.Linear(self.input_ch, hidden_dim)
        # Layers 1-3
        self.fc1 = nn.Linear(hidden_dim, hidden_dim)
        self.fc2 = nn.Linear(hidden_dim, hidden_dim)
        self.fc3 = nn.Linear(hidden_dim, hidden_dim)
        # Layer 4 (Skip connection here)
        self.fc4 = nn.Linear(hidden_dim + self.input_ch, hidden_dim)
        # Layers 5-7
        self.fc5 = nn.Linear(hidden_dim, hidden_dim)
        self.fc6 = nn.Linear(hidden_dim, hidden_dim)
        self.fc7 = nn.Linear(hidden_dim, hidden_dim)
        
        # Output heads from layer 7 output
        self.sigma_head = nn.Linear(hidden_dim, 1)
        self.feature_head = nn.Linear(hidden_dim, hidden_dim)
        
        # Color Head
        # Concatenates feature (256) + direction encoding (input_ch_views)
        color_input_dim = hidden_dim + self.input_ch_views
        self.fc_color1 = nn.Linear(color_input_dim, 128)
        self.fc_color2 = nn.Linear(128, 3)

    def forward(self, x, d):
        """
        x: (N, 3) spatial coordinates
        d: (N, 3) viewing directions
        """
        # 1. Positional Encoding
        x_enc = positional_encoding(x, self.L_pos)
        d_enc = positional_encoding(d, self.L_dir)
        
        # 2. Density Backbone
        h = x_enc
        h = F.relu(self.fc0(h))
        h = F.relu(self.fc1(h))
        h = F.relu(self.fc2(h))
        h = F.relu(self.fc3(h))
        
        # Skip connection at layer 4 (index 4 in 0-based counting of layers 0-7)
        # The source says "concatenate input to the 5th layer's activation"
        # Layer 0 is 1st, Layer 4 is 5th.
        h = torch.cat([h, x_enc], dim=-1)
        h = F.relu(self.fc4(h))
        
        h = F.relu(self.fc5(h))
        h = F.relu(self.fc6(h))
        h = F.relu(self.fc7(h))
        
        # 3. Output Heads
        sigma = F.relu(self.sigma_head(h)) # Ensure non-negative density
        # Alternative in some sources: sigma = F.softplus(self.sigma_head(h) - 1)
        features = self.feature_head(h)
        
        # 4. Color Head
        # Concatenate features with direction encoding
        h_color = torch.cat([features, d_enc], dim=-1)
        h_color = F.relu(self.fc_color1(h_color))
        rgb = torch.sigmoid(self.fc_color2(h_color))
        
        return rgb, sigma

def positional_encoding(x, L):
    """
    x: (N, 3)
    Returns: (N, 3 * (1 + 2*L))
    """
    # x is (N, 3). We want to expand each dimension.
    # Result shape: (N, 3 * (1 + 2*L))
    # We can process each of the 3 dimensions separately and concatenate
    
    # Original coordinates
    out = [x]
    
    # Sin/Cos components
    for i in range(L):
        freq = 2**i * torch.pi
        out.append(torch.sin(freq * x))
        out.append(torch.cos(freq * x))
        
    return torch.cat(out, dim=-1)
```

### Parameters and Typical Values
*   **Hidden Dimension ($W$)**: 256 [S2][S12, unofficial].
*   **Depth of Position MLP ($D$)**: 8 layers [S2][S12, unofficial].
*   **Depth of Color MLP**: 1 hidden layer (2 linear layers total) [S2][S12, unofficial].
*   **Positional Encoding Bands ($L_{pos}$)**: 10 [S2][S11, unofficial].
*   **Directional Encoding Bands ($L_{dir}$)**: 4 [S11, unofficial] or 6 [S17, unofficial].
*   **Skip Connection Layer**: Index 4 (5th layer) [S2][S12, unofficial].
*   **Optimizer**: Adam, learning rate $10^{-4}$, $\beta_1=0.9$, $\beta_2=0.999$ [S22].
*   **Batch Size**: 128 pixels (rays) per batch [S22].

### Edge Cases and Pitfalls
*   **View Independence for Density**: The network must predict density $\sigma$ using only position $\mathbf{x}$, not direction $\mathbf{d}$, to ensure multiview consistency [S2, S13]. If direction is fed into the density head, artifacts appear.
*   **Normalization**: Spatial coordinates should be normalized to $[-1, 1]$ or bounded within a specific volume (e.g., unit cube) to ensure stable training [S2, S4].
*   **High-Frequency Bias**: Without positional encoding, the MLP struggles to represent high-frequency details due to spectral bias [S2][S5, unofficial].
*   **Density Initialization**: Using ReLU on the density output ensures non-negativity. Some implementations use `softplus(output - 1)` to encourage sparser initial densities [S9, unofficial].

## Subtopics

### [Unbounded inward-facing scene parameterization](957-unbounded-inward-facing-scene-parameterization.md)
Parameterizes unbounded 3D scenes into a bounded coordinate space, enabling the use of voxel grids or hash-based encodings that require finite domains. It solves the problem where infinite coordinate values break hash tables or MLPs by compressing distant background geometry into a finite ball or cube. It differs from standard normalization by preserving angular direction while non-linearly compressing radial distance, ensuring points at infinity map to the boundary of the bounded space.

### [Position-Only NeRF Field](1253-position-only-nerf-field.md)
A position-only NeRF field is an implicit volume representation that maps a 3D spatial coordinate directly to volume density and emitted color, omitting the viewing direction input to reduce model size and training time. Unlike the full NeRF architecture which models view-dependent effects, this variant assumes isotropic appearance, making it suitable for scenes where lighting is uniform or view dependence is negligible. It serves as a simplified baseline for neural radiance fields, trading view-dependent accuracy for computational efficiency.

### [Tiny NeRF](1275-tiny-nerf.md)
Tiny NeRF is a compression pipeline for voxel-based neural radiance fields that transforms voxel grids into the frequency domain via block-wise Discrete Cosine Transformation (DCT), then prunes and quantizes the resulting coefficients to reduce storage by over 100x with minimal quality loss. Unlike sibling methods that prune empty spatial voxels (e.g., [Unbounded inward-facing scene parameterization](957-unbounded-inward-facing-scene-parameterization.md), [Position-Only NeRF Field](1253-position-only-nerf-field.md)), Tiny NeRF operates on frequency coefficients, allowing higher pruning rates by overcoming foreground-background ratio limitations. It differs from [MLPRender_Fea](2414-mlprender-fea.md) and [View-Dependent MLP](2444-view-dependent-mlp.md) by compressing the explicit voxel grid representation rather than optimizing the MLP architecture itself.

### [MLPRender_Fea](2414-mlprender-fea.md)
MLPRender_Fea is a neural rendering module that predicts RGB color from input features, view directions, and optional positional encodings using a Multi-Layer Perceptron (MLP). It solves the problem of mapping continuous spatial features to view-dependent radiance values in neural implicit representations. It sets itself apart from its parent [NeRF MLP Architecture](910-nerf-mlp-architecture.md) by explicitly decoupling the input representation: it accepts pre-computed features (rather than raw 3D coordinates) as primary input, while still processing view directions to model appearance variations. Unlike [NeRF with Per-Image Embeddings](2484-nerf-with-per-image-embeddings.md) which injects global scene context, MLPRender_Fea focuses on local feature-to-color mapping.

### [View-Dependent MLP](2444-view-dependent-mlp.md)
The View-Dependent MLP is an expanded neural field component designed to model complex view-dependent appearance effects, such as specularities, which standard compact representations often fail to capture. It addresses the problem where insufficient capacity in the view-dependent bottleneck leads to rendering artifacts, including incorrect semi-transparent voxels near surfaces and the generation of "floaters" (small, spurious geometry) that the network uses to explain away view-dependent color variations. It sets itself apart from its sibling [Position-Only NeRF Field](1253-position-only-nerf-field.md) by explicitly incorporating viewing direction into the color prediction, and from the parent [NeRF MLP Architecture](910-nerf-mlp-architecture.md) by utilizing a significantly larger hidden dimension and specific skip connections to improve expressivity.

### [NeUDF Network Architecture](3732-neudf-network-architecture.md)
The NeUDF network architecture is a neural field method that represents 3D geometry as an Unsigned Distance Field (UDF) and color as a separate radiance field, using two distinct Multi-Layer Perceptrons (MLPs). It differs from standard NeRF by modeling unsigned distance rather than volume density, allowing for explicit surface extraction via the zero-level set of the UDF, and by decoupling geometry and appearance into separate networks. This approach builds on the principles of [NeuS](2444-view-dependent-mlp.md) and [IDR](2444-view-dependent-mlp.md) but specifically utilizes the UDF formulation to handle non-manifold geometries and occlusions without prior assumptions about surface intersections.

### [InstantNGP Network Architecture](5049-instantngp-network-architecture.md)
InstantNGP is a neural field architecture designed for real-time training and rendering of 3D scenes by replacing traditional positional encoding with a multiresolution hash grid. It solves the bottleneck of MLP evaluation latency in NeRF by leveraging hardware-accelerated memory locality and bilinear interpolation. Unlike the parent [NeRF MLP Architecture](910-nerf-mlp-architecture.md) which maps raw coordinates to density and color, InstantNGP first encodes spatial positions into a high-dimensional feature vector via hash lookups, which are then processed by a lightweight MLP. This approach enables training convergence in seconds rather than hours, distinguishing it from standard NeRF variants.

### Recursive Neural Field
A sub-network $F_{\Phi_i}$ that takes its parent branch's output $y_{p_i}$ and viewing direction $d$ as inputs, and predicts color $c_i$, density $\sigma_i$, uncertainty $\delta_i$, and a latent vector $y_i$ [S23]. The sub-network consists of an MLP module, a Branch module, and an Out module [S23]. The Branch module predicts uncertainty $\delta_i$, forwards low uncertainty points to the Out module, and distributes high uncertainty points to different sub-networks based on distances to $k_i$ cluster centers [S23]. The function is defined as $F_{\Phi_i} : (y_{p_i}, d) \rightarrow (c_i, \sigma_i, y_i, \delta_i)$, where $F_{\Phi_1}$ is the root and $y_{p_1}$ is the query coordinate $(x, y, z)$ [S23].

### VFR Network Architecture
Uses a Multiresolution Hash Grid (MHG) for feature representation [S24]. The Color NN consists of a Spatial MLP (2 layers, 256 hidden neurons) and a Directional MLP (4 layers, 256 hidden neurons) with a bottleneck feature size of 256 and GELU activations [S24]. Optimizer is Adam with learning rate 0.01 [S24].

### CT-NeRF Network Architecture
Follows the BARF approach [S25, unofficial]. Uses a single 8-layer MLP network with a width of 128 [S25, unofficial].

### Soft Zero-Skipping Gate
A component added to the MLP to ensure that a feature compressed to 0 translates to a zero density [S26]. It applies a differentiable gate $\hat{g}(v)$ to the MLP decoder output $M(v)$ such that $\hat{M}(v) = \hat{g}(v) M(v)$ [S26]. The gate is defined as $\hat{g}(v) = \tanh(\alpha \|v\|_2)$, where $\alpha$ controls the steepness (scheduled from $10^4$ to $10^5$) [S26]. This allows smooth transitions and non-zero gradients for pruning, unlike hard gates [S26].

### DoubleField Network
A joint implicit function $f_{db}$ represented by MLPs that fits both a surface field and a radiance field simultaneously, conditioned on pixel-aligned image features $\phi(x, I)$ [S27]. The function is $f_{db}(x, d, \phi(x, I)) = (s, \sigma, c)$ [S27]. It uses a Shared MLP ($E_{db}$) to produce a double embedding $e_{db}$ from positional encoding $\gamma(x)$ and image features, a Geometry MLP ($E_g$) to output surface field $s$ and density $\sigma$, and a Texture MLP ($E_c$) to output color $c$ using $e_{db}$ and direction $d$ [S27].

## Operating characteristics
*   **Time Complexity**: Training is slow, typically taking 12+ hours per scene on a single GPU (e.g., NVIDIA V100) [S2][S6, unofficial]. Rendering a single frame requires querying the network for hundreds of thousands of points along rays, taking approximately 30 seconds per frame on a V100 [S2].
*   **Memory Complexity**: The model weights are small, typically around 5 MB for the standard architecture [S2]. This is significantly smaller than explicit voxel-based representations (e.g., LLFF requires >15 GB) [S2].
*   **Performance**: Achieves state-of-the-art novel view synthesis quality on complex scenes with specularities and fine details, outperforming SRN and LLFF in metrics like PSNR, SSIM, and LPIPS [S2].
*   **Strengths**: Continuous representation allows arbitrary resolution; view-dependent shading captures complex lighting; small storage footprint.
*   **Limitations**: Slow training and rendering times; sensitive to positional encoding parameters; requires careful normalization of input coordinates; struggles with unbounded scenes without parameterization [S2, S4].
*   **When to use**: When high-quality novel view synthesis is required and computational resources allow for long training times.
*   **When not to use**: When real-time training or rendering is required (consider [InstantNGP Network Architecture](5049-instantngp-network-architecture.md)) or when the scene is unbounded and simple normalization is insufficient (consider [Unbounded inward-facing scene parameterization](957-unbounded-inward-facing-scene-parameterization.md)).

## Background
The NeRF MLP Architecture was introduced by Mildenhall et al. in the paper "NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis" (ECCV 2020) [S2][S9, unofficial]. It was developed to address the limitations of previous neural rendering methods like Neural Volumes and SRN, which either lacked view-dependent shading or suffered from blurriness and artifacts [S2]. The architecture builds on the concept of implicit neural representations and positional encoding to enable the network to learn high-frequency scene details [S2][S5, unofficial]. It has become the foundational architecture for many subsequent NeRF variants and neural rendering methods [S3].
