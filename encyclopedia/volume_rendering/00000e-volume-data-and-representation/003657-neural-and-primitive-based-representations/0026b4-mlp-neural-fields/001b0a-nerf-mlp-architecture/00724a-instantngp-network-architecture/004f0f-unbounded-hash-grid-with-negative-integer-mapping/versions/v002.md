# Unbounded Hash-Grid with Negative Integer Mapping

Also called: Instant-NGP Unbounded Hash Grid, Negative Integer Mapping for Hash Grids

## Overview
This method extends the Instant-NGP hash-grid encoding to support unbounded input domains by modifying the hash function to handle negative integers without structured collisions [S1]. It solves the problem of applying neural field representations, originally designed for normalized $[0, 1]^d$ inputs, to large-scale scenes with arbitrary coordinate ranges [S1]. It differs from its parent [InstantNGP Network Architecture](5049-instantngp-network-architecture.md) by replacing the bounded hash lookup with a negative-integer-aware mapping and by computing positional gradients directly from interpolation weights rather than assuming non-differentiable sample positions [S1].

## How it works
**Inputs and Outputs**
The input is a 3D position vector $\mathbf{x} \in \mathbb{R}^3$ [S1]. The output is a feature vector resulting from trilinear interpolation across multiple hash-grid levels [S1].

**Data Structures**
The method uses multiple hash-grid levels $\ell$, including coarse levels that also use hash-grids instead of traditional grids to maintain consistency in the unbounded domain [S1]. Parameters stored in the hash-grid use 2 bytes each, while all other parameters use 4 bytes each [S1]. Both the hash-grid and the MLP use 16-bit floating-point numbers (FP16) [S1]. Gradients are accumulated in 32-bit floating-point (FP32) tensors to maintain optimization accuracy [S1].

**Mapping Function**
The core modification is a mapping function `MapPositive(x)` applied to each coordinate component $x$ before hashing [S1]. This ensures negative integers map to distinct hash indices, avoiding the structured collisions present in the original hash function when evaluated over positive and negative domains [S1]. The mapping is defined as:
$$
\text{MapPositive}(x) = 
\begin{cases} 
2x - 1 & \text{if } x > 0 \\
-2x & \text{otherwise}
\end{cases}
$$

**Algorithm Steps**
1. **Coordinate Mapping:** For each component $x_i$ of the input position $\mathbf{x}$, apply `MapPositive(x_i)` [S1].
2. **Hashing:** For each hash-grid level $\ell$, scale the mapped coordinates by the level's scale factor $s_\ell$, then compute the hash index [S1].
3. **Interpolation:** Perform trilinear interpolation within the hash-grid at level $\ell$ using the scaled coordinates and their integer indices [S1].
4. **Gradient Computation:** Compute positional gradients directly from the bilinear/trilinear interpolation weights into each hash-grid level [S1].
5. **MLP Processing:** Concatenate the interpolated features from all levels and pass them to the MLP [S1].
6. **Output:** Return the MLP output [S1].

**Pseudocode**
```python
import math

def map_positive(x):
    """Maps input x to handle negative integers for hash grid indexing."""
    return 2 * x - 1 if x > 0 else -2 * x

def concatenate(vectors):
    """Concatenates a list of feature vectors into a single vector."""
    result = []
    for vec in vectors:
        result.extend(vec)
    return result

def trilinear_interpolate(grid, scaled_coords):
    """Performs trilinear interpolation using scaled coordinates and grid lookup."""
    # Extract integer indices and fractional offsets
    indices = [int(math.floor(c)) for c in scaled_coords]
    frac = [c - math.floor(c) for c in scaled_coords]
    # Standard trilinear interpolation weights and lookup [G]
    # Returns interpolated feature vector
    return grid.lookup(indices, frac)

def trilinear_gradient(grid, scaled_coords):
    """Computes positional gradient directly from interpolation weights."""
    # Standard trilinear gradient computation using interpolation weights [G]
    # Returns gradient vector w.r.t. scaled_coords
    return grid.gradient(scaled_coords)

def unbounded_hash_grid_query(x_coords, hash_grids, scales):
    """Queries the unbounded hash grid for a given 3D position."""
    features = []
    mapped_coords = [map_positive(x) for x in x_coords]
    
    for level_idx, grid in enumerate(hash_grids):
        scale = scales[level_idx]
        scaled_coords = [c * scale for c in mapped_coords]
        value = trilinear_interpolate(grid, scaled_coords)
        features.append(value)
        
    return concatenate(features)

def compute_gradient(x_coords, hash_grids, scales):
    """Computes the gradient of the hash grid output w.r.t. input coordinates."""
    mapped_coords = [map_positive(x) for x in x_coords]
    grad_accum = [0.0, 0.0, 0.0]
    
    for level_idx, grid in enumerate(hash_grids):
        scale = scales[level_idx]
        scaled_coords = [c * scale for c in mapped_coords]
        level_grad = trilinear_gradient(grid, scaled_coords)
        # Chain rule: gradient w.r.t. original coords scales by level scale
        for i in range(3):
            grad_accum[i] += level_grad[i] * scale
            
    return grad_accum
```

**Parameters**
A default loss scale of 128 is used during the backward pass to reduce gradient underflow [S1]. The MLP omits bias terms, and combined with ReLU activations, this forces $G(\mathbf{0}) = \mathbf{0}$ [S1]. This property is intentionally preserved to match the linear approximation assumption in the derivation [S1].

**Edge Cases and Pitfalls**
The original hash function exhibits structured collisions over both positive and negative inputs, which the `MapPositive` function avoids [S1]. Without the loss scale of 128, gradient underflow may occur during optimization [S1]. The absence of bias in the MLP means the output is zero for zero input, which aligns with the linear approximation assumption [S1].

## Operating characteristics
Time complexity is not given in the sources. Memory usage reports 2 bytes for each Instant-NGP parameter and 4 bytes for all other parameters [S1]. The use of 16-bit floating-point numbers for the hash-grid and MLP leverages tensor core operations on recent NVIDIA GPUs, greatly accelerating the MLP pass [S1]. Strengths include support for unbounded input domains without space contraction, avoidance of structured collisions for negative coordinates, differentiable sample positions, and efficient GPU acceleration via FP16 [S1]. Limitations include reliance on the `tinycudann` library's bias-less MLP design and the requirement for FP32 gradient accumulation [S1]. When to use and when not to use are not given in the sources.

## Background
This method was introduced in the paper "Nexels: Neurally-Textured Surfels for Real-Time Novel View Synthesis with Sparse Primitives" [S1]. It modifies the Instant-NGP implementation to accept unbounded inputs, addressing the limitation that Instant-NGP assumes inputs $x \in [0, 1]^d$ [S1]. Later works often apply Instant-NGP to large-scale scenes by contracting space to this hypercube, but this method avoids contraction by modifying the hash-grid itself [S1].
