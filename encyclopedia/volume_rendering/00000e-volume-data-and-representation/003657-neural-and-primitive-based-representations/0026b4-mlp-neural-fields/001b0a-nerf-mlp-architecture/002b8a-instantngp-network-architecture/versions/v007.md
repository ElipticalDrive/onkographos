# InstantNGP Network Architecture

Also called: Instant Neural Graphics Primitives Network, InstantNGP MLP, MonoSDF Network, Network Architecture and Implementation

## Overview
InstantNGP is a neural field architecture designed for near-instantaneous training and rendering of neural radiance fields by replacing expensive positional encoding with a multiresolution hash grid [S1, unofficial]. It sets itself apart from the standard NeRF MLP Architecture by decoupling the feature extraction (hash grid) from the lightweight MLP, enabling training in seconds rather than hours [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D spatial coordinate $\mathbf{x} \in \mathbb{R}^3$ and viewing direction $\mathbf{d} \in \mathbb{R}^3$.
*   **Output:** Volume density $\sigma$ and view-dependent emitted color $\mathbf{c}$.

**Data Structures:**
The core data structure is a multiresolution hash grid.
*   **Hash Grid:** A collection of $L$ levels (resolutions). Each level $l$ consists of a hash table mapping integer indices to feature vectors.
*   **Hash Table:** Maps a hash index to a feature vector of dimension $F$ (typically 2 or 4).
*   **Feature Vector:** A dense vector of floating-point numbers.
*   **Hash Function:** A universal hash function (e.g., xxHash) maps the input coordinate to an integer index. The coordinate is first quantized to the grid resolution of level $l$, then hashed.

**Method Steps:**
1.  **Coordinate Quantization:** For each resolution level $l$ (from coarse to fine), the input coordinate $\mathbf{x}$ is scaled by the grid resolution $N_l$ and quantized to integer grid coordinates $\mathbf{g}_l = \lfloor N_l \cdot \mathbf{x} \rfloor$.
2.  **Hash Lookup:** For each level $l$, compute the hash index $h_l = \text{Hash}(\mathbf{g}_l)$. Retrieve the feature vector $\mathbf{f}_l$ from the hash table at index $h_l$. If the index is not yet populated, initialize it to zero or a small random value [G].
3.  **Bilinear Interpolation:** To ensure differentiability, perform trilinear interpolation of the features from the 8 surrounding grid vertices at level $l$. This yields a smoothed feature vector $\mathbf{f}'_l$ for each level.
4.  **Feature Concatenation:** Concatenate the interpolated feature vectors from all $L$ levels: $\mathbf{f}_{\text{total}} = [\mathbf{f}'_1; \mathbf{f}'_2; \dots; \mathbf{f}'_L]$. The total dimension is $L \times F$.
5.  **View Direction Encoding:** The viewing direction $\mathbf{d}$ is typically encoded using standard spherical harmonics or positional encoding, or passed directly if the MLP is small enough [S1, S2, unofficial]. In the baseline InstantNGP, $\mathbf{d}$ is often concatenated with the position features or processed by a separate small network.
6.  **MLP Forward Pass:** The concatenated feature vector $\mathbf{f}_{\text{total}}$ (and optionally $\mathbf{d}$) is passed through a small Multi-Layer Perceptron (MLP).
    *   **Density Network:** A small MLP (e.g., 2-4 layers) outputs the density $\sigma$.
    *   **Color Network:** A small MLP (e.g., 2 layers) outputs the color $\mathbf{c}$.
7.  **Activation:** ReLU is used for hidden layers. The density output is often passed through an exponential or softplus function to ensure positivity [G].

**Pseudocode:**
```python
import numpy as np

class InstantNGP:
    def __init__(self, num_levels=16, features_per_level=2, base_resolution=16, 
                 hash_size=2**19, mlp_hidden=256):
        self.num_levels = num_levels
        self.features_per_level = features_per_level
        self.base_resolution = base_resolution
        self.hash_size = hash_size
        self.mlp_hidden = mlp_hidden
        
        # Initialize hash grid: array of shape (hash_size, features_per_level)
        # Initialized to zeros [G]
        self.hash_grid = np.zeros((hash_size, features_per_level))
        
        # Initialize MLP weights [G]
        # Density MLP: 2 layers, hidden size mlp_hidden
        self.density_w1 = np.random.randn(features_per_level * num_levels, mlp_hidden)
        self.density_b1 = np.zeros(mlp_hidden)
        self.density_w2 = np.random.randn(mlp_hidden, 1)
        self.density_b2 = np.zeros(1)
        
        # Color MLP: 2 layers, hidden size mlp_hidden
        # Input includes features + view direction encoding [S1, unofficial]
        self.color_w1 = np.random.randn(features_per_level * num_levels + 8, mlp_hidden)
        self.color_b1 = np.zeros(mlp_hidden)
        self.color_w2 = np.random.randn(mlp_hidden, 3)
        self.color_b2 = np.zeros(3)

    def hash(self, x_int):
        # Simple hash function for demonstration [G]
        # In practice, use xxHash or similar
        return int(abs(hash(tuple(x_int))) % self.hash_size)

    def get_features(self, x):
        features = []
        for l in range(self.num_levels):
            resolution = self.base_resolution * (2 ** l)
            # Quantize coordinate
            x_quant = np.floor(x * resolution).astype(int)
            
            # Get 8 neighbors for trilinear interpolation
            neighbors = []
            for i in range(2):
                for j in range(2):
                    for k in range(2):
                        neighbor_coord = x_quant + np.array([i, j, k])
                        h_idx = self.hash(neighbor_coord)
                        neighbors.append(self.hash_grid[h_idx])
            
            # Trilinear interpolation weights
            # x_frac = x * resolution - x_quant
            # Weights w_ijk = (1 - dx)(1 - dy)(1 - dz) etc.
            # For brevity, assume a helper function interpolate_3d exists
            # which takes the 8 neighbor features and the fractional coordinates
            # and returns the interpolated feature vector.
            x_frac = x * resolution - x_quant
            f_l = interpolate_3d(neighbors, x_frac)
            features.append(f_l)
            
        return np.concatenate(features)

    def forward(self, x, d):
        # Encode view direction d using positional encoding [S1, unofficial]
        # Assuming 3 bands -> 6 dimensions + bias = 7, or similar
        d_enc = positional_encoding(d, num_bands=3)
        
        # Get hash features
        f_hash = self.get_features(x)
        
        # Concatenate hash features and view direction
        input_vec = np.concatenate([f_hash, d_enc])
        
        # Density Network
        h1 = np.maximum(0, input_vec @ self.density_w1 + self.density_b1) # ReLU
        sigma = np.exp(h1 @ self.density_w2 + self.density_b2) # Ensure positivity [G]
        
        # Color Network
        h1_c = np.maximum(0, input_vec @ self.color_w1 + self.color_b1) # ReLU
        color = np.tanh(h1_c @ self.color_w2 + self.color_b2) # Output color
        
        return sigma, color
```

**Parameters:**
*   **Hash Map Size:** $2^{19}$ (524,288) entries per level [S3].
*   **Number of Levels:** Typically 16 [S1, unofficial].
*   **Features per Level:** 2 or 4 [S1, unofficial].
*   **Base Resolution:** 16 [S1, unofficial].
*   **Optimizer:** Adam [S1, unofficial].
*   **Learning Rate:** Schedule from $10^{-2}$ to $10^{-4}$ [S1, unofficial].
*   **Iterations:** 20,000 [S1, unofficial].
*   **Occupancy Grid:** Used to skip empty space during training [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** With a finite hash table size, collisions occur. The hash function should be uniform to minimize structured collisions [S1, unofficial].
*   **Negative Coordinates:** Standard hash grids assume inputs in $[0, 1]^3$. Negative coordinates require specific handling or coordinate transformation [S13889].
*   **Precision:** Floating-point precision in hash lookups and interpolation can affect gradient quality [S1, unofficial].

## Subtopics

### [iNGP Texture Storage](5826-ingp-texture-storage.md)
This method replaces hash-table-based feature storage with explicit 3D grid and triplane textures to leverage hardware-accelerated memory locality and bilinear interpolation. It reduces the number of texture fetches per neural network evaluation by storing presummed multi-resolution features, enabling a 3× reduction in fetch overhead compared to the original InstantNGP approach.

### [Tiny MLP for Density and Color Estimation](8555-tiny-mlp-for-density-and-color-estimation.md)
The Tiny MLP is a lightweight neural network component used in Rip-NeRF to estimate the density $\tau$ and view-dependent color $c$ of a sampled sphere $S$. It builds on [InstantNGP Network Architecture](5049-instantngp-network-architecture.md) by mapping the Ripmap-Encoding feature vector $f$ and the encoded view direction $d$ to radiance properties. It sets itself apart from sibling methods like [iNGP Texture Storage](5826-ingp-texture-storage.md) by using a dedicated small MLP for density/color prediction rather than relying solely on texture lookups for these specific outputs, and differs from [HyperINR](10461-hyperinr.md) by using a fixed-width MLP with specific activation constraints rather than hypernetworks.

### HyperINR
HyperINR is a method for instantiating Neural Implicit Representations (INRs) for specific scene parameters by predicting the network weights directly, thereby bypassing per-volume optimization [S1, unofficial]. It solves the latency bottleneck of training or optimizing an INR for every new parameter set by using a hypernetwork conditioned on those parameters [S1, unofficial]. It sets itself apart from standard NeRF-like approaches by generating a compact INR for any query parameter in 0.07–0.28 ms, achieving 100× the inference bandwidth of the teacher model it distills from [S1, unofficial].

### [Hybrid Fourier-Hash Encoding](13021-hybrid-fourier-hash-encoding.md)
Hybrid Fourier-Hash Encoding is a neural geometry representation technique that combines low-dimensional Fourier positional encoding with learnable multi-scale hash features to improve the continuity of the signed distance function (SDF) and satisfy eikonal constraints. It addresses the non-smooth solutions and poor gradient continuity produced by hash encoding alone, which arises from the discontinuous nature of features on discrete grids. Unlike the baseline InstantNGP architecture which uses only hash encoding, this method decouples geometry from appearance by extracting features from an intermediate connected layer, ensuring hash encoding encodes only geometry.

### [Unbounded Hash-Grid with Negative Integer Mapping](13889-unbounded-hash-grid-with-negative-integer-mapping.md)
This method extends the Instant-NGP hash-grid encoding to support unbounded input domains by modifying the hash function to handle negative integers without structured collisions. It solves the problem of applying neural field representations, originally designed for normalized $[0, 1]^d$ inputs, to large-scale scenes with arbitrary coordinate ranges. It differs from its parent [InstantNGP Network Architecture](5049-instantngp-network-architecture.md) by replacing the bounded hash lookup with a negative-integer-aware mapping and by computing positional gradients directly from interpolation weights rather than assuming non-differentiable sample positions.

#### Flash Cache Implementation
*   **NGP Resolution:** Maximum grid resolution for the fast cache NGP is 256 [S3].
*   **MLP Architecture:** The fast cache NGP uses a 4-layer MLP with 128 hidden units [S3].
*   **S:** The number of sample-point distances predicted by the fast cache is 8 [S3].
*   **Hash Map Size:** Size of the hash maps for all NGPs is $2^{19}$ [S3].

#### Upsampling Activations
*   **Definition:** An extension that reduces processing time by computing intermediate network activations at a lower resolution and upsampling them to full resolution before density proposal [S4].
*   **Steps:** Record intermediate activations $A^{(\ell)}$ at a reduced resolution of $w/2 \times h/2 \times N/2 \times c \times N_h$. Upsample the reduced-resolution activations to full resolution using nearest neighbor interpolation [S4].
*   **Parameters:** Layer index $\ell$: Best performance is observed at $\ell = 1$ [S4]. Function configuration $f_2$: The specific activation/weight configuration that performed best in experiments for Blender and LLFF datasets [S4].
*   **Performance:** On the Blender dataset with $\ell=1$ and $f_2$, the method achieves PSNR 23.69, SSIM 0.704, LPIPS 0.267 with a 44% speedup over the baseline [S4].
*   **Comparison:** Differs from full-resolution activation extraction by trading negligible visual quality loss for significant speedup, whereas DONeRF filters along depth and neighboring rays for smoothing [S4].
*   **Usage:** Applied to NeRF and Mip-NeRF architectures on Blender and LLFF datasets to reduce processing time [S4].

#### INGP-NeRF
*   **Parameters:** Maximum time step $T$ set to 8. Initial target time step $t^*$ initialized to 7 after pretraining [S5, unofficial].
*   **Layout:** INGP-NeRF backbone uses a multiresolution hash-grid representation followed by lightweight density and color networks. Density network: 1 hidden layer, 128 units. Color network: 2 hidden layers, 128 units. Nonlinear activations are replaced with PLIF neurons. Output PLIF layers accumulate temporal estimates of density $\sigma$ and color $\mathbf{c}$ [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** Training is significantly faster than standard NeRF, often completing in seconds to minutes for moderate scenes [S1, unofficial]. Rendering is also accelerated due to the efficient hash grid lookups and small MLPs.
*   **Memory Complexity:** Memory usage is dominated by the hash grid. With $L$ levels, hash size $H$, and features $F$, memory is approximately $L \times H \times F \times 4$ bytes. For $L=16, H=2^{19}, F=2$, this is roughly 128 MB [S3].
*   **Measured Performance:** Trained with Adam optimizer, learning rate schedule $10^{-2} \to 10^{-4}$, 20k iterations, utilizing an occupancy grid [S1, unofficial].
*   **Strengths:** Extremely fast training and rendering; suitable for interactive applications and rapid prototyping [S1, unofficial].
*   **Limitations:** May suffer from lower visual quality compared to high-resolution tensor-based methods or large MLPs due to limited capacity and hash collisions [S1, unofficial]. Not ideal for very high-fidelity static scenes where training time is not a constraint.
*   **When to Use:** When training speed and rendering latency are critical, such as in real-time applications or large-scale scene capture [S1, unofficial].
*   **When Not to Use:** When maximum possible visual fidelity is required and training time is not a constraint [S1, unofficial].

## Background
InstantNGP was introduced as a method for near-instantaneous training and rendering of neural radiance fields [S1, unofficial]. It employs a multiresolution hash grid combined with a tiny MLP for fast training and rendering [S1, unofficial]. The architecture has become a baseline for many subsequent methods, including MonoSDF, which uses InstantNGP to encode input position information for its SDF, bias, and color networks [S2, unofficial]. It is part of the "Instant Neural Graphics Primitives" family, which aims to make neural graphics accessible and fast [S1, unofficial].
