# InstantNGP Network Architecture

Also called: Instant Neural Graphics Primitives Network, InstantNGP MLP, MonoSDF Network, Network Architecture and Implementation

## Overview
This article describes the specific Multi-Layer Perceptron (MLP) architecture and encoding pipeline used in InstantNGP and its derivatives (such as MonoSDF and Flash Cache) to accelerate neural volume rendering. It solves the computational bottleneck of evaluating dense MLPs for every ray sample by replacing the standard positional encoding with a sparse, multi-resolution hash grid feature storage mechanism [S1, unofficial][S2]. Unlike the base [NeRF MLP Architecture](910-nerf-mlp-architecture.md) which relies on sinusoidal positional encoding, this method maps input coordinates to learnable feature vectors stored in hash tables, enabling significantly faster training and inference on commodity hardware [S1, unofficial][S2].

## How it works

### Inputs and Outputs
*   **Inputs:** 3D spatial coordinates $\mathbf{x} \in \mathbb{R}^3$ and, for color networks, viewing direction $\mathbf{d} \in \mathbb{R}^3$.
*   **Outputs:** Volume density $\sigma$ (or signed distance field $SDF$) and view-dependent color $\mathbf{c}$.

### Data Structures

#### Hash Grid Feature Storage
The core data structure is a set of hash tables, one for each resolution level $l \in \{0, \dots, L-1\}$.
*   **Hash Table $H_l$:** Maps a 3D coordinate to a feature vector.
*   **Hash Function:** A standard hash function (e.g., CRC32 or similar) maps the integer-rounded coordinate to an index in the table.
*   **Table Size:** The number of entries $T$ is a hyperparameter. Typical value: $2^{19}$ [S2].
*   **Feature Vector Dimension:** The dimension $F$ of the feature vector stored at each entry. Not given in the sources for the base InstantNGP, but implied by the MLP input size.
*   **Resolution:** Each level $l$ corresponds to a grid resolution $R_l$. The maximum resolution is a hyperparameter. Typical value: $2048$ for appearance, $256$ for fast cache [S2].

#### MLP Architectures
The architecture varies by variant. The base configuration described in [S1, unofficial] consists of three distinct networks:
1.  **Base SDF Network:** 4-layer MLP.
2.  **Bias Network:** 2-layer MLP.
3.  **Color Network:** 2-layer MLP.

### Numbered Steps

1.  **Coordinate Hashing:** For a given 3D position $\mathbf{x}$, compute the hash index for each resolution level $l$.
    $$ \text{index}_l = \text{Hash}(\lfloor \mathbf{x} \cdot R_l \rfloor) \pmod T $$
    where $R_l$ is the resolution scale for level $l$, and $T$ is the hash table size [S2].

2.  **Feature Lookup:** Retrieve the feature vectors $\mathbf{v}_l$ from the hash tables $H_l$ using $\text{index}_l$.
    $$ \mathbf{v}_l = H_l[\text{index}_l] $$

3.  **Interpolation (Optional/Implicit):** In standard InstantNGP, bilinear interpolation is performed on the grid features before hashing or after lookup to ensure smoothness. The sources for [S1, unofficial] and [S2] do not explicitly detail the interpolation step in the text, but [S1, unofficial] cites InstantNGP [20] which uses it. [G] Standard InstantNGP implementation performs trilinear interpolation on the 8 neighboring grid points of the fractional coordinate before hashing, or hashes the integer coordinate and interpolates the resulting features. For the purpose of this text, we assume the features $\mathbf{v}_l$ are the interpolated features fed into the MLP.

4.  **Feature Concatenation:** Concatenate the feature vectors from all resolution levels.
    $$ \mathbf{f}_{\text{pos}} = [\mathbf{v}_0; \mathbf{v}_1; \dots; \mathbf{v}_{L-1}] $$

5.  **View Direction Encoding (Color Network Only):**
    *   If the network predicts color, the viewing direction $\mathbf{d}$ is also encoded.
    *   [S1, unofficial] states that InstantNGP is used to encode input position information. It does not explicitly detail the direction encoding for the color network in the provided text, but standard InstantNGP uses a separate hash grid or spherical harmonics for direction. [G] Standard practice is to use a separate hash grid for direction or a fixed number of spherical harmonic bases. The provided notes for [S1, unofficial] do not specify the direction encoding method, only that InstantNGP is used for position. We assume the direction is either hashed similarly or processed via a separate small MLP.

6.  **MLP Evaluation:**
    *   **Base SDF Network:** Input $\mathbf{f}_{\text{pos}}$. Output $\sigma$ or $SDF$.
        *   Structure: 4 layers, 256 hidden units [S1, unofficial].
        *   Activation: ReLU [S3] (noting that removing ReLU causes artifacts).
    *   **Bias Network:** Input $\mathbf{f}_{\text{pos}}$. Output bias term.
        *   Structure: 2 layers, similar scale (implied 256 hidden units) [S1, unofficial].
    *   **Color Network:** Input $[\mathbf{f}_{\text{pos}}; \mathbf{f}_{\text{dir}}]$. Output $\mathbf{c}$.
        *   Structure: 2 layers, 128 hidden units [S1, unofficial].

### Pseudocode

```python
import numpy as np

class InstantNGPNetwork:
    def __init__(self, hash_table_size=2**19, resolutions=[2048, 1024, 512, 256, 128, 64, 32, 16], 
                 sdf_hidden=256, color_hidden=128, feature_dim=2):
        """
        Initialize the InstantNGP network.
        :param hash_table_size: Size of the hash tables T.
        :param resolutions: List of grid resolutions R_l for each level.
        :param sdf_hidden: Number of hidden units in SDF MLP.
        :param color_hidden: Number of hidden units in Color MLP.
        :param feature_dim: Dimension of feature vectors stored in hash tables.
        """
        self.T = hash_table_size
        self.resolutions = resolutions
        self.num_levels = len(resolutions)
        self.feature_dim = feature_dim
        
        # Initialize hash tables with random features
        # H[l] is a 2D array of shape (T, feature_dim)
        self.hash_tables = [np.random.randn(self.T, self.feature_dim).astype(np.float32) for _ in range(self.num_levels)]
        
        # Initialize MLP weights
        # SDF Network: 4 layers, 256 hidden
        self.sdf_weights = [
            np.random.randn(self.num_levels * self.feature_dim, sdf_hidden).astype(np.float32),
            np.random.randn(sdf_hidden, sdf_hidden).astype(np.float32),
            np.random.randn(sdf_hidden, sdf_hidden).astype(np.float32),
            np.random.randn(sdf_hidden, 1).astype(np.float32) # Output sigma or SDF
        ]
        self.sdf_biases = [np.zeros(sdf_hidden).astype(np.float32) for _ in range(3)] + [np.zeros(1).astype(np.float32)]
        
        # Color Network: 2 layers, 128 hidden
        # Input: pos features + dir features (assuming dir features also from hash or fixed dim)
        # Note: [S1, unofficial] does not specify dir encoding. We assume a separate hash or fixed dim for dir.
        # For simplicity, we assume dir features are concatenated with pos features.
        # Let's assume dir features have the same dimension as pos features per level, or a fixed dim.
        # Standard InstantNGP uses a separate hash for direction. We will assume a separate set of hash tables for direction.
        self.dir_hash_tables = [np.random.randn(self.T, self.feature_dim).astype(np.float32) for _ in range(self.num_levels)]
        
        self.color_weights = [
            np.random.randn(self.num_levels * self.feature_dim * 2, color_hidden).astype(np.float32), # *2 for pos and dir
            np.random.randn(color_hidden, color_hidden).astype(np.float32),
            np.random.randn(color_hidden, 3).astype(np.float32) # Output RGB
        ]
        self.color_biases = [np.zeros(color_hidden).astype(np.float32) for _ in range(1)] + [np.zeros(3).astype(np.float32)]

    def hash(self, coord, resolution):
        """Hash a 3D coordinate to an index in the hash table."""
        # Integer coordinate
        int_coord = np.floor(coord * resolution).astype(np.int32)
        # Simple hash function (e.g., CRC32 or similar)
        # Using a simple polynomial hash for demonstration
        h = 0
        for c in int_coord:
            h = (h * 31 + c) % self.T
        return h

    def get_features(self, pos, dir=None):
        """
        Get hashed features for position and optionally direction.
        :param pos: 3D position (3,)
        :param dir: 3D direction (3,)
        :return: Concatenated feature vector
        """
        pos_features = []
        for l, res in enumerate(self.resolutions):
            idx = self.hash(pos, res)
            pos_features.append(self.hash_tables[l][idx])
        
        # Interpolation is typically done here in full InstantNGP.
        # For this simplified version, we assume the features are already interpolated or we use nearest neighbor.
        # [G] Standard InstantNGP uses trilinear interpolation. We will skip it for brevity as it's not detailed in sources.
        
        pos_feat_vec = np.concatenate(pos_features)
        
        if dir is not None:
            dir_features = []
            for l, res in enumerate(self.resolutions):
                idx = self.hash(dir, res)
                dir_features.append(self.dir_hash_tables[l][idx])
            dir_feat_vec = np.concatenate(dir_features)
            return np.concatenate([pos_feat_vec, dir_feat_vec])
        else:
            return pos_feat_vec

    def relu(self, x):
        return np.maximum(0, x)

    def forward_sdf(self, pos):
        """Forward pass for SDF network."""
        x = self.get_features(pos)
        for i in range(3):
            x = self.relu(np.dot(x, self.sdf_weights[i]) + self.sdf_biases[i])
        sigma = np.dot(x, self.sdf_weights[3]) + self.sdf_biases[3]
        return sigma

    def forward_color(self, pos, dir):
        """Forward pass for Color network."""
        x = self.get_features(pos, dir)
        for i in range(1):
            x = self.relu(np.dot(x, self.color_weights[i]) + self.color_biases[i])
        color = np.dot(x, self.color_weights[2]) + self.color_biases[2]
        return color

    def forward(self, pos, dir=None):
        """
        Forward pass for the entire network.
        :param pos: 3D position
        :param dir: 3D direction (optional)
        :return: sigma (or SDF), color (if dir provided)
        """
        sigma = self.forward_sdf(pos)
        if dir is not None:
            color = self.forward_color(pos, dir)
            return sigma, color
        else:
            return sigma
```

### Parameters with Typical Values
*   **Hash Table Size ($T$):** $2^{19}$ [S2].
*   **Maximum Grid Resolution:** $2048$ for appearance, $256$ for fast cache [S2].
*   **SDF MLP Layers:** 4 layers [S1, unofficial].
*   **SDF MLP Hidden Units:** 256 [S1, unofficial].
*   **Color MLP Layers:** 2 layers [S1, unofficial].
*   **Color MLP Hidden Units:** 128 [S1, unofficial].
*   **Bias MLP Layers:** 2 layers [S1, unofficial].
*   **Point Cloud Size:** Downsampled to 2 million points for experiments [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision:** Hash collisions can occur if the table size is too small. The sources specify $2^{19}$ to mitigate this [S2].
*   **Boundaries:** The hash function maps coordinates to indices. Coordinates outside the defined grid bounds should be handled (e.g., clamped or ignored). Not given in the sources.
*   **Degenerate Input:** Empty scenes or zero-length rays. Not given in the sources.
*   **ReLU Usage:** Removing ReLU from the network leads to more artifacts, particularly around sharp edges, causing a drop in image metrics [S3].

## Subtopics

### [iNGP Texture Storage](5826-ingp-texture-storage.md)
This method replaces hash-table-based feature storage with explicit 3D grid and triplane textures to leverage hardware-accelerated memory locality and bilinear interpolation. It reduces the number of texture fetches per neural network evaluation by storing presummed multi-resolution features, enabling a 3× reduction in fetch overhead compared to the original InstantNGP approach. Choose this when hardware acceleration for texture lookups is preferred over hash table management. Link: [iNGP Texture Storage](5826-ingp-texture-storage.md).

### [Tiny MLP for Density and Color Estimation](8555-tiny-mlp-for-density-and-color-estimation.md)
The Tiny MLP is a lightweight neural network component used in Rip-NeRF to estimate the density $\tau$ and view-dependent color $c$ of a sampled sphere $S$. It builds on [InstantNGP Network Architecture](5049-instantngp-network-architecture.md) by mapping the Ripmap-Encoding feature vector $f$ and the encoded view direction $d$ to radiance properties. It sets itself apart from sibling methods like [iNGP Texture Storage](5826-ingp-texture-storage.md) by using a dedicated small MLP for density/color prediction rather than relying solely on texture lookups for these specific outputs, and differs from [HyperINR](10461-hyperinr.md) by using a fixed-width MLP with specific activation constraints rather than hypernetworks. Choose this for lightweight, real-time density/color estimation in specific sampling contexts. Link: [Tiny MLP for Density and Color Estimation](8555-tiny-mlp-for-density-and-color-estimation.md).

### [HyperINR](10461-hyperinr.md)
HyperINR is a method for instantiating Neural Implicit Representations (INRs) for specific scene parameters by predicting the network weights directly, thereby bypassing per-volume optimization. It solves the latency bottleneck of training or optimizing an INR for every new parameter set by using a hypernetwork conditioned on those parameters. It sets itself apart from standard NeRF-like approaches by generating a compact INR for any query parameter in 0.07–0.28 ms, achieving 100× the inference bandwidth of the teacher model it distills from. Choose this when instantiating INRs for many different scene parameters is required without per-scene optimization. Link: [HyperINR](10461-hyperinr.md).

### Flash Cache Implementation
A variant of the InstantNGP architecture used in Flash Cache for inverse rendering. It uses a fast cache NGP with a maximum grid resolution of 256 and a 4-layer 128-hidden-unit MLP to predict $S=8$ sample-point distances [S2]. The hash maps for all NGPs have size $2^{19}$ [S2]. This variant is optimized for predicting sample-point distances in a radiance cache context.

### Upsampling Activations
An extension that reduces processing time by computing intermediate network activations at a lower resolution and upsampling them to full resolution before density proposal [S3]. It records activations $A^{(\ell)}$ at a reduced resolution of $w/2 \times h/2 \times N_c/2 \times N_h$, then upsamples using nearest neighbor interpolation [S3]. The best performance is observed at layer index $\ell=1$ with function configuration $f2$ [S3]. On the Blender dataset, this achieves PSNR 23.69, SSIM 0.704, LPIPS 0.267 with a 44% speedup over the baseline [S3]. It differs from full-resolution activation extraction by trading negligible visual quality loss for significant speedup, whereas DONeRF filters along depth and neighboring rays for smoothing [S3]. Applied to NeRF and Mip-NeRF architectures on Blender and LLFF datasets [S3].

## Operating characteristics

### Time and Memory Complexity
*   **Time Complexity:** The hash-based lookup is $O(1)$ per resolution level, making the encoding step significantly faster than sinusoidal positional encoding for high-dimensional inputs. The MLP evaluation is $O(L \cdot F \cdot H)$, where $L$ is the number of levels, $F$ is the feature dimension, and $H$ is the hidden size.
*   **Memory Complexity:** $O(T \cdot F \cdot L)$, where $T$ is the hash table size, $F$ is the feature dimension, and $L$ is the number of resolution levels. For $T=2^{19}$ and $L=8$, this is substantial but fits in modern GPU memory.

### Measured Performance
*   **Flash Cache:** Uses a 4-layer 128-hidden-unit MLP with max resolution 256 for the fast cache [S2].
*   **Upsampling Activations:** Achieves a 44% speedup on the Blender dataset with negligible quality loss [S3].

### Strengths and Limitations
*   **Strengths:** Fast training and inference due to efficient feature storage and lookup. Scalable to large scenes via multi-resolution grids.
*   **Limitations:** Hash collisions can affect quality if $T$ is too small. Memory usage can be high for large $T$ and $L$. Not given in the sources for specific hardware benchmarks beyond the speedup percentages.

### When to Use
*   Use when real-time or fast training of neural radiance fields is required.
*   Use when the scene is large and requires multi-resolution representation.
*   Do not use when exact analytical gradients are required without approximation, or when memory is extremely constrained.

## Background

### Origin
The InstantNGP architecture was introduced in the paper "Instant Neural Graphics Primitives with a Multiresolution Hash Encoding" by Müller et al. [S1, unofficial][S2]. It was designed to address the slow training times of NeRF by introducing a sparse, multi-resolution hash encoding.

### History and Development
The method has been adopted and extended in various works, such as MonoSDF [S1, unofficial], Flash Cache [S2], and Analyzing the Internals of Neural Radiance Fields [S3]. MonoSDF uses the InstantNGP encoding for position information in a point-guided neural implicit surface reconstruction framework [S1, unofficial]. Flash Cache uses a variant of the InstantNGP architecture for a fast radiance cache in inverse rendering [S2]. The Upsampling Activations extension was proposed to further speed up density proposal in NeRF [S3].

### Usage
The InstantNGP architecture is widely used in modern neural rendering frameworks for its efficiency. It is a key component in many state-of-the-art NeRF variants.
