# Unbounded Hash-Grid with Negative Integer Mapping

Also called: Instant-NGP Unbounded Hash Grid, Negative Integer Mapping for Hash Grids

## Overview
This method extends the Instant-NGP hash-grid encoding to support unbounded input domains by modifying the hash function to handle negative integers without structured collisions [S1]. It solves the problem of applying neural field representations, originally designed for normalized $[0, 1]^d$ inputs, to large-scale scenes with arbitrary coordinate ranges [S1]. It differs from its parent [InstantNGP Network Architecture](5049-instantngp-network-architecture.md) by replacing the bounded hash lookup with a negative-integer-aware mapping and by computing positional gradients directly from interpolation weights rather than assuming non-differentiable sample positions [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D position vector $\mathbf{x} \in \mathbb{R}^3$.
*   **Output:** A feature vector resulting from trilinear interpolation across multiple hash-grid levels.

**Data Structures**
*   **Hash-Grid Levels:** Multiple levels $\ell$ are used, including coarse levels. Unlike the original Instant-NGP which may use traditional grids for coarse levels, this method uses hash-grids for all levels to maintain consistency in the unbounded domain [S1].
*   **Storage Layout:** Parameters stored in the hash-grid use 2 bytes (16-bit) each [S1].
*   **Precision:** The hash-grid and the subsequent MLP use 16-bit floating-point numbers (FP16) [S1]. Gradients are accumulated in 32-bit floating-point (FP32) tensors [S1].

**Mapping Function**
The core modification is a mapping function `MapPositive(x)` applied to each coordinate component $x$ before hashing. This ensures negative integers map to distinct hash indices, avoiding the structured collisions present in the original hash function when evaluated over positive and negative domains [S1].

The mapping is defined as:
$$
\text{MapPositive}(x) = 
\begin{cases} 
2x - 1 & \text{if } x > 0 \\
-2x & \text{otherwise}
\end{cases}
$$

**Algorithm Steps**
1.  **Coordinate Mapping:** For each component $x_i$ of the input position $\mathbf{x}$, apply `MapPositive(x_i)`. This transforms the unbounded real input into a domain suitable for the hash function [S1].
2.  **Hashing:** For each hash-grid level $\ell$, compute the hash index using the mapped coordinates. The original Instant-NGP hash function is applied to these mapped integer coordinates [S1].
3.  **Interpolation:** Perform trilinear interpolation within the hash-grid at level $\ell$ using the mapped coordinates. This yields the interpolated feature value for that level [S1].
4.  **Gradient Computation:** Compute the positional gradient directly from the bilinear/trilinear interpolation weights into each hash-grid level. This makes the sample positions differentiable, unlike prior work that assumed non-differentiable positions [S1].
5.  **MLP Processing:** Pass the concatenated features from all levels into the Tiny MLP. The MLP uses ReLU activations and omits bias terms [S1].
6.  **Output:** Return the MLP output.

**Parameters**
*   **Loss Scale:** A default loss scale of 128 is used during the backward pass to reduce gradient underflow [S1].
*   **MLP Bias:** The MLP omits bias terms. Combined with ReLU activations, this forces $G(\mathbf{0}) = \mathbf{0}$ [S1]. This property is intentionally preserved to match the linear approximation assumption in the derivation [S1].

**Edge Cases and Pitfalls**
*   **Structured Collisions:** The original hash function exhibits structured collisions over both positive and negative inputs. The `MapPositive` function is required to avoid this [S1].
*   **Gradient Underflow:** Without the loss scale of 128, gradient underflow may occur during optimization [S1].
*   **MLP Zero-Input:** The absence of bias in the MLP means the output is zero for zero input. This is a feature, not a bug, as it aligns with the linear approximation assumption [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Nexels storage memory uses 2 bytes for each Instant-NGP parameter and 4 bytes for all other parameters [S1].
*   **Performance:** The use of 16-bit floating point numbers for the hash-grid and MLP leverages tensor core operations on recent NVIDIA GPUs, greatly accelerating the MLP pass [S1].
*   **Strengths:** Supports unbounded input domains without space contraction; avoids structured collisions for negative coordinates; differentiable sample positions; efficient GPU acceleration via FP16.
*   **Limitations:** Relies on the `tinycudann` library's MLP implementation (no bias); requires careful handling of gradient accumulation in FP32 [S1].
*   **When to use:** When rendering large-scale scenes with arbitrary coordinate ranges using neural fields, and when avoiding the artifacts associated with space contraction or bounded hash grids.
*   **When not to use:** When memory is extremely constrained and the scene fits within a bounded domain where standard Instant-NGP suffices.

## Background
This method was introduced in the paper "Nexels: Neurally-Textured Surfels for Real-Time Novel View Synthesis with Sparse Primitives" by Loop, Nowrouzezahrai, Jacobson, McGuire, and Fidler, published in the IEEE/CVF Conf. Comput. Vis. Pattern Recognit. (CVPR) in 2021 [S1]. It modifies the Instant-NGP implementation [36] to accept unbounded inputs, addressing the limitation that Instant-NGP assumes inputs $x \in [0, 1]^d$ [S1]. Later works often apply Instant-NGP to large-scale scenes by contracting space to this hypercube [3, 4, 59], but this method avoids contraction by modifying the hash-grid itself [S1].
