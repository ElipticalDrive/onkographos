# iNGP Texture Storage
Also called: Texture Storage for Real-Time Rendering, iNGP Texture Storage for Real-Time Rendering
## Overview
This method replaces hash-table-based feature storage with explicit 3D grid and triplane textures to leverage hardware-accelerated memory locality and texture interpolation [S1]. It reduces the number of texture fetches per neural network evaluation by storing presummed multi-resolution features, enabling a 3× reduction in fetch overhead compared to the original InstantNGP approach [S1].
## How it works
**Inputs and Outputs:**
- Input: Multi-resolution feature grids (3D) and triplanes (2D) optimized during training.
- Output: Anti-aliased feature vectors for a given 3D sample point $x$ at render time.

**Data Structures:**
- **Feature Grids/Triplanes:** Explicit 3D or 2D arrays of floating-point values stored as textures in GPU memory instead of hash tables [S1].
- **Presummed Features:** For each resolution level $L$, the stored value $g'(v)$ is the cumulative sum of features from level $0$ to $L$:
  $$g'(v) = \sum_{l=0}^{L} g(v, l)$$
  where $g(v, l)$ is the feature at location $v$ and resolution level $l$ [S1].

**Algorithm:**
1. **Training Phase:** Optimize the multi-resolution feature grids and triplanes, summing features across levels to form the presummed features $g'$ stored in texture memory [S1].
2. **Render-Time Level Selection:** For a sample point $x$, determine two adjacent resolution levels implied by the pixel area $p(x)$ [S1].
3. **Texture Fetch:** Retrieve the presummed feature vectors from both selected levels using hardware-accelerated interpolation (trilinear for 3D grids, bilinear for triplanes) [S1].
4. **Anti-Aliasing Interpolation:** Interpolate between the two fetched feature vectors based on $p(x)$ to produce the final anti-aliased feature input for the MLP [S1].

**Parameters:**
- **Resolution Levels:** The number of levels depends on the scene complexity and desired quality. In the cited implementation, seven triplane levels and three 3D grids were used [S1].
- **Pixel Area Threshold:** Determines which two resolution levels to interpolate between based on $p(x)$ [S1].

**Edge Cases and Pitfalls:**
- **Memory Locality:** Explicit textures improve locality over hash tables but require careful management of texture memory size for high-resolution grids [S1].
- **Interpolation Artifacts:** Hardware interpolation may introduce slight blurring compared to nearest-neighbor hash lookups, mitigated by the multi-resolution presummed storage design [S1].

## Subtopics

### [CAwa-NeRF](11288-cawa-nerf.md)
A method for instant learning of compression-aware NeRF features that applies an entropy-aware training scheme with a rate-distortion trade-off to learn low entropy features, allowing export of zip-compressed feature grids with negligible overhead without changing the storage architecture or parameters of the base INGP method.

## Operating characteristics
- **Time Complexity:** The number of texture fetches per MLP evaluation is reduced to 8, compared to 24 (3+3×7) in the original hash-table-based InstantNGP approach, representing a 3× reduction [S1].
- **Memory Complexity:** Uses explicit 3D grids and triplanes, which have a fixed memory footprint based on resolution, unlike hash tables which can have variable overhead [S1].
- **Performance:** Benefits from hardware-accelerated texture interpolation and improved memory locality [S1].
- **Strengths:** Reduced fetch overhead, better memory locality, suitability for real-time rendering [S1].
- **Limitations:** Fixed memory usage, potential for interpolation artifacts if not carefully tuned [S1].
## Background
This method is described in the HybridNeRF paper, which introduces efficient neural rendering via adaptive volumetric surfaces [S1]. It was introduced to optimize real-time rendering performance by leveraging explicit grid structures instead of hash tables [S1].
