# View-Conditioned Rendering

Also called: View Conditioning, View-Dependent Rendering Setup, View-dependent RGB decoding

## Overview
View-Conditioned Rendering is a technique used in neural volume rendering to model view-dependent appearance effects, such as specularities, by conditioning the RGB decoder network on the camera viewpoint [S1]. It solves the problem where non-view-conditioned models incorrectly reconstruct extra semi-transparent voxels near the surface to explain angular variations in color [S1]. It sets itself apart from standard view-independent MLPs by explicitly appending encoded view directions to the positional encoding of 3D coordinates before the network query, allowing the network to change the color of certain parts of the scene depending on the viewing angle [S2, unofficial].

## How it works
**Inputs and Outputs:**
* **Input:** 3D spatial coordinates $\mathbf{x}$, normalized view direction $\mathbf{v}$, and positional encoding functions $PE_{xyz}(\cdot)$ and $PE_{dir}(\cdot)$ [S2, unofficial].
* **Output:** RGB color value $\mathbf{c}$ and opacity $\alpha$ [S1].

**Data Structures:**
* **Positional Encoding:** Standard Fourier features or hash grid encoding for 3D coordinates [S2, unofficial].
* **View Direction Encoding:** Separate positional encoding for the 3D normalized vector of the view direction [S2, unofficial].
* **Decoder Architecture:** A Multi-Layer Perceptron (MLP) or convolutional branch structure [S1]. The architecture uses separate branches to produce RGB values and $\alpha$ values, conditioning only the RGB branch on the viewpoint [S1].

**Steps:**
1. Check `use_viewdirs` flag to determine if view conditioning is enabled [S2, unofficial].
2. Encode spatial coordinates $\mathbf{x}$ using $PE_{xyz}$ to obtain $\mathbf{z}_{xyz}$ [S2, unofficial].
3. If `use_viewdirs` is true, encode the normalized view direction $\mathbf{v}$ using $PE_{dir}$ to obtain $\mathbf{z}_{dir}$ [S2, unofficial].
4. Concatenate the encoded spatial features and encoded view direction features: $\mathbf{z}_{combined} = \text{concat}(\mathbf{z}_{xyz}, \mathbf{z}_{dir})$ [S2, unofficial].
5. Pass $\mathbf{z}_{combined}$ to the RGB decoder network $V_{rgb}$ to predict color $\mathbf{c}$ [S1].
6. Pass $\mathbf{z}_{xyz}$ to the $\alpha$ decoder network $V_{\alpha}$ to predict opacity $\alpha$ [S1]. The $\alpha$ branch does not receive the view direction input [S1].

**Pseudocode:**
```python
def view_conditioned_render(x, v, use_viewdirs, embed_fn, embeddirs_fn, rgb_network, alpha_network):
    """
    x: 3D coordinates [B, 3]
    v: Normalized view direction [B, 3]
    use_viewdirs: Boolean flag
    embed_fn: Function to encode 3D coordinates
    embeddirs_fn: Function to encode view directions
    rgb_network: MLP/conv branch for RGB
    alpha_network: MLP/conv branch for alpha
    """
    embedded_xyz = embed_fn(x)
    if use_viewdirs:
        embedded_dirs = embeddirs_fn(v)
        embedded = np.concatenate([embedded_xyz, embedded_dirs], axis=-1)
        rgb = rgb_network(embedded)
    else:
        rgb = rgb_network(embedded_xyz)
    alpha = alpha_network(embedded_xyz)
    return rgb, alpha
```

**Parameters:**
* `use_viewdirs`: Boolean flag to enable full 5D input (3D pos + 2D dir) instead of 3D [S2, unofficial].
* `input_ch_views`: Number of channels for view direction encoding (e.g., 3 for raw vector, or higher for Fourier features) [S2, unofficial].

**Edge Cases and Pitfalls:**
* **Precision:** View directions must be normalized to unit length before encoding to ensure consistent magnitude in the positional encoding space [S1].
* **Degenerate Input:** If the view direction is zero (camera at origin with no direction), normalization fails. Guard against division by zero in normalization [G].
* **Overfitting:** Without sufficient data, view conditioning may overfit to specific viewpoints, causing artifacts in novel views [S1].

## Subtopics

### [View-Dependent Feature MLP](13159-view-dependent-feature-mlp.md)
Computes view-dependent features by taking semantic features and relative view changes as inputs to model effects like lighting and view direction. It sets itself apart from its siblings by explicitly encoding the change in viewpoint between an input view and a target view, rather than just conditioning on the absolute camera pose, ensuring geometric consistency across views.

### [View-Dependent Effects Preservation](13529-view-dependent-effects-preservation.md)
A technique used during the editing of pre-trained Neural Radiance Fields to retain existing specularities and other view-dependent appearance effects that would otherwise be lost or distorted by global recoloring operations. It distinguishes itself from standard NeRF editing methods by automatically identifying and freezing specific neurons in the final color prediction layer that encode angular variation, thereby isolating geometry information from view-dependent appearance.

## Operating characteristics
* **Time Complexity:** Increases slightly compared to view-independent models due to the additional encoding step for view directions and the larger input dimension to the RGB decoder [S2, unofficial].
* **Measured Performance:** On a human face dataset, view conditioning reduces validation MSE from 117.8 to 85.7 [S1]. Training time is approximately 10 days on a single NVIDIA Tesla V100, depending on dataset size [S1].
* **Strengths:** Better generalization to novel viewpoints and correct modeling of specularities without creating ghost geometry [S1].
* **Limitations:** Requires careful tuning of view direction encoding and may overfit if training data is sparse [S1].
* **When to use:** When the scene contains glossy or specular materials that change appearance with viewing angle [S1].
* **When not to use:** For purely diffuse, Lambertian surfaces where view dependence is negligible, as it adds unnecessary complexity [S1].

## Background
Originated in the "Neural Volumes" paper by Lempitsky et al. (2019) [S1]. The method was developed to address the limitations of earlier neural volume representations that could not capture view-dependent effects like specular highlights [G]. It builds on the idea of conditioning neural networks on additional inputs (view direction) to expand their expressive power [S1].
