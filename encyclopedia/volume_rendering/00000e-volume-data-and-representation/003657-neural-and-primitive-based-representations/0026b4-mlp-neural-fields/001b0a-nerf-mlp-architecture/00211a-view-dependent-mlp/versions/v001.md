# View-Dependent MLP

Also called: Larger View-Dependent MLP, iNGP View-Dependent MLP

## Overview
This method replaces the small bottleneck in Instant Neural Graphics Primitives (iNGP) with a larger view-dependent MLP to better express complex view-dependent effects and reduce the formation of "floaters" (spurious geometry) [S1]. It builds on [NeRF MLP Architecture](910-nerf-mlp-architecture.md) by expanding the capacity of the view-dependent color decoding stage.

## How it works
**Inputs and Outputs:**
*   Input: A 256-dimensional bottleneck vector $b$ representing the view-dependent features.
*   Output: Directional emitted color $c$.

**Data Structures:**
*   Bottleneck vector $b \in \mathbb{R}^{256}$.
*   MLP weights and biases for a 3-layer network with 256 hidden units.

**Steps:**
1.  Initialize the bottleneck vector $b$ with size 256.
2.  Pass $b$ through a 3-layer Multi-Layer Perceptron (MLP) with 256 hidden units.
3.  Apply a skip connection from the bottleneck vector $b$ to the second layer of the MLP.
4.  Output the resulting color $c$.

**Parameters:**
*   Bottleneck size: 256 [S1].
*   Hidden units per layer: 256 [S1].
*   Number of layers: 3 [S1].

**Pseudocode:**
```python
def view_dependent_mlp(bottleneck: list[float]) -> list[float]:
    """
    Implements the larger view-dependent MLP from iNGP.
    
    Args:
        bottleneck: A list of 256 floats representing the view-dependent features.
        
    Returns:
        A list of floats representing the emitted color.
    """
    # Layer 1: Linear transformation of bottleneck
    # Note: Exact weight initialization and activation function (e.g., ReLU) 
    # are not specified in the source notes. Standard practice implies 
    # a linear layer followed by an activation.
    h1 = linear_layer_1(bottleneck)
    h1 = relu(h1)
    
    # Layer 2: Linear transformation of h1
    h2 = linear_layer_2(h1)
    
    # Skip connection: Add bottleneck to the output of the first layer of the second stage
    # The source specifies a skip connection from the bottleneck to the second layer.
    # This typically means adding the bottleneck vector to the pre-activation or 
    # post-activation of the second layer's input. Given the phrasing "skip connection 
    # from the bottleneck to the second layer", it implies:
    h2_with_skip = h2 + bottleneck
    
    h2_with_skip = relu(h2_with_skip)
    
    # Layer 3: Linear transformation of h2_with_skip
    h3 = linear_layer_3(h2_with_skip)
    
    # Output layer: Linear transformation to color (typically 3 channels)
    color = linear_output_layer(h3)
    
    return color
```

## Subtopics

### View-Conditioned Rendering
Conditioning the RGB decoder $V_{rgb}$ on the viewpoint of the rendered view to model view-dependent effects such as specularities [S2]. This approach reduces validation MSE from 117.8 to 85.7 on a human face dataset [S2]. The view-conditioned model outperforms non-view-conditioned models on validation viewpoints (MSE 85.7 vs 117.8) [S2]. Non-view-conditioned models incorrectly reconstruct extra semi-transparent voxels near the surface to explain view-dependent phenomena [S2].

## Operating characteristics
*   **Complexity:** Not given in the sources.
*   **Performance:** The larger model reduces floaters and improves rendering quality on shiny surfaces compared to smaller bottlenecks [S1].
*   **Strengths:** Better expression of view-dependent effects [S1].
*   **Limitations:** Increased model size compared to smaller bottlenecks [S1].

## Background
This method was introduced in the context of iNGP (Instant Neural Graphics Primitives) to address limitations in capturing complex view-dependent effects [S1]. It is part of the broader effort to improve neural radiance field rendering quality and reduce artifacts like floaters [S1].
