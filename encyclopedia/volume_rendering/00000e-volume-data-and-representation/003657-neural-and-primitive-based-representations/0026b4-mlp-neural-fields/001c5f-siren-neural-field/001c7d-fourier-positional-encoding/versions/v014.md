# Fourier Positional Encoding

Also called: Fourier Features, Sinusoidal Encoding, Sinusoidal Embedding, Fourier Feature Mappings, Fourier Feature Embedding, Sinusoidal Positional Encoding, Fourier Feature Positional Encoding

## Overview
Fourier Positional Encoding (FPE) maps low-dimensional input coordinates (such as 3D positions or 2D viewing directions) into a higher-dimensional feature space using a multi-resolution sequence of sine and cosine functions at exponentially increasing frequencies [S1][S2, S3, unofficial]. It solves the problem of spectral bias in standard Multi-Layer Perceptrons (MLPs), which struggle to learn high-frequency details from raw smooth coordinates [S7][S21, unofficial]. Unlike [Uncertainty-Aware SIREN](10449-uncertainty-aware-siren.md), which focuses on uncertainty estimation, FPE is a deterministic preprocessing step that lifts inputs to a basis where high-frequency variations are explicitly represented, enabling the MLP to converge faster and represent fine scene details [S1][S2, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tensor of coordinates $x \in \mathbb{R}^{B \times D}$, where $B$ is the batch size and $D$ is the input dimension (typically $D=3$ for position, $D=2$ or $3$ for direction).
*   **Output:** A tensor $E \in \mathbb{R}^{B \times D_{out}}$, where $D_{out}$ is the encoded dimension.

**Data Structures and Parameters:**
*   `input_dims` ($D$): Integer, dimensionality of input (default 3) [S20, S22, unofficial].
*   `num_freqs` ($N$): Integer, number of frequency bands (octaves) [S20, S22, unofficial]. Default 10 for position, 4 for direction [S9, S12, S28, unofficial].
*   `max_freq_log2` ($M$): Float, log2 of the maximum frequency. Often set to $N-1$ [S22, unofficial].
*   `log_sampling` (bool): If True, frequencies are sampled logarithmically ($2^k$); if False, linearly [S5, S6, unofficial]. Default True [S5, S6, unofficial].
*   `include_input` (bool): If True, the original input $x$ is concatenated to the output [S5, S6, unofficial]. Default True [S5, S6, unofficial].
*   `omega0` (float): Frequency scaling factor. Default 1.0 [S4, S8, unofficial].

**Formulas:**
The frequency bands $f_k$ are generated based on `log_sampling`:
*   Logarithmic: $f_k = 2^k$ for $k \in [0, N-1]$ [S4, S8, S10, unofficial].
*   Linear: $f_k$ spaced linearly from $1.0$ to $2^{N-1}$ [S4, S8, S10, unofficial].

The encoding for a scalar input $p$ at level $l$ is:
$$ \gamma_l(p) = (\sin(2^l \pi p), \cos(2^l \pi p)) $$
[S1][S9, S11, unofficial][S13]

The full encoding for input $x$ is the concatenation of these bands. If `include_input` is True:
$$ E(x) = [x, \sin(2^0 \pi x), \cos(2^0 \pi x), \dots, \sin(2^{N-1} \pi x), \cos(2^{N-1} \pi x)] $$
[S12, S15, S22, unofficial]

The output dimension is:
$$ D_{out} = D \times (2N + 1) \quad \text{if } include\_input \text{ is True} $$
$$ D_{out} = D \times 2N \quad \text{if } include\_input \text{ is False} $$
[S4, S8, S10, S18, S20, unofficial]

**Steps:**
1.  **Generate Frequencies:** Compute the array of frequency bands `freq_bands` of length $N$. If `log_sampling` is True, `freq_bands` = $[2^0, 2^1, \dots, 2^{N-1}]$. If False, use linear spacing [S4, S5, S6, S10, unofficial].
2.  **Scale Input:** Multiply the input $x$ by the frequency bands. This creates a tensor of shape $(B, D, N)$ where each channel corresponds to a frequency [S3, S10, S27, S29, unofficial].
3.  **Apply Trigonometry:** Compute the sine and cosine of the scaled values. This results in two tensors of shape $(B, D, N)$ [S3, S6, S25, S27, S29, unofficial].
4.  **Interleave/Concatenate:** Concatenate the sine and cosine components along the last dimension. The layout interleaves frequencies for each input dimension: for input dimension $i$, the first $N$ channels are sines, and the next $N$ are cosines, or they are interleaved per frequency depending on implementation [S3, S19, S27, unofficial]. Specifically, for each frequency $f$, append $\sin(f \cdot x)$ and $\cos(f \cdot x)$ [S19, S27, unofficial].
5.  **Include Input (Optional):** If `include_input` is True, concatenate the original input $x$ to the beginning or end of the encoded tensor [S5, S6, S12, S15, S19, unofficial].

**Pseudocode:**
```python
import torch
import math

def fourier_pos_encoding(x, num_freqs=10, max_freq_log2=9, log_sampling=True, include_input=True):
    """
    x: Tensor of shape (*, D) where * is batch dimensions and D is input dim.
    """
    # 1. Generate frequencies
    if log_sampling:
        # Powers of 2: 2^0, 2^1, ..., 2^(num_freqs-1)
        # max_freq_log2 is typically num_freqs - 1
        freq_bands = 2.0 ** torch.linspace(0, max_freq_log2, num_freqs)
    else:
        # Linear spacing from 1.0 to 2^(num_freqs-1)
        freq_bands = torch.linspace(1.0, 2.0 ** max_freq_log2, num_freqs)
    
    # 2. Scale input
    # x shape: (*, D)
    # freq_bands shape: (N,)
    # We need to multiply x by freq_bands. 
    # Reshape freq_bands to (1, 1, ..., N) to broadcast over batch and D
    freq_bands = freq_bands.view(1, 1, -1)
    
    # scaled_x shape: (*, D, N)
    scaled_x = x.unsqueeze(-1) * freq_bands
    
    # 3. Apply trig functions
    # sin_x and cos_x shape: (*, D, N)
    sin_x = torch.sin(scaled_x)
    cos_x = torch.cos(scaled_x)
    
    # 4. Concatenate sin and cos
    # Result shape: (*, D, 2*N)
    # Note: The order of concatenation determines the layout. 
    # Common layout: [sin(f0), cos(f0), sin(f1), cos(f1), ...]
    # This is achieved by reshaping and concatenating along the last dim.
    # Using the approach from [S27, S29, unofficial]:
    pts = torch.cat([sin_x, cos_x], dim=-1) # (*, D, 2*N)
    
    # Reshape to (*, D * 2 * num_freqs)
    # Flatten all batch dims except the last feature dim
    # Assuming x has shape (*, D), pts has shape (*, D, 2*N)
    # We want (*, D * 2 * N)
    new_shape = list(pts.shape[:-2]) + [-1]
    encoded = pts.view(new_shape)
    
    # 5. Include input
    if include_input:
        encoded = torch.cat([x, encoded], dim=-1)
        
    return encoded
```

**Edge Cases and Pitfalls:**
*   **Lambda Closure Issue:** When implementing FPE as a list of lambda functions (e.g., in TensorFlow/Keras), variables `p_fn` and `freq` must be bound as default arguments in the loop to avoid capturing the final loop values [S20, unofficial].
*   **Precision:** High frequencies can lead to numerical instability if inputs are not normalized. Inputs are often scaled to $[-\pi, \pi]$ or $[-1, 1]$ [S23, unofficial].
*   **Spectral Bias:** Without FPE, ReLU MLPs prioritize low-frequency signals, failing to capture fine details [S7][S21, unofficial].

### Scale Featurization
A method to provide scale information to the MLP by averaging and concatenating a featurized version of downweighting factors, ensuring consistent feature magnitude [S31]. It scales the result by the standard deviation of grid values, padded with an initialization value, and applies a stop-gradient operator to the mean of squared grid values to prevent indirect optimization modification [S31]. The featurized scale input is $(2 \cdot \operatorname{mean}_j(\downweight_{j, \ell}) - 1)\sqrt{\initval^2 + \stopgrad(\operatorname{mean}(\grid_\ell^2))}$ [S31]. An approximation for erf is used for speed: $\operatorname{erf}(x) \approx \operatorname{sign}(x) \sqrt{1 - \exp(-(\frac{4}{\pi})x^2)}$ [S31].

### Fixed Sine/Cosine Positional Encoding
A baseline variant using fixed sine/cosine positional encoding for 3D Gaussian centers [S32]. On the Brandenburg Gate scene, it achieves PSNR 18.66, SSIM 0.763, LPIPS 0.347. On the Trevi Fountain scene, it achieves PSNR 19.91, SSIM 0.741, LPIPS 0.305 [S32].

### Gated Positional Encoding (BARF)
A scheme where higher frequency bands are multiplied by a time-dependent gating factor $\alpha(t)$ to gradually introduce high-frequency details [S33]. The formula is $\gamma_{\text{BARF}}(x, t) = [x, \sin(2^0 \pi x), \cos(2^0 \pi x), \alpha(t)\sin(2^1 \pi x), \alpha(t)\cos(2^1 \pi x), \dots, \alpha(t)\sin(2^L \pi x), \alpha(t)\cos(2^L \pi x)]$ [S33]. It differs from standard NeRF encoding by gating frequencies $2^i$ for $i > 0$ while leaving the base frequency $x$ ungated [S33]. The view-direction encoding uses $L_d=4$ bands [S33].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** The output dimension is $D \times (2N + 1)$ (with input) or $D \times 2N$ (without) [S4, S6, S10, S18, S20, unofficial]. For $D=3, N=10$, this is 63 features per coordinate [S9, S12, unofficial]. This increases the MLP input size significantly compared to raw coordinates [S2, unofficial][S26].
*   **Time:** The encoding computation is $O(B \cdot D \cdot N)$, which is negligible compared to the MLP forward pass [S3, S6, unofficial].

**Measured Performance:**
*   Requires a larger network (e.g., 8 hidden layers, 256 wide) compared to Multiresolution Hash Encoding to achieve similar quality [S2, unofficial][S26].
*   Trains slower than hash encoding methods due to the larger network size and dense updates [S2, unofficial][S26].
*   Fourier encoding does not suffer from gradient locality issues because its derivative is continuous across space, allowing for second-order derivative computation (e.g., curvature regularization) [S13].

**Strengths and Limitations:**
*   **Strengths:** Simple to implement, differentiable, continuous derivatives, effective at overcoming spectral bias in ReLU MLPs [S7, S13][S21, unofficial].
*   **Limitations:** Requires larger networks, slower training compared to sparse hash encodings, prone to aliasing if not integrated (addressed by IPE) [S2, unofficial][S26, S7].

**When to Use:**
*   Use when the scene has high-frequency details and the MLP uses ReLU activations [S7][S21, unofficial].
*   Use when second-order derivatives are needed for regularization [S13].
*   Do not use if training speed is critical and hash encoding is an option [S2, unofficial][S26].

## Background
Fourier Positional Encoding was introduced in the NeRF paper (Mildenhall et al., ECCV 2020) as Eq. 4 [S9, S17, unofficial]. It was inspired by positional encoding in natural language processing (Vaswani et al., 2017) [S2, unofficial][S7]. The technique lifts low-dimensional queries into a higher-dimensional space to help the neural network better capture high-frequency details, addressing the spectral bias of ReLU-based networks [S7][S21, unofficial]. It is widely adopted in neural radiance fields and implicit representations [S2, S6, unofficial][S26].
