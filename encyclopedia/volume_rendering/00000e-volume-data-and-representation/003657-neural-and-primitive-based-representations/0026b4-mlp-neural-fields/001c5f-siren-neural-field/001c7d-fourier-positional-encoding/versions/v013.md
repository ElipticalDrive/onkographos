# Fourier Positional Encoding

Also called: Fourier Feature Embedding, Fourier Feature Mappings, Fourier Feature Positional Encoding, Fourier Features, Sinusoidal Embedding, Sinusoidal Encoding, Sinusoidal Positional Encoding

## Overview
Fourier Positional Encoding is an input encoding technique that maps low-dimensional scalar coordinates (such as 3D spatial positions or 2D viewing directions) into a higher-dimensional feature space using a multi-resolution sequence of sine and cosine functions at exponentially increasing frequencies [S1][S2, S3, S4, S5, S6, unofficial][S7][S8, S9, S10, S11, S12, unofficial][S13][S14, S15, S16, S17, S18, S19, S20, S21, S22, S23, unofficial][S24, S25][S26, S27, S28, S29, unofficial]. It solves the problem of spectral bias in neural networks, where standard MLPs (particularly those with ReLU activations) struggle to learn high-frequency details because they prioritize smooth, low-frequency signals [S7][S21, unofficial]. By lifting inputs into a Fourier space, the method allows the MLP to capture fine-scale variations and high-frequency scene details more effectively [S1][S3, S5, S6, unofficial][S7][S9, S12, S16, S19, S20, S22, unofficial][S24, S25]. It differs from its parent [SIREN Neural Field](1250-siren-neural-field.md) by using fixed (or learned via a separate matrix) sinusoidal mappings as a preprocessing step rather than relying on sine activations within the network layers themselves, and it differs from [Uncertainty-Aware SIREN](10449-uncertainty-aware-siren.md) by not explicitly modeling uncertainty in the encoding domain [S1][S2, S3, S4, S5, S6, unofficial][S7][S8, S9, S10, S11, S12, unofficial][S13][S14, S15, S16, S17, S18, S19, S20, S21, S22, S23, unofficial][S24, S25][S26, S27, S28, S29, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tensor of coordinates $x \in \mathbb{R}^{B \times D}$, where $B$ is the batch size and $D$ is the input dimensionality (typically $D=3$ for 3D position $\mathbf{p}$ or viewing direction $\mathbf{d}$) [S1][S2, S3, S4, S5, S6, unofficial][S7][S8, S9, S10, S11, S12, unofficial][S13][S14, S15, S16, S17, S18, S19, S20, S21, S22, S23, unofficial][S24, S25][S26, S27, S28, S29, unofficial].
*   **Output:** A tensor of encoded features $E \in \mathbb{R}^{B \times D_{out}}$, where $D_{out}$ is the output dimensionality [S3, S4, S8, S10, S18, S20, S21, S22, unofficial][S25][S26, S28, unofficial].

**Data Structures:**
The output tensor layout depends on the implementation variant, but common layouts include:
1.  **Interleaved Sine/Cosine:** For each input dimension $i$, the sine and cosine components for all frequencies are interleaved. Specifically, for input dimension $i$, the sine components for frequencies $0 \dots L-1$ are placed at indices $i, i+2L, i+4L, \dots$ and cosine components at $i+L, i+3L, \dots$ within the channel dimension, or simply concatenated as $[\sin(f_0 x_i), \cos(f_0 x_i), \sin(f_1 x_i), \cos(f_1 x_i), \dots]$ [S3, S5, S6, S8, S10, S15, S16, S18, S19, S20, S22, S26, S28, S29, unofficial].
2.  **Block Layout:** All sine components for all frequencies and dimensions, followed by all cosine components [S2, S9, S12, unofficial][S25].
3.  **Identity Prefix:** If `include_input` is true, the original coordinates $x$ are concatenated as the first $D$ channels [S4, S5, S6, S8, S10, S12, S15, S17, S18, S19, S20, S22, unofficial][S24, S25][S29, unofficial].

**Parameters:**
*   $L$ (or `num_freqs`, `num_octaves`, `multires`): The number of frequency bands (levels) [S1][S2, S3, S4, S5, S6, unofficial][S7][S8, S9, S10, S11, S12, unofficial][S13][S14, S15, S16, S17, S18, S19, S20, S21, S22, S23, unofficial][S24, S25][S26, S27, S28, S29, unofficial]. Typical values: $L=10$ for position, $L=4$ for direction [S9, S12, S27, unofficial].
*   `log_sampling` (or `logspace`): Boolean flag determining if frequencies are exponentially spaced ($2^i$) or linearly spaced [S4, S5, S6, S8, S10, S15, S20, S22, S28, unofficial]. Default: True [S4, S5, S6, S8, S10, S15, S20, S22, S28, unofficial].
*   `max_freq_log2` (or `max_freq`): The maximum frequency exponent. If `log_sampling` is True, the highest frequency is $2^{\text{max\_freq\_log2}}$ [S5, S6, S15, S20, S22, unofficial].
*   `include_input`: Boolean flag to prepend original coordinates to the encoded output [S4, S5, S6, S8, S10, S12, S15, S17, S18, S19, S20, S22, unofficial][S24, S25][S29, unofficial]. Default: True [S4, S5, S6, S8, S10, S12, S15, S17, S18, S19, S20, S22, unofficial][S24, S25][S29, unofficial].
*   $\omega_0$: A scaling factor for frequencies. Default: 1.0 [S4, S8, S10, unofficial].

**Formulas:**
The frequency bands $f_k$ are generated as:
*   Logarithmic: $f_k = 2^k$ for $k \in [0, L-1]$ [S4, S5, S6, S8, S10, S15, S16, S18, S19, S20, S22, S26, S28, S29, unofficial].
*   Linear: $f_k = \text{linspace}(1, 2^{L-1}, L)$ [S4, S5, S6, S8, S10, S15, S20, S22, S28, unofficial].

The encoding for a scalar input $p$ is:
$$ \gamma(p) = (\sin(2^0 \pi p), \cos(2^0 \pi p), \dots, \sin(2^{L-1} \pi p), \cos(2^{L-1} \pi p)) $$
[S1][S9, S11, unofficial][S13].
Note: Some implementations omit the $\pi$ factor, using $\sin(2^k p)$ [S2, S8, S12, unofficial][S25]. The output dimension for a single scalar is $2L$ [S1][S9, S11, unofficial][S13].

For a vector input $x \in \mathbb{R}^D$, the encoding is applied independently to each dimension:
$$ \gamma(x) = [\gamma(x_1), \gamma(x_2), \dots, \gamma(x_D)] $$
[S1, S7].
The total output dimension is:
$$ D_{out} = D \times (2L + \text{include\_input}) $$
[S4, S8, S10, S18, S20, unofficial][S25][S26, S28, unofficial].

**Numbered Steps:**
1.  Generate frequency bands $f_k$ based on `log_sampling` and `max_freq_log2` [S4, S5, S6, S8, S10, S15, S20, S22, S28, unofficial].
2.  If `include_input` is True, initialize the output list with the original input $x$ [S5, S6, S12, S15, S17, S18, S19, S20, S22, unofficial][S24, S25][S29, unofficial].
3.  For each frequency $f_k$ in $f_k$:
    a. Compute scaled inputs: $s_k = x \cdot f_k$ (broadcasting $f_k$ to match $x$'s dimensions) [S3, S8, S10, S16, S26, S28, S29, unofficial].
    b. Compute sine components: $sine_k = \sin(s_k)$ [S3, S5, S6, S8, S10, S15, S16, S18, S19, S20, S22, S26, S28, S29, unofficial].
    c. Compute cosine components: $cosine_k = \cos(s_k)$ [S3, S5, S6, S8, S10, S15, S16, S18, S19, S20, S22, S26, S28, S29, unofficial].
    d. Append $sine_k$ and $cosine_k$ to the output list [S3, S5, S6, S8, S10, S15, S16, S18, S19, S20, S22, S26, S28, S29, unofficial].
4.  Concatenate all elements in the output list along the last dimension (feature dimension) [S3, S5, S6, S8, S10, S15, S16, S18, S19, S20, S22, S26, S28, S29, unofficial].

**Pseudocode:**
```python
import torch
import math

def fourier_positional_encoding(x, num_freqs=10, log_sampling=True, include_input=True, max_freq_log2=9.0):
    """
    x: Tensor of shape (*, D) where * is batch dimensions and D is input dimensionality.
    num_freqs: Number of frequency bands L.
    log_sampling: If True, frequencies are powers of 2. If False, linearly spaced.
    include_input: If True, concatenate original x to the output.
    max_freq_log2: The log2 of the maximum frequency (used only if log_sampling is True).
    """
    batch_dims = x.shape[:-1]
    input_dim = x.shape[-1]
    
    # Step 1: Generate frequency bands
    if log_sampling:
        # Frequencies: 2^0, 2^1, ..., 2^num_freqs-1
        # Note: max_freq_log2 is often set to num_freqs-1 in standard NeRF implementations
        freq_bands = 2.0 ** torch.linspace(0, max_freq_log2, num_freqs, device=x.device, dtype=x.dtype)
    else:
        # Linear spacing from 1.0 to 2^num_freqs-1
        freq_bands = torch.linspace(1.0, 2.0 ** (num_freqs - 1), num_freqs, device=x.device, dtype=x.dtype)
        
    # Step 2: Prepare output list
    parts = []
    if include_input:
        parts.append(x)
        
    # Step 3: Compute sine and cosine for each frequency
    # Reshape freq_bands to (1, 1, ..., num_freqs) to broadcast with x (..., D)
    # x shape: (*, D)
    # freq_bands shape: (num_freqs,)
    # We want to compute sin(x * freq) for each freq
    # Reshape x to (*, D, 1) and freq_bands to (1, 1, num_freqs)
    # Result shape: (*, D, num_freqs)
    
    # Expand x to (*, D, 1)
    x_expanded = x.unsqueeze(-1)
    # Expand freq_bands to (1, 1, num_freqs)
    freq_bands_expanded = freq_bands.view(1, 1, -1)
    
    # Compute scaled inputs: (*, D, num_freqs)
    scaled_inputs = x_expanded * freq_bands_expanded
    
    # Compute sine and cosine: (*, D, num_freqs)
    sin_vals = torch.sin(scaled_inputs)
    cos_vals = torch.cos(scaled_inputs)
    
    # Reshape to (*, D * num_freqs) for sine and cosine separately
    # Then concatenate along the last dimension
    sin_vals_reshaped = sin_vals.view(*batch_dims, -1)
    cos_vals_reshaped = cos_vals.view(*batch_dims, -1)
    
    parts.append(sin_vals_reshaped)
    parts.append(cos_vals_reshaped)
    
    # Step 4: Concatenate
    output = torch.cat(parts, dim=-1)
    
    return output
```

**Edge Cases and Pitfalls:**
*   **Lambda Closure Issue:** When implementing the encoding as a list of lambda functions (e.g., in TensorFlow or older PyTorch versions), variables `p_fn` and `freq` must be bound explicitly as default arguments (`p_fn=p_fn, freq=freq`) to avoid capturing the final loop values [S20, unofficial].
*   **Precision:** Directly regressing shape properties from raw coordinates fails due to spectral bias [S7].
*   **Boundary Conditions:** The encoding assumes inputs are in a range where the frequencies provide meaningful differentiation. Inputs outside the expected range may require scaling [S23, unofficial].

### Scale Featurization
A method to provide scale information to the MLP by averaging and concatenating a featurized version of the downweighting factors $\omega_{j,\ell}$, ensuring features have consistent magnitude regardless of training progression [S30]. It scales the result by the standard deviation of values in $V_\ell$, padded with $\initval$ to prevent zero values [S30]. It applies a stop-gradient operator to the mean of the squared grid values to prevent optimization from indirectly modifying the scale-feature via $V_\ell$ [S30]. The featurized scale input is calculated as: $(2 \cdot \operatorname{mean}_j(\downweight_{j, \ell}) - 1)\sqrt{\initval^2 + \stopgrad(\operatorname{mean}(\grid_\ell^2))}$, where $\downweight_{j, \ell}$ is the downweighting factor, $\initval$ is the initialization magnitude of $V_\ell$, and $\grid_\ell$ represents the values in $V_\ell$ [S30]. An approximation for erf(x) is used for speed: $\operatorname{erf}(x) \approx \operatorname{sign}(x) \sqrt{1 - \exp(-(\sfrac{4}{\pi})x^2)}$ [S30]. The erf approximation has no discernible impact on quality and only a marginal impact on performance [S30].

### Conditional Positional Encoding
A positional encoding technique that applies phase shifts based on time index to sampled features, inspired by Fourier transformation phase information retention [S31]. It applies positional encoding to 6D attributes (x, y, z, t, θ, ϕ) and to sampled features (Fden, Ftex) [S31]. It explicitly assigns phase shift to different frequencies using time index t [S31]. It calculates CPE using formula (2) for texture features only [S31]. The frequency order L is 5 [S31]. CPE is not applied to density field features to maintain zero initialization for correct volume rendering [S31].

### Fixed Sine/Cosine Positional Encoding
A baseline variant using fixed sine/cosine positional encoding for 3D Gaussian centers [S32]. On the Brandenburg Gate scene, this method achieves PSNR 18.66, SSIM 0.763, LPIPS 0.347 [S32]. On the Trevi Fountain scene, this method achieves PSNR 19.91, SSIM 0.741, LPIPS 0.305 [S32].

## Operating characteristics
*   **Time Complexity:** The encoding computation is $O(B \cdot D \cdot L)$, where $B$ is batch size, $D$ is input dimension, and $L$ is the number of frequency bands [S3, S4, S5, S6, S8, S10, S15, S16, S18, S19, S20, S22, S26, S28, S29, unofficial].
*   **Memory Complexity:** The output tensor size is $B \cdot D \cdot (2L + \text{include\_input})$ [S3, S4, S8, S10, S18, S20, unofficial][S25][S26, S28, unofficial].
*   **Measured Performance:** Requires a larger network (e.g., 8 hidden layers, 256 wide) compared to hash encoding to achieve similar quality, and trains slower [S2, unofficial][S25]. However, it trains over 8× faster than some hash encoding configurations with similar parameter counts due to sparsity of updates [S2, unofficial].
*   **Strengths:** Continuous derivatives suitable for higher-order derivative computations like curvature regularization [S13]. Does not suffer from gradient locality issues because its derivative is continuous across space and retains the position variable [S13].
*   **Limitations:** Requires a larger network and slower training compared to hash encoding [S2, unofficial][S25].
*   **When to Use:** When continuous derivatives are needed, or when the network architecture is not optimized for sparse hash lookups [S13][S21, unofficial].
*   **When Not to Use:** When training speed and memory efficiency are critical, and hash encoding is a viable alternative [S2, unofficial][S25].

## Background
Fourier Positional Encoding was introduced in the NeRF paper (Mildenhall et al., ECCV 2020) [S9, S17, unofficial]. It was adopted to encode the five dimensions of the spatiodirectionally varying light field and volume density independently [S2, unofficial][S25]. It addresses the spectral bias of ReLU-based MLPs [S7][S21, unofficial]. It is used in various neural rendering frameworks, including NeuralVDB, which prefers feature mapping techniques over geometric approaches to decouple the neural network design from the VDB tree structure [S21, unofficial].
