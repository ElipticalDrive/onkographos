# Coordinate-Time Encoding

Also called: One-Blob Encoding

## Overview
Coordinate-Time Encoding (also known as One-Blob Encoding) is a continuous, single-scale positional encoding method that maps input coordinates into a higher-dimensional space [S2]. It serves as a continuous variant of one-hot encoding, rasterizing a kernel to represent coordinates [S1, unofficial]. Unlike the multi-frequency approach of its parent [Fourier Positional Encoding](1267-fourier-positional-encoding.md), it provides a localized representation that can achieve more accurate results than frequency encodings in bounded domains at the cost of being single-scale [S1, unofficial]. It is particularly noted for concatenating with spatiotemporal features to handle dynamic conditions in in vivo sequences [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar coordinate value $s \in \mathbb{R}$ (typically a spatial coordinate $x, y, z$ or a temporal coordinate $\tau$) [S2].
*   **Output:** A vector $\mathbf{b}(s) \in \mathbb{R}^k$, where $k$ is the dimensionality of the encoded space [S2].

**Data Structures:**
*   The encoding is applied independently to each coordinate component [S2]. For a 4D input $(x, y, z, \tau)$, the final encoded vector is the concatenation of the one-blob encodings for each component: $\mathbf{b}(x, y, z, \tau) = [\mathbf{b}(x); \mathbf{b}(y); \mathbf{b}(z); \mathbf{b}(\tau)]$ [S2].

**Parameters:**
*   $k$: The dimensionality of the encoded space [S2].
*   $\xi^2$: The variance of the Gaussian kernel [S2].
*   Typical values: Not given in the sources.

**Formula:**
The encoding is defined by evaluating a Gaussian kernel at discrete points [S2]:

$$
\mathbf{b}(s) = g_{s, \xi^2}\left(\frac{i - 0.5}{k}\right), \quad i = 1, 2, \dots, k
$$

Where:
*   $g_{s, \xi^2}(u)$ is a Gaussian kernel with mean $s$ and variance $\xi^2$, evaluated at $u$ [S2].
*   The standard Gaussian PDF is $g_{s, \xi^2}(u) = \frac{1}{\sqrt{2\pi\xi^2}} \exp\left(-\frac{(u - s)^2}{2\xi^2}\right)$ [G].
*   The evaluation points are uniformly spaced in the interval $(0, 1)$, specifically at $\frac{i - 0.5}{k}$ [S2].

**Pseudocode:**
```python
def one_blob_encode(s: float, k: int, xi2: float) -> list[float]:
    b = [0.0] * k
    for i in range(1, k + 1):
        u = (i - 0.5) / k
        b[i - 1] = (1.0 / sqrt(2 * pi * xi2)) * exp(-((u - s) ** 2) / (2 * xi2))
    return b
```

**Edge Cases and Pitfalls:**
*   **Bounded Domains:** While defined for $s \in \mathbb{R}$ [S2], the evaluation points are restricted to $(0, 1)$. If $s$ falls far outside this range, the Gaussian values will be near zero, potentially leading to vanishing gradients or uninformative representations [G].
*   **Single-Scale Limitation:** Because it uses a fixed variance $\xi^2$ and a fixed set of grid points, it cannot represent high-frequency details as effectively as multi-scale encodings like Fourier Positional Encoding if the scene contains features smaller than the effective support of the kernel [S1, unofficial].

## Subtopics

### Off-Axis Positional Encoding
An alternative encoding that shifts the frequency bands to avoid aliasing artifacts. Choose when high-frequency details are critical and standard Fourier encoding suffers from banding. [Off-Axis Positional Encoding](3503-off-axis-positional-encoding.md)

### Integrated Positional Encoding
An extension that integrates the positional encoding over the volume segment to account for density variations. Choose when accurate volume rendering integration is required. [Integrated Positional Encoding](5255-integrated-positional-encoding.md)

## Operating characteristics
*   **Time Complexity:** $O(k)$ per coordinate, where $k$ is the encoding dimension [G].
*   **Memory Complexity:** $O(k)$ to store the encoded vector [G].
*   **Strengths:** Can achieve more accurate results than frequency encodings in bounded domains [S1, unofficial]. It provides a smooth, localized representation suitable for concatenating with other features (e.g., in dynamic in vivo sequences) [S2].
*   **Limitations:** It is single-scale, meaning it lacks the ability to represent a wide range of frequencies simultaneously, which can limit its effectiveness for scenes with complex high-frequency details compared to multi-scale methods [S1, unofficial].
*   **When to use:** When continuous, smooth coordinate representation is needed for dynamic sequences, particularly when concatenating with feature planes [S2].
*   **When not to use:** When multi-scale frequency representation is required for high-frequency details [S1, unofficial].

## Background
The method was suggested by Müller et al. in 2019 and 2020 as a continuous variant of one-hot encoding based on rasterizing a kernel [S1, unofficial]. It is categorized under parametric encodings, which blur the line between classical data structures and neural approaches by arranging trainable parameters in auxiliary data structures [S1, unofficial]. It has been applied in contexts such as Efficient Deformable Tissue Reconstruction via Orthogonal Neural Plane, where it is used to encode spatiotemporal information for dynamic in vivo sequences [S2].
