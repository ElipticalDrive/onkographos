# Expected Sine/Cosine Encoding


## Overview
Expected Sine/Cosine Encoding computes the expected value of sine and cosine functions for input coordinates treated as Gaussian random variables with a specified mean and variance [S1, S2, unofficial]. It serves as an integrated positional encoding that accounts for uncertainty or scale in the input domain, distinguishing it from standard Fourier positional encoding which assumes deterministic inputs [S1, S2, unofficial]. This method is particularly useful in neural fields where inputs represent volumes or regions rather than points, ensuring the encoded features remain statistically consistent with the underlying distribution [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: `y` (tensor of means, shape $[N, D]$) and `y_var` (tensor of variances, shape $[N, D]$).
- Output: `y_out` (encoded means) and `y_var_out` (encoded variances), both with shape $[N, 2D]$.

**Data Structures:**
- The inputs are concatenated along the last dimension. Specifically, `y` is concatenated with `y + \pi/2` to handle the phase shift for sine/cosine duality. Similarly, `y_var` is concatenated with itself.

**Formulas:**
Let $x$ be the input mean and $x_{var}$ be the input variance. The encoding applies the following transformations to produce the output mean $y$ and variance $y_{var}$ for the encoded features [S2, unofficial]:

$$
y = \exp(-0.5 \cdot x_{var}) \cdot \sin(x)
$$

$$
y_{var} = \max\left(0, 0.5 \cdot \left(1 - \exp(-2 \cdot x_{var}) \cdot \cos(2x)\right) - y^2\right)
$$

Note: The source [S2, unofficial] uses `safe_sin` and `safe_cos`, implying numerical stability guards for extreme values, though the exact guard logic is not specified [S2, unofficial].

**Steps:**
1. Receive input tensors `y` (means) and `y_var` (variances).
2. Compute the phase-shifted mean: `y_shifted = y + \pi/2`.
3. Concatenate `y` and `y_shifted` along the last dimension to form the mean component of the output.
4. Concatenate `y_var` with itself along the last dimension to form the variance component of the output.
5. Apply the expected value formulas to each element. For each element $x$ with variance $x_{var}$:
   - Calculate the scaled sine component: $y = \exp(-0.5 \cdot x_{var}) \cdot \sin(x)$.
   - Calculate the variance component: $y_{var} = \max(0, 0.5 \cdot (1 - \exp(-2 \cdot x_{var}) \cdot \cos(2x)) - y^2)$.
6. Return the concatenated results.

**Pseudocode:**

```python
import numpy as np

def expected_sin(y, y_var):
    """
    Computes the expected value of sin(x) and cos(x) for Gaussian variables.
    
    Args:
        y: Tensor of means, shape (..., D).
        y_var: Tensor of variances, shape (..., D).
        
    Returns:
        y_out: Encoded means, shape (..., 2*D).
        y_var_out: Encoded variances, shape (..., 2*D).
    """
    # Step 1: Prepare phase-shifted components
    # Concatenate y with y + pi/2
    y_shifted = y + np.pi / 2.0
    y_mean_concat = np.concatenate([y, y_shifted], axis=-1)
    
    # Concatenate y_var with itself
    y_var_concat = np.concatenate([y_var, y_var], axis=-1)
    
    # Step 2: Apply expected value formulas element-wise
    # Note: The formulas in [S2, unofficial] apply to the original x and x_var before concatenation
    # for the mean calculation, but the output structure is concatenated.
    # We must compute the encoded mean and variance for the original dimensions,
    # then map them to the concatenated structure.
    
    # Calculate encoded mean for the sine part (original x)
    # y_sin = exp(-0.5 * x_var) * sin(x)
    y_sin = np.exp(-0.5 * y_var) * np.sin(y)
    
    # Calculate encoded mean for the cosine part (x + pi/2)
    # Note: sin(x + pi/2) = cos(x). The variance transformation is the same for sin and cos
    # because the variance of sin(x) and cos(x) for Gaussian x depends on cos(2x) and sin(2x)
    # but the formula in [S2, unofficial] is derived for the general case.
    # However, the source [S2, unofficial] implies a specific structure where y and y_var are returned
    # after concatenation. Let's follow the source's implicit logic:
    # The output y_out corresponds to the expected value of sin(x) and cos(x).
    # The output y_var_out corresponds to the variance of sin(x) and cos(x).
    
    # For the first D dimensions (sin(x)):
    # Mean: exp(-0.5 * x_var) * sin(x)
    # Variance: max(0, 0.5 * (1 - exp(-2 * x_var) * cos(2x)) - Mean^2)
    
    # For the second D dimensions (cos(x) = sin(x + pi/2)):
    # Mean: exp(-0.5 * x_var) * cos(x)
    # Variance: max(0, 0.5 * (1 - exp(-2 * x_var) * cos(2(x + pi/2))) - Mean^2)
    # cos(2(x + pi/2)) = cos(2x + pi) = -cos(2x)
    
    # Compute for first half (sin)
    y_sin_mean = np.exp(-0.5 * y_var) * np.sin(y)
    y_sin_var = np.maximum(0, 0.5 * (1 - np.exp(-2 * y_var) * np.cos(2 * y)) - y_sin_mean**2)
    
    # Compute for second half (cos)
    y_cos_mean = np.exp(-0.5 * y_var) * np.cos(y)
    # cos(2*(x + pi/2)) = -cos(2x)
    y_cos_var = np.maximum(0, 0.5 * (1 - np.exp(-2 * y_var) * (-np.cos(2 * y))) - y_cos_mean**2)
    
    # Concatenate results
    y_out = np.concatenate([y_sin_mean, y_cos_mean], axis=-1)
    y_var_out = np.concatenate([y_sin_var, y_cos_var], axis=-1)
    
    return y_out, y_var_out
```

**Parameters:**
- No explicit hyperparameters are defined in the sources. The method relies on the input `y` and `y_var`.

**Edge Cases and Pitfalls:**
- **Precision:** Extreme values of $x$ or $x_{var}$ may lead to numerical instability in `exp` or `sin`/`cos`. The use of `safe_sin` and `safe_cos` in [S2, unofficial] suggests such guards are necessary [S2, unofficial].
- **Degenerate Input:** If $x_{var}$ is very large, the exponential terms decay to zero, resulting in near-zero encoded values. If $x_{var}$ is zero, the encoding reduces to standard sine/cosine encoding.

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(N \cdot D)$, where $N$ is the batch size and $D$ is the dimensionality.
- Memory: $O(N \cdot D)$ for input and output tensors.

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Linear with respect to input size and dimensionality.

**Strengths and Limitations:**
- **Strengths:** Provides a statistically consistent encoding for uncertain inputs, useful in volume rendering and neural fields where inputs represent volumes [S1, S2, unofficial].
- **Limitations:** Requires variance information as input, which may not always be available. Computationally more expensive than standard positional encoding due to additional exponential and trigonometric operations.

**When to Use:**
- Use when inputs are uncertain or represent volumes/regions rather than points.
- Use in neural fields like SIREN where integrated positional encoding improves performance [S1, S2, unofficial].

**When Not to Use:**
- Use standard Fourier positional encoding when inputs are deterministic points.

## Background
Expected Sine/Cosine Encoding is used in the context of mip-NeRF and related neural field methods to handle multi-scale representations [S2, unofficial]. It is implemented in libraries such as `CaSE-NeRF` and `density_bounded_ray_weights` [S1, S2, unofficial]. The method leverages the analytical expectation of sine and cosine functions under Gaussian distributions to provide robust positional encoding [S1, S2, unofficial].
