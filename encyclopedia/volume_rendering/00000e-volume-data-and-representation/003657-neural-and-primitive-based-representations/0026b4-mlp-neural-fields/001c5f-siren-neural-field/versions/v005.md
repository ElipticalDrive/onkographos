# SIREN Neural Field

Also called: SIREN, Sine Neural Field, Sinusoidal Representation Networks

## Overview
The SIREN Neural Field is an Implicit Neural Representation (INR) that encodes volumetric data as a continuous function mapping 3D spatial coordinates to voxel intensity values, preventing GPU memory overflow by storing network parameters instead of explicit voxels [S1]. It replaces a discrete volumetric grid with a continuous function $f_\theta: \mathbb{R}^3 \rightarrow \mathbb{R}$ parameterized by network weights $\theta$, mapping any coordinate $(x, y, z)$ to a predicted scalar value [S3, unofficial]. Unlike standard MLP Neural Fields which suffer from spectral bias and cannot model high-frequency details due to zero second derivatives in ReLU activations, SIREN uses sine activation functions to capture intricate volumetric structures and maintain well-behaved derivatives [S2, unofficial][S4, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A batch of 3D spatial coordinates $\mathbf{x} \in \mathbb{R}^{B \times 3}$, typically normalized to the range $[-1, 1]$ [S2, unofficial][S3, unofficial].
- Output: A scalar field value (e.g., voxel intensity) $\mathbf{y} \in \mathbb{R}^{B \times 1}$ or a vector field value [S1][S4, unofficial].

**Data Structures:**
The network is a Multi-Layer Perceptron (MLP) composed of linear layers and sine activation layers.
- **SineLayer**: A linear transformation followed by a sine activation.
  - Fields: `in_features` (int), `out_features` (int), `bias` (bool), `omega` (float).
- **Linear**: A standard affine transformation.
  - Fields: `in_features` (int), `out_features` (int), `bias` (bool).

**Parameters:**
- `in_features`: Dimensionality of input coordinates (typically 3) [S2, unofficial].
- `out_features`: Dimensionality of output values (typically 1 for scalar fields) [S2, unofficial].
- `hidden_features`: Width of hidden layers [S2, unofficial].
- `hidden_layers`: Number of hidden sine layers [S2, unofficial].
- `bias`: Whether linear layers carry a bias (default: True) [S2, unofficial].
- `last_layer_linear`: If True, the final layer is linear; otherwise, it is a SineLayer (default: False) [S2, unofficial].
- `first_omega_0`: Frequency parameter for the first layer (default: 20.0) [S2, unofficial].
- `hidden_omega_0`: Frequency parameter for hidden layers (default: 20.0) [S2, unofficial] [S2, unofficial].

**Initialization:**
To enable the representation of high-frequency details, weights are initialized using specific uniform distributions scaled by $\omega_0$ [S2, unofficial]:
1. **First Layer**: Weights $W_1$ are drawn from $\text{Uniform}(-1/n, 1/n)$, where $n = \text{in\_features}$ [S2, unofficial].
2. **Hidden Layers**: Weights $W_i$ are drawn from $\text{Uniform}(-\sqrt{6/n} / \omega_0, \sqrt{6/n} / \omega_0)$, where $n = \text{in\_features}$ (for the first hidden layer) or $n = \text{hidden\_features}$ (for subsequent hidden layers) [S2, unofficial].
3. **Final Layer**: If `last_layer_linear` is True, weights are drawn from $\text{Uniform}(-\sqrt{6/n} / \text{hidden\_omega\_0}, \sqrt{6/n} / \text{hidden\_omega\_0})$, where $n = \text{hidden\_features}$ [S2, unofficial]. If False, the same rule as hidden layers applies [S2, unofficial].

**Algorithm:**
1. Clone the input coordinates $\mathbf{x}$ and enable gradient tracking on the copy to allow differentiation with respect to coordinates [S2, unofficial].
2. Pass the cloned coordinates through the network sequentially:
   - Apply the first linear layer.
   - Apply the sine activation: $\sin(\omega_0 \cdot \mathbf{z})$.
   - For each subsequent hidden layer, apply the linear transformation followed by the sine activation with $\omega_0 = \text{hidden\_omega\_0}$.
   - If `last_layer_linear` is True, apply the final linear layer without activation. Otherwise, apply the final sine activation.
3. Return the output values and the gradient-enabled coordinates [S2, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn
import math

class SineLayer(nn.Module):
    """A linear layer with sine activation."""
    def __init__(self, in_features, out_features, bias=True, is_first=False, omega=30):
        super().__init__()
        self.omega = omega
        self.is_first = is_first
        self.linear = nn.Linear(in_features, out_features, bias=bias)
        self.init_weights()

    def init_weights(self):
        with torch.no_grad():
            if self.is_first:
                # Uniform(-1/n, 1/n)
                self.linear.weight.uniform_(-1 / self.linear.in_features, 1 / self.linear.in_features)
            else:
                # Uniform(-sqrt(6/n) / omega, sqrt(6/n) / omega)
                bound = math.sqrt(6 / self.linear.in_features) / self.omega
                self.linear.weight.uniform_(-bound, bound)

    def forward(self, x):
        x = self.linear(x)
        return torch.sin(self.omega * x)

class SIREN(nn.Module):
    """SIREN Neural Field."""
    def __init__(self, in_features, out_features, hidden_features, hidden_layers, 
                 bias=True, last_layer_linear=False, first_omega_0=20.0, hidden_omega_0=20.0):
        super().__init__()
        layers = []
        
        # First layer
        layers.append(SineLayer(in_features, hidden_features, bias=bias, is_first=True, omega=first_omega_0))
        
        # Hidden layers
        for _ in range(hidden_layers):
            layers.append(SineLayer(hidden_features, hidden_features, bias=bias, is_first=False, omega=hidden_omega_0))
            
        # Final layer
        if last_layer_linear:
            layers.append(nn.Linear(hidden_features, out_features, bias=bias))
        else:
            layers.append(SineLayer(hidden_features, out_features, bias=bias, is_first=False, omega=hidden_omega_0))
            
        self.network = nn.Sequential(*layers)

    def forward(self, x):
        # Clone input to enable gradients if needed for coordinate derivatives
        # Note: In standard forward pass, x is just passed through.
        # If gradients w.r.t x are required, x.requires_grad_(True) should be set externally.
        return self.network(x)
```

**Edge Cases and Pitfalls:**
- **Precision**: Standard grids require interpolation for off-grid queries; INR avoids this but incurs per-query inference cost [S3, unofficial].
- **Boundaries**: Coordinates follow the $[-1, 1]$ convention [S2, unofficial].
- **Degenerate Input**: Conventional explicit voxel representations require considerable memory; INR mitigates this by representing the volume as a compact continuous function [S1].

## Subtopics

### [Fourier Positional Encoding](1267-fourier-positional-encoding.md)
Fourier Positional Encoding (FPE) maps low-dimensional input coordinates into a high-dimensional space using a multi-resolution sequence of sine and cosine functions at exponentially increasing frequencies. It solves the problem of spectral bias in standard Multi-Layer Perceptrons (MLPs), which inherently prioritize learning low-frequency signals and fail to capture high-frequency scene details. By lifting inputs to a Fourier feature space, the MLP can represent fine spatial variations without needing to learn the high-frequency basis functions itself. It differs from its parent SIREN Neural Field by using fixed (or randomly initialized) sinusoidal mappings as a preprocessing step, whereas SIREN uses sine activations within the network layers themselves.

### [Uncertainty-Aware SIREN](10449-uncertainty-aware-siren.md)
Uncertainty-Aware SIREN is a method for quantifying prediction confidence in implicit neural representations of steady-state vector fields, addressing the gap where preceding approaches did not quantify prediction confidence. It augments SIREN architectures with residual blocks and dropout layers to enable Deep Ensemble and Monte Carlo Dropout techniques, providing per-grid-point uncertainty estimates alongside predicted vectors. Unlike its siblings, it is the only method in its surveyed section that provides explicit uncertainty quantification, which is critical for downstream scientific analysis where decisions depend on knowing where learned representations are trustworthy.

## Operating characteristics
**Time and Memory Complexity:**
- **Memory**: Memory cost decouples from spatial resolution; a network of fixed size can represent a volume at arbitrary query density [S3, unofficial]. The architecture size is approximately 5.7 MB, an order of magnitude smaller than CNN-based alternatives [S3, unofficial].
- **Inference**: Inference cost requires a full network forward pass per query [S3, unofficial].
- **Training**: Fitting the network to a large volume can take minutes to hours depending on network capacity and target fidelity [S3, unofficial].

**Measured Performance:**
- SIREN reaches a sharp reconstruction in ~100 steps, whereas ReLU-MLP never reaches it in 2000 steps, attributed to spectral bias [S2, unofficial].
- In medical image compression experiments, SIREN outperforms other INR-based compression techniques using ReLU or tanh activation functions [S4, unofficial].
- A 3-layer SIREN with 30-230 neurons per layer offers satisfactory performance for small volume data while cutting GPU memory usage [S1].

**Strengths and Limitations:**
- **Strengths**: Captures high-frequency detail that standard ReLU networks smooth away; allows for higher-order derivatives (useful for normals/curvatures); resolution-independent inference [S3, unofficial][S5].
- **Limitations**: Per-query inference cost; fitting time can be long; standard grids scale memory with resolution while INR does not, but INR requires network fitting [S3, unofficial].

**When to Use:**
- When memory is constrained and explicit voxel grids cause overflow [S1].
- When high-frequency details or smooth derivatives are required [S2, unofficial][S4, unofficial].
- For neural compression and surrogate models [S3, unofficial].

**When Not to Use:**
- When real-time inference with minimal latency is critical and network forward passes are too slow.
- When the scene is simple and low-frequency, where ReLU-MLPs might suffice with less training time.

## Background
The SIREN Neural Field was introduced as a way to encode low-resolution volumetric data as a continuous function, preventing GPU memory overflow [S1]. It was proposed to overcome the lack of capacity in ReLU-based MLPs, which have zero second derivatives and cannot model high-order signals [S4, unofficial]. The method uses periodic activation functions (sine) to enable Implicit Neural Representations (INRs) to capture high-frequency detail [S3, unofficial]. It has been applied to medical image stacks, neural compression, and flow field super-resolution [S4, unofficial][S3, unofficial]. The architecture typically consists of an MLP with 3 layers and 30-230 neurons per layer for small volume data [S1].
