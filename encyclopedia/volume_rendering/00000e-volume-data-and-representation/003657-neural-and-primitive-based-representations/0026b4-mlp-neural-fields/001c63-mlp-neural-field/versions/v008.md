# MLP Neural Field

Also called: Baseline MLP, Coordinate MLP, Plain MLP, Plain MLP Neural Field, ReLU-MLP

## Overview
A plain MLP neural field is a coordinate-based implicit representation that maps continuous spatial coordinates to signal values (such as density and color) using a Multi-Layer Perceptron with standard activations like ReLU [S1, unofficial]. It serves as the fundamental baseline for neural volume rendering, contrasting with specialized architectures like SIREN by lacking spectral bias, which results in slower convergence and an inability to reconstruct high-frequency details within practical training steps [S1, unofficial].

## How it works
The method defines a scene function $F_\Theta: \mathbb{R}^3 \rightarrow \mathbb{R}^k$ where the input is a 3D coordinate vector and the output is a signal vector. The network is trained by minimizing the difference between rendered images and ground truth observations [G].

**Inputs and Outputs:**
*   **Input:** A batch of 3D coordinates $\mathbf{x} \in \mathbb{R}^{B \times 3}$, typically normalized to the range $[-1, 1]$ [S1, unofficial].
*   **Output:** A signal vector containing density $\sigma$ and color $\mathbf{c}$, or occupancy probability, depending on the specific rendering formulation [S1, unofficial].

**Data Structures:**
The network is a sequential stack of linear layers and activation functions.
*   **Layer 1:** Linear transformation from `in_features` (3) to `hidden_features`.
*   **Hidden Layers:** `hidden_layers - 1` repetitions of Linear(`hidden_features`, `hidden_features`) followed by an Activation function.
*   **Output Layer:** Linear transformation from `hidden_features` to `out_features` (typically 4 for density + RGB).
*   **Parameters:**
    *   `in_features`: int, dimensionality of input coordinates (default 3) [S1, unofficial].
    *   `out_features`: int, dimensionality of output values [S1, unofficial].
    *   `hidden_features`: int, width of hidden layers [S1, unofficial].
    *   `hidden_layers`: int, number of hidden layers [S1, unofficial].
    *   `bias`: bool, whether linear layers carry a bias (default True) [S1, unofficial].
    *   `activation`: str, name of the activation function (default "ReLU") [S1, unofficial].

**Algorithm Steps:**
1.  **Preprocessing:** Clone the input coordinate tensor $\mathbf{x}$ and enable gradient tracking on the copy to allow differentiation with respect to spatial coordinates [S1, unofficial].
2.  **Forward Pass:** Pass the gradient-enabled coordinates through the sequential MLP architecture defined above.
3.  **Output:** Return the predicted signal values and the coordinate tensor (if gradients are needed for backpropagation or visualization) [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn

class PlainMLP(nn.Module):
    def __init__(self, in_features=3, out_features=4, hidden_features=256, 
                 hidden_layers=8, bias=True, activation="ReLU"):
        super().__init__()
        layers = []
        
        # First layer: input to hidden
        layers.append(nn.Linear(in_features, hidden_features, bias=bias))
        
        # Activation after first layer
        if activation == "ReLU":
            layers.append(nn.ReLU())
        elif activation == "Tanh":
            layers.append(nn.Tanh())
        elif activation == "GELU":
            layers.append(nn.GELU())
        else:
            raise ValueError(f"Unsupported activation: {activation}")
            
        # Hidden layers
        for _ in range(hidden_layers - 1):
            layers.append(nn.Linear(hidden_features, hidden_features, bias=bias))
            if activation == "ReLU":
                layers.append(nn.ReLU())
            elif activation == "Tanh":
                layers.append(nn.Tanh())
            elif activation == "GELU":
                layers.append(nn.GELU())
                
        # Output layer
        layers.append(nn.Linear(hidden_features, out_features, bias=bias))
        
        self.network = nn.Sequential(*layers)

    def forward(self, points_xyz):
        """
        Args:
            points_xyz: Tensor of shape [B, 3] containing 3D coordinates.
        Returns:
            signal: Tensor of shape [B, out_features] containing density and color.
        """
        # Clone input and enable gradients for differentiation w.r.t coordinates [S1, unofficial]
        points_grad = points_xyz.clone().detach().requires_grad_(True)
        
        # Pass through network
        signal = self.network(points_grad)
        
        return signal, points_grad
```

**Parameters and Training:**
*   Typical training involves fitting the network to a single image or a set of views.
*   For a ReLU-MLP, a typical number of training steps is 2000 [S1, unofficial].
*   In contrast, SIREN may converge in ~100 steps for similar tasks, highlighting the spectral bias of ReLU networks [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Coordinate Convention:** Inputs must follow the $[-1, 1]$ normalization convention; unnormalized coordinates may lead to poor convergence or saturation of activations [S1, unofficial].
*   **Spectral Bias:** The ReLU activation causes the network to prioritize low-frequency functions, making it difficult to represent high-frequency details (sharp edges, fine textures) compared to sinusoidal activations [S1, unofficial].
*   **Gradient Computation:** Gradients with respect to coordinates are computed via automatic differentiation (autograd) during the forward pass, which is essential for computing density gradients or Laplacians for visualization [S1, unofficial].

## Subtopics

### [MLP with Input Skips](1643-mlp-with-input-skips.md)
An MLP architecture that concatenates the original input vector to intermediate layers, allowing the network to access low-level features at deeper layers. It serves as the baseline for standard NeRF-style neural fields, contrasting with SIREN by using ReLU activations and explicit skip connections rather than sinusoidal embeddings. See [MLP with Input Skips](1643-mlp-with-input-skips.md).

### [Deformation MLP Configuration](9661-deformation-mlp-configuration.md)
Deformation MLP Configuration defines the architecture, initialization, and conditioning mechanisms for a Multi-Layer Perceptron (MLP) used to predict spatial or temporal deformations (delta positions) in neural volume rendering. It solves the problem of mapping canonical coordinates to deformed coordinates by configuring the MLP's weights, biases, and input processing to ensure stable optimization and effective conditioning on latent codes or external features. It is distinguished from standard MLP Neural Fields by its specific focus on deformation outputs and the integration of conditioning strategies like FiLM or concatenation to handle dynamic or multi-instance scenes. See [Deformation MLP Configuration](9661-deformation-mlp-configuration.md).

### [Residual Block with Shortcut (ReLU MLP Extension)](10016-residual-block-with-shortcut-relu-mlp-extension.md)
This method extends the analytic marching algorithm for implicit surface reconstruction to Multi-Layer Perceptrons (MLPs) constructed with residual blocks containing shortcut connections. It enables the theoretical analysis and exact linear region partitioning of such architectures, allowing for efficient meshing via analytic marching. See [Residual Block with Shortcut (ReLU MLP Extension)](10016-residual-block-with-shortcut-relu-mlp-extension.md).

### MLP Decomposition Baseline
An alternative decomposition method where a neural network (MLP) with a softmax activation outputs the weights $w_{\phi n}(\mathbf{x})$. It is used as a baseline to demonstrate the efficiency of Voronoi decomposition [S2]. While it has similar theoretical operation counts to Voronoi decomposition, it suffers from random memory access during integration, leading to much faster runtime growth as the number of heads increases compared to Voronoi decomposition [S2].

## Operating characteristics
*   **Time Complexity:** Training time is significantly higher than sinusoidal-based fields (like SIREN) for equivalent visual quality due to spectral bias. For example, fitting an image may require 2000 steps for ReLU-MLP versus ~100 steps for SIREN [S1, unofficial].
*   **Memory Complexity:** Memory usage is constant with respect to spatial resolution, determined only by the number of network parameters ($O(N_{params})$) [S1, unofficial].
*   **Strengths:** Simple architecture; easy to implement; serves as a robust baseline for comparison; compatible with standard deep learning frameworks.
*   **Limitations:** Cannot efficiently represent high-frequency details; slow convergence; requires more training steps to achieve acceptable reconstruction quality compared to spectral bias-free alternatives [S1, unofficial].
*   **When to use:** As a baseline for comparison in research; for scenes with low-frequency content; when computational resources for specialized architectures are unavailable.
*   **When not to use:** For high-frequency details; when fast convergence is required; when spectral bias is a limiting factor.

## Background
The plain MLP neural field was introduced as a baseline method in the context of differentiable rendering and neural implicit representations. It is often compared against SIREN (Sinusoidal Representation Networks) to highlight the importance of activation functions in learning high-frequency signals [S1, unofficial]. The method is part of the broader family of coordinate-based neural fields, which map continuous coordinates to scene properties [G].
