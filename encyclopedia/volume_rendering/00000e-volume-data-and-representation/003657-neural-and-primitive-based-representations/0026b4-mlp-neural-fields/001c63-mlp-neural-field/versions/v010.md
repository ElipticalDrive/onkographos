# MLP Neural Field

Also called: Baseline MLP, Coordinate MLP, Plain MLP, Plain MLP Neural Field, ReLU-MLP

## Overview
The MLP Neural Field is a baseline method for representing continuous scenes by mapping spatial coordinates directly to signal values (such as density and color) using a standard Multi-Layer Perceptron with ReLU activations [S1, unofficial]. It solves the problem of implicit scene representation by providing a differentiable function $F_\Theta: \mathbb{R}^3 \rightarrow \mathbb{R}^k$ that can be optimized against rendered observations [G]. Unlike its sibling [SIREN Neural Field](1250-siren-neural-field.md), which uses sinusoidal activations to capture high-frequency details, the MLP Neural Field suffers from spectral bias, making it slower to converge and less capable of representing sharp boundaries [S1, unofficial]. It serves as the standard reference for evaluating the effectiveness of architectural modifications like input skips or residual blocks in neural fields.

## How it works
The method defines a scene function using a feedforward neural network. The network takes continuous 3D coordinates as input and outputs a signal vector.

**Inputs and Outputs:**
*   **Input:** A batch of 3D coordinates $\mathbf{x} \in \mathbb{R}^{N \times 3}$, typically normalized to the range $[-1, 1]$ [S1, unofficial].
*   **Output:** A signal vector $\mathbf{y} \in \mathbb{R}^{N \times k}$, where $k$ is the number of output features (e.g., 1 for density, 3 for RGB color) [S1, unofficial].

**Data Structures:**
The network is implemented as a sequential stack of linear layers and activation functions.
*   **Layer 0:** Linear transformation from `in_features` to `hidden_features`.
*   **Layers 1 to $H-1$:** Linear transformation from `hidden_features` to `hidden_features`, followed by an activation function.
*   **Layer $H$:** Linear transformation from `hidden_features` to `out_features`.
*   **Parameters:** Weights and biases for each linear layer.

**Parameters:**
*   `in_features`: Dimensionality of input coordinates (typically 3) [S1, unofficial].
*   `out_features`: Dimensionality of output signal (e.g., 4 for density+alpha+RGB, or 1+3) [S1, unofficial].
*   `hidden_features`: Width of hidden layers [S1, unofficial].
*   `hidden_layers`: Number of hidden layers [S1, unofficial].
*   `bias`: Boolean, whether linear layers include a bias term (default: True) [S1, unofficial].
*   `activation`: String specifying the activation function (default: "ReLU") [S1, unofficial].
*   `steps`: Number of training steps (e.g., 2000 for ReLU-MLP on simple scenes) [S1, unofficial].

**Algorithm Steps:**
1.  **Input Preparation:** Clone the input coordinate tensor $\mathbf{x}$ and enable gradient tracking on the clone. This is necessary to compute gradients of the output with respect to the input coordinates for rendering losses [S1, unofficial].
2.  **Forward Pass:** Pass the gradient-enabled coordinates through the MLP network.
    *   Apply the linear transformation and activation for each hidden layer.
    *   Apply the final linear transformation without activation (or with a specific output activation like Softmax if used for decomposition weights, though standard MLP fields use linear output) [S1, unofficial][S2].
3.  **Output:** Return the predicted signal values and the input coordinates (for gradient computation) [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn

class MLPNeuralField(nn.Module):
    """
    A plain MLP neural field mapping coordinates to signal values.
    """
    def __init__(self, in_features=3, out_features=4, hidden_features=256, 
                 hidden_layers=8, bias=True, activation="ReLU"):
        super().__init__()
        layers = []
        
        # First layer: in_features -> hidden_features
        layers.append(nn.Linear(in_features, hidden_features, bias=bias))
        
        # Activation for first hidden layer
        if activation == "ReLU":
            layers.append(nn.ReLU())
        elif activation == "Tanh":
            layers.append(nn.Tanh())
        elif activation == "GELU":
            layers.append(nn.GELU())
        else:
            raise ValueError(f"Unsupported activation: {activation}")
            
        # Hidden layers: hidden_features -> hidden_features
        for _ in range(hidden_layers - 1):
            layers.append(nn.Linear(hidden_features, hidden_features, bias=bias))
            if activation == "ReLU":
                layers.append(nn.ReLU())
            elif activation == "Tanh":
                layers.append(nn.Tanh())
            elif activation == "GELU":
                layers.append(nn.GELU())
                
        # Output layer: hidden_features -> out_features
        layers.append(nn.Linear(hidden_features, out_features, bias=bias))
        
        self.network = nn.Sequential(*layers)

    def forward(self, x):
        """
        Args:
            x: Tensor of shape [N, 3] containing 3D coordinates.
        Returns:
            y: Tensor of shape [N, out_features] containing signal values.
        """
        # Clone input to enable gradient tracking if not already enabled
        # Note: In practice, gradients are enabled on the input tensor 
        # before calling forward, or the module assumes x.requires_grad is True.
        # Here we assume x already has requires_grad=True as per standard usage.
        y = self.network(x)
        return y
```

**Edge Cases and Pitfalls:**
*   **Coordinate Normalization:** Coordinates must follow the $[-1, 1]$ convention to ensure stable training and proper activation behavior [S1, unofficial].
*   **Spectral Bias:** The ReLU-MLP struggles to represent high-frequency details (sharp edges) compared to sinusoidal networks, often requiring many more training steps to converge [S1, unofficial].
*   **Gradient Computation:** The input coordinates must be cloned with gradients enabled to allow backpropagation through the network with respect to spatial position, which is essential for computing density gradients or rendering losses [S1, unofficial].

## Subtopics

### [MLP with Input Skips](1643-mlp-with-input-skips.md)
An MLP architecture that concatenates the original input vector to intermediate layers, allowing the network to access low-level features at deeper layers. It serves as the baseline for standard NeRF-style neural fields, contrasting with SIREN by using ReLU activations and explicit skip connections rather than sinusoidal embeddings.

### [Deformation MLP Configuration](9661-deformation-mlp-configuration.md)
Deformation MLP Configuration refers to the architectural setup and initialization strategies used in Multi-Layer Perceptrons (MLPs) that map spatial or spatio-temporal coordinates to deformation fields (e.g., delta positions or feature transformations) within neural volume representations. It solves the problem of stably training implicit deformation networks by ensuring that initial deformations are small and controlled, preventing gradient explosion or collapse during early optimization stages. It is distinct from standard MLPs by its specific focus on outputting displacement vectors or conditional modulation parameters rather than direct density or color values, and it differs from sibling methods like Input Skips or Residual Blocks by focusing on the initialization and conditioning mechanics (such as FiLM) rather than connectivity patterns.

### [Residual Block with Shortcut (ReLU MLP Extension)](10016-residual-block-with-shortcut-relu-mlp-extension.md)
This method extends the analytic marching algorithm for implicit surface reconstruction to Multi-Layer Perceptrons (MLPs) constructed with residual blocks containing shortcut connections. It enables the theoretical analysis and exact linear region partitioning of such architectures, allowing for efficient meshing via analytic marching.

### MLP Decomposition Baseline
An alternative decomposition method where a neural network (MLP) with a softmax activation outputs the weights $w_{\phi n}(\mathbf{x})$. It is used as a baseline to demonstrate the efficiency of Voronoi decomposition [S2]. While it has similar theoretical operation counts to Voronoi decomposition, it suffers from random memory access during integration, leading to much faster runtime growth as the number of heads increases [S2].

## Operating characteristics
*   **Time Complexity:** The forward pass is $O(L \cdot H^2)$ where $L$ is the number of hidden layers and $H$ is the hidden width. Training time is significantly higher than sinusoidal networks for high-frequency scenes due to spectral bias, often requiring 2000+ steps compared to ~100 steps for SIREN on simple analytic scenes [S1, unofficial].
*   **Memory Complexity:** Memory usage is constant with respect to spatial resolution, depending only on the number of network parameters ($O(L \cdot H^2)$) [S1, unofficial].
*   **Strengths:** Simple architecture, easy to implement, serves as a robust baseline for comparing more complex neural field architectures.
*   **Limitations:** Poor at representing high-frequency details and sharp boundaries due to spectral bias. Requires careful coordinate normalization.
*   **When to use:** As a baseline for comparison, or for scenes with low-frequency content where high precision is not required.
*   **When not to use:** For scenes requiring sharp edges or high-frequency details, where [SIREN Neural Field](1250-siren-neural-field.md) or [NeRF MLP Architecture](910-nerf-mlp-architecture.md) with positional encoding is preferred.

## Background
The MLP Neural Field, often referred to as the ReLU-MLP, originates from early work on implicit neural representations for 3D shapes and scenes. It was established as a baseline to demonstrate the advantages of sinusoidal activation functions (SIREN) in capturing high-frequency details [S1, unofficial]. The method is widely used in differentiable rendering research to compare the convergence properties and representational capacity of different activation functions and network architectures [S1, unofficial]. It is a fundamental component in the family of neural fields, preceding more advanced variants like those with input skips or residual connections.
