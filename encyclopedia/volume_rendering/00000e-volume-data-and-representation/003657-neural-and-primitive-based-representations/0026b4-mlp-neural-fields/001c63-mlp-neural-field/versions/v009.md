# MLP Neural Field

Also called: Baseline MLP, Coordinate MLP, Plain MLP, Plain MLP Neural Field, ReLU-MLP

## Overview
The MLP Neural Field is a coordinate-based implicit representation that maps continuous spatial coordinates to signal values (such as density and color) using a standard Multi-Layer Perceptron (MLP) with piecewise-linear activations like ReLU [S1, unofficial]. It serves as the fundamental baseline for neural volume rendering, contrasting with spectral-bias-resistant variants like SIREN by relying on standard initialization and activation functions [S1, unofficial]. Unlike voxel-based methods, it offers constant memory usage relative to spatial resolution, enabling infinite-resolution reconstruction [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A batch of 3D coordinates $\mathbf{x} \in \mathbb{R}^{B \times 3}$, typically normalized to the range $[-1, 1]$ [S1, unofficial].
*   **Output:** A signal vector $\mathbf{y} \in \mathbb{R}^{B \times k}$, where $k$ is the number of output features (e.g., 1 for density, 3 for RGB color) [S1, unofficial].

**Data Structures:**
The network is a sequential stack of linear layers and activations.
*   **Layer 0:** Linear transformation $W_1 \mathbf{x} + b_1$, where $W_1 \in \mathbb{R}^{H \times 3}$ and $b_1 \in \mathbb{R}^{H}$.
*   **Layers $1$ to $L-1$:** Hidden layers. Each consists of a linear transformation $W_i \mathbf{h}_{i-1} + b_i$ followed by an activation function $\sigma(\cdot)$, where $W_i \in \mathbb{R}^{H \times H}$ and $b_i \in \mathbb{R}^{H}$.
*   **Layer $L$:** Output layer. A linear transformation $W_{L+1} \mathbf{h}_{L-1} + b_{L+1}$, where $W_{L+1} \in \mathbb{R}^{k \times H}$ and $b_{L+1} \in \mathbb{R}^{k}$.
*   **Parameters:** $\Theta = \{W_i, b_i\}_{i=1}^{L+1}$.

**Parameters:**
*   `in_features`: Dimensionality of input coordinates (typically 3) [S1, unofficial].
*   `out_features`: Dimensionality of output signal (e.g., 4 for density+alpha, or 3 for color) [S1, unofficial].
*   `hidden_features` ($H$): Width of hidden layers [S1, unofficial].
*   `hidden_layers` ($L-1$): Number of hidden layers [S1, unofficial].
*   `bias`: Boolean flag for bias terms (default `True`) [S1, unofficial].
*   `activation`: String name of the activation function (default `"ReLU"`) [S1, unofficial].
*   `steps`: Number of training steps for fitting an image (e.g., 2000 for ReLU-MLP) [S1, unofficial].

**Algorithm:**
1.  Clone the input coordinate tensor $\mathbf{x}$ to $\mathbf{x}_{grad}$ and enable gradient tracking on $\mathbf{x}_{grad}$ [S1, unofficial].
2.  Pass $\mathbf{x}_{grad}$ through the MLP:
    $$ \mathbf{h}_0 = \text{ReLU}(W_1 \mathbf{x}_{grad} + b_1) $$
    $$ \mathbf{h}_i = \text{ReLU}(W_{i+1} \mathbf{h}_{i-1} + b_{i+1}) \quad \text{for } i = 1, \dots, L-2 $$
    $$ \mathbf{y} = W_{L+1} \mathbf{h}_{L-2} + b_{L+1} $$
    *(Note: If `hidden_layers` is 0, the output is directly $W_1 \mathbf{x}_{grad} + b_1$. If `hidden_layers` is 1, the output is $W_2 \text{ReLU}(W_1 \mathbf{x}_{grad} + b_1) + b_2$.)*
3.  Return $\mathbf{y}$ and $\mathbf{x}_{grad}$ to allow backpropagation of gradients with respect to the input coordinates [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn

class MLPNeuralField(nn.Module):
    def __init__(self, in_features=3, out_features=4, hidden_features=256, hidden_layers=8, bias=True, activation="ReLU"):
        super().__init__()
        layers = []
        # First layer: in_features -> hidden_features
        layers.append(nn.Linear(in_features, hidden_features, bias=bias))
        layers.append(get_activation(activation))
        
        # Hidden layers: hidden_features -> hidden_features
        for _ in range(hidden_layers - 1):
            layers.append(nn.Linear(hidden_features, hidden_features, bias=bias))
            layers.append(get_activation(activation))
            
        # Output layer: hidden_features -> out_features
        layers.append(nn.Linear(hidden_features, out_features, bias=bias))
        
        self.network = nn.Sequential(*layers)

    def forward(self, x):
        # x: [B, 3]
        # Clone input and enable gradients for coordinate-based differentiation
        x_grad = x.clone().detach().requires_grad_(True)
        y = self.network(x_grad)
        return y, x_grad

def get_activation(name):
    if name == "ReLU":
        return nn.ReLU()
    elif name == "Tanh":
        return nn.Tanh()
    elif name == "GELU":
        return nn.GELU()
    else:
        raise ValueError(f"Unknown activation: {name}")
```

**Edge Cases and Pitfalls:**
*   **Coordinate Convention:** Inputs must follow the $[-1, 1]$ convention to match the training distribution [S1, unofficial].
*   **Spectral Bias:** ReLU-MLPs suffer from spectral bias, making it difficult to represent high-frequency details compared to SIREN [S1, unofficial].
*   **Gradient Computation:** Gradients with respect to coordinates must be computed via autodiff on the cloned input tensor; analytical derivatives are not used [S1, unofficial].

## Subtopics

### [MLP with Input Skips](1643-mlp-with-input-skips.md)
An MLP architecture that concatenates the original input vector to intermediate layers, allowing the network to access low-level features at deeper layers. It serves as the baseline for standard NeRF-style neural fields, contrasting with SIREN by using ReLU activations and explicit skip connections rather than sinusoidal embeddings. See [MLP with Input Skips](1643-mlp-with-input-skips.md).

### [Deformation MLP Configuration](9661-deformation-mlp-configuration.md)
Deformation MLP Configuration refers to the architectural setup and initialization strategies used in Multi-Layer Perceptrons (MLPs) that map spatial or spatio-temporal coordinates to deformation fields (e.g., delta positions or feature transformations) within neural volume representations. It solves the problem of stably training implicit deformation networks by ensuring that initial deformations are small and controlled, preventing gradient explosion or collapse during early optimization stages. It is distinct from standard MLPs by its specific focus on outputting displacement vectors or conditional modulation parameters rather than direct density or color values, and it differs from sibling methods like Input Skips or Residual Blocks by focusing on the initialization and conditioning mechanics (such as FiLM) rather than connectivity patterns. See [Deformation MLP Configuration](9661-deformation-mlp-configuration.md).

### [Residual Block with Shortcut (ReLU MLP Extension)](10016-residual-block-with-shortcut-relu-mlp-extension.md)
This method extends the analytic marching algorithm for implicit surface reconstruction to Multi-Layer Perceptrons (MLPs) constructed with residual blocks containing shortcut connections. It enables the theoretical analysis and exact linear region partitioning of such architectures, allowing for efficient meshing via analytic marching. See [Residual Block with Shortcut (ReLU MLP Extension)](10016-residual-block-with-shortcut-relu-mlp-extension.md).

### MLP Decomposition Baseline
An alternative decomposition method where a neural network (MLP) with a softmax activation outputs the weights $w_{\phi_n}(\mathbf{x})$. It is used as a baseline to demonstrate the efficiency of Voronoi decomposition [S2]. While it has similar theoretical operation counts to Voronoi decomposition, it suffers from random memory access during integration, leading to much faster runtime growth as the number of heads increases [S2].

## Operating characteristics
*   **Time Complexity:** Inference is $O(L \cdot H^2)$ per sample, where $L$ is the number of layers and $H$ is the hidden width [S1, unofficial]. Training time is significantly longer than spectral variants like SIREN for high-frequency scenes due to spectral bias [S1, unofficial].
*   **Memory Complexity:** $O(L \cdot H^2)$ for storing weights, independent of scene resolution [S1, unofficial].
*   **Performance:** For simple analytic scenes, ReLU-MLP may require ~2000 steps to converge, whereas SIREN converges in ~100 steps [S1, unofficial].
*   **Strengths:** Simple implementation, standard initialization, constant memory usage.
*   **Limitations:** Spectral bias limits high-frequency detail reconstruction; slower convergence for complex scenes compared to SIREN [S1, unofficial].
*   **When to Use:** As a baseline for comparison; when standard ReLU activations are preferred; when computational simplicity is prioritized over high-frequency fidelity.
*   **When Not to Use:** When high-frequency detail reconstruction is critical and training time is constrained; when spectral bias is a known bottleneck.

## Background
The MLP Neural Field, often referred to as the ReLU-MLP baseline, originates from early work on coordinate-based implicit representations. It is frequently cited in comparison to SIREN (Sinusoidal Representation Networks) to highlight the impact of activation functions and initialization on spectral bias [S1, unofficial]. The method is implemented in various open-source differentiable rendering frameworks, such as `Yonghao-Lee/differentiable-rendering`, where it serves as a standard reference for volume rendering and sphere tracing demos [S1, unofficial].
