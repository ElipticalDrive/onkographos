# CoDeF
## Overview
CoDeF is a temporal deformation field representation for dynamic volume rendering that uses a multiresolution hash table to map points from a canonical space to a deformed space [S1]. It enables the direct application of standard image processing algorithms to a canonical image, with results propagated across time via the deformation field [S1]. It distinguishes itself from sibling methods by prioritizing storage efficiency and hash-grid-based deformation over explicit MLP parameterizations or latent code conditioning [S1, S2].
## How it works
**Inputs and Outputs:**
*   **Input:** Canonical coordinates $\mathbf{x}_c$ and time $t$ [G].
*   **Output:** Deformed coordinates $\mathbf{x}_t$ or deformation vector $\mathbf{v}$ [G].

**Data Structures:**
The core data structure is a multiresolution hash table (hash grid) storing deformation vectors at various resolutions [S1].
*   **Hash Grid:** A sparse hash map storing deformation vectors (typically 3D floats) at multiple resolution tiers [G].
*   **Hash Function:** Maps 3D coordinates $(x, y, z)$ and time $t$ to a hash index [G].
*   **Interpolation:** Trilinear interpolation is applied between neighboring hash entries to ensure smooth deformation fields [G].

**Steps:**
1.  **Canonical Representation:** Store the static scene properties (color, opacity, Gaussian parameters) in a canonical space [S1].
2.  **Deformation Query:** For a given point $\mathbf{x}_c$ at time $t$:
    a. Compute the hash index for $(\mathbf{x}_c, t)$ using the multiresolution hash table [G].
    b. Retrieve the stored deformation vector $\mathbf{v}$ from the hash grid [G].
    c. Interpolate $\mathbf{v}$ across neighboring grid cells [G].
3.  **Coordinate Transformation:** Apply the deformation to the canonical coordinate:
    $$ \mathbf{x}_t = \mathbf{x}_c + \mathbf{v} $$
    where $\mathbf{x}_t$ is the deformed coordinate [G].
4.  **Rendering:** Render the deformed point $\mathbf{x}_t$ using standard volume rendering or splatting techniques [G].
5.  **Temporal Propagation:** Results from image processing applied to the canonical image are propagated across time via the temporal deformation field [S1].

**Parameters:**
*   **Hash Grid Resolution:** Determines the granularity of the deformation field [G].
*   **Number of Hash Tiers:** Multiresolution hashing uses multiple tiers of resolution [G].
*   **CCA Profile:** CoDeF is often used in conjunction with Point-Cloud Compression (CCA), though capacity sweeps fix the CCA profile at CCA-Default [S2].

**Edge Cases and Pitfalls:**
*   **Optical Flow Accuracy:** The method is limited by optical flow accuracy [S1].
*   **Complex Motion:** It has difficulty modeling complex motion [S1].
*   **Boundary Conditions:** Proper handling of points outside the hash grid bounds is required (e.g., clamping or zero deformation) [G].
## Subtopics

### CDF Capacity Sweeps
CDF Capacity Sweeps systematically vary the deformation network/grid capacity to generate rate-distortion operating points, evaluating storage-quality trade-offs independently of CCA compression [S2].
*   **Definition:** Systematically varies the deformation network/grid capacity to generate rate-distortion operating points, evaluating storage-quality trade-offs independently of CCA compression [S2].
*   **Parameters:** CDF capacity tiers: Small, Mid, Default. Controls deformation module size and representational capacity [S2]. Hash-grid capacity tiers (for baseline comparison): Hash-Small $\equiv H^*-4$, Hash-Mid $\equiv H^*-2$, Hash-Default $\equiv H^*$, where $H^*$ is scene-specific default [S2].
*   **Performance Numbers:** CC-4DGS configurations stay under 30 MB total and under 2 MB Deform-module storage across all tiers, spanning $\approx 30.4–32.0$ dB PSNR [S2]. Swift4D spans 31–94 MB total and 5–68 MB Deform-module storage for the same PSNR range [S2].
*   **Comparison:** CC-4DGS achieves comparable PSNR to Swift4D's default configuration with an order-of-magnitude smaller storage envelope. Even Swift4D's most aggressively shrunk hash-grid uses more Deform storage than CC-4DGS at full capacity, confirming that the storage advantage is not merely due to point-cloud compression but also reflects the compact CDF representation [S2].

## Operating characteristics
*   **Time Complexity:** Querying the hash grid is $O(1)$ on average, making it efficient for real-time rendering [G].
*   **Memory Complexity:** Depends on the hash grid size and number of tiers. CoDeF is designed to be storage-efficient, with deformation module storage often under 2 MB for typical scenes [S2].
*   **Measured Performance:** On N3DV scenes, CC-4DGS with CoDeF achieves 30.4–32.0 dB PSNR with total model size under 30 MB [S2].
*   **Strengths:** Compatibility with standard image processing pipelines and efficient temporal propagation [S1].
*   **Limitations:** Limited by optical flow accuracy and difficulty in modeling complex motion [S1].
*   **When to Use:** When storage efficiency is critical and motion is relatively smooth or predictable [S1].
*   **When Not to Use:** For scenes with highly complex motion where optical flow estimation is unreliable [S1].
## Background
CoDeF is discussed in the context of dynamic Gaussian Splatting and 3D editing based on NeRF and 3DGS [S1, S2]. It builds on the use of multiresolution hash tables for efficient spatial and temporal representation [S1]. The method is evaluated alongside point-cloud compression techniques to analyze storage-quality trade-offs [S2].
