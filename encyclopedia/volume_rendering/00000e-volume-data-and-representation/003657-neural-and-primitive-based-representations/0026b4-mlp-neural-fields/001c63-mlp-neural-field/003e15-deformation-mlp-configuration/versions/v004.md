# Deformation MLP Configuration

Also called: Conditional Batch Normalization, Deformation MLP Setup, Feature-wise Linear Modulation (FiLM), Feature-wise transformations, MLP setup

## Overview
Deformation MLP Configuration refers to the specific architectural setup and initialization strategies used in Multi-Layer Perceptrons (MLPs) that map spatial or spatio-temporal coordinates to deformation fields (e.g., delta positions). It solves the problem of stably optimizing dynamic neural representations by ensuring that initial deformations are small and predictable, preventing gradient explosion or collapse during early training stages [S1]. It is distinct from standard MLPs by its focus on output stability via specialized initialization and its frequent integration with conditioning mechanisms like Feature-wise Linear Modulation (FiLM) or latent codes [S2, unofficial]. It differs from [MLP with Input Skips](1643-mlp-with-input-skips.md) by prioritizing deformation stability over high-frequency detail reconstruction, and from [Residual Block with Shortcut (ReLU MLP Extension)](10016-residual-block-with-shortcut-relu-mlp-extension.md) by often lacking explicit residual connections in favor of direct coordinate mapping [S1].

## How it works
The method configures an MLP to predict a deformation vector $\delta\mathbf{x}$ from input coordinates. The configuration involves specific network topology, input encoding, and weight initialization protocols.

### Inputs and Outputs
*   **Inputs**: Spatial coordinates $\mathbf{x} \in \mathbb{R}^3$ and optionally time $t \in \mathbb{R}$ [S1]. In some variants, these are processed via positional encoding [S1] or hash encoding [S3].
*   **Outputs**: A delta position vector $\delta\mathbf{x} \in \mathbb{R}^3$ (or higher dimensional feature vectors in other contexts like LiDAR encoding [S3]) representing the displacement from the canonical position.

### Data Structures and Layout
The canonical deformation MLP structure, as defined in [S1], consists of:
*   **Layers**: 8 linear layers.
*   **Neurons**: 256 neurons per hidden layer.
*   **Input Encoding**: Positional encoding is applied to coordinates.
    *   Spatial frequencies $L_x = 10$.
    *   Temporal frequencies $L_t = 10$ [S1].
*   **Activation**: Not explicitly specified in [S1], but standard ReLU or SIREN (Sinusoidal) activations are implied by the context of neural fields [S1][S2, unofficial]. The parent article [MLP Neural Field](1256-mlp-neural-field.md) notes configurable activations.

### Initialization
Stable optimization of deformation fields requires specific initialization to ensure the network starts with near-zero deformation [S1]:
1.  **Hidden Layers**: Weights are initialized using Xavier normal initialization. Biases are initialized to zero [S1].
2.  **Final Layer**: The final linear layer maps the last 256 features to the output dimension (e.g., 3 for $\delta\mathbf{x}$). Its weights are initialized from a normal distribution with standard deviation $\sigma = 10^{-5}$. Biases are initialized to zero [S1].

### Conditional Conditioning (FiLM/CBN)
In configurations utilizing Feature-wise Linear Modulation (FiLM) or Conditional Batch Normalization (CBN), the deformation is conditioned on a latent code $\mathbf{z}$ [S2, unofficial].
*   **Mechanism**: For each layer $i$, small networks predict scale $\boldsymbol{\gamma_i}(\mathbf{z})$ and bias $\boldsymbol{\beta_i}(\mathbf{z})$ vectors [S2, unofficial].
*   **Formula**: The layer output $\hat{\boldsymbol{x}}_i$ is computed as:
    $$ \hat{\boldsymbol{x}}_i = L_i(\boldsymbol{x}) \odot \boldsymbol{\gamma_i}(\mathbf{z}) + \boldsymbol{\beta_i}(\mathbf{z}) $$
    where $L_i(\boldsymbol{x})$ is the standard linear transformation output, $\odot$ is element-wise multiplication, and the size of $\boldsymbol{\gamma_i}$ and $\boldsymbol{\beta_i}$ matches the layer's output size [S2, unofficial].

class FiLMDeformationMLP(DeformationMLP):
    """
    Deformation MLP with FiLM conditioning as per [S2, unofficial].
    """
    def __init__(self, latent_dim, **kwargs):
        super().__init__(**kwargs)
        self.latent_dim = latent_dim
        # Create FiLM networks for each linear layer
        self.film_layers = nn.ModuleList()
        for module in self.network:
            if isinstance(module, nn.Linear):
                # Predict scale and bias for this layer's output size
                out_size = module.out_features
                film_net = nn.Sequential(
                    nn.Linear(self.latent_dim, out_size),
                    nn.ReLU() # [G] Activation for FiLM predictor
                )
                self.film_layers.append(film_net)
            else:
                self.film_layers.append(None)

    def forward(self, x, z):
        """
        x: [B, input_dim] (or encoded)
        z: [B, latent_dim]
        """
        # Apply FiLM at each linear layer
        h = x
        for i, module in enumerate(self.network):
            if isinstance(module, nn.Linear):
                # Get scale and bias from FiLM network
                gamma = self.film_layers[i](z) # [B, out_features]
                beta = self.film_layers[i](z) # [B, out_features]
                
                # Apply transformation: y = gamma * x + beta
                h = module(h)
                h = h * gamma + beta
            else:
                h = module(h)
        return h

## Subtopics

### [Multi-MLP Linear Layer](15116-multi-mlp-linear-layer.md)
Enables parallel training of multiple independent MLPs within a single computational graph using 3D tensors indexed by MLP ID. Chosen when batch-processing multiple distinct deformation fields or instances efficiently.

### [Latent Code Conditioning](16345-latent-code-conditioning.md)
Uses latent codes to condition the MLP, allowing for global or local control over the deformation field. Chosen when the deformation needs to vary based on external parameters or scene configurations.

### Fused Hash Encoding MLP Architecture
Uses "fused" MLPs with hash encoding to process 3D positions for density prediction. It employs a minimum hash grid resolution of 16, 5 levels of hash encoding, and 2-dim features per level [S3]. Chosen for efficient street scene LiDAR/NeRF integration where memory efficiency is critical [S3].

### MLP Lidar Encoding
Processes LiDAR features using an MLP with three hidden layers (sizes 64, 96, 128) and a 64-dim output. Chosen for extracting high-dimensional features from LiDAR points in street scene reconstruction [S3].

### CoDeF
Uses a content field and temporal deformation field with multiresolution hash tables to allow image processing on canonical images and propagation across time. Chosen for efficient video processing, though limited by optical flow accuracy and complex motion modeling [S4].

### Spatial-Ratio Neural Field Configuration
Models a 4D voxel space (x, y, z, e) using six 2D planes to predict Gaussian transformations conditioned on an elastic ratio $e$. Uses hidden feature dimension $D=64$ and plane resolutions $\{64, 64, 64, 100\}$ for $\{x, y, z, e\}$. Chosen for flexible 3D Gaussian Splatting with elastic inference [S5].

### Deformation Network (Static)
Queries a grid field for features and computes displacement using a static MLP (`dx = self.static_mlp(grid_feature)`). Chosen for static scene deformation in 4DGS variants where grid features are pre-computed [S6, unofficial].

### Multi-Head MLP Decoder
Attaches multiple lightweight MLP decoders (e.g., five heads, two layers each) to a shared feature grid encoder. Chosen for uncertainty-aware volume rendering, amortizing parameter costs while identifying high-error regions via variance regularization [S7, unofficial].

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of layers and neurons. The FiLM variant adds overhead for the conditioning networks [S2, unofficial]. Hash encoding variants add lookup overhead but reduce MLP depth requirements [S3].
*   **Memory Complexity**: Proportional to the number of parameters. The 8-layer, 256-neuron configuration uses approximately $8 \times 256 \times 256$ weights plus biases, which is moderate [S1]. Hash encoding reduces MLP parameters but adds grid memory [S3].
*   **Performance**: The specific initialization (std $10^{-5}$ for final layer) ensures stable optimization, preventing large initial deformations that could destabilize training [S1].
*   **Strengths**: Stable training dynamics for dynamic scenes; flexible conditioning via FiLM or latent codes [S1][S2, unofficial].
*   **Limitations**: Standard MLPs may struggle with high-frequency details compared to SIRENs or hash-based methods [S1, S3]. CoDeF is limited by optical flow accuracy [S4].

## Background
The configuration originates from the need to stabilize the training of dynamic neural radiance fields and Gaussian splatting methods. The specific initialization strategy (Xavier for hidden layers, small std for final layer) was introduced in the context of Time-of-Flight Gaussian optimization to handle indirect depth optimization [S1]. The FiLM/CBN approach was adapted from generative modeling (StyleGAN) to neural fields for conditional rendering [S2, unofficial]. Variants like hash encoding were developed to improve efficiency in large-scale street scene reconstruction [S3].
