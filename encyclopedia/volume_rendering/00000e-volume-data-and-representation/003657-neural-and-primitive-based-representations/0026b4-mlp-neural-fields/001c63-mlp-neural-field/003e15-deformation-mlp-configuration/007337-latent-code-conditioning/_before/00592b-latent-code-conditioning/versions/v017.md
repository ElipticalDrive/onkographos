# Latent Code Conditioning

Also called: Global Conditioning, Instance-Specific Conditioning, Latent Vector Conditioning

## Overview
Latent Code Conditioning is a family of techniques for injecting instance-specific information into a Neural Field decoder by associating a unique latent vector with each data sample (e.g., a specific 3D shape, volume, or dynamic object) [S1, unofficial][S2, S3, S4]. It solves the problem of representing multiple distinct instances using a single shared neural architecture, enabling the model to distinguish between different geometries, appearances, or temporal states without duplicating the entire network [S1, unofficial][S2]. It is distinguished from [Multi-MLP Linear Layer](15116-multi-mlp-linear-layer.md) by using a single global vector per instance rather than multiple local vectors, and from [Spatial-Ratio Neural Field Configuration](16086-spatial-ratio-neural-field-configuration.md) by conditioning on instance identity rather than spatial resolution or scale [S1, unofficial][S2].

## Shared principles
All methods in this family share the following mechanism:
1.  **Instance Association:** Each data instance $i$ is associated with a latent code $z_i \in \mathbb{R}^D$. This code encapsulates the global information required to reconstruct or render that specific instance [S1, unofficial][S2].
2.  **Shared Decoder:** A single neural network $f_\theta$ (the decoder) is shared across all instances. The latent code $z_i$ is used to modulate the behavior of this shared network [S1, unofficial][S2].
3.  **Conditioning Injection:** The latent code $z_i$ is combined with the query input (typically spatial coordinates $x$) before or during the evaluation of $f_\theta$ [S1, unofficial][S2, S3, S4].
4.  **Optimization:** The latent codes $z_i$ and/or the decoder weights $\theta$ are optimized to minimize a reconstruction loss against the target data for each instance [S1, unofficial][S3, S4].

## Subtopics

### [Concatenation Conditioning](12582-concatenation-conditioning.md)
Concatenation Conditioning injects the latent code by appending it to the input features or descriptors before evaluation. It is distinguished from [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md) by modifying inputs rather than weights, and from [Autoencoder/Autodecoder Conditioning](12588-autoencoder-autodecoder-conditioning.md) by typically using a separate encoder-decoder pipeline rather than a unified autodecoder. Choose this method when you have pre-computed latent codes (e.g., from an encoder) and want a simple, fixed decoder.

### [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md)
HyperNetwork Conditioning generates a unique set of decoder weights for each data instance by using a secondary neural network (the HyperNetwork) to predict the parameters of the primary Neural Field decoder from a latent code. Unlike Concatenation Conditioning, which shares a single fixed decoder across all instances and relies on input mixing to distinguish samples, this method creates a distinct Neural Field for each instance, allowing the primary decoder's complexity to be significantly lower while maintaining representational power. Choose this method when instance variations are complex and require distinct network topologies or weights.

### [Autoencoder/Autodecoder Conditioning](12588-autoencoder-autodecoder-conditioning.md)
Autoencoder/Autodecoder Conditioning assigns a unique learnable latent vector $z_i$ to each data instance, which is concatenated with spatial coordinates and fed into a shared decoder network $f_\theta$ to reconstruct instance-specific geometry or appearance. It differs from Concatenation Conditioning by optimizing the latent codes themselves as trainable parameters rather than deriving them from a fixed encoder or context, and from HyperNetwork Conditioning by using direct vector concatenation instead of generating network weights. This method enables the model to learn a continuous shape or appearance space where interpolation of latent vectors yields smooth transitions between instances. Choose this method when you want to learn a continuous latent space directly from data without a separate encoder.

### [Global Conditioning](12589-global-conditioning.md)
Global conditioning encodes the entire information of a data sample into a single latent vector $z$, which is then used to condition a shared neural field decoder. It serves as the foundational mechanism for instance association in neural field representations, distinguishing itself from local conditioning methods that distribute latent codes across spatial or temporal coordinates. It is typically implemented via a mapping network that transforms the raw latent code into an intermediate non-linear latent space. Choose this method when you need to map raw features (e.g., from an image encoder) into a suitable latent space for the decoder.

### Local Conditioning
**Definition:** Spreading information about a data sample over multiple latent codes assigned to specific subsets of spatio-temporal coordinates (regions or time steps) [S1, unofficial]. This contrasts with global conditioning by allowing instance-specific details to vary spatially or temporally [S1, unofficial].

### Dynamic Object Radiance Field Conditioning
**Definition:** A radiance field $\psi$ for dynamic objects conditioned by separate shape and appearance latent vectors [S2].
**Steps:**
1. Concatenate a shape code with the input coordinate $x$ at the network input [S2].
2. Concatenate an appearance code with the direction $d$ at the bottleneck after density prediction [S2].
3. Concatenate sequence and object appearance latent vectors to propagate sequence appearance to individual objects [S2].

### Image Encoding
**Definition:** Passes the appearance source image $A$ through a network to generate a latent code, which is then appended to the input voxels [S3].
**Comparison:** Captures overall color but fails to assign it correctly to individual parts [S3].

### Edit Code Mapping
**Definition:** A process to map each edited 2D image $S_i^j$ into a latent feature vector $z_i^j \in \mathbb{R}^{64}$ named edit code to characterize diverse edits and solve the inconsistency problem in 3D scenes caused by 2D image-to-image translation generating different content for the same target [S4].
**Steps:**
1. Extract feature from edited image $S_i^j$ using an off-the-shelf VAE encoder $\mathcal{E}$ from stable diffusion [30] [S4].
2. Apply a tiny MLP network $\mathcal{M}$ to produce the edit code $z_i^j$ [S4].
3. Keep the pre-trained encoder fixed and only optimize the parameters of the tiny MLP network during training [S4].
**Formula:** $\mathbf {z}_i^j = \mathcal {D}(\mathbf {S}_i^j) = \mathcal {M}(\mathcal {E}(\mathbf {S}_i^j))$, where $\mathcal{D}$ represents the mapping process, $\mathcal{E}$ is the fixed encoder, and $\mathcal{M}$ is the learnable tiny MLP [S4].
**Parameter:** Edit code dimension: $\mathbb{R}^{64}$ [S4].

## Background
The concept of using a single latent vector per data sample is referred to as global conditioning [S1, unofficial]. The practice of spreading information over multiple latent codes assigned to specific subsets of spatio-temporal coordinates is referred to as local conditioning [S1, unofficial]. Hybrid approaches using one global code for shared information and several local codes for instance-specific details are also possible [S1, unofficial]. The use of separate shape and appearance latent vectors for dynamic objects was introduced in the context of multi-level neural scene graphs for dynamic urban environments [S2]. Image encoding for neural rendering was explored in the Neural Voxel Renderer (NVR) [S3]. Edit code mapping for NeRF-to-NeRF translation was proposed in GenN2N [S4].
