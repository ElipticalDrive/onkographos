# Concatenation Conditioning

Also called: Latent Code Concatenation

## Overview
Concatenation Conditioning is a method for injecting instance-specific latent codes into a Neural Field decoder by appending the latent vector to the input feature tensor. It solves the problem of conditioning a shared neural field on distinct data instances (e.g., different volumes or transfer functions) by providing global context directly at the network's entry point. It is distinguished from [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md) by avoiding weight prediction, and from [Autoencoder/Autodecoder Conditioning](12588-autoencoder-autodecoder-conditioning.md) by not using adaptive normalization layers to modulate intermediate features.

## How it works
**Inputs and Outputs:**
- Input: A query point $x \in \mathbb{R}^3$ (and potentially other features like normal or material properties), and a latent code $z_i \in \mathbb{R}^D$ associated with instance $i$.
- Output: The predicted value (e.g., density, color, ambient occlusion) $y_i \in \mathbb{R}^k$.

**Data Structures:**
- Latent Code $z_i$: A fixed-size vector of dimension $D$. Typical values are $D=512$, though $D=64$ or $D=256$ are used [S1][S2, unofficial].
- Input Features $x$: The spatial coordinates and any explicit descriptors (e.g., Transfer Function descriptors).

**Steps:**
1.  **Encode (Optional):** If the latent code is derived from data, process the input volume or data with an encoder network to extract $z_i$. For example, a convolutional feature extractor may process a volume to produce a 512-dimensional vector containing compressed global information [S1].
2.  **Concatenate:** Append the latent code $z_i$ to the input feature vector $x$. The new input vector $x'$ is defined as:
    $$ x' = [x; z_i] $$
    where $[;]$ denotes concatenation along the feature dimension.
3.  **Decode:** Feed $x'$ into the first layer of the Neural Field decoder $f_\theta$. The decoder computes the output $y_i$:
    $$ y_i = f_\theta(x') $$
    The weights $\theta$ are shared across all instances [S1][S2, unofficial].

**Pitfalls:**
- **Limited Condition Propagation:** Only the first layer directly incorporates the condition $z_i$. Subsequent layers operate only on internal feature representations derived from the first layer's output. The network must therefore distinguish between samples based on the transformed input alone, which can be challenging for complex conditions [S2, unofficial].
- **Re-computation Cost:** In scenarios where the condition changes (e.g., updating a Transfer Function), the encoder and decoder must be re-executed. However, if the latent code represents the volume itself, the compressed volume representation remains constant, offering an inference advantage over methods requiring full re-evaluation of the raw volume [S1].

**Pseudocode:**
```python
def concatenate_conditioning_decoder(x, z, weights):
    """
    x: Input features (e.g., coordinates, TF descriptors), shape [B, F_x]
    z: Latent code for the instance, shape [B, D]
    weights: Weights for the first layer of the decoder
    """
    # Concatenate input features with latent code
    # x: [B, F_x], z: [B, D] -> x_prime: [B, F_x + D]
    x_prime = torch.cat([x, z], dim=1)
    
    # First layer: Linear transformation + Activation
    # weights[0]: [F_x + D, H], weights[1]: [H]
    h = torch.relu(torch.matmul(x_prime, weights[0].T) + weights[1])
    
    # Subsequent layers operate on h, which implicitly contains the condition
    # ... (remaining decoder layers)
    return h
```

## Subtopics

### HyperNetwork Conditioning
Generates decoder weights from the latent code. Choose when the condition requires complex, non-linear modulation of the network's internal structure. [Link](12585-hypernetwork-conditioning.md)

### Autoencoder/Autodecoder Conditioning
Uses AdaIN to modulate intermediate feature tensors. Choose when the condition needs to influence the network at multiple depths, not just the input. [Link](12588-autoencoder-autodecoder-conditioning.md)

### Global Conditioning
Uses a separate global network or pooling to inject context. Choose when the condition is not a single vector but a more complex global representation. [Link](12589-global-conditioning.md)

## Operating characteristics
- **Time Complexity:** $O(D \cdot F_{in})$ for the concatenation step, where $D$ is latent dimension and $F_{in}$ is input feature size. The decoding complexity is unchanged from the base neural field.
- **Memory Complexity:** $O(D)$ per instance to store the latent code. No additional memory for weight generation or modulation parameters.
- **Strengths:** Simple to implement; computationally efficient at inference; allows pre-computation of the latent code if it is derived from static data [S1].
- **Limitations:** The condition is only explicitly visible to the first layer, potentially limiting the network's ability to use complex conditional information [S2, unofficial].
- **When to use:** When the condition is a low-dimensional vector and the decoder is shallow or the condition is simple. When computational efficiency is prioritized over expressive power.

## Background
Concatenation Conditioning is a standard technique in conditional generative modeling, adapted for neural fields in volume rendering. It was explicitly proposed for volumetric ambient occlusion prediction, where a latent vector encoding the volume is concatenated with Transfer Function descriptors to condition a generative decoder [S1]. It is also described as the "straightforward option" for implementing conditioning in neural fields, serving as a baseline for more sophisticated methods like HyperNetworks [S2, unofficial].
