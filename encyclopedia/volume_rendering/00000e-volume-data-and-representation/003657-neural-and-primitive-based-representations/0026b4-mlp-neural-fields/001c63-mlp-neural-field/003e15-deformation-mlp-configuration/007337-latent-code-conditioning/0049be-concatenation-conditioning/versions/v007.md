# Concatenation Conditioning

Also called: Latent Code Concatenation

## Overview
Concatenation Conditioning is a method for injecting instance-specific information into a Neural Field by appending a latent code vector to the input feature tensor before the first layer of the decoder [S1][S2, unofficial]. It solves the problem of how to condition a single neural network on variable data (such as a specific volume instance or transfer function) without altering the network's weights [S2, unofficial]. It is distinguished from [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md) by using fixed weights and simply expanding the input dimension, and from [Autoencoder/Autodecoder Conditioning](12588-autoencoder-autodecoder-conditioning.md) by explicitly separating the encoding of the global context from the local decoding process [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A query coordinate $x$ (and potentially direction $d$ or time $t$), and a latent code $z \in \mathbb{R}^D$ encoding instance-specific information [S1][S2, unofficial].
*   **Output:** Volumetric properties $y$ (e.g., density, color, ambient occlusion) [S1][S2, unofficial].

**Data Structures:**
*   **Latent Code ($z$):** A vector of length $D$. Typical values are $D=512$, though $D=64$ or $D=256$ are used in specific applications [S1][S2, unofficial].
*   **Input Tensor ($x$):** The local features or coordinates passed to the decoder.
*   **Concatenated Tensor ($x_{cat}$):** The result of appending $z$ to $x$.

**Steps:**
1.  **Encode:** Process the input volume or data instance with an encoder network to extract the latent vector $z$ [S1]. This vector contains highly compressed global information about the input [S1].
2.  **Concatenate:** Append the latent code $z$ to the input feature vector $x$ along the feature dimension. The resulting tensor is $x_{cat} = [x; z]$ [S1][S2, unofficial].
3.  **Decode:** Feed $x_{cat}$ into the first layer of the Neural Field decoder [S2, unofficial]. The decoder $f$ computes the output $y = f(x_{cat})$ [S2, unofficial].

**Pseudocode:**
```python
def concatenate_conditioning_decoder(x, z, decoder_network):
    """
    x: Tensor of local features/coordinates, shape (..., F_x)
    z: Latent code vector, shape (..., D)
    decoder_network: A neural network (e.g., MLP) where the first layer
                     expects input dimension F_x + D.
    """
    # Step 2: Concatenate latent code with input features
    # Assuming batch dimensions are compatible or broadcastable
    x_cat = torch.cat([x, z], dim=-1)
    
    # Step 3: Feed concatenated tensor into the decoder
    y = decoder_network(x_cat)
    
    return y
```

**Parameters:**
*   **Latent Dimension ($D$):** Typically 512 [S1][S2, unofficial].
*   **Decoder Architecture:** The first layer must be sized to accept $F_x + D$ inputs. Subsequent layers operate on internal feature representations derived from this concatenation [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Layer Limitation:** Only the first layer of the decoder directly incorporates the condition $z$. Remaining layers operate only on internal feature representations, requiring the network to distinguish samples based on the input alone [S2, unofficial].
*   **Inference Cost:** While the compressed volume representation from the encoder stays constant, any update to the transfer function or instance data requires re-execution of the TF extractor and the decoder [S1].
*   **Precision:** Standard floating-point concatenation is used; no specific bit-packing is mentioned [S1][S2, unofficial].

## Subtopics

### HyperNetwork Conditioning
Uses a secondary network to predict the weights of the main decoder based on $z$, allowing every layer to use the condition. Choose when dynamic weight adaptation is needed. [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md)

### Autoencoder/Autodecoder Conditioning
The latent code $z$ is often the output of an encoder trained jointly with the decoder, or the decoder is trained to reconstruct the input from $z$. Choose when end-to-end learning of the representation is preferred. [Autoencoder/Autodecoder Conditioning](12588-autoencoder-autodecoder-conditioning.md)

### Global Conditioning
Uses global pooling or attention mechanisms to inject $z$ into intermediate layers. Choose when deeper integration of global context is required. [Global Conditioning](12589-global-conditioning.md)

## Operating characteristics
*   **Time Complexity:** $O(N \cdot (F_x + D))$ for the concatenation and first layer, where $N$ is the number of query points. The encoder is run once per instance, not per query [S1].
*   **Memory Complexity:** Requires storing the latent code $z$ ($D$ floats) per instance. The decoder weights are shared [S1][S2, unofficial].
*   **Strengths:** Simple to implement; efficient inference as the encoder output is cached [S1].
*   **Limitations:** The condition is only directly visible to the first layer, which may limit the network's ability to use global information in deeper features [S2, unofficial].
*   **When to Use:** When a simple, lightweight conditioning mechanism is sufficient and the first layer can adequately propagate the condition [S1][S2, unofficial].

## Background
Concatenation Conditioning is a standard technique in conditional generative modeling, adapted for volumetric neural fields [S1]. It was explicitly proposed for volumetric ambient occlusion prediction to combine global volume information with local transfer function descriptors [S1]. The approach relies on the principle that a latent vector $z$ can encode instance-specific information, which is then injected into the neural field $f(x; z)$ [S1][S2, unofficial].
