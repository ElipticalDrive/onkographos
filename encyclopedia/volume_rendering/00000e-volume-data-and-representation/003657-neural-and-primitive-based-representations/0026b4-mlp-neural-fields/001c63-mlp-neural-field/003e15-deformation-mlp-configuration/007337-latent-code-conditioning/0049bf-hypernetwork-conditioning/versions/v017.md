# HyperNetwork Conditioning

Also called: HyperNet Conditioning, Hypernetwork-based Conditioning

## Overview
HyperNetwork Conditioning generates instance-specific neural field weights by using a secondary network (the HyperNetwork) to predict the parameters of the primary decoder from a latent code [S1, unofficial]. Unlike Concatenation Conditioning, which shares fixed weights across all instances and relies on the latent code to modulate the input, this method creates a distinct Neural Field (different weights) for each input instance [S1, unofficial]. This separation allows the primary network complexity to be significantly lower, offering a more compact representation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A latent code $z_i \in \mathbb{R}^D$ for instance $i$.
*   **Output:** The weight parameters $\theta_i$ of the primary Neural Field decoder $f_{\theta_i}$, and subsequently the field value $f_{\theta_i}(x)$.

**Data Structures:**
1.  **HyperNetwork ($h_\phi$):** A neural network with parameters $\phi$. It takes $z_i$ as input and outputs a vector containing all weights and biases for the primary decoder.
2.  **Primary Decoder ($f_{\theta}$):** A standard MLP. Its weights $\theta$ are not learned directly via gradient descent on the reconstruction loss; instead, they are dynamically generated.

**Numbered Steps:**
1.  **Encode Latent Code:** Input the instance-specific latent code $z_i$ into the HyperNetwork $h_\phi$.
2.  **Predict Weights:** The HyperNetwork outputs a flattened vector $w_{pred}$. This vector is reshaped and split to form the weight matrices $W^{(l)}$ and bias vectors $b^{(l)}$ for each layer $l$ of the primary decoder.
    $$ \theta_i = h_\phi(z_i) $$
    Where $\theta_i$ represents the collection of all parameters $\{W^{(1)}, b^{(1)}, \dots, W^{(L)}, b^{(L)}\}$.
3.  **Evaluate Field:** Evaluate the primary decoder using the generated parameters $\theta_i$ and the query point $x$:
    $$ y = f_{\theta_i}(x) $$
4.  **Optimization:** During training, gradients flow through the primary decoder evaluation to the generated weights $\theta_i$, and then through the HyperNetwork generation process to update $\phi$ and $z_i$. The primary weights $\theta_i$ are not stored as persistent learnable parameters but are recomputed per instance or cached if memory permits.

**Parameters:**
*   **HyperNetwork Depth/Width:** Not given in the sources.
*   **Latent Dimension $D$:** Typical values are 64, 256, or 512 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory:** Storing unique weights for every instance can be memory-intensive if the primary network is large. However, the primary network itself can be smaller than a shared network handling all variations [S1, unofficial].
*   **Precision:** The HyperNetwork must accurately predict valid weight configurations. Poor convergence in the HyperNetwork leads to unstable field evaluations.

**Pseudocode:**
```python
import torch
import torch.nn as nn

class HyperNetworkDecoder(nn.Module):
    def __init__(self, hyper_net_config, decoder_layer_dims):
        super().__init__()
        # HyperNetwork: maps latent code to decoder weights
        self.hyper_net = build_hyper_network(hyper_net_config)
        self.decoder_layer_dims = decoder_layer_dims

    def forward(self, z, x):
        """
        z: latent code [batch_size, D]
        x: query points [batch_size, 3]
        """
        # 1. Predict weights from latent code
        # hyper_net outputs a flat vector of all weights and biases
        flat_weights = self.hyper_net(z)
        
        # 2. Unpack weights into layer-specific tensors
        # This step depends on the specific architecture of the decoder
        # For a simple MLP with L layers:
        params = unpack_weights(flat_weights, self.decoder_layer_dims)
        
        # 3. Evaluate the primary decoder with these dynamic weights
        # We must manually implement the forward pass of the decoder 
        # using the generated parameters to avoid re-initializing modules
        y = self.forward_decoder(x, params)
        return y

    def forward_decoder(self, x, params):
        """
        params: list of tuples (W_l, b_l) for each layer l
        """
        h = x
        for W, b in params:
            h = torch.matmul(h, W.t()) + b
            h = torch.relu(h) # Assuming ReLU activation
        return h

def unpack_weights(flat_weights, layer_dims):
    """
    Splits the flat weight vector into individual layer weights.
    layer_dims: list of [in_features, out_features] for each layer
    """
    params = []
    offset = 0
    for in_f, out_f in layer_dims:
        # Weights: [out_f, in_f]
        num_weights = out_f * in_f
        W = flat_weights[:, offset:offset + num_weights].view(-1, out_f, in_f)
        offset += num_weights
        
        # Biases: [out_f]
        num_biases = out_f
        b = flat_weights[:, offset:offset + num_biases].view(-1, out_f)
        offset += num_biases
        
        params.append((W, b))
    return params
```

## Subtopics

### Hybrid Conditioning
Hybrid Conditioning combines global and local latent codes [S1, unofficial]. It uses one global code to encode basic information shared between instances and several local codes to encode instance-specific details [S1, unofficial]. The local codes are assigned over a subset of spatio-temporal coordinates, allowing for region-specific or time-step-specific variations [S1, unofficial]. This approach is chosen when an object has both global structural similarities and local detailed variations.

## Operating characteristics
*   **Complexity:** The primary network complexity can be much lower than in shared-weight approaches because it does not need to learn the full variance of all instances [S1, unofficial].
*   **Memory:** Requires storing the HyperNetwork parameters and the latent codes. If the primary network is large, generating weights on-the-fly is memory-efficient compared to storing multiple full network instances.
*   **Performance:** Inference requires a forward pass through the HyperNetwork to generate weights, adding computational overhead per query compared to a simple lookup in a shared network.
*   **Strengths:** Enables distinct behaviors per instance without bloating the shared model capacity.
*   **Limitations:** Training can be unstable due to the nested optimization problem (gradients through generated weights).

## Background
HyperNetworks were introduced by Ha et al. in 2016 [S1, unofficial]. The application of HyperNetworks to Neural Fields for instance-specific conditioning was highlighted in recent basic research suggesting that the primary network complexity can be reduced [S1, unofficial][Galanti & Wolf, 2020]. This method is used in contexts requiring high variability across instances while maintaining a compact shared representation.
