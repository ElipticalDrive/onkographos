# Concatenation Conditioning
Also called: Latent Code Concatenation
## Overview
Concatenation Conditioning is a method for injecting instance-specific latent codes into a shared Neural Field decoder by appending the latent vector to the input query or feature descriptor. It solves the problem of modulating a single generative network to produce different outputs for different data instances (e.g., different volumes or transfer functions) without retraining the entire model. It is distinguished from [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md) by its simplicity and from [Autoencoder/Autodecoder Conditioning](12588-autoencoder-autodecoder-conditioning.md) by its explicit separation of encoder and decoder roles.
## How it works
### Inputs and Outputs
- **Input:** A query point $x$ (e.g., spatial coordinates), an explicit feature descriptor $d$ (e.g., Transfer Function descriptor), and a latent code $z_i \in \mathbb{R}^D$ associated with instance $i$.
- **Output:** The predicted value $y_i$ (e.g., illumination, density) for instance $i$ at query $x$.

### Data Structures
- **Latent Code ($z_i$):** A fixed-size vector of length $D$. Typical values for $D$ are 64, 256, or 512 [S1][S2, unofficial].
- **Feature Descriptor ($d$):** An explicit vector representing instance-specific properties (e.g., Transfer Function parameters).
- **Concatenated Input ($c_i$):** The tensor formed by joining $z_i$ and $d$ (or $x$).

### Steps
1. **Encode:** Process the input volume or instance data with an encoder network to extract the latent vector $z_i$ [S1].
2. **Concatenate:** Combine the latent code $z_i$ with the explicit feature descriptor $d$ (or input coordinates $x$) via concatenation:
   $$ c_i = \text{concat}(z_i, d) $$
   [S1]
3. **Decode:** Feed the concatenated tensor $c_i$ into the shared Neural Field decoder $f_\theta$:
   $$ y_i = f_\theta(c_i) $$
   [S1][S2, unofficial]

### Pseudocode
```python
def concatenate_conditioning_decode(decoder, latent_code, feature_descriptor):
    """
    Decodes a value using concatenation conditioning.
    
    Args:
        decoder: A neural network function f_theta that takes a concatenated vector.
        latent_code: Tensor of shape (D,), the instance-specific latent vector.
        feature_descriptor: Tensor of shape (K,), the explicit feature vector (e.g., TF descriptor).
        
    Returns:
        Tensor of shape (1,), the predicted output value.
    """
    # Concatenate latent code and feature descriptor
    # Note: Ensure dimensions align for concatenation along the feature axis
    concatenated_input = torch.cat((latent_code, feature_descriptor), dim=0)
    
    # Feed into the shared decoder
    output = decoder(concatenated_input)
    
    return output
```

### Parameters
- **Latent Dimension ($D$):** Hyperparameter, typically 512 [S1].
- **Feature Descriptor Dimension ($K$):** Depends on the explicit representation (e.g., number of TF control points).

### Edge Cases and Pitfalls
- **Limited Condition Propagation:** Only the first layer of the decoder directly incorporates the condition; remaining layers operate only on internal feature representations, requiring the network to distinguish samples based on input alone [S2, unofficial].
- **Re-execution Cost:** Requires re-execution of the feature extractor and decoder upon transfer function updates, although the compressed volume representation from the encoder stays constant [S1].
- **Precision:** Standard floating-point concatenation is used; no special bit-packing is required beyond standard tensor operations.

## Subtopics

### HyperNetwork Conditioning
Generates decoder weights from the latent code. Choose when per-instance weight adaptation is needed. [Link](12585-hypernetwork-conditioning.md)

### Autoencoder/Autodecoder Conditioning
Uses the decoder to reconstruct the input, often with a shared latent space. Choose for unsupervised or self-supervised learning. [Link](12588-autoencoder-autodecoder-conditioning.md)

### Global Conditioning
Uses global pooling or attention to inject conditions. Choose when spatial locality of conditions is important. [Link](12589-global-conditioning.md)

## Operating characteristics
- **Time Complexity:** $O(D + K)$ for concatenation; $O(N)$ for decoder evaluation, where $N$ is the number of parameters in the decoder.
- **Memory Complexity:** $O(D)$ for storing the latent code per instance.
- **Strengths:** Simple to implement; efficient inference as the encoder output is constant for a given instance [S1].
- **Limitations:** The condition is only directly visible to the first layer, potentially limiting the decoder's ability to use the condition for complex transformations [S2, unofficial].
- **When to Use:** When a simple, fast conditioning mechanism is sufficient and the decoder architecture allows the first layer to capture the necessary variance.

## Background
Originated in the context of conditional generative modeling for volumetric data, specifically for predicting volumetric ambient occlusion [S1]. The method leverages the established practice of concatenating latent vectors with input descriptors in generative networks [S1].
