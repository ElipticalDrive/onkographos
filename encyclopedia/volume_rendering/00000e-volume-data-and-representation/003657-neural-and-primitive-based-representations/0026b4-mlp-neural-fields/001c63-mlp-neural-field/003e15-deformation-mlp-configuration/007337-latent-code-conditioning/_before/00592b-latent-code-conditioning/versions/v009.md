# Latent Code Conditioning

Also called: Global Conditioning, Latent Vector Conditioning, Instance-Specific Neural Fields

## Overview
Latent Code Conditioning is a family of techniques that inject global context into a Neural Field by associating a data sample with a low-dimensional latent vector $z$ [S1, unofficial][S2]. It solves the problem of enabling a single neural field architecture to represent multiple distinct data instances, such as different shapes, transfer functions, or dynamic objects, without requiring separate networks for each instance [S1, unofficial][S2]. Unlike sibling methods that share decoder parameters across instances (e.g., [Concatenation Conditioning](12582-concatenation-conditioning.md)) or generate weights dynamically (e.g., [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md)), this family encompasses various strategies for how $z$ is integrated into the network's computation graph, ranging from direct concatenation to weight generation and optimization-based inference [S1, unofficial][S2].

## Shared principles
All methods in this family rely on the existence of a latent vector $z \in \mathbb{R}^D$ that encodes global information about a specific data instance [S1, unofficial][S2]. The dimensionality $D$ is typically 512, though specific applications may use smaller dimensions such as 64 or 256 [S1, unofficial][S2]. The core principle is that the neural field $f$ becomes a function of both the local query coordinates $x$ (and potentially direction $d$ or time $t$) and the global latent code $z$:
$$ y = f(x, z) $$
where $y$ represents the predicted volumetric properties (e.g., density, color, SDF) [S1, unofficial][S2]. The latent code $z$ can be obtained via an encoder network, optimized per-shape during inference, or generated by a secondary network (HyperNetwork) [S1, unofficial][S2]. The integration of $z$ into the network architecture varies by variant, but the goal remains consistent: to allow the network to modulate its output based on the global context provided by $z$ [S1, unofficial][S2].

## Subtopics

### [Concatenation Conditioning](12582-concatenation-conditioning.md)
Concatenation Conditioning is a method for injecting global context into a Neural Field by appending a latent code vector to the input feature tensor before it enters the decoder network. It solves the problem of enabling a single neural field architecture to represent multiple distinct data instances or conditions, such as different transfer functions in volumetric rendering. Unlike HyperNetwork Conditioning, which generates network weights, or AdaIN-based Global Conditioning, which modulates internal feature statistics, Concatenation Conditioning relies on the network's first layer to explicitly distinguish between input samples based on the concatenated input alone.

### [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md)
HyperNetwork Conditioning generates instance-specific weights for a Neural Field decoder using a secondary network (the HyperNetwork) driven by a latent code. Unlike sibling methods that share decoder parameters across instances (e.g., [Concatenation Conditioning](12582-concatenation-conditioning.md)), this approach creates a distinct Neural Field for each input, allowing the primary decoder's complexity to be significantly lower while maintaining high representational capacity.

### [Autoencoder/Autodecoder Conditioning](12588-autoencoder-autodecoder-conditioning.md)
Autoencoder/Autodecoder Conditioning enables a single neural field to represent multiple distinct geometric instances by associating each instance with a unique latent vector $z$. Unlike concatenation conditioning which injects $z$ into the coordinate stream, this method treats $z$ as a global context parameter optimized per-shape, allowing the network to learn a structured shape space rather than just overfitting a single geometry. It is chosen when the goal is to learn a manifold of shapes or to generalize across a dataset of similar objects, as opposed to rendering a single static scene.

### [Global Conditioning](12589-global-conditioning.md)
Global conditioning encodes the entire information of a data sample into a single latent vector $z$, allowing a neural field to represent distinct instances. It maps this global code to an intermediate non-linear latent space to modulate the radiance field, distinguishing itself from local conditioning which distributes information across spatial coordinates. It serves as the foundational step for [Latent Code Conditioning](16345-latent-code-conditioning.md), preceding variants like the [Global Generator](#global-generator) or [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md).

#### Local Conditioning
- **Definition**: Spreading information about a data sample over multiple latent codes assigned to specific subsets of spatio-temporal coordinates (regions or time steps) [S1, unofficial].
- **Comparison**: Unlike global conditioning which uses a single vector for the entire sample, local conditioning allows for spatially or temporally varying context [S1, unofficial].

#### Dynamic Object Radiance Field Conditioning
- **Definition**: A radiance field $\psi$ for dynamic objects conditioned by separate shape and appearance latent vectors [S2].
- **Steps**:
    1. Concatenate a shape code with the input coordinate $x$ at the network input [S2].
    2. Concatenate an appearance code with the direction $d$ at the bottleneck after density prediction [S2].
    3. Concatenate sequence and object appearance latent vectors to propagate sequence appearance to individual objects [S2].

#### Image Encoding
- **Definition**: Passes the appearance source image $A$ through a network to generate a latent code, which is then appended to the input voxels [S3].
- **Comparison**: Captures overall color but fails to assign it correctly to individual parts [S3].

#### Edit Code Mapping
- **Definition**: A process to map each edited 2D image $S_i^j$ into a latent feature vector $z_i^j \in \mathbb{R}^{64}$ named edit code to characterize diverse edits and solve the inconsistency problem in 3D scenes caused by 2D image-to-image translation generating different content for the same target [S4].
- **Steps**:
    1. Extract feature from edited image $S_i^j$ using an off-the-shelf VAE encoder $\mathcal{E}$ from stable diffusion [30] [S4].
    2. Apply a tiny MLP network $\mathcal{M}$ to produce the edit code $z_i^j$ [S4].
    3. Keep the pre-trained encoder fixed and only optimize the parameters of the tiny MLP network during training [S4].
- **Formula**:
    $$ \mathbf {z}_i^j = \mathcal {D}(\mathbf {S}_i^j) = \mathcal {M}(\mathcal {E}(\mathbf {S}_i^j)) $$
    where $\mathcal{D}$ represents the mapping process, $\mathcal{E}$ is the fixed encoder, and $\mathcal{M}$ is the learnable tiny MLP [S4].
- **Parameter**: Edit code dimension: $\mathbb{R}^{64}$ [S4].

## Background
The concept of global conditioning, where a single latent vector encodes the whole information about a data sample, was introduced in the context of Neural Fields to enable representation of multiple instances [S1, unofficial]. Local conditioning, which spreads information over multiple latent codes assigned to specific spatio-temporal coordinates, was also proposed as an alternative or hybrid approach [S1, unofficial]. The use of separate shape and appearance latent vectors for dynamic objects was detailed in work on Multi-Level Neural Scene Graphs for Dynamic Urban Environments [S2]. Image encoding methods for neural rendering, where a latent code from an appearance source image is appended to input voxels, were explored in the Neural Voxel Renderer [S3]. More recently, Edit Code Mapping was introduced in GenN2N to handle 3D scene inconsistencies arising from 2D image-to-image translation [S4].
