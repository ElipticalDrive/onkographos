# Concatenation Conditioning

Also called: Latent Code Concatenation

## Overview
Concatenation Conditioning is a method for integrating a latent code $z$ into a Neural Field by appending it to the input feature vector or spatial descriptor before feeding it to the decoder [S1][S2, unofficial]. It solves the problem of how to inject instance-specific or conditional information into a generative model that maps spatial coordinates to output values [S1][S2, unofficial]. Unlike HyperNetwork Conditioning, which predicts weights, or Global Conditioning via Mapping Networks, which transforms the latent space, Concatenation Conditioning directly mixes the condition with the input data [S2, unofficial]. It is distinct from Local Conditioning because it typically applies a single global latent code to all spatial queries rather than distributing codes across regions [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A spatial query point $x \in \Omega$ (e.g., 3D coordinates), an optional explicit descriptor $d$ (e.g., Transfer Function parameters), and a latent code $z \in \mathcal{Z}$ representing the global context of the data sample [S1][S2, unofficial].
*   **Output:** The predicted value $\hat{y} \in \mathcal{X}$ (e.g., density, color, ambient occlusion) [S1][S2, unofficial].

**Data Structures:**
*   **Latent Code ($z$):** A low-dimensional vector. A common dimensionality is 512 [S1]. In specific applications like edit code mapping, dimensions such as 64 are used .
*   **Input Descriptor ($d$):** Explicit features associated with the query, such as Transfer Function (TF) descriptors [S1].
*   **Concatenated Tensor ($c$):** The result of joining $z$ and $d$ (and potentially $x$) along the feature dimension.

**Steps:**
1.  **Encode:** Process the input volume or data sample with an encoder network to extract the latent vector $z$ [S1]. This step is performed once per sample and the result remains constant during inference updates to the descriptor [S1].
2.  **Concatenate:** Combine the latent code $z$ with the explicit descriptor $d$ (and optionally the spatial coordinates $x$) via concatenation [S1][S2, unofficial].
    $$ c = \text{concat}(z, d) $$
    The resulting vector $c$ contains global information about both the volume modality and the conditioning context [S1].
3.  **Decode:** Feed the concatenated tensor $c$ into the Neural Field decoder (generative network) [S1][S2, unofficial].
    $$ \hat{y} = f_{\theta}(c) $$
    where $f_{\theta}$ is the decoder network parameterized by $\theta$ [S2, unofficial].

**Pseudocode:**
```python
def concatenate_conditioning_decode(decoder, latent_code, descriptor, coordinates):
    """
    Predicts output by concatenating latent code and descriptor.
    
    Args:
        decoder: Neural network function f_theta.
        latent_code: Tensor of shape (batch_size, latent_dim), e.g., 512.
        descriptor: Tensor of shape (batch_size, desc_dim), e.g., TF parameters.
        coordinates: Tensor of shape (batch_size, 3), spatial coordinates.
        
    Returns:
        predictions: Tensor of predicted values.
    """
    # Step 1: Concatenate latent code with explicit descriptor
    # Note: Coordinates may also be concatenated depending on the specific Neural Field architecture.
    # Here we follow the source description of combining latent vector with TF descriptor.
    combined_input = torch.cat([latent_code, descriptor], dim=-1)
    
    # Step 2: Feed concatenated tensor into the generative decoder
    # The decoder processes this combined vector to predict the output (e.g., illumination)
    predictions = decoder(combined_input)
    
    return predictions
```

**Parameters:**
*   **Latent Dimension:** Typically 512 [S1].
*   **Concatenation Axis:** The feature dimension (last axis in standard batched tensors) [S1][S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Layer Isolation:** Only the first layer of the decoder directly incorporates the condition. Remaining layers operate only on internal feature representations, requiring the network to distinguish samples based on the initial input alone [S2, unofficial].
*   **Re-execution Cost:** While the compressed volume representation from the encoder stays constant, the TF extractor and decoder must be re-executed upon Transfer Function updates [S1].

## Operating characteristics
*   **Time Complexity:** Encoding is $O(1)$ per sample (precomputed). Decoding is $O(N)$ where $N$ is the number of query points, with a slight increase in input dimensionality due to concatenation.
*   **Memory Complexity:** Requires storing the latent code $z$ per sample. The decoder weights are shared across all samples [S2, unofficial].
*   **Strengths:** Simple to implement; proven useful in conditional generative modeling [S1]. Efficient during inference when the latent code is fixed but descriptors change, as the encoder does not need re-execution [S1].
*   **Limitations:** The condition is only directly visible to the first layer, potentially limiting the network's ability to use the condition deeply within the feature hierarchy [S2, unofficial].
*   **When to use:** When a global, instance-specific latent code is available and computational simplicity is preferred over sophisticated modulation mechanisms [S1][S2, unofficial].

## Background
Concatenation Conditioning is a standard injection strategy for explicit representations in neural fields [S1]. It is derived from general conditional generative modeling techniques [S1]. The specific application to volumetric ambient occlusion was proposed in "Deep Volumetric Ambient Occlusion" [S1]. The theoretical context of neural field conditioning and latent space integration is discussed in "Introduction to Neural Fields" [S2, unofficial].
