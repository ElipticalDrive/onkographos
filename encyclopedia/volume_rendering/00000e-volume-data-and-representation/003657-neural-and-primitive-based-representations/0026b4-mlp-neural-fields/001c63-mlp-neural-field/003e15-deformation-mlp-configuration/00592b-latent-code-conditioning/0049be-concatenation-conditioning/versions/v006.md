# Concatenation Conditioning

Also called: Latent Code Concatenation

## Overview
Concatenation Conditioning is a method for injecting global context into a neural field by appending a latent vector $z$ to the local input features before decoding [S1][S2, unofficial]. It solves the problem of enabling a single neural network to represent multiple data instances or conditions (such as different transfer functions) by providing a global identifier alongside local query coordinates [S1][S2, unofficial]. Unlike [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md), which generates weights, or [Autoencoder/Autodecoder Conditioning](12588-autoencoder-autodecoder-conditioning.md), which optimizes latent codes per-shape, Concatenation Conditioning directly modifies the input tensor, making it the simplest but potentially least expressive injection strategy [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Local query coordinates $x$ (and potentially direction $d$ or time $t$), and a global latent vector $z \in \mathbb{R}^D$ [S1][S2, unofficial].
*   **Output:** Volumetric properties $y$ (e.g., density, color, ambient occlusion) [S1][S2, unofficial].

**Data Structures:**
*   **Latent Vector ($z$):** A fixed-size vector encoding global information. The dimensionality $D$ is typically 512, though smaller dimensions like 64 or 256 are possible [S1][S2, unofficial].
*   **Input Tensor:** The concatenation of the local feature descriptor (e.g., TF descriptor or coordinates) and $z$ [S1][S2, unofficial].

**Steps:**
1.  **Encode:** Process the input volume (or data instance) with an encoder network to extract the latent vector $z$ [S1].
2.  **Concatenate:** Append $z$ to the local input features $x$ (or explicit descriptor) along the feature dimension [S2, unofficial].
    $$ x_{combined} = [x; z] $$
3.  **Decode:** Feed $x_{combined}$ into the first layer of the neural field decoder [S2, unofficial].
4.  **Predict:** The decoder outputs the volumetric properties $y$ [S1][S2, unofficial].

**Pitfalls:**
*   **Limited Layer Access:** Only the first layer directly incorporates the condition $z$. Subsequent layers operate only on internal feature representations derived from the first layer, requiring the network to propagate the condition implicitly [S2, unofficial].
*   **Re-execution Cost:** When conditions change (e.g., transfer function updates), the TF extractor and decoder must be re-executed, although the encoder's compressed volume representation remains constant [S1].

**Pseudocode:**
```python
def concat_conditioning_decode(x_local, z_latent, decoder_network):
    """
    x_local: Tensor of local features/coordinates [B, L]
    z_latent: Tensor of global latent codes [B, D]
    decoder_network: Neural network function
    """
    # Concatenate local features with global latent code
    # Assuming both are batched and aligned
    x_combined = torch.cat([x_local, z_latent], dim=-1)
    
    # Feed into the decoder
    # Note: Only the first layer sees z directly; subsequent layers
    # see only the transformed features from the first layer [S2, unofficial]
    y = decoder_network(x_combined)
    
    return y
```

## Subtopics

### HyperNetwork Conditioning
Generates decoder weights from $z$ rather than concatenating inputs. Chose when dynamic weight adaptation is needed. [HyperNetwork Conditioning](12585-hypernetwork-conditioning.md)

### Autoencoder/Autodecoder Conditioning
Optimizes $z$ per-shape during inference. Chose when per-instance optimization is feasible. [Autoencoder/Autodecoder Conditioning](12588-autoencoder-autodecoder-conditioning.md)

### Global Conditioning
Uses a separate global network branch. Chose when global features need complex non-linear processing before injection. [Global Conditioning](12589-global-conditioning.md)

## Operating characteristics
*   **Complexity:** Time complexity is dominated by the encoder (once per instance) and the decoder (per query). Memory complexity includes storing $z$ per instance [S1][S2, unofficial].
*   **Strengths:** Simple to implement; efficient inference if $z$ is pre-computed [S1].
*   **Limitations:** Less expressive than HyperNetworks because $z$ is only visible to the first layer [S2, unofficial].
*   **Use Case:** Suitable for conditional generation where the condition is static per query batch (e.g., different transfer functions for the same volume) [S1].

## Background
Originated in volumetric ambient occlusion research, where it was used to condition illumination prediction on both volume modality and transfer function [S1]. It is a standard technique in conditional generative modeling [S1].
