# HyperNetwork Conditioning

Also called: Hypernetwork-based conditioning, HyperNet conditioning

## Overview
HyperNetwork Conditioning generates instance-specific weights for a Neural Field decoder using a secondary network (the HyperNetwork) driven by a latent code [S1, unofficial]. Unlike Concatenation Conditioning, which shares a single set of decoder weights across all instances and relies on the latent code to modulate activations, HyperNetwork Conditioning creates a distinct Neural Field (a unique set of parameters) for each input instance [S1, unofficial]. This separation allows the primary decoder network to maintain lower complexity, potentially yielding a more compact representation [S1, unofficial].

## How it works
**Inputs:**
*   Latent code $z_i \in \mathbb{R}^D$ for instance $i$.
*   Spatial coordinates $x \in \mathbb{R}^3$ (or 2D/4D for spatio-temporal).
*   HyperNetwork parameters $\phi$.
*   Base Decoder parameters $\theta_{base}$ (optional, often initialized to zero or small values).

**Outputs:**
*   Density $\sigma$ and color $c$ (or other attributes) for instance $i$ at location $x$.

**Data Structures:**
*   **HyperNetwork:** A neural network $H_\phi$ that maps $z_i$ to a vector of weights.
*   **Decoder:** A neural network $D_{\theta_i}$ where $\theta_i$ are the weights generated by $H_\phi$.

**Steps:**
1.  **Encode Latent:** Input the instance latent code $z_i$ into the HyperNetwork $H_\phi$.
2.  **Generate Weights:** The HyperNetwork outputs a vector of parameters $\theta_i$. This vector contains all weights and biases required by the target Neural Field decoder.
    $$ \theta_i = H_\phi(z_i) $$
3.  **Construct Decoder:** Reshape $\theta_i$ into the specific weight matrices and bias vectors required by the decoder architecture. Let the decoder be defined by layers $L_1, \dots, L_k$. The weights for layer $j$ are extracted from $\theta_i$ as $W^{(j)}_i, b^{(j)}_i$.
4.  **Evaluate Field:** Pass the spatial coordinate $x$ through the decoder $D_{\theta_i}$ using the generated weights to produce the output.
    $$ [\sigma, c] = D_{\theta_i}(x) $$

**Pseudocode:**
```python
def hypernetwork_conditioning(z_i, x, hypernet, decoder_arch):
    """
    z_i: Latent code vector for instance i.
    x: Spatial coordinate vector.
    hypernet: Function representing the HyperNetwork H_phi.
    decoder_arch: Definition of the target Neural Field structure (layer sizes, activation functions).
    """
    # Step 1 & 2: Generate instance-specific weights
    # The hypernet outputs a flat vector of all parameters needed for the decoder
    theta_i = hypernet(z_i)
    
    # Step 3: Unpack weights into the decoder's layer structure
    # This step depends on the specific architecture of the decoder.
    # For a simple MLP with 2 hidden layers:
    # Assume decoder_arch defines layer dimensions: [input_dim, h1, h2, output_dim]
    # And we know the size of weights/biases for each layer.
    
    # Example unpacking for a 2-layer MLP (simplified)
    # In practice, this requires precise mapping of theta_i indices to W1, b1, W2, b2
    W1, b1, W2, b2 = unpack_weights(theta_i, decoder_arch)
    
    # Step 4: Evaluate the decoder with generated weights
    # Forward pass through the decoder using the generated parameters
    h1 = activation(x @ W1.T + b1)
    h2 = activation(h1 @ W2.T + b2)
    output = h2 # Typically density and color are concatenated or split here
    
    return output
```

**Parameters:**
*   Latent dimension $D$: Typically 512, though 64 or 256 are used [S1, unofficial].
*   HyperNetwork depth/width: Not specified in sources.

**Edge Cases:**
*   **Weight Initialization:** If the HyperNetwork outputs weights that are poorly scaled, the decoder may fail to converge. [G] Common practice involves initializing the HyperNetwork to output small weights or using residual connections to stabilize training.
*   **Memory:** Storing a full set of weights for every instance can be memory-intensive if the decoder is large. [G] The HyperNetwork itself is usually small, but the generated weights $\theta_i$ must be stored or recomputed per instance.

## Subtopics

### Hybrid Conditioning
Hybrid Conditioning combines global and local latent codes. It uses one global code to encode basic information shared between instances and several local codes to encode instance-specific details [S1, unofficial]. The HyperNetwork likely takes the concatenation or combination of these codes to generate the final weights, allowing for both shared structural priors and specific variations.

## Operating characteristics
*   **Complexity:** The primary Neural Field decoder can be much simpler (lower complexity) compared to concatenation-based methods because it does not need to encode instance identity within its weights [S1, unofficial].
*   **Memory:** Requires storing the HyperNetwork parameters and the latent codes. If weights are generated on-the-fly, no per-instance decoder weights are stored, but computation increases. If pre-computed, memory usage scales with the number of instances and decoder size.
*   **Performance:** Generating weights adds computational overhead per query compared to a single shared decoder. However, the reduced complexity of the decoder may offset this for high-dimensional outputs.
*   **Use Cases:** Suitable when instances share a common underlying structure but require significant variation, or when the decoder needs to be very shallow/compact.

## Background
HyperNetworks were introduced by Ha et al. in 2016 [S1, unofficial]. The application of HyperNetworks to Neural Fields for volume rendering and implicit representations was discussed in recent basic research suggesting that the complexity of the primary network can be significantly reduced [S1, unofficial][Galanti & Wolf, 2020]. The specific application to neural fields is detailed in introductory resources on the topic [S1, unofficial].
