# HyperNetwork Conditioning

Also called: Hypernetwork-based conditioning, HyperNet conditioning

## Overview
HyperNetwork Conditioning modulates a shared neural field decoder by predicting its weights directly from a latent code, rather than concatenating the code to the input. This creates a distinct neural field (a unique set of weights) for each input instance, allowing the primary decoder network to maintain lower complexity compared to concatenation-based methods [S1, unofficial].

## How it works
HyperNetwork Conditioning replaces the standard concatenation of the latent code $z$ with the query point $x$ by using a secondary network (the HyperNetwork) to generate the decoder's parameters.

**Inputs and Outputs:**
*   **Input:** A latent code vector $z \in \mathbb{R}^D$ associated with a specific instance.
*   **Output:** A set of weights $\theta_{instance}$ for the Neural Field decoder $f_{\theta_{instance}}$.

**Data Structures:**
1.  **HyperNetwork ($h_\phi$):** A neural network with parameters $\phi$. It takes $z$ as input and outputs the concatenated weights of the decoder.
2.  **Decoder Weights ($\theta_{instance}$):** The output of $h_\phi(z)$. These weights define the instance-specific neural field.

**Steps:**
1.  **Encode:** Obtain the latent code $z$ for the target instance.
2.  **Generate Weights:** Pass $z$ through the HyperNetwork to predict the decoder parameters:
    $$ \theta_{instance} = h_\phi(z) $$
    The HyperNetwork architecture must match the structure of the decoder's weights (e.g., if the decoder has layers with weights $W_1, W_2$, the HyperNetwork outputs flattened tensors of corresponding shapes).
3.  **Decode:** Evaluate the instance-specific neural field $f_{\theta_{instance}}$ at query points $x$:
    $$ y = f_{\theta_{instance}}(x) $$

**Parameters:**
*   **HyperNetwork Depth/Width:** Not specified in sources. Must be sufficient to map $z$ to the full weight space of the decoder.
*   **Latent Dimension ($D$):** Typically 64, 256, or 512, consistent with general latent code conditioning [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Weight Space Dimensionality:** The output dimension of the HyperNetwork must exactly match the total number of parameters in the decoder. Mismatched dimensions cause implementation failure.
*   **Optimization Stability:** Predicting weights directly can be more sensitive to initialization and learning rates than predicting activations or biases, as the scale of weight updates is coupled to the HyperNetwork's output [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn

class HyperNetworkDecoder(nn.Module):
    def __init__(self, decoder_arch, latent_dim):
        super().__init__()
        # decoder_arch defines the structure of the primary neural field
        # e.g., list of layer sizes for an MLP
        self.decoder_arch = decoder_arch
        
        # Calculate total number of parameters in the decoder
        # This assumes a simple MLP structure for calculation
        total_params = 0
        for i, (in_dim, out_dim) in enumerate(decoder_arch):
            total_params += in_dim * out_dim + out_dim # weights + biases
        self.total_params = total_params
        
        # HyperNetwork: maps latent code z to decoder weights
        # Input: latent_dim
        # Output: total_params
        self.hypernet = nn.Sequential(
            nn.Linear(latent_dim, 512),
            nn.ReLU(),
            nn.Linear(512, 512),
            nn.ReLU(),
            nn.Linear(512, self.total_params)
        )
        
        # Initialize the primary decoder with dummy weights
        # The actual weights will be replaced by hypernet output
        self.decoder = self._build_decoder(decoder_arch)

    def _build_decoder(self, arch):
        layers = []
        for i, (in_dim, out_dim) in enumerate(arch):
            layers.append(nn.Linear(in_dim, out_dim))
            if i < len(arch) - 1: # No activation after last layer usually
                layers.append(nn.ReLU())
        return nn.Sequential(*layers)

    def forward(self, x, z):
        """
        x: query points [N, input_dim]
        z: latent codes [N, latent_dim]
        """
        # 1. Generate instance-specific weights
        weight_vector = self.hypernet(z) # [N, total_params]
        
        # 2. Reshape weights to match decoder layer shapes
        # This step requires knowing the exact shape of each layer's weights
        # For simplicity, we assume a helper function exists to split the vector
        # In practice, this involves reshaping and assigning to nn.Parameter buffers
        # or using a custom forward pass that applies these weights directly.
        
        # Note: Directly replacing nn.Parameter buffers in a batched manner 
        # is complex. A common implementation is to compute the forward pass 
        # manually using the generated weights.
        
        # Manual forward pass using generated weights
        current_input = x
        weight_idx = 0
        
        for i, (in_dim, out_dim) in enumerate(self.decoder_arch):
            # Extract weights and biases for this layer
            num_weights = in_dim * out_dim
            num_biases = out_dim
            
            W = weight_vector[:, weight_idx : weight_idx + num_weights].view(-1, in_dim, out_dim)
            b = weight_vector[:, weight_idx + num_weights : weight_idx + num_weights + num_biases]
            
            # Apply linear transformation: y = x @ W + b
            # x: [N, in_dim], W: [N, in_dim, out_dim], b: [N, out_dim]
            # Result: [N, out_dim]
            current_input = torch.bmm(current_input.unsqueeze(1), W).squeeze(1) + b
            
            if i < len(self.decoder_arch) - 1:
                current_input = torch.relu(current_input)
            
            weight_idx += num_weights + num_biases
            
        return current_input
```

## Subtopics

### Hybrid Conditioning
Hybrid Conditioning combines global and local latent codes. It uses one global code to encode basic information shared between instances and several local codes to encode instance-specific details assigned to subsets of spatio-temporal coordinates [S1, unofficial]. This approach allows the model to capture both common structural features and fine-grained local variations.

## Operating characteristics
*   **Complexity:** The primary neural field decoder can be significantly smaller (lower complexity) than in concatenation-based methods because the instance-specific variation is handled by the HyperNetwork's weight generation rather than requiring a large, expressive decoder to interpret a concatenated code [S1, unofficial].
*   **Memory:** Requires storing the HyperNetwork parameters in addition to the decoder architecture definition. The decoder weights themselves are not stored per instance; they are generated on the fly.
*   **Performance:** Generating weights for each instance adds computational overhead during inference compared to a simple lookup or concatenation. However, the reduced decoder size may offset this in terms of memory bandwidth and cache efficiency.
*   **Strengths:** Enables compact representation of multiple instances; theoretically allows for lower decoder complexity.
*   **Limitations:** Training can be unstable; the HyperNetwork must learn to map latent codes to valid weight spaces; implementation complexity is higher due to dynamic weight generation.

## Background
HyperNetworks were introduced by Ha et al. in 2016 [S1, unofficial]. The application of HyperNetworks to Neural Fields for volume rendering and implicit shape representation was discussed in the context of neural field conditioning by inovex GmbH [S1, unofficial]. Recent research suggests that HyperNetworks can hint at more compact representations by allowing the primary network complexity to be much lower [S1, unofficial][Galanti & Wolf, 2020].
