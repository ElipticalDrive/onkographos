# HyperNetwork Conditioning

Also called: Hypernetwork-based conditioning, HyperNet conditioning

## Overview
HyperNetwork Conditioning generates instance-specific neural field weights by using a secondary network (the HyperNetwork) to predict the parameters of the primary decoder from a latent code [S1, unofficial]. Unlike Concatenation Conditioning, which shares a single set of decoder weights across all instances and relies on the latent code to modulate features, HyperNetwork Conditioning creates a distinct neural field for each input instance [S1, unofficial]. This separation allows the primary network to maintain lower complexity, potentially yielding a more compact representation [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A latent code $z \in \mathbb{R}^D$ encoding instance-specific information.
- Output: The weight tensors $W$ of the primary Neural Field decoder.

**Data Structures:**
- Latent Code $z$: A vector of dimension $D$ (typically 512, or 64/256 in specific applications).
- HyperNetwork: A neural network $H$ that maps $z$ to the weight space of the decoder.
- Primary Decoder: A neural network $f$ parameterized by weights $W$, which maps spatial coordinates $x$ to volumetric properties $y$.

**Steps:**
1. Encode the instance into a latent vector $z$.
2. Pass $z$ through the HyperNetwork $H$ to generate the weight tensors $W$ for the primary decoder:
   $$ W = H(z) $$
3. Query the primary decoder $f$ with coordinates $x$ using the generated weights $W$:
   $$ y = f(x; W) $$

**Parameters:**
- Latent dimension $D$: Not given in the sources.
- HyperNetwork architecture: Not given in the sources.

**Edge Cases and Pitfalls:**
- The HyperNetwork must be trained jointly with the primary decoder or via meta-learning strategies to ensure the predicted weights produce valid outputs [S1, unofficial].
- Precision issues may arise if the HyperNetwork outputs weights that are ill-conditioned for the primary decoder's activation functions [G].

## Subtopics

### Hybrid Conditioning
Hybrid Conditioning combines global and local latent codes [S1, unofficial]. It uses one global code to encode basic information shared between instances and several local codes to encode instance-specific details assigned to subsets of spatio-temporal coordinates [S1, unofficial]. This approach allows for both shared structural priors and fine-grained instance variation [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Memory: Requires storing the HyperNetwork parameters in addition to the primary decoder weights. The primary decoder weights are regenerated per instance, so they do not need to be stored for all instances simultaneously if generated on-the-fly [S1, unofficial].
- Time: Inference requires an additional forward pass through the HyperNetwork to generate weights before querying the primary decoder [S1, unofficial].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- The complexity of the primary network can be lower compared to concatenation-based methods, as it does not need to encode instance-specific variations [S1, unofficial].

**Strengths and Limitations:**
- Strengths: Enables distinct neural fields per instance; allows for lower primary network complexity [S1, unofficial].
- Limitations: Requires training a HyperNetwork; potentially higher computational overhead during inference due to weight generation [S1, unofficial].

**When to Use:**
- Use when instance-specific variations are significant and cannot be efficiently encoded via feature modulation alone, or when a more compact primary network is desired [S1, unofficial].

## Background
HyperNetworks were introduced by Ha et al. in 2016 [S1, unofficial]. In the context of Neural Fields, HyperNetwork Conditioning was highlighted as a method to create instance-specific decoders, with recent research suggesting benefits in network compactness [Galanti & Wolf, 2020; S1, unofficial].
