# HyperNetwork Conditioning

Also called: Hypernetwork-based conditioning, HyperNet

## Overview
HyperNetwork Conditioning generates instance-specific decoder weights by passing a latent code through a secondary network (the HyperNetwork), resulting in a unique Neural Field for each input instance [S1, unofficial]. Unlike Concatenation Conditioning, which shares a single set of decoder weights across all instances, this method allows the primary decoder network to have significantly lower complexity while maintaining high representational capacity [S1, unofficial].

## How it works
**Inputs:**
*   Latent code $z_i \in \mathbb{R}^D$ for instance $i$.
*   Query point $x$ (spatial coordinates).
*   HyperNetwork parameters $\phi$.
*   Base decoder architecture definition (e.g., MLP depth, width, activation).

**Outputs:**
*   Instance-specific decoder weights $\theta_i$.
*   Volume density/opacity $\sigma_i$ and color $c_i$ at $x$.

**Data Structures:**
*   $z_i$: Vector of dimension $D$. Common values are $D=512$ for volumetric applications or $D=256$ for shape space learning [S1, unofficial].
*   $\theta_i$: Flattened vector of all weights and biases in the decoder MLP.
*   $h_\phi$: The HyperNetwork MLP.

**Steps:**
1.  **HyperNetwork Forward Pass:** Compute the instance-specific weights by passing the latent code through the HyperNetwork:
    $$ \theta_i = h_\phi(z_i) $$
    The HyperNetwork $h_\phi$ maps $\mathbb{R}^D \to \mathbb{R}^W$, where $W$ is the total number of parameters in the decoder.
2.  **Weight Reshaping:** Reshape the vector $\theta_i$ into the specific tensor shapes required by the decoder layers (e.g., weight matrices $W_l$ and bias vectors $b_l$ for each layer $l$).
3.  **Instance-Specific Decoding:** Evaluate the decoder $f_{\theta_i}$ at query point $x$:
    $$ y_i = f_{\theta_i}(x) $$
    where $y_i$ represents the predicted volume properties (e.g., density $\sigma$, color $c$).

**Pseudocode:**
```python
def hypernetwork_conditioning(z_i, x, hypernet, decoder_arch):
    """
    z_i: latent code vector
    x: query coordinate vector
    hypernet: function mapping z -> theta
    decoder_arch: definition of decoder layer sizes and activations
    """
    # Step 1: Generate weights
    theta_i = hypernet(z_i)
    
    # Step 2: Reshape weights into layer-specific tensors
    # Implementation detail: Split theta_i according to decoder_arch parameter counts
    layer_weights = reshape_weights(theta_i, decoder_arch)
    
    # Step 3: Evaluate decoder with generated weights
    # This is a standard MLP forward pass using the generated weights
    output = evaluate_mlp(x, layer_weights)
    
    return output
```

**Edge Cases and Pitfalls:**
*   **Memory:** Storing distinct weights $\theta_i$ for every instance increases memory usage compared to shared weights.
*   **Training Stability:** The HyperNetwork must learn to map latent codes to valid decoder weights; poor initialization can lead to unstable gradients [S1, unofficial].
*   **Complexity:** While the primary decoder can be smaller, the total parameter count includes the HyperNetwork, which must be sized to output the full weight vector of the decoder [S1, unofficial].

## Subtopics

### Hybrid Conditioning
Uses a combination of global and local latent codes. One global code encodes information shared across all instances, while several local codes encode instance-specific details [S1, unofficial]. This approach allows the HyperNetwork to handle specific variations while the global code maintains structural consistency.

## Operating characteristics
*   **Complexity:** Allows the primary Neural Field decoder to have lower complexity (fewer parameters) compared to a single large shared decoder, as the HyperNetwork offloads the complexity of representing instance differences [S1, unofficial].
*   **Memory:** Higher memory footprint than Concatenation Conditioning because each instance requires its own set of decoder weights $\theta_i$ to be stored or recomputed.
*   **Performance:** Inference requires an additional forward pass through the HyperNetwork to generate weights before evaluating the decoder.
*   **Use Case:** Suitable when instances are highly diverse and a single shared decoder cannot capture the variations efficiently, or when the number of instances is manageable relative to the cost of weight generation.

## Background
The concept originates from the use of HyperNetworks [Ha et al., 2016] in neural network parameter prediction. In the context of Neural Fields, it was highlighted as an intriguing alternative to concatenation-based conditioning for creating instance-specific representations [S1, unofficial]. Recent research suggests that this approach can lead to more compact representations by reducing the complexity of the primary network [Galanti & Wolf, 2020].
