# Autoencoder/Autodecoder Conditioning

Also called: Conditional Neural Field

## Overview
Autoencoder and Autodecoder Conditioning are training paradigms for Latent Code Conditioning that determine how the latent vector $z$ is acquired to modulate a Neural Field $f: (\Omega, \mathcal{Z}) \mapsto \mathcal{X}$ [S1, unofficial][S2]. The Autoencoder approach uses a dedicated encoder network to map input data to $z$, while the Autodecoder approach treats $z$ as a learnable parameter optimized jointly with the decoder weights for each sample [S1, unofficial]. This method enables the representation of multiple distinct instances (e.g., shapes or images) within a single shared neural field architecture [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Spatial coordinates $\Omega$ (e.g., 3D points or 2D image coordinates) and a latent code $z \in \mathcal{Z}$.
*   **Output:** Signal value in $\mathcal{X}$ (e.g., density, color, SDF value).

**Data Structures:**
*   **Latent Code ($z$):** A low-dimensional vector. Common dimensionality is 512 [S1, unofficial][S2]. In specific applications like edit code mapping, dimensions such as 64 are used .
*   **Decoder Network:** A neural network (MLP) that accepts concatenated inputs of coordinates and $z$.

**Training Paradigms:**
1.  **Autoencoder:** An encoder network processes the input data to produce the latent code $z$ [S1, unofficial].
2.  **Autodecoder:** The latent code $z$ is treated as a learnable parameter optimized jointly with the decoder weights for each sample [S1, unofficial].

**Integration:**
The latent code $z$ is typically concatenated with the input spatial coordinates before being passed to the decoder network [S1, unofficial][S2].

**Pitfalls:**
*   In some frameworks (e.g., SDF/DDF), the Signed Distance Field (SDF) and Directional Distance Field (DDF) share the same latent code for a given shape [S2].
*   Precision issues may arise if the latent space is not properly regularized, leading to poor generalization or overfitting to individual instances.

## Subtopics

### Latent Code Regularizer
A regularization term applied to the latent codes to prevent them from growing arbitrarily large and to enforce similarity between different shapes in the autodecoder framework [S2]. It is defined as the L2 norm of the latent code:
$$ \mathcal{L}_{l}(z) = \|z\|_2 $$
where $z$ is the latent code for a given shape [S2]. This term is often included in the total training loss:
$$ \mathcal{L} = w_{s}\mathcal{L}_{s} + w_{d}\mathcal{L}_{d} + w_{\sigma }\mathcal{L}_{\sigma } + w_{tv}\mathcal{L}_{tv} + w_{ts}\mathcal{L}_{ts} + w_{l}\mathcal{L}_{l} $$
[S2]. A key implementation detail is that the SDF and DDF models share the same latent code for a given shape [S2].

## Operating characteristics
*   **Memory:** Requires storing one latent vector $z$ per instance in the dataset. For $N$ instances, this adds $N \times \dim(z)$ parameters to the model [S1, unofficial][S2].
*   **Training Time:** Autodecoders require optimizing $N$ latent vectors simultaneously with the network weights, which can be slower than standard supervised training but avoids the need for an encoder network [S1, unofficial].
*   **Strengths:** Enables compact representation of multiple shapes/images with a single network; Autodecoder avoids encoder training overhead [S1, unofficial].
*   **Limitations:** Latent codes are instance-specific and do not generalize to unseen shapes without re-optimization [S1, unofficial].

## Background
The concept of conditioning neural fields on latent codes was introduced to overcome the limitation of overfitting a single image or shape [S1, unofficial]. The autoencoder and autodecoder formulations are standard approaches in this domain [S1, unofficial]. The FIRe method utilizes an autodecoder framework with latent code regularization for inverse rendering [S2].
