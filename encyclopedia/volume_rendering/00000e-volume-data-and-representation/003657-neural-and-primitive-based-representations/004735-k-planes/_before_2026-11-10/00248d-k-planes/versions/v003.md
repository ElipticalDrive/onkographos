# K-planes
Also called: hex-planes, k-planes factorization, tri-planes

## Overview
K-planes is a white-box, interpretable radiance field representation that factorizes a $d$-dimensional scene into $k = \binom{d}{2}$ 2D feature planes, one for every unique pair of dimensions [S1]. It solves the scaling and memory limitations of dense voxel grids and the opacity of black-box MLPs by using explicit planar features combined via element-wise multiplication [S1]. Unlike sibling methods that add plane features (e.g., [TriPlane NeRF](6932-triplane-nerf.md) or [TensoRF](6932-triplane-nerf.md)), K-planes multiplies them, enabling spatially localized signals and allowing a linear decoder to replace the MLP decoder without quality loss [S1].

## How it works
**Inputs:** A set of training images with known camera poses and, for dynamic scenes, timestamps.
**Outputs:** A scene function $F_\Theta: \mathbb{R}^d \rightarrow \mathbb{R}^k$ (typically density $\sigma$ and color $\mathbf{c}$) and optimized 2D feature planes.

**Data Structures:**
The core data structure is a set of $k$ 2D feature planes $\mathbf{P} = \{\mathbf{P}_c\}_{c \in C}$.
*   For static 3D scenes ($d=3$), $k=3$ (tri-planes): $\mathbf{P}_{xy}, \mathbf{P}_{xz}, \mathbf{P}_{yz}$.
*   For dynamic 4D scenes ($d=4$), $k=6$ (hex-planes): $\mathbf{P}_{xy}, \mathbf{P}_{xz}, \mathbf{P}_{yz}$ (space-only) and $\mathbf{P}_{xt}, \mathbf{P}_{yt}, \mathbf{P}_{zt}$ (space-time).
*   Each plane $\mathbf{P}_c$ has shape $N \times N \times M$, where $N$ is the spatial/temporal resolution and $M$ is the feature dimension.
*   Multiscale support: Multiple copies of planes exist at resolutions $N \in \{64, 128, 256, 512\}$. Features from all scales are concatenated.

**Steps:**
1.  **Normalization:** Normalize query coordinate $\mathbf{q} \in \mathbb{R}^d$ to $[0, N)$. For forward-facing scenes, apply Normalized Device Coordinates (NDC) [S1]. For unbounded scenes, apply $\ell_\infty$ scene contraction [S1].
2.  **Projection:** For each plane $c \in C$, project $\mathbf{q}$ onto the 2D axes defining that plane to get 2D coordinates $\pi_c(\mathbf{q})$ [S1].
3.  **Interpolation:** Perform multiscale bilinear interpolation on each plane at $S$ scales to retrieve feature vectors $\mathbf{f}(\mathbf{q})_c$ [S1].
    $$ \mathbf{f}(\mathbf{q})_c = \psi(\mathbf{P}_c, \pi_c(\mathbf{q})) $$
    where $\psi$ denotes bilinear interpolation [S1].
4.  **Combination:** Multiply the feature vectors from all $k$ planes element-wise (Hadamard product) to produce a combined feature vector $\mathbf{f}(\mathbf{q})$ of length $M$ [S1].
    $$ \mathbf{f}(\mathbf{q}) = \prod_{c \in C} \mathbf{f}(\mathbf{q})_c $$
    [S1]
5.  **Concatenation:** Concatenate the combined feature vectors from all $S$ scales [S1].
6.  **Decoding:** Decode the concatenated features into density $\sigma$ and color $\mathbf{c}$ using either a Linear Decoder or an MLP Decoder (see Subtopics) [S1].
7.  **Rendering:** Render ray color and density using standard volumetric rendering [S1].

**Pseudocode:**
```python
def kplanes_forward(q, planes, scales, decoder_type='linear'):
    """
    q: (d,) query coordinate, normalized to [0, N)
    planes: dict mapping plane_name (str) to tensor (N, N, M)
    scales: list of int, resolutions for multiscale planes
    decoder_type: 'linear' or 'mlp'
    """
    combined_features = []
    
    for scale in scales:
        # 1. Project and Interpolate
        scale_features = []
        for plane_name, P in planes.items():
            # Determine 2D axes based on plane_name (e.g., 'xy' -> axes 0,1)
            axes = get_axes(plane_name) 
            # Project q onto these axes
            coords = q[axes] 
            # Bilinear interpolation
            # Note: P shape is (N, N, M). coords are in [0, N).
            # Interpolate P at coords to get (M,) vector
            f_c = bilinear_interpolate(P, coords)
            scale_features.append(f_c)
        
        # 2. Multiply features (Hadamard product)
        # Initialize with ones of shape (M,)
        f_combined = torch.ones(M)
        for f_c in scale_features:
            f_combined = f_combined * f_c
            
        combined_features.append(f_combined)
        
    # 3. Concatenate scales
    f_concat = torch.cat(combined_features, dim=0)
    
    # 4. Decode
    if decoder_type == 'linear':
        sigma = f_concat.dot(b_sigma)
        color = f_concat.dot(b_color) # b_color depends on view direction d
        # Apply sigmoid to color, exp to sigma
        sigma = torch.exp(sigma)
        color = torch.sigmoid(color)
    elif decoder_type == 'mlp':
        sigma, f_hat = mlp_sigma(f_concat)
        color = mlp_rgb(f_hat, view_direction)
        sigma = torch.exp(sigma)
        color = torch.sigmoid(color)
        
    return sigma, color
```

**Parameters:**
*   $d$: Dimensionality. Typical: 3 (static), 4 (dynamic) [S1].
*   $k$: Number of planes. $k = \binom{d}{2}$ [S1].
*   $N$: Resolution. Typical: 64, 128, 256, 512 [S1].
*   $M$: Feature size. Not given in the sources.

**Edge Cases:**
*   **Static Regions:** Space-time planes are initialized to 1 (multiplicative identity) and regularized with $\mathcal{L}_{sep}$ to remain 1 for static content, ensuring separation of static and dynamic components [S1].
*   **Unbounded Scenes:** Requires $\ell_\infty$ scene contraction to map infinite space to a bounded domain [S1].

## Subtopics

### [TriPlane NeRF](6932-triplane-nerf.md)
TriPlane NeRF is a hybrid 3D representation that aligns explicit features along three axis-aligned orthogonal feature planes to solve the scaling problems of voxel-based representations while maintaining efficiency and expressiveness. It differs from its parent [K-planes](3317-k-planes.md) by restricting the factorization to exactly three planes (XY, XZ, YZ) for 3D scenes, and from [Voxel NeRF](52-name.md) by using explicit feature planes that allow the decoder to remain small and the features to be optimized via gradients or generated by CNNs like StyleGAN.

### K-planes MLP Decoder
A hybrid model where k-planes features are decoded by small MLPs, similar to Instant-NGP and DVGO [S1]. Features are decoded by two small MLPs: $g_\sigma$ maps features $\mathbf{f}(\mathbf{q})$ into density $\sigma$ and additional features $\hat{\mathbf{f}}$; $g_{RGB}$ maps $\hat{\mathbf{f}}$ and embedded view direction $\gamma(\mathbf{d})$ into RGB color [S1]. Predicted density and color values are normalized via exponential and sigmoid, respectively [S1].
$$ \sigma(\mathbf{q}, \hat{\mathbf{f}}(\mathbf{q})) = g_\sigma(\mathbf{f}(\mathbf{q})) $$
$$ \mathbf{c}(\mathbf{q}, \mathbf{d}) = g_{RGB}(\hat{\mathbf{f}}(\mathbf{q}), \gamma(\mathbf{d})) $$
[S1]

### Appearance Code Augmentation
An extension to handle scenes with varying appearance (e.g., changing illumination) by adding a global appearance code per frame to disentangle global appearance from scene geometry [S1]. The model (linear or MLP decoder) is augmented with a learned $M$-dimensional vector for each training image, passed as an additional input to the color decoder/basis so it affects color but not geometry [S1].

## Operating characteristics
**Time and Memory Complexity:**
*   Memory: $O(k \cdot N^2 \cdot M)$. For 4D, $k=6$. Achieves 1000x compression over a full 4D grid (200 MB vs >300 GB for direct representation at same resolution) [S1].
*   Training: Orders of magnitude faster than prior implicit models and on par with concurrent hybrid models [S1].

**Performance:**
*   Competitive and often state-of-the-art reconstruction fidelity across synthetic/real, static/dynamic, fixed/varying appearance scenes [S1].
*   Linear decoder achieves similar performance to MLP decoder due to Hadamard product enabling spatial localization [S1].

**Strengths and Limitations:**
*   **Strengths:** White-box/interpretable, graceful scaling to arbitrary dimensions, low memory, fast training, supports dynamic scenes and varying appearance [S1].
*   **Limitations:** Multiplication-based combination requires careful initialization (space-time planes at 1) and regularization ($\mathcal{L}_{TV}, \mathcal{L}_{smooth}, \mathcal{L}_{sep}$) to maintain stability and separation [S1].

**When to Use:**
*   Static 3D volumes, 3D photo collections with varying appearances, and 4D dynamic videos [S1].
*   When interpretability and low memory are prioritized over the flexibility of black-box MLPs [S1].

## Background
K-planes was introduced in "K-Planes: Explicit Radiance Fields in Space, Time, and Appearance" (CVPR 2023) [S1]. It builds on explicit modeling of Plenoxels and spatial decompositions like Triplane (EG3D) and Tensor Decomposition (TensoRF) [S1]. It addresses the black-box nature of MLP-based NeRFs and the memory inefficiency of dense voxels by providing a prescriptive, interpretable factorization for arbitrary dimensions [S1].
