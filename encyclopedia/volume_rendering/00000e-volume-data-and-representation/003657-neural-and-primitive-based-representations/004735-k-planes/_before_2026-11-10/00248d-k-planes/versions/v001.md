# K-planes

Also called: hex-planes, k-planes factorization, tri-planes

## Overview
K-planes is a white-box, interpretable representation for radiance fields in arbitrary dimensions $d$ that uses planar factorization to represent a $d$-dimensional scene [S1]. It solves the problem of efficiently encoding spatial and temporal information by decomposing the volume into $k = \binom{d}{2}$ 2D planes, one for every pair of dimensions [S1]. Unlike sibling methods that add features from planes (e.g., [EG3D](52-eg3d.md), [TensoRF](6060-neus.md)), K-planes multiplies them element-wise, which allows for spatially localized signals and enables the replacement of black-box MLP decoders with linear feature decoders while maintaining competitive quality [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A query point $\mathbf{q}$ in $d$-dimensional space (e.g., 3D spatial coordinates $(x,y,z)$ for static scenes, or 4D space-time $(x,y,z,t)$ for dynamic scenes) and optionally a viewing direction $\mathbf{d}$.
*   **Output:** Density $\sigma$ and color $\mathbf{c}$.

**Data Structures:**
The scene is represented by a set of $k = \binom{d}{2}$ 2D feature planes $\mathbf{P}$.
*   For $d=3$ (static), $k=3$ planes: $\mathbf{P}_{xy}, \mathbf{P}_{xz}, \mathbf{P}_{yz}$ (tri-planes).
*   For $d=4$ (dynamic), $k=6$ planes: $\mathbf{P}_{xy}, \mathbf{P}_{xz}, \mathbf{P}_{yz}$ (space-only) and $\mathbf{P}_{xt}, \mathbf{P}_{yt}, \mathbf{P}_{zt}$ (space-time) (hex-planes) [S1].
*   Each plane $\mathbf{P}_c$ has shape $N \times N \times M$, where $N$ is the symmetric spatial/temporal resolution and $M$ is the feature dimension [S1].
*   **Multiscale:** The model includes multiple copies of planes at different resolutions (e.g., $64, 128, 256, 512$) [S1].

**Steps:**
1.  **Normalization:** Normalize the entries of the query point $\mathbf{q}$ to the range $[0, N)$ [S1]. For forward-facing scenes, apply Normalized Device Coordinates (NDC) [S1]. For unbounded scenes, apply an $l_\infty$ scene contraction [S1].
2.  **Projection:** For each plane $c \in C$ (where $|C|=k$), project $\mathbf{q}$ onto the 2D plane corresponding to the pair of dimensions defining $c$ to obtain 2D coordinates $\pi_c(\mathbf{q})$ [S1].
3.  **Interpolation:** Perform multiscale bilinear interpolation on each plane at $S$ scales to retrieve feature vectors $\mathbf{f}(\mathbf{q})_c$ [S1].
    $$ \mathbf{f}(\mathbf{q})_c = \psi(\mathbf{P}_c, \pi_c(\mathbf{q})) $$
    where $\psi$ denotes bilinear interpolation of a point into a regularly spaced 2D grid [S1].
4.  **Combination:** Multiply the feature vectors from all $k$ planes element-wise (Hadamard product) to combine spatial/dynamic information [S1].
    $$ \mathbf{f}(\mathbf{q}) = \prod_{c \in C} \mathbf{f}(\mathbf{q})_c $$
    This produces a final feature vector of length $M$ [S1].
5.  **Concatenation:** Concatenate the multiplied features from all $S$ scales [S1].
6.  **Decoding:** Decode the concatenated features into density $\sigma$ and color $\mathbf{c}$ using either a linear decoder (explicit) or an MLP (hybrid) [S1].
7.  **Rendering:** Render the ray color and density using the standard volumetric rendering formula [S1].

**Formulas:**
*   **Linear Decoder (Explicit):**
    Density is predicted via a linear projection with a learned basis $\mathbf{b}_\sigma$:
    $$ \sigma(\mathbf{q}) = \mathbf{f}(\mathbf{q}) \cdot \mathbf{b}_\sigma $$
    Color is predicted via a learned color basis $\mathbf{B}_{RGB}$ and view direction embedding $\gamma(\mathbf{d})$:
    $$ \mathbf{c}(\mathbf{q}, \mathbf{d}) = \mathbf{f}(\mathbf{q}) \cdot \mathbf{B}_{RGB}(\gamma(\mathbf{d})) $$
    Predicted values are normalized via sigmoid for color and exponential (with truncated gradient) for density [S1].

*   **MLP Decoder (Hybrid):**
    Two small MLPs decode the features:
    $$ \sigma(\mathbf{q}, \hat{\mathbf{f}}(\mathbf{q})) = g_\sigma(\mathbf{f}(\mathbf{q})) $$
    $$ \mathbf{c}(\mathbf{q}, \mathbf{d}) = g_{RGB}(\hat{\mathbf{f}}(\mathbf{q}), \gamma(\mathbf{d})) $$
    where $g_\sigma$ maps features to density and additional features $\hat{\mathbf{f}}$, and $g_{RGB}$ maps $\hat{\mathbf{f}}$ and view direction to RGB [S1].

*   **Regularization:**
    *   **Spatial Total Variation:** Encourages sparse or smooth gradients in space (applied to space-only and space-time planes):
        $$ \mathcal{L}_{TV}(\mathbf{P}) = \frac{1}{|C|n^2} \sum_{c,i,j} \left( \|\mathbf{P}_c^{i,j} - \mathbf{P}_c^{i-1,j}\|_2^2 + \|\mathbf{P}_c^{i,j} - \mathbf{P}_c^{i,j-1}\|_2^2 \right) $$
        [S1]
    *   **Temporal Smoothness:** 1D Laplacian filter on the time dimension of space-time planes to penalize sharp acceleration:
        $$ \mathcal{L}_{smooth}(\mathbf{P}) = \frac{1}{|C|n^2} \sum_{c,i,t} \|\mathbf{P}_c^{i,t-1} - 2\mathbf{P}_c^{i,t} + \mathbf{P}_c^{i,t+1}\|_2^2 $$
        [S1]
    *   **Sparse Transients:** Encourages static regions to remain at 1 (multiplicative identity) in space-time planes:
        $$ \mathcal{L}_{sep}(\mathbf{P}) = \sum_{c} \|\mathbf{1} - \mathbf{P}_c\|_1, \quad c \in \{xt, yt, zt\} $$
        Space-time planes are initialized as 1 [S1].

**Parameters:**
*   $d$: Dimensionality of scene space. Typical: $d=3$ (static), $d=4$ (dynamic) [S1].
*   $k$: Number of planes, $k = \binom{d}{2}$. Typical: $k=3$ (tri-planes), $k=6$ (hex-planes) [S1].
*   $N$: Symmetric spatial and temporal resolution [S1].
*   $M$: Size of stored features [S1].

**Pseudocode:**
```python
def kplanes_forward(q, planes, scales, decoder_type='linear'):
    """
    q: tuple of coordinates (e.g., (x, y, z) or (x, y, z, t))
    planes: list of 3D tensors [num_scales, num_planes, N, N, M]
    scales: list of resolutions corresponding to planes
    decoder_type: 'linear' or 'mlp'
    """
    # 1. Normalize q to [0, N) for each scale
    # Note: N varies by scale. q is normalized per scale.
    features_per_scale = []
    
    for s_idx, N in enumerate(scales):
        # Normalize q for this scale's resolution
        q_norm = normalize(q, N)
        
        # 2. Project and Interpolate
        scale_features = []
        for c_idx, plane in enumerate(planes[s_idx]):
            # Determine the 2D axes for plane c based on dimension d
            axes = get_axes_for_plane(c_idx, d) 
            # Project q onto the 2D plane
            coords = project(q_norm, axes)
            # Bilinear interpolation
            f_c = bilinear_interpolate(plane, coords)
            scale_features.append(f_c)
        
        # 3. Multiply features across planes (Hadamard product)
        # scale_features is a list of M-dimensional vectors
        combined = scale_features[0]
        for f in scale_features[1:]:
            combined = combined * f
            
        features_per_scale.append(combined)
        
    # 4. Concatenate features from all scales
    final_features = concat(features_per_scale, dim=-1)
    
    # 5. Decode
    if decoder_type == 'linear':
        sigma = linear_decode_density(final_features)
        color = linear_decode_color(final_features, view_direction)
    elif decoder_type == 'mlp':
        sigma, intermediate = mlp_decode_density(final_features)
        color = mlp_decode_color(intermediate, view_direction)
        
    # 6. Normalize outputs
    sigma = exp(sigma)
    color = sigmoid(color)
    
    return sigma, color
```

## Subtopics

### K-planes MLP Decoder
A hybrid model where K-planes features are decoded by small MLPs, similar to Instant-NGP and DVGO [S1]. Features are decoded by two small MLPs: $g_\sigma$ maps features $\mathbf{f}(\mathbf{q})$ into density $\sigma$ and additional features $\hat{\mathbf{f}}$; $g_{RGB}$ maps $\hat{\mathbf{f}}$ and embedded view direction $\gamma(\mathbf{d})$ into RGB color [S1]. Predicted density and color values are normalized via exponential and sigmoid, respectively [S1].

### Appearance Code Augmentation
An extension to handle scenes with varying appearance (e.g., changing illumination) by adding a global appearance code per frame to disentangle global appearance from scene geometry [S1]. The model (either linear or MLP decoder) is augmented with a learned M-dimensional vector for each training image, passed as an additional input to the color decoder [S1].

## Operating characteristics
*   **Compression:** Achieves 1000x compression over a full 4D grid. A 4D volume represented by K-planes uses 200 MB, whereas a direct representation at the same resolution requires >300 GB [S1].
*   **Performance:** Trains orders of magnitude faster than prior implicit models and on par with concurrent hybrid models [S1].
*   **Strengths:** White-box, interpretable, scalable to arbitrary dimensions, low memory usage, fast optimization [S1].
*   **Limitations:** Multiplication-based combination requires careful initialization (space-time planes initialized to 1) and regularization to prevent vanishing gradients or static/dynamic mixing issues [S1].
*   **Usage:** Static 3D volumes, 3D photo collections with varying appearances, and 4D dynamic videos [S1].

## Background
K-planes was introduced as a white-box model for radiance fields in arbitrary dimensions, extending the concept of tri-planes (used in generative models like EG3D) and tensor decompositions (like TensoRF) to a general $d$-dimensional framework [S1]. It was proposed to address the black-box nature of MLP-based radiance fields and the redundancy of previous tensor decompositions (e.g., Tensor4D used 9 planes for 4D, while K-planes uses 6) [S1]. The method draws inspiration from explicit modeling in Plenoxels and multiscale grid models like Instant-NGP [S1].
