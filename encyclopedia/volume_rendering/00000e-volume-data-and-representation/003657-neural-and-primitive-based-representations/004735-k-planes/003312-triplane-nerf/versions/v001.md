# TriPlane NeRF
Also called: TriPlane representation in NeRF

## Overview
TriPlane NeRF is a neural radiance field method that replaces the implicit 3D volume or dense voxel grid with three explicit, axis-aligned feature planes to improve scalability and training efficiency [S1]. It solves the resolution scaling limitations of voxel-based representations by maintaining a compact, fixed-size memory footprint regardless of scene complexity, while preserving the expressiveness required for high-fidelity rendering [S1]. Unlike Voxel NeRF, which requires large memory for high-resolution grids, TriPlane NeRF keeps the decoder network small and relies on explicit feature aggregation, allowing the planes to be optimized via gradients or generated by generative models [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A 3D position $x \in \mathbb{R}^3$, a viewing direction $d \in \mathbb{R}^3$, a set of learnable parameters $\Theta$ for the decoder, and a set of feature planes $P$.
*   **Outputs:** A color $c \in \mathbb{R}^3$ and an opacity $\sigma \in \mathbb{R}$.

**Data Structures:**
The representation consists of three feature planes $P = (P_{xy}, P_{xz}, P_{yz})$.
*   Each plane $P_{axis}$ has a resolution of $N \times N \times C$.
*   $N$ is the spatial resolution (width and height in pixels/features).
*   $C$ is the number of channels (feature dimension).
*   The planes are axis-aligned orthogonal to the x, y, and z axes respectively.

**Numbered Steps:**
1.  **Projection:** For a query 3D point $x = (x, y, z)$, project it onto the three feature planes to obtain 2D coordinates:
    *   On $P_{xy}$: $(x, y)$
    *   On $P_{xz}$: $(x, z)$
    *   On $P_{yz}$: $(y, z)$
2.  **Interpolation:** Retrieve the feature vector from each plane at the projected 2D coordinates using bilinear interpolation. Let the retrieved vectors be $F_{xy}$, $F_{xz}$, and $F_{yz}$.
3.  **Aggregation:** Sum the three feature vectors to form the aggregated 3D feature vector $F_{agg}$:
    $$ F_{agg} = F_{xy} + F_{xz} + F_{yz} $$
4.  **Decoding:** Pass the aggregated feature vector $F_{agg}$ and the viewing direction $d$ into a lightweight decoder network (typically a small Multi-Layer Perceptron, MLP) parameterized by $\Theta$.
5.  **Output:** The decoder outputs the final color $c$ and opacity $\sigma$.

**Formula:**
The complete TriPlane NeRF function is defined as:
$$ F_{TriPlaneNeRF}(x, d; \Theta, P) = (c, \sigma) $$
Where:
*   $x$ is the 3D position.
*   $d$ is the viewing direction.
*   $\Theta$ are the decoder parameters.
*   $P$ are the feature planes.

**Pseudocode:**
```python
def triplane_nerf_query(x, d, planes, decoder):
    """
    Query the TriPlane NeRF representation.
    
    Args:
        x: 3D position vector (x, y, z)
        d: Viewing direction vector
        planes: Dictionary or tuple containing P_xy, P_xz, P_yz
                Each plane is a 3D tensor of shape (N, N, C)
        decoder: A function or MLP that takes (features, direction) -> (color, opacity)
        
    Returns:
        color: RGB color vector
        opacity: Scalar opacity value
    """
    x_val, y_val, z_val = x
    
    # Step 1 & 2: Project and interpolate
    # Note: In implementation, coordinates must be normalized to [0, 1] or [-1, 1] 
    # depending on the specific coordinate system used for bilinear sampling.
    # Assuming normalized coordinates [0, 1] for standard bilinear interpolation.
    
    # Interpolate from XY plane
    F_xy = bilinear_interpolate(planes['P_xy'], x_val, y_val)
    
    # Interpolate from XZ plane
    F_xz = bilinear_interpolate(planes['P_xz'], x_val, z_val)
    
    # Interpolate from YZ plane
    F_yz = bilinear_interpolate(planes['P_yz'], y_val, z_val)
    
    # Step 3: Aggregate via summation
    F_agg = F_xy + F_xz + F_yz
    
    # Step 4 & 5: Decode
    color, opacity = decoder(F_agg, d)
    
    return color, opacity

def bilinear_interpolate(plane, u, v):
    """
    Perform bilinear interpolation on a 2D feature plane.
    
    Args:
        plane: 3D tensor (H, W, C)
        u: x-coordinate (column index)
        v: y-coordinate (row index)
        
    Returns:
        Feature vector of shape (C,)
    """
    # Get integer coordinates
    u_int = floor(u)
    v_int = floor(v)
    
    # Get fractional parts
    u_frac = u - u_int
    v_frac = v - v_int
    
    # Get corner values
    # Handle boundary conditions by clamping or wrapping as per implementation choice [G]
    v00 = plane[v_int, u_int, :]
    v01 = plane[v_int, u_int + 1, :]
    v10 = plane[v_int + 1, u_int, :]
    v11 = plane[v_int + 1, u_int + 1, :]
    
    # Interpolate in x
    v0 = v00 * (1 - u_frac) + v01 * u_frac
    v1 = v10 * (1 - u_frac) + v11 * u_frac
    
    # Interpolate in y
    result = v0 * (1 - v_frac) + v1 * v_frac
    
    return result
```

## Subtopics

### [MultiPlaneGAN](7441-multiplanegan.md)
MultiPlaneGAN is a GAN-based 3D generation framework that synthesizes 3D objects by replacing the tri-plane representation of EG3D with a MultiPlane 3D representation consisting of 32 planes posed on a sphere. It differs from its parent [TriPlane NeRF](6932-triplane-nerf.md) and the baseline EG3D by using a spherical distribution of feature planes rather than axis-aligned orthogonal planes, while retaining the EG3D decoder, super-resolution module, and discriminator architecture.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** The memory usage is determined by the size of the three planes: $3 \times N \times N \times C$. This is significantly more scalable than voxel representations, which scale as $N^3$ [S1].
*   **Measured Performance:** The source provides performance metrics for "MultiPlaneNeRF" (which uses the TriPlane representation) compared to SRN, NV, NeRF, and NSFV on datasets like Chair, Drums, Ficus, and Hotdog [S1].
    *   **Chair PSNR:** MultiPlaneNeRF achieves 32.81, compared to NeRF's 33.00 and NSFV's 32.81.
    *   **Drums PSNR:** MultiPlaneNeRF achieves 24.28, compared to NeRF's 25.01 and NSFV's 25.18.
    *   **Chair SSIM:** MultiPlaneNeRF achieves 0.972, compared to NeRF's 0.967 and NSFV's 0.968.
    *   **Drums SSIM:** MultiPlaneNeRF achieves 0.921, compared to NeRF's 0.925 and NSFV's 0.931.
    *   **Chair LPIPS:** MultiPlaneNeRF achieves 0.026, compared to NeRF's 0.046 and NSFV's 0.043.
    *   **Drums LPIPS:** MultiPlaneNeRF achieves 0.071, compared to NeRF's 0.091 and NSFV's 0.069.
*   **Strengths:** Keeps the decoder small; uses explicit feature representation; efficient and expressive; solves scaling problems of voxel representations [S1].
*   **Limitations:** Not given in the sources.
*   **When to use:** When scaling to higher resolutions is required and voxel-based methods become too memory-intensive [S1].
*   **When not to use:** Not given in the sources.

## Background
TriPlane NeRF builds on the TriPlane 3D representation introduced in prior work [S1]. It was proposed as a solution to the scaling problems inherent in voxel representations for neural radiance fields [S1]. The method allows the feature planes to be calculated via gradient-based optimization or produced by convolutional neural networks like StyleGAN or diffusion models [S1]. The loss function and rendering procedure are directly taken from vanilla NeRF [S1].
