# TensorBase

Also called: Tensor-based volume rendering base class

## Overview
TensorBase is a foundational base class for tensor-based volume rendering methods, specifically designed to manage the geometric bounds (AABB), grid resolution, and rendering module selection for neural feature volumes [S1, unofficial]. It serves as the structural backbone for initializing SVD-based volume representations and handling ray sampling logic, distinguishing itself from sibling methods by providing the low-level infrastructure for coordinate normalization and step-size calculation rather than implementing specific neural architectures or inpainting strategies [S1, unofficial].

## How it works
**Inputs and Outputs:**
The class initializes with a set of configuration parameters defining the scene's spatial bounds, grid dimensions, and neural network properties. It outputs normalized coordinates for ray sampling and manages the state of the rendering module (e.g., MLP, SH, or RGB renderers) based on the selected shading mode.

**Data Structures and Layout:**
The class maintains several key tensors and parameters. The primary parameters include:
- `aabb`: Axis-Aligned Bounding Box, stored as a tensor of shape `[2, 3]` representing min and max coordinates.
- `gridSize`: Resolution of the voxel grid, stored as a `torch.LongTensor`.
- `dtype`: Data type for tensors (default `torch.float32`).
- `device`: Compute device.
- `density_n_comp`: Number of components for density SVD (default 8).
- `appearance_n_comp`: Number of components for appearance SVD (default 24).
- `app_dim`: Dimensionality of the appearance feature vector (default 27).
- `shadingMode`: String selecting the rendering module (e.g., `'MLP_PE'`, `'MLP'`, `'SH'`, `'RGB'`).
- `alphaMask`: Optional mask for sparse rendering.
- `near_far`: Default ray sampling range `[2.0, 6.0]`.
- `density_shift`: Shift applied to density values (default -10).
- `alphaMask_thres`: Threshold for alpha mask creation (default 0.001).
- `distance_scale`: Scaling factor for distance (default 25).
- `rayMarch_weight_thres`: Threshold for ray marching weights (default 0.0001).
- `pos_pe`, `view_pe`, `fea_pe`: Number of positional encoding frequencies for position, view, and feature (default 6).
- `featureC`: Feature channel dimension (default 128).
- `step_ratio`: Multiplier for step size calculation (default 2.0).
- `fea2denseAct`: Activation function for feature-to-dense conversion (default `'softplus'`).
- `volume_init_scale`, `volume_init_bias`: Initialization parameters for the volume (default 0.1).

**Mode Matrices for SVD:**
The class initializes mode matrices for tensor decomposition operations:
- `matMode`: `[[0, 1], [0, 2], [1, 2]]`
- `vecMode`: `[2, 1, 0]`
- `comp_w`: `[1, 1, 1]`

**Numbered Steps:**

1.  **Initialization (`__init__`):**
    - Store all input parameters as instance attributes.
    - Initialize `matMode`, `vecMode`, and `comp_w` as defined above.

2.  **Reset (`reset`):**
    - Convert the input `aabb` (list or array of min/max coordinates) to a tensor:
      $$ \text{self.aabb} = \text{torch.tensor}(\text{aabb}, \text{dtype}=\text{self.dtype}) $$

3.  **Update Step Size (`update_stepSize`):**
    - Compute the size of the AABB:
      $$ \text{self.aabbSize} = \text{self.aabb}[1] - \text{self.aabb}[0] $$
    - Compute the inverse AABB size:
      $$ \text{self.invaabbSize} = \frac{2.0}{\text{self.aabbSize}} $$
    - Set the grid size tensor:
      $$ \text{self.gridSize} = \text{torch.LongTensor}(\text{gridSize}).\text{to}(\text{self.device}) $$
    - Compute the unit size (voxel dimensions):
      $$ \text{self.units} = \frac{\text{self.aabbSize}}{\text{self.gridSize} - 1} $$
    - Compute the step size for ray marching:
      $$ \text{self.stepSize} = \text{torch.mean}(\text{self.units}) \times \text{self.step\_ratio} $$
    - Compute the AABB diagonal length:
      $$ \text{self.aabbDiag} = \sqrt{\sum (\text{self.aabbSize})^2} $$
    - Compute the number of samples required to traverse the diagonal:
      $$ \text{self.nSamples} = \left\lfloor \frac{\text{self.aabbDiag}}{\text{self.stepSize}} \right\rfloor + 1 $$

4.  **Initialize Rendering Function (`init_render_func`):**
    - Select the rendering module based on `shadingMode`:
      - `'MLP_PE'` $\rightarrow$ `MLPRender_PE`
      - `'MLP'` $\rightarrow$ `MLPRender`
      - `'SH'` $\rightarrow$ `SHRender`
      - `'RGB'` $\rightarrow$ `RGBRender`

5.  **Normalize Coordinates (`normalize_coord`):**
    - Map sampled 3D points `xyz_sampled` from world space to the range $[-1, 1]$:
      $$ \text{normalized} = (\text{xyz\_sampled} - \text{self.aabb}[0]) \times \text{self.invaabbSize} - 1 $$

6.  **Sample Ray NDC (`sample_ray_ndc`):**
    - Determine the number of samples $N_{samples}$. If $N_{samples} < 0$, use `self.nSamples`.
    - Compute linear interpolation between `near` and `far` depths:
      $$ \text{interpx} = \text{linspace}(\text{near}, \text{far}, N_{samples}) $$
    - If in training mode (`is_train`), add uniform noise to break symmetry:
      $$ \text{interpx} \leftarrow \text{interpx} + \text{rand}() \times \frac{\text{far} - \text{near}}{N_{samples}} $$
    - Compute NDC depth (assuming perspective projection parameters `ndc_near_plane`):
      $$ \text{ndc\_depth} = \frac{2 \times \text{ndc\_near\_plane}}{1 - \text{ndc\_near\_plane} - \text{interpx}} $$
    - If `simulate_euclid_sample` is enabled, rescale the depth to simulate Euclidean spacing:
      $$ \text{simulated\_interpx} = \text{grad\_rescale}(\text{interpx}, \text{ndc\_depth}) $$
    - Compute the 3D ray points:
      $$ \text{rays\_pts} = \text{rays\_o} + \text{rays\_d} \times \text{simulated\_interpx} $$
      (Note: Broadcasting applies to batch and ray dimensions).

7.  **Save/Load Parameter State:**
    - `save_param_state`: Saves `reset_kwargs` and alpha mask state into a checkpoint dictionary.
    - `load_param_state`: If an `alphaMask` is present in the checkpoint, unpack the bit-packed mask:
      $$ \text{alpha\_volume} = \text{torch.from\_numpy}(\text{np.unpackbits}(\text{ckpt}['\text{alphaMask.mask}'])[:\text{length}].\text{reshape}(\text{ckpt}['\text{alphaMask.shape'}])) $$

**Edge Cases and Pitfalls:**
- **Division by Zero:** `self.gridSize - 1` in `update_stepSize` will cause division by zero if any grid dimension is 1. Ensure `gridSize` components are $>1$.
- **Precision:** SVD operations in related methods (like `procrustes_analysis` in the source context) often require double precision (`torch.float64`) to avoid numerical instability, though `TensorBase` itself defaults to `float32`.
- **NDC Plane:** The `ndc_near_plane` parameter in `sample_ray_ndc` must be valid (typically $< 1$) to avoid singularities in the NDC depth calculation.

## Subtopics

### [UniVoxel](16853-univoxel.md)
UniVoxel is a unified voxelization framework for inverse rendering that encodes a scene into two learnable voxel fields: a Signed Distance Function (SDF) field for geometry and a semantic field for materials and illumination. It enables efficient trilinear interpolation and volumetric physics-based rendering, jointly modeling geometry, materials, and incident light radiance using local Spherical Gaussians (SG). Unlike environment map-based methods that require expensive visibility simulation for every incident direction, UniVoxel avoids this heavy computational burden by integrating illumination directly into the voxel grid.

## Operating characteristics
- **Time Complexity:** Initialization is $O(1)$ relative to grid size for setting up constants, but `update_stepSize` is $O(D)$ where $D$ is the number of grid dimensions (typically 3). Ray sampling is $O(N_{samples})$.
- **Memory Complexity:** The base class itself stores minimal state ($O(1)$). However, it manages references to large tensor volumes (SVD components) whose memory footprint depends on `density_n_comp`, `appearance_n_comp`, and `gridSize`.
- **Performance:** Performance is heavily dependent on the chosen `shadingMode` and the efficiency of the underlying rendering module (e.g., MLP vs. SH). The `step_ratio` parameter directly controls the trade-off between rendering speed and visual fidelity; higher ratios result in fewer samples and faster rendering but potential aliasing.
- **Strengths:** Provides a standardized interface for coordinate normalization and ray sampling, reducing boilerplate code for tensor-based volume renderers.
- **Limitations:** Does not define the neural architecture itself; it relies on external modules for feature decoding. The default `MLP_PE` shading mode may be computationally expensive for high-resolution grids.

## Background
TensorBase originates from the Joint-TensoRF project, an unofficial implementation of tensor-based neural radiance fields [S1, unofficial]. It serves as the foundational class for managing the geometric and sampling aspects of volume rendering in this codebase, supporting variants like UniVoxel that build upon its infrastructure for advanced inverse rendering tasks [S1, unofficial].
