# Hole Filling

Also called: Depth Image Hole Filling, Statistical Hole Filling

## Overview
Hole filling is a post-processing step for projected depth images that replaces zero-valued pixels (holes) with estimated non-zero values, distinguishing between missing foreground surface information and valid background voids [S1]. It sets itself apart from general inpainting by using a statistical test on local neighborhood statistics ($\mu, \sigma$) to decide whether to apply a moving average filter, thereby preserving background areas that should remain empty [S1].

## How it works
**Inputs and Outputs:**
- Input: A projected depth image $D$ where holes are represented by zero values.
- Output: A filled depth image $D'$ where holes corresponding to missing foreground surface are replaced with interpolated values.

**Data Structures:**
- The depth image is treated as a 2D array of floating-point values.
- A kernel size $M \times M$ is used for local neighborhood calculations.

**Parameters:**
- $M$: Kernel size for the moving average filter and neighborhood statistics calculation. Not given in the sources.
- $\kappa$: Threshold for the statistical test. Empirically found best value is 2 [S1].

**Steps:**
1. For each pixel $p$ in the depth image $D$ that has a value of 0 (a hole):
   a. Identify the $M \times M$ neighborhood of pixels centered at $p$.
   b. Calculate the mean $\mu$ and standard deviation $\sigma$ of the non-zero values in this neighborhood. If the neighborhood contains no non-zero values, $\mu$ and $\sigma$ are undefined; the hole is not filled [G].
   c. Evaluate the condition:
      $$ \frac{p - \mu}{\sigma} > \kappa $$
      Since $p=0$ for a hole, this simplifies to:
      $$ \frac{-\mu}{\sigma} > \kappa $$
   d. If the condition is satisfied, the hole is determined to be missing foreground surface information.
   e. Fill the hole by applying a moving average filter with kernel size $M \times M$ to the original depth image (or the neighborhood) [S1]. The specific implementation details of the moving average filter (e.g., whether it includes the hole pixel itself before replacement) are not explicitly detailed beyond the kernel size [S1].

**Pseudocode:**
```python
import numpy as np

def hole_filling(depth_image: np.ndarray, kernel_size: int, kappa: float) -> np.ndarray:
    """
    Fills holes (zero values) in a depth image using statistical neighborhood analysis.
    
    Args:
        depth_image: 2D numpy array of depth values. Holes are 0.
        kernel_size: Size M of the M x M kernel.
        kappa: Threshold for the statistical test.
        
    Returns:
        Filled depth image.
    """
    filled_image = depth_image.copy()
    M = kernel_size
    half_kernel = M // 2
    
    # Get coordinates of hole pixels
    hole_mask = (depth_image == 0)
    hole_coords = np.argwhere(hole_mask)
    
    for y, x in hole_coords:
        # Define neighborhood bounds
        y_min = max(0, y - half_kernel)
        y_max = min(depth_image.shape[0], y + half_kernel + 1)
        x_min = max(0, x - half_kernel)
        x_max = min(depth_image.shape[1], x + half_kernel + 1)
        
        neighborhood = depth_image[y_min:y_max, x_min:x_max]
        
        # Calculate mean and std of non-zero neighbors
        non_zero_neighbors = neighborhood[neighborhood != 0]
        
        if len(non_zero_neighbors) == 0:
            # No valid neighbors to estimate from, leave as 0 or handle as edge case [G]
            continue
            
        mu = np.mean(non_zero_neighbors)
        sigma = np.std(non_zero_neighbors)
        
        if sigma == 0:
            # Avoid division by zero; if sigma is 0, all neighbors are identical
            # The condition (0 - mu) / 0 is undefined. 
            # If mu is also 0, it's ambiguous. If mu != 0, it's a strong signal.
            # Standard practice might treat this as not a hole or fill with mu.
            # Based on [S1], we assume sigma > 0 for the condition to be meaningful.
            continue
            
        # Check condition: (p - mu) / sigma > kappa
        # Since p = 0 for a hole:
        if (0 - mu) / sigma > kappa:
            # Fill with moving average of the neighborhood
            # Note: The source says "apply a moving average filter with kernel size M x M"
            # This usually implies convolving the original image or taking the mean of the neighborhood.
            # Given the context of "filling", taking the mean of the valid neighbors is a robust interpretation.
            filled_value = np.mean(non_zero_neighbors)
            filled_image[y, x] = filled_value
            
    return filled_image
```

**Edge Cases and Pitfalls:**
- If $\kappa$ is too small, holes in background areas may be filled, blurring the depth image [S1].
- If $\kappa$ is too large, holes with missing foreground information may remain unfilled [S1].
- If the neighborhood has zero standard deviation ($\sigma = 0$), the condition is undefined [G].

## Subtopics

### Diffusion Fill (Hole Inpainting)
Fills hole pixels in an image by diffusing values from their surroundings using iterative box filtering [S2, unofficial]. It initializes an output copy of the image and iteratively updates hole pixels using the ratio of a box-filtered numerator (output) to a box-filtered denominator (weight mask), updating weights and shrinking the hole mask until no holes remain or a maximum iteration count is reached [S2, unofficial]. It is suitable for general image inpainting where iterative diffusion is preferred over statistical thresholding [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the number of holes and the kernel size $M$. For each hole, an $M \times M$ neighborhood is processed. In the worst case (all pixels are holes), it is $O(H \cdot W \cdot M^2)$ where $H, W$ are image dimensions.
- **Memory Complexity:** $O(H \cdot W)$ for the depth image and temporary neighborhood arrays.
- **Measured Performance:** On the DONeRF Lego dataset ($N=8, \alpha=1/16$), hole filling improves rendering PSNR from 27.29 dB (without filling) to a peak of 30.25 dB with $\kappa=1$ or $\kappa=2$ [S1].
- **Strengths:** Simple to implement, preserves background areas when $\kappa$ is chosen correctly, improves downstream rendering quality [S1].
- **Limitations:** Sensitive to $\kappa$ selection; poor choice leads to either residual holes or background blurring [S1]. Relies on local statistics, which may fail in textureless or uniform regions [G].

## Background
Originated in the context of improving Neural Radiance Fields (NeRF) using near-surface sampling with point cloud generation [S1]. The method was introduced to address the issue of zero-valued pixels in projected depth images derived from point clouds, which correspond to missing 3D surface information [S1]. It was empirically evaluated on synthetic (Lego, Ship) and real (BlendedMVS, Pavillon) datasets [S1].
