# Neural Volume Construction

Also called: Sparse 3D ConvNet Feature Aggregation, Sparse Tensor Construction, UV volume construction network, Volume Generator

## Overview
Neural Volume Construction initializes and aggregates neural features into an explicit 3D latent volume from sparse input primitives or multi-view projections [S1, S2]. It constructs a sparse tensor from initialized noisy primitives and processes it through a 3D sparse Convolutional Neural Network (ConvNet) to produce a world-aligned feature volume [S2]. The method explicitly stores neural features as a large tensor, building on [Explicit Neural Feature Volume](1838-explicit-neural-feature-volume.md).

## How it works
### Inputs and Outputs
**Inputs:**
1. **Initialized Noisy Primitives ($\mathcal{P}$):** A set of 3D points or Gaussian centers, often derived from a scene point cloud or noisy initialization [S2].
2. **Posed Human Point Cloud with Latent Codes ($\mathbf{z}$):** For human performance synthesis, time-invariant latent codes are anchored to posed point clouds [S1].
3. **Multi-view Image Features (Optional):** 2D image features extracted from input views for multi-view aggregation variants [S6].

**Outputs:**
1. **Neural Feature Volume ($\mathbf{F}$):** A tensor $\mathbf{F} \in \mathbb{R}^{H \times W \times D \times C}$, where $H \times W \times D$ is the spatial resolution and $C$ is the feature dimension [S2]. The volume is aligned with the world coordinate system [S2].

### Data Structures
* **Sparse Tensor:** The input $\mathcal{P}$ is stored as a sparse tensor to optimize memory and computation, leveraging the sparsity of real-world scenes [S2].
* **Feature Grid:** The output $\mathbf{F}$ is stored as a 3D grid aligned with the world coordinate system [S2].

### Steps
1. **Primitive Initialization:** Initialize the scene with noisy primitives $\mathcal{P}$ (e.g., centers from a point cloud) [S2]. For human performance, animate point clouds using SMPL and anchor time-invariant latent codes [S1].
2. **Sparse Tensor Construction:** Voxelize the point cloud or primitives into a sparse tensor representation [S1, S2].
3. **Feature Aggregation via 3D ConvNet:**
    * Employ a sparse U-Net style 3D ConvNet, denoted as $\psi^{3D}$ [S2].
    * The network follows an encoder-decoder structure with a bottleneck of low spatial dimension [S2].
    * Skip connections are added to preserve both local and global information [S2].
    * Compute the output feature volume:
      $$ \mathbf{F} = \psi^{3D}(\mathcal{P}) $$
      where $\mathbf{F}$ is the aggregated neural feature volume [S2].
4. **Channel Reduction (Optional):** Reduce channels from 352 to 64 to capture low-frequency semantic information [S1].
5. **Querying (Downstream):** For each primitive $i$ with center $\mu_{init}^i$, query the latent feature from $\mathbf{F}$ using trilinear interpolation to predict offsets (e.g., position offset $\Delta \mu_i$) [S2].

### Parameters
* **Spatial Resolution ($H \times W \times D$):** Not given in the sources for the general method. Specific variants use $128^3$ [S4] or $40 \times 40 \times 16$ [S6].
* **Feature Dimension ($C$):** Not given in the sources for the general method. Specific variants use 64 output channels [S1].
* **Network Architecture:** Sparse U-Net with encoder-decoder structure, bottleneck, and skip connections [S2].

### Edge Cases and Pitfalls
* **Information Loss in Reference Views:** If the volume is constructed in a fixed reference view space, regions outside the reference view's epipolar lines are less likely to be sampled, leading to information loss, especially with large baselines [S5].
* **Over-population:** Naive scattering of features from multiple views can "over populate" projection rays without considering empty spaces, causing ambiguous 3D representations and detection errors [S6].
* **Aliasing:** Using low grid resolutions (e.g., $40 \times 40 \times 16$) for feature sampling can suffer from aliasing issues, degrading geometry learning [S6].

### Pseudocode
```python
def construct_neural_volume(primitives, resolution, feature_dim):
    """
    Constructs a neural feature volume from primitives using a sparse 3D ConvNet.
    
    Args:
        primitives: List of (coords, features) tuples. coords are continuous [0,1]^3.
        resolution: Tuple (H, W, D) for the output feature volume.
        feature_dim: Integer C for the output feature dimension.
        
    Returns:
        F: Neural feature volume tensor of shape (H, W, D, C).
    """
    if not primitives:
        return zeros((resolution[0], resolution[1], resolution[2], feature_dim)) # [G]
    
    # Step 1: Voxelize primitives into a sparse tensor
    sparse_tensor = voxelize(primitives, resolution)
    
    # Step 2: Process through sparse U-Net 3D ConvNet
    # Encoder-decoder structure with bottleneck and skip connections
    feature_volume = sparse_unet_3d_forward(sparse_tensor, feature_dim)
    
    return feature_volume

def voxelize(points, resolution):
    """Maps continuous 3D points to discrete grid cells, aggregating features."""
    grid = {}
    for coords, feats in points:
        cell = tuple(int(c * d) for c, d in zip(coords, resolution))
        if cell not in grid:
            grid[cell] = []
        grid[cell].append(feats)
    # Average features for cells with multiple points
    for cell in grid:
        grid[cell] = mean(grid[cell], axis=0)
    return grid

def sparse_unet_3d_forward(sparse_tensor, output_channels):
    """Simulates sparse U-Net 3D ConvNet with encoder, bottleneck, decoder, and skips."""
    # Encoder downsamples spatial dimensions
    encoded = downsample(sparse_tensor)
    # Bottleneck
    bottleneck = bottleneck_layer(encoded)
    # Decoder upsamples with skip connections
    decoded = upsample(bottleneck, skip_connections=encoded)
    # Project to output feature dimension
    output = linear_projection(decoded, output_channels)
    return output

def trilinear_interpolate(volume, point_coords):
    """Standard trilinear interpolation for 3D grid at continuous coordinates."""
    # Returns feature vector at continuous coordinates
    return volume[point_coords] # [G] Standard grid sampling operation
```

## Subtopics

### [Neural Inpainting for Holes](8918-neural-inpainting-for-holes.md)
Neural Inpainting for Holes resolves the "one-to-many" geometric ambiguity in dynamic volume rendering where forward warping leaves empty voxels. It uses a dedicated 3D convolutional network to predict and fill missing voxel values, enabling high-resolution reconstruction from lower-resolution warped inputs. It is distinct from sibling methods by addressing temporal warping artifacts specifically [8918-neural-inpainting-for-holes.md].

### [Sparse Domain Decomposition](9993-sparse-domain-decomposition.md)
Sparse Domain Decomposition partitions the spatial domain into fixed-size subdomains, each modeled by a dedicated neural network (expert). This solves performance degradation in large domains where normalized coordinates become incoherently clustered. It enables parallel training/inference without inter-process communication and uses a fixed, non-learnable gate function, differing from standard Mixture-of-Experts [9993-sparse-domain-decomposition.md].

### [TensorBase](10906-tensorbase.md)
TensorBase is a base class for tensor-based volume rendering that manages the axis-aligned bounding box (AABB), grid size, SVD volume initialization, and rendering module selection. It provides the core tensor management and ray sampling logic, distinguishing itself by handling the geometric mapping from ray space to the feature grid [10906-tensorbase.md].

### [4D Semantic Embedding](13330-4d-semantic-embedding.md)
4D Semantic Embedding constructs a spatio-temporal field of semantic feature vectors derived from the Segment Anything Model (SAM). It leverages SAM's 2D encoder outputs as ground-truth supervision targets for a learnable 4D field, providing object priors for photometric rendering and tracking, rather than relying solely on implicit neural representations [13330-4d-semantic-embedding.md].

#### Precomputed Sampling Features
Pre-calculated transmission and phase features stored in a table to accelerate neural network input generation [S3, unofficial]. It involves 4129 template samplings per volume using a uniform strategy, generating 254 sampled transmission and 254 phase transmission features per sample [S3, unofficial]. Phase features are calculated using volume phase and angles between incident light and camera, while transmission features are derived from a graded density field via 3D-CNN [S3, unofficial]. All points are pre-calculated and stored in a table [S3, unofficial].

#### Neural Volumes Baseline Adaptation
An adaptation of the Neural Volumes method for single-camera dynamic scenes [S4]. It modifies the encoder to take a single input image, disables background estimation, and learns the complete scene centered around the face scaled to a unit cube [S4]. Parameters include a $128^3$ voxel grid, $32^3$ warp field resolution, and 100k training iterations per sequence [S4].

#### Target View Frustum Volume Construction
Constructs the radiance volume in the target view frustum space rather than a fixed reference view space to aggregate multi-view input information [S5]. This avoids information loss from regions outside the reference view's epipolar lines, which is critical for large baselines [S5]. It outperforms reference view volumes by 1 dB PSNR on large baselines (RealEstate10K) and maintains an advantage on small baselines (DTU) [S5].

#### NeRF-Det Multi-View Feature Aggregation
Scatters image features to voxels along rays from each camera origin through each pixel [S6]. Multi-view features are aggregated by averaging all effective features: $V_{avg}(p) = \sum_{i=1}^{M_p} V_i(p) / M_p$ [S6]. A pitfall is that naive volume features "over populate" projection rays without considering empty spaces, causing detection errors [S6]. This is mitigated by incorporating a NeRF branch to improve geometry learning [S6].

#### Frustum Fusion into Shared 3D Neural Field
Transforms frustums from each view to world coordinates and fuses them into a shared 3D neural field represented as density and feature voxel grids ($V_{Density}$, $V_{Feat}$) [S7]. For each voxel indexed by $(x, y, z)$, it pools all densities and features of the corresponding frustum entries and takes the mean [S7]. $V_{Density}$ and $V_{Feat}$ have the same spatial size, and each voxel represents a region in the world coordinate system [S7].

#### PixelNeRF Volume Construction
Encodes input images using a CNN encoder $E$ to produce feature volumes at resolutions $128 \times H/8 \times W/8$ and $256 \times H/16 \times W/16$ [S8]. These are upsampled bilinearly to $H/2 \times W/2$ and concatenated along the channel dimension to form a final volume of size $512 \times H/2 \times W/2$ [S8]. For small input images (e.g., $64 \times 64$), the first pooling layer is skipped to avoid excessive resolution loss [S8]. The encoder uses ImageNet pretrained weights [S8].

## Operating characteristics
* **Time Complexity:** Depends on the 3D ConvNet size and resolution; sparse operations reduce complexity relative to dense grids [S2].
* **Memory Complexity:** Proportional to $H \times W \times D \times C$; sparse representations mitigate this for large volumes [S2].
* **Performance:** Target view frustum construction yields +1 dB PSNR over reference view volumes on large baselines [S5].
* **Strengths:** Integrates local and global information via U-Net structure; world-aligned output facilitates downstream decoding [S2].
* **Limitations:** Naive aggregation can lead to ambiguity and over-population [S6]; reference view construction suffers from information loss [S5].

## Background
The method draws inspiration from generalizable 3D latent neural volume models [S2]. It is used in systems like EVolSplat for efficient volume-based Gaussian splatting [S2], UV Volumes for real-time rendering of editable free-view human performance [S1], Nerfies for deformable radiance fields [S4], MuRF for multi-baseline synthesis [S5], and NeRF-Det for 3D object detection [S6].
