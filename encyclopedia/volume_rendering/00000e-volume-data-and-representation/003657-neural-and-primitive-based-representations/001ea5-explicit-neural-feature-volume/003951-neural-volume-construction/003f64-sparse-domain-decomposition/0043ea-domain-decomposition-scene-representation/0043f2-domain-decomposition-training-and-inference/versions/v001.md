# Domain Decomposition Training and Inference

Also called: Domain Decomposition Training, Parallel SRN training

## Overview
A model-parallel strategy for fitting large-scale volumes by partitioning the data into a grid of bricks, where one SRN is trained per brick in parallel on multiple GPUs [S1]. It avoids out-of-core I/O overhead by ensuring each brick fits in GPU memory and accelerates inference using spatial hashing to map query points to the correct model [S1]. It is distinguished from single-model approaches by enabling the reconstruction of volumes (e.g., 450 GB) in under 7 minutes on 8 GPUs while increasing accuracy over a single model with the same total parameter count [S1].

## How it works
**Inputs:** Large-scale volume data (e.g., NetCDF), number of GPUs available, brick grid dimensions ($I \times J \times K$).
**Outputs:** A set of trained SRN models (specifically APMGSRN), each associated with a spatial extent.

**Data Structures:**
*   **Brick Grid:** The volume is divided into a 3D grid of bricks. Each brick corresponds to one SRN.
*   **Job Queue:** A list of training jobs assigned to available GPUs.
*   **Spatial Hash Table:** A hash function mapping 3D spatial coordinates to the index of the brick (and thus the model) responsible for that region.

**Steps:**
1.  **Pre-calculation:** Calculate the spatial extents of each network within the volume's total extents. This includes defining boundaries for "ghost cells" if using the variant with ghost cells [S1]. Generate a list of jobs (bricks) to be assigned to available GPUs.
2.  **Parallel Training Loop:**
    *   Assign a job to an available GPU.
    *   Initialize an APMGSRN model on that GPU [S1].
    *   Load only the data within the assigned brick's extents into GPU memory. This leverages parallel file access and arbitrary cropping (e.g., in NetCDF) to minimize I/O overhead [S1].
    *   Train the model using the following early stopping criteria:
        *   Use a plateau learning rate scheduler.
        *   Monitor reconstruction loss $L_{rec}$.
        *   If $L_{rec}$ has not decreased by 0.01% over 500 iterations, reduce the learning rate by a factor of 10.
        *   Repeat the reduction up to 3 times. After the 3rd trigger, terminate training for that model [S1].
    *   When training finishes, return the GPU to the available list and assign the next job.
3.  **Inference Setup:** Load all trained models into GPU memory on the inference machine [S1].
4.  **Inference Query:** For a query point $\mathbf{p}$:
    *   Compute the hash of $\mathbf{p}$ to determine the corresponding brick index.
    *   Retrieve the model associated with that brick.
    *   Query the model to obtain the volume properties (e.g., density, color) [S1].

**Pseudocode:**

```python
def train_domain_decomposition(volume_data, brick_grid_shape, gpu_ids):
    """
    Trains one SRN per brick in parallel across available GPUs.
    """
    # 1. Pre-calculate extents and generate job list
    # Each job is a tuple: (brick_id, spatial_extent, data_subset)
    jobs = []
    for i in range(brick_grid_shape[0]):
        for j in range(brick_grid_shape[1]):
            for k in range(brick_grid_shape[2]):
                brick_id = (i, j, k)
                # Calculate spatial bounds for this brick
                extent = calculate_brick_extent(brick_id, brick_grid_shape, volume_data.total_extent)
                # Load data subset for this extent
                # Assumes parallel file access support (e.g., NetCDF)
                data_subset = volume_data.crop(extent)
                jobs.append((brick_id, extent, data_subset))
    
    # 2. Parallel training loop
    available_gpus = list(gpu_ids)
    trained_models = {}
    
    while jobs:
        if not available_gpus:
            # Wait for a GPU to finish (simplified synchronization)
            finished_gpu, model, brick_id = wait_for_gpu_completion()
            trained_models[brick_id] = model
            available_gpus.append(finished_gpu)
        
        # Assign next job to an available GPU
        gpu_id = available_gpus.pop(0)
        brick_id, extent, data_subset = jobs.pop(0)
        
        # Initialize APMGSRN model
        model = APMGSRN()
        
        # Training loop with early stopping
        learning_rate = initial_lr
        patience_count = 0
        best_loss = float('inf')
        
        for iteration in range(max_iterations):
            # Sample points from data_subset
            points, targets = sample_points(data_subset)
            
            # Forward pass
            predictions = model(points)
            
            # Calculate reconstruction loss
            loss = calculate_loss(predictions, targets)
            
            # Early stopping logic
            if loss < best_loss - 0.0001 * best_loss: # 0.01% decrease
                best_loss = loss
                patience_count = 0
            else:
                patience_count += 1
                if patience_count >= 500:
                    learning_rate /= 10.0
                    patience_count = 0
                    patience_count_trigger += 1
                    if patience_count_trigger >= 3:
                        break # Finish training
        
        trained_models[brick_id] = model
        # Return GPU to pool (handled by wait_for_gpu_completion in next iteration)

def infer_domain_decomposition(query_point, trained_models, spatial_hash):
    """
    Infers volume properties for a query point using spatial hashing.
    """
    # Map spatial coordinates to brick index
    brick_id = spatial_hash(query_point)
    
    # Retrieve the correct model
    model = trained_models[brick_id]
    
    # Query the model
    result = model(query_point)
    return result
```

**Parameters:**
*   **Brick Grid Shape ($I \times J \times K$):** Determines the number of models. Not given in the sources.
*   **Initial Learning Rate:** Not given in the sources.
*   **Max Iterations:** Not given in the sources.
*   **Plateau Threshold:** 0.01% decrease in $L_{rec}$ [S1].
*   **Plateau Patience:** 500 iterations [S1].
*   **LR Reduction Factor:** 10 [S1].
*   **Max LR Reductions:** 3 [S1].

**Edge Cases and Pitfalls:**
*   **Inference Search:** Inference requires finding the correct model for a query point, which is a search problem. Spatial hashing is used to accelerate this [S1].
*   **Boundary Artifacts:** Without ghost cells, adjacent networks trained independently may produce discontinuous outputs at interfaces [S1, see Subtopics].
*   **Sparse Data:** Regions with sparse data may converge quickly, allowing for early stopping (down to 20 seconds per model) [S1].

## Subtopics

### [Domain Decomposition with Ghost Cells](11133-domain-decomposition-with-ghost-cells.md)
Extends this method by adding overlapping "ghost cells" at brick boundaries to solve visible seams and boundary artifacts. It trades a slight reduction in learning capacity for improved visual continuity.

## Operating characteristics
*   **Time Complexity:** Training time is reduced significantly by parallelizing across GPUs and using early stopping. In the cited experiment, a 450 GB volume was fitted in under 7 minutes on 8 GPUs [S1]. Sparse regions can be trained in as little as 20 seconds per model [S1].
*   **Memory Complexity:** Each GPU only loads the data for its assigned brick, avoiding out-of-core I/O overhead. This requires sufficient GPU memory to hold one brick's data and model parameters [S1].
*   **Scaling:** Scales with the number of available GPUs. Assumes a compute node with multiple GPUs [S1].
*   **Strengths:** Fits very large volumes (450 GB) efficiently; increases reconstruction accuracy over a single model with the same total parameters; reduces I/O overhead [S1].
*   **Limitations:** Inference requires a spatial search (mitigated by hashing); potential boundary artifacts without ghost cells [S1].
*   **When to use:** Large-scale volumes that do not fit in a single GPU's memory; scenarios where training time is critical and parallel hardware is available [S1].
*   **When not to use:** Small volumes that fit in a single GPU; scenarios requiring seamless boundaries without the overhead of ghost cells [S1].

## Background
Originated from the work of Skylar W. Wurster at The Ohio State University, published in *IEEE Transactions on Visualization and Computer Graphics* in 2023 [S1]. The method builds on the Adaptively Placed Multi-Grid Scene Representation Network (APMGSRN) architecture, which uses adaptive feature grids to localize trainable parameters [S1]. It addresses the limitations of single-model SRNs in handling large-scale data by distributing the training load across multiple GPUs [S1].
