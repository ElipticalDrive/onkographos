# Sparse Domain Decomposition

Also called: MoE-inspired decomposition, MoE-inspired domain decomposition, Sparsely-gated Mixture-of-Experts inspired decomposition

## Overview
Sparse domain decomposition is a technique for representing large-scale volumetric scenes by partitioning the spatial domain into fixed-size subdomains, each modeled by a dedicated neural network (expert) [S1][S2, unofficial]. It solves the performance degradation of single-network approaches in large domains, where normalized input coordinates $[0, 1]$ become incoherently clustered, causing poor feature mapping [S1][S2, unofficial]. Unlike single-model approaches, it enables parallel training and inference without inter-process communication by assigning groups of subdomains to each GPU [S1]. It differs from standard Mixture-of-Experts (MoE) by using a fixed, non-learnable gate function rather than a learned gating mechanism [S1].

## How it works
**Inputs:**
- A 3D spatial domain (scene).
- A target resolution or voxel grid.

**Outputs:**
- A set of active subdomains, each associated with a neural network (expert) and a gate function [S1].
- For a query coordinate $\mathbf{x}$, the output $\hat{y}$ (child/active masks or voxel values) [S1].

**Data Structures:**
1. **Subdomain Grid:** A regular 3D grid partitioning the domain [S1].
2. **Active Subdomains:** A list of subdomains that contain data; empty subdomains are discarded [S1].
3. **Expert Network ($E_k$):** A neural network assigned to each active subdomain $D_k$ [S1]. All experts share the same architecture [S1].
4. **Gate Function ($G(\mathbf{x})_k$):** A fixed clamped tent function associated with each subdomain $D_k$ [S2, unofficial].

**Parameters:**
- **Subdomain Size:** Configurable size in index space, range $[512, 2048]$ [S1][S2, unofficial].
- **Halo Size:** Fixed-width overlap between adjacent subdomains, set to 8 voxels [S1][S2, unofficial]. This width is chosen to eliminate discontinuities while minimizing compute overhead [S1].

**Algorithm:**
1. Partition the entire domain into a regular grid of subdomains [S1].
2. Discard empty subdomains [S1].
3. Define a dedicated neural network (expert) $E_k$ for each subdomain, using the same architecture for all experts [S1].
4. Define a gate function $G(\mathbf{x})_k$ for each subdomain $D_k$, where $\mathbf{x}$ is normalized to $[0, 1]$ within the subdomain's bounding box [S1][S2, unofficial]. The gate is a clamped tent function covering the subdomain including the halo, with a maximum value of 1 uniformly outside the overlapping region [S2, unofficial].
5. For a query coordinate $\mathbf{x}$, determine the set of active subdomains $\mathcal{K}$ whose gate functions return a non-zero value. Due to halo overlaps, up to 8 gates may be active [S1].
6. **Optimization:** Evaluate the gate functions first to determine which networks to invoke; only compute for networks with non-zero gate values [S1].
7. Compute the output for each active expert and aggregate. When multiple gates are active, average the evaluated values weighted by the gate functions [S1].

**Formula:**
The final output $\hat{y}$ is calculated as:
$$
\hat{y} = \sum_{k=1}^n G(\mathbf{x})_k E_k(\mathbf{x})
$$
where $n$ is the total number of subdomains, $\hat{y}$ is the output (child/active masks or voxel values), $G(\mathbf{x})_k$ is the gate function for subdomain $k$, and $E_k(\mathbf{x})$ is the expert network output for subdomain $k$ [S1][S2, unofficial].

**Pseudocode:**
```python
def sparse_domain_decomposition_query(x, subdomains, halo_ratio):
    """
    Query the sparse domain decomposition for a normalized coordinate x.
    Args:
        x: tuple (x, y, z) normalized coordinates in [0, 1] for the global domain.
        subdomains: list of dicts with keys 'bbox_min', 'bbox_max', 'expert'.
        halo_ratio: float, halo_size / subdomain_size in normalized units.
    Returns:
        y_hat: weighted average output.
    """
    active_experts = []
    gate_weights = []

    for sub in subdomains:
        bbox_min = sub['bbox_min']
        bbox_max = sub['bbox_max']
        size = [bbox_max[i] - bbox_min[i] for i in range(3)]
        # Transform global x to local coordinates [0, 1] for this subdomain's core
        local_x = [(x[i] - bbox_min[i]) / size[i] for i in range(3)]

        gate_val = compute_clamped_tent_gate(local_x, halo_ratio)

        if gate_val > 0.0:
            active_experts.append(sub['expert'])
            gate_weights.append(gate_val)

    if not active_experts:
        return 0.0  # Default background value [G]

    numerator = 0.0
    denominator = 0.0
    for expert, weight in zip(active_experts, gate_weights):
        # Experts expect coordinates normalized to their subdomain bounding box [S1]
        expert_output = expert.forward(local_x)
        numerator += weight * expert_output
        denominator += weight

    if denominator == 0.0:
        return 0.0
    return numerator / denominator

def compute_clamped_tent_gate(local_x, halo_ratio):
    """
    Computes a 3D clamped tent gate function.
    local_x: coordinates in [0, 1] for the subdomain core.
    halo_ratio: halo_size / subdomain_size in normalized units.
    Returns value in [0, 1].
    """
    dist = [abs(local_x[i] - 0.5) for i in range(3)]
    max_dist = 0.5 + halo_ratio
    gate_1d = []
    for d in dist:
        if d <= 0.5:
            gate_1d.append(1.0)
        elif d <= max_dist:
            gate_1d.append(1.0 - (d - 0.5) / halo_ratio)
        else:
            gate_1d.append(0.0)
    return gate_1d[0] * gate_1d[1] * gate_1d[2]
```

**Training:**
1. Train experts concurrently on multiple GPUs [S1].
2. Assign groups of subdomains to each GPU; there may be more subdomains than available GPUs [S1].
3. The gate functions are fixed and not learned [S1].

**Post-Training:**
1. Merge groups of subdomains into a single NeuralVDB structure [S1].

**Edge Cases and Pitfalls:**
- **Boundary Discontinuities:** The halo size must be sufficient to eliminate discontinuities; 8 voxels is recommended [S1][S2, unofficial].
- **Empty Subdomains:** Must be discarded to save memory and compute [S1].
- **Coordinate Normalization:** Input coordinates must be normalized to $[0, 1]$ relative to the subdomain's bounding box for gate evaluation [S1].
- **Overlap Handling:** Multiple gate functions can be non-zero (up to 8). The output must be averaged/normalized to prevent intensity doubling in overlaps [S1].

## Subtopics

### [Domain Decomposition Scene Representation](11124-domain-decomposition-scene-representation.md)
Domain Decomposition Scene Representation is a model-parallel technique for representing large-scale volumetric data by partitioning the spatial domain into fixed-size bricks, each modeled by a dedicated neural network. It solves the memory and I/O bottlenecks of single-network approaches by ensuring each brick fits within GPU memory, eliminating the need for out-of-core sampling. Unlike single-model approaches, it enables parallel training and inference without inter-process communication, scaling accuracy and speed for massive datasets.

## Operating characteristics
- **Time Complexity:** Query time is proportional to the number of active experts covering the query point (up to 8) plus the cost of evaluating those experts. Training is parallelizable across GPUs [S1].
- **Memory Complexity:** Memory usage is proportional to the number of active subdomains times the size of the expert network. Empty subdomains are discarded, reducing memory compared to a dense grid of experts [S1].
- **Performance:** Enables high-resolution rendering of large scenes by avoiding the poor performance of single networks on normalized coordinates [S1][S2, unofficial].
- **Strengths:** Scalability to large scenes, parallel training, no inter-process communication needed, eliminates discontinuities with halos [S1].
- **Limitations:** Fixed gate functions may not adapt to scene complexity as well as learned gates (standard MoE) [S1]. Requires careful tuning of subdomain size and halo size [S1].
- **When to Use:** Large-scale volumetric scenes where single-network approaches fail due to coordinate normalization issues or memory constraints [S1].
- **When Not to Use:** Small scenes where a single network suffices, or when adaptive gating is required for complex, non-uniform data distributions [G].

## Background
Sparse domain decomposition was proposed in the NeuralVDB paper (2022) by NVIDIA researchers [S1][S2, unofficial]. It is inspired by the sparsely-gated Mixture-of-Experts (MoE) method [Shazeer et al. 2017] [S1]. The method addresses the limitations of standard VDB value-mapping, which is agnostic to incoherent clustering of voxels in large domains [S1]. It is used in high-resolution sparse volume representation using hierarchical neural networks [S1].
