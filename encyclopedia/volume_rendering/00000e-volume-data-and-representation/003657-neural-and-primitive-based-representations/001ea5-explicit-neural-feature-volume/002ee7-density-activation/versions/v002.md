# Density Activation

Also called: DVGO Alpha Activation (Raw2Alpha), Density Rendering, Raw2Alpha, TensorBase Density Feature to Density, fea2denseAct

## Overview
Density Activation converts raw neural feature outputs (pre-activations) into valid, non-negative density values suitable for volume rendering [S2, unofficial]. It solves the problem of ensuring that density values remain physically meaningful (non-negative) and differentiable for gradient-based optimization [S4, unofficial]. It differs from its parent [Explicit Neural Feature Volume](1838-explicit-neural-feature-volume.md) by specifically handling the final non-linear mapping step from feature space to scalar density, whereas the parent focuses on the storage and retrieval of the feature tensor itself [G].

## How it works
**Inputs and Outputs:**
- Input: Raw density features (pre-activations), typically a tensor of real-valued logits [S2, unofficial].
- Output: Activated density values $\sigma$ or alpha values $\alpha$, a tensor of the same shape with values in $[0, \infty)$ [S4, unofficial].

**Data Structures:**
- `density_features`: Tensor of raw logits.
- `density_shift` ($b$ or `self.act_shift`): Scalar hyperparameter added before activation [S4, unofficial].
- `interval`: Scalar hyperparameter representing the distance between sample points, defaulting to `self.voxel_size_ratio` if not provided [S1, unofficial].

**Parameters:**
- `fea2denseAct`: String specifying the activation function type. Options: `'softplus'` or `'relu'` [S4, unofficial].
- `density_shift` ($b$): Shift value added to density features before activation [S4, unofficial]. In Direct Voxel Grid Optimization, this is determined by initialization logic in the coarse stage [S6].
- `interval`: Used in alpha conversion to account for sampling distance [S1, unofficial].

**Steps:**
1. Retrieve the raw density features from the feature volume [S2, unofficial].
2. If processing chunks (e.g., ray points), query the network for density features in the current chunk [S2, unofficial].
3. Apply the selected activation function to convert features to density:
   - If `fea2denseAct` is `'softplus'`: Compute $\sigma = \text{softplus}(\vec{\sigma} + b)$ [S4, unofficial].
   - If `fea2denseAct` is `'relu'`: Compute $\sigma = \text{ReLU}(\vec{\sigma})$ [G].
4. Convert density to alpha using the sampling interval: $\alpha = 1 - (1 + \exp(\sigma + b))^{-\text{interval}}$ [S1, unofficial].
5. If flattening was used, reshape the output to match the original density feature shape [S1, unofficial].
6. Concatenate results from all chunks and return [S2, unofficial].

**Formulas:**
The shifted softplus activation is defined as [S4, unofficial]:
$$\sigma = \text{softplus}(\vec{\sigma}) = \log(1 + \exp(\vec{\sigma} + b))$$
where $\vec{\sigma}$ is the raw density feature and $b$ is the shift hyperparameter [S4, unofficial].

The alpha conversion accounting for the sampling interval is defined as [S1, unofficial]:
$$\alpha = 1 - (1 + \exp(\sigma + b))^{-\text{interval}}$$

The derivative for backpropagation is [S1, unofficial]:
$$\alpha' = \text{interval} \cdot (1 + \exp(\sigma + b))^{-(\text{interval}+1)} \cdot \exp(\sigma + b)$$

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def density_activation(density_features: torch.Tensor, 
                       activation_type: str = 'softplus', 
                       density_shift: float = 0.0, 
                       interval: float = None,
                       voxel_size_ratio: float = 1.0) -> torch.Tensor:
    """
    Converts raw density features to density and alpha values.
    
    Args:
        density_features: Raw logits tensor.
        activation_type: 'softplus' or 'relu'.
        density_shift: Shift parameter b for softplus.
        interval: Distance between sample points. Defaults to voxel_size_ratio if None.
        voxel_size_ratio: Fallback interval value.
        
    Returns:
        Activated density tensor and alpha tensor.
    """
    # Step 1: Apply activation to get density
    if activation_type == 'softplus':
        density = F.softplus(density_features + density_shift)
    elif activation_type == 'relu':
        density = F.relu(density_features)
    else:
        raise ValueError(f"Unknown activation type: {activation_type}")
        
    # Step 2: Convert density to alpha using interval
    if interval is None:
        interval = voxel_size_ratio # Not given in the sources.
    exp_val = torch.exp(density + density_shift)
    alpha = 1.0 - torch.pow(1.0 + exp_val, -interval)
    
    return density, alpha
```

**Edge Cases and Pitfalls:**
- **Negative Values with ReLU:** Using ReLU can result in irreparable negative density values if the voxel is falsely set to a negative value during optimization, as ReLU hard-clamps to 0, potentially creating holes or artifacts [S4, unofficial]. Softplus is preferred because it allows density to explore values very close to 0 without hard clamping [S4, unofficial].
- **Precision:** The exponential in softplus can cause numerical overflow if $\vec{\sigma} + b$ is large. Standard implementations use stable log-sum-exp tricks or library functions that handle this [G].
- **Shift Initialization:** The value of $b$ in softplus is critical and is often determined by initialization logic in the coarse stage of training [S6].
- **Chunk Processing:** When processing ray points in chunks, results must be concatenated before returning [S2, unofficial].

## Subtopics

### Gaussian Parameter Activation
Converts raw network outputs (pre-activations) into valid Gaussian parameters: scales, rotations, and opacities [S5, unofficial]. It differs from standard density activation by handling multiple parameter types rather than a single scalar density [S5, unofficial]. Choose this when working with 3D Gaussian Splatting representations [S5, unofficial].
- **Steps:**
  1. Compute scales by exponentiating pre-activation scales: $\text{scales} = \exp(\text{pre\_act\_scales})$ [S5, unofficial].
  2. Normalize pre-activation quaternions to unit length: $\text{quats} = \text{normalize}(\text{pre\_act\_quats})$ [S5, unofficial].
  3. Compute opacities using sigmoid activation: $\text{opacities} = \sigma(\text{pre\_act\_opacities})$ [S5, unofficial].

### Post-activated Density Voxel Grid
A voxel grid representation where density values are stored explicitly in grid cells and interpolated via trilinear interpolation before applying a non-linear activation function (softplus) and alpha calculation [S6]. It allows sharp decision boundaries with fewer grid cells compared to pre- or in-activation methods [S6]. Choose this when high-fidelity reconstruction with fewer grid cells is required [S6].
- **Parameters:**
  - $b$: The shift hyperparameter in the softplus activation function, determined by initialization logic in the coarse stage [S6].

### Low-density Initialization & Post-activation
Initializes voxel grids with low density values and applies post-activation to the network outputs [S6]. A known pitfall is that low-density initialization and free space skipping cannot be applied simultaneously [S6].

### Density Mapping Layer
A layer that derives the density of a sample from its queried feature vector [S7]. For real-world 360 datasets, it applies a linear transform from the feature vector to the density value. For NeRF synthetic datasets, it applies a tiny network with one hidden layer and 64 neurons [S7].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels/features, as it involves a simple element-wise operation [G].
- **Memory Complexity:** $O(1)$ additional memory per feature, as it operates in-place or creates a new tensor of the same size [G].
- **Strengths:** Softplus provides smooth gradients and avoids hard clamping artifacts associated with ReLU [S4, unofficial].
- **Limitations:** Softplus is computationally more expensive than ReLU due to the exponential and logarithm operations [G]. The choice of activation impacts final image quality [S4, unofficial].
- **When to use:** Use softplus for general volume rendering to ensure smooth density transitions and avoid artifacts [S4, unofficial]. Use ReLU only if computational speed is critical and artifacts are acceptable or mitigated by other means [S4, unofficial].

## Background
Density Activation is a fundamental component in neural volume rendering, particularly in methods that use explicit neural feature volumes or voxel grids [G]. The use of shifted softplus for density activation was popularized by Mip-NeRF [S6]. Direct Voxel Grid Optimization (DVGO) further refined its use by demonstrating the benefits of post-activation in voxel grids [S6]. The term "fea2denseAct" is used in implementations like Collaborative Neural Radiance Fields [S4, unofficial].
