# Density Activation

Also called: TensorBase Density Feature to Density, fea2denseAct

## Overview
Density Activation converts raw neural feature outputs (pre-activations) into valid, non-negative density values suitable for volume rendering. It solves the problem of ensuring that density values remain physically meaningful (non-negative) and differentiable for gradient-based optimization. It differs from its parent [Explicit Neural Feature Volume](1838-explicit-neural-feature-volume.md) by specifically handling the final non-linear mapping step from feature space to scalar density, whereas the parent focuses on the storage and retrieval of the feature tensor itself.

## How it works
**Inputs and Outputs:**
- Input: Raw density features (pre-activations), typically a tensor of shape $(N, 1)$ or $(H, W, D, 1)$ containing real-valued logits.
- Output: Activated density values $\sigma$, a tensor of the same shape with values in $[0, \infty)$.

**Data Structures:**
- `density_features`: Tensor of raw logits.
- `density_shift`: Scalar hyperparameter $b$ (or `self.act_shift`).
- `interval`: Scalar hyperparameter, often defaulting to `self.voxel_size_ratio` [S1, unofficial].

**Parameters:**
- `fea2denseAct`: String specifying the activation function type. Options: `'softplus'` or `'relu'` [S2, unofficial].
- `density_shift` ($b$): Shift value added to density features before activation [S2, unofficial]. In Direct Voxel Grid Optimization, this is determined by initialization logic in the coarse stage [S4].
- `interval`: Used in some implementations (e.g., ref-dvgo) to scale the input before activation [S1, unofficial].

**Steps:**
1. Retrieve the raw density features from the feature volume.
2. If an `interval` is provided, scale the features by `interval` [S1, unofficial].
3. Apply the selected activation function:
   - If `fea2denseAct` is `'softplus'`: Compute $\sigma = \text{softplus}(\vec{\sigma} + b)$ [S2, unofficial][S4].
   - If `fea2denseAct` is `'relu'`: Compute $\sigma = \text{ReLU}(\vec{\sigma})$ [S2, unofficial].
4. Reshape the output to match the original density feature shape [S1, unofficial].

**Formulas:**
The shifted softplus activation is defined as [S4]:
$$
\sigma = \text{softplus}(\vec{\sigma}) = \log(1 + \exp(\vec{\sigma} + b))
$$
where $\vec{\sigma}$ is the raw density feature and $b$ is the shift hyperparameter [S4].

The ReLU activation is defined as [S2, unofficial]:
$$
\sigma = \max(0, \vec{\sigma})
$$

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def density_activation(density_features: torch.Tensor, 
                       activation_type: str = 'softplus', 
                       density_shift: float = 0.0, 
                       interval: float = None) -> torch.Tensor:
    """
    Converts raw density features to density values.
    
    Args:
        density_features: Raw logits tensor.
        activation_type: 'softplus' or 'relu'.
        density_shift: Shift parameter b for softplus.
        interval: Scaling factor (optional, defaults to None).
        
    Returns:
        Activated density tensor.
    """
    # Step 1: Apply interval scaling if provided [S1, unofficial]
    if interval is not None:
        density_features = density_features * interval
        
    # Step 2: Apply activation [S2, unofficial]
    if activation_type == 'softplus':
        # Shifted softplus: log(1 + exp(x + b)) [S4]
        # Using F.softplus(x, beta=1, threshold=100) is equivalent to log(1+exp(x))
        # We manually add the shift to ensure exact formula compliance [S2, unofficial][S4]
        density = F.softplus(density_features + density_shift)
    elif activation_type == 'relu':
        density = F.relu(density_features)
    else:
        raise ValueError(f"Unknown activation type: {activation_type}")
        
    # Step 3: Reshape to original shape [S1, unofficial]
    # Note: If input was flattened, reshape back. 
    # Assuming input is already in correct shape for simplicity, 
    # but ref-dvgo explicitly reshapes after flattening [S1, unofficial].
    return density
```

**Edge Cases and Pitfalls:**
- **Negative Values with ReLU:** Using ReLU can result in irreparable negative density values if the voxel is falsely set to a negative value during optimization, as ReLU hard-clamps to 0, potentially creating holes or artifacts [S4]. Softplus is preferred because it allows density to explore values very close to 0 without hard clamping [S4].
- **Precision:** The exponential in softplus can cause numerical overflow if $\vec{\sigma} + b$ is large. Standard implementations use stable log-sum-exp tricks or library functions that handle this [S4].
- **Shift Initialization:** The value of $b$ in softplus is critical and is often determined by initialization logic in the coarse stage of training [S4].

## Subtopics

### Gaussian Parameter Activation
Converts raw network outputs (pre-activations) into valid Gaussian parameters: scales, rotations, and opacities [S3, unofficial]. It sets apart from standard density activation by handling multiple parameter types (scales, quaternions, opacities) rather than a single scalar density [S3, unofficial]. Choose this when working with 3D Gaussian Splatting representations [S3, unofficial].
- **Steps:**
  1. Compute scales by exponentiating pre-activation scales: $\text{scales} = \exp(\text{pre\_act\_scales})$ [S3, unofficial].
  2. Normalize pre-activation quaternions to unit length: $\text{quats} = \text{normalize}(\text{pre\_act\_quats})$ [S3, unofficial].
  3. Compute opacities using sigmoid activation: $\text{opacities} = \sigma(\text{pre\_act\_opacities})$ [S3, unofficial].

### Post-activated Density Voxel Grid
A voxel grid representation where density values are stored explicitly in grid cells and interpolated via trilinear interpolation before applying a non-linear activation function (softplus) and alpha calculation [S4]. It allows sharp decision boundaries with fewer grid cells compared to pre- or in-activation methods [S4]. Choose this when high-fidelity reconstruction with fewer grid cells is required [S4].
- **Parameters:**
  - $b$: The shift hyperparameter in the softplus activation function, determined by initialization logic in the coarse stage [S4].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels/features, as it involves a simple element-wise operation.
- **Memory Complexity:** $O(1)$ additional memory per feature, as it operates in-place or creates a new tensor of the same size.
- **Strengths:** Softplus provides smooth gradients and avoids hard clamping artifacts associated with ReLU [S4]. It is computationally inexpensive.
- **Limitations:** Softplus is slightly more expensive than ReLU due to the exponential and logarithm operations [S4]. The choice of activation can significantly impact optimization stability and final image quality [S4].
- **When to use:** Use softplus for general volume rendering to ensure smooth density transitions and avoid artifacts [S4]. Use ReLU only if computational speed is critical and artifacts are acceptable or mitigated by other means [S2, unofficial].

## Background
Density Activation is a fundamental component in neural volume rendering, particularly in methods that use explicit neural feature volumes or voxel grids. The use of shifted softplus for density activation was popularized by Mip-NeRF [S4]. Direct Voxel Grid Optimization (DVGO) further refined its use by demonstrating the benefits of post-activation in voxel grids [S4]. The term "fea2denseAct" is used in implementations like Collaborative Neural Radiance Fields [S2, unofficial].
