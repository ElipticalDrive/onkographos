# Feature-based TF Design via ViT Features

Also called: Feature-based TF Design, Ours, Transfer Function Design via ViT Features

## Overview
This method designs transfer functions (TFs) for volume rendering by leveraging semantic features extracted from a pre-trained Vision Transformer (ViT), specifically DINO, to guide segmentation and opacity mapping [S1]. It solves the problem of ambiguous intensity-based segmentation in medical imaging where different structures share similar CT intensities [S1]. Unlike traditional intensity-thresholding or supervised learning approaches that require extensive annotation or training, this method performs one-time feature extraction and uses a post-processing step (Block Label Smoothing) to generate similarity maps for TF design [S1]. It sets itself apart from its parent [DINO ViT Feature Extraction](6425-dino-vit-feature-extraction.md) by providing the specific annotation and post-processing pipeline that converts raw feature volumes into usable transfer functions, and it outperforms Support Vector Machines (SVM) and Random Forests (RF) in segmentation quality with significantly fewer annotations [S1].

## How it works
**Inputs and Outputs:**
- Input: Volumetric data $V$ (e.g., CT scan) [S1].
- Output: A Transfer Function (TF) defined by similarity maps or opacity values for volume rendering [S1].

**Data Structures:**
- Feature Volume $F$: A 3D grid of semantic feature vectors [S1].
  - Layout: $F \in \mathbb{R}^{H \times W \times D \times C}$, where $H, W, D$ are spatial dimensions and $C$ is the feature dimension (e.g., 384 for DINO) [S1, S2].
  - Resolution: Typically $80^3$ for consumer GPUs [S1].
- Similarity Map: A scalar field derived from comparing query annotations against $F$ [S1].

**Steps:**
1. **Feature Extraction (Pre-processing):**
   - The input volume $V$ is processed by a pre-trained DINO ViT [S1].
   - To achieve a target feature resolution, the input to the ViT is scaled by the patch size [S1].
   - Feature maps are extracted for all three slicing directions (axial, coronal, sagittal) [S1].
   - These maps are pooled to the desired feature size to form the Feature Volume $F$ [S1].
   - This step is performed once at the beginning; no training phase is required [S1].

2. **Annotation and Inference:**
   - The user provides interactively collected annotations for structures of interest within the volume [S1].
   - For each annotated point, the corresponding feature vector is retrieved from $F$ [S1].
   - During inference, the method computes a similarity measure between the feature vector of every voxel in $F$ and the annotated feature vectors [S1]. This inference time is constant regardless of the original volume resolution [S1].

3. **Post-processing (Block Label Smoothing - BLS):**
   - The raw similarity maps undergo a post-processing step called Block Label Smoothing (BLS) [S1].
   - This step refines the similarity maps to reduce noise and blockiness, adapting to the feature resolution [S1].
   - The output is a refined similarity map used to define the transfer function [S1].

**Parameters:**
- Feature Volume Resolution ($F_{res}$): $80^3$ is sufficient for consumer GPUs with 8GB VRAM [S1]. Higher resolutions are possible but memory-intensive [S1].
- Input Scaling Factor: Determined by the ViT patch size to match the desired $F_{res}$ [S1].

**Pseudocode:**
```python
def design_tf_via_vit(volume, annotations, feature_resolution=80, patch_size=16):
    """
    volume: 3D array of shape (H, W, D) representing volumetric data.
    annotations: List of tuples (x, y, z, class_id) for interactively collected annotations [S1].
    feature_resolution: Target resolution for the feature volume F (e.g., 80) [S1].
    patch_size: Patch size of the ViT used for input scaling [S1].
    """
    # Step 1: Feature Extraction (Pre-processing)
    # Scale input to match ViT patch size requirements for target resolution [S1].
    target_shape = (feature_resolution * patch_size, feature_resolution * patch_size, feature_resolution * patch_size)
    scaled_volume = resize(volume, target_shape) # Bilinear interpolation [G]

    # Extract features using pre-trained DINO ViT for all three slicing directions [S1].
    feature_maps_axial = extract_vit_slices(scaled_volume, axis=2)
    feature_maps_coronal = extract_vit_slices(scaled_volume, axis=1)
    feature_maps_sagittal = extract_vit_slices(scaled_volume, axis=0)

    # Pool feature maps to desired feature size to form Feature Volume F [S1].
    F = pool_features([feature_maps_axial, feature_maps_coronal, feature_maps_sagittal], 
                      target_shape=(feature_resolution, feature_resolution, feature_resolution))

    # Step 2: Annotation and Inference
    # Retrieve feature vectors for each annotation from F [S1].
    annotation_features = []
    for (x, y, z, class_id) in annotations:
        f_voxel = F[x, y, z]
        annotation_features.append((f_voxel, class_id))

    # Compute similarity measure between every voxel in F and annotated feature vectors [S1].
    similarity_maps = {}
    for class_id, f_annot in annotation_features:
        sim_map = compute_similarity(F, f_annot)
        similarity_maps[class_id] = sim_map

    # Step 3: Post-processing (Block Label Smoothing - BLS)
    # Apply BLS to refine similarity maps; time varies with resolution [S1].
    refined_tf_maps = {}
    for class_id, sim_map in similarity_maps.items():
        refined_sim = block_label_smoothing(sim_map)
        refined_tf_maps[class_id] = refined_sim

    return refined_tf_maps

def extract_vit_slices(volume, axis):
    # Extract 2D slices along axis, pass through ViT encoder, return feature maps [G]
    slices = [volume[..., i] if axis == 2 else (volume[:, :, i] if axis == 1 else volume[:, i, :]) for i in range(volume.shape[axis])]
    features = [vit_encoder(slice_2d) for slice_2d in slices]
    return np.stack(features, axis=axis)

def pool_features(maps, target_shape):
    # Average pool feature maps from three directions to target resolution [G]
    pooled = [np.array(m).reshape(target_shape + (-1,)).mean(axis=-1) for m in maps]
    return np.mean(pooled, axis=0)

def compute_similarity(F, query):
    # Compute cosine similarity between query vector and all vectors in F [G]
    F_flat = F.reshape(-1, F.shape[-1])
    query_flat = query.reshape(-1, query.shape[-1])
    sim = np.dot(F_flat, query_flat) / (np.linalg.norm(F_flat, axis=1) * np.linalg.norm(query_flat) + 1e-8)
    return sim.reshape(F.shape[:-1])

def block_label_smoothing(sim_map):
    # Apply block label smoothing to reduce noise and blockiness [S1]
    return gaussian_filter(sim_map, sigma=1.0) # Standard smoothing [G]
```

**Edge Cases and Pitfalls:**
- **Memory Limits:** High memory requirements prevent the use of larger transformer models (ViT-B, ViT-L) or models with higher patch sizes [S1]. All feature maps for three slicing directions must be saved simultaneously [S1].
- **Ambiguous Structures:** Structures with similar CT intensities (e.g., bladder vs. kidneys/tissue) may be recognized as similar by the feature extractor, requiring careful threshold selection in the TF [S1].
- **Block Artifacts:** Renderings may exhibit block artifacts if structures cannot be perfectly detected at their surfaces [S1].
- **Disconnected Components:** Connected components filtering can discard falsely detected disconnected structures (e.g., separate kidneys), but fails if structures are too close [S1].

## Subtopics

### Neural DINO Feature MLP
A 4-layer Multi-Layer Perceptron (MLP) that outputs DINO features ($f_{dino}$) for a 3D coordinate $x$ [S2]. It is used in contexts where continuous feature fields are needed rather than discrete voxel grids [G]. The hidden dimension is 256 [S2]. The input 3D coordinate $x$ is encoded using 6 frequencies [S2]. The output feature dimension is 384 [S2].

### [SAM Encoder Feature Extraction](15946-sam-encoder-feature-extraction.md)
This method extracts high-level semantic features from a pre-trained Segment Anything Model (SAM) encoder to serve as ground-truth or supervisory signals for neural feature volumes in volume rendering. It solves the problem of aspect-ratio mismatch and padding artifacts introduced by SAM’s fixed-input resolution requirement. By cropping the encoder output to the original image’s aspect ratio, it isolates the valid semantic information from the padded regions, ensuring that the rendered features align spatially and semantically with the input geometry.

## Operating characteristics
- **Time Complexity:** Feature extraction is a one-time pre-processing cost [S1]. Inference time for annotation-based TF generation is constant regardless of the original volume resolution [S1]. Post-processing (BLS) time varies with resolution [S1].
- **Memory Complexity:** High. Requires saving feature maps for three slicing directions [S1]. 8GB VRAM suffices for $80^3$ resolution [S1]. Higher resolutions or larger models (ViT-B/L) exceed consumer GPU budgets [S1].
- **Performance:** Outperforms SVM and Random Forest approaches in segmentation quality (mean IoU of 0.981 on CT-ORG) even when SVM/RF annotation counts are increased by three orders of magnitude [S1]. SVM and RF approaches are significantly slower [S1].
- **Strengths:** No training phase required [S1]; leverages self-supervised semantic features [S1]; robust to intensity ambiguities compared to thresholding [S1]; high segmentation quality with sparse annotations [S1].
- **Limitations:** Memory-intensive [S1]; sensitive to similar appearances of different structures [S1]; potential for block artifacts in rendering [S1]; limited by ViT patch size and model size due to VRAM constraints [S1].
- **When to Use:** When semantic understanding of volume structures is needed, training data is scarce, and intensity-based segmentation fails due to tissue similarity [S1]. Suitable for consumer hardware if $80^3$ resolution is acceptable [S1].
- **When Not to Use:** When high-resolution feature maps are critical and sufficient VRAM is unavailable; when structures are extremely close together and connected component filtering cannot separate them [S1].

## Background
The method originates from research leveraging self-supervised Vision Transformers (ViT) for segmentation-based transfer function design in volume rendering [S1]. It was proposed to overcome the limitations of traditional intensity-based TF design and supervised learning methods that require extensive annotated data [S1]. The approach builds on the DINO ViT feature extraction technique [6425-dino-vit-feature-extraction.md] and was evaluated on medical imaging datasets like CT-ORG [S1]. It was published in IEEE Transactions on Visualization and Computer Graphics in 2024 [S1].
