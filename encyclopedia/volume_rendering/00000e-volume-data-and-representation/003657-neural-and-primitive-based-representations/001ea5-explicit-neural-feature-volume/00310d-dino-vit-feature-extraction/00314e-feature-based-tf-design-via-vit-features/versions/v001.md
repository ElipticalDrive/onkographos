# Feature-based TF Design via ViT Features

Also called: Feature-based TF Design, Ours, Transfer Function Design via ViT Features

## Overview
This method designs transfer functions (TFs) for volume rendering by leveraging semantic features extracted from a pre-trained Vision Transformer (ViT) [S1]. It solves the problem of ambiguous intensity-based segmentation in medical imaging by mapping user annotations to high-dimensional feature spaces, allowing for robust selection of structures with similar CT intensities [S1]. Unlike traditional intensity-based or machine learning approaches (e.g., SVM, Random Forests), it requires no training phase, relying instead on a one-time feature extraction and a post-processing similarity map refinement [S1]. It outperforms SVM and RF methods in segmentation quality even when annotation counts for those methods are increased by three orders of magnitude [S1].

## How it works
**Inputs and Outputs:**
- Input: Volumetric data $V$ (e.g., CT scan).
- Input: User annotations (points or regions) for target structures.
- Output: A Transfer Function (TF) or segmentation mask derived from feature similarity.

**Data Structures:**
- Feature Volume $F$: A 3D grid of feature vectors.
  - Layout: $F \in \mathbb{R}^{H \times W \times D \times C}$, where $H,W,D$ are spatial dimensions and $C$ is the feature dimension (e.g., 384 for DINO, 256 for SAM).
  - Bit packing: Not specified in sources. Typically stored as float32 per channel.

**Steps:**
1. **Feature Extraction (Pre-processing):**
   - Extract the 3D feature volume $F$ from $V$ using a self-supervised ViT (e.g., DINO or SAM encoder) [S1, S3].
   - This step is performed once at the beginning; no training is required [S1].
   - To achieve a specific feature resolution, the input volume must be scaled by the ViT's patch size [S1].
   - Feature maps are saved for all three slicing directions (axial, coronal, sagittal) and then pooled to the desired feature size [S1].

2. **Annotation and Similarity Map Generation:**
   - For each user annotation, compute a similarity map in the feature space [S1].
   - The similarity is calculated between the feature vector at each voxel and the feature vector(s) of the annotated region [S1].
   - Inference time for this step applies regardless of the volume resolution [S1].

3. **Post-processing (Block-based Similarity / BLS):**
   - Apply a post-processing step (referred to as BLS in sources) to refine the similarity map [S1].
   - This step varies with resolution and helps mitigate block artifacts [S1].
   - The refinement allows structures to be selected even if detected in a subset of slices ($S_L$) [S1].

4. **Thresholding and Segmentation:**
   - Select a threshold on the refined similarity map to generate the final TF/segmentation [S1].
   - Careful threshold selection is required to avoid selecting similar structures (e.g., bladder vs. kidneys) [S1].
   - Optional: Use a connected components filter to discard disconnected false positives [S1].

**Pseudocode:**

```python
def feature_based_tf_design(volume, annotations, vit_model, feature_resolution):
    """
    volume: 3D numpy array (H, W, D)
    annotations: list of (label, points) or (label, bounding_boxes)
    vit_model: Pre-trained ViT model (e.g., DINO or SAM)
    feature_resolution: Desired output resolution for F (e.g., 80)
    """
    # Step 1: Feature Extraction
    # Scale input to match ViT patch size requirements
    scaled_volume = scale_to_patch_size(volume, vit_model.patch_size)
    
    # Extract features for all three slicing directions
    # Note: This is memory intensive. 
    features_axial = vit_model.forward(scaled_volume, direction='axial')
    features_coronal = vit_model.forward(scaled_volume, direction='coronal')
    features_sagittal = vit_model.forward(scaled_volume, direction='sagittal')
    
    # Pool to desired feature resolution
    F = pool_features([features_axial, features_coronal, features_sagittal], feature_resolution)
    
    # Step 2: Generate Similarity Maps for each annotation
    similarity_maps = {}
    for label, ann_points in annotations:
        # Get feature vectors for annotated points
        ann_features = get_features_at_points(F, ann_points)
        
        # Compute similarity for all voxels in F
        # Similarity metric (e.g., cosine similarity) is not explicitly defined in sources [G]
        # Assuming cosine similarity between voxel feature and mean annotation feature
        mean_ann_feat = np.mean(ann_features, axis=0)
        sim_map = cosine_similarity(F, mean_ann_feat)
        similarity_maps[label] = sim_map
        
    # Step 3: Post-processing (BLS Refinement)
    refined_maps = {}
    for label, sim_map in similarity_maps.items():
        # Apply block-based similarity refinement
        # This step varies with resolution [S1]
        refined_map = apply_bls_refinement(sim_map, feature_resolution)
        refined_maps[label] = refined_map
        
    # Step 4: Thresholding
    tf = {}
    for label, refined_map in refined_maps.items():

        # Connected components filter can be applied here [S1]
        mask = refined_map > threshold
        tf[label] = mask
        
    return tf
```

**Parameters:**
- Feature Volume Resolution ($F$): $80^3$ suffices for consumer GPUs with 8GB VRAM [S1]. Higher resolutions (e.g., $96^3$) increase visual quality but demand prohibitive VRAM [S1].
- Input Scaling: Input to ViT must be scaled by the patch size to obtain specific feature resolution [S1].
- ViT Model: DINO or SAM encoder [S1, S3]. Larger models (ViT-B, ViT-L) are prevented by memory constraints [S1].

**Edge Cases and Pitfalls:**
- **Memory:** High memory requirement prevents using larger transformer models or higher patch sizes [S1].
- **Ambiguity:** Similar CT intensities cause the method to recognize multiple structures of similar appearance (e.g., bladder vs. kidneys/tissue) [S1]. Requires careful threshold selection [S1].
- **Block Artifacts:** Renderings may show block artifacts when structures cannot be perfectly detected at their surfaces [S1].
- **Connected Components:** Connected components filter works for separated structures but fails when structures are too close [S1].

## Subtopics

### Neural DINO Feature MLP
A 4-layer MLP that outputs DINO features ($f_{dino}$) for a 3D coordinate $x$ [S2]. It is used in photometric inverse rendering contexts to encode semantic features into a neural field [S2].
- **Hidden dimension:** 256 [S2].
- **Input encoding:** The 3D coordinate $x$ is encoded using 6 frequencies [S2].
- **Output dimension:** 384 [S2].
- **Source:** [S2]

### SAM Encoder Feature Extraction
Extraction of semantic features using a pre-trained Vision Transformer (ViT) from SAM, including specific resolution handling and cropping of padding regions [S3].
- **Definition:** Uses an MAE pre-trained ViT-H/16 with 14x14 windowed attention and four equally-spaced global attention blocks [S3].
- **Steps:**
  1. Resize input image to $1024 \times 1024$ by padding the shorter side [S3].
  2. Downscale resolution by a factor of 16 to obtain a $64 \times 64$ feature map [S3].
  3. Crop out the padding region from the $64 \times 64$ feature map to obtain ground-truth semantic features [S3].
  4. For aspect ratio handling: If original image is $H \times W$ ($W > H$), crop the $64 \times 64$ feature map to $64W/H \times 64$ with feature dimension 256 [S3].
  5. During inference, pad the rendered feature from $64W/H \times 64$ back to $64 \times 64$ so the SAM decoder receives equivalent semantic information [S3].
- **Parameters:** SAM encoder output feature dimension is 256 [S3].
- **Source:** [S3]

## Operating characteristics
- **Time Complexity:** Feature extraction is a one-time pre-processing cost [S1]. Inference time for annotation is independent of volume resolution [S1]. Post-processing (BLS) time varies with resolution [S1].
- **Memory Complexity:** High. Requires saving feature maps for all three slicing directions and pooling to desired size [S1]. $80^3$ resolution fits in 8GB VRAM; higher resolutions are prohibitive [S1].
- **Measured Performance:** On CT-ORG dataset, achieves mean IoU of 0.981 with ~5.2 annotations per class [S1]. Outperforms SVM and RF even when their annotations are increased by three orders of magnitude [S1].
- **Strengths:** No training required; robust to intensity ambiguity; high segmentation quality with minimal annotations [S1].
- **Limitations:** High VRAM usage; block artifacts at surfaces; difficulty separating closely spaced similar structures [S1].
- **When to use:** When high-quality semantic segmentation is needed with minimal user annotation and training data is unavailable [S1].
- **When not to use:** When VRAM is limited to <8GB or when structures are extremely close and have similar semantic features [S1].

## Background
- **Origin:** The method was proposed in a paper accepted at IEEE Transactions on Visualisation and Computer Graphics (TVCG) in 2024 [S1].
- **Development:** It builds on the use of self-supervised Vision Transformers (DINO) for feature extraction [S1]. It addresses limitations of previous machine learning-based TF design methods (SVM, RF) which require extensive annotations and training [S1].
- **Usage:** Applied to medical volume data (CT scans) for segmentation-based transfer function design [S1].
