# DINO ViT Feature Extraction

Also called: DINO, DINO Feature Encoding, DINO feature extraction, Self-Supervised ViT Feature Extraction for Transfer Functions, ViT-S/8

## Overview
DINO ViT Feature Extraction is a method for defining transfer functions in volume rendering by leveraging high-level semantic features extracted from volumetric data using a frozen, self-supervised Vision Transformer (ViT) [S2]. It solves the problem of locality in traditional intensity-based features by providing semantic context that allows users to select structures of interest via slice-view annotations, with the system automatically identifying similar structures based on feature similarity [S2]. Unlike supervised learning approaches that require extensive labeled data and per-volume training, this method uses off-the-shelf pre-trained models to enable interactive exploration without model training [S2].

## How it works
**Inputs and Outputs:**
- **Input:** Volumetric data $V \in \mathbb{R}^{W \times H \times D}$, where $W, H, D$ are the dimensions along the X, Y, and Z axes.
- **Output:** A 3D feature volume $F \in \mathbb{R}^{W' \times H' \times D' \times F}$, where $W'=W/p, H'=H/p, D'=D/p$ are the reduced spatial dimensions, and $F$ is the feature dimension.

**Data Structures:**
- **Feature Volume ($F$):** A 4D tensor of type Float32. The spatial dimensions depend on the input resolution and patch size. A typical configuration yields $F \in \mathbb{R}^{80 \times 80 \times 80 \times 384}$ [S2].
- **Model:** DINO ViT-S/8 (`dino_vits8`) [S1, S2].
- **Patch Size ($p$):** 8 [S2].
- **Feature Dimension ($F$):** 384 [S2].

**Parameters:**
- **Input Resolution:** Images are resized to approximately $640 \times 640$ pixels before feeding to the ViT to achieve a spatial feature dimension of 80 [S2]. An alternative implementation uses $448 \times 448$ input resolution [S1].
- **Implementation Variant:** The method may use an extended implementation by Amir et al. [S1] which utilizes overlapping patches with a stride of 4 to enlarge the feature map size [S1].
- **Pre-processing Time:** Approximately 1–3 minutes on a consumer GPU (e.g., RTX 2070, 8GB VRAM) [S2].

**Algorithm Steps:**
1.  **Pre-processing (Feature Extraction):**
    1.  Slice the input volume $V$ along its three principal axes (X, Y, Z).
    2.  For each slice, replicate the 2D data to create an RGB image (3 channels).
    3.  Resize the RGB images to the target input size (e.g., $640 \times 640$ or $448 \times 448$) [S1, S2].
    4.  Feed the RGB slices separately through the frozen DINO ViT network.
    5.  Extract the feature maps from the last self-attention layer. Specifically, save the **Keys ($K$)** of the attention mechanism, as they represent semantic features designed to be matched to queries [S2].
    6.  If using the extended implementation, average the extracted features with the features of the horizontally flipped image [S1].
    7.  The resulting 2D feature maps have dimensions reduced by the patch size $p$ in the non-sliced dimensions:
        -   $F_X \in \mathbb{R}^{W \times H/p \times D/p \times F}$
        -   $F_Y \in \mathbb{R}^{W/p \times H \times D/p \times F}$
        -   $F_Z \in \mathbb{R}^{W/p \times H/p \times D \times F}$
        [S2]
    8.  Merge the three stacks ($F_X, F_Y, F_Z$) into a single 3D feature volume $F$. This is done by average pooling each stack to the target dimensions ($W', H', D'$) and then averaging the three pooled volumes [S2].

2.  **Interactive Annotation (Similarity Computation):**
    1.  The user annotates structures of interest in a slice viewer.
    2.  Sample the feature vectors $f_{ann}$ from the feature volume $F$ at the annotated voxel locations.
    3.  Compute the cosine similarity between $f_{ann}$ and every voxel in $F$ to generate a similarity map $S_L$ [S2].
    4.  Display $S_L$ to provide immediate feedback.

3.  **Refinement (Optional):**
    1.  If higher visual quality is needed, enable a refinement step (taking $\approx 0.5$ seconds) [S2].
    2.  Apply a 3D extension to the Fast Bilateral Solver [12] to the similarity map $S_L$ to produce a high-resolution similarity volume $S_H$ that adapts to the underlying intensity volume [S2].

**Edge Cases and Pitfalls:**
- **Low Resolution:** Due to input patching in ViTs, extracted features are of low resolution, which prohibits high visual quality when rendered directly [S2]. The refinement step is necessary to address this [S2].
- **2D vs 3D Mismatch:** Pre-trained ViTs are trained on 2D data, requiring the slice-wise extraction and merging strategy to handle 3D volumetric data [S2].
- **Memory Constraints:** Larger models (ViT-B, ViT-L, DINOv2) require prohibitive GPU memory and have larger patch sizes, decreasing spatial resolution [S2]. The method is typically limited to ViT-S/8 on consumer GPUs [S2].
- **Input Size:** The input size is restricted by available GPU memory, as larger inputs result in higher memory usage [S2].

## Subtopics

### [Feature-based TF Design via ViT Features](6466-feature-based-tf-design-via-vit-features.md)
Extends the feature extraction to design transfer functions based on the semantic similarity maps generated by the ViT features.

## Operating characteristics
- **Time Complexity:** Pre-processing takes approximately 1–3 minutes on a consumer GPU (RTX 2070, 8GB VRAM) [S2]. Interactive annotation feedback is immediate, and refinement takes approximately 0.5 seconds [S2].
- **Memory Complexity:** The feature volume size is $W' \times H' \times D' \times F$. For a typical $80 \times 80 \times 80$ volume with $F=384$, the size is manageable on consumer GPUs [S2]. Larger models or higher resolutions may exceed memory limits [S2].
- **Strengths:** No training required; interactive; leverages semantic information; fast inference [S2].
- **Limitations:** Low spatial resolution of features without refinement; limited to 2D pre-trained models; cannot accept text queries (unlike LSeg) [S1, S2].
- **When to use:** When semantic understanding of volume structures is needed without the cost of training a custom model, and interactive exploration is desired [S2].
- **When not to use:** When high-resolution features are required without refinement, or when text-based queries are necessary [S1, S2].

## Background
The method was introduced in "Leveraging Self-Supervised Vision Transformers for Segmentation-Based Transfer Function Design" (2024) [S2]. It builds on the DINO (Self-DIstillation with NO labels) framework [9], which is a self-supervised pre-trained Vision Transformer [S2]. The approach addresses the limitations of traditional intensity-based transfer functions and supervised learning-based methods that require labeled data and training [S2]. It is used in volume rendering for interactive exploration and segmentation-based transfer function design [S2].
