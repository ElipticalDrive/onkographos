# DINO ViT Feature Extraction

Also called: DINO, DINO feature extraction, Self-Supervised ViT Feature Extraction for Transfer Functions, ViT-S/8, ViT-based TF design

## Overview
DINO ViT Feature Extraction is a method for defining transfer functions in volume rendering by leveraging high-level semantic features extracted from volumetric data using a frozen, self-supervised pre-trained Vision Transformer (ViT) [S1]. It solves the problem of locality in traditional intensity-based features by providing semantic context, allowing users to select structures of interest via slice annotations and automatically identifying similar structures based on feature similarity without requiring model training [S1]. Unlike supervised learning or generative adversarial network approaches that require costly per-volume training or large labeled datasets, this method enables interactive exploration with quick inference on consumer hardware [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric data $V \in \mathbb{R}^{W \times H \times D}$, where $W, H, D$ are the width, height, and depth dimensions [S1].
*   **Output:** A 3D feature volume $F \in \mathbb{R}^{W' \times H' \times D' \times F}$, where $W'=W/p, H'=H/p, D'=D/p$, $p$ is the patch size, and $F$ is the feature dimension [S1].

**Data Structures:**
*   **Feature Volume ($F$):** A 4D tensor of type Float32 [S1]. The spatial dimensions are reduced by the patch size $p$ relative to the input volume [S1]. The channel dimension corresponds to the feature dimension of the ViT [S1].
    *   *Example Layout:* For an input of $512^3$ and $p=8$, the output is $64 \times 64 \times 64 \times 384$ [S1].
    *   *Typical Size:* $80 \times 80 \times 80 \times 384$ (requires ~8GB VRAM for intermediate buffers) [S1].

**Parameters:**
*   **Patch Size ($p$):** 8 (from ViT-S/8) [S1].
*   **Feature Dimension ($F$):** 384 (output of DINO ViT-S/8) [S1].
*   **Input Resize Dimension:** ~640x640 pixels per slice to achieve a spatial feature dimension of 80 [S1].
*   **Model:** DINO ViT-S/8 (frozen) [S1].

**Steps:**

1.  **Pre-processing (Feature Extraction):**
    1.  Slice the input volume $V$ along its three principal axes (X, Y, Z) [S1].
    2.  For each slice, replicate the 2D grayscale data into 3 channels to form an RGB image [S1].
    3.  Resize the RGB slices to the target input dimension (e.g., 640x640) if necessary to control feature resolution [S1].
    4.  Feed the RGB slices separately through the frozen DINO ViT network [S1].
    5.  Extract the Key ($K$) vectors from the last self-attention layer of the ViT [S1]. These serve as the semantic feature maps [S1].
    6.  The resulting 2D feature maps for each axis have dimensions reduced by $p$ in the non-sliced dimensions:
        *   $F_X \in \mathbb{R}^{W \times (H/p) \times (D/p) \times F}$
        *   $F_Y \in \mathbb{R}^{(W/p) \times H \times (D/p) \times F}$
        *   $F_Z \in \mathbb{R}^{(W/p) \times (H/p) \times D \times F}$
    7.  Merge the three stacks ($F_X, F_Y, F_Z$) into a single 3D feature volume $F$:
        *   Average pool each stack to the target dimensions $W' \times H' \times D'$ [S1].
        *   Average the three pooled volumes element-wise [S1].
        *   Result: $F \in \mathbb{R}^{W' \times H' \times D' \times F}$ [S1].

2.  **Interactive Annotation and Similarity Computation:**
    1.  The user annotates voxels of interest in a slice viewer [S1].
    2.  Sample the feature vectors from $F$ at the annotated locations [S1].
    3.  Compute the cosine similarity between the sampled annotation features and every voxel in $F$ to generate a low-resolution similarity volume $S_L$ [S1].

3.  **Refinement (Optional):**
    1.  Apply a 3D extension of the Fast Bilateral Solver (BLS) to $S_L$ to increase resolution and adapt to the underlying intensity volume, producing a high-resolution similarity volume $S_H$ [S1].

**Pseudocode:**

import numpy as np
import torch
import torch.nn.functional as F

def extract_dino_features(volume: np.ndarray, patch_size: int = 8, 
                          feature_dim: int = 384, target_size: int = 640) -> np.ndarray:
    """
    Extracts 3D feature volume from 3D input volume using DINO ViT-S/8.
    
    Args:
        volume: Input 3D numpy array of shape (W, H, D).
        patch_size: Patch size of the ViT (default 8).
        feature_dim: Dimension of the feature vector (default 384).
        target_size: Target input size for ViT (default 640).
        
    Returns:
        Merged 3D feature volume of shape (W', H', D', F).
    """
    W, H, D = volume.shape
    W_prime, H_prime, D_prime = W // patch_size, H // patch_size, D // patch_size
    
    # Initialize stacks for X, Y, Z slicing
    features_x = np.zeros((W, H_prime, D_prime, feature_dim))
    features_y = np.zeros((W_prime, H, D_prime, feature_dim))
    features_z = np.zeros((W_prime, H_prime, D, feature_dim))
    
    # 1. Extract features along X-axis (Slices are Y-Z planes)
    for i in range(W):
        slice_img = volume[i, :, :]  # Shape (H, D)
        slice_rgb = np.stack([slice_img, slice_img, slice_img], axis=0)  # (3, H, D)
        # Resize to target_size using standard interpolation [G]
        slice_rgb_t = torch.from_numpy(slice_rgb).unsqueeze(0).float()
        slice_rgb_resized = F.interpolate(slice_rgb_t, size=(target_size, target_size), mode='bilinear', align_corners=False).squeeze(0).numpy()
        # Extract Key vectors from last self-attention layer of frozen DINO ViT [G]
        feat_map = get_vit_key_features(slice_rgb_resized)  # Shape (target_size//patch_size, target_size//patch_size, feature_dim)
        features_x[i, :, :, :] = feat_map
        
    # 2. Extract features along Y-axis (Slices are X-Z planes)
    for j in range(H):
        slice_img = volume[:, j, :]  # Shape (W, D)
        slice_rgb = np.stack([slice_img, slice_img, slice_img], axis=0)
        slice_rgb_t = torch.from_numpy(slice_rgb).unsqueeze(0).float()
        slice_rgb_resized = F.interpolate(slice_rgb_t, size=(target_size, target_size), mode='bilinear', align_corners=False).squeeze(0).numpy()
        feat_map = get_vit_key_features(slice_rgb_resized)
        features_y[:, j, :, :] = feat_map
        
    # 3. Extract features along Z-axis (Slices are X-Y planes)
    for k in range(D):
        slice_img = volume[:, :, k]  # Shape (W, H)
        slice_rgb = np.stack([slice_img, slice_img, slice_img], axis=0)
        slice_rgb_t = torch.from_numpy(slice_rgb).unsqueeze(0).float()
        slice_rgb_resized = F.interpolate(slice_rgb_t, size=(target_size, target_size), mode='bilinear', align_corners=False).squeeze(0).numpy()
        feat_map = get_vit_key_features(slice_rgb_resized)
        features_z[:, :, k, :] = feat_map
        
    # Merge: Average pool each stack to target dimensions (already aligned by loop bounds)
    # and average the three volumes element-wise [S1]
    F_merged = (features_x + features_y + features_z) / 3.0
    
    return F_merged

def compute_similarity(feature_volume: np.ndarray, annotations: list) -> np.ndarray:
    """
    Computes cosine similarity between annotated features and the full volume.
    
    Args:
        feature_volume: 3D feature volume F.
        annotations: List of voxel coordinates (x, y, z) annotated by user.
        
    Returns:
        Similarity volume S_L.
    """
    annotation_features = []
    for (x, y, z) in annotations:
        # Map volume coordinates to feature grid indices
        fx, fy, fz = x // 8, y // 8, z // 8
        # Clamp to bounds
        fx = min(max(fx, 0), feature_volume.shape[0]-1)
        fy = min(max(fy, 0), feature_volume.shape[1]-1)
        fz = min(max(fz, 0), feature_volume.shape[2]-1)
        feat = feature_volume[fx, fy, fz, :]
        annotation_features.append(feat)
        
    annotation_features = np.array(annotation_features)  # (N, F)
    
    # Compute cosine similarity for every voxel in F [S1]
    norm_annot = np.linalg.norm(annotation_features, axis=1, keepdims=True)
    norm_annot[norm_annot == 0] = 1
    annot_normalized = annotation_features / norm_annot
    
    norm_F = np.linalg.norm(feature_volume, axis=-1, keepdims=True)
    norm_F[norm_F == 0] = 1
    F_normalized = feature_volume / norm_F
    
    similarities = []
    for i in range(annotation_features.shape[0]):
        sim = np.sum(F_normalized * annot_normalized[i, :], axis=-1)
        similarities.append(sim)
        
    # Average similarities from all annotations
    S_L = np.mean(similarities, axis=0)
    
    return S_L

**Edge Cases and Pitfalls:**
*   **Low Resolution:** ViT features are low resolution due to patching, prohibiting high visual quality when rendered directly [S1].
*   **2D vs 3D Mismatch:** Pre-trained ViTs are trained on 2D data; the slice-wise merging strategy is required to extract meaningful 3D features [S1].
*   **Memory Constraints:** Larger models (ViT-B, ViT-L, DINOv2) require prohibitive GPU memory and have larger patch sizes, decreasing spatial resolution [S1].
*   **Similar Intensities:** Structures with similar CT intensities (e.g., bladder vs. kidneys) may be recognized as similar, requiring careful threshold selection or connected components filtering [S1].
*   **Block Artifacts:** Renderings may show block artifacts if structures cannot be perfectly detected at their surfaces [S1].

## Subtopics

### Feature-based TF Design via ViT Features
This variant emphasizes the workflow where features are extracted once at the beginning, requiring no training phase [S1]. During annotation, inference time is constant regardless of resolution, followed by a post-processing step (Bilateral Linear Solver, BLS) that varies with resolution [S1]. It highlights that a feature volume resolution of $80^3$ suffices for consumer GPUs (8GB VRAM), while higher resolutions demand prohibitive VRAM [S1]. It notes that input scaling must be done by the patch size to obtain specific feature resolutions [S1]. It outperforms SVM and RF approaches in segmentation quality even when annotation counts for SVM/RF are increased by three orders of magnitude [S1]. Pitfalls include high memory requirements preventing the use of larger transformer models and block artifacts in renderings when structures cannot be perfectly detected at their surfaces [S1].

## Operating characteristics
*   **Time Complexity:** Pre-processing takes approximately 1–3 minutes on a consumer GPU (RTX 2070, 8GB VRAM) [S1]. Refinement takes approximately 0.5 seconds per operation [S1]. Inference time for similarity computation is fast and can run on CPU [S1].
*   **Memory Complexity:** The method requires significant GPU memory for intermediate feature maps. A feature volume of $80^3$ with 384 channels fits on 8GB VRAM. Higher resolutions or larger models (ViT-B/L) exceed consumer GPU memory budgets [S1].
*   **Performance:** The method achieves high segmentation accuracy with very few annotations (average 5.2 per class), outperforming SVM and Random Forest approaches that require thousands of annotations [S1].
*   **Strengths:** No training required; interactive exploration; leverages semantic features to overcome locality of intensity-based TFs; works on consumer hardware [S1].
*   **Limitations:** Low spatial resolution of features without refinement; sensitive to similar intensities; block artifacts in rendering; memory-intensive for high-resolution features [S1].
*   **When to Use:** Interactive volume exploration where semantic understanding of structures is beneficial and training data is unavailable [S1].
*   **When Not to Use:** When high-resolution feature maps are required without refinement, or when GPU memory is severely constrained and high resolution is critical [S1].

## Background
The method was proposed in a paper accepted at IEEE Transactions on Visualization and Computer Graphics in 2024 [S1]. It builds on the capabilities of self-supervised Vision Transformers (ViTs), specifically DINO [9], which are pre-trained on large image datasets without labels [S1]. The approach addresses the limitations of traditional transfer function design, which relies on low-level, local features like intensity and gradient, by introducing high-level semantic features [S1]. It contrasts with supervised learning-based transfer function approaches (e.g., Tzeng et al., Cheng et al.) that require labeled data and training, and with GAN-based approaches (e.g., Hong et al.) that require costly per-volume training [S1].
