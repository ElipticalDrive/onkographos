# Probabilistic Scene Graph Generation

Also called: CG3D

## Overview
Probabilistic Scene Graph Generation (CG3D) is a text-to-3D scene synthesis method that explicitly models semantic relationships and physical interactions between objects using a scene graph interpreted as a probabilistic graphical model [S1][S2, unofficial]. Unlike methods that generate individual objects or extend outward from a single reference image, CG3D addresses multi-object composition by enforcing structural consistency through a two-stage ancestor sampling optimization process [S1][S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A text prompt manually deconstructed by the user into a structured scene graph [S1][S2, unofficial].
*   **Output:** A 3D scene representation satisfying the graph constraints and physical forces [S1][S2, unofficial].

**Data Structures**
The scene graph is represented as a directed graph where:
*   **Nodes:** Represent objects [S1][S2, unofficial].
*   **Edges:** Directed edges connect an object node (tail) to an interaction node (head) [S1][S2, unofficial].
*   **Interpretation:** The textual scene graph is interpreted as a probabilistic graphical model [S1][S2, unofficial].

**Algorithm Steps**
The generation process follows an ancestor sampling strategy, divided into two distinct optimization stages [S1][S2, unofficial]:
1.  **Stage 1: Object Generation**
    *   Generate the initial 3D representations of the object nodes defined in the scene graph [S1][S2, unofficial].
    *   This stage establishes the base geometry and appearance of individual entities [S1][S2, unofficial].
2.  **Stage 2: Interaction and Physical Constraint Optimization**
    *   Generate the interaction nodes and their relationships to the object nodes [S1][S2, unofficial].
    *   Introduce physical forces to ensure plausible composition: gravity and normal contact forces are applied [S1][S2, unofficial].
    *   Optimize the scene parameters to satisfy these physical constraints while maintaining visual fidelity to the input prompt [S1][S2, unofficial].

**Pseudocode**
```python
def probabilistic_scene_graph_generation(user_prompt):
    # Parse manually deconstructed text prompt into scene graph structure
    scene_graph = parse_scene_graph(user_prompt)
    
    # Stage 1: Object Generation (Ancestor Sampling)
    objects = initialize_objects(scene_graph.object_nodes)
    
    # Stage 2: Interaction Generation & Physical Optimization
    interactions = define_interactions(scene_graph.edges, objects)
    
    # Apply gravity to all objects
    apply_gravity(objects)
    
    # Apply normal contact forces between interacting objects
    apply_contact_forces(objects, interactions)
    
    # Optimize scene parameters via gradient descent
    optimized_scene = optimize_scene(objects, interactions)
    
    return optimized_scene

def parse_scene_graph(prompt):
    # Standard NLP parsing of structured text prompt into graph nodes and edges
    return {"object_nodes": [], "edges": []}

def initialize_objects(object_nodes):
    # Initialize 3D representations for each node
    return [create_primitive(node) for node in object_nodes]

def define_interactions(edges, objects):
    # Map directed edges to interaction constraints between object pairs
    return [(edge.tail, edge.head) for edge in edges]

def apply_gravity(objects):
    # Apply downward force vector to object positions
    for obj in objects:
        obj.velocity += GRAVITY_VECTOR * dt

def apply_contact_forces(objects, interactions):
    # Compute repulsive normal forces to prevent interpenetration
    for obj_a, obj_b in interactions:
        if distance(obj_a.position, obj_b.position) < COLLISION_THRESHOLD:
            force = NORMAL_FORCE_SCALE * (obj_b.position - obj_a.position)
            obj_a.velocity += force * dt
            obj_b.velocity -= force * dt

def optimize_scene(objects, interactions):
    # Standard iterative optimization loop
    for step in range(MAX_STEPS):
        compute_gradients(objects, interactions)
        update_parameters(objects, interactions, LEARNING_RATE)
    return objects
```

**Edge Cases and Pitfalls**
*   **Manual Decomposition:** The method requires the user to manually deconstruct the text prompt into a scene graph [S1][S2, unofficial].
*   **Missing Formulas:** The sources do not provide explicit mathematical formulas for the probabilistic graphical model or the force calculations [S1][S2, unofficial].

## Operating characteristics
*   **Strengths:** Explicitly models relationships and interactions between objects, addressing a key limitation of single-object generation methods [S1][S2, unofficial].
*   **Limitations:** Relies on manual scene graph construction, which is labor-intensive and not fully automated [S1][S2, unofficial].
*   **Performance:** Specific performance metrics (time, memory) are not provided in the sources [S1][S2, unofficial].

## Background
*   **Origin:** The method is referred to as CG3D in the literature [S1][S2, unofficial].
*   **Context:** It is positioned as a solution to the problem of scene generation requiring consideration of interactions and relationships between different objects, contrasting with methods that focus on individual object generation or extend from reference images (e.g., LucidDreamer, Text2Immersion) [S1][S2, unofficial].
*   **Relation to Other Methods:** It differs from LucidDreamer and Text2Immersion, which use reference images and inpainting to extend 3D scenes, by using a probabilistic graphical model approach [S1][S2, unofficial].
