# Feature Extraction Network

Also called: Encoder Network for Feature Fusion, ResNet34-based Feature Extraction

## Overview
The Feature Extraction Network is a neural network component that maps 2D input images to multi-scale feature representations for use in generalizable neural radiance fields [S1]. It solves the problem of extracting robust, spatially aligned features from unposed or sparsely posed multi-view images by leveraging a ResNet34 backbone with specific up-convolutional fusion paths [S1]. It sets itself apart from sibling methods like the MELON Encoder by using a deeper residual structure with explicit multi-scale concatenation, and from the Multi-Scale Feature Extractor by relying on standard ResNet blocks rather than a Feature Pyramid Network (FPN) hierarchy [S1].

## How it works
**Inputs and Outputs:**
- Input: Intermediate feature map extracted from a ResNet34 backbone [S1].
- Output: Concatenated multi-scale feature map [S1].

**Data Structures:**
The network comprises a ResNet34 backbone and two fusion paths [S1].
1. **Backbone:** Standard ResNet34 [S1]. The max-pooling layer after the first convolution is omitted [S1].
2. **Path 1 (Deep Feature Path):** Three convolutional layers (`[Conv]×3`), up-convolution (3×3 kernel, 256 channels), up-convolution (3×3 kernel, 128 channels), three convolutional layers (`[Conv]×3`, 3×3 kernel, 64 channels), three convolutional layers (`[Conv]×3`, 3×3 kernel, 64 channels), and a final convolution (7×7 kernel, 64 channels) [S1].
3. **Path 2 (Shallow Feature Path):** Six convolutional layers (`[Conv]×6`), followed by three convolutional layers (`[Conv]×3`) [S1].
4. **Concatenation:** Features from Path 1 and Path 2 are concatenated after the up-convolution steps [S1]. If spatial dimensions mismatch, bilinear interpolation rescales Path 1 features to match Path 2 features [S1].

**Numbered Steps:**
1. Extract an intermediate feature map from the ResNet34 backbone (excluding the initial max-pooling layer) [S1].
2. Process the feature map through Path 1: apply three convolutions, up-convolve (3×3, 256 channels), up-convolve (3×3, 128 channels) [S1].
3. Process the same feature map through Path 2: apply six convolutions, then three convolutions [S1].
4. Align spatial dimensions: if the output of Path 1 does not match the spatial shape of Path 2, use bilinear interpolation to rescale Path 1 features [S1].
5. Concatenate the aligned features from Path 1 and Path 2 [S1].
6. Apply the remaining Path 1 convolutions to the concatenated tensor: three convolutions (3×3, 64 channels), three convolutions (3×3, 64 channels), and a final 7×7 convolution (64 channels) [S1].

**Formulas:**
- Bilinear Interpolation: Used to rescale feature map $F_{\text{path1}}$ to match $F_{\text{path2}}$ dimensions $H \times W$ [S1].

**Parameters:**
- Kernel sizes: 3×3 for standard convolutions, 7×7 for the final layer [S1].
- Channels: 256, 128, 64 in Path 1; unspecified in Path 2 [S1].
- Depth sampling: 64 inverse-depth samples are used in the broader GeNeRF context, but this is a sampling parameter, not a network parameter [S1].

**Edge Cases and Pitfalls:**
- Shape Mismatch: After up-convolution, the resulting feature map shape may not match the shape of the feature map to be concatenated. This must be handled via bilinear interpolation [S1].
- Max-Pooling: The max-pooling layer after the first convolution is explicitly omitted, which affects the spatial reduction rate compared to standard ResNet [S1].

**Pseudocode:**
```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class FeatureExtractionNetwork(nn.Module):
    def __init__(self, in_channels: int):
        super().__init__()
        # Path 1: [Conv]x3 -> UpConv(256) -> UpConv(128) -> [Conv]x3(64) -> [Conv]x3(64) -> 7x7(64)
        self.p1_conv1 = nn.Conv2d(in_channels, 64, kernel_size=3, padding=1)
        self.p1_conv2 = nn.Conv2d(64, 64, kernel_size=3, padding=1)
        self.p1_conv3 = nn.Conv2d(64, 64, kernel_size=3, padding=1)
        self.p1_upconv1 = nn.ConvTranspose2d(64, 256, kernel_size=3, stride=2, padding=1, output_padding=1)
        self.p1_upconv2 = nn.ConvTranspose2d(256, 128, kernel_size=3, stride=2, padding=1, output_padding=1)
        self.p1_conv4 = nn.Conv2d(128, 64, kernel_size=3, padding=1)
        self.p1_conv5 = nn.Conv2d(64, 64, kernel_size=3, padding=1)
        self.p1_conv6 = nn.Conv2d(64, 64, kernel_size=7, padding=3)

        # Path 2: [Conv]x6 -> [Conv]x3
        # Channel dimensions for Path 2 are not specified in the sources [G]
        self.p2_conv1 = nn.Conv2d(in_channels, 64, kernel_size=3, padding=1)
        self.p2_conv2 = nn.Conv2d(64, 64, kernel_size=3, padding=1)
        self.p2_conv3 = nn.Conv2d(64, 64, kernel_size=3, padding=1)
        self.p2_conv4 = nn.Conv2d(64, 64, kernel_size=3, padding=1)
        self.p2_conv5 = nn.Conv2d(64, 64, kernel_size=3, padding=1)
        self.p2_conv6 = nn.Conv2d(64, 64, kernel_size=3, padding=1)
        self.p2_conv7 = nn.Conv2d(64, 64, kernel_size=3, padding=1)
        self.p2_conv8 = nn.Conv2d(64, 64, kernel_size=3, padding=1)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # Path 1 processing
        p1 = self.p1_conv1(x)
        p1 = self.p1_conv2(p1)
        p1 = self.p1_conv3(p1)
        p1 = self.p1_upconv1(p1)
        p1 = self.p1_upconv2(p1)

        # Path 2 processing
        p2 = self.p2_conv1(x)
        p2 = self.p2_conv2(p2)
        p2 = self.p2_conv3(p2)
        p2 = self.p2_conv4(p2)
        p2 = self.p2_conv5(p2)
        p2 = self.p2_conv6(p2)
        p2 = self.p2_conv7(p2)
        p2 = self.p2_conv8(p2)

        # Align shapes: bilinear interpolation if dimensions mismatch [S1]
        if p1.shape[2:] != p2.shape[2:]:
            p1 = F.interpolate(p1, size=p2.shape[2:], mode='bilinear', align_corners=False)

        # Concatenate features [S1]
        out = torch.cat([p1, p2], dim=1)

        # Apply remaining Path 1 convolutions to concatenated output [S1]
        out = self.p1_conv4(out)
        out = self.p1_conv5(out)
        out = self.p1_conv6(out)

        return out
```

## Subtopics

### [MELON Encoder Architecture](11900-melon-encoder-architecture.md)
The MELON Encoder is a neural network component that maps 2D input images to camera pose parameters (azimuth, elevation, and optionally roll and translation) for use in unposed image NeRF reconstruction. It distinguishes itself from sibling encoders by using a compact, fixed-depth convolutional stack with group normalization and SiLU activations, optimized for rapid convergence of pose estimates in low-view-count scenarios.

### [Multi-Scale Feature Extractor](15126-multi-scale-feature-extractor.md)
The Multi-Scale Feature Extractor is a neural network module designed to extract semantic-aware features from input images for 3D scene understanding. It solves the problem of capturing multi-scale semantic information by combining a deep convolutional backbone with a Feature Pyramid Network (FPN). It is distinct from its sibling, the MELON Encoder Architecture, and its alternative baseline, the Multi-Scale Tri-Plane Architecture, by relying on 2D image-based convolutional hierarchies rather than 3D implicit representations or self-attention convolutions for frequency separation.

### Feature Pyramid Encoder
Extracts a feature pyramid by selecting feature maps prior to the first pooling operation and after the first three ResNet layers [S2]. For an input image of size $H \times W$, the extracted feature maps have shapes $64 \times H/2 \times W/2$ and $64 \times H/4 \times W/4$ [S2]. It uses a positional encoding scale scalar multiplier to make NeRF-related methods scale-invariant [S2]. Achieved a mean PSNR of 22.71 on ShapeNet category-agnostic benchmarks, outperforming DVR (17.72) and SRN (18.71) [S2].

## Background
The Feature Extraction Network was introduced in the DBARF paper (Deep Bundle-Adjusting Generalizable Neural Radiance Fields) [S1]. It is based on the ResNet34 architecture [S1]. The method is part of the broader GeNeRF framework, which uses inverse-depth sampling [S1].
