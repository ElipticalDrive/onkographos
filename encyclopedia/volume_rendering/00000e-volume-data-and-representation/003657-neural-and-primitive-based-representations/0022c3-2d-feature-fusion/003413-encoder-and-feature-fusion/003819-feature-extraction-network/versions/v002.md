# Feature Extraction Network

Also called: Encoder Network for Feature Fusion, ResNet34-based Feature Extraction

## Overview
The Feature Extraction Network is a neural network component that maps 2D input images to high-dimensional feature representations for subsequent fusion and density prediction in generalizable neural radiance fields [S1]. It distinguishes itself from sibling methods by employing a ResNet34 backbone combined with a specific multi-path up-convolutional decoder structure that fuses features at different scales, optimized for robust feature extraction from unposed multi-view inputs [S1].

## How it works
**Inputs and Outputs:**
- Input: A set of 2D input images (typically multi-view).
- Output: A concatenated feature map containing fused multi-scale features.

**Data Structures and Layout:**
The network is built upon the ResNet34 architecture [S1]. The detailed layout, as specified in the source, is as follows:

1.  **Backbone (Encoder):**
    -   Input images pass through an initial convolutional block denoted as `[Conv]x3`.
    -   A MaxPool layer follows (omitted in the architectural diagram but present in the standard ResNet34 definition) [S1].
    -   The data flows through a series of Residual Blocks. The source specifies a path involving `[Conv]x6` and `[Conv]x3` blocks within the residual structure [S1].

2.  **Decoder (Feature Fusion Path):**
    The decoder consists of two parallel paths that are concatenated:
    -   **Path 1 (Up-sampling Path):**
        -   Starts with `[Conv]x3`.
        -   Followed by an Up-Convolution (`UpConv`) with a $3 \times 3$ kernel and 256 output channels.
        -   Followed by another `UpConv` with a $3 \times 3$ kernel and 128 output channels.
        -   Followed by `[Conv]x3` with $3 \times 3$ kernels and 64 output channels.
        -   Followed by another `[Conv]x3` with $3 \times 3$ kernels and 64 output channels.
        -   Ends with a final convolution of size $7 \times 7$ and 64 output channels [S1].
    -   **Path 2 (Skip Connection Path):**
        -   Consists of `[Conv]x6` followed by `[Conv]x3` [S1].
    -   **Concatenation:** Features from Path 1 and Path 2 are concatenated. The source notes that concatenation occurs after up-convolution steps [S1].

3.  **Resizing:**
    -   After up-convolution, the resulting feature map shape may not match the shape of the feature map to be concatenated. In this case, bilinear interpolation is used to rescale the up-sampled features to the same shape as the skip-connection features [S1].

**Pseudocode:**
```python
def feature_extraction_network(images):
    # Backbone: ResNet34
    # Initial Conv Block
    x = conv_block(images, count=3)
    x = max_pool(x) # Omitted in diagram, standard in ResNet34
    
    # Residual Blocks
    # The source specifies paths involving [Conv]x6 and [Conv]x3
    # We assume standard ResNet34 residual block structure
    x = residual_blocks(x) 
    
    # Decoder Path 1
    path1 = conv_block(x, count=3)
    path1 = up_conv(path1, kernel_size=3, out_channels=256)
    path1 = up_conv(path1, kernel_size=3, out_channels=128)
    path1 = conv_block(path1, count=3, kernel_size=3, out_channels=64)
    path1 = conv_block(path1, count=3, kernel_size=3, out_channels=64)
    path1 = conv(path1, kernel_size=7, out_channels=64)
    
    # Decoder Path 2
    path2 = conv_block(x, count=6, kernel_size=3)
    path2 = conv_block(path2, count=3, kernel_size=3)
    
    # Resize Path 1 to match Path 2 if necessary
    if path1.shape != path2.shape:
        path1 = bilinear_interpolate(path1, target_shape=path2.shape)
        
    # Concatenate
    features = concatenate(path1, path2, dim=channel_dim)
    
    return features
```

**Parameters:**
-   Kernel sizes: $3 \times 3$ for most convolutions, $7 \times 7$ for the final layer [S1].
-   Channels: 256, 128, 64 in the up-convolutional path [S1].
-   Depth sampling: 64 inverse-depth samples are used in the broader GeNeRF context, though this is a sampling parameter rather than a network parameter [S1].

**Edge Cases and Pitfalls:**
-   Shape mismatch after up-convolution requires explicit bilinear interpolation to ensure concatenation compatibility [S1].

## Subtopics

### [MELON Encoder Architecture](11900-melon-encoder-architecture.md)
The MELON Encoder is a neural network component that maps 2D input images to camera pose parameters (azimuth, elevation, and optionally roll and translation) for use in unposed image NeRF reconstruction. It distinguishes itself from sibling encoders by using a compact, fixed-depth convolutional stack with group normalization and SiLU activations, optimized for rapid convergence of pose estimates in low-view-count scenarios.

## Background
The Feature Extraction Network is based on ResNet34 [S1]. It was introduced in the context of DBARF (Deep Bundle-Adjusting Generalizable Neural Radiance Fields) [S1]. The architecture is designed to extract robust features from input images for subsequent fusion and density prediction in generalizable neural radiance fields [S1].
