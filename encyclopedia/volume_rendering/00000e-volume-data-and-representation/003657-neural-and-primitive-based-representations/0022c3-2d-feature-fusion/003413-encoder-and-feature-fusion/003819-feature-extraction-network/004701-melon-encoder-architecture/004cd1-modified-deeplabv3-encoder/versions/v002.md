# Modified DeepLabV3 Encoder

Also called: DeepLabV3 feature extractor, F_low encoder

## Overview
The Modified DeepLabV3 Encoder extracts low-resolution canonical features ($F_{low}$) from a single input image by adapting the standard DeepLabV3 architecture to accept pixel coordinates and bypass batch normalization [S1]. It serves as the foundational feature extraction stage in the MELON Encoder Architecture, providing the semantic and structural base for subsequent global and high-resolution feature fusion [S1]. Unlike its sibling, the Hybrid Convolutional-Transformer Encoder, which focuses on processing $F_{low}$ into global features, this encoder is responsible for the initial spatial encoding of the raw image [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A single RGB image $I$ of resolution $H \times W$ [S1].
*   **Output:** A low-resolution feature map $F_{low}$ of dimensions $H/8 \times W/8 \times C$, where $C$ is the channel count of the DeepLabV3 decoder output [S1].

**Data Structures:**
The input tensor is constructed by concatenating the original RGB channels with 2D pixel coordinates [S1].
*   **Input Tensor Layout:** 5 channels.
    *   Channel 0-2: Red, Green, Blue values [G].
    *   Channel 3: Normalized x-coordinates ($x/W$) [G].
    *   Channel 4: Normalized y-coordinates ($y/H$) [G].
*   **Internal State:** The architecture uses a ResNet34 backbone [S1]. All Batch Normalization layers are removed, and biases are reintroduced in all convolutional layers [S1].

**Steps:**
1.  **Coordinate Generation:** For each pixel $(i, j)$ in the input image where $0 \le i < H$ and $0 \le j < W$, compute normalized coordinates:
    $$ x_{norm} = \frac{i}{H}, \quad y_{norm} = \frac{j}{W} $$
2.  **Input Assembly:** Construct the 5-channel input tensor $X_{in}$ by stacking the RGB channels and the coordinate maps:
    $$ X_{in} = [I_R, I_G, I_B, X_{map}, Y_{map}] $$
    where $X_{map}$ and $Y_{map}$ are $H \times W$ grids of $x_{norm}$ and $y_{norm}$ respectively [S1].
3.  **Feature Extraction:** Pass $X_{in}$ through the modified DeepLabV3 encoder-decoder structure [S1].
    *   The first convolutional layer accepts 5 input channels instead of the standard 3 [S1].
    *   The backbone is ResNet34 [S1].
    *   All Batch Normalization layers are disabled [S1].
    *   Biases are enabled for all convolutional layers [S1].
4.  **Feature Extraction Point:** The output $F_{low}$ is taken from the decoder layer immediately preceding the bilinear upsampling and segmentation head [S1]. This corresponds to the feature map at $1/8$th the resolution of the input [S1].

**Pseudocode:**
```python
import torch
import torch.nn as nn

def create_coordinate_maps(H, W, device):
    """
    Creates normalized x and y coordinate maps.
    """
    y_coords = torch.arange(H, device=device).float() / H
    x_coords = torch.arange(W, device=device).float() / W
    # Create meshgrid: y_coords is rows (height), x_coords is cols (width)
    Y_map, X_map = torch.meshgrid(y_coords, x_coords, indexing='ij')
    return X_map.unsqueeze(0), Y_map.unsqueeze(0)

def modify_deeplabv3(model):
    """
    Modifies a DeepLabV3 model to accept 5-channel input and bypass batch normalization.
    """
    # 1. Modify first conv layer to accept 5 channels [S1]
    first_conv = model.backbone.conv1
    old_weight = first_conv.weight
    # Append zero-initialized weights for the two new coordinate channels
    new_weight = torch.cat([old_weight, torch.zeros_like(old_weight[:, :2, :, :])], dim=1)
    first_conv.weight = nn.Parameter(new_weight)
    first_conv.in_channels = 5

    # 2. Remove all Batch Normalization layers and enable biases in all Conv layers [S1]
    for module in model.modules():
        if isinstance(module, nn.BatchNorm2d):
            # Bypass BN by replacing it with an Identity operation [G]
            module.replace_with_identity()
        if isinstance(module, nn.Conv2d):
            module.bias = nn.Parameter(torch.zeros(module.out_channels))
            module.bias.requires_grad = True
    return model

def extract_f_low(image_tensor, model):
    """
    Extracts F_low from image_tensor.
    image_tensor: [B, 3, H, W]
    """
    B, C, H, W = image_tensor.shape
    
    # Generate coordinate maps
    X_map, Y_map = create_coordinate_maps(H, W, image_tensor.device)
    X_map = X_map.expand(B, 1, H, W)
    Y_map = Y_map.expand(B, 1, H, W)
    
    # Concatenate RGB and Coordinates
    # Input is [B, 5, H, W]
    input_tensor = torch.cat([image_tensor, X_map, Y_map], dim=1)
    
    # Forward pass through the modified encoder-decoder [S1]
    features = model(input_tensor) 
    
    # Extract feature map from decoder layer immediately before bilinear upsampling and segmentation head [S1]
    F_low = features.decoder_output
    return F_low
```

**Parameters:**
*   **Input Channels:** 5 (RGB + 2 coordinates) [S1].
*   **Backbone:** ResNet34 [S1].
*   **Batch Normalization:** Disabled [S1].
*   **Biases:** Enabled in all Conv layers [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** Coordinate normalization must be consistent with the training data distribution [G].
*   **Boundaries:** The coordinate maps cover the full image extent $[0, 1]$ [G].
*   **Degenerate Input:** If the image is not square, the coordinate normalization handles aspect ratio correctly by dividing by $H$ and $W$ respectively [G].

## Subtopics

### High-Resolution Encoder
A variant encoder that produces high-resolution features ($F_{high}$) [S1]. It differs from the standard $F_{low}$ encoder by taking the second layer output features of DeepLabV3 (rather than the raw conditioning image) along with stacked pixel coordinates as input [S1]. This allows it to capture high-frequency details that are lost in the low-resolution $F_{low}$ stream [S1].

### Triplane Encoder for Single-Image Portrait View Synthesis
This is not a variant of the encoder itself, but the broader pipeline context in which the Modified DeepLabV3 Encoder is used [S1]. The encoder extracts $F_{low}$, which is then processed by a Vision Transformer (ViT) block from Segformer to create global features $F$, and concatenated with high-resolution features $F_{high}$ to form the final triplane representation [S1]. Key parameters in this context include $\lambda_1$ (adversarial loss weight: 0.1 for reference, 0.025 for multiview) and $\lambda_2$ (category loss weight: 1 for human faces, 0 for cat faces) [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels in the input image, $O(H \cdot W)$, due to the convolutional nature of the ResNet34 backbone [G].
*   **Memory Complexity:** Proportional to the memory footprint of the ResNet34 model and the intermediate feature maps. The removal of Batch Normalization reduces memory overhead associated with running mean/variance buffers [G].
*   **Strengths:** Provides robust low-resolution semantic features. The inclusion of pixel coordinates allows the network to learn spatial priors directly, which is crucial for canonicalizing 3D structures from 2D images [S1].
*   **Limitations:** The low-resolution output ($1/8$ scale) loses high-frequency details, necessitating the fusion with $F_{high}$ in the full MELON pipeline [S1].
*   **When to use:** When a feedforward, low-resolution semantic encoding of an image is required for downstream 3D representation learning, particularly in single-image portrait view synthesis [S1].

## Background
The Modified DeepLabV3 Encoder originates from the work by Hew Chan et al. (2023) on "Real-Time Radiance Fields for Single-Image Portrait View Synthesis" [S1]. It adapts the DeepLabV3 architecture [Chen et al. 2017], originally designed for semantic segmentation, to serve as a feature extractor for 3D neural rendering. The modification of removing Batch Normalization and adding pixel coordinates is a specific adaptation to enable the network to learn spatially aware canonical features from unposed images, avoiding the need for expensive GAN inversion [S1].
