# Spatial Feature Encoding

Also called: Spatial Feature Encoder, SF Encoder, Feature Registration (Freg)

## Overview
Spatial Feature Encoding maps the semantics of input 2D views into compact, robust per-pixel feature vectors that serve as a bridge between 2D image data and 3D scene representation [S1, S3]. It solves the problem of raw RGB values being sensitive to lighting conditions, environmental noise, and lack of geometric context by learning higher-level patterns that encode spatial awareness [S1]. It differs from sibling methods like [ResNet Architecture](8378-resnet-architecture.md) by explicitly integrating camera position data to encode 3D spatial awareness, and from [Attention-based Multi-View Density Prediction](10674-attention-based-multi-view-density-prediction.md) by relying on convolutional structures rather than attention mechanisms for feature fusion [S1].

## Shared principles
The family of Spatial Feature Encoding methods shares the core mechanism of transforming 2D input data (typically RGB or RGBD images) into a dense feature map where each pixel corresponds to a feature vector in a latent space. This transformation is achieved using convolutional neural networks (CNNs) or similar encoder architectures.

Key shared characteristics include:
1.  **Input Augmentation:** Inputs are often augmented with geometric context. For instance, camera positions (xyz) are stacked with RGB channels to provide spatial awareness [S1]. In RGBD variants, depth and intrinsic/extrinsic camera parameters are used for inverse projection to map pixels to 3D world positions [S3].
2.  **Convolutional Encoding:** The core operation involves passing the augmented input through a series of convolutional layers. These layers extract hierarchical features, preserving local spatial details through skip connections or specific architectural designs (e.g., U-Net, BigGAN-based) [S1, S3].
3.  **Output Dimensionality:** The output is a feature map $C$ or $F$ with dimensions $H \times W \times D$, where $H$ and $W$ are the image height and width, and $D$ is the feature dimension [S1, S3]. The dimension $D$ varies by implementation (e.g., 128, 64, or 512) [S1][S2, unofficial][S3].
4.  **Robustness:** The encoded features are designed to be invariant to lighting variations and noise, providing a stable representation for downstream tasks like density prediction, radiance decoding, or 3D reconstruction [S1].

## Subtopics

### [CNN-based 2D Feature Extraction](8649-cnn-based-2d-feature-extraction.md)
This method extracts robust, generalizable per-pixel features from input RGB images to serve as a compact description of the light ray emitted from the camera center to the 3D surface. It solves the problem of raw RGB values being sensitive to lighting conditions and environmental noise by learning higher-level patterns. It differs from sibling methods like [ResNet Architecture](8378-resnet-architecture.md) by explicitly stacking camera position data to each pixel to encode 3D spatial awareness, and from [Attention-based Multi-View Density Prediction](10674-attention-based-multi-view-density-prediction.md) by relying on convolutional skip connections rather than attention mechanisms for feature fusion.

### Spatial Feature Encoder
- **Definition:** Maps scene semantics of an input view $I_i$ to per-pixel feature vectors $F_i$ [S1].
- **Parameters:**
    - Output dimension: 61 dimensions per vector [S1].
    - Architecture: Built on BigGAN architecture [S1].
    - Feature vector dimension: 61 dimensions [S1].
    - Total dimension after concatenation with RGB channels: 64 dimensions [S1].
- **History:** Built on BigGAN architecture [3] [S1].

### SF Encoder
- **Steps:**
    1. Transpose input tensor from $[batch\_size, num\_points, input\_dim]$ to $[batch\_size, input\_dim, num\_points]$ [S2, unofficial].
    2. Pass transposed input through sequential convolutional layers with BatchNorm and ReLU activations [S2, unofficial].
    3. Apply max pooling over the point dimension (dim=2) to aggregate local features into a global feature vector of shape $[batch\_size, feature\_dim]$ [S2, unofficial].
    4. If `vae` is True, compute $\mu$ and $\log var$ via fully connected layers. Clamp $\log var$ to $[-6, 3]$. If `deterministic` is False, sample $z = \mu + std * noise$ where $std = \exp(0.5 * \log var) + 1e-8$. Return $z, \mu, \log var$ [S2, unofficial].
    5. If `vae` is False, pass global feature through two fully connected layers with ReLU and linear output respectively [S2, unofficial].
- **Parameters:**
    - `input_dim`: number of input channels per point, default 3 [S2, unofficial].
    - `feature_dim`: dimensionality of the global feature vector, default 512 [S2, unofficial].
    - `vae`: whether to use variational autoencoder reparameterization, default True [S2, unofficial].
    - `deterministic`: whether to skip stochastic sampling and use only $\mu$, default False [S2, unofficial].
- **Layout:** Four 1D convolutional layers with kernel size 1: Conv1d($input\_dim$, 64, 1), Conv1d(64, 128, 1), Conv1d(128, 256, 1), Conv1d(256, $feature\_dim$, 1). Each followed by BatchNorm1d and ReLU activation [S2, unofficial].

### Feature Registration (Freg)
- **Definition:** Encodes an input RGBD image $I_t$ into a same-sized feature map $C_t$ of dimensions $H \times W \times D$ using an encoder network with parameters $\theta_{enc}$ [S3].
- **Formula:**
    $$m_t^{l}, n_t^{l} = F_{reg}(I_t, p_t; \theta_{enc})$$
    where $m_t^l$ is the local map feature and $n_t^l$ is the local mask count [S3].
- **Process:** When an RGBD image $I_t \in \mathbb{R}^{H \times W \times 4}$ comes in, the encoder encodes the image into a same-sized feature $C_t \in \mathbb{R}^{H \times W \times D}$, where $H$ and $W$ refer to height and width of the image, respectively, and $D$ refers to the channel size [S3]. First, each pixel $c_{w,h} \in \mathbb{R}^D$ in $C_t$ is mapped to its corresponding 3D world position $[q_x, q_y, q_z]^T$ using the known camera intrinsic $K$, the extrinsic matrix $[R|t]$ based on the agent pose, and the depth information $d_{h,w}$ of the pixel [S3]. The world position of each pixel is calculated using inverse camera projection [S3]. The registration process $F_{reg}$ outputs a local map $m_t^l$ and a local mask $n_t^l$ [S3].

## Background
Spatial Feature Encoding originated in the context of neural rendering and novel view synthesis, where the need for robust, geometry-aware feature representations became critical for high-quality 3D reconstruction from 2D images. The concept of mapping 2D view semantics to 3D-aware feature vectors was formalized in works such as FWD (Forward Warping and Depth) [S1], which utilized a BigGAN-based encoder to generate 61-dimensional feature vectors concatenated with RGB channels. Concurrently, variations like the SF Encoder [S2, unofficial] and Feature Registration (Freg) [S3] adapted these principles for point cloud processing and visual navigation, respectively. The method has evolved to incorporate various architectural choices, including CNNs with skip connections [S1], 1D convolutions with VAE components [S2, unofficial], and inverse projection-based registration [S3], reflecting a broader trend in computer vision towards integrating geometric priors into deep learning pipelines.
