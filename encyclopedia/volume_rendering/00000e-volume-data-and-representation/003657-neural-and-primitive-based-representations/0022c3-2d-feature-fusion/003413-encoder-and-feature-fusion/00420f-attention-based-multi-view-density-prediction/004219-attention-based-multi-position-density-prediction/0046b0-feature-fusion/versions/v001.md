# Feature Fusion

Also called: Maxpooling Feature Fusion

## Overview
Feature Fusion combines multi-view 2D features into a single representation for 3D points or novel views, addressing the problem of integrating spatially aligned information from multiple projections. It sets itself apart from concatenation-based fusion by using max-pooling, which provides a flexible architecture capable of handling any number of input neighbors and generally outperforms concatenation in robustness and memory efficiency [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of 2D feature maps (one per view) and the corresponding 3D point coordinates (or novel view indices).
*   **Outputs:** A fused feature vector per 3D point or a fused feature map for the novel view.

**Data Structures:**
*   **Feature Maps:** Tensor of shape $[B, C, H, W]$ or $[B, K, C, H, W]$ where $B$ is batch size, $K$ is number of views, $C$ is channels, $H, W$ are spatial dimensions.
*   **Projected Coordinates:** Tensor of shape $[N, K, 2]$ containing normalized 2D coordinates $(u, v) \in [-1, 1]$ for $N$ points across $K$ views.

**Steps:**
1.  **Encoding:** Encode 2D projection images into feature maps using a UNet encoder [S2, unofficial].
2.  **Projection:** For each 3D point, compute its 2D projection coordinates $(u, v)$ in each source view. This involves rotating and scaling the 3D points to align with the camera coordinate system and normalizing to $[-1, 1]$ [S2, unofficial].
3.  **Sampling:** Sample features from each view's feature map at the projected coordinates $(u, v)$ using bilinear interpolation. Let $f_{k}(p)$ be the feature vector for point $p$ from view $k$.
4.  **Fusion:** Combine the sampled features from all $K$ views using element-wise max-pooling:
    $$ H_{pool}(p) = \max_{k \in \{1, \dots, K\}} f_{k}(p) $$
    This step replaces concatenation, allowing the model to handle variable numbers of input neighbors without changing the output dimensionality [S1][S2, unofficial].
5.  **Decoding/Enhancement:**
    *   *For 3D Points:* Pass the fused features $H_{pool}(p)$ through a residual MLP with batch normalization to predict point-wise values (e.g., density, color) [S2, unofficial].
    *   *For Novel Views (RoGUENeRF):* Concatenate the pooled features $H^{f}_{pool}$ with the novel view's initial features $I^{f}_{k}$, pass through a convolutional merge layer, and then process with a Uformer [S1]:
        $$ \hat{H}_{k} = \mathcal{U}(conv_{merge}([I^{f}_{k}, H^{f}_{pool}])) $$
        where $\mathcal{U}$ is the Uformer and $conv_{merge}$ is a convolutional layer [S1].

**Parameters:**
*   **Fusion Strategy:** Set to 'max' [S2, unofficial].
*   **Batch Size for Evaluation:** Large point batches are split into chunks of `eval_npoint` (default 100,000) to prevent GPU memory overflow [S2, unofficial].

**Pitfalls:**
*   **Memory Overflow:** Processing all points simultaneously can exceed GPU memory limits; chunking is required for evaluation [S2, unofficial].
*   **Coordinate Normalization:** Points may fall outside the $[-1, 1]$ range after projection and scaling; sampling must handle or clip these out-of-bounds coordinates appropriately [S2, unofficial].

## Subtopics

### Multi-View Pixel-Aligned Feature Fusion
Fuses features from multiple 2D projection views into a single 3D point representation using pixel-aligned sampling and max-pooling. It is chosen when explicit 3D geometry is available and multi-view consistency is required for point-wise prediction. It differs from RoGUENeRF's approach by focusing on point cloud decoding rather than image enhancement. [S2, unofficial]

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of points $N$ and views $K$ for sampling and pooling. The Uformer enhancement adds complexity dependent on the feature map size.
*   **Memory Complexity:** Proportional to $N \times C$ for storing fused features. Chunking reduces peak memory usage during evaluation.
*   **Strengths:** Flexible number of input views; robust to missing views (max-pooling ignores empty slots if masked); outperforms concatenation in some settings [S1].
*   **Limitations:** Max-pooling discards information from non-maximal views; requires accurate projection coordinates [S1][S2, unofficial].

## Background
Originating from work on NeRF enhancement and Gaussian Splatting decoding, this method leverages the observation that max-pooling is more effective than concatenation for fusing multi-view features [S1][S2, unofficial]. It was developed to allow flexible integration of varying numbers of neighboring views in both image enhancement (RoGUENeRF) and 3D point decoding (DIF-Gaussian) [S1][S2, unofficial].
