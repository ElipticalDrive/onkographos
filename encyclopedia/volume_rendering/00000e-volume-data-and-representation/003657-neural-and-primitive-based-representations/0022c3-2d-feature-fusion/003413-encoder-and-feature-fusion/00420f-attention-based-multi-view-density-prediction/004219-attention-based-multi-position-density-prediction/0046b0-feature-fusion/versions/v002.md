# Feature Fusion

Also called: Maxpooling Feature Fusion

## Overview
Feature Fusion combines multi-view 2D features into a single representation for 3D points or novel views [S2, unofficial][S1]. It sets itself apart from concatenation-based fusion by using max-pooling, which outperforms concatenation and allows a flexible architecture capable of handling any number of input neighbours [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 2D feature maps (one per view) and 3D point coordinates or novel view indices [S2, unofficial][S1].
*   **Outputs:** A fused feature vector per 3D point or an enhanced feature map for the novel view [S2, unofficial][S1].

**Steps:**
1.  **Encoding:** Encode 2D projection images into feature maps using a UNet encoder [S2, unofficial].
2.  **Projection:** For each 3D point, compute its 2D projection coordinates $(u, v)$ in each source view by applying camera rotation and scaling, then normalizing to $[-1, 1]$ [S2, unofficial].
3.  **Sampling:** Sample features from each view's feature map at the projected coordinates $(u, v)$ [S2, unofficial].
4.  **Fusion:** Combine the sampled features from all $K$ views using element-wise max-pooling:
    $$ H_{pool}(p) = \max_{k \in \{1, \dots, K\}} f_{k}(p) $$
    This replaces concatenation, allowing the model to handle variable numbers of input neighbours without changing the output dimensionality [S1][S2, unofficial].
5.  **Decoding/Enhancement:**
    *   *For 3D Points:* Pass the fused features $H_{pool}(p)$ through a residual MLP with batch normalization to predict point-wise values [S2, unofficial].
    *   *For Novel Views:* Concatenate the pooled features $H^{f}_{pool}$ with the novel view's initial features $I^{f}_{k}$, pass through a convolutional merge layer, and process with a Uformer modified to accept image features instead of RGB [S1]:
        $$ \hat{H}_{k} = \mathcal{U}(conv_{merge}([I^{f}_{k}, H^{f}_{pool}])) $$
        where $\mathcal{U}$ is the Uformer and $conv_{merge}$ is a convolutional layer [S1].

**Parameters:**
*   **Fusion Strategy:** Set to 'max' [S2, unofficial].
*   **Evaluation Chunk Size:** Large point batches are split into chunks of `eval_npoint` (default 100,000) to prevent GPU memory overflow [S2, unofficial].

**Pitfalls:**
*   **Memory Overflow:** Processing all points simultaneously can exceed GPU memory limits; chunking is required for evaluation [S2, unofficial].
*   **Coordinate Normalization:** Points may fall outside the $[-1, 1]$ range after projection and scaling; sampling must handle or clip these out-of-bounds coordinates appropriately [S2, unofficial].

## Subtopics

### Multi-View Pixel-Aligned Feature Fusion
Fuses features from multiple 2D projection views into a single 3D point representation using pixel-aligned sampling and max-pooling [S2, unofficial]. It is chosen when explicit 3D geometry is available and multi-view consistency is required for point-wise prediction [S2, unofficial].

## Operating characteristics
*   **Strengths:** Flexible number of input views; outperforms concatenation [S1].
*   **Limitations:** Requires accurate projection coordinates [S2, unofficial].
*   **When to use:** When explicit 3D geometry is available and multi-view consistency is required for point-wise prediction [S2, unofficial].
*   **When not:** Not given in the sources.
*   **Time and memory complexity:** Not given in the sources.
*   **Scaling and measured performance:** Not given in the sources.

## Background
This method originates from NeRF enhancement [S1] and 3D point decoding [S2, unofficial]. It leverages the observation that max-pooling is more effective than concatenation for fusing multi-view features [S1]. It was developed to allow flexible integration of varying numbers of neighboring views [S1].
