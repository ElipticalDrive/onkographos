# Convolutional Decoder with Ray-Patch Querying

Also called: RP-DeFiNe decoder, RP-OSRT decoder, RP-SRT decoder

## Overview
The Convolutional Decoder with Ray-Patch Querying is a multi-scale upsampling architecture that generates final image outputs from latent feature representations by integrating Ray-Patch querying [S1, unofficial]. It differs from learned up-sampling or attention-based upsamplers by using fixed nearest-neighbour interpolation combined with convolutional blocks and batch normalization [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A latent feature map with 128 channels [S1, unofficial].
*   **Output:** The ultimate output image $\tilde{I}_t$ [S1, unofficial].

**Data Structures**
*   **Feature Map:** A 3D tensor $F \in \mathbb{R}^{H \times W \times C}$, where $H, W$ are spatial dimensions and $C$ is the channel count.
*   **Preliminary Output:** An intermediate tensor $P_i$ generated at each stage $i$.

**Parameters**
*   **Patch size $k$:** Determines the number of upsampling blocks. For $k=8$ ($2^3$), exactly 3 upsampling blocks are used [S1, unofficial].
*   **Initial channel count:** Fixed at 128 channels at the input of the decoder [S1, unofficial].
*   **Channel scaling factor:** Halved per block [S1, unofficial].
*   **Spatial scaling factor:** Doubled per block via nearest neighbour up-sampling [S1, unofficial].

```python
def convolutional_decoder_with_ray_patch_querying(latent_features, patch_size_k=8):
    """
    latent_features: Tensor of shape (B, 128, H, W)
    patch_size_k: int, determines number of blocks (e.g., 8 -> 3 blocks)
    """
    num_blocks = int(np.log2(patch_size_k))
    initial_channels = 128
    current_channels = initial_channels
    
    # Preliminary output from a "virtual" preceding block for the first block
    # The first block adds to "preliminary output from the preceding block".
    # For i=0, there is no preceding block. We assume 0 or skip addition.
    prev_prelim = None
    
    for i in range(num_blocks):
        # 1. Generate preliminary output
        # Prelim Conv outputs 'initial_channels' (128) to match previous prelim
        prelim_conv = Conv2d(current_channels, initial_channels, kernel_size=3, padding=1)
        P_i = prelim_conv(latent_features)
        
        # 2. Add preliminary output from preceding block
        if prev_prelim is not None:
            # P_i and prev_prelim have same channels (128) and spatial dims (current H, W)
            P_i = P_i + prev_prelim
        
        # 3. Up-scale doubling dimensions
        latent_features = UpsampleNearest(latent_features, scale_factor=2)
        
        # 4. Convolutional layer
        # Halves the channel count
        next_channels = current_channels // 2
        conv = Conv2d(initial_channels, next_channels, kernel_size=3, padding=1)
        latent_features = conv(latent_features)
        
        # 5. Batch Normalization
        latent_features = BatchNorm2d(next_channels)(latent_features)
        
        # 6. Leaky ReLU
        latent_features = LeakyReLU()(latent_features)
        
        # Store current prelim for next iteration
        prev_prelim = P_i
        current_channels = next_channels
        
    # Final Step
    # Apply a convolutional layer to transform the output from the last block into a c-channel result
    # c is likely initial_channels (128) based on the pattern
    final_conv = Conv2d(current_channels, initial_channels, kernel_size=3, padding=1)
    final_result = final_conv(latent_features)
    
    # Add the final c-channel result to the preliminary output (from the last block)
    # prev_prelim is P_{N-1}
    ultimate_output = final_result + prev_prelim
    
    return ultimate_output
```

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and channels, dominated by the convolutional operations in the upsampling blocks.
*   **Memory Complexity:** Requires storing preliminary outputs for skip connections, increasing memory usage compared to simple decoders.
*   **Performance:** The use of normalization (Batch Normalization) after convolutional layers speeds up convergence and elevates the plateau value [S1, unofficial].
*   **Strengths:** Fixed nearest-neighbour interpolation is computationally efficient and stable compared to learned upsamplers [S1, unofficial].
*   **Limitations:** Fixed interpolation may not adapt as well to complex geometric structures as attention-based methods [S1, unofficial].

## Background
The method is based on GIRAFFE’s decoder [35] [S1, unofficial]. It was adapted for Ray-Patch querying in the context of Light Field Transformers [S1, unofficial]. The training schedule was adapted to accelerate convergence with a linear decay to $4 \times 10^{-5}$ over 300k steps [S1, unofficial].
