# Hybrid Lighting Prediction Network

Also called: Hybrid Lighting Prediction Architecture, Hybrid lighting representation, Lighting Representation (Sky + VSG Volume), Lighting estimation

## Overview
The Hybrid Lighting Prediction Network is a neural architecture that predicts a hybrid lighting representation for outdoor street scenes by simultaneously estimating an HDR sky dome and a Volumetric Spherical Gaussian (VSG) lighting volume [S1]. It differs from prior methods like Wang et al. [37] by explicitly tailoring the VSG volume dimensions ($256 \times 256 \times 64$) to accommodate large outdoor scales ($300 \times 300 \times 80$ meters$^3$) and employing a log projection to handle dense close-to-camera surfaces [S1]. The method uses a 2D CNN backbone to extract features, which are then processed by separate branches: a pre-trained sky decoder for the environment map and a 3D UNet for the volumetric lighting [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A single RGB image $I$ of resolution $H \times W$.
*   **Output:**
    1.  HDR Sky Dome: A tensor of shape $\mathbb{R}^{3 \times 64 \times 256}$ representing the sky environment map [S1].
    2.  VSG Lighting Volume: A 3D grid of shape $\mathbb{R}^{8 \times 64 \times 256 \times 256}$ representing the volumetric lighting [S1].

**Data Structures and Layout:**
*   **Sky Feature Vector:** $\mathbf{f}_{sky} \in \mathbb{R}^{64}$ [S1].
*   **Scene Lighting Feature:** $\mathbf{f}_{scene} \in \mathbb{R}^{128}$ [S1].
*   **Visible Surface Volume:** $\mathbf{V}_{vis} \in \mathbb{R}^{4 \times 64 \times 256 \times 256}$, created by unprojecting the input image [S1].
*   **Global Scene Feature Volume:** $\mathbf{V}_{global} \in \mathbb{R}^{32 \times 16 \times 64 \times 64}$, generated by an MLP [S1].
*   **VSG Volume:** Stored as a 3D grid in $xyz$ coordinates with dimensions $256 \times 256 \times 64$ [S1]. The spatial bounds covered are $300 \times 300 \times 80$ meters$^3$ [S1].
*   **Depth Map:** Dense depth map $D$ predicted by PackNet [S1].

**Parameters:**
*   **Sky Decoder:** Pre-trained, fixed weights (frozen) [S1].
*   **Coordinate MLP:** 3 residual MLP blocks, hidden size 64 [S1].
*   **3D UNet:** 5 downsampling and 5 upsampling conv-blocks with residual connections. Each conv-block contains two 3D convolution layers [S1].
*   **3D UNet Intermediate Channels:** $(12, 16, 32, 128, 256, 256, 128, 64, 32, 16)$ [S1].
*   **Log Projection:** Used to map volume representation to 3D scene location to handle large scales [S1].

**Steps:**

1.  **Depth Estimation:**
    Use an off-the-shelf monocular depth estimator (PackNet) to predict a dense depth map $D$ for the input image $I$ [S1].

2.  **Feature Extraction (ResNet Backbone):**
    Pass the input image $I$ through a ResNet50 backbone [8] to extract two features:
    *   Sky feature vector $\mathbf{f}_{sky} \in \mathbb{R}^{64}$ [S1].
    *   Scene lighting feature $\mathbf{f}_{scene} \in \mathbb{R}^{128}$ [S1].

3.  **HDR Sky Prediction Branch:**
    *   Pass $\mathbf{f}_{sky}$ into a pre-trained sky decoder with frozen weights [S1].
    *   The decoder outputs the HDR Sky Dome tensor of shape $\mathbb{R}^{3 \times 64 \times 256}$ [S1].

4.  **Lighting Volume Prediction Branch:**
    *   **Unprojection:** Unproject the input image $I$ using the depth map $D$ and camera intrinsics into an initial visible surface volume $\mathbf{V}_{vis} \in \mathbb{R}^{4 \times 64 \times 256 \times 256}$ [S1]. This encodes visible field-of-view information [S1].
    *   **Global Feature Volume Generation:** Pass $\mathbf{f}_{scene}$ into a coordinate MLP (3 residual MLP blocks, hidden size 64) to decode it into a global scene feature volume $\mathbf{V}_{global} \in \mathbb{R}^{32 \times 16 \times 64 \times 64}$ [S1].
    *   **3D UNet Processing:**
        *   Initialize the 3D UNet with $\mathbf{V}_{vis}$ as input [S1].
        *   The UNet consists of 5 downsampling and 5 upsampling conv-blocks [S1].
        *   After the 2nd downsampling conv-block, fuse $\mathbf{V}_{global}$ into the UNet feature map [S1].
        *   The UNet uses residual connections [8]. Each conv-block has two 3D convolution layers [S1].
        *   Intermediate channel dimensions follow the sequence: $(12, 16, 32, 128, 256, 256, 128, 64, 32, 16)$ [S1].
    *   **Output:** The final conv-layer of the 3D UNet produces the VSG lighting volume prediction of shape $\mathbb{R}^{8 \times 64 \times 256 \times 256}$ [S1].

5.  **Coordinate Mapping:**
    Map the VSG volume representation to 3D scene locations using log projection to handle large outdoor scales and dense close-to-camera surfaces [S1].

## Subtopics

### Multi-view Lighting Extension
Extends the monocular model to consume multiple camera views for improved accuracy by fusing features in a canonical space [S1]. For the HDR sky branch, it applies max pooling to intensity ($f_{intensity}$) and albedo ($f_{albedo}$) features, and rotates direction features ($f_{dir}$) from different views to a canonical view before applying average pooling [S1]. For volumetric lighting, it unprojects multi-view images and fuses them into a common lighting volume representation defined in world coordinates [S1].

## Operating characteristics
*   **Inference Time:** 180ms per image on a TITAN V GPU [S1].
*   **Memory/Scale:** The VSG volume covers $300 \times 300 \times 80$ meters$^3$ [S1]. The volume resolution is $256 \times 256 \times 64$ [S1].
*   **Strengths:** Explicitly tailored for large outdoor scene scales, unlike [37] [S1]. Uses log projection to handle dense close-to-camera surfaces effectively [S1].
*   **Limitations:** Relies on the accuracy of an off-the-shelf monocular depth estimator (PackNet); depth prediction errors influence lighting estimation performance [S1].
*   **When to use:** Outdoor street scene lighting estimation for AR object insertion where both sky and volumetric lighting are required [S1].

## Background
The method originates from the paper "Neural Light Field Estimation for Street Scenes with Differentiable Virtual Object Insertion" [S1]. It adapts the VSG prediction subnetwork from Wang et al. [37] but modifies the volume dimensions and coordinate mapping for street scenes [S1]. It builds on the Hybrid Lighting Joint Prediction Module [14686-lighting-joint-prediction-module.md].
