# Feature Fusion for Radiance Decoding

Also called: Lidar-Hash Feature Fusion MLP

## Overview
This method decodes radiance fields by fusing geometric priors from LiDAR point clouds with appearance features from a hash grid. It solves the problem of sparse LiDAR data by combining it with dense hash-encoded features to predict density and color. It differs from its siblings by explicitly concatenating a LiDAR-specific encoding $\phi_L$ with a hash encoding $\phi_h$ before passing them to a density MLP, whereas [Feature Extraction Network](8151-feature-extraction-network.md) and [CNN-based 2D Feature Extraction](8649-cnn-based-2d-feature-extraction.md) rely primarily on image-derived features, and [Attention-based Multi-View Density Prediction](10674-attention-based-multi-view-density-prediction.md) uses attention mechanisms rather than direct feature concatenation for decoding.

## How it works
**Inputs:**
1.  A 3D query location $x$.
2.  A viewing direction $d$.
3.  A set of LiDAR points $P$ and their associated features.
4.  A hash grid encoding structure.

**Outputs:**
1.  Per-sample density $\alpha$.
2.  Density embedding $h$.
3.  View-dependent color $c$.

**Data Structures:**
*   **Hash Encoding $\phi_h(x)$:** A vector resulting from the hash grid lookup at location $x$. The exact dimension is not specified in the sources, but it is concatenated with $\phi_L(x)$.
*   **LiDAR Encoding $\phi_L(x)$:** A vector representing the local LiDAR context at $x$. It is computed as a weighted average of features from $K$ neighboring LiDAR points. If the set of neighbors $S_{xK}$ is empty, $\phi_L(x) = 0$.
    *   The weight $w_i$ for a neighbor point $p_i$ is defined as:
        $$ w_i = \frac{1}{\|p_i - x\|} $$
    *   The encoding is calculated as:
        $$ \phi_L(x) = \frac{\sum_{i \in S_{xK}} w_i f_{i,x}}{\sum_{i \in S_{xK}} w_i} $$
        where $f_{i,x}$ is the feature of the $i$-th neighbor at location $x$.
*   **Spherical Harmonics (SH):** A vector encoding the viewing direction $d$.

**Steps:**
1.  Compute the LiDAR encoding $\phi_L(x)$ by aggregating features from $K$ nearest LiDAR neighbors using inverse distance weighting.
2.  Compute the hash encoding $\phi_h(x)$ by querying the hash grid at location $x$.
3.  Concatenate the two encodings: $v = [\phi_L(x), \phi_h(x)]$.
4.  Pass the concatenated vector $v$ through an MLP $F_\alpha$ to predict the density $\alpha$ and the density embedding $h$:
    $$ \alpha, h = F_\alpha([\phi_L(x), \phi_h(x)]) $$
5.  Encode the viewing direction $d$ using Spherical Harmonics to obtain $SH(d)$.
6.  Concatenate the density embedding $h$ with the directional encoding $SH(d)$: $v_c = [h, SH(d)]$.
7.  Pass $v_c$ through a second MLP $F_c$ to predict the color $c$:
    $$ c = F_c([h, SH(d)]) $$

**Pseudocode:**
```python
def feature_fusion_decode(x, d, lidar_points, lidar_features, hash_grid, K=8):
    """
    x: 3D query location (vector)
    d: Viewing direction (vector)
    lidar_points: Array of LiDAR point locations
    lidar_features: Array of features corresponding to lidar_points
    hash_grid: Hash grid structure supporting lookup(x)
    K: Number of nearest neighbors for LiDAR encoding
    """
    # Step 1: Compute LiDAR Encoding phi_L(x)
    # Find K nearest neighbors
    neighbors = get_k_nearest_neighbors(x, lidar_points, K)
    
    if len(neighbors) == 0:
        phi_L = zeros_like(phi_L) # Not given in sources, assumed zero vector
    else:
        weights = []
        weighted_features = []
        for p_i in neighbors:
            dist = norm(p_i - x)
            w_i = 1.0 / dist
            weights.append(w_i)
            # f_i,x is the feature of the neighbor at location x
            # Assuming feature is stored per point and interpolated or taken directly
            # The source formula implies f_i,x is the feature value
            f_i_x = get_feature_for_point(p_i, lidar_features) 
            weighted_features.append(w_i * f_i_x)
        
        sum_weights = sum(weights)
        sum_weighted_features = sum(weighted_features)
        phi_L = sum_weighted_features / sum_weights

    # Step 2: Compute Hash Encoding phi_h(x)
    phi_h = hash_grid.lookup(x)

    # Step 3 & 4: Density MLP F_alpha
    concat_density = concatenate(phi_L, phi_h)
    alpha, h = F_alpha(concat_density)

    # Step 5: Directional Encoding
    sh_d = spherical_harmonics_encode(d)

    # Step 6 & 7: Color MLP F_c
    concat_color = concatenate(h, sh_d)
    c = F_c(concat_color)

    return alpha, h, c
```

**Parameters:**
*   $K$: Number of LiDAR neighbors. Not given in the sources.
*   MLP Architectures ($F_\alpha, F_c$): Not given in the sources.

**Edge Cases:**
*   If no LiDAR points are within the neighborhood $S_{xK}$, $\phi_L(x)$ is zero. This may lead to reliance solely on hash features, potentially reducing geometric accuracy in sparse regions.

## Subtopics

### Context-aware Radiance Field Decoder
A variant that models 3D context using a (2+1)D CNN to factorize 3D convolutions into 2D spatial and 1D depth convolutions. It uses 12 stacked (2+1)D residual blocks and a lightweight 8× upsampler. It predicts color and density via two linear layers (3 and 1 output channels). It has 10.4M parameters, which is 50% fewer than a full 3D CNN (16.6M) while producing sharper structures and better performance than Ray Transformers or MLPs alone [S2].

### (2+1)D CNN Radiance Decoder
A factorized convolutional neural network decoder that applies 2D spatial convolutions followed by 1D depth convolutions to predict the radiance field from the target view frustum volume. It consists of 12 stacked (2+1)D residual blocks and a lightweight upsampler. It uses 10.4M parameters, offering better efficiency than a 3D CNN (16.6M) and superior performance to Ray Transformers and MLPs [S2].

## Operating characteristics
*   **Memory:** Depends on the hash grid size and the number of LiDAR points. The (2+1)D CNN variant uses 10.4M parameters, significantly less than the 16.6M required by a full 3D CNN [S2].
*   **Performance:** The (2+1)D CNN variant produces sharper structures than MLPs and Ray Transformers, and performs similarly to 3D CNNs but with fewer parameters [S2].
*   **Strengths:** Combines sparse LiDAR geometry with dense hash features for robust decoding. The (2+1)D CNN variant offers a good balance between parameter efficiency and reconstruction quality.
*   **Limitations:** Relies on the availability of LiDAR data for the $\phi_L$ component. Performance may degrade in regions with sparse LiDAR coverage if the hash features alone are insufficient.

## Background
The method was introduced in the LidaRF paper [S1] to address the challenges of neural radiance fields on street scenes by leveraging LiDAR data. The (2+1)D CNN variant was explored in the MuRF paper [S2] as an efficient alternative to 3D CNNs for multi-baseline radiance fields.
