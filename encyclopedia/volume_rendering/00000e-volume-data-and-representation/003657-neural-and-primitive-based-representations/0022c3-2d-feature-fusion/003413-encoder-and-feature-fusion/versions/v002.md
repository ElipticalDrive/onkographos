# Encoder and Feature Fusion

Also called: Deep Convolution Feature Fusion, Semantic Feature Fusion

## Overview
Encoder and Feature Fusion methods address the semantic gap in neural volume rendering by replacing raw point coordinates with deep convolutional features extracted from input images [S1, unofficial][S4]. Unlike standard NeRF which maps coordinates directly to color and density, this approach conditions the rendering network on scene-specific features, enabling better generalization to unseen scenes and handling complex geometry and texture [S1, unofficial]. It sets itself apart from sibling methods like [Attention-based Multi-View Density Prediction](10674-attention-based-multi-view-density-prediction.md) by relying on hierarchical convolutional feature extraction and explicit reprojection or fusion mechanisms rather than solely on attention-weighted pooling [S1, unofficial].

## How it works
The method consists of two main phases: feature extraction from 2D input views and the fusion of these features into a 3D representation for rendering.

### Inputs and Outputs
*   **Inputs:** A set of $N$ input RGB images $I_i \in [0, 1]^{H \times W \times 3}$ with known camera poses (position and orientation) [S1, unofficial][S4].
*   **Outputs:** For a query 3D point $x_j$ and view direction $r$, the method predicts color $c$ and opacity $\sigma$ [S1, unofficial].

### Data Structures
1.  **Image Feature Map ($M_i$):** A tensor of shape $H \times W \times Z$ extracted from each input image $I_i$ [S1, unofficial].
2.  **Multi-view Aware Features ($W_n$):** A fused feature representation for each point in 3D space, generated by aggregating features from multiple views [S1, unofficial].
3.  **Pixel Features:** In some variants, a tensor of shape $H \times W \times C_{out}$ (e.g., 128) representing robust per-pixel features [S4].

### Steps

1.  **Feature Extraction:**
    *   Pass each input image $I_i$ through an encoder network (e.g., U-ResNet, ResNet34, or a generic CNN) to extract deep convolution features $M_i$ [S1, unofficial][S2, S4].
    *   The encoder captures geometry, shape, and texture information [S1, unofficial].
    *   *Variant (GRF):* Stack the camera xyz location to each pixel of the input RGB image to make pixel features explicitly aware of their relative position in 3D space [S4]. Input dimension becomes $H \times W \times (3 + 3)$ [S4].
    *   *Variant (GRF):* Use skip connections between encoder and decoder to preserve high-frequency local features [S4]. Optionally integrate fully connected (fc) layers to learn global features [S4].

2.  **Feature Consistency and Fusion (GARF approach):**
    *   Concatenate the image feature $M_i$ with its mean and variance map to check consistency among features [S1, unofficial].
    *   Feed the concatenated feature into a PointNet-like MLP to integrate local and global information [S1, unofficial].
    *   Generate multi-view aware features $W_n$ for each point [S1, unofficial].

3.  **Reprojection or Fusion into 3D Space:**
    *   *Reprojection (GRF):* Reproject the 2D pixel features back to 3D space along the light ray from the camera center to the 3D surface point $p$ [S4]. Since depth scans are unavailable, features are accumulated or interpolated along the ray [S4].
    *   *Fusion (GARF):* Fuse multi-view features for representing each point in the 3D space semantically [S1, unofficial].

4.  **Rendering Query:**
    *   The rendering function $f_{GARF}$ takes the point $x_j$, the fused feature $F(x_j)$, and the view direction $r$ to predict color $c$ and opacity $\sigma$ [S1, unofficial]:
        $$ f_{GARF}: F(x_j), x_j, r \mapsto (c, \sigma) $$
    *   *Variant (VS-Splat):* For selected voxels, concatenate the unified coarse feature $\tilde{v}_{h,w,d}$, fine detail feature $\hat{v}_{h,w,d}$, and position-encoded skeletal primitive position $\gamma(\mu_{crs_{h,w,d}})$ in a channel-wise manner [S3, unofficial]. Pass through a Selective Feature Refinement (SFR) module to generate refined object-centric features [S3, unofficial].

### Parameters and Typical Values
*   **Encoder Backbone:** ResNet34 is commonly used [S2].
*   **Output Channel Dimension:** 128 for GRF pixel features [S4]; 512 for VS-Splat SFR output [S3, unofficial].
*   **Residual Blocks (SFR):** $R=2$ [S3, unofficial].
*   **Depth Sampling:** 64 inverse-depth samples are used in related methods like GeNeRF [S2].

### Edge Cases and Pitfalls
*   **Camera Intrinsics/Rotation:** Stacking additional camera rotation and intrinsics to each pixel does not noticeably improve performance compared to just position [S4].
*   **Shape Mismatch:** After up-convolution in the feature extraction network, the shape of the resulting feature map may not match the shape of the feature map to be concatenated. Bilinear interpolation must be used to rescale them to the same shape [S2].
*   **Semantic Gap:** Using raw RGB values as pixel features is sub-optimal due to sensitivity to lighting and noise; deep features are required for robustness [S4].

## Subtopics

### [ResNet Architecture](8378-resnet-architecture.md)
The ResNet architecture serves as the basic building block for residual connections in 3D and 2D convolutions, primarily used to mitigate the vanishing gradient problem in deep networks. It sets itself apart from standard convolutional layers by introducing shortcut connections that add the input directly to the output, allowing the network to learn residual functions. In the context of volume rendering and feature fusion, it acts as a core component for encoding 3D volumetric data or processing 2D feature maps, often appearing in encoders like RenderNet.

### [Attention-based Multi-View Density Prediction](10674-attention-based-multi-view-density-prediction.md)
This method fuses features from multiple camera views to predict the density field for neural volume rendering, addressing the limitation of single-view or naive averaging approaches in complex geometric scenes. It sets itself apart from sibling methods like [ResNet Architecture](8378-resnet-architecture.md) by explicitly modeling inter-view relationships through weighted pooling and intra-ray dependencies through self-attention, rather than relying solely on hierarchical convolutional feature extraction.

### Feature Extraction Network
A network architecture for extracting features from input images, based on ResNet34 with specific convolutional and up-convolutional layers for feature fusion [S2]. The backbone is ResNet34 [S2]. The architecture consists of: Input -> [Conv]x3 -> MaxPool (omitted in diagram) -> Residual Blocks [S2]. Path 1: [Conv]x3 -> UpConv (3x3 256) -> UpConv (3x3 128) -> [Conv]x3 (3x3 64) -> [Conv]x3 (3x3 64) -> 7x7 64 [S2]. Path 2: [Conv]x6 -> [Conv]x3 [S2]. Concatenation of features occurs after up-convolution steps [S2]. If shapes mismatch after up-convolution, bilinear interpolation is used to rescale to the same shape [S2].

### Selective Feature Refinement (SFR) Module
A module that operates exclusively on selected voxels to refine features, using sparse 3D convolutional layers [S3, unofficial]. For each selected voxel $(h, w, d)$, it concatenates the unified coarse feature $\tilde{v}_{h,w,d}$, the fine detail feature $\hat{v}_{h,w,d}$, and the position-encoded skeletal primitive position $\gamma(\mu_{crs_{h,w,d}})$ in a channel-wise manner [S3, unofficial]. The module contains $R=2$ residual convolutional blocks and produces features with a channel dimension of 512 [S3, unofficial].

### CNN-based 2D Feature Extraction
A convolutional neural network (CNN) module extracts robust per-pixel features from input RGB images to learn general patterns for each pixel [S4]. It stacks the camera xyz location to each pixel of the input RGB image to make pixel features explicitly aware of their relative position in 3D space [S4]. It uses skip connections between the encoder and decoder to preserve high frequency local features for each pixel [S4]. It optionally integrates fully connected (fc) layers in the middle of the CNN module to learn global features [S4]. The input dimension is $H \times W \times (3 + 3)$, where 3 is RGB and 3 is the stacked camera xyz location [S4]. Stacking additional camera rotation and intrinsics to each pixel does not noticeably improve performance [S4].

## Operating characteristics
*   **Time Complexity:** Depends on the encoder depth and the number of views. VS-Splat achieves about a 1.3× speedup compared to LaRa on the GObjaverse dataset [S3, unofficial].
*   **Memory Complexity:** VS-Splat consists of approximately 128 million trainable parameters [S3, unofficial].
*   **Strengths:** Eliminates the semantic gap of implicit mapping by using deep convolution features [S1, unofficial]. Enhances generalization via commonality learning [S1, unofficial]. Robust to lighting conditions and environmental noise compared to raw RGB [S4].
*   **Limitations:** Requires careful handling of shape mismatches during up-convolution [S2]. Performance does not significantly benefit from adding camera rotation/intrinsics to pixel features [S4].
*   **When to use:** When generalizing to unseen scenes is required, or when scene-specific semantic information (texture, geometry) needs to be preserved [S1, unofficial][S4].
*   **When not to use:** When computational resources are extremely limited and simple coordinate-based NeRF is sufficient, or when camera poses are highly inaccurate (though some variants handle noisy poses with extensions) [S3, unofficial].

## Background
The concept of using deep features for generalizable neural rendering originated with works like GARF (Geometry-Aware Generalized Neural Radiance Field) and GRF (Learning a General Radiance Field for 3D Representation and Rendering) [S1, unofficial][S4]. GARF introduced the idea of conditioning the prediction on reference images via a U-ResNet encoder to eliminate the semantic gap of implicit mapping [S1, unofficial]. GRF proposed using a CNN to extract robust per-pixel features and reprojecting them to 3D space [S4]. Later works like DBARF and VS-Splat refined these approaches with specific architectures like ResNet34-based feature extraction networks and Selective Feature Refinement modules [S2][S3, unofficial].
