# Cross-View Feature Matching and Cost Volume Construction

Also called: Cost Volume Construction, Plane-Sweep Cost Volume

## Overview
This method constructs a 3D cost volume from multiple 2D image features to enable dense depth estimation and subsequent 3D feature lifting. It solves the correspondence problem across views by warping features from neighboring cameras to a reference view at hypothesized depths and aggregating similarity scores. It is distinguished from sibling methods like [Attention-based Multi-View Density Prediction](10674-attention-based-multi-view-density-prediction.md) by explicitly constructing an intermediate 2D cost volume per view before regressing depth, rather than predicting density or attributes directly in 3D space.

## How it works
**Inputs:** $N$ input RGB images, camera intrinsics $K$, and extrinsic parameters (rotation $R_i$, translation $t_i$) for each view $i$.
**Outputs:** A set of per-view cost volumes $\{C_i\}_{i=1}^N$ where $C_i \in \mathbb{R}^{\frac{H}{p} \times \frac{W}{p} \times D}$, and optionally a depth map $D_i$ if the depth module is included.

**Data Structures:**
*   **Feature Maps ($F_i$):** Downsampled feature maps of size $\frac{H}{p} \times \frac{W}{p} \times C$.
*   **Cost Volume ($C_i$):** 3D tensor where the first two dimensions correspond to the spatial resolution of the feature map, and the third dimension corresponds to the depth axis.
*   **Candidate Depths ($d_m$):** A discrete set of $D$ depth values sampled from a predefined range.

**Steps:**

1.  **Feature Extraction:** Apply a weight-sharing ResNet backbone [S1] to each of the $N$ input RGB images. This produces downsampled feature maps $F_i \in \mathbb{R}^{\frac{H}{p} \times \frac{W}{p} \times C}$ for each view $i$, where $p$ is the downsampling factor (e.g., 8 or 16) and $C$ is the feature dimension [S1].

2.  **Cross-View Refinement:** Refine the features $F_i$ using cross-view attention. For each view, information is exchanged with its two nearest neighboring views using local window attention [S1]. This produces cross-view-aware features, denoted as $F_i$ (refined).

3.  **Plane-Sweep Warping:** For each reference view $i$:
    *   Define a set of $D$ candidate depths $\{d_m\}_{m=1}^D$.
    *   For each candidate depth $d_m$ and each neighboring view $j$:
        *   Warp the refined feature map $F_j$ to the reference view $i$'s coordinate system at depth $d_m$. This involves projecting pixels from view $j$ into view $i$ using the relative camera pose and the hypothesized depth $d_m$.
        *   Let $F_{j \to i}^{(d_m)}$ be the warped feature from view $j$ at depth $d_m$.

4.  **Similarity Aggregation:** Compute pairwise feature similarities between the reference feature $F_i$ and the warped features from neighbors. The similarity is computed via dot-product matching [S1]:
    $$ S_{i,j}^{(d_m)} = F_i \cdot F_{j \to i}^{(d_m)} $$
    *(Note: The dot product is computed element-wise or as a scalar similarity depending on implementation, but the source specifies "aggregated by dot-product matching" [S1]. Typically, this results in a scalar or channel-wise similarity map. We assume element-wise dot product across channels $C$ to produce a scalar similarity map per neighbor, or a vector if channels are preserved. Given the output shape $\frac{H}{p} \times \frac{W}{p} \times D$, the similarity is likely aggregated across neighbors to a single value per pixel per depth.)*

5.  **Cost Volume Formation:** Stack the similarity scores along the depth axis to form the cost volume $C_i$:
    $$ C_i \in \mathbb{R}^{\frac{H}{p} \times \frac{W}{p} \times D} $$
    The value $C_i(u, v, m)$ represents the matching confidence for pixel $(u, v)$ at depth index $m$ [S1].

6.  **Depth Regression (Optional Depth Module):** To produce robust depth estimates, a depth module fuses the monocular features $F_{mono}$ (from step 1 before refinement or a separate branch) with the cost volume $C_i$ to regress a dense per-pixel depth map $D_i \in \mathbb{R}^{\frac{H}{p} \times \frac{W}{p}}$ [S1]. This depth map serves as a geometric prior for lifting features into 3D space.

def build_cost_volume(images, cameras, resnet_backbone, num_depths, depth_range):
    """
    images: List of N RGB images.
    cameras: List of camera parameters (intrinsics K, extrinsics R, t) for N views.
    resnet_backbone: Weight-sharing ResNet model.
    num_depths: D, number of candidate depths.
    depth_range: Tuple (min_depth, max_depth) for sampling D depths.
    """
    N = len(images)
    p = 8  # Downsampling factor, typical value [G]
    C = 256  # Feature dimension, typical value [G]
    
    # Step 1: Feature Extraction
    features = []
    for img in images:
        # ResNet outputs downsampled features
        F = resnet_backbone(img) 
        # F shape: H/p x W/p x C
        features.append(F)
        
    # Step 2: Cross-View Refinement (Simplified Local Window Attention)
    refined_features = []
    for i in range(N):
        # Get neighbors (e.g., i-1, i+1)
        neighbors = get_neighboring_indices(i, N)
        # Apply local window attention with neighbors
        F_refined = cross_view_attention(features[i], [features[j] for j in neighbors])
        refined_features.append(F_refined)
        
    # Step 3 & 4 & 5: Plane-Sweep Cost Volume Construction
    cost_volumes = []
    depths = sample_depths(depth_range, num_depths)
    
    for i in range(N):
        H_feat, W_feat, _ = refined_features[i].shape
        C_i = torch.zeros((H_feat, W_feat, num_depths))
        
        for m, d_m in enumerate(depths):
            similarity_sum = torch.zeros((H_feat, W_feat))
            
            for j in neighbors:
                # Warp feature from view j to view i at depth d_m
                # Requires unprojecting pixels in j, transforming to world, 
                # projecting to i, and sampling features from F_j
                F_warped = warp_feature(refined_features[j], cameras[j], cameras[i], d_m)
                
                # Dot-product matching
                # Element-wise dot product across channels C
                # F_i: H/p x W/p x C
                # F_warped: H/p x W/p x C
                sim = torch.sum(refined_features[i] * F_warped, dim=-1)
                similarity_sum += sim
                
            # Normalize or aggregate if necessary
            C_i[:, :, m] = similarity_sum / len(neighbors)
            
        cost_volumes.append(C_i)
        
    return cost_volumes, refined_features

## Subtopics

### Depth Module for Geometric Prior
This variant includes a depth regression module that fuses monocular features with the constructed cost volume to predict a dense depth map $D_i$. This depth map acts as a geometric prior, improving the robustness of the 3D feature lifting process by providing explicit depth estimates rather than relying solely on the cost volume peaks [S1].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot D \cdot H \cdot W \cdot C)$ for feature warping and similarity computation, where $N$ is the number of views, $D$ is the number of depth samples, $H, W$ are image dimensions, and $C$ is feature dimension. The warping operation is the bottleneck.
*   **Memory Complexity:** $O(N \cdot \frac{H}{p} \cdot \frac{W}{p} \cdot D)$ to store the cost volumes. This can be significant for high-resolution images and large depth ranges.
*   **Strengths:** Explicitly models multi-view consistency; leverages strong 2D feature extractors (ResNet); allows for efficient aggregation of information from neighboring views.
*   **Limitations:** Computationally expensive due to plane-sweep warping; memory-intensive for high resolution and fine depth granularity; performance depends on the accuracy of camera parameters and the quality of feature descriptors.
*   **When to use:** When high-quality dense depth estimation is required from multi-view images, and computational resources allow for plane-sweep operations. Suitable for scenarios with known camera poses.

## Background
The method is based on the VolSplat framework, which rethinks feed-forward 3D Gaussian Splatting with voxel-aligned prediction [S1]. It builds on established techniques in stereo matching and multi-view stereo, specifically plane-sweep cost volume construction [S1, S57]. The use of cross-view attention for feature refinement is inspired by Transformer-based feature matching [S1, S56].
