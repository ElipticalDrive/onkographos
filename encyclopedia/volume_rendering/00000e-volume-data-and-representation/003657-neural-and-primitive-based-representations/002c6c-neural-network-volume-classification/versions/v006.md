# Neural Network Volume Classification

Also called: Higher-dimensional classification via pixel shaders, Interactive classification via painting, Neural Network Classification, Neural-network-driven volume renderer, Paint-based classification, Painting-Based Intelligent User Interface for Volume Classification, Sample-based volume classification

## Overview
Neural Network Volume Classification is an interactive method for partitioning volumetric data into material classes by training a neural network on user-provided samples [S2, S3]. Unlike traditional transfer function editing, which requires defining mappings in derived parameter spaces, this method replaces the transfer function space with a direct volume-space painting interface [S2, S3]. It sets itself apart from implicit scene reconstruction methods by focusing on explicit material classification for visualization rather than novel view synthesis [S2, S3]. The system provides real-time visual feedback, allowing users to iteratively refine the classification by painting on slicing planes [S2, S3].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric data (scalar or color), user-painted sample points on slicing planes indicating membership (positive/negative) for a target material class [S2, S3].
*   **Output:** A classified volume where each voxel is assigned an uncertainty value (0 to 1) representing membership probability, which is mapped to opacity for rendering [S2, S3].

**Data Structures:**
1.  **Sample Point Table:** Stores training data for the neural network [S2, S3]. Each entry contains:
    *   Scalar value of the voxel (or R, G, B for color data) [S2, S3].
    *   Gradient magnitude of the voxel [S2, S3].
    *   Scalar values of neighboring voxels (e.g., 6 neighbors: up, down, left, right, front, back) or RGB values for color data [S2, S3].
    *   Position coordinates ($x, y, z$) [S2, S3].
    *   Desired output label (1 for material member, 0 for non-member) [S2, S3].
2.  **Neural Network Weights:** Stored in memory; for hardware implementation, weights are transferred to the GPU per frame [S2, S3].

**Network Topology:**
A three-layer feed-forward perceptron [S2, S3]:
*   **Input Layer:** $m$ inputs. Dimensionality depends on data type and neighbor count [S2, S3].
    *   Scalar data: Scalar value + gradient magnitude + 6 neighbor scalars + 3 position coordinates = 11 inputs [S2, S3].
    *   Color data (6 neighbors): 3 RGB + 18 neighbor RGB + 3 position = 24 inputs [S2].
    *   Color data (12 neighbors): 3 RGB + 36 neighbor RGB + 3 position = 42 inputs [S3].
*   **Hidden Layer:** $n$ hidden nodes. Fully connected to input layer [S2, S3].
*   **Output Layer:** 1 output node. Fully connected to hidden layer [S2, S3].
*   **Activation Function:** Sigmoid function $f(x) = \frac{1}{1 + e^{-x}}$ [S2, S3].

**Algorithm Steps:**
1.  **Initialization:** Initialize network weights randomly [S2, S3].
2.  **User Interaction:** User paints sample points on a slice using two colors (e.g., red for target material, blue for background). Painted regions are projected to other slicers [S2, S3].
3.  **Data Collection:** Record painted voxel properties (value, gradient, neighbors, position) and labels into the Sample Point Table [S2, S3].
4.  **Training Loop (Iterative):** Perform incremental training in the system idle loop to maintain interactivity [S2, S3].
    *   **Forward Propagation:** For each sample point, compute input vector $\mathbf{I}$. Compute hidden layer activations $\mathbf{H}$ and output $O$ [S2, S3].
    *   **Error Calculation:** Compare output $O$ with desired output $T$ (1 or 0). Calculate error [S2, S3].
    *   **Back-Propagation:** Propagate error back to input layer to adjust weights $W$ and biases $b$ to minimize error [S2, S3].
5.  **Visualization:** Apply the trained network to the volume to generate a classified uncertainty volume [S2, S3].
6.  **Refinement:** User views results. If classification is unsatisfactory, user adds/removes paint (Step 2) and training continues (Step 4) [S2, S3].

**Pseudocode:**
```python
import math
import random

def sigmoid(x):
    return 1.0 / (1.0 + math.exp(-x))

def init_weights(m, n):
    # Initialize weights randomly [S2, S3]
    w_in = [[random.uniform(-1, 1) for _ in range(n)] for _ in range(m)]
    w_out = [random.uniform(-1, 1) for _ in range(n)]
    b_hidden = [0.0 for _ in range(n)]
    b_out = 0.0
    return w_in, w_out, b_hidden, b_out

class NeuralNetwork:
    def __init__(self, m, n):
        self.w_in, self.w_out, self.b_hidden, self.b_out = init_weights(m, n)

    def forward(self, x):
        # Hidden layer
        h = []
        for j in range(len(self.b_hidden)):
            z = self.b_hidden[j]
            for i in range(len(x)):
                z += x[i] * self.w_in[i][j]
            h.append(sigmoid(z))
        # Output layer
        z = self.b_out
        for j in range(len(h)):
            z += h[j] * self.w_out[j]
        return sigmoid(z), h

    def train_step(self, samples, lr):
        for sample in samples:
            x = sample['features']
            t = sample['label']
            o, h = self.forward(x)
            delta_out = (o - t) * o * (1.0 - o) # [G] derivative of sigmoid at output
            for j in range(len(self.w_out)):
                self.w_out[j] -= lr * delta_out * h[j]
                self.b_out -= lr * delta_out
            for j in range(len(self.b_hidden)):
                delta_h = delta_out * self.w_out[j] * h[j] * (1.0 - h[j]) # [G] derivative of sigmoid at hidden
                for i in range(len(self.w_in)):
                    self.w_in[i][j] -= lr * delta_h * x[i]
                    self.b_hidden[j] -= lr * delta_h

# Main interaction loop
network = NeuralNetwork(m=11, n=8) # Example dimensions [S2, S3]
samples = []
# User paints on slicing planes, recording voxel properties and labels into samples [S2, S3]
# Training occurs incrementally in the system idle loop [S2, S3]
network.train_step(samples, lr=0.1)
# Apply network to volume voxels to compute uncertainty values [S2, S3]
# Render classified volume using standard volume rendering techniques [S2, S3]
```

**Edge Cases and Pitfalls:**
*   **Generalization Failure:** If position information is included in the input vector, painted voxels must be spread out across different slices. Painting only on one slice leads to poor generalization [S2, S3].
*   **Hardware Limits:** Hardware implementation is limited by pixel shader instruction count and data passing limits. Maximum 8 hidden nodes are supported in the cited hardware implementation [S2, S3]. Hidden node count should be divisible by 4 for vectorization efficiency [S2, S3].
*   **Interpolation Artifacts:** In software classification, interpolation is performed on the scalar-valued classified uncertainty volume, not an RGBA color volume [S2, S3].

## Subtopics

### [Vortex-Net](10429-vortex-net.md)
Vortex-Net identifies vortices in volumetric flow data by training a convolutional neural network to replicate the classification boundary of the Instantaneous Vorticity Deviation (IVD) criterion. It sets itself apart from its parent [Neural Network Volume Classification](5271-neural-network-volume-classification.md) by focusing on specific physical feature extraction rather than general opacity mapping, and from its sibling [Berenjkoub et al. vortex segmentation](10626-berenjkoub-et-al-vortex-segmentation.md) by relying on labels generated from an existing analytical criterion rather than synthetic ground truth.

### Hardware vs Software Neural Network Rendering
*   **Software:** Classifies each voxel before sending to hardware (preclassification). Allows arbitrary network size. Slow (e.g., 9 seconds for 256³ volume) [S2, S3].
*   **Hardware:** Classifies in the fragment program using interpolated data (postclassification). Limited network size (max 8 hidden nodes). Fast (e.g., 1.5 fps for 256³ volume) [S2, S3].

## Operating characteristics
*   **Time Complexity:** Training is iterative and incremental. Software classification is slow (9 seconds for 256³ volume on 2.8 GHz Pentium 4) [S2, S3]. Hardware rendering is limited by rasterization time and texture lookups (7 lookups per pixel) [S2, S3].
*   **Memory Complexity:** Software requires storing the full classified volume. Hardware requires storing network weights (<1 KB) and volume texture [S2, S3].
*   **Performance:** Hardware implementation achieves ~1.5 frames per second for a 256×256×256 volume rendered to a 512×512 window on an ATI Radeon 9700 Pro [S2, S3].
*   **Strengths:** Intuitive user interface (painting in volume space); eliminates manual transfer function tuning; real-time feedback [S2, S3].
*   **Limitations:** Hardware implementation has strict limits on network size; software implementation is too slow for real-time training feedback; requires user to understand data structure for effective painting [S2, S3].
*   **When to use:** Interactive exploration and classification of biomedical or scientific volume data where user intuition guides segmentation [S2, S3].
*   **When not to use:** When high-performance real-time training feedback is required with large networks (use hardware if small network suffices, or accept slow software feedback) [S2, S3].

## Background
*   **Origin:** Proposed by Tzeng et al. [S2, S3] in the mid-2000s. [S3] was presented at IEEE Visualization 2003, and [S2] was published in IEEE Transactions on Visualization and Computer Graphics in 2005.
*   **Development:** The method builds on earlier work in neural networks for image segmentation [S3] and transfer function design [S3]. It addresses the difficulty users face in mapping high-dimensional data to 2D transfer functions [S3].
*   **Usage:** Primarily used in biomedical imaging for segmenting and visualizing structures like brain tissue in MRI scans [S2, S3].
