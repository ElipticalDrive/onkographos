# Shared Feature Grid

Also called: Multi-region Feature Grid, Region-shared Feature Grid

## Overview
The Shared Feature Grid is a compact volumetric representation that reduces memory usage by repeating a single feature grid across $N$ distinct spatial regions of a scene, while employing $N$ region-specific density decoders and a single shared color decoder [S1, S2, S3]. It solves the memory bottleneck of standard feature grids by forcing features to be compact, as they must represent multiple parts of the scene simultaneously [S1, S3]. Unlike sibling methods that use separate grids or separate color fields for each region, this approach reduces the number of unique features and memory footprint by a factor of $N$ [S1, S3].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D query point $x_j$ on a ray $r_j(t) = o_j + d_j t$, where $o_j$ is the ray origin and $d_j$ is the viewing direction [S1, S3].
*   **Output:** The volume density $\sigma_j$ and the final color $c_j$ at point $x_j$ [S1, S3].

**Data Structures**
1.  **Shared Feature Grid:** A single voxel grid containing features [S1, S2, S3]. The grid is repeated identically across $N$ regions [S1, S3].
    *   **Layout:** The grid is defined by a resolution $R$ (chosen independently per dataset) and a feature dimension $C=32$ [S1, S2, S3].
    *   **Placement:** Features are placed symmetrically to the scene center in each volume to favor continuity between density fields [S3].
2.  **Region-Specific Density Decoders:** A set of $N$ neural networks $\{\theta_1, \dots, \theta_N\}$ [S1, S3].
3.  **Shared Color Decoder:** A single neural network $\theta_{\text{color}}$ [S1, S3].

**Parameters**
*   $N$: The number of regions the scene is split into. Typically set to 8 [S1, S2, S3].
*   Region Geometry: Each region is a cube with a side length equal to half the side of the scene's bounding box [S1, S2, S3].
*   Feature Dimension: 32 [S1, S2, S3].

**Numbered Steps**
1.  **Region Identification:** For a query point $x_j$ on ray $r_j$, determine the region index $i$ such that $x_j$ falls within the $i$-th region, where $i \in [1, N]$ [S1, S3].
2.  **Feature Retrieval:** Retrieve the integrated feature $\hat{f}(x_j)$ from the shared feature grid at position $x_j$ [S1, S3].
3.  **Density and Intermediate Representation:** Pass the feature $\hat{f}(x_j)$ and the region index $i$ to the region-specific density decoder $\theta_i$ to compute the density $\sigma_j$ and an intermediate representation $h_j$ [S1, S3]:
    $$ \sigma_j, h_j = \theta_i(\hat{f}(x_j)), \quad i \in [1, N] $$
4.  **Color Computation:** Pass the intermediate representation $h_j$ and the positional encoding of the viewing direction $\gamma(d_j)$ to the shared color decoder $\theta_{\text{color}}$ to obtain the color $c_j$ [S1, S3]:
    $$ c_j = \theta_{\text{color}}(h_j, \gamma(d_j)) $$

**Pseudocode**
```python
def query_shared_feature_grid(x_j, ray_direction, N_regions, 
                              shared_grid_weights, grid_resolution, 
                              density_decoders, color_decoder, 
                              bbox_min, bbox_max):
    """
    Query the Shared Feature Grid representation for a point on a ray.
    
    Args:
        x_j: 3D point coordinates (x, y, z).
        ray_direction: 3D ray direction (d_j).
        N_regions: Number of regions (typically 8).
        shared_grid_weights: 4D tensor of shape (C, R, R, R) for the shared grid.
        grid_resolution: Integer resolution R of the voxel grid.
        density_decoders: List of N neural networks for density prediction.
        color_decoder: Single neural network for color prediction.
        bbox_min: 3D array of minimum bounding box coordinates.
        bbox_max: 3D array of maximum bounding box coordinates.
        
    Returns:
        sigma_j: Volume density.
        c_j: Output color.
    """
    
    # 1. Determine Region Index
    # The scene is split into N=8 regions (2x2x2 grid). Each region is a cube 
    # with side length equal to half the bounding box side [S1, S2, S3].
    region_side = (bbox_max[0] - bbox_min[0]) / 2.0
    
    # Determine which octant the point falls into based on bounding box bounds.
    idx_x = 0 if x_j[0] < bbox_min[0] + region_side else 1
    idx_y = 0 if x_j[1] < bbox_min[1] + region_side else 1
    idx_z = 0 if x_j[2] < bbox_min[2] + region_side else 1
    
    # Map to 0-based index for decoder selection.
    i_idx = idx_x * 4 + idx_y * 2 + idx_z
    
    # 2. Retrieve Feature
    # Map x_j to local normalized coordinates [0, 1] within the region.
    # The grid is shared and repeated identically across regions [S1, S3].
    local_x = (x_j[0] - (bbox_min[0] + idx_x * region_side)) / region_side
    local_y = (x_j[1] - (bbox_min[1] + idx_y * region_side)) / region_side
    local_z = (x_j[2] - (bbox_min[2] + idx_z * region_side)) / region_side
    
    # Trilinear interpolation from the shared grid [G]
    f_hat = trilinear_interpolate(shared_grid_weights, grid_resolution, 
                                  local_x, local_y, local_z)
    
    # 3. Density and Intermediate Representation
    theta_i = density_decoders[i_idx]
    sigma_j, h_j = theta_i(f_hat)
    
    # 4. Color Computation
    gamma_d = positional_encoding(ray_direction)
    c_j = color_decoder(h_j, gamma_d)
    
    return sigma_j, c_j

def trilinear_interpolate(weights, res, u, v, w):
    """Standard trilinear interpolation for a 3D voxel grid [G]."""
    # Clamp coordinates to [0, 1]
    u, v, w = max(0.0, min(1.0, u)), max(0.0, min(1.0, v)), max(0.0, min(1.0, w))
    
    # Map to grid indices
    u0, v0, w0 = int(u * (res - 1)), int(v * (res - 1)), int(w * (res - 1))
    u1, v1, w1 = min(u0 + 1, res - 1), min(v0 + 1, res - 1), min(w0 + 1, res - 1)
    
    # Fractional parts
    du, dv, dw = u * (res - 1) - u0, v * (res - 1) - v0, w * (res - 1) - w0
    
    # Interpolate across C channels
    result = []
    for c in range(weights.shape[0]):
        w000 = weights[c, w0, v0, u0]
        w100 = weights[c, w0, v0, u1]
        w010 = weights[c, w0, v1, u0]
        w110 = weights[c, w0, v1, u1]
        w001 = weights[c, w1, v0, u0]
        w101 = weights[c, w1, v0, u1]
        w011 = weights[c, w1, v1, u0]
        w111 = weights[c, w1, v1, u1]
        
        # Trilinear blend
        val = (w000 * (1-du)*(1-dv)*(1-dw) + 
               w100 * du*(1-dv)*(1-dw) + 
               w010 * (1-du)*dv*(1-dw) + 
               w110 * du*dv*(1-dw) + 
               w001 * (1-du)*(1-dv)*dw + 
               w101 * du*(1-dv)*dw + 
               w011 * (1-du)*dv*dw + 
               w111 * du*dv*dw)
        result.append(val)
    return result

def positional_encoding(v, num_frequencies=10):
    """Standard positional encoding for NeRF [G]."""
    import math
    freq_bands = [2.0 ** (i * num_frequencies / num_frequencies) for i in range(num_frequencies)]
    encoded = []
    for freq in freq_bands:
        encoded.extend([math.sin(v[i] * freq), math.cos(v[i] * freq)])
    return encoded
```

**Edge Cases and Pitfalls**
*   **Boundary Discontinuities:** Placing features symmetrically to the scene center favors continuity between density fields [S3]. A naive linear repetition of features across regions may introduce discontinuities at the seams [S2].
*   **Memory vs. Capacity Trade-off:** While memory is reduced by a factor of $N$, the features must be compact enough to represent multiple distinct parts of the scene, potentially limiting the expressiveness of the feature grid compared to separate grids [S1, S3].

## Operating characteristics
*   **Memory Complexity:** The memory usage for the feature grid is reduced by a factor of $N$ compared to using separate grids for each region [S1, S3]. The total memory is proportional to the size of one grid plus $N$ density decoders and one color decoder [S1, S3].
*   **Time Complexity:** Query time involves one grid lookup, one density decoder inference, and one color decoder inference [G]. The region-specific density decoder adds a small overhead of selecting the correct decoder $\theta_i$ based on the region index [G].
*   **Strengths:** Significant reduction in memory footprint and number of unique features [S1, S3]. Allows for a single color field, simplifying the color prediction network [S3].
*   **Limitations:** The shared feature grid must represent multiple regions, which may require more compact features (dimension 32) compared to methods with dedicated grids [S1, S3]. Discontinuities can occur at region boundaries if not handled carefully (e.g., via symmetric placement) [S2, S3].
*   **When to Use:** Suitable for scenes where memory is a constraint and the scene can be effectively partitioned into regions that share visual characteristics or where a single color field is sufficient [S1, S3].
*   **When Not to Use:** When high-fidelity, region-specific color variations are required that cannot be captured by a single shared color decoder [S3].

## Background
The Shared Feature Grid was introduced in the NeRFLight paper [S1, S2, S3]. It was proposed as a method to make Neural Radiance Fields (NeRF) faster and lighter by reducing the memory footprint of the feature grid representation [S1, S3]. The method is part of the NeRFLight framework, which aims to optimize the trade-off between rendering quality and computational resources [S1]. The approach builds on the concept of feature grids [17764-feature-grid-3d-representation.md] but introduces region-sharing to enhance compactness [S1, S3].
