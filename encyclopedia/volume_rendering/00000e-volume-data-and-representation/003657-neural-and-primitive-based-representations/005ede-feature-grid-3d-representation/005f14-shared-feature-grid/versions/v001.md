# Shared Feature Grid

Also called: Multi-region Feature Grid, Region-shared Feature Grid

## Overview
The Shared Feature Grid is a compact volumetric representation that reduces memory usage by repeating a single feature grid across $N$ distinct spatial regions of a scene, while employing $N$ region-specific density decoders and a single shared color decoder [S1, S2, S3]. It solves the memory bottleneck of standard feature grids by forcing features to be compact, as they must represent multiple parts of the scene simultaneously [S1, S3]. Unlike sibling methods that use separate grids or separate color fields for each region, this approach reduces the number of unique features and memory footprint by a factor of $N$ [S1, S3].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D query point $x_j$ on a ray $r_j(t) = o_j + d_j t$, where $o_j$ is the ray origin and $d_j$ is the viewing direction.
*   **Output:** The volume density $\sigma_j$ and the final color $c_j$ at point $x_j$.

**Data Structures**
1.  **Shared Feature Grid:** A single voxel grid containing features. The grid is repeated identically across $N$ regions.
    *   **Layout:** The grid is defined by a resolution $R$ (chosen independently per dataset) and a feature dimension $C=32$ [S1, S2, S3].
    *   **Placement:** Features are placed symmetrically to the scene center in each volume to favor continuity between density fields [S3].
2.  **Region-Specific Density Decoders:** A set of $N$ neural networks $\{\theta_1, \dots, \theta_N\}$ [S1, S3].
3.  **Shared Color Decoder:** A single neural network $\theta_{\text{color}}$ [S1, S3].

**Parameters**
*   $N$: The number of regions the scene is split into. Typically set to 8 [S1, S2, S3].
*   Region Geometry: Each region is a cube with a side length equal to half the side of the scene's bounding box [S1, S2, S3].
*   Feature Dimension: 32 [S1, S2, S3].

**Numbered Steps**
1.  **Region Identification:** For a query point $x_j$ on ray $r_j$, determine the region index $i$ such that $x_j$ falls within the $i$-th region, where $i \in [1, N]$ [S1, S3].
2.  **Feature Retrieval:** Retrieve the integrated feature $\hat{f}(x_j)$ from the shared feature grid at position $x_j$ [S1, S3].
3.  **Density and Intermediate Representation:** Pass the feature $\hat{f}(x_j)$ and the region index $i$ to the region-specific density decoder $\theta_i$ to compute the density $\sigma_j$ and an intermediate representation $h_j$ [S1, S3]:
    $$ \sigma_j, h_j = \theta_i(\hat{f}(x_j)), \quad i \in [1, N] $$
4.  **Color Computation:** Pass the intermediate representation $h_j$ and the positional encoding of the viewing direction $\gamma(d_j)$ to the shared color decoder $\theta_{\text{color}}$ to obtain the color $c_j$ [S1, S3]:
    $$ c_j = \theta_{\text{color}}(h_j, \gamma(d_j)) $$

**Edge Cases and Pitfalls**
*   **Boundary Discontinuities:** Placing features symmetrically to the scene center favors continuity between density fields [S3]. A naive linear repetition of features across regions may introduce discontinuities at the seams [S2].
*   **Memory vs. Capacity Trade-off:** While memory is reduced by a factor of $N$, the features must be compact enough to represent multiple distinct parts of the scene, potentially limiting the expressiveness of the feature grid compared to separate grids [S1, S3].

## Operating characteristics
*   **Memory Complexity:** The memory usage for the feature grid is reduced by a factor of $N$ compared to using separate grids for each region [S1, S3]. The total memory is proportional to the size of one grid plus $N$ density decoders and one color decoder.
*   **Time Complexity:** Query time involves one grid lookup, one density decoder inference, and one color decoder inference. The region-specific density decoder adds a small overhead of selecting the correct decoder $\theta_i$ based on the region index.
*   **Strengths:** Significant reduction in memory footprint and number of unique features [S1, S3]. Allows for a single color field, simplifying the color prediction network [S3].
*   **Limitations:** The shared feature grid must represent multiple regions, which may require more compact features (dimension 32) compared to methods with dedicated grids [S1, S3]. Discontinuities can occur at region boundaries if not handled carefully (e.g., via symmetric placement) [S2, S3].
*   **When to Use:** Suitable for scenes where memory is a constraint and the scene can be effectively partitioned into regions that share visual characteristics or where a single color field is sufficient [S1, S3].
*   **When Not to Use:** When high-fidelity, region-specific color variations are required that cannot be captured by a single shared color decoder [S3].

## Background
The Shared Feature Grid was introduced in the NeRFLight paper [S1, S2, S3]. It was proposed as a method to make Neural Radiance Fields (NeRF) faster and lighter by reducing the memory footprint of the feature grid representation [S1, S3]. The method is part of the NeRFLight framework, which aims to optimize the trade-off between rendering quality and computational resources [S1]. The approach builds on the concept of feature grids [17764-feature-grid-3d-representation.md] but introduces region-sharing to enhance compactness [S1, S3].
