# NeuS2 Network Architecture

Also called: NeuS2 components

## Overview
NeuS2 is a neural implicit surface reconstruction method that replaces the coordinate-based MLP of the original NeuS framework with a multi-resolution hash grid encoding [S1]. It solves the problem of slow convergence and high memory usage in standard neural fields by leveraging sparse, learnable feature grids [S1]. It differs from its parent [Hash Grid Neural Fields](3855-hash-grid-neural-fields.md) by specifying a particular lightweight MLP decoder structure (1-layer SDF, 2-layer RGB) and a specific 14-level hash grid configuration, and from [NeuS](10-neural-and-primitive-based-representations.md) by introducing this hash-based acceleration while retaining the unbiased volume rendering formulation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D spatial coordinate $\mathbf{x} \in \mathbb{R}^3$.
*   **Outputs:** Signed Distance Field (SDF) value $f(\mathbf{x})$ and RGB color $\mathbf{c}(\mathbf{x})$.

**Data Structures:**
1.  **Multi-resolution Hash Grid:** Consists of 14 levels with resolutions ranging from 16 to 2048 [S1]. Each level stores learnable feature vectors [S1]. Features are interpolated from the grid based on $\mathbf{x}$ and concatenated [G].
2.  **SDF Network:** A 1-layer Multi-Layer Perceptron (MLP) with 64 hidden units [S1]. Input is the concatenated hash features. Output is the scalar SDF value $f(\mathbf{x})$ [S1].
3.  **RGB Network:** A 2-layer Multi-Layer Perceptron (MLP) with 64 hidden units [S1]. Input is the concatenated hash features. Output is the RGB color vector $\mathbf{c}(\mathbf{x})$ [S1].

**Rendering Process:**
The method applies unbiased volume rendering as defined in NeuS [S1].
1.  **Density Conversion:** The SDF $f(\mathbf{x})$ is converted to volume density $\sigma$ using a logistic distribution:
    $$ \sigma = \phi_s(f(\mathbf{x})) = \frac{s e^{-s f(\mathbf{x})}}{(1 + e^{-s f(\mathbf{x})})^2} $$
    where $s$ is a learnable parameter [S1].
2.  **Ray Sampling:** For each pixel, $n$ points $\{p(t_i) = o + t_i \mathbf{v} \mid i = 0, \dots, n-1\}$ are sampled along the camera ray, where $o$ is the ray origin and $\mathbf{v}$ is the direction [S1].
3.  **Rendering:** The color is computed using an unbiased weight function derived from the density [S1].

**Pseudocode:**
```python
def query_neus2(x, hash_grids, sdf_mlp, rgb_mlp, s):
    # x: (3,) float array, 3D spatial coordinate
    # hash_grids: list of 14 3D feature arrays, resolutions 16 to 2048
    # sdf_mlp: function implementing 1-layer MLP (64 hidden units)
    # rgb_mlp: function implementing 2-layer MLP (64 hidden units)
    # s: float, learnable sharpness parameter
    
    # 1. Extract and concatenate features from multi-resolution hash grid
    features = []
    for grid in hash_grids:
        # Trilinear interpolation at x within the current grid resolution [G]
        feat = interpolate_trilinear(grid, x)
        features.append(feat)
    features = concatenate(features)
    
    # 2. Predict SDF
    sdf = sdf_mlp(features)
    
    # 3. Predict RGB
    rgb = rgb_mlp(features)
    
    return sdf, rgb

def compute_density(sdf, s):
    # Converts SDF to volume density using logistic distribution [S1]
    exp_val = math.exp(-s * sdf)
    density = (s * exp_val) / ((1 + exp_val) ** 2)
    return density
```

**Parameters:**
*   **Hash Grid Levels:** 14 [S1].
*   **Hash Grid Resolutions:** Range from 16 to 2048 [S1].
*   **SDF MLP Hidden Units:** 64 [S1].
*   **RGB MLP Hidden Units:** 64 [S1].
*   **Density Parameter $s$:** Learnable [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The hash grid interpolation requires careful handling of boundary conditions and floating-point precision for coordinate hashing [G].
*   **Degenerate Input:** Coordinates far outside the bounding box of the hash grid may require clamping or out-of-bounds handling [G].

## Subtopics

### STSR-INR
STSR-INR extends the CoordNet architecture by adding variable-specific latent embeddings via a variational auto-decoder and a modulated dual-network architecture [S2, unofficial]. It handles multivariate and ensemble data, supporting non-integer upscaling factors such as 1.75× spatial and 2.5× temporal [S2, unofficial]. It is chosen when variable-specific latent embeddings and non-integer upscaling are required for scientific volume data [S2, unofficial].

### Distillation and Fine-tuning Training
This training scheme involves training a teacher model (NeuS) first, then optimizing codes and decoders using output from the teacher model and images [S3]. During training, a batch size of 512 rays is used on a single Nvidia RTX3090-24G GPU, with the Adam optimizer at an initial learning rate of 0.0005 and a cosine annealing scheduler with 5000 warm-up steps [S3]. The queried color and SDF values are supervised with the teacher model's output via a distillation loss [S3]. The training process takes about 16 hours for each model [S3].

## Operating characteristics
*   **Time Complexity:** Training time on real scenes is approximately 3 hours, while synthetic scenes take about 1 hour [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** The method is designed for fast learning compared to standard NeuS [S1].
*   **Strengths:** Fast convergence and efficient memory usage compared to dense voxel grids [S1].
*   **Limitations:** Training time on real scenes remains significant at approximately 3 hours [S1].

## Background
NeuS2 was introduced in the paper "NeuS2: Fast Learning of Neural Implicit Surfaces for Multi-view Reconstruction" [S1]. The method utilizes multi-resolution hash encoding to accelerate the neural field training process [S1].
