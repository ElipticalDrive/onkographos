# Hash Grid Neural Fields

Also called: Multi-Resolution Hash Encoding, InstantNGP-style Hashing

## Overview
Hash Grid Neural Fields represent volumetric or radiance data by mapping spatial coordinates to feature vectors via a sparse, multi-resolution hash table, enabling efficient training and inference of neural implicit representations on consumer GPUs [S1][S3, unofficial]. They distinguish themselves from dense voxel grids by storing features in a sparse hash table, allowing high-resolution details to be captured with significantly less memory, and from pure MLP fields by replacing the heavy neural decoding of coordinates with fast hardware-accelerated lookups and trilinear interpolation [S1][S3, unofficial].

## Shared principles
The core mechanism maps a continuous input coordinate $\mathbf{x} \in [0, 1]^D$ to a set of feature vectors across $L$ resolution levels. Each level $l$ has a grid resolution $R_l$ and a hash table of size $H_l$.

1.  **Coordinate Normalization:** Input coordinates are normalized to $[0, 1]$. If `align_corners` is false, the range $[0, 1]$ maps to $[0.5/\text{scale}, \text{scale}-0.5/\text{scale}]$ to center pixels; otherwise, it maps to $[0, \text{scale}]$ [S1].
2.  **Resolution Scaling:** For level $l$, the scale is calculated as:
    $$ \text{scale}_l = 2^l \times H - 1 $$
    where $H$ is the base resolution [S1][S3, unofficial]. The grid resolution is $\lceil \text{scale}_l \rceil + 1$ [S1][S3, unofficial].
3.  **Grid Positioning:** The continuous position $\mathbf{pos}$ is computed as:
    $$ \mathbf{pos} = \mathbf{x} \times \text{scale}_l + (\text{align\_corners} ? 0.0 : 0.5) $$
    The integer grid coordinates are $\mathbf{pos\_grid} = \lfloor \mathbf{pos} \rfloor$, and the fractional parts $\mathbf{pos\_frac} = \mathbf{pos} - \mathbf{pos\_grid}$ serve as interpolation weights [S1][S3, unofficial].
4.  **Hashing:** For each of the $2^D$ corners of the voxel containing $\mathbf{x}$, a hash index is computed.
    *   **Tiled (Linear):** Index is calculated via stride-based linear indexing modulo $H_l$ [S3, unofficial].
    *   **Hash:** Uses a fast hash function, typically:
        $$ \text{hash}(\mathbf{pos\_grid}) = \bigoplus_{i=0}^{D-1} (\text{pos\_grid}[i] \times \text{primes}[i]) $$
        where $\text{primes} = [1, 2654435761, 805459861, 3674653429, 2097192037, 1434869437, 2165219737]$ [S3, unofficial]. The final index is $\text{hash} \pmod{H_l}$ [S3, unofficial].
5.  **Interpolation:** Features from the $2^D$ corners are accumulated using trilinear interpolation weights derived from $\mathbf{pos\_frac}$ [S1][S3, unofficial].
6.  **Gradient Computation:** The backward pass computes gradients with respect to input coordinates by taking the difference between right and left neighbor features along each dimension, weighted by the product of fractional parts of other dimensions [S1][S3, unofficial].

## Background
Hash Grid Neural Fields were popularized by the Instant Neural Graphics Primitives (InstantNGP) paper, which introduced multi-resolution hash encoding to accelerate the training of neural radiance fields [S1][S3, unofficial]. The technique leverages the sparsity of real-world data to store features in a hash table rather than a dense grid, significantly reducing memory usage while maintaining high resolution [S1][S3, unofficial]. It has since been adopted in various forms for real-time rendering, volume visualization, and editable scene representations [S1][S2, unofficial].
