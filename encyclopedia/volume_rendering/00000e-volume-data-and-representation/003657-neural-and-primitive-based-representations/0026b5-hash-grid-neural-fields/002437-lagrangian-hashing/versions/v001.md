# Lagrangian Hashing

Also called: LagHash

## Overview
Lagrangian Hashing is a hybrid neural field representation that combines the memory efficiency of Eulerian hierarchical hash grids (specifically InstantNGP) with a Lagrangian point-based representation (similar to 3D Gaussian Splatting) to achieve high-quality novel view synthesis with compact parameters [S1]. It differs from its siblings by storing a small set of learnable points, each equipped with a feature and a field of influence, inside the high-resolution hash buckets, allowing the representation to adaptively allocate budget to regions requiring more detail without relying on careful initialization or pruning heuristics [S1].

## How it works
Lagrangian Hashing builds on the multi-scale hash grid structure of InstantNGP [Parent](3855-hash-grid-neural-fields.md). It replaces the static feature vectors in the finest resolution levels with a mixture of Gaussians (MoG) centered at learnable positions.

### Inputs and Outputs
*   **Input:** A continuous query coordinate $\mathbf{x} \in [0, 1]^D$.
*   **Output:** A feature vector $\mathcal{F}(\mathbf{x}) \in \mathbb{R}^F$ (e.g., color, density).

### Data Structures
The representation consists of $L$ levels of hash tables. For each level $l \in \{1, \dots, L\}$:
*   **Resolution:** $N_l = N_{\min} \cdot b^l$, where $N_{\min}$ is the base resolution and $b$ is the scaling base [S1].
*   **Bucket Size:** $B$ is the maximum number of points per bucket [S1].
*   **Feature Tensor $\mathbf{F}_l$:**
    *   If $N_l < B$: Shape $\mathbb{R}^{N_l \times F}$. The map is injective.
    *   If $N_l \ge B$: Shape $\mathbb{R}^{B \times F}$. The map is a hash function [S1].
*   **Lagrangian Points (for $l \ge L - \tilde{L}$):**
    *   Each bucket $v$ in the hash table stores a set of $K$ points.
    *   Each point $k$ has:
        *   Position $\mathbf{p}_{l,v,k} \in \mathbb{R}^D$ (learnable).
        *   Feature vector $\mathbf{c}_{l,v,k} \in \mathbb{R}^F$ (learnable).
        *   Standard deviation $\sigma$ (non-trainable, implicitly proportional to grid resolution) [S1].
    *   The Gaussians are isotropic [S1].

### Numbered Steps

1.  **Coordinate Normalization and Grid Positioning:**
    Compute the grid position $\mathbf{pos}$ for level $l$ using the scale $\text{scale}_l$ and alignment offset as defined in the parent article [Parent](3855-hash-grid-neural-fields.md).
    $$ \mathbf{pos} = \mathbf{x} \times \text{scale}_l + (\text{align\_corners} ? 0.0 : 0.5) $$
    Compute integer grid coordinates $\mathbf{pos\_grid} = \lfloor \mathbf{pos} \rfloor$ and fractional parts $\mathbf{pos\_frac} = \mathbf{pos} - \mathbf{pos\_grid}$ [Parent](3855-hash-grid-neural-fields.md).

2.  **Hash Indexing:**
    For each of the $V = 2^D$ corners $v$ of the voxel containing $\mathbf{x}$:
    *   Compute the hash index $h_v = \text{hash}(\mathbf{pos\_grid}_v) \pmod{B}$ (or $N_l$ if $N_l < B$) using the standard hash function from the parent article [Parent](3855-hash-grid-neural-fields.md).
    *   Retrieve the bucket index $v$ in the feature tensor $\mathbf{F}_l$ [S1].

3.  **Per-Level Feature Computation ($\mathbf{f}_l(\mathbf{x})$):**
    The feature $\mathbf{f}_l(\mathbf{x})$ is computed by summing contributions from all $V$ corners. The contribution of corner $v$ depends on whether the level is Eulerian or Lagrangian.
    $$ \mathbf{f}_l(\mathbf{x}) = \sum_{v \in \mathcal{H}_l(\mathbf{x})} \alpha_v \cdot \mathbf{F}_l[v](\mathbf{x}) \quad (2) $$
    where $\alpha_v$ are the trilinear interpolation weights derived from $\mathbf{pos\_frac}$ [S1].

    *   **Case A: Eulerian Level ($l < L - \tilde{L}$):**
        $\mathbf{F}_l[v](\mathbf{x})$ is the static feature vector stored at index $v$ in $\mathbf{F}_l$.
    
    *   **Case B: Lagrangian Level ($l \ge L - \tilde{L}$):**
        $\mathbf{F}_l[v](\mathbf{x})$ is the weighted sum of features from the $K$ points stored in bucket $v$. Each point $k$ contributes based on its Gaussian influence at $\mathbf{x}$:
        $$ \mathbf{F}_l[v](\mathbf{x}) = \sum_{k=1}^{K} w_{l,v,k}(\mathbf{x}) \cdot \mathbf{c}_{l,v,k} $$
        The weight $w_{l,v,k}(\mathbf{x})$ is the value of the isotropic Gaussian centered at $\mathbf{p}_{l,v,k}$ evaluated at $\mathbf{x}$:
        $$ w_{l,v,k}(\mathbf{x}) = \exp\left( -\frac{\|\mathbf{x} - \mathbf{p}_{l,v,k}\|^2}{2\sigma_l^2} \right) $$
        The standard deviation $\sigma_l$ is non-trainable and proportional to the grid resolution of level $l$ [S1]. The weights are typically normalized so $\sum_k w_{l,v,k}(\mathbf{x}) = 1$ or handled as raw contributions depending on the specific implementation of the decoder [S1, G]. *Note: The source describes the representation as a mixture of Gaussians, implying the weights define the mixture.*

4.  **Feature Concatenation and Decoding:**
    Concatenate the features from all $L$ levels:
    $$ \mathbf{f}_{\text{total}}(\mathbf{x}) = \mathbf{f}_1(\mathbf{x}) \oplus \mathbf{f}_2(\mathbf{x}) \oplus \dots \oplus \mathbf{f}_L(\mathbf{x}) $$
    Pass through a shared MLP decoder with parameters $\boldsymbol{\theta}$:
    $$ \mathcal{F}(\mathbf{x}) = \text{MLP}(\mathbf{f}_{\text{total}}(\mathbf{x}); \boldsymbol{\theta}) \quad (1) $$

### Parameters
*   $L$: Number of levels of detail [S1].
*   $N_{\min}$: Minimum resolution base [S1].
*   $b$: Base of the geometric progression for grid resolution scaling [S1].
*   $B$: Bucket size for the hash table, used when $N_l \ge B$ [S1].
*   $\tilde{L}$: Number of Lagrangian levels at the top of the hierarchy [S1].
*   $K$: Number of points per bucket in Lagrangian levels [S1, G]. *Not explicitly given in sources, but implied by "small set of points".*

### Edge Cases and Pitfalls
*   **Initialization:** Unlike 3D Gaussian Splatting, Lagrangian Hashing does not require careful initialization from depth, COLMAP, or LiDAR, nor does it rely on heuristics to grow/prune points [S1].
*   **Gaussian Standard Deviation:** The standard deviation is non-trainable and implicitly proportional to grid resolution. This differs from 3DGS which uses trainable anisotropic Gaussians [S1].
*   **Precision:** As with all hash-based methods, hash collisions in the bucket can cause feature interference. The injective map for $N_l < B$ avoids this, but hash collisions are possible for $N_l \ge B$ [S1].

def compute_hash_indices(corners, primes, B):
    """
    corners: (..., 2^D, D)
    primes: List of D primes
    B: Hash table size
    """
    # Dot product of corners and primes
    # corners shape: (..., 2^D, D)
    # primes shape: (D,)
    # result shape: (..., 2^D)
    hash_val = torch.sum(corners * torch.tensor(primes, device=corners.device), dim=-1)
    return hash_val % B

def gather_bucket_features(l, hash_indices, B, K):
    """
    Retrieves features from the hash table for level l.
    If l < L - L_tilde: Eulerian (static features)
    If l >= L - L_tilde: Lagrangian (MoG)
    """
    # This is a placeholder for the actual tensor gathering logic
    # which depends on the specific implementation of the hash table storage.
    # For Eulerian: return F_l[hash_indices]
    # For Lagrangian: return weighted sum of K points in each bucket
    
    # Assuming global state access
    if l < params['L'] - params['L_tilde']:
        # Eulerian
        return F_l[l][hash_indices]
    else:
        # Lagrangian
        # Retrieve K points for each hash index
        # Points_l[l] has shape (B, K, D) for positions and (B, K, F) for features
        # We need to compute Gaussian weights for each point relative to x
        # This requires broadcasting x and points_l[l]
        
        # Get positions and features for the hashed buckets
        # Note: hash_indices might have collisions, so we gather all K points for each index
        bucket_positions = Points_l[l][hash_indices] # (..., 2^D, K, D)
        bucket_features = Features_l[l][hash_indices] # (..., 2^D, K, F)
        
        # Compute Gaussian weights
        # sigma_l is non-trainable, proportional to grid resolution
        sigma_l = get_sigma_for_level(l)
        
        # Distance squared
        diff = x.unsqueeze(-2) - bucket_positions # (..., 2^D, K, D)
        dist_sq = torch.sum(diff**2, dim=-1) # (..., 2^D, K)
        
        # Gaussian weights
        weights = torch.exp(-dist_sq / (2 * sigma_l**2)) # (..., 2^D, K)
        
        # Normalize weights? Source says "mixture of Gaussians", usually implies normalized weights
        # But in hash grid context, they might be raw contributions. 
        # Let's assume normalized for mixture interpretation
        weights_sum = torch.sum(weights, dim=-1, keepdim=True) + 1e-8
        weights_norm = weights / weights_sum
        
        # Weighted sum of features
        # (..., 2^D, K, F) * (..., 2^D, K, 1) -> (..., 2^D, F)
        bucket_feat = torch.sum(weights_norm.unsqueeze(-1) * bucket_features, dim=-2)
        
        return bucket_feat

## Subtopics

### [Lagrangian Per-Bucket Feature Representation](3527-lagrangian-per-bucket-feature-representation.md)
A feature representation used at deeper levels (l >= L - L_tilde) of a hierarchical hash grid where features are not stored as static vectors in buckets but are instead computed as a weighted sum of isotropic Gaussians centered at learnable means, allowing for continuous, position-dependent feature retrieval.

## Operating characteristics
*   **Memory Efficiency:** Achieves high-quality novel view synthesis with fewer parameters than traditional methods. For example, it achieves a PSNR of 35.60 dB with 6.68M parameters, compared to a baseline of 27.31 dB with the same parameter count [S1].
*   **Training:** Does not require careful initialization (e.g., from depth, COLMAP, or LiDAR) or heuristics for point growth/pruning [S1].
*   **Performance:** Combines the fast training of Eulerian grids with the adaptive representation of Lagrangian points [S1].
*   **Limitations:** The method relies on a fixed number of points per bucket and non-trainable standard deviations, which may limit flexibility compared to fully trainable anisotropic Gaussian methods like 3DGS [S1].

## Background
Lagrangian Hashing was introduced in 2024 by researchers from Simon Fraser University, University of Trento, University of Toronto, University of British Columbia, and Google DeepMind [S1]. It was presented as a solution to the demand for compact multimedia formats for immersive mixed reality and volumetric content capture. The method bridges the gap between Eulerian representations (like InstantNGP) and Lagrangian point-based representations (like 3D Gaussian Splatting) [S1].
