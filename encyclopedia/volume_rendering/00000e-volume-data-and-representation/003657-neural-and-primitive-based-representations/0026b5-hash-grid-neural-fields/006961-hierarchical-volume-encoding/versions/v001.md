# Hierarchical Volume Encoding

Also called: Multi-scale Volume Encoding

## Overview
Hierarchical Volume Encoding is a spatial representation technique that uses multiple 3D feature volumes at different resolutions to encode 3D space, optimized jointly with Multi-Layer Perceptrons (MLPs) to improve surface reconstruction quality [S1, unofficial]. It solves the problem of "shape crushing" in neural implicit surface reconstruction by enforcing spatial smoothness through low-resolution voxels, which prevents the MLP from overfitting to high-frequency noise [S1, unofficial]. It sets itself apart from single large-width volume approaches by leveraging the fact that low-resolution voxels represent large spaces with a single code, thereby smoothing the space and preserving 3D shape integrity [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A continuous 3D spatial coordinate $\mathbf{x} \in \mathbb{R}^3$.
- Output: A feature vector $\mathbf{F}(\mathbf{x})$ passed to an MLP, which predicts the Signed Distance Function (SDF) and color. The final surface is defined as the zero-level set $S = \{ \mathbf{x} \in \mathbb{R}^3 \mid \text{sdf}(\mathbf{F}(\mathbf{x})) = 0 \}$ [S1, unofficial].

**Data Structures:**
The method employs a set of $N$ dense 3D feature volumes.
- Number of volumes ($N$): 8 [S1, unofficial].
- Feature dimension per volume ($d$): 4 [S1, unofficial].
- Resolutions ($R_i$): The volumes have resolutions increasing from coarse to fine. The specific resolutions used in the source are:
  1. $2 \times 2 \times 2$
  2. $4 \times 4 \times 4$
  3. $8 \times 8 \times 8$
  4. $16 \times 16 \times 16$
  5. $32 \times 32 \times 32$
  6. $64 \times 64 \times 64$
  7. $128 \times 128 \times 128$
  8. $256 \times 256 \times 256$ [S1, unofficial].
- Storage: Each volume is a dense tensor of shape $R_i \times R_i \times R_i \times 4$.

**Algorithm Steps:**
1. **Query:** For a given query point $\mathbf{x}$, compute the normalized coordinates for each of the 8 volumes.
2. **Interpolate:** Perform trilinear interpolation on each of the 8 feature volumes at the corresponding position to retrieve a feature vector $\mathbf{f}_i$ for each resolution level $i \in \{1, \dots, 8\}$.
3. **Concatenate:** Concatenate the 8 interpolated feature vectors to form the combined feature vector $\mathbf{F}(\mathbf{x})$:
   $$ \mathbf{F}(\mathbf{x}) = [\mathbf{f}_1; \mathbf{f}_2; \dots; \mathbf{f}_8] $$
   The resulting vector $\mathbf{F}(\mathbf{x})$ has a dimension of $8 \times 4 = 32$.
4. **Decode:** Pass $\mathbf{F}(\mathbf{x})$ as input to the MLP to predict the SDF and color.

**Pseudocode:**
```python
import numpy as np

def hierarchical_volume_encode(x, volumes):
    """
    Encodes a 3D point x using hierarchical multi-scale volumes.
    
    Args:
        x: numpy array of shape (3,), the query point coordinates.
        volumes: list of 8 numpy arrays, each of shape (R, R, R, 4),
                 representing the feature volumes at increasing resolutions.
                 Resolutions are [2, 4, 8, 16, 32, 64, 128, 256].
    
    Returns:
        F_x: numpy array of shape (32,), the concatenated feature vector.
    """
    # Resolutions corresponding to the 8 volumes
    resolutions = [2, 4, 8, 16, 32, 64, 128, 256]
    
    features = []
    
    for i, res in enumerate(resolutions):
        vol = volumes[i]
        
        # Normalize x to [0, 1] range assuming the volume covers unit space
        # Note: In practice, x might need to be scaled by the bounding box size
        # before normalization. Here we assume unit bounding box for simplicity.
        x_norm = x / res 
        
        # Trilinear interpolation
        # Clamp coordinates to [0, 1] to handle boundary cases
        x_norm = np.clip(x_norm, 0.0, 1.0)
        
        # Extract integer and fractional parts
        ix = (x_norm * (res - 1)).astype(int)
        fx = x_norm * (res - 1) - ix
        
        # Get corner indices
        x0 = ix
        x1 = np.minimum(ix + 1, res - 1)
        
        # Interpolate along x, y, z axes
        # vol shape: (res, res, res, 4)
        # We need to gather features from the 8 corners and interpolate
        
        # Corner indices
        corners = [
            (x0[0], x0[1], x0[2]),
            (x1[0], x0[1], x0[2]),
            (x0[0], x1[1], x0[2]),
            (x1[0], x1[1], x0[2]),
            (x0[0], x0[1], x1[2]),
            (x1[0], x0[1], x1[2]),
            (x0[0], x1[1], x1[2]),
            (x1[0], x1[1], x1[2])
        ]
        
        # Gather features from corners
        corner_features = np.array([vol[c[0], c[1], c[2]] for c in corners])
        
        # Weights for interpolation
        w = fx
        w0 = 1.0 - w
        w1 = w
        
        # Trilinear interpolation weights
        # w000, w100, w010, w110, w001, w101, w011, w111
        weights = np.array([
            w0[0]*w0[1]*w0[2],
            w1[0]*w0[1]*w0[2],
            w0[0]*w1[1]*w0[2],
            w1[0]*w1[1]*w0[2],
            w0[0]*w0[1]*w1[2],
            w1[0]*w0[1]*w1[2],
            w0[0]*w1[1]*w1[2],
            w1[0]*w1[1]*w1[2]
        ])
        
        # Interpolate features
        f_i = np.dot(weights, corner_features)
        features.append(f_i)
        
    # Concatenate all features
    F_x = np.concatenate(features, axis=0)
    return F_x
```

**Parameters:**
- Number of volumes: 8 [S1, unofficial].
- Feature dimension: 4 per volume [S1, unofficial].
- Resolutions: $2^3$ to $256^3$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** Coordinates must be clamped or wrapped appropriately when querying near the boundaries of the volumes to avoid out-of-bounds access during trilinear interpolation [G].
- **Memory Usage:** While effective, dense volumes at $256^3$ resolution consume significant memory. This method is often a precursor to sparse variants (see Subtopics) to mitigate this [S1, unofficial].

## Subtopics

### [Sparse High Resolution Volume](20377-sparse-high-resolution-volume.md)
A memory-efficient variant that replaces dense high-resolution feature volumes with a sparse set of valid voxels near the surface. It uses a two-phase optimization strategy: first optimizing a coarse hierarchical structure, then sparsifying the highest-resolution layers based on coarse geometry to reduce memory while maintaining detail.

## Operating characteristics
- **Time Complexity:** Query time is proportional to the number of volumes (8) and the cost of trilinear interpolation. It is generally faster than hash-based methods for dense queries but slower than single-resolution volumes due to the multiple lookups.
- **Memory Complexity:** High. The method uses dense volumes up to $256^3$. The total memory is $\sum_{i=1}^{8} R_i^3 \times 4$ floats. For the specified resolutions, this is substantial, especially for the largest volumes [S1, unofficial].
- **Performance:** The multi-scale approach is preferred over a single large-width volume because low-resolution voxels enforce spatial smoothness, preventing shape crushing and improving surface reconstruction quality [S1, unofficial].
- **Strengths:** Prevents shape crushing; captures multi-scale details; simple to implement with standard trilinear interpolation.
- **Limitations:** High memory consumption for high-resolution dense volumes; less efficient than sparse or hash-based methods for large scenes [S1, unofficial].

## Background
Hierarchical Volume Encoding was introduced in the paper "HIVE: HIerarchical Volume Encoding for Neural Implicit Surface Reconstruction" [S1, unofficial]. It addresses the limitations of single-resolution feature volumes in neural implicit surface reconstruction, specifically the issue of shape crushing, by employing a multi-scale mechanism with 8 feature volumes optimized jointly with MLPs.
