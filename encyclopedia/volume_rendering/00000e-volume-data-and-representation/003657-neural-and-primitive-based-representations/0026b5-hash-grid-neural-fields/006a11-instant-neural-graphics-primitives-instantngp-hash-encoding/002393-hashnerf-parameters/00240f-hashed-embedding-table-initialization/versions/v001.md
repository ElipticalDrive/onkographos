# Hashed Embedding Table Initialization

Also called: HashGrid parameter initialization, Instant-NGP embedding setup

## Overview
This method defines the configuration and initialization of the hashed embedding tables used in HashGrid-based neural fields, specifically within the HashNeRF framework. It solves the problem of mapping continuous 3D coordinates to high-dimensional feature vectors using a multi-resolution hash grid. It is distinguished from standard positional encoding by its use of learnable hash tables with trilinear interpolation, and from dense voxel grids by its sparse, hash-based memory access pattern.

## How it works
The initialization process configures the hyperparameters for the `HashEmbedding` module and sets up the optimizer specifically for these parameters.

**Inputs:**
- Configuration arguments (`args`), specifically `args.i_embed` (embedding type selector) and `embedding_params` (hyperparameter container).
- For the HashGrid variant (Instant-NGP style), specific level counts and resolutions are required.

**Outputs:**
- Initialized `HashEmbedding` module with tensor parameters.
- Optimizer instance configured with specific learning rates and epsilon values for the embedding parameters.

**Data Structures:**
1.  **HashEmbedding Module:**
    -   Contains a list of `nn.Embedding` layers, one per level.
    -   Each embedding layer stores feature vectors of dimension $F$ (typically 2 or 8, depending on the specific implementation variant).
    -   The hash map size is determined by `log2_hashmap_size`.
2.  **Optimizer State:**
    -   Parameters: The weights of the `nn.Embedding` layers.
    -   Hyperparameters: Learning rate, epsilon.

**Steps:**
1.  **Check Embedding Type:** If `args.i_embed == 1`, proceed with Hashed Embedding initialization. Otherwise, use standard NeRF positional encoding or other variants [S1, unofficial].
2.  **Initialize Hash Grid Levels:**
    -   Determine the number of levels $N$.
    -   For each level $i \in [0, N-1]$:
        -   Calculate resolution: $R_i = \lfloor B \cdot b^i \rfloor$, where $B$ is the base resolution and $b$ is the growth rate [S1, unofficial].
        -   Determine the number of hash entries: $H_i = 2^{\text{log2\_hashmap\_size}}$.
        -   Initialize an `nn.Embedding(H_i, F)` layer with random weights (typically uniform or normal distribution, though exact initialization distribution is not specified in the primary source [G]).
3.  **Configure Optimizer for Embeddings:**
    -   Select the optimizer (RAdam for HashNeRF [S1, unofficial], Adam for CNC [S2]).
    -   Set epsilon for embedding parameters: $\epsilon = 10^{-15}$ [S1, unofficial].
    -   Set initial learning rate: $lr = 0.01$ [S2].
4.  **Link to Rendering MLP:**
    -   The output of the hash embedding (concatenated features from all levels) is fed into the rendering MLP.
    -   For HashNeRF, the MLP is `NeRFSmall` with `hidden_dim=64` and `geo_feat_dim=15` [S1, unofficial].
    -   For CNC, the MLP width is 160 [S2].

**Formulas:**
-   Resolution at level $i$:
    $$ R_i = \lfloor B \cdot b^i \rfloor $$
    Where $B$ is the base resolution and $b$ is the growth factor [S1, unofficial].
-   Total feature dimension:
    $$ D_{total} = N \times F $$
    Where $N$ is the number of levels and $F$ is the feature dimension per level [S1, unofficial][S2].

**Parameters:**
-   `args.i_embed`: Integer flag. 1 for Hashed Embedding [S1, unofficial].
-   `base_resolution` ($B$): Not given in the sources for HashNeRF, but implied by the resolution formula [G].
-   `growth_rate` ($b$): Not given in the sources for HashNeRF, but implied by the resolution formula [G].
-   `log2_hashmap_size`: Not given in the sources for HashNeRF [G].
-   `feature_dim` ($F$): 8 for CNC [S2]. For HashNeRF, the embedding dimension is not explicitly stated in the provided notes, but standard Instant-NGP uses 2 [G].

**Edge Cases and Pitfalls:**
-   **Hash Collisions:** Multiple coordinates may hash to the same index. The method relies on the large hash table size to minimize this, but collisions are inherent [G].
-   **Precision:** The use of $\epsilon = 10^{-15}$ for the optimizer suggests sensitivity to numerical precision in the embedding gradients [S1, unofficial].
-   **Boundary Conditions:** The `get_voxel_vertices` function handles points outside the bounding box, returning a `keep_mask` to filter out invalid samples [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn
import torch.optim as optim

def initialize_hashed_embedding(args, embedding_params):
    """
    Initializes the Hashed Embedding table and optimizer based on configuration.
    """
    # Step 1: Check if hashed embedding is selected
    if args.i_embed != 1:
        raise ValueError("Hashed embedding initialization only applies when args.i_embed == 1")

    # Step 2: Initialize Hash Embedding Module
    # Note: Specific values for base_resolution, growth_rate, and log2_hashmap_size
    # are not provided in the sources for HashNeRF. We assume they are in embedding_params.
    n_levels = embedding_params.n_levels
    base_resolution = embedding_params.base_resolution
    growth_rate = embedding_params.growth_rate
    log2_hashmap_size = embedding_params.log2_hashmap_size
    feature_dim = embedding_params.feature_dim # Typically 2 for Instant-NGP, 8 for CNC

    embeddings = nn.ModuleList()
    for i in range(n_levels):
        # Calculate resolution for this level
        resolution = int(torch.floor(base_resolution * (growth_rate ** i)))
        
        # Calculate hash table size
        hash_size = 2 ** log2_hashmap_size
        
        # Initialize embedding layer with random weights
        # [G] Standard initialization is not specified in sources; using default nn.Embedding init
        embed_layer = nn.Embedding(hash_size, feature_dim)
        embeddings.append(embed_layer)

    hash_embed_module = nn.Module()
    hash_embed_module.embeddings = embeddings
    hash_embed_module.n_levels = n_levels
    hash_embed_module.base_resolution = base_resolution
    hash_embed_module.growth_rate = growth_rate
    hash_embed_module.log2_hashmap_size = log2_hashmap_size
    
    # Step 3: Configure Optimizer for Embedding Parameters
    # [S1, unofficial] HashNeRF uses RAdam with eps=1e-15
    # [S2] CNC uses Adam with lr=0.01
    
    optimizer_name = embedding_params.optimizer_name # 'RAdam' or 'Adam'
    
    if optimizer_name == 'RAdam':
        # [S1, unofficial]
        optimizer = optim.RAdam(
            hash_embed_module.parameters(),
            lr=embedding_params.learning_rate, # Not given in sources for HashNeRF [G]
            eps=1e-15
        )
    elif optimizer_name == 'Adam':
        # [S2]
        optimizer = optim.Adam(
            hash_embed_module.parameters(),
            lr=0.01
        )
    else:
        raise ValueError(f"Unsupported optimizer: {optimizer_name}")

    return hash_embed_module, optimizer
```

## Subtopics

### HashGrid Hyperparameter Configuration
This variant refers to the specific hyperparameter settings used in the CNC (Compressed Neural Fields) framework, which extends Instant-NGP. It differs from the base HashNeRF configuration by using 12 levels for 3D embeddings (resolutions 16 to 512) and 4 levels for 2D embeddings (resolutions 128 to 1024) [S2]. It uses a maximum of $2^{19}$ feature vectors per level for 3D and $2^{17}$ for 2D [S2]. The occupancy grid resolution is set to 128, and the rendering MLP width is 160 [S2]. Training uses the Adam optimizer with an initial learning rate of 0.01 for 20,000 iterations on a single NVIDIA RTX 3090 GPU [S2].

## Operating characteristics
-   **Time Complexity:** Lookup is $O(1)$ per level per point, but requires hashing and interpolation. Total time is proportional to $N \times F$ per point [G].
-   **Memory Complexity:** $O(N \times 2^{\text{log2\_hashmap\_size}} \times F)$ [G].
-   **Performance:** Highly efficient for real-time rendering due to sparse memory access [S2].
-   **Strengths:** Scalable to high resolutions with limited memory footprint compared to dense grids.
-   **Limitations:** Hash collisions can degrade quality; requires careful tuning of hash table size and levels.

## Background
The method originates from the HashNeRF project, an unofficial PyTorch implementation of Instant-NGP [S1, unofficial]. It was further adapted and analyzed in the context of NeRF compression, specifically in the CNC framework [S2]. The approach leverages the multi-resolution hash grid encoding introduced by Müller et al. (Instant-NGP) to accelerate neural rendering.
