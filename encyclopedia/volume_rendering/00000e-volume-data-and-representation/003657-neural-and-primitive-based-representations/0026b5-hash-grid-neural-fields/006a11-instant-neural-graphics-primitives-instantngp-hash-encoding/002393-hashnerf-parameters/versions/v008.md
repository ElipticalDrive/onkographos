# HashNeRF Parameters

Also called: HashNeRF Hyperparameters

## Overview
HashNeRF Parameters define the configuration for training Neural Radiance Fields using HashGrid encoding, balancing rendering quality and training speed on consumer hardware. It differs from standard NeRF by using a sparse, multi-resolution hash grid for feature storage [S1, unofficial], and from dense voxel methods by its spatial hashing mechanism [S1, unofficial]. The configuration is heavily influenced by Instant Neural Graphics Primitives (i-NGP) and ZipNeRF, optimizing for fast convergence with limited memory [S2].

## How it works
The method configures the data structures, training loop, and sampling strategy for a HashGrid-based NeRF.

### Inputs and Outputs
**Inputs:**
- Dataset path and type (`dataset_type`: 'llff', 'blender', 'deepvoxels') [S1, unofficial].
- Image resolution settings (e.g., `half_res` for 400x400 vs 800x800) [S1, unofficial].
- Camera pose data (normalized device coordinates or world space) [S1, unofficial].
- Target resolution and scene bounds [S1, unofficial].

**Outputs:**
- Trained neural field model (HashGrid embeddings + MLP) [S1, unofficial].
- Rendered images and videos [S1, unofficial].
- Checkpoint weights [S1, unofficial].

### Data Structures
**HashGrid Pyramid:**
- Consists of $L$ levels (typically 10) [S2].
- Resolutions range from $R_{min}=16$ to $R_{max}=8192$ with a growth factor of 2 [S2].
- Each level has a hashmap of size $H = 2^{19}$ (default) or $2^{21}$ (ZipNeRF/RING-NeRF configuration) [S1, unofficial][S2].
- Feature vector size per entry: 8 dimensions (default in RING-NeRF/ZipNeRF context) or 4 (original HashNeRF) [S1, unofficial][S2].
- Hashmap size per level: $128^3 = 2^{21}$ entries in the referenced baseline configuration [S2].

**Proposal Samplers:**
- Two rounds of sampling using grid-based proposal samplers [S2].
- Samplers use max resolutions of 512 and 2048 [S2].
- Feature size for samplers: 1 (density-only) [S2].
- Architecture: Concatenation model based on i-NGP [S2].

### Numbered Steps
1. **Data Loading:**
   - Load images and poses based on `dataset_type` [S1, unofficial].
   - Apply downsampling factor (`factor`) if specified (e.g., LLFF default 8) [S1, unofficial].
   - If `half_res` is true, resize Blender synthetic data to 400x400 [S1, unofficial].
   - If `white_bkgd` is true, composite alpha channel onto white background [S1, unofficial].
   - If `no_ndc` is true, do not convert to normalized device coordinates [S1, unofficial].
   - If `lindisp` is true, sample linearly in disparity rather than depth [S1, unofficial].
   - If `spherify` is true, recenter poses for spherical 360 scenes [S1, unofficial].
   - Split dataset into train/test using `llffhold` (every $N$-th image, default 8) [S1, unofficial].

2. **Initialization:**
   - Initialize HashGrid pyramid with $L=10$ levels, resolutions $16 \dots 8192$ [S2].
   - Initialize hashmap size $H=2^{19}$ (default) or $2^{21}$ [S1, unofficial][S2].
   - Initialize MLP weights [S1, unofficial].
   - Set `raw_noise_std` to $1.0$ to regularize sigma output [S1, unofficial].

3. **Training Loop (25k iterations):** [S2]
   - **Batching:** Sample $2^{16}$ rays per batch [S2].
   - **Proposal Sampling:**
     - Perform 2 rounds of sampling using proposal samplers with max resolutions 512 and 2048 [S2].
     - Use features of size 1 for density estimation [S2].
   - **Forward Pass:**
     - Encode sampled points using HashGrid encoding [S1, unofficial].
     - Pass through MLP to predict color and density [S1, unofficial].
     - Add noise to density with std `raw_noise_std` [S1, unofficial].
     - Render pixel color via volume rendering [S1, unofficial].
   - **Loss Calculation:**
     - Compute MSE loss between rendered and ground truth images [S1, unofficial].
     - Apply TV loss with weight `tv-loss-weight` ($10^{-6}$) [S1, unofficial].
     - Apply sparse loss with weight `sparse-loss-weight` ($10^{-10}$) [S1, unofficial].
     - Apply distortion loss (as implemented in NerfStudio) [S2].
   - **Optimization:**
     - Use RAdam optimizer with initial learning rate $10^{-2}$ [S2].
     - Apply cosine decay scheduler to final learning rate $10^{-3}$ [S2].
   - **Logging/Saving:**
     - Print metrics every `i_print` steps (default 100) [S1, unofficial].
     - Log images to TensorBoard every `i_img` steps (default 500) [S1, unofficial].
     - Save weights every `i_weights` steps (default 10000) [S1, unofficial].
     - Save testset renders every `i_testset` steps (default 1000) [S1, unofficial].
     - Save video renders every `i_video` steps (default 5000) [S1, unofficial].

4. **Pre-cropping (Optional):**
   - If `precrop_iters > 0`, train on central crops of fraction `precrop_frac` (default 0.5) for the first `precrop_iters` steps [S1, unofficial].

### Formulas
- **Hash Function:** $h(k) = k \mod H$, where $k$ is the hashed coordinate and $H$ is hashmap size [S1, unofficial].
- **Trilinear Interpolation:** Features are interpolated from the 8 neighboring grid cells in the active resolution level [S1, unofficial].
- **Volume Rendering:** $C(r) = \sum_{i=1}^N T_i (1 - \exp(-\sigma_i \delta_i)) c_i$, where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ [S1, unofficial].
- **Learning Rate Schedule:** $\eta(t) = \eta_{min} + \frac{1}{2}(\eta_{max} - \eta_{min})(1 + \cos(\frac{t}{T}\pi))$ [S2].

### Edge Cases and Pitfalls
- **Precision:** Hash collisions may occur if hashmap size is too small for the resolution [S1, unofficial].
- **Boundaries:** Scene contraction is used to handle unbounded scenes [S2].
- **Degenerate Input:** Mismatch between image count and pose count causes failure [S1, unofficial].
- **Memory:** Large hashmap sizes ($2^{21}$) require significant GPU memory [S2].

### Pseudocode
```python
def train_hashnerf(config):
    # 1. Data Loading
    dataset = load_dataset(config.dataset_type, config.factor, config.half_res)
    train_loader, test_loader = split_dataset(dataset, config.llffhold)
    
    # 2. Initialization
    hash_grid = HashGridPyramid(
        levels=10,
        resolutions=generate_resolutions(16, 8192, factor=2),
        hashmap_size=2**config.log2_hashmap_size,
        feature_size=8
    )
    mlp = MLP()
    optimizer = RAdam(
        params=list(hash_grid.parameters()) + list(mlp.parameters()),
        lr=1e-2
    )
    scheduler = CosineDecayScheduler(optimizer, max_lr=1e-2, min_lr=1e-3, total_iters=25000)
    
    # 3. Training Loop
    for step in range(25000):
        rays = sample_rays(train_loader, batch_size=2**16)
        
        # Proposal Sampling
        proposal_points = proposal_sampler_sample(
            rays, 
            hash_grid, 
            max_resolutions=[512, 2048], 
            feature_size=1
        )
        
        # Forward Pass
        features = hash_grid.encode(proposal_points)
        color, density = mlp(features)
        density += noise(std=config.raw_noise_std)
        
        # Rendering
        rendered_color = volume_render(rays, density, color)
        target_color = rays.target
        
        # Loss Calculation
        mse_loss = mse(rendered_color, target_color)
        tv_loss = total_variation(hash_grid)
        sparse_loss = sparsity_loss(hash_grid)
        distortion_loss = compute_distortion_loss(density, rays)
        
        total_loss = (mse_loss + 
                      config.tv_loss_weight * tv_loss + 
                      config.sparse_loss_weight * sparse_loss + 
                      distortion_loss)
        
        # Optimization
        optimizer.zero_grad()
        total_loss.backward()
        optimizer.step()
        scheduler.step()
        
        # Logging
        if step % config.i_print == 0:
            log_metrics(step, total_loss)
        if step % config.i_img == 0:
            log_image(step, rendered_color)
        if step % config.i_weights == 0:
            save_checkpoint(step, hash_grid, mlp)
        if step % config.i_testset == 0:
            save_testset(step, test_loader, hash_grid, mlp)
        if step % config.i_video == 0:
            save_video(step, render_poses, hash_grid, mlp)
```

## Subtopics

### [Hashed Embedding Table Initialization](3188-hashed-embedding-table-initialization.md)
Defines the configuration and initialization of the hashed embedding tables used in HashGrid-based neural fields, specifically within the HashNeRF framework. It is distinguished from standard positional encoding by its use of learnable hash tables with trilinear interpolation, and from dense voxel grids by its sparse, hash-based memory access pattern.

## Operating characteristics
- **Time Complexity:** Training is fast due to efficient hash lookups and trilinear interpolation. 25k iterations are typically sufficient [S2].
- **Memory Complexity:** Memory usage is proportional to the hashmap size and feature dimensions. $2^{21}$ entries with 8 features per entry require significant VRAM [S2].
- **Measured Performance:** Achieves high quality on consumer GPUs with 25k iterations and $2^{16}$ rays per batch [S2].
- **Scaling:** Scales well with resolution increases by adjusting the finest resolution and hashmap size [S1, unofficial].
- **Strengths:** Fast training, low memory footprint compared to dense grids, high quality [S1, unofficial][S2].
- **Limitations:** Hash collisions can degrade quality if hashmap size is insufficient [S1, unofficial].
- **When to Use:** When fast training and rendering are required on consumer hardware [S1, unofficial].
- **When Not to Use:** When absolute highest quality is required and memory is not a constraint [S2].

## Background
HashNeRF was introduced by Müller et al. in "Instant Neural Graphics Primitives with a Hash Encoding" [S1, unofficial]. It was developed to enable real-time training and rendering of NeRFs on consumer GPUs. The method uses spatial hashing to map 3D coordinates to a sparse feature grid, allowing for efficient memory access and fast training [S1, unofficial]. It has been widely adopted and extended in subsequent works such as ZipNeRF and RING-NeRF [S2].
