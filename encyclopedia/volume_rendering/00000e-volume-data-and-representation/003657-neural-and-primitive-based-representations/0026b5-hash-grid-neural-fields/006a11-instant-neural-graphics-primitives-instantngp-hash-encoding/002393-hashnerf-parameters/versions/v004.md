# HashNeRF Parameters

Also called: HashNeRF Hyperparameters

## Overview
HashNeRF parameters define the configuration for training Neural Radiance Fields using the Instant Neural Graphics Primitives (iNGP) hash-based encoding [S1, unofficial][S2]. This method solves the trade-off between training speed and reconstruction fidelity by replacing expensive positional encoding with a learnable, sparse hash grid [S1, unofficial]. It differs from standard NeRF by using a multi-resolution hash grid pyramid for input encoding, allowing for significantly faster convergence and rendering [S2].

## How it works
The method configures the training loop, optimizer, and model architecture for HashNeRF.

**Inputs and Outputs:**
*   **Inputs:** Dataset images, camera poses, and configuration parameters (listed below).
*   **Outputs:** Trained hash embeddings, MLP weights, and rendered images/depth maps.

**Data Structures:**
*   **Hash Grid Pyramid:** A list of $L$ hash tables. Each table $i$ has a resolution $R_i$ and a hashmap size $H$.
    *   Resolution $R_i$: The side length of the voxel grid at level $i$.
    *   Hashmap Size $H$: The number of entries in the hash table, mapped via a hash function to indices in the embedding vector.
*   **Embedding Parameters:** A tensor storing the feature vectors for each hash entry.

**Parameters and Typical Values:**
*   **Grid Pyramid:** 10 grids with a growth factor of $b=2$ [S2]. Resolutions range from $16$ to $8192$ [S2].
*   **Finest Resolution ($finest\_res$):** Default $512$ [S1, unofficial].
*   **Hashmap Size ($log2\_hashmap\_size$):** Default $19$ (size $2^{19}$) [S1, unofficial]. In RING-NeRF, a size of $128^3 = 2^{21}$ is used per level [S2].
*   **Feature Dimension:** 8 features per level in RING-NeRF [S2]. Standard HashNeRF uses configurable dimensions, often defaulting to small hidden sizes (e.g., hidden_dim=64, geo_feat_dim=15) when using hashed embeddings [S1, unofficial].
*   **Optimizer:** RAdam [S1, unofficial][S2].
    *   Initial Learning Rate: $1e-2$ [S2].
    *   Scheduler: Cosine decay to $1e-3$ [S2].
    *   Embedding Specific Epsilon: $1e-15$ [S1, unofficial].
*   **Training Iterations:** 25,000 [S2].
*   **Batch Size:** $2^{16}$ rays [S2].
*   **Regularization:**
    *   `raw_noise_std`: Standard deviation of noise added to $\sigma$ output, recommended $1e0$ [S1, unofficial].
    *   `tv-loss-weight`: Total Variation loss weight, default $1e-6$ [S1, unofficial].
    *   `sparse-loss-weight`: Sparse loss weight, default $1e-10$ [S1, unofficial].
*   **Rendering:**
    *   `render_factor`: Downsampling factor for preview, set to 4 or 8 [S1, unofficial].
    *   `precrop_iters`: Steps to train on central crops, default 0 [S1, unofficial].
    *   `precrop_frac`: Fraction of image for central crops, default 0.5 [S1, unofficial].
*   **Dataset Specifics:**
    *   `dataset_type`: 'llff', 'blender', or 'deepvoxels' [S1, unofficial].
    *   `testskip`: Load 1/N images for test/val, default 8 [S1, unofficial].
    *   `llffhold`: Every N-th image for LLFF test set, default 8 [S1, unofficial].
    *   `factor`: LLFF downsample factor, default 8 [S1, unofficial].
    *   `half_res`: Load Blender data at 400x400 instead of 800x800 [S1, unofficial].
    *   `white_bkgd`: Render synthetic data on white background [S1, unofficial].
    *   `no_ndc`: Disable Normalized Device Coordinates for non-forward facing scenes [S1, unofficial].
    *   `lindisp`: Sample linearly in disparity [S1, unofficial].
    *   `spherify`: Enable for spherical 360 scenes [S1, unofficial].
*   **Logging:**
    *   `i_print`: Console print frequency, default 100 [S1, unofficial].
    *   `i_img`: Tensorboard image logging frequency, default 500 [S1, unofficial].
    *   `i_weights`: Checkpoint saving frequency, default 10,000 [S1, unofficial].
    *   `i_testset`: Testset saving frequency, default 1,000 [S1, unofficial].
    *   `i_video`: Video rendering frequency, default 5,000 [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Initialize the hash grid pyramid with $L=10$ levels, growth factor $b=2$, and base resolution $R_0=16$ [S2]. Initialize hashmaps with size $H=2^{19}$ (or $2^{21}$ for RING-NeRF) [S1, unofficial][S2]. Initialize MLP weights.
2.  **Sampling:** For each batch of $2^{16}$ rays [S2]:
    *   If using proposal samplers (as in RING-NeRF), perform 2 rounds of sampling using grid-based proposal samplers (hashgrid pyramid + linear layer) with max resolutions 512 and 2048, using feature size 1 [S2].
    *   Perform one final forward pass into the true model [S2].
3.  **Forward Pass:**
    *   For each 3D point $\mathbf{x}$ along the ray:
        *   For each level $i$ in the hash grid:
            *   Compute resolution $R_i = \lfloor R_0 \cdot b^i \rfloor$ [S1, unofficial].
            *   Determine voxel vertices and hashed indices [S1, unofficial].
            *   Lookup embeddings from the hash table [S1, unofficial].
            *   Perform trilinear interpolation to get level-specific features [S1, unofficial].
        *   Concatenate features from all levels [S1, unofficial].
        *   Pass concatenated features through the MLP to predict density $\sigma$ and color $\mathbf{c}$ [S1, unofficial].
    *   Apply raw noise to $\sigma$ with std `raw_noise_std` [S1, unofficial].
    *   Render the ray using volume rendering integration [S1, unofficial].
4.  **Loss Calculation:**
    *   Compute photometric loss between rendered and ground truth colors [S1, unofficial].
    *   Compute TV loss with weight `tv-loss-weight` [S1, unofficial].
    *   Compute sparse loss with weight `sparse-loss-weight` [S1, unofficial] (if applicable).
    *   Compute distortion loss (as implemented in NerfStudio) [S2].
5.  **Optimization:**
    *   Update parameters using RAdam optimizer [S1, unofficial][S2].
    *   Apply cosine decay to learning rate from $1e-2$ to $1e-3$ over 25,000 iterations [S2].
    *   Use specific epsilon ($1e-15$) for embedding parameters if `i_embed==1` [S1, unofficial].
6.  **Logging and Saving:**
    *   Log metrics every `i_print` steps [S1, unofficial].
    *   Save images every `i_img` steps [S1, unofficial].
    *   Save weights every `i_weights` steps [S1, unofficial].
    *   Save testset renders every `i_testset` steps [S1, unofficial].
    *   Save video renders every `i_video` steps [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** With finite hashmap size, collisions occur. Larger hashmap sizes reduce this but increase memory [S1, unofficial][S2].
*   **Precision:** Use specific epsilon for embedding optimizer to handle sparse updates [S1, unofficial].
*   **Scene Type:** Use `no_ndc` for non-forward facing scenes to avoid coordinate normalization issues [S1, unofficial]. Use `spherify` for 360 scenes [S1, unofficial].

## Subtopics

### Hashed Embedding Table Initialization
When `args.i_embed==1`, the model uses a hashed embedding table stored in `embedding_params` [S1, unofficial]. The optimizer uses RAdam with a specific epsilon of $1e-15$ for these parameters [S1, unofficial]. If `args.i_embed==1`, the model uses `NeRFSmall` with fixed dimensions (hidden_dim=64, geo_feat_dim=15); otherwise, it uses the standard `NeRF` model with configurable depth/width [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Training is significantly faster than standard NeRF due to the efficient hash-based lookup and smaller MLP size [S1, unofficial][S2].
*   **Memory Complexity:** Memory usage is determined by the hash grid size and MLP parameters. The hash grid size is $L \times H \times D$, where $L$ is the number of levels, $H$ is the hashmap size, and $D$ is the feature dimension [S1, unofficial][S2].
*   **Performance:** Trained for 25k iterations with a batch size of $2^{16}$ rays [S2].
*   **Strengths:** Fast training and rendering, good reconstruction quality for many scenes [S1, unofficial][S2].
*   **Limitations:** Hash collisions can affect quality; memory usage scales with hashmap size [S1, unofficial][S2].
*   **When to Use:** When fast training and rendering are prioritized over absolute highest fidelity [S1, unofficial][S2].
*   **When Not to Use:** When memory is extremely constrained and hashmap size cannot be reduced, or when highest possible fidelity is required and slower methods are acceptable [S1, unofficial][S2].

## Background
HashNeRF parameters are derived from the Instant Neural Graphics Primitives (iNGP) method, which introduced hash-based encoding for neural radiance fields [S1, unofficial]. The specific configuration details are documented in the unofficial HashNeRF-pytorch repository [S1, unofficial] and the RING-NeRF paper, which adapts these parameters for versatile neural fields [S2].
