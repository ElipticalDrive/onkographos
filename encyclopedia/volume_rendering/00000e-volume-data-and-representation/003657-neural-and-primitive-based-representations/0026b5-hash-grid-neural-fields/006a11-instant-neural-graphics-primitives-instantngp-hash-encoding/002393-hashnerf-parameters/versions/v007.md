# HashNeRF Parameters

Also called: HashNeRF Hyperparameters

## Overview
HashNeRF Parameters define the configuration for training Neural Radiance Fields using HashGrid Encoding, specifically targeting the implementation found in the `HashNeRF-pytorch` repository [S1, unofficial]. This method solves the problem of efficient spatial feature storage and interpolation for neural rendering by mapping 3D coordinates to a multi-resolution hash grid [Parent]. It sets itself apart from standard NeRF by using a learnable hash table with trilinear interpolation, allowing for significantly faster training and inference on consumer hardware compared to dense MLP-based coordinate representations [Parent].

## How it works
The method configures the data structures, optimization, and rendering pipeline for a HashGrid-based NeRF.

### Inputs and Outputs
*   **Inputs**: Camera poses, intrinsics, and images from a dataset (LLFF, Blender, DeepVoxels, or ScanNet); training iterations; batch size.
*   **Outputs**: Rendered images, PSNR/SSIM/LPIPS metrics, and model checkpoints.

### Data Structures
1.  **HashGrid Pyramid**: A list of `n_levels` hash tables.
    *   **Resolution**: For level $i$, resolution $R_i = \lfloor \text{base\_resolution} \times b^i \rfloor$.
    *   **Hashmap Size**: $2^{\text{log2\_hashmap\_size}}$ entries per level.
    *   **Embedding Dimension**: Fixed per level (typically 2 or 4 in the base implementation, though RING-NeRF uses 8 [S2]).
2.  **Neural Network**:
    *   **HashNeRF Variant**: Uses `NeRFSmall` with `hidden_dim=64` and `geo_feat_dim=15` [S1, unofficial].
    *   **Standard NeRF Variant**: Uses configurable depth/width if `args.i_embed != 1` [S1, unofficial].
3.  **Optimizer State**:
    *   Embedding parameters use `RAdam` with `eps=1e-15` [S1, unofficial].
    *   Other parameters use `RAdam` with `eps=1e-8` (standard) or as configured [S2].

### Parameters and Typical Values
*   `finest_res`: Finest resolution for hashed embedding. Default: 512 [S1, unofficial].
*   `log2_hashmap_size`: Log2 of hashmap size. Default: 19 [S1, unofficial].
*   `raw_noise_std`: Standard deviation of noise added to the output sigma (density) to regularize. Recommended: $1.0$ [S1, unofficial].
*   `tv_loss_weight`: Weight for Total Variation loss on the hash grid. Default: $10^{-6}$ [S1, unofficial].
*   `sparse_loss_weight`: Weight for sparse loss. Default: $10^{-10}$ [S1, unofficial].
*   `render_factor`: Downsampling factor for rendering. Set to 4 or 8 for fast preview [S1, unofficial].
*   `precrop_iters`: Number of steps to train on central crops. Default: 0 [S1, unofficial].
*   `precrop_frac`: Fraction of image taken for central crops. Default: 0.5 [S1, unofficial].
*   `dataset_type`: Options: `llff`, `blender`, `deepvoxels`. Default: `llff` [S1, unofficial].
*   `shape`: For synthetic datasets, options: `armchair`, `cube`, `greek`, `vase`. Default: `greek` [S1, unofficial].
*   `white_bkgd`: Boolean. Render synthetic data on a white background [S1, unofficial].
*   `half_res`: Boolean. Load Blender synthetic data at 400x400 instead of 800x800 [S1, unofficial].
*   `scannet_sceneID`: Scene ID for ScanNet. Default: `scene0000_00` [S1, unofficial].
*   `factor`: Downsample factor for LLFF images. Default: 8 [S1, unofficial].
*   `no_ndc`: Boolean. Do not use Normalized Device Coordinates (set for non-forward facing scenes) [S1, unofficial].
*   `lindisp`: Boolean. Sample linearly in disparity rather than depth [S1, unofficial].
*   `spherify`: Boolean. Set for spherical 360 scenes [S1, unofficial].
*   `llffhold`: Take every 1/N images as LLFF test set. Default: 8 [S1, unofficial].
*   `testskip`: Load 1/N images from test/val sets. Default: 8 [S1, unofficial].
*   `i_print`: Frequency of console printout and metric logging. Default: 100 [S1, unofficial].
*   `i_img`: Frequency of TensorBoard image logging. Default: 500 [S1, unofficial].
*   `i_weights`: Frequency of weight checkpoint saving. Default: 10000 [S1, unofficial].
*   `i_testset`: Frequency of testset saving. Default: 1000 [S1, unofficial].
*   `i_video`: Frequency of render_poses video saving. Default: 5000 [S1, unofficial].

### Training Configuration (from RING-NeRF/ZipNeRF context)
*   **Iterations**: 25,000 [S2].
*   **Batch Size**: $2^{16}$ rays [S2].
*   **Optimizer**: RAdam, initial LR $10^{-2}$, cosine decay to $10^{-3}$ [S2].
*   **Grid Pyramid**: 10 grids, growth factor 2, resolutions 16 to 8192 [S2].
*   **Hashmap Size**: $128^3 = 2^{21}$ per level [S2].
*   **Features**: 8 features per level [S2].
*   **Proposal Samplers**: 2 rounds of sampling via 2 different grid-based proposal samplers (hashgrid pyramid + one linear layer), followed by one last forward process [S2].
    *   Sampler 1 max resolution: 512.
    *   Sampler 2 max resolution: 2048.
    *   Sampler feature size: 1 [S2].
    *   Architecture: I-NGP-based concatenation model [S2].
*   **Loss**: Distortion loss (as implemented in NerfStudio) [S2].
*   **Excluded**: Appearance embedding, novel interlevel loss, scale featurization, weight decay loss, Affine Generative Latent Optimization [S2].

### Edge Cases and Pitfalls
*   **Precision**: Hash collisions can occur if the hashmap size is too small for the number of active voxels. The `log2_hashmap_size` parameter controls this trade-off between memory and collision rate [S1, unofficial].
*   **Boundaries**: Points outside the bounding box should be handled, either by clamping or by using a `keep_mask` to ignore them [S1, unofficial].
*   **Degenerate Input**: If `finest_res` is too high, memory usage may exceed GPU limits. If `log2_hashmap_size` is too low, performance may degrade due to collisions [S1, unofficial].

## Subtopics

### Hashed Embedding Table Initialization
When `args.i_embed==1`, the embedding function uses a hashed embedding table, and its parameters are stored in `embedding_params`. The optimizer uses RAdam with a specific epsilon for embedding parameters: `eps: 1e-15` [S1, unofficial]. If `args.i_embed==1` (hashed), the model uses `NeRFSmall` with fixed dimensions (`hidden_dim=64`, `geo_feat_dim=15`); otherwise, it uses the standard `NeRF` model with configurable depth/width [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Training time is significantly reduced compared to dense NeRF due to the efficient hash table lookups and sparse updates. The number of iterations is typically 25k [S2].
*   **Memory Complexity**: Memory usage is proportional to the number of active voxels and the hashmap size. The hashmap size is $2^{\text{log2\_hashmap\_size}}$ per level [S1, unofficial].
*   **Measured Performance**: Trained on consumer GPUs with a batch size of $2^{16}$ rays [S2].
*   **Strengths**: Fast training, low memory footprint, high-quality renderings.
*   **Limitations**: Hash collisions can affect quality. Performance depends on the choice of `log2_hashmap_size` and `finest_res` [S1, unofficial].
*   **When to Use**: When training speed and memory efficiency are critical, and high-quality novel view synthesis is required.
*   **When Not to Use**: When exact spatial locality is more important than hash-based approximation, or when memory is extremely constrained and hash collisions are unacceptable.

## Background
HashNeRF parameters are derived from the HashNeRF-pytorch repository, an unofficial implementation of HashGrid-based NeRF [S1, unofficial]. The underlying HashGrid Encoding method was introduced in the paper "Instant Neural Graphics Primitives with a Multiresolution Hash Encoding" by Müller et al. (2022) [Parent]. The specific parameters and configurations described here are also influenced by RING-NeRF and ZipNeRF, which use similar hash grid pyramids and proposal samplers [S2].
