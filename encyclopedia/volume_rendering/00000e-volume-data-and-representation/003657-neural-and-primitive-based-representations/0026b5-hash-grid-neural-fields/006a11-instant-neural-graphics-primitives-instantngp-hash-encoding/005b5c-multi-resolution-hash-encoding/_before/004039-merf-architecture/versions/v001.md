# MERF Architecture

Also called: Memory-Efficient Radiance Fields

## Overview
MERF is a neural radiance field architecture designed for real-time view synthesis in unbounded scenes [S1]. It builds on [Standard Multi-resolution Hash Encoding](13152-standard-multi-resolution-hash-encoding.md) to parameterize 3D voxel grids and 2D planes, solving the memory bottleneck of dense 3D storage while maintaining high rendering quality [S1]. It distinguishes itself from [HashNeRF](8678-hashnerf.md) by employing a deferred view-dependency model and hierarchical sampling to achieve interactive frame rates on mobile hardware [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D spatial coordinates $\mathbf{x}$ and viewing direction $\mathbf{v}$.
*   **Output:** Density $\sigma$, diffuse RGB color $\mathbf{c}_{diff}$, and a 4-dimensional view-dependent feature vector $\mathbf{f}_{view}$ [S1].

**Data Structures:**
*   **Hash Grids:** A set of multi-resolution hash tables. The main encoding uses 20 levels, with each individual hash table containing $2^{21}$ entries [S1].
*   **Proposal Grids:** A separate set of hash tables for hierarchical sampling, using 10 levels, a maximum grid resolution of 512, and hash table sizes of $2^{16}$ [S1].
*   **MLPs:**
    *   **Main MLP:** A 2-layer MLP with 64 hidden units used to resolve hash collisions [S1].
    *   **Deferred View-Dependence MLP:** A 3-layer MLP with 16 hidden units [S1].
    *   **Proposal-MLPs:** Two 2-layer MLPs with 64 hidden units, each using hash encoding [S1].

**Steps:**

1.  **Hash Encoding:** The input coordinate $\mathbf{x}$ is encoded using the main multi-resolution hash encoding [S1]. This involves scaling $\mathbf{x}$ by $2^l$ for each level $l \in \{0, \dots, 19\}$, hashing the voxel indices to table entries, and interpolating the features [S1, Parent].
2.  **Collision Resolution:** The concatenated features from all 20 levels are passed through the Main MLP (2 layers, 64 hidden units) [S1]. This MLP outputs an 8-dimensional vector: density $\sigma$, diffuse RGB $\mathbf{c}_{diff}$, and the view-dependent feature vector $\mathbf{f}_{view} \in \mathbb{R}^4$ [S1].
3.  **View Direction Encoding:** The viewing direction $\mathbf{v}$ is encoded using 4 spherical harmonics frequencies [S1].
4.  **Deferred View-Dependence:** The view-dependent color is computed by passing the encoded view direction and the feature vector $\mathbf{f}_{view}$ through the Deferred View-Dependence MLP (3 layers, 16 hidden units) [S1]. This follows the SNeRG approach [Hedman et al. 2021].
5.  **Hierarchical Sampling:** To improve geometry modeling, hierarchical sampling is used with three levels [S1]. This requires two Proposal-MLPs [S1].
    *   **Proposal-MLP Encoding:** Each Proposal-MLP uses a hash encoding with 10 levels, max resolution 512, and table size $2^{16}$ [S1].
    *   **Proposal-MLP Structure:** Each Proposal-MLP consists of 2 layers with 64 hidden units [S1].
    *   These MLPs model coarse geometry to guide the sampling of the main radiance field [S1].

**Parameters:**
*   **Main Hash Encoding:** 20 levels, $2^{21}$ entries per table [S1].
*   **Proposal Hash Encoding:** 10 levels, max resolution 512, $2^{16}$ entries per table [S1].
*   **View Direction Encoding:** 4 frequencies [S1].
*   **Regularization:** Weight decay of 0.1 on grid values [S1].
*   **Optimizer:** Adam with $\beta_1=0.9, \beta_2=0.99, \epsilon=10^{-15}$ [S1].

**Pseudocode:**

    v: View direction (3,)

    main_mlp_output = apply_mlp(main_features, main_mlp_weights)
    sigma = main_mlp_output[0]

    f_view = main_mlp_output[4:8]

def hash_encode(x, hash_tables, table_sizes, feature_dim):
    """
    Standard multi-resolution hash encoding.
    """
    L = len(hash_tables)
    concatenated_features = []
    
    for l in range(L):
        scale = 2 ** l
        scaled_x = [x[i] * scale for i in range(3)]
        
        voxel_indices = [math.floor(scaled_x[i]) for i in range(3)]
        frac = [scaled_x[i] - voxel_indices[i] for i in range(3)]
        
        weights = []
        for i in range(8):
            w = 1.0
            for d in range(3):
                bit = (i >> d) & 1
                w *= frac[d] if bit else (1.0 - frac[d])
            weights.append(w)
            
        interpolated_feat = [0.0] * feature_dim
        for i in range(8):
            neighbor_idx = [voxel_indices[d] + ((i >> d) & 1) for d in range(3)]
            h_idx = sum(neighbor_idx) % table_sizes[l]
            feat = hash_tables[l][h_idx]
            for j in range(feature_dim):
                interpolated_feat[j] += weights[i] * feat[j]
                
        concatenated_features.append(interpolated_feat)
        
    result = []
    for feat in concatenated_features:
        result.extend(feat)
    return result

def encode_view_direction(v, freqs):
    """
    Encodes view direction with specified frequencies.
    """
    # Standard spherical harmonics or positional encoding
    # Source says "4 frequencies"
    # Assuming standard positional encoding: sin(2^i * pi * v)
    encoded = []
    for f in freqs:
        encoded.append(math.sin(2**f * math.pi * v[0]))
        encoded.append(math.sin(2**f * math.pi * v[1]))
        encoded.append(math.sin(2**f * math.pi * v[2]))
    return encoded

def apply_mlp(x, weights):
    """
    Applies a simple MLP.
    weights: List of [W1, b1, W2, b2] for 2-layer MLP
    """
    # Layer 1
    h1 = [sum(x[j] * weights[0][i][j] for j in range(len(x))) + weights[1][i] for i in range(len(weights[1]))]
    h1 = [max(0, h) for h in h1] # ReLU
    
    # Layer 2
    out = [sum(h1[j] * weights[2][i][j] for j in range(len(h1))) + weights[3][i] for i in range(len(weights[3]))]
    return out

def apply_deferred_mlp(v_enc, f_view, weights):
    """
    Applies the 3-layer, 16-hidden MLP for deferred view dependence.
    """
    # Input: v_enc (12 dims for 4 freqs) + f_view (4 dims) = 16 dims
    x = v_enc + f_view
    
    # Layer 1
    h1 = [sum(x[j] * weights[0][i][j] for j in range(len(x))) + weights[1][i] for i in range(16)]
    h1 = [max(0, h) for h in h1]
    
    # Layer 2
    h2 = [sum(h1[j] * weights[2][i][j] for j in range(16)) + weights[3][i] for i in range(16)]
    h2 = [max(0, h) for h in h2]
    
    # Layer 3
    out = [sum(h2[j] * weights[4][i][j] for j in range(16)) + weights[5][i] for i in range(3)]
    return out

## Subtopics

### [Hashed 3D Representations](16815-hashed-3d-representations.md)
Hashed 3D Representations are a family of neural 3D field parameterizations that decompose a field $f$ into a hashing scheme $h$ and a small MLP $g$, such that $f = g \circ h$. They solve the memory bottleneck inherent in dense 3D storage by using sparse or structured hash-like access patterns (e.g., voxel grids, triplanes) to sample features efficiently, enabling fast, memory-efficient training and rendering. What sets them apart from dense voxel-based methods is the decoupling of spatial indexing from the neural network, allowing the use of compact structures like triplanes where cells lack explicit 3D coordinates, and from pure neural fields by providing a differentiable, interpolation-based sampling mechanism.

## Operating characteristics
*   **Performance:** MERF achieves real-time view synthesis, with frame rates of 30fps or better on mobile devices [S1]. This is significantly faster than Instant-NGP (~5fps) and MipNeRF360 (~30 seconds per frame) [S1].
*   **Memory:** By using hash encoding with $2^{21}$ entries per level for 20 levels, MERF is memory-efficient compared to dense voxel grids [S1]. The use of 2D planes in addition to 3D voxels further optimizes memory for unbounded scenes [S1].
*   **Quality:** MERF provides state-of-the-art view synthesis quality for real-time applications, comparable to offline methods like MipNeRF360 [S1]. Omitting the low-resolution 3D voxel grid can result in poor reconstruction of background parts [S1].
*   **Limitations:** The method relies on hierarchical sampling and multiple MLPs, which can increase training complexity. The deferred view-dependency model may not capture all view-dependent effects as accurately as fully integrated models, but it offers a good trade-off for real-time performance [S1].

## Background
MERF (Memory-Efficient Radiance Fields) was introduced to enable real-time view synthesis in unbounded scenes [S1]. It builds on the Instant-NGP architecture [Müller et al. 2022] by incorporating deferred view-dependency (following SNeRG [Hedman et al. 2021]) and hierarchical sampling (following MipNeRF360 [Barron et al. 2022]) to optimize for mobile hardware [S1]. The architecture was benchmarked against other real-time methods like Mobile-NeRF [Chen et al. 2022a] and offline methods like MipNeRF360 [S1].
