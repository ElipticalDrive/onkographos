# HashNeRF

Also called: Instant Neural Graphics Primitives, Instant Neural Graphics Primitives with a Multiresolution Hash Encoding

## Overview
HashNeRF is a method for accelerating the training and inference of Neural Radiance Fields (NeRF) by replacing traditional positional encoding with a trainable multiresolution hash encoding [S1, unofficial]. It maps 3D coordinates to a higher-dimensional feature space using multiple hash tables, which are then processed by a shallow neural network to predict density and color [S1, unofficial]. It sets itself apart from standard NeRF implementations by enabling significantly faster convergence and lower training times due to the generic, trainable nature of the encoding and the shallow network architecture [S1, unofficial].

## How it works
HashNeRF consists of two main stages: input encoding and a shallow neural network decoder [S1, unofficial]. The encoding stage builds upon the Standard Multi-resolution Hash Encoding [13152-standard-multi-resolution-hash-encoding.md] to produce a concatenated feature vector. The decoder stage processes this vector to output scene properties.

**Inputs and Outputs:**
*   **Input:** A 3D spatial coordinate $\mathbf{x} = (x, y, z)$ and a 3D viewing direction $\mathbf{d} = (d_x, d_y, d_z)$.
*   **Output:** Volume density $\sigma$ and view-dependent color $\mathbf{c}$.

**Data Structures:**
*   **Hash Tables:** A set of $L$ hash tables, one for each resolution level $l \in \{0, \dots, L-1\}$. Each table $l$ has a fixed size $T_l$ (number of entries) [S2].
*   **Feature Vectors:** Each entry in the hash tables stores a feature vector of dimension $F$ [G]. These features are typically initialized randomly or with small values [G].
*   **MLP Weights:** The shallow neural network consists of fully connected layers. It is divided into a Density MLP (outputting log-space density) and a Color MLP (adding color variation information) [S1, unofficial].

**Parameters:**
*   $L$: Number of resolution levels.
*   $T_l$: Size of the hash table at level $l$.
*   $F$: Dimensionality of the feature vectors.
*   $H$: Hash function mapping coordinates to table indices.
*   $\alpha$: Interpolation factor (derived from the coordinate's position within the voxel).

**Steps:**

1.  **Coordinate Hashing:** For each resolution level $l$, the input coordinate $\mathbf{x}$ is scaled by $2^l$ and mapped to a voxel grid [S2]. The hash function $H_l(\mathbf{x})$ computes the table index by taking the modulo of the table size $T_l$ [G].
2.  **Feature Fetching:** Retrieve the feature vector $\mathbf{f}_l$ from the hash table at index $i_l$ [G].
3.  **Interpolation:** To ensure smoothness, features from neighboring voxels are interpolated [G]. For a coordinate $\mathbf{x}$, let $\mathbf{x}_l$ be the scaled coordinate at level $l$. The fractional part $\mathbf{u}_l = \mathbf{x}_l - \lfloor \mathbf{x}_l \rfloor$ determines the interpolation weights [G]. The interpolated feature $\hat{\mathbf{f}}_l$ is computed by trilinearly interpolating the 8 surrounding feature vectors in the hash grid [G].
4.  **Feature Concatenation:** Concatenate the interpolated features from all levels: $\mathbf{F} = [\hat{\mathbf{f}}_0; \hat{\mathbf{f}}_1; \dots; \hat{\mathbf{f}}_{L-1}]$ [G].
5.  **Density Prediction:** The concatenated feature vector $\mathbf{F}$ is passed through the Density MLP. The output is the log-space density $\sigma$ [S1, unofficial].
6.  **Directional Encoding:** The viewing direction $\mathbf{d}$ is typically encoded using standard positional encoding or a separate small hash grid (implementation detail not fully specified in [S1, unofficial], but implied by "Color MLP layers add color variation information") [S1, unofficial].
7.  **Color Prediction:** The concatenated feature vector $\mathbf{F}$ and the encoded direction are passed through the Color MLP to produce the view-dependent color $\mathbf{c}$ [S1, unofficial].

**Pseudocode:**

```python
import math

def hash_encode(x, hash_tables, table_sizes, feature_dim):
    """
    Encodes a 3D coordinate using multiresolution hash encoding.
    x: list of 3 floats (x, y, z)
    hash_tables: list of lists/arrays, hash_tables[l] is the table for level l
    table_sizes: list of ints, table_sizes[l] is the size of table l
    feature_dim: int, dimension of each feature vector
    """
    L = len(hash_tables)
    concatenated_features = []
    
    for l in range(L):
        scale = 2 ** l
        scaled_x = [x[i] * scale for i in range(3)]
        
        # Floor to get voxel indices
        voxel_indices = [math.floor(scaled_x[i]) for i in range(3)]
        # Fractional part for interpolation weights
        frac = [scaled_x[i] - voxel_indices[i] for i in range(3)]
        
        # Precompute interpolation weights for 8 neighbors
        weights = []
        for i in range(8):
            w = 1.0
            for d in range(3):
                bit = (i >> d) & 1
                w *= frac[d] if bit else (1.0 - frac[d])
            weights.append(w)
            
        # Fetch and interpolate features
        interpolated_feat = [0.0] * feature_dim
        for i in range(8):
            # Determine neighbor voxel coordinates
            neighbor_idx = [voxel_indices[d] + ((i >> d) & 1) for d in range(3)]
            # Hash neighbor index to table index (standard hash function) [G]
            h_idx = sum(neighbor_idx) % table_sizes[l]
            feat = hash_tables[l][h_idx]
            for j in range(feature_dim):
                interpolated_feat[j] += weights[i] * feat[j]
                
        concatenated_features.append(interpolated_feat)
        
    # Concatenate all levels
    result = []
    for feat in concatenated_features:
        result.extend(feat)
    return result

def hashnerf_forward(x, d, hash_tables, table_sizes, feature_dim, density_mlp, color_mlp):
    """
    Forward pass for HashNeRF.
    x: 3D coordinate
    d: Viewing direction
    hash_tables: List of hash tables for each resolution level
    table_sizes: List of table sizes
    feature_dim: Dimension of features in hash tables
    density_mlp: Function representing the Density MLP
    color_mlp: Function representing the Color MLP
    """
    # 1. Encode 3D position
    f_pos = hash_encode(x, hash_tables, table_sizes, feature_dim)
    
    # 2. Predict density
    # Density MLP takes the concatenated features
    sigma = density_mlp(f_pos)
    
    # 3. Predict color
    # Color MLP takes concatenated features and encoded direction
    # Note: Direction encoding method is not explicitly detailed in [S1, unofficial] beyond "Color MLP layers add color variation"
    # Assuming standard positional encoding for direction as is common in NeRF variants, 
    # or that the MLP handles raw direction if dimensionality matches.
    # For implementation completeness, we assume a placeholder for direction encoding.
    f_dir = encode_direction(d) # [G] Placeholder for direction encoding
    color = color_mlp(f_pos, f_dir)
    
    return sigma, color

def encode_direction(d):
    """
    Placeholder for direction encoding. 
    Standard NeRF uses positional encoding. HashNeRF [S1, unofficial] implies direction is processed 
    by the Color MLP but does not specify if it uses hash encoding or standard PE.
    """
    # [G] Standard positional encoding for direction is assumed if not specified.
    # This function would expand d into a higher-dimensional vector.
    return d # Simplified for structure; actual implementation requires PE or similar.
```

*Note: Hash collisions are resolved with a 2-layer MLP with 64 hidden units [S2].*

## Subtopics

### [HashNeRF Architectural Variants](8688-hashnerf-architectural-variants.md)
This article details four specific architectural modifications to the HashNeRF color and density networks, proposed to evaluate the impact of residual connections, convolutional layers, and network depth on reconstruction quality and training time. These variants address the limitations of the standard shallow multi-layer perceptron (MLP) decoder by exploring alternative feature aggregation and information preservation strategies. They are distinct from the base HashNeRF method [8678-hashnerf.md] by altering the internal connectivity and layer types of the feature-decoding stage.

### [Zip-NeRF Hash Encoding with Gaussian Expectation](11492-zip-nerf-hash-encoding-with-gaussian-expectation.md)
Zip-NeRF Hash Encoding with Gaussian Expectation is a spatial encoding method for Neural Radiance Fields (NeRF) that replaces large multi-layer perceptrons (MLPs) with a multi-scale hash grid to store 3D features, using Gaussian expectation approximation to prevent aliasing during grid queries. It serves as an acceleration of mip-NeRF 360, replacing its large MLP with a hash encoding based on Instant Neural Graphics Primitives, followed by a smaller MLP. The method sets itself apart from standard hash-based NeRFs by explicitly modeling the query as an expectation over 3D Gaussians rather than point samples, thereby mitigating high-frequency aliasing artifacts inherent in sparse grid representations.

### HollowNeRF
HollowNeRF is a NeRF compression method that automatically sparsifies the feature grid during training by using a trainable 3D saliency mask to guide efficient feature pruning, redistributing hash collisions to improve rendering quality with fewer parameters [S2]. It differs from standard HashNeRF by introducing a coarse 3D saliency grid $G$ of resolution $T \times T \times T$ (where $T$ is typically much smaller than the feature grid resolution) [S2]. During inference, for an input coordinate $\mathbf{x}$, the feature $\mathbf{f}$ is fetched from the multi-level hashgrid following Instant-NGP [S2]. A saliency weight $p$ is predicted by processing information from the trainable 3D saliency grid $G$ through trilinear interpolation and a sigmoid function [S2]. The feature is scaled by this weight ($\mathbf{v} = p\mathbf{f}$) before being fed into the MLP to decode density $\sigma$ and color [S2]. A zero-skipping gate ensures that $\mathbf{v}=0$ maps to $\sigma=0$ [S2]. During training, an ADMM pruner sparsifies the saliency value distribution by enforcing a sparsity constraint when optimizing the loss $L$ [S2]. HollowNeRF uses 31% of the parameters of Instant-NGP while delivering comparable rendering quality, and achieves up to 1dB PSNR accuracy gain using only 56% of the parameters compared to Instant-NGP [S2].

## Operating characteristics
HashNeRF trains faster and converges in fewer iterations than standard NeRF because the encoding is generic, trainable, and the network is shallow with fewer parameters [S1, unofficial]. The specific performance metrics depend on the hardware and dataset; for example, models were trained on NVIDIA GeForce RTX 3090 Ti GPUs, with evaluations conducted at 500 and 1,000 iterations using a dataset of 100 training, 100 validation, and 200 test images (RGB + depth) [S1, unofficial]. The shallow network architecture reduces the computational burden compared to deeper NeRF models, making it suitable for real-time or near-real-time applications where training speed is critical [S1, unofficial].

## Background
HashNeRF, formally known as "Instant Neural Graphics Primitives with a Multiresolution Hash Encoding," was proposed by Thomas Müller, Alex Evans, Christoph Schied, and Alexander Keller [S1, unofficial]. The method was published in ACM Transactions on Graphics in July 2022 [S1, unofficial]. It builds upon the general NeRF framework [S1, unofficial] but introduces a radical approach to reducing training times by leveraging multiresolution hash encoding [S1, unofficial]. The architecture is designed to be generic and trainable, allowing it to be applied to various neural graphics primitives beyond just NeRF, such as Gigapixel approximation and generating signed distance functions [S1, unofficial].
