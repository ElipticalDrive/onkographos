# HashNeRF

Also called: Instant Neural Graphics Primitives, Instant Neural Graphics Primitives with a Multiresolution Hash Encoding

## Overview
HashNeRF is a method for representing Neural Radiance Fields (NeRF) that utilizes a multiresolution hash encoding to map 3D coordinates to a higher-dimensional feature space, followed by a shallow neural network to decode density and color [S1, unofficial]. It solves the problem of slow training times and high memory consumption associated with traditional NeRF models by replacing expensive positional encoding and large MLPs with a trainable, compact hash grid representation [S1, unofficial]. Unlike its siblings, it achieves faster convergence and reduced parameter counts by making the encoding itself trainable alongside the shallow network, allowing it to represent 3D geometry at multiple levels of detail [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D spatial coordinates $\mathbf{x} = (x, y, z)$ and viewing direction $\mathbf{d}$ [G].
*   **Output:** Volume density $\sigma$ and view-dependent color $\mathbf{c}$ [G].

**Data Structures and Parameters:**
The core data structure, parameter definitions, and initialization procedures follow the parent method [Standard Multi-resolution Hash Encoding](13152-standard-multi-resolution-hash-encoding.md).

**Steps:**
1.  **Coordinate Hashing:** For each resolution level $l \in \{0, \dots, L-1\}$, the input coordinate $\mathbf{x}$ is hashed to an index $i_l$ in the hash table for level $l$ [G]. The hash function $H_l(\mathbf{x})$ typically involves scaling the coordinate by $2^l$ and taking the modulo of the table size $T_l$ [G].
2.  **Feature Fetching:** Retrieve the feature vector $\mathbf{f}_l$ from the hash table at index $i_l$ [G].
3.  **Interpolation:** To ensure smoothness, features from neighboring voxels are interpolated [G]. For a coordinate $\mathbf{x}$, let $\mathbf{x}_l$ be the scaled coordinate at level $l$ [G]. The fractional part $\mathbf{u}_l = \mathbf{x}_l - \lfloor \mathbf{x}_l \rfloor$ determines the interpolation weights [G]. The interpolated feature $\hat{\mathbf{f}}_l$ is computed by linearly interpolating the 8 surrounding feature vectors in the hash grid [S1, unofficial].
4.  **Feature Concatenation:** Concatenate the interpolated features from all levels: $\mathbf{F} = [\hat{\mathbf{f}}_0; \hat{\mathbf{f}}_1; \dots; \hat{\mathbf{f}}_{L-1}]$ [G].
5.  **Density Decoding:** Pass $\mathbf{F}$ through a shallow Multi-Layer Perceptron (MLP) to predict the log-space density $\log(\sigma)$ [S1, unofficial]. The output is typically passed through an exponential function to ensure positive density [G].
6.  **Color Decoding:** Concatenate the viewing direction $\mathbf{d}$ (optionally encoded via positional encoding) with the feature vector $\mathbf{F}$ (or a subset thereof) [G]. Pass this through another shallow MLP to predict the color $\mathbf{c}$ [S1, unofficial].
7.  **Volume Rendering:** Use the predicted density $\sigma$ and color $\mathbf{c}$ along camera rays to render the final image using standard volume rendering techniques (e.g., differentiable ray marching) [G].

**Pseudocode:**

```python
import math

def linear_layer(weights, bias, x):
    """Standard fully connected layer: y = Wx + b"""
    out = [0.0] * len(bias)
    for i, w_row in enumerate(weights):
        s = bias[i]
        for j, x_val in enumerate(x):
            s += w_row[j] * x_val
        out[i] = s
    return out

def hash_encode(x, hash_tables, table_sizes, feature_dim):
    """
    Encodes a 3D coordinate using multiresolution hash encoding.
    """
    L = len(hash_tables)
    concatenated_features = []
    
    for l in range(L):
        scale = 2 ** l
        scaled_x = [x[i] * scale for i in range(3)]
        
        voxel_indices = [math.floor(scaled_x[i]) for i in range(3)]
        frac = [scaled_x[i] - voxel_indices[i] for i in range(3)]
        
        # Calculate weights for 8 neighbors
        weights = []
        for i in range(8):
            w = 1.0
            for d in range(3):
                bit = (i >> d) & 1
                w *= frac[d] if bit else (1.0 - frac[d])
            weights.append(w)
            
        # Fetch and interpolate features
        interpolated_feat = [0.0] * feature_dim
        for i in range(8):
            neighbor_idx = [voxel_indices[d] + ((i >> d) & 1) for d in range(3)]
            # Hash neighbor index to table index (standard hash function) [G]
            h_idx = sum(neighbor_idx) % table_sizes[l]
            feat = hash_tables[l][h_idx]
            for j in range(feature_dim):
                interpolated_feat[j] += weights[i] * feat[j]
                
        concatenated_features.append(interpolated_feat)
        
    # Concatenate all levels
    result = []
    for feat in concatenated_features:
        result.extend(feat)
    return result

def hashnerf_forward(x, d, hash_tables, table_sizes, feature_dim, density_weights, density_bias, color_weights, color_bias):
    """
    Forward pass for HashNeRF.
    """
    features = hash_encode(x, hash_tables, table_sizes, feature_dim)
    
    log_sigma = linear_layer(density_weights, density_bias, features)
    sigma = math.exp(log_sigma[0])
    
    color_input = features + d
    c = linear_layer(color_weights, color_bias, color_input)
    
    return sigma, c
```

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Different coordinates may map to the same hash table index [G].
*   **Precision:** Floating-point precision in hashing and interpolation can affect gradient stability [G].
*   **Boundary Conditions:** Coordinates outside the training domain should be handled, e.g., by clamping or returning zero features [G].

## Subtopics

### [HashNeRF Architectural Variants](8688-hashnerf-architectural-variants.md)
This variant explores modifications to the standard shallow MLP decoder, specifically introducing convolutional and dilated convolutional layers into the color generation pipeline to provide spatial context and potentially accelerate convergence. It also evaluates the impact of residual connections between the density and color pipelines to ensure communication and avoid vanishing gradients. These changes aim to improve reconstruction quality and training efficiency compared to the base fully-connected architecture.

### [Zip-NeRF Hash Encoding with Gaussian Expectation](11492-zip-nerf-hash-encoding-with-gaussian-expectation.md)
Zip-NeRF replaces the standard point-query hash encoding with a Gaussian expectation approximation. This method models the query as an expectation over 3D Gaussians to mitigate high-frequency aliasing artifacts inherent in sparse grid representations. It serves as an acceleration for mip-NeRF 360, replacing its large MLP with a hash encoding based on Instant Neural Graphics Primitives, followed by a smaller MLP.

### HollowNeRF
HollowNeRF is a compression method that automatically sparsifies the feature grid during training using a trainable 3D saliency mask [S2]. It predicts a saliency weight $p$ for each coordinate by processing a coarse 3D saliency grid $G$ through trilinear interpolation and a sigmoid function [S2]. The feature $f$ is scaled by $p$ to get $v = pf$, which is then fed into the MLP [S2]. A zero-skipping gate ensures $v=0$ maps to $\sigma=0$ [S2]. An ADMM pruner enforces sparsity on the saliency mask during training [S2]. It uses 31% of the parameters of Instant-NGP while delivering comparable rendering quality, and can achieve up to 1dB PSNR gain using only 56% of the parameters [S2].

## Operating characteristics
*   **Time Complexity:** Training is significantly faster than traditional NeRF due to the shallow network and efficient hash-based lookup [S1, unofficial]. Convergence is achieved in fewer iterations, with evaluations commonly performed at 500 and 1,000 iterations [S1, unofficial].
*   **Memory Complexity:** Memory usage is determined by the total size of the hash tables ($\sum T_l \times F$) and the shallow MLP parameters [G].
*   **Measured Performance:** Evaluated on NVIDIA GeForce RTX 3090 Ti GPUs using datasets consisting of 100 training, 100 validation, and 200 test images (RGB + depth) [S1, unofficial].
*   **Strengths:** Fast training, low memory footprint, and generic applicability to various neural graphics primitives [S1, unofficial].

## Background
HashNeRF, also known as Instant Neural Graphics Primitives with a Multiresolution Hash Encoding, was proposed by Thomas Müller, Alex Evans, Christoph Schied, and Alexander Keller in 2022 [S1, unofficial]. It builds on the idea of using hash tables for efficient feature storage, originally introduced in the context of Instant Neural Graphics Primitives [S1, unofficial]. The method addresses the limitations of earlier NeRF models, which suffered from slow training times and high memory consumption due to large MLPs and positional encoding [S1, unofficial]. It has found applications in Gigapixel approximation, generating signed distance functions, and Neural Radiance Caching [S1, unofficial].
