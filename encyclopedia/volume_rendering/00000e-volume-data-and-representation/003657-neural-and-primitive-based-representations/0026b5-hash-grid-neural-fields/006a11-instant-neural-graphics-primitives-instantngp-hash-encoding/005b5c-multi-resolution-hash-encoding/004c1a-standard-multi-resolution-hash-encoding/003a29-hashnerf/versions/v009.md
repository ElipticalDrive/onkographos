# HashNeRF

Also called: Instant Neural Graphics Primitives, Instant Neural Graphics Primitives with a Multiresolution Hash Encoding

## Overview
HashNeRF is a neural radiance field representation that accelerates training and rendering by replacing traditional positional encoding with a multi-resolution hash encoding scheme [S1][S2, unofficial]. It maps 3D spatial coordinates to feature vectors stored in a set of hash tables, which are then processed by a shallow multi-layer perceptron (MLP) to predict volume density and color [S2, unofficial]. It sets itself apart from standard NeRF by achieving significant reductions in learning time and convergence iterations through a trainable, generic encoding that avoids the high computational cost of sinusoidal positional encodings [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D spatial coordinate $\mathbf{x} = (x, y, z)$ and a viewing direction $\mathbf{d} = (d_x, d_y, d_z)$.
*   **Output:** Volume density $\sigma$ and view-dependent color $\mathbf{c}$.

**Data Structures:**
The method utilizes $L$ hash tables (grids), indexed by resolution level $l \in \{0, \dots, L-1\}$ [S1].
*   Each hash table $l$ contains $T_l$ entries. The size of the hash table is denoted by $T$ [S1].
*   Each entry stores a feature vector of dimension $F$ [S1].
*   The total feature dimension passed to the MLP is $L \times F$ [S1].
*   The neural network is a shallow Multi-Layer Perceptron (MLP) with fully connected layers [S1][S2, unofficial]. It typically consists of:
    *   A **Density MLP** that outputs log-space density $\sigma$.
    *   A **Color MLP** that takes the concatenated features and viewing direction $\mathbf{d}$ to output color $\mathbf{c}$ [S1][S2, unofficial].

**Encoding Process:**
The encoding process for a 3D spatial coordinate $\mathbf{x}$ proceeds as follows for each level $l$:

1.  **Coordinate Scaling:** The input coordinate is scaled by $2^l$:
    $$ \mathbf{x}_l = 2^l \mathbf{x} $$
2.  **Voxel Indexing:** The integer voxel indices $\mathbf{v}_l = (v_x, v_y, v_z)$ are computed by flooring the scaled coordinates:
    $$ v_i = \lfloor (\mathbf{x}_l)_i \rfloor, \quad i \in \{x, y, z\} $$
3.  **Fractional Part:** The fractional part $\mathbf{u}_l = (u_x, u_y, u_z)$ is computed for interpolation weights:
    $$ u_i = (\mathbf{x}_l)_i - v_i $$
4.  **Hashing:** The voxel indices are mapped to table indices using a hash function $H_l$. A common implementation uses a sum or XOR-based hash with modulo $T_l$ [S1, G]:
    $$ i_l = H_l(v_x, v_y, v_z) \pmod{T_l} $$
    The specific collision resolution strategy (e.g., chaining or open addressing) is implementation-dependent [G].
5.  **Feature Retrieval and Interpolation:** Feature vectors $\mathbf{f}_{l, \mathbf{v}'}$ are retrieved from the 8 neighboring voxels $\mathbf{v}'$ of $\mathbf{v}_l$. The interpolated feature $\hat{\mathbf{f}}_l$ is computed using trilinear interpolation:
    $$ \hat{\mathbf{f}}_l = \sum_{\mathbf{v}' \in \text{neighbors}(\mathbf{v}_l)} w(\mathbf{v}') \cdot \mathbf{f}_{l, \mathbf{v}'} $$
    where the weight $w(\mathbf{v}')$ for neighbor $\mathbf{v}' = (v'_x, v'_y, v'_z)$ is:
    $$ w(\mathbf{v}') = \prod_{i \in \{x,y,z\}} \begin{cases} u_i & \text{if } v'_i = v_i + 1 \\ 1 - u_i & \text{if } v'_i = v_i \end{cases} $$
6.  **Feature Concatenation:** The interpolated features from all $L$ levels are concatenated to form the final feature vector $\mathbf{F}$:
    $$ \mathbf{F} = [\hat{\mathbf{f}}_0; \hat{\mathbf{f}}_1; \dots; \hat{\mathbf{f}}_{L-1}] $$

**Decoding:**
The concatenated feature vector $\mathbf{F}$ and viewing direction $\mathbf{d}$ are fed into the shallow MLP. The Density MLP outputs $\sigma$, and the Color MLP outputs $\mathbf{c}$ [S1][S2, unofficial].

**Parameters:**
*   **Levels ($L$):** Standard implementation uses 16 levels ($L=16$) [S1].
*   **Hash Table Size ($T$):** The hash index is limited by $T$ via modulo operation [S1].
*   **Hardware:** Typically implemented using the Tiny-CUDA-NN library on NVIDIA GeForce RTX 3090 Ti GPUs [S1][S2, unofficial].

**Pseudocode:**
```python
import math

def hash_function(coords, table_size):
    """
    Computes the hash index for a given voxel coordinate.
    Uses a simple XOR-based hash as a common implementation [S1, G].
    """
    # coords: tuple (vx, vy, vz)
    # table_size: T_l
    h = 0
    for c in coords:
        # Simple hash mixing; implementation details vary [G]
        h = h ^ (c * 2654435761)
    return h % table_size

def trilinear_interpolation(feature_vectors, fractional_parts):
    """
    Performs trilinear interpolation on 8 feature vectors.
    feature_vectors: list of 8 vectors corresponding to neighbors
    fractional_parts: (ux, uy, uz)
    """
    ux, uy, uz = fractional_parts
    result = [0.0] * len(feature_vectors[0])
    
    # Iterate through all 8 neighbors (0 to 7)
    for i in range(8):
        # Determine which corner this index corresponds to
        # Bit 0 -> x, Bit 1 -> y, Bit 2 -> z
        # If bit is 0, we use (1 - u), if 1, we use u
        wx = ux if (i & 1) else (1.0 - ux)
        wy = uy if (i & 2) else (1.0 - uy)
        wz = uz if (i & 4) else (1.0 - uz)
        
        weight = wx * wy * wz
        for k in range(len(result)):
            result[k] += weight * feature_vectors[i][k]
            
    return result

def hashnerf_encode_decode(x, d, hash_tables, mlp_density, mlp_color):
    """
    x: 3D coordinate (x, y, z)
    d: Viewing direction (dx, dy, dz)
    hash_tables: List of L hash tables, each is a list/array of feature vectors
    mlp_density: Function implementing Density MLP
    mlp_color: Function implementing Color MLP
    """
    L = len(hash_tables)
    F = len(hash_tables[0][0]) # Feature dimension per level
    concatenated_features = []
    
    for l in range(L):
        # 1. Coordinate Scaling
        scale = 2 ** l
        scaled_x = x[0] * scale
        scaled_y = x[1] * scale
        scaled_z = x[2] * scale
        
        # 2. Voxel Indexing
        vx = math.floor(scaled_x)
        vy = math.floor(scaled_y)
        vz = math.floor(scaled_z)
        
        # 3. Fractional Part
        ux = scaled_x - vx
        uy = scaled_y - vy
        uz = scaled_z - vz
        
        # 4 & 5. Hashing and Feature Retrieval/Interpolation
        # Get 8 neighbors' voxel indices
        neighbors = []
        for i in range(2):
            for j in range(2):
                for k in range(2):
                    neighbors.append((vx + i, vy + j, vz + k))
        
        # Retrieve features from hash tables
        # Note: Hash collisions may occur; standard hash tables handle this via 
        # the stored value at the index. In a dense array implementation, 
        # the index is simply the hash result.
        table = hash_tables[l]
        table_size = len(table)
        
        neighbor_features = []
        for n in neighbors:
            # Compute hash index
            idx = hash_function(n, table_size)
            # Retrieve feature vector
            f = table[idx]
            neighbor_features.append(f)
            
        # Interpolate
        interp_feat = trilinear_interpolation(neighbor_features, (ux, uy, uz))
        concatenated_features.extend(interp_feat)
        
    # 6. Feature Concatenation is already done by extending the list
    
    # Decoding
    # Density MLP takes only the features
    sigma = mlp_density(concatenated_features)
    
    # Color MLP takes features and viewing direction
    color = mlp_color(concatenated_features, d)
    
    return sigma, color
```

## Subtopics

### [HashNeRF Architectural Variants](8688-hashnerf-architectural-variants.md)
HashNeRF Architectural Variants are specific modifications to the shallow neural network decoder used in HashNeRF, designed to optimize the trade-off between rendering accuracy (PSNR) and training time. While the standard HashNeRF uses a simple multi-layer perceptron (MLP) with linear layers, these variants explore convolutional layers, residual connections, and deeper network structures to improve feature extraction and color prediction. They differ from sibling methods like Zip-NeRF by focusing on architectural ablation of the MLP decoder rather than changing the underlying hash encoding or density estimation mechanism.

### [Zip-NeRF Hash Encoding with Gaussian Expectation](11492-zip-nerf-hash-encoding-with-gaussian-expectation.md)
Zip-NeRF Hash Encoding with Gaussian Expectation is a spatial encoding method for Neural Radiance Fields (NeRF) that replaces large multi-layer perceptrons (MLPs) with a multi-scale hash grid to store 3D features, using Gaussian expectation approximation to prevent aliasing during grid queries. It serves as an acceleration of mip-NeRF 360, replacing its large MLP with a hash encoding based on Instant Neural Graphics Primitives, followed by a smaller MLP. The method sets itself apart from standard hash-based NeRFs by explicitly modeling the query as an expectation over 3D Gaussians rather than point samples, thereby mitigating high-frequency aliasing artifacts inherent in sparse grid representations.

### HollowNeRF
HollowNeRF is a NeRF compression method that automatically sparsifies the feature grid during training by using a trainable 3D saliency mask to guide efficient feature pruning, redistributing hash collisions to improve rendering quality with fewer parameters [S3]. Given input coordinate $\mathbf{x}=(x,y,z)$, it fetches feature $\mathbf{f}$ from the multi-level hashgrid following Instant-NGP [S3]. It predicts a saliency weight $p$ by processing information from a trainable 3D saliency grid $G$ through trilinear interpolation and a sigmoid function [S3]. The feature is scaled by $p$ to get $\mathbf{v} = p\mathbf{f}$ [S3]. The weighted feature $\mathbf{v}$ is fed into an MLP to decode density $\sigma$ and color [S3]. A zero-skipping gate ensures $\mathbf{v}=0$ maps to $\sigma=0$ [S3]. During training, an ADMM pruner sparsifies the saliency value distribution by enforcing a sparsity constraint when optimizing the loss $L$ [S3]. The resolution of the trainable 3D saliency grid $G$ is $T \times T \times T$, typically much smaller than the resolution of the dense feature grid [S3]. HollowNeRF uses 31% of the parameters of Instant-NGP while delivering comparable rendering quality [S3]. It achieves up to 1dB PSNR accuracy gain using only 56% of the parameters compared to Instant-NGP [S3].

## Operating characteristics
*   **Time and Memory Complexity:** The method achieves excellent memory utilization and reduces training and rendering time compared to traditional position encoding methods [S1]. It trains faster and converges in fewer iterations than standard NeRF because the encoding is generic, trainable, and the network is shallow with fewer parameters [S2, unofficial].
*   **Measured Performance:** Evaluated on NVIDIA GeForce RTX 3090 Ti GPUs [S2, unofficial]. Training iterations evaluated include 500 and 1,000 [S2, unofficial]. The dataset used for training, validation, and testing consists of 100, 100, and 200 (RGB + depth) images respectively [S2, unofficial].
*   **Strengths and Limitations:** Significant reduction in learning time compared to traditional position encoding methods [S1]. The encoding is generic and trainable, working with all kinds of Neural Graphics primitives [S2, unofficial].
*   **When to use:** When fast training and rendering of NeRFs are required, and hardware acceleration via Tiny-CUDA-NN is available [S1][S2, unofficial].

## Background
HashNeRF, formally known as "Instant Neural Graphics Primitives with a Multiresolution Hash Encoding," was proposed by Thomas Müller, Alex Evans, Christoph Schied, and Alexander Keller [S2, unofficial]. It was published in ACM Transactions on Graphics, Vol. 41, No. 4, Article 102, in July 2022 [S2, unofficial]. The method addresses the high computational cost of traditional NeRFs by introducing a multi-resolution hash encoding approach [S1]. It is implemented using the Tiny-CUDA-NN library based on Cuda and C++ [S1].
