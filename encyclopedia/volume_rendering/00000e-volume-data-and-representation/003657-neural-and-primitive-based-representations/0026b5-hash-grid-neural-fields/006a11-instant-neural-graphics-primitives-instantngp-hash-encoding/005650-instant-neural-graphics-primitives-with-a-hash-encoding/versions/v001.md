# Instant Neural Graphics Primitives with a Hash Encoding

Also called: Instant Neural Graphics Primitives with a Multiresolution Hash Encoding, Instant-NGP Multi-Resolution Hash Encoding

## Overview
Instant Neural Graphics Primitives with a Hash Encoding (Instant-NGP) is a method that drastically reduces the training time of Neural Radiance Fields (NeRF) from days to minutes and enables interactive rendering speeds by replacing traditional positional encoding with a multi-resolution hash grid [S1][S2, unofficial]. It achieves this by mapping 3D coordinates to a sparse set of learnable feature vectors via spatial hashing, allowing the network to capture high-frequency details with significantly fewer queries than dense grid structures [S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** 3D spatial coordinates $\mathbf{x} \in \mathbb{R}^3$ (and optionally view direction $\mathbf{d}$).
*   **Output:** A feature vector $\mathbf{v} \in \mathbb{R}^C$ (where $C$ is the feature dimension per level) used as input to a subsequent small neural network (MLP) to predict density and color.

**Data Structures**
The method employs a multi-resolution hash grid consisting of $L$ levels.
*   **Level $l$ ($0 \le l < L$):** Defined by a grid resolution $R_l$ (number of voxels per axis) and a hash table size $T_l$.
*   **Hash Table:** An array of size $T_l$ storing learned feature vectors. Each entry (bucket) holds a vector of dimension $C$.
*   **Coordinate System:** The 3D space is discretized into voxel cubes. For a given resolution $R_l$, the space is normalized to $[0, R_l]^3$.

**Algorithm Steps**
1.  **Ray Sampling:** Place a large number of sampling points along virtual rays from an object-centric perspective [S1].
2.  **Empty Space Skipping:** Skip all empty space until the object surface is hit, utilizing 10-100x fewer steps than naive dense stepping [S2, unofficial].
3.  **Voxel Encapsulation:** For each sampling point, identify the voxel cubes it resides in across all $L$ levels [S1].
4.  **Hash Index Calculation:** For each level $l$, compute the hash index for the voxel coordinates. The hash function maps the integer grid coordinates $\mathbf{x}_l$ to a bucket index $h(\mathbf{x}_l)$ [S1][S2, unofficial].
    *   The hash function is defined as [S1]:
        $$ h(\mathbf{x}) = \left( \bigoplus_{i=1}^{d} x_i \pi_i \right) \mod T $$
        Where:
        *   $d=3$ is the dimensionality.
        *   $x_i$ are the integer coordinates of the voxel vertex at level $l$.
        *   $\pi_i$ are distinct prime numbers (constants).
        *   $\oplus$ denotes bitwise XOR.
        *   $T$ is the size of the hash table for that level.
5.  **Feature Retrieval:** Retrieve the learned feature vector $\mathbf{f}_{l, k}$ from the hash table at index $h(\mathbf{x}_{l, k})$ for each of the $2^d$ vertices of the voxel at level $l$ [S1].
6.  **Trilinear Interpolation:** Weight the retrieved features based on the distance between the sampling point and the voxel vertices to generate a single feature vector for level $l$ [S1].
7.  **Concatenation:** Concatenate the interpolated feature vectors from all $L$ levels to form the final input feature vector for the MLP [S2, unofficial].

def compute_hash_index(coords, table_size):
    """
    Computes the hash index for a 3D coordinate using the formula from [S1].
    coords: tuple (x, y, z) of integer grid coordinates
    table_size: T, the size of the hash table
    """
    x, y, z = coords
    # Using large primes as multipliers. The source uses pi_i in the sum.
    # We use standard 32-bit primes for stability.
    p1, p2, p3 = 2654435761, 2246822519, 3266489917
    
    # Bitwise XOR sum of coordinate * prime
    h = (x * p1) ^ (y * p2) ^ (z * p3)
    
    # Modulo table size
    return h % table_size

    """
    # Normalize point to grid coordinates [0, level_res]
    # Assuming world space is normalized to [0, 1] or similar, 
    # and grid covers a specific bounding box. 
    # For simplicity, assume point_3d is already in grid coordinates [0, R_l].
    
    # Get integer coordinates of the voxel corner
    x0 = int(math.floor(point_3d[0]))
    y0 = int(math.floor(point_3d[1]))
    z0 = int(math.floor(point_3d[2]))
    
    # Fractional parts
    fx = point_3d[0] - x0
    fy = point_3d[1] - y0
    fz = point_3d[2] - z0
    
    # Get the 8 vertices of the voxel
    vertices = [
        (x0, y0, z0), (x0+1, y0, z0), (x0, y0+1, z0), (x0+1, y0+1, z0),
        (x0, y0, z0+1), (x0+1, y0, z0+1), (x0, y0+1, z0+1), (x0+1, y0+1, z0+1)

    # Retrieve features using hash
    table = grid_hash_tables[level_res] # Assuming table indexed by resolution or level
    features = []
    for v in vertices:
        idx = compute_hash_index(v, len(table))
        features.append(table[idx])
        
    # Trilinear interpolation
    # c000, c100, c010, c110, c001, c101, c011, c111
    c000 = features[0]
    c100 = features[1]
    c010 = features[2]
    c110 = features[3]
    c001 = features[4]
    c101 = features[5]
    c011 = features[6]
    c111 = features[7]
    
    # Interpolate x
    c00 = c000 * (1-fx) + c100 * fx
    c01 = c010 * (1-fx) + c110 * fx
    c10 = c001 * (1-fx) + c101 * fx
    c11 = c011 * (1-fx) + c111 * fx
    
    # Interpolate y
    c0 = c00 * (1-fy) + c01 * fy
    c1 = c10 * (1-fy) + c11 * fy

    result = c0 * (1-fz) + c1 * fz

**Edge Cases and Pitfalls**
*   **Hash Collisions:** Hash collisions cause grainy noise in outputs (e.g., SDFs), requiring filtering or smoothness priors for mitigation [S2, unofficial].
*   **Hash Function Choice:** Simple hashing is fast but lacks coherence. Advanced methods (e.g., PCG32) add overhead without clear quality improvements [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Training time is reduced to minutes, compared to hours or days for traditional NeRF [S2, unofficial].
*   **Memory Complexity:** Uses a hash table of size $T$ instead of allocating $R^3$ vectors, significantly reducing memory usage [S2, unofficial].
*   **Performance:** Enables interactive rendering at tens of frames per second [S2, unofficial].
*   **Strengths:** Fast training, interactive rendering, compact representation of high-frequency details [S2, unofficial].
*   **Limitations:** Hash collisions can cause noise; simple hashing lacks coherence [S2, unofficial].
*   **When to use:** When fast training and interactive rendering are required, and the scene can be represented with a hash grid.
*   **When not to use:** When high coherence in the hash function is critical, or when dealing with sparse volumetric data like clouds [S2, unofficial].

## Background
Instant Neural Graphics Primitives with a Hash Encoding was introduced by Thomas Mueller, Alex Evans, Christoph Schied, and Alexander Keller in 2022 [S2, unofficial]. It builds on prior work to make input encoding trainable along with the weights of the network [S2, unofficial]. The method was developed to address the limitations of NeRF, specifically its expensive training time and slow inference [S2, unofficial].
