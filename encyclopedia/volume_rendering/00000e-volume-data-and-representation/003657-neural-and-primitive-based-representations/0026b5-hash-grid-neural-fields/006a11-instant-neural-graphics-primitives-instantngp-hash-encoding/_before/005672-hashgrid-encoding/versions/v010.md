# HashGrid Encoding

Also called: GridEncoding, Hash Encodings, Hash Grid Feature Interpolation, Instant NGP encoding, Instant Neural Graphics Primitives Encoding

## Overview
HashGrid Encoding maps continuous spatial coordinates to high-dimensional feature vectors using a cascade of multi-resolution hash tables, enabling efficient training and inference of neural graphics primitives by replacing large implicit neural networks with sparse, learnable feature lookups [S4, unofficial][S15]. It sets itself apart from standard positional encoding by using learnable parameters stored in sparse hash grids rather than fixed basis functions, and from dense grid encodings by allocating parameters only where needed via spatial hashing, significantly reducing memory usage and training time while maintaining high reconstruction quality [S1, S15].

## How it works
**Inputs and Outputs:**
*   **Input:** A batch of $B$ input coordinate vectors $\mathbf{x} \in \mathbb{R}^{B \times D}$, where $D$ is the spatial dimensionality (typically 2 or 3). Values are expected to be normalized to the range $[0, 1]$ [S5, S11, unofficial].
*   **Output:** A concatenated feature vector $\mathbf{y} \in \mathbb{R}^{B \times (L \cdot C)}$, where $L$ is the number of resolution levels and $C$ is the number of feature channels per level [S11, unofficial][S15].
*   **Gradients:** Optionally, the gradient of the output with respect to the input, $\frac{\partial \mathbf{y}}{\partial \mathbf{x}} \in \mathbb{R}^{B \times L \times D \times C}$, is computed for backpropagation [S11, S14, unofficial].

**Data Structures:**
The encoding relies on a set of $L$ hash tables. The parameters are stored in a flattened tensor `embeddings` of shape $[sO, C]$, where $sO = \sum_{l=0}^{L-1} \text{hashmap\_size}_l$ is the total capacity [S11, S14, unofficial].
*   **Offsets:** An integer array `offsets` of size $L+1$ stores the cumulative start indices for each level in the `embeddings` tensor. The hash table size for level $l$ is $\text{hashmap\_size}_l = \text{offsets}[l+1] - \text{offsets}[l]$ [S11, S14, unofficial].
*   **Precision:** Entries are stored at half precision (2 bytes) for memory efficiency, with a master copy in full precision for stable mixed-precision updates [S4, unofficial][S15].

**Parameters:**
*   $L$: Number of resolution levels. Typical value: 16 [S4, unofficial][S15].
*   $T$: Max entries per level (hash table size). Range: $2^{14}$ to $2^{24}$. This is the primary hyper-parameter trading parameter count for quality [S4, unofficial][S15].
*   $F$ (or $C$): Number of feature dimensions per entry. Typical value: 2 [S4, unofficial][S15]. Supported values: 1, 2, 4, 8 [S11, S14, unofficial].
*   $H$: Base resolution (grid size at level 0) [S11, S14, unofficial].
*   $S$: Scaling factor exponent controlling exponential resolution growth [S11, S5, unofficial].
*   $N_{\min}$: Coarsest resolution. Typical value: 16 [S15].
*   $N_{\max}$: Finest resolution. Tunable to match finest detail. Typical range: $[512, 524288]$ [S15].
*   Primes for hashing: $\pi_1 = 1$, $\pi_2 = 2,654,435,761$, $\pi_3 = 805,459,861$ [S3, unofficial][S15].

**Algorithm:**
The encoding is computed level by level to optimize GPU cache usage [S4, unofficial]. For each level $l \in [0, L-1]$:

1.  **Calculate Resolution:** Compute the scale factor and integer grid resolution for level $l$:
    $$ \text{scale}_l = 2^{l \cdot S} \cdot H - 1 $$
    $$ \text{resolution}_l = \lceil \text{scale}_l \rceil + 1 $$
    [S11, S14, S5, unofficial]

2.  **Map to Grid Coordinates:** For each input coordinate $\mathbf{x}_b$ (batch index $b$):
    *   Check bounds: If any component of $\mathbf{x}_b$ is outside $[0, 1]$, set output features and gradients to 0 and skip [S11, S5, unofficial].
    *   Compute continuous grid position:
        $$ \text{pos}[d] = \mathbf{x}_b[d] \cdot \text{scale}_l + 0.5 $$
        The offset $0.5$ staggers scales to prevent spurious alignment of fractional coordinates [S3, S14, unofficial].
    *   Compute integer grid coordinates and fractional remainders:
        $$ \text{pos\_grid}[d] = \lfloor \text{pos}[d] \rfloor $$
        $$ \text{pos}[d] \leftarrow \text{pos}[d] - \text{pos\_grid}[d] $$
        [S14, S5, unofficial]

3.  **Hash Lookup:** For each of the $2^D$ corners of the voxel defined by $\text{pos\_grid}$:
    *   Determine the local grid coordinate $\text{pos\_grid\_local}[d]$ and interpolation weight $w$ for dimension $d$:
        *   If the $d$-th bit of the corner index $idx$ is 0 (lower bound): $\text{pos\_grid\_local}[d] = \text{pos\_grid}[d]$, weight factor $(1 - \text{pos}[d])$.
        *   If the $d$-th bit is 1 (upper bound): $\text{pos\_grid\_local}[d] = \text{pos\_grid}[d] + 1$, weight factor $\text{pos}[d]$.
    *   Compute the total weight $w$ as the product of factors across all dimensions $d$ [S14, S5, unofficial].
    *   Compute the hash index. The spatial hash function maps integer grid coordinates to table indices:
        $$ h(\text{pos\_grid}) = \left( \bigoplus_{i=0}^{D-1} (\text{pos\_grid}[i] \times \pi_i) \right) \pmod{\text{hashmap\_size}_l} $$
        where $\oplus$ is bitwise XOR and $\pi_i$ are the unique large primes [S15][S3, S14, unofficial].
        *   Note: If the stride-based index exceeds `hashmap_size`, a fallback hash is used [S14, S11, unofficial].
    *   Fetch the feature vector from the `embeddings` tensor at index $\text{offsets}[l] + h(\text{pos\_grid})$ [S14, S5, unofficial].

4.  **Interpolation:** Accumulate the weighted feature vectors from all $2^D$ corners to produce the level's output feature vector $\mathbf{y}_l$:
    $$ \mathbf{y}_l = \sum_{idx=0}^{2^D-1} w_{idx} \cdot \text{embeddings}[\text{index}_{idx}] $$
    [S14, unofficial][S15]

5.  **Concatenation:** Concatenate the feature vectors from all levels $l=0 \dots L-1$ to form the final encoding $\mathbf{y}$ [S6, S15].

**Backward Pass (Gradients):**
*   **Feature Gradients:** Gradients $\frac{\partial \mathcal{L}}{\partial \mathbf{y}_l}$ are accumulated into the hash table entries using atomic addition (`atomicAdd`) [S14, S11, unofficial].
    *   Optimization: Use `__half2` vectorized atomics if $C$ is even; otherwise fall back to scalar `atomicAdd` or float [S14, S5, unofficial].
    *   Optimization: Skip Adam steps for entries with zero gradient to save ~10% performance [S4, unofficial].
*   **Input Gradients:** Compute $\frac{\partial \mathbf{y}}{\partial \mathbf{x}}$ by summing contributions from all levels. For each dimension $gd \in [0, D-1]$:
    *   Initialize `results_grad` to 0.
    *   Iterate over $2^{D-1}$ neighbors fixing $gd$. For other dimensions $nd \neq gd$, determine corner position and weight $w$ (product of $\text{pos}[nd]$ or $1-\text{pos}[nd]$) [S11, S5, unofficial].
    *   Compute left and right indices along $gd$: $\text{index\_left}$ at $\text{pos\_grid}[gd]$ and $\text{index\_right}$ at $\text{pos\_grid}[gd] + 1$ [S5, unofficial].
    *   Accumulate: $\text{results\_grad}[ch] += w \cdot (\text{grid}[\text{index\_right} + ch] - \text{grid}[\text{index\_left} + ch]) \cdot \text{scale}_l$ [S11, S5, unofficial].
    *   Store in $\frac{\partial \mathbf{y}}{\partial \mathbf{x}}$ [S5, S14, unofficial].

**Pseudocode:**
```python
def hash_grid_encode(inputs, offsets, embeddings, L, H, S, C, primes):
    """
    inputs: [B, D] float, range [0, 1]
    offsets: [L+1] int
    embeddings: [sO, C] float
    Returns: [L, B, C] outputs, [B, L, D, C] dy_dx
    """
    B, D = inputs.shape
    outputs = torch.zeros(L, B, C)
    dy_dx = torch.zeros(B, L, D, C)
    
    for l in range(L):
        # 1. Calculate Resolution
        scale = (2 ** (l * S)) * H - 1
        resolution = int(math.ceil(scale)) + 1
        hashmap_size = offsets[l+1] - offsets[l]
        base_idx = offsets[l]
        
        # 2. Map to Grid Coordinates
        # pos: [B, D]
        pos = inputs * scale + 0.5
        pos_grid = torch.floor(pos).long()
        pos_frac = pos - pos_grid.float()
        
        # Check bounds
        if torch.any((inputs < 0) | (inputs > 1)):
            # Handle out-of-bounds: set outputs/grads to 0 (already initialized)
            pass
            
        level_features = torch.zeros(B, C)
        level_grads = torch.zeros(B, D, C)
        
        # 3. & 4. Interpolation over 2^D corners
        for idx in range(1 << D):
            w = 1.0
            pos_grid_local = torch.zeros(D, dtype=torch.long)
            
            for d in range(D):
                if (idx >> d) & 1:
                    w *= pos_frac[:, d]
                    pos_grid_local[d] = pos_grid[:, d] + 1
                else:
                    w *= (1.0 - pos_frac[:, d])
                    pos_grid_local[d] = pos_grid[:, d]
            
            # Hash Index Calculation
            # h(x) = XOR(x_i * pi_i) % T
            hash_val = 0
            for d in range(D):
                hash_val ^= pos_grid_local[:, d] * primes[d]
            indices = (hash_val % hashmap_size) + base_idx
            
            # Fetch and Accumulate
            # embeddings[indices] shape: [B, C]
            features = embeddings[indices]
            level_features += w.unsqueeze(1) * features
            
            # 5. Input Gradient Calculation (dy_dx)
            # For each dimension gd, compute partial derivative
            for gd in range(D):
                # Neighbors fixing gd
                # Left index: pos_grid[gd], Right index: pos_grid[gd] + 1
                # We need to re-calculate indices for left and right specifically
                # This is simplified; in practice, loop over 2^(D-1) masks for other dims
                
                # Construct left/right indices for this gd
                # Left: same as pos_grid_local but gd dim is pos_grid[:, gd]
                # Right: same as pos_grid_local but gd dim is pos_grid[:, gd] + 1
                
                # Weights for other dimensions
                w_other = 1.0
                for d in range(D):
                    if d != gd:
                        if (idx >> d) & 1:
                            w_other *= pos_frac[:, d]
                        else:
                            w_other *= (1.0 - pos_frac[:, d])
                
                # Left Index
                idx_left = 0
                for d in range(D):
                    if d == gd:
                        val = pos_grid[:, d]
                    else:
                        val = pos_grid_local[:, d]
                    idx_left ^= val * primes[d]
                idx_left = (idx_left % hashmap_size) + base_idx
                
                # Right Index
                idx_right = 0
                for d in range(D):
                    if d == gd:
                        val = pos_grid[:, d] + 1
                    else:
                        val = pos_grid_local[:, d]
                    idx_right ^= val * primes[d]
                idx_right = (idx_right % hashmap_size) + base_idx
                
                grad_val = w_other * (embeddings[idx_right] - embeddings[idx_left]) * scale
                level_grads[:, gd, :] += grad_val

        outputs[l] = level_features
        dy_dx[:, l, :, :] = level_grads
        
    return outputs, dy_dx
```

## Subtopics

### [HashNeRF Parameters](3068-hashnerf-parameters.md)
Defines configuration for training Neural Radiance Fields using HashGrid Encoding, specifically targeting the `HashNeRF-pytorch` repository. It sets itself apart by using a learnable hash table with trilinear interpolation for faster training/inference on consumer hardware compared to dense MLPs [Parent].

### [Progressive Training](9142-progressive-training.md)
A strategy for optimizing multi-resolution hash encodings that gradually activates higher resolution levels. It solves training instability by freezing higher-resolution grids until their activation step, differing from simultaneous training by applying multi-rate-distortion supervision.

### [Dense Grid Encoding](9335-dense-grid-encoding.md)
Maps input coordinates to feature vectors using a dense, regular grid structure. It trades a larger memory footprint for reduced computational cost, unlike sparse hash-based variants which allocate parameters uniformly.

### [ACORN](9336-acorn.md)
Uses a tree subdivision of the input domain to output dense feature grids in leaf nodes. It yields greater adaptivity compared to previous parametric encodings at greater computational cost.

### [Multi-resolution Hash Encoding](10200-multi-resolution-hash-encoding.md)
Maps 3D spatial coordinates to a high-dimensional feature vector using a set of trainable hash tables at multiple resolutions. It replaces the large, deep MLP with a multi-resolution learnable hash grid, achieving a 1000–10,000× training speedup compared to vanilla NeRF.

### [RHINO](10245-rhino.md)
A regularization framework that restores interpolation quality by introducing an additional input coordinate with an analytical transformation $T$, compensating for broken gradient flow between input coordinates and hash-keys.

### [HollowNeRF Saliency Grid Weighting](10745-hollownerf-saliency-grid-weighting.md)
A collision mitigation technique that learns a 3D probability distribution of feature presence to weight feature vectors, allowing important features to dominate shared hash buckets during gradient updates.

### [TetraHashGridEncode](13232-tetrahashgridencode.md)
Replaces standard trilinear interpolation within hash-grid cells with barycentric interpolation over a fixed tetrahedral decomposition, allowing for efficient training of NeRF on consumer GPUs.

### [Vanishing Point Aided Hash-Frequency Encoding](13623-vanishing-point-aided-hash-frequency-encoding.md)
Combines multi-resolution hash encoding with deterministic frequency encoding aligned to scene structure via vanishing points to improve generalizability from sparse inputs.

### [Instant Neural Graphics Primitives with a Hash Encoding](15672-instant-neural-graphics-primitives-with-a-hash-encoding.md)
The original Instant-NGP method that drastically reduces NeRF training time from days to minutes by replacing traditional positional encoding with a multi-resolution hash grid.

## Operating characteristics
**Time and Memory Complexity:**
*   **Forward Pass:** $O(B \cdot L \cdot 2^D \cdot C)$ operations per batch element [S11, unofficial].
*   **Backward Pass:** $O(B \cdot L \cdot 2^D \cdot N_C)$ with atomic addition overhead, where $N_C = \min(2, C)$ [S11, S14, unofficial].
*   **Memory:** $O(\sum_{l=0}^{L-1} \text{hashmap\_size}_l \times C)$ for the embedding table. The total number of trainable parameters is $O(T \cdot L \cdot F)$, bounded by $T \cdot L \cdot F$ [S14, unofficial][S15].

**Measured Performance:**
*   On an NVIDIA RTX 3090, performance remains constant as long as the hash table size stays below $T \le 2^{20}$ (approx. 6 MB L2 cache limit for $2 \cdot L \cdot d$ entries) [S4, unofficial].
*   Training speedup of 1000–10,000× compared to vanilla NeRF is reported [S1][S3, unofficial].
*   Rendering speeds reach tens of milliseconds at 1920×1080 resolution [S4, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Adaptive to training data distribution; prioritizes sparse areas with important fine-scale detail via hash collision averaging; no structural updates needed during training; O(1) lookups without control flow divergence [S4, unofficial][S15].
*   **Limitations:** Hash collisions between distant points can introduce artifacts if table size is reduced [S9, unofficial]. Visually undesirable surface roughness (microstructure) may appear in SDF rendering due to random hash collisions [S4, unofficial]. Performance drops significantly if hash table size exceeds the L2 cache threshold [S4, unofficial]. Half-precision atomic addition is slow for scalar features ($C=1$); $C=2$ is optimal for vectorization [S14, unofficial][S15].

**When to Use:**
*   Use for efficient training and inference of neural graphics primitives (NeRF, SDF, Gigapixel images) on consumer GPUs where training time and memory are constraints [S4, unofficial][S15].
*   Avoid if strict continuity of higher-order derivatives is required without additional smoothing techniques, or if the scene has extremely sparse data where hash collisions might dominate [S4, S9, unofficial].

## Background
HashGrid Encoding was introduced by Thomas Müller, Alex Evans, Christoph Schied, and Alexander Keller in 2022 in the paper "Instant Neural Graphics Primitives with a Multiresolution Hash Encoding" [S4, unofficial]. It was developed to address the high computational cost of training and evaluating fully connected neural networks for spatial representations. The method builds on the concept of parametric positional encoding using auxiliary data structures like hash tables [S3, unofficial]. It is the core encoding method used in Instant-NGP and has become a standard for fast neural rendering [S1, S15].
