# HashGrid Encoding

Also called: GridEncoding, Hash Encodings, Hash Grid Feature Interpolation, Instant NGP encoding, Instant Neural Graphics Primitives Encoding

## Overview
HashGrid Encoding is a parametric positional encoding method that maps continuous input coordinates to high-dimensional feature vectors using a cascade of multi-resolution hash tables [S1][S4, unofficial][S15]. It solves the computational bottleneck of querying large implicit neural networks at every point in space by replacing dense positional encodings with sparse, trainable feature lookups, reducing model size and improving synthesis quality [S1][S2, S4, unofficial]. It sets itself apart from dense grid methods by its spatial hashing mechanism which allocates parameters only to visited regions, and from standard NeRF by enabling significantly faster convergence and smaller MLPs [S1][S4, unofficial][S15].

## How it works
**Inputs and Outputs:**
*   **Input:** A tensor of coordinates $\mathbf{x} \in \mathbb{R}^{B \times D}$, where $B$ is the batch size and $D$ is the spatial dimensionality (typically 2 or 3). Values are expected to be normalized to the range $[0, 1]$ [S5, S11, S14, unofficial].
*   **Output:** A tensor of encoded features $\mathbf{y} \in \mathbb{R}^{L \times B \times C}$, where $L$ is the number of resolution levels and $C$ is the number of feature channels per level [S5, S11, S14, unofficial]. Optionally, the gradient of the output with respect to the input $\frac{\partial \mathbf{y}}{\partial \mathbf{x}} \in \mathbb{R}^{B \times L \times D \times C}$ is computed [S5, S11, S14, unofficial].

**Data Structures:**
The encoding relies on a set of $L$ hash tables. The features are stored in a flattened array `embeddings` of shape `[sO, C]`, where `sO` is the total capacity across all levels [S5, S11, S14, unofficial].
*   **Offsets:** An integer array `offsets` of size $L+1$. `offsets[l]` is the starting index in `embeddings` for level $l$. The hash table size for level $l$ is `hashmap_size_l = offsets[l+1] - offsets[l]` [S5, S11, S14, unofficial].
*   **Precision:** Hash table entries are typically stored at half precision (2 bytes per entry) for memory efficiency, with a master copy in full precision for stable mixed-precision updates [S4, unofficial][S15].

**Parameters:**
*   $L$: Number of resolution levels. Typical value: 16 [S4, unofficial][S15].
*   $T$: Max entries per level (hash table size). Range: $2^{14}$ to $2^{24}$. This is the primary hyper-parameter for tuning the trade-off between parameters and quality [S4, unofficial][S15].
*   $F$: Number of feature dimensions per entry. Typical value: 2 [S4, unofficial][S15].
*   $N_{\min}$: Coarsest resolution. Typical value: 16 [S4, unofficial][S15].
*   $N_{\max}$: Finest resolution. Tunable to match finest detail. Typical range: $[512, 524288]$ [S4, unofficial][S15].
*   $H$: Base resolution (resolution at level 0).
*   $S$: Scaling factor exponent. Controls exponential resolution growth [S5, S11, unofficial].
*   `align_corners`: Boolean flag. If true, input range $[0,1]$ maps to $[0, scale]$. If false, adds 0.5 offset for center-aligned sampling [S5, S11, unofficial].
*   `interp`: Interpolation type. 0 for linear, 1 for smoothstep [S11, unofficial].

**Formulas:**
1.  **Resolution Scale:** For level $l$, the scale factor is calculated as [S5, S11, S14, unofficial]:
    $$ \text{scale}_l = 2^{l \cdot S} \cdot H - 1 $$
    Alternatively, using geometric progression between $N_{\min}$ and $N_{\max}$ [S15]:
    $$ N_l = \lfloor N_{\min} \cdot b^l \rfloor, \quad b = \exp\left(\frac{\ln(N_{\max}) - \ln(N_{\min})}{L - 1}\right) $$
2.  **Grid Resolution:** The integer resolution for level $l$ is [S5, S11, S14, unofficial]:
    $$ \text{resolution}_l = \lceil \text{scale}_l \rceil + 1 $$
3.  **Coordinate Mapping:** Input coordinates $\mathbf{x}$ are mapped to continuous grid coordinates [S5, S11, S14, unofficial]:
    $$ \text{pos}[d] = \mathbf{x}[d] \times \text{scale}_l + \begin{cases} 0.0 & \text{if align\_corners} \\ 0.5 & \text{otherwise} \end{cases} $$
    Integer grid coordinates and fractional parts are derived as [S5, S11, S14, unofficial]:
    $$ \text{pos\_grid}[d] = \lfloor \text{pos}[d] \rfloor $$
    $$ \text{pos}[d] \leftarrow \text{pos}[d] - \text{pos\_grid}[d] $$
4.  **Hash Function:** To map integer grid coordinates to hash table indices, a spatial hash function is used [S3, S4, unofficial][S15]:
    $$ h(\mathbf{p}) = \left( \bigoplus_{i=1}^{D} (p_i \times \pi_i) \right) \pmod T $$
    where $\oplus$ is bitwise XOR and $\pi_i$ are unique large primes. Recommended primes for $D=3$: $\pi_1=1, \pi_2=2654435761, \pi_3=805459861$ [S3, S4, unofficial][S15].
5.  **Interpolation:** Features are interpolated from the $2^D$ corners of the voxel containing $\mathbf{x}$ [S4, unofficial][S15]. For a corner index $idx \in [0, 2^D-1]$, the weight $w$ is [S5, S14, unofficial]:
    $$ w = \prod_{d=0}^{D-1} \begin{cases} \text{pos}[d] & \text{if bit } d \text{ of } idx \text{ is 1} \\ 1 - \text{pos}[d] & \text{if bit } d \text{ of } idx \text{ is 0} \end{cases} $$
    The final encoded feature for level $l$ is [S6, S15]:
    $$ \text{enc}(\mathbf{x}, l) = \sum_{idx=0}^{2^D-1} w_{idx} \cdot \text{embeddings}[\text{index}_{idx} + ch] $$
    where $\text{index}_{idx}$ is the hash index for the corner.
6.  **Concatenation:** The final encoding is the concatenation of features from all levels [S6, S7, S15]:
    $$ \text{enc}(\mathbf{x}; \theta) = [\text{enc}(\mathbf{x}, 0); \dots; \text{enc}(\mathbf{x}, L-1)] $$

**Steps:**
1.  **Bounds Check:** If any input coordinate is outside $[0, 1]$, set outputs to 0 and return (gradients initialized to 0) [S5, S11, unofficial].
2.  **Iterate Levels:** For each level $l$ from $0$ to $L-1$:
    a. Calculate `scale` and `resolution` using the formulas above.
    b. Map input coordinates $\mathbf{x}$ to grid space `pos` and compute integer grid coordinates `pos_grid` and fractional parts `pos` [S5, S11, S14, unofficial].
    c. Iterate over all $2^D$ corners of the voxel defined by `pos_grid`.
    d. For each corner, compute the local grid coordinate and the interpolation weight $w$ [S5, S14, unofficial].
    e. Compute the hash index for the corner using the spatial hash function [S4, S11, S14, unofficial].
    f. Fetch the feature vectors from the `embeddings` array at the computed indices [S5, S11, S14, unofficial].
    g. Accumulate the weighted features into the output buffer for level $l$ [S5, S11, S14, unofficial].
3.  **Backward Pass (if requested):**
    a. Compute gradients with respect to the embeddings using atomic addition, weighted by the interpolation weights [S11, S14, unofficial].
    b. Compute gradients with respect to the input coordinates $\frac{\partial \mathbf{y}}{\partial \mathbf{x}}$ by summing contributions from all levels and channels [S11, S14, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Forward Pass:** $O(B \cdot L \cdot 2^D \cdot C)$ operations per batch element [S11, unofficial].
*   **Backward Pass:** $O(B \cdot L \cdot 2^D \cdot N_C)$ with atomic addition overhead [S11, unofficial].
*   **Memory:** $O(\sum_{l=0}^{L-1} \text{hashmap\_size}_l \times C)$ for the embedding table [S14, unofficial]. The total number of trainable parameters is $O(T \cdot L \cdot F)$ [S15].

**Measured Performance:**
*   On NVIDIA RTX 3090, performance remains constant as long as $2 \cdot T \cdot F \le 6 \cdot 2^{20}$ (6 MB L2 cache limit) [S4, unofficial].
*   Training speed is significantly faster than dense grids or frequency encodings due to sparsity of updates and smaller MLP [S4, unofficial].
*   Rendering speeds can reach tens of milliseconds at 1920x1080 [S4, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Adaptive to training data distribution, no structural updates needed, fast convergence, small MLP size [S4, unofficial][S15].
*   **Limitations:** Hash collisions can cause artifacts if table size is too small [S9, unofficial]. Performance drops if hash table size exceeds L2 cache limits [S4, unofficial]. Half-precision atomicAdd is slow for scalar features ($F=1$) [S15].

**When to Use:**
*   Use for fast training and rendering of neural graphics primitives (NeRF, SDF, Gigapixel images) on consumer GPUs [S4, unofficial][S15].
*   Avoid if exact geometric continuity is required without interpolation or if memory is extremely constrained below the L2 cache threshold [S4, unofficial][S15].

## Background
HashGrid Encoding was introduced by Thomas Müller, Alex Evans, Christoph Schied, and Alexander Keller in the paper "Instant Neural Graphics Primitives with a Multiresolution Hash Encoding" (2022) [S4, unofficial][S15]. It was developed to address the high computational cost of training and evaluating implicit neural representations by replacing dense positional encodings with a multi-resolution hash table structure. The method has become a standard component in modern neural rendering frameworks, including Instant-NGP and various NeRF variants [S1][S2, unofficial][S15].
