# HashGrid Encoding

Also called: GridEncoding, Hash Encodings, Hash Grid Feature Interpolation, Instant NGP encoding, Instant Neural Graphics Primitives Encoding, Instant-NGP Hash Encoding, Multi-Resolution Hash Grids

## Overview
HashGrid Encoding is a parametric positional encoding method that maps continuous input coordinates to high-dimensional feature vectors using a cascade of multi-resolution hash tables [S1][S4, unofficial][S15, unofficial]. It solves the computational bottleneck of querying large implicit neural networks at every point in space by replacing dense positional encodings with sparse, trainable feature lookups, reducing model size and improving synthesis quality [S1][S2, unofficial][S4, unofficial]. It sets itself apart from dense grid methods by its spatial hashing mechanism which allocates parameters only to visited regions, and from standard NeRF by enabling significantly faster convergence and smaller MLPs [S1][S4, unofficial][S15, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tensor of coordinates $\mathbf{x} \in \mathbb{R}^{B \times D}$, where $B$ is the batch size and $D$ is the spatial dimensionality (typically 2 or 3) [S5, unofficial][S12, unofficial][S15, unofficial]. Values are expected to be normalized to the range $[0, 1]$ [S5, unofficial][S11, unofficial][S14, unofficial].
*   **Output:** A tensor of encoded features $\mathbf{y} \in \mathbb{R}^{L \times B \times C}$, where $L$ is the number of resolution levels and $C$ is the number of feature channels per level [S5, unofficial][S11, unofficial][S14, unofficial]. Optionally, the gradient of the output with respect to the input $\frac{\partial \mathbf{y}}{\partial \mathbf{x}} \in \mathbb{R}^{B \times L \times D \times C}$ is computed [S12, unofficial][S14, unofficial] (or flattened to $[B, L \cdot D \cdot C]$ [S5, unofficial][S11, unofficial]).

**Data Structures:**
The encoding relies on a set of $L$ hash tables [S4, unofficial][S15, unofficial]. The features are stored in a flattened array `embeddings` of shape `[sO, C]`, where `sO` is the total capacity across all levels [S5, unofficial][S11, unofficial][S14, unofficial].
*   **Offsets:** An integer array `offsets` of size $L+1$. `offsets[l]` is the starting index in `embeddings` for level $l$. The hash table size for level $l$ is `hashmap_size_l = offsets[l+1] - offsets[l]` [S5, unofficial][S12, unofficial][S15, unofficial].
*   **Precision:** Hash table entries are typically stored at half precision (2 bytes per entry) for memory efficiency, with a master copy in full precision for stable mixed-precision updates [S4, unofficial][S15, unofficial].

**Numbered Steps:**
1.  **Bounds Check:** If any input coordinate is outside $[0, 1]$, set outputs to 0 and return (gradients initialized to 0) [S5, unofficial][S11, unofficial].
2.  **Iterate Levels:** For each level $l$ from $0$ to $L-1$:
    a. Calculate `scale` and `resolution` using the formulas below [S5, unofficial][S12, unofficial][S15, unofficial].
    b. Map input coordinates $\mathbf{x}$ to grid space `pos` and compute integer grid coordinates `pos_grid` and fractional parts `pos` [S5, unofficial][S12, unofficial][S15, unofficial].
    c. Iterate over all $2^D$ corners of the voxel defined by `pos_grid` [S5, unofficial][S12, unofficial].
    d. For each corner, compute the local grid coordinate and the interpolation weight $w$ [S5, unofficial][S12, unofficial][S15, unofficial].
    e. Compute the hash index for the corner using the spatial hash function [S3, unofficial][S4, unofficial][S15, unofficial].
    f. Fetch the feature vectors from the `embeddings` array at the computed indices [S5, unofficial][S11, unofficial][S14, unofficial].
    g. Accumulate the weighted features into the output buffer for level $l$ [S5, unofficial][S11, unofficial][S14, unofficial].
3.  **Concatenation:** Concatenate the interpolated feature vectors from all $L$ levels to form the final encoded input [S6][S16].
4.  **Backward Pass (if requested):** Compute gradients with respect to the embeddings using atomic addition, weighted by the interpolation weights [S11, unofficial][S14, unofficial]. Compute gradients with respect to the input coordinates $\frac{\partial \mathbf{y}}{\partial \mathbf{x}}$ by summing contributions from all levels and channels [S11, unofficial][S14, unofficial].

**Formulas:**
1.  **Resolution Scale:** For level $l$, the scale factor is calculated as [S5, unofficial][S12, unofficial][S15, unofficial]:
    $$ \text{scale}_l = 2^{l \cdot S} \cdot H - 1 $$
2.  **Grid Resolution:** The integer resolution for level $l$ is [S5, unofficial][S12, unofficial][S15, unofficial]:
    $$ \text{resolution}_l = \lceil \text{scale}_l \rceil + 1 $$
3.  **Coordinate Mapping:** Input coordinates $\mathbf{x}$ are mapped to continuous grid coordinates [S5, unofficial][S12, unofficial][S15, unofficial]:
    $$ \text{pos}[d] = \mathbf{x}[d] \times \text{scale}_l + \begin{cases} 0.0 & \text{if align\_corners} \\ 0.5 & \text{otherwise} \end{cases} $$
    Integer grid coordinates and fractional parts are derived as [S5, unofficial][S12, unofficial][S15, unofficial]:
    $$ \text{pos\_grid}[d] = \lfloor \text{pos}[d] \rfloor $$
    $$ \text{pos}[d] \leftarrow \text{pos}[d] - \text{pos\_grid}[d] $$
4.  **Hash Function:** To map integer grid coordinates to hash table indices, a spatial hash function is used [S3, unofficial][S4, unofficial][S15, unofficial]:
    $$ h(\mathbf{p}) = \left( \bigoplus_{i=1}^{D} (p_i \times \pi_i) \right) \pmod T $$
    where $\oplus$ is bitwise XOR and $\pi_i$ are unique large primes [S3, unofficial][S4, unofficial][S15, unofficial]. Recommended primes for $D=3$: $\pi_1=1, \pi_2=2654435761, \pi_3=805459861$ [S3, unofficial][S4, unofficial][S15, unofficial].
5.  **Interpolation:** Features are interpolated from the $2^D$ corners of the voxel containing $\mathbf{x}$ [S4, unofficial][S15, unofficial]. For a corner index $idx \in [0, 2^D-1]$, the weight $w$ is [S5, unofficial][S12, unofficial][S15, unofficial]:
    $$ w = \prod_{d=0}^{D-1} \begin{cases} \text{pos}[d] & \text{if bit } d \text{ of } idx \text{ is 1} \\ 1 - \text{pos}[d] & \text{if bit } d \text{ of } idx \text{ is 0} \end{cases} $$
    The encoded feature for level $l$ is:
    $$ \text{enc}(\mathbf{x}, l) = \sum_{idx=0}^{2^D-1} w_{idx} \cdot \text{embeddings}[\text{index}_{idx} + ch] $$
    where $\text{index}_{idx}$ is the hash index for the corner [S5, unofficial][S15, unofficial].
6.  **Concatenation:** The final encoding is the concatenation of features from all levels [S6][S16]:
    $$ \text{enc}(\mathbf{x}; \theta) = [\text{enc}(\mathbf{x}, 0); \dots; \text{enc}(\mathbf{x}, L-1)] $$

**Parameters:**
*   $L$: Number of resolution levels. Typical value: 16 [S4, unofficial][S15, unofficial].
*   $T$: Max entries per level (hash table size). Range: $2^{14}$ to $2^{24}$. This is the primary hyper-parameter for tuning the trade-off between parameters and quality [S4, unofficial][S15, unofficial].
*   $F$: Number of feature dimensions per entry. Typical value: 2 [S4, unofficial][S15, unofficial].
*   $N_{\min}$: Coarsest resolution. Typical value: 16 [S4, unofficial][S15, unofficial].
*   $N_{\max}$: Finest resolution. Tunable to match finest detail. Typical range: $[512, 524288]$ [S4, unofficial][S15, unofficial].
*   $H$: Base resolution (resolution at level 0).
*   $S$: Scaling factor exponent. Controls exponential resolution growth [S5, unofficial][S12, unofficial].
*   `align_corners`: Boolean flag. If true, input range $[0,1]$ maps to $[0, scale]$ [S5, unofficial][S12, unofficial]. If false, adds 0.5 offset for center-aligned sampling [S5, unofficial][S12, unofficial].
*   `interp`: Interpolation type. 0 for linear, 1 for smoothstep [S12, unofficial].

**Edge Cases and Pitfalls:**
*   **Out-of-bounds inputs:** Coordinates outside $[0, 1]$ cause undefined behavior if not clamped [S12, S15, unofficial]. The implementation explicitly checks bounds and zeros outputs/grads instead of clamping [S12, S15, unofficial].
*   **Hash collisions:** Collisions occur when different integer grid coordinates hash to the same table index [S16]. The method relies on the neural network and gradient-based optimization to disambiguate these collisions without explicit handling [S16]. At fine resolutions, colliding training gradients average, meaning the largest gradients dominate, automatically prioritizing sparse areas with important fine-scale detail [S4, unofficial]. However, if the table size is too small, distant point collisions can introduce artifacts [S9].
*   **Precision and Performance:** Half-precision `atomicAdd` is slow for scalar features ($F=1$) on older architectures; vectorized `__half2` operations are used when $C$ is even [S12, unofficial][S15, unofficial]. Performance drops significantly if $2 \cdot T \cdot F > 6 \cdot 2^{20}$ (6 MB L2 cache limit on RTX 3090) [S4, unofficial]. Skipping Adam steps for zero gradients saves $\sim 10\%$ performance when gradients are sparse [S4, unofficial].
*   **Discontinuities:** Without interpolation, grid-aligned discontinuities cause a blocky appearance; linear interpolation ensures continuity of encoding and network output [S4, unofficial][S16].

**Pseudocode:**
```python
import math

def hash_grid_encode(inputs, offsets, embeddings, L, C, D, H, S, align_corners=True, interp=0):
    """
    inputs: list of lists [B, D], values in [0, 1]
    offsets: list [L+1], cumulative hash table sizes
    embeddings: list of lists [sO, C], hash table features
    L: int, number of levels
    C: int, channels per level (1, 2, 4, 8)
    D: int, input dimensions (2 or 3)
    H: float, base resolution
    S: float, scaling factor exponent
    align_corners: bool, coordinate mapping offset
    interp: int, 0 for linear, 1 for smoothstep (gradient computation omitted for brevity)
    """
    B = len(inputs)
    outputs = [[[0.0] * C for _ in range(B)] for _ in range(L)]
    primes = [1, 2654435761, 805459861] # Assumes D <= 3 [S3, unofficial][S4, unofficial]

    for l in range(L):
        scale = math.exp2(l * S) * H - 1.0
        resolution = math.ceil(scale) + 1
        hashmap_size = offsets[l+1] - offsets[l]
        start_idx = offsets[l]

        for b in range(B):
            # Bounds check
            if any(x < 0.0 or x > 1.0 for x in inputs[b]):
                continue # Skip out-of-bounds points, outputs remain 0.0 [S5, unofficial][S12, unofficial]

            # Map inputs to grid coordinates
            pos = [inputs[b][d] * scale + (0.0 if align_corners else 0.5) for d in range(D)]
            pos_grid = [math.floor(p) for p in pos]
            pos_frac = [p - pg for p, pg in zip(pos, pos_grid)]

            # Iterate over 2^D corners
            for idx in range(1 << D):
                w = 1.0
                pos_grid_local = [0] * D

                for d in range(D):
                    if (idx >> d) & 1:
                        w *= pos_frac[d]
                        pos_grid_local[d] = pos_grid[d] + 1
                    else:
                        w *= 1.0 - pos_frac[d]
                        pos_grid_local[d] = pos_grid[d]

                # Compute hash index
                h_val = 0
                for d in range(D):
                    h_val ^= pos_grid_local[d] * primes[d]
                index = (h_val % hashmap_size) * C + start_idx

                # Accumulate weighted features
                for c in range(C):
                    outputs[l][b][c] += w * embeddings[index + c]

    return outputs
```

## Subtopics

### [HashNeRF Parameters](3068-hashnerf-parameters.md)
HashNeRF Parameters define the configuration for training Neural Radiance Fields using HashGrid encoding, balancing rendering quality and training speed on consumer hardware. It differs from standard NeRF by using a sparse, multi-resolution hash grid for feature storage, and from dense voxel methods by its spatial hashing mechanism. The configuration is heavily influenced by Instant Neural Graphics Primitives (i-NGP) and ZipNeRF, optimizing for fast convergence with limited memory.

### [Progressive Training](9142-progressive-training.md)
Progressive training is a strategy for optimizing multi-resolution hash encodings that gradually activates higher resolution levels over the course of training. It solves the problem of training instability inherent in hash-based neural fields: using only low-resolution grids leads to underfitting (smooth geometry lacking details), while using all high-resolution grids from the start causes overfitting to specific camera views, resulting in noise, artifacts, and view inconsistency. By starting with coarse levels and incrementally introducing finer details, the method ensures view consistency and efficient convergence. It differs from simultaneous multi-resolution training by freezing higher-resolution grids until their activation step and applying multi-rate-distortion supervision.

### [Dense Grid Encoding](9335-dense-grid-encoding.md)
Dense Grid Encoding is a parametric input encoding method that maps input coordinates to multi-dimensional feature vectors by storing trainable parameters in a dense, regular grid structure. It solves the problem of efficiently representing high-frequency scene details in neural radiance fields (NeRF) by trading a larger memory footprint for reduced computational cost during training. Unlike fixed frequency encodings, it allows the network to learn spatially varying features, but unlike sparse or hash-based variants, it allocates parameters uniformly across the entire domain, which can be wasteful in empty space.

### [ACORN](9336-acorn.md)
ACORN is a parametric feature encoding method that uses a tree subdivision of the input domain to output dense feature grids in leaf nodes, which are then linearly interpolated. It yields a greater degree of adaptivity compared with previous parametric encodings, albeit at greater computational cost.

### [Multi-resolution Hash Encoding](10200-multi-resolution-hash-encoding.md)
Multi-resolution Hash Encoding (MERH) accelerates neural radiance field (NeRF) training and rendering by replacing the slow, deep multi-layer perceptron (MLP) of vanilla NeRF with a trainable, multi-resolution hash grid. It maps 3D coordinates to high-dimensional feature vectors via hash table lookups and trilinear interpolation, which are then decoded by a shallow neural network to predict density and color. It sets itself apart from standard NeRF by achieving significant reductions in learning time and convergence iterations through a generic, trainable encoding that allows the network to be shallow with fewer parameters.

### [RHINO](10245-rhino.md)
RHINO is a regularization framework for hash-based Implicit Neural Representations (INRs) that restores interpolation quality by introducing an additional input coordinate with an analytical and continuous transformation $T$ to the network, compensating for the broken gradient flow between input coordinates and hash-keys. It solves the problem of discontinuous and noisy interpolation in unsampled regions caused by the non-analytical mapping from spatial coordinates to hash keys. Unlike [Instant-NGP](6604-instant-ngp.md) which relies solely on hash-based indexing, RHINO rebuilds the connection between the input space and the network output, ensuring that interpolation follows spectral bias.

### [HollowNeRF Saliency Grid Weighting](10745-hollownerf-saliency-grid-weighting.md)
HollowNeRF Saliency Grid Weighting is a collision mitigation technique for hash grid-based neural radiance fields that learns a 3D probability distribution of feature presence to weight feature vectors fetched from a multi-level hashgrid. Unlike Instant-NGP, which distributes hash collisions evenly across voxels, this method learns to "shuffle" collisions by assigning higher saliency weights to important features, allowing them to dominate shared hash buckets during gradient updates while pruning less significant features.

### [TetraHashGridEncode](13232-tetrahashgridencode.md)
TetraHashGridEncode is a differentiable hash grid encoding method for 3D coordinates that utilizes tetrahedral decomposition for interpolation, implemented via CUDA extensions for forward and backward passes. It builds on [HashGrid Encoding](3866-hashgrid-encoding.md) by replacing standard trilinear interpolation within hash-grid cells with barycentric interpolation over a fixed tetrahedral decomposition, allowing for efficient training of neural radiance fields (NeRF) on consumer GPUs.

### [Vanishing Point Aided Hash-Frequency Encoding](13623-vanishing-point-aided-hash-frequency-encoding.md)
Vanishing Point Aided Hash-Frequency Encoding is a neural radiance field encoding scheme that combines multi-resolution hash encoding with deterministic frequency encoding aligned to scene structure via vanishing points. It solves the problem of poor reconstruction quality from sparse 360° inputs, where standard hash encoding fails due to lack of learnable explicit structure and sensitivity to imperfect scene centering. Unlike standard hash encoding which relies solely on learnable features, this method adds deterministic frequency features to improve generalizability and robustness without requiring additional depth information or pre-training.

### [Instant Neural Graphics Primitives with a Hash Encoding](15672-instant-neural-graphics-primitives-with-a-hash-encoding.md)
Instant Neural Graphics Primitives with a Hash Encoding (Instant-NGP) is a method that drastically reduces the training time of Neural Radiance Fields (NeRF) from days to minutes and enables interactive rendering speeds by replacing traditional positional encoding with a multi-resolution hash grid. It achieves this by mapping 3D coordinates to a sparse set of learnable feature vectors via spatial hashing, allowing the network to capture high-frequency details with significantly fewer queries than dense grid structures.

### [Spatially-Adaptive Hash Encoding](19095-spatially-adaptive-hash-encoding.md)
Splitting feature hash grids into an SDF representation and a smaller spatial mask hash grid to adaptively weight the contribution of different resolution levels.

## Operating characteristics
**Time and Memory Complexity:**
*   **Forward Pass:** $O(B \cdot L \cdot 2^D \cdot C)$ operations per batch element [S12, unofficial].
*   **Backward Pass:** $O(B \cdot L \cdot 2^D \cdot N_C)$ with atomic addition overhead [S12, unofficial].
*   **Memory:** $O(\sum_{l=0}^{L-1} \text{hashmap\_size}_l \times C)$ for the embedding table [S14, unofficial]. The total number of trainable parameters is $O(T \cdot L \cdot F)$ [S15, unofficial].

**Measured Performance:**
*   On NVIDIA RTX 3090, performance remains constant as long as $2 \cdot T \cdot F \le 6 \cdot 2^{20}$ (6 MB L2 cache limit) [S4, unofficial].
*   Training speed is significantly faster than dense grids or frequency encodings due to sparsity of updates and smaller MLP [S4, unofficial].
*   Rendering speeds can reach tens of milliseconds at 1920x1080 [S4, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Adaptive to training data distribution, no structural updates needed, fast convergence, small MLP size [S4, unofficial][S15, unofficial].
*   **Limitations:** Hash collisions can cause artifacts if table size is too small [S9]. Performance drops if hash table size exceeds L2 cache limits [S4, unofficial]. Half-precision atomicAdd is slow for scalar features ($F=1$) [S15, unofficial].

**When to Use:**
*   Use for fast training and rendering of neural graphics primitives (NeRF, SDF, Gigapixel images) on consumer GPUs [S4, unofficial][S15, unofficial].
*   Avoid if exact geometric continuity is required without interpolation or if memory is extremely constrained below the L2 cache threshold [S4, unofficial][S15, unofficial].

## Background
HashGrid Encoding was introduced by Thomas Müller, Alex Evans, Christoph Schied, and Alexander Keller in the paper "Instant Neural Graphics Primitives with a Multiresolution Hash Encoding" (2022) [S4, unofficial][S15, unofficial]. It was developed to address the high computational cost of training and evaluating implicit neural representations by replacing dense positional encodings with a multi-resolution hash table structure [S4, unofficial]. The method has become a standard component in modern neural rendering frameworks, including Instant-NGP and various NeRF variants [S1][S2, unofficial][S15, unofficial].
