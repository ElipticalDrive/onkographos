# HashGrid Encoding

Also called: GridEncoding, Hash Encodings, Hash Grid Feature Interpolation, Instant NGP encoding, Instant Neural Graphics Primitives Encoding

## Overview
HashGrid Encoding maps continuous spatial coordinates to high-dimensional feature vectors using a multi-resolution hierarchy of spatial hash tables, enabling efficient training and rendering of neural graphics primitives [S3, unofficial][S13]. It solves the problem of high computational cost and memory usage in traditional implicit neural representations by replacing expensive positional encodings and large MLPs with a compact, trainable feature grid [S3, unofficial][S13]. Unlike dense grid encodings, it avoids wasting memory on empty space by using hash collisions to automatically prioritize relevant areas via gradient averaging, and unlike tree-based encodings, it avoids execution divergence by using O(1) hash lookups [S3, unofficial][S13].

## How it works
**Inputs and Outputs:**
*   **Input:** A batch of $B$ input coordinate vectors $\mathbf{x} \in \mathbb{R}^{B \times D}$, where $D$ is the spatial dimensionality (typically 2 or 3). Values are expected in the normalized range $[0, 1]$ [S9, S12, unofficial].
*   **Output:** A concatenated feature vector $\mathbf{y} \in \mathbb{R}^{B \times (L \cdot C)}$, where $L$ is the number of resolution levels and $C$ is the number of feature channels per level [S9, unofficial][S13].
*   **Backward Output:** Gradient of the output with respect to the input, $\frac{\partial \mathbf{y}}{\partial \mathbf{x}} \in \mathbb{R}^{B \times L \times D \times C}$ [S9, S12, unofficial].

**Data Structures:**
The encoding consists of $L$ hash tables. Each level $l \in \{0, \dots, L-1\}$ has a hash table of size $T_l$ (entries) and stores feature vectors of dimension $C$.
*   **Embeddings:** A flattened tensor `embeddings` of shape $[sO, C]$, where $sO = \sum_{l=0}^{L-1} T_l$ is the total number of entries across all levels [S9, S12, unofficial].
*   **Offsets:** An integer array `offsets` of shape $[L+1]$. `offsets[l]` is the starting index in `embeddings` for level $l$. The size of level $l$ is $T_l = \text{offsets}[l+1] - \text{offsets}[l]$ [S9, S12, unofficial].
*   **Precision:** Entries are stored at half precision (2 bytes) for memory efficiency, with a master copy in full precision for stable mixed-precision updates [S3, unofficial][S13].

**Parameters:**
*   $L$: Number of resolution levels. Typical value: 16 [S3, unofficial][S13].
*   $C$: Number of feature channels per level. Supported values: 1, 2, 4, 8. Optimal trade-off is $C=2$ [S9, S12, S3, unofficial].
*   $T$: Max entries per level (hash table size). Tunable hyper-parameter trading parameters for quality. Typical range: $[2^{14}, 2^{24}]$ [S3, unofficial][S13].
*   $N_{\min}$: Coarsest resolution. Typical value: 16 [S3, unofficial][S13].
*   $N_{\max}$: Finest resolution. Tunable to match finest detail. Typical range: $[512, 524288]$ [S3, unofficial][S13].
*   $S$: Scale factor exponent determining resolution growth per level [S4, S9, unofficial].
*   $H$: Base resolution (grid size at level 0) [S9, S12, unofficial].
*   $\text{gridtype}$: Hashing strategy. 0 = Hash (uses fast_hash), 1 = Tiled (linear indexing) [S4, S9, unofficial].
*   $\text{align\_corners}$: Boolean flag. If true, coordinate mapping adds 0.0 offset; if false, adds 0.5 offset for center-aligned sampling [S9, S4, unofficial].
*   $\text{interp}$: Interpolation type. 0 = linear, 1 = smoothstep [S9, unofficial].

**Formulas:**
1.  **Resolution Scale:** For level $l$, the scale factor is:
    $$ \text{scale}_l = \exp_2(l \cdot S) \cdot H - 1.0 $$
    Alternatively, using geometric progression between $N_{\min}$ and $N_{\max}$:
    $$ N_l = \lfloor N_{\min} \cdot b^l \rfloor, \quad b = \exp\left(\frac{\ln(N_{\max}) - \ln(N_{\min})}{L - 1}\right) $$
    [S4, S9, unofficial][S13]

2.  **Grid Resolution:** The integer grid resolution for level $l$ is:
    $$ \text{resolution}_l = \lceil \text{scale}_l \rceil + 1 $$
    [S9, S12, unofficial]

3.  **Coordinate Mapping:** Input coordinates $\mathbf{x}$ are mapped to continuous grid coordinates $\mathbf{pos}$:
    $$ \text{pos}[d] = \mathbf{x}[d] \cdot \text{scale}_l + (\text{align\_corners} ? 0.0 : 0.5) $$
    [S4, S9, S12, unofficial]

4.  **Integer and Fractional Coordinates:**
    $$ \text{pos\_grid}[d] = \lfloor \text{pos}[d] \rfloor $$
    $$ \text{pos}[d] \leftarrow \text{pos}[d] - \text{pos\_grid}[d] $$
    [S4, S9, S12, unofficial]

5.  **Hash Function:** Maps integer grid coordinates $\text{pos\_grid}$ to a hash table index. Using unique large primes $\pi_i$ (where $\pi_1=1$ for cache coherence):
    $$ h(\text{pos\_grid}) = \left( \bigoplus_{i=0}^{D-1} (\text{pos\_grid}[i] \cdot \pi_i) \right) \pmod{T_l} $$
    [S13][S4, unofficial]
    Specific primes for $D \le 7$: $\pi = [1, 2654435761, 805459861, 3674653429, 2097192037, 1434869437, 2165219737]$ [S4, unofficial].

6.  **Trilinear Interpolation:** For each of the $2^D$ corners of the voxel defined by $\text{pos\_grid}$, indexed by $idx \in [0, 2^D-1]$:
    *   Local grid coordinate: $\text{pos\_grid\_local}[d] = \text{pos\_grid}[d] + ((idx \gg d) \& 1)$
    *   Weight: $w = \prod_{d=0}^{D-1} (\text{pos}[d] \text{ if } ((idx \gg d) \& 1) \text{ else } 1 - \text{pos}[d])$
    *   Feature contribution: $\mathbf{f}_{idx} = w \cdot \text{embeddings}[\text{index}_{idx} + \text{offsets}[l]]$
    *   Where $\text{index}_{idx} = h(\text{pos\_grid\_local}) \cdot C + \text{channel}$
    [S4, S9, S12, unofficial][S13]

**Algorithm Steps:**
1.  **Input Validation:** Check if any coordinate in $\mathbf{x}$ is outside $[0, 1]$. If so, set output features and gradients to 0 and return [S4, S9, unofficial].
2.  **Level Iteration:** Iterate through each level $l$ from 0 to $L-1$. This order optimizes GPU cache usage by keeping one level's hash table in cache at a time [S3, unofficial].
3.  **Scale Calculation:** Compute $\text{scale}_l$ and $\text{resolution}_l$ using the parameters [S4, S9, S12, unofficial].
4.  **Coordinate Transformation:** For each input point $\mathbf{x}_b$, compute $\text{pos}[d]$ and $\text{pos\_grid}[d]$ for all dimensions $d$ [S4, S9, S12, unofficial].
5.  **Hash Lookup and Interpolation:**
    *   For each of the $2^D$ corners:
        *   Compute $\text{pos\_grid\_local}$ and weight $w$ [S4, S9, S12, unofficial].
        *   Compute hash index $\text{index} = h(\text{pos\_grid\_local})$ [S4, S9, S12, unofficial].
        *   Fetch feature vector from `embeddings` at `offsets[l] + index * C` [S4, S9, S12, unofficial].
        *   Accumulate weighted features into the output buffer for level $l$ [S4, S9, S12, unofficial].
6.  **Concatenation:** Concatenate the feature vectors from all levels $l$ to form the final encoded input $\mathbf{y}$ [S5, S13].
7.  **Backward Pass (Gradients):**
    *   **Embedding Gradients:** For each corner, compute the gradient of the loss w.r.t. the fetched features, weighted by $w$, and accumulate into the embedding table using `atomicAdd` [S4, S9, S12, unofficial]. Note: `atomicAdd` on half-precision is slow; use `__half2` vectorization if $C$ is even [S4, S9, S12, unofficial].
    *   **Input Gradients:** Compute $\frac{\partial \mathbf{y}}{\partial \mathbf{x}}$. For each dimension $gd$, initialize gradient accumulator. Loop over $2^{D-1}$ neighbors fixing $gd$. Compute weight $w$ for other dimensions. Fetch left/right grid values at $\text{pos\_grid}[gd]$ and $\text{pos\_grid}[gd]+1$. Accumulate: $\text{results\_grad} += w \cdot (\text{grid}_{\text{right}} - \text{grid}_{\text{left}}) \cdot \text{scale}_l \cdot \text{pos\_deriv}[gd]$ [S4, S9, S12, unofficial]. If $\text{interp}=1$ (smoothstep), $\text{pos\_deriv}[d] = 6 \cdot \text{pos}[d] \cdot (1 - \text{pos}[d])$ [S9, unofficial].

## Subtopics

### [Progressive Training](9142-progressive-training.md)
Progressive training is a strategy for optimizing multi-resolution hash encodings that gradually activates higher resolution levels over the course of training. It solves the problem of training instability inherent in hash-based neural fields: using only low-resolution grids leads to underfitting (smooth geometry lacking details), while using all high-resolution grids from the start causes overfitting to specific camera views, resulting in noise, artifacts, and view inconsistency. By starting with coarse levels and incrementally introducing finer details, the method ensures view consistency and efficient convergence. It differs from [Instant-NGP](6604-instant-ngp.md) primarily in its explicit multi-rate-distortion supervision and residual grid freezing mechanisms, and from [Dense Grid Encoding](9335-dense-grid-encoding.md) by leveraging spatial hashing for memory efficiency.

### [Dense Grid Encoding](9335-dense-grid-encoding.md)
Dense Grid Encoding is a parametric input encoding method that maps input coordinates to multi-dimensional feature vectors by storing trainable parameters in a dense, regular grid structure. It solves the problem of efficiently representing high-frequency scene details in neural radiance fields (NeRF) by trading a larger memory footprint for reduced computational cost during training. Unlike fixed frequency encodings, it allows the network to learn spatially varying features, but unlike sparse or hash-based variants, it allocates parameters uniformly across the entire domain, which can be wasteful in empty space.

### [ACORN](9336-acorn.md)
ACORN is a parametric feature encoding method that uses a tree subdivision of the input domain to output dense feature grids in leaf nodes, which are then linearly interpolated. It yields a greater degree of adaptivity compared with previous parametric encodings, albeit at greater computational cost.

### [Multi-resolution Hash Encoding](10200-multi-resolution-hash-encoding.md)
Multi-resolution Hash Encoding (MHE) is a feature encoding method that maps 3D spatial coordinates to a high-dimensional feature vector using a set of trainable, sparse hash grids at multiple resolutions, enabling efficient neural rendering by replacing expensive positional encoding and large MLPs with a compact, trainable representation. It solves the problem of slow training times and high memory consumption associated with traditional NeRF models by allowing the encoding itself to be trained alongside a shallow network, achieving faster convergence and reduced parameter counts. Unlike its siblings, it relies on a fixed-size hash table structure with trilinear interpolation and a specific hash function, whereas alternatives may use simplex structures, tetrahedron querying, or global preconditioners.

### [RHINO](10245-rhino.md)
RHINO is a regularization framework for hash-based Implicit Neural Representations (INRs) that restores interpolation quality by introducing an additional input coordinate with an analytical and continuous transformation $T$ to the network, compensating for the broken gradient flow between input coordinates and hash-keys. It solves the problem of discontinuous and noisy interpolation in unsampled regions caused by the non-analytical mapping from spatial coordinates to hash keys. Unlike [Instant-NGP](6604-instant-ngp.md) which relies solely on hash-based indexing, RHINO rebuilds the connection between the input space and the network output, ensuring that interpolation follows spectral bias.

### [HollowNeRF Saliency Grid Weighting](10745-hollownerf-saliency-grid-weighting.md)
HollowNeRF Saliency Grid Weighting is a collision mitigation technique for hash grid-based neural radiance fields that learns a 3D probability distribution of feature presence to weight feature vectors fetched from a multi-level hashgrid. Unlike Instant-NGP, which distributes hash collisions evenly across voxels, this method learns to "shuffle" collisions by assigning higher saliency weights to important features, allowing them to dominate shared hash buckets during gradient updates while pruning less significant features.

### [TetraHashGridEncode](13232-tetrahashgridencode.md)
TetraHashGridEncode is a differentiable hash grid encoding method for 3D coordinates that utilizes tetrahedral decomposition for interpolation, implemented via CUDA extensions for forward and backward passes. It builds on [HashGrid Encoding](3866-hashgrid-encoding.md) by replacing standard trilinear interpolation within hash-grid cells with barycentric interpolation over a fixed tetrahedral decomposition, allowing for efficient training of neural radiance fields (NeRF) on consumer GPUs.

## Operating characteristics
*   **Time Complexity:** Forward pass is $O(B \cdot L \cdot 2^D \cdot C)$ operations per batch element [S9, unofficial]. Backward grid pass is $O(B \cdot L \cdot 2^D \cdot N_C)$ with atomicAdd overhead [S9, unofficial].
*   **Memory Complexity:** $O(\sum_{l=0}^{L-1} \text{hashmap\_size}_l \times C)$ for the embedding table [S12, unofficial]. Total parameters are $O(T \cdot L \cdot F)$ [S13].
*   **Performance:** Training is over 8x faster than frequency encoding with similar parameter counts, achieving state-of-the-art quality in seconds [S3, unofficial][S13]. Rendering takes tens of milliseconds at 1920x1080 resolution [S3, unofficial][S13].
*   **Scaling:** Performance remains constant as long as hash table size $T \le 2^{19}$ on RTX 3090. Beyond this, L2 cache oversubscription causes significant performance drops [S3, unofficial][S13].
*   **Strengths:** High training speed, low memory footprint compared to dense grids, adaptive to training data distribution, no structural updates needed [S3, unofficial][S13].
*   **Limitations:** Hash collisions can cause surface roughness in SDFs [S3, unofficial]. Performance sensitive to hash table size relative to GPU cache [S3, unofficial]. Half-precision atomicAdd is slow for scalar features ($C=1$) [S3, S12, unofficial].
*   **When to Use:** When fast training and rendering of neural graphics primitives (NeRF, SDF, images) are required on consumer GPUs [S3, unofficial].
*   **When Not to Use:** When exact geometric continuity (C1/C2) is required without post-processing, or when hash collisions cause unacceptable artifacts in specific applications like SDFs [S3, unofficial].

## Background
HashGrid Encoding was introduced by Thomas Müller, Alex Evans, Christoph Schied, and Alexander Keller in 2022 in the paper "Instant Neural Graphics Primitives with a Multiresolution Hash Encoding" [S3, unofficial]. It was developed to address the high computational cost and slow training times of previous neural graphics primitives, such as those using frequency encodings or tree-based structures like ACORN [S3, unofficial][S13]. The method leverages spatial hashing to create a compact, trainable feature representation that can be optimized using stochastic gradient descent, enabling training in seconds rather than hours [S3, unofficial][S13]. It has become a standard component in many modern neural rendering frameworks, including Instant-NGP [S3, unofficial][S13].
