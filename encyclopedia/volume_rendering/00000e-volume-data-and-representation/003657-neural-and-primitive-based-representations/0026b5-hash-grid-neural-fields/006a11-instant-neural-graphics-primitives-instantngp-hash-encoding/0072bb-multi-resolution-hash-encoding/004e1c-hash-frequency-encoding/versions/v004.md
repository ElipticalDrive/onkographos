# Hash-Frequency Encoding
Also called: Composited Encoding, HE+FE

## Overview
Hash-Frequency Encoding (HE+FE) combines hash encoding (HE) and frequency encoding (FE) levels to enhance performance on sparse inputs [S1]. It addresses the severe performance degradation and artifact generation (floaters) that standard hash-only encoders exhibit with sparse views [S1]. Unlike hash-only baselines, HE+FE augments hash lookups with frequency levels to stabilize reconstruction, while training significantly faster than frequency-only alternatives like MIP-NeRF 360 [S1].

## How it works
**Inputs and Outputs:**
- Input: 3D spatial coordinates $\mathbf{x} \in \mathbb{R}^3$ [S1].
- Output: Concatenated feature vector combining hash and frequency components [G].

**Data Structures:**
1. **Hash Grids:** A set of $L_{hash}$ resolution levels [G]. Each level $l$ consists of a hash table mapping hashed coordinate indices to feature vectors of size $d$ [G].
2. **Frequency Levels:** A set of $L_{freq}$ frequency levels [G]. Each level $l$ defines a set of sinusoidal basis functions [G].

**Parameters:**
- $L_{hash}$: Number of hash grid levels. Fixed at 16 [S1].
- $L_{freq}$: Number of frequency levels. Swept across 2, 4, 8, 16. Optimal setting is 8 (HE + FE8) [S1].
- $d$: Feature dimension per hash level. Standard Instant-NGP values are 2 or 4 [G].
- $s_l$: Voxel size at level $l$ [G].
- $\omega_l$: Frequency multiplier at level $l$ [G].
- $\mathbf{v}_l$: Feature vector retrieved from the hash table at level $l$ [G].
- $\mathbf{f}_{freq}$: Concatenated frequency feature vector [G].
- $\mathbf{f}$: Final output feature vector [G].

**Algorithm:**
The encoding process computes features from both components and concatenates them [G].
1. **Hash Encoding Step:**
   For each hash level $l \in \{0, \dots, L_{hash}-1\}$:
   a. Compute the voxel size $s_l$ for level $l$ [G].
   b. Compute the voxel index $\mathbf{i}_l = \lfloor \mathbf{x} / s_l \rfloor$ [G].
   c. Compute the hash index $h_l = \text{Hash}(\mathbf{i}_l) \pmod{N_l}$, where $N_l$ is the table size for level $l$ [G].
   d. Retrieve the feature vector $\mathbf{v}_l$ from the hash table at index $h_l$ [G].
   e. Store $\mathbf{v}_l$ for later concatenation [G].
2. **Frequency Encoding Step:**
   For each frequency level $l \in \{0, \dots, L_{freq}-1\}$:
   a. Compute the frequency multiplier $\omega_l$ using standard sinusoidal encoding spacing (e.g., $\omega_l = 2^l$ or linear spacing) [G].
   b. Compute the sinusoidal features for each dimension $k \in \{1, 2, 3\}$ of $\mathbf{x}$: $\sin(2\pi \omega_l x_k)$, $\cos(2\pi \omega_l x_k)$ [G].
   c. Concatenate these values into the frequency feature vector $\mathbf{f}_{freq}$ [G].
3. **Concatenation:**
   $\mathbf{f} = [\mathbf{v}_0, \dots, \mathbf{v}_{L_{hash}-1}, \mathbf{f}_{freq}]$ [G].

**Pseudocode:**
```python
def hash_frequency_encoding(x, hash_grids, freq_levels):
    """
    x: Array of shape (..., 3) containing 3D coordinates.
    hash_grids: List of L_hash arrays, each of shape (N_l, d).
    freq_levels: List of L_freq frequency multipliers.
    Returns: Concatenated feature array.
    """
    hash_features = []
    
    # Hash Encoding
    for l in range(len(hash_grids)):
        grid = hash_grids[l]
        # Compute voxel indices based on resolution level l [G]
        base_res = 16.0
        voxel_size = base_res * (2.0 ** l)
        voxel_indices = floor(x / voxel_size)
        
        # Hash the indices to get table indices [G]
        table_indices = simple_hash(voxel_indices) % grid.shape[0]
        
        # Gather features
        features = grid[table_indices]
        hash_features.append(features)
        
    # Frequency Encoding
    freq_features = []
    for omega in freq_levels:
        # Compute sinusoidal features for each dimension [G]
        scaled_x = x * omega * 2 * 3.14159265359
        sin_features = sin(scaled_x)
        cos_features = cos(scaled_x)
        freq_features.append(sin_features)
        freq_features.append(cos_features)
        
    # Concatenate all features
    all_features = hash_features + freq_features
    return concatenate(all_features, axis=-1)

def simple_hash(v):
    """Deterministic integer hash function [G]."""
    v = v & 0xFFFFFFFF
    v = (v ^ 61) ^ (v >> 16)
    v = v ^ (v >> 7)
    v = v ^ (v >> 4)
    v = v ^ (v >> 2)
    v = v ^ (v >> 1)
    v = v * 0x27d4eb2d
    v = v ^ (v >> 15)
    return v
```

**Edge Cases and Pitfalls:**
- **Sparse Inputs:** Standard hash encoding degrades heavily with sparse inputs [S1]. HE+FE mitigates this by adding frequency information [S1].
- **Frequency Level Selection:** Too few frequency levels may not capture high-frequency details; too many may increase memory and computation without benefit [G]. Optimal is 8 [S1].
- **Training Time:** While slower than pure hash encoding, it is significantly faster than pure frequency encoding (5 mins vs 2 hours on a single NVIDIA A40) [S1].
- **Normal Camera Setups:** May not be optimal for normal camera setups compared to sparse ones [S1].

## Subtopics

### [Vanishing Point Aligned Frequency Encoding](14036-vanishing-point-aligned-frequency-encoding.md)
Aligns sinusoidal positional encoding with scene structures using estimated vanishing points, ensuring points on the same spatial line share the same mapping of specific encoding levels. Chosen for axis-aligned structures in 360° images.

## Operating characteristics
- **Performance:** HE + FE8 provides stable PSNR, SSIM, and LPIPS on synthetic datasets (Classroom, Lone Monk) with sparse (2x2x2) and normal (3x3x2) camera setups [S1].
- **Comparison:** Outperforms Nerfacto (hash-only) on sparse inputs, avoiding degradation and floaters [S1]. Comparable to MIP-NeRF 360 (frequency-only) in quality but trains much faster (5 minutes vs 2 hours on a single NVIDIA A40) [S1].
- **Limitations:** May not be optimal for normal camera setups compared to sparse ones [S1].

## Background
Originated in the paper "Vanishing Point Aided Hash-Frequency Encoding for Neural Radiance Fields (NeRF) from Sparse 360° Input" [S1]. It was developed to address the limitations of hash-only encoders (like Nerfacto) when dealing with sparse 360° input data, combining the strengths of hash encoding and frequency encoding [S1].
