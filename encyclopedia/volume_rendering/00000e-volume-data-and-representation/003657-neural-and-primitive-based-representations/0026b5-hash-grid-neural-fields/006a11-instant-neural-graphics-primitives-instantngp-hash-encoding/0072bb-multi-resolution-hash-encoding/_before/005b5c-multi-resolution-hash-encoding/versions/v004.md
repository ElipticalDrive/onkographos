# Multi-resolution Hash Encoding

Also called: Instant-NGP Hash Encoding, Instant-NGP Multiresolution Hash Encoding, NGP hash encoding, Multi-scale Hash Encoding, Multiresolution Hash Grid Model

## Overview
Multi-resolution Hash Encoding (MHE) is a feature embedding method that maps 3D spatial coordinates to a high-dimensional feature vector using a set of trainable hash tables at multiple resolutions, enabling efficient neural scene representation [S2]. It solves the problem of slow training and rendering in Neural Radiance Fields (NeRF) by replacing the large, deep Multi-Layer Perceptron (MLP) with a multi-resolution learnable hash grid [S3, unofficial]. This design leverages GPU-optimized hash table lookups to reduce MLP depth and width substantially, achieving a 1000–10,000× training speedup compared to vanilla NeRF while maintaining comparable rendering quality [S1]. It sets itself apart from traditional positional encoding by replacing fixed basis functions with learnable parameters stored in sparse hash grids, significantly reducing memory usage and training time while maintaining high reconstruction quality [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D spatial coordinate $\mathbf{x} \in \mathbb{R}^3$ (and optionally a viewing direction $\mathbf{d}$).
*   **Output:** A concatenated feature vector $\mathbf{F} \in \mathbb{R}^{L \cdot F}$, where $L$ is the number of resolution levels and $F$ is the feature dimension per level. This vector is fed into a small MLP (decoder) to predict density and color.

**Data Structures:**
The encoding consists of $L$ levels. Each level $l$ has a hash table with $T$ entries. Each entry stores a learnable feature vector of dimension $F$.
*   **Hash Table Layout:** A 1D array of size $T$. Each element is a vector of size $F$.
*   **Resolution Layout:** Level $l$ corresponds to a conceptual 3D grid of resolution $N_l$.
*   **Total Parameters:** $L \times T \times F$ for the hash tables, plus the decoder MLP parameters.

**Parameters (Typical Values):**
*   Number of levels $L$: 16–20 [S4][S7, unofficial].
*   Hash table size $T$: $2^{19}$ is a common default, balancing cache locality and capacity [S6, unofficial][S14]. Performance drops significantly if $2 \cdot T \cdot F > 6 \text{ MB}$ (L2 cache limit on RTX 3090) [S14].
*   Feature dimension $F$: 2–4 per level. $F=2$ provides the best cost-quality trade-off on tested GPUs [S7, unofficial][S14].
*   Minimum resolution $N_{\min}$: 16 [S5][S7, unofficial].
*   Maximum resolution $N_{\max}$: 512–2048 [S5][S7, unofficial].
*   Hash table entry precision: Half precision (2 bytes) for storage, with a master copy in full precision for stable mixed-precision parameter updates [S14].

**Algorithm:**

1.  **Define Resolutions:** Calculate the resolution $N_l$ for each level $l \in [1, L]$. The resolutions grow exponentially between $N_{\min}$ and $N_{\max}$:
    $$ N_l = \lfloor N_{\min} \cdot b^{l-1} \rfloor $$
    where $b = (N_{\max} / N_{\min})^{1/(L-1)}$ [S10, unofficial]. Alternatively, $b = 2^{\frac{\log_2(N_{\max}/N_{\min})}{L}}$ [S5].

2.  **Hash Function:** Define a spatial hash function $h: \mathbb{Z}^3 \to \mathbb{Z}_T$ that maps integer grid coordinates to hash table indices. A common implementation uses bit-wise XOR with large unique prime numbers $\pi_i$:
    $$ h(i, j, k) = (i \cdot \pi_1 \oplus j \cdot \pi_2 \oplus k \cdot \pi_3) \pmod T $$
    where $\pi_1 = 1$, $\pi_2 = 2,654,435,761$, and $\pi_3 = 805,459,861$ [S10, unofficial].

3.  **Query for Each Level:** For a given input point $\mathbf{x}$ and level $l$:
    a.  **Grid Coordinates:** Compute the fractional grid coordinates by scaling $\mathbf{x}$ by $N_l$. Determine the integer coordinates of the cell containing $\mathbf{x}$:
        $$ \mathbf{c}_{\text{floor}} = \lfloor \mathbf{x} \cdot N_l \rfloor, \quad \mathbf{c}_{\text{ceil}} = \lceil \mathbf{x} \cdot N_l \rceil $$
        These define the 8 vertices of the cell in $\mathbb{Z}^3$ [S5].
    b.  **Hash Lookup:** Map each of the 8 vertices to hash table indices using $h$. Retrieve the corresponding $F$-dimensional feature vectors from the hash table for level $l$. Let these be $\mathbf{v}_1, \dots, \mathbf{v}_8$ [S10, unofficial].
    c.  **Interpolation:** Perform trilinear interpolation of the 8 feature vectors based on the relative position of $\mathbf{x}$ within the cell. To improve continuity of high-level features, a second-order continuous interpolation weight function $d(x)$ can be used instead of linear weights:
        $$ d(x) = 6x^5 - 15x^4 + 10x^3 $$
        where $x$ is the fractional coordinate component [S5]. Let the interpolated feature vector for level $l$ be $\mathbf{f}_l \in \mathbb{R}^F$ [S10, unofficial].

4.  **Concatenation:** Concatenate the feature vectors from all $L$ levels to form the final input vector:
    $$ \mathbf{F} = [\mathbf{f}_1; \mathbf{f}_2; \dots; \mathbf{f}_L] \in \mathbb{R}^{L \cdot F} $$
    [S6, S10, unofficial].

5.  **Decoding:** Feed $\mathbf{F}$ (and optionally view direction $\mathbf{d}$ encoded via Spherical Harmonics or Fourier features) into a small MLP to predict density $\sigma$ and color $\mathbf{c}$ [S10, unofficial].

**Pseudocode:**

```python
import numpy as np

def multi_resolution_hash_encode(x, L, N_min, N_max, T, F, hash_tables, primes):
    """
    x: numpy array of shape (3,), input 3D coordinate
    L: int, number of levels
    N_min: float, minimum grid resolution
    N_max: float, maximum grid resolution
    T: int, hash table size
    F: int, feature dimension per level
    hash_tables: list of L numpy arrays, each of shape (T, F)
    primes: tuple of 3 large prime numbers (pi1, pi2, pi3)
    """
    pi1, pi2, pi3 = primes
    features = []
    
    # Calculate resolution ratio b
    # Using formula from [S10, unofficial]: b = (N_max / N_min)^(1/(L-1))
    b = (N_max / N_min) ** (1.0 / (L - 1))
    
    for l in range(L):
        # Calculate resolution for this level
        N_l = int(np.floor(N_min * (b ** l)))
        
        # 1. Compute grid coordinates
        # Scale x by resolution
        scaled_x = x * N_l
        
        # Floor and ceil to get cell corners
        c_floor = np.floor(scaled_x).astype(int)
        c_ceil = np.ceil(scaled_x).astype(int)
        
        # Relative position within the cell (fractional part)
        # Note: scaled_x - c_floor gives the fractional part [0, 1)
        frac = scaled_x - c_floor
        
        # 2. Identify 8 vertices
        # Vertices are combinations of floor/ceil for x, y, z
        # Indices: 000, 001, 010, 011, 100, 101, 110, 111
        # where bit 0 is x, bit 1 is y, bit 2 is z
        vertices = []
        for i in range(8):
            vx = c_floor[0] if (i & 1) == 0 else c_ceil[0]
            vy = c_floor[1] if (i & 2) == 0 else c_ceil[1]
            vz = c_floor[2] if (i & 4) == 0 else c_ceil[2]
            vertices.append((vx, vy, vz))
            
        # 3. Hash lookup
        # Retrieve feature vectors for all 8 vertices
        vertex_features = []
        for (vx, vy, vz) in vertices:
            # Hash function: (vx * pi1 ^ vy * pi2 ^ vz * pi3) % T
            h_idx = (vx * pi1 ^ vy * pi2 ^ vz * pi3) % T
            # Get feature vector from hash table for level l
            feat = hash_tables[l][h_idx]
            vertex_features.append(feat)
            
        vertex_features = np.array(vertex_features) # Shape (8, F)
        
        # 4. Trilinear Interpolation
        # Weights for the 8 corners based on fractional coordinates
        # Corner 0 (0,0,0) weight: (1-fx)*(1-fy)*(1-fz)
        # Corner 7 (1,1,1) weight: fx*fy*fz
        fx, fy, fz = frac[0], frac[1], frac[2]
        
        # Precompute weights for each corner
        # Using the order defined by bits: i=0 is (0,0,0), i=7 is (1,1,1)
        weights = np.zeros(8)
        for i in range(8):
            wx = fx if (i & 1) else (1 - fx)
            wy = fy if (i & 2) else (1 - fy)
            wz = fz if (i & 4) else (1 - fz)
            weights[i] = wx * wy * wz
            
        # Interpolate features
        f_l = np.dot(weights, vertex_features)
        features.append(f_l)
        
    # Concatenate all level features
    F_concat = np.concatenate(features, axis=0)
    return F_concat
```

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Multiple 3D points may map to the same hash entry. In a global model, this causes gradients from different scene parts to be averaged, degrading reconstruction quality [S6, unofficial]. Increasing $T$ reduces collisions but increases memory and training time because gradients must be computed for all bins during backpropagation, even if many are empty [S6, S10, unofficial].
*   **Cache Misses:** Allocating hash tables that exceed the GPU's L2 cache (e.g., > 6 MB on RTX 3090) significantly increases training time due to cache misses, without improving quality [S10, unofficial][S14].
*   **Precision:** Storing hash table entries in half precision optimizes performance, but a full-precision master copy is required for stable Adam optimizer updates [S14].
*   **Gradient Sparsity:** When $T \gg \text{BatchSize}$, many hash table entries have zero gradients. Skipping Adam steps for these entries saves ~10% performance [S14].

## Subtopics

### [Tetrahedron Property Querying via Instant-NGP](4935-tetrahedron-property-querying-via-instant-ngp.md)
This method queries a differentiable radiance field parameterized by an Instant-NGP data structure and the mip-NeRF 360 contraction function to produce density and appearance features for individual tetrahedra. It solves the problem of mapping point-based neural fields to volume-based primitives during optimization, where attaching features directly to vertices fails due to topological changes in the Delaunay tetrahedralization. It differs from standard NeRF point querying by using tetrahedron centers (centroid or circumcenter) and incorporating a radius-based downweighting to handle geometric degeneracy.

### [Multi-resolution Hash Encoding with Simplex Structure](9584-multi-resolution-hash-encoding-with-simplex-structure.md)
Multi-resolution Hash Encoding with Simplex Structure is a neural encoding method that replaces the explicit hypercube-based grid structure of Instant-NGP with a simplex-based structure, using hash tables to store learnable feature vectors at simplex vertices across multiple resolution levels. It solves the memory inefficiency of dense grids in simplicial domains by storing only accessed vertices, avoiding the overhead of explicit ordering for unused vertices. It sets itself apart from standard Instant-NGP by using barycentric interpolation within skewed simplices rather than trilinear interpolation within hypercubes.

### [Global Preconditioner for Encoder-Induced Metric](11747-global-preconditioner-for-encoder-induced-metric.md)
The Global Preconditioner for Encoder-Induced Metric is a fixed linear transformation applied to the input space of a HashGrid encoding to isotropize the average metric induced by the encoder. It solves the problem of anisotropic feature scaling caused by the discrete, multi-resolution grid structure, ensuring that all spatial directions are treated equally on average without globally rescaling the volume. Unlike adaptive preconditioners, it uses a closed-form solution derived from the symmetrized average metric of the canonical cell, setting apart from siblings by providing a static, volume-preserving correction that reduces the condition number of the encoder-induced metric to 1 for the average case.

### DWTNeRF
DWTNeRF is a unified framework for few-shot Neural Radiance Fields (NeRF) that builds on [Standard Multi-resolution Hash Encoding](13152-standard-multi-resolution-hash-encoding.md) (Instant-NGP) to enable fast training from sparse views [S1]. It distinguishes itself by introducing a Discrete Wavelet Transform (DWT) loss to explicitly prioritize low-frequency learning and multi-head attention modules for cross-branch interactions, avoiding architectural changes to the base MLP that typically degrade performance in Instant-NGP [S1].

### [Standard Multi-resolution Hash Encoding](13152-standard-multi-resolution-hash-encoding.md)
Standard Multi-resolution Hash Encoding (SMHE) maps 3D spatial coordinates to a high-dimensional feature vector using a set of trainable hash tables at multiple resolutions, enabling efficient neural scene representation. It distinguishes itself from traditional positional encoding by replacing fixed basis functions with learnable parameters stored in sparse hash grids, significantly reducing memory usage and training time while maintaining high reconstruction quality.

### [MF-NeRF Mixed-Feature Hash Encoding](13261-mf-nerf-mixed-feature-hash-encoding.md)
MF-NeRF is a memory-efficient neural radiance field framework that reduces memory usage and training time by sharing scene features across consecutive resolution grids via a shared hash table. Unlike [Standard Multi-resolution Hash Encoding](13152-standard-multi-resolution-hash-encoding.md) which assigns dedicated grid sizes to different resolution levels, MF-NeRF mixes multiple grids into a single hash table to learn combined coarse and fine abstracted features, assuming that overlapping grids in the same radiance field exhibit analogous feature distributions.

### [Hash-Frequency Encoding](13636-hash-frequency-encoding.md)
Hash-Frequency Encoding (HE+FE) is a hybrid feature representation for neural radiance fields that combines the memory efficiency of multi-resolution hash encoding with the high-frequency approximation capabilities of sinusoidal frequency encoding. It solves the problem of severe performance degradation and artifact generation (floaters) in sparse input scenarios, where standard hash-only encoders fail to capture fine details. Unlike its sibling [Standard Multi-resolution Hash Encoding](13152-standard-multi-resolution-hash-encoding.md), which relies solely on hash lookups, HE+FE augments the hash features with frequency levels to stabilize reconstruction on sparse views, while training significantly faster than frequency-only alternatives like [MIP-NeRF 360](13152-standard-multi-resolution-hash-encoding.md).

### [Hashed 3D Representations](16815-hashed-3d-representations.md)
Hashed 3D Representations are a family of neural 3D field parameterizations that decompose a field $f$ into a hashing scheme $h$ and a small MLP $g$, such that $f = g \circ h$. They solve the memory bottleneck inherent in dense 3D storage by using sparse or structured hash-like access patterns (e.g., voxel grids, triplanes) to sample features efficiently, enabling fast, memory-efficient training and rendering. What sets them apart from dense voxel-based methods is the decoupling of spatial indexing from the neural network, allowing the use of compact structures like triplanes where cells lack explicit 3D coordinates, and from pure neural fields by providing a differentiable, interpolation-based sampling mechanism.

### F-Hash
An extension of multi-resolution hash encoding to four dimensions using Tesseract grids and collision-free minimal perfect hashing for faster convergence. Compression ratios: 9.5–55.2×. Convergence speed: 10–100× faster than standard hash encoding. Performance on combustion data: 47.1 dB in 7.4 minutes vs. 23.7 dB in 45.7 minutes [S20, unofficial].

### Canonical Network with Multi-resolution Hash Encoding
A neural network that maps 3D spatial coordinates to a scalar density value, serving as the static representation of the object's attenuation coefficient field. It eliminates the need for color output and viewing direction input because X-ray imaging is monochromatic and lacks orientation-dependent reflection. Input: 3D position (x, y, z). Output: Scalar density $\rho$. Implementation: Use multi-resolution hash encoding [15] as the feature extractor $\Theta$. Unlike classical X-CT where density is a discrete 3D voxel grid, this method represents the density field as a continuous function $\Theta(x, y, z)$ [S21, unofficial].

### Hybrid Encoding
An encoding formed by concatenating the view encoding with all-but-the-first-dimension of the hash encoding. Used as input to the color MLP. Hash encoding for density MLP: $\gamma'(x) = \gamma_0(x)$ (only first dimension retained). Hybrid encoding for color MLP: $\gamma''(d, x) = [\gamma(d), \gamma_{1:N_x}(x)]$ [S22, unofficial].

## Operating characteristics
*   **Time Complexity:** Training time is proportional to the number of sampled points rather than the complexity of the scene, due to the shallow MLP [S1]. Instant-NGP converges to 95% of final PSNR in 2.4 ± 0.4 minutes on Blender scenes, compared to 18.4 minutes for 3DGS and 12.4 hours for NeRF [S1].
*   **Memory Complexity:** Training requires more than twelve times as much video memory as rendering due to intermediate activations and Adam optimizer statistics [S4]. The hash table size $T$ directly impacts memory usage; $T=2^{19}$ with $L=16$ and $F=4$ results in 12.6M encoding parameters, which is 1,191× larger than weight parameters (10k) [S10, unofficial].
*   **Measured Performance:** On an NVIDIA A100 GPU at 1080p, Instant-NGP renders at 2.4 ± 0.4 FPS [S1]. This is 12× faster than NeRF (0.2 FPS) but 28× slower than 3DGS (68.4 FPS) [S1]. On the NeRF Synthetic (Blender) dataset, Instant-NGP achieved PSNR = 32.6 ± 0.4 dB [S1]. On the Mip-NeRF 360 unbounded dataset, it achieved PSNR = 26.4 ± 0.6 dB [S1].
*   **Strengths:** Extremely fast training (seconds to minutes), high rendering speed compared to MLP-based NeRF, good preservation of sharpness and fine details compared to frequency-based encoding [S9].
*   **Limitations:** Moderate surface accuracy compared to SDF-based methods like NeuS because it uses a faster density representation rather than explicit surface geometry [S1]. Performance degrades on unbounded scenes compared to methods like Mip-NeRF 360 or 3DGS [S1]. Hash collisions can degrade quality if $T$ is too small [S6, unofficial].
*   **When to Use:** Rapid prototyping, applications requiring immediate visual feedback during acquisition, and scenarios where training time is a critical bottleneck [S1].
*   **When Not to Use:** Applications requiring real-time interactive rendering (>50 FPS) where 3DGS is superior, or applications requiring high-precision surface geometry where NeuS or similar SDF methods are preferred [S1].

## Background
Multi-resolution Hash Encoding was introduced in the paper "Instant Neural Graphics Primitives with a Multiresolution Hash Encoding" by Thomas Müller, Alex Evans, Christoph Schied, and Alexander Keller in 2022 [S14]. It was developed to address the computational bottleneck of NeRF, which relies on a large, deep MLP that is expensive to train and render [S3, unofficial]. The method leverages the fact that modern GPUs have highly optimized hash table lookup operations, allowing the scene representation to be stored in learnable feature grids rather than network weights [S1]. This approach has become a standard baseline for fast NeRF training and has inspired numerous variants and applications in medical imaging, agricultural reconstruction, and scientific visualization [S9, S11][S20, unofficial].
