# Hash-Based Dispatching
## Overview
Hash-based dispatching is a method for integrating expert selection into the hash table lookup operation within hash-based gating networks, eliminating the need for explicit input feature reorganization [S1]. It differs from MLP-based dispatching by avoiding matrix multiplications on features and removing the requirement for a capacity factor, thereby reducing memory overhead and computational latency [S1].
## How it works
**Inputs:** A set of 3D points and their corresponding expert indices [S1].
**Outputs:** Feature vectors retrieved from the appropriate expert hash tables for each point [S1].
**Data Structures:** Hash tables, one per expert, and a hash function that maps combined inputs to table indices [S1].
**Steps:**
1. Compute a hash index for each 3D point [S1].
2. Pass the expert index into the hash function [S1].
3. Compute the hash table offset using the expert index and the hash index [S1].
4. Fetch features from the hash tables at the computed offsets [S1].
**Formula:**
Let $h$ be the hash index for a point, $e$ be the expert index, and $H$ be the hash function. The offset is $O = H(h, e)$ [S1]. The feature is retrieved as $f = \text{Table}_e[O]$ [S1].
**Parameters:**
* Number of experts $N$: Not given in the sources. [S1]
* Hash table size: Not given in the sources. [S1]
**Edge Cases and Pitfalls:**

**Pseudocode:**
```python
def hash_based_dispatch(points, expert_indices, hash_tables, hash_function):
    """
    Fetches features from hash tables based on point coordinates and expert indices.
    Args:
        points: Array of 3D points (N, 3).
        expert_indices: Array of expert indices for each point (N,).
        hash_tables: List of N hash tables, one per expert.
        hash_function: Function that takes (point_hash, expert_index) and returns table offset.
    Returns:
        features: Array of fetched features (N, D).
    """
    features = []
    for i in range(len(points)):
        # 1. Compute hash index for each 3D point
        point_hash = hash(points[i])  # [G] standard hash of 3D coordinates
        e = expert_indices[i]
        # 2 & 3. Pass expert index into hash function to compute offset
        offset = hash_function(point_hash, e)  # [S1]
        # 4. Fetch features from the hash tables
        feature = hash_tables[e][offset]  # [S1]
        features.append(feature)
    return features
```
## Subtopics

### MoE Dispatching
MoE dispatching consumes more GPU memory and training time compared to Hash-based Dispatching [S1]. In training, MoE dispatching uses 10386M memory and 15.2 hours, while Hash-based Dispatching uses 8707M memory and 10.7 hours [S1]. In testing, MoE dispatching uses 2981M memory and 13.5 seconds, while Hash-based Dispatching uses 2857M memory and 6.65 seconds [S1].

## Operating characteristics
**Time and Memory Complexity:**
Hash-based dispatching is more efficient than MoE dispatching [S1]. In training, Hash dispatching uses 8707M memory compared to MoE's 10386M, and takes 10.7 hours compared to MoE's 15.2 hours [S1]. In testing (inference), Hash dispatching uses 2857M memory compared to MoE's 2981M, and takes 6.65 seconds compared to MoE's 13.5 seconds [S1].
**Measured Performance:**
* Training Memory: 8707M (Hash) vs 10386M (MoE) [S1].
* Training Time: 10.7h (Hash) vs 15.2h (MoE) [S1].

## Background
Hash-based dispatching was introduced as part of the Switch-NeRF++ framework, which builds on HashGrid Encoding and Hash-based Gating [S1]. It was developed to address the inefficiencies of MLP-based gating networks in Switch-NeRF, which required extra memory and computation for dispatching [S1]. The method leverages the inherent structure of hash tables to integrate expert selection directly into the lookup process [S1].
