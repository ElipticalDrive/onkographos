# Switch-NeRF++ Forward Pass and Loss

Also called: Switch-NeRF++

## Overview
Switch-NeRF++ is a large-scale neural radiance field method that employs a Mixture of Experts (MoE) architecture to efficiently render heterogeneous urban scenes [S1]. It solves the scalability problem of HashGrid Neural Fields by routing 3D points to specialized hash experts based on local scene complexity, thereby balancing memory usage and rendering accuracy [S1]. It differs from standard HashNeRF by introducing a learned gating mechanism that selects a single expert per point, and from Switch-NeRF by upgrading the expert capacity and resolution scaling for higher fidelity in massive environments [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D point coordinates $x$, view direction $d$, and appearance embedding $a$ [S1].
*   **Outputs:** Predicted density $\sigma$, color $c$, and rendered image color $\hat{C}(r)$ [S1].

**Data Structures and Layout:**
The method uses a HashGate and $N$ Hash Experts [S1].
*   **HashGate:** Uses a base resolution of 16 and a desired resolution of 2048. The hashmap size is $2^{19}$ [S1].
*   **Hash Experts:** There are $N=8$ experts [S1]. Their base resolutions $\{r\}$ are logarithmically spaced in $[16, 512]$ and their desired resolutions $\{\tilde{r}\}$ are logarithmically spaced in $[2048, 16384]$ [S1].
*   **Space Contraction:** To handle unbounded space, points are normalized into a unit sphere. If $\|x\| \le 1$, $x$ remains unchanged. If $\|x\| > 1$, $x$ is transformed by $\frac{x}{2 - \frac{1}{\|x\|}}$ [S1]. This maps background points into a bounded scene without affecting foreground points [S1].

**Numbered Steps:**
1.  **Space Contraction:** Apply the contraction function to input point $x$ if $\|x\| > 1$ [S1].
2.  **Gating Network:** Encode the contracted position $x$ using the HashGate to get feature vector $f_g$ [S1].
3.  **Gate Values:** Compute gate probabilities $G = \text{Softmax}(f_g)$ [S1].
4.  **Expert Selection:** Select the top-1 expert index $i = \arg\max(G)$ [S1].
5.  **Expert Encoding:** Encode $x$ using the selected expert $i$ to obtain $E_i(x)$ [S1].
6.  **Gate Application:** Apply the gate value to the expert output: $\hat{E}_i(x) = G_i \cdot E_i(x)$ [S1].
7.  **Direction Encoding:** Encode view direction $d$ using Spherical Harmonics to get $SH_d$ [S1].
8.  **Feature Concatenation:** Concatenate features: $f_{final} = [\hat{E}_i(x), SH_d, a]$ [S1].
9.  **Density Prediction:** Pass $\hat{E}_i(x)$ through a density MLP: $\sigma = \text{MLP}_{density}(\hat{E}_i(x))$ [S1].
10. **Color Prediction:** Pass $\hat{E}_i(x)$ through a color MLP: $c = \text{MLP}_{color}(\hat{E}_i(x))$ [S1].
11. **Volume Rendering:** Compute transmittance $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ and rendered color $\hat{C}(r) = \sum_{i=1}^{K} T_i (1 - \exp(-\sigma_i \delta_i)) c_i$ [S1]. (Note: $K$ denotes the number of samples along the ray).
12. **Loss Computation:** Calculate Rendering Loss $L_r$ and Gate Balance Loss $L_b$ [S1].

**Formulas:**
*   **Gate Balance Loss:** $L_b = \sum_n f_n g_n$, where $f_n$ and $g_n$ are flow and gate values for expert $n$ [S1].
*   **Overall Loss:** $L_o = L_r + \lambda L_b$ [S1].
*   **Rendering Loss:** $L_r = \sum_{r \in R} (\hat{C}(r) - C(r))^2$ [S1].

**Parameters:**
*   **Balance Loss Weight ($\lambda$):** $5 \times 10^{-4}$ [S1].
*   **Optimizer:** Adam with learning rate $5 \times 10^{-4}$, exponentially decreasing [S1].
*   **Precision:** Half-precision training and testing [S1].
*   **Batch Prioritized Routing:** Integrated to refine training by prioritizing critical samples, with $C_f$ empirically set to $1.0$ to avoid extra memory consumption [S1].

**Pseudocode:**
```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F

def contract_point(x):
    """Contracts unbounded 3D space into a unit sphere per Mip-NeRF 360 [S1]."""
    norm = torch.norm(x, dim=-1, keepdim=True)
    norm = torch.clamp(norm, min=1e-8)
    mask = norm > 1.0
    contracted = x / (2.0 - 1.0 / norm)
    return torch.where(mask, contracted, x)

def spherical_harmonics(d, degree=3):
    """Standard SH basis encoding for direction d [G]."""
    x, y, z = d[:, 0:1], d[:, 1:2], d[:, 2:3]
    xx, yy, zz = x*x, y*y, z*z
    xy, yz, xz = x*y, y*z, x*z
    # Degree 0 to 3 SH basis (16 coefficients)
    sh = torch.cat([
        0.282095,
        0.488603 * y, 0.488603 * z, 0.488603 * x,
        1.092548 * yz, -1.092548 * xz, 0.315392 * (3*zz - 1),
        -1.092548 * xy, 0.546274 * (xx - yy),
        0.590044 * y * (3*xx - yy), 2.890611 * x * y * z,
        0.457046 * z * (5*zz - 1), 1.092548 * xz * (3*xx - yy),
        0.373176 * (5*zz - 3) * z, 1.092548 * xy * (3*zz - 1),
        0.590044 * y * (xx - 3*yy)
    ], dim=-1)
    return sh

class HashEncoding(nn.Module):
    """Simplified hash grid encoding matching Instant-NGP settings [S1]."""
    def __init__(self, base_res, desired_res, hashmap_size):
        super().__init__()
        self.base_res = base_res
        self.desired_res = desired_res
        self.hashmap_size = hashmap_size
        self.embeddings = nn.Embedding(hashmap_size, 256)

    def forward(self, x):
        x_norm = (x + 1.0) / 2.0
        idx = torch.round(x_norm * (self.desired_res - 1)).long()
        idx = (idx[:, 0] * self.desired_res * self.desired_res +
               idx[:, 1] * self.desired_res + idx[:, 2]) % self.hashmap_size
        return self.embeddings(idx)

class SwitchNeRFPlusPlus(nn.Module):
    def __init__(self, num_experts=8):
        super().__init__()
        self.num_experts = num_experts
        self.hash_gate = HashEncoding(16, 2048, 2**19)

        base_resolutions = [16 * (512/16)**(i/(num_experts-1)) for i in range(num_experts)]
        desired_resolutions = [2048 * (16384/2048)**(i/(num_experts-1)) for i in range(num_experts)]
        self.experts = nn.ModuleList([
            HashEncoding(int(b), int(d), 2**19) for b, d in zip(base_resolutions, desired_resolutions)
        ])

        self.mlp_density = nn.Sequential(nn.Linear(256, 128), nn.ReLU(), nn.Linear(128, 1))
        self.mlp_color = nn.Sequential(nn.Linear(256, 128), nn.ReLU(), nn.Linear(128, 3))
        self.lambda_balance = 5e-4

    def forward(self, x, d, a):
        # Part I: Space Contraction
        x_c = contract_point(x)
        
        # Part II: Gating Network
        f_g = self.hash_gate(x_c)
        G = F.softmax(f_g, dim=-1)
        expert_idx = torch.argmax(G, dim=-1, keepdim=True)
        
        # Part III: Hash Expert Processing
        expert_features = torch.stack([expert(x_c) for expert in self.experts], dim=1)
        gated_features = expert_features * G.unsqueeze(-1)
        selected = torch.gather(gated_features, 1, expert_idx.unsqueeze(-1).expand(-1, -1, 256)).squeeze(1)
        
        # Part IV: Prediction
        SH_d = spherical_harmonics(d)
        f_final = torch.cat([selected, SH_d, a], dim=-1)
        
        sigma = self.mlp_density(selected)
        c = self.mlp_color(selected)
        return sigma, c, G, expert_idx

    def compute_loss(self, sigma, c, G, expert_idx, gt_color, delta):
        # Volume Rendering
        alpha = 1.0 - torch.exp(-sigma * delta)
        T = torch.ones_like(sigma[..., 0])
        T = torch.cat([T, torch.cumprod(1 - alpha[..., :-1], dim=0)], dim=0)
        rendered_color = torch.sum(T.unsqueeze(-1) * alpha.unsqueeze(-1) * c, dim=0)
        
        # Rendering Loss
        L_r = torch.mean((rendered_color - gt_color) ** 2)
        
        # Gate Balance Loss: L_b = sum_n f_n g_n
        batch_size = sigma.shape[0]
        expert_counts = torch.bincount(expert_idx.flatten(), minlength=self.num_experts).float()
        f_n = expert_counts / batch_size
        g_n = torch.zeros(self.num_experts).to(sigma.device)
        g_n.scatter_add_(0, expert_idx.flatten(), G[torch.arange(batch_size), expert_idx.flatten()])
        g_n = g_n / (f_n + 1e-8)
        L_b = torch.sum(f_n * g_n)
        
        L_o = L_r + self.lambda_balance * L_b
        return L_o, rendered_color
```

## Operating characteristics
*   **Time Complexity:** Dominated by the hash lookups in the gating network and the selected expert [G]. Since only one expert is selected per point, the per-point cost is comparable to a single HashGrid lookup plus MLP inference, rather than summing all experts [G].
*   **Memory Complexity:** Determined by the sum of the hash table sizes of all $N$ experts. The logarithmic spacing of resolutions ensures that experts covering large scales (high resolution) are fewer, while those covering fine details (low resolution) are more numerous but smaller, optimizing memory for urban scenes [S1].
*   **Performance:** Designed for large-scale scenes (e.g., 4k-5k resolution images, km-scale coverage). It uses half-precision training to reduce memory footprint [S1].
*   **Strengths:** Scalability to massive urban environments; efficient memory usage via expert specialization; improved accuracy over single-expert models through hierarchical resolution [S1].
*   **Limitations:** Not given in the sources.

## Background
Switch-NeRF++ was developed to address the limitations of previous neural radiance field methods in large-scale urban reconstruction [S1]. It builds on the HashNeRF architecture and the Switch-NeRF MoE approach [S1]. The method was introduced in the paper "Learning Heterogeneous Mixture of Scene Experts for Large-Scale Neural Radiance Fields" [S1]. It is particularly suited for datasets like Block-NeRF, UrbanBIS, and MatrixCity, which feature high-resolution imagery over vast areas [S1].
