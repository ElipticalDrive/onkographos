# Surface-Relative Hash Encoding

Also called: Surface-Relative Representation

## Overview
Surface-Relative Hash Encoding maps 3D query points to feature vectors by conditioning on their geometric relationship to a human surface mesh [S1, unofficial]. It solves pose-dependent artifacts and slow convergence in standard hash-based NeRFs by encoding relative attributes to surface vertices rather than absolute world coordinates [S1, unofficial]. Unlike [Standard Multi-resolution Hash Encoding](13152-standard-multi-resolution-hash-encoding.md) which processes absolute positions, this method aggregates features from multiple nearest surface points to handle non-rigid deformation [S1, unofficial].

## How it works
**Inputs:**
- Query point $\mathbf{x}$ in posed space at frame $t$ [S1, unofficial].
- Current human surface point cloud/mesh $T_t$ (e.g., SMPL or SelfRecon) [S1, unofficial].
- Template surface $T_0$ in canonical frame [S1, unofficial].
- Multi-resolution hash encoding structure $H$ [S1, unofficial].
- Number of nearest neighbors $k$ [S1, unofficial].

**Outputs:**
- Blended feature vector $\text{Rel}(\mathbf{x}|T_t)$ [S1, unofficial].

**Data Structures:**
- $T_t$: Set of vertices $\{p_i\}$ with associated normal vectors $\{n_i\}$ [S1, unofficial].
- $T_0$: Set of corresponding template vertices $\{\bar{p}_i\}$ [S1, unofficial].
- Hash Encoder $H$: Maps normalized relative vectors to feature vectors $\mathbf{f}$ [S1, unofficial].

**Steps:**
1. **K-Nearest Neighbor Search:** Find the $k$-nearest points $N_k(\mathbf{x}) = \{r_1, r_2, \dots, r_k\}$ in $T_t$ [S1, unofficial]. Each neighbor is $r_i = (p_i, d_i(\mathbf{x}))$, where $p_i \in T_t$ and $d_i(\mathbf{x})$ is the signed distance from $p_i$ to $\mathbf{x}$ [S1, unofficial].
2. **Relative Representation Construction:** Construct $\hat{r}_i = (\bar{p}_i, d_i(\mathbf{x}))$, where $\bar{p}_i$ is the corresponding point of $p_i$ in $T_0$ [S1, unofficial].
3. **Normalization:** Normalize $r_i$ to obtain $\hat{r}_i$ [S1, unofficial].
4. **Hash Encoding:** Encode each normalized representation using the multi-resolution hash encoder: $\mathbf{f}_i = h(\hat{r}_i|H)$ [S1, unofficial].
5. **Weight Calculation:** Compute the blending weight $w_i = |\cos(\mathbf{x} - p_i, n_i)|$, where $n_i$ is the normal vector of $p_i$ on $T_t$ [S1, unofficial].
6. **Feature Blending:** Aggregate the encoded features using the calculated weights: $\text{Rel}(\mathbf{x}|T_t) = \frac{\sum_{i=1}^{k} w_i \mathbf{f}_i}{\sum_{i=1}^{k} w_i}$ [S1, unofficial].

**Parameters:**
- $k$: Number of nearest neighbors. Not given in the sources.
- $T_t$: Human surface mesh/point cloud for frame $t$. Can be SMPL or SelfRecon mesh [S1, unofficial].
- $T_0$: Template surface (canonical frame) [S1, unofficial].

**Edge Cases and Pitfalls:**
- Using only the single nearest point (as in HNeRF) leads to artifacts around body joints (e.g., armpits) for unseen poses and incurs high computational cost for exact nearest-point computation on the face [S1, unofficial]. Using $k$-nearest vertices resolves these issues [S1, unofficial].

```python
import math

def dot(a, b):
    return sum(ai * bi for ai, bi in zip(a, b))

def normalize(v):
    mag = math.sqrt(sum(vi * vi for vi in v))
    return [vi / mag for vi in v] if mag > 0 else v

def surface_relative_hash_encoding(x, T_t, T_0, normals_t, k, hash_encoder):
    # 1. KNN search: find k nearest points in T_t to x
    # The exact KNN algorithm implementation is not specified in the sources [G]
    dists = [math.sqrt(sum((xi - ti)**2 for xi, ti in zip(x, T_t[i]))) for i in range(len(T_t))]
    sorted_indices = sorted(range(len(T_t)), key=lambda i: dists[i])
    neighbor_indices = sorted_indices[:k]
    
    encoded_features = []
    weights = []
    
    for idx in neighbor_indices:
        p_i = T_t[idx]
        d_i = dists[idx]
        
        # 2. Relative representation: (template_point, signed_distance)
        r_i = (T_0[idx], d_i)
        
        # 3. Normalize relative representation
        # Normalization applies to the vector components of r_i
        p_bar_i = T_0[idx]
        p_bar_norm = normalize(p_bar_i)
        r_hat_i = p_bar_norm + [d_i]
        
        # 4. Hash encode
        f_i = hash_encoder(r_hat_i)
        encoded_features.append(f_i)
        
        # 5. Weight calculation: w_i = |cos(x - p_i, n_i)|
        n_i = normals_t[idx]
        diff = [xi - pi for xi, pi in zip(x, p_i)]
        cos_val = dot(normalize(diff), normalize(n_i))
        w_i = abs(cos_val)
        weights.append(w_i)
        
    # 6. Feature blending: Rel(x) = sum(w_i * f_i) / sum(w_i)
    total_weight = sum(weights)
    if total_weight == 0:
        return encoded_features[0]
        
    blended = [0.0] * len(encoded_features[0])
    for w, f in zip(weights, encoded_features):
        for j in range(len(blended)):
            blended[j] += w * f[j]
    blended = [v / total_weight for v in blended]
    return blended
```

## Background
Originating in the paper "SelfNeRF: Fast Training NeRF for Human from Monocular Self-rotating Video" [S1, unofficial], this method was introduced to address the limitations of static scene NeRFs and the artifacts of single-neighbor surface-relative approaches in dynamic human rendering [S1, unofficial]. It leverages the consistency of human surface topology across poses to accelerate training and improve novel view synthesis quality [S1, unofficial].
