# Vanishing Point Aided Hash-Frequency Encoding

Also called: NeurVPS-ERP

## Overview
Vanishing Point Aided Hash-Frequency Encoding is a neural radiance field encoding scheme that combines multi-resolution hash encoding with deterministic frequency encoding aligned to scene structure via vanishing points [S1]. It solves the problem of poor reconstruction quality from sparse 360° inputs, where standard hash encoding fails due to extreme sparsity and imperfect scene centering [S1]. Unlike standard hash encoding which relies solely on learnable features, this method adds deterministic frequency features to improve generalizability and robustness without requiring additional depth information or pre-training [S1].

## How it works
The method maps a 3D input coordinate $\mathbf{u}$ to a feature vector $\boldsymbol{\gamma}(\mathbf{u})$ by concatenating features from a multi-resolution hash grid and a vanishing-point-aligned frequency encoder [S1].

**Inputs and Outputs:**
*   Input: 3D coordinate $\mathbf{u} \in \mathbb{R}^3$.
*   Parameters: $m$ (number of frequency levels), $k$ (number of hash grid levels), $f$ (feature size per hash cell), $\sigma$ (frequency scaling factor), and estimated vanishing points $\{\mathbf{v}_1, \dots, \mathbf{v}_n\}$ [S1].
*   Output: Feature vector $\boldsymbol{\gamma}(\mathbf{u}) \in \mathbb{R}^{kf + 2md}$ [S1].

**Data Structures:**
1.  **Hash Grids:** $k$ levels of hash tables. Level $l$ has resolution $R_l$, hash table size $T$, and feature dimension $f$. Features are stored in a learnable embedding table $E_l$ [S1].
2.  **Vanishing Points:** A set of $n$ directions $\mathbf{v}_i$ estimated from input images [S1].

**Steps:**

1.  **Vanishing Point Estimation:**
    Estimate vanishing points from 2D input images using an adapted NeurVPS network (NeurVPS-ERP) that utilizes conic convolution on Equi-Rectangular Projection (ERP) images [S1]. Let the estimated vanishing points be $\mathbf{v}_1, \dots, \mathbf{v}_n$ [S1].

2.  **Coordinate Transformation for Frequency Encoding:**
    For each vanishing point $\mathbf{v}_i$, transform the input coordinate $\mathbf{u}$ into angular coordinates $\alpha_i$ relative to the vanishing point direction [S1].
    
    The transformation relies on spherical geometry. Let the vanishing point be defined by longitude $\lambda_0$ and inclination $\theta$ [S1]. Let the point $\mathbf{u}$ be represented in spherical coordinates $(\lambda, \phi)$ [S1].
    
    First, calculate the elevation $\phi_0(\lambda, \phi)$ of the point relative to the vanishing point:
    $$
    \phi_0(\lambda, \phi) = \arctan\left( \tan(\phi) \sqrt{1 + \tan^2(\lambda - \lambda_0)} - \tan(\theta)\tan(\lambda - \lambda_0) \right)
    $$
    [S1]
    
    The aligned angular coordinate $\alpha_i$ corresponds to this elevation $\phi_0$ (or a function thereof, specifically the value that is constant for points on radial lines from the vanishing point) [S1]. The text states: "points on the radial lines originating from the vanishing point will share the same $\alpha$ value" and defines $\alpha_{aligned} = (\alpha_1, \dots, \alpha_n)^\top$ [S1]. While the explicit formula for $\alpha$ is not isolated as a single line, it is derived from the geometry where $\phi_0$ represents the angular deviation from the vanishing point direction in the local tangent plane or similar projection [S1]. We define $\alpha_i$ as the value computed via the geometric relationship defined by $\phi_0$ [S1].

3.  **Frequency Encoding:**
    Generate $m$-level frequency-encoded input coordinates $\boldsymbol{\gamma}_{FE}(\mathbf{u}) \in \mathbb{R}^{2md}$ using sinusoidal positional encoding on the aligned coordinates $\alpha_{aligned}$ [S1].
    
    For each vanishing point $i \in \{1, \dots, n\}$ and frequency level $j \in \{0, \dots, m-1\}$, compute:
    $$
    \gamma_{FE, i, 2j} = \cos(2\pi \sigma^j \alpha_i)
    $$
    $$
    \gamma_{FE, i, 2j+1} = \sin(2\pi \sigma^j \alpha_i)
    $$
    [S1]
    
    Concatenate these for all $i$ and $j$ to form $\boldsymbol{\gamma}_{FE}(\mathbf{u})$ [S1]. Note: The source defines $\gamma(u)$ for a single axis as $\dots, \cos(2\pi \sigma^{j/m} u), \sin(2\pi \sigma^{j/m} u), \dots$ for $j=0,\dots,m-1$ [S1]. However, in the context of the aligned coordinates, the exponent is typically $\sigma^j$ or similar logarithmic spacing. The source text says "logarithmically-spaced axis-aligned frequencies" and cites $\sigma^{j/m}$ in one instance but $\sigma^j$ is standard in Instant-NGP. The source explicitly writes: $\cos(2\pi \sigma^{j/m} u)$ in Eq (2) [S1]. We follow the source's explicit formula notation:
    $$
    \gamma_{FE, i, 2j} = \cos(2\pi \sigma^{j/m} \alpha_i)
    $$
    $$
    \gamma_{FE, i, 2j+1} = \sin(2\pi \sigma^{j/m} \alpha_i)
    $$
    [S1]

4.  **Hash Encoding:**
    Hash-encode the input coordinate $\mathbf{u}$ using a $k$-level multi-resolution feature grid of feature size $f$ [S1].
    
    For each level $l \in \{0, \dots, k-1\}$:
    a. Normalize $\mathbf{u}$ to the bounding box $[0, 1]^3$ and scale by resolution $R_l$ to get continuous coordinates $\mathbf{c}_l$ [S1].
    b. Compute integer voxel indices $\mathbf{i} = \lfloor \mathbf{c}_l \rfloor$ [S1].
    c. Identify 8 corner vertices by adding binary offsets $\mathbf{o} \in \{0, 1\}^3$ to $\mathbf{i}$ [S1].
    d. Hash each corner coordinate $\mathbf{i} + \mathbf{o}$ to a bucket index $h \in \{0, \dots, T-1\}$ using hash function $H_l$ [S1].
    e. Retrieve learnable features $\mathbf{e}_{corner} = E_l[H_l(\mathbf{i} + \mathbf{o})]$ [S1].
    f. Perform trilinear interpolation using the fractional part of $\mathbf{c}_l$ to produce level-specific feature $\mathbf{f}_l$ [S1].
    
    Concatenate all $\mathbf{f}_l$ to form the hash-encoded feature vector $\boldsymbol{\gamma}_{H}(\mathbf{u}) \in \mathbb{R}^{kf}$ [S1].

5.  **Concatenation:**
    Concatenate the hash-encoded features and the frequency-encoded features:
    $$
    \boldsymbol{\gamma}(\mathbf{u}) = [\boldsymbol{\gamma}_{H}(\mathbf{u}), \boldsymbol{\gamma}_{FE}(\mathbf{u})] \in \mathbb{R}^{kf + 2md}
    $$
    [S1]

**Pseudocode:**

```python
import math
import numpy as np

def vanishing_point_aided_hash_frequency_encoding(
    u: np.ndarray,          # Shape (3,), 3D input coordinate
    vanishing_points: list, # List of n vanishing points, each (3,)
    m: int,                 # Number of frequency levels
    k: int,                 # Number of hash grid levels
    f: int,                 # Feature size per hash cell
    sigma: float,           # Frequency scaling factor
    hash_tables: list,      # List of k hash tables (dict or array)
    embeddings: list,       # List of k embedding tables (array)
    resolutions: list       # List of k resolutions R_l
) -> np.ndarray:
    """
    Computes the Vanishing Point Aided Hash-Frequency Encoding for coordinate u.
    Returns feature vector of shape (k*f + 2*m*n,).
    """
    n = len(vanishing_points)
    
    # --- Part 1: Frequency Encoding ---
    freq_features = []
    
    # Convert u to spherical coordinates (lambda, phi)
    # Assuming u is in Cartesian. 
    # x = r * cos(phi) * cos(lambda)
    # y = r * cos(phi) * sin(lambda)
    # z = r * sin(phi)
    # Note: Standard math convention vs computer graphics convention may vary.
    # We assume standard spherical: lambda in [0, 2pi), phi in [-pi/2, pi/2]
    r = np.linalg.norm(u)
    if r == 0:
        # Handle singularity
        lambda_u = 0.0
        phi_u = 0.0
    else:
        lambda_u = math.atan2(u[1], u[0])
        phi_u = math.asin(u[2] / r)
        
    for vp in vanishing_points:
        # Convert vanishing point to spherical (lambda_0, theta)
        # Source uses theta for inclination. Assuming theta is similar to phi or elevation.
        # Source formula uses tan(theta).
        r_vp = np.linalg.norm(vp)
        if r_vp == 0:
            lambda_0 = 0.0
            theta = 0.0
        else:
            lambda_0 = math.atan2(vp[1], vp[0])
            theta = math.asin(vp[2] / r_vp)
            
        # Calculate phi_0 (elevation relative to VP)
        # phi_0 = arctan( tan(phi) * sqrt(1 + tan^2(lambda - lambda_0)) - tan(theta)*tan(lambda - lambda_0) )
        tan_phi = math.tan(phi_u)
        tan_theta = math.tan(theta)
        delta_lambda = lambda_u - lambda_0
        tan_delta = math.tan(delta_lambda)
        
        term1 = tan_phi * math.sqrt(1 + tan_delta**2)
        term2 = tan_theta * tan_delta
        phi_0 = math.atan(term1 - term2)
        
        # alpha is the aligned coordinate. Based on context, alpha corresponds to phi_0
        # or a normalized version. We use phi_0 as the primary angular deviation.
        alpha = phi_0
        
        # Generate m levels of sinusoidal encoding
        for j in range(m):
            freq = sigma**(j/m) # Source: sigma^(j/m)
            arg = 2 * math.pi * freq * alpha
            freq_features.append(math.cos(arg))
            freq_features.append(math.sin(arg))
            
    freq_features = np.array(freq_features)
    
    # --- Part 2: Hash Encoding ---
    hash_features = []
    
    # Normalize u to [0, 1] range relative to scene bounds.
    # Assuming u is already normalized or scaled appropriately for the hash grid.
    # If u is in world coordinates, it must be normalized. 
    # The source mentions "input coordinate u is normalized to the bounding box [0, 1]^3"
    # We assume u is passed in normalized space or we normalize it here.
    # For this implementation, we assume u is in [0, 1]^3.
    
    for l in range(k):
        R_l = resolutions[l]
        
        # Scale to grid coordinates
        c_l = u * R_l
        
        # Integer indices
        i_l = np.floor(c_l).astype(int)
        
        # Fractional part for interpolation
        frac_l = c_l - i_l
        
        # 8 corners
        features_l = np.zeros(f)
        
        for o0 in [0, 1]:
            for o1 in [0, 1]:
                for o2 in [0, 1]:
                    # Corner index
                    corner_idx = i_l + np.array([o0, o1, o2])
                    
                    # Hash to bucket
                    # Simple hash function: combine coordinates
                    # H(i) = (i[0] * 73856093 ^ i[1] * 19349663 ^ i[2] * 83492791) % T
                    # Using a standard polynomial hash for determinism
                    h = (corner_idx[0] * 73856093 ^ 
                         corner_idx[1] * 19349663 ^ 
                         corner_idx[2] * 83492791) % len(hash_tables[l])
                    
                    # Lookup feature
                    e = embeddings[l][h]
                    
                    # Trilinear interpolation weight
                    w = (1 - frac_l[0])**o0 * frac_l[0]**(1-o0) * \
                        (1 - frac_l[1])**o1 * frac_l[1]**(1-o1) * \
                        (1 - frac_l[2])**o2 * frac_l[2]**(1-o2)
                        
                    features_l += w * e
                    
        hash_features.append(features_l)
        
    hash_features = np.concatenate(hash_features)
    
    # --- Part 3: Concatenation ---
    final_feature = np.concatenate([hash_features, freq_features])
    
    return final_feature
```

**Parameters:**
*   $m$: Number of frequency levels. Typical values not given in sources.
*   $k$: Number of levels in the multi-resolution hash grid. Typical values not given in sources.
*   $f$: Feature size (dimensionality) of each cell in the hash grid. Typical values not given in sources.
*   $\sigma$: Frequency scaling factor. Typical values not given in sources.

**Edge Cases and Pitfalls:**
*   **Sparse Input:** Hash encoding fails when input is extremely sparse (e.g., 8 inputs 1 meter apart). The method mitigates this by adding deterministic frequency features which do not rely on learnable explicit structure [S1].
*   **Scene Centering:** Scene centering and scaling are crucial for hash encoding performance. Imperfect positioning in 360° scenes with random camera poses requires the robustness provided by the auxiliary frequency features [S1].
*   **Singularity:** The spherical coordinate transformation has singularities at the poles ($r=0$ or $\phi = \pm \pi/2$). The pseudocode handles $r=0$. The source formulas involve $\tan(\phi)$ and $\tan(\lambda)$, which are undefined at $\pm \pi/2$ and $\pm \pi/2$ respectively. Care must be taken to handle these boundaries [S1].

## Operating characteristics
*   **Time Complexity:** Dominated by the hash lookups and the frequency encoding. Hash lookup is $O(1)$ per level. Frequency encoding is $O(m \cdot n)$. Total time is $O(k + m \cdot n)$ per query.
*   **Memory Complexity:** $O(k \cdot T \cdot f + m \cdot n)$, where $T$ is the hash table size. The frequency features are small compared to the hash grid.
*   **Strengths:** Improves reconstruction from sparse 360° inputs; robust to imperfect scene centering; does not require additional depth information or pre-training [S1].
*   **Limitations:** Requires vanishing point estimation from input images, which adds a preprocessing step [S1]. Performance still depends on proper scene scaling/centering for the hash component [S1].
*   **When to use:** Sparse 360° input reconstruction where standard hash encoding fails due to sparsity or misalignment [S1].
*   **When not to use:** Dense input scenarios where standard hash encoding is sufficient and faster; scenarios where vanishing points are difficult to estimate reliably [S1].
