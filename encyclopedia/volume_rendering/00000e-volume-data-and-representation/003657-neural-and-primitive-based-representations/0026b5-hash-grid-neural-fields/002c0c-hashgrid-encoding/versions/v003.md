# HashGrid Encoding

Also called: Hash Encoding, Instant-NGP Hash Grid, Instant-NGP Grid Encoding

## Overview
HashGrid Encoding is a learnable feature encoding method that maps input coordinates to multi-resolution grid features using spatial hashing and trilinear interpolation, allowing for efficient training of neural radiance fields (NeRF) on consumer GPUs [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   `inputs`: Float array of shape `[B, D]`, values in `[0, 1]` [S1, unofficial].
*   `embeddings`: Float array of shape `[sO, C]`, where `sO` is the total size of all hash tables [S1, unofficial].
*   `offsets`: Integer array of shape `[L + 1]`, cumulative sizes of hash tables per level [S1, unofficial].
*   `outputs`: Float array of shape `[L, B, C]` [S1, unofficial].
*   `dy_dx`: Float array of shape `[B, L * D * C]` [S1, unofficial].

**Parameters:**
*   $L$: Number of grid levels [S1, unofficial].
*   $C$: Number of channels per grid level. Supported values: 1, 2, 4, 8 [S1, unofficial][S3, unofficial].
*   $H$: Base resolution (resolution at level 0) [S1, unofficial].
*   $S$: Scale factor determining resolution growth per level [S1, unofficial].
*   `align_corners`: Boolean flag. If true, input range $[0,1]$ maps to $[0, \text{scale}]$. If false, it maps to $[0.5/\text{scale}, \text{scale}-0.5/\text{scale}]$ [S1, unofficial].
*   `gridtype`: Hashing strategy. 0 = Hash, 1 = Tiled [S1, unofficial].

**Data Structures:**
The embedding table is a single flat array `grid` of size $\sum_{l=0}^{L-1} \text{hashmap\_size}_l \times C$. Access to level $l$ is determined by `offsets[l]` [S1, unofficial].

**Algorithm Steps:**

1.  **Boundary Check:** If any coordinate in `inputs` is $< 0$ or $> 1$, set `outputs` to 0 and return immediately [S1, unofficial].
2.  **Normalization:** Normalize input coordinates to $[0, 1]$ range if not already done: `xyz = (inputs - xyz_min) / xyz_delta` [S3, unofficial].
3.  **Level Iteration:** For each level $l$ from $0$ to $L-1$:
    a.  **Calculate Scale and Resolution:** $\text{scale} = 2^l \times H - 1$ [S1, unofficial][S3, unofficial]. $\text{resolution} = \lceil \text{scale} \rceil + 1$ [S1, unofficial][S3, unofficial].
    b.  **Map to Grid Space:** For each dimension $d \in [0, D-1]$: $\text{pos}[d] = \text{xyz}[d] \times \text{scale} + (\text{align\_corners} ? 0.0 : 0.5)$ [S1, unofficial][S3, unofficial].
    c.  **Compute Integer Grid Coordinates:** $\text{pos\_grid}[d] = \lfloor \text{pos}[d] \rfloor$ [S1, unofficial][S3, unofficial]. $\text{pos}[d] \leftarrow \text{pos}[d] - \text{pos\_grid}[d]$ [S1, unofficial][S3, unofficial].
    d.  **Trilinear Interpolation:** Initialize `results[ch] = 0` for all $ch \in [0, C-1]$ [S1, unofficial]. Iterate over all $2^D$ corners of the voxel, indexed by $idx \in [0, 2^D - 1]$:
        i.  Compute weight $w = 1$. For each dimension $d \in [0, D-1]$: if bit $d$ of $idx$ is 0, $w \leftarrow w \times (1 - \text{pos}[d])$ and $\text{pos\_grid\_local}[d] = \text{pos\_grid}[d]$; else $w \leftarrow w \times \text{pos}[d]$ and $\text{pos\_grid\_local}[d] = \text{pos\_grid}[d] + 1$ [S1, unofficial][S3, unofficial].
        ii. **Hash Index Calculation:** Compute the hash index for the corner [S4, unofficial]. If `gridtype` is 0 (Hash) and stride exceeds `hashmap_size`, use `fast_hash` [S1, unofficial]. Otherwise, use modulo arithmetic on the stride-based index: $\text{index} = \left( \sum_{d=0}^{D-1} \text{pos\_grid\_local}[d] \times \prod_{k=0}^{d-1} (\text{resolution}+1) \right) \pmod{\text{hashmap\_size}}$ [S3, unofficial]. The final index into the `grid` array is `offsets[l] + index` [S1, unofficial].
        iii. **Accumulate Features:** For each channel $ch \in [0, C-1]$: $\text{results}[ch] \leftarrow \text{results}[ch] + w \times \text{grid}[\text{index} + ch]$ [S1, unofficial][S3, unofficial].
    e.  **Store Output:** Store `results` into `outputs[l, :, :]` [S2, unofficial].
4.  **Backward Pass:** If `dy_dx` is requested:
    a.  Initialize `dy_dx` to 0 [S1, unofficial].
    b.  For each level $l$, dimension $gd \in [0, D-1]$, and channel $ch$:
        i.  Compute partial derivative using finite differences along dimension $gd$ [S1, unofficial].
        ii. Iterate over $2^{D-1}$ corners for the fixed dimension $gd$ (left and right neighbors) [S1, unofficial].
        iii. For dimensions $nd \neq gd$, determine corner position and weight $w$ as in the forward pass [S1, unofficial].
        iv. Set $\text{pos\_grid\_local}[gd]$ to $\text{pos\_grid}[gd]$ for the left index and $\text{pos\_grid}[gd] + 1$ for the right index [S1, unofficial].
        v.  Calculate indices for left and right neighbors [S1, unofficial].
        vi. Accumulate gradient: $\text{results\_grad}[ch] \leftarrow \text{results\_grad}[ch] + w \times (\text{grid}[\text{index\_right} + ch] - \text{grid}[\text{index\_left} + ch])$ [S1, unofficial].
        vii. Write `results_grad` to `dy_dx` at offset $l \cdot D \cdot C + gd \cdot C + ch$ [S1, unofficial].
    c.  Sum gradients over levels and channels to get final `dy_dx` [S1, unofficial][S3, unofficial].

**Pseudocode:**

```python
import math

PRIMES = [1, 2654435761, 805459861, 3674653429, 2097192037, 1434869437, 2165219737]

def fast_hash(pos_grid):
    result = 0
    for i, coord in enumerate(pos_grid):
        result ^= coord * PRIMES[i]
    return result

def hash_grid_encode(inputs, embeddings, offsets, L, C, H, S, align_corners, gridtype):
    B = len(inputs)
    D = len(inputs[0])
    outputs = [[[0.0] * C for _ in range(B)] for _ in range(L)]
    
    for l in range(L):
        scale = (2 ** l) * H - 1.0
        resolution = math.ceil(scale) + 1
        hashmap_size = offsets[l+1] - offsets[l]
        grid_offset = offsets[l]
        
        for b in range(B):
            pos = [0.0] * D
            for d in range(D):
                pos[d] = inputs[b][d] * scale
                if not align_corners:
                    pos[d] += 0.5
            
            pos_grid = [int(math.floor(p)) for p in pos]
            pos_frac = [pos[d] - pos_grid[d] for d in range(D)]
            
            for idx in range(1 << D):
                w = 1.0
                pos_grid_local = [0] * D
                for d in range(D):
                    if (idx >> d) & 1:
                        w *= pos_frac[d]
                        pos_grid_local[d] = pos_grid[d] + 1
                    else:
                        w *= 1.0 - pos_frac[d]
                        pos_grid_local[d] = pos_grid[d]
                
                if gridtype == 0:
                    hash_val = fast_hash(pos_grid_local)
                    index = hash_val % hashmap_size
                else:
                    stride = 1
                    index = 0
                    for d in range(D):
                        index += pos_grid_local[d] * stride
                        stride *= (resolution + 1)
                    index = index % hashmap_size
                
                base_idx = grid_offset + index
                for ch in range(C):
                    outputs[l][b][ch] += w * embeddings[base_idx + ch]
                
    return outputs

# Backward pass computes gradients w.r.t. inputs by summing over levels and channels [S1, unofficial].
```

**Edge Cases and Pitfalls:**
*   **Out of Bounds:** Input coordinates must be in $[0, 1]$. If out of bounds, the forward pass outputs 0 and the backward pass returns immediately (gradient is 0) [S1, unofficial][S3, unofficial].
*   **AtomicAdd Performance:** In GPU implementations, `atomicAdd` on `__half` is very slow. The implementation uses `__half2` vectorization when $N_C \% 2 == 0$ (where $N_C = \min(2, C)$) to process two halves at once. If $N_C \% 2 \neq 0$, it falls back to scalar `atomicAdd` or `float` [S4, unofficial].
*   **Hash Collisions:** Handled by modulo arithmetic on the stride-based index, with a fallback to `fast_hash` when the stride exceeds `hashmap_size` [S3, unofficial].
*   **Dimensionality:** Input dimensionality $D$ is supported for values 1 through 5 [S1, unofficial], though some implementations restrict it to 2 or 3 and throw a runtime error otherwise [S3, unofficial].

## Subtopics

### [Instant-NGP](6604-instant-ngp.md)
A specific implementation of HashGrid Encoding optimized for real-time neural rendering, featuring a fixed set of resolution levels and a highly tuned hash function. Choose it when targeting consumer GPU training speeds for NeRF-like scenes.

## Operating characteristics
*   **Time Complexity:** Per sample per level, the complexity is $O(2^D)$ hash lookups and atomic additions. For a batch of size $B$ and $L$ levels, the total time complexity per thread block is $O(B \times L \times 2^D)$ [S4, unofficial].
*   **Memory Complexity:** $O(\sum_{l=0}^{L-1} \text{hashmap\_size}_l \times C)$ for the embedding table, where `hashmap_size` scales with the number of levels and desired resolution [S3, unofficial]. The total size is $sO \times C$, where $sO = \text{offsets}[L]$ [S1, unofficial][S3, unofficial].
*   **Performance:** Enables real-time training of NeRF on consumer GPUs by avoiding the memory overhead of dense high-resolution grids [S1, unofficial].
*   **Strengths:** Memory efficient for sparse scenes, supports multi-resolution details, fast lookup via hashing.
*   **Limitations:** Hash collisions can occur if the hash table is too small, leading to artifacts. Atomic operations can be a bottleneck on GPU if not vectorized [S1, unofficial][S4, unofficial].

## Background
The hash is technically not necessary for NeRF as noted in instant-ngp issue #97, but is included for general grid encoding utility [S1, unofficial].
