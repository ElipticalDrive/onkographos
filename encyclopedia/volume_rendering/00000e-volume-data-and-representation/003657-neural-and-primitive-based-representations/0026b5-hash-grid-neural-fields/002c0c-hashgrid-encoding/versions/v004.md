# HashGrid Encoding

Also called: Hash Grid, Hash Encoding, Grid Encoder, GridEncoding

## Overview
HashGrid Encoding is a learnable feature representation that maps continuous input coordinates $\mathbf{x} \in [0, 1]^D$ to multi-resolution feature vectors using spatial hashing and trilinear interpolation [S1, unofficial][S3, unofficial]. It solves the problem of efficiently storing and querying high-dimensional feature grids for neural fields (such as NeRFs) by replacing dense voxel grids with sparse, hash-mapped embedding tables [S1, unofficial][S2, unofficial]. It distinguishes itself from standard NeRF by enabling training on consumer GPUs in minutes through this sparse structure, and from pure MLPs by providing spatial locality via grid interpolation [S1, unofficial]. It builds on [Hash Grid Neural Fields](3855-hash-grid-neural-fields.md).

## How it works
**Inputs and Outputs:**
*   **Inputs:** A tensor of shape $[B, D]$ containing $B$ input coordinates, where each coordinate is normalized to $[0, 1]$ [S1, unofficial][S3, unofficial][S5, unofficial].
*   **Outputs:** A tensor of shape $[L, B, C]$ containing the interpolated features for $L$ resolution levels and $C$ channels per level [S1, unofficial][S3, unofficial][S5, unofficial].
*   **Optional Output:** A tensor `dy_dx` of shape $[B, L, D, C]$ storing the gradient of the output with respect to the input coordinates [S3, unofficial][S5, unofficial].

**Data Structures:**
*   **Embeddings (`grid`):** A flattened 1D array of shape $[sO, C]$, where $sO = \sum_{l=0}^{L-1} \text{hashmap\_size}_l$ is the total capacity of all hash tables [S3, unofficial][S5, unofficial]. Memory layout is row-major with channels contiguous [S3, unofficial].
*   **Offsets (`offsets`):** An integer array of size $L+1$ storing cumulative start indices for each level in the embeddings array [S1, unofficial][S3, unofficial][S5, unofficial]. The size of the hash table for level $l$ is $\text{hashmap\_size}_l = \text{offsets}[l+1] - \text{offsets}[l]$ [S5, unofficial].

**Parameters:**
*   $D$: Input dimensionality (typically 3) [S3, unofficial][S5, unofficial].
*   $L$: Number of resolution levels [S3, unofficial][S5, unofficial].
*   $C$: Number of feature channels per level (restricted to 1, 2, 4, or 8) [S3, unofficial][S5, unofficial].
*   $H$: Base resolution (grid size at level 0) [S3, unofficial][S5, unofficial].
*   $S$: Scaling factor exponent controlling resolution growth [S3, unofficial].
*   `align_corners`: Boolean. If `true`, maps input $[0,1]$ to grid corners; if `false`, adds 0.5 offset for center-aligned sampling [S3, unofficial].
*   `gridtype`: Hashing strategy. 0 = Hash (uses fast_hash), 1 = Tiled (linear indexing) [S1, unofficial][S3, unofficial].
*   `interp`: Interpolation type. 0 = linear, 1 = smoothstep [S3, unofficial].

**Steps:**

1.  **Input Validation:** Check if any input coordinate is outside $[0, 1]$. If so, set outputs to 0 and return (or skip processing for that batch item) [S1, unofficial][S3, unofficial].
2.  **Level Iteration:** For each level $l$ from $0$ to $L-1$:
    a.  **Calculate Scale and Resolution:**
        $$ \text{scale}_l = 2^{l \cdot S} \cdot H - 1 $$
        $$ \text{resolution}_l = \lceil \text{scale}_l \rceil + 1 $$
        [S1, unofficial][S3, unofficial][S5, unofficial]
    b.  **Coordinate Mapping:** For each input dimension $d \in [0, D-1]$:
        $$ \text{pos}[d] = \mathbf{x}[d] \times \text{scale}_l + (\text{align\_corners} ? 0.0 : 0.5) $$
        [S1, unofficial][S3, unofficial][S5, unofficial]
    c.  **Grid Positioning:**
        $$ \text{pos\_grid}[d] = \lfloor \text{pos}[d] \rfloor $$
        $$ \text{pos\_frac}[d] = \text{pos}[d] - \text{pos\_grid}[d] $$
        [S1, unofficial][S3, unofficial][S5, unofficial]
    d.  **Interpolation Weights and Corner Indices:** Iterate over all $2^D$ corners of the voxel, indexed by `idx` from $0$ to $2^D - 1$. For each dimension $d$:
        *   If bit $d$ of `idx` is 0 (lower bound):
            $$ w_d = 1 - \text{pos\_frac}[d] $$
            $$ \text{pos\_grid\_local}[d] = \text{pos\_grid}[d] $$
        *   If bit $d$ of `idx` is 1 (upper bound):
            $$ w_d = \text{pos\_frac}[d] $$
            $$ \text{pos\_grid\_local}[d] = \text{pos\_grid}[d] + 1 $$
        *   Total weight for corner: $w = \prod_{d=0}^{D-1} w_d$ [S1, unofficial][S3, unofficial][S5, unofficial].
    e.  **Hash Index Calculation:** Compute the hash index for the corner's local grid coordinates.
        *   If `gridtype` is 1 (Tiled): Use stride-based linear indexing modulo $\text{hashmap\_size}_l$ [S3, unofficial].
        *   If `gridtype` is 0 (Hash):
            $$ \text{hash}(\text{pos\_grid\_local}) = \bigoplus_{i=0}^{D-1} (\text{pos\_grid\_local}[i] \times \text{primes}[i]) $$
            where $\text{primes} = [1, 2654435761, 805459861, 3674653429, 2097192037, 1434869437, 2165219737]$ [S3, unofficial][S5, unofficial].
            $$ \text{index} = (\text{hash} \pmod{\text{hashmap\_size}_l}) \times C + ch $$
            [S3, unofficial][S5, unofficial]
            *Note: If stride exceeds hashmap_size, fallback to hash function [S5, unofficial].*
    f.  **Feature Accumulation:** For each channel $ch \in [0, C-1]$:
        $$ \text{results}[ch] += w \times \text{grid}[\text{index} + ch] $$
        [S1, unofficial][S3, unofficial][S5, unofficial]
3.  **Output:** Store accumulated results for level $l$ into the output tensor [S1, unofficial][S3, unofficial].

**Gradient Computation (Backward Pass):**
1.  **Grid Gradients:** For each corner and channel, compute the gradient contribution:
    $$ \text{grad\_grid}[\text{index} + ch] += w \times \text{grad\_output}[ch] $$
    Use `atomicAdd` for concurrent updates [S3, unofficial][S5, unofficial].
2.  **Input Gradients (`dy_dx`):** If requested, for each dimension $gd \in [0, D-1]$:
    a.  Initialize `results_grad` to 0.
    b.  Iterate over $2^{D-1}$ neighbors fixing $gd$. For dimensions $nd \neq gd$, determine corner position and weight $w_{nd}$ as in forward pass.
    c.  Compute left and right indices along $gd$:
        $$ \text{index\_left} = \text{get\_grid\_index}(\dots, \text{pos\_grid}[gd]) $$
        $$ \text{index\_right} = \text{get\_grid\_index}(\dots, \text{pos\_grid}[gd] + 1) $$
    d.  Compute derivative weight:
        $$ w_{gd} = \text{scale}_l \times \prod_{nd \neq gd} w_{nd} $$
        If `interp` is smoothstep, apply derivative of smoothstep: $6 \cdot \text{pos\_frac}[gd] \cdot (1 - \text{pos\_frac}[gd])$ [S3, unofficial].
    e.  Accumulate:
        $$ \text{results\_grad}[ch] += w_{gd} \times (\text{grid}[\text{index\_right} + ch] - \text{grid}[\text{index\_left} + ch]) $$
    f.  Store in `dy_dx` [S1, unofficial][S3, unofficial][S5, unofficial].

**Pseudocode:**

```python
import math

def hash_encode(inputs, offsets, embeddings, L, C, H, S, align_corners, gridtype):
    """
    inputs: [B, D] float, normalized to [0, 1]
    offsets: [L+1] int, cumulative hash table sizes
    embeddings: [sO, C] float, flattened hash tables
    L: int, number of levels
    C: int, channels per level
    H: int, base resolution
    S: float, scale exponent
    align_corners: bool
    gridtype: int, 0 for hash, 1 for tiled
    """
    B, D = inputs.shape
    primes = [1, 2654435761, 805459861, 3674653429, 2097192037, 1434869437, 2165219737]
    outputs = [None] * L
    
    for l in range(L):
        scale = 2.0 ** (l * S) * H - 1.0
        resolution = math.ceil(scale) + 1
        hashmap_size = offsets[l+1] - offsets[l]
        level_outputs = []
        
        for b in range(B):
            # Check bounds
            if any(inputs[b, d] < 0.0 or inputs[b, d] > 1.0 for d in range(D)):
                level_outputs.append([0.0] * C)
                continue
                
            # Map to grid space
            pos = [0.0] * D
            pos_grid = [0] * D
            pos_frac = [0.0] * D
            
            for d in range(D):
                offset = 0.0 if align_corners else 0.5
                pos[d] = inputs[b, d] * scale + offset
                pos_grid[d] = int(math.floor(pos[d]))
                pos_frac[d] = pos[d] - pos_grid[d]
            
            # Interpolate over 2^D corners
            results = [0.0] * C
            num_corners = 1 << D
            
            for idx in range(num_corners):
                w = 1.0
                pos_grid_local = [0] * D
                
                for d in range(D):
                    if (idx & (1 << d)) == 0:
                        w *= 1.0 - pos_frac[d]
                        pos_grid_local[d] = pos_grid[d]
                    else:
                        w *= pos_frac[d]
                        pos_grid_local[d] = pos_grid[d] + 1
                
                # Compute hash index
                if gridtype == 1:
                    # Tiled: linear indexing
                    # Simplified: assuming stride-based calculation not fully detailed in sources for generic D
                    # Using hash fallback for consistency with sources' emphasis on hash
                    pass 
                
                # Hash calculation (default or fallback)
                h = 0
                for i in range(D):
                    h ^= pos_grid_local[i] * primes[i]
                
                index = (h % hashmap_size) * C
                
                # Accumulate features
                for ch in range(C):
                    results[ch] += w * embeddings[index + ch]
            
            level_outputs.append(results)
        
        outputs[l] = level_outputs
    
    return outputs

    """

    primes = [1, 2654435761, 805459861, 3674653429, 2097192037, 1434869437, 2165219737]
    dy_dx = [[[0.0] * C for _ in range(D)] for _ in range(B)]

            pos_grid = [0] * D
            pos_frac = [0.0] * D

                pos[d] = inputs[b, d] * scale + offset

            for gd in range(D):
                # Initialize gradient for this dimension
                grad_dim = [0.0] * C

                # We need to sum contributions from left and right neighbors along gd
                # This is equivalent to: scale * product(other weights) * (grid_right - grid_left)

                for d in range(D):

                    # Actually, the derivative is computed by considering the change in pos_frac[gd]
                    # The standard trilinear derivative involves the difference of features

                    # We must sum over all combinations of other dimensions.

                # Loop over 2^(D-1) masks for other dims
                num_other = 1 << (D - 1)
                for mask in range(num_other):
                    w_other = 1.0
                    pos_grid_local_left = [0] * D
                    pos_grid_local_right = [0] * D
                    
                    other_d_idx = 0
                    for d in range(D):
                        if d == gd:
                            continue
                        bit = (mask >> other_d_idx) & 1
                        if bit == 0:
                            w_other *= 1.0 - pos_frac[d]
                            pos_grid_local_left[d] = pos_grid[d]
                            pos_grid_local_right[d] = pos_grid[d]
                        else:
                            w_other *= pos_frac[d]
                            pos_grid_local_left[d] = pos_grid[d] + 1
                            pos_grid_local_right[d] = pos_grid[d] + 1
                        other_d_idx += 1
                    
                    # Left index along gd
                    pos_grid_local_left[gd] = pos_grid[gd]
                    h_left = 0
                    for i in range(D):
                        h_left ^= pos_grid_local_left[i] * primes[i]
                    index_left = (h_left % hashmap_size) * C
                    
                    # Right index along gd
                    pos_grid_local_right[gd] = pos_grid[gd] + 1
                    h_right = 0
                    for i in range(D):
                        h_right ^= pos_grid_local_right[i] * primes[i]
                    index_right = (h_right % hashmap_size) * C
                    
                    w_gd = scale * w_other
                    
                    for ch in range(C):
                        diff = embeddings[index_right + ch] - embeddings[index_left + ch]
                        grad_dim[ch] += w_gd * diff
                
                for ch in range(C):
                    dy_dx[b][l][gd][ch] = grad_dim[ch]
                    
    return dy_dx
```

## Subtopics

### [Instant-NGP](6604-instant-ngp.md)
Instant-NGP is a method for fast neural radiance field (NeRF) reconstruction that utilizes a multiresolution hash grid encoding to map spatial coordinates to feature vectors, which are then processed by small multi-layer perceptrons (MLPs) to predict density and color. It distinguishes itself from standard NeRF by replacing the large, static voxel grid or pure MLP with a learnable, sparse hash table structure, enabling training on consumer GPUs in minutes rather than hours. While it builds on [HashGrid Encoding](3866-hashgrid-encoding.md), Instant-NGP specifically defines the network architecture, density mapping, and sampling strategies required to achieve real-time rendering capabilities.

## Operating characteristics
*   **Time Complexity:** Forward pass is $O(B \cdot L \cdot 2^D \cdot C)$ operations per batch element [S3, unofficial]. Backward grid pass is $O(B \cdot L \cdot 2^D \cdot N_C)$ with atomic addition overhead [S3, unofficial].
*   **Memory Complexity:** $O(sO \times C)$ for the embedding table, where $sO$ scales with the number of levels and desired resolution [S5, unofficial].
*   **Performance:** Enables training on consumer GPUs in minutes [S2, unofficial].
*   **Strengths:** Sparse storage allows high-resolution grids without excessive memory usage; differentiable; fast lookup [S1, unofficial][S3, unofficial].
*   **Limitations:** Hash collisions can occur if `hashmap_size` is small relative to the number of voxels, requiring fallback to hash functions or causing gradient noise [S3, unofficial][S5, unofficial]. Atomic operations for half-precision (`__half`) are slow; `__half2` vectorization is used when $N_C \% 2 == 0$ [S1, unofficial][S5, unofficial].
*   **When to use:** When training neural fields on limited hardware or requiring fast convergence [S1, unofficial].
*   **When not to use:** When exact spatial locality without hashing artifacts is required and memory is abundant (use Tiled Grid or dense Voxel Grid).

## Background
HashGrid Encoding was introduced as part of the Instant-NGP method for fast neural radiance field reconstruction [S1, unofficial][S2, unofficial]. It addresses the memory and computational bottlenecks of dense voxel grids and pure MLPs in NeRFs by using a sparse, hash-mapped multi-resolution feature grid [S1, unofficial]. The technique allows for efficient training and rendering on consumer-grade hardware [S2, unofficial].
