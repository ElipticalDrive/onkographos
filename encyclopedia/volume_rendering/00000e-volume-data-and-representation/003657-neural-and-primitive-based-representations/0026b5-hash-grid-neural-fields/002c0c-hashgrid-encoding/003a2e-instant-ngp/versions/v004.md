# Instant-NGP

Also called: Instant Neural Graphics Primitives

## Overview
Instant-NGP replaces the slow multi-layer perceptron (MLP) of standard Neural Radiance Fields (NeRF) with a multi-resolution hash-encoded feature grid to accelerate training and rendering while maintaining comparable quality [S1, S3, S7]. It achieves a 1000–10000× training speedup, enabling convergence in 2–5 minutes on a single GPU, by leveraging highly optimized GPU hash table lookups to reduce MLP depth and width [S1]. Unlike frequency-based encodings that prioritize low-frequency shape capture, hash encoding facilitates both overall shape and local textures, outperforming vanilla NeRF in preserving sharpness and fine details [S3].

## How it works
**Inputs and Outputs:**
- **Input:** 3D spatial coordinates $\mathbf{x}$ and view direction $\mathbf{d}$. Auxiliary non-spatial dimensions $\xi$ (e.g., material parameters) may also be provided [S4].
- **Output:** Volume density $\sigma$ and RGB color $\mathbf{c}$ [S5].

**Data Structures:**
1.  **Multi-resolution Hash Grid (MHG):** A set of $L$ hash tables, one per resolution level $l \in \{0, \dots, L-1\}$.
    -   Each table maps 3D grid coordinates to feature vectors.
    -   Entry precision: Half-precision (2 bytes) for storage, with a master full-precision copy for stable mixed-precision updates [S4].
    -   Feature dimension per lookup: $F$. Optimal $F=2$ balances cache locality and memory coherence [S4].
    -   Hash table size threshold: Performance remains constant for total entries $T \le 2^{19}$. Beyond this, performance drops due to L2 cache limits (e.g., 6 MB on RTX 3090) where $2 \cdot T \cdot F > 6 \cdot 2^{20}$ bytes [S4]. If voxel count exceeds $2^{19}$, positions are hashed to a one-dimensional table [S2].
2.  **Encoder MLP:** Takes concatenated multi-scale features as input.
    -   Architecture: 4-layer MLP with dimensions $32 \times 64$, $64 \times 64$, $64 \times 64$, $64 \times 8$ [S5].
    -   Input: 32-dimensional vector (multiresolution hash encoded position) [S5].
    -   Output: 8D feature vector $M_i$ and opacity $\alpha_i$ [S5].
    -   Activation: GELU [S2].
3.  **Density Mapping Layer:**
    -   Real-world 360 dataset: Linear transform from feature vector to density [S2].
    -   NeRF synthetic dataset: Tiny network with one hidden layer and 64 neurons [S2].
4.  **Decoder MLP:**
    -   Architecture: 3-layer MLP with dimensions $17 \times 16$, $16 \times 16$, $16 \times 3$ [S5].
    -   Input: 17D vector (8D spatial features $M_i$ + 9D view direction $\mathbf{d}$ encoded via Spherical Harmonics) [S5].
    -   Output: 3D RGB color $\mathbf{c}_i$ [S5].
    -   *Note:* Some implementations use two hidden layers of width 64 with ReLU for non-NeRF tasks [S4].

**Numbered Steps:**
1.  **Hash Encoding:** For each resolution level $l$, hash the input coordinate $\mathbf{x}$ to a table index. Retrieve the feature vector $\mathbf{f}_l$ from the hash table. Concatenate features from all levels to form the input vector for the Encoder MLP [S1, S4].
2.  **Feature Extraction:** Pass the concatenated features through the Encoder MLP to obtain the 8D feature vector $M_i$ and opacity $\alpha_i$ [S5].
3.  **Density Estimation:** Derive density $\sigma$ from $M_i$ using the density mapping layer (linear or tiny MLP) [S2].
4.  **Color Prediction:** Encode view direction $\mathbf{d}$ using Spherical Harmonics (degree 4, yielding 9 coefficients) [S2, S5]. Concatenate $M_i$ and SH coefficients to form the 17D input for the Decoder MLP. Output RGB color $\mathbf{c}_i$ [S5].
5.  **Rendering:** Use volume rendering (ray marching) with the estimated density and color to compute pixel colors [S1].

def hash_encode(x, hash_tables, num_levels, feature_dim):
    """
    Multi-resolution hash encoding.
    x: (N, 3) input coordinates
    hash_tables: List of L arrays, each of size T_l
    num_levels: Number of resolution levels L
    feature_dim: Feature dimension per level F
    Returns: (N, L * F) concatenated features
    """
    features = []
    # Evaluate hash tables level by level for cache optimization [S4]
    for l in range(num_levels):
        table = hash_tables[l]
        # Hash function: map 3D coord to table index
        # Standard implementation uses a simple hash function (e.g., XOR folding)
        # and handles collisions via probing or chaining.
        # Here we assume a direct hash function h(x, l) -> index
        indices = compute_hash_indices(x, l)
        
        # Gather features from the table
        # Table entries are stored as half-precision, but read as float for computation
        # In practice, this is done via CUDA gather instructions
        level_features = gather_features(table, indices, feature_dim)
        features.append(level_features)
    
    # Concatenate features from all levels
    return torch.cat(features, dim=-1)

def encoder_mlp(features):
    """
    Encoder MLP: 4 layers, dimensions 32->64->64->64->8
    Input: 32D (L=16 levels, F=2)
    Output: 8D feature vector + opacity
    """
    # Layer 1: 32 -> 64, GELU
    x = torch.nn.functional.gelu(torch.nn.functional.linear(features, W1, b1))
    # Layer 2: 64 -> 64, GELU
    x = torch.nn.functional.gelu(torch.nn.functional.linear(x, W2, b2))
    # Layer 3: 64 -> 64, GELU
    x = torch.nn.functional.gelu(torch.nn.functional.linear(x, W3, b3))
    # Layer 4: 64 -> 8
    out = torch.nn.functional.linear(x, W4, b4)
    return out[:, :8], out[:, 8:] # Feature vector, Opacity

def decoder_mlp(spatial_features, view_direction):
    """
    Decoder MLP: 3 layers, dimensions 17->16->16->3
    Input: 17D (8D spatial + 9D SH direction)
    Output: 3D RGB color
    """
    # Concatenate spatial features and SH-encoded direction
    input_vec = torch.cat([spatial_features, view_direction], dim=-1)
    
    # Layer 1: 17 -> 16, ReLU (or GELU depending on variant)
    x = torch.nn.functional.relu(torch.nn.functional.linear(input_vec, W5, b5))
    # Layer 2: 16 -> 16, ReLU
    x = torch.nn.functional.relu(torch.nn.functional.linear(x, W6, b6))
    # Layer 3: 16 -> 3
    color = torch.nn.functional.linear(x, W7, b7)
    return color

**Parameters:**
-   **Hash Table Size ($T$):** Optimal performance for $T \le 2^{19}$ [S4].
-   **Feature Dimensions ($F$):** 2 [S4].
-   **Number of Levels ($L$):** 16 for NeRF synthetic, 18 for real-world 360 [S2].
-   **MLP Width:** 64 neurons for hidden layers [S4, S5].
-   **Learning Rate:** 0.01 for Adam [S2].
-   **Activation:** GELU [S2].

**Edge Cases and Pitfalls:**
-   **Hash Collisions:** Multi-resolution structure helps eliminate ambiguity from hash conflicts [S7].
-   **Surface Accuracy:** Moderate surface accuracy because it uses a faster density representation rather than explicit surface geometry (SDF) [S1].
-   **Soft Tissues:** NeRF techniques are sensitive to tissue type; soft tissues have lower contrast and homogeneous textures, leading to artifact-free but potentially less detailed or slightly blurred reconstructions [S3].

## Subtopics

### [Multi-resolution Hash Encoding with Simplex Structure](9584-multi-resolution-hash-encoding-with-simplex-structure.md)
Multi-resolution Hash Encoding with Simplex Structure replaces the explicit hypercube-based grid of Instant-NGP with a simplex-based structure, using hash tables to store learnable feature vectors at simplex vertices across multiple resolution levels. It solves the memory inefficiency of dense grids in simplicial domains by storing only accessed vertices, avoiding the overhead of explicit ordering for unused vertices. It sets itself apart from standard Instant-NGP by using barycentric interpolation within skewed simplices rather than trilinear interpolation within hypercubes.

### F-Hash
F-Hash extends multi-resolution hash encoding to four dimensions using Tesseract grids and collision-free minimal perfect hashing for faster convergence [S8, unofficial]. It achieves 10–100× faster convergence than standard hash encoding (e.g., 47.1 dB in 7.4 minutes vs. 23.7 dB in 45.7 minutes on combustion data) with compression ratios of 9.5–55.2× [S8, unofficial].

## Operating characteristics
-   **Training Speed:** 1000–10000× faster than NeRF, converging in 2–5 minutes on a single GPU (e.g., A100) [S1]. Converges to 95% of final PSNR in 2.4 ± 0.4 minutes on Blender scenes [S1].
-   **Rendering Speed:** 2.4 ± 0.4 FPS at 1080p on an A100 GPU [S1]. This is 12× faster than NeRF (0.2 FPS) but 28× slower than 3D Gaussian Splatting (68.4 FPS) [S1].
-   **Quality:** On NeRF Synthetic (Blender) dataset, PSNR = 32.6 ± 0.4 dB [S1]. On Mip-NeRF 360 unbounded dataset, PSNR = 26.4 ± 0.6 dB [S1]. In medical imaging (Chest dataset), 3D SSIM = 0.943 vs. 0.885 for vanilla NeRF [S3].
-   **Memory:** Hash table entries stored at half precision (2 bytes) to optimize performance [S4]. Performance degrades if total hash table size exceeds L2 cache capacity (e.g., 6 MB on RTX 3090) [S4].
-   **Strengths:** Extremely fast training, suitable for rapid prototyping and real-time feedback during acquisition [S1]. Preserves fine details and sharp edges better than frequency-based encodings [S3].
-   **Limitations:** Moderate surface accuracy compared to SDF-based methods like NeuS [S1]. Rendering speed is significantly lower than explicit methods like 3DGS [S1]. Performance sensitive to hash table size relative to GPU cache [S4].

## Background
Instant-NGP (Instant Neural Graphics Primitives) was introduced by Müller et al. in 2022 [S4]. It was developed to address the slow training and rendering speeds of NeRF by replacing the MLP with a multi-resolution hash-encoded feature grid [S1]. The method leverages CUDA and the tiny-cuda-nn framework for optimized inference and backpropagation [S4]. It has been widely adopted for rapid neural rendering and is used in various applications including medical image reconstruction, where it outperforms traditional methods like FDK and vanilla NeRF in preserving structural details [S3].
