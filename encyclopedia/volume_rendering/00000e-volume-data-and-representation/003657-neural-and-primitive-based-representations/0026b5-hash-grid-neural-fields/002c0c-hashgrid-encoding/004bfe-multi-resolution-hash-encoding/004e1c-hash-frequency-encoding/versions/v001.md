# Hash-Frequency Encoding

Also called: Composited Encoding, HE+FE

## Overview
Hash-Frequency Encoding (HE+FE) is a hybrid feature representation for Neural Radiance Fields that combines multi-resolution hash encoding with sinusoidal frequency encoding to improve robustness on sparse input views [S1]. It addresses the degradation and artifact generation (floaters) typical of pure hash-based methods like Nerfacto when camera coverage is limited, while avoiding the slow convergence of pure frequency-based methods like MIP-NeRF 360 [S1].

## How it works
**Inputs:** 3D spatial coordinates $\mathbf{x} \in \mathbb{R}^3$.
**Outputs:** A concatenated feature vector $\mathbf{v}$ passed to a lightweight MLP.

**Data Structures:**
1.  **Hash Grids:** A set of $L_H$ hash tables (levels). Each level $l$ has a resolution $R_l$ and stores feature vectors of dimension $F_H$. The hash function maps coordinates to table indices.
2.  **Frequency Levels:** A set of $L_F$ frequency bands. Each band $k$ uses a base frequency $\omega_k$.

**Parameters:**
*   $L_H = 16$: Fixed number of hash grid levels (default) [S1].
*   $L_F$: Number of frequency levels. Swept values: $\{2, 4, 8, 16\}$. Optimal value found to be $L_F = 8$ (HE+FE8) [S1].
*   $\omega_k$: Frequency scaling factor for level $k$. Typically $\omega_k = 2^k$ or similar geometric progression, though exact scaling is not specified in the source [G].

**Algorithm:**
1.  **Hash Encoding:** For each hash level $l \in [0, L_H-1]$:
    *   Quantize $\mathbf{x}$ to the grid resolution $R_l$.
    *   Compute hash index $h_l = \text{Hash}(\mathbf{x}, l)$.
    *   Retrieve feature vector $\mathbf{f}_l$ from the hash table at index $h_l$.
    *   Concatenate $\mathbf{f}_l$ into a hash feature list.
2.  **Frequency Encoding:** For each frequency level $k \in [0, L_F-1]$:
    *   Compute scaled coordinates $\mathbf{x}'_k = \omega_k \mathbf{x}$.
    *   Apply sinusoidal mapping: $\mathbf{s}_k = [\sin(\mathbf{x}'_k), \cos(\mathbf{x}'_k)]$.
    *   Concatenate $\mathbf{s}_k$ into a frequency feature list.
3.  **Concatenation:** Combine all hash features and frequency features into the final vector $\mathbf{v}$ [S1].

**Pseudocode:**
```python
def hash_frequency_encoding(x, hash_tables, num_freq_levels=8):
    """
    x: torch.Tensor of shape (..., 3)
    hash_tables: List of torch.Tensor, each of shape (num_entries, feature_dim)
    num_freq_levels: Integer, number of frequency bands
    """
    features = []
    
    # 1. Hash Encoding (L_H = 16 fixed)
    for i, table in enumerate(hash_tables):
        # Quantize and hash x to get indices for this level
        # Note: Exact hashing logic depends on Instant-NGP implementation details
        # Assuming a helper function that returns indices for all points
        indices = compute_hash_indices(x, level=i) 
        # Gather features from the table
        # Expand dims for broadcasting if necessary
        table_expanded = table.unsqueeze(0) # (1, num_entries, feat_dim)
        indices_expanded = indices.unsqueeze(-1).expand(-1, -1, table.shape[1])
        hash_feats = torch.gather(table_expanded, 1, indices_expanded)
        features.append(hash_feats)
        
    # 2. Frequency Encoding
    for k in range(num_freq_levels):
        # Base frequency scaling. Source does not specify exact omega_k formula.
        # Standard practice is geometric progression, e.g., 2^k.
        # [G] Assuming omega_k = 2^k for implementation completeness.
        omega = 2 ** k
        scaled_x = x * omega
        sin_vals = torch.sin(scaled_x)
        cos_vals = torch.cos(scaled_x)
        freq_feats = torch.cat([sin_vals, cos_vals], dim=-1)
        features.append(freq_feats)
        
    # 3. Concatenate all features
    # features is a list of tensors. Concatenate along the last dimension.
    v = torch.cat(features, dim=-1)
    return v
```

**Edge Cases and Pitfalls:**
*   **Sparse Inputs:** Pure hash encoding degrades significantly with sparse views (e.g., 2x2x2 camera setup) [S1]. HE+FE mitigates this.
*   **Training Time:** While comparable to MIP-NeRF 360 in quality, HE+FE trains significantly faster (~5 mins vs ~2 hours on NVIDIA A40) [S1].
*   **Frequency Level Selection:** $L_F=8$ provides the most stable PSNR/SSIM/LPIPS across sparse and normal setups [S1].

## Subtopics
## Operating characteristics
*   **Performance:** HE+FE8 provides stable PSNR, SSIM, and LPIPS on synthetic datasets (Classroom, Lone Monk) with both sparse (2x2x2) and normal (3x3x2) camera setups [S1].
*   **Comparison:** Outperforms Nerfacto (hash-only) on sparse inputs, avoiding heavy degradation and floaters [S1]. Achieves results comparable to or better than MIP-NeRF 360 (frequency-only) [S1].
*   **Efficiency:** Training time is approximately 5 minutes, compared to ~2 hours for MIP-NeRF 360 on a single NVIDIA A40 [S1].
*   **Limitations:** May not be optimal for normal camera setups where high-contrast axis-aligned structures (e.g., blinds) are present, as MIP-NeRF 360 can sometimes yield better results in those specific high-contrast scenarios [S1].

## Background
Originating from research on Neural Radiance Fields from sparse 360° input, Hash-Frequency Encoding was introduced to balance the memory efficiency of hash encoding with the global continuity of frequency encoding [S1]. It was developed to address the specific challenge of reconstructing scenes from sparse omnidirectional image (ODI) inputs, where standard hash-based methods fail to generalize [S1].
