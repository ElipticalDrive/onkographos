# Multi-resolution Hash Encoding with Simplex Structure

Also called: Simplex Instant-NGP, Simplicial Grid Hashing

## Overview
Multi-resolution Hash Encoding with Simplex Structure replaces the explicit hypercube grid of Instant-NGP with a simplex-based structure that stores learnable feature vectors at simplex vertices across multiple resolution levels using hash tables [S1, unofficial]. It sets itself apart from standard Instant-NGP by performing barycentric interpolation within skewed simplices rather than trilinear interpolation within hypercubes, which avoids the memory inefficiency and ordering overhead of dense grids for simplicial domains [S1, unofficial].

## How it works
**Inputs:** Input coordinate $\mathbf{x} \in \mathbb{R}^n$ (typically $n=2$ or $3$), number of multi-resolution levels $L$, hash table size $M$ per level, auxiliary inputs (e.g., view direction) [S1, unofficial].
**Outputs:** Encoded feature vector concatenated from all levels, ready for MLP input [S1, unofficial].

**Data Structures:**
*   **Hash Tables ($H_l$):** For each level $l \in \{0, \dots, L-1\}$, a hash table mapping integer vertex indices to $d$-dimensional feature vectors [S1, unofficial].

**Parameters:**
*   $L$: Number of levels. Typical value: 16 [S1, unofficial].
*   $M$: Hash table size per level. Fixed size scaled by $(n+1)^{(n-1)/2}$ [S1, unofficial].
*   $n$: Input dimension.
*   $d$: Feature vector dimension.

**Steps:**
1.  **Coordinate Skewing:** Transform the input coordinate $\mathbf{x}$ to a skewed space $\mathbf{x}'$ using an affine transformation $\mathbf{x}' = \mathbf{A}\mathbf{x}$, where the matrix $\mathbf{A}$ has diagonal entries $1+F_n$ and off-diagonal entries $1$, with $F_n = \frac{\sqrt{n+1}-1}{n}$ [S1, unofficial].
2.  **Scale Adjustment:** Apply an adjustment scale $S_n = \sqrt{n+1}$ to ensure the skewed parallelepiped covers the sampling volume entirely and avoids out-of-bounds access, yielding $\mathbf{x}_{eff} = S_n \mathbf{x}'$ [S1, unofficial].
3.  **Level Scaling:** For each level $l$, scale the coordinate by $2^l$ to get $\mathbf{x}_l = 2^l \mathbf{x}_{eff}$ [S1, unofficial].
4.  **Voxel Identification:** Compute the floor $\lfloor \mathbf{x}_l \rfloor$ and ceiling $\lceil \mathbf{x}_l \rceil$ of the scaled coordinate to identify the local parallelepiped (unit n-cube in skewed space) containing the point [S1, unofficial].
5.  **Hashing:** Hash the integer coordinates of the parallelepiped corners to assign indices in the hash table $H_l$ [S1, unofficial].
6.  **Lookup:** Retrieve the $d$-dimensional feature vectors from $H_l$ for all corner indices [S1, unofficial].
7.  **Interpolation:** Perform barycentric interpolation on the retrieved feature vectors based on the relative position of $\mathbf{x}_l$ within the unit n-cube [S1, unofficial].
8.  **Concatenation:** Concatenate the results from all levels and auxiliary inputs for MLP input [S1, unofficial].
9.  **Backpropagation:** Propagate the loss through the MLP, interpolation, and update the looked-up features [S1, unofficial].

**Pseudocode:**

import numpy as np

def simplex_hash_encoding(x, L, M, d, n, hash_tables):
    """
    x: input coordinate, shape (n,)
    L: number of levels
    M: hash table size per level
    d: feature vector dimension
    n: input dimension
    hash_tables: list of L dictionaries mapping int index to feature vector
    """
    # Precompute skewing matrix A
    F_n = (np.sqrt(n + 1) - 1) / n
    A = np.ones((n, n))
    np.fill_diagonal(A, 1 + F_n)
    
    # Scale adjustment factor
    S_n = np.sqrt(n + 1)
    
    # Skew and scale the input coordinate
    x_skewed = A @ x
    x_scaled = S_n * x_skewed
    
    encoded_features = []
    
    for l in range(L):
        # Scale by level
        x_l = (2 ** l) * x_scaled
        
        # Identify voxel bounds
        floor_coords = np.floor(x_l).astype(int)
        ceil_coords = np.ceil(x_l).astype(int)
        
        # Generate all 2^n corner coordinates of the hypercube
        corners = []
        for mask in range(1 << n):
            corner = np.array([(floor_coords[i] if (mask >> i) & 1 else ceil_coords[i]) for i in range(n)])
            corners.append(corner)
            
        # Hash corners to indices
        indices = []
        for v in corners:
            # Standard polynomial hash for integer vectors
            h = 0
            for c in v:
                h = (h * 31 + c) % M
            indices.append(h)
        
        # Lookup features
        features = []
        for idx in indices:
            if idx in hash_tables[l]:
                features.append(hash_tables[l][idx])
            else:
                # Initialize new features to zero [G]
                feat = np.zeros(d)
                hash_tables[l][idx] = feat
                features.append(feat)
                
        # Barycentric Interpolation
        # The source specifies barycentric interpolation within the simplex.

        # specific simplex containing x_l are not provided in the sources.
        # In practice, one determines the permutation pi such that x_l falls

        # vertices = get_simplex_vertices(floor_coords, ceil_coords, n)
        # interpolated_feat = sum(w * f for w, f in zip(weights, features))

        encoded_features.append(interpolated_feat)
    
    # Concatenate all levels
    final_encoding = np.concatenate(encoded_features)
    return final_encoding

**Edge Cases and Pitfalls:**
*   **Out-of-bounds Access:** The skewed vertex $\mathbf{1}^T$ becomes $\sqrt{n+1}\mathbf{1}^T$ in the new coordinate system, making the resulting parallelepiped smaller than the original hypercube [S1, unofficial]. Without the scale adjustment $S_n = \sqrt{n+1}$, accessing points outside the simplicial grids can occur [S1, unofficial].
*   **Memory Efficiency:** Using a dense grid for simplicial grids is extremely inefficient because only a portion of vertices are accessed [S1, unofficial]. Hash tables are used to avoid this memory wastage and the overhead of explicit ordering [S1, unofficial].
*   **Collision Handling:** Hash collisions may occur [S1, unofficial]. The source suggests using a hash table size based on the theoretical ratio of used vertices to total vertices, which converges to 1 as levels increase [S1, unofficial]. In practice, a fixed size scaled by $(n+1)^{(n-1)/2}$ is used [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Similar to Instant-NGP, but with additional overhead for coordinate skewing and simplicial subdivision [S1, unofficial].
*   **Memory Complexity:** More memory efficient than dense grids for simplicial structures [S1, unofficial]. Hash table size is determined by the ratio of parallelepiped volume to hypercube volume, approximated as $(n+1)^{(n-1)/2}$ [S1, unofficial].
*   **Measured Performance:** On a 439M pixel image overfitting task with 16 levels and $2^{19}$ hash table size, simplex encoding achieved PSNR 29.94 in 14.94 seconds, compared to grid-based PSNR 29.82 in 16.34 seconds [S1, unofficial].
*   **Scaling:** The ratio of used vertices to total vertices decays exponentially but converges to the theoretical lower bound as levels increase [S1, unofficial].
*   **Strengths:** Memory efficiency for simplicial structures; comparable or slightly better performance than grid-based methods in some tasks [S1, unofficial].
*   **Limitations:** Additional computational overhead for coordinate skewing and simplicial subdivision [S1, unofficial].
*   **When to use:** Suitable when encoding graphics primitives with simplicial domains where memory efficiency is prioritized and the overhead of skewing is acceptable [S1, unofficial].

## Background
This method was proposed in "Efficient Encoding of Graphics Primitives with Simplex-based Structures" [S1, unofficial]. It builds on the Instant-NGP framework by replacing the hypercube-based grid with a simplex-based structure to leverage the properties of simplices for more efficient encoding of graphics primitives [S1, unofficial].
