# Multi-resolution Hash Encoding with Simplex Structure

Also called: Simplex Instant-NGP, Simplicial Grid Hashing

## Overview
Multi-resolution Hash Encoding with Simplex Structure is a neural encoding method that replaces the explicit hypercube-based grid structure of Instant-NGP with a simplex-based structure, using hash tables to store learnable feature vectors at simplex vertices across multiple resolution levels [S1, unofficial]. It solves the memory inefficiency of dense grids in simplicial domains by storing only accessed vertices, avoiding the overhead of explicit ordering for unused vertices [S1, unofficial]. It sets itself apart from standard Instant-NGP by using barycentric interpolation within skewed simplices rather than trilinear interpolation within hypercubes [S1, unofficial].

## How it works
**Inputs:** Input coordinate $\mathbf{x} \in \mathbb{R}^n$ (typically $n=2$ or $3$); number of multi-resolution levels $L$; hash table size $M$ per level; auxiliary inputs (e.g., view direction, time) [S1, unofficial].
**Outputs:** Encoded feature vector concatenated from all levels, ready for MLP input [S1, unofficial].

**Data Structures:**
*   **Hash Tables ($H_l$):** For each level $l \in \{0, \dots, L-1\}$, a hash table mapping integer vertex indices to $d$-dimensional feature vectors. The size is fixed at $M$ [S1, unofficial].
*   **Feature Vectors:** Stored in $H_l$. Size $d$ is a hyperparameter [S1, unofficial].

**Parameters:**
*   $L$: Number of levels. Typical value: 16 [S1, unofficial].
*   $M$: Hash table size per level. Determined by scaling factors related to dimension $n$. Typical value: $2^{19}$ [S1, unofficial].
*   $n$: Input dimension.

**Steps:**
1.  **Coordinate Skewing:** Transform the input coordinate $\mathbf{x}$ to a skewed space $\mathbf{x}'$ using an affine transformation matrix. This maps the unit hypercube to a skewed parallelepiped containing the simplex [S1, unofficial].
    $$ \mathbf{x}' = \mathbf{A} \mathbf{x} $$
    where $\mathbf{A}$ is defined by $F_n = \frac{\sqrt{n+1}-1}{n}$:
    $$ \mathbf{A} = \begin{bmatrix} 1+F_n & \cdots & 1 \\ \vdots & \ddots & \vdots \\ 1 & \cdots & 1+F_n \end{bmatrix} $$
    [S1, unofficial]
2.  **Scale Adjustment:** To ensure the skewed parallelepiped covers the sampling volume entirely and avoids out-of-bounds access, apply an adjustment scale $S_n = \sqrt{n+1}$ [S1, unofficial]. The effective coordinate becomes $\mathbf{x}_{eff} = S_n \mathbf{x}'$ [S1, unofficial].
3.  **Level Scaling:** For each level $l$, scale the coordinate $\mathbf{x}_{eff}$ by $2^l$. Let $\mathbf{x}_l = 2^l \mathbf{x}_{eff}$ [S1, unofficial].
4.  **Voxel Identification:** Compute the floor $\lfloor \mathbf{x}_l \rfloor$ and ceiling $\lceil \mathbf{x}_l \rceil$ of the scaled coordinate to identify the local parallelepiped (unit n-cube in skewed space) containing the point [S1, unofficial].
5.  **Hashing:** For each vertex of the identified parallelepiped, compute its integer coordinates. Hash these integer coordinates to an index in the hash table $H_l$ [S1, unofficial].
6.  **Lookup:** Retrieve the $d$-dimensional feature vectors from $H_l$ for all hashed vertex indices [S1, unofficial].
7.  **Barycentric Interpolation:** Perform barycentric interpolation on the retrieved feature vectors based on the relative position of $\mathbf{x}_l$ within the unit n-cube. The interpolation weights are determined by the barycentric coordinates of the point within the simplex formed by the vertices [S1, unofficial].
    *   Note: The simplex vertices are a subset of the hypercube vertices. The interpolation is performed over the simplex defined by the relevant vertices [S1, unofficial].
8.  **Concatenation:** Concatenate the interpolated feature vectors from all $L$ levels and any auxiliary inputs to form the final encoded vector [S1, unofficial].
9.  **Backpropagation:** During training, propagate the loss through the MLP, the concatenation, the interpolation, and the hash lookups to update the feature vectors in the hash tables [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Out-of-bounds Access:** The skewed vertex $\mathbf{1}^T$ becomes $\sqrt{n+1}\mathbf{1}^T$ in the new coordinate system. The resulting parallelepiped is smaller than the original hypercube. Without the scale adjustment $S_n = \sqrt{n+1}$, accessing points outside the simplicial grids can occur [S1, unofficial].
*   **Memory Efficiency:** Using a dense grid for simplicial grids is extremely inefficient because only a portion of vertices are accessed. Hash tables are used to avoid this memory wastage and the overhead of explicit ordering [S1, unofficial].
*   **Collision Handling:** Hash collisions may occur. The source suggests using a hash table size based on the theoretical ratio of used vertices to total vertices, which converges to 1 as levels increase. In practice, a fixed size scaled by $(n+1)^{(n-1)/2}$ is used [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Similar to Instant-NGP, but with additional overhead for coordinate skewing and simplicial subdivision [S1, unofficial].
*   **Memory Complexity:** More memory efficient than dense grids for simplicial structures. Hash table size is determined by the ratio of parallelepiped volume to hypercube volume, approximated as $(n+1)^{(n-1)/2}$ [S1, unofficial].
*   **Performance:** On a 439M pixel image overfitting task with 16 levels and $2^{19}$ hash table size, simplex encoding achieved PSNR 29.94 in 14.94 seconds, compared to grid-based PSNR 29.82 in 16.34 seconds [S1, unofficial].
*   **Parameters:** 7.9M trainable parameters were used to represent the 439M pixel image [S1, unofficial].
*   **Strengths:** Memory efficiency for simplicial structures; comparable or slightly better performance than grid-based methods in some tasks [S1, unofficial].
*   **Limitations:** Additional computational overhead for coordinate skewing and simplicial subdivision [S1, unofficial].

## Background
This method was proposed in "Efficient Encoding of Graphics Primitives with Simplex-based Structures" [S1, unofficial]. It builds on the Instant-NGP framework [6604-instant-ngp.md] by replacing the hypercube-based grid with a simplex-based structure. The motivation is to leverage the properties of simplices for more efficient encoding of graphics primitives.
