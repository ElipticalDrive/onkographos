# HashNeRF

Also called: Instant Neural Graphics Primitives, Instant Neural Graphics Primitives with a Multiresolution Hash Encoding

## Overview
HashNeRF is a method for representing Neural Radiance Fields (NeRF) that utilizes a multiresolution hash encoding to map 3D coordinates to a higher-dimensional feature space, followed by a shallow neural network to decode density and color [S1, unofficial]. It solves the problem of slow training times and high memory consumption associated with traditional NeRF models by replacing expensive positional encoding and large MLPs with a trainable, compact hash grid representation [S1, unofficial]. Unlike its siblings, it achieves faster convergence and reduced parameter counts by making the encoding itself trainable alongside the shallow network, allowing it to represent 3D geometry at multiple levels of detail [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D spatial coordinates $\mathbf{x} = (x, y, z)$ and viewing direction $\mathbf{d}$.
*   **Output:** Volume density $\sigma$ and view-dependent color $\mathbf{c}$.

**Data Structures:**
The core data structure is a set of $L$ hash tables (one per resolution level). Each table $l$ has a fixed size $T_l$ (number of entries). Each entry stores a feature vector of dimension $F$. The features are typically initialized randomly or with small values.

**Parameters:**
*   $L$: Number of resolution levels (multiresolution levels).
*   $T_l$: Size of the hash table at level $l$.
*   $F$: Dimensionality of the feature vectors.
*   $H$: Hash function mapping coordinates to table indices.
*   $\alpha$: Interpolation factor (typically derived from the coordinate's position within the voxel).

**Steps:**

1.  **Coordinate Hashing:** For each resolution level $l \in \{0, \dots, L-1\}$, the input coordinate $\mathbf{x}$ is hashed to an index $i_l$ in the hash table for level $l$. The hash function $H_l(\mathbf{x})$ typically involves scaling the coordinate by $2^l$ and taking the modulo of the table size $T_l$.
2.  **Feature Fetching:** Retrieve the feature vector $\mathbf{f}_l$ from the hash table at index $i_l$.
3.  **Interpolation:** To ensure smoothness, features from neighboring voxels are interpolated. For a coordinate $\mathbf{x}$, let $\mathbf{x}_l$ be the scaled coordinate at level $l$. The fractional part $\mathbf{u}_l = \mathbf{x}_l - \lfloor \mathbf{x}_l \rfloor$ determines the interpolation weights. The interpolated feature $\hat{\mathbf{f}}_l$ is computed by trilinearly interpolating the 8 surrounding feature vectors in the hash grid [S1, unofficial].
4.  **Feature Concatenation:** Concatenate the interpolated features from all levels: $\mathbf{F} = [\hat{\mathbf{f}}_0; \hat{\mathbf{f}}_1; \dots; \hat{\mathbf{f}}_{L-1}]$.
5.  **Density Decoding:** Pass $\mathbf{F}$ through a shallow Multi-Layer Perceptron (MLP) to predict the log-space density $\log(\sigma)$. The output is typically passed through an exponential function to ensure positive density.
6.  **Color Decoding:** Concatenate the viewing direction $\mathbf{d}$ (optionally encoded via positional encoding) with the feature vector $\mathbf{F}$ (or a subset thereof). Pass this through another shallow MLP to predict the color $\mathbf{c}$.
7.  **Volume Rendering:** Use the predicted density $\sigma$ and color $\mathbf{c}$ along camera rays to render the final image using standard volume rendering techniques (e.g., differentiable ray marching) [S1, unofficial].

**Pseudocode:**

```python
import math

def hash_encode(x, hash_tables, table_sizes, feature_dim):
    """
    Encodes a 3D coordinate using multiresolution hash encoding.
    
    Args:
        x: numpy array of shape (3,) representing the 3D coordinate.
        hash_tables: list of numpy arrays, each of shape (table_size, feature_dim).
        table_sizes: list of integers, size of each hash table.
        feature_dim: integer, dimensionality of feature vectors.
        
    Returns:
        concatenated_features: numpy array of shape (L * feature_dim,)
    """
    L = len(hash_tables)
    concatenated_features = []
    
    for l in range(L):
        # Scale coordinate for current resolution level
        scale = 2 ** l
        scaled_x = x * scale
        
        # Compute voxel indices (floor)
        voxel_indices = np.floor(scaled_x).astype(int)
        
        # Compute fractional part for interpolation
        frac = scaled_x - voxel_indices
        
        # Compute interpolation weights for 8 neighbors
        # Weights are products of (1-f) and f for each dimension
        weights = np.ones(8)
        for d in range(3):
            weights[0::2] *= (1 - frac[d])
            weights[1::2] *= frac[d]
            weights[0:4] *= (1 - frac[(d+1)%3]) # Simplified logic for 8 neighbors
            # Correct 8-neighbor weight calculation:
            # w = (1-fx)(1-fy)(1-fz), (1-fx)(1-fy) fz, ...
            pass 
            
        # Re-calculate weights correctly for 8 neighbors
        # Indices: 000, 001, 010, 011, 100, 101, 110, 111
        # where bit d is 1 if we take the upper neighbor in dim d
        w000 = (1-frac[0])*(1-frac[1])*(1-frac[2])
        w001 = (1-frac[0])*(1-frac[1])*frac[2]
        w010 = (1-frac[0])*frac[1]*(1-frac[2])
        w011 = (1-frac[0])*frac[1]*frac[2]
        w100 = frac[0]*(1-frac[1])*(1-frac[2])
        w101 = frac[0]*(1-frac[1])*frac[2]
        w110 = frac[0]*frac[1]*(1-frac[2])
        w111 = frac[0]*frac[1]*frac[2]
        
        weights = [w000, w001, w010, w011, w100, w101, w110, w111]
        
        # Get neighbor voxel indices
        neighbors = []
        for i in range(8):
            idx = voxel_indices + np.array([(i>>0)&1, (i>>1)&1, (i>>2)&1])
            neighbors.append(idx)
            
        # Fetch features and interpolate
        features = []
        for n_idx in neighbors:
            # Hash the neighbor index to get table index
            # Using a simple hash function: sum of coordinates mod table size
            # Note: In practice, a more robust hash function is used
            h_idx = np.sum(n_idx) % table_sizes[l]
            feat = hash_tables[l][h_idx]
            features.append(feat)
            
        # Weighted sum
        interpolated_feat = np.zeros(feature_dim)
        for w, f in zip(weights, features):
            interpolated_feat += w * f
            
        concatenated_features.append(interpolated_feat)
        
    return np.concatenate(concatenated_features)

def hashnerf_forward(x, d, hash_tables, table_sizes, feature_dim, density_mlp, color_mlp):
    """
    Forward pass for HashNeRF.
    
    Args:
        x: numpy array of shape (3,)
        d: numpy array of shape (3,) viewing direction
        hash_tables: list of numpy arrays
        table_sizes: list of integers
        feature_dim: integer
        density_mlp: function taking features -> log_density
        color_mlp: function taking features + direction -> color
        
    Returns:
        sigma: float, volume density
        c: numpy array of shape (3,), color
    """
    # 1. Encode
    features = hash_encode(x, hash_tables, table_sizes, feature_dim)
    
    # 2. Decode Density
    log_sigma = density_mlp(features)
    sigma = np.exp(log_sigma)
    
    # 3. Decode Color
    # Direction might need positional encoding if not handled in MLP
    color_input = np.concatenate([features, d])
    c = color_mlp(color_input)
    
    return sigma, c
```

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Different coordinates may map to the same hash table index. The multiresolution structure mitigates this by allowing higher-resolution tables to store more specific features, but collisions still occur, especially in sparse regions. [S1, unofficial]
*   **Precision:** Floating-point precision in hashing and interpolation can affect gradient stability. [G]
*   **Boundary Conditions:** Coordinates outside the training domain should be handled, e.g., by clamping or returning zero features. [G]

## Subtopics

### [HashNeRF Architectural Variants](8688-hashnerf-architectural-variants.md)
This variant explores modifications to the standard shallow MLP decoder, specifically introducing convolutional and dilated convolutional layers into the color generation pipeline to provide spatial context and potentially accelerate convergence. It also evaluates the impact of residual connections between the density and color pipelines to ensure communication and avoid vanishing gradients. These changes aim to improve reconstruction quality and training efficiency compared to the base fully-connected architecture.

### [Zip-NeRF Hash Encoding with Gaussian Expectation](11492-zip-nerf-hash-encoding-with-gaussian-expectation.md)
Zip-NeRF replaces the standard point-query hash encoding with a Gaussian expectation approximation. This method models the query as an expectation over 3D Gaussians to mitigate high-frequency aliasing artifacts inherent in sparse grid representations. It serves as an acceleration for mip-NeRF 360, replacing its large MLP with a hash encoding based on Instant Neural Graphics Primitives, followed by a smaller MLP.

### HollowNeRF
HollowNeRF is a compression method that automatically sparsifies the feature grid during training using a trainable 3D saliency mask [S2]. It predicts a saliency weight $p$ for each coordinate by processing a coarse 3D saliency grid $G$ through trilinear interpolation and a sigmoid function [S2]. The feature $f$ is scaled by $p$ to get $v = pf$, which is then fed into the MLP [S2]. A zero-skipping gate ensures $v=0$ maps to $\sigma=0$ [S2]. An ADMM pruner enforces sparsity on the saliency mask during training [S2]. It uses 31% of the parameters of Instant-NGP while delivering comparable rendering quality, and can achieve up to 1dB PSNR gain using only 56% of the parameters [S2].

## Operating characteristics
*   **Time Complexity:** Training is significantly faster than traditional NeRF due to the shallow network and efficient hash-based lookup [S1, unofficial]. Convergence is achieved in fewer iterations (e.g., 500-1000 iterations evaluated in studies) [S1, unofficial].
*   **Memory Complexity:** Memory usage is determined by the total size of the hash tables ($\sum T_l \times F$), which is much smaller than the memory required for large MLPs in standard NeRF [S1, unofficial].
*   **Measured Performance:** Evaluated on NVIDIA GeForce RTX 3090 Ti GPUs using datasets with 100 training, 100 validation, and 200 test images (RGB + depth) [S1, unofficial].
*   **Strengths:** Fast training, low memory footprint, generic applicability to various neural graphics primitives [S1, unofficial].
*   **Limitations:** Potential for hash collisions affecting quality in sparse regions; performance depends on careful tuning of hash table sizes and feature dimensions [S1, unofficial].
*   **When to Use:** When fast training and low memory are critical, and high-frequency detail is not the primary concern or can be handled by multiresolution levels.
*   **When Not to Use:** When extremely high-fidelity reconstruction with minimal aliasing is required without additional techniques like Gaussian expectation (Zip-NeRF) [S1, unofficial].

## Background
HashNeRF, also known as Instant Neural Graphics Primitives with a Multiresolution Hash Encoding, was proposed by Thomas Müller, Alex Evans, Christoph Schied, and Alexander Keller in 2022 [S1, unofficial]. It builds on the idea of using hash tables for efficient feature storage, originally introduced in the context of Instant Neural Graphics Primitives [S1, unofficial]. The method addresses the limitations of earlier NeRF models, which suffered from slow training times and high memory consumption due to large MLPs and positional encoding [S1, unofficial]. It has found applications in Gigapixel approximation, generating signed distance functions, and Neural Radiance Caching [S1, unofficial].
