# Progressive Training

Also called: Coarse-to-Fine Hash Training, Coarse-to-fine optimization, Level Activation Schedule, Progressive Training for Hash Encodings

## Overview
Progressive training is a strategy for optimizing multi-resolution hash encodings that gradually activates higher-resolution feature levels over the course of training [S1, S2, S3]. It solves the problem of balancing convergence speed and geometric fidelity: starting with low-resolution grids prevents the model from overfitting to noise or specific camera views, while the gradual introduction of high-resolution grids allows the network to learn fine details without "unlearning" coarse structures [S1, S4]. Unlike [Instant-NGP](6604-instant-ngp.md) which may use fixed resolutions or different activation schedules, this method explicitly modulates the bandwidth of the encoding based on training progress [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A multi-resolution hash encoding structure with $L$ levels, total training steps $T$, and current step $t$.
*   **Output:** A feature vector constructed from a subset of active hash levels.

**Data Structures:**
The hash encoding consists of $L$ levels. Each level $i$ has a hash grid with a specific resolution and a fixed number of entries.
*   Level $i$ hash grid: Contains $N_i$ entries. Each entry stores a feature vector of dimension $C$ (typically 8) [S4].
*   The levels are indexed $1$ to $L$.

**Parameters:**
*   $\lambda$: The bandwidth parameter, an integer indicating the highest active level index.
*   $T$: Total number of training iterations.
*   $\epsilon$: Numerical gradient step size (used in Neuralangelo variant) [S4].

**Algorithm:**
The method restricts the hash encoding to a low-pass filter defined by $\lambda$. The weight $w_i(\lambda)$ for level $i$ is:
$$ w_i(\lambda) = \mathbb{I}[i \le \lambda] $$
where $\mathbb{I}$ is the indicator function [S1].

**Steps:**
1.  **Initialize:** Set $\lambda = 2$ [S1]. Alternatively, for Neuralangelo, initialize with a subset of coarse grids (4 for DTU, 8 for Tanks and Temples) [S4].
2.  **Iterate:** For each training step $t$ from 1 to $T$:
    *   **Update $\lambda$:**
        *   *Standard NeuS2 approach:* Increase $\lambda$ by 1 every 2.5% of total steps $T$ [S1].
        *   *Neuralangelo approach:* Decrease the numerical gradient step size $\epsilon$. Enable a new hash resolution when $\epsilon$ equals the spatial size of that resolution [S4].
    *   **Forward Pass:** Compute the hash encoding $\gamma(\mathbf{x})$ using only levels $i$ where $i \le \lambda$.
    *   **Optimization:** Perform gradient descent on the network parameters and hash features using the active levels.
    *   **Regularization:** Apply weight decay to all parameters to prevent single-resolution features from dominating the final result [S4].

**Pseudocode:**
```python
def progressive_training(hash_levels, total_steps, method="neus2"):
    """
    hash_levels: List of L hash grid objects.
    total_steps: Total number of training iterations T.
    method: "neus2" or "neuralangelo".
    """
    if method == "neus2":
        lambda_val = 2
        step_interval = int(0.025 * total_steps)
        
        for t in range(1, total_steps + 1):
            # Update lambda every 2.5% of steps
            if t % step_interval == 0 and lambda_val < len(hash_levels):
                lambda_val += 1
            
            # Activate only levels <= lambda_val
            active_levels = [hash_levels[i] for i in range(lambda_val)]
            
            # Forward pass with active levels
            features = compute_hash_encoding(active_levels)
            
            # Backward pass and update
            loss = compute_loss(features)
            apply_gradients(loss)
            
            # Apply weight decay to all parameters
            apply_weight_decay()

    elif method == "neuralangelo":
        # Initialize with coarse grids (e.g., 4 for DTU, 8 for T&T)
        initial_active_count = 4 
        active_count = initial_active_count
        # epsilon decreases over time
        epsilon = initial_epsilon 
        
        for t in range(1, total_steps + 1):
            # Decrease epsilon (implementation specific)
            epsilon = update_epsilon(epsilon, t)
            
            # Check if new resolution should be enabled
            # Enable when epsilon equals the spatial size of the next resolution
            if active_count < len(hash_levels):
                next_resolution_size = hash_levels[active_count].spatial_size
                if epsilon <= next_resolution_size:
                    active_count += 1
            
            # Activate levels 0 to active_count-1
            active_levels = hash_levels[:active_count]
            
            # Forward pass
            features = compute_hash_encoding(active_levels)
            
            # Backward pass
            loss = compute_loss(features)
            apply_gradients(loss)
            
            # Apply weight decay
            apply_weight_decay()
```

**Edge Cases and Pitfalls:**
*   **Underfitting:** Using only low-resolution grids results in smooth geometry lacking details [S1].
*   **Overfitting:** Using high-resolution grids from the start induces noise and artifacts [S1].
*   **View Inconsistency:** Starting with high-resolution grids causes the strong capacity of the grid to overfit predefined camera views, producing inconsistent geometry across different views [S3].
*   **Local Minima:** Coarse-to-fine optimization helps shape the loss landscape to avoid false local minima [S4].

## Subtopics

### Progressive Levels of Details (Coarse-to-Fine Optimization)
A variant used in Neuralangelo that ties activation to the numerical gradient step size $\epsilon$ [S4]. Instead of a fixed time schedule, it enables finer hash grids as $\epsilon$ decreases to their spatial size [S4]. This avoids the need for fine grids to "unlearn" coarse features [S4]. It initializes with 4 coarse grids for DTU and 8 for Tanks and Temples due to scene scale differences [S4]. It applies weight decay to all parameters to prevent single-resolution dominance [S4].

## Operating characteristics
*   **Time Complexity:** Training is faster initially because fewer hash levels are active. As $\lambda$ increases, the computational cost per step increases [S1].
*   **Memory Complexity:** Memory usage increases as more hash levels are activated. However, since levels are activated sequentially, peak memory is lower than training with all levels active from the start [S1].
*   **Performance:** Improves convergence speed and reduces noise compared to training with all levels active [S1, S2].
*   **Strengths:** Prevents overfitting to camera views [S3], ensures view consistency [S3], and captures high-frequency details effectively [S2].
*   **Limitations:** Requires careful tuning of the activation schedule (e.g., 2.5% intervals or $\epsilon$ thresholds) [S1, S4].

## Background
Progressive training for hash encodings was introduced in NeuS2 to improve training convergence and speed while maintaining high-quality reconstruction [S1]. It addresses the empirical observation that low resolutions underfit and high resolutions overfit [S1]. The concept of coarse-to-fine optimization is also adopted in Neuralangelo, where it is linked to the numerical gradient step size [S4]. GO-NeRF also employs coarse-to-fine optimization to ensure view consistency [S3].
