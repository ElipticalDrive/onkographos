# Hybrid Training for Explicit Primitives

Also called: Hybrid training of convexes, Two-stage hybrid training scheme

## Overview
Hybrid training is a two-stage optimization procedure for explicit primitive-based scene representations that combines vanilla geometric primitives with appearance embeddings to balance geometric fidelity, photometric quality, and parameter efficiency [S1, unofficial]. It sets itself apart from single-stage training by decoupling geometry initialization from appearance modeling, allowing the model to first establish a robust structural baseline before adapting to lighting variations [S1, unofficial]. This approach is specifically designed for space robotics applications where compactness and safety-critical robustness are prioritized over pure photometric fidelity [S1, unofficial]. It builds on [Structure-aware primitive learning](3157-structure-aware-primitive-learning.md) and contrasts with [Volume Exploration-Optimized INR](6823-volume-exploration-optimized-inr.md), [Mixture-of-Experts Neural Fields](10460-mixture-of-experts-neural-fields.md), and [Direction-Dependent Representations](18699-direction-dependent-representations.md).

## How it works
The method trains explicit convex primitives (CS) using a staged approach to mitigate clutter and improve geometric accuracy [S1, unofficial].

**Inputs and Outputs**
*   **Input:** A set of $N$ training images with known camera poses [S1, unofficial].
*   **Output:** A set of convex primitives defined by their geometric parameters and, in Stage 2, appearance embeddings [S1, unofficial].

**Data Structures**
*   **Convex Primitives:** Each primitive $i$ is defined by a set of geometric parameters $\theta_i$ (position, orientation, scale) [S1, unofficial].
*   **Appearance Embeddings:** A learnable vector $e_i$ per primitive that substitutes for missing data in low-data regimes by explaining lighting variations [S1, unofficial].

**Numbered Steps**
1.  **Stage 1: Vanilla Geometry Training**
    *   Initialize a set of convex primitives with geometric parameters only [S1, unofficial].
    *   Optimize these parameters for 30,000 iterations using a photometric loss between rendered images and ground truth images [S1, unofficial].
    *   No appearance embeddings are used during this stage [S1, unofficial].
2.  **Stage 2: Hybrid Appearance Training**
    *   Introduce appearance embeddings $e_i$ for each primitive [S1, unofficial].
    *   Continue training for an additional 30,000 iterations [S1, unofficial].
    *   Optimize both the geometric parameters (from Stage 1) and the new appearance embeddings to minimize the photometric loss [S1, unofficial].

**Formulas**
*   Photometric loss $\mathcal{L}$: Standard L1 or SSIM metric between rendered and ground-truth images [S1, unofficial]. Not given in the sources.

**Parameters**
*   **Stage 1 Iterations:** 30,000 [S1, unofficial].
*   **Stage 2 Iterations:** 30,000 [S1, unofficial].
*   **Total Iterations:** 60,000 [S1, unofficial].
*   **Appearance Embeddings:** Their utility is highest in low-data regimes (e.g., 20 images) where they act as a substitute for missing data [S1, unofficial]. As the training set size grows (e.g., 500 images), the dataset itself absorbs much of the variation, and the utility of embeddings for geometry learning diminishes [S1, unofficial].

**Pseudocode**
```python
def hybrid_training(primitives, images, poses, num_stage1_iters=30000, num_stage2_iters=30000):
    # Stage 1: Train vanilla convexes for geometry
    for step in range(num_stage1_iters):
        rendered = project_and_composite(primitives, poses)
        loss = compute_photometric_loss(rendered, images)
        gradient_step(primitives, loss)
        
    # Stage 2: Introduce appearance embeddings and continue training
    for prim in primitives:
        prim.embedding = zeros_like(prim.embedding_dim)  # [G] Initialize embedding vector
        
    for step in range(num_stage2_iters):
        rendered = project_and_composite_with_appearance(primitives, poses)
        loss = compute_photometric_loss(rendered, images)
        gradient_step(primitives, loss)
        
    return primitives

def project_and_composite(primitives, poses):
    # Projects each primitive's geometric parameters to image space and composites
    return composite_primitives(primitives, poses)

def project_and_composite_with_appearance(primitives, poses):
    # Projects primitives using geometry and modulates with appearance embeddings
    return composite_primitives_with_embeddings(primitives, poses)

def compute_photometric_loss(rendered, ground_truth):
    # Computes photometric loss (e.g., L1 or SSIM)
    return mean_absolute_error(rendered, ground_truth)

def gradient_step(primitives, loss):
    # Backpropagates loss and updates parameters
    loss.backward()
    for prim in primitives:
        prim.update_parameters()
```

**Edge Cases and Pitfalls**
*   **Low-Data Regimes:** Appearance embeddings are critical when training data is scarce (e.g., 20 images) to handle lighting variations [S1, unofficial].
*   **High-Data Regimes:** With abundant data (e.g., 500 images), the benefit of appearance embeddings diminishes as the dataset absorbs variation, and their effect becomes less predictable [S1, unofficial].
*   **Clutter:** Vanilla convexes may repurpose noise primitives for geometry, while wild convexes (with embeddings) may reduce clutter but require careful tuning [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method requires 60,000 iterations total (30k for Stage 1, 30k for Stage 2) [S1, unofficial].
*   **Memory Complexity:** The parameter count is compact [S1, unofficial]. On the SPEED+ dataset, the hybrid model uses 137,034 parameters (±1,986) [S1, unofficial].
*   **Measured Performance (SPEED+ Dataset):** PSNR 23.12, SSIM 0.85, LPIPS 0.49, IoU 0.60, TPR 1.00, FPR 0.11, FDR 0.40, Parameters 137,034 (±1,986) [S1, unofficial].
*   **Data Efficiency:** With 20 training images: IoU 0.44, PSNR 18.69, Params 197,961 [S1, unofficial]. With 500 training images: IoU 0.78, PSNR 24.95, Params 232,185 [S1, unofficial].
*   **Strengths:** High geometric fidelity (IoU 0.60, TPR 1.00), parameter efficiency (137k params), and robustness in low-data regimes [S1, unofficial].
*   **Limitations:** Potential drop in image quality compared to Gaussian Splatting (GS) in some metrics, which may affect downstream interaction tasks [S1, unofficial].
*   **When to Use:** Space robotics applications requiring compact, safe, and efficient 3D reconstructions [S1, unofficial].

## Background
Hybrid training for explicit primitives was introduced in the context of comparing implicit and explicit neural scene representations for space robotics [S1, unofficial]. The work highlights that explicit methods, particularly convex splatting with hybrid training, offer a flexible trade-off between efficiency, fidelity, and robustness [S1, unofficial]. The method was evaluated on the SPEED+ dataset, demonstrating its suitability for onboard deployment in space applications [S1, unofficial].
