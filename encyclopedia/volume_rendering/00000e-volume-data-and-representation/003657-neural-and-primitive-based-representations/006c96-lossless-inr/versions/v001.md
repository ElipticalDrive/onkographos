# Lossless-INR

Also called: Lossless Volumetric Implicit Neural Representations

## Overview
Lossless-INR is a framework for 3D scientific volumetric data that achieves zero bit-error rate and bit-exact reconstruction by decomposing voxel values into binary bit-planes and reformulating reconstruction as a per-bit binary classification task [S1, unofficial]. Unlike existing INR-based methods which are inherently lossy and leave a persistent gap from original data even with increased capacity, Lossless-INR guarantees exact reconstruction [S1, unofficial]. It sets itself apart from siblings like [Hash Grid Neural Fields](3855-hash-grid-neural-fields.md) by combining bit-plane decomposition with octree block partitioning and ternary feature grids to make the optimization of zero-error classification tractable while keeping the representation compact [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A 3D volumetric dataset where each voxel value is represented by $B$ bits of precision.
- **Output:** A set of neural network parameters (one per octree leaf block) that define a continuous function $F_\Theta: \mathbb{R}^4 \rightarrow \{0, 1\}$ for each bit index $i \in \{0, \dots, B-1\}$. The final output is the reconstructed volume $V(\mathbf{x})$ which matches the ground truth exactly.

**Data Structures:**
1.  **Octree:** Hierarchical partitioning of the volume space.
    -   Root level: Uniform blocks of size $64^3$.
    -   Leaf level: Minimum block size of $16^3$.
    -   Structure: Each node represents a spatial block. Nodes are subdivided into 8 children if the block cannot be fit losslessly.
2.  **Ternary Feature Grid Network (per block):**
    -   **Hash Grids:**
        -   One 4D hash grid operating on coordinates $(x, y, z, i)$, where $i$ is the bit index.
        -   Four 3D hash grids, each operating on a distinct triplet of axes (e.g., $(x,y,z), (x,y,i), \dots$).
        -   Grid Configuration: 4-level multi-resolution hash grid. Hashmap size $2^{17}$. Feature dimension: 2 per entry.
        -   Weight Constraint: Grid weights are constrained to a ternary set $\{-\gamma, 0, +\gamma\}$.
    -   **MLP Decoder:**
        -   Input: Concatenated feature vectors from the 4D and 3D hash grids.
        -   Architecture: 3-layer MLP with 64 hidden units.
        -   Output: Continuous scalar value for bit classification.
        -   Precision: MLP weights remain at full precision (floating-point).

**Numbered Steps:**
1.  **Bit-Plane Decomposition:** For a volume with $B$ bits of precision, decompose each voxel value $V(x,y,z)$ into $B$ binary bit-planes $\{b_0, \dots, b_{B-1}\}$. Each bit-plane $b_i(x,y,z)$ contains the $i$-th bit of the voxel value at position $(x,y,z)$.
2.  **Octree Initialization:** Start with a uniform partition of the volume into non-overlapping blocks of size $64^3$.
3.  **Sequential Block Optimization:** For each block:
    a. Initialize a separate network $f_\theta$ for the block.
    b. Optimize $f_\theta$ for each bit index $i \in \{0, \dots, B-1\}$ using binary cross-entropy loss:
       $$ \hat{\theta} = \arg \min_\theta \mathcal{L}(b_i(x,y,z), f_\theta(x,y,z,i)) $$
       where $\mathcal{L}$ is binary cross-entropy.
    c. Training parameters: Adam optimizer, initial learning rate $10^{-2}$, cosine annealing to $10^{-5}$, batch size 32,000, max 2,000 iterations.
    d. Early stopping: Stop if zero bit errors are achieved for all bits in the block.
    e. **Leaf Check:** If $f_\theta$ predicts all bits correctly for all $i$, accept the block as an octree leaf.
    f. **Subdivision:** If any bit is predicted incorrectly, subdivide the block into 8 smaller children (minimum size $16^3$) and repeat optimization for each child.
4.  **Ternary Parameterization:** During training, constrain the hash grid weights $W$ to a ternary set to reduce storage cost:
    a. Compute scale $\gamma = \frac{\sum_j |W_j|}{n}$, where $n$ is the number of weights.
    b. Compute quantized weights: $f_W = \gamma \cdot \text{RoundClip}\left(\frac{W}{\gamma+\epsilon}, -1, 1\right)$.
    c. Resulting weights take values $\{-\gamma, 0, +\gamma\}$.
5.  **Reconstruction:** To reconstruct the voxel value at $(x,y,z)$:
    a. Query the network $f_\theta$ for each bit index $i$ to get a continuous output.
    b. Quantize the output to $\{0, 1\}$ using $Q(\cdot)$.
    c. Recompose the value:
       $$ V(x,y,z) = \frac{1}{2^B - 1} \sum_{i=0}^{B-1} 2^i Q(f_\theta(x,y,z,i)) $$
    d. If every bit is predicted correctly, $V(x,y,z)$ equals the ground truth exactly.

**Pseudocode:**

```python
import numpy as np

def round_clip(value, min_val, max_val):
    """Clip value to [min_val, max_val] and round to nearest integer."""
    clipped = np.clip(value, min_val, max_val)
    return np.round(clipped)

def ternary_parameterize(W, epsilon=1e-8):
    """
    Constrain grid weights W to ternary set {-gamma, 0, +gamma}.
    W: numpy array of weights.
    """
    gamma = np.mean(np.abs(W))
    # Avoid division by zero
    if gamma < epsilon:
        gamma = epsilon
    normalized = W / (gamma + epsilon)
    clipped = round_clip(normalized, -1.0, 1.0)
    return gamma * clipped

def query_network(block_network, x, y, z, bit_index):
    """
    Query the MLP decoder with features from hash grids.
    block_network: Object containing hash grids and MLP.
    x, y, z: Spatial coordinates.
    bit_index: Integer i.
    Returns: Continuous scalar output.
    """
    # 1. Query 4D hash grid at (x, y, z, bit_index)
    feat_4d = block_network.hash_grid_4d.query(x, y, z, bit_index)
    
    # 2. Query four 3D hash grids at distinct axis triplets
    # Assuming triplets are (x,y,z), (x,y,i), (x,z,i), (y,z,i)
    feat_3d_1 = block_network.hash_grid_3d_1.query(x, y, z)
    feat_3d_2 = block_network.hash_grid_3d_2.query(x, y, bit_index)
    feat_3d_3 = block_network.hash_grid_3d_3.query(x, bit_index, z)
    feat_3d_4 = block_network.hash_grid_3d_4.query(bit_index, y, z)
    
    # 3. Concatenate features
    combined_feat = np.concatenate([feat_4d, feat_3d_1, feat_3d_2, feat_3d_3, feat_3d_4])
    
    # 4. Pass through 3-layer MLP (64 hidden units)
    # Note: MLP weights are full precision
    output = block_network.mlp.forward(combined_feat)
    return output

def optimize_block(block_coords, ground_truth_bits, max_iter=2000, lr=1e-2):
    """
    Optimize a single block's network.
    block_coords: List of (x,y,z) positions in the block.
    ground_truth_bits: Array of shape (len(block_coords), B) with values 0 or 1.
    Returns: Optimized block_network or None if not converged.
    """
    B = ground_truth_bits.shape[1]
    block_network = initialize_network() # Creates hash grids and MLP
    
    for iteration in range(max_iter):
        total_error = 0
        for i in range(B):
            bit_plane = ground_truth_bits[:, i]
            
            # Sample batch of coordinates
            batch_indices = np.random.choice(len(block_coords), size=32000, replace=False)
            batch_coords = block_coords[batch_indices]
            
            # Forward pass
            outputs = []
            for coord in batch_coords:
                out = query_network(block_network, coord[0], coord[1], coord[2], i)
                outputs.append(out)
            outputs = np.array(outputs)
            
            # Compute Binary Cross-Entropy Loss
            # L = -mean(y * log(p) + (1-y) * log(1-p))
            # Clip outputs for numerical stability
            outputs_clipped = np.clip(outputs, 1e-7, 1 - 1e-7)
            loss = -np.mean(bit_plane[batch_indices] * np.log(outputs_clipped) + 
                            (1 - bit_plane[batch_indices]) * np.log(1 - outputs_clipped))
            
            # Backpropagation to update block_network parameters
            # Note: Hash grid weights are updated via ternary parameterization after gradient step
            update_gradients(block_network, loss)
            
            # Apply ternary parameterization to hash grids
            for grid in block_network.hash_grids:
                grid.weights = ternary_parameterize(grid.weights)
                
            total_error += loss
            
        # Check for zero bit error
        zero_error = True
        for i in range(B):
            bit_plane = ground_truth_bits[:, i]
            predictions = []
            for coord in block_coords:
                out = query_network(block_network, coord[0], coord[1], coord[2], i)
                predictions.append(1 if out >= 0.5 else 0)
            predictions = np.array(predictions)
            if not np.array_equal(predictions, bit_plane):
                zero_error = False
                break
        
        if zero_error:
            return block_network
            
    return None

def reconstruct_volume(octree, volume_shape, B):
    """
    Reconstruct the full volume from the trained octree.
    """
    volume = np.zeros(volume_shape)
    for x in range(volume_shape[0]):
        for y in range(volume_shape[1]):
            for z in range(volume_shape[2]):
                value = 0
                for i in range(B):
                    # Find the leaf block containing (x,y,z)
                    block = octree.find_leaf(x, y, z)
                    if block is None:
                        raise ValueError("Coordinate not covered by octree")
                    
                    # Query network
                    out = query_network(block.network, x, y, z, i)
                    bit = 1 if out >= 0.5 else 0
                    value += bit * (2 ** i)
                
                # Normalize to [0, 1] range for B-bit precision
                volume[x, y, z] = value / (2**B - 1)
    return volume
```

**Parameters:**
-   $B$: Number of bits per voxel value (e.g., 8, 16, 32). Determines the number of bit-planes.
-   Hash Grid Size: $2^{17}$ for the 4-level multi-resolution hash grid.
-   Feature Dimension: 2 dimensions per entry in the hash grids.
-   Training Hyperparameters: Adam optimizer, initial LR $10^{-2}$, cosine annealing to $10^{-5}$, batch size 32,000, max 2,000 iterations per block.
-   Block Sizes: Initial uniform blocks $64^3$, minimum leaf size $16^3$.

**Edge Cases and Pitfalls:**
-   **Precision:** Directly applying lossless INR to 3D data is non-trivial because driving bit error to zero requires substantial model capacity. Small reconstruction errors in existing INRs propagate through the DVR pipeline (transfer function lookups, gradient estimation) leading to incorrect colors and lighting [S1, unofficial].
-   **Boundaries:** The octree subdivision stops at $16^3$. If a block of this size cannot be fit losslessly, the method fails to converge for that region.
-   **Degenerate Input:** Without block partitioning, neither floating-point nor ternary grids achieve lossless reconstruction and exhibit high BER [S1, unofficial].
-   **Binary Grid Limitation:** Using a binary grid (weights $\{-1, 0, 1\}$ without scaling) yields the most compact model but cannot drive BER to zero, failing lossless representation [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** Training time is substantially higher than baselines, especially on complex data (e.g., foot, vortex) requiring fine-level blocks. Training cost grows with the number of blocks due to sequential optimization. On large-scale volumes, optimization could take several days [S1, unofficial].
-   **Memory Complexity:** Model size is relatively large and can even be larger than the original volume. However, the ternary grid achieves a model size 20x smaller than its floating-point counterpart [S1, unofficial].
-   **Measured Performance:**
    -   **Foot Dataset (66.8 MB):** PSNR $+\infty$, LPIPS 0.0000, BER 0.0000, Training Time 22.20 min [S1, unofficial].
    -   **Engine Dataset (61.0 MB):** PSNR $+\infty$, LPIPS 0.0000, BER 0.0000, Training Time 2.20 min [S1, unofficial].
    -   **Tooth Dataset (12.5 MB):** PSNR $+\infty$, LPIPS 0.0000, BER 0.0000, Training Time 0.94 min [S1, unofficial].
    -   **MRI-woman Ablation:** Ternary grid yields 0.0000 BER, 39.2 MB model size. Floating-point grid yields 0.0000 BER, 794.4 MB model size. Binary grid yields 0.0029 BER, 24.6 MB model size [S1, unofficial].
-   **Strengths:** Guarantees exact reconstruction (zero BER). Enables faithful rendering and downstream analysis without error propagation. Compact compared to full-precision INRs.
-   **Limitations:** High training time. Large model size compared to original volume. Sequential optimization hinders scaling to very large volumes.
-   **When to Use:** Scientific volumetric data where bit-exact reconstruction is required for analysis or archival.
-   **When Not to Use:** Real-time rendering where speed is critical, or when approximate reconstruction is acceptable.

## Background
Lossless-INR was introduced by Tang et al. in 2026 [S1, unofficial]. It addresses the limitation of existing INR-based methods for volumetric data, which are inherently lossy and leave a persistent gap from original data even with increased capacity [S1, unofficial]. The method builds on the multi-resolution hash grid design of Instant-NGP [S1, unofficial] but reformulates the problem as per-bit binary classification. It is used for 3D scientific volumetric data representation, compression, rendering, and downstream analysis tasks like computing derived fields or extracting topology [S1, unofficial].
