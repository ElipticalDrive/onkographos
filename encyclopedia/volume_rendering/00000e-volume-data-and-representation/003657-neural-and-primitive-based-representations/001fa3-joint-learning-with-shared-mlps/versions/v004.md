# Joint Learning with Shared MLPs

Also called: Context Model Architecture, Joint training, Shared decoder training

## Overview
Joint Learning with Shared MLPs is a strategy for simultaneously training multiple volumetric visualization (VolVis) scenes using a single, lightweight neural network to decode scene attributes from compact anchor points [S1, unofficial]. It solves the problem of redundant computation and storage when handling large collections of similar volumetric datasets by exploiting inter-scene correlations [S1, unofficial]. Unlike separate per-scene optimization, this method groups geometrically similar scenes via hierarchical clustering and shares a context model (typically a hash-grid-based MLP) across all scenes in a group, significantly reducing training time, model size, and anchor count while maintaining reconstruction quality [S1, unofficial].

## How it works
**Inputs:** A set of $N$ VolVis scenes, each represented by a point cloud (for geometric initialization) and associated training images.
**Outputs:** A shared context model (hash grids + MLP) and a set of anchor attributes (e.g., Gaussian parameters) for each scene, optimized jointly.

**Data Structures:**
1.  **Anchor Point Cloud:** A subsampled set of points $\mathbf{x}_a$ representing the scene geometry. For clustering, point clouds are subsampled to at most 10,000 points [S1, unofficial].
2.  **Context Model:** Based on BiRF [S1, unofficial], consisting of:
    *   Multiple binary hash grids. Parameters in the grids are restricted to values $+1$ or $-1$ [S1, unofficial].
    *   A shallow Multi-Layer Perceptron (MLP) that decodes aggregated hash features.
3.  **Scene Grouping:** Scenes are partitioned into disjoint groups $\mathcal{G}_1, \dots, \mathcal{G}_k$ based on pairwise Chamfer distances between their point clouds using hierarchical clustering [S1, unofficial].

**Steps:**
1.  **Scene Grouping:** Compute pairwise Chamfer distances between the subsampled point clouds of all $N$ scenes. Apply hierarchical clustering with a threshold $\tau$ (Chamfer distance) to form groups. Scenes within a group are geometrically similar [S1, unofficial].
2.  **Initialization:** Initialize anchor points for each scene. The point clouds used for this initialization are subsampled to $\le 10,000$ points to reduce clustering and initialization cost [S1, unofficial].
3.  **Joint Optimization:** For each group $\mathcal{G}_g$:
    *   Initialize the shared context model parameters (hash grid values and MLP weights).
    *   Initialize scene-specific anchor attributes (e.g., position, scaling, color, opacity) for all scenes in the group.
    *   Iterate over training images from all scenes in the group.
    *   For each image, sample rays and evaluate the scene function using the shared context model. The context model takes an anchor position $\mathbf{x}_a$ as input and outputs values modeling the probability distribution for the anchor attributes [S1, unofficial].
    *   Render the image and compute the loss against the ground truth.
    *   Backpropagate gradients to update both the shared context model and the scene-specific anchor attributes [S1, unofficial].
4.  **Entropy Coding (Optional/Post-Training):** Continuous anchor attributes are quantized to discrete values (via noise injection for backpropagation during training) to enable neural entropy coding, further compressing the model [S1, unofficial].

**Parameters:**
*   **Clustering Threshold ($\tau$):** Controls the maximum Chamfer distance for scenes to be grouped together. Tested values: $0, 0.005, 0.01, 0.02, 0.04$ [S1, unofficial]. Larger $\tau$ reduces the number of groups but risks OOM errors if groups become too large [S1, unofficial].
*   **Subsampling Limit:** Maximum 10,000 points for clustering and initialization [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **OOM Errors:** Setting the clustering threshold too high (e.g., 0.04) can group >20 scenes together, causing Out-Of-Memory (OOM) errors during training because anchor/optimizer parameters and training images cannot fit in GPU memory [S1, unofficial]. Peak memory occurs during joint training; inference memory is significantly lower (<2 GB) [S1, unofficial].
*   **Quality Degradation:** Joint learning across fundamentally unrelated datasets (e.g., beetle and argon bubble) degrades quality because the shared MLPs lack the capacity to simultaneously encode different volume structures [S1, unofficial]. Scene grouping based on Chamfer distance is essential [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Clustering overhead is negligible, scaling quadratically with the number of scenes but reduced by subsampling to 10K points. For 41 scenes, clustering takes 0.49s (<0.02% of total training time) [S1, unofficial]. Joint learning reduces total training time by 35% to 54% compared to separate optimization [S1, unofficial].
*   **Memory Complexity:** Model size is reduced by 44% to 60% compared to separate optimization [S1, unofficial]. Peak memory usage is high during joint training due to loading all anchors and optimizer states for a group, but inference memory is low (<2 GB) [S1, unofficial].
*   **Performance:** On the multivariate combustion dataset (41 scenes), joint learning reduced training time from 156.9 to 72.0 min, model size from 45.75 to 15.99 MB, and anchors from 1,049,074 to 415,275 [S1, unofficial]. Reconstruction quality (PSNR, LPIPS) remains nearly unchanged [S1, unofficial].
*   **Strengths:** Significant reductions in training time, model size, and anchor count. Savings grow monotonically with the number of basic scenes [S1, unofficial].
*   **Limitations:** Requires geometric similarity between scenes for effective grouping. Cannot handle fundamentally unrelated scenes in the same group without quality loss [S1, unofficial].

## Background
The method was introduced in the paper "ECoNGS: Efficient Compressive Neural Gaussian Splats for Volume Visualization" [S1, unofficial]. It leverages the BiRF architecture [S1, unofficial] as the context model, which uses binary hash grids and a shallow MLP. The approach is designed for Volume Visualization (VolVis) scenes, addressing the redundancy in representing multiple similar volumetric datasets.
