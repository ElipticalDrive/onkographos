# Directed Distance Fields (DDF)
## Overview
A Directed Distance Field (DDF) is a 5D neural field representation that maps a 3D position $p$ and a view direction $v$ to a binary visibility $\xi(p, v)$ and a non-negative distance $d(p, v)$ to the first surface intersection along the ray defined by $(p, v)$ [S1, S2]. It solves the problem of efficient, differentiable geometric rendering by enabling depth map computation with a single forward pass per pixel, unlike standard implicit shapes (SDFs/occupancy) which require multiple queries or complex calculations [S2]. It differs from Signed Directional Distance Fields (SDDF) by lacking a sign; a DDF measures the distance to the *next* object after an intersection, reducing complexity but potentially limiting representational utility for certain internal structures [S1].
## How it works
The DDF takes an oriented point $\tau = (p, v)$ as input, where $p \in B \subset \mathbb{R}^3$ is a position in a convex compact domain $B$, and $v \in S^2$ is a unit direction vector [S2]. It outputs a tuple $(\xi(p, v), d(p, v))$, where $\xi \in \{0, 1\}$ is the binary visibility indicator and $d \in \mathbb{R}_{\ge 0}$ is the distance to the first surface intersection along the ray [S1, S2]. The DDF is implemented as a neural network $F_\theta: \Gamma \rightarrow \{0, 1\} \times \mathbb{R}_{\ge 0}$, where $\Gamma = B \times S^2$ is the 5D product space [S2]. The visibility component $\xi$ outputs a scalar, typically activated with a sigmoid or step function to approximate the binary indicator [G]. The distance component $d$ outputs a scalar, typically activated with a softplus or ReLU to ensure non-negativity [G].

Rendering a depth map follows these steps [S2]:
1. For each pixel, determine the camera position $p_0$ and the pixel ray direction $v_\rho = (\rho - p_0) / \|\rho - p_0\|_2$, where $\rho$ is the pixel's 3D position in world space [S2].
2. If $p_0 \notin B$, compute the intersection $p_r$ of the ray $r(t) = p_0 + t v_\rho$ with the boundary $\partial B$ [S2]. If no intersection exists, set $\xi(p_r, v_\rho) = 0$ and depth to infinity [S2]. Otherwise, use $p_r$ as the query position [S2].
3. Query the DDF network with $(p_r, v_\rho)$ to obtain $(\xi, d)$ [S2].
4. If $\xi(p_r, v_\rho) = 1$, the depth for the pixel is $d(p_r, v_\rho) + \|p_0 - p_r\|_2$ [S2].
5. If $\xi(p_r, v_\rho) = 0$, the pixel is background (depth is infinite or handled by background model) [S2].

The fields are regularized with geometric constraints to mitigate view inconsistencies, though these alone cannot guarantee mathematical view consistency [S2]. Formally, a DDF $F=(\xi,d)$ requires $\xi$ to be a Visibility Field (VF) and $d$ to be a $\xi$-coherent Simple DDF, plus compatibility between them [S2].
1. **Directed Eikonal Equation (DEd):** For any visible $(p, v)$, the gradient of the distance field with respect to position projected onto the view direction equals -1: $\nabla_p d(p, v) \cdot v = -1$ [S1, S2]. This implies $\|\nabla_p d(p, v)\|_2 \ge 1$ [S1, S2].
2. **Visibility Field (VF) Constraints:** The visibility field $\xi$ must be a Binary Open Zero (BOZ) field satisfying:
   * **Non-Visible Boundary Condition (BC$\xi$):** $\xi(\tau) = 0$ for all rays starting in $B \setminus B_\varepsilon$ that miss $B_\varepsilon$ [S2].
   * **Directed Eikonal Constraint (DE$\xi$):** $\xi$ is non-increasing along any ray ($f_\xi(s_1|\tau) \le f_\xi(s_2|\tau)$ for $s_1 > s_2$) [S2].
   * **Isotropic Opaqueness Constraint (IO$\xi$):** If a "one-to-zero flip" occurs at $q$ along direction $v$, then $\xi(\tau) = 1$ for all rays $\tau$ intersecting $q$ [S2].
3. **Compatibility:** $\xi$ and $d$ are compatible if the zero set of $d$ (positional zeroes $Q_d$) corresponds exactly to the visible rays of $\xi$ [S2]. Specifically, $q \in Q_{d,\xi} \implies \tau \in R_V[\xi]$ for all $\tau \in I_q$, and $\tau \in R_V[\xi] \implies [B]_\tau \cap Q_{d,\xi} \neq \emptyset$ [S2].
4. **Surface Normal Extraction:** For visible $(p, v)$ where the normal $n(p, v)$ is not perpendicular to $v$, the surface normal at the intersection point $q(p, v) = p + d(p, v)v$ is: $n(p, v) = \varsigma \frac{\nabla_p d(p, v)^T}{\|\nabla_p d(p, v)\|_2}$, where $\varsigma \in \{-1, 1\}$ is chosen such that $n^T v < 0$ (normal points back to the query point) [S1, S2].
5. **Gradient Consistency:** The directional derivative with respect to viewpoint relates to the position gradient: $\nabla_v d(p, v) \delta v = d(p, v) \nabla_p d(p, v) \delta v$, where $\delta v = \omega \times v$ for any $\omega \in \mathbb{R}^3$ [S1, S2].

Parameters: $\varepsilon$: Width of the boundary shell defining the $\varepsilon$-domain $B_\varepsilon$ [S2]. $\gamma$ weights: Hyperparameters for loss functions (e.g., $\gamma_d, \gamma_\xi, \gamma_n$) [S2].

Edge Cases and Pitfalls:
* **Discontinuities:** DDFs are inherently discontinuous when $p$ passes through the surface $S$ (surface discontinuity) or when $p/v$ moves across an occlusion boundary (occlusion discontinuity) [S1, S2]. This challenges differentiable neural networks [S2].
* **View Inconsistency:** The 5D nature permits view-dependent geometry [S2]. Without regularization, the DDF may represent an aberrant 5D entity rather than a consistent 3D shape [S2].
* **Pathologies:** In proof-of-concept path tracing with Probabilistic DDFs (PDDFs), geometry may exhibit weight field seams ("cuts"), occlusion difficulties ("black spots" at intersections), and normal inaccuracies ("waviness") [S2].

Pseudocode:
```python
import numpy as np

def ray_aabb_intersect(origin, direction, bbox_min, bbox_max):
    """Standard ray-AABB intersection. Returns intersection point or None."""
    tmin = (bbox_min - origin) / direction
    tmax = (bbox_max - origin) / direction
    t1 = np.minimum(tmin, tmax)
    t2 = np.maximum(tmin, tmax)
    t_near = np.max(t1)
    t_far = np.min(t2)
    if t_near > t_far or t_far < 0:
        return None
    return origin + t_near * direction

def compute_gradient_finite_diff(p, v, network, eps=1e-4):
    """Computes gradient of d w.r.t p using central finite differences."""
    grad = np.zeros(3)
    for i in range(3):
        p_plus = p.copy()
        p_plus[i] += eps
        p_minus = p.copy()
        p_minus[i] -= eps
        d_plus = network(p_plus, v)[1]
        d_minus = network(p_minus, v)[1]
        grad[i] = (d_plus - d_minus) / (2 * eps)
    return grad

def query_ddf(p, v, network):
    v = v / np.linalg.norm(v)
    xi, d = network(p, v)
    return xi, d

def render_depth_map(camera_pos, pixel_positions, network, bbox_min, bbox_max):
    depths = np.zeros(len(pixel_positions))
    for i, pixel_pos in enumerate(pixel_positions):
        ray_dir = pixel_pos - camera_pos
        ray_len = np.linalg.norm(ray_dir)
        if ray_len == 0:
            depths[i] = np.inf
            continue
        ray_dir = ray_dir / ray_len

        if not np.all((camera_pos >= bbox_min) & (camera_pos <= bbox_max)):
            intersection = ray_aabb_intersect(camera_pos, ray_dir, bbox_min, bbox_max)
            if intersection is None:
                depths[i] = np.inf
                continue
            query_p = intersection
            dist_to_boundary = np.linalg.norm(camera_pos - intersection)
        else:
            query_p = camera_pos
            dist_to_boundary = 0.0

        xi, d = query_ddf(query_p, ray_dir, network)
        if xi > 0.5:
            depths[i] = d + dist_to_boundary
        else:
            depths[i] = np.inf
    return depths

def extract_surface_normal(p, v, network):
    grad_d = compute_gradient_finite_diff(p, v, network)
    grad_norm = np.linalg.norm(grad_d)
    if grad_norm == 0:
        return None
    s = 1 if np.dot(grad_d, v) < 0 else -1
    normal = s * grad_d / grad_norm
    return normal
```
## Subtopics

### [UDF Extraction via Minimal Direction Field](9280-udf-extraction-via-minimal-direction-field.md)
UDF Extraction via Minimal Direction Field converts a View-Consistent Directed Distance Field (DDF) into an Unoriented Distance Field (UDF) by optimizing a direction field $v^*: B \rightarrow S^2$. The resulting Minimal Direction Field (MDF) $v^*(p)$ points from query point $p$ to its closest point on the surface $S$, such that $UDF(p) = d(p, v^*(p))$. This method differs from direct UDF fitting by leveraging the geometric stability of the DDF's distance field $d$ while avoiding the ambiguity of unoriented gradients, though it introduces the challenge of optimizing for local minima in $v^*$.

### [Intrinsic Appearance DDF (IADDF)](9285-intrinsic-appearance-ddf-iaddf.md)
Intrinsic Appearance DDF (IADDF) is a rendering technique that augments a Probabilistic Directed Distance Field (PDDF) with material and lighting models to enable path tracing by recursively querying the DDF for surface intersections. It solves the problem of disentangling geometry, reflectance, and illumination in a view-consistent manner, allowing for the differentiable rendering of intrinsic images from any viewpoint. Unlike standard Neural Radiance Fields (NeRF) which act as entangled "clouds of particles," IADDF explicitly separates the scene into a geometric DDF and continuous Implicit Neural Representations (INRs) for appearance and lighting, leveraging the DDF's ability to model inter-surface light transport.

### DDF Composition
DDF Composition allows combining multiple DDFs into a single combined DDF for internal structure representation and compositionality, useful for manipulation without retraining [S2]. Given a set of $N$ DDFs $\zeta = \{T^{(i)}, \xi^{(i)}, d^{(i)}, B^{(i)}\}_{i=1}^N$, where $T^{(i)}$ is a transform on oriented points converting world to object coordinates for the $i$-th DDF, the combined visibility is:
$$ \xi_\zeta(p, v) = 1 - \prod_k (1 - \xi^{(k)}(T^{(k)}(p, v))) $$
The combined depth is a weighted sum:
$$ d_\zeta(p, v) = \sum_k a_\zeta^{(k)}(p, v) d^{(k)}(T^{(k)}(p, v)) $$
where weights $a_\zeta^{(k)}$ are computed via visibility and distance:
$$ a_\zeta(p, v) = \text{Softmax} \left( \left\{ \frac{\eta_T^{-1} \xi^{(k)}(T^{(k)}(p, v))}{\varepsilon_s + d^{(k)}(T^{(k)}(p, v))} \right\}_k \right) $$
Parameters $\eta_T$ (temperature) and $\varepsilon_s$ (maximum inverse depth scale) control the weighting [S2].

## Operating characteristics
* **Time Complexity:** Rendering complexity is independent of shape complexity [S2]. Depth rendering requires a single forward pass per pixel [S2].
* **Memory Complexity:** The 5D nature of the field ($3$ for position, $2$ for direction) requires significant memory for storage and computation compared to 3D fields [S1, S2].
* **Measured Performance:** In proof-of-concept forward rendering, DDF geometry showed accurate first-order values (initial ray-casting) and sufficient accuracy for surface bounces, but exhibited pathologies: weight field seams ('cuts'), occlusion difficulties ('black spots' at sphere intersections), and normal inaccuracies ('waviness' in reflected horizons) [S2].
* **Strengths:** Single forward pass per pixel for depth; topologically unconstrained; supports internal structure; enables differentiable rendering [S1, S2].
* **Limitations:** Inherently discontinuous; view inconsistencies possible without regularization; high dimensionality makes learning difficult [S1, S2].
* **When to use:** When fast, differentiable geometric rendering is required, or when internal structure and compositionality are needed [S1, S2].
* **When not to use:** When strict view consistency is required without regularization, or when computational resources for 5D networks are limited [S2].
## Background
Directed Distance Fields were introduced in 'Probabilistic Directed Distance Fields for Ray-Based Shape Representations' (CVPR 2022) by Aumentado-Armstrong et al. [S2]. The work builds on the history of distance field representations in computer vision, specifically Signed and Unsigned Distance Fields (S/UDFs) [S1]. It was developed to address the limitations of meshes (topological constraints, complexity-dependent rendering) and standard implicit shapes (inefficient rendering, multiple forward passes) [S2]. The theory of View Consistency and the geometric constraints (BC, DE, IO) were formalized to ensure the 5D field represents a valid 3D shape [S2].
