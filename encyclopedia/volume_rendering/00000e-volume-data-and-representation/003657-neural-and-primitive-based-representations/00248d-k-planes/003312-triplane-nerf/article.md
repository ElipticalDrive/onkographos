# TriPlane NeRF

Also called: TriPlane

## Overview
TriPlane NeRF is a hybrid 3D representation that aligns explicit features along three axis-aligned orthogonal feature planes to solve the scaling problems of voxel-based representations while maintaining efficiency and expressiveness [S1]. It differs from its parent [K-planes](3317-k-planes.md) by restricting the factorization to exactly three planes (XY, XZ, YZ) for 3D scenes, and from [Voxel NeRF](52-name.md) by using explicit feature planes that allow the decoder to remain small and the features to be optimized via gradients or generated by CNNs like StyleGAN [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D position $x \in \mathbb{R}^3$ and a viewing direction $d$.
*   **Output:** A color $c$ and volume density $\sigma$, denoted as $(c, \sigma)$.

**Data Structures:**
The representation consists of three feature planes $P = (P_{xy}, P_{xz}, P_{yz})$ [S1].
*   Each plane has a resolution of $N \times N \times C$, where $N$ is the spatial resolution and $C$ is the number of channels [S1].
*   The planes are stored as 2D grids of feature vectors.

**Algorithm:**
1.  **Projection:** Project the 3D position $x = (x, y, z)$ onto each of the three feature planes to obtain 2D coordinates:
    *   $P_{xy}$: $(x, y)$
    *   $P_{xz}$: $(x, z)$
    *   $P_{yz}$: $(y, z)$
2.  **Interpolation:** Retrieve the feature vector from each plane at the projected coordinates using bilinear interpolation [S1]. Let the retrieved vectors be $F_{xy}$, $F_{xz}$, and $F_{yz}$.
3.  **Aggregation:** Sum the three feature vectors to form the aggregated 3D feature vector $F_{agg}$:
    $$ F_{agg} = F_{xy} + F_{xz} + F_{yz} $$
4.  **Decoding:** Pass the aggregated feature $F_{agg}$ and the viewing direction $d$ into a lightweight decoder network (typically a small MLP) parameterized by $\Theta$ to predict the color $c$ and density $\sigma$ [S1].

**Formula:**
The final output is defined as:
$$ F_{TriPlaneNeRF}(x, d; \Theta, P) = (c, \sigma) $$
where $x$ is the 3D position, $d$ is the viewing direction, $\Theta$ are decoder parameters, and $P$ are the feature planes [S1].

**Parameters:**
*   $N$: Spatial resolution of each plane. Typical values depend on the desired detail level; higher $N$ increases memory usage quadratically.
*   $C$: Number of channels per plane.
*   $\Theta$: Parameters of the decoder MLP.

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Bilinear interpolation requires handling coordinates outside the $[0, N-1]$ range. Standard clamping or zero-padding is implied by the interpolation step [S1].
*   **Precision:** Floating-point precision in interpolation coordinates can affect gradient flow during optimization [G].

```python
def triplane_query_full(x, y, z, d, planes, decoder):
    F_xy = bilinear_interpolate(planes['xy'], x, y)
    F_xz = bilinear_interpolate(planes['xz'], x, z)
    F_yz = bilinear_interpolate(planes['yz'], y, z)
    
    F_agg = F_xy + F_xz + F_yz

    return color, sigma

def bilinear_interpolate(plane, u, v):
    """
    Performs bilinear interpolation on a 2D plane of feature vectors.
    plane: Tensor of shape (H, W, C)
    u, v: Float coordinates in [0, H-1] and [0, W-1]
    """
    # Get integer coordinates
    u0 = floor(u)
    v0 = floor(v)
    u1 = u0 + 1
    v1 = v0 + 1
    
    # Clamp to boundaries
    u0 = clamp(u0, 0, plane.shape[0] - 1)
    u1 = clamp(u1, 0, plane.shape[0] - 1)
    v0 = clamp(v0, 0, plane.shape[1] - 1)
    v1 = clamp(v1, 0, plane.shape[1] - 1)
    
    # Get fractional parts
    fu = u - u0
    fv = v - v0
    
    # Retrieve corner vectors
    v00 = plane[u0, v0, :]
    v10 = plane[u1, v0, :]
    v01 = plane[u0, v1, :]
    v11 = plane[u1, v1, :]
    
    # Interpolate
    # First dimension (u)
    v0_interp = lerp(v00, v10, fu)
    v1_interp = lerp(v01, v11, fu)
    
    # Second dimension (v)
    result = lerp(v0_interp, v1_interp, fv)
    
    return result

def lerp(a, b, t):
    return a + t * (b - a)

def clamp(val, min_val, max_val):
    return max(min_val, min(val, max_val))
```

## Subtopics

### HexPlane-Swap
HexPlane-Swap is a variant that groups planes with repeated axes, such as $P_{XY}$ and $P_{XT}$, breaking the symmetry of complementary axes. This design is inferior because it loses features associated with the particular axis that is not paired [S2]. On the D-NeRF dataset, it achieves a PSNR of 28.562, SSIM of 0.954, LPIPS of 0.056, and a training time of 11m 44s [S2].

### HexPlane-SH
HexPlane-SH is a pure explicit model that removes the MLP decoder. It stores spherical harmonics (SH) as appearance features and directly regresses RGB from them [S2]. On the D-NeRF dataset, it achieves a PSNR of 29.284, SSIM of 0.952, LPIPS of 0.056, and a training time of 10m 42s [S2].

### [Spatial Planes](9808-spatial-planes.md)
Spatial Planes is a variant that contains only three spatial planes: $P_{XY}$, $P_{XZ}$, and $P_{YZ}$. It cannot represent dynamic scenes alone and lacks the temporal or additional spatial dimensions found in more complex variants like HexPlane.

## Operating characteristics
*   **Memory Complexity:** The memory usage is $O(N^2 C)$, where $N$ is the spatial resolution and $C$ is the number of channels. This is significantly more scalable than voxel representations, which scale as $O(N^3)$ [S1].
*   **Performance:** TriPlane NeRF maintains efficiency and expressiveness. It allows for faster training compared to high-resolution voxel methods because the decoder remains small [S1].
*   **Strengths:** The primary advantage is keeping the decoder small while using explicit feature representation. This allows planes to be calculated with gradient-based optimization or produced by convolutional neural networks like StyleGAN or diffusion models [S1].
*   **Limitations:** It is restricted to three planes for 3D scenes, whereas the parent K-planes method generalizes to arbitrary dimensions $d$ using $\binom{d}{2}$ planes [S1]. It may suffer from aliasing or blurring if $N$ is too low, as it relies on bilinear interpolation [S1].

## Background
TriPlane NeRF was introduced as a solution to the scaling problems of voxel representations in neural radiance fields [S1]. It builds on the TriPlane representation [6] (referenced in [S1]) to provide an efficient and expressive 3D representation. The method uses a vanilla NeRF loss function and rendering procedure [S1]. It is often compared against Voxel NeRF, SRN, NV, and NSFV [S1].
