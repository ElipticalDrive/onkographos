# TriPlane NeRF

Also called: MultiPlaneNeRF, TriPlane representation

## Overview
TriPlane NeRF is a hybrid 3D representation that aligns explicit features along three axis-aligned orthogonal feature planes to solve the scaling problems of voxel-based representations while maintaining efficiency and expressiveness [S1]. It differs from its parent [K-planes](3317-k-planes.md) by restricting the factorization to exactly three specific planes ($XY, XZ, YZ$) rather than all $\binom{d}{2}$ pairs, and from [Voxel NeRF](3318-voxel-nerf.md) by keeping the decoder small and using explicit feature grids that can be optimized via gradients or generated by CNNs [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D position $x \in \mathbb{R}^3$ and a viewing direction $d$.
*   **Output:** A color $c$ and density $\sigma$, denoted as $(c, \sigma)$.

**Data Structures:**
The representation consists of three feature planes $P = (P_{xy}, P_{xz}, P_{yz})$ [S1].
*   Each plane $P_{ij}$ has a resolution of $N \times N \times C$, where $N$ is the spatial resolution and $C$ is the number of channels [S1].
*   The planes are axis-aligned and orthogonal [S1].

**Parameters:**
*   $N$: Spatial resolution of each plane. Not given in the sources.
*   $C$: Number of channels per plane. Not given in the sources.
*   $\Theta$: Parameters of the lightweight decoder network (MLP) [S1].
*   $P$: The set of three feature planes [S1].

**Steps:**
1.  **Project:** For a query 3D position $x = (x, y, z)$, project it onto each of the three feature planes to obtain 2D coordinates.
    *   For $P_{xy}$, the coordinates are $(x, y)$.
    *   For $P_{xz}$, the coordinates are $(x, z)$.
    *   For $P_{yz}$, the coordinates are $(y, z)$.
2.  **Interpolate:** Retrieve the corresponding feature vector from each plane via bilinear interpolation at the projected 2D coordinates [S1]. Let the retrieved vectors be $F_{xy}$, $F_{xz}$, and $F_{yz}$ [S1].
3.  **Aggregate:** Sum the three feature vectors to form the aggregated 3D feature vector $F_{agg}$ [S1]:
    $$ F_{agg} = F_{xy} + F_{xz} + F_{yz} $$
4.  **Decode:** Pass the aggregated feature vector $F_{agg}$ and the viewing direction $d$ into a lightweight decoder network (implemented as a small MLP) with parameters $\Theta$ to predict the color $c$ and density $\sigma$ [S1].

**Formula:**
The final output is computed as:
$$ F_{TriPlaneNeRF}(x, d; \Theta, P) = (c, \sigma) $$
where $x$ is the 3D position, $d$ is the viewing direction, $\Theta$ are decoder parameters, and $P$ are the feature planes [S1].

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def triplane_nerf_query(x, d, planes, decoder):
    """
    Query TriPlane NeRF for color and density at position x and direction d.
    
    Args:
        x: 3D position vector (x, y, z)
        d: Viewing direction vector
        planes: Dictionary containing 'Pxy', 'Pxz', 'Pyz' feature planes.
                Each plane is a 3D tensor of shape (N, N, C).
        decoder: A function representing the lightweight MLP decoder.
    
    Returns:
        color: Predicted RGB color
        density: Predicted density sigma
    """
    # Step 1 & 2: Project and Interpolate
    # Extract coordinates
    x_val, y_val, z_val = x[0], x[1], x[2]
    
    # Bilinear interpolation helper (standard operation)
    def bilinear_interp(plane, u, v):
        # u, v are normalized coordinates in [0, 1]
        # Map to pixel coordinates
        h, w, c = plane.shape
        u_px = u * (w - 1)
        v_px = v * (h - 1)
        
        # Get floor and ceil indices
        u0 = int(floor(u_px))
        v0 = int(floor(v_px))
        u1 = u0 + 1
        v1 = v0 + 1
        
        # Clamp to boundaries
        u0 = max(0, min(u0, w - 1))
        u1 = max(0, min(u1, w - 1))
        v0 = max(0, min(v0, h - 1))
        v1 = max(0, min(v1, h - 1))
        
        # Get corner values
        val_00 = plane[v0, u0, :]
        val_01 = plane[v0, u1, :]
        val_10 = plane[v1, u0, :]
        val_11 = plane[v1, u1, :]
        
        # Interpolate
        du = u_px - u0
        dv = v_px - v0
        
        top = lerp(val_00, val_01, du)
        bottom = lerp(val_10, val_11, du)
        
        return lerp(top, bottom, dv)

    # Project onto XY plane
    # Assuming x,y,z are in range [-1, 1] or [0, 1], normalization needed based on specific implementation.
    # Standard NeRF often uses [-1, 1]. We assume normalization to [0, 1] for interpolation.
    # [G] Normalization logic depends on the coordinate system definition. 
    # Assuming standard normalization: coord_norm = (coord + 1) / 2
    x_norm = (x_val + 1) / 2
    y_norm = (y_val + 1) / 2
    z_norm = (z_val + 1) / 2
    
    F_xy = bilinear_interp(planes['Pxy'], x_norm, y_norm)
    F_xz = bilinear_interp(planes['Pxz'], x_norm, z_norm)
    F_yz = bilinear_interp(planes['Pyz'], y_norm, z_norm)
    
    # Step 3: Aggregate via summation
    F_agg = F_xy + F_xz + F_yz
    
    # Step 4: Decode
    # The decoder takes the aggregated features and viewing direction
    color, density = decoder(F_agg, d)
    
    return color, density
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Bilinear interpolation requires handling coordinates outside the $[0, 1]$ range if the query point $x$ is outside the bounding box of the planes. Standard clamping or reflection padding is typically used, though not explicitly detailed in the sources [S1].
*   **Decoder Size:** The advantage of this representation relies on keeping the decoder small. If the decoder is too large, the memory benefits of the explicit planes may be negated [S1].

## Subtopics

### HexPlane-Swap
HexPlane-Swap is a variant of HexPlane that groups planes with repeated axes, such as $P_{XY}$ and $P_{XT}$ [S2]. It achieves inferior results compared to the standard HexPlane because its axes are not complementary, leading to a loss of features from particular axes [S2]. On the D-NeRF dataset, HexPlane-Swap achieves a PSNR of 28.562, SSIM of 0.954, LPIPS of 0.056, and a training time of 11 minutes 44 seconds [S2].

### HexPlane-SH
HexPlane-SH is a pure explicit model variant of HexPlane that does not use MLPs for the final prediction on the D-NeRF dataset [S2]. It stores spherical harmonics (SH) as appearance features and directly regresses RGB from them rather than using a decoder network [S2]. On the D-NeRF dataset, HexPlane-SH achieves a PSNR of 29.284, SSIM of 0.952, LPIPS of 0.056, and a training time of 10 minutes 42 seconds [S2].

## Operating characteristics
*   **Complexity:** The representation scales with $O(N^2)$ per plane, totaling $3 \times N^2 \times C$ memory for the planes, which is significantly more efficient than voxel representations that scale with $O(N^3)$ [S1].
*   **Performance:** TriPlane NeRF (referred to as MultiPlaneNeRF in the source) shows improved metrics over Voxel NeRF and SRN. For example, on the Chair scene, it achieves a PSNR of 33.00 and SSIM of 0.967, compared to Voxel NeRF's 28.33 PSNR and 0.916 SSIM [S1].
*   **Strengths:** It keeps the decoder small and uses explicit feature representation, allowing planes to be calculated with gradient-based optimization or produced by CNNs like StyleGAN or diffusion models [S1].
*   **Limitations:** It is limited to three axis-aligned planes, which may not capture complex 3D structures as well as methods using more planes or different geometries (like HexPlane or Platonic Solid Projection) [S1, S2].

## Background
TriPlane NeRF was introduced as a solution to the scaling problems of voxel representations in neural radiance fields [S1]. It builds on the TriPlane representation [6] (cited in [S1]), which is both efficient and expressive. The method was presented in the paper "MultiPlaneNeRF: Neural radiance field with non-trainable representation" [S1].
