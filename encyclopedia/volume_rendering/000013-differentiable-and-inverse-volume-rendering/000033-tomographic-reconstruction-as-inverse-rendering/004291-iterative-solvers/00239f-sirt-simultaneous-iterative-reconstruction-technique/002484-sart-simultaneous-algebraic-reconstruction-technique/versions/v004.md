# SART (Simultaneous Algebraic Reconstruction Technique)

Also called: Simultaneous Algebraic Reconstruction Technique, Proximal SART, ProxiSART

## Overview
SART is an iterative algebraic reconstruction technique that solves the discrete linear system $Af = b$ arising from tomographic projection data by updating the volume estimate simultaneously for all rays in a subset of projections [S2, unofficial]. It improves upon single-ray methods (like ART) by normalizing the backprojection by the number of rays intersecting each voxel, which reduces streak artifacts and accelerates convergence [S2, unofficial]. It is distinguished from its sibling [SIRT](3101-sirt-simultaneous-iterative-reconstruction-technique.md) by the order of normalization: SART normalizes the residual by the ray's total intersected length before backprojecting, whereas SIRT normalizes the backprojected update by the voxel's total intersected length [S2, unofficial]. It is preferred over direct methods like FDK for limited projection scenarios and over Conjugate Gradient (CG) for sparse-view settings due to better convergence properties in matrix-free implementations [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Measured projection data $b \in \mathbb{R}^m$, system matrix $A \in \mathbb{R}^{m \times n}$ (implicitly defined by geometry), initial volume estimate $f^{(0)} \in \mathbb{R}^n$, relaxation parameter $\alpha$, and number of outer iterations $T$.
*   **Output:** Reconstructed volume $f \in \mathbb{R}^n$.

**Data Structures:**
*   $f$: 3D volume array of size $n$ (voxels).
*   $b$: 1D array of size $m$ (projection rays).
*   $w_i$: 1D array of size $m$, where $w_i = \sum_k a_{ik}$ is the sum of weights for ray $i$ (ray sensitivity).
*   $v_j$: 1D array of size $n$, where $v_j = \sum_{i \in \text{rays through } j} a_{ij}$ is the sum of weights for voxel $j$ (voxel sensitivity). *Note: In standard SART, the denominator in the backprojection step is $\sum_{i \in S} a_{ij}$, which is the sum of weights of rays in the current subset $S$ intersecting voxel $j$. Precomputing global sensitivities is optional but common for normalization.*

**Algorithm Steps:**
The standard SART algorithm updates the volume by iterating through subsets of projections (often all projections or a subset $S$). For each subset, it performs three steps for each ray $i$:

1.  **Forward Projection:** Compute the estimated projection $\hat{b}_i^{(t)}$ for all rays $i$ in the current subset $S$ using the current volume estimate $f^{(t)}$:
    $$ \hat{b}_i^{(t)} = \sum_{k=1}^{n} a_{ik} f_k^{(t)} $$
    where $a_{ik}$ is the contribution of voxel $k$ to ray $i$.

2.  **Correction:** Compute the correction factor $c_i^{(t)}$ for each ray $i \in S$:
    $$ c_i^{(t)} = \frac{b_i - \hat{b}_i^{(t)}}{\sum_{k=1}^{n} a_{ik}} $$
    The denominator $\sum_{k} a_{ik}$ is the total weight of the ray (sum of contributions from all voxels it passes through). This normalizes the residual by the ray's path length/weight.

3.  **Backprojection:** Update the volume $f$ for all voxels $j=1 \dots n$:
    $$ f_j^{(t+1)} = f_j^{(t)} + \alpha \frac{\sum_{i \in S} c_i^{(t)} a_{ij}}{\sum_{i \in S} a_{ij}} $$
    The denominator $\sum_{i \in S} a_{ij}$ is the sum of weights of the rays in subset $S$ that intersect voxel $j$. This normalizes the backprojected correction by the number of rays contributing to the voxel.

**Parameters:**
*   $\alpha$: Relaxation parameter. Typical values range from 0.1 to 0.8 [S2, unofficial]. A value of 0.5 is commonly used [S1, unofficial].
*   $T$: Number of outer iterations.
*   $S$: Subset of projections. Often $S$ is the set of all projections.

**Pseudocode:**
```python
def sart(b, A_forward, A_back, n_voxels, n_rays, alpha, T, subset_indices=None):
    """
    Standard SART reconstruction.
    
    Args:
        b: array of measured projections (size m)
        A_forward: function that computes forward projection (volume -> projections)
        A_back: function that computes backprojection (corrections -> volume)
        n_voxels: number of voxels
        n_rays: number of rays
        alpha: relaxation parameter
        T: number of iterations
        subset_indices: list of ray indices for the subset S. If None, use all rays.
        
    Returns:
        f: reconstructed volume
    """
    # Initialize volume
    f = zeros(n_voxels)
    
    # Precompute ray weights (sum of a_ik for all k) if not provided
    # ray_weights[i] = sum_k a_ik
    # This requires iterating over all voxels for each ray, which is expensive.
    # In practice, A_forward and A_back are often implemented with precomputed weights.
    # For this generic pseudocode, we assume A_forward/back handle the geometry.
    # However, the denominator in correction requires ray_weights.
    
    # Compute ray weights: w_i = sum_k a_ik
    # This is equivalent to A_forward(ones(n_voxels))
    ray_weights = A_forward(ones(n_voxels))
    
    # If subset_indices is not provided, use all rays
    if subset_indices is None:
        subset_indices = range(n_rays)
        
    for t in range(T):
        # Initialize correction array for this iteration
        corrections = zeros(n_rays)
        
        # Step 1 & 2: Forward Projection and Correction for subset S
        # Compute estimated projections for the subset
        # Note: A_forward typically computes for all rays. We only need subset.
        # For efficiency, A_forward should support subset.
        b_hat = A_forward(f, subset=subset_indices)
        
        for i in subset_indices:
            residual = b[i] - b_hat[i]
            # Avoid division by zero
            if ray_weights[i] > 0:
                corrections[i] = residual / ray_weights[i]
            else:
                corrections[i] = 0.0
                
        # Step 3: Backprojection and Update
        # We need to compute the denominator for each voxel: sum_{i in S} a_ij
        # This is equivalent to A_back(ones(n_rays), subset=subset_indices) but only for voxels
        # However, A_back usually takes corrections and returns volume update.
        # We need the sensitivity of each voxel to the subset S.
        
        # Compute voxel sensitivities for the subset S
        # voxel_sens[j] = sum_{i in S} a_ij
        # This can be computed by backprojecting a vector of ones for the subset
        voxel_sens = A_back(ones(len(subset_indices)), subset=subset_indices)
        
        # Compute the backprojected correction
        # backprojected_corr[j] = sum_{i in S} corrections[i] * a_ij
        backprojected_corr = A_back(corrections, subset=subset_indices)
        
        # Update volume
        for j in range(n_voxels):
            if voxel_sens[j] > 0:
                f[j] = f[j] + alpha * (backprojected_corr[j] / voxel_sens[j])
            else:
                # If no rays in subset intersect voxel j, no update
                pass
                
    return f
```

**Proximal SART (for Data Term in Optimization):**
When used as a proximal operator for the data fidelity term $f(f) = \|Af - p\|_2^2$ within a Chambolle-Pock scheme, the problem is transformed into an under-determined linear system by introducing auxiliary variables $y$ and $z$ [S2, unofficial]:
$$ \text{prox}_{\lambda_f}(q) = \text{argmin}_f \|Af - p\|_2^2 + \frac{1}{2\lambda}\|f - q\|_2^2 $$
This is equivalent to solving:
$$ \min_{\tilde{f}} \|\tilde{f}\|_2^2 \quad \text{subject to: } \tilde{A}\tilde{f} = \tilde{p} $$
where $\tilde{f} = [y; z]$, $\tilde{A} = [I \ \sqrt{2\lambda}A]$, and $\tilde{p} = \sqrt{2\lambda}(p - Aq)$ [S2, unofficial].
The modified SART algorithm for this proximal operator is [S2, unofficial]:

1.  **Initialization:** Set $y^{(0)} = 0$, $f^{(0)} = q$. Scale inputs: $\tilde{p} = \sqrt{2\lambda}p$, $\tilde{A} = \sqrt{2\lambda}A$.
2.  **Outer Loop:** Iterate $t$ from 1 to $T$.
3.  **Inner Loop:** Iterate over projections $S$ in $S_1 \dots S_N$.
4.  **Update:**
    *   Update $y$ for indices $j$ in current projection set $S$:
        $$ y_j^{(t+1)} = y_j^{(t)} + \alpha c_j^{(t)} $$
    *   Compute predicted projection sum:
        $$ \hat{b}_i^{(t+1)} = \sum_k a_{ik} f_k^{(t)} + y_i^{(t)} $$
    *   Compute correction factor:
        $$ c_i^{(t+1)} = \frac{b_i - \hat{b}_i^{(t+1)}}{\sum_k a_{ik} + 1} $$
    *   Update volume $f$ for all voxels $j=1 \dots n$:
        $$ f_j^{(t+1)} = f_j^{(t)} + \alpha \frac{\sum_{i \in S} c_i^{(t+1)} a_{ij}}{\sum_{i \in S} a_{ij}} $$

**Edge Cases and Pitfalls:**
*   **Division by Zero:** Rays with zero weight (e.g., outside the field of view) or voxels not intersected by any ray in the current subset must be handled to avoid NaNs [S2, unofficial].
*   **Memory Usage:** In proximal SART implementations involving patch-based Jacobians, memory usage can be high. For a volume of size $N$, storage can be 82 times the volume size (81 for Jacobian + 1 for volume) [S2, unofficial]. For a $690 \times 668 \times 776$ voxel volume, this requires 109 GB [S2, unofficial].
*   **Convergence:** SART is preferred over CG because CG suffers from numerical noise in matrix-free tomography and convergence issues with large sparse systems [S2, unofficial].

## Subtopics

### [Voxel Splatting SART/SIRT](15304-voxel-splatting-sart-sirt.md)
A GPU-accelerated implementation that treats forward/back-projection as splatting kernels, inverting the data flow to project voxels onto the detector. It is distinguished by its efficiency in parallel ray geometry (e.g., cryo-ET) and use of pre-integrated lookup tables.

### [Proximal Jointly-Optimized Reconstruction and Denoising](15324-proximal-jointly-optimized-reconstruction-and-denoising.md)
A method that integrates denoising into reconstruction using SART as the solver for the data fidelity term. It is chosen over CG for sparse-view settings to maintain consistency with raw projections.

## Operating characteristics
*   **Time Complexity:** Each iteration involves one forward projection and one backprojection. The cost is proportional to the number of voxels and rays. Convergence is generally faster than ART but slower than FDK for full-view data.
*   **Memory Complexity:** Modest memory requirements compared to direct methods that require storing the full system matrix $A$ ($O(mn)$). SART is matrix-free, requiring only storage for the volume and projections [S2, unofficial]. However, proximal variants may require additional storage for auxiliary variables and Jacobians [S2, unofficial].
*   **Measured Performance:** On a machine with 24 cores and 48 GB RAM, SART with Kaiser-Bessel kernels (radius 2 voxels) and slice-by-slice optimization was used for reconstruction [S1, unofficial]. For sparse-view settings, SART provides better reconstruction results than FDK and CG [S2, unofficial].
*   **Strengths:** Handles limited projections better than FDK [S2, unofficial]. Incorporates prior information (e.g., TV priors) easily [S2, unofficial]. Modest memory usage [S2, unofficial].
*   **Limitations:** Slower than FDK for full-view data. Convergence can be slow for high-accuracy requirements. Sensitive to noise if not regularized [S1, unofficial].
*   **When to Use:** Sparse-view tomography, limited-angle tomography, or when incorporating regularization priors.
*   **When Not to Use:** Full-view, high-quality data where speed is critical (use FDK). Large-scale problems where memory for auxiliary variables in proximal methods is prohibitive.

## Background
SART was proposed by Andersen and Kak [7] as an efficient iterative reconstruction method based on the Kaczmarz projection method [S2, unofficial]. It updates the volume for each scan view, offering better results than FDK for limited projections [S2, unofficial]. It has been widely used in computed tomography, including industrial CT and medical imaging [S1, S2, unofficial]. Recent developments include its use as a proximal operator in Chambolle-Pock schemes for robust 3D cone beam reconstruction [S1, unofficial] and in space-time tomographic reconstruction of deforming objects [S2, unofficial].
