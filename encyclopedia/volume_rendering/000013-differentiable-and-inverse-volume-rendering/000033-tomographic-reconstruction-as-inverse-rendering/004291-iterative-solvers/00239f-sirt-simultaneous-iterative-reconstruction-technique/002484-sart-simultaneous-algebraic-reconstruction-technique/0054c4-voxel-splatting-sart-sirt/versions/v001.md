# Voxel Splatting SART/SIRT
Also called: Voxel Splatting Implementation of SART/SIRT

## Overview
Voxel Splatting SART/SIRT is a GPU-accelerated implementation of the Simultaneous Algebraic Reconstruction Technique (SART) and Simultaneous Iterative Reconstruction Technique (SIRT) proximal operators for tomographic reconstruction [S1]. It solves the inverse problem of reconstructing a 3D volume from 2D projections by treating the forward and back-projection operations as splatting kernels rather than ray-casting [S1]. It is distinguished from its sibling, Ray Casting SART/SIRT, by inverting the data flow: instead of casting rays from the detector to sample the volume, it projects each voxel onto the detector plane, accumulating contributions into ray-sum and weight images [S1]. This approach leverages pre-integrated lookup tables for weights, enabling efficient parallelization in cryo-electron tomography (cryo-ET) where parallel ray geometry is common [S1].

## How it works
The method implements the forward and back-projection operators required for the SART/SIRT iterative solver. The core principle is that the forward projection (splatting voxels to detector) and back-projection (splatting detector corrections to voxels) are transposes of each other [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Current volume estimate $V$ (3D grid of voxel values).
    *   Measured projection images $I(p_i)$ in log space for each view angle.
    *   Relaxation parameter $\alpha$.
    *   Pre-computed weight lookup tables (LUTs) derived from line integrals of radially symmetric filter kernels at various distances [S1].
*   **Outputs:**
    *   Updated volume estimate $V'$.
    *   Correction image (intermediate result for back-projection).

### Data Structures
1.  **Ray-sum Image ($R$):** A 2D image matching the detector resolution. Stores the accumulated weighted sum of voxel contributions.
2.  **Weights Image ($W$):** A 2D image matching the detector resolution. Stores the sum of weights for each pixel, used to normalize the correction term.
3.  **Correction Image ($C$):** A 2D image matching the detector resolution. Stores the computed correction term for each pixel before back-projection.
4.  **Weight Lookup Table (LUT):** A 1D or 2D array mapping geometric parameters (e.g., distance from voxel center to pixel center) to pre-integrated kernel weights [S1].

### Numbered Steps

#### Forward Projection
1.  **Initialize:** Zero out the Ray-sum Image $R$ and Weights Image $W$.
2.  **Splat Voxels:** For each voxel $v$ in the volume $V$:
    a.  Determine the kernel support (the set of detector pixels affected by the voxel).
    b.  For each pixel $i$ in the kernel support:
        i.  Calculate the geometric weight $w_{v,i}$ using the pre-computed LUT based on the distance between the voxel center and pixel $i$ [S1].
        ii. Update the Ray-sum Image: $R[i] \leftarrow R[i] + w_{v,i} \cdot V[v]$.
        iii. Update the Weights Image: $W[i] \leftarrow W[i] + w_{v,i}$.
    *   *Note:* Data races may occur if multiple voxels update the same pixel $i$ simultaneously in $R$ and $W$ [S1]. Atomic operations or parallel reduction are required to ensure correctness.

#### Correction Image Computation
1.  For each pixel $i$ in the detector image:
    a.  Retrieve the measured line integral $I(p_i)$ from the input projection data.
    b.  Retrieve the computed ray sum $R[i]$ and weight sum $W[i]$.
    c.  Compute the correction term $C[i]$ using the formula:
        $$ C[i] = \alpha \cdot \frac{I(p_i) - R[i]}{W[i]} $$
        where $\alpha$ is the relaxation parameter [S1].
    *   *Edge Case:* If $W[i] = 0$ (no voxels contributed to this pixel), $C[i]$ should be set to 0 to avoid division by zero.

#### Back-projection
1.  **Initialize:** Create a temporary buffer for the updated volume values, initialized to zero.
2.  **Splat Corrections:** For each voxel $v$ in the volume $V$:
    a.  Determine the kernel support (the set of detector pixels affected by the voxel).
    b.  For each pixel $i$ in the kernel support:
        i.  Retrieve the correction value $C[i]$ from the Correction Image.
        ii. Retrieve the weight $w_{v,i}$ from the LUT (same weight used in forward projection).
        iii. Accumulate the contribution: $V_{new}[v] \leftarrow V_{new}[v] + w_{v,i} \cdot C[i]$.
    *   *Note:* No data races occur in back-projection because each voxel writes to a unique memory location in the volume buffer [S1].
3.  **Update Volume:** Replace $V$ with $V_{new}$.

### Pseudocode
```python
def voxel_splatting_sart_sirt(volume, projections, alpha, weight_lut, detector_shape):
    """
    volume: 3D array (D, H, W) of voxel values
    projections: list of 2D arrays (detector images) in log space
    alpha: float, relaxation parameter
    weight_lut: function or array mapping (voxel_center, pixel_center) -> weight
    detector_shape: tuple (H_det, W_det)
    """
    num_views = len(projections)
    updated_volume = np.zeros_like(volume)
    
    for view_idx in range(num_views):
        # 1. Forward Projection: Splat voxels to detector
        ray_sum_image = np.zeros(detector_shape)
        weights_image = np.zeros(detector_shape)
        
        # Iterate over all voxels
        for v in volume.nonzero(): # Or iterate over all voxels if dense
            voxel_val = volume[v]
            
            # Determine kernel support for this voxel
            # In practice, this is a small bounding box around the projected voxel center
            kernel_support = get_kernel_support(v, detector_shape)
            
            for pixel in kernel_support:
                # Get weight from pre-computed LUT
                w = weight_lut(v, pixel)
                
                # Update ray-sum and weights images
                # Use atomic add in GPU implementation to handle data races
                ray_sum_image[pixel] += w * voxel_val
                weights_image[pixel] += w
        
        # 2. Compute Correction Image
        measured_projection = projections[view_idx]
        correction_image = np.zeros(detector_shape)
        
        for i in range(detector_shape[0]):
            for j in range(detector_shape[1]):
                w_sum = weights_image[i, j]
                if w_sum > 0:
                    # Formula: alpha * (I(p_i) - ray_sum_image[i]) / weights_image[i]
                    correction_image[i, j] = alpha * (measured_projection[i, j] - ray_sum_image[i, j]) / w_sum
                else:
                    correction_image[i, j] = 0.0
        
        # 3. Back-projection: Splat corrections to voxels
        # Initialize a temporary buffer for this view's contribution
        view_contribution = np.zeros_like(volume)
        
        for v in volume.nonzero():
            kernel_support = get_kernel_support(v, detector_shape)
            
            for pixel in kernel_support:
                w = weight_lut(v, pixel)
                c_val = correction_image[pixel]
                
                # Accumulate correction weighted by the same kernel weight
                view_contribution[v] += w * c_val
        
        # Update the global volume estimate
        updated_volume += view_contribution
        
    return updated_volume
```

### Parameters
*   **$\alpha$ (Relaxation Parameter):** Controls the step size of the update. Typical values are in the range $(0, 2)$, with $1.0$ being common for SART [S1].
*   **Kernel Support:** The spatial extent of the splatting kernel. This determines how many detector pixels are updated per voxel. It depends on the interpolation kernel used (e.g., linear, cubic) [S1].
*   **Weight Lookup Table (LUT):** Pre-computed weights based on line integrals of radially symmetric filter kernels at different distances [S1].

### Edge Cases and Pitfalls
*   **Data Races:** In forward projection, multiple voxels may update the same detector pixel simultaneously. This requires atomic operations or parallel reduction techniques to avoid race conditions [S1].
*   **Division by Zero:** If a detector pixel has no contributing voxels ($W[i] = 0$), the correction term calculation must handle this to avoid NaNs.
*   **Precision:** The use of pre-integrated LUTs introduces approximation errors compared to exact ray casting, but linear interpolation yields results "practically the same" as ray-based methods [S1].

## Subtopics

### Ray Casting SART/SIRT
An alternative implementation of SART/SIRT proximal operators based on ray casting [S1]. In this variant, threads compute line integrals and correction terms for forward projection by casting rays from the detector through the volume, and update voxels based on correction images for back-projection [S1]. Forward projection involves casting a ray from each pixel, sampling the volume at equidistant points, and retrieving volume values via tri-linear interpolation [S1]. The correction term is computed as $(I(p_i) - \text{sample\_rate} \times \sum_{s=1}^k v_{sk}) / \text{ray\_length}$, where $I(p_i)$ is the measured line integral, $S$ is the number of samples, $\text{sample\_rate}$ is the distance between samples, $v_{sk}$ is the volume estimate at sample $s$, and $\text{ray\_length}$ is the ray-volume intersection length [S1]. Back-projection involves casting a ray from each voxel to the detector, retrieving a correction value via bi-linear interpolation, and updating the voxel [S1]. Unlike voxel splatting, forward and back-projection are not exact transposes in this implementation due to the interpolation methods used [S1]. This method is chosen when exact geometric modeling is prioritized over the parallelization benefits of splatting, or when the volume is sparse and ray casting is more efficient [S1].

## Operating characteristics
*   **Time Complexity:** The complexity is proportional to the number of voxels times the kernel support size for forward projection, and the number of detector pixels for correction image computation. Back-projection is proportional to the number of voxels times the kernel support size. Overall, it is $O(N_v \cdot K + N_p)$, where $N_v$ is the number of voxels, $K$ is the kernel support size, and $N_p$ is the number of detector pixels [S1].
*   **Memory Complexity:** Requires storage for the volume, two 2D images (ray-sum and weights), and the correction image. The LUT size depends on the resolution of the pre-computed weights [S1].
*   **Performance:** The voxel splatting approach is highly parallelizable on GPUs, making it suitable for large volumes in cryo-ET [S1]. The use of pre-integrated LUTs reduces the computational cost of weight calculation during runtime [S1].
*   **Strengths:** Efficient parallelization, no data races in back-projection, practical equivalence to ray-based methods with linear interpolation [S1].
*   **Limitations:** Data races in forward projection require atomic operations, which can reduce performance on some GPU architectures. Approximation errors from LUTs [S1].
*   **When to Use:** Suitable for cryo-ET with parallel ray geometry where high performance is needed and slight approximation errors are acceptable [S1].
*   **When Not to Use:** When exact geometric accuracy is critical and ray casting is preferred, or when the volume is extremely sparse and ray casting is more efficient [S1].

## Background
The voxel splatting implementation of SART/SIRT was developed as part of a framework for GPU-accelerated 3D tomographic reconstruction and visualization from noisy electron microscopy tilt-series [S1]. It was introduced to address the computational demands of cryo-electron tomography (cryo-ET), where large volumes and parallel ray geometry allow for efficient parallelization [S1]. The method builds on the concept of voxel splatting, where voxels are projected onto the detector plane using pre-integrated lookup tables for weights, which are computed by line integrals of rays traversing radially symmetric filter kernels [S1]. This approach was compared with a ray casting implementation to evaluate performance and accuracy [S1].
