# Voxel Splatting SART/SIRT
Also called: Voxel Splatting Implementation of SART/SIRT

## Overview
Voxel Splatting SART/SIRT is a GPU-accelerated implementation of the Simultaneous Algebraic Reconstruction Technique (SART) and Simultaneous Iterative Reconstruction Technique (SIRT) proximal operators for tomographic reconstruction [S1]. It solves the inverse problem of reconstructing a 3D volume from 2D projections by treating forward and back-projection operations as splatting kernels rather than ray-casting [S1]. It is distinguished from its sibling, Ray Casting SART/SIRT, by inverting the data flow: instead of casting rays from the detector to sample the volume, it projects each voxel onto the detector plane, accumulating contributions into ray-sum and weight images [S1]. This approach leverages pre-integrated lookup tables for weights, enabling efficient parallelization in cryo-electron tomography (cryo-ET) where parallel ray geometry is common [S1].

## How it works
The method implements the forward and back-projection operators required for the SART/SIRT iterative solver [G]. The core principle is that the forward projection (splatting voxels to detector) and back-projection (splatting detector corrections to voxels) are transposes of each other [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Current volume estimate $V$ (3D grid of voxel values) [G].
    *   Measured projection images $I(p_i)$ in log space for each view angle [S1].
    *   Relaxation parameter $\alpha$ [S1].
    *   Pre-computed weight lookup tables (LUTs) derived from line integrals of radially symmetric filter kernels at various distances [S1].
*   **Outputs:**
    *   Updated volume estimate $V'$ [G].
    *   Correction image (intermediate result for back-projection) [S1].

### Data Structures
1.  **Ray-sum Image ($R$):** A 2D image matching the detector resolution [G]. Stores the accumulated weighted sum of voxel contributions [S1].
2.  **Weights Image ($W$):** A 2D image matching the detector resolution [G]. Stores the sum of weights for each pixel, used to normalize the correction term [S1].
3.  **Correction Image ($C$):** A 2D image matching the detector resolution [G]. Stores the computed correction term for each pixel before back-projection [S1].
4.  **Weight Lookup Table (LUT):** A 1D or 2D array mapping geometric parameters (e.g., distance from voxel center to pixel center) to pre-integrated kernel weights [S1].

### Numbered Steps

#### Forward Projection
1.  **Initialize:** Zero out the Ray-sum Image $R$ and Weights Image $W$ [G].
2.  **Splat Voxels:** For each voxel $v$ in the volume $V$:
    a.  Determine the kernel support (the spatial extent of the splatting kernel) [S1].
    b.  For each pixel $i$ in the kernel support:
        i.  Calculate the geometric weight $w_{v,i}$ using the pre-computed LUT based on the distance between the voxel center and pixel $i$ [S1].
        ii. Update the Ray-sum Image: $R[i] \leftarrow R[i] + w_{v,i} \cdot V[v]$ [S1].
        iii. Update the Weights Image: $W[i] \leftarrow W[i] + w_{v,i}$ [S1].
    *   *Note:* Data races can occur if two voxels try to update the same pixels at once, either in the ray-sum image or the weights image [S1]. Atomic operations or parallel reduction are required to ensure correctness [G].

#### Correction Image Computation
1.  For each pixel $i$ in the detector image:
    a.  Retrieve the measured line integral $I(p_i)$ from the input projection data [S1].
    b.  Retrieve the computed ray sum $R[i]$ and weight sum $W[i]$ [S1].
    c.  Compute the correction term $C[i]$ using the formula:
        $$ C[i] = \alpha \cdot \frac{I(p_i) - R[i]}{W[i]} $$
        where $\alpha$ is the relaxation parameter [S1].
    *   *Edge Case:* If $W[i] = 0$ (no voxels contributed to this pixel), $C[i]$ should be set to 0 to avoid division by zero [G].

#### Back-projection
1.  **Initialize:** Create a temporary buffer for the updated volume values, initialized to zero [G].
2.  **Splat Corrections:** For each voxel $v$ in the volume $V$:
    a.  Identify the detector pixels covered by the voxel's kernel [S1].
    b.  For each pixel $i$ in the kernel support:
        i.  Retrieve the correction value $C[i]$ from the Correction Image [S1].
        ii. Retrieve the weight $w_{v,i}$ from the LUT (same weight used in forward projection) [S1].
        iii. Accumulate the contribution: $V_{new}[v] \leftarrow V_{new}[v] + w_{v,i} \cdot C[i]$ [S1].
    *   *Note:* There are no data races in the back-projection operation because each voxel writes to a unique memory location in the volume buffer [S1].
3.  **Update Volume:** Replace $V$ with $V_{new}$ [G].

def voxel_splatting_sart_sirt(volume, projections, alpha, detector_shape, kernel_radius):
    """
    volume: 3D list (D, H, W) of voxel values
    projections: list of 2D lists (detector images) in log space
    alpha: float, relaxation parameter
    detector_shape: tuple (H_det, W_det)
    kernel_radius: float, spatial extent of the splatting kernel
    """
    D, H, W = len(volume), len(volume[0]), len(volume[0][0])
    num_views = len(projections)
    updated_volume = [[[0.0] * W for _ in range(H)] for _ in range(D)]
    
    for view_idx in range(num_views):
        ray_sum_image = zeros(detector_shape)
        weights_image = zeros(detector_shape)
        
        for d in range(D):
            for h in range(H):
                for w in range(W):
                    voxel_val = volume[d][h][w]
                    if voxel_val == 0.0:
                        continue
                    
                    voxel_center = (h, w)
                    kernel_support = compute_kernel_support(voxel_center, detector_shape, kernel_radius)
                    
                    for pixel in kernel_support:
                        w_val = lookup_weight(voxel_center, pixel)
                        ray_sum_image[pixel[1]][pixel[0]] += w_val * voxel_val
                        weights_image[pixel[1]][pixel[0]] += w_val
        
        measured_projection = projections[view_idx]
        correction_image = zeros(detector_shape)
        
        for i in range(detector_shape[0]):
            for j in range(detector_shape[1]):
                w_sum = weights_image[i][j]
                if w_sum > 0.0:
                    correction_image[i][j] = alpha * (measured_projection[i][j] - ray_sum_image[i][j]) / w_sum
                else:
                    correction_image[i][j] = 0.0
        
        view_contribution = [[[0.0] * W for _ in range(H)] for _ in range(D)]
        
        for d in range(D):
            for h in range(H):
                for w in range(W):
                    voxel_center = (h, w)
                    kernel_support = compute_kernel_support(voxel_center, detector_shape, kernel_radius)
                    
                    for pixel in kernel_support:
                        w_val = lookup_weight(voxel_center, pixel)
                        c_val = correction_image[pixel[1]][pixel[0]]
                        view_contribution[d][h][w] += w_val * c_val
        
        for d in range(D):
            for h in range(H):
                for w in range(W):
                    updated_volume[d][h][w] += view_contribution[d][h][w]
        
    return updated_volume

### Parameters
*   **$\alpha$ (Relaxation Parameter):** Controls the step size of the update. Not given in the sources.
*   **Kernel Support:** The spatial extent of the splatting kernel [S1].
*   **Weight Lookup Table (LUT):** Pre-computed weights based on line integrals of radially symmetric filter kernels at different distances [S1].

### Edge Cases and Pitfalls
*   **Data Races:** In forward projection, multiple voxels may update the same detector pixel simultaneously [S1].
*   **Division by Zero:** If a detector pixel has no contributing voxels ($W[i] = 0$), the correction term calculation must handle this to avoid NaNs [G].
*   **Precision:** The use of pre-integrated LUTs introduces approximation errors compared to exact ray casting, but linear interpolation yields results practically the same as ray-based methods [S1].

## Subtopics

### Ray Casting SART/SIRT
An alternative implementation of SART/SIRT proximal operators based on ray casting [S1]. In this variant, threads compute line integrals and correction terms for forward projection by casting rays from the detector through the volume, and update voxels based on correction images for back-projection [S1]. Forward projection involves casting a ray from each pixel, sampling the volume at equidistant points, and retrieving volume values via tri-linear interpolation [S1]. The correction term is computed as $(I(p_i) - \text{sample\_rate} \times \sum_{s=1}^S v_{sk}) / \text{ray\_length}$, where $I(p_i)$ is the measured line integral, $S$ is the number of samples, $\text{sample\_rate}$ is the distance between samples, $v_{sk}$ is the volume estimate at sample $s$, and $\text{ray\_length}$ is the ray-volume intersection length [S1]. Back-projection involves casting a ray from each voxel to the detector, retrieving a correction value via bi-linear interpolation, and updating the voxel [S1]. In this way, the forward projection and backward projection are not exact [S1].

## Background
The voxel splatting implementation of SART/SIRT was developed as part of a framework for GPU-accelerated 3D tomographic reconstruction and visualization from noisy electron microscopy tilt-series [S1]. It was introduced to address the computational demands of cryo-electron tomography (cryo-ET), where large volumes and parallel ray geometry allow for efficient parallelization [S1]. The method builds on the concept of voxel splatting, where voxels are projected onto the detector plane using pre-integrated lookup tables for weights, which are computed by line integrals of rays traversing radially symmetric filter kernels [S1].
