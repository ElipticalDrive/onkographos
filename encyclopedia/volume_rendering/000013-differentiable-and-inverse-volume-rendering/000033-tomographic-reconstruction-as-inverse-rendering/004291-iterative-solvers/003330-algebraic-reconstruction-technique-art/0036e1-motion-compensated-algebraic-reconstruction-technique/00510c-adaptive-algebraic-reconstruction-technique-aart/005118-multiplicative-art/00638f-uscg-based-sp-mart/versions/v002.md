# USCG-based Sp-MART

Also called: USCG Sp-MART, Uniformly Sampled Cylindrical Grid Sp-MART

## Overview
USCG-based Sp-MART is a tomographic reconstruction method that reduces the space and time complexity of algebraic reconstruction techniques by discretizing the image domain using a Uniformly Sampled Cylindrical Grid (USCG) [S1]. It solves the radial deterioration of resolution found in conventional polar grid methods while accelerating line tracing by leveraging rotational symmetry and on-the-fly coefficient calculation [S1]. Compared to Cartesian grid-based methods, it enhances overall reconstruction speed by a factor of 2.5, and unlike the Feldkamp-Davis-Kress (FDK) algorithm, it produces high-quality images with a significantly limited number of projections and detectors, making it suitable for low-cost CT setups [S1].

## How it works
**Inputs:**
* $p$: Number of projection views [S1].
* $d$: Number of detectors per projection [S1].
* $\theta_k$: Source angle for the $k$-th projection view ($k = 0, \dots, p-1$) [S1].
* $P_k$: The $k$-th projection data vector of size $d$ [S1].
* $V$: Initial volume estimate [G].

**Outputs:**
* $V$: Reconstructed volume [G].

**Data Structures:**
The USCG discretization organizes voxels into slices, rings, and angular sectors [S1].
* **Slice ($s$):** Index along the z-axis [S1].
* **Ring ($r$):** Radial index from the center [S1].
* **Angle ($\alpha$):** Angular position within the ring [S1].
* **Line Segment Attributes:** For each line segment in the first projection, store the slice number ($s$), ring number ($r$), and initial angular position ($\alpha_0$) [S1]. Intersection points with the grid boundaries are calculated only for one-fourth of the lines, with the remaining points derived via mirroring [S1].

**Parameters:**
* Typical experimental setups use 50–70 projections and 10,000–40,000 detectors [S1].
* X-ray voltages range from 110 to 120 KeV [S1].
* X-ray tube currents range from 105 to 110 microamperes [S1].

**Algorithm Steps:**
1. **Initialize Volume:** Set all voxel values in $V$ to zero or a background value [G].
2. **First Projection Tracing ($k=0$):** Identify the lines corresponding to the first projection view [S1]. Due to symmetry, calculate intersection points and grid attributes ($s, r, \alpha_0$) for only one-fourth of the total lines [S1]. Generate the remaining lines by mirroring the calculated intersection points [S1]. Store the slice number ($s$), ring number ($r$), and initial angular position ($\alpha_0$) for each line segment [S1]. Perform time-consuming steps (intersection calculation, array sorting, rounding, angular position finding) only for this projection [S1].
3. **Iterative Update (Sp-MART):** For each iteration and each projection view $k = 0, \dots, p-1$:
    * **Trace Line for Projection $k$:** Retrieve the stored $s$ and $r$ for the line segment [S1]. Calculate the current angular position $\alpha_k$ using rotational symmetry:
      $$ \alpha_k = \alpha_0 + \theta_k $$
      where $\theta_k$ is the source angle of the $k$-th projection [S1]. The slice number $s$ and ring number $r$ remain unchanged from the first projection [S1].
    * **Calculate Line Coefficients On-the-Fly:** Compute the path length $L$ of the line segment through the voxel defined by $(s, r, \alpha_k)$ [S1]. Compute the projection coefficient $a_{ij}$ (weight of voxel $j$ in projection $i$) based on the intersection geometry [S1]. Since coefficients are calculated on the fly, no storage is required for the system matrix [S1].
    * **Forward Projection:** Compute the estimated projection value $\hat{p}_i$ for detector $i$:
      $$ \hat{p}_i = \sum_{j \in \text{voxels}} a_{ij} V_j $$
    * **Backprojection and Multiplicative Update:** Compute the ratio of measured to estimated projection:
      $$ R_i = \frac{p_i}{\hat{p}_i} $$
      Update the voxel values $V_j$ using the multiplicative ART rule:
      $$ V_j^{\text{new}} = V_j^{\text{old}} \times \frac{\sum_{i \in \text{detectors}} a_{ij} R_i}{\sum_{i \in \text{detectors}} a_{ij}} $$
      The normalization denominator ensures stability, consistent with standard MART formulations [G].
4. **Termination:** Repeat step 3 until convergence or a fixed number of iterations is reached [G].

**Pseudocode:**
```python
def uscg_sp_mart(projections, source_angles, num_slices, num_rings, num_angles, max_iter):
    # Initialize volume to zero or a background value [G]
    V = zeros((num_slices, num_rings, num_angles))
    # Trace first projection view [S1]
    first_proj_lines = []
    for i in range(num_detectors // 4):
        s, r, alpha_0 = compute_line_attributes(i)
        first_proj_lines.append((s, r, alpha_0))
    # Mirror points for the remaining three-fourths [S1]
    full_lines = first_proj_lines + mirror_points(first_proj_lines)
    for iteration in range(max_iter):
        for k in range(p):
            theta_k = source_angles[k]
            for s, r, alpha_0 in full_lines:
                # Update angular position using rotational symmetry [S1]
                alpha_k = alpha_0 + theta_k
                # Compute projection coefficient on the fly [S1]
                a_ij = compute_coefficient(s, r, alpha_k)
                # Forward projection [G]
                p_hat = sum(a_ij * V[s, r, alpha_k] for all voxels)
                # Backprojection and multiplicative update [G]
                ratio = projections[k] / p_hat
                V[s, r, alpha_k] *= sum(a_ij * ratio) / sum(a_ij)
```

**Edge Cases and Pitfalls:**
* **Grid Symmetry Requirement:** The method relies on the USCG grid's rotational symmetry for the mirror-image optimization [S1]. If the grid is not uniformly sampled, the one-fourth calculation may introduce artifacts [S1].
* **Precision:** Rounding numbers during the initial trace of the first projection must be handled carefully to avoid accumulation errors in subsequent projections [S1].
* **Degenerate Input:** Lines passing exactly through grid boundaries or the center axis require special handling for intersection calculations [S1].

## Operating characteristics
* **Time Complexity:** Line tracing speed is enhanced by $O(N)$ compared to traditional polar grid methods because it avoids finding intersections with radial planes [S1]. The line tracing process is accelerated by $O(p)$ where $p$ is the number of projection views, as time-consuming steps are executed only for the first projection [S1]. Overall reconstruction speed is enhanced by a factor of 2.5 compared to Cartesian grid-based methods [S1].
* **Memory Complexity:** Storage requirement is reduced by a factor of $p$ because projection coefficients are calculated on the fly and not stored [S1]. Only the slice, ring, and angle for the first projection need to be stored [S1].
* **Performance:** Cu-Lump reconstruction (50 projections, 10,000 detectors) yields MAE 0.0011, RMSE 0.0037, and SSIM 0.9909 [S1]. Frog reconstruction (70 projections, 40,000 detectors) yields MAE 0.0019, RMSE 0.0052, and SSIM 0.9626 [S1]. FDK requires 400 projections and over 1 million detectors to generate comparable quality images [S1].
* **Strengths:** The method is ideal for low-cost CT setups with limited projections and detectors [S1]. It solves the radial deterioration of resolution inherent in conventional polar grids [S1].
* **Limitations:** The approach relies on specific grid symmetries and is less flexible for arbitrary Cartesian or non-uniform sampling without modification [S1].

## Background
The method was proposed to address the limitations of algebraic reconstruction techniques, specifically the high computational cost and memory usage associated with large system matrices in traditional polar or Cartesian grids [S1]. It builds on [Multiplicative ART](14391-multiplicative-art.md), which uses multiplicative updates for stability and positivity preservation [G]. The USCG discretization scheme was introduced to solve the radial resolution deterioration found in conventional polar grid methods [S1]. Experimental validation was performed on a Copper Lump and a Frog specimen using X-ray voltages of 120 KeV and 110 KeV, respectively [S1].
