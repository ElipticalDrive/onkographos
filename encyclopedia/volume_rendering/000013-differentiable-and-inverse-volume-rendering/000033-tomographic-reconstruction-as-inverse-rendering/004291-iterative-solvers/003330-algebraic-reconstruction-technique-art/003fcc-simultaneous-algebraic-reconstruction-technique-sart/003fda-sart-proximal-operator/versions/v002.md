# SART Proximal Operator

Also called: Modified SART, SART with Proximal Term

## Overview
The SART Proximal Operator is an iterative tomographic reconstruction method that extends the Simultaneous Algebraic Reconstruction Technique (SART) by incorporating a proximal term to enforce prior information or regularization [S1, unofficial]. It solves the linear system $Ax = p$ while minimizing the distance to an input estimate $u$, effectively finding the least-squares solution closest to $u$ [S1, unofficial]. Unlike standard SART, which initializes the volume to zero, this method maintains an auxiliary variable $y$ to handle the data fidelity term relative to the prior, allowing for the inclusion of prior knowledge directly in the iteration loop [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Forward projection matrix $A \in \mathbb{R}^{m \times n}$, projection measurements $p \in \mathbb{R}^m$, input volume estimate (prior) $u \in \mathbb{R}^n$, regularization parameter $\lambda \in \mathbb{R}$, step size $\alpha \in \mathbb{R}$, and number of iterations $T$ [S1, unofficial].
*   **Outputs:** Reconstructed volume $x \in \mathbb{R}^n$ [S1, unofficial].

**Data Structures:**
*   $x$: Volume reconstruction array of size $n$ (number of voxels) [S1, unofficial].
*   $y$: Auxiliary variable array of size $m$ (number of projection pixels/lines) [S1, unofficial].
*   $A$: Forward projection operator matrix [S1, unofficial].
*   $p$: Projection measurements vector [S1, unofficial].

**Parameters:**
*   $\lambda$: Regularization parameter used in the scaling of the projection matrix and projections [S1, unofficial].
*   $\alpha$: Step size (relaxation parameter) [S1, unofficial].
*   $u$: Input volume estimate or prior used to initialize $x$ and modify the data term [S1, unofficial].

**Algorithm Steps:**
1.  **Preprocessing:** Scale the projection measurements and the matrix by $\sqrt{2\lambda}$ [S1, unofficial].
    $$ \tilde{p} = \sqrt{2\lambda} p $$
    $$ \tilde{A} = \sqrt{2\lambda} A $$
    *Note: The source applies this scaling in-place and subsequently refers to the scaled variables simply as $p$ and $A$ in the update formulas [S1, unofficial].*
2.  **Initialization:** Set the auxiliary variable to zero and initialize the volume with the prior [S1, unofficial].
    $$ y^{(0)} = 0 $$
    $$ x^{(0)} = u $$
3.  **Iteration:** For $t = 1$ to $T$:
    a. **Subset Loop:** Iterate over all projection subsets $S$ [S1, unofficial].
    b. **Residual Calculation:** For each projection $i \in S$, compute the residual term $c_i^{(t)}$ [S1, unofficial].
       $$ c_i^{(t)} = \frac{p_i - \sum_{k=1}^{n} a_{ik} x_k^{(t)} - y_i^{(t)}}{\sum_{k=1}^{n} a_{ik} + 1} $$
       Here, $a_{ik}$ is the element of matrix $A$ at row $i$ and column $k$ [S1, unofficial]. The term $\sum_{k=1}^{n} a_{ik}$ is the sum of the $i$-th row of $A$ [S1, unofficial].
    c. **Update Auxiliary Variable $y$:** For each $j \in S$ (where $j$ corresponds to the projection pixel index $i$), update $y$ [S1, unofficial].
       $$ y_j^{(t+1)} = y_j^{(t)} + \alpha c_j^{(t)} $$
       Only one element of $y$ is updated per projection pixel in the subset [S1, unofficial].
    d. **Update Volume $x$:** For all voxels $j = 1$ to $n$, update $x$ [S1, unofficial].
       $$ x_j^{(t+1)} = x_j^{(t)} + \alpha \frac{\sum_{i \in S} c_i^{(t)} a_{ij}}{\sum_{i \in S} a_{ij}} $$
       Here, $\sum_{i \in S} a_{ij}$ is the sum of the elements in column $j$ of $A$ restricted to the rows in subset $S$ [S1, unofficial].
4.  **Return:** $x^{(T)}$ [S1, unofficial].

**Pseudocode:**
```python
def sart_proximal_operator(A, p, u, lambda_reg, alpha, T, subsets):
    """
    A: Forward projection matrix (m x n)
    p: Projection measurements (m,)
    u: Prior volume estimate (n,)
    lambda_reg: Regularization parameter lambda
    alpha: Step size
    T: Number of outer iterations
    subsets: List of projection subsets, each containing indices of projections
    """
    import numpy as np

    # Preprocessing: Scale p and A by sqrt(2*lambda)
    scale = np.sqrt(2 * lambda_reg)
    p = scale * p
    A = scale * A
    
    # Initialization
    y = np.zeros(len(p))
    x = np.array(u, dtype=float).copy()
    
    # Precompute row sums of A for the residual denominator
    row_sums = np.sum(A, axis=1)
    
    for t in range(1, T + 1):
        for S in subsets:
            # Compute residuals c_i for i in S
            # c_i = (p_i - sum_k a_ik x_k - y_i) / (sum_k a_ik + 1)
            forward_proj = A[S, :] @ x
            numerators = p[S] - forward_proj - y[S]
            denominators = row_sums[S] + 1
            c = numerators / denominators
            
            # Update y for j in S
            y[S] += alpha * c
            
            # Update x for all j
            # Compute sum_{i in S} a_ij for each j (column sums for subset S)
            col_sums_S = np.sum(A[S, :], axis=0)
            
            # Compute sum_{i in S} c_i * a_ij for each j
            weighted_col_sums = A[S, :].T @ c
            
            # Guard against division by zero if a voxel is not intersected by any ray in S [G]
            safe_col_sums = np.where(col_sums_S > 0, col_sums_S, 1.0)
            x += alpha * (weighted_col_sums / safe_col_sums)
            
    return x
```

**Edge Cases and Pitfalls:**
*   **Memory Usage:** The method requires storing the volume $x$ and the auxiliary variable $y$ [S1, unofficial]. For a $256^3$ volume (64 MB) and 360 projections of $2000 \times 1500$ pixels ($\approx 4$ GB for $y$), total memory can exceed 12 GB if multiple versions are kept in RAM [S1, unofficial].
*   **Division by Zero:** The denominators $\sum_k a_{ik} + 1$ and $\sum_{i \in S} a_{ij}$ must be non-zero [S1, unofficial]. The $+1$ in the residual denominator ensures the first is never zero [S1, unofficial]. The column sum denominator should be checked for zero if a voxel is not intersected by any ray in the subset [G].

## Operating characteristics
*   **Memory Complexity:** The method requires $O(n + m)$ memory for storing $x$ and $y$ [S1, unofficial]. This is significantly higher than standard SART, which only requires $O(n)$ [S1, unofficial].
*   **Strengths:** Incorporates prior information $u$ effectively and modifies the data term to find the least-squares solution closest to $u$ [S1, unofficial].
*   **Limitations:** High memory consumption due to the auxiliary variable $y$ [S1, unofficial].
*   **When to Use:** When prior information is available and regularization is needed [S1, unofficial]. When memory resources are sufficient to store the auxiliary variable [S1, unofficial].

## Background
The SART Proximal Operator was introduced in the context of industrial computed tomography to improve reconstruction quality by incorporating prior knowledge [S1, unofficial]. It is based on the proximal algorithm framework, which allows for the minimization of a function involving a data fidelity term and a regularization term [S1, unofficial]. The method modifies the standard SART algorithm by introducing an auxiliary variable $y$ and initializing the volume with a prior estimate $u$ [S1, unofficial].
