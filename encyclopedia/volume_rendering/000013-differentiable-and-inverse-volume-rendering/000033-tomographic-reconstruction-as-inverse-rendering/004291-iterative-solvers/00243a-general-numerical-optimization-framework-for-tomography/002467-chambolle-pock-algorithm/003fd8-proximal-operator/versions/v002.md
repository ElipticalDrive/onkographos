# Proximal Operator
Also called: Prox, Proximal Mapping
## Overview
The proximal operator is a mathematical tool used in proximal algorithms to solve non-smooth, constrained, or large-scale optimization problems by iteratively getting closer to the optimal solution while staying close to the current estimate [S1, unofficial]. It serves as a generalization of projections onto convex sets, allowing complex optimization problems to be split into smaller, simpler sub-problems [S1, unofficial]. In tomographic reconstruction, it enables the handling of regularization terms such as smoothing norms or sparsity-inducing norms, which often admit closed-form solutions [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A vector $u \in \mathbb{R}^n$ (the current estimate), a scalar $\lambda > 0$ (regularization parameter), and a function $h(\cdot)$ [S1, unofficial].
- Output: A vector $x \in \mathbb{R}^n$ that minimizes the composite objective [S1, unofficial].

**Data Structures:**
- The input $u$ and output $x$ are dense vectors or grids (e.g., voxel arrays in tomography) [G].
- The function $h$ is defined analytically [S1, unofficial].

**Formula:**
The proximal operator of $h$ at $u$ with parameter $\lambda$ is defined as:
$$ \text{prox}_{\lambda h}(u) = \operatorname{argmin}_x \left( h(x) + \frac{1}{2\lambda} \|x - u\|_2^2 \right) $$
where $x$ is the variable to optimize, $u$ is the current estimate, and $\lambda$ controls the trade-off between minimizing $h(x)$ and staying close to $u$ [S1, unofficial]. The term $\| \cdot \|_2$ denotes the Euclidean norm [S1, unofficial].

**Algorithm Steps:**
1. Construct the composite objective function $J(x) = h(x) + \frac{1}{2\lambda} \|x - u\|_2^2$ for the given $u$ and $\lambda$ [S1, unofficial].
2. Solve for $x$ that minimizes $J(x)$ [S1, unofficial].
3. Return the resulting $x$ as $\text{prox}_{\lambda h}(u)$ [S1, unofficial].
Many proximal operators admit a closed-form solution, which is computed directly rather than via iterative minimization [S1, unofficial].

**Pseudocode (L1 Norm Example):**
The L1 norm proximal operator applies soft thresholding element-wise [S1, unofficial].
```python
def prox_l1(u, lam):
    result = []
    for val in u:
        if val >= lam:
            result.append(val - lam)
        elif val <= -lam:
            result.append(val + lam)
        else:
            result.append(0.0)
    return result
```
For general $h$, the argmin is solved via closed-form expressions when available, or via an inner optimization solver [G].

**Parameters:**
- $\lambda$: Regularization parameter controlling the trade-off between $h(x)$ and the distance to $u$ [S1, unofficial].

## Subtopics

### L1 Norm Proximal Operator
The proximal operator for the L1 norm, used for sparsity regularization [S1, unofficial]. It applies soft thresholding to the input vector [S1, unofficial]. It is chosen when the solution is expected to be sparse [S1, unofficial].
**Formula:**
$$ \text{prox}_{\lambda g}(u) = (u - \lambda)_+ - (-u - \lambda)_+ $$
where $(u)_+ = \max(u, 0)$ is the positive part of $u$ [S1, unofficial].
**Element-wise:**
$$ (\text{prox}_{\lambda g}(u))_i = \begin{cases} u_i - \lambda & \text{if } u_i \geq \lambda \\ 0 & \text{if } |u_i| \leq \lambda \\ u_i + \lambda & \text{if } u_i \leq -\lambda \end{cases} $$
where $(\text{prox}_{\lambda g}(u))_i$ is the $i$-th element of the output [S1, unofficial].

### Anisotropic Total Variation (ATV) Prior
A regularization prior defined as $h(x) = \sum_{i,j,k} |x_{i+1,j,k} - x_{i,j,k}| + |x_{i,j+1,k} - x_{i,j,k}| + |x_{i,j,k+1} - x_{i,j,k}|$, where $x_{i,j,k}$ is the voxel value [S1, unofficial]. It can be represented as $g(Dx)$ where $D$ is the forward difference matrix [S1, unofficial]. The proximal operator for ATV does not have a simple closed-form element-wise solution and typically requires iterative methods or splitting techniques (like Chambolle-Pock) to solve [S1, unofficial]. It is chosen when piecewise constant solutions with sharp edges are desired [S1, unofficial].

## Operating characteristics
- **Time and memory complexity:** Not given in the sources.
- **Strengths:** Modular; allows handling of non-smooth regularization terms. Often admits closed-form solutions for common norms [S1, unofficial].
- **Limitations:** Requires convexity for well-definedness. For complex priors (like Total Variation), the proximal operator may not have a closed form, requiring nested optimization [G].
- **When to use:** When the optimization problem involves non-smooth regularization terms (sparsity, total variation) that are difficult to handle with standard gradient descent [G].
- **When not to use:** When the function $h$ is smooth and strongly convex, standard gradient-based methods may be simpler and faster [G].

## Background
The proximal operator was introduced as a generalization of projections onto convex sets [S1, unofficial]. It has been widely used in optimization theory and applied to various fields, including image processing and tomography [S1, unofficial]. In industrial computed tomography, proximal algorithms utilizing these operators are employed for reconstruction [S1, unofficial]. The method builds on the Chambolle-Pock algorithm, which splits the optimization problem into sub-problems solvable via proximal operators [3282-chambolle-pock-algorithm.md].
