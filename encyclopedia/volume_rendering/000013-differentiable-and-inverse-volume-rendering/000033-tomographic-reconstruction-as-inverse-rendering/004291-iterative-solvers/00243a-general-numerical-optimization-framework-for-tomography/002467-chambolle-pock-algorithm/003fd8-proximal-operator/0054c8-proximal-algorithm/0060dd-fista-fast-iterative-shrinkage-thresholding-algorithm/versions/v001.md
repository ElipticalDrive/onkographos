# FISTA (Fast Iterative Shrinkage-Thresholding Algorithm)
Also called: Fast Iterative Shrinkage-Thresholding Algorithm

## Overview
FISTA is an iterative optimization algorithm for solving inverse problems, specifically designed to accelerate convergence by combining gradient descent with Nesterov’s momentum acceleration [S1, unofficial]. It handles constraints and non-smooth regularization (such as L1 norms) via proximal operators or projection, making it suitable for tomographic reconstruction where sparsity or bounded support is required [S1, unofficial]. It distinguishes itself from standard gradient descent by achieving an $O(1/k^2)$ convergence rate for convex objectives, compared to $O(1/k)$, through the use of an extrapolated search point [S1, unofficial].

## How it works
**Inputs:**
- `projections`: Array of measured projection data $y$.
- `volume`: Initial guess of the reconstruction volume $v_0$.
- `volume_old`: Previous iteration volume (used for momentum).
- `volume_t`: Extrapolated volume used for gradient computation.
- `volume_tv`: Temporary array for total variation or L1 updates.
- `geometry`: Forward/backward projection operator definitions (matrix $A$ and $A^*$).
- `lmbda` ($\lambda$): Regularization parameter.
- `bounds`: Optional tuple $(b_{min}, b_{max})$ for box constraints.
- `subsets`: Number of data subsets used for gradient estimation.
- `iterations`: Number of optimization steps.

**Outputs:**
- `volume`: The reconstructed volume array.
- `rnorms`: List of residual norms recorded at each iteration.

**Data Structures:**
- `volume`, `volume_old`, `volume_t`, `volume_tv`: Float32 arrays. `volume_tv` shape is `[3, vrt, mag, hrz]` (representing gradients in 3 dimensions) [S1, unofficial].
- `t`: Scalar momentum parameter.
- `L`: Lipschitz constant of the gradient.

**Algorithm Steps:**

1.  **Initialization:**
    - Copy `volume` to `volume_t` and `volume_old`.
    - Initialize `volume_tv` as a zero-filled float32 array with shape `[3, vrt, mag, hrz]` [S1, unofficial].
    - Initialize momentum parameter $t = 1$.
    - Initialize `rnorms` as an empty list.

2.  **Iteration Loop** (for $ii$ in range `iterations`):
    - **Compute Gradient Term:**
      Calculate the gradient of the data fidelity term. In the source implementation, this is computed as $A^*(A(v_t) - y)$ using `l2_update` [S1, unofficial].
      Let $g = A^*(A(v_t) - y)$.
      Compute the norm of this gradient: `norm = ||g||` [S1, unofficial].
      Append `norm` to `rnorms` if `norm` is truthy [S1, unofficial].

    - **Update Lipschitz Constant:**
      Compute $L = 1 / \text{subsets}$ [S1, unofficial].

    - **Apply Regularization/Constraints:**
      If $\lambda > 0$:
      Apply the proximal operator for the regularization term (e.g., L1 or Total Variation). The source calls `l1_update` on `volume_tv`, `volume_t`, `volume`, $L$, and $\lambda$ [S1, unofficial].
      *Note: The source notes indicate that TV minimization substeps are not implemented in this specific version, implying `l1_update` may handle L1 sparsity or a simplified variant [S1, unofficial].*
      
      Else if `bounds` are defined:
      Clip `volume_t` in-place between `bounds[0]` and `bounds[1]` [S1, unofficial].
      
      Else:
      Assign `volume[:] = volume_t` [S1, unofficial].

    - **Momentum Update (Nesterov Acceleration):**
      Save old momentum: $t_{old} = t$.
      Update momentum parameter:
      $$ t = \frac{1 + \sqrt{1 + 4 t^2}}{2} $$
      Update the extrapolated variable `volume_t` for the next iteration's gradient calculation:
      $$ v_t = v + \frac{t_{old} - 1}{t} (v - v_{old}) $$
      where $v$ is the current `volume` and $v_{old}$ is `volume_old` [S1, unofficial].

    - **State Update:**
      Update `volume_old` to the current `volume` before the next loop iteration begins (implicit in the source logic where `volume` is updated via clipping/assignment and `volume_old` is used in the extrapolation step). *Note: The source pseudocode explicitly updates `volume_t` using `vol` and `vol_old`, then the loop continues. The standard FISTA update requires $x_{k+1}$ to be computed from the proximal step, then $x_{k+1}^{extrap}$ for the next gradient. The source code structure suggests `vol` holds the proximal result, and `vol_t` is the extrapolated point for the next gradient.*

**Edge Cases and Pitfalls:**
- **Precision:** The momentum parameter $t$ involves a square root. Ensure floating-point precision is sufficient to avoid stagnation if $t$ becomes very large or small.
- **Bounds:** If bounds are set, clipping is performed *after* the gradient step but *before* the momentum extrapolation in the source logic? No, the source says: "If bounds are set, clip the volume array...". The order in the loop is: Gradient -> Update Norm -> Clip/Proximal -> Momentum. This is consistent with standard FISTA where the proximal step yields $x_{k+1}$, which is then used for extrapolation.
- **Subsets:** The Lipschitz constant $L$ is inversely proportional to the number of subsets. Using subsets accelerates convergence but may introduce noise if not handled correctly.
- **TV Implementation:** The source explicitly notes that TV minimization substeps are not implemented in this version. Users relying on TV regularization should be aware that only L1 or basic constraints may be active [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Each iteration involves forward and adjoint projections, which are typically $O(N \log N)$ or $O(N)$ depending on the geometry and interpolation method, plus the proximal operator cost. The momentum update is $O(N)$. Total per iteration is dominated by projections.
- **Memory Complexity:** $O(N)$ for the volume, plus auxiliary arrays for gradients and temporary storage. The source uses `volume_tv` of shape `[3, vrt, mag, hrz]`, adding a constant factor overhead [S1, unofficial].
- **Performance:** FISTA converges faster than standard gradient descent for convex problems, with a theoretical rate of $O(1/k^2)$ [S1, unofficial].
- **Strengths:** Handles non-smooth regularization (L1) efficiently via proximal operators. Momentum acceleration improves convergence speed. Supports subsets for large datasets.
- **Limitations:** Requires tuning of the regularization parameter $\lambda$ and Lipschitz constant $L$ (or subsets). TV implementation may be missing or simplified in some versions. Convergence is not guaranteed for non-convex problems, though it is often used heuristically.
- **When to Use:** Sparse reconstruction, compressed sensing tomography, or when bounded support is known.
- **When Not to Use:** When smoothness is preferred (use Tikhonov/LSQR), or when real-time performance is critical and the overhead of iterative methods is prohibitive.

## Background
FISTA was introduced by Amir Beck and Marc Teboulle in 2009 as a fast version of the Iterative Shrinkage-Thresholding Algorithm (ISTA) [S1, unofficial]. It is widely used in signal processing and inverse problems, including tomographic reconstruction, where sparsity is a key prior. The implementation described here is from the `flexTOMO` project, an unofficial tool for flexible tomographic reconstruction [S1, unofficial].
