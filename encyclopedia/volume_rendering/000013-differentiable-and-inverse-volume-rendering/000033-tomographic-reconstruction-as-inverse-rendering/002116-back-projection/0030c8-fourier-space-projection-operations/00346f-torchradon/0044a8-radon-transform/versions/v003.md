# Radon Transform
Also called: Discrete Radon Transform, Forward Radon Transform, Parallel-Beam Radon Transform, Sinogram Generation, Transformée de Radon, Transformée de Radon discrète

## Overview
The Radon transform maps a 2D continuous or discrete function $f(x,y)$ into a set of 1D projections $R_\theta(\rho)$ by integrating the function along parallel lines defined by an angle $\theta$ and a radial offset $\rho$ [S2, S3, unofficial]. In digital imaging, it generates a **sinogram**, which is the fundamental input for tomographic reconstruction algorithms like Filtered Back-Projection [S3, unofficial]. It differs from its sibling [Filtered Back-Projection](11308-filtered-back-projection-fbp.md) by being the forward acquisition model (image to sinogram) rather than the inverse reconstruction model (sinogram to image).

## How it works
### Inputs and Outputs
*   **Input:** A 2D image $I$ of size $H \times W$ (height $\times$ width), where $I(i,j)$ is the intensity at pixel coordinates $(i,j)$.
*   **Input:** An array of projection angles $\Theta = \{\theta_0, \dots, \theta_{N-1}\}$ in radians, typically spanning $[0, \pi)$ [S2, S3, unofficial].
*   **Input:** A set of detector positions (radial offsets) $\rho$, typically linearly spaced to cover the image diagonal [S1, S3, unofficial].
*   **Output:** A sinogram matrix $P$ of size $N_\rho \times N_\theta$, where $P(k, m) = R_{\theta_m}(\rho_k)$ [S1, S3, unofficial].

### Data Structures
*   **Image $I$:** 2D array, indices $i \in [0, H-1]$ (row/y), $j \in [0, W-1]$ (col/x).
*   **Angles $\Theta$:** 1D array of floats, length $N_\theta$.
*   **Detectors $\rho$:** 1D array of floats, length $N_\rho$.
*   **Sinogram $P$:** 2D array, rows correspond to detector indices, columns to angle indices.

### Mathematical Definition
The continuous Radon transform is defined as the line integral of the function $f(x,y)$ along a line $L$ parameterized by $\theta$ and $\rho$ [S2, unofficial]:

$$
R_\theta(\rho) = \int_{-\infty}^{\infty} \int_{-\infty}^{\infty} f(x,y) \delta(\rho - x \cos \theta - y \sin \theta) \, dx \, dy
$$

where $\delta(\cdot)$ is the Dirac delta function [S2, unofficial].

For a discrete image $I(i,j)$, the function is modeled as a sum of discrete Dirac impulses [S2, unofficial]:

$$
f(x,y) = \sum_{i=-\infty}^{\infty} \sum_{j=-\infty}^{\infty} I(i,j) \Delta(x - j) \Delta(y - i)
$$

where $\Delta(\cdot)$ is the discrete Dirac impulse (1 if argument is 0, 0 otherwise) [S2, unofficial]. Substituting this into the continuous definition yields the discrete Radon transform [S2, unofficial]:

$$
R_\theta(\rho) = \sum_{i=0}^{H-1} \sum_{j=0}^{W-1} I(i,j) \Delta(\rho - j \cos \theta - i \sin \theta)
$$

In practice, $\Delta(\rho - j \cos \theta - i \sin \theta)$ is non-zero only if the line passes through the pixel $(i,j)$. Since pixels have finite area, this is often approximated by summing pixel values weighted by the intersection area or using interpolation (e.g., nearest-neighbor or linear) to map pixel centers to the projection grid [S2, S3, unofficial].

### Parameters
*   **Angles ($\theta$):** Typically $N_\theta = \max(H, W)$ angles spaced evenly in $[0, 180^\circ)$ [S3, unofficial].
*   **Detectors ($\rho$):** Linearly spaced positions covering the image extent. Commonly from $-R$ to $R$ where $R$ is the image radius, with $N_\rho = \max(H, W)$ [S1, S3, unofficial].
*   **Detector Spacing ($dr$):** The distance between adjacent detector positions, used for numerical integration scaling [S1, unofficial].

### Algorithm Steps
1.  **Initialize:** Create an empty sinogram matrix $P$ of shape $(N_\rho, N_\theta)$.
2.  **Loop over angles:** For each angle $\theta_m$ in $\Theta$:
    a.  **Rotate Image:** Rotate the image $I$ by $-\theta_m$ (or equivalently, rotate the coordinate system) so that the projection direction aligns with one of the image axes. Alternatively, compute the projection geometry directly using rotation matrices [S1, S3, unofficial].
    b.  **Project:** Sum the pixel values along the axis perpendicular to the projection direction. If rotating the image, sum along rows (axis 0) to get a 1D projection profile $p_m$ of length $N_\rho$ [S1, unofficial].
    c.  **Scale:** Multiply the projection profile by the detector spacing $dr$ to approximate the integral [S1, unofficial].
    d.  **Store:** Assign $p_m$ to the $m$-th column of $P$.
3.  **Transpose:** Depending on convention, the sinogram may be stored as $(N_\rho, N_\theta)$ or $(N_\theta, N_\rho)$. Standard convention (e.g., scikit-image) is $(N_\rho, N_\theta)$ [S1, S3, unofficial].

### Pseudocode
```python
import numpy as np
from scipy.ndimage import rotate

def radon_transform(image, angles_deg, num_detectors=None):
    """
    Compute the discrete Radon transform (sinogram) of a 2D image.
    
    Args:
        image: 2D numpy array (H, W).
        angles_deg: 1D array of angles in degrees, typically 0 to 180.
        num_detectors: Number of detector bins. Defaults to max(image.shape).
        
    Returns:
        sinogram: 2D numpy array (num_detectors, len(angles_deg)).
    """
    H, W = image.shape
    if num_detectors is None:
        num_detectors = max(H, W)
        
    # Define detector positions linearly spaced from -R to R
    # R is the radius of the image (half diagonal)
    R = np.sqrt((H/2)**2 + (W/2)**2)
    rs = np.linspace(-R, R, num_detectors)
    dr = rs[1] - rs[0] if len(rs) > 1 else 1.0
    
    N_angles = len(angles_deg)
    sinogram = np.zeros((num_detectors, N_angles))
    
    for m, theta_deg in enumerate(angles_deg):
        theta_rad = np.deg2rad(theta_deg)
        
        # Rotate the image to align the projection direction with the vertical axis.
        # The angle for rotation is -theta_rad to project along the direction theta_rad.
        # mode='constant' with cval=0 handles boundaries.
        rotated = rotate(image, -theta_deg, reshape=False, order=1, mode='constant', cval=0.0)
        
        # Sum along the vertical axis (axis 0) to get the projection profile
        # This corresponds to integrating along lines of constant x' in the rotated frame
        projection = np.sum(rotated, axis=0)
        
        # Scale by detector spacing to approximate the integral
        projection *= dr
        
        # Store in sinogram. 
        # Note: The projection profile length is W (or H depending on reshape=False behavior).
        # We must map this to the detector grid rs.
        # In a simple implementation using reshape=False, the projection is along the original width.
        # For a rigorous implementation, interpolation onto the rs grid is required.
        # Here we assume a simplified case where the projection length matches num_detectors
        # or we interpolate.
        
        # Interpolate projection onto the detector grid rs
        # The projection array corresponds to positions along the rotated x-axis.
        # We need to map the pixel coordinates to the rs positions.
        # This step is complex in pure Python without libraries; 
        # standard libraries (skimage) handle this via ray-driven or distance-driven methods.
        # For this pseudocode, we assume the projection array is already aligned 
        # or we use a simple nearest-neighbor assignment for demonstration.
        
        # Simplified assignment: assume projection length matches num_detectors
        if len(projection) == num_detectors:
            sinogram[:, m] = projection
        else:
            # Fallback: interpolate
            # The projection values are at positions corresponding to the rotated image width.
            # This is a simplification; real implementations use geometry matrices.
            pass 
            
    return sinogram
```
[G] The pseudocode above is a high-level approximation. Production implementations (like `skimage.transform.radon`) use distance-driven or ray-driven methods to accurately map pixel contributions to detector bins, handling sub-pixel geometry and interpolation. The `rotate` method is computationally expensive and introduces interpolation artifacts.

### Edge Cases and Pitfalls
*   **Boundary Effects:** Pixels at the image edge contribute partially to projections. Using `reshape=False` in rotation avoids resampling artifacts but may leave gaps. Proper handling requires accounting for the exact intersection area of rays with pixels [S2, unofficial].
*   **Aliasing:** If the number of angles $N_\theta$ is too small relative to the image frequency content, reconstruction artifacts occur. The Nyquist criterion for angular sampling suggests $N_\theta \ge \pi N_\rho / 2$ [S2, S3, unofficial].
*   **Precision:** Floating-point errors in rotation and summation can accumulate. Using double precision is recommended [S1, unofficial].

## Subtopics

### [Filtered Back-Projection (FBP)](11308-filtered-back-projection-fbp.md)
The inverse method that reconstructs the image from the sinogram. It applies a high-pass filter to the projections to correct for the $1/|\omega|$ blurring inherent in simple back-projection. Choose FBP when speed is critical and noise levels are moderate.

## Operating characteristics
*   **Time Complexity:** $O(N_\theta \cdot N_\rho \cdot \log(\max(H,W)))$ if using FFT-based methods, or $O(N_\theta \cdot N_\rho \cdot N_{pixels})$ for direct ray-tracing. The rotation-based approach is $O(N_\theta \cdot H \cdot W \cdot \log(HW))$ due to FFT rotation [S1, S3, unofficial].
*   **Memory Complexity:** $O(N_\rho \cdot N_\theta)$ for the sinogram storage.
*   **Strengths:** Mathematically well-defined; direct link to Fourier Slice Theorem; standard input for FBP [S2, S3, unofficial].
*   **Limitations:** Sensitive to noise; requires many projections for high-quality reconstruction; artifacts from limited angles or missing data [S2, unofficial].
*   **When to use:** As the forward model in differentiable tomography [S1, S2, unofficial] or as a preprocessing step for FBP [S3, unofficial].
*   **When not to use:** For real-time applications with very few projections; iterative methods (e.g., SIRT) may be better for sparse data.

## Background
The Radon transform was introduced by Johann Radon in 1917 [S2, unofficial]. It forms the mathematical foundation of computed tomography (CT). The discrete implementation is widely used in medical imaging, materials science, and computer vision. The `skimage.transform.radon` function provides a standard implementation in Python [S3, unofficial]. The TorchRadon library extends this to GPU-accelerated, differentiable operations for deep learning applications [S1, unofficial].
