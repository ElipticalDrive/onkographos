# GPU Backprojection using OpenCL Buffers

Also called: Full GPU Path (Ramp Filter + Backprojection), GPU-Buffer Backprojection

## Overview
A GPU-accelerated tomographic reconstruction pipeline that performs filtered backprojection by storing projection data in OpenCL global memory buffers rather than image objects [S1, unofficial]. It distinguishes itself from [GPU Backprojection using OpenCL Image Textures](5111-gpu-backprojection-using-opencl-image-textures.md) by avoiding texture sampling hardware, and from [GPU Backprojection with Global Memory Buffer](4991-gpu-backprojection-with-global-memory-buffer.md) by explicitly including the ramp filtering step in the pipeline [S1, unofficial]. It solves the problem of reconstructing a 3D volume from 2D projections by mapping projection weights to volume expansion coefficients, building on [Back-projection](2450-back-projection.md) [S1, unofficial].

## How it works
**Inputs:**
- `projections`: `std::vector<float>` of size $P \times W \times H$ (column-major layout: `psrc[u * H + v]` for each projection $p$) [S1, unofficial].
- `P`: Number of projections [S1, unofficial].
- `W`, `H`: Detector width and height in pixels [S1, unofficial].
- `NX`, `NY`: Volume dimensions ($NX \times NX \times NY$ voxels) [S1, unofficial].
- `voxelSize`: Voxel size in mm [S1, unofficial].
- `pixelSize`: Pixel size in mm [S1, unofficial].
- `sdd`: Source-to-detector distance in mm [S1, unofficial].
- `sod`: Source-to-object distance in mm [S1, unofficial].

**Outputs:**
- `std::vector<float>` representing the reconstructed volume of size $NX \times NX \times NY$ [S1, unofficial].

**Data Structures:**
- **Volume Buffer:** `cl_mem` with `CL_MEM_READ_WRITE`, size `sizeof(float) * volumeSize` where `volumeSize = NX * NX * NY` [S1, unofficial].
- **Projection Buffer:** `cl_mem` with `CL_MEM_READ_WRITE`, size `sizeof(float) * projSize` where `projSize = W * H` (per projection, reused or copied per iteration) [S1, unofficial].

**Steps:**
1. **Pre-filtering:** Apply FDK pre-filter (ramp filter) on CPU to raw projections [S1, unofficial].
2. **Volume Initialization:** Fill volume buffer with zeros using `clEnqueueFillBuffer` [S1, unofficial].
3. **Loop over projections:** For each projection $p$ from $0$ to $P-1$:
   a. Calculate angle: $\theta = 2.0f \times \pi \times p / P$ [S1, unofficial].
   b. **Data Transposition:** Convert projection data from column-major (`psrc[u * H + v]`) to row-major (`rowMajor[v * W + u]`) for memory coalescing in the kernel [S1, unofficial].
   c. **Kernel Execution:** Enqueue NDRange kernel with global size equal to `volumeSize` ($NX \times NX \times NY$) [S1, unofficial]. The kernel computes backprojection weights based on geometry and accumulates into the volume buffer [S1, unofficial].
4. **Final Scaling:** After reading the volume buffer back to host, multiply every voxel by `scale = M_PI / P` [S1, unofficial].

**Pseudocode:**
```python
import math

def reconstruct_gpu_buffer(projections, P, W, H, NX, NY, voxelSize, pixelSize, sdd, sod):
    """
    Reconstructs volume using GPU backprojection with OpenCL buffers.
    Implements the exact steps from the source pipeline.
    """
    volume_size = NX * NX * NY
    proj_size = W * H
    
    # 2. Volume Initialization: Fill volume buffer with zeros
    volume = [0.0] * volume_size
    
    # 1. Pre-filtering: Apply FDK pre-filter on CPU to raw projections
    # (FDK ramp filter implementation details are not provided in the sources)
    filtered_projections = apply_fdk_filter(projections, W, H, voxelSize, sdd, sod)
    
    # 3. Loop over projections
    for p in range(P):
        # a. Calculate angle
        angle = 2.0 * math.pi * p / P
        
        # b. Data Transposition: Convert column-major to row-major
        # Input layout: psrc[u * H + v]
        # Output layout: rowMajor[v * W + u]
        row_major_proj = [0.0] * proj_size
        for u in range(W):
            for v in range(H):
                row_major_proj[v * W + u] = filtered_projections[p * proj_size + u * H + v]
        
        # c. Kernel Execution: Enqueue NDRange kernel with global size volume_size
        # The kernel computes backprojection weights based on geometry and accumulates into the volume buffer
        # (OpenCL kernel implementation details are not provided in the sources)
        backproject_kernel(volume, row_major_proj, W, H, NX, NY, voxelSize, pixelSize, sdd, sod, angle)
        
    # 4. Final Scaling: After reading the volume buffer back to host, multiply every voxel by scale = M_PI / P
    scale = math.pi / P
    result = [voxel * scale for voxel in volume]
    return result
```

**Edge Cases and Pitfalls:**
- **Precision:** Expected MSE < 1e-4 against CPU reference [S1, unofficial].
- **Boundaries:** Ensure `clEnqueueFillBuffer` is used correctly to zero-initialize the volume [S1, unofficial].
- **Memory:** Large volumes may exceed global memory limits; not given in the sources.

## Subtopics

### [GPU Backprojection using Local-Memory Tiling](5112-gpu-backprojection-using-local-memory-tiling.md)
A GPU-accelerated tomographic reconstruction variant that optimizes memory access patterns by tiling the Z-axis reconstruction loop using OpenCL local memory. It reduces global memory bandwidth pressure by reusing projection data across threads within a work-group, distinguishing it from the parent [GPU Backprojection using OpenCL Buffers](5110-gpu-backprojection-using-opencl-buffers.md) which relies solely on global memory buffers for projection storage.

## Operating characteristics
- **Time Complexity:** $O(P \times NX \times NX \times NY)$, where $P$ is the number of projections and $NX, NY$ are volume dimensions [S1, unofficial].
- **Memory Complexity:** $O(NX^2 \times NY + W \times H)$ for volume and projection buffers [S1, unofficial].
- **Measured Performance:** Not given in the sources [S1, unofficial].
- **Scaling:** Linear with number of projections and volume size [S1, unofficial].
- **Strengths:** Full GPU path for backprojection, avoids texture unit overhead [S1, unofficial].
- **Limitations:** Relies on global memory for projection data, which may cause bandwidth bottlenecks compared to local-memory tiling variants [S1, unofficial].
- **When to use:** When texture units are unavailable or when a simple buffer-based approach is preferred over image objects [S1, unofficial].
- **When not:** When memory bandwidth is a critical bottleneck and local memory tiling is feasible [S1, unofficial].

Part of a suite of GPU reconstruction methods including CPU reference, image texture-based, and local-memory tiling variants [S1, unofficial].
