# Gradient w.r.t Source/Detector Geometry

Also called: Cone Beam Geometry Gradient, Cone Beam Geometry Gradient CUDA Kernel, Gradient of Projection Error w.r.t Source and Detector Positions

## Overview
Computes the gradient of the projection error (or forward projection loss) with respect to the 3D positions of the X-ray source and detector elements in a cone-beam geometry [S1, unofficial]. It differs from standard back-projection by applying the chain rule through the trilinear interpolation derivatives, scattering gradients back to the camera parameters rather than the volume [S1, unofficial]. It is the adjoint operation required for differentiable tomographic reconstruction where geometry is optimized [S1, unofficial].

## How it works
**Inputs:**
- `volume`: 3D volume data in a bricked layout with a 1-voxel zero border [S1, unofficial].
- `sources`: Array of source positions [S1, unofficial].
- `detectors`: Array of detector element positions [S1, unofficial].
- `box`: 12 floats defining volume centre (3), half-extent (3), inverse voxel spacing (3), and stored centre coordinate (3) [S1, unofficial].
- `grad`: Packed gradient tensor for the current group [S1, unofficial].
- `n`: Number of sample points along each ray [S1, unofficial].

**Outputs:**
- `grad_sources`: Gradient w.r.t. source positions [S1, unofficial].
- `grad_detectors`: Gradient w.r.t. detector positions [S1, unofficial].

**Data Structures:**
- `ConeRay`: Struct containing ray origin (source), direction components (`ex, ey, ez`), length, entry/exit distances along the ray (`entry, exit`), entry/exit axes (`entry_axis, exit_axis`), and sample step parameters in stored coordinates (`px, py, pz, sx, sy, sz`) [S1, unofficial].
- `Layout`: Defines volume dimensions (`X, Y, Z`) and brick tiling parameters (`bricks_x, row, plane`) [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization**: For each thread handling a ray, initialize `F=0` (accumulated value), `G[3]={0}` (accumulated spatial gradients), `M[3]={0}` (accumulated weighted spatial gradients), and `loaded=0xffffffff` (cache invalidation flag) [S1, unofficial].
2.  **Ray Setup**: Construct the `ConeRay` from source and detector positions [S1, unofficial]. Compute direction vector $\vec{e} = \text{detector} - \text{source}$ and length $L = \|\vec{e}\|$ [S1, unofficial]. If $L \le 0$, skip [S1, unofficial]. Normalize direction $\vec{u} = \vec{e}/L$ [S1, unofficial]. Clip the ray against the volume box defined by `box` to find `entry`, `exit`, and the axes of intersection (`entry_axis`, `exit_axis`) [S1, unofficial]. If the ray misses the volume, skip [S1, unofficial]. Compute step size in stored coordinates: `weight` = $(\text{exit} - \text{entry}) / n$ [S1, unofficial]. Compute starting position in stored coordinates for the first sample midpoint [S1, unofficial].
3.  **Sampling Loop**: Iterate $k$ from $0$ to $n-1$ [S1, unofficial]. Calculate the current sample position in stored coordinates using `px, py, pz` and steps `sx, sy, sz` [S1, unofficial]. Determine the 8 neighboring voxel indices (trilinear stencil) [S1, unofficial]. If the stencil index has not been loaded (`s.index != loaded`): fetch the 8 voxel values from the volume for all channels, weight by `g[c]`, store in `v[q]`, and set `loaded = s.index` [S1, unofficial]. Compute the interpolated value $f$ and its spatial derivatives $f_x, f_y, f_z$ using the precomputed trilinear derivatives [S1, unofficial]. Accumulate: $F \leftarrow F + f$ [S1, unofficial]; $G[0] \leftarrow G[0] + f_x$, $G[1] \leftarrow G[1] + f_y$, $G[2] \leftarrow G[2] + f_z$ [S1, unofficial]; $M[0] \leftarrow M[0] + w \cdot f_x$, $M[1] \leftarrow M[1] + w \cdot f_y$, $M[2] \leftarrow M[2] + w \cdot f_z$ where $w = (k + 0.5) / n$ [S1, unofficial].
4.  **Gradient Accumulation**: Let $E = [e_x, e_y, e_z]$ be the ray direction vector [S1, unofficial]. Let $\tau_e = \text{entry} / L$ and $\tau_x = \text{exit} / L$ be the normalized entry and exit positions [S1, unofficial]. Let $\delta = \tau_x - \tau_e$ be the normalized ray span [S1, unofficial]. Let `step` = `weight` [S1, unofficial]. Scale $G[a]$ and $M[a]$ by `box[6+a]` [S1, unofficial]. Compute $GE = \sum_{a} G[a] \cdot E[a]$ and $ME = \sum_{a} M[a] \cdot E[a]$ [S1, unofficial]. Compute $\text{along} = \delta \cdot F / n$ and $\text{ends} = L \cdot F / n$ [S1, unofficial]. For each axis $a \in \{0, 1, 2\}$: $H = \tau_e \cdot G[a] + \delta \cdot M[a]$ [S1, unofficial]; $\text{gd}[a] = \text{along} \cdot E[a] / L + \text{step} \cdot H$ [S1, unofficial]; $\text{gs}[a] = \text{step} \cdot G[a] - \text{gd}[a]$ [S1, unofficial].
5.  **Boundary Corrections**: If $a == \text{exit\_axis}$: $c = (\text{ends} + \text{step} \cdot ME) / E[a]$ [S1, unofficial]; $\text{gs}[a] \leftarrow \text{gs}[a] - c \cdot (1 - \tau_x)$ [S1, unofficial]; $\text{gd}[a] \leftarrow \text{gd}[a] - c \cdot \tau_x$ [S1, unofficial]. If $a == \text{entry\_axis}$: $c = (-\text{ends} + \text{step} \cdot (GE - ME)) / E[a]$ [S1, unofficial]; $\text{gs}[a] \leftarrow \text{gs}[a] - c \cdot (1 - \tau_e)$ [S1, unofficial]; $\text{gd}[a] \leftarrow \text{gd}[a] - c \cdot \tau_e$ [S1, unofficial].
6.  **Writing Results**: Write $\text{gd}[a]$ to `grad_detectors[3*r + a]` for active rays [S1, unofficial]. Reduce $\text{gs}[a]$ across the warp using warp shuffle instructions [S1, unofficial]. If the thread is the first in the warp and the total gradient is non-zero, `atomicAdd` to `grad_sources[3*view + a]` [S1, unofficial].

**Python Wrapper Logic:**
```python
def cone_geometry_grad_wrapper(volume, grad_flat, sources, detectors, box, projection_shape, n):
    grad_sources = zeros_like(sources)
    grad_detectors = zeros_like(detectors)
    library = _kernels()
    for start, count, group in _groups(batch, _GROUP):
        stored = _brick(volume, start, count, group)
        packed_grad = _pack(grad_flat, start, count, group)
        group_detectors = grad_detectors if start == 0 else empty_like(detectors)
        kernel = library[f"cone_geometry_grad_c{group}"]
        kernel(grid=_grid(projection_shape), block=(32, 4, 1),
               args=[stored, packed_grad, sources, detectors, box,
                     grad_sources, group_detectors, width, height, depth,
                     *projection_shape[1:], n])
        if start > 0:
            grad_detectors += group_detectors
    return grad_sources, grad_detectors
```

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of rays $R$ and samples $n$. The kernel launch overhead is minimized by batching [S1, unofficial].
- **Memory Complexity**: Requires storage for `grad_sources` and `grad_detectors`. The kernel uses shared memory/cache for voxel fetching, leveraging the bricked layout to keep 8 voxels in 1-2 cache lines [S1, unofficial].
- **Performance**: On an RTX 2080 Ti, PyTorch 2.4.0, for a 512x512 projection with 360 views and batch 4, the CUDA exact backend performs the adjoint (geometry gradient) in ~1.963 ms (Parallel) or ~2.983 ms (Fan) [S1, unofficial]. This is significantly faster than the pure PyTorch implementation (37.426 ms and 50.901 ms respectively) [S1, unofficial].
- **Strengths**: Exact adjoint of the forward projection; efficient GPU implementation using NVRTC and warp-level primitives; handles cone-beam geometry explicitly [S1, unofficial].
- **Limitations**: Requires volume to be in a specific bricked layout with a 1-voxel border; precision limited to float32 as per the arithmetic description [S1, unofficial].

## Background
The method is part of the `torchtomo` library, which provides differentiable tomographic reconstruction operators [S1, unofficial]. It was developed to enable end-to-end training of tomographic pipelines where camera geometry is a learnable parameter [S1, unofficial]. The implementation uses NVRTC to compile CUDA kernels at runtime, allowing for template specialization on the number of channels $C$ [S1, unofficial].
