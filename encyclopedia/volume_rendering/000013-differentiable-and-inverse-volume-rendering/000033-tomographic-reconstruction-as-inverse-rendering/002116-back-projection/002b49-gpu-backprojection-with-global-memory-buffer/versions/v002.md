# GPU Backprojection with Global Memory Buffer

Also called: GPU Backprojection Kernel Mapping, backproject

## Overview
This method performs cone-beam CT reconstruction by mapping projection weights to volume expansion coefficients using a GPU-accelerated kernel that iterates over projection angles [S1, unofficial]. It solves the inverse problem of tomographic reconstruction by accumulating contributions from projection slices into a global memory volume buffer [S1, unofficial]. It is distinguished from sibling methods by its use of a single kernel launch per projection angle with a 1D NDRange where each work-item corresponds to one voxel, avoiding complex local memory tiling or image texture sampling [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** A sequence of $P$ projection images, each of size $W \times H$. Geometric parameters: Source-to-Object Distance ($sod$), Source-to-Detector Distance ($sdd$), voxel size ($voxelSize$), and pixel size ($pixelSize$) [S1, unofficial]. Volume dimensions $NX \times NX \times NY$ [S1, unofficial].
- **Outputs:** A reconstructed 3D volume buffer of size $NX \times NX \times NY$ of type `float` [S1, unofficial].

**Data Structures:**
- **Volume Buffer:** A 1D array of size $V = NX \times NX \times NY$ allocated in global memory (`CL_MEM_READ_WRITE`) and initialized to zero [S1, unofficial].
- **Projection Buffer:** A 1D array of size $W \times H$ allocated in global memory (`CL_MEM_READ_ONLY | CL_MEM_COPY_HOST_PTR`) for the current projection angle [S1, unofficial].

**Numbered Steps:**
1. Initialize OpenCL context, command queue, and program from source file `kernels/backprojection_buffer.cl` [S1, unofficial].
2. Allocate the volume buffer of size $V \times \text{sizeof(float)}$ and fill with zeros [S1, unofficial].
3. Loop over each projection angle $p$ from $0$ to $P-1$:
    a. Calculate the rotation angle: $\theta_p = 2.0 \pi \frac{p}{P}$ [S1, unofficial].
    b. Create the projection buffer containing the $p$-th projection slice [S1, unofficial].
    c. Set kernel arguments: `projBuffer`, `volumeBuffer`, `W`, `H`, `NX`, `NY`, `voxelSize`, `pixelSize`, `sdd`, `sod`, `angle` [S1, unofficial].
    d. Launch the backprojection kernel with a global size equal to $V$ (1D NDRange) [S1, unofficial].
    e. Release the projection buffer [S1, unofficial].
4. After all projections, read the volume buffer back to the host [S1, unofficial].
5. Scale the reconstructed volume by $\frac{\pi}{P}$ [S1, unofficial].

**Kernel Logic (Per Work-Item):**
Each work-item with global ID $gid$ corresponds to a unique voxel in the volume [S1, unofficial]. The voxel coordinates $(x, y, z)$ are derived from $gid$ [S1, unofficial]. Each work-item independently computes the contribution from one projection angle to one voxel [S1, unofficial]. No synchronization is needed because each Global ID (GID) owns its volume element [S1, unofficial]. The exact geometric projection formula is not given in the sources. [G] A standard implementation maps voxel indices to physical coordinates, rotates by $-\theta_p$ around the Y-axis, projects to detector coordinates $(u, v)$ using similar triangles with $sdd/sod$, and samples the projection buffer.

**Pseudocode:**
```python
import math

def reconstruct_gpu_buffer(projections, P, W, H, NX, NY, voxel_size, pixel_size, sdd, sod):
    # 1. Initialize OpenCL context, command queue, and program
    # (Implementation details omitted; assumed initialized)
    
    # 2. Allocate volume buffer of size NX*NX*NY, fill with 0
    volume_buffer = [0.0] * (NX * NX * NY)
    
    # 3. Loop over projections
    for p in range(P):
        angle = 2.0 * math.pi * p / P
        
        # 4. Create projection buffer with p-th projection
        proj_buffer = list(projections[p])
        
        # 5. Launch kernel with global size NX*NX*NY
        # Each work-item processes one voxel
        for gid in range(NX * NX * NY):
            # Kernel logic for work-item gid
            # Map 1D gid to 3D voxel indices (row-major: z, y, x)
            z = gid // (NX * NX)
            rem = gid % (NX * NX)
            y = rem // NX
            x = rem % NX
            
            # Convert voxel indices to physical coordinates (center at 0,0,0)
            x_phys = (x - (NX - 1) / 2.0) * voxel_size
            y_phys = (y - (NX - 1) / 2.0) * voxel_size
            z_phys = (z - (NY - 1) / 2.0) * voxel_size
            
            # Rotate voxel coordinates by -angle around Y-axis
            cos_a = math.cos(angle)
            sin_a = math.sin(angle)
            x_rot = x_phys * cos_a + z_phys * sin_a
            z_rot = -x_phys * sin_a + z_phys * cos_a
            y_rot = y_phys
            
            # Project to detector coordinates (u, v)
            scale = sdd / sod
            u = x_rot * scale
            v = y_rot * scale
            
            # Map detector coordinates to pixel indices
            u_idx = u / pixel_size + W / 2.0
            v_idx = v / pixel_size + H / 2.0
            
            # Sample projection buffer with bounds check
            if 0 <= u_idx < W and 0 <= v_idx < H:
                u_int = int(round(u_idx))
                v_int = int(round(v_idx))
                weight = proj_buffer[v_int * W + u_int]
            else:
                weight = 0.0
            
            # Accumulate into volume buffer
            volume_buffer[gid] += weight
        
        # 7. Release projection buffer (handled by garbage collection in Python)
    
    # 8. Read volume buffer back to host (already in host memory)
    result = volume_buffer
    
    # 9. Scale by PI / P
    result = [val * math.pi / P for val in result]
    
    return result
```

**Parameters:**
- $P$: Total number of projection angles [S1, unofficial].
- $NX, NY$: Volume dimensions. Volume size is $NX \times NX \times NY$ [S1, unofficial].
- $W, H$: Projection image dimensions [S1, unofficial].
- $voxelSize$: Physical size of a voxel [S1, unofficial].
- $pixelSize$: Physical size of a pixel [S1, unofficial].
- $sdd$: Source-to-Detector Distance [S1, unofficial].
- $sod$: Source-to-Object Distance [S1, unofficial].
- Typical work-item count: $128 \times 128 \times 128 = 2,097,152$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point accumulation errors may occur if $P$ is very large [G]. Use double precision for intermediate geometric calculations if necessary [G].
- **Boundaries:** Voxel projections falling outside the detector bounds $(0 \le u < W, 0 \le v < H)$ must be handled to avoid out-of-bounds memory access [G]. Clamp or check bounds before sampling [G].
- **Degenerate Input:** If $sod = 0$ or $sdd = 0$, division by zero occurs [G]. Validate inputs before kernel launch [G].

## Operating characteristics
- **Time Complexity:** $O(P \cdot V)$, where $P$ is the number of projections and $V$ is the number of voxels [G]. Each voxel is processed once per projection [G].
- **Memory Complexity:** $O(V + W \cdot H)$ [G]. The volume buffer is stored in global memory, and one projection buffer is allocated and reused [G].
- **Strengths:** Simple implementation, no need for local memory management, easy to debug [G].
- **Limitations:** High global memory traffic as each voxel reads from the projection buffer [G]. Not optimized for cache coalescing as effectively as tiled approaches [G].
- **When to use:** Suitable for prototyping, moderate resolution CT reconstruction, and when implementation simplicity is prioritized over maximum performance [G].
- **When not to use:** For very large volumes or real-time applications where memory bandwidth is a critical constraint [G].

## Background
This method is part of the GPU-accelerated cone-beam CT reconstruction pipeline described in the `ct-reconstruction-gpu` repository [S1, unofficial]. It serves as a baseline GPU implementation for backprojection [S1, unofficial].
