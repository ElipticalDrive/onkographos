# Differential Rendering for CT Reconstruction

Also called: Differentiable Rendering for CT Reconstruction, Differentiable Volume Rendering Reconstruction, Gradient-based Volumetric Reconstruction, Inverse Rendering for CT, Iterative Differential CT

## Overview
Differential Rendering for CT Reconstruction is an inverse rendering technique that reconstructs the volumetric absorption coefficients of an object from a series of 2D X-ray projection images by optimizing scene parameters via gradient descent [S1, unofficial]. It formulates Computed Tomography (CT) as an iterative optimization problem where the Mean Squared Error (MSE) between differentially rendered images and reference projections is minimized [S1, unofficial]. Unlike traditional algebraic reconstruction techniques or deep learning-based methods, this approach relies on fully auto-differentiable rendering engines to compute gradients directly from the rendering equation, allowing for end-to-end optimization without pre-trained models [S1, unofficial]. It sets itself apart from siblings like DiffVox by utilizing a specific multi-view iterative rotation strategy with fixed 45° steps and ADAM optimization [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Reference projection images (Ground Truth) acquired at various rotation angles; initial scene parameters $\pi$ including rotation angle and volume data $\sigma$; optimization hyperparameters ($N_{rot}, N_{iter}, LR, \beta_1, \beta_2, \epsilon$) [S1, unofficial].
*   **Outputs:** Optimized 3D volume data (absorption coefficient matrix $\sigma$) [S1, unofficial].

**Data Structures:**
*   **Voxel Grid:** A 3D grid representation of the object, specifically a $16 \times 16 \times 16$ grid [S1, unofficial].
*   **Absorption Coefficient ($\sigma$):** A scalar value per voxel [S1, unofficial]. Value 1 means fully absorbing; 0 means no absorption [S1, unofficial]. Non-zero values ($10^{-4}$) are assigned if surface data is present in the bounding box subdivision [S1, unofficial].
*   **Scene Parameters ($\pi$):** Contains the current rotation angle and the current state of the volume data $\sigma$ [S1, unofficial].
*   **Update Buffer ($\sigma_{update}$):** A non-absorbing matrix (volume data) used to update the scene parameters [S1, unofficial]. Initialized to zero in the first run [S1, unofficial].

**Mathematical Formulation:**
The core principle is differentiating the rendering function with respect to the absorption coefficient matrix $\pi_0$ (representing $\sigma$) [S1, unofficial]:

$$
\frac{\partial}{\partial \pi_0} \iint f(x, y; \pi) \, dx \, dy = \frac{\partial I_i}{\partial \pi_0}
$$

Where:
*   $\pi_0$ is the absorption coefficient matrix of the volumetric object [S1, unofficial].
*   $f(x, y; \pi)$ is the rendering function mapping scene parameters to image coordinates [S1, unofficial].
*   $I_i$ is the pixel value in the rendered image [S1, unofficial].

**Algorithm Steps:**
1.  **Initialize:** Set $N_{rot}$ (number of 45° rotations) and $N_{iter}$ (iterations per rotation) [S1, unofficial]. Initialize the absorption coefficient parameter matrix $\pi_0$ with constant entries (e.g., 0 or 0.001) [S1, unofficial].
2.  **Loop over Rotations ($i$ from 0 to $N_{rot}-1$):**
    a.  **Calculate Angle:** Compute rotation angle as $(i \times 45.0) \pmod{360}$ [S1, unofficial].
    b.  **Load Scene:** Create scene object using parameters $\pi$ and current rotation [S1, unofficial].
    c.  **Render Reference:** Forward render the scene to create the target image ($I_{ref}$) [S1, unofficial].
    d.  **Initialize Update Buffer:** If $\sigma_{update}$ is null, initialize it as a zero-filled array matching the length of the reference volume $\sigma$ data [S1, unofficial].
    e.  **Update Volume:** Apply $\sigma_{update}$ to the scene volume parameters [S1, unofficial].
    f.  **Loop over Iterations ($j$ from 0 to $N_{iter}-1$):**
        i.  **Differential Render:** Render the scene using the differentiable renderer to get the current image ($I_{curr}$) and compute gradients [S1, unofficial].
        ii. **Calculate Loss:** Compute MSE between $I_{curr}$ and $I_{ref}$:
        $$
        L = \frac{1}{N} \sum_{k=1}^{N} (I_{curr, k} - I_{ref, k})^2
        $$
        iii. **Backpropagate:** Compute gradients of the loss with respect to scene parameters ($\frac{\partial L}{\partial \pi}$) [S1, unofficial].
        iv. **Gradient Step:** Update parameters using the ADAM optimizer [S1, unofficial].
    g.  **Update Buffer:** After the iteration loop, update $\sigma_{update}$ with the optimized $\sigma$ data from the scene volume [S1, unofficial].
3.  **Convergence:** Repeat until $N_{rot}$ rotations are complete or convergence is reached (no further changes in scene parameters) [S1, unofficial].

**Pseudocode:**
```python
def differential_ct_reconstruction(Nrot, Niter, initial_sigma, lr, beta1, beta2, epsilon):
    """
    Reconstructs volumetric data using differential rendering.
    
    Args:
        Nrot: Number of 45-degree rotations (e.g., 40 for 360 degrees).
        Niter: Number of optimization iterations per rotation (e.g., 40).
        initial_sigma: Initial absorption coefficient matrix (e.g., zeros or 0.001).
        lr: Learning rate for ADAM (0.002).
        beta1: ADAM beta1 (0.9).
        beta2: ADAM beta2 (0.99).
        epsilon: ADAM epsilon (1e-8).
        
    Returns:
        Optimized sigma volume.
    """
    sigma = initial_sigma.copy()
    sigma_update = None
    # ADAM state variables
    m = np.zeros_like(sigma)
    v = np.zeros_like(sigma)
    t = 1

    for i in range(Nrot):
        rotation_angle = (i * 45.0) % 360.0
        # Construct scene geometry, camera, detector, and volume buffer
        scene = create_scene(sigma, rotation_angle)
        # Render image without gradient tracking
        image_ref = forward_render(scene)

        if sigma_update is None:
            sigma_update = np.zeros_like(sigma)

        scene.volume.sigma = sigma_update

        for j in range(Niter):
            # Render image and compute gradients w.r.t scene.volume.sigma
            image_curr = differential_render(scene)
            loss = mean((image_curr - image_ref) ** 2)
            # Backpropagate loss through the computational graph
            gradients = compute_gradients(loss, scene.volume.sigma)
            
            # ADAM update step
            m = beta1 * m + (1 - beta1) * gradients
            v = beta2 * v + (1 - beta2) * (gradients ** 2)
            m_hat = m / (1 - beta1 ** t)
            v_hat = v / (1 - beta2 ** t)
            sigma = scene.volume.sigma - lr * m_hat / (np.sqrt(v_hat) + epsilon)
            scene.volume.sigma = sigma
            t += 1

        sigma_update = scene.volume.sigma.copy()

    return sigma_update

def create_scene(sigma, rotation_angle):
    # Standard operation: constructs scene geometry, camera, detector, and volume buffer
    return {'volume': {'sigma': sigma}, 'rotation': rotation_angle}

def forward_render(scene):
    # Standard operation: renders image without gradient tracking
    return render(scene, requires_grad=False)

def differential_render(scene):
    # Standard operation: renders image and computes gradients w.r.t scene.volume.sigma
    return render(scene, requires_grad=True)

def compute_gradients(loss, params):
    # Standard operation: backpropagates loss through the computational graph
    return loss.backward(params)

def zeros_like(tensor):
    # Standard operation: creates a tensor of zeros with the same shape
    return np.zeros_like(tensor)

def mean(tensor):
    # Standard operation: computes arithmetic mean
    return np.mean(tensor)

def sqrt(tensor):
    # Standard operation: computes element-wise square root
    return np.sqrt(tensor)
```

**Parameters:**
*   **Learning Rate (LR):** 0.002 [S1, unofficial].
*   **Beta1 ($\beta_1$):** 0.9 [S1, unofficial].
*   **Beta2 ($\beta_2$):** 0.99 [S1, unofficial].
*   **Epsilon ($\epsilon$):** $10^{-8}$ [S1, unofficial].
*   **Nrot:** 40 (covering 360° in 45° steps) [S1, unofficial].
*   **Niter:** 40 iterations per rotation [S1, unofficial].
*   **Resolution:** 256x256 pixels [S1, unofficial].
*   **Sample Count:** 10 samples per pixel [S1, unofficial].
*   **Initial Absorption Coefficient:** 0.001 (for reference) or 0 (for optimization start) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **High GPU Memory Usage:** Auto-differential volume rendering requires significant GPU memory [S1, unofficial]. High resolutions or sample counts cause out-of-memory errors [S1, unofficial]. Mitigation: Use lower resolution (256x256) and sample count (10) [S1, unofficial].
*   **Noise in Reference Images:** Noise in forward-rendered reference images propagates into the optimized volume, causing "noise clouds" [S1, unofficial].
*   **Edge Artifacts:** Undesired clouds around volume edges may be caused by interpolation algorithms or reference image noise [S1, unofficial].
*   **Loss Spikes at Rotation Start:** The MSE loss function shows descending spikes at the start of each new 45° rotation during the first full 360° because the full geometry is not yet known to the optimizer [S1, unofficial].
*   **Convergence Threshold:** The loss function converges around an MSE of 0.0010 after the first full rotation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method is iterative and computationally expensive [S1, unofficial]. Total reconstruction time can exceed 15 hours for 40 rotations and 40 iterations per rotation on an Nvidia RTX 3090 [S1, unofficial]. The mean time per 45° rotation is 23.441 minutes [S1, unofficial].
*   **Memory Complexity:** High GPU memory usage (>90% utilization) due to the storage of gradients and intermediate rendering states for auto-differentiation [S1, unofficial]. This limits the feasible resolution and sample count [S1, unofficial].
*   **Performance:** On an AMD Ryzen 9 3950X and Nvidia RTX 3090, the algorithm is slow but produces reliable results [S1, unofficial].
*   **Strengths:** Works without pre-trained models; leverages existing differentiable rendering engines (e.g., Mitsuba 2); provides a proof-of-concept for inverse rendering in CT [S1, unofficial].
*   **Limitations:** High memory consumption limits resolution; noisy reference images degrade reconstruction quality; slow convergence; sensitive to initial geometric assumptions during early rotations [S1, unofficial].
*   **When to Use:** Suitable for proof-of-concept demonstrations, small-scale volumetric reconstruction where high precision is not critical, or when traditional reconstruction methods fail due to complex lighting/material interactions that can be modeled in a differentiable renderer [G].
*   **When Not to Use:** For large-scale clinical CT scans requiring high resolution and speed; when GPU memory is constrained; when reference images are extremely noisy [G].

## Background
The method was implemented using the Mitsuba 2 framework and a specific fork (master @f4bc83c68f) [S1, unofficial]. It builds upon the work of Zhao et al. [ZJL20] for mathematical insights into differentiable volume rendering and Hochhauser et al. [Hoc22] for X-ray spectrum rendering [S1, unofficial]. The approach is part of the broader field of differentiable rendering, which seeks to make rendering pipelines differentiable with respect to scene parameters, enabling inverse problems like shape and material estimation [S1, unofficial].
