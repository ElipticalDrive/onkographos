# Differentiable CT Execution Model

Also called: Differentiable CT Operators, cell-constant ray integrator, diffct, diffct 2.2.1 API, diffct Differentiable CT Execution Model, diffct Native Projector/Backprojector, matched discrete adjoint, native forward model

## Overview
The Differentiable CT Execution Model (commonly known as **diffct**) is a PyTorch-based framework for differentiable computed tomography that integrates a cell-constant attenuation field along rays defined by arbitrary per-view acquisition geometry [S1, unofficial]. It solves the forward projection and matched discrete adjoint (backprojection) problems for parallel, fan, and cone beams, supporting non-circular trajectories and parameterized detector surfaces [S1, unofficial]. It sets itself apart from siblings like [Back-projection](2450-back-projection.md) and [FastFDK](3315-fastfdk.md) by providing a native, differentiable forward model with first-order geometry derivatives, whereas analytical methods (FBP/FDK) in this family reject trainable geometry and return incomplete derivatives [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume tensor $x$ of shape $(D, H, W)$ representing the attenuation field, and a trajectory object defining the source and detector positions for each view.
*   **Output:** A sinogram tensor $y$ of shape $(N_{views}, U, V)$ representing the projected intensities, and gradients with respect to the volume and/or geometry.

**Data Structures:**
*   **Volume:** Centered on the origin. On an axis with $N$ cells and spacing $s$, voxel $i$ has center $(i + 1/2 - N/2)s$ and faces at $(i - N/2)s$ and $(i + 1 - N/2)s$ [S1, unofficial].
*   **Detector:** Flat detector sampling uses a half-cell-centered convention. For detector indices $k$ (width $U$) and $\ell$ (height $V$) with spacing $\Delta u, \Delta v$:
    $$ u_k = \left( k - \frac{U-1}{2} \right) \Delta u, \quad v_\ell = \left( \ell - \frac{V-1}{2} \right) \Delta v $$
    [S1, unofficial].
*   **Beam Types:**
    *   **Parallel:** Stores $(d_n, o_n, e_{u,n})$ where $d_n$ is the unit ray direction orthogonal to the unit detector axis $e_{u,n}$ [S1, unofficial].
    *   **Fan/Cone:** Stores source $S_n$, isocenter $C_n$, and detector axes. Cone beams add $e_{v,n}$ orthogonal to $e_{u,n}$ [S1, unofficial].

**Algorithm Steps:**

1.  **Construction:** Initialize `Projector(trajectory, volume_shape, detector_shape, ...)`. The constructor records shapes, pitches, beam type, and execution choices. If geometry has no trainable components, it is cloned. If any trajectory component requires gradients, the geometry is read live on each call, and values needed for backward are saved. Trainable components must be marked before construction [S1, unofficial].
2.  **Forward Projection (`project(x)`):**
    *   For each view, define the ray line equation. For parallel beams: $r_{n,k}(t) = o_n + u_k e_{u,n} + t d_n$. For cone/fan beams, the detector point is $D_{n,k,l} = C_n + u_k e_{u,n} + v_l e_{v,n}$ and the direction is $\hat{d} = (D_{n,k,l} - S_n) / \| D_{n,k,l} - S_n \|$ [S1, unofficial].
    *   Use Siddon's grid-plane traversal to compute the intersection of the ray with the volume box [S1, unofficial].
    *   Clip the ray segment to the volume box. Rays do not extend through the detector or behind the source [S1, unofficial].
    *   Integrate the cell-constant attenuation field $f(r)$ along the clipped ray segment:
        $$ p(n, k) = \int_{\mathbb{R}} f(r_{n,k}(t)) \, dt \quad \text{(Parallel)} $$
        $$ p_f = \int_0^L f(S + t\hat{d}) \, dt \quad \text{(Cone/Fan)} $$
        where $L$ is the distance from source to detector [S1, unofficial].
3.  **Backprojection (`backproject(y)`):**
    *   Compute the matched discrete adjoint of the forward projection. This maps the measurement residuals from the sinogram space back into the volume image space [S1, unofficial].

**Pseudocode:**
```python
import torch
import math
from diffct import Projector, circular_trajectory_3d, fdk

# 1. Define trajectory and projector
# Trajectory: 360 views, Source-to-Isocenter Distance (SID) 320, Source-to-Detector Distance (SDD) 512
trajectory = circular_trajectory_3d(360, sid=320., sdd=512., device="cpu")

# Initialize Projector with volume shape (128, 128, 128) and detector shape (192, 128)
# Beam type is cone, detector spacing is 1.0
A = Projector(trajectory, (128, 128, 128), (192, 128), beam="cone", detector_spacing=1.)

# 2. Create volume tensor with gradients enabled
x = torch.ones(A.volume_shape, device="cuda", requires_grad=True)

# 3. Forward Projection
# Computes the sinogram y by integrating attenuation along rays
y = A.project(x)

# 4. Backprojection (Adjoint)
# Computes the gradient of the projection loss w.r.t the volume (or the adjoint of the projection)
adjoint = A.backproject(y)

# 5. Analytical Reconstruction (Optional)
# Compute FDK reconstruction for comparison or initialization
angles = torch.arange(360, device="cuda") * (2 * math.pi / 360)
reconstruction = fdk(y, trajectory, A.volume_shape, angles, detector_spacing=1., isocenter=(0, 0, 0))
```

**Parameters and Typical Values:**
*   **Data Type:** Native operations return `float32` on the input device. Data gradients are returned in the input dtype [S1, unofficial].
*   **Voxel Spacing:** Must be isotropic [S1, unofficial].
*   **Detector Spacing:** Defined in physical length units, consistent with voxel spacing [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Ray Clipping:** The ray segment is strictly clipped to the volume box. Source and detector-pixel coincidences are invalid [S1, unofficial].
*   **Edge-on Detector:** The native flat path rejects detectors viewed edge-on from the source [S1, unofficial].
*   **Float32 Stability:** For stable `float32` setup, at least one source or detector-center endpoint must lie within $10^6$ voxel lengths of the volume center, and both must lie within $10^{15}$ [S1, unofficial].
*   **Differentiability:** Cell-constant point-ray sampling does not integrate a pixel footprint and is only piecewise differentiable in geometry [S1, unofficial].
*   **Analytical Limits:** FDK is approximate away from circular settings. The helical extension is a slice-windowed approximation with coverage and truncation constraints. Analytical FBP/FDK rejects trainable acquisition geometry and isocenter [S1, unofficial].

## Subtopics

### Attenuation-based Rendering
A rendering equation adapted for X-ray tomography where intensity is attenuated along the ray path, rather than emitted/reflected. It assumes symmetry along the ray (reversing bounds does not change intensity). The rendered intensity is $I = I_0 \exp(-\int \mu(s) ds)$, where $I_0$ is source intensity and $\mu(s)$ is the density/attenuation coefficient [S2, unofficial]. Implementation steps include: 1. Conceptually fixing the sample at the origin and rotating the camera; 2. Calculating attenuation along the ray using the canonical density field; 3. Outputting monochromatic intensity (RGB channels identical); 4. Adding a trainable flat field background to account for non-saturated detector response [S2, unofficial].

## Operating characteristics
*   **Time and Memory Complexity:** The native forward and backprojection operations are $O(N_{rays} \cdot N_{voxels\_intersected})$. Memory usage depends on the partitioning mode: view partitions replicate volume state, while spatial partitions distribute volume state but replicate ray batches [S1, unofficial].
*   **Measured Performance:** In a $512^3$ experiment, cross-node view partitioning demonstrated checked numerical parity and up to $6.74\times$ projection speedup on eight GPUs [S1, unofficial].
*   **Strengths:** Supports arbitrary trajectories, parameterized detector surfaces, and first-order geometry derivatives. Enables end-to-end differentiable optimization of volume and geometry [S1, unofficial].
*   **Limitations:** Does not integrate finite-area pixel footprints (point-ray sampling). Voxel spacing must be isotropic. Analytical methods (FBP/FDK) are non-differentiable with respect to geometry and approximate outside circular orbits [S1, unofficial].
*   **When to use:** When differentiable optimization of acquisition geometry or volume parameters is required, or when using arbitrary non-circular trajectories.
*   **When not to use:** When finite-area footprint integration is critical, or when only fast, non-differentiable analytical reconstruction is needed.

## Background
The Differentiable CT Execution Model (diffct) was developed by Yipeng Sun, Linda-Sophie Schneider, Chengze Ye, and Andreas Maier at the Pattern Recognition Lab, Friedrich-Alexander University Erlangen-Nürnberg [S1, unofficial]. It implements computed-tomography projection and reconstruction in PyTorch using Numba CUDA kernels [S1, unofficial]. The framework addresses the need for differentiable forward models in tomographic reconstruction, allowing for gradient-based optimization of both the volume and the acquisition geometry. It extends earlier circular-orbit implementations to arbitrary trajectories and supports distributed execution across multiple GPUs and nodes [S1, unofficial].
