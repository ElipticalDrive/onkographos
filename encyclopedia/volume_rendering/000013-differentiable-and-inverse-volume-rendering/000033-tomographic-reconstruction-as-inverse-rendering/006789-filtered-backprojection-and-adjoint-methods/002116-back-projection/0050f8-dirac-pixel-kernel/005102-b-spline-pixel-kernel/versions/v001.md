# B-Spline Pixel Kernel

Also called: B-Spline interpolator, Noyau de pixel B-Spline

## Overview
The B-Spline Pixel Kernel is a weighting function for back-projection in tomographic reconstruction that assigns contribution to a pixel proportionally to the geometric intersection length of the projection line within that pixel [S1, unofficial]. It improves upon the Dirac Pixel Kernel by accounting for the varying path lengths of rays traversing a pixel at different angles, thereby reducing sampling artifacts and improving Signal-to-Noise Ratio (SNR) in reconstructed images [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**:
    *   Projection angle $\theta$ (in radians).
    *   Projection offset $\rho$.
    *   Pixel coordinates $(i, j)$ (integer indices).
    *   Pixel size $\Delta_p$ (physical width/height of a square pixel).
*   **Output**:
    *   Kernel weight $B^0(\theta, \rho, i, j)$, a scalar value in $[0, 1]$.

**Data Structures**
No complex data structures are required. The calculation relies on scalar arithmetic operations on the input parameters.

**Step-by-Step Method**
1.  **Calculate Distance**: Compute the perpendicular distance $e$ from the center of the pixel $(i, j)$ to the projection line defined by $(\theta, \rho)$. The center of pixel $(i, j)$ is at coordinates $(i \cdot \Delta_p, j \cdot \Delta_p)$ assuming a standard grid origin, or simply use the normalized distance formula provided in the source:
    $$ e = \rho - i \cos \theta - j \sin \theta $$
    *Note: The source defines $e$ directly in this form, implying $\rho$ and coordinates are in consistent units [S1, unofficial].*

2.  **Determine Bounding Extents**: Calculate the half-widths of the trapezoidal kernel support.
    *   Inner half-width (full overlap region):
        $$ w_{inner} = \frac{\Delta_p (||\cos \theta| - |\sin \theta||)}{2} $$
    *   Outer half-width (total support):
        $$ w_{outer} = \frac{\Delta_p (|\cos \theta| + |\sin \theta|)}{2} $$

3.  **Compute Weight**: Evaluate $B^0$ based on the absolute distance $|e|$:
    *   **Case 1 (Full Overlap)**: If $|e| \le w_{inner}$, the line passes fully through the pixel's central region.
        $$ B^0 = 1 $$
    *   **Case 2 (Partial Overlap)**: If $w_{inner} < |e| \le w_{outer}$, the line intersects the pixel edges. Interpolate linearly based on the distance.
        $$ B^0 = \frac{-2|e| + (|\cos \theta| + |\sin \theta|)\Delta_p}{2 \Delta_p \min(|\cos \theta|, |\sin \theta|)} $$
    *   **Case 3 (No Overlap)**: If $|e| > w_{outer}$, the line does not intersect the pixel.
        $$ B^0 = 0 $$

**Formulas and Definitions**
*   $e$: Signed distance from pixel center to projection line.
*   $\Delta_p$: Pixel size (assumed square).
*   $\theta$: Projection angle.
*   $B^0$: The B-Spline kernel value (also referred to as the zero-order B-spline interpolator in the context of the box function convolution [S1, unofficial]).

**Parameters**
*   $\Delta_p$: Determined by the image resolution and field of view. Typical values depend on the specific application (e.g., for a $512 \times 512$ image, $\Delta_p$ is the FOV/512) [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Angle Symmetry**: The kernel is periodic with period $\pi/2$ due to the absolute values of sine and cosine. The formula derivation in the source assumes $\theta \in [0, \pi/4[$ for the interpolation segment, but the absolute value formulation generalizes it to all angles [S1, unofficial].
*   **Division by Zero**: The denominator in Case 2 contains $\min(|\cos \theta|, |\sin \theta|)$. This term is zero only when $\theta$ is a multiple of $\pi/2$. In these cases, the projection line is axis-aligned. The limit of the expression as $\min \to 0$ should be handled carefully. If $\theta = 0$, $\cos \theta = 1, \sin \theta = 0$. The support width is $\Delta_p$. The inner width is $\Delta_p/2$. The formula becomes $\frac{-2|e| + \Delta_p}{0}$, which is undefined. However, geometrically, for axis-aligned lines, the intersection length is simply $\Delta_p$ if the line passes through, and 0 otherwise. The source notes the derivation is for $[0, \pi/4[$, implying a need for special handling or limit evaluation at $\theta = k\pi/2$ [S1, unofficial]. [G] In implementation, if $\min(|\cos \theta|, |\sin \theta|) < \epsilon$, check if the line is within the pixel bounds directly using axis-aligned intersection logic.
*   **Precision**: Floating point comparisons for $|e| \le w_{inner}$ should use a small epsilon to avoid jitter at boundaries.

**Pseudocode**
```python
def b_spline_pixel_kernel(theta, rho, i, j, delta_p):
    """
    Computes the B-Spline pixel kernel weight.
    
    Args:
        theta (float): Projection angle in radians.
        rho (float): Projection offset.
        i (int): Pixel column index.
        j (int): Pixel row index.
        delta_p (float): Pixel size.
        
    Returns:
        float: Kernel weight B^0.
    """
    # 1. Calculate distance from pixel center to projection line
    # Source defines e = rho - i*cos(theta) - j*sin(theta)
    cos_t = abs(cos(theta))
    sin_t = abs(sin(theta))
    
    # Note: The source formula for e uses i and j directly. 
    # This assumes the pixel center is at (i, j) in normalized coordinates 
    # or that rho is scaled appropriately. 
    # Standard geometric distance from point (x0, y0) to line x*cos + y*sin = rho is:
    # |x0*cos + y0*sin - rho|. 
    # The source writes e = rho - j*cos - i*sin. 
    # Assuming standard image coordinates where x corresponds to i and y to j:
    # e = rho - (i * cos_t + j * sin_t) # Using absolute cos/sin as per source structure
    
    e = rho - (i * cos_t + j * sin_t)
    abs_e = abs(e)
    
    # 2. Calculate bounds
    # Inner bound: where line fully traverses pixel (weight 1)
    # Formula: delta_p * (||cos| - |sin||) / 2
    inner_bound = delta_p * abs(cos_t - sin_t) / 2.0
    
    # Outer bound: total support width / 2
    # Formula: delta_p * (|cos| + |sin|) / 2
    outer_bound = delta_p * (cos_t + sin_t) / 2.0
    
    # 3. Compute weight
    if abs_e <= inner_bound:
        return 1.0
    elif abs_e <= outer_bound:
        # Interpolation region
        # Denominator: 2 * delta_p * min(|cos|, |sin|)
        min_cos_sin = min(cos_t, sin_t)
        
        # Guard against division by zero at axis-aligned angles
        if min_cos_sin < 1e-9:
            # At theta = 0 or pi/2, the line is axis aligned.
            # The intersection length is delta_p if the line passes through the pixel column/row.
            # Based on the limit of the trapezoid, if min is 0, the trapezoid becomes a rectangle.
            # If the line is within the pixel, weight is 1. If outside, 0.
            # The outer_bound check already handles "outside".
            # If we are here, abs_e <= outer_bound.
            # For theta=0: outer_bound = delta_p/2. inner_bound = delta_p/2.
            # So abs_e <= delta_p/2. The line is inside.
            return 1.0
        
        numerator = -2.0 * abs_e + (cos_t + sin_t) * delta_p
        denominator = 2.0 * delta_p * min_cos_sin
        return numerator / denominator
    else:
        return 0.0
```

## Operating characteristics
*   **Complexity**: $O(1)$ per pixel per projection line. The calculation involves basic arithmetic operations (abs, min, max, multiply, add).
*   **Memory**: $O(1)$ auxiliary memory. No lookup tables are required.
*   **Performance**: Faster than analytical integration methods but more expensive than the Dirac kernel due to the trigonometric calculations and conditional logic.
*   **Strengths**: Reduces aliasing artifacts compared to the Dirac kernel by weighting pixels based on actual intersection length. Improves SNR, especially at lower sampling rates (fewer projections) [S1, unofficial].
*   **Limitations**: More complex to implement than the Dirac kernel. Requires careful handling of edge cases at axis-aligned angles.

## Background
The B-Spline Pixel Kernel was first defined in 1993 by Unser et al. [S1, unofficial]. It is derived from the concept of convolving a box function (zero-order B-spline) with the projection line, resulting in a trapezoidal kernel shape that accounts for the geometric intersection length. It is used in tomographic reconstruction algorithms to optimize back-projection accuracy.
