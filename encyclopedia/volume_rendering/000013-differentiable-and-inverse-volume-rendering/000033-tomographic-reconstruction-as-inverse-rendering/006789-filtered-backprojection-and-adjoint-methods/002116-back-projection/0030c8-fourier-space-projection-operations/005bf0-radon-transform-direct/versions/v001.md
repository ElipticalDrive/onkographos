# Radon Transform (Direct)

Also called: Discrete Radon Transform, skradon

## Overview
Computes the Radon transform (sinogram) of a batch of multi-channel images by rotating the image and summing along one axis for each angle [S1, unofficial]. It differs from [TorchRadon](7278-torchradon.md) by providing a specific implementation of the direct projection operator within the `torchskradon` library, focusing on explicit rotation and summation steps rather than optimized Fourier-space approximations [S1, unofficial].

## How it works
**Inputs:**
- `image`: A 4-D `torch.Tensor` of shape `(B, C, H, W)` representing a batch of multi-channel images.
- `theta`: A 1-D `torch.Tensor` of angles in degrees. If `None`, defaults to `torch.arange(180, dtype=torch.float32)` [S1, unofficial].
- `circle`: A boolean flag. If `True`, assumes the image is zero outside the inscribed circle and crops to a square; if `False`, pads the image to the diagonal size [S1, unofficial].
- `preserve_range`: A boolean flag. If `True`, preserves the original value range by converting to double precision if necessary; if `False`, scales integer types to `[0.0, 1.0]` or `[-1.0, 1.0]` [S1, unofficial].

**Outputs:**
- `radon_image`: A `torch.Tensor` of shape `(B, C, N, M)`, where `B` is batch size, `C` is channels, `N` is the projection width (padded image size), and `M` is the number of angles [S1, unofficial].

**Data Structures:**
- The implementation uses standard PyTorch tensors. No custom data structures are defined.

**Steps:**
1. **Type Conversion:** Convert `image` to float using `convert_to_float(image, preserve_range)`. If `preserve_range` is true, convert non-float types to `double`. If false, scale unsigned integers to `[0.0, 1.0]` and signed integers to `[-1.0, 1.0]` [S1, unofficial].
2. **Validation:** Validate input is 4-D. If `theta` is `None`, set `theta = torch.arange(180, dtype=torch.float32)`. Clone `theta` and move it to the same device as `image` [S1, unofficial].
3. **Preprocessing (Circle Mode):** If `circle` is `True`:
    - Calculate `shape_min = min(image.size()[2:])` and `radius = shape_min // 2`.
    - Create a meshgrid `x, y` for the image coordinates.
    - Calculate distance from center: `dist = ((coords - center.view(-1, 1, 1)) ** 2).sum(0)`.
    - Identify `outside_reconstruction_circle = dist > radius**2`.
    - Warn if any non-zero values exist outside the circle [S1, unofficial].
    - Calculate `excess = img_shape - shape_min`.
    - Create slices to crop the image to a square: `padded_image = image[:, :, slices[0], slices[1]]` [S1, unofficial].
4. **Preprocessing (Padding Mode):** If `circle` is `False`:
    - Calculate `diagonal = torch.sqrt(torch.tensor(2)) * max(image.size()[2:])`.
    - Calculate padding `pad = [int(torch.ceil(diagonal - s)) for s in image.size()[2:]]`.
    - Calculate new/old centers and pad widths.
    - Apply `torch.nn.functional.pad` with mode `'constant'` and value `0` to get `padded_image` [S1, unofficial].
5. **Square Assertion:** Assert `padded_image` is square. If `padded_image.size()[2] != padded_image.size()[3]`, raise `ValueError` [S1, unofficial].
6. **Center Calculation:** If `padded_image.size()[2]` is even, `center = 0.5`; else `center = 0.0` [S1, unofficial].
7. **Initialization:** Initialize `radon_image` tensor of shape `(batch, channels, padded_size, len(theta))` with zeros [S1, unofficial].
8. **Rotation and Summation:** Loop `for i, angle in enumerate(torch.deg2rad(theta))`:
    - Calculate `cos_a, sin_a = torch.cos(angle), torch.sin(angle)`.
    - Construct 3x3 rotation matrix `R`:
      $$
      R = \begin{bmatrix}
      \cos_a & \sin_a & -center \cdot \frac{\cos_a + \sin_a - 1}{padded\_size / 2} \\
      -\sin_a & \cos_a & -center \cdot \frac{\cos_a - \sin_a - 1}{padded\_size / 2} \\
      0 & 0 & 1
      \end{bmatrix}
      $$
    - Warp image using `rotated = warp(padded_image, R)`.
    - Sum along axis 2: `radon_image[:, :, :, i] = rotated.sum(2)` [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def radon_transform(image, theta=None, circle=True, preserve_range=True):
    # Step 1: Type Conversion
    if image.dtype == torch.float16:
        image = image.float()
    if preserve_range:
        if image.dtype not in [torch.float32, torch.float64]:
            image = image.double()
    else:
        if not image.dtype.is_floating_point:
            if image.dtype == torch.bool:
                image = image.double()
            elif image.dtype == torch.uint8:
                imax_in = torch.iinfo(image.dtype).max
                image = image / imax_in
                image = image.double()
            elif image.dtype in [torch.int8, torch.int16, torch.int32, torch.int64]:
                # Signed integers -> [-1.0, 1.0]
                imax_in = torch.iinfo(image.dtype).max
                image = image / imax_in
                image = image.double()
    
    # Step 2: Validation
    assert image.dim() == 4, "Input must be 4-D"
    if theta is None:
        theta = torch.arange(180, dtype=torch.float32, device=image.device)
    else:
        theta = theta.clone().to(image.device)
        
    # Step 3 & 4: Preprocessing
    if circle:
        shape_min = min(image.size()[2:])
        radius = shape_min // 2
        # Create meshgrid and calculate distance from center
        # Note: Exact meshgrid creation depends on image dimensions
        # Assuming standard coordinate system
        y, x = torch.meshgrid(torch.arange(image.size(2), device=image.device),
                              torch.arange(image.size(3), device=image.device),
                              indexing='ij')
        center_coord = shape_min / 2.0
        dist = ((x - center_coord) ** 2 + (y - center_coord) ** 2)
        outside_reconstruction_circle = dist > radius ** 2
        if torch.any((image != 0) & outside_reconstruction_circle):
            import warnings
            warnings.warn("Non-zero values exist outside the reconstruction circle")
        
        excess = [image.size(2) - shape_min, image.size(3) - shape_min]
        slices = []
        for e in excess:
            if e.item() > 0:
                slices.append((int(torch.ceil(e / 2).item()), int(torch.ceil(e / 2).item() + shape_min)))
            else:
                slices.append(slice(None))
        padded_image = image[:, :, slices[0][0]:slices[0][1], slices[1][0]:slices[1][1]]
    else:
        diagonal = torch.sqrt(torch.tensor(2.0, device=image.device)) * max(image.size()[2:])
        pad = [int(torch.ceil(diagonal - s)) for s in image.size()[2:]]
        new_center = [(s + p) // 2 for s, p in zip(image.size()[2:], pad)]
        old_center = [s // 2 for s in image.size()[2:]]
        pad_before = [nc - oc for oc, nc in zip(old_center, new_center)]
        pad_width = [(pb, p - pb) for pb, p in zip(pad_before, pad)]
        # pad_width format for F.pad: (left, right, top, bottom)
        # pad_width[0] is for dim 2 (height), pad_width[1] is for dim 3 (width)
        padded_image = F.pad(image, (pad_width[1][0], pad_width[1][1], pad_width[0][0], pad_width[0][1]), mode="constant", value=0)
        
    # Step 5: Square Assertion
    if padded_image.size()[2] != padded_image.size()[3]:
        raise ValueError("padded_image must be a square")
        
    # Step 6: Center Calculation
    if padded_image.size()[2] % 2 == 0:
        center = 0.5
    else:
        center = 0.0
        
    # Step 7: Initialization
    radon_image = torch.zeros(
        (padded_image.size(0), padded_image.size(1), padded_image.size(2), len(theta)),
        dtype=padded_image.dtype,
        device=padded_image.device,
    )
    
    # Step 8: Rotation and Summation
    for i, angle in enumerate(torch.deg2rad(theta)):
        cos_a, sin_a = torch.cos(angle), torch.sin(angle)
        R = torch.tensor([
            [cos_a, sin_a, -center * (cos_a + sin_a - 1) / (padded_image.size(2) / 2)],
            [-sin_a, cos_a, -center * (cos_a - sin_a - 1) / (padded_image.size(3) / 2)],
            [0, 0, 1]
        ], dtype=padded_image.dtype, device=padded_image.device)
        
        # Warp function is not standard PyTorch, assuming a grid_sample based implementation
        # or a custom warp function. For completeness, we assume a helper `warp` exists
        # that applies the affine transform R.
        rotated = warp(padded_image, R)
        radon_image[:, :, :, i] = rotated.sum(2)
        
    return radon_image
```

**Parameters:**
- `circle`: `bool`, optional. If `True`, assumes image is zero outside inscribed circle and crops to square. If `False`, pads to diagonal size [S1, unofficial].
- `preserve_range`: `bool`, optional. Whether to keep original value range or convert via `img_as_float` conventions [S1, unofficial].

**Edge Cases and Pitfalls:**
- If `circle=True` and image has non-zero values outside the reconstruction circle, a `UserWarning` is raised [S1, unofficial].
- If `circle=False`, the padded image must be square. If not, `ValueError` is raised [S1, unofficial].
- Precision issues may arise when converting integer types to float/double, especially with large dynamic ranges [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Time complexity is $O(B \cdot C \cdot N^2 \cdot M)$, where $B$ is batch size, $C$ is channels, $N$ is image size, and $M$ is number of angles, due to the rotation and summation for each angle [S1, unofficial].
- Memory complexity is $O(B \cdot C \cdot N \cdot M)$ for the output sinogram [S1, unofficial].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Scales linearly with batch size, channels, and number of angles [S1, unofficial].

**Strengths and Limitations:**
- Strengths: Explicit control over rotation and summation; supports multi-channel images [S1, unofficial].
- Limitations: Computationally expensive for large images and many angles due to explicit warping; requires square images after preprocessing [S1, unofficial].

**When to Use:**
- Use when explicit control over the projection process is needed, or when integrating with other `torchskradon` operations [S1, unofficial].

**When Not to Use:**
- Avoid for large-scale tomographic reconstruction where performance is critical; consider Fourier-space methods instead [S1, unofficial].

## Background
The Radon transform is a fundamental tool in tomography, mapping a function to its line integrals [S1, unofficial]. The direct implementation described here is part of the `torchskradon` library, which provides differentiable Radon transform operations in PyTorch [S1, unofficial]. It is based on the principles outlined in "Principles of Computerized Tomographic Imaging" by Kak and Slaney [S1, unofficial].
