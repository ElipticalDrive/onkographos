# 2D Fan-beam Reconstruction

Also called: Fan-beam FBP, Fan-beam Tomographic Reconstruction

## Overview
2D Fan-beam Reconstruction is an analytic algorithm for reconstructing a 2D density field from projection data acquired with a diverging X-ray beam. It solves the inverse problem for fan-beam geometry by mapping the diverging ray paths to equivalent parallel-beam line integrals via a geometric Jacobian, then applying standard filtered backprojection. It differs from parallel-beam FBP by explicitly accounting for the source-to-detector divergence and the resulting non-uniform sampling density in the projection space.

## How it works
**Inputs:**
*   Fan-beam projection data $g(s,t)$, where $s$ is the angular parameter defining the ray direction and $t$ is the distance along the central ray from the source to the point $(x,y)$ in the object.
*   Filter kernel $h(s)$.
*   Geometric parameters: Source-to-center-of-rotation distance $d$, source-to-detector distance $D$ (if not normalized), and detector spacing.

**Outputs:**
*   Reconstructed 2D volume $f(x,y)$.

**Data Structures:**
*   Projection array: 2D array indexed by $(s, t)$.
*   Filter kernel: 1D array or function $h(s)$.
*   Reconstruction grid: 2D array indexed by $(x, y)$.

**Steps:**

1.  **Weighting:** Apply a geometric weighting factor $w(s)$ to the raw projection data $g(s,t)$ to compensate for the projective distance. The weighting term is an inverse projective distance-squared normalization.
    $$ w(s) = \frac{1}{r(s)^2} $$
    Where $r(s)$ is the distance from the source to the detector element corresponding to parameter $s$. In many implementations, if the detector is curved or the geometry is normalized, this simplifies to a constant or a function of the fan angle. The source text defines $w(s)$ generally as an "inverse projective distance-squared normalization term" [S1].

2.  **Filtering:** Convolve the weighted projection data with the filter kernel $h(s)$ along the detector dimension $t$ (or the equivalent parallel-beam coordinate).
    $$ p(s,t) = [w(s) g(s,t)] * h(s) $$
    Here, $p(s,t)$ is the filtered projection data. The convolution is performed along the axis corresponding to the detector position or the parallel-beam offset $t$ [S1].

3.  **Backprojection:** Distribute the filtered projection values $p(s,t)$ back into the image space $(x,y)$. For each pixel $(x,y)$, determine the corresponding fan-beam parameters $(s,t)$:
    *   $s$: The angle of the ray passing through $(x,y)$.
    *   $t$: The distance from the source to $(x,y)$ along the central ray of that fan beam.
    *   Apply the Jacobian weighting again during backprojection to account for the change in measure from the projection space to the image space. The backprojection sums the filtered projections weighted by the geometric factor.
    $$ f(x,y) = \int p(s,t(x,y)) \cdot J(x,y) \, ds $$
    Where $J(x,y)$ is the Jacobian of the transformation from fan-beam coordinates to Cartesian coordinates. The source text notes that the algorithm uses "appropriate geometry and Jacobian" [S1].

**Pseudocode:**

```python
def fan_beam_reconstruction(projections, filter_kernel, geometry):
    """
    Reconstructs a 2D volume from fan-beam projections using Filtered Backprojection.
    
    Args:
        projections: 2D array [num_angles, num_detectors], g(s, t)
        filter_kernel: 1D array or function h(s)
        geometry: Object containing source-to-center distance d, 
                  source-to-detector distance D, detector spacing, etc.
    
    Returns:
        reconstructed_volume: 2D array [width, height], f(x, y)
    """
    num_angles, num_detectors = projections.shape
    reconstructed_volume = np.zeros((geometry.image_width, geometry.image_height))
    
    # Precompute filter in frequency domain for efficiency
    filter_freq = np.fft.fft(filter_kernel, n=num_detectors)
    
    # Step 1 & 2: Weighting and Filtering
    filtered_projections = np.zeros_like(projections)
    for i in range(num_angles):
        # Get projection for angle i
        proj = projections[i, :]
        
        # Apply geometric weighting w(s)
        # w(s) is inverse projective distance-squared normalization
        # For a flat detector at distance D from source, distance to detector element j is r_j
        # r_j = sqrt(D^2 + (j - num_detectors/2)^2 * det_spacing^2)
        # w(s) = 1 / r_j^2
        # Note: Source [S1] defines w(s) generally. Implementation depends on specific geometry.
        distances = np.sqrt(D**2 + (np.arange(num_detectors) - num_detectors/2)**2 * geometry.det_spacing**2)
        weights = 1.0 / (distances**2)
        weighted_proj = proj * weights
        
        # Convolve with filter kernel
        # Using FFT convolution
        proj_fft = np.fft.fft(weighted_proj)
        filtered_fft = proj_fft * filter_freq
        filtered_proj = np.real(np.fft.ifft(filtered_fft))
        
        filtered_projections[i, :] = filtered_proj
        
    # Step 3: Backprojection
    for x in range(geometry.image_width):
        for y in range(geometry.image_height):
            # Convert Cartesian (x,y) to fan-beam coordinates (s, t)
            # s is the angle of the ray from source to (x,y)
            # t is the distance from source to (x,y)
            # Assuming source is at origin for simplicity, or offset by geometry
            dx = x - geometry.center_x
            dy = y - geometry.center_y
            t = np.sqrt(dx**2 + dy**2)
            s = np.arctan2(dy, dx)
            
            # Interpolate filtered projection value at (s, t)
            # s corresponds to an angle index, t corresponds to a detector position
            # Map s to angle index
            angle_idx = (s - geometry.start_angle) / geometry.angle_step
            # Map t to detector index
            # t is distance along central ray. In fan-beam, t is often related to detector position
            # For a curved detector, t is constant for all rays? No, t is distance to point.
            # In standard fan-beam FBP, we map (x,y) to (angle, detector_index)
            # detector_index = t / det_spacing (approx, depends on geometry)
            # More precisely, for a flat detector, the detector position u is related to t and s
            # u = D * tan(s)
            # The value p(s, t) is interpolated from filtered_projections
            
            # Interpolation logic [G]:
            # Find closest angle index and interpolate
            # Find closest detector index and interpolate
            # This is a simplification; exact mapping depends on geometry definition
            val = interpolate(filtered_projections, s, t, geometry)
            
            # Apply Jacobian weighting for backprojection [G]
            # Jacobian J = t / D or similar depending on geometry
            # Source [S1] mentions "appropriate geometry and Jacobian"
            jacobian = t / D # Example Jacobian for flat detector
            reconstructed_volume[x, y] += val * jacobian
            
    # Normalize by number of angles
    reconstructed_volume /= num_angles
    
    return reconstructed_volume
```

**Parameters:**
*   Filter kernel $h(s)$: Typically a ramp filter or Ram-Lak filter, often modified with a window (e.g., Shepp-Logan, Hamming) to reduce noise. Typical values depend on the desired resolution and noise trade-off.
*   Geometric parameters: Source-to-center distance $d$, source-to-detector distance $D$.

**Edge Cases and Pitfalls:**
*   **Boundary Effects:** The finite detector size and angular range can cause artifacts at the edges of the reconstructed field of view.
*   **Precision:** Interpolation errors during backprojection can introduce artifacts. High-order interpolation is recommended.
*   **Degenerate Input:** Missing projections or large gaps in angular coverage can lead to streak artifacts.

## Subtopics

### Cone-beam Reconstruction (FDK)
Cone-beam Reconstruction (specifically Feldkamp-Davis-Kress or FDK) is an analytic 3D reconstruction method for circular source trajectories. It extends 2D fan-beam filtered backprojection to 3D by applying 2D weighting and filtering to the projection data $g_c(s,t,\beta)$ and then performing weighted backprojection. It produces approximate results because a single circular trajectory provides insufficient information to correctly reconstruct the entire volume, except for the central $z=0$-plane [S1]. The filtered projection data $p_c(s,t,\beta) = [w(s,t) g_c(s,t,\beta)] * h(s,t)$ is backprojected to calculate the 3D volume $f(x_i,y_j,z_k)$ using a pre-factor that handles the 3D weighting, such as $\frac{1}{2\pi} \frac{d^2}{(x_i^2+y_j^2+d^2)^{3/2}}$ [S1]. It is chosen when 3D reconstruction from a circular scan is required and speed is prioritized over accuracy for large cone angles, where Grangeat's method would be more accurate but complex [S1].

## Operating characteristics
*   **Time Complexity:** $O(N^2 \log N)$ for filtering and $O(N^3)$ for backprojection in 3D, or $O(N^2 \log N)$ for filtering and $O(N^2)$ for backprojection in 2D, where $N$ is the number of pixels/detectors.
*   **Memory Complexity:** $O(N^2)$ for storing projections and the reconstructed volume.
*   **Strengths:** Fast, analytic solution; well-understood; efficient for 2D and approximate 3D.
*   **Limitations:** Approximate for 3D cone-beam; sensitive to noise; requires complete angular coverage for accurate 2D reconstruction.
*   **When to use:** 2D fan-beam tomography; approximate 3D cone-beam reconstruction (FDK).
*   **When not to use:** High-accuracy 3D cone-beam reconstruction with large cone angles (use iterative methods or Grangeat's method); sparse-view tomography (use iterative methods).

## Background
The 2D fan-beam reconstruction algorithm is derived from the parallel-beam filtered backprojection method by accounting for the geometric differences in ray paths. The fan-beam transform is isomorphic to the parallel-beam case, with a direct geometric mapping between line integrals [S1]. The Feldkamp cone-beam reconstruction method, an extension of fan-beam FBP to 3D, was developed in the context of X-ray CT and volume rendering, with references to Feldkamp's and Grangeat's work [S1]. The method is discussed in the context of tomographic image reconstruction and rendering with texture-mapping hardware [S1].
