# Discrete Inverse Radon Transform

Also called: Direct Tomographic Reconstruction, Filtered Backprojection for Attention Map Synthesis, Inverse Radon Transform, R^-1

## Overview
The Discrete Inverse Radon Transform (DIRT) is a method to estimate an attenuation map $\tilde{\mu}(x, y)$ or an image $I$ from a set of projections (sinogram) $p(u, a)$ or $R_\theta(\rho)$ [S1][S2, unofficial]. It is conventionally implemented via filtered backprojection, where the inverse operation sums projection values back into the image domain [S1][S2, unofficial]. Unlike iterative reconstruction methods which handle inconsistent projections over limited angles via optimization, DIRT provides a direct, closed-form estimate [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A sinogram $S$ of size $N_\theta \times N_\rho$, where $N_\theta$ is the number of projection angles and $N_\rho$ is the number of radial samples per angle. The sinogram contains values $S(i_\theta, i_\rho)$ corresponding to angle $\theta_{i_\theta}$ and radial distance $\rho_{i_\rho}$ [S2, unofficial].
- **Output:** A reconstructed image $I$ of size $W \times H$, where $W$ is the width and $H$ is the height [S2, unofficial].

**Data Structures:**
- The image $I$ is a 2D array of size $H \times W$.
- The sinogram $S$ is a 2D array of size $N_\theta \times N_\rho$.
- Angles $\theta$ and radial positions $\rho$ are assumed to be known or uniformly sampled.

**Preprocessing (Filtering):**
Before backprojection, the projections must be filtered to correct for the blurring inherent in simple backprojection. For the specific application of synthesizing light fields for attenuation-based displays, an ideal ramp filter is required [S1].
The filtered projection $\bar{l}_0(u, a)$ is obtained by convolving the input projection $\bar{l}(u, a)$ with a filter kernel $h(u)$ [S1]:
$$ \bar{l}_0(u, a) = \bar{l}(u, a) \otimes h(u) $$
In the frequency domain, this is:
$$ \hat{\bar{l}}_0(f_u, a) = \hat{h}(f_u) \hat{\bar{l}}(f_u, a) $$
where $\hat{h}(f_u)$ is the 1D Fourier transform of the filter kernel. For this application, the ideal ramp filter is defined as:
$$ \hat{h}(f_u) = |f_u| $$
where $f_u$ is the spatial frequency [S1].

**Reconstruction Steps:**
1. Initialize the image $I(i, j)$ to zero for all $0 \le i < H$ and $0 \le j < W$ [S2, unofficial].
2. Loop over all projection angles $\theta_{i_\theta}$ for $0 \le i_\theta < N_\theta$ [S2, unofficial].
3. Loop over all radial samples $\rho_{i_\rho}$ for $0 \le i_\rho < N_\rho$ [S2, unofficial].
4. For each pixel $(i, j)$, determine if the line defined by $(\theta_{i_\theta}, \rho_{i_\rho})$ traverses the pixel. This is evaluated using the discrete Dirac impulse $\Delta(\cdot)$ [S2, unofficial].
5. Update the pixel value by adding the product of the (filtered) sinogram value and the impulse:
   $$ I(i, j) \leftarrow I(i, j) + S(i_\theta, i_\rho) \times \Delta(\rho_{i_\rho} - j \cos \theta_{i_\theta} - i \sin \theta_{i_\theta}) $$
   Note: Some implementations center the coordinates, using the argument $\rho - (j - W/2) \cos \theta - (i - H/2) \sin \theta$ [S2, unofficial]. The impulse $\Delta(\xi)$ equals 1 if the geometric condition is met (within a tolerance for discrete sampling) and 0 otherwise [S2, unofficial].

**Pseudocode:**
```python
def discrete_inverse_radon(sinogram, angles, radial_positions, width, height):
    """
    Reconstructs an image from a sinogram using the Discrete Inverse Radon Transform.
    
    Args:
        sinogram: 2D array of shape (N_theta, N_rho) containing projection values.
                  Note: Input sinogram should be pre-filtered if required by the application.
        angles: 1D array of shape (N_theta,) containing projection angles in radians.
        radial_positions: 1D array of shape (N_rho,) containing radial distances.
        width: Integer, width of the output image (W).
        height: Integer, height of the output image (H).
        
    Returns:
        image: 2D array of shape (height, width) representing the reconstructed image.
    """
    N_theta, N_rho = sinogram.shape
    image = zeros((height, width))
    
    # Pre-calculate trigonometric values for efficiency
    cos_angles = cos(angles)
    sin_angles = sin(angles)
    
    # Center coordinates if necessary (common in tomographic implementations)
    # The source [S2, unofficial] mentions centering: rho - (j - W/2)cos(theta) - (i - H/2)sin(theta)
    # We assume standard pixel indices i, j.
    
    for i_theta in range(N_theta):
        theta = angles[i_theta]
        c_theta = cos_angles[i_theta]
        s_theta = sin_angles[i_theta]
        
        for i_rho in range(N_rho):
            rho = radial_positions[i_rho]
            proj_val = sinogram[i_theta, i_rho]
            
            # Determine which pixels are intersected by this ray
            # The condition is: rho = (j - W/2)*cos(theta) + (i - H/2)*sin(theta)
            # Or without centering: rho = j*cos(theta) + i*sin(theta)
            # We use the centered version as suggested by [S2, unofficial] for accuracy.
            
            # Calculate the line equation in image coordinates
            # rho = (j - W/2)*c_theta + (i - H/2)*s_theta
            # => (j - W/2)*c_theta + (i - H/2)*s_theta - rho = 0
            
            # To avoid iterating all pixels for every ray (O(N^2)), 
            # an optimized approach maps pixels to contributing rays.
            # However, the direct summation formula is:
            
            for i in range(height):
                for j in range(width):
                    # Calculate the distance of the pixel center from the origin
                    # relative to the ray angle
                    dist = (j - width / 2.0) * c_theta + (i - height / 2.0) * s_theta
                    
                    # Check if the ray passes through the pixel
                    # In discrete implementation, we check if the radial position
                    # matches the calculated distance within a bin width.
                    # The Dirac impulse Delta is 1 if the line traverses the pixel.
                    # A simple implementation checks if the calculated distance
                    # is close to the radial position.
                    
                    # Note: The exact definition of "traverses" depends on the 
                    # discretization of the Dirac impulse. A common approach is
                    # to assign the projection value to the pixel if the ray
                    # passes through its center or if the pixel center is the
                    # closest to the ray.
                    
                    # Using the formula from [S2, unofficial]: Delta(rho - j*cos - i*sin)
                    # With centering: Delta(rho - (j-W/2)*cos - (i-H/2)*sin)
                    
                    diff = abs(dist - rho)
                    
                    # If the difference is within half the radial bin width,
                    # the ray is considered to traverse the pixel.
                    # Bin width is not explicitly given, but typically:
                    bin_width = (radial_positions[-1] - radial_positions[0]) / N_rho if N_rho > 1 else 1.0
                    
                    if diff < bin_width / 2.0:
                        image[i, j] += proj_val
                        
    return image
```

**Parameters:**
- **Filter:** An ideal ramp filter $\hat{h}(f_u) = |f_u|$ is specified for the application of synthesizing light fields [S1].
- **Geometry:** Parallel beam geometry is assumed [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Limited Angle:** Filtered backprojection requires projections to vary over a full hemisphere ($-\infty < a < \infty$). It fails or produces artifacts if oblique views are known only over a limited set of angles [S1].
- **Negative Attenuations:** High-pass filtering can lead to negative attenuation values, which may prohibit fabrication in physical displays [S1].
- **Inconsistent Projections:** Gross inconsistencies in the input projections (e.g., from measurement artifacts or incompatible light fields) introduce negative attenuations and artifacts [S1].

## Operating characteristics
- **Complexity:** The naive implementation has a complexity of $O(N N_\theta N_\rho)$, which simplifies to $O(N^2)$ if $N_\theta \approx \sqrt{N}$ and $N_\rho \approx \sqrt{N}$, where $N = W \times H$ [S2, unofficial]. An optimized implementation using a mapping between each pixel and contributing projection lines can reduce the complexity to $O(N \log N)$ [S2, unofficial].
- **Strengths:** Direct and computationally efficient (with optimization); provides a sharp estimate of the attenuation map [S1][S2, unofficial].
- **Limitations:** Fails with limited angle data; prone to negative values and artifacts from inconsistent projections; does not enforce non-negativity constraints [S1].
- **When to use:** When a full set of projections is available and consistency is high; when computational speed is prioritized over handling inconsistencies [S1][S2, unofficial].
- **When not to use:** When projections are limited in angle or inconsistent; when non-negativity is strictly required [S1].

## Background
The Discrete Inverse Radon Transform is a fundamental technique in tomographic reconstruction. It is based on the inverse Radon transform, which recovers a function from its line integrals [S1]. The method is conventionally implemented using filtered backprojection, a technique described in standard texts such as Kak and Slaney [S1]. In the context of computer graphics and display technology, it was applied by Wetzstein et al. (2011) for synthesizing attenuation-based light fields and HDR displays [S1]. The discrete formulation and its complexity analysis are detailed in various tomographic literature, including works on precision and quality in tomographic reconstruction [S2, unofficial].
