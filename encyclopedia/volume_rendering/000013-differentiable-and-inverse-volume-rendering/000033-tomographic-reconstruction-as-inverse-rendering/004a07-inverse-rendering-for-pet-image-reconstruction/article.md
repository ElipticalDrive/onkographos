# Inverse Rendering for PET Image Reconstruction

Also called: Differentiable PET Reconstruction, PET Inverse Rendering

## Overview
Inverse Rendering (IR) for Positron Emission Tomography (PET) reconstructs the highest-resolution spatial distribution of a radioactive tracer (the emission image) from measured sinograms by inverting a differentiable forward rendering process [S1]. Unlike traditional algebraic methods or standard Maximum Likelihood Expectation Maximization (MLEM), this approach treats reconstruction as a gradient-based optimization problem where the forward model simulates photon detection via hybrid Monte Carlo sampling coupled with an analytical projector [S1]. It sets itself apart by leveraging physical differentiability to directly optimize voxel values against measured data, achieving superior resolution (clearly separating 0.7 mm hot-spots) and intensity accuracy compared to MLEM and deep learning baselines [S1].

## How it works
The method reconstructs the 3D emission image $\mathbf{I}$ by minimizing the discrepancy between the measured sinogram $\mathbf{M}$ and a rendered sinogram $\mathcal{R}(\mathbf{I})$ generated by a differentiable forward model [S1].

### Inputs and Outputs
*   **Input:** Measured sinogram data $\mathbf{M}$, representing coincident photon detection events.
*   **Output:** Reconstructed emission image $\hat{\mathbf{I}}$, a 3D volume representing the spatial distribution of the radiotracer.

### Data Structures
*   **Emission Image ($\mathbf{I}$):** A 3D voxel grid representing the radioactive tracer distribution $f(x, y, z)$. The values correspond to emission intensity at each voxel.
*   **Sinogram ($\mathbf{M}$):** A 4D dataset indexed by LOR parameters $(s, \theta, z, \delta)$.
    *   $s$: Distance between the axial axis and the projection of the Line of Response (LOR) onto the transaxial plane.
    *   $\theta$: Angle between the projection and the transaxial axis (y-axis).
    *   $z$: Axial coordinate of the midpoint between the two detectors of the LOR.
    *   $\delta$: Tangent of the angle between the LOR and the transaxial plane.
    *   The set of all LORs is specified by $(s, \theta, z, \delta) \in \mathbb{R}^{M \times 4}$, where $M$ is the number of crystal pairs.
*   **Time-of-Flight (TOF) Bins:** For TOF-capable scanners, each LOR is divided into multiple bins symmetrically centered around the LOR midpoint.

### Forward Rendering Operator $\mathcal{R}(\mathbf{I})$
The forward model simulates the PET acquisition process. It uses hybrid Monte Carlo sampling to estimate line integrals of the source distribution along each LOR [S1].

For Time-of-Flight (TOF) rendering, the LOR is divided into $n$ TOF bins. For the $i$-th TOF bin, the rendered sinogram value is estimated by sampling the emission image at various points within the image domain [S1]. The Monte Carlo estimator for the rendered sinogram $\mathcal{R}(\mathbf{I})$ is defined as [S1]:

$$
\mathcal{R}(\mathbf{I}) = p(s, \theta, z, \delta) = \frac{1}{m} \sum_{i=1}^n \sum_{j=1}^m f_i\left(s \cdot \cos(\theta) - t_j \cdot \sin(\theta), \, s \cdot \sin(\theta) + t_j \cdot \cos(\theta)\right)
$$

Where:
*   $\mathcal{R}(\mathbf{I})$ is the rendered sinogram value for a specific LOR.
*   $n$ is the total number of TOF bins.
*   $m$ is the total number of sampling points in the $i$-th TOF bin.
*   $f_i$ is the voxel value of the emission image at the sampled location.
*   $t_j$ denotes the projection of the LOR in the transaxial plane from the axial position $z$, corresponding to the $j$-th sampling point.
*   The coordinates $(s \cdot \cos(\theta) - t_j \cdot \sin(\theta), s \cdot \sin(\theta) + t_j \cdot \cos(\theta))$ map the LOR geometry to the 2D transaxial plane coordinates for sampling.

*Note: The source formula [S1] sums over $i$ (TOF bins) and $j$ (sampling points) but divides by $m$. In standard Monte Carlo integration, the divisor typically corresponds to the total number of samples. The source explicitly defines $m$ as "total number of sampling points in ith TOF bin" and $n$ as "total number of TOF bins". The implementation must follow the source's specific indexing and normalization.*

### Optimization Loop
The reconstruction is performed by minimizing a loss function $\mathcal{L}$ that measures the alignment between the rendered sinogram $\mathcal{R}(\mathbf{I})$ and the measured sinogram $\mathbf{M}$ [S1].

1.  **Initialize:** Start with an initial estimate of the emission image $\mathbf{I}^0$ (e.g., zero-filled or filtered back-projection).
2.  **Forward Pass:** Compute the rendered sinogram $\mathcal{R}(\mathbf{I}^k)$ using the forward rendering operator described above.
3.  **Loss Calculation:** Compute the loss $\mathcal{L}(\mathbf{M}; \mathcal{R}(\mathbf{I}^k))$. The source specifies Mean Squared Error (MSE) as an example [S1].
    $$
    \hat{\mathbf{I}} = \operatorname{argmin}_{\mathbf{I}} \mathcal{L}(\mathbf{M}; \mathcal{R}(\mathbf{I}))
    $$
4.  **Gradient Computation:** Compute the gradient of the loss with respect to the emission image $\mathbf{I}^k$. This requires differentiating the forward rendering operator $\mathcal{R}$ with respect to each voxel [S1]. The differentiable forward rendering process provides the estimation of how a change in sinogram $y$ can be achieved by modifying voxel values [S1].
5.  **Update:** Update the emission image using gradient descent [S1]:
    $$
    \mathbf{I}^{k+1} = \mathbf{I}^k - \eta \frac{\partial \mathcal{L}}{\partial \mathbf{I}^k}
    $$
    Where:
    *   $\eta$ is the learning rate.
    *   $\frac{\partial \mathcal{L}}{\partial \mathbf{I}^k}$ is the gradient propagated from the loss function at iteration $k$.
6.  **Iterate:** Set $\mathbf{I}^k = \mathbf{I}^{k+1}$ and repeat until convergence or a maximum number of iterations is reached.

def inverse_rendering_pet(measured_sinogram, scanner_geometry, num_iterations, learning_rate, num_tof_bins, num_samples_per_bin):
    """
    Reconstructs PET emission image using inverse rendering.
    
    Args:
        measured_sinogram: Array of shape (M, num_tof_bins) containing measured sinogram data M.
        scanner_geometry: Object containing LOR parameters (s, theta, z, delta) for M crystal pairs.
        num_iterations: Number of optimization steps.
        learning_rate: Step size eta for gradient descent.
        num_tof_bins: Number of TOF bins n.
        num_samples_per_bin: Number of sampling points m per TOF bin.
        
    Returns:
        reconstructed_image: 3D volume representing the emission image I.
    """
    
    # Initialize emission image I (e.g., zeros or simple backprojection)
    # Dimensions depend on scanner field of view and voxel size
    emission_image = initialize_emission_image(scanner_geometry)
    
    for k in range(num_iterations):
        # 1. Forward Rendering: Compute rendered sinogram R(I)
        # R(I) has shape (M, num_tof_bins)
        rendered_sinogram = forward_render(emission_image, scanner_geometry, num_tof_bins, num_samples_per_bin)
        
        # 2. Compute Loss L(M; R(I))
        # Using Mean Squared Error as per source [S1]
        loss = mean_squared_error(measured_sinogram, rendered_sinogram)
        
        # 3. Compute Gradient dL/dI
        # This requires the derivative of the forward render operator with respect to I
        # The source states that PBDR allows efficient differentiation of the full process [S1]
        gradient = compute_gradient(loss, rendered_sinogram, emission_image, scanner_geometry, num_tof_bins, num_samples_per_bin)
        
        # 4. Update Emission Image
        emission_image = emission_image - learning_rate * gradient
        
    return emission_image

def forward_render(emission_image, scanner_geometry, num_tof_bins, num_samples_per_bin):
    """
    Computes the rendered sinogram using the Monte Carlo estimator from [S1].
    """
    M = scanner_geometry.num_crystal_pairs
    rendered_sinogram = zeros((M, num_tof_bins))
    
    for i in range(M):
        s, theta, z, delta = scanner_geometry.lor_params[i]
        
        # Generate sampling points t_j for this LOR
        # t_j represents the projection of the LOR in the transaxial plane
        # The source implies sampling along the LOR within the image domain
        sampling_points_t = generate_sampling_points(num_samples_per_bin, s, theta, z, delta)
        
        for j in range(num_samples_per_bin):
            t_j = sampling_points_t[j]
            
            # Calculate 2D transaxial coordinates for sampling
            # Formula from [S1]: x' = s*cos(theta) - t_j*sin(theta)
            #                   y' = s*sin(theta) + t_j*cos(theta)
            x_prime = s * cos(theta) - t_j * sin(theta)
            y_prime = s * sin(theta) + t_j * cos(theta)
            
            # Sample voxel value f_i at (x_prime, y_prime) at axial position z
            # Interpolation may be needed if coordinates are not integer voxel indices
            f_i = sample_voxel(emission_image, x_prime, y_prime, z)
            
            # Accumulate sum
            # Note: Source formula divides by m (samples per bin) after summing over j and i?
            # Source: (1/m) * sum_i=1^n sum_j=1^m f_i(...)
            # This structure is ambiguous in the source text. 
            # Standard MC estimator for a single LOR bin would average samples.
            # We follow the source's explicit formula structure.
            rendered_sinogram[i, :] += f_i 
            
        # Apply normalization factor 1/m as per source formula (1)
        # Note: The source formula sums over i (TOF bins) and j (samples).
        # If the output is per TOF bin, the division should likely be by m.
        # The source writes: (1/m) sum_{i=1}^n sum_{j=1}^m ...
        # This implies the result is a scalar or the summation indices are mislabeled in the source text vs standard notation.
        # Given "m represents total number of sampling points in ith TOF bin", 
        # and the output is a sinogram (one value per LOR per TOF bin), 
        # the value for bin i should be the average of m samples.
        # We implement the average over samples j for each bin i.
        rendered_sinogram[i, :] = rendered_sinogram[i, :] / num_samples_per_bin
        
    return rendered_sinogram

def compute_gradient(loss, rendered_sinogram, emission_image, scanner_geometry, num_tof_bins, num_samples_per_bin):
    """
    Computes the gradient of the loss with respect to the emission image.
    Uses backpropagation through the differentiable forward render operator.
    """
    # The source states that derivatives are computed from the objective function [S1]
    # and utilized to adjust scene parameters (voxel values) [S1].
    # This is effectively the adjoint of the forward projection.
    
    # 1. Gradient of Loss w.r.t Rendered Sinogram
    # For MSE: dL/dR = 2 * (R - M) / (M * N)
    dL_dR = 2 * (rendered_sinogram - scanner_geometry.measured_sinogram) / (scanner_geometry.num_crystal_pairs * num_tof_bins)
    
    # 2. Backpropagate through Forward Render to get dL/dI
    # The forward render samples voxels. The gradient flows back to the sampled voxels.
    gradient_image = zeros_like(emission_image)
    
    for i in range(scanner_geometry.num_crystal_pairs):
        s, theta, z, delta = scanner_geometry.lor_params[i]
        
        # Generate sampling points t_j
        sampling_points_t = generate_sampling_points(num_samples_per_bin, s, theta, z, delta)
        
        for j in range(num_samples_per_bin):
            t_j = sampling_points_t[j]
            x_prime = s * cos(theta) - t_j * sin(theta)
            y_prime = s * sin(theta) + t_j * cos(theta)
            
            # The contribution of this sample to the loss gradient
            # dL/dI(x',y',z) = dL/dR * dR/df_i * df_i/dI
            # dR/df_i = 1/m (from the averaging in forward render)
            # df_i/dI is the interpolation kernel derivative (e.g., trilinear)
            
            grad_contribution = dL_dR[i, :] / num_samples_per_bin
            
            # Accumulate gradient into the image
            # Using trilinear interpolation gradient for smoothness [G]
            gradient_image = accumulate_gradient(gradient_image, x_prime, y_prime, z, grad_contribution)
            
    return gradient_image

### Parameters
*   **Learning Rate ($\eta$):** The step size for gradient descent. Typical values are not specified in the source, but standard optimization practices apply [S1].
*   **Number of TOF Bins ($n$):** Determines the temporal resolution of the forward model.
*   **Number of Sampling Points ($m$):** The number of Monte Carlo samples per TOF bin. Higher $m$ reduces noise in the forward estimate but increases computation time [S1].
*   **Scanner Geometry:** Defined by $(s, \theta, z, \delta)$ for each of the $M$ crystal pairs [S1].

### Edge Cases and Pitfalls
*   **Ambiguity:** The inverse problem is inherently ambiguous; gradient-based optimization finds a local minimum [S1]. Regularization or constraints may be needed for stability, though the source focuses on the basic gradient descent formulation [S1].
*   **Precision:** The Monte Carlo estimator introduces noise. Insufficient sampling points ($m$) can lead to noisy gradients and unstable convergence [S1].
*   **Boundaries:** Sampling points $t_j$ must be within the image domain. Points outside should be handled (e.g., zero contribution or clamping) [S1].

## Operating characteristics
*   **Time Complexity:** The forward pass involves Monte Carlo sampling for each LOR and TOF bin. Complexity is proportional to $M \times n \times m$, where $M$ is the number of LORs, $n$ is the number of TOF bins, and $m$ is the number of samples per bin. The backward pass requires similar complexity for gradient accumulation.
*   **Memory Complexity:** Requires storing the 3D emission image $\mathbf{I}$ and the sinogram $\mathbf{M}$. Intermediate gradients also require memory proportional to the image size.
*   **Measured Performance:** In tests with a simulated hot-spot phantom, the IR model achieved clear separation for hot-spots with a minimum diameter of 0.7 mm, whereas MLEM only demonstrated optimal separation for 0.8 mm [S1]. The IR model also showed higher pixel intensity accuracy in gray matter and nearly no intensity in white matter compared to MLEM [S1].
*   **Strengths:** Higher resolution than MLEM; outperforms DNN-based methods in some metrics; physically grounded differentiable model [S1].
*   **Limitations:** Computationally expensive due to Monte Carlo sampling and iterative optimization; solution is ambiguous without regularization; sensitive to initialization [S1].
*   **When to Use:** High-resolution PET reconstruction where physical accuracy is prioritized over speed, and when MLEM or DNNs fail to resolve fine structures [S1].
*   **When Not to Use:** Real-time applications requiring fast reconstruction; scenarios with very low count statistics where Monte Carlo noise dominates [S1].

## Background
Inverse Rendering for PET was introduced by W. Jakob, B. Nicolet, Y. Li, Z. Wang, W. Tan, and Amirhossein Goldan [S1]. The work leverages Physically-Based Differentiable Rendering (PBDR) techniques, which have been used to differentiate image formation processes with respect to millions of parameters [S1]. This approach is similar to training a neural network but uses physical simulation instead of a learned model [S1]. The method aims to outperform Maximum Likelihood Expectation Maximization (MLEM) and Deep Neural Networks (DNNs) in PET image reconstruction [S1].
