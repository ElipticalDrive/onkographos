# Fixed Basis for Time Axis

Also called: Basis Function Volume Representation, Static Feature Matrix with Time Basis

## Overview
A failed design for dynamic scene representation that models temporal changes by storing a static feature matrix for each spatial point and computing features at time $t$ via an inner product with time-dependent basis functions [S1]. It differs from successful methods like [HexPlane](6885-space-time-representations.md) by attempting to represent the entire spatiotemporal volume as a linear combination of static basis volumes, which proved computationally intractable due to excessive memory requirements and reconstruction artifacts [S1].

## How it works
**Inputs:**
- Spatial dimensions $X, Y, Z$ [S1].
- Number of time basis functions $R_t$ [S1].
- Feature dimension $F$ [S1].
- Time parameter $t$ [S1].

**Outputs:**
- Feature vector $\mathbf{V}_t \in \mathbb{R}^F$ for a specific spatial location and time $t$ [S1].

**Data Structures:**
The naive representation stores a static feature matrix for every spatial point [S1].
- **Basis Volumes Stack ($\hat{\mathbf{V}}$):** A tensor of shape $\mathbb{R}^{XYZF \times R_t}$ [S1]. This can be viewed as a stack of $R_t$ basis volumes $\hat{\mathbf{V}}_i$, where each $\hat{\mathbf{V}}_i$ has shape $\mathbb{R}^{XYZF}$ [S1].
- **Time Coefficients ($\mathbf{f}(t)$):** A vector of shape $\mathbb{R}^{R_t}$ containing the values of the basis functions at time $t$ [S1].

**Numbered Steps:**
1. **Define Basis Functions:** Construct the vector $\mathbf{f}(t)$ using a set of sine and cosine functions, similar to positional encoding in neural radiance fields [S1]. The standard definition is:
   $$ \mathbf{f}(t) = [1, \sin(t), \cos(t), \sin(2t), \cos(2t), \sin(4t), \cos(4t), \dots] $$
   Legendre or Chebyshev polynomials were also explored as alternatives [S1].

2. **Compute Features (Naive Approach):** For a spatial location $(x,y,z)$, retrieve the feature matrix $\mathbf{M}_{xyz} \in \mathbb{R}^{F \times R_t}$ from $\hat{\mathbf{V}}$ [S1]. Compute the feature vector at time $t$ using the inner product:
   $$ \mathbf{V}_t = \sum_{i=1}^{R_t} \mathbf{f}(t)_i \cdot \hat{\mathbf{V}}_i(x,y,z) = \hat{\mathbf{V}}(x,y,z) \cdot \mathbf{f}(t) $$
   where $\hat{\mathbf{V}}(x,y,z)$ is the slice of the basis stack at $(x,y,z)$ with shape $\mathbb{R}^{F \times R_t}$ [S1].

3. **Memory Optimization (Tensor Decomposition):** Due to the memory cost of the naive approach, tensor decomposition is applied to factorize the volume into smaller components [S1]. The representation is factorized into matrices $M_{XY}, M_{XZ}, M_{YZ}$ and vectors $v_X, v_Y, v_Z$, each augmented with an additional dimension $R_t$ [S1].
   - $M_{XY}^T \in \mathbb{R}^{XY \times R_t}$ [S1].
   - $v_X^T \in \mathbb{R}^{X \times R_t}$ [S1].
   - Similar structures are used for $M_{XZ}, M_{YZ}, v_Y, v_Z$ [S1].

4. **Compute Features (Decomposed Approach):**
   a. Multiply $\mathbf{f}(t)$ with the transposed decomposition matrices and vectors along the last dimension ($R_t$) to obtain time-specific matrices $\mathbf{M}$ and vectors $\mathbf{v}$ [S1].
   b. Use the resulting $\mathbf{M}$ and $\mathbf{v}$ to calculate features following the HexPlane feature aggregation equation (Eq. 1 in [S1]) [S1].

5. **Training Regularization:**
   a. Apply a weighted L1 loss to regularize the time-decomposed components $M_{Tr}$ and $v_{Tr}$ [S1]. Higher weights are assigned to high-frequency coefficients to encourage smoothness [S1].
   b. Use smoothly bandwidth annealing during training to gradually introduce high-frequency components [S1].

import numpy as np

def compute_basis_vector(t, num_freqs=4):
    """
    Computes the basis function vector f(t).
    Args:
        t: float, time parameter.
        num_freqs: int, number of frequency pairs (excluding DC).
    Returns:
        f: np.array of shape (2 * num_freqs + 1,)
    """
    f = [1.0]
    for i in range(1, num_freqs + 1):
        f.append(np.sin(i * t))
        f.append(np.cos(i * t))
    return np.array(f)

def get_features_naive(x, y, z, t, basis_stack, f_t):
    """
    Naive feature retrieval from the full basis stack.
    Args:
        x, y, z: int, spatial coordinates.
        t: float, time.
        basis_stack: np.array of shape (X, Y, Z, F, Rt).
        f_t: np.array of shape (Rt,).
    Returns:
        V_t: np.array of shape (F,).
    """
    # Retrieve feature matrix for point (x,y,z): shape (F, Rt)
    feature_matrix = basis_stack[x, y, z, :, :]
    # Inner product: (F, Rt) dot (Rt,) -> (F,)
    V_t = np.dot(feature_matrix, f_t)
    return V_t

def get_features_decomposed(x, y, z, t, M_XY, M_XZ, M_YZ, v_X, v_Y, v_Z, f_t, Y_dim, Z_dim):
    """
    Feature retrieval using tensor decomposition.

        M_XZ: np.array of shape (XZ, Rt).
        M_YZ: np.array of shape (YZ, Rt).
        v_X: np.array of shape (X, Rt).
        v_Y: np.array of shape (Y, Rt).
        v_Z: np.array of shape (Z, Rt).
        f_t: np.array of shape (Rt,).
        Y_dim, Z_dim: int, spatial dimensions for index flattening.
    Returns:
        V_t: np.array of shape (F,).
    """
    # Map 3D coordinates to 2D indices for matrices
    # Assuming row-major flattening for XY, XZ, YZ
    xy_idx = x * Y_dim + y
    xz_idx = x * Z_dim + z
    yz_idx = y * Z_dim + z
    
    # Get time-specific components by multiplying with f_t
    # M_XY_t: shape () -> scalar for this xy
    M_XY_t = np.dot(M_XY[xy_idx, :], f_t)
    M_XZ_t = np.dot(M_XZ[xz_idx, :], f_t)
    M_YZ_t = np.dot(M_YZ[yz_idx, :], f_t)
    
    v_X_t = np.dot(v_X[x, :], f_t)
    v_Y_t = np.dot(v_Y[y, :], f_t)
    v_Z_t = np.dot(v_Z[z, :], f_t)

**Parameters:**
- $R_t$: Number of time basis functions. Typical value: 32 [S1].
- $F$: Feature dimension. Typical value: 27 [S1].
- Basis function frequencies: Powers of 2 ($1, 2, 4, \dots$) are used in the sine/cosine series [S1].

**Edge Cases and Pitfalls:**
- **Memory Overflow:** The naive implementation requires enormous GPU memory. For $X=Y=Z=128$, $R_t=32$, $F=27$, storage is ~7GB, and training memory reaches ~30GB due to back-propagation and Adam optimizer states [S1].
- **Performance:** Extremely slow due to memory I/O bottlenecks when reading/writing large volumes [S1].
- **Visual Artifacts:** Severe color jittering and distortions occur in the rendered output [S1].
- **Degenerate Input:** Fails to produce satisfactory results when objects move too fast or when there are too few observations to synthesize details [S1].

## Subtopics

### [HexPlane](6885-space-time-representations.md)
The successful method that replaced this design. It uses a different feature aggregation strategy to avoid the memory and artifact issues of the fixed basis approach.

## Operating characteristics
- **Time Complexity:** Extremely high due to memory I/O bottlenecks in the naive implementation. The decomposed version reduces memory footprint but adds computational overhead for the tensor contractions [S1].
- **Memory Complexity:**
  - Naive: $O(XYZF R_t)$. Example: 7GB for $128^3$ volume [S1].
  - Decomposed: Significantly reduced by factorizing into $M_{XY}, M_{XZ}, M_{YZ}, v_X, v_Y, v_Z$ [S1].
- **Strengths:** Conceptually simple; leverages traditional time-series basis function approaches [S1].
- **Limitations:** Proven to be a "failed design" due to intractable memory usage, slow training/inference speeds, and poor visual quality (color jittering, distortions) [S1].
- **When to use:** Not recommended for production. Included primarily as a cautionary example of what not to do in dynamic scene representation [S1].

## Background
This method was explored as part of the development of HexPlane, a fast representation for dynamic scenes [S1]. The authors initially attempted to model dynamic scenes by extending the query space with time using fixed basis functions, similar to positional encoding [S1]. However, they found this approach computationally infeasible and visually inferior, leading to the development of the HexPlane architecture which uses feature planes instead of a full 3D basis stack [S1]. The design is discussed in Section 9.1 of the HexPlane paper as a "Failed Design for Dynamic Scenes" [S1].
