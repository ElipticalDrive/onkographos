# Local Solver

Also called: Block-based Solver, Block-based gradient solver, Block-wise CG Solver, Compressive Rendering (Local Solver), Local Conjugate Gradient Solver, Tiled CG Solver, Tiled Solver

## Overview
The Local Solver is a parallel implementation of the conjugate gradient solver for compressive volume rendering that partitions the image into smaller, mutually exclusive blocks to reduce global memory access and improve performance using shared memory [S1, unofficial]. It reconstructs a full image by solving each block independently and merging the outputs [S1, unofficial]. It differs from the Global Solver [4281-global-solver.md] by processing blocks independently, which allows for different numbers of iterations per block based on local convergence criteria [S1, unofficial].

## How it works
The method solves the linear system $(S^T S + \lambda H)x = S^T y$ derived from the compressive rendering formulation, where $S$ is the sampling matrix, $H$ is the convolution filter, $\lambda$ is a regularization parameter, and $y$ is the given image with missing pixels [S1, unofficial].

### Inputs and Outputs
*   **Inputs**: The sampling matrix $S$, the convolution filter $H$, the regularization parameter $\lambda$, and the input image $y$ containing missing pixels [S1, unofficial].
*   **Outputs**: The reconstructed volume density field $x$ [S1, unofficial].

### Data Structures
*   **Shared Memory**: Used per block to store intermediate vectors for the conjugate gradient algorithm [S1, unofficial]. The amount of memory is limited, typically 48 KB per block [S1, unofficial].
*   **Ghost Elements**: A padded region surrounding each image block containing known pixels from neighboring blocks to incorporate neighborhood information [S1, unofficial].

### Parameters
*   **Thread Configuration**: The number of threads per block in the x and y dimensions, denoted as $threadSize_x$ and $threadSize_y$ [S1, unofficial]. A configuration of $16 \times 16$ threads produces the best results [S1, unofficial].
*   **Padding Size ($P$)**: The size of the ghost element border, defined as $P = kernelWidth/2$, where $kernelWidth$ is the width of the convolution filter [S1, unofficial].

### Number of Blocks
The image is partitioned into blocks [S1, unofficial]. The number of blocks in each dimension is calculated as:
$$
blockNumber_x = \frac{imageWidth - P}{threadSize_x + P}
$$
$$
blockNumber_y = \frac{imageHeight - P}{threadSize_y + P}
$$
[S1, unofficial]

### Algorithm Steps
1.  **Partition**: Divide the image data into mutually exclusive blocks of size $(threadSize_x + P) \times (threadSize_y + P)$, including the padding region [S1, unofficial].
2.  **Pad**: For each block, populate the border region of size $P$ with "ghost elements" (known pixels) from the neighboring blocks in the original image $y$ [S1, unofficial]. This ensures the convolution operation has access to neighborhood data [S1, unofficial].
3.  **Initialize**: For each block, initialize the conjugate gradient vectors ($r, p, x$) based on the local sub-problem defined by the padded block data [S1, unofficial].
4.  **Iterate**: Run the conjugate gradient solver locally for each block [S1, unofficial].
    *   Perform block-wise convolution using the shared memory [S1, unofficial].
    *   Perform vector dot product reductions using parallel reduction (complexity $O(\log n)$) within the block [S1, unofficial].
    *   Update vectors $r, p, x$ [G].
    *   Check for convergence [G]. Since blocks are independent, each block may require a different number of iterations to converge [S1, unofficial].
5.  **Synchronize**: Use `syncthreads()` within each block to ensure correct execution order when writing to shared memory, as global fences do not apply [S1, unofficial].
6.  **Merge**: Combine the reconstructed blocks into the final image [S1, unofficial].

### Pseudocode
```python
def zeros(shape):
    """Returns a list of zeros with the given shape."""
    if len(shape) == 1:
        return [0.0] * shape[0]
    return [[0.0] * shape[1] for _ in range(shape[0])]

def zeros_like(arr):
    """Returns a zero array with the same shape as arr."""
    rows = len(arr)
    cols = len(arr[0]) if isinstance(arr[0], list) else 1
    return zeros((rows, cols))

def local_solver(image_width, image_height, sampling_matrix_S, convolution_filter_H, lambda_param, input_image_y, max_iterations=100, tolerance=1e-6):
    """
    Solves the compressive rendering problem using a block-wise conjugate gradient solver.
    """
    # Parameters
    thread_size_x = 16
    thread_size_y = 16
    kernel_width = len(convolution_filter_H)
    P = kernel_width // 2
    
    # Calculate block dimensions
    block_width = thread_size_x + P
    block_height = thread_size_y + P
    
    # Calculate number of blocks
    num_blocks_x = (image_width - P) // block_width
    num_blocks_y = (image_height - P) // block_height
    
    # Initialize output image
    reconstructed_image = zeros((image_height, image_width))
    
    for bx in range(num_blocks_x):
        for by in range(num_blocks_y):
            # 1. Extract block coordinates
            x_start = bx * block_width
            y_start = by * block_height
            
            # 2. Create local block data with ghost elements
            local_block = zeros((block_height, block_width))
            
            # Copy center data from input image
            for i in range(thread_size_y):
                for j in range(thread_size_x):
                    local_block[P + i][P + j] = input_image_y[y_start + i][x_start + j]
            
            # Fill ghost elements (padding) from neighbors [G]
            # Top padding
            if by > 0:
                for i in range(P):
                    for j in range(thread_size_x):
                        local_block[i][P + j] = input_image_y[y_start - P + i][x_start + j]
            # Bottom padding
            if by < num_blocks_y - 1:
                for i in range(P):
                    for j in range(thread_size_x):
                        local_block[thread_size_y + P + i][P + j] = input_image_y[y_start + thread_size_y + i][x_start + j]
            # Left padding
            if bx > 0:
                for i in range(thread_size_y):
                    for j in range(P):
                        local_block[P + i][j] = input_image_y[y_start + i][x_start - P + j]
            # Right padding
            if bx < num_blocks_x - 1:
                for i in range(thread_size_y):
                    for j in range(P):
                        local_block[P + i][thread_size_x + P + j] = input_image_y[y_start + i][x_start + thread_size_x + j]
            
            # Flatten block for vector-based CG solver
            b_vec = [val for row in local_block for val in row]
            
            # 3. Run Conjugate Gradient on local block
            # The system is (S_local^T S_local + lambda H) x_local = S_local^T y_local
            x_local_vec = conjugate_gradient_local(b_vec, sampling_matrix_S, convolution_filter_H, lambda_param, max_iterations, tolerance)
            
            # Reshape result back to block coordinates
            x_local = zeros((block_height, block_width))
            for idx, val in enumerate(x_local_vec):
                r = idx // block_width
                c = idx % block_width
                x_local[r][c] = val
            
            # 4. Store result back to global image (only the center part)
            for i in range(thread_size_y):
                for j in range(thread_size_x):
                    reconstructed_image[y_start + i][x_start + j] = x_local[P + i][P + j]
                    
    return reconstructed_image

def conjugate_gradient_local(b, A_mat, lambda_param, H_mat, max_iterations, tolerance):
    """
    Standard Conjugate Gradient solver for the local block.
    A_mat represents the system matrix derived from S and H.
    """
    # Initialize
    x = zeros_like(b)
    r = [b[i] - mat_vec_mul(A_mat, x)[i] for i in range(len(b))]
    p = list(r)
    rs_old = dot_product(r, r)
    
    # Iteration
    for i in range(max_iterations):
        Ap = mat_vec_mul(A_mat, p)
        pAp = dot_product(p, Ap)
        
        if pAp == 0: break # Singular matrix
        
        alpha = rs_old / pAp
        x = [x[i] + alpha * p[i] for i in range(len(x))]
        r = [r[i] - alpha * Ap[i] for i in range(len(r))]
        
        rs_new = dot_product(r, r)
        
        if (rs_new ** 0.5) < tolerance: break
        
        p = [r[i] + (rs_new / rs_old) * p[i] for i in range(len(p))]
        rs_old = rs_new
        
    return x

def mat_vec_mul(M, v):
    """Matrix-vector multiplication."""
    return [sum(M[i][k] * v[k] for k in range(len(v))) for i in range(len(M))]

def dot_product(v1, v2):
    """Parallel reduction dot product."""
    return sum(v1[i] * v2[i] for i in range(len(v1)))
```

### Edge Cases and Pitfalls
*   **Boundary Artifacts**: Without padding with ghost elements, the local solver generates incoherent results and boundary artifacts around the border of each block because the convolution lacks neighborhood information [S1, unofficial].
*   **Shared Memory Limits**: The limited amount of shared memory (e.g., 48 KB) restricts the size of the blocks and the number of vectors that can be stored simultaneously [S1, unofficial].
*   **Race Conditions**: Uncontrolled execution of threads may lead to race conditions if multiple threads try to read/write the same shared memory location without synchronization [S1, unofficial].
*   **Synchronization Scope**: `syncthreads()` only synchronizes threads within a block. It does not act as a global fence, so care must be taken when merging results [S1, unofficial].

## Operating characteristics
*   **Performance**: The local solver significantly improves performance compared to the global solver by reducing global memory traffic [S1, unofficial]. Using shared memory for block-level computations avoids the bottleneck of global memory access [S1, unofficial]. At 60% pixel coverage, the local solver takes 5.6 milliseconds, which is 24 times faster than the global solver's 119 milliseconds [S1, unofficial].
*   **Complexity**: The parallel reduction for dot products has a complexity of $O(\log n)$, which is more efficient than the $O(n)$ complexity of sequential summation [S1, unofficial].
*   **Adaptivity**: Since each block is solved independently, the solver can adapt the number of iterations per block based on local convergence, potentially reducing computational cost [S1, unofficial].
*   **Limitations**: The method is constrained by the limited shared memory per block. It also requires careful handling of block boundaries via padding [S1, unofficial].

## Background
The Local Solver was proposed as part of a parallel approach to GPU-based compressive volume rendering to address the poor performance of global solvers on GPUs due to high data transfer rates between CPU and GPU and global memory bottlenecks [S1, unofficial]. It builds on the global solver approach [4281-global-solver.md] by decomposing the global problem into local problems [S1, unofficial]. The method was detailed in a thesis by Liu and Alim et al., which compared CPU-based reconstruction times with parallel GPU approaches [S1, unofficial].
