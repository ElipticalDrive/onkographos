# L-Curve Regularization Parameter Selection
Also called: Alpha Sweep, L-curve, L-Curve Parameter Selection

## Overview
L-Curve Regularization Parameter Selection determines the optimal regularization parameter $\alpha$ for ill-posed inverse problems by plotting the norm of the solution $\|f\|$ against the norm of the residual $\|r\|$ on a log-log scale and identifying the curve's corner [S1, unofficial]. It solves the trade-off between data fidelity and solution smoothness without requiring a direct error metric like MSE, unlike grid search methods [S1, unofficial].

## How it works
**Inputs:**
- A range of regularization parameters $\alpha$, typically logarithmically spaced (e.g., $10^{\text{linspace}(-3, 4, 15)}$) [S1, unofficial].
- The noisy sinogram data $g$ [S1, unofficial].
- The forward projection operator $A$ (Radon transform) [S1, unofficial].
- The regularization type (e.g., 0-order or 1st-order Tikhonov) [S1, unofficial].
- Solver and geometry parameters (number of angles, samples, volume dimensions) [S1, unofficial].

**Outputs:**
- The optimal regularization parameter $\alpha_{opt}$ corresponding to the L-curve corner [S1, unofficial].
- Arrays of solution norms $\|f_\alpha\|$ and residual norms $\|r_\alpha\|$ for all tested $\alpha$ [S1, unofficial].

**Data Structures:**
- `alphas`: 1D array of floats, logarithmically spaced values for $\alpha$ [S1, unofficial].
- `fi_norms`: 1D array of floats, storing $\|f_\alpha\|$ for each $\alpha$ [S1, unofficial].
- `r_norms`: 1D array of floats, storing $\|r_\alpha\|$ for each $\alpha$ [S1, unofficial].
- `keys`: List of tuples/arrays, storing `[fi_norm, r_norm, alpha]` for each iteration [S1, unofficial].

**Steps:**
1. Generate a logarithmic grid of regularization parameters $\alpha$. A common range is $10^{-3}$ to $10^{4}$ with 15 points [S1, unofficial].
2. For each $\alpha$ in the grid:
   a. Solve the regularized inverse problem to obtain the reconstruction $f_\alpha$ [S1, unofficial].
   b. Compute the forward projection of the solution: $p_\alpha = A f_\alpha$ [S1, unofficial].
   c. Compute the residual vector: $r_\alpha = g - p_\alpha$ [S1, unofficial].
   d. Compute the solution norm: $\text{fi\_norm} = \|f_\alpha\|$ [S1, unofficial].
   e. Compute the residual norm: $\text{r\_norm} = \|r_\alpha\|$ [S1, unofficial].
   f. Store $\text{fi\_norm}$, $\text{r\_norm}$, and $\alpha$ [S1, unofficial].
3. Plot $\text{r\_norm}$ versus $\text{fi\_norm}$ on a log-log scale [S1, unofficial].
4. Identify the "corner" of the curve, which represents the optimal trade-off between data fidelity and solution smoothness [S1, unofficial]. In the provided implementation, this is manually selected by index (e.g., `idx_sp = 5` or `idx_lim = 6`) [S1, unofficial].

**Formulas:**
- Residual: $r_\alpha = g - A f_\alpha$ [S1, unofficial]
- Solution Norm: $\text{fi\_norm} = \|f_\alpha\|$ [S1, unofficial]
- Residual Norm: $\text{r\_norm} = \|r_\alpha\|$ [S1, unofficial]

**Parameters:**
- `theta`: Noise level for the sinogram. Typical value used in examples is $10000$ [S1, unofficial].
- `alphas`: Logarithmically spaced array. Example: `10.0**np.linspace(-3, 4, 15)` [S1, unofficial].

**Edge Cases and Pitfalls:**
- The "corner" can be ambiguous in noisy data or for certain regularization types, often requiring manual index selection or curvature-based heuristics [S1, unofficial].
- The method assumes the L-curve shape is well-defined; for some ill-conditioned systems, the curve may not exhibit a clear corner [G].
- Computational cost increases linearly with the number of $\alpha$ values tested, as each requires a full independent solve [G].

**Pseudocode:**
```python
import numpy as np

def l_curve_selection(g, A, alphas, solve_func, project_func):
    """
    Selects optimal alpha using the L-curve method.
    Args:
        g: Noisy sinogram data (vector).
        A: Forward projection operator (matrix or callable).
        alphas: Array of regularization parameters to test.
        solve_func: Function that solves the regularized inverse problem for a given alpha.
        project_func: Function that computes forward projection.
    Returns:
        alpha_opt: Optimal regularization parameter.
        fi_norms: Array of solution norms.
        r_norms: Array of residual norms.
    """
    n_alphas = len(alphas)
    fi_norms = np.zeros(n_alphas)
    r_norms = np.zeros(n_alphas)

    for i, alpha in enumerate(alphas):
        # Solve the regularized problem
        f_alpha = solve_func(g, A, alpha)

        # Compute forward projection
        p_alpha = project_func(f_alpha, A)

        # Compute residual and norms
        r_alpha = g - p_alpha
        fi_norms[i] = np.linalg.norm(f_alpha)
        r_norms[i] = np.linalg.norm(r_alpha)

    # Identify the corner of the L-curve
    # The source implementation manually selects the index (e.g., idx_sp = 5)
    # Standard heuristic: maximize curvature of the log-log plot [G]
    log_fi = np.log(fi_norms)
    log_r = np.log(r_norms)

    dx = np.gradient(log_fi)
    dy = np.gradient(log_r)
    ddx = np.gradient(dx)
    ddy = np.gradient(dy)

    numerator = np.abs(dx * ddy - dy * ddx)
    denominator = np.power(dx**2 + dy**2, 1.5)
    denominator = np.where(denominator == 0, 1e-10, denominator)
    kappa = numerator / denominator

    idx_opt = np.argmax(kappa)
    alpha_opt = alphas[idx_opt]

    return alpha_opt, fi_norms, r_norms
```

## Subtopics

### Curvature-Based Corner Detection
Automated method to find the L-curve corner by maximizing curvature on the log-log plot, removing manual selection [G]. Chosen when high-throughput parameter tuning is required.

### Generalized L-Curve
Extension using different norms or regularization terms when the standard L-curve lacks a clear corner [G]. Chosen for non-standard ill-posed formulations.

## Operating characteristics
- **Time Complexity**: $O(N \cdot T)$, where $N$ is the number of regularization parameters tested and $T$ is the time to solve the inverse problem for one $\alpha$ [G]. Each solve is independent, allowing parallelization [G].
- **Memory Complexity**: $O(N + M)$, where $M$ is the memory required for one solution $f_\alpha$ and residual $r_\alpha$ [G].
- **Strengths**: Does not require knowledge of the noise level or true solution; provides a visual diagnostic of the regularization trade-off [S1, unofficial].
- **Limitations**: Computationally expensive due to multiple solves; the "corner" can be ambiguous or non-existent for some problems; manual selection introduces subjectivity [S1, unofficial].
- **When to use**: When the noise level is unknown and a robust, visually interpretable method for parameter selection is needed [S1, unofficial].
- **When not to use**: When computational resources are limited and a single solve is preferred; when the L-curve does not exhibit a clear corner [G].

## Background
The L-curve method was introduced by Per Christian Hansen as a tool for selecting regularization parameters in discrete ill-posed problems [G]. It has been applied in various fields including image processing and tomography. In the provided source, it is used to select $\alpha$ for Tikhonov regularization in CT reconstruction [S1, unofficial].
