# Global Solver
## Overview
The Global Solver is a compressive volume rendering reconstruction method that treats the entire image as a single unit for inverse rendering recovery [S1, unofficial]. It solves for missing pixel values by running a solver over the full image domain simultaneously, contrasting with block-based partitioning strategies [S1, unofficial]. It addresses the problem of recovering high-quality volumes from images with high missing pixel rates [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: volume rendering image with missing pixels [S1, unofficial].
- Output: reconstructed full-resolution image [S1, unofficial].

**Data Structures:**
- The method operates on the entire image matrix as a single entity without partitioning it into blocks [S1, unofficial].

**Steps:**
1. Initialize the solver for the entire image domain [S1, unofficial].
2. Set the iteration parameter, which can be fixed to a constant value or controlled via a flag to run until a desired solution is reached [S1, unofficial].
3. Execute the iterative solver loop.
4. Inside the loop, perform the convolution process, identified as the most time-consuming operation [S1, unofficial].
5. Update the image data iteratively until the fixed iteration count is met or the convergence flag indicates a desired solution is arrived at [S1, unofficial].

**Parameters:**
- **Number of iterations:** Affects solver performance; can be fixed or set via a flag to run multiple times until a desired solution is arrived at [S1, unofficial].

**Pitfalls:**
- **FFT-based convolution overhead:** Using Fast Fourier Transform (FFT) for convolution causes memory to be copied back and forth from CPU to GPU for each iteration, resulting in very slow reconstruction time [S1, unofficial].

## Subtopics

### [Local Solver](4294-local-solver.md)
A parallel implementation that partitions the image into mutually exclusive blocks to reduce global memory access and improve performance using shared memory. It differs from the Global Solver by processing blocks independently, allowing for different numbers of iterations per block based on local convergence criteria.

## Operating characteristics
- **Time Complexity:** High, as the convolution process is the most time-consuming operation [S1, unofficial].
- **Memory Access:** Inefficient when using FFT-based convolution due to frequent CPU/GPU memory transfers [S1, unofficial].
- **Measured Performance:** Reconstruction time of approximately 124 milliseconds (about 10 frames per second) when 60% of pixels are missing (40% present) [S1, unofficial]. The global solver takes 119 milliseconds using only 60% pixels [S1, unofficial].
- **Scaling:** Not well suited for interactivity due to the high reconstruction time [S1, unofficial].
- **Strengths:** Provides a global solution for the entire image, maintaining consistency across the full domain [S1, unofficial].
- **Limitations:** Very slow reconstruction time compared to local solvers; for example, the Local Solver takes 5.6 milliseconds for the same task, making it 24 times faster [S1, unofficial].
- **When to use:** When global consistency is prioritized over speed and interactivity is not required [S1, unofficial].
- **When not to use:** When interactive frame rates are needed [S1, unofficial].

## Background
The Global Solver was proposed in a thesis on GPU-based compressive volume rendering as one of two parallel approaches to reconstruction, the other being the Local Solver [S1, unofficial]. It builds on gradient solver techniques previously demonstrated by Liu and Alim et al., who measured reconstruction times using a CPU [S1, unofficial]. The method was developed to address the limitations of CPU-based reconstruction and to provide a baseline for comparing block-based optimizations [S1, unofficial].
