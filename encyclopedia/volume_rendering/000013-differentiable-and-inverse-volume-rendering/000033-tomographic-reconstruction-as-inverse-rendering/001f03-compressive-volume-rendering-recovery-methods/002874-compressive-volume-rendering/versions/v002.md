# Compressive Volume Rendering

Also called: Compressive Rendering

## Overview
Compressive Volume Rendering is a technique that renders a full-resolution image by tracing rays for only a sparse subset of pixels and reconstructing the remaining pixels using an image representation model [S1, unofficial]. It extends the two-step compressive rendering proposal by Sen and Darabi [40] by replacing compressed sensing with a smoothness-based recovery approach [S1, unofficial].

## How it works
**Inputs:**
- Image dimensions $W \times H$.
- Total pixel count $N = W \times H$.
- Target number of rendered pixels $M$, where $M \ll N$ [S1, unofficial].
- Rendering engine capable of tracing rays through the volume [G].

**Outputs:**
- Full-resolution image $x$ of size $N \times 1$ (linearized) [S1, unofficial].
- Sparse measurements $y$ of size $M \times 1$ [S1, unofficial].

**Data Structures:**
1. **Sampling Matrix $S$**: An $M \times N$ binary matrix where each row contains exactly one `1` at the index corresponding to a pixel location to be rendered, and `0` elsewhere [S1, unofficial].
2. **Kernel Function $\phi(t)$**: A bi-variate interpolating kernel defined as the tensor product $\phi(t_1, t_2) = \beta_3^I(t_1)\beta_3^I(t_2)$, where $\beta_3^I$ is the optimal interpolating cubic B-spline [S1, unofficial].
3. **Hessian Matrix $H$**: An $N \times N$ symmetric matrix representing the smoothness penalty, where $H_{p,q} = \langle \phi(\cdot - j_p), \phi(\cdot - j_q) \rangle_{BL^2}$ [S1, unofficial].

**Steps:**

1. **Pixel Selection**: Select $M$ pixel locations from the $N$ total pixels. The selection should follow a low-discrepancy distribution (e.g., linear pixel shuffling or Poisson-disk sampling) [S1, unofficial]. Let $K = \{k_1, \dots, k_M\}$ be the set of selected 2D pixel coordinates.
2. **Sparse Rendering**: Trace rays only for the pixels in $K$. Collect the resulting color/intensity values into the vector $y \in \mathbb{R}^M$. This establishes the relationship $y = Sx$, where $x$ is the unknown full image vector [S1, unofficial].
3. **Formulation**: The reconstruction problem is formulated as minimizing the following objective function:
   $$ \min_f \lambda \|f\|_{BL^2}^2 + \sum_{m=1}^M (f(k_m) - y_m)^2 $$
   where $f(t)$ is approximated by coefficients $c$ such that $f(t) = \sum_{n=1}^N c_n \phi(t - j_n)$, $j_n$ are the 2D locations of all pixels in $x$, and $\lambda$ is a smoothing parameter [S1, unofficial].
4. **Matrix Assembly**: Convert the continuous minimization problem into a discrete linear system. The problem becomes:
   $$ \min_x \|Sx - y\|_2^2 + \lambda x^T H x $$
   where $H$ is the convolution matrix defined by the Beppo-Levi inner product of the kernel functions [S1, unofficial]. The Beppo-Levi inner product for functions $g$ and $h$ is:
   $$ \langle g, h \rangle_{BL^2} := \langle \partial_{t_1}^2 g, \partial_{t_1}^2 h \rangle + 2\langle \partial_{t_1}\partial_{t_2} g, \partial_{t_1}\partial_{t_2} h \rangle + \langle \partial_{t_2}^2 g, \partial_{t_2}^2 h \rangle $$
   where $\langle \cdot, \cdot \rangle$ is the standard $L^2$ inner product $\int_{\mathbb{R}^2} f(x)g(x)dx$ [S1, unofficial].
5. **Solution**: Solve the linear system for $x$. The gradient of the objective function with respect to $x$ is:
   $$ \nabla E(x) = 2S^T(Sx - y) + 2\lambda H x $$
   Setting the gradient to zero yields the normal equation:
   $$ (S^T S + \lambda H) x = S^T y $$
   Let $A = S^T S + \lambda H$ and $b = S^T y$. Solve $Ax = b$ using an iterative solver such as Conjugate Gradient [S1, unofficial].

    for idx in sampled_indices:

        v = idx // W
        # Standard volume rendering step
        color = trace_ray(u, v, volume_data)
        y.append(float(color))

    # b = S^T y

    # We define a matvec function for H to avoid explicit O(N^2) storage.

        # For cubic B-splines, the kernel support is small (radius 2).
        # Hx is computed via separable convolution.

def conjugate_gradient_solver(matvec_A, b, N, max_iter=1000, tol=1e-6):
    x = [0.0] * N
    r = [b[i] - matvec_A(x)[i] for i in range(N)]
    p = r[:]
    r_dot_r = sum(r[i] * r[i] for i in range(N))
    
    for k in range(max_iter):
        Ap = matvec_A(p)
        pAp = sum(p[i] * Ap[i] for i in range(N))
        if pAp == 0:
            break
        alpha = r_dot_r / pAp
        for i in range(N):
            x[i] += alpha * p[i]
        r_new = [r[i] - alpha * Ap[i] for i in range(N)]
        r_new_dot_r_new = sum(r_new[i] * r_new[i] for i in range(N))
        if r_new_dot_r_new < tol:
            break
        beta = r_new_dot_r_new / r_dot_r
        for i in range(N):
            p[i] = r_new[i] + beta * p[i]
        r = r_new
        r_dot_r = r_new_dot_r_new
    return x

**Parameters:**
- $\lambda$: Smoothing parameter. Controls the trade-off between fidelity to the rendered pixels and the smoothness of the reconstructed image [S1, unofficial].
- Kernel: Optimal interpolating cubic B-spline $\beta_3^I$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision**: The matrix $H$ can be ill-conditioned if $\lambda$ is too small or too large [G]. A typical range for $\lambda$ is determined empirically based on the noise level of the volume rendering [G].
- **Boundaries**: The convolution matrix $H$ requires boundary handling. The source mentions "automatic boundary handling" but does not specify the exact method [S1, unofficial]. Zero-padding is a common default for such convolutions [G].
- **Degenerate Input**: If $M=0$, the problem is unsolvable. If $M=N$, the problem reduces to standard rendering with no reconstruction needed [G].

## Operating characteristics
- **Time Complexity**: The rendering phase is $O(M \cdot R)$, where $R$ is the average ray length. The reconstruction phase involves solving a linear system of size $N \times N$. Using Conjugate Gradient, each iteration is $O(N)$ if $H$ is applied via convolution (since $H$ is sparse/banded). The number of iterations depends on the condition number of $A$ [G].
- **Memory Complexity**: Storing $H$ explicitly requires $O(N \cdot \text{support}^2)$ space. If $H$ is applied via convolution, only the kernel needs to be stored, reducing memory to $O(1)$ relative to $N$ (excluding the image buffer). The sampling matrix $S$ is stored implicitly [G].
- **Performance**: The method reduces rendering time by a factor of $N/M$. However, the reconstruction cost must be considered. For large $N$, the conjugate gradient solver can be expensive [S1, unofficial]. The solver is implemented on CUDA for acceleration [S1, unofficial].
- **Strengths**: Significant reduction in ray-casting overhead. High-quality recovery if the image is smooth [S1, unofficial].
- **Limitations**: Reconstruction artifacts if the image is not smooth or if $M$ is too small. The method assumes the image can be well-approximated by the chosen kernel basis [S1, unofficial].
- **When to use**: When ray casting is the bottleneck and the volume rendering result is expected to be spatially smooth [G].
- **When not to use**: When high-frequency details are critical and cannot be interpolated, or when $M$ cannot be reduced significantly [G].

## Background
Compressive Volume Rendering was initially proposed by Sen and Darabi [40] as cited in [S1, unofficial]. The method extends the concept of compressive rendering to volume data. The thesis [S1, unofficial] modifies the original proposal by using linear pixel shuffling instead of Poisson-disk distribution and a smoothness-based approach by Liu and Alim [4] instead of general compressed sensing, showing better performance. The kernel choice is based on work by Blu et al. [48] [S1, unofficial].
