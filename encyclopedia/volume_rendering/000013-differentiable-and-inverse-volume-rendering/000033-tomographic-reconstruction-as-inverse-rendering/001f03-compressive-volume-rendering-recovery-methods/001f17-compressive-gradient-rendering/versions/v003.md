# Compressive Gradient Rendering

Also called: CS-Gradient

## Overview
Compressive Gradient Rendering is a compressive sensing technique that renders discrete gradient components instead of pixel values to exploit sparsity in the Fourier domain, then reconstructs the image using a Poisson solver [S1, unofficial]. It differs from standard Compressive Volume Rendering by operating on gradient fields rather than intensity values, allowing for higher recovery rates with fewer samples by leveraging the sparsity of image derivatives [S1, unofficial].

## How it works
**Inputs:**
- Volume data (implicit or explicit).
- Sampling matrix $\mathbf{S}$ defining $m$ random pixel locations.
- Tolerance parameter $\epsilon$ for noise/convergence.
- Kernel choice for gradient estimation (e.g., bilinear B-spline or Mitchell-Netravali cubic) [S1, unofficial].

**Outputs:**
- Reconstructed 2D image $\mathbf{x}$.

**Data Structures:**
- $\mathbf{y}_1, \mathbf{y}_2$: Vectors of size $m \times 1$ containing measured horizontal and vertical gradient components at sampled locations.
- $\hat{\mathbf{x}}_1, \hat{\mathbf{x}}_2$: Vectors of size $N \times 1$ (where $N$ is total pixels) representing the 2D Discrete Fourier Transform (DFT) of the horizontal and vertical gradient components, respectively.
- $\mathbf{F}^{-1}$: The inverse 2D DFT matrix.

**Steps:**

1. **Render Horizontal Gradient Component ($x_1$):**
   Compute the horizontal gradient component $x_1$ for each ray. This is achieved by weighting incoming rays with the derivative of the pixel reconstruction kernel (e.g., the derivative of a bilinear B-spline or Mitchell-Netravali cubic kernel) [S1, unofficial]. Alternatively, render using a box filter and apply finite differencing to obtain the gradient [S1, unofficial]. Collect these values into vector $\mathbf{y}_1$ at the $m$ sampled locations defined by $\mathbf{S}$.

2. **Render Vertical Gradient Component ($x_2$):**
   Compute the vertical gradient component $x_2$ similarly to step 1. Collect these values into vector $\mathbf{y}_2$ at the same $m$ sampled locations.

3. **Recover Horizontal Gradient Spectrum ($\hat{\mathbf{x}}_1$):**
   Solve the $l_1$ minimization problem to recover the DFT of the horizontal gradient. The sensing mechanism is defined as:
   $$ \mathbf{y}_1 = \mathbf{S}\mathbf{F}^{-1}\hat{\mathbf{x}}_1 $$
   where $\mathbf{S}$ is the sampling matrix, $\mathbf{F}^{-1}$ is the inverse 2D DFT matrix, and $\hat{\mathbf{x}}_1$ is the 2D DFT of the horizontal gradient [S1, unofficial].
   The recovery is formulated as:
   $$ \min \|\hat{\mathbf{x}}_1\|_1 \quad \text{subject to} \quad \|\mathbf{S}\mathbf{F}^{-1}\hat{\mathbf{x}}_1 - \mathbf{y}_1\|_2 \leq \epsilon $$
   [S1, unofficial].

4. **Recover Vertical Gradient Spectrum ($\hat{\mathbf{x}}_2$):**
   Solve the analogous $l_1$ minimization problem for the vertical gradient component to obtain $\hat{\mathbf{x}}_2$:
   $$ \min \|\hat{\mathbf{x}}_2\|_1 \quad \text{subject to} \quad \|\mathbf{S}\mathbf{F}^{-1}\hat{\mathbf{x}}_2 - \mathbf{y}_2\|_2 \leq \epsilon $$
   [S1, unofficial].

5. **Reconstruct Image ($\mathbf{x}$):**
   Reconstruct the image $\mathbf{x}$ from the gradient components by applying a Poisson solver with Dirichlet boundary conditions to the divergence of the gradient [S1, unofficial]. This involves inverting the relationship between the image and its gradients in the frequency domain or solving the resulting linear system in the spatial domain.

**Parameters:**
- $\epsilon$: Noise tolerance or convergence threshold. Typical values depend on the noise level in the rendered gradient measurements [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** The Poisson solver requires boundary conditions. Dirichlet conditions (setting boundary pixels to zero or known values) are specified, but incorrect handling can introduce artifacts at the image edges [S1, unofficial].
- **Random Sampling:** The theory assumes random pixel locations to ensure $\mathbf{S}\mathbf{F}^{-1}$ is a partial Fourier matrix, which is crucial for compressive sensing guarantees. Structured sampling may degrade performance [S1, unofficial].
- **Gradient Sparsity:** The method relies on the assumption that image gradients are sparse in the Fourier domain. Images with high-frequency noise or non-sparse gradients may not compress well [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Dominated by the $l_1$ minimization steps for each gradient component and the Poisson solver. $l_1$ minimization is generally iterative and computationally expensive, scaling with the number of samples and image size. The Poisson solver is typically $O(N \log N)$ or $O(N)$ with multigrid methods.
- **Memory Complexity:** Requires storage for the gradient spectra ($\hat{\mathbf{x}}_1, \hat{\mathbf{x}}_2$) and the sampling matrix. $O(N)$ where $N$ is the number of pixels.
- **Strengths:** Exploits sparsity in the gradient domain, which can be higher than in the pixel domain, allowing for recovery from fewer samples. Effective for images with piecewise constant regions.
- **Limitations:** Requires solving two $l_1$ minimization problems and a Poisson solver, increasing computational cost compared to direct reconstruction. Sensitive to the choice of sampling pattern and kernel.
- **When to Use:** When the image is expected to be sparse in the gradient domain and the number of samples is significantly less than the Nyquist rate. Suitable for applications like MRI or specific volume rendering scenarios where gradient sparsity is a strong prior [S1, unofficial].
- **When Not to Use:** For images with high-frequency noise or non-sparse gradients. When computational resources are limited and faster, less accurate methods are acceptable.

## Background
Compressive Gradient Rendering was introduced in the context of Compressive Volume Rendering, aiming to handle higher percentages of missing pixels by exploiting sparsity in the gradient domain [S1, unofficial]. The method builds on compressive sensing theory, which suggests that point measurements in the DFT domain are ideal, but since rendering typically produces pixel measurements, rendering gradient components is a practical alternative [S1, unofficial]. The approach follows the gradient-domain image processing framework by Pérez et al., using a Poisson solver for reconstruction [S1, unofficial].
