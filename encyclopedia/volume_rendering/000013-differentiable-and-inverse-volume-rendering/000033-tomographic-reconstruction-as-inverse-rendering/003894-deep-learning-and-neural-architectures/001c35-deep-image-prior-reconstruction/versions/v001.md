# Deep Image Prior Reconstruction

Also called: DIP Reconstruction, DRP Denoising

## Overview
Deep Image Prior Reconstruction (DIP Reconstruction) is an iterative inverse rendering method that uses a neural network as an implicit regularizer to solve for a volume or image from sparse or noisy projection data [S1, unofficial]. It distinguishes itself from traditional iterative methods like SIRT by optimizing the network weights to fit the data while simultaneously updating a latent variable to maintain data consistency, leveraging the bias of convolutional architectures toward natural image structures [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Sparse sinogram $p$ (measured projections).
- **Input:** A differentiable projector (forward and backward projection operators).
- **Input:** A PriorModel (neural network architecture, e.g., U-Net or CNN).
- **Output:** Reconstructed image/volume $x$.

**Data Structures:**
The method maintains:
- $z$: Latent variable tensor, same shape as the reconstruction grid.
- $\theta$: Parameters of the PriorModel.
- Optimizer state for Adam.

**Parameters:**
- `epochs`: Number of outer optimization epochs. Default: 250 [S1, unofficial].
- `inner_steps`: Number of Adam optimization steps on PriorModel weights per epoch. Default: 50 [S1, unofficial].
- `beta`: Step size for the latent variable update. Default: 0.25 [S1, unofficial].
- `lr`: Learning rate for the Adam optimizer on PriorModel weights. Not given in the sources.

**Algorithm Steps:**

1. **Initialization:**
   - Initialize the PriorModel with random weights.
   - Initialize the Adam optimizer with the PriorModel's parameters and learning rate `lr` [S1, unofficial].
   - Compute an initial estimate of the reconstruction by applying Filtered Back Projection (FBP) to the sinogram $p$: $z_{init} = \text{FBP}(p)$ [S1, unofficial].
   - Detach $z_{init}$ from the computation graph to prevent gradients from flowing back through the FBP operation: $z = z_{init}.\text{detach()}$ [S1, unofficial].

2. **Outer Loop (Epochs):**
   For each epoch from $0$ to `epochs` - 1:
   
   a. **Data Consistency Update:**
      - Compute the current image estimate: $x = \text{PriorModel}(z)$ [S1, unofficial].
      - Compute the forward projection of the estimate: $\hat{p} = \text{projector.forward}(x)$ [S1, unofficial].
      - Compute the residual in projection space: $r = p - \hat{p}$ [S1, unofficial].
      - Compute the back-projected residual (gradient of the data fidelity term with respect to the image): $\delta = \text{projector.backward}(r)$ [S1, unofficial].
      - Update the latent variable: $z = x + \beta \cdot \delta$ [S1, unofficial].

   b. **Network Optimization (Inner Steps):**
      For each inner step from $0$ to `inner_steps` - 1:
      - Compute the current image estimate: $x = \text{PriorModel}(z)$ [S1, unofficial].
      - Compute the forward projection: $\hat{p} = \text{projector.forward}(x)$ [S1, unofficial].
      - Compute the Mean Squared Error (MSE) loss between the measured sinogram and the projected estimate: $\mathcal{L} = \text{MSE}(\hat{p}, p)$ [S1, unofficial].
      - Perform backpropagation to compute gradients of $\mathcal{L}$ with respect to the PriorModel parameters $\theta$ [S1, unofficial].
      - Perform one Adam optimizer step to update $\theta$ [S1, unofficial].

3. **Final Output:**
   - After all epochs, compute the final reconstruction: $x_{final} = \text{PriorModel}(z)$ [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.optim as optim

def deep_image_prior_reconstruction(
    sinogram: torch.Tensor,
    projector: object,
    prior_model: nn.Module,
    epochs: int = 250,
    inner_steps: int = 50,
    beta: float = 0.25,
    lr: float = 0.01,
    device: str = 'cpu'
) -> torch.Tensor:
    """
    Performs Deep Image Prior Reconstruction.
    
    Args:
        sinogram: Measured projection data (torch.Tensor).
        projector: Object with methods forward(x) and backward(residual).
        prior_model: Neural network (nn.Module) mapping latent z to image x.
        epochs: Number of outer epochs.
        inner_steps: Number of Adam steps per epoch.
        beta: Step size for latent variable update.
        lr: Learning rate for Adam optimizer.
        device: Device to run computation on.
        
    Returns:
        Reconstructed image/tensor.
    """
    # Move prior model to device
    prior_model = prior_model.to(device)
    
    # Initialize Adam optimizer on prior model parameters
    optimizer = optim.Adam(prior_model.parameters(), lr=lr)
    
    # Initialize latent variable z using FBP
    # Note: FBP implementation is assumed to be available or provided by the user.
    # The result is detached to stop gradient flow through FBP.
    z_init = fbp(sinogram) # [G] FBP function is not defined in sources; assumed available.
    z = z_init.detach().to(device)
    
    # Loss function
    mse_loss = nn.MSELoss()
    
    for epoch in range(epochs):
        # --- Data Consistency Step ---
        # 1. Compute current image estimate from latent z
        x = prior_model(z)
        
        # 2. Forward project the estimate
        p_hat = projector.forward(x)
        
        # 3. Compute residual in sinogram space
        residual_sinogram = sinogram - p_hat
        
        # 4. Back-project residual to image space
        # This acts as the gradient of the data fidelity term w.r.t x
        delta = projector.backward(residual_sinogram)
        
        # 5. Update latent variable
        z = x + beta * delta
        
        # --- Network Optimization Steps ---
        for _ in range(inner_steps):
            # 1. Forward pass through prior model
            x = prior_model(z)
            
            # 2. Forward projection
            p_hat = projector.forward(x)
            
            # 3. Compute loss
            loss = mse_loss(p_hat, sinogram)
            
            # 4. Backpropagation and optimizer step
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            
    # Final reconstruction
    output = prior_model(z)
    return output
```

**Edge Cases and Pitfalls:**
- **FBP Initialization:** The quality of the initial $z$ depends on the FBP implementation. If FBP is not available or inaccurate, the reconstruction may converge to a poor local minimum [S1, unofficial].
- **Gradient Detachment:** It is critical to detach $z$ from the computation graph after FBP initialization. If not detached, gradients will flow through the FBP operator, which is typically non-differentiable or computationally expensive to differentiate [S1, unofficial].
- **Precision:** The method relies on floating-point arithmetic for the latent variable updates. Precision issues may arise if the residual $\delta$ is very small or very large relative to $x$ [S1, unofficial].
- **Projector Implementation:** The `projector` object must support both forward and backward projections. The backward projection is typically the adjoint of the forward projection (e.g., unweighted back-projection for a weighted forward projection) [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The method is iterative and computationally expensive. Each epoch involves one forward/backward projection for the latent update and `inner_steps` forward projections and backpropagations for the network optimization. Total complexity is roughly $O(\text{epochs} \times \text{inner\_steps} \times (\text{proj\_cost} + \text{net\_forward\_cost}))$ [S1, unofficial].
- **Memory Complexity:** Requires storing the latent variable $z$, the current image estimate $x$, and the gradients for the neural network. Memory usage is proportional to the size of the reconstruction grid and the neural network parameters [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Strengths:** Implicit regularization via the neural network architecture often leads to high-quality reconstructions from sparse or noisy data without explicit regularization parameters [S1, unofficial].
- **Limitations:** Computationally intensive due to the need for many optimization steps. Convergence is not guaranteed and depends on the initialization and network architecture [S1, unofficial].
- **When to Use:** Suitable for sparse-view tomography or noisy data where traditional methods produce artifacts, and computational resources are available [S1, unofficial].
- **When Not to Use:** Not suitable for real-time applications or when computational efficiency is critical [S1, unofficial].

## Background
Deep Image Prior Reconstruction was introduced as a method to leverage the structure of convolutional neural networks as a prior for inverse problems, specifically in the context of tomographic reconstruction [S1, unofficial]. It builds on the Deep Image Prior concept, which suggests that the architecture of a neural network itself acts as a regularizer for natural images [S1, unofficial]. The method was implemented in the DiffTomo repository, demonstrating its application to CT reconstruction [S1, unofficial].
