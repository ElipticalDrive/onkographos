# Hierarchical CT Reconstruction via Partial Line Integrals

Also called: Hierarchical flow for CT reconstruction, Intermediate data $q_\eta(r, \theta, t)$ method, Intermediate data $q_\alpha(r

## Overview
This method solves the tomographic inverse problem by decomposing the transformation from line integrals (sinograms) to image voxels into a hierarchy of incremental steps using an intermediate representation called partial line integrals [S1]. Unlike generic fully connected networks that require $O(n^2)$ parameters, this approach uses sparse connections to achieve $O(n \log n)$ parameter complexity, making high-resolution 3D reconstruction computationally feasible [S1]. It builds on the domain transform concept by explicitly defining the intermediate data structure and the hierarchical progression of integration lengths [S1].

## How it works

### Inputs and Outputs
*   **Input**: Sinogram data $p(r, \theta)$, representing line integrals with radial distance $r$ and projection angle $\theta$. For the standard implementation, this is a 512x512 sinogram (512 detector channels, 512 angles) [S1].
*   **Output**: Reconstructed image voxels, represented as partial line integrals with a single projection angle ($\theta=0$) and full depth resolution [S1].

### Data Structures
The core data structure is the intermediate representation $q_\alpha(r, \theta, t)$, defined in the partial line integral domain [S1].

**Fields:**
*   $r$: Radial distance parameter.
*   $\theta$: In-plane rotation angle.
*   $t$: Depth parameter along the projection line.
*   $\alpha$: Integration length (width of the window function).

**Layout:**
At each hierarchical stage $L$, the data is defined by the tuple $(N_t, N_\theta)$, where $N_t$ is the number of depth bins and $N_\theta$ is the number of projection angles [S1]. The total data volume remains constant across stages [S1].

**Sparse Connection Layer:**
The network layers are implemented as sparse connection layers. Non-zero weights are stored in a sparse matrix format. This differs from dropout layers, which remove output neurons; sparse layers remove connections between input and output neurons [S1]. The sparsity pattern ensures that each input neuron affects only a small neighborhood of output neurons [S1].

### Formulas

**Partial Line Integral Definition:**
The partial line integral $q_\alpha(r, \theta, t)$ is generated by restricting the full line integral with a window function $\Pi$ [S1]:

$$ q_\alpha(r, \theta, t) = \int_{-\infty}^{\infty} f(x,y) \cdot \Pi\left(\frac{-u_x \sin \theta + v_y \cos \theta - t}{\alpha}\right) \, ds $$

Where:
*   $f(x,y)$ is the object function.
*   $\Pi(\cdot)$ is the window function.
*   $\alpha$ specifies the width of the window function, corresponding to a line segment of length $\alpha$ centered at position $t$ along the projection line [S1].
*   $u_x, v_y$ are coordinates in the detector plane [S1].

**Hierarchical Flow:**
The reconstruction progressively solves for partial line integrals with decreasing integration lengths $\alpha$ [S1]:

$$ p(r, \theta) \rightarrow q_{\alpha_1}(r, \theta, t) \rightarrow q_{\alpha_2}(r, \theta, t) \rightarrow \dots \rightarrow q_{\alpha_N}(r, \theta, t) |_{\theta=0} $$

Where $\alpha_1 > \alpha_2 > \dots > \alpha_N$ [S1].

### Parameters
*   $\alpha$: Integration length. Decreases from coarse to fine depth resolution across stages [S1].
*   $N_t$: Number of depth bins. Increases across stages [S1].
*   $N_\theta$: Number of projection angles. Decreases across stages [S1].
*   Kernel Sizes: L1 uses a sinogram domain convolutional kernel of size 512. L2-L5 use image domain convolutional kernels of size 3x3 [S1].
*   Initialization: Sparse connections initialized with all ones. Convolution kernels initialized with Glorot uniform initializer [S1].

### Numbered Steps

1.  **Stage L0 (Input):** Receive line integrals $p(r, \theta)$ with $N_t=1$ and $N_\theta=512$ [S1].
2.  **Stage L1:** Transform to partial line integrals $q_{\alpha_1}$ with $N_t=2$ and $N_\theta=256$ using a sparse connection layer with a 512-sized kernel [S1].
3.  **Stage L2:** Transform to partial line integrals $q_{\alpha_2}$ with $N_t=8$ and $N_\theta=64$ using a sparse connection layer with a 3x3 kernel and ReLU activation [S1].
4.  **Stage L3:** Transform to partial line integrals $q_{\alpha_3}$ with $N_t=32$ and $N_\theta=16$ using a sparse connection layer with a 3x3 kernel and ReLU activation [S1].
5.  **Stage L4:** Transform to partial line integrals $q_{\alpha_4}$ with $N_t=128$ and $N_\theta=4$ using a sparse connection layer with a 3x3 kernel and ReLU activation [S1].
6.  **Stage L5 (Output):** Transform to regular image voxels with $N_t=512$ and $N_\theta=1$ using a sparse connection layer with a 3x3 kernel and ReLU activation [S1].

class SparseConnectionLayer(tf.keras.layers.Layer):
    """
    A sparse connection layer where non-zero weights are stored in a sparse matrix.
    Each input neuron affects only a small neighborhood of output neurons.
    """
    def __init__(self, output_dim, sparsity_pattern, **kwargs):
        super(SparseConnectionLayer, self).__init__(**kwargs)
        self.output_dim = output_dim
        # sparsity_pattern: list of tuples (input_idx, output_idx) for non-zero connections
        self.sparsity_pattern = sparsity_pattern
        self.num_connections = len(sparsity_pattern)
        
    def build(self, input_shape):
        # Initialize weights for non-zero connections with ones
        self.w = self.add_weight(
            shape=(self.num_connections,),
            initializer='ones',
            trainable=True,
            name='weights'
        )
        super(SparseConnectionLayer, self).build(input_shape)

    def call(self, inputs):
        # inputs shape: (batch_size, input_dim)
        # outputs shape: (batch_size, output_dim)
        outputs = tf.zeros((tf.shape(inputs)[0], self.output_dim))
        
        # Apply sparse connections
        # For each non-zero weight, add input * weight to the corresponding output
        # This is a simplified representation; actual implementation would use scatter_add or similar
        for i, (in_idx, out_idx) in enumerate(self.sparsity_pattern):
            weight = self.w[i]
            # Gather input values
            input_vals = tf.gather(inputs, in_idx, axis=1)
            # Scatter to output positions
            outputs = tf.tensor_scatter_nd_add(
                outputs,

            )
        return outputs

### Edge Cases and Pitfalls
*   **Vanishing Gradients:** During end-to-end noise training, gradients may vanish. This is addressed by randomly selecting a single network layer for update per iteration while freezing the others [S1].
*   **Parameter Explosion:** A fully connected network for 512x512 input/output would require 69 billion parameters. The sparse connection approach reduces this to ~42 million parameters (0.06%) [S1]. For 3D cases (512^3), a fully connected network would require ~18 quadrillion parameters, while this approach is estimated to require ~21 billion [S1].
*   **Sparse Connection vs. Dropout:** Sparse connection layers remove connections between input and output neurons, whereas dropout layers remove output neurons. This distinction is critical for maintaining the local neighborhood structure [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Parameter Complexity:** The number of network parameters in each sparse connection layer is $O(n)$, where $n$ is the data dimension [S1].
*   **Stage Complexity:** The number of hierarchical stages is $O(\log n)$ because the number of angles decreases exponentially [S1].
*   **Total Complexity:** The total number of parameters is $O(n \log n)$ [S1].
*   **Measured Performance:** For a 512x512 input/output, the 5 sparse connection layers used ~42 million trainable parameters [S1].

### Strengths and Limitations
*   **Strengths:**
    *   Significantly reduces the number of parameters compared to fully connected networks, making high-resolution 3D reconstruction feasible [S1].
    *   Decomposes the non-local tomographic inverse problem into a series of local transforms suitable for neural networks [S1].
    *   Hierarchical structure allows for progressive refinement of depth resolution [S1].
*   **Limitations:**
    *   Requires careful handling of vanishing gradients during end-to-end training [S1].
    *   The sparsity pattern must be carefully designed to ensure local connectivity [S1].
    *   Training involves multiple phases (pre-training, end-to-end noise, clinical refinement) which can be complex to implement [S1].

### When to Use
*   Use this method when reconstructing high-resolution CT images (e.g., 512x512 or larger) where a fully connected network would be computationally intractable due to parameter count [S1].
*   Use when the goal is to leverage the hierarchical nature of the tomographic inverse problem to improve reconstruction quality [S1].

### When Not to Use
*   Do not use for low-resolution reconstructions where a fully connected network is feasible and simpler to implement [S1].
*   Do not use if the computational resources for multi-phase training (especially end-to-end with random layer updates) are not available [S1].
