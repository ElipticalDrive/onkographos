# Fusion ViT

Also called: Fusion Transformer (in the context of pixel-wise feature fusion), ViT-B/16 Fusion Module

## Overview
Fusion ViT is a neural module designed to fuse multi-view features by performing all-to-all self-attention over encoded image patches or rendered feature vectors from multiple input views [S1, unofficial][S2]. It solves the problem of multi-view inconsistency and incomplete context in neural rendering and tomographic reconstruction by providing each view's features with full spatial and semantic context from all other views [S1, unofficial]. It distinguishes itself from standard fusion methods by leveraging the Transformer's ability to model long-range dependencies across views, either at the patch level for global reconstruction [S1, unofficial] or at the pixel level for lightweight synthesis [S2].

## How it works
**Inputs and Outputs:**
The method accepts encoded features from $K$ input views. In the global reconstruction setting, inputs are concatenated encoded image patches $\{\tilde{H}_1, \tilde{H}_2, \dots, \tilde{H}_K\}$ [S1, unofficial]. In the pixel-wise setting, inputs are rendered feature vectors from $N$ views at each pixel location [S2]. The output is a set of fused tokens $\{F_1, F_2, \dots, F_K\}$ [S1, unofficial] or a fused feature map $\tilde{F}$ [S2].

**Data Structures:**
The core data structure is a sequence of tokens. For the ViT-B/16 variant, each token has an embedding dimension of 768 [S1, unofficial]. The patches are typically $16 \times 16$ pixels [S1, unofficial].

**Parameters:**
- **Architecture:** Vision Transformer Base (ViT-B/16) [S1, unofficial].
- **Layers:** 16 layers [S1, unofficial].
- **Heads:** 12 attention heads [S1, unofficial].
- **Embedding Dimension:** 768 [S1, unofficial].
- **MLP Ratio:** 4.0 (hidden dimension is $4 \times 768 = 3072$) [S1, unofficial].
- **Patch Size:** $16 \times 16$ [S1, unofficial].
- **Initialization:** Initialized from scratch [S1, unofficial]. (Note: The encoder preceding the fusion module may use DINO pre-trained weights [S1, unofficial]).

**Steps:**
1.  **Feature Encoding:** Input views are processed by an encoder (e.g., ViT-B/16) to produce encoded patches $\tilde{H}_i$ [S1, unofficial].
2.  **Concatenation:** Encoded patches from all $K$ views are concatenated into a single sequence [S1, unofficial].
3.  **Self-Attention Fusion:** The concatenated sequence is passed through a 16-layer Transformer $\mathcal{F}_{fuse}$ [S1, unofficial]. This module performs all-to-all self-attention, allowing every token to attend to every other token across all views [S1, unofficial].
4.  **Output Generation:** The output of the transformer is a set of fused tokens $\{F_1, \dots, F_K\}$, where each $F_i$ contains context from all other views [S1, unofficial].

**Formula:**
The fusion operation is defined as [S1, unofficial]:
$$
\{F_1, F_2, \dots, F_K\} = \mathcal{F}_{fuse}(\tilde{H}_1, \tilde{H}_2, \dots, \tilde{H}_K)
$$
where $\mathcal{F}_{fuse}$ is the fusion transformer, $\tilde{H}_i$ are the concatenated encoded image patches, and $F_i$ is the fused token of the $i$-th view.

**Pseudocode:**
```python
def fusion_vit(encoded_patches_list, num_views=K, num_layers=16, embed_dim=768, num_heads=12, mlp_ratio=4.0):
    """
    Fuses features from multiple views using a Transformer.
    
    Args:
        encoded_patches_list: List of tensors [K, P, D], where P is patches per view, D is embed_dim.
        num_views: Number of input views K.
        num_layers: Number of transformer layers (16).
        embed_dim: Embedding dimension (768).
        num_heads: Number of attention heads (12).
        mlp_ratio: MLP hidden dim ratio (4.0).
        
    Returns:
        fused_tokens: List of tensors [K, P, D], fused features.
    """
    # Step 1: Concatenate patches from all views
    # Shape: [K * P, D]
    concatenated_tokens = torch.cat(encoded_patches_list, dim=0)
    
    # Add positional embeddings if not already included in encoded_patches
    # [G] Standard ViT requires positional embeddings. Assuming encoded_patches 
    # are raw features, we add learnable positional embeddings.
    pos_embed = get_learnable_positional_embedding(num_patches=K * P, dim=embed_dim)
    tokens = concatenated_tokens + pos_embed
    
    # Step 2: Pass through Transformer Encoder
    # The transformer consists of num_layers blocks of Multi-Head Self-Attention and MLP
    transformer_blocks = [
        TransformerBlock(
            embed_dim=embed_dim, 
            num_heads=num_heads, 
            mlp_ratio=mlp_ratio
        ) for _ in range(num_layers)
    ]
    
    for block in transformer_blocks:
        tokens = block(tokens)
        
    # Step 3: Split back into per-view tokens
    # Shape: [K, P, D]
    fused_tokens_list = torch.split(tokens, split_size_or_sections=encoded_patches_list[0].shape[1], dim=0)
    
    return fused_tokens_list
```

**Edge Cases and Pitfalls:**
- **Geometry Cues:** In pixel-wise variants, rendered results may lose geometry cues (e.g., depth-based occlusion) when rendered from 3D to 2D, which can hinder fusion [S2].
- **Position Encoding:** Using geometry features as position encoding was explored but found not helpful [S2].
- **Calibration Errors:** The all-to-all attention helps robustly handle geometry inference and calibration errors by leveraging full context [S1, unofficial].

## Subtopics

### [View-to-View Transformer](13701-view-to-view-transformer.md)
A neural module designed to fuse multi-view features and learn view-dependent appearance directly from high-resolution raw RGB inputs. It distinguishes itself by employing an encoder-decoder architecture: the encoder performs self-attention across input views, while the decoder performs cross-attention between a specific query viewpoint and all input views. This enables robust handling of geometry inference and calibration errors. Choose this when view-dependent appearance modeling and handling of sparse-view inconsistencies are critical. See [View-to-View Transformer](13701-view-to-view-transformer.md).

### Fusion Transformer
A lightweight pixel-wise Transformer used to fuse rendered feature maps from $N$ input views on each pixel [S2]. It inputs rendered feature vectors and queries fused results using a learnable "token" [S2]. It utilizes semantics for fusion [S2]. It is chosen for real-time novel view synthesis where computational efficiency is paramount [S2]. Pitfalls include the loss of geometry cues during 3D-to-2D rendering [S2].

## Operating characteristics
- **Time Complexity:** Depends on the number of views $K$ and patches $P$. Self-attention is $O((K \cdot P)^2)$ [S1, unofficial].
- **Memory Complexity:** Proportional to the number of tokens and layers. The ViT-B/16 variant uses 16 layers with 768-dim embeddings [S1, unofficial].
- **Performance:** The model is trained end-to-end with photometric and perceptual losses [S2]. It supports variable-view learning with 6, 8, or 10 views [S1, unofficial].
- **Strengths:** Provides full context from all views, enabling complete spatial and context reasoning [S1, unofficial]. Handles multi-view inconsistency [S1, unofficial].
- **Limitations:** Computationally intensive due to self-attention over all views [S1, unofficial]. May lose geometry cues if not properly encoded [S2].
- **When to use:** Sparse-view tomographic reconstruction [S1, unofficial] or real-time novel view synthesis [S2].
- **When not to use:** When geometry cues are critical and cannot be adequately captured by semantic features [S2].

## Background
Fusion ViT originates from the application of Vision Transformers to multi-view reconstruction and novel view synthesis. The specific 16-layer ViT-B/16 fusion module was introduced in X-GRM for sparse-view X-ray to CT reconstruction [S1, unofficial]. The pixel-wise variant was proposed in FWD for real-time novel view synthesis [S2]. The method builds on the success of Transformers in capturing long-range dependencies [S2].
