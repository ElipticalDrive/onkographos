# View-to-View Transformer

Also called: V2V Transformer, DoubleField Transformer Module

## Overview
The View-to-View Transformer is a neural module designed to fuse multi-view features and predict view-dependent appearance directly from high-resolution input images, thereby alleviating multi-view inconsistency and calibration errors [S1]. It distinguishes itself from sibling methods like Fusion ViT by employing a specific encoder-decoder architecture that separates feature fusion (encoder) from view-dependent query processing (decoder), allowing it to handle relationships between input views and a specific query viewpoint more robustly than self-attention-only approaches [S1].

## How it works
The method takes $N$ input images $I_1, \dots, I_N$ and a 3D point $x$ as inputs, and outputs a color embedding $e_c$ and fused geometry features $\Phi(x)$ [S1]. The architecture consists of an Encoder and a Decoder [S1].

**Data Structures and Inputs:**
*   $\phi_i(x, I_i)$: Pixel-aligned feature vector extracted from the $i$-th input image $I_i$ at the projection of point $x$.
*   $d_i$: Viewing direction of the $i$-th input camera in its own coordinate system.
*   $d_q$: Viewing direction of the query camera.
*   $p_i$: Raw RGB color value at the projection of $x$ in the $i$-th image.
*   $\gamma(\cdot)$: Colored encoding function mapping raw RGB values to a higher-dimensional space to capture high-frequency appearance variations [S1].
*   $e_{db}$: Double embedding (geometry and appearance shared representation) generated by the encoder [S1].

**Step 1: Encoder (Multi-View Feature Fusion)**
The encoder fuses geometry features from all input views using self-attention [S1].

1.  **Feature Preparation**: For each view $i \in \{1, \dots, N\}$, concatenate the pixel-aligned feature $\phi_i(x, I_i)$ with the viewing direction $d_i$:
    $$ \Phi_i = \oplus(\phi_i(x, I_i), d_i) $$
    where $\oplus$ denotes concatenation [S1].

2.  **Attention Inputs**: Pass the set of fused features $\{\Phi_1, \dots, \Phi_N\}$ through linear layers to generate Query ($Q_e$), Key ($K_e$), and Value ($V_e$) matrices:
    $$ Q_e, K_e, V_e = F_{Q,K,V}(\phi_1, \dots, \phi_N) $$
    Here, $F_{Q,K,V}$ represents the linear projection layers [S1].

3.  **Self-Attention**: Compute the multi-head attention output:
    $$ \text{Att}_{out} = \text{Att}(Q_e, K_e, V_e) $$
    where $\text{Att}$ is the multi-head attention operation [S1].

4.  **Feature Fusion**: Apply a feed-forward layer $F_e$ to the attention output to produce the fused feature representation $\Phi$:
    $$ \Phi = F_e(\text{Att}_{out}) $$
    This $\Phi$ serves as the conditioned feature for geometry prediction [S1].

5.  **Double Embedding Generation**: Combine the 3D position $x$ (encoded via $\gamma(x)$) and the fused features $\Phi$ through a double MLP $E_{db}$ to generate the double embedding $e_{db}$:
    $$ e_{db} = E_{db}(\gamma(x), \Phi) $$
    This embedding bridges surface and radiance fields [S1].

**Step 2: Decoder (View-Dependent Color Prediction)**
The decoder produces view-dependent color features by attending to input views conditioned on the query view direction [S1].

1.  **Query Construction**: Project the query view direction $d_q$ through a linear layer:
    $$ Q_d = F_{Q_d}(d_q) $$
    where $F_{Q_d}$ is a linear layer [S1].

2.  **Key Construction**: Project the viewing directions of all input views $\{d_1, \dots, d_N\}$ through a linear layer:
    $$ K_d = F_{K_d}(d_1, \dots, d_N) $$
    where $F_{K_d}$ is a linear layer [S1].

3.  **Value Construction**: For each view $i$, concatenate the double embedding $e_{db}$ with the colored encoding of the raw RGB value $\gamma(p_i)$. These concatenated vectors form the Value inputs:
    $$ V_d = F_{V_d}([e_{db}, \gamma(p_1)], \dots, [e_{db}, \gamma(p_N)]) $$
    where $F_{V_d}$ is a linear layer and $[\cdot, \cdot]$ denotes concatenation [S1].

4.  **Cross-Attention**: Compute the attention between the query view and input views:
    $$ \text{Att}_{cross} = \text{Att}(Q_d, K_d, V_d) $$

5.  **Color Embedding**: Apply a feed-forward layer $F_d$ to the cross-attention output to obtain the color embedding $e_c$:
    $$ e_c = F_d(\text{Att}_{cross}) $$
    [S1]

**Step 3: Final Color Prediction**
Pass the color embedding $e_c$ through a texture MLP $E_c$ to predict the final high-resolution color $c$:
$$ c = E_c(e_c) $$
[S1]

**Pseudocode**
```python
def view_to_view_transformer(x, d_q, input_views):
    """
    x: 3D point coordinates
    d_q: Query view direction vector
    input_views: List of N tuples (phi_i, d_i, p_i)
                 phi_i: Pixel-aligned feature from view i
                 d_i: Input view direction vector
                 p_i: Raw RGB value at projection of x in view i
    """
    N = len(input_views)
    
    # --- Encoder ---
    # 1. Prepare inputs for self-attention
    # Note: F_{Q,K,V} are linear layers applied to phi_i
    Q_e = linear_layer_Q(phi_i for phi_i, _, _ in input_views)
    K_e = linear_layer_K(phi_i for phi_i, _, _ in input_views)
    V_e = linear_layer_V(phi_i for phi_i, _, _ in input_views)
    
    # 2. Self-Attention
    att_out = multi_head_attention(Q_e, K_e, V_e)
    
    # 3. Feed-Forward to get fused features Phi
    Phi = feed_forward_encoder(att_out)
    
    # 4. Generate Double Embedding
    # gamma(x) is positional encoding for x
    e_db = double_mlp(concat(gamma(x), Phi))
    
    # --- Decoder ---
    # 5. Prepare Cross-Attention Inputs
    # Query is based on d_q
    Q_d = linear_layer_Q_d(d_q)
    
    # Keys are based on input view directions d_i
    K_d = linear_layer_K_d([d_i for _, d_i, _ in input_views])
    
    # Values are based on [e_db, gamma(p_i)]
    # gamma(p_i) is colored encoding for raw RGB p_i
    values = []
    for _, _, p_i in input_views:
        val_input = concat(e_db, colored_encoding(p_i))
        values.append(val_input)
    V_d = linear_layer_V_d(values)
    
    # 6. Cross-Attention
    att_cross = multi_head_attention(Q_d, K_d, V_d)
    
    # 7. Feed-Forward to get color embedding
    e_c = feed_forward_decoder(att_cross)
    
    # 8. Final Color Prediction
    c = texture_mlp(e_c)
    
    return c, Phi, e_db
```

## Subtopics

### [Multi-View Feature Encoder](13802-multi-view-feature-encoder.md)
Aggregates appearance and geometric information using weight-sharing CNNs and joint multi-view Transformers with visibility-weighted cosine similarities, explicitly modeling multi-view consistency via pairwise similarities rather than simple averaging.

## Operating characteristics
The method enables the utilization of original high-resolution images by taking raw RGB values into account, contributing to high-fidelity rendering [S1]. It is more robust to geometry inference and calibration errors in real-world multi-view setups compared to methods with limited feature representation power [S1]. However, training on high-resolution domains is expensive; the method typically employs a two-phase strategy: large-scale dataset pre-training at low resolution and efficient person-specific high-resolution fine-tuning [S1].

## Background
The View-to-View Transformer was introduced in the DoubleField framework, which bridges neural surface and radiance fields for high-fidelity human reconstruction and rendering [S1]. It addresses limitations in prior methods that relied on low-resolution feature maps or required strict SMPL fitting, allowing DoubleField to handle loose clothing and leverage large-scale human scan datasets [S1].
