# Scene Parameter Saliency via Differentiable Light Transport

Also called: Gradient-based Saliency, Metric Saliency Maps, gradient-based saliency for differentiable rendering, per-parameter gradients of a scalar objective

## Overview
Metric saliency maps identify which scene parameters most influence a specific scalar image-space metric by computing per-parameter gradients through a differentiable renderer [S1]. Unlike neural saliency methods that propagate attribution through learned weights, this method propagates gradients through the physical light transport simulation, capturing multi-bounce dependencies and parameter interactions that are opaque to manual inspection [S1]. It serves as an interpretability tool for inverse rendering and scene understanding, providing a local sensitivity characterization at the cost of a single reverse-mode differentiation pass, avoiding the expensive re-renders required by finite-difference sensitivity analysis [S1].

## How it works
The method consists of three stages: (1) render an image through a differentiable pipeline, (2) evaluate a scalar metric on that image, and (3) backpropagate through both the metric and the renderer to obtain per-parameter gradients, which are then mapped back to image space for visualization [S1].

### Inputs and Outputs
**Inputs:**
*   Scene parameters $\theta$: A vector including surface reflectances, roughness values, indices of refraction, emitter intensities, and geometric quantities [S1].
*   Scalar metric $M$: A function evaluating a property of the light transport simulation, defined as $M: \mathbb{R}^D \to \mathbb{R}$, where $I = R(\theta) \in \mathbb{R}^D$ is the rendered image (generalized sensor response) [S1].
*   Differentiable renderer $R$: A function computing the image $I$ from $\theta$, such as a physically-based Monte Carlo path tracer with multi-bounce global illumination [S1].

**Outputs:**
*   Parameter-space gradient $g$: A vector where each component $g_i = \partial M / \partial \theta_i$ measures the sensitivity of the metric to the corresponding parameter [S1].
*   Saliency map: An image-space visualization where pixels are colored by the saliency of the material visible at that location [S1].

### Data Structures
*   **Scene Parameters ($\theta$):** Stored as a structured object containing differentiable attributes for each material and light source [S1]. This work focuses on uniform material parameters; spatially-varying saliency fields are left to future work [S1].
*   **Rendered Image ($I$):** A tensor of shape $H \times W \times C$ (height, width, channels) representing the generalized sensor response [S1].
*   **Material Identity Map:** A per-pixel map generated by tracing primary rays from the camera, identifying the hit scene object and its associated material parameters [S1].

### Numbered Steps
1. Render an image $I$ through a differentiable pipeline using $I = R(\theta)$ [S1].
2. Evaluate a scalar metric $M$ on the rendered image [S1].
3. Backpropagate through both the metric and the renderer to obtain per-parameter gradients $g = \partial M / \partial \theta$ [S1].
4. Map the obtained per-parameter gradients back to image space for visualization by tracing primary rays from the camera, identifying hit scene objects, and coloring each pixel with the saliency value of the visible material [S1].

### Formulas
The parameter-space gradient $g$ is computed via the chain rule [S1]:

$$
g = \frac{\partial M(R(\theta))}{\partial \theta} = \frac{\partial M}{\partial I} \frac{\partial I}{\partial \theta}
$$

The product is obtained automatically by backpropagation through the metric and the light transport simulation jointly [S1].

The saliency of a parameter $\theta_i$ is defined as the magnitude of its gradient component [S1]:

$$
\text{Saliency}(\theta_i) = |g_i|, \quad \text{where } g_i = \frac{\partial M}{\partial \theta_i}
$$

For vector-valued parameters (e.g., RGB reflectance), the saliency is the $\ell_2$ norm of the gradient components [S1]:

$$
\text{Saliency}(\mathbf{v}) = \left\| \frac{\partial M}{\partial \mathbf{v}} \right\|_2
$$

### Pseudocode
```python
import math

def compute_metric_saliency(scene_params, metric_fn, renderer, camera, material_to_param_map):
    # Stage 1: Render image through differentiable pipeline
    image = renderer(scene_params)

    # Stage 2: Evaluate scalar metric on the image
    metric_value = metric_fn(image)

    # Stage 3: Backpropagate through metric and renderer
    # Compute dM/dI (metric sensitivity to image)
    dM_dI = metric_fn.gradient(image)

    # Compute dI/dtheta (image sensitivity to parameters) via reverse-mode AD
    # The chain rule g = (∂M/∂I) * (∂I/∂θ) is applied automatically by the AD engine [S1]
    # Implementation detail: reverse-mode AD traverses the computational graph backward
    gradients = renderer.backward_pass(dM_dI)

    # Compute saliency magnitudes
    saliency_values = []
    for grad in gradients:
        if grad.is_vector:
            # L2 norm of gradient components
            saliency = math.sqrt(sum(x**2 for x in grad.flatten()))
        else:
            saliency = abs(grad)
        saliency_values.append(saliency)

    # Normalize saliency values to [0, 1] for visualization
    max_val = max(saliency_values) if saliency_values else 1.0
    normalized_saliency = [s / max_val for s in saliency_values]

    # Stage 4: Map gradients to image space
    # Trace primary rays from camera to identify hit scene objects
    material_identity_map = []
    for y in range(camera.height):
        row = []
        for x in range(camera.width):
            ray = camera.generate_ray(x, y)
            hit = renderer.scene.intersect(ray)
            row.append(hit.object_id if hit else -1)
        material_identity_map.append(row)

    # Color each pixel with the saliency of the visible material
    saliency_map = [[0.0] * camera.width for _ in range(camera.height)]
    for y in range(camera.height):
        for x in range(camera.width):
            obj_id = material_identity_map[y][x]
            if obj_id != -1 and obj_id in material_to_param_map:
                param_idx = material_to_param_map[obj_id]
                saliency_map[y][x] = normalized_saliency[param_idx]

    return saliency_map, gradients
```

### Parameters
*   **Renderer:** Must be differentiable. The implementation uses Mitsuba 3 with Path Replay Backpropagation (PRB) to handle multi-bounce global illumination gradients [S1].
*   **Metric $M$:** Can be qualitatively different objectives, including psychovisual glare indices (e.g., Unified Glare Rating), mean scene luminance, and neural perceptual scores (e.g., ResNet-50 logits) [S1].
*   **Maximum path depth:** 6 bounces [S1].
*   **Samples per pixel (SPP):** 1024 for main results [S1].
*   **Learning rate for validation:** 0.01 (used for ablation validation to verify gradient accuracy) [S1].

### Edge Cases and Pitfalls
*   **Metric Specificity:** The saliency map is specific to the metric and not an intrinsic property of the scene. Parameters that dominate one objective may be negligible for another [S1].
*   **Monte Carlo Variance:** Gradient estimators inherit variance from the path tracer. At low sample counts, saliency values are noisy. Stable rankings require moderate sample counts (64–256 spp); fine-grained spatially-varying fields require higher budgets or variance reduction [S1].
*   **Non-differentiable Metrics:** Metrics with hard thresholds or discrete decisions (e.g., binary glare detection) are not differentiable. They must be relaxed into smooth approximations (e.g., sigmoid relaxations for visibility checks), which affects the resulting saliency map [S1].
*   **First-Order Limitation:** Gradient magnitude only measures local, first-order sensitivity. It does not capture parameter interactions (second-order effects) or physical constraints (e.g., roughness clamping at 1.0) [S1].

## Operating characteristics
*   **Time Complexity:** The method requires a single forward pass for rendering and a single reverse-mode differentiation pass (backpropagation) for gradient computation. This is significantly faster than finite-difference sensitivity analysis, which requires dozens of independent simulation evaluations [S1].
*   **Memory Complexity:** Memory usage depends on the differentiable renderer's implementation. Storing intermediate states for reverse-mode AD can be high, though PRB-based renderers like Mitsuba 3 manage memory efficiently for multi-bounce paths [G].
*   **Measured Performance:** In experiments with 1024 SPP and 6 bounces, the method successfully isolated and ranked true physical drivers of discomfort glare and mean luminance, validating against finite-difference steps with a learning rate of 0.01 [S1].
*   **Strengths:** Provides a local sensitivity characterization at the cost of a single backward pass; captures multi-bounce light transport dependencies; works with any differentiable renderer and metric [S1].
*   **Limitations:** Noisy at low sample counts; requires differentiable metrics; does not capture second-order effects or physical constraints; saliency is metric-specific [S1].
*   **When to use:** When interpreting which scene parameters drive a specific image-space metric, especially for multi-bounce global illumination scenarios where manual inspection is difficult [S1].
*   **When not to use:** When second-order interactions are critical, when metrics are inherently non-differentiable and cannot be relaxed, or when computational resources are too limited for stable Monte Carlo gradient estimation [S1].

## Background
The method was introduced by Linas Beresna and Eugene Fiume in "Scene Parameter Saliency via Differentiable Light Transport" [S1]. It builds on [Differentiable volume rendering](43-differentiable-volume-rendering.md), extending the concept of gradient-based attribution from neural networks to physical light transport simulations [S1]. The approach addresses the need for interpretability in inverse rendering and scene understanding, offering an alternative to traditional sensitivity analysis methods like parametric sweeps or finite-difference probing [S1]. It is implemented using Mitsuba 3 and DrJit, leveraging Path Replay Backpropagation for efficient gradient computation [S1].
