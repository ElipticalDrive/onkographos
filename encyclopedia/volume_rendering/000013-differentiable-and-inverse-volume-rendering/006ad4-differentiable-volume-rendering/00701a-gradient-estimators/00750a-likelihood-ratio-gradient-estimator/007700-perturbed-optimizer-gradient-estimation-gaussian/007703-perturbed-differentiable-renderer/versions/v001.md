# Perturbed Differentiable Renderer

Also called: Approximate differentiable rendering via perturbed optimizers, Differentiable Rendering with Perturbed Optimizers, Perturbed Renderers, Randomized Smoothing for Differentiable Rendering

## Overview
The Perturbed Differentiable Renderer formulates non-smooth rasterization and aggregation steps as optimization problems (argmax) and makes them differentiable by applying random perturbations to the input arguments, effectively smoothing the Heaviside and Z-buffer selection functions [S1, unofficial]. Unlike methods that use gradient approximations in the backward pass (e.g., OpenDR, NMR) or smooth approximations of the forward pass (e.g., SoftRas, DIB-R), this method uses randomized smoothing of the optimization formulation, providing a theoretical link to perturbed optimizers and guaranteeing non-null gradients everywhere [S1, unofficial].

## How it works
The method reformulates rasterization and aggregation as perturbed Linear Programming (LP) optimizers. It introduces stochastic noise to the input parameters of the argmax operation to create a smooth approximation of the non-smooth hard constraints, allowing gradients to flow to background pixels and ensuring non-null gradients everywhere [S1, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   Triangle mesh geometry (vertices, faces).
    *   Camera parameters (intrinsics, extrinsics).
    *   Triangle colors $C_j^i$ for each triangle $j$ and pixel $i$.
    *   Smoothing parameters: $\sigma$ (rasterization), $\gamma$ (aggregation), $\alpha$ (logarithmic barrier).
    *   Perturbation scale $\epsilon$ (often implicit in $\sigma, \gamma$).
    *   Number of Monte-Carlo samples $M$.
*   **Outputs:**
    *   Rendered image $R$.
    *   Gradients of the loss with respect to mesh parameters and camera parameters.

### Data Structures
*   **Occupancy Map $I$:** A binary mask where $I_j^i = 1$ if pixel $i$ is covered by triangle $j$, else $0$.
*   **Inverse Depth Vector $z$:** A vector of size $m+1$ (where $m$ is the number of triangles) containing inverse depths $z_j$ for each triangle and a background value $z_{m+1} = z_{\min}$.
*   **Color Map $C$:** Tensor of shape $(H, W, m, 3)$ storing colors for each triangle at each pixel.
*   **Noise Samples $Z^{(i)}$:** $M$ samples drawn from distribution $\mu(z) \propto \exp(-\nu(z))$.

### Formulas and Definitions
1.  **Rigid Rasterization:**
    The occupancy map is defined using the Heaviside function $H$ of the distance $d(i, j)$ between pixel center $i$ and triangle projection $j$:
    $$ I_j^i = H(d(i, j)) = \begin{cases} 0 & \text{if } d(i, j) \leq 0 \\ 1 & \text{otherwise} \end{cases} = \underset{0 \leq y \leq 1}{\operatorname{argmax}} y d(i, j) $$
    [S1, unofficial]

2.  **Rigid Aggregation:**
    The rendered image $R$ aggregates colors $C_j^i$ using weights $w_j^i(z)$ determined by an argmax over the simplex constraints and occlusion mask $I$:
    $$ R^i = \sum_j w_j^i(z) C_j^i $$
    $$ w^i(z) = \underset{y \text{ s.t. } \|y\|_1 = 1, y \geq 0, y_j = 0 \text{ if } I_j^i = 0}{\operatorname{argmax}} \langle z, y \rangle $$
    [S1, unofficial]

3.  **Perturbed Optimizer Approximation:**
    The non-differentiable argmax is replaced by the expectation over perturbed inputs:
    $$ y_\epsilon^*(\theta) = \mathbb{E}_Z [ y^*(\theta + \epsilon Z) ] = \mathbb{E}_Z \left[ \underset{y \in \mathcal{C}}{\operatorname{argmax}} \langle \theta + \epsilon Z, y \rangle \right] $$
    where $Z$ follows distribution $\mu(z) \propto \exp(-\nu(z))$. As $\epsilon \rightarrow 0$, $y_\epsilon^*(\theta) \rightarrow y^*(\theta)$.
    [S1, unofficial]

4.  **Differentiable Rasterization:**
    $$ \hat{I}_j^i = H_\sigma(d(i, j)) = \mathbb{E}_X[H(d(i, j) + \sigma X)] = \mathbb{E}_X\left[\underset{0 \leq y \leq 1}{\operatorname{argmax}} \langle y, d(i, j) + \sigma X \rangle\right] $$
    where $X$ is noise with distribution $H_\sigma$.
    [S1, unofficial]

5.  **Differentiable Aggregation:**
    $$ \hat{R}^i = \sum_j w_{\alpha, \gamma}^i(z) C_j^i $$
    $$ w_{\alpha, \gamma}^i(z) = \mathbb{E}_Z[w_\alpha(z + \gamma Z)] = \mathbb{E}_Z\left[\underset{y \text{ s.t. } \|y\|_1=1, y \geq 0}{\operatorname{argmax}} \left\langle y + \frac{1}{\alpha} \ln(\hat{I}^i), z + \gamma Z \right\rangle\right] $$
    Here, $\alpha$ (or $\beta$ in some notations) is the smoothing parameter for the logarithmic barrier. As $\alpha \rightarrow +\infty$, the hard constraint $y_j=0$ if $I_j^i=0$ is recovered. As $I_j^i \rightarrow 0$, $\ln I_j^i \rightarrow -\infty$, enforcing $w_j^i \rightarrow 0$.
    [S1, unofficial]

6.  **Jacobian of Perturbed Optimizer:**
    $$ J_\theta y_\epsilon^*(\theta) = \mathbb{E}_Z \left[ \frac{y^*(\theta + \epsilon Z)}{\epsilon} \nabla \nu(Z)^\top \right] $$
    [S1, unofficial]

### Parameters
*   $\sigma$: Smoothing parameter for rasterization. Scales noise $X$ added to distance metric. Can be scaled automatically according to object dimensions. [S1, unofficial]
*   $\gamma$: Smoothing parameter for aggregation. Scales noise $Z$ added to vector $z$. Can be scaled automatically according to object dimensions. [S1, unofficial]
*   $\alpha$ (or $\beta$): Smoothing parameter for the logarithmic barrier in aggregation LP. [S1, unofficial]
*   $M$: Number of Monte-Carlo samples. $M=8$ is sufficient for stable and accurate results. [S1, unofficial]
*   $\epsilon$: Perturbation scale. Controls smoothing level. $\epsilon=0$ recovers rigid optimizer. [S1, unofficial]

### Edge Cases and Pitfalls
*   **Null Gradients:** The Jacobian of the rigid optimizer is null almost everywhere and undefined otherwise, making standard backpropagation impossible without smoothing [S1, unofficial].
*   **Variance:** Decreasing the noise scale $\epsilon$ increases the variance of the naive Monte-Carlo gradient estimator, making gradients noisy. The variance scales as $\text{Var}[J_\theta y_\epsilon^M(z)] \propto \frac{\text{Var}[y^(\theta + \epsilon Z) \nabla \nu(Z^{(i)})^\top]}{M\epsilon^2}$ [S1, unofficial].
*   **Computational Cost:** Computing the exact expectation is intractable; Monte-Carlo estimation is required. The computation is naturally parallelizable, leading to constant computation time at the cost of increased memory footprint [S1, unofficial].
*   **Logarithmic Barrier:** The logarithmic barrier $\ln(I_j^i)$ can lead to numerical instability if $I_j^i$ is close to 0. A small epsilon should be added before taking the logarithm [G].

## Operating characteristics
*   **Time Complexity:** Forward pass time is comparable to classical differentiable renderers. For 1-8 samples, forward pass is 30ms ($\pm 3$), backward pass is 19ms ($\pm 1$). For 32-64 samples, forward pass is 31ms ($\pm 3$), backward pass is 20-22ms ($\pm 1-2$) [S1, unofficial].
*   **Memory Complexity:** Max memory usage is 217.6 MB for 1-8 samples, 303.1 MB for 32 samples, and 440.0 MB for 64 samples. Compared to SoftRas (180.3 MB) and Hard renderer (178.5 MB) [S1, unofficial].
*   **Strengths:** Guarantees non-null gradients everywhere, allowing for strong pixel-level supervision. The smoothing parameters can be scaled automatically according to object dimensions. The method provides a theoretical link to perturbed optimizers [S1, unofficial].
*   **Limitations:** Requires solving multiple optimization problems (one per Monte-Carlo sample) in the forward pass, increasing memory usage. The variance of the gradient estimator increases as the smoothing parameter decreases [S1, unofficial].
*   **When to use:** Suitable for tasks requiring strong pixel-level supervision, such as 3D scene reconstruction, 6D pose estimation, and 3D mesh reconstruction [S1, unofficial].

## Background
The Perturbed Differentiable Renderer was proposed in the paper "Differentiable Rendering with Perturbed Optimizers" [S1, unofficial]. It builds on the idea of using randomized smoothing to make non-smooth optimization problems differentiable. The method is implemented in Pytorch3d and compared against SoftRas and DIB-R [S1, unofficial]. It is applied to 3D scene reconstruction, 6D pose estimation, and 3D mesh reconstruction [S1, unofficial].
