# Prefiltering-aware gradient metric estimation

Also called: Kernel-based gradient metric, LHS/RHS integrand estimation

## Overview
This method estimates the gradient of a pre-filtered function $\hat{f}$ by approximating it as the convolution of the original function's gradient $\nabla f$ with a separable kernel $K$. It sets itself apart from [First-Order Correctness Gradient Approximation](20430-first-order-correctness-gradient-approximation.md) by explicitly modeling the pre-filtering operation within the gradient estimator itself, using an adaptive 1D box kernel to smooth noise in the integrand. Unlike [Gradient Theorem Violation Metric](23084-gradient-theorem-violation-metric.md), which serves as an error metric rather than an estimator, this method provides the actual gradient values for differentiable rendering.

## How it works
**Inputs:** Original function $f$, separable kernel $K = K_x * K_y * K_z$ (typically a box kernel), sampling parameters.
**Outputs:** Estimated gradient $\nabla \hat{f}$.

**Data Structures:**
- Kernel $K$: Defined by its dimensions (widths) along $x, y, z$ axes. The kernel size is identical to the dimension of the gradient component being approximated.
- Sampling points: Discrete locations in parameter space.

**Steps:**
1. **Approximation Formulation:** The method approximates the gradient of the pre-filtered function $\hat{f} = f * K$ as:
   $$ (f * K) * (\nabla g) \approx (\nabla f * K) * K \approx \nabla f * K $$
   where $g$ is the test function or weight. The approximation error arises from the commutativity assumption and the specific kernel shape [S1].

2. **Adaptive Axis Selection:** For a given pixel, the algorithm adaptively chooses between the $x$ or $y$ axis as the primary sampling axis. This decision is made to optimize the trade-off between pre-filtering smoothness and computational cost [S1].

3. **Prefiltering:** Along the chosen axis (e.g., $x$), the integrand is pre-filtered using a 1D box kernel. The size of this kernel matches the dimension of the gradient component $g$ [S1].
   $$ (\hat{f} * K) * (\nabla_x g) \approx \nabla_x f * K * K_y * K_z $$
   If pre-filtered along $y$, the result is $K_x * \nabla_y f * K_z$ [S1].

4. **Integrand Sampling:** Along the orthogonal axis, the integrand is sampled densely. This dense outer sampling smooths out the noise inherent in the gradient estimate [S1].

**Parameters:**
- **RHS Samples:** $10^5$ samples for the Right-Hand Side (RHS) integration [S1].
- **LHS Quadrature Samples:** $10^4$ samples for the Left-Hand Side (LHS) quadrature [S1].
- **LHS Integrand Prefiltering Samples:** 1 sample for pre-filtering the integrand of the LHS [S1].

**Edge Cases and Pitfalls:**
- **Perfect Reconstruction:** If the kernel shapes are chosen poorly, the method may form a perfect reconstruction, leading to artifacts. Care must be taken to avoid this [S1].
- **Discontinuous Functions:** The method guarantees relative first-order correctness for discontinuous functions, but convergence may be slower or require more samples compared to continuous functions [S1].
- **Bug in Ring Shader:** Specific implementations (like DVG) may fail to converge for certain shapes (e.g., ring shader) due to bugs in handling discontinuities [S1].

## Subtopics

### [Gradient Theorem Violation Metric](23084-gradient-theorem-violation-metric.md)
A quantitative error metric that evaluates gradient approximations by measuring how much the gradient theorem is violated, avoiding the flaws of L1/L2 norms (which are sensitive to distribution shape limits) and finite difference errors.

## Operating characteristics
**Time and Memory Complexity:**
- The method requires dense outer sampling ($10^5$ samples for RHS) which increases computational cost compared to methods with fewer samples.
- Memory usage is low as it primarily stores function values and kernel parameters.

**Measured Performance:**
- **Hardware/Resolution:** Not given in the sources.
- **Scaling:** Performance scales linearly with the number of samples. The dense sampling helps smooth noise but increases runtime.
- **Strengths:** Effectively smooths noise in the integrand estimate through dense outer sampling and adaptive prefiltering. Converges close to the target image for simple shapes like circles [S1].
- **Limitations:** May fail to converge for complex shapes (e.g., ring shader) if not implemented carefully. Higher sample counts than some alternatives (e.g., TEG uses 10 samples for inner integrand) [S1].

**When to Use:**
- Use when noise in gradient estimates is a significant issue and adaptive prefiltering can help smooth the integrand.
- Suitable for interactive applications where some manual tuning is acceptable [S1].

**When Not to Use:**
- Avoid for complex shapes that require precise handling of discontinuities if the implementation is not robust (e.g., ring shader issues) [S1].
- Not suitable if computational resources are extremely limited, due to high sample counts.

## Background
**Origin:**
- The method is described in [S1] as "Ours" in the context of comparing different gradient estimation methods for differentiable rendering.
- It is part of a broader effort to improve gradient estimation in volume rendering by incorporating pre-filtering awareness.

**History and Development:**
- The method was developed to address the limitations of finite difference (FD) and other gradient estimators that do not account for pre-filtering.
- It was compared against [Gradient Theorem Violation Metric](23084-gradient-theorem-violation-metric.md) (DVG) and other methods in various experiments, including a rope application for interactive use [S1].

**Usage:**
- Used in differentiable volume rendering pipelines where accurate gradient estimation is crucial for optimization tasks.
- Applied in scenarios involving simple manual decisions for interactive applications [S1].
