# Gradient Estimators
Also called: Gradient Estimation Schemes

## Overview
Gradient Estimators compute the derivatives of the volume rendering integral with respect to scene parameters (such as density, color, or geometry) to enable differentiable volume rendering. They solve the problem of efficiently and accurately propagating error signals from the rendered image back to the volumetric data or scene representation. Unlike [Automatic Differentiation (Reverse/Adjoint Mode)](7151-automatic-differentiation-reverse-adjoint-mode.md), which requires storing $O(kn)$ intermediate states, or [Analytical Gradients](7613-analytical-gradients.md), which derive closed-form derivatives for specific operations, gradient estimation schemes in volume raycasting often focus on the numerical differentiation of the interpolation and filtering steps inherent to raycasting [S1].

## How it works
Gradient estimation in volume raycasting primarily concerns the computation of spatial derivatives (normals) of the volume density field $\sigma(\mathbf{x})$ at arbitrary sample positions along a ray. These gradients are essential for shading, normal estimation, and certain inverse rendering formulations. The method relies on the interpolation filter used during raycasting (e.g., trilinear, tricubic).

### Inputs and Outputs
- **Input:** Volume data grid (density values), interpolation filter kernel, ray sample positions.
- **Output:** Gradient vector $\nabla \sigma$ at the sample position.

### Data Structures
The implementation typically operates on the volume grid. For caching variants, a secondary cache structure stores precomputed gradients per brick (sub-volume) [S1].

### Methods
Four distinct schemes exist for computing gradients during volume raycasting [S1]:

1.  **Continuous Derivative:** A derivative filter is pre-convolved with the interpolation filter. The gradient at a re-sample location is computed by convolving the volume data with this combined filter. No caching mechanism is available for this scheme [S1].
2.  **Analytic Derivative:** A special gradient filter is derived analytically from the interpolation filter. This filter is used directly for gradient estimation. No caching mechanism is available for this scheme [S1].
3.  **Interpolation First:** The volume data is re-sampled onto a new, finer grid such that the derivative operator can be applied directly at the re-sample position. This is beneficial for orthographic rendering. However, if the object sample distance is significantly smaller than one, the grid size increases drastically (e.g., a sample distance of 0.25 increases grid size by a factor of 4), making caching inefficient [S1].
4.  **Derivative First:** Gradients are computed at the original grid points first. These precomputed gradients are then interpolated at the desired re-sample position. This scheme is more efficient for caching because the amount of data to cache is determined by the grid size, not the sample distance, allowing for interactive changes in object sample distance and jittering [S1].

### Comparison of Caching Efficiency
Schemes 1 and 2 do not support efficient caching. Schemes 3 and 4 support caching. While Moeller et al. [S1] originally proposed Interpolation First as the most efficient for non-cached rendering, Derivative First is superior for cached rendering due to the grid expansion issue in Interpolation First.

### Pseudocode: Derivative First Scheme
```python
# Pre-computation phase (once per volume update)
def precompute_gradients(volume_grid):
    """
    Computes gradients at all grid points using a central difference scheme
    or the derivative of the interpolation filter.
    Returns a grid of gradient vectors.
    """
    grad_grid = zeros_like(volume_grid, shape=(volume_grid.shape[0], volume_grid.shape[1], volume_grid.shape[2], 3))
    # Implementation depends on the specific interpolation filter used for rendering.
    # For trilinear interpolation, the gradient is the sum of the gradients of the basis functions.
    for x in range(volume_grid.shape[0] - 1):
        for y in range(volume_grid.shape[1] - 1):
            for z in range(volume_grid.shape[2] - 1):
                # Example: Central difference for density gradient
                dx = (volume_grid[x+1, y, z] - volume_grid[x-1, y, z]) / 2.0
                dy = (volume_grid[x, y+1, z] - volume_grid[x, y-1, z]) / 2.0
                dz = (volume_grid[x, y, z+1] - volume_grid[x, y, z-1]) / 2.0
                grad_grid[x, y, z] = (dx, dy, dz)
    return grad_grid

# Rendering phase
def raycast_with_gradient_first(ray_origin, ray_direction, volume_grid, grad_grid, filter_kernel):
    """
    Renders a ray and computes the gradient at sample points by interpolating
    the precomputed gradient grid.
    """
    t = 0.0
    step_size = 0.1 # Example step size
    accumulated_transmittance = 1.0
    accumulated_color = (0.0, 0.0, 0.0)
    sample_gradient = (0.0, 0.0, 0.0)
    
    while t < 100.0 and accumulated_transmittance > 1e-4:
        pos = ray_origin + ray_direction * t
        # Interpolate density and gradient at pos using filter_kernel
        density = interpolate(volume_grid, pos, filter_kernel)
        grad = interpolate(grad_grid, pos, filter_kernel)
        
        # Update rendering integral (simplified)
        alpha = 1.0 - exp(-density * step_size)
        color_contribution = accumulated_transmittance * alpha * density # Simplified emission
        accumulated_color += color_contribution
        accumulated_transmittance *= (1.0 - alpha)
        
        # Accumulate or store gradient for shading/inverse rendering
        sample_gradient += grad # Or weight by transmittance
        
        t += step_size
        
    return accumulated_color, sample_gradient
```

## Subtopics

### [Reparameterization Estimators](6499-reparameterization-estimators.md)
Reparameterization estimators compute gradients of rendering integrals by transforming the integration domain or sampling distribution so that parameter dependence moves from domain boundaries or probability density functions into the integrand's argument [G]. This allows differentiation under the integral sign without boundary terms [G]. Unlike [Automatic Differentiation (Reverse/Adjoint Mode)](7151-automatic-differentiation-reverse-adjoint-mode.md) which propagates gradients through the computational graph, or [Analytical Gradients](7613-analytical-gradients.md) which derive closed-form derivatives, reparameterization relies on a change of variables to make discontinuities or sampling distributions static with respect to optimization variables [G].

### [Gradient Estimation and Smoothing](7152-gradient-estimation-and-smoothing.md)
Gradient estimation and smoothing techniques address discontinuities in differentiable rendering that cause vanishing gradients [G]. This family modifies gradient computation by smoothing the integrand to permit differentiation under the integral sign, approximating gradients via non-local spatial statistics, or applying axis-aligned filters [6449-smooth-gradient-estimation-via-convolution.md, 6784-non-local-approximated-gradients.md, 7600-axis-aligned-neighbor-smoothing.md].

### [Recursive Control Variates for Inverse Rendering](11549-recursive-control-variates-for-inverse-rendering.md)
Recursive Control Variates (RCV) is a gradient estimation technique for physically based differentiable inverse rendering that reduces variance and bias by leveraging information from previous optimization steps. It exploits the high correlation between consecutive renderings in gradient descent, where scene parameters change minimally, to recursively compound variance reduction across the optimization sequence. Unlike SAGA and SVRG which maintain a running approximation of the full gradient for machine learning pipelines, RCV handles variance from numerical integration over continuous domains, and unlike the optimal strategy of using all previous renderings as individual control variates, RCV uses only the immediate previous estimate to avoid growing covariance matrices. It effectively mitigates bias introduced by differentiating non-linear loss functions with respect to noisy inputs, preventing optimization drift.

### Multi-level Monte Carlo for Debiasing
A hierarchical Monte Carlo approach using telescopic sums to debias estimators and improve consistency [S2]. It provides an opportunity to make biased gradient estimators at least consistent, unlike standard single-level estimators [S2].

### Likelihood-Ratio Gradient Estimator
An unbiased gradient estimator derived using the likelihood-ratio identity [S3, unofficial]. It expresses the gradient of the expected loss as a sum of the expected gradient of the loss and a term involving the gradient of the probability density function [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the interpolation filter and the number of samples per ray. Derivative First requires precomputation $O(V)$ where $V$ is volume size, but rendering remains $O(N)$ per ray. Interpolation First may require $O(V \cdot k^3)$ precomputation if $k$ is the expansion factor.
- **Memory Complexity:** Derivative First requires storing a gradient grid of the same size as the density grid ($O(V)$). Interpolation First requires $O(V \cdot k^3)$ memory for the expanded grid. Continuous and Analytic derivatives require $O(1)$ extra memory per sample but no caching.
- **Strengths:** Derivative First is efficient for caching and dynamic sample distances. Interpolation First is efficient for orthographic rendering without caching.
- **Limitations:** Interpolation First becomes memory-prohibitive for high-resolution sampling (small object sample distance). Continuous and Analytic derivatives do not support caching, leading to redundant computations.

## Background
Gradient estimation schemes for volume raycasting were thoroughly compared by Moeller et al. [S1], who differentiated between the four main types: Continuous Derivative, Analytic Derivative, Interpolation First, and Derivative First. The comparison highlighted the trade-offs between numerical accuracy, image quality, and efficiency, particularly regarding caching mechanisms for interactive applications.
