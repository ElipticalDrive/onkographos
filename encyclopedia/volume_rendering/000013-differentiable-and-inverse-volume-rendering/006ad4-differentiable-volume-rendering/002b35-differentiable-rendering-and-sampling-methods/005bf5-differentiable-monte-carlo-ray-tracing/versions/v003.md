# Differentiable Monte Carlo Ray Tracing

Also called: Differentiable MC Ray Tracing

## Overview
Differentiable Monte Carlo Ray Tracing computes global illumination by combining stochastic path sampling with automatic differentiation to propagate gradients from the image plane back to scene parameters (geometry, materials, lights) [S1, unofficial]. It sets itself apart from deterministic ray marching methods like [Ray Marching with Differential Diffusion](3547-ray-marching-with-differential-diffusion.md) and screen-space derivative methods like [RGBXY Derivatives with Optimal Transport (DROT)](8830-rgbxy-derivatives-with-optimal-transport-drot.md) by replacing fixed sampling grids with stochastic estimators, which allows for unbiased radiance estimates and accelerates training in voxel-based scene representations by evaluating fewer samples per ray [S1, unofficial]. Unlike previous differentiable MC methods that avoided multi-bounce tracing due to noise and cost, this approach enables single-bounce differentiable MC ray tracing within a joint optimization framework [S1, unofficial].

## How it works
**Inputs:** Scene geometry (neural SDF fields), material properties (GGX parameters $\hat{K}_d, \hat{K}_s, \hat{\rho}$), light sources (emission array $L[\cdot]$), and camera parameters [S2].
**Outputs:** Differentiable image radiance and gradients with respect to input parameters [S2].

**Data Structures:**
The method uses a neural SDF field $\hat{M}$ for geometry, a material network for BRDF parameters, and an emission array $L[\cdot]$ for light sources [S2]. A Radiance Cache (NRC) can be used to initialize differentiable marching tetrahedrons (DMTet) and model indirect illumination [S1, unofficial].

**Steps:**
1. Cast primary ray $r: x = o + t v_s$ from the camera [S2].
2. Intersect $r$ with the neural SDF field $\hat{M}$ to find surface point $s$ and normal $\hat{N}(s)$ [S2].
3. Given a sample rate $N$, use GGX importance sampling to generate $N$ outgoing rays $\{r_k: x = s + t d_k\}_{k=1}^N$ from $s$ based on $\hat{N}(s)$ and material parameters [S2].
4. For each ray $r_k$, check the emitter mask $\hat{M}_e$; if true, retrieve emission from $L[\cdot]$, otherwise query the radiance field $F_c$ [S2].
5. Compute the radiance estimate $\hat{R}(s)$ via Monte Carlo integration [S2].
6. Compute loss and backpropagate gradients through the AD graph [S2].

**Formula:**
$$\hat{R}(s) = \frac{1}{N} \sum_{k=1}^{N} \frac{f_r(v_s, d_k; \hat{N}, \hat{K}_d, \hat{K}_s, \hat{\rho}) L_k \cos \theta_k}{p(v_s, d_k)}$$
where $f_r$ is the GGX BRDF, $p$ is the PDF, $L_k$ is the radiance of ray $r_k$, and $\theta_k$ is the angle between $d_k$ and $\hat{N}(s)$ [S2].

**Pseudocode:**
```python
def differentiable_mc_ray_tracing(ray_o, ray_d, sdf_field, material_net, emission_array, emitter_mask, N):
    # 1. Intersect ray with SDF to get surface point s and normal N_hat
    s = trace_ray(ray_o, ray_d, sdf_field)
    N_hat = compute_normal(sdf_field, s)
    
    # 2. Generate N outgoing rays using GGX importance sampling
    directions = ggx_importance_sample(N_hat, material_net(s))
    
    radiance_sum = 0.0
    for k in range(N):
        d_k = directions[k]
        # 3. Check emitter mask and retrieve radiance
        if emitter_mask(s, d_k):
            L_k = emission_array[trace_ray(s, d_k, sdf_field)]
        else:
            L_k = material_net.query_radiance(s, d_k)
        
        # 4. Compute Monte Carlo weight
        f_r = ggx_brdf(material_net(s), N_hat, d_k)
        p = ggx_pdf(N_hat, d_k)
        cos_theta = dot(N_hat, d_k)
        radiance_sum += (f_r * L_k * cos_theta) / p
        
    return radiance_sum / N
```

**Parameters:**
- **Sample Count ($N$):** Not given in the sources.
- **Bounce Depth:** Single-bounce is standard for this method [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Visibility Discontinuities:** Naive automatic differentiation misses boundary effects when an occluder edge crosses a ray, as the visibility function is a step function [S3, unofficial]. This requires specialized techniques like edge sampling [S3, unofficial].
- **Jacobian Factors:** Transformations from UV space to surface and then to camera rays involve Jacobian determinants (geometry term $\frac{\cos(\theta)}{d^2}$). Omitting these can assign equal weight to optimization variables, which may be desirable for convergence but differs from standard Monte Carlo weighting [S4].

## Subtopics

### [Monte Carlo Radiance Estimate for Scene Reconstruction](1119-monte-carlo-radiance-estimate-for-scene-reconstruction.md)
Monte Carlo Radiance Estimate (MC + RVS) is an unbiased color estimation method for differentiable volume rendering that accelerates training in voxel-based scene representations like DVGO by evaluating fewer samples per ray. It replaces deterministic ray marching with stochastic sampling, yielding a ×6 speedup over DVGO's sparsity thresholding with $k=8$ at the cost of increased estimate variance. It provides an unbiased radiance estimate for any sample count $k$, making it suitable for architectures where density field evaluation is faster than radiance field evaluation.

### Edge Sampling for Visibility Derivatives
Edge sampling is a technique to capture derivative contributions from visibility changes (discontinuities) that normal path samples miss by explicitly sampling discontinuity edges [S3, unofficial]. Unlike naive automatic differentiation which only differentiates the currently traced path and misses boundary effects when an edge crosses a ray, edge sampling captures the missing boundary term [S3, unofficial]. Introduced by Li et al. in 'Differentiable Monte Carlo Ray Tracing through Edge Sampling' at SIGGRAPH Asia 2018 [S3, unofficial].

### Jacobian Factor Omission
Jacobian factor omission is a method where explicit Jacobian terms (UV mapping distortion and geometry term $\frac{\cos(\theta)}{d^2}$) are omitted from the Monte Carlo weight calculation [S4]. This assigns equal weight to all optimization variables, implicitly introducing a factor $\alpha_j$ that cancels them out in the per-ray objective function [S4]. It contrasts with Tsai et al. [TSG19], where reconstructed surface points are sampled directly and all Jacobian terms are included; Tsai's method is suitable for non-line-of-sight reconstruction with roughly constant observation distances, whereas this method handles varying distances [S4].

## Operating characteristics
- **Time Complexity:** Depends on the sample count $N$ and bounce depth; single-bounce tracing is faster than multi-bounce [S1, unofficial].
- **Memory Complexity:** Requires storage for the scene representation (neural fields, meshes), material networks, emission arrays, and the AD graph [S2].
- **Measured Performance:** In voxel-based scene representations like DVGO, Monte Carlo radiance estimates can yield a ×6 speedup over deterministic ray marching with sparsity thresholding [S1, unofficial].
- **Strengths:** Handles complex geometry and materials via neural fields, and accelerates training in neural rendering [S1, unofficial].
- **Limitations:** High variance with few samples, noise in multi-bounce tracing limits it to single-bounce in practice [S1, unofficial], and misses visibility derivatives without edge sampling [S3, unofficial].
- **When to Use:** When unbiased gradients are required, or when scene representation evaluation is expensive compared to radiance evaluation [S1, unofficial].
- **When Not to Use:** When visibility derivatives are crucial and edge sampling is not implemented [S3, unofficial].

## Background
Differentiable Monte Carlo Ray Tracing originated from the need to optimize complex 3D scenes using gradient-based methods [S1, unofficial]. Early differentiable renderers like NVDIFFRECMC avoided multi-bounce path tracing due to noise and cost, limiting them to direct lighting [S1, unofficial]. The Joint Optimization of Triangle Mesh, Material, and Light from Neural Fields with Neural Radiance Cache (NRC) introduced single-bounce differentiable MC ray tracing to jointly optimize geometry, material, and light through backpropagation [S1, unofficial]. Edge sampling was introduced by Li et al. at SIGGRAPH Asia 2018 to handle visibility derivatives [S3, unofficial]. Jacobian factor omission was proposed in texture-space differentiable rendering to simplify optimization by omitting explicit Jacobian terms [S4].
