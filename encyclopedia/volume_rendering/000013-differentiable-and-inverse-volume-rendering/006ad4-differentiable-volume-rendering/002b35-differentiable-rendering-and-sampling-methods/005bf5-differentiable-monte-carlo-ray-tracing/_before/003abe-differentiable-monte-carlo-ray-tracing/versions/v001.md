# Differentiable Monte Carlo Ray Tracing

Also called: Differentiable MC Ray Tracing, Differentible Monte Carlo (MC) Ray Tracing

## Overview
Differentiable Monte Carlo (MC) Ray Tracing is a rendering technique that computes global illumination by applying automatic differentiation to stochastic ray tracing paths [S1, unofficial]. It enables gradient-based optimization of scene geometry, materials, and lighting by propagating derivatives through the random sampling process [S1, unofficial]. Unlike deterministic ray marching methods, it handles complex visibility and indirect lighting via single-bounce differentiable MC rendering, avoiding the noise and cost associated with multi-bounce path tracing in inverse rendering contexts [S1, unofficial].

## How it works
The method integrates standard Monte Carlo path tracing with reverse-mode automatic differentiation (AD) to compute gradients of the rendered image with respect to scene parameters [S2, unofficial].

**Inputs:**
- Scene representation (e.g., triangle mesh, neural fields) [S1, unofficial].
- Material properties (e.g., PBR parameters) [S1, unofficial].
- Light sources (e.g., HDR light probes) [S1, unofficial].
- Camera parameters [S2, unofficial].

**Outputs:**
- Rendered image (radiance) [S1, unofficial].
- Gradients of the image with respect to inputs [S2, unofficial].

**Data Structures:**
- Path state: Current position, direction, throughput, and accumulated radiance [S2, unofficial].
- Visibility function: Boolean indicator $V(e)$ for edge $e$ relative to ray position [S2, unofficial].

**Steps:**
1. **Ray Generation:** Generate primary rays from the camera through each pixel [S2, unofficial].
2. **Path Tracing:** For each ray, stochastically sample interactions (bounces) with the scene. In the context of JOC, this is limited to single-bounce differentiable MC rendering to manage noise [S1, unofficial].
3. **Radiance Estimation:** Compute the contribution of each path sample to the pixel color [S1, unofficial].
4. **Differentiation:** Apply automatic differentiation to the path tracing code. Standard AD differentiates the currently traced path but misses boundary effects when visibility changes discretely [S2, unofficial].
5. **Gradient Accumulation:** Accumulate gradients for scene parameters (geometry, material, light) [S1, unofficial].

**Formulas:**
The measurement equation is defined as [S1, unofficial]:
$$
I = \int W_e(x, \omega) L_i(x, \omega) dx d\omega
$$
where $W_e$ is the measurement weight and $L_i$ is the incoming radiance [S1, unofficial].

Visibility $V(e)$ for an occluder edge $e$ relative to a ray position $y_{ray}$ is a step function [S2, unofficial]:
$$
V(e) = \begin{cases} 
0 & \text{if } e \le y_{ray} \\
1 & \text{if } e > y_{ray}
\end{cases}
$$
Naive AD yields zero derivative almost everywhere because $V(e)$ is constant except at the discontinuity [S2, unofficial].

**Parameters:**
- Bounce count: Single-bounce is used in JOC to avoid multi-bounce noise [S1, unofficial].
- Sample count: Not specified in sources.

**Edge Cases and Pitfalls:**
- **Discontinuities:** Naive AD misses the boundary term when an edge crosses a ray, leading to incorrect gradients [S2, unofficial].
- **Noise:** Multi-bounce path tracing introduces significant noise and increased iteration time, limiting its use in inverse rendering [S1, unofficial].

**Pseudocode:**
```python
def differentiable_mc_ray_trace(ray, scene, material, light):
    # Initialize path state
    throughput = 1.0
    radiance = 0.0
    
    # Single-bounce path tracing (as per JOC)
    hit = scene.intersect(ray)
    if hit:
        # Sample material response
        bsdf = material.sample(hit)
        new_ray = ray.spawn(hit.position, bsdf.direction)
        
        # Evaluate light contribution
        light_contribution = light.evaluate(hit.position, bsdf.direction)
        
        # Accumulate radiance
        radiance += throughput * bsdf.reflectance * light_contribution
        
        # Note: Standard AD would differentiate this line.
        # However, it misses visibility changes if the hit status changes discretely.
        
    return radiance
```

## Subtopics

### [Monte Carlo Radiance Estimate for Scene Reconstruction](1119-monte-carlo-radiance-estimate-for-scene-reconstruction.md)
Monte Carlo Radiance Estimate (MC + RVS) is an unbiased color estimation method for differentiable volume rendering that accelerates training in voxel-based scene representations like DVGO by evaluating fewer samples per ray. It replaces deterministic ray marching with stochastic sampling, yielding a ×6 speedup over DVGO's sparsity thresholding with $k=8$ at the cost of increased estimate variance. It provides an unbiased radiance estimate for any sample count $k$, making it suitable for architectures where density field evaluation is faster than radiance field evaluation.

### Edge Sampling for Visibility Derivatives
Edge Sampling is a technique to capture derivative contributions from visibility changes (discontinuities) that normal path samples miss by explicitly sampling discontinuity edges [S2, unofficial]. Unlike naive automatic differentiation which only differentiates the currently traced path and misses boundary effects when an edge crosses a ray, edge sampling captures the missing boundary term [S2, unofficial]. Introduced by Li et al. in 'Differentiable Monte Carlo Ray Tracing through Edge Sampling' at SIGGRAPH Asia 2018 [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Single-bounce MC is faster than multi-bounce, but stochastic sampling is generally slower than deterministic ray marching for simple scenes [S1, unofficial].
- **Memory Complexity:** Depends on scene representation (neural fields vs. meshes) [S1, unofficial].
- **Performance:** JOC effectively prevents indirect illumination effects from being baked into materials, enabling high-quality reconstruction of triangle meshes, PBR materials, and HDR light probes [S1, unofficial].
- **Strengths:** Handles complex visibility and indirect lighting; unbiased estimates [S1, unofficial].
- **Limitations:** Multi-bounce path tracing is noisy and computationally expensive; naive AD misses visibility derivatives [S1, unofficial][S2, unofficial].
- **When to use:** Inverse rendering where global illumination and material/light optimization are required [S1, unofficial].
- **When not to use:** Real-time rendering or scenarios requiring multi-bounce global illumination with strict noise constraints [S1, unofficial].

## Background
Differentiable Monte Carlo Ray Tracing originated from the need to optimize scene parameters via gradients in inverse rendering [S2, unofficial]. The technique was formally introduced by Li et al. in 'Differentiable Monte Carlo Ray Tracing through Edge Sampling' at SIGGRAPH Asia 2018 [S2, unofficial]. It builds on the measurement equation from Veach 1998 [S1, unofficial]. Recent applications include Joint Optimization of Triangle Mesh, Material, and Light from Neural Fields with Neural Radiance Cache (JOC) [S1, unofficial].
