# Differentiable Rendering from First Principles

Also called: Gradient-based Inverse Rendering

## Overview
Differentiable rendering computes the gradient of a scalar loss of a synthesized image with respect to scene parameters (e.g., camera pose, light intensity, vertex positions), enabling gradient descent to optimize scene parameters to match observed images or to train neural networks with rendering losses [S1]. Unlike methods that approximate image formation models, this approach derives correct derivatives from first principles, explicitly handling discontinuities caused by occlusion and object boundaries without approximation [S1].

## How it works
The method treats pixel formation as an antialiasing integral, allowing the application of calculus to derive gradients even when the scene color function is discontinuous.

**Inputs and Outputs**
*   **Inputs:** Scene parameters $p$ (e.g., geometry, lighting), pixel position $\mathbf{x}$, reconstruction filter kernel $k$, and pixel filter support domain $D$.
*   **Outputs:** The gradient of the pixel color $I_x$ with respect to $p$, denoted $\frac{dI_x}{dp}$.

**Data Structures**
*   **Scene Parameter $p$:** A vector or set of variables defining the scene state.
*   **Pixel Filter Support $D$:** The 2D domain over which the reconstruction filter is non-zero (typically a square or circle centered at $\mathbf{x}$).
*   **Reconstruction Filter $k(\mathbf{x}')$:** A function defining the weighting of samples within $D$.

**Mathematical Formulation**
The color $I_x$ at 2D position $\mathbf{x}$ is defined by the antialiasing integral [S1]:

$$
I_x = \iint_D k(\mathbf{x}') f(\mathbf{x} + \mathbf{x}'; p) d\mathbf{x}' \quad (1)
$$

where:
*   $k(\mathbf{x}')$ is the reconstruction filter kernel.
*   $f(\mathbf{x}; p)$ is the color of the 3D scene at location $\mathbf{x}$ with scene parameter $p$.
*   $D$ is the pixel filter support.

**Derivation of the Gradient**
Naive differentiation fails because swapping the derivative operator $\frac{d}{dp}$ inside the integral results in Dirac delta signals at discontinuities (object boundaries/occlusion) [S1]. Area sampling (e.g., rasterization center sampling) has zero probability of hitting these infinitesimal edges, leading to incorrect gradients [S1].

To compute $\frac{dI_x}{dp}$ correctly, the derivative must be decomposed into two terms:
1.  **Interior Term:** The integral of the derivative of the scene color over the continuous regions.
2.  **Boundary Term:** The integral over the discontinuities (edges) where the scene color jumps.

$$
\frac{dI_x}{dp} = \iint_D k(\mathbf{x}') \frac{\partial f(\mathbf{x} + \mathbf{x}'; p)}{\partial p} d\mathbf{x}' + \text{Boundary Contributions}
$$

The boundary contributions arise from the movement of discontinuities (e.g., triangle edges moving across the pixel filter support) and are modeled using Dirac delta functions [S1].

**Algorithm Steps**
1.  **Evaluate Interior Gradient:** Sample the interior of the pixel filter support $D$ using standard Monte Carlo or quadrature. Compute the derivative of the scene color $\frac{\partial f}{\partial p}$ at these sample points. This accounts for changes in lighting, material properties, or geometry that do not cross pixel boundaries.
2.  **Identify Discontinuities:** Determine the locations of edges and boundaries within the pixel filter support $D$ that are sensitive to changes in $p$.
3.  **Evaluate Boundary Gradient:** Explicitly sample the derivative integral at these discontinuities. This involves calculating the contribution of the moving boundaries (Dirac delta terms) [S1].
4.  **Combine:** Sum the interior and boundary contributions to obtain the unbiased estimator for $\frac{dI_x}{dp}$ [S1].

**Pseudocode**
```python
def compute_gradient_pixel(I_x, p, scene, pixel_filter_support, reconstruction_kernel):
    """
    Computes the gradient of pixel color I_x with respect to scene parameter p.
    
    Args:
        I_x: Current pixel color value.
        p: Scene parameters (e.g., vertex positions, camera pose).
        scene: Scene representation (geometry, materials, lights).
        pixel_filter_support: Domain D of the pixel filter.
        reconstruction_kernel: Function k(x') for the filter.
        
    Returns:
        dI_x_dp: Gradient of pixel color with respect to p.
    """
    # Step 1: Interior Term (Standard Area Sampling)
    # Sample points inside the pixel filter support D
    interior_samples = sample_monte_carlo(pixel_filter_support, num_samples=100)
    
    interior_gradient = 0.0
    for x_prime in interior_samples:
        # Evaluate scene color and its derivative at the sample point
        # f(x + x'; p) is the scene color
        # df/dp is the derivative of scene color w.r.t parameters
        # Note: df/dp is non-zero only where f is continuous
        color_val = scene.evaluate_color(x_prime, p)
        color_deriv = scene.evaluate_color_derivative(x_prime, p)
        
        # Weight by reconstruction kernel
        weight = reconstruction_kernel(x_prime)
        
        # Accumulate interior gradient contribution
        interior_gradient += weight * color_deriv
        
    # Average over samples (Monte Carlo estimation)
    interior_gradient /= len(interior_samples)
    
    # Step 2: Boundary Term (Explicit Sampling of Discontinuities)
    # Identify edges/boundaries within the pixel filter support
    # This requires detecting where the scene color f is discontinuous
    # and how these boundaries move with p.
    
    boundary_gradient = 0.0
    edges = scene.get_edges_within_support(pixel_filter_support, p)
    
    for edge in edges:
        # Calculate the contribution of the moving boundary
        # This involves the Dirac delta function at the edge location
        # The derivative of the integral includes a term for the boundary velocity
        # d/dp int(f) = int(df/dp) + int(f * delta(edge) * d(edge)/dp)
        
        # Evaluate the scene color at the edge
        edge_color = scene.evaluate_color_at_edge(edge, p)
        
        # Calculate the velocity of the edge with respect to p
        # This is the derivative of the edge position w.r.t p
        edge_velocity = scene.get_edge_velocity(edge, p)
        
        # Weight by reconstruction kernel at the edge location
        # Note: The edge location is relative to the pixel center
        edge_location = edge.get_location_relative_to_pixel_center()
        weight = reconstruction_kernel(edge_location)
        
        # Accumulate boundary gradient contribution
        # The sign depends on the orientation of the edge and the direction of movement
        boundary_gradient += weight * edge_color * edge_velocity
        
    # Step 3: Combine
    dI_x_dp = interior_gradient + boundary_gradient
    
    return dI_x_dp
```

**Parameters and Typical Values**
*   **Number of Samples:** The number of Monte Carlo samples for the interior term should be sufficient to reduce variance. The number of boundary samples depends on the number of edges intersecting the pixel filter support.
*   **Reconstruction Filter:** Common filters include box, tent, Gaussian, or Lanczos. The choice affects the smoothness of the gradient.

**Edge Cases and Pitfalls**
*   **Naive Differentiation:** Swapping the derivative operator inside the integral without accounting for boundary terms leads to incorrect gradients [S1].
*   **Zero Probability of Hitting Edges:** Area sampling has zero probability of hitting infinitesimal edges, so explicit boundary sampling is required [S1].
*   **Discontinuities:** The method must handle all types of discontinuities, including occlusion, shadow boundaries, and object boundaries [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the number of samples for interior and boundary terms. Boundary sampling adds overhead proportional to the number of edges intersecting the pixel filter support.
*   **Memory Complexity:** Low, as it does not require storing large intermediate structures beyond the scene representation.
*   **Strengths:** Provides correct, unbiased gradients for differentiable rendering, handling discontinuities without approximation [S1].
*   **Limitations:** Requires explicit handling of boundaries, which can be complex to implement for all rendering phenomena (e.g., global illumination, soft shadows) [S1].
*   **When to Use:** When accurate gradients are required for inverse rendering or training neural networks with rendering losses, especially in scenes with significant occlusion or moving boundaries [S1].

## Background
The method was introduced in the context of differentiable visual computing, emphasizing the need to derive correct derivatives from first principles rather than approximating image formation models [S1]. It builds on the observation that pixel formation can be modeled as an antialiasing integral, allowing the application of calculus to derive gradients [S1]. The approach has been implemented in the GPU differentiable renderer 'redner' [S1].
