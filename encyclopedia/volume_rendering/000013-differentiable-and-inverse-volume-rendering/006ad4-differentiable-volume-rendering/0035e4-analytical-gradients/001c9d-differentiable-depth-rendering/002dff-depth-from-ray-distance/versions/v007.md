# Depth from Ray Distance


## Overview
Depth from Ray Distance converts the scalar ray distance $d$ into camera-space depth $z_c$ [S1]. This conversion is necessary because standard depth maps represent the $z$-coordinate in the camera frame, not the arc length along the ray [G]. It differs from sibling methods like [Median Depth Rendering](8815-median-depth-rendering.md) or [Sigma-Threshold Depth Rendering](5955-sigma-threshold-depth-rendering.md) by providing a continuous, differentiable geometric metric derived directly from the ray integration distance, rather than a discrete sample index or threshold crossing point [G].

## How it works
**Inputs and Outputs:**
- Input: Ray distance $d$ (scalar, output of differentiable volume rendering), pixel coordinates $(x, y)$, camera intrinsic matrix $K$ [S1].
- Output: Camera-space depth $z_c$ [S1].

**Data Structures:**
- $K$: $3 \times 3$ camera intrinsic matrix [S1].
- $(x, y)$: Integer pixel coordinates [S1].
- $d$: Float32 ray distance [S1].

**Steps:**
1. Compute the normalized homogeneous coordinate vector by applying the inverse camera intrinsics to the pixel coordinates:
   $$ \begin{bmatrix} \tilde{x} \\ \tilde{y} \\ 1 \end{bmatrix} = K^{-1} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix} $$ [S1]
2. Calculate the norm of the normalized direction vector:
   $$ \|\mathbf{v}_{norm}\| = \sqrt{\tilde{x}^2 + \tilde{y}^2 + 1} $$ [S1]
3. Compute the camera-space depth $z_c$ by dividing the ray distance $d$ by this norm:
   $$ z_c = \frac{d}{\|\mathbf{v}_{norm}\|} = \frac{d}{\sqrt{\tilde{x}^2 + \tilde{y}^2 + 1}} $$ [S1]

**Formulas:**
- $z_c = d / \sqrt{\tilde{x}^2 + \tilde{y}^2 + 1}$ [S1]
- $\begin{bmatrix} \tilde{x} \\ \tilde{y} \\ 1 \end{bmatrix} = K^{-1} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix}$ [S1]

**Parameters:**
- $K$: Camera intrinsic matrix. Not given in the sources.
- $d$: Ray distance from the parent method [Differentiable Depth Rendering](1332-differentiable-depth-rendering.md).

**Edge Cases and Pitfalls:**
- Division by zero: The term $\sqrt{\tilde{x}^2 + \tilde{y}^2 + 1}$ is always $\ge 1$ for valid pixel coordinates, so division by zero is not possible [G].
- Precision: Ensure $K^{-1}$ is computed with sufficient precision to avoid numerical drift in $\tilde{x}$ and $\tilde{y}$ [G].

**Pseudocode:**
```python
import torch

def depth_from_ray_distance(d: torch.Tensor, x: torch.Tensor, y: torch.Tensor, K: torch.Tensor) -> torch.Tensor:
    """
    Convert ray distance d to camera-space depth z_c.
    
    Args:
        d: Ray distance tensor of shape (N,) or (H, W).
        x: Pixel x-coordinates tensor of shape (N,) or (H, W).
        y: Pixel y-coordinates tensor of shape (N,) or (H, W).
        K: Camera intrinsic matrix of shape (3, 3).
        
    Returns:
        z_c: Camera-space depth tensor of the same shape as d.
    """
    # Ensure inputs are on the same device
    device = d.device
    dtype = d.dtype
    
    # Create homogeneous pixel coordinates: shape (..., 3)
    ones = torch.ones_like(x)
    pixel_coords = torch.stack([x, y, ones], dim=-1)
    
    # Compute normalized homogeneous coordinates: shape (..., 3)
    K_inv = torch.inverse(K)
    v_norm = torch.matmul(pixel_coords, K_inv.T)
    
    # Extract tilde_x and tilde_y
    tilde_x = v_norm[..., 0]
    tilde_y = v_norm[..., 1]
    
    # Calculate norm of normalized direction vector
    norm = torch.sqrt(tilde_x**2 + tilde_y**2 + 1.0)
    
    # Compute camera-space depth
    z_c = d / norm
    
    return z_c
```

## Subtopics

### [Expected Term Rendering](5952-expected-term-rendering.md)
Expected Term Rendering computes the expected termination distance (depth) for each ray traversing a volume, returning a tensor of size $Q$ (number of rays). It differs from standard depth rendering by calculating the weighted mean of sample depths along the ray, where weights are derived from the volume's transmittance and absorption properties [G]. This method builds on [Depth from Ray Distance](5665-depth-from-ray-distance.md) by specifically implementing the expected value strategy for depth estimation. Choose it when a probabilistic depth estimate that accounts for volumetric transparency is required.

### [Sigma-Threshold Depth Rendering](5955-sigma-threshold-depth-rendering.md)
Sigma-Threshold Depth Rendering computes a binary mask indicating the sample index where cumulative weight accumulation exceeds a specified density threshold, effectively identifying a 'surface' location along the ray. It serves as a differentiable depth estimation method that renders a binary or thresholded output based on whether volume density exceeds a given value, referencing the approach used in Dex-NeRF. Unlike Expected Term Rendering which computes the mean distance, or Median Depth Rendering which finds the median, this method identifies the depth at which the accumulated opacity crosses a hard boundary. It builds on [Depth from Ray Distance](5665-depth-from-ray-distance.md) by introducing a termination condition based on accumulated sigma rather than fixed sample counts or probabilistic expectations. Choose it when a sharp, threshold-based surface cue is needed.

### [Median Depth Rendering](8815-median-depth-rendering.md)
Median Depth Rendering computes the geometric depth of a volume by identifying the sample along a ray where the accumulated transmittance drops to 0.5. It solves the bias introduced by residual density in free space that affects Expected Depth Rendering, providing a sharper and less biased geometric representation for ambiguous or sparse scenes. Unlike Expected Depth Rendering, which integrates the entire ray's contribution to find a weighted average, Median Depth Rendering selects a single threshold-crossing point, making it robust to noise in empty regions. Choose it when robust geometric depth is needed without volumetric averaging bias.

### [Robust Depth-Range Estimation](10825-robust-depth-range-estimation.md)
Estimates a robust clipped depth range $[z_{min}, z_{max}]$ for binning by sampling visible Gaussians, applying a near-depth shift, and selecting percentiles via exact order statistics. It sets itself apart from sibling methods like Median Depth Rendering by using percentile-based range estimation with exact order statistics rather than a single median value, ensuring the binning range covers the majority of contributing geometry while excluding outliers. Choose it when establishing safe depth bounds for ray marching or binning is required.

## Background
The method originates from the need to convert ray-based rendering outputs into standard depth map formats for integration with RGB-D sensors and SLAM systems [S1, S2]. It is used in RGB-D Mapping and Tracking in a Plenoxel Radiance Field [S2] and DIST: Rendering Deep Implicit Signed Distance Function With Differentiable Sphere Tracing [S1]. The conversion is a standard geometric operation in computer vision, relating ray space to camera space [G].
