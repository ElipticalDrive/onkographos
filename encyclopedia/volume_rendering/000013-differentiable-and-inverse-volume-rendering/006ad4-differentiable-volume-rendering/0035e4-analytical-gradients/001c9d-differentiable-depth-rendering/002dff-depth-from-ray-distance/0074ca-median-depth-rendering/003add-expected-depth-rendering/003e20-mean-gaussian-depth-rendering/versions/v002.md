# Mean Gaussian Depth Rendering

Also called: Expected Depth, Mean Depth Calculation

## Overview
Mean Gaussian Depth Rendering computes the expected depth of a ray by calculating the weighted mean of sample depths, where weights are derived from the Gaussian's opacity, 2D contribution, and transmittance [S2]. It differs from Mode Depth Rendering, which selects the single Gaussian with the highest weight, by integrating contributions from all Gaussians along the ray to produce a continuous depth value [S3]. This method builds on [Expected Depth Rendering](8816-expected-depth-rendering.md) [G].

## How it works
**Inputs:**
- A set of $N$ 3D Gaussians $\{G_k\}_{k=1}^N$ [G].
- For each Gaussian $k$: center position $\mathbf{c}_k$ (from which depth $d_k$ is derived, typically the z-coordinate in camera space) [G], opacity $\alpha_k$ (or density $\sigma_k$ converted to opacity) [G], 2D covariance matrix $\mathbf{\Sigma}_k$ (projected to image plane) [G], view direction and camera intrinsics [G].

**Outputs:**
- A scalar depth value $d(\mathbf{x})$ for each pixel $\mathbf{x}$ [G].

**Data Structures:**
- Gaussians are sorted by depth $d_k$ along the ray to ensure correct front-to-back compositing for transmittance calculation [G].

**Pseudocode:**
```python
def compute_mean_depth(gaussians, pixel_x):
    # Sort Gaussians by depth d_k front-to-back [G]
    gaussians.sort(key=lambda g: g.depth)
    T = 1.0
    accumulated_depth = 0.0
    for k in range(len(gaussians)):
        G = gaussians[k]
        # Calculate 2D Gaussian contribution at pixel x [G]
        G_contrib = evaluate_2d_gaussian(G.covariance, G.center, pixel_x)
        # Calculate opacity contribution o_k [G]
        o_k = G.opacity
        # Calculate weight w_k
        w_k = o_k * G_contrib * T
        # Update accumulated depth
        accumulated_depth += G.depth * w_k
        # Update transmittance
        T = T * (1 - o_k * G_contrib)
        # Early termination if transmittance is negligible [G]
        if T < 1e-5:
            break
    return accumulated_depth
```

**Formula:**
The mean depth $d(\mathbf{x})$ for a pixel $\mathbf{x}$ is computed as the weighted sum of Gaussian depths [S2]:
$$d(\mathbf{x}) = \sum_{k=1}^N d_k o_k \mathcal{G}_k^{\text{D}}(\mathbf{x}) T_k \quad (5)$$
where:
- $d_k$ is the depth of the $k$-th Gaussian [G].
- $o_k$ is the opacity contribution of the $k$-th Gaussian [G].
- $\mathcal{G}_k^{\text{D}}(\mathbf{x})$ is the 2D Gaussian contribution (density) at pixel $\mathbf{x}$ [G].
- $T_k = \prod_{j=1}^{k-1} (1 - o_j \mathcal{G}_j^{\text{D}}(\mathbf{x}))$ is the transmittance up to the $k$-th Gaussian [G].

An alternative normalization used in meshing processes divides by the accumulated alpha to ensure planar 2D disk rendering [S1]:
$$z_{\text{mean}} = \frac{\sum_i \omega_i z_i}{\sum_i \omega_i + \epsilon} \quad (18)$$
where $\omega_i$ is the weight contribution of the $i$-th Gaussian and $\epsilon$ is a small constant for numerical stability [S1].

**Parameters:**
- $\epsilon$: Small constant for numerical stability in normalization [S1]. Typical value: $10^{-5}$ [G].
- Transmittance threshold for early termination: $10^{-5}$ [G].

**Pitfalls:**
- **Inconsistency with Volumetric Density:** Fitting volumetric density (e.g., from ToF phase encoding) does not guarantee consistency with the rendered mean depth [S2]. If multiple density peaks exist along a ray but only one surface exists, the rendered mean depth diverges from the depth derived from raw quads [S2].
- **Jensen's Inequality:** The discrepancy arises because sine/cosine functions in phase encoding oscillate, preventing equality in the finite form of Jensen's inequality [S2].
- **Clustering Requirement:** The gap between fitted density and rendered depth reduces only when all Gaussians are clustered at the same z-position along each ray [S2].
- **Normalization:** Without normalization, the output is an unnormalized moment rather than a true expected value [S1].

## Subtopics

### Mode Depth Rendering
Mode Depth Rendering selects the depth of the single Gaussian with the largest contributing weight $w_i = T_i \alpha_i$ as the pixel depth [S3]. The formula is $d_{\text{mode}_{x,y}} = d_{\arg \max_i (w_i)}$ [S3]. It differs from Mean Gaussian Depth Rendering by ignoring all other Gaussians, making it discrete and sensitive to the highest-opacity Gaussian rather than a weighted average [S3]. It is chosen when a sharp, single-surface depth is preferred over a continuous expected depth, though it may create ambiguity if low-weight Gaussians with greater depths influence the scene geometry [S3].

## Operating characteristics
- **Time and Memory Complexity:** Not given in the sources.
- **Strengths:** Suitable for meshing processes and differentiable training [S1, S2]. Integrates contributions from all Gaussians along the ray to produce a continuous depth value [S3].
- **Limitations:** Fitting volumetric density does not guarantee consistency with rendered mean depth [S2]. Diverges from raw quad-derived depth when multiple density peaks exist along a ray [S2].
- **When to use:** When a continuous depth estimate is required for meshing or differentiable rendering [S1, S2].
- **When not to use:** When a sharp, single-surface depth is required, or when the scene has multiple distinct surfaces along a ray and averaging is undesirable [S3].

## Background
Mean Gaussian Depth Rendering is used in optimizing 3D Gaussian Splatting for depth estimation, particularly from Time-of-Flight (ToF) cameras [S2]. It addresses the challenge that optimized volumetric properties (phasors or raw quads) are not the same as the property of interest (depth) [S2]. The method also supports meshing processes where normal consistency and accurate depth are required [S1].
