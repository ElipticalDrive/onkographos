# Expected Depth Rendering

Also called: Expected Depth Calculation, DepthRenderer.method='expected'

## Overview
Expected Depth Rendering computes the geometric center of mass of a ray's interaction with a volume or Gaussian mixture by calculating the weighted average of sample depths, normalized by the accumulated transmittance weight [S1]. It provides a continuous, differentiable depth signal that is numerically stable for downstream tasks such as pseudo-normal estimation and ray-tracing initialization [S1]. Unlike Median Depth Rendering, which selects a discrete sample index based on a cumulative opacity threshold, Expected Depth Rendering integrates contributions from all samples along the ray, resulting in smoother gradients and superior reconstruction quality for inverse rendering pipelines [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `z`: Tensor or array of depth samples (or sample positions $t_i$) along each ray [S1, S5].
    *   `w`: Tensor or array of per-sample weights. For Gaussian mixtures, $w_i = T_i g_i \alpha_i$ [S1]. For volumetric density, $w_i = T_i (1 - \exp(-\sigma_i \delta_i))$ [S5].
    *   `T`: Transmittance tensor, where $T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)$ or the product of $(1-\alpha_j)$ for Gaussians [S1, S5].
    *   `ray_indices`: Optional packed indices mapping samples to rays (used in sparse implementations) [S2, unofficial].
    *   `num_rays`: Total number of rays (used in sparse implementations) [S2, unofficial].
*   **Outputs:**
    *   `depth`: Tensor or array of expected depth values for each ray [S4, unofficial].

**Data Structures:**
*   **Samples:** Stored as 1D or 2D arrays. In packed formats (e.g., `nerfacc`), samples are flattened into a 1D array with a corresponding `ray_indices` array indicating which ray each sample belongs to [S2, unofficial].
*   **Weights:** Must be non-negative. In Gaussian splatting, this combines the Gaussian response $g_i$, opacity $\alpha_i$, and transmittance $T_i$ [S1].

**Steps:**
1.  **Compute Sample Positions:** Determine the depth value $z_i$ for each sample. If only frustum bounds are available, compute midpoints: $z_i = (\text{starts}_i + \text{ends}_i) / 2$ [S2, S3, unofficial].
2.  **Compute Weights:** Calculate the weight $w_i$ for each sample. For Gaussian mixtures: $w_i = T_i g_i \alpha_i$ [S1]. For volumetric density: $w_i = T_i (1 - \exp(-\sigma_i \delta_i))$ [S5].
3.  **Accumulate Weights:** Compute the total accumulated weight $W$ for each ray: $W = \sum_{i \in N} w_i$ [S1].
4.  **Compute Expected Depth:** Calculate the weighted sum of depths and normalize by the total weight: $z_E = \frac{\sum_{i \in N} w_i z_i}{W}$ [S1].
5.  **Numerical Stability:** Add a small constant $\epsilon$ to the denominator to prevent division by zero in empty regions [G].
6.  **Clipping:** Clip the resulting depth to $[\min(z), \max(z)]$ to handle boundary artifacts [S2, S3, unofficial].

**Pseudocode:**
```python
def expected_depth_rendering(z, weights, eps=1e-7):
    """
    Compute expected depth from sample depths and weights.
    
    Args:
        z: 2D array of shape (N_rays, N_samples) containing sample depths.
        weights: 2D array of shape (N_rays, N_samples) containing per-sample weights.
        eps: Small constant for numerical stability.
        
    Returns:
        depth: 1D array of shape (N_rays) containing expected depth.
    """
    depth = []
    for ray_z, ray_w in zip(z, weights):
        weighted_sum = sum(w * z_val for w, z_val in zip(ray_w, ray_z))
        total_w = sum(ray_w)
        d = weighted_sum / (total_w + eps)
        d = max(min(d, max(ray_z)), min(ray_z))  # Clip to [min(z), max(z)]
        depth.append(d)
    return depth

def expected_depth_rendering_packed(z, weights, ray_indices, num_rays, eps=1e-7):
    """
    Compute expected depth for packed ray samples.
    
    Args:
        z: 1D array of sample depths.
        weights: 1D array of sample weights.
        ray_indices: 1D array mapping each sample to a ray index.
        num_rays: Total number of rays.
        eps: Small constant for numerical stability.
        
    Returns:
        depth: 1D array of shape (num_rays) containing expected depth.
    """
    depth_sum = [0.0] * num_rays
    weight_sum = [0.0] * num_rays
    
    for i in range(len(z)):
        r = ray_indices[i]
        depth_sum[r] += weights[i] * z[i]
        weight_sum[r] += weights[i]
        
    depth = [d / (w + eps) for d, w in zip(depth_sum, weight_sum)]
    return depth
```

**Parameters:**
*   `eps`: Small constant for numerical stability to prevent division by zero [G].
*   `method`: Strategy for computing depth. The value `'expected'` denotes the weighted mean approach [S6, unofficial].

**Edge Cases and Pitfalls:**
*   **Empty Rays:** If a ray hits no geometry, $W=0$. Division by zero is prevented by adding $\epsilon$ [G].
*   **Boundary Conditions:** Depth values at the start/end of the ray may be biased if the volume extends beyond the sampled interval. Clipping to $[z_{min}, z_{max}]$ mitigates this [S2, S3, unofficial].

## Subtopics

### [Mean Gaussian Depth Rendering](9666-mean-gaussian-depth-rendering.md)
Computes the expected depth of a ray by calculating the weighted mean of sample depths, where weights are derived from the Gaussian's opacity, 2D contribution, and transmittance. It differs from Mode Depth Rendering, which selects the single Gaussian with the highest weight, by integrating contributions from all Gaussians along the ray to produce a continuous depth value. This method builds on [Expected Depth Rendering](8816-expected-depth-rendering.md).

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Linear in the number of samples to store depths and weights [G].
*   **Strengths:** Provides a smooth, continuous depth signal that is robust to noise and suitable for normal estimation [S1]. It integrates information from the entire ray, reducing artifacts from sparse sampling [S1].
*   **Limitations:** Produces a continuous average rather than a discrete surface location, which may not suit methods requiring exact hit points [S1].
*   **When to Use:** When a continuous depth signal is needed for gradient-based optimization, pseudo-normal estimation, or ray-tracing initialization [S1]. Preferred over inverse-depth variants for overall reconstruction quality [S1].
*   **When Not to Use:** When a discrete surface location is required [S1].

## Background
Expected Depth Rendering originates from foundational volumetric rendering techniques, computing depth by weighting samples by their depth position analogous to color rendering [S5]. It is widely used in 3D Gaussian Splatting variants for geometry supervision, where it provides a stable geometric signal for pseudo-normal estimation and ray-tracing initialization [S1]. The method is often compared with Median Depth Rendering, which uses a threshold-based accumulation point [S3, unofficial].
