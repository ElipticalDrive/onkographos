# RGBXY Derivatives with Optimal Transport (DROT)

Also called: Basic, Hybrid

## Overview
RGBXY Derivatives with Optimal Transport (DROT) is a differentiable rendering method that associates each screen-space pixel with a visible 3D geometric point (point proxy) to compute 5D RGBXY derivatives, measuring how 3D RGB color and 2D projected screen-space position change with respect to scene parameters [S1]. It combines these dense derivatives with an optimal transport-based loss function to find pixel matching between rendered and target images, solving the problem of converging in inverse rendering when initial and target object locations are not close [S1]. Unlike traditional methods that rely on sparse, local per-pixel color derivatives and L2 loss, DROT captures global and long-range object motions, making it superior for optimizing global translations and rotations [S1].

## How it works
**Inputs:**
*   Scene parameters $\theta$ (e.g., transformation matrices for furniture models).
*   Target image $I_{target}$ (resolution $256 \times 256$ in experiments) [S1].
*   Camera parameters (intrinsics and extrinsics) [S1].
*   Geometric representation (e.g., triangle meshes) [S1].

**Outputs:**
*   Optimized scene parameters $\theta^*$ [S1].
*   Rendered image $I_{rendered}$ [S1].

**Data Structures:**
*   **Point Proxy:** For each pixel $(u, v)$ in the rendered image, the point proxy is the visible 3D geometric point on the mesh covered by the center of the pixel. This requires a visibility test (e.g., ray casting or rasterization depth buffer) to find the closest surface point $P_{proxy}$ for each pixel [S1].
*   **RGBXY Derivative Vector:** A 5-dimensional vector for each point proxy, containing partial derivatives of the RGB color values and the 2D screen-space coordinates $(X, Y)$ with respect to the scene parameters $\theta$ [S1].

**Steps:**
1.  **Render and Identify Point Proxies:** Render the scene to obtain the image $I_{rendered}$ and depth buffer. For each pixel $(u, v)$, identify the visible 3D geometric point $P_{proxy}$ on the mesh surface that projects to the pixel center. This point is the "point proxy" for that pixel [S1].
2.  **Compute RGBXY Derivatives:** For each point proxy $P_{proxy}$, compute the 5D RGBXY derivatives. This involves calculating the partial derivatives of the 3D RGB color $C$ and the 2D screen-space position $(X, Y)$ with respect to the scene parameters $\theta$ [S1].
    *   Let $\theta$ be the vector of optimization variables (e.g., translation in X-Z plane and rotation around Y axis) [S1].
    *   The derivative vector $D$ for a proxy is:
        $$ D = \left[ \frac{\partial C_r}{\partial \theta}, \frac{\partial C_g}{\partial \theta}, \frac{\partial C_b}{\partial \theta}, \frac{\partial X}{\partial \theta}, \frac{\partial Y}{\partial \theta} \right]^T $$
    *   These derivatives are dense because they are computed on geometric points rather than a fixed grid of pixels, allowing them to account for global motions [S1].
3.  **Optimal Transport Matching:** Use optimal transport to find a matching between the pixels of the rendered image $I_{rendered}$ and the target image $I_{target}$. This step establishes correspondences between objects in the rendered and target images, even if they are not perfectly aligned [S1].
4.  **Compute Loss:** Design a loss function based on the pixel matching obtained from optimal transport. The loss incorporates the RGBXY derivatives to guide the optimization [S1].
5.  **Optimize:** Update the scene parameters $\theta$ using gradient descent (or similar optimizer) using the computed gradients from the loss function. Repeat until convergence [S1].

**Pseudocode:**
```python
def optimize_scene(scene_params, target_image, camera, mesh):
    """
    Optimizes scene parameters using DROT.
    scene_params: Initial transformation parameters (e.g., translation, rotation).
    target_image: Target RGB image (256x256).
    camera: Camera intrinsics and extrinsics.
    mesh: 3D geometric model (e.g., furniture).
    """
    # Initialize optimizer
    optimizer = torch.optim.Adam(scene_params, lr=0.01)
    
    for iteration in range(max_iterations):
        # 1. Render scene with current parameters
        rendered_image, depth_buffer = render(scene_params, camera, mesh)
        
        # 2. Identify point proxies for each pixel
        # For each pixel (u, v), find the visible 3D point on the mesh
        point_proxies = []
        for u in range(width):
            for v in range(height):
                # Ray cast from camera through pixel (u, v)
                ray = camera.get_ray(u, v)
                # Find intersection with mesh
                hit_point, hit_normal, hit_color = mesh.intersect(ray)
                if hit_point is not None:
                    point_proxies.append({
                        'pixel': (u, v),
                        'point': hit_point,
                        'color': hit_color,
                        'screen_pos': (u, v)
                    })
        
        # 3. Compute RGBXY derivatives for each point proxy
        # This requires differentiable rendering or automatic differentiation
        # through the intersection and shading process
        derivatives = []
        for proxy in point_proxies:
            # Compute partial derivatives of color and screen position w.r.t scene_params
            # Note: In practice, this is done via autograd in a differentiable renderer
            d_color = compute_color_derivatives(proxy['color'], scene_params)
            d_screen = compute_screen_derivatives(proxy['screen_pos'], scene_params)
            derivatives.append(torch.cat([d_color, d_screen]))
        
        # 4. Optimal Transport Matching
        # Compute cost matrix between rendered and target pixels
        # Cost is typically based on color difference
        cost_matrix = compute_cost_matrix(rendered_image, target_image)
        # Solve optimal transport problem to get matching
        matching = solve_optimal_transport(cost_matrix)
        
        # 5. Compute Loss
        # Loss is based on the matching and the RGBXY derivatives
        loss = compute_drot_loss(matching, derivatives, rendered_image, target_image)
        
        # 6. Update parameters
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        if iteration % 100 == 0:
            print(f"Iteration {iteration}, Loss: {loss.item()}")
            
    return scene_params
```

**Parameters:**
*   Optimization variables: Transformations including translation within X-Z plane and rotation around Y axis for furniture models [S1].
*   Rendering resolution: $256 \times 256$ rasterized images [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The method relies on accurate visibility tests to identify point proxies. Occlusions or self-intersections can lead to incorrect proxies.
*   **Boundaries:** The method is designed to handle cases where initial and target object locations are far apart, but the optimal transport step may struggle if the images are completely disjoint or have significant noise.
*   **Degenerate Input:** If the mesh has no visible surface for a pixel (e.g., background), the point proxy is undefined. The method assumes a foreground object covers the pixels of interest.

## Subtopics

### Basic
The core DROT method using RGBXY derivatives and optimal transport. It is chosen when global object motions need to be optimized from a distant initialization. [Link](4973-differentiable-rendering-and-sampling-methods.md)

### Hybrid
A combination of DROT with traditional differentiable rendering methods. It is chosen to further improve accuracy in inverse rendering tasks by leveraging the strengths of both approaches. [Link](4973-differentiable-rendering-and-sampling-methods.md)

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:**
    *   **Bedroom Scene:** Basic method achieves MAE 6.084mm / PSNR 30.07; Hybrid achieves MAE 5.580mm / PSNR 30.87. Compared against PyTorch3D (447.4/15.01), Nvdiffrast (449.4/14.72), and Basic (447.4/15.01) [S1].
    *   **Living Room Scene:** Basic method achieves MAE 8.562mm / PSNR 29.52; Hybrid achieves MAE 7.903mm / PSNR 35.95. Compared against PyTorch3D (278.9/16.91), Nvdiffrast (317.3/16.56), and Basic (278.9/16.91) [S1].
*   **Scaling:** Not given in the sources.
*   **Strengths:** Dense RGBXY derivatives and optimal transport allow for robust convergence in inverse rendering, especially for global and long-range object motions when initial and target positions are far apart. It outperforms traditional methods like PyTorch3D and Nvdiffrast in terms of MAE and PSNR [S1].
*   **Limitations:** Traditional differentiable rendering approaches are hard to converge when initial and target object locations are not close. Per-pixel color derivatives are sparse and local, leading to less robustness in optimization [S1].
*   **When to use:** Automatic furniture layout adjustment and other inverse rendering tasks where global object motions need to be optimized from a distant initialization [S1].
*   **When not to use:** Fine-scale geometry refinement with sufficiently overlapped and aligned image regions, where traditional per-pixel color derivatives are naturally well suited [S1].

## Background
RGBXY Derivatives with Optimal Transport (DROT) was introduced by Jiankai Xing, Houde Qian, and Kun Xu from BNRist, Department of CS&T, Tsinghua University, China [S1]. The method is inspired by Lagrangian fluid simulation and aims to address the convergence issues in inverse rendering optimizations [S1]. It was presented in the paper "Differentiable Rendering Using RGBXY Derivatives and Optimal Transport" [S1].
