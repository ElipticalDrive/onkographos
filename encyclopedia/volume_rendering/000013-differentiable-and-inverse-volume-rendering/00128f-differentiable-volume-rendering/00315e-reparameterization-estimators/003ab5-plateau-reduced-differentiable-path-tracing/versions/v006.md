# Plateau-Reduced Differentiable Path Tracing

Also called: PR-DPT, Differentiable Path Tracing with Derivative-Kernel (Our∂κP), Convolutional Gradient Estimation, Our∂κP

## Overview
Plateau-Reduced Differentiable Path Tracing (PR-DPT) is an inverse rendering technique that alleviates optimization plateaus (regions of zero gradient) by convolving the rendering equation with a smoothing kernel over the parameter space [S1]. Unlike standard differentiable path tracers that suffer from discontinuous gradients due to visibility changes, PR-DPT ensures that small parameter changes continuously influence the objective function in expectation, allowing gradient-based optimizers to converge on problems with intricate light transport such as caustics or global illumination [S1]. It sets itself apart from reparameterization estimators by not requiring a special integrator for visibility-induced discontinuities or the construction of a gradient tape, instead relying on a forward model and stochastic parameter perturbation [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A non-differentiable or differentiable rendering function $P(\theta)$ (or scene function $f(x, \theta)$), current parameters $\theta$, initial kernel spread $\sigma_0$, minimum kernel spread $\sigma_m$, and number of samples $N$.
*   **Outputs:** An estimate of the gradient $\nabla_\theta Q(\theta)$ of the plateau-reduced objective.

**Data Structures:**
*   $\theta$: Scene parameters (e.g., position, rotation, texture values).
*   $\tau$: Parameter offset vector, sampled from the kernel distribution.
*   $\xi$: Uniform random number in $(0, 1)$.

**Formulas:**
The plateau-reduced rendering equation $Q(\theta)$ is the convolution of the original rendering equation $P(\theta)$ with a symmetric, monotonous decreasing kernel $\kappa(\tau)$ over the parameter space $\Theta$ [S1]:
$$
Q(\theta) = \kappa * P(\theta) = \int_{\Theta} \int_{\Omega} \kappa(\tau) f(x, \theta - \tau) dx d\tau
$$
where $x \in \Omega$ are light paths and $\tau$ is the parameter offset [S1].

The Monte Carlo estimator for $Q(\theta)$ is:
$$
\hat{Q} \approx \frac{1}{N} \sum_{i=1}^{N} \kappa(\tau_i) f(x_i, \theta - \tau_i)
$$
where $N$ is the number of perturbations (samples) [S1].

For gradient estimation, two cases exist [S1]:
1.  **Differentiable Renderer:** If $\frac{\partial P}{\partial \theta}$ is available:
    $$
    \frac{\partial Q}{\partial \theta} = \frac{1}{N} \sum_{i=1}^{N} \kappa(\tau_i) \frac{\partial P}{\partial \theta}(\theta - \tau_i)
    $$
2.  **Non-Differentiable Renderer (Our∂κP):** If only $P$ is available, the gradient is estimated by weighting the rendering result by the gradient of the blur kernel [S1]:
    $$
    \frac{\partial Q}{\partial \theta} \approx \frac{1}{N} \sum_{i=1}^{N} \frac{\partial \kappa}{\partial \theta}(\tau_i) P(\theta - \tau_i)
    $$
    Note: The derivative is taken with respect to the parameter $\theta$, which shifts the argument of the kernel. For a Gaussian kernel $\kappa(\tau) = \frac{1}{\sigma\sqrt{2\pi}} \exp\left(-\frac{\tau^2}{2\sigma^2}\right)$, the gradient with respect to the shift $\tau$ (which corresponds to $-\frac{\partial}{\partial \theta}$ acting on $P(\theta-\tau)$) is [S1]:
    $$
    \frac{\partial \kappa}{\partial \theta}(\tau) = -\frac{\partial \kappa}{\partial \tau}(\tau) = \sqrt{\frac{2}{\sigma^2 \pi}} \frac{-\tau}{\sigma^2} \exp\left(\frac{-\tau^2}{2\sigma^2}\right)
    $$
    *Correction based on source notation:* The source defines $\frac{\partial \kappa}{\partial \theta}(\tau)$ in Eq. 11 as $\sqrt{\frac{2}{\sigma^2 \pi}} \frac{-\tau}{\sigma^2} \exp\left(\frac{-\tau^2}{2\sigma^2}\right)$. This term is negative for $\tau > 0$.

**Parameters:**
*   $\kappa(\tau)$: Gaussian kernel is used for simplicity [S1].
*   $\sigma$: Standard deviation of the blur kernel. Decays from $\sigma_0$ to $\sigma_m$ [S1].
*   $\sigma_0$: Initial kernel spread. Typical default: 0.5 (roughly 50% of the domain) [S1].
*   $\sigma_m$: Minimum value for $\sigma$. Set to 0.01 to avoid numerical instabilities [S1].
*   $N$: Number of perturbations. Typical values: 2, 4, 8, 16, 32. $N=2$ is common [S1].
*   $spp$: Samples per pixel for the underlying path tracer. Set so rendering noise is less than the optimization signal [S1].
*   LR: Optimizer learning rate (Adam). Varies by task (0.125 to 0.800) [S1].

**Steps:**
1.  **Normalize Parameters:** Normalize parameter spaces to $[0, 1]$ where possible (e.g., rotation) [S1].
2.  **Initialize $\sigma$:** Set $\sigma = \sigma_0$.
3.  **Annealing Schedule:** If optimization iteration $t > 0.5 \times \text{Total Iterations}$, decay $\sigma$ linearly: $\sigma_{t+1} = \sigma_0 - t(\sigma_0 - \sigma_m)$ [S1].
4.  **Sample Offsets:** For $i$ from 1 to $N/2$:
    a. Generate $\xi \sim U(0, 1)$.
    b. Compute $\tau = \sqrt{-2\sigma^2 \log(\xi)}$ [S1].
    c. Generate antithetic pair $\pm \tau$ [S1].
5.  **Evaluate Rendering:**
    a. Evaluate $P(\theta + \tau)$ and $P(\theta - \tau)$ using the forward path tracer [S1].
6.  **Accumulate Gradient:**
    a. For the non-differentiable case (Eq. 10), the contribution of the pair $\pm \tau$ to the gradient sum is proportional to $P(\theta + \tau) - P(\theta - \tau)$ [S1].
    b. Specifically, Algorithm 1 in [S1] shows: $G \leftarrow G + P(\theta + \tau) - P(\theta - \tau)$.
    c. Return $G / N$ [S1].
    *Note:* The source Algorithm 1 implicitly handles the kernel gradient weighting through the antithetic difference and the sampling distribution. The sampling $\tau \sim |\frac{\partial \kappa}{\partial \theta}|$ ensures the estimator is unbiased for Eq. 10 [S1].

**Pseudocode:**
```python
import math
import random

def estimate_gradient_non_diff(P, theta, sigma, N):
    """
    Estimates the gradient of the plateau-reduced objective for a non-differentiable renderer P.
    Uses importance sampling of the kernel gradient and antithetic sampling.
    
    Args:
        P: Function evaluating the renderer P(theta).
        theta: Current scene parameters.
        sigma: Current standard deviation of the blur kernel.
        N: Total number of samples (must be even).
        
    Returns:
        Gradient estimate.
    """
    G = 0.0
    # Loop N/2 times to generate N samples via antithetic pairs
    for _ in range(N // 2):
        # 1. Sample tau proportional to |d_kappa/d_theta|
        # Inverse CDF of positivized gradient of Gaussian
        xi = random.uniform(0, 1)
        tau = math.sqrt(-2 * sigma**2 * math.log(xi))
        
        # 2. Antithetic sampling: use +tau and -tau
        # 3. Evaluate renderer at perturbed parameters
        # Note: P is assumed to handle the parameter shift.
        # The source Algorithm 1 computes the difference directly.
        val_plus = P(theta + tau)
        val_minus = P(theta - tau)
        
        # 4. Accumulate
        # The source algorithm returns G/N. 
        # The weighting by the kernel gradient PDF is handled by the sampling distribution.
        G += val_plus - val_minus
        
    return G / N

def anneal_sigma(t, total_iterations, sigma_0, sigma_m):
    """
    Linearly decays sigma after 50% of iterations.
    """
    if t > total_iterations / 2:
        # Linear schedule from sigma_0 to sigma_m over the second half
        # t is current iteration index (0-based or 1-based, assuming 1-based for formula match)
        # Formula: sigma_{t+1} = sigma_0 - t(sigma_0 - sigma_m)
        # This formula in source seems to define the value at step t+1 based on t.
        # Let's implement the schedule described: decay from sigma_0 to sigma_m during second half.
        progress = (t - total_iterations / 2) / (total_iterations / 2)
        return sigma_0 - progress * (sigma_0 - sigma_m)
    else:
        return sigma_0
```

**Edge Cases and Pitfalls:**
*   **Small $\sigma_0$:** If $\sigma_0 < 0.2$, optimization fails to converge. As $\sigma_0 \to 0$, the method approaches rigid optimization, and the loss landscape is not smoothed, causing stagnation [S1].
*   **Large $\sigma_0$:** If $\sigma_0 \to 1$, perturbation samples may fall outside the view frustum. With $N=2$, this leads to noisy gradients and divergence. Alleviated by enlarging the camera FOV (e.g., 40° to 60°) [S1].
*   **High Dimensions:** Variance increases with parameter dimensionality, mitigated by increasing $N$ [S1].

## Subtopics

### Reparameterized Volume Sampling
Uses a differentiable transformation to map static domains to parameter-dependent ones, eliminating boundary terms. Chosen when explicit differentiable transformations are available. [Reparameterized Volume Sampling](3309-reparameterized-volume-sampling.md)

### Boundary Path Integral Formulation
Handles discontinuities by explicitly computing boundary terms in the gradient. Chosen when adjoint methods or boundary integrals are preferred over stochastic smoothing. [Boundary Path Integral Formulation](3389-boundary-path-integral-formulation.md)

### Reparameterized Monte Carlo Volume Rendering
Applies reparameterization specifically to volume rendering integrals. Chosen for volumetric scenes where density or geometry parameters are optimized. [Reparameterized Monte Carlo Volume Rendering](4798-reparameterized-monte-carlo-volume-rendering.md)

## Operating characteristics
*   **Time Complexity:** Runtime scales linearly with $N$ [S1]. The bulk of time is spent evaluating $f$ (rendering). At $N \approx 16$, runtime equals the baseline of differentiable path tracers (which use complex gradient tracking for 1 sample) [S1].
*   **Memory Complexity:** Low, as it does not require storing a gradient tape or compute graph [S1].
*   **Performance:** On average 8x faster than differentiable rendering with Mitsuba (Our∂κP) [S1]. Convergence improves with $N$ up to ~10, then stagnates [S1].
*   **Strengths:** Works with black-box renderers; no gradient tape required; handles discontinuities via smoothing; compatible with standard path tracers [S1].
*   **Limitations:** Requires tuning of $\sigma$; variance increases with dimensionality; sensitive to $\sigma_0$ choice [S1].
*   **When to use:** Inverse rendering tasks with plateaus (e.g., caustics, global illumination) where differentiable renderers fail or are too slow.
*   **When not to use:** When the renderer is already smooth and differentiable, or when $N$ must be very large for high-dimensional problems.

## Background
PR-DPT was proposed by Fischer et al. in 2023 [S1]. It addresses the issue of optimization plateaus in inverse rendering, where standard differentiable renderers fail to converge due to zero-gradient regions caused by visibility changes [S1]. The method connects variational optimization with inverse rendering by interpreting the convolution as a smoothing operation [S1]. It has been tested on tasks including light source optimization, shadow optimization, and geometry optimization [S1].
