# Plateau-Reduced Differentiable Path Tracing

Also called: PR-DPT, Differentiable Path Tracing with Derivative-Kernel (Our∂κP), Convolutional Gradient Estimation, Our∂κP

## Overview
Plateau-Reduced Differentiable Path Tracing (PR-DPT) is an inverse rendering technique that alleviates optimization plateaus (regions of zero gradient) by convolving the rendering equation with a smoothing kernel over the parameter space [S1]. Unlike standard differentiable path tracers that suffer from discontinuous gradients due to visibility changes, PR-DPT ensures that scene parameters continuously influence the objective function in expectation, allowing gradient-based optimizers to converge on problems with intricate light transport like caustics [S1]. It sets itself apart from siblings like [Reparameterization Estimators](6499-reparameterization-estimators.md) by avoiding the need for a gradient tape, adjoint formulation, or special integrators for visibility discontinuities; instead, it relies on stochastic sampling of a blurred parameter space [S1].

## How it works
**Inputs:**
*   Scene function $f(x, \theta)$: A forward renderer (path tracer) mapping light paths $x \in \Omega$ and scene parameters $\theta \in \Theta$ to pixel values.
*   Current parameters $\theta$.
*   Kernel standard deviation $\sigma$.
*   Number of perturbation samples $N$ (even integer).

**Outputs:**
*   Gradient estimate $\hat{\nabla}_\theta Q$.

**Data Structures:**
*   $\theta$: Parameter vector, normalized to $[0, 1]$ where possible (e.g., rotations) [S1].
*   $\tau$: Parameter offset vector, sampled from the kernel distribution.

**Method:**
The method estimates the gradient of the plateau-reduced rendering equation $Q(\theta)$, defined as the convolution of the original rendering equation $P(\theta)$ with a symmetric, monotonous decreasing kernel $\kappa(\tau)$ [S1]:

$$
Q(\theta) = \int_{\Theta} \int_{\Omega} \kappa(\tau) f(x, \theta - \tau) \, dx \, d\tau
$$

The Monte Carlo estimator for $Q(\theta)$ is:

$$
\hat{Q} \approx \frac{1}{N} \sum_{i=1}^{N} \kappa(\tau_i) f(x_i, \theta - \tau_i)
$$

To compute the gradient $\frac{\partial Q}{\partial \theta}$, PR-DPT offers two paths depending on renderer differentiability. This article details the **non-differentiable case** (Eq. 10 in [S1]), which is preferred for efficiency as it skips the renderer's internal gradient computation [S1]. The gradient is estimated by sampling the derivative of the kernel:

$$
\frac{\partial Q}{\partial \theta} \approx \frac{1}{N} \sum_{i=1}^{N} \frac{\partial \kappa}{\partial \theta}(\tau_i) f(x_i, \theta - \tau_i)
$$

For a Gaussian kernel $\kappa(\tau) = \frac{1}{\sigma\sqrt{2\pi}} \exp\left(-\frac{\tau^2}{2\sigma^2}\right)$, the derivative with respect to $\theta$ (where $\tau$ represents the offset $\theta_{sample} - \theta$) is:

$$
\frac{\partial \kappa}{\partial \theta}(\tau) = \sqrt{\frac{2}{\sigma^2 \pi}} \frac{-\tau}{\sigma^2} \exp\left(\frac{-\tau^2}{2\sigma^2}\right)
$$

Note that $\frac{\partial \kappa}{\partial \theta}$ is negative for $\tau > 0$. To perform importance sampling, the method uses "positivization" by sampling proportional to the absolute value $|\frac{\partial \kappa}{\partial \theta}(\tau)|$ [S1].

**Sampling Procedure:**
1.  **Positivization:** The PDF for sampling is proportional to $|\frac{\partial \kappa}{\partial \theta}(\tau)|$.
2.  **CDF Inversion:** The Cumulative Distribution Function (CDF) for this PDF is:
    $$
    F(\tau) = 0.5 \, \text{sgn}(\tau) \exp\left(\frac{-\tau^2}{2\sigma^2}\right) + C
    $$
    where $C=1$ for $\tau > 0$ and $C=0$ otherwise [S1].
3.  **Sample Generation:** Inverting the CDF yields the sample generation formula:
    $$
    \tau = \sqrt{-2\sigma^2 \log(\xi)}
    $$
    where $\xi \sim U(0,1)$ [S1].
4.  **Antithetic Sampling:** To achieve a zero-variance estimator for the point-symmetric function, for every generated $\tau$, the algorithm also uses $-\tau$ [S1].

**Algorithm:**
The following pseudocode implements the gradient estimation for the non-differentiable case using antithetic sampling and importance sampling derived from the kernel gradient [S1].

```python
import math
import random

def estimate_gradient(P, theta, sigma, N):
    """
    Estimates the gradient of the plateau-reduced rendering equation
    using the derivative-kernel method (Eq. 10 in [S1]).
    
    Args:
        P: Forward renderer function f(x, theta).
        theta: Current scene parameters.
        sigma: Standard deviation of the blur kernel.
        N: Total number of perturbation samples (must be even).
        
    Returns:
        Gradient estimate G.
    """
    G = 0.0
    # Loop runs for N/2 iterations to generate N samples via antithetic pairs
    for i in range(N // 2):
        # 1. Generate uniform random number
        xi = random.uniform(0, 1)
        
        # 2. Sample tau proportional to |d_kappa/d_theta| using inverse CDF
        # Formula: tau = sqrt(-2 * sigma^2 * log(xi))
        tau = math.sqrt(-2 * (sigma ** 2) * math.log(xi))
        
        # 3. Evaluate renderer at perturbed parameters
        # Note: P returns the scalar pixel value (or integrated radiance)
        val_plus = P(theta + tau)
        val_minus = P(theta - tau)
        
        # 4. Accumulate difference
        # The term P(theta + tau) - P(theta - tau) effectively handles the 
        # weighting by the signed kernel gradient and the positivization.
        # See Eq. 10 and Algorithm 1 in [S1].
        G = G + (val_plus - val_minus)
        
    # 5. Normalize by N
    return G / N
```

**Parameters:**
*   $\sigma$: Standard deviation of the blur kernel. Controls the spread of perturbations.
    *   $\sigma_0$: Initial value. Recommended to be roughly 50% of the parameter domain range [S1]. Typical default: 0.5 [S1].
    *   $\sigma_m$: Minimum value. Set to 0.01 to avoid numerical instabilities [S1].
*   $N$: Number of perturbations (samples) per optimization iteration.
    *   Typical values: 2, 4, 8, 16, 32 [S1].
    *   $N=2$ (one sample + antithesis) is often sufficient for convergence [S1].
*   $spp$: Samples per pixel for the underlying path tracer. Not a hyperparameter of PR-DPT but must be set high enough so rendering noise is less than the optimization signal [S1].
*   LR: Optimizer learning rate (e.g., Adam). Values vary by task (0.125 to 0.800) [S1].

**Annealing Schedule:**
The bandwidth $\sigma$ is decayed linearly to refine the solution:
$$
\sigma_{t+1} = \sigma_0 - t(\sigma_0 - \sigma_m)
$$
The schedule is warm-started after approximately 50% of the total optimization iterations have completed [S1].

**Edge Cases and Pitfalls:**
*   **Small $\sigma_0$ ($< 0.2$):** Optimization fails to converge. As $\sigma_0 \to 0$, the method approaches rigid optimization, and the loss landscape is not smoothed, causing stagnation [S1].
*   **Large $\sigma_0$ ($\to 1$):** Perturbation samples may fall outside the view frustum. With small $N$, this produces noisy gradients causing divergence. Alleviated by enlarging the camera FOV (e.g., 40° to 60°) [S1].
*   **High Dimensions:** Variance increases with parameter dimensionality. Mitigated by increasing $N$ [S1].

## Operating characteristics
*   **Time Complexity:** Runtime scales linearly with $N$ [S1]. The bulk of time is spent evaluating the forward renderer $f$; sampling and gradient computation overhead is negligible [S1].
*   **Memory Complexity:** Low. Does not require storing a gradient tape or compute graph [S1].
*   **Performance:** On average 8× faster than differentiable rendering with Mitsuba [S1]. At $N \approx 16$, runtime equals Mitsuba's constant baseline (which uses re-parametrization/adjoint methods for 1 sample) [S1].
*   **Convergence:** Convergence improves with $N$ up to $\sim 10$, then stagnates. Final parameter MSE decreases slightly with higher $N$ ($9.5 \times 10^{-5}$ for $N=2$ vs $4.7 \times 10^{-6}$ for $N=16$), but $N>2$ yields no net benefit for tested tasks due to offsetting runtime [S1].
*   **Accuracy:** Achieves parameter-space MSE errors as low as $10^{-7}$ on tested tasks [S1].
*   **Strengths:** Works with black-box/non-differentiable renderers; handles complex light transport (caustics, GI) where standard differentiable tracers fail; no gradient tape required [S1].
*   **Limitations:** Variance increases in high-dimensional spaces; requires careful tuning of $\sigma_0$ [S1].

## Background
PR-DPT was introduced by Fischer et al. in 2023 [S1]. It addresses the issue of optimization plateaus in inverse rendering, where standard differentiable renderers fail to converge due to zero gradients in regions where scene parameter changes do not immediately affect the image (e.g., occlusion) [S1]. The method connects variational optimization approaches with inverse rendering, interpreting the stochastic sampling as a Monte Carlo estimate of the gradient of a smoothed objective [S1].
