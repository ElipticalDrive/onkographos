# Grid-based Implementation of Cross-Bilateral Filter

Also called: Cross-Bilateral Filter

## Overview
This method implements the spatial filtering of gradients and their associated buffers defined on regular 2D or 3D grids, as described in [À-trous Cross-Bilateral Filtering](13139-trous-cross-bilateral-filtering.md). It solves the performance bottleneck of real-time inverse rendering by replacing standard bilateral filtering with a series of à-trous filters, enabling fast optimization with low sample budgets [S1]. It is distinguished from its parent by its specific grid-based data structures and the iterative bistochastization technique used to normalize the bilateral grid weights [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A bilateral grid $G$ containing splatted values from image pixels and 3D vertices.
*   **Input:** Gradient $\nabla_\theta f_t$ and buffers $m_t, v_t$ defined on regular 2D or 3D grids.
*   **Output:** Filtered gradients and buffers suitable for inverse rendering optimization.

**Data Structures:**
The bilateral grid is represented as a tensor where values are splatted from image space to grid space. The grid supports operations for blurring (convolution with a kernel) and splatting (accumulation from source points).

**Algorithm Steps:**
1.  **Initialization:** Initialize the vertex weights $n$ as a vector of ones with size equal to the number of grid vertices: $n = \mathbf{1}_{N_v}$ [S2, unofficial]. Initialize the pixel weights $m$ by splatting a vector of ones from the image pixels to the grid: $m = \text{grid.splat}(\mathbf{1}_{N_p})$ [S2, unofficial].
2.  **Iteration:** Repeat for a fixed number of iterations (e.g., `maxiter`):
    a. Compute the blurred vertex weights: $b = \text{grid.blur}(n)$ [S2, unofficial].
    b. Update $n$ using the geometric mean of the current $n$ and the ratio of pixel weights to blurred vertex weights:
       $$n_{new} = \sqrt{n \odot \frac{m}{b + \epsilon}}$$
       where $\odot$ is element-wise multiplication and $\epsilon = 10^{-10}$ prevents division by zero [S2, unofficial].
    c. Update $m$ to maintain consistency:
       $$m_{new} = n_{new} \odot \text{grid.blur}(n_{new})$$
3.  **Matrix Construction:** Construct diagonal matrices $D_n$ and $D_m$ from the final $n$ and $m$ vectors:
    $$D_n = \text{diag}(n), \quad D_m = \text{diag}(m)$$
    These matrices are used to bistochastize the bilateral grid, ensuring row and column sums are equal [S2, unofficial].
4.  **Filtering:** Apply the sequence of à-trous cross-bilateral filters to the gradients $\nabla_\theta f_t$ and buffers $m_t, v_t$ using the normalized grid weights [S1].

**Parameters:**
*   `maxiter`: Number of bistochastization iterations. Not given in the sources.
*   $\epsilon$: Regularization constant for numerical stability. Value: $10^{-10}$ [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Division by Zero:** The term $b + \epsilon$ in the update step prevents division by zero when blurred weights are zero [S2, unofficial].
*   **Grid Boundaries:** The implementation assumes regular grids where boundary conditions for `grid.blur` and `grid.splat` are handled consistently [S1].

## Subtopics

### Bistochastization of Bilateral Grid
A technique to normalize the bilateral grid by computing diagonal matrices $D_n$ and $D_m$ such that row and column sums are equal [S2, unofficial]. It is chosen when the bilateral grid requires normalization for stable optimization in inverse rendering [S2, unofficial]. It differs from standard bilateral filtering by explicitly balancing the influence of pixels and vertices through iterative weight adjustment [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and vertices per iteration of bistochastization, plus the cost of the à-trous filtering sequence [S1][S2, unofficial].
*   **Memory Complexity:** Proportional to the size of the bilateral grid and the input buffers [S1][S2, unofficial].
*   **Performance:** Enables real-time performance for inverse rendering tasks [S1].
*   **Strengths:** Fast optimization convergence with low sample budgets [S1].
*   **Limitations:** Requires careful tuning of bistochastization iterations [S2, unofficial].

## Background
The method originates from the need for fast spatial filtering in inverse rendering, leveraging previous work in real-time denoising [Dammertz et al. 2010] as cited in [S1]. The bistochastization technique is associated with the NerfingMVS project [S2, unofficial].
