# Dual Number Automatic Differentiation for Scalar Fields

Also called: Exact Normals via Forward Automatic Differentiation, Forward-mode AD via dual numbers, dual_object gradient computation

## Overview
This method computes the exact gradient of a scalar field $f: \mathbb{R}^3 \to \mathbb{R}$ at a point by evaluating the field on dual numbers that automatically propagate derivative information alongside the primal value [S1, S2, unofficial]. It is primarily used to compute exact vertex normals for implicit surfaces, avoiding the numerical instability and approximation errors inherent in finite difference methods [S2, unofficial].

## How it works
### Inputs and Outputs
- **Input**: A point $p = (x, y, z)$ in 3D space and a scalar field function $f(x, y, z)$ [S1, S2, unofficial].
- **Output**: The normalized gradient vector $\mathbf{n} = (n_x, n_y, n_z)$ representing the surface normal at $p$ [S2, unofficial].

### Data Structures
The implementation uses a templated dual number type, typically `autodiff::Real<1, T>` or a custom `dual_object` [S1, S2, unofficial]. A base class `object<Scalar>` declares pure virtual `value_grad()` returning the dual type and `value()` returning the scalar type [S1, unofficial]. Derived classes override these methods and use the Curiously Recurring Template Pattern (CRTP) via a `derived()` method to enable static polymorphism [S1, unofficial].

### Steps
1. Extract the floating-point coordinates $x, y, z$ from the input point $p$ [S2, unofficial].
2. Construct three dual numbers representing coordinate perturbations: $dx = \text{dual}(x, (1, 0, 0))$, $dy = \text{dual}(y, (0, 1, 0))$, $dz = \text{dual}(z, (0, 0, 1))$ [S1, unofficial].
3. Pack the dual numbers into a dual vector and pass them to the scalar field evaluation function [S1, unofficial].
4. Compute derivatives along each axis using the automatic differentiation API: $n_x = \text{derivative}(f, \text{wrt}(x), \text{at}(x, y, z))$, $n_y = \text{derivative}(f, \text{wrt}(y), \text{at}(x, y, z))$, $n_z = \text{derivative}(f, \text{wrt}(z), \text{at}(x, y, z))$ [S2, unofficial].
5. Normalize the gradient: compute reciprocal norm $nn = 1 / \sqrt{n_x^2 + n_y^2 + n_z^2}$ and return $(n_x \cdot nn, n_y \cdot nn, n_z \cdot nn)$ [S2, unofficial].

### Pseudocode
The following Python-like pseudocode implements the core logic [S2, unofficial]. It defines a self-contained `Dual` class with overloaded arithmetic operators and implements the `derivative` helper exactly as specified in the evidence [G].

```python
class Dual:
    def __init__(self, value, grad):
        self.value = value
        self.grad = grad
    def __add__(self, o): return Dual(self.value + o.value, tuple(a + b for a, b in zip(self.grad, o.grad)))
    def __mul__(self, o): return Dual(self.value * o.value, tuple(a * o.value + o.value * b for a, b in zip(self.grad, o.grad)))
    def __truediv__(self, o): return Dual(self.value / o.value, tuple((a * o.value - self.value * b) / (o.value ** 2) for a, b in zip(self.grad, o.grad)))
    def __pow__(self, n): return Dual(self.value ** n, tuple(n * (self.value ** (n - 1)) * b for b in self.grad))

def wrt(axis):
    return axis

def at(x, y, z):
    return (x, y, z)

def derivative(f, axis, coords):
    x, y, z = coords
    if axis == 0:
        dx = Dual(x, (1.0, 0.0, 0.0))
        dy = Dual(y, (0.0, 0.0, 0.0))
        dz = Dual(z, (0.0, 0.0, 0.0))
    elif axis == 1:
        dx = Dual(x, (0.0, 0.0, 0.0))
        dy = Dual(y, (0.0, 1.0, 0.0))
        dz = Dual(z, (0.0, 0.0, 0.0))
    elif axis == 2:
        dx = Dual(x, (0.0, 0.0, 0.0))
        dy = Dual(y, (0.0, 0.0, 0.0))
        dz = Dual(z, (0.0, 0.0, 1.0))
    result = f(dx, dy, dz)
    return result.grad[axis]

def compute_normal(p, f):
    x, y, z = p
    nx = derivative(f, wrt(0), at(x, y, z))
    ny = derivative(f, wrt(1), at(x, y, z))
    nz = derivative(f, wrt(2), at(x, y, z))
    norm_sq = nx * nx + ny * ny + nz * nz
    if norm_sq == 0.0:
        return (0.0, 0.0, 0.0)
    inv_norm = 1.0 / (norm_sq ** 0.5)
    return (nx * inv_norm, ny * inv_norm, nz * inv_norm)
```

### Parameters
- **Vertex Property Registration**: In some implementations, the normal computation is registered as a vertex property using metadata such as `VertexProperty("normal", fname="compute_normal", dtype="T", shape=("dim",))` [S2, unofficial].
- **Type Parameter**: The scalar type `T` (e.g., `float`, `double`) determines the precision of the primal and dual values [S2, unofficial].

### Edge Cases and Pitfalls
- **Stationary Points**: If the gradient magnitude is zero (e.g., at a local extremum or saddle point), normalization fails; a guard returns a zero vector or a default normal [G].
- **Function Differentiability**: The scalar field function $f$ must be differentiable everywhere in the domain of interest [G].

## Subtopics

### Exact Normals via Forward Automatic Differentiation
Focuses on the application of this method specifically for computing surface normals for implicit geometry, highlighting its advantage over finite differences in avoiding aliasing and approximation errors [S2, unofficial].

### Forward-mode Automatic Differentiation
The broader category of AD techniques that compute derivatives by propagating tangent vectors forward through the computation graph, suitable for functions with many inputs and few outputs [Forward-mode Automatic Differentiation](853-forward-mode-automatic-differentiation.md).

## Operating characteristics
- **Time Complexity**: Not given in the sources [S1, S2, unofficial].
- **Memory Complexity**: Not given in the sources [S1, S2, unofficial].
- **Strengths**: Computes exact analytical gradients, avoiding the truncation and round-off errors of finite differences [S2, unofficial].
- **Limitations**: Requires the scalar field function to be implemented with dual number support (operator overloading) [S2, unofficial].
- **When to Use**: When exact normals are required for implicit surfaces and the field is differentiable [S2, unofficial].
- **When Not to Use**: When the field involves non-differentiable operations that cannot be adapted to dual number arithmetic [G].

## Background
The method originates from forward-mode automatic differentiation for computing exact normals in implicit surface rendering [S1, S2, unofficial]. It is implemented in libraries such as `planaria/dmc` and `keckj/cupmb` to compute vertex normals by evaluating the exact gradient of the scalar field, avoiding finite differences [S2, unofficial].
