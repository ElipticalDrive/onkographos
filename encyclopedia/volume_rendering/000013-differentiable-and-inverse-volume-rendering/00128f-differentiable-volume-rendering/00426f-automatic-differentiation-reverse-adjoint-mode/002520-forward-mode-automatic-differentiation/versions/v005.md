# Forward-Mode Automatic Differentiation

Also called: Forward Differentiation, Forward mode differentiation, Tangent Mode AD, Tape-based Automatic Differentiation, Tracing (Automatic Differentiation), Wengert tape, computation graph

## Overview
Forward-mode automatic differentiation (AD) computes derivatives by recursively applying the chain rule to elementary operations, propagating derivative information from input scene parameters to the output image simultaneously with the forward simulation pass [S1, S2][S6, unofficial]. It solves the problem of computing exact gradients without symbolic manipulation or finite differences by replacing every variable with a tuple of the original value and its derivative with respect to a parameter [S2][S3, unofficial]. Unlike reverse-mode AD, which traverses the graph from output to input, forward-mode traverses from input to output, making it efficient when the input dimension is low and the output dimension is high, but typically less suitable for optimization in high-dimensional scenes because each parameter requires a separate rendering pass or significant memory overhead [S7, S8].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A primal computational graph representing the rendering function $f: \mathbb{R}^n \to \mathbb{R}^m$, where $n$ is the number of input parameters (scene variables, camera parameters, etc.) and $m$ is the number of output variables (pixel colors).
*   **Outputs:** The primal values (rendered image) and the Jacobian-vector products (gradients) of the outputs with respect to the specified input parameters.

**Data Structures:**
The core data structure is the **forward variable** (often called `fvar` or dual number), which wraps a scalar value and its derivative information [S2][S3, unofficial].

1.  **Dual Number / Forward Variable (`fvar`):**
    *   **Layout:** A struct containing:
        *   `value`: The primal scalar value ($T$).
        *   `derivatives`: An array or vector of size $p$ storing the partial derivatives with respect to $p$ input parameters ($T[p]$) [S2][S6, unofficial].
    *   **Bit Packing:** Not specified in the sources. Typically implemented as a standard struct with alignment padding.
    *   **Fields:**
        *   `value`: Stores $x$.
        *   `derivatives[i]`: Stores $\frac{\partial x}{\partial w_i}$ for $i \in \{0, \dots, p-1\}$.

2.  **Computation Graph / Tape (Optional for Tracing-based AD):**
    *   If using a tracing approach (Wengert tape), the graph records the sequence of operations. The trace ignores control flow constructs and stores unrolled versions of all loops and taken branches [S5]. Each edge carries a weight indicating sensitivity [S5].

**Numbered Steps:**

1.  **Initialization:**
    *   Initialize constant variables with zero derivative: $\tilde{x}_{\text{const}} = \langle x_{\text{const}}, 0 \rangle$ [S2].
    *   Initialize parameters of interest with unit derivative: $\tilde{w}_i = \langle w_i, e_i \rangle$, where $e_i$ is a vector with 1 at index $i$ and 0 elsewhere [S1, S2].
    *   If computing derivatives for multiple parameters, extend the `derivatives` array to size $p$ [S2][S6, unofficial].

2.  **Forward Propagation (Primal and Tangent):**
    *   Traverse the computational graph from inputs to outputs [S1].
    *   For each operation $c = f(a, b)$, compute the primal value and the derivative using the chain rule [S2]:
        $$ \tilde{c} = \tilde{f}(\tilde{a}, \tilde{b}) = \left\langle f(a, b), \frac{\partial f}{\partial a} \frac{da}{dw} + \frac{\partial f}{\partial b} \frac{db}{dw} \right\rangle $$
    *   Apply operator overloading for elementary arithmetic operations [S2][S6, unofficial]:
        *   **Addition:** $\tilde{c} = \tilde{a} + \tilde{b}$
            *   $c = a + b$
            *   $\frac{dc}{dw_i} = \frac{da}{dw_i} + \frac{db}{dw_i}$ [S3, unofficial]
        *   **Multiplication:** $\tilde{c} = \tilde{a} \cdot \tilde{b}$
            *   $c = a \cdot b$
            *   $\frac{dc}{dw_i} = a \cdot \frac{db}{dw_i} + b \cdot \frac{da}{dw_i}$ [S3, unofficial]
        *   **Division:** $\tilde{c} = \tilde{a} / \tilde{b}$
            *   $c = a / b$
            *   $\frac{dc}{dw_i} = \frac{b \cdot \frac{da}{dw_i} - a \cdot \frac{db}{dw_i}}{b^2}$ [S3, unofficial]
        *   **Elementary Functions (e.g., $\sin, \cos, \sqrt{}$):**
            *   $\sin(\tilde{a})$: value $= \sin(a)$, grad $= \cos(a) \cdot \frac{da}{dw_i}$ [S3, unofficial]
            *   $\cos(\tilde{a})$: value $= \cos(a)$, grad $= -\sin(a) \cdot \frac{da}{dw_i}$ [S3, unofficial]
            *   $\sqrt{\tilde{a}}$: value $= \sqrt{a}$, grad $= \frac{1}{2\sqrt{a}} \cdot \frac{da}{dw_i}$ [S3, unofficial]
            *   $|\tilde{a}|$: value $= |a|$, grad $= \text{sign}(a) \cdot \frac{da}{dw_i}$ (returns $-\frac{da}{dw_i}$ if $a<0$, else $\frac{da}{dw_i}$) [S3, unofficial]

3.  **Accumulation:**
    *   Derivatives are accumulated forward in time using the chain rule [S4].
    *   If using a tracing-based approach with latent variables, ensure gradients are kept in all variables during traversal to handle dependencies between scene parameters (e.g., using a `ClearEdges` flag) [S8].

4.  **Output Retrieval:**
    *   Extract the `derivatives` component from the output variables (e.g., the rendered image) [S7, S8].

**Pseudocode:**

```python
# Definition of the forward variable structure
class fvar:
    def __init__(self, value, derivatives):
        self.value = value
        self.derivatives = derivatives # List or array of size p

    def __add__(self, other):
        # Addition: c = a + b
        # dc/dw = da/dw + db/dw
        new_value = self.value + other.value
        new_derivs = [self.derivatives[i] + other.derivatives[i] for i in range(len(self.derivatives))]
        return fvar(new_value, new_derivs)

    def __mul__(self, other):
        # Multiplication: c = a * b
        # dc/dw = a * db/dw + b * da/dw
        new_value = self.value * other.value
        new_derivs = [self.value * other.derivatives[i] + other.value * self.derivatives[i] 
                      for i in range(len(self.derivatives))]
        return fvar(new_value, new_derivs)

    def __truediv__(self, other):
        # Division: c = a / b
        # dc/dw = (b * da/dw - a * db/dw) / b^2
        denom = other.value * other.value
        new_value = self.value / other.value
        new_derivs = [(other.value * self.derivatives[i] - self.value * other.derivatives[i]) / denom 
                      for i in range(len(self.derivatives))]
        return fvar(new_value, new_derivs)

    def sin(self):
        # sin(a)
        # d(sin(a))/dw = cos(a) * da/dw
        new_value = sin(self.value)
        new_derivs = [cos(self.value) * self.derivatives[i] for i in range(len(self.derivatives))]
        return fvar(new_value, new_derivs)

# Example usage for a single parameter (p=1)
def compute_forward_mode():
    # 1. Initialize parameters
    # Parameter w with derivative 1 w.r.t itself
    w = fvar(value=2.0, derivatives=[1.0]) 
    
    # Constant c with derivative 0
    c = fvar(value=3.0, derivatives=[0.0])
    
    # 2. Forward propagation
    # Example operation: y = w * c + sin(w)
    temp1 = w * c          # temp1.value = 6.0, temp1.derivatives = [3.0]
    temp2 = w.sin()        # temp2.value = sin(2.0), temp2.derivatives = [cos(2.0)]
    y = temp1 + temp2      # y.value = 6.0 + sin(2.0), y.derivatives = [3.0 + cos(2.0)]
    
    return y

# Example usage for multiple parameters (p=2)
def compute_forward_mode_multi():
    # Parameters w0, w1
    # w0 derivative vector: [1, 0]
    w0 = fvar(value=2.0, derivatives=[1.0, 0.0])
    # w1 derivative vector: [0, 1]
    w1 = fvar(value=3.0, derivatives=[0.0, 1.0])
    
    # Operation: y = w0 * w1
    y = w0 * w1
    # y.value = 6.0
    # y.derivatives[0] = w0.val * w1.deriv[0] + w1.val * w0.deriv[0] = 2*0 + 3*1 = 3
    # y.derivatives[1] = w0.val * w1.deriv[1] + w1.val * w0.deriv[1] = 2*1 + 3*0 = 2
    return y
```

**Parameters:**
*   $p$: The number of parameters to differentiate with respect to. The `derivatives` array size is $p$ [S6, unofficial].
*   Typical values: $p$ is small (e.g., 2 for camera viewpoint) for efficient use; large $p$ (e.g., thousands for Transfer Functions) makes it inefficient [S2][S6, unofficial].

**Edge Cases and Pitfalls:**
*   **High Dimensionality:** Forward differentiation becomes unfeasible for high-dimensional input data (like Transfer Functions or 3D volumetric fields) because the number of parameters $p$ is large, requiring the process to be repeated for each parameter or extending the derivatives array significantly [S2, S4][S6, unofficial].
*   **Latent Variables:** If gradients of latent variables are not propagated to scene parameters before rendering, the loop tracing may destroy the part of the computational graph outside the loop, resulting in incorrect gradients [S8].
*   **Visualization:** Gradient values are not necessarily within $[0, 1]$. Directly displaying them as RGB floats will clip or distort the visualization; use a colormap and clamp the display range [S7, S8].
*   **Control Flow:** Differentiating long-running loops can be challenging in tracing-based implementations due to overheads from repeated tracing and unrolling [S5].

## Subtopics

### [Dual Number Automatic Differentiation for Scalar Fields](5494-dual-number-automatic-differentiation-for-scalar-fields.md)
Computes exact gradients of scalar fields using dual numbers, primarily for computing vertex normals for implicit surfaces. Chosen when exact gradients are needed for geometric primitives, avoiding finite difference errors.

### [Tracing-based Automatic Differentiation with Dynamic Compilation](11558-tracing-based-automatic-differentiation-with-dynamic-compila.md)
Combines tracing (Wengert tape) with dynamic compilation to reduce overhead in dynamic dispatch scenarios. Chosen when runtime performance and compilation time are critical for complex, dynamic rendering code.

## Operating characteristics
*   **Time Complexity:** $O(d)$ times the time complexity of the original algorithm, where $d$ is the number of input variables (parameters) [S1]. Scales linearly with the number of parameters $p$ [S2][S6, unofficial].
*   **Memory Complexity:** $O(np)$, where $n$ is the size of intermediate results (e.g., image dimensions) and $p$ is the number of parameters [S2][S6, unofficial]. Only the current state needs to be stored, unlike reverse mode which may require caching all states [S6, unofficial].
*   **Measured Performance:** Efficient for functions with few input variables (e.g., viewpoint selection with 2 parameters) [S1, S2][S6, unofficial]. Inefficient for functions with thousands or millions of input variables (e.g., volume density fields) [S1, S2][S6, unofficial].
*   **Strengths:** Simpler implementation than source transformation; easier to incorporate into existing code; efficient for low-dimensional inputs; computes derivatives for arbitrary number of outputs in one pass [S1][S6, unofficial].
*   **Limitations:** Unfeasible for high-dimensional inputs; requires separate pass per parameter if $p$ is large; runtime overheads dominate in scalar programs [S2, S4, S5, S7].
*   **When to Use:** When the number of input parameters is small (e.g., camera pose optimization) and the number of outputs is large [S1, S2][S6, unofficial].
*   **When Not to Use:** When the number of input parameters is large (e.g., optimizing a high-resolution Transfer Function or volume density field) [S2, S4][S6, unofficial].

## Background
Forward-mode automatic differentiation was introduced as a method to compute derivatives by replacing variables with tuples of values and derivatives, propagating them right-to-left (top-to-bottom) in the computation graph [S2]. It is historically used in optimal control (linear quadratic regulators, trajectory optimization) and robotics toolboxes [S4]. In the context of differentiable rendering, it is used to visualize the effect of individual scene parameters on the rendered image, such as how changes in a wall's color affect global illumination [S7, S8]. It contrasts with reverse-mode (backpropagation), which is more common in optimization due to its efficiency with high-dimensional inputs [S7, S8].
