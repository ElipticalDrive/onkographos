# Forward-Mode Automatic Differentiation

Also called: Forward Differentiation, Forward mode differentiation, Tangent Mode AD, Tape-based Automatic Differentiation, Tracing (Automatic Differentiation), Wengert tape, computation graph

## Overview
Forward-mode automatic differentiation (AD) computes derivatives by propagating derivative information from input scene parameters to the output image simultaneously with the forward evaluation of the rendering equation [S6, S7]. Unlike reverse-mode AD, which requires storing the entire computational graph and traversing it backward, forward-mode uses dual numbers or operator overloading to compute the derivative of the output with respect to specific input variables as the computation proceeds [S1, S2]. It is primarily distinguished by its efficiency when the number of input parameters is small relative to the output dimension, making it suitable for tasks like viewpoint selection, but generally less suitable for optimizing high-dimensional parameters like transfer functions or volumetric fields due to linear scaling with the number of parameters [S1, S2][S5, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Scene parameters (e.g., camera position, transfer function values, density field values) and the rendering algorithm (e.g., direct volume rendering or path tracing).
*   **Outputs:** The rendered image and the gradient of the image with respect to the specified input parameters.

**Data Structures:**
The core data structure is the **forward variable** (often denoted as $\tilde{a}$ or `fvar`), which wraps a primal value and its derivatives [S2].

1.  **Dual Number / Forward Variable (`fvar`):**
    *   **Layout:** A struct or class containing:
        *   `value`: The primal scalar or vector value (e.g., color, density).
        *   `derivatives`: An array or vector of size $p$, where $p$ is the number of parameters being differentiated. `derivatives[i]` stores $\frac{\partial \text{value}}{\partial w_i}$ [S2][S5, unofficial].
    *   **Bit Packing:** Not specified in the sources. Typically stored as contiguous memory for SIMD efficiency [G].

2.  **Computation Graph / Tape (Optional):**
    *   In tracing-based implementations, a Wengert tape records the sequence of operations. The trace ignores control flow constructs and stores unrolled versions of loops and taken branches [S4].

**Numbered Steps:**

1.  **Initialization:**
    *   Select an AD-compatible backend variant (e.g., `llvm_ad_rgb` in Dr.Jit) [S6, S7].
    *   Identify the parameters to differentiate. For each parameter $w_i$, initialize its forward variable $\tilde{w}_i$ with:
        $$ \tilde{w}_i = \langle w_i, \mathbf{e}_i \rangle $$
        where $\mathbf{e}_i$ is a unit vector with 1 at index $i$ and 0 elsewhere [S1, S2].
    *   Initialize constant variables (e.g., step sizes, fixed geometry) with zero derivatives:
        $$ \tilde{x}_{\text{const}} = \langle x_{\text{const}}, \mathbf{0} \rangle $$ [S2].
    *   If using a latent variable (a parameter that is a function of other differentiable computations), enable gradient tracking on the latent variable first [S6, S7].

2.  **Forward Propagation (Operator Overloading or Tracing):**
    *   Execute the rendering algorithm. Every arithmetic operation $c = f(a, b)$ is replaced by a forward function $\tilde{c} = \tilde{f}(\tilde{a}, \tilde{b})$ [S2].
    *   The forward function computes the primal value $c = f(a, b)$ and the derivative using the chain rule:
        $$ \tilde{c} = \left\langle f(a, b), \frac{\partial f}{\partial a} \frac{da}{dw} + \frac{\partial f}{\partial b} \frac{db}{dw} \right\rangle $$ [S2].
    *   Elementary operations are implemented as follows (where $v$ is value, $g$ is gradient/derivative):
        *   **Addition:** $v = a.v + b.v$; $g = a.g + b.g$ [S3, unofficial].
        *   **Multiplication:** $v = a.v \cdot b.v$; $g = a.v \cdot b.g + b.v \cdot a.g$ [S3, unofficial].
        *   **Division:** $v = a.v / b.v$; $g = (a.g \cdot b.v - a.v \cdot b.g) / b.v^2$ [S3, unofficial].
        *   **Exponential:** $v = \exp(a.v)$; $g = a.g \cdot \exp(a.v)$ [S1].
        *   **Sine:** $v = \sin(a.v)$; $g = a.g \cdot \cos(a.v)$ [S3, unofficial].
        *   **Square Root:** $v = \sqrt{a.v}$; $g = a.g \cdot \frac{1}{2\sqrt{a.v}}$ [S3, unofficial].
    *   If using a tracing approach, the operations are recorded in a tape. The forward sweep traverses the tape in order, computing derivatives scaled by edge weights [S4].

3.  **Handling Latent Variables (if applicable):**
    *   If scene parameters depend on other differentiable computations (latent variables), propagate gradients from the latent variable to the scene parameters before rendering [S6, S7].
    *   Use a flag such as `dr.ADFlag.ClearEdges` to ensure gradient values are kept in all variables during traversal, preventing leaf nodes from having their gradients zeroed out [S7].

4.  **Rendering:**
    *   Render the image using the standard rendering integrator. The forward variables propagate through the blend and loss functions [S2][S5, unofficial].
    *   Example: `image = mi.render(scene, params, spp=128)` [S6].

5.  **Gradient Extraction:**
    *   If using `dr.forward()` directly on a parameter, it assigns a gradient of 1.0 and propagates through the graph [S6].
    *   If using `dr.forward_to(image)`, it finds all possible sources in the AD graph and propagates gradients to the image without overwriting intermediate gradient values [S7].
    *   Fetch the resulting gradient image: `grad_image = dr.grad(image)` [S6].

**Edge Cases and Pitfalls:**
*   **High Dimensionality:** Forward differentiation becomes unfeasible for high-dimensional input data (e.g., 3D volumetric fields, large transfer functions) because the number of parameters $p$ is large, requiring the process to be repeated for each parameter or significantly extending the derivatives array [S2][S5, unofficial].
*   **Long-Running Loops:** Differentiating long-running loops can be challenging in tracing-based implementations due to the overhead of recording and traversing the unrolled trace [S4].
*   **Latent Variable Propagation:** If gradients of latent variables are not propagated to scene parameters before calling the renderer, the loop tracing may destroy parts of the computational graph, resulting in incorrect gradients [S7].
*   **Gradient Visualization:** Gradient values are not necessarily within the $[0, 1]$ range. Directly displaying them as RGB floats will clip or distort the visualization. Use a colormap (e.g., coolwarm) and clamp the display range to $[-v_{lim}, v_{lim}]$ where $v_{lim}$ is the maximum absolute value of the gradient [S6, S7].

## Operating characteristics
*   **Time Complexity:** $O(d)$ times the time complexity of the original algorithm, where $d$ is the number of input variables [S1]. Computational complexity scales linearly with the number of parameters $p$ [S2][S5, unofficial].
*   **Memory Complexity:** $O(np)$, where $n$ is the number of operations/steps or intermediate results (e.g., $W \times H \times 4$ for RGB$\alpha$ images) and $p$ is the number of parameters [S2][S5, unofficial]. Only the current state needs to be stored, unlike reverse-mode which stores the entire graph [S5, unofficial].
*   **Performance:** Efficient for functions with few input variables (e.g., viewpoint selection with 2 parameters) [S1, S2][S5, unofficial]. Inefficient for high-dimensional inputs like transfer functions or volumetric fields [S2][S5, unofficial].
*   **Strengths:** Simpler implementation than source transformation; easier to incorporate into existing code; suitable for visualizing individual parameter effects [S1, S6].
*   **Limitations:** Not suitable for optimization with many parameters; runtime overheads dominate in scalar programs [S4, S6].

## Background
Forward-mode automatic differentiation was introduced as a method to compute derivatives by recursively applying the chain rule to elementary operations [S1]. It is often implemented using dual numbers or operator overloading [S2][S3, unofficial]. The approach is efficient when the input dimension is low and the output dimension is high [S1]. It has been applied in differentiable volume rendering for tasks such as viewpoint selection and visualizing parameter effects [S2, S6].
