# Neural Field Derivatives via Autograd

Also called: Differential Operators (Gradient, Divergence, Laplace), Gradient, Laplace via Autograd, autograd operators, neural field derivatives

## Overview
This method computes spatial differential operators (gradient, divergence, Laplacian) of neural field outputs with respect to their spatial inputs using automatic differentiation (autograd) [S1, unofficial]. It enables supervision on gradient targets in differentiable volume rendering by computing exact derivatives of the model outputs, avoiding the need for finite-difference approximations [S1, unofficial].

## How it works
**Inputs:**
- `x`: Input spatial coordinates, shape `[... , D]` where $D$ is the spatial dimension [G].
- `model`: A differentiable neural network mapping `x` to output `y` [G].
- `y`: Model output, shape `[... , C]` where $C$ is the number of output channels [G].

**Outputs:**
- Gradient, divergence, or Laplacian of `y` with respect to `x` [S1, unofficial].

**Data Structures:**
- Tensors `x` and `y` with standard floating-point precision (e.g., `float32`) [G].
- Computation graph maintained by the autograd engine when `create_graph=True` [S1, unofficial].

**Parameters:**
- `create_graph=True`: Boolean flag passed to the gradient computation function to keep the gradient in the computation graph so that the result is itself differentiable [S1, unofficial].

**Steps:**
1. **Gradient Computation:** Compute the gradient of the output `y` with respect to the input `x` using `torch.autograd.grad` with `grad_outputs=torch.ones_like(y)` and `create_graph=True` [S1, unofficial].
2. **Divergence Computation:** Compute the divergence of `y` with respect to `x` by summing the diagonal of the Jacobian; for each component $i$ of `y`, compute the gradient of `y[..., i]` with respect to `x`, then sum `grad_i[..., i : i + 1]` [S1, unofficial].
3. **Laplacian Computation:** Compute the Laplacian of `y` with respect to `x` as the divergence of the gradient [S1, unofficial].

**Pseudocode:**
```python
import torch

def compute_gradient(model, x, create_graph=True):
    """Compute gradient of model(x) with respect to x."""
    x.requires_grad_(True)
    y = model(x)
    grad = torch.autograd.grad(
        outputs=y,
        inputs=x,
        grad_outputs=torch.ones_like(y),
        create_graph=create_graph,
        retain_graph=create_graph
    )[0]
    return grad

def compute_divergence(model, x, create_graph=True):
    """Compute divergence of model(x) with respect to x. Assumes model(x) has shape [..., D]."""
    x.requires_grad_(True)
    y = model(x)
    D = y.shape[-1]
    div = torch.zeros_like(y[..., 0])
    for i in range(D):
        grad_i = torch.autograd.grad(
            outputs=y[..., i:i+1],
            inputs=x,
            grad_outputs=torch.ones_like(y[..., i:i+1]),
            create_graph=create_graph,
            retain_graph=create_graph
        )[0]
        div = div + grad_i[..., i:i+1]
    return div

def compute_laplacian(model, x, create_graph=True):
    """Compute Laplacian of model(x) with respect to x. Assumes model(x) has shape [..., 1]."""
    grad = compute_gradient(model, x, create_graph=True)
    D = grad.shape[-1]
    lap = torch.zeros_like(grad[..., 0])
    for i in range(D):
        grad_grad_i = torch.autograd.grad(
            outputs=grad[..., i:i+1],
            inputs=x,
            grad_outputs=torch.ones_like(grad[..., i:i+1]),
            create_graph=create_graph,
            retain_graph=create_graph
        )[0]
        lap = lap + grad_grad_i[..., i:i+1]
    return lap
```

**Edge Cases and Pitfalls:**
- Higher-order derivatives (Laplacian) are sensitive to numerical precision [G].
- `create_graph=True` increases memory usage as the gradient computation graph is retained [G].
- Autograd computes derivatives only at the sampled points and does not inherently handle domain boundaries [G].

## Subtopics

### [Implicit Differentiation for Sphere Tracing](2012-implicit-differentiation-for-sphere-tracing.md)
This method computes the gradients of the sphere tracing output with respect to the input parameters of the Signed Distance Function (SDF) model without backpropagating through the iterative sphere tracing loop. It solves the problem of differentiating an iterative fixed-point solver by applying the implicit function theorem, treating the convergence condition as an implicit constraint. It differs from naive backpropagation through the loop by avoiding the accumulation of computational graph overhead from multiple iterations and by handling the non-differentiable convergence mask explicitly.

### SDF Laplacian Estimation
A numerical estimation of the Laplacian $\Delta f$ of an SDF $f$ at a point $p$, using the average value of $f$ over a small sphere centered at $p$ [S2, unofficial]. It is chosen when analytical derivatives are unavailable or when a mesh-free approximation is preferred [G]. It differs from the autograd Laplacian by using finite-difference-like averaging rather than backpropagation [G].
- **Formula:** $\overline{f}(p, h) \approx f(p) - \frac{(\Delta f)(p)}{2n}h^2$ [S2, unofficial].
- **Approximation:** $\overline{f}(p, \epsilon) \approx \frac{1}{4}\sum_{i=0}^3f(p+\epsilon v_i)$ [S2, unofficial].
- **Laplacian Estimate:** $(\Delta f)(p) \approx \frac{6}{\epsilon^2} \left( f(p) - \frac{1}{4}\sum_{i=0}^3f(p+\epsilon v_i) \right)$ [S2, unofficial].
- **Parameters:** $n$ (dimension, e.g., 3 for 3D SDFs), $\epsilon$ (radius of the small sphere), $v_i$ (vectors defining the points on the sphere for averaging) [S2, unofficial].
- **Pitfall:** The sign convention for the Laplacian is positive-definite [S2, unofficial].

## Background
The method leverages automatic differentiation, a core feature of modern deep learning frameworks [G]. It was introduced in the context of differentiable rendering to enable gradient-based optimization of neural implicit representations [S1, unofficial]. The specific application to SDF Laplacian estimation using averaging is documented in ray marching implementations [S2, unofficial].
