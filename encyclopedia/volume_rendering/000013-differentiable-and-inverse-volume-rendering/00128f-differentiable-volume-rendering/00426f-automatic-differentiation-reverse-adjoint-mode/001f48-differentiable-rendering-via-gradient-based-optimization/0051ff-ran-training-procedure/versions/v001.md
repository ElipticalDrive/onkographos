# RAN Training Procedure

Also called: Pix2Vex training, Reconstruction Adversarial Network training

## Overview
The RAN (Reconstruction Adversarial Network) training procedure is an unsupervised method for reconstructing 3D geometry from 2D images by finding an internal representation that minimizes content-wise changes while translating between image spaces [S1, unofficial]. It distinguishes itself from sibling methods like [Single-Scattering Differentiable Volume Rendering](4143-single-scattering-differentiable-volume-rendering.md) by relying on adversarial learning and cycle-consistency across multiple image domains rather than direct physical scattering models.

## How it works
**Inputs and Outputs:**
- **Inputs:** Sets of 2D images (e.g., from synthetic ShapeNet meshes or camera-captured objects) rendered from multiple viewpoints.
- **Outputs:** A reconstructed 3D mesh (internal representation) and associated material/lighting parameters that minimize reconstruction error [S1, unofficial].

**Data Structures:**
- **Mesh:** Defined by vertices and faces. A uniform sphere base model with 162 vertices and 320 faces is used in standard experiments [S1, unofficial].
- **Image Space:** Images are typically 128x128 or 64x64 pixels [S1, unofficial].
- **Network Modules:** Includes image-to-image translators (pix2pix) and a geometry translator (pix2vex) [S1, unofficial].

**Numbered Steps:**
1. **Initialization:** Initialize the network weights. Use Float32 precision. Clamp extreme values for logarithmic and exponential functions to ensure stability [S1, unofficial].
2. **Training Order:** If training multiple modules simultaneously, split the training into two steps to avoid mode collapse:
   - Train the module adjacent to the discriminator first (e.g., $b \to a$).
   - Train the module adjacent to the input second (e.g., $a \to b$) [S1, unofficial].
3. **Loss Calculation:**
   - **Discriminator Loss:** Apply binary cross-entropy loss for the discriminator $D$ [S1, unofficial].
   - **Reconstruction Loss:** Apply L1 loss between any two images belonging to the same image space [S1, unofficial].
4. **Weighting:** Weight the sub-RANs based on relevance. For example, the path containing the pix2vex module carries more weight than the cycle of two image translators [S1, unofficial].
5. **Iteration:** Update weights using gradient descent. Maintain a low learning rate due to competing alternating losses [S1, unofficial].
6. **Duration:** Train for 1–3 weeks on a single GTX Titan Xp [S1, unofficial].

**Pseudocode:**
```python
def train_ran(images_a, images_b, mesh, discriminator, generator_a2b, generator_b2a, generator_pix2vex):
    # Constants
    learning_rate = 0.0002 # Low rate for stability [S1, unofficial]
    batch_size = 1
    precision = "float32"
    
    # Preprocessing: Clamp extreme values for log/exp functions [S1, unofficial]
    images_a = clamp_extreme_values(images_a)
    images_b = clamp_extreme_values(images_b)
    
    for epoch in range(epochs):
        for batch_a, batch_b in zip(images_a, images_b):
            # Step 1: Train discriminator first (or module next to it)
            # Use binary cross-entropy loss [S1, unofficial]
            loss_d = compute_binary_cross_entropy(discriminator, batch_a, batch_b)
            update_weights(discriminator, loss_d)
            
            # Step 2: Train generators
            # Generate fake images
            fake_b = generator_a2b(batch_a)
            fake_a = generator_b2a(batch_a)
            reconstructed_mesh = generator_pix2vex(batch_a)
            
            # Compute L1 loss between images of the same space [S1, unofficial]
            # Cycle consistency: a -> b -> a
            loss_cycle_a = l1_loss(batch_a, generator_b2a(fake_b))
            # Cycle consistency: b -> a -> b
            loss_cycle_b = l1_loss(batch_b, generator_a2b(fake_a))
            
            # Adversarial loss for generators
            loss_adv_a = compute_adversarial_loss(discriminator, fake_a)
            loss_adv_b = compute_adversarial_loss(discriminator, fake_b)
            
            # Weighted combination of losses
            # pix2vex path carries more weight than image translator cycle [S1, unofficial]
            total_loss = (
                weight_pix2vex * compute_geometry_loss(reconstructed_mesh, ground_truth_mesh_if_available) +
                weight_cycle * (loss_cycle_a + loss_cycle_b) +
                weight_adv * (loss_adv_a + loss_adv_b)
            )
            
            update_weights(generator_a2b, total_loss)
            update_weights(generator_b2a, total_loss)
            update_weights(generator_pix2vex, total_loss)
```

**Parameters:**
- **Learning Rate:** Must be kept low. Cannot be significantly increased even with huge batch sizes [S1, unofficial].
- **Precision:** Float32. Float16 causes worse instability. Float64 is numerically beneficial but inefficient on most GPUs [S1, unofficial].
- **Training Duration:** 1–3 weeks on a single GTX Titan Xp [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Dissociating Vertices:** Occurs when processing low-resolution images (64x64) with high mesh resolution (e.g., 642 vertices, 1280 faces), causing sub-pixel faces. Vertices dissociate from the mesh when invisible. This is worse if the smooth visibility test only considers distance to faces instead of directed distance to all edges [S1, unofficial].
- **Silhouette Loss Instability:** Using silhouette losses can drop accuracy because the RAN's internal representation lacks silhouette consistency due to shifts or small scaling factors between images of spaces A and B [S1, unofficial].

## Operating characteristics
- **Time Complexity:** 4 seconds per iteration on a single GTX Titan Xp (batch size 1). 5.2 seconds on two GTX Titan Xp GPUs (batch size 2). 2 minutes per iteration on an i9-7920X CPU @ 2.90GHz with 12 threads [S1, unofficial].
- **Memory Complexity:** ~2GB per image in a batch at 128x128 resolution and 320 faces. Four-view training with batch size 1 requires 6.5GB VRAM [S1, unofficial].
- **Scaling:** Reducing image resolution to 64x64 pixels yields approximately four times faster training and a smaller memory footprint [S1, unofficial].
- **Strengths:** Unsupervised; robust to randomized azimuth, light source position, and class mixing; works on real-world camera-captured images [S1, unofficial].
- **Limitations:** High VRAM usage; slow training time; sensitive to learning rate; prone to vertex dissociation at low resolutions [S1, unofficial].
- **When to Use:** When ground truth 3D models are unavailable and multiple views of an object are accessible [S1, unofficial].
- **When Not to Use:** When real-time performance is required or when silhouette consistency is critical and cannot be handled by the internal representation [S1, unofficial].

## Background
The RAN training procedure was introduced in the paper "Pix2Vex: Image-to-Geometry Reconstruction using a Smooth Differentiable Renderer" [S1, unofficial]. It was developed to reconstruct 3D geometry from 2D data without requiring ground truth 3D models or prior knowledge of materials and lighting conditions [S1, unofficial]. The method leverages a globally differentiable renderer and adversarial learning to align 2D image spaces with 3D geometry [S1, unofficial]. It has been evaluated on synthetic ShapeNet dataset meshes and camera-captured single-view shoe images [S1, unofficial].
