# Autograd Wrapper for Volume Rendering

Also called: Python autograd wrapper for volume rendering, RenderEquation autograd function, torch.autograd.Function wrapper, torch.autograd.Function wrapper for volume rendering

## Overview
The Autograd Wrapper for Volume Rendering is a Python `torch.autograd.Function` implementation that replaces a previous C++-based autograd layer to route between custom C++/CUDA forward and backward operations [S2, unofficial]. It solves the problem of integrating differentiable volume rendering into deep learning pipelines by handling gradient requirements, tensor management, and device placement automatically [S2, unofficial]. It differs from lower-level C++ implementations by providing a high-level Python API that serves as the primary entry point for users [S2, unofficial]. It differs from the Adjoint Method by acting as the plumbing layer that invokes the underlying differentiable kernels rather than deriving analytical gradients itself [S2, unofficial].

## How it works
The method consists of a Python class `_VolumeRenderFn` inheriting from `torch.autograd.Function`, defined in `fvdb/_volume_render.py` [S2, unofficial]. It wraps C++ public API functions `fvdb::volumeRenderForward` and `fvdb::volumeRenderBackward` exposed via `FVDB.h` and bound to Python as `_fvdb_cpp.volume_render_fwd` and `_fvdb_cpp.volume_render_bwd` [S2, unofficial].

**Inputs and Outputs:**
*   **Inputs:** The forward pass accepts tensors for `base_color`, `roughness`, `metallic`, `normals`, `viewdirs`, `incidents_shs`, `direct_shs`, `visibility_shs`, `sample_num`, `is_training`, and `debug` [S1, unofficial].
*   **Outputs:** The forward pass returns `pbr`, `incident_dirs`, and `diffuse_light` [S1, unofficial]. In the general volume rendering context, the forward pass returns `rgb`, `opacity`, `depth`, `ws` (weighted sum), and `total_samples` [S2, unofficial].

**Data Structures:**
*   The Python module `fvdb/_volume_render.py` contains the `_VolumeRenderFn` class [S2, unofficial].
*   The C++ API exposes `fvdb::volumeRenderForward` and `fvdb::volumeRenderBackward` [S2, unofficial].
*   Python bindings in `src/python/Bindings.cpp` map these to `_fvdb_cpp.volume_render_fwd` and `_fvdb_cpp.volume_render_bwd` [S2, unofficial].

**Steps:**
1.  **Check Gradient Requirements:** Determine if gradients are enabled and if at least one differentiable input has `requires_grad=True` [S2, unofficial].
2.  **Dispatch Forward:**
    *   **If gradients are required:** Call `_VolumeRenderFn.apply`, which invokes the CUDA forward pass with `needsBackward=true` and executes the backward kernel [S2, unofficial]. This path saves intermediate variables for the backward pass [S1, unofficial].
    *   **If gradients are not required (Inference Fast Path):** Call `_fvdb_cpp.volume_render_fwd(..., needs_backward=False)` directly [S2, unofficial]. Return size-0 placeholder tensors for `depth`, `ws`, and `total_samples` to maintain tensor shape consistency while saving computation [S2, unofficial].
3.  **Save for Backward:** In the forward method, save `sample_num`, `debug`, and all input tensors except `diffuse_light` to `ctx` for use in the backward pass [S1, unofficial].
4.  **Backward Pass:**
    *   Retrieve saved tensors from `ctx` [S1, unofficial].
    *   Compute gradients via `_C.render_equation_backward` (or the equivalent `_fvdb_cpp.volume_render_bwd`) [S1, unofficial][S2, unofficial].
    *   Handle `None` gradients for outputs by coercing them into zero tensors with matching shape, dtype, and device [S2, unofficial].
    *   Return a tuple of gradients matching the forward inputs, padding with `None` for unused inputs [S1, unofficial].

**Pseudocode:**
```python
import torch
from fvdb import _fvdb_cpp

class _VolumeRenderFn(torch.autograd.Function):
    @staticmethod
    def forward(ctx, base_color, roughness, metallic, normals, viewdirs, 
                incidents_shs, direct_shs, visibility_shs, sample_num, 
                is_training, debug):
        requires_grad = any(x.requires_grad for x in [base_color, roughness, metallic, 
                                                      normals, viewdirs, incidents_shs, 
                                                      direct_shs, visibility_shs])
        
        if requires_grad:
            pbr, incident_dirs, diffuse_light = _fvdb_cpp.volume_render_fwd(
                base_color, roughness, metallic, normals, viewdirs, 
                incidents_shs, direct_shs, visibility_shs, sample_num, 
                is_training, debug, needs_backward=True
            )
            ctx.save_for_backward(base_color, roughness, metallic, normals, viewdirs, 
                                  incidents_shs, direct_shs, visibility_shs)
            ctx.sample_num = sample_num
            ctx.debug = debug
            ctx.is_training = is_training
            return pbr, incident_dirs, diffuse_light
        else:
            pbr, incident_dirs, diffuse_light = _fvdb_cpp.volume_render_fwd(
                base_color, roughness, metallic, normals, viewdirs, 
                incidents_shs, direct_shs, visibility_shs, sample_num, 
                is_training, debug, needs_backward=False
            )
            return pbr, incident_dirs, diffuse_light

    @staticmethod
    def backward(ctx, grad_pbr, grad_incident_dirs, grad_diffuse_light):
        base_color, roughness, metallic, normals, viewdirs, incidents_shs, direct_shs, visibility_shs = ctx.saved_tensors
        
        def coerce_none(grad, tensor):
            if grad is None:
                return torch.zeros_like(tensor)
            return grad

        grad_pbr = coerce_none(grad_pbr, base_color)
        grad_incident_dirs = coerce_none(grad_incident_dirs, base_color)
        grad_diffuse_light = coerce_none(grad_diffuse_light, base_color)
        
        grad_inputs = _fvdb_cpp.volume_render_bwd(
            base_color, roughness, metallic, normals, viewdirs, 
            incidents_shs, direct_shs, visibility_shs, ctx.sample_num, 
            ctx.debug, ctx.is_training, grad_pbr, grad_incident_dirs, grad_diffuse_light
        )
        
        return (grad_inputs[0], grad_inputs[1], grad_inputs[2], grad_inputs[3], grad_inputs[4],
                grad_inputs[5], grad_inputs[6], grad_inputs[7], None, None, None)
```

**Edge Cases and Pitfalls:**
*   **Inference Fast Path:** The inference fast path returns size-0 placeholders for `depth`, `ws`, and `total_samples` [S2, unofficial]. Callers consuming only `rgb` and `opacity` are observationally equivalent, but tests asserting `ws`/`total_samples` must force the backward-aware path [S2, unofficial].
*   **None Gradients:** The backward method must handle `None` gradients for outputs by coercing them into zero tensors with matching shape, dtype, and device [S2, unofficial].

## Subtopics

### [Differentiable Adaptive Stepsize Rendering](2194-differentiable-adaptive-stepsize-rendering.md)
Differentiable Adaptive Stepsize Rendering is a PyTorch `torch.autograd.Function` that computes the forward pass of adaptive stepsize volume rendering and approximates the backward pass using finite differences to enable gradient-based optimization of stepsize maps. It treats the renderer as a black box, trading computational efficiency for implementation simplicity compared to adjoint-based methods that require deriving analytical gradients for the rendering equation.

### [PyTorch Interface](2902-pytorch-interface.md)
The PyTorch Interface provides a high-level Python API for differentiable volume rendering, specifically targeting X-ray computed tomography (CT) forward and back projections. It wraps custom C++/CUDA extensions within a `torch.nn.Module` to enable end-to-end automatic differentiation via PyTorch's autograd engine. It solves the problem of integrating differentiable projection operations into deep learning pipelines without manual gradient implementation, allowing gradients to flow from 2D projection losses back to 3D volume parameters and scanner poses. It differs from lower-level C++ implementations by handling device placement and tensor management automatically, serving as the primary entry point for users.

## Operating characteristics
*   **Time Complexity:** The inference fast path is optimized to skip backward computation, reducing runtime significantly (e.g., from 60.7% to 27.1% of total time in some contexts, though `sample_trilinear` may become the new bottleneck) [S2, unofficial].
*   **Memory Complexity:** The backward-aware path saves intermediate variables, increasing memory usage proportional to the number of inputs and the complexity of the forward pass [S2, unofficial].
*   **Strengths:** Simplifies integration of differentiable volume rendering into PyTorch pipelines; handles gradient requirements automatically; provides an inference fast path for efficiency [S2, unofficial].
*   **Limitations:** Relies on underlying C++/CUDA implementations for the actual gradient computation; the inference fast path may break tests that expect specific output tensor shapes [S2, unofficial].

## Background
The Autograd Wrapper for Volume Rendering was introduced as part of an optimization effort to move the autograd layer from C++ to Python, matching the pattern used for other functional operations like `_gaussian_autograd.py` [S2, unofficial]. This change was made to improve code maintainability and flexibility, allowing for easier routing between forward and backward passes based on gradient requirements [S2, unofficial]. The underlying C++ functions `fvdb::volumeRenderForward` and `fvdb::volumeRenderBackward` are documented with Doxygen comments detailing parameters, shapes, early-termination conditions (`T <= transmittanceThresh`), and channel-count limits (`1 <= C <= MAX_VOLUME_RENDER_CHANNELS`) [S2, unofficial].
