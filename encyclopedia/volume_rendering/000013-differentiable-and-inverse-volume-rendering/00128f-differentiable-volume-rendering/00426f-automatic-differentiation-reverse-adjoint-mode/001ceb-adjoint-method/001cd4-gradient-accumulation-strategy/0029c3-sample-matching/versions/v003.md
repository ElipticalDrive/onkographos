# Sample Matching
## Overview
Sample Matching is a differentiable volume rendering estimator that implements sample matching to reduce variance in gradient estimation for volumetric path tracing [S2, unofficial]. It solves the high-variance gradient problem in differentiable volume rendering by estimating the transmittance and scattering terms of the Differentiable Radiative Transfer Equation (DRTE) at the same spatial points on each path segment, causing their opposite-sign contributions to cancel [S2, unofficial]. Unlike the base `prbvolpath` method which estimates these terms at unrelated points, Sample Matching confines all modifications to the adjoint pass while keeping the primal image rendering identical [S2, unofficial]. It builds on [Gradient Accumulation Strategy](1374-gradient-accumulation-strategy.md) and differs from [Adjoint Beer-Lambert Marching](1905-adjoint-beer-lambert-marching.md) and [Inference Fast Path for Volume Rendering](2192-inference-fast-path-for-volume-rendering.md) by focusing on variance reduction through paired term estimation rather than acceleration or alternative marching schemes.

## How it works
**Inputs and Outputs:**
*   **Input:** Primal path trace data (segments, transmittance, scattering contributions) generated by the base `prbvolpath` integrator [S2, unofficial].
*   **Output:** Gradient estimates for the extinction grid parameters [S2, unofficial].

**Data Structures:**
The method uses a record structure to store segment information during the replay phase [S2, unofficial].
*   `segment_slots`: Integer specifying the capacity of the record buffer per path [S2, unofficial]. Any number of slots is unbiased [S2, unofficial].

**Parameters:**
*   `defer_probes`: Boolean. Enables two-stage adjoint computation where probes run in small dedicated kernels rather than inside the OptiX megakernel [S1, unofficial]. Default is `True` [S1, unofficial].
*   `real_interaction_fused`: Boolean. Enables C++ walk fusing the majorant-supergrid DDA with accept-until-real null tracking [S1, unofficial]. Default is `True` [S1, unofficial].
*   `linear_cost`: Boolean. Switches the estimator from $O(n^2)$ quad cost to $O(n)$ linear cost by using one reservoir-picked suffix per path [S1, unofficial].
*   `segment_reservoir`: Integer. Specifies the number of slots in the striped reservoir (e.g., 4), providing bounded cost and exactness for paths with $\le 4$ segments [S1, unofficial].

**Algorithm Steps:**
The adjoint pass executes as two distinct kernels [S2, unofficial]:

1.  **Path Replay (Record Writing):**
    The path replay loop iterates through the segments of the primal path [S2, unofficial]. For each segment, it writes a record containing the necessary state (position, direction, transmittance, etc.) to a buffer [S2, unofficial]. The number of records written is limited by `segment_slots` [S2, unofficial].
    *   If `segment_slots` is 1, the path keeps a single segment chosen by weighted reservoir sampling [S2, unofficial]. This configuration is registered as `prbvolpath_sm_linear` [S2, unofficial].
    *   If `segment_slots` is `max_depth + 1` (default), all segments are recorded [S2, unofficial]. This configuration is registered as `prbvolpath_sm_quad` [S2, unofficial].

2.  **Gradient Sampling (Ray Tracing):**
    A second kernel reads the records from the buffer [S2, unofficial]. For each record, it traces new rays to compute the gradient samples [S2, unofficial]. This kernel estimates both the transmittance and scattering terms at the same points on each path segment, leveraging the cancellation of opposite-sign terms to reduce variance [S2, unofficial].

**Pseudocode:**
```python
import random as _random

def adjoint_pass(primal_path, segment_slots):
    # Stage 1: Path Replay Loop
    buffer = []
    if segment_slots == 1:
        # Weighted reservoir sampling to keep exactly one segment
        total_weight = 0.0
        for segment in primal_path:
            total_weight += segment.weight
            if _random.random() < segment.weight / total_weight:
                buffer = [segment]
    else:
        # Record segments up to the slot limit
        for i, segment in enumerate(primal_path):
            if i < segment_slots:
                buffer.append(segment)
            else:
                break

    # Stage 2: Gradient Kernel
    gradient = 0.0
    for record in buffer:
        # Traces new rays for gradient samples at the same spatial points
        # Merges transmittance and scattering terms of the DRTE [G]
        gradient += record.transmittance * record.extinction_gradient + record.scattering * record.extinction_gradient
    return gradient
```

**Edge Cases and Pitfalls:**
*   **Polarized Variants:** Not supported, consistent with the base `prbvolpath` [S2, unofficial].
*   **Forward Mode:** Not supported, consistent with the base `prbvolpath` [S2, unofficial].
*   **Spectral Variants:** Supported, including extinction that varies across channels [S2, unofficial].

### prbvolpath_sm_quad
The default configuration with `segment_slots = max_depth + 1` [S2, unofficial]. It uses $O(n^2)$ cost but provides exact gradient estimation for all segments [S1, unofficial]. Choose it for highest accuracy [S2, unofficial].

### prbvolpath_sm_linear
Configured with `linear_cost=True` and `segment_slots=1` [S1, unofficial][S2, unofficial]. It uses $O(n)$ cost by keeping only one reservoir-picked segment per path [S1, unofficial]. Choose it for faster training with acceptable variance trade-off [S2, unofficial].

### prbvolpath_sm_bounded
Configured with `segment_reservoir=K` [S1, unofficial]. It uses a striped reservoir with $K$ slots, providing bounded cost and exactness for paths with $\le K$ segments [S1, unofficial]. Choose it when bounded memory and exactness for short paths are required [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Quad (`prbvolpath_sm_quad`):** $O(n^2)$ cost, where $n$ is the path depth [S1, unofficial]. Memory usage is proportional to `max_depth + 1` records per path [S2, unofficial].
*   **Linear (`prbvolpath_sm_linear`):** $O(n)$ cost [S1, unofficial]. Memory usage is proportional to 1 record per path [S2, unofficial].
*   **Bounded (`prbvolpath_sm_bounded`):** Bounded cost depending on `segment_reservoir` [S1, unofficial].

**Measured Performance:**
*   On a Bunny cloud scene with one NVIDIA A40 GPU over 8000 iterations:
    *   `prbvolpath_sm_quad` achieved 38.35 dB PSNR at 256 spp, compared to 26.66 dB for `prbvolpath` [S2, unofficial].
    *   `prbvolpath_sm_linear` achieved 35.71 dB PSNR at 256 spp [S2, unofficial].
    *   Gradient variance was reduced to 0.25 for `prbvolpath_sm_quad` and 0.29 for `prbvolpath_sm_linear`, compared to 1.0 for `prbvolpath` [S2, unofficial].
    *   Rendering time for `prbvolpath_sm_quad` was 26.3 hours, compared to 41.6 hours for `prbvolpath` [S2, unofficial].
*   Gradients agree with finite differences within 1% in RGB and spectral variants [S2, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Significantly reduces gradient variance by canceling opposite-sign terms [S2, unofficial]. The fused C++ walk with `real_interaction_fused=True` is faster than stock `prbvolpath` because null collisions do not spin the 'fat kernel' [S1, unofficial].
*   **Limitations:** Does not support polarized variants or forward mode differentiation [S2, unofficial].

**When to Use:**
*   Use when differentiating through volume rendering with high variance in extinction gradients is a bottleneck [S1, unofficial].
*   Use `prbvolpath_sm_quad` for highest accuracy [S2, unofficial].
*   Use `prbvolpath_sm_linear` for faster training with acceptable variance trade-off [S2, unofficial].

**When Not to Use:**
*   Do not use if polarized volume rendering is required [S2, unofficial].
*   Do not use if forward mode differentiation is required [S2, unofficial].

## Background
Sample Matching was introduced by Yu et al. in ACM TOG 2026 [S1, unofficial]. It is a port of the original method to Mitsuba 3.9.0 as a built-in AD integrator `prbvolpath_sm` [S1, unofficial]. The method addresses the issue that denser media scatter more light toward the camera but also block more light passing through, creating two terms in the extinction gradient with opposite signs [S2, unofficial]. By estimating both terms at the same points, it reduces the variance of the extinction grid's gradient in optimization [S2, unofficial].
