# Inference Fast Path for Volume Rendering
Also called: NeedsBackward specialization, Stage 2 optimization

## Overview
The Inference Fast Path is a compile-time specialization of the volume rendering kernel that eliminates backward-only output storage and computation when gradients are not required [S1, unofficial]. It differs from the register accumulation stage by removing the largest remaining source of global-memory traffic: the per-sample `outWs` store and the host-side zero-initialization of the $N$-sized buffer [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Volume data, ray origins, ray directions, and a compile-time boolean template parameter `NeedsBackward` [S1, unofficial].
*   **Outputs:**
    *   `outRgb`: Accumulated color (always allocated) [S1, unofficial].
    *   `outWs`: Per-sample weights (allocated only if `NeedsBackward` is true) [S1, unofficial].
    *   `outDepth`: Per-ray depth (allocated only if `NeedsBackward` is true) [S1, unofficial].
    *   `outTotalSamples`: Per-ray total sample count (allocated only if `NeedsBackward` is true) [S1, unofficial].

**Data Structures:**
*   `outRgb`: Tensor of shape `[num_rays, channels]` [S1, unofficial].
*   `outWs`: Tensor of shape `[num_rays, max_samples]` [S1, unofficial].
*   `outDepth`: Tensor of shape `[num_rays]` [S1, unofficial].
*   `outTotalSamples`: Tensor of shape `[num_rays]` [S1, unofficial].
*   When `NeedsBackward` is false, `outWs`, `outDepth`, and `outTotalSamples` are size-0 placeholder tensors with matching dtype and device [S1, unofficial].

**Algorithm:**
1.  **Dispatch:** The host-side dispatcher uses `std::true_type` / `std::false_type` tag-dispatch inside `AT_DISPATCH_V2` to select the kernel specialization based on the `NeedsBackward` template parameter [S1, unofficial].
2.  **Host-Side Allocation:** If `NeedsBackward` is false, allocate size-0 placeholder tensors for `outWs`, `outDepth`, and `outTotalSamples` with matching dtype and device [S1, unofficial]. If `NeedsBackward` is true, allocate `outWs` with zeros because the backward pass's `thrust::inclusive_scan` reads into the early-termination tail, and allocate `outDepth` and `outTotalSamples` [S1, unofficial].
3.  **Kernel Execution:** If `NeedsBackward` is true, the kernel computes and stores per-sample weights to `outWs` and per-ray depth/total samples to `outDepth`/`outTotalSamples` [S1, unofficial]. If `NeedsBackward` is false, the kernel skips the per-sample store to `outWs` and the per-ray stores to `outDepth` and `outTotalSamples` [S1, unofficial].

**Pseudocode:**
```python
def volume_render_forward(volume_data, ray_origins, ray_directions, needs_backward):
    # Allocate color output tensor
    out_rgb = allocate_tensor(shape=[num_rays, channels], dtype=float32, device=current_device)
    
    if needs_backward:
        # Allocate backward-only outputs with zeros for inclusive_scan tail
        out_ws = allocate_zeros_tensor(shape=[num_rays, max_samples], dtype=float32, device=current_device)
        out_depth = allocate_tensor(shape=[num_rays], dtype=float32, device=current_device)
        out_total_samples = allocate_tensor(shape=[num_rays], dtype=int32, device=current_device)
        kernel_needs_backward = True
    else:
        # Allocate size-0 placeholder tensors with matching dtype and device
        out_ws = allocate_tensor(shape=[0], dtype=float32, device=current_device)
        out_depth = allocate_tensor(shape=[0], dtype=float32, device=current_device)
        out_total_samples = allocate_tensor(shape=[0], dtype=int32, device=current_device)
        kernel_needs_backward = False
        
    # Execute kernel specialization via tag dispatch
    execute_kernel(volume_data, ray_origins, ray_directions, out_rgb, out_ws, out_depth, out_total_samples, kernel_needs_backward)
    
    return out_rgb, out_ws, out_depth, out_total_samples

def volume_render_kernel(out_rgb, out_ws, out_depth, out_total_samples, needs_backward):
    for ray_id in range(num_rays):
        # Standard ray marching accumulation into out_rgb[ray_id]
        accumulate_color(out_rgb, ray_id, volume_data, ray_origins[ray_id], ray_directions[ray_id])
        
        if needs_backward:
            # Store per-sample weight for backward pass
            out_ws[ray_id, sample_idx] = current_weight
            # Store per-ray depth and total samples
            out_depth[ray_id] = current_depth
            out_total_samples[ray_id] = current_total_samples
        # When needs_backward is false, these stores are skipped entirely
```

**Parameters:**
*   `NeedsBackward`: Compile-time template parameter (bool) for `volumeRenderFwdCallback`, `volumeRenderCPU`, and `volumeRender` CUDA kernel. When false, the inference fast path is enabled [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Gradient Requirement:** The Python wrapper must route through the CUDA forward with `needsBackward=true` whenever any input requires grad, ensuring saved tensors and backward kernels function correctly [S1, unofficial].
*   **Placeholder Tensors:** Size-0 tensors must have matching dtype and device to avoid runtime errors in subsequent operations that might expect non-empty tensors [S1, unofficial].

## Operating characteristics
*   **Performance:** Further reduced `volume_render` stage time from 6171.4 ms to 2127.0 ms (~2.9x speedup) and end-to-end walltime from 11887.0 ms to 7862.8 ms (~1.86x total speedup vs baseline) in a fire renderer at 256 spp [S1, unofficial].
*   **Memory:** Eliminates the allocation and zero-initialization of the $N$-sized `outWs` buffer and the per-sample stores to `outDepth` and `outTotalSamples` during inference [S1, unofficial].
*   **Strengths:** Significant reduction in global-memory traffic and kernel execution time for inference-only workloads [S1, unofficial].
*   **Limitations:** Only applicable when gradients are not required. Requires careful handling of placeholder tensors in the host code [S1, unofficial].

## Background
This optimization is part of a series of improvements to the `volume_render` stage in the FVDB library [S1, unofficial]. It follows the "Register accumulation" stage (Stage 1) and precedes other optimizations like the "Add Vec2 and double fast paths to SampleGridTrilinear" [S1, unofficial]. The autograd layer was moved to Python (`fvdb/_volume_render.py`) to facilitate this specialization [S1, unofficial].
