# GradBlock with Automatic Differentiation

Also called: AD Tape Surgery, GradBlock

## Overview
GradBlock (also known as AD Tape Surgery) is a technique to attach derivative tracking to specific factors within an expression without recomputing the entire primal value, avoiding unnecessary extra computation in both primal and adjoint programs [S1]. It solves the problem of efficiently differentiating parts of a computation graph that were originally computed with detached or non-differentiable operations, such as GPU texture mapping unit (TMU) lookups or importance sampling strategies [S1]. It sets itself apart from naive substitution methods by combining the primal value of one variable with the AD trace of another, thereby bypassing redundant forward and backward passes [S1].

## How it works
**Inputs and Outputs:**
- Input: Two variables, $a$ (primal value) and $b$ (differential value/trace).
- Output: A new variable that carries the primal value of $a$ but is linked to the AD tape via $b$ [S1].

**Data Structures:**
- The implementation relies on the underlying AD tape structure of the framework [S1]. The function `dr.replace_grad` manipulates the tape to replace the dependency of a node on its original parent with a dependency on $b$, while retaining the computed value of $a$ [S1].

**Steps:**
1. Compute the primal value $a$ and a differentiable counterpart $b$ that holds the same numerical value [S1].
2. Call `dr.replace_grad(a, b)` to combine the primal value of $a$ with the AD trace of $b$ [S1].
3. Use the resulting variable in subsequent computations to enable gradient flow through $b$ without recomputing $a$ [S1].

**Formulas:**
The operation can be conceptually described as:
$$ c = \text{dr.replace\_grad}(a, b) $$
Where:
- $val(c) = val(a)$
- Gradients flow back through the tape associated with $b$ [S1].

In the context of rescaling gradients (e.g., for BSDF values), the sources show usage like:
$$ L_r \leftarrow L_r \times \text{dr.replace\_grad}\left(1, \frac{\text{bsdf\_value\_diff}}{\text{bsdf\_value}}\right) $$
Here, $\text{bsdf\_value}$ and $\text{bsdf\_value\_diff}$ have the same value, but $\text{bsdf\_value\_diff}$ is attached to the AD graph [S1].

**Parameters:**
- $a$: The primal value variable.
- $b$: The variable with the desired AD trace.

**Pitfalls:**
- Naively changing a factor in the expression (e.g., `Lr *= bsdf_value_diff / bsdf_value`) introduces unnecessary extra computation in both primal and adjoint programs [S1].
- Precision issues may arise if $\text{bsdf\_value}$ is near zero when dividing [G].
- The method assumes the framework supports tape manipulation [S1].

**Pseudocode:**
```python
def apply_grad_block_example():
    # Primal value computed once
    bsdf_value = 0.5  # Example primal value
    # Differentiable counterpart with same value
    bsdf_value_diff = bsdf_value.clone().requires_grad_(True)
    
    # Efficient approach: attach AD trace of bsdf_value_diff to primal 1
    # This avoids recomputing bsdf_value in the adjoint pass
    Lr = Lr * replace_grad(1, bsdf_value_diff / bsdf_value)
    
    # Example: GPU texture lookup to differentiable software lookup
    # Standard array lookup simulating hardware TMU behavior
    tex_val = texture_array[tex_coords] 
    # Differentiable software interpolation
    soft_val = software_interpolate(texture_array, tex_coords)
    
    # Combine primal value of tex_val with AD trace of soft_val
    diff_tex_val = replace_grad(tex_val, soft_val)
    
    return diff_tex_val

def replace_grad(a, b):
    # Returns a tensor with the value of a, but gradients flow through b
    # Implementation detail: attaches the AD tape of b to the value of a
    result = a.detach().clone()
    result.requires_grad_(True)
    # In a real AD framework, this manipulates the tape to link result to b
    return result
```

## Subtopics

### [Isolation Boundaries](11535-isolation-boundaries.md)
A mechanism to restrain the process of derivative propagation. Only edges within and just across the isolation boundary may be traversed; others are postponed until the scope is destructed. Used to ensure correct generation of a differential megakernel embedded within a larger differential calculation.

## Operating characteristics
- **Time Complexity:** Avoids recomputing the primal value, thus saving forward pass time [S1].
- **Performance:** Benchmarks show reduced time overhead compared to naive substitution [S1]. For example, in the "Staircase" scene, it contributed to a 0.71× speedup in kernel execution time compared to a baseline [S1].
- **Strengths:** Efficiently enables differentiation of detached operations without redundant computation [S1].
- **Limitations:** Requires framework support for tape manipulation [S1]. Not applicable to operations that cannot be represented in the AD tape [G].
- **Memory Complexity:** Not given in the sources.

## Background
The technique originates from the Dr.Jit paper [S1]. It is used in differentiable rendering to handle cases where importance sampling or texture lookups are not naturally differentiable [S1]. The technique allows for the generation of nonzero derivatives in scenarios like reflected radiance calculations with detached BSDF sampling strategies [S1].
