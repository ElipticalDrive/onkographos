# Scene Parameter Saliency via Differentiable Light Transport

Also called: Gradient-based Saliency, Metric Saliency Maps, gradient-based saliency for differentiable rendering, per-parameter gradients of a scalar objective

## Overview
Metric saliency maps identify which scene parameters most influence a specific scalar image-space metric by computing per-parameter gradients through a differentiable renderer [S1, unofficial]. Unlike neural saliency methods that propagate attribution through learned weights, this method propagates gradients through the physical light transport simulation, capturing multi-bounce dependencies and parameter interactions that are opaque to manual inspection [S1, unofficial]. It serves as an interpretability tool for inverse rendering and scene understanding, providing a local sensitivity characterization at the cost of a single reverse-mode differentiation pass, avoiding the expensive re-renders required by finite-difference sensitivity analysis [S1, unofficial].

## How it works
The method consists of three stages: (1) render an image through a differentiable pipeline, (2) evaluate a scalar metric on that image, and (3) backpropagate through both the metric and the renderer to obtain per-parameter gradients, which are then mapped back to image space for visualization [S1, unofficial].

### Inputs and Outputs
**Inputs:**
*   Scene parameters $\theta$: A vector including surface reflectances, roughness values, indices of refraction, emitter intensities, and geometric quantities [S1, unofficial].
*   Scalar metric $M$: A function evaluating a property of the light transport simulation, defined as $M: \mathbb{R}^D \to \mathbb{R}$, where $I = R(\theta) \in \mathbb{R}^D$ is the rendered image (generalized sensor response) [S1, unofficial].
*   Differentiable renderer $R$: A function computing the image $I$ from $\theta$, such as a physically-based Monte Carlo path tracer with multi-bounce global illumination [S1, unofficial].

**Outputs:**
*   Parameter-space gradient $g$: A vector where each component $g_i = \partial M / \partial \theta_i$ measures the sensitivity of the metric to the corresponding parameter [S1, unofficial].
*   Saliency map: An image-space visualization where pixels are colored by the saliency of the material visible at that location [S1, unofficial].

### Data Structures
*   **Scene Parameters ($\theta$):** Stored as a flat vector or structured object containing differentiable attributes for each material and light source. For spatially-varying parameters (e.g., texture maps), gradients are stored as fields aligned with the surface geometry [S1, unofficial].
*   **Rendered Image ($I$):** A tensor of shape $H \times W \times C$ (height, width, channels) representing the generalized sensor response [S1, unofficial].
*   **Material Identity Map:** A per-pixel map generated by tracing primary rays from the camera, identifying the hit scene object and its associated material parameters [S1, unofficial].

### Formulas
The parameter-space gradient $g$ is computed via the chain rule [S1, unofficial]:

$$
g = \frac{\partial M(R(\theta))}{\partial \theta} = \frac{\partial M}{\partial I} \frac{\partial I}{\partial \theta}
$$

The product is obtained automatically by backpropagation through the metric and the light transport simulation jointly [S1, unofficial].

The saliency of a parameter $\theta_i$ is defined as the magnitude of its gradient component [S1, unofficial]:

$$
\text{Saliency}(\theta_i) = |g_i|, \quad \text{where } g_i = \frac{\partial M}{\partial \theta_i}
$$

For vector-valued parameters (e.g., RGB reflectance), the saliency is the $\ell_2$ norm of the gradient components [S1, unofficial]:

$$
\text{Saliency}(\mathbf{v}) = \left\| \frac{\partial M}{\partial \mathbf{v}} \right\|_2
$$

```python
def compute_metric_saliency(scene_params, metric_function, renderer, camera):
    """
    Computes metric saliency maps for a given scene and metric.
    
    Args:
        scene_params: Differentiable parameters theta (reflectances, roughness, etc.)
        metric_function: Scalar function M(I) evaluating image properties
        renderer: Differentiable renderer R(theta)
        camera: Camera configuration for primary ray tracing
        
    Returns:
        saliency_map: Image-space visualization of parameter saliency
        gradients: Per-parameter gradient values
    """
    # Stage 1: Render image through differentiable pipeline
    # I = R(theta)
    image = renderer(scene_params)
    
    # Stage 2: Evaluate scalar metric on the image
    # M = M(I)
    metric_value = metric_function(image)
    
    # Stage 3: Backpropagate through metric and renderer
    # g = dM/dtheta = (dM/dI) * (dI/dtheta)
    # Automatic differentiation computes this jointly
    gradients = autograd.grad(metric_value, scene_params)
    
    # Compute saliency magnitudes
    # For scalar parameters: |g_i|
    # For vector parameters: ||g_i||_2
    saliency_values = []
    for i, param in enumerate(scene_params):
        grad = gradients[i]
        if param.is_vector:
            saliency = l2_norm(grad)
        else:
            saliency = abs(grad)
        saliency_values.append(saliency)
        
    # Normalize saliency values to [0, 1] for visualization
    max_saliency = max(saliency_values)
    if max_saliency > 0:
        normalized_saliency = [s / max_saliency for s in saliency_values]
    else:
        normalized_saliency = saliency_values
        
    # Map gradients to image space for visualization
    # Trace primary rays to identify visible materials
    material_identity_map = trace_primary_rays(camera, scene_params)
    
    # Color each pixel by the saliency of the visible material
    saliency_map = create_saliency_map(material_identity_map, normalized_saliency)
    
    return saliency_map, gradients
```

### Parameters
*   **Renderer:** Must be differentiable. The implementation uses Mitsuba 3 with Path Replay Backpropagation (PRB) to handle multi-bounce global illumination gradients [S1, unofficial].
*   **Metric $M$:** Can be qualitatively different objectives, including psychovisual glare indices (e.g., Unified Glare Rating), mean scene luminance, and neural perceptual scores (e.g., ResNet-50 logits) [S1, unofficial].
*   **Maximum path depth:** 6 bounces [S1, unofficial].
*   **Samples per pixel (SPP):** 1024 for main results [S1, unofficial].
*   **Learning rate for validation:** 0.01 (used for ablation validation to verify gradient accuracy) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Metric Specificity:** The saliency map is specific to the metric and not an intrinsic property of the scene. Parameters that dominate one objective may be negligible for another [S1, unofficial].
*   **Monte Carlo Variance:** Gradient estimators inherit variance from the path tracer. At low sample counts, saliency values are noisy. Stable rankings require moderate sample counts (64–256 spp); fine-grained spatially-varying fields require higher budgets or variance reduction [S1, unofficial].
*   **Non-differentiable Metrics:** Metrics with hard thresholds or discrete decisions (e.g., binary glare detection) are not differentiable. They must be relaxed into smooth approximations (e.g., sigmoid relaxations for visibility checks), which affects the resulting saliency map [S1, unofficial].
*   **First-Order Limitation:** Gradient magnitude only measures local, first-order sensitivity. It does not capture parameter interactions (second-order effects) or physical constraints (e.g., roughness clamping at 1.0) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method requires a single forward pass for rendering and a single reverse-mode differentiation pass (backpropagation) for gradient computation. This is significantly faster than finite-difference sensitivity analysis, which requires dozens of independent simulation evaluations [S1, unofficial].
*   **Memory Complexity:** Memory usage depends on the differentiable renderer's implementation. PRB-based renderers like Mitsuba 3 manage memory efficiently for multi-bounce paths, but storing intermediate states for reverse-mode AD can be high [S5, G].
*   **Measured Performance:** In experiments with 1024 SPP and 6 bounces, the method successfully isolated and ranked true physical drivers of discomfort glare and mean luminance, validating against finite-difference steps with a learning rate of 0.01 [S1, unofficial].
*   **Strengths:** Provides a local sensitivity characterization at the cost of a single backward pass; captures multi-bounce light transport dependencies; works with any differentiable renderer and metric [S1, unofficial].
*   **Limitations:** Noisy at low sample counts; requires differentiable metrics; does not capture second-order effects or physical constraints; saliency is metric-specific [S1, unofficial].
*   **When to use:** When interpreting which scene parameters drive a specific image-space metric, especially for multi-bounce global illumination scenarios where manual inspection is difficult [S1, unofficial].
*   **When not to use:** When second-order interactions are critical, when metrics are inherently non-differentiable and cannot be relaxed, or when computational resources are too limited for stable Monte Carlo gradient estimation [S1, unofficial].

## Background
The method was introduced by Linas Beresna and Eugene Fiume in "Scene Parameter Saliency via Differentiable Light Transport" [S1, unofficial]. It builds on the principles of differentiable volume rendering and differentiable rendering in general, extending the concept of gradient-based attribution from neural networks to physical light transport simulations [S1, unofficial]. The approach addresses the need for interpretability in inverse rendering and scene understanding, offering an alternative to traditional sensitivity analysis methods like parametric sweeps or finite-difference probing [S1, unofficial]. It is implemented using Mitsuba 3 and DrJit, leveraging Path Replay Backpropagation for efficient gradient computation [S1, unofficial].
