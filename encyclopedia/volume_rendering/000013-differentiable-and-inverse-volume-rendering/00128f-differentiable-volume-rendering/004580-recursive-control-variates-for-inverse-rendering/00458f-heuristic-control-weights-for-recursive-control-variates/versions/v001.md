# Heuristic Control Weights for Recursive Control Variates

Also called: alpha_n heuristics

## Overview
Heuristic Control Weights for Recursive Control Variates is a method for dynamically adjusting the influence of previous control variates in differentiable volume rendering to minimize bias and variance in gradient estimates. It addresses the trade-off between reusing historical rendering information and maintaining statistical independence from the current optimization step. It sets itself apart from static weighting schemes by adapting $\alpha_n$ based on running (co-)variance statistics, though it requires careful ordering of updates to avoid introducing bias.

## How it works
The method computes a control variate estimate $\langle F^n \rangle_{CV}$ using a weight $\alpha_n$ derived from historical data. The core challenge is ensuring that $\alpha_n$ is not correlated with the current rendering noise, which would introduce bias.

**Inputs and Outputs:**
- Input: Current scene parameters, previous control variate estimate $\langle F^{n-1} \rangle_{CV}$, running (co-)variance statistics.
- Output: Updated control variate estimate $\langle F^n \rangle_{CV}$, updated statistics, new weight $\alpha_{n+1}$.

**Data Structures:**
- Running mean $\mu_n$ and variance $\sigma^2_n$ of the control variate estimates.
- Running covariance $\gamma_n$ between consecutive estimates.
- Weight parameter $\alpha_n \in [0, 1]$.

**Numbered Steps:**
1. **Compute Control Variate Estimate:** Calculate $\langle F^n \rangle_{CV}$ using the current weight $\alpha_n$ and the previous control variate $\langle F^{n-1} \rangle_{CV}$. The exact combination formula depends on the specific heuristic for $\alpha_n$, but generally follows the structure of a weighted average or exponential moving average.
2. **Update Statistics:** Update the running (co-)variance statistics using the newly computed $\langle F^n \rangle_{CV}$ and $\langle F^{n-1} \rangle_{CV}$. This step must occur *after* the evaluation of $\langle F^n \rangle_{CV}$ to ensure statistical independence between $\alpha_{n+1}$ and the current rendering noise.
3. **Compute Next Weight:** Calculate $\alpha_{n+1}$ based on the updated statistics.

**Formulas:**
The weight $\alpha_n$ is typically defined to balance the contribution of the current and previous estimates. While the exact definition of $\alpha_n$ is in the parent article, the heuristic update logic is critical. The running statistics are updated as:
$$ \mu_n = \text{update}(\mu_{n-1}, \langle F^n \rangle_{CV}) $$
$$ \sigma^2_n = \text{update}(\sigma^2_{n-1}, \langle F^n \rangle_{CV}) $$
$$ \gamma_n = \text{update}(\gamma_{n-1}, \langle F^{n-1} \rangle_{CV}, \langle F^n \rangle_{CV}) $$
The weight $\alpha_n$ is then derived from these statistics, often involving ratios of covariance to variance.

**Parameters:**
- $\alpha_n$: The control variate weight. Typical values are determined by the optimization trajectory.

**Edge Cases and Pitfalls:**
- Setting $\alpha_n = 1$ causes unbounded variance because the previous control variate is never down-weighted while independent random variation continues to be added [S1].
- Setting $\alpha_n = n/(n+1)$ results in a uniform combination over all prior control variates regardless of how similar each one is to the current scene [S1].
- Updating statistics *before* evaluation correlates the weight with the current image, adding significant bias [S1].

**Pseudocode:**
```python
def update_control_variate(prev_cv, prev_stats, current_rendering):
    # Step 1: Compute control variate estimate using current alpha
    # alpha_n is derived from prev_stats
    alpha_n = compute_alpha(prev_stats)
    current_cv = alpha_n * current_rendering + (1 - alpha_n) * prev_cv
    
    # Step 2: Update statistics AFTER evaluation
    # This ensures alpha_{n+1} is independent of current_rendering noise
    new_stats = update_statistics(prev_stats, prev_cv, current_cv)
    
    return current_cv, new_stats
```

## Subtopics

### Bias Mitigation in Control Variate Weight Update
This variant focuses on the timing of the statistics update. Updating the running (co-)variance estimates *after* evaluating $\langle F^n \rangle_{CV}$ ensures that $\alpha_n$ and $\langle F^{n-1} \rangle_{n-1}$ are statistically independent, removing the bias introduced by correlating the weight with the current image [S1]. A small amount of bias remains because $\alpha_n$ is still correlated with $\langle F^{n-1} \rangle_{CV}$, but this trade-off significantly reduces bias in the loss function gradient [S1].

## Operating characteristics
- **Time Complexity:** Adds overhead for computing and updating statistics, but reduces the number of samples needed for convergence.
- **Memory Complexity:** Requires storing running statistics (mean, variance, covariance).
- **Strengths:** Significantly reduces bias in gradient estimates, leading to higher effective sample counts (e.g., 1024 vs. 16 samples per pixel) at a fraction of the cost [S1].
- **Limitations:** Requires careful implementation to avoid bias from correlated weights. Failure modes include unbounded variance if $\alpha_n$ is not properly bounded [S1].
- **When to Use:** When differentiable volume rendering is used for inverse rendering with iterative optimization, and bias in gradient estimates is a concern.

## Background
Originated in the paper "Recursive Control Variates for Inverse Rendering" by Nicolet et al. (2023) [S1]. The method addresses the issue of bias in control variate estimators when used in iterative optimization schemes for differentiable rendering.
