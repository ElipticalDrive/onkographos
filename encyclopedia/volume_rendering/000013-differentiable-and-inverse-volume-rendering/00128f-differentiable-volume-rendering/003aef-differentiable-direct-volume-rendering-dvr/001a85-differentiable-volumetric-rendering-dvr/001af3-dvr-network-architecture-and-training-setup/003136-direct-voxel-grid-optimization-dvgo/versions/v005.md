# Direct Voxel Grid Optimization (DVGO)

Also called: SimpleDVGO

## Overview
Direct Voxel Grid Optimization (DVGO) is a differentiable volume rendering method that replaces the multi-layer perceptron (MLP) used in NeRF with direct voxel grids for density and color features, enabling significantly faster training and inference [S1, unofficial]. Unlike NeRF-like methods that query a neural network for density from coordinates, DVGO stores density and color directly in 3D grids, allowing for efficient trilinear interpolation and gradient accumulation [S1, unofficial]. It sets itself apart from its sibling [NeRF Model Initialization](1868-nerf-model-initialization.md) by using a dense voxel grid representation rather than a coordinate-based MLP, trading off some representational flexibility for computational speed [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Ray origins $\mathbf{o}$ and directions $\mathbf{d}$, camera parameters (near/far planes), and scene bounding box [S2, unofficial].
- **Outputs:** Rendered RGB color and depth for each ray [S2, unofficial].

**Data Structures:**
1.  **Density Voxel Grid:** A 3D tensor of shape $(N_x, N_y, N_z)$ with 1 channel, storing raw density values [S2, unofficial]. Initialized to a small positive value (e.g., 0.001) [S2, unofficial].
2.  **Color Voxel Grid:** A 3D tensor of shape $(N_x, N_y, N_z)$ with 3 channels (RGB), storing color features [S2, unofficial]. Initialized to a default color (e.g., BLUE) [S2, unofficial].
3.  **Bounding Box Buffers:**
    -   `min`: Tuple of floats $(x_{min}, y_{min}, z_{min})$ defining the scene bounding box minimum corner [S2, unofficial].
    -   `max`: Tuple of floats $(x_{max}, y_{max}, z_{max})$ defining the scene bounding box maximum corner [S2, unofficial].
    -   `shape`: Tuple of ints $(N_x, N_y, N_z)$ defining the grid resolution [S2, unofficial].
4.  **Sampling Buffers:**
    -   `t_values`: 1D tensor of size $K$ (number of samples), containing midpoints between $K+1$ linearly spaced depths from `near` to `far` [S2, unofficial].

**Parameters:**
-   `num_voxels`: Total number of voxels ($N_x \times N_y \times N_z$) [S1, unofficial].
-   `near`: Near plane distance (default 1.5) [S2, unofficial].
-   `far`: Far plane distance (default 3.5) [S2, unofficial].
-   `num_samples`: Number of sample points along each ray (default 64) [S2, unofficial].
-   `min_corner`: Scene bounding box minimum (default $(-1.0, -1.0, 0.0)$) [S2, unofficial].
-   `max_corner`: Scene bounding box maximum (default $(1.0, 1.0, 1.0)$) [S2, unofficial].
-   `shape`: Grid dimensions (default $(128, 128, 128)$) [S2, unofficial].
-   `background`: Background color (default WHITE) [S2, unofficial].
-   `alpha_init`: Initial alpha value for density bias shift calculation (default None) [S1, unofficial].
-   `rgbnet_dim`: Dimension of color feature vector. If $\le 0$, uses coarse stage (3-channel grid) [S1, unofficial]. If $> 0$, uses fine stage (feature grid + MLP) [S1, unofficial].
-   `mask_cache_thres`: Threshold for mask cache occupancy [S1, unofficial].
-   `fast_color_thres`: Threshold for voxel occupancy based on alpha [S1, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    a.  Calculate `act_shift` for density bias: $\text{act\_shift} = \ln\left(\frac{1}{1-\alpha_{init}} - 1\right)$ [S1, unofficial].
    b.  Create `t_values` as midpoints of $K+1$ linearly spaced points between `near` and `far` [S2, unofficial].
    c.  Initialize `min`, `max`, and `shape` buffers [S2, unofficial].
    d.  Initialize `rgb_voxel_grid` with shape `config.shape`, 3 channels, filled with BLUE [S2, unofficial].
    e.  Initialize `density_voxel_grid` with shape `config.shape`, 1 channel, filled with 0.001 [S2, unofficial].
    f.  Register `background` color [S2, unofficial].
    g.  If `rgbnet_dim > 0`, initialize RGB MLP with input dimension $d_0 = (3 + 3 \cdot \text{viewbase\_pe} \cdot 2) + (\text{k0\_dim} \text{ if } \text{rgbnet\_direct} \text{ else } 0) - (3 \text{ if } \neg \text{rgbnet\_full\_implicit} \text{ else } 0)$, depth `rgbnet_depth`, width `rgbnet_width`, ReLU activations, and 3 output neurons with 0 bias [S1, unofficial].
    h.  Initialize mask cache (ones if not loaded) [S1, unofficial].

2.  **Ray Sampling:**
    a.  For each ray, sample points $\mathbf{P}$ at depths $t \in \text{t\_values}$: $\mathbf{P} = \mathbf{o} + t \cdot \mathbf{d}$ [S2, unofficial].
    b.  During training, add jitter: $t' = t + \frac{\text{rand}() - 0.5}{K}$ where $K$ is batch size [S2, unofficial].

3.  **Coordinate Rescaling:**
    a.  Convert scene coordinates $\mathbf{P}$ to grid coordinates $\mathbf{P}_{grid}$:
        $$ \mathbf{P}_{grid} = \text{shape} \cdot \frac{\mathbf{P} - \text{min}}{\text{max} - \text{min}} $$
        [S2, unofficial]

4.  **Grid Query:**
    a.  Query density: $\sigma_{raw} = \text{density\_voxel\_grid}(\mathbf{P}_{grid})$ [S2, unofficial].
    b.  Apply ReLU: $\sigma = \text{ReLU}(\sigma_{raw})$ [S2, unofficial].
    c.  Query color: $\mathbf{c}_{raw} = \text{rgb\_voxel\_grid}(\mathbf{P}_{grid})$ [S2, unofficial].
    d.  Clamp color: $\mathbf{c} = \text{clamp}(\mathbf{c}_{raw}, 0.0, 1.0)$ [S2, unofficial].
    e.  If `rgbnet_dim > 0`, pass $\mathbf{c}_{raw}$ and view direction through RGB MLP to get final $\mathbf{c}$ [S1, unofficial].

5.  **Volume Rendering:**
    a.  Compute transmittance and alpha:
        $$ \alpha_i = 1 - \exp(-\sigma_i \cdot \delta_i) $$
        $$ T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \cdot \delta_j\right) $$
        where $\delta_i$ is the step size along the ray [G].
    b.  Render color:
        $$ C = \sum_{i=1}^{K} T_i \alpha_i \mathbf{c}_i + T_K \cdot \text{background} $$
        [S2, unofficial]

6.  **Regularization and Caching (Optional):**
    a.  Apply total variation regularization to density and color grids [S1, unofficial].
    b.  Update mask cache based on density thresholds [S1, unofficial].
    c.  Mask out voxels near camera if distance < `near` plane [S1, unofficial].

**Pseudocode:**

```python
import numpy as np

def trilinear_interpolate(grid, points):
    """Standard trilinear interpolation for grid of shape (Nx, Ny, Nz, C) and points (N, 3)."""
    # Clamp coordinates to grid bounds
    x = np.clip(points[:, 0], 0, grid.shape[0] - 1.001)
    y = np.clip(points[:, 1], 0, grid.shape[1] - 1.001)
    z = np.clip(points[:, 2], 0, grid.shape[2] - 1.001)
    
    # Floor and ceil indices
    x0, y0, z0 = np.floor([x, y, z]).astype(int)
    x1, y1, z1 = x0 + 1, y0 + 1, z0 + 1
    
    # Interpolation weights
    dx, dy, dz = x - x0, y - y0, z - z0
    w000 = (1-dx)*(1-dy)*(1-dz)
    w100 = dx*(1-dy)*(1-dz)
    w010 = (1-dx)*dy*(1-dz)
    w110 = dx*dy*(1-dz)
    w001 = (1-dx)*(1-dy)*dz
    w101 = dx*(1-dy)*dz
    w011 = (1-dx)*dy*dz
    w111 = dx*dy*dz
    
    # Gather and interpolate
    vals = grid[x0, y0, z0] * w000 + grid[x1, y0, z0] * w100 + \
           grid[x0, y1, z0] * w010 + grid[x1, y1, z0] * w110 + \
           grid[x0, y0, z1] * w001 + grid[x1, y0, z1] * w101 + \
           grid[x0, y1, z1] * w011 + grid[x1, y1, z1] * w111
    return vals

class SimpleDVGO:
    def __init__(self, config):
        self.near = config.near
        self.far = config.far
        self.num_samples = config.num_samples
        self.min = np.array(config.min_corner, dtype=np.float32)
        self.max = np.array(config.max_corner, dtype=np.float32)
        self.shape = np.array(config.shape, dtype=np.float32)
        self.background = np.array(config.background, dtype=np.float32)
        
        # Initialize t_values
        depths = np.linspace(self.near, self.far, self.num_samples + 1)
        self.t_values = 0.5 * (depths[1:] + depths[:-1])
        
        # Initialize voxel grids
        self.density_grid = np.full((*config.shape, 1), 0.001, dtype=np.float32)
        self.rgb_grid = np.zeros((*config.shape, 3), dtype=np.float32)
        self.rgb_grid[..., 2] = 1.0  # BLUE
        
        # Optional: RGB MLP for fine stage
        if config.rgbnet_dim > 0:
            self.rgbnet_dim = config.rgbnet_dim
            self.rgbnet_depth = config.rgbnet_depth
            self.rgbnet_width = config.rgbnet_width
            self.viewbase_pe = config.viewbase_pe
            self.rgbnet_direct = config.rgbnet_direct
            self.rgbnet_full_implicit = config.rgbnet_full_implicit
            # MLP weights initialized elsewhere [G]

    def forward(self, rays, training=True):
        origins = rays[:, :3]
        directions = rays[:, 3:]
        
        t_values = self.t_values
        if training:
            n = t_values.shape[0]
            random_scalar = (np.random.rand(n) - 0.5) / n
            actual_ts = t_values + random_scalar
        else:
            actual_ts = t_values
            
        actual_ts = actual_ts[np.newaxis, :]
        origins = origins[:, np.newaxis, :]
        directions = directions[:, np.newaxis, :]
        
        samples = origins + actual_ts * directions
        
        rescaled = self.shape * (samples - self.min) / (self.max - self.min)
        
        density = trilinear_interpolate(self.density_grid, rescaled)
        density = np.maximum(density, 0.0)  # ReLU
        
        rgb = trilinear_interpolate(self.rgb_grid, rescaled)
        rgb = np.clip(rgb, 0.0, 1.0)
        
        deltas = np.diff(actual_ts, axis=1)
        delta_inf = np.ones_like(deltas[:, :1]) * 1e10
        deltas = np.concatenate([deltas, delta_inf], axis=1)
        
        alpha = 1.0 - np.exp(-density * deltas)
        
        T = np.cumprod(1.0 - alpha + 1e-10, axis=1)
        T = np.concatenate([np.ones_like(T[:, :1]), T[:, :-1]], axis=1)
        
        weights = alpha * T[:, :-1]
        color = np.sum(weights[:, :, np.newaxis] * rgb, axis=1)
        color = color + T[:, -1, np.newaxis] * self.background
        
        return color
```

## Subtopics

### [DVGO with Reparameterized Rendering](3525-dvgo-with-reparameterized-rendering.md)
This method adapts the Direct Voxel Grid Optimization (DVGO) architecture by replacing its standard volume rendering integral with a reparameterized estimate based on differentiable ray point sampling. It solves the problem of high computational cost in standard ray marching by allowing the number of radiance samples to be explicitly controlled and minimized, particularly during the coarse training stage. It sets itself apart from standard DVGO by trading off rendering quality (PSNR) for significant training speed improvements in the coarse stage, while maintaining competitive performance in the fine stage only when sample counts are kept low.

### DVGO Interval Length Heuristic
A heuristic in DVGO that sets the interval lengths $d$ in the volume rendering equation to the ratio of the current voxel grid resolution to the base voxel grid resolution, making the model independent of scene size [S3]. Disabling this heuristic by setting interval lengths to true physical distances between sample points causes DVGO to fail to render at high quality, as observed in Table A2 where 'disabled' rows show significantly lower PSNR or 'fail' status [S3]. On the Blender dataset, DVGO with the heuristic ('default') achieves PSNR values such as 34.10 (drums), 25.40 (ficus), and 32.56 (hotdog), whereas disabling it ('disabled') results in failures or much lower scores like 15.74 (fern) and 17.38 (flower) [S3].

### Naive Combination Baseline (DVGO-NeuS)
A straightforward combination of DVGO and NeuS, replacing the volume rendering in DVGO with the SDF-based volume rendering scheme [S4, unofficial]. It serves as the naive baseline in this work, which can hardly produce satisfactory results [S4, unofficial]. In the baseline model, the color network tends to depend more on the additional under-constrained voxel feature grid input, thus breaking color-geometry dependency [S4, unofficial]. Additionally, due to a high degree of freedom in optimizing a voxel grid, it is hard to maintain a globally coherent shape without additional constraints [S4, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** DVGO is significantly faster than NeRF in both training and inference due to the replacement of MLP queries with grid lookups [S1, unofficial]. It achieves 2-3x speedup with PyTorch CUDA extensions [S1, unofficial].
- **Scaling:** Scales linearly with grid resolution. Higher resolutions require more memory but offer better detail [S1, unofficial]. Octree or hash encoding variants can be used for scaling to higher resolutions [S1, unofficial].
- **Strengths:** Fast training and inference, simple implementation, efficient memory usage for moderate resolutions [S1, unofficial].
- **Limitations:** Memory usage grows cubically with resolution. Less flexible than MLPs for complex geometries [G].
- **When to Use:** When training speed is critical and the scene can be represented well with a voxel grid [S1, unofficial]. Suitable for forward-facing and bounded scenes [G].
- **When Not to Use:** For very large unbounded scenes where memory is a constraint, or when high-frequency details require very high grid resolutions [G].

## Background
DVGO was introduced by Sun et al. in CVPR 2022 [S1, unofficial]. It builds on the idea of differentiable volume rendering but replaces the neural network representation with direct voxel grids [S1, unofficial]. The method was developed to address the slow training times of NeRF [S1, unofficial]. It is used in various datasets including NeRF Synthetic, NSVF, BlendedMVS, Tanks and Temples, DeepVoxels, and LLFF [S1, unofficial].
