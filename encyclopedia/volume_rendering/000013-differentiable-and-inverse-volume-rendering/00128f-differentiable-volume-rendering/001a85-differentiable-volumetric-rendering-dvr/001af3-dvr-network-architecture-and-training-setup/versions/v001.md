# DVR Network Architecture and Training Setup

Also called: DVR, DVR Implementation Details, DepthFunction, DepthModule, Differentiable Volumetric Rendering (Depth Estimation via Implicit Surface), Network Architecture and Training Configuration

## Overview
This article details the neural network architecture and training configuration required to implement the Differentiable Volumetric Rendering (DVR) method [S1, S3]. It defines the implicit function network that maps 3D coordinates to occupancy logits and texture values, and specifies the hyperparameters, optimization strategy, and ray-sampling schedules used to train the model from single-view or multi-view inputs [S2, S3]. It builds on [Differentiable Volumetric Rendering (DVR)](775-differentiable-volumetric-rendering-dvr.md) by providing the concrete implementation details for the forward pass and gradient computation via the `DepthFunction` [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   **Ray Origin ($\mathbf{r}_0$):** 3D camera origin for each pixel.
*   **Ray Direction ($\mathbf{d}$):** Normalized direction vector from camera origin through the pixel.
*   **Decoder Network ($f_\theta$):** The implicit neural representation parameters $\theta$.
*   **Context ($c$):** Latent code or conditioning vector (e.g., from an encoder network for single-view reconstruction) [S3].
*   **Threshold ($\tau$):** Occupancy logit threshold for surface intersection (default 0.5) [S1].
*   **Depth Range:** Interval $[s_0, n\Delta s + s_0]$ covering the volume of interest [S3].

**Outputs:**
*   **Surface Depth ($\hat{d}$):** The distance along the ray to the first intersection with the isosurface $f_\theta(\mathbf{p}) = \tau$.
*   **Texture/Color:** RGB values sampled at the surface point $\hat{\mathbf{p}} = \mathbf{r}_0 + \hat{d}\mathbf{d}$ [S3].

### Data Structures

**Combined Network (Implicit Representation):**
*   **Architecture:** 5 fully-connected ResNet blocks with ReLU activation [S2, S3].
*   **Input:** 3D coordinates $(x, y, z)$ concatenated with context $c$ (if applicable).
*   **Output Layer:** Dimension 4.
    *   Index 0: Occupancy probability/logit.
    *   Indices 1-3: Texture (RGB) values [S2, S3].

**Encoder Network (Single-View Reconstruction):**
*   **Architecture:** ResNet-18 [S2, S3].
*   **Input:** Single RGB image.
*   **Output:** 256-dimensional latent code $z$ [S2, S3].

**DepthModule Parameters:**
*   `tau` (float): Threshold for occupancy logits. Default: 0.5 [S1].
*   `n_steps` (tuple): Number of evaluation steps for initial ray sampling. Default: `[128, 129]` [S1].
*   `n_secant_steps` (int): Number of refinement steps for root-finding. Default: 8 [S1].
*   `depth_range` (tuple): Range of possible depth values. Default: `[0., 2.4]` [S1].
*   `method` (string): Refinement method. Options: 'secant' (default) [S1].
*   `check_cube_intersection` (bool): Whether to intersect rays with the unit cube. Default: True [S1].
*   `max_points` (int): Maximum number of points loaded to GPU memory. Default: 3,700,000 [S1].
*   `schedule_ray_sampling` (bool): Whether to schedule ray sampling accuracy. Default: True [S1].
*   `schedule_milestones` (list): Training iterations after which sampling accuracy doubles. Default: `[50000, 100000, 250000]` [S1].
*   `init_resolution` (int): Initial resolution for ray sampling. Default: 16 [S1].

### Algorithm Steps

1.  **Initialization:** Initialize `DepthModule` with parameters listed above [S1].
2.  **Determine Sampling Steps:**
    *   If `n_steps` is `None`, use `self.n_steps`.
    *   If `schedule_ray_sampling` is `True` and current iteration `it` is provided, call `get_sampling_accuracy(it)` to determine the effective number of steps [S1].
3.  **Ray Sampling:**
    *   Calculate step size $\Delta s$ based on the depth range and number of steps $n$ [S3].
    *   Generate $n$ equally-spaced sample points along the ray:
        $$ \mathbf{p}_j^{\text{ray}} = \mathbf{r}_0 + (j\Delta s + s_0)\mathbf{d}, \quad j = 0, \dots, n-1 $$
        where $s_0$ determines the closest possible surface point [S3].
4.  **Surface Detection:**
    *   Evaluate the decoder $f_\theta(\mathbf{p}_j^{\text{ray}}, c)$ for all samples [S3].
    *   Find the smallest index $j$ such that the occupancy logit crosses the threshold $\tau$:
        $$ j = \operatorname{argmin}_{j'} \left( f_\theta(\mathbf{p}_{j'+1}^{\text{ray}}) \geq \tau > f_\theta(\mathbf{p}_{j'}^{\text{ray}}) \right) $$
        This identifies the interval $[j\Delta s + s_0, (j+1)\Delta s + s_0]$ containing the surface [S3].
5.  **Refinement (Secant Method):**
    *   Apply the secant method within the identified interval to find the precise depth $\hat{d}$ [S3].
    *   Iterate $n_{\text{secant\_steps}}$ times to refine the depth estimate [S1].
6.  **Texture Sampling:**
    *   Compute surface point $\hat{\mathbf{p}} = \mathbf{r}_0 + \hat{d}\mathbf{d}$ [S3].
    *   Query the decoder at $\hat{\mathbf{p}}$ to retrieve RGB values [S3].

### Pseudocode

```python
import torch
import torch.nn as nn

class DepthFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, ray0, ray_direction, decoder, c, n_steps, n_secant_steps, tau, depth_range, method, check_cube_intersection, max_points):
        """
        Forward pass for DVR depth estimation.
        
        Args:
            ray0: Tensor of shape (N, 3), ray origins.
            ray_direction: Tensor of shape (N, 3), ray directions.
            decoder: Neural network function f_theta.
            c: Context tensor (e.g., latent code).
            n_steps: Tuple (min_steps, max_steps) for sampling.
            n_secant_steps: Number of secant refinement steps.
            tau: Occupancy threshold.
            depth_range: Tuple (s0, s1) defining the ray interval.
            method: String, currently only 'secant' is implemented.
            check_cube_intersection: Boolean, unused in this simplified version.
            max_points: Integer, unused in this simplified version.
            
        Returns:
            depth: Tensor of shape (N,), estimated surface depths.
        """
        # 1. Determine number of steps
        if isinstance(n_steps, tuple) and len(n_steps) > 1:
            n = n_steps[0] # Use min_steps for simplicity; scheduling logic handled externally in training loop
        else:
            n = n_steps
            
        s0, s1 = depth_range
        delta_s = (s1 - s0) / n
        
        # 2. Generate sample points
        # Create depth values: s0, s0+ds, ..., s0+(n-1)ds
        depths_samples = torch.linspace(s0, s1 - delta_s, n, device=ray0.device)
        # Expand to (N, n)
        depths_samples = depths_samples.unsqueeze(0).expand(ray0.size(0), -1)
        
        # Calculate 3D points: p_j = r0 + (j*ds + s0) * d
        # ray_direction shape (N, 3), depths_samples shape (N, n)
        # We need to broadcast correctly.
        # p = r0.unsqueeze(1) + (depths_samples.unsqueeze(2) * ray_direction.unsqueeze(1))
        # However, depths_samples already includes s0 offset if we generated it that way.
        # Let's stick to the formula: p_j = r0 + (j*ds + s0) * d
        # j goes from 0 to n-1.
        j_indices = torch.arange(n, device=ray0.device).float()
        offsets = j_indices * delta_s + s0
        offsets = offsets.unsqueeze(0).expand(ray0.size(0), -1)
        
        points = ray0.unsqueeze(1) + offsets.unsqueeze(2) * ray_direction.unsqueeze(1)
        
        # 3. Evaluate decoder
        # decoder expects points (N*n, 3) and context c
        # Reshape points to (N*n, 3)
        points_flat = points.view(-1, 3)
        
        # Handle context c: if c is per-ray, repeat it. If global, broadcast.
        # Assuming c is (N, D) or (1, D).
        if c.dim() == 2:
            c_flat = c.repeat_interleave(n, dim=0)
        else:
            c_flat = c.expand(-1, -1).repeat_interleave(n, dim=0)
            
        with torch.no_grad():
            # decoder returns (N*n, 4)
            outputs = decoder(points_flat, c_flat)
            
        # Reshape back to (N, n, 4)
        outputs = outputs.view(ray0.size(0), n, -1)
        
        occupancy = outputs[..., 0]
        
        # 4. Find crossing interval
        # Find j where occupancy[j] < tau and occupancy[j+1] >= tau
        # We look for the first index j such that occupancy[j+1] >= tau > occupancy[j]
        # Create boolean mask for crossing
        # occupancy[:, 1:] >= tau and occupancy[:, :-1] < tau
        crossing = (occupancy[:, 1:] >= tau) & (occupancy[:, :-1] < tau)
        
        # Find the first True index in each row
        # If no crossing, depth is infinity
        if not torch.any(crossing):
            return torch.full_like(ray0[:, 0], float('inf'))
            
        # Get indices of first crossing
        # argmax returns the first True index if we use cumsum trick or just search
        # Since we want the smallest j, we can use (crossing * torch.arange(n-1)).max(dim=1) ? No.
        # Use torch.argmax on the boolean mask, but it returns the first True.
        # However, if multiple crossings, we want the first one.
        # torch.argmax returns the index of the first maximum. For booleans, True=1, False=0.
        # So argmax returns the index of the first True.
        j_indices_crossing = torch.argmax(crossing.float(), dim=1)
        
        # 5. Secant Refinement
        # Interval is [d_low, d_high] corresponding to j and j+1
        d_low = offsets[torch.arange(ray0.size(0)), j_indices_crossing]
        d_high = offsets[torch.arange(ray0.size(0)), j_indices_crossing + 1]
        
        d_pred = (d_low + d_high) / 2.0
        
        # We need to evaluate the decoder at the refined points.
        # To do this efficiently, we can iterate.
        # Note: The original code uses a loop for secant steps.
        
        for _ in range(n_secant_steps):
            # Calculate mid points
            # p_mid = r0 + d_pred * d
            p_mid = ray0 + d_pred.unsqueeze(1) * ray_direction
            
            # Evaluate decoder at mid points
            # p_mid shape (N, 3)
            with torch.no_grad():
                # decoder(p_mid, c)
                # c might need broadcasting if it's (1, D) or (N, D)
                if c.dim() == 2 and c.size(0) == 1:
                    c_mid = c.expand(ray0.size(0), -1)
                else:
                    c_mid = c
                    
                f_mid = decoder(p_mid, c_mid)[..., 0] - tau
            
            # Update intervals
            # if f_mid < 0, then root is in [d_pred, d_high] -> d_low = d_pred
            # else root is in [d_low, d_pred] -> d_high = d_pred
            
            ind_low = f_mid < 0
            d_low[ind_low] = d_pred[ind_low]
            d_high[~ind_low] = d_pred[~ind_low]
            
            d_pred = 0.5 * (d_low + d_high)
            
        return d_pred

    @staticmethod
    def backward(ctx, grad_output):
        # DVR uses implicit differentiation, so gradients are computed analytically
        # without unrolling the forward pass.
        # This is a placeholder for the actual implicit differentiation logic.
        # In practice, this involves computing the gradient of the occupancy function
        # with respect to the input coordinates and using the chain rule.
        # For the purpose of this article, we note that the gradient is computed
        # via the autograd engine if the forward pass is differentiable,
        # but the paper emphasizes implicit differentiation for efficiency.
        # [G] The actual backward pass requires computing the normal vector
        # n = grad_p f_theta(p) and using the formula:
        # d(depth)/d(input) = - (grad_p f_theta . d_ray) / (grad_p f_theta . grad_p f_theta)
        # This is complex to implement from scratch without the specific framework hooks.
        # We return None for simplicity as the core method is the forward pass.
        return None, None, None, None, None, None, None, None, None, None, None

def get_sampling_accuracy(it, schedule_milestones, init_resolution):
    """
    Determines the number of ray samples based on training iteration.
    
    Args:
        it: Current training iteration.
        schedule_milestones: List of iteration milestones.
        init_resolution: Initial number of samples.
        
    Returns:
        n: Number of samples.
    """
    if not schedule_milestones:
        return init_resolution * 8 # Default to 128 if no milestones? Source says [128, 129] default n_steps.
        
    res = init_resolution
    for milestone in schedule_milestones:
        if it < milestone:
            return res
        res = res * 2
    return res

```

### Parameters and Typical Values
*   **Batch Size:** 64 images [S2, S3].
*   **Pixels per Image:** 1024 random pixels [S2, S3].
*   **Optimizer:** Adam with learning rate $\gamma = 10^{-4}$ [S2, S3].
*   **Learning Rate Schedule:** Decrease by factor of 5 after 750 and 1000 epochs [S2, S3].
*   **Hardware:** Single NVIDIA V100 GPU [S2, S3].
*   **Ray Sampling Schedule:** Start with $n=16$. Double $n$ after 50,000, 150,000, and 250,000 iterations, reaching $n=128$ [S2, S3].

### Edge Cases and Pitfalls
*   **No Surface Intersection:** If no crossing is found along the ray, the depth is set to infinity [S1].
*   **Precision:** The secant method refines the depth estimate, but precision depends on the number of secant steps (default 8) and the initial sampling density [S1, S3].
*   **Memory:** The `max_points` parameter limits GPU memory usage for point clouds, but for DVR, the primary memory constraint is the batch size and the number of samples per ray [S1].

## Operating characteristics

*   **Time Complexity:** The forward pass involves $N \times n$ evaluations of the decoder, where $N$ is the number of pixels and $n$ is the number of samples per ray. The secant refinement adds $N \times n_{\text{secant\_steps}}$ evaluations. With $n=128$ and $n_{\text{secant\_steps}}=8$, this is significant but manageable on modern GPUs [S1, S3].
*   **Memory Complexity:** Memory usage scales with the batch size and the number of samples per ray. The `max_points` parameter is not directly relevant for DVR as it does not store point clouds, but the decoder weights and intermediate activations do consume memory [S1].
*   **Performance:** Trained on a single NVIDIA V100 GPU with a batch size of 64 images and 1024 pixels each [S2, S3].
*   **Strengths:** Differentiable rendering allows for end-to-end training from single-view images without explicit 3D supervision [S3].
*   **Limitations:** The quality of the reconstruction depends heavily on the ray sampling schedule and the initial resolution [S3].

## Background

*   **Origin:** The DVR method was introduced by Mescheder et al. in "Occupancy Networks: Learning 3D Reconstruction in Function Space" (CVPR 2019) and extended by Niemeyer et al. in "Differentiable Volumetric Rendering: Learning Implicit 3D Representations without 3D Supervision" (CVPR 2020) [S1, S3].
*   **History:** The method builds on the concept of occupancy networks, which represent 3D shapes as implicit functions. The differentiable rendering component allows these implicit representations to be trained from 2D images [S1, S3].
*   **Usage:** DVR is used for 3D shape and texture reconstruction from single-view or multi-view images, particularly in scenarios where 3D supervision is unavailable [S3].
