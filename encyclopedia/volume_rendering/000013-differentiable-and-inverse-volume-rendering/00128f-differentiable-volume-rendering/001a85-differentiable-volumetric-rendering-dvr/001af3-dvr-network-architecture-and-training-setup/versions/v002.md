# DVR Network Architecture and Training Setup

Also called: DVR, DVR Implementation Details, DepthFunction, DepthModule, Differentiable Volumetric Rendering (Depth Estimation via Implicit Surface), Network Architecture and Training Configuration

## Overview
This article details the neural network architecture and training configuration for the Differentiable Volumetric Rendering (DVR) method [S1, S3, unofficial]. It defines the implicit function network mapping 3D coordinates to occupancy logits and texture values, and specifies the hyperparameters, optimization strategy, and ray-sampling schedules required to train the model from single-view or multi-view inputs [S2][S3, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   **Ray Origin ($\mathbf{r}_0$):** 3D camera origin for each pixel [G].
*   **Ray Direction ($\mathbf{d}$):** Normalized direction vector from camera origin through the pixel [G].
*   **Decoder Network ($f_\theta$):** The implicit neural representation parameters $\theta$ [S3, unofficial].
*   **Context ($c$):** Latent code or conditioning vector (e.g., from an encoder network for single-view reconstruction) [S3, unofficial].
*   **Threshold ($\tau$):** Occupancy logit threshold for surface intersection (default 0.5) [S1, unofficial].
*   **Depth Range:** Interval $[s_0, n\Delta s + s_0]$ covering the volume of interest [S3, unofficial].

**Outputs:**
*   **Surface Depth ($\hat{d}$):** The distance along the ray to the first intersection with the isosurface $f_\theta(\mathbf{p}) = \tau$ [S3, unofficial].
*   **Texture/Color:** RGB values sampled at the surface point $\hat{\mathbf{p}} = \mathbf{r}_0 + \hat{d}\mathbf{d}$ [S3, unofficial].

### Data Structures

**Combined Network (Implicit Representation):**
*   **Architecture:** 5 fully-connected ResNet blocks with ReLU activation [S2][S3, unofficial].
*   **Input:** 3D coordinates $(x, y, z)$ concatenated with context $c$ (if applicable).
*   **Output Layer:** Dimension 4.
    *   Index 0: Occupancy probability/logit [S2][S3, unofficial].
    *   Indices 1-3: Texture (RGB) values [S2][S3, unofficial].

**Encoder Network (Single-View Reconstruction):**
*   **Architecture:** ResNet-18 [S2][S3, unofficial].
*   **Input:** Single RGB image.
*   **Output:** 256-dimensional latent code $z$ [S2][S3, unofficial].

**DepthModule Parameters:**
*   `tau` (float): Threshold for occupancy logits. Default: 0.5 [S1, unofficial].
*   `n_steps` (tuple): Number of evaluation steps for initial ray sampling. If `n_steps` is `None`, use `self.n_steps` [S1, unofficial]. Default: `[128, 129]` [S1, unofficial].
*   `n_secant_steps` (int): Number of refinement steps for root-finding. Default: 8 [S1, unofficial].
*   `depth_range` (tuple): Range of possible depth values. Not relevant when unit cube intersection is used. Default: `[0., 2.4]` [S1, unofficial].
*   `method` (string): Refinement method. Options: 'secant' (default) [S1, unofficial].
*   `check_cube_intersection` (bool): Whether to intersect rays with the unit cube. Default: True [S1, unofficial].
*   `max_points` (int): Maximum number of points loaded to GPU memory. Default: 3,700,000 [S1, unofficial].
*   `schedule_ray_sampling` (bool): Whether to schedule ray sampling accuracy. Default: True [S1, unofficial].
*   `schedule_milestones` (list): Training iterations after which sampling accuracy doubles. Default: `[50000, 100000, 250000]` [S1, unofficial].
*   `init_resolution` (int): Initial resolution for ray sampling. Default: 16 [S1, unofficial].

### Algorithm Steps

1.  **Initialization:** Initialize `DepthModule` with parameters listed above [S1, unofficial].
2.  **Determine Sampling Steps:** If `n_steps` is `None`, use `self.n_steps` [S1, unofficial]. If `schedule_ray_sampling` is `True` and current iteration `it` is provided, call `get_sampling_accuracy(it)` to determine the effective number of steps [S1, unofficial].
3.  **Ray Sampling:** Calculate step size $\Delta s$ based on the depth range and number of steps $n$ [S3, unofficial]. Generate $n$ equally-spaced sample points along the ray:
    $$ \mathbf{p}_j^{\text{ray}} = \mathbf{r}_0 + (j\Delta s + s_0)\mathbf{d}, \quad j = 0, \dots, n-1 $$
    where $s_0$ determines the closest possible surface point [S3, unofficial].
4.  **Surface Detection:** Evaluate the decoder $f_\theta(\mathbf{p}_j^{\text{ray}}, c)$ for all samples [S3, unofficial]. Find the smallest index $j$ such that the occupancy logit crosses the threshold $\tau$:
    $$ j = \operatorname{argmin}_{j'} \left( f_\theta(\mathbf{p}_{j'+1}^{\text{ray}}) \geq \tau > f_\theta(\mathbf{p}_{j'}^{\text{ray}}) \right) $$
    This identifies the interval $[j\Delta s + s_0, (j+1)\Delta s + s_0]$ containing the surface [S3, unofficial].
5.  **Refinement (Secant Method):** Apply the secant method within the identified interval to find the precise depth $\hat{d}$ [S3, unofficial]. Iterate $n_{\text{secant\_steps}}$ times to refine the depth estimate [S1, unofficial].
6.  **Texture Sampling:** Compute surface point $\hat{\mathbf{p}} = \mathbf{r}_0 + \hat{d}\mathbf{d}$ [S3, unofficial]. Query the decoder at $\hat{\mathbf{p}}$ to retrieve RGB values [S3, unofficial].

### Pseudocode

```python
import torch

class DepthFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, ray0, ray_direction, decoder, c, n_steps, n_secant_steps, tau, depth_range, method, check_cube_intersection, max_points):
        # 1. Determine number of steps
        if isinstance(n_steps, tuple) and len(n_steps) > 1:
            n = n_steps[0]
        else:
            n = n_steps
            
        s0, s1 = depth_range
        delta_s = (s1 - s0) / n
        
        # 2. Generate sample points
        j_indices = torch.arange(n, device=ray0.device).float()
        offsets = j_indices * delta_s + s0
        offsets = offsets.unsqueeze(0).expand(ray0.size(0), -1)
        
        points = ray0.unsqueeze(1) + offsets.unsqueeze(2) * ray_direction.unsqueeze(1)
        
        # 3. Evaluate decoder
        points_flat = points.view(-1, 3)
        if c.dim() == 2:
            c_flat = c.repeat_interleave(n, dim=0)
        else:
            c_flat = c.expand(-1, -1).repeat_interleave(n, dim=0)
            
        with torch.no_grad():
            outputs = decoder(points_flat, c_flat)
            
        outputs = outputs.view(ray0.size(0), n, -1)
        occupancy = outputs[..., 0]
        
        # 4. Find crossing interval
        crossing = (occupancy[:, 1:] >= tau) & (occupancy[:, :-1] < tau)
        
        if not torch.any(crossing):
            return torch.full_like(ray0[:, 0], float('inf'))
            
        j_indices_crossing = torch.argmax(crossing.float(), dim=1)
        
        # 5. Secant Refinement
        d_low = offsets[torch.arange(ray0.size(0)), j_indices_crossing]
        d_high = offsets[torch.arange(ray0.size(0)), j_indices_crossing + 1]
        
        d_pred = (d_low + d_high) / 2.0
        
        for _ in range(n_secant_steps):
            p_mid = ray0 + d_pred.unsqueeze(1) * ray_direction
            if c.dim() == 2 and c.size(0) == 1:
                c_mid = c.expand(ray0.size(0), -1)
            else:
                c_mid = c
                    
            f_mid = decoder(p_mid, c_mid)[..., 0] - tau
            
            ind_low = f_mid < 0
            d_low[ind_low] = d_pred[ind_low]
            d_high[~ind_low] = d_pred[~ind_low]
            
            d_pred = 0.5 * (d_low + d_high)
            
        return d_pred

    @staticmethod
    def backward(ctx, grad_output):
        # [G] The sources specify that gradients are computed analytically via implicit differentiation
        # without unrolling the forward pass. Implementing this requires framework-specific hooks
        # to compute the normal vector n = grad_p f_theta(p) and applying the chain rule.
        # This step is omitted from the pseudocode as it is framework-dependent.
        return None, None, None, None, None, None, None, None, None, None, None

def get_sampling_accuracy(it, schedule_milestones, init_resolution):
    if not schedule_milestones:
        return [128, 129]
        
    res = init_resolution
    for milestone in schedule_milestones:
        if it < milestone:
            return [res, res + 1]
        res = res * 2
    return [res, res + 1]
```

### Parameters and Typical Values
*   **Batch Size:** 64 images [S2][S3, unofficial].
*   **Pixels per Image:** 1024 random pixels [S2][S3, unofficial].
*   **Optimizer:** Adam with learning rate $\gamma = 10^{-4}$ [S2][S3, unofficial].
*   **Learning Rate Schedule:** Decrease by factor of 5 after 750 and 1000 epochs [S2][S3, unofficial].
*   **Hardware:** Single NVIDIA V100 GPU [S2][S3, unofficial].
*   **Ray Sampling Schedule:** Start with $n=16$. Double $n$ after 50,000, 150,000, and 250,000 iterations, reaching $n=128$ [S2][S3, unofficial].

### Edge Cases and Pitfalls
*   **No Surface Intersection:** If no crossing is found along the ray, the depth is set to infinity [S1, unofficial].
*   **Precision:** The secant method refines the depth estimate, but precision depends on the number of secant steps (default 8) and the initial sampling density [S1, S3, unofficial].
*   **Memory:** The `max_points` parameter limits GPU memory usage for point clouds, but for DVR, the primary memory constraint is the batch size and the number of samples per ray [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** The forward pass involves $N \times n$ evaluations of the decoder, where $N$ is the number of pixels and $n$ is the number of samples per ray [S1, S3, unofficial]. The secant refinement adds $N \times n_{\text{secant\_steps}}$ evaluations [S1, unofficial].
*   **Memory Complexity:** Memory usage scales with the batch size and the number of samples per ray [S1, unofficial]. The `max_points` parameter is not directly relevant for DVR as it does not store point clouds, but the decoder weights and intermediate activations do consume memory [S1, unofficial].
*   **Performance:** Trained on a single NVIDIA V100 GPU with a batch size of 64 images and 1024 pixels each [S2][S3, unofficial].
*   **Strengths:** Differentiable rendering allows for end-to-end training from single-view images without explicit 3D supervision [S3, unofficial].
*   **Limitations:** The quality of the reconstruction depends heavily on the ray sampling schedule and the initial resolution [S3, unofficial].

## Background

*   **Origin:** The DVR method was introduced by Mescheder et al. in "Occupancy Networks: Learning 3D Reconstruction in Function Space" (CVPR 2019) and extended by Niemeyer et al. in "Differentiable Volumetric Rendering: Learning Implicit 3D Representations without 3D Supervision" (CVPR 2020) [S1, S3, unofficial].
*   **History:** The method builds on the concept of occupancy networks, which represent 3D shapes as implicit functions. The differentiable rendering component allows these implicit representations to be trained from 2D images [S1, S3, unofficial].
*   **Usage:** DVR is used for 3D shape and texture reconstruction from single-view or multi-view images, particularly in scenarios where 3D supervision is unavailable [S3, unofficial].
