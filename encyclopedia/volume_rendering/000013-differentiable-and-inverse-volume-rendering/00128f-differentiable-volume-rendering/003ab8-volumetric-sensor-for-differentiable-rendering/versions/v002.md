# Volumetric Sensor for Differentiable Rendering
Also called: DeltaVolumetricSensor

## Overview
The Volumetric Sensor (DeltaVolumetricSensor) is a differentiable rendering component that accumulates radiance contributions into a volumetric film using delta tracking or similar path tracing logic, supporting both forward and reverse-mode automatic differentiation [S1, unofficial]. It distinguishes itself from standard differentiable volume rendering by explicitly managing the gradient propagation through the scattering and extinction coefficients within the sensor's accumulation step, rather than relying solely on the integrator's path tracing loop [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ray parameters (origin, direction, time $t$), volume density field ($\sigma_t$), scattering coefficient ($\sigma_s$), emitted radiance ($em$), and an active ray mask [S1, unofficial].
*   **Outputs:** Accumulated radiance in the film buffer and gradients for $\sigma_t$, $\sigma_s$, and $em$ [S1, unofficial].

**Data Structures:**
*   **Film Buffer:** Stores accumulated radiance [S1, unofficial]. In primal mode, this is the final output [S1, unofficial]. In forward-mode AD, contributions are scattered into a gradient buffer (`δL.array`) [S1, unofficial].
*   **Gradient Buffers:** `g_em`, `g_st`, `g_ss` initialized to zeros, storing gradients for emitted radiance, total extinction, and scattering coefficients respectively [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Initialize gradient buffers `g_em`, `g_st`, `g_ss` to zeros [S1, unofficial].
2.  **Ray Validation:** Determine active rays using `active = mi.Bool(active & mei.is_valid())` [S1, unofficial].
3.  **Position and Voxel Lookup:** Compute ray position `pos = ray(mei.t)` [S1, unofficial]. Determine the current voxel index `current_voxel` and its flat index `current_voxel_flat` [S1, unofficial]. Check if the position is inside the grid bounds `is_inside_grid` [S1, unofficial].
4.  **Index Selection:** Select the accumulation index [S1, unofficial]. If surface-aware, use `2*current_voxel_flat` for inside and `2*current_voxel_flat+1` for outside [S1, unofficial]. Otherwise, use `current_voxel_flat` [S1, unofficial].
5.  **Gradient Setup:** Detach primal values for `emitted`, `sigma_s`, and `sigma_t` to break the computational graph where necessary [S1, unofficial]. Enable gradients for these variables and set initial gradients using `dr.set_grad` [S1, unofficial].
6.  **Forward-Mode AD Propagation:** If operating in forward-mode AD, propagate gradients from `sigma_t` to `sigma_s` if `sigma_t` has a gradient; otherwise, propagate from `sigma_s` [S1, unofficial]. Set gradients for `ss` and `st` accordingly [S1, unofficial].
7.  **Contribution Calculation:** Compute the radiance contribution using the formulas below [S1, unofficial].
8.  **Accumulation:**
    *   **Primal Mode:** Write the contribution to the film: `self.m_film.write(contrib, idx, active & is_inside_grid)` [S1, unofficial].
    *   **Forward Mode (Non-Primal):** Scatter and reduce the contribution into the gradient buffer `δL.array` [S1, unofficial].

**Formulas:**
The core accumulation relies on delta tracking statistics [S1, unofficial]:

*   **Scattering Coefficient:**
    $$ sa = \sigma_t - \sigma_s $$
*   **Transmittance:**
    $$ tr = e^{-\sigma_t t} $$
*   **Transmittance PDF:**
    $$ tr_{pdf} = tr \cdot \sigma_t $$
*   **Inverse PDF:**
    $$ inv_{pdf} = \text{select}(tr_{pdf} \neq 0, \text{detach}(1/tr_{pdf}), 0) $$
*   **Throughput:**
    $$ throughput = \text{detach}(attenuation \cdot e^{\sigma_t t_{prev}}) \cdot e^{-\sigma_t t_{prev}} \cdot \text{select}(\sigma_s \neq 0, \sigma_s^{n_{scat}} / \text{detach}(\sigma_s^{n_{scat}}), 1) $$
*   **Contribution:**
    $$ contrib = \text{select}(active, throughput \cdot sa \cdot tr \cdot inv_{pdf} \cdot em, 0) $$

**Parameters:**
*   `n_scat`: Number of scattering events considered in the throughput term. Not given in the sources.
*   `attenuation`: Pre-computed attenuation factor. Not given in the sources.
*   `t_prev`: Previous time/distance step. Not given in the sources.

**Pitfalls:**
*   **Inverse PDF Calculation:** The calculation of `inv_pdf` is noted as potentially incorrect if free-flight distances are not sampled proportional to transmittance [S1, unofficial]. Implementers must ensure the sampling strategy matches the PDF definition to avoid biased gradients [S1, unofficial].
*   **Gradient Detachment:** Care must be taken when using `detach()` in the throughput and inverse PDF calculations to prevent gradient flow through terms that should remain constant during the specific AD mode [S1, unofficial].

## Subtopics

### RatioVolumetricSensor
A variant of the volumetric sensor that uses a majorant for ratio tracking or similar variance reduction techniques in volumetric rendering [S1, unofficial]. It requires a `majorant` property during initialization, which represents the maximum extinction coefficient used to bound the sampling probability [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of active rays and samples per ray, dominated by the exponential and selection operations in the contribution formula [S1, unofficial].
*   **Memory Complexity:** $O(n)$ for the film buffer and gradient buffers, where $n$ is the number of voxels or pixels, depending on the accumulation target [S1, unofficial].
*   **Strengths:** Supports both forward and reverse-mode AD, allowing flexibility in optimization strategies [S1, unofficial].
*   **Limitations:** The inverse PDF calculation is sensitive to sampling strategies; incorrect sampling proportional to transmittance leads to biased gradients [S1, unofficial]. Requires specific Mitsuba variants (`cuda_ad_mono`, `llvm_ad_mono`, `metal_ad_mono`) to function [S1, unofficial].

## Background
The Volumetric Sensor originates from the `drtvam` repository, an inverse rendering framework for tomographic volumetric additive manufacturing [S1, unofficial]. It leverages the Dr.Jit library for differentiable programming and is tied to specific Mitsuba renderer variants that support automatic differentiation [S1, unofficial].
