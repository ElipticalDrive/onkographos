# Progressive GAN Discriminator

Also called: Progressive Growing Discriminator

## Overview
A convolutional discriminator that grows progressively in resolution to stabilize training and allow larger batch sizes at lower resolutions [S1]. Unlike the generator in this context, which maintains a fixed implicit representation, the discriminator architecture expands to handle increasing image resolutions, enabling the model to first learn coarse shapes before refining fine details [S1].

## How it works
**Inputs and Outputs**
*   **Input:** Real or generated image samples (e.g., RGB-D data).
*   **Output:** A scalar probability indicating whether the input is real or fake [S2].

**Data Structures**
The discriminator consists of a sequence of convolutional layers, residual blocks, and linear layers. Specific layer configurations depend on the current training resolution. For a standard implementation involving depth inputs:
*   **Depth Normalization:** Depth values are normalized to the range $[0, 1]$ [S2].
*   **Feature Maps:** Intermediate representations are stored as tensors (e.g., $256 \times H \times W$) [S2].

**Steps**
1.  **Initialization:** Begin training at a low resolution (e.g., $32 \times 32$) [S1].
2.  **Progressive Growth:** Double the resolution twice during training, up to $128 \times 128$, adding new layers to the discriminator to handle higher resolutions [S1].
3.  **Feature Extraction:**
    *   Apply a $3 \times 3$ convolution to the input [S2].
    *   Pass the output through Residual Blocks [S2].
    *   Apply a Minibatch Standard Deviation layer to introduce global statistical information [S2].
    *   Apply a final $3 \times 3$ convolution [S2].
4.  **Classification:**
    *   Flatten the feature maps [S2].
    *   Apply two Linear layers [S2].
    *   Output a single scalar value [S2].

**Pitfalls**
*   **Resolution Mismatch:** If the radiance field network is sampled at a lower resolution than the final output, generated depth maps will have lower resolution than real examples. To prevent the discriminator from exploiting this detail difference, downsample all real depth maps to match the generated depth map resolution, then upsample both back to full resolution [S2].

**Pseudocode**
```python
def discriminator_forward(input_rgb, input_depth):
    # Normalize depth to [0, 1]
    normalized_depth = input_depth / 255.0
    
    # Concatenate RGB and Depth
    x = concatenate(input_rgb, normalized_depth, axis=-1)
    
    # Initial Convolution
    x = Conv2d(x, kernel_size=3, stride=1, padding=1)
    x = LeakyReLU(x, negative_slope=0.2)
    
    # Residual Blocks and Downsampling
    # Note: Specific block count and stride depend on current resolution
    x = ResidualBlock(x)
    x = Downsample(x)
    
    # Minibatch Standard Deviation
    # Adds a channel dimension representing the std dev across the batch
    x = MinibatchStdDev(x)
    
    # Final Convolution and Flattening
    x = Conv2d(x, kernel_size=3, stride=1, padding=1)
    x = Flatten(x)
    
    # Linear Layers
    x = Linear(x, out_features=512)
    x = Linear(x, out_features=1)
    
    return x
```

## Subtopics

### Discriminator and Decoder
A variant where the discriminator evaluates real vs. fake samples using residual blocks and minibatch standard deviation, while a separate decoder upsamples feature maps to the original resolution [S2]. The discriminator input is RGB-D, with depth normalized to $[0, 1]$. The decoder takes $4 \times 4$ feature maps from the discriminator (before the minibatch standard deviation layer) and applies successive transposed convolutions with stride 2 and bilinear filtering to upsample until the original resolution is recovered [S2].

## Operating characteristics
*   **Training Stability:** Allows for larger batch sizes at the beginning of training, which helps to stabilize and speed up training [S1].
*   **Resolution Scaling:** Final results are rendered by sampling $512 \times 52$ pixels, but training occurs at lower resolutions ($32 \times 32$ to $128 \times 128$) [S1].
*   **Generator Independence:** Unlike ProgressiveGAN, the generator architecture does not grow; instead, resolution is increased by sampling rays more densely from the same implicit representation [S1].

## Background
Originating from the ProgressiveGAN framework [S1], this method was adapted for 3D-aware image synthesis and volume rendering to manage the complexity of high-resolution generation. It was notably used in pi-GAN for periodic implicit generative adversarial networks [S1] and in unconstrained scene generation with locally conditioned radiance fields [S2].
