# Parameter-space ReSTIR

Also called: GRIS for derivatives, PGRIS, Parameter-Space Differentiable Rendering, Parameter-centric reservoirs

## Overview
Parameter-space ReSTIR is a differentiable rendering formulation that computes gradients with respect to scene parameters directly in parameter space rather than image space [S1]. It solves the memory bottleneck of standard reservoir-based differentiable rendering by reformulating the derivative estimation as a single integral over the parameter space [S1]. This allows the method to store only one reservoir per parameter (texel), accumulating derivative estimates from all relevant pixels, thereby reducing storage complexity from $O(\text{pixels} \times \text{parameters})$ to $O(\text{parameters})$ [S1]. It builds on [Differentiable volume rendering](43-differentiable-volume-rendering.md) by enabling efficient sample reuse across optimization iterations [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Scene parameters (e.g., texture maps defining density $\sigma$ or color $\mathbf{c}$), camera rays, and a loss function $L$ dependent on the rendered image $\hat{C}$ [S1].
*   **Outputs:** Gradient estimates $\nabla_\theta L$ with respect to the scene parameters $\theta$ [S1].

**Data Structures:**
The core data structure is the **Parameter-space Reservoir**, which stores a single selected sample and its associated weights [S1].

**Reservoir Layout:**
The `Reservoir` struct contains five fields [S1]:
1.  `x`: The selected sample (e.g., a path or sample index) [S1].
2.  `wsum`: The sum of weights, calculated as $\sum (q/p)$, where $q$ is the target distribution and $p$ is the source distribution [S1].
3.  `M`: The number of candidates or confidence weight [S1].
4.  `W`: The unbiased contribution weight [S1].
5.  `lock`: A synchronization lock to handle concurrent updates from multiple pixels [S1].

**Algorithm Steps:**
1.  **Candidate Generation:** Generate paths from the camera, restricted to visible texels to avoid wasted computation on invisible parameters [S1].
2.  **Reservoir Update:** For each pixel, compute the derivative contribution of each candidate sample with respect to the texels it intersects, and update the corresponding texel's reservoir [S1]. The update uses the reservoir resampling rule: a new candidate $x_s$ with weight $w_s$ replaces the current reservoir sample $x$ with probability $w_s / w_{sum}$ [S1].
3.  **Reuse Across Iterations:** At optimization iteration $v+1$, if a newly drawn sample is occluded or poor, the algorithm reuses the sample stored in the reservoir from iteration $v$ [S1]. This allows obtaining unoccluded samples by leveraging previous iterations' results [S1].
4.  **Gradient Estimation:** Use the final selected sample from each texel's reservoir to compute the derivative of the loss $L$ with respect to the parameter [S1]. The weight $w$ characterizes how the change in parameter affects the radiance carried by the path and how this change affects the loss $L$ [S1].

**Pseudocode:**

```python
import threading
import random

class Reservoir:
    def __init__(self):
        self.x = 0          # Selected sample
        self.wsum = 0.0     # Sum of weights
        self.M = 0          # Number of candidates
        self.W = 0.0        # Unbiased contribution weight
        self.lock = threading.Lock()

    def update(self, x_s, w_s):
        with self.lock:
            self.wsum += w_s
            if random.random() < (w_s / self.wsum):
                self.x = x_s
            self.M += 1
            self.W = self.W + w_s - (self.W * w_s / self.wsum)

def parameter_space_restir(scene_params, rays, loss_fn, num_iterations):
    reservoirs = {t: Reservoir() for t in scene_params.texels}
    for v in range(num_iterations):
        paths = [generate_path(ray, scene_params) for ray in rays]
        for path in paths:
            for t in path.intersected_texels:
                w_s = compute_derivative_weight(path, t, loss_fn)
                reservoirs[t].update(path.sample_id, w_s)
        gradients = {t: evaluate_gradient(reservoirs[t].x, t, loss_fn) for t in scene_params.texels}
        scene_params.update(gradients)

def generate_path(ray, scene_params):
    # Standard path generation from camera ray [G]
    return Path(ray.origin, ray.direction, scene_params)

def compute_derivative_weight(path, t, loss_fn):
    # Standard AD step to compute derivative weight [G]
    return loss_fn.derivative(path, t)

def evaluate_gradient(sample, t, loss_fn):
    # Standard gradient evaluation from selected sample [G]
    return loss_fn.evaluate(sample, t)
```

**Edge Cases and Pitfalls:**
*   **Invisible Texels:** Generating candidates for texels not visible from the camera is wasteful as their contribution to the loss is zero [S1]. Visibility culling is required.
*   **Concurrency:** Multiple pixels may update the same texel's reservoir simultaneously, requiring synchronization locks [S1].
*   **Precision:** Accumulating weights in `wsum` can lead to precision issues if weights vary significantly in magnitude [G].

## Subtopics

### [Parameter-space Reservoir](11751-parameter-space-reservoir.md)
A data structure for storing a single selected sample and its associated weights to support reservoir resampling in parameter space. It allows for efficient merging and updating of candidate samples across iterations. It is chosen when memory usage must be minimized by sharing derivative estimates across pixels for a single parameter. See [Parameter-space Reservoir](11751-parameter-space-reservoir.md).

## Operating characteristics
*   **Memory Complexity:** $O(\text{parameters})$ or $O(\text{texels})$, compared to $O(\text{pixels} \times \text{parameters})$ for per-pixel reservoirs [S1].
*   **Time Complexity:** Depends on the number of paths and texels, with candidate generation limited to visible texels [S1].
*   **Strengths:** Significant memory reduction for inverse rendering with many parameters; enables sample reuse across optimization iterations [S1].
*   **Limitations:** Requires synchronization for concurrent updates; visibility culling is necessary to avoid wasted computation [S1].
*   **When to use:** Inverse rendering problems with large texture maps or parameter sets where memory is a bottleneck [S1].

## Background
Parameter-space ReSTIR was introduced by Chang, Sivaram, Nowrouzezahrai, Hachisuka, Ramamoorthi, and Li [S1]. It extends Generalized Resampled Importance Sampling (GRIS) [Lin et al. 2022] to differentiable rendering [S1]. It builds on the principles of ReSTIR [Talbot et al. 2005] and applies them to the estimation of derivatives in inverse rendering [S1].
