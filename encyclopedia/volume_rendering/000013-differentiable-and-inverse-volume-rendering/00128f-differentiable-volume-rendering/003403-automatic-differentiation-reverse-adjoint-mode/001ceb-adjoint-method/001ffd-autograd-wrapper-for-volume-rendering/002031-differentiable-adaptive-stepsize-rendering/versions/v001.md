# Differentiable Adaptive Stepsize Rendering

Also called: AdaptiveStepsizeRendering, finite-difference stepsize backprop

## Overview
Differentiable Adaptive Stepsize Rendering is a PyTorch `torch.autograd.Function` that enables gradient-based optimization of adaptive stepsize maps used in volume rendering [S1, unofficial]. It computes the forward pass using a custom CUDA renderer and approximates the backward pass via finite differences, allowing the stepsize map itself to be trained as a learnable parameter [S1, unofficial]. Unlike adjoint-based methods that require deriving analytical gradients for the rendering equation, this approach treats the renderer as a black box, trading computational efficiency for implementation simplicity and robustness to complex rendering pipelines [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A batch of stepsize tensors $S$ of shape $(B, H_s, W_s)$, where $H_s, W_s$ are the stepsize resolution dimensions. Settings including viewport coordinates $[x_{start}, y_{start}, x_{end}, y_{end}]$ and internal renderer resolution.
- **Output:** Rendered color tensors $O$ of shape $(B, C, H_v, W_v)$, where $C$ is the number of color channels and $H_v, W_v$ are the viewport dimensions.
- **Backward Input:** Upstream gradient tensor $\frac{\partial L}{\partial O}$ of shape $(B, C, H_v, W_v)$.
- **Backward Output:** Gradient tensor $\frac{\partial L}{\partial S}$ of shape $(B, 1, H_s, W_s)$.

**Data Structures:**
- **Stepsize Map:** A 3D tensor $(B, H_s, W_s)$. The sources indicate that the internal renderer expects the stepsize map to be padded to match the full internal resolution before rendering.
- **Viewport:** Defined as $[viewStartX, viewStartY, viewEndX, viewEndY]$. This defines the region of interest within the internal renderer's output that is cropped to produce the final result.

**Algorithm Steps:**

1.  **Forward Pass:**
    1.  Retrieve the viewport settings and internal resolution.
    2.  Assert that the input stepsize tensor $S$ shape matches the expected viewport dimensions or internal resolution requirements.
    3.  Pad the stepsize tensor $S$ with a value of $1.0$ along the edges to match the full internal resolution required by the CUDA kernel. Let the padded tensor be $S_{pad}$ [S1, unofficial].
    4.  Call the custom CUDA operation `render_adaptive_stepsize(S_{pad})` to compute the rendered output $O_{full}$ [S1, unofficial].
    5.  Crop $O_{full}$ to the viewport coordinates $[viewStartX, viewStartY, viewEndX, viewEndY]$ to obtain the final output $O$ [S1, unofficial].
    6.  Return $O$.

2.  **Backward Pass (Finite Difference Approximation):**
    1.  Retrieve the saved original stepsize tensor $S$ and the forward output $O$ from the forward pass context [S1, unofficial].
    2.  Define the perturbation magnitude $\epsilon$ (typically $10^{-3}$) [S1, unofficial].
    3.  For each batch item $b$:
        a.  Create a perturbed stepsize tensor $S_{perturbed} = S + \epsilon$, where $\epsilon$ is added element-wise.
        b.  Pad $S_{perturbed}$ with $1.0$ along the edges to match the internal resolution, resulting in $S_{perturbed, pad}$ [S1, unofficial].
        c.  Call `render_adaptive_stepsize(S_{perturbed, pad})` to compute the perturbed output $O_{perturbed, full}$ [S1, unofficial].
        d.  Crop $O_{perturbed, full}$ to the viewport coordinates to obtain $O_e$ [S1, unofficial].
        e.  Compute the finite difference approximation for the gradient with respect to the stepsize:
            $$ \Delta O = \frac{O_e - O}{\epsilon} $$
            where $O$ is the unperturbed output for this batch item.
        f.  Compute the gradient for the stepsize map using the upstream gradient $\frac{\partial L}{\partial O}$ (denoted as $c'$ in the source formula):
            $$ \frac{\partial L}{\partial S_b} = \sum_{c, h, w} \left( \frac{\partial L}{\partial O_b} \cdot \Delta O \right) $$
            The source specifies the operation as `torch.sum(grad_output[b] * ((oe-o)/epsilon), 0, keepdim=True)`. This implies summing over the spatial dimensions and channels, resulting in a gradient tensor of shape $(B, 1, H_s, W_s)$ [S1, unofficial].
    4.  Stack the gradients for all batch items and return $\frac{\partial L}{\partial S}$ [S1, unofficial].

**Parameters:**
- **$\epsilon$ (epsilon):** Perturbation magnitude for finite difference approximation. Typical value: $10^{-3}$ [S1, unofficial].
- **Viewport:** Defines the rendering region $[viewStartX, viewStartY, viewEndX, viewEndY]$. Used to crop/pad tensors to match internal renderer resolution [S1, unofficial].
- **valueScaling:** Retrieved from settings and passed to the renderer update. Its exact mathematical role in the gradient computation is not specified in the provided sources [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Finite differences are sensitive to the choice of $\epsilon$. Too small a value leads to numerical noise; too large a value introduces approximation error. The source uses $10^{-3}$, validated via `torch.autograd.gradcheck` [S1, unofficial].
- **Boundary Conditions:** The stepsize map must be padded with $1.0$ to match the internal resolution. Failure to pad correctly will cause shape mismatches or incorrect rendering at the boundaries [S1, unofficial].
- **Degenerate Input:** The stepsize map should not contain zero or negative values if the renderer assumes positive stepsizes. The source does not specify explicit clamping for the stepsize map itself, but the `normalize` function in the `ImportanceSamplingMethod` clamps mean values to $10^{-7}$, suggesting similar care might be needed [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The backward pass requires $N$ additional forward renders per batch item, where $N$ is the number of elements in the stepsize map if a full Jacobian-vector product is computed, or $1$ if a single finite difference vector is used. The source implies a single perturbation per batch item for the entire map, which is an approximation. If $\epsilon$ is added to the entire tensor, the gradient computed is an approximation of the directional derivative in the direction of the all-ones vector, scaled element-wise. This is significantly faster than adjoint methods for high-resolution maps but less accurate.
- **Memory Complexity:** Requires storing the forward output $O$ and the original stepsize $S$ for the backward pass. The perturbed render requires temporary memory for $O_e$.
- **Strengths:** Simple to implement; does not require analytical derivation of the rendering gradient; works with any differentiable or non-differentiable CUDA renderer as long as it can be called twice.
- **Limitations:** Approximate gradients; computational cost scales with the number of perturbations if a more accurate Jacobian-vector product is desired; sensitive to $\epsilon$.
- **When to use:** When the rendering pipeline is complex or black-box, and analytical gradients are difficult to derive. Suitable for optimizing stepsize maps where high precision in the gradient is not critical.
- **When not to use:** When high-fidelity gradients are required, or when the rendering pipeline is already differentiable and an adjoint method is available.

## Background
The method originates from the "Learning adaptive sampling and reconstruction for Volume Visualization" project [S1, unofficial]. It is part of a PyTorch-based framework for differentiable volume rendering, specifically designed to optimize adaptive stepsize maps. The approach leverages PyTorch's autograd system by wrapping the custom CUDA renderer in a `torch.autograd.Function`, using finite differences to bypass the need for manual gradient implementation [S1, unofficial].
