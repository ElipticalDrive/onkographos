# PyTorch Interface

Also called: Projector class, Differentiable Forward Projector PyTorch binding

## Overview
The PyTorch Interface provides a high-level Python API for differentiable volume rendering, specifically targeting X-ray computed tomography (CT) forward and back projections [S1, unofficial]. It wraps custom C++/CUDA extensions within a `torch.nn.Module` to enable end-to-end automatic differentiation via PyTorch's autograd engine [S1, unofficial]. It solves the problem of integrating differentiable projection operations into deep learning pipelines without manual gradient implementation [S1, unofficial].

## How it works
The interface is implemented as a Python class `Projector` inheriting from `torch.nn.Module` [S1, unofficial]. It exposes forward and back projection operations as differentiable functions [S1, unofficial].

**Inputs and Outputs:**
- **Forward Projection:** Input is a 3D volume tensor (voxel grid) and a set of projection parameters. Output is a 2D projection image tensor [G].
- **Back Projection:** Input is a 2D projection image tensor and projection parameters. Output is a 3D volume tensor containing gradients [G].

**Data Structures:**
The `Projector` class encapsulates CT scanner parameters: scanner geometry type, number of projections, angular range or list of projection angles, detector pixel width and height, source-to-detector distance, source-to-object distance, horizontal/vertical detector shift, number of voxels in each dimension, voxel sizes, and volume center position [S1, unofficial]. These parameters are stored as module attributes and can be specified using set functions or a configuration file [S1, unofficial].

**Steps:**
1. **Initialization:** The `Projector` class is instantiated with CT parameters [S1, unofficial].
2. **Device Management:** If the input volume is not on the GPU but GPU computation is requested, the interface automatically copies the data to the GPU, performs the calculation, and copies the result back to the CPU [S1, unofficial].
3. **Forward Pass:** The `forward` method is called. It invokes the underlying C++/CUDA extension for forward projection [S1, unofficial].
4. **Backward Pass:** PyTorch's autograd engine triggers the backward pass. The C++/CUDA extension provides the gradient computation for the back projection, allowing gradients to flow to the input volume [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Device Mismatch:** The interface handles CPU/GPU transfers, but users must ensure input tensors are compatible with the requested device [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Strengths:** Seamless integration with PyTorch; automatic differentiation; handles device placement [S1, unofficial].
- **Limitations:** Requires custom C++/CUDA extensions; limited to specific CT geometries defined in the configuration [S1, unofficial].

## Background
The PyTorch Interface is part of a differentiable forward projector library for X-ray CT [S1, unofficial]. It leverages PyTorch's autograd system and custom C++/CUDA extensions for performance [S1, unofficial].
