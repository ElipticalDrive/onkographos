# Differential Ratio Tracing

Also called: Differential Ratio Tracking (DRT), Mitsuba 3's Differential Ratio Tracing, volpathsimple-drt

## Overview
Differential Ratio Tracing (DRT) is a differentiable volume rendering method implemented in Mitsuba 3 that provides an unbiased estimator for in-scattering gradients [S2, unofficial]. It addresses the high variance and bias issues inherent in standard free-flight sampling-based baselines when medium density approaches zero [S2, unofficial]. Unlike single-scattering methods that pre-compute view-independent terms, DRT recomputes gradients for each view, making it a general-purpose baseline for path-traced differentiable volume rendering [S1].

## How it works
DRT modifies the adjoint (gradient) computation of a path tracer. While the primal rendering follows standard path tracing, the gradient estimation for in-scattering terms uses a dedicated ratio-tracking estimator to stabilize derivatives in low-density regions [S2, unofficial].

**Inputs:**
- Scene definition (volumes, sensors, parameters to optimize) [S2, unofficial].
- Integrator configuration dictionary [S2, unofficial].

**Outputs:**
- Rendered image and its gradients with respect to scene parameters [S2, unofficial].

**Data Structures:**
The method is exposed via the `volpathsimple` integrator in Mitsuba 3 [S2, unofficial]. It does not introduce new persistent data structures but modifies the sampling logic during the adjoint pass [S2, unofficial].

**Parameters:**
- `use_drt` (bool): Enables Differential Ratio Tracking. If `False`, the standard free-flight sampling-based baseline is used [S2, unofficial].
- `use_drt_mis` (bool): Enables Multiple Importance Sampling (MIS) to combine gradients estimated by DRT and the baseline [S2, unofficial].
- `use_drt_subsampling` (bool): Reduces DRT sampling to once per path rather than at every vertex, reducing complexity from $O(n^2)$ to $O(n)$ [S2, unofficial].
- `use_nee` (bool): Enables Next-Event Estimation in both primal and adjoint phases [S2, unofficial].

**Algorithm Steps:**
1. Initialize the path tracer with `max_depth` and `use_drt=True` [S2, unofficial].
2. For each pixel, generate a path using standard free-flight sampling for the primal pass [S2, unofficial].
3. During the adjoint pass, if `use_drt` is enabled:
   - Instead of relying solely on the derivative of the free-flight distance, sample the in-scattering gradient using the DRT estimator [S2, unofficial].
   - This estimator specifically targets the ratio of scattering coefficients to avoid singularities when density $\sigma_t \to 0$ [S2, unofficial].
4. If `use_drt_mis` is enabled, combine the DRT gradient estimate with the baseline free-flight gradient estimate using MIS weights [S2, unofficial].
5. If `use_drt_subsampling` is enabled, apply the DRT estimator only once per path (e.g., at the first interaction) rather than at every vertex to reduce computational cost [S2, unofficial].

**Pseudocode:**
```python
# Pseudocode for integrator configuration and usage
import mitsuba as mi

mi.set_variant('cuda_ad_rgb')

integrator_config = {
    'type': 'volpathsimple',
    'max_depth': 64,
    'use_drt': True,       # Enable Differential Ratio Tracing
    'use_drt_mis': True,   # Combine with baseline via MIS
    'use_drt_subsampling': True, # Reduce complexity to O(n)
    'use_nee': True        # Enable Next-Event Estimation
}

integrator = mi.load_dict(integrator_config)

# Render and compute gradients
# scene contains parameters to optimize
image, grad = mi.render(scene, integrator=integrator, return_gradients=True)
```

**Edge Cases and Pitfalls:**
- **Zero Density:** The primary motivation for DRT is handling regions where medium density approaches zero. Standard free-flight sampling becomes biased or high-variance here [S2, unofficial].
- **Performance Scaling:** DRT's Monte Carlo estimation becomes more expensive with higher sample counts compared to pre-computed methods [S1].
- **Subsampling Trade-off:** Using `use_drt_subsampling` reduces runtime but may impact gradient accuracy if the single-sample approximation is insufficient for complex paths [S2, unofficial].

## Operating characteristics
- **Time Complexity:** With `use_drt_subsampling` disabled, the runtime is $O(n^2)$ with respect to path length $n$ due to per-vertex gradient estimation [S2, unofficial]. With subsampling enabled, it reduces to $O(n)$ [S2, unofficial].
- **Memory Complexity:** Reasonable even for high-resolution volumes due to efficient data structures in the underlying renderer [S1].
- **Performance:** DRT serves as a baseline. In multi-view scenarios, it is significantly slower than single-scattering methods because it must recompute gradients for each view, whereas single-scattering methods pre-compute view-independent terms [S1].
- **Strengths:** Unbiased estimation of in-scattering gradients; robust in low-density regions where free-flight sampling fails [S2, unofficial].
- **Limitations:** Computationally expensive for high sample counts; no pre-computation advantage for multi-view rendering [S1].
- **When to use:** When unbiased gradients are required for general volume paths, especially in low-density regimes, and multi-view speedups are not the primary concern.
- **When not to use:** When single scattering is sufficient and multi-view performance is critical; use single-scattering differentiable methods instead [S1].

## Background
Differential Ratio Tracing was implemented in Mitsuba 3 as a differentiable rendering method [S1]. It was introduced as a baseline for comparison in research on unbiased inverse volume rendering, specifically to address the limitations of standard free-flight path replay backpropagation [S2, unofficial]. The method is part of the broader effort to enable stable gradient-based optimization for volume reconstruction tasks [S2, unofficial].
