# Neural 3D Mesh Renderer (NMR)
Also called: Kato et al, NMR (Neural 3D Mesh Renderer) Rasterization

## Overview
Neural 3D Mesh Renderer (NMR) is a differentiable rendering method that approximates the non-differentiable rasterization step by replacing sudden visibility changes with linear interpolation, allowing gradients to flow from pixels to mesh vertices beyond the immediate boundary [S2]. It addresses the "localness" limitation of prior methods like OpenDR, where gradients only flowed from boundary pixels, by using non-local approximated gradients that are aware of the optimization objective [S1, unofficial].

## How it works
NMR preserves traditional rasterization for the forward pass but approximates gradients for the backward pass to handle discontinuities caused by occlusions and boundary crossings [S2]. The core insight is replacing the step-function change in visibility with a linear interpolation change, enabling gradients to flow from pixel color to lighting, textures, geometry vertices, and camera models [S2].

### Inputs and Outputs
*   **Inputs:**
    *   Mesh geometry: Set of vertices $V$ and triangles $T$.
    *   Camera parameters: Intrinsics and extrinsics.
    *   Texture map: If texture-based shading is used.
    *   Shading model: Vertex attributes or fragment-level shading parameters.
*   **Outputs:**
    *   Rendered image (forward pass).
    *   Gradients with respect to vertices, textures, and camera parameters (backward pass).

### Data Structures
*   **Triangle List:** Stores vertex indices for each triangle.
*   **Rasterization Buffer:** Standard depth buffer (z-buffer) and color buffer.
*   **Barycentric Coordinates:** Computed for each fragment within a triangle.

### Steps
1.  **Forward Rasterization:** Perform standard rasterization. For each pixel, determine the closest triangle using z-culling. Compute barycentric coordinates $(\alpha, \beta, \gamma)$ for the fragment [S2].
2.  **Shading:** Compute the color of the fragment. NMR supports fragment-level shading, allowing it to handle shading models differentiable with respect to textures, unlike methods restricted to local vertex shading [S2].
3.  **Gradient Approximation (Backward Pass):**
    *   For pixels covered by a triangle, compute gradients using standard barycentric interpolation derivatives.
    *   For pixels *outside* the triangle boundary but within a defined neighborhood, NMR approximates the gradient by assuming a linear change in visibility [S2].
    *   Specifically, the gradient with respect to a vertex $v_p$ considers pixels to the left and right of the vertex projection $v_p^*$, allowing non-zero gradients even if the pixel is not strictly inside the triangle [S1, unofficial].
    *   The gradient flow is objective-aware, leveraging the loss gradient from the target application (e.g., image reconstruction) to guide vertex displacement [S1, unofficial].

### Formulas
Let $c_v$ be the color at pixel $v$. The gradient with respect to vertex position $v_p$ is computed considering pixels $\{x_p, y_p\}$ near the vertex projection. The key relation cited is:
$$ \frac{\partial c_v}{\partial v_p} \text{ is non-zero for pixels adjacent to the boundary.} $$
The method replaces the discontinuous visibility function $V(t)$ with a linear approximation, allowing $\frac{\partial V}{\partial t}$ to be non-zero across the boundary [S2].

### Parameters
*   **Neighborhood Size:** The extent of pixels considered for non-local gradient flow is not explicitly defined in the sources, but it implies a local neighborhood around the triangle boundary [S1, unofficial][S2].

### Edge Cases and Pitfalls
*   **Z-culling:** Only the closest triangle affects the pixel color. Consequently, gradients do not flow to the vertices of occluded triangles [S2]. This saves computation but may hinder geometry optimization in applications where occluded geometry needs correction [S2].
*   **Local Minima:** By allowing gradients from pixels beyond the boundary, NMR avoids the poor local minima associated with OpenDR's strict localness [S1, unofficial].
*   **Complex Occlusions:** While NMR handles local boundaries well, methods relying on similar approximations (like TF Mesh Renderer) may fail with complex mutual occlusions between objects [S2].

### Pseudocode
```python
def nmr_backward_gradient(triangles, vertices, camera, loss_gradient):
    """
    Compute gradients for NMR.
    triangles: List of triangles, each with 3 vertex indices.
    vertices: Array of vertex positions [N, 3].
    camera: Camera parameters.
    loss_gradient: Gradient of loss w.r.t. rendered image [H, W, C].
    
    Returns:
    grad_vertices: Gradient w.r.t. vertex positions [N, 3].
    """
    grad_vertices = zeros_like(vertices)
    
    # Forward pass is assumed to have produced a rasterization map
    # mapping each pixel to a triangle index and barycentric coords
    
    for each pixel (u, v) in image:
        if pixel (u, v) is covered by triangle t:
            # Standard differentiable rasterization gradient
            # Flow gradient to the 3 vertices of t based on barycentric coords
            grad_vertices += standard_rasterization_grad(triangles[t], vertices, loss_gradient[u, v])
            
        else:
            # Check if pixel is in the neighborhood of any triangle boundary
            # NMR approximates gradient for pixels outside the triangle
            # but near the boundary, assuming linear interpolation change
            for each triangle t_nearby:
                if is_near_boundary(pixel (u, v), t_nearby):
                    # Compute approximate gradient based on distance to boundary
                    # and the loss gradient at this pixel
                    # This allows gradient flow to vertices even if pixel is outside
                    grad_vertices += approximate_boundary_grad(t_nearby, vertices, loss_gradient[u, v])
                    
    return grad_vertices
```
Note: The exact formula for `approximate_boundary_grad` is not provided in the sources, but it relies on the linear interpolation approximation of visibility [S2].

## Subtopics

### DIB-R
A differentiable rasterization method that uses a soft rasterization approach with a stochastic sampling mechanism, allowing gradients to flow to occluded triangles, unlike NMR's z-culling. [DIB-R](6798-dib-r.md)

## Operating characteristics
*   **Time Complexity:** Not explicitly given, but Jrender's optimized NMR implementation is about ten times faster than the official implementation [S2].
*   **Memory Complexity:** Standard rasterization buffers plus overhead for gradient computation.
*   **Performance:** On a 280-triangle bowl at 256x256 resolution, Jrender's NMR takes 7.5ms for forward rendering + gradient, compared to 8.1ms for the official NMR [S2].
*   **Strengths:** Handles localness issue of OpenDR; supports fragment-level shading; objective-aware gradients; efficient with z-culling.
*   **Limitations:** Gradients do not flow to occluded triangles due to z-culling; may struggle with complex mutual occlusions compared to probabilistic methods like SoftRas.
*   **When to use:** General purpose differentiable mesh rendering where efficiency and boundary gradient flow are important.
*   **When not to use:** When gradients to occluded geometry are critical for optimization (consider SoftRas instead).

## Background
NMR was proposed by Kato et al. [9] (cited as [33] in [S2]) to overcome the limitations of OpenDR, specifically the localness of gradient computation and the lack of objective awareness [S1, unofficial]. It has been integrated into applications such as single image 3D reconstruction and 3D mesh style editing [S2]. An optimized implementation in Jrender is about ten times faster than the original [S2].
