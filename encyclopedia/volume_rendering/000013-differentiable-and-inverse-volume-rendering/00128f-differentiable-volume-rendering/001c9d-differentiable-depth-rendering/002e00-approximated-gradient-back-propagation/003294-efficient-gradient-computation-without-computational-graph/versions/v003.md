# Efficient Gradient Computation without Computational Graph

Also called: Nimier-David et al. method

## Overview
This method computes gradients for material and light parameters in differentiable volume rendering by avoiding the storage of a computational graph during the forward pass, thereby significantly reducing memory footprint [S1, unofficial]. It differs from standard reverse-mode automatic differentiation by deferring gradient computation to a separate backpropagation pass that casts rays with gradients from the camera, rather than storing intermediate values during the forward pass [S1, unofficial].

## How it works
**Inputs:**
*   Scene representation (e.g., SDF, volume density) [G].
*   Material and light parameters $\theta$ [S1, unofficial].
*   Camera configuration [G].

**Outputs:**
*   Gradients $\frac{\partial L}{\partial \theta}$ with respect to the loss $L$ [S1, unofficial].

**Data Structures:**
*   Ray structures containing position, direction, and accumulated gradient values [G].
*   Exact field layouts, sizes, and bit packing are Not given in the sources [G].
*   No persistent computational graph or tape is stored in memory during rendering [S1, unofficial].

**Steps:**
1.  **Forward Pass:** Render the image normally without storing the computational graph or intermediate derivative states [S1, unofficial].
2.  **Backpropagation Ray Casting:** Cast new rays from the camera, initialized with gradients propagated from the pixel loss [S1, unofficial].
3.  **Gradient Propagation:** As rays traverse the scene, gradients are propagated along the ray path [S1, unofficial].
4.  **Occlusion Handling:** Gradients are propagated to surfaces at occlusion points [S1, unofficial].

**Formulas:**
Not given in the sources.

**Parameters:**
*   The method is implemented in Mitsuba 2, which explores approaches between forward- and reverse-mode automatic differentiation [S2].

**Edge Cases and Pitfalls:**
*   **Visibility Changes:** The method does not account for the non-differentiability of object visibility changes (e.g., an object entering or leaving the frame) [S1, unofficial]. This makes optimizing shapes challenging [S1, unofficial].
*   **Memory vs. Compute:** The approach trades arithmetic operations for memory traffic by avoiding graph storage, which is beneficial on modern hardware where memory access is costly [S2].

**Pseudocode:**
```python
import math

def compute_gradients(scene, params, camera, loss_fn):
    # Forward pass: render image without storing computational graph [S1, unofficial]
    image = []
    for pixel in camera.pixels:
        ray = camera.build_ray(pixel)
        transmittance = 1.0
        color = 0.0
        for sample in ray.samples:
            density = scene.density(sample)
            alpha = 1.0 - math.exp(-density * step_size)
            color += transmittance * alpha * scene.color(sample)
            transmittance *= 1.0 - alpha
        image.append(color)
    
    # Initialize parameter gradients
    grad_params = {k: 0.0 for k in params}
    
    # Backpropagation: cast rays with gradients from camera [S1, unofficial]
    for pixel_idx, pixel in enumerate(camera.pixels):
        ray = camera.build_ray(pixel)
        current_grad = loss_fn.derivative(image[pixel_idx])
        
        # Traverse scene to find interaction points
        hit = None
        for sample in ray.samples:
            if scene.is_occluded(sample):
                hit = sample
                break
        
        if hit is not None:
            # Compute local gradient contribution at hit point
            # Not given in the sources.
            local_grad = scene.evaluate_gradient(hit, params)
            
            # Accumulate gradient
            # Note: Visibility changes are ignored [S1, unofficial]
            for k in params:
                grad_params[k] += local_grad * current_grad
                
    return grad_params
```

## Subtopics

### Greedy vertex elimination
An algorithm that finds common factors in the computational graph to optimize derivative computation, trading arithmetic operations for memory traffic [S2]. It is used in Mitsuba 2 to explore approaches between forward- and reverse-modes [S2].

## Operating characteristics
*   **Memory Complexity:** Significantly lower than full reverse-mode AD because no computational graph is stored during rendering [S1, unofficial].
*   **Time Complexity:** Requires two passes (forward and backward ray casting), potentially increasing compute time compared to a single forward pass, but avoids the overhead of graph traversal and storage [S1, unofficial][S2].
*   **Strengths:** Suitable for scenes with large memory footprints where storing a computational graph is infeasible [S1, unofficial].
*   **Limitations:** Cannot handle non-differentiable visibility changes, limiting its applicability to shape optimization [S1, unofficial].

## Background
The method was proposed by Nimier-David et al. [S1, unofficial]. It addresses the high memory footprint of automatic differentiation in differentiable rendering, which limits applications to simple scenes [S1, unofficial]. Mitsuba 2 adopted this approach to explore the spectrum between forward- and reverse-mode AD, utilizing a greedy vertex elimination algorithm to optimize derivative computation [S2].
