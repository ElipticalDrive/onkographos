# Efficient Gradient Computation without Computational Graph

Also called: Nimier-David et al. method

## Overview
This method computes gradients for material and light parameters in differentiable volume rendering by avoiding the storage of a computational graph during the forward pass, thereby significantly reducing memory footprint [S2, unofficial]. It distinguishes itself from standard reverse-mode automatic differentiation by casting rays with gradients from the camera during a separate backpropagation pass, rather than storing intermediate values for a single forward pass [S2, unofficial].

## How it works
**Inputs:**
*   Scene representation (e.g., SDF, volume density).
*   Material and light parameters $\theta$.
*   Camera configuration.

**Outputs:**
*   Gradients $\frac{\partial L}{\partial \theta}$ with respect to the loss $L$.

**Data Structures:**
*   Ray structures containing position, direction, and accumulated gradient values.
*   No persistent computational graph or tape is stored in memory during rendering [S2, unofficial].

**Steps:**
1.  **Forward Pass:** Render the image normally without storing the computational graph or intermediate derivative states [S2, unofficial].
2.  **Backpropagation Ray Casting:** Cast new rays from the camera. These rays carry gradient information propagated from the loss function at the pixel level [S2, unofficial].
3.  **Gradient Propagation:** As rays traverse the scene, gradients are propagated along the ray path. When a ray hits a surface or volume element, the local gradient contribution is computed and accumulated [S2, unofficial].
4.  **Occlusion Handling:** Gradients are propagated to surfaces at occlusion points. Note that changes in object visibility are not differentiable and are not considered during this backpropagation step [S2, unofficial].

**Pseudocode:**
```python
def compute_gradients(scene, params, camera):
    # Forward pass: render image without storing graph
    image = render_forward(scene, params, camera)
    
    # Initialize gradients for parameters
    grad_params = initialize_zeros_like(params)
    
    # Backpropagation: cast rays with gradients from camera
    for ray in camera.cast_rays_with_gradients(image):
        # Propagate gradients along the ray
        current_grad = ray.gradient
        
        # Traverse scene to find interaction points
        hit = scene.intersect(ray)
        
        if hit is not None:
            # Compute local gradient contribution at the hit point
            # This involves the derivative of the rendering equation w.r.t params
            local_grad = compute_local_gradient(hit, scene, params)
            
            # Accumulate gradient
            # Note: Visibility changes are ignored [S2, unofficial]
            grad_params += local_grad * current_grad
            
    return grad_params
```

**Parameters:**
*   The method is implemented in Mitsuba 2, which explores approaches between forward- and reverse-mode automatic differentiation [S1].

**Edge Cases and Pitfalls:**
*   **Visibility Changes:** The method does not account for the non-differentiability of object visibility changes (e.g., an object entering or leaving the frame) [S2, unofficial]. This makes optimizing shapes challenging.
*   **Memory vs. Compute:** The approach trades arithmetic operations for memory traffic by avoiding graph storage, which is beneficial on modern hardware where memory access is costly [S1].

## Operating characteristics
*   **Memory Complexity:** Significantly lower than full reverse-mode AD because no computational graph is stored during rendering [S2, unofficial].
*   **Time Complexity:** Requires two passes (forward and backward ray casting), potentially increasing compute time compared to a single forward pass, but avoids the overhead of graph traversal and storage [S1][S2, unofficial].
*   **Strengths:** Suitable for scenes with large memory footprints where storing a computational graph is infeasible [S2, unofficial].
*   **Limitations:** Cannot handle non-differentiable visibility changes, limiting its applicability to shape optimization [S2, unofficial].

## Background
The method was proposed by Nimier-David et al. [S2, unofficial]. It addresses the high memory footprint of automatic differentiation in differentiable rendering, which limits applications to simple scenes [S2, unofficial]. Mitsuba 2 adopted this approach to explore the spectrum between forward- and reverse-mode AD, utilizing a greedy vertex elimination algorithm to optimize derivative computation [S1].
