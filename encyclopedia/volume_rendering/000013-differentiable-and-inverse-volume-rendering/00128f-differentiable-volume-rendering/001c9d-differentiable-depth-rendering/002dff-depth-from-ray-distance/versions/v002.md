# Depth from Ray Distance


## Overview
Depth from Ray Distance converts accumulated ray distance into camera-space depth ($z_c$) by accounting for perspective projection geometry [S1]. It is distinguished from [Approximated Gradient Back-Propagation](5666-approximated-gradient-back-propagation.md) by providing exact gradients via the Implicit Function Theorem (IFT) as implemented in [Differentiable Depth Rendering](1332-differentiable-depth-rendering.md), avoiding numerical instability from differentiating through iterative bisection or sphere tracing algorithms directly [G].

## How it works
**Inputs:**
* Ray distance $d$: Accumulated distance along the ray from the camera origin to the surface intersection [S1].
* Pixel coordinates $(x, y)$: Integer coordinates of the pixel in the image plane [S1].
* Camera intrinsics $K$: $3 \times 3$ camera calibration matrix [S1].

**Outputs:**
* Camera-space depth $z_c$: Depth value along the camera's optical axis (Z-axis in camera coordinates) [S1].

**Data Structures:**
* $K$: $3 \times 3$ matrix [S1].
* $K^{-1}$: Inverse of the camera intrinsics matrix [S1].

**Steps:**
1. **Normalize Homogeneous Coordinates:** Compute the normalized homogeneous direction vector components $(\tilde{x}, \tilde{y})$ by applying the inverse camera intrinsics to the pixel coordinates [S1].
   $$ \begin{bmatrix} \tilde{x} \\ \tilde{y} \\ 1 \end{bmatrix} = K^{-1} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix} $$
   Here, $\tilde{x}$ and $\tilde{y}$ are the x and y components of the ray direction in camera space, normalized such that the z-component is 1 [S1].

2. **Compute Ray Direction Norm:** Calculate the Euclidean norm of the normalized direction vector $(\tilde{x}, \tilde{y}, 1)$ [S1].
   $$ \|\mathbf{v}\| = \sqrt{\tilde{x}^2 + \tilde{y}^2 + 1} $$

3. **Calculate Camera-Space Depth:** Divide the ray distance $d$ by the norm of the direction vector to project the distance onto the camera's Z-axis [S1].
   $$ z_c = \frac{d}{\sqrt{\tilde{x}^2 + \tilde{y}^2 + 1}} $$

**Parameters:**
* $K$: Camera intrinsic matrix. Typical values depend on the specific camera calibration. Not given in the sources. [G]
* Threshold for surface intersection: Determined by the upstream differentiable volume rendering method (e.g., sphere tracing threshold). Not given in the sources. [G]

**Edge Cases and Pitfalls:**
* **Principal Point Offset:** If the camera principal point $(c_x, c_y)$ is not at the image center, $K^{-1}$ must correctly account for this offset in the homogeneous coordinate calculation [G].
* **Division by Zero:** The denominator $\sqrt{\tilde{x}^2 + \tilde{y}^2 + 1}$ is always $\ge 1$ for valid pixel coordinates, so division by zero is not possible [G].
* **Precision:** For pixels far from the principal point, $\tilde{x}$ and $\tilde{y}$ become large, potentially affecting numerical precision in the square root calculation [G]. Use `hypot` or equivalent stable square root implementations if available [G].

**Pseudocode:**
```python
import torch

def depth_from_ray_distance(d: torch.Tensor, x: torch.Tensor, y: torch.Tensor, K_inv: torch.Tensor) -> torch.Tensor:
    """
    Compute camera-space depth from ray distance and pixel coordinates.
    
    Args:
        d: Ray distance tensor of shape (N,).
        x: Pixel x-coordinates tensor of shape (N,).
        y: Pixel y-coordinates tensor of shape (N,).
        K_inv: Inverse camera intrinsic matrix of shape (3, 3).
        
    Returns:
        z_c: Camera-space depth tensor of shape (N,).
    """
    # Step 1: Compute normalized homogeneous coordinates
    ones = torch.ones_like(x)
    hom_coords = torch.stack([x, y, ones], dim=-1)  # Shape (N, 3)
    normalized_dir = hom_coords @ K_inv.T  # Shape (N, 3)
    tilde_x = normalized_dir[:, 0]
    tilde_y = normalized_dir[:, 1]
    
    # Step 2: Compute norm of direction vector (tilde_x, tilde_y, 1)
    norm = torch.sqrt(tilde_x**2 + tilde_y**2 + 1.0)
    
    # Step 3: Calculate camera-space depth
    z_c = d / norm
    
    return z_c
```

## Subtopics

### Expected Term Rendering
Renders the expected termination distance (depth) along each ray by tracing through the volume [S2, unofficial]. It computes the expected value of the depth distribution rather than a single hard intersection [S2, unofficial]. Steps: Get ray_id, create SingleRaySpec, find bounds, and call trace_ray_expected_term [S2, unofficial]. Create a result tensor of dtype and device matching `rays.origins`, size `{rays.origins.size(0)}`, with `requires_grad=false` [S2, unofficial]. Launch `device::render_ray_expected_term_kernel` with blocks calculated by `CUDA_N_BLOCKS_NEEDED(Q, TRACE_RAY_CUDA_THREADS)` [S2, unofficial]. Pass `grid`, `rays`, `opt`, and `results.data_ptr<float>()` [S2, unofficial].

### Sigma-Threshold Depth Rendering
Renders depth based on a binary threshold of the volume density ($\sigma$) [S2, unofficial]. It finds the first point along the ray where $\sigma$ exceeds a specified `sigma_thresh` value [S2, unofficial]. Steps: Get ray_id, create SingleRaySpec, find bounds, and call trace_ray_sigma_thresh with sigma_thresh [S2, unofficial]. Create a result tensor of dtype and device matching `rays.origins`, size `{rays.origins.size(0)}`, with `requires_grad=false` [S2, unofficial]. Launch `device::render_ray_sigma_thresh_kernel` with blocks calculated by `CUDA_N_BLOCKS_NEEDED(Q, TRACE_RAY_CUDA_THREADS)` [S2, unofficial]. Pass `grid`, `rays`, `opt`, `sigma_thresh`, and `results.data_ptr<float>()` [S2, unofficial]. Parameter: `sigma_thresh`: A float threshold value for density comparison [S2, unofficial].

## Operating characteristics
* **Time Complexity:** $O(1)$ per pixel after the ray distance $d$ is computed [G]. The dominant cost is the upstream differentiable volume rendering step [G].
* **Memory Complexity:** $O(1)$ auxiliary memory per pixel [G].
* **Strengths:** Provides geometrically correct depth values that are consistent with the camera model [S1]. Exact gradients are available via the IFT implementation in the parent method [G].
* **Limitations:** Depends entirely on the accuracy of the upstream ray distance computation [G]. If the volume rendering fails to find a surface (e.g., transparent regions), the depth may be undefined or require a fallback (e.g., far plane) [G].
* **When to use:** When geometric accuracy of depth maps is required for downstream tasks like stereo matching, SLAM, or 3D reconstruction [G].
* **When not to use:** When only relative depth or normalized depth is sufficient, or when computational resources are extremely limited and the overhead of the upstream differentiable rendering is prohibitive [G].

## Background
The method is based on the geometric relationship between ray distance and camera-space depth in perspective projection [S1]. It is commonly used in differentiable rendering pipelines that support depth output, such as those based on differentiable sphere tracing for Signed Distance Fields (SDFs) [S1]. The specific implementation details for expected term and sigma-threshold variants are found in the Svox2 library [S2, unofficial].
