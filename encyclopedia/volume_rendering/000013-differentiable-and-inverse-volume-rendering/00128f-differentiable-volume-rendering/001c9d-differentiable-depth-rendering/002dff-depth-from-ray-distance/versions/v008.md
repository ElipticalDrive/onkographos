# Depth from Ray Distance

Also called: Camera-space depth conversion

## Overview
Depth from Ray Distance converts the accumulated ray distance $d$ (the weighted sum of sample distances along a ray) into camera-space depth $z_c$, which is the distance along the camera's optical axis. This method solves the problem of interpreting differentiable volume rendering outputs, which naturally produce distances along the ray direction, into a coordinate system compatible with standard depth sensors and geometric losses. It differs from sibling methods like [Expected Term Rendering](5952-expected-term-rendering.md) and [Median Depth Rendering](8815-median-depth-rendering.md) by providing a direct geometric conversion of the ray distance rather than computing statistical moments or threshold crossings of the volume density.

## How it works
**Inputs and Outputs:**
- Input: Ray distance $d$ (scalar), pixel coordinates $(x, y)$ (integers), camera intrinsic matrix $K$ ($3 \times 3$ matrix).
- Output: Camera-space depth $z_c$ (scalar).

**Data Structures:**
- $K$: $3 \times 3$ matrix representing camera intrinsics.
- $K^{-1}$: Inverse of $K$.
- $(x, y)$: Integer pixel coordinates.
- $d$: Float representing the accumulated distance along the ray.

**Steps:**
1. Compute the normalized homogeneous coordinate vector $(\tilde{x}, \tilde{y}, 1)^T$ by applying the inverse camera intrinsics to the pixel coordinates:
   $$
   \begin{bmatrix} \tilde{x} \\ \tilde{y} \\ 1 \end{bmatrix} = K^{-1} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix}
   $$
2. Calculate the norm of the normalized direction vector:
   $$
   n = \sqrt{\tilde{x}^2 + \tilde{y}^2 + 1}
   $$
3. Compute the camera-space depth $z_c$ by dividing the ray distance $d$ by the norm $n$:
   $$
   z_c = \frac{d}{n}
   $$

**Formulas:**
- Normalized homogeneous coordinate:
  $$
  \begin{bmatrix} \tilde{x} \\ \tilde{y} \\ 1 \end{bmatrix} = K^{-1} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix}
  $$
- Camera-space depth:
  $$
  z_c = \frac{d}{\sqrt{\tilde{x}^2 + \tilde{y}^2 + 1}}
  $$
  Where:
  - $z_c$ is the camera-space depth.
  - $d$ is the ray distance from the Differentiable Depth Rendering formula.
  - $(\tilde{x}, \tilde{y}, 1)^T = K^{-1}(x, y, 1)^T$ is the normalized homogeneous coordinate derived from pixel coordinates $(x,y)$ and camera matrix $K$.

**Parameters:**
- Not given in the sources.

**Edge Cases and Pitfalls:**
- Precision: Division by the norm $n$ requires $n > 0$. For valid pixel coordinates within the image bounds, $n$ is always positive.
- Boundaries: The method assumes the ray distance $d$ is correctly computed from the volume rendering process. If $d$ is zero (empty space), $z_c$ is zero.

**Pseudocode:**
```python
import numpy as np

def depth_from_ray_distance(d: float, x: int, y: int, K_inv: np.ndarray) -> float:
    """
    Convert ray distance to camera-space depth.
    
    Args:
        d: Ray distance (scalar).
        x: Pixel x-coordinate (int).
        y: Pixel y-coordinate (int).
        K_inv: Inverse camera intrinsic matrix (3x3 numpy array).
        
    Returns:
        z_c: Camera-space depth (float).
    """
    # Step 1: Compute normalized homogeneous coordinate
    # (x_tilde, y_tilde, 1)^T = K^{-1} * (x, y, 1)^T
    pixel_vec = np.array([x, y, 1.0])
    normalized_vec = K_inv @ pixel_vec
    
    # Extract tilde_x and tilde_y
    x_tilde = normalized_vec[0]
    y_tilde = normalized_vec[1]
    
    # Step 2: Calculate norm of normalized direction vector
    norm = np.sqrt(x_tilde**2 + y_tilde**2 + 1.0)
    
    # Step 3: Compute camera-space depth
    z_c = d / norm
    
    return z_c
```

## Subtopics

### RGB-D Mapping Optimization
RGB-D Mapping Optimization uses Depth from Ray Distance to compute geometric depth losses for optimizing radiance fields. It defines a photometric loss $L_p$ and a geometric depth loss $L_g$. The photometric loss is the mean squared error between rendered color $\hat{C}$ and input color $C$: $L_p(\hat{C}(\sigma, c)) = \frac{1}{M} \sum_{i=1}^{M} ||\hat{C}(\sigma_i, c_i) - C||^2$. The geometric depth loss is the mean squared error between rendered depth $\hat{D}$ and input depth $D$: $L_g(\hat{D}(\sigma)) = \frac{1}{M} \sum_{i=1}^{M} ||\hat{D}(\sigma) - D||^2$. The total loss is $L = L_p + \lambda_d L_g$, where $\lambda_d$ is the scaling factor of the geometric loss. The partial derivative of rendered color $\hat{C}$ w.r.t. color $c_i$ is $\frac{\partial \hat{C}}{\partial c_i} = w_i(\sigma) = T_i (1 - \exp(-\sigma_i \delta_i))$. The partial derivative of rendered depth $\hat{D}$ w.r.t. density $\sigma_i$ is $\frac{\partial \hat{D}}{\partial \sigma_i} = \delta_i [ t_i T_{i+1}(\sigma) - \hat{D} + \sum_{j=0}^{i} t_j w_j(\sigma) ]$, derived by interpreting distance $t_i$ as color $c_i$. These derivatives are implemented directly in a custom CUDA kernel, building on code developed for Plenoxel to boost computational speed [S2].

### Camera Pose Tracking via Differentiable Rendering
Camera Pose Tracking via Differentiable Rendering estimates camera pose by treating pose as the variable and radiance field parameters ($\vec{\sigma}, \vec{c}$) as static, performing image-to-model alignment using RGB-D input. The derivative of rendered depth $\hat{D}$ w.r.t. ray $\vec{r}$ is $\frac{\partial \hat{D}}{\partial \vec{r}} = \sum_{i=1}^{N} \frac{\partial \hat{D}}{\partial \sigma_i} \frac{\partial \sigma_i}{\partial \vec{p}_i} \frac{\partial \vec{p}_i}{\partial \vec{r}}$. The derivative of sample point $\vec{p}_i$ w.r.t. ray $\vec{r}$ is decomposed as $\frac{\partial \vec{p}_i}{\partial \vec{r}} = [\frac{\partial \vec{p}_i}{\partial \vec{o}}, \frac{\partial \vec{p}_i}{\partial \vec{d}}] = [1, t_i]$. The Adam optimizer is used for tracking [S2]. A pitfall is that the partial derivatives $\frac{\partial \sigma_i}{\partial \vec{p}_i}$, $\frac{\partial c_i}{\partial \vec{p}_i}$, and $\frac{\partial \vec{p}_i}{\partial \vec{r}}$ are model-specific and produce messy functions for trilinear interpolation; complete analytical equations are reserved for Appendix A of the source [S2].

### Gumbel Depth Perturbations
Gumbel Depth Perturbations is a method for aggregating coloring based on depth, using Gumbel-Max/Min distributions, resulting in the softmin function. Unlike no depth perturbations or taking the closest triangle, Gumbel depth perturbations are truly continuous [S3].

- When to use it: Use when you need to convert differentiable volume rendering outputs (ray distances) into camera-space depth for comparison with ground-truth depth maps or for geometric losses.
- When not: Use other methods like [Expected Term Rendering](5952-expected-term-rendering.md) if you need the expected termination distance rather than the geometric depth along the optical axis.

## Background
Depth from Ray Distance is a fundamental component in differentiable volume rendering pipelines, particularly those involving RGB-D data. It was introduced in the context of rendering deep implicit signed distance functions with differentiable sphere tracing [S1] and in RGB-D mapping and tracking in plenoxel radiance fields [S2]. The method allows for the integration of geometric supervision into neural rendering frameworks by providing a differentiable link between the ray-space distance and the camera-space depth.
