# Depth from Ray Distance

Also called: Camera-space Depth Rendering, Ray Distance to Depth Conversion

## Overview
Depth from Ray Distance computes the camera-space depth $z_c$ for a pixel by converting the accumulated ray distance $d$ (the Euclidean distance from the camera origin to the integration endpoint) into the coordinate along the camera's optical axis. It solves the problem of mapping the scalar ray length, typically obtained from differentiable volume rendering or sphere tracing, into a standard depth map format compatible with camera intrinsics. It differs from [Expected Depth Rendering](1332-differentiable-depth-rendering.md) and [Median Depth Rendering](8815-median-depth-rendering.md) by treating the ray distance as a single geometric scalar rather than a distribution of sample depths, providing a direct projection of the ray endpoint onto the camera plane [S1].

## How it works
**Inputs and Outputs:**
- Input: Ray distance $d$ (scalar, Euclidean distance from camera origin to the surface/volume boundary along the ray), pixel coordinates $(x, y)$, and camera intrinsic matrix $K$ ($3 \times 3$).
- Output: Camera-space depth $z_c$ (scalar, distance along the principal axis).

**Data Structures:**
- $K$: $3 \times 3$ matrix containing focal lengths and principal point offsets.
- $(x, y)$: Integer or float pixel coordinates.
- $d$: Float representing the ray length.

**Steps:**
1.  **Normalize Pixel Coordinates:** Compute the normalized homogeneous coordinate vector $(\tilde{x}, \tilde{y}, 1)^T$ by applying the inverse of the camera intrinsic matrix $K^{-1}$ to the homogeneous pixel coordinate $(x, y, 1)^T$ [S1].
    $$
    \begin{bmatrix} \tilde{x} \\ \tilde{y} \\ 1 \end{bmatrix} = K^{-1} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix}
    $$
2.  **Compute Direction Norm:** Calculate the Euclidean norm of the normalized direction vector $(\tilde{x}, \tilde{y}, 1)^T$ [S1].
    $$
    \text{norm} = \sqrt{\tilde{x}^2 + \tilde{y}^2 + 1}
    $$
3.  **Convert to Depth:** Divide the ray distance $d$ by the computed norm to obtain the camera-space depth $z_c$ [S1].
    $$
    z_c = \frac{d}{\sqrt{\tilde{x}^2 + \tilde{y}^2 + 1}}
    $$

**Parameters:**
- $K$: Camera intrinsic matrix. Typical values depend on the camera calibration. Not given in the sources for specific standard values, but required for $K^{-1}$.

**Edge Cases and Pitfalls:**
- **Division by Zero:** The denominator $\sqrt{\tilde{x}^2 + \tilde{y}^2 + 1}$ is always $\ge 1$ because the third component is 1. Thus, division by zero is impossible [S1].
- **Precision:** Ensure $K^{-1}$ is computed with sufficient precision. If $K$ is ill-conditioned, the normalized coordinates may be inaccurate [G].
- **Ray Distance Definition:** This method assumes $d$ is the Euclidean distance from the camera origin. If $d$ is defined differently (e.g., parameter $t$ in a ray equation $O + tD$ where $D$ is not normalized), the formula must be adjusted [G].

**Pseudocode:**
```python
import torch
import numpy as np

def depth_from_ray_distance(d: torch.Tensor, x: torch.Tensor, y: torch.Tensor, K: torch.Tensor) -> torch.Tensor:
    """
    Compute camera-space depth z_c from ray distance d and pixel coordinates.
    
    Args:
        d: Tensor of ray distances (Euclidean length from camera origin). Shape: (N,)
        x: Tensor of x pixel coordinates. Shape: (N,)
        y: Tensor of y pixel coordinates. Shape: (N,)
        K: Camera intrinsic matrix. Shape: (3, 3)
        
    Returns:
        z_c: Tensor of camera-space depths. Shape: (N,)
    """
    # Step 1: Normalize pixel coordinates
    # Convert pixel coordinates to homogeneous vector [x, y, 1]
    # Shape: (N, 3)
    pixel_hom = torch.stack([x, y, torch.ones_like(x)], dim=-1)
    
    # Apply inverse intrinsics
    # K_inv @ pixel_hom.T -> (3, N) -> transpose to (N, 3)
    K_inv = torch.inverse(K)
    norm_coords = (K_inv @ pixel_hom.T).T
    
    # Extract tilde_x and tilde_y
    # The third component should be 1, but we use the computed values for robustness if needed,
    # though the formula explicitly uses 1 in the norm calculation as per [S1].
    # [S1] specifies: (x_tilde, y_tilde, 1)^T = K^{-1}(x, y, 1)^T
    # So we take the first two components.
    x_tilde = norm_coords[:, 0]
    y_tilde = norm_coords[:, 1]
    
    # Step 2: Compute the norm of the normalized direction vector
    # Formula: sqrt(x_tilde^2 + y_tilde^2 + 1)
    # Note: The source [S1] explicitly uses 1 in the sqrt, corresponding to the z-component of the normalized homogeneous coord.
    denom = torch.sqrt(x_tilde**2 + y_tilde**2 + 1.0)
    
    # Step 3: Compute depth
    z_c = d / denom
    
    return z_c
```

## Subtopics

### Expected Term Rendering
Renders the expected termination distance (depth) along each ray by tracing through the volume [S2, unofficial]. It computes the weighted mean of sample depths, typically used for depth map rendering [S2, unofficial]. Implementation involves creating a `SingleRaySpec`, finding bounds, and calling `trace_ray_expected_term` within a CUDA kernel `device::render_ray_expected_term_kernel` [S2, unofficial]. The result tensor is initialized with `requires_grad=false` [S2, unofficial].

### Sigma-Threshold Depth Rendering
Renders a binary or thresholded output based on whether the volume density ($\sigma$) exceeds a given threshold along the ray [S2, unofficial]. It computes depth based on a sigma threshold, referencing the method used in Dex-NeRF [S2, unofficial]. Implementation involves calling `trace_ray_sigma_thresh` with a `sigma_thresh` parameter within a CUDA kernel `device::render_ray_sigma_thresh_kernel` [S2, unofficial]. The parameter `sigma_thresh` is a float threshold for sigma values [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per pixel for the conversion step, assuming ray distance $d$ is already computed. The overall cost depends on the upstream depth computation method (e.g., sphere tracing or volume rendering).
- **Memory Complexity:** $O(1)$ additional memory per pixel for storing intermediate normalized coordinates.
- **Strengths:** Simple, differentiable, and directly compatible with standard camera models. It provides a geometrically consistent depth map from ray lengths [S1].
- **Limitations:** It does not account for multi-modal depth distributions or transparency effects within the volume, unlike Expected or Median Depth Rendering. It assumes a single intersection point or a well-defined endpoint for the ray distance [S1].
- **When to use:** When the ray distance represents a clear surface intersection or integration endpoint and a standard depth map is required for downstream tasks like RGB-D mapping [S3].
- **When not to use:** When the scene has significant transparency or multiple surfaces along the ray, and a representative depth (mean/median) is preferred over the endpoint depth [S1].

## Background
The method originates from the need to render depth maps from implicit signed distance fields (SDFs) using differentiable sphere tracing [S1]. It was introduced in the context of rendering deep implicit SDFs, where direct application of sphere tracing is computationally expensive, and efficient forward propagation is required [S1]. The conversion from ray distance to camera-space depth is a standard geometric operation in computer vision, adapted here for differentiable rendering pipelines [S1]. It is used in RGB-D mapping and tracking applications, where geometric depth loss is combined with photometric loss for optimization [S3].
